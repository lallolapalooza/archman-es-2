spu_create(2) Manual de llamadas al sistema spu_create(2)

NOMBRE

spu_create - crea un nuevo contexto de SPU

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/spu.h>          /* Definición de las constantes SPU_* */
#include <sys/syscall.h>      /* Definición de las constantes SYS_* */
#include <unistd.h>
int syscall(SYS_spu_create, const char *path, unsigned int flags,
            mode_t mode, int neighbor_fd);

Nota: glibc no proporciona una envoltura para spu_create(), necesitando el uso de syscall(2).

DESCRIPCIÓN

La llamada al sistema spu_create() se utiliza en máquinas PowerPC que implementan la arquitectura Cell Broadband Engine para acceder a las Unidades de Procesamiento Sinérgico (SPU). Crea un nuevo contexto lógico para una SPU en path y devuelve un descriptor de archivo asociado a él. path debe referirse a un directorio inexistente en el punto de montaje del sistema de archivos SPU (spufs). Si spu_create() tiene éxito, se crea un directorio en path y se rellena con los archivos descritos en spufs(7).

Cuando se crea un contexto, el descriptor de archivo devuelto solo puede pasarse a spu_run(2), usarse como argumento dirfd para la familia de llamadas al sistema *at (por ejemplo, openat(2)), o cerrarse; otras operaciones no están definidas. Un contexto SPU lógico se destruye (junto con todos los archivos creados dentro del directorio path del contexto) una vez que la última referencia al contexto ha desaparecido; esto ocurre normalmente cuando se cierra el descriptor de archivo devuelto por spu_create().

El argumento mode (menos cualquier bit establecido en la umask(2) del proceso) especifica los permisos utilizados para crear el nuevo directorio en spufs. Véase stat(2) para una lista completa de los posibles valores de mode.

El argumento neighbor_fd se utiliza solo cuando se especifica la bandera SPU_CREATE_AFFINITY_SPU; véase más abajo.

El argumento flags puede ser cero o cualquier combinación OR-bitwise de las siguientes constantes:

SPU_CREATE_EVENTS_ENABLED
En lugar de usar señales para informar de errores de DMA, utiliza el argumento event de spu_run(2).
SPU_CREATE_GANG
Crea una banda SPU (gang) en lugar de un contexto. (Una banda es un grupo de contextos SPU que están funcionalmente relacionados entre sí y que comparten parámetros comunes de planificación —prioridad y política. En el futuro, puede implementarse la planificación de bandas, haciendo que el grupo se cambie como una única unidad).
Se creará un nuevo directorio en la ubicación especificada por el argumento path. Esta banda puede usarse para contener otros contextos SPU, proporcionando un nombre de ruta que esté dentro del directorio de la banda a llamadas posteriores a spu_create().
SPU_CREATE_NOSCHED
Crea un contexto que no se ve afectado por el planificador SPU. Una vez que el contexto se ejecuta, no se planificará hasta que sea destruido por el proceso que lo creó.
Dado que el contexto no puede eliminarse de la SPU, algunas funcionalidades están deshabilitadas para los contextos SPU_CREATE_NOSCHED. Solo un subconjunto de archivos estará disponible en el directorio de este contexto en spufs. Además, los contextos SPU_CREATE_NOSCHED no pueden volcar un archivo core al fallar.
La creación de contextos SPU_CREATE_NOSCHED requiere la capacidad CAP_SYS_NICE.
SPU_CREATE_ISOLATE
Crea un contexto SPU aislado. Los contextos aislados están protegidos de algunas operaciones de PPE (Elemento de Procesamiento PowerPC), como el acceso al almacenamiento local de SPU y el registro NPC.
La creación de contextos SPU_CREATE_ISOLATE también requiere la bandera SPU_CREATE_NOSCHED.
SPU_CREATE_AFFINITY_SPU (desde Linux 2.6.23)
Crea un contexto con afinidad a otro contexto SPU. Esta información de afinidad se utiliza dentro del algoritmo de planificación SPU. El uso de esta bandera requiere que se pase un descriptor de archivo que se refiera al otro contexto SPU en el argumento neighbor_fd.
SPU_CREATE_AFFINITY_MEM (desde Linux 2.6.23)
Crea un contexto con afinidad a la memoria del sistema. Esta información de afinidad se utiliza dentro del algoritmo de planificación SPU.

VALOR DE RETORNO

En caso de éxito, spu_create() devuelve un nuevo descriptor de archivo. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EACCES
El usuario actual no tiene acceso de escritura al punto de montaje de spufs(7).
EEXIST
Ya existe un contexto SPU en la ruta dada.
EFAULT
path no es un puntero de cadena válido en el espacio de direcciones del proceso que llama.
EINVAL
path no es un directorio en el punto de montaje de spufs(7), o se han proporcionado banderas inválidas.
ELOOP
Se encontraron demasiados enlaces simbólicos al resolver path.
EMFILE
Se ha alcanzado el límite por proceso en el número de descriptores de archivo abiertos.
ENAMETOOLONG
path es demasiado largo.
ENFILE
Se ha alcanzado el límite a nivel de sistema del número total de archivos abiertos.
ENODEV
Se solicitó un contexto aislado, pero el hardware no admite el aislamiento de SPU.
ENOENT
Parte de path no se pudo resolver.
ENOMEM
El kernel no pudo asignar todos los recursos requeridos.
ENOSPC
No hay suficientes recursos SPU disponibles para crear un nuevo contexto o se ha alcanzado el límite específico del usuario para el número de contextos SPU.
ENOSYS
La funcionalidad no es proporcionada por el sistema actual, ya sea porque el hardware no proporciona SPUs o el módulo spufs no está cargado.
ENOTDIR
Parte de path no es un directorio.
EPERM
Se ha proporcionado la bandera SPU_CREATE_NOSCHED, pero el usuario no tiene la capacidad CAP_SYS_NICE.

ARCHIVOS

path debe apuntar a una ubicación debajo del punto de montaje de spufs. Por convención, se monta en /spu.

ESTÁNDARES

Linux en PowerPC.

HISTORIA

Linux 2.6.16.

Antes de la adición de la bandera SPU_CREATE_AFFINITY_SPU en Linux 2.6.23, la llamada al sistema spu_create() tomaba solo tres argumentos (es decir, no había argumento neighbor_fd).

NOTAS

spu_create() está pensada para ser utilizada desde bibliotecas que implementan una interfaz más abstracta para SPUs, no para ser utilizada desde aplicaciones regulares. Ver http://www.bsc.es/projects/deepcomputing/linuxoncell/ para las bibliotecas recomendadas.

EJEMPLOS

Ver spu_run(2) para un ejemplo del uso de spu_create()
