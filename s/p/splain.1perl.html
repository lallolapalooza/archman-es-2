SPLAIN(1perl) Guía de Referencia para Programadores de Perl SPLAIN(1perl)

NOMBRE

diagnostics, splain - produce diagnósticos de advertencia detallados

SINOPSIS

Usando la pragmática "diagnostics":

use diagnostics;
use diagnostics -verbose;
diagnostics->enable;
diagnostics->disable;

Usando el programa de filtro independiente "splain":

perl programa 2>diag.out
splain [-v] [-p] diag.out

Usando diagnósticos para obtener trazas de pila de un script que se comporta mal:

perl -Mdiagnostics=-traceonly mi_script.pl

DESCRIPCIÓN

La pragmática "diagnostics"

Este módulo extiende los diagnósticos breves normalmente emitidos tanto por el compilador de perl como por el intérprete de perl (al ejecutar perl con el modificador -w o "use warnings"), aumentándolos con las descripciones más explicativas y amigables que se encuentran en perldiag. Al igual que las otras pragmáticas, afecta la fase de compilación de su programa en lugar de simplemente la fase de ejecución.

Para usarlo en su programa como una pragmática, simplemente invoque

use diagnostics;

al principio (o cerca del principio) de su programa. (Note que esto *sí* activa el flag -w de perl). Toda su compilación será entonces sujeto :-) a los diagnósticos mejorados. Estos aún se envían a STDERR.

Debido a la interacción entre problemas de tiempo de ejecución y tiempo de compilación, y porque probablemente no es una muy buena idea de todos modos, no puede usar "no diagnostics" para desactivarlos en tiempo de compilación. Sin embargo, puede controlar su comportamiento en tiempo de ejecución usando los métodos disable() y enable() para desactivarlos y activarlos respectivamente.

El flag -verbose imprime primero la introducción de perldiag antes de cualquier otro diagnóstico. La variable $diagnostics::PRETTY puede generar secuencias de escape más agradables para los paginadores.

Las advertencias emitidas por el propio perl (o más precisamente, aquellas que coinciden con las descripciones encontradas en perldiag) solo se muestran una vez (sin descripciones duplicadas). Las advertencias generadas por el código del usuario a la manera de warn() no se ven afectadas, lo que permite que se muestren mensajes duplicados del usuario.

Este módulo también agrega una traza de pila al mensaje de error cuando perl muere. Esto es útil para identificar qué causó la muerte. El flag -traceonly (o simplemente -t) desactiva las explicaciones de los mensajes de advertencia, dejando solo las trazas de pila. Así que si su script está muriendo, ejecútelo de nuevo con

perl -Mdiagnostics=-traceonly mi_script_defectuoso

para ver la pila de llamadas en el momento de la muerte. Al proporcionar el flag -warntrace (o simplemente -w), cualquier advertencia emitida también vendrá con una traza de pila.

El programa splain

Otro programa, splain, es en realidad nada más que un enlace al módulo diagnostics.pm (ejecutable), así como un enlace a la documentación diagnostics.pod. El flag -v es como la directiva "use diagnostics -verbose". El flag -p es como la variable $diagnostics::PRETTY. Dado que está post-procesando con splain, no tiene sentido poder activar/desactivar el procesamiento.

La salida de splain se dirige a STDOUT, a diferencia de la pragmática.

EJEMPLOS

El siguiente archivo seguramente activará algunos errores tanto en tiempo de ejecución como en tiempo de compilación:

use diagnostics;
print NOWHERE "nada\n";
print STDERR "\n\tEste mensaje debería estar sin adornos.\n";
warn "\tEsta es una advertencia del usuario";
print "\nPROBADOR DE DIAGNÓSTICOS: Por favor, ingrese una <CR> aquí: ";
my $a, $b = scalar <STDIN>;
print "\n";
print $x/$y;

Si prefiere ejecutar su programa primero y revisar sus problemas después, haga esto:

perl -w test.pl 2>test.out
./splain < test.out

Note que esto no es generalmente posible en shells de herencia más dudosa, ya que la teórica

(perl -w test.pl >/dev/tty) >& test.out
./splain < test.out

Porque acaba de mover el stdout existente a otro lugar.

Si no desea modificar el código fuente, pero aún así tiene advertencias sobre la marcha, haga esto:

exec 3>&1; perl -w test.pl 2>&1 1>&3 3>&- | splain 1>&2 3>&-

Genial, ¿eh?

Si desea controlar las advertencias sobre la marcha, haga algo como esto. Asegúrese de hacer primero el "use", o no podrá acceder a los métodos enable() o disable().

use diagnostics; # revisa toda la fase de compilación
    print "\ntiempo para las 1ras diags falsas: GRITOS\n";
    print BOGUS1 'nada';
    print "hecho con las 1ras falsas\n";
diagnostics->disable; # solo desactiva las advertencias en tiempo de ejecución
    print "\ntiempo para las 2das falsas: (silenciadas)\n";
    print BOGUS2 'nada';
    print "hecho con las 2das falsas\n";
diagnostics->enable; # vuelve a activar las advertencias en tiempo de ejecución
    print "\ntiempo para las 3ras falsas: GRITOS\n";
    print BOGUS3 'nada';
    print "hecho con las 3ras falsas\n";
diagnostics->disable;
    print "\ntiempo para las 4tas falsas: (silenciadas)\n";
    print BOGUS4 'nada';
    print "hecho con las 4tas falsas\n";

INTERNOS

Los mensajes de diagnóstico derivan del archivo perldiag.pod cuando está disponible en tiempo de ejecución. De lo contrario, pueden estar incrustados en el propio archivo cuando se construye el paquete splain. Consulte el Makefile para obtener detalles.

Si se descubre un manejador $SIG{__WARN__} existente, se seguirá respetando, pero solo después de que la función diagnostics::splainthis() (el interceptor $SIG{__WARN__} del módulo) haya hecho su trabajo con sus advertencias.

Hay una variable $diagnostics::DEBUG que puede establecer si está desesperadamente curioso sobre qué tipos de cosas se están interceptando.

BEGIN { $diagnostics::DEBUG = 1 }

ERRORES

No poder decir "no diagnostics" es molesto, pero puede que no sea insuperable.

La directiva "-pretty" se llama demasiado tarde para afectar los asuntos. En su lugar, debe hacer esto, y *antes* de cargar el módulo.

BEGIN { $diagnostics::PRETTY = 1 }

Podría iniciar más rápido retrasando la compilación hasta que sea necesaria, pero esto genera un "panic: top_level" al usar la forma de pragmática en Perl 5.001e.

Si bien es cierto que esta documentación es algo subseria, si usa un programa llamado splain, debería esperar un poco de diversión.

NOMBRE

splain - explícame los mensajes de error de Perl

SINopsis

splain [archivo...]

DESCRIPCIÓN

splain lee mensajes de error de Perl de la entrada estándar o de uno o más archivos, y luego imprime una versión más explícita de los mensajes. Es útil para entender errores que se producen en módulos o en código que no reconoces.

OPCIONES

splain no tiene opciones de línea de comandos.

EJEMPLO

Si tienes un archivo llamado error.log con el siguiente contenido:

Use of uninitialized value in scalar multiplication at ./mi_script.pl line 10.

Ejecutar splain error.log producirá la siguiente salida:

Use of uninitialized value in scalar multiplication at ./mi_script.pl line 10.
    (W uninitialized) The variable $variable indicated here was used before it
    was assigned a value.  This usually happens when you use a variable in an
    expression before you assign anything to it.  The value of an uninitialized
    scalar is undefined, and will be treated as "" or 0 in a numeric context,
    or "" in a string context.  This warning is enabled by default.

    To suppress this warning, you can either assign a default value to the
    variable, for example:

        my $variable = '';

    or check if the variable is defined before using it:

        if (defined $variable) {
            # ... use $variable ...
        }
