spu_run(2) Manual de Llamadas al Sistema spu_run(2)

NOMBRE

spu_run - ejecutar un contexto SPU

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/spu.h>          /* Definición de constantes SPU_* */
#include <sys/syscall.h>      /* Definición de constantes SYS_* */
#include <unistd.h>
int syscall(SYS_spu_run, int fd, uint32_t *npc, uint32_t *event);

Nota: glibc no proporciona un envoltorio para spu_run(), requiriendo el uso de syscall(2).

DESCRIPCIÓN

La llamada al sistema spu_run() se utiliza en máquinas PowerPC que implementan la Arquitectura Cell Broadband Engine para acceder a las Unidades de Procesamiento sinérgico (SPU). El argumento fd es un descriptor de archivo devuelto por spu_create(2) que hace referencia a un contexto SPU específico. Cuando el contexto se programa en una SPU física, comienza la ejecución en el puntero de instrucción pasado en npc.

La ejecución del código SPU ocurre de forma síncrona, lo que significa que spu_run() se bloquea mientras la SPU todavía se está ejecutando. Si hay necesidad de ejecutar código SPU en paralelo con otro código en la CPU principal u otras SPUs, primero se debe crear un nuevo hilo de ejecución (por ejemplo, usando pthread_create(3)).

Cuando spu_run() retorna, el valor actual del contador de programa de la SPU se escribe en npc, de modo que las llamadas sucesivas a spu_run() pueden usar el mismo puntero npc.

El argumento event proporciona un búfer para un código de estado extendido. Si el contexto SPU se creó con el marcador de bits SPU_CREATE_EVENTS_ENABLED, entonces este búfer es poblado por el kernel de Linux antes de que spu_run() retorne.

El código de estado puede ser una (o más) de las siguientes constantes:

SPE_EVENT_DMA_ALIGNMENT
Ocurrió un error de alineación DMA.
SPE_EVENT_INVALID_DMA
Se intentó un comando DMA MFC inválido.
SPE_EVENT_SPE_DATA_STORAGE
Ocurrió un error de almacenamiento DMA.
SPE_EVENT_SPE_ERROR
Se ejecutó una instrucción ilegal.

NULL es un valor válido para el argumento event. En este caso, los eventos no se informarán al proceso llamante.

VALOR DE RETORNO

En caso de éxito, spu_run() devuelve el valor del registro spu_status. En caso de fallo, devuelve -1 y se establece errno para indicar el error.

El valor del registro spu_status es una máscara de bits de códigos de estado y opcionalmente un código de 14 bits devuelto desde la instrucción stop-and-signal en la SPU. Las máscaras de bits para los códigos de estado son:

0x02
La SPU se detuvo por una instrucción stop-and-signal.
0x04
La SPU se detuvo por una instrucción halt.
0x08
La SPU está esperando un canal.
0x10
La SPU está en modo de un solo paso.
0x20
La SPU ha intentado ejecutar una instrucción inválida.
0x40
La SPU ha intentado acceder a un canal inválido.
0x3fff0000
Los bits enmascarados con este valor contienen el código devuelto desde una instrucción stop-and-signal. Estos bits son válidos solo si el bit 0x02 está establecido.

Si spu_run() no ha devuelto un error, uno o más bits entre los ocho inferiores siempre están establecidos.

ERRORES

EBADF
fd no es un descriptor de archivo válido.
EFAULT
npc no es un puntero válido, o event es no-NULL y un puntero inválido.
EINTR
Ocurrió una señal mientras spu_run() estaba en progreso; ver signal(7). El valor npc se ha actualizado al nuevo valor del contador de programa si es necesario.
EINVAL
fd no es un descriptor de archivo válido devuelto desde spu_create(2).
ENOMEM
No había suficiente memoria disponible para manejar un error de página resultante de un acceso directo a memoria (DMA) del Controlador de Flujo de Memoria (MFC).
ENOSYS
La funcionalidad no es proporcionada por el sistema actual, ya sea porque el hardware no proporciona SPUs o el módulo spufs no está cargado.

ESTÁNDARES

Linux en PowerPC.

HISTORIA

Linux 2.6.16.

NOTAS

spu_run() está pensado para ser utilizado desde bibliotecas que implementan una interfaz más abstracta para las SPUs, no para ser utilizado desde aplicaciones regulares. Ver http://www.bsc.es/projects/deepcomputing/linuxoncell/ para las bibliotecas recomendadas.

EJEMPLOS

El siguiente es un ejemplo de ejecución de un programa SPU simple de una instrucción con la llamada al sistema spu_run().

#include <err.h>
#include <fcntl.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
int main(void)
{
    int       context, fd, spu_status;
    uint32_t  instruction, npc;
    context = syscall(SYS_spu_create, "/spu/example-context", 0, 0755);
    if (context == -1)
        err(EXIT_FAILURE, "spu_create");
    /*
     * Escribir una instrucción 'stop 0x1234' en la memoria
     * local de la SPU.
     */
    instruction = 0x00001234;
    fd = open("/spu/example-context/mem", O_RDWR);
    if (fd == -1)
        err(EXIT_FAILURE, "open");
    write(fd, &instruction, sizeof(instruction));
    /*
     * establecer npc en la dirección de la instrucción de inicio del
     * programa SPU. Como escribimos la instrucción al
     * inicio del archivo mem, el punto de entrada será 0x0.
     */
    npc = 0;
    spu_status = syscall(SYS_spu_run, context, &npc, NULL);
    if (spu_status == -1)
        err(EXIT_FAILURE, "open");
    /*
     * Deberíamos ver un código de estado de 0x12340002:
     *   0x00000002 (spu se detuvo debido a stop-and-signal)
     * | 0x12340000 (el código stop-and-signal)
     */
    printf("Estado SPU: %#08x\n", spu_status);
    exit(EXIT_SUCCESS);
}

VER TAMBIÉN

close(2), spu_create(2), capabilities(7), spufs(7)

spu_run.2

NOMBRE

spu_run - Ejecutar un programa en un SPE (Cell Broadband Engine)

BIBLIOTECA

Biblioteca de manejo de SPE (libspe)

SINOPSIS

#include <libspe2.h>

int spu_run(spe_context_ptr_t ctx, unsigned int wait_time);

DESCRIPCIÓN

La función spu_run ejecuta un programa que se ha cargado previamente en un contexto SPE especificado por ctx. El SPE se ejecutará hasta que finalice el programa, hasta que se agote el wait_time especificado o hasta que el SPE se detenga por alguna otra razón.

ctx es un puntero a un contexto SPE devuelto por una llamada anterior a spe_context_create.

wait_time especifica el tiempo máximo de espera en microsegundos. Si se establece en 0, la llamada es no bloqueante y la función devuelve inmediatamente.

VALOR DE RETORNO

En caso de éxito, spu_run devuelve 0. En caso de error, devuelve -1 y la variable global errno se establece para indicar el error.

ERRORES

EBUSY
El contexto SPE ya está en uso o el SPE asociado no está disponible.
EINVAL
El puntero ctx no es válido o wait_time es negativo.
ETIME
Se agotó el tiempo de espera especificado por wait_time antes de que el SPE terminara.
EFAULT
Se produjo un error de direccionamiento de memoria.

ESTÁNDARES

spu_run es parte de la API de libspe2 y no se corresponde con ningún estándar POSIX.

HISTORIA

La función spu_run apareció por primera vez en la biblioteca libspe2.

NOTAS

Esta función solo es relevante en sistemas que tienen hardware SPE (como la arquitectura Cell Broadband Engine).

Es importante asegurarse de que el programa cargado en el SPE se maneje correctamente y libere los recursos antes de finalizar.
