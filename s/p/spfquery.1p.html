SPFQUERY(1) Documentación de Perl contribuida por el usuario SPFQUERY(1)

NOMBRE

spfquery - (Mail::SPF) - Comprueba si un conjunto dado de parámetros de correo electrónico coincide con la política SPF de un dominio.

VERSIÓN

versión 3.20250505

SINOPSIS

Uso preferido:
spfquery [--versiones|-v 1|2|1,2] [--ambito|-s helo|mfrom|pra] --identidad|--id identidad --direccion-ip|--ip direccion-ip [--identidad-helo|--id-helo identidad-helo] [OPCIONES]

spfquery [--versiones|-v 1|2|1,2] [--ambito|-s helo|mfrom|pra] --archivo|-f nombre-archivo|- [OPCIONES]

Uso heredado:
spfquery --helo identidad-helo --direccion-ip|--ip direccion-ip [OPCIONES]

spfquery --mfrom identidad-mfrom --direccion-ip|--ip direccion-ip [--helo identidad-helo] [OPCIONES]

spfquery --pra identidad-pra --direccion-ip|--ip direccion-ip [OPCIONES]

Otro uso:
spfquery --version|-V

spfquery --help

DESCRIPCIÓN

spfquery comprueba si un conjunto dado de parámetros de correo electrónico (por ejemplo, la dirección IP del remitente SMTP) coincide con la política SPF del dominio responsable. Para más información sobre SPF, consulte https://tools.ietf.org/html/rfc7208.

Uso Preferido

Las siguientes formas de uso son preferidas sobre las formas heredadas utilizadas por versiones anteriores de spfquery:

La forma --identidad comprueba si la direccion-ip dada es un remitente SMTP autorizado para el nombre de host "helo", la dirección de correo electrónico del remitente del sobre "mfrom" o la dirección de correo electrónico "pra" (denominada dirección responsable supuesta), dependiendo del valor de la opción --ambito (que por defecto es mfrom si se omite).

La forma --archivo lee tuplas de "direccion-ip identidad [identidad-helo]" del archivo con el nombre-archivo especificado, o de la entrada estándar si nombre-archivo es -, y las comprueba con el ámbito especificado (mfrom por defecto).

Ambas formas admiten una opción opcional --versiones, que especifica una lista separada por comas de los números de versión SPF de los registros SPF que se pueden utilizar. 1 significa que se deben utilizar los registros "v=spf1". 2 significa que se deben utilizar los registros "spf2.0". Por defecto es 1,2, es decir, utiliza cualquier registro SPF disponible. Se prefieren los registros de una versión superior.

Uso Heredado

Las versiones de spfquery anteriores a la 2.500 presentaban las siguientes formas de uso, que se desaconsejan pero aún se admiten por compatibilidad con versiones anteriores:

La forma --helo comprueba si la direccion-ip dada es un remitente SMTP autorizado para el nombre de host "HELO" dado como identidad (llamado comprobación "HELO").

La forma --mfrom comprueba si la direccion-ip dada es un remitente SMTP autorizado para la dirección de correo electrónico del remitente del sobre (o dominio) dada como identidad (llamada comprobación "MAIL FROM"). Si se proporciona un dominio en lugar de una dirección de correo electrónico, se sustituirá "postmaster" por la parte local.

La forma --pra comprueba si la direccion-ip dada es un remitente SMTP autorizado para la dirección de correo electrónico PRA (Dirección Responsable Supuesta) dada como identidad.

Otro Uso

La forma --version imprime información de la versión de spfquery. La forma --help imprime información de uso para spfquery.

OPCIONES

Opciones Estándar

Las formas preferidas y heredadas pueden tomar opcionalmente cualquiera de las siguientes OPCIONES:

--explicacion-predeterminada cadena
--exp-pred cadena
Utiliza la cadena especificada como explicación predeterminada si el dominio de autoridad no especifica su propia cadena de explicación.
--nombre-host nombre-host
Utiliza nombre-host como nombre de host del sistema local en lugar de detectarlo automáticamente.
--mantener-comentarios
--no-mantener-comentarios
Imprime (o no) cualquier comentario encontrado al leer desde un archivo o desde la entrada estándar.
--sanitizar (actualmente ignorado)
--no-sanitizar (actualmente ignorado)
Limpia (o no) la salida condensando los espacios en blanco consecutivos en un solo espacio y reemplazando los caracteres no imprimibles por signos de interrogación. Habilitado por defecto.
--depurar (actualmente ignorado)
Imprime información de depuración.

Opciones de Magia Negra

Varias opciones que eran compatibles con versiones anteriores de spfquery se consideran magia negra (es decir, potencialmente peligrosas para el usuario inocente) y, por lo tanto, están deshabilitadas por defecto. Si está instalado el módulo Perl Mail::SPF::BlackMagic (módulo actualmente no disponible), se pueden habilitar especificando --enable-magia-negra.

--max-terminos-dns-interactivos n
Evalúa un máximo de n mecanismos y modificadores DNS interactivos por comprobación SPF. Por defecto es 10. ¡No anule el valor predeterminado a menos que sepa lo que está haciendo!
--max-busquedas-nombre-por-termino n
Realiza un máximo de n búsquedas de nombres DNS por mecanismo o modificador. Por defecto es 10. ¡No anule el valor predeterminado a menos que sepa lo que está haciendo!
--autorizar-mx-para direccion-correo|dominio,...
Considera todos los MX de la lista separada por comas de direcciones-correo y dominios como intrínsecamente autorizados.
--tfwl
Realiza la comprobación de acreditación de "trusted-forwarder.org".
--adivinar terminos-spf
Utiliza terminos-spf como registro predeterminado si no se encuentra ningún registro SPF.
--local terminos-spf
Procesa terminos-spf como política local antes de recurrir a un resultado predeterminado (el mecanismo "all" implícito o explícito al final del registro SPF del dominio). Por ejemplo, esto podría utilizarse para incluir en la lista blanca de los MX secundarios: "mx:midominio.ejemplo.org".
--anular dominio=registro-spf
--fallback dominio=registro-spf
Establece anulaciones y fallbacks. Cada opción se puede especificar varias veces. Por ejemplo: 
--anular ejemplo.org='v=spf1 -all'
--fa

spfquery(1p) — Arch Linux man pages

NAME

spfquery — query SPF records

VERSION

2.904

SYNOPSIS

spfquery [--scope scope] [--identity identity] [--ip ip_address] [--helo helo_identity] [--file file_name] [--no-multiline] [--verbose] [--debug] [--version] [--help]

DESCRIPTION

spfquery is a command-line tool that queries the SPF (Sender Policy Framework) records for a given identity. It can perform checks for different scopes (e.g., the MAIL FROM address, the HELO hostname, or the receiving client's IP address).

SPF records are published in the DNS and specify which mail servers are authorized to send mail for a given domain. spfquery allows you to manually test these policies.

The tool determines the SPF result by querying the DNS for the specified identity and comparing the connecting IP address against the published policy.

Preferred usage

The preferred way to perform individual SPF checks is by using the --identity and --scope options:

 spfquery --scope mfrom --identity user@example.com --ip 1.2.3.4
 spfquery --scope helo --identity mail.example.com --ip 1.2.3.4
 spfquery --scope rcpt --identity user@example.com --ip 1.2.3.4

Legacy usage

Older versions of spfquery used separate options for different scopes:

 spfquery --mfrom user@example.com --ip 1.2.3.4
 spfquery --helo mail.example.com --ip 1.2.3.4
 spfquery --rcpt user@example.com --ip 1.2.3.4

Note that the --rcpt scope is not fully supported by the SPF standard and may yield unexpected results.

Checking multiple records

You can check multiple SPF records from a file or standard input:

 spfquery --file spf_records.txt
 cat spf_records.txt | spfquery
 echo "1.2.3.4 user@example.com mail.example.com" | spfquery --file -

Each line in the input file or standard input should contain:

 ip_address identity helo_identity

The identity and helo_identity are optional.

Fallback mechanism

spfquery supports the SPF fallback mechanism, which allows you to specify a default SPF record to use if no specific record is found for a given domain.

For example, to use v=spf1 a mx -all for all subdomains of example.net and v=spf1 -all as a fallback for example.com:

<<SPF_FALLBACK>>

erride '*.example.net'='v=spf1 a mx -all'
--fallback example.com='v=spf1 -all'

OPTIONS

--scope scope
Specifies the scope of the identity to check. Valid values are mfrom (MAIL FROM), helo, and rcpt (RCPT TO). The default is mfrom.
--identity identity
Specifies the identity (e.g., an email address like user@example.com) for which to check the SPF record. This option is used in conjunction with --scope.
--ip ip_address
Specifies the IP address of the connecting server. If not specified, spfquery will attempt to determine it from the environment or default to 127.0.0.1.
--helo helo_identity
Specifies the HELO identity (e.g., a hostname like mail.example.com). This is used when the scope is helo. If not specified and the scope is helo, spfquery will use the identity value.
--file file_name
Read SPF checks from the specified file. Use --file - to read from standard input.
--no-multiline
Do not allow multiline SPF records. SPF records are typically single-line DNS TXT records, but some implementations might support multiline records. This option disables that support.
--verbose
Enable verbose output, showing more details about the SPF check process.
--debug
Enable debug output. This option is currently ignored.
--version
Print version information and exit.
--help
Print a help message and exit.

RESULT CODES

pass
The specified IP address is an authorized SMTP sender for the identity.
fail
The specified IP address is not an authorized SMTP sender for the identity.
softfail
The specified IP address is not an authorized SMTP sender for the identity, however the authority domain is still testing out its SPF policy.
neutral
The identity's authority domain makes no assertion about the status of the IP address.
permerror
A permanent error occurred while evaluating the authority domain's policy (e.g., a syntax error in the SPF record). Manual intervention is required from the authority domain.
temperror
A temporary error occurred while evaluating the authority domain's policy (e.g., a DNS error). Try again later.
none
There is no applicable SPF policy for the identity domain.

EXIT CODES

 Result    | Exit code
-----------+-----------
 pass      |     0
 fail      |     1
 softfail  |     2
 neutral   |     3
 permerror |     4
 temperror |     5
 none      |     6

EXAMPLES

spfquery --scope mfrom --id user@example.com --ip 1.2.3.4
spfquery --file test_data
echo "127.0.0.1 user@example.com helohost.example.com" | spfquery -f -

COMPATIBILITY

spfquery has undergone the following interface changes compared to earlier versions:

2.500
  • A new preferred usage style for performing individual SPF checks has been introduced. The new style accepts a unified --identity option and an optional --scope option that specifies the type (scope) of the identity. In contrast, the legacy usage style requires a separate usage form for every supported scope. See "Preferred usage" and "Legacy usage" for details.
  • The former "unknown" and "error" result codes have been renamed to "permerror" and "temperror", respectively, in order to comply with RFC 4408 terminology.
  • SPF checks with an empty identity are no longer supported. In the case of an empty "MAIL FROM" SMTP transaction parameter, perform a check with the "helo" scope directly.
  • The --debug and --(no-)sanitize options are currently ignored by this version of spfquery. They will again be supported in the future.
  • Several features that were supported by earlier versions of spfquery are considered black magic and thus are now disabled by default. See "Black Magic Options".
  • Several option names have been deprecated. This is a list of them and their preferred synonyms: 
     Deprecated options  | Preferred options
---------------------+-----------------------------
 --sender, -s        | --mfrom
 --ipv4, -i          | --ip-address, --ip
 --name              | --hostname
 --max-lookup-count, | --max-dns-interactive-terms
   --max-lookup      |
 --rcpt-to, -r       | --authorize-mxes-for
 --trusted           | --tfwl
