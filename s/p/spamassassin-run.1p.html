NOMBRE

spamassassin - script de filtro frontend simple para SpamAssassin

SINOPSIS

spamassassin [opciones] [ < mensaje de correo | ruta ... ]

spamassassin -d [ < mensaje de correo | ruta ... ]

spamassassin -r [ < mensaje de correo | ruta ... ]

spamassassin -k [ < mensaje de correo | ruta ... ]

spamassassin -W|-R [ < mensaje de correo | ruta ... ]

Opciones:

-L, --local                       Solo pruebas locales (sin pruebas en línea)
-r, --report                      Reportar mensaje como spam
-k, --revoke                      Revocar mensaje como spam
-d, --remove-markup               Eliminar reportes de spam de un mensaje
-C ruta, --configpath=ruta, --config-file=ruta
                                  Ruta al directorio de configuración estándar
-p prefs, --prefspath=archivo, --prefs-file=archivo
                                  Establecer archivo de preferencias del usuario
--siteconfigpath=ruta             Ruta para configuraciones del sitio
                                  (por defecto: /etc/mail/spamassassin)
--cf='línea de configuración'    Línea de configuración adicional
--pre='línea de configuración'   Línea de ".pre" adicional (antepuesta a la configuración)
-x, --nocreate-prefs              No crear archivo de preferencias del usuario
-e, --exit-code                   Salir con un código de salida distinto de cero si el
                                  mensaje probado fue spam
--mbox                            leer mensajes en formato mbox
--mbx                             leer mensajes en formato UW mbx
-t, --test-mode                   Enviar mensaje a través de un pipe y añadir un reporte
                                  adicional al final
--lint                            Verificar la sintaxis del conjunto de reglas: reportar errores de sintaxis
-W, --add-to-welcomelist          Añadir direcciones en el correo a la lista de bienvenida persistente
--add-to-blocklist                Añadir direcciones en el correo a la lista de bloqueo persistente
-R, --remove-from-welcomelist     Eliminar todas las direcciones encontradas en el correo de la lista de bienvenida persistente
--add-addr-to-welcomelist=dir     Añadir dir a la lista de bienvenida persistente
--add-addr-to-blocklist=dir       Añadir dir a la lista de bloqueo persistente
--remove-addr-from-welcomelist=dir Eliminar dir de la lista de bienvenida persistente
-u usuario, --username=usuario  Sobrescribir nombre de usuario tomado del entorno de ejecución
                                  usado con SQL
-4 --ipv4only, --ipv4-only, --ipv4 Usar IPv4, deshabilitar el uso de IPv6 para DNS etc.
-6                                Usar IPv6, deshabilitar el uso de IPv4 donde sea posible
--progress                        Mostrar barra de progreso
-D, --debug [area,...]            Mostrar mensajes de depuración
-V, --version                     Mostrar versión
-h, --help                        Mostrar mensaje de uso

DESCRIPCIÓN

spamassassin es un filtro frontend simple para SpamAssassin.

Usando la base de reglas de SpamAssassin, utiliza una amplia gama de pruebas heurísticas en las cabeceras y el cuerpo del correo electrónico para identificar "spam", también conocido como correo electrónico masivo no solicitado. Una vez identificado, el correo se marca como spam para su posterior filtrado utilizando la aplicación del agente de usuario de correo del propio usuario.

Las operaciones de etiquetado predeterminadas que se llevan a cabo se detallan en "TAGGING" en spamassassin.

Por defecto, los mensajes se leen desde STDIN (< mensaje de correo), o desde archivos y directorios especificados (ruta ...) STDIN y archivos se asumen en formato de archivo, con un solo mensaje por archivo. Los directorios se asumen en un formato donde cada archivo en el directorio contiene solo un mensaje (los directorios no se recorren recursivamente y se omiten los nombres de archivo que contienen espacios en blanco o que comienzan con "." o ","). Las opciones --mbox y --mbx pueden sobrescribir el formato asumido, ver la información de OPCIÓN apropiada a continuación.

Los archivos comprimidos con gzip/bzip2/xz/lz4/lzip/lzo se descomprimen automáticamente. Ver "Mail::SpamAssassin::ArchiveIterator" para más detalles.

Tenga en cuenta que SpamAssassin no está diseñado para escanear mensajes enormes. No se deben alimentar a SpamAssassin mensajes de más de ~10-20 MB, ya que el consumo de memoria aumentará rápidamente.

OPCIONES

-e, --error-code, --exit-code
Salir con un código de error distinto de cero si el mensaje se determina que es spam.
-h, --help
Mostrar mensaje de ayuda y salir.
-V, --version
Mostrar versión y salir.
-t, --test-mode
Modo de prueba. Enviar mensaje a través de un pipe y añadir un reporte adicional. Tenga en cuenta que el texto del reporte asume que el mensaje es spam, ya que en uso normal solo es visible en este caso. Preste atención a la puntuación en su lugar.

Si ejecuta esto con -d, el mensaje primero tendrá el marcado de SpamAssassin eliminado antes de ser probado.

-r, --report
Reportar este mensaje como spam verificado manualmente. Esto enviará el mensaje de correo electrónico leído desde STDIN a varias bases de datos de bloqueo de spam. Actualmente, estas son Distributed Checksum Clearinghouse "https://www.dcc-servers.net/dcc/", Pyzor "https://www.pyzor.org/", Vipul's Razor "http://razor.sourceforge.net/", y SpamCop "https://www.spamcop.net/".

Si el mensaje contiene marcado de SpamAssassin, el marcado se eliminará automáticamente antes de la presentación. Los módulos de soporte para DCC, Pyzor y Razor deben estar instalados para que el spam se reporte a cada servicio. Los reportes de SpamCop tendrán mayor efecto si se registra y se establece la opción "spamcop_to_address".

El mensaje también se enviará a los sistemas de aprendizaje de SpamAssassin; actualmente este es el sistema de filtrado estadístico bayesiano interno (las reglas BAYES). (Tenga en cuenta que si *solo* desea realizar aprendizaje estadístico, y no desea reportar correos electrónicos a terceros, debe usar el comando "sa-learn" directamente en su lugar.)

-k, --revoke
Revocar este mensaje. Esto revocará el mensaje de correo electrónico leído desde STDIN de varias bases de datos de bloqueo de spam. Actualmente, estas son Vipul's Razor.

El soporte de revocación para Distributed Checksum Clearinghouse, Pyzor y SpamCop no está disponible actualmente.

Si el mensaje contiene marcado de SpamAssassin, el marcado se eliminará automáticamente antes de la presentación. Los módulos de soporte para Razor deben estar instalados para que el spam se revoque del servicio.

El mensaje también se presentará como 'ham' (no spam) a los sistemas de aprendizaje de SpamAssassin; actualmente este es el sistema de filtrado estadístico bayesiano interno (las reglas BAYES). (Tenga en cuenta que si *solo* desea realizar aprendizaje estadístico, y no desea reportar correos electrónicos a terceros, debe usar el comando "sa-learn" directamente en su lugar.)

--lint
Comprobación de sintaxis (lint) del conjunto de reglas y archivos de configuración, reportando errores tipográficos y reglas que no compilan correctamente. Sale con 0 si no hay errores, o mayor que 0 si se encuentran errores.
-W, --add-to-welcomelist
Anteriormente --add-to-whitelist que funcionará de forma intercambiable hasta la versión 4.1.

Añade todas las direcciones de correo electrónico, en las cabeceras y el cuerpo del mensaje de correo leído desde STDIN, a una lista de bienvenida persistente. Tenga en cuenta que debe estar ejecutando "spamassassin" o "spamd" con un plugin de lista de direcciones persistente habilitado para que esto funcione.

--add-to-blocklist
Anteriormente --add-to-blacklist que funcionará de forma intercambiable hasta la versión 4.1.

Añade todas las direcciones de correo electrónico, en las cabeceras y el cuerpo del mensaje de correo leído desde STDIN, a la lista de bloqueo persistente de direcciones. Tenga en cuenta que debe estar ejecutando "spamassassin" o "spamd" con un plugin de lista persistente

NAME

spamassassin – SpamAssassin mail filter

SYNOPSIS

spamassassin [options] [mail-file ...]

DESCRIPTION

spamassassin is a mail filter that identifies spam messages using a variety of heuristic analysis and blacklists.

spamassassin is intended to be used as a filter program, passed a mail message via standard input, and outputting the (possibly modified) mail message to standard output. It scores the message according to the rules enabled in its configuration files, and adds appropriate headers indicating the spam score and actions taken. It may also modify the message body, or not pass it through at all, depending on the configuration.

When checking mail, SpamAssassin determines scores for the mail message via tests. Some tests require network access, such as DNS lookups for blacklists. Other tests only require local processing.

When checking mail with the spamassassin program, options can be used to control which tests are run, where configuration files are read from, and how the results are presented. The default behaviour is to run all enabled tests and print the modified message to standard output.

OPTIONS

-A, --add-to-welcomelist
Previously —add-to-whitelist— which will work interchangeably until 4.1.

Add all email addresses, in the headers and body of the mail message read from STDIN, to a persistent address welcomelist. STDIN must contain a full email message, so to add a single address you should use --add-addr-to-welcomelist instead.

Note that you must be running "spamassassin" or "spamd" with a persistent address list plugin enabled for this to work.

-R, --remove-from-welcomelist
Previously —remove-from-whitelist— which will work interchangeably until 4.1.

Remove all email addresses, in the headers and body of the mail message read from STDIN, from a persistent address list. STDIN must contain a full email message, so to remove a single address you should use --remove-addr-from-welcomelist instead.

Note that you must be running "spamassassin" or "spamd" with a persistent address list plugin enabled for this to work.

--add-addr-to-welcomelist
Previously —add-addr-to-whitelist— which will work interchangeably until 4.1.

Add the named email address to a persistent address welcomelist. Note that you must be running "spamassassin" or "spamd" with a persistent address list plugin enabled for this to work.

--add-addr-to-blocklist
Previously —add-addr-to-blacklist— which will work interchangeably until 4.1.

Add the named email address to a persistent address blocklist. Note that you must be running "spamassassin" or "spamd" with a persistent address list plugin enabled for this to work.

--remove-addr-from-welcomelist
Previously —remove-addr-from-whitelist— which will work interchangeably until 4.1.

Remove the named email address from a persistent address welcomelist. Note that you must be running "spamassassin" or "spamd" with a persistent address list plugin enabled for this to work.

-u username, --username=username
If specified this username will override the username taken from the runtime environment. You can use this option to specify users in a virtual user configuration when using SQL as the Bayes backend.

NOTE: This option will not change to the given username, it will only attempt to act on behalf of that user. Because of this you will need to have proper permissions to be able to change files owned by username. In the case of SQL this generally is not a problem.

--ipv4only, --ipv4-only, --ipv4
Do not use IPv6 for DNS tests. Normally, SpamAssassin will try to detect if IPv6 is available, using only IPv4 if it is not. Use if the existing tests for IPv6 availability produce incorrect results or crashes.
-L, --local
Do only the “local” tests, ones that do not require an internet connection to operate. Normally, SpamAssassin will try to detect whether you are connected to the net before doing these tests anyway, but for faster checks you may wish to use this.

Note that SpamAssassin’s network rules are run in parallel. This can cause overhead in terms of the number of file descriptors required if --local is not used; it is recommended that the minimum limit on fds be raised to at least 256 for safety.

-d, --remove-markup
Remove SpamAssassin markup (the "SpamAssassin results" report, X-Spam-Status headers, etc.) from the mail message. The resulting message, which will be more or less identical to the original, pre-SpamAssassin input, will be output to STDOUT.

(Note: the message will not be exactly identical; some headers will be reformatted due to some features of the Mail::Internet package, but the body text will be.)

-C path, --configpath=path, --config-file=path
Use the specified path for locating the distributed configuration files. Ignore the default directories (usually "/usr/share/spamassassin" or similar).
--siteconfigpath=path
Use the specified path for locating site-specific configuration files. Ignore the default directories (usually "/etc/mail/spamassassin" or similar).
--cf='config line'
Add additional lines of configuration directly from the command-line, parsed after the configuration files are read. Multiple --cf arguments can be used, and each will be considered a separate line of configuration. For example: 
spamassassin -t --cf="body NEWRULE /text/" --cf="score NEWRULE 3.0"
--pre='config line'
Add additional lines of .pre configuration directly from the command-line, parsed before the configuration files are read. Multiple --pre arguments can be used, and each will be considered a separate line of configuration. For example: 
spamassassin -t --pre="loadplugin Mail::SpamAssassin::Plugin::Foobar"
-p prefs, --prefspath=prefs, --prefs-file=prefs
Read user score preferences from prefs (usually "$HOME/.spamassassin/user_prefs").
--progress
Prints a progress bar (to STDERR) showing the current progress. This option will only be useful if you are redirecting STDOUT (and not STDERR). In the case where no valid terminal is found this option will behave very much like the --showdots option in other SpamAssassin programs.
-D [area,...], --debug [area,...]
Produce debugging output. If no areas are listed, all debugging information is printed. Diagnostic output can also be enabled for each area individually; area is the area of the code to instrument. For example, to produce diagnostic output on bayes, learn, and dns, use: 
spamassassin -D bayes,learn,dns

Use an empty string (-D '') to indicate no areas when the next item on the command line is a path, to prevent the path from being parsed as an area.

Higher priority informational messages that are suitable for logging in normal circumstances are available with an area of "info".

For more information about which areas (also known as channels) are available, please see the documentation at:

L<https://wiki.apache.org/spamassassin/DebugChannels>
-x, --nocreate-prefs
Disable creation of user preferences file.
--mbox
Specify that the input message(s) are in mbox format. mbox is a standard Unix message folder format.
--mbx
Specify that the input message(s) are in UW .mbx format. mbx is the mailbox format used within the University of Washington’s IMAP implementation; see "https://en.wikipedia.org/wiki/UW_IMAP".
