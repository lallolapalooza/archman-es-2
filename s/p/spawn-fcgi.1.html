NOMBRE

spawn-fcgi - Inicia procesos FastCGI

SINOPSIS

spawn-fcgi [opciones] [ -- <fcgiapp> [argumentos de la aplicación fcgi]]

spawn-fcgi -v

spawn-fcgi -h

DESCRIPCIÓN

spawn-fcgi se utiliza para iniciar procesos FastCGI remotos y locales.

Aunque obviamente es necesario para iniciar backends FastCGI remotos (el servidor web solo puede iniciar los locales), se recomienda iniciar también los backends locales con spawn-fcgi.

Razones por las que podrías querer usar spawn-fcgi en lugar de otra cosa:

  • Separación de privilegios sin necesidad de un binario suid o de ejecutar un servidor como root.
  • Puedes reiniciar tu servidor web y las aplicaciones FastCGI sin reiniciar los otros.
  • Puedes ejecutarlos en diferentes chroot().
  • Ejecutar tus aplicaciones FastCGI no depende del servidor web que estés ejecutando, lo que permite probar más fácilmente otros servidores web.

OPCIONES

spawn-fcgi acepta las siguientes opciones:

-f <ruta>
Nombre del archivo de la aplicación FastCGI a iniciar. Esta opción está obsoleta y se recomienda especificar siempre la aplicación (ruta absoluta) y sus parámetros después de "--"; el parámetro fcgiapp se usa directamente para la llamada exec(), mientras que para iniciar el binario dado con -f se necesita /bin/sh (que puede no estar disponible en un chroot).
Esta opción se ignora si se proporciona fcgiapp.
-d <ruta>
Cambiar el directorio actual antes de iniciar la aplicación.
-a <dirección>
Dirección IPv4/IPv6 a la que enlazar; solo se usa si también se proporciona -p. Por defecto es "0.0.0.0" (IPv4).
-p <puerto>
Puerto TCP al que enlazar; no puedes combinar esto con la opción -s.
-s <ruta>
Ruta al socket de dominio Unix al que enlazar; no puedes combinar esto con la opción -p.
-C <hijos>
(Solo PHP) Número de hijos a iniciar estableciendo la variable de entorno PHP_FCGI_CHILDREN. Por defecto, no se sobrescribe la variable de entorno; php no iniciará ningún hijo si la variable no está establecida (lo mismo que establecerla a 0).
-F <hijos>
Número de hijos a bifurcar, por defecto es 1. Esta opción no funciona con -n; echa un vistazo a multiwatch(1) si quieres supervisar múltiples bifurcaciones en el mismo socket.
-b <cola>
Cola permitida en el socket (por defecto 1024). Esto suele estar limitado también por el kernel, comprueba sysctl net.core.somaxconn (por defecto 128) para linux.
La cola es la lista de espera de conexiones que el kernel acepta antes de que la aplicación en el espacio de usuario las vea.
-P <ruta>
Nombre del archivo PID para los procesos iniciados (ignorado en modo sin bifurcación)
-n
No se deben realizar bifurcaciones (para daemontools)
-M <modo>
Cambiar el modo de archivo del socket de dominio Unix (entero octal); solo se usa si también se proporciona -s. Por defecto es lectura/escritura para usuario y grupo (0660) en la medida que la umask lo permita.
-?, -h
Instrucciones generales de uso
-v
Muestra información de la versión y sale

Las siguientes opciones solo están disponibles si invocas spawn-fcgi como root:

-c <directorio>
Chroot al directorio especificado; el socket de dominio Unix se crea dentro del chroot a menos que se proporcione -S.
-S
Crear el socket de dominio Unix antes del chroot().
-u
ID de usuario al que cambiarse.
-g
ID de grupo al que cambiarse. Por defecto es el grupo principal del usuario dado para -u.
-U
Cambiar el usuario del socket de dominio Unix, por defecto es el valor de -u. (solo se usa si se proporciona -s)
-G
Cambiar el grupo del socket de dominio Unix, por defecto es el grupo principal del usuario dado para -U; si no se proporcionó -U, por defecto es el valor de -g. (solo se usa si se proporciona -s)
