SPLIT(1P) Manual del Programador POSIX SPLIT(1P)

PROLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

split — dividir un archivo en partes

SINOPSIS

split [-l conteo_lineas] [-a longitud_sufijo] [archivo [nombre]]
split -b n[k|m] [-a longitud_sufijo] [archivo [nombre]]

DESCRIPCIÓN

La utilidad split leerá un archivo de entrada y escribirá cero o más archivos de salida. El tamaño predeterminado de cada archivo de salida será de 1000 líneas. El tamaño de los archivos de salida se puede modificar especificando las opciones -b o -l. Cada archivo de salida se creará con un sufijo único. El sufijo consistirá en exactamente longitud_sufijo letras minúsculas del locale POSIX. Las letras del sufijo se utilizarán como si fueran un sistema de dígitos de base 26, siendo el primer sufijo que se creará constituido por todas las 'a', el segundo con una 'b' reemplazando la última 'a', y así sucesivamente, hasta que se cree un nombre con todas las 'z'. Por defecto, los nombres de los archivos de salida serán 'x', seguido de un sufijo de dos caracteres del conjunto de caracteres descrito anteriormente, comenzando con "aa", "ab", "ac", y así sucesivamente, y continuando hasta el sufijo "zz", para un máximo de 676 archivos.

Si el número de archivos requeridos excede el máximo permitido por la longitud de sufijo proporcionada, de manera que el último archivo permitido sea más grande que el tamaño solicitado, la utilidad split fallará después de crear el último archivo con un sufijo válido; split no eliminará los archivos que creó con sufijos válidos. Si el límite de archivos no se excede, el último archivo creado contendrá el resto del archivo de entrada y puede ser más pequeño que el tamaño solicitado. Si la entrada es un archivo vacío, no se creará ningún archivo de salida y esto no se considerará un error.

OPCIONES

La utilidad split se ajustará a las Definiciones Base del volumen de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis de Utilidades.

Se admitirán las siguientes opciones:

-a longitud_sufijo

Utilice longitud_sufijo letras para formar la porción del sufijo de los nombres de archivo del archivo dividido. Si no se especifica -a, la longitud de sufijo predeterminada será dos. Si la suma del operando nombre y el argumento de opción longitud_sufijo creara un nombre de archivo que excediera los bytes {NAME_MAX}, se producirá un error; split saldrá con un mensaje de diagnóstico y no se crearán archivos.
-b n
Dividir un archivo en piezas de n bytes de tamaño.
-b nk
Dividir un archivo en piezas de n*1024 bytes de tamaño.
-b nm
Dividir un archivo en piezas de n*1048576 bytes de tamaño.
-l conteo_lineas
Especificar el número de líneas en cada pieza de archivo resultante. El argumento conteo_lineas es un entero decimal sin signo. El valor predeterminado es 1000. Si la entrada no termina con una <nueva línea>, la línea parcial se incluirá en el último archivo de salida.

OPRANDS

Se admitirán los siguientes operandos:

archivo
La ruta del archivo ordinario que se dividirá. Si no se proporciona ningún archivo de entrada o archivo es '-', se utilizará la entrada estándar.
nombre
El prefijo que se utilizará para cada uno de los archivos resultantes de la operación de división. Si no se proporciona ningún argumento nombre, 'x' se utilizará como prefijo de los archivos de salida. La longitud combinada del nombre base de prefijo y longitud_sufijo no puede exceder los bytes {NAME_MAX}. Véase la sección OPCIONES.

ENTRADA ESTANDAR

Véase la sección ARCHIVOS DE ENTRADA.

ARCHIVOS DE ENTRADA

Se puede utilizar cualquier archivo como entrada.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de split:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no estén definidas o estén vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de locale.)
LC_ALL
Si se establece en un valor de cadena no vacío, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar el locale para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en argumentos y archivos de entrada).
LC_MENSAJES

Determinar el locale que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MENSAJES.

EVENTOS ASINCRONOS

Predeterminado.

SALIDA ESTANDAR

No se utiliza.

ERROR ESTANDAR

El error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Los archivos de salida contienen porciones del archivo de entrada original; de lo contrario, sin cambios.

EJEMPLOS

En los siguientes ejemplos, foo es un archivo de texto que contiene 5000 líneas.

1.
Crear cinco archivos, xaa, xab, xac, xad y xae:
split foo
2.
Crear cinco archivos, pero la porción sufijada de los archivos creados consta de tres letras, xaaa, xaab, xaac, xaad y xaae:
split -a 3 foo
3.
Crear tres archivos con sufijos de cuatro letras y un prefijo proporcionado, bar_aaaa, bar_aaab y bar_aaac:
> 
split -a 4 -l 2000 foo bar_
4.
Crear tantos archivos como sean necesarios para contener como máximo 20*1024 bytes, cada uno con el prefijo predeterminado de x y un sufijo de cinco letras:
split -a 5 -b 20k foo

FUNDAMENTO

La opción -b se añadió para proporcionar un mecanismo para dividir archivos que no fuera por líneas. Mientras que la mayoría de los usos de la opción -b son para transmitir archivos a través de redes, algunos creían que tendría usos adicionales.

La opción -a se añadió para superar la limitación de poder crear solo 676 archivos.

Se consideró la posibilidad de eliminar esta utilidad, utilizando como argumento que la funcionalidad proporcionada por esta utilidad está disponible a través de la utilidad csplit (ver csplit). Tras reconsiderar el propósito de la opción de Utilidades de Portabilidad del Usuario, se decidió retener tanto esta utilidad como la utilidad csplit porque los usuarios utilizan ambas utilidades y tienen expectativas históricas de su comportamiento. Además, la división por límites de bytes en split no se puede duplicar con la utilidad histórica csplit.

El texto ``split no eliminará los archivos que creó con sufijos válidos'' se asumiría normalmente, pero dado que la utilidad relacionada, csplit, sí elimina archivos en algunas circunstancias, el comportamiento histórico de split se hace explícito para evitar malas interpretaciones.

Las versiones anteriores de este estándar permitían una opción -número_líneas. Esta forma ya no se especifica en POSIX.1‐2008 pero puede estar presente en algunas implementaciones.
