SPIPED(1) README de spiped SPIPED(1)

NOMBRE

spiped - demonio de tubería segura

SINOPSIS

spiped {-e | -d} -s <socket de origen> -t <socket de destino> -k <archivo de clave>
[-DFj] [-b <dirección de enlace>] [-f | -g] [-n <conexiones máximas>]
[-o <tiempo de espera de conexión>] [-p <archivo PID>] [-r <tiempo de reresolución> | -R] [--syslog]
[-u <nombre de usuario> | <:nombre de grupo> | <nombre de usuario:nombre de grupo>]
spiped -v

OPCIONES

-e
Aceptar conexiones sin cifrar del socket de origen y enviar conexiones cifradas al socket de destino.
-d
Aceptar conexiones cifradas del socket de origen y enviar conexiones sin cifrar al socket de destino.
-s <socket de origen>
Dirección en la que spiped debe escuchar las conexiones entrantes. Los formatos aceptados son los mismos que los aceptados por el socket de destino. Tenga en cuenta que a diferencia del socket de destino, los nombres de host se resuelven cuando se lanza spiped y no se vuelven a resolver más tarde; por lo tanto, si las entradas de DNS cambian, spiped continuará aceptando conexiones en la dirección caducada.
-t <socket de destino>
Dirección a la que spiped debe conectarse. Debe estar en uno de los siguientes formatos:
  • /ruta/absoluta/al/socket/unix
  • nombredehost:puerto
  • [dir.ipv4.a.a]:puerto
  • [ipv6::dir]:puerto
Los nombres de host se vuelven a resolver cada tiempo de resolución segundos.
-k <archivo de clave>
Utilice el archivo de clave proporcionado para autenticar y cifrar. Pase "-" para leer de la entrada estándar.
-b <dirección de enlace>
Enlazar la dirección de salida. Si se trata de una dirección de red, el número de puerto puede especificarse o dejarse al sistema operativo. Si especifica el número de puerto, el sistema operativo no le permitirá abrir una segunda conexión hasta que la primera haya expirado por completo (es decir, el estado TCP ya no esté en estado TIME-WAIT).
-D
Esperar a DNS. Normalmente, cuando se lanza spiped, resuelve direcciones y se enlaza a su socket de origen antes de que el proceso padre devuelva; con esta opción, se demonizará primero e intentará de nuevo las búsquedas de DNS fallidas hasta que tengan éxito. Esto permite que spiped se inicie incluso si DNS no está configurado aún, pero a costa de perder la garantía de que una vez que spiped haya terminado de iniciarse estará listo para crear tuberías.
-f
Utilizar handshake rápido/débil: esto reduce el tiempo de CPU dedicado a la configuración inicial de la conexión al deshabilitar el handshake de Diffie-Hellman, a costa de perder la confidencialidad directa perfecta.
-g
Requerir confidencialidad directa perfecta descartando conexiones si el otro host está utilizando la opción -f.
-F
Ejecutar en primer plano. Esto puede ser útil con sistemas como daemontools.
-j
Deshabilitar los keep-alive de la capa de transporte. (Por defecto están habilitados).
-n <máximo # de conexiones>
Límite en el número de conexiones simultáneas permitidas. Un valor de 0 indica que no se debe imponer ningún límite; esto puede ser desaconsejable en algunas circunstancias, ya que spiped terminará si no puede asignar memoria para manejar una nueva conexión. El valor por defecto es 100 conexiones.
-o <tiempo de espera de conexión>
Tiempo de espera, en segundos, después del cual un intento de conectarse al destino o un handshake de protocolo se cancelará (y la conexión se descartará) si no se completa. El valor por defecto es 5s.
-p <archivo PID>
Archivo al que se debe escribir el ID de proceso de spiped. Por defecto, es socket de origen.pid (en el directorio actual si socket de origen no es una ruta absoluta). No se escribirá ningún archivo si se utiliza -F (ejecutar en primer plano).
-r <tiempo de resolución>
Vuelve a resolver la dirección del socket de destino cada tiempo de resolución segundos. El valor por defecto es la resolución cada 60 segundos.
-R
Deshabilitar la resolución de direcciones de destino.
--syslog
Después de demonizarse, enviar advertencias a syslog en lugar de a stderr. No tiene ningún efecto si se utiliza -F (ejecutar en primer plano).
-u <nombre de usuario> | <:nombre de grupo> | <nombre de usuario:nombre de grupo>
Después de enlazar un socket, cambiar el usuario a nombre de usuario y/o el grupo a nombre de grupo.
-v
Imprimir el número de versión.

SEÑALES

spiped proporciona un tratamiento especial de las siguientes señales:

SIGTERM
Al recibir la señal SIGTERM, spiped dejará de aceptar nuevas conexiones y saldrá una vez que no queden conexiones activas.

VER TAMBIÉN
