SPIN(1) Manual de Comandos Generales SPIN(1)

NOMBRE


Spin − verificación de sistemas multihilo

SINOPSIS

spin -V
spin [ opciones ] archivo

DESCRIPCIÓN

SPIN es una herramienta para analizar la consistencia lógica de sistemas asíncronos, específicamente software distribuido, sistemas multihilo y protocolos de comunicación. Un modelo del sistema se especifica en un lenguaje de comandos protegidos llamado Promela (lenguaje meta de proceso). Este lenguaje de modelado soporta la creación dinámica de procesos, selección de casos no determinista, bucles, gotos, variables locales y globales. También permite una especificación concisa de requisitos de corrección lógica, incluyendo, pero sin limitarse a, requisitos expresados en lógica temporal lineal.

Dado un modelo Promela almacenado en archivo, SPIN puede realizar simulaciones interactivas, guiadas o aleatorias de la ejecución del sistema. También puede generar un programa C que realiza una verificación exhaustiva de los requisitos de corrección para el sistema. Las opciones principales admitidas son las siguientes. (Siempre puede obtener una lista completa de las opciones actuales con el comando "spin --".

-a
Genera un verificador (un model checker) para la especificación. La salida se escribe en un conjunto de archivos C llamados pan.[cbhmt], que se pueden compilar (cc -o pan pan.c) para producir un verificador ejecutable. Los manuales en línea de SPIN contienen los detalles sobre la compilación y el uso de los verificadores.
-b
No ejecuta sentencias printf en una ejecución de simulación.
-c
Produce una aproximación ASCII de un diagrama de secuencia de mensajes para una ejecución de simulación aleatoria o guiada (cuando se combina con -t). Ver también la opción -M.
-Dxxx
Pasa -Dxxx al preprocesador (ver también -E e -I).
-d
Produce información de la tabla de símbolos para el modelo especificado en archivo. Para cada objeto Promela, esta información incluye el tipo, nombre y número de elementos (si se declara como un array), el valor inicial (si es un objeto de datos) o tamaño (si es un canal de mensajes), el ámbito (global o local) y si el objeto se declara como una variable o como un parámetro. Para los canales de mensajes, se enumeran los tipos de datos de los campos del mensaje. Para variables de estructura, el tercer campo define el nombre de la declaración de estructura que contiene la variable.
-Exxx
Pasa xxx al preprocesador (ver también -D e -I).
-e
Si la especificación contiene múltiples reclamaciones (never claims) o propiedades ltl, calcula el producto síncrono de todas las reclamaciones y escribe el resultado en la salida estándar.
-f LTL
Traduce la fórmula LTL LTL a una reclamación (never claim).
Esta opción lee una fórmula en sintaxis LTL del segundo argumento y la traduce a sintaxis Promela (una reclamación, que es el equivalente de Promela a un Autómata de Büchi). Los operadores LTL se escriben: [] (siempre), <> (eventualmente) y U (hasta fuerte). No hay operador X (siguiente), para asegurar la compatibilidad con las reglas de reducción de orden parcial que se aplican durante el proceso de verificación. Si la fórmula contiene espacios, debe entrecomillarse para formar un único argumento para el comando SPIN.
Esta opción ha sido reemplazada en gran medida por el soporte para la especificación en línea de fórmulas ltl, en Spin versión 6.0.
-F archivo
Traduce la fórmula LTL almacenada en archivo a una reclamación (never claim).
Esto se comporta de manera idéntica a la opción -f pero leerá la fórmula del archivo en lugar de la línea de comandos. El archivo debe contener la fórmula como la primera línea. Cualquier texto que siga a esta primera línea se ignora, por lo que se puede usar para almacenar comentarios o anotaciones sobre la fórmula. (En algunos sistemas, las convenciones de entrecomillado del shell complican el uso de la opción -f. La opción -F está destinada a resolver esos problemas).
-g
En combinación con la opción -p, imprime todas las actualizaciones de variables globales en una ejecución de simulación.
-h
Al final de una ejecución de simulación, imprime el valor de la semilla que se utilizó para el generador de números aleatorios. Al especificar la misma semilla con la opción -n, la ejecución exacta se puede repetir más tarde.
-I
Muestra el resultado de la inserción y el preprocesamiento.
-i
Realiza una simulación interactiva, solicitando al usuario en cada paso de ejecución que requiera que se tome una decisión no determinista. La simulación procede sin intervención del usuario cuando la ejecución es determinista.
-jN
Omite la impresión de los primeros N pasos en una ejecución de simulación.
-J
Invierte el orden de evaluación para sentencias unless anidadas, por ejemplo, para que coincida con la forma en que Java maneja las excepciones.
-k archivo
Usa el nombre de archivo archivo como archivo de rastreo (trail file), ver también -t.
-l
En combinación con la opción -p, incluye todas las actualizaciones de variables locales en la salida de una ejecución de simulación.
-M
Produce un diagrama de secuencia de mensajes en formato tcl/tk para una simulación aleatoria o una simulación guiada (cuando se combina con -t), para el modelo en archivo, y muestra el resultado con wish. Ver también la opción -c.
-m
Cambia la semántica de los eventos de envío. Normalmente, una acción de envío se bloqueará si el buffer de mensajes de destino está lleno. Con esta opción, un mensaje enviado a un buffer lleno se pierde.
-nN
Establece la semilla para una simulación aleatoria al valor entero N. No hay espacio entre -n y el entero N. ,TP -N archivo Usa la reclamación (never claim) almacenada en archivo para generar el verificador (ver -a).
-O
Usa las reglas de ámbito originales de la versión pre-Spin 6.
-o[123]
Desactiva la optimización de flujo de datos (-o1). No oculta las variables de solo escritura (-o2) durante la verificación. Desactiva la fusión de sentencias (-o3) durante la verificación. Activa la optimización de rendezvous (-o4) durante la verificación. Activa el caché de casos (-o5) para reducir el tamaño de pan.m, pero perdiendo precisión en los informes de alcanzabilidad.
-O
Usa las reglas de ámbito pre-versión 6.0. En este caso, solo hay dos niveles posibles de ámbito para todas las declaraciones de datos: global o local de proctype. En la versión 6.0 y posteriores, hay un tercer nivel de ámbito: inlines o bloques.
-Pxxx
Usa el comando xxx para preprocesamiento en lugar del preprocesador C estándar.
-p
Incluye todas las ejecuciones de sentencias en la salida de las ejecuciones de simulación.
-qN
Suprime la salida generada para el canal N durante las ejecuciones de simulación.
-r
Muestra todos los eventos de recepción de mensajes, dando el nombre y número del proceso receptor y el número de línea de origen correspondiente. Para cada parámetro del mensaje, muestra el tipo de mensaje y el número y nombre del canal de mensajes.
-replay
Vuelve a reproducir un rastro de error encontrado en una verificación anterior (ver -search). Al igual que con -search, los argumentos destinados al propio Spin (por ejemplo, -p) se pueden proporcionar antes del argumento -replay. Si la repetición solo se puede hacer con el ejecutable ./pan, entonces los argumentos para la repetición con el ejecutable ./pan se pueden proporcionar después del argumento -replay.
-search
Compila y ejecuta directamente. Las banderas de compilación y tiempo de ejecución de verificación se pueden añadir después de este parámetro. Cualquier parámetro de tiempo de análisis de Spin

OPCIONES DE SIMULACIÓN

-a
Imprime la secuencia de llamadas a las funciones de transición de estado que conducen a un estado alcanzable.
-A
Igual que -a, pero no imprime el nombre de los archivos de código fuente, solo el número de línea.
-c
Suprime la impresión del nombre de archivo y el número de línea de las sentencias de código fuente que ejecutan los procesos.
-d
Muestra la tabla de estados de los procesos que se muestran en la salida de simulación.
-e
Imprime los mensajes que se envían en las transferencias de estado en la salida de simulación.
-f
El modelo se ejecuta en modo de depuración.
-F
Imprime la tabla de cadenas de cada proceso.
-h
Imprime una traza de todos los estados alcanzados en la simulación.
-i
Simulación interactiva.
-k archivo
Realiza una simulación guiada, siguiendo el rastro de errores en archivo. Si el nombre del archivo no se proporciona, se busca un archivo con el mismo nombre base que el modelo y la extensión .trail.
-m
Imprime los nombres y el contenido de los mensajes en las transferencias de estado en la salida de simulación.
-p
Imprime la lista de procesos que han cambiado de estado, junto con el número de línea de la sentencia de código fuente que causó el cambio.
-q
Activa el modo de consulta, que permite al usuario hacer preguntas al modelo.
-r
Imprime un resumen detallado de todos los mensajes recibidos por los procesos, incluyendo el nombre y el número del proceso receptor, el número de línea fuente correspondiente, y para cada parámetro del mensaje, el tipo de mensaje y el número y nombre del canal del mensaje.
-s
Incluye todas las operaciones de envío en la salida de las ejecuciones de simulación.
-T
No indenta automáticamente la salida de printf del proceso i con i tabulaciones.
-t[N]
Realiza una simulación guiada, siguiendo el rastro de error [N] que se produjo en una ejecución de verificación anterior. Consulte los manuales en línea para obtener detalles sobre la verificación. Por defecto, el rastro de error se busca en un archivo con el mismo nombre base que el modelo y con la extensión .trail. Consulte también -k.
-v
Modo detallado, añade más detalles y genera más sugerencias y advertencias sobre el modelo.
-V
Imprime el número de versión de SPIN y sale.
-x
Genera tablas de transición a partir del modelo y sale (genera, compila y ejecuta pan.c).

Con solo un nombre de archivo como argumento y sin indicadores de opción, SPIN realiza una simulación aleatoria del modelo especificado en el archivo. Esto normalmente no genera ninguna salida, excepto lo que el usuario genera explícitamente dentro del modelo con sentencias de printf, y algunos detalles sobre el estado final que se alcanza una vez completada la simulación. El grupo de opciones -bgilmprstv se utiliza para establecer el nivel deseado de información que el usuario desea sobre una ejecución de simulación aleatoria, guiada o interactiva. Cada línea de salida normalmente contiene una referencia a la línea fuente en la especificación que la generó. Si se incluye la opción -i, la simulación es interactiva, o si se añaden las opciones -t o -k archivo, la simulación es guiada.

-b
Suprime la ejecución de sentencias printf dentro del modelo.
-g
Muestra en cada paso de tiempo el valor actual de las variables globales.
-l
En combinación con la opción -p, muestra el valor actual de las variables locales del proceso.
-p
Muestra en cada paso de simulación qué proceso cambió de estado y qué sentencia de código fuente se ejecutó.
-r
Muestra todos los eventos de recepción de mensajes, dando el nombre y el número del proceso receptor y el número de línea fuente correspondiente. Para cada parámetro del mensaje, muestra el tipo de mensaje y el número y nombre del canal del mensaje.
-s
Muestra todos los eventos de envío de mensajes.
-v
Modo detallado, añade más detalles y genera más sugerencias y advertencias sobre el modelo.
