SPHINX-APIDOC(1) Sphinx SPHINX-APIDOC(1)

NOMBRE

sphinx-apidoc - Herramienta generadora de documentación de API de Sphinx

SINOPSIS

sphinx-apidoc [OPCIONES] -o <RUTA_SALIDA> <RUTA_MODULO> [PATRON_EXCLUIR ...]

DESCRIPCIÓN

sphinx-apidoc es una herramienta para la generación automática de fuentes de Sphinx que, utilizando la extensión autodoc, documenta un paquete completo al estilo de otras herramientas de documentación automática de API.

ADVERTENCIA:

sphinx-apidoc genera archivos fuente que utilizan sphinx.ext.autodoc para documentar todos los módulos encontrados. Si algún módulo tiene efectos secundarios al importarse, estos serán ejecutados por autodoc cuando se ejecute sphinx-build.

Si documenta scripts (en lugar de módulos de biblioteca), asegúrese de que su rutina principal esté protegida por una condición de if __name__ == '__main__'.

OPCIONES

-o <RUTA_SALIDA>
Directorio donde colocar los archivos de salida. Si no existe, se crea.
-q
No generar nada en la salida estándar, solo escribir advertencias y errores en la salida de error estándar.
-f, --force
Forzar la sobrescritura de cualquier archivo generado existente.
-l, --follow-links
Seguir enlaces simbólicos. Por defecto es False.
-n, --dry-run
No crear ni eliminar ningún archivo.
-s <sufijo>
Sufijo para los archivos fuente generados. Por defecto es rst.
-d <MAXPROFUNDIDAD>
Profundidad máxima para el archivo de tabla de contenidos generado. Por defecto es 4.
--tocfile
Nombre de archivo para un archivo de tabla de contenidos. Por defecto es modules.
-T, --no-toc
No crear un archivo de tabla de contenidos. Ignorado cuando se proporciona --full.
--remove-old
Eliminar archivos existentes en el directorio de salida que ya no se generan. No compatible con --full.
-F, --full
Generar un proyecto Sphinx completo (conf.py, Makefile, etc.) utilizando el mismo mecanismo que sphinx-quickstart.
-e, --separate
Poner la documentación de cada módulo en su propia página.

Añadido en la versión 1.2.

-E, --no-headings
No crear encabezados para los módulos/paquetes. Esto es útil, por ejemplo, cuando las docstrings ya contienen encabezados.
-P, --private
Incluir módulos "_privados".

Añadido en la versión 1.2.

--implicit-namespaces
Sin esta opción, sphinx-apidoc busca en sys.path paquetes de Python que contengan archivos __init__.py, o módulos de Python de un solo archivo.
-M, --module-first
Poner la documentación del módulo antes de la documentación de los submódulos.

Estas opciones se utilizan cuando se especifica --full:

-a
Añadir module_path a sys.path.
-H <proyecto>
Establece el nombre del proyecto a incluir en los archivos generados (ver proyecto).
-A <autor>
Establece el/los nombre(s) del autor a incluir en los archivos generados (ver copyright).
-V <versión>
Establece la versión del proyecto a incluir en los archivos generados (ver version).
-R <lanzamiento>
Establece el lanzamiento del proyecto a incluir en los archivos generados (ver release).

Plantillas de proyecto

Añadido en la versión 2.2: Opciones de plantillas de proyecto para sphinx-apidoc

-t, --templatedir=TEMPLATEDIR
Directorio de plantillas para los archivos de plantilla. Puedes modificar las plantillas de los archivos del proyecto de Sphinx generados por apidoc. Los siguientes archivos de plantilla Jinja2 están permitidos:
  • module.rst.jinja
  • package.rst.jinja
  • toc.rst.jinja
  • root_doc.rst.jinja
  • conf.py.jinja
  • Makefile.jinja
  • Makefile.new.jinja
  • make.bat.jinja
  • make.bat.new.jinja

En detalle, por favor, consulta los archivos de plantilla del sistema que proporciona Sphinx. (sphinx/templates/apidoc y sphinx/templates/quickstart)

ENTORNO

SPHINX_APIDOC_OPTIONS
Una lista separada por comas de opciones a añadir a las directivas automodule generadas. Por defecto es members,undoc-members,show-inheritance.

sphinx-apidoc(1) — Arch Linux manual pages
NAME:
sphinx-apidoc - Sphinx API documentation generator
SYNOPSIS:
sphinx-apidoc [OPTIONS] -o output_path module_path [exclude_pattern ...]
DESCRIPTION:
The sphinx-apidoc command extracts API documentation from a Python package or module and generates reStructuredText (.rst) files that Sphinx can use to build API documentation. It scans the specified module path, identifies modules and packages, and creates corresponding .rst files with basic docstrings. These files serve as the starting point for creating comprehensive API documentation with Sphinx.

You can customize the generated documentation by editing the .rst files and by using Sphinx's configuration options.
OPTIONS:
  • -o output_path: Specifies the directory where the generated .rst files will be saved. This directory will be created if it doesn't exist.
  • -f: Forces the overwriting of existing .rst files. Use with caution.
  • -e: Creates an separate .rst file for each module, rather than grouping them in a package index.
  • -n: Turns off the generation of module indices.
  • -N: Turns off the generation of submodule indices.
  • -n<project_name>: Sets the project name for the generated documentation.
  • --implicit-namespaces: Enable implicit namespace handling for packages.
  • --ext-autodoc: Enables the autodoc extension in Sphinx configuration.
  • --ext-napoleon: Enables the Napoleon extension for parsing NumPy and Google style docstrings.
  • --ext-viewcode: Enables the Viewcode extension to link to source code.
  • --ext-githubpages: Enables the GitHubpages extension for GitHub Pages deployment.
  • module_path: The path to the Python package or module to document.
  • exclude_pattern ...: Optional patterns to exclude specific files or directories from the documentation generation.
ENVIRONMENT:
No specific environment variables are required for sphinx-apidoc.
