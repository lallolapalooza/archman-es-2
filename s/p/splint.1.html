NOMBRE

splint - Una herramienta para verificar estáticamente programas C

SINOPSIS

splint [opciones]

DESCRIPCIÓN

splint es una herramienta para verificar estáticamente programas C en busca de vulnerabilidades de seguridad y errores de programación comunes. Con un esfuerzo mínimo, splint puede ser utilizado como un mejor lint(1). Si se invierte un esfuerzo adicional añadiendo anotaciones a los programas, splint puede realizar comprobaciones más robustas que las que se pueden hacer con cualquier lint estándar. Para obtener documentación completa, por favor, consulte http://www.splint.org. Esta página del manual solo cubre algunas de las opciones disponibles.

OPCIONES

-help
Muestra la ayuda

Inicialización

Estas banderas controlan los directorios y archivos utilizados por splint. Pueden ser utilizadas desde la línea de comandos o en un archivo de opciones, pero no pueden ser usadas como comentarios de control en el código fuente. Excepto donde se indica, tienen el mismo significado precedidas por - o +.

-tmpdir directorio
Establece el directorio para escribir archivos temporales. El valor por defecto es /tmp/.
-I directorio
Añade el directorio a la ruta de búsqueda de archivos de inclusión C. Tenga en cuenta que no hay espacio después de la I, para ser consistente con las banderas del preprocesador C.
-S directorio
Añade el directorio a la ruta de búsqueda de archivos de especificación .lcl.
-f archivo
Carga el archivo de opciones <archivo>. Si se utiliza esta bandera desde la línea de comandos, el archivo predeterminado ~/.splintrc no se carga. Esta bandera puede ser utilizada en un archivo de opciones para cargar otro archivo de opciones.
-nof
Impide que se carguen los archivos de opciones predeterminados (./.splintrc y ~/.splintrc). (Establecer -nof anula +nof, haciendo que los archivos de opciones se carguen normalmente.)
-system-dirs directorios
Establece los directorios para archivos del sistema (el valor por defecto es "/usr/include"). Separe los directorios con dos puntos (por ejemplo, "/usr/include:/usr/local/lib"). La configuración de las banderas se propaga a los archivos en un directorio del sistema. Si se establece -system-dir-errors, no se informan errores para los archivos en directorios del sistema.

Preprocesador

Estas banderas se utilizan para definir o anular constantes del preprocesador. La bandera -I<directorio> también se pasa al preprocesador C.

-D inicializador
Se pasa al preprocesador C.
-U inicializador
Se pasa al preprocesador C.

Bibliotecas Estas banderas controlan la creación y el uso de bibliotecas.

-dump archivo
Guarda el estado en <archivo> para cargarlo. La extensión predeterminada .lcd se añade si <archivo> no tiene extensión.
-load archivo
Carga el estado desde <archivo> (creado por -dump). La extensión predeterminada .lcd se añade si <archivo> no tiene extensión. Solo se puede cargar un archivo de biblioteca.

Por defecto, la biblioteca estándar se carga si la bandera -load no se utiliza para cargar una biblioteca de usuario. Si no se carga ninguna biblioteca de usuario, se puede utilizar una de las siguientes banderas para seleccionar una biblioteca estándar diferente. Anteponga la bandera con + para cargar la biblioteca descrita (o impedir que se cargue una biblioteca usando nolib). Consulte el Apéndice F para obtener información sobre las bibliotecas proporcionadas.

-nolib
No carga ninguna biblioteca. Esto impide que se cargue la biblioteca estándar.
-standard-lib
Utiliza la biblioteca estándar (ISO C99) (seleccionada por defecto).
-standard-strict-lib
Utiliza la versión estricta de la biblioteca estándar (ISO C99).
-posix-lib
Utiliza la biblioteca estándar POSIX.
-posix-strict-lib
Utiliza la versión estricta de la biblioteca estándar POSIX.
-unix-lib
Utiliza la versión UNIX de la biblioteca estándar.
-unix-strict-lib
Utiliza la versión estricta de la biblioteca estándar UNIX.

Salida

Estas banderas controlan qué información adicional se imprime por splint. Establecer +<bandera> hace que se imprima la información descrita; establecer -<bandera> lo impide. Por defecto, todas estas banderas están desactivadas.

-use-stderr
Envía los mensajes de error a la salida de error estándar (en lugar de a la salida estándar).
-show-summary
Muestra un resumen de todos los errores informados y suprimidos. Los recuentos de errores suprimidos no son necesariamente correctos, ya que desactivar una bandera puede impedir algunas verificaciones para ahorrar recursos computacionales, y los errores que no se informan pueden propagarse de manera diferente a cuando se informan.
-show-scan
Muestra los nombres de los archivos a medida que se procesan.
-show-alluses
Muestra la lista de usos de todos los identificadores externos ordenados por número de usos.
-stats
Muestra el número de líneas procesadas y el tiempo de verificación.
-time-dist
Muestra la distribución de dónde se invierte el tiempo de verificación.
-quiet
Suprime el encabezado y el recuento de errores. (Si quiet no está activado, splint imprime un encabezado con información de la versión antes de que comience la verificación, y una línea que resume el número total de errores informados.)
-which-lib
Imprime el nombre del archivo de la biblioteca estándar y la información de creación.
-limit número
Se informan como máximo <número> errores similares consecutivamente. Se suprimen errores adicionales y se imprime un mensaje que muestra el número de mensajes suprimidos.

Errores Esperados

Normalmente, splint esperará no informar ningún error. El estado de salida será éxito (0) si no se informan errores, y fallo si se informan errores. Se pueden utilizar banderas para establecer el número esperado de errores informados. Debido a los mecanismos de supresión de errores proporcionados, estas opciones probablemente no deberían utilizarse para la verificación final de programas reales, pero pueden ser útiles en el desarrollo de programas que utilizan make.

-expect número
Se esperan exactamente <número> errores de código. splint saldrá con un estado de fallo a menos que se detecten <número> errores de código.
-Message Formato
Estas banderas controlan cómo se imprimen los mensajes. Pueden establecerse en la línea de comandos, en archivos de opciones o localmente en comentarios sintácticos. Las banderas linelen y limit pueden ir precedidas de + o - con el mismo significado; para las otras banderas, + activa la impresión descrita y - la desactiva. El recuadro a la izquierda de cada bandera indica su valor predeterminado.
-show-column
Muestra el número de columna donde se encuentra el error. Predeterminado: +
-show-func
Muestra el nombre de la función (o macro) que contiene el error. El nombre de la función se imprime una vez antes del primer mensaje detectado en esa función. Predeterminado: +
-show-all-conjs
Muestra todos los tipos alternativos posibles (ver Sección 8.2.2). Predeterminado: -
-paren-file-format
Utiliza el formato archivo(línea) en los mensajes.
-hi

OPTIONS

The splint utility provides a number of flags that allow you to control the checking performed. The flags are used to enable or disable various checks. Flags are prefixed with either +/-. Flags may be used locally or globally. Command line flags override the default settings.

Flags are used to enable or disable checks for specific error classes. The -? option displays a list of all flags.

The default settings are determined by the -standard mode selector. To see the complete flag settings in each mode, use splint -help modes.

The default value for each flag is given after the description. An asterisk (*) indicates the default value.

-help [mode]
Prints a usage message, or a detailed description of the specified mode.
-quiet
Suppress all messages. Default: -
-noquiet
Report all messages. Default: +
-brief
Suppress informational messages. Default: -
-nobrief
Report all messages, including informational messages. Default: +
-noadvise
Suppress warning messages. Default: -
-noerror
Suppress error messages. Default: -
-verbose
Report all messages, including verbose messages. Default: -
-showbranch
Show the code branch for each message. Default: -
-showcall
Show the call stack for each message. Default: -
-showcontext
Show the context of each message. Default: -
-showfile
Show the file name for each message. Default: +
-showloc
Show the location (line number and column) for each message. Default: +
-showpos
Show the position (character offset) for each message. Default: -
-hints
Provide hints describing an error and how a message may be suppressed for the first error reported in each error class. Default: +
-force-hints
Provide hints for all errors reported, even if the hint has already been displayed for the same error class. Default: -
-linelen number
Set length of maximum message line to <number> characters. splint will split messages longer than <number> characters long into multiple lines. Default: 80

Mode Selector Flags

Mode selects flags set the mode checking flags to predefined values. They provide a quick coarse-grain way of controlling what classes of errors are reported. Specific checking flags may be set after a mode flag to override the mode settings. Mode flags may be used locally, however the mode settings will override specific command line flag settings. A warning is produced if a mode flag is used after a mode checking flag has been set.

These are brief descriptions to give a general idea of what each mode does. To see the complete flag settings in each mode, use splint -help modes. A mode flag has the same effect when used with either + or -.

-weak
Weak checking, intended for typical unannotated C code. No modifies checking, macro checking, rep exposure, or clean interface checking is done. Return values of type int may be ignored. The types bool, int, char and user-defined enum types are all equivalent. Old style declarations are unreported.
-standard
The default mode. All checking done by weak, plus modifies checking, global alias checking, use all parameters, using released storage, ignored return values or any type, macro checking, unreachable code, infinite loops, and fall-through cases. The types bool, int and char are distinct. Old style declarations are reported.
-checks
Moderately strict checking. All checking done by standard, plus must modification checking, rep exposure, return alias, memory management and complete interfaces.
-strict
Absurdly strict checking. All checking done by checks, plus modifications and global variables used in unspecified functions, strict standard library, and strict typing of C operators. A special reward will be presented to the first person to produce a real program that produces no errors with strict checking.
