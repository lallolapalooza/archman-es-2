NOMBRE

spamc - cliente para spamd

SINOPSIS

spamc [opciones] < mensaje

DESCRIPCIÓN

Spamc es la parte cliente del par spamc/spamd. Debe usarse en lugar de "spamassassin" en scripts para procesar correo. Leerá el correo desde STDIN y lo enviará a su conexión con spamd, luego leerá el resultado y lo imprimirá en STDOUT. Spamc tiene una sobrecarga de carga extremadamente baja, por lo que debería ser mucho más rápido de cargar que el programa completo spamassassin.

Consulte el archivo README en el directorio spamd de la distribución SpamAssassin para obtener más detalles.

OPCIONES

Todas las opciones detalladas a continuación se pueden pasar como argumentos de línea de comandos o estar contenidas en un archivo de configuración, como se describe en la sección ARCHIVO DE CONFIGURACIÓN más abajo.

Tenga en cuenta que las opciones largas, al estilo "--opciones-largas", son nuevas a partir de SpamAssassin 3.2.0 y no estaban disponibles en versiones anteriores.

-B, --bsmtp
Asume que la entrada es un único mensaje con formato BSMTP. En otras palabras, spamc extraerá todo entre la línea DATA y la línea de punto solitario para enviarlo a spamd, y colocará la salida de spamd de nuevo en el mismo sobre (por lo tanto, la extensión SIZE en su archivo BSMTP causará muchos problemas).
-c, --check
Simplemente comprueba si el mensaje es spam o no. Establece el código de salida del proceso a 1 si el mensaje es spam, 0 si no es spam o si ocurre un error de procesamiento. Imprimirá la puntuación/umbral en stdout (como enteros) o 0/0 si hubo un error. Combinar -c y -E es una operación nula, ya que -c implica el comportamiento de -E.
-d host[,host2], --dest=host[,host2]
En modo TCP/IP, conéctese al servidor spamd en el host dado (predeterminado: localhost). Se pueden especificar varios hosts si están separados por comas.

Si host se resuelve en varias direcciones, spamc fallará a las otras direcciones si no se puede conectar a la primera. Intentará primero todas las direcciones de un host antes de intentar el siguiente en la lista. Tenga en cuenta que este comportamiento de fail-over es incompatible con -x; si se usa ese switch, no ocurrirá el fail-over.

-4
Use solo IPv4 para conectarse al servidor. Restringe la resolución de nombres de dominio de los hosts del servidor spamd a la familia de direcciones AF_INET a través del flag "hints.ai_family" en la llamada a getaddrinfo(3).
-6
Use solo IPv6 para conectarse al servidor. Restringe la resolución de nombres de dominio de los hosts del servidor spamd a la familia de direcciones AF_INET6 a través del flag "hints.ai_family" en la llamada a getaddrinfo(3).
-e comando [argumentos], --pipe-to comando [argumentos]
En lugar de escribir en stdout, canalice la salida al estándar de entrada de comando. Tenga en cuenta que existe una posibilidad muy pequeña de pérdida de correo aquí, porque si falla el fork-and-exec no hay lugar a donde poner el mensaje de correo.

Tenga en cuenta que esta debe ser la ÚLTIMA opción de línea de comandos, ya que todo lo que siga a -e se tomará como argumentos para el comando (es como rxvt o xterm).

Esta opción no es compatible con plataformas Win32.

-E, --exitcode
Filtra de acuerdo con las otras opciones, pero establece el código de salida del proceso a 1 si el mensaje es spam, 0 si no es spam o si ocurre un error de procesamiento.
-F /ruta/al/archivo, --config=ruta
Especifique un archivo de configuración para leer flags de línea de comandos adicionales. Consulte ARCHIVO DE CONFIGURACIÓN más abajo.
-h, --help
Imprima este mensaje de ayuda y termine sin acción.
-H, --randomize
Para sockets TCP/IP, aleatorice las direcciones IP devueltas para los hosts dados por el switch -d. Esto proporciona un tipo simple de balanceo de carga. Sin embargo, solo intentará tres veces.
-l, --log-to-stderr
Envíe mensajes de registro a stderr, en lugar de a syslog.
-L tipo_aprendizaje, --learntype=tipo
Envíe el mensaje a spamd para aprender. El "tipo de aprendizaje" puede ser spam, ham u olvidar. El código de salida para spamc se establecerá a 0 si el mensaje fue aprendido o si ya había sido aprendido. Los códigos de salida distintos de cero indican un fallo real de algún tipo.

Tenga en cuenta que "spamd" debe ejecutarse con la opción "--allow-tell" para que esto funcione.

-C tipo_informe, --reporttype=tipo
Informe o revoque un mensaje a una de las bases de datos de filtrado colaborativo configuradas. El "tipo de informe" puede ser report o revoke.

Tenga en cuenta que "spamd" debe ejecutarse con la opción "--allow-tell" para que esto funcione.

-p puerto, --port=puerto
En modo TCP/IP, conéctese al servidor spamd que escucha en el puerto dado (predeterminado: 783).
-r, --full-spam
Simplemente imprima el texto del informe de SpamAssassin en stdout, si el mensaje es spam. Si el mensaje es ham (no spam), no se imprimirá nada. La primera línea de la salida es la puntuación del mensaje y el umbral, en este formato: 
puntuacion/umbral
-R, --full
Simplemente imprima el texto del informe de SpamAssassin en stdout, para todos los mensajes. Consulte -r para conocer los detalles del formato de salida utilizado.
-s tamano_max, --max-size=tamano_max
Establezca el tamaño máximo del mensaje que se enviará a spamd; cualquier mensaje mayor que este umbral será devuelto sin procesar (predeterminado: 500 KB). Si spamc recibe un mensaje más grande que esto, no se pasará a spamd. El tamaño máximo del mensaje es 256 MB.

El tamaño se especifica en bytes, como un entero positivo mayor que 0. Por ejemplo, -s 500000.

--connect-retries=reintentos
Reintente conectarse a spamd reintentos veces. El valor predeterminado es 3 veces.
--retry-sleep=espera
Espere espera segundos entre intentos de conectarse a spamd. El valor predeterminado es 1 segundo.
--filter-retries=reintentos
Reintente el filtrado reintentos veces si el proceso spamd falla (generalmente se agota el tiempo de espera). Esto difiere de --connect-retries en que agota el tiempo de espera de la transacción después de que la conexión TCP se haya establecido correctamente. El valor predeterminado es 1 vez (es decir, un intento y sin reintentos).
--filter-retry-sleep=espera
Espere espera segundos entre intentos de filtrado fallidos de spamd. El valor predeterminado es 1 segundo.
-S, --ssl
Si spamc fue compilado con soporte para SSL, cifre los datos hacia y desde el proceso spamd con SSL; spamd también debe soportar SSL.
--ssl-cert=archivo_certificado
Autentíquese en el servidor spamd con un certificado de cliente SSL. Especifique el archivo de certificado a utilizar.
--ssl-key=archivo_clave
Autentíquese en el servidor spamd con un certificado de cliente SSL. Especifique el archivo de clave de certificado a utilizar.
--ssl-ca-file=archivo_ca
Utilice el certificado de Autoridad Certificadora especificado para verificar el certificado del servidor. El certificado del servidor debe estar firmado por este certificado.
--ssl-check-cert
Verifique el certificado del servidor spamd. Si el certificado no es válido, la conexión fallará. Esto está habilitado por defecto.
--ssl-no-check-cert
No verifique el certificado del servidor spamd. Esto podría ser peligroso, ya que permite ataques de suplantación de identidad (man-in-the-middle).
-t, --tidy
Elimina las cabeceras de correo de Internet que están marcadas como obsoletas (por ejemplo, la cabecera 'Received'). El contenido de la cabecera se eliminará, pero los saltos de línea que marcan la cabecera no se eliminarán. Si se establece la opción "strip_from" en el archivo de configuración, la cabecera de origen también se eliminará. Tenga en cuenta que si el mensaje no tiene ninguna cabecera de Internet a eliminar, entonces el mensaje será devuelto sin procesar. También, esta opción está en desuso y debería ser sustituida por la opción "strip_headers" de spamd.
-u user, --user=user
En modo TCP/IP, ejecute el proceso spamd como el usuario user en el servidor de destino. Esto solo es útil si el servidor spamd está ejecutando varios procesos spamd bajo diferentes usuarios (por ejemplo, en modo de balanceo de carga). El valor predeterminado es el usuario actual. Tenga en cuenta que esta opción es ignorada si se está conectando a un servidor de balanceo de carga.
-v, --version
Imprima la versión de spamc y termine.
-x, --noblock
No bloquee. Si la conexión a spamd falla, spamc devolverá el mensaje sin procesar. Esto es útil para el filtrado local en máquinas sin conexión. Si spamd está caído, los mensajes simplemente pasarán. Esto es un no-op si se usa el parámetro de host único de la opción -d. Consulte la documentación de fail-over de la opción -d.
-V, --verbose
Activa la salida detallada. Es decir, spamc imprimirá un mensaje cada vez que se conecte a un servidor spamd.

ARCHIVO DE CONFIGURACIÓN

Un archivo de configuración puede ser especificado con la opción -F /path/to/file. El archivo de configuración puede contener cualquier opción de línea de comandos, una por línea. Los comentarios pueden ser indicados por un carácter "#" al principio de la línea, o por un carácter "#" seguido por un espacio en blanco.

Las opciones especificadas en la línea de comandos anularán las opciones especificadas en el archivo de configuración.

Ejemplo de archivo de configuración:

  # Conectarse a spamd en la máquina remota
  -d remote.example.com
  -p 1234

ARCHIVOS

/etc/mail/spamassassin/spamc.cf
Directorio de configuración del sistema por defecto.
~/.spamc.cf
Directorio de configuración del usuario por defecto.

NAME

spamc — client for the SpamAssassin spam filtering daemon

SYNOPSIS

spamc [-fF] [-s max-size] [-d host] [-p port] [-U socket] [-u username] [-t timeout] [-n timeout] [-e exit-on-error] [-l retry-on-error] [-c connect-only] [-v verbose] [-Y] [-z] [-x] [-X] [-y] [-K] [-U socketpath] [-h] [-V] [-B <bounce-addr>] [-R <report-addr>]

DESCRIPTION

spamc is a client program that communicates with a running SpamAssassin daemon (spamd(1)) to check mail for spam. It is typically used by mail delivery agents (MDAs) or mail submission agents (MSAs) to filter mail before it is delivered to a user's mailbox.

spamc reads a mail message from standard input, sends it to spamd for processing, and writes the (potentially modified) message to standard output.

The communication between spamc and spamd is done over a TCP/IP socket or a UNIX domain socket.

OPTIONS

-f, --config-file=filename
Use the specified configuration file instead of the default (see CONFIGURATION FILE below).
-F, --load-config-file=filename
Load command-line options from the specified configuration file. Command-line switches override configuration file settings.
-s max-size, --max-size=max-size
Set the maximum message size (in kilobytes) that spamc will process. If a message larger than this size is encountered, spamc will exit with an error code. The default is 0, which means no limit.
-d host, --host=host
Connect to spamd on the specified host. Defaults to "localhost".
-p port, --port=port
Connect to spamd on the specified port. Defaults to 783.
-U socketpath, --socket=path
Connect to spamd via UNIX domain socket socketpath instead of a TCP/IP connection. This option is not supported on Win32 platforms.
-u username, --username=username
To have spamd use per-user-config files, run spamc as the user whose config files spamd should load; by default the effective user-ID is sent to spamd. If you're running spamc as some other user, though, (eg. root, mail, nobody, cyrus, etc.) then you may use this flag to override the default.
-t timeout, --timeout=timeout
Set the timeout for spamc-to-spamd communications (default: 600, 0 disables). If spamd takes longer than this many seconds to reply to a message, spamc will abort the connection and treat this as a failure to connect; in other words the message will be returned unprocessed.
-n timeout, --connect-timeout=timeout
Set the timeout for spamc-to-spamd connection establishment (default: 600, 0 disables). If spamc takes longer than this many seconds to establish a connection to spamd, spamc will abort the connection and treat this as a failure to connect; in other words the message will be returned unprocessed.
-e exit-on-error, --exit-on-error=exit-on-error
Set the exit code on error. By default, spamc returns 0 on error and passes the message through unaltered. If this is set, spamc will return the specified exit code instead.
-l retry-on-error, --retry-on-error=retry-on-error
If an error occurs, and this option is set, spamc will exit with EX_TEMPFAIL (75) instead of EX_UNAVAILABLE (69) or another error code. This tells the calling Mail Transfer Agent (MTA) to retry sending the message later.
-c, --exit-code
If the message is determined to be spam, exit with a non-zero exit code (1). Otherwise, exit with 0.
-v, --verbose
Increase verbosity. Can be specified multiple times.
-Y, --ssl
Use SSL/TLS encryption for the connection to spamd. This requires spamd to be configured to accept SSL connections. You may need to specify CA certificates using --ssl-ca-path or --ssl-ca-file.
--ssl-ca-path=capath
Use the Certificate Authority certificate files in the specified set of directories to verify the server certificate. The server certificate must be signed by one of these Certificate Authorities. See the man page for IO::Socket::SSL for additional details.
--ssl-ca-file=cafile
Use the specified Certificate Authority certificate file to verify the server certificate. The server certificate must be signed by this Certificate Authority. See the man page for IO::Socket::SSL for additional details.
-t timeout, --timeout=timeout
Set the timeout for spamc-to-spamd communications (default: 600, 0 disables). If spamd takes longer than this many seconds to reply to a message, spamc will abort the connection and treat this as a failure to connect; in other words the message will be returned unprocessed.
-n timeout, --connect-timeout=timeout
Set the timeout for spamc-to-spamd connection establishment (default: 600, 0 disables). If spamc takes longer than this many seconds to establish a connection to spamd, spamc will abort the connection and treat this as a failure to connect; in other words the message will be returned unprocessed.
-u username, --username=username
To have spamd use per-user-config files, run spamc as the user whose config files spamd should load; by default the effective user-ID is sent to spamd. If you're running spamc as some other user, though, (eg. root, mail, nobody, cyrus, etc.) then you may use this flag to override the default.
-U socketpath, --socket=path
Connect to "spamd" via UNIX domain socket socketpath instead of a TCP/IP connection.

This option is not supported on Win32 platforms.

-V, --version
Report the version of this "spamc" client. If built with SSL support, an additional line will be included noting this, like so: 
SpamAssassin Client version 3.0.0-rc4
      compiled with SSL support (OpenSSL 0.9.7d 17 Mar 2004)
-x, --no-safe-fallback
Disables the 'safe fallback' error-recovery method, which passes through the unaltered message if an error occurs. Instead, exit with an error code, and let the MTA queue up the mails for a retry later. See also "EXIT CODES".

This also disables the TCP fail-over behaviour from -d.

-X, --unavailable-tempfail
When disabling 'safe fallback' with -x, this option will turn EX_UNAVAILABLE errors into EX_TEMPFAIL. This may allow your MTA to defer mails with a temporary SMTP error instead of bouncing them with a permanent SMTP error. See also "EXIT CODES".
-y, --tests
Just output the names of the tests hit to stdout, on one line, separated by commas.
-K
Perform a keep-alive check of spamd, instead of a full message check.
-z
Use gzip compression to compress the mail message sent to "spamd". This is useful for long-distance use of spamc over the internet. Note that this relies on "zlib" being installed on the "spamc" client side, and the "Compress::Zlib" perl module on the server side; an error will be returned otherwise.
--headers
Perform a scan, but instead of allowing any part of the message (header and body) to be rewritten, limit rewriting to only the message headers. This is much more efficient in bandwidth usage, since the response message transmitted back from the spamd server will not include the body.

Note that this only makes sense if you are using "report_safe 0" in the scanning configuration on the remote end; with "report_safe 1", it is likely to result in corrupt messages.

CONFIGURATION FILE

The above command-line switches can also be loaded from a configuration file.

The format of the file is similar to the SpamAssassin rules files; blank lines and lines beginning with "#" are ignored. Any space-separated words are considered additions to the command line, and are prepended. Newlines are treated as equivalent to spaces. Existing command line switches will override any settings in the configuration file.

If the -F switch is specified, that file will be used. Otherwise, "spamc" will attempt to load spamc.conf in "SYSCONFDIR" (default: /etc/mail/spamassassin). If that file doesn't exist, and the -F switch is not specified, no configuration file will be read.

Example:

# spamc global configuration file 

# connect to "server.example.com", port 783
-d server.example.com
-p 783
# max message size for scanning = 350k
-s 350000

EXIT CODES

By default, spamc will use the 'safe fallback' error recovery method. That means, it will always exit with an exit code of 0, even if an error was encountered. If any error occurs, it will simply pass through the unaltered message.

The -c and -E options modify this; instead, spamd will use an exit code of 1 if the message is determined to be spam.

If one of the "-x", "-L" or "-C" options are specified, 'safe fallback' will be disabled, and certain error conditions related to communication between spamc and spamd will result in an error code.

The exit codes used are as follows:

EX_USAGE        64  command line usage error
EX_DATAERR      65  data format error       
EX_NOINPUT      66  cannot open input
EX_NOUSER       67  addressee unknown
EX_NOHOST       68  host name unknown
EX_UNAVAILABLE  69  service unavailable
EX_SOFTWARE     70  internal software error
EX_OSERR        71  system error (e.g., can't fork)
EX_OSFILE       72  critical OS file missing
EX_CANTCREAT    73  can't create (user) output file
EX_IOERR        74  input/output error
EX_TEMPFAIL     75  temp failure; user is invited to retry
EX_PROTOCOL     76  remote error in protocol
EX_NOPERM       77  permission denied
EX_CONFIG       78  configuration error
* The EX_TOOBIG error level is never used.  If spamc receives a message 
  that is too big, the exit code will be 0.
EX_TOOBIG       98  message was too big to process (see --max-size)
