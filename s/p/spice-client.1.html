SPICE-CLIENT(1) Documentación de Spice-GTK SPICE-CLIENT(1)

NOMBRE

Spice-GTK - una biblioteca del lado del cliente para acceder a pantallas SPICE remotas

DESCRIPCIÓN

Spice-GTK es una biblioteca que permite el acceso a pantallas remotas a través del protocolo SPICE. Actualmente se utiliza principalmente para acceder a máquinas virtuales remotas.

La biblioteca Spice-GTK proporciona un conjunto de opciones de línea de comandos que se pueden utilizar para ajustar algunas opciones específicas de SPICE.

URI

Para iniciar una conexión SPICE simple (la conexión no estará cifrada) al host hostname.example.com y puerto 5900, utilice la siguiente URI:

spice://hostname.example.com:5900

Para iniciar una conexión TLS, se utilizaría:

spice+tls://hostname.example.com:5900

Nota: 'spice+tls' está disponible desde la v0.35; antes de eso, debe usar la cadena de consulta spice:// con el parámetro 'tls-port'.

cadena de consulta URI

La URI de SPICE acepta cadenas de consulta. Se pueden especificar varios parámetros a la vez si están separados por & o ;

spice://hostname.example.com?port=5900;tls-port=5901

Al usar 'tls-port', se recomienda no especificar ningún puerto que no sea TLS. Si proporciona tanto 'port' como 'tls-port', asegúrese de usar las opciones --spice-secure-channels para indicar qué canales deben ser seguros. De lo contrario, Spice-GTK primero intenta una conexión al puerto no TLS y luego intenta usar el puerto TLS. Esto significa que un atacante intermedio podría forzar que toda la sesión SPICE se envíe en texto plano, independientemente de la configuración TLS del servidor SPICE.

Otros parámetros URI válidos son 'username' y 'password'. Tenga cuidado, ya que pasar una contraseña a través de una URI SPICE podría hacer que la contraseña sea visible por cualquier usuario local a través de 'ps'.

OPCIONES

Las siguientes opciones son aceptadas al ejecutar un cliente SPICE que utiliza las opciones predeterminadas de Spice-GTK:

--spice-secure-channels=<main,display,inputs,...,all>
Forzar que los canales especificados sean seguros

Esto indica al cliente SPICE que debe usar una conexión TLS para estos canales. Si el servidor solo ofrece conexiones no TLS para estos canales, el cliente no los utilizará. Si se usa el valor especial "all", esto indica que todos los canales SPICE deben cifrarse.

Los canales SPICE actuales son: main, display, inputs, cursor, playback, record, smartcard, usbredir.

--spice-disable-effects=<wallpaper,font-smooth,animation,all>
Desactivar efectos de pantalla del invitado

Esto indica al cliente SPICE que debe intentar desactivar algunas características del invitado para reducir el uso de ancho de banda. Esto requiere soporte del invitado, generalmente a través de un agente SPICE. Actualmente, esto solo se admite en invitados de Windows.

"wallpaper" desactivará el fondo de pantalla del invitado, "font-smooth" desactivará el antialiasing de fuentes, "animation" intentará desactivar algunas de las animaciones del entorno de escritorio. "all" intentará desactivar todo lo que se pueda desactivar.

--spice-color-depth=<16,32>
Profundidad de color de la pantalla del invitado - OBSOLETO

Esto indica al cliente SPICE que debe intentar forzar la profundidad de color del sistema operativo invitado. Una profundidad de color menor debería reducir el uso de ancho de banda. Esto requiere soporte del invitado, generalmente a través de un agente SPICE. Actualmente, esto solo se admite en invitados de Windows 7 y anteriores.

--spice-ca-file=<archivo>
Archivo de almacén de confianza para conexiones seguras

Esta opción se utiliza para especificar un archivo .crt que contenga el certificado de CA con el que se firman los certificados TLS del servidor SPICE. Esto es útil cuando se utilizan certificados TLS autofirmados en lugar de certificados firmados por una CA oficial.

--spice-host-subject=<sujeto-host>
Sujeto del certificado del host (pares campo=valor separados por comas)

Al usar certificados autofirmados, o cuando el invitado se migra entre diferentes hosts, el sujeto/sujeto alternativo del certificado TLS que proporcionará el servidor SPICE no coincidirá necesariamente con el nombre de host al que nos estamos conectando. Esta opción permite anular el sujeto esperado del certificado TLS.

El sujeto debe corresponder a la línea "Subject:" devuelta por:
openssl x509 -noout -text -in server-cert.pem

--spice-debug
Habilitar la depuración de Spice-GTK. Esto también se puede activar con la variable de entorno SPICE_DEBUG, o usando G_MESSAGES_DEBUG=all
--spice-disable-audio
Desactivar soporte de audio
--spice-disable-usbredir
Desactivar soporte de redirección USB
--spice-usbredir-auto-redirect-filter=<cadena-filtro>
Filtro para seleccionar dispositivos USB que se redirigirán automáticamente al conectarse

Este filtro especifica qué dispositivos USB deben ser redirigidos automáticamente cuando se conectan durante la vida útil de una sesión SPICE.

Una regla tiene el formato: "clase,vendedor,producto,version,permitir"

-1 se puede usar en lugar de clase, vendedor, producto o versión para aceptar cualquier valor. Varias reglas se pueden concatenar con '|': "regla1|regla2|regla3"

--spice-usbredir-redirect-on-connect=<cadena-filtro>
Filtro para seleccionar dispositivos USB que se redirigirán al conectar

Este filtro especifica qué dispositivos USB deben ser redirigidos automáticamente cuando se ha establecido una conexión SPICE a una pantalla remota.

--spice-gtk-version
Mostrar información de la versión de Spice-GTK
--spice-smartcard
Habilitar soporte de tarjeta inteligente
--spice-smartcard-db=<db-certificado>
Ruta a la base de datos de certificados local que se utilizará para los certificados de software de tarjeta inteligente

Esta opción solo es útil para fines de prueba. En lugar de tener un lector de tarjetas inteligentes de hardware y una tarjeta inteligente física, puede especificar un archivo que contenga 3 certificados que se utilizarán para emular una tarjeta inteligente en software. Consulte "http://www.spice-space.org/page/SmartcardUsage#Using_a_software_smartcard" para obtener más detalles sobre cómo generar estos certificados.

--spice-smartcard-certificates=<certificados>
Certificados que se utilizarán para tarjetas inteligentes de software (campo=valores separados por comas)

Esta opción solo es útil para fines de prueba. Esto permite especificar qué certificados de la base de datos de certificados especificada con --spice-smartcard-db se deben usar para la emulación de tarjetas inteligentes.

--spice-cache-size=<bytes>
Tamaño de la caché de imágenes - OBSOLETO

Esta opción solo debe usarse para pruebas/depuración.

--spice-glz-window-size=<bytes>
Tamaño del historial de compresión Glz - OBSOLETO

Esta opción solo debe usarse para pruebas/depuración.
