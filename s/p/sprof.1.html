sprof(1) Manual de Comandos Generales sprof(1)

NOMBRE

sprof - leer y mostrar datos de perfilado de objetos compartidos

SINOPSIS

sprof [opción ...] ruta-objeto-compartido [ruta-datos-perfil]

DESCRIPCIÓN

El comando sprof muestra un resumen del perfilado para el objeto compartido (biblioteca compartida) especificado como su primer argumento de línea de comandos. El resumen del perfilado se crea utilizando datos de perfilado previamente generados en el argumento (opcional) de línea de comandos que figura en segundo lugar. Si se omite la ruta de los datos de perfilado, sprof intentará deducirla utilizando el soname del objeto compartido, buscando un archivo con el nombre <soname>.profile en el directorio actual.

OPCIONES

Las siguientes opciones de línea de comandos especifican la salida del perfil a producir:

--call-pairs
-c
Imprime una lista de pares de rutas de llamada para las interfaces exportadas por el objeto compartido, junto con el número de veces que se utiliza cada ruta.
--flat-profile
-p
Genera un perfil plano de todas las funciones en el objeto monitorizado, con recuentos y ticks.
--graph
-q
Genera un grafo de llamadas.

Si no se especifica ninguna de las opciones anteriores, el comportamiento por defecto es mostrar un perfil plano y un grafo de llamadas.

Las siguientes opciones adicionales de línea de comandos están disponibles:

--help
-?
Muestra un resumen de las opciones y argumentos de la línea de comandos y sale.
--usage
Muestra un breve mensaje de uso y sale.
--version
-V
Muestra la versión del programa y sale.

ESTÁNDARES

GNU.

EJEMPLOS

El siguiente ejemplo demuestra el uso de sprof. El ejemplo consta de un programa principal que llama a dos funciones en un objeto compartido. Primero, el código del programa principal:


$ cat prog.c;
#include <stdlib.h>
void x1(void);
void x2(void);
int
main(int argc, char *argv[])
{
    x1();
    x2();
    exit(EXIT_SUCCESS);
}

Las funciones x1() y x2() se definen en el siguiente archivo fuente que se utiliza para construir el objeto compartido:


$ cat libdemo.c;
#include <unistd.h>
void
consumeCpu1(int lim)
{
    for (unsigned int j = 0; j < lim; j++)
	getppid();
}
void
x1(void) {
    for (unsigned int j = 0; j < 100; j++)
	consumeCpu1(200000);
}
void
consumeCpu2(int lim)
{
    for (unsigned int j = 0; j < lim; j++)
	getppid();
}
void
x2(void)
{
    for (unsigned int j = 0; j < 1000; j++)
	consumeCpu2(10000);
}

Ahora construimos el objeto compartido con el nombre real libdemo.so.1.0.1 y el soname libdemo.so.1:


$ cc -g -fPIC -shared -Wl,-soname,libdemo.so.1 \
        -o libdemo.so.1.0.1 libdemo.c;

Luego construimos enlaces simbólicos para el soname de la biblioteca y el nombre del enlazador de la biblioteca:


$ ln -sf libdemo.so.1.0.1 libdemo.so.1;
$ ln -sf libdemo.so.1 libdemo.so;

A continuación, compilamos el programa principal, enlazándolo contra el objeto compartido, y luego listamos las dependencias dinámicas del programa:


$ cc -g -o prog prog.c -L. -ldemo;
$ ldd prog;
	linux-vdso.so.1 =>  (0x00007fff86d66000)
	libdemo.so.1 => not found
	libc.so.6 => /lib64/libc.so.6 (0x00007fd4dc138000)
	/lib64/ld-linux-x86-64.so.2 (0x00007fd4dc51f000)

Para obtener información de perfilado para el objeto compartido, definimos la variable de entorno LD_PROFILE con el soname de la biblioteca:


$ export LD_PROFILE=libdemo.so.1;

Luego definimos la variable de entorno LD_PROFILE_OUTPUT con la ruta del directorio donde se escribirán los datos de perfilado y creamos ese directorio si aún no existe:


$ export LD_PROFILE_OUTPUT=$(pwd)/prof_data;
$ mkdir -p $LD_PROFILE_OUTPUT;

LD_PROFILE hace que la salida de perfilado se *añada* al archivo de salida si ya existe, por lo que nos aseguramos de que no haya datos de perfilado preexistentes:


$ rm -f $LD_PROFILE_OUTPUT/$LD_PROFILE.profile;

Luego ejecutamos el programa para producir la salida de perfilado, que se escribe en un archivo en el directorio especificado en LD_PROFILE_OUTPUT:


$ LD_LIBRARY_PATH=. ./prog;
$ ls prof_data;
libdemo.so.1.profile

Luego usamos la opción sprof -p para generar un perfil plano con recuentos y ticks:


$ sprof -p libdemo.so.1 $LD_PROFILE_OUTPUT/libdemo.so.1.profile;
Flat profile:
Each sample counts as 0.01 seconds.
  %   cumulative   self              self     total
 time   seconds   seconds    calls  us/call  us/call  name
 60.00      0.06     0.06      100   600.00           consumeCpu1
 40.00      0.10     0.04     1000    40.00           consumeCpu2
  0.00      0.10     0.00        1     0.00           x1
  0.00      0.10     0.00        1     0.00           x2

La opción sprof -q genera un grafo de llamadas:


$ sprof -q libdemo.so.1 $LD_PROFILE_OUTPUT/libdemo.so.1.profile;
index % time    self  children    called     name
                0.00    0.00      100/100         x1 [1]
[0]    100.0    0.00    0.00      100         consumeCpu1 [0]
-----------------------------------------------
                0.00    0.00        1/1           <UNKNOWN>
[1]      0.0    0.00    0.00        1         x1 [1]
                0.00    0.00      100/100         consumeCpu1 [0]
-----------------------------------------------
                0.00    0.00     1000/1000        x2 [3]
[2]      0.0    0.00    0.00     1000         consumeCpu2 [2]
-----------------------------------------------
                0.00    0.00        1/1           <UNKNOWN>
[3]      0.0    0.00    0.00        1         x2 [3]
                0.00    0.00     1000/1000        consumeCpu2 [2]
-----------------------------------------------

Arriba y abajo, las cadenas "<UNKNOWN>" representan identificadores que están fuera del objeto perfilado (en este ejemplo, estas son instancias de main()).

La opción sprof -c genera una lista de pares de llamadas y el número de sus ocurrencias:


$ sprof -c libdemo.so.1 $LD_PROFILE_OUTPUT/libdemo.so.1.profile;
<UNKNOWN>                  x1                                 1
x1                         consumeCpu1                      100
<UNKNOWN>                  x2                                 1
x2                         consumeCpu2                     1000
