SPAWN(8) Manual del Administrador del Sistema SPAWN(8)

NOMBRE

spawn - Iniciador de comandos externos de Postfix

SINOPSIS

spawn [opciones genéricas de demonio de Postfix] atributos_comando...

DESCRIPCIÓN


El demonio spawn(8) monitoriza un socket de flujo de dominio TCP o UNIX, configurado en master.cf con un tipo de servicio inet o unix.

Este demonio inicia un comando externo cada vez que se establece una conexión, con los descriptores de archivo de entrada, salida y error estándar conectados al cliente remoto.

El proceso del comando está sujeto al límite de tiempo especificado con el parámetro transporte_time_limit (por defecto: command_time_limit), donde transporte equivale al nombre del servicio en master.cf. Un proceso que excede el límite de tiempo recibirá una señal SIGKILL.

El servicio demonio spawn(8) típicamente tiene un límite de proceso > 1 en su definición de servicio master.cf, para que el número de procesos pueda escalar según la demanda.

SINTAXIS DE ATRIBUTOS DE COMANDO

Los atributos del comando externo se proporcionan en el archivo master.cf al final de una definición de servicio. La sintaxis es la siguiente:

usuario=nombre_usuario (requerido)
usuario=nombre_usuario:nombre_grupo
El comando externo se ejecuta con los derechos del nombre_usuario especificado. El software se niega a ejecutar comandos con privilegios de root, o con los derechos del propietario del sistema de correo. Si se especifica nombre_grupo, se utiliza el ID de grupo correspondiente en lugar del ID de grupo de nombre_usuario.
argv=comando... (requerido)
El comando a ejecutar. Debe especificarse como el último atributo del comando. El comando se ejecuta directamente, es decir, sin interpretación de caracteres especiales de shell por un intérprete de comandos de shell.

Si un argumento de comando debe contener espacios en blanco, o si un argumento de comando debe comenzar con "{", encierre el argumento con "{" y "}". Esta forma ignorará los espacios en blanco después del "{" exterior y antes del "}" exterior. Ejemplo:



argv=/bin/sh -c { sintaxis de shell aquí }

DIAGNÓSTICO


El demonio spawn(8) informa de salidas anormales de hijos. Los problemas se registran en syslogd(8) o postlogd(8).

SEGURIDAD

El demonio spawn(8) necesita privilegios de root para ejecutar comandos externos como el usuario especificado. Por lo tanto, es sensible a la seguridad.

Sin embargo, el demonio spawn(8) no recibe datos de o sobre clientes de servicio o comandos externos, y por lo tanto no es vulnerable a ataques basados en datos.

PARÁMETROS DE CONFIGURACIÓN

Los cambios en main.cf se capturan automáticamente ya que los procesos spawn(8) se ejecutan solo durante un tiempo limitado. Use el comando "postfix reload" para acelerar un cambio.

El texto a continuación proporciona solo un resumen de parámetros. Consulte postconf(5) para obtener más detalles, incluidos ejemplos.

En el texto a continuación, transporte es el primer campo de la entrada en el archivo master.cf.

CONTROL DE RECURSOS Y TARIFAS

transport_time_limit ($command_time_limit)
Una anulación específica del transporte para el valor del parámetro command_time_limit, donde transporte es el nombre de master.cf del transporte de entrega de mensajes.

El tiempo máximo que un proceso demonio de Postfix inactivo espera una conexión entrante antes de terminar voluntariamente.
max_use (100)
El número máximo de conexiones entrantes que un proceso demonio de Postfix atenderá antes de terminar voluntariamente.
process_id (solo lectura)
El ID del proceso de un comando o proceso demonio de Postfix.

syslog_facility (mail)

spawn(8)

NAME

spawn - Postfix pipe(8) service for non-local delivery.

SYNOPSIS

spawn [-d]

DESCRIPTION

The spawn command is a Postfix(5) service that is used for non-local delivery of email messages. It is typically invoked by the pipe(8) service to deliver mail to external commands or scripts.

The spawn service is configured in the Postfix master.cf file. It takes an email message as standard input and delivers it to an external command or script specified in the pipe(8) service's configuration.

The -d option disables debugging messages.

COMMAND ATTRIBUTE SYNTAX

The spawn command itself does not have any command-line attributes or arguments other than the optional -d flag. All configuration and control over the delivery process are handled by the Postfix main configuration file (main.cf) and the master configuration file (master.cf).

DIAGNOSTICS

The spawn service logs its actions to the Postfix mail log. Diagnostic messages typically include information about the delivery process, any errors encountered, and the status of the delivery attempt.

Common error conditions include:

  • Failure to execute the external command or script.
  • Errors returned by the external command or script.
  • Problems with mail routing or delivery.

The verbosity of logging can be controlled by the pipe_service_level parameter in main.cf.

SECURITY

The spawn service executes external commands, which can pose a security risk if not properly configured. It is crucial to ensure that the commands or scripts executed by spawn are trusted and do not have vulnerabilities that could be exploited.

Consider the following security measures:

  • Run spawn with minimal privileges.
  • Do not execute untrusted commands or scripts.
  • Sanitize any input passed to the external commands or scripts.
  • Use dedicated, restricted environments for executing external commands if possible.

CONFIGURATION PARAMETERS

The behavior of the spawn service is primarily controlled by parameters defined in the Postfix main.cf and master.cf files. Key parameters include:

  • pipe_command: Specifies the command to be executed for delivery.
  • pipe_args: Specifies the arguments to be passed to the command.
  • pipe_timeout: The time limit for the command to complete.
  • pipe_busy_limit: The maximum number of concurrent pipe(8) processes.

These parameters are configured within the pipe service entry in master.cf.

RESOURCE AND RATE CONTROL

Resource and rate control for the spawn service are managed through Postfix's general queue management and rate limiting mechanisms. Parameters such as pipe_busy_limit in master.cf limit the number of concurrent processes that can be spawned. Additionally, Postfix's global rate limiting parameters can be used to control the overall rate of delivery attempts.

MISCELLANEOUS

The spawn service is a low-level component of Postfix's delivery infrastructure. It is designed to be flexible and allow integration with various external programs and scripts for customized mail processing and delivery.
