splice(2) Manual de llamadas al sistema splice(2)

NOMBRE

splice - transfiere datos a/desde una tubería (pipe)

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE         /* Véase feature_test_macros(7) */
#define _FILE_OFFSET_BITS 64
#include <fcntl.h>
ssize_t splice(int fd_in, off_t *_Nullable off_in,
               int fd_out, off_t *_Nullable off_out,
               size_t size, unsigned int flags);

DESCRIPCIÓN

splice() mueve datos entre dos descriptores de archivo sin copiar entre el espacio de direcciones del kernel y el espacio de direcciones del usuario. Transfiere hasta size bytes de datos desde el descriptor de archivo fd_in al descriptor de archivo fd_out, donde uno de los descriptores de archivo debe referirse a una tubería (pipe).

Las siguientes semánticas se aplican para fd_in y off_in:

•
Si fd_in se refiere a una tubería, entonces off_in debe ser NULL.
•
Si fd_in no se refiere a una tubería y off_in es NULL, entonces se leen bytes de fd_in comenzando desde el offset del archivo, y el offset del archivo se ajusta apropiadamente.
•
Si fd_in no se refiere a una tubería y off_in no es NULL, entonces off_in debe apuntar a un buffer que especifique el offset de inicio desde el cual se leerán los bytes de fd_in; en este caso, el offset del archivo de fd_in no se modifica, y en su lugar se ajusta el offset al que apunta off_in.

Declaraciones análogas se aplican para fd_out y off_out.

El argumento flags es una máscara de bits que se compone mediante la operación OR de cero o más de los siguientes valores:

SPLICE_F_MOVE
Intenta mover páginas en lugar de copiarlas. Esto es solo una pista para el kernel: las páginas aún pueden ser copiadas si el kernel no puede mover las páginas de la tubería, o si los buffers de la tubería no se refieren a páginas completas. La implementación inicial de esta bandera fue defectuosa: por lo tanto, a partir de Linux 2.6.21 es un no-op (pero todavía se permite en una llamada splice()); en el futuro, puede restaurarse una implementación correcta.
SPLICE_F_NONBLOCK
No bloquea en I/O. Esto hace que las operaciones de la tubería de splice no bloqueen, pero splice() puede bloquearse ya que los descriptores de archivo que se empalman hacia/desde pueden bloquearse (a menos que tengan el flag O_NONBLOCK establecido).
SPLICE_F_MORE
Vendrán más datos en un splice posterior. Esto es una pista útil cuando fd_out se refiere a un socket (ver también la descripción de MSG_MORE en send(2), y la descripción de TCP_CORK en tcp(7)).
SPLICE_F_GIFT
No utilizado para splice(); ver vmsplice(2).

VALOR DE RETORNO

Al completarse con éxito, splice() devuelve el número de bytes transferidos hacia o desde la tubería.

Un valor de retorno de 0 significa fin de entrada. Si fd_in se refiere a una tubería, significa que no había datos para transferir, y no tendría sentido bloquear ya que no hay escritores conectados al extremo de escritura de la tubería.

En caso de error, splice() devuelve -1 y errno se establece para indicar el error.

ERRORES

EAGAIN
Se especificó SPLICE_F_NONBLOCK en flags o uno de los descriptores de archivo se había marcado como no bloqueante (O_NONBLOCK), y la operación bloquearía.
EBADF
Uno o ambos descriptores de archivo no son válidos, o no tienen el modo de lectura-escritura adecuado.
EINVAL
El sistema de archivos de destino no admite el empalme.
EINVAL
El archivo de destino está abierto en modo de añadir (append).
EINVAL
Ninguno de los descriptores de archivo se refiere a una tubería.
EINVAL
Se proporcionó un offset para un dispositivo no buscable (por ejemplo, una tubería).
EINVAL
fd_in y fd_out se refieren a la misma tubería.
ENOMEM
Falta de memoria.
ESPIPE
O bien off_in o off_out no era NULL, pero el descriptor de archivo correspondiente se refiere a una tubería.

ESTÁNDARES

Linux.

HISTORIA

Linux 2.6.17, glibc 2.5.

En Linux 2.6.30 y anteriores, se requería que exactamente uno de fd_in y fd_out fuera una tubería. Desde Linux 2.6.31, ambos argumentos pueden referirse a tuberías.

NOTAS

Las tres llamadas al sistema splice(), vmsplice(2) y tee(2), proporcionan a los programas de espacio de usuario control total sobre un búfer arbitrario del kernel, implementado dentro del kernel utilizando el mismo tipo de búfer que se usa para una tubería. En resumen, estas llamadas al sistema realizan las siguientes tareas:

splice()
mueve datos desde el búfer a un descriptor de archivo arbitrario, o viceversa, o de un búfer a otro.
tee(2)
"copia" los datos de un búfer a otro.
vmsplice(2)
"copia" datos del espacio de usuario al búfer.

Aunque hablamos de copiar, generalmente se evitan las copias reales. El kernel lo hace implementando un búfer de tubería como un conjunto de punteros contadores de referencias a páginas de memoria del kernel. El kernel crea "copias" de páginas en un búfer creando nuevos punteros (para el búfer de salida) que se refieren a las páginas, e incrementando los contadores de referencias para las páginas: solo se copian los punteros, no las páginas del búfer.

_FILE_OFFSET_BITS debe definirse como 64 en el código que usa off_in u off_out no NULL o que toma la dirección de splice, si el código está destinado a ser portable a plataformas x86 y ARM tradicionales de 32 bits donde el ancho de off_t por defecto es de 32 bits.
