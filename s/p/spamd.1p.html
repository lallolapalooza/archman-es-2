NOMBRE

spamd - versión demonizada de spamassassin

SINOPSIS

spamd [opciones]

Opciones:

-l, --allow-tell                  Permitir aprendizaje/informe
-c, --create-prefs                Crear archivos de preferencias de usuario
-C path, --configpath=path        Ruta para los archivos de configuración predeterminados
--siteconfigpath=path             Ruta para las configuraciones del sitio
--cf='línea de configuración'      Línea de configuración adicional
--pre='línea de configuración'     Línea adicional de ".pre" (agregada al principio de la configuración)
-d, --daemonize                   Convertir en demonio
-h, --help                        Imprimir mensaje de uso
-i [ip_o_nombre[:puerto]], --listen=[ip_o_nombre[:puerto]] Escuchar en IP y puerto
-p puerto, --port=puerto          Escuchar en el puerto especificado, puede ser anulado por -i
-4, --ipv4-only, --ipv4           Usar IPv4 donde sea aplicable, deshabilita IPv6
-6                                Usar IPv6 donde sea aplicable, deshabilita IPv4
-A host,..., --allowed-ips=..,..  Restringir a direcciones IP que pueden conectarse
-m num, --max-children=num        Permitir un número máximo de hijos
--min-children=num                Permitir un número mínimo de hijos
--min-spare=num                   Límite inferior para el número de hijos de repuesto
--max-spare=num                   Límite superior para el número de hijos de repuesto
--max-conn-per-child=num          Conexiones máximas aceptadas por un hijo 
                                  antes de que sea reiniciado
--round-robin                     Usar el algoritmo tradicional prefork
--timeout-tcp=secs                Tiempo de espera de conexión para encabezados de cliente
--timeout-child=secs              Tiempo de espera de conexión para comprobaciones de mensajes
-q, --sql-config                  Habilitar configuración SQL (requiere -x)
-Q, --setuid-with-sql             Habilitar configuración SQL (requiere -x,
                                  habilita el uso de -H)
--ldap-config                     Habilitar configuración LDAP (requiere -x)
--setuid-with-ldap                Habilitar configuración LDAP (requiere -x,
                                  habilita el uso de -H)
--virtual-config-dir=dir          Habilitar configuraciones virtuales basadas en patrones
                                  (requiere -x)
-r pidfile, --pidfile             Escribir el id de proceso en pidfile
-s facility, --syslog=facility    Especificar la facilidad de syslog
--syslog-socket=type              Cómo conectarse a syslogd
--log-timestamp-fmt=fmt           Formato strftime(3) para marcas de tiempo, puede ser
                                  vacío para deshabilitar marcas de tiempo, o 'default'
-u username, --username=username  Ejecutar como username
-g groupname, --groupname=groupname  Ejecutar como groupname
-v, --vpopmail                    Habilitar configuración vpopmail
-x, --nouser-config               Deshabilitar archivos de configuración de usuario
-U username, --default-user=username  Recurrir a este username si el usuario de spamc
                                  no se encuentra (predeterminado: nobody)
-D, --debug[=areas]               Imprimir mensajes de depuración (para áreas)
-L, --local                       Usar solo pruebas locales (sin DNS)
-P, --paranoid                    Morir ante errores de usuario
-H [dir], --helper-home-dir[=dir] Especificar un directorio HOME diferente
--ssl                             Habilitar SSL en conexiones TCP
--ssl-verify                      Solicitar un certificado de cliente y verificarlo
--ssl-ca-file cafile              Archivo de certificado de la Autoridad Certificadora
--ssl-ca-path capath              Directorio de la Autoridad Certificadora
--ssl-port port                   Anular la configuración de --port para conexiones SSL
--server-key keyfile              Especificar un archivo de clave SSL
--server-cert certfile            Especificar un certificado SSL
--socketpath=path                 Escuchar en un socket de dominio UNIX dado
--socketowner=name                Establecer el propietario del archivo del socket de dominio UNIX
--socketgroup=name                Establecer el grupo del archivo del socket de dominio UNIX
--socketmode=mode                 Establecer el modo del archivo del socket de dominio UNIX
--timing                          Habilitar temporización y registro
-V, --version                     Imprimir versión y salir

La opción --listen (o -i) se puede especificar varias veces, su sintaxis es: [ ssl: ] [ nombre-host-o-dirección-IP ] [ : puerto ] o una ruta absoluta (nombre de archivo) de un socket de Unix. Si se omite el puerto, predetermina --port o 783. La opción --ssl implica un prefijo 'ssl:'. Una dirección IPv6 debe estar entre corchetes, por ejemplo, [::1]:783, una dirección IPv4 puede estarlo pero no es necesario, entre corchetes. Un asterisco '*' en lugar de un nombre de host implica una dirección no especificada, ('0.0.0.0' o '::'), es decir, se vincula a todas las interfaces. Una opción vacía implica '*'. El valor predeterminado es '--listen localhost', que se vincula solo a una interfaz de bucle inverso.

DESCRIPCIÓN

El propósito de este programa es proporcionar una versión demonizada del ejecutable spamassassin. El objetivo es mejorar el rendimiento de producción para la comprobación automática de correo.

La intención es usarlo junto con "spamc", un programa cliente C rápido y de baja sobrecarga.

Consulte el archivo README en el directorio "spamd" de la distribución SpamAssassin para más detalles.

Nota: Aunque "spamd" comprobará los archivos de configuración por usuario para cada mensaje, cualquier cambio en los archivos de configuración a nivel de sistema requerirá reiniciar spamd o forzar su recarga mediante SIGHUP para que los cambios tengan efecto.

Nota: Si "spamd" recibe una señal SIGHUP, se recarga internamente, lo que significa que cambiará su PID y es posible que no se reinicie en absoluto si su entorno ha cambiado (por ejemplo, si no puede volver a su propio directorio). Si planea usar SIGHUP, siempre debe iniciar "spamd" con el interruptor -r para conocer su PID actual.

OPCIONES

Las opciones de la forma larga se pueden acortar siempre que sigan sin ser ambiguas. (es decir, se puede usar --dae en lugar de --daemonize). Además, las opciones booleanas (como --user-config) se pueden negar agregando no (--nouser-config), sin embargo, esto suele ser innecesario.

-l, --allow-tell
Permite el aprendizaje y el olvido (a una base de datos Bayes local), el informe y la revocación (a una base de datos remota) por parte de spamd. El cliente emite un comando TELL para indicar qué tipo de mensaje se está procesando y si las bases de datos locales (aprender/olvidar) o remotas (informar/revocar) deben actualizarse.

Tenga en cuenta que spamd siempre confía en el nombre de usuario pasado, por lo que los clientes podrían aprender maliciosamente mensajes para otros usuarios. (Esto normalmente no es una preocupación con un almacén Bayes SQL, ya que los usuarios normalmente tendrán acceso de lectura/escritura directamente a la base de datos, y también pueden usar "sa-learn" con la opción -u para lograr el mismo resultado).

-c, --create-prefs
Crea archivos de preferencias de usuario si no existen (predeterminado: no los crea).
-C ruta, --configpath=ruta
Usa la ruta especificada para localizar los archivos de configuración distribuidos. Ignora los directorios predeterminados (generalmente "/usr/share/spamassassin" o similar).
--siteconfigpath=ruta
Usa la ruta especificada para localizar los archivos de configuración específicos del sitio. Ignora los directorios predeterminados (generalmente "/etc/mail/spamassassin" o similar).
--cf='línea de configuración'
Agrega líneas de configuración adicionales directamente desde la línea de comandos, analizadas después de leer los archivos de configuración. Se pueden usar varios argumentos --cf, y cada uno se considerará una línea de configuración separada.
--pre='línea de configuración'
Agrega líneas de configuración .pre adicionales directamente desde la línea de comandos, analizadas antes de leer los archivos de configuración. Se pueden usar varios argumentos --pre, y cada uno se considerará una línea de configuración separada.
-d, --daemonize
Desacoplar del proceso de inicio y ejecutar en segundo plano (convertir en demonio).
-h, --help
Imprimir un breve mensaje de ayuda y salir sin más acciones.
-V, --version
Imprimir información de la versión y salir sin más acciones.

Si se usa el interruptor --ssl y se establece --ssl-port, entonces se aceptarán conexiones no cifradas en el --port al mismo tiempo que se aceptan conexiones cifradas en el --ssl-port. -q, --sql-config Activar búsquedas SQL incluso cuando los archivos de configuración por usuario han sido deshabilitados con -x. esto es útil para hosts de spamd que no tienen directorios de inicio de usuario pero sí desean cargar preferencias de usuario desde una base de datos SQL. Si tu cliente spamc no soporta el envío de la cabecera "User:", como "exiscan", entonces el nombre de usuario SQL utilizado siempre será nobody. Esto inhibe el comportamiento setuid(), por lo que se requiere la opción "-u". Si deseas el comportamiento setuid(), usa "-Q" o "--setuid-with-sql" en su lugar. --ldap-config Activar búsquedas LDAP. Esto es completamente análogo a "--sql-config", solo que utiliza un servidor LDAP. Al igual que "--sql-config", esto deshabilita el comportamiento setuid y requiere "-u". Si lo deseas, usa "--setuid-with-ldap" en su lugar. -Q, --setuid-with-sql Activar búsquedas SQL incluso cuando los archivos de configuración por usuario han sido deshabilitados con -x y también hacer setuid al usuario. Esto es útil para hosts de spamd que desean cargar preferencias de usuario desde una base de datos SQL pero también desean soportar el uso de -H (Directorios de inicio de ayudante). --setuid-with-ldap Activar búsquedas LDAP incluso cuando los archivos de configuración por usuario han sido deshabilitados con -x y también hacer setuid al usuario. Esto es nuevamente completamente análogo a "--setuid-with-sql", solo que utiliza un servidor LDAP. --virtual-config-dir=patrón Esta opción especifica dónde se pueden encontrar las preferencias por usuario para usuarios virtuales, para el interruptor -x. El patrón se usa como patrón base para el nombre del directorio. Se pueden usar cualquiera de los siguientes escapes: %u -- se reemplaza con el nombre completo del usuario actual, tal como lo envía spamc. %l -- se reemplaza con la 'parte local' del nombre de usuario actual. En otras palabras, si el nombre de usuario es una dirección de correo electrónico, esta es la parte antes del signo "@". %d -- se reemplaza con el 'dominio' del nombre de usuario actual. En otras palabras, si el nombre de usuario es una dirección de correo electrónico, esta es la parte después del signo "@". %x -- se reemplaza con el nombre completo del usuario actual, tal como lo envía spamc. Si el directorio de configuración resultante no existe, reemplaza con la parte del dominio para usar un valor predeterminado en todo el dominio. %% -- se reemplaza con un solo signo de porcentaje (%). Entonces, por ejemplo, si se especifica "/vhome/users/%u/spamassassin" y spamc envía un nombre de usuario virtual de "jm@example.com", se usará el directorio "/vhome/users/jm@example.com/spamassassin". El conjunto de caracteres permitidos en el nombre de usuario virtual para esta ruta está restringido a: A-Z a-z 0-9 - + _ . , @ = Todos los demás se reemplazarán por guiones bajos ("_"). Esta ruta debe ser un directorio escribible. Se creará si no existe. Si existe un archivo llamado user_prefs en este directorio (¡nota: no en un subdirectorio ".spamassassin"!), se cargará como las preferencias del usuario. Las bases de datos Bayes para ese usuario se almacenarán en este directorio. Ten en cuenta que esto requiere que se use -x y no se puede combinar con la configuración basada en SQL o LDAP. El patrón debe expandirse a un directorio absoluto cuando spamd se esté ejecutando como demonio (-d). Actualmente, el uso de esto sin -u no es compatible. Esto inhibe setuid. -r pidfile, --pidfile=pidfile Escribir el ID del proceso del padre de spamd en el archivo especificado por pidfile. El archivo se eliminará cuando el padre salga. Ten en cuenta que cuando se ejecuta con la opción -u, el archivo debe ser escribible por ese usuario. -v, --vpopmail Activar la configuración de vpopmail. Si se especifica con -u configurado en el usuario de vpopmail, esto permite a spamd buscar/crear user_prefs en el propio maildir del usuario de vpopmail. Esta opción es útil para usuarios virtuales de vpopmail que no tienen una entrada en el archivo /etc/passwd del sistema. Actualmente, el uso de esto sin -u no es compatible. Esto inhibe setuid. -s facility, --syslog=facility Especificar la instalación de syslog a utilizar (por defecto: mail). Si se especifica "stderr", la salida se escribirá en stderr. (Esto es útil si estás ejecutando "spamd" bajo el paquete "daemontools".) Con una instalación de "file", toda la salida va a spamd.log. La instalación se interpreta como un nombre de archivo al que registrar si contiene algún carácter excepto a-z y 0-9. "null" deshabilita el registro completamente (se usa internamente). Ejemplos: spamd -s mail # usar syslog, instalación mail (predeterminada) spamd -s ./mail # registrar en archivo ./mail spamd -s stderr 2>/dev/null # registrar en stderr, descartar mensajes spamd -s null # lo mismo que lo anterior spamd -s file # registrar en archivo ./spamd.log spamd -s /var/log/spamd.log # registrar en archivo /var/log/spamd.log Si se habilita el registro en un archivo y ese archivo de registro se rota, el servidor spamd debe reiniciarse con un SIGHUP. (Si el archivo de registro simplemente se trunca, esto no es necesario pero aún así se recomienda). Ten en cuenta que el registro en un archivo no utiliza bloqueo, por lo que no puedes mezclar registros de spamd y otros procesos en el mismo archivo. Si deseas mezclar el registro de esta manera, usa syslog en su lugar. Si utilizas el registro de syslog, es esencial enviar un SIGHUP al demonio spamd cuando reinicies el demonio syslogd. (Esto se debe a una deficiencia en el manejo de syslog de Perl, donde la desaparición de la conexión a syslogd se considera un error fatal). --syslog-socket=type Especificar cómo spamd debe enviar mensajes a syslogd. El tipo puede ser cualquiera de los tipos de socket o mecanismos de registro aceptados por la subrutina Sys::Syslog::setlogsock(). Dependiendo de la versión de Sys::Syslog y del sistema operativo subyacente, se pueden usar uno de los siguientes valores (o un subconjunto de ellos): "native", "eventlog", "tcp", "udp", "inet", "unix", "stream", "pipe", o "console". El valor "eventlog" es específico del registrador de eventos de Win32 y requiere que se instale el módulo perl Win32::EventLog. Para más información, consulta la documentación de Sys::Syslog. Una configuración histórica --syslog-socket=none se mapea a --syslog=stderr. El valor predeterminado para las plataformas Windows es "none", de lo contrario, el valor predeterminado es intentar "unix" primero, y si falla, recurrir a "inet" si perl detecta errores en su soporte "unix". Algunas plataformas, o versiones de perl, se envían con versiones antiguas o defectuosas del módulo Sys::Syslog que no soportan algunos tipos de socket, por lo que es posible que necesites establecer esta opción explícitamente. Si recibes mensajes de error relacionados con __PATH_LOG o similares de spamd, intenta cambiar esta configuración. Los tipos de socket "file" se utilizan internamente y no deben especificarse. Utiliza el interruptor "-s" en su lugar. --log-timestamp-fmt=formato La opción --log-timestamp-fmt puede proporcionar un formato strftime(3) POSIX para las marcas de tiempo incluidas en cada mensaje registrado. Cada registrador (stderr, file, syslog) tiene su propio valor predeterminado para un formato de marca de tiempo, que se aplica cuando no se proporciona la opción --log-timestamp-fmt, o con --log-timestamp-fmt=default. Las marcas de tiempo se pueden desactivar especificando una cadena vacía con esta opción, por ejemplo, --log-timestamp-fmt='' o simplemente --log-timestamp-fmt=. Uso típico: --log-timestamp-fmt='%a %b %e %H:%M:%S %Y' (proporciona nombres de días de la semana y meses localizados en el estilo ctime(3)), o '%a, %e %b %Y %H:%M:%S %z (%Z) para un formato RFC 2822, o quizás '%Y-%m-%d %H:%M:%S%z' para un formato ISO 8601 (EN 28601), o simplemente '%Y%m%dT%H%M%S'.
-u nombredeusuario, --username=nombredeusuario
Ejecutar como el usuario nombrado. Si esta opción no está configurada, el comportamiento predeterminado es hacer setuid() al usuario que ejecuta "spamc", si "spamd" se está ejecutando como root.

Nota: "--username=root" no es una opción válida. Si se especifica, "spamd" saldrá con un error fatal al inicio.

-g nombredegrupo, --groupname=nombredegrupo
Ejecutar como el grupo nombrado si se está usando --username. Si esta opción no está configurada cuando se usa --username, entonces se utiliza el grupo principal del usuario proporcionado a --username.
-x, --nouser-config, --user-config
Desactivar (activar) la lectura de archivos de configuración por usuario (user_prefs) desde el directorio de inicio del usuario. El comportamiento predeterminado es leer la configuración por usuario desde el directorio de inicio del usuario (--user-config).

Esta opción no deshabilita ni influye de ninguna otra manera en la configuración de SQL, LDAP o Directorio de Configuración Virtual.

-U nombredeusuario, --default-user=nombredeusuario
Retroceder a este nombre de usuario si el nombre de usuario proporcionado por spamc no se encuentra. El valor predeterminado es nobody, que podría no existir o no tener un directorio de inicio utilizable; usa esta configuración para definir un usuario adecuado si es necesario.
-A host,..., --allowed-ips=host,...
Especifica una lista separada por comas de hosts o redes autorizadas que pueden conectarse a esta instancia de spamd. Cada elemento de la lista es una dirección IP única, o un rango de direcciones IP en notación CIDR de máscara de red, o rangos de direcciones IPv4 especificando 3 o menos octetos con un punto final. No se admiten nombres de host, solo direcciones IPv4 o IPv6. Esta opción se puede especificar varias veces o puede tomar una lista de direcciones separadas por comas. Las direcciones IPv6 pueden estar (pero no es necesario que lo estén) encerradas entre corchetes para coherencia con la opción --listen. Ejemplos:

-A 10.11.12.13 -- solo permitir conexiones desde 10.11.12.13.

-A 10.11.12.13,10.11.12.14 -- solo permitir conexiones desde 10.11.12.13 y 10.11.12.14.

-A 10.200.300.0/24 -- permitir conexiones desde cualquier máquina en el rango "10.200.300.*".

-A 10. -- permitir conexiones desde cualquier máquina en el rango "10.*.*.*".

-A [2001:db8::]/32,192.0.2.0/24,::1,127.0.0.0/8 -- solo aceptar conexiones de redes de prueba especificadas y de localhost.

En ausencia de la opción -A, solo se aceptan conexiones de la dirección IP 127.0.0.1 o ::1, es decir, de localhost en una interfaz de loopback.

-D [area,...], --debug [area,...]
Producir salida de depuración. Si no se listan áreas, se imprimirá toda la información de depuración. La salida de diagnóstico también se puede habilitar para cada área individualmente; area es el área del código a instrumentar. Por ejemplo, para producir salida de diagnóstico en bayes, learn y dns, usa: 
spamassassin -D bayes,learn,dns

Los mensajes informativos de mayor prioridad que son adecuados para el registro en circunstancias normales están disponibles con el área "info".

Para más información sobre qué áreas (también conocidas como canales) están disponibles, por favor consulta la documentación en:

C<https://wiki.apache.org/spamassassin/DebugChannels>
-4, --ipv4only, --ipv4-only, --ipv4
Usar IPv4 cuando sea aplicable, no usar IPv6. La opción afecta a un conjunto de sockets de escucha (ver opción "--listen") y deshabilita IPv6 para pruebas DNS.
-6
Usar IPv6 cuando sea aplicable, no usar IPv4. La opción afecta a un conjunto de sockets de escucha (ver opción "--listen") y deshabilita IPv4 para pruebas DNS. Se recomienda instalar un módulo IO::Socket::IP si se espera que spamd reciba solicitudes a través de IPv6.
-L, --local
Realizar solo pruebas locales en todo el correo. En otras palabras, omitir DNS y otras pruebas de red. Funciona igual que el indicador "-L" de spamassassin(1).
-P, --paranoid
Morir ante errores del usuario (para el usuario pasado desde spamc) en lugar de retroceder al usuario "--default-user" y usar la configuración predeterminada.
-m número , --max-children=número
Esta opción especifica el número máximo de procesos hijos a generar. Spamd generará ese número de procesos hijos, luego dormirá en segundo plano hasta que un proceso hijo muera, momento en el cual irá y generará un nuevo proceso hijo.

Las conexiones entrantes aún pueden ocurrir si todos los procesos hijos están ocupados, sin embargo, esas conexiones se pondrán en cola esperando un proceso hijo libre. El valor mínimo es 1, el valor predeterminado es 5.

Por favor, ten en cuenta que existe un máximo específico del sistema operativo de conexiones que pueden ponerse en cola (Intenta "perl -MSocket -e'print SOMAXCONN'" para encontrar este máximo).

Ten en cuenta que si ejecutas demasiados servidores para la cantidad de RAM libre disponible, corres el peligro de perjudicar el rendimiento al causar una alta carga de intercambio ya que los procesos del servidor se intercambian continuamente.

--min-children=número
El número mínimo de procesos hijos que se mantendrán en ejecución. El valor mínimo es 1, el valor predeterminado es 1. Si tienes mucha RAM libre, es posible que quieras aumentar esto.
--min-spare=número
El límite inferior para el número de procesos hijos de repuesto permitidos en ejecución. Un proceso hijo de repuesto o inactivo es aquel que no está gestionando una solicitud de escaneo. Si hay muy pocos procesos hijos de repuesto disponibles, se iniciará un nuevo servidor cada segundo más o menos. El valor predeterminado es 1.
--max-spare=número
El límite superior para el número de procesos hijos de repuesto permitidos en ejecución. Si hay demasiados procesos hijos de repuesto, uno será terminado cada segundo más o menos hasta que el número de procesos hijos inactivos esté en el rango deseado. El valor predeterminado es 2.
--max-conn-per-child=número
Esta opción especifica el número máximo de conexiones que cada proceso hijo debería procesar antes de morir y permitir que el proceso maestro spamd genere un nuevo proceso hijo. El valor mínimo es 1, el valor predeterminado es 200.
--round-robin
Por defecto, "spamd" intentará mantener un pequeño número de procesos hijos "calientes" lo más ocupados posible, y mantener los demás lo más inactivos posible, utilizando algo similar al algoritmo de escalado del servidor httpd de Apache. Esto se logra mediante el proceso maestro que coordina las actividades de los procesos hijos. Este interruptor deshabilitará este algoritmo de escalado, y se utilizará el comportamiento visto en las versiones 3.0.x, donde todos los procesos reciben una carga igual y no se realiza ningún escalado.
--timeout-tcp=número
Esta opción especifica el número de segundos a esperar por las cabeceras de un cliente (spamc) antes de cerrar la conexión. El valor mínimo es 1, el valor predeterminado es 30, y un valor de 0 deshabilitará los tiempos de espera del socket por completo.
--timeout-child=número
Esta opción especifica el número de segundos a esperar a que un proceso hijo de spamd procese o verifique un mensaje. El valor mínimo es 1, el valor predeterminado es 300, y un valor de 0 deshabilitará los tiempos de espera del proceso hijo por completo.

NOMBRE

spamd — demonio de filtrado de spam de SpamAssassin

SINOPSIS

spamd [ --allow-tell-bad ] [ --allow-tell-good ] [ --bayes-auto-learn ] [ --bayes-cleanup-interval number ] [ --bayes-store-cutoff number ] [ --cachedir directory ] [ --create-prefs-file ] [ --daemonize | -d ] [ --debug [category [,...] ]] [ --dump-prefs ] [ --filter-only ] [ --help ] [ --heartbeat-interval number ] [ --IMAP-url url ] [ --IMAP-user username ] [ --IMAP-passwd password ] [ --IMAP-ns namespace ] [ --IMAP-conn-expire seconds ] [ --IMAP-conn-max count ] [ --IMAP-copy=folder ] [ --IMAP-copy=folder ] [ --IMAP-copy-seen=folder ] [ --IMAP-copy-seen=folder ] [ --IMAP-copy-spam=folder ] [ --IMAP-copy-spam=folder ] [ --IMAP-keep-message ] [ --IMAP-set-flags=flags ] [ --IMAP-set-flags=flags ] [ --IMAP-remove-flags=flags ] [ --IMAP-remove-flags=flags ] [ --IMAP-skip-spam-folder ] [ --IMAP-skip-spam-folder ] [ --IMAP-store-spam=folder ] [ --IMAP-store-spam=folder ] [ --IMAP-user-dir dir ] [ --IMAP-user-dir dir ] [ --IMAP-username-format format ] [ --IMAP-username-format format ] [ -l | --listen [=address ]] [ --log-level level ] [ --log-topic topic [,...] ] [ --max-child-processes number ] [ --max-restarts number ] [ --max-servers number ] [ --pidfile pidfile ] [ --port port ] [ --prefs-file file ] [ --quiet ] [ --read-timeout seconds ] [ --relax-ruleset-path ] [ --send-socket pathname ] [ --socketpath pathname ] [ --socketowner name ] [ --socketgroup name ] [ --socketmode mode ] [ --stats-interval number ] [ --stats-mail-stat-interval number ] [ --stats-per-user-interval number ] [ --stats-socket pathname ] [ --stats-user-socket pathname ] [ --syslog [=facility ]] [ --timing ] [ -u | --username username ] [ --utf8-messages ] [ -v | --verbose ] [ --version ] [ -X | --exclude-home-dir ] --allowed-ips ip [,...] --allowed-methods method [,...] --max-unauthenticated-users number --user-scores file ]

DESCRIPCIÓN

El demonio spamd es un servidor que escucha solicitudes de spamc (el cliente) y utiliza el conjunto de reglas de SpamAssassin para determinar si un correo electrónico es spam.

Los clientes se conectan a spamd a través de sockets de red (TCP) o sockets de dominio UNIX. spamd acepta la entrada estándar de un cliente, la pasa a través de SpamAssassin, y devuelve la puntuación de spam resultante, así como otras estadísticas, al cliente.

Cuando se inicia spamd, generalmente se ejecuta como un demonio en segundo plano. Si se invoca con la opción -d o --daemonize, se bifurcará en segundo plano y continuará ejecutándose. De lo contrario, se ejecutará en primer plano.

OPCIONES

--allow-tell-bad
Permite que los usuarios envíen correos electrónicos marcados como spam a spamd para aprender. Esto es lo mismo que --allow-tell-good.
--allow-tell-good
Permite que los usuarios envíen correos electrónicos marcados como no spam a spamd para aprender. Esto es lo mismo que --allow-tell-bad.
--bayes-auto-learn
Activa el aprendizaje automático de Bayes. Si se activa, spamd intentará aprender automáticamente sobre los correos electrónicos que procesa. Esto puede mejorar la precisión con el tiempo.
--bayes-cleanup-interval número
Establece el intervalo de limpieza para la base de datos de Bayes. El valor es en horas. Un valor de 0 deshabilita la limpieza automática.
--bayes-store-cutoff número
Establece el umbral de puntuación de corte para el aprendizaje de Bayes. Las puntuaciones por debajo de este umbral no se aprenderán.
--cachedir directorio
Especifica el directorio donde se almacenarán los archivos cacheados. El valor predeterminado es ~/.spamassassin/cache/.
--create-prefs-file
Si el archivo de preferencias no existe, se creará uno nuevo con la configuración predeterminada.
--daemonize, -d
Ejecuta spamd como un demonio en segundo plano.
--debug [categoría[,...]]
Habilita la depuración. Se puede especificar una o más categorías separadas por comas para limitar la salida de depuración. Por ejemplo, --debug=bayes,bayes_learn.
--dump-prefs
Imprime las preferencias utilizadas y sale.
--filter-only
Solo realiza el filtrado de correo electrónico y no se conecta a la base de datos de Bayes ni a otros servicios externos.
--heartbeat-interval número
Establece el intervalo del latido del corazón del proceso principal en segundos.
--IMAP-url url
URL del servidor IMAP, p. ej., imaps://imap.example.com:993/.
--IMAP-user nombredeusuario
Nombre de usuario para conectarse al servidor IMAP.
--IMAP-passwd contraseña
Contraseña para conectarse al servidor IMAP.
--IMAP-ns espacioNombres
Espacio de nombres IMAP a utilizar, p. ej., INBOX.
--IMAP-conn-expire segundos
Tiempo en segundos antes de que se expire una conexión IMAP inactiva. El valor predeterminado es 60.
--IMAP-conn-max conteo
Número máximo de conexiones IMAP simultáneas. El valor predeterminado es 10.
--IMAP-copy=carpeta
Copia los correos electrónicos procesados a la carpeta IMAP especificada.
--IMAP-copy-seen=carpeta
Copia los correos electrónicos procesados a la carpeta IMAP especificada y marca como leídos.
--IMAP-copy-spam=carpeta
Copia los correos electrónicos marcados como spam a la carpeta IMAP especificada.
--IMAP-keep-message
No elimina los correos electrónicos del servidor IMAP después del procesamiento.
--IMAP-set-flags=flags
Establece las banderas IMAP especificadas en los correos electrónicos procesados.
--IMAP-remove-flags=flags
Elimina las banderas IMAP especificadas de los correos electrónicos procesados.
--IMAP-skip-spam-folder
No procesa correos electrónicos en la carpeta IMAP Spam.
--IMAP-store-spam=carpeta
Almacena los correos electrónicos marcados como spam en la carpeta IMAP especificada.
--IMAP-user-dir dir
Directorio donde se encuentran los archivos de configuración del usuario.
--IMAP-username-format formato
Formato para generar nombres de usuario IMAP a partir de direcciones de correo electrónico.
-l, --listen [=dirección]
Escucha en el socket especificado por dirección. Si no se especifica ninguna dirección, escucha en todos los interfaces de red. Las direcciones pueden ser un nombre de host, una dirección IP o un nombre de servicio/puerto. Por ejemplo, --listen=8080 o --listen=127.0.0.1:7000. Si se especifica un nombre de servicio, se buscará en /etc/services. Si se utiliza la opción --socketpath, esta opción se puede utilizar para añadir sockets adicionales, p. ej., --listen=:` o --listen=*:.
--log-level nivel
Establece el nivel de registro. Los niveles disponibles son: debug, info, notice, warning, error, critical, alert, emergency.
--log-topic tema[,...]
Habilita la generación de registros para los temas especificados. Los temas disponibles incluyen: bayes, dnsbl, rate, rewrite, sync, all.
--max-child-processes número
Número máximo de procesos hijos que spamd puede iniciar. El valor predeterminado es 10.
--max-restarts número
Número máximo de veces que un proceso hijo puede reiniciarse antes de que el proceso principal salga. El valor predeterminado es 5.
--max-servers número
Número máximo de servidores spamd que se pueden ejecutar simultáneamente. El valor predeterminado es 5.
--pidfile archivo_pid
Escribe el ID del proceso del demonio spamd en el archivo especificado. Por defecto, es /var/run/spamd.pid.
--port puerto
Especifica el número de puerto en el que debe escuchar spamd. El valor predeterminado es 783. Ver --ssl para más detalles.
--server-key archivo_clave
Especifica el archivo de clave SSL a utilizar para conexiones SSL.
--server-cert archivo_cert
Especifica el archivo de certificado SSL a utilizar para conexiones SSL.
--socketpath ruta_acceso
Escucha en un socket de dominio UNIX en la ruta ruta_acceso, además de los sockets especificados con la opción "--listen". Esta opción se proporciona para compatibilidad con versiones anteriores de spamd. A partir de la versión 3.4.0, la opción "--listen" también puede tomar un socket de dominio UNIX como su valor (un nombre de ruta absoluto). A diferencia de "--socketpath", la opción "--listen" puede especificarse varias veces si spamd necesita escuchar en varios sockets UNIX o INET o INET6.

Advertencia: El soporte de Perl en plataformas BSD para sockets de dominio UNIX parece tener un error con rutas de más de 100 bytes aproximadamente (bug de SpamAssassin 4380). Si ve un mensaje de error 'no se pudo encontrar el socket UNIX recién creado' y la ruta parece truncada, esta puede ser la causa. Intente usar una ruta más corta al socket.

Por defecto, el uso de --socketpath sin --listen inhibirá las conexiones SSL y las conexiones TCP sin cifrar. Para añadir otros sockets, especifíquelos con --listen, por ejemplo, '--listen=:' o '--listen=*:'

--socketowner nombre
Establece la propiedad del socket de dominio UNIX al usuario llamado nombre. Tenga en cuenta que esto requiere que spamd se inicie como "root", y si se utiliza "-u", ese usuario debe tener permisos de escritura para eliminar el archivo más tarde, cuando el servidor "spamd" se detenga.
--socketgroup nombre
Establece la propiedad del grupo del socket de dominio UNIX al grupo llamado nombre. Ver "--socketowner" para notas sobre la propiedad y los permisos.
--socketmode modo
Establece el modo octal del socket de dominio UNIX a modo. Tenga en cuenta que si se utiliza "-u", ese usuario debe tener permisos de escritura para eliminar el archivo más tarde, cuando el servidor "spamd" se detenga.
--timing
Habilita mediciones de tiempo y muestra la información para el registro. Esta
es la misma información que proporciona la etiqueta TIMING.
