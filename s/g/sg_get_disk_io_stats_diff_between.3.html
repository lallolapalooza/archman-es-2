DESCRIPCIÓN

Las funciones sg_get_disk_io_stats proporcionan estadísticas de E/S de disco por disco. Todas las funciones get y diff toman un parámetro opcional entries, que apunta (cuando se proporciona) a un size_t para obtener el número de entradas del vector devueltas.

Las funciones sg_get_disk_io_stats() y sg_get_disk_io_stats_r() entregan las estadísticas de E/S desde que el disco se conectó al sistema. Las funciones sg_get_disk_io_stats_diff() y sg_get_disk_io_stats_diff_between() entregan la diferencia entre dos llamadas a sg_get_disk_io_stats() o sg_get_disk_io_stats_r(), respectivamente.

Atajo de API

función retorna propietario de datos
sg_get_disk_io_stats sg_disk_io_stats * libstatgrab (local del hilo)
sg_get_disk_io_stats_r sg_disk_io_stats * llamador
sg_get_disk_io_stats_diff sg_disk_io_stats * libstatgrab (local del hilo)
sg_get_disk_io_stats_diff_between sg_disk_io_stats * llamador

Los vectores sg_disk_io_stats obtenidos de sg_get_disk_io_stats_r() o sg_get_disk_io_stats_diff_between() deben liberarse usando sg_free_disk_io_stats() cuando ya no se necesiten. El llamador es responsable de hacerlo.

Adicionalmente, hay dos funciones de soporte para qsort(3) disponibles: sg_disk_io_compare_name() y sg_disk_io_compare_traffic().

Ejemplo

size_t entries;
sg_disk_io_stats *io_stats = NULL;
while( NULL != ( io_stats = sg_get_disk_io_stats_diff(&entries) ) ) {
    /* mostrar discos con más tráfico primero */
    qsort( io_stats, entries, sizeof(io_stats[0]), &sg_disk_io_compare_traffic );
    show_disk_io_stats( io_stats );
}

En algunas plataformas, como Solaris 7, el valor del kernel se almacena en un int de 32 bits, por lo que se desborda cuando alcanza los 4 GB. Otras plataformas, como Solaris 8 (y la mayoría de los sistemas modernos), mantienen el valor en un int de 64 bits, que se desborda cerca de los 17 millones de terabytes. Las funciones sg_get_disk_io_stats_diff() y sg_get_disk_io_stats_diff_between() se ocupan de estos desbordamientos e intentan detectarlos al calcular la diferencia.

En Solaris, libstatgrab intentará obtener la representación cXtXdXsX para la cadena disk_name. Si falla, usará un nombre como sd0. En algunos sistemas, los programas que llaman a libstatgrab necesitarán privilegios elevados para buscar algunos de los nombres. Los mapeos se crean cuando se llama a sg_init() por primera vez.

VALORES DE RETORNO

Todas las estadísticas de disco_io devuelven un puntero a una estructura de tipo sg_disk_io_stats.

typedef struct {
        char *disk_name;
        unsigned long long read_bytes;
        unsigned long long write_bytes;
        time_t systime;
} sg_disk_io_stats;
disk_name
El nombre conocido por el sistema operativo. (ej. en linux podría ser hda)
read_bytes
El número de bytes que el disco ha leído.
write_bytes
El número de bytes que el disco ha escrito.
systime
El período de tiempo durante el cual se transfirieron read_bytes y write_bytes.

ERRORES

sg_get_disk_io_stats_diff y sg_get_disk_io_stats_diff_between comparan dos listas de estadísticas de E/S relacionadas con discos (dispositivos de bloque). Cada entrada que ocurre solo en la segunda lista se pasa a la lista resultante como si se hubiera comparado con una entrada con todos los valores estadísticos establecidos en 0. Esto implica que, en la primera llamada, sg_get_disk_io_stats_diff devolverá lo mismo que sg_get_disk_io_stats.

En sistemas operativos que solo tienen 32 bits de datos, existe un problema si los valores se desbordan dos veces. Por ejemplo, en Solaris 7 si se transfieren 9 GB y el sistema operativo se desborda a 4 GB, la función sg_get_disk_io_stats_diff() devolverá 5 GB.

Las funciones de comparación existen más por compatibilidad retroactiva que por mejoras de funcionalidad. La flexibilidad limitada (por ejemplo, orden inverso) y la falta de oportunidades de optimización para el compilador llevan a la recomendación de implementar las rutinas de comparación requeridas localmente.
