NOMBRE

sg_logs - accede a páginas de registro con el comando SCSI LOG SENSE

SINOPSIS

sg_logs [--ALL] [--all] [--brief] [--exclude] [--filter=FL] [--full] [--hex] [--json[=JO]] [--js-file=JFN] [--list] [--maxlen=LEN] [--name] [--no_inq] [--page=PG] [--paramp=PP] [--pcb] [--ppc] [--pdt=DT] [--raw] [--readonly] [--sp] [--temperature] [--transport] [--undefined] [--vendor=VP] [--verbose] DISPOSITIVO

sg_logs --inhex=FN [--ALL] [--all] [--brief] [--exclude] [--filter=FL] [--full] [--hex] [--json[=JO]] [--js-file=JFN] [--list] [--name] [--page=PG] [--pdt=DT] [--raw] [--undefined] [--vendor=VP]

sg_logs --select [--control=PC] [--page=PG] [--raw] [--reset] [--sp] [--verbose] DISPOSITIVO

sg_logs --enumerate [--filter=FL] [--help] [--vendor=VP] [--version]

sg_logs [-a] [-A] [-b] [-c=PC] [-D=DT] [-e] [-E] [-f=FL] [-F] [-h] [-H] [-i=FN] [-l] [-L] [-m=LEN] [-M=VP] [-n] [-p=PG] [-paramp=PP] [-pcb] [-ppc] [-r] [-R] [-select] [-sp] [-t] [-T] [-u] [-v] [-V] [-?] [-x] DISPOSITIVO

DESCRIPCIÓN

Esta utilidad envía un comando SCSI LOG SENSE al DISPOSITIVO y luego muestra la respuesta. El comando LOG SENSE se utiliza para obtener páginas de registro que, si se conocen, se decodifican por defecto. Cuando se proporciona la opción --reset y/o --select, se emite un comando SCSI LOG SELECT al DISPOSITIVO. Alternativamente, una o más respuestas de páginas de registro pueden estar en un archivo leído usando la opción --inhex=FN; en este caso, esas respuestas se decodifican y se ignora el argumento DISPOSITIVO, si se proporciona.

En la revisión 5 de SPC-4, se introdujo el código de subpágina tanto en el comando LOG SENSE como en el LOG SELECT. Al mismo tiempo, se introdujo un campo de código de página en el comando LOG SELECT. El código de subpágina de registro puede variar de 0 a 255 (0xff) inclusive. El valor 255 del código de subpágina puede considerarse como un comodín.

La sección SINOPSIS anterior se divide en cinco formas. La primera forma muestra las opciones que se pueden usar para enviar un comando LOG SENSE al DISPOSITIVO y decodificar su respuesta. La segunda forma obtiene datos de un archivo (llamado FN) y los decodifica como si fueran una respuesta de un comando LOG SENSE. La tercera forma muestra las opciones que se pueden usar para enviar un comando LOG SELECT. La cuarta forma agrupa varias opciones de gestión. La última forma muestra la interfaz de línea de comandos antigua y obsoleta, que se mantiene por compatibilidad con versiones anteriores.

Cuando no se proporcionan opciones, solo un DISPOSITIVO, es equivalente a llamar a esta utilidad con la opción --list. En ese caso, se enumeran los nombres de las páginas de registro compatibles (pero no las subpáginas).

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas. Las opciones están ordenadas alfabéticamente según el nombre de la opción larga.

-A, --ALL
obtiene y decodifica todas las páginas y subpáginas de registro compatibles con el DISPOSITIVO. Esto requiere un proceso de dos etapas: primero se obtiene la página de registro "páginas y subpáginas de registro compatibles", luego, para cada entrada en su respuesta, se obtiene y se muestra la página (o subpágina) de registro correspondiente. Tenga en cuenta que hay muchos dispositivos SCSI que no admiten subpáginas LOG SENSE y responden a esta opción con una clave de sense de solicitud ilegal. En este caso, esta utilidad continúa obteniendo la página de registro "páginas de registro compatibles" en su lugar. En otras palabras, si la opción --ALL falla, se usa --all en su lugar. La razón es que casi con certeza el DISPOSITIVO no tiene subpáginas de registro para informar.
Para forzar un error si la obtención de la página de registro "páginas y subpáginas de registro compatibles" falla, use las opciones --ALL y --full juntas.
Dado que algunos proveedores no enumeran todas las páginas de registro en la página "páginas y subpáginas de registro compatibles", la opción '-lll' puede darse adicionalmente. Esto fusionará ambas páginas de registro "compatibles ...", luego, a partir de esa lista combinada resultante, obtendrá el contenido de la página.
Esta opción anula --page=PG si esta última también se proporciona.
-a, --all
muestra todas las páginas de registro compatibles con el DISPOSITIVO. Esto requiere un proceso de dos etapas: primero se obtiene la página de registro "páginas de registro compatibles", luego, para cada entrada en su respuesta, se obtiene y se muestra la página de registro correspondiente. Cuando se usa dos veces (por ejemplo, '-aa'), se obtienen todas las páginas y subpáginas de registro.
Esta opción anula --page=PG si esta última también se proporciona.
-b, --brief
acorta la cantidad de salida para algunas páginas de registro. Por ejemplo, la página de registro Tape Alert solo muestra los parámetros cuyas banderas están activadas cuando se proporciona --brief.
-c, --control=PC
acepta 0, 1, 2 o 3 para el argumento PC:
0 : valores de umbral actuales
1 : valores acumulativos actuales
2 : valores de umbral predeterminados
3 : valores acumulativos predeterminados
El valor predeterminado es 1 (es decir, valores acumulativos actuales).
-e, --enumerate
esta opción se utiliza para mostrar información contenida en las tablas internas de esta utilidad sobre las páginas de registro conocidas, incluido su nombre, acrónimo y campos. Si se proporciona, el argumento DISPOSITIVO se ignora. Cuando se proporciona una vez (por ejemplo, '-e'), se enumeran todas las páginas conocidas, ordenadas alfabéticamente por acrónimo ascendente.
Cuando se proporciona dos veces, se excluyen las páginas de proveedor. Cuando se proporciona tres veces, se enumeran todas las páginas conocidas, ordenadas numéricamente en orden ascendente; cuando se proporciona cuatro veces, se excluyen las páginas de proveedor del orden numérico.
Las opciones --filter=FL y --verbose reducen la salida de la enumeración.
-E, --exclude
esta opción excluye las páginas y parámetros específicos del proveedor de la salida. Intentar decodificar páginas y parámetros específicos del proveedor no siempre funciona bien por varias razones. Esta opción limita la salida a páginas y parámetros definidos por T10.
Solo se excluyen los campos de parámetros identificados en los borradores como 'específicos del proveedor'. Por lo tanto, se muestran los códigos de parámetros identificados como 'reservados'.
-f, --filter=FL
FL es un código de parámetro cuando se proporciona DISPOSITIVO, o un tipo de dispositivo periférico (pdt) (u otro) si se proporciona --enumerate.
En el caso del código de parámetro, FL es un valor entre 0 y 65535 (0xffff) y solo se muestra la sección de parámetro que coincide con ese código. Si se proporciona la opción --hex, el parámetro de registro se muestra en hexadecimal en lugar de decodificarse. Si la opción --hex se usa dos veces, se elimina la dirección inicial en cada línea hexadecimal. Si se proporciona la opción --raw, el parámetro de registro se muestra en binario. La mayoría de las páginas de registro contienen uno o más parámetros de registro. Ejemplos de aquellas que no siguen esta convención son aquellas páginas que enumeran las páginas (y subpáginas) de registro compatibles.
En el caso de --enumerate, cuando FL >= cero, se toma como un valor pdt y solo se enumeran las páginas de registro asociadas con ese pdt más las páginas genéricas enumeradas en SPC. Si FL es -1, el filtro no hace nada, lo que es lo mismo que no proporcionar esta opción; cuando FL es -2, solo se enumeran las páginas genéricas listadas en SPC. Si FL es -10, solo se enumeran las páginas genéricas de acceso directo (por ejemplo, disco). Si FL es -11, solo se enumeran las páginas genéricas tipo cinta (por ejemplo, incluye ADC).
-F, --full
esta opción solo se usa en dos situaciones: con la página de registro del cliente de aplicación (AC) y con la opción --ALL. Típicamente, la página de registro AC tiene más de 16.000 bytes de datos proporcionados por el usuario. -h, --help
imprime el mensaje de uso y luego sale.
-H, --hex
La acción predeterminada es decodificar números de página de registro conocidos (y números de subpágina) a texto. Cuando se usa esta opción una vez, la respuesta se muestra en hexadecimal. Cuando se usa dos veces, cada línea hexadecimal muestra su equivalente ASCII a la derecha. Cuando se usa tres veces, el hexadecimal no tiene dirección inicial ni ASCII final, lo que lo hace adecuado para ser colocado en un archivo (o canalizado). Ese archivo podría ser utilizado más tarde por otra invocación usando la opción --inhex=FN.
Una forma más débil de esta opción, llamada --undefined, maneja el formato de salida hexadecimal para campos que esta utilidad no puede decodificar.
-i, --in=FN
Igual que la opción --inhex=FN. Se mantiene por compatibilidad con versiones anteriores.
-i, --inhex=FN
Esta opción se puede usar en dos contextos diferentes. Uno es con --select para enviar un comando LOG SELECT al DEVICE dado; consulte la sección LOG SELECT a continuación.
El otro contexto es cuando no se proporciona un argumento DEVICE, en cuyo caso el contenido de FN se decodifica como si fuera la respuesta de un comando LOG SENSE (es decir, una o más páginas de registro). Para la decodificación, los números de página y subpágina se toman de FN, mientras que el tipo de dispositivo periférico es genérico (es decir, de SPC) o el valor dado por --pdt=DT.
FN se trata como un nombre de archivo (o '-' para stdin) que contiene hexadecimal o binario ASCII que representa una página de registro. El hexadecimal debe organizarse como 1 o 2 dígitos que representan un byte cada uno, separados por espacios en blanco o comas. Se ignora todo desde un signo de almohadilla hasta el final de la línea. Si la opción --raw también se da, entonces FN se trata como binario.
-j[=JO], --json[=JO]
la salida está en formato JSON en lugar de texto plano. Tenga en cuenta que los argumentos para la forma corta y larga son opcionales y, si están presentes, comienzan con "=" y no se permiten espacios alrededor de ese "=".
Consulte la página del manual sg3_utils_json o use '?' para JO para obtener un resumen.
-J, --js-file=JFN
la salida está en formato JSON y se envía a un archivo llamado JFN. Si ese archivo existe, se trunca. De forma predeterminada, la salida JSON se envía a stdout.
Cuando se da esta opción, la opción --json[=JO] se implica y no es necesario proporcionarla. La opción --json[=JO] aún puede ser necesaria para establecer el parámetro JO a valores no predeterminados.
-l, --list
enumera los nombres de las páginas de registro que admite este dispositivo. Esto se hace leyendo la página de registro "supported log pages". Cuando se usa una vez, solo se enumeran las páginas de registro, no las subpáginas. Cuando se usa dos veces, se muestra la página de registro "supported log pages and subpages". Algunos proveedores no enumeran algunas páginas de registro (por ejemplo, aquellas sin subpáginas) en la página de registro "supported log pages and subpages". Para obtener un inventario completo, esta opción se puede usar tres veces (por ejemplo, '-lll') y la salida de las dos páginas de registro se fusiona. Incluso si la página de registro "supported log pages and subpages" no es compatible, usar esta opción tres veces generará una lista de la página de registro "supported log pages". En ausencia de otras opciones, los nombres de página/subpágina, pero no sus contenidos, se muestran cuando se da esta opción.
La forma '-lll' puede ser útil con la opción --ALL para mostrar el contenido de todas las páginas a las que se hace referencia en la página de registro "supported log page" o "supported log page and subpage".
-m, --maxlen=LEN
establece el campo "allocation length" en el CDB LOG SENSE. Esta es la longitud máxima en bytes que tendrá la respuesta. Sin esta opción (o LEN igual a 0), esta utilidad primero obtiene la respuesta de 4 bytes y luego realiza un segundo acceso con la longitud indicada en la primera respuesta (de 4 bytes). No se aceptan valores negativos ni 1 para LEN. Las respuestas pueden ser bastante grandes (por ejemplo, la página de registro de resultados de escaneo en segundo plano) y esta opción se puede usar para limitar la cantidad de información devuelta.
El valor predeterminado de LEN es 65532, a menos que se proporcione la opción --in=FN; en ese caso, el valor predeterminado es 262144.
-n, --name
decodifica algunas páginas de registro en entradas 'nombre=valor', una por línea. El nombre no contiene espacios y puede abreviarse, y el valor es decimal a menos que esté precedido por '0x'. La anidación se indica con espacios iniciales. Esta forma está pensada para ser relativamente fácil de analizar.
Esta opción se ve superada por la opción --json[=JO]. Si se proporcionan ambas, esta opción se ignora.
-x, --no_inq
suprime la salida de información obtenida de una llamada inicial al comando INQUIRY para la respuesta estándar. La opción predeterminada (suponiendo que otras opciones que suprimen esta salida tampoco se dan) es mostrar varias cadenas de identificación del dispositivo.
Si se proporciona esta opción dos veces (o más), no se envía ningún comando INQUIRY, por lo tanto, tampoco se mostrará ninguna cadena de identificación del dispositivo. Además, no se obtendrá el campo de tipo de dispositivo periférico (PDT), por lo que esta utilidad no podrá diferenciar entre algunas páginas de registro que dependen del dispositivo. La utilidad asumirá un PDT de 0 (es decir, un disco) a menos que se proporcione la opción --pdt=DT.
-O, --old
Cambia a opciones de estilo antiguo. Por favor, úsela como primera opción.
-p, --page=PG
nombre/número de página de registro a acceder. PG es un acrónimo, un número de página o un par de número de página, número de subpágina. Los acrónimos disponibles se pueden enumerar con la opción --enumerate. Los números de página (de 0 a 63) y subpágina (de 0 a 255) se separan por comas. Son decimales a menos que se indique una indicación hexadecimal. Un número hexadecimal se puede especificar con un prefijo "0x" o un sufijo "h".
Algunos acrónimos especifican un rango de valores de subpágina, en cuyo caso el acrónimo puede ir seguido de una coma y luego un número de subpágina. Este método también se puede utilizar para obtener la página de registro "Supported subpages" (por ejemplo, --page=temp,0xff).
-P, --paramp=PP
PP es el valor del puntero de parámetro a colocar en un campo de ese nombre en el CDB LOG SENSE. Se espera un número en el rango de 0 a 65535 (0x0 a 0xffff). Cuando se proporciona un valor mayor que 0, se debe seleccionar la opción --ppc. El valor predeterminado es 0.
Para páginas de registro que tienen códigos de parámetro, el DEVICE debe devolver solo parámetros con un código igual o superior a PP en su respuesta.
-q, --pcb
muestra la configuración del Byte de Control de Parámetros (solo relevante cuando los parámetros de registro se muestran en ASCII). Este byte incluye los bits DU y TSD más el campo "Format and linking" (de 2 bits de ancho).
-D, --pdt=DT
DT es el tipo de dispositivo periférico (PDT) que se utiliza cuando no está disponible desde el DEVICE. Hay varios casos: cuando no se proporciona el DEVICE (por ejemplo, cuando se proporciona la opción --inhex=FN o --enumerate) y cuando se proporciona DEVICE y se combina con la opción --no_inq. Eso detiene que esta utilidad envíe el comando SCSI INQUIRY, que es donde esta utilidad generalmente encuentra las páginas de registro asociadas al PDT que se están decodificando.
Se pueden usar valores numéricos entre -1 y 31 (inclusive), donde -1 implica lo que está en SPC. Los Comandos Primarios SCSI (SPC) son comunes a todos los dispositivos SCSI. También se pueden dar nombres como 'tape', 'disk' y 'processor' para DT. El valor predeterminado es 0 o 'disk' para SBC (y el acrónimo estándar asociado también se puede dar, que en este caso es 'sbc').
-Q, --ppc
establece el bit Parameter Pointer Control (PPC) en el CDB LOG SENSE. El valor predeterminado es 0 (es decir, borrado). Este bit se volvió obsoleto en la revisión 18 de SPC-4.
-r, --raw
muestra la respuesta en binario a stdout. Los mensajes de error y las advertencias se muestran en stderr.
Esta opción también se puede proporcionar junto con --in=FN, en cuyo caso el contenido de FN se interpreta como datos binarios (y la respuesta se decodifica normalmente, no se vuelca como binario).
-R, --readonly
abre el DEVICE en modo de solo lectura (por ejemplo, en Unix con el flag O_RDONLY). La acción predeterminada es intentar abrir DEVICE en modo lectura-escritura y luego, si falla, intentar abrir de nuevo en modo de solo lectura. Sin embargo, cuando se abre correctamente en modo lectura-escritura, puede haber acciones no deseadas al cerrar (por ejemplo, algunos sistemas operativos intentan ejecutar un comando SYNCHRONIZE CACHE). Por lo tanto, esta opción fuerza una apertura de solo lectura en DEVICE y, si falla, esta utilidad saldrá. Tenga en cuenta que opciones como --select probablemente necesiten una apertura en modo lectura-escritura.
-R, --reset
usa el comando SCSI LOG SELECT (con el bit PCR establecido) para restablecer todas las páginas de registro (o la página dada). Exactamente qué se restablece depende del bit SP (es decir, la opción --sp que por defecto es 0) y el valor de PC ("page control") (que por defecto es 1). Proporcionar esta opción implica también la opción --select. Esta opción parece borrar las páginas de registro de contadores de errores, pero deja sin afectar páginas como los resultados de autocomprobación, el contador de ciclos de inicio-parada y las páginas de registro de temperatura. Esta opción puede ser necesaria para borrar páginas de registro si un contador alcanza su valor máximo, ya que la página de registro en la que se encuentra el contador permanecerá "atascada" en su valor máximo hasta que haya alguna interacción del usuario (por ejemplo, llamar a sg_logs con esta opción).
-S, --select
usa un comando LOG SELECT. La acción predeterminada (es decir, cuando ni esta opción ni --reset se dan) es realizar un comando LOG SENSE. Consulte la sección LOG SELECT.

OPTIONS

-a, --all
outputs all the log pages supported by the DEVICE. This is done by looping through the "Supported log pages" log page (page 0x0). If the "log page length" field in the response is zero, it means that the device does not report on its supported log pages, so in that case this option is ignored.
-A, --ALL
outputs all the log pages and subpages supported by the DEVICE. This is done by looping through the "Supported log pages and subpages" log page (page 0x0, subpage 0xff). If the "log page length" field in the response is zero, it means that the device does not report on its supported log pages and subpages, so in that case this option is ignored.
-c, --control=PC
Set the Parameter Control (PC) field in the cdb. PC is a decimal integer in the range 0 to 7. Default is 0.
-e, --enumerate
enumerate internal tables to show information about known log pages. This lists the page codes and names recognized by this utility. When used with --verbose the number of bytes for each parameter is also shown.
-E, --exclude=PG
exclude log page PG (and its subpages). PG can be a hexadecimal number (e.g. 0x1) or a name (e.g. "error"). This option can be used multiple times. This option can only be used when the --all or --ALL option is also used. See the --page option for more details on specifying PG.
-h, --hex
output the response in hex. This is the default action when the utility cannot decode a given log page or parameter. It can also be used to force hex output even when decoding is possible.
-H, --inhex=FN
read response data from file name FN instead of the block device. This is useful for replaying saved responses. The file FN is expected to contain ASCII hexadecimal data. Alternatively FN can be '-' which means read from standard input. See the INHEX INSTEAD OF DEVICE section for more details.
-i, --in=FN
read parameter data from file name FN and place it in the data-out buffer of a LOG SELECT command. If FN is '-' then read from standard input. See the LOG SELECT section.
-l, --list
list the names of all log pages supported by this DEVICE. This is done by reading the "Supported log pages" log page (page 0x0). If the "log page length" field in the response is zero, it means that the device does not report on its supported log pages, so in that case this option is ignored.
-L, --list, --list
list the names of all log pages and subpages supported by this DEVICE. This is done by reading the "Supported log pages and subpages" log page (page 0x0, subpage 0xff). If the "log page length" field in the response is zero, it means that the device does not report on its supported log pages and subpages, so in that case this option is ignored.
-m, --maxlen=LEN
request only LEN bytes of response data. Default is 0 which is interpreted as all that is available. LEN is decimal unless it has a leading '0x' or trailing 'h'.
-n, --name
output in a name=value format. This is useful for scripting.
-O, --old
use older command line options (prior to sg3_utils version 1.23). Use with caution.
-p, --page=PG
select log page PG. PG can be a hexadecimal number (e.g. 0x1) or a name (e.g. "error"). Names are case insensitive. If a subpage is required then use a comma separated list, e.g. '--page=0,1' or '--page=error,0'. The default is page 0 (Supported log pages). A list of known log pages can be obtained with the --enumerate option.
-P, --pdt=DT
Set the Physical Device Type (PDT) field in the cdb. DT is a decimal integer in the range 0 to 127. Default is 0.
-r, --raw
output the response in hex, without any attempt to decode it. This is equivalent to --hex.
-R, --reset
Set the Reset (R) bit in the cdb. This is only relevant when the LOG SELECT command is used. This option causes the selected log page parameters to be reset to vendor specific defaults.
-s, --select
issue a LOG SELECT command instead of a LOG SENSE command. This is the default action when the --in=FN option is used. Can be combined with --reset or --sp.
-S, --sp
Set the Save Parameters (SP) bit in the cdb. This is only relevant when the LOG SELECT command is used. This option causes the current log page parameters (as indicated by the DS and TSD parameter codes) in some non-volatile location. Hence the log parameters will be preserved across power cycles. This option is typically not needed, especially if the GLTSD flag is clear in the control mode page which causes the DEVICE to periodically save all saveable log parameters to non-volatile storage.
-t, --temperature
outputs the temperature. First looks in the temperature log page and if that is not available tries the Informational Exceptions log page which may also have the current temperature (especially on older disks).
-T, --transport
outputs the transport ('Protocol specific port') log page. Equivalent to setting '--page=18h'.
-u, --undefined
to see fields decoded, the --hex option cannot be used. However some fields are not defined in the T10 documents and in that case they are output in hex. This option controls the format of 'undefined' fields when they output in hex. Multiple uses of this option has the same sense as the --hex option. For example '-uu' will output undefined fields in hexadecimal with an ASCII rendering to the right of each line.
-M, --vendor=VP
where VP is a vendor/manufacturer (e.g. "sea" for Seagate) or product (group) acronym (e.g. "lto5" for the 5th generation LTO (tape) consortium). Either the whole log page is vendor specific (e.g. page numbers 0x30 to 0x3f) or part of a T10 defined log page is vendor specific. For example SPC-5 defines parameter code 0x0 of page 0x2f (the Informational Exceptions log page) and states that the remaining parameter codes (i.e. 0x1 to 0xffff) are vendor specific. Using a VP of "xxx" will list the available acronyms.
If this option is used with --page=PG and PG is an acronym then this option is ignored. If PG is a number (e.g. 0xc0) then VP is used to choose the which vendor specific page (e.g. sharing page number 0xc0) to decode.
-v, --verbose
increase level of verbosity. When used with --enumerate, in the list of known log page names, those that have no associated decode logic are followed by "[hex only]".
-V, --version
print out version string then exit.

LOG SELECT

The SCSI LOG SELECT command can be used to reset certain parameters to vendor specific defaults, save them to non-volatile storage (i.e. the media), or supply new page contents. This command has changed between SPC-3 and SPC-4 with the addition of the Page and Subpage Code fields which can only be non zero when the Parameter list length is zero.

The --select (or --reset) option is required to issue a LOG SELECT command. If the --in=FN option is not given (or FN is effectively empty) then the Parameter list length field is set to zero. If the --in=FN option is is given then its decoded data is placed in the data-out buffer and its length in bytes is placed in the Parameter list length field.

Other options that are active with the LOG SELECT command are --control=PC, --reset (which sets the PCR bit) and --sp.

APPLICATION CLIENT

This is the name of a log page that acts as a container for data provided by the user. An application client is a SCSI term for the program that issues commands to a SCSI initiator (often known as a Host Bus Adapter (HBA)). So, for example, this utility is a SCSI application client.

The Application Client log page has 64 log parameters with parameters codes 0 to 63. Each can hold 252 bytes of user binary data. That 252 bytes (or less) of user data, with a 4 byte prefix (for a total of 256 bytes) can be provided with the --in=FN option. A typical prefix would be '0,n,83,fc'. The "n" is the parameter code in hex so the last log parameter would be '0,3f,83,fc'. That log parameter could be read back at some later time with '--page=0xf --filter=0x<n>'.

INHEX INSTEAD OF DEVICE

This section applies when the --inhex=FN option is used and there is no DEVICE argument. This can be viewed as a replay facility where the FN file was created by a prior invocation of this utility, most likely with the '-HHHHH' option, with command line output redirection used to create FN.

If the --all option is given once then all pages (but not subpages) found in FN will be decoded, or output in hex if this utility is unable to decode some of them. If the --all option is given two or more times then all pages and subpages found in FN will be decoded. In both cases pages are decoded in the order they are found in FN.

Next, if the --page=PG] option is given, then FN is searched for a match on PG and, if found, that log (sub)page is decoded. If the --list option is given once, then the Supported log pages log page [0x0,0x0] is decoded, if present. If the --list option is given two or more times, then the Supported Log Pages and Subpages log page [0x0,0xff] is decoded, if present.

If none of the above selection options are given, then this utility will attempt to decode the first log page found in FN. If there are more log pages following the first one in FN then they are ignored.

NOTES

This utility will usually do a double fetch of log pages with the SCSI LOG SENSE command. The first fetch requests a 4 byte response (i.e. place 4 in the "allocation length" field in the cdb). From that response it can calculate the actual length of the response which is what it asks for on the second fetch. This is typical practice in SCSI and guaranteed to work in the standards. However some older devices don't comply. For those devices using the --maxlen=LEN option will do a single fetch. A value of 252 should be a safe starting point.

Various log pages hold information error rates, device temperature, start stop cycles since the device was produced and the results of the last 20 self tests. Self tests can be initiated by the sg_senddiag(8) utility. The smartmontools package provides much of the information found with sg_logs in a form suitable for monitoring the health of SCSI disks and tape drives.

The simplest way to find which log pages can be decoded by this utility is to use the --enumerate option. Some page names are known but there is no decode logic; such cases have "[hex only]" after the log page name when the --verbose option is given with --enumerate.

Vendors are specifically permitted by the SPC-6 to _not_ report all pages and subpages supported by a device. That weakens the usefulness of the pages that report a list of supported pages and subpages. One guarantee which is given is that the pages reported shall be in ascending order.

EXIT STATUS

The exit status of sg_logs is 0 when it is successful. Otherwise see the sg3_utils(8) man page.

sg_logs(8)

NAME

sg_logs

fetch SCSI log pages

SYNOPSIS

sg_logs [OPTIONS] <device>

DESCRIPTION

This utility fetches and displays SCSI log pages from a given SCSI device (e.g., disk, tape drive).

A SCSI device can have up to 256 log pages, numbered 0 to 0xff. By default, this utility attempts to fetch and display all log pages that are implemented by the device. If the device responds with an ILLEGAL REQUEST sense key and ASC/ASCQ indicating an invalid page, that page is skipped.

Log pages can be fetched and displayed in either binary or hexadecimal format. Log pages are grouped into page codes. Each page code can contain subpages.

The output is typically presented in hexadecimal and ASCII.

APPLICATION CLIENT

The -c option attempts to interpret and display the data as a SCSI transport 'application client' log page. This log page is defined in the SCSI SBC-3 specification and is used to report information about the application client software interacting with the storage device.

INHEX INSTEAD OF DEVICE

You can specify a hexadecimal number (0x...) instead of a device name. This is useful if you want to use the tool without root privileges, as it will access the device via the sg driver's interface using the provided file descriptor number.

NOTES

Log pages are typically used for device-specific diagnostic information. The format and content of log pages vary widely between different types of SCSI devices.

The --enumerate and --list options are useful for discovering which log pages are supported by a device. The output of --enumerate provides short descriptions of the log pages, which can help in understanding their purpose.

The --reset option should be used with caution, as it can affect the operational state of the device.

EXIT STATUS

Exits with 0 on success, or a non-zero value on failure.
