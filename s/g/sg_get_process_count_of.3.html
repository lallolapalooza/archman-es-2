DESCRIPCIÓN

Las funciones sg_get_process_stats proporcionan estadísticas sobre los procesos en ejecución actualmente. Ambas funciones, sg_get_process_stats() y sg_get_process_stats_r(), toman un parámetro opcional de entradas, que apunta (cuando se proporciona) a un size_t para obtener el número de entradas del vector devueltas.

Las funciones sg_get_process_count_of() y sg_get_process_count_r() proporcionan una vista agregada de la tabla de procesos: entregan la cantidad de procesos por estado de proceso. sg_get_process_count() es en realidad una macro preprocesador para compatibilidad con versiones anteriores y llama a sg_get_process_count_of() con el parámetro pcs de sg_entire_process_count para emular el comportamiento hasta la versión 0.17.

Atajo de API

función retorna propietario de los datos
sg_get_process_stats sg_process_stats * libstatgrab (local del hilo)
sg_get_process_stats_r sg_process_stats * llamador
sg_get_process_count_of sg_process_count * libstatgrab (local del hilo)
sg_get_process_count_r sg_process_count * llamador

Los vectores sg_process_stats recibidos de sg_get_process_stats_r() o los resúmenes sg_process_count recibidos de sg_get_process_count_r deben liberarse utilizando sg_free_process_stats() o sg_free_process_count(), respectivamente. El llamador es responsable de hacerlo cuando los datos ya no son necesarios.

Estas funciones comparan dos entradas sg_process_stats y devuelven un int para representar cuál es mayor. El uso principal de estas funciones es ser pasadas a qsort para ordenar sg_process_stats por el tipo dado.

Ejemplo

size_t entries;
sg_process_stats *proc_stats = NULL;
while( NULL != ( proc_stats = sg_get_process_stats_r(&entries) ) ) {
    /* ordenar entradas comparando el identificador del proceso */
    qsort( proc_stats, entries, sizeof(proc_stats[0]), &sg_process_compare_pid );
    show_proc_stats( proc_stats );
    sg_free_process_stats( proc_stats );
}

VALORES DE RETORNO

La estructura devuelta por sg_get_process_stats es de tipo sg_process_stats.

typedef struct {
        char *process_name;
        char *proctitle;
        pid_t pid;    /* identificador del proceso */
        pid_t parent; /* pid del padre */
        pid_t pgid;   /* id del proceso líder del grupo de procesos */
        pid_t sessid; /* id de sesión del proceso al que pertenece */
        uid_t uid;
        uid_t euid;
        gid_t gid;
        gid_t egid;
        unsigned long long context_switches;
        unsigned long long voluntary_context_switches;
        unsigned long long involuntary_context_switches;
        unsigned long long proc_size; /* en bytes */
        unsigned long long proc_resident; /* en bytes */
        time_t start_time; /* Cuándo se inició el proceso */
        time_t time_spent; /* tiempo de ejecución en segundos */
        double cpu_percent;
        int nice;
        sg_process_state state;
        time_t systime;
} sg_process_stats;

typedef enum {
        SG_PROCESS_STATE_RUNNING,
        SG_PROCESS_STATE_SLEEPING,
        SG_PROCESS_STATE_STOPPED,
        SG_PROCESS_STATE_ZOMBIE,
        SG_PROCESS_STATE_UNKNOWN
} sg_process_state;
process_name
El nombre del comando que se ejecutó. El contenido de este campo depende en gran medida del sistema operativo subyacente, algunos almacenan el nombre base que el ejecutable pasa a la llamada del sistema exec(2), otros la ruta completa. La mayoría de los sistemas operativos restringen el tamaño de este campo, algunos como la familia *BSD a un valor muy bajo de 15 bytes.

Este campo suele ser inmutable para los procesos del espacio de usuario.

proctitle
La línea de comandos (el "título") del proceso. Ten en cuenta que esto puede ser modificado por el proceso, por lo que no se garantiza que sea la línea de comandos original.
pid
El ID del proceso.
parent
El ID del proceso padre.
pgid
El ID del proceso líder del grupo de procesos.
sessid
ID de sesión del proceso al que pertenece.
uid
El ID del usuario con el que se está ejecutando el proceso.
euid
El ID del usuario efectivo con el que se está ejecutando el proceso.
gid
El ID del grupo con el que se está ejecutando el proceso.
egid
El ID del grupo efectivo con el que se está ejecutando el proceso.
context_switches
El número de cambios de contexto de este proceso (voluntarios e involuntarios).
voluntary_context_switches
El número de cambios de contexto voluntarios de este proceso (por ejemplo, al llamar a sched_yield() o sleep()).
involuntary_context_switches
El número de cambios de contexto involuntarios de este proceso (por ejemplo, tiempo de ejecución agotado o recepción de una señal).
proc_size
El tamaño de memoria virtual del proceso en bytes.

NAME

sg_get_process_count_of, sg_get_process_count_r - obtener el recuento de procesos del sistema

SYNOPSIS

#include <statgrab.h>
sg_process_count_t *
sg_get_process_count_of(sg_process_count_source_t source);
sg_process_count_t *
sg_get_process_count_r(sg_process_count_source_t source,
    sg_error_t *error);
int
sg_process_count_compare(const void *data1, const void *data2);
int
sg_process_count_compare_reversed(const void *data1, const void *data2);

DESCRIPTION

The sg_get_process_count_of() function shall return a pointer to a sg_process_count structure which contains the current number of processes on the system. The source argument determines whether the statistic should be collected from the begining of the system runtime or only the last collected sample.

The sg_get_process_count_r() function shall be equivalent to sg_get_process_count_of(), but it returns the pointer to the structure through the error argument.

The functions sg_process_count_compare() and sg_process_count_compare_reversed() are provided for compatibility reasons. They compare the elements of two sg_process_count structures, based on the total number of processes.

The structure returned by sg_get_process_count_of and sg_get_process_count_r is of type sg_process_count.

typedef enum sg_process_count_source {
        sg_entire_process_count,
        sg_last_process_count
} sg_process_count_source_t;

typedef struct{
        unsigned long long total;
        unsigned long long running;
        unsigned long long sleeping;
        unsigned long long stopped;
        unsigned long long zombie;
        unsigned long long unknown;
        time_t systime;
}sg_process_count_t;
total
The total number of processes.
running
The number of running processes.
sleeping
The number of sleeping processes.
stopped
The number of stopped processes.
zombie
The number of zombie processes.
unknown
The number of processes not matching any of above named categories.
systime
The time in seconds since epoch of the moment where the present statistic has been created.

A pointer to a sg_process structure is returned by sg_get_process_list(), sg_get_process_list_r(), sg_get_process_list_with_detail() and sg_get_process_list_with_detail_r().

        pid_t pid;
        char *name;
        char *exe;
        char *cmdline;
        char *cwd;
        uid_t uid;
        gid_t gid;
        unsigned long long size;
        unsigned long long proc_resident;
        time_t start_time;
        time_t time_spent;
        float cpu_percent;
        int nice;
        sg_process_state_t state;
        time_t systime;

pid
The process ID of the process.
name
The name of the process.
exe
The path name of the executable.
cmdline
The command line of the process.
cwd
The current working directory of the process.
uid
The user ID of the process.
gid
The group ID of the process.
size
The size of the process in memory.
proc_resident
The size of the process that's resident in memory.
start_time
The time when the process has been started in seconds since epoch.
time_spent
The number of seconds the process has been running (user+system time, without time spent by child processes).
cpu_percent
The current percentage of CPU the process is using.
nice
The nice value of the process.
state
The current state of the process. See sg_process_state for permitted values.
systime
The time in seconds since epoch of the moment where the present statistic has been created. This might be (but doesn't have to be) the same moment for all returned entries, regardless whether they're fetched with one snapshot or puzzled from some kind of procfs.

BUGS

The very first call of sg_get_process_count_of(sg_last_process_count) will return the same as sg_get_process_count_of(sg_entire_process_count).

The compare functions exist rather for backward compatibility than for functionality enhancements. Limited flexibility (e.g. reverse order) and lack of optimising opportunities for the compiler leads to the recommendation to implement the required compare routines locally.
