NOMBRE

sg_sync - enviar comando SCSI SYNCHRONIZE CACHE

SINOPSIS

sg_sync [--16] [--count=COUNT] [--group=GN] [--help] [--immed] [--lba=LBA] [--sync-nv] [--timeout=SECS] [--verbose] [--version] DISPOSITIVO

DESCRIPCIÓN

Envía el comando SYNCHRONIZE CACHE(10) o SYNCHRONIZE CACHE(16) al DISPOSITIVO. Estos comandos están definidos para dispositivos de bloque SCSI (ver SBC-3). Si tienen éxito, estos comandos aseguran que cualquier bloque cuya última versión se mantenga en caché se escriba en el medio (también denominado "sincronizado con").

Si los argumentos LBA y COUNT son ambos cero (sus valores predeterminados), entonces se sincronizan todos los bloques de la caché. Si LBA es mayor que cero mientras COUNT es cero, entonces se sincronizan en el medio los bloques de la caché cuyas direcciones van desde y incluyendo LBA hasta la LBA más alta del dispositivo. Si tanto LBA como COUNT son distintos de cero, entonces se sincronizan en el medio los bloques de la caché cuyas direcciones se encuentran en el rango LBA a LBA+COUNT-1 inclusive.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas.

-S, --16
realiza un comando SYNCHRONIZE CACHE(16). El valor predeterminado es realizar un comando SYNCHRONIZE CACHE(10).
-c, --count=COUNT
donde COUNT es el número de bloques a sincronizar desde y incluyendo LBA. El valor predeterminado es 0. Cuando es 0, se sincronizan todos los bloques de la caché desde y incluyendo el argumento LBA hasta la dirección de bloque más alta.
-g, --group=GN
donde GN es el número de grupo, que puede estar entre 0 y 63 inclusive. El valor predeterminado es 0. Los números de grupo se utilizan para segregar los datos recopilados dentro del dispositivo. Esta es una característica nueva en SBC-2 y probablemente se pueda ignorar por el momento.
-h, --help
muestra el mensaje de uso y sale.
-i, --immed
establece el bit IMMED en el comando SYNCHRONIZE CACHE. Esto instruye al dispositivo, si el formato del comando es aceptable, a devolver un estado BUENO inmediatamente en lugar de esperar a que los bloques de la caché se sincronicen con el medio (es decir, se escriban en él).
-l, --lba=LBA
donde LBA es la dirección de bloque lógico más baja en la caché a sincronizar con el medio. El valor predeterminado es 0.
-s, --sync-nv
sincroniza la caché (volátil) con la caché no volátil. Sin esta opción (o si no hay caché no volátil en el dispositivo), la sincronización es con el medio. El bit SYNC_NV se volvió obsoleto en la revisión 35d de SBC-3.
-t, --timeout=SECS
donde SECS es el número de segundos que el SO permite que se complete SYNCHRONIZE CACHE(16) antes de intentar cancelar el comando. Se deben evitar las cancelaciones de comandos (típicamente con la función de gestión de tareas "abort task"). Tenga en cuenta que esta opción solo está activa junto con la opción --16. El tiempo de espera predeterminado es de 60 segundos tanto para SYNCHRONIZE CACHE(10) como para SYNCHRONIZE CACHE(16). Tenga en cuenta que los problemas de tiempo de espera se pueden evitar con la opción --immed.
-v, --verbose
aumenta el nivel de verbosidad (es decir, la salida de depuración).
-V, --version
imprime la cadena de versión y sale.

NOTAS

Con el comando SYNCHRONIZE CACHE(16), LBA puede tener hasta 64 bits de tamaño y COUNT hasta 32 bits de tamaño. Con el comando SYNCHRONIZE CACHE(10), LBA puede tener hasta 32 bits de tamaño y COUNT hasta 16 bits de tamaño.

Varios argumentos numéricos (por ejemplo, LBA) pueden incluir sufijos multiplicadores o darse en hexadecimal. Consulte la sección "ARGUMENTOS NUMÉRICOS" en la página del manual de sg3_utils(8).

ESTADO DE SALIDA

El estado de salida de sg_sync es 0 cuando tiene éxito. De lo contrario, consulte la página del manual de sg3_utils(8).
