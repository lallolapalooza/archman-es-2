DESCRIPCIÓN

Esta utilidad enviará uno de los seis comandos SCSI, todos ellos asociados con la escritura de datos en el DEVICE dado. Son WRITE "normal", ORWRITE, WRITE ATOMIC, WRITE SAME, WRITE SCATTERED o WRITE STREAM. Esta utilidad soporta las variantes de 16 y 32 bytes de los seis comandos. Por lo tanto, no se soportan algunos comandos estrechamente relacionados (por ejemplo, WRITE(10)). Todas las variantes de 32 bytes, aparte de ORWRITE(32), requieren que el DEVICE esté formateado con Información de Protección (PI) de tipo 1, 2 o 3, haciendo que todos los bloques lógicos sean 8 bytes (o un múltiplo de 8 bytes) más largos en el medio.

La interfaz de línea de comandos está un poco saturada con más de treinta opciones. Por lo tanto, la SINOPSIS, después de enumerar todas las opciones (largas), enumera las aplicables a cada comando soportado. Para cada sinopsis de comando, la opción que selecciona el comando SCSI se muestra primero seguida de las opciones requeridas. Si no se da ninguna opción de comando, se asume un WRITE "normal". Aunque la opción --scat-file=SF puede darse para cada comando, sólo se muestra para WRITE SCATTERED donde es más útil. Si se da la opción --scat-file=SF, entonces ni las opciones --lba=LBA[,LBA...] ni las opciones --num=NUM[,NUM...] deben darse. Sólo el primer elemento de las opciones --lba=LBA[,LBA...] y --num=NUM[,NUM...] (o el primer par (o quinteto) de la opción --scat-file=SF) se utiliza para todos los comandos excepto WRITE SCATTERED. Todos los comandos pueden tomar --dry-run y --verbose además de los que se muestran en la SINOPSIS.

El tamaño del bloque lógico en bytes puede especificarse explícitamente con la opción --bs=BS, siempre que BS sea mayor que cero. Normalmente es una potencia de dos, 512 o superior. Si la opción --bs=BS no se da o BS es cero, entonces se utiliza el comando SCSI READ CAPACITY para encontrar el tamaño del bloque lógico. Primero se intenta el comando READ CAPACITY(16) y si tiene éxito, el tamaño del bloque lógico en la respuesta se utiliza típicamente como el tamaño real del bloque para esta utilidad. La excepción es cuando PROT_EN está establecido en la respuesta y se da la opción --wrprotect=WPR y es distinto de cero; en cuyo caso se añaden 8 (bytes) al tamaño del bloque lógico para obtener el tamaño real del bloque utilizado por esta utilidad. Si READ CAPACITY(16) falla, se intenta READ CAPACITY(10) y si eso funciona, el tamaño del bloque lógico en la respuesta se utiliza como el tamaño real del bloque.

El número de bytes que esta utilidad intentará leer del archivo nombrado por IF es el producto del tamaño real del bloque y el número_de_bloques (NUM o la suma de los argumentos NUM). Si se leen menos bytes del archivo IF y se da la opción --strict, esta utilidad saldrá con un estado de salida SG_LIB_FILE_ERROR. Si se leen menos bytes del archivo IF y la opción --strict no se da, se sustituyen bytes de cero por los bytes "faltantes" y esta utilidad continúa.

Los intentos de escribir datos de varios megabytes con un solo comando probablemente fallarán por una de varias razones. Primero, el sistema operativo podría objetar la asignación de un buffer tan grande. Luego, el passthrough SCSI generalmente limita los bloques de datos a unos pocos megabytes o menos. Finalmente, el dispositivo de almacenamiento podría tener una cantidad limitada de RAM para soportar una operación de escritura como la atómica (ya que podría necesitar revertir). El dispositivo de almacenamiento puede informar al cliente de la aplicación de sus limitaciones a través de la página VPD de límites de bloques (0xb0), con el campo de longitud máxima de transferencia atómica entre otros.

Un descriptor de rango de LBA (Logical Block Address) degenerado sin PI tiene un LBA y NUM de cero. Un descriptor de rango de LBA degenerado con PI además tiene sus campos RT, AT y TM establecidos a cero (nota: esos no son los valores por defecto para RT, AT y TM). Son degenerados en el sentido de que son indistinguibles de un relleno de ceros que sigue a la lista de dispersión en el buffer de salida de datos. SBC-4 deja claro que un descriptor de rango de LBA degenerado es válido. Esto puede convertirse en un problema si RD dado en la opción --scattered=RD tiene el valor 0. En este caso, la lógica puede necesitar escanear los datos proporcionados por el usuario para calcular el número de descriptores de rango de LBA que se requiere para el cdb WRITE SCATTERED. En ausencia de otra información, la lógica tomará un descriptor de rango de LBA degenerado como un terminador de la lista de dispersión.

La referencia para estos comandos es SBC-4 (T10/BSR INCITS 506-2021) y el borrador SBC-5 INCITS 571 revisión 1 con fecha 21 de mayo de 2021. Los seis comandos SCSI se describen en esos documentos. WRITE ATOMIC se añadió en la revisión 3 de SBC-4; WRITE STREAM se añadió en la revisión 7 de SBC-4; WRITE SCATTERED se añadió en la revisión 11 de SBC-4, mientras que los otros están en el estándar SBC-3 anterior.

-a, --app-tag=AT
donde AT es el campo "etiqueta lógica de aplicación de bloque esperada" que se encuentra en la mayoría de las variantes de cdb de 32 bytes (la excepción es ORWRITE(32)). AT es un campo de 16 bits, lo que significa que el valor máximo es 0xffff. El valor predeterminado es 0xffff.
-A, --atomic=AB
selecciona el comando WRITE ATOMIC y AB se coloca en el campo Atomic Boundary de su cdb. Es un campo de 16 bits, por lo que el valor máximo es 0xffff. Si no está seguro del valor a establecer, pruebe con 0, que intentará escribir el búfer completo de datos de salida en una única operación atómica.
-B, --bmop=OP,PGP
donde OP y PGP son los valores que se colocarán en los campos BMOP y 'Previous Generation Processing' de ORWRITE(32), respectivamente. BMOP es un campo de 3 bits (rango de 0 a 7) y PGP es un campo de 4 bits (rango de 0 a 15). Ambos campos tienen un valor predeterminado de 0.
-b, --bs=BS
donde BS es el tamaño de bloque lógico o el tamaño de bloque real que será ligeramente mayor. El valor predeterminado es cero. Si esta opción no se proporciona o se proporciona con un BS de cero, entonces se envía el comando SCSI READ CAPACITY(16) a DEVICE. Si falla, se envía el comando READ CAPACITY(10). El tamaño de bloque lógico y real se derivará de la respuesta del comando READ CAPACITY.
Esta sección asume que BS es mayor que cero. Si BS es menor que 512 (bytes) o no es un múltiplo de 8, se emitirá una advertencia y la utilidad continuará a menos que también se proporcione la opción --strict. Si BS es una potencia de dos (por ejemplo, 512), entonces el tamaño de bloque lógico y real se establecerá en BS (por ejemplo, 512). Si BS no es una potencia de dos (por ejemplo, 520), entonces el tamaño de bloque lógico se establecerá en la potencia de dos más cercana menor que BS (por ejemplo, 512) y el tamaño de bloque real se establecerá en BS (por ejemplo, 520).
Si los tamaños de bloque lógico y real son diferentes, una comprobación posterior reducirá el tamaño de bloque real al tamaño de bloque lógico a menos que --wrprotect=WPR sea mayor que cero.
-c, --combined=DOF
Esta opción solo se aplica a WRITE SCATTERED y asume que todo el búfer de datos de salida se puede leer de IF proporcionado por la opción --in=IF. Todo el búfer de datos de salida es la cabecera de la lista de parámetros, seguido de cero o más descriptores de rango de LBA, opcionalmente seguido de algunos bytes de relleno y luego los datos a escribir en los medios. Si las opciones --lba=LBA[,LBA...], --num=NUM[,NUM...] o --scat-file=SF también se proporcionan, se genera un error. El argumento DOF debe ser el valor adecuado para el campo 'Logical Block Data Offset' en el cdb de WRITE SCATTERED. Este es el desplazamiento en el búfer de datos de salida donde comienzan los datos a escribir en los medios. La unidad de ese campo es el tamaño de bloque real, que es el tamaño de bloque lógico más un múltiplo de 8, si se está enviando información de protección (PI). Cuando WPR (de --wrprotect=WPR) es mayor que cero, se espera PI. SBC-4 revisión 15 no lo indica, pero parecería que un valor DOF de 0 no es válido. Se sugiere que esta opción se utilice con la opción --strict mientras se experimenta, ya que datos aleatorios o incorrectos proporcionados a través de la opción --in=IF podrían escribir una gran cantidad de datos "interesantes" en todo el DEVICE. Si se proporciona DOF como 0, la utilidad escaneará los datos en IF hasta que se encuentren RD descriptores de rango de LBA; o si RD también es 0 hasta que se encuentre un descriptor de rango de LBA degenerado.
-D, --dld=DLD
donde DLD es el descriptor de límites de duración distribuido en 3 bits en los cdb de SCSI WRITE(16) y WRITE SCATTERED(16). DLD está entre 0 y 7 inclusive, con un valor predeterminado de cero. El campo DLD0 en WRITE(16) y WRITE SCATTERED(16) se establece si (0x1 & DLD) no es cero. El campo DLD1 en ambos cdb se establece si (0x2 & DLD) no es cero. El campo DLD2 en ambos cdb se establece si (0x4 & DLD) no es cero.
-d, --dpo
si se proporciona esta opción, se establece el campo de bits DPO (disable page out) en el cdb. El valor predeterminado es borrar este campo de bits. Se aplica a todos los comandos compatibles con esta utilidad, excepto WRITE SAME.
-x, --dry-run
esta opción sale (con un estado de 0) justo antes de enviar el comando de escritura SCSI seleccionado. Aún puede enviar un comando SCSI READ CAPACITY (variante de 16 bytes y quizás también variante de 10 bytes), por lo que el DEVICE sigue siendo necesario. Lee los datos y los procesa si se proporcionan las opciones --in=IF y/o --scat-file=SF. Se realizarán todos los procesamientos de línea de comandos y comprobaciones de validez (por ejemplo, si se proporciona la opción --strict) y si hay un error, habrá un valor de estado de salida distinto de cero.
Si esta opción se proporciona dos veces (por ejemplo, -xx), en lugar de realizar el comando SCSI de escritura seleccionado, el búfer de datos de salida se escribe en un archivo llamado sg_write_x.bin. Si no existe, ese archivo se crea en el directorio actual y se trunca si existía previamente con contenido más largo. El búfer de datos de salida se escribe en binario con información sobre él en stdout. Para escrituras distintas de la dispersa, el nombre del archivo y su longitud en bytes se muestran en stdout. Para escritura dispersa, además se muestran su número de descriptores de rango de LBA y su desplazamiento de bloque lógico en stdout.
-f, --fua
si se proporciona esta opción, se establece el campo de bits FUA (force unit access) en el cdb. El valor predeterminado es borrar este campo de bits. Se aplica a todos los comandos compatibles con esta utilidad, excepto WRITE SAME.
-G, --generation=EOG,NOG
los argumentos de esta opción se utilizan solo con el comando ORWITE(32). EOG se coloca en el campo "Expected ORWgeneration" mientras NOG se coloca en el campo "New ORWgeneration". Ambos tienen 32 bits de longitud y un valor predeterminado de cero.
-g, --grpnum=GN
establece el campo 'Group number' en GN. El valor predeterminado es cero. GN debe ser un valor entre 0 y 63.
-h, --help
muestra el mensaje de uso y luego sale. Usa varias veces para obtener más ayuda. Actualmente, '-h' a '-hhhh' proporcionan salidas diferentes.
-i, --in=IF
lee datos (en binario) de un archivo llamado IF en una única llamada al sistema operativo (en Unix: read(2)). Esos datos se colocan en un búfer continuo y luego se utilizan como búfer de datos de salida para todos los comandos de escritura SCSI, excepto WRITE SCATTERED(16 o 32), que pueden incluir otros datos en el búfer de datos de salida. Para WRITE SCATTERED (16 o 32), el búfer de datos de salida consta de 3 o 4 componentes en este orden: una cabecera de lista de parámetros (32 bytes cero); cero o más descriptores de rango de LBA, opcionalmente algunos bytes de relleno (ceros) y luego datos para escribir en los medios. Para WRITE SCATTERED, IF solo proporciona los datos para escribir en los medios, a menos que se proporcione --combined=DOF. En este caso, se pueden proporcionar --offset=OFF,DLEN con OFF establecido en 0 y LEN establecido en un valor distinto de cero, preferiblemente un múltiplo del tamaño de bloque real. La utilidad también puede deducir la longitud que debe tener IF a partir de NUM (o la suma de ellos en el caso de una lista dispersa). -l, --lba=LBA[,LBA...]
donde el argumento es una única Dirección de Bloque Lógico (LBA) o una lista separada por comas de LBAs, cada una de las cuales es la dirección del primer bloque escrito por el comando de escritura seleccionado. -a, --append
selecciona el comando APPEND. APPEND tiene un campo que le indica al dispositivo la longitud de los datos de salida que se envía. Por defecto, la longitud se determina a partir del tamaño del archivo de entrada (que se puede especificar con la opción -I).
-b, --bidi
selecciona el comando WRITE BAND. Esto se usa típicamente para escribir datos de configuración en una cinta magnética.
-c, --cmdlen=CL
longitud del CDB en bytes; por defecto es 16. Los valores comunes son 16 y 32.
-d, --dpo
establece el campo DPO (Desactivar la colocación de caché) en el CDB. Cuando está establecido, el dispositivo puede colocar en caché los datos escritos o ignorarlos según lo considere conveniente.
-f, --force
intenta forzar la operación de escritura incluso si se encuentran errores. Usar con precaución.
-g, --grouped
selecciona el comando WRITE AND VERIFY.
-H, --heavy
activa el modo "heavy" para ciertos comandos de escritura. La funcionalidad exacta depende del comando específico.
-i, --in=IF
especifica el archivo de entrada IF para leer datos. Si se usa con --out, los datos se leen de IF y se escriben en OF. Si se usa solo, los datos se leen de IF y se escriben en el dispositivo de destino.
-I, --length=DLEN
especifica la longitud en bytes de los datos a escribir. Si no se proporciona, se utiliza la longitud del archivo de entrada especificado por -i. Si DLEN es cero o no se proporciona, se supone que la lectura desde el desplazamiento de byte OFF hasta el final del archivo llamado IF se asume.
-O, --or
selecciona el comando ORWRITE. ORWRITE(16) tiene campos similares a WRITE(16) aparte de que el campo WRPROTECT se llama ORPROTECT con una semántica ligeramente diferente y la ausencia de los 3 campos de bits DLD. ORWRITE(32) tiene cuatro campos adicionales que se establecen con las opciones --bmop=OP,PGP y --generation=EOG,NOG. ORWRITE(32) es el único comando cdb de 32 bytes en esta utilidad que no requiere un DEVICE formateado con PI de tipo 1, 2 o 3 (aunque seguirá funcionando si está formateado con PI).
-Q, --quiet
suprime algunos mensajes informativos, como los asociados con errores detectados cuando esta utilidad está a punto de salir. El valor de estado de salida todavía se devuelve al sistema operativo cuando esta utilidad sale.
-r, --ref-tag=RT
donde RT es el campo "etiqueta de referencia de bloque lógico inicial esperada" que se encuentra en las variantes cdb de 32 bytes de WRITE, WRITE ATOMIC, WRITE SAME y WRITE STREAM. El campo también se encuentra en los descriptores de rango LBA de WRITE SCATTERED(32). Es un campo de 32 bits, lo que significa que el valor máximo es 0xffffffff. El valor predeterminado es 0xffffffff.
-S, --same=NDOB
selecciona el comando WRITE SAME con el campo NDOB establecido en NDOB, que significa No Data-Out Buffer. NDOB puede tomar los valores 0 o 1 (es decir, es un campo de un solo bit). Cuando --same=1, todas las opciones asociadas con el búfer de salida de datos se ignoran.
-q, --scat-file=SF
donde SF es el nombre de un archivo auxiliar que contiene la lista de dispersión para el comando WRITE SCATTERED. Si también se proporciona la opción --scat-raw, entonces se asume que SF contiene tanto la cabecera de la lista de parámetros (32 bytes de ceros) seguida de cero o más descriptores de rango LBA que también tienen 32 bytes de longitud cada uno. Estos componentes son como se definen en SBC-4 (es decir, en binario con enteros en formato big endian). Si la opción --scat-raw no se proporciona, se espera un archivo en formato hexadecimal ASCII como se describe en la sección FORMATO ASCII DEL ARCHIVO SCATTERED a continuación.
Si se proporciona esta opción junto con la opción --combined=DOF, esta utilidad saldrá con un error de sintaxis. SF no debe ser "-" , una forma de evitar que el usuario intente redirigir la entrada estándar.
-R, --scat-raw
esta opción solo afecta la forma en que se interpreta el archivo llamado SF de la opción --scat-file=SF para WRITE SCATTERED. Por defecto (es decir, sin esta opción), SF se analiza como hexadecimal ASCII, ignorando las líneas en blanco y el contenido de la línea desde y hasta el final de la línea (incluido '#'). Por lo tanto, puede contener comentarios y otras indicaciones. Cuando se proporciona esta opción, el archivo llamado SF se interpreta como binario. Como binario, se asume que contiene 32 bytes de ceros (la cabecera de la lista de parámetros WRITE SCATTERED) seguidos de cero o más descriptores de rango LBA (que tienen 32 bytes cada uno). Si se proporciona la opción --strict, se verifican los campos reservados en esos dos elementos y cualquier byte distinto de cero causará un error.
-S, --scattered=RD
selecciona el comando WRITE SCATTERED con RD siendo el número de descriptores de rango LBA que se colocarán en el búfer de salida de datos. Si RD es cero, entonces la lógica intentará determinar el número de descriptores de rango por otros medios (por ejemplo, analizando el archivo llamado por SF, si lo hay). Los descriptores de rango LBA difieren entre las variantes cdb de 16 y 32 bytes de WRITE SCATTERED. En la variante cdb de 16 bytes, el descriptor de rango LBA de 32 bytes se compone de un LBA de 8 bytes, seguido de un number_of_blocks de 4 bytes y 20 bytes de ceros. En la variante de 32 bytes, el LBA y number_of_blocks van seguidos de un RT (4 bytes), un AT (2 bytes) y un TM (2 bytes) y luego 12 bytes de ceros.
Este párrafo se aplica cuando RD es mayor que cero. Si RD es menor que el número de descriptores de rango LBA construidos a partir de las opciones de línea de comandos, de la opción --scat-file=SF o decodificados de IF (cuando se proporciona la opción --combined=DOF), entonces RD tiene prioridad; por lo tanto, RD se coloca en el campo "Número de descriptores de rango LBA" en el cdb. Si RD es mayor que el número de descriptores de rango LBA encontrados a partir de los datos y opciones proporcionados, se genera un error.
-T, --stream=ID
selecciona el comando WRITE STREAM con el campo STR_ID establecido en ID. ID puede tomar valores de 0 a 0xffff (es decir, es un campo de 16 bits).
-s, --strict
cuando esta opción está presente, más cosas (por ejemplo, que los campos reservados contengan ceros) y cualquier irregularidad terminarán la utilidad con un mensaje a stderr y un estado de salida indicativo. Mientras experimenta con estos comandos, especialmente WRITE SCATTERED, se recomienda usar esta opción.
-t, --tag-mask=TM
donde TM es el campo "máscara de etiqueta de aplicación de bloque lógico" que se encuentra en las variantes cdb de 32 bytes de WRITE, WRITE ATOMIC, WRITE SAME y WRITE STREAM. El campo también se encuentra en los descriptores de rango LBA de WRITE SCATTERED(32). Es un campo de 16 bits, lo que significa que el valor máximo es 0xffff. El valor predeterminado es 0xffff.
-I, --timeout=TO
donde TO es el valor del tiempo de espera del comando en segundos. El valor predeterminado es 120 segundos. Si NUM es grande en medios lentos, estos comandos WRITE pueden requerir considerablemente más de 120 segundos para completarse. Una forma alternativa de opción larga es --tmo=TO.
-u, --unmap=U_A
donde U_A son valores de bits OR-ed utilizados para establecer los campos de bits UNMAP y ANCHOR en el CDB de WRITE SAME (16 o 32). Si U_A es 1, se establece el campo de bits UNMAP; si U_A es 2, se establece el campo de bits ANCHOR; si U_A es 3, se establecen ambos campos de bits UNMAP y ANCHOR. El valor predeterminado para ambos campos de bits está claro (0); establecer U_A en 0 también borrará ambos campos de bits.
-v, --verbose
aumenta el grado de verbosidad (mensajes de depuración). Estos mensajes generalmente se escriben en stderr.
-V, --version
muestra la cadena de la versión y sale.
-w, --wrprotect=WPR
establece el campo WRPROTECT (3 bits) en todos los comandos sg_write_x, excepto en ORWRITE, que tiene un campo ORPROTECT de 3 bits (y la sinopsis muestra OPR para resaltar la diferencia). En todos los casos, WPR se coloca en ese campo de 3 bits. El valor predeterminado es cero, que no envía ningún PI en el búfer de salida de datos. WPR debe ser un valor entre 0 y 7.

FORMATO ASCII DEL ARCHIVO SCATTERED

Todos los comandos de esta utilidad pueden aceptar un --scat-file=SF y esa opción puede considerarse un reemplazo para las opciones --lba=LBA[,LBA...] y --num=NUM[,NUM...]. si se proporcionan ambas opciones --scat-file=SF y --scat-raw, entonces se espera que el archivo llamado SF sea binario y contenga la cabecera de la lista de parámetros (32 bytes de ceros para ambas variantes de 16 y 32 bytes) seguida de cero o más descriptores de rango LBA, cada uno de 32 bytes. Esta sección describe lo que se espera en SF cuando la opción --scat-raw no se proporciona.

El archivo "scatter" hexadecimal ASCII (llamado por SF) puede contener comentarios, líneas vacías y números. Si aparecen varios números en una línea, pueden separarse por espacios, tabulaciones o una coma simple. Los números se analizan como decimales a menos que vayan precedidos por "0x" (o "0X") o tengan un sufijo de "h". Ox es el prefijo de un número hexadecimal en el lenguaje C, mientras que T10 utiliza el sufijo "h" para el mismo propósito. Todo lo que sea desde un carácter "#" hasta el final de la línea (incluidos ambos) se ignora, por lo que se pueden colocar comentarios allí.

Para el comando WRITE SCATTERED (16), sus descriptores de rango LBA contienen dos elementos por descriptor: un LBA de 8 bytes seguido de un number_of_blocks de 4 bytes. Los 20 bytes restantes del descriptor son ceros. El formato aceptado es relativamente flexible, y cada valor decodificado se coloca en un LBA y luego en un number_of_blocks hasta que se alcanza el final del archivo. El patrón comienza con un LBA y si no termina con un number_of_blocks (es decir, se analizan un número impar de valores), ocurre un error. Por lo tanto, el número de descriptores de rango LBA generados será la mitad del número de valores analizados en SF.

Para el comando WRITE SCATTERED (32), sus descriptores de rango LBA contienen cinco elementos por descriptor: un LBA de 8 bytes seguido de un number_of_blocks de 4 bytes, luego un RT de 4 bytes, un AT de 2 bytes y un TM de 2 bytes. Los últimos tres elementos están asociados con la información de protección (PI). El formato aceptado en el archivo SF es más restringido que la variante cdb de 16 bytes. Los elementos para cada descriptor de rango LBA deben encontrarse en una línea, con elementos adyacentes separados por comas. Se deben proporcionar los dos primeros elementos (LBA y number_of_blocks), y si no hay más elementos en la línea, RT, AT y TM reciben sus valores predeterminados (todos bytes "ff"). Pueden aparecer espacios y tabulaciones entre elementos, pero las comas son los separadores. Dos comas sin ningún valor entre ellas harán que el elemento "faltante" reciba su valor predeterminado.

NOTAS

Varios argumentos numéricos (por ejemplo, LBA) pueden incluir sufijos multiplicadores o darse en hexadecimal. Consulte la sección "ARGUMENTOS NUMÉRICOS" en la página del manual sg3_utils(8).

En Linux, antes de lk 3.17, el controlador sg no admitía tamaños de cdb superiores a 16 bytes. Por lo tanto, un nodo de dispositivo como /dev/sg1 asociado con el controlador sg fallaría con esta utilidad si se proporcionaba la opción --32 (o se implicaba por otras opciones). El controlador bsg con nodos de dispositivo como /dev/bsg/6:0:0:1 admite tamaños de cdb superiores a 16 bytes desde su introducción en lk 2.6.28.

sg_write_x(8)

sg_write_x

sg_write_x - write data to a SCSI device's logical blocks.

SYNOPSIS

sg_write_x [OPTIONS] DEVICE

DESCRIPTION

Writes data from a given file or standard input to the logical blocks of a SCSI device (e.g., disk, CD-ROM, tape). The type of write operation is determined by the options given. The most common SCSI write commands are WRITE (10 or 16) and WRITE SAME (10 or 16). If the --scattered option is used, WRITE SCATTERED (16) is used.

If no options specifying a particular write command (e.g., --atomic, --same, --scattered) are given, then WRITE (16) is assumed by default.

OPTIONS

The SCSI command options may be prefixed by a number indicating the length of the CDB in bytes, defaulting to 16 bytes (e.g. --10 implies a 10 byte CDB, --16 implies a 16 byte CDB). If no length is given, the default is 16 bytes. If a command variant is specified with a number (e.g. --atomic=0), that length is used.

General options:

    -b, --bs=BS Number of bytes in each logical block. If not specified, then the utility will try to determine this using READ CAPACITY(10) or READ CAPACITY(16) SCSI commands. If BS is a power of 2, it is used directly. Otherwise, the logical block size is the largest power of 2 less than or equal to BS and the actual block size is BS.

    -f, --in=FILE Read data to be written from FILE instead of standard input. If FILE is a single hyphen ('-') standard input is used.

    -n, --num=NUM Number of logical blocks to write. Defaults to 1.

    -l, --lba=LBA Logical block address (LBA) to start writing from. Defaults to 0.

    -v, --verbose Increase the verbosity of the output.

    -vv Increase verbosity further.

    -h, --help Print the usage summary.

    -V, --version Print the version string and exit.

Command specific options:

    --10 Use 10 byte CDB length for the SCSI command.

    --16 Use 16 byte CDB length for the SCSI command.

    --32 Use 32 byte CDB length for the SCSI command.

    --atomic=ABD Use the WRITE ATOMIC command. ABD is the atomic boundary descriptor (0 to 7).

    --same=NDOB Use the WRITE SAME command. NDOB is the number of logical blocks of data to write. Defaults to 1. See also sg_write_same(8).

    --stream=STR_ID Use the WRITE STREAM command. STR_ID is the stream identifier (0 to 255).

    --scattered=N Use the WRITE SCATTERED command. N is the number of LBA range descriptors (elements) in the scatter list. If N is 0, then the number of descriptors is inferred from the input file (see --combined).

    --combined=LBDO When used with --scattered, this option specifies the logical block data offset within the input buffer (FILE or stdin). If LBDO is 0, it defaults to the size of the CDB. If LBDO is greater than 0, it is the offset in bytes. If LBDO is 1, then the scatter list is read first, followed by the logical block data. The default for --scattered without --combined is --combined=0 which means the number of LBA range descriptors is inferred from the CDB size.

    -q, --quiet Skip the write to media. Instead, write the constructed SCSI command (with its data payload if any) to a file named sg_write_x.bin. This file can be used as input to a subsequent invocation of sg_write_x which *will* write to the media.

    -xx Dump out the received SCSI CDB in hex. Do not send to the device. This is useful for debugging.

    --wce Enable write cache

    --wcd Disable write cache

SCATTERED FILE ASCII FORMAT

If the --scattered option is used and the input file (given by -f or -i) is an ASCII file, then each line in the file should represent an LBA range descriptor for the WRITE SCATTERED command. The format for each line is:

   LBA,LEN where LBA is the logical block address and LEN is the number of logical blocks in the range.

For example:


0,1024
10240,512
0x20000,2048

If --scattered is given with a value greater than 0, and the input file is an ASCII file, then the number of LBA range descriptors on the lines is checked against the value given to --scattered.

If --scattered is given with a value of 0, then the number of LBA range descriptors is inferred from the input file. Lines are read until a blank line is encountered, or until the end of the file. The number of lines read is taken as the number of LBA range descriptors.

The data to be written follows the LBA range descriptors. There should be a blank line separating the descriptors from the data. The data itself should be in binary format.

An alternative to this ASCII file format is to use the --combined option with a binary file containing both the LBA range descriptors and the data payload.

NOTES

This utility constructs and sends SCSI WRITE commands. It is intended for advanced users who understand the implications of writing directly to SCSI devices. Incorrect usage can lead to data loss.

The block size BS is determined by READ CAPACITY(16) or READ CAPACITY(10) SCSI commands unless the --bs=BS option is given. If BS is provided and it's not a power of 2, then the logical block size is the largest power of 2 less than or equal to BS, and the actual block size is BS.

The --scattered option allows for writing to non-contiguous logical block addresses within a single command. The data payload must be structured accordingly.

The -q or --quiet option is useful for preparing the data and command for a WRITE SCATTERED operation without actually performing the write. The output file (sg_write_x.bin) can then be used as input for the actual write command.

EXIT STATUS

Returns 0 if the operation was successful, or non-zero if the operation failed. The failure code is the sense key and additional sense code from the SCSI sense data, formatted as:


0xSSKKLLXX
where SS is the SCSI sense key, KKLL is the additional sense code (ASC/ASCQ), and XX is typically 0.

If the exit status is 0, then sg_write_x was successful. Otherwise, an error occurred, and the contents of the error message indicate the problem. The SCSI sense data can also be printed if the --verbose option is used. See also the sg3_utils(8) man page.

EXAMPLES

One simple usage is to write 4 blocks of zeros from (and including) a given LBA according to the rules of WRITE ATOMIC with an atomic boundary of 0. Since no cdb size option is given, the 16 byte cdb will be assumed (i.e. WRITE ATOMIC(16)):


sg_write_x --atomic=0 --in=/dev/zero --lba=0x1234 --num=4 /dev/sdc

Since --bs=BS has not been given, then this utility will call the READ CAPACITY(16) command on /dev/sdc to determine the number of bytes in a logical block. If the READ CAPACITY(16) command fails then the READ CAPACITY(10) command is tried. Let us assume one of them works and that the number of bytes in each logical block is 512 bytes. So 4 blocks of zeros (each block containing 512 bytes) will be written from (and including) LBA 0x1234 . Now to bypass the need for the READ CAPACITY command(s) the --bs=BS option can be used:


sg_write_x --atomic=0 --bs=512 --in=/dev/zero --lba=0x1234 --num=4 /dev/sdc

Since --bs= is given and its value (512) is a power of 2, then the actual block size is also 512. If instead 520 was given then the logical block size would be 512 (the highest power of 2 less than 520) and the actual block size would be 520 bytes. To send the 32 byte variant add --32 as in:


sg_write_x --atomic=0 --32 --bs=512 --in=/dev/zero --lba=0x1234 --num=4 /dev/sdc

For examples using 'sg_write_x --same=NDOB' see the manpage for sg_write_same(8). The syntax is a little different but the semantics are the same.

To send a WRITE STREAM(32) with a STR_ID of 1 use the following:


sg_write_x --stream=1 --32 --bs=512 --in=/dev/zero --lba=0x1234 --num=4 /dev/sdc

Next is a WRITE SCATTERED(16) command with the scatter list, split between the --lba= and --num= options, on the command line:


sg_write_x --scattered=2 --lba=2,0x33 --num=4,1 -i /dev/zero /dev/sg1

Example of a WRITE SCATTERED(16) command with a degenerate LBA range descriptor (first element to --lba= and --num=):


sg_write_x --scattered=2 --lba=0,0x33 --num=0,1 -i /dev/zero /dev/sg1

Example of a WRITE SCATTERED(16) command with the scatter list in scat_file.txt


sg_write_x --scattered=3 -q scat_file.txt -i /dev/zero /dev/sg1

Next a WRITE SCATTERED(16) command with its scatter list and data in a single file. Note that the argument to --scattered= is 0 so the number of LBA range descriptors is calculated by analyzing the first two blocks of scat_data.bin (because the argument to --combined= is 2) :


sg_write_x --scattered=0 --combined=2 -i scat_data.bin /dev/sg1

When the -xx option is used, a WRITE SCATTERED command is not executed but instead the contents of the data-out buffer are written to a file called sg_write_x.bin . In the case of WRITE SCATTERED that binary file is suitable for supplying to a later invocation to do the actual write to media. For example:


$ sg_write_x --scattered=3 -q scat_file.txt -xx -i /dev/zero /dev/sg1
Wrote 8192 bytes to sg_write_x.bin, LB data offset: 1
Number of LBA range descriptors: 3


sg_write_x --scattered=0 --combined=1 -i sg_write_x.bin /dev/sg1

Notice when the sg_write_x.bin is written (and nothing is written to the media), a summary of what has happened is sent to stdout. The value shown for "LB data offset:" (1) should be given to the --combined= option when the write to media actually occurs (i.e. the second invocation shown directly above).
