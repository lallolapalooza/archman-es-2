NOMBRE

sg_opcodes - informa sobre comandos SCSI o funciones de gestión de tareas soportados

SINOPSIS

sg_opcodes [--alpha] [--compact] [--enumerate] [--help] [--hex] [--inhex=FN] [--json[=JO]] [--js-file=JFN] [--mask] [--mlu] [--no-inquiry] [--opcode=OP[,SA]] [--pdt=DT] [--raw] [--rctd] [--repd] [--sa=SA] [--tmf] [--unsorted] [--verbose] [--version] DISPOSITIVO

sg_opcodes [-a] [-c] [-e] [-H] [-i=FN] [-j] [-m] [-M] [-n] [-o=OP] [-p=DT] [-q] [-R] [-s=SA] [-t] [-u] [-v] [-V] [-?] DISPOSITIVO

DESCRIPCIÓN

Esta utilidad envía un comando SCSI REPORT SUPPORTED OPERATION CODES o REPORT SUPPORTED TASK MANAGEMENT FUNCTIONS al DISPOSITIVO y luego muestra la respuesta. La acción por defecto es informar sobre los códigos de operación soportados. En este modo, listará todos los comandos soportados o proporcionará información detallada sobre un comando específico identificado por la opción --opcode=OP (quizás con información adicional de la opción --sa=SA).

El nombre de un comando SCSI depende de su tipo de dispositivo periférico (por ejemplo, un disco). Los comandos REPORT SUPPORTED OPERATION CODES y REPORT SUPPORTED TASK MANAGEMENT FUNCTIONS no son compatibles en el conjunto de comandos MMC para dispositivos CD y DVD. Esta utilidad realiza una consultación INQUIRY para obtener el tipo de dispositivo periférico e imprime las cadenas de vendedor, producto y revisión.

Una facilidad similar para consultar códigos de operación soportados anteriormente estaba disponible a través del bit CmdDt en el comando SCSI INQUIRY (ver sg_inq(8)). Sin embargo, esa facilidad quedó obsoleta y fue reemplazada por el comando REPORT SUPPORTED OPERATION CODES en SPC-3 (revisión 4) en febrero de 2002.

Esta utilidad soporta dos sintaxis de línea de comandos, la preferida se muestra primero en la sinopsis y se explica en esta sección. Una sección posterior sobre la sintaxis de línea de comandos antigua describe el segundo grupo de opciones.

OPCIONES

Los argumentos a las opciones largas son obligatorios para las opciones cortas también.

-a, --alpha
cuando se listan todos los comandos soportados, no hay requisito de que el servidor de dispositivos (es decir, el DISPOSITIVO) ordene la lista de comandos. Cuando se proporciona esta opción, la lista de comandos soportados se ordena por nombre (alfabéticamente). Cuando esta opción y la opción --unsorted no se proporcionan, la lista de comandos soportados se ordena numéricamente (primero por código de operación y luego por acción de servicio).
-c, --compact
algunos nombres de comandos, especialmente los asociados con algunas acciones de servicio, se están alargando. Esto puede causar saltos de línea en el modo de una línea por comando en algunos terminales. Cuando se proporciona esta opción, los campos de código de operación y acción de servicio se combinan en un solo campo con la acción de servicio, prefijado por una coma mostrada directamente después del código de operación. Si no hay una acción de servicio asociada con el comando, entonces la coma y la acción de servicio no se muestran después del código de operación. El campo de tamaño del CDB no se muestra cuando se proporciona esta opción.
-e, --enumerate
esta opción imprime el nombre del comando SCSI basado en el código de operación proporcionado, el tipo de dispositivo periférico y opcionalmente la acción de servicio. Si se proporciona, DISPOSITIVO es ignorado. El código de operación, el tipo de dispositivo periférico y la acción de servicio se establecen en cero por defecto si no se proporcionan. Por lo tanto, si esta opción es la única opción proporcionada, se mostrará "Test Unit ready" ya que su código de operación es 0, no tiene acción de servicio y es común a todos los tipos de dispositivos periféricos ya que está definido en los estándares SCSI Primary Commands (SPC).
-h, --help
muestra el mensaje de uso resumiendo las opciones de la línea de comandos y luego sale. Ignora DISPOSITIVO si se proporciona.
-H, --hex
muestra la respuesta en hexadecimal ASCII en stdout. Cuando se usa una o dos veces, cada línea comienza con una dirección relativa (hexadecimal) que empieza en 0 en la primera línea hexadecimal mostrada. La diferencia es que cuando se usa dos veces, los bytes hexadecimales se representan en ASCII a la derecha de cada línea; los caracteres no imprimibles se reemplazan por ".".
Cuando se usa tres o más veces, no hay una dirección relativa inicial en cada línea. Esta salida es adecuada para ser redirigida a un archivo que luego pueda ser proporcionado a la opción --inhex=FN.
-i, --inhex=FN
donde FN es un nombre de archivo cuyo contenido se supone que está en hexadecimal ASCII. Si también se proporciona DISPOSITIVO, entonces DISPOSITIVO es ignorado, se emite una advertencia y la utilidad continúa decodificando el archivo llamado FN. Ver la sección "FORMATOS HEX, BINARIO Y JSON" en la página del manual sg3_utils para más información. Si la opción --raw también se proporciona, el contenido de FN se trata como binario.
-j[=JO], --json[=JO]
la salida está en formato JSON en lugar de texto plano. Tenga en cuenta que los argumentos para la forma corta y larga son opcionales y si están presentes comienzan con "=" y no se permiten espacios en blanco alrededor de ese "=".
Ver la página del manual sg3_utils_json o usar '?' para JO para obtener un resumen.
-J, --js-file=JFN
la salida está en formato JSON y se envía a un archivo llamado JFN. Si ese archivo existe, se trunca. Por defecto, la salida JSON se envía a stdout.
Cuando se proporciona esta opción, la opción --json[=JO] se implica y no es necesario proporcionarla. La opción --json[=JO] aún puede ser necesaria para establecer el parámetro JO a valores no predeterminados.
-m, --mask
además, imprime la máscara cdb en hexadecimal. Por lo tanto, un cdb de 12 bytes tendrá una máscara hexadecimal de 12 bytes. Si el hexadecimal se expande (mentalmente) a binario, un "1" significa que la posición correspondiente en el cdb puede ser establecida. Y un "0" significa que la posición correspondiente en el cdb no debe ser establecida. Para las posiciones de máscara "0" que un usuario intenta establecer en un cdb, el dispositivo puede ignorarlo o informar un error, típicamente con una clave de sentido de "solicitud ilegal".
-M, --mlu
además, imprime una indicación (0 o 1) de si el comando afecta a todas las unidades lógicas en el objetivo contenedor. MLU (Multiple Logical Units) es un bit en la respuesta de REPORT SUPPORTED OPERATION CODES introducido por la propuesta 18-045r1 (y posiblemente en spc5r20). Sin la opción, el formato de salida por defecto que lista todos los opcodes, no incluye una indicación MLU.
-n, --no-inquiry
antes de llamar a un comando SCSI REPORT SUPPORTED OPERATION CODES o REPORT SUPPORTED TASK MANAGEMENT FUNCTIONS, se realiza un comando SCSI INQUIRY. La razón es determinar el tipo de dispositivo periférico (pdt) del DISPOSITIVO, ya que esto es útil para traducir los códigos de operación a los nombres de los comandos. Por defecto, esta utilidad imprime un resumen de la respuesta del comando INQUIRY en stdout. Si se proporciona esta opción (o la opción --raw), ese resumen no se imprime en stdout.
-O, --old
Cambiar al estilo de opciones antiguas. Por favor, úselo como primera opción.
-o, --opcode=OP[,SA]
el DISPOSITIVO será consultado para el código de operación dado (es decir, el valor OP) que es el primer byte de un comando SCSI. Opcionalmente, si se proporciona un valor SA, se utilizará como la acción de servicio de ese comando SCSI. Tenga en cuenta que OP y OP,0 no son lo mismo, ya que SCSI permite que la acción de servicio sea 0 (pero no en este comando). OP y SA son decimales a menos que estén prefijados por "0x" o tengan una "h" al final. OP debe estar en el rango de 0 a 255 (0xff) inclusive. SA debe estar en el rango de 0 a 65535 (0xffff) inclusive. Cuando esta opción no se proporciona, se listan todos los comandos SCSI disponibles soportados por el DISPOSITIVO.
-p, --pdt=DT
donde DT

-r, --raw
salida de respuesta en binario (a stdout) a menos que la opción --inhex=FN también se proporcione. En ese caso, el nombre del archivo de entrada (FN) se decodifica como binario (y la salida _no_ está en binario (pero puede estar en hexadecimal)).
-R, --rctd
establecer el bit de descriptor de tiempo de espera del comando de informe (RCTD) en el cdb. La respuesta puede o no contener descriptores de tiempo de espera del comando. Si están disponibles, se muestran. Si son compatibles, hay dos valores: un tiempo de espera nominal del comando y un tiempo de espera recomendado del comando. Ambos tienen unidades de segundos. Un valor de cero significa que no se indica tiempo de espera y esto se muestra en la salida decodificada correspondiente como "-" .
-q, --repd
establecer el bit de datos de parámetros extendidos de lectura (REPD) en el comando cdb de funciones de administración de tareas de informe. 16 bytes en lugar de los 4 bytes predeterminados esperados en la respuesta. Esto se agregó en SPC-4 (revisión 26).
-s, --sa=SA
el DEVICE será consultado para un comando con la acción de servicio (es decir, el valor SA) dada. Se usa junto con la opción --opcode=OP. Si esta opción no se proporciona, se proporciona --opcode=OP y el comando en cuestión tiene una acción de servicio, entonces se asumirá un valor de 0. SA está en decimal y se espera que esté en el rango de 0 a 65535 (0xffff) inclusive.
-t, --tmf
listar las funciones de administración de tareas admitidas. Esto se hace con el comando SCSI REPORT SUPPORTED TASK MANAGEMENT FUNCTIONS. Cuando se elige esta opción, se ignoran las opciones --alpha, --opcode=OP, --rctd, --sa=SA y --unsorted.
-u, --unsorted
cuando se listan todos los comandos admitidos, no hay requisito para que el servidor de dispositivos (es decir, el DEVICE) ordene la lista de comandos. Cuando se proporciona esta opción, la lista de comandos admitidos está en el orden proporcionado por el DEVICE. Cuando esta opción no se proporciona, los comandos admitidos se ordenan numéricamente (primero por código de operación y luego por acción de servicio).
-v, --verbose
aumentar el nivel de verbosidad. Se puede usar varias veces.
-V, --version
imprimir la cadena de versión y salir.

NOTAS

A partir de la revisión 8 de SPC-5, las funciones de administración de tareas reconocidas son: abortar conjunto, abortar tarea, borrar ACA, borrar conjunto de tareas, restablecimiento de unidad lógica, consultar tarea, consultar evento asíncrono, consultar conjunto de tareas y restablecimiento de nexo I_T. En la revisión 26 de SPC-4, las funciones de administración de tareas de restablecimiento de destino y despertar se volvieron obsoletas.

En la serie 2.4 de los kernels de Linux, el DEVICE debe ser un dispositivo genérico SCSI (sg). En la serie 2.6, también se pueden especificar dispositivos de bloque (por ejemplo, discos SCSI y unidades de DVD). Por ejemplo, "sg_opcodes /dev/sda" funcionará en los kernels de la serie 2.6.

ESTADO DE SALIDA

El estado de salida de sg_opcodes es 0 cuando tiene éxito. De lo contrario, consulte la página man de sg3_utils(8).

Consulte la sección VARIABLES DE ENTORNO para otra forma de forzar el uso de estas opciones de línea de comandos anteriores.

-N, --new
cambiar a las opciones de estilo más nuevas.
-o=OP

Cuando esta opción no se proporciona, se listan todos los comandos SCSI disponibles compatibles con el DEVICE.
-p=DT
ver la opción --pdt=DT anterior.
-q
establecer el bit de datos de parámetros extendidos de lectura (REPD) en el cdb de TMF de informe. Equivalente a --repd en la descripción principal.
-R
establecer el bit de descriptor de tiempo de espera del comando de informe (RCTD) en el cdb. Equivalente a --rctd en la descripción principal.

EJEMPLOS

Los ejemplos en esta página utilizan nombres de dispositivos de Linux. Para nombres de dispositivos adecuados en otros sistemas operativos compatibles, consulte la página man de sg3_utils(8).

Para ver la información sobre un comando específico, proporcione su código de operación a la opción '--op='. Se muestra primero una invocación de línea de comandos seguida de una respuesta típica:


# sg_opcodes --op=93h /dev/sdb


Opcode=0x93
Command_name: Write same(16)
Command supported [conforming to SCSI standard]
Usage data: 93 e2 00 00 00 00 ff ff ff ff 00 00 ff ff 00 00

El siguiente ejemplo muestra las funciones de administración de tareas admitidas:


# sg_opcodes --tmf -n /dev/sdb

Task Management Functions supported by device:
Abort task
Abort task set
Clear ACA
Clear task set
Logical unit reset
Query task

Enumerate se puede usar para buscar un nombre de comando SCSI en ausencia de un dispositivo que admita ese comando. Se deben proporcionar el código de operación y la acción de servicio (si es necesario):


# sg_opcodes --enumerate --op=0x9b,0xa


SCSI command:
Read buffer(16), read data from echo buffer

VARIABLES DE ENTORNO

Desde la versión 1.23 de sg3_utils, se puede proporcionar la variable de entorno SG3_UTILS_OLD_OPTS. Cuando está presente, esta utilidad esperará las opciones de línea de comandos anteriores. Por lo tanto, la presencia de esta variable de entorno es equivalente a usar --old (o -O) como la primera opción de línea de comandos.

    NOMBRE

    sg_opcodes - Imprime códigos de operación del dispositivo SCSI.

    SINÓPSIS

    sg_opcodes [opciones] [dispositivo]

    DESCRIPCIÓN

    La utilidad sg_opcodes se utiliza para imprimir los códigos de operación SCSI soportados por un dispositivo SCSI.

    OPCIONES

    • -h, --help: Muestra un mensaje de ayuda y sale.
    • -v, --verbose: Modo detallado.
    • -V, --version: Muestra información de la versión y sale.

    NOTAS

    Esta utilidad interactúa directamente con el dispositivo SCSI.

    CÓDIGO DE SALIDA

    0 si la operación fue exitosa, otro valor en caso de error.

    OPCIONES DE LÍNEA DE COMANDOS ANTIGUAS

    No se documentan opciones antiguas.

    EJEMPLOS

    Para ver los códigos de operación de un disco duro:

    sg_opcodes /dev/sda

    VARIABLES DE ENTORNO

    No se documentan variables de entorno específicas.
