NOMBRE

sg_turs - envía uno o más comandos SCSI TEST UNIT READY

SINOPSIS

sg_turs [--ascq=ASC[,ASQ]] [--delay=MS] [--help] [--low] [--num=NUM] [--number=NUM] [--progress] [--time] [--timeout=SE] [--verbose] [--version] DISPOSITIVO

sg_turs [-d=MS] [-n=NUM] [-p] [-t] [-v] [-V] DISPOSITIVO

DESCRIPCIÓN

Esta utilidad envía uno o más comandos SCSI TEST UNIT READY al DISPOSITIVO. Esto puede ser útil para medir el tiempo de sobrecarga de cada comando. Tenga en cuenta que TEST UNIT READY no tiene datos asociados, solo un comando de 6 bytes (con cada byte a cero) y un valor de estado SCSI devuelto.

Esta utilidad soporta dos sintaxis de línea de comandos, la preferida se muestra primero en la sinopsis y se explica en esta sección. Una sección posterior sobre la sintaxis antigua de la línea de comandos describe el segundo grupo de opciones.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas.

-a, --ascq=ASC[,ASQ]
comprueba los datos de sentido asociados con una clave de sentido de NOT READY. Si hay una coincidencia con ASC y, si se proporciona, con ASQ, esta utilidad establece su estado de salida en 36. Ese es un código de éxito alternativo porque un estado de salida de 0 implicaría que la unidad está lista.

La razón por la que se añadió esta opción son los lectores de tarjetas USB (por ejemplo, lectores de tarjetas SD) que a menudo producen un código de sentido adicional de 0x3a,0x0 para "sin medio presente" cuando no hay ninguna tarjeta SD en el lector. Hay variaciones del código de sentido adicional 0x3a, por lo que es mejor no proporcionar el valor ASQ para que cualquier código ascq coincida.

-d, --delay=MS
esta opción provoca un retraso de MS milisegundos antes de que se envíe cada comando TEST UNIT READY.
-h, --help
imprime el mensaje de uso y luego sale.
-l, --low
cuando [--progress] no se está utilizando, esta utilidad intenta completar los comandos SCSI TEST UNIT READY lo más rápido posible. Normalmente llama a una función de biblioteca para hacer cada TUR (sg_ll_test_unit_ready). Con esta opción, utiliza la interfaz sg_pt de nivel inferior (ver sg_pt.h) para ahorrar un poco de tiempo en cada TUR.
-n, --num=NUM
realiza TEST UNIT READY NUM veces. Si no se especifica, el valor predeterminado es 1. Se permiten los siguientes multiplicadores: c C *1; w W *2; b B *512; k K KiB *1,024; KB *1,000; m M MiB *1,048,576; MB *1,000,000; g G GiB *1,073,741,824; y GB *1,000,000,000. También un sufijo de la forma "x<n>" multiplica el número inicial por <n>. Alternativamente, se puede dar un número hexadecimal, prefijado con '0x' o con una 'h' al final.
--number=NUM
igual que --num=NUM. Añadido por compatibilidad con sg_requests y otras utilidades de este paquete. La utilidad sg_request ha asumido el papel de sondeo de la indicación de progreso que originalmente se asignó al comando TEST UNIT READY. Este es un cambio de T10.
-O, --old
Cambia a las opciones de estilo antiguo. Utilizar como primera opción.
-p, --progress
muestra la indicación de progreso (un porcentaje) si está disponible. Si se da --num=NUM, NUM es mayor que 1 y se detectó una indicación de progreso inicial, esta utilidad espera 30 segundos antes de las comprobaciones posteriores. Si se da la opción --delay=MS, esperará ese número de milisegundos en lugar de 30 segundos. Sale cuando se alcanza NUM o no quedan más indicaciones de progreso. Ignora la opción --time. Ver la sección NOTAS a continuación.
-t, --time
después de completar el número solicitado de comandos TEST UNIT READY, muestra la duración total y el número promedio de comandos ejecutados por segundo.
-T, --timeout=SE
donde SE es el tiempo de espera del comando para cada comando TEST UNIT READY. La unidad para SE son segundos y si se da 0, se mapea a 60 segundos, que es el valor predeterminado. Una forma alternativa de opción larga es --tmo=SE.
-v, --verbose
aumenta el nivel de verbosidad.
-V, --version
imprime la cadena de versión y sale.

NOTAS

La indicación de progreso es opcionalmente parte de los datos de sentido. Cuando un comando anterior que tarda mucho en completarse (y típicamente impide el acceso a otros medios) todavía está en curso, la indicación de progreso se puede utilizar para determinar cuánto tiempo antes de que el dispositivo vuelva a su estado normal. Alrededor de SPC-3, T10 cambió el comando preferido para sondeo de la indicación de progreso de TEST UNIT READY a REQUEST SENSE (ver la utilidad sg_requests).

El comando SCSI FORMAT para discos utilizados con el bit IMMED establecido es un ejemplo de una operación que requiere mucho tiempo y impide el acceso a otros medios durante ese tiempo. El bit IMMED establecido instruye al comando FORMAT a devolver el control al cliente de la aplicación una vez que el formato ha comenzado (ver SBC-3). Varios comandos SCSI de larga duración asociados con unidades de cinta también utilizan la indicación de progreso (ver SSC-3).

El DISPOSITIVO se abre con una bandera de solo lectura (por ejemplo, en Unix con la bandera O_RDONLY).

Los primeros estándares sugerían que el comando SCSI TEST UNIT READY se utilizara para sondeo de la indicación de progreso. Los estándares más recientes parecen sugerir que se utilice el comando SCSI REQUEST SENSE en su lugar.

ESTADO DE SALIDA

El estado de salida de sg_turs es 0 cuando tiene éxito (por ejemplo, en el caso de un disco mecánico, está girando y listo para aceptar comandos de E/S). Para esta utilidad, los otros valores de estado de salida de interés son 2, 12, 13 y 36. 12 es para el caso en que la clave de sentido sea "not ready" [0x2] y el código de sentido adicional termine con "Target port in standby state" [0x4, 0xb]. 13 es para el caso en que la clave de sentido sea "not ready" [0x2] y el código de sentido adicional sea "Target port in unavailable state" [0x4, 0xc]. El estado de salida 36 está asociado con la opción --ascq=ASC[,ASQ]. Todos los demás casos en que la clave de sentido sea "not ready" [0x2] establecerán el estado de salida en 2. Para otros valores de estado de salida, consulte la página del manual sg3_utils(8).

OPCIONES ANTIGUAS DE LA LÍNEA DE COMANDOS

Las opciones en esta sección eran las únicas disponibles antes de la versión 1.23 de sg3_utils. Desde entonces, esta utilidad utiliza por defecto las opciones de línea de comandos más nuevas, que se pueden anular utilizando --old (o -O) como primera opción. Consulte la sección VARIABLES DE ENTORNO para otra forma de forzar el uso de estas opciones de línea de comandos antiguas.

-d, --delay=MS
esta opción provoca un retraso de MS milisegundos antes de que se envíe cada comando TEST UNIT READY.
-n=NUM
realiza TEST UNIT READY NUM veces. Si no se especifica, el valor predeterminado es 1. Equivalente a --num=NUM en la descripción principal.
-N, --new
Cambia a las opciones de estilo más nuevas.
-p
muestra la indicación de progreso (un porcentaje) si está disponible. Equivalente a --progress en la descripción principal.
-t
después de completar el número solicitado de comandos TEST UNIT READY, muestra la duración total y el número promedio de comandos ejecutados por segundo. Equivalente a --time en la descripción principal.
-v
aumenta el nivel de verbosidad.
-V
imprime la cadena de versión y sale.

VARIABLES DE ENTORNO

Desde la versión 1.23 de sg3_utils se puede proporcionar la variable de entorno SG3_UTILS_OLD_OPTS. Cuando está presente, esta utilidad esperará las opciones de línea de comandos antiguas. Por lo tanto, la presencia de esta variable de entorno es equivalente a usar --old (o -O) como la primera opción de línea de comandos.
