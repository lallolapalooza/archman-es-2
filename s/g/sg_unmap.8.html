sg_unmap(8)

Paquete: sg3_utils

Licencias: GPL, custom:BSD

SG_UNMAP(8) SG3_UTILS SG_UNMAP(8)

NOMBRE

sg_unmap - envía un comando SCSI UNMAP (conocido como 'trim' en las especificaciones ATA)

SINOPSIS

sg_unmap [--all=ST,RN[,LA]] [--anchor] [--dry-run] [--force] [--grpnum=GN] [--help] [--in=ARCHIVO] [--lba=LBA,LBA...] [--num=NUM,NUM...] [--timeout=TO] [--verbose] [--version] DISPOSITIVO

DESCRIPCIÓN

Envía un comando SCSI UNMAP a DISPOSITIVO para desasignar uno o más bloques lógicos. Este comando se introdujo en la revisión 18 de SBC-3 bajo el encabezado general de "aprovisionamiento de bloques lógicos". Los bloques lógicos también pueden ser desasignados por el comando SCSI WRITE SAME; vea la utilidad sg_write_same. La capacidad de desasignación está estrechamente relacionada con el comando ATA DATA SET MANAGEMENT con el bit "Trim" activado.

Los bloques lógicos a desasignar se pueden especificar de una de las tres maneras a esta utilidad. Una forma es proporcionando las LBA de inicio a la opción '--lba=' y el número(s) correspondiente(s) a desasignar a la opción '--num='. Otra forma es colocando pares de LBA de inicio y número a desasignar en un archivo cuyo nombre se proporciona a la opción '--in='. Alternativamente, un segmento grande o todo un disco (SSD) se puede desasignar con la opción --all=ST_RN[,LA]. Todos los valores se asumen decimales a menos que vayan precedidos por "0x" (o "0X") o tengan una "h" (o "H") al final, en cuyo caso se interpretan como hexadecimales. Se permiten multiplicadores de sufijo en los valores decimales (por ejemplo, '--num=1m').

Cuando se proporciona la opción '--lba=', la opción '--num=' también debe proporcionarse. Si una tiene una lista separada por comas como argumento, la otra debe tener el mismo número de elementos en su lista. Los argumentos pueden usar un solo espacio como separador, pero deben estar entre comillas o escapados para que el shell no los malinterprete.

Con la opción '--in=ARCHIVO', se encontrará un número par de valores y se interpretarán como pares: el primer valor de cada par es una LBA de inicio y el segundo valor es el número a desasignar desde esa LBA. Todo desde y incluyendo un carácter '#' en una línea se ignora, al igual que las líneas en blanco. Los valores pueden estar separados por comas, espacios y tabulaciones o aparecer en líneas separadas. Cada línea no debe exceder los 1023 bytes de longitud.

Dado que se pueden perder muchos datos con esta utilidad, se proporciona un período de "enfriamiento" de 15 segundos antes de enviar cualquier comando UNMAP. Durante este período, se recuerda al usuario qué sucederá y a qué dispositivo, para que pueda usar control-C (o alguna otra técnica) para terminar esta utilidad antes de que ocurra cualquier desasignación. Este período se puede omitir con la opción --force.

OPCIONES

Los argumentos de las opciones largas son obligatorios para las opciones cortas también.

-A, --all=ST,RN[,LA]
donde ST es la LBA de inicio, RN es el número de repetición, que es el número máximo de bloques en cada comando SCSI UNMAP, y LA, si se proporciona, es la última LBA a desasignar. Si no se proporciona LA, se utiliza la última LBA en el DISPOSITIVO. Esto se obtiene mediante el comando SCSI READ CAPACITY.
-a, --anchor
establece el bit 'Anchor' en el comando (introducido en sbc3r22).
-d, --dry-run
realiza toda la preparación, incluyendo la apertura de DISPOSITIVO y el envío de un comando SCSI INQUIRY 'estándar' (y opcionalmente un READ CAPACITY), pero sale antes de realizar cualquier comando SCSI UNMAP.
-f, --force
omite el período de advertencia de 15 segundos que ocurre antes de enviar cualquier comando UNMAP.
-g, --grpnum=GN
establece el campo 'Group number' a GN. Por defecto es un valor de cero. GN debe ser un valor entre 0 y 63.
-h, --help
muestra el mensaje de uso y sale.
-I, --in=ARCHIVO
donde ARCHIVO es el nombre de un archivo que contiene pares de valores. El primer miembro de cada par es una LBA de inicio y el segundo miembro del par es el número de bloques lógicos a desasignar desde y incluyendo esa LBA de inicio. Los valores se interpretan como decimales a menos que se indique lo contrario. Esta opción no puede estar presente con la opción '--lba='.
-l, --lba=LBA,LBA...
donde LBA,LBA... es una cadena de valores separados por comas (o espacios) que se interpretan como direcciones de bloques lógicos de inicio. Cada número se interpreta como decimal a menos que vaya precedido por '0x' o '0X' (o tenga una 'h' o 'H' al final). Un argumento que contenga separadores de espacios debe ir entre comillas (o escaparse de otra manera). Cuando se proporciona esta opción, la opción '--num=' también debe proporcionarse y deben contener el mismo número de elementos en sus argumentos.
-n, --num=NUM,NUM...
donde NUM,NUM... es una cadena de valores separados por comas (o espacios) que se interpretan como un número de bloques lógicos a desasignar. Cada número se interpreta como decimal a menos que vaya precedido por '0x' o '0X' (o tenga una 'h' o 'H' al final). Tenga en cuenta que 0 bloques es aceptable. Un argumento que contenga separadores de espacios debe ir entre comillas (o escaparse de otra manera). Cuando se proporciona esta opción, la opción '--lba=' también debe proporcionarse y deben contener el mismo número de elementos en sus argumentos.
-t, --timeout=TO
donde TO es un valor de tiempo de espera (en segundos) para el comando UNMAP. El valor predeterminado es 60 segundos.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración).
-V, --version
imprime la cadena de versión y sale.

NOTAS

Algunos límites: una LBA puede tener hasta 64 bits, un NUM hasta 32 bits (impuesto por la estructura de los datos del comando UNMAP SCSI). El NUM está además limitado por el campo MAXIMUM UNMAP LBA COUNT en la página VPD BLOCK LIMITS (0xb0). El número máximo de pares LBA,NUM está limitado a 128 por esta utilidad y puede estar aún más limitado por el campo MAXIMUM UNMAP BLOCK DESCRIPTOR COUNT en la página VPD BLOCK LIMITS.

Dado que no está claro cuánto tiempo tardará el comando UNMAP en ejecutarse, se ha proporcionado la opción '--timeout='. El período de tiempo de espera predeterminado es de 60 segundos. Si se van a desasignar todos los bloques lógicos de una unidad lógica (por ejemplo, un disco duro), se puede considerar el comando SCSI FORMAT UNIT (consulte la utilidad sg_format) como una alternativa.

El soporte para el aprovisionamiento de bloques lógicos se indica mediante el bit LBPME en la respuesta al comando SCSI READ CAPACITY (16) (consulte la utilidad sg_readcap).

En la revisión 25 de SBC-3, se agregaron los bits LBPU y ANC_SUP a la página VPD Logical Block Provisioning. Cuando LBPU está activado, indica que el dispositivo soporta el comando UNMAP. Cuando el bit ANC_SUP está activado, indica que el dispositivo soporta LBAs ancladas.

El comando SCSI UNMAP hace lo "correcto" con respecto a la cola de comandos. Sin embargo, su contraparte ATA: el comando DATA SET MANAGEMENT con el bit "Trim" activado no interactúa bien con la cola SATA conocida como NCQ. Para abordar este problema, T13 ha introducido un nuevo comando llamado SFQ DATA SET MANAGEMENT que también tiene un bit Trim.

EJEMPLOS

En el directorio de ejemplos del paquete sg3_utils, hay un archivo sg_unmap_example.txt que muestra el formato que acepta la opción '--in='.

Para desasignar todos los bloques desde y incluyendo la LBA 0x2000 hasta el final del dispositivo (por ejemplo, disco o SSD) con cada comando SCSI UNMAP dando 1024 bloques para desasignar:


sg_unmap --all=0x2000,1k /dev/sg2

Agregue '--force' para omitir los 15 segundos de advertencias. Por lo tanto, '--force' es apropiado para archivos por lotes.

ESTADO DE SALIDA

El estado de salida de sg_unmap es 0 cuando tiene éxito. De lo contrario, consulte la página del manual de sg3_utils(8).
