NOMBRE

sg_rbuf - lee datos usando el comando SCSI READ BUFFER

SINOPSIS

sg_rbuf [--buffer=CADA] [--dio] [--help] [--mmap] [--quick] [--size=TOTAL] [--verbose] [--version] DISPOSITIVO

sg_rbuf [-b=CADA_KIB] [-d] [-m] [-q] [-s=TOTAL_MIB] [-t] [-v] [-V] DISPOSITIVO

DESCRIPCIÓN

Este comando lee datos con el comando SCSI READ BUFFER y luego los descarta. Típicamente, los datos que se leen provienen de la memoria caché de un disco. Se asume que los datos se obtienen rápidamente (aunque esto no está garantizado por los estándares SCSI) por lo que es más rápido que leer datos de los medios. Este comando está diseñado para cronometrar las velocidades de transferencia a través de un transporte SCSI.

Para obtener los datos con un comando SCSI READ BUFFER y opcionalmente decodificarlos, consulte la utilidad sg_read_buffer. También existe la utilidad sg_write_buffer, útil para descargar firmware entre otras cosas.

Esta utilidad admite dos sintaxis de línea de comandos; la preferida se muestra primero en la sinopsis y se explica en esta sección. Una sección posterior sobre la sintaxis de línea de comandos antigua describe el segundo grupo de opciones.

Esta es una utilidad exclusiva para Linux y solo funciona cuando DISPOSITIVO es un dispositivo sg (por ejemplo, "/dev/sg1"). La utilidad sg_read_buffer tiene funcionalidad similar y está portado a otros sistemas operativos, y dentro de Linux puede usar nombres de dispositivos de bloque normales y bsg (por ejemplo, "/dev/sdc").

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas.

-b, --buffer=CADA
donde CADA es el número de bytes que se transferirán por cada comando READ BUFFER. El valor predeterminado es el tamaño de búfer real disponible devuelto por el comando READ BUFFER (descriptor). El máximo es el mismo que el predeterminado, por lo tanto, este argumento solo se puede utilizar para reducir el tamaño de cada transferencia a menos que el tamaño real del búfer disponible del dispositivo.
-d, --dio
usa IO directo si está disponible. Esta opción solo está disponible si DISPOSITIVO es un nodo de dispositivo del controlador sg (por ejemplo, /dev/sg1). En este caso, el controlador sg intentará configurar el DMA desde el adaptador SCSI para transferir directamente a la memoria del usuario. Esto eliminará la copia a través de los búferes del kernel. Si no está disponible, se informará y se realizará IO indirecto en su lugar.
-h, --help
imprime el mensaje de uso y luego sale.
-m, --mmap
usa IO mapeado en memoria si está disponible. Esta opción solo está disponible si DISPOSITIVO es un nodo de dispositivo del controlador sg (por ejemplo, /dev/sg1). En este caso, el controlador sg intentará configurar el DMA desde el adaptador SCSI para transferir directamente a la memoria del usuario. Esto eliminará la copia a través de los búferes del kernel.
-O, --old
Cambia a las opciones de estilo antiguo. Por favor, úselo como la primera opción.
-q, --quick
solo transfiere los datos a los búferes del kernel (típicamente por DMA desde la tarjeta adaptadora SCSI) y no los mueve al espacio del usuario. Esta opción solo está disponible si DISPOSITIVO es un nodo de dispositivo del controlador sg (por ejemplo, /dev/sg1).
-s, --size=TOTAL
donde TOTAL es el tamaño de la transferencia total en bytes. El valor predeterminado es 200 MiB (200*1024*1024 bytes). El número real de bytes transferidos puede ser ligeramente menor que el solicitado, ya que todas las transferencias tienen el mismo tamaño (y se involucra una división entera que redondea hacia cero).
-t, --time
mide el componente de transferencia de datos masiva de este comando. Se imprime el tiempo transcurrido más un cálculo de MB/segundo. En este caso, "MB" son 1.000.000 de bytes. La llamada al sistema gettimeofday() se utiliza internamente para el cálculo del tiempo.
-v, --verbose
aumenta el nivel de verbosidad. Se puede usar varias veces.
-V, --version
imprime la cadena de versión y luego sale.

NOTAS

Este comando se usa típicamente en discos SCSI modernos que tienen una caché de RAM en su electrónica de unidad. Si no hay IO con los medios magnéticos, o dispositivos más lentos como memoria flash, involucrados, el disco puede ser capaz de obtener datos lo suficientemente rápido como para saturar el ancho de banda del transporte SCSI. El cuello de botella puede ser entonces el elemento DMA en la HBA, los controladores de Linux o el hardware de la máquina host (por ejemplo, la velocidad de la RAM).

Varios argumentos numéricos (por ejemplo, TOTAL) pueden incluir sufijos multiplicadores o darse en hexadecimal. Consulte la sección "ARGUMENTOS NUMÉRICOS" en la página del manual sg3_utils(8).

EJEMPLOS

En el sistema de prueba, /dev/sg0 corresponde a un disco rápido en un bus SCSI U2W (máximo 80 MB/segundo). Las especificaciones del disco indican que su caché es de 4 MB.
$ time ./sg_rbuf /dev/sg0
READ BUFFER informa: capacidad del búfer=3434944,
límite del desplazamiento=6
Leído 200 MiB (actual 199 MiB, 209531584 bytes),
tamaño del búfer=3354 KiB
real 0m5.072s, usuario 0m0.000s, sys 0m2.280s

Eso es aproximadamente 40 MB/segundo al 40% de utilización. Ahora, con la adición de la opción "-q", este rendimiento mejora y la utilización se reduce al 0%.
$ time ./sg_rbuf -q /dev/sg0
READ BUFFER informa: capacidad del búfer=3434944,
límite del desplazamiento=6
Leído 200 MiB (actual 199 MiB, 209531584 bytes),
tamaño del búfer=3354 KiB
real 0m2.784s, usuario 0m0.000s, sys 0m0.000s

ESTADO DE SALIDA

El estado de salida de sg_rbuf es 0 cuando tiene éxito. De lo contrario, consulte la página del manual sg3_utils(8).

OPCIONES DE LÍNEA DE COMANDOS ANTIGUAS

Las opciones de esta sección eran las únicas disponibles antes de la versión 1.23 de sg3_utils. Desde entonces, esta utilidad utiliza por defecto las opciones de línea de comandos más recientes que pueden ser anuladas usando --old (o -O) como la primera opción. Consulte la sección VARIABLES DE ENTORNO para otra forma de forzar el uso de estas opciones de línea de comandos antiguas.

-b=CADA_KIB
donde CADA_KIB es el número de Kilobytes (es decir, unidades de 1024 bytes) que se transferirán por cada comando READ BUFFER. Similar a la opción --buffer=CADA en la descripción principal, pero las unidades son diferentes.
-d
usa IO directo si está disponible. Equivalente a la opción --dio en la descripción principal.
-m
usa IO mapeado en memoria si está disponible. Equivalente a la opción --mmap en la descripción principal.
-N, --new
Cambia a las opciones de estilo más nuevo.
-q
solo transfiere los datos a los búferes del kernel (típicamente por DMA desde la tarjeta adaptadora SCSI) y no los mueve al espacio del usuario. Equivalente a la opción --quick en la descripción principal.
-s=TOTAL_MIB
donde TOTAL_MIB es el tamaño de la transferencia total en Megabytes (1048576 bytes). Similar a la opción --size=TOTAL en la descripción principal, pero las unidades son diferentes.
-t
mide el componente de transferencia de datos masiva de este comando. Equivalente a la opción --time en la descripción principal.
-v
aumenta el nivel de verbosidad. Se puede usar varias veces.
-V
imprime la cadena de versión y luego sale.

VARIABLES DE ENTORNO
