NOMBRE

sg_copy_results - envía el comando SCSI RECEIVE COPY RESULTS (relacionado con XCOPY)

SINOPSIS

sg_copy_results [--failed|--params|--receive|--status] [--help] [--hex] [--list_id=ID] [--readonly] [--verbose] [--version] [--xfer_len=BTL] DEVICE

DESCRIPCIÓN

Esta utilidad está diseñada para consultar el estado de la instalación SCSI Extended Copy (XCOPY) (ver SPC-3 revisión 23 secciones 6.3 y 6.17), presente en algunos arrays de almacenamiento modernos. Esta utilidad envía un comando SCSI RECEIVE COPY RESULTS al DEVICE dado y muestra la respuesta.

Durante las fases de borrador de SPC-4, el comité T10 ha expandido el comando XCOPY para que ahora tenga dos variantes: "LID1" (para una longitud de Identificador de Lista de 1 byte) y "LID4" (para una longitud de Identificador de Lista de 4 bytes). Esta utilidad soporta la variante más antigua, LID1, que también se encuentra en SPC-3 y anteriores. Aunque la variante LID1 en SPC-4 es compatible a nivel de comando (binario) con XCOPY tal como se define en SPC-3, algunos de los nombres de los comandos han cambiado. Esta utilidad utiliza los nombres más antiguos de SPC-3 XCOPY.

El comando tiene cuatro modos de operación distintos, distinguidos por el campo de acción del servicio:

ESTADO DE COPIA [SPC-4: RECEIVE COPY STATUS(LID1)]
Muestra el estado actual del comando EXTENDED COPY identificado por el campo del id de lista.
DATOS DE RECEPCIÓN [SPC-4: RECEIVE COPY DATA(LID1)]
Devuelve los datos retenidos leídos por el comando EXTENDED COPY identificado por el campo del id de lista. Esta opción solo es significativa si se soportan los descriptores de segmento respectivos.
PARÁMETROS DE OPERACIÓN [SPC-4: RECEIVE COPY OPERATING PARAMETERS]
Devuelve los parámetros de operación del gestor de copias. Esta opción también es útil para determinar si se soporta la instalación SCSI Extended Copy.
DETALLES DEL SEGMENTO FALLIDO [SPC-4: RECEIVE COPY FAILURE DETAILS(LID1)]
Devuelve los datos de sentido del dispositivo de destino de la copia y otra información sobre cualquier segmento fallido.

OPCIONES

Los argumentos de las opciones largas son obligatorios también para las opciones cortas.

-f, --failed
establece el campo de acción del servicio a DETALLES DEL SEGMENTO FALLIDO [4].
-h, --help
muestra el mensaje de uso y luego sale.
-H, --hex
imprime el buffer de respuesta en hexadecimal.
-l, --list_id=ID
establece el campo del identificador de lista a ID (por defecto: 0).
-p, --params
establece el campo de acción del servicio a PARÁMETROS DE OPERACIÓN [3]. Este es el valor por defecto.
-R, --readonly
abre el DEVICE en modo de solo lectura (por ejemplo, en Unix con la bandera O_RDONLY). El valor por defecto es abrirlo en modo lectura-escritura.
-r, --receive
establece el campo de acción del servicio a DATOS DE RECEPCIÓN [1].
-s, --status
establece el campo de acción del servicio a ESTADO DE COPIA [0].
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración).
-V, --version
imprime la cadena de versión y luego sale.
-x, --xfer_len=BTL
establece el campo de longitud de asignación a BTL. Es la longitud de transferencia de bytes y es el tamaño máximo (en bytes) de la respuesta. BTL debe ser menor que 10000 y por defecto es 520.

NOTAS

La decodificación de la acción del servicio RECEIVE DATA no está implementada.

De manera similar, la funcionalidad de sg_xcopy se ha portado a la utilidad más general ddpt (y paquete), la funcionalidad de esta utilidad se ha portado a la utilidad ddptctl.

EJEMPLOS

Consulta los parámetros de operación para un dispositivo:

# sg_copy_results -p /dev/sdo
Recibir resultados de copia (informar parámetros de operación):
No soporta identificador de lista: no
Número máximo de descriptores de destino: 2
Número máximo de descriptores de segmento: 1
Longitud máxima de lista de descriptores: 92 bytes
Longitud máxima de segmento: 33553920 bytes
Datos en línea no soportados
Límite de datos retenidos: 0 bytes
Tamaño máximo de transferencia de dispositivo de flujo: 0 bytes
Copias concurrentes totales: 0
Copias concurrentes máximas: 255
Granularidad del segmento de datos: 512 bytes
Granularidad de datos en línea: 1 bytes
Granularidad de datos retenidos: 1 bytes
Lista de descriptores implementada:
Descriptor de segmento 0x02: Copia de dispositivo de bloque a dispositivo de bloque
Descriptor de destino 0xe4: Descriptor de identificación

ESTADO DE SALIDA

El estado de salida de sg_copy_results es 0 cuando tiene éxito. En caso contrario, consulta la página del manual sg3_utils(8).
