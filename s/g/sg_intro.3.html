NOMBRE

sg_intro - obtener estadísticas del sistema

SINOPSIS

#include <statgrab.h>

DESCRIPCIÓN

La biblioteca statgrab proporciona una interfaz multiplataforma para obtener estadísticas del sistema. Cada una de las llamadas a funciones para obtener estadísticas devuelve una matriz de estructuras. Las funciones que devuelven un número fijo de entradas de matriz (típicamente una) no tomarán un parámetro adicional para almacenar el número de entradas de matriz; otras lo harán. De todos modos, si la información ya no está disponible, puede llamar a sg_get_nelements(). Consulte la página del manual de cada función individual para obtener más detalles sobre el uso.

Para cada tipo de estadística hay dos funciones disponibles para obtener los datos: sg_get_STATTYPE (por ejemplo, sg_get_cpu_stats) y sg_get_STATTYPE_r (por ejemplo, sg_get_cpu_stats_r). La diferencia entre ambas interfaces es la propiedad de las estructuras de estadísticas devueltas: mientras que el (conocido) sg_get_cpu_stats devuelve un puntero a un área de memoria propiedad y controlada por la biblioteca statgrab, sg_get_cpu_stats_r devolverá un puntero a un área de memoria propiedad y controlada por el llamador. El almacenamiento propiedad de la biblioteca statgrab se reutilizará en llamadas posteriores a la misma función de obtención de estadísticas dentro del mismo hilo. La memoria se libera cuando el hilo termina. Esto podría resultar en punteros colgantes al intercambiar estos punteros entre hilos. El almacenamiento propiedad del llamador debe ser liberado por el llamador cuando ya no se utilice.

sg_init() debe ser la primera función que llame antes de comenzar a usar libstatgrab; realiza todas las operaciones de inicialización únicas que requieren privilegios setuid/setgid. Por ejemplo, en *BSD abre un descriptor para poder leer estructuras del kernel más tarde, y en Solaris lee los mapeos de dispositivos que en algunos casos solo son accesibles por root (máquinas con un /dev/osa). Para manejar esto, cada módulo statgrab tiene una rutina de inicialización privada llamada por sg_init(). sg_init() toma un argumento para indicar si los errores de inicialización de los componentes deben abortar el proceso de inicialización de la biblioteca o no. Independientemente de este valor, las inicializaciones de módulos fallidas generalmente conducirán a estadísticas (parcialmente) inutilizables. Una vez que sg_init() se ha ejecutado, la mayoría de las otras funciones de libstatgrab ya no necesitan privilegios elevados (algunos Unices requieren privilegios más altos para acceder a los argumentos de la línea de comandos de procesos propiedad de otros usuarios, Linux no entrega información de algunas tarjetas de red a usuarios no privilegiados, etc.). Por lo tanto, es una buena idea llamar a sg_drop_privileges(), que descarta los privilegios setuid y setgid, inmediatamente después de llamar a sg_init(), a menos que su aplicación tenga una razón para necesitar privilegios setuid o setgid.

sg_shutdown() debe ser la última función de la biblioteca statgrab que llame. No debe invocar esta función cuando todavía exista algún hilo que haya realizado llamadas a la biblioteca statgrab. Si no invoca sg_shutdown(), se realiza automáticamente at_exit().

Tanto sg_init() como sg_shutdown() utilizan un contador para evitar la destrucción prematura de libstatgrab en un proceso donde más de un componente utiliza libstatgrab. Este contador está protegido por un semáforo de exclusión mutua cuando se incluyen capacidades de hilo.

sg_init(), sg_shutdown() y sg_drop_privileges() devuelven SG_ERROR_NONE en caso de éxito y cualquier otro valor en caso de fallo.

Para un soporte de hilos adecuado, están disponibles sg_lock_mutex() y sg_unlock_mutex() para permitir el bloqueo de funciones del sistema que no son seguras para hilos. Si bien, en general, no es la idea más sensata mezclar llamadas a la biblioteca statgrab y llamadas similares a la biblioteca del sistema, es posible proteger funciones conocidas como no seguras. Actualmente, hay una API del sistema conocida por no ser segura para hilos: el acceso a utmp. La otra funcionalidad no segura para hilos utilizada por la biblioteca statgrab es la gestión global de componentes durante la inicialización (por ejemplo, contar el número de llamadas a sg_init() para evitar que la primera llamada a sg_shutdown() deje la biblioteca en un estado inutilizable).

Nombre del mutex: statgrab
Protege: globales de la biblioteca statgrab

Nombre del mutex: utmp
Protege: acceso a registros de inicio de sesión

Actualmente no hay forma de obtener una lista de nombres de mutex utilizados, así que ruegue que cualquier autor que añada más semáforos para proteger implementaciones sea lo suficientemente justo como para añadirlos aquí.

La práctica prevista es que cada vez que se llame a una función de libstatgrab y posteriormente falle, se establecerá un error apropiado. Por favor, utilice sg_get_error() y sus asociados para informarse sobre las circunstancias individuales de la condición de error.
