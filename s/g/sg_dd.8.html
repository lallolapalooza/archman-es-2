Paquete: sg3_utils

SG_DD(8) SG3_UTILS SG_DD(8)

NOMBRE

sg_dd - copia datos hacia y desde archivos, especialmente dispositivos SCSI

SINOPSIS

sg_dd [bs=BS] [conv=CONV] [count=COUNT] [ibs=BS] [if=IFILE] [iflag=FLAGS] [obs=BS] [of=OFILE] [oflag=FLAGS] [seek=SEEK] [skip=SKIP] [--help] [--verbose] [--version]

[blk_sgio={0|1}] [bpt=BPT] [cdbsz={6|10|12|16}] [cdl=CDL] [coe={0|1|2|3}] [coe_limit=CL] [dio={0|1}] [odir={0|1}] [of2=OFILE2] [retries=RETR] [sync={0|1}] [time={0|1}[,TO]] [verbose=VERB] [--dry-run] [--progress] [--verify]

DESCRIPCIÓN

Copia datos hacia y desde cualquier archivo. Especializado para "archivos" que son dispositivos genéricos SCSI (sg) de Linux, dispositivos raw u otros dispositivos que soportan el ioctl SG_IO (que solo se encuentran en la serie 2.6 del kernel de Linux). Sintaxis y semántica similar al comando dd(1).

El primer grupo en la sinopsis anterior son operandos "estándar" de dd(1) de Unix. El segundo grupo son opciones adicionales añadidas por esta utilidad.

Cuando se proporciona la opción --verify, el lado de lectura es el mismo, pero en el lado de escritura, el comando SCSI WRITE se reemplaza por el comando SCSI VERIFY. Si algún comando VERIFY produce una clave de sentido (sense key) de MISCOMPARE, la operación de verificación se detendrá. La opción --verify solo se puede usar cuando OFILE es un dispositivo sg o un dispositivo de bloque con 'oflag=sgio' también dado. Cuando se usa la opción --verify, esta utilidad funciona de manera similar al comando cmp(1) de Unix.

Esta utilidad solo se admite en Linux, mientras que la mayoría de las otras utilidades del paquete sg3_utils han sido portadas a otros sistemas operativos. Una utilidad llamada "ddpt" tiene una sintaxis y funcionalidad similar a sg_dd. ddpt omite algunas características específicas de Linux mientras añade algunas otras características genéricas. Esto permite que ddpt sea portado a otros sistemas operativos.

Para el soporte de dispositivos de almacenamiento NVMe, consulte la sección a continuación titulada: SOPORTE NVME.

OPCIONES

blk_sgio={0|1}
cuando se establece en 0, los dispositivos de bloque (por ejemplo, /dev/sda) se tratan como archivos normales (es decir, se utilizan read(2) y write(2) para IO). Cuando se establece en 1, se supone que los dispositivos de bloque aceptan el ioctl SG_IO y se emiten comandos SCSI para IO. Esto solo es compatible con kernels de la serie 2.6. Tenga en cuenta que los dispositivos ATAPI (por ejemplo, reproductores de CD/DVD) utilizan el conjunto de comandos SCSI, pero los discos ATA no (a menos que haya una conversión de protocolo, como ocurre a menudo en la clase de almacenamiento masivo USB). Si el dispositivo de entrada o salida es una partición de dispositivo de bloque (por ejemplo, /dev/sda3), establecer esta opción hace que se ignore la información de la partición (ya que el acceso es directamente al dispositivo subyacente). El valor predeterminado es 0. Consulte la bandera 'sgio'.
bpt=BPT
cada transacción de IO se realizará utilizando BPT bloques (o menos si está cerca del final de la copia). El valor predeterminado es 128 para tamaños de bloque lógicos menores de 2048 bytes, de lo contrario, el valor predeterminado es 32. Por lo tanto, para bs=512, las lecturas y escrituras transportarán 64 KiB de datos por defecto (menos si está cerca del final de la transferencia o por restricciones de memoria). Cuando se accede a unidades de CD/DVD, el tamaño de bloque lógico suele ser de 2048 bytes y bpt tiene un valor predeterminado de 32, lo que nuevamente implica transferencias de 64 KiB. La capa de bloques cuando se utiliza la opción blk_sgio=1 tiene límites superiores relativamente bajos para los tamaños de transferencia (en comparación con los nodos de dispositivos sg, consulte /sys/block/<nombre_dev>/queue/max_sectors_kb).
bs=BS
donde BS **debe** ser el tamaño de bloque lógico del dispositivo físico (si los archivos de entrada o salida se acceden a través de comandos SCSI). Tenga en cuenta que esto difiere de dd(1), que permite que BS sea un múltiplo integral. El valor predeterminado es 512, que normalmente es correcto para discos, pero incorrecto para CD-ROM (que normalmente tienen bloques de 2048 bytes). Para esta utilidad, el tamaño máximo de cada operación de IO individual es BS * BPT bytes.
cdbsz={6|10|12|16}
tamaño de los bloques de comandos SCSI READ y/o WRITE emitidos en nombres de dispositivos sg (o dispositivos de bloque cuando se usa 'iflag=sgio' y/o 'oflag=sgio'). El valor predeterminado es bloques de comandos SCSI de 10 bytes (a menos que los cálculos indiquen que se puede exceder un número de bloque de 4 bytes o que BPT es mayor que 16 bits (65535), en cuyo caso se utiliza por defecto comandos SCSI de 16 bytes).
cdl=CDL
permite establecer límites de duración de comandos. CDL es un valor único o dos valores separados por una coma. Si se proporciona un valor, se aplica tanto a IFILE como a OFILE (si son dispositivos de paso). Si se proporcionan dos valores, el primero se aplica a IFILE mientras que el segundo se aplica a OFILE. El valor puede ser de 0 a 7, donde 0 es el valor predeterminado y significa que no hay límites de duración de comandos. Los límites de duración de comandos solo son soportados por comandos READ y WRITE de 16 bytes (más READ(32), WRITE(32) y el comando WRITE SCATTERED, pero son utilizados por esta utilidad). Si no se proporciona el operando cdbsz y tendría un valor inferior a 16, entonces, si CDL es mayor que 0, cdbsz se incrementa a 16.
Los límites de duración de comandos se pueden acceder y cambiar en las páginas de modo A y B de límites de duración de comandos, además de las páginas de modo T2A y T2B de límites de duración de comandos. La utilidad sdparm se puede utilizar para acceder y cambiar estas páginas de modo.
coe={0|1|2|3}
establecer en 1 o más para continuar ante errores ('coe'). Solo se aplica a errores en dispositivos sg o dispositivos de bloque con la bandera 'sgio' activada. Por lo tanto, los errores en otros archivos detendrán sg_dd. El valor predeterminado es 0, lo que implica detenerse ante cualquier error. Consulte la bandera 'coe' para obtener más información.
coe_limit=CL
donde CL es el número máximo de bloques defectuosos consecutivos ignorados (debido a "coe>0") en las lecturas antes de que la copia termine. Esto solo se aplica cuando IFILE se accede a través del ioctl SG_IO. El valor predeterminado es 0, que se interpreta como sin límite. Esta opción está destinada a detener la copia poco después de detectar medios no grabados, mientras se ofrece la capacidad de "continuar ante errores".
conv=sparse
consulte la sección CONVERSIONES a continuación.
count=COUNT
copia COUNT bloques desde IFILE a OFILE. El valor predeterminado es el número mínimo (de IFILE y OFILE) de bloques que los dispositivos sg informan desde los comandos SCSI READ CAPACITY o que los dispositivos de bloque (o sus particiones) informan. Los archivos normales no se sondean para conocer su tamaño. Si se dan skip=SKIP o seek=SEEK y el recuento se deriva (es decir, no se proporciona explícitamente), el recuento derivado se ajusta para que la copia no exceda el dispositivo. Si el nombre del archivo es una partición de dispositivo de bloque y COUNT no se proporciona, se utiliza el tamaño de la partición en lugar del tamaño del dispositivo completo. Si COUNT no se proporciona (o count=-1) y no se puede derivar, se emite un mensaje de error y no se realiza ninguna copia.
dio={0|1}
el valor predeterminado es 0, que selecciona IO indirecto (en caché) en dispositivos sg. Un valor de 1 intenta IO directo que, si no está disponible, recurre a IO indirecto y lo indica al completarse. Si se selecciona IO directo y /sys/module/sg/parameters/allow_dio tiene el valor 0, se emite una advertencia (y se realiza IO indirecto). Para un control más detallado, use 'iflag=dio' o 'oflag=dio'.
ibs=BS
si se proporciona, debe ser el mismo que BS dado a la opción 'bs='.
if=IFILE
lee desde IFILE en lugar de stdin. Si IFILE es '-', se lee desde stdin. Comienza a leer desde el principio de IFILE a menos que se proporcione SKIP.
iflag=FLAGS
donde FLAGS es una lista separada por comas de una o más banderas descritas a continuación. Estas banderas están asociadas con IFILE y se ignoran cuando IFILE es stdin.
obs=BS
si se proporciona, debe ser el mismo que BS dado a la opción 'bs='.
odir={0|1}
El valor predeterminado es 0 (IO indirecto). Un valor de 1 intenta IO directo (direct IO) en dispositivos sg. Si no está disponible, recurre a IO indirecto y lo indica al completarse. Si se selecciona IO directo y /sys/module/sg/parameters/allow_dio tiene el valor 0, se emite una advertencia (y se realiza IO indirecto). Para un control más detallado, use 'oflag=dio'.
of=OFILE
escribe en OFILE en lugar de stdout. Si OFILE es '-', se escribe en stdout. Si OFILE es un dispositivo sg, la escritura se realiza de forma predeterminada con el comando SCSI WRITE. Si OFILE es un dispositivo de bloque y se usa 'oflag=sgio', el comando SCSI WRITE se usa para la escritura. Si se proporciona la opción '--verify', el comando SCSI WRITE se reemplaza por el comando SCSI VERIFY. Si no se da SEEK, la escritura comienza en el primer bloque o sector del archivo. Si el archivo de salida es un dispositivo sg o un dispositivo de bloque con 'oflag=sgio', el tamaño del bloque se establece en el tamaño de bloque lógico del dispositivo (obtenido mediante un comando SCSI READ CAPACITY). Si el archivo de salida es un archivo regular, el tamaño del bloque es el dado a la opción 'bs='. Los archivos normales que reciben escrituras son creados si no existen, o truncados a cero si existen.
of2=OFILE2
esto permite escribir los mismos datos que en OFILE, pero también en OFILE2. Esto se implementa emitiendo los mismos comandos SCSI de escritura o verificación a ambos dispositivos. Si se da la opción --verify, ambos archivos se verificarán.
oflag=FLAGS
donde FLAGS es una lista separada por comas de una o más banderas descritas a continuación. Estas banderas se asocian con OFILE y se ignoran si OFILE es stdout.
retries=RETR
número de reintentos en caso de errores de IO. Solo se aplica a los errores en dispositivos sg o dispositivos de bloque con la bandera 'sgio' activada. Por lo tanto, los errores en otros archivos detendrán sg_dd. El valor predeterminado es 0 (sin reintentos).
seek=SEEK
donde SEEK es el número de bloques desde el principio de OFILE para comenzar a escribir. Si OFILE es un dispositivo sg o un dispositivo de bloque con 'oflag=sgio', entonces SEEK se interpreta como un número de bloques (y no de bytes). La operación de búsqueda es posible solo si OFILE se abre en modo de acceso aleatorio (es decir, no en modo de solo lectura, y no es un archivo regular que debe crearse).
skip=SKIP
donde SKIP es el número de bloques para omitir desde el principio de IFILE. Si IFILE es un dispositivo sg o un dispositivo de bloque con 'iflag=sgio', entonces SKIP se interpreta como un número de bloques (y no de bytes).
sync={0|1}
cuando se establece en 1, se emite una llamada de sincronización después de cada escritura. Esto asegura que los datos se escriban físicamente en el medio de almacenamiento, pero puede ralentizar significativamente la operación.
time= {0|1}[,TO]
cuando se establece en 1, se imprimen estadísticas de rendimiento (velocidad de transferencia y tiempo total) al final de la operación. Si se proporciona un valor opcional TO (separado por una coma), se utilizará como el tiempo máximo de espera en segundos para la operación general (que puede ser útil para limitar el tiempo total de ejecución de una copia larga). Los tiempos de espera para comandos individuales se controlan con la opción 'cdl'.
verbose=VERB
cuando se establece en 1 o más, se imprimen mensajes de depuración. Un valor de 2 o más implica más detalles.
--dry-run
muestra las acciones que se realizarían sin ejecutar realmente ninguna operación de E/S.
--help
imprime el mensaje de uso y sale.
--progress
imprime una barra de progreso en la terminal. Esto solo se puede hacer de forma fiable para operaciones de larga duración.
--verify
consulte la sección DESCRIPCIÓN.
--version
imprime la versión de la utilidad y sale.

FLAGS

dio
intenta usar IO directo.
sgio
realiza la E/S utilizando comandos SCSI en el dispositivo de bloque dado. Esto solo es aplicable a los dispositivos de bloque de Linux y solo es válido para kernels de la serie 2.6 y posteriores. Si se usa junto con 'blk_sgio=0', esta opción tiene prioridad y se utiliza el método sg predeterminado.
direct
sinónimo de 'dio'.
sync
garantiza que los datos se escriban en el medio de almacenamiento antes de que se considere completada la operación de escritura.
nocache
intenta evitar el uso de la caché del sistema de archivos.
direct_io
sinónimo de 'dio'.
dsync
equivalente a 'sync' pero solo para datos, no para metadatos.
parallel
para dispositivos sg, usa un segundo hilo para enviar comandos. Esto puede ser útil para mejorar el rendimiento en algunos casos, pero puede causar problemas de concurrencia en otros.
fua
para dispositivos sg, establece la bandera FUA (Force Unit Access) en los comandos de escritura SCSI. Esto garantiza que los datos se escriban en el medio de almacenamiento, omitiendo cualquier caché en el dispositivo.
verify
para dispositivos sg, utiliza el comando SCSI VERIFY en lugar de WRITE. Esto verifica que los datos escritos en el medio coinciden con los datos enviados, pero no realmente escribe los datos.
fullblock
para dispositivos sg, solo se procesan bloques completos. Si el último bloque es incompleto, se ignora.
append
para dispositivos sg, añade datos al final del archivo o dispositivo. Esto solo se puede utilizar si el dispositivo de destino admite la operación de añadir (por ejemplo, una unidad de cinta).
nobar
suprime la visualización de la barra de progreso.

CONVERSIONS

Se admite la siguiente conversión:

sparse
si se lee un bloque de entrada que consta enteramente de ceros, no se escribe ningún bloque de salida para él; el archivo de salida se acorta en consecuencia. Esto solo se aplica a archivos de salida regulares. El valor predeterminado es que los bloques cero se escriben como bloques cero.

NVME SUPPORT

Los dispositivos NVMe (Non-Volatile Memory Express) se pueden manejar utilizando la opción sg(1) o la opción equivalente de dispositivo de bloque sgio. Para usar esta utilidad con un dispositivo NVMe, el dispositivo debe ser accesible a través de la interfaz de dispositivo genérico SCSI de Linux (que se logra montando el dispositivo NVMe con la opción scsi_mod.allow_dg=1 en el módulo sg). El nombre del dispositivo NVMe suele ser algo como /dev/nvme0n1 o similar.

Por ejemplo, para hacer una copia de seguridad de un dispositivo NVMe, puede usar:

sg_dd if=/dev/nvme0n1 of=/path/to/backup.img bs=4K \ iflag=sgio,direct oflag=sgio,direct cdl=1

En este ejemplo:

  • if=/dev/nvme0n1: especifica el dispositivo NVMe de origen.
  • of=/path/to/backup.img: especifica el archivo de destino para la copia de seguridad.
  • bs=4K: establece el tamaño del bloque en 4 Kibibytes. Ajuste esto según sea necesario para optimizar el rendimiento.
  • iflag=sgio,direct: indica que la E/S de entrada se realizará a través de la interfaz sg, utilizando E/S directa si es posible.
  • oflag=sgio,direct: indica que la E/S de salida se realizará a través de la interfaz sg, utilizando E/S directa si es posible.
  • cdl=1: establece un límite de duración de comando de 1 segundo para las operaciones de lectura y escritura. Ajuste esto según sea necesario para las operaciones de su dispositivo NVMe.

**Nota**: Asegúrese de que el módulo sg pueda acceder a su dispositivo NVMe. Es posible que deba cargar el módulo con parámetros específicos o asegurarse de que el dispositivo NVMe esté configurado correctamente en el sistema.

EJEMPLOS

Para crear una imagen de un disco duro (por ejemplo, /dev/sdb) en un archivo llamado disk.img:

sg_dd if=/dev/sdb of=disk.img bs=4M

Para escribir una imagen de disco (disk.img) en un disco duro (por ejemplo, /dev/sdc):

sg_dd if=disk.img of=/dev/sdc bs=4M

Para copiar datos desde un dispositivo CD/DVD (por ejemplo, /dev/sr0) a un archivo, asegurándose de usar el tamaño de bloque correcto para los CD/DVD (2048 bytes):

sg_dd if=/dev/sr0 of=cd_image.iso bs=2048

Para realizar una copia de seguridad de un dispositivo de cinta (por ejemplo, /dev/st0) en un archivo, omitiendo los primeros 10 bloques (por ejemplo, para saltarse el espacio libre al principio de la cinta):

sg_dd if=/dev/st0 of=tape_backup.img bs=1M skip=10

Para verificar si los datos escritos en un dispositivo sg (por ejemplo, /dev/sg0) coinciden con los datos de un archivo (data.bin):

sg_dd if=data.bin of=/dev/sg0 --verify

Para continuar la copia desde un dispositivo sg incluso si se encuentran errores de lectura (por ejemplo, sectores defectuosos), hasta un máximo de 5 errores consecutivos, y luego detenerse:

sg_dd if=/dev/sdX of=backup.img coe=1 coe_limit=5

OPTIONS

odir={0|1}
cuando se establece en uno, abre dispositivos de bloque (por ejemplo, /dev/sda) con la bandera O_DIRECT. Los búferes de memoria del usuario se alinean al tamaño de página cuando se establece. El valor predeterminado es 0 (es decir, la bandera O_DIRECT no se utiliza). No tiene efecto en archivos sg, normales o sin formato. Si blk_sgio también está configurado, se honran ambos: los dispositivos de bloque se abren con la bandera O_DIRECT y los comandos SCSI se emiten a través del ioctl SG_IO.
of=OFILE
escribir en OFILE en lugar de stdout. Si OFILE es '-' entonces escribe en stdout. Si OFILE es /dev/null entonces no se realizan escrituras reales. Si OFILE es . (punto) entonces se trata de la misma manera que /dev/null (esta es una notación abreviada). Si OFILE existe, NO se trunca; se sobrescribe desde el principio de OFILE a menos que se indique 'oflag=append' o SEEK.
of2=OFILE2
escribe la salida en OFILE2. La acción predeterminada es no realizar esta escritura adicional (es decir, cuando no se proporciona esta opción). Se asume que OFILE2 es un archivo normal o un fifo (es decir, una tubería con nombre). OFILE2 se abre para escritura, se crea si es necesario y se cierra al final de la transferencia. Si OFILE2 es un fifo (tubería con nombre), entonces otro comando debería estar consumiendo esos datos (por ejemplo, 'md5sum OFILE2'), de lo contrario, esta utilidad se bloqueará.
oflag=FLAGS
donde FLAGS es una lista separada por comas de una o más banderas descritas a continuación. Estas banderas están asociadas con OFILE y se ignoran cuando OFILE es /dev/null, . (punto) o stdout.
retries=RETR
a veces los reintentos en el host son útiles, por ejemplo, cuando hay un error de transporte. Cuando RETR es mayor que cero, entonces las lecturas y escrituras SCSI se reintentan en caso de error, RETR veces. El valor predeterminado es cero.
seek=SEEK
comienza a escribir bloques de tamaño bs SEEK desde el principio de OFILE. El valor predeterminado es el bloque 0 (es decir, el principio del archivo).
skip=SKIP
comienza a leer bloques de tamaño bs SKIP desde el principio de IFILE. El valor predeterminado es el bloque 0 (es decir, el principio del archivo).
sync={0|1}
cuando es 1, realiza el comando SYNCHRONIZE CACHE en OFILE al final de la transferencia. Solo activo cuando OFILE es un nombre de archivo de dispositivo sg o un dispositivo de bloque y se proporciona 'blk_sgio=1'.
time={0|1}[,TO]
cuando es 1, mide el tiempo de la transferencia y calcula el rendimiento, mostrando los resultados (en stderr) al finalizar. Cuando es 0 (predeterminado) no realiza la medición del tiempo.
Si ese valor va seguido de una coma, entonces TO es el tiempo de espera del comando en segundos para los comandos SCSI READ, WRITE o VERIFY emitidos por esta utilidad. El valor predeterminado es 60 segundos.
verbose=VERB
a medida que VERB aumenta, también lo hace la cantidad de salida de depuración enviada a stderr. El valor predeterminado es cero, que produce la cantidad mínima de salida de depuración. Un valor de 1 informa información adicional que no es repetitiva. Un valor de 2 informa cdbs y respuestas para comandos SCSI que no son repetitivos (es decir, distintos de READ y WRITE). El procesamiento de errores no se considera repetitivo. Los valores de 3 y 4 producen salida para todos los comandos SCSI (y llamadas de lectura y escritura de Unix), por lo que puede haber mucha salida. Esto solo ocurre para dispositivos genéricos SCSI (sg) y dispositivos de bloque cuando se establece la opción 'blk_sgio=1'.
-d, --dry-run
realiza todo el análisis y preparación de la línea de comandos, pero omite la copia o lectura real. Esa preparación puede incluir abrir IFILE u OFILE para determinar sus longitudes. Esta opción puede ser útil para probar la sintaxis de invocaciones complejas de línea de comandos antes de ejecutarlas.
-h, --help
muestra el mensaje de uso y sale.
-p, --progress
esta opción causa que se muestre un informe de progreso cada dos minutos hasta que la copia se complete. Después de que la copia se complete, se imprime una línea con "completed" para distinguir el informe final de los informes de progreso anteriores. Cuando se usa dos veces, el informe de progreso es cada minuto, cuando se usa tres veces, el informe de progreso es cada 30 segundos.
Si se proporciona esta opción, la opción 'time=1' se establece implícitamente.
-v, --verbose
cuando se usa una vez, es equivalente a verbose=1. Cuando se usa dos veces (por ejemplo, "-vv") es equivalente a verbose=2, etc.
-x, --verify
realiza una operación de verificación (como el comando Unix cmp(1)) en lugar de una copia. No se puede usar con "oflag=sparse". Se debe proporcionar of=OFILE y OFILE debe ser un dispositivo sg o un dispositivo de bloque con "oflag=sgio" también proporcionado. Utiliza el comando SCSI VERIFY con el campo BYTCHK establecido en 1. El comando VERIFY se usa en lugar de WRITE cuando se proporciona esta opción. No existe el comando VERIFY(6). Se detiene en la primera discrepancia a menos que se proporcione 'oflag=coe'.
-V, --version
muestra la información del número de versión y sale.

CONVERSIONES

Se pueden proporcionar una o más conversiones a la opción "conv=". Si se proporcionan más de una, deben estar separadas por comas. sg_dd no realiza las conversiones tradicionales de dd (por ejemplo, ASCII a EBCDIC). Las conversiones añadidas recientemente se superponen parcialmente con las banderas, por lo que algunas conversiones ahora son compatibles con sg_dd.

nocreat
esta conversión tiene el mismo efecto que "oflag=nocreat", a saber: OFILE debe existir, no se creará.
noerror
esta conversión es muy similar a "iflag=coe" y se trata como tal. Ver la bandera "coe". Tenga en cuenta que un error en OFILE detendrá la copia.
notrunc
esta conversión se acepta por compatibilidad con dd y se ignora, ya que la acción predeterminada de esta utilidad es no truncar OFILE.
null
no tiene efecto, solo un marcador de posición.
sparse
FreeBSD admite "conv=sparse", por lo que se admite la misma sintaxis en sg_dd. Ver "sparse" en la sección FLAGS para más información.
sync
es ignorada por sg_dd. Con dd significa suministrar relleno de ceros (en lugar de omitir) y se usa típicamente de esta manera "conv=noerror,sync" para tener la misma funcionalidad que "iflag=coe" de sg_dd.

BANDERA

Aquí hay una lista de banderas y sus significados:

00
esta bandera solo está activa con iflag= y cuando se proporciona reemplaza if=IFILE. Si se proporcionan ambas, se genera un error. La entrada será un flujo de ceros, similar a usar "if=/dev/zero" solo (pero un poco más rápido), aparte del siguiente caso.
Si se proporciona 'iflag=00,ff', la dirección del bloque (32 bits inferiores, en 4 bytes, big endian) se coloca, varias veces, en cada bloque. La dirección del bloque tiene en cuenta la configuración de skip=SKIP. La utilidad sgp_dd tiene una opción --chkaddr que complementa esta opción.
append
causa que la bandera O_APPEND se agregue a la apertura de OFILE. Para archivos regulares, esto conducirá a que los datos se añadan al final de cualquier dato existente. No se puede usar junto con la opción seek=SEEK ya que entran en conflicto. La acción predeterminada de esta utilidad es sobrescribir cualquier dato existente desde el principio del archivo o, si se proporciona SEEK, comenzando en el bloque SEEK. Tenga en cuenta que intentar "añadir" a un archivo de dispositivo (por ejemplo, un disco) generalmente se ignorará o puede causar un error.
coe
continuar en caso de error. Solo activo para dispositivos sg y dispositivos de bloque que tienen configurada la bandera 'sgio'. 'iflag=coe oflag=coe' y 'coe=1' son equivalentes. Use esta bandera dos veces (por ejemplo, 'iflag=coe,coe') para tener la misma acción que 'coe=2'. Un error de medio, hardware o comprobación en blanco al leer volverá a leer los bloques anteriores al bloque defectuoso, luego intentará recuperar el bloque defectuoso, proporcionando ceros si falla, y finalmente volverá a leer los bloques posteriores al bloque defectuoso. Un error de medio, hardware o comprobación en blanco al escribir se anota y se ignora. Una clave de sentido de desajuste durante un comando VERIFY (es decir, se proporciona --verify) se anota y se ignora cuando 'oflag=coe'. La recuperación del bloque defectuoso al leer utiliza el comando SCSI READ LONG si 'coe' se proporciona dos o más veces (también con la opción de línea de comandos 'coe=2'). Además, READ LONG establecerá su bit CORRCT si 'coe' se proporciona tres veces. Los discos SCSI pueden intentar reasignar automáticamente sectores defectuosos (consulte AWRE y ARRE en la página de modo de recuperación de errores de lectura/escritura (la utilidad sdparm puede acceder y posiblemente cambiar estos atributos)). Los errores que ocurren en otros tipos de archivos detendrán sg_dd. Los mensajes de error se envían a stderr. Esta bandera es similar a 'conv=noerror,sync' en la utilidad dd(1). Ver nota sobre READ LONG a continuación.
dio
solicita que el nodo del dispositivo sg asociado con esta bandera realice E/S directa. Si la E/S directa no está disponible, recurre a E/S indirecta y lo anota al finalizar. Si se selecciona E/S directa y /sys/module/sg/parameters/allow_dio tiene el valor 0, se emite una advertencia (y se realiza E/S indirecta).
direct
causa que la bandera O_DIRECT se agregue a la apertura de IFILE y/o OFILE. Esta bandera requiere cierta alineación de memoria en la E/S. Por lo tanto, los búferes de memoria del usuario se alinean al tamaño de página. No tiene efecto en archivos sg, normales o sin formato. Si también se establece 'iflag=sgio' y/o 'oflag=sgio', se honran ambos: los dispositivos de bloque se abren con la bandera O_DIRECT y los comandos SCSI se emiten a través del ioctl SG_IO.
dpo
establece el bit DPO (desactivar paginación) en los comandos SCSI READ y WRITE. No compatible con variantes de 6 bytes de CDB de READ y WRITE. Indica que es poco probable que los datos permanezcan en la caché del dispositivo (por ejemplo, disco). Puede acelerar la copia de medios.

OPTIONS

direct
causes O_DIRECT flag to be added to the open of IFILE and/or OFILE. This bypasses the kernel buffer cache, potentially increasing I/O performance on large transfers to/from devices like disk drives, but potentially decreasing performance on transfers to and from regular files. It may also reduce the impact that a media copy has on other device users.
dsync
causes the O_SYNC flag to be added to the open of IFILE and/or OFILE. The 'd' is prepended to lower confusion with the 'sync=0|1' option which has another action (i.e. a synchronisation to media at the end of the transfer).
excl
causes the O_EXCL flag to be added to the open of IFILE and/or OFILE.
ff
this flag is only active with iflag= and when given replaces if=IFILE. If both are given an error is generated. The input will be a stream of 0xff bytes (or all bits set), apart from the following case.
If 'iflag=00,ff' is given then the block address (lower 32 bits, in 4 bytes, big endian) is placed, multiple times, in each block. The block address takes into account the skip=SKIP setting.
flock
after opening the associated file (i.e. IFILE and/or OFILE) an attempt is made to get an advisory exclusive lock with the flock() system call. The flock arguments are "FLOCK_EX | FLOCK_NB" which will cause the lock to be taken if available else a "temporarily unavailable" error is generated. An exit status of 90 is produced in the latter case and no copy is done.
fua
causes the FUA (force unit access) bit to be set in SCSI READ and/or WRITE commands. This only has an effect with sg devices or block devices that have the 'sgio' flag set. The 6 byte variants of the SCSI READ and WRITE commands do not support the FUA bit.
nocache
use posix_fadvise() to advise corresponding file there is no need to fill the file buffer with recently read or written blocks.
nocreat
this flag is only active in oflag=FLAGS. If present then OFILE will be opened if it exists. If OFILE doesn't exist then an error is generated. Without this flag a regular (empty) file named OFILE will be created (and then filled). For production quality scripts where OFILE is a device node (e.g. '/dev/sdc') this flag is recommended. It guards against the remote possibility of 'dev/sdc' disappearing temporarily (e.g. a USB memory key removed) resulting in a large regular file called '/dev/sdc' being created.
null
has no affect, just a placeholder.
pt
has the same meaning as the sgio flag. Added for compatibility with the ddpt utility.
random
this flag is only active with iflag= and when given replaces if=IFILE. If both are given an error is generated. The input will be a stream of pseudo random bytes. The Linux getrandom(2) system call is used to create a seed and there after mrand48(3) is used to generate a pseudo random sequence, 4 bytes at a time. The quality of the randomness can be viewed with the ent(1) utility. This is not a high quality random number generator, it is built for speed, not quality. One application is checking the correctness of the copy and verify operations of this utility.
sgio
causes block devices to be accessed via the SG_IO ioctl rather than standard UNIX read() and write() commands. When the SG_IO ioctl is used the SCSI READ and WRITE commands are used directly to move data. sg devices always use the SG_IO ioctl. This flag offers finer grain control compared to the otherwise identical 'blk_sgio=1' option.
sparse
after each BS * BPT byte segment is read from the input, it is checked for being all zeros. If so, nothing is written to the output file unless this is the last segment of the transfer. This flag is only active with the oflag option. It cannot be used when the output is not seekable (e.g. stdout). It is ignored if the output file is /dev/null . Note that this utility does not remove the OFILE prior to starting to write to it. Hence it may be advantageous to manually remove the OFILE if it is large prior to using oflag=sparse. The last segment is always written so regular files will show the same length and so programs like md5sum and sha1sum will generate the same value regardless of whether oflag=sparse is given or not. This option may be used when the OFILE is a raw device but is probably only useful if the device is known to contain zeros (e.g. a SCSI disk after a FORMAT command).

RETIRED OPTIONS

Here are some retired options that are still present:

append=0 | 1
when set, equivalent to 'oflag=append'. When clear the action is to overwrite the existing file (if it exists); this is the default. See the 'append' flag.
fua=0 | 1 | 2 | 3
force unit access bit. When 3, fua is set on both IFILE and OFILE; when 2, fua is set on IFILE;, when 1, fua is set on OFILE; when 0 (default), fua is cleared on both. See the 'fua' flag.

NOTES

Block devices (e.g. /dev/sda and /dev/hda) can be given for IFILE. If neither '-iflag=direct', 'iflag=sgio' nor 'blk_sgio=1' is given then normal block IO involving buffering and caching is performed. If only '-iflag=direct' is given then the buffering and caching is bypassed (this is applicable to both SCSI devices and ATA disks). If 'iflag=sgio' or 'blk_sgio=1' is given then the SG_IO ioctl is used on the given file causing SCSI commands to be sent to the device and that also bypasses most of the actions performed by the block layer (this is only applicable to SCSI devices, not ATA disks). The same applies for block devices given for OFILE.

Various numeric arguments (e.g. SKIP) may include multiplicative suffixes or be given in hexadecimal. See the "NUMERIC ARGUMENTS" section in the sg3_utils(8) man page.

The COUNT, SKIP and SEEK arguments can take 64 bit values (i.e. very big numbers). Other values are limited to what can fit in a signed 32 bit number.

Data usually gets to the user space in a 2 stage process: first the SCSI adapter DMAs into kernel buffers and then the sg driver copies this data into user memory (write operations reverse this sequence). This is called "indirect IO" and there is a 'dio' option to select "direct IO" which will DMA directly into user memory. Due to some issues "direct IO" is disabled in the sg driver and needs a configuration change to activate it. This is typically done with 'echo 1 > /sys/module/sg/parameters/allow_dio'.

All informative, warning and error output is sent to stderr so that dd's output file can be stdout and remain unpolluted. If no options are given, then the usage message is output and nothing else happens.

Even if READ LONG succeeds on a "bad" block when 'coe=2' (or 'coe=3') is given, the recovered data may not be useful. There are no guarantees that the user data will appear "as is" in the first 512 bytes.

A raw device must be bound to a block device prior to using sg_dd. See raw(8) for more information about binding raw devices. To be safe, the sg device mapping to SCSI block devices should be checked with sg_map before use.

Disk partition information can often be found with fdisk(8) [the "-ul" argument is useful in this respect].

For sg devices (and block devices when blk_sgio=1 is given) this utility issues SCSI READ and WRITE (SBC) commands which are appropriate for disks and reading from CD/DVD/HD-DVD/BD drives. Those commands are not formatted correctly for tape devices so sg_dd should not be used on tape devices. If the largest block address of the requested transfer exceeds a 32 bit block number (i.e 0xffff) then a warning is issued and the sg device is accessed via SCSI READ(16) and WRITE(16) commands.

The attributes of a block device (partition) are ignored when 'blk_sgio=1' is used. Hence the whole device is read (rather than just the second partition) by this invocation:


sg_dd if=/dev/sdb2 blk_sgio=1 of=t bs=512

NVME SUPPORT

Some support for copying from and to NVMe devices in Linux have been added. There are two varieties of NVME "char" devices, examples: /dev/nvme<cid> and /dev/ng<cid>n<nsid> where <cid> is the controller identifier (starting at 0) and <nsid> is the NVMe namespace identifier (starting at 1). The latter form is called "nvme-generic" in /proc/devices . The NVMe block devices have the form: /dev/nvme<cid>n<nsid>[p<part_id>] where the optional <part_id> is the partition identifier (starting at 1). In the case of NVMe block devices the default action of sg_dd is to access them using standard Unix IO (i.e. read(2) or write(2)). To access them using SCSI/NVMe commands, the flag "sgio" or "pt" needs to be given (e.g. iflag=pt if=/dev/nvme0n1 ).

Just as with partitions on SCSI disks, it is dangerous to access NVMe partitions (e.g. iflag=pt if=/dev/nvme0n1p2) using a pass-through interface. The reason is that both SCSI and NVMe commands are oblivious to any partitioning arrangement which Linux (or any other OS) has set up on those disks. In other words, in the above example the "p2" at the end of if=/dev/nvme0n1p2 is ignored when a pass-through is being used.

The READ and WRITE commands in NVMe are in the "NVM" command set which requires a NVMe namespace to be specified. This means that the char device /dev/nvme0 is not useful for the utility, only administrative commands can be sent to it. That leaves the /dev/ng<cid>n<nsid> as the only NVMe "char" device that can be used with this utility. Since it is not a block device, the standard Unix read(2) and write(2) will not work with it; so the pass-through interface, issuing SCSI/NVMe commands, is assumed by this utility.

EJEMPLOS

Su uso es bastante similar a dd:


sg_dd if=/dev/sg0 of=t bs=512 count=1MB

Esto copiará un millón de bloques de 512 bytes del dispositivo asociado con /dev/sg0 (que debería tener bloques de 512 bytes) a un archivo llamado t. Suponiendo que /dev/sda y /dev/sg0 son el mismo dispositivo, entonces lo anterior es equivalente a:


dd if=/dev/sda iflag=direct of=t bs=512 count=1000000

aunque la velocidad de dd puede mejorar si bs fuera mayor y count se redujera adecuadamente. El uso de la opción 'iflag=direct' omite el almacenamiento en búfer y la caché que normalmente se realiza en un dispositivo de bloques.

Usando un dispositivo sin procesar para hacer algo similar en un disco ATA:


raw /dev/raw/raw1 /dev/hda
sg_dd if=/dev/raw/raw1 of=t bs=512 count=1MB

Para copiar una partición de disco SCSI a una partición de disco ATA:


raw /dev/raw/raw2 /dev/hda3
sg_dd if=/dev/sg0 skip=10123456 of=/dev/raw/raw2 bs=512

Esto asume que se encuentra una partición válida en el disco SCSI en la dirección de bloque de salto dada (pasando el punto de 5 GB de ese disco) y que la partición llega hasta el final del disco SCSI. Un conteo explícito es probablemente una opción más segura. La partición se copia a /dev/hda3, que es un desplazamiento dentro del disco ATA /dev/hda. El número exacto de bloques leídos de /dev/sg0 se escriben en /dev/hda (es decir, sin relleno).

Para medir el tiempo de una lectura en streaming del primer GB (2 ** 30 bytes) en un disco, se podría usar esta utilidad:


sg_dd if=/dev/sg0 of=/dev/null bs=512 count=2m time=1

Al finalizar, se mostrará una línea como: "el tiempo de transferencia de datos fue de 18.779506 segundos, 57.18 MB/seg". El "MB/seg" en este caso es 1.000.000 de bytes por segundo.

La opción 'of2=' se puede usar para copiar datos y obtener su md5sum sin necesidad de volver a leer los datos:


mkfifo fif
md5sum fif &
sg_dd if=/dev/sg3 iflag=coe of=sg3.img oflag=sparse of2=fif bs=512

Esto creará una imagen de /dev/sg3 (por ejemplo, un disco desmontado) y colocará el contenido en el archivo (disperso) sg3.img. Sin volver a leer los datos, también realizará un cálculo md5sum sobre la imagen.

SEÑALES

El manejo de señales se ha tomado prestado de dd: SIGINT, SIGQUIT y SIGPIPE muestran el número de bloques restantes por transferir y los recuentos de registros de entrada + salida; luego tienen su acción predeterminada. SIGUSR1 causa que se muestre la misma información, pero la copia continúa. Toda la salida causada por señales se envía a stderr.

ESTADO DE SALIDA

El estado de salida de sg_dd es 0 cuando tiene éxito. De lo contrario, consulte la página del manual sg3_utils(8). Dado que esta utilidad funciona a un nivel superior al de los comandos individuales, y existen las banderas 'coe' y 'retries', los fallos individuales de comandos SCSI no causan necesariamente la salida del proceso.

Se genera un estado de salida adicional de 90 si se proporciona la bandera flock y otro proceso mantiene el bloqueo exclusivo consultivo.
