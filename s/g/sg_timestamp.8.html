NOMBRE

sg_timestamp - informa o establece la marca de tiempo en un dispositivo SCSI

SINOPSIS

sg_timestamp [--elapsed] [--help] [--hex] [--milliseconds=MS] [--no-timestamp] [--origin] [--raw] [--readonly] [--seconds=SECS] [--srep] [--verbose] [--version] DISPOSITIVO

DESCRIPCIÓN

Envía un comando SCSI REPORT TIMESTAMP o SET TIMESTAMP al DISPOSITIVO. Estos comandos se encuentran en el borrador del estándar SPC-5, revisión 7 (spc5r07.pdf).

Si se proporciona la opción --milliseconds=MS o --seconds=SECS (y no ambas), se envía el comando SET TIMESTAMP; de lo contrario, se envía el comando REPORT TIMESTAMP.

La marca de tiempo se envía y se recibe del DISPOSITIVO como el número de milisegundos desde la época del 1970-01-01 00:00:00 UTC y se almacena en un entero sin signo de 48 bits. La misma época se utiliza en máquinas Unix, pero normalmente almacenan el número de segundos desde esa época. El comando date de Unix y especialmente su formato ""+%s"" son útiles para convertir marcas de tiempo a y desde formas más legibles por humanos. Consulte la sección EJEMPLOS a continuación.

Una utilidad complementaria llamada sg_sat_datetime con opciones similares está disponible para acceder o establecer la fecha y hora en un dispositivo ATA (típicamente un disco SATA). sg_sat_datetime emite comandos ATA a través de la capa SCSI a ATA Translation (SAT).

OPCIONES

Los argumentos para las opciones largas son obligatorios para las opciones cortas también.

-e, --elapsed
asume que la marca de tiempo en REPORT TIMESTAMP es un tiempo transcurrido desde un evento como un ciclo de encendido o un reinicio forzado y formatea la salida como '<n> días hh:mm:ss.xxx' donde hh son las horas (00 a 23 inclusive); mm son los minutos (00 a 59 inclusive); ss son los segundos (00 a 59 inclusive) y xxx son los milisegundos (000 a 999 inclusive). Si el número de días es 0, entonces '0 días' no se muestra a menos que esta opción se proporcione dos o más veces.
-h, --help
muestra el mensaje de uso y luego sale.
-H, --hex
muestra la respuesta a REPORT TIMESTAMP en hexadecimal ASCII en stderr. La respuesta no se decodifica.
-m, --milliseconds=MS
donde MS es el número de milisegundos desde el 1970-01-01 00:00:00 UTC para establecer en el DISPOSITIVO con el comando SCSI SET TIMESTAMP.
-N, --no-timestamp
cuando se llama a REPORT TIMESTAMP, esta opción suprime la salida del valor de la marca de tiempo (en segundos o milisegundos). Esto puede ser útil para despejar la salida al intentar decodificar el origen de la marca de tiempo (ver la opción --origin).
-o, --origin
los datos del parámetro devuelto por REPORT TIMESTAMP contienen un campo de "origen de la marca de tiempo". Cuando se proporciona esta opción, ese campo se decodifica y se imprime antes de que se muestre el valor de la marca de tiempo. La acción predeterminada (es decir, cuando no se proporciona la opción) es no imprimir este campo decodificado.
T10 define este campo como "el evento más reciente que inicializó el reloj del dispositivo devuelto". El valor 0 indica que un reinicio forzado al encender inicializó el reloj; 2 indica que un SET TIMESTAMP inicializó el reloj, mientras que 3 indica que algún otro método inicializó el reloj.
Cuando se usa una vez, se muestra una cadena descriptiva (en una línea antes del valor de la marca de tiempo). Cuando se usa dos veces, se muestra el valor del campo TIMESTAMP ORIGIN (en decimal, un valor entre 0 y 7 inclusive). Cuando se usa tres veces, se muestra una línea de la forma 'TIMESTAMP_ORIGIN=<valor>'.
-r, --raw
muestra la respuesta SCSI REPORT TIMESTAMP (es decir, el búfer de datos de salida) en binario (a stdout). Tenga en cuenta que las opciones --origin y --srep se ignoran cuando se proporciona esta opción. Además, todos los mensajes de error y verbosos se muestran en stderr.
-R, --readonly
abre el DISPOSITIVO en modo de solo lectura. La acción predeterminada es abrir el DISPOSITIVO en modo de lectura-escritura.
-s, --seconds=SECS
donde SECS es el número de segundos desde el 1970-01-01 00:00:00 UTC para establecer en el DISPOSITIVO con el comando SCSI SET TIMESTAMP. SECS se multiplica por 1000 antes de usarse en el comando SET TIMESTAMP.
-S, --srep
informa el número de segundos desde el 1970-01-01 00:00:00 UTC. Esto se hace dividiendo por 1000 el valor devuelto por el comando SCSI REPORT TIMESTAMP.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración).
-V, --version
imprime la cadena de versión y luego sale.

VALOR DE SALIDA

El valor de salida de sg_timestamp es 0 cuando tiene éxito. De lo contrario, consulte la página del manual de sg3_utils(8).

NOTAS

Los bits TCMOS y SCSIP en la página de modo de extensión de Control (ver sdparm) modifican las acciones de la marca de tiempo mantenida por un DISPOSITIVO.

Actualmente, solo los parámetros de "Utilización de la tasa de uso basada en fecha y hora" dentro de la página de registro de Utilización (sbc4r09.pdf) usan marcas de tiempo. Consulte la utilidad sg_logs. Los comandos y páginas específicos del proveedor también pueden estar utilizando marcas de tiempo.

EJEMPLOS

En máquinas Unix (por ejemplo, Linux, FreeBSD y Solaris), el comando date es útil cuando se trabaja con marcas de tiempo.

Para obtener la marca de tiempo de un DISPOSITIVO y mostrarla en un formato legible por humanos, se podría usar lo siguiente:


# sg_timestamp -S /dev/sdb
1448993950
# date --date=@1448993950
Tue Dec 1 13:19:10 EST 2015
# date -R --date="@1448993950"
Tue, 01 Dec 2015 13:19:10 -0500

Los dos últimos comandos de fecha muestran diferentes formas de la misma fecha (es decir, 1448993950 segundos desde el 1970-01-01 00:00:00 UTC). sg_timestamp y el comando date se pueden combinar usando comillas simples:


# date -R --date=@`sg_timestamp -S /dev/sdc`
Wed, 16 Dec 2015 20:12:59 -0500

Para establecer la marca de tiempo en el DISPOSITIVO a ahora (aproximadamente), se podría usar lo siguiente:


# date +%s
1448993955
# sg_timestamp --seconds=1448993955 /dev/sdb

Esas dos líneas de comando se podrían combinar en una usando comillas simples:


# sg_timestamp --seconds=`date +%s` /dev/sdb
