NOMBRE

sg_wr_mode - escribir (modificar) página de modo SCSI

SINOPSIS

sg_wr_mode [--cfile=CF] [--contents=H,H...] [--dbd] [--force] [--help] [--len=10|6] [--mask=M,M...] [--page=PG_H[,SPG_H]] [--raw] [--rtd] [--save] [--six] [--verbose] [--version] DISPOSITIVO

DESCRIPCIÓN

Escribe una página de modo modificada en DISPOSITIVO. Usa el comando SCSI MODE SENSE (variante de 6 u 8 bytes) para obtener los datos de modo existentes, que incluyen una página (o subpágina) de modo. Luego la combina con los contenidos, potencialmente enmascarados, y escribe la página de modo modificada con el comando SCSI MODE SELECT (variante de 6 u 8 bytes). Esta utilidad no modifica los descriptores de bloque; si se obtienen descriptores de bloque por el comando MODE SENSE, entonces los mismos descriptores de bloque se escriben de nuevo con el siguiente comando MODE SELECT.

Si se proporciona la opción --rtd, la mayoría de las otras opciones aparte de --save, --len=10|6 y --six se ignoran. En este caso, solo se envía un comando MODE SELECT al DISPOSITIVO con el bit RTD (Revert To Defaults) activado. Este bit se añadió a este comando en la revisión 11 de SPC-5, por lo que los dispositivos más antiguos pueden no soportarlo. La página de consulta extendida VPD tiene el bit RTD_SUP para indicar si el DISPOSITIVO soporta el bit RTD en los comandos MODE SELECT (6 y 10). Cuando se proporciona la opción --rtd, el resto de esta sección puede ignorarse.

Si no se proporciona una opción de contenidos, se imprimen los diversos componentes (es decir, cabecera, descriptores de bloque y página de modo) de los valores "actuales" de la página de modo existente. En este caso, la página de modo no se altera en el dispositivo.

Si se especifican los contenidos y no se especifica una máscara, los contenidos deben coincidir con la página de modo existente en varios aspectos, a menos que se proporcione la opción --force. Estos incluyen la longitud, el código de página de modo y el código de subpágina si es aplicable. Si todo está bien, la cadena de contenidos se escribe en DISPOSITIVO como la nueva página de modo.

Si se especifican tanto contenidos como máscara, solo se toman las posiciones de bits en los contenidos correspondientes a bits activados en la máscara, mientras que la página de modo existente proporciona las posiciones de bits correspondientes a bits desactivados. Cuando se da una máscara, la máscara y/o los contenidos pueden ser más cortos que la página de modo existente. Si la máscara es más corta que los contenidos, los bytes restantes se toman de los contenidos. Si los contenidos son más cortos que la página de modo existente, los bytes restantes se toman de la página de modo existente.

La opción force permite que la cadena de contenidos se tome como la nueva página de modo sin ninguna comprobación previa de la página de modo existente. Esto solo debería ser necesario para páginas de modo específicas del proveedor. Los datos de modo existentes se ignoran aparte de los descriptores de bloque, que pueden suprimirse con la opción --dbd si fuera necesario.

Cambiar campos individuales en una página de modo es probablemente más fácil de hacer con la utilidad sdparm. Los campos pueden identificarse por acrónimo o por un descriptor numérico.

OPCIONES

Los argumentos de las opciones largas son obligatorios también para las opciones cortas.

-C, --cfile=CF
donde CF es un nombre de archivo que contiene la página de modo. Consulte la sección "FORMATOS HEX, BINARIO Y JSON" en la página del manual de sg3_utils para más información. Si también se proporciona la opción --raw, el contenido de FN se trata como binario.
-c, --contents=H,H...
donde H,H... es una cadena de números hexadecimales separados por comas, cada uno de los cuales debe resolverse en un valor de byte (es decir, de 0 a ff inclusive). También se permite una cadena (única) de números hexadecimales separados por espacios, pero la lista debe ir entre comillas. Estos son los nuevos contenidos de la página de modo que se escribirán en DISPOSITIVO, potencialmente filtrados por la cadena de máscara.
-c, --contents=-
lee la cadena de contenidos desde stdin. Consulte la opción --cfile=CF arriba.
-d, --dbd
desactivar descriptores de bloque (bandera DBD en cdb). Algunos tipos de dispositivos incluyen descriptores de bloque en los datos de modo devueltos por un comando MODE SENSE. Si es así, los mismos descriptores de bloque se escriben con el comando MODE SELECT. Esta opción instruye al comando MODE SENSE a no devolver ningún descriptor de bloque. Esto sería un valor predeterminado sensato para esta utilidad, aparte del hecho de que no todos los dispositivos SCSI soportan el bit DBD en el cdb.
-f, --force
fuerza que la cadena de contenidos se tome como la nueva página de modo, o al menos no realiza comprobaciones en la página de modo existente. Tenga en cuenta que DISPOSITIVO aún puede rechazar los nuevos contenidos para la página de modo. No se puede proporcionar con la opción --mask=M,M....
-h, --help
muestra el mensaje de uso y sale.
-l, --len=10 | 6
longitud de los comandos SCSI (cdb) enviados a DISPOSITIVO. El valor predeterminado es 10, por lo que se emiten comandos MODE SENSE y MODE SELECT de 10 bytes. Algunos dispositivos antiguos no soportan las variantes de 10 bytes, de ahí esta opción.
-m, --mask=M,M...
donde M,M... es una cadena de números hexadecimales separados por comas, cada uno de los cuales debe resolverse en un valor de byte (es decir, de 0 a ff inclusive). También se permite una cadena (única) de números hexadecimales separados por espacios, pero la lista debe ir entre comillas. La máscara elige (bit a bit) si la nueva página de modo proviene de los contenidos (bit de máscara activado) o de la página de modo existente (bit de máscara desactivado). Si la cadena de máscara es más corta que la cadena de contenidos, los bytes restantes se toman de la cadena de contenidos. Si la cadena de contenidos es más corta que la página de modo existente, los bytes restantes se toman de la página de modo existente (es decir, se dejan inalterados).
-p, --page=PG_H
donde PG_H es el valor del código de página a obtener y modificar. El código de página está en hexadecimal y debe estar entre 0 y 3e inclusive. Tenga en cuenta que el código de página 3f para obtener todas las páginas de modo está desautorizado.
-p, --page=PG_H,SPG_H
donde PG_H es el valor del código de página y SPG_H es el valor del código de subpágina a obtener y modificar. Ambos valores están en hexadecimal. El código de subpágina debe estar entre 0 y fe inclusive. Tenga en cuenta que el código de subpágina ff para obtener todas las subpáginas de modo (para una página de modo dada o todas las páginas de modo en el caso de 3f,ff) está desautorizado.
-r, --raw
cuando se proporciona esta opción, el archivo dado por la opción --cfile=CF se trata como binario (el valor predeterminado es tratarlo como hexadecimal ASCII).
-R, --rtd
cuando se proporciona esta opción, la mayoría de las otras acciones se omiten y se envía un comando MODE SELECT(6 o 10) al DISPOSITIVO con el bit RTD activado. Esto hará que todos los valores actuales (y los valores guardados si también se proporciona la opción --save) de todas las páginas de modo vuelvan a sus valores predeterminados.
-s, --save
cambia la página de modo "guardada" cuando MODE SELECT tiene éxito. Por defecto (es decir, cuando no se usa --save) solo se cambian los valores "actuales" de la página de modo cuando MODE SELECT tiene éxito. En este caso, la nueva página de modo permanecerá en vigor hasta que el dispositivo se reinicie (por ejemplo, se apague y vuelva a encender). Cuando se reinicie, se restablecerán los valores "guardados" para la página de modo. Por lo tanto, para hacer cambios permanentes, use la opción --save.
Cuando se usa con la opción --rtd, tanto los valores actuales como los guardados en cada página de modo se revertirán a sus valores predeterminados. En ausencia de la opción --save, solo se revertirán los valores actuales de cada página de modo a sus valores predeterminados.
-6, --six
esta opción hará que se usen las variantes de 6 bytes de los comandos MODE SENSE y MODE SELECT. El valor predeterminado es usar las opciones de 10 bytes. Esta opción es equivalente a usar la opción --len=6.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración).
-V, --version
imprime la cadena de versión y luego sale.

EJEMPLOS

Para mostrar la página de modo 1 (código de página 0x01) de un disco SCSI (suponiendo que el disco está en /dev/sda):

sg_wr_mode --page=1 /dev/sda

Para mostrar la página de modo 1, subpágina 1 (códigos de página 0x01, 0x01) de un disco SCSI:

sg_wr_mode --page=1,1 /dev/sda

Para cambiar el bit 7 de la página de modo 1 del disco /dev/sda a 1:

sg_wr_mode --page=1 --contents=80 /dev/sda

Para cambiar el bit 7 de la página de modo 1 del disco /dev/sda a 1, pero solo si el bit 0 está actualmente en 0 (enmascaramiento):

sg_wr_mode --page=1 --contents=80 --mask=01 /dev/sda

Para obtener la página de modo 1, su contenido en un archivo llamado p1.hex, y luego usarla para cambiar la página de modo 1 del disco /dev/sda:

sg_rd_mode --page=1 /dev/sda > p1.hex
sg_wr_mode --page=1 --cfile=p1.hex --save /dev/sda

Para revertir todos los modos a sus valores predeterminados en el disco /dev/sda:

sg_wr_mode --rtd --save /dev/sda

NOTAS

Esta utilidad no comprueba si la cadena de contenido intenta modificar partes de la página de modo que sean modificables. El dispositivo debería hacer eso y, si alguna parte no es modificable, debería informar: "Campo inválido en la lista de parámetros".

Algunas páginas de modo no son guardables. Si es así, un intento de usar la opción --save debería causar un error informado por el dispositivo: "Campo ilegal en cdb".

Se requiere que el dispositivo realice varias comprobaciones antes de aceptar una nueva página de modo. Si estas comprobaciones fallan, la página de modo no se altera y el dispositivo devuelve un error de "error de longitud de lista de parámetros" o "campo inválido en lista de parámetros" en los datos de sentido.

La forma recomendada de modificar una página de modo es leerla con MODE SENSE, modificar alguna parte de ella y luego escribirla de nuevo en el dispositivo con un comando MODE SELECT. Por ejemplo, leer una página de modo existente se puede lograr con 'sg_modes -p=1a -r /dev/sdb > mp_1a.txt' (la página de modo de condición de potencia). El archivo mp_1a.txt se puede editar y luego usar como cadena de contenido para esta utilidad (por ejemplo, 'sg_wr_mode -p 1a -s -c - /dev/sdb < mp_1a.txt').

Dos campos difieren entre lo que se lee del dispositivo con MODE SENSE y lo que se escribe en el dispositivo con MODE SELECT: la longitud de los datos del modo está reservada (es decir, ceros) en un comando MODE SELECT, mientras que el bit PS (bit 7 del byte 0 de la subpágina) en cada modo (sub)página está reservado (cero) en un comando MODE SELECT. El bit PS proporcionado en la cadena de contenido se pone a cero a menos que se seleccione la opción --force.

EJEMPLOS

Esta utilidad se puede utilizar junto con la utilidad sg_modes. Para restablecer los valores predeterminados de la página de modo (es decir, los valores de la página de modo elegidos por el fabricante del dispositivo) como valores de página de modo actuales y guardados, se podría usar la siguiente secuencia:


$ sg_modes --control=2 --page=1a -r /dev/sda > t


$ sg_wr_mode --page=1a --contents=- --save /dev/sda < t

A continuación se muestra un ejemplo de uso de una máscara para modificar el "contador de condición de inactividad" de la página de modo "condición de potencia" (0x1a) de 0x28 a 0x37. Tenga en cuenta que el cambio no se guarda, por lo que el "contador de condición de inactividad" volverá a ser 0x28 después del próximo ciclo de energía. La salida de sg_modes está abreviada.


$ sg_modes --page=1a /dev/hdc
>> Condición de potencia (mmc), page_control: actual
00 1a 0a 00 03 00 00 00 28 00 00 01 2c


$ sg_wr_mode -p 1a -c 0,0,0,0,0,0,0,37 -m 0,0,0,0,0,0,0,ff /dev/hdc


$ sg_modes -p 1a /dev/hdc
>> Condición de potencia (mmc), page_control: actual
00 1a 0a 00 03 00 00 00 37 00 00 01 2c

ESTADO DE SALIDA

El estado de salida de sg_wr_mode es 0 cuando tiene éxito. De lo contrario, consulte la página del manual sg3_utils(8).
