NOMBRE

sg_sat_read_gplog - usa el comando ATA READ LOG EXT o SMART READ LOG a través de una capa de traducción SCSI a ATA (SAT)

SINOPSIS

sg_sat_read_gplog [--address=LA_L] [--ck_cond] [--count=CO] [--dma] [--help] [--hex] [--len=CMD_LEN] [--log=LA_L] [--page=PN] [--ppt=PPT] [--readonly] [--smart] [--verbose] [--version] DISPOSITIVO

DESCRIPCIÓN

Esta utilidad envía un comando ATA READ LOG EXT, ATA READ LOG DMA EXT o ATA SMART READ LOG al DISPOSITIVO. Por defecto, envía uno de los dos primeros comandos para leer páginas de "registro de propósito general". Solo los dispositivos (S)ATA (por ejemplo, discos) pero no los dispositivos ATAPI (por ejemplo, lectores de DVD) soportan las páginas de registro de propósito general. En lugar de enviar el comando READ LOG (DMA) EXT directamente al dispositivo, se envía a través de un transporte SCSI que se supone que contiene una Capa de Traducción SCSI a ATA (SAT). La SATL puede estar en un controlador del sistema operativo, en el firmware de la controladora de host (HBA) o en alguna carcasa externa.

Esta utilidad actualmente no intenta decodificar la respuesta del disco ATA, sino que muestra la respuesta en hexadecimal ASCII agrupada en bytes de 8 bits o palabras de 16 bits. Siguiendo las convenciones ATA, esas palabras se decodifican en little endian (ten en cuenta que los comandos SCSI usan una representación big endian). La dirección de registro 0, número de página 0 es la página de registro de 'directorio' y se decodifica si no se proporciona la opción --hex. En el futuro, esta utilidad puede intentar decodificar otras páginas de registro. Quizás otras utilidades ATA podrán decodificar estas páginas de registro dado la salida hexadecimal de esta utilidad.

Obtener todas las páginas de registro parece tan simple como leer la página de registro del directorio y luego acceder a aquellas direcciones de registro que tienen más de cero números de página asociados. Desafortunadamente, no es tan simple. Algunas direcciones de registro (mirando específicamente 0xe1 ("SCT Data transfer")) requieren que se ejecute un comando SCT antes de obtener la página de registro en esa dirección de registro. Otras direcciones de registro podrían ser problemáticas (por ejemplo, se ha sugerido que los "Registros específicos del proveedor del dispositivo" 0xa0:0xdf) por lo que quizás también deban evitarse. Esa es la razón por la que las opciones --address=LA_L y --log=LA_L están diseñadas para aceptar una lista de rangos.

El estándar SAT-4 (SAT ANSI INCITS 491-201r7 borrador previo: sat4r06.pdf en www.t10.org) define tres comandos SCSI "ATA PASS-THROUGH": uno usando un "cdb" de 12 bytes, otro usando un cdb de 16 bytes, y el tercero un cdb de 32 bytes. Esta utilidad usa por defecto la variante de cdb de 16 bytes.

OPCIONES

Los argumentos de las opciones largas son obligatorios también para las opciones cortas.

-a, --address=LA_L
donde LA_L es una única "dirección de registro", un rango de direcciones de registro, o una lista de (rangos de) direcciones de registro. Una dirección de registro es un número entre 0 y 255 (0xff) donde la dirección de registro 0, número de página 0, es un directorio. Un rango de direcciones de registro tiene el formato "lo:hi" donde la dirección de registro "hi" debe ser mayor o igual que "lo". Una lista de direcciones de registro es una lista separada por comas de direcciones de registro o rangos de direcciones de registro.
Cada dirección de registro contiene hasta 256 (registro SMART) o 65536 (registro de propósito general) números de página, comenzando desde el número de página 0. El número de páginas disponibles para cada dirección de registro se enumera en la página de registro del directorio.
Resumen de la sintaxis de LA_L: lo:hi,lo2:hi2,lo3:hi3 ...
-C, --ck_cond
establece el bit CK_COND en el cdb SCSI ATA PASS-THROUGH. El valor por defecto es claro (es decir, 0). Cuando está establecido, la SATL debe proporcionar un búfer de sense que contenga un descriptor de resultado ATA independientemente de si el comando ATA tuvo éxito o falló. Cuando está claro, la SATL solo debe proporcionar un búfer de sense que contenga un descriptor de resultado ATA si el comando ATA falló.
-c, --count=CO
el número CO se coloca en el campo "count" del comando ATA READ LOG EXT. Esto especifica el número de páginas de registro de 512 bytes de datos a leer de la dirección de registro especificada. Se lee la dirección de página dada comenzando desde el número de página dado. El último número de página leído será (PN + CO - 1) si existe.
El valor máximo de CO es 0xffff (65,535) para páginas de registro de propósito general y 0xff (255) para páginas de registro SMART.
Normalmente se informa un error si la página dada --page=PN (por defecto 0) más CO excede el número mostrado en el directorio de registro (dirección de registro 0) para la dirección de registro dada.
Ten en cuenta que CO solo se aplica a la dirección de registro actual; en otras palabras, no hay desbordamiento al principio del siguiente registro de dirección.
-d, --dma
usa el comando ATA READ LOG DMA EXT en lugar del comando ATA READ LOG EXT. Algunos dispositivos requieren esto para devolver datos de registro válidos.
-h, --help
muestra el mensaje de uso resumiendo las opciones de línea de comandos y luego sale. Ignora DISPOSITIVO si se proporciona.
-H, --hex
cuando se usa una vez, la respuesta se muestra en bytes hexadecimales ASCII. Cuando se usa dos veces, la respuesta se agrupa en palabras de 16 bits usando convenciones ATA (es decir, little endian); esta es la salida por defecto (es decir, cuando esta opción no se usa). Cuando se usa tres veces (es decir, '-HHH') la salida está en hexadecimal, agrupada en palabras de 16 bits (sin un desplazamiento inicial y el ASCII final en cada línea), en un formato que es aceptable para que 'hdparm --Istdin' lo procese.

Si esta opción se invoca cuatro veces (por ejemplo, '-HHHH') las páginas de registro se muestran como bytes hexadecimales, sin dirección inicial al principio de cada línea. Eso hace que el hexadecimal sea más fácil de decodificar para las computadoras (pero no para los humanos). Si esta opción se invoca cinco veces, se muestra una línea de comentario, que comienza con un carácter '#', antes de cada página de registro de 512 bytes. El comentario describe la siguiente página de registro.

-l, --len=CMD_LEN
donde CMD_LEN es la longitud del comando (cdb) del comando SCSI ATA PASS-THROUGH que se utiliza para tunelizar comandos ATA. Se permiten tres valores: 12, 16 y 32 (bytes de longitud). La variante de 12 bytes tiene las mayores restricciones (por ejemplo, su campo 'count' es un solo byte), pero los sistemas más antiguos pueden no permitir comandos de 16 o 32 bytes.
-L, --log=LA_L
ver la opción --address=LA_L.
-p, --page=PN
el número PN es el número de página (dentro de la dirección de registro) y se coloca en los bits 32:16 del campo "lba" del comando ATA READ LOG (DMA) EXT. El valor por defecto que se coloca en el campo "lba" es 0.
El valor máximo de PN es 0xffff (65,535) para páginas de registro de propósito general y 0xff (255) para páginas de registro SMART. En este último caso, PN debe ser 0 y CO es 255.

Cuando se especifican múltiples direcciones de registro (a través del argumento LA_L) esta opción se trata de manera diferente. Con múltiples direcciones de registro y si PN es mayor que 0, actúa como un límite superior del número de números de página que se mostrarán para cada dirección de registro. El número real de páginas de registro de 512 bytes mostradas también dependerá del número de números de página que se muestren en la página de registro del directorio para la dirección de registro actual.

-P, --ppt=PPT
donde PPT es el número de páginas a transferir desde el DISPOSITIVO por invocación del comando ATA READ LOG EXT o ATA READ LOG DMA EX. El valor por defecto es 128 (o 64 Kibibytes) que se elige porque la mayoría de los sistemas operativos tienen un límite superior en el tamaño de las transferencias hacia y desde un dispositivo con un solo comando. Cuando el número de páginas de registro dado con la opción --count=CO es grande, puede exceder lo que un SO permitirá en una sola invocación de comando. De ahí la necesidad de esta opción.
-l, --len={32|16|12}
esta es la longitud del cdb SCSI utilizado para los comandos ATA PASS-THROUGH. El argumento puede ser 32, 16 o 12. Por defecto es 16. Algunos transportes SCSI no pueden transmitir comandos SCSI de más de 12 bytes.
-r, --readonly
hace que el DISPOSITIVO se abra con el indicador de solo lectura (O_RDONLY en C).

Esta opción no tiene ningún efecto en los sistemas que no tienen el indicador O_RDONLY (por ejemplo, ciertos sistemas operativos o controladores que no exponen este indicador).

-s, --smart
usa el comando ATA SMART READ LOG en lugar de ATA READ LOG EXT. Este comando solo puede leer páginas de registro SMART (y no páginas de registro de propósito general). La mayoría de los discos modernos se reportan a sí mismos como dispositivos SMART, por lo que este comando solo funcionará en tales dispositivos.
-v, --verbose
incrementa el nivel de verbosidad de la salida. La información detallada incluye el contenido del búfer de respuesta de la solicitud SCSI.
-V, --version
imprime la versión del paquete e información de licencia y sale.

EJEMPLOS

Para leer todas las páginas de registro de propósito general (incluida la página de directorio):

sg_sat_read_gplog --address=0 /dev/sda

Para leer el registro de directorio (página 0, número de página 0) y luego la página 1 de la dirección de registro 0:

sg_sat_read_gplog --address=0 --page=1 --count=1 /dev/sda

Para leer 10 páginas de registro de propósito general comenzando desde la página 5 de la dirección de registro 1:

sg_sat_read_gplog --address=1 --page=5 --count=10 /dev/sda

Para leer todas las páginas de registro SMART (la dirección de registro 0x00, con el comando SMART READ LOG, y todas las 255 páginas posibles):

sg_sat_read_gplog --smart --address=0x0 --page=0 --count=255 /dev/sg0

Para leer la página 0x0001 (primera página de registro) de la dirección de registro 0x00 (directorio), usando el comando DMA, y el cdb de 12 bytes, y mostrar la salida en formato compatible con hdparm:

sg_sat_read_gplog -d -l12 -H -H -H --address=0x0 --page=0x0001 --count=1 /dev/sg1

sg_sat_read_gplog(8) - Arch Linux Manual Pages

NAME

sg_sat_read_gplog

leer páginas de registros de propósito general (y SMART) de discos ATA

SYNOPSIS

sg_sat_read_gplog [OPTION...] DEVICE

DESCRIPTION

Lee páginas de registros de propósito general (o registros SMART) de un disco ATA usando el comando SAT (SCSI ATA Translation) READ LOG EXT (o SMART READ LOG). Los registros de propósito general se describen en el estándar T13 (www.t13.org).

Los registros de propósito general están indexados por un número de dirección de registro de 32 bits y un número de página de 8 bits. El número de registro se puede dar como un número hexadecimal (con prefijo "0x") o como un número decimal. El número de página se puede dar como un número hexadecimal (con prefijo "0x") o como un número decimal.

La opción --address puede usarse para especificar una lista de direcciones de registro y números de página que se leerán. Si no se especifica, se lee la página 0 de la dirección de registro 0.

Para algunas unidades ATA, la opción --all leerá todas las páginas de registro de propósito general que la unidad declare en su página de directorio de registros de propósito general. Tenga en cuenta que algunos registros de propósito general (por ejemplo, 0xc, 0xa0-0xdf, 0xe1) pueden no estar disponibles o no ser válidos en algunas unidades.

La mayoría de los comandos SAT envían el comando SCSI dado al dispositivo DEVICE. La acción predeterminada es abrir DEVICE con el indicador de lectura-escritura (O_RDWR en Unix). En algunos casos, el envío de comandos de administración de energía a discos ATA se ve frustrado por las acciones del sistema operativo en close() si DEVICE se abrió con el indicador de lectura-escritura (por ejemplo, el sistema operativo podría pensar que necesita vaciar algo al disco).

OPTIONS

-a, --all
lee todas las páginas de registro de propósito general disponibles (o SMART si se especifica --smart). El rango de direcciones de registro es de 0 a 31 (0x0 a 0x1f). Las páginas de directorio (dirección de registro 0) se leen primero para determinar qué otras páginas de registro están disponibles.
-A, --address=LA_L
una lista de direcciones de registro y números de página. El formato es una lista separada por comas de especificaciones de dirección de registro y número de página. Cada especificación puede tener uno de los siguientes formatos:
  • LA:PN
  • LA:PN_PN
  • LA
donde LA es una dirección de registro (0 a 65535, 0x0 a 0xffff) y PN es un número de página (0 a 255, 0x0 a 0xff). Si se omite el número de página (p. ej., LA), se utiliza el número de página 0. Si se proporciona un rango (p. ej., LA:PN_PN), se incluyen todos los números de página en el rango (inclusive). Si se omiten la dirección de registro y el número de página (p. ej., -A), se lee la dirección de registro 0, página 0.

Hay 32 direcciones de registro de propósito general (0 a 31, o 0x0 a 0x1f). Si se especifica una dirección de registro de propósito general que está fuera de este rango (p. ej., 32, 0x20), se generará un error. El número de páginas de registro de propósito general que pueden ser solicitadas (a través de la página de directorio) es de 255. Por lo tanto, la opción --all está limitada a leer páginas 0 a 255.

Si se especifica la opción --smart, se utiliza el comando SMART READ LOG en lugar de READ LOG EXT. El comando SMART READ LOG solo tiene un campo de número de página (8 bits) y no tiene un campo de dirección de registro. El número de páginas de registro disponibles se limita a 255 (0 a 255). Las páginas de directorio se utilizan de forma diferente para SMART.

Tenga en cuenta que algunos registros de propósito general (por ejemplo, 0xc, 0xa0-0xdf, 0xe1) pueden no estar disponibles o ser inválidos en algunas unidades.

-c, --ck_cond
verifica la condición de carga y el código de retorno del comando SCSI. Si hay un error, se imprime una cadena que describe el error y el programa sale con un valor de salida de 1. Esta opción es útil para depurar. La condición de carga es un campo de 4 bits que se devuelve en el encabezado Período de respuesta de SCSI.
-d, --device=DEVICE
el dispositivo a leer. Esto podría ser algo como /dev/sg0 o /dev/sda. Si no se especifica, se intenta usar /dev/sg0.
-h, --help
imprime el mensaje de uso y sale.
-o, --offset=OFF
el desplazamiento en bytes desde el inicio de la página de registro donde comenzará la salida. El valor predeterminado es 0. Solo se aplica cuando se lee una sola página de registro.
-p, --page=PN
especifica el número de página que se leerá. Solo se puede especificar si solo se está leyendo una dirección de registro. El valor predeterminado es 0. Si se especifica 0, se leerá la página de directorio.
-P, --page_count=PN
especifica el número de páginas de registro que se leerán. El valor predeterminado es 1. Esto solo se aplica cuando se lee una sola dirección de registro.
-s, --smart
en el conjunto de características ATA SMART, las páginas de registro "SMART" han estado presentes durante mucho tiempo y preceden a la adición posterior de las páginas de registro de "propósito general". Por lo tanto, esta utilidad se puede extender fácilmente para leer páginas de registro "SMART" en lugar de las páginas de registro de propósito general. Eso es exactamente lo que hace esta opción.
El comando ATA SMART READ LOG no tiene campo de número de página, todas las recuperaciones comienzan desde el número de página 0. Además, el número de números de página (en su dirección de registro) está limitado a un solo byte (es decir, 255). La página de directorio de registros de propósito general y la página de directorio de registros SMART tienen el mismo formato (dada la restricción de un solo byte en el número de números de página en cada dirección de registro SMART).
-v, --verbose
aumenta el nivel de verbosidad.
-V, --version
imprime la cadena de la versión

NOTAS

Antes del kernel de Linux 2.6.29, el almacenamiento masivo USB limitaba los datos de sondeo a 18 bytes, lo que hacía que la opción --ck_cond produjera resultados extraños (truncados).

Existen ligeras diferencias en el manejo cuando se recupera una sola dirección de registro y cuando se recuperan varias páginas de registro. En el caso de una sola dirección de registro, la dirección de registro, el número de página y el recuento van a los campos correspondientes en el comando ATA READ LOG EXT o ATA SMART READ LOG. Cuando se dan múltiples direcciones de registro, primero se carga la página de registro del 'directorio' (dirección de registro=0, número de página=0). Luego, solo se recuperan las direcciones de registro que el directorio indica que tienen más de cero números de página. El recuento de números de página de registro accedidos puede estar aún más restringido por la opción --page=PN si PN es mayor que cero.

EJEMPLOS

Primero, aquí hay un ejemplo que evita las direcciones de registro problemáticas observadas en la sección DESCRIPCIÓN anterior.


sg_sat_read_gplog -a 0:0xb,0xd:0x9f,0xe0,0xe2:255 /dev/sdc

Lo anterior utiliza la forma corta de la opción --address=LA_L con una lista que evita las direcciones de registro 0xc, 0xa0 a 0xdf y 0xe1. La salida incluirá todas las direcciones de registro, aparte de esas exclusiones, que el directorio indica que tienen más de 0 números de página.
La siguiente invocación utiliza el comando SMART READ LOG en lugar del comando READ LOG EXT:


sg_sat_read_gplog --smart -a 0:0xb,0xd:0x9f,0xe0,0xe2:255 /dev/sdc

ESTADO DE SALIDA

El estado de salida de sg_sat_read_gplog es 0 cuando tiene éxito. De lo contrario, consulte la página man sg3_utils(8).
