Paquete: sg3_utils

Licencias: GPL, custom:BSD

SG_READ(8) SG3_UTILS SG_READ(8)

NOMBRE

sg_read - lee múltiples bloques de datos, opcionalmente con comandos SCSI READ

SINOPSIS

sg_read [blk_sgio=0|1] [bpt=BPT] [bs=BS] [cdbsz=6|10|12|16] count=COUNT [dio=0|1] [dpo=0|1] [fua=0|1] if=IFILE [mmap=0|1] [no_dxfer=0|1] [odir=0|1] [skip=SKIP] [time=TI] [verbose=VERB] [--help] [--version]

DESCRIPCIÓN

Lee datos de un dispositivo genérico SCSI (sg) de Linux, un dispositivo de bloques o un archivo normal, con cada comando de lectura emitido a la misma posición o dirección de bloque lógico (lba). Esto se puede usar para probar (o cronometrar) la caché del disco, el rendimiento del transporte SCSI (o de otro tipo) y/o la sobrecarga de los comandos SCSI.

Cuando el valor de COUNT es positivo, se leen hasta BPT bloques a la vez, hasta que se agota COUNT. Cada operación de lectura comienza en la misma lba que, si no se proporciona SKIP, es el inicio del archivo o dispositivo.

El valor COUNT puede ser negativo cuando IFILE es un dispositivo sg o es un dispositivo de bloques con 'blk_sgio=1' activado. Alternativamente, se puede proporcionar 'bpt=0'. En estos casos, se emiten comandos SCSI READ de |COUNT| "bloques cero". "Bloques cero" significa "no hacer nada" para los comandos SCSI READ de 10, 12 y 16 bytes (pero no para la variante de 6 bytes). En la práctica, los comandos SCSI READ de "bloques cero" tienen una latencia baja y, por lo tanto, son una forma de medir la sobrecarga de los comandos SCSI.

Tenga en cuenta: esta es una utilidad muy antigua que utiliza enteros de 32 bits para las LBA de disco y el contador. Por lo tanto, no podrá acceder más allá de 2 Terabytes en un disco con bloques lógicos de 512 bytes. Las alternativas son las utilidades sg_dd y ddpt.

OPCIONES

blk_sgio=0 | 1
La acción predeterminada de esta utilidad es usar el comando read() de Unix cuando IFILE es un dispositivo de bloques. En lk 2.6, muchos dispositivos de bloques pueden manejar comandos SCSI emitidos a través del ioctl SG_IO. Por lo tanto, cuando esta opción está activada, el ioctl SG_IO envía comandos SCSI READ a IFILE si es un dispositivo de bloques.
bpt=BPT
donde BPT es el número máximo de bloques que recupera cada operación de lectura. Se recuperarán menos bloques cuando el COUNT restante sea menor que BPT. El valor predeterminado para BPT es 128. Tenga en cuenta que cada operación de lectura comienza en la misma lba (según lo dado por skip=SKIP o 0). Si 'bpt=0', entonces COUNT se interpreta como el número de comandos SCSI READ de bloques cero a emitir.
bs=BS
donde BS es el tamaño (en bytes) de cada bloque leído. Este debe ser el tamaño del bloque del dispositivo físico (por defecto 512) si se están emitiendo comandos SCSI a IFILE.
cdbsz=6 | 10 | 12 | 16
tamaño de los comandos SCSI READ emitidos en nombres de dispositivos sg, o en dispositivos de bloques si se proporciona 'blk_sgio=1'. El valor predeterminado es un CDB SCSI READ de 10 bytes.
count=COUNT
cuando COUNT es un número positivo, lee esa cantidad de bloques, típicamente con múltiples operaciones de lectura. Cuando COUNT es negativo, se realizan |COUNT| comandos SCSI READ solicitando que no se transfieran bloques (cero bloques). Esta opción es obligatoria.
dio=0 | 1
el valor predeterminado es 0, que selecciona E/S indirecta. El valor 1 intenta E/S directa que, si no está disponible, vuelve a la E/S indirecta y lo nota al completarse. Esta opción solo está activa si IFILE es un dispositivo sg. Si se selecciona E/S directa y /sys/module/sg/parameters/allow_dio tiene el valor 0, se emite una advertencia (y se realiza E/S indirecta)
dpo=0 | 1
cuando está activado, se establece el bit de deshabilitar página de salida (DPO) en los comandos SCSI READ. De lo contrario, el bit DPO se borra (predeterminado).
fua=0 | 1
cuando está activado, se establece el bit de forzar acceso a unidad (FUA) en los comandos SCSI READ. De lo contrario, el bit FUA se borra (predeterminado).
if=IFILE
lee desde este IFILE. Este argumento debe proporcionarse. Si IFILE es un archivo normal, debe ser buscable (si (COUNT > BPT) o se proporciona skip=SKIP). Por lo tanto, la entrada estándar no es aceptable (y dar "-" como argumento de IFILE se reporta como un error).
mmap=0 | 1
el valor predeterminado es 0, que selecciona E/S indirecta. El valor 1 causa que se realice E/S mapeada en memoria. Seleccionar tanto dio como mmap es un error. Esta opción solo está activa si IFILE es un dispositivo sg.
no_dxfer=0 | 1
cuando está activado, las transferencias DMA desde el dispositivo se realizan a buffers del kernel pero no más allá (es decir, no hay una segunda copia al espacio de usuario). El valor predeterminado es 0, en cuyo caso las transferencias se realizan al espacio de usuario. Cuando ni mmap ni dio están activados, las transferencias de datos se copian a través de buffers del kernel (es decir, una doble copia). Principalmente para pruebas.
odir=0 | 1
cuando está activado, abre un IFILE que es un dispositivo de bloques con un flag O_DIRECT adicional. El valor predeterminado es 0 (es decir, no abre dispositivos de bloques con O_DIRECT).
skip=SKIP
todas las operaciones de lectura comenzarán desplazadas por SKIP bloques del tamaño de bs desde el inicio del archivo (o dispositivo) de entrada.
time=TI
Cuando TI es 0 (predeterminado), no realiza mediciones de tiempo. Cuando es 1, mide el tiempo de transferencia y calcula el rendimiento, comenzando en el primer comando emitido hasta su finalización. Cuando es 2, mide el tiempo de transferencia y calcula el rendimiento, comenzando en el segundo comando emitido hasta su finalización. Cuando es 3, mide desde el tercer comando, etc. También se muestra un número promedio de comandos (SCSI READ o read() de Unix) ejecutados por segundo.
verbose=VERB
a medida que VERB aumenta, aumenta la cantidad de salida de depuración enviada a stderr. El valor predeterminado es cero, lo que produce la cantidad mínima de salida de depuración. Un valor de 1 informa información adicional que no es repetitiva.
--help
Muestra el mensaje de uso y luego sale.
--version
Muestra la cadena de versión y luego sale.

NOTAS

Varios argumentos numéricos (por ejemplo, SKIP) pueden incluir sufijos multiplicadores o darse en hexadecimal. Consulte la sección "ARGUMENTOS NUMÉRICOS" en la página del manual sg3_utils(8).

Los datos generalmente llegan al espacio de usuario en un proceso de 2 etapas: primero el adaptador SCSI DMA a buffers del kernel y luego el driver sg copia estos datos a la memoria del usuario. Esto se llama "E/S indirecta" y hay una opción "dio" para seleccionar "E/S directa" que hará DMA directamente a la memoria del usuario. Debido a algunos problemas, la "E/S directa" está deshabilitada en el driver sg y requiere un cambio de configuración para activarla. Esto generalmente se hace con "echo 1 > /sys/module/sg/parameters/allow_dio". Una forma alternativa de evitar la copia de 2 etapas es seleccionar E/S mapeada en memoria con 'mmap=1'.

SEÑALES

El manejo de señales se ha tomado prestado de dd: SIGINT, SIGQUIT y SIGPIPE muestran el número de bloques restantes a transferir; luego tienen su acción predeterminada. SIGUSR1 hace que la misma información se muestre, pero la copia continúa. Toda la salida causada por señales se envía a stderr.

EJEMPLOS

Supongamos que /dev/sg0 es un disco y deseamos medir el rendimiento de la caché del disco.


sg_read if=/dev/sg0 bs=512 count=1MB mmap=1 time=2

Este comando leerá continuamente 128 bloques de 512 bytes desde el bloque 0. El "128" es el valor predeterminado para 'bpt', mientras que el "bloque 0" se elige porque no se proporcionó el argumento 'skip'. Esto continuará hasta que se lean 1,000,000 de bloques. La idea detrás del uso de 'time=2' es que la primera operación de lectura de 64 KiB implicará leer el medio magnético

a mientras que las operaciones de lectura restantes "golpearán" la caché del disco. La salida del tercer comando se verá así:


tiempo desde el segundo comando hasta el final fue 4.50 segundos, 113.70 MB/seg
Número promedio de comandos READ por segundo fue 1735.27
1000000+0 registros en, comandos SCSI emitidos: 7813

ESTADO DE SALIDA

El estado de salida de sg_read es 0 cuando es exitoso. De lo contrario, consulte la página man de sg3_utils(8).
