NOMBRE

sg_write_same - enviar comando SCSI WRITE SAME

SINOPSIS

sg_write_same [--10] [--16] [--32] [--anchor] [--ff] [--grpnum=GN] [--help] [--in=IF] [--lba=LBA] [--lbdata] [--num=NUM] [--ndob] [--pbdata] [--timeout=TO] [--unmap] [--verbose] [--version] [--wrprotect=WPR] [--xferlen=LEN] DISPOSITIVO

DESCRIPCIÓN

Envía el comando SCSI WRITE SAME (10, 16 o 32 bytes) al DISPOSITIVO. Este comando escribe el bloque dado NUM veces en bloques consecutivos en el DISPOSITIVO comenzando en la dirección de bloque lógico LBA.

La longitud del bloque que se escribirá varias veces se obtiene del argumento LEN, o de la longitud del archivo de entrada dado IF, o llamando a READ CAPACITY(16) en el DISPOSITIVO. El contenido del bloque a escribir se obtiene del archivo de entrada IF o se utilizan ceros. Si se llama a READ CAPACITY(16) (lo que implica que no se proporcionó IF) y el bit PROT_EN está configurado, se envían 8 bytes adicionales (es decir, más que el tamaño del bloque lógico) de 0xff.

Si no se proporciona ni --10, ni --16, ni --32, se envía WRITE SAME(10) a menos que se cumpla una de las siguientes condiciones. Si LBA (más NUM) excede los 32 bits, NUM excede 65535, o se da la opción --unmap, se envía WRITE SAME(16). Las opciones --10, --16 y --32 son mutuamente excluyentes.

SBC-3 revisión 35d introdujo un bit "No Data-Out Buffer" (NDOB) que, si está configurado, evita el requisito de enviar un solo bloque de datos al DISPOSITIVO junto con el comando. Solo WRITE SAME (16 y 32 bytes) soportan el bit NDOB. Si se proporciona, se asume un bloque de ceros de usuario; si es necesario, se asume información de protección de 0xff.

En la revisión 26 de SBC-3 se agregaron los bits UNMAP y ANCHOR al comando WRITE SAME (10). Dado que el bit UNMAP ha estado en WRITE SAME (16) y WRITE SAME (32) desde la revisión 18 de SBC-3, el menor de los dos (es decir, WRITE SAME (16)) es el predeterminado cuando se proporciona la opción --unmap. Para enviar WRITE SAME (10) use la opción --10.

Tenga cuidado: Los comandos WRITE SAME(10, 16 y 32) pueden interpretar un NUM de cero como escribir hasta el final del DISPOSITIVO. Esta utilidad establece NUM en 1 por defecto. Los comandos WRITE SAME no tienen bit IMMED, por lo que si NUM es grande (o cero), una invocación de esta utilidad podría tomar mucho tiempo, potencialmente tanto como un comando FORMAT UNIT. En tales situaciones, el valor de tiempo de espera del comando TO puede necesitar ser aumentado desde su valor predeterminado de 60 segundos. En la revisión 26 de SBC-3 se agregó el bit WSNZ (write same no zero) a la página VPD Block Limits [0xB0]. Si está configurado, los comandos WRITE SAME no aceptarán un NUM de cero. La misma revisión SBC-3 agregó el campo "Maximum Write Same Length" a la página VPD Block Limits.

La página Logical Block Provisioning VPD [0xB2] contiene los bits LBPWS y LBPWS10. Si LBPWS está configurado, WRITE SAME (16) soporta el bit UNMAP. Si LBPWS10 está configurado, WRITE SAME (10) soporta el bit UNMAP. Si LBPWS o LBPWS10 está configurado y WRITE SAME (32) es soportado, entonces WRITE SAME (32) soporta el bit UNMAP.

Como medida de precaución contra un accidental 'sg_write_same /dev/sda' (por ejemplo) que sobrescriba LBA 0 en /dev/sda con ceros, se debe proporcionar al menos una de las opciones --in=IF, --lba=LBA o --num=NUM. Obviamente, esta utilidad puede destruir muchos datos del usuario, así que verifique las opciones cuidadosamente.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas. Las opciones están ordenadas alfabéticamente según el nombre de la opción larga.

-R, --10
envía un comando SCSI WRITE SAME (10) al DISPOSITIVO. La capacidad de configurar las opciones --unmap (y --anchor) a este comando se agregó en la revisión 26 de SBC-3.
-S, --16
envía un comando SCSI WRITE SAME (16) al DISPOSITIVO.
-T, --32
envía un comando SCSI WRITE SAME (32) al DISPOSITIVO.
-a, --anchor
configura el bit ANCHOR en el cdb. Introducido en la revisión 22 de SBC-3. Ese borrador requiere que la opción --unmap también se especifique.
-f, --ff
el buffer de datos de salida enviado con este comando se inicializa con bytes 0xff cuando se proporciona esta opción.
-g, --grpnum=GN
configura el campo 'Número de grupo' a GN. Por defecto es un valor de cero. GN debe ser un valor entre 0 y 63.
-h, --help
muestra el mensaje de uso y luego sale.
-i, --in=IF
lee datos (binarios) del archivo llamado IF y los usa como buffer de datos de salida para el comando SCSI WRITE SAME. La longitud del buffer de datos de salida es --xferlen=LEN o, si no se proporciona, la longitud del archivo IF. Si IF es "-" se lee de stdin. Si esta opción y --ff no se proporcionan, se usan bytes 0x00 como relleno con la longitud del buffer de datos de salida obtenida de --xferlen=LEN o llamando a READ CAPACITY(16 o 10). Si la respuesta a READ CAPACITY(16) tiene el bit PROT_EN configurado, el tamaño del buffer de datos de salida se modifica en consecuencia con los últimos 8 bytes configurados a 0xff.
-l, --lba=LBA
donde LBA es la dirección de bloque lógico para iniciar el comando WRITE SAME. Por defecto es LBA 0, que es un bloque peligroso de sobrescribir en un disco en uso. Se asume que está en decimal a menos que sea prefijado con '0x' o tenga una 'h' al final.
-L, --lbdata
configura el bit LBDATA en el cdb WRITE SAME. Este bit se volvió obsoleto en sbc3r32 en septiembre de 2012.
-N, --ndob
configura el bit NDOB en los comandos WRITE SAME (16 y 32 bytes). NDOB significa No Data-Out Buffer. Por defecto, este bit está desconfigurado. Cuando se proporciona esta opción, --in=IF no está permitido y --xferlen=LEN solo se puede proporcionar si LEN es 0.
Por defecto, se escriben ceros en cada bloque, pero es posible que el "patrón de inicialización de aprovisionamiento" se escriba dependiendo de otras configuraciones.
-n, --num=NUM
donde NUM es el número de bloques, comenzando en LBA, a los que escribir el buffer de datos de salida. El valor predeterminado para NUM es 1. El valor corresponde al campo 'Número de bloques lógicos' en el cdb WRITE SAME.
Tenga en cuenta que un valor de 0 en NUM puede interpretarse como escribir el buffer de datos de salida en cada bloque a partir de LBA hasta el final del DISPOSITIVO. Si el bit WSNZ (introducido en sbc3r26, enero de 2011) en la página VPD Block Limits está configurado, el valor 0 no está permitido, lo que genera una clave de sentido "Invalid request" (Solicitud inválida).
-P, --pbdata
configura el bit PBDATA en el cdb WRITE SAME. Este bit se volvió obsoleto en sbc3r32 en septiembre de 2012.
-t, --timeout=TO
donde TO es el valor de tiempo de espera del comando en segundos. El valor predeterminado es 60 segundos. Si NUM es grande (o cero), un comando WRITE SAME puede requerir considerablemente más tiempo que 60 segundos para completarse.
-U, --unmap
configura el bit UNMAP en el cdb WRITE SAME(10, 16 y 32). Ver sección UNMAP a continuación.
-v, --verbose
aumenta el nivel de verbosidad (mensajes de depuración).
-V, --version
muestra la cadena de versión y luego sale.
-w, --wrprotect=WPR
configura el campo "Write protect" en el cdb WRITE SAME a WPR. El valor predeterminado es cero. WPR debe ser un valor entre 0 y 7. Cuando WPR es 1 o mayor, y el tipo de protección del disco es 1 o mayor, se esperan o generan 8 bytes adicionales de información de protección.
-x, --xferlen=LEN
especifica la longitud en bytes del buffer de datos de salida a enviar. Si no se proporciona y no se usa la opción --in=IF, entonces se llama a READ CAPACITY para obtener el tamaño del bloque lógico. Si se utiliza la opción --in=IF, la longitud se toma de la longitud del archivo IF a menos que se especifique --xferlen=LEN. El valor predeterminado es obtener la longitud del bloque lógico llamando a READ CAPACITY (y ajustando si la información de protección está activa). "LEN" debe ser un múltiplo del tamaño del bloque lógico (si se conoce).

UNMAP

Cuando se establece el bit UNMAP, el comando WRITE SAME se utiliza para desaprovisionar (es decir, marcar como no utilizado) los bloques lógicos especificados por el campo 'Number of logical blocks' en el cdb. Esto puede tener implicaciones en el rendimiento, ya que el dispositivo de almacenamiento puede reclamar los recursos asociados con esos bloques. El comportamiento exacto depende de la implementación del dispositivo. Tenga en cuenta que el comando UNMAP (y por lo tanto, WRITE SAME con UNMAP) está diseñado para desaprovisionar bloques, no para escribir datos en ellos.

ESTADO DE SALIDA

Devuelve 0 si el comando fue exitoso. Devuelve 1 si hubo un error con los argumentos de la línea de comandos o si el comando SCSI devolvió un error.

EJEMPLOS

Para escribir un bloque de datos de 4096 bytes desde el archivo `data.bin` en el disco `/dev/sdc` en LBA 10000, repitiendo la escritura 5 veces:

sg_write_same --in=data.bin --lba=10000 --num=5 /dev/sdc

Para escribir un bloque de ceros de 512 bytes, 10 veces, comenzando en LBA 2000 en `/dev/sdb` usando un comando WRITE SAME de 16 bytes:

sg_write_same --16 --lba=2000 --num=10 --xferlen=512 /dev/sdb

Para desaprovisionar bloques desde LBA 5000 hasta LBA 5999 en `/dev/sdc` (es decir, desaprovisionar 1000 bloques):

sg_write_same --unmap --lba=5000 --num=1000 /dev/sdc

Para escribir datos del archivo `my_data.raw` al dispositivo `/dev/sg0`, permitiendo que la longitud de transferencia sea determinada por la longitud del archivo:

sg_write_same --in=my_data.raw /dev/sg0

sg_write_same

escribe bloques idénticos en un dispositivo SCSI

SYNOPSIS 

  sg_write_same [OPTION...] DEVICE

DESCRIPTION

Este programa en modo de usuario en el espacio de Linux envía un comando SCSI WRITE SAME (en SBC-3 revisiones 16 o posterior) al DEVICE especificado. El comando WRITE SAME se utiliza para escribir datos idénticos en uno o más bloques lógicos contiguos en el dispositivo de almacenamiento.

Esto es útil para el saneamiento de datos donde se desea llenar secciones grandes (o todo) de un disco con un patrón específico, como ceros. Los comandos ATA equivalentes son ATA TRIM (con el bit de información de reserva establecido) y WRITE SAME.

Los comandos SCSI WRITE SAME y ATA TRIM no tienen problemas con la gestión de colas de comandos SCSI o SATA respectivamente. Sin embargo, la implementación de ATA TRIM en versiones anteriores a la especificación ATA command que incluía el comando SFQ (Stream Flow Quencing) tenía problemas con la cola de comandos NCQ de SATA.

OPTIONS

--16
Usa el comando SCSI WRITE SAME (16 bytes). El valor predeterminado es usar el comando WRITE SAME (10 bytes) si es posible (es decir, si el LBA y el número de bloques están dentro del rango permitido para el comando de 10 bytes). El comando de 16 bytes es necesario para LBA más allá de 2^32 (aproximadamente 2 terabytes).
--32
Usa el comando SCSI WRITE SAME (32 bytes). Esto se usa cuando la longitud del CDB es mayor que 16 bytes (por ejemplo, cuando se usa la opción --xferlen=LEN con un valor grande).
--all
Esto es un atajo para establecer el LBA en 0 y el número de bloques en 0. Cuando el número de bloques es 0, significa "hasta el final del dispositivo". Tenga en cuenta que esta operación puede fallar si el bit WSNZ en la página VPD Block Limits está configurado y no se proporciona un bloque de datos de salida (o si el bloque de datos de salida no está lleno de ceros).
--dry-run
No envía el comando SCSI al dispositivo. Imprime el CDB y los datos de salida (si los hubiera) que se habrían enviado.
--in=IF
Lee los datos de entrada del archivo IF. Si no se proporciona esta opción, el comando WRITE SAME intentará escribir ceros en el dispositivo. Si se proporciona el archivo IF y la opción --xferlen=LEN no se da, la longitud de los datos de salida será la longitud del archivo IF.
--lba=LBA
Donde LBA es la dirección de bloque lógico de inicio. El valor predeterminado es 0.
--num=NUM
Donde NUM es el número de bloques lógicos a escribir. Si NUM es 0, se escribirán bloques hasta el final del dispositivo. El valor predeterminado es 1.
--ndob
No envía un bloque de datos de salida. Esto es útil para el saneamiento de datos y puede ser más eficiente que enviar un bloque lleno de ceros. En Linux, esto se traduce en el flag --unmap si no se dan datos de entrada explícitos. Si se dan datos de entrada, se utiliza el flag --unmap si el bloque de datos de salida está lleno de ceros.
--protection=PROT
Establece el campo PROT (protección) en el CDB. Los valores son 0, 1, 2, 3. El valor predeterminado es 0. Consulte la especificación SBC-3 para obtener detalles.
--unmap
Establece el bit UNMAP en el CDB. Esto indica al dispositivo que los bloques que se van a escribir ya no están en uso. Esto es útil para liberar espacio en dispositivos de almacenamiento de aprovisionamiento lógico (por ejemplo, SSDs). Si se utiliza con datos de entrada, los datos deben ser ceros, y si se utiliza sin datos de entrada, el dispositivo puede rellenar los bloques con un patrón de inicialización de aprovisionamiento.
--xferlen=LEN
Donde LEN es la longitud del búfer de datos de salida. El valor predeterminado es la longitud del archivo IF o, si no se proporciona, se utiliza el comando READ CAPACITY (16 o 10) para encontrar la 'Longitud lógica del bloque en bytes'. Esa cifra puede incrementarse en 8 bytes si el tipo de protección del DEVICE es 1 o superior y el campo WRPROTECT (ver --wrprotect=WPR) es 1 o superior. Si se dan ambas opciones, esta y la opción IF, y LEN excede la longitud del archivo IF, entonces LEN es la longitud del búfer de datos de salida con ceros utilizados como bytes de relleno.

UNMAP

El aprovisionamiento de bloques lógicos es un término nuevo introducido en SBC-3 revisión 25 para la capacidad de marcar bloques como no utilizados. Para matrices de almacenamiento grandes, es una forma de aprovisionar menos almacenamiento físico del que el comando READ CAPACITY informa que está disponible, asignando potencialmente más almacenamiento físico cuando los comandos WRITE lo requieren. Para memoria flash (por ejemplo, unidades SSD), es una forma de ahorrar potencialmente energía (y quizás tiempo de acceso) cuando se sabe que grandes secciones (o casi todas) de la memoria flash no están en uso. Las SSDs necesitan algoritmos de nivelación de desgaste para tener una resistencia aceptable y típicamente sobre-aprovisionan para simplificar esos algoritmos; por lo tanto, típicamente contienen más almacenamiento flash físico del que su tamaño lógico dictaría.

La compatibilidad con el aprovisionamiento de bloques lógicos se indica mediante el bit LBPME establecido en la respuesta del comando READ CAPACITY (16) (ver la utilidad sg_readcap). Eso implica que al menos uno de los comandos UNMAP o WRITE SAME (16) está implementado. Si el comando UNMAP está implementado, entonces los campos "Recuento máximo de LBA de desmapeo" y "Recuento máximo de descriptores de bloque de desmapeo" en la página Block Limits VPD deberían ser ambos mayores que cero. La respuesta del comando READ CAPACITY (16) también contiene un bit LBPRZ que, si está establecido, significa que si se leen bloques desmapeados, se devolverán ceros para los datos (y si la información de protección está activa, se devolverán bytes 0xff para ella). En SBC-3 revisión 27, el mismo bit LBPRZ se agregó a la página Logical Block Provisioning VPD.

Cuando el bit UNMAP está establecido en el cdb, también se envía el búfer de datos de salida. Adicionalmente, la sección de datos de ese búfer de datos de salida debe estar llena de bytes 0x0, mientras que el bloque de protección de datos, 8 bytes al final si está presente, debe establecerse en bytes 0xff. Si estas condiciones no se cumplen y el bit LBPRZ está establecido, entonces el bit UNMAP se ignora y el búfer de datos de salida se escribe en el DEVICE como si el bit UNMAP fuera cero. En ausencia de la opción --in=IF, esta utilidad intentará construir un búfer de datos de salida que cumpla los requisitos para que el bit UNMAP en el cdb sea procesado por el DEVICE.

Los bloques lógicos también pueden ser desmapeados por los comandos SCSI UNMAP y FORMAT UNIT (ver las utilidades sg_unmap y sg_format).

La capacidad de desmapeo en SCSI está estrechamente relacionada con el comando ATA DATA SET MANAGEMENT con el bit "Trim" establecido. Esa capacidad ATA trim no interactúa bien con la cola de comandos SATA conocida como NCQ. T13 ha introducido un nuevo comando llamado SFQ DATA SET MANAGEMENT también con el bit "Trim" para abordar ese problema. Los comandos SCSI WRITE SAME con el bit UNMAP establecido y los comandos UNMAP no tienen problemas con la cola de comandos SCSI.

NOTES

Varios argumentos numéricos (por ejemplo, LBA) pueden incluir sufijos multiplicativos o darse en hexadecimal. Ver la sección "ARGUMENTOS NUMÉRICOS" en la página de manual sg3_utils(8).

En Linux, antes de lk 3.17, el controlador sg no soportaba tamaños de cdb mayores de 16 bytes. Por lo tanto, un nodo de dispositivo como /dev/sg1 que está asociado con el controlador sg fallaría con esta utilidad si se daba la opción --32 (o si era implicada por otras opciones). El controlador bsg con nodos de dispositivo como /dev/bsg/6:0:0:1 soporta tamaños de cdb mayores de 16 bytes desde su introducción en lk 2.6.28.

EXIT STATUS

El estado de salida de sg_write_same es 0 cuando tiene éxito. De lo contrario, ver la página de manual sg3_utils(8).

EXAMPLES

TENGA CUIDADO: todos estos ejemplos sobrescribirán los datos en uno o más bloques, ¡potencialmente BORRANDO TODO EL DISCO!

Un uso simple es escribir bloques de ceros desde (e incluyendo) un LBA dado para 63 bloques:


sg_write_same --lba=0x1234 --num=63 /dev/sdc

Dado que no se ha proporcionado --xferlen=LEN, esta utilidad llamará al comando READ CAPACITY en /dev/sdc para determinar el número de bytes en un bloque lógico. Supongamos que son 512 bytes. Dado que no se proporciona --in=IF, se asume un bloque de ceros. Por lo tanto, se escribirán 63 bloques de ceros (cada bloque que contiene 512 bytes) desde (e incluyendo) el LBA 0x1234. Tenga en cuenta que solo se pasa un bloque de ceros al comando SCSI WRITE SAME en el búfer de datos de salida (según lo requiere SBC-3). Usar el comando SCSI WRITE SAME para escribir uno o más bloques de ceros es equivalente al comando NVMe: Write Zeroes.

Ahora escribiremos bloques de ceros en TODO el disco. [Nota: los comandos de saneamiento de datos también borrarán bloques y metadatos que no son directamente visibles]:


sg_write_same --lba=0x0 --num=0 /dev/sdc

Sí, en este contexto --num=0 significa el resto del disco. La invocación anterior puede dar un error debido a que el bit WSNZ en la página VPD Block Limits está configurado. Para sortear eso, intente:


sg_write_same --lba=0x0 --ndob /dev/sdc

Esta invocación, si es compatible, tiene el beneficio añadido de no enviar un bloque de datos de salida de ceros. Tenga en cuenta que es posible que el "patrón de inicialización de aprovisionamiento" se escriba en cada bloque en lugar de ceros.

Un ejemplo similar sigue, pero en este caso los bloques se "desmapean" ("trimean" en lenguaje ATA) en lugar de ser puestos a cero:


sg_write_same --unmap -L 0x1234 -n 63 /dev/sdc

Tenga en cuenta que si el bit LBPRZ en la respuesta de READ CAPACITY (16) está establecido (es decir, LPPRZ es un acrónimo de logical block provisioning read zeros), entonces estos dos ejemplos hacen lo mismo, al menos desde el punto de vista de lecturas posteriores.

Esta utilidad también se puede utilizar para escribir información de protección (PI) en discos formateados con un tipo de protección mayor que cero. La PI son 8 bytes de datos adicionales que se añaden a los datos del usuario de un bloque lógico: los dos primeros bytes son una CRC (el "guard"), los dos siguientes bytes son la "etiqueta de aplicación" y los últimos cuatro bytes son la "etiqueta de referencia". Con los tipos de protección 1 y 2, si la etiqueta de aplicación es 0xffff, entonces el guard no debe ser verificado (contra los datos del usuario).

En este ejemplo, asumimos que el tamaño del bloque lógico (de los datos del usuario) es de 512 bytes y que el disco ha sido formateado con el tipo de protección 1. Dado que vamos a modificar el LBA 2468, primero hacemos una copia:


dd if=/dev/sdb skip=2468 bs=512 of=2468.bin count=1

La siguiente línea de comandos establece los datos del usuario en ceros y la PI en 8 bytes 0xFF en el LBA 2468:


sg_write_same --lba=2468 /dev/sdb

Leer de nuevo ese bloque debería ser exitoso porque la etiqueta de aplicación es 0xffff, lo que suprime la verificación del guard (CRC) (que de lo contrario sería incorrecta):


dd if=/dev/sdb skip=2468 bs=512 of=/dev/null count=1

Ahora se intenta crear un archivo binario con ceros en los datos del usuario, 0x0000 en la etiqueta de aplicación y bytes 0xff en los otros dos campos de PI. Es difícil crear bytes 0xff en un archivo (en Unix) como muestra el siguiente comando "tr":


dd if=/dev/zero bs=1 count=512 of=ud.bin
tr "\000" "\377" < /dev/zero | dd bs=1 of=ff_s.bin count=8
cat ud.bin ff_s.bin > lb.bin
dd if=/dev/zero bs=1 count=2 seek=514 conv=notrunc of=lb.bin

El archivo resultante se puede ver con 'hexdump -C lb.bin' y debería contener 520 bytes. Ahora ese archivo se puede escribir en el LBA 2468 de la siguiente manera:


sg_write_same --lba=2468 wrprotect=3 --in=lb.bin /dev/sdb

Nota el --wrprotect=3 en lugar de 1, ya que queremos que el comando WRITE SAME tenga éxito aunque los datos de PI ahora indiquen que los datos del usuario están corruptos. Cuando se intenta leer el LBA, debería ocurrir un error:


dd if=/dev/sdb skip=2468 bs=512 of=/dev/null count=1

Los errores de dd no son muy expresivos; si se revisa dmesg, debería haber una línea similar a esta: "[sdb] Add. Sense: Logical block guard check failed". El bloque se puede corregir haciendo de nuevo un "sg_write_same --lba=1234 /dev/sdb" o restaurando el contenido original de ese LBA:


dd if=2468.bin bs=512 seek=2468 of=/dev/sdb conv=notrunc count=1

Esperemos que el comando dd nunca intente truncar el archivo de salida cuando este es un dispositivo de bloque.

sg_write_same(8)

SG3_UTILS

NOMBRE

sg_write_same - send SCSI WRITE SAME command

SINOPSIS

sg_write_same [OPTIONS] DEVICE

DESCRIPCIÓN

This utility sends the SCSI WRITE SAME (16) command to the given DEVICE. WRITE SAME is used to write identical data to a range of logical blocks. This can be useful for initializing disk media.

The data written is a block of zeros of the size given by the block size of the device. This data is broadcast across the specified logical block address (LBA) range.

The DEVICE is typically a block device file such as /dev/sda or /dev/sg0.

OPCIONES

-d, --data_type=DT
Set the DATA TYPE field in the WRITE SAME cdb. DT can be 0 (unspecified) or 1 (write same is specified for all blocks). Default is 0.
-f, --force
Force the WRITE SAME command even if the device reports that it does not support it. Use with caution.
-i, --immutable
Set the IMMUTABLE bit in the WRITE SAME cdb. This bit indicates that the data written should be immutable and cannot be overwritten by a WRITE SAME command with the IMMUTABLE bit cleared.
-l, --lb_count=LC
Set the logical block count field in the WRITE SAME cdb. This specifies the number of logical blocks to write the same data to. Default is 1. Maximum value depends on the CDB size (16-bit for CDBs less than 256 bytes, 32-bit for CDBs 256 bytes or larger).
-p, --protect=PR
Set the PROTECT field in the WRITE SAME cdb. PR can be 0 (no protection), 4 (write protect) or 5 (read protect). Default is 0.
-s, --start_lba=LBA
Set the logical block address (LBA) from which to start writing. Default is 0.
-t, --sense_len=SCL
Set the sense data length for the command. Default is 96 bytes.
-v, --verbose
Increase verbosity.
-w, --wwn=WWN
Set the WRITE SAME NOW (WSN) bit in the WRITE SAME cdb. This bit indicates that the WRITE SAME command should be executed immediately and not deferred. This option is only applicable if the device supports WRITE SAME NOW.
-X, --hex_lba
Treat the LBA argument as a hexadecimal number.

UNMAP

The WRITE SAME command can also be used to unmap blocks, effectively freeing up space on the underlying storage. To use this feature, set the DATA TYPE field to 2 (unmap).

sg_write_same -d 2 --lb_count=LC --start_lba=LBA DEVICE

NOTES

Some devices may not support the WRITE SAME command. Use `sg_inq` to check for command support.

Be cautious when using WRITE SAME, as it can overwrite data. It is recommended to back up any important data before using this command.

ESTADO DE SALIDA

The exit status of sg_write_same is 0 when the command completes successfully. Otherwise, it is a non-zero value indicating the error.

EJEMPLOS

Write identical data to 10 blocks starting from LBA 100 on /dev/sda: 

    sg_write_same --lb_count=10 --start_lba=100 /dev/sda

Unmap 5 blocks starting from LBA 200 on /dev/sdb: 

    sg_write_same --data_type=2 --lb_count=5 --start_lba=200 /dev/sdb
