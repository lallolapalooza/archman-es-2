sg_get_fs_stats(3) sg_get_fs_stats(3)

NOMBRE

sg_get_fs_stats, sg_get_fs_stats_r, sg_get_fs_stats_diff, sg_get_fs_stats_diff_between, sg_free_fs_stats, sg_get_valid_filesystems, sg_set_valid_filesystems, sg_fs_compare_device_name, sg_fs_compare_mnt_point - obtener estadísticas del sistema de archivos

#include <statgrab.h>


sg_fs_stats *sg_get_fs_stats
(size_t *entries);

sg_fs_stats *sg_get_fs_stats_diff

sg_fs_stats *sg_get_fs_stats_diff_between
(const sg_fs_stats *cur, const sg_fs_stats *last, size_t *entries);


sg_error sg_free_fs_stats
(sg_fs_stats *data);


const char **sg_get_valid_filesystems
(size_t *entries);

int sg_fs_compare_device_name

(const void *va, const void *vb);

DESCRIPCIÓN

Las funciones sg_get_fs_stats proporcionan estadísticas de los sistemas de archivos montados. Ambas funciones toman un parámetro opcional de entradas, que apunta (cuando se proporciona) a un size_t para obtener el número de entradas de vector devueltas.

Las funciones sg_get_fs_stats() y sg_get_fs_stats_r() entregan las estadísticas del sistema de archivos del momento en que se llama a la función. sg_get_fs_stats_diff() y sg_get_fs_stats_diff_between() entregan la diferencia entre dos llamadas a sg_get_fs_stats() o sg_get_fs_stats_r(), respectivamente.

Atajo de API

función devuelve propietario de los datos
sg_get_fs_stats sg_fs_stats * libstatgrab (hilo local)
sg_get_fs_stats_r sg_fs_stats * llamador
sg_get_fs_stats_diff sg_fs_stats * libstatgrab (hilo local)
sg_get_fs_stats_diff_between sg_fs_stats * llamador
sg_get_valid_filesystems char ** libstatgrab (global)

Los vectores de sg_fs_stats recibidos de sg_get_fs_stats_r() o sg_get_fs_stats_diff_between() deben liberarse usando sg_free_fs_stats() cuando ya no se necesiten. El llamador es responsable de hacerlo.

La biblioteca statgrab viene con una lista incorporada de tipos de sistemas de archivos válidos según el sistema operativo para el que fue compilada. Algunos sistemas operativos también proporcionan una API para conocer los tipos de sistemas de archivos conocidos o válidos para la instancia del sistema operativo en ejecución, que se utiliza cuando se detecta. Sin embargo, existen problemas conocidos al recopilar estadísticas del sistema de archivos: los sistemas de archivos de red se montan desde servidores remotos, los desarrolladores de sistemas de archivos ejecutan un controlador experimental, etc.

Para evitar que los procesos se cuelguen al obtener estadísticas del sistema de archivos o para permitir a los desarrolladores probar sus controladores, los procesos pueden modificar la lista de sistemas de archivos válidos utilizando sg_get_valid_filesystems() y sg_set_valid_filesystems(). La lista de parámetros char * con los que trabajan ambas funciones siempre termina con un elemento que apunta a NULL.

La lista devuelta por sg_get_valid_filesystems() no debe modificarse. Siempre copie la lista en su propia estructura si planea extender o reducir la lista:

Ejemplo de eliminación de sistemas de archivos de red

int compare_fs_type(const void *va, const void *vb) {
    const char **a = (const char **)va;
    const char **b = (const char **)vb;
    return strcmp( *a, *b );
}
void filter_network_fs_types(void) {
    /* nombres de sistemas de archivos de red conocidos en diferentes plataformas */
    const char *nfs_types[] = { "nfs", "nfs3", "nfs4", "cifs", "smbfs", "samba" };
    const size_t nfs_types_count = sizeof(nfs_types) / sizeof(nfs_types[0])
    size_t fs_entries = 0;
    const char **orig_valid_fs = sg_get_valid_filesystems(&fs_entries);
    /* duplicar en memoria propia para modificar la lista */
    char **valid_fs = calloc( entries + 1, sizeof(valid_fs[0]) );
    memcpy( valid_fs, orig_valid_fs, (entries + 1) * sizeof(valid_fs[0]) );
    size_t i;
    for( i = 0; i < nfs_types_count; ++i ) {
        char **inv_fs = bsearch( &nfs_types[i], &valid_fs[0],
                                 fs_entries, sizeof(valid_fs[0]),
                                 compare_fs_type );
        if( NULL != inv_fs ) {
            /* copiar incluyendo el puntero NULL final */
            memmove( inv_fs, inv_fs + 1, fs_entries - (inv_fs - valid_fs) );
            --fs_entries;
        }
    }
    sg_set_valid_filesystems( valid_fs );
    free( valid_fs );
}

Tenga en cuenta que no es necesario duplicar las cadenas contenidas en la lista de sistemas de archivos válidos en el ejemplo anterior; no se modifican.

La lista devuelta por sg_get_valid_filesystems() podría invalidarse cuando se utiliza mientras el proceso realiza llamadas a sg_set_valid_filesystems(). Ninguna de las funciones sg_fs_stats protege el acceso al almacenamiento utilizado globalmente donde se mantiene la copia propia de la lista de sistemas de archivos válidos. Es responsabilidad del llamador no mezclar llamadas de configuración con llamadas para obtener estadísticas.

Además, hay dos funciones de soporte para qsort(3): sg_fs_compare_device_name() y sg_fs_compare_mnt_point().

Ejemplo de ordenación

size_t entries;
sg_fs_stats *fs_stats = NULL;
while( NULL != ( fs_stats = sg_get_fs_stats_diff(&entries) ) ) {
    /* ordenar entradas alfabéticamente usando el punto de montaje */
    qsort( fs_stats, entries, sizeof(fs_stats[0]), &sg_fs_compare_mnt_point );
    show_fs_stats( fs_stats );
}

VALORES DE RETORNO

sg_get_fs_stats devuelve un puntero a una estructura de tipo sg_fs_stats.

typedef enum {
        sg_fs_unknown  = 0,
        sg_fs_regular  = 1 << 0,
        sg_fs_special  = 1 << 1,
        sg_fs_loopback = 1 << 2,
        sg_fs_remote   = 1 << 3,
        sg_fs_local    = (sg_fs_regular | sg_fs_special),
        sg_fs_alltypes = (sg_fs_regular | sg_fs_special | sg_fs_loopback | sg_fs_remote)
} sg_fs_device_type;

typedef struct {
        char *device_name;
        char *fs_type;
        char *mnt_point;
        sg_fs_device_type device_type;
        unsigned long long size;
        unsigned long long used;
        unsigned long long free;
        unsigned long long avail;
        unsigned long long total_inodes;
        unsigned long long used_inodes;
        unsigned long long free_inodes;
        unsigned long long avail_inodes;
        unsigned long long io_size;
        unsigned long long block_size;
        unsigned long long total_blocks;
        unsigned long long free_blocks;
        unsigned long long used_blocks;
        unsigned long long avail_blocks;
        time_t systime;
} sg_fs_stats;
device_name
El nombre conocido por el sistema operativo. (por ejemplo, en linux podría ser hda)
fs_type
El tipo de sistema de archivos del sistema de archivos (por ejemplo, hpfs o ufs).
mnt_point
El punto de montaje en el que está montado el sistema de archivos.
device_type
El tipo de dispositivo del sistema de archivos, actualmente no se rellena y siempre es sg_fs_unknown.
size
El tamaño total, en bytes, del sistema de archivos.

size = used + free

used
La cantidad de espacio, en bytes, utilizada en el sistema de archivos.
avail
La cantidad de espacio, en bytes, disponible en el sistema de archivos para el usuario.

sg_set_valid_filesystems(3) — libstatgrab

NAME

sg_set_valid_filesystems, sg_get_valid_filesystems - set or get the list of valid file systems

SYNOPSIS

#include <statgrab.h>

void sg_set_valid_filesystems(const char *const *filesystems);
char *const * sg_get_valid_filesystems(void);

DESCRIPTION

The sg_set_valid_filesystems function allows you to specify a list of file systems that you want libstatgrab to pay attention to. By default libstatgrab pays attention to all file systems that it can identify. The list of file systems should be terminated by a NULL pointer.

The sg_get_valid_filesystems function returns a pointer to the current list of valid file systems. The returned list is terminated by a NULL pointer. The returned list should not be modified by the caller. If you need to modify the list you should make a copy of it.

RETURN VALUES

sg_get_valid_filesystems returns a list of strings terminated by a NULL pointer. Each string in the list is the name of a file system that libstatgrab will pay attention to. If no file systems have been specified, then a list containing only a NULL pointer is returned.

The returned list is owned by the caller and should be freed using free when no longer needed. Note that the strings themselves are owned by libstatgrab and should not be freed.

The following structure members are available in the Sg_fs_stats structure:

total_space
The total space on the file system in bytes.
free_space
The free space on the file system in bytes.
reserved_space
The space reserved for the super-user on the file system in bytes.
avail_space
The free space available to non-privileged users/processes (free space less reserved space).

avail = free - reserved

free
The amount of space, in bytes, free on the file system.
total_inodes
The total number of inodes in the file system.
used_inodes
The number of used inodes in the file system.
free_inodes
The number of free inodes in the file system.
avail_inodes
The number of free inodes available to non-privileged processes.
io_size
A suggested optimal block size for I/O operations -- if you're reading or writing lots of data, do it in chunks of this size.
block_size
The size in bytes of the minimum unit of allocation on this file system.
total_blocks
The total number of blocks in the file system.
free_blocks
The number of free blocks in the file system.
used_blocks
The number of used blocks in the file system.
avail_blocks
The number of free blocks available to non-privileged processes.
systime
The time in seconds since epoch when the statistic was retrieved from kernel.

BUGS

Only mounted file systems are recognised.

Some file systems might be reported twice when mounted on different mount points.

The compare functions exist rather for backward compatibility than for functionality enhancements. Limited flexibility (e.g. reverse order) and lack of optimising opportunities for the compiler leads to the recommendation to implement the required compare routines locally.

Calling sg_set_valid_filesystems with an empty list with clear the internal list of valid file systems. There's currently no way to reset to the initial list.
