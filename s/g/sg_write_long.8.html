NOMBRE

sg_write_long - enviar comando SCSI WRITE LONG

SINOPSIS

sg_write_long [--16] [--cor_dis] [--help] [--in=IF] [--lba=LBA] [--pblock] [--verbose] [--version] [--wr_uncor] [--xfer_len=BTL] DEVICE

DESCRIPCIÓN

Envía el comando SCSI WRITE LONG (10 o 16 bytes) al DEVICE. El búfer que se va a escribir en el DEVICE se rellena con bytes 0xff o se lee del archivo IF. Este búfer incluye los datos lógicos (por ejemplo, 512 bytes) y los bytes ECC.

Esta utilidad se puede usar para generar un ERROR DE MEDIO en una dirección de bloque lógico específica. Esto puede ser útil para probar el manejo de errores. Antes de una prueba de este tipo, la utilidad sg_dd podría usarse para copiar el contenido original de la dirección del bloque lógico a una ubicación segura. Después de la prueba, la utilidad sg_dd podría usarse para reescribir el contenido original de la dirección del bloque lógico. Una estrategia alternativa sería leer el contenido "largo" de la dirección del bloque lógico con la utilidad sg_read_long antes de la prueba y restaurarlo con esta utilidad después de la prueba.

Tenga cuidado: Si se están inyectando errores recuperables (por ejemplo, solo uno o unos pocos bits cambiados de modo que el ECC pueda corregir los datos), se debe tener cuidado con la configuración en la página de modo de recuperación de errores de lectura/escritura. Específicamente, si los bits ARRE (para lecturas) y/o AWRE (para escrituras) están establecidos, los errores recuperados causarán que el lba sea reasignado (y la ubicación antigua se agregará a la lista de defectos crecidos (PLIST)). Esto no es fácilmente reversible y utiliza (uno de los números finitos de) sectores de respaldo reservados para este propósito. En caso de duda, probablemente sea más seguro borrar los bits ARRE y AWRE. Estos bits se pueden verificar y modificar con la utilidad sdparm. Por ejemplo: "sdparm -c AWRE,ARRE /dev/sda" borrará los bits hasta que el disco se apague.

En SBC-4 revisión 7, todos los usos de los comandos SCSI WRITE LONG (10 y 16 bytes) se volvieron obsoletos, excepto en el caso en que el bit WR_UNCOR esté establecido. Los comandos SCSI READ LONG (10 y 16 bytes) se volvieron obsoletos en la misma revisión.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas.

-S, --16
envía un comando SCSI WRITE LONG (16) al DEVICE. La acción por defecto (en ausencia de esta opción) es enviar un comando SCSI WRITE LONG (10).
-c, --cor_dis
establece el bit de corrección deshabilitada (es decir, 'COR_DIS'). Esto inhibe varios otros mecanismos como la reasignación automática de bloques, la recuperación de errores y la activación de varias condiciones de excepción informativas. Este bit es relativamente nuevo en SBC-3.
-h, --help
muestra el mensaje de uso y luego sale.
-i, --in=IF
lee datos (binarios) del archivo llamado IF y los usa para el comando SCSI WRITE LONG. Si IF es "-", se lee desde la entrada estándar. Si no se proporciona esta opción, se usan bytes 0xff como relleno.
-l, --lba=LBA
donde LBA es la dirección del bloque lógico del sector a sobrescribir. Por defecto es lba 0, que es un bloque peligroso de sobrescribir en un disco en uso. Se asume en decimal a menos que esté prefijado con '0x' o tenga una 'h' al final. Si LBA es mayor de lo que cabe en 32 bits, se debe usar la opción --16.
-p, --pblock
establece el bit de bloque físico (es decir, 'PBLOCK'). Esto instruye al DEVICE a usar los datos proporcionados (a menos que también se proporcione --wr_uncor) para escribir en el bloque físico especificado por LBA. La acción por defecto es escribir en el bloque lógico correspondiente al lba dado. Este bit es relativamente nuevo en SBC-3.
-v, --verbose
aumenta el grado de verbosidad (mensajes de depuración).
-V, --version
muestra la cadena de versión y luego sale.
-w, --wr_uncor
establece el bit de "escritura sin corregir" (es decir, 'WR_UNCOR'). Esto instruye al DEVICE a marcar el lba dado (o el bloque físico que lo contiene si también se proporciona --pblock) como si tuviera un error irrecuperable asociado. Nota: no se transfieren datos al DEVICE, aparte del comando (es decir, el cdb). En ausencia de esta opción, la acción por defecto es usar los datos proporcionados o bytes 0xff (de longitud --xfer_len=BTL) y escribirlos en el DEVICE. Este bit es relativamente nuevo en SBC-3.
-x, --xfer_len=BTL
donde BTL es la longitud de transferencia de bytes (por defecto 520). Si el valor proporcionado (o el valor por defecto) no coincide con el tamaño de bloque "largo" del dispositivo, no se escribe nada en el DEVICE y el valor xfer_len apropiado puede deducirse de la respuesta de error que se imprime (en stderr).

NOTAS

Varios argumentos numéricos (por ejemplo, LBA) pueden incluir sufijos multiplicativos o darse en hexadecimal. Consulte la sección "ARGUMENTOS NUMÉRICOS" en la página del manual sg3_utils(8).

El comando SCSI WRITE LONG de 10 bytes limita la dirección del bloque lógico a una cantidad de 32 bits. Para LBAs más grandes, use la opción --16 para el comando SCSI WRITE LONG (16).

EJEMPLOS

Esta sección describe cómo configurar un bloque con datos corruptos, verificar la condición de error y luego restaurar el contenido útil en ese sector.

Primero, si los datos de un sector son importantes, guárdelos con la utilidad sg_read_long:


sg_read_long --lba=0x1234 --out=0x1234_1.img -x BTL /dev/sda

Es posible que esta utilidad deba ejecutarse varias veces para determinar cuál es el valor correcto de BTL. A continuación, use esta utilidad para "corromper" ese sector. Esto podría hacerse con:


sg_write_long --lba=0x1234 -x BTL /dev/sda

Esto escribirá un sector (y datos ECC) de bytes 0xff. Algunos discos pueden rechazar esto (al menos uno del autor lo hace). Otro enfoque es copiar el archivo 0x1234_1.img (a 0x1234_2.img en este ejemplo) y cambiar algunos valores con un editor hexadecimal. Luego escriba la imagen modificada con:


sg_write_long --lba=0x1234 --in=0x1234_2.img -x BTL /dev/sda

Sin embargo, otro enfoque es usar la opción --wr_uncor, si es compatible:


sg_write_long --lba=0x1234 --wr_uncor /dev/sda

A continuación, usamos la utilidad sg_dd para verificar que el sector está corrupto. Aquí hay un ejemplo:


sg_dd if=/dev/sda blk_sgio=1 skip=0x1234 of=. bs=512 count=1 verbose=4

Tenga en cuenta que se proporciona la opción "blk_sgio=1". Esto es para asegurarse de que el sector se lea (y no otros) y que el error se informe por completo. La opción "blk_sgio=1" hace que sg_dd utilice la llamada al sistema SG_IO en lugar del subsistema de bloques.

Finalmente, deberíamos restaurar el sector 0x1234 a un estado no corrupto. Un sector lleno de ceros se puede escribir con:


sg_dd if=/dev/zero of=/dev/sda blk_sgio=1 seek=0x1234 bs=512 count=1

Esto resultará en un sector (bloque) con 512 bytes de 0x0 sin un ERROR DE MEDIO, ya que el ECC y los datos asociados se regenerarán y, por lo tanto, estarán bien formados. La opción 'blk_sgio=1' es aún más importante en este caso, ya que puede evitar que el subsistema de bloques realice una lectura antes de escribir (ya que la lectura probablemente fallará). Otra opción es reescribir el contenido original:


sg_write_long --lba=0x1234 --in=0x1234_1.img -x BTL /dev/sda

ESTADO DE SALIDA

El estado de salida de sg_write_long es 0 cuando es exitoso. De lo contrario, consulte la página del manual sg3_utils(8).
