NOMBRE

sg_inq - emite el comando SCSI INQUIRY y/o decodifica su respuesta

SINOPSIS

sg_inq [--ata] [--block=0|1] [--cmddt] [--descriptors] [--export] [--extended] [--force] [--help] [--hex] [--id] [--inhex=FN] [--json[=JO]] [--js-file=JFN] [--len=LEN] [--long] [--maxlen=LEN] [--only] [--page=PG] [--quiet] [--raw] [--sinq_inraw=RFN] [--vendor] [--verbose] [--version] [--vpd] DISPOSITIVO

sg_inq [-36] [-a] [-A] [-b] [--B=0|1] [-c] [-cl] [-d] [-e] [-f] [-h] [-H] [-i] [-I=FN] [-j[=JO]] [-l=LEN] [-L] [-m] [-M] [-o] [-p=VPD_PG] [-P] [-q] [-r] [-s] [-u] [-v] [-V] [-x] [-36] [-?] DISPOSITIVO

DESCRIPCIÓN

Esta utilidad, cuando se le proporciona DISPOSITIVO, le envía un comando SCSI INQUIRY y luego muestra la respuesta. Se espera que todos los dispositivos SCSI respondan a un comando INQUIRY "estándar" con al menos una respuesta de 36 bytes (en SCSI 2 y superior). Una INQUIRY se denomina "estándar" cuando las banderas EVPD y CmdDt (ahora obsoleta) están despejadas. Formalmente (es decir, según los estándares SPC), el nombre de una respuesta INQUIRY estándar es el "formato de datos INQUIRY estándar", pero aquí se usa la "respuesta INQUIRY estándar" ya que es más corta y descriptiva.

Alternativamente, se puede proporcionar la opción --inhex=FN. En este caso, se asume que FN es un nombre de archivo ('-' para stdin) que contiene hexadecimales ASCII que representan una respuesta INQUIRY.

Esta utilidad admite dos sintaxis de línea de comandos. La preferida se muestra primero en la sinopsis y se describe en la sección OPCIONES principal. Una sección posterior titulada OPCIONES DE LÍNEA DE COMANDOS ANTIGUAS describe el segundo grupo de opciones.

Una "página" INQUIRY "no estándar" importante es la página de datos de identificación del dispositivo (VPD) [0x83]. Desde SPC-3, el soporte para esta página es obligatorio. La utilidad --id decodifica esta página. Ya no se agregan nuevas informaciones de páginas VPD a esta utilidad. La utilidad sg_vpd(8) está especializada en decodificar páginas VPD y comparte código con esta utilidad para ese propósito. La utilidad sdparm(8), que se encuentra en un paquete con ese nombre, también decodifica páginas VPD, aunque su propósito principal es acceder y modificar páginas de modo SCSI.

En Linux, si el DISPOSITIVO existe y el SCSI INQUIRY falla (por ejemplo, porque el ioctl SG_IO no es compatible), entonces se intenta un ATA IDENTIFY (PACKET) DEVICE. Si tiene éxito, se muestran cadenas de identificación del dispositivo. Las opciones --raw y --hex se pueden usar para manipular la salida. Si se proporciona la opción --ata, no se realiza el SCSI INQUIRY y se asume que el DISPOSITIVO es ATA (o ATAPI). Para más información, vea la sección DISPOSITIVOS ATA a continuación.

En algunos sistemas operativos, se puede proporcionar un dispositivo NVMe (por ejemplo, SSD) como DISPOSITIVO. Para más información, vea la sección DISPOSITIVOS NVME a continuación.

El documento de referencia utilizado para interpretar una INQUIRY es T10/BSR INCITS 566 Revisión 6, que es el borrador SPC-6 con fecha del 22 de octubre de 2021. Se puede encontrar en https://www.t10.org . Los elementos obsoletos y reservados en la salida de respuesta INQUIRY estándar se muestran entre corchetes.

OPCIONES

Los argumentos de las opciones largas son obligatorios también para las opciones cortas. Las opciones están ordenadas alfabéticamente según el nombre de la opción larga.

-a, --ata
Asume que el DISPOSITIVO dado es un dispositivo ATA o ATAPI que puede recibir comandos ATA del sistema operativo anfitrión. Omite el comando SCSI INQUIRY y utiliza el comando ATA IDENTIFY DEVICE (para dispositivos que no son de paquete) o el comando ATA IDENTIFY PACKET DEVICE. Para mostrar la respuesta en hexadecimal, agregue la opción '--verbose'. Esta opción solo está disponible en Linux.
-B, --block=0|1
esta opción controla cómo se abre el manejador de archivos para el DISPOSITIVO. Si este argumento es 0, la apertura es no bloqueante. Si el argumento es 1, la apertura es bloqueante. En Unix, una apertura no bloqueante se indica con una bandera O_NONBLOCK, mientras que una apertura bloqueante se indica con la ausencia de esa bandera. El valor predeterminado depende del sistema operativo y del tipo de nodo DISPOSITIVO. Para las pasarelas de Linux (es decir, los controladores sg y bsg), el valor predeterminado es 0.
-c, --cmddt
establece la bandera Command Support Data (CmdDt) (por defecto está despejada(0)). Se utiliza junto con la opción --page=PG donde PG especifica el opcode del comando SCSI a consultar. Cuando se usa dos veces (por ejemplo, '-cc'), esta utilidad forma una lista iterando sobre todos los opcodes (de 0 a 255 inclusive), mostrando solo una línea para los comandos que se encuentran. La bandera CmdDt ahora está obsoleta; ha sido reemplazada por el comando REPORT SUPPORTED OPERATION CODES, vea la utilidad sg_opcodes(8).
-d, --descriptors
decodifica e imprime los descriptores de versión encontrados en una respuesta INQUIRY estándar. Hay hasta 8 de ellos. Los descriptores de versión indican con qué versiones de estándares y/o borradores cumple el DISPOSITIVO. Se muestran los componentes normales de una INQUIRY estándar (típicamente de los primeros 36 bytes de la respuesta) seguidos por los descriptores de versión, si los hay.
-e
vea la entrada más abajo para --vpd.
-f, --force
Como verificación de seguridad, la acción normal al obtener páginas VPD distintas de la página 0x0 (la página VPD de "Páginas VPD Soportadas") es primero obtener la página 0x0 y solo si la página solicitada es una de las páginas soportadas, proceder a obtener la página solicitada.
Cuando se proporciona esta opción, omite la verificación de la página VPD 0x0 antes de acceder a la página VPD solicitada. La verificación previa de la página VPD 0x0 ha demostrado causar fallos en ciertos dispositivos USB, así que úsela con precaución.
-u, --export
imprime la información obtenida del dispositivo. La salida se puede modificar seleccionando una página VPD con PG (desde --page=PG). Si se proporciona la página VPD de identificación del dispositivo 0x83, imprime la información en el formato: "SCSI_IDENT_<assoc>_<type>=<ident>" a stdout. Si se proporciona la página VPD del número de serie del dispositivo 0x80, imprime la información en el formato: "SCSI_SERIAL=<ident>". Otras páginas VPD no son compatibles. Si no se proporciona ninguna página VPD, imprime la información en el formato: "SCSI_VENDOR=<vendor>", "SCSI_MODEL=<model>" y "SCSI_REVISION=<rev>", tomados de la consulta estándar. Esto puede ser útil para herramientas como udev(7) en Linux.
-E, -x, --extended
imprime la página VPD de INQUIRY extendida [0x86]. Tiene el mismo efecto que proporcionar la opción --page=ei.
-h, --help
imprime el mensaje de uso y luego sale. Cuando se usa dos veces, después del mensaje de uso, hay una lista de abreviaturas disponibles que se pueden proporcionar a la opción --page=PG.
-H, --hex
en lugar de decodificar una respuesta INQUIRY estándar, una página VPD o datos de soporte de comandos; imprime la respuesta en hexadecimal y envía la salida a stdout. Los mensajes de error y las advertencias generalmente se envían a stderr. Cuando se usa dos veces con la página VPD de Información ATA [0x89], decodifica el inicio de la respuesta y luego muestra la respuesta ATA IDENTIFY (PACKET) DEVICE en bytes hexadecimales (no en palabras de 16 bits). Cuando se usa tres veces con la página VPD de Información ATA [0x89] o la opción --ata, esta utilidad muestra la respuesta ATA IDENTIFY (PACKET) DEVICE en palabras hexadecimales adecuadas para la entrada de 'hdparm --Istdin'. Vea la nota a continuación.
Para generar una salida adecuada para colocar en un archivo que pueda ser utilizado por una invocación posterior con la opción --inhex=FN, use la opción '-HHHH' (por ejemplo, 'sg_inq -p di -HHHH /dev/sg3 > dev_id.hex').
-i, --id
imprime la página VPD de identificación del dispositivo [0x83]. Tiene el mismo efecto que proporcionar la opción --page=di.
-I,
--inhex=FN
FN es el nombre de un archivo (o '-' para stdin) que contiene datos hexadecimales ASCII o binarios que representan una respuesta de INQUIRY (incluida una página VPD). Esta utilidad decodificará esa respuesta. Es preferible también proporcionar la opción --page=PG; si no, esta utilidad intentará adivinar a qué página VPD (o INQUIRY estándar) está asociada la respuesta. Los datos hexadecimales deben estar organizados como 1 o 2 dígitos representando un byte cada uno, separados por espacios en blanco o comas. Todo lo que comience con un signo de almohadilla (#) hasta el final de la línea se ignora. Si también se proporciona la opción --raw, entonces FN se trata como binario.
-j[=JO], --json[=JO]
La salida estará en formato JSON en lugar de texto plano. Tenga en cuenta que los argumentos para la forma corta y larga son opcionales y, si están presentes, comienzan con "=", y no se permiten espacios alrededor de ese "=".
Consulte la página del manual de sg3_utils_json o use '?' para JO para obtener un resumen.
-J, --js-file=JFN
La salida estará en formato JSON y se enviará a un archivo llamado JFN. Si ese archivo existe, se truncará. Por defecto, la salida JSON se envía a stdout.
Cuando se proporciona esta opción, la opción --json[=JO] se implica y no es necesario proporcionarla. La opción --json[=JO] aún puede ser necesaria para establecer el parámetro JO a valores distintos de los predeterminados.
-l, --len=LEN
El número LEN es el campo "longitud de asignación" en el CDB de INQUIRY. Esta es la longitud (máxima) de la respuesta devuelta por el dispositivo. El valor predeterminado de LEN es 0, que se interpreta como: la primera solicitud es de 36 bytes y, si es necesario, se ejecuta otra INQUIRY si el campo "longitud adicional" en la respuesta indica que hay más de 36 bytes disponibles.
Si LEN es mayor que 0, solo se realiza un comando INQUIRY. Esto significa que el número de serie (obtenido de la página VPD de número de serie (0x80)) no se recupera y, por lo tanto, no se imprime. Consulte la sección NOTAS a continuación sobre "INQUIRY de 36 bytes".
-L, --long
Esta opción hace que se decodifique más información del comando Identify enviado a un DEVICE NVMe.
-m, --maxlen=LEN
Esta opción tiene la misma acción que la opción --len=LEN anterior. Se ha añadido por compatibilidad con las utilidades sg_vpd, sg_modes y sg_logs.
-O, --old
Cambiar a opciones de estilo antiguo. Por favor, úsela como la primera opción en la línea de comandos.
-o, --only
No intentar recuperar adicionalmente la página VPD de número de serie (0x80) para mejorar la salida de una INQUIRY estándar. Por lo tanto, con esta opción dada y ninguna otra, esta utilidad enviará un comando SCSI INQUIRY estándar y decodificará su respuesta. No se enviarán otros comandos SCSI al DEVICE. Sin esta opción, se envía un comando SCSI adicional: una INQUIRY SCSI (no estándar) para obtener la página VPD de número de serie. Sin embargo, la página VPD de número de serie no es obligatoria (mientras que la página de identificación del dispositivo es obligatoria, pero mil millones de llaves USB la ignoran) y puede causar informes de error molestos. En la mayoría de los casos, si la opción --maxlen=LEN se proporciona y LEN es mayor que 0, esta opción no es necesaria.
Para dispositivos NVMe, solo se realiza la identificación del controlador, incluso si el DEVICE incluye un identificador de namespace. Por ejemplo, en FreeBSD, dado un DEVICE llamado /dev/nvme0ns1, se envía un Identify controller a /dev/nvme0 y no se envía nada a su namespace "ns1" (primer namespace).
-p, --page=PG
El argumento PG puede ser un número o una abreviatura de una página VPD. Para enumerar las abreviaturas disponibles para las páginas VPD, use '-hh' o una abreviatura incorrecta (por ejemplo, '--page=xxx'). Cuando se proporciona la opción --cmddt (una vez), entonces PG se interpreta como un número de opcode (por lo que las abreviaturas de página VPD tienen poco sentido).
Si PG es un número negativo, se realiza una INQUIRY estándar. Esto se puede usar para anular la lógica de adivinanza asociada con la opción --inhex=FN.
Si PG no se encuentra en la página VPD "Páginas VPD compatibles" (0x0), se devuelve EDOM. Para omitir esta verificación, use la opción --force.
-q, --quiet
Suprime la cantidad de decodificación y salida de errores.
-r, --raw
En ausencia de --inhex=FN, la respuesta de salida está en formato binario. La salida debe enviarse a través de una tubería a un archivo u otra utilidad cuando se utiliza esta opción. Los datos binarios se envían a stdout y los errores se envían a stderr.
Si se usa con --inhex=FN, el contenido de FN se trata como binario.
-Q, --sinq_inraw=RFN
donde RFN es un nombre de archivo que contiene datos binarios de respuesta de INQUIRY estándar que coinciden con DEVICE o FN. Linux coloca esta respuesta de INQUIRY estándar en su sistema de archivos pseudo sysfs. Una ubicación típica es /sys/class/scsi_device/<hctl>/device/inquiry, donde <hctl> es una tupla numérica de cuatro partes separada por dos puntos. Esta tupla distingue el dispositivo de cualquier otro en el sistema. Linux también coloca algunas respuestas de páginas VPD en formato binario en el mismo directorio con nombres como "vpd_pg83", donde los dos últimos dígitos forman el número de página VPD hexadecimal cuyos contenidos binarios están allí.
Algunas páginas VPD (por ejemplo, la página de Inquiry extendida) dependen de conocer la configuración en la respuesta de INQUIRY estándar para interpretar los campos en esa página VPD. Esta opción, junto con --all, --examine o --page=PG, permite que esta utilidad procese tanto la respuesta de INQUIRY estándar como las páginas VPD en la misma invocación.
La opción --raw no tiene efecto sobre esta opción. El argumento DEVICE puede proporcionarse con esta opción.
-s, --vendor
Imprime los campos específicos del vendedor de una respuesta de INQUIRY estándar desde el desplazamiento 36 hasta el 55 en ASCII. Cuando se usa dos veces (es decir, '-ss'), también imprime el campo específico del vendedor desde el desplazamiento 96 en ASCII. Esto solo se hace si los datos pasan algunas comprobaciones de sanidad simples.
-v, --verbose
Aumenta el nivel de verbosidad. Se puede usar varias veces.
-V, --version
Imprime la cadena de versión y sale.
-e, --vpd
Establece el bit Enable Vital Product Data (EVPD) (predeterminado a borrado (0)). Se usa en conjunto con la opción --page=PG, donde PG especifica el número de página VPD que se consultará. Si no se proporciona --page=PG, PG toma el valor predeterminado de cero, que es la página VPD de "Páginas VPD compatibles".

NOTAS

Algunos dispositivos con implementaciones de conjuntos de comandos SCSI débiles se bloquean cuando reciben comandos que no entienden (y algunos se bloquean si reciben longitudes de respuesta que no esperan). Dichos dispositivos deben tratarse con cuidado; utilice la opción '--len=36'. Sin esta opción, esta utilidad emitirá una INQUIRY estándar inicial solicitando 36 bytes de datos de respuesta. Si el dispositivo indica que podría haber suministrado más datos, se emitirá una segunda INQUIRY para obtener la respuesta más larga. Ese segundo comando puede bloquear dispositivos defectuosos.

Los dispositivos ATA o ATAPI que utilizan una capa de traducción SCSI a ATA (ver SAT en www.t10.org) pueden admitir la página VPD ATA Information. Esta devuelve la respuesta IDENTIFY (PACKET) DEVICE entre otras cosas. La página VPD ATA Information se puede obtener con '--page=ai'.

En la respuesta estándar de INQUIRY, hay un indicador 'MultiP' que se establece cuando el dispositivo tiene 2 o más puertos. Algunos fabricantes utilizan el bit específico del proveedor ('VS') anterior para indicar qué puerto está siendo accedido por el comando INQUIRY (0 -> puerto relativo 1 (puerto "a"), 1 -> puerto relativo 2 (puerto "b")). Cuando el indicador 'MultiP' está establecido, el bit específico del proveedor anterior se muestra entre paréntesis. Los dispositivos compatibles con SPC-3 deberían utilizar la página VPD de identificación del dispositivo (0x83) para mostrar qué puerto se utiliza para el acceso y la página VPD de puertos SCSI (0x88) para mostrar todos los puertos disponibles en el dispositivo.

En la serie 2.4 de los kernels de Linux, el DEVICE debe ser un dispositivo genérico SCSI (sg). En la serie 2.6 y posteriores, también se pueden especificar dispositivos de bloque (por ejemplo, discos y DVDs ATAPI). Por ejemplo, "sg_inq /dev/sda" funcionará en los kernels de la serie 2.6. A partir de lk 2.6.6, también se pueden utilizar otros nombres de dispositivos "char" de SCSI (por ejemplo, "/dev/st0m").

El número de bytes generados por --hex y --raw es de 36 bytes o el número proporcionado a --len=LEN (o --maxlen=LEN). Ese número se reduce si el "residuo" devuelto por el HBA indica que se enviaron menos bytes desde DEVICE.

El DEVICE se abre con un indicador de solo lectura (por ejemplo, en Unix con el indicador O_RDONLY).

DISPOSITIVOS ATA

Existen dos tipos principales de dispositivos ATA: dispositivos no de paquete (por ejemplo, discos ATA) y dispositivos de paquete (ATAPI). La mayoría de los dispositivos ATAPI son unidades de CD/DVD/BD en las que el transporte ATAPI lleva el conjunto MMC (es decir, un conjunto de comandos SCSI). Además, ambos tipos de dispositivos ATA se pueden conectar a un ordenador host a través de un transporte "SCSI" (o algún otro). Cuando un disco ATA se controla a través de un transporte SCSI (o no ATA), se utilizan comúnmente dos enfoques: tunelización (por ejemplo, STP en Serial Attached SCSI (SAS)) o emulando un dispositivo SCSI (por ejemplo, con una capa de traducción SCSI a ATA, consulte SAT en www.t10.org). Incluso cuando el transporte físico al ordenador host es ATA (especialmente en el caso de SATA), el sistema operativo puede optar por colocar una capa SAT en la "pila" del controlador (por ejemplo, libata en Linux).

El comando de identificación principal para cualquier dispositivo SCSI es INQUIRY. El comando correspondiente para un dispositivo ATA no de paquete es IDENTIFY DEVICE, mientras que para un dispositivo de paquete ATA es IDENTIFY PACKET DEVICE.

Cuando se invoca esta utilidad para un dispositivo ATAPI (por ejemplo, una unidad de CD/DVD/BD con "sg_inq /dev/hdc"), se envía un comando SCSI INQUIRY al dispositivo y, si responde, la respuesta se decodifica y se muestra, y la utilidad finaliza. Para ver la respuesta de un comando ATA IDENTIFY PACKET DEVICE

ATA DEVICES

SCSI devices can be found connected via the ATA (IDE) interface. Typically these are CD/DVD drives and older hard disk drives. On Linux, these devices are often presented as /dev/hd[a-z]. To treat such a device as ATA, use the --ata option (e.g. "sg_inq --ata /dev/hdc").

This utility doesn't decode the response to an ATA IDENTIFY (PACKET) DEVICE command, hdparm does a good job at that. The '-HHH' option has been added for use with either the '--ata' or '--page=ai' option to produce a format acceptable to "hdparm --Istdin". An example: 'sg_inq --ata -HHH /dev/hdc | hdparm --Istdin'. See hdparm.

NVME DEVICES

Currently these device are typically SSDs (Solid State Disks) directly connected to a PCIe connector or via a specialized connector such as a M2 connector. Linux and FreeBSD treat NVMe storage devices as separate from SCSI storage with device names like /dev/nvme0n1 (in Linux) and /dev/nvme0ns1 (in FreeBSD). The NVM Express group has a document titled "NVM Express: SCSI Translation Reference" which defines a partial "SCSI to NVMe Translation Layer" often known by its acronym: SNTL.

On operating systems where it is supported by this package, this utility will detect NVMe storage devices directly connected and send an Identify controller NVMe Admin command and decode its response. A NVMe controller is architecturally similar to a SCSI target device. If the NVMe DEVICE indicates a namespace then an Identify namespace NVMe Admin command is sent to that namespace and its response is decoded. Namespaces are numbered sequentially starting from 1. Namespaces are similar to SCSI Logical Units and their identifiers (nsid_s) can be thought of as SCSI LUNs. In the Linux and FreeBSD example device names above the "n1" and the "ns1" parts indicate nsid 1 . If no namespace is given in the DEVICE then all namespaces found in the controller are sent Identify namespace commands and the responses are decoded.

To get more details in the response use the --long option. To only get the controller's Identify decoded use the --only option.

It is possible that even though the DEVICE presents as a NVMe device, it has a SNTL and accepts SCSI commands. In this case to send a SCSI INQUIRY command (and fetch its VPD pages) use the sg_vpd(8) utility.

SG_INQ y SG_VPD

Ambas utilidades tienen mucho en común ya que las páginas VPD se obtienen con el comando SCSI INQUIRY. A medida que se han añadido más páginas VPD (y se han ampliado las existentes), las más nuevas solo se decodificaban con sg_vpd. Recientemente, con el trabajo opcional de salida JSON, se decidió colocar toda la decodificación de páginas VPD en un archivo fuente llamado sg_vpd_common.c que se enlaza tanto en sg_inq como en sg_vpd.

Esto significa que las capacidades de decodificación de páginas VPD de sg_inq y sg_vpd serán las mismas. Sus acciones predeterminadas siguen siendo como estaban, es decir, cuando se usa sg_inq sin opciones de línea de comandos, decodifica la respuesta de "formato de datos estándar de INQUIRY" (generalmente llamada "respuesta estándar de INQUIRY"), mientras que cuando se usa sg_vpd sin opciones, decodifica la página VPD de "Páginas VPD admitidas".

ESTADO DE SALIDA

El estado de salida de sg_inq es 0 cuando tiene éxito. De lo contrario, consulte la página man de sg3_utils(8).

OPCIONES DE LÍNEA DE COMANDOS ANTIGUAS

Las opciones de esta sección eran las únicas disponibles antes de la versión 1.23 de sg3_utils. Desde entonces, esta utilidad utiliza por defecto las opciones de línea de comandos más nuevas, que pueden ser anuladas utilizando --old (o -O) como la primera opción. Consulte la sección VARIABLES DE ENTORNO para otra forma de forzar el uso de estas opciones de línea de comandos antiguas.

-36
solo solicita 36 bytes de datos de respuesta para una INQUIRY. Además, incluso si el dispositivo indica en su respuesta que puede suministrar más datos, no se realiza una segunda INQUIRY (más larga). Esta es una configuración de precaución. Equivalente a '--len=36' en la sección OPCIONES.
-a
obtiene la página VPD de Información ATA [0x89]. Equivalente a '--page=ai' en la sección OPCIONES. Esta página se define en SAT (ver en www.t10.org).
-A
asume que el DEVICE dado es un dispositivo ATA o ATAPI. Equivalente a --ata en la sección OPCIONES.
-b
decodifica la página VPD de Límites de Bloque [0xb0]. Equivalente a '--page=bl' en la sección OPCIONES. Esta página se define en SBC-2 (ver en www.t10.org) y posteriores.
-B=0|1
equivalente a --block=0|1 en la sección OPCIONES.
-c
establece el bit de Datos de Soporte de Comando (CmdDt) (por defecto es borrado (0)). Se utiliza en conjunción con la opción -p=VPD_PG para especificar el opcode del comando SCSI a consultar. Equivalente a --cmddt en la sección OPCIONES.
-cl
lista los datos de comando de todos los comandos compatibles (seguido del nombre del comando) iterando a través de los 256 opcodes. Esta opción utiliza el bit CmdDt que ahora está obsoleto. Ver la utilidad sg_opcodes(8). Equivalente a '--cmddt --cmddt' en la sección OPCIONES.
-d
decodifica según el contexto. Si se da la opción -e, o cualquier opción que implique -e (p. ej., '-i' o '-p=80'), entonces esta utilidad intenta decodificar la página VPD indicada. De lo contrario, los descriptores de versión (si los hay) se listan después de una respuesta estándar de INQUIRY. En el sentido de los descriptores de versión, equivalente a --descriptors en la sección OPCIONES.
-e
habilita (es decir, establece) el bit de Datos de Producto Vital (EVPD) (por defecto es borrado (0)). Se utiliza en conjunción con la opción -p=VPD_PG para especificar la página VPD a obtener. Si no se da -p=VPD_PG, se asume la página VPD 0 (lista las páginas VPD admitidas).
-f
Equivalente a --force en la sección OPCIONES.
-h
muestra la respuesta de INQUIRY en hexadecimal en lugar de intentar decodificarla. Equivalente a --hex en la sección OPCIONES.
-H
misma acción que -h. Equivalente a --hex en la sección OPCIONES.
-i
decodifica la página VPD de Identificación de Dispositivo [0x83]. Equivalente a --id en la sección OPCIONES. Esta página se compone de varios "descriptores de designación". Si se da -h, se decodifica cada encabezado de descriptor y el identificador en sí se muestra en hexadecimal. Para ver la respuesta completa de la página VPD 0x83 en hexadecimal, use '-p=83 -h'.
-I=FN
equivalente a --inhex=FN en la sección OPCIONES.
-j[=JO]
equivalente a --json[=JO] en la sección OPCIONES.
-l=LEN
equivalente a --len=LEN en la sección OPCIONES.
-L
equivalente a --long en la sección OPCIONES.
-m
decodifica la página VPD de direcciones de red de gestión [0x85]. Equivalente a '--page=mna' en la sección OPCIONES.
-M
decodifica la página VPD de política de página de modo [0x87]. Equivalente a '--page=mpp' en la sección OPCIONES.
-N, --new
cambia a las opciones de estilo más nuevo.
-o
equivalente a --only en la sección OPCIONES.
-p=VPD_PG
se utiliza en conjunción con la opción -e o -c. Si no se proporciona ninguna, se asume la opción -e. Cuando se da (o se asume) la opción -e, el argumento de esta opción es el número de página VPD. El argumento se interpreta como hexadecimal y se espera que esté en el rango de 0 a ff inclusive. Solo se decodifica la página VPD 0 y lista las páginas VPD admitidas y sus nombres (si se conocen). Para decodificar la página de identificación de dispositivo obligatoria (0x83), use la opción -i. Un uso ahora obsoleto es cuando se da la opción -c, en cuyo caso se asume que el argumento de esta opción es un número de opcode de comando. Los borradores recientes de los estándares SCSI han trasladado esta funcionalidad a un comando separado (ver sg_opcodes(8)). Por defecto es 0, por lo que si se da -e sin esta opción, se muestra la página VPD 0.
-P
decodifica la página VPD Unit Path Report [0xc0] que es específica de EMC. Equivalente a '--page=upr' en la sección OPCIONES.
-r
muestra la respuesta en binario a stdout. Equivalente a --raw en la sección OPCIONES. Se puede usar dos veces (es decir, '-rr' (y '-HHH' tiene el mismo efecto)) y si se usa con la opción -A o -a, produce una salida con el mismo formato que "cat /proc/ide/hd<x>/identify" para que luego pueda ser canalizada a "hdparm --Istdin".
-s
decodifica la página VPD de Puertos SCSI [0x88]. Equivalente a '--page=sp' en la sección OPCIONES.
-u
equivalente a '--export' en la sección OPCIONES.
-v
aumenta el nivel de verbosidad. Se puede usar varias veces.
-V
imprime la cadena de versión y sale.
-x
decodifica la página de datos extendidos de INQUIRY VPD [0x86]. Equivalente a '--page=ei' en la sección OPCIONES.
-?
muestra el mensaje de uso y sale. Ignora todos los demás parámetros.

EJEMPLOS

Los ejemplos en esta página utilizan nombres de dispositivos de Linux. Para nombres de dispositivos adecuados en otros sistemas operativos compatibles, consulte la página man de sg3_utils(8).

Para ver la respuesta de consulta estándar, use sin opciones:


sg_inq /dev/sda

Algunos dispositivos SCSI incluyen descriptores de versión que indican los diversos estándares y borradores de SCSI que admiten. Se pueden ver con:


sg_inq -d /dev/sda

SCSI modernos

EJEMPLOS

Los dispositivos incluyen páginas de Datos Vitales del Producto (VPD) que se pueden ver con el comando SCSI INQUIRY. Para enumerar las páginas VPD soportadas (pero no su contenido) intente:


sg_inq -e /dev/sda

En Linux, las imágenes binarias de algunas respuestas de páginas VPD importantes (por ejemplo, 0, 80h y 83h) se almacenan en caché en archivos dentro del sistema de archivos pseudo sysfs. Dado que las páginas VPD rara vez cambian su contenido, decodificar esos archivos dará el mismo resultado que consultar el dispositivo con el beneficio adicional de que decodificar esos archivos no necesita permisos de root. Si /dev/sg3 es un disco en 2:0:0:0, entonces estas tres invocaciones deberían dar el mismo resultado:


sg_inq --raw --inhex=/sys/class/scsi_generic/sg3/device/vpd_pg83


sg_inq -rI /sys/class/scsi_generic/sg3/device/vpd_pg83


sg_inq -r -I /sys/class/scsi_disk/2:0:0:0/device/vpd_pg83

Sin la opción --raw, la opción --inhex=FN esperaría que el contenido de esos archivos fuera hexadecimal. vpd_pg83 contiene la respuesta (en binario) a la página VPD de Identificación del Dispositivo cuya número de página es 83h (es decir, hexadecimal).

Algunas páginas VPD se pueden leer con la utilidad sg_inq, pero una utilidad más nueva llamada sg_vpd se especializa en mostrar su contenido. La utilidad sdparm también se puede usar para mostrar el contenido de las páginas VPD.

Se pueden encontrar más ejemplos de sg_inq junto con una salida típica en la página web https://sg.danny.cz/sg/sg3_utils.html.

VARIABLES DE ENTORNO

Desde la versión 1.23 de sg3_utils, se puede dar la variable de entorno SG3_UTILS_OLD_OPTS. Cuando está presente, esta utilidad esperará las opciones de línea de comandos más antiguas. Por lo tanto, la presencia de esta variable de entorno es equivalente a usar --old (o -O) como la primera opción de la línea de comandos.
