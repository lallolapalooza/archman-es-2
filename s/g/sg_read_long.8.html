NOMBRE

sg_read_long - enviar un comando SCSI READ LONG

SINOPSIS

sg_read_long [--16] [--correct] [--help] [--lba=LBA] [--out=OF] [--pblock] [--readonly] [--verbose] [--version] [--xfer_len=BTL] DISPOSITIVO

DESCRIPCIÓN

Envía el comando SCSI READ LONG a DISPOSITIVO. El búfer de lectura se muestra en formato hexadecimal y ASCII en la salida estándar o se coloca en un archivo. Tenga en cuenta que los datos devueltos incluyen los datos del bloque lógico (típicamente 512 bytes para un disco) más información ECC (cuyo formato es propietario) y, opcionalmente, otros datos propietarios. Tenga en cuenta que los datos del bloque lógico pueden estar codificados o cifrados.

En la revisión 7 de SBC-4, los comandos SCSI READ LONG (de 10 y 16 bytes) quedaron obsoletos. En la misma revisión, todos los usos de los comandos SCSI WRITE LONG (de 10 y 16 bytes) quedaron obsoletos, excepto en el caso en que se establece el bit WR_UNCOR.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas.

-S, --16
utiliza un comando SCSI READ LONG(16). La acción predeterminada es utilizar un comando SCSI READ LONG(10). El comando READ LONG(10) tiene un campo de 32 bits para el lba, mientras que READ LONG(16) tiene un campo de 64 bits.
-c, --correct
establece el bit 'CORRCT' en el comando SCSI READ LONG. Cuando se establece, los datos son corregidos por la ECC antes de ser transferidos de vuelta a esta utilidad. El valor predeterminado es dejar el bit 'CORRCT' sin establecer, en cuyo caso los datos no se corrigen.
-h, --help
muestra el mensaje de uso y luego sale.
-l, --lba=LBA
donde LBA es la dirección del bloque lógico del sector a leer. Se asume que está en decimal a menos que se prefije con '0x' (o tenga un sufijo 'h'). El valor predeterminado es lba 0. Si el lba es mayor de lo que cabe en 32 bits, se debe usar la opción --16.
-o, --out=OF
en lugar de mostrar hexadecimal ASCII en la salida estándar, envíelo en binario al archivo llamado OF. Si se da '-' para OF, la salida (binaria) se envía a la salida estándar. Tenga en cuenta que toda la salida informativa y de errores se envía al error estándar.
-p, --pblock
establece el bit 'PBLOCK' en el comando SCSI READ LONG. Cuando se establece, se lee el bloque físico (más datos ECC) que contiene la dirección del bloque lógico solicitada. El valor predeterminado es dejar el bit 'PBLOCK' sin establecer, en cuyo caso se lee el bloque lógico (más cualquier dato ECC).
-r, --readonly
abre el DISPOSITIVO en modo de solo lectura en lugar de lectura-escritura, que es el valor predeterminado. El controlador sg de Linux necesita acceso de lectura-escritura para el comando SCSI READ LONG, pero otros métodos de acceso pueden requerir acceso de solo lectura.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración).
-V, --version
imprime la cadena de versión y luego sale.
-x, --xfer_len=BTL
donde BTL es la longitud de transferencia de bytes (predeterminado a 520). Si el valor dado (o el predeterminado) no coincide con el tamaño del bloque "largo" del dispositivo, el BTL apropiado se deduce de la respuesta de error y se imprime (en el error estándar). La idea es que el usuario vuelva a intentar usar esta utilidad con la longitud de transferencia correcta.

NOTAS

Si se encuentra un bloque defectuoso y se han recuperado sus contenidos, si los hay, se podría usar "sg_reassign" para marcar el bloque defectuoso. Asociado con tal acción, el número de elementos en la lista de defectos "crecidos" podría ser monitoreado ("sg_reassign --grown") ya que el disco podría estar llegando al final de su vida útil.

Varios argumentos numéricos (por ejemplo, LBA) pueden incluir sufijos multiplicadores o darse en hexadecimal. Consulte la sección "ARGUMENTOS NUMÉRICOS" en la página del manual sg3_utils(8).

Como punto de datos, Fujitsu utiliza un ECC de 54 bytes (por bloque) capaz de corregir hasta un único error de ráfaga o 216 bits "sobre la marcha". [Información obtenida del manual del producto MAV20xxrc.]

ESTADO DE SALIDA

El estado de salida de sg_read_long es 0 cuando tiene éxito. De lo contrario, consulte la página del manual sg3_utils(8).
