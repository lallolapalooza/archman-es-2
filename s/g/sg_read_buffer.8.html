NOMBRE

sg_read_buffer - envía el comando SCSI READ BUFFER

SINOPSIS

sg_read_buffer [--eh_code=EHC] [--help] [--hex] [--id=ID] [--inhex=FN] [--length=LEN] [--mode=MO] [--no_output] [--offset=OFF] [--raw] [--readonly] [--specific=MS] [--verbose] [--version] DISPOSITIVO

DESCRIPCIÓN

Envía un comando SCSI READ BUFFER al DISPOSITIVO y, si hay una respuesta, la decodifica, la imprime en hexadecimal o la envía en binario a la salida estándar. Si se recibe una respuesta para un modo de "descriptor", en ausencia de --hex y --raw, se decodifica. Las respuestas para modos no descriptores se envían en hexadecimal a menos que se especifique la opción --raw.

Las respuestas a los modos de estado de microcódigo de lectura ('rd_microc_st' [0xf]) y historial de errores ('err_hist' [0x1c]) se decodifican como se describe en spc6r06.pdf y documentos T10 anteriores.

Esta utilidad puede llamarse sin un DISPOSITIVO pero con la opción --inhex=FN en su lugar. Se espera que FN sea un nombre de archivo (o
'-' para stdin). El contenido del archivo (o flujo stdin) se asume que es datos hexadecimales (o binarios) que representan una respuesta del comando SCSI READ BUFFER y se decodifica como tal.

OPCIONES

Los argumentos de las opciones largas son obligatorios también para las opciones cortas.

-e, --eh_code=EHC
EHC es el código del historial de errores colocado en el campo ID del buffer del cdb. El campo Modo se establece en err_hist [0x1c]. La opción es equivalente a usar las opciones '--mode=eh --id=EHC'. Si se proporciona esta opción y una de las otras opciones, se generará un error si contradicen. La longitud de respuesta predeterminada (máxima) se incrementa a 64 bytes cuando puede ser necesario aumentar (si es así, se indica si la salida está truncada).
Un ejemplo es establecer EHC en 0, en cuyo caso se decodificará el directorio del historial de errores (a menos que se especifiquen las opciones --hex o --raw).
-h, --help
muestra el mensaje de uso y luego sale. Si se usa varias veces, también imprime los nombres de los modos y sus acrónimos.
-H, --hex
envía la respuesta en hexadecimal. Cuando se usa dos veces, la respuesta se envía en hex con la representación correspondiente en ASCII a la derecha de cada línea. Cuando se usa tres veces, el hex se imprime sin direcciones (índices) al principio de cada línea; este tipo de formato es adecuado para la opción --inhex=FN en una invocación posterior.
-i, --id=ID
esta opción establece el campo ID del buffer en el cdb. ID es un valor entre 0 (predeterminado) y 255 inclusive. El significado del campo ID del buffer varía con el valor en el campo Modo del cdb.
-I, --inhex=FN
se espera que FN sea un nombre de archivo (o '-' para stdin) que contenga hexadecimal ASCII o binario representando una respuesta de READ BUFFER. Si se conoce, esta utilidad decodificará esa respuesta. Es preferible también proporcionar las opciones --mode=MO, --id=ID y posiblemente --specific=MS, ya que no están presentes en la respuesta. Consulte la sección "FORMATOS HEXADECIMAL, BINARIO Y JSON" en la página del manual de sg3_utils para obtener más información. Si también se da la opción --raw, el contenido de FN se trata como binario.
-l, --length=LEN
donde LEN es la longitud, en bytes, que se coloca en el campo "longitud de asignación" en el cdb. El valor predeterminado es 4 (bytes) que se incrementa a 64 si se da o se implica el modo 'err_hist' [0x1c]. El dispositivo puede responder con menos bytes.
Si se proporciona la opción --inhex=FN, el valor predeterminado de la longitud se incrementa a 8192 bytes. Esta longitud puede luego reducirse para que coincida con el número de bytes decodificados del contenido de FN.
-m, --mode=MO
esta opción establece el campo modo en el cdb. MO es un valor entre 0 (predeterminado) y 31 inclusive. Alternativamente, se puede dar una abreviatura. Consulte la sección MODOS a continuación. Para listar las abreviaturas de modo disponibles, use una inválida (por ejemplo, '--mode=xxx'). Como ejemplo, para obtener el descriptor de lectura del buffer, dé '--mode=desc'.
-N, --no_output
cuando se proporciona esta opción después de enviar el comando SCSI al DISPOSITIVO, la respuesta se procesa, buscando errores, y luego esta utilidad sale. Se ignora cualquier dato leído por el comando READ BUFFER.
Puede ser útil para cronometrar lecturas más grandes del buffer del DISPOSITIVO en modo 'data' [0x2].
-o, --offset=OFF
esta opción establece el campo offset del buffer en el cdb. OFF es un valor entre 0 (predeterminado) y 2**24-1. Es un offset de byte.
-r, --raw
si se recibe una respuesta, se envía en binario a la salida estándar. Cuando se proporciona esta opción junto con --inhex=FN, se asume que el contenido de FN es binario y la salida de esta utilidad es ASCII normal (es decir, *no* en binario).
-R, --readonly
abre el DISPOSITIVO en modo de solo lectura (por ejemplo, en Unix con la bandera O_RDONLY). El valor predeterminado es abrirlo en modo lectura-escritura.
-S, --specific=MS
esta opción establece el campo modo específico en el cdb. MS es un valor entre 0 y 7, ya que es un campo de 3 bits.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración).
-V, --version
imprime la cadena de versión y luego sale.

MODOS

A continuación se muestra una lista de configuraciones del comando READ BUFFER para el campo MODO. Primero aparece un acrónimo aceptado por el argumento MO de esta utilidad. A continuación del acrónimo entre corchetes se encuentran los valores decimales y hexadecimales correspondientes que también se pueden dar para MO. Los siguientes se enumeran en orden numérico.

hd [0, 0x0]
Cabecera y datos combinados (obsoleto en SPC-4).
vendor [1, 0x1]
Específico del proveedor.
data [2, 0x2]
Datos.
desc [3, 0x3]
Descriptor: produce 4 bytes que contienen un campo de límite de offset (1 byte) y capacidad del buffer (3 bytes).
echo [10, 0xa]
Lee datos del buffer de eco (se llamaba "Buffer de eco" en SPC-3).
echo_desc [11, 0xb]
Descriptor de buffer de eco: produce 4 bytes de los cuales los últimos 13 bits (de menor peso) representan la capacidad del buffer de eco. El tamaño máximo del buffer de eco es de 4096 bytes.
rd_microc_st [15, 0xf]
Lee el estado del microcódigo. Añadido en spc5r20.
en_ex [26, 0x1a]
Habilita el protocolo de comunicaciones del expansor y el buffer de eco. Quedó obsoleto en SPC-4.
err_hist|eh [28, 0x1c]
Historial de errores. Se puede usar la abreviatura 'err_hist' o la corta 'eh' para este modo. Introducido en SPC-4.

NOTAS

Se asume que todos los números dados con las opciones están en decimal. Alternativamente, los valores numéricos se pueden dar en hexadecimal precedidos por "0x" o "0X" (o tienen un sufijo "h" o "H").

ESTADO DE SALIDA

El estado de salida de sg_read_buffer es 0 cuando tiene éxito. De lo contrario, consulte la página del manual de sg3_utils(8).
