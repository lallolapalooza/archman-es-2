NOMBRE

sg_xcopy - copia datos a y desde archivos y dispositivos usando SCSI EXTENDED COPY (XCOPY)

SINOPSIS

sg_xcopy [bs=BS] [conv=CONV] [count=COUNT] [ibs=BS] [if=IFILE] [iflag=FLAGS] [obs=BS] [of=OFILE] [oflag=FLAGS] [seek=SEEK] [skip=SKIP] [--help] [--version]

[app=0|1] [bpt=BPT] [cat=0|1] [dc=0|1] [fco=0|1] [id_usage={hold|discard|disable}] [list_id=ID] [prio=PRIO] [time=0|1] [verbose=VERB] [--on_dst|--on_src] [--verbose]

DESCRIPCIÓN

Copia datos a y desde cualquier archivo. Especializado para "archivos" que son dispositivos SCSI de Linux que soportan el comando SCSI EXTENDED COPY (XCOPY).

Esta utilidad tiene una sintaxis y semántica similar a dd(1) pero sin "conversiones" soportadas.

El primer grupo en la sinopsis anterior son operandos "estándar" de dd(1) de Unix. El segundo grupo son opciones adicionales añadidas por esta utilidad. Ambos grupos se definen a continuación en orden alfabético combinado.

Por defecto, el comando XCOPY se envía a OFILE. Esto puede cambiarse con las opciones --on_src o iflag=xflag que hacen que el comando XCOPY se envíe a IFILE en su lugar. Vea también la sección sobre VARIABLES DE ENTORNO.

En el estándar SPC-4, el comité T10 ha expandido el comando XCOPY para que ahora tenga dos variantes: "LID1" (para una longitud de Identificador de Lista de 1 byte) y "LID4" (para una longitud de Identificador de Lista de 4 bytes). Esta utilidad soporta la variante más antigua, LID1, que también se encuentra en SPC-3 y anteriores. Aunque la variante LID1 en SPC-4 es compatible a nivel de comando (binario) con XCOPY tal como se define en SPC-3, algunos de los nombres de los comandos han cambiado. Esta utilidad utiliza los nombres de XCOPY más antiguos, de SPC-3.

La utilidad ddpt soporta la misma funcionalidad xcopy(LID1) que esta utilidad con las mismas opciones y flags. Adicionalmente, ddpt soporta un subconjunto de la funcionalidad xcopy(LID4) denominado "xcopy versión 2, lite" u ODX. ODX es un nombre de marketing y significa Offloaded Data Xfer (es decir, transferencia).

OPCIONES

app={0|1}
si es 1, inicia el destino de la copia al final de OFILE. Esto asume que OFILE es un archivo regular. El valor por defecto es 0, en cuyo caso el destino de la copia comienza al principio de OFILE (posiblemente desplazado por SEEK). Esta opción no puede usarse con la opción seek=SEEK.
bpt=BPT
cada transacción de E/S se realizará utilizando BPT bloques (o menos si está cerca del final de la copia). El valor por defecto es 128 para tamaños de bloque lógicos menores de 2048 bytes, de lo contrario, el valor por defecto es 32. Así, para bs=512, las lecturas y escrituras transmitirán 64 KiB de datos por defecto (menos si están cerca del final de la transferencia o si hay restricciones de memoria). Cuando se accede a unidades de CD/DVD, el tamaño de bloque lógico suele ser de 2048 bytes y bpt por defecto es 32, lo que de nuevo implica transferencias de 64 KiB.
bs=BS
donde BS **debe** ser el tamaño de bloque lógico del dispositivo físico (si los archivos de entrada o salida se acceden a través de comandos SCSI). Tenga en cuenta que esto difiere de dd(1), que permite que BS sea un múltiplo integral.
cat={0|1}
establece el bit CAT del descriptor de segmento del comando SCSI EXTENDED COPY a 0 o 1 (por defecto: 0). El bit CAT (junto con el bit PAD) controla el manejo de datos residuales. Vea la sección MANEJO DE DATOS RESIDUALES para más detalles.
conv=CONV
todos los argumentos CONV son ignorados.
count=COUNT
copia COUNT bloques desde IFILE a OFILE. El valor por defecto es el mínimo (IFILE si dc=0 o OFILE si dc=1) número de bloques que los dispositivos SCSI reportan de los comandos SCSI READ CAPACITY o que los dispositivos de bloque (o sus particiones) reportan. Los archivos normales no se sondean para conocer su tamaño. Si se especifican skip=SKIP o seek=SEEK y el contador se deriva (es decir, no se da explícitamente), el contador derivado se ajusta para que la copia no se desborde del dispositivo. Si el nombre del archivo es una partición de dispositivo de bloque y no se proporciona COUNT, se utiliza el tamaño de la partición en lugar del tamaño del dispositivo completo. Si COUNT no se proporciona (o count=-1) y no se puede derivar, se emite un mensaje de error y no se realiza ninguna copia.
dc={0|1}
establece el bit DC del descriptor de segmento del comando SCSI EXTENDED COPY a 0 o 1 (por defecto: 0). El bit DC controla si COUNT se refiere al descriptor de origen (dc=0) o al de destino (dc=1).
fco={0|1}
establece el bit FCO (Fast Copy Only) del descriptor de segmento del comando SCSI EXTENDED COPY a 0 o 1 (por defecto: 0). Con el bit FCO activado, la copia se realizará pero utilizando una técnica más rápida que los comandos SCSI READ y WRITE. Si la copia no se puede realizar de una manera más rápida, se devuelve una clave de sentido de "Copia abortada" con un sentido adicional de "Copia rápida no posible".
ibs=BS
si se proporciona, debe ser el mismo que BS dado a la opción 'bs='.
id_usage={hold|discard|disable}
establece el campo de lista de parámetros del comando SCSI EXTENDED COPY llamado LIST ID USAGE a 0 si el argumento es 'hold', a 2 si el argumento es 'discard', o a '3' si el argumento es 'disable'.
Si el dispositivo tiene la capacidad de retener datos (indicado por un "límite de datos retenidos" mayor que cero), entonces id_usage por defecto es 'hold', de lo contrario, por defecto es 'discard'.
if=IFILE
leer desde IFILE en lugar de stdin. Si IFILE es '-', se lee desde stdin. Comienza a leer desde el principio de IFILE a menos que se especifique SKIP.
iflag=FLAGS
donde FLAGS es una lista separada por comas de uno o más flags descritos a continuación. Estos flags están asociados con IFILE y se ignoran cuando IFILE es stdin.
list_id=ID
establece el campo de lista de parámetros del comando SCSI EXTENDED COPY llamado LIST IDENTIFIER a ID. ID debe ser un valor entre 0 y 255 (inclusive). ID por defecto suele ser 1, a menos que id_usage=disable, en cuyo caso por defecto es 0.
obs=BS
si se proporciona, debe ser el mismo que BS dado a la opción 'bs='.
of=OFILE
escribir en OFILE en lugar de stdout. Si OFILE es '-', se escribe en stdout. Si OFILE es /dev/null, no se realizan escrituras reales. Si OFILE es '.' (punto), se trata de la misma manera que /dev/null (esto es una notación abreviada). Si OFILE existe, **no** se trunca; se sobrescribe desde el principio de OFILE a menos que se especifique 'oflag=append' o SEEK.
oflag=FLAGS
donde FLAGS es una lista separada por comas de uno o más flags descritos a continuación. Estos flags están asociados con OFILE y se ignoran cuando OFILE es /dev/null, '.' (punto), o stdout.
prio=PRIO
establece el campo de lista de parámetros del comando SCSI EXTENDED COPY llamado PRIORITY a PRIO. El valor por defecto es 1.
seek=SEEK
comenzar a escribir SEEK bloques de tamaño bs desde el principio de OFILE. El valor por defecto es el bloque 0 (es decir, el principio del archivo).
skip=SKIP
comenzar a leer SKIP bloques de tamaño bs desde el principio de IFILE. El valor por defecto es el bloque 0 (es decir, el principio del archivo).
time={0|1}
cuando es 1, mide el tiempo de la transferencia y realiza cálculos de rendimiento, mostrando los resultados (en stderr) al finalizar. Cuando es 0 (por defecto), no realiza esta operación.
verbose=VERB
cuando es 1 o más, imprime información sobre la operación de copia y, cuando es 2 o más, imprime información sobre los comandos SCSI enviados. Por defecto es 0.

Las siguientes opciones son para el control de la operación cuando el comando XCOPY se envía a un dispositivo SCSI:

--on_dst
el comando XCOPY se envía al dispositivo de destino (OFILE). Este es el comportamiento por defecto.
--on_src
el comando XCOPY se envía al dispositivo de origen (IFILE). Esto puede ser útil si el dispositivo de origen soporta XCOPY pero el de destino no. Solo un dispositivo puede soportar XCOPY.
--help
muestra el mensaje de ayuda y sale.
--version
muestra la información de la versión y sale.
iflag=FLAGS
donde FLAGS es una lista separada por comas de uno o más de los siguientes flags:
append
esta opción solo tiene efecto cuando IFILE es un archivo normal y OFILE es un dispositivo SCSI. Si OFILE tiene la capacidad de anexar datos, entonces los datos se anexan al final de OFILE. Esto solo puede funcionar si IFILE es un archivo normal.
eos
establece el bit EOS (End Of Segment) en el descriptor del segmento del comando EXTENDED COPY. Esto indica el final de un segmento de datos lógicos. Solo debe usarse en el último segmento del comando.
seek
esta opción solo tiene efecto cuando IFILE es un dispositivo SCSI y OFILE es un archivo normal. El archivo de salida se posiciona al offset dado por SEEK antes de la operación de copia.
skip
esta opción solo tiene efecto cuando IFILE es un dispositivo SCSI. El dispositivo de entrada se posiciona al offset dado por SKIP antes de la operación de copia.
xflag
el comando XCOPY se envía al dispositivo de origen (IFILE). Esto es equivalente a la opción --on_src y solo puede ser usada cuando IFILE es un dispositivo SCSI.
oflag=FLAGS
donde FLAGS es una lista separada por comas de uno o más de los siguientes flags:
append
esta opción solo tiene efecto cuando OFILE es un dispositivo SCSI. Si OFILE tiene la capacidad de anexar datos, entonces los datos se anexan al final de OFILE. Esto solo puede funcionar si OFILE es un dispositivo SCSI.
eos
establece el bit EOS (End Of Segment) en el descriptor del segmento del comando EXTENDED COPY. Esto indica el final de un segmento de datos lógicos. Solo debe usarse en el último segmento del comando.
seek
esta opción solo tiene efecto cuando OFILE es un dispositivo SCSI. El dispositivo de salida se posiciona al offset dado por SEEK antes de la operación de copia.
skip
esta opción solo tiene efecto cuando OFILE es un dispositivo SCSI. El dispositivo de salida se posiciona al offset dado por SKIP antes de la operación de copia.
xflag
el comando XCOPY se envía al dispositivo de destino (OFILE). Esto es equivalente al comportamiento por defecto y solo puede ser usado cuando OFILE es un dispositivo SCSI.

MANEJO DE DATOS RESIDUALES

El comando EXTENDED COPY tiene bits para controlar el manejo de datos residuales, en particular, si se deben descartar o mantener los datos que quedan en los búferes del dispositivo. Estos son los bits CAT (Copy and Transfer) y PAD (Pad). Este programa utiliza el bit CAT y el bit PAD (que nunca se establece).

Cuando cat=0 (por defecto), el comando EXTENDED COPY transferirá datos hasta que se complete el recuento solicitado o hasta que el dispositivo alcance el final de los medios. Los datos que queden en los búferes del dispositivo se descartan. Esto es lo que hace que la utilidad se comporte de manera similar a `dd` si se leen o escriben menos datos de los solicitados (por ejemplo, al final de un archivo).

Cuando cat=1, el comando EXTENDED COPY intentará transferir datos hasta que se complete el recuento solicitado. Si el dispositivo alcanza el final de los medios antes de que se complete el recuento, los datos residuales que queden en los búferes del dispositivo se mantendrán y se colocarán al final de la transferencia. Esto puede ser útil para copias de seguridad que involucran discos que pueden tener áreas defectuosas o al final de la capacidad de almacenamiento. Tenga en cuenta que el comportamiento exact o de los datos residuales puede variar entre diferentes implementaciones de SCSI.

EJEMPLOS

Para copiar el contenido de un disco duro (dev/sda) a otro (dev/sdb) sin pasar por el espacio de usuario:

sg_xcopy bs=4k if=/dev/sda of=/dev/sdb

Para copiar 1000 bloques de 512 bytes desde el primer CD/DVD (dev/cdrom) a un archivo llamado cd_image.img:

sg_xcopy bs=512 count=1000 if=/dev/cdrom of=cd_image.img

Para copiar el contenido de un archivo llamado tape_image.img a un dispositivo de cinta (dev/st0):

sg_xcopy if=tape_image.img of=/dev/st0

Para copiar los últimos 100 bloques de 512 bytes desde dev/sda1 a dev/sdb1:

sg_xcopy bs=512 skip=100 count=100 if=/dev/sda1 of=/dev/sdb1

Para copiar el contenido de un disco a otro, colocando el comando XCOPY en el disco de destino:

sg_xcopy --on_dst bs=4k if=/dev/sda of=/dev/sdb

Para copiar el contenido de un disco a otro, colocando el comando XCOPY en el disco de origen:

sg_xcopy --on_src bs=4k if=/dev/sda of=/dev/sdb

FLAGS

Aquí hay una lista de flags y sus significados:

append
hace que el flag O_APPEND se agregue a la apertura de OFILE. Para archivos regulares, esto conducirá a que los datos se anexen al final de los datos existentes. No se puede usar junto con la opción seek=SEEK ya que entran en conflicto. La acción predeterminada de esta utilidad es sobrescribir cualquier dato existente desde el principio del archivo o, si se proporciona SEEK, comenzando en el bloque SEEK. Tenga en cuenta que intentar 'anexar' a un archivo de dispositivo (por ejemplo, un disco) generalmente se ignorará o puede generar un error.
excl
hace que el flag O_EXCL se agregue a la apertura de IFILE y/o OFILE.
flock
después de abrir el archivo asociado (es decir, IFILE y/o OFILE), se intenta obtener un bloqueo exclusivo de asesoramiento con la llamada al sistema flock(). Los argumentos de flock son "FLOCK_EX | FLOCK_NB", lo que provocará que el bloqueo se tome si está disponible, de lo contrario, se generará un error de "temporalmente no disponible". Se produce un estado de salida de 90 en este último caso y no se realiza ninguna copia.
null
no tiene ningún efecto, solo es un marcador de posición.
pad
establece el bit PAD del descriptor de segmento del comando EXTENDED COPY SCSI. El bit PAD (junto con el bit CAT) controla el manejo de datos residuales. (Ver la sección MANEJO DE DATOS RESIDUALES para más detalles).
xcopy
no tiene ningún efecto; para compatibilidad con ddpt.

MANEJO DE DATOS RESIDUALES

Los bits pad y cat controlan el manejo de datos residuales. Dado que los datos se pueden especificar en términos del tamaño de bloque lógico de origen o destino y ambos pueden tener tamaños de bloque diferentes, es probable que ocurran datos residuales en estos casos. Si ambos tamaños de bloque lógicos son idénticos, estos bits no tienen ningún efecto, ya que no ocurrirán datos residuales.

Si ninguno de estos bits está establecido, el comando EXTENDED COPY se abortará con un sentido adicional 'UNEXPECTED INEXACT SEGMENT'.

Si solo está establecido el bit cat, los datos residuales se conservarán y estarán disponibles para descriptores de segmento posteriores. Los datos residuales se descartarán para el último descriptor de segmento.

Si el bit pad está establecido solo para el descriptor de origen, cualquier dato residual tanto de origen como de destino se descartará.

Si el bit pad está establecido solo para el descriptor de destino, cualquier dato residual de origen se manejará como si el bit cat estuviera establecido, pero cualquier dato residual de destino se rellenará para realizar una transferencia de bloque completo.

Si el bit pad está establecido tanto para el origen como para el destino, cualquier dato residual de origen se descartará y cualquier dato residual de destino se rellenará.

VARIABLES DE ENTORNO

Si la invocación de la línea de comandos no indica explícitamente (y sin ambigüedades) si el comando SCSI XCOPY debe enviarse a IFILE (es decir, el origen) o OFILE (es decir, el destino), entonces se verifica la presencia de las variables de entorno XCOPY_TO_SRC y XCOPY_TO_DST. Si existe alguna de ellas (pero no ambas), indica a dónde se enviará el comando SCSI XCOPY. Por defecto, el comando XCOPY se envía a OFILE.

OPCIONES RETIRADAS

Aquí hay algunas opciones retiradas que todavía están presentes:

append=0 | 1
cuando está establecido, es equivalente a 'oflag=append'. Cuando está claro, la acción es sobrescribir el archivo existente (si existe); esto es lo predeterminado. Consulte el flag 'append'.

NOTAS

Copiar datos a espaldas del Sistema Operativo puede causar problemas. En el caso de Linux, los usuarios deben consultar este enlace:
https://linux-mm.org/Drop_Caches

Esta secuencia de comandos puede ser útil:
sync; echo 3 > /proc/sys/vm/drop_caches

Varios argumentos numéricos (por ejemplo, SKIP) pueden incluir sufijos multiplicadores o darse en hexadecimal. Consulte la sección "ARGUMENTOS NUMÉRICOS" en la página del manual de sg3_utils(8).

Los argumentos COUNT, SKIP y SEEK pueden admitir valores de 64 bits (es decir, números muy grandes). Otros valores están limitados a lo que puede caber en un número con signo de 32 bits.

Toda la información, advertencias y mensajes de error se envían a stderr para que el archivo de salida de dd pueda ser stdout y permanecer sin contaminar. Si no se proporcionan opciones, se muestra el mensaje de uso y no sucede nada más.

Si un dispositivo admite operaciones xcopy, debe establecer el campo 3PC (3PC significa Third Party Copy) en su respuesta INQUIRY estándar. Esta utilidad intentará una operación xcopy independientemente del valor en el campo 3PC, pero si es cero (borrado), se esperaría que la operación xcopy fallara.

El estado del comando SCSI EXTENDED COPY se puede consultar con sg_copy_results(sg3_utils)

Actualmente solo se implementan las transferencias de bloque a bloque; IFILE y OFILE deben referirse a un dispositivo de bloque SCSI.

No se tienen en cuenta las particiones, por lo que, por ejemplo, /dev/sbc2, /dev/sdc, /dev/sg2 y /dev/bsg/3:0:0:1 se referirían a lo mismo: la unidad lógica completa (es decir, todo el disco) que comienza en LBA 0. Por lo tanto, se ignora cualquier indicación de partición (por ejemplo, /dev/sdc2). El usuario debe establecer SKIP, SEEK y COUNT con información obtenida de un comando como 'fdisk -l -u /dev/sdc' para tener en cuenta las particiones.

La capacidad XCOPY (LID1) se ha agregado a la utilidad ddpt, que se encuentra en un paquete del mismo nombre. La utilidad ddpt se ejecutará en otros sistemas operativos (por ejemplo, FreeBSD y Windows), mientras que sg_xcopy solo se ejecuta en Linux. Además, ddpt permite que los argumentos de ibs= e ibs= sean diferentes.

SEÑALES

El manejo de señales se ha tomado prestado de dd: SIGINT, SIGQUIT y SIGPIPE muestran el número de bloques restantes a transferir y los recuentos de registros de entrada y salida; luego tienen su acción predeterminada. SIGUSR1 provoca que se muestre la misma información y la copia continúa. Toda la salida causada por señales se envía a stderr.

ESTADO DE SALIDA

El estado de salida de sg_xcopy es 0 cuando es exitoso. De lo contrario, consulte la página del manual de sg3_utils(8).

Se genera un estado de salida adicional de 90 si se proporciona el flag flock y otro proceso mantiene el bloqueo exclusivo de asesoramiento.

NAME

sg_xcopy - copy blocks from a source device to a destination device using the SCSI COPY AND VERIFY command (or mode sense/mode select for CD/DVDs)

SYNOPSIS

sg_xcopy [--cb=ACTION] [--cmnd_max=LEN] [--device=DEVICE] [--dry-run]
      [--enumerate] [--fua] [--help] [--inbin=FILE] [--inhex=FILE]
      [--len=LEN] [--lba] [--log] [--long_unique] [--new_lba]
      [--num=NUM] [--of=FILE] [--outbin=FILE] [--outhx=FILE] [--page_len=PLEN]
      [--pback] [--progress] [--read] [--rc=RC] [--retries=N] [--r_reason=CODE]
      [--sback] [--skip=LEN] [--src_id=ID] [--src_port=PORT] [--src_port_group=GROUP]
      [--tback] [--toc] [--transport=STR] [--verbose] [--version]
      [--verify=ACTION] [--xfer=LEN] DEST_DEVICE SRC_DEVICE

DESCRIPTION

The sg_xcopy utility is designed to copy blocks of data from a source (SRC_DEVICE) to a destination (DEST_DEVICE) using the SCSI COPY AND VERIFY command (or related commands if the COPY AND VERIFY command is not supported or applicable). This is particularly useful for copying data between storage devices like hard drives, SSDs, or tape drives. The utility can also be used to read data from a device and write it to a file, or vice versa, though this is less common. Key features include:

  • Support for various copying methods including direct device-to-device transfer.
  • Ability to specify source and destination LBA (Logical Block Addresses).
  • Options for verifying the data after copying.
  • Handling of residual data and retries.
  • Support for different SCSI transport mechanisms.

Note that sg_xcopy may not be suitable for all scenarios, especially when dealing with complex file systems or when data integrity requires more advanced checking than simple block verification. For file system level copies, standard utilities like cp or rsync are generally preferred. dd, ddrescue, and sg_copy_results are also related tools that might be useful in specific data recovery or imaging tasks.

OPTIONS

A detailed description of all options can be found in the man page. Some common options include:

  • --len=LEN: Specifies the number of blocks to copy.
  • --skip=LEN: Skips a specified number of blocks from the beginning of the source.
  • --verify=ACTION: Specifies the action for verification (e.g., 'data', 'crc').
  • --progress: Shows progress during the copy operation.
  • --dry-run: Performs a trial run without actually copying data.
  • --lba: Treats the addresses as Logical Block Addresses.

The utility provides mechanisms to handle residual data, which can occur during SCSI command execution. Options like --rc (residual count) and --r_reason (residual transport protocol reason) allow for more robust error handling and recovery.

NOTES

sg_xcopy relies on the SCSI COPY AND VERIFY command. The availability and exact behavior of this command can vary depending on the SCSI devices and the operating system's SCSI subsystem. If the COPY AND VERIFY command is not supported, sg_xcopy may fall back to using other methods or report an error.

For tasks involving low-level disk imaging or data recovery, tools like ddrescue might be more appropriate as they are specifically designed to handle read errors gracefully.

EXAMPLES

To copy 1000 blocks from device /dev/sda to /dev/sdb, starting at LBA 0:

sg_xcopy --len=1000 /dev/sdb /dev/sda

To copy data from /dev/sg0 to a file output.bin:

sg_xcopy --len=10000 --of=output.bin /dev/sg0
