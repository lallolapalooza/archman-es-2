SG_REQUESTS(8) SG3_UTILS SG_REQUESTS(8)

NOMBRE

sg_requests - envía uno o más comandos SCSI REQUEST SENSE

SINOPSIS

sg_requests [--desc] [--error] [--help] [--hex] [--maxlen=LEN] [--num=NUM] [--number=NUM] [--progress] [--raw] [--status] [--time] [--timeout=SE] [--verbose] [--version] DISPOSITIVO

DESCRIPCIÓN

Envía el comando SCSI REQUEST SENSE al DISPOSITIVO y muestra los datos de parámetros de respuesta que se espera que estén en formato de datos de sentido. Se admiten tanto formatos de datos de sentido fijos como descriptores.

Se pueden enviar varios comandos REQUEST SENSE con la opción --num=NUM. Esto se puede usar para fines de tiempo o para monitorizar la indicación de progreso.

OPCIONES

Los argumentos de las opciones largas son obligatorios también para las opciones cortas.

-d, --desc
establece el bit DESC en el cdb de REQUEST SENSE. El DISPOSITIVO debería devolver datos de sentido en formato descriptor (en lugar de fijo). Esto solo ocurrirá si el DISPOSITIVO reconoce el formato descriptor (SPC-3 y posterior). Si el dispositivo es anterior a SPC-3, establecer un bit en un campo reservado puede causar un estado de condición de chequeo con una clave de sentido de solicitud ilegal, pero lo más probable es que se ignore.
-e, --error
cuando se usa una vez, cambia el opcode de REQUEST SENSE de 0x3 a 0xff que debería ser rechazado por el DISPOSITIVO. Existe una pequeña posibilidad de que el proveedor del dispositivo haya implementado un comando específico del proveedor en ese opcode (0xff). Cuando se usa dos veces, la llamada de traspaso para enviar el comando SCSI se omite. La idea aquí es medir la sobrecarga del espacio de usuario de esta biblioteca del paquete para configurar y procesar la respuesta de un comando SCSI. Esta opción generalmente se usará con las opciones --num=NUM y --time donde NUM es un número grande (por ejemplo, 1000000).
-h, --help
muestra el mensaje de uso y luego sale.
-H, --hex
muestra la respuesta en hexadecimal ASCII.
-m, --maxlen=LEN
donde LEN es la longitud (máxima) de respuesta en bytes. Se coloca en el campo "longitud de asignación" del cdb. Si no se proporciona (o LEN es cero), se usa 252. El valor máximo de LEN es 255 (pero SPC-4 recomienda 252).
-n, --num=NUM
realiza NUM comandos SCSI REQUEST SENSE, deteniéndose cuando se alcanza NUM o ocurre un error. El valor predeterminado para NUM es 1.
--number=NUM
misma acción que --num=NUM. Añadido para compatibilidad con sg_turs.
-p, --progress
muestra la indicación de progreso (un porcentaje) si está disponible. Si se da --num=NUM, NUM es mayor que 1 y se detectó una indicación de progreso inicial, esta utilidad espera 30 segundos antes de las verificaciones posteriores. Sale cuando se alcanza NUM o no quedan más indicaciones de progreso. Ignora las opciones --hex, --raw y --time. Ver la sección NOTAS a continuación.
-r, --raw
muestra la respuesta en binario (a stdout).
-s, --status
si el comando REQUEST SENSE finalizó sin error (como lo indica su estado SCSI), el contenido de los datos de parámetros se analiza como datos de sentido y el estado de salida se establece en consecuencia. La acción predeterminada (es decir, cuando esta opción no se proporciona) es ignorar el contenido de los datos de parámetros a efectos de establecer el estado de salida. Algunos tipos de error establecen una clave de sentido de "NO SENSE" con información no cero en el código de sentido adicional (por ejemplo, el grupo de códigos de UMBRAL DE PREDICCIÓN DE FALLOS EXCEDIDO); esto resulta en un valor de estado de salida de 10. Si la clave de sentido es "NO SENSE" y tanto asc como ascq son cero, el estado de salida se establece en 0. Consulte la página del manual de sg3_utils(8) para ver los valores del estado de salida.
-t, --time
mide el tiempo del(los) comando(s) SCSI REQUEST SENSE y calcula el número promedio de operaciones por segundo.
-T, --timeout=SE
donde SE es el tiempo de espera del comando de cada comando TEST UNIT READY. La unidad para SE son segundos y si se da 0, se mapea a 60 segundos, que es el valor predeterminado. Una forma alternativa de opción larga es --tmo=SE.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración). Adicionalmente, la respuesta (si se recibe) se muestra en ASCII-HEX. Use esta opción varias veces para mayor verbosidad.
-V, --version
imprime la cadena de versión y luego sale.

NOTAS

En SCSI 1 y 2, el comando REQUEST SENSE era muy importante para el procesamiento de errores y advertencias en SCSI. La capacidad de autosensado hizo que este comando fuera casi superfluo.

Sin embargo, borradores recientes de SCSI (por ejemplo, SPC-4 rev 14 y SBC-3 rev 14) aumentan la utilidad del comando REQUEST SENSE. Las condiciones de energía inactiva y en espera (baja) se pueden detectar con este comando.

El comando REQUEST SENSE no está marcado como obligatorio en SPC-3 (es decir, para todos los dispositivos SCSI), pero está marcado como obligatorio en SBC-2 (es decir, para discos), SSC-3 (es decir, para cintas) y MMC-4 (es decir, para unidades CD/DVD/HD-DVD/BD).

La indicación de progreso es opcionalmente parte de los datos de sentido. Cuando un comando previo que tarda mucho tiempo en completarse (y típicamente excluye otros comandos de acceso a medios) aún está en curso, la indicación de progreso se puede utilizar para determinar cuánto tiempo antes de que el dispositivo vuelva a su estado normal.

El comando SCSI FORMAT para discos utilizado con el bit IMMED establecido es un ejemplo de una operación que lleva una cantidad de tiempo significativa y excluye otros accesos a medios durante ese tiempo. El bit IMMED establecido instruye al comando FORMAT a devolver el control al cliente de la aplicación una vez que se ha iniciado el formato (consulte SBC-3). Varios comandos SCSI de larga duración asociados con unidades de cinta también utilizan la indicación de progreso (consulte SSC-3).

Los primeros estándares sugerían que el comando SCSI TEST UNIT READY se utilizara para sondear la indicación de progreso (consulte la utilidad sg_turs). Desde SPC-3, los estándares sugieren que el comando SCSI REQUEST SENSE debería usarse en su lugar.

El DISPOSITIVO se abre con una bandera de solo lectura (por ejemplo, en Unix con la bandera O_RDONLY).

ESTADO DE SALIDA

El estado de salida de sg_requests es 0 cuando tiene éxito. De lo contrario, consulte la página del manual de sg3_utils(8).
