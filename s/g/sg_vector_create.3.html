DESCRIPCIÓN

sg_vector_create() asigna e inicializa un nuevo vector de statgrab con `initial_used` elementos listos para usar. Inicialmente se asigna espacio para `alloc_count` elementos (para evitar demasiadas llamadas a realloc() durante las posteriores llamadas a sg_vector_resize()). El valor de `block_size` debe ser una potencia de 2; si no lo es, se redondea a la siguiente potencia de 2. Si `alloc_count` no es múltiplo de `block_size`, se redondea al siguiente múltiplo de `block_size`. Devuelve un puntero al vector recién creado.

sg_vector_clear() destruye todos los elementos contenidos en el vector dado. A diferencia de sg_vector_resize( x, 0 ), el tamaño asignado del vector permanece intacto.

sg_vector_resize() aumenta o disminuye la cantidad de elementos asignados en el vector especificado. La cantidad de elementos asignados es siempre un múltiplo del parámetro de inicialización `block_size`. En el caso especial en que se llama a sg_vector_resize() con 0 como argumento `new_count`, el vector se libera después de que todos los elementos del vector hayan sido destruidos. Devuelve el puntero al vector redimensionado.

sg_vector_free() destruye todos los elementos del vector y libera el almacenamiento perteneciente al vector dado.

sg_vector_clone() clona todos los elementos del vector dado en un nuevo vector creado con la misma especificación que el referenciado. Devuelve un puntero al vector clonado.

sg_vector_clone_into() clona todos los elementos del vector fuente dado en el vector destino dado. El vector destino debe crearse para el mismo tipo de dato de elemento que el vector fuente. Devuelve un código de error distinto de SG_ERROR_NONE si algo salió mal.

sg_vector_compute_diff() calcula un vector de diferencia entre el vector que contiene las estadísticas actuales y otro vector que contiene estadísticas más antiguas. Si un elemento existe en el vector actual pero no en el opuesto, se clona en el vector resultado. Si un elemento existe solo en el vector opuesto, no aparece en el vector destino. sg_vector_compute_diff() devuelve un código de error distinto de SG_ERROR_NONE si algo salió mal.

sg_prove_vector() comprueba si un puntero a un vector realmente apunta a un vector. En caso de que el puntero de vector dado apunte a datos corruptos, el programa se aborta. Cuando sg_prove_vector() devuelve, retorna SG_ERROR_NONE.

sg_get_nelements() devuelve el número de elementos que el área de datos dada, abarcada por un vector statgrab, contiene. La cabecera del vector se calcula internamente a partir del puntero dado al primer elemento del vector.

sg_free_stats_buf() libera el vector que abarca el área de datos dada.

NOTAS

Excepto sg_get_nelements() y sg_free_stats_buf(), ninguna de las funciones anteriores puede ser llamada desde fuera de las fuentes de libstatgrab. Las estructuras y APIs documentadas pueden cambiar sin previo aviso. La descripción de todas las demás APIs está destinada a ser leída solo por los desarrolladores de libstatgrab.

Cada vector se crea a partir de dos elementos: la información del vector y la lista de elementos:

template <class T, class Impl>
struct sg_vector {
        size_t used_count;
        size_t alloc_count;
        size_t block_shift;
        Impl vector_implementation;
        T elements[alloc_count];
};

Por supuesto, esto no es C válido, así que la solución fue ser ingenioso:

typedef struct sg_vector {
	size_t used_count;
	size_t alloc_count;
	size_t block_shift;
	struct sg_vector_init_info info;
} sg_vector;
struct sg_vector_size_helper {
	struct sg_vector v;
	long long ll;
};
#define VECTOR_SIZE offsetof(struct sg_vector_size_helper,ll)
/* Devuelve el puntero de datos de un vector */
#define VECTOR_DATA(vector) \
	(vector ? (void *)(((char *)vector)+VECTOR_SIZE) : NULL)
#define VECTOR_ADDR_ARITH(ptr) \
	(sg_vector *)(((char *)(ptr))-VECTOR_SIZE)
/* Devuelve el vector para unos datos */
#define VECTOR_ADDRESS(ptr) \
	((ptr) ? (SG_ERROR_NONE == sg_prove_vector(VECTOR_ADDR_ARITH(ptr)) ? VECTOR_ADDR_ARITH(ptr) : NULL ) : NULL)

Esto también permite a funciones de usuario como sg_get_nelements() y sg_free_stats_buf() cambiar fácilmente entre la estructura del vector y el contenido.

LA ESTRUCTURA DE ESPECIALIZACIÓN DEL VECTOR

Como se mencionó, la implementación del vector utiliza estrategias del concepto de programación orientada a objetos llamado "polimorfismo". Un vector se describe mediante un pequeño objeto que contiene atributos inherentes como el tamaño del elemento y un conjunto de "métodos virtuales" para realizar tareas relacionadas con los elementos, como inicializar o destruir elementos.

typedef void (*vector_init_function)(void *item);
typedef sg_error (*vector_copy_function)(const void *src, void *dst);
typedef sg_error (*vector_compute_diff_function)(void *dst, const void *src);
typedef int (*vector_compare_function)(const void *a, const void *b);
typedef void (*vector_destroy_function)(void *item);
struct sg_vector_init_info {
        size_t item_size;
        vector_init_function init_fn;
        vector_copy_function copy_fn;
        vector_compute_diff_function compute_diff_fn;
        vector_compare_function compare_fn;
        vector_destroy_function destroy_fn;
};

Las instancias de struct sg_vector_init_info se inicializan conceptualmente de forma estática utilizando la macro preprocesador VECTOR_INIT_INFO_FULL_INIT(type) o VECTOR_INIT_INFO_EMPTY_INIT(type). Aquí hay algunos ejemplos para demostrar cómo está pensado:

Inicialización de la descripción del vector de estadísticas de CPU

VECTOR_INIT_INFO_EMPTY_INIT(sg_cpu_stats);

Inicialización de la descripción del vector de estadísticas de Host-Info

static void sg_os_stats_item_init(sg_os_stats *d);
static void sg_os_stats_item_destroy(sg_os_stats *d);
#define sg_os_stats_item_copy NULL
#define sg_os_stats_item_compute_diff NULL
#define sg_os_stats_item_compare NULL
VECTOR_INIT_INFO_FULL_INIT(sg_os_stats);

Inicialización de la descripción del vector de estadísticas de Disk-IO

void VECTOR_CLEAR(struct sg_vector *vector)

DESCRIPCIÓN

El módulo statgrab proporciona estructuras de datos para la recopilación de datos del sistema. Los vectores son una de esas estructuras de datos, que son básicamente listas enlazadas de una longitud fija y que se pueden redimensionar.

El tipo de dato que se almacenará en el vector se determina mediante el parámetro type. La estructura sg_vector se define en /usr/include/statgrab.h.

Hay una serie de funciones y macros para la creación y manipulación de estas estructuras de datos.

sg_vector_create() crea un nuevo vector. alloc_count es el número de elementos que se asignarán inicialmente. initial_used es el número de elementos que se considerarán utilizados. type especifica el tipo de datos que contendrá el vector y se utiliza para inicializar la información de inicialización del vector.

sg_vector_resize() redimensiona el vector dado a new_count elementos. Si new_count es mayor que el tamaño actual, se asignará más memoria. Si new_count es menor que el tamaño actual, los datos se truncarán. El puntero al vector redimensionado se devuelve, o NULL si falla la reasignación de memoria.

sg_vector_clear() libera la memoria asignada para el vector dado.

VECTOR_CREATE() llama a sg_vector_create() con alloc_count = count y initial_used = 0, utilizando el tipo de especialización del vector type.

VECTOR_CLEAR() simplemente llama a sg_vector_clear(). Esta macro solo existe por conformidad.

VECTOR_CREATE_OR_RESIZE() llama a sg_vector_create() cuando el puntero del vector dado apunta a NULL, o a sg_vector_resize() en caso contrario. Se devuelve el resultado de la función apropiada.

VECTOR_UPDATE() llama a VECTOR_CREATE_OR_RESIZE() y establece los datos en el primer elemento del vector resultante cuando se obtiene un puntero no NULL, de lo contrario a NULL. Cuando VECTOR_CREATE_OR_RESIZE() devuelve un puntero NULL y new_count no es igual a 0 (cero), se ejecutan las instrucciones de la macro VECTOR_UPDATE_ERROR_CLEANUP para limpiar antes de devolver desde la subrutina actual con el error que ha ocurrido.

VECTOR_ITEM_COUNT() devuelve 0 para un vector no existente (vector == 0) y el número de elementos que contiene en caso contrario.

VALORES DE RETORNO

Además de los códigos de error, los valores de retorno, si los hay, son siempre un puntero a estructuras de vector (struct sg_vector *).
