SINOPSIS

#include "tools.h"


void *get_global_static
(unsigned int id);


sg_error sg_global_lock
(void);


sg_error sg_global_unlock
(void);

DESCRIPCIÓN

sg_comp_init() es llamada por sg_init() para ejecutar la inicialización del componente de globales y de cada componente registrado en libstatgrab. Este registro se realiza estáticamente añadiendo una estructura de información de inicialización del componente (instancia de sg_comp_info) a la lista comp_info en src/libstatgrab/globals.c. La instancia de sg_comp_info normalmente se define usando EASY_COMP_SETUP() o EXTENDED_COMP_SETUP(), respectivamente.

sg_comp_destroy() es llamada por sg_shutdown() para destruir todos los recursos globales, por ejemplo, tablas de traducción de nombres de dispositivos o expresiones regulares compiladas para hacer coincidir nombres de rutas, etc. Los recursos de estadísticas se gestionan en otro lugar y se liberan (conceptualmente y normalmente) antes de que se invoque sg_comp_destroy().

sg_comp_get_tls() es la función interna para acceder al almacenamiento local de hilos (anteriormente globales estáticas) del componente. Normalmente es más fácil depender de la macro que la encapsula GLOBAL_GET_TLS().

NOTAS

La entrega de estadísticas del sistema es trabajo de libstatgrab, la gestión de la entrega es trabajo del componente de globales. Para cumplir este trabajo, los componentes a gestionar deben estar preparados:

1.
declarar la estructura de datos global y TLS del componente (probablemente solo en teoría, no en código)
2.
definir funciones de inicialización global, destrucción de hilos y destrucción de procesos (si son requeridas por 1.)
3.
definir la estructura de información del componente usando *_COMP_SETUP()
4.
definir los accesores del componente usando uno o más de

EASY_COMP_ACCESS()
EASY_COMP_DIFF()
MULTI_COMP_ACCESS()
MULTI_COMP_DIFF()

Una vez realizados estos pasos, nace un nuevo componente que entrega nuevas estadísticas y necesita ser "anunciado". Suponiendo que el componente se llama cpu, añada la línea { &sg_cpu_init, 0 } a la lista comp_info mencionada anteriormente.

Información de inicialización del componente en detalle:

typedef sg_error (*comp_global_init_function)(unsigned id);
typedef void (*comp_global_destroy_function)(void);
typedef void (*comp_global_cleanup_function)(void *);
struct sg_comp_status {
        sg_error init_error;
};
struct sg_comp_init {
        comp_global_init_function init_fn;
        comp_global_destroy_function destroy_fn;
        comp_global_cleanup_function cleanup_fn;
        size_t static_buf_size;
#if defined(ENABLE_THREADS) && defined(HAVE_PTHREAD)
        const char **required_locks;
#endif
        struct sg_comp_status *status;
};

Los componentes que no necesitan algo especial pueden depender de EASY_COMP_SETUP():

Inicialización del componente de memoria

EASY_COMP_SETUP(mem,1,NULL);

Cuando se necesita inicialización propia, hacerlo es un poco más complejo:

Inicialización del componente de red

#define SG_NETWORK_IO_NOW_IDX	0
#define SG_NETWORK_IO_DIFF_IDX	1
#define SG_NETWORK_IFACE_IDX	2
#define SG_NETWORK_MAX_IDX	3
EXTENDED_COMP_SETUP(network,SG_NETWORK_MAX_IDX,NULL);
#ifdef LINUX
static regex_t network_io_rx;
#define RX_MATCH_COUNT (8+1)
#endif
sg_error
sg_network_init_comp(unsigned id) {
        GLOBAL_SET_ID(network,id);
#ifdef LINUX
        if( regcomp( &network_io_rx, ..., REG_EXTENDED)!=0) {
                return sg_set_error(SG_ERROR_PARSE, NULL);
        }
#endif
        return SG_ERROR_NONE;
}
void
sg_network_destroy_comp(void) {
#ifdef LINUX
        regfree(&network_io_rx);
#endif
}
EASY_COMP_CLEANUP_FN(network,SG_NETWORK_MAX_IDX)

EASY_COMP_SETUP() se encarga de todo lo necesario para instanciar automáticamente una estructura de información de componente para el componente especificado comp. La estructura de almacenamiento TLS creada contendrá nvect elementos de puntero y eso es todo. Todas las rutinas de inicialización, destrucción y limpieza se crean según sea necesario usando EASY_COMP_INIT_FN(), EASY_COMP_DESTROY_FN() y EASY_COMP_CLEANUP_FN(). Después de la cantidad de punteros de vector requeridos para ser almacenados, se debe especificar la lista de mutexes requeridos, terminada con un puntero NULL.

EXTENDED_COMP_SETUP() se encarga de todo lo necesario para instanciar una estructura de información de componente para el componente especificado comp, pero requiere la definición de las rutinas de inicialización, destrucción y limpieza. La estructura de almacenamiento TLS creada contendrá nvect elementos de puntero y eso es todo. Después de la cantidad de punteros de vector requeridos para ser almacenados, se debe especificar la lista de mutexes requeridos, terminada con un puntero NULL. Todas las rutinas estándar se pueden crear semi-automáticamente usando EASY_COMP_INIT_FN(), EASY_COMP_DESTROY_FN() y EASY_COMP_CLEANUP_FN().

DEFAULT_INIT_COMP() simplemente declara los prototipos para las rutinas de inicialización, destrucción y limpieza, define el búfer de estado de inicialización, la lista de nombres de bloqueo y finalmente rellena la estructura de inicialización del componente. Úselo cuando su almacenamiento TLS contenga más que solo punteros de vector.

GLOBAL_GET_TLS() devuelve el puntero al almacenamiento local de hilos del componente.

GLOBAL_SET_ID() almacena el identificador del componente, requerido por ejemplo para acceder a su TLS.

EASY_COMP_INIT_FN() define una rutina de inicialización de componente predeterminada. Almacena el identificador del componente y retorna con SG_ERROR_NONE.

EASY_COMP_DESTROY_FN() define un destructor de componente predeterminado, llamado al final de todo el proceso (o cuando se llama al último sg_shutdown()). El destructor predeterminado no hace nada y normalmente una rutina de inicialización individual requiere un destructor individual, también.

EASY_COMP_CLEANUP_FN() define una rutina de limpieza TLS predeterminada, siempre llamada cuando un hilo termina para liberar los vectores mantenidos en el almacenamiento local de hilos.

EASY_COMP_ACCESS() define accesores a una estadística específica que contiene un elemento proporcionado por el componente: las funciones fn() y fn##_r(). La siguiente función debe existir:
sg_error fn##_int
(sg_vector *name##_vect);
Accede al índice del vector idx del TLS del componente comp y retorna

DESCRIPTION

These macros are intended for use by the component wrappers. They simplify the handling of statistics.

EASY_COMP_INIT() initializes the statistic collection for a component. It is intended to be used for components returning a single value. nowidx and diffidx should be pointers to indices into a vector. The vector is created by the macro if it does not exist. The argument getfn() is the function used to retrieve the current statistics. The resulting index is stored in nowidx.

EASY_COMP_DIFF() calculates the difference between two statistic collection runs. The variant dealing with statgrab owned statistics return the difference between the content currently in the vector specified by nowidx and the resulting vector of getfn(). The result is stored in the vector diffidx. If there is no current result, simply the result of getfn() is returned.

MULTI_COMP_ACCESS() defines accessors to a specific statistic containing 0..n elements provided by the component: the functions fn() and the fn##_r(). The following function must exists:
sg_error
fn##_int
(sg_vector **name##_vect);
It accesses the vector idx from TLS of component comp and returns sg_##name##_stats. It manages all standard things like memory and error anagement, return values, entries update, etc.

MULTI_COMP_DIFF() does the same as EASY_COMP_DIFF() but for vectors with more than one element.

NOTES

The following functions are intended to be used by the component wrappers and not by the end user.

sg_comp_init_private() Initializes a component and returns a pointer to the component structure.

sg_comp_set_id() Sets the id for the component.

sg_comp_set_init() Sets the initialization function for the component.

sg_comp_set_update() Sets the update function for the component.
