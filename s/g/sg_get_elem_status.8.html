NOMBRE

sg_get_elem_status - envía el comando SCSI GET PHYSICAL ELEMENT STATUS

SINOPSIS

sg_get_elem_status [--brief] [--filter=FLT] [--help] [--hex] [--inhex=FN] [--json[=JO]] [--js-file=JFN] [--maxlen=LEN] [--raw] [--readonly] [--report-type=RT] [--starting=ELEM] [--verbose] [--version] DISPOSITIVO

DESCRIPCIÓN

Envía el comando SCSI GET PHYSICAL ELEMENT STATUS al DISPOSITIVO y muestra la respuesta. Ese comando se introdujo en la revisión 16 del borrador de SBC-4.

Los borradores de T10 ahora hablan tanto de elementos 'físicos' como de 'almacenamiento'. El último término es más específico (es decir, los elementos de almacenamiento son un subconjunto de los elementos físicos) y se refiere a los recursos del disco que controlan el almacenamiento de datos del usuario. Un ejemplo de elemento de almacenamiento son los datos del usuario asociados con un cabezal en un disco duro giratorio. Cuando un elemento de almacenamiento ha sido "despoblado", su almacenamiento anterior al que se accedía a través de LBA ya no está disponible. Los elementos físicos son más generales e incluyen elementos de almacenamiento y pueden incluir recursos del disco utilizados para configuraciones de página de modo "guardadas", entre otras cosas.

La acción predeterminada de esta utilidad es decodificar la respuesta en una cabecera y hasta 32 descriptores de estado de elemento físico. Los descriptores de estado se muestran uno por línea. La cantidad de salida se puede reducir con la opción --brief.

En lugar de enviar este comando SCSI al DISPOSITIVO, si se proporciona la opción --inhex=FN, el contenido del archivo llamado FN se decodifica como hexadecimal ASCII (o binario si también se proporciona --raw) y luego se procesa como si fuera la respuesta del comando GET PHYSICAL ELEMENT STATUS.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas.

-b, --brief
cuando se usa una vez, la salida de cada descriptor de estado de elemento físico se reduce a: <id_elemento>: <tipo_elemento>,<salud_elemento> . Los tres se muestran como enteros decimales. Cuando se usa dos veces, la línea "Element descriptors:" que introduce los descriptores de estado no se muestra. Cuando se usa tres o más veces, solo se muestra la cabecera de respuesta.
-f, --filter=FLT
donde FLT se coloca en un campo de dos bits llamado FILTER en el comando GET PHYSICAL ELEMENT STATUS. Solo dos valores están definidos para ese campo: 0 para todos los descriptores de elemento; 1 para aquellos descriptores de elemento que están fuera de especificación ('spec') o que tienen información de despoblación para informar. En ambos casos, los campos REPORT TYPE y STARTING ELEMENT pueden restringir (reducir) aún más el número de descriptores de elemento devueltos. El valor predeterminado es cero.
-h, --help
muestra el mensaje de uso y sale.
-H, --hex
muestra la respuesta a este comando en hexadecimal ASCII. Cada línea de 16 bytes va precedida por una dirección o índice, comenzando en 0, y la dirección también está en hexadecimal. Si se usa dos veces, se añade una representación ASCII de cada byte a la línea de salida. Si se usa tres o más veces, solo se muestra el hexadecimal ASCII de cada byte, 16 bytes por línea (es decir, sin dirección inicial ni representación ASCII final). Esta última forma es adecuada para colocarla en un archivo y ser utilizada con la opción --inhex=FN en una invocación posterior.
-i, --inhex=FN
donde FN es un nombre de archivo cuyo contenido se asume que es hexadecimal ASCII. Si también se proporciona DISPOSITIVO, se ignora DISPOSITIVO, se emite una advertencia y la utilidad continúa, decodificando el archivo llamado FN. Consulte la sección "FORMATOS HEX, BINARIO Y JSON" en la página del manual de sg3_utils para obtener más información. Si también se proporciona la opción --raw, el contenido de FN se trata como binario.
-j[=JO], --json[=JO]
la salida está en formato JSON en lugar de texto plano. Tenga en cuenta que los argumentos para la forma corta y larga son opcionales y, si están presentes, comienzan con "=" y no se permite espacio en blanco alrededor de ese "=".
Consulte la página del manual de sg3_utils_json o use '?' para JO para obtener un resumen.
-J, --js-file=JFN
la salida está en formato JSON y se envía a un archivo llamado JFN. Si ese archivo existe, se trunca. Por defecto, la salida JSON se envía a stdout.
Cuando se proporciona esta opción, la opción --json[=JO] se implica y no es necesario proporcionarla. La opción --json[=JO] aún puede ser necesaria para establecer el parámetro JO a valores distintos de los predeterminados.
-m, --maxlen=LEN
donde LEN es la longitud (máxima) de la respuesta en bytes. Se coloca en el campo "longitud de asignación" del cdb. Si no se proporciona, se utiliza 1056. 1056 es suficiente espacio para la cabecera de respuesta más 32 descriptores de estado de elemento físico. LEN debe ser un múltiplo de 32 (por ejemplo, 32, 64 y 96 son adecuados).
-r, --raw
muestra la respuesta en binario (a stdout) a menos que también se proporcione la opción --inhex=FN. En ese caso, el nombre del archivo de entrada (FN) se decodifica como binario (y la salida *no* está en binario).
-R, --readonly
abre el DISPOSITIVO en modo de solo lectura (por ejemplo, en Unix con el indicador O_RDONLY). El valor predeterminado es abrirlo en modo de lectura/escritura.
-t, --report-type=RT
donde RT se colocará en el campo REPORT TYPE del comando GET PHYSICAL ELEMENT STATUS. Actualmente solo se definen dos valores: 0 para 'elemento físico' y 1: para 'elemento de almacenamiento'. El valor predeterminado es 0.
-s, --starting=ELEM
donde ELEM se coloca en el campo STARTING ELEMENT del comando GET PHYSICAL ELEMENT STATUS. Solo se devuelven los elementos físicos con identificadores mayores o iguales a ELEM. El valor predeterminado es cero, que, si bien no es un identificador de elemento válido (ya que debe ser distinto de cero), se da en un ejemplo en el Anexo L de la revisión 17 de SBC-4. Por lo tanto, se asume que un ELEM de cero es válido en este contexto.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración). La salida adicional causada por esta opción se envía a stderr.
-V, --version
imprime la cadena de versión y sale.

NOTAS

El código de sentido adicional "Advertencia: cambio de estado del elemento físico" [0xb, 0x14] es especial y debería hacer que un cliente de aplicación llame al comando GET PHYSICAL ELEMENT STATUS. Cómo se activa esta advertencia depende de la configuración de la página de modo de control de excepciones informativas [0xc, 0x0].

Después de detectar uno o más elementos de almacenamiento fuera de especificación, el disco en cuestión debería ser desmantelado o debería invocarse el comando REMOVE ELEMENT AND TRUNCATE (o ... AND MODIFY ZONES) para reparar (y reducir la capacidad de almacenamiento) del disco.

ESTADO DE SALIDA

El estado de salida de sg_get_elem_status es 0 cuando es exitoso. De lo contrario, consulte la página del manual de sg3_utils(8).
