NOMBRE

sg_seek - envía el comando SCSI SEEK, PRE-FETCH(10) o PRE-FETCH(16)

SINOPSIS

sg_seek [--10] [--count=NC] [--grpnum=GN] [--help] [--immed] [--lba=LBA] [--num-blocks=NUM] [--pre-fetch] [--readonly] [--skip=SB] [--time] [--verbose] [--version] [--wrap-offset=WO] DISPOSITIVO

DESCRIPCIÓN

Envía un comando SCSI SEEK(10), PRE-FETCH(10) o PRE-FETCH(16) al DISPOSITIVO. El comando SEEK ha sido obsoleto desde SBC-2 (2005) pero aún es compatible con algunos discos duros e incluso algunas SSD (unidades de estado sólido). El comando PRE-FETCH puede considerarse el reemplazo moderno de SEEK. En lugar de hablar de mover los cabezales del disco a la pista que contiene la LBA buscada, habla de llevar la LBA buscada (y un número dado de bloques) a la caché del disco. Los comandos PRE-FETCH también tienen un campo IMMED.

Los comandos PRE-FETCH pueden informar errores "reales", pero generalmente informarán uno de dos estados "buenos". Para hacer esto, devuelven el estado poco utilizado CONDITION MET (condición cumplida). Si el número de bloques cabe realmente en la caché (cuando IMMED=0) o hay suficiente espacio en la caché cuando llega el comando (cuando IMMED=1), se devuelve un estado CONDITION MET. Si el número de bloques solicitado no cabía (IMMED=0) o no cabería (IMMED=1), se devuelve el estado GOOD (bueno). Por lo tanto, si un disco tiene una caché grande y PRE-FETCH se usa con poca frecuencia, es más probable que el comando devuelva CONDITION MET que GOOD. Esto presenta problemas para algunos subsistemas SCSI, ya que debido a su rareza, manejan mal CONDITION MET y lo tratan como un error (ver la sección NOTAS a continuación).

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas.

-T, --10
utiliza un comando cdb de 10 bytes, ya sea el comando SEEK(10) o PRE-FETCH(10). En ausencia de la opción --pre-fetch, se utiliza el comando SEEK(10). Si se proporciona la opción --pre-fetch sin esta opción, se utiliza un comando PRE-FETCH(16).
-c, --count=NC
NC es el número de comandos (uno de SEEK(10), PRE-FETCH(10) o PRE-FETCH(16)) que se ejecutarán. El valor predeterminado es 1. Si ocurre un error, se registra y el programa continúa hasta que se agotan NC. Si NC es 0, se comprueban las opciones y se abre el DISPOSITIVO, pero no se envían comandos.
-g, --grpnum=GN
GN es el número de grupo, un valor entre 0 y 63 (en hexadecimal: 0x3f). El valor predeterminado es 0. Esta opción se ignora si el comando seleccionado es SEEK(10).
-h, --help
muestra el mensaje de uso y sale.
-i, --immed
esta opción solo se aplica a PRE-FETCH(10) y PRE-FETCH(16), estableciendo el bit IMMED. Sin esta opción, el DISPOSITIVO regresa después de haber completado la transferencia de todos, o parte de, los bloques solicitados a la caché. Si se proporciona esta opción, el DISPOSITIVO regresa después de haber realizado verificaciones de cordura en el cdb (por ejemplo, asegurándose de que la LBA sea mayor que el número de bloques disponibles) y antes de realizar la transferencia a la caché.
Tenga en cuenta que incluso cuando se proporciona esta opción, el estado de retorno de los comandos PRE-FETCH sigue siendo CONDITION MET (si la caché parece tener suficiente espacio libre para la transferencia) o GOOD (si la caché no parece tener suficiente espacio libre).
-l, --lba=LBA
LBA es la dirección de bloque lógico inicial que se coloca en el bloque de descriptor de comando (cdb) del comando seleccionado. Tenga en cuenta que el campo LBA en SEEK(10) y PRE-FETCH(10) es una cantidad de 32 bits, mientras que con PRE-FETCH(16) es una cantidad de 64 bits. El valor predeterminado es 0.
-n, --num-blocks=NUM
NUM es el número de bloques, comenzando con y incluyendo LBA, que se colocarán en la caché del DISPOSITIVO. El comando SEEK(10) no utiliza el valor NUM. Para PRE-FETCH(10), NUM es una cantidad de 16 bits, mientras que para PRE-FETCH(16) es una cantidad de 32 bits. El valor predeterminado es 1. Si NUM es 0, el DISPOSITIVO intentará transferir todos los bloques desde la LBA dada hasta el final del medio.
-p, --pre-fetch
esta opción selecciona los comandos PRE-FETCH(10) o PRE-FETCH(16). Con la opción --10 también dada, se selecciona el comando PRE-FETCH(10); sin esa opción, se selecciona PRE-FETCH(16). Por defecto (en ausencia de esta y otras opciones 'selectivas'), se selecciona el comando SEEK(10).
-r, --readonly
esta opción establece un indicador 'solo lectura' cuando el sistema operativo subyacente abre el DISPOSITIVO dado. Esto puede no funcionar, ya que los sistemas operativos no pueden determinar fácilmente si un pase directo es una operación de lectura o escritura lógica, por lo que adoptan una postura de aversión al riesgo y requieren aperturas de DISPOSITIVO de tipo lectura-escritura independientemente de lo que realice el pase directo.
-s, --skip=SB
SB es el número de direcciones de bloque lógico a omitir, entre comandos repetidos cuando NC es mayor que 1. El valor predeterminado de SB es 1. SB puede establecerse en 0 para que todos los comandos PRE-FETCH NC utilicen la misma LBA.
-t, --time
si se proporciona, se registra el tiempo transcurrido para ejecutar NC comandos. Esto se muestra antes de que esta utilidad salga. Si NC es mayor que 1, también se muestra el tiempo "por comando".
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración).
-V, --version
muestra la cadena de versión y sale.
-w, --wrap-offset=WO
WO es el número de bloques, relativo a LBA, que cuando se excede, establece la dirección del bloque lógico del siguiente comando de nuevo a LBA. Si esta acción de "reiniciar a LBA" ocurre depende de los valores de NC y SB.

NOTAS

Antes del kernel de Linux 4.17, el estado CONDITION MET se registraba como un error. Las versiones recientes de FreeBSD manejan correctamente el estado CONDITION MET.

Si se proporciona la opción --count=NC o --verbose, se mostrará una línea de resumen como la siguiente:


Número de comandos=5, número de condition_mets=3, número de goods=2

antes de que la utilidad salga.

ESTADO DE SALIDA

El estado de salida de sg_seek es 0 (GOOD) o 25 (CONDITION_MET) cuando esta utilidad tiene éxito. Si se ejecutan múltiples comandos (por ejemplo, cuando NC es mayor que 1), el resultado del último comando SEEK o PRE-FETCH ejecutado establece el estado de salida. De lo contrario, consulte la página del manual de sg3_utils(8).
