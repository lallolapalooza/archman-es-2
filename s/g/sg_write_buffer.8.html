NOMBRE

sg_write_buffer - envía comandos SCSI WRITE BUFFER

SINOPSIS

sg_write_buffer [--bpw=CS] [--dry-run] [--help] [--id=ID] [--in=FILE] [--length=LEN] [--mode=MO] [--offset=OFF] [--read-stdin] [--skip=SKIP] [--specific=MS] [--timeout=TO] [--verbose] [--version] DISPOSITIVO

DESCRIPCIÓN

Envía uno o más comandos SCSI WRITE BUFFER al DISPOSITIVO, junto con los datos proporcionados por el usuario. En algunos casos no se requieren datos, o los datos se pueden leer del archivo dado en la opción --in=FILE, o los datos se leen de la entrada estándar cuando se da --read-stdin o --in=-.

Algunas variantes del comando WRITE BUFFER no tienen datos asociados para enviar al dispositivo. Por ejemplo, "activate_mc" activa microcódigo diferido que se envió a través de comandos WRITE BUFFER anteriores. Hay un método diferente utilizado para descargar microcódigo a dispositivos SES, consulta la utilidad sg_ses_microcode.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas. Las opciones están ordenadas alfabéticamente según el nombre de la opción larga.

-b, --bpw=CS
donde CS es el tamaño del fragmento en bytes. Este será el número máximo de bytes enviados por comando WRITE BUFFER. Por lo tanto, si CS es menor que la longitud efectiva, se envían varios comandos WRITE BUFFER, cada uno tomando el siguiente fragmento de los datos leídos y aumentando el campo de desplazamiento del búfer en el comando WRITE BUFFER por la cantidad apropiada. El valor predeterminado es un tamaño de fragmento de 0, que se interpreta como un número muy grande, por lo que solo se enviará un comando WRITE BUFFER. Esta opción solo debe usarse con modos que "descargan microcódigo, con desplazamientos ..."; es decir, el modo 0x6, 0x7, 0xd o 0xe.
El número en CS puede ir seguido opcionalmente por ",act" o ",activate". En este caso, después de enviar los comandos WRITE BUFFER hasta que se agote la longitud efectiva, se envía otro comando WRITE BUFFER con su modo establecido en "Activar modo de microcódigo diferido" [modo 0xf].
-d, --dry-run
Realiza todo el procesamiento de la línea de comandos y las comprobaciones de sanidad, incluida la lectura del archivo de entrada. Sin embargo, en el punto en que se enviarían los comandos SCSI WRITE BUFFER, omite esa llamada y asume que se completó sin errores y continúa. DISPOSITIVO aún se abre pero puede ser /dev/null (en Unix). Se recomienda usar --verbose con esta opción para obtener una visión general de lo que habría sucedido.
-h, --help
muestra el mensaje de uso y luego sale. Si se usa varias veces, también imprime los nombres de los modos y sus acrónimos.
-i, --id=ID
esta opción establece el campo de ID del búfer en el CDB. ID es un valor entre 0 (predeterminado) y 255 inclusive.
-I, --in=ARCHIVO
lee datos del archivo ARCHIVO que se enviarán con el comando WRITE BUFFER. Si ARCHIVO es '-' entonces se lee de la entrada estándar hasta que se detecta un EOF (esta es la misma acción que --read-stdin). Los datos se leen desde el principio de ARCHIVO, excepto en el caso en que sea un archivo regular y se proporcione la opción --skip=SKIP.
-l, --length=LEN
donde LEN es la longitud, en bytes, de los datos a escribir en el dispositivo. Si no se proporciona (y la longitud no se puede deducir de --in=ARCHIVO o --read-stdin), el valor predeterminado es cero. Si se proporciona la opción y la longitud deducida de --in=ARCHIVO o --read-stdin es menor (o no se proporcionan datos), entonces se utilizan bytes de 0xff como bytes de relleno.
-m, --mode=MO
esta opción establece el campo MODO en el CDB. MO es un valor entre 0 (predeterminado) y 31 inclusive. Alternativamente, se puede proporcionar un acrónimo. Consulte la sección MODOS a continuación. Para listar los acrónimos de modo disponibles en tiempo de ejecución, proporcione uno inválido (por ejemplo, '--mode=xxx') o use la opción '-hh'.
-o, --offset=OFF
esta opción establece el campo DESPLAZAMIENTO DEL BÚFER en el CDB. OFF es un valor entre 0 (predeterminado) y 2**24-1. Es un desplazamiento en bytes.
-r, --read-stdin
lee datos de la entrada estándar hasta que se detecta un EOF. Estos datos se envían con el comando WRITE BUFFER a DISPOSITIVO. La acción de esta opción es la misma que usar '--in=-'. Anteriormente, el nombre largo de esta opción era --raw y aún puede usarse por compatibilidad con versiones anteriores.
-s, --skip=SKIP
esta opción solo está activa cuando se proporciona --in=ARCHIVO y ARCHIVO es un archivo regular, en lugar de la entrada estándar. Los datos se leen a partir del desplazamiento de bytes SKIP hasta el final del archivo (o la cantidad dada por --length=LEN). Si no se proporciona, el desplazamiento de bytes tiene como valor predeterminado 0 (es decir, el inicio del archivo).
-S, --specific=MS
MS es el campo ESPECÍFICO DEL MODO en el CDB. Este es un campo de 3 bits, por lo que se aceptan los valores de 0 a 7. Este campo se introdujo en la revisión 32 de SPC-4 y se puede usar para especificar eventos adicionales que activan el microcódigo diferido (cuando MO es 0xD).
-t, --timeout=TO
TO es el tiempo de espera del comando (en segundos) para cada comando WRITE BUFFER emitido por esta utilidad. Su valor predeterminado es 300 segundos (5 minutos) y solo debe modificarse si esto no es suficiente.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración).
-V, --version
imprime la cadena de versión y luego sale.

Después del acrónimo entre corchetes se encuentran los valores decimales y hexadecimales correspondientes que también se pueden proporcionar para MO. Los siguientes se enumeran en orden numérico.

hd [0, 0x0]

vendor [1, 0x1]

data [2, 0x2]
Datos (se llamaba "Write Data" en SPC-3).
dmc [4, 0x4]

dmc_save [5, 0x5]
Descargar microcódigo, guardar y activar (se llamaba "Download microcode and save" en SPC-3).
dmc_offs [6, 0x6]

dmc_offs_save [7, 0x7]

sg_write_buffer

escribir datos en un búfer del dispositivo SCSI

SYNOPSIS

sg_write_buffer [OPTIONS] [FILE]

DESCRIPTION

Este comando lee datos del argumento FILE (o de la entrada estándar si no se proporciona FILE) y los escribe en un búfer del dispositivo SCSI dado. El tipo de búfer y otras opciones se controlan con las opciones proporcionadas.

Normalmente, el comando SCSI WRITE BUFFER se utiliza para actualizar el firmware de un dispositivo. El significado exacto de los búferes y sus números puede variar entre los vendedores de dispositivos.

OPTIONS

-b BUFFER_ID
Identificador del búfer (entero, 0 a 255). El valor predeterminado es 0.
-B byte-per-word
Define el tamaño de la palabra en bytes. El valor predeterminado es 1. Este valor puede tener un impacto en el rendimiento. Para firmware muy grande, podría ser necesario usarlo junto con un modo que contenga la palabra "offset" (desplazamiento) y un tamaño de palabra pequeño.
-c
Permite al dispositivo combinar escrituras en el búfer. Esto puede reducir la sobrecarga, pero el valor predeterminado (no combinar) es más seguro.
-d dev=DEVICE
Especifica el nombre del archivo del dispositivo SCSI (por ejemplo, /dev/sg0).
-e
Escritura de bloque expandido. Habilita el modo de bloque expandido.
-f
Fuerza la operación. Intenta continuar incluso si se detectan advertencias. Esto no es recomendable para la actualización de firmware.
-h
Imprime el mensaje de ayuda y sale.
-I FILE
Lee los datos de entrada del archivo especificado. Si se omite, se utiliza la entrada estándar.
-l LEN
Especifica la longitud en bytes de los datos a escribir. Si no se especifica, el programa intentará leer hasta 8 MiB de datos del archivo de entrada.
-m MODE
Especifica el modo de operación. Los modos comunes incluyen:
-p bits
Establece bits de protección específicos para el búfer. Consulte la documentación del dispositivo para conocer el significado de estos bits.
-s
Utiliza la interfaz SCSI-3.
-t timeout
Establece el tiempo de espera en segundos para el comando SCSI. El valor predeterminado es 120 segundos.
-v
Modo detallado. Imprime información adicional sobre la operación.
-V
Imprime la versión del programa y sale.

MODES

Esta sección describe varios modos disponibles para la utilidad sg_write_buffer. Cada modo se identifica por un nombre y un valor numérico (hexadecimal y decimal).

deh [28, 0x1C]
Descarga el historial de errores del cliente de la aplicación (se llamaba "Descargar registro de aplicación" en SPC-3).

NOTES

Si no se proporciona la opción --length=LEN, esta utilidad lee hasta 8 MiB de datos del archivo FILE dado (o de la entrada estándar). Si se requiere una cantidad mayor de datos, se debe proporcionar la opción --length=LEN.

El usuario debe tener en cuenta que la mayoría de los sistemas operativos tienen límites en la cantidad de datos que se pueden enviar con un solo comando SCSI. En Linux, esto depende del mecanismo de paso utilizado (por ejemplo, SG_IO de bloque o el controlador sg) y de varias configuraciones en sysfs en la serie de Linux lk 2.6/3 (por ejemplo, /sys/block/sda/queue/max_sectors_kb). Los dispositivos (es decir, las unidades lógicas) también suelen tener límites en la cantidad máxima de datos que pueden manejar en un comando. Estas dos limitaciones sugieren que los modos que contienen la palabra "offset" junto con la opción --bpw=CS son necesarios a medida que los archivos de firmware se hacen cada vez más grandes. Y CS puede ser bastante pequeño, por ejemplo, 4096 bytes, lo que resulta en el envío de muchos comandos WRITE BUFFER.

Intentar descargar un archivo de microcódigo/firmware demasiado grande puede provocar un error en la capa de paso (es decir, antes de que se emita el comando SCSI). En Linux, estos informes de error pueden ser oscuros, como en "pass through os error invalid argument". FreeBSD informa bien de estos errores en la consola de la máquina, pero devuelve un mensaje de error críptico a esta utilidad.

La descarga de un microcódigo incorrecto en un dispositivo tiene la capacidad de dejar ese dispositivo inoperable. Se podría esperar que el proveedor del dispositivo verifique los datos antes de activarlos. Si el comando SCSI WRITE BUFFER recibe valores inapropiados en su cdb (por ejemplo, LEN) (por ejemplo, demasiado grandes), el dispositivo debe responder con una clave de sentido de ILLEGAL REQUEST y un código de sentido adicional de INVALID FIELD IN CDB. Si un comando WRITE BUFFER (o una secuencia de ellos) falla debido a comprobaciones de verificación del proveedor del dispositivo, debe responder con una clave de sentido de ILLEGAL REQUEST y un código de sentido adicional de COMMAND SEQUENCE ERROR.

Se asume que todos los números dados con las opciones están en decimal. Alternativamente, los valores numéricos se pueden dar en hexadecimal precedidos por "0x" o "0X" (o con una "h" o "H" al final).

EXAMPLES

Lo siguiente envía nuevo firmware a un enclosure. El envío de un archivo de 1.5 MB en un solo comando WRITE BUFFER provocó que el enclosure se bloqueara temporalmente y no actualizara el firmware. Dividir el archivo de firmware en fragmentos de 4 KB (una suposición educada) tuvo más éxito:


sg_write_buffer -b 4k -m dmc_offs_save -I firmware.bin /dev/sg4

La actualización del firmware ocurrió en el siguiente ciclo de encendido del enclosure. Con un enclosure moderno, la página VPD de consulta extendida da indicaciones sobre en qué situaciones se realizará una actualización de firmware.

EXIT STATUS

El estado de salida de sg_write_buffer es 0 cuando tiene éxito. De lo contrario, consulte la página del manual sg3_utils(8).
