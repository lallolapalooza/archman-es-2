NOMBRE

sg_comp_init, sg_comp_destroy, sg_comp_get_tls, sg_global_lock, sg_global_unlock - gestión de la entrega de estadísticas del sistema

SINOPSIS

#include "tools.h"


void *get_global_static
(unsigned int id);


sg_error sg_global_lock
(void);


sg_error sg_global_unlock
(void);

DESCRIPCIÓN

sg_comp_init() es llamado por sg_init() para ejecutar la inicialización del componente global y de cada componente libstatgrab registrado. Este registro se realiza de forma estática, añadiendo una estructura de información de inicialización de componentes (instancia de sg_comp_info) a la lista comp_info en src/libstatgrab/globals.c. La instancia de sg_comp_info se define normalmente utilizando EASY_COMP_SETUP() o EXTENDED_COMP_SETUP(), respectivamente.

sg_comp_destroy() es llamado por sg_shutdown() para destruir todos los recursos globales, por ejemplo, tablas de traducción de nombres de dispositivos o expresiones regulares compiladas para coincidir con nombres de rutas, etc. Los recursos de estadísticas se gestionan en otro lugar y se liberan (conceptualmente y normalmente) antes de que se invoque sg_comp_destroy().

sg_comp_get_tls() es la función interna para acceder al almacén local de hilos (anteriormente globales estáticas) del componente. Normalmente, es más fácil confiar en la macro envolvente GLOBAL_GET_TLS().

NOTAS

La entrega de estadísticas del sistema es el trabajo de libstatgrab, la gestión de la entrega es el trabajo del componente global. Para cumplir con este trabajo, los componentes a gestionar deben estar preparados:

1.
declarar la estructura de datos global y TLS del componente (probablemente solo en papel, no en código)
2.
definir las funciones de inicialización global, destrucción de hilos y destrucción de procesos (si son requeridas por 1.)
3.
definir la estructura de información del componente usando *_COMP_SETUP()
4.
definir los accesores del componente usando uno o más de

EASY_COMP_ACCESS()
EASY_COMP_DIFF()
MULTI_COMP_ACCESS()
MULTI_COMP_DIFF()

Una vez realizados estos pasos, nace un nuevo componente que entrega nuevas estadísticas y debe ser "anunciado". Suponiendo que el componente se llama cpu, añada la línea { &sg_cpu_init, 0 } a la lista comp_info mencionada anteriormente.

Información de inicialización de componentes en detalle:

typedef sg_error (*comp_global_init_function)(unsigned id);
typedef void (*comp_global_destroy_function)(void);
typedef void (*comp_global_cleanup_function)(void *);
struct sg_comp_status {
        sg_error init_error;
};
struct sg_comp_init {
        comp_global_init_function init_fn;
        comp_global_destroy_function destroy_fn;
        comp_global_cleanup_function cleanup_fn;
        size_t static_buf_size;
#if defined(ENABLE_THREADS) && defined(HAVE_PTHREAD)
        const char **required_locks;
#endif
        struct sg_comp_status *status;
};

EASY_COMP_SETUP() se encarga de todo lo necesario para instanciar una estructura de información de componente para el componente especificado comp. La estructura de almacenamiento TLS creada contendrá nvect elementos puntero y eso es todo. Todas las rutinas de inicialización, destrucción y limpieza se crean según sea necesario utilizando EASY_COMP_INIT_FN(), EASY_COMP_DESTROY_FN() y EASY_COMP_CLEANUP_FN(). Después de la cantidad de punteros de vector requeridos para almacenar, se debe especificar la lista de mutexes requeridos, terminando con un puntero NULL.

EXTENDED_COMP_SETUP() se encarga de todo lo necesario para instanciar una estructura de información de componente para el componente especificado comp, excepto la definición requerida de las rutinas de inicialización, destrucción y limpieza. La estructura de almacenamiento TLS creada contendrá nvect elementos puntero y eso es todo. Después de la cantidad de punteros de vector requeridos para almacenar, se debe especificar la lista de mutexes requeridos, terminando con un puntero NULL. Todas las rutinas estándar se pueden crear semi-automáticamente usando EASY_COMP_INIT_FN(), EASY_COMP_DESTROY_FN() y EASY_COMP_CLEANUP_FN().

DEFAULT_INIT_COMP() simplemente declara los prototipos para las rutinas de inicialización, destrucción y limpieza, define el buffer de estado de inicialización, la lista de nombres de bloqueos y finalmente rellena la estructura de inicialización del componente. Úselo cuando su almacenamiento TLS contenga más que solo punteros de vector.

GLOBAL_GET_TLS() devuelve el puntero al almacén local de hilos del componente.

GLOBAL_SET_ID() almacena el identificador del componente, requerido, por ejemplo, para acceder a su TLS.

EASY_COMP_INIT_FN() define una rutina de inicialización de componente predeterminada. Almacena el identificador del componente y devuelve SG_ERROR_NONE.

EASY_COMP_DESTROY_FN() define un destructor de componente predeterminado, llamado al final de todo el proceso (o cuando se llama al último sg_shutdown()). El destructor predeterminado no hace nada y normalmente una rutina de inicialización individual requiere también un destructor individual.

EASY_COMP_CLEANUP_FN() define una rutina de limpieza TLS predeterminada, siempre llamada cuando un hilo termina para liberar los vectores mantenidos en el almacén local de hilos.

NOMBRE

sg_comp_get_tls ― obtener el índice TLS del componente

SINOPSIS

#include <statgrab.h>
sg_uint32_t
sg_comp_get_tls(sg_component_t *comp);

DESCRIPCIÓN

La función sg_comp_get_tls() devuelve el índice TLS del componente dado.

Un componente gestiona un número de estadísticas. Estas estadísticas pueden ser consultadas de manera segura por varios hilos. El valor devuelto por esta función puede ser utilizado como índice en el hilo de datos del componente.

Las macros EASY_COMP_ACCESS, EASY_COMP_DIFF, MULTI_COMP_ACCESS y MULTI_COMP_DIFF se encargan de acceder a los datos del componente de forma segura y de gestionar el hilo de datos asociado.

MACROS DE ACCESO AL COMPONENTE

Las siguientes macros facilitan el acceso y la gestión de los datos del componente.

EASY_COMP_ACCESS() define un acceso a una estadística específica con un solo elemento proporcionada por el componente. Crea una función fn() y fn##_r(). Las siguientes funciones deben existir:

sg_error
fn##_int(sg_uint32_t idx);

Accede al vector idx del hilo de datos del componente comp y devuelve sg_##name##_stats. Gestiona todas las cosas estándar como la memoria y la gestión de errores, el valor de retorno, etc.

EASY_COMP_DIFF() devuelve la diferencia entre las dos ejecuciones de recolección de estadísticas. La variante que se ocupa de las estadísticas propiedad de statgrab devuelve la diferencia entre el contenido actual del vector especificado por nowidx y el vector resultante de getfn(). El resultado se almacena en el vector diffidx. Si no hay un resultado actual, simplemente se devuelve el resultado de getfn().

MULTI_COMP_ACCESS() define accesores para una estadística específica que contiene 0..n elementos proporcionados por el componente: las funciones fn() y fn##_r(). La siguiente función debe existir:

sg_error
fn##_int(sg_uint32_t idx, sg_vector **name##_vect);

Accede al vector idx del hilo de datos del componente comp y devuelve sg_##name##_stats. Gestiona todas las cosas estándar como la memoria y la gestión de errores, los valores de retorno, la actualización de entradas, etc.

MULTI_COMP_DIFF() hace lo mismo que EASY_COMP_DIFF() pero para vectores con más de un elemento.
