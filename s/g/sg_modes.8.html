NOMBRE

sg_modes - lee páginas de modo con el comando SCSI MODE SENSE

SINOPSIS

sg_modes [--all] [--ALL] [--control=PC] [--dbd] [--dbout] [--examine] [--flexible] [--help] [--hex] [--list] [--llbaa] [--maxlen=LEN] [--multiple] [--page=PG[,SPG]] [--raw] [-R] [--readwrite] [--six] [--verbose] [--version] [DISPOSITIVO]

sg_modes [-6] [-a] [-A] [-c=PC] [-d] [-D] [-e] [-f] [-h] [-H] [-l] [-L] [-m=LEN] [-M] [-p=PG[,SPG]] [-r] [-subp=SPG] [-v] [-V] [-w] [-?] [DISPOSITIVO]

DESCRIPCIÓN

Esta utilidad envía un comando SCSI MODE SENSE al DISPOSITIVO y muestra la respuesta. Existe una variante de 6 y 10 bytes (cdb) del comando MODE SENSE, esta utilidad utiliza la variante de 10 bytes por defecto. El estándar SPC-4 (y el estándar SPC-5) indicaron que los implementadores debían migrar de los comandos SCSI MODE SELECT(6) y MODE SENSE(6) en favor de las variantes de 10 bytes (por ejemplo, MODE SENSE(10)). En el borrador SPC-6 revisión 7, los comandos SCSI MODE SELECT(6) y MODE SENSE(6) han sido eliminados.

Esta utilidad decodifica las cabeceras de las páginas de modo y los descriptores de bloque, pero muestra el contenido de cada página de modo en hexadecimal. Tampoco tiene una función para cambiar el contenido de las páginas de modo o los datos de los descriptores de bloque. El contenido de las páginas de modo se decodifica y se puede cambiar con la utilidad sdparm.

Esta utilidad soporta dos sintaxis de línea de comandos, la preferida se muestra primero en la sinopsis y se explica en esta sección. Una sección posterior sobre la sintaxis de línea de comandos antigua describe el segundo grupo de opciones.

Si no se proporciona una página (y no se selecciona --list) entonces se asume --all. La opción --all solicita todas las páginas de modo (pero no subpáginas) en una sola respuesta.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas.

-a, --all
muestra todas las páginas de modo reportadas por el DISPOSITIVO. Esto es lo que la página de código 63 (0x3f) está definida para hacer. Cuando se usa una vez, las subpáginas de modo no se obtienen. Cuando se usa dos veces (por ejemplo, '-aa'), se solicitan todas las páginas y subpáginas de modo, lo que equivale a '--page=63,255'.
-A, --ALL
mismo significado que usar la opción --all dos veces. Es decir, se obtienen todas las páginas y subpáginas de modo. El valor predeterminado es obtener todas las páginas de modo, pero no las subpáginas de modo.
-c, --control=PC
PC es el valor de control de página. El dispositivo mantiene hasta cuatro versiones diferentes de cada página:
0: valores actuales (es decir, los que están activos en este momento)
1: valores modificables
2: valores predeterminados (es decir, la configuración del fabricante)
3: valores guardados
Los valores modificables son máscaras de bits que muestran qué campos se podrían cambiar con un MODE SELECT. Los valores guardados se restablecerán la próxima vez que el dispositivo se reinicie o se restablezca la energía. Si esta opción no se proporciona, se asumen los valores actuales [0].
-d, --dbd
deshabilita los descriptores de bloque. Por defecto, los descriptores de bloque (generalmente uno (para discos) o ninguno) se devuelven en una respuesta MODE SENSE. Esta opción establece el bit "disable block descriptors" (DBD) en el cdb, que instruye al dispositivo a no devolver ningún descriptor de bloque en su respuesta. Es posible que los dispositivos más antiguos no admitan esta configuración y devuelvan una clave de sentido de "solicitud ilegal"; alternativamente, pueden ignorarlo. Curiosamente, el conjunto de comandos de bloque reducido (RBC) requiere que este bit esté establecido.
-D, --dbout
deshabilita la salida de descriptores de bloque. Independientemente de si los descriptores de bloque están presentes en la respuesta o no, no se muestran.
-e, --examine
si la opción --page=PG[,SPG] no se proporciona, examina cada página de modo en el rango de 0 a 62 (inclusive). Si se proporciona la opción --page=PG[,SPG], entonces se examinan todas las subpáginas cuyo código de página es PN (subpáginas 0 a 254 (inclusive)). Si se recibe alguna respuesta, imprime el nombre de la página de modo (o subpágina) o el número (en hexadecimal) si el nombre no se conoce.
La utilidad sdparm, que lista las páginas de modo y VPD, también tiene una opción --examine con funcionalidad similar.
-f, --flexible
Algunos dispositivos, puentes y/o controladores intentan traducciones rudimentarias entre los comandos MODE SENSE de 6 y 10 bytes sin corregir la respuesta. Esto hará que la respuesta se interprete incorrectamente (generalmente con un error que dice que la respuesta está mal formada). Con esta opción, se comprueba la longitud de la respuesta y, si parece incorrecta, la respuesta se decodifica como si se hubiera enviado el otro modo de sentido (longitud del cdb).
-h, --help
muestra el mensaje de uso y sale.
-H, --hex
Dado que esta utilidad muestra la estructura de una respuesta del comando MODE SENSE (es decir, su cabecera de parámetros, cero o más descriptores de bloque seguidos de cero o más páginas de modo), pero muestra la mayor parte del contenido de la respuesta en hexadecimal. Cuando esta opción se usa una vez, la única diferencia es que el nombre de la página de modo, si se conoce, va seguido de su número de página (y número de subpágina) entre paréntesis en hexadecimal.
Cuando esta opción se da dos veces, cada línea de salida hexadecimal tiene una representación ASCII de ese lugar hexadecimal al final de cada línea. Cuando esta opción se da tres veces, se omite la dirección hexadecimal, que se muestra al principio de cada línea hexadecimal, no hay representación ASCII del hexadecimal y se eliminan todas las líneas de texto. Esto deja un hexadecimal simple que es analizable y representa la respuesta del comando MODE SENSE. Las partes componentes de esa respuesta se colocan en líneas separadas.
Cuando la opción se da cuatro o más veces (recomendado para un formato analizable), las líneas informativas ASCII vuelven, pero todas comienzan con "#" que un analizador necesita ignorar. La salida se envía a stdout mientras que cualquier mensaje de error o advertencia se envía a stderr. Por lo tanto, la redirección simple de línea de comandos de Unix de stdout a un archivo (hecho con '>' en la mayoría de los shells de Unix) debería ser suficiente para capturar la salida. Como se mencionó anteriormente, la utilidad sdparm se puede usar para decodificar ese archivo hexadecimal más tarde con su opción '--inhex=FN'.
-l, --list
enumera todos los códigos de página y subpágina comunes y sus nombres que se encuentran en el conjunto de comandos que coincide con el tipo de periférico del DISPOSITIVO dado. Si no se proporciona DISPOSITIVO ni --page=PG, se enumeran los códigos y nombres de páginas y subpáginas comunes para SBC (por ejemplo, un disco). Si no se proporciona DISPOSITIVO y se proporciona --page=PG, se enumeran los códigos y nombres de páginas y subpáginas comunes para el conjunto de comandos cuyo tipo de dispositivo periférico coincide con el valor dado a PG. Por ejemplo, 'sg_mode --list --page=1' enumera las páginas de modo y subpáginas de comandos para dispositivos de cinta. Además, si se proporciona un sub_page_code, se interpreta como un identificador de transporte y se enumeran los códigos de página específicos del transporte de comandos y sus nombres después de la lista principal de páginas de modo. Se ignoran otras opciones.
-L, --llbaa
establece el bit Long LBA Accepted (LLBAA) en el cdb MODE SENSE (10). Este bit no está definido en el cdb MODE SENSE (6), por lo que establecer las opciones '-L' y '--six' se informa como un error. Cuando se establece, el DISPOSITIVO puede responder con descriptores de bloque de 16 bytes, como se indica en el campo 'LongLBA' en la respuesta. En la mayoría de los casos, no es necesario establecer esta opción.
-m, --maxlen=LEN
LEN es la longitud máxima de respuesta en bytes. Es el campo de 'longitud de asignación' en el cdb. Cuando no se proporciona (o LEN es cero), el campo de longitud de asignación se establece en 4096 para MODE SENSE (10) o 252 para MODE SENSE (6). El argumento LEN debe ser no negativo y no mayor que 65535 para MODE SENSE (10) y no mayor que 255 para MODE SENSE (6).
-M, --multiple
para cada página de modo (y subpágina de modo), obtén todas

VER TAMBIÉN

-R
envía la página de modo seleccionada a stdout un byte por línea. Cada línea contiene dos dígitos hexadecimales (p. ej., "3e"). Útil como entrada (después de editarla) para la utilidad sg_wr_mode(8).
-w, --readwrite
abre DEVICE en modo "lectura-escritura". El valor predeterminado es abrirlo en modo de solo lectura.
-6, -s, --six
por defecto, esta utilidad envía un comando MODE SENSE de 10 bytes al DEVICE. Sin embargo, algunos dispositivos SCSI solo admiten comandos MODE SENSE de 6 bytes (p. ej., unidades de cinta SCSI-2). Este parámetro fuerza el uso de comandos MODE SENSE de 6 bytes.
-v, --verbose

-V, --version

NOTAS

Si la utilidad sg_modes normal falla con "illegal command operation code" (código de operación de comando ilegal), intente la opción '--six' (o '-6').

Esta utilidad realiza un comando SCSI INQUIRY para determinar el tipo de periférico del dispositivo (p. ej., 0 -> Dispositivo de Acceso Directo (disco)) antes de enviar un comando MODE SENSE. Esto ayuda a decodificar el descriptor de bloque y las páginas de modo.

Esta utilidad abre DEVICE en modo de solo lectura (p. ej., en Unix, con la bandera O_RDONLY) por defecto. Abrirá DEVICE en modo de lectura-escritura si se proporciona la opción --readwrite.

En la serie 2.4 de los kernels de Linux, DEVICE debe ser un dispositivo genérico SCSI (sg). En la serie 2.6, también se pueden especificar dispositivos de bloque (p. ej., discos SCSI y unidades de DVD). Por ejemplo, "sg_modes -a /dev/sda" funcionará en los kernels de la serie 2.6.

Esta utilidad no tiene salida JSON porque su salida principal son las páginas de modo en hexadecimal. Por lo tanto, aparte del nombre de la página de modo y su estructura, no se decodifica nada. La utilidad sdparm decodifica el contenido de las páginas de modo y admite salida JSON.

ESTADO DE SALIDA

El estado de salida de sg_modes es 0 cuando tiene éxito. De lo contrario, consulte la página del manual sg3_utils(8).

Consulte la sección VARIABLES DE ENTORNO para otra forma de forzar el uso de estas opciones de línea de comandos antiguas.

-6

-c=PC

-d
consulte --dbd en la descripción principal.
-D
consulte --dbout en la descripción principal.
-e
consulte --examine en la descripción principal.
-f
consulte --flexible en la descripción principal.
-h
La acción predeterminada es decodificar números de página de modo conocidos (y números de subpágina) a texto. Con esta opción, los números de página de modo (y números de subpágina) se envían en hexadecimal.
-H
misma acción que la opción '-h'.
-l
consulte --list en la descripción principal.
-L
consulte --llbaa en la descripción principal.
-N, --new
Cambia a las opciones de estilo más nuevo.
-m=LEN
consulte --maxlen=LEN en la descripción principal.
-M
consulte --multiple en la descripción principal.
-p=PG
PG es el código de página a obtener. Debería ser un número hexadecimal entre 0 y 3f inclusive (0 a 63 decimal). El valor predeterminado cuando se requiere es 3f (obtener todas las páginas de modo). Tenga en cuenta que no se acepta un acrónimo para los valores de página y/o subpágina en este formato antiguo (porque cualquier acrónimo que comience con las letras 'a' a 'f' es ambiguo; podría ser un número hexadecimal o un acrónimo).
-p=PG,SPG
valores de código de página y subpágina a obtener. El código de página debería ser un número hexadecimal entre 0 y 3f inclusive. El código de subpágina debería ser un número hexadecimal entre 0 y ff inclusive. El valor predeterminado para el código de subpágina es 0.
-r
envía la página de modo seleccionada a stdout un byte por línea. Cada línea contiene dos dígitos hexadecimales (p. ej., "3e"). Útil como entrada (después de editarla) para la utilidad sg_wr_mode(8).
-subp=SPG
código de subpágina a obtener. Debería ser un número hexadecimal entre 0 y 0xff inclusive. El valor predeterminado es 0.

-V
imprime la cadena de versión y sale.
-w
consulte --readwrite en la descripción principal.
-?
imprime el mensaje de uso y sale. Ignora todos los demás parámetros.

VARIABLES DE ENTORNO

Desde la versión 1.23 de sg3_utils, se puede proporcionar la variable de entorno SG3_UTILS_OLD_OPTS. Cuando está presente, esta utilidad esperará las opciones de línea de comandos antiguas. Por lo tanto, la presencia de esta variable de entorno equivale a usar --old (o -O) como la primera opción de línea de comandos.

EJEMPLOS

Todas las páginas de modo, pero no las subpáginas de modo, se pueden volcar en hexadecimal a un archivo así:


# sg_modes -a -HHHH /dev/sdb > modes_sdeb.hex

Si hay algún error, se envían a stderr para que aparezcan en la consola y no dentro del archivo modes_sdeb.hex. No obstante, el contenido de modes_sdeb.hex puede no ser útil si ha ocurrido un error.

La opción '-HHHH' produce salida hexadecimal con líneas de comentarios que comienzan con un carácter '#'. Cada comentario describe el bloque siguiente. Si todo está bien, el archivo modes_sdeb.hex será adecuado para que la utilidad sdparm lo decodifique:


# sdparm -a --inhex=modes_sdeb.hex

Consulte la página del manual de sdparm(8) para obtener más información.
Para volcar tanto páginas de modo como subpáginas, use esta invocación:


# sg_modes -aa -HHHH /dev/sdb > modes_sdeb.hex

No se necesita ningún cambio en la llamada asociada a sdparm. Hay alguna salida de ejemplo en el directorio inhex del paquete sg3_utils, en un archivo llamado: modes_sdeb.hex. El archivo se produjo utilizando esta utilidad en el controlador scsi_debug en Linux.

Cada página de modo (y subpágina) tiene hasta cuatro 'controles de página': actual, modificable, predeterminado y guardado. Los últimos tres pueden ser o no compatibles con el dispositivo. Todos los controles de página disponibles para todas las páginas de modo y subpáginas se pueden colocar en un archivo hexadecimal con esta invocación:


# sg_modes -aa -M -HHHH /dev/sdb > modes_mm_sdeb.hex

Nuevamente, no se necesita ningún cambio en la llamada asociada a sdparm. Hay alguna salida de ejemplo en el directorio inhex del paquete sg3_utils, en un archivo llamado: modes_mm_sdeb.hex.
