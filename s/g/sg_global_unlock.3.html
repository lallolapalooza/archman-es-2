NOMBRE

sg_comp_init, sg_comp_destroy, sg_comp_get_tls, sg_global_lock, sg_global_unlock - gestión de la entrega de estadísticas del sistema

SINOPSIS

#include "tools.h"


void *get_global_static
(unsigned int id);


sg_error sg_global_lock
(void);


sg_error sg_global_unlock
(void);

DESCRIPCIÓN

sg_comp_init() es llamada por sg_init() para ejecutar la inicialización del componente global y de cada componente registrado de libstatgrab. Este registro se realiza estáticamente añadiendo una estructura de información de inicialización de componentes (instancia de sg_comp_info) a la lista comp_info en src/libstatgrab/globals.c. La instancia de sg_comp_info se define normalmente usando EASY_COMP_SETUP() o EXTENDED_COMP_SETUP(), respectivamente.

sg_comp_destroy() es llamada por sg_shutdown() para destruir todos los recursos globales, p. ej., tablas de traducción de nombres de dispositivos o expresiones regulares compiladas para coincidir con nombres de rutas, etc. Los recursos de estadísticas se gestionan en otro lugar y se liberan (conceptualmente y normalmente) antes de que se invoque sg_comp_destroy().

sg_comp_get_tls() es la función interna para acceder al almacenamiento local de hilos (anteriormente globales estáticos) del componente. Normalmente es más fácil confiar en la macro encapsulante GLOBAL_GET_TLS().

NOTAS

La entrega de estadísticas del sistema es trabajo de libstatgrab, la gestión de la entrega es trabajo del componente global. Para cumplir con este trabajo, los componentes a gestionar deben estar preparados:

1.
declarar la estructura de datos global y TLS del componente (probablemente solo en papel, no en código)
2.
definir funciones de inicialización global, destrucción de hilos y destrucción de procesos (si son requeridas por 1.)
3.
definir la estructura de información del componente usando *_COMP_SETUP()
4.
definir los accesores del componente usando una o más de

EASY_COMP_ACCESS()
EASY_COMP_DIFF()
MULTI_COMP_ACCESS()
MULTI_COMP_DIFF()

Después de haber realizado estos pasos, nace un nuevo componente que entrega nuevas estadísticas y necesita ser "anunciado". Suponiendo que el componente se llama cpu, añadir la línea { &sg_cpu_init, 0 } a la lista de información de componentes mencionada anteriormente.

Información de inicialización del componente en detalle:

typedef sg_error (*comp_global_init_function)(unsigned id);
typedef void (*comp_global_destroy_function)(void);
typedef void (*comp_global_cleanup_function)(void *);
struct sg_comp_status {
        sg_error init_error;
};
struct sg_comp_init {
        comp_global_init_function init_fn;
        comp_global_destroy_function destroy_fn;
        comp_global_cleanup_function cleanup_fn;
        size_t static_buf_size;
#if defined(ENABLE_THREADS) && defined(HAVE_PTHREAD)
        const char **required_locks;
#endif
        struct sg_comp_status *status;
};

Los componentes que no necesitan nada especial pueden depender de EASY_COMP_SETUP():

Inicializando el componente de memoria

EASY_COMP_SETUP(mem,1,NULL);

Cuando se necesita una inicialización propia, hacerlo es un poco más complejo:

Inicializando el componente de red

#define SG_NETWORK_IO_NOW_IDX	0
#define SG_NETWORK_IO_DIFF_IDX	1
#define SG_NETWORK_IFACE_IDX	2
#define SG_NETWORK_MAX_IDX	3
EXTENDED_COMP_SETUP(network,SG_NETWORK_MAX_IDX,NULL);
#ifdef LINUX
static regex_t network_io_rx;
#define RX_MATCH_COUNT (8+1)
#endif
sg_error
sg_network_init_comp(unsigned id) {
        GLOBAL_SET_ID(network,id);
#ifdef LINUX
        if( regcomp( &network_io_rx, ..., REG_EXTENDED)!=0) {
                return sg_set_error(SG_ERROR_PARSE, NULL);
        }
#endif
        return SG_ERROR_NONE;
}
void
sg_network_destroy_comp(void) {
#ifdef LINUX
        regfree(&network_io_rx);
#endif
}

EASY_COMP_SETUP() se encarga de todo lo necesario para instanciar una estructura de información de componente para el componente especificado comp. La estructura de almacenamiento TLS creada contendrá nvect elementos de puntero y eso es todo. Todas las rutinas de inicialización, destrucción y limpieza se crean según sea necesario usando EASY_COMP_INIT_FN(), EASY_COMP_DESTROY_FN() y EASY_COMP_CLEANUP_FN(). Después de la cantidad de punteros de vector requeridos que se van a almacenar, se debe especificar la lista de mutexes requeridos, terminando con un puntero NULL.

EXTENDED_COMP_SETUP() se encarga de todo lo necesario para instanciar una estructura de información de componente para el componente especificado comp, pero requiere la definición de las rutinas de inicialización, destrucción y limpieza. La estructura de almacenamiento TLS creada contendrá nvect elementos de puntero y eso es todo. Después de la cantidad de punteros de vector requeridos que se van a almacenar, se debe especificar la lista de mutexes requeridos, terminando con un puntero NULL. Todas las rutinas estándar se pueden crear semi-automáticamente usando EASY_COMP_INIT_FN(), EASY_COMP_DESTROY_FN() y EASY_COMP_CLEANUP_FN().

DEFAULT_INIT_COMP() simplemente declara los prototipos para las rutinas de inicialización, destrucción y limpieza, define el búfer de estado de inicialización, la lista de nombres de bloqueos y finalmente rellena la estructura de información del componente. Úselo cuando su almacenamiento TLS contenga más que solo punteros de vector.

GLOBAL_GET_TLS() devuelve el puntero al almacenamiento local de hilos del componente.

GLOBAL_SET_ID() almacena el identificador del componente, requerido p. ej. para acceder a su TLS.

EASY_COMP_INIT_FN() define una rutina de inicialización de componente predeterminada. Almacena el identificador del componente y retorna con SG_ERROR_NONE.

EASY_COMP_DESTROY_FN() define un destructor de componente predeterminado, llamado al final de todo el proceso (o cuando se llama al último sg_shutdown()). El destructor predeterminado no hace nada y normalmente una rutina de inicialización individual requiere un destructor individual, también.

EASY_COMP_CLEANUP_FN() define una rutina de limpieza TLS predeterminada, siempre llamada cuando un hilo termina para liberar los vectores mantenidos en el almacenamiento local de hilos.

EASY_COMP_ACCESS() define los accesores a una estadística específica que contiene un elemento proporcionado por el componente: las funciones fn() y fn##_r(). Debe existir la siguiente función:
sg_error fn##_int
(sg_vector *name##_vect);
Accede al vector idx del TLS del componente comp y retorna

sg_global_unlock.3.en — libstatgrab

NAME

sg_global_unlock, sg_comp_unlock, sg_mem_unlock, sg_error_unlock, EASY_COMP_DIFF, MULTI_COMP_DIFF — desbloquea la estructura de datos global

SYNOPSIS

#include <statgrab.h>
void
sg_global_unlock(void);
sg_error
sg_comp_unlock(sg_component_t    *comp);
sg_error
sg_mem_unlock(sg_vector      **vect);
sg_error
sg_error_unlock(sg_error_t   **err);
sg_error EASY_COMP_DIFF(sg_component_t *comp,
    sg_vector **nowidx, sg_vector **diffidx,
    sg_error (*getfn)(sg_component_t *,
        sg_vector **));
sg_error MULTI_COMP_DIFF(sg_component_t *comp,
    sg_vector **nowidx, sg_vector **diffidx,
    sg_error (*getfn)(sg_component_t *,
        sg_vector **));

DESCRIPTION

Estas funciones son las correspondientes para liberar recursos de las funciones de bloqueo de la interfaz de la biblioteca libstatgrab. La más importante es sg_global_unlock, que libera el bloqueo global de los recursos de la biblioteca. Casi todas las funciones de la biblioteca libstatgrab (y por lo tanto su API) están protegidas por un bloqueo global para evitar condiciones de carrera. Esto evita la posibilidad de que un hilo cambie el contenido de los datos que otro hilo está intentando leer.

sg_comp_unlock libera el bloqueo de un componente específico. Los componentes son las distintas colecciones de estadísticas como la red, los procesos, la memoria, etc. Los datos de estos componentes se guardan en las estructuras de datos de sg_vector. A menos que se acceda directamente a las estructuras de datos de sg_vector (lo que se desaconseja encarecidamente), esta función no debería ser necesaria para la mayoría de los usuarios.

sg_mem_unlock libera el bloqueo de un vector de estadísticas específico. Esto debería hacerse cuando ya no se necesita la información del vector. La mayoría de las veces, el vector se liberará como parte de la llamada a sg_vector_free.

sg_error_unlock libera el bloqueo de una estructura de error específica. Esto libera la estructura de error que se obtuvo al llamar a sg_error_get.

El uso principal de estas funciones de desbloqueo es para los desarrolladores que acceden directamente a las estructuras de datos de bajo nivel de la biblioteca libstatgrab. Por ejemplo, para obtener los datos de la red, un desarrollador podría llamar a sg_net_stats_get, que devuelve un puntero a una estructura sg_net_stats. Si el desarrollador quisiera liberar esta estructura de datos, llamaría a sg_net_stats_free.

NOTES

EASY_COMP_DIFF() se utiliza para comparar las estadísticas de un único componente. El componente es proporcionado por el argumento comp. El argumento nowidx apunta al resultado actual del componente, y diffidx contendrá la diferencia entre nowidx y el resultado de getfn(). Si nowidx es NULL, diffidx contendrá simplemente el resultado de getfn().

La función proporcionada a getfn debe ser una que devuelva un sg_error y acepte dos argumentos: un sg_component_t * y un sg_vector **. Por ejemplo:

sg_error get_proc_stats(sg_component_t *comp, sg_vector **vect);

Esta función accederá al vector idx de TLS del componente comp y devolverá sg_##name##_stats. Gestiona todas las cosas estándar como la gestión de memoria y errores, el valor de retorno, etc.

EASY_COMP_DIFF() devuelve la diferencia entre las dos ejecuciones de recopilación de estadísticas. La variante que se ocupa de las estadísticas propiedad de statgrab devuelve la diferencia entre el contenido actual en el vector especificado por nowidx y el vector resultante de getfn(). El resultado se almacena en el vector diffidx. Si no hay ningún resultado actual, simplemente se devuelve el resultado de getfn().

MULTI_COMP_ACCESS() define los accesores a una estadística específica que contiene 0..n elementos proporcionados por el componente: las funciones fn() y fn##_r(). La siguiente función debe existir:
sg_error fn##_int
(sg_vector **name##_vect);
Accede al vector idx del TLS del componente comp y devuelve sg_##name##_stats. Gestiona todas las cosas estándar como la gestión de memoria y errores, los valores de retorno, las actualizaciones de entradas, etc.

MULTI_COMP_DIFF() hace lo mismo que EASY_COMP_DIFF() pero para vectores con más de un elemento.
