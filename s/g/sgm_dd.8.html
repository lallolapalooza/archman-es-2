SGM_DD(8) SG3_UTILS SGM_DD(8)

NOMBRE

sgm_dd - copia datos hacia y desde archivos, especialmente dispositivos SCSI

SINOPSIS

sgm_dd [bs=BS] [count=COUNT] [ibs=BS] [if=IFILE] [iflag=FLAGS] [obs=BS] [of=OFILE] [oflag=FLAGS] [seek=SEEK] [skip=SKIP] [--help] [--version]

[bpt=BPT] [cdbsz=6|10|12|16] [dio=0|1] [sync=0|1] [time=0|1] [verbose=VERB] [--dry-run] [--progress] [--verbose]

DESCRIPCIÓN

Copia datos hacia y desde cualquier archivo. Especializado para "archivos" que son dispositivos genéricos SCSI (sg) de Linux y dispositivos raw. Utiliza transferencias mapeadas en memoria en dispositivos sg. Sintaxis y semántica similar a dd(1) pero no realiza ninguna conversión.

Solo realizará transferencias mapeadas en memoria cuando IFILE u OFILE sean dispositivos genéricos SCSI (sg).

Si tanto IFILE como OFILE son dispositivos sg, entonces se realizan transferencias mapeadas en memoria en IFILE. Si no se especifican otras banderas, entonces se realiza E/S indirecta en OFILE. Si se proporciona 'oflag=dio', se intenta E/S directa en OFILE. Si la E/S directa no está disponible, esta utilidad recurre a la E/S indirecta y lo informa al final de la copia.

El primer grupo en la sinopsis anterior son operandos "estándar" de dd(1) de Unix. El segundo grupo son opciones adicionales agregadas por esta utilidad. Ambos grupos se definen a continuación.

OPCIONES

bpt=BPT
cada transacción de E/S se realizará utilizando BPT bloques (o menos si está cerca del final de la copia). El valor predeterminado es 128 para tamaños de bloque menores a 2048 bytes, de lo contrario, el valor predeterminado es 32. Por lo tanto, para bs=512, las lecturas y escrituras transmitirán cada una 64 KiB de datos por defecto (menos si está cerca del final de la transferencia o por restricciones de memoria). Cuando se accede a unidades de CD/DVD, el tamaño del bloque suele ser de 2048 bytes y bpt tiene un valor predeterminado de 32, lo que nuevamente implica transferencias de 64 KiB.
bs=BS
donde BS **debe** ser el tamaño del bloque del dispositivo físico. Tenga en cuenta que esto difiere de dd(1), que permite que BS sea un múltiplo integral. El valor predeterminado es 512, que suele ser correcto para discos pero incorrecto para CD-ROMs (que normalmente tienen bloques de 2048 bytes). Para esta utilidad, el tamaño máximo de cada operación de E/S individual es BS * BPT bytes.
cdbsz=6 | 10 | 12 | 16
tamaño de los bloques de comandos SCSI READ y/o WRITE emitidos en nombres de dispositivos sg. El valor predeterminado es 10 bytes para bloques de comandos SCSI (a menos que los cálculos indiquen que se puede exceder un número de bloque de 4 bytes, en cuyo caso el valor predeterminado es 16 bytes para comandos SCSI).
count=COUNT
copia COUNT bloques desde IFILE a OFILE. El valor predeterminado es el número mínimo (de IFILE y OFILE) de bloques que los dispositivos sg informan desde los comandos SCSI READ CAPACITY o que los dispositivos de bloque (o sus particiones) reportan. Los archivos normales no se sondean para conocer su tamaño. Si se dan skip=SKIP o seek=SEEK y el recuento se deriva (es decir, no se da explícitamente), el recuento derivado se reduce para que la copia no supere el dispositivo. Si el nombre del archivo es una partición de dispositivo de bloque y no se proporciona COUNT, se utiliza el tamaño de la partición en lugar del tamaño del dispositivo completo. Si no se proporciona COUNT y no se puede derivar, se emite un mensaje de error y no se realiza ninguna copia.
dio=0 | 1
permite que la E/S directa se seleccione en el lado de escritura (es decir, en OFILE). Solo se permite cuando el lado de lectura (es decir, IFILE) es un dispositivo sg. Cuando es 1, puede haber una copia "sin copia" (es decir, transferencia mapeada en memoria de la lectura al espacio del usuario y E/S directa desde allí en la escritura, potencialmente dos DMA y sin copia de datos de la CPU). El valor predeterminado es 0. La misma acción que 'dio=1' también está disponible con 'oflag=dio'.
ibs=BS
si se proporciona, debe ser el mismo que BS dado a la opción 'bs='.
if=IFILE
lee desde IFILE en lugar de stdin. Si IFILE es '-', lee desde stdin. Comienza a leer al principio de IFILE a menos que se proporcione SKIP.
iflag=FLAGS
donde FLAGS es una lista separada por comas de una o más banderas descritas a continuación. Estas banderas están asociadas con IFILE y se ignoran cuando IFILE es stdin.
obs=BS
si se proporciona, debe ser el mismo que BS dado a la opción 'bs='.
of=OFILE
escribe en OFILE en lugar de stdout. Si OFILE es '-', escribe en stdout. Si OFILE es /dev/null, no se realizan escrituras reales. Si OFILE es '.', se trata de la misma manera que /dev/null (esta es una notación abreviada). Si OFILE existe, **no** se trunca; se sobrescribe desde el principio de OFILE a menos que se proporcione 'oflag=append' o SEEK.
oflag=FLAGS
donde FLAGS es una lista separada por comas de una o más banderas descritas a continuación. Estas banderas están asociadas con OFILE y se ignoran cuando OFILE es /dev/null, '.' (punto), o stdout.
seek=SEEK
comienza a escribir SEEK bloques del tamaño de bs desde el principio de OFILE. El valor predeterminado es el bloque 0 (es decir, el principio del archivo).
skip=SKIP
comienza a leer SKIP bloques del tamaño de bs desde el principio de IFILE. El valor predeterminado es el bloque 0 (es decir, el principio del archivo).
sync=0 | 1
cuando es 1, realiza el comando SYNCHRONIZE CACHE en OFILE al final de la transferencia. Solo está activo cuando OFILE es un nombre de archivo de dispositivo sg.
time=0 | 1
cuando es 1, mide el tiempo de transferencia y calcula el rendimiento, mostrando los resultados (en stderr) al finalizar. Cuando es 0 (predeterminado), no realiza mediciones de tiempo.
verbose=VERB
a medida que VERB aumenta, también lo hace la cantidad de salida de depuración enviada a stderr. El valor predeterminado es cero, lo que produce la mínima cantidad de salida de depuración. Un valor de 1 informa información adicional que no es repetitiva. Un valor de 2 informa cdbs y respuestas para comandos SCSI que no son repetitivos (es decir, distintos de READ y WRITE). El procesamiento de errores no se considera repetitivo. Los valores 3 y 4 producen salida para todos los comandos SCSI (y llamadas Unix read() y write()), por lo que puede haber mucha salida.
-d, --dry-run
realiza todo el análisis y preparación de la línea de comandos, pero omite la copia o lectura real. Esa preparación puede incluir la apertura de IFILE u OFILE para determinar sus longitudes. Esta opción puede ser útil para probar la sintaxis de invocaciones complejas de línea de comandos antes de ejecutarlas.
-h, --help
muestra el mensaje de uso y sale.
-p, --progress
esta opción hace que se muestre un informe de progreso cada dos minutos hasta que se complete la copia. Después de que la copia se complete, se imprime una línea con "completed" para distinguir el informe final de los informes de progreso anteriores. Cuando se usa dos veces, el informe de progreso es cada minuto, cuando se usa tres veces, el informe de progreso es cada 30 segundos.
Si se proporciona esta opción, la opción 'time=1' se establece implícitamente.
-v, --verbose
cuando se usa una vez, es equivalente a verbose=1. Cuando se usa dos veces (por ejemplo, "-vv"), es equivalente a verbose=2, etc.
-V, --version
muestra la información del número de versión y sale.

sgm_dd(8) — sg3_utils-1.48

NAME

sgm_dd

copy files using SCSI commands

SYNOPSIS

sgm_dd [if=IFILE] [of=OFILE] [bs=BS] [count=COUNT] [skip=SKIP] [seek=SEEK] [conv=CONV] [status=STATUS] [oflag=OFLAG] [iflag=IFLAG] [dpo=DPO] [dsync=DSYNC] [fua=FUA] [dio=DIO] [direct=DIRECT] [excl=EXCL] [sync=SYNC] [help] [version]

DESCRIPTION

The sgm_dd utility performs file copies like dd(1) but uses SCSI commands for the data transfer. This utility is mainly intended for use with SCSI block devices (e.g. disks), but can also be used with normal files and Unix character devices (like /dev/null).

The options are grouped into standard dd options and device-specific flags. Device-specific flags are grouped as iflag=... or oflag=... options.

The sgm_dd utility issues SCSI READ and WRITE (SBC) commands, which are suitable for disks and optical drives. It is not suitable for tape devices.

OPTIONS

Many options have the same meaning as their dd(1) counterparts:

if=IFILE
Input file. Defaults to stdin.
of=OFILE
Output file. Defaults to stdout.
bs=BS
Block size. Defaults to 512 bytes.
count=COUNT
Number of blocks to copy. Defaults to copy until EOF on the input.
skip=SKIP
Skip number of blocks at the start of the input.
seek=SEEK
Skip number of blocks at the start of the output.
conv=CONV
Conversion options. Only conv=notrunc is supported. See dd(1) for others.
status=STATUS
Controls the level of detail in reporting. Supported values are none, noxfer, and full (default).
help
Print usage message and exit.
version
Print version string and exit.

FLAGS

These flags are mainly used with SCSI devices. They can be given with the iflag= or oflag= options. For example: iflag=direct,dsync.

append
causes the O_APPEND flag to be added to the open of OFILE. For normal files this will lead to data appended to the end of any existing data. Cannot be used together with the seek=SEEK option as they conflict. The default action of this utility is to overwrite any existing data from the beginning of the file or, if SEEK is given, starting at block SEEK. Note that attempting to 'append' to a device file (e.g. a disk) will usually be ignored or may cause an error to be reported.
dio
is only active with oflag (i.e. 'oflag=dio'). Its action is described in the 'dio=1' option description above.
direct
causes the O_DIRECT flag to be added to the open of IFILE and/or OFILE. This flag requires some memory alignment on IO. Hence user memory buffers are aligned to the page size. Has no effect on sg, normal or raw files.
dpo
set the DPO bit (disable page out) in SCSI READ and WRITE commands. Not supported for 6 byte cdb variants of READ and WRITE. Indicates that data is unlikely to be required to stay in device (e.g. disk) cache. May speed media copy and/or cause a media copy to have less impact on other device users.
dsync
causes the O_SYNC flag to be added to the open of IFILE and/or OFILE. The "d" is prepended to lower confusion with the 'sync=0|1' option which has another action (i.e. a synchronisation to media at the end of the transfer).
excl
causes the O_EXCL flag to be added to the open of IFILE and/or OFILE.
fua
causes the FUA (force unit access) bit to be set in SCSI READ and/or WRITE commands. This only has effect with sg devices. The 6 byte variants of the SCSI READ and WRITE commands do not support the FUA bit. Only active for sg device file names.
null
has no affect, just a placeholder.

RETIRED OPTIONS

Here are some retired options that are still present:

fua=0 | 1 | 2 | 3
force unit access bit. When 3, fua is set on both IFILE and OFILE; when 2, fua is set on IFILE; when 1, fua is set on OFILE; when 0 (default), fua is cleared on both. See the 'fua' flag.

NOTES

A raw device must be bound to a block device prior to using sgm_dd. See raw(8) for more information about binding raw devices. To be safe, the sg device mapping to SCSI block devices should be checked with the lsscsi utility before use.

Raw device partition information can often be found with fdisk(8) [the "-ul" argument is useful in this respect].

Various numeric arguments (e.g. SKIP) may include multiplicative suffixes or be given in hexadecimal. See the "NUMERIC ARGUMENTS" section in the sg3_utils(8) man page.

The count, skip and seek parameters can take 64 bit values (i.e. very big numbers). Other values are limited to what can fit in a signed 32 bit number.

Data usually gets to the user space in a 2 stage process: first the SCSI adapter DMAs into kernel buffers and then the sg driver copies this data into user memory (write operations reverse this sequence). With memory mapped transfers a kernel buffer reserved by sg is memory mapped (see the mmap(2) system call) into the user space. When this is done the second (redundant) copy from kernel buffers to user space is not needed. Hence the transfer is faster and requires less "grunt" from the CPU.

All informative, warning and error output is sent to stderr so that dd's output file can be stdout and remain unpolluted. If no options are given, then the usage message is output and nothing else happens.

For sg devices this utility issues SCSI READ and WRITE (SBC) commands which are appropriate for disks and reading from CD/DVD/BD drives. Those commands are not formatted correctly for tape devices so sgm_dd should not be used on tape devices.

This utility stops the copy if any error is encountered. For more advanced "copy on error" logic see the sg_dd utility (and its 'coe' flag).

EXAMPLES

See the examples given in the man page for sg_dd(8).

SIGNALS

The signal handling has been borrowed from dd: SIGINT, SIGQUIT and SIGPIPE output the number of remaining blocks to be transferred and the records in + out counts; then they have their default action. SIGUSR1 causes the same information to be output yet the copy continues. All output caused by signals is sent to stderr.

EXIT STATUS

The exit status of sgm_dd is 0 when it is successful. Otherwise see the sg3_utils(8) man page. Since this utility works at a higher level than individual commands, and there are 'coe' and 'retries' flags, individual SCSI command failures do not necessary cause the process to exit.
