NOMBRE

sg_comp_init, sg_comp_destroy, sg_comp_get_tls, sg_global_lock, sg_global_unlock - gestión de la entrega de estadísticas del sistema

SINOPSIS

#include "tools.h"


void *get_global_static
(unsigned int id);


sg_error sg_global_lock
(void);


sg_error sg_global_unlock
(void);

DESCRIPCIÓN

sg_comp_init() es llamada por sg_init() para ejecutar la inicialización del componente global y de cada componente de libstatgrab registrado. Este registro se realiza estáticamente añadiendo una estructura de información de inicialización de componentes (instancia de sg_comp_info) a la lista comp_info en src/libstatgrab/globals.c. La instancia de sg_comp_info se define normalmente utilizando uno de EASY_COMP_SETUP() o EXTENDED_COMP_SETUP(), respectivamente.

sg_comp_destroy() es llamada por sg_shutdown() para destruir todos los recursos globales, por ejemplo, tablas de traducción de nombres de dispositivos o expresiones regulares compiladas para hacer coincidir nombres de rutas, etc. Los recursos de estadísticas se gestionan en otro lugar y se liberan (conceptualmente y normalmente) antes de que se invoque sg_comp_destroy().

sg_comp_get_tls() es la función interna para acceder al almacenamiento local del hilo (anteriormente globales estáticos) del componente. Normalmente es más fácil depender de la macro envolvente GLOBAL_GET_TLS().

NOTAS

La entrega de estadísticas del sistema es el trabajo de libstatgrab, la gestión de la entrega es el trabajo del componente global. Para cumplir con este trabajo, los componentes a gestionar deben estar preparados:

1.
declarar la estructura de datos global y TLS del componente (probablemente solo en papel, no en código)
2.
definir las funciones de inicialización global, destrucción de hilos y destrucción de procesos (si son requeridas por 1.)
3.
definir la estructura de información del componente utilizando *_COMP_SETUP()
4.
definir los accesores del componente utilizando uno o más de

EASY_COMP_ACCESS()
EASY_COMP_DIFF()
MULTI_COMP_ACCESS()
MULTI_COMP_DIFF()

Una vez realizados estos pasos, nace un nuevo componente que entrega nuevas estadísticas y debe ser "anunciado". Suponiendo que el componente se llama cpu, añada la línea { &sg_cpu_init, 0 } a la lista comp_info mencionada anteriormente.

Información de inicialización de componentes en detalle:

typedef sg_error (*comp_global_init_function)(unsigned id);
typedef void (*comp_global_destroy_function)(void);
typedef void (*comp_global_cleanup_function)(void *);
struct sg_comp_status {
        sg_error init_error;
};
struct sg_comp_init {
        comp_global_init_function init_fn;
        comp_global_destroy_function destroy_fn;
        comp_global_cleanup_function cleanup_fn;
        size_t static_buf_size;
#if defined(ENABLE_THREADS) && defined(HAVE_PTHREAD)
        const char **required_locks;
#endif
        struct sg_comp_status *status;
};

Los componentes que no necesitan nada especial pueden confiar en EASY_COMP_SETUP():

Inicializando el componente de memoria

EASY_COMP_SETUP(mem,1,NULL);

Cuando se necesita inicialización propia, hacerlo es un poco más complejo:

Inicializando el componente de red

#define SG_NETWORK_IO_NOW_IDX	0
#define SG_NETWORK_IO_DIFF_IDX	1
#define SG_NETWORK_IFACE_IDX	2
#define SG_NETWORK_MAX_IDX	3
EXTENDED_COMP_SETUP(network,SG_NETWORK_MAX_IDX,NULL);
#ifdef LINUX
static regex_t network_io_rx;
#define RX_MATCH_COUNT (8+1)
#endif
sg_error
sg_network_init_comp(unsigned id) {
        GLOBAL_SET_ID(network,id);
#ifdef LINUX
        if( regcomp( &network_io_rx, ..., REG_EXTENDED)!=0) {
                return sg_set_error(SG_ERROR_PARSE, NULL);
        }
#endif
        return SG_ERROR_NONE;
}
void
sg_network_destroy_comp(void) {
#ifdef LINUX
        regfree(&network_io_rx);
#endif
}
EASY_COMP_CLEANUP_FN(network,SG_NETWORK_MAX_IDX)

EASY_COMP_SETUP() se encarga de todo lo necesario para instanciar una estructura de información de componente para el componente especificado comp. La estructura de almacenamiento TLS creada contendrá nvect elementos de puntero y eso es todo. Todas las rutinas de inicialización, destrucción y limpieza se crean según sea necesario utilizando EASY_COMP_INIT_FN(), EASY_COMP_DESTROY_FN() y EASY_COMP_CLEANUP_FN(). Después de la cantidad de punteros vectoriales requeridos a almacenar, se debe especificar la lista de mutex requeridos, terminada con un puntero NULL.

EXTENDED_COMP_SETUP() se encarga de todo lo necesario para instanciar una estructura de información de componente para el componente especificado comp, pero requiere la definición de las rutinas de inicialización, destrucción y limpieza. La estructura de almacenamiento TLS creada contendrá nvect elementos de puntero y eso es todo. Después de la cantidad de punteros vectoriales requeridos a almacenar, se debe especificar la lista de mutex requeridos, terminada con un puntero NULL. Todas las rutinas estándar se pueden crear semi-automáticamente utilizando EASY_COMP_INIT_FN(), EASY_COMP_DESTROY_FN() y EASY_COMP_CLEANUP_FN().

DEFAULT_INIT_COMP() simplemente declara los prototipos para las rutinas de inicialización, destrucción y limpieza, define el búfer de estado de inicialización, la lista de nombres de bloqueo y finalmente rellena la estructura de inicialización del componente. Úselo cuando su almacenamiento TLS contenga más que solo punteros vectoriales.

GLOBAL_GET_TLS() devuelve el puntero al *almacenamiento local del hilo* del componente.

GLOBAL_SET_ID() almacena el identificador del componente, requerido, por ejemplo, para acceder a su TLS.

EASY_COMP_INIT_FN() define una rutina de inicialización de componente predeterminada. Almacena el identificador del componente y devuelve SG_ERROR_NONE.

EASY_COMP_DESTROY_FN() define un destructor de componente predeterminado, llamado al final de todo el proceso (o cuando se llama al último sg_shutdown()). El destructor predeterminado no hace nada y normalmente una rutina de inicialización individual requiere un destructor individual, también.

EASY_COMP_CLEANUP_FN() define una rutina de limpieza TLS predeterminada, siempre llamada cuando un hilo finaliza para liberar vectores mantenidos en el *almacenamiento local del hilo*.

EASY_COMP_ACCESS() define los accesores para una estadística específica que contiene un elemento proporcionado por el componente: las funciones fn() y fn##_r(). La siguiente función debe existir:
sg_error fn##_int
(sg_vector *name##_vect);
Accede al índice del vector idx del TLS del componente comp y devuelve

sg_global_lock(3) - libstatgrab

NAME

sg_global_lock, MULTI_COMP_ACCESS, EASY_COMP_DIFF, MULTI_COMP_DIFF - component statistic access

SYNOPSIS

#include <statgrab.h>
sg_error
sg_global_lock(void);
sg_error
sg_global_unlock(void);
sg_error
MULTI_COMP_ACCESS(foo, Foo);
sg_error
EASY_COMP_DIFF(foo, Foo);
sg_error
MULTI_COMP_DIFF(foo, Foo);

DESCRIPTION

The functions described here are used by components in order to simplify the access to statistics.

sg_global_lock() and sg_global_unlock() are used to protect access to the global statistics.

MULTI_COMP_ACCESS() defines accessors to a specific statistic containing 0..n elements provided by the component: the functions fn() and the fn##_r(). The following function must exist:

sg_error fn##_int
    (sg_vector **name##_vect);

It accesses the vector idx from TLS of component comp and returns sg_##name##_stats. It manages all standard things like memory and error management, return value etc.

EASY_COMP_DIFF() returns the difference between the two statistic collection runs. The variant dealing with statgrab owned statistics return the difference between the content currently in the vector specified by nowidx and the resulting vector of getfn(). The result is stored in the vector diffidx. If there is no current result, simply the result of getfn() is returned.

MULTI_COMP_DIFF() does the same as EASY_COMP_DIFF() but for vectors with more than one element.

NOTES

These macros are intended for use by developers of components for libstatgrab. They should not be used directly by applications using libstatgrab.

The definitions of these macros rely on the availability of certain functions and variables within the component code.
