NOMBRE

sg_stream_ctl - enviar comando SCSI STREAM CONTROL o GET STREAM STATUS

SINOPSIS

sg_stream_ctl [--brief] [--close] [--ctl=CTL] [--get] [--help] [--id=SID] [--maxlen=LEN] [--open] [--readonly] [--verbose] [--version] DISPOSITIVO

DESCRIPCIÓN

Envía un comando SCSI STREAM CONTROL o GET STREAM STATUS al DISPOSITIVO. Estos comandos, junto con WRITE STREAM(16 y 32) y varios campos de la página VPD Block Limits Extension [0xb7] soportan el concepto de streams. Los comandos de stream se añadieron en SBC-4 draft 8 (septiembre de 2015).

Tanto los comandos STREAM CONTROL como GET STREAM STATUS esperan datos del DISPOSITIVO (denominado 'data-in'). En el caso de STREAM CONTROL, solo el 'open' (STR_CTL<--0x1) realmente necesita el data-in, ya que contiene el "Assigned stream id" si el open fue exitoso. El stream id asignado debe ser utilizado por los comandos WRITE STREAM subsiguientes y, en última instancia, por el close de STREAM CONTROL (STR_CTL<--0x2). Los stream ids válidos están entre 1 y 65535 inclusive.

OPCIONES

Los argumentos para las opciones largas son obligatorios para las opciones cortas también.

-b, --brief
esta opción reduce la salida del comando GET STREAM STATUS a solo un número (en decimal) por línea enviada a stdout. Esos números son los stream ids actualmente abiertos. Si ocurre un error, se envía -1 a stdout y los mensajes relacionados con el error se envían a stderr. El valor predeterminado es imprimir más palabras (y campos) de la respuesta de GET STREAM STATUS.
-c, --close
selecciona el comando STREAM CONTROL y establece STR_CTL<--0x2 (es decir, 'close'). La opción --id=SID también debe proporcionarse, ya que su valor predeterminado es 0, que no es un stream id válido.
-C, --ctl=CTL
CTL es el valor colocado en el campo STR_CTL del comando STREAM CONTROL (cdb). Es un campo de dos bits, por lo que tiene 4 variantes: 0 y 3 están reservados; 1 significa abrir un nuevo stream y 2 cerrar el stream id dado. '--ctl=1' es equivalente a '--open' mientras que '--ctl=2' es equivalente a '--close'.
-g, --get
selecciona el comando GET STREAM STATUS. Si la opción --id=SID también se proporciona, la respuesta comienza enumerando los stream ids abiertos a partir de SID (incluido). Si la opción --id=SID no se proporciona (o SID es 0), se devolverán todos los stream ids abiertos en la respuesta (data-in) siempre que la longitud de asignación (el valor predeterminado es 248 bytes, que puede ser anulado por la opción --maxlen=LEN) sea suficiente. Esta es la acción predeterminada de esta utilidad (es decir, comando GET STREAM STATUS) si no se proporcionan opciones de "selección".
-h, --help
muestra el mensaje de uso y luego sale.
-i, --id=SID
SID es un stream id, un valor entre 1 y 65535. Es utilizado por STREAM CONTROL (close) para identificar el stream a cerrar. Es utilizado por el comando GET STREAM STATUS como el stream id de inicio (a partir de, incluido); por lo tanto, los stream ids menores que SID no aparecerán en la respuesta.
-m, --maxlen=LEN
LEN es la longitud máxima que puede tener la respuesta. Se convierte en el campo ALLOCATION LENGTH en ambos comandos. El valor predeterminado (en ausencia de esta opción) es 8 bytes para STREAM CONTROL y 248 bytes para GET STREAM STATUS.
-o, --open
selecciona el comando STREAM CONTROL y establece STR_CTL<--0x1 (es decir, 'open'). Si se proporciona la opción --id=SID, se ignora. El usuario debe observar la respuesta, ya que el "Assigned stream id" se imprime en stdout si el open es exitoso; de lo contrario, se envía '-1' a stdout y los mensajes de error se envían a stderr. Si la opción --brief también se proporciona, lo único que se envía a stdout es un número del stream id asignado (de 1 a 65535 inclusive) o '-1' si hay un error.
-r, --readonly
esta opción establece un indicador 'solo lectura' cuando el sistema operativo subyacente abre el DISPOSITIVO dado. Esto puede no funcionar, ya que los sistemas operativos no pueden determinar fácilmente si un comando de paso es una operación lógica de lectura o escritura en el medio (o sus metadatos), por lo que adoptan una postura aversiva al riesgo y requieren permisos de tipo lectura-escritura en la apertura del DISPOSITIVO independientemente de lo que se realice mediante el paso.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración).
-V, --version
imprime la cadena de versión y luego sale.

NOTAS

No hay comandos de lectura especiales para los streams. Esto implica que se pueden usar las lecturas "normales" (6, 10, 12, 16 o 32). Tenga en cuenta que cuando un stream se cierra, todos los recursos asociados con ese stream id se eliminan, aparte de los datos en los LBAs escritos. Para asegurarse de que la lectura de datos no se retrase demasiado debido a la recuperación de errores (en presencia de errores de medios), el usuario puede establecer el campo RECOVERY TIME LIMIT (RTL, unidades para valores distintos de cero: milisegundos) en la página de modo 'Read-write error recovery'. Esto se puede hacer con la utilidad sdparm.

Los comandos SCSI WRITE STREAM (16 y 32) se encuentran en la utilidad sg_write_x de este paquete.

ESTADO DE SALIDA

El estado de salida de sg_stream_ctl es 0 cuando tiene éxito. De lo contrario, consulte la página del manual de sg3_utils(8).

sg_stream_ctl - control stream devices with SCSI INQUIRY and MODE SELECT

NAME

sg_stream_ctl - control stream devices with SCSI INQUIRY and MODE SELECT

SYNOPSIS

sg_stream_ctl
[SG_FLAGS] [OPTIONS] DEVICE

sg_stream_ctl [VERSION] [HELP]

DESCRIPTION

This utility sends SCSI MODE SELECT (10) or MODE SENSE (10) commands to the given DEVICE. It is intended for stream devices like tape drives.

By default it will perform a MODE SENSE (10) command to fetch the current mode page 0x1b (stream device mode page) and print it in hex. The page 0x1b is described in the SBC-2 standard and provides control over features like the write filemark command.

The SG_FLAGS and OPTIONS are generic sg3_utils options. The DEVICE is the SCSI generic device name, which on Linux is typically of the form /dev/sgX or /dev/stX.

OPTIONS

-a, --all
Fetch and print all mode pages. This is done using MODE SENSE (6) and is a more general way to inspect mode pages.
-b, --block_limits
Fetch and print the block limits mode page (0x5).
-c, --command=STR
Set a command. STR can be “auto” (default), “disable” or “enable”. When enabled, the command will be executed when the drive is accessed via the sg driver.
-e, --error_recovery
Fetch and print the error recovery mode page (0x1).
-f, --fmt_blk_desc
Fetch and print the format mode page (0x3).
-h, --help
Display usage information and exit.
-i, --immutable
Fetch and print the immutable mode page (0x11).
-l, --logical_unit
Fetch and print the logical unit mode page (0x1f).
-m, --medium_changer
Fetch and print the medium changer mode page (0x12).
-n, --notify=STR
Set the notification option. STR can be “auto” (default), “disable”, or “enable”. When enabled, the drive will notify the host when the medium is changed.
-o, -- கட்டுப்பாط
Fetch and print the control mode page (0x0a).
-p, --page=NUM
Specify the mode page number to fetch. Defaults to 0x1b (stream device mode page).
-r, --read_write_error_recovery
Fetch and print the read-write error recovery mode page (0x1).
-s, --set
Set mode page(s). This is done using MODE SELECT (10). Only one page can be set at a time.
-t, --tape_driver_options
Fetch and print the tape driver options mode page (0x1b).
-v, --verbose
Increase the verbosity of the output.
-w, --write=STR
Set the write control mode page (0x1a). STR can be “normal”, “write_and_verify”, or “verify”.
-x, --hex
Output the mode page in hexadecimal.
-y, --immutable_protected
Fetch and print the immutable protected mode page (0x17).
--version
Print version string and exit.

EXAMPLE

To fetch and print the default stream device mode page (0x1b) for the device /dev/sg0:

sg_stream_ctl /dev/sg0

To set the write control to “write and verify” for the device /dev/sg1:

sg_stream_ctl --set --write=write_and_verify /dev/sg1
