NOMBRE

sg_vpd - obtener página VPD SCSI y/o decodificar su respuesta

SINOPSIS

sg_vpd [--all] [--enumerate] [--examine] [--force] [--help] [--hex] [--ident] [--inhex=FN] [--json[=JO]] [--js-file=JFN] [--long] [--maxlen=LEN] [--page=PG] [--quiet] [--raw] [--sinq_inraw=RFN] [--vendor=VP] [--verbose] [--version] [DISPOSITIVO]

DESCRIPCIÓN

Esta utilidad, cuando se le proporciona un DISPOSITIVO, obtiene una página de Datos de Producto Vital (VPD) y la decodifica o la muestra en hexadecimal ASCII o binario. Las páginas VPD se obtienen con un comando SCSI INQUIRY.

Alternativamente, se puede usar la opción --inhex=FN. En este caso, se asume que FN es un nombre de archivo ('-' para stdin) que contiene hexadecimal ASCII que representa una respuesta de página VPD. Si también se usa la opción --raw, se asume entrada binaria (en lugar de hexadecimal ASCII).

Probablemente la página más importante es la página VPD de Identificación de Dispositivo (número de página: 0x83). Desde SPC-3, el soporte para esta página se ha marcado como obligatorio. Esta página se puede obtener usando la opción --ident.

El documento de referencia utilizado para interpretar las páginas VPD (y la respuesta estándar INQUIRY) es T10/BSR INCITS 566 Revisión 6, que es un borrador de SPC-6 con fecha del 22 de octubre de 2021. Se puede encontrar en https://www.t10.org.

Cuando no se proporcionan opciones, aparte de un DISPOSITIVO, se obtiene y decodifica la página VPD "Páginas VPD soportadas" (0x0).

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas. Las opciones están ordenadas alfabéticamente según el nombre de la opción larga.

-a, --all
decodificar todas las páginas VPD. Cuando se usa con DISPOSITIVO, las páginas a decodificar se encuentran en la página VPD "Páginas VPD soportadas". Las páginas que no se pueden decodificar se muestran en hexadecimal; agregue la opción --long para mostrar texto ASCII a la derecha de cada línea hexadecimal.
Si esta opción se usa con la opción --inhex=FN, se asume que el archivo FN contiene 1 o más páginas VPD (en hexadecimal ASCII o binario). La decodificación continúa hasta que el archivo se agota (o ocurre un error). Se aplican verificaciones de cordura sobre la longitud de cada página VPD y el orden ascendente de los números de página VPD (requerido por SPC-4), por lo que se pueden detectar datos erróneos.
Si la opción --page=PG también se proporciona, no se decodificará ninguna página VPD cuyo número de página sea mayor que PG (o su equivalente numérico).
-e, --enumerate
listar los nombres de las páginas VPD conocidas, primero las páginas estándar (es decir, las definidas por T10), luego las páginas específicas del proveedor. Cada grupo se ordena por orden de abreviatura. El DISPOSITIVO y la mayoría de las otras opciones se ignoran y esta utilidad sale después de listar los nombres de las páginas VPD. Puede usarse junto con --page=PG, donde PG es numérico. Si es así, busca las líneas de resumen de todas las páginas VPD cuyo número coincide con PG. Puede usarse con --vendor=VP para restringir la salida a páginas específicas conocidas del proveedor para el proveedor/producto VP.
-E, --examine
escanear parte o todo el espacio VPD (números de página 0x0 a 0xff) y mostrar cualquier página encontrada. Si esta opción se proporciona una vez, el escaneo comienza en la página 0x80; si se proporciona dos veces, el escaneo comienza en 0x0; y si se proporciona tres veces, el escaneo comienza en 0xc0. Esta opción no tiene en cuenta el contenido de la página VPD 0x0, que debería contener una lista de todas las páginas VPD soportadas. Algunos proveedores olvidan enumerar algunas páginas estándar o, quizás, no enumeran a propósito páginas específicas del proveedor que se encuentran en el rango de 0xc0 a 0xff.
Si no se proporciona la opción --page=PG, el escaneo finaliza en la página 0xff. Si se proporciona la opción --page=PG, el escaneo finaliza en la página PG. Se realiza una verificación antes del escaneo para asegurarse de que la página de inicio sea menor o igual que la página de finalización; de lo contrario, los números de página de inicio y finalización se intercambian.
La utilidad sdparm, que lista las páginas de modo y VPD, también tiene una opción --examine con funcionalidad similar. Tenga en cuenta que T10 ha cambiado la mayoría de las páginas que listan las páginas soportadas (por ejemplo, páginas VPD, de modo y de registro; comandos soportados) para agregar las palabras cautelosas "puede o no listar todas...".
-f, --force
como verificación de cordura, la acción normal al obtener páginas VPD distintas de la página 0x0 (la página VPD "Páginas VPD soportadas"), es primero obtener la página 0x0 y solo si la página solicitada es una de las páginas soportadas, proceder a obtener la página solicitada.
Cuando se proporciona esta opción, omite la verificación de la página VPD 0x0 antes de acceder a la página VPD solicitada. La verificación previa de la página VPD 0x0 se sabe que bloquea ciertos dispositivos USB, así que úsela con cuidado.
-h, --help
muestra el mensaje de uso resumiendo las opciones de la línea de comandos y luego sale. Ignora DISPOSITIVO si se proporciona.
-H, --hex
muestra la página VPD solicitada en hexadecimal ASCII. Se puede usar múltiples veces, ver sección sobre la página de información VPD ATA.
Para generar una salida adecuada para colocar en un archivo que pueda ser utilizado por una invocación posterior con la opción --inhex=FN, use la opción '-HHHH' (por ejemplo, 'sg_vpd -p di -HHHH /dev/sg3 > dev_id.hex'). La razón por la que se usa '-HHHH' es para indicar que se envía hexadecimal sin adornos (sin otro texto ni desplazamientos de dirección) a la salida estándar.
-i, --ident
decodifica la página VPD de identificación de dispositivo (0x83). Cuando se usa una vez, esta opción tiene el mismo efecto que '--page=di'. Cuando se usa dos veces, se decodifica la forma corta del descriptor de unidad lógica de la página VPD de identificación de dispositivo. En este último caso, esta opción tiene el mismo efecto que '--quiet --page=di_lu'.
-I, --inhex=FN
FN se espera que sea un nombre de archivo (o '-' para stdin) que contiene hexadecimal ASCII o binario que representa una respuesta de página VPD (o INQUIRY estándar). Esta utilidad decodificará esa respuesta. Es preferible proporcionar también la opción --page=PG, de lo contrario esta utilidad intentará adivinar con qué página VPD (o INQUIRY estándar) está asociada la respuesta. El hexadecimal debe estar organizado como 1 o 2 dígitos que representan un byte, cada uno de ellos separado por espacios en blanco o comas. Se ignora todo desde un símbolo de almohadilla hasta el final de la línea, incluido el propio símbolo. Si la opción --raw también se proporciona, FN se trata como binario.
-j[=JO], --json[=JO]
la salida está en formato JSON en lugar de texto plano. Tenga en cuenta que los argumentos para la forma corta y larga son opcionales y, si están presentes, comienzan con "=" y no se permiten espacios en blanco alrededor de ese "=".
Consulte la página del manual de sg3_utils_json o use '?' para JO para obtener un resumen.
-J, --js-file=JFN
la salida está en formato JSON y se envía a un archivo llamado JFN. Si ese archivo existe, se trunca. Por defecto, la salida JSON se envía a stdout.
Cuando se proporciona esta opción, se implica la opción --json[=JO] y no es necesario proporcionarla. La opción --json[=JO] aún puede ser necesaria para establecer el parámetro JO a valores no predeterminados.
-l, --long
al decodificar algunas páginas VPD, proporciona un poco más de salida. Por ejemplo, la página de información VPD ATA solo muestra la firma (en hexadecimal) y la IDENTIFY (PACKET) DEVICE (en hexadecimal) cuando se proporciona esta opción.
-m, --maxlen=LEN
donde LEN es la longitud máxima de respuesta en bytes. Se coloca en el campo "longitud de asignación" del cdb. Si no se proporciona (o LEN es cero), se usa 252 (aparte de la página de información VPD ATA que por defecto es 572) y, si la respuesta indica que este valor es insuficiente, se envía otro comando INQUIRY con un valor mayor en el campo "longitud de asignación" del cdb. Si se proporciona esta opción y LEN es mayor que 0, solo se envía un comando INQUIRY. Dado que muchos dispositivos simples implementan el comando INQUIRY de manera deficiente (y no soportan páginas VPD), el valor más seguro.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

OPTIONS

-p, --page=PG
donde PG es la página VPD a decodificar o mostrar. El argumento PG puede ser una abreviatura, un número o un par de números/abreviaturas separadas por una coma. Las abreviaturas de las páginas VPD se pueden ver usando la opción --enumerate. Si se proporciona un número, se asume que es decimal a menos que tenga un indicador hexadecimal, que es '0x' al principio o 'h' al final. Si se proporciona un número, se asume que es un número de página VPD. Si se proporcionan dos números (o abreviaturas), el segundo es el mismo que VP (ver la opción --vendor=VP). Si no se proporciona esta opción (ni '-i', '-l' ni '-V'), se recupera y decodifica la página VPD "Supported VPD pages" (0x0). Si PG es '-1' o 'sinq', se muestra la respuesta INQUIRY estándar. Esta opción también se puede usar con la opción --enumerate (ver su descripción).
Si PG no se encuentra en la página VPD 'Supported VPD pages' (0x0), se devuelve EDOM. Para omitir esta verificación, use la opción --force.
-q, --quiet
suprime la cantidad de decodificación y salida de errores.
-r, --raw
si no se usa con --inhex=FN, muestra la página VPD solicitada en binario. La salida debe enviarse a un archivo o a otra utilidad cuando se usa esta opción. El binario se envía a stdout y los errores a stderr.
si se usa con --inhex=FN, el contenido de FN se trata como binario.
-Q, --sinq_inraw=RFN
donde RFN es un nombre de archivo que contiene datos binarios de la respuesta INQUIRY estándar que coinciden con DEVICE o FN. Linux coloca esta respuesta INQUIRY estándar en su sistema de archivos pseudo sysfs. Una ubicación típica es /sys/class/scsi_device/<hctl>/device/inquiry, donde <hctl> es una tupla numérica de cuatro partes separada por dos puntos. Esta tupla distingue el dispositivo de otros en el sistema. Linux también coloca algunas respuestas de páginas VPD en binario en el mismo directorio con nombres como "vpd_pg83", donde los dos últimos dígitos forman el número de página VPD hexadecimal cuyo contenido binario se encuentra allí.
Algunas páginas VPD (por ejemplo, la página VPD de consulta extendida) dependen de conocer la configuración de la respuesta INQUIRY estándar para interpretar los campos de esa página VPD. Esta opción, junto con --all, --examine o --page=PG, permite que esta utilidad procese tanto la respuesta INQUIRY estándar como las páginas VPD en la misma invocación.
La opción --raw no tiene efecto sobre esta opción. El argumento DEVICE se puede proporcionar con esta opción.
-M, --vendor=VP
donde VP es un acrónimo de proveedor (por ejemplo, "sea" para Seagate) o proveedor/producto (por ejemplo, "hp3par" para la matriz 3PAR de HP). Muchos proveedores han reutilizado los números al principio del rango de páginas VPD específicas del proveedor (por ejemplo, página 0xc0) y esta opción es una forma de seleccionar solo aquellas que son de interés. Usar un VP de "xxx" mostrará los acrónimos disponibles.
Si esta opción se usa con --page=PG y PG es un acrónimo, esta opción se ignora. Si PG es un número (por ejemplo, 0xc0), VP se usa para elegir la página específica del proveedor (por ejemplo, compartiendo el número de página 0xc0) a decodificar.
-v, --verbose
aumenta el nivel de verbosidad.
-V, --version
muestra la cadena de versión y sale.

PÁGINA VPD DE INFORMACIÓN ATA

Esta página VPD (0x89 o 'ai') está definida por el estándar SCSI a ATA Translation. Contiene información sobre la capa SAT, la "firma" del dispositivo ATA y la respuesta al comando ATA IDENTIFY (PACKET) DEVICE. La última parte tiene 512 bytes de datos de identidad, capacidad y configuración que la utilidad hdparm es capaz de decodificar (por lo que esta utilidad no los decodifica).

Para simplificar la salida de esta página, la firma y la respuesta IDENTIFY (PACKET) DEVICE no se muestran a menos que se proporcionen las opciones --long (o --hex o --raw). Cuando se proporciona la opción --long, la respuesta IDENTIFY (PACKET) DEVICE se muestra como 256 palabras (de 16 bits), como es costumbre para los dispositivos ATA. Para ver esa respuesta como una cadena de bytes, use la opción '-HH'. Para formatear la salida adecuada para que hdparm la decodifique, use la opción '-HHH' o '-rr'. Por ejemplo, si 'dev/sdb' es un disco SATA detrás de una capa SAT, entonces este comando: 'sg_vpd -p ai -HHH /dev/sdb | hdparm --Istdin' debería decodificar la respuesta ATA IDENTIFY (PACKET) DEVICE.

NOTAS

Dado que algunas páginas VPD (por ejemplo, la página de consulta extendida) dependen de la configuración de la respuesta INQUIRY estándar, la respuesta INQUIRY estándar se muestra como una página VPD pseudo cuando PG se establece en '-1' o 'sinq'. Además, la decodificación de algunos campos (por ejemplo, el campo SPT de la página de consulta extendida) se expande cuando se proporciona la opción '--long', utilizando la información de la respuesta INQUIRY estándar (por ejemplo, los campos PDT y PROTECT).

El DEVICE se abre con un indicador de solo lectura (por ejemplo, en Unix con el indicador O_RDONLY).

ESTADO DE SALIDA

El estado de salida de sg_vpd es 0 cuando tiene éxito. De lo contrario, consulte la página del manual sg3_utils(8).

EJEMPLOS

Los ejemplos en esta página usan nombres de dispositivos de Linux. Para nombres de dispositivos adecuados en otros sistemas operativos compatibles, consulte la página del manual sg3_utils(8).

Para ver las páginas VPD que admite un dispositivo, úselo sin opciones. La invocación de la línea de comandos se muestra primero seguida de una respuesta típica:


# sg_vpd /dev/sdb
Página VPD de páginas VPD compatibles:
Páginas VPD compatibles [sv]
Número de serie de la unidad [sn]
Identificación del dispositivo [di]
Datos de consulta extendida [ei]
Límites de bloque (SBC) [bl]

Para ver los números de página VPD asociados con cada página admitida, agregue la opción '--long' a la línea de comandos anterior. Para ver una página VPD, se puede proporcionar su número o abreviatura a la opción '--page='. Las abreviaturas de los nombres de página se muestran entre corchetes arriba. En el siguiente ejemplo, se lista la página VPD de datos de consulta extendida:


# sg_vpd --page=ei /dev/sdb
Página VPD de datos de consulta extendida:
ACTIVATE_MICROCODE=0 SPT=0 GRD_CHK=0 APP_CHK=0 REF_CHK=0
UASK_SUP=0 GROUP_SUP=0 PRIOR_SUP=0 HEADSUP=1 ORDSUP=1 SIMPSUP=1
WU_SUP=0 CRD_SUP=0 NV_SUP=0 V_SUP=0
P_I_I_SUP=0 LUICLR=0 R_SUP=0 CBCS=0
Descarga de microcódigo de múltiples I_T nexus=0
Minutos de finalización de autoprueba extendida=0
POA_SUP=0 HRA_SUP=0 VSA_SUP=0

Para verificar si un disco admite algún tipo de protección, use la opción '--long' en la página VPD de consulta extendida:


# sg_vpd --page=ei --long /dev/sdb
Página VPD de datos de consulta extendida:
ACTIVATE_MICROCODE=0
SPT=1 [tipos de protección 1 y 2 compatibles]
GRD_CHK=1
....

Busca el nombre (y acrónimo) de todas las páginas que comparten el número de página VPD 0xb0.


# sg_vpd --page=0xb0 --enumerate
Páginas VPD estándar coincidentes:
bl 0xb0 Límites de bloque (SBC)
oi 0xb0 Información OSD
sad 0xb0 Capacidades del dispositivo de acceso secuencial (SSC)

A continuación se muestran algunos ejemplos que utilizan la opción "--all". Envía una representación hexadecimal ASCII de todas las páginas VPD a un archivo:


# sg_vpd --all -HHHH /dev/sg3 > all_vpds.hex

Más tarde, ese archivo podría decodificarse con:


# sg_vpd --all --inhex=all_vpds.hex

Para hacer lo mismo que el ejemplo anterior pero usando un archivo que contiene binario:


# sg_vpd --all --raw /dev/sg3 > all_vpds.bin
# sg_vpd --all --raw --inhex=all_vpds.bin

Tenga en cuenta que "--raw" debe proporcionarse con la segunda invocación (--inhex) para alertar a la utilidad de que all_vpds.bin contiene binario, ya que asume hexadecimal ASCII por defecto. A continuación, solo decodificamos las páginas VPD especificadas por T10, excluyendo las páginas VPD específicas del proveedor que comienzan en el número de página 0xc0:


# sg_vpd --all --page=0xbf --raw --inhex=all_vpds.bin

En Linux, las imágenes binarias de algunas respuestas importantes de páginas VPD (por ejemplo, 0, 80h y 83h) se almacenan en caché en archivos dentro del sistema de archivos pseudo sysfs. Dado que las páginas VPD rara vez cambian su contenido, decodificar esos archivos dará la misma salida que sondear el dispositivo, con el beneficio adicional de que decodificar esos archivos no requiere permisos de root. Se muestran las formas larga y corta:


sg_vpd --raw --inhex=/sys/class/scsi_generic/sg3/device/vpd_pg83


sg_vpd -rI /sys/class/scsi_generic/sg3/device/vpd_pg83

Si /dev/sg3 es un disco en 2:0:0:0, esta invocación debería dar una salida más detallada pero esencialmente la misma que los dos ejemplos anteriores.


sg_vpd -v -r -I /sys/class/scsi_disk/2:0:0:0/device/vpd_pg83

Se pueden encontrar más ejemplos en la página web https://sg.danny.cz/sg/sg3_utils.html.

NAME

sg_vpd - fetch and interpret Vital Product Data (VPD) pages from a SCSI device

SYNOPSIS

sg_vpd [-E] [-h] [-m] [-N] [-p<type>] [-v] [-B<hex>] [-H<hex>] [-I<hex>] [-O<hex>] [-S<hex>] [-d<dev>] [-x] [-n] [-c] [-t] [-C] [-V] [-?] <device>

DESCRIPTION

This utility fetches one or more Vital Product Data (VPD) pages from the given SCSI device and either prints them in ASCII hexadecimal representation or attempts to interpret and print them in a more human-readable format.

VPD pages are standard SCSI structures that contain information about the device's identity, configuration, and capabilities. They are accessed via the INQUIRY CDB (Command Descriptor Block).

OPTIONS

-E, --ata-info
Interpret the ATA Information VPD page (page code 0xB0). This option is a shorthand for -p B0 followed by -I B0. It displays ATA device information in a human-readable format.
-h, --help
Print usage information and exit.
-m, --enumerate
List the VPD page identifiers (page codes) supported by the device. This is done by sending an INQUIRY CDB with the EVPD (Enable Vital Product Data) parameter set, but the page code set to 0. The device should respond with a list of supported page codes.
-N, --no-vendor-page-interpret
Do not attempt to interpret vendor-specific VPD pages. Usually, if a vendor-specific page (page code between 0xC0 and 0xFF) is requested, sg_vpd will try to provide some interpretation if it knows how. This option disables that behavior.
-p<type>, --page=<type>
Specify the VPD page to request. <type> can be a standard page code (e.g., 00 for Version Descriptors, 83 for Device Serial Number, B1 for Extended Inquiry Data) or a vendor-specific page code (e.g., C0).
If this option is not given, sg_vpd will fetch and print all supported VPD pages (equivalent to using -m first and then requesting each page).
-v, --verbose
Increase the level of verbosity. Can be used multiple times.
-B<hex>, --block-device-info=<hex>
Interpret the Block Device Characteristics VPD page (page code 0xB1). <hex> should be the page code, typically B1.
-H<hex>, --history-inquiry=<hex>
Interpret the History Inquiry VPD page (page code 0x03). <hex> should be the page code, typically 03.
-I<hex>, --ident-device-info=<hex>
Interpret the Device Identification VPD page (page code 0x83). <hex> should be the page code, typically 83.
-O<hex>, --obsolete-inquiry=<hex>
Interpret the Obsolete VPD page (page code 0x00). <hex> should be the page code, typically 00.
-S<hex>, --scsi-serial-number=<hex>
Interpret the SCSI Device Serial Number VPD page (page code 0x80). <hex> should be the page code, typically 80.
-d<dev>, --device=<dev>
Use the SCSI device named <dev> (e.g., /dev/sg0, /dev/sdc). If not specified, the device name is taken from the command line argument without any options.
-x, --hex
Print the VPD page contents in hexadecimal ASCII format. This is the default behavior if no interpretation option (like -E, -I, etc.) is given.
-n, --no-bytes
Do not print the byte counts for each line of hex output. This option is only effective when -x is used.
-c, --cdb-scan
Scan the device for supported VPD pages by sending CDBs with page codes from 0x00 to 0xFF. This is slower than using -m but can be more thorough if the device does not correctly implement the EVPD=0 INQUIRY command.
-t, --transport-id
Interpret the Transport Identifier VPD page (page code 0x84).
-C, --code-set
Interpret the Designator Code Set VPD page (page code 0x89).
-V, --vendor-specific
Interpret the Vendor Specific VPD page (page code 0x01).
-?, --usage
Print usage information and exit.

ATA INFORMATION VPD PAGE

The ATA Information VPD page (page code 0xB0) is a standard way for SCSI translators (like SATL) to expose ATA Identify Device data to the host system. When the -E or --ata-info option is used, sg_vpd attempts to parse and display this data in a human-readable format. It requires the page code B0.

Common fields displayed include:

  • Serial Number
  • Firmware Revision
  • Model Number
  • Capabilities (e.g., LBA, DMA)
  • SATA features
  • ATA commands supported
  • SMART status

Note that the interpretation is based on the ATA Identify Device structure. The exact fields and their meaning can vary slightly depending on the ATA device.

NOTES

VPD pages are requested using the SCSI INQUIRY command with the EVPD bit set. The page code determines which specific VPD page is retrieved.

If no specific page is requested (e.g., no -p or other page interpretation option), sg_vpd will first try to list all supported pages using EVPD=0, and then fetch and print each of them.

Some interpretation routines might be vendor-specific or may only work correctly for certain types of devices.

EXIT STATUS

The exit status is 0 on success, and non-zero otherwise. Possible error conditions include:

  • Incorrect usage
  • Failure to open or communicate with the device
  • Device not a SCSI device
  • INQUIRY command failed
  • Requested VPD page not supported

EXAMPLES

List all supported VPD pages on /dev/sg0:

sg_vpd -m /dev/sg0

Fetch and print the Device Serial Number VPD page (0x80) on /dev/sda:

sg_vpd -p 80 /dev/sda

Fetch and print the Extended Inquiry Data VPD page (0x83) on /dev/sdb, attempting to interpret it:

sg_vpd -I 83 /dev/sdb

Fetch and print the ATA Information VPD page (0xB0) on /dev/sdc, interpreting it:

sg_vpd -E /dev/sdc

Fetch and print all supported VPD pages on /dev/sg1 in hex format:

sg_vpd /dev/sg1

Fetch and print the Vendor Specific VPD page (0xC1) on /dev/st0:

sg_vpd -p C1 /dev/st0
