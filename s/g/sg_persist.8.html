NOMBRE

sg_persist - utiliza el comando SCSI PERSISTENT RESERVE para acceder a registros y reservas

SINOPSIS

sg_persist [OPCIONES] DISPOSITIVO

sg_persist [OPCIONES] --device=DISPOSITIVO

sg_persist --ayuda | --version

DESCRIPCIÓN

Esta utilidad permite consultar y modificar Reservas y Registros Persistentes. Las reservas y registros persistentes se consultan mediante sub-comandos (llamados "acciones de servicio" en SPC-4) del comando SCSI PERSISTENT RESERVE IN (PRIN). Las reservas y registros persistentes se modifican mediante sub-comandos del comando SCSI PERSISTENT RESERVE OUT (PROUT).

Existe un proceso de dos etapas para obtener una reserva persistente. Primero, una aplicación (un nexo I_T en la jerga del estándar) debe registrar una clave de reserva. Si eso se acepta (y debería ser así a menos que otro nexo I_T tenga registrada esa clave), entonces la aplicación puede intentar reservar el dispositivo. La operación de reserva debe especificar la clave de reserva y un "tipo" (ver la opción --prout-type=TIPO).

Es relativamente seguro consultar el estado de las reservas y registros persistentes. Sin opciones, esta utilidad recurre por defecto al sub-comando READ KEYS del comando PRIN. Otros sub-comandos de PRIN son READ RESERVATION, REPORT CAPABILITIES y READ FULL STATUS.

Antes de intentar modificar las reservas y registros persistentes, los usuarios deben ser conscientes de lo que están haciendo. Las secciones relevantes del documento SCSI Primary Commands (es decir, SPC-5 ANSI INCITS 502-2020) son las secciones 8.14 (titulada "Reservations"), 9.16 (para el comando PRIN) y 9.17 (para el comando PROUT). Para protegerse contra el uso accidental, se debe proporcionar la opción --out cuando se utiliza un sub-comando PROUT (por ejemplo, --register).

Los comandos SCSI más antiguos RESERVE y RELEASE (variantes de 6 y 10 bytes) no son compatibles con esta utilidad. En SPC-3, RESERVE y RELEASE están obsoletos, reemplazados por Reservas Persistentes. RESERVE y RELEASE se han eliminado de SPC-4 y se proporciona el Anexo B que muestra cómo convertirse a comandos de reserva persistente. Consulte una utilidad llamada 'scsires' para obtener soporte para los comandos SCSI RESERVE y RELEASE.

DISPOSITIVO debe especificarse para todas las variantes de esta utilidad, excepto para --ayuda y --version. El DISPOSITIVO puede proporcionarse como un argumento (típicamente, pero no necesariamente después de las opciones) o a través de la opción --device=DISPOSITIVO.

SPC-4 no utiliza el término "sub-comando". Utiliza el término "acción de servicio" para esto y para parte del nombre de un campo en el bloque de parámetros asociado con el comando PROUT (es decir, "clave de reserva de acción de servicio"). Para disminuir la posible confusión, se ha introducido el término "sub-comando".

OPCIONES

Los argumentos de las opciones largas son obligatorios también para las opciones cortas. Las siguientes opciones están ordenadas alfabéticamente, basándose en el nombre de la opción larga.

-l, --alloc-length=LONGITUD
especificar la longitud de asignación del comando PRIN. LONGITUD es un valor hexadecimal. Por defecto, este valor se establece en el tamaño del búfer de datos de entrada (8192). Este parámetro es útil para verificar que la respuesta a los comandos PRIN con varias longitudes de asignación cumple con la sección 4.3.5.6 de SPC-4 revisión 18. Los valores de LONGITUD válidos son 0-8192.
-C, --clear
Clear es un sub-comando del comando PROUT. Libera la reserva persistente (si la hay) y borra todos los registros del dispositivo. Se requiere proporcionar una clave de reserva que esté registrada para este nexo I_T_L (identificado por --param-rk=RK).
Esta opción emite el comando SCSI PERSISTENT RESERVE OUT con su campo de acción de servicio establecido en CLEAR [0x3].
-d, --device=DISPOSITIVO
DISPOSITIVO al que enviar comandos SCSI. El DISPOSITIVO puede proporcionarse a través de esta opción o de un argumento independiente. Por ejemplo, estos dos: 'sg_persist --device=/dev/sg2' y 'sg_persist /dev/sg2' son equivalentes.
-h, --ayuda
mostrar un mensaje de uso con las opciones principales. Usar dos veces (por ejemplo, '-hh') para obtener otras opciones y más ayuda.
-H, --hex
la respuesta a un sub-comando PRIN válido se mostrará en hexadecimal. Por defecto (es decir, sin esta opción) si se reconoce el sub-comando PRIN, la respuesta se decodificará según SPC-4. Puede usarse más de una vez para obtener más hexadecimal y menos texto.
-i, --in
especificar que se requiere un comando SCSI PERSISTENT RESERVE IN. Este es el valor por defecto.
-m, --maxlen=LONGITUD
LONGITUD se utiliza como campo ALLOCATION LENGTH del comando PRIN. LONGITUD es por defecto un valor decimal. Para dar un valor hexadecimal, use un prefijo '0x' o '0X', o use un sufijo 'h' (o 'H'). También puede tomar multiplicadores, consulte la opción --maxlen=LONGITUD en la página del manual de sg3_utils.
Esta opción es la misma que la opción --alloc-length=LONGITUD, aparte de la representación de LONGITUD. La opción es decimal por defecto, mientras que --alloc-length=LONGITUD solo acepta hexadecimal.
-n, --no-inquiry
la acción por defecto es ejecutar un comando SCSI INQUIRY estándar y mostrar las cadenas de marca, producto y revisión, además del tipo de dispositivo periférico, antes de ejecutar un comando PRIN o PROUT. Con esta opción, el comando INQUIRY se omite.
-o, --out
especificar que se requiere un comando SCSI PERSISTENT RESERVE OUT. Es necesario proporcionarla cuando se utilizan sub-comandos PROUT.
-Y, --param-alltgpt
establecer el indicador 'all target ports' (ALL_TG_PT) en el bloque de parámetros del comando PROUT. Solo relevante para los sub-comandos 'register' y 'register and ignore existing key'.
-Z, --param-aptpl
establecer el indicador 'activate persist through power loss' (APTPL) en el bloque de parámetros del comando PROUT. Relevante para los sub-comandos 'register', 'register and ignore existing key' y 'register and move'.
-K, --param-rk=RK
especificar la clave de reserva que se encuentra en el bloque de parámetros del comando PROUT. Se asume que RK es hexadecimal (hasta 8 bytes de longitud). El valor por defecto es 0. Esta opción es necesaria para la mayoría de los sub-comandos PROUT.
-S, --param-sark=SARK
especificar la clave de reserva de acción de servicio que se encuentra en el bloque de parámetros del comando PROUT. Se asume que SARK es hexadecimal (hasta 8 bytes de longitud). El valor por defecto es 0. Esta opción es necesaria para algunos sub-comandos PROUT.
-P, --preempt
Preempt es un sub-comando del comando PROUT. Interrumpe la reserva persistente existente (identificada por --param-sark=SARK) con la clave de registro que está registrada para este nexo I_T_L (identificado por --param-rk=RK). Si se establece una nueva reserva como resultado de la interrupción, se utiliza el --prout-type=TIPO proporcionado como tipo para esta nueva reserva.
Esta opción emite el comando SCSI PERSISTENT RESERVE OUT con su campo de acción de servicio establecido en PREEMPT [0x4].
-A, --preempt-abort
Preempt and Abort es un sub-comando del comando PROUT. Interrumpe la reserva persistente existente (identificada por --param-sark=SARK) con la clave de registro que está registrada para este nexo I_T_L (identificado por --param-rk=RK). Si se establece una nueva reserva como resultado de la interrupción, se utiliza el --prout-type=TIPO proporcionado como tipo para esta nueva reserva. ACA y otras tareas pendientes se abortan.
Esta opción emite el comando SCSI PERSISTENT RESERVE OUT con su campo de acción de servicio establecido en PREEMPT AND ABORT [0x5].
-T, --prout-type=TIPO
especificar el argumento de 'tipo' del comando PROUT. Requerido por los sub-comandos 'register-move', 'reserve', 'release' y 'preempt (and abort)'. Valores válidos de TIPO: 1-> write exclusive, 3-> exclusive access, 5-> write exclusive - registra
-R, --register
Register es un sub-comando del comando PROUT. Registra la clave de reserva proporcionada por --param-rk=RK para el nexo I_T_L. Si otra I_T_L ya tiene una clave registrada, fallará.
Esta opción emite el comando SCSI PERSISTENT RESERVE OUT con su campo de acción de servicio establecido en REGISTER [0x1].
-X, --register-ignore
Register and Ignore Existing Key es un sub-comando del comando PROUT. Registra la clave de reserva proporcionada por --param-rk=RK para el nexo I_T_L. Si ya existe una clave registrada (para cualquier I_T_L), se ignora y se reemplaza por la clave proporcionada.
Esta opción emite el comando SCSI PERSISTENT RESERVE OUT con su campo de acción de servicio establecido en REGISTER AND IGNORE EXISTING KEY [0x6].
-M, --register-move
Register and Move es un sub-comando del comando PROUT. Registra la clave de reserva proporcionada por --param-rk=RK para el nexo I_T_L. Si ya existe una clave registrada para la I_T_L de destino (identificada por --param-sark=SARK) entonces esa reserva se mueve a la nueva clave proporcionada por --param-rk=RK. Si se utiliza con el tipo establecido en 1 (write exclusive) o 5 (write exclusive - registrants only) entonces el valor de APTPL (si se establece) también se moverá.
Esta opción emite el comando SCSI PERSISTENT RESERVE OUT con su campo de acción de servicio establecido en REGISTER AND MOVE [0x7].
-L, --release
Release es un sub-comando del comando PROUT. Libera la reserva persistente (si la hay) asociada con la clave de reserva proporcionada por --param-rk=RK. Si la clave de reserva proporcionada no coincide con la que tiene la reserva, fallará.
Esta opción emite el comando SCSI PERSISTENT RESERVE OUT con su campo de acción de servicio establecido en RELEASE [0x2].
-e, --service-action=SA
especificar la acción de servicio SCSI para el comando PRIN o PROUT. SA puede ser un número decimal o hexadecimal (con prefijo '0x' o '0X'). Consulte la documentación de SCSI para ver las acciones de servicio disponibles. Para los comandos PRIN, las acciones de servicio 0 a 3 son implementadas por esta utilidad. Para los comandos PROUT, las acciones de servicio 0 a 7 son implementadas por esta utilidad.
-v, --verbose
incrementar el nivel de verbosidad. Puede usarse varias veces.
-w, --version
imprimir la versión del paquete sg3_utils y salir.

EJEMPLOS

Para obtener una lista de las claves registradas en el dispositivo `/dev/sg0`, use:

sg_persist --device=/dev/sg0 --read-keys

Para liberar una reserva en `/dev/sg0` para la clave `0x1234567890abcdef`, use:

sg_persist --out --release --param-rk=0x1234567890abcdef /dev/sg0

Para registrar una clave `0x1234567890abcdef` en `/dev/sg0`, use:

sg_persist --out --register --param-rk=0x1234567890abcdef /dev/sg0

Para registrar una clave `0x1234567890abcdef` en `/dev/sg0` y establecerla como una reserva de acceso exclusivo, use:

sg_persist --out --register --prout-type=3 --param-rk=0x1234567890abcdef /dev/sg0

Para interrumpir una reserva existente y establecer una nueva reserva de acceso exclusivo con la clave `0x1234567890abcdef` en `/dev/sg0`, use:

sg_persist --out --preempt --prout-type=3 --param-rk=0x1234567890abcdef --param-sark=0xabcdef1234567890 /dev/sg0

Set the ALL TARGETS bit in the service action parameter list when issuing a PROUT command. This means that the persistent reservation, if it exists, applies to all targets associated with the logical unit.
-c, --cmd-timeout=TIMEOUT

TRANSPORT IDs

TransportIDs are used in persistent reservations to identify initiators. The format of a TransportID differs depending on the type of transport being used. Their format is described in SPC-4 (in draft revision 37 see section 7.6.4).

A TransportID is required for the PROUT 'register and move' sub-command and the PROUT 'register' sub-command can have zero, one or more TransportIDs.

When the --transport-id=TIDS option is given then the TIDS argument may be a comma (or single space) separated list of ASCII hex bytes that represent a single TransportID as defined in SPC-4. Alternatively the TIDS argument may be a transport specific string starting with either "fcp,", "spi,", "sbp,", "srp,", "iqn", "sas," or "sop,". The "iqn" form is an iSCSI qualified name. Apart from "iqn" the other transport specific leadin string may be given in upper case (e.g. "FCP,").

The "fcp," form should be followed by 16 ASCII hex digits that represent an initiator's N_PORT_NAME (e.g. "fcp,10000000C9F3A571"). The "spi," form should be followed by "<scsi_address>,<relative_target_port_identifier>" (both decimal numbers). The "sbp," form should be followed by 16 ASCII hex digits that represent an initiator's EUI-64 name. The "srp," form should be followed by 32 ASCII hex digits that represent an initiator port identifier. The "sas," form should be followed by 16 ASCII hex digits that represent an initiator's port SAS address (e.g. "sas,5000c50005b32001"). The "sop," form takes a hex number that represents a routing id.

There are two iSCSI qualified name forms. The shorter form contains the iSCSI name of the initiator port (e.g. "iqn.5886.com.acme.diskarrays-sn-a8675309"). The longer form adds the initiator session id (ISID in hex) separated by ",i,0x". For example "iqn.5886.com.acme.diskarrays-sn-a8675309,i,0x1234567890ab". On the command line to stop punctuation in an iSCSI name being (mis)-interpreted by the shell, putting the option argument containing the iSCSI name in double quotes is advised. iSCSI names are encoded in UTF-8 so if non (7 bit) ASCII characters appear in the iSCSI name on the command line, there will be difficulties if they are not encoded in UTF-8. The locale can be changed temporarily by prefixing the command line invocation of sg_persist with "LANG=en_US.utf-8" for example.

NOMBRE

sg_persist - Utilidad de la línea de comandos para los comandos SCSI persistentes.

SINOPSIS

sg_persist [OPTION<<gt>;...

sg_persist [--all] [--clear] [--device=DEVICE] [--dump-ascii=FILENAME] [--echo=] [--help] [--in] [--key=KEY] [--list] [--log=] [--out] [--prout-type=TYPE] [--read-key] [--read-reservation] [--register] [--release] [--reserve] [--transport-id=TIDS] [--verbose] [--version] [--xferlen=LEN]

DESCRIPCIÓN

El comando sg_persist lee y escribe información sobre persistencia de SCSI, que está definida en el estándar SPC-3 y SPC-4.

Los comandos persistentes son utilizados para gestionar reservas y claves de registro en un dispositivo de almacenamiento SCSI. Estos comandos permiten a los iniciadores (controladores) reservar un dispositivo de forma persistente para asegurar que solo un iniciador a la vez pueda acceder a él, lo cual es crucial para aplicaciones de alta disponibilidad y clústeres de almacenamiento.

El comando sg_persist expone las funcionalidades de los subcomandos PERSISTENT RESERVE OUT (PROUT) y PERSISTENT RESERVE IN (PRIN) del estándar SCSI.

OPCIONES

--all
Solo relevante para el subcomando READ RESERVATION. Imprime todos los elementos de reserva presentes en el dispositivo.
--clear
Ejecuta el subcomando CLEAR PERSISTENT RESERVE. Borra todas las reservas y registros en el dispositivo.
--device=DEVICE
Especifica el dispositivo SCSI sobre el cual operar. Esto podría ser algo como /dev/sg0 o /dev/sdb. Si no se especifica, sg_persist buscará un dispositivo adecuado.
--dump-ascii=FILENAME
Exporta los datos recibidos del dispositivo (para subcomandos READ KEY o READ RESERVATION) a un archivo en formato de texto ASCII.
--echo=
Imprime la cadena dada en la salida estándar. Útil para depuración o para construir cadenas de comandos complejas.
--help
Muestra un mensaje de ayuda y sale.
--in
Indica que se realizará una operación PERSISTENT RESERVE IN (PRIN). Es el valor predeterminado si no se especifica --out.
--key=KEY
Especifica la clave de registro (un número hexadecimal) para la operación. Por ejemplo, --key=0x12345678.
--list
Solo relevante para los subcomandos READ KEY y READ RESERVATION. Imprime una lista de las claves de registro y las reservas presentes en el dispositivo.
--log=
Escribe información de depuración detallada en el archivo especificado.
--out
Indica que se realizará una operación PERSISTENT RESERVE OUT (PROUT). Es el valor predeterminado si no se especifica --in.
--prout-type=TYPE
Especifica el tipo de reserva para subcomandos REGISTER, RESERVE, RELEASE o CLEAR. Los tipos válidos son: 0 (Write Exclusive), 1 (Exclusive Access), 2 (Write Exclusive and Registrants Follow), 3 (Exclusive Access and Registrants Follow), 4 (Write Exclusive, Registrants Follow, All Recipients), 5 (Exclusive Access, Registrants Follow, All Recipients).
--read-key
Ejecuta el subcomando READ KEY. Lee una clave de registro del dispositivo.
--read-reservation
Ejecuta el subcomando READ RESERVATION. Lee la información de reserva actual del dispositivo.
--register
Ejecuta el subcomando REGISTER PERSISTENT RESERVE. Registra una clave en el dispositivo.
--release
Ejecuta el subcomando RELEASE PERSISTENT RESERVE. Libera una reserva existente.
--reserve
Ejecuta el subcomando RESERVE PERSISTENT RESERVE. Reserva el dispositivo con la clave y el tipo especificados.
--transport-id=TIDS
Especifica un identificador de transporte. Puede ser una cadena de bytes hexadecimales ASCII o un nombre de archivo. Ver la sección TRANSPORT IDs.
--verbose
Incrementa el nivel de detalle de la salida.
--version
Muestra la información de la versión y sale.
--xferlen=LEN
Establece la longitud de la transferencia de datos para comandos IN. El valor predeterminado es 65536 bytes.

TRANSPORT IDs

El argumento --transport-id=TIDS se utiliza para especificar un identificador de transporte (TransportID) para las operaciones de reserva persistente. Este identificador se utiliza para asociar las reservas con iniciadores específicos en entornos complejos de red de almacenamiento.

Si el argumento TIDS es "-", se lee la entrada estándar (stdin). Si el argumento TIDS tiene el formato "file=<nombre>", se lee un archivo llamado <nombre>. Un TransportID válido de SPC-4 se construye a partir de la cadena específica del transporte descrita en los párrafos anteriores.

El análisis de los datos leídos es relativamente simple. Las líneas vacías se ignoran. Todo desde y incluyendo un "#" en una línea se ignora. Los espacios y tabulaciones iniciales se ignoran. Puede haber un transportID por línea. El transportID puede ser una lista de bytes hexadecimales ASCII separados por comas, espacios o tabulaciones que representan un TransportID tal como se define en SPC-4. Se realiza un relleno con bytes cero a una longitud mínima de 24 bytes si es necesario. El transportID también puede ser el tipo de cadena específica del transporte discutido anteriormente.

En SPC-3, el bit SPEC_I_PT se establecía en uno y se permitían TransportIDs para el registro PROUT e ignorar el subcomando de clave existente. En SPC-4, eso se desaconseja, produciendo un estado CHECK CONDITION con una clave de sentido ILLEGAL REQUEST y un código de sentido adicional establecido en INVALID FIELD IN PARAMETER LIST.

NOTAS

En la serie 2.4 de los kernels de Linux, el DEVICE debe ser un dispositivo genérico SCSI (sg). En la serie 2.6, se puede especificar cualquier nombre de dispositivo SCSI (por ejemplo, /dev/sdc, /dev/st1m o /dev/sg3). Por ejemplo, "sg_persist --read-keys /dev/sdb" funcionará en los kernels de la serie 2.6.

El único ámbito para los comandos PROUT admitido en el borrador actual de SPC-4 es "LU_SCOPE". Por lo tanto, parece inútil ofrecer una opción para establecer el ámbito a otro valor.

La mayoría de los errores con los subcomandos PROUT (por ejemplo, --prout-type=TYPE faltante o incorrecto) resultarán en un estado RESERVATION CONFLICT. Esto puede ser un poco confuso cuando sabes que solo hay un iniciador (activo): el "conflicto" es con el estándar SPC, no con otro iniciador.

Algunos discos recientes aceptan algunos subcomandos PRIN y PROUT cuando los medios están detenidos. Una excepción fue el establecimiento del indicador APTPL (con la opción --param-aptpl) durante una operación de registro de clave; se quejó si el disco estaba detenido. El error indicó que quería que el disco estuviera encendido y, cuando eso sucedió, el registro fue exitoso.

EJEMPLOS

Estos ejemplos utilizan nombres de dispositivos de Linux. Para nombres de dispositivos adecuados en otros sistemas operativos compatibles, consulte la página man de sg3_utils(8).

Debido a los diversos valores predeterminados de las opciones, el ejemplo más simple ejecuta el subcomando 'read keys' del comando PRIN:


sg_persist /dev/sdb

Esto es lo mismo que el siguiente comando (prolijo):


sg_persist --in --read-keys --device=/dev/sdb

Para leer la reserva actual, se puede usar la forma '--read-reservation' o la forma más corta '-r':


sg_persist -r /dev/sdb

Para registrar la nueva clave de reserva 0x123abc, se podría usar lo siguiente:


sg_persist --out --register --param-sark=123abc /dev/sdb

Dado que el registro anterior tiene éxito, para reservar el DEVICE (con tipo 'write exclusive'), se podría usar lo siguiente:


sg_persist --out --reserve --param-rk=123abc
--prout-type=1 /dev/sdb

Para liberar la reserva, se puede usar el siguiente comando (tenga en cuenta que los argumentos --param-rk y --prout-type deben coincidir con los de la reserva):


sg_persist --out --release --param-rk=123abc
--prout-type=1 /dev/sdb

Finalmente, para desregistrar una clave de reserva (y no afectar otros registros, que es lo que haría '--clear'), el comando es un poco sorprendente:


sg_persist --out --register --param-rk=123abc /dev/sdb

Ahora observe detenidamente la diferencia entre los ejemplos de registro y desregistro anteriores.

Se puede encontrar un archivo de ejemplo con el formato adecuado para pasar TransportIDs a través de una opción '--transport-id=file=transport_ids.txt' en el subdirectorio de ejemplos del paquete sg3_utils. También hay un script de prueba simple llamado sg_persist_tst.sh en el mismo directorio.

La secuencia de comandos anterior se probó con éxito en un disco Seagate Savvio 10K.3 y un SSD 1200, ambos con interfaces SAS.

ESTADO DE SALIDA

El estado de salida de sg_persist es 0 cuando tiene éxito. De lo contrario, consulte la página man de sg3_utils(8).

VARIABLES DE ENTORNO

Actualmente, hay una variable de entorno reconocida: SG_PERSIST_IN_RDONLY. Si está presente y solo si se ha seleccionado un comando PRIN, el DEVICE dado se abre en modo de solo lectura (por ejemplo, en Unix, con el indicador O_RDONLY). Consulte la opción --readonly.
