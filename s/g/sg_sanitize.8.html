NOMBRE

sg_sanitize - elimina todos los datos de usuario del disco con el comando SCSI SANITIZE

SINOPSIS

sg_sanitize [--ause] [--block] [--count=OC] [--crypto] [--dry-run] [--desc] [--early] [--fail] [--help] [--invert] [--ipl=LEN] [--overwrite] [--pattern=PF] [--quick] [--test=TE] [--timeout=SECS] [--verbose] [--version] [--wait] [--zero] [--znr] DISPOSITIVO

DESCRIPCIÓN

Esta utilidad invoca el comando SCSI SANITIZE. Este comando se introdujo por primera vez en la revisión 27 del borrador de SBC-3. El propósito de la operación de sanitización es alterar la información en la caché y en el medio de una unidad lógica (por ejemplo, un disco) de modo que la recuperación de datos del usuario no sea posible. Si esos datos del usuario no pueden ser borrados, o están en proceso de ser borrados, entonces la operación de sanitización impide el acceso a esos datos del usuario.

Una vez que se ha iniciado con éxito un comando SCSI SANITIZE, los datos del usuario de ese disco ya no están disponibles. Incluso si el disco se apaga y se vuelve a encender, la operación de sanitización continuará después de que se restablezca la energía hasta que se complete.

Esta utilidad requiere la opción --block, --crypto, --fail u --overwrite. Con la opción --block, --crypto u --overwrite, se le dan al usuario 15 segundos para reconsiderar si desea borrar todos los datos de un disco, a menos que se proporcione la opción --quick, en cuyo caso la operación de sanitización comienza inmediatamente. Las cadenas de respuesta de INQUIRY del disco se imprimen por si se ha proporcionado el DISPOSITIVO incorrecto.

Si se proporciona la opción --early, esta utilidad saldrá poco después de iniciar el comando SANITIZE con el bit IMMED establecido. El usuario puede monitorear el progreso de la operación de sanitización con "sg_requests --num=9999 --progress", que envía un comando REQUEST SENSE cada 30 segundos. De lo contrario, si se proporciona la opción --wait, esta utilidad esperará hasta que el comando SANITIZE se complete (o falle), lo que puede llevar muchas horas.

Si no se proporciona la opción --wait, el comando SANITIZE se inicia con el bit IMMED establecido. Si no se proporcionan ni la opción --early ni la opción --wait, esta utilidad envía un comando REQUEST SENSE cada 60 segundos hasta que no haya más indicaciones de progreso, en cuyo caso esta utilidad sale silenciosamente. Si adicionalmente se proporciona la opción --verbose, la salida estará marcada por un breve mensaje que indica que la sanitización parece haber tenido éxito.

OPCIONES

Los argumentos de las opciones largas son obligatorios también para las opciones cortas. Las opciones están ordenadas alfabéticamente según el nombre de la opción larga.

-A, --ause
establece el bit AUSE en el cdb. AUSE es el acrónimo de "allow unrestricted sanitize exit" (permitir salida de sanitización sin restricciones). La acción predeterminada es dejar el bit AUSE borrado.
-B, --block
realiza una operación de sanitización de "borrado en bloque".
-c, --count=OC
donde OC es el "número de sobrescrituras" asociado con la operación de sanitización de "sobrescritura". OC puede ser un valor entre 1 y 31, y 1 es el valor predeterminado.
-C, --crypto
realiza una operación de sanitización de "borrado criptográfico". Tenga en cuenta que este borrado suele ser muy rápido, ya que simplemente sobrescribe una clave criptográfica interna con un nuevo valor. Esas claves no son accesibles para los usuarios y cifran todos los datos que se escriben y descifran todos los datos que se leen del medio. La razón principal para hacer esto es que la operación sea rápida. Esta operación no se puede revertir.
-d, --desc
establece el campo DESC en el comando REQUEST SENSE utilizado para el sondeo. Por defecto, este campo se establece en cero. Se utiliza un bucle de sondeo de REQUEST SENSE después de que se emite el comando SANITIZE (suponiendo que no se hayan proporcionado ni la opción --early ni la opción --wait) para verificar el progreso de este comando, ya que puede llevar tiempo.
-D, --dry-run
esta opción analizará la línea de comandos, realizará toda la preparación pero omitirá el comando SANITIZE real.
-e, --early
la acción predeterminada de esta utilidad es sondear el disco cada 60 segundos para obtener la indicación de progreso hasta que se complete la sanitización. Cuando se proporciona esta opción, la utilidad saldrá "temprano" tan pronto como se haya reconocido el comando SANITIZE con el bit IMMED establecido en 1. Esta opción y --wait no se pueden proporcionar juntas.
-F, --fail
realiza una operación de sanitización de "salida del modo de error". Típicamente requiere que el comando SANITIZE anterior haya establecido el bit AUSE.
-h, --help
imprime la información de uso y luego sale.
-i, --ipl=LEN
establece la longitud del patrón de inicialización en LEN bytes. Por defecto, se establece en la longitud del archivo de patrón (PF) o 4 si se proporciona la opción --zero. Solo está activo cuando se proporciona también la opción --overwrite. Es el número de bytes del archivo PF que se utilizarán como patrón de inicialización (si no se proporciona la opción --zero). El tamaño mínimo es de 1 byte y el máximo es el tamaño del bloque lógico del DISPOSITIVO (y no debe exceder 65535). Si LEN excede el tamaño del archivo PF, el patrón de inicialización se rellena con ceros.
-I, --invert
establece el bit INVERT en la lista de parámetros de la acción de servicio de sobrescritura. Esto solo afecta a la operación de sanitización de "sobrescritura". El valor predeterminado es un bit INVERT borrado. Cuando el bit INVERT está establecido, el patrón de inicialización se invierte entre pases de sobrescritura consecutivos.
-O, --overwrite
realiza una operación de sanitización de "sobrescritura". Cuando se proporciona esta opción, se requiere la opción --pattern=PF o la opción --zero.
-p, --pattern=PF
donde PF es el nombre del archivo que contiene el patrón de inicialización requerido por una operación de sanitización de "sobrescritura". La longitud de este archivo se utilizará como la longitud del patrón de inicialización a menos que se proporcione la opción --ipl=LEN. La longitud del patrón de inicialización debe estar entre 1 y el tamaño del bloque lógico del DISPOSITIVO.
-Q, --quick
la acción predeterminada (es decir, cuando la opción no se proporciona) es dar al usuario 15 segundos para reconsiderar la realización de una operación de sanitización en el DISPOSITIVO. Cuando se proporciona esta opción, se omite ese paso (es decir, el período de advertencia de 15 segundos).
-T, --test=TE
establece el campo TEST en la lista de parámetros de la acción de servicio de sobrescritura. Esto solo afecta a la operación de sanitización de "sobrescritura". El valor predeterminado es colocar 0 en ese campo.
-t, --timeout=SECS
donde SECS es el número de segundos utilizado para el tiempo de espera del comando SANITIZE.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración).
-V, --version
imprime la cadena de versión y luego sale.
-w, --wait
la acción predeterminada (es decir, sin esta opción y la opción --early) es iniciar el comando SANITIZE con el bit IMMED establecido y luego sondear la indicación de progreso con el comando REQUEST SENSE hasta que la operación de sanitización se complete (o falle). Cuando se proporciona esta opción (y la opción --early no se proporciona), el comando SANITIZE se inicia con el bit IMMED borrado. Para un disco grande, esto podría llevar horas. [Una operación de borrado criptográfico podría ser muy rápida.]
-z, --zero
con una operación de sanitización de "sobrescritura", esta opción hace que el patrón de inicialización sea cero

EJEMPLOS

Para sobrescribir un disco `/dev/sdc` con un patrón de un archivo `patron.bin` en tres pasadas:

sg_sanitize --overwrite --pattern=patron.bin --count=3 /dev/sdc

Para realizar un borrado criptográfico en `/dev/sdb` y esperar a que termine:

sg_sanitize --crypto --wait /dev/sdb

Para iniciar un borrado en bloque en `/dev/sda` y salir inmediatamente:

sg_sanitize --block --early /dev/sda

ESTADO DE SALIDA

Las opciones --help y --version salen con un estado de 0. Si la operación tiene éxito, el valor devuelto es 0. Si falla, el valor devuelto es un código de error estándar de sysexits.h (por ejemplo, EX_IOERR).

NOTAS

El comando SCSI SANITIZE está estrechamente relacionado con el comando ATA SANITIZE, ambos son relativamente nuevos, siendo el comando ATA el primero en definirse. La definición de SCSI a ATA Translation (SAT) para el comando SCSI SANITIZE apareció en el borrador de SAT-3 revisión 4.

Cuando se utiliza una capa SAT en un disco (S)ATA, para OVERWRITE el patrón de inicialización debe tener 4 bytes de longitud. Esto significa que o bien se puede dar la opción --zero, o un archivo de patrón (con la opción --pattern=PF) que sea de 4 bytes de longitud o se establezca a esa longitud con la opción --ipl=LEN.

El comando SCSI SANITIZE está relacionado con el comando SCSI FORMAT UNIT. Es probable que una operación de sanitización de borrado de bloques lleve una cantidad de tiempo similar a un formateo en el mismo disco (por ejemplo, 9 horas para un disco de 2 Terabytes). El objetivo principal de un formateo es la configuración del disco al final del mismo (por ejemplo, diferente tamaño de bloque lógico o información de protección añadida). La eliminación de datos de usuario es solo un efecto secundario de un formateo. Con el comando SCSI SANITIZE, la eliminación de datos de usuario es el objetivo principal. Si una operación de sanitización se interrumpe (por ejemplo, el disco se apaga y se vuelve a encender) entonces después de encenderse, cualquier dato de usuario restante no estará disponible y la operación de sanitización continuará. Cuando un formateo se interrumpe (por ejemplo, el disco se apaga y se vuelve a encender), los borradores dicen muy poco sobre el estado del disco. En la práctica, es posible que queden algunos de los datos de usuario originales y que el formateo necesite reiniciarse.

Averiguar si un disco (SCSI o ATA) soporta SANITIZE puede ser un desafío. Si el usuario realmente necesita saberlo y no hay otra información disponible, entonces intentar 'sg_sanitize --fail -vvv <dispositivo>' y observar los datos de sentido devueltos puede ser el enfoque más seguro. Usar la variante --fail de esta utilidad no debería tener ningún efecto a menos que siga a una operación de sanitización ya fallida. Si el comando SCSI REPORT SUPPORTED OPERATION CODES (ver sg_opcodes) es compatible, entonces usarlo sería un mejor enfoque para averiguar si sanitize es compatible.

Si se utiliza el comando dd para verificar los datos antes y después de un bloque particular (es decir, comprobar si el borrado funcionó realmente) es una buena idea usar el operando 'iflag=direct'. De lo contrario, la primera lectura podría ser cacheada y devuelta cuando el mismo LBA se lee un poco más tarde. Obviamente, esta utilidad solo debe usarse para sanitizar datos en un disco cuyos sistemas de archivos montados (si los hay) se hayan desmontado antes del borrado.

EJEMPLOS

Estos ejemplos utilizan nombres de dispositivos de Linux. Para nombres de dispositivos adecuados en otros sistemas operativos compatibles, consulte la página man de sg3_utils(8).

Como precaución, si esta utilidad se llama sin opciones, aparte de imprimir un mensaje de uso, no ocurre nada:


sg_sanitize /dev/sdm

Para hacer una sanitización de "borrado de bloques", se requiere la opción --block. Se dará al usuario un período de 15 segundos para reconsiderar, se iniciará el comando SCSI SANITIZE con el bit IMMED establecido, y luego esta utilidad hará un sondeo para obtener una indicación de progreso con un comando REQUEST SENSE hasta que la operación de sanitización haya terminado:


sg_sanitize --block /dev/sdm

Para iniciar una sanitización de "borrado de bloques" y salir de esta utilidad una vez que se haya iniciado (pero aún no completado), use la opción --early:


sg_sanitize --block --early /dev/sdm

Si el tiempo de reconsideración de 15 segundos no es necesario, añada la opción --quick:


sg_sanitize --block --quick --early /dev/sdm

Para hacer una sanitización de "overwrite", se puede proporcionar un archivo de patrón:


sg_sanitize --overwrite --pattern=rand.img /dev/sdm

Si la longitud de ese "rand.img" es de 512 bytes (un tamaño de bloque lógico típico), entonces para usar solo los primeros 17 bytes (repetidamente) en la operación de sanitización de "overwrite":


sg_sanitize --overwrite --pattern=rand.img --ipl=17 /dev/sdm

Para sobrescribir con ceros use:
sg_sanitize --overwrite --zero /dev/sdm

ESTADO DE SALIDA

El estado de salida de sg_sanitize es 0 cuando es exitoso. De lo contrario, consulte la página man de sg3_utils(8). A menos que se proporcione la opción --wait, el estado de salida puede no reflejar el éxito o el fracaso del formateo.

La convención Unix es que "no news is good news" (ninguna noticia es buena noticia), pero eso puede ser un poco inquietante después de una operación como la sanitización, especialmente si termina rápidamente (es decir, antes de que se envíe la primera encuesta de progreso). Dar la opción --verbose una vez debería proporcionar suficiente salida adicional para calmar esos nervios.
