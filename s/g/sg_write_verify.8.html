NOMBRE

sg_write_and_verify - enviar el comando SCSI WRITE AND VERIFY

SINOPSIS

sg_write_verify [--16] [--bytchk=BC] [--dpo] [--group=GN] [--help] [--ilen=ILEN] [--in=IF] --lba=LBA [--num=NUM] [--repeat] [--timeout=TO] [--verbose] [--version] [--wrprotect=WP] DISPOSITIVO

DESCRIPCIÓN

Envía un comando SCSI WRITE AND VERIFY (10) o (16) al DISPOSITIVO. Los datos a escribir se leen del archivo IF o, en su ausencia, se utiliza un búfer lleno de bytes 0xff. La longitud del búfer de datos de salida enviado con el comando es ILEN bytes o, si no se proporciona, es la longitud del archivo IF.

La operación de escritura es en el medio del DISPOSITIVO (opcionalmente en su caché) comenzando en la dirección de bloque lógico LBA durante NUM bloques lógicos. Después de realizar la escritura en el medio, se realiza una operación de verificación que puede verse como una lectura del medio (con las comprobaciones adecuadas) pero sin devolver los datos. Además, si BS se establece en uno, los datos leídos del medio en la operación de verificación se comparan con el búfer de datos de salida original.

La relación entre el número de bloques lógicos a escribir (es decir, NUM) y la longitud (en bytes) del búfer de datos de salida (es decir, ILEN) se puede encontrar simplemente multiplicando el primero por el tamaño del bloque lógico. Sin embargo, si el DISPOSITIVO tiene información de protección (PI), se vuelve un poco más complicado. Por lo tanto, el cálculo se deja al usuario con el valor predeterminado de ILEN, en ausencia del archivo IF, establecido en NUM \* 512.

Para enviar grandes cantidades de datos a bloques lógicos contiguos, un solo comando WRITE AND VERIFY puede no ser apropiado (por ejemplo, debido a limitaciones del sistema operativo). En tales casos, consulte la sección REPEAT a continuación.

OPCIONES

Los argumentos de las opciones largas son obligatorios también para las opciones cortas. Las opciones están ordenadas alfabéticamente según el nombre de la opción larga.

-S, --16
Enviar un comando WRITE AND VERIFY(16). El valor predeterminado es enviar un comando WRITE AND VERIFY(10) a menos que LBA o NUM sean demasiado grandes para la variante de 10 bytes.
-b, --bytchk=BC
donde BC es el valor a colocar en el campo BYTCHK del comando. Se aceptan valores entre 0 y 3 (inclusive). El valor predeterminado es 0, que implica que solo se realizan una escritura en el medio y luego una operación de verificación. El único otro valor que T10 define actualmente es 1, que realiza una comparación adicional entre el búfer de datos de salida utilizado por la operación de escritura y el contenido de los bloques lógicos leídos del medio.
-d, --dpo
Establecer el bit DPO (deshabilitar page out) en el comando. El valor predeterminado es dejarlo despejado.
-g, --group=GN
donde GN es el valor a colocar en el campo GROUP NUMBER del comando. Se aceptan valores entre 0 y 63 (inclusive). El valor predeterminado es 0.
-h, --help
mostrar el mensaje de uso y salir.
-I, --ilen=ILEN
donde ILEN es el número de bytes que se colocarán en el búfer de datos de salida. Si se proporciona el archivo IF, no se leen más de ILEN bytes de ese archivo. Si el archivo IF no contiene ILEN bytes, se informa un error. Si no se proporciona el archivo IF, se envía un búfer de datos de salida con ILEN bytes de 0xff.
-i, --in=IF
leer datos (binarios) del archivo llamado IF. Si IF es "-", se utiliza la entrada estándar. Estos datos se convertirán en el búfer de datos de salida y se escribirán en el medio del DISPOSITIVO. Si BC es 1, ese búfer de datos de salida se conservará hasta después de la operación de verificación y se comparará con los datos leídos del medio.
-l, --lba=LBA
donde LBA es la dirección de bloque lógico desde la que comenzar la escritura en el medio. Se asume en decimal a menos que se prefije con '0x' o tenga un sufijo 'h'. Debe proporcionarse.
-n, --num=NUM
donde NUM es el número de bloques, comenzando en LBA, a escribir en el medio. El valor predeterminado para NUM es 1.
-R, --repeat
esta opción continuará haciendo comandos WRITE AND VERIFY hasta que se agote el archivo IF. Esta opción requiere que se proporcionen las opciones --ilen=ILEN y --in=IF. Cada comando comienza en la siguiente dirección de bloque lógico y es para no más de NUM bloques. El último comando puede ser más corto, escalando el número de bloques según sea necesario. Si hay bytes residuales, se envía una advertencia a stderr. Consulte la sección REPEAT.
-t, --timeout=TO
donde TO es el valor de tiempo de espera del comando en segundos. El valor predeterminado es 60 segundos. Si NUM es grande, el comando puede requerir considerablemente más tiempo que 60 segundos para completarse.
-v, --verbose
aumentar el grado de verbosidad (mensajes de depuración).
-V, --version
mostrar la cadena de versión y salir.
-w, --wrprotect=WP
establecer el campo WRPROTECT en el cdb a WP. El valor predeterminado es 0, lo que implica que no se envía información de protección (junto con los datos del usuario) en el búfer de datos de salida.

REPETIR

Para tamaños de datos de alrededor de un megabyte o más, puede ser apropiado enviar múltiples comandos SCSI WRITE AND VERIFY debido a limitaciones del sistema operativo (por ejemplo, las interfaces SCSI de paso directo a menudo limitan la cantidad de datos que se pueden pasar con un comando SCSI). Con esta utilidad, el mecanismo para hacerlo es la opción --repeat.

En este modo, se deben proporcionar las opciones --ilen=ILEN y --in=IF. Los valores ILEN y NUM se tratan como parámetros por comando SCSI. Se leerán hasta ILEN bytes del archivo IF continuamente hasta que se agote. Si el archivo IF es la entrada estándar, la lectura continúa hasta que se detecta un EOF. Los datos leídos de cada iteración se convierten en el búfer de datos de salida para un nuevo comando WRITE AND VERIFY.

La última lectura del archivo (o entrada estándar) puede leer menos de ILEN bytes, en cuyo caso el número de bloques lógicos enviados al último WRITE AND VERIFY se ajusta en consecuencia. Si hay un número residual de bytes después de ese ajuste, se informa a stderr.

Si ocurre un error, se informa a stderr y a través del estado de salida, y la utilidad se detiene en ese punto.

NOTAS

Otros comandos SCSI WRITE tienen un bit Force Unit Access (FUA) pero ese se establece (implícitamente) por los comandos WRITE AND VERIFY, por lo tanto, no hay opción para establecerlo. El búfer de datos de salida aún puede colocarse adicionalmente en la caché del DISPOSITIVO y establecer el bit DPO es una sugerencia para no hacer eso.

Las escrituras SCSI normales se pueden realizar con las utilidades ddpt y sg_dd. El comando SCSI WRITE SAME se puede realizar con la utilidad sg_write_same, mientras que el comando SCSI COMPARE AND WRITE (utilidad sg_compare_and_write) ofrece una función de "probar y establecer".

Varios argumentos numéricos (por ejemplo, LBA) pueden incluir sufijos multiplicativos o darse en hexadecimal. Consulte la sección "ARGUMENTOS NUMÉRICOS" en la página del manual sg3_utils(8).

ESTADO DE SALIDA

El estado de salida de sg_write_verify es 0 cuando tiene éxito. Si la operación de verificación falla, generalmente se indica con un error de medio, lo que lleva a un estado de salida de 3.

Si BC se establece en 1 y la comparación que provoca falla, esta utilidad indicará la discrepancia con un estado de salida de 14. Para otros valores de estado de salida, consulte la sección ESTADO DE SALIDA en la página del manual sg3_utils(8).

EJEMPLOS

Para empezar, un ejemplo sencillo: escribir 1 bloque de datos almacenado en el archivo t.bin que tiene 512 bytes de longitud, y luego escribir ese bloque en la LBA 0x1234 en /dev/sg4.


# sg_write_verify --lba=0x1234 --in=t.bin /dev/sg4

Dado que no se proporciona '--num=', este valor por defecto es 1. Además, el valor ILEN se obtiene del tamaño del archivo t.bin. Para realizar adicionalmente una comparación de salida de datos con los datos leídos de vuelta:


# sg_write_verify -l 0x1234 -i t.bin --bytchk=1 /dev/sg4

El comando ddpt puede realizar copias entre dispositivos SCSI utilizando comandos READ y WRITE. Sin embargo, actualmente no tiene facilidad para promocionar esos WRITES a comandos WRITE AND VERIFY. Usando una tubería, eso podría hacerse así:


# ddpt if=/dev/sg2 bs=512 bpt=8 count=11 of=- |
sg_write_verify --in=- -l 0x567 -n 8 --ilen=4096 --repeat /dev/sg4

Tanto ddpt como sg_write_verify están configurados para segmentos de 8 bloques lógicos de 512 bytes. Dado que se leen 11 bloques lógicos, se copian los primeros 8 bloques lógicos, seguidos de una copia de los 3 bloques restantes. Dado que se asume que no hay información de protección, los buffers de entrada de datos y salida de datos tendrán 4096 bytes cada uno. Para sg_write_verify, esto debe indicarse explícitamente con la opción --ilen=4096.
