NOMBRE

sg_format - formatear, formatear con preajuste, redimensionar disco SCSI; formatear cinta

SINOPSIS

sg_format [--cappid] [--cmplst={0|1}] [--count=COUNT] [--dcrt] [--dry-run] [--early] [--ffmt=FFMT] [--fmtmaxlba [--format] [--help] [--ip-def] [--long] [--mode=MP] [--pfu=PFU] [--pie=PIE] [--pinfo] [--poll=PT] [--preset=ID] [--quick] [--resize] [--rto_req] [--security] [--six] [--size=LB_SZ] [--tape=FM] [--timeout=SECS] [--verbose] [--verify] [--version] [--wait] DISPOSITIVO

DESCRIPCIÓN

No todos los dispositivos de acceso directo SCSI necesitan ser formateados y algunos tienen procedimientos de formateo específicos del fabricante. Los discos SCSI con medios rotatorios son probablemente el grupo más grande que soporta una operación de formato 'estándar'. Típicamente se formatean en fábrica con un tamaño de bloque de 512 bytes y el número más grande de bloques que el fabricante recomienda. La recomendación del fabricante típicamente reserva un cierto número de pistas, distribuidas en los medios, para la reasignación de bloques a direcciones de bloques lógicas durante la vida útil del disco.

Esta utilidad emite uno de los tres comandos de formato SCSI: FORMAT UNIT, FORMAT MEDIUM o FORMAT WITH PRESET. En la siguiente descripción, las secciones no calificadas generalmente se referirán al comando SCSI FORMAT UNIT. Tanto FORMAT UNIT como FORMAT WITH PRESET se aplican a discos (o dispositivos similares a discos). El comando FORMAT MEDIUM es para cintas. Una respuesta SCSI INQUIRY clasifica el 'Peripheral Device Type' (PDT) de cada dispositivo SCSI. Esta utilidad utiliza el PDT para verificar si hay un conflicto entre el DISPOSITIVO y la opción dada (por ejemplo, dar la opción --tape=FM cuando DISPOSITIVO es un disco normal). Si hay un conflicto, esta utilidad no continuará.

Esta utilidad puede formatear discos SCSI modernos y potencialmente cambiar su tamaño de bloque (si está permitido) y el número de bloques (es decir, el número de bloques accesibles en el medio, también conocido como "redimensionamiento"). Redimensionar un disco a menos del número de bloques recomendado por el fabricante a veces se denomina "short stroking" (ver sección NOTAS). Redimensionar el número de bloques sin cambiar el tamaño del bloque puede no requerir una operación de formato. El estándar SBC-2 (ver www.t10.org) ha dejado obsoleto el modo página "format device". Muchos de los detalles de bajo nivel que se encuentran en esa página de modo ahora se dejan a discreción del fabricante. Hay una página de registro de estado de formato (Format Status log page) que informa sobre las operaciones de formato exitosas anteriores.

Cuando esta utilidad se usa sin opciones (es decir, solo se le da un argumento DISPOSITIVO) imprime el tamaño de bloque existente y el número de bloques derivados de dos fuentes. Estas dos fuentes son un descriptor de bloque en la respuesta a un comando MODE SENSE y la respuesta a un comando READ CAPACITY. La razón de esta doble verificación es detectar un estado de "formato corrupto" (ver sección NOTAS). Este uso no modificará el disco.

Cuando esta utilidad se usa con --format, --preset=ID o --tape=FM, intentará formatear el DISPOSITIVO dado. En ausencia de la opción --quick, hay una pausa de 15 segundos durante la cual se invita al usuario tres veces (cada 5 segundos) a abortar sg_format. Esto ocurre justo antes de que se emita el comando SCSI FORMAT UNIT, FORMAT WITH PRESET o FORMAT MEDIUM. Ver la sección NOTAS para más información.

La información de protección (PI) es opcional y se compone de uno o más intervalos de protección, cada uno compuesto por 8 bytes asociados con un bloque lógico. Cuando PI está activo, cada bloque lógico tendrá 1, 2, 4, 8, etc. intervalos de protección (es decir, una potencia de dos), intercalados con (y siguiendo) los datos del usuario a los que se refieren. Se definen cuatro tipos de protección, siendo el tipo de protección 0 sin intervalos de protección. Ver la sección INFORMACIÓN DE PROTECCIÓN abajo para más información.

Cuando se da la opción --tape=FM, se envía el comando SCSI FORMAT MEDIUM al DISPOSITIVO. FORMAT MEDIUM está definido en los documentos SSC de T10 y prepara un volumen para su uso. Eso puede incluir el particionamiento del medio. Ver la sección sobre CINTA abajo para más información.

FORMAT WITH PRESET se añadió en el borrador SBC-4 revisión 18. Un patrón preestablecido, seleccionado por el campo PRESET IDENTIFIER (--id=FWPID), se escribe en el disco. Ver la página VPD Format Presets (0xb8) para una lista de identificadores de preajuste de formato disponibles y sus datos asociados.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas. Las opciones están ordenadas alfabéticamente según el nombre de la opción larga.

-a, --cappid
esta opción establece el bit CAPPID en la cabecera MODE SELECT que forma parte de la lista de parámetros de ese comando. Se necesita un comando MODE SELECT cuando se está cambiando el COUNT (es decir, el número de bloques lógicos). El comando MODE SELECT debe completarse exitosamente antes de que se realice el comando FORMAT UNIT. El bit CAPPID (introducido en SBC-5 revisión 4) está estrechamente relacionado con la página VPD Capacity/Product identification mapping (0xba). Si esa página VPD no está presente, entonces el bit CAPPID no se establece a menos que se dé la opción dos veces. Si el bit CAPPID no es compatible, se debería informar una clave de sentido de solicitud ilegal con un sentido adicional de "campo inválido en la lista de parámetros".
Si tiene éxito, esta opción puede llevar a que se cambie el campo Product identification de la respuesta INQUIRY estándar. Si es así, se establece una condición de atención de unidad con un sentido adicional de "Los datos de Inquiry han cambiado".
-C, --cmplst={0|1}
establece el bit CMPLST ("lista completa") en el cdb FORMAT UNIT a 0 o 1. Si el valor es 0, se tiene en cuenta la lista existente GLIST (lista de crecimiento). Si el valor es 1, se ignora la GLIST existente. CMPLST por defecto es 1, excepto cuando el valor de la opción --ffmt=FFMT es distinto de cero, en cuyo caso CMPLST por defecto es 0. Ver la sección LISTAS abajo. En la mayoría de los casos, este bit debe dejarse en su valor por defecto.
-c, --count=COUNT
donde COUNT es el número de bloques a formatear o la cantidad de medios a redimensionar. Se puede usar con --format o --resize. Con --format, esta opción no es necesario que se dé, en cuyo caso se asume que es cero.
Con --format la interpretación de COUNT es:
(COUNT > 0) : formatear solo los primeros COUNT bloques y READ CAPACITY informará COUNT bloques después del formato
(COUNT = 0) y tamaño de bloque sin cambios : usar el número de bloques existente
(COUNT = 0) y tamaño de bloque cambiado : número máximo de bloques recomendado para el nuevo tamaño de bloque
(COUNT = -1) : usar el número máximo de bloques recomendado
(COUNT < -1) : ilegal Con --resize esta opción debe darse y COUNT tiene esta interpretación:
(COUNT > 0) : después del redimensionamiento, READ CAPACITY informará COUNT bloques
(COUNT = 0) : después del redimensionamiento, READ CAPACITY informará 0 bloques
(COUNT = -1) : después del redimensionamiento, READ CAPACITY informará su número máximo de bloques
(COUNT < -1) : ilegal
En ambos casos, si el COUNT dado excede el número máximo de bloques (para el tamaño de bloque), el disco informa un error. Ver sección NOTAS abajo.
-D, --dcrt
esta opción establece el bit DCRT en la cabecera del parámetro del comando FORMAT UNIT. "Desactivará la certificación". La certificación verifica que los bloques son utilizables durante el proceso de formato. Usar esta opción puede acelerar el formato, pero --ffmt=FFMT, si está disponible, probablemente sería mejor. La acción por defecto de esta utilidad (es decir, cuando esta opción no se da) es borrar el bit DCRT, solicitando así "certificación del medio" (además, a menos que otra opción lo requiera, el bit FOV se borrará). Cuando el bit DCRT se establece, el bit FOV también debe establecerse, por lo que sg_format lo hace.
Si esta opción se da dos veces, la certificación se habilita borrando el bit DCRT y estableciendo el bit FOV. Ambos bits se encuentran en la lista de parámetros asociada con el cdb FORMAT UNIT.
-d, --dry-run
esta opción analizará la línea de comandos, realizará toda la preparación pero omitirá el comando FORMAT UNIT, FORMAT WITH PRESET o FORMAT MEDIUM real. Imprime un mensaje indicando lo que habría hecho.

FORMAT CON EL COMANDO PRESET o FORMAT MEDIUM. Además, si las opciones de otro modo causarían que el tamaño del bloque lógico cambiara, entonces el comando MODE SELECT que lo haría también se omite cuando se da la opción de ejecución en seco.
-e, --early
durante una operación de formato, La acción predeterminada de esta utilidad es consultar el disco cada 60 segundos (o cada 10 segundos si FFMT es distinto de cero) para determinar el progreso de la operación de formato hasta que finalice. Cuando se da esta opción, esta utilidad saldrá "temprano", es decir, tan pronto como haya comenzado la operación de formato. Luego, el usuario puede monitorear el progreso de la operación de formato en curso con otras utilidades (por ejemplo, sg_turs(8) o sg_requests(8)). Esta opción y --wait son mutuamente excluyentes.
-t, --ffmt=FFMT
FFMT (formato rápido) se coloca en un campo del mismo nombre en el CDB FORMAT UNIT. El campo se introdujo en SBC-4 revisión 10. El valor predeterminado es 0, lo que implica la acción anterior, que normalmente es sobrescribir todos los bloques del DEVICE. Eso puede llevar mucho tiempo (por ejemplo, con discos duros de más de 10 TB pueden ser días). Con FFMT establecido, ese tiempo se puede reducir a minutos o menos. Por lo tanto, vale la pena intentar si está disponible.
FFMT tiene los valores 1 y 2 para formato rápido, siendo 3 reservado actualmente. Estos dos valores incluyen esta descripción: "El servidor del dispositivo inicializa el medio... sin sobrescribir el medio (es decir, se inicializan los recursos para la gestión del acceso al medio y el medio no se escribe)". La diferencia entre 1 y 2 concierne a las operaciones de lectura en LBAs a los que no se han escrito datos, después del formato rápido. Cuando FFMT es 1, la operación de lectura debe devolver "datos de bloque lógico no especificados" y completarse sin errores. Cuando FFMT es 2, la operación de lectura puede generar un estado de condición de verificación con una clave de sentido establecida en error de hardware, error de medio o comando abortado. Consulte el borrador SBC-4 revisión 16, sección 4.34, para obtener más detalles.
-b, --fmtmaxlba
Esta opción solo está activa si se proporciona junto con la opción --preset=ID. Si es así, establece el campo FMTMAXLBA en el comando FORMAT WITH PRESET.
-f, --fmtpinfo=FPI
establece el campo FMTPINFO en el CDB FORMAT UNIT a un valor entre 0 y 3. El valor predeterminado es 0. El campo FMTPINFO de SBC-3 revisión 16 es un campo de 2 bits (bits 7 y 6 del byte 1 en el CDB). Antes de esa revisión, era un campo de un solo bit (bit 7 del byte 1 en el CDB) y había un bit acompañante llamado RTO_REQ (bit 6 del byte 1 en el CDB). Las opciones obsoletas "--pinfo" y "--rto-req" representan el uso anterior. Esta opción debe usarse en su lugar. Consulte la sección INFORMACIÓN DE PROTECCIÓN a continuación para obtener más información.
-F, --format
emite uno de los tres comandos SCSI de "formato". En ausencia de las opciones --preset=ID y --tape=FM, se emite el comando SCSI FORMAT UNIT. Estos comandos destruirán todos los datos contenidos en el medio. Esta opción es necesaria para cambiar el tamaño del bloque de un disco. En ausencia de la opción --quick, se le da al usuario una cuenta regresiva de 15 segundos para reflexionar sobre la conveniencia de hacer esto, durante el cual se puede usar control-C (entre otros comandos de Unix) para matar este proceso antes de que cause algún daño.
Cuando se usa tres veces (o más), se omiten los comandos preliminares MODE SENSE y SELECT, dejando solo los comandos INQUIRY y FORMAT UNIT iniciales. Esto es para uso de emergencia (por ejemplo, cuando los comandos MODE SENSE/SELECT no funcionan) y no puede cambiar el tamaño del bloque lógico.
Los dispositivos con zonas administradas por host (por ejemplo, muchos discos con zonas) tienen un PDT diferente en comparación con otros discos, pero aún pueden formatearse como si fueran discos 'normales'.
Consulte la sección NOTAS para obtener detalles de implementación y la sección EJEMPLOS para uso típico.
-h, --help
imprime la información de uso y luego sale.
-I, --ip-def
establece el patrón de inicialización predeterminado. Algunos discos (SSD) utilizan esto para indicar que un formato debe aprovisionarse completamente (es decir, asociar un bloque físico con cada bloque lógico). Los mismos discos (SSD) pueden aprovisionar de forma delgada si esta opción no se proporciona. Si se proporciona esta opción, la opción --security no puede proporcionarse. También acepta --ip_def para esta opción.
-l, --long
la acción predeterminada de esta utilidad es asumir direcciones de bloque lógico de 32 bits. Con un tamaño de bloque de 512 bytes, esto permite más de 2 terabytes (casi 2 ** 41 bytes) en un solo disco. Esta opción selecciona comandos y parámetros que permiten direcciones de bloque lógico de 64 bits. Específicamente, esta opción establece el indicador "longlba" en el comando MODE SENSE (10) y utiliza READ CAPACITY (16) en lugar de READ CAPACITY (10). Si esta opción no se proporciona y READ CAPACITY (10) o MODE SELECT detectan un disco que necesita más de 32 bits para representar sus bloques lógicos, entonces se establece internamente. Esta opción no establece el bit LONGLIST en el comando FORMAT UNIT. El bit LONGLIST se establece según sea necesario dependiendo de otros parámetros (por ejemplo, cuando '--pie=PIE' es mayor que cero).
-M, --mode=MP
MP es un número de página de modo (de 0 a 62 inclusive) que se utilizará para leer y quizás cambiar el tamaño del bloque lógico del dispositivo. El valor predeterminado es 1, que es la página de modo de recuperación de errores de lectura/escritura.
Preferiblemente, la página de modo elegida (o predeterminada) debe ser guardable (es decir, aceptar el bit SP establecido en el comando MODE SELECT utilizado cuando se cambia el tamaño del bloque lógico). Las versiones recientes de esta utilidad reintentarán un MODE SELECT si la variante SP=1 falla con una clave de sentido de SOLICITUD ILEGAL. Ese reintento utilizará el mismo comando MODE SELECT pero con SP=0.
-P, --pfu=PFU
establece el campo "Protection Field Usage" (Uso del campo de protección) en el bloque de parámetros asociado con un comando FORMAT UNIT a PFU. El valor predeterminado es 0; el único otro valor definido actualmente es 1. Consulte la sección INFORMACIÓN DE PROTECCIÓN a continuación para obtener más información.
-q, --pie=PIE
establece el campo "Protection Interval Exponent" (Exponente del intervalo de protección) en el bloque de parámetros asociado con un comando FORMAT UNIT a PIE. El valor predeterminado es 0. PIE solo puede ser distinto de cero con los tipos de protección 2 y 3. El valor de 0 es típico para bloques de 512 bytes; con bloques de 4096 bytes, un valor de 3 puede ser apropiado (es decir, 8 intervalos de protección intercalados con 4096 bytes de datos de usuario). Es posible que un dispositivo no admita ningún valor distinto de cero. Este campo apareció por primera vez en SBC-3 revisión 18.
-p, --pinfo
esta opción está obsoleta, utilice la opción --fmtpinfo=FPI en su lugar. Si se utiliza, establece el bit 7 del byte 1 en el CDB FORMAT UNIT y eso es equivalente a establecer --fmtpinfo=2. [Por lo tanto, si se usa --pinfo (además de no proporcionar --fmtpinfo=FPI y --pfu=PFU o si sus argumentos son 0), entonces se selecciona el tipo de protección 1.]
-x, --poll=PT
donde PT es el tipo de sondeo utilizado. Si PT es 0, se utiliza un comando TEST UNIT READY; de lo contrario, se utiliza un comando REQUEST SENSE. El valor predeterminado es actualmente 0, pero esto cambiará a 1 en un futuro próximo. Consulte las secciones NOTAS a continuación.
-E, --preset=ID
esta opción indica a esta utilidad que emita un comando SCSI FORMAT WITH PRESET. El campo PRESET IDENTIFIER en ese CDB se establece en ID. El campo IMMED en ese CDB también se establece a menos que la opción --wait también se proporcione, en cuyo caso se borra.
-Q, --quick
la acción predeterminada (es decir, cuando no se proporciona la opción) es darle al usuario 15 segundos para reconsiderar la realización de una operación de formato en el DEVICE. Cuando se proporciona esta opción, ese paso (es decir, el período de advertencia de 15 segundos) se omite.
-r, --resize
en lugar de formatear el disco, se puede cambiar su tamaño. Esto significa cambiar el número de bloques en el dispositivo reportado por el comando READ CAPACITY. Esta opción debe usarse con la opción --count=COUNT. El contenido de todos los bloques lógicos en el medio permanece sin cambios cuando se usa esta opción. Esto significa que cualquier operación de redimensionamiento se puede revertir. Esta opción no se puede usar junto con --format o un --size=LB_SZ cuyo argumento sea diferente al tamaño de bloque existente.
-R, --rto_req
La opción está obsoleta, utilice la opción --fmtpinfo=FPI en su lugar. Si se utiliza, establece el bit 6 del byte 1 en el CDB FORMAT UNIT.
-S, --security
establece el bit "Security Initialization" (SI) en el descriptor del patrón de inicialización del comando FORMAT UNIT dentro de la lista de parámetros. Según SBC-3, el patrón de inicialización predeterminado "deberá escribirse utilizando una técnica de escritura de borrado de seguridad". Consulte la sección NOTAS sobre el comando SCSI SANITIZE. Si se proporciona esta opción, la opción --ip_def no puede proporcionarse.
-6, --six
Utiliza variantes de 6 bytes de MODE SENSE y MODE SELECT. La acción predeterminada es utilizar variantes de 10 bytes. Algunas unidades MO necesitan esta opción establecida al realizar un formato.
-s, --size=LB_SZ
donde LB_SZ es el tamaño del bloque lógico (es decir, el número de bytes de usuario en cada bloque) al que se formateará el dispositivo. El valor predeterminado es el que se informa actualmente en el descriptor de bloque de un comando MODE SENSE. Si el tamaño del bloque proporcionado por esta opción es diferente del valor actual, se utiliza un comando MODE SELECT para cambiarlo antes de que se inicie el comando FORMAT UNIT (como se recomienda en los estándares SBC). Algunos discos SCSI tienen bloques lógicos de 512 bytes por defecto y permiten un tamaño de bloque lógico alternativo de 4096 bytes. Si el tamaño dado no es aceptable para el disco, lo más probable es que aparezca un mensaje de "Campo inválido en la lista de parámetros" en los datos de sentido (requiere el uso de '-v' para decodificar los datos de sentido).
Tenga en cuenta que formatear un disco para agregar o eliminar información de protección no se considera un cambio en su tamaño de bloque lógico, por lo que esta opción no debe usarse.
-T, --tape=FM
enviará un comando FORMAT MEDIUM al DEVICE con su campo FORMAT establecido en FM. Esta opción se utiliza para preparar un cinta (es decir, el "medio") en una unidad de cinta para su uso. Los valores para FM incluyen 0 para hacer el formato "predeterminado"; 1 para particionar un volumen y 2 para hacer un formato predeterminado y luego particionar.
-m, --timeout=SECS
donde SECS es el tiempo de espera en segundos para el comando FORMAT UNIT, FORMAT WITH PRESET o FORMAT MEDIUM. SECS solo se utilizará si excede el tiempo de espera interno que es de 20 segundos si el bit IMMED está establecido y 72000 segundos (20 horas) o más si el bit IMMED no está establecido. Si el tamaño del disco excede las 4 TB, el valor del tiempo de espera aumenta a 144000 segundos (40 horas). Y si es mayor a 8 TB, el valor del tiempo de espera aumenta a 288000 segundos (80 horas). Si se excede el tiempo de espera, el sistema operativo normalmente cancelará el comando. Cancelar un comando puede escalar a un reinicio de LUN (o algo peor). Un tiempo de espera también puede dejar la operación de formato del disco o de la cinta incompleta. Y eso puede resultar en que el disco o la cinta estén en un estado de "formato corrupto" que requiere otro formato para remediar la situación. Por lo tanto, por varias razones, es mejor evitar los tiempos de espera de los comandos. Una forma alternativa de opción larga es --tmo=SECS.
-v, --verbose
aumentar el nivel de verbosidad, (es decir, salida de depuración). "-vvv" da mucha más salida de depuración.
-y, --verify
establecer el bit VERIFY en el cdb de FORMAT MEDIUM. El valor predeterminado es que el bit VERIFY está borrado. Esta opción solo es apropiada para cintas.
-V, --version
imprimir la cadena de versión y luego salir.
-w, --wait
la acción de formato predeterminada es establecer el bit "IMMED" en la cabecera de parámetros (corta) del comando FORMAT UNIT. Si se proporciona esta opción (es decir, --wait), el bit "IMMED" no se establece. Si se proporciona --wait, el comando FORMAT UNIT, FORMAT WITH PRESET o FORMAT MEDIUM espera hasta que la operación de formato se complete antes de devolver su respuesta. Esto puede llevar muchas horas en discos grandes. Ver la opción --timeout=SECS.
Alternativamente, esta opción puede ser útil cuando se usa junto con --ffmt=FFMT (y FFMT mayor que 0), ya que el formato rápido puede ser solo cuestión de segundos.

LISTAS

El borrador SBC-3 (revisión 20) define PLIST, CLIST, DLIST y GLIST en la sección 4.10 sobre "defectos del medio". Brevemente, PLIST es la lista "primaria" de defectos detectados por el fabricante, CLIST (lista de "certificación") contiene aquellos detectados durante la operación de formato, DLIST es una lista de defectos que se pueden dar a la operación de formato. GLIST es la lista de crecimiento que comienza en el proceso de formato como CLIST+DLIST y puede "crecer" más tarde debido a la reasignación automática (ver los bits ARRE y AWRE en la página de modo de recuperación de errores de lectura/escritura (ver sdparm(8))) y el uso del comando SCSI REASSIGN BLOCKS (ver sg_reassign(8)).

Según el estándar SBC-3 (siguiendo el borrador de la revisión 36), CLIST y DLIST se eliminaron, quedando PLIST y GLIST. Solo PLIST y GLIST se encuentran en los borradores de SBC-4.

El bit CMPLST (controlado por la opción --cmplst=0|1) determina si la GLIST existente, cuando se invoca la operación de formato, se tiene en cuenta. La utilidad sg_format establece el bit FOV a cero, lo que provoca DPRY=0, por lo que se tiene en cuenta PLIST, y DCRT=0, por lo que CLIST se genera y se utiliza durante el proceso de formato.

La utilidad sg_format no permite al usuario proporcionar una lista de defectos (es decir, DLIST).

INFORMACIÓN DE PROTECCIÓN

La Información de Protección (PI) es información adicional que se mantiene con los bloques lógicos para que una aplicación y/o el adaptador del bus host puedan verificar la corrección de esos bloques lógicos. La PI se coloca en uno o más intervalos de protección intercalados en cada bloque lógico. Cada intervalo de protección sigue a los datos del usuario a los que se refiere. Un intervalo de protección contiene 8 bytes compuestos por un "guardián de bloque lógico" de 2 bytes (CRC), un "guardián de aplicación de bloque lógico" de 2 bytes y una "etiqueta de referencia de bloque lógico" de 4 bytes. Los dispositivos con un tamaño de bloque lógico de 512 bytes suelen tener un intervalo de protección añadido, lo que hace que sus datos de bloque lógico tengan 520 bytes. Los dispositivos con un tamaño de bloque lógico de 4096 bytes suelen tener 8 intervalos de protección distribuidos en sus datos de bloque lógico para un tamaño total de 4160 bytes. Tenga en cuenta que para todos los demás propósitos, el tamaño del bloque lógico se considera 512 y 4096 bytes respectivamente.

El estándar SBC-3 ha añadido varios "tipos de protección" a la PI introducida en el estándar SBC-2. SBC-3 define 4 tipos de protección (tipos 0 a 3), donde el tipo de protección 0 significa que no se mantiene PI. Si bien un dispositivo puede admitir uno o más tipos de protección, solo se puede formatear con 1 de los 4. Para cambiar el tipo de protección de un dispositivo, debe ser reformatado. Para más información, consulte la Información de Protección en la sección 4.21 del borrador SBC-4 revisión 16.

Un dispositivo que admite información PI (es decir, admite uno o más tipos de protección 1, 2 y 3) establece el bit "PROTECT" en su respuesta INQUIRY estándar. También establece el campo SPT en la respuesta de la página VPD EXTENDED INQUIRY para indicar qué tipos de protección admite. Dado PROTECT=1, SPT=0 implica que el dispositivo admite solo el tipo de PI 1, SPT=1 implica que el dispositivo admite los tipos de PI 1 y 2, y varias otras asignaciones no obvias hasta SPT=7, que implica que se admiten los tipos de protección 1, 2 y 3. El tipo de protección *actual* de un disco se puede encontrar en los campos "P_TYPE" y "PROT_EN" en la respuesta de un comando READ CAPACITY (16) (por ejemplo, con la utilidad 'sg_readcap --long').

Dado que un dispositivo admite un tipo de protección particular, un usuario puede entonces optar por formatear ese disco con ese tipo de protección estableciendo los campos "FMTPINFO" y "Protection Field Usage" en el comando FORMAT UNIT. Esos campos corresponden a las opciones --fmtpinfo=FPI y --pfu=PFU en esta utilidad. La siguiente lista muestra los cuatro tipos de protección seguidos de las opciones de esta utilidad necesarias para seleccionarlos:
0 : --fmtpinfo=0 --pfu=0
1 : --fmtpinfo=2 --pfu=0
2 : --fmtpinfo=3 --pfu=0
3 : --fmtpinfo=3 --pfu=1
El valor predeterminado de FPI (en --fmtpinfo=FPI) es 0 y el valor predeterminado de PFU (en --pfu=PFU) es 0. Por lo tanto, si no se proporcionan ni --fmtpinfo=FPI ni --pfu=PFU, se elige el tipo de protección 0 (es decir, sin información de protección).

NOTAS

Después de un formato que cambia el tamaño del bloque lógico o el número de bloques lógicos en un disco, es posible que sea necesario indicar al sistema operativo que reinicialice su configuración para ese disco. En Linux, eso se puede hacer con:
echo 1 > /sys/block/sd{letra(s)}/device/rescan
donde "letra(s)" estará entre 'a' y 'zzz'. La utilidad lsscsi en Linux se puede usar para verificar los diversos nombres de un disco.

El estándar SBC-2 establece que el comando REQUEST SENSE debe usarse para obtener indicación de progreso cuando el comando de formato está en curso. Sin embargo, las pruebas en una selección de discos muestran que los comandos TEST UNIT READY proporcionan indicaciones de progreso (pero no los comandos REQUEST SENSE). Por lo tanto, la versión actual de esta utilidad usa por defecto comandos TEST UNIT READY para encuestar el disco y conocer el progreso del formato. La opción --poll=PT se ha añadido para controlar esto.

Cuando se proporciona la opción --format, --preset=ID o --tape=FM sin la opción --wait, el comando SCSI correspondiente se emite con el bit IMMED establecido, lo que hace que el comando SCSI regrese después de haber iniciado la operación de formato. La opción --early hará que sg_format salga en ese punto. De lo contrario, el DEVICE se encuestará cada 60 segundos o cada 10 segundos si FFMT es distinto de cero. La encuesta se realiza con comandos TEST UNIT READY o REQUEST SENSE hasta que uno informe "todo claro" (es decir, la operación de formato ha completado). Normalmente, estos comandos de encuesta resultarán en una indicación de progreso (expresada como un porcentaje) que se mostrará en la pantalla. Si el usuario se aburre mirando el informe de progreso, el proceso de sg_format se puede terminar (por ejemplo, con control-C) sin afectar la operación de formato que continúa. Sin embargo, un reinicio del destino o del dispositivo (o un ciclo de energía) probablemente hará que el formato se detenga y que el DEVICE quede en estado de "formato corrupto".

Cuando las opciones --format (--preset=ID o --tape) y --wait se proporcionan ambas, esta utilidad puede tardar mucho en devolver el control. En este caso, se debe tener cuidado de no enviar ningún otro comando SCSI al disco, ya que es posible que no responda, dejando esos comandos en cola detrás del comando de formato activo. Esto puede causar un tiempo de espera en el controlador del SO (en un período mucho más corto que las 20 horas aplicables a algunas operaciones de formato). Esto puede resultar en que el SO reinicie el disco, dejando la operación de formato incompleta. Esto puede dejar el disco en un estado de "formato corrupto" que requiere otro formato para remediar la situación. Los dispositivos SCSI modernos deberían generar una clave de sentido de "no listo" con un sentido adicional que indique que se está realizando un formato. Con dispositivos más antiguos, el usuario debe tomar precauciones para que nada intente acceder a un dispositivo mientras se está formateando. Se recomienda encarecidamente desmontar los sistemas de archivos montados en un DEVICE antes de llamar a esta utilidad.

Cuando el tamaño del bloque (es decir, el número de bytes en cada bloque) se cambia en un disco, se deben enviar dos comandos SCSI: un MODE SELECT para cambiar el tamaño del bloque seguido de un comando FORMAT. Si el comando MODE SELECT tiene éxito y el FORMAT falla, el disco puede estar en un estado que el estándar denomina "formato corrupto". Un descriptor de bloque en un MODE SENSE posterior informará el nuevo tamaño de bloque solicitado, mientras que un comando READ CAPACITY informará el tamaño de bloque existente (es decir, anterior). Alternativamente, el comando READ CAPACITY puede fallar, informando que el dispositivo no está listo, lo que podría requerir un formato. La solución a esta situación es realizar un formato nuevamente (y esta vez el nuevo tamaño de bloque no tiene que proporcionarse) o cambiar el tamaño del bloque al tamaño original.

El estándar SBC-2 establece que el recuento de bloques se puede restablecer al valor máximo recomendado por el fabricante en una operación de formato o redimensionamiento. Esto se puede hacer colocando una dirección de 0xffffffff (o su equivalente de 64 bits) en el campo del descriptor de bloque apropiado en un comando MODE SELECT. I

CINTA

Los sistemas de cinta usan una variante del comando FORMAT UNIT utilizado en discos. Los sistemas de cinta usan el comando FORMAT MEDIUM, que es más simple y típicamente utiliza solo tres campos en el cdb. Aparte de compartir el mismo opcode, los cdbs de FORMAT UNIT y FORMAT MEDIUM son bastante diferentes. Los campos de FORMAT MEDIUM son VERIFY, IMMED y FORMAT (con TRANSFER LENGTH siempre establecido en 0). El campo de bits VERIFY se establece con la opción --verify. El bit IMMED se manipula con la opción --wait de la misma manera que para los discos; una diferencia es que si no se proporciona la opción --poll=PT, entonces, por defecto, PT es 1, lo que significa que el sondeo se realiza con comandos REQUEST SENSE.

El argumento proporcionado a la opción --tape=FM se utiliza para establecer el campo FORMAT. FM puede tomar valores de "-1" a "15", donde "-1" (el valor predeterminado) significa no realizar un formato de cinta; los valores "8" a "15" son para formatos específicos del proveedor. La opción --early también se puede utilizar para establecer el bit IMMED y luego salir de esta utilidad (en lugar de sondear periódicamente hasta que finalice). En este caso, la unidad de cinta seguirá ocupada realizando el formato durante algún tiempo, pero, según T10, aún debería responder completamente a los comandos INQUIRY y REPORT LUNS. Otros comandos (incluido REQUEST SENSE) deberían generar una clave de sentido "no listo" con un código de sentido adicional de "Unidad lógica no lista, formato en progreso". Además, REQUEST SENSE debería contener una indicación de progreso en sus datos de sentido.

Cuando FM es 1 o 2, la configuración de la página de modo de partición del medio controla el particionamiento. Esa página de modo se puede ver y modificar con la utilidad sdparm.

Antes de invocar esta utilidad, puede ser necesario posicionar la cinta al principio de la partición 0. En Linux, eso generalmente se puede hacer con la utilidad mt (por ejemplo, 'mt -f /dev/st0 rewind').

EJEMPLOS

Estos ejemplos utilizan nombres de dispositivos de Linux. Para nombres de dispositivos adecuados en otros sistemas operativos compatibles, consulte la página del manual sg3_utils(8).

En el primer ejemplo a continuación, simplemente se encuentra el recuento de bloques existente y el tamaño derivado de dos fuentes: un descriptor de bloque en una respuesta al comando MODE SELECT y de la respuesta de los comandos READ CAPACITY. No se realizan cambios:


# sg_format /dev/sdm

Ahora, un formato simple, dejando el recuento y el tamaño de los bloques como estaban anteriormente. El comando FORMAT UNIT se ejecuta en modo IMMED y el dispositivo se sondea cada 60 segundos para imprimir una indicación de progreso:


# sg_format --format /dev/sdm

Ahora el mismo formato, pero esperando (pasivamente) hasta que la operación de formato se complete:


# sg_format --format --wait /dev/sdm

A continuación, se muestra un formato en el que el tamaño del bloque se cambia a 520 bytes y el recuento de bloques se establece en el valor máximo del fabricante (para ese tamaño de bloque). Nota: no todos los discos admiten el cambio del tamaño del bloque:


# sg_format --format --size=520 /dev/sdm

Ahora, una operación de redimensionamiento para que solo los primeros 0x10000 (65536) bloques de un disco sean accesibles. Los bloques restantes permanecen inalterados.


# sg_format --resize --count=0x10000 /dev/sdm

Ahora, redimensione el disco de nuevo a su recuento de bloques normal (máximo):


# sg_format --resize --count=-1 /dev/sdm

Una razón para formatear un disco SCSI es agregar información de protección. Primero, verifique qué tipos de protección son compatibles con un disco (verificando el campo SPT en la página VPD de Extended inquiry junto con el bit Protect en la respuesta de inquiry estándar):


# sg_vpd -p ei -l /dev/sdb
página VPD de datos INQUIRY extendida:
ACTIVATE_MICROCODE=0
SPT=1 [tipos de protección 1 y 2 compatibles]
....

Formato con protección de tipo 1:


# sg_format --format --fmtpinfo=2 /dev/sdm

Después de un formato exitoso con protección de tipo 1, READ CAPACITY(16) debería mostrar algo como esto:


# sg_readcap -l /dev/sdm
Resultados de Read Capacity:
Protección: prot_en=1, p_type=0, p_i_exponent=0 [protección de tipo 1]
Aprovisionamiento de bloques lógicos: lbpme=0, lbprz=0
....

Para formatear con protección de tipo 3:


# sg_format --format --fmtpinfo=3 --pfu=1 /dev/sdm

Para el disco que se muestra arriba, esto probablemente fallará porque la página VPD de Extended inquiry solo mostró que se admiten los tipos de protección 1 y 2.

Aquí hay ejemplos de uso del formato rápido (campo FFMT en el cdb FORMAT UNIT) para cambiar rápidamente entre tamaños de bloque lógico de 512 y 4096 bytes. Suponga que el disco comienza con un tamaño de bloque lógico de 4096 bytes y se han respaldado todos los datos importantes.


# sg_format --format --ffmt=1 --size=512 /dev/sdd

Ahora /dev/sdd debería tener un tamaño de bloque lógico de 512 bytes. Y para cambiarlo de nuevo:


# sg_format --format --ffmt=1 --size=4096 /dev/sdd

Dado que los formatos rápidos pueden ser muy rápidos (cuestión de segundos), puede ser apropiado usar la opción --wait.

Y para usar el comando Format with preset, se podría usar esta invocación:


# sg_format --preset=1 --fmtmaxlba /dev/sdd

Se debe consultar la página VPD de FORMAT PRESETS (0xb8) para verificar que el identificador Preset 0x1 está allí y tiene el formato esperado (es decir, "modelo de dispositivo de bloque zonificado controlado por host predeterminado con 512 bytes de datos de usuario en cada bloque lógico"). Esa página VPD se puede ver con la utilidad sg_vpd.

ESTADO DE SALIDA

El estado de salida de sg_format es 0 cuando tiene éxito. De lo contrario, consulte la página del manual sg3_utils(8). A menos que se proporcione la opción --wait, el estado de salida puede no reflejar el éxito o no del formato. Puede ser prudente usar sg_turs(8) y sg_readcap(8) después de la operación de formato.

La convención de Unix es que "no news is good news" (sin noticias son buenas noticias), pero eso puede ser un poco desconcertante después de una operación como el formato, especialmente si finaliza rápidamente (es decir, antes de que se envíe el primer sondeo de progreso). Proporcionar la opción --verbose una vez debería proporcionar suficiente información adicional para calmar esos nervios.
