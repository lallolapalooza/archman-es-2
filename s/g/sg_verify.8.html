Paquete: sg3_utils

NOMBRE

sg_verify - invoca comandos SCSI VERIFY (verificar) en un dispositivo de bloques

SINOPSIS

sg_verify [--0] [--16] [--bpc=BPC] [--count=COUNT] [--dpo] [--ff] [--ebytchk=BCH] [--group=GN] [--help] [--in=IF] [--lba=LBA] [--ndo=NDO] [--quiet] [--readonly] [--verbose] [--version] [--vrprotect=VRP] DISPOSITIVO

DESCRIPCIÓN

Envía uno o más comandos SCSI VERIFY (10 o 16) al DISPOSITIVO. Estos comandos SCSI están definidos en los estándares SBC-2 y SBC-3 en https://www.t10.org y en los borradores de SBC-4.

Cuando no se proporciona --ndo=NDO, la verificación comienza en la dirección de bloque lógico dada por la opción --lba=LBA y continúa para --count=COUNT bloques. No se verifican más de --bpc=BPC bloques por cada comando VERIFY, por lo que si es necesario, se envían múltiples comandos VERIFY. Las operaciones de verificación del medio son realizadas por el DISPOSITIVO (por ejemplo, asumiendo que cada bloque tiene datos EEC adicionales, compruebe esto con el contenido de los bloques lógicos). No recibir noticias es una buena noticia (es decir, si no se detectan errores de verificación, no se envían mensajes a stderr y el estado de salida de Unix es 0).

Cuando se proporciona --ndo=NDO, se ignora la opción --bpc=BPC. Se emite un único comando VERIFY y una comparación comienza en la dirección de bloque lógico dada por la opción --lba=LBA y continúa para --count=COUNT bloques. El comando VERIFY tiene un buffer de salida de datos asociado que tiene una longitud de NDO bytes. El contenido del buffer de salida de datos se obtiene del archivo FN (si se proporciona --in=FN) o de stdin. Se realiza una comparación entre el buffer de salida de datos y los bloques lógicos en el DISPOSITIVO. Si la comparación es correcta, no se envían mensajes a stderr y el estado de salida de Unix es 0. Si la comparación falla, se devuelve un buffer de sentido (sense buffer) con una clave de sentido (sense key) de MISCOMPARE; en este caso, el estado de salida de Unix será 14. Se enviarán mensajes a stderr asociados con el buffer de sentido MISCOMPARE a menos que se proporcione la opción --quiet.

En la revisión 34 de SBC-3, el campo BYTCHK en todos los comandos SCSI VERIFY se expandió de uno a dos bits. Esto requirió algunos cambios en las opciones de esta utilidad, consulte la sección a continuación sobre CAMBIOS EN LAS OPCIONES.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas. Las opciones están ordenadas alfabéticamente según el nombre de la opción larga.

-0, --0
se envía un buffer de NDO bytes lleno de ceros como parte de salida de datos de un comando VERIFY. Por lo tanto, no se lee stdin y si se proporciona --in=IF, se genera un error. Útil cuando BCH es 3 para comprobar si parte o todo el DISPOSITIVO (por ejemplo, un disco) está lleno de bloques de ceros.
-S, --16
utiliza un comando VERIFY(16) (el valor predeterminado es VERIFY(10)). Incluso sin esta opción, usar un --lba=LBA demasiado grande hará que la utilidad emita un comando VERIFY(16).
-b, --bpc=BPC
esta opción se ignora si se proporciona --ndo=NDO. De lo contrario, BPC especifica el número máximo de bloques que se verificarán con un único comando SCSI VERIFY. El valor predeterminado es 128 bloques, lo que equivale a 64 KB para un disco con bloques de 512 bytes. Si BPC es menor que COUNT, se envían múltiples comandos SCSI VERIFY al DISPOSITIVO. Para el VERIFY(10) predeterminado, BPC no puede exceder 0xffff (65.535), mientras que para VERIFY(16), BPC no puede exceder 0x7fffffff (2.147.483.647). Para dispositivos de bloques recientes (discos), este valor puede estar limitado por el campo de longitud máxima de transferencia en la página VPD de límites de bloques.
-c, --count=COUNT
donde COUNT especifica el número de bloques a verificar. El valor predeterminado es 1. Si COUNT es mayor que BPC (o su valor predeterminado de 128) y no se proporciona NDO, se envían cero o múltiples comandos SCSI VERIFY al dispositivo. De lo contrario, COUNT se convierte en el contenido del campo de longitud de verificación del comando SCSI VERIFY emitido. La utilidad sg_readcap se puede usar para encontrar el número máximo de bloques que tiene un dispositivo de bloques (por ejemplo, un disco).
-d, --dpo
disable page out (desactivar página de salida) cambia la prioridad de retención de caché de los bloques leídos en la caché del dispositivo a la prioridad más baja. Esto significa que es más probable que los bloques leídos por otros comandos permanezcan en la caché del dispositivo.
-E, --ebytchk=BCH
establece el campo BYTCHK en BCH, anulando el valor (1) establecido por la opción --ndo=NDO. Se aceptan los valores 1, 2 o 3 para BCH, sin embargo, sbc3r34 reserva el valor 2. Si se proporciona esta opción, también se debe proporcionar --ndo=NDO. Si BCH es 3, NDO debe ser el tamaño de un bloque lógico (más el tamaño de parte o toda la información de protección si VRP es mayor que 0).
-f, --ff
se envía un buffer de NDO bytes lleno de bytes 0xff como parte de salida de datos de un comando VERIFY. Por lo tanto, no se lee stdin y si se proporciona --in=IF, se genera un error. Útil cuando BCH es 3 para comprobar si parte o todo el DISPOSITIVO (por ejemplo, un disco) está lleno de bloques de bytes 0xff.
-g, --group=GN
donde GN se convierte en el contenido del campo de número de grupo en el comando SCSI VERIFY(16). Puede ser de 0 a 63 inclusive. El valor predeterminado para GN es 0. Tenga en cuenta que esta opción se ignora para el comando SCSI VERIFY(10).
-h, --help
muestra el mensaje de uso y luego sale.
-i, --in=IF
donde IF es el nombre de un archivo del cual se leerán NDO bytes y se colocarán en el buffer de salida de datos. Esto solo se hace cuando se proporciona la opción --ndo=NDO. Si no se proporciona esta opción, se lee stdin. Si IF es "-", también se usa stdin.
-l, --lba=LBA
donde LBA especifica la dirección de bloque lógico del primer bloque para iniciar la operación de verificación. Se asume que LBA está en decimal a menos que esté prefijado por '0x' o una 'h' al final (ver más abajo). El valor predeterminado es 0 (es decir, el inicio del dispositivo).
-n, --ndo=NDO
NDO es el número de bytes que se obtendrán del archivo FN (si se proporciona --in=FN) o de stdin. Esos bytes se colocarán en el buffer de salida de datos asociado con el comando SCSI VERIFY y NDO se colocará en el campo de longitud de verificación en el cdb. El valor predeterminado para NDO es 0 y el valor máximo depende del SO. Si la opción --ebytchk=BCH no se proporciona, el campo BYTCHK en el cdb se establece en 1.
-q, --quiet
suprime los mensajes del buffer de sentido asociados con una clave de sentido MISCOMPARE que de otro modo se enviarían a stderr. Aún así establece el estado de salida a 14, que es el valor de la clave de sentido que indica un MISCOMPARE.
-r, --readonly
abre el DISPOSITIVO en modo de solo lectura en lugar de lectura-escritura, que es el valor predeterminado. El controlador sg de Linux necesita acceso de lectura-escritura para el comando SCSI VERIFY, pero otros métodos de acceso pueden requerir acceso de solo lectura.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración).
-V, --version
imprime la cadena de versión y luego sale.
-P, --vrprotect=VRP
donde VRP es el valor en el campo vrprotect del cdb del comando VERIFY. Debe ser un valor entre 0 y 7 inclusive. El valor predeterminado es cero.

BYTCHK

BYTCHK es el nombre de un campo (de dos bits de ancho) en los comandos VERIFY(10) y VERIFY(16). Cuando se establece en 1 o 3 (sbc3r34 reserva el valor 2), indica que asociado con el comando SCSI VERIFY, se enviará un buffer de salida de datos para que el dispositivo (disco) lo verifique. El uso de la opción --ndo=NDO establece el campo BYTCHK en 1 y NDO es el número

número de bytes colocados en el búfer de datos de salida. Esos bytes se obtienen de stdin o SI (de la opción --in=FN). La opción --ebytchk=BCH puede usarse para anular el valor del campo BYTCHK de 1 con BCH.

El cálculo de NDO queda a cargo del usuario. Su valor depende del tamaño lógico del bloque (que se puede encontrar con la utilidad sg_readcap), del COUNT y de los valores VRP. Si el VRP es mayor que 0, entonces cada bloque lógico contendrá 8 bytes adicionales (al menos) de información de protección.

Cuando el campo BYTCHK es 0, el proceso de verificación realizado por el dispositivo (disco) es específico del proveedor. Típicamente implica comprobar cada bloque en el disco contra sus códigos de corrección de errores (ECC), que son datos adicionales que también se encuentran en el disco.

Muchos sistemas operativos imponen límites al tamaño máximo del búfer de datos de salida (y de entrada). En Linux, en un momento dado, el límite era inferior a 1 MB, pero ha aumentado algo.

CAMBIOS DE OPCIÓN

Las versiones anteriores de esta utilidad tenían una opción --bytchk=NDO que establecía el bit BYTCHK y el campo de longitud de verificación del cdb a NDO. La forma más corta de esa opción era -B NDO. Para compatibilidad hacia atrás, esa opción todavía está presente, pero no se documenta. En su lugar está la opción --ndo=NDO, cuya forma corta es -n NDO. --ndo=NDO establece el campo BYTCHK en 1, a menos que se anule con la opción --ebytchk=BCH.

NOTAS

Varios argumentos numéricos (por ejemplo, LBA) pueden incluir sufijos multiplicadores o darse en hexadecimal. Consulte la sección "ARGUMENTOS NUMÉRICOS" en la página del manual sg3_utils(8).

La cantidad de corrección de errores y el número de reintentos intentados antes de que un bloque se considere defectuoso se controlan en parte mediante la página de modo de recuperación de errores de verificación. Una nota en el borrador de SBC-3 (rev 29, sección 6.4.9 sobre la página de modo de recuperación de errores de verificación) aconseja que, para minimizar el número de comprobaciones (y, por lo tanto, tener la comprobación de verificación más "sensible"), se haga lo siguiente en esa página de modo: establecer el bit EER en 0, el bit PER en 1, el bit DTE en 1, el bit DCR en 1, el recuento de reintentos de verificación en 0 y el límite de tiempo de recuperación de verificación en 0. Las páginas de modo se pueden modificar con la utilidad sdparm.

El comando SCSI VERIFY(6) definido en el estándar SSC-2 y posteriores (es decir, para sistemas de unidades de cinta) no es compatible con esta utilidad.

ESTADO DE SALIDA

El estado de salida de sg_verify es 0 cuando es exitoso. Cuando BCH es distinto de 0, se realiza una comparación y si falla, el estado de salida es 14, que casualmente es el valor de la clave de sentido MISCOMPARE. De lo contrario, consulte la sección ESTADO DE SALIDA en la página del manual sg3_utils(8).

Las versiones anteriores de esta utilidad establecían un estado de salida de 98 cuando había una MISCOMPARE.
