NOMBRE

sg_luns - enviar comando SCSI REPORT LUNS o decodificar LUN dado

SINOPSIS

sg_luns [--decodificar] [--ayuda] [--hex] [--enhex=FN] [--hex-interno] [--json[=JO]] [--archivo-js=JFN] [--linux] [--lu_cong] [--maxlen=LEN] [--silencioso] [--crudo] [--sololec] [--seleccionar=SR] [--sinq_enraw=RFN] [--verbose] [--version] DISPOSITIVO

sg_luns --test=ALUN [--decodificar] [--hex] [--hex-interno] [--lu_cong] [--verbose]

DESCRIPCIÓN

En la primera forma mostrada en la SINOPSIS, esta utilidad envía el comando SCSI REPORT LUNS al DISPOSITIVO y muestra la respuesta. La respuesta debe ser una lista de LUNs ("un inventario de LUNs") para el nexo I_T asociado con el DISPOSITIVO. Aproximadamente hablando, son todos los LUNs que comparten el dispositivo de destino a través del cual se envía el comando REPORT LUNS. Este comando está definido en los estándares SCSI SPC-3 y SPC-4 y su soporte es obligatorio. El borrador más reciente es SPC-6 revisión 1.

Cuando se da la opción --test=ALUN (la segunda forma en la SINOPSIS), entonces el valor ALUN se decodifica según se describe en varios estándares del Modelo de Arquitectura SCSI (SAM) y borradores recientes (por ejemplo, SAM-6 revisión 2, sección 4.7).

Donde sea necesario abajo, la primera forma mostrada en la SINOPSIS se llama "modo dispositivo" y la segunda forma se llama "modo prueba".

OPCIONES

Los argumentos para las opciones largas son obligatorios para las opciones cortas también.

-d, --decodificar
decodifica LUNs en sus partes componentes, como se describe en la sección LUN de SAM-3, SAM-4 y SAM-5.
[modo de prueba] ALUN se decodifica independientemente de si esta opción se da o no. Si se da esta opción una vez, entonces el ALUN dado se muestra en formato preferido T10 (que son 8 pares de dígitos hexadecimales, cada uno separado por un espacio). Si se da dos veces, entonces el ALUN dado se muestra en un formato T10 alternativo compuesto por cuatro cuádruples de dígitos hexadecimales con cada cuádruple separada por un guión ("-") (por ejemplo, C101-0000-0000-0000).
-h, --ayuda
muestra el mensaje de uso y luego sale.
-H, --hex
[modo de dispositivo] cuando se da una vez, esta utilidad mostrará la respuesta SCSI (es decir, el búfer de datos de salida) al comando REPORT LUNS en hexadecimal ASCII y luego saldrá. Cuando se da dos veces, provoca que --decodificar muestre los campos componentes en hexadecimal en lugar de decimal. Tenga en cuenta que esto (es decir, cómo se procesa '-HH') difiere de la descripción en sg3_utils(8). La opción --hex-interno tiene la misma acción que '-HH'. Cuando esta opción se usa tres (o más) veces, la salida hexadecimal es adecuada para colocarla en un archivo y usarla con una invocación posterior de sg_luns con la opción --enhex=FN.
[modo de prueba] cuando se da esta opción, los campos componentes decodificados de ALUN se muestran en hexadecimal.
Cuando esta opción se da tres o más veces, se muestran bytes hexadecimales ASCII (hasta 16 por línea) sin dirección o índice inicial. Esta salida es adecuada para colocarla en un archivo y usarla posteriormente con esta utilidad decodificándola con la opción --enhex=FN. Cuando esta opción se usa cuatro veces, se agrega una línea de comentario (que comienza con '#') antes de los hexadecimales que describe para qué se generaron los hexadecimales. Un archivo que contenga dichos comentarios aún es analizable con la opción --enhex=FN.
-i, --enhex=FN
FN se espera que sea un nombre de archivo (o '-' para stdin) que contenga hexadecimal ASCII o binario representando una respuesta REPORT LUNS. Esta utilidad decodificará esa respuesta. Consulte la sección "FORMATOS HEXADECIMAL, BINARIO Y JSON" en la página del manual de sg3_utils para más información. Si la opción --crudo también se da, entonces FN se trata como binario.
-I, --hex-interno
se usa junto con la opción --decodificar para que los valores decodificados se muestren en hexadecimal. La acción predeterminada es mostrar los valores decodificados en decimal. Esta opción tiene la misma acción que '-HH', pero la intención es un poco más clara con esta opción.
-j[=JO], --json[=JO]
la salida está en formato JSON en lugar de texto plano. Tenga en cuenta que los argumentos para la forma corta y larga son opcionales y si están presentes comienzan con "=" y no se permite espacio en blanco alrededor de ese "=".
Consulte la página del manual sg3_utils_json o use '?' para JO para obtener un resumen.
-J, --archivo-js=JFN
la salida está en formato JSON y se envía a un archivo llamado JFN. Si ese archivo existe, se trunca. Por defecto, la salida JSON se envía a stdout.
Cuando se da esta opción, la opción --json[=JO] se implica y no es necesario darla. La opción --json[=JO] aún puede ser necesaria para establecer el parámetro JO a valores no predeterminados.
-l, --linux
esta opción solo está disponible en Linux. Después de la representación T10 de cada LUN de 64 bits (en 16 dígitos hexadecimales), si se da esta opción, a la derecha, entre corchetes, está el entero LUN de Linux en decimal. Si la opción --hex se da dos veces (por ejemplo, -HH) también, entonces el entero LUN de Linux se muestra en hexadecimal.
-L, --lu_cong
esta opción solo se considera con --decodificar. Cuando se da una vez, la lista de LUNs se decodifica como si el bit LU_CONG estuviera establecido en la respuesta INQUIRY correspondiente de cada LU. Cuando se da dos veces, la lista de LUNs se decodifica como si el bit LU_CONG estuviera claro en la respuesta INQUIRY correspondiente de cada LU. Cuando esta opción no se da y se da --decodificar, se envía un INQUIRY al DISPOSITIVO y se utiliza el ajuste de su bit LU_CONG para decodificar la lista de LUNs.
[modo de prueba] decodifica ALUN como si el bit LU_CONG estuviera establecido en su respuesta INQUIRY estándar correspondiente. En otras palabras, trata ALUN como si fuera un LUN conglomerado. Si no se da (o se da dos veces), decodifica ALUN como si el bit LU_CONG estuviera claro.
-m, --maxlen=LEN
donde LEN es la longitud (máxima) de respuesta en bytes. Se coloca en el campo "longitud de asignación" del cdb. Si no se da (o LEN es cero), se usa 8192. El valor máximo permitido de LEN es 1048576.
-q, --silencioso
muestra solo la representación hexadecimal ASCII de cada informe LUN, una por línea. Sin la opción --silencioso, hay información de encabezado impresa antes de la lista de LUNs.
-r, --crudo
muestra la respuesta SCSI (es decir, el búfer de datos de salida) en binario (a stdout).
-R, --sololec
abre el DISPOSITIVO en solo lectura (por ejemplo, en Unix con la bandera O_RDONLY). Por defecto, lo abre en lectura-escritura.
-s, --seleccionar=SR
SR se coloca en el campo SELECT REPORT del comando SCSI REPORT LUNS. El valor predeterminado es 0. Los valores hexadecimales pueden darse con un prefijo "0x" o un sufijo "h". Para información detallada, consulte el comando REPORT LUNS en SPC (la más reciente es SPC-4 revisión 37 en la sección 6.33). Para simplificar, para el nexo I_T asociado con el DISPOSITIVO, los significados de los valores SR definidos hasta la fecha para SPC-4 son:
0 : la mayoría de los LUNs excluyendo los números de unidad lógica bien conocidos
1 : números de unidad lógica bien conocidos
2 : todos los LUNs accesibles para este nexo I_T
0x10 : solo LUNs administrativos accesibles
0x11 : LUNs administrativos más LUNs no conglomerados (ver SPC-4)
0x12 : si DISPOSITIVO es un LU administrativo, entonces informe su
LUN más sus LUNs subsidiarios
Para los valores SR 0x10 y 0x11, el DISPOSITIVO debe ser el LUN 0 o la unidad lógica bien conocida de REPORT LUNS. Los valores entre 0xf8 y 0xff (inclusive) son específicos del proveedor, otros valores están reservados. Esta utilidad aceptará cualquier valor entre 0 y 255 (0xff) para SR.
-Q, --sinq_enraw=

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

>=RFN
donde RFN es un nombre de archivo que contiene datos binarios de respuesta INQUIRY estándar que coinciden con DEVICE o FN. Linux coloca esta respuesta INQUIRY estándar en su sistema de archivos pseudo sysfs. Una ubicación típica es en /sys/class/scsi_device/<hctl>/device/inquiry donde <hctl> es una tupla numérica de cuatro partes separada por dos puntos. Esta tupla distingue el dispositivo de cualquier otro en el sistema.
Actualmente, el campo LU_CONG se lee de la respuesta INQUIRY estándar cuando se proporciona esta opción. La opción --raw no tiene ningún efecto en esta opción. El argumento DEVICE se puede proporcionar con esta opción.
-t, --test=ALUN
ALUN se asume que es un número hexadecimal en formato ASCII hexadecimal o la letra 'L' seguida de un número decimal (ver más abajo). El número hexadecimal puede tener hasta 64 bits de tamaño (es decir, 16 dígitos hexadecimales) y se rellena a la derecha si se proporcionan menos de 16 dígitos hexadecimales (por ejemplo, --test=0122003a representa T10 LUN: 01 22 00 3a 00 00 00 00). ALUN puede ir precedido por '0x' o '0X' (por ejemplo, el ejemplo anterior podría haber sido --test=0x0122003a). ALUN también se puede proporcionar con espacios, tabulaciones o un '-' entre cada byte (o otra agrupación (por ejemplo, c101-0000-0000-0000)). Sin embargo, en el caso de separadores de espacio o tabulación, ALUN debería ir entre comillas simples o dobles.
En el caso de la 'L' inicial, el número decimal siguiente (hexadecimal si va precedido por '0x') se asume que es un LUN "word flipped" de Linux que se convierte en una representación T10 LUN y se imprime. En ambos casos, el número se interpreta como un LUN y se decodifica como si se hubiera dado la opción --decode. Además, cuando ALUN es un número hexadecimal, puede tener una 'L' al final, en cuyo caso se emite el valor LUN "word flipped" de Linux correspondiente. El LUN se decodifica en todos los casos.
La acción cuando se usa con --decode se explica en esa opción.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración).
-V, --version
imprime la cadena de versión y luego sale.

NOTAS

El comando SCSI REPORT LUNS es importante para el descubrimiento de Unidades Lógicas (LU). Después de descubrir un dispositivo de destino (generalmente a través de algún mecanismo específico del transporte) y después de enviar un comando INQUIRY (para determinar la configuración de LU_CONG), se debe enviar un comando REPORT LUNS al LUN 0 (que es el método de direccionamiento de dispositivo periférico con bus_id=0 y target/lun=0) o al LUN bien conocido de REPORT LUNS (es decir, 0xc101000000000000). SAM-5 requiere que uno de estos responda con un inventario de LUNs contenidos en este dispositivo de destino.

En modo de prueba, si se proporciona la opción --hex una vez, en la salida decodificada, algunos de los campos componentes se imprimen en hexadecimal con ceros iniciales. Los ceros iniciales sirven para indicar el tamaño del campo componente. Por ejemplo: en el método de direccionamiento de dispositivo periférico (16 bits en total), el bus ID tiene 6 bits de ancho y el campo target/LUN tiene 8 bits de ancho; por lo tanto, ambos se muestran con dos dígitos hexadecimales (por ejemplo, bus_id=0x02, target=0x3a).

EJEMPLOS

Normalmente, para cuando los programas del espacio de usuario se ejecutan, las LUs SCSI ya han sido descubiertas. En Linux, la utilidad lsscsi lista las LUs que están presentes actualmente. El LUN de un dispositivo (LU) es el cuarto elemento en la tupla al principio de cada línea. A continuación, vemos que un destino (o "I_T Nexus": "6:0:0") tiene dos LUNs: 1 y 49409. Si 49409 se convierte al formato T10 LUN, es 0xc101000000000000, que es el LUN bien conocido de REPORT LUNS.


# lsscsi -g
[6:0:0:1] disk Linux scsi_debug 0004 /dev/sdb /dev/sg1
[6:0:0:2] disk Linux scsi_debug 0004 /dev/sdc /dev/sg2
[6:0:0:49409]wlun Linux scsi_debug 0004 - /dev/sg3

Podríamos enviar un comando REPORT LUNS (con SR 0x0, 0x1 o 0x2) a cualquiera de esos nodos de dispositivo de archivo y obtener el mismo resultado. A continuación, usamos /dev/sg1:


# sg_luns /dev/sg1
Longitud de la lista de LUN = 16, lo que implica 2 entradas de LUN
Report luns [select_report=0x0]:
0001000000000000
0002000000000000

Eso es un poco ruidoso, así que reducimos el desorden con --quiet:


# sg_luns -q /dev/sg1
0001000000000000
0002000000000000

Ahora decodificamos ese LUN en sus partes componentes:


# sg_luns -d -q /dev/sg1
0001000000000000
Direccionamiento de dispositivo periférico: lun=1
0002000000000000
Direccionamiento de dispositivo periférico: lun=2

Ahora usamos --select=1 para averiguar si hay algún LUN bien conocido:


# sg_luns -q -s 1 /dev/sg1
c101000000000000

Entonces, ¿cuántos LUNs tenemos en total (asociados con el Nexus I_T actual)?


# sg_luns -q -s 2 /dev/sg1
0001000000000000
0002000000000000
c101000000000000


# sg_luns -q -s 2 -d /dev/sg1
0001000000000000
Direccionamiento de dispositivo periférico: lun=1
0002000000000000
Direccionamiento de dispositivo periférico: lun=1
c101000000000000
Unidad lógica bien conocida de REPORT LUNS

El siguiente ejemplo usa la opción --linux y no está disponible en otros sistemas operativos. El número adicional entre corchetes es la versión de Linux del T10 LUN que se muestra al principio de la línea.


# sg_luns -q -s 2 -l /dev/sg1
0001000000000000 [1]
0002000000000000 [2]
c101000000000000 [49409]

Ahora usamos la opción --test= para decodificar LUNs ingresados en la línea de comandos (en lugar de enviar un comando REPORT LUNS y actuar sobre la respuesta):


# sg_luns --test=0002000000000000
LUN decodificado:
Direccionamiento de dispositivo periférico: lun=2


# sg_luns --test="c1 01"
LUN decodificado:
Unidad lógica bien conocida de REPORT LUNS


# sg_luns -t 0x023a004b -H
LUN decodificado:
Direccionamiento de dispositivo periférico: bus_id=0x02, target=0x3a
>>Direccionamiento de segundo nivel:
Direccionamiento de dispositivo periférico: lun=0x4b

El siguiente ejemplo es específico de Linux, ya que intentamos averiguar a qué se traduce el LUN de Linux 49409 en el mundo T10:


# sg_luns --test=L49409
LUN de 64 bits en formato preferido T10 (hexadecimal): c1 01 00 00 00 00 00 00
LUN decodificado:
Unidad lógica bien conocida de REPORT LUNS

Y la correspondencia entre las representaciones de LUN T10 y Linux se puede hacer a la inversa:


# sg_luns -t c101L
Representación de LUN entero "word flipped" de Linux: 49409
LUN decodificado:
Unidad lógica bien conocida de REPORT LUNS

ESTADO DE SALIDA

El estado de salida de sg_luns es 0 cuando tiene éxito. De lo contrario, consulte la página del manual sg3_utils(8).
