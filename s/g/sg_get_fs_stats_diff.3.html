DESCRIPCIÓN

Las funciones sg_get_fs_stats proporcionan estadísticas de sistemas de archivos montados. Ambas funciones toman un parámetro opcional de entradas, que apunta (cuando se proporciona) a un size_t para obtener el número de entradas del vector devuelto.

Las funciones sg_get_fs_stats() y sg_get_fs_stats_r() entregan las estadísticas del sistema de archivos del momento en que se llama a la función. sg_get_fs_stats_diff() y sg_get_fs_stats_diff_between() entregan la diferencia entre dos llamadas a sg_get_fs_stats() o sg_get_fs_stats_r(), respectivamente.

Atajo de API

función retorna propietario de los datos
sg_get_fs_stats sg_fs_stats * libstatgrab (local al hilo)
sg_get_fs_stats_r sg_fs_stats * llamador
sg_get_fs_stats_diff sg_fs_stats * libstatgrab (local al hilo)
sg_get_fs_stats_diff_between sg_fs_stats * llamador
sg_get_valid_filesystems char ** libstatgrab (global)

Los vectores sg_fs_stats recibidos de sg_get_fs_stats_r() o sg_get_fs_stats_diff_between() deben liberarse usando sg_free_fs_stats() cuando ya no se necesiten. El llamador es responsable de hacerlo.

La biblioteca statgrab viene con una lista incorporada de tipos de sistemas de archivos válidos, dependiendo del sistema operativo para el que se compiló. Algunos sistemas operativos además proporcionan una API para conocer los tipos de sistemas de archivos conocidos o válidos para la instancia del SO en ejecución, que se utiliza cuando se detectan. Sin embargo, existen problemas conocidos al recopilar estadísticas de sistemas de archivos: los sistemas de archivos de red se montan desde servidores remotos, los desarrolladores de sistemas de archivos ejecutan un controlador experimental, etc.

Para evitar que los procesos se bloqueen al obtener estadísticas de sistemas de archivos o para permitir a los desarrolladores probar sus controladores, los procesos pueden modificar la lista de sistemas de archivos válidos utilizando sg_get_valid_filesystems() y sg_set_valid_filesystems(). La lista de parámetros char * con los que trabajan ambas funciones siempre termina con un elemento que apunta a NULL.

La lista devuelta por sg_get_valid_filesystems() no debe modificarse. Siempre copie la lista en su propia estructura si planea extender o reducir la lista:

Ejemplo de eliminación de FS de red

int compare_fs_type(const void *va, const void *vb) {
    const char **a = (const char **)va;
    const char **b = (const char **)vb;
    return strcmp( *a, *b );
}
void filter_network_fs_types(void) {
    /* nombres conocidos de sistemas de archivos de red en diferentes plataformas */
    const char *nfs_types[] = { "nfs", "nfs3", "nfs4", "cifs", "smbfs", "samba" };
    const size_t nfs_types_count = sizeof(nfs_types) / sizeof(nfs_types[0])
    size_t fs_entries = 0;
    const char **orig_valid_fs = sg_get_valid_filesystems(&fs_entries);
    /* duplicar en memoria propia para modificar la lista */
    char **valid_fs = calloc( entries + 1, sizeof(valid_fs[0]) );
    memcpy( valid_fs, orig_valid_fs, (entries + 1) * sizeof(valid_fs[0]) );
    size_t i;
    for( i = 0; i < nfs_types_count; ++i ) {
        char **inv_fs = bsearch( &nfs_types[i], &valid_fs[0],
                                 fs_entries, sizeof(valid_fs[0]),
                                 compare_fs_type );
        if( NULL != inv_fs ) {
            /* copiar incluyendo el puntero NULL final */
            memmove( inv_fs, inv_fs + 1, fs_entries - (inv_fs - valid_fs) );
            --fs_entries;
        }
    }
    sg_set_valid_filesystems( valid_fs );
    free( valid_fs );
}

Tenga en cuenta que no es necesario duplicar las cadenas contenidas en la lista de sistemas de archivos válidos en el ejemplo anterior; no se modifican.

La lista devuelta por sg_get_valid_filesystems() podría invalidarse al usarse mientras el proceso realiza llamadas a sg_set_valid_filesystems(). Ninguna de las funciones sg_fs_stats protege el acceso al almacenamiento globalmente utilizado donde se mantiene la copia propia de la lista de sistemas de archivos válidos. Es responsabilidad del llamador no mezclar llamadas de configuración con llamadas para obtener estadísticas.

Además, hay dos funciones de soporte para qsort(3) disponibles: sg_fs_compare_device_name() y sg_fs_compare_mnt_point().

Ejemplo de ordenación

size_t entries;
sg_fs_stats *fs_stats = NULL;
while( NULL != ( fs_stats = sg_get_fs_stats_diff(&entries) ) ) {
    /* ordenar entradas alfabéticamente usando el punto de montaje */
    qsort( fs_stats, entries, sizeof(fs_stats[0]), &sg_fs_compare_mnt_point );
    show_fs_stats( fs_stats );
}

VALORES DE RETORNO

sg_get_fs_stats devuelve un puntero a una estructura de tipo sg_fs_stats.

typedef enum {
        sg_fs_unknown  = 0,
        sg_fs_regular  = 1 << 0,
        sg_fs_special  = 1 << 1,
        sg_fs_loopback = 1 << 2,
        sg_fs_remote   = 1 << 3,
        sg_fs_local    = (sg_fs_regular | sg_fs_special),
        sg_fs_alltypes = (sg_fs_regular | sg_fs_special | sg_fs_loopback | sg_fs_remote)
} sg_fs_device_type;

typedef struct {
        char *device_name;
        char *fs_type;
        char *mnt_point;
        sg_fs_device_type device_type;
        unsigned long long size;
        unsigned long long used;
        unsigned long long free;
        unsigned long long avail;
        unsigned long long total_inodes;
        unsigned long long used_inodes;
        unsigned long long free_inodes;
        unsigned long long avail_inodes;
        unsigned long long io_size;
        unsigned long long block_size;
        unsigned long long total_blocks;
        unsigned long long free_blocks;
        unsigned long long used_blocks;
        unsigned long long avail_blocks;
        time_t systime;
} sg_fs_stats;
device_name
El nombre conocido por el sistema operativo. (por ejemplo, en linux podría ser hda)
fs_type
El tipo de sistema de archivos del sistema de archivos (por ejemplo, hpfs o ufs).
mnt_point
El punto de montaje en el que está montado el sistema de archivos.
device_type
El tipo de dispositivo del sistema de archivos, actualmente no relleno y siempre sg_fs_unknown.
size
El tamaño total, en bytes, del sistema de archivos.

size = used + free

used
La cantidad de espacio, en bytes, utilizada en el sistema de archivos.
avail
La cantidad de espacio, en bytes, disponible en el sistema de archivos para n

DESCRIPTION

avail
The amount of space, in bytes, available to non-privileged users or processes (espacio libre menos espacio reservado).

avail = free - reserved

free
La cantidad de espacio, en bytes, libre en el sistema de archivos.
total_inodes
El número total de inodos en el sistema de archivos.
used_inodes
El número de inodos utilizados en el sistema de archivos.
free_inodes
El número de inodos libres en el sistema de archivos.
avail_inodes
El número de inodos libres disponibles para procesos no privilegiados.
io_size
Un tamaño de bloque óptimo sugerido para operaciones de E/S -- si está leyendo o escribiendo muchos datos, hágalo en bloques de este tamaño.
block_size
El tamaño en bytes de la unidad mínima de asignación en este sistema de archivos.
total_blocks
El número total de bloques en el sistema de archivos.
free_blocks
El número de bloques libres en el sistema de archivos.
used_blocks
El número de bloques utilizados en el sistema de archivos.
avail_blocks
El número de bloques libres disponibles para procesos no privilegiados.
systime
El tiempo en segundos desde la época en que la estadística fue recuperada del kernel.

BUGS

Solo se reconocen los sistemas de archivos montados.

Algunos sistemas de archivos pueden aparecer dos veces cuando están montados en diferentes puntos de montaje.

Las funciones de comparación existen más por compatibilidad retroactiva que por mejoras funcionales. La flexibilidad limitada (por ejemplo, orden inverso) y la falta de oportunidades de optimización para el compilador llevan a la recomendación de implementar las rutinas de comparación requeridas localmente.

Llamar a sg_set_valid_filesystems con una lista vacía borrará la lista interna de sistemas de archivos válidos. Actualmente no hay forma de restablecer a la lista inicial.
