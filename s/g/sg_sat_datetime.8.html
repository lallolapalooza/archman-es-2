sg_sat_datetime(8)

Paquete: sg3_utils

Licencias: GPL, custom:BSD

SG_SAT_DATETIME(8) SG3_UTILS SG_SAT_DATETIME(8)

NOMBRE

sg_sat_datetime - reportar o establecer fecha y hora en un dispositivo ATA

SINOPSIS

sg_sat_datetime [--dma] [--elapsed] [--format] [--help] [--hex] [--milliseconds=MS] [--readonly] [--seconds=SECS] [--srep] [--verbose] [--version] DISPOSITIVO

DESCRIPCIÓN

Envía un comando SET DATE & TIME EXT o READ LOG [DMA] EXT al DISPOSITIVO ATA para establecer la fecha y hora o leerla desde la dirección del registro de estadísticas del dispositivo (04h), página de estadísticas generales (01h). Estos comandos se encuentran en el estándar ATA Command Set (ACS-5). Los comandos ATA se envían utilizando comandos SCSI ATA PASS-THROUGH.

Si se proporciona la opción --milliseconds=MS o --seconds=SECS (y no se pueden dar ambas) entonces se envía el comando SET DATE & TIME. De lo contrario, se envía el comando READ LOG EXT, o si se usa la opción --dma, se envía el comando READ LOG DMA EXT al dispositivo.

La fecha y hora se envía y se recibe del DISPOSITIVO generalmente como el número de milisegundos desde la época del 1970-01-01 00:00:00 UTC y se almacena en un entero sin signo de 48 bits. Esa misma época es utilizada por las máquinas Unix, pero estas suelen almacenar el número de segundos desde esa época. El comando date de Unix y especialmente su formato "+%s" es útil para convertir entre marcas de tiempo y formatos más legibles por humanos. Ver la sección EJEMPLOS más abajo. Si la fecha y hora no se ha establecido después de un reinicio de encendido, el valor es el mismo que las horas de encendido del dispositivo en milisegundos.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas.

-d, --dma
usa READ LOG DMA EXT para leer el valor de fecha y hora del dispositivo. Ignorado si se está estableciendo la fecha y hora.
-e, --elapsed
asume que la fecha y hora de READ LOG [DMA] EXT es un tiempo transcurrido desde un evento como un ciclo de energía o un reinicio forzado y formatea la salida como '<n> días hh:mm:ss.xxx' donde hh son las horas (00 a 23 inclusive); mm son los minutos (00 a 59 inclusive); ss son los segundos (00 a 59 inclusive) y xxx son los milisegundos (000 a 999 inclusive). Si el número de días es 0 entonces '0 días' no se muestra a menos que esta opción se dé dos o más veces.
Esta opción es especialmente útil si la fecha y hora no se ha establecido. Según ACS-5, cuando no está establecida, la fecha y hora se inicializa a las horas de encendido del dispositivo en milisegundos.
-f, --format
muestra la fecha y hora formateada usando la configuración regional por defecto.
-h, --help
muestra el mensaje de uso y luego sale.
-H, --hex
muestra la fecha y hora en hexadecimal ASCII.
-m, --milliseconds=MS
donde MS es el número de milisegundos desde el 1970-01-01 00:00:00 UTC para establecer en el DISPOSITIVO con el comando ATA SET DATE & TIME EXT.
-R, --readonly
abre el DISPOSITIVO en modo de solo lectura. La acción por defecto es abrir el DISPOSITIVO en modo de lectura-escritura.
-s, --seconds=SECS
donde SECS es el número de segundos desde el 1970-01-01 00:00:00 UTC para establecer en el DISPOSITIVO con el comando ATA SET DATE & TIME. SECS se multiplica por 1000 antes de ser usado en el comando ATA SET DATE & TIME.
-S, --srep
reporta el número de segundos desde el 1970-01-01 00:00:00 UTC. Esto se hace dividiendo el valor devuelto por el comando ATA READ LOG [DMA] EXT por 1000.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración).
-V, --version
imprime la cadena de versión y luego sale.

ESTADO DE SALIDA

El estado de salida de sg_sat_datetime es 0 cuando es exitoso. De lo contrario, ver la página del manual sg3_utils(8).

NOTAS

El DISPOSITIVO debería comenzar a acumular tiempo inmediatamente después de establecer la fecha y hora. Es decir, si estableces y luego recuperas la fecha y hora, los valores devueltos probablemente habrán aumentado.

El estándar ACS-5 no contempla un almacenamiento de fecha y hora a prueba de fallos de energía. A menos que el dispositivo tenga capacidad específica del proveedor para ser a prueba de fallos, después de un reinicio de encendido, según ACS-5, la fecha y hora deberían ser las horas de encendido del dispositivo devueltas en milisegundos (o segundos si se usa la opción --srep).

EJEMPLOS

En máquinas Unix (por ejemplo, Linux, FreeBSD y Solaris) el comando date es útil cuando se trabaja con marcas de tiempo.

Para obtener la marca de tiempo de un DISPOSITIVO y mostrarla en un formato legible por humanos, se podría usar lo siguiente:


# sg_sat_datetime -S /dev/sg2
1681156506


# date --date=@1681156506
lun abr 10 14:55:06 CDT 2023


# date -R --date="@1681156506"
Mon, 10 Apr 2023 14:55:06 -0500

Los dos últimos comandos date muestran diferentes formatos de la misma fecha (es decir, 1681156506 segundos desde el 1970-01-01 00:00:00 UTC). Los comandos sg_sat_datetime y date se pueden combinar usando comillas invertidas :


# date -R --date=@`sg_sat_datetime -S /dev/sg2`
Mon, 10 Apr 2023 14:55:06 -0500

Alternativamente, la opción --format se puede usar para formatear la fecha y hora usando la configuración regional por defecto.
# sg_sat_datetime --format /dev/sg2
lun abr 10 15:02:54 2023

Para establecer la fecha y hora en el DISPOSITIVO a ahora (aproximadamente) se podría usar lo siguiente:


# date +%s
1681157099


# sg_sat_datetime --seconds=1681157099 /dev/sg0

Esas dos líneas de comando se pueden combinar en una usando comillas invertidas:


# sg_sat_datetime --seconds=`date +%s` /dev/sg0
