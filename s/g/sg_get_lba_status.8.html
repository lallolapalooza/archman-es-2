SG_GET_LBA_STATUS(8) SG3_UTILS SG_GET_LBA_STATUS(8)

NOMBRE

sg_get_lba_status - envía el comando SCSI GET LBA STATUS(16 o 32)

SINOPSIS

sg_get_lba_status [--16] [--32] [--blockhex] [--brief] [--element-id=EI] [--help] [--hex] [--inhex=FN] [--json[=JO]] [--lba=LBA] [--maxlen=LEN] [--raw] [--readonly] [--report-type=RT] [--scan-len=SL] [--verbose] [--version] DISPOSITIVO

DESCRIPCIÓN

Envía el comando SCSI GET LBA STATUS(16) o GET LBA STATUS(32) al DISPOSITIVO y muestra la respuesta. La variante de comando de 16 bytes se introdujo en la revisión 20 (borrador) de SBC-3 y los dispositivos que soportan el aprovisionamiento de bloques lógicos deben soportar este comando. El comando GET LBA STATUS(32) se añadió en la revisión 14 (borrador) de SBC-4.

La acción predeterminada es decodificar la respuesta en un descriptor de estado LBA por línea, luego mostrar una cabecera y los descriptores de estado en la salida estándar. La LBA del descriptor se muestra en hexadecimal (precedida por '0x') y el número de bloques se muestra en decimal seguido del estado de aprovisionamiento, la accesibilidad de la LBA y el estado adicional en decimal. El estado de aprovisionamiento puede estar en el rango de 0 a 15, de los cuales actualmente solo se utilizan 0 (mapeado o desconocido), 1 (no mapeado), 2 (anclado), 3 (mapeado) y 4 (desconocido). La cantidad de salida se puede reducir con la opción --brief.

En lugar de enviar este comando SCSI al DISPOSITIVO, si se proporciona la opción --inhex=FN, el contenido del archivo llamado FN se decodifica como hexadecimal ASCII y luego se procesa si fuera la respuesta de este comando.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas.

-S, --16
envía el comando SCSI GET LBA STATUS(16), que es la variante de 16 bytes. En ausencia de las opciones --16 o --32, se envía el comando SCSI GET LBA STATUS(16). Si se proporcionan ambas opciones --16 y --32, se envía el comando GET LBA STATUS(16).
-T, --32
envía el comando SCSI GET LBA STATUS(32), que es la variante de 32 bytes. Cuando se proporciona junto con la opción --16, esta opción se ignora (por lo que se envía el comando GET LBA STATUS(16)).
-b, --brief
cuando se usa una vez, se muestra un descriptor de estado LBA por línea en la salida estándar. Cada línea tiene el siguiente formato: "0x<descriptor_LBA> 0x<bloques> <estado_aprovisionamiento> <estado_adicional>". Por lo tanto, la LBA de inicio del descriptor y el número de bloques se muestran en hexadecimal, mientras que el estado de aprovisionamiento y el estado adicional se muestran en decimal. Cuando se usa dos veces (por ejemplo, '-bb' o '--brief --brief'), se muestra en la salida estándar el estado de aprovisionamiento de la LBA dada (o LBA 0 si no se proporciona la opción --lba). Se realiza una comprobación de que la LBA dada se encuentra dentro del rango del primer descriptor de estado LBA devuelto (como debería ser según la revisión 20 de SBC-3) y se envían advertencias a stderr si no es así.
-B, --blockhex
el número de bloques en cada descriptor de estado LBA se muestra normalmente en decimal. Una excepción es cuando se proporciona la opción --brief, en cuyo caso se muestra en hexadecimal. Cuando se proporciona la opción una vez, ambos casos se muestran en hexadecimal. Cuando se proporciona la opción dos veces, ambos casos se muestran en decimal.
-e, --element-id=EI
donde EI es el identificador del elemento del elemento físico para el cual se informarán las LBAs basándose en el valor en el campo de tipo de informe (es decir, RT). Esta opción solo está activa con el comando SCSI GET LBA STATUS(32) (es decir, se ignora si se envía el comando GET LBA STATUS(16)).
Los identificadores de elemento válidos son distintos de cero. El valor predeterminado de EI es 0, que en este contexto significa que no se especifica ningún identificador de elemento.
-h, --help
muestra el mensaje de uso y luego sale.
-H, --hex
muestra la respuesta a este comando en hexadecimal ASCII. Para producir una salida hexadecimal adecuada para una invocación posterior para obtenerla con la opción --inhex=FN, use esta opción tres veces. La opción de forma corta lo hace más conveniente: '-HHH'.
-i, --inhex=FN
donde FN es un nombre de archivo cuyo contenido se asume que son bytes hexadecimales ASCII. Consulte la sección "FORMATOS HEX, BINARIO Y JSON" en la página del manual de sg3_utils para obtener más información. Si también se proporciona DISPOSITIVO, se ignora. Si también se proporciona la opción --raw, el contenido de FN se trata como binario.
-j[=JO], --json[=JO]
la salida está en formato JSON en lugar de texto plano. Tenga en cuenta que los argumentos para la forma corta y larga son opcionales y, si están presentes, comienzan con "=" y no se permiten espacios en blanco alrededor de ese "=".
Consulte la página del manual de sg3_utils_json o use '?' para JO para obtener un resumen.
-J, --js-file=JFN
la salida está en formato JSON y se envía a un archivo llamado JFN. Si ese archivo existe, se trunca. Por defecto, la salida JSON se envía a la salida estándar.
Cuando se proporciona esta opción, la opción --json[=JO] se implica y no es necesario proporcionarla. La opción --json[=JO] aún puede ser necesaria para establecer el parámetro JO a valores no predeterminados.
-l, --lba=LBA
donde LBA es la Dirección de Bloque Lógico (LBA) de inicio para la que se verifica el estado de aprovisionamiento. Tenga en cuenta que el DISPOSITIVO elige cuántos bloques siguientes para los que devolverá el estado de aprovisionamiento.
-m, --maxlen=LEN
donde LEN es la longitud (máxima) de la respuesta en bytes. Se coloca en el campo "longitud de asignación" del cdb. Si no se proporciona, se usa 24. 24 es suficiente espacio para la cabecera de respuesta y un descriptor de estado LBA. LEN debe ser 8 más un múltiplo de 16 (por ejemplo, 24, 40 y 56 son adecuados).
-r, --raw
muestra la respuesta en binario (a la salida estándar) a menos que también se proporcione la opción --inhex=FN. En ese caso, el nombre del archivo de entrada (FN) se decodifica como binario (y la salida *no* está en binario).
-R, --readonly
abre el DISPOSITIVO en modo de solo lectura (por ejemplo, en Unix con la bandera O_RDONLY). El valor predeterminado es abrirlo en modo de lectura/escritura.
-t, --report-type=RT
donde RT es 0 para informar todas las LBAs; 1 para informar LBAs con estado de aprovisionamiento distinto de cero; 2 para informar LBAs que están mapeadas; 3 para informar LBAs que están desasignadas; 4 para informar LBAs que están ancladas; 16 para informar LBAs que pueden devolver un error no recuperado. El campo REPORT TYPE se añadió al cdb GET LBA STATUS en sbc4r12.
Dado que el campo REPORT TYPE es más reciente que el comando, la respuesta contiene el bit RTP para indicar si el DISPOSITIVO actúa o no sobre el campo REPORT TYPE (establecido cuando actúa sobre él, claro en caso contrario).
-s, --scan-len=SL
donde SL es la longitud de escaneo, que es el número máximo de bloques lógicos contiguos a escanear para bloques lógicos que cumplen con el tipo de informe dado (es decir, RT). Esta opción solo está activa con el comando SCSI GET LBA STATUS(32) (es decir, se ignora si se envía el comando GET LBA STATUS(16)).
El valor predeterminado de SL es 0, lo que debe ser interpretado por el DISPOSITIVO como que no hay límites en el número de LBAs que se deben escanear.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración). La salida adicional causada por esta opción se envía a stderr.
-V, --version
imprime la cadena de versión y luego sale.

NAME

sg_get_lba_status

get logical block status

SYNOPSIS

sg_get_lba_status [OPTION]... DEVICE

DESCRIPTION

This utility reads the logical block status from a SCSI device (e.g., disk, SSD). It does this by sending a T10 SBC command, READ LB PROTECTION INFORMATION (SBC-3 rev 39+), READ LONG (SBC-2 rev 31+), or READ BUFFER (SBC-2 rev 31+). The choice of command depends on the device's reported features. The primary use case is to find out which logical blocks have been deallocated (e.g., by TRIM or UNMAP commands).

The output is a list of logical block address (LBA) ranges and their status. The status can indicate whether a block is mapped (i.e., allocated), deallocated, or inaccessible.

OPTIONS

-b, --byte
When reporting LBA status, show the results as a sequence of 16-byte (128-bit) blocks. This is the default. The number of bits in the 'blocks' field of the T10 standard is 256.
-e, --enclosure
Attempt to find the LBA status via the enclosure device rather than the disk device. This is experimental.
-h, --help
Print usage message and exit.
-H, --hex
Print the raw response buffer in hexadecimal.
-i, --inhex=FILE
Read response from the given hex FILE. This bypasses sending a SCSI command to the device. Useful for testing.
-L, --long
Use the READ LONG SBC-2 command if available (revision 31+). Otherwise defaults to READ BUFFER. The READ LB PROTECTION INFORMATION (SBC-3 rev 39+) command is preferred if available.
-n, --num=NUM
Interpret the response buffer as NUM blocks. This option is used if the device returns a response buffer that is smaller than expected, and the number of blocks reported in the CDB is not used. The maximum value for NUM is 256.
-p, --protection
Use the READ LB PROTECTION INFORMATION (SBC-3 rev 39+) command. This command is the most appropriate for LBA status.
-r, --revision
Print the SCSI command revision used.
-S, --Slist
When reporting LBA status, show the results as a sequence of 16-bit (short) blocks. This is equivalent to setting the byte offset to 8 and in revision 25 it was changed to 4.
-v, --verbose
Increase the verbosity of the output.
-V, --version
Print the version string and exit.

NOTES

For a discussion of logical block provisioning see section 4.7 of sbc4r14.pdf at https://www.t10.org (or the corresponding section of a later draft).

EXAMPLES

This example uses a "canned" hex file rather than a real DEVICE.


# cd <folder at root of sg3_utils source package>
# sg_get_lba_status --inhex=inhex/get_lba_status.hex


Command completed due to meeting capacity of medium
RTP=0x0
[1] LBA: 0x0 blocks: 287453952 mapped (or unknown); LBA accessibility not reported
[2] LBA: 0x11223300 blocks: 68 deallocated; LBA access not reported [may contain unrecovered errors]
[3] LBA: 0x11223344 blocks: 51 deallocated; LBA extent inaccessible [may contain unrecovered errors]

EXIT STATUS

The exit status of sg_get_lba_status is 0 when it is successful. Otherwise see the sg3_utils(8) man page.
