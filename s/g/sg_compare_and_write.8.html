NOMBRE

sg_compare_and_write - envía el comando SCSI COMPARE AND WRITE

SINOPSIS

sg_compare_and_write [--dpo] [--fua] [--fua_nv] [--grpnum=GN] [--help] --in=IF [--inw=WF] --lba=LBA [--num=NUM] [--quiet] [--timeout=TO] [--verbose] [--version] [--wrprotect=WP] [--xferlen=LEN] DISPOSITIVO

DESCRIPCIÓN

Envía el comando SCSI COMPARE AND WRITE al DISPOSITIVO. Esta utilidad obtiene un búfer de comparación y un búfer de escritura de uno o dos archivos. Si se proporciona la opción --inw=WF, el búfer de comparación se obtiene del archivo indicado por --in=IF, mientras que el búfer de escritura se obtiene del archivo indicado por --inw=WF. Si la opción --inw=WF no se proporciona, los búferes de comparación y escritura concatenados se obtienen del archivo indicado por la opción --in=IF.

Se espera que cada uno de esos búferes contenga NUM bloques de datos. La comparación comienza en la dirección de bloque lógico LBA en el DISPOSITIVO y, si la comparación falla (es decir, el búfer de comparación proporcionado no coincide con los datos en LBA en el DISPOSITIVO), el comando COMPARE AND WRITE finaliza con una clave de sentido MISCOMPARE. En este caso, esta utilidad se completará y establecerá un estado de salida de 14 (que casualmente es el valor de la clave de sentido de MISCOMPARE).

Si la comparación tiene éxito, el búfer de escritura proporcionado se almacena comenzando en LBA durante NUM bloques en el DISPOSITIVO.

El número real de bytes transferidos en el búfer de salida de datos del comando COMPARE AND WRITE puede necesitar ser proporcionado por el usuario con la opción --xferlen=LEN. LEN tiene un valor predeterminado de (2 * NUM * 512), que es 1024 para el valor predeterminado de NUM de 1. Si el tamaño del bloque es diferente de 512, el usuario deberá usar la opción --xferlen=LEN. Si se proporciona información de protección (indicada por un valor de WP distinto de 0 (el predeterminado)), entonces para un NUM de 1, LEN debe ser 1040. Tenga en cuenta que el comando SCSI READ CAPACITY no es realizado por esta utilidad (por ejemplo, para encontrar el tamaño del bloque).

La definición T10 del comando SCSI COMPARE AND WRITE requiere que el DISPOSITIVO implemente la comparación y la escritura opcional como una serie ininterrumpida de acciones. Dependiendo de otras configuraciones del DISPOSITIVO, una operación de verificación puede ocurrir antes de la comparación.

Cuando ocurre una discrepancia entre el búfer de comparación y los bloques que comienzan en LBA leídos del DISPOSITIVO, el búfer de sentido que contiene la clave de sentido MISCOMPARE causa que se envíen varios mensajes a stderr (incluido el desplazamiento del primer byte de la discrepancia). Para suprimir estos mensajes, use la opción --quiet. Con o sin la opción --quiet, el estado de salida se establecerá en 14, que es el valor de la clave de sentido que indica un MISCOMPARE.

Este comando está definido en SBC-3, cuya revisión más reciente es 36. SBC-3 y otros documentos SCSI se pueden encontrar en https://www.t10.org.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas. Las opciones están ordenadas alfabéticamente según el nombre de la opción larga.

-d, --dpo
Establece el bit DPO en el CDB COMPARE AND WRITE.
-f, --fua
Establece el bit FUA en el CDB COMPARE AND WRITE.
-F, --fua_nv
Establece el bit FUA_NV en el CDB COMPARE AND WRITE. Este bit fue eliminado en la revisión 35d de SBC-3 y su posición marcada como "reservada".
-g, --grpnum=GN
donde GN es el valor que se colocará en el campo del número de grupo en el CDB COMPARE AND WRITE.
-h, --help
muestra el mensaje de uso y luego sale.
-i, --in=IF
lee datos (binarios) del archivo llamado IF. Este será ya sea el búfer de comparación y escritura combinado (cuando la opción --inw=WF no se proporciona) o solo el búfer de comparación (cuando la opción --inw=WF se proporciona). Si IF es '-' entonces se lee desde la entrada estándar (por ejemplo, una tubería).
-C, --inc=IF
Igual que la opción --in.
-D, --inw=WF
lee datos (binarios) del archivo llamado WF. Este será el búfer de escritura que se convertirá en la segunda mitad del búfer de salida de datos enviado al DISPOSITIVO asociado con el comando COMPARE AND WRITE. Tenga en cuenta que cuando se proporciona esta opción, se espera que --in=IF contenga el búfer de comparación asociado.
-l, --lba=LBA
donde LBA es la dirección de bloque lógico para iniciar el comando COMPARE AND WRITE. Se asume que está en decimal a menos que esté precedido por '0x' o tenga un sufijo 'h'.
-n, --num=NUM
donde NUM es el número de bloques, comenzando en LBA, para leer y comparar con la instancia de verificación. Y dada una coincidencia, el número de bloques NUM para escribir comenzando en LBA. El valor predeterminado para NUM es 1.
-q, --quiet
suprime los mensajes del búfer de sentido asociados con una clave de sentido MISCOMPARE que de otro modo se enviarían a stderr. Aún así establece el estado de salida en 14, que es el valor de la clave de sentido que indica un MISCOMPARE.
-t, --timeout=TO
donde TO es el valor de tiempo de espera del comando en segundos. El valor predeterminado es 60 segundos. Si NUM es grande (o cero), un comando WRITE SAME puede requerir considerablemente más de 60 segundos para completarse.
-v, --verbose
aumenta el grado de verbosidad (mensajes de depuración).
-V, --version
muestra la cadena de versión y luego sale.
-w, --wrprotect=WP
establece el campo WRPROTECT en el cdb a WP. El valor predeterminado es 0, lo que implica que no se envía información de protección (junto con los datos del usuario) por esta utilidad.
-x, --xferlen=LEN
donde LEN es la longitud del búfer de salida de datos en bytes. Tiene un valor predeterminado de (2 * NUM * 512) bytes. Si el tamaño del bloque del DISPOSITIVO es diferente de 512 bytes o si WP es distinto de cero (lo que implica información de protección adicional), entonces este valor predeterminado será incorrecto; el usuario debe proporcionar el valor correcto para LEN.

NOTAS

Varios argumentos numéricos (por ejemplo, LBA) pueden incluir sufijos multiplicadores o proporcionarse en hexadecimal. Consulte la sección "ARGUMENTOS NUMÉRICOS" en la página del manual sg3_utils(8).

sg_compare_and_write(8) — sg3_utils 1.47

NAME

sg_compare_and_write - performs SCSI COMPARE AND WRITE (10 or 12) command

SYNOPSIS

sg_compare_and_write [--data=DAT] [--dif] [--dpo] [--force] [--in=FILE] [--len=LEN] [--lba=LBA] [--num=NUM] [--of=OF] [--old-length] [--pbdt] [--unmap] [--verbose=LEVEL] [--version] DEVICE

DESCRIPTION

This utility, when given one or more LBA (Logical Block Address) ranges, will perform the SCSI COMPARE AND WRITE command. This command compares data in the LBA range with data read from the device. If the data matches, then the data is written to the device. If the data does not match, the write does not occur, and an error is reported.

The contents of the data to be compared and potentially written are either read from the file specified by the --in=FILE option, or generated as zeros (if --in=FILE is not given) or as the SCSI Inquiry data.

The compare and write is performed over NUM logical blocks starting at LBA LBA.

The SCSI COMPARE AND WRITE command is defined in SBC-3 (revision 27) and later.

OPTIONS

--data=DAT
Specifies the data to be compared and written. The content is taken from the file DAT. If this option is not given, then data is read from --in=FILE. If neither is given, then zeros are used.
--dif
Set the DIF (Data Integrity Field) or PI (Protection Information) bit in the cdb. See the man page for sg_write_buffer for a full explanation of DIF/PI.
--dpo
--disable-protection
Set the DPO (Disable Page Out) bit in the cdb. If set, the block device should treat this command as a normal command and not a prefetch candidate.
--force
By default this utility will not overwrite the first logical block (LBA 0) if it is a block device file like /dev/sda. This option overrides that restriction.
--in=FILE
Read data to be compared and potentially written from FILE. If this option is not specified, and --data=DAT is also not given, then the utility will send zeros to the SCSI command.
--len=LEN
The length of data (in bytes) to be compared and potentially written. This option is only needed if the length cannot be deduced from the --in=FILE or --data=DAT arguments (e.g. reading from stdin). If this option is not given, and --in=FILE or --data=DAT is specified, the length is taken from the file size.
--lba=LBA
The starting Logical Block Address (LBA). LBA is assumed to be zero if not specified.
--num=NUM
The number of logical blocks to read and write. The default is 1.
--of=OF
Write the data read from the device to the file OF. This is useful for debugging and verifying the contents of the device.
--old-length
Use the 10-byte CDB variant of COMPARE AND WRITE (if possible) instead of the 12-byte CDB variant. The 10-byte variant is not able to specify an LBA greater than 0x0FFFFFFF.
--pbdt
Set the PBDT (Protection Background Task) bit in the cdb. This is used with DIF/PI.
--unmap
Set the UNMAP bit in the cdb. This causes the LBAs specified to be deallocated.
--verbose=LEVEL
Increase the verbosity of the output. LEVEL can be from 1 to 6.
--version
Print the version string to stdout then exit.

NOTES

The LBA is the logical block address from the perspective of the SCSI device. It is not necessarily the same as the sector number from the perspective of the operating system.

When using this utility on a block device file like /dev/sda, care must be taken, as writing to LBA 0 could render the device unbootable.

EXAMPLES

The following example performs a compare and write of one block of data read from ff00.bin to LBA 0 of the device /dev/sg1. The data in ff00.bin is assumed to be 0xff bytes.


# sg_compare_and_write --in=ff00.bin --lba=0 --num=1 /dev/sg1

Assuming that the first logical block of /dev/sg1 is also full of 0xff bytes, then the compare will succeed, and the write will occur. The first logical block of /dev/sg1 will now contain the data from ff00.bin. Since ff00.bin contains only 0xff bytes, then the first logical block of /dev/sg1 will now be all 0xff bytes.

Now if we try to write the same data again to LBA 0:


# sg_compare_and_write --in=ff00.bin --lba=0 --num=1 /dev/sg1
Miscompare at byte offset: 0 [0x0]
sg_compare_and_write failed: Miscompare

This is the expected result. The compare failed immediately because the data on disk (which is all 0xff bytes) does not match the data we are trying to write (which is also all 0xff bytes).

Let's try overwriting the first 3 bytes of ff00.bin with 0x0:


# sg_dd bs=1 iflag=00 of=ff00.bin count=3
3+0 records in
3+0 records out

Now we perform the compare and write again:


# sg_compare_and_write --in=ff00.bin --lba=0 --num=1 /dev/sg1
Miscompare at byte offset: 3 [0x3]
sg_compare_and_write failed: Miscompare

The compare succeeded for the first 3 bytes, but failed at offset 3. The SCSI COMPARE AND WRITE command stops comparing at the first mismatched byte.

EXIT STATUS

The exit status of sg_compare_and_write is 0 when it is successful. If the compare step fails then the exit status is 14. For other exit status values see the EXIT STATUS section in the sg3_utils(8) man page.

Earlier versions of this utility set an exit status of 98 when there was a MISCOMPARE.
