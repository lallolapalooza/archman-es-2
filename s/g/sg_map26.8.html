NOMBRE

sg_map26 - mapea el dispositivo genérico SCSI (sg) a nombres de dispositivo correspondientes

SINOPSIS

sg_map26 [--dev_dir=DIR] [--given_is=0|1] [--help] [--result=0|1|2|3] [--symlink] [--verbose] [--version] DISPOSITIVO

DESCRIPCIÓN

Mapea un archivo especial (de bloque o de carácter) asociado a un dispositivo SCSI al dispositivo genérico SCSI (sg) correspondiente, o viceversa. También puede recibir un archivo de sysfs, por ejemplo '/sys/block/sda' o '/sys/block/sda/dev'.

En lugar de mapear hacia o desde un dispositivo sg, se puede solicitar el nombre del archivo sysfs que coincide con un archivo especial de dispositivo (o viceversa). Esto se hace con '--result=2' y '--result=3'. Esta función funciona tanto en dispositivos ATA (por ejemplo, 'dev/hdc') como en dispositivos SCSI.

En esta utilidad, "mapeado" se refiere a encontrar la relación entre un nodo genérico SCSI (sg) y el nombre del dispositivo SCSI de nivel superior; o viceversa. Por ejemplo, '/dev/sg0' puede "mapear" a '/dev/sda'. Es posible que no existan mapeos si, por ejemplo, no está cargado un módulo relevante. Además, hay dispositivos SCSI a los que solo se puede acceder a través de un nodo sg (por ejemplo, dispositivos SAF-TE y algunos SES).

En esta utilidad, "coincidente" se refiere a diferentes representaciones del mismo dispositivo accedido a través del mismo controlador. Por ejemplo, '/dev/hdc' y '/sys/block/hdc' suelen referirse al mismo dispositivo y, por lo tanto, se considerarían coincidentes. Un ejemplo relacionado es que '/dev/cdrom' y '/dev/hdc' también se consideran coincidentes si '/dev/cdrom' es un enlace simbólico a '/dev/hdc'.

Tenga en cuenta que esta utilidad requiere permisos de root para acceder a los nodos de dispositivos de almacenamiento en el directorio /dev. La utilidad lsscsi puede usarse en su lugar en muchos casos, y lsscsi no requiere permisos de root ya que "minería de datos" del sistema de archivos pseudo-sysfs para la información que necesita.

Para notas sobre los nodos de dispositivos bsg y nvme, consulte la sección BSG Y DISPOSITIVOS NVME a continuación.

OPCIONES

Los argumentos de las opciones largas son obligatorios también para las opciones cortas.

-d, --dev_dir=DIR
donde DIR es el directorio donde buscar los archivos especiales de dispositivo resultantes (o enlaces simbólicos de los mismos). Solo activo cuando '--result=0' (el valor por defecto) o '--result=2'. Si no se proporciona esta opción y DISPOSITIVO es un archivo especial de dispositivo, entonces se asume el directorio de DISPOSITIVO. Si no se proporciona esta opción y DISPOSITIVO es un nombre de sysfs, entonces se asume '/dev' como directorio si es necesario.
-g, --given_is=0 | 1
especifica que DISPOSITIVO es un archivo especial de dispositivo (cuando el argumento es 0) o un archivo 'dev' de sysfs (cuando el argumento es 1). El directorio padre de un archivo 'dev' de sysfs también es aceptado (por ejemplo, se aceptan '/sys/block/sda/dev' o '/sys/block/sda'). Normalmente, no es necesario proporcionar esta opción ya que esta utilidad primero verifica los archivos especiales (o enlaces simbólicos a archivos especiales) y, si no los encuentra, asume que se le ha proporcionado un archivo 'dev' de sysfs (o su padre). Genera un error si se proporciona y entra en conflicto con el tipo de DISPOSITIVO.
-h, --help
muestra el mensaje de uso y sale.
-r, --result=0 | 1 | 2 | 3
especifica qué tipo de archivo (o archivos) intenta encontrar esta utilidad. El valor por defecto es un archivo especial de dispositivo "mapeado", cuando el argumento es 0. Cuando el argumento es 1, esta utilidad intenta encontrar el nombre del nodo sysfs "mapeado". Cuando el argumento es 2, esta utilidad intenta encontrar el archivo especial de dispositivo "coincidente". Cuando el argumento es 3, esta utilidad intenta encontrar el nodo sysfs "coincidente".
-s, --symlink
cuando se busca un archivo especial de dispositivo (es decir, cuando '--result=0' (el valor por defecto) o '--result=2'), busca también enlaces simbólicos a ese archivo especial de dispositivo en el mismo directorio.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración).
-V, --version
imprime la cadena de versión y sale.

BSG Y DISPOSITIVOS NVME

El controlador bsg (Block Scsi Generic) presenta dispositivos de carácter Unix alternativos de la forma: /dev/bsg/<h:c:t:l>. <h:c:t:l> es una tupla de 4 elementos donde 'h' es el número de host, 'c' es el número de controlador, 't' es el identificador de destino y 'l' es el LUN (Logical Unit Number). Aparte de los nombres de dispositivo bsg, cada dispositivo, una vez abierto (), opera de forma similar a un dispositivo sg: una interfaz genérica a nivel de comando SCSI.

Si se le proporciona un dispositivo bsg a esta utilidad, primero intentará mapearlo a un dispositivo de bloque SCSI. Este será de la forma /dev/sd<letras> para un disco o /dev/sr<número> para una unidad BD/DVD o CD. Si no se encuentra ninguna coincidencia, se realiza una comprobación de una unidad de cinta SCSI con un nombre de la forma /dev/st<número>. Si esto falla, se realiza el mapeo al dispositivo sg correspondiente. Si se proporciona la opción --result=2, se omiten las comprobaciones de dispositivos de bloque y de cinta y se realiza el mapeo al dispositivo sg correspondiente.

Tenga en cuenta que esta utilidad no realiza ningún mapeo a un dispositivo bsg. Eso es bastante fácil de establecer usando la utilidad lsscsi, ya que la tupla de 4 elementos <h:c:t:l> se muestra al principio de cada línea (por defecto) y identifica de forma única cada dispositivo SCSI. Cada línea también mostrará el nombre del dispositivo principal y, si se proporciona la opción --generic, el nodo del dispositivo sg.

Actualmente, los nodos de dispositivos NVMe vienen en varias variedades: dispositivos de bloque de la forma: /dev/nvme<c>n<n>[p<pn>] donde <c> es el número de controlador (empezando por 0), <n> es el identificador de namespace (empezando por 1) y <pn> es el número de partición (empezando por 1). Hay dos formas de nodos de dispositivo de carácter NVMe: una de la forma /dev/nvme<c> y la otra de la forma /dev/ng<c>n<n> donde "ng" es más reciente y se denomina 'nvme-generic' en la salida de /proc/devices. Esta utilidad identifica pero no mapea dispositivos NVMe. Sus nombres son más consistentes, por lo que una utilidad como esta es menos necesaria. Udev podría usarse para remapear el esquema de nombres del kernel para NVMe, eliminando su consistencia de nombres inherente.

NOTAS

Esta utilidad está diseñada para la serie de kernels Linux 2.6 (y posteriores). Utiliza números principales y menores de archivos especiales (y si el especial es de bloque o de carácter) junto con sysfs para hacer su mapeo o coincidencia. En ausencia de cualquier otra información, se asume que los archivos especiales de dispositivo están en el directorio '/dev' mientras que se asume que sysfs está montado en '/sys'. Los nombres de los dispositivos en sysfs son predecibles, dado el número principal y menor correspondiente del dispositivo. Sin embargo, debido a las reglas de udev, el nombre de los archivos especiales de dispositivo puede ser cualquiera que desee el usuario (por ejemplo, '/dev/sda' podría llamarse '/dev/my_boot_disk'). Al intentar encontrar un archivo especial de dispositivo resultante, esta utilidad utiliza los números principales y menores (y si se busca un dispositivo de bloque o de carácter) para buscar en el directorio de dispositivos.

Esta utilidad solo muestra una relación a la vez. Para obtener una visión general de todos los dispositivos SCSI, con nombres de archivos especiales y opcionalmente el nombre del dispositivo sg "mapeado", consulte la utilidad lsscsi.

Aunque lsscsi es un reemplazo funcional para esta utilidad, se ha informado que esta utilidad se ejecuta más rápido en sistemas que tienen muchos discos conectados. Teóricamente, un sistema Linux puede tener hasta 16383 discos SCSI conectados.

EJEMPLOS

Supongamos que sg2 se mapea a sdb mientras que dvd, cdrom y hdc son todos coincidentes.


# sg_map26 /dev/sg2
/dev/sdb


# sg_map26 /dev/sdb
/dev/sg2


# sg_map26 --result=0 /dev/sdb
/dev/sg2


# sg_map26 --result=3 /dev/sdb
/sys/block/sda


# sg_map26 --result=1 /dev/sdb
/sys/class/scsi_generic/sg0

Ahora veamos '/dev/hdc' y similares


# sg_map26 /dev/hdc
<error: un dispositivo hd no se mapea a un dispositivo sg>


# sg_map26 --result=3 /dev/hdc
/sys/block/hdc

sg_map26(8)

NAME

sg_map26 - list block devices (e.g., SATA, SCSI, USB) that are mapped to sg devices.

SYNOPSIS

sg_map26 [OPTIONS] [DEVICE]

DESCRIPTION

Prints a list of block devices (e.g., SATA, SCSI, USB storage devices) that are mapped to sg devices. For each matching block device, its sg device name (e.g., /dev/sg0) is printed. The output is one sg device name per line.

If the DEVICE argument is given, it must be a block device name (e.g., /dev/hdc) or its sysfs path (e.g., /sys/block/hdc). Only if the given DEVICE corresponds to an sg device will it be printed.

The block device name is derived from the information found in the sysfs filesystem. The mapping is usually done by the scsi_mod module (for SCSI, CD, DVD, etc. devices) or the usb_storage module (for USB storage devices).

OPTIONS

-h, --help
Print out the usage message then exit.
-r, --result=N
Sets the exit status code. The default value is 2. This option is mainly for testing. Exit status 0 means success (at least one sg device was found). Exit status N means failure.
-s, --symlink
Prints any symlink names associated with the sg device. These are often found in the /dev/ directory, e.g. /dev/cdrom, /dev/dvd or /dev/cdrw.
-v, --verbose
Increase the level of verbosity, and print the scanned sysfs directory name.
-V, --version
Print the version string and then exit.

BSG and NVME DEVICES

This utility is primarily for mapping block devices to sg devices. Devices accessed via the BSG interface (e.g. NVMe block devices) are not listed.

NOTES

This utility requires access to the sysfs filesystem, usually mounted at /sys.

EXAMPLES

List the sg device mapped to the block device /dev/hdc:


# sg_map26 --result=2 /dev/hdc
/dev/hdc

List any symlinks associated with the sg device mapped to /dev/hdc:


# sg_map26 --result=2 --symlink /dev/hdc
/dev/cdrom
/dev/dvd
/dev/hdc

List any symlinks associated with the sg device mapped to the sysfs path /sys/block/hdc:


# sg_map26 --result=2 --symlink /sys/block/hdc
/dev/cdrom
/dev/dvd
/dev/hdc

EXIT STATUS

The exit status of sg_map26 is 0 when it is successful. Otherwise see the sg3_utils(8) man page.
