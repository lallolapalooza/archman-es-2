NOMBRE

sg_reassign - envía el comando SCSI REASSIGN BLOCKS

SINOPSIS

sg_reassign [--dirección=D,D...] [--dummy] [--ocho=0|1] [--crecido] [--ayuda] [--hex] [--listalong=0|1] [--primario] [--verboso] [--versión] DISPOSITIVO

DESCRIPCIÓN

Envía un comando SCSI REASSIGN BLOCKS al DISPOSITIVO. Alternativamente, esta utilidad puede encontrar el número de elementos en una lista de defectos "crecida" o "primaria" con un comando SCSI READ DEFECT DATA (10). Estos comandos SCSI están definidos en SBC-2 para dispositivos de acceso directo (por ejemplo, un disco). Reassign blocks está diseñado para cambiar la ubicación física de un bloque lógico que se sabe o se sospecha que está defectuoso a otra área del medio. Los discos suelen formatearse con bloques reservados para esta situación.

Si no se proporciona la opción --crecido ni --primario, se deben proporcionar una o más direcciones. Si la dirección (o todas las direcciones) caben en 4 bytes y no se proporciona '--ocho=1', el bloque de parámetros que se pasa al DISPOSITIVO se compone de direcciones de bloque lógico de 4 bytes. Si alguna de las direcciones necesita más de 4 bytes para representarse (es decir, >= 2**32) o se proporciona '--ocho=1', el bloque de parámetros que se pasa al DISPOSITIVO se compone de direcciones de bloque lógico de 8 bytes.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas. Las opciones están ordenadas alfabéticamente según el nombre de la opción larga.

-a, --dirección=D,D...
donde D,D... es una cadena de números separados por comas. Cada número se interpreta como decimal a menos que vaya precedido por '0x' o '0X' (o tenga una 'h' o 'H' al final). Si se dan múltiples direcciones de bloque lógico, deben estar separadas por una coma o un espacio (único). Una cadena que contenga separadores de espacio debe ir entre comillas. Debe proporcionarse al menos una dirección.
-a, --dirección=-
lee una o más direcciones de bloque lógico desde la entrada estándar. Estas pueden estar separadas por comas, espacios, tabulaciones o saltos de línea. Si una línea contiene "#", los caracteres restantes de esa línea se ignoran. De lo contrario, cada secuencia de caracteres que no sea un separador debe resolverse en un número decimal a menos que vaya precedido por '0x' o '0X' (o tenga una 'h' al final). Debe proporcionarse al menos una dirección. Las líneas no deben tener más de 1023 bytes.
-d, --dummy
prepara pero no ejecuta el comando SCSI REASSIGN BLOCKS. Dado que el comando REASSIGN BLOCKS es esencialmente irreversible, los usuarios paranoicos pueden desear verificar la invocación de esta utilidad antes de reasignar bloques defectuosos en un disco. Útil con '-vv' para aquellos que deseen ver el bloque de parámetros que acompañará al comando.
-e, --ocho=0 | 1
cuando el valor es 1, establece el indicador 'LONGLBA' en el comando, lo que indica que las direcciones en el bloque de parámetros asociado son cantidades de 8 bytes. Cuando el valor es 0, borra el indicador 'LONGLBA' en el comando, lo que indica que las direcciones en el bloque de parámetros asociado son cantidades de 4 bytes. Si esta opción no se proporciona, se asumen cantidades de 4 bytes a menos que alguna de las direcciones sea demasiado grande.
-g, --crecido
utiliza el comando SCSI READ DEFECT DATA (10) para determinar el número de elementos en la "lista de defectos crecida". Cuando se proporciona esta opción, no se realiza reasignación de bloques (es decir, esta utilidad es pasiva). Cuando se proporciona esta opción, la opción --dirección= no está permitida. Ver la discusión a continuación sobre la relación entre bloques reasignados y la lista de defectos crecida. Esta lista a veces se denomina GLIST.
-h, --ayuda
muestra el mensaje de uso y luego sale.
-H, --hex
imprime la respuesta en hexadecimal (para -g, --crecido, -p o --primario).
-l, --listalong=0 | 1
establece el campo cdb de REASSIGN BLOCKS del mismo nombre al valor dado. Solo se permiten 1000 direcciones, por lo que no debería ser necesario especificar un valor de 1. La variante de lista corta restringe la longitud del bloque de parámetros a 2 ** 16 bytes (es decir, aproximadamente 16000 direcciones de 4 bytes u 8000 direcciones de 8 bytes). Añadido por completitud.
-p, --primario
utiliza el comando SCSI READ DEFECT DATA (10) para determinar el número de elementos en la "lista de defectos primaria", que se establece durante el proceso de fabricación. Cuando se proporciona esta opción, no se realiza reasignación de bloques (es decir, esta utilidad es pasiva). Cuando se proporciona esta opción, la opción --dirección= no está permitida. Esta lista se denomina a veces PLIST.
-v, --verboso
aumenta el nivel de verbosidad (es decir, salida de depuración).
-V, --versión
imprime la cadena de versión y luego sale.

NOTAS

Tenga en cuenta que si los campos ARRE (para lecturas) y/o AWRE (para escrituras) están establecidos en la página de modo "Read Write Error Recovery", los errores de lectura y/o escritura recuperables causan la reasignación automática del bloque defectuoso. El bit PER en la misma página de modo controla si se informa o no una clave de sentido de ERROR RECUPERADO (PER=1 implica informar). Independientemente de la configuración de los campos ARRE, AWRE o PER, las páginas de registro del contador de errores reflejan cualquier error (recuperado o no). Cada vez que se reasigna un bloque, se añade una nueva entrada en la lista de defectos "crecida". Además de realizar auto-pruebas (ver sg_senddiag o smartmontools) regularmente, monitorizar la lista de defectos crecida de un disco es una métrica razonable de su salud. Si la lista crecida comienza a crecer rápidamente, es una señal ominosa. Las mejores listas de defectos crecidas son las vacías. El número de elementos en la lista de defectos crecida se puede ver con la opción --crecido. El contenido de la lista de defectos crecida se puede ver con la utilidad 'sginfo -G'.

Si se detecta un error irrecuperable en una dirección de bloque lógico, se necesita REASSIGN BLOCKS para reasignar el bloque. También, si los campos ARRE y/o AWRE están borrados y se detecta un error recuperable, el bloque lógico en cuestión puede reasignarse con esta utilidad (de lo contrario, las páginas de registro del contador de errores se incrementarán continuamente por cada acceso recuperado).

El número de bloques reservados para los fines de REASSIGN BLOCKS es específico del proveedor y puede limitarse a la zona dentro del medio donde residía el bloque original (defectuoso). Cuando este número se agota, las invocaciones posteriores de esta utilidad pueden resultar en una clave de sentido de error de hardware y un sentido adicional de 'No hay ubicación de repuesto disponible para defectos'. El siguiente paso sería reformatear el disco (o conseguir un reemplazo).

El borrador del estándar SBC-2 (revisión 16) señala que cuando se proporcionan múltiples direcciones al comando SCSI REASSIGN BLOCKS y hay alguna falla en una de las direcciones posteriores, todas las direcciones anteriores ya han sido reasignadas. Se debe tener cuidado en tal caso. Volver a ejecutar el comando con las mismas direcciones hará que las direcciones anteriores se reasignen nuevamente. En algún momento, el disco se quedará sin ubicaciones reservadas. Por lo tanto, a menos que se trate un gran número de direcciones, puede ser más seguro reasignarlas una dirección a la vez.

ESTADO DE SALIDA

El estado de salida de sg_reassign es 0 cuando tiene éxito. De lo contrario, consulte la página del manual de sg3_utils(8).
