NOMBRE

sg_reset - envía un reinicio de dispositivo, destino, bus o host SCSI; o verifica el estado del reinicio

SINOPSIS

sg_reset [--bus] [--device] [--help] [--host] [--no-esc] [--target] [--verbose] [--version] DISPOSITIVO

DESCRIPCIÓN

La utilidad sg_reset sin opciones (solo un DISPOSITIVO) informa sobre el estado de reinicio (por ejemplo, si un reinicio está en curso) del DISPOSITIVO. Cuando se le da una opción --device, --target, --bus o --host, solicita un reinicio de dispositivo, destino, bus o host, respectivamente.

Un reinicio de dispositivo se aplica a la Unidad Lógica (LU) correspondiente a DISPOSITIVO. Es muy probable que un Controlador de Bajo Nivel (LLD) en Linux lo implemente como una función de gestión de tareas de REINICIO DE UNIDAD LÓGICA.

La capacidad de reiniciar un destino SCSI se añadió en el kernel de Linux 2.6.27. Un LLD puede enviar a los Controladores de Bajo Nivel (LLDs) la función de gestión de tareas I_T NEXUS RESET. Alternativamente, puede usar un mecanismo de transporte para hacer lo mismo (por ejemplo, un reinicio completo en el enlace que contiene un destino SAS).

En los kernels de Linux 2.6 y 3, esta utilidad se puede llamar en nodos de dispositivo sd, sr (cd/dvd), st o sg; si el usuario tiene los permisos adecuados.

Los usuarios de esta utilidad pueden verificar si ya se está recuperando un reinicio antes de intentar enviar un nuevo reinicio con esta utilidad. Llamar a esta utilidad sin opciones, solo con el DISPOSITIVO, hará tal verificación.

OPCIONES

-b, --bus
intenta un reinicio de bus SCSI. Un reinicio de bus es un concepto de Interfaz Paralela SCSI (SPI) que no se encuentra en los transportes modernos. Un LLD reciente puede implementarlo como una serie de reinicios en los destinos que podrían considerarse hermanos del destino en la ruta del DISPOSITIVO.
-d, --device
intenta un reinicio de dispositivo SCSI. Esto implicaría típicamente enviar una función de gestión de tareas de REINICIO DE UNIDAD LÓGICA al DISPOSITIVO.
-z, --help
imprime el mensaje de uso y luego sale.
-H, --host
intenta un reinicio de host. El "host" en este contexto a menudo se llama Adaptador de Bus Host (HBA) y contiene uno o más iniciadores SCSI.
-N, --no-esc
sin esta opción, si un reinicio de dispositivo (--device) falla, escalará a un reinicio de destino. Y si un reinicio de destino (--target) falla, escalará a un reinicio de bus. Y si un reinicio de bus (--bus) falla, escalará a un reinicio de host. Con esta opción, solo se intenta el reinicio solicitado. También se acepta un nombre de opción alternativo de --no-escalate.
--no-escalate
Igual que -N, --no-esc.
-t, --target
intenta un reinicio de destino SCSI. Un destino SCSI contiene una o más LU. Esto implicaría típicamente enviar una función de gestión de tareas I_T NEXUS RESET al DISPOSITIVO. Puede haber una acción de transporte equivalente (por ejemplo, en SAS un reinicio completo en el enlace que contiene el destino).
-v, --verbose
aumenta el grado de verbosidad (mensajes de depuración).
-V, --version
imprime la cadena de versión y luego sale.

NOTAS

El código de recuperación de errores dentro del kernel de Linux (nivel medio SCSI), al enfrentarse a un tiempo de espera de un comando SCSI y sin respuesta del dispositivo (LU), hace lo siguiente. Primero intenta un reinicio de dispositivo y si no tiene éxito, intenta un reinicio de destino. Si eso no tiene éxito, intenta un reinicio de bus. Si eso no tiene éxito, intenta un reinicio de host. El orden "dispositivo, destino, bus, host" es la escalada de reinicio que la opción --no-esc intenta detener. En configuraciones de almacenamiento grandes, la escalada puede ser (muy) indeseable.

Esta utilidad llama al ioctl SG_SCSI_RESET y, a partir de lk 3.10.7, la opción --no-esc no es compatible. Los parches para implementar esta funcionalidad pueden ser aceptados en lk 3.18 o 3.19.

SAM-4 y 5 definen un reinicio completo, un REINICIO DE UNIDAD LÓGICA y un REINICIO I_T NEXUS. Un reinicio completo se define como una condición de encendido, un cambio de microcódigo o un evento de reinicio de transporte. REINICIO DE UNIDAD LÓGICA y REINICIO I_T NEXUS se pueden solicitar a través de funciones de gestión de tareas (y el soporte para REINICIO DE UNIDAD LÓGICA es obligatorio). En Linux, el subsistema SCSI deja en manos de los LLD determinar exactamente qué tipo (si alguno) de reinicio se realiza. El "reinicio de bus" es un concepto de Interfaz Paralela SCSI (SPI) que puede no mapear bien a los transportes SCSI recientes, por lo que puede ser una operación ficticia. Un "reinicio de host" intenta reinicializar el HBA por el que pasa la solicitud en ruta al DISPOSITIVO. Tenga en cuenta que un "reinicio de host" y un "reinicio de bus" pueden causar daños colaterales.

Esta utilidad no permite abortar comandos SCSI individuales. SAM-4 define las funciones de gestión de tareas ABORT TASK y ABORT TASK SET para eso.

Antes de SAM-3 existía una función de gestión de tareas TARGET RESET. Y en SAM-4 apareció I_T NEXUS RESET, que parece estrechamente relacionado: "I_T" significa Initiator-Target.

Los transportes pueden tener sus propios tipos de reinicios no soportados por esta utilidad. Por ejemplo, SAS tiene un reinicio de enlace en el que ambos extremos de un enlace físico (por ejemplo, entre un expansor SAS y una unidad de cinta SAS) renegocian su conexión.

Antes de la versión 0.57 de esta utilidad, la línea de comandos solo tenía opciones cortas (por ejemplo, -d pero no --device). Además, -h invocaba un reinicio de host, mientras que en la versión actual -h es equivalente a --help y tanto -H como --host invocan un reinicio de host. Para compatibilidad con versiones anteriores, defina la variable de entorno SG3_UTILS_OLD_OPTS o SG_RESET_OLD_OPTS. En este caso, -h invocará un reinicio de host y la salida será detallada como lo era anteriormente (equivalente a usar la opción --verbose ahora). Por ejemplo:


SG_RESET_OLD_OPTS=1 sg_reset -h /dev/sg1
sg_reset: starting host reset
sg_reset: completed host reset

VARIABLES DE ENTORNO

Desde la versión 1.23 de sg3_utils, se pueden proporcionar las variables de entorno SG3_UTILS_OLD_OPTS o SG_RESET_OLD_OPTS. Cuando alguna esté presente, esta utilidad esperará las opciones de línea de comandos anteriores, como se describe en la sección NOTAS.

sg_reset(8)

sg_reset - reset SCSI devices or bus

SYNOPSIS

sg_reset [OPTIONS] DEVICE...

DESCRIPTION

The sg_reset utility is used to reset SCSI devices or the SCSI bus. It can be used to reset individual devices or all devices on a bus.

OPTIONS

-b, --bus
Reset the entire SCSI bus. This will reset all devices on the bus.
-d, --device
Reset the specified device. This is the default behavior if no option is given.
-r, --reset-type=TYPE
Specify the type of reset to perform. TYPE can be:
  • bus: Reset the SCSI bus.
  • device: Reset the specified device.
  • target: Reset the target containing the specified device.
-v, --verbose
Increase verbosity.
-h, --help
Display help text and exit.
-V, --version
Display version information and exit.

EXAMPLES

Reset a specific SCSI device:

sg_reset /dev/sg0

Reset all devices on the SCSI bus:

sg_reset --bus /dev/sg0

Reset the target containing the specified device:

sg_reset --reset-type=target /dev/sg0
