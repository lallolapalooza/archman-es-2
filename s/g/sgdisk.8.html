SGDISK(8) Manual de GPT fdisk SGDISK(8)

NOMBRE

sgdisk - Manipulador de tabla de particiones GUID (GPT) de línea de comandos para Linux y Unix

SINOPSIS

sgdisk [ opciones ] dispositivo

DESCRIPCIÓN

GPT fdisk es un paquete interactivo en modo texto para la creación y manipulación de tablas de particiones. Consiste en dos programas: el interactivo gdisk en modo texto y el de línea de comandos sgdisk. Cualquiera de los programas convertirá automáticamente una tabla de particiones MBR (Master Boot Record) antigua o un disklabel BSD almacenado sin una partición portadora MBR al formato más nuevo de tabla de particiones GUID (GPT), o cargará una tabla de particiones GUID. Esta página del manual documenta el programa sgdisk de línea de comandos.

Algunas opciones avanzadas de manipulación y recuperación de datos requieren que comprendas las distinciones entre los datos principales y de respaldo, así como entre las cabeceras GPT y las tablas de particiones. Para obtener información sobre MBR vs. GPT, así como sobre la terminología y estructura de GPT, consulta la documentación extendida de gdisk en https://www.rodsbooks.com/gdisk/ o consulta Wikipedia.

El programa sgdisk emplea una interfaz de usuario basada enteramente en la línea de comandos, lo que lo hace adecuado para su uso en scripts o por expertos que desean realizar uno o dos cambios rápidos en un disco. (El programa puede consultar al usuario cuando se encuentran ciertos errores, sin embargo.) El nombre del programa se basa en sfdisk, pero las opciones de usuario de los dos programas son completamente diferentes entre sí.

Por lo general, sgdisk opera en archivos de dispositivos de disco, como /dev/sda o /dev/hda en Linux, /dev/disk0 en Mac OS X, o /dev/ad0 o /dev/da0 en FreeBSD. El programa también puede operar en archivos de imagen de disco, que pueden ser copias de discos completos (hechas con dd, por ejemplo) o imágenes de disco sin procesar utilizadas por emuladores como QEMU o VMWare. Ten en cuenta que solo se admiten imágenes de disco *sin procesar*; sgdisk no puede trabajar con formatos de imagen de disco comprimidos u otros avanzados.

El sistema de particionado MBR utiliza una combinación de direccionamiento de cilindro/cabezal/sector (CHS) y direccionamiento de bloques lógicos (LBA). El primero es torpe y limitante. GPT elimina el direccionamiento CHS y utiliza el modo LBA de 64 bits exclusivamente. Por lo tanto, las estructuras de datos GPT, y por ende sgdisk, no necesitan tratar con geometrías CHS y todos los problemas que crean.

Para obtener los mejores resultados, debes utilizar un programa de tabla de particiones específico del sistema operativo siempre que sea posible. Por ejemplo, debes crear particiones de Mac OS X con el programa Disk Utility de Mac OS X y particiones de Linux con los programas gdisk, sgdisk o GNU Parted de Linux.

Al inicio, sgdisk intenta identificar el tipo de partición en uso en el disco. Si encuentra datos GPT válidos, sgdisk los utilizará. Si sgdisk encuentra un MBR válido o un disklabel BSD pero ningún dato GPT, intentará convertir el MBR o el disklabel a formato GPT. (Los disklabels BSD probablemente tendrán particiones iniciales y/o finales inutilizables porque se superponen con las estructuras de datos GPT, ¡sin embargo!) GPT fdisk puede identificar, pero no usar datos de, discos con Mapa de Particiones de Apple (APM), que se utilizan en Macs basados en 680x0 y PowerPC. Si especificas alguna opción que resulte en cambios a un MBR o disklabel BSD, sgdisk ignorará esos cambios a menos que se use la opción -g (--mbrtogpt), -z (--zap) o -Z (--zap-all). Si usas la opción -g, sgdisk reemplaza el MBR o disklabel con un GPT. ¡Esta acción es potencialmente peligrosa! Tu sistema puede volverse inarrancable y los códigos de tipo de partición pueden corromperse si el disco utiliza códigos de tipo no reconocidos. Los problemas de arranque son particularmente probables si estás en multiarranque con algún sistema operativo no compatible con GPT.

La conversión de MBR a GPT dejará al menos un hueco en la numeración de particiones si el MBR original usaba particiones lógicas. Estos huecos son inofensivos, pero puedes eliminarlos usando la opción -s (--sort), si lo deseas. (Hacer esto puede requerir que actualices tu archivo /etc/fstab.)

Al crear una tabla de particiones nueva, se deben tener en cuenta algunas consideraciones:

*
Para discos de datos (no de arranque) y para discos de arranque utilizados en computadoras basadas en BIOS con GRUB como cargador de arranque, las particiones pueden crearse en cualquier orden y en los tamaños deseados.
*
Los discos de arranque para sistemas basados en EFI requieren una Partición del Sistema EFI (código interno de gdisk 0xEF00) formateada como FAT-32. Recomiendo crear esta partición de 550 MiB. (Son comunes las ESP más pequeñas, pero algunas EFI tienen controladores FAT defectuosos que requieren una partición más grande para un funcionamiento fiable). Los archivos relacionados con el arranque se almacenan aquí. (Ten en cuenta que GNU Parted identifica dichas particiones como si tuvieran la "bandera de arranque" establecida).
*
Algunos cargadores de arranque para sistemas basados en BIOS utilizan una Partición de Arranque BIOS (código interno de gdisk 0xEF02), en la que se almacena el cargador de arranque secundario, posiblemente sin el beneficio de un sistema de archivos. (GRUB2 puede usar opcionalmente dicha partición). Esta partición puede ser típicamente bastante pequeña (aproximadamente de 32 a 200 KiB, aunque 1 MiB es más común en la práctica), pero debes consultar la documentación de tu cargador de arranque para obtener detalles.
*
Si Windows va a arrancar desde un disco GPT, se recomienda una partición de tipo Reservado para Microsoft (código interno de sgdisk 0x0C01). Esta partición debería tener un tamaño de aproximadamente 128 MiB. Normalmente sigue a la Partición del Sistema EFI y precede inmediatamente a las particiones de datos de Windows. (Ten en cuenta que GNU Parted crea todas las particiones FAT como este tipo, lo que en realidad hace que la partición sea inutilizable para almacenamiento de archivos normal tanto en Windows como en Mac OS X).
*
Algunas utilidades GPT de sistemas operativos crean un espacio en blanco (típicamente 128 MiB) después de cada partición. La intención es permitir que las utilidades de disco futuras utilicen este espacio. Este espacio libre no es necesario para los discos GPT, pero crearlo puede ayudar en el mantenimiento futuro del disco.

OPCIONES

Algunas opciones no toman argumentos, otras toman un argumento (típicamente un número de partición), y otras toman argumentos compuestos delimitados por dos puntos. Por ejemplo, -n (--new) toma un número de partición, un número de sector de inicio y un número de sector de fin, como en sgdisk -n 2:2000:50000 /dev/sdc, que crea una nueva partición, numerada 2, que comienza en el sector 2000 y termina en el sector 50,000, en /dev/sdc.

Las opciones no relacionadas pueden combinarse; sin embargo, algunas de estas combinaciones serán absurdas (como eliminar una partición y luego cambiar su código de tipo GUID). sgdisk interpreta las opciones en el orden en que se ingresan, por lo que los efectos pueden variar según el orden. Por ejemplo, sgdisk -s -d 2 ordena las entradas de la tabla de particiones y luego elimina la partición 2 de la lista recién ordenada; pero sgdisk -d 2 -s elimina la partición 2 original y luego ordena la tabla de particiones modificada.

La comprobación de errores y las oportunidades para corregir errores en sgdisk son mínimas. Aunque el programa se esfuerza por mantener las estructuras de datos GPT legales, no solicita verificación antes de realizar sus acciones. A menos que necesites un programa dirigido por línea de comandos, deberías usar el gdisk interactivo en lugar de sgdisk, ya que gdisk te permite salir sin guardar tus cambios, si cometes un error.

Aunque sgdisk se basa en el mismo código de manipulación de particiones que gdisk, sgdisk implementa menos características que su hermano interactivo. Las opciones disponibles en sgdisk son:

-a, --set-alignment=valor
Establece el múltiplo de alineación de sectores. GPT fdisk alinea el inicio de las particiones a sectores que son múltiplos de este valor, que por defecto es 1 MiB (2048 en discos con sectores de 512 bytes) en discos recién formateados. Este valor de alineación es necesario para obtener un rendimiento óptimo con Western Digital Advanced Format y unidades similares con tamaños de sector físico mayores que los lógicos, con algunos tipos de matrices RAID y con dispositivos SSD. Cuando se utiliza la opción -I, este mismo valor de alineación se utiliza para determinar los puntos finales de las particiones; pero las particiones terminan en un número menor que un múltiplo de este valor, para que la longitud de la partición sea un múltiplo de este valor.
-A, --attributes=lista|[partnum:mostrar|o|nand|xor|=|establecer|borrar|conmutar|obtener[:bitnum|mascarahexbit]]
Ver o establecer atributos de partición. Usa lista para ver los valores de atributos definidos (conocidos). Omite la partición
número (e incluso el nombre del archivo del dispositivo) al usar esta opción. Los otros requieren un número de partición. Las opciones show y get muestran la configuración actual de los atributos (todos los atributos o para un bit particular, respectivamente). Las opciones or, nand, xor, =, set, clear y toggle le permiten cambiar el valor del bit del atributo. Las opciones set, clear, toggle y get funcionan en un número de bit; las otras funcionan en una máscara de bits hexadecimal. Por ejemplo, escriba sgdisk -A 4:set:2 /dev/sdc para establecer el atributo de bit 2 (arrancable por BIOS heredado) en la partición 4 en /dev/sdc.
-b, --backup=archivo
Guarda los datos de la partición en un archivo de respaldo. Puede hacer una copia de seguridad de su tabla de particiones actual en memoria en un archivo de disco usando esta opción. El archivo resultante es un archivo binario que consta del MBR protector, la cabecera GPT principal, la cabecera GPT de respaldo y una copia de la tabla de particiones, en ese orden. Tenga en cuenta que la copia de seguridad es de las estructuras de datos actuales en memoria, por lo que si inicia el programa, realiza cambios y luego usa esta opción, la copia de seguridad reflejará sus cambios. Si las estructuras de datos GPT están dañadas, es posible que la copia de seguridad no refleje con precisión el estado dañado; en cambio, reflejarán la interpretación de primer paso que GPT fdisk hace de la GPT.
-B, --byte-swap-name=num_part
Intercambia el orden de bytes del nombre de la partición especificada. Algunas herramientas de particionado, incluido GPT fdisk 1.0.7 y versiones anteriores, pueden escribir el nombre de la partición en el orden de bytes incorrecto en computadoras big-endian, como los mainframes IBM s390 y las Macintosh basadas en PowerPC. Esta característica corrige este problema.
-c, --change-name=num_part:nombre
Cambia el nombre GPT de una partición. Este nombre se codifica como una cadena UTF-16, pero la entrada y visualización correctas de cualquier cosa más allá de los valores ASCII básicos requiere soporte de locale y fuente adecuados. En su mayor parte, Linux ignora el nombre de la partición, pero puede ser importante en algunos sistemas operativos. Si desea establecer un nombre que incluya un espacio, envuélvalo entre comillas, como en sgdisk -c 1:"Nombre de ejemplo" /dev/sdb. Tenga en cuenta que el nombre GPT de una partición es distinto del nombre del sistema de archivos, que se codifica en las estructuras de datos del sistema de archivos.
-C, --recompute-chs
Recalcula los valores CHS en el MBR protector o híbrido. Esta opción a veces puede ayudar si una utilidad de disco, un sistema operativo o una BIOS no aceptan los valores CHS utilizados por las particiones en el MBR protector o híbrido. En particular, la especificación GPT requiere un valor CHS de 0xFFFFFF para particiones de más de 8 GiB, pero este valor es técnicamente ilegal según los estándares habituales. Algunas BIOS se bloquean si encuentran este valor. Esta opción recalculará un valor CHS más normal -- 0xFEFFFF para particiones de más de 8 GiB, permitiendo que estas BIOS arranquen.
-d, --delete=num_part
Elimina una partición. Esta acción elimina la entrada de la tabla de particiones pero no perturba los datos dentro de los sectores originalmente asignados a la partición en el disco. Si existe una partición MBR híbrida correspondiente, gdisk también la elimina y expande cualquier partición MBR adyacente 0xEE (EFI GPT) para llenar el nuevo espacio libre.
-D, --display-alignment
Muestra el valor actual de alineación de sectores. Las particiones se crearán en múltiplos del valor de sector informado por esta opción. Puede cambiar el valor de alineación con la opción -a.
-e, --move-second-header
Mueve las estructuras de datos GPT de respaldo al final del disco. Use esta opción si ha agregado discos a una matriz RAID, creando así un disco virtual con espacio que sigue a las estructuras de datos GPT de respaldo. Este comando mueve las estructuras de datos GPT de respaldo al final del disco, donde pertenecen.
-E, --end-of-largest
Muestra el número de sector del final del bloque más grande de sectores disponible en el disco. Un script puede almacenar este valor y pasarlo como parte de la opción de -n para crear una partición. Si no hay sectores no asignados disponibles, esta función devuelve el valor 0.
-f, --first-in-largest
Muestra el número de sector del inicio del bloque más grande de sectores disponible en el disco. Un script puede almacenar este valor y pasarlo como parte de la opción de -n para crear una partición. Si no hay sectores no asignados disponibles, esta función devuelve el valor 0. Tenga en cuenta que este parámetro no tiene en cuenta la alineación de la partición; cuando cree realmente una partición, su punto de inicio podría cambiar de este valor.
-F, --first-aligned-in-largest
Similar a -f (--first-in-largest), excepto que devuelve el número de sector con la corrección de alineación actual aplicada. Use esta función si necesita calcular el punto de inicio real de la partición en lugar de un punto de inicio teórico o el punto de inicio real si establece el valor de alineación a 1.
-g, --mbrtogpt
Convierte un disco MBR o de etiqueta de disco BSD a un disco GPT. Como medida de seguridad, se requiere el uso de esta opción en discos MBR o de etiqueta de disco BSD si tiene la intención de guardar sus cambios, para evitar dañar accidentalmente dichos discos.
-G, --randomize-guids
Aleatoriza la GUID del disco y las GUID únicas de todas las particiones (pero no sus GUID de código de tipo de partición). Esta función puede usarse después de clonar un disco para hacer que todas las GUID vuelvan a ser únicas.
-h, --hybrid
Crea un MBR híbrido. Esta opción toma de uno a tres números de partición, separados por dos puntos, como argumentos. Opcionalmente, puede especificar una partición final "EE" para indicar que el GPT EFI (tipo 0xEE) debe colocarse al final de la tabla; de lo contrario, se colocará al principio, seguido de las particiones que especifique. Sus códigos de tipo se basan en los códigos de tipo de GPT fdisk divididos por 0x0100, lo que generalmente es correcto para las particiones de Windows. Si se debe establecer la bandera activa/arrancable, debe hacerlo en otro programa, como fdisk. El programa gdisk ofrece opciones adicionales de creación de MBR híbrido.
-i, --info=num_part
Muestra información detallada de la partición. La información resumida producida por el comando -p necesariamente omite muchos detalles, como la GUID única de la partición y la traducción del código de tipo de partición interno de sgdisk a un nombre de tipo simple. La opción -i muestra esta información para una sola partición.
-I, --align-end
Cuando sea posible, alinee los puntos finales de las particiones a uno menos que un múltiplo del valor de alineación. Cuando los puntos de inicio y fin están alineados, las particiones deben ser múltiplos del valor de alineación en tamaño, lo cual es necesario para que algunas herramientas de cifrado de particiones funcionen correctamente. Esta opción se aplica a todas las particiones creadas después de esta opción en la línea de comandos. Tenga en cuenta que esta alineación no siempre es posible; por ejemplo, si el espacio libre al final de un disco es menor que el valor de alineación, con la partición final actual alineada, y si a sgdisk se le pide que cree una partición en ese espacio, entonces no se alineará al final.
-j, --move-main-table=sector
Establece el sector de inicio de la tabla de particiones principal. Este valor es normalmente 2, pero puede necesitar aumentarse en algunos casos, como cuando un sistema en chip (SoC) está codificado para leer el código de arranque desde el sector 2. No recomiendo ajustar este valor a menos que sea absolutamente necesario.
-k, --move-backup-table=sector
Establece el sector de inicio de la tabla de particiones segunda/de respaldo. La tabla de respaldo generalmente se coloca justo antes del último sector, que contiene la cabecera de respaldo. Por lo tanto, el valor predeterminado es el tamaño del disco, menos uno, menos el tamaño total de la tabla de particiones (en sectores, generalmente 32). Probablemente haya muy pocas razones para cambiar esto, y aunque el estándar EFI no lo exige, la mayoría de las herramientas asumen que la tabla de respaldo está al final del disco.
-l, --load-backup=archivo
Carga los datos de la partición desde un archivo de respaldo. Esta opción es la inversa de la opción -b. Tenga en cuenta que no se recomienda restaurar datos de particiones desde nada que no sea el disco original. Esta opción funcionará incluso si la tabla de particiones original del disco está dañada; sin embargo, la mayoría de las otras opciones en la misma línea de comandos se ignorarán.
-L, --list-types
Muestra un resumen de los tipos de partición. GPT usa una GUID para identificar los tipos de partición para sistemas operativos y propósitos particulares. Para facilitar la entrada de datos, sgdisk los comprime en valores de dos bytes (cuatro dígitos hexadecimales) que están relacionados con sus códigos MBR equivalentes. Específicamente, el código MBR se multiplica por hexadecimal 0x0100. Por ejemplo, el código para el espacio de intercambio de Linux en MBR es 0x82, y es 0x8200 en gdisk. Sin embargo, no es posible una correspondencia uno a uno. En particular, los códigos para todas las variedades de particiones FAT y NTFS corresponden a un solo código GPT (introducido como 0x0700 en sgdisk). Algunos sistemas operativos usan un solo código MBR pero emplean muchos más códigos en GPT. Para estos, sgdisk agrega números de código secuencialmente, como 0xa500 para una etiqueta de disco FreeBSD, 0xa501 para arranque FreeBSD, 0xa502 para intercambio FreeBSD, y así sucesivamente. Tenga en cuenta que estos códigos de dos bytes son exclusivos de gdisk y sgdisk. Esta opción no requiere que especifique un nombre de archivo de dispositivo de disco válido.
-m, --gpttombr
Convierte el disco de formato GPT a MBR. Esta opción toma de una a cuatro particiones, separadas por dos puntos, como argumentos. Sus códigos de tipo se basan en los códigos de tipo de GPT fdisk divididos por 0x0100. Si se debe establecer la bandera activa/arrancable, debe hacerlo en otro programa, como fdisk. El programa gdisk ofrece opciones adicionales de conversión MBR. No es posible convertir más de cuatro particiones de GPT a formato MBR ni convertir particiones que comiencen por encima de la marca de 2 TiB o que sean mayores de 2 TiB.
-n, --new=num_part:inicio:fin
Crea una nueva partición. Ingresa un número de partición, el sector de inicio y el final

OPTIONS

-a, --set-alignment
Set partition alignment. You can use this option to adjust the alignment of new partitions. This option is most useful when creating the first partition on a disk, but can also be used to adjust the alignment of existing partitions. The alignment value is specified in sectors.
-A, --attributes=partnum:options
Set attributes for an individual partition. The options are a comma-separated list of attributes. Supported attributes include:
legacy_boot
Marks the partition as legacy bootable.
msft_reserved
Marks the partition as Microsoft reserved.
msft_data
Marks the partition as Microsoft data.
-b, --backup=filename
Write the main GPT data structure to the specified backup file.
-c, --change-name=partnum:name
Change the partition name. The name is a string of up to 36 characters.
-C, --clear-name=partnum
Clear the partition name.
-d, --delete=partnum
Delete the specified partition.
-D, --delete-all
Delete all partitions.
-e, --edit=partnum
Edit the specified partition. This option will launch an interactive editor for the partition's attributes.
-E, --move-backup
Move the backup GPT table to the end of the disk. This option is useful when the backup GPT table is located at the beginning of the disk and is preventing the creation of a new partition.
-f, --force
Force the operation to complete even if errors are encountered. Use with caution.
-g, --disk-guid=guid
Set the disk GUID. The GUID can be a standard GUID or 'R' to generate a random GUID.
-G, --partition-guid=partnum:guid
Set the partition GUID. The GUID can be a standard GUID or 'R' to generate a random GUID.
-h, --disk-layout=filename
Load disk layout from a file.
-i, --info
Display detailed information about the disk and its partitions.
-I, --immutable
Mark the disk as immutable. This prevents any further changes to the partition table.
-j, --mbr-force-westmere
Force MBR to use Westmere partition types.
-J, --mbr-force-guid
Force MBR to use GUID partition types.
-k, --legacy-blank
Create a blank MBR partition table.
-K, --legacy-import
Import MBR partition table.
-l, --load-partitions=filename
Load partitions from a file.
-L, --load-disk=filename
Load disk layout from a file.
-m, --move-partition=old_partnum:new_partnum
Move a partition to a new number.
-M, --move-free=partnum:new_start_sector
Move a free partition to a new start sector.
-n, --newpartition=partnum:start:end
Create a new partition. The start and end sectors can be specified in absolute terms as sector numbers or as positions measured in kibibytes (K), mebibytes (M), gibibytes (G), tebibytes (T), or pebibytes (P); for instance, 40M specifies a position 40MiB from the start of the disk. You can specify locations relative to the start or end of the specified default range by preceding the number by a '+' or '-' symbol, as in +2G to specify a point 2GiB after the default start sector, or -200M to specify a point 200MiB before the last available sector. A start or end value of 0 specifies the default value, which is the start of the largest available block for the start sector and the end of the same block for the end sector. A partnum value of 0 causes the program to use the first available partition number. Subsequent uses of the -A (--attributes), -c (--change-name), -t (--typecode), and -u (--partition-guid) options may also use 0 to refer to the same partition.
-N, --largest-new=num
Create a new partition that fills the largest available block of space on the disk. You can use the -a (--set-alignment) option to adjust the alignment, if desired. A num value of 0 causes the program to use the first available partition number. Subsequent uses of the -A (--attributes), -c (--change-name), -t (--typecode), and -u (--partition-guid) options may also use 0 to refer to the same partition.
-o, --clear
Clear out all partition data. This includes GPT header data, all partition definitions, and the protective MBR. Note that this operation will, like most other operations, fail on a damaged disk. If you want to prepare a disk you know to be damaged for GPT use, you should first wipe it with -Z and then partition it normally. This option will work even if the disk's original partition table is bad; however, most other options on the same command line will be ignored.
-O, --print-mbr
Display basic MBR partition summary data. This includes partition numbers, starting and ending sector numbers, partition sizes, MBR partition types codes, and partition names. This option is useful mainly for diagnosing partition table problems, particularly on disks with hybrid MBRs.
-p, --print
Display basic GPT partition summary data. This includes partition numbers, starting and ending sector numbers, partition sizes, sgdisk's partition types codes, and partition names. For additional information, use the -i (--info) option.
-P, --pretend
Pretend to make specified changes. In-memory GPT data structures are altered according to other parameters, but changes are not written to disk.
-r, --transpose
Swap two partitions' entries in the partition table. One or both partitions may be empty, although swapping two empty partitions is pointless. For instance, if partitions 1-4 are defined, transposing 1 and 5 results in a table with partitions numbered from 2-5. Transposing partitions in this way has no effect on their disk space allocation; it only alters their order in the partition table.
-R, --replicate=second_device_filename
Replicate the main device's partition table on the specified second device. Note that the replicated partition table is an exact copy, including all GUIDs; if the device should have its own unique GUIDs, you should use the -G option on the new disk.
-s, --sort
Sort partition entries. GPT partition numbers need not match the order of partitions on the disk. If you want them to match, you can use this option. Note that some partitioning utilities sort partitions whenever they make changes. Such changes will be reflected in your device filenames, so you may need to edit /etc/fstab if you use this option.
-t, --typecode=partnum:{hexcode|GUID}
Change a single partition's type code. You enter the type code using either a two-byte hexadecimal number, as described earlier, or a fully-specified GUID value, such as EBD0A0A2-B9E5-4433-87C0-68B6B72699C7.
-T, --transform-bsd=partnum
Transform BSD partitions into GPT partitions. This option works on BSD disklabels held within GPT (or converted MBR) partitions. Converted partitions' type codes are likely to need manual adjustment. sgdisk will attempt to convert BSD disklabels stored on the main disk when launched, but this conversion is likely to produce first and/or last partitions that are unusable. The many BSD variants means that the probability of sgdisk being unable to convert a BSD disklabel is high compared to the likelihood of problems with an MBR conversion.
-u, --partition-guid=partnum:guid
Set the partition unique GUID for an individual partition. The GUID may be a complete GUID or 'R' to set a random GUID.
-U, --disk-guid=guid
Set the GUID for the disk. The GUID may be a complete GUID or 'R' to set a random GUID.
--usage
Print a brief summary of available options.
-v, --verify
Verify disk. This option checks for a variety of problems, such as incorrect CRCs and mismatched main and backup data. This option does not automatically correct most problems, though; for that, you must use options on the recovery & transformation menu. If no problems are found, this command displays a summary of unallocated disk space. This option will work even if the disk's original partition table is bad; however, most other options on the same command line will be ignored.
-V, --version
Display program version information. This option may be used without specifying a device filename.
-z, --zap
Zap (destroy) the GPT data structures and then exit. Use this option if you want to repartition a GPT disk using fdisk or some other GPT-unaware program. This option destroys only the GPT data structures; it leaves the MBR intact. This makes it useful for wiping out GPT data structures after a disk has been repartitioned for MBR using a GPT-unaware utility; however, there's a risk that it will damage boot loaders or even the start of the first or end of the last MBR partition. If you use it on a valid GPT disk, the MBR will be left with an inappropriate EFI GPT (0xEE) partition definition, which you can delete using another utility.
-Z, --zap-all
Zap (destroy) the GPT and MBR data structures and then exit. This option works much like -z, but as it wipes the MBR as well as the GPT, it's more suitable if you want to repartition a disk after using this option, and completely unsuitable if you've already repartitioned the disk.

Print a summary of options.

ERRORES

Los errores y limitaciones conocidos incluyen:

*
El programa solo compila correctamente en Linux, FreeBSD y Mac OS X. Se han probado las versiones de Linux para x86-64 (64 bits), x86 (32 bits) y PowerPC (32 bits), siendo la versión x86-64 la que ha visto más pruebas.
*
La versión de FreeBSD del programa no puede escribir cambios en la tabla de particiones de un disco cuando las particiones existentes en ese disco están montadas. (El mismo problema existe con muchas otras utilidades de FreeBSD, como gpt, fdisk y dd). Esta limitación se puede superar escribiendo sysctl kern.geom.debugflags=16 en un prompt de shell.
*
Los campos utilizados para mostrar los números de sector de inicio y fin de las particiones en la opción -p tienen un ancho de 14 caracteres. Esto se traduce en una limitación de aproximadamente 45 PiB. En discos más grandes, las columnas mostradas se desalinearán.
*
El programa solo puede cargar hasta 128 particiones (4 particiones primarias y 124 particiones lógicas) al convertir desde el formato MBR. Este límite se puede aumentar cambiando la línea #define MAX_MBR_PARTS en el archivo de código fuente basicmbr.h y recompilando; sin embargo, dicho cambio requerirá el uso de una tabla de particiones más grande de lo normal. (El límite de 128 particiones se eligió porque ese número es igual a las 128 particiones admitidas por el tamaño de tabla de particiones más común).
*
La conversión desde formato MBR a veces falla debido a espacio insuficiente al principio o (más comúnmente) al final del disco. Redimensionar la tabla de particiones (usando la opción 's' en el menú de expertos) a veces puede superar este problema; sin embargo, en casos extremos puede ser necesario redimensionar una partición usando GNU Parted o una herramienta similar antes de la conversión con gdisk.
*
Las conversiones MBR solo funcionan si el disco tiene descriptores de partición LBA correctos. Estos descriptores deberían estar presentes en cualquier disco de más de 8 GiB de tamaño o en discos más pequeños particionados con cualquier software excepto el muy antiguo.
*
El soporte de etiquetas de disco BSD puede crear particiones iniciales y/o finales que se superponen con las estructuras de datos GPT. Esto a veces se puede compensar ajustando el tamaño de la tabla de particiones, pero en casos extremos, el efecto

BUGS

MBR and BSD disklabel conversion routines are complex and have not been as thoroughly tested as the other parts of this package. As a consequence, these routines may have bugs.

*
Some disk label structures may cause the conversion routines to fail or produce incorrect results. This is particularly true for non-standard or corrupted disk labels.
*
The conversion routines assume that the disk label contains valid partition information. If the disk label is corrupted or contains invalid entries, the conversion may fail or produce unexpected results. For example, partitions that extend beyond the end of the disk may cause errors. You may need to use a partitioning tool like fdisk(8) or parted(8) to fix the partition table before conversion. In some cases, partitions may need to be deleted.
*
Debido a la naturaleza altamente variable de las estructuras de las etiquetas de disco BSD, las conversiones desde esta forma pueden ser poco fiables: las particiones pueden ser descartadas, convertidas de forma que creen solapamientos con otras particiones, o convertidas con valores de inicio o fin incorrectos. ¡Utilice esta función con precaución!
*
El arranque después de convertir un disco MBR o con etiqueta de disco BSD probablemente se verá interrumpido. A veces, reinstalar un cargador de arranque solucionará el problema, pero otras veces puede que necesite cambiar de cargador de arranque. Excepto en plataformas basadas en EFI, Windows (al menos hasta Windows 7 RC) no admite el arranque desde discos GPT. Crear un MBR híbrido (usando la opción 'h' en el menú de recuperación y transformación) o abandonar GPT en favor de MBR pueden ser sus únicas opciones en este caso.
