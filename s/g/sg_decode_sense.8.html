NOMBRE

sg_decode_sense - decodifica datos de sentido SCSI y relacionados

SINOPSIS

sg_decode_sense [--binary=BFN] [--cdb] [--err=ES] [--file=HFN] [--help] [--hex] [--inhex=HFN] [--ignore-first] [--json[=JO]] [--js-file=JFN] [--nodecode] [--nospace] [--status=SS] [--verbose] [--version] [--write=WFN] [H1 H2 H3 ...]

DESCRIPCIÓN

Esta utilidad toma datos de sentido SCSI en binario o como una secuencia de bytes hexadecimales ASCII y los decodifica. La referencia principal para la decodificación es SPC-5 ANSI INCITS 502-2020 y la revisión más reciente del borrador SPC-6 número 6 que se puede encontrar en https://www.t10.org y otros lugares en Internet.

Los datos de sentido SCSI a menudo se encuentran en archivos de registro del kernel como resultado de que algo salió mal o pueden ser una advertencia informativa. A menudo se muestran como una secuencia de bytes hexadecimales, que comienzan con 70, 71, 72, 73, f0 o f1. Los datos de sentido pueden tener hasta 252 bytes de longitud, pero típicamente son mucho más cortos que eso; a menudo se ven 18 bytes, lo que generalmente está asociado con el formato más antiguo de datos de sentido "fijo".

Los datos de sentido se pueden proporcionar en la línea de comandos o en un archivo. Si se proporcionan en la línea de comandos, los datos de sentido deben ser una secuencia de bytes hexadecimales separados por espacios. Alternativamente, se puede proporcionar un archivo con el contenido en bytes binarios o hexadecimales ASCII. Esta última forma puede contener varias líneas, cada una con cero, uno o más bytes hexadecimales ASCII separados por espacios (comas o tabulaciones). El símbolo de almohadilla puede aparecer y él y el resto de la línea se ignoran, lo que lo hace útil para comentarios.

Si se proporciona la opción --cdb, en lugar de ver los argumentos hexadecimales dados como datos de sentido, se ven como un bloque descriptor de comando SCSI (CDB). En este caso, se imprime el nombre del comando. Ese nombre se basa en el primer byte hexadecimal dado (conocido como opcódigo) y opcionalmente en otro campo llamado "acción de servicio".

Otra acción alternativa es cuando se proporciona --err=ES. Se asume que ES es un valor de "estado de salida" entre 0 y 255 de una de las utilidades de este paquete. Se imprime una cadena descriptiva.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas.

-b, --binary=BFN
los datos se leen en binario desde un archivo llamado BFN. La opción no se puede dar con --file=HFN o --inhex=HFN ya que son contradictorias. Se asume que los datos son datos de sentido a menos que se dé la opción fI--nodecode.
-c, --cdb
trata la cadena de argumentos hexadecimales dada como bytes en un CDB SCSI y decodifica el nombre del comando.
-e, --err=ES
ES debe ser un valor de "estado de salida" entre 0 y 255 que esté disponible desde el shell (es decir, el contexto de ejecución de la utilidad) después de que la utilidad haya terminado. Por defecto, se imprime un mensaje de error indicativo en stdout; y si la opción --verbose se da una vez (o un número impar de veces) entonces el mensaje se imprime en stderr. Si --verbose se da dos o más veces se imprime una forma más larga del mensaje. En todos los casos, el mensaje tiene menos de 128 caracteres de longitud con una línea de salto final. Todas las demás opciones y argumentos de la línea de comandos se ignoran.
-f, --file=HFN
los datos de sentido se leen en hexadecimal ASCII desde un archivo llamado HFN. Los datos de sentido deben aparecer como una secuencia de bytes separados por espacio, coma, tabulación, guión o nueva línea. Se ignora todo lo que comienza desde un símbolo de almohadilla en adelante y hasta el final de esa línea. Si se establece --nospace, no se requiere separador entre los dígitos hexadecimales ASCII en HFN y los bytes se decodifican de pares de dígitos hexadecimales ASCII.
-h, --help
muestra el mensaje de uso y sale.
-H, --hex
esta opción se usa una vez en conjunción con --write=WFN para cambiar la salida escrita a WFN a líneas de bytes hexadecimales ASCII adecuadas para un compilador de lenguaje C. Cada línea contiene hasta 16 bytes (por ejemplo, una línea que comienza con "0x3b,0x07,0x00,0xff").
En otros casos (es decir, cuando no se da --write=WFN, o esta opción se da más de una vez) la salida es como se describe en la página del manual de sg3_utils(8).
La combinación de --inhex=HFN y esta opción utilizada tres veces puede ser útil para convertir bytes hexadecimales (por ejemplo, separados por guiones) a una forma más regular. La forma de opción corta es más conveniente para invocar esta opción tres veces (por ejemplo, '-HHH').
-i, --inhex=HFN
misma acción que --file=HFN. Esta opción se agregó para compatibilidad con otras utilidades de este paquete que tienen una opción --inhex=.
-I, --ignore-first
muchos programas que generan bytes hexadecimales (por ejemplo, 'hexdump -C') tienen un contador en ejecución (o índice) en la primera columna de cada línea. Esta opción ignora el primer valor hexadecimal en cada línea. Esta opción no tiene efecto si se dan --binary=BFN o --nospace. Se ignoran las líneas en blanco y cualquier carácter a partir de "#" inclusive y hasta el final de una línea. Útil con las opciones --file=HFN y --nodecode.
-j[=JO], --json[=JO]
la salida está en formato JSON en lugar de texto plano. Tenga en cuenta que los argumentos para la forma corta y larga son opcionales y si están presentes comienzan con "=" y no se permiten espacios en blanco alrededor de ese "=".
Consulte la página del manual sg3_utils_json o use '?' para JO para obtener un resumen.
-J, --js-file=JFN
la salida está en formato JSON y se envía a un archivo llamado JFN. Si ese archivo existe, se trunca. Por defecto, la salida JSON se envía a stdout.
Cuando se da esta opción, se implica la opción --json[=JO] y no es necesario darle. La opción --json[=JO] aún puede ser necesaria para establecer el parámetro JO a valores no predeterminados.
-N, --nodecode
no decodifique los datos proporcionados como sentido o cdb. Útil cuando se proporcionan datos arbitrarios (por ejemplo, al convertir de hexadecimal a binario o viceversa).
-n, --nospace
espera que el hexadecimal ASCII sea una cadena de dígitos hexadecimales sin espacios entre ellos. Los bytes se decodifican tomando dos dígitos hexadecimales a la vez, por lo que se espera un número par de dígitos. La cadena de dígitos hexadecimales puede estar en la línea de comandos (reemplazando "H1 H2 H3") o distribuida en varias líneas en el archivo HFN dado a --file=. En la línea de comandos, los espacios (u otros caracteres de espacio en blanco) entre secuencias de dígitos hexadecimales se ignoran; la cadena hexadecimal máxima de la línea de comandos es de 1023 caracteres.
-s, --status=SS
donde SS es un valor de byte de estado SCSI, dado en hexadecimal. El byte de estado SCSI está relacionado, pero es distinto, de los datos de sentido.
-v, --verbose
aumenta el grado de verbosidad (mensajes de depuración).
-V, --version
muestra la cadena de versión y sale.
-w, --write=WFN
escribe los datos de sentido en un archivo llamado WFN. Si es necesario, se crea WFN. Si WFN existe, se trunca antes de escribir los datos de sentido en él. Si también se da la opción --hex, se escribe hexadecimal ASCII en WFN (consulte la descripción de la opción --hex); de lo contrario, se escribe binario en WFN. Esta opción es una conveniencia y puede ser útil para convertir la representación hexadecimal ASCII de datos de sentido (o cualquier otra cosa) a su equivalente binario o a un formato hexadecimal ASCII compilable.

sg_decode_sense(8) — sg3_utils — Linux man page

NAME

sg_decode_sense

decode SCSI sense data and CDBs

SYNOPSIS

sg_decode_sense [OPTION]... [SENSE_DATA]...

DESCRIPTION

This utility decodes SCSI sense data. It can also decode CDBs (Command Descriptor Blocks) if the appropriate option is given. Sense data is typically obtained from a SCSI device via the REQUEST SENSE command or may appear in kernel logs (e.g. via dmesg).

When sense data is given on the command line (as positional arguments), it is expected to be ASCII hexadecimal. Alternatively, the --inhex= option can be used to read hexadecimal sense data from a file. The --binary= option can read binary sense data from a file.

If the --verbose= option is used (especially with a value of 3 or higher), the decoded sense data is augmented with information derived from the CDB that generated the sense data. To do this, the CDB itself needs to be supplied, typically via the --cdb= option or --inhex= or --binary= options with the appropriate flavour.

If no sense data is provided on the command line and no file-based input options are used, the utility waits to read sense data from standard input.

OPTIONS

The options are largely the same as for other sg3_utils utilities. See the sg3_utils(8) man page for a full list. The most relevant options for sg_decode_sense are:

-b, --binary=BFN
Read binary SCSI sense data from file BFN. If the file contains CDB data, it will be decoded if possible. Can be used multiple times.
-c, --cdb=CDB
Provide the CDB (as ASCII hex) that generated the sense data. If this option is given then the sense data is usually assumed to come from standard input (unless other input options are given). This option can be used multiple times.
--cdb_binary=CDBFN
Provide the CDB (in binary) from file CDBFN. Can be used multiple times.
--decode
Decode the input sense data and/or CDB. This is the default action.
-h, --help
Print out the usage message then exit.
-H, --hex
Output the decoded sense data (or CDB) in ASCII hexadecimal. The format is similar to that used by hexdump -C. This option can be repeated (e.g. "-HHH") to increase verbosity.
-i, --inhex=HFN
Read hexadecimal sense data (or CDB) from file HFN. Can be used multiple times.
-n, --nodecode
Do not decode the input. Just print it out (in hex unless -H is given).
-o, --old_sense
Interpret sense data in older (pre-SBC-2) formats. Typically shorter (e.g. 8 byte) sense data.
-s, --sense_len=LEN
The length of the sense data in bytes. If not given, it is inferred from the input (if possible).
-v, --verbose=N
Set the verbosity level. Default is 0. Higher values give more output. Level 1 is default when decoding. Level 3 or higher is needed to get CDB decoding based on sense data.
-w, --write=WFN
Write the result (decoded or not) to file WFN. If WFN is "-" then standard output is used.

NOTES

Unlike most utilities in this package, this utility does not access a SCSI device (logical unit). This utility accesses a library associated with this package. Amongst other things the library decodes SCSI sense data.

The sg_raw utility takes a ASCII hexadecimal sequence representing a SCSI CDB. When sg_raw is given the '-vvv' option, it will attempt to decode the CDB name.

Using the option combination: "--inhex=HFN --nodecode --write=WFN" may be used to convert hexadecimal (as produced by this and other utilities in this package) to binary where the output file is WFN.

Unlike many other utilities there is no --raw option. However binary data can be input using the --binary=BFN option while binary data can be output using the --write=WFN option (in the absence of the --hex option).

EXAMPLES

Sense data is often printed out in kernel logs and sometimes on the command line when verbose or debug flags are given. It will be at least 8 bytes long, often 18 bytes long but may be longer. A sense data string might look like this:

f0 00 03 00 00 12 34 0a 00 00 00 00 11 00 00 00
00 00

Cut and paste it after the sg_decode_sense command:


sg_decode_sense f0 00 03 00 00 12 34 0a 00 00 00 00 11 00 00 00 00 00

and for this sense data the output should look like this:


Fixed format, current; Sense key: Medium Error
Additional sense: Unrecovered read error
Info fld=0x1234 [4660]

For a medium error the Info field is the logical block address (LBA) of the lowest numbered block that the associated SCSI command was not able to read (verify or write).

To convert arbitrary binary data to hex, suitable to be parsed by other sg3_utils utilities. The --nodecode option is used in this case:


sg_decode_sense -N -i vpd_zbdc.hex -w vpd_zbdc.bin

The '-HHH' will output hex to the console (stdout) in a form suitable for other utilities in this package to parse as input. And sg_decode_sense can also be used to convert from arbitrary hex to binary with:


sg_decode_sense -N -b vpd_zbdc.raw -HHH

Note that tools like hexdump and od place a counter (i.e. an index starting at 0) at the beginning of each line which is a pain when parsing hex. The '/-HHH' option(s) does not output that leading counter on each line.

EXIT STATUS

The exit status of sg_decode_sense is 0 when it is successful. Otherwise see the sg3_utils(8) man page.
