DESCRIPCIÓN

sg_vector_create() asigna e inicializa un nuevo vector statgrab con `initial_used` elementos listos para usarse. Se asigna espacio inicialmente para `alloc_count` elementos (para evitar demasiadas llamadas a realloc() durante posteriores llamadas a sg_vector_resize()). El valor de `block_size` debe ser una potencia de 2; se redondea a la potencia de 2 superior si no lo es. Si `alloc_count` no es un múltiplo de `block_size`, se redondea al múltiplo superior de `block_size`. Devuelve un puntero al vector recién creado.

sg_vector_clear() destruye todos los elementos contenidos en el vector dado. A diferencia de sg_vector_resize( x, 0 ), el tamaño asignado del vector no se modifica.

sg_vector_resize() aumenta o disminuye la cantidad de elementos asignados en el vector especificado. La cantidad de elementos asignados es siempre un múltiplo del parámetro de inicialización `block_size`. En el caso especial, si se llama a sg_vector_resize() con 0 como argumento `new_count`, el vector se libera después de que todos los elementos del vector hayan sido destruidos. Devuelve el puntero al vector redimensionado.

sg_vector_free() destruye todos los elementos del vector y desasigna el almacenamiento perteneciente al vector dado.

sg_vector_clone() clona todos los elementos del vector dado en un nuevo vector creado con la misma especificación que el referenciado. Devuelve un puntero al vector clonado.

sg_vector_clone_into() clona todos los elementos del vector fuente dado en el vector destino dado. El vector destino debe haber sido creado para el mismo tipo de dato de elemento que el vector fuente. Devuelve un código de error distinto de SG_ERROR_NONE si algo salió mal.

sg_vector_compute_diff() calcula un vector de diferencia entre el vector que contiene las estadísticas actuales y otro vector que contiene estadísticas más antiguas. Si un elemento existe en el vector actual pero no en el opuesto, se clona en el vector resultado. Si un elemento solo existe en el vector opuesto, no aparece en el vector destino. sg_vector_compute_diff() devuelve un código de error distinto de SG_ERROR_NONE si algo salió mal.

sg_prove_vector() prueba si un puntero a un vector apunta realmente a un vector. En caso de que el puntero del vector dado apunte a datos corruptos, el programa se aborta. Cuando sg_prove_vector() retorna, devuelve SG_ERROR_NONE.

sg_get_nelements() devuelve el número de elementos que el área de datos dada, abarcada por un vector statgrab, contiene. La cabecera del vector se calcula internamente a partir del puntero dado al primer elemento del vector.

sg_free_stats_buf() libera el vector que abarca el área de datos dada.

NOTAS

Excepto sg_get_nelements() y sg_free_stats_buf(), ninguna de las funciones anteriores puede ser llamada desde fuera del código fuente de libstatgrab. Las estructuras y APIs documentadas pueden cambiar sin previo aviso. La descripción de todas las demás APIs está destinada a ser leída solo por los desarrolladores de libstatgrab.

Cada vector se crea a partir de dos elementos: la información del vector y la lista de elementos:

template <class T, class Impl>
struct sg_vector {
        size_t used_count;
        size_t alloc_count;
        size_t block_shift;
        Impl vector_implementation;
        T elements[alloc_count];
};

Por supuesto, esto no es C válido, por lo que la solución fue ser ingenioso:

typedef struct sg_vector {
	size_t used_count;
	size_t alloc_count;
	size_t block_shift;
	struct sg_vector_init_info info;
} sg_vector;
struct sg_vector_size_helper {
	struct sg_vector v;
	long long ll;
};
#define VECTOR_SIZE offsetof(struct sg_vector_size_helper,ll)
/* Devuelve el puntero a los datos de un vector */
#define VECTOR_DATA(vector) \
	(vector ? (void *)(((char *)vector)+VECTOR_SIZE) : NULL)
#define VECTOR_ADDR_ARITH(ptr) \
	(sg_vector *)(((char *)(ptr))-VECTOR_SIZE)
/* Devuelve el vector para unos datos */
#define VECTOR_ADDRESS(ptr) \
	((ptr) ? (SG_ERROR_NONE == sg_prove_vector(VECTOR_ADDR_ARITH(ptr)) ? VECTOR_ADDR_ARITH(ptr) : NULL ) : NULL)

Esto también permite a funciones de usuario como sg_get_nelements() y sg_free_stats_buf() cambiar fácilmente entre la estructura del vector y el contenido.

LA ESTRUCTURA DE ESPECIALIZACIÓN DEL VECTOR

Como se mencionó, la implementación del vector utiliza estrategias del concepto de programación orientada a objetos llamado "polimorfismo". Un vector se describe mediante un pequeño objeto que contiene atributos inherentes como el tamaño del elemento y un conjunto de "métodos virtuales" para realizar tareas relacionadas con los elementos, como inicializar o destruir elementos.

typedef void (*vector_init_function)(void *item);
typedef sg_error (*vector_copy_function)(const void *src, void *dst);
typedef sg_error (*vector_compute_diff_function)(void *dst, const void *src);
typedef int (*vector_compare_function)(const void *a, const void *b);
typedef void (*vector_destroy_function)(void *item);
struct sg_vector_init_info {
        size_t item_size;
        vector_init_function init_fn;
        vector_copy_function copy_fn;
        vector_compute_diff_function compute_diff_fn;
        vector_compare_function compare_fn;
        vector_destroy_function destroy_fn;
};

Las instancias de `struct sg_vector_init_info` se inicializan conceptualmente de forma estática utilizando la macro preprocesador VECTOR_INIT_INFO_FULL_INIT(type) o VECTOR_INIT_INFO_EMPTY_INIT(type). Aquí hay algunos ejemplos para demostrar cómo está previsto:

Inicialización de la descripción del vector de estadísticas de CPU

VECTOR_INIT_INFO_EMPTY_INIT(sg_cpu_stats);

Inicialización de la descripción del vector de estadísticas de Host-Info

static void sg_os_stats_item_init(sg_os_stats *d);
static void sg_os_stats_item_destroy(sg_os_stats *d);
#define sg_os_stats_item_copy NULL
#define sg_os_stats_item_compute_diff NULL
#define sg_os_stats_item_compare NULL
VECTOR_INIT_INFO_FULL_INIT(sg_os_stats);

Inicialización de la descripción del vector de estadísticas de Disk-IO

static sg_error sg_disk_io_stats_item_copy(sg_disk_io_stats *d, const sg_disk_io_stats *s);

NAME

sg_vector_clone_into, VECTOR_CREATE, VECTOR_CLEAR, VECTOR_CREATE_OR_RESIZE, VECTOR_UPDATE, VECTOR_ITEM_COUNT — vectors (dynamic arrays)

SYNOPSIS

#include <statgrab.h>

struct sg_vector *
sg_vector_clone_into(const struct sg_vector *src, size_t new_count,
    sg_vector_init_info_t type);

void
VECTOR_CREATE(struct sg_vector **vectorptr, size_t count, identifier
    type);

void
VECTOR_CLEAR(struct sg_vector *vector);

struct sg_vector *
VECTOR_CREATE_OR_RESIZE(struct sg_vector *vector, size_t new_count,
    identifier type);

void
VECTOR_UPDATE(struct sg_vector **vectorptr, size_t new_count,
    datatype *data, identifier datatype);

size_t
VECTOR_ITEM_COUNT(const struct sg_vector *vector);

DESCRIPTION

A vector is a dynamic array. It can be compared to a list in Python or a vector in C++. Vectors in libstatgrab are implemented as a pointer to a structure containing the pointer to the data, the number of elements that the allocated memory can hold and the number of elements that are currently used.

A vector can contain any type of data. The type of data is defined by the identifier type argument to the creation and update functions. The macro VECTOR_CREATE() exists for convenience when creating a new vector.

The macro VECTOR_CLEAR() frees the memory occupied by the vector elements, but not the vector structure itself.

The macro VECTOR_CREATE_OR_RESIZE() calls sg_vector_create() when the vector pointer points to NULL, and sg_vector_resize() otherwise. The pointer to the vector is passed in, and the result of the appropriate function is returned.

The macro VECTOR_UPDATE() can be used to create or resize a vector, and then set the data pointer to the first element of the vector. When the vector is NULL, the data pointer is set to NULL. If VECTOR_CREATE_OR_RESIZE() returns a NULL pointer and new_count is not zero, the instructions from the macro VECTOR_UPDATE_ERROR_CLEANUP are executed.

The macro VECTOR_ITEM_COUNT() returns the number of elements currently stored in the vector. If the vector pointer is NULL, it returns 0.

NOTES

The functions sg_vector_clone_into(), sg_vector_create(), sg_vector_resize() and sg_vector_clear() are the underlying functions that the macros use. The macros are provided for convenience and ease of use.

VECTOR_CREATE() calls sg_vector_create() with alloc_count = block_size and initial_used = 0 using the vector specialisation type##_vector_init_info.

VECTOR_CLEAR() simply calls sg_vector_clear(). This macro exists only for conformity.

VECTOR_CREATE_OR_RESIZE() calls sg_vector_create() when the given vector pointer points to NULL or sg_vector_resize() otherwise. The result of the appropriate function is returned.

VECTOR_UPDATE() calls VECTOR_CREATE_OR_RESIZE() and sets data to the first element of the resulting vector when a non-NULL pointer got, to NULL otherwise. When VECTOR_CREATE_OR_RESIZE() returns a NULL pointer and new_count is not equal to 0 (zero), the instructions from the macro VECTOR_UPDATE_ERROR_CLEANUP are executed to cleanup before returning from current subroutine with the error which has been occurred.

VECTOR_ITEM_COUNT() returns 0 for a non-existing vector (vector == 0) and the number of containing elements otherwise.

RETURN VALUES

Beside error codes, the return values, if any, are always a pointer to vector structures (struct sg_vector *).
