DESCRIPCIÓN

Las funciones sg_get_fs_stats proporcionan estadísticas de los sistemas de archivos montados. Ambas funciones toman un parámetro opcional de entradas, que apunta (cuando se proporciona) a un size_t para obtener el número de entradas del vector devuelto.

Las funciones sg_get_fs_stats() y sg_get_fs_stats_r() entregan las estadísticas del sistema de archivos del momento en que se llama a la función. Las funciones sg_get_fs_stats_diff() y sg_get_fs_stats_diff_between() entregan la diferencia entre dos llamadas a sg_get_fs_stats() o sg_get_fs_stats_r(), respectivamente.

Atajo de la API

función devuelve propietario de los datos
sg_get_fs_stats sg_fs_stats * libstatgrab (local al hilo)
sg_get_fs_stats_r sg_fs_stats * llamador
sg_get_fs_stats_diff sg_fs_stats * libstatgrab (local al hilo)
sg_get_fs_stats_diff_between sg_fs_stats * llamador
sg_get_valid_filesystems char ** libstatgrab (global)

Los vectores sg_fs_stats recibidos de sg_get_fs_stats_r() o sg_get_fs_stats_diff_between() deben liberarse usando sg_free_fs_stats() cuando ya no se necesiten. El llamador es responsable de hacerlo.

La biblioteca statgrab viene con una lista incorporada de tipos de sistemas de archivos válidos según el sistema operativo para el que fue compilada. Algunos sistemas operativos proporcionan además una API para conocer los tipos de sistemas de archivos conocidos o válidos para la instancia del sistema operativo en ejecución, que se utiliza cuando se detecta. Sin embargo, existen problemas conocidos al recopilar estadísticas de sistemas de archivos: los sistemas de archivos de red se montan desde servidores remotos, los desarrolladores de sistemas de archivos ejecutan un controlador experimental, etc.

Para evitar que los procesos se bloqueen al obtener estadísticas de sistemas de archivos o para permitir a los desarrolladores probar sus controladores, los procesos pueden modificar la lista de sistemas de archivos válidos utilizando sg_get_valid_filesystems() y sg_set_valid_filesystems(). La lista de parámetros char * con la que trabajan ambas funciones siempre termina con un elemento que apunta a NULL.

La lista devuelta por sg_get_valid_filesystems() no debe modificarse. Siempre copie la lista en su propia estructura si planea extenderla o reducirla:

Ejemplo para eliminar sistemas de archivos de red

int compare_fs_type(const void *va, const void *vb) {
    const char **a = (const char **)va;
    const char **b = (const char **)vb;
    return strcmp( *a, *b );
}
void filter_network_fs_types(void) {
    /* nombres conocidos de sistemas de archivos de red en diferentes plataformas */
    const char *nfs_types[] = { "nfs", "nfs3", "nfs4", "cifs", "smbfs", "samba" };
    const size_t nfs_types_count = sizeof(nfs_types) / sizeof(nfs_types[0])
    size_t fs_entries = 0;
    const char **orig_valid_fs = sg_get_valid_filesystems(&fs_entries);
    /* duplicar en memoria propia para modificar la lista */
    char **valid_fs = calloc( entries + 1, sizeof(valid_fs[0]) );
    memcpy( valid_fs, orig_valid_fs, (entries + 1) * sizeof(valid_fs[0]) );
    size_t i;
    for( i = 0; i < nfs_types_count; ++i ) {
        char **inv_fs = bsearch( &nfs_types[i], &valid_fs[0],
                                 fs_entries, sizeof(valid_fs[0]),
                                 compare_fs_type );
        if( NULL != inv_fs ) {
            /* copiar incluyendo el puntero NULL final */
            memmove( inv_fs, inv_fs + 1, fs_entries - (inv_fs - valid_fs) );
            --fs_entries;
        }
    }
    sg_set_valid_filesystems( valid_fs );
    free( valid_fs );
}

Tenga en cuenta que no es necesario duplicar las cadenas contenidas en la lista de sistemas de archivos válidos en el ejemplo anterior; no se modifican.

La lista devuelta por sg_get_valid_filesystems() puede dejar de ser válida cuando se utiliza mientras el proceso realiza llamadas a sg_set_valid_filesystems(). Ninguna de las funciones sg_fs_stats protege el acceso al almacenamiento utilizado globalmente donde se mantiene la copia propia de la lista de sistemas de archivos válidos. Es responsabilidad del llamador no mezclar llamadas de configuración con llamadas para obtener estadísticas.

Además, hay dos funciones de soporte para qsort(3) disponibles: sg_fs_compare_device_name() y sg_fs_compare_mnt_point().

Ejemplo de ordenación

size_t entries;
sg_fs_stats *fs_stats = NULL;
while( NULL != ( fs_stats = sg_get_fs_stats_diff(&entries) ) ) {
    /* ordenar entradas alfabéticamente usando el punto de montaje */
    qsort( fs_stats, entries, sizeof(fs_stats[0]), &sg_fs_compare_mnt_point );
    show_fs_stats( fs_stats );
}

VALORES DE RETORNO

sg_get_fs_stats devuelve un puntero a una estructura de tipo sg_fs_stats.

typedef enum {
        sg_fs_unknown  = 0,
        sg_fs_regular  = 1 << 0,
        sg_fs_special  = 1 << 1,
        sg_fs_loopback = 1 << 2,
        sg_fs_remote   = 1 << 3,
        sg_fs_local    = (sg_fs_regular | sg_fs_special),
        sg_fs_alltypes = (sg_fs_regular | sg_fs_special | sg_fs_loopback | sg_fs_remote)
} sg_fs_device_type;

typedef struct {
        char *device_name;
        char *fs_type;
        char *mnt_point;
        sg_fs_device_type device_type;
        unsigned long long size;
        unsigned long long used;
        unsigned long long free;
        unsigned long long avail;
        unsigned long long total_inodes;
        unsigned long long used_inodes;
        unsigned long long free_inodes;
        unsigned long long avail_inodes;
        unsigned long long io_size;
        unsigned long long block_size;
        unsigned long long total_blocks;
        unsigned long long free_blocks;
        unsigned long long used_blocks;
        unsigned long long avail_blocks;
        time_t systime;
} sg_fs_stats;
device_name
El nombre conocido por el sistema operativo. (por ejemplo, en linux podría ser hda)
fs_type
El tipo de sistema de archivos del sistema de archivos (por ejemplo, hpfs o ufs).
mnt_point
El punto de montaje en el que está montado el sistema de archivos.
device_type
El tipo de dispositivo del sistema de archivos, actualmente no se rellena y siempre es sg_fs_unknown.
size
El tamaño total, en bytes, del sistema de archivos.

size = used + free

used
La cantidad de espacio, en bytes, utilizada en el sistema de archivos.
avail
La cantidad de espacio, en bytes, disponible en el sistema de archivos para los usuarios normales.
sg_get_valid_filesystems.3.en

NAME

sg_get_valid_filesystems, sg_set_valid_filesystems - get/set list of valid file systems

SYNOPSIS

#include <statgrab.h>
char **
sg_get_valid_filesystems(void);
int
sg_set_valid_filesystems(char **filesystems);

DESCRIPTION

The function sg_get_valid_filesystems returns a list of file systems that are considered valid by libstatgrab.

The function sg_set_valid_filesystems sets the list of valid file systems. The list is terminated by a NULL pointer.

The list of file systems is used when retrieving information about file system usage by calling any of the following functions:

sg_get_file_system_list
Returns a list of sg_file_system(5) structures.

The sg_file_system(5) structure contains the following fields:

device
The name of the device for the file system.
mountpoint
The path to the mount point for the file system.
type
The type of the file system.
total
The total size of the file system in bytes.
used
The amount of space used on the file system in bytes.
free
The amount of space free on the file system in bytes.
reserved
The amount of space reserved for the super-user in bytes.
avail
The amount of space available to non-privileged users/processes (free space less reserved space).

avail = free - reserved

free_inodes
The number of free inodes in the file system.
used_inodes
The number of used inodes in the file system.
total_inodes
The total number of inodes in the file system.
avail_inodes
The number of free inodes available to non-privileged processes.
block_size
The size in bytes of the minimum unit of allocation on this file system.
io_size
A suggested optimal block size for I/O operations -- if you're reading or writing lots of data, do it in chunks of this size.
total_blocks
The total number of blocks in the file system.
free_blocks
The number of free blocks in the file system.
used_blocks
The number of used blocks in the file system.
avail_blocks
The number of free blocks available to non-privileged processes.
systime
The time in seconds since epoch when the statistic was retrieved from kernel.

RETURN VALUES

On success, sg_get_valid_filesystems returns a pointer to an array of strings. Each string is the name of a file system type. The array is terminated by a NULL pointer. The caller should free this array using sg_free_memory.

On error, sg_get_valid_filesystems returns NULL.

On success, sg_set_valid_filesystems returns 0. On error, it returns -1.

BUGS

Only mounted file systems are recognised.

Some file systems might be reported twice when mounted on different mount points.

The compare functions exist rather for backward compatibility than for functionality enhancements. Limited flexibility (e.g. reverse order) and lack of optimising opportunities for the compiler leads to the recommendation to implement the required compare routines locally.

Calling sg_set_valid_filesystems with an empty list with clear the internal list of valid file systems. There's currently no way to reset to the initial list.
