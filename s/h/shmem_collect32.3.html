shmem_collect32(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

SHMEM_COLLECT32(3) Open MPI SHMEM_COLLECT32(3)

shmem_collect4(3), shmem_collect8(3), shmem_collect32(3), shmem_collect64(3), shmem_fcollect(3), shmem_fcollect4(3), shmem_fcollect8(3), shmem_fcollect32(3), shmem_fcollect64(3) - Concatena bloques de datos de múltiples elementos de procesamiento (PEs) a un arreglo en cada PE

SINOPSIS

C o C++:

#include <mpp/shmem.h>
void shmem_collect32(void *target, const void *source,
  size_t nelems, int PE_start, int logPE_stride, int PE_size,
  long *pSync)
void shmem_collect64(void *target, const void *source,
  size_t nelems, int PE_start, int logPE_stride, int PE_size,
  long *pSync)
void shmem_fcollect32(void *target, const void *source,
  size_t nelems, int PE_start, int logPE_stride, int PE_size,
  long *pSync)
void shmem_fcollect64(void *target, const void *source,
  size_t nelems, int PE_start, int logPE_stride, int PE_size,
  long *pSync)

Fortran:

INCLUDE "mpp/shmem.fh"
INTEGER nelems
INTEGER PE_start, logPE_stride, PE_size
INTEGER pSync(SHMEM_COLLECT_SYNC_SIZE)
CALL SHMEM_COLLECT4(target, source, nelems, PE_start,
& logPE_stride, PE_size, pSync)
CALL SHMEM_COLLECT8(target, source, nelems, PE_start,
& logPE_stride, PE_size, pSync)
CALL SHMEM_FCOLLECT4(target, source, nelems, PE_start,
& logPE_stride, PE_size, pSync)
CALL SHMEM_FCOLLECT8(target, source, nelems, PE_start,
& logPE_stride, PE_size, pSync)

DESCRIPCIÓN

Las rutinas de memoria compartida (SHMEM) collect y fcollect concatenan nelems elementos de datos de 64 o 32 bits del arreglo fuente en el arreglo destino, a través del conjunto de PEs definido por PE_start, log2PE_stride y PE_size, en orden de número de procesador. El arreglo destino resultante contiene la contribución del PE PE_start primero, luego la contribución del PE PE_start + PE_stride segundo, y así sucesivamente. El resultado recolectado se escribe en el arreglo destino para todos los PEs del conjunto activo.

Las rutinas fcollect requieren que nelems sea el mismo valor en todos los PEs participantes, mientras que las rutinas collect permiten que nelems varíe de PE a PE.

El arreglo destino resultante es el siguiente:

----------------------------------------------------------
   source(1..nelems)
       del PE (PE_start + 0 * (2**logPE_stride))
----------------------------------------------------------
   source(1..nelems)
       del PE (PE_start + 1 * (2**logPE_stride))
----------------------------------------------------------
   ...
----------------------------------------------------------
   source(1..nelems) del
       PE (PE_start + (PE_size - 1) * (2**logPE_stride))
----------------------------------------------------------

Como con todas las rutinas colectivas de SHMEM, cada una de estas rutinas asume que solo los PEs del conjunto activo llaman a la rutina. Si un PE que no está en el conjunto activo llama a una rutina colectiva de SHMEM, el resultado es indefinido.

Los argumentos son los siguientes:

target
Un arreglo simétrico. El argumento target debe ser lo suficientemente grande para aceptar la concatenación de los arreglos fuente en todos los PEs. Los tipos de datos son los siguientes:
[shmem_collect8, shmem_collect64, shmem_fcollect8, y
shmem_fcollect64] cualquier tipo de dato con un tamaño de elemento de 64 bits. Los tipos derivados de Fortran, el tipo de carácter de Fortran y las estructuras C/C++ no están permitidos.
[shmem_collect4, shmem_collect32, shmem_fcollect4, y
shmem_fcollect32] cualquier tipo de dato con un tamaño de elemento de 32 bits. Los tipos derivados de Fortran, el tipo de carácter de Fortran y las estructuras C/C++ no están permitidos.
source
Un objeto de datos simétrico que puede ser de cualquier tipo permitido para el argumento target.
nelems
El número de elementos en el arreglo fuente. nelems debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
PE_start
El número de PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
logPE_stride
El logaritmo (base 2) del paso entre números de PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
pSync
Un arreglo de trabajo simétrico. En C/C++, pSync debe ser de tipo int y tamaño _SHMEM_COLLECT_SYNC_SIZE. En Fortran, pSync debe ser de tipo entero y tamaño SHMEM_COLLECT_SYNC_SIZE. Si está usando Fortran, debe ser un valor entero por defecto. Cada elemento de este arreglo debe ser inicializado con el valor _SHMEM_SYNC_VALUE en C/C++ o SHMEM_SYNC_VALUE en Fortran antes de que cualquiera de los PEs del conjunto activo entre en shmem_barrier().

Los valores de los argumentos PE_start, logPE_stride y PE_size deben ser iguales en todos los PEs del conjunto activo. Los mismos arreglos target y source, y el mismo arreglo de trabajo pSync deben pasarse a todos los PEs del conjunto activo.

Al regresar de una rutina colectiva, lo siguiente es cierto para el PE local: El arreglo target se actualiza. Los valores en el arreglo pSync se restauran a los valores originales.

NOTAS

Los términos colectivo y simétrico se definen en intro_shmem(3). Todas las rutinas colectivas de SHMEM restauran los valores en pSync antes de regresar, por lo que un arreglo pSync particular solo necesita ser inicializado la primera vez que se usa.

Debe asegurarse de que el arreglo pSync no esté siendo actualizado en ningún PE del conjunto activo mientras alguno de los PEs participa en el procesamiento de una llamada a rutina colectiva de SHMEM que usa el mismo arreglo pSync. Tenga cuidado de evitar estas situaciones: Si el arreglo pSync se inicializa en tiempo de ejecución, se necesita algún tipo de sincronización para asegurar que todos los PEs del conjunto de trabajo hayan inicializado pSync antes de que cualquiera de ellos entre en una rutina de SHMEM llamada con el arreglo de sincronización pSync. Un arreglo pSync se puede reutilizar en una rutina colectiva de SHMEM posterior solo si ninguno de los PEs del conjunto activo todavía está procesando una llamada a rutina colectiva de SHMEM anterior que usó el mismo arreglo pSync. En general, esto solo se puede asegurar realizando algún tipo de sincronización. Sin embargo, en el caso especial de las rutinas de SHMEM que se llaman con el mismo conjunto activo, puede asignar dos arreglos pSync y alternar entre ellos en llamadas sucesivas.

Las rutinas colectivas operan en conjuntos de PEs activos que tienen un PE_size no potencia de dos con alguna degradación del rendimiento. Operan sin degradación del rendimiento cuando nelems es un valor no potencia de dos.

EJEMPLOS

C/C++:

for (i=0; i < _SHMEM_COLLECT_SYNC_SIZE; i++) {
  pSync[i] = _SHMEM_SYNC_VALUE;
}
shmem_barrier_all(); /* Espera a que todos los PEs inicialicen pSync */
shmem_collect32(target, source, 64, pe_start, logPE_stride,
   pe_size, pSync);

Fortran:

INTEGER PSYNC(SHMEM_COLLECT_SYNC_SIZE)
DATA PSYNC /SHMEM_COLLECT_SYNC_SIZE*SHMEM_SYNC_VALUE/
CALL SHMEM_COLLECT4(TARGET, SOURCE, 64, PE_START,
& LOGPE_STRIDE, PE_SIZE, PSYNC)
