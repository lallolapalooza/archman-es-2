SHELLCHECK(1) Manual de Comandos Generales SHELLCHECK(1)

NOMBRE

shellcheck - Herramienta de análisis de scripts de Shell

SINOPSIS

shellcheck [OPCIONES...] ARCHIVOS...

DESCRIPCIÓN

ShellCheck es una herramienta de análisis estático y linting para scripts sh/bash. Se enfoca principalmente en manejar errores de sintaxis y trampas típicas de nivel principiante e intermedio donde el shell solo produce un mensaje de error críptico o un comportamiento extraño, pero también informa sobre algunos problemas más avanzados donde los casos extremos pueden causar fallos tardíos.

ShellCheck da consejos específicos para el shell. Considere esta línea:

(( area = 3.14*r*r ))
•
Para scripts que comienzan con #!/bin/sh (o al usar -s sh), ShellCheck advertirá que (( .. )) no es compatible con POSIX (similar a checkbashisms).
•
Para scripts que comienzan con #!/bin/bash (o al usar -s bash), ShellCheck advertirá que los decimales no son compatibles.
•
Para scripts que comienzan con #!/bin/ksh (o al usar -s ksh), ShellCheck no advertirá en absoluto, ya que ksh admite decimales en contextos aritméticos.

OPCIONES

-a, --check-sourced
Emitir advertencias en archivos fuentes. Normalmente, shellcheck solo advertirá sobre problemas en los archivos especificados. Con esta opción, también se informarán los problemas en archivos fuentes.
-C[CUÁNDO], --color[=CUÁNDO]
Para la salida TTY, habilita colores *siempre*, *nunca* o *automáticamente*. El valor predeterminado es *automáticamente*. --color sin un argumento es equivalente a --color=always.
-i CÓDIGO1[,CÓDIGO2...], --include=CÓDIGO1[,CÓDIGO2...]
Incluir explícitamente solo los códigos especificados en el informe. Las opciones posteriores de -i son acumulativas, pero todos los códigos pueden especificarse a la vez, separados por comas como un solo argumento. Las opciones de inclusión anulan cualquier opción de exclusión proporcionada.
-e CÓDIGO1[,CÓDIGO2...], --exclude=CÓDIGO1[,CÓDIGO2...]
Excluir explícitamente los códigos especificados del informe. Las opciones posteriores de -e son acumulativas, pero todos los códigos pueden especificarse a la vez, separados por comas como un solo argumento.
--extended-analysis=true/false
Habilitar/deshabilitar el Análisis de Flujo de Datos para identificar más problemas (predeterminado: true). Si ShellCheck usa demasiado CPU/RAM al verificar scripts con varios miles de líneas de código, el análisis extendido puede deshabilitarse con esta opción o con una directiva. Esta opción anula las directivas y los archivos rc.
-f FORMATO, --format=FORMATO
Especifica el formato de salida de shellcheck, que imprime sus resultados en la salida estándar. Las opciones posteriores de -f se ignoran, ver FORMATOS más abajo para más información.
--list-optional
Genera una lista de comprobaciones opcionales conocidas. Estas pueden ser habilitadas con opciones -o o directivas enable.
--norc
No intentes buscar archivos de configuración .shellcheckrc.
--rcfile ARCHIVO_RC
Prefiere el archivo de configuración especificado en lugar de buscar en las ubicaciones predeterminadas.
-o NOMBRE1[,NOMBRE2...], --enable=NOMBRE1[,NOMBRE2...]
Habilita comprobaciones opcionales. El nombre especial *all* habilita todas ellas. Las opciones posteriores de -o se acumulan. Esto es equivalente a especificar directivas enable.
-P RUTA_FUENTES, --source-path=RUTA_FUENTES
Especifica rutas para buscar archivos fuente, separadas por : en Unix y ; en Windows. Esto es equivalente a especificar directivas search-path.
-s shell, --shell=shell
Especifica el dialecto de Bourne shell. Los valores válidos son sh, bash, dash, ksh y busybox. El predeterminado es deducir el shell de la directiva de shell del archivo, el shebang o la extensión .bash/.bats/.dash/.ksh, en ese orden. sh se refiere a POSIX sh (no al del sistema), y advertirá sobre problemas de portabilidad.
-S SEVERIDAD, --severity=severidad
Especifica la severidad mínima de los errores a considerar. Los valores válidos en orden de severidad son *error*, *warning*, *info* y *style*. El valor predeterminado es *style*.
-V, --version
Imprime la información de la versión y sale.
-W NUM, --wiki-link-count=NUM
Para la salida TTY, muestra *NUM* enlaces a la wiki con más información sobre las advertencias mencionadas. Establecer a 0 para deshabilitarlos por completo.
-x, --external-sources
Sigue las sentencias source incluso cuando el archivo no está especificado como entrada. Por defecto, shellcheck solo seguirá archivos especificados en la línea de comandos (más /dev/null). Esta opción permite seguir cualquier archivo que el script pueda source.

Esta opción también puede ser habilitada usando external-sources=true en .shellcheckrc. Esta opción tiene prioridad.

ARCHIVOS...
Uno o más archivos de script para verificar, o "-" para la entrada estándar.

FORMATOS

tty
Salida de texto plano, legible por humanos. Este es el valor predeterminado.
gcc
Salida compatible con GCC. Útil para editores que admiten compilar y mostrar errores de sintaxis.

Por ejemplo, en Vim, :set makeprg=shellcheck\ -f\ gcc\ % permitirá usar :make para verificar el script, y :cnext para saltar al siguiente error.

<archivo>:<línea>:<columna>: <tipo>: <mensaje>
checkstyle
Salida XML compatible con Checkstyle. Soportada directamente o a través de plugins por muchos IDEs y sistemas de monitoreo de compilación.

    <error
      line='línea'
      column='columna'
      severity='severidad'
      message='mensaje'
      source='ShellCheck.SC####' />
    ...
  </file>
  ...
</checkstyle>
diff
Correcciones automáticas en formato de diff unificado. Puede ser enviado a git apply o patch -p1 para aplicar las correcciones automáticamente.

@@ -2,6 +2,6 @@
 ## Ejemplo de un script roto.
 for f in $(ls *.m3u)
 do
-  grep -qi hq.*mp3 $f \
+  grep -qi hq.*mp3 "$f" \
     && echo -e 'La lista de reproducción $f contiene un archivo HQ en formato mp3'
 done
json1
JSON es un formato de serialización popular que es más adecuado para aplicaciones web. El JSON de ShellCheck es compacto y contiene solo lo esencial. Las tabulaciones se cuentan como 1 carácter.

DIRECTIVAS

Las directivas de ShellCheck se pueden especificar como comentarios en el script de shell. Si aparecen antes del primer comando, se consideran aplicables a todo el archivo. De lo contrario, se aplican al comando o bloque inmediatamente siguiente:

# shellcheck key=valor key=valor
comando-o-estructura

Por ejemplo, para suprimir SC2035 sobre el uso de ./*.jpg:

# shellcheck disable=SC2035
echo "Archivos: " *.jpg

Para indicarle a ShellCheck dónde buscar un archivo que de otro modo se determinaría dinámicamente:

# shellcheck source=./lib.sh
source "$(find_install_dir)/lib.sh"

Aquí se utiliza un grupo de llaves de shell para suprimir una advertencia en varias líneas:

# shellcheck disable=SC2016
{
  echo 'Modificando $PATH'
  echo 'PATH=foo:$PATH' >> ~/.bashrc
}

Las claves válidas son:

disable
Deshabilita una lista de códigos de error separados por comas para el comando siguiente. El comando puede ser un comando simple como echo foo, o un comando compuesto como una definición de función, un bloque de subshell o un bucle. Se puede especificar un rango con un guión, por ejemplo, disable=SC3000-SC4000 para excluir los 3xxx. Todas las advertencias se pueden deshabilitar con disable=all.
enable
Habilita una verificación opcional por nombre, como se enumera con --list-optional. Solo se consideran las directivas enable aplicables a todo el archivo.
extended-analysis
Establecer en true/false para habilitar/deshabilitar el análisis de flujo de datos. Especificar # shellcheck extended-analysis=false en scripts generados automáticamente particularmente grandes (más de 2000 líneas) reducirá el uso de recursos de ShellCheck a expensas de ciertas verificaciones. El análisis extendido está habilitado por defecto.
external-sources
Establecer en true en .shellcheckrc para permitir siempre que ShellCheck abra archivos arbitrarios de declaraciones 'source' (la forma en que lo hacen la mayoría de las herramientas).

Esta opción tiene como valor predeterminado false solo debido al origen de ShellCheck como un servicio remoto para verificar scripts no confiables. Puede habilitarse de forma segura para el desarrollo normal.

source
Anula el nombre del archivo incluido en una declaración source/.. Esto puede usarse para indicar a shellcheck dónde buscar un archivo cuyo nombre se determina en tiempo de ejecución, o para omitir una fuente indicándole que use /dev/null.
source-path
Agrega un directorio a la ruta de búsqueda para declaraciones source/. (por defecto, solo se incluye el directorio de trabajo de ShellCheck). Las rutas absolutas también se anclarán en estas rutas. La ruta especial SCRIPTDIR se puede usar para especificar el directorio del script que se está verificando actualmente, como en source-path=SCRIPTDIR o source-path=SCRIPTDIR/../libs. Múltiples rutas se acumulan, y -P tiene prioridad sobre ellas.
shell
Anula el shell detectado a partir de la línea shebang. Esto es útil para archivos destinados a ser incluidos (y que, por lo tanto, carecen de shebang), o posiblemente como una alternativa más específica a 'disable=SC2039'.

ARCHIVOS RC

A menos que se use --norc, ShellCheck buscará un archivo .shellcheckrc o shellcheckrc en el directorio del script y en cada directorio padre. Si lo encuentra, leerá pares clave=valor de él y los tratará como directivas aplicables a todo el archivo.

Aquí hay un ejemplo de .shellcheckrc:

# Buscar archivos 'source' relativos al script verificado,
# y también buscar rutas absolutas en /mnt/chroot
source-path=SCRIPTDIR
source-path=/mnt/chroot
# Desde la versión 0.9.0, los valores se pueden citar con '' o "" para permitir espacios
source-path="Mis Documentos/scripts"
# Permitir abrir cualquier archivo 'source', incluso si no se especifica como entrada
external-sources=true
# Activar advertencias para variables sin comillas con valores seguros
enable=quote-safe-variables
# Activar advertencias para variables en mayúsculas no asignadas
enable=check-unassigned-uppercase
# Permitir [ ! -z foo ] en lugar de sugerir -n
disable=SC2236

Si no se encuentra ningún .shellcheckrc en ninguno de los directorios padre, ShellCheck buscará en ~/.shellcheckrc seguido por $XDG_CONFIG_HOME (generalmente ~/.config/shellcheckrc) en Unix, o %APPDATA%/shellcheckrc en Windows. Solo se utilizará el primer archivo encontrado.

Nota para usuarios de Snap: la caja de arena de Snap prohíbe el acceso a archivos ocultos. Use shellcheckrc sin el punto en su lugar.

Nota para usuarios de Docker: ShellCheck solo podrá buscar archivos que estén montados en el contenedor, por lo que ~/.shellcheckrc no se leerá.

VARIABLES DE ENTORNO

La variable de entorno SHELLCHECK_OPTS puede configurarse con indicadores predeterminados:

export SHELLCHECK_OPTS='--shell=bash --exclude=SC2016'

Su valor se dividirá por espacios y se antepondrá a la línea de comandos en cada invocación.

VALORES DE RETORNO

ShellCheck utiliza los siguientes códigos de salida:

•
0: Todos los archivos escaneados con éxito sin problemas.
•
1: Todos los archivos escaneados con éxito con algunos problemas.
•
2: Algunos archivos no pudieron ser procesados (por ejemplo, archivo no encontrado).
•
3: ShellCheck se invocó con sintaxis incorrecta (por ejemplo, indicador desconocido).
•
4: ShellCheck se invocó con opciones incorrectas (por ejemplo, formateador desconocido).

LOCALIZACIÓN

Esta versión de ShellCheck solo está disponible en inglés. Todos los archivos se decodifican de forma flexible como UTF-8, con un fallback de ISO-8859-1 para secuencias inválidas. Se respeta LC_CTYPE para la salida, y tiene como valor predeterminado UTF-8 para locales donde la codificación no está especificada (como la locale C).

Los usuarios de Windows que vean commitBuffer: invalid argument (invalid character) deben configurar su terminal para usar UTF-8 con chcp 65001.

INCOMPATIBILIDADES CONOCIDAS

(Si nada en esta sección tiene sentido, es poco probable que se vea afectado por ella)

Para evitar sugerencias confusas y equivocadas, ShellCheck requiere que los cuerpos de las funciones sean { grupos de llaves; } o ( subshells ), y los nombres de funciones que contienen []*=! solo se reconocen después de la palabra clave function.

Las siguientes definiciones de funciones no convencionales son idénticas en Bash, pero ShellCheck solo reconoce la última.

[x!=y] () [[ $1 ]]
function [x!=y] () { [[ $1 ]]; }

Los shells sin la palabra clave function no permiten estos caracteres en los nombres de funciones para empezar. Los nombres de funciones que contienen {} no se admiten en absoluto.

Además, si ShellCheck ve [x!=y], asumirá que es una comparación inválida. Para invocar la función anterior, cite el comando como en '[x!=y]', o para conservar el mismo comportamiento de globbing, use command [x!=y].

ShellCheck impone restricciones adicionales al comando [ para ayudar a diagnosticar usos inválidos comunes. Si bien [ $x= 1 ] está definido en POSIX, ShellCheck asumirá que se pretendía como la comparación mucho más probable [ "$x" = 1 ] y fallará en consecuencia. Para usos no convencionales o dinámicos del comando [, use test o \[ en su lugar.
