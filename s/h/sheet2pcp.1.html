SHEET2PCP(1) Manual de comandos generales SHEET2PCP(1)

NOMBRE

sheet2pcp - importar datos de hoja de cálculo y crear un archivo PCP

SINOPSIS

sheet2pcp [-h host] [-V version] [-Z zona_horaria] archivo_entrada archivo_mapeo archivo_salida

DESCRIPCIÓN

sheet2pcp tiene la intención de leer una hoja de cálculo de datos (archivo_entrada) y traducirla a un archivo de Performance Co-Pilot (PCP) con el nombre base archivo_salida.

La hoja de cálculo de entrada puede estar en cualquiera de los formatos comunes, siempre que los módulos de Perl apropiados se hayan instalado (ver la sección ADVERTENCIAS más abajo). La hoja de cálculo debe estar "normalizada" de modo que cada fila contenga datos para el mismo intervalo de tiempo, y una de las columnas contenga la fecha y hora de los datos en cada fila.

El archivo PCP resultante puede usarse con todas las herramientas cliente de PCP para graficar subconjuntos de los datos usando pmchart(1), realizar reducción de datos e informes, filtrar con el motor de inferencia de PCP pmie(1), etc.

El archivo_mapeo controla el proceso de importación y define el mapeo de datos de las columnas de la hoja de cálculo al modelo de datos de PCP. El archivo está escrito en XML y cumple con la sintaxis definida en la sección CONFIGURACIÓN DE MAPEADO más abajo.

Se crearán una serie de archivos físicos con el prefijo archivo_salida. Estos son archivo_salida.0 (los datos de rendimiento), archivo_salida.meta (los metadatos que describen los datos de rendimiento) y archivo_salida.index (un índice temporal para mejorar la eficiencia de las operaciones de reproducción del archivo). Si alguno de estos archivos existe, entonces sheet2pcp **no** los sobrescribirá y saldrá con un mensaje de error.

La opción -h es una alternativa al atributo hostname del elemento <sheet> en archivo_mapeo descrito a continuación. Si ambos se especifican, se utiliza el valor de archivo_mapeo.

La opción -V especifica la versión para el archivo PCP de salida. Por defecto, se utiliza la versión de archivo $PCP_ARCHIVE_VERSION (establecida en 3 en las versiones actuales de PCP), y los únicos valores actualmente compatibles con version son 2 o 3.

La opción -Z es una alternativa al atributo timezone del elemento <sheet> en archivo_mapeo descrito a continuación. Si ambos se especifican, se utiliza el valor de archivo_mapeo.

sheet2pcp es un script de Perl que utiliza el wrapper de Perl PCP::LogImport que está sobre la biblioteca libpcp_import de PCP, y como tal podría usarse como ejemplo para desarrollar nuevas herramientas para importar otros tipos de datos de rendimiento y crear archivos PCP.

CONFIGURACIÓN DE MAPEADO

El archivo_mapeo contiene especificaciones en formato XML estándar.

La especificación completa está envuelta en un elemento <sheet> ... </sheet>. La etiqueta sheet admite los siguientes atributos opcionales:

heading
Especifica el número de filas de encabezado a omitir al inicio de la hoja de cálculo antes de procesar los datos. Ejemplo: heading="1".
hostname
Establece el nombre de host de origen en el archivo PCP (el valor predeterminado es usar el nombre de host de la máquina local). Ejemplo: hostname="algun.lugar.com".
timezone
Establece la zona horaria de origen en el archivo PCP (el valor predeterminado es usar UTC). La zona horaria debe tener el formato +HHMM (para horas y minutos al este de UTC) o -HHMM (para horas y minutos al oeste de UTC). Tenga en cuenta en particular que **ni** el formato zoneinfo (también conocido como Olson), por ejemplo, Europe/Paris, **ni** el formato Posix TZ, por ejemplo, EST+5, están permitidos. Ejemplo: timezone="+1100".
datefmt
El formato de la fecha importada de la hoja de cálculo se puede especificar como una concatenación de valores que especifican el orden del año (Y), mes (M) y día (D) en una fecha. Las variantes soportadas son DMY (el valor predeterminado), MDY y YMD. Ejemplo: datefmt="YMD".

Un elemento <sheet> contiene una o más especificaciones de métrica de la forma <metric>nombre_metrica</metric>. La etiqueta metric admite los siguientes atributos opcionales:

pmid
El Identificador de Métricas de Rendimiento (PMID), especificado como 3 números separados por un punto (.) para establecer los campos dominio, cluster e ítem del PMID, ver PMNS(5) para más detalles sobre los PMID. Si se omite, el PMID se asignará automáticamente por pmiAddMetric(3). El valor PM_ID_NULL puede usarse para nominar explícitamente el comportamiento predeterminado. Ejemplos: pmid="60.0.2", pmid="PM_ID_NULL".
indom
Cada métrica puede tener uno o más valores. Si una métrica **siempre** tiene un valor, es singular y el Dominio de Instancia debe establecerse en PM_INDOM_NULL. De lo contrario, indom debe especificarse como 2 números separados por un punto (.) para establecer los campos dominio y ordinal del Dominio de Instancia. Ejemplos: indom="PM_INDOM_NULL", indom="60.3", indom="PMI_DOMAIN.4".

Más de una métrica puede compartir el mismo Dominio de Instancia cuando las métricas tienen valores definidos sobre conjuntos similares de instancias, por ejemplo, todas las métricas para cada interfaz de red. Es una práctica estándar que el campo dominio sea el mismo para el pmid y el indom; si el atributo pmid falta, entonces el campo dominio para el indom debe ser el dominio reservado PMI_DOMAIN.

Si el atributo indom se omite, entonces el Dominio de Instancia predeterminado para la métrica es PM_INDOM_NULL.

units
La escala y la dimensión de los valores métricos en los ejes de espacio, tiempo y recuento (eventos, mensajes, paquetes, etc.) se especifican con un 6-tupla. Estos valores se pasan a la función pmiUnits(3) para generar una estructura pmUnits. Consulte pmLookupDesc(3) para una descripción completa de todos los campos de esta estructura. El valor predeterminado es asignar ninguna escala ni dimensión a la métrica, es decir, units="0,0,0,0,0,0". Ejemplos: units="0,1,0,0,PM_TIME_MSEC,0" (milisegundos), units="1,-1,0,PM_SPACE_MBYTE,PM_TIME_SEC,0" (Mbytes/segundo), units="0,1,-1,0,PM_TIME_USEC,PM_COUNT_ONE" (microsegundos/evento).
type
Define el tipo de datos para la métrica. Consulte pmLookupDesc(3) para una descripción completa de los posibles valores de tipo; el valor predeterminado es PM_TYPE_FLOAT. Ejemplos: type="PM_TYPE_32", type="PM_TYPE_U64", type="PM_TYPE_STRING".
sem
Define la semántica de la métrica. Consulte pmLookupDesc(3) para una descripción completa de los posibles valores; el valor predeterminado es PM_SEM_INSTANT. Ejemplos: sem="PM_SEM_COUNTER", type="PM_SEM_DISCRETE".

Las especificaciones restantes definen las columnas de datos **en orden** usando **exactamente** un elemento <datetime></datetime>, uno o más elementos <data>espec_metrica</data> y uno o más elementos <skip></skip>.

El elemento <datetime> define la columna en la que se encontrará una fecha y hora para formar la marca de tiempo en el archivo PCP para todos los datos de cada fila del archivo PCP.

Para el elemento <data>, una espec_metrica consiste en un nombre de métrica (como se define en un elemento <metric> anterior), seguido opcionalmente por un nombre de instancia que está entre corchetes, por ejemplo <data>hinv.ncpu</data>, <data>kernel.all.load[1 minute]</data>.

La etiqueta skip define la columna que debe omitirse al preparar los datos para el archivo PCP.

El orden de los elementos <datetime>, <data> y <skip> coincide con el orden de las columnas en la hoja de cálcul

ADVERTENCIAS

La importación de hojas de cálculo requiere que el módulo de Perl Spreadsheet::ParseExcel esté instalado para los archivos `.xls` o el módulo Text::CSV_XS esté instalado para los archivos `.csv`. Esto se puede lograr ejecutando:

cpanm Spreadsheet::ParseExcel

o

cpanm Text::CSV_XS

También se puede usar una combinación de los dos anteriores.

Si el archivo de entrada se lee con retraso (es decir, hay un intervalo de tiempo entre el momento en que se crean los datos y el momento en que se importan en un archivo PCP), entonces la marca de tiempo en el archivo PCP se ajustará hacia atrás en el número de intervalos de tiempo especificados por el atributo delay del elemento <sheet>.

El retraso se especifica como un número de intervalos de tiempo de la hoja de cálculo para retroceder. Por ejemplo, si la hoja de cálculo tiene registros cada 5 minutos, y el atributo delay se establece en "2", entonces se observarán 10 minutos de retraso.

EJEMPLO

La siguiente es una muestra de un archivo de mapeo XML llamado `myperf.xml` que especifica la importación de un archivo CSV, `myperf.csv` que contendrá métricas de rendimiento para un host llamado `myhost`. El archivo CSV contiene columnas para la fecha y hora, la carga de CPU (en un intervalo de 1 minuto) y la cantidad de memoria utilizada (en MBytes).

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE sheet SYSTEM "pcp.dtd"
[
  <!ENTITY % pminfo SYSTEM "pcp.entities" >
  %pminfo;
]>

<sheet heading="1" hostname="myhost" timezone="+1100">
  <metric pmid="60.0.1" indom="60.1" units="0,1,0,0,0,0" type="PM_TYPE_FLOAT" sem="PM_SEM_COUNTER">
    <help>Load average over 1 minute</help>
  </metric>
  <metric pmid="60.0.2" indom="PM_INDOM_NULL" units="0,1,0,PM_SPACE_MBYTE,0,0" type="PM_TYPE_FLOAT" sem="PM_SEM_INSTANT">
    <help>Memory used</help>
  </metric>

  <datetime>A1</datetime>
  <data>kernel.all.load[1 minute]</data>
  <data>mem.used</data>
</sheet>

La llamada al comando para importar estos datos en un archivo PCP sería:

sheet2pcp myperf.csv myperf.xml myperf

Esto creará los archivos `myperf.0`, `myperf.meta` y `myperf.index`.

CONSULTE TAMBIÉN

pmchart(1), pmie(1), PMNS(5), pmiAddMetric(3), pmiUnits(3), pmLookupDesc(3) y el archivo de ejemplo en `$PCP_DEMO_DIR/lib PCP/LogImport/sheet2pcp.xml`.

sheet2pcp(1) — PCP Performance Co-Pilot

NAME

sheet2pcp - convert spreadsheet to Process Control Protocol (PCP) archive format

SYNOPSIS

sheet2pcp [-h] [-H host] [-d domain] [-t time] [-c config] [-i infile] [-o outfile]

DESCRIPTION

The sheet2pcp utility reads a spreadsheet file, converts the data into the PCP archive format, and writes it to the archive file named by outfile.

By default, sheet2pcp reads from standard input and writes to standard output. The infile and outfile arguments specify input and output files respectively. If infile is omitted, standard input is used. If outfile is omitted, standard output is used.

The conversion process is controlled by a mapping configuration file, which is specified by the -c option. See MAPPING CONFIGURATION below.

The mapping configuration file uses XML syntax to define how spreadsheet columns and rows are mapped to PCP metrics and time series.

The -t option specifies the time interval (in seconds) between consecutive data points. The default is 1 second.

The -H option specifies the PMCD host to connect to. The -d option specifies the domain to use for metrics. These options are typically used when importing live data from a PMCD.

MAPPING CONFIGURATION

The mapping configuration file is an XML document that describes how to interpret the spreadsheet data. It typically contains one or more <sheet> elements, each defining a mapping for a specific spreadsheet sheet.

Each <sheet> element has the following attributes:

heading
Specifies the row number (1-based) containing the column headers. If this is not specified, the first row is assumed to be the header row.

Within a <sheet> element, the following elements can be used:

<metric>
Defines a PCP metric. This element is mandatory and must appear at least once.
<datetime>
Specifies the column containing the date and time information. The format of the date and time string is determined by the Date::Parse(3pm) module.
<skip>
Specifies a column to be skipped. This is useful for columns that do not contain data to be imported.
<data>
Specifies a column containing data values for a metric. The column name must match one of the headers in the specified heading row.

The <metric> element has the following attributes:

pmid
The PCP metric identifier (PMID) for the metric. This can be a numeric PMID or a textual name (e.g., "kernel.percpu.cpu.sys").
indom
The PCP instance domain (INDOM) for the metric. This is optional. If not specified, the metric is assumed to be non-instance-based.
units
The PCP units for the metric. This is a comma-separated string of values that define the units. See pmiUnits(3) for details.
type
The PCP data type for the metric. Possible values include "PM_TYPE_U64", "PM_TYPE_DOUBLE", etc. See pmLookupDesc(3) for details.
sem
The PCP semantics for the metric. Possible values include "PM_SEM_COUNTER", "PM_SEM_GAUGE", etc. See pmLookupDesc(3) for details.

If the number of elements in the <data> tags does not match the number of columns specified in the mapping configuration, a warning is issued, and the extra elements or columns generate no metric values in the output archive.

EXAMPLE

The mapfile ...

<?xml version="1.0" encoding="UTF-8"?>
<sheet heading="1">
    <!-- simple example -->
    <metric pmid="60.0.2" indom="60.0" units="0,1,0,0,PM_TIME_MSEC,0"
        type="PM_TYPE_U64" sem="PM_SEM_COUNTER">
    kernel.percpu.cpu.sys</metric>
    <datetime></datetime>
    <skip></skip>
    <data>kernel.percpu.cpu.sys[cpu0]</data>
    <data>kernel.percpu.cpu.sys[cpu1]</data>
</sheet>

could be used for a spreadsheet in which the first few rows are ...

    Date;"Status";"SysTime - 0";"SysTime - 1";
    26/01/2001 14:05:22;"Some Busy";0.750;0.133
    26/01/2001 14:05:37;"OK";0.150;0.273
    26/01/2001 14:05:52;"All Busy";0.733;0.653

CAVEATS

Only the first sheet from infile will be processed.

Additional Perl modules must be installed for the various spreadsheet formats, although these are checked for ar run-time so only the modules required for the specific types of spreadsheets you wish to process need be installed:

*.csv
Spreadsheets in the Comma Separated Values (CSV) format require Text::CSV_XS(3pm).
*.sxc or *.ods
OpenOffice documents require Spreadsheet::ReadSXC(3pm), which in turn requires Archive::Zip(3pm).
*.xls
Classical Microsoft Office documents require Spreadsheet::ParseExcel(3pm), which in turn requires OLE::Storage_Lite(3pm).
*.xlsx
Microsoft OpenXML documents require Spreadsheet::XLSX(3pm). sheet2pcp does not appear to work with OpenXML documents saved from OpenOffice.

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).
