DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) calculan una o más reducciones en arrays simétricos en múltiples PEs virtuales. Una reducción realiza una operación binaria asociativa en un conjunto de valores. Para obtener una lista de otras rutinas de reducción SHMEM, consulte intro_shmem(3).

Al igual que con todas las rutinas colectivas de SHMEM, cada una de estas rutinas asume que solo los PEs del conjunto activo llaman a la rutina. Si un PE que no está en el conjunto activo llama a una rutina colectiva SHMEM, se producirá un comportamiento indefinido.

El argumento nreduce determina el número de reducciones separadas a realizar. El array fuente en todos los PEs del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en el array destino en todos los PEs del conjunto activo. El conjunto activo se define por el triplete PE_start, logPE_stride, PE_size.

Los arrays fuente y destino pueden ser el mismo array, pero no pueden ser arrays superpuestos.

Los argumentos son los siguientes:

target
El objeto de datos entero accesible remotamente que se va a actualizar en el PE remoto. Si está utilizando C/C++, el tipo de target debe coincidir con el implícito en la sección SINOPSIS. Si está utilizando el compilador Fortran, debe ser de tipo entero con un tamaño de elemento de 4 bytes para SHMEM_INT4_ADD y 8 bytes para SHMEM_INT8_ADD.
valor
El valor que se va a sumar atómicamente a target. Si está utilizando C/C++, el tipo de value debe coincidir con el implícito en la sección SINOPSIS. Si está utilizando Fortran, debe ser de tipo entero con un tamaño de elemento igual al de target.
pe
Un entero que indica el número de PE en el que se debe actualizar target. Si está utilizando Fortran, debe ser un valor entero predeterminado.
target
Un array simétrico de longitud nreduce elementos para recibir los resultados
de las operaciones de reducción.
El tipo de datos de target varía con la versión de la rutina de reducción
que se llama y el lenguaje utilizado. Al llamar desde C/C++, consulte la
sección SINOPSIS para obtener información sobre los tipos de datos.
Al llamar desde Fortran, los tipos de datos de target son los siguientes:

shmem_comp4_sum_to_all:** COMPLEX(KIND=4).

shmem_comp8_sum_to_all:** Complejo. Si está utilizando Fortran, debe ser
un valor complejo predeterminado.

shmem_int4_sum_to_all:** INTEGER(KIND=4).

shmem_int8_sum_to_all:** Entero. Si está utilizando Fortran, debe ser un
valor entero predeterminado.

shmem_real4_sum_to_all:** REAL(KIND=4).

shmem_real8_sum_to_all:** Real. Si está utilizando Fortran, debe ser un
valor real predeterminado.
shmem_real16_sum_to_all:** Real. Si está utilizando Fortran, debe ser un
valor real predeterminado.
source
Un array simétrico, de longitud nreduce elementos, que contiene un elemento por cada operación de reducción separada. El argumento source debe tener el mismo tipo de datos que target.
nreduce
El número de elementos en los arrays target y source. nreduce debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
PE_start
El número de PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
logPE_stride
El logaritmo (base 2) del paso entre números de PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
pWrk
Un array de trabajo simétrico. El argumento pWrk debe tener el mismo tipo de datos que target. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Un array de trabajo simétrico. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Debe ser un valor entero predeterminado. Cada elemento de este array debe inicializarse con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran) antes de que cualquiera de los PEs del conjunto activo entre en la rutina de reducción.

SYNOPSIS

        #include <mpp/shmem.h>

        void shmem_longdouble_sum_to_all(long double *target, const long double *source,
                                         int nlongdouble, int logPE_stride, int PE_size,
                                         long double *pWrk, long double *pSync);

DESCRIPTION

The `shmem_longdouble_sum_to_all` routine performs a symmetric, all-to-all reduction on the `long double` values in the `source` array and places the results in the `target` array. The reduction is performed across the PEs specified by the `PE_size`, `logPE_stride`, and `PE_mask` arguments. The `PE_mask` is implicit in the reduction routines.

For the reduction operation, the values in the `source` array are summed element-wise, and the final sum is placed in the corresponding element of the `target` array. The `source` and `target` arrays are treated as arrays of `long double` elements, and the `nlongdouble` argument specifies the number of `long double` elements to be summed.

The `logPE_stride` and `PE_size` arguments are used to specify the active set of PEs participating in the reduction. The active set is determined by `PE_size`, `logPE_stride`, and the calling PE's ID.

The `pWrk` and `pSync` arrays are used for internal synchronization and work space. Their sizes are dependent on the specific reduction operation and the number of elements being processed. The required sizes are defined by `SHMEM_REDUCE_MIN_WRKDATA_SIZE` and `SHMEM_REDUCE_SYNC_SIZE`, respectively.

The values of arguments `nlongdouble`, `PE_start`, `logPE_stride`, and `PE_size` must be equal on all PEs in the active set. The same target and source arrays, and the same `pWrk` and `pSync` work arrays, must be passed to all PEs in the active set.

Before any PE calls a reduction routine, you must ensure that the following conditions exist (synchronization via a barrier or some other method is often needed to ensure this): The `pWrk` and `pSync` arrays on all PEs in the active set are not still in use from a prior call to a collective SHMEM routine. The target array on all PEs in the active set is ready to accept the results of the reduction.

Upon return from a reduction routine, the following are true for the local PE: The target array is updated. The values in the `pSync` array are restored to the original values.

NOTES

The terms collective, symmetric, and cache aligned are defined in intro_shmem(3).

All SHMEM reduction routines reset the values in `pSync` before they return, so a particular `pSync` buffer need only be initialized the first time it is used.

You must ensure that the `pSync` array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the `pSync` array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized `pSync` before any of them enter a SHMEM routine called with the `pSync` synchronization array. A `pSync` or `pWrk` array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same `pSync` or `pWrk` arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two `pSync` and `pWrk` arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the `pSync` array and finds the sum of the real variable FOO across all even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOSUM, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOSUM, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_INT4_SUM_TO_ALL(FOOSUM, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOSUM
ENDIF

Example 2: Consider the following C/C++ call:

shmem_int_sum_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_int_sum_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_sum_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_sum_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);
Note that two sets of pWrk and pSync arrays are used alternately because no
synchronization is done between calls.
