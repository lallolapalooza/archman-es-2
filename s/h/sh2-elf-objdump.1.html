DESCRIPCIÓN

objdump muestra información sobre uno o más archivos objeto. Las opciones controlan qué información específica se muestra. Esta información es mayormente útil para programadores que trabajan en las herramientas de compilación, en contraposición a programadores que solo quieren que su programa compile y funcione.

archivo_objeto... son los archivos objeto a examinar. Cuando especificas archivos, objdump muestra información sobre cada uno de los archivos objeto miembros.

OPCIONES

Las formas largas y cortas de las opciones, mostradas aquí como alternativas, son equivalentes. Se debe proporcionar al menos una opción de la lista -a,-d,-D,-e,-f,-g,-G,-h,-H,-p,-P,-r,-R,-s,-S,-t,-T,-V,-x.

-a
--archive-headers
Si alguno de los archivos archivo_objeto son archivos, muestra la información de encabezado del archivo (en un formato similar a ls -l). Además de la información que podrías listar con ar tv, objdump -a muestra el formato del archivo objeto de cada miembro del archivo.
--adjust-vma=offset
Al mostrar información, primero agrega offset a todas las direcciones de sección. Esto es útil si las direcciones de sección no corresponden a la tabla de símbolos, lo que puede ocurrir al colocar secciones en direcciones particulares cuando se usa un formato que no puede representar direcciones de sección, como a.out.
-b nombre_bfd
--target=nombre_bfd
Especifica que el formato del código objeto para los archivos objeto es nombre_bfd. Esta opción puede no ser necesaria; objdump puede reconocer automáticamente muchos formatos.

Por ejemplo,

objdump -b oasys -m vax -h fu.o

muestra información resumida de los encabezados de sección (-h) de fu.o, que se identifica explícitamente (-m) como un archivo objeto VAX en el formato producido por los compiladores Oasys. Puedes listar los formatos disponibles con la opción -i.

-C
--demangle[=estilo]
Decodifica (desenreda) nombres de símbolos de bajo nivel a nombres de nivel de usuario. Además de eliminar el guion bajo inicial agregado por el sistema, esto hace que los nombres de funciones C++ sean legibles. Diferentes compiladores tienen diferentes estilos de mangling. El argumento opcional de estilo de desenredado puede usarse para elegir un estilo de desenredado apropiado para tu compilador.
--recursion-limit
--no-recursion-limit
Habilita o deshabilita un límite en la cantidad de recursión realizada al desenredar cadenas. Dado que los formatos de mangling de nombres permiten un nivel infinito de recursión, es posible crear cadenas cuya decodificación agote la cantidad de espacio de pila disponible en la máquina anfitriona, activando una falla de memoria. El límite intenta evitar que esto suceda restringiendo la recursión a 2048 niveles de anidamiento.

Por defecto, este límite está habilitado, pero deshabilitarlo puede ser necesario para desenredar nombres verdaderamente complicados. Sin embargo, ten en cuenta que si el límite de recursión está deshabilitado, es posible el agotamiento de la pila y cualquier informe de error sobre dicho evento será rechazado.

-g
--debugging
Muestra información de depuración. Esto intenta analizar la información del formato de depuración STABS almacenada en el archivo y la imprime usando una sintaxis similar a C. Si no se encontró depuración STABS, esta opción recibe la opción -W para imprimir cualquier información DWARF en el archivo.
-e
--debugging-tags
Similar a -g, pero la información se genera en un formato compatible con la herramienta ctags.
-d
--disassemble
--disassemble=símbolo
Muestra las mnemónicas del ensamblador para las instrucciones de máquina del archivo de entrada. Esta opción solo desensambla aquellas secciones que se espera que contengan instrucciones. Si se proporciona el argumento opcional símbolo, entonces muestra las mnemónicas del ensamblador comenzando en símbolo. Si símbolo es el nombre de una función, el desensamblado se detendrá al final de la función, de lo contrario, se detendrá cuando se encuentre el siguiente símbolo. Si no hay coincidencias para símbolo, no se mostrará nada.

Nota: si la opción --dwarf=follow-links está habilitada, se leerán las tablas de símbolos en los archivos de información de depuración enlazados y se usarán al desensamblar.

-D
--disassemble-all
Similar a -d, pero desensambla

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Ensambla el contenido de todas las secciones no vacías que no son BSS, no solo aquellas que se espera que contengan instrucciones. Se puede usar -j para seleccionar secciones específicas.

Esta opción también tiene un efecto sutil en el desmontaje de instrucciones en secciones de código. Cuando la opción -d está activa, objdump asumirá que los símbolos presentes en una sección de código ocurren en el límite entre instrucciones y se negará a desmontar a través de dicho límite. Sin embargo, cuando la opción -D está activa, esta suposición se suprime. Esto significa que la salida de -d y -D puede diferir si, por ejemplo, los datos se almacenan en secciones de código.

Si el objetivo es una arquitectura ARM, este interruptor también tiene el efecto de forzar al desmontador a decodificar piezas de datos encontradas en secciones de código como si fueran instrucciones.

Tenga en cuenta que si la opción --dwarf=follow-links está habilitada, se leerán las tablas de símbolos en archivos de información de depuración enlazados y se usarán al desmontar.

--no-addresses
Al desmontar, no imprima direcciones en cada línea ni para símbolos y desplazamientos de reubicación. En combinación con --no-show-raw-insn, esto puede ser útil para comparar la salida del compilador.
--prefix-addresses
Al desmontar, imprima la dirección completa en cada línea. Este es el formato de desmontaje anterior.
-EB
-EL
--endian={big|little}
Especifique la endianidad de los archivos objeto. Esto solo afecta al desmontaje. Puede ser útil al desmontar un formato de archivo que no describe la información de endianidad, como los registros S.
-f
--file-headers
Muestre información resumida de la cabecera general de cada uno de los archivos objfile.
-F
--file-offsets
Al desmontar secciones, siempre que se muestre un símbolo, también se mostrará la posición en el archivo de la región de datos que se va a volcar. Si se están omitiendo ceros, cuando se reanude el desmontaje, se informará al usuario cuántos ceros se omitieron y la posición en el archivo de la ubicación desde donde se reanuda el desmontaje. Al volcar secciones, se mostrará la posición en el archivo de la ubicación desde donde comienza el volcado.
--file-start-context
Especifique que, al mostrar código fuente/desmontaje intercalado (asume -S) de un archivo que aún no se ha mostrado, el contexto se extienda hasta el inicio del archivo.
-h
--section-headers
--headers
Muestre información resumida de las cabeceras de sección del archivo objeto.

Los segmentos de archivo pueden ser reubicados a direcciones no estándar, por ejemplo, utilizando las opciones -Ttext, -Tdata o -Tbss de ld. Sin embargo, algunos formatos de archivo objeto, como a.out, no almacenan la dirección de inicio de los segmentos de archivo. En esas situaciones, aunque ld reubica las secciones correctamente, usar objdump -h para listar las cabeceras de sección del archivo no puede mostrar las direcciones correctas. En su lugar, muestra las direcciones habituales, que son implícitas para el objetivo.

Tenga en cuenta que, en algunos casos, es posible que una sección tenga establecidos tanto el atributo READONLY como el atributo NOREAD. En tales casos, el atributo NOREAD tiene prioridad, pero objdump informará ambos, ya que la configuración exacta de los bits de bandera podría ser importante.

-H
--help
Imprima un resumen de las opciones de objdump y salga.
-i
--info
Muestre una lista que muestre todas las arquitecturas y formatos de objeto disponibles para especificar con -b o -m.
-j name
--section=name
Muestre información para la sección name. Esta opción se puede especificar varias veces.
-L
--process-links
Muestre el contenido de las secciones no de depuración que se encuentran en archivos de depuración separados enlazados al archivo principal. Esta opción implica automáticamente la opción -WK, y solo se mostrarán las secciones solicitadas por otras opciones de la línea de comandos.
-l
--line-numbers
Etiquete la pantalla (utilizando información de depuración) con el nombre del archivo y los números de línea de origen correspondientes al código objeto o las reubicaciones mostradas. Solo útil con -d, -D o -r.
-m machine
--architecture=machine
Especifique la arquitectura a utilizar al desmontar archivos objeto. Esto puede ser útil al desmontar archivos objeto que no describen información de arquitectura, como los registros S. Puede listar las arquitecturas disponibles con la opción -i.

Para la mayoría de las arquitecturas, es posible proporcionar un nombre de arquitectura y un nombre de máquina, separados por dos puntos. Por ejemplo, foo:bar se referiría al tipo de máquina bar en la arquitectura foo. Esto puede ser útil si objdump se ha configurado para admitir múltiples arquitecturas.

Si el objetivo es una arquitectura ARM, este interruptor tiene un efecto adicional. Restringe el desmontaje solo a las instrucciones soportadas por la arquitectura especificada por machine. Si es necesario usar este interruptor porque el archivo de entrada no contiene información de arquitectura, pero también se desea desmontar todas las instrucciones, use -marm.

-M options
--disassembler-options=options
Pase información específica del objetivo al desmontador. Solo compatible con algunos objetivos. Si es necesario especificar más de una opción de desmontador, se pueden usar múltiples opciones -M o se pueden agrupar en una lista separada por comas.

Para ARC, dsp controla la impresión de instrucciones DSP, spfp selecciona la impresión de instrucciones FP de precisión simple FPX, dpfp selecciona la impresión de instrucciones FP de precisión doble FPX, quarkse_em selecciona la impresión de instrucciones especiales QuarkSE-EM, fpuda selecciona la impresión de instrucciones de asistencia de precisión doble, fpus selecciona la impresión de instrucciones FP de precisión simple FPU, mientras que fpud selecciona la impresión de instrucciones FP de precisión doble FPU. Además, se puede optar por que todos los inmediatos se impriman en hexadecimal utilizando hex. Por defecto, los inmediatos cortos se imprimen utilizando la representación decimal, mientras que los valores de inmediato largos se imprimen en hexadecimal.

cpu=... permite forzar una ISA particular al desmontar instrucciones, anulando el valor de -m o lo que sea que esté en el archivo ELF. Esto podría ser útil para seleccionar la ISA ARC EM o HS, porque la arquitectura es la misma para esas y el desmontador se basa en datos privados de la cabecera ELF para decidir si el código es para EM o HS. Esta opción se puede especificar varias veces; solo se usará el último valor. Los valores válidos son los mismos que para la opción del ensamblador -mcpu=....

Si el objetivo es una arquitectura ARM, este interruptor se puede utilizar para seleccionar qué conjunto de nombres de registro se utiliza durante el desmontaje. Especificar -M reg-names-std (el predeterminado) seleccionará los nombres de registro tal como se utilizan en la documentación del conjunto de instrucciones de ARM, pero con el registro 13 llamado 'sp', el registro 14 llamado 'lr' y el registro 15 llamado 'pc'. Especificar -M reg-names-apcs seleccionará el conjunto de nombres utilizado por el Estándar de Llamada de Procedimientos ARM, mientras que especificar -M reg-names-raw simplemente usará r seguido del número de registro.

Existen también dos variantes del esquema de nombres de registro APCS habilitadas por -M reg-names-atpcs y -M reg-names-special-atpcs que utilizan las convenciones de nombres del Estándar de Llamada de Procedimientos ARM/Thumb. (Ya sea con los nombres normales de registro o los nombres de registro especiales).

Esta opción también se puede usar para arquitecturas ARM para forzar al desmontador a interpretar todas las instrucciones como instrucciones Thumb utilizando el interruptor --disassembler-options=force-thumb. Esto puede ser útil al intentar desmontar código thumb producido por otros compiladores.

Para objetivos AArch64, este interruptor se puede usar para establecer si las instrucciones se desmontan como la instrucción más general utilizando la opción -M no-aliases o si las notas de instrucción deben generarse como comentarios en el desmontaje utilizando -M notes.

Para x86, algunas de las opciones duplican las funciones del interruptor -m, pero permiten un control más granular.

"x86-64"
"i386"
"i8086"
Selecciona el desmontaje para la arquitectura dada.
"intel"
"att"
Selecciona entre el modo de sintaxis Intel y el modo de sintaxis AT&T.
"amd64"
"intel64"
Selecciona entre ISA AMD64 e ISA Intel64.
"intel-mnemonic"
"att-mnemonic"
Selecciona entre el modo de mnemónicos Intel y el modo de mnemónicos AT&T. Nota: "intel-mnemonic" implica "intel" y "att-mnemonic" implica "att".
"addr64"
"addr32"
"addr16"
"data32"
"data16"
Especifica el tamaño de dirección y el tamaño de operando predeterminados. Estas cinco opciones serán reemplazadas si "x86-64", "i386" o "i8086" aparecen más tarde en la cadena de opciones.
"suffix"
Cuando está en modo AT&T y también para un conjunto limitado de instrucciones cuando está en modo Intel, instruye al desensamblador a imprimir un sufijo de mnemónica incluso cuando el sufijo podría inferirse de los operandos o, para ciertas instrucciones, los valores predeterminados del modo de ejecución.

Para PowerPC, el argumento -M raw selecciona la desensamblado de instrucciones de hardware en lugar de alias. Por ejemplo, verá "rlwinm" en lugar de "clrlwi", y "addi" en lugar de "li". Todos los argumentos -m para gas que seleccionan una CPU son compatibles. Estos son: 403, 405, 440, 464, 476, 601, 603, 604, 620, 7400, 7410, 7450, 7455, 750cl, 821, 850, 860, a2, booke, booke32, cell, com, e200z2, e200z4, e300, e500, e500mc, e500mc64, e500x2, e5500, e6500, efs, power4, power5, power6, power7, power8, power9, power10, ppc, ppc32, ppc64, ppc64bridge, ppcps, pwr, pwr2, pwr4, pwr5, pwr5x, pwr6, pwr7, pwr8, pwr9, pwr10, pwrx, titan, vle y future. 32 y 64 modifican la selección de CPU predeterminada o anterior, deshabilitando y habilitando las instrucciones de 64 bits respectivamente. Además, altivec, any, lsp, htm, vsx, spe y spe2 añaden capacidades a una selección de CPU anterior o posterior. any desensamblará cualquier opcode conocido por binutils, pero en casos donde un opcode tiene dos significados diferentes o argumentos diferentes, puede que no vea el desensamblado que espera. Si desensambla sin especificar una selección de CPU, se elegirá una predeterminada a partir de la información obtenida por BFD de los encabezados de los archivos objeto, pero el resultado nuevamente puede no ser el que espera.

Para MIPS, esta opción controla la impresión de nombres de mnemónicas de instrucción y nombres de registros en instrucciones desensambladas. Se pueden especificar múltiples selecciones de las siguientes opciones como una cadena separada por comas, y las opciones inválidas se ignoran:

"no-aliases"
Imprime la mnemónica de instrucción 'raw' en lugar de alguna mnemónica de instrucción pseudo. Es decir, imprime 'daddu' u 'or' en lugar de 'move', 'sll' en lugar de 'nop', etc.
"msa"
Desensambla instrucciones MSA.
"virt"
Desensambla las instrucciones de la ASE de virtualización.
"xpa"
Desensambla las instrucciones de la ASE de Dirección Física Extendida (XPA).
"gpr-names=ABI"
Imprime los nombres de los registros de propósito general (GPR) según corresponda a la ABI especificada. Por defecto, los nombres de los GPR se seleccionan de acuerdo con la ABI del binario que se está desensamblando.
"fpr-names=ABI"
Imprime los nombres de los registros de punto flotante (FPR) según corresponda a la ABI especificada. Por defecto, se imprimen los números de FPR en lugar de los nombres.
"cp0-names=ARCH"
Imprime los nombres de los registros CP0 (coprocesador de control del sistema; coprocesador 0) según corresponda a la CPU o arquitectura especificada por ARCH. Por defecto, los nombres de los registros CP0 se seleccionan de acuerdo con la arquitectura y la CPU del binario que se está desensamblando.
"hwr-names=ARCH"
Imprime los nombres de los registros de hardware (HWR, utilizados por la instrucción "rdhwr") según corresponda a la CPU o arquitectura especificada por ARCH. Por defecto, los nombres de los HWR se seleccionan de acuerdo con la arquitectura y la CPU del binario que se está desensamblando.
"reg-names=ABI"
Imprime los nombres de los GPR y FPR según corresponda a la ABI seleccionada.
"reg-names=ARCH"
Imprime nombres de registros específicos de la CPU (nombres de registros CP0 y HWR) según corresponda a la CPU o arquitectura seleccionada.

Para cualquiera de las opciones enumeradas anteriormente, ABI o ARCH se pueden especificar como numeric para que se impriman números en lugar de nombres, para los tipos de registros seleccionados. Puede listar los valores disponibles de ABI y ARCH utilizando la opción --help.

Para VAX, puede especificar direcciones de entrada de funciones con -M entry:0xf00ba. Puede usar esto varias veces para desensamblar correctamente archivos binarios VAX que no contienen tablas de símbolos (como volcados de ROM). En estos casos, la máscara de entrada de función se decodificaría de lo contrario como instrucciones VAX, lo que probablemente llevaría a que el resto de la función se desensamblara incorrectamente.

-p
--private-headers
Imprime información específica del formato del archivo objeto. La información exacta impresa depende del formato del archivo objeto. Para algunos formatos de archivo objeto, no se imprime información adicional.
-P opciones
--private=opciones
Imprime información específica del formato del archivo objeto. El argumento opciones es una lista separada por comas que depende del formato (las listas de opciones se muestran con la ayuda).

Para XCOFF, las opciones disponibles son:

"header"
"aout"
"sections"
"syms"
"relocs"
"lineno,"
"loader"
"except"
"typchk"
"traceback"
"toc"
"ldinfo"

Para PE, las opciones disponibles son:

"header"
"sections"

No todos los formatos de objeto soportan esta opción. En particular, el formato ELF no la utiliza.

-r
--reloc
Imprime las entradas de reubicación del archivo. Si se usa con -d o -D, las reubicaciones se imprimen intercaladas con el desensamblado.
-R
--dynamic-reloc
Imprime las entradas de reubicación dinámicas del archivo. Esto solo es significativo para objetos dinámicos, como ciertos tipos de bibliotecas compartidas. Al igual que con -r, si se usa con -d o -D, las reubicaciones se imprimen intercaladas con el desensamblado.
-s
--full-contents
Muestra el contenido completo de las secciones, a menudo se usa en combinación con -j para solicitar secciones específicas. Por defecto, se muestran todas las secciones no vacías que no son bss. Por defecto, cualquier sección comprimida se mostrará en su forma comprimida. Para ver el contenido en forma descomprimida, agregue la opción -Z a la línea de comandos.
-S
--source
Muestra el código fuente intercalado con el desensamblado, si es posible. Implica -d.
--show-all-symbols
Al desensamblar, muestra todos los símbolos que coinciden con una dirección dada, no solo el primero.
--source-comment[=txt]
Al igual que la opción -S, pero todas las líneas de código fuente se muestran con un prefijo de txt. Típicamente txt será una cadena de comentario que puede usarse para distinguir el código ensamblador del código fuente. Si txt no se proporciona, se usará una cadena predeterminada de "# " (el símbolo de almohadilla seguido de un espacio).
--prefix=prefijo
Especifica prefijo para añadir a las rutas absolutas cuando se usa con -S.
--prefix-strip=nivel
Indica cuántos nombres de directorio iniciales eliminar de las rutas absolutas codificadas. No tiene efecto sin --prefix=prefijo.
--show-raw-insn
Al desensamblar instrucciones, imprime la instrucción en hexadecimal además de en forma simbólica. Esto es lo predeterminado, excepto cuando se usa --prefix-addresses.
--no-show-raw-insn
Al desensamblar instrucciones, no imprima los bytes de la instrucción. Esto es lo predeterminado cuando se usa --prefix-addresses.
--insn-width=ancho
Muestra ancho bytes en una sola línea al desensamblar instrucciones.
--visualize-jumps[=color|=extended-color|=off]
Visualiza los saltos que permanecen dentro de una función dibujando arte ASCII entre las direcciones de inicio y destino. El argumento opcional =color agrega color a la salida utilizando colores de terminal simples. Alternativamente, el argumento =extended-color agregará color utilizando colores de 8 bits, pero estos pueden no funcionar en todos los terminales.

Si es necesario deshabilitar la opción visualize-jumps después de que se haya habilitado previamente, use visualize-jumps=off.

--disassembler-color=off
--disassembler-color=terminal
--disassembler-color=on|color|colour
--disassembler-color=extened|extended-color|extened-colour
Habilita o deshabilita el uso de resaltado de sintaxis en color en la salida de desensamblado. El valor predeterminado
El comportamiento se determina mediante una opción de tiempo de configuración. Nota: no todas las arquitecturas admiten resaltado de sintaxis en color, y dependiendo del terminal utilizado, la salida en color puede no ser realmente legible.

NAME

objdump — display information from object files

SYNOPSIS

objdump [option...] [objfile...]

objdump -i

objdump -j section ...

objdump -T [objfile...]

objdump -x [objfile...]

DESCRIPTION

The objdump utility is a universal binary parsing tool. It can display information from object files to help programmers understand the structure of object files and the assembly code generated by the compiler.

The output format of objdump is divided into several sections. The section headers of the file are listed first, followed by the contents of each section. The symbol table is displayed last.

objdump can display information from object files in a variety of formats. Some of the most common formats are described below.

OPTIONS

-a
--all-headers
Display all available header information, including the symbol table and relocation entries. Using -a is equivalent to specifying all of -h -l -p -r -t.
-A <architecture>
--architecture=<architecture>
Display information for the specified architecture. This option is only useful when disassembling files with multiple architectures.
-b <format>
--target=<format>
Display information for the specified format. The default is to automatically determine the file format. This option is only useful when disassembling files that have multiple formats.
-B <prefix>
--prefix-symbols=<prefix>
Prepend the specified prefix to all symbols. This option is useful for creating unique symbol names in shared libraries.
-C
--demangle
Decode name-mangled symbols. This option is useful for displaying C++ symbols in a human-readable format.
-d
--disassemble
Disassemble the contents of the object file. This option is useful for viewing the assembly code generated by the compiler.
-D
--disassemble-all
Disassemble all of the contents of the object file, including non-executable sections. This option is useful for viewing the assembly code for the entire object file.
-e <section>
--section=<section>
Display only the specified section. This option can be used multiple times to display multiple sections.
-f
--file-headers
Display the full file header information.
-g
--debugging
Display debugging information. This option is useful for viewing symbol table entries and other debugging information.
-h
--headers
Display the section headers.
-i
--info
Display detailed information about the file format and its supported architectures.
-j <section>
--section=<section>
Display only the specified section. This option can be used multiple times to display multiple sections.
-l
--line-numbers
Display line number information. This option is useful for correlating assembly code with source code.
-p
--program-headers
Display the program headers.
-r
--relocations
Display the relocation entries.
-s
--hex-dump=<section>
