DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) calculan una o más reducciones en arrays simétricos en múltiples PEs virtuales. Una reducción realiza una operación binaria asociativa en un conjunto de valores. Para obtener una lista de otras rutinas de reducción de SHMEM, consulte intro_shmem(3).

Al igual que con todas las rutinas colectivas de SHMEM, cada una de estas rutinas asume que solo los PEs del conjunto activo llaman a la rutina. Si un PE que no está en el conjunto activo llama a una rutina colectiva de SHMEM, el resultado es indefinido.

El argumento nreduce determina el número de reducciones separadas a realizar. El array fuente en todos los PEs del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en el array destino en todos los PEs del conjunto activo. El conjunto activo se define mediante el trío PE_start, logPE_stride, PE_size.

Los arrays fuente y destino pueden ser el mismo array, pero no pueden ser arrays superpuestos.

Los argumentos son los siguientes:

target
Un array simétrico de longitud nreduce elementos para recibir los resultados de las operaciones de reducción. El tipo de datos de target varía según la versión de la rutina de reducción que se llama y el idioma utilizado. Al llamar desde C/C++, consulte la sección RESUMEN para obtener información sobre los tipos de datos. Al llamar desde Fortran, los tipos de datos de destino son los siguientes:
shmem_comp4_prod_to_all: Complejo, con un tamaño de elemento igual a dos
Valores reales de 4 bytes.
shmem_comp8_prod_to_all: Complejo, con un tamaño de elemento igual a dos
Valores reales de 8 bytes.

shmem_int4_prod_to_all: Entero, con un tamaño de elemento de 4 bytes

shmem_int8_prod_to_all: Entero, con un tamaño de elemento de 8 bytes

shmem_real4_prod_to_all: Real, con un tamaño de elemento de 4 bytes

shmem_real8_prod_to_all: Real, con un tamaño de elemento de 8 bytes

shmem_real16_prod_to_all: Real, con un tamaño de elemento de 16 bytes

source
Un array simétrico, de longitud nreduce elementos, que contiene un elemento para cada operación de reducción separada. El argumento fuente debe tener el mismo tipo de datos que target.
nreduce
El número de elementos en los arrays target y source. nreduce debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
PE_start
El número PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
logPE_stride
El logaritmo (base 2) del paso entre los números PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
pWrk
Un array de trabajo simétrico. El argumento pWrk debe tener el mismo tipo de datos que target. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Un array de trabajo simétrico. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Si está utilizando Fortran, debe ser un valor entero por defecto. Antes de que cualquiera de los PEs del conjunto activo entre en la rutina de reducción, cada elemento de este array debe inicializarse con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran).

Los valores de los argumentos nreduce, PE_start, logPE_stride y PE_size deben ser iguales en todos los PEs del conjunto activo. Los mismos arrays target y source, y los mismos arrays de trabajo pWrk y pSync, deben pasarse a todos los PEs del conjunto activo. Antes de que cualquier PE llame a una rutina de reducción, debe asegurarse de que se cumplan las siguientes condiciones (la sincronización mediante una barrera u otro método suele ser necesaria para garantizar esto): Los arrays pWrk y pSync en todos los PEs del conjunto activo ya no están en uso de una llamada anterior a una rutina colectiva de SHMEM. El array target en todos los PEs del conjunto activo está listo para recibir los resultados de la reducción.

Al regresar de una rutina de reducción, lo siguiente es cierto para el PE local: el array target se actualiza. Los valores del array pSync se restauran a los valores originales.

NOTAS

Los términos colectivo, simétrico y alineado en caché se definen en intro_shmem(3). Todas las rutinas de reducción de SHMEM restauran los valores en pSync antes de regresar, por lo que un búfer pSync particular solo necesita ser inicializado

shmem_double_prod_to_all(3) — Arch manual pages

SYNOPSIS

Fortran:
CALL SHMEM_DOUBLE_PROD_TO_ALL(TARGET, SOURCE, N, REDUX, ...)
C/C++:
void shmem_double_prod_to_all(double *target, double *source, int n, int redux, int stride, int PE_count, long PE_group[], double pWrk[], long pSync[])

DESCRIPTION

The SHMEM reduction routines compute the product of elements between the source arrays on participating processing elements (PEs), and place the result in the target arrays.

The target array is updated on each PE with the product of the source arrays. The product is computed across all PEs specified by the PE_count and PE_group arguments.

The n argument specifies the number of double-precision floating-point values to be multiplied.

The redux argument specifies the type of reduction. REDUX = 0 specifies a product reduction. Other values are ignored.

The stride argument specifies the element stride in the source and target arrays.

The PE_count argument specifies the number of PEs in the group that will participate in the reduction.

The PE_group argument is an array of PEs that will participate in the reduction.

The pWrk and pSync arguments are work arrays. pWrk is used to store intermediate reduction results. pSync is used to synchronize the PEs during the reduction operation.

The sizes of the work arrays are:

  • pWrk: MAX(n/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elements.
  • pSync: SHMEM_REDUCE_SYNC_SIZE elements.

These work arrays must be initialized appropriately before calling the SHMEM reduction routines. See the SHMEM man page for details.

NOTES

The pSync array must be initialized to the value SHMEM_SYNC_VALUE before the first time it is used.

You must ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the product of the real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMP8_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

Example 2: Consider the following C/C++ call:

shmem_short_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_short_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_short_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_short_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
