shm_open(3) Manual de Funciones de Biblioteca shm_open(3)

NOMBRE

shm_open, shm_unlink - crear/abrir o desvincular objetos de memoria compartida POSIX

BIBLIOTECA

Biblioteca en tiempo real (librt, -lrt)

SINOPSIS

#include <sys/mman.h>
#include <sys/stat.h>        /* Para constantes de modo */
#include <fcntl.h>           /* Para constantes O_* */
int shm_open(const char *nombre, int oflag, mode_t mode);
int shm_unlink(const char *nombre);

DESCRIPCIÓN

shm_open() crea y abre un nuevo objeto de memoria compartida POSIX, o abre uno existente. Un objeto de memoria compartida POSIX es en efecto un manejador que puede ser utilizado por procesos no relacionados para mmap(2) la misma región de memoria compartida. La función shm_unlink() realiza la operación inversa, eliminando un objeto creado previamente por shm_open().

La operación de shm_open() es análoga a la de open(2). nombre especifica el objeto de memoria compartida a crear o abrir. Para un uso portable, un objeto de memoria compartida debe ser identificado por un nombre de la forma /nombredelobj; es decir, una cadena terminada en nulo de hasta NAME_MAX (es decir, 255) caracteres que consisten en una barra inicial, seguida de uno o más caracteres, ninguno de los cuales son barras.

oflag es una máscara de bits creada combinando exactamente una de O_RDONLY u O_RDWR con cualesquiera de las otras banderas listadas aquí:

O_RDONLY
Abrir el objeto para acceso de lectura. Un objeto de memoria compartida abierto de esta manera solo puede ser mapeado con mmap(2) para acceso de lectura (PROT_READ).
O_RDWR
Abrir el objeto para acceso de lectura-escritura.
O_CREAT
Crear el objeto de memoria compartida si no existe. La propiedad de usuario y grupo del objeto se toma de los IDs efectivos correspondientes del proceso que llama, y los bits de permisos del objeto se establecen según los 9 bits de orden inferior de mode, excepto que aquellos bits establecidos en la máscara de creación de modo de archivo del proceso (ver umask(2)) se borran para el nuevo objeto. Un conjunto de constantes macro que pueden usarse para definir mode se lista en open(2). (Las definiciones simbólicas de estas constantes se pueden obtener incluyendo <sys/stat.h>).
Un nuevo objeto de memoria compartida tiene inicialmente longitud cero: el tamaño del objeto se puede establecer usando ftruncate(2). Los bytes recién asignados de un objeto de memoria compartida se inicializan automáticamente a 0.
O_EXCL
Si también se especificó O_CREAT, y un objeto de memoria compartida con el nombre dado ya existe, devuelve un error. La comprobación de la existencia del objeto, y su creación si no existe, se realizan de forma atómica.
O_TRUNC
Si el objeto de memoria compartida ya existe, truncarlo a cero bytes.

Las definiciones de estos valores de bandera se pueden obtener incluyendo <fcntl.h>.

En caso de éxito, shm_open() devuelve un descriptor de archivo que se refiere al objeto de memoria compartida. Este descriptor de archivo está garantizado para ser el descriptor de archivo de menor número no abierto previamente dentro del proceso. La bandera FD_CLOEXEC (ver fcntl(2)) se establece para el descriptor de archivo.

El descriptor de archivo se usa normalmente en llamadas posteriores a ftruncate(2) (para un objeto recién creado) y mmap(2). Después de una llamada a mmap(2), el descriptor de archivo puede cerrarse sin afectar al mapeo de memoria.

La operación de shm_unlink() es análoga a unlink(2): elimina un nombre de objeto de memoria compartida y, una vez que todos los procesos han desmapeado el objeto, desasigna y destruye el contenido de la región de memoria asociada. Después de un shm_unlink() exitoso, los intentos de shm_open() de un objeto con el mismo nombre fallan (a menos que se especifique O_CREAT, en cuyo caso se crea un nuevo objeto distinto).

VALOR DE RETORNO

En caso de éxito, shm_open() devuelve un descriptor de archivo (un entero no negativo). En caso de éxito, shm_unlink() devuelve 0. En caso de fallo, ambas funciones devuelven -1 y establecen errno para indicar el error.

ERRORES

EACCES
Se denegó el permiso para shm_unlink() del objeto de memoria compartida.
EACCES
Se denegó el permiso para shm_open() de nombre en el mode especificado, o se especificó O_TRUNC y el llamante no tiene permiso de escritura sobre el objeto.
EEXIST
Se especificaron tanto O_CREAT como O_EXCL a shm_open() y el objeto de memoria compartida especificado por nombre ya existe.
EINVAL
El argumento nombre de shm_open() era inválido.
EMFILE
Se alcanzó el límite por proceso en el número de descriptores de archivo abiertos.
ENAMETOOLONG
La longitud de nombre excede PATH_MAX.
ENFILE
Se alcanzó el límite del sistema en el número total de archivos abiertos.
ENOENT
Se intentó shm_open() un nombre que no existía, y no se especificó O_CREAT.
ENOENT
Se intentó shm_unlink() un nombre que no existe.

VERSIÓNES

POSIX deja sin especificar el comportamiento de la combinación de O_RDONLY y O_TRUNC. En Linux, esto truncará con éxito un objeto de memoria compartida existente; esto puede no ser así en otros sistemas UNIX.

La implementación de objetos de memoria compartida POSIX en Linux utiliza un sistema de archivos tmpfs(5) dedicado que normalmente está montado en /dev/shm.

ESTÁNDARES

POSIX.1-2008.

HISTORIA

glibc 2.2. POSIX.1-2001.

POSIX.1-2001 dice que la propiedad de grupo de un objeto de memoria compartida recién creado se establece en el ID de grupo efectivo del proceso que llama o "un ID de grupo predeterminado del sistema". POSIX.1-2008 dice que la propiedad de grupo puede establecerse en el ID de grupo efectivo del proceso que llama o, si el objeto es visible en el sistema de archivos, el ID de grupo del directorio padre.

PROGRAM SOURCE: pshm_ucase_bounce.c

The "bounce" program creates a new shared memory object with the name given in its command-line argument and sizes the object to match the size of the shmbuf structure defined in the header file. It then maps the object into the process's address space, and initializes two POSIX semaphores inside the object to 0.

After the "send" program has posted the first of the semaphores, the "bounce" program upper cases the data that has been placed in the memory by the "send" program and then posts the second semaphore to tell the "send" program that it may now access the shared memory.


/* pshm_ucase_bounce.c
   Licensed under GNU General Public License v2 or later.
*/
#include <ctype.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <unistd.h>
#include "pshm_ucase.h"
int
main(int argc, char *argv[])
{
    int            fd;
    char           *shmpath;
    struct shmbuf  *shmp;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s /shm-path\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    shmpath = argv[1];
    /* Create shared memory object and set its size to the size
       of our structure.  */
    fd = shm_open(shmpath, O_CREAT | O_EXCL | O_RDWR, 0600);
    if (fd == -1)
        err(EXIT_FAILURE, "shm_open");
    if (ftruncate(fd, sizeof(struct shmbuf)) == -1)
        err(EXIT_FAILURE, "ftruncate");
    /* Map the object into the caller's address space.  */
    shmp = mmap(NULL, sizeof(*shmp), PROT_READ | PROT_WRITE,
                MAP_SHARED, fd, 0);
    if (shmp == MAP_FAILED)
        err(EXIT_FAILURE, "mmap");
    /* Initialize semaphores as process-shared, with value 0.  */
    if (sem_init(&shmp->sem1, 1, 0) == -1)
        err(EXIT_FAILURE, "sem_init-sem1");
    if (sem_init(&shmp->sem2, 1, 0) == -1)
        err(EXIT_FAILURE, "sem_init-sem2");
    /* Wait for 'sem1' to be posted by peer before touching
       shared memory.  */
    if (sem_wait(&shmp->sem1) == -1)
        err(EXIT_FAILURE, "sem_wait");
    /* Convert data in shared memory into upper case.  */
    for (size_t j = 0; j < shmp->cnt; j++)
        shmp->buf[j] = toupper((unsigned char) shmp->buf[j]);
    /* Post 'sem2' to tell the peer that it can now
       access the modified data in shared memory.  */
    if (sem_post(&shmp->sem2) == -1)
        err(EXIT_FAILURE, "sem_post");
    /* Unlink the shared memory object.  Even if the peer process
       is still using the object, this is okay.  The object will
       be removed only after all open references are closed.  */
    shm_unlink(shmpath);
    exit(EXIT_SUCCESS);
}

PROGRAM SOURCE: pshm_ucase_send.c

The "send" program takes two command-line arguments: the pathname of a shared memory object previously created by the "bounce" program and a string that is to be copied into that object.

The program opens the shared memory object and maps the object into its address space. It then copies the data specified in its second argument into the shared memory, and posts the first semaphore, which tells the "bounce" program that it can now access that data. After the "bounce" program posts the second semaphore, the "send" program prints the contents of the shared memory on standard output.


/* pshm_ucase_send.c
   Licensed under GNU General Public License v2 or later.
*/
#include <fcntl.h>
#include <stddef.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#include <unistd.h>
#include "pshm_ucase.h"
int
main(int argc, char *argv[])
{
    int            fd;
    char           *shmpath, *string;
    size_t         len;
    struct shmbuf  *shmp;
    if (argc != 3) {
        fprintf(stderr, "Usage: %s /shm-path string\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    shmpath = argv[1];
    string = argv[2];
    len = strlen(string);
    if (len > BUF_SIZE) {
        fprintf(stderr, "String is too long\n");
        exit(EXIT_FAILURE);
    }
    /* Open the existing shared memory object and map it
       into the caller's address space.  */
    fd = shm_open(shmpath, O_RDWR, 0);
    if (fd == -1)
        err(EXIT_FAILURE, "shm_open");
    shmp = mmap(NULL, sizeof(*shmp), PROT_READ | PROT_WRITE,
                MAP_SHARED, fd, 0);
    if (shmp == MAP_FAILED)
        err(EXIT_FAILURE, "mmap");
    /* Copy data into the shared memory object.  */
    shmp->cnt = len;
    memcpy(&shmp->buf, string, len);
    /* Tell peer that it can now access shared memory.  */
    if (sem_post(&shmp->sem1) == -1)
        err(EXIT_FAILURE, "sem_post");
    /* Wait until peer says that it has finished accessing
       the shared memory.  */
    if (sem_wait(&shmp->sem2) == -1)
        err(EXIT_FAILURE, "sem_wait");
    /* Write modified data in shared memory to standard output.  */
    if (write(STDOUT_FILENO, &shmp->buf, len) == -1)
        err(EXIT_FAILURE, "write");
    if (write(STDOUT_FILENO, "\n", 1) == -1)
        err(EXIT_FAILURE, "write");
    exit(EXIT_SUCCESS);
}
