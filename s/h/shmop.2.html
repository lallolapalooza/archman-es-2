SHMOP(2) Manual de llamadas al sistema SHMOP(2)

NOMBRE

shmat, shmdt - operaciones de memoria compartida System V

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/shm.h>
void *shmat(int shmid, const void *_Nullable shmaddr, int shmflg);
int shmdt(const void *shmaddr);

DESCRIPCIÓN

shmat()

shmat() adjunta el segmento de memoria compartida System V identificado por shmid al espacio de direcciones del proceso que llama. La dirección de adjunción se especifica mediante shmaddr con uno de los siguientes criterios:

•
Si shmaddr es NULL, el sistema elige una dirección adecuada (no utilizada) alineada en páginas para adjuntar el segmento.
•
Si shmaddr no es NULL y SHM_RND se especifica en shmflg, la adjunción se realiza en la dirección igual a shmaddr redondeada hacia abajo al múltiplo más cercano de SHMLBA.
•
De lo contrario, shmaddr debe ser una dirección alineada en páginas en la que se realiza la adjunción.

Además de SHM_RND, las siguientes banderas se pueden especificar en el argumento de máscara de bits shmflg:

SHM_EXEC (específico de Linux; desde Linux 2.6.9)
Permitir que el contenido del segmento sea ejecutado. El llamante debe tener permiso de ejecución sobre el segmento.
SHM_RDONLY
Adjuntar el segmento para acceso de solo lectura. El proceso debe tener permiso de lectura para el segmento. Si esta bandera no se especifica, el segmento se adjunta para acceso de lectura y escritura, y el proceso debe tener permiso de lectura y escritura para el segmento. No existe la noción de un segmento de memoria compartida de solo escritura.
SHM_REMAP (específico de Linux)
Esta bandera especifica que el mapeo del segmento debe reemplazar cualquier mapeo existente en el rango que comienza en shmaddr y continúa por el tamaño del segmento. (Normalmente, un error EINVAL resultaría si ya existiera un mapeo en este rango de direcciones). En este caso, shmaddr no debe ser NULL.

El valor de brk(2) del proceso que llama no se altera con la adjunción. El segmento se desadjuntará automáticamente al salir del proceso. El mismo segmento puede adjuntarse como de solo lectura, como de lectura/escritura, y más de una vez, en el espacio de direcciones del proceso.

Una llamada exitosa a shmat() actualiza los miembros de la estructura shmid_ds (ver shmctl(2)) asociada al segmento de memoria compartida de la siguiente manera:

•
shm_atime se establece a la hora actual.
•
shm_lpid se establece al ID de proceso del proceso que llama.
•
shm_nattch se incrementa en uno.

shmdt()

shmdt() desadjunta el segmento de memoria compartida ubicado en la dirección especificada por shmaddr del espacio de direcciones del proceso que llama. El segmento a desadjuntar debe estar actualmente adjunto con shmaddr igual al valor devuelto por la llamada a shmat() que lo adjuntó.

Tras una llamada exitosa a shmdt(), el sistema actualiza los miembros de la estructura shmid_ds asociada al segmento de memoria compartida de la siguiente manera:

•
shm_dtime se establece a la hora actual.
•
shm_lpid se establece al ID de proceso del proceso que llama.
•
shm_nattch se decrementa en uno. Si se vuelve 0 y el segmento está marcado para eliminación, el segmento se elimina.

VALOR DE RETORNO

En caso de éxito, shmat() devuelve la dirección del segmento de memoria compartida adjunto; en caso de error, se devuelve (void *) -1, y errno se establece para indicar el error.

En caso de éxito, shmdt() devuelve 0; en caso de error, se devuelve -1, y errno se establece para indicar el error.

ERRORES

shmat() puede fallar con uno de los siguientes errores:

EACCES
El proceso que llama no tiene los permisos requeridos para el tipo de adjunción solicitado, y no tiene la capacidad CAP_IPC_OWNER en el espacio de nombres de usuario que rige su espacio de nombres IPC.
EIDRM
shmid apunta a un identificador eliminado.
EINVAL
Valor de shmid inválido, dirección de adjunción no alineada (es decir, no alineada en páginas y SHM_RND no se especificó) o valor de shmaddr inválido, o no se puede adjuntar el segmento en shmaddr, o se especificó SHM_REMAP y shmaddr era NULL.
ENOMEM
No se pudo asignar memoria para el descriptor o para las tablas de páginas.

shmdt() puede fallar con uno de los siguientes errores:

EINVAL
No hay ningún segmento de memoria compartida adjunto en shmaddr; o, shmaddr no está alineado en un límite de página.

ESTÁNDARES

POSIX.1-2008.

HISTORIA

POSIX.1-2001, SVr4.

En SVID 3 (o quizás anterior), el tipo del argumento shmaddr se cambió de char * a const void *, y el tipo devuelto por shmat() de char * a void *.

POSIX.1-2024 cambió el código de error de (void *) -1 a SHM_FAILED.

NOTAS

Después de un fork(2), el hijo hereda los segmentos de memoria compartida adjuntos.

Después de un execve(2), todos los segmentos de memoria compartida adjuntos se desadjuntan del proceso.

Al salir con _exit(2), todos los segmentos de memoria compartida adjuntos se desadjuntan del proceso.

Usar shmat() con shmaddr igual a NULL es la forma preferida y portable de adjuntar un segmento de memoria compartida. Tenga en cuenta que el segmento de memoria compartida adjuntado de esta manera puede adjuntarse en direcciones diferentes en procesos diferentes. Por lo tanto, cualquier puntero mantenido dentro de la memoria compartida debe hacerse relativo (típicamente a la dirección de inicio del segmento), en lugar de absoluto.

En Linux, es posible adjuntar un segmento de memoria compartida incluso si ya está marcado para su eliminación. Sin embargo, POSIX.1 no especifica este comportamiento y muchas otras implementaciones no lo soportan.

El siguiente parámetro del sistema afecta a shmat():

SHMLBA
Múltiplo del límite inferior del segmento de dirección. Al especificar explícitamente una dirección de adjunción en una llamada a shmat(), el llamante debe asegurarse de que la dirección sea un múltiplo de este valor. Esto es necesario en algunas arquitecturas, ya sea para garantizar un buen rendimiento de la caché de la CPU o para garantizar que las diferentes adjunciones del mismo segmento tengan vistas consistentes dentro de la caché de la CPU. SHMLBA es normalmente un múltiplo del tamaño de página del sistema. (En muchas arquitecturas de Linux, SHMLBA es el mismo que el tamaño de página del sistema).

La implementación no impone un límite intrínseco por proceso en el número de segmentos de memoria compartida (SHMSEG).

shmop(2) - Arch Linux man pages

NAME

shmop - System V shared memory operations

LIBRARY

All functions shown below are provided by the standard C library (libc).

SYNOPSIS

#include <sys/shm.h>

void *shmat(int shmid, const void *shmaddr, int shmflg);
int shmdt(const void *shmaddr);
int shmctl(int shmid, int cmd, struct shmid_ds *buf);
int shmget(key_t key, size_t size, int shmflg);

DESCRIPTION

System V shared memory is a mechanism that allows multiple processes to share a region of memory. The API for System V shared memory consists of four system calls:

shmget()
allocates a shared memory segment.
shmat()
attaches a shared memory segment to the calling process's address space.
shmdt()
detaches a shared memory segment from the calling process's address space.
shmctl()
performs various control operations on a shared memory segment.

The shmget() system call returns the identifier of a shared memory segment. This identifier is used in subsequent calls to shmat(), shmdt(), and shmctl().

The argument key is a key used to identify a shared memory segment. If key is IPC_PRIVATE, then a new shared memory segment is created, and its identifier is returned. If key is not IPC_PRIVATE, then the system searches for an existing shared memory segment that corresponds to key.

The argument size specifies the size of the shared memory segment in bytes. If key is IPC_PRIVATE, then a new shared memory segment of size size is created. If the shared memory segment already exists, then size must be equal to the size of the existing segment, or zero if you do not wish to check the size.

The argument shmflg is a bit mask that specifies the desired resource limits and permissions. It is the bitwise OR of zero or more of the following flags:

IPC_CREAT
Create a new shared memory segment if it does not exist. If this flag is not specified, and the shared memory segment does not exist, shmget() will fail.
IPC_EXCL
If both IPC_CREAT and IPC_EXCL are specified, then shmget() will fail if the shared memory segment already exists.
IPC_NOWAIT
If IPC_CREAT is specified, and the shared memory segment does not exist, then shmget() will return without waiting for the resource to become available.

In addition, the shmflg argument can specify the access permissions for the shared memory segment. These permissions are specified as a three-digit octal number, where each digit represents the permissions for the owner, the group, and others, respectively. The permissions are:

SHM_R
Read permission.
SHM_W
Write permission.

The shmat() system call attaches the shared memory segment identified by shmid to the calling process's address space. The shmaddr argument specifies the desired address at which to attach the shared memory segment. If shmaddr is NULL, then the kernel chooses an address at which to attach the shared memory segment. If shmaddr is not NULL, then the kernel attempts to attach the shared memory segment at the specified address. The shmflg argument specifies the flags that control the attachment. It can be SHM_RDONLY (attach for read-only access) or SHM_RND (round address down to the nearest page boundary).

The shmdt() system call detaches the shared memory segment at the address specified by shmaddr from the calling process's address space. The shmaddr argument must be the address returned by a previous call to shmat().

The shmctl() system call performs various control operations on the shared memory segment identified by shmid.

IPC_STAT
Copy the current state of the shared memory segment into the structure pointed to by buf.
IPC_SET
Set the values of certain members of the shmid_ds structure associated with the shared memory segment.
IPC_RMID
Mark the shared memory segment for removal. The segment will be destroyed when it is no longer attached to any process.

The shmid_ds structure contains the following members:

struct shmid_ds {
    struct ipc_perm shm_perm;    /* Ownership and permissions */
    size_t          shm_segsz;   /* Size of segment */
    time_t          shm_atime;   /* Last attach time */
    time_t          shm_dtime;   /* Last detach time */
    time_t          shm_ctime;   /* Last change time */
    pid_t           shm_lpid;    /* PID of last shmat() */
    pid_t           shm_cpid;    /* PID of creator */
    shmatt_t        shm_nattch;  /* Number of current attaches */
    ...
};

The ipc_perm structure contains the following members:

struct ipc_perm {
    key_t   key;       /* Key */
    uid_t   uid;       /* Real UID of owner */
    gid_t   gid;       /* Real GID of owner */
    uid_t   cuid;      /* Effective UID of owner */
    gid_t   cgid;      /* Effective GID of owner */
    mode_t  mode;      /* Permissions */
    ...
};

RETURN VALUE

On success, shmat() returns a pointer to the shared memory segment. On failure, it returns (void *) -1, and errno is set to indicate the error.

On success, shmdt() returns 0. On failure, it returns -1, and errno is set to indicate the error.

On success, shmctl() returns 0. On failure, it returns -1, and errno is set to indicate the error.

On success, shmget() returns the shared memory identifier. On failure, it returns -1, and errno is set to indicate the error.

ERRORS

Errors are set in the errno variable.

shmat():

EACCES
Operation permitted only for the superuser. (Or, the required permissions were not granted.
EADDRINUSE
The specified address is already in use.
EINVAL
Invalid shmid value, or shmaddr is not NULL and not a valid address. shmaddr is not aligned to a page boundary.
ENOMEM
Not enough core memory available.
ENOSPC
The specified address is not within the range [addr, addr + len).
SHM_SRXFLG
Could not attach the segment for the requested flags.

shmdt():

EINVAL
Invalid shmaddr value.

shmctl():

EACCES
Operation permitted only for the superuser.
EINVAL
Invalid shmid value, or invalid cmd value.
EPERM
Operation permitted only for the owner of the resource, when cmd is IPC_SET.

shmget():

EACCES
A shared memory segment exists, but the calling process does not have permission to access it.
EEXIST
A shared memory segment exists with the given key, but IPC_CREAT and IPC_EXCL were specified.
EINVAL
Invalid shmflg value, or size is negative. (Or, the shmid value is illegal.)
ENFILE
The system limit on the total number of open shared memory segments has been reached.
ENOENT
No shared memory segment exists with the given key, and IPC_CREAT was not specified.
ENOMEM
A new shared memory segment is to be created, but the system does not have enough memory available.
ENOSPC
A new shared memory segment is to be created, but the system limit on the number of shared memory segments per user ID has been reached.

STANDARDS

POSIX.1-2008.

HISTORY

These functions first appeared in Version 7 Unix.

NOTES

System V shared memory is generally discouraged in favor of POSIX shared memory (shm_open(2)). System V IPC objects are identified by keys, which are arbitrary integer values. POSIX shared memory objects are identified by names, which are path-like strings.

The shmget function with IPC_PRIVATE creates an unnamed shared memory segment. This segment can only be accessed by the creator and its children. It is intended for use with semaphores or other synchronization primitives.

The shmat function with SHM_RDONLY flag causes the shared memory segment to be attached read-only. Any attempt to write to a read-only segment will result in a SIGSEGV signal being sent to the process.

When a process terminates, all shared memory segments attached to it are detached automatically.

The shared memory segment is not cleared upon creation. If you need a cleared segment, you must explicitly clear it.

The kernel associates a System V semaphore set with each System V shared memory segment. This set contains a single semaphore. The semaphore can be used to synchronize access to the shared memory segment. The reader program below uses this mechanism to ensure that the writer program has finished writing to the shared memory segment before the reader program attempts to read from it.

The following shell session demonstrates the use of the programs.

In one terminal window, we run the "reader" program, which creates a System V shared memory segment and a System V semaphore set. The program prints out the IDs of the created objects, and then waits for the semaphore to change value.


$ ./svshm_string_read;
shmid = 1114194
semid = 15

In another terminal window, we run the "writer" program. The "writer" program takes three command-line arguments: the IDs of the shared memory segment and semaphore set created by the "reader", and a string. It attaches the existing shared memory segment, copies the string to the shared memory, and modifies the semaphore value.


$ ./svshm_string_write 1114194 15 'Hello, world';

Returning to the terminal where the "reader" is running, we see that the program has ceased waiting on the semaphore and has printed the string that was copied into the shared memory segment by the writer:


Hello, world

The following header file is included by the "reader" and "writer" programs:


/* svshm_string.h

*/
#ifndef SVSHM_STRING_H
#define SVSHM_STRING_H
#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/sem.h>
union semun {                   /* Used in calls to semctl() */
    int                 val;
    struct semid_ds     *buf;
    unsigned short      *array;
#if defined(__linux__)
    struct seminfo      *__buf;
#endif
};
#define MEM_SIZE 4096
#endif  // include guard

Program source: svshm_string_read.c

The "reader" program creates a shared memory segment and a semaphore set containing one semaphore. It then attaches the shared memory object into its address space and initializes the semaphore value to 1. Finally, the program waits for the semaphore value to become 0, and afterwards prints the string that has been copied into the shared memory segment by the "writer".


/* svshm_string_read.c
   Licensed under GNU General Public License v2 or later.
*/
#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/ipc.h>
#include <sys/sem.h>
#include <sys/shm.h>
#include "svshm_string.h"
int
main(void)
{
    int            semid, shmid;
    char           *addr;
    union semun    arg, dummy;
    struct sembuf  sop;
    /* Create shared memory and semaphore set containing one
       semaphore.  */
    shmid = shmget(IPC_PRIVATE, MEM_SIZE, IPC_CREAT | 0600);
    if (shmid == -1)
        err(EXIT_FAILURE, "shmget");
    semid = semget(IPC_PRIVATE, 1, IPC_CREAT | 0600);
    if (semid == -1)
        err(EXIT_FAILURE, "semget");
    /* Attach shared memory into our address space.  */
    addr = shmat(shmid, NULL, SHM_RDONLY);
    if (addr == (void *) -1)
        err(EXIT_FAILURE, "shmat");
    /* Initialize semaphore 0 in set with value 1.  */
    arg.val = 1;
    if (semctl(semid, 0, SETVAL, arg) == -1)
        err(EXIT_FAILURE, "semctl");
    printf("shmid = %d\n", shmid);
    printf("semid = %d\n", semid);
    /* Wait for semaphore value to become 0.  */
    sop.sem_num = 0;
    sop.sem_op = 0;
    sop.sem_flg = 0;
    if (semop(semid, &sop, 1) == -1)
        err(EXIT_FAILURE, "semop");
    /* Print the string from shared memory.  */
    printf("%s\n", addr);
    /* Remove shared memory and semaphore set.  */
    if (shmctl(shmid, IPC_RMID, NULL) == -1)
        err(EXIT_FAILURE, "shmctl");
    if (semctl(semid, 0, IPC_RMID, dummy) == -1)
        err(EXIT_FAILURE, "semctl");
    exit(EXIT_SUCCESS);
}

Program source: svshm_string_write.c

The writer program takes three command-line arguments: the IDs of the shared memory segment and semaphore set that have already been created by the "reader", and a string. It attaches the shared memory segment into its address space, and then decrements the semaphore value to 0 in order to inform the "reader" that it can now examine the contents of the shared memory.


/* svshm_string_write.c
   Licensed under GNU General Public License v2 or later.
*/
#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/sem.h>
#include <sys/shm.h>
#include "svshm_string.h"
int
main(int argc, char *argv[])
{
    int            semid, shmid;
    char           *addr;
    size_t         size;
    struct sembuf  sop;
    if (argc != 4) {
        fprintf(stderr, "Usage: %s shmid semid string\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    size = strlen(argv[3]) + 1;  /* +1 to include trailing '\0' */
    if (size > MEM_SIZE) {
        fprintf(stderr, "String is too big!\n");
        exit(EXIT_FAILURE);
    }
    /* Get object IDs from command-line.  */
    shmid = atoi(argv[1]);
    semid = atoi(argv[2]);
    /* Attach shared memory into our address space and copy string
       (including trailing null byte) into memory.  */
    addr = shmat(shmid, NULL, 0);
    if (addr == (void *) -1)
        err(EXIT_FAILURE, "shmat");
    memcpy(addr, argv[3], size);
    /* Decrement semaphore to 0.  */
    sop.sem_num = 0;
    sop.sem_op = -1;
    sop.sem_flg = 0;
    if (semop(semid, &sop, 1) == -1)
        err(EXIT_FAILURE, "semop");
    exit(EXIT_SUCCESS);
}
