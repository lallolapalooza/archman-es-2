NAME

as -- GNU Assembler

The GNU assembler, as, is a program that translates assembly language programs into machine code, producing binary files in a format that can be linked by the GNU linker, ld.

as accepts both traditional AT&T syntax and Intel syntax. The default syntax depends on the target system. To explicitly specify the syntax, use the --traditional-syntax option to select AT&T syntax, or the --no-traditional-syntax option to select Intel syntax.

The GNU assembler can be invoked in several ways. The most common way is: as [options] file ...

If file is omitted, or if it is -, the assembler reads from the standard input.

The assembler can also be invoked indirectly by the compiler. For example, if you compile with gcc -c foo.c, this will invoke the assembler as part of the compilation process.

The following options are recognized by as:

-ah
include high-level source
-al
include assembly
-ali
include assembly with ginsn
-am
include macro expansions
-an
omit forms processing
-as
include symbols
=file
set the name of the listing file

You may combine these options; for example, use -aln for assembly listing without forms processing. The =file option, if used, must be the last one. By itself, -a defaults to -ahls.

The GNU assembler also supports directives for conditional assembly. These directives allow you to include or exclude sections of code based on certain conditions.

The main conditional assembly directives are:

.if expression
Starts a conditional block. If the expression evaluates to a non-zero value, the code within the block is assembled. The block must be terminated by .endif.
.elseif expression
Checks a condition if the preceding .if or .elseif was false. If the expression evaluates to true, the code following is assembled.
.else
If the preceding .if or .elseif conditions were false, the code following .else is assembled.
.endif
Ends a conditional block started with .if.

These directives can be nested.

Las siguientes opciones están disponibles cuando as está configurado para un procesador Xtensa.

--text-section-literals | --no-text-section-literals
Controla el tratamiento de los pools de literales. El valor predeterminado es --no-text-section-literals, que coloca los literales en secciones separadas en el archivo de salida. Esto permite que el pool de literales se coloque en una RAM/ROM de datos. Con --text-section-literals, los literales se intercalan en la sección de texto para mantenerlos lo más cerca posible de sus referencias. Esto puede ser necesario para archivos de ensamblaje grandes, donde los literales estarían fuera del alcance de las instrucciones "L32R" en la sección de texto. Los literales se agrupan en pools siguiendo las directivas ".literal_position" o precediendo las instrucciones "ENTRY". Estas opciones solo afectan a los literales referenciados a través de instrucciones "L32R" relativas a PC; los literales para instrucciones "L32R" en modo absoluto se manejan por separado.
--auto-litpools | --no-auto-litpools
Controla el tratamiento de los pools de literales. El valor predeterminado es --no-auto-litpools, que en ausencia de --text-section-literals coloca los literales en secciones separadas en el archivo de salida. Esto permite que el pool de literales se coloque en una RAM/ROM de datos. Con --auto-litpools, los literales se intercalan en la sección de texto para mantenerlos lo más cerca posible de sus referencias, no se requieren directivas explícitas de ".literal_position". Esto puede ser necesario para funciones muy grandes, donde un único pool de literales al principio de la función puede no ser alcanzable por las instrucciones "L32R" al final. Estas opciones solo afectan a los literales referenciados a través de instrucciones "L32R" relativas a PC; los literales para instrucciones "L32R" en modo absoluto se manejan por separado. Cuando se utiliza junto con --text-section-literals, --auto-litpools tiene precedencia.
--absolute-literals | --no-absolute-literals
Indica al ensamblador si las instrucciones "L32R" utilizan direccionamiento absoluto o relativo a PC. Si el procesador incluye la opción de direccionamiento absoluto, el valor predeterminado es usar relocaciones "L32R" absolutas. De lo contrario, solo se pueden utilizar las reubicaciones "L32R" relativas a PC.
--target-align | --no-target-align
Habilita o deshabilita la alineación automática para reducir las penalizaciones de salto a costa de un aumento en el tamaño del código. Esta optimización está habilitada por defecto. Tenga en cuenta que el ensamblador siempre alineará instrucciones como "LOOP" que tienen requisitos de alineación fijos.
--longcalls | --no-longcalls
Habilita o deshabilita la transformación de instrucciones de llamada para permitir llamadas a través de un mayor rango de direcciones. Esta opción debe usarse cuando los destinos de llamada pueden estar fuera de rango. Puede degradar tanto el tamaño del código como el rendimiento, pero el enlazador generalmente puede optimizar la sobrecarga innecesaria cuando una llamada termina dentro del rango. El valor predeterminado es --no-longcalls.
--transform | --no-transform
Habilita o deshabilita todas las transformaciones del ensamblador de instrucciones Xtensa, incluyendo tanto la relajación como la optimización. El valor predeterminado es --transform; --no-transform solo debe usarse en los casos raros en que las instrucciones deben ser exactamente como se especifican en el código fuente ensamblado. Usar --no-transform causa que los operandos de instrucciones fuera de rango sean errores.
--rename-section nombreantiguo=nombrenuevo
Renombra la sección nombreantiguo a nombrenuevo. Esta opción puede ser utilizada varias veces para renombrar múltiples secciones.
--trampolines | --no-trampolines
Habilita o deshabilita la transformación de instrucciones de salto para permitir saltos a través de un mayor rango de direcciones. Esta opción debe usarse cuando los destinos de salto pueden estar fuera de rango. En ausencia de tales saltos, esta opción no afecta el tamaño del código ni el rendimiento. El valor predeterminado es --trampolines.
--abi-windowed | --abi-call0
Elige la etiqueta ABI escrita en la sección ".xtensa.info". La etiqueta ABI indica la ABI del código ensamblado. El enlazador emite una advertencia al intentar enlazar archivos objeto con etiquetas ABI inconsistentes. La ABI predeterminada es elegida por la configuración del núcleo Xtensa.

@chapter Características dependientes de Z80

Opciones de línea de comandos

-march=CPU[-EXT...][+EXT...]
Esta opción especifica el procesador de destino. El ensamblador emitirá un mensaje de error si se intenta ensamblar una instrucción que no se ejecutará en el procesador de destino. Los siguientes nombres de procesador son reconocidos: "z80", "z180", "ez80", "gbz80", "z80n", "r800". Además del conjunto de instrucciones básico, se puede indicar al ensamblador que acepte algunas extensiones de mnemónicas. Por ejemplo, "-march=z180+sli+infc" extiende z180 con instrucciones SLI e IN F,(C). Las siguientes extensiones son compatibles actualmente: "full" (todas las instrucciones conocidas), "adl" (modo CPU ADL por defecto, solo eZ80), "sli" (instrucción conocida como SLI, SLL o SL1), "xyhl" (instrucciones con mitades de registros índice: IXL, IXH, IYL, IYH), "xdcb" (instrucciones como RotOp (II+d),R y BitOp n,(II+d),R), "infc" (instrucción IN F,(C) o IN (C)), "outc0" (instrucción OUT (C),0). Tenga en cuenta que en lugar de extender un conjunto de instrucciones básico, las mnemónicas de extensión que comienzan con "-" revierten la funcionalidad respectiva: "-march=z80-full+xyhl" primero elimina todas las extensiones predeterminadas y solo agrega soporte para las mitades de los registros índice.

Si esta opción no se especifica, se asume "-march=z80+xyhl+infc".

-colonless
Acepta etiquetas sin dos puntos. Todos los símbolos al comienzo de la línea se tratan como etiquetas.
-sdcc
Acepta código de ensamblador producido por SDCC.
