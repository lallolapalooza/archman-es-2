DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) calculan una o más reducciones a través de matrices simétricas en múltiples PE virtuales. Una reducción realiza una operación binaria asociativa en un conjunto de valores. Para obtener una lista de otras rutinas de reducción de SHMEM, consulte intro_shmem(3).

Como con todas las rutinas colectivas de SHMEM, cada una de estas rutinas asume que solo los PE en el conjunto activo llaman a la rutina. Si un PE que no está en el conjunto activo llama a una rutina colectiva de SHMEM, el comportamiento resultante no está definido.

El argumento nreduce determina el número de reducciones separadas a realizar. La matriz de origen en todos los PE del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en la matriz de destino en todos los PE del conjunto activo. El conjunto activo se define por el triplete PE_start, logPE_stride, PE_size.

Las matrices de origen y destino pueden ser la misma matriz, pero no pueden ser matrices superpuestas.

Los argumentos son los siguientes:

objetivo
Una matriz simétrica de longitud nreduce elementos para recibir los resultados de las operaciones de reducción. El tipo de datos de objetivo varía con la versión de la rutina de reducción que se llama y el idioma utilizado. Al llamar desde C/C++, consulte la sección SINOPSIS para obtener información sobre el tipo de datos. Al llamar desde Fortran, los tipos de datos de objetivo son los siguientes:
shmem_comp4_prod_to_all: Complejo, con un tamaño de elemento igual a dos
Valores reales de 4 bytes.
shmem_comp8_prod_to_all: Complejo, con un tamaño de elemento igual a dos
Valores reales de 8 bytes.

shmem_int4_prod_to_all: Entero, con un tamaño de elemento de 4 bytes

shmem_int8_prod_to_all: Entero, con un tamaño de elemento de 8 bytes

shmem_real4_prod_to_all: Real, con un tamaño de elemento de 4 bytes

shmem_real8_prod_to_all: Real, con un tamaño de elemento de 8 bytes

shmem_real16_prod_to_all: Real, con un tamaño de elemento de 16 bytes

fuente
Una matriz simétrica, de longitud nreduce elementos, que contiene un elemento para cada operación de reducción separada. El argumento fuente debe tener el mismo tipo de datos que objetivo.
nreduce
El número de elementos en las matrices de destino y fuente. nreduce debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
PE_start
El número de PE virtual más bajo del conjunto activo de PE. PE_start debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
logPE_stride
El logaritmo (base 2) del paso entre los números de PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
PE_size
El número de PE en el conjunto activo. PE_size debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
pWrk
Una matriz de trabajo simétrica. El argumento pWrk debe tener el mismo tipo de datos que objetivo. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Una matriz de trabajo simétrica. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Si está utilizando Fortran, debe ser un valor entero predeterminado. Antes de que cualquiera de los PE del conjunto activo entre en la rutina de reducción, cada elemento de esta matriz debe inicializarse con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran).

Los valores de los argumentos nreduce, PE_start, logPE_stride y PE_size deben ser iguales en todos los PE del conjunto activo. Las mismas matrices de destino y fuente, y las mismas matrices de trabajo pWrk y pSync, deben pasarse a todos los PE del conjunto activo. Antes de que cualquier PE llame a una rutina de reducción, debe asegurarse de que se cumplen las siguientes condiciones (a menudo se necesita sincronización mediante una barrera u otro método para garantizar esto): Las matrices pWrk y pSync en todos los PE del conjunto activo ya no se están utilizando de una llamada anterior a una rutina colectiva de SHMEM. La matriz de destino en todos los PE del conjunto activo está lista para recibir los resultados de la reducción.

Al regresar de una rutina de reducción, lo siguiente es cierto para el PE local: La matriz de destino se actualiza. Los valores de la matriz pSync se restauran a sus valores originales.

DESCRIPTION

The shmem_complexf_prod_to_all (Fortran) and shmem_complexf_prod_to_all (C/C++) routines compute the product of elements from the array specified by source on the PEs in the specified symmetric multithreaded processing element (PE) group and places the result in the corresponding element of the array specified by target on all PEs in the group.

The arguments to the shmem_complexf_prod_to_all routines are as follows:

  • target In Fortran, this is a variable of type complex or an array of complex variables. In C/C++, this is a pointer to complex data type. This is the target array into which the reduction results are placed.
  • source In Fortran, this is a variable of type complex or an array of complex variables. In C/C++, this is a pointer to complex data type. This is the source array containing the data to be reduced.
  • nreduce This is the number of elements in the arrays specified by target and source.
  • PE_start This is the first PE in the range of PEs that will participate in this operation.
  • logPe_stride This is the log base 2 of the stride between PEs.
  • PE_size This is the number of PEs in the active set.
  • pSync This is an array of integers (Fortran) or long integers (C/C++) that must be allocated and initialized as described in intro_shmem(3).

The specific reduction routine requested indicates the type of reduction to be performed. The reduction is performed with respect to the complex product operator. The specific reduction routines are:

  • shmem_complexf_prod_to_all (Fortran and C/C++): Computes the complex product.

For Fortran, the target and source arrays must be declared as COMPLEX*8 (4-byte real and imaginary parts). For C/C++, the target and source must be declared as complex. The reduction is performed element by element across the arrays.

The reduction routines are collective operations. All PEs in the symmetric multithreaded processing element group specified by PE_start, logPe_stride, and PE_size must call these routines. The active set of PEs are those PEs in the range [PE_start, PE_start + (PE_size-1)*2logPe_stride].

The pSync argument is a synchronization array that is used to coordinate the reduction operation. It is assumed that this array is initialized to the value SHMEM_SYNC_VALUE (Fortran) or 0 (C/C++) on all PEs in the active set prior to the call. The size of this array must be at least SHMEM_REDUCE_SYNC_SIZE.

The reduction routines must be called with the same arguments (PE_start, logPe_stride, PE_size) by all PEs in the active set.

NOTES

The reduction routines are designed to be called efficiently. The synchronization array, pSync, is used only by the reduction routines. It is assumed that the pSync array is initialized only once, typically at the beginning of the program. The pSync array is initialized the first time it is used.

You must ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the product of the real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMP8_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

Example 2: Consider the following C/C++ call:

shmem_short_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_short_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_short_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_short_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
