shmem_int_xor_to_all(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

SHMEM_INT_XOR_TO_ALL(3) Open MPI SHMEM_INT_XOR_TO_ALL(3)

shmem_comp4_xor_to_all(3), shmem_int_xor_to_all(3), shmem_int4_xor_to_all(3), shmem_int8_xor_to_all(3), shmem_long_xor_to_all(3), shmem_longlong_xor_to_all(3), shmem_short_xor_to_all(3) - Realiza una operación XOR bit a bit en arrays simétricos sobre el conjunto activo de PEs.

SINOPSIS

C o C++:

#include <mpp/shmem.h>
void shmem_int_xor_to_all(int *target, const int *source,
  int nreduce, int PE_start, int logPE_stride, int PE_size,
  int *pWrk, long *pSync)
void shmem_long_xor_to_all(long *target, const long *source,
  int nreduce, int PE_start, int logPE_stride, int PE_size,
  long *pWrk, long *pSync)
void shmem_longlong_xor_to_all(long long *target,
  const long long *source, int nreduce, int PE_start, int logPE_stride,
  int PE_size, long long *pWrk, long *pSync)
void shmem_short_xor_to_all(short *target, const short *source,
  int nreduce, int PE_start, int logPE_stride, int PE_size,
  short *pWrk, long *pSync)

Fortran:

INCLUDE "mpp/shmem.fh"
INTEGER pSync(SHMEM_REDUCE_SYNC_SIZE)
INTEGER nreduce, PE_start, logPE_stride, PE_size
CALL SHMEM_COMP4_XOR_TO_ALL(target, source, nreduce,
& PE_start, logPE_stride, PE_size, pWrk, pSync)
CALL SHMEM_INT4_XOR_TO_ALL(target, source, nreduce,
& PE_start, logPE_stride, PE_size, pWrk, pSync)
CALL SHMEM_INT8_XOR_TO_ALL(target, source, nreduce,
& PE_start, logPE_stride, PE_size, pWrk, pSync)

DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) calculan una o más reducciones sobre arrays simétricos en múltiples PEs virtuales. Una reducción realiza una operación binaria asociativa sobre un conjunto de valores. Para una lista de otras rutinas de reducción SHMEM, consulte intro_shmem(3).

Como con todas las rutinas colectivas SHMEM, cada una de estas rutinas asume que solo los PEs del conjunto activo llaman a la rutina. Si un PE que no está en el conjunto activo llama a una rutina colectiva SHMEM, el comportamiento no está definido.

El argumento nreduce determina el número de reducciones independientes a realizar. El array fuente en todos los PEs del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en el array destino en todos los PEs del conjunto activo. El conjunto activo se define por el triplete PE_start, logPE_stride, PE_size.

Los arrays fuente y destino pueden ser el mismo array, pero no pueden ser arrays superpuestos.

Los argumentos son los siguientes:

objetivo
Un array simétrico de longitud nreduce elementos para recibir los resultados de las operaciones de reducción. El tipo de datos de objetivo varía con la versión de la rutina de reducción que se llama y el lenguaje utilizado. Al llamar desde C/C++, consulte la sección SINOPSIS para obtener información sobre el tipo de datos. Al llamar desde Fortran, los tipos de datos de destino son los siguientes:
shmem_comp8_xor_to_all:** Complejo, con un tamaño de elemento igual a dos valores reales de 8 bytes
shmem_comp4_xor_to_all:** Complejo, con un tamaño de elemento igual a dos valores reales de 4 bytes

shmem_int8_xor_to_all:** Entero, con un tamaño de elemento de 8 bytes

shmem_int4_xor_to_all:** Entero, con un tamaño de elemento de 4 bytes

shmem_real8_xor_to_all:** Real, con un tamaño de elemento de 8 bytes

shmem_real4_xor_to_all:** Real, con un tamaño de elemento de 4 bytes

fuente
Un array simétrico, de longitud nreduce elementos, que contiene un elemento para cada operación de reducción independiente. El argumento fuente debe tener el mismo tipo de datos que objetivo.
nreduce
El número de elementos en los arrays objetivo y fuente. nreduce debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
PE_start
El número PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
logPE_stride
El logaritmo (base 2) del paso entre números PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
pWrk
Un array de trabajo simétrico. El argumento pWrk debe tener el mismo tipo de datos que objetivo. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Un array de trabajo simétrico. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Si está utilizando Fortran, debe ser un valor entero predeterminado. Cada elemento de este array debe inicializarse con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran) antes de que cualquiera de los PEs del conjunto activo entre en la rutina de reducción.

Los valores de los argumentos nreduce, PE_start, logPE_stride y PE_size deben ser iguales en todos los PEs del conjunto activo. Los mismos arrays objetivo y fuente, y los mismos arrays de trabajo pWrk y pSync, deben pasarse a todos los PEs del conjunto activo.

Antes de que cualquier PE llame a una rutina de reducción, debe asegurarse de que existen las siguientes condiciones (la sincronización mediante una barrera u otro método a menudo es necesaria para garantizar esto): Los arrays pWrk y pSync en todos los PEs del conjunto activo ya no están en uso de una llamada anterior a una rutina colectiva SHMEM. El array objetivo en todos los PEs del conjunto activo está listo para aceptar los resultados de la reducción.

Al regresar de una rutina de reducción, lo siguiente es cierto para el PE local: El array objetivo está actualizado. Los valores en el array pSync se restauran a los valores originales.

NOTAS

Los términos colectivo, simétrico y alineado en caché se definen en intro_shmem(3). Todas las rutinas de reducción SHMEM restablecen los valores en pSync antes de que devuelvan, por lo que un buffer pSync particular solo necesita inicializarse la primera vez que se usa.

Debe asegurarse de que el array pSync no está siendo actualizado en ningún PE del conjunto activo mientras alguno de los PEs participa en el procesamiento de una rutina de reducción SHMEM. Tenga cuidado con las siguientes situaciones: Si el array pSync se inicializa en tiempo de ejecución, se necesita algún tipo de sincronización para asegurar que todos los PEs del conjunto de trabajo han inicializado pSync antes de que alguno de ellos entre en una rutina SHMEM llamada con el array de sincronización pSync. Un array pSync o pWrk puede reutilizarse en una llamada posterior a una rutina de reducción solo si ninguno de los PEs del conjunto activo está aún procesando una rutina de reducción anterior que utilizó los mismos arrays pSync o pWrk. En general, esto solo se puede garantizar realizando algún tipo de sincronización. Sin embargo, en el caso especial de las rutinas de reducción que se llaman con el mismo conjunto activo, puede asignar dos arrays pSync y pWrk y alternar entre ellos en llamadas sucesivas.

EJEMPLOS

Ejemplo 1: Este ejemplo de Fortran inicializa estáticamente el array pSync y calcula el XOR exclusivo de la variable FOO en todos los PEs pares.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOXOR, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOXOR, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_REAL8_XOR_TO_ALL(FOOXOR, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Resultado en PE ', MY_PE(), ' es ', FOOXOR
ENDIF

SYNOPSIS

shmem_int_xor_to_all(3)

DESCRIPTION

The shmem_int_xor_to_all routine performs a symmetric global XOR operation on the elements of an array. The array is distributed among the processes. Each process contributes one element from its local array to the global XOR sum. The result is placed in the target array.

int
shmem_int_xor_to_all(void *target, const void *source, size_t nlong, int PE_start, int logPE_stride, int PE_size, void *pWrk, void *pSync);

This routine is identical to shmem_long_xor_to_all, except for the type and size of the data elements. The data elements are of type int.

All arguments are unchanged. See shmem_long_xor_to_all(3) for details.

NOTES

The data types for the target and source arrays are assumed to be int.

The following macros are provided to simplify the invocation of these routines:

SHMEM_INT_XOR_TO_ALL(target, source, nlong, PE_start, logPE_stride, PE_size)

This macro invokes the function with the appropriate pWrk and pSync arguments.

EXAMPLES

The following code fragment illustrates the use of the SHMEM_INT_XOR_TO_ALL macro:

int srcbuf[3], dstbuf[3];
int *pSync;
int *pWrk;

/* Initialize arrays, pSync, pWrk etc. */
...

SHMEM_INT_XOR_TO_ALL(dstbuf, srcbuf, 3, 0, 0, 8);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_int_xor_to_all(&(dstbuf[0]), &(srcbuf[0]), 1, 0, 0, 8,
  pWrk1, pSync1);
shmem_int_xor_to_all(&(dstbuf[1]), &(srcbuf[1]), 1, 0, 0, 8,
  pWrk2, pSync2);
shmem_int_xor_to_all(&(dstbuf[2]), &(srcbuf[2]), 1, 0, 0, 8,
  pWrk1, pSync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
