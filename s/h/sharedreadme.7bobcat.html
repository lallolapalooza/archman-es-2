SharedREADME(7bobcat) README de memoria compartida de Bobcat SharedREADME(7bobcat)

NOMBRE

SharedREADME - Descripción de las clases de memoria compartida de Bobcat

DESCRIPCIÓN

Las siguientes clases de memoria compartida están disponibles:

o
SharedBlock(3bobcat)
La clase SharedBlock(3bobcat) define un pequeño objeto que consiste en un SharedMutex y un ID (de segmento compartido). Ofrece funcionalidad para establecer y recuperar el ID, y para bloquear y desbloquear el SharedMutex. Los objetos SharedBlock son utilizados por los objetos SharedSegment(3bobcat) para hacer un seguimiento de qué segmentos contienen realmente los datos de memoria compartida. Es una clase auxiliar de contabilidad.
o
SharedSegment(3bobcat)
La clase SharedSegment (cf. figura images/sharedsegment1.jpg) interactúa con la memoria compartida real. Su principal función miembro es el miembro estático create, que devuelve un puntero a un objeto SharedMemory recién asignado.
El miembro create recibe como parámetros de entrada el número de bloques, el tamaño de los segmentos asignados por SharedSegment, y el modo de acceso del segmento (como se utiliza en, por ejemplo, chmod(1)). Devuelve un puntero al SharedSegment asignado y su ID (establecido usando un puntero a un int, pasado como primer parámetro).
Aunque la clase SharedSegment define un array de un único objeto SharedBlock(3bobcat), de hecho contendrá d_nBlocks objetos SharedBlock. El miembro create primero asigna un bloque de memoria cruda del tamaño total requerido. A continuación, inicializa la primera parte de esta memoria cruda y compartida, utilizando el constructor SharedSegment y el placement new. A continuación, la cantidad restante de memoria cruda compartida se inicializa con d_nBlocks - 1 objetos SharedBlock, de nuevo utilizando placement new (cf. figura images/sharedsegment2.jpg).
o
SharedPos(3bobcat)
La clase SharedPos(3bobcat) monitoriza la información de posición en los segmentos de memoria compartida gestionados por objetos SharedSegment. SharedPos solo tiene un constructor por defecto, pero ofrece un miembro reset que recibe en el momento de la construcción un puntero a un objeto SharedSegment.
o
SharedMemory(3bobcat)
La clase SharedMemory(3bobcat) ofrece la interfaz estándar a la memoria compartida, definiendo miembros como read, get, write y put. Interactúa con un objeto SharedSegment y utiliza un objeto SharedPos para hacer un seguimiento de los offsets de SharedMemory.
Un objeto SharedMemory en sí reside en la memoria de trabajo de un programa, y no en el área de memoria compartida del ordenador. En cualquier momento, el objeto SharedMemory solo carga como máximo un bloque real del bloque de memoria compartida gestionado por SharedSegment. La posición actual en la memoria compartida gestionada por SharedSegment es monitorizada por el miembro SharedBlock d_pos de SharedMemory.
Después de las operaciones de lectura/escritura, el offset se actualiza en consecuencia. Solo hay un offset, que es utilizado por los objetos [IO]?SharedStream al solicitar o actualizar offsets. Un objeto SharedMemory ofrece salvaguardas contra el uso inapropiado. Por ejemplo, si aún no se ha asignado memoria, puede lanzar excepciones. Además, los offsets nunca pueden exceder el offset máximo posible de SharedMemory.
o
SharedMutex(3bobcat)
La clase SharedMutex implementa un mutex no recursivo que puede ser almacenado en memoria compartida. Simplemente ofrece miembros lock y unlock. Dentro de un hilo, lock nunca debe ser llamado repetidamente a menos que unlock se llame primero. El miembro unlock puede ser llamado repetidamente de forma segura; una vez que el mutex ha sido desbloqueado, las solicitudes repetidas para desbloquear el mutex simplemente se ignoran. Cuando un SharedMutex es destruido, llama a unlock. Utilice el miembro install de SharedMemory para definir un objeto SharedMutex en memoria compartida, y utilice ptr->~SharedMutex() (con SharedMutex *ptr apuntando al objeto SharedMutex) para destruirlo de nuevo.
o
SharedCondition(3bobcat)
La clase SharedCondition implementa una variable de condición y un mutex asociado, ambos creados en memoria compartida controlada por un objeto SharedMemory. Ofrece toda la funcionalidad de std::condition_variable. Un objeto SharedCondition en sí mismo está definido en la memoria de trabajo de un hilo, pero interactúa con un objeto `Condition’ que contiene una variable de condición y un mutex que están instalados en memoria compartida. El tamaño de este objeto `Condition’ se obtiene mediante el miembro estático SharedCondition::size. Los miembros de SharedCondition aseguran que el hilo tenga acceso al objeto `Condition’ y que el offset de la memoria compartida no haya cambiado al regresar de los miembros de SharedCondition.
o
SharedBuf(3bobcat)
La clase SharedBuf implementa una especialización de std::streambuf que interactúa con un objeto SharedMemory. Además de un constructor por defecto que es un stub vacío, la clase ofrece constructores que interactúan inmediatamente con un objeto SharedMemory, así como un miembro para asociar (o reasociar) un objeto SharedBuf con un objeto SharedMemory.
o
SharedStream, ISharedStream, OSharedStream(3bobcat)
Estas clases de flujo ofrecen facilidades de flujo que operan sobre memoria compartida mantenida por un objeto SharedMemory. La clase SharedStream utiliza el miembro seek de SharedMemory tanto para seekp como para seekg, y utiliza el miembro offset de SharedMemory tanto para tellp como para tellg. Todos los objetos de flujo compartido, incluido ISharedStream, ofrecen un miembro para inicializar un SharedCondition.
Un resumen de los segmentos de memoria compartida definidos actualmente se muestra con el comando ipcs -ma. Para eliminar un segmento de memoria compartida definido, se puede usar el comando ipcrm -m <id>, donde <id> es el ID del segmento de memoria compartida.

NAME

libbobcat-dev — C++ Base Classes and Templates

DESCRIPTION

The Bobcat library provides a set of base classes and templates for C++ development. It aims to offer a robust and efficient foundation for various programming tasks.

EXAMPLE

Here's a simple example of using Bobcat:

#include <iostream>
#include <string>
#include <bobcat/string.hpp>

int main() {
    // Using Bobcat's String class
    Bobcat::String message = "Hello, Bobcat!";
    std::cout << message.c_str() << std::endl;
    return 0;
}

FILES

/usr/include/bobcat/*
Header files for the Bobcat library.
/usr/lib/libbobcat.so*
Shared library files.
/usr/share/doc/libbobcat-dev/*
Documentation and examples.

SEE ALSO

The Bobcat library documentation can be found in /usr/share/doc/libbobcat-dev/. Specific class documentation may be available as separate manual pages or HTML files.

BUGS

Please report any bugs to the Bobcat project's issue tracker at https://fbb-git.gitlab.io/bobcat/report-bugs.

BOBCAT PROJECT FILES

The Bobcat project consists of various files including source code, documentation, build scripts, and test cases. These are typically organized within the project's repository.

Source Code:
Header files (.hpp) and implementation files (.cpp) for the library's components.
Documentation:
Manual pages, README files, and other descriptive documents.
Build System:
Build scripts (e.g., Makefiles, CMakeLists.txt) used to compile the library.
Tests:
Test suites to verify the correctness of the library.

These files collectively form the Bobcat project, enabling its development, distribution, and usage.

BOBCAT

Bobcat is an acronym for 'Brokken's Own Base Classes And Templates'.
