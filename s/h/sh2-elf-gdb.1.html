GDB(1) Herramientas de Desarrollo GNU GDB(1)

NOMBRE

gdb - El Depurador GNU

SINOPSIS

gdb [OPCIONES] [programa|programa ID_proceso|programa núcleo]

DESCRIPCIÓN

El propósito de un depurador como GDB es permitirle ver qué está sucediendo "dentro" de otro programa mientras se ejecuta, o qué estaba haciendo otro programa en el momento en que falló.

GDB puede hacer cuatro tipos principales de cosas (además de otras cosas en apoyo de estas) para ayudarle a detectar errores:

  • Iniciar su programa, especificando cualquier cosa que pueda afectar su comportamiento.
  • Hacer que su programa se detenga bajo condiciones especificadas.
  • Examinar lo que ha sucedido, cuando su programa se ha detenido.
  • Cambiar cosas en su programa, para que pueda experimentar corrigiendo los efectos de un error y continuar aprendiendo sobre otro.

Puede usar GDB para depurar programas escritos en C, C++, Fortran y Modula-2.

GDB se invoca con el comando de shell "gdb". Una vez iniciado, lee comandos del terminal hasta que le indica que salga con el comando GDB "quit" o "exit". Puede obtener ayuda en línea desde GDB mismo usando el comando "help".

Puede ejecutar "gdb" sin argumentos ni opciones; pero la forma más habitual de iniciar GDB es con uno o dos argumentos, especificando un programa ejecutable como argumento:

gdb programa

También puede iniciar con un programa ejecutable y un archivo núcleo especificados:

gdb programa núcleo

Alternativamente, puede especificar un ID de proceso como segundo argumento o usar la opción "-p", si desea depurar un proceso en ejecución:

gdb programa 1234
gdb -p 1234

adjuntaría GDB al proceso 1234. Con la opción -p puede omitir el nombre de archivo del programa.

Aquí hay algunos de los comandos GDB más frecuentemente necesarios:

break [archivo:][función|línea]
Establece un punto de interrupción en función o línea (en archivo).
run [lista_args]
Inicia su programa (con lista_args, si se especifica).
bt
Backtrace: muestra la pila del programa.
print expr
Muestra el valor de una expresión.
c
Continúa ejecutando su programa (después de detenerse, p. ej. en un punto de interrupción).
next
Ejecuta la siguiente línea del programa (después de detenerse); pasa por encima de las llamadas a funciones en la línea.
edit [archivo:]función
examina la línea del programa donde se detuvo actualmente.
list [archivo:]función
escribe el texto del programa en las proximidades de donde se detuvo actualmente.
step
Ejecuta la siguiente línea del programa (después de detenerse); entra en las llamadas a funciones en la línea.
help [nombre]
Muestra información sobre el comando GDB nombre, o información general sobre el uso de GDB.
quit
exit
Sale de GDB.

Para obtener detalles completos sobre GDB, consulte Using GDB: A Guide to the GNU Source-Level Debugger, de Richard M. Stallman y Roland H. Pesch. El mismo texto está disponible en línea como la entrada "gdb" en el programa "info".

OPCIONES

Cualquier argumento que no sean opciones especifica un archivo ejecutable y un archivo núcleo (o ID de proceso); es decir, el primer argumento encontrado sin un indicador de opción asociado es equivalente a una opción --se, y el segundo, si existe, es equivalente a una opción -c si es el nombre de un archivo. Muchas opciones tienen formas largas y abreviadas; ambas se muestran aquí. Las formas largas también se reconocen si las trunca, siempre que se incluya suficiente parte de la opción para que sea inequívoca.

Las formas abreviadas se muestran aquí con - y las formas largas se muestran con -- para reflejar cómo se muestran en --help. Sin embargo, GDB reconoce todas las siguientes convenciones para la mayoría de las opciones:

"--opcion=valor"
"--opcion valor"
"-opcion=valor"
"-opcion valor"
"--o=valor"
"--o valor"
"-o=valor"
"-o valor"

gdb(1) - Arch Linux Manual Pages

NAME

gdb -- GNU Project Debugger

SYNOPSIS

sh2-elf-gdb [-nx] [-q] [--se[=file]] [--nx] [--batch[-silent]] [--args prog [arglist]] [--pid=pid] [--tui] [--readnow] [--readnever] [--return-child-result] [--configuration] [--version] [--cd=directory] [--data-directory=directory] [-D] [--fullname] [-f] [-b baudrate] [-l timeout] [--tty=device] [file [args ...]]
sh2-elf-gdb -h | --help

DESCRIPTION

GDB, the GNU Project Debugger, allows you to see what is going on inside another program while it executes—or what another program was doing at the moment it crashed. You can examine files, data, memory, and function calls in the core file or when the program is running in the debugger. You can also modify program data and affect its future execution, for example by forcing a function to return a specified value.

GDB has two modes of operation:

  • Interactive: You type commands to GDB, and it performs them and prints results.
  • Batch: GDB reads commands from a file, performs them, and exits.

GDB can be used to debug programs written in C, C++, Ada, and Fortran. It can also be used for languages that don't directly support debugging but for which a source-level debugging interface is available.

You can use GDB to debug a running process or a core dump. To debug a running process, you need to attach GDB to the process using its Process ID (PID).

When GDB starts, it prints an introductory message and prompts you for a command. When you use GDB to run a program, it starts that program and runs it until it terminates or is interrupted.

OPTIONS

-nx
--nx
Do not read any init files. GDB normally reads init files like .gdbinit from the current directory, and from the user's home directory. This option prevents that.
-q
--quiet
Do not print the introductory and copyright messages in GDB's banner. This is useful for writing scripts that invoke GDB.
--se=file
--se
Read GDB commands from file. This option is useful for running GDB in batch mode.
--batch
Run GDB in batch mode. GDB reads commands from standard input and sends output to standard output. This is useful for automating debugging tasks, for example, to download and run a program on another computer; in order to make this more useful, the message

Program exited normally.

(which is ordinarily issued whenever a program running under GDB control terminates) is not issued when running in batch mode.

--batch-silent
Run in batch mode, just like --batch, but totally silent. All GDB output is suppressed (stderr is unaffected). This is much quieter than --silent and would be useless for an interactive session.

This is particularly useful when using targets that give Loading section messages, for example.

Note that targets that give their output via GDB, as opposed to writing directly to "stdout", will also be made silent.

--args prog [arglist]
Change interpretation of command line so that arguments following this option are passed as arguments to the inferior. As an example, take the following command: 
gdb ./a.out -q

It would start GDB with -q, not printing the introductory message. On the other hand, using:

gdb --args ./a.out -q

starts GDB with the introductory message, and passes the option to the inferior.

--pid=pid
Attach GDB to an already running program, with the PID pid.
--tui
Open the terminal user interface.
--readnow
Read all symbols from the given symfile on the first access.
--readnever
Do not read symbol files.
--return-child-result
GDB's exit code will be the same as the child's exit code.
--configuration
Print details about GDB configuration and then exit.
--version
Print version information and then exit.
--cd=directory
Run GDB using directory as its working directory, instead of the current directory.
--data-directory=directory
-D
Run GDB using directory as its data directory. The data directory is where GDB searches for its auxiliary files.
--fullname
-f
Emacs sets this option when it runs GDB as a subprocess. It tells GDB to output the full file name and line number in a standard, recognizable fashion each time a stack frame is displayed (which includes each time the program stops). This recognizable format looks like two \032 characters, followed by the file name, line number and character position separated by colons, and a newline. The Emacs-to-GDB interface program uses the two \032 characters as a signal to display the source code for the frame.
-b baudrate
Set the line speed (baud rate or bits per second) of any serial interface used by GDB for remote debugging.
-l timeout
Set timeout, in seconds, for remote debugging.
--tty=device
Run using device for your program's standard input and output.

SEE ALSO

The full documentation for GDB is maintained as a Texinfo manual. If the "info" and "gdb" programs and GDB's Texinfo documentation are properly installed at your site, the command

info gdb

should give you access to the complete manual.
