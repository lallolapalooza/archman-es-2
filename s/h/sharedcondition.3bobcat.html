NOMBRE

FBB::SharedCondition - Variable de condición de memoria compartida

SINOPSIS

#include <bobcat/sharedcondition>
Opción de enlazado: -lpthread, -lbobcat

DESCRIPCIÓN

Las variables de condición se utilizan para sincronizar hilos basándose en los valores de los datos. Las variables de condición permiten a los hilos esperar hasta que ocurra una determinada condición, después de lo cual los hilos continúan sus acciones. Por lo tanto, los hilos que esperan no tienen que consultar continuamente el estado de una variable (lo que requiere que los hilos obtengan acceso a la variable antes de poder inspeccionar su valor). Usando variables de condición, los hilos que esperan simplemente esperan hasta que se les notifica.

Los objetos SharedCondition se pueden usar en combinación con memoria compartida. Los objetos SharedCondition interactúan con objetos (llamados objetos de *Condición* en esta página de manual) que se definen en memoria compartida y contienen un *SharedMutex* y un objeto de condición compartido. Estos objetos de *Condición* pueden ser accedidos por hilos que se ejecutan en diferentes procesos. Estos diferentes procesos pueden ejecutar un único hilo *main* o pueden ser multi-hilo ellos mismos.

Las variables de condición se utilizan en situaciones como estas:

o
Existe un hilo que debe suspenderse hasta que se cumpla una condición determinada.
o
Este hilo bloquea un mutex (o espera hasta que se obtenga el bloqueo)
o
Mientras la condición no se haya cumplido, el hilo se suspende (es decir, espera), liberando automáticamente el bloqueo del mutex.
o
De alguna manera (ver más abajo) el hilo se reanuda, momento en el cual el hilo ha readquirido automáticamente el bloqueo.
o
Una vez que se cumple la condición, el bucle while termina y se libera el bloqueo del mutex.
o
Existe un segundo hilo, que influye en las variables que son elementos de la condición, y que puede notificar al hilo que espera, una vez que se cumpla la condición requerida.
o
Este segundo hilo bloquea el mismo mutex que usa el primer hilo.
o
El segundo hilo modifica las variables involucradas y, si se cumple la condición requerida, notifica al primer hilo.
o
El segundo hilo libera el bloqueo del mutex, permitiendo que el primer hilo obtenga el bloqueo del mutex.

Mientras el primer hilo está esperando, está suspendido. Puede reanudarse cuando recibe una notificación de otro hilo, pero también por razones espurias. Por lo tanto, el primer hilo debe verificar que la condición se haya cumplido después de reanudar sus acciones.

Como las variables de condición siempre se usan en combinación con un mutex, SharedMutex encapsula el manejo del mutex. El software que utiliza objetos SharedCondition no tiene que manejar el mutex por sí mismo.

Los objetos SharedCondition se utilizan para sincronizar acciones de diferentes procesos, utilizando la memoria compartida como su vehículo de sincronización/comunicación. La variable de condición real que utiliza un objeto SharedCondition se define en memoria compartida. Los propios objetos SharedCondition son objetos pequeños, que contienen la información necesaria para acceder a la variable de condición de memoria compartida real.

CONSTRUCTORES, DESTRUCTOR

o
SharedCondition():
El constructor predeterminado crea un stub vacío que aún no se puede usar (o se lanza una FBB::Exception). Dado que la clase SharedCondition admite operadores de asignación, los stubs vacíos se pueden configurar fácilmente (o reconfigurar) en cualquier momento después de su construcción.
o
~SharedCondition():
El destructor de la clase libera (si es aplicable) su bloqueo en el bloqueo del mutex de la variable de condición compartida. El destructor no realiza ninguna acción si su objeto es un stub vacío.

Están disponibles los constructores predeterminados, de copia y de movimiento, así como los operadores de asignación de copia y de movimiento.

FUNCIONES MIEMBRO

Al devolver de las funciones miembro de SharedCondition, el desplazamiento del objeto SharedMemory en el que se ha definido la variable de condición no ha cambiado. Internamente, se guarda el desplazamiento actual; se realiza la función solicitada; y se restaura el desplazamiento original. En consecuencia, las funciones miembro de SharedCondition se pueden utilizar sin tener en cuenta el desplazamiento actual de SharedMemory.

o
void lock() const:
Al regresar de este miembro, el proceso actual ha bloqueado el objeto SharedCondition. Tenga cuidado de no llamar a lock dos veces durante el mismo hilo de ejecución (consulte sharedmutex(3bobcat) para obtener detalles).
o
void notify() noexept:
Uno de los hilos que esperan en el objeto SharedCondition se despierta. El hilo que llama a notify debe liberar su bloqueo de mutex poco después de llamar a notify, permitiendo que el hilo notificado obtenga el bloqueo. Un fragmento de pseudocódigo prototípico que ilustra el uso de notify se ve así: 
    sharedCondition.lock();     // bloquea el mutex
    ...                         // opera sobre las variables de la condición
    if (conditionWasMet)        // listo para notificar
        sharedCondition.notify();
    sharedCondition.unlock();   // libera el bloqueo
Dado que la secuencia sharedCondition.lock ... sharedCondition.unlock en sí misma puede ejecutarse en diferentes secciones de flujo de control, el miembro unlock no puede ser llamado desde dentro de notify.
o
void notifyAll() noexept:
A diferencia del miembro notify simple, este miembro despierta a todos los hilos que esperan en el objeto SharedCondition. Sin embargo, después de que el hilo actual libere su bloqueo de mutex, solo uno de esos hilos señalizados obtendrá realmente el bloqueo. El pseudocódigo para usar notifyAll es idéntico al pseudocódigo para usar notify (es decir, llamar a notifyAll, por supuesto).
o
std::streamsize offset() const:
Se devuelve la ubicación de la variable de condición compartida (dentro del objeto SharedMemory). El objeto de condición compartido termina en offset() + SharedCondition::width(), ver más abajo.
o
void unlock() const:
Se libera el bloqueo del objeto (no sucede nada si se llama cuando el objeto actual no tiene el bloqueo del objeto).
o
void wait():
Antes de llamar a wait, el hilo actual debería haber obtenido un bloqueo en el objeto SharedCondition.
Al llamar a wait, el hilo en ejecución suspende sus actividades y espera hasta ser notificado. Una vez notificado, readquiere el bloqueo y continúa. Poco después, el proceso debería liberar nuevamente su bloqueo en el objeto SharedCondition. bloqueo. Un fragmento de pseudocódigo prototípico que ilustra cómo usar wait se ve así: 
    sharedCondition.lock();         // bloquea el mutex
    while (conditionWasNotYetMet)   // se requiere esperar
        sharedCondition.wait();
    ...                             // haz algo: tenemos el bloqueo
    sharedCondition.unlock();       // libera el bloqueo

std::cv_status wait_for(std::chrono::duration<Type, Unit> const &relTime):
Este miembro se implementó como una plantilla de miembro. Type define el tipo de la variable que contiene la cantidad de tiempo (generalmente int64_t), especificada en la unidad de tiempo Unit. Los tipos de duration predefinidos están disponibles en el espacio de nombres std::chrono, como std::chrono::seconds(4), que representa 4 segundos, o std::chrono::milliseconds(30), que representa 30 milisegundos.
El hilo en ejecución debe haber obtenido un bloqueo en SharedCondition antes de llamar a este miembro, y debe liberar el bloqueo después de que este miembro haya retornado.
Este miembro actúa como wait, devolviendo std::cv_status::no_timeout si se recibió una notificación antes de que pasara relTime. De lo contrario, se devuelve std::cv_status::timeout.
Un ejemplo prototípico de pseudocódigo que ilustra cómo usar wait_for es el siguiente: 
    sharedCondition.lock();         // bloquear el mutex
    while (conditionWasNotYetMet)   // se requiere espera
    {
        while (sharedCondition.wait_for(someTime)
               == std::cv_status::timeout)
            handle_timeout
        do_something
    }
    sharedCondition.unlock();       // liberar el bloqueo
Al retornar de wait_for, el hilo actual ha obtenido el bloqueo de la condición compartida, pero quizás debido a un tiempo de espera: esto se puede verificar inspeccionando el valor de retorno de wait_for, y se puede seleccionar una acción apropiada.

SharedCondition &attach(SharedMemory &shmem, std::ios::off_type offset = 0, std::ios::seekdir origin = std::ios::beg):
Se devuelve el objeto SharedCondition que interactúa con la variable de condición compartida ubicada en offset (relativo a origin) en shmem.

o

Se inicializa una variable de condición compartida en el desplazamiento actual del objeto SharedMemory al que se refiere shmem, o en el primer desplazamiento del siguiente segmento de datos compartidos físico.

Se lanza una FBB::Exception si no hay suficiente memoria disponible en el objeto SharedMemory para definir una variable de condición compartida.

Devuelve el tamaño en bytes de las variables de condición compartidas almacenadas en objetos SharedMemory.

EJEMPLO

#include <iostream>
#include <bobcat/sharedcondition>
#include <bobcat/sharedmemory>
using namespace std;
using namespace FBB;
int main(int argc, char **argv)
try
{
    if (argc == 1)
    {
        cout <<
            "Argumento:\n"
            "   c: crear un segmento de memoria compartida + SharedCondition "
                                                    ", mostrar ID\n"
            "   k <id>: eliminar segmento de memoria compartida <id>\n"
            "   m <id>: mostrar un mensaje cada 5 segundos, de lo contrario esperar hasta\n"
            "           ser notificado en el segmento <id>\n"
            "   n <id>: notificar el SharedCondition en el segmento ID <id>\n"
        ;
        return 0;
    }
    switch (argv[1][0])
    {
        case ’c’:
        {
            SharedMemory shmem(1, SharedMemory::kB);
            SharedCondition cond = SharedCondition::create(shmem);
            void *ptr = shmem.ptr();
            cout << "ID = " << shmem.id() << ", SharedCondition en " <<
                    cond.offset() << endl;
            break;
        }
        case ’k’:
        {
            SharedMemory shmem(stoll(argv[2]));
            shmem.kill();
            break;
        }
        case ’m’:
        {
            SharedMemory shmem(stoll(argv[2]));
            SharedCondition cond = SharedCondition::attach(shmem);
            cond.lock();
            cout << "Obtenido el bloqueo. Esperando notificación\n";
            while (true)
            {
                switch (cond.wait_for(chrono::seconds(5)))
                {
                    case cv_status::timeout:
                        cout << "Esperado 5 segundos\n\n";
                    break;
                    case cv_status::no_timeout:
                        cond.unlock();
                        cout << "Notificación recibida. Desbloqueado.\n";
                    return 0;
                }
            }
        }
        case ’w’:
        {
            SharedMemory shmem(stoll(argv[2]));
            SharedCondition cond = SharedCondition::attach(shmem);
            cond.lock();
            cout << "Obtenido el bloqueo. Esperando notificación\n";
            cond.wait();
            cout << "Notificación recibida. Desbloqueando.\n";
            cond.unlock();
            break;
        }
        case ’n’:
        {
            SharedMemory shmem(stoll(argv[2]));
            SharedCondition cond = SharedCondition::attach(shmem);
            cout << "Notificando al otro después de Enter ";
            cin.ignore(1000, ’\n’);
            cond.lock();
            cout << "Obtenido el bloqueo. Notificando al otro\n";
            cond.notify();
            cout << "Enviada la notificación. Desbloqueando.\n";
            cond.unlock();
            break;
        }
    }
}
catch (exception const &exc)
{
    cout << "Excepción: " << exc.what() << endl;
}

sharedcondition(3bobcat)

NAME

sharedcondition — a condition variable that can be shared between processes

SYNOPSIS

#include <bobcat/sharedcondition>

namespace bobcat {

class SharedCondition
{
    // ...
};

} // namespace bobcat

DESCRIPTION

SharedCondition is a condition variable that can be used to coordinate multiple processes. It is intended to be used with SharedMutex to protect shared data. A thread can wait on a SharedCondition until signaled by another thread. The condition variable is initialized with a shared mutex.

To use a SharedCondition, you first need to create a shared memory region and place a SharedMutex and a SharedCondition in it. Then, multiple processes can map this shared memory region and use the SharedMutex and SharedCondition to coordinate their access to shared data.

The SharedCondition class provides the following member functions:

wait(SharedMutex &mutex)
Waits for the condition to be signaled. This function must be called while the calling thread holds the lock on the specified SharedMutex. The mutex will be unlocked before waiting and re-locked before returning.
timed_wait(SharedMutex &mutex, const timespec &ts)
Waits for the condition to be signaled or until the specified time has elapsed. This function also requires the calling thread to hold the lock on the SharedMutex.
signal()
Signals one waiting thread that the condition has been met. If no threads are waiting, this function has no effect.
broadcast()
Signals all waiting threads that the condition has been met. If no threads are waiting, this function has no effect.

NAMESPACE

All SharedCondition members are defined within the bobcat namespace.

INHERITS FROM

SharedCondition does not inherit from any class.

CONSTRUCTORS, DESTRUCTOR

The SharedCondition class has a default constructor and a destructor. These are used to initialize and clean up the condition variable.

MEMBER FUNCTIONS

See DESCRIPTION for a description of the member functions.

STATIC MEMBER FUNCTIONS

None.

EXAMPLE

Here is a simple example demonstrating the usage of SharedCondition with SharedMutex:

#include <iostream>
#include <thread>
#include <bobcat/sharedmutex>
#include <bobcat/sharedcondition>
#include <bobcat/sharedmemory>

using namespace bobcat;

// Shared data structure
struct SharedData {
    SharedMutex mutex;
    SharedCondition condition;
    int value = 0;
    bool ready = false;
};

void producer(SharedData *data)
{
    // Lock the mutex
    SharedMutex::Lock lock(data->mutex);

    // Produce data
    data->value = 42;
    data->ready = true;
    std::cout << "Producer: Data produced." << std::endl;

    // Signal the condition variable
    data->condition.signal();
}

void consumer(SharedData *data)
{
    // Lock the mutex
    SharedMutex::Lock lock(data->mutex);

    // Wait for the condition to be signaled
    while (!data->ready) {
        data->condition.wait(data->mutex);
    }

    // Consume data
    std::cout << "Consumer: Data received: " << data->value << std::endl;
}

int main()
{
    // Create shared memory
    SharedMemory shm(sizeof(SharedData));
    SharedData *data = static_cast<SharedData*>(shm.get());

    // Initialize shared data (important for first process)
    new (&(data->mutex)) SharedMutex();
    new (&(data->condition)) SharedCondition();
    data->value = 0;
    data->ready = false;

    // Create producer and consumer threads
    std::thread prod_thread(producer, data);
    std::thread cons_thread(consumer, data);

    // Join threads
    prod_thread.join();
    cons_thread.join();

    // Destroy shared objects (optional, but good practice)
    data->condition.~SharedCondition();
    data->mutex.~SharedMutex();

    return 0;
}
