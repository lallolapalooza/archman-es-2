NOMBRE

shairport-sync - Reproductor de Audio AirPlay y AirPlay 2

SINOPSIS

shairport-sync [-djvw] [-a nombre-servicio | --nombre=nombre-servicio] [-B comando | --al-iniciar=comando] [-c archivo-configuracion | --archivo-configuracion=archivo-configuracion] [-d | --demonio] [-E comando | --al-detener=comando] [-g | --obtener-arte-album] [-j | --soloDemonioSinArchivoPID] [--nivel-salida-log] [--log-a-syslog] [-L latencia | --latencia=latencia] [-m backend | --mdns=backend] [-M | --habilitar-metadatos] [-o backend | --salida=backend] [-p puerto | --puerto=puerto] [--contrasena=secreto] [-r umbral | --resincronizar=umbral] [--estadisticas] [-S modo | --relleno=modo] [-t tiempo-espera | --tiempo-espera=tiempo-espera] [--tolerancia=frames] [-v | --verboso] [-w | --esperar-comando] [-- opciones-backend-audio]

shairport-sync -X | --mostrar-configuracion

shairport-sync -h

shairport-sync -k

shairport-sync -V

DESCRIPCIÓN

Shairport Sync reproduce audio AirPlay. Puede ser compilado para transmitir desde AirPlay "clásico" (también conocido como "AirPlay 1") o desde dispositivos AirPlay 2.

El soporte para AirPlay 2 es limitado, y AirPlay 2 desde iTunes para Windows no está soportado. Para la operación de AirPlay 2, un programa complementario llamado nqptp debe ser instalado.

Por favor, consulte https://github.com/mikebrady/shairport-sync para detalles.

El nombre del ejecutable de Shairport Sync es shairport-sync.

AJUSTES DEL ARCHIVO DE CONFIGURACIÓN

Debería usar el archivo de configuración para configurar Shairport Sync porque -- aparte de unos pocos comandos de propósito especial -- tiene un conjunto de opciones mucho más rico de lo que está disponible en la línea de comandos. Este archivo es usualmente shairport-sync.conf y se encuentra normalmente en el Directorio de Configuración del Sistema, que es normalmente el directorio /etc en Linux o el directorio /usr/local/etc en los sistemas Unix BSD. Puede que necesite tener privilegios de root para modificarlo.

(Nota: Shairport Sync puede haber sido compilado para usar un directorio de configuración diferente. Puede determinar cuál ejecutando el comando $ shairport-sync -V. El último elemento en la cadena de salida es el valor de sysconfdir, es decir, el Directorio de Configuración del Sistema.)

Dentro del archivo de configuración, los ajustes están organizados en grupos, por ejemplo, hay un grupo general de ajustes estándar, y hay un grupo alsa con ajustes que pertenecen al backend ALSA. Aquí hay un ejemplo de un archivo de configuración típico:

general = {

name = "Boombox de Mike";

};

alsa = {

output_device = "hw:0";

mixer_control_name = "PCM";

};

Los usuarios generalmente solo necesitan establecer (1) el nombre del servicio y (2) el dispositivo de salida. Si se omite el ajuste name, el nombre del servicio se deriva del nombre de host del sistema. Por defecto, se elegirá el backend ALSA si está incluido en la compilación. Si el dispositivo de salida (alsa) tiene un mezclador que se puede usar para controlar el volumen, entonces (3) se debe especificar el nombre del mezclador. Es importante hacerlo si el mezclador existe. De lo contrario, la salida máxima del dispositivo de salida será la que sea que tenga el ajuste del mezclador, lo cual será cuestión de azar y podría ser muy bajo o incluso silencioso.

Un archivo de configuración de ejemplo con todos los ajustes posibles, pero con todos ellos comentados, se instala en shairport-sync.conf.sample, dentro del Directorio de Configuración del Sistema -- /etc en Linux, /usr/local/etc en sistemas Unix BSD.

El archivo de configuración de ejemplo incluye documentación exhaustiva de los ajustes, y también está disponible en https://github.com/mikebrady/shairport-sync/blob/master/scripts/shairport-sync.conf. Por favor, consulte este para obtener la información más actualizada sobre los ajustes del archivo de configuración.

OPCIONES

Hay dos tipos de opciones de línea de comandos para shairport-sync: **opciones del programa** regulares y **opciones del backend de audio**. Las opciones del programa se enumeran siempre primero, seguidas de cualquier opción del backend de audio, precedidas por un símbolo --.

Consulte la sección EJEMPLOS para ver ejemplos de uso.

OPCIONES DEL PROGRAMA

Las opciones del programa son utilizadas por shairport-sync mismo.

-a nombre-servicio | --nombre=nombre-servicio
Use este nombre-servicio para identificar este reproductor en iTunes, etc.

Se permiten las siguientes sustituciones: %h para el nombre de host del ordenador, %H para el nombre de host del ordenador con la primera letra capitalizada (solo ASCII), %v para el número de versión de shairport-sync, por ejemplo "3.0.1" y %V para la cadena de versión de shairport-sync, por ejemplo "3.0.1-OpenSSL-Avahi-ALSA-soxr-metadata-sysconfdir:/etc".

El valor predeterminado es "%H", que se reemplaza por el nombre de host con la primera letra capitalizada.

-B programa | --al-iniciar=programa
Ejecute programa cuando la reproducción esté a punto de comenzar. Especifique la ruta completa al programa, por ejemplo, /usr/bin/logger. Se pueden usar scripts ejecutables, pero deben tener el shebang apropiado (#!/bin/sh) en la cabecera.

Si desea que shairport-sync espere hasta que el comando se complete antes de comenzar a reproducir, seleccione también la opción -w.

-c nombre-archivo | --archivo-configuracion=nombre-archivo
Lea los ajustes de configuración desde nombre-archivo. El valor por defecto es leerlos desde shairport-sync.conf en el Directorio de Configuración del Sistema -- /etc en Linux, /usr/local/etc en sistemas Unix BSD. Para obtener información sobre los ajustes de configuración, consulte la sección "Ajustes del Archivo de Configuración" arriba.
-d | --demonio
Instruya a shairport-sync para que se convierta en un demonio. Escribirá su ID de Proceso (PID) en un archivo, usualmente en /var/run/shairport-sync/shairport-sync.pid, que es utilizado por las opciones -k, -D y -R para localizar el demonio en un momento posterior. Vea también la opción -j. Solo disponible si shairport-sync ha sido compilado con soporte para libdaemon.
-E programa | --al-detener=programa
Ejecute programa cuando la reproducción haya terminado. Especifique la ruta completa al programa, por ejemplo, /usr/bin/logger. Se pueden usar scripts ejecutables, pero deben tener el shebang apropiado (#!/bin/sh) en la cabecera.

Si desea que shairport-sync espere hasta que el comando se complete antes de continuar, seleccione también la opción -w.

-g | --obtener-arte-album
Esta opción requiere que la opción -M | --habilitar-metadatos esté configurada, y permite a shairport-sync solicitar la carátula del álbum de la fuente y procesarla como metadatos.
-h | --ayuda
Imprima un breve mensaje de ayuda y salga.
-j | soloDemonioSinArchivoPID
Instruya a shairport-sync para que se convierta en un demonio. A diferencia de la opción -d, no escribirá un ID de Proceso (PID) en un archivo -- simplemente se (de ahí la "j" de "just") convertirá en un demonio. Solo disponible si shairport-sync ha sido compilado con libdaemon

DESCRIPTION

shairport-sync is an AirPlay audio receiver. It allows you to stream audio from an AirPlay client (such as an iOS device or iTunes) to your Raspberry Pi or other Linux-based system.

CONFIGURATION FILE SETTINGS

The configuration file for shairport-sync is typically located at /etc/shairport-sync.conf. The file is written in JSON format and allows you to configure various aspects of the receiver.

Here is a breakdown of the common settings:

enabled
Boolean. If true, the service is enabled. Defaults to true.
run_dir
String. Directory for runtime files. Defaults to /run/shairport.
mdns
Object. Settings related to mDNS discovery.
mdns.bonjour
Boolean. Enable Bonjour compatibility. Defaults to true.
mdns.zeroconf
Boolean. Enable Zeroconf compatibility. Defaults to true.
mdns.multicast_addr
String. Multicast address for mDNS. Defaults to 224.0.0.251.
mdns.interface
String. Network interface to use for mDNS. Defaults to auto.
metadata
Object. Settings related to metadata handling.
metadata.enabled
Boolean. Enable metadata. Defaults to true.
metadata.database
String. Path to the metadata database file. Defaults to /var/lib/shairport-sync/db.
metadata.verbosity
Integer. Verbosity level for metadata logging. Defaults to 0.
player
Object. Settings related to the audio player.
player.output_backend
String. The audio output backend to use (e.g., alsa, pipewire, pulseaudio, jack, oss, null). Defaults to auto.
player.device
String. The audio device to use. Format depends on the backend.
player.sample_rate
Integer. The desired sample rate in Hz. Defaults to 44100.
player.buffer_duration
Integer. The desired buffer duration in microseconds. Defaults to 200000.
player.latency
Integer. The desired latency in microseconds. Defaults to 50000.
player.session_timeout
Integer. Timeout for AirPlay sessions in seconds. Defaults to 20.
dns_sd
Object. Settings related to DNS-SD service discovery.
dns_sd.name
String. The name advertised for the AirPlay service. Defaults to the hostname.
dns_sd.type
String. The service type advertised. Defaults to _raop._tcp.local..
dns_sd.port
Integer. The port to advertise for the service. Defaults to 5000.
log
Object. Settings related to logging.
log.syslog
Boolean. Log to syslog. Defaults to true.
log.stdout
Boolean. Log to standard output. Defaults to false.
log.stderr
Boolean. Log to standard error. Defaults to true.
log.level
String. Logging level (e.g., debug, info, warn, error). Defaults to info.
password
String. Optional password for AirPlay access.
rsa_key
String. Path to the RSA private key file for encrypted AirPlay sessions.
airplay2
Boolean. Enable AirPlay 2 support. Defaults to true.
srtp
Boolean. Enable SRTP for encrypted audio streams. Defaults to true.
allow_powermanagement
Boolean. Allow the system to enter power management states. Defaults to false.
bind_addr
String. The network address to bind to. Defaults to 0.0.0.0.
port
Integer. The port to listen on for AirPlay connections. Defaults to 5000.

AUDIO BACKEND OPTIONS

The available audio backends and their specific options may vary depending on your system's configuration and how shairport-sync was compiled.

alsa
Uses the ALSA audio system. The device option typically takes the form hw:CARD=Device,DEV=0 or a name like plughw:CARD=Device,DEV=0.
pipewire
Uses PipeWire for audio output. The device option might be a node name or ID.
pulseaudio
Uses PulseAudio for audio output. The device option typically specifies a sink name, e.g., alsa_output.pci-0000_00_1b.0.analog-stereo.
jack
Uses the JACK Audio Connection Kit. The device option might specify the JACK client name.
oss
Uses the OSS (Open Sound System) audio API. The device option might be /dev/dsp.
null
Discards audio output. Useful for testing or silent operation.
auto
Attempts to automatically detect and use the best available audio backend.

Consult the shairport-sync documentation or use the --help option for backend-specific details.

EXAMPLES

Run shairport-sync as a daemon with default settings:

sudo shairport-sync -d

Run shairport-sync using a custom configuration file:

sudo shairport-sync -c /path/to/my/shairport.conf

Run shairport-sync and log verbosely to the console:

shairport-sync -i -v --log-stdout --log-stderr

Run shairport-sync with PulseAudio output to a specific sink:

sudo shairport-sync --output-backend pulseaudio --device alsa_output.pci-0000_00_1f.3.analog-stereo

Run shairport-sync with a password and AirPlay 2 disabled:

sudo shairport-sync --password mysecretpassword --no-airplay2

COMMENTS

shairport-sync utilizes mDNS (Multicast DNS) for service discovery. Ensure that mDNS is enabled and working correctly on your network for clients to find the AirPlay receiver.

For encrypted audio streams (SRTP), you may need to generate or provide an RSA key pair using the --rsa-key option or the corresponding configuration setting.

The auto setting for output_backend is convenient but may not always select the desired audio device. Explicitly specifying the backend and device is often more reliable.

When running as a daemon (-d), shairport-sync typically logs to syslog by default. Use the logging options (--log-stdout, --log-stderr) to redirect logs to the console if needed.
