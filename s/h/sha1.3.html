NAME

sha1 — compute the SHA-1 message digest

LIBRARY

Message Digest API (libmd, -lmd)

SYNOPSIS

#include <sys/types.h>
#include <stdio.h>
#include <stdlib.h>
#include <sha1.h>

unsigned char *
SHA1_Data(const unsigned char *data, unsigned int len);

unsigned char *
SHA1_File(const char *filename);

unsigned char *
SHA1_FileChunk(const char *filename, off_t offset,
    off_t length);

void
SHA1End(SHA1_CTX *ctx, unsigned char *hash);

int
SHA1Init(SHA1_CTX *ctx);

void
SHA1Update(SHA1_CTX *ctx, const unsigned char *data,
    unsigned int len);

DESCRIPTION

The SHA-1 message digest algorithm, specified in FIPS PUB 180-1, produces a 160-bit message digest. This digest can be used to detect data corruption and to verify data integrity.

The SHA-1 algorithm is a public-domain cryptographic hash function developed by the NSA. It is the successor to the SHA-0 algorithm.

The functions SHA1Init(), SHA1Update() and SHA1End() compute the SHA-1 message digest for an arbitrary length message. The SHA1Init() function initializes a cryptographic context SHA1_CTX. The SHA1Update() function can be called one or more times between calls to SHA1Init() and SHA1End() to update the context with message content. The SHA1End() function computes the message digest and stores it in the hash argument, which must point to an area large enough to hold 20 bytes. The ctx must be re-initialized before it can be used again.

The SHA1_Data() function computes the SHA-1 message digest for the data pointed to by data which is len bytes long. It returns a pointer to a statically allocated buffer which contains the digest. The buffer is overwritten by subsequent calls to SHA1_Data() or SHA1_File(). The memory for this buffer is allocated by the system and should not be freed by the caller.

The SHA1_File() function computes the SHA-1 message digest for the contents of the file named by filename. It returns a pointer to a statically allocated buffer which contains the digest. The buffer is overwritten by subsequent calls to SHA1_Data() or SHA1_File(). The memory for this buffer is allocated by the system and should not be freed by the caller.

The SHA1_FileChunk() function computes the SHA-1 message digest for a portion of the file named by filename. The portion starts at offset bytes into the file and has a length of length bytes. If length is zero, the rest of the file starting from offset is used. It returns a pointer to a statically allocated buffer which contains the digest. The buffer is overwritten by subsequent calls to SHA1_Data(), SHA1_File() or SHA1_FileChunk(). The memory for this buffer is allocated by the system and should not be freed by the caller.

The digest is returned as an array of 20 unsigned char elements.

EXAMPLES

Compute the SHA-1 digest for a string:

    unsigned char *digest;
    digest = SHA1_Data((const unsigned char *)"hello world", 11);
    // Use digest...

Compute the SHA-1 digest for a file:

    unsigned char *digest;
    digest = SHA1_File("/etc/motd");
    // Use digest...

Compute the SHA-1 digest for a portion of a file:

    unsigned char *digest;
    digest = SHA1_FileChunk("/etc/passwd", 0, 1024); // first 1KB
    // Use digest...

Using the SHA1_CTX structure:

    SHA1_CTX ctx;
    unsigned char hash[20];

    SHA1Init(&ctx);
    SHA1Update(&ctx, (const unsigned char *)"hello ", 6);
    SHA1Update(&ctx, (const unsigned char *)"world", 5);
    SHA1End(&ctx, hash);
    // Use hash...

HISTORY

The sha1 functionality first appeared in OpenBSD 2.0.

AUTHORS

This implementation of SHA-1 was written by Steve Reid.

The SHA1End(), SHA1File(), SHA1FileChunk(), and SHA1Data() helper functions are derived from code written by Poul-Henning Kamp.

CAVEATS

This implementation of SHA-1 has not been validated by NIST and as such is not in official compliance with the standard.

If a message digest is to be copied to a multi-byte type (ie: an array of five 32-bit integers) it will be necessary to perform byte swapping on little endian machines such as the i386, alpha, and vax.
