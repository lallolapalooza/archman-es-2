Paquete: openmpi

SHMEM_BROADCAST64(3) Open MPI SHMEM_BROADCAST64(3)

shmem_broadcast4(3), shmem_broadcast8(3), shmem_broadcast32(3), shmem_broadcast64(3) - Copia un objeto de datos de un PE designado a una ubicación de destino en todos los demás PEs del conjunto activo.

SINÓPSIS

C o C++:

#include <mpp/shmem.h>
void shmem_broadcast32(void *target, const void *source,
  size_t nelems, int PE_root, int PE_start, int logPE_stride,
  int PE_size, long *pSync)
void shmem_broadcast64(void *target, const void *source,
  size_t nelems, int PE_root, int PE_start, int logPE_stride,
  int PE_size, long *pSync)

Fortran:

INCLUDE "mpp/shmem.fh"
INTEGER nelems, PE_root, PE_start, logPE_stride, PE_size
INTEGER pSync(SHMEM_BCAST_SYNC_SIZE)
CALL SHMEM_BROADCAST4(target, source, nelems, PE_root,
& PE_start, logPE_stride, PE_size, fIpSync)
CALL SHMEM_BROADCAST8(target, source, nelems, PE_root,
& PE_start, logPE_stride, PE_size, pSync)
CALL SHMEM_BROADCAST32(target, source, nelems,
& PE_root, PE_start, logPE_stride, PE_size, pSync)
CALL SHMEM_BROADCAST64(target, source, nelems,
& PE_root, PE_start, logPE_stride, PE_size, pSync)

DESCRIPCIÓN

Las rutinas de broadcast copian los datos en la dirección source del PE especificado por PE_root a la dirección target en todos los demás PEs del conjunto activo. El conjunto activo de PEs se define por el trío PE_start, logPE_stride y PE_size. Los datos no se copian a la dirección de destino en el PE especificado por PE_root. Antes de retornar, las rutinas de broadcast aseguran que los elementos del array pSync se restauren a sus valores iniciales.

Como con todas las rutinas colectivas de SHMEM, cada una de estas rutinas asume que solo los PEs en el conjunto activo llaman a la rutina. Si un PE no en el conjunto activo llama a una rutina colectiva de SHMEM, el comportamiento resultante es indefinido.

Los argumentos son los siguientes:

target
Un objeto de datos simétrico con uno de los siguientes tipos de datos:
shmem_broadcast8, shmem_broadcast64: Cualquier tipo no caracter que
tenga un tamaño de elemento de 64 bits. No se permiten tipos derivados de Fortran ni estructuras de C/C++.
shmem_broadcast32: Cualquier tipo no caracter que tenga un tamaño de elemento
de 32 bits. No se permiten tipos derivados de Fortran ni estructuras de C/C++.
shmem_broadcast4: Cualquier tipo no caracter que tenga un tamaño de elemento
de 32 bits.
source
Un objeto de datos simétrico que puede ser de cualquier tipo de datos permitido para el argumento target.
nelems
El número de elementos en source. Para shmem_broadcast32 y shmem_broadcast4, este es el número de medias palabras de 32 bits. nelems debe ser de tipo entero. Si estás usando Fortran, debe ser un valor entero por defecto.
PE_root
El ordinal de base cero del PE, con respecto al conjunto activo, desde el cual se copian los datos. Debe ser mayor o igual a 0 y menor que PE_size. PE_root debe ser de tipo entero. Si estás usando Fortran, debe ser un valor entero por defecto.
PE_start
El número de PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si estás usando Fortran, debe ser un valor entero por defecto.
logPE_stride
El log (base 2) del paso entre números de PE virtuales consecutivos en el conjunto activo. log_PE_stride debe ser de tipo entero. Si estás usando Fortran, debe ser un valor entero por defecto.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si estás usando Fortran, debe ser un valor entero por defecto.
pSync
Un array de trabajo simétrico. En C/C++, pSync debe ser de tipo long y tamaño _SHMEM_BCAST_SYNC_SIZE. En Fortran, pSync debe ser de tipo entero y tamaño SHMEM_BCAST_SYNC_SIZE. Cada elemento de este array debe inicializarse con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran) antes de que cualquiera de los PEs del conjunto activo entre en shmem_barrier().

Los valores de los argumentos PE_root, PE_start, logPE_stride y PE_size deben ser iguales en todos los PEs del conjunto activo. Los mismos objetos de datos target y source, y el mismo array de trabajo pSync deben pasarse a todos los PEs del conjunto activo.

Antes de que cualquier PE llame a una rutina de broadcast, debes asegurarte de que se cumplen las siguientes condiciones (la sincronización mediante una barrera u otro método suele ser necesaria para garantizar esto): El array pSync en todos los PEs del conjunto activo no está todavía en uso desde una llamada anterior a una rutina de broadcast. El array target en todos los PEs del conjunto activo está listo para aceptar los datos del broadcast.

Al retornar de una rutina de broadcast, lo siguiente es cierto para el PE local: Si el PE actual no es el PE raíz, el objeto de datos target se actualiza. Los valores en el array pSync se restauran a los valores originales.

NOTAS

Los términos colectivo y simétrico se definen en intro_shmem(3).

Todas las rutinas de broadcast de SHMEM restauran pSync a su contenido original. Múltiples llamadas a rutinas de SHMEM que utilizan el mismo array pSync no requieren que pSync se reinicialice después de la primera llamada.

Debes asegurarte de que el array pSync no esté siendo actualizado por ningún PE en el conjunto activo mientras alguno de los PEs participa en el procesamiento de una rutina de broadcast de SHMEM. Ten cuidado para evitar estas situaciones: Si el array pSync se inicializa en tiempo de ejecución, se necesita algún tipo de sincronización para asegurar que todos los PEs del conjunto de trabajo hayan inicializado pSync antes de que alguno de ellos entre en una rutina de SHMEM llamada con el array de sincronización pSync. Un array pSync puede reutilizarse en una rutina de broadcast de SHMEM posterior solo si ninguno de los PEs del conjunto activo está procesando todavía una llamada previa a una rutina de broadcast de SHMEM que utilizó el mismo array pSync. En general, esto solo se puede garantizar haciendo algún tipo de sincronización. Sin embargo, en el caso especial de que las rutinas de SHMEM se llamen con el mismo conjunto activo, puedes asignar dos arrays pSync y alternar entre ellos en llamadas sucesivas.

EJEMPLOS

En los siguientes ejemplos, la llamada a shmem_broadcast64 copia source en PE 4 a target en los PEs 5, 6 y 7.

Ejemplo C/C++:

for (i=0; i < _SHMEM_BCAST_SYNC_SIZE; i++) {
  pSync[i] = _SHMEM_SYNC_VALUE;
}
shmem_barrier_all(); /* Espera a que todos los PEs inicialicen pSync */
shmem_broadcast64(target, source, nelems, 0, 4, 0, 4, pSync);

Ejemplo Fortran:

INTEGER PSYNC(SHMEM_BCAST_SYNC_SIZE)
INTEGER TARGET, SOURCE, NELEMS, PE_ROOT, PE_START,
& LOGPE_STRIDE, PE_SIZE, PSYNC
COMMON /COM/ TARGET, SOURCE
DATA PSYNC /SHMEM_BCAST_SYNC_SIZE*SHMEM_SYNC_VALUE/
CALL SHMEM_BROADCAST64(TARGET, SOURCE, NELEMS, 0, 4, 0, 4,
& PSYNC)
