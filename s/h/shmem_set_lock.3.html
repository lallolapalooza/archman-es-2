shmem_set_lock(3)

Paquete: openmpi

SHMEM_SET_LOCK(3) Open MPI SHMEM_SET_LOCK(3)

shmem_set_lock(3), shmem_clear_lock(3), shmem_test_lock(3) - Libera, bloquea y prueba un bloqueo de exclusión mutua de memoria.

SINOPSIS

C o C++:

#include <mpp/shmem.h>
void shmem_clear_lock(volatile long *lock)
void shmem_set_lock(volatile long *lock)
int shmem_test_lock(volatile long *lock)

Fortran:

INCLUDE "mpp/shmem.h"
INTEGER lock, SHMEM_TEST_LOCK
CALL SHMEM_CLEAR_LOCK(lock)
CALL SHMEM_SET_LOCK(lock)
I = SHMEM_TEST_LOCK(lock)

DESCRIPCIÓN

La rutina shmem_set_lock establece un bloqueo de exclusión mutua después de esperar a que el bloqueo sea liberado por cualquier otro PE que lo tenga actualmente. Se garantiza que los PEs en espera obtendrán el bloqueo de manera de primer llegado, primer servido.

La rutina shmem_clear_lock libera un bloqueo previamente establecido por shmem_set_lock después de asegurar que todas las escrituras locales y remotas iniciadas en la región crítica se han completado.

La función shmem_test_lock establece un bloqueo de exclusión mutua solo si está actualmente liberado. Al usar esta función, un PE puede evitar bloquearse en un bloqueo establecido. Si el bloqueo está actualmente establecido, la función regresa sin esperar. Estas rutinas son apropiadas para proteger una región crítica de la actualización simultánea por múltiples PEs. Aceptan los siguientes argumentos:

lock
Un objeto de datos simétrico que es una variable escalar o un array de longitud 1. Este objeto de datos debe establecerse en 0 en todos los elementos de procesamiento (PEs) antes de su primer uso. lock debe ser de tipo entero. Si está usando Fortran, debe ser de tipo predeterminado.

NOTAS

El término objeto de datos simétrico se define en intro_shmem(3).

VALORES DE RETORNO

La función shmem_test_lock devuelve 0 si el bloqueo estaba originalmente liberado y esta llamada pudo establecer el bloqueo. Se devuelve el valor 1 si el bloqueo había sido establecido y la llamada regresó sin esperar para establecer el bloqueo.
