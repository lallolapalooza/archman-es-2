NOMBRE

shfmt - Formatea programas de shell

SINOPSIS

shfmt [opciones] [ruta...]

DESCRIPCIÓN

shfmt formatea programas de shell. Si el único argumento es un guion (-) o no se proporcionan argumentos, se utilizará la entrada estándar. Si una ruta dada es un directorio, se utilizarán todos los scripts de shell encontrados bajo ese directorio.

Si se encuentran archivos EditorConfig, se utilizarán para aplicar opciones de formato. Si se pasan opciones de analizador o de impresora a la herramienta, no se utilizarán las opciones de formato de EditorConfig. Se puede usar un valor predeterminado como -i=0 para este propósito.

El formato predeterminado de shell de shfmt se eligió para ser consistente, común y predecible. Algunos aspectos del formato se pueden configurar a través de las opciones de la impresora.

OPCIONES

Opciones genéricas

--version

Muestra la versión y sale.

-l[=0], --list[=0]

Lista los archivos cuyo formato difiere del de shfmt; las rutas están separadas por un salto de línea o un carácter nulo si -l=0

-w, --write

Escribe el resultado en el archivo en lugar de stdout.

-d, --diff

Genera un error con un diff cuando el formato difiere.

El diff usa color cuando la salida es una terminal. Para nunca usar color, configure una NO_COLOR no vacía o TERM=dumb. Para siempre usar color, configure una FORCE_COLOR no vacía.

--apply-ignore

Aplica siempre las reglas de ignorar de EditorConfig.

Al formatear archivos directamente, las reglas de ignorar se omiten sin esta opción. Debería ser útil para cualquier herramienta o editor que formatee stdin o un solo archivo. Al imprimir resultados en stdout, un archivo ignorado no produce ninguna salida.

--filename str

Proporciona un nombre para el archivo de entrada estándar.

El uso de esta opción es necesario para que el soporte de EditorConfig funcione con stdin, ya que los archivos EditorConfig se encuentran en relación con la ubicación de un script.

Opciones de analizador

-ln, --language-dialect <str>

Dialecto de lenguaje (bash/posix/mksh/bats, predeterminado auto).

Cuando se establece en auto, el lenguaje se detecta a partir del nombre del archivo de entrada, siempre que tenga una extensión de shell como foo.mksh. De lo contrario, si la entrada comienza con un shebang de shell como #!/bin/sh, se utiliza eso en su lugar. Si ninguno de los dos resulta en un resultado, se utiliza bash como respaldo.

La extensión de nombre de archivo .sh es un caso especial: implica posix, pero puede ser anulada por un shebang de shell válido.

-p, --posix

Atajo para -ln=posix.

-s, --simplify

Simplifica el código.

Opciones de impresora

-i, --indent <uint>

Indentación: 0 para tabulaciones (predeterminado), >0 para número de espacios.

-bn, --binary-next-line

Los operadores binarios como && y | pueden comenzar una línea.

-ci, --case-indent

Las declaraciones de switch se indentarán.

-sr, --space-redirects

Los operadores de redirección irán seguidos de un espacio.

-kp, --keep-padding

Mantiene el relleno de alineación de columnas.

Esta opción está OBSOLETA y se eliminará en la próxima versión principal. Para más información, ver: https://github.com/mvdan/sh/issues/658

-fn, --func-next-line

Las llaves de apertura de funciones se colocan en una línea separada.

-mn, --minify

Minifica el código para reducir su tamaño (implica -s).

Opciones de utilidad

-f[=0], --find[=0]

Encuentra recursivamente todos los archivos de shell e imprime las rutas; las rutas están separadas por un salto de línea o un carácter nulo si -f=0.

--to-json

Imprime el árbol de sintaxis en stdout como un JSON tipado.

--from-json

Lee el árbol de sintaxis desde stdin como un JSON tipado.

EJEMPLOS

Formatea todos los scripts bajo el directorio actual, imprimiendo cuáles se modifican:

shfmt -l -w .

Para CI, se puede usar una variante donde los cambios de formato solo se muestran como diffs:

shfmt -d .

Las siguientes opciones de formato se parecen mucho al estilo de shell de Google definido en https://google.github.io/styleguide/shellguide.html:

shfmt -i 2 -ci -bn

A continuación, se muestra un archivo de ejemplo de EditorConfig según lo definido por https://editorconfig.org/, que muestra cómo establecer cualquier opción:

[*.sh]
# como -i=4
indent_style = space
indent_size = 4
# --language-variant
shell_variant      = posix
binary_next_line   = true
# --case-indent
switch_case_indent = true
space_redirects    = true
keep_padding       = true
# --func-next-line
function_next_line = true
# Ignora todo el directorio "third_party" al llamar shfmt en directorios,
# como "shfmt -l -w .". Al formatear archivos directamente,
# como "shfmt -w third_party/foo.sh" o "shfmt --filename=third_party/foo.sh",
# la lógica de ignorar solo se aplica cuando se da la opción --apply-ignore.
[third_party/**]
ignore = true

Las secciones de EditorConfig también pueden usar `[[shell]]` o `[[bash]]` para coincidir con cualquier script de shell o bash, lo que es particularmente útil cuando los scripts usan un shebang pero no una extensión. Tenga en cuenta que esta característica está fuera de la especificación de EditorConfig y puede cambiarse en el futuro.

shfmt también puede reemplazar bash -n para verificar si hay errores de sintaxis en los scripts de shell. Es más exhaustivo, ya que analiza toda la sintaxis estáticamente y requiere UTF-8 válido:

$ echo '${foo:1 2}' | bash -n
$ echo '${foo:1 2}' | shfmt >/dev/null
1:9: no es un operador aritmético válido: 2
$ echo 'foo=(1 2)' | bash --posix -n
$ echo 'foo=(1 2)' | shfmt -p >/dev/null
1:5: los arrays son una característica de bash
