DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) calculan una o más reducciones en arrays simétricos en múltiples PEs virtuales. Una reducción realiza una operación binaria asociativa sobre un conjunto de valores. Para una lista de otras rutinas de reducción de SHMEM, ver intro_shmem(3).

Como con todas las rutinas colectivas de SHMEM, cada una de estas rutinas asume que solo los PEs del conjunto activo llaman a la rutina. Si un PE no perteneciente al conjunto activo llama a una rutina colectiva de SHMEM, el resultado es indefinido.

El argumento nreduce determina el número de reducciones separadas a realizar. El array fuente en todos los PEs del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en el array destino en todos los PEs del conjunto activo. El conjunto activo se define por el trío PE_start, logPE_stride, PE_size.

Los arrays fuente y destino pueden ser el mismo array, pero no pueden ser arrays superpuestos.

Los argumentos son los siguientes:

target
Un array simétrico de longitud nreduce elementos para recibir los resultados de las operaciones de reducción. El tipo de datos de target varía con la versión de la rutina de reducción que se llama y el idioma utilizado. Al llamar desde C/C++, consulte la sección SINOPSIS para obtener información sobre los tipos de datos. Al llamar desde Fortran, los tipos de datos de destino son los siguientes:
shmem_comp4_prod_to_all: Complejo, con un tamaño de elemento igual a dos
Valores reales de 4 bytes.
shmem_comp8_prod_to_all: Complejo, con un tamaño de elemento igual a dos
Valores reales de 8 bytes.

shmem_int4_prod_to_all: Entero, con un tamaño de elemento de 4 bytes

shmem_int8_prod_to_all: Entero, con un tamaño de elemento de 8 bytes

shmem_real4_prod_to_all: Real, con un tamaño de elemento de 4 bytes

shmem_real8_prod_to_all: Real, con un tamaño de elemento de 8 bytes

shmem_real16_prod_to_all: Real, con un tamaño de elemento de 16 bytes

source
Un array simétrico, de longitud nreduce elementos, que contiene un elemento para cada operación de reducción separada. El argumento source debe tener el mismo tipo de datos que target.
nreduce
El número de elementos en los arrays target y source. nreduce debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
PE_start
El número de PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
logPE_stride
El logaritmo (base 2) del paso entre los números de PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
pWrk
Un array de trabajo simétrico. El argumento pWrk debe tener el mismo tipo de datos que target. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Un array de trabajo simétrico. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Si está utilizando Fortran, debe ser un valor entero por defecto. Antes de que cualquiera de los PEs en el conjunto activo entre en la rutina de reducción, cada elemento de este array debe ser inicializado con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran).

Los valores de los argumentos nreduce, PE_start, logPE_stride y PE_size deben ser iguales en todos los PEs del conjunto activo. Los mismos arrays target y source, y los mismos arrays de trabajo pWrk y pSync, deben pasarse a todos los PEs del conjunto activo. Antes de que cualquier PE llame a una rutina de reducción, debe asegurarse de que se cumplen las siguientes condiciones (la sincronización mediante una barrera u otro método suele ser necesaria para garantizar esto): Los arrays pWrk y pSync en todos los PEs del conjunto activo ya no están en uso por una llamada anterior a una rutina colectiva de SHMEM. El array target en todos los PEs del conjunto activo está listo para aceptar los resultados de la reducción.

Al regresar de una rutina de reducción, lo siguiente es cierto para el PE local: El array target está actualizado. Los valores del array pSync se restauran a los valores originales.

DESCRIPTION

These routines perform an all-to-all product reduction. Each PE in the group specified by logPe, id, and hints contributes its input data from the array source to the calculation. The result of the reduction is placed in the array target on all PEs in the group.

The reduction operation is a product. For example, if PEs 0, 1, and 2 all have the value 3 in their respective source arrays, then after the call, all PEs will have the value 9 (3 * 3) in their target arrays.

The operation is performed on the elements of the arrays source and target. The number of elements to be reduced is specified by nlonglong, nlongdouble, nlong, nint, nfloat, ndouble, or ncomplx, depending on the specific routine being called.

The arrays pWrk and pSync are working arrays used by the reduction routine. pWrk is used for intermediate storage of data. pSync is used for synchronization between PEs. The sizes of these arrays are defined by the constants SHMEM_REDUCE_MIN_WRKDATA_SIZE and SHMEM_REDUCE_SYNC_SIZE, respectively. These constants are defined in the Fortran header file <mpp/shmem.h>. In C/C++, the caller is responsible for allocating these arrays. The type of the elements in these arrays should match the type of the data being reduced.

The arguments logPe, id, and hints specify the processing elements (PEs) that participate in the reduction. These arguments are used to define the active set of PEs. The details of how these arguments are interpreted are specific to the SHMEM implementation and are not further elaborated here. However, in general, they are used to select a subset of PEs for the reduction operation.

The target and source arrays can be the same.

NOTES

The pSync array must be initialized to the value SHMEM_SYNC_VALUE (defined in <mpp/shmem.h>) on all participating PEs before the reduction routine is called. This initialization should occur only once, typically at the beginning of the program. Subsequent calls to reduction routines that use the same pSync array do not require re-initialization, provided that the synchronization is handled correctly.

It is the caller's responsibility to ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the product of the real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMP8_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

Example 2: Consider the following C/C++ call:

shmem_short_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_short_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_short_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_short_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
