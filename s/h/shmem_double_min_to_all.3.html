DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) computan una o más reducciones a través de arreglos simétricos en múltiples PEs virtuales. Una reducción realiza una operación binaria asociativa en un conjunto de valores. Para una lista de otras rutinas de reducción de SHMEM, ver intro_shmem(3).

Al igual que con todas las rutinas colectivas de SHMEM, cada una de estas rutinas asume que solo los PEs del conjunto activo llaman a la rutina. Si un PE no perteneciente al conjunto activo llama a una rutina colectiva de SHMEM, el comportamiento no está definido.

El argumento nreduce determina el número de reducciones separadas a realizar. El arreglo fuente en todos los PEs del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en el arreglo destino en todos los PEs del conjunto activo. El conjunto activo se define por el trío PE_start, logPE_stride, PE_size.

Los arreglos fuente y destino pueden ser el mismo arreglo, pero no pueden ser arreglos superpuestos.

Los argumentos son los siguientes:

target
Un arreglo simétrico de longitud nreduce elementos para recibir los resultados de las operaciones de reducción. El tipo de dato de target varía con la versión de la rutina de reducción que se llama. Al llamar desde C/C++, consulte la sección SINOPSIS para obtener información sobre el tipo de dato. Al llamar desde Fortran, los tipos de dato de destino son los siguientes:

shmem_int4_min_to_all: Entero, con un tamaño de elemento de 4 bytes

shmem_int8_min_to_all: Entero, con un tamaño de elemento de 8 bytes

shmem_real4_min_to_all: Real, con un tamaño de elemento de 4 bytes

shmem_real8_min_to_all: Real, con un tamaño de elemento de 8 bytes

shmem_real16_min_to_all: Real, con un tamaño de elemento de 16 bytes

source Un arreglo simétrico: de longitud nreduce elementos, que contiene un
elemento para cada operación de reducción separada. El argumento fuente debe tener el mismo tipo de dato que target.
nreduce
El número de elementos en los arreglos target y source. nreduce debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
PE_start
El número PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
logPE_stride
El logaritmo (base 2) del paso entre números PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
pWrk
Un arreglo de trabajo simétrico. El argumento pWrk debe tener el mismo tipo de dato que target. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Un arreglo de trabajo simétrico. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Si está utilizando Fortran, debe ser un valor entero por defecto. Cada elemento de este arreglo debe inicializarse con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran) antes de que cualquiera de los PEs del conjunto activo ingrese a la rutina de reducción.

Los valores de los argumentos nreduce, PE_start, logPE_stride y PE_size deben ser iguales en todos los PEs del conjunto activo. Los mismos arreglos target y source, y los mismos arreglos de trabajo pWrk y pSync, deben pasarse a todos los PEs del conjunto activo.

Antes de que cualquier PE llame a una rutina de reducción, debe asegurarse de que existan las siguientes condiciones (a menudo se necesita sincronización a través de una barrera o algún otro método para asegurar esto): Los arreglos pWrk y pSync en todos los PEs del conjunto activo ya no se están utilizando de una llamada previa a una rutina colectiva de SHMEM. El arreglo target en todos los PEs del conjunto activo está listo para recibir los resultados de la reducción.

Al regresar de una rutina de reducción, lo siguiente es verdadero para el PE local: El arreglo target se actualiza. Los valores en el arreglo pSync se restauran a los valores originales.

NOTAS

Los términos colectivo, simétrico y alineado en caché se definen en intro_shmem(3). Todas las rutinas de reducción de SHMEM restablecen los valores en pSync antes de devolverlos, por lo que un arreglo pSync particular solo necesita ser inicializado la primera vez que se usa.

Debe asegurarse de que el arreglo pSync no esté siendo actualizado en ningún PE del conjunto activo mientras alguno de los PEs participa en el procesamiento de una rutina de reducción de SHMEM. Tenga cuidado con las siguientes situaciones: Si el arreglo pSync se inicializa en tiempo de ejecución, se necesita algún tipo de sincronización para asegurar que todos los PEs del conjunto de trabajo hayan inicializado pSync antes de que alguno de ellos ingrese a una rutina de SHMEM llamada con el arreglo de sincronización pSync. Un arreglo pSync o pWrk se puede reutilizar en una llamada de rutina de reducción posterior solo si ninguno de los PEs del conjunto activo todavía está procesando una rutina de reducción anterior que utilizó los mismos arreglos pSync o pWrk. En general, esto solo se puede asegurar realizando algún tipo de sincronización. Sin embargo, en el caso especial de las rutinas de reducción que se llaman con el mismo conjunto activo, puede asignar dos arreglos pSync y pWrk y alternar entre ellos en llamadas sucesivas.

shmem_double_min_to_all(3)

SYNOPSIS

Synopsis

Fortran:
CALL SHMEM_REAL8_MIN_TO_ALL(target, source, nlong, PE_access, PE_stride, PE_count, pWrk, pSync)
C/C++:
void shmem_double_min_to_all(double *target, double *source, size_t nlong, int PE_access, int PE_stride, int PE_count, void *pWrk, long *pSync);

DESCRIPTION

The shmem_double_min_to_all and SHMEM_REAL8_MIN_TO_ALL routines compute the minimum value of a data object across a specified subset of processing elements (PEs).

The reduction operation is performed on the elements of the source array (or the scalar variable source if nlong is 1) and the result is placed in the target array (or the scalar variable target if nlong is 1).

The following is a list of the arguments:

target
A pointer to the target array or scalar variable where the result of the reduction is to be stored. For Fortran, this is a variable or array element.
source
A pointer to the source array or scalar variable containing the data to be reduced. For Fortran, this is a variable or array element.
nlong
The number of double-precision elements to be reduced. For Fortran, this is an integer value.
PE_access
The PE number from which the reduction operation is initiated. For Fortran, this is an integer value.
PE_stride
The stride between PE numbers that participate in the reduction. For Fortran, this is an integer value.
PE_count
The number of PEs that participate in the reduction. For Fortran, this is an integer value.
pWrk
A pointer to a work array. This array must be of type (for C/C++) double and large enough to hold the reduction work space. For Fortran, this is an array. The required size is implementation- dependent, but is at least SHMEM_REDUCE_MIN_WRKDATA_SIZE.
pSync
A pointer to a synchronization array. This array must be of type (for C/C++) long and initialized to the value SHMEM_SYNC_VALUE. The size of this array is implementation-dependent, but is at least SHMEM_REDUCE_SYNC_SIZE. For Fortran, this is an array initialized to SHMEM_SYNC_VALUE.

NOTES

The reduction operation involves a specified subset of PEs. The PE set is defined by the PE_access, PE_stride, and PE_count arguments. The reduction is initiated on the PE specified by PE_access. The stride between PEs in the reduction is specified by PE_stride. The total number of PEs participating in the reduction is specified by PE_count.

The reduction operation computes the minimum value. The result is placed in the target variable/array.

The pWrk and pSync arrays are used for internal communication and synchronization. They must be initialized before calling the reduction routine. The pSync array must be initialized with SHMEM_SYNC_VALUE.

The behavior is undefined if any PE is included in more than one reduction operation that is not properly synchronized.

EXAMPLES

Example 1: Fortran

This example finds the minimum value of the real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOMIN, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOMIN, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_REAL8_MIN_TO_ALL(FOOMIN, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOMIN
ENDIF

Example 2: Consider the following C/C++ call:

shmem_int_min_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_int_min_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_min_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_min_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
