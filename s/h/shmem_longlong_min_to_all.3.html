DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) calculan una o más reducciones en arrays simétricos en múltiples PEs virtuales. Una reducción realiza una operación binaria asociativa en un conjunto de valores. Para una lista de otras rutinas de reducción SHMEM, ver intro_shmem(3).

Como con todas las rutinas colectivas de SHMEM, cada una de estas rutinas asume que solo los PEs del conjunto activo llaman a la rutina. Si un PE que no está en el conjunto activo llama a una rutina colectiva de SHMEM, el comportamiento resultante no está definido.

El argumento nreduce determina el número de reducciones separadas a realizar. El array fuente en todos los PEs del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en el array destino en todos los PEs del conjunto activo. El conjunto activo se define por el triplete PE_start, logPE_stride, PE_size.

Los arrays fuente y destino pueden ser el mismo array, pero no pueden ser arrays superpuestos.

Los argumentos son los siguientes:

objetivo
Un array simétrico de longitud nreduce elementos para recibir los resultados de las operaciones de reducción. El tipo de dato de objetivo varía con la versión de la rutina de reducción que se llama. Al llamar desde C/C++, consulte la sección SINOPSIS para obtener información sobre el tipo de dato. Al llamar desde Fortran, los tipos de datos de objetivo son los siguientes:

shmem_int4_min_to_all: Entero, con un tamaño de elemento de 4 bytes

shmem_int8_min_to_all: Entero, con un tamaño de elemento de 8 bytes

shmem_real4_min_to_all: Real, con un tamaño de elemento de 4 bytes

shmem_real8_min_to_all: Real, con un tamaño de elemento de 8 bytes

shmem_real16_min_to_all: Real, con un tamaño de elemento de 16 bytes

fuente Un array: simétrico
de longitud nreduce elementos, que contiene un elemento para cada operación de reducción separada. El argumento fuente debe tener el mismo tipo de dato que objetivo.
nreduce
El número de elementos en los arrays objetivo y fuente. nreduce debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
PE_start
El número de PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
logPE_stride
El logaritmo (base 2) del paso entre números de PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
pWrk
Un array de trabajo simétrico. El argumento pWrk debe tener el mismo tipo de dato que objetivo. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Un array de trabajo simétrico. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Si está usando Fortran, debe ser un valor entero por defecto. Cada elemento de este array debe inicializarse con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran) antes de que cualquiera de los PEs del conjunto activo entre en la rutina de reducción.

Los valores de los argumentos nreduce, PE_start, logPE_stride y PE_size deben ser iguales en todos los PEs del conjunto activo. Los mismos arrays objetivo y fuente, y los mismos arrays de trabajo pWrk y pSync, deben pasarse a todos los PEs del conjunto activo.

Antes de que cualquier PE llame a una rutina de reducción, debe asegurarse de que existen las siguientes condiciones (la sincronización mediante una barrera u otro método suele ser necesaria para garantizar esto): Los arrays pWrk y pSync en todos los PEs del conjunto activo ya no están en uso de una llamada anterior a una rutina colectiva de SHMEM. El array objetivo en todos los PEs del conjunto activo está listo para aceptar los resultados de la reducción.

Al regresar de una rutina de reducción, lo siguiente es cierto para el PE local: El array objetivo se actualiza. Los valores en el array pSync se restauran a los valores originales.

NOTAS

Los términos colectivo, simétrico y alineado en caché se definen en intro_shmem(3). Todas las rutinas de reducción SHMEM restablecen los valores en pSync antes de que regresen, por lo que un pSync buffer en particular solo necesita ser inicializado la primera vez que se usa.

Debe asegurarse de que el array pSync no está siendo actualizado en ningún PE del conjunto activo mientras alguno de los PEs participa en el procesamiento de una rutina de reducción SHMEM. Tenga cuidado con las siguientes situaciones: Si el array pSync se inicializa en tiempo de ejecución, se necesita algún tipo de sincronización para asegurar que todos los PEs del conjunto de trabajo hayan inicializado pSync antes de que alguno de ellos entre en una rutina SHMEM llamada con el array de sincronización pSync. Un array pSync o pWrk puede reutilizarse en una llamada posterior a la rutina de reducción solo si ninguno de los PEs del conjunto activo todavía está procesando una rutina de reducción anterior que utilizó los mismos arrays pSync o pWrk. En general, esto solo se puede garantizar mediante algún tipo de sincronización. Sin embargo, en el caso especial de las rutinas de reducción que se llaman con el mismo conjunto activo, puede asignar dos arrays pSync y pWrk y alternar entre ellos en llamadas sucesivas.

SYNOPSIS

#include <shmem.h>

long long shmem_longlong_min_to_all(long long target, long long value, int nreduce, int PE_start, int logPE_stride, int PE_size, void *pSync, void *pWrk);
void shmem_longlong_min_reduce(long long *target, long long value, int nreduce, int PE_start, int logPE_stride, int PE_size, void *pSync, void *pWrk);
void shmem_longlong_min_to_all_reduce(long long *target, long long value, int nreduce, int PE_start, int logPE_stride, int PE_size, void *pSync, void *pWrk);

DESCRIPTION

These collective communication routines compute the minimum of a variable across a specified set of processing elements (PEs).

The shmem_longlong_min_to_all routine is the most efficient, but semantically equivalent to, the other routines. shmem_longlong_min_to_all is a blocking routine that returns the minimum value of value across all PEs in the specified symmetric communication domain.

The shmem_longlong_min_reduce and shmem_longlong_min_to_all_reduce routines are blocking routines that compute the minimum of value across all PEs in the specified symmetric communication domain. The minimum value is placed in the target array.

The target argument is the destination array where the result of the reduction is stored.

The value argument is the input value to be reduced.

The nreduce argument specifies the number of elements to be reduced.

The reduction is performed over the PEs specified by PE_start, logPE_stride, and PE_size.

  • PE_start: The first PE in the communication domain.
  • logPE_stride: The log of the stride between PEs.
  • PE_size: The number of PEs in the communication domain.

The pSync argument is a pointer to a synchronization array, which must be of size SHMEM_REDUCE_SYNC_SIZE.

The pWrk argument is a pointer to a work array, which must be of size SHMEM_REDUCE_MIN_WRKDATA_SIZE.

The shmem_longlong_min_to_all routine returns the minimum value across all PEs in the communication domain. The other two routines return the result to the target array.

NOTES

The synchronization arrays pSync must be initialized with SHMEM_SYNC_VALUE.

The reduction operations are performed on the PEs in the symmetric communication domain defined by PE_start, logPE_stride, and PE_size. All PEs in the symmetric communication domain must call these routines. The behavior is undefined if any PE in the domain does not call the routine.

The shmem_longlong_min_to_all routine is more efficient as it avoids the need for a separate reduction step and can leverage specific hardware optimizations.

EXAMPLES

Example 1: Fortran code snippet:

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOMIN, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOMIN, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_REAL8_MIN_TO_ALL(FOOMIN, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOMIN
ENDIF

Example 2: Consider the following C/C++ call:

shmem_int_min_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_int_min_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_min_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_min_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
