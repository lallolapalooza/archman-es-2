DESCRIPCIÓN

La utilidad objcopy de GNU copia el contenido de un archivo objeto a otro. objcopy utiliza la Biblioteca GNU BFD para leer y escribir los archivos objeto. Puede escribir el archivo objeto de destino en un formato diferente al del archivo objeto de origen. El comportamiento exacto de objcopy se controla mediante opciones de línea de comandos. Tenga en cuenta que objcopy debería ser capaz de copiar un archivo completamente enlazado entre dos formatos cualesquiera. Sin embargo, copiar un archivo objeto relocable entre dos formatos cualesquiera puede no funcionar como se espera.

objcopy crea archivos temporales para realizar sus traducciones y los elimina posteriormente. objcopy utiliza BFD para realizar todo su trabajo de traducción; tiene acceso a todos los formatos descritos en BFD y, por lo tanto, es capaz de reconocer la mayoría de los formatos sin que se le indique explícitamente.

objcopy puede usarse para generar S-records utilizando un formato de salida srec (por ejemplo, use -O srec).

objcopy puede usarse para generar un archivo binario plano utilizando un formato de salida binary (por ejemplo, use -O binary). Cuando objcopy genera un archivo binario plano, esencialmente producirá un volcado de memoria del contenido del archivo objeto de entrada. Se desechará toda la información de símbolos y reubicación. El volcado de memoria comenzará en la dirección de carga de la sección más baja copiada en el archivo de salida.

Al generar un archivo S-record o un archivo binario plano, puede ser útil usar -S para eliminar secciones que contengan información de depuración. En algunos casos, -R será útil para eliminar secciones que contengan información que no es necesaria para el archivo binario.

Nota: objcopy no es capaz de cambiar el endianness de sus archivos de entrada. Si el formato de entrada tiene un endianness (algunos formatos no lo tienen), objcopy solo puede copiar las entradas a formatos de archivo que tengan el mismo endianness o que no tengan endianness (por ejemplo, srec). (Sin embargo, vea la opción --reverse-bytes).

-j patrón de sección
--only-section=patrón de sección
Copia solo las secciones indicadas del archivo de entrada al archivo de salida. Esta opción se puede dar más de una vez. Ten en cuenta que usar esta opción inapropiadamente puede hacer que el archivo de salida no sea utilizable. Se aceptan caracteres comodín en patrón de sección.

Si el primer carácter de patrón de sección es un signo de exclamación (!) entonces las secciones coincidentes no se copiarán, incluso si un uso anterior de --only-section en la misma línea de comandos las copiaría de otro modo. Por ejemplo:

--only-section=.text.* --only-section=!.text.foo

copiará todas las secciones que coincidan con '.text.*' pero no la sección '.text.foo'.

-R patrón de sección
--remove-section=patrón de sección
Elimina cualquier sección que coincida con patrón de sección del archivo de salida. Esta opción se puede dar más de una vez. Ten en cuenta que usar esta opción inapropiadamente puede hacer que el archivo de salida no sea utilizable. Se aceptan caracteres comodín en patrón de sección. Usar las opciones -j y -R juntas resulta en un comportamiento indefinido.

Si el primer carácter de patrón de sección es un signo de exclamación (!) entonces las secciones coincidentes no se eliminarán, incluso si un uso anterior de --remove-section en la misma línea de comandos las eliminaría de otro modo. Por ejemplo:

--remove-section=.text.* --remove-section=!.text.foo

eliminará todas las secciones que coincidan con el patrón '.text.*', pero no eliminará la sección '.text.foo'.

--keep-section=patrón de sección
Al eliminar secciones del archivo de salida, conserva las secciones que coincidan con patrón de sección.
--remove-relocations=patrón de sección
Elimina las reubicaciones no dinámicas del archivo de salida para cualquier sección que coincida con patrón de sección. Esta opción se puede dar más de una vez. Ten en cuenta que usar esta opción inapropiadamente puede hacer que el archivo de salida no sea utilizable, y intentar eliminar una sección de reubicación dinámica como .rela.plt de un ejecutable o biblioteca compartida con --remove-relocations=.plt no funcionará. Se aceptan caracteres comodín en patrón de sección. Por ejemplo: 
--remove-relocations=.text.*

eliminará las reubicaciones de todas las secciones que coincidan con el patrón '.text.*'.

Si el primer carácter de patrón de sección es un signo de exclamación (!) entonces a las secciones coincidentes no se les eliminarán sus reubicaciones, incluso si un uso anterior de --remove-relocations en la misma línea de comandos causaría de otro modo la eliminación de las reubicaciones. Por ejemplo:

--remove-relocations=.text.* --remove-relocations=!.text.foo

eliminará todas las reubicaciones de las secciones que coincidan con el patrón '.text.*', pero no eliminará las reubicaciones de la sección '.text.foo'.

Convierte el símbolo nombre de símbolo en débil. Esta opción se puede dar más de una vez.

-w
--wildcard
Permite expresiones regulares en los nombres de símbolos utilizados en otras opciones de línea de comandos. Los operadores de signo de interrogación (?), asterisco (*), barra invertida (\) y corchetes ([]) se pueden usar en cualquier lugar del nombre del símbolo. Si el primer carácter del nombre del símbolo es un signo de exclamación (!), el sentido del interruptor se invierte para ese símbolo. Por ejemplo: 
-w -W !foo -W fo*

haría que objcopy debilitara todos los símbolos que comienzan con "fo" excepto el símbolo "foo".

-x
--discard-all
No copies símbolos no globales del archivo fuente.
-X
--discard-locals
No copies símbolos locales generados por el compilador. (Estos suelen empezar por L o ..)
-b byte
--byte=byte
Si se ha habilitado el intercalado mediante la opción --interleave, comienza el rango de bytes a mantener en el byte-ésimo byte. byte puede estar en el rango de 0 a amplitud-1, donde amplitud es el valor dado por la opción --interleave.
-i [amplitud]
--interleave[=amplitud]
Copia solo un rango de cada amplitud bytes. (Los datos de la cabecera no se ven afectados). Selecciona qué byte del rango inicia la copia con la opción --byte. Selecciona la anchura del rango con la opción --interleave-width.

Esta opción es útil para crear archivos para programar ROM. Se suele usar con un destino de salida "srec". Ten en cuenta que objcopy se quejará si no especificas también la opción --byte.

La amplitud de intercalado predeterminada es 4, por lo que con --byte establecido en 0, objcopy copiaría el primer byte de cada cuatro bytes de la entrada a la salida.

--interleave-width=anchura
Cuando se usa con la opción --interleave, copia anchura bytes a la vez. El inicio del rango de bytes a copiar se establece con la opción --byte, y la extensión del rango se establece con la opción --interleave.

El valor predeterminado para esta opción es 1. El valor de anchura más el valor byte establecido por la opción --byte no debe exceder la amplitud de intercalado establecida por la opción --interleave.

Esta opción se puede usar para crear imágenes para dos flashes de 16 bits intercalados en un bus de 32 bits pasando -b 0 -i 4 --interleave-width=2 y -b 2 -i 4 --interleave-width=2 a dos comandos de objcopy. Si la entrada fuera '12345678', las salidas serían '1256' y '3478' respectivamente.

-p
--preserve-dates
Establece las fechas de acceso y modificación del archivo de salida para que sean las mismas que las del archivo de entrada.

Esta opción también copia la fecha almacenada en la cabecera de un archivo en formato PE, a menos que la variable de entorno SOURCE_DATE_EPOCH esté definida. Si está definida, esta variable se usará como la fecha almacenada en la cabecera, interpretada como el número de segundos desde la época Unix.

-D
--deterministic-archives
Operate in deterministic mode. When copying archive members and writing the archive index, use zero for UIDs, GIDs, timestamps, and use consistent file modes for all files.

If binutils was configured with --enable-deterministic-archives, then this mode is on by default. It can be disabled with the -U option, below.

--debugging
Convert debugging information, if possible. This is not the default because only certain debugging formats are supported, and the conversion process can be time consuming.
--gap-fill val
Fill gaps between sections with val. This operation applies to the load address (LMA) of the sections. It is done by increasing the size of the section with the lower address, and filling in the extra space created with val.
--pad-to address
Pad the output file up to the load address address. This is done by increasing the size of the last section. The extra space is filled in with the value specified by --gap-fill (default zero).
--set-start val
Set the start address (also known as the entry address) of the new file to val. Not all object file formats support setting the start address.
--change-start incr
--adjust-start incr
Change the start address (also known as the entry address) by adding incr. Not all object file formats support setting the start address.
--change-addresses incr
--adjust-vma incr
Change the VMA and LMA addresses of all sections, as well as the start address, by adding incr. Some object file formats do not permit section addresses to be changed arbitrarily. Note that this does not relocate the sections; if the program expects sections to be loaded at a certain address, and this option is used to change the sections such that they are loaded at a different address, the program may fail.
--change-section-address sectionpattern{=,+,-}val
--adjust-section-vma sectionpattern{=,+,-}val
Set or change both the VMA address and the LMA address of any section matching sectionpattern. If = is used, the section address is set to val. Otherwise, val is added to or subtracted from the section address. See the comments under --change-addresses, above. If sectionpattern does not match any sections in the input file, a warning will be issued, unless --no-change-warnings is used.
--change-section-lma sectionpattern{=,+,-}val
Set or change the LMA address of any sections matching sectionpattern. The LMA address is the address where the section will be loaded into memory at program load time. Normally this is the same as the VMA address, which is the address of the section at program run time, but on some systems, especially those where a program is held in ROM, the two can be different. If = is used, the section address is set to val. Otherwise, val is added to or subtracted from the section address. See the comments under --change-addresses, above. If sectionpattern does not match any sections in the input file, a warning will be issued, unless --no-change-warnings is used.
--change-section-vma sectionpattern{=,+,-}val
Set or change the VMA address of any section matching sectionpattern. The VMA address is the address where the section will be located once the program has started executing. Normally this is the same as the LMA address, which is the address where the section will be loaded into memory, but on some systems, especially those where a program is held in ROM, the two can be different. If = is used, the section address is set to val. Otherwise, val is added to or subtracted from the section address. See the comments under --change-addresses, above. If sectionpattern does not match any sections in the input file, a warning will be issued, unless --no-change-warnings is used.
--change-warnings
--adjust-warnings
If --change-section-address or --change-section-lma or --change-section-vma is used, and the section pattern does not match any sections, issue a warning. This is the default.
--no-change-warnings
--no-adjust-warnings
Do not issue a warning if --change-section-address or --adjust-section-lma or --adjust-section-vma is used, even if the section pattern does not match any sections.
--set-section-flags sectionpattern=flags
Set the flags for any sections matching sectionpattern. The flags argument is a comma separated string of flag names. The recognized names are alloc, contents, load, noload, readonly, code, data, rom, exclude, share, debug, and large. You can set the contents flag for a section which does not have contents, but it is not meaningful to clear the contents flag of a section which does have contents--just remove the section instead. Not all flags are meaningful for all object file formats. In particular the share flag is only meaningful for COFF format files and not for ELF format files. The ELF x86-64 specific flag large corresponds to SHF_X86_64_LARGE.
--set-section-alignment sectionpattern=align
Set the alignment for any sections matching sectionpattern. align specifies the alignment in bytes and must be a power of two, i.e. 1, 2, 4, 8....
--add-section sectionname=filename
Add a new section named sectionname while copying the file. The contents of the new section are taken from the file filename. The size of the section will be the size of the file. This option only works on file formats which can support sections with arbitrary names. Note - it may be necessary to use the --set-section-flags option to set the attributes of the newly created section.
--dump-section sectionname=filename
Place the contents of section named sectionname into the file filename, overwriting any contents that may have been there previously. This option is the inverse of --add-section. This option is similar to the --only-section option except that it does not create a formatted file, it just dumps the contents as raw binary data, without applying any relocations. The option can be specified more than once.
--update-section sectionname=filename
Replace the existing contents of a section named sectionname with the contents of file filename. The size of the section will be adjusted to the size of the file. The section flags for sectionname will be unchanged. For ELF format files the section to segment mapping will also remain unchanged, something which is not possible using --remove-section followed by --add-section. The option can be specified more than once.

Note - it is possible to use --rename-section and --update-section to both update and rename a section from one command line. In this case, pass the original section name to --update-section, and the original and new section names to --rename-section.

--add-symbol name=[section:]value[,flags]
Add a new symbol named name while copying the file. This option may be specified multiple times. If the section is given, the symbol will be associated with and relative to that section, otherwise it will be an ABS symbol. Specifying an undefined section will result in a fatal error. There is no check for the value, it will be taken as specified. Symbol flags can be specified and not all flags will be meaningful for all object file formats. By default, the symbol will be global. The special flag 'before=othersym' will insert the new symbol in front of the specified othersym, otherwise the symbol(s) will be added at the end of the symbol table in the order they appear.
--rename-section oldname=newname[,flags]
Rename a section from oldname to newname, optionally changing the section's flags to flags in the process. This has the advantage over using a linker script to perform the rename in that the output stays as an object file and does not become a linked executable. This option accepts the same set of flags as the --set-section-flags option.

--long-section-names {enable,disable,keep}
Controla el manejo de nombres de sección largos al procesar los formatos de objeto "COFF" y "PE-COFF". El comportamiento predeterminado, keep, es preservar los nombres de sección largos si hay alguno presente en el archivo de entrada. Las opciones enable y disable habilitan o deshabilitan forzosamente el uso de nombres de sección largos en el objeto de salida; cuando disable está activo, los nombres de sección largos en el objeto de entrada se truncarán. La opción enable solo emitirá nombres de sección largos si hay alguno presente en las entradas; esto es mayormente lo mismo que keep, pero queda sin definir si la opción enable podría forzar la creación de una tabla de cadenas vacía en el archivo de salida.
--change-leading-char
Algunos formatos de archivo objeto usan caracteres especiales al principio de los símbolos. El carácter más común es el guion bajo, que los compiladores a menudo añaden antes de cada símbolo. Esta opción indica a objcopy que cambie el carácter inicial de cada símbolo al convertir entre formatos de archivo objeto. Si los formatos de archivo objeto usan el mismo carácter inicial, esta opción no tiene efecto. De lo contrario, añadirá un carácter, o eliminará un carácter, o cambiará un carácter, según corresponda.
--remove-leading-char
Si el primer carácter de un símbolo global es un carácter inicial especial utilizado por el formato de archivo objeto, elimina el carácter. El carácter inicial más común es el guion bajo. Esta opción eliminará un guion bajo inicial de todos los símbolos globales. Esto puede ser útil si deseas enlazar objetos de diferentes formatos de archivo con diferentes convenciones para los nombres de símbolos. Esto es diferente de --change-leading-char porque siempre cambia el nombre del símbolo cuando es apropiado, independientemente del formato de archivo objeto del archivo de salida.
--reverse-bytes=num
Invierte los bytes en una sección con contenido de salida. La longitud de una sección debe ser divisible por el valor dado para que el intercambio pueda llevarse a cabo. La inversión se realiza antes de que se realice la intercalación.

Esta opción se usa típicamente en la generación de imágenes de ROM para sistemas de destino problemáticos. Por ejemplo, en algunas placas de destino, las palabras de 32 bits obtenidas de ROMs de 8 bits se reensamblan en orden de bytes little-endian independientemente del orden de bytes de la CPU. Dependiendo del modelo de programación, el endianness de la ROM puede necesitar ser modificado.

Considere un archivo simple con una sección que contiene los siguientes ocho bytes: 12345678.

Usando --reverse-bytes=2 para el ejemplo anterior, los bytes en el archivo de salida se ordenarían 21436587.

Usando --reverse-bytes=4 para el ejemplo anterior, los bytes en el archivo de salida se ordenarían 43218765.

Al usar --reverse-bytes=2 para el ejemplo anterior, seguido de --reverse-bytes=4 en el archivo de salida, los bytes en el segundo archivo de salida se ordenarían 34127856.

--srec-len=ival
Solo significativo para salida srec. Establece la longitud máxima de los Srecords que se están produciendo a ival. Esta longitud cubre los campos de dirección, datos y crc.
--srec-forceS3
Solo significativo para salida srec. Evita la generación de registros S1/S2, creando el formato de registro S3-only.
--redefine-sym old=new

--redefine-syms=archivo
Aplica --redefine-sym a cada par de símbolos "old new" listado en el archivo archivo. archivo es simplemente un archivo plano, con un par de símbolos por línea. Los comentarios de línea pueden ser introducidos por el carácter de almohadilla. Esta opción puede ser dada más de una vez.
--weaken

--localize-symbols=archivo
Aplica la opción --localize-symbol a cada símbolo listado en el archivo archivo. archivo es simplemente un archivo plano, con un nombre de símbolo por línea. Los comentarios de línea pueden ser introducidos por el carácter de almohadilla. Esta opción puede ser dada más de una vez.

--alt-machine-code=índice
Si la arquitectura de salida tiene códigos de máquina alternativos, usa el índice-ésimo código en lugar del predeterminado. Esto es útil en caso de que una máquina reciba un código oficial y la cadena de herramientas adopte el nuevo código, pero otras aplicaciones sigan dependiendo del código original. Para arquitecturas basadas en ELF, si la alternativa índice no existe, entonces el valor se trata como un número absoluto que se almacenará en el campo e_machine de la cabecera ELF.

Marca el texto de salida como escribible. Esta opción no es significativa para todos los formatos de archivo objeto.
--readonly-text
Hace que el texto de salida esté protegido contra escritura. Esta opción no es significativa para todos los formatos de archivo objeto.

Marca el archivo de salida como paginable bajo demanda. Esta opción no es significativa para todos los formatos de archivo objeto.

Marca el archivo de salida como impuro. Esta opción no es significativa para todos los formatos de archivo objeto.

Añade el prefijo cadena a todos los nombres de sección en el archivo de salida.
--prefix-alloc-sections=cadena
Añade el prefijo cadena a todos los nombres de las secciones asignadas en el archivo de salida.
--add-gnu-debuglink=ruta-al-archivo
Crea una sección .gnu_debuglink que contiene una referencia a ruta-al-archivo y la añade al archivo de salida. Nota: el archivo en ruta-al-archivo debe existir. Parte del proceso de añadir la sección .gnu_debuglink implica incrustar una suma de verificación del contenido del archivo de información de depuración en la sección.

Si el archivo de información de depuración se crea en una ubicación pero se instalará más tarde en una ubicación diferente, no uses la ruta a la ubicación instalada. La opción --add-gnu-debuglink fallará porque el archivo instalado aún no existe. En su lugar, coloca el archivo de información de depuración en el directorio actual y usa la opción --add-gnu-debuglink sin componentes de directorio, así:

objcopy --add-gnu-debuglink=foo.debug

En tiempo de depuración, el depurador intentará buscar el archivo de información de depuración separado en un conjunto de ubicaciones conocidas. El conjunto exacto de estas ubicaciones varía según la distribución utilizada, pero típicamente incluye:

"* El mismo directorio que el ejecutable."
"* Un subdirectorio del directorio que contiene el ejecutable"
llamado .debug
"* Un directorio de depuración global como /usr/lib/debug."

Siempre que el archivo de información de depuración se instale en una de estas ubicaciones antes de ejecutar el depurador, todo debería funcionar correctamente.

--keep-section-symbils
--keep-section-symbols
Al depurar un archivo, quizás con --strip-debug o --strip-unneeded, conserva cualquier símbolo que especifique nombres de secciones, los cuales de otro modo serían eliminados.
--keep-file-symbols
Al depurar un archivo, quizás con --strip-debug o --strip-unneeded, conserva cualquier símbolo que especifique nombres de archivos fuente, los cuales de otro modo serían eliminados.
--only-keep-debug
Depura un archivo, eliminando los contenidos de cualquier sección que no sería eliminada por --strip-debug y dejando intactas las secciones de depuración. En archivos ELF, esto preserva todas las secciones de notas en la salida.

Nota: las cabeceras de sección de las secciones depuradas se preservan, incluyendo sus tamaños, pero los contenidos de la sección se descartan. Las cabeceras de sección se preservan para que otras herramientas puedan emparejar el archivo de información de depuración con el ejecutable real, incluso si ese ejecutable ha sido reubicado a un espacio de direcciones diferente.

La intención es que esta opción se utilice junto con --add-gnu-debuglink para crear un ejecutable de dos partes. Una es un binario depurado que ocupará menos espacio en RAM y en una distribución, y la segunda es un archivo de información de depuración que solo se necesita si se requieren capacidades de depuración. El procedimiento sugerido para crear estos archivos es el siguiente:

1.<Enlaza el ejecutable como de costumbre. Asumiendo que se llama>
"foo" entonces...
1.<Ejecuta "objcopy --only-keep-debug foo foo.dbg" para>
crear un archivo que contenga la información de depuración.
1.<Ejecuta "objcopy --strip-debug foo" para crear un>
ejecutable depurado.
1.<Ejecuta "objcopy --add-gnu-debuglink=foo.dbg foo">
para añadir un enlace a la información de depuración en el ejecutable depurado.

Nota: la elección de ".dbg" como extensión para el archivo de información de depuración es arbitraria. También el paso "--only-keep-debug" es opcional. Puedes hacer esto en su lugar:

1.<Enlaza el ejecutable como de costumbre.>
1.<Copia "foo" a "foo.full">
1.<Ejecuta "objcopy --strip-debug foo">
1.<Ejecuta "objcopy --add-gnu-debuglink=foo.full foo">

es decir, el archivo al que apunta --add-gnu-debuglink puede ser el ejecutable completo. No tiene que ser un archivo creado por el interruptor --only-keep-debug.

Nota: este interruptor solo está destinado a ser utilizado en archivos completamente enlazados. No tiene sentido usarlo en archivos objeto donde la información de depuración puede estar incompleta. Además, la característica gnu_debuglink actualmente solo admite la presencia de un nombre de archivo que contenga información de depuración, no varios nombres de archivo de forma individual por archivo objeto.

--strip-dwo
Elimina el contenido de todas las secciones DWARF .dwo, dejando las secciones de depuración restantes y todos los símbolos intactos. Esta opción está destinada a ser utilizada por el compilador como parte de la opción -gsplit-dwarf, que divide la información de depuración entre el archivo .o y un archivo .dwo separado. El compilador genera toda la información de depuración en el mismo archivo, luego usa la opción --extract-dwo para copiar las secciones .dwo al archivo .dwo, y luego la opción --strip-dwo para eliminar esas secciones del archivo .o original.
--extract-dwo
Extrae el contenido de todas las secciones DWARF .dwo. Consulte la opción --strip-dwo para obtener más información.
--file-alignment num
Especifica la alineación del archivo. Las secciones en el archivo siempre comenzarán en offsets de archivo que son múltiplos de este número. El valor predeterminado es 512. [Esta opción es específica para objetivos PE.]
--heap reserve
--heap reserve,commit
Especifica el número de bytes de memoria a reservar (y opcionalmente confirmar) que se utilizarán como heap para este programa. [Esta opción es específica para objetivos PE.]
--image-base value
Utiliza value como la dirección base de tu programa o dll. Esta es la ubicación de memoria más baja que se utilizará cuando tu programa o dll se cargue. Para reducir la necesidad de reubicación y mejorar el rendimiento de tus dlls, cada una debería tener una dirección base única y no solaparse con ninguna otra dll. El valor predeterminado es 0x400000 para ejecutables, y 0x10000000 para dlls. [Esta opción es específica para objetivos PE.]
--section-alignment num
Establece el campo de alineación de sección en la cabecera PE. Las secciones en memoria siempre comenzarán en direcciones que sean múltiplos de este número. El valor predeterminado es 0x1000. [Esta opción es específica para objetivos PE.]
--stack reserve

--subsystem which

--subsystem which:major.minor
Especifica el subsistema bajo el cual se ejecutará tu programa. Los valores legales para which son "native", "windows", "console", "posix", "efi-app", "efi-bsd", "efi-rtd", "sal-rtd", y "xbox". Opcionalmente, también puedes establecer la versión del subsistema. También se aceptan valores numéricos para which. [Esta opción es específica para objetivos PE.]
--extract-symbol
Mantiene las marcas de sección y los símbolos del archivo pero elimina todos los datos de sección. Específicamente, la opción:
*<elimina los contenidos de todas las secciones;>
*<establece el tamaño de cada sección a cero; y>
*<establece la dirección de inicio del archivo a cero.>

Esta opción se utiliza para construir un archivo .sym para un kernel VxWorks. También puede ser una forma útil de reducir el tamaño de un archivo de entrada del enlazador --just-symbols.

--compress-debug-sections
Comprime las secciones de depuración DWARF usando zlib con SHF_COMPRESSED de la ABI ELF. Nota: si la compresión realmente hiciera una sección más grande, entonces no se comprime.
--compress-debug-sections=none
--compress-debug-sections=zlib
--compress-debug-sections=zlib-gnu
--compress-debug-sections=zlib-gabi
--compress-debug-sections=zstd
Para archivos ELF, estas opciones controlan cómo se comprimen las secciones de depuración DWARF. --compress-debug-sections=none es equivalente a --decompress-debug-sections. --compress-debug-sections=zlib y --compress-debug-sections=zlib-gabi son equivalentes a --compress-debug-sections. --compress-debug-sections=zlib-gnu comprime las secciones de depuración DWARF usando el formato obsoleto zlib-gnu. Las secciones de depuración se renombran para que comiencen con .zdebug. --compress-debug-sections=zstd comprime las secciones de depuración DWARF usando zstd. Nota: si la compresión realmente hiciera una sección más grande, entonces no se comprime ni se renombra.
--decompress-debug-sections
Descomprime las secciones de depuración DWARF. Para una sección .zdebug, se restaura el nombre original.
--elf-stt-common=yes
--elf-stt-common=no
Para archivos ELF, estas opciones controlan si los símbolos comunes deben convertirse al tipo "STT_COMMON" o "STT_OBJECT". --elf-stt-common=yes convierte el tipo de símbolo común a "STT_COMMON". --elf-stt-common=no convierte el tipo de símbolo común a "STT_OBJECT".
--merge-notes
--no-merge-notes
Para archivos ELF, intenta (o no intenta) reducir el tamaño de cualquier sección de tipo SHT_NOTE eliminando notas duplicadas.
