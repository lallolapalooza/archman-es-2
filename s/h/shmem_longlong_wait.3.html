CALL SHMEM_WAIT_UNTIL(ivar, cmp, cmp_value)

DESCRIPCIÓN

shmem_wait y shmem_wait_until esperan a que ivar sea modificado por una escritura remota o un intercambio atómico emitido por un procesador diferente. Estas rutinas se pueden utilizar para sincronización dirigida punto a punto. Una llamada a shmem_wait no retorna hasta que otro procesador escribe un valor, distinto de cmp_value, en ivar en el procesador que espera. Una llamada a shmem_wait_until no retorna hasta que otro procesador modifica ivar para satisfacer la condición implícita por cmp y cmp_value. Este mecanismo es útil cuando un procesador necesita indicar a otro procesador que ha completado alguna acción.

Los argumentos son los siguientes:

target
El objeto de datos entero accesible remotamente que se actualizará en el PE remoto. Si estás utilizando C/C++, el tipo de target debe coincidir con el implícito en la sección SYNOPSIS. Si estás utilizando el compilador Fortran, debe ser de tipo entero con un tamaño de elemento de 4 bytes para SHMEM_INT4_ADD y de 8 bytes para SHMEM_INT8_ADD.
value
El valor que se agregará atómicamente a target. Si estás utilizando C/C++, el tipo de value debe coincidir con el implícito en la sección SYNOPSIS. Si estás utilizando Fortran, debe ser de tipo entero con un tamaño de elemento igual al de target.
pe
Un entero que indica el número de PE en el que se actualizará target. Si estás utilizando Fortran, debe ser un valor entero por defecto.
ivar
Una variable entera accesible remotamente que está siendo actualizada por otro PE. Si estás utilizando C/C++, el tipo de ivar debe coincidir con el implícito en la sección SYNOPSIS. Si estás utilizando Fortran, ivar debe ser de un tipo entero de tamaño específico según la función que se esté llamando, como sigue:

shmem_wait, shmem_wait_until: ** entero por defecto

shmem_int4_wait, shmem_int4_wait_until: ** ENTERO*4

shmem_int8_wait, shmem_int8_wait_until: ** ENTERO*8

cmp
El operador de comparación que compara ivar con cmp_value. cmp debe ser de tipo entero. Si estás utilizando Fortran, debe ser de tipo por defecto. Si estás utilizando C/C++, el tipo de cmp debe coincidir con el implícito en la sección SYNOPSIS. Los siguientes valores de cmp son compatibles:
SHMEM_CMP_EQ
Igual
SHMEM_CMP_NE
No igual
SHMEM_CMP_GT
Mayor que
SHMEM_CMP_LE
Menor o igual que
SHMEM_CMP_LT
Menor que
SHMEM_CMP_GE
Mayor o igual que
cmp_value
cmp_value debe ser de tipo entero. Si estás utilizando C/C++, el tipo de cmp_value debe coincidir con el implícito en la sección SYNOPSIS. Si estás utilizando Fortran, cmp_value debe ser un entero del mismo tamaño y tipo que ivar. Las rutinas shmem_wait retornan cuando ivar ya no es igual a cmp_value. Las rutinas shmem_wait_until retornan cuando la condición de comparación se cumple. La condición de comparación se define por el argumento ivar comparado con cmp_value utilizando el operador de comparación, cmp.

EJEMPLOS

Ejemplo 1: La siguiente llamada retorna cuando la variable ivar no es igual a 100:

INTEGER*8 IVAR
CALL SHMEM_INT8_WAIT(IVAR, INT8(100))

Ejemplo 2: La siguiente llamada a SHMEM_INT8_WAIT_UNTIL es equivalente a la llamada a SHMEM_INT8_WAIT en el ejemplo 1:

INTEGER*8 IVAR
CALL SHMEM_INT8_WAIT_UNTIL(IVAR, SHMEM_CMP_NE, INT8(100))

Ejemplo 3: La siguiente llamada C/C++ espera hasta que el bit de signo en ivar sea establecido por una transferencia desde un PE remoto:

int ivar;
shmem_int_wait_until(&ivar, SHMEM_CMP_LT, 0);

Ejemplo 4: El siguiente ejemplo Fortran está en el contexto de una subrutina:

SUBROUTINE EXAMPLE()
  INTEGER FLAG_VAR
  COMMON/FLAG/FLAG_VAR
  . . .
  FLAG_VAR = FLAG_VALUE ! inicializa la variable de evento
  . . .
  IF (FLAG_VAR .EQ. FLAG_VALUE) THEN
    CALL SHMEM_WAIT(FLAG_VAR, FLAG_VALUE)
  ENDIF
  FLAG_VAR = FLAG_VALUE ! reinicia la variable de evento para la próxima vez
  . . .
END

NAME

shmem_longlong_wait - Espera a que una variable de memoria compartida de 64 bits sin signo (long long) alcance un valor determinado.

SYNOPSIS


#include <shmem.h>

long long shmem_longlong_wait(long long *addr, long long value);
long long shmem_longlong_wait_until(long long *addr, long long cmp, long long value);

DESCRIPTION

Estas funciones forman parte de la API de OpenSHMEM, que proporciona un conjunto de primitivas para la programación paralela en clústeres.

shmem_longlong_wait espera hasta que el valor de la variable de 64 bits sin signo (long long) en la dirección de memoria compartida addr sea igual a value.

shmem_longlong_wait_until espera hasta que la condición cmp se cumpla entre el valor en addr y el valor value. El argumento cmp puede ser uno de los siguientes:

  • SHMEM_CMP_EQ: igual a
  • SHMEM_CMP_NE: no igual a
  • SHMEM_CMP_LT: menor que
  • SHMEM_CMP_LE: menor o igual que
  • SHMEM_CMP_GT: mayor que
  • SHMEM_CMP_GE: mayor o igual que

RETURN VALUE

Ambas funciones devuelven el valor de la variable en addr en el momento en que se cumple la condición de espera.

ERRORS

No se especifican errores explícitos para estas funciones. Sin embargo, una implementación podría fallar si la dirección addr no es accesible o si ocurre un error de comunicación.

EXAMPLE


#include <shmem.h>
#include <stdio.h>

int main(void) {
    long long *shared_var;
    long long value_to_wait_for = 42;
    long long current_value;

    // Inicializar OpenSHMEM
    shmem_init();

    // Asignar memoria compartida para una variable long long
    shared_var = (long long *)shmem_malloc(sizeof(long long));
    *shared_var = 0; // Inicializar la variable compartida

    // En otro proceso, se podría escribir en shared_var para cambiar su valor.
    // Por ejemplo, usando shmem_longlong_put.

    // Esperar hasta que la variable compartida sea igual a value_to_wait_for
    printf("Proceso %d esperando hasta que la variable compartida sea %lld...\n", shmem_my_pe(), value_to_wait_for);
    current_value = shmem_longlong_wait_until(shared_var, SHMEM_CMP_EQ, value_to_wait_for);

    printf("Proceso %d: La variable compartida ahora es %lld\n", shmem_my_pe(), current_value);

    // Liberar memoria compartida
    shmem_free(shared_var);

    // Finalizar OpenSHMEM
    shmem_finalize();

    return 0;
}
