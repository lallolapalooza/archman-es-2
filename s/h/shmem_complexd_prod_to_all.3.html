DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) calculan una o más reducciones en arreglos simétricos en múltiples PEs virtuales. Una reducción realiza una operación binaria asociativa sobre un conjunto de valores. Para obtener una lista de otras rutinas de reducción SHMEM, consulte intro_shmem(3).

Al igual que con todas las rutinas colectivas de SHMEM, cada una de estas rutinas asume que solo los PEs del conjunto activo llaman a la rutina. Si un PE que no está en el conjunto activo llama a una rutina colectiva de SHMEM, el resultado es indefinido.

El argumento nreduce determina el número de reducciones separadas a realizar. El arreglo de origen en todos los PEs del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en el arreglo de destino en todos los PEs del conjunto activo. El conjunto activo se define por el triplete PE_start, logPE_stride, PE_size.

Los arreglos de origen y destino pueden ser el mismo arreglo, pero no pueden ser arreglos superpuestos.

Los argumentos son los siguientes:

objetivo
Un arreglo simétrico de longitud nreduce elementos para recibir los resultados de las operaciones de reducción. El tipo de datos del objetivo varía con la versión de la rutina de reducción que se llama y el idioma utilizado. Al llamar desde C/C++, consulte la sección SINOPSIS para obtener información sobre los tipos de datos. Al llamar desde Fortran, los tipos de datos del objetivo son los siguientes:
shmem_comp4_prod_to_all: Complejo, con un tamaño de elemento igual a dos
valores reales de 4 bytes.
shmem_comp8_prod_to_all: Complejo, con un tamaño de elemento igual a dos
valores reales de 8 bytes.

shmem_int4_prod_to_all: Entero, con un tamaño de elemento de 4 bytes

shmem_int8_prod_to_all: Entero, con un tamaño de elemento de 8 bytes

shmem_real4_prod_to_all: Real, con un tamaño de elemento de 4 bytes

shmem_real8_prod_to_all: Real, con un tamaño de elemento de 8 bytes

shmem_real16_prod_to_all: Real, con un tamaño de elemento de 16 bytes

fuente
Un arreglo simétrico, de longitud nreduce elementos, que contiene un elemento para cada operación de reducción separada. El argumento fuente debe tener el mismo tipo de datos que objetivo.
nreduce
El número de elementos en los arreglos objetivo y fuente. nreduce debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
PE_start
El número de PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
logPE_stride
El logaritmo (base 2) del paso entre números de PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero por defecto.
pWrk
Un arreglo de trabajo simétrico. El argumento pWrk debe tener el mismo tipo de datos que objetivo. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Un arreglo de trabajo simétrico. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Si está utilizando Fortran, debe ser un valor entero por defecto. Antes de que alguno de los PEs del conjunto activo entre en la rutina de reducción, cada elemento de este arreglo debe ser inicializado con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran).

Los valores de los argumentos nreduce, PE_start, logPE_stride y PE_size deben ser iguales en todos los PEs del conjunto activo. Los mismos arreglos objetivo y fuente, y los mismos arreglos de trabajo pWrk y pSync, deben pasarse a todos los PEs del conjunto activo. Antes de que cualquier PE llame a una rutina de reducción, debe asegurarse de que se cumplen las siguientes condiciones (la sincronización mediante una barrera u otro método es a menudo necesaria para garantizar esto): Los arreglos pWrk y pSync en todos los PEs del conjunto activo ya no están en uso por una llamada previa a una rutina colectiva de SHMEM. El arreglo objetivo en todos los PEs del conjunto activo está listo para recibir los resultados de la reducción.

Al regresar de una rutina de reducción, lo siguiente es cierto para el PE local: El arreglo objetivo se actualiza. Los valores en el arreglo pSync se restauran a los valores originales.

NAME

shmem_complexd_prod_to_all, shmem_complexd_prod_reduce, shmem_complexd_prod — product reduction routines for complex double-precision numbers

SYNOPSIS

C++:
inline void shmem_complexd_prod_to_all(complex_double *target, const complex_double *source, size_t nreduce, int PE_min, int PE_stride, int PE_count, complex_double *pWrk, long *pSync);
inline void shmem_complexd_prod_reduce(complex_double *target, const complex_double *source, size_t nreduce, int PE_min, int PE_stride, int PE_count, complex_double *pWrk, long *pSync);
inline void shmem_complexd_prod(complex_double *target, const complex_double *source, size_t nreduce, int PE_min, int PE_stride, int PE_count, complex_double *pWrk, long *pSync);

Fortran:
SUBROUTINE shmem_complexd_prod_to_all(target, source, nreduce, PE_min, PE_stride, PE_count, pWrk, pSync)
INTEGER, INTENT(IN) :: nreduce, PE_min, PE_stride, PE_count
REAL*16, DIMENSION(nreduce), INTENT(INOUT) :: target
REAL*16, DIMENSION(nreduce), INTENT(IN) :: source
REAL*16, DIMENSION(MAX(nreduce/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE)), INTENT(OUT) :: pWrk
INTEGER*8, DIMENSION(SHMEM_REDUCE_SYNC_SIZE), INTENT(OUT) :: pSync
END SUBROUTINE shmem_complexd_prod_to_all

SUBROUTINE shmem_complexd_prod_reduce(target, source, nreduce, PE_min, PE_stride, PE_count, pWrk, pSync)
INTEGER, INTENT(IN) :: nreduce, PE_min, PE_stride, PE_count
REAL*16, DIMENSION(nreduce), INTENT(INOUT) :: target
REAL*16, DIMENSION(nreduce), INTENT(IN) :: source
REAL*16, DIMENSION(MAX(nreduce/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE)), INTENT(OUT) :: pWrk
INTEGER*8, DIMENSION(SHMEM_REDUCE_SYNC_SIZE), INTENT(OUT) :: pSync
END SUBROUTINE shmem_complexd_prod_reduce

SUBROUTINE shmem_complexd_prod(target, source, nreduce, PE_min, PE_stride, PE_count, pWrk, pSync)
INTEGER, INTENT(IN) :: nreduce, PE_min, PE_stride, PE_count
REAL*16, DIMENSION(nreduce), INTENT(INOUT) :: target
REAL*16, DIMENSION(nreduce), INTENT(IN) :: source
REAL*16, DIMENSION(MAX(nreduce/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE)), INTENT(OUT) :: pWrk
INTEGER*8, DIMENSION(SHMEM_REDUCE_SYNC_SIZE), INTENT(OUT) :: pSync
END SUBROUTINE shmem_complexd_prod

DESCRIPTION

These routines operate on the active set of processing elements (PEs) specified by PE_min, PE_stride, and PE_count. They compute the product of elements in the source arrays and place the results in the corresponding elements of the target arrays. The computation is performed across all PEs in the active set.

shmem_complexd_prod_to_all performs a product reduction and distributes the final result to all PEs in the active set.

shmem_complexd_prod_reduce performs a product reduction, but the final result is available only on the root PE (PE_min).

shmem_complexd_prod is an alias for shmem_complexd_prod_reduce.

The routines support complex double-precision numbers, which are represented as pairs of real numbers (e.g., REAL*16 in Fortran or complex_double in C++).

The pWrk array is a work array used by the reduction routines. Its size must be at least MAX(nreduce/2+1, SHMEM_REDUCE_MIN_WRKDATA_SIZE).

The pSync array is a synchronization array used to ensure proper ordering of operations. Its size must be at least SHMEM_REDUCE_SYNC_SIZE. Each element of pSync should be initialized to SHMEM_SYNC_VALUE before the call.

NOTES

The pSync array must be initialized before the first use. All PEs in the active set must have completed initialization of pSync before any PE enters a SHMEM reduction routine that uses it. A common approach is to statically initialize pSync with SHMEM_SYNC_VALUE.

You must ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations:

  • If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array.
  • A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the product of the real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL*16 FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMP8_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

Example 2: Consider the following C/C++ call:

shmem_complexd_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_complexd_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_complexd_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_complexd_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
