NOMBRE

shmat, shmdt - operaciones de memoria compartida System V

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/shm.h>
void *shmat(int shmid, const void *_Nullable shmaddr, int shmflg);
int shmdt(const void *shmaddr);

DESCRIPCIÓN

shmat()

shmat() adjunta el segmento de memoria compartida System V identificado por shmid al espacio de direcciones del proceso que llama. La dirección de adjunción se especifica mediante shmaddr con uno de los siguientes criterios:

•
Si shmaddr es NULL, el sistema elige una dirección adecuada (no utilizada) alineada por páginas para adjuntar el segmento.
•
Si shmaddr no es NULL y SHM_RND se especifica en shmflg, la adjunción ocurre en la dirección igual a shmaddr redondeada hacia abajo al múltiplo más cercano de SHMLBA.
•
De lo contrario, shmaddr debe ser una dirección alineada por páginas en la que ocurre la adjunción.

Además de SHM_RND, las siguientes banderas pueden especificarse en el argumento de máscara de bits shmflg:

SHM_EXEC (específico de Linux; desde Linux 2.6.9)
Permite que el contenido del segmento sea ejecutado. El llamante debe tener permiso de ejecución sobre el segmento.
SHM_RDONLY
Adjunta el segmento para acceso de solo lectura. El proceso debe tener permiso de lectura para el segmento. Si esta bandera no se especifica, el segmento se adjunta para acceso de lectura y escritura, y el proceso debe tener permiso de lectura y escritura para el segmento. No existe la noción de un segmento de memoria compartida de solo escritura.
SHM_REMAP (específico de Linux)
Esta bandera especifica que la adjunción del segmento debe reemplazar cualquier adjunción existente en el rango que comienza en shmaddr y continúa por el tamaño del segmento. (Normalmente, se produciría un error EINVAL si ya existe una adjunción en este rango de direcciones.) En este caso, shmaddr no debe ser NULL.

El valor de brk(2) del proceso que llama no se altera por la adjunción. El segmento se desadjuntará automáticamente al salir del proceso. El mismo segmento puede adjuntarse como de solo lectura y como de lectura/escritura, y más de una vez, en el espacio de direcciones del proceso.

Una llamada exitosa a shmat() actualiza los miembros de la estructura shmid_ds (ver shmctl(2)) asociada al segmento de memoria compartida de la siguiente manera:

•
shm_atime se establece en la hora actual.
•
shm_lpid se establece en el ID de proceso del proceso que llama.
•
shm_nattch se incrementa en uno.

shmdt()

shmdt() desadjunta el segmento de memoria compartida ubicado en la dirección especificada por shmaddr del espacio de direcciones del proceso que llama. El segmento a desadjuntar debe estar actualmente adjunto con shmaddr igual al valor devuelto por la llamada a shmat() que lo adjuntó.

Tras una llamada exitosa a shmdt(), el sistema actualiza los miembros de la estructura shmid_ds asociada al segmento de memoria compartida de la siguiente manera:

•
shm_dtime se establece en la hora actual.
•
shm_lpid se establece en el ID de proceso del proceso que llama.
•
shm_nattch se decrementa en uno. Si se vuelve 0 y el segmento está marcado para eliminación, el segmento se elimina.

VALOR DE RETORNO

En caso de éxito, shmat() devuelve la dirección del segmento de memoria compartida adjunto; en caso de error, devuelve (void *) -1, y errno se establece para indicar el error.

En caso de éxito, shmdt() devuelve 0; en caso de error, devuelve -1, y errno se establece para indicar el error.

ERRORES

shmat() puede fallar con uno de los siguientes errores:

EACCES
El proceso que llama no tiene los permisos requeridos para el tipo de adjunción solicitada, y no tiene la capacidad CAP_IPC_OWNER en el espacio de nombres del usuario que rige su espacio de nombres IPC.
EIDRM
shmid apunta a un identificador eliminado.
EINVAL
Valor shmid inválido, dirección shmaddr no alineada (es decir, no alineada por páginas y no se especificó SHM_RND) o inválida, o no se puede adjuntar el segmento en shmaddr, o se especificó SHM_REMAP y shmaddr era NULL.
ENOMEM
No se pudo asignar memoria para el descriptor o para las tablas de páginas.

shmdt() puede fallar con uno de los siguientes errores:

EINVAL
No hay ningún segmento de memoria compartida adjunto en shmaddr; o, shmaddr no está alineado en un límite de página.

ESTÁNDARES

POSIX.1-2008.

HISTORIA

POSIX.1-2001, SVr4.

En SVID 3 (o quizás antes), el tipo del argumento shmaddr se cambió de char * a const void *, y el tipo devuelto por shmat() de char * a void *.

POSIX.1-2024 cambió el código de error de (void *) -1 a SHM_FAILED.

NOTAS

Después de un fork(2), el hijo hereda los segmentos de memoria compartida adjuntos.

Después de un execve(2), todos los segmentos de memoria compartida adjuntos se desadjuntan del proceso.

Al salir con _exit(2), todos los segmentos de memoria compartida adjuntos se desadjuntan del proceso.

Usar shmat() con shmaddr igual a NULL es la forma preferida y portable de adjuntar un segmento de memoria compartida. Tenga en cuenta que el segmento de memoria compartida adjuntado de esta manera puede adjuntarse en direcciones diferentes en procesos diferentes. Por lo tanto, cualquier puntero mantenido dentro de la memoria compartida debe hacerse relativo (típicamente a la dirección de inicio del segmento), en lugar de absoluto.

En Linux, es posible adjuntar un segmento de memoria compartida incluso si ya está marcado para ser eliminado. Sin embargo, POSIX.1 no especifica este comportamiento y muchas otras implementaciones no lo soportan.

El siguiente parámetro del sistema afecta a shmat():

SHMLBA
Múltiplo del límite inferior del segmento de dirección. Al especificar explícitamente una dirección de adjunción en una llamada a shmat(), el llamante debe asegurarse de que la dirección sea un múltiplo de este valor. Esto es necesario en algunas arquitecturas, ya sea para asegurar un buen rendimiento de la caché de la CPU o para asegurar que las diferentes adjunciones del mismo segmento tengan vistas consistentes dentro de la caché de la CPU. SHMLBA es normalmente algún múltiplo del tamaño de página del sistema. (En muchas arquitecturas de Linux, SHMLBA es lo mismo que el tamaño de página del sistema).

La implementación no impone límites intrínsecos por proceso al número de segmentos de memoria compartida (SHMSEG).

NAME

shmat, shmdt - attach and detach System V shared memory segments

LIBRARY

System V IPC (library libc, which is part of libucv)"

SYNOPSIS

#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/shm.h>

    void *shmat(int shmid, const void *shmaddr, int shmflg);
    int shmdt(const void *shmaddr);

DESCRIPTION

System V shared memory allows several processes to share a region of memory. The shmget() function creates a new shared memory segment, or retrieves the ID of an existing segment.

The shmat() function attaches the shared memory segment identified by shmid to the calling process's address space. The segment is attached at the address specified by shmaddr. If shmaddr is NULL, the system chooses a suitable available address at which to attach the segment. If shmaddr is not NULL, it must be a multiple of the architecture's page size. The segment is attached at this address, which must be a free area in the process's address space.

shmflg specifies the desired access and creation flags. It is the bitwise OR of zero or more of the following flags:

SHM_RDONLY
Attach the segment for reading only. If this flag is not specified, the segment is attached for reading and writing.
SHM_RMW
Attach the segment for reading and writing. This flag is the default if neither SHM_RDONLY nor SHM_RMW is specified.
SHM_REMAP
(Since Linux 2.1) If the segment is already attached, detach and then reattach it. This is useful for changing the access flags (e.g., from read/write to read-only). The shmaddr must be specified and must be the address at which the segment is currently attached.
SHM_EXEC
(Since Linux 3.1) The memory segment can be executed.
SHM_HUGETLB
Use huge pages to back the segment. This flag is only relevant when creating a segment (see shmget(2)). The size of the huge pages is architecture-dependent. On Linux, this can be set system-wide via the kernel configuration.
SHM_PAGETABLE
(Since Linux 4.7) Attach the segment as a page table page. This is an advanced feature used for memory management, typically by containers.
IPC_64BIT
Return a 64-bit segment ID if the kernel supports this. This is the default on 64-bit systems.

The shmdt() function detaches the shared memory segment identified by the address shmaddr from the calling process's address space. shmaddr must be the address returned by a prior shmat() call.

When a shared memory segment is attached, its size is determined by the shm_segsz field in the shared memory identifier data structure. For details, see shmctl(2).

When a process terminates, or when it detaches a shared memory segment using shmdt(), the segment remains in the system as long as at least one process has it attached. When the last process detaches a segment, it is marked for destruction. The memory is actually freed by the kernel after the last process has detached it, and after the last process has terminated if it had attached the segment without detaching it.

RETURN VALUE

On success, shmat() returns a pointer to the shared memory segment. On error, it returns (void *) -1, and errno is set to indicate the error.

On success, shmdt() returns 0. On error, it returns -1, and errno is set to indicate the error.

ERRORS

The shmat() function may fail if:

EACCES
Read or write access denied. The calling process does not have permission to access the shared memory segment with the requested flags.
EADDRINUSE
The specified shmaddr is already in use.
EINVAL
shmid is not a valid shared memory identifier, or shmaddr is not NULL and is not a multiple of the page size, or the segment is not large enough to map at shmaddr with the specified flags.
ENOMEM
Not enough core: Not enough memory is available to satisfy the attach request.
FAULTRPC
Too many segments are mapped (e.g., mmap(2)'s MAP_FIXED is not allowed to overlap with other mappings).
SHM_INVALID
The shared memory segment has been marked for destruction.

The shmdt() function may fail if:

EINVAL
shmaddr is not a valid address that was returned by shmat().

STANDARDS

POSIX.1-2001, POSIX.1-2008, SVr4, SUSv2.

HISTORY

The shmat() and shmdt() functions originate from System V.

NOTES

The shmat() function may fail with EINVAL if the requested attach address (shmaddr) is not page-aligned. If shmaddr is NULL, the system chooses an address. This address is usually a multiple of the system page size, but this is not guaranteed.

The behavior of shmat() with respect to shmaddr is somewhat subtle. If shmaddr is not NULL, it represents a *hint* to the kernel about where to attach the segment. The kernel will try to attach the segment at that address. If that address is not available, or if SHM_REMAP is not used and the segment is already attached at a different address, then shmat() fails with EADDRINUSE or EINVAL. It is generally recommended to use shmaddr = NULL to let the kernel choose the attach address.

The shmdt() function takes the attached address as an argument. The kernel maintains a list of attached segments for each process. When shmdt() is called, the kernel searches this list for an entry matching shmaddr and removes it. If no such entry is found, shmdt() fails with EINVAL.

A process can attach the same shared memory segment multiple times, potentially at different addresses and with different access permissions. For example, a process might attach a segment for reading and writing, use it, and then attach it again for read-only access.

A shared memory segment remains valid as long as at least one process has it attached. When the last process detaches a segment (either via shmdt() or upon process termination), the kernel marks the segment for destruction. The actual memory is freed only after the last process has detached the segment.

See shm_overview(7) for a general overview of System V shared memory.

Consider the following example:

The "reader" program creates a shared memory segment and a System V semaphore set. The program prints out the IDs of the created objects, and then waits for the semaphore to change value.


$ ./svshm_string_read;
shmid = 1114194
semid = 15

In another terminal window, we run the "writer" program. The "writer" program takes three command-line arguments: the IDs of the shared memory segment and semaphore set created by the "reader", and a string. It attaches the existing shared memory segment, copies the string to the shared memory, and modifies the semaphore value.


$ ./svshm_string_write 1114194 15 'Hello, world';

Returning to the terminal where the "reader" is running, we see that the program has ceased waiting on the semaphore and has printed the string that was copied into the shared memory segment by the writer:


Hello, world

#ifndef SVSHM_STRING_H

union semun {                   /* Used in calls to semctl() */
    int                 val;
    struct semid_ds     *buf;
    unsigned short      *array;
#if defined(__linux__)
    struct seminfo      *__buf;
#endif
};
#define MEM_SIZE 4096
#endif  // include guard

Program source: svshm_string_read.c

The "reader" program creates a shared memory segment and a semaphore set containing one semaphore. It then attaches the shared memory object into its address space and initializes the semaphore value to 1. Finally, the program waits for the semaphore value to become 0, and afterwards prints the string that has been copied into the shared memory segment by the "writer".


/* svshm_string_read.c
   Licensed under GNU General Public License v2 or later.
*/
#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/ipc.h>
#include <sys/sem.h>
#include <sys/shm.h>
#include "svshm_string.h"
int
main(void)
{
    int            semid, shmid;
    char           *addr;
    union semun    arg, dummy;
    struct sembuf  sop;
    /* Create shared memory and semaphore set containing one
       semaphore.  */
    shmid = shmget(IPC_PRIVATE, MEM_SIZE, IPC_CREAT | 0600);
    if (shmid == -1)
        err(EXIT_FAILURE, "shmget");
    semid = semget(IPC_PRIVATE, 1, IPC_CREAT | 0600);
    if (semid == -1)
        err(EXIT_FAILURE, "semget");
    /* Attach shared memory into our address space.  */
    addr = shmat(shmid, NULL, SHM_RDONLY);
    if (addr == (void *) -1)
        err(EXIT_FAILURE, "shmat");
    /* Initialize semaphore 0 in set with value 1.  */
    arg.val = 1;
    if (semctl(semid, 0, SETVAL, arg) == -1)
        err(EXIT_FAILURE, "semctl");
    printf("shmid = %d\n", shmid);
    printf("semid = %d\n", semid);
    /* Wait for semaphore value to become 0.  */
    sop.sem_num = 0;
    sop.sem_op = 0;
    sop.sem_flg = 0;
    if (semop(semid, &sop, 1) == -1)
        err(EXIT_FAILURE, "semop");
    /* Print the string from shared memory.  */
    printf("%s\n", addr);
    /* Remove shared memory and semaphore set.  */
    if (shmctl(shmid, IPC_RMID, NULL) == -1)
        err(EXIT_FAILURE, "shmctl");
    if (semctl(semid, 0, IPC_RMID, dummy) == -1)
        err(EXIT_FAILURE, "semctl");
    exit(EXIT_SUCCESS);
}

Program source: svshm_string_write.c

The writer program takes three command-line arguments: the IDs of the shared memory segment and semaphore set that have already been created by the "reader", and a string. It attaches the shared memory segment into its address space, and then decrements the semaphore value to 0 in order to inform the "reader" that it can now examine the contents of the shared memory.


/* svshm_string_write.c
   Licensed under GNU General Public License v2 or later.
*/
#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/sem.h>
#include <sys/shm.h>
#include "svshm_string.h"
int
main(int argc, char *argv[])
{
    int            semid, shmid;
    char           *addr;
    size_t         size;
    struct sembuf  sop;
    if (argc != 4) {
        fprintf(stderr, "Usage: %s shmid semid string\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    size = strlen(argv[3]) + 1;  /* +1 to include trailing '\0' */
    if (size > MEM_SIZE) {
        fprintf(stderr, "String is too big!\n");
        exit(EXIT_FAILURE);
    }
    /* Get object IDs from command-line.  */
    shmid = atoi(argv[1]);
    semid = atoi(argv[2]);
    /* Attach shared memory into our address space and copy string
       (including trailing null byte) into memory.  */
    addr = shmat(shmid, NULL, 0);
    if (addr == (void *) -1)
        err(EXIT_FAILURE, "shmat");
    memcpy(addr, argv[3], size);
    /* Decrement semaphore to 0.  */
    sop.sem_num = 0;
    sop.sem_op = -1;
    sop.sem_flg = 0;
    if (semop(semid, &sop, 1) == -1)
        err(EXIT_FAILURE, "semop");
    exit(EXIT_SUCCESS);
}
