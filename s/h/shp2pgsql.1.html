NOMBRE

shp2pgsql - cargador de shapefile a postgis

SINTAXIS

shp2pgsql [opciones] shapefile [esquema.]tabla

DESCRIPCIÓN

El cargador de datos shp2pgsql convierte archivos Shape de ESRI en SQL adecuado para su inserción en una base de datos PostGIS/PostgreSQL.

Versión: 1.1.5 (06/10/2006)

USO

El <shapefile> es el nombre del archivo shape, sin ninguna información de extensión. Por ejemplo, 'roads' sería el nombre del archivo shape que comprende los archivos 'roads.shp', 'roads.shx' y 'roads.dbf'.

El <nombre_tabla> es el nombre (opcionalmente calificado por el esquema) de la tabla de la base de datos donde desea almacenar los datos en la base de datos. Dentro de esa tabla, la geometría se colocará en la columna 'geo_value' por defecto.

OPCIONES

El cargador tiene varios modos de operación distinguidos por banderas de línea de comandos:

(Tenga en cuenta que -a, -c, -d y -p son mutuamente excluyentes.)

-d
Elimina la tabla de la base de datos antes de crear una nueva tabla con los datos del archivo Shape.
-a
Agrega datos del archivo Shape a la tabla de la base de datos. Tenga en cuenta que para usar esta opción para cargar varios archivos, los archivos deben tener los mismos atributos y los mismos tipos de datos.
-c
Crea una nueva tabla y la popula con los datos del archivo Shape. Este es el modo por defecto.
-p
Solo produce el código SQL de creación de tabla, sin agregar ningún dato real. Esto se puede usar si necesita separar completamente los pasos de creación de tabla y carga de datos.
-D
Utiliza el formato "dump" de PostgreSQL para los datos de salida. Esto se puede combinar con -a, -c y -d. Es mucho más rápido de cargar que el formato SQL "insert" por defecto. Úselo para conjuntos de datos muy grandes.
-w
Salida en formato WKT, en lugar de WKB. Tenga en cuenta que esto puede introducir derivas de coordenadas debido a la pérdida de precisión.
-e
Ejecuta cada sentencia por separado, sin usar una transacción. Esto permite la carga de la mayoría de los datos buenos cuando hay algunas geometrías defectuosas que generan errores. Tenga en cuenta que esto no se puede usar con la bandera -D ya que el formato "dump" siempre usa una transacción.
-s [<SRID_ORIGEN>:]<SRID>
Crea y popula las tablas de geometría con el SRID especificado. Si se proporciona SRID_ORIGEN, las geometrías se reproyectarán. La reproyección no se puede usar con -D.
-G
Utiliza el tipo de datos geográficos en lugar de geométricos. Geografía se utiliza para almacenar datos de lat/lon. Actualmente, la única referencia espacial admitida es 4326.
-g <columna_geometria>
Especifica el nombre de la columna de geometría (principalmente útil en modo de adición).
-k
Mantiene la capitalización de los identificadores (columna, esquema y atributos). Tenga en cuenta que los atributos en Shapefile suelen ser siempre en MAYÚSCULAS.
-m <nombre_archivo>
Especifica un archivo que contiene un conjunto de mapeos de nombres de columna (largos) a nombres de columna DBF de 10 caracteres. El contenido del archivo son una o más líneas de dos nombres separados por espacios en blanco y sin espacios al principio o al final:

NOMBREDELCOLUMNA CAMPO_DBF1\n
UNNOMBREDELCOLUMNAMUY LARGO CAMPO_DBF2\n

etc.

-i
Convierte todos los enteros a enteros estándar de 32 bits, no crea bigints de 64 bits, incluso si la firma del encabezado DBF parece garantizarlo.
-S
Genera geometrías simples en lugar de MULTIgeometrías. Los archivos Shape no diferencian entre LINESTRING y MULTILINESTRING, por lo que shp2pgsql genera MULTILINESTRING por defecto. Este interruptor producirá LINESTRINGs en su lugar, pero shp2pgsql fallará cuando encuentre un MULTILINESTRING real. Lo mismo ocurre con los POLYGONs frente a MULTIPOLYGONs.
-W <codificación>
Especifica la codificación de caracteres de los atributos de Shapefile. Si se utiliza esta opción, la salida se codificará en UTF-8.
-I
Crea un índice GiST en la columna de geometría.
-N <política>
Especifica la política de manejo de geometrías NULL (insertar, omitir, abortar).
-T <tablespace>
Especifica el tablespace para la nueva tabla. Los índices seguirán usando el tablespace por defecto a menos que también se use el parámetro -X. La documentación de PostgreSQL tiene una buena descripción sobre cuándo usar tablespaces personalizados.
-X <tablespace>
Especifica el tablespace para los índices de la nueva tabla. Esto se aplica al índice de clave primaria y al índice espacial GIST si también se usa -I.
-?
Muestra información de versión y uso.

INSTALACIÓN

Para compilar el programa desde el código fuente, simplemente ejecute "make" en el directorio fuente. Luego, copie el binario en su ruta de búsqueda de shell (o donde prefiera). Este texto también está disponible como una página de manual en el directorio ../doc/man/, listo para ser copiado en la ruta de búsqueda de manual en sistemas un*x.

EJEMPLOS

Una sesión de ejemplo usando el cargador para crear un archivo de entrada y cargarlo podría verse así:

# shp2pgsql shaperoads roadstable roadsdb > roads.sql
# psql -d roadsdb -f roads.sql

Una conversión y carga se pueden hacer todas en un solo paso usando tuberías de UNIX:

# shp2pgsql shaperoads roadstable roadsdb | psql -d roadsdb
