DESCRIPCIÓN

Las funciones SHA2 implementan el Estándar de Hash Seguro de NIST, FIPS PUB 180-2. Las funciones SHA2 se utilizan para generar una representación condensada de un mensaje llamada resumen de mensaje, adecuada para su uso como firma digital. Hay tres familias de funciones, con nombres que corresponden al número de bits en el resumen del mensaje resultante. Las funciones SHA-256 están limitadas a procesar un mensaje de menos de 2^64 bits como entrada. Las funciones SHA-384 y SHA-512 pueden procesar un mensaje de un máximo de 2^128 - 1 bits como entrada.

Las funciones SHA2 se consideran más seguras que las sha1(3) funciones con las que comparten una interfaz similar. Las variantes de 256, 384 y 512 bits de SHA2 comparten la misma interfaz. Por brevedad, solo se describen las variantes de 256 bits a continuación.

La función SHA256Init() inicializa un SHA2_CTX context para su uso con SHA256Update() y SHA256Final(). La función SHA256Update() agrega data de longitud len al SHA2_CTX especificado por context. SHA256Final() se llama cuando todos los datos se han agregado a través de SHA256Update() y almacena un resumen del mensaje en el parámetro digest.

La función SHA256Pad() se puede utilizar para aplicar el relleno al resumen del mensaje.

sha2(3) — SHA-2 hash functions

LIBRARY

libmd, −lcrypto

SYNOPSIS

A convenient interface to the SHA-2 hash functions is provided by SHA256Init(), SHA256Update(), and SHA256Final().

A more convenient interface is provided by SHA256End(), SHA256File(), SHA256FileChunk(), and SHA256Data(). These convenience functions may allocate memory which must be freed by the caller.

The following functions are available for SHA-224, SHA-256, SHA-384, and SHA-512:

typedef struct SHA2_CTX SHA2_CTX;

int SHA256_Init(SHA2_CTX *);
int SHA256_Update(SHA2_CTX *, const void *, size_t);
int SHA256_Final(uint8_t *, SHA2_CTX *);
char *SHA256_End(SHA2_CTX *, char *);
char *SHA256_File(const char *, char *);
char *SHA256_FileChunk(const char *, char *, off_t, off_t);
char *SHA256_Data(const void *, size_t, char *);

int SHA384_Init(SHA2_CTX *);
int SHA384_Update(SHA2_CTX *, const void *, size_t);
int SHA384_Final(uint8_t *, SHA2_CTX *);
char *SHA384_End(SHA2_CTX *, char *);
char *SHA384_File(const char *, char *);
char *SHA384_FileChunk(const char *, char *, off_t, off_t);
char *SHA384_Data(const void *, size_t, char *);

int SHA512_Init(SHA2_CTX *);
int SHA512_Update(SHA2_CTX *, const void *, size_t);
int SHA512_Final(uint8_t *, SHA2_CTX *);
char *SHA512_End(SHA2_CTX *, char *);
char *SHA512_File(const char *, char *);
char *SHA512_FileChunk(const char *, char *, off_t, off_t);
char *SHA512_Data(const void *, size_t, char *);

DESCRIPTION

The SHA-2 hash functions are cryptographic hash functions developed by the National Security Agency (NSA). The SHA-2 family consists of six hash functions with digests ranging from 224 to 512 bits:

  • SHA-224
  • SHA-256
  • SHA-384
  • SHA-512
  • SHA-512/224
  • SHA-512/256

The interface provided by SHA256Init(), SHA256Update(), and SHA256Final() is a standard interface for cryptographic hash functions.

The SHA256Init() function initializes a context structure ctx to use the SHA-256 algorithm.

The SHA256Update() function is called to process data which has length len bytes. This function can be called multiple times to process arbitrary length data.

The SHA256Final() function computes the message digest from the context ctx and stores it in the buf. The context ctx is not cleared after this call, and can be reused by calling SHA256Init() again, but the current context can still be used with SHA256Update().

The SHA256Transform() function is used by SHA256Update() to hash 512-bit blocks and forms the core of the algorithm. Most programs should use the interface provided by SHA256Init(), SHA256Update(), and SHA256Final() instead of calling SHA256Transform() directly.

The SHA256End() function is a front end for SHA256Final() which converts the digest into an ASCII representation of the digest in hexadecimal.

The SHA256File() function calculates the digest for a file and returns the result via SHA256End(). If SHA256File() is unable to open the file, a NULL pointer is returned.

SHA256FileChunk() behaves like SHA256File() but calculates the digest only for that portion of the file starting at offset and continuing for length bytes or until end of file is reached, whichever comes first. A zero length can be specified to read until end of file. A negative length or offset will be ignored.

The SHA256Data() function calculates the digest of an arbitrary string and returns the result via SHA256End().

For each of the SHA256End(), SHA256File(), SHA256FileChunk(), and SHA256Data() functions the buf parameter should either be a string large enough to hold the resulting digest (e.g. SHA256_DIGEST_STRING_LENGTH, SHA384_DIGEST_STRING_LENGTH, or SHA512_DIGEST_STRING_LENGTH, depending on the function being used) or a NULL pointer. In the latter case, space will be dynamically allocated via malloc(3) and should be freed using free(3) when it is no longer needed.

EXAMPLES

The following code fragment will calculate the SHA-256 digest for the string "abc", which is “0xba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad”.

SHA2_CTX ctx;
uint8_t results[SHA256_DIGEST_LENGTH];
char *buf;
int n;

buf = "abc";
n = strlen(buf);
SHA256Init(&ctx);
SHA256Update(&ctx, (uint8_t *)buf, n);
SHA256Final(results, &ctx);

/* Print the digest as one long hex value */
printf("0x");
for (n = 0; n < SHA256_DIGEST_LENGTH; n++)
	printf("%02x", results[n]);
putchar('\n');

Alternately, the helper functions could be used in the following way:

uint8_t output[SHA256_DIGEST_STRING_LENGTH];
char *buf = "abc";

printf("0x%s\n", SHA256Data(buf, strlen(buf), output));

AUTHORS

This implementation of the SHA functions was written by Aaron D. Gifford.

The SHA256End(), SHA256File(), SHA256FileChunk(), and SHA256Data() helper functions are derived from code written by Poul-Henning Kamp.

CAVEATS

This implementation of the Secure Hash Standard has not been validated by NIST and as such is not in official compliance with the standard.

If a message digest is to be copied to a multi-byte type (i.e. an array of 32-bit integers) it will be necessary to perform byte swapping on little endian machines such as the i386, alpha, and vax.
