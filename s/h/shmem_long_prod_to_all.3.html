DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) calculan una o más reducciones en arreglos simétricos en múltiples PEs virtuales. Una reducción realiza una operación binaria asociativa en un conjunto de valores. Para una lista de otras rutinas de reducción SHMEM, consulte intro_shmem(3).

Como con todas las rutinas colectivas SHMEM, cada una de estas rutinas asume que solo los PEs en el conjunto activo llaman a la rutina. Si un PE que no está en el conjunto activo llama a una rutina colectiva SHMEM, el resultado es indefinido.

El argumento nreduce determina el número de reducciones separadas a realizar. El arreglo fuente en todos los PEs del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en el arreglo destino en todos los PEs del conjunto activo. El conjunto activo se define por el triplete PE_start, logPE_stride, PE_size.

Los arreglos fuente y destino pueden ser el mismo arreglo, pero no pueden ser arreglos superpuestos.

Los argumentos son los siguientes:

target
Un arreglo simétrico de longitud nreduce elementos para recibir los resultados de las operaciones de reducción. El tipo de datos de target varía con la versión de la rutina de reducción que se llama y el idioma utilizado. Al llamar desde C/C++, consulte la sección RESUMEN para obtener información sobre los tipos de datos. Al llamar desde Fortran, los tipos de datos de destino son los siguientes:
shmem_comp4_prod_to_all: Complejo, con un tamaño de elemento igual a dos
Valores reales de 4 bytes.
shmem_comp8_prod_to_all: Complejo, con un tamaño de elemento igual a dos
Valores reales de 8 bytes.

shmem_int4_prod_to_all: Entero, con un tamaño de elemento de 4 bytes

shmem_int8_prod_to_all: Entero, con un tamaño de elemento de 8 bytes

shmem_real4_prod_to_all: Real, con un tamaño de elemento de 4 bytes

shmem_real8_prod_to_all: Real, con un tamaño de elemento de 8 bytes

shmem_real16_prod_to_all: Real, con un tamaño de elemento de 16 bytes

source
Un arreglo simétrico, de longitud nreduce elementos, que contiene un elemento para cada operación de reducción separada. El argumento source debe tener el mismo tipo de datos que target.
nreduce
El número de elementos en los arreglos target y source. nreduce debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero predeterminado.
PE_start
El número PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero predeterminado.
logPE_stride
El logaritmo (base 2) del paso entre números PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero predeterminado.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero predeterminado.
pWrk
Un arreglo de trabajo simétrico. El argumento pWrk debe tener el mismo tipo de datos que target. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Un arreglo de trabajo simétrico. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Si está usando Fortran, debe ser un valor entero predeterminado. Antes de que cualquiera de los PEs en el conjunto activo ingrese a la rutina de reducción, cada elemento de este arreglo debe ser inicializado con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran).

Los valores de los argumentos nreduce, PE_start, logPE_stride y PE_size deben ser iguales en todos los PEs del conjunto activo. Los mismos arreglos target y source, y los mismos arreglos de trabajo pWrk y pSync, deben pasarse a todos los PEs del conjunto activo. Antes de que cualquier PE llame a una rutina de reducción, debe asegurarse de que se cumplan las siguientes condiciones (la sincronización mediante una barrera u otro método a menudo es necesaria para garantizar esto): Los arreglos pWrk y pSync en todos los PEs del conjunto activo no están todavía en uso desde una llamada anterior a una rutina colectiva SHMEM. El arreglo target en todos los PEs del conjunto activo está listo para recibir los resultados de la reducción.

Al regresar de una rutina de reducción, lo siguiente es cierto para el PE local: El arreglo target se actualiza. Los valores en el arreglo pSync se restauran a los valores originales.

DESCRIPTION

These collective routines compute the product of elements of type long, across a specified set of processing elements (PEs).

The product operation is defined for the types shown in the SYNOPSIS.

The routines perform a reduction operation. A reduction operation is a two-step process. First, a reduction is performed across the PEs in the active set. Second, the result is broadcast to all PEs in the active set.

The set of PEs that participate in the reduction is specified by the arguments log_pe, skip, and stride.

All PEs in the active set must execute the reduction routine. Prologues and epilogues are not allowed.

The following arguments are common to all routines:

  • target: On input, this argument contains the local value to be included in the reduction. On output, this argument contains the result of the reduction.
  • source: This argument is not used for the shmem_prod and shmem_prod_inplace routines. For the others, it contains the value to be included in the reduction.
  • nlong: The number of long integers to be reduced.
  • pe: The PE to which the reduction is to be performed.
  • log_pe: If log_pe is 0, then all PEs in the symmetric transport set are included in the reduction. Otherwise, log_pe is the base 2 logarithm of the number of PEs in the symmetric transport set.
  • skip: The starting PE in the symmetric transport set.
  • stride: The stride between PEs in the symmetric transport set.
  • pwrk: This is a working memory array. The size of this array must be at least MAX(NR/2+1, SHMEM_REDUCE_MIN_WRKDATA_SIZE), where NR is the number of elements being reduced.
  • psync: This is a synchronization array. The size of this array must be SHMEM_REDUCE_SYNC_SIZE.

The reduction is performed with respect to the active set of PEs. The active set is determined by the arguments log_pe, skip, and stride. All PEs in the active set must participate in the reduction.

The shmem_prod and shmem_prod_inplace routines perform a reduction to a single PE. The PE to which the reduction is performed is specified by the argument pe.

The shmem_prod_to_all and shmem_long_prod_to_all routines perform a reduction across the active set of PEs and then broadcast the result to all PEs in the active set.

The shmem_prod_inplace routine is an optimization that can be used when the source and target arrays are the same.

NOTES

The psync array must be initialized to SHMEM_SYNC_VALUE before the first time it is used.

You must ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the product of the real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMP8_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

Example 2: Consider the following C/C++ call:

shmem_short_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_short_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_short_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_short_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
