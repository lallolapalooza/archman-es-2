shmem_quiet(3) - Espera la finalización de todas las escrituras remotas pendientes emitidas por un elemento de procesamiento (PE).

SINOPSIS

C o C++:

#include <mpp/shmem.h>
void shmem_quiet(void)

Fortran:

CALL SHMEM_QUIET

DESCRIPCIÓN

shmem_quiet asegura el orden de las operaciones de put (escritura remota). Se garantiza que todas las operaciones put emitidas a cualquier elemento de procesamiento (PE) antes de la llamada a shmem_quiet serán visibles para todos los demás PEs no más tarde que cualquier carga o almacenamiento de memoria posterior, put o get remotos, o operaciones de sincronización que sigan a la llamada a shmem_quiet.

NOTAS

shmem_quiet es más útil como una forma de asegurar el orden de entrega de varias operaciones de put. Por ejemplo, podrías usar shmem_quiet para esperar la entrega de un bloque de datos antes de emitir otro put, que establece una bandera de finalización en otro PE.
Normalmente, shmem_quiet no es necesario si se llaman shmem_barrier_all(3) o shmem_barrier(3). Las rutinas de barrera esperan la finalización de las escrituras remotas (puts) pendientes.

EJEMPLOS

PROGRAM COMPFLAG
  INCLUDE "mpp/shmem.fh"
  INTEGER FLAG_VAR, ARRAY(100), RECEIVER, SENDER
  COMMON/FLAG/FLAG_VAR
  COMMON/DATA/ARRAY
  INTRINSIC MY_PE
  FLAG_VAR = 0
  CALL SHMEM_BARRIER_ALL ! espera a que se inicialice FLAG_VAR
  SENDER = 0                        ! PE 0 envía los datos
  RECEIVER = 1                      ! PE 1 recibe los datos
  IF (MY_PE() .EQ. 0) THEN
    ARRAY = 33
    CALL SHMEM_PUT(ARRAY, ARRAY, 100, RECEIVER) ! inicia el envío de datos
    CALL SHMEM_QUIET                ! espera la entrega
    CALL SHMEM_PUT(FLAG_VAR, 1, 1, RECEIVER) ! envía la bandera de finalización
  ELSE IF (MY_PE() .EQ. RECEIVER) THEN
    CALL SHMEM_UDCFLUSH
    CALL SHMEM_WAIT(FLAG_VAR, 0)
    PRINT *,ARRAY                       ! ARRAY ha sido entregado
  ENDIF
END
