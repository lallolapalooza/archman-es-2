DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) calculan una o más reducciones en arrays simétricos en múltiples PEs virtuales. Una reducción realiza una operación binaria asociativa en un conjunto de valores. Para una lista de otras rutinas de reducción SHMEM, ver intro_shmem(3).

Como con todas las rutinas colectivas SHMEM, cada una de estas rutinas asume que solo los PEs en el conjunto activo llaman a la rutina. Si un PE que no está en el conjunto activo llama a una rutina colectiva SHMEM, el resultado es indefinido.

El argumento nreduce determina el número de reducciones separadas a realizar. El array fuente en todos los PEs del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en el array destino en todos los PEs del conjunto activo. El conjunto activo se define por el triplete PE_start, logPE_stride, PE_size.

Los arrays fuente y destino pueden ser el mismo array, pero no pueden ser arrays superpuestos.

Los argumentos son los siguientes:

target
Un array simétrico de longitud nreduce elementos para recibir los resultados de las operaciones de reducción. El tipo de dato de target varía con la versión de la rutina de reducción que se llama y el lenguaje utilizado. Al llamar desde C/C++, consulte la sección RESUMEN para obtener información sobre el tipo de dato. Al llamar desde Fortran, los tipos de datos de destino son los siguientes:
shmem_comp4_prod_to_all: Complejo, con un tamaño de elemento igual a dos
valores reales de 4 bytes.
shmem_comp8_prod_to_all: Complejo, con un tamaño de elemento igual a dos
valores reales de 8 bytes.

shmem_int4_prod_to_all: Entero, con un tamaño de elemento de 4 bytes

shmem_int8_prod_to_all: Entero, con un tamaño de elemento de 8 bytes

shmem_real4_prod_to_all: Real, con un tamaño de elemento de 4 bytes

shmem_real8_prod_to_all: Real, con un tamaño de elemento de 8 bytes

shmem_real16_prod_to_all: Real, con un tamaño de elemento de 16 bytes

source
Un array simétrico, de longitud nreduce elementos, que contiene un elemento para cada operación de reducción separada. El argumento fuente debe tener el mismo tipo de dato que target.
nreduce
El número de elementos en los arrays target y source. nreduce debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero predeterminado.
PE_start
El número de PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero predeterminado.
logPE_stride
El logaritmo (base 2) del paso entre números de PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero predeterminado.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero predeterminado.
pWrk
Un array de trabajo simétrico. El argumento pWrk debe tener el mismo tipo de dato que target. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Un array de trabajo simétrico. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Si está usando Fortran, debe ser un valor entero predeterminado. Antes de que cualquiera de los PEs en el conjunto activo entre en la rutina de reducción, cada elemento de este array debe ser inicializado con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran).

Los valores de los argumentos nreduce, PE_start, logPE_stride y PE_size deben ser iguales en todos los PEs del conjunto activo. Los mismos arrays target y source, y los mismos arrays de trabajo pWrk y pSync, deben ser pasados a todos los PEs del conjunto activo. Antes de que cualquier PE llame a una rutina de reducción, debe asegurarse de que se cumplan las siguientes condiciones (la sincronización mediante una barrera u otro método es a menudo necesaria para asegurar esto): Los arrays pWrk y pSync en todos los PEs del conjunto activo ya no están en uso desde una llamada anterior a una rutina colectiva SHMEM. El array target en todos los PEs del conjunto activo está listo para recibir los resultados de la reducción.

Al regresar de una rutina de reducción, lo siguiente es cierto para el PE local: El array target se actualiza. Los valores en el array pSync se restauran a los valores originales.

NOTAS

Los términos colectivo, simétrico y alineado en caché se definen en intro_shmem(3). Todas las rutinas de reducción SHMEM restablecen los valores en pSync antes de regresar, por lo que un buffer pSync en particular solo necesita ser inicializado la primera vez que se usa.

DESCRIPTION

The SHMEM reduction routines compute the product of elements of an array source and stores the result in the array target. All PEs in the group specified by pC (Fortran) or reduceSize (C/ C++) participate in the reduction. The reduction is performed on each corresponding element of the source and target arrays. For example, the first element of source is multiplied by the first element of target, and the result is stored in the first element of target.

The nreduce argument specifies the number of elements in the source and target arrays to be reduced.

The logPeOdd and logPeEven arguments specify the processor group participation in the reduction. logPeOdd is the log base 2 of the size of the odd-addressed PE group, and logPeEven is the log base 2 of the size of the even-addressed PE group. If an even-addressed PE is not participating in the reduction, its logPeEven value should be set to -1. Similarly, if an odd-addressed PE is not participating in the reduction, its logPeOdd value should be set to -1. reduceSize specifies the number of PE's that will participate in the reduction. This is an alternative to logPeOdd and logPeEven and is used to specify the size of the reduction group.

The pWrk argument is a pointer to a user-allocated symmetric working array. The size of this array is specified by SHMEM_REDUCE_MIN_WRKDATA_SIZE or MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE) in Fortran.

The pSync argument is a pointer to a user-allocated synchronization array. The size of this array is specified by SHMEM_REDUCE_SYNC_SIZE.

All elements of the pSync array must be initialized to the value SHMEM_SYNC_VALUE before the first call to a SHMEM reduction routine. The elements of the pSync array are used to synchronize the PEs during the reduction operation.

The specific reduction operation is determined by the function name:

  • shmem_short_prod_to_all: Product of short integers.

  • shmem_prod_to_all: Product of integers.

  • shmem_long_prod_to_all: Product of long integers.

  • shmem_real_prod_to_all: Product of single-precision real numbers.

  • shmem_double_prod_to_all: Product of double-precision real numbers.

  • shmem_comple_prod_to_all: Product of single-precision complex numbers.

  • shmem_dcomple_prod_to_all: Product of double-precision complex numbers.

NOTES

You must ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the product of the real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.h"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMP8_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

Example 2: Consider the following C/C++ call:

shmem_short_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_short_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_short_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_short_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
