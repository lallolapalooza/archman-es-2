sh2-elf-size(1)

Paquete: sh2-elf-binutils

Licencias: GPL

SIZE(1) Herramientas de desarrollo de GNU SIZE(1)

NOMBRE

size - lista los tamaños de sección y el tamaño total de archivos binarios

SINOPSIS

size [-A|-B|-G|--format=compatibilidad]
[--help]
[-d|-o|-x|--radix=número]
[--common]
[-t|--totals]
[--target=nombrebfd] [-V|--version]
[-f]
[archivoobj...]

DESCRIPCIÓN

La utilidad size de GNU lista los tamaños de sección y el tamaño total para cada uno de los archivos binarios archivoobj en su lista de argumentos. Por defecto, se genera una línea de salida por cada archivo o por cada módulo si el archivo es un archivo.

archivoobj... son los archivos a examinar. Si no se especifica ninguno, se utilizará el archivo "a.out" en su lugar.

OPCIONES

Las opciones de línea de comandos tienen los siguientes significados:

-A
-B
-G
--format=compatibilidad
Usando una de estas opciones, puede elegir si la salida de size de GNU se parece a la salida de size de System V (usando -A, o --format=sysv), o a la de size de Berkeley (usando -B, o --format=berkeley). El valor predeterminado es el formato de una línea similar al de Berkeley. Alternativamente, puede elegir la salida de formato GNU (usando -G, o --format=gnu), que es similar al formato de salida de Berkeley, pero los tamaños se cuentan de manera diferente.

Aquí hay un ejemplo del formato de salida de Berkeley (predeterminado) de size:

$ size --format=Berkeley ranlib size
   text    data     bss     dec     hex filename
 294880   81920   11592  388392   5ed28 ranlib
 294880   81920   11888  388688   5ee50 size

El estilo de salida de Berkeley cuenta los datos de solo lectura en la columna "text", no en la columna "data"; las columnas "dec" y "hex" muestran la suma de las columnas "text", "data" y "bss" en decimal y hexadecimal respectivamente.

El formato GNU cuenta los datos de solo lectura en la columna "data", no en la columna "text", y solo muestra la suma de las columnas "text", "data" y "bss" una vez, en la columna "total". La opción --radix puede ser utilizada para cambiar la base numérica de todas las columnas. Aquí están los mismos datos mostrados con convenciones GNU:

$ size --format=GNU ranlib size
      text       data        bss      total filename
    279880      96920      11592     388392 ranlib
    279880      96920      11888     388688 size

Estos son los mismos datos, pero mostrados más cerca de las convenciones de System V:

$ size --format=SysV ranlib size
ranlib  :
section         size         addr
.text         294880         8192
.data          81920       303104
.bss           11592       385024
Total         388392


size  :
section         size         addr
.text         294880         8192
.data          81920       303104
.bss           11888       385024
Total         388688
--help
-h
-H
-?
Mostrar un resumen de los argumentos y opciones aceptables.
-d
-o
-x
--radix=número
Usando una de estas opciones, puede controlar si el tamaño de cada sección se da en decimal (-d, o --radix=10); octal (-o, o --radix=8); o hexadecimal (-x, o --radix=16). En --radix=número, solo se admiten los tres valores (8, 10, 16). El tamaño total siempre se da en dos bases; decimal y hexadecimal para la salida -d o -x, u octal y hexadecimal si está usando -o.
--common
Imprimir el tamaño total de los símbolos comunes en cada archivo. Al usar el formato Berkeley o GNU, estos se incluyen en el tamaño bss.
-t
--totals
Mostrar totales de todos los objetos listados (solo en modo de formato Berkeley o GNU).
--target=nombrebfd
Especificar que el formato del código objeto de archivoobj es nombrebfd. Esta opción puede no ser necesaria; size puede reconocer automáticamente muchos formatos.
-v
-V
--version
Mostrar el número de versión de size.
-f
Ignorado. Esta opción es utilizada por otras versiones del programa size, pero no es compatible con la versión de GNU Binutils.
@archivo
Leer las opciones de línea de comandos de archivo. Las opciones leídas se insertan en lugar de la opción @archivo original. Si archivo no existe, o no se puede leer, la opción se tratará literalmente y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Un carácter de espacio en blanco puede incluirse en una opción rodeando la opción completa con comillas simples o dobles. Cualquier carácter (incluida una barra invertida) puede incluirse prefijando el carácter a incluir con una barra invertida. El archivo puede contener opciones adicionales de @archivo; dichas opciones se procesarán recursivamente.
