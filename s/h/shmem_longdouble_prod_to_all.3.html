DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) calculan una o más reducciones en arrays simétricos en múltiples PEs virtuales. Una reducción realiza una operación binaria asociativa en un conjunto de valores. Para una lista de otras rutinas de reducción SHMEM, consulte intro_shmem(3).

Al igual que con todas las rutinas colectivas SHMEM, cada una de estas rutinas asume que solo los PEs del conjunto activo llaman a la rutina. Si un PE que no está en el conjunto activo llama a una rutina colectiva SHMEM, el comportamiento resultante no está definido.

El argumento nreduce determina el número de reducciones separadas a realizar. El array fuente en todos los PEs del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en el array destino en todos los PEs del conjunto activo. El conjunto activo se define por el triplete PE_start, logPE_stride, PE_size.

Los arrays fuente y destino pueden ser el mismo array, pero no pueden ser arrays superpuestos.

Los argumentos son los siguientes:

target
Un array simétrico de longitud nreduce elementos para recibir los resultados de las operaciones de reducción. El tipo de datos de target varía con la versión de la rutina de reducción que se llama y el idioma utilizado. Al llamar desde C/C++, consulte la sección SINOPSIS para obtener información sobre tipos de datos. Al llamar desde Fortran, los tipos de datos de target son los siguientes:
shmem_comp4_prod_to_all: Complejo, con un tamaño de elemento igual a dos
valores reales de 4 bytes.
shmem_comp8_prod_to_all: Complejo, con un tamaño de elemento igual a dos
valores reales de 8 bytes.

shmem_int4_prod_to_all: Entero, con un tamaño de elemento de 4 bytes

shmem_int8_prod_to_all: Entero, con un tamaño de elemento de 8 bytes

shmem_real4_prod_to_all: Real, con un tamaño de elemento de 4 bytes

shmem_real8_prod_to_all: Real, con un tamaño de elemento de 8 bytes

shmem_real16_prod_to_all: Real, con un tamaño de elemento de 16 bytes

source
Un array simétrico, de longitud nreduce elementos, que contiene un elemento para cada operación de reducción separada. El argumento source debe tener el mismo tipo de datos que target.
nreduce
El número de elementos en los arrays target y source. nreduce debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
PE_start
El número de PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
logPE_stride
El logaritmo (base 2) del paso entre números de PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
pWrk
Un array de trabajo simétrico. El argumento pWrk debe tener el mismo tipo de datos que target. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Un array de trabajo simétrico. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Si está utilizando Fortran, debe ser un valor entero predeterminado. Antes de que alguno de los PEs del conjunto activo entre en la rutina de reducción, cada elemento de este array debe inicializarse con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran).

Los valores de los argumentos nreduce, PE_start, logPE_stride y PE_size deben ser iguales en todos los PEs del conjunto activo. Los mismos arrays target y source, y los mismos arrays de trabajo pWrk y pSync, deben pasarse a todos los PEs del conjunto activo. Antes de que cualquier PE llame a una rutina de reducción, debe asegurarse de que existen las siguientes condiciones (la sincronización mediante una barrera o algún otro método suele ser necesaria para garantizar esto): Los arrays pWrk y pSync en todos los PEs del conjunto activo ya no están en uso de una llamada anterior a una rutina colectiva SHMEM. El array target en todos los PEs del conjunto activo está listo para aceptar los resultados de la reducción.

Al regresar de una rutina de reducción, lo siguiente es cierto para el PE local: El array target se actualiza. Los valores en el array pSync se restauran a los valores originales.

DESCRIPCIÓN

Las rutinas de reducción SHMEM son rutinas colectivas que realizan una operación de reducción de puntos sobre un conjunto de procesadores (PEs). Las rutinas de reducción SHMEM son variaciones de las rutinas colectivas de reducción que se encuentran en la especificación MPI. El objetivo de estas rutinas es proporcionar una interfaz más sencilla para realizar operaciones de reducción comunes para aquellos usuarios que no necesitan todas las funciones de las rutinas colectivas de reducción de MPI.

La operación de reducción realiza una operación binaria en los datos proporcionados por cada PE en el conjunto activo. El resultado de esta operación binaria se combina entonces con el resultado de otros PEs en el conjunto activo hasta que el resultado final está disponible en un PE especificado o en todos los PEs.

Las rutinas de reducción SHMEM admiten las siguientes operaciones de reducción:

  • Suma: suma los valores.
  • Producto: multiplica los valores.
  • AND: realiza una operación AND bit a bit.
  • OR: realiza una operación OR bit a bit.
  • XOR: realiza una operación XOR bit a bit.
  • Min: encuentra el valor mínimo.
  • Max: encuentra el valor máximo.

Las rutinas de reducción SHMEM también admiten los siguientes tipos de datos:

  • Byte: caracteres de 8 bits.
  • Short: enteros cortos de 16 bits.
  • Int: enteros de 32 bits.
  • Long: enteros largos de 64 bits.
  • Float: números de punto flotante de 32 bits.
  • Double: números de punto flotante de 64 bits.
  • Long Double: números de punto flotante de 128 bits.

Las rutinas de reducción SHMEM se declaran como sigue:

Fortran:

CALL SHMEM_<TYPE>_<REDUCE_OP>_TO_ALL(TARGET, SOURCE, N, PE, LOGICAL_PE_STRIDE, PE_STRIDE, WRKDATA, PSYNC)

C/C++:

shmem_<TYPE>_<REDUCE_OP>_to_all(target, source, n, pe, logical_pe_stride, pe_stride, wrkdata, psync);
TARGET
Puntero a la matriz de destino donde se almacenará el resultado de la reducción.
SOURCE
Puntero a la matriz de origen que contiene los datos que se van a reducir.
N
Número de elementos en las matrices TARGET y SOURCE.
PE
PE raíz en el que se almacenará el resultado de la reducción. Si PE es SHMEM_BROADCAST_ROOT, el resultado se almacenará en todos los PEs.
LOGICAL_PE_STRIDE
El paso lógico entre los PEs que participan en la reducción. El PE 0 siempre está en el conjunto activo.
PE_STRIDE
El paso PE físico entre los PEs que participan en la reducción.
WRKDATA
Puntero a la matriz de trabajo utilizada para la reducción.
PSYNC
Puntero a la matriz de sincronización utilizada para la reducción.

NOTAS

La matriz pSync debe inicializarse antes de su uso. La matriz pWrk se utiliza como almacenamiento temporal durante la operación de reducción. Es posible que sea necesario inicializar la matriz pSync en tiempo de ejecución si no se inicializa estáticamente.

Debe asegurarse de que la matriz pSync no se esté actualizando en ningún PE del conjunto activo mientras alguno de los PE participa en el procesamiento de una rutina de reducción SHMEM. Tenga cuidado con las siguientes situaciones: Si la matriz pSync se inicializa en tiempo de ejecución, se necesita algún tipo de sincronización para garantizar que todos los PE del conjunto de trabajo hayan inicializado pSync antes de que alguno de ellos entre en una rutina SHMEM llamada con la matriz de sincronización pSync. Una matriz pSync o pWrk se puede reutilizar en una llamada posterior a la rutina de reducción solo si ninguno de los PE del conjunto activo todavía está procesando una llamada anterior a la rutina de reducción que utilizó las mismas matrices pSync o pWrk. En general, esto solo se puede garantizar realizando algún tipo de sincronización. Sin embargo, en el caso especial de las rutinas de reducción que se llaman con el mismo conjunto activo, puede asignar dos matrices pSync y pWrk y alternar entre ellas en llamadas sucesivas.

EJEMPLOS

Ejemplo 1: Este ejemplo de Fortran inicializa estáticamente la matriz pSync y encuentra el producto de la variable real FOO en todos los PEs pares.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMP8_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

Ejemplo 2: Considere la siguiente llamada C/C++:

shmem_short_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

La llamada anterior es más eficiente, pero semánticamente equivalente a, la combinación de las siguientes llamadas:

shmem_short_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_short_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_short_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Tenga en cuenta que se utilizan dos conjuntos de matrices pWrk y pSync alternativamente porque no se realiza ninguna sincronización entre llamadas.
