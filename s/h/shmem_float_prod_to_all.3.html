DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) calculan una o más reducciones en arrays simétricos en múltiples PEs virtuales. Una reducción realiza una operación binaria asociativa a través de un conjunto de valores. Para una lista de otras rutinas de reducción SHMEM, consulte intro_shmem(3).

Como con todas las rutinas colectivas de SHMEM, cada una de estas rutinas asume que solo los PEs en el conjunto activo llaman a la rutina. Si un PE que no está en el conjunto activo llama a una rutina colectiva de SHMEM, se produce un comportamiento indefinido.

El argumento nreduce determina el número de reducciones separadas a realizar. El array fuente en todos los PEs del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en el array destino en todos los PEs del conjunto activo. El conjunto activo se define por el triplete PE_start, logPE_stride, PE_size.

Los arrays fuente y destino pueden ser el mismo array, pero no pueden ser arrays superpuestos.

Los argumentos son los siguientes:

target
Un array simétrico de longitud nreduce elementos para recibir los resultados de las operaciones de reducción. El tipo de datos de target varía según la versión de la rutina de reducción que se llama y el lenguaje utilizado. Al llamar desde C/C++, consulte la sección SINOPSIS para obtener información sobre el tipo de datos. Al llamar desde Fortran, los tipos de datos de destino son los siguientes:
shmem_comp4_prod_to_all: Complejo, con un tamaño de elemento igual a dos
Valores reales de 4 bytes.
shmem_comp8_prod_to_all: Complejo, con un tamaño de elemento igual a dos
Valores reales de 8 bytes.

shmem_int4_prod_to_all: Entero, con un tamaño de elemento de 4 bytes

shmem_int8_prod_to_all: Entero, con un tamaño de elemento de 8 bytes

shmem_real4_prod_to_all: Real, con un tamaño de elemento de 4 bytes

shmem_real8_prod_to_all: Real, con un tamaño de elemento de 8 bytes

shmem_real16_prod_to_all: Real, con un tamaño de elemento de 16 bytes

source
Un array simétrico, de longitud nreduce elementos, que contiene un elemento para cada operación de reducción separada. El argumento source debe tener el mismo tipo de datos que target.
nreduce
El número de elementos en los arrays target y source. nreduce debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
PE_start
El número de PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
logPE_stride
El logaritmo (base 2) del paso entre números de PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
pWrk
Un array de trabajo simétrico. El argumento pWrk debe tener el mismo tipo de datos que target. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Un array de trabajo simétrico. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Si está usando Fortran, debe ser un valor entero por defecto. Antes de que cualquiera de los PEs del conjunto activo ingrese a la rutina de reducción, cada elemento de este array debe inicializarse con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran).

Los valores de los argumentos nreduce, PE_start, logPE_stride y PE_size deben ser iguales en todos los PEs del conjunto activo. Se deben pasar los mismos arrays target y source, y los mismos arrays de trabajo pWrk y pSync, a todos los PEs del conjunto activo. Antes de que cualquier PE llame a una rutina de reducción, debe asegurarse de que se cumplen las siguientes condiciones (la sincronización mediante una barrera u otro método a menudo es necesaria para asegurar esto): Los arrays pWrk y pSync en todos los PEs del conjunto activo ya no están en uso de una llamada anterior a una rutina colectiva de SHMEM. El array target en todos los PEs del conjunto activo está listo para aceptar los resultados de la reducción.

Al regresar de una rutina de reducción, lo siguiente es cierto para el PE local: El array target se actualiza. Los valores en el array pSync se restauran a los valores originales.

NOTAS

Los términos colectivo, simétrico y alineado en caché se definen en intro_shmem(3). Todas las rutinas de reducción de SHMEM restablecen los valores en pSync antes de devolverlos, por lo que un buffer pSync particular solo necesita ser inicializado

DESCRIPTION

DESCRIPTION

These collective routines compute the product of the elements in the source array (source) on the calling processing elements (PEs) and store the result in the target array (target) on all PEs. The product operation is defined for Fortran real, integer, and complex data types. It is defined for C/C++ double, float, int, long, long long, short, signed char, and complex data types. In addition, Fortran has specific routines for double complex and real (which is equivalent to float in C/C++).

The product is performed across a specified subset of PEs (an "active set"). All PEs in the program are implicitly part of the active set unless specified otherwise by the group argument.

The arguments are:

  • TARGET

    In Fortran, TARGET is a variable of the corresponding data type. In C/C++, TARGET is a pointer to the first element of the target array.

  • SOURCE

    In Fortran, SOURCE is a variable of the corresponding data type. In C/C++, SOURCE is a pointer to the first element of the source array.

  • NELEMS

    The number of elements in the source and target arrays.

  • START

    The starting PE number for the reduction operation.

  • STRIDE

    The stride between PE numbers for the reduction operation.

  • NTHREADS

    The number of threads to use for the reduction operation. This argument is ignored if SHMEM_NORACE is defined.

  • WRK

    In Fortran, WRK is an array of type LOGICAL. In C/C++, WRK is a pointer to a working buffer.

    The size of the WRK array depends on the data type and the number of elements being processed. The minimum size required is defined by SHMEM_REDUCE_MIN_WRKDATA_SIZE in Fortran, or calculated as follows in C/C++:

        (nelems / 2 + 1) * sizeof(data_type)

    where data_type is the data type of the target and source arrays.

  • SYNC

    In Fortran, SYNC is an array of type LOGICAL. In C/C++, SYNC is a pointer to a synchronization array.

    The size of the SYNC array is defined by SHMEM_REDUCE_SYNC_SIZE in Fortran, or by SHMEM_REDUCE_SYNC_SIZE in C/C++.

    The SYNC array must be initialized with the value SHMEM_SYNC_VALUE in Fortran, or SHMEM_SYNC_VALUE in C/C++ before the first call to a SHMEM reduction routine that uses it.

NOTES

NOTES

The active set is determined by the START, STRIDE, and NELEMS arguments. All PEs in the program are implicitly part of the active set unless specified otherwise by the group argument.

The pSync array is used for synchronization between reduction operations. It must be initialized before the first use of any SHMEM reduction routine. All PEs participating in the reduction must use the same pSync array.

The pWrk array is used for temporary storage during the reduction operation. It does not need to be initialized, but it must be the same size on all PEs participating in the reduction.

It is the user's responsibility to ensure that the pSync and pWrk arrays are not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations:

  • If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array.

  • A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the product of the real variable FOO across all the even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOPROD, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOPROD, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_COMP8_PROD_TO_ALL(FOOPROD, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOPROD
ENDIF

Example 2: Consider the following C/C++ call:

shmem_short_prod_to_all(target, source, 3, 0, 0, 8, pwrk, psync);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_short_prod_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_short_prod_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_short_prod_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
