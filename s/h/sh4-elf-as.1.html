-m32 | -m64
Selecciona el tamaño de palabra, ya sea de 32 bits o de 64 bits.
-EB | -EL
Selecciona la endianidad, ya sea big-endian (-EB) o little-endian (-EL).

La siguiente opción está disponible cuando as está configurado para un procesador Visium.

-mtune=arch
Esta opción especifica la arquitectura objetivo. Si se intenta ensamblar una instrucción que no se ejecutará en la arquitectura objetivo, el ensamblador emitirá un mensaje de error.

Se reconocen los siguientes nombres: "mcm24" "mcm" "gr5" "gr6"

Las siguientes opciones están disponibles cuando as está configurado para un procesador Xtensa.

--text-section-literals | --no-text-section-literals
Controla el tratamiento de los pools de literales. La predeterminada es --no-text-section-literals, que coloca los literales en secciones separadas en el archivo de salida. Esto permite colocar el pool de literales en una RAM/ROM de datos. Con --text-section-literals, los literales se intercalan en la sección de texto para mantenerlos lo más cerca posible de sus referencias. Esto puede ser necesario para archivos de ensamblaje grandes, donde los literales estarían fuera del rango de las instrucciones "L32R" en la sección de texto. Los literales se agrupan en pools siguiendo las directivas ".literal_position" o precediendo a las instrucciones "ENTRY". Estas opciones solo afectan a los literales referenciados a través de instrucciones "L32R" relativas a PC; los literales para instrucciones "L32R" en modo absoluto se manejan por separado.
--auto-litpools | --no-auto-litpools
Controla el tratamiento de los pools de literales. La predeterminada es --no-auto-litpools, que en ausencia de --text-section-literals coloca los literales en secciones separadas en el archivo de salida. Esto permite colocar el pool de literales en una RAM/ROM de datos. Con --auto-litpools, los literales se intercalan en la sección de texto para mantenerlos lo más cerca posible de sus referencias, no se requieren directivas explícitas de ".literal_position". Esto puede ser necesario para funciones muy grandes, donde un único pool de literales al principio de la función puede no ser alcanzable por las instrucciones "L32R" al final. Estas opciones solo afectan a los literales referenciados a través de instrucciones "L32R" relativas a PC; los literales para instrucciones "L32R" en modo absoluto se manejan por separado. Cuando se usa junto con --text-section-literals, --auto-litpools tiene precedencia.
--absolute-literals | --no-absolute-literals
Indica al ensamblador si las instrucciones "L32R" utilizan direccionamiento absoluto o relativo a PC. Si el procesador incluye la opción de direccionamiento absoluto, la predeterminada es utilizar reubicaciones "L32R" absolutas. De lo contrario, solo se pueden utilizar las reubicaciones "L32R" relativas a PC.
--target-align | --no-target-align
Habilita o deshabilita la alineación automática para reducir las penalizaciones de salto a expensas de un mayor tamaño de código. Esta optimización está habilitada por defecto. Ten en cuenta que el ensamblador siempre alineará instrucciones como "LOOP" que tienen requisitos de alineación fijos.

TARGET

DESCRIPTION

as

is the GNU assembler. It is a two-pass assembler, meaning that it reads the assembly code twice. During the first pass, it records the location of symbols and pseudo-operations. In the second pass, it generates the object code.

The as program supports the GNU assembler syntax for the target architecture. Most assemblers follow the syntax of the target architecture's native assembler, but as uses a common syntax for all architectures. Refer to the Texinfo documentation for a full description of the syntax.

The assembler can be invoked directly, or indirectly via the GNU compiler collection (gcc). When invoked via gcc, the compiler driver program determines the appropriate assembler options and invokes as automatically.

When as is invoked directly, it is given a list of input files and options on the command line. The assembler produces an object file for each input file. If no object file is specified using the -o option, the output file is named after the first input file, with its suffix changed from any suffix recognized by make to .o.

The assembler supports the following command line options:

-march=CPU[-EXT...][+EXT...]
Esta opción especifica el procesador de destino. El ensamblador emitirá un mensaje de error si se intenta ensamblar una instrucción que no se ejecutará en el procesador de destino. Se reconocen los siguientes nombres de procesador: "z80", "z180", "ez80", "gbz80", "z80n", "r800". Además del conjunto de instrucciones básico, se le puede indicar al ensamblador que acepte algunos mnemónicos de extensión. Por ejemplo, "-march=z180+sli+infc" extiende z180 con instrucciones SLI e IN F,(C). Las siguientes extensiones son compatibles actualmente: "full" (todas las instrucciones conocidas), "adl" (modo CPU ADL por defecto, solo eZ80), "sli" (instrucción conocida como SLI, SLL o SL1), "xyhl" (instrucciones con mitades de registros de índice: IXL, IXH, IYL, IYH), "xdcb" (instrucciones como RotOp (II+d),R y BitOp n,(II+d),R), "infc" (instrucción IN F,(C) o IN (C)), "outc0" (instrucción OUT (C),0). Tenga en cuenta que en lugar de extender un conjunto de instrucciones básico, los mnemónicos de extensión que comienzan con "-" revocar la funcionalidad respectiva: "-march=z80-full+xyhl" primero elimina todas las extensiones predeterminadas y agrega soporte solo para mitades de registros de índice.

Si esta opción no se especifica, se asume "-march=z80+xyhl+infc".
