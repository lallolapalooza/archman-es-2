shar(1) Comandos de usuario shar(1)

NOMBRE

shar - crear un archivo shell

SINOPSIS

shar [-flags] [-flag [valor]] [--nombre-opcion[[=| ]valor]] [<archivo>...]

Si no se especifican archivos, la lista de archivos de entrada se lee desde la entrada estándar. La entrada estándar no debe ser una terminal.

DESCRIPCIÓN

shar crea "archivos shell" (o archivos shar) que están en formato de texto y pueden ser enviados por correo electrónico. Estos archivos pueden ser desempaquetados más tarde ejecutándolos con /bin/sh. El archivo resultante se envía a la salida estándar a menos que se especifique la opción -o. Una amplia gama de características proporciona una gran flexibilidad en la fabricación de shars y en la especificación de la "inteligencia" de shar. Los archivos pueden ser bastante simples (--operacion-normal) o esencialmente un archivo tar envíable por correo.

Las opciones pueden especificarse en cualquier orden hasta que se reconozca un argumento archivo. Si se ha especificado la opción --tipo-mixto, se reconocerán más opciones de compresión y codificación entre los argumentos archivo.

Aunque este programa soporta archivos uuencode-d, están obsoletos. Si está enviando archivos por correo, considere los archivos codificados en mime. Si usa uuencode, base64 es el método de codificación preferido.

OPCIONES

Especificar compresión

-p, --tipo-mixto

especificar compresión para los archivos de entrada. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: operacion-normal.

Permitir opciones de parámetros posicionales. Las opciones de método de compresión y método de codificación pueden mezclarse con los nombres de archivo. Los archivos nombrados después de estas opciones se procesarán de la manera especificada.

-C programa, --compactador=programa

especificar programa de compactación (compresión). Esta opción puede aparecer un número ilimitado de veces. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: operacion-normal.

Los comandos de compactación gzip, bzip2 y compress pueden especificarse por el nombre del programa como el nombre de la opción, p.ej., --gzip. Esas opciones, sin embargo, están siendo obsoletas. Ahora también existe el compactador xz. Especifique xz con -C xz o --compactador=xz.


Especificar el compactador "none" deshabilitará la compresión de archivos. Los archivos comprimidos nunca se procesan como texto plano. Siempre se codifican con uuencode y el destinatario debe tener uudecode para desempaquetarlos.

Especificar el compactador compress está obsoleto.

-g nivel, --nivel-de-compresion=nivel

pasar NIVEL para compresión. Esta opción toma un número entero como argumento. El valor de nivel está restringido a estar: 
en el rango  1 a 9

El nivel por defecto para esta opción es:
9

Algunos programas de compresión permiten un nivel de compresión. El valor por defecto es 9, pero esta opción le permite especificar algo diferente. Este valor es utilizado por gzip, bzip2 y xz, pero no por compress.

-j, --bzip2

bzip2 y uuencode archivos. Esta opción puede aparecer un número ilimitado de veces.

Comprime con bzip2 y codifica con uuencode todos los archivos antes de empaquetarlos. El destinatario debe tener uudecode y bzip2 para poder desempaquetar.

Especificar metodología de codificación de archivos

Los archivos pueden almacenarse en el shar como texto plano o codificados con uuencode. Por defecto, el programa selecciona cuál examinando el archivo. Puede forzar la selección para todos los archivos. En modo de opciones/archivos mezclados, esta configuración puede cambiarse durante el procesamiento.

-M, --uuencode-mixto

decidir el uuencoding para cada archivo. Esta opción es un miembro de la clase de opciones mixed-uuencode.

Determinar automáticamente si los archivos son de texto o binarios y archivarlos correctamente. Los archivos que se encuentran como binarios se codifican con uuencode antes de empaquetarlos. Este es el comportamiento por defecto para shar.

Para que un archivo sea considerado un archivo de texto en lugar de un archivo binario, todas las siguientes condiciones deben ser ciertas:

El archivo no contiene ningún carácter de control ASCII aparte de BS (retroceso), HT (tabulador horizontal), LF (nueva línea) o FF (salto de página).

El archivo no contiene ningún carácter con su octavo bit establecido.

El archivo no contiene ninguna línea que comience con las cinco letras "from ", ya sea en mayúsculas o minúsculas. (Los programas de manejo de correo a menudo insertarán gratuitamente un carácter > antes de ella.)

El archivo está vacío o termina con un byte LF (nueva línea).

Ninguna línea del archivo contiene más de 200 caracteres. Para fines de conteo, las líneas se separan por un LF (nueva línea).

-B, --archivos-de-texto

tratar todos los archivos como binarios. Esta opción es un miembro de la clase de opciones mixed-uuencode.

Usar uuencode antes de empaquetar todos los archivos. Esto aumenta el tamaño del archivo. El destinatario debe tener uudecode para poder desempaquetar. Los archivos comprimidos siempre se codifican.

-T, --archivos-de-texto

tratar todos los archivos como texto. Esta opción es un miembro de la clase de opciones mixed-uuencode.

Si tiene archivos con bytes no ASCII o texto que algunos programas de manejo de correo no admiten, puede encontrar dificultades. Sin embargo, si está utilizando FTP o SSH/SCP, los archivos de texto no conformes deberían estar bien.

-l tamaño, --whole-size-limit=tamaño

dividir el archivo, no los archivos, a tamaño. Esta opción pertenece a la clase de opciones whole-size-limit. Esta opción debe aparecer en combinación con las siguientes opciones: output-prefix. Esta opción toma un número entero como argumento. El valor de tamaño está restringido a: 
en el rango  8 a 1023, o
en el rango  8192 a 4194304

Limita el tamaño del archivo de salida a tamaño bytes, pero no divide los archivos de entrada. Si tamaño es menor que 1024, se multiplicará por 1024. El valor también se puede especificar con un sufijo k, K, m o M. El número se multiplica entonces por 1000, 1024, 1000000 o 1048576, respectivamente. 4M (4194304) es el máximo permitido.

A diferencia de la opción split-size-limit, esta permite al destinatario de los archivos shar desempaquetarlos en cualquier orden.

-L tamaño, --split-size-limit=tamaño

dividir archivo o archivos a tamaño. Esta opción pertenece a la clase de opciones whole-size-limit. Esta opción debe aparecer en combinación con las siguientes opciones: output-prefix. Esta opción toma un número entero como argumento. El valor de tamaño está restringido a: 
en el rango  8 a 1023, o
en el rango  8192 a 4194304

Limita el tamaño del archivo de salida a tamaño bytes, dividiendo los archivos si es necesario. Los valores permitidos se especifican como con la opción --whole-size-limit.

Las partes del archivo creadas con esta opción deben ser desempaquetadas en el orden correcto. Si el destinatario de los archivos shell desea colocarlos todos en una única carpeta (archivo) de correo electrónico, deberán guardarse en el orden correcto para que unshar pueda desempaquetarlos todos a la vez (utilizando una de las opciones de archivo dividido). ver: Invocación de unshar.

-I archivo, --input-file-list=archivo

leer lista de archivos de un archivo.

Esta opción hace que se reabra archivo como entrada estándar. Si no se encuentran archivos en la línea de entrada, se leerá la entrada estándar para obtener los nombres de los archivos de entrada. El uso de esta opción prohibirá que los archivos de entrada se listen en la línea de comandos.

La entrada debe estar en un formato similar al generado por find, un nombre de archivo por línea. Este interruptor es especialmente útil cuando la línea de comandos no puede contener la lista de archivos a archivar.

Si se especifica la opción --intermix-type en la línea de comandos, entonces las opciones de compresión se pueden incluir en la entrada estándar en líneas por sí solas y ningún nombre de archivo puede comenzar con un guión.

Por ejemplo:

    { echo --compact xz
       find . -type f -print | sort
    } | shar -S -p -L50K -o /somewhere/big
-S, --stdin-file-list

leer lista de archivos desde la entrada estándar.

Esta opción es en realidad una operación nula. Es un envoltorio para --input-file-list=-.

Control de las cabeceras de shar

-n nombre, --archive-name=nombre

usar nombre para documentar el archivo.

Nombre del archivo a incluir en la cabecera del asunto de los archivos shar. Ver la opción --net-headers.

-s quién@dónde, --submitter=quién@dónde

anular el nombre del remitente.

shar normalmente determinará el nombre del remitente consultando al sistema. Use esta opción si se está haciendo en nombre de otro.

-a, --net-headers

emitir cabeceras Submitted-by: & Archive-name:. Esta opción debe aparecer en combinación con las siguientes opciones: archive-name.

Añade cabeceras de correo electrónico especializadas:

    Submitted-by: quién@@dónde
    Archive-name: nombre/part##
El quién@@dónde se deriva normalmente, pero se puede especificar con la opción --submitter. El nombre debe proporcionarse con la opción --archive-name. Si el nombre del archivo incluye un carácter de barra (/), entonces se omite /part##. Por lo tanto, -n xyzzy produce: 
    xyzzy/part01
    xyzzy/part02

mientras que -n xyzzy/patch produce:

    xyzzy/patch01
    xyzzy/patch02

    xyzzy/patch01.01
    xyzzy/patch01.02
-c, --cut-mark

iniciar el shar con una línea de corte.

Se coloca una línea que dice 'Corta aquí' al principio de cada archivo de salida.

-t, --translate

traducir mensajes en el script.

Traducir mensajes en el script. Si ha configurado la variable de entorno LANG, los mensajes impresos por shar estarán en el idioma especificado. El script producido seguirá emitiéndose utilizando mensajes en la lengua franca del mundo informático: el inglés. Esta opción hará que los mensajes del script aparezcan en los idiomas especificados por la variable de entorno LANG establecida cuando se produjo el script.

Protección contra problemas de transmisión

--no-character-count

no usar `wc -c' para comprobar el tamaño.

NO comprobar cada archivo con 'wc -c' después de desempaquetar. El valor predeterminado es comprobar.

-D, --no-md5-digest

no usar el resumen md5sum para verificar.

NO usar el resumen md5sum para verificar los archivos desempaquetados. El valor predeterminado es comprobar.

-F, --force-prefix

aplicar el carácter de prefijo en cada línea.

Fuerza a que el carácter de prefijo se anteponga a cada línea, incluso si no es necesario. Esta opción puede aumentar ligeramente el tamaño del archivo, especialmente si se utiliza --uuencode o una opción de compresión.

-d delimitador, --here-delimiter=delimitador

usar delimitador para delimitar los archivos. El delimitador predeterminado para esta opción es:
SHAR_EOF

Utiliza DELIMITADOR para delimitar los archivos en el shar en lugar de SHAR_EOF. Esto es para aquellos que quieren personalizar sus archivos shar. El delimitador siempre irá precedido y seguido de guiones bajos.

Creación de diferentes tipos de shars

-V, --vanilla-operation

crear shars muy simples.

Esta opción produce shars vanilla que solo dependen de la existencia de echo, test y sed en el entorno de desempaquetado.

Cambia el comportamiento predeterminado de modo mixto (--mixed-uuencode) a modo de texto (--text-files). Se producen advertencias si se especifican opciones que requieran descompresión o decodificación en el entorno de desempaquetado.

-P, --no-piping

usar archivos temporales entre programas.

En el archivo shar, utiliza un archivo temporal para mantener los contenidos de los archivos entre las etapas de desempaquetado en lugar de usar tuberías. Esta opción es obligatoria cuando se sabe que el desempaquetado se realizará en sistemas que no admiten tuberías.

-x, --no-check-existing

sobrescribir archivos existentes sin preguntar.

Crea el archivo de modo que, al ser procesado, sobrescribirá los archivos existentes sin preguntar primero. Si no se especifica esta opción ni la opción --query-user, el desempaquetado no sobrescribirá los archivos preexistentes. En todos los casos, sin embargo, si se pasa --cut-mark como parámetro al script al desempaquetar, los archivos existentes se sobrescribirán incondicionalmente.

    sh shar-archive-file -c
-X, --query-user

preguntar al usuario antes de sobrescribir archivos. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: vanilla-operation.

Al desempaquetar, preguntar interactivamente al usuario si se deben sobrescribir los archivos. No usar para shars enviados a la red.

El uso de esta opción produce shars que *causarán* problemas con algunos procedimientos de estilo unshar, particularmente cuando se usan junto con el modo vanilla (--vanilla-operation). Utilice esta función principalmente para archivos que se pasarán entre partes de acuerdo. Ciertamente, -X *no* es para archivos shell que se enviarán a Usenet u otras redes públicas.

El problema es que los programas o procedimientos unshar a menudo alimentan /bin/sh desde su entrada estándar, poniendo así /bin/sh y el script de archivo shell en competencia por las líneas de entrada. Como intento de aliviar este problema, shar intentará detectar si /dev/tty existe en el sitio receptor y lo utilizará para leer las respuestas del usuario. Pero esto no funciona en todos los casos, puede suceder que el usuario receptor tenga que evitar usar programas o procedimientos unshar, y llamar a /bin/sh directamente. En modo vanilla, ni siquiera se intenta usar /dev/tty.

OPTIONS

The following options are available:

-b, --no-timestamp

do not preserve original times.

Do not try to preserve the original modification times of files. By default, shar tries to make the shell archive contain information that will allow unshar to restore the original modification times of the files. This may not always be desirable. For example, when shar is used in automated build systems (like "make"), it is desirable that built files are timestamped after they are built. When this option is used, timestamps are NOT preserved, and programs like "make" will see built files older than the files they get built from. This is why, when this option is not used, a special effort is made to restore timestamps.

-Q, --quiet-unshar

avoid verbose messages at unshar time.

Verbose OFF. Disables the inclusion of comments to be output when the archive is unpacked.

-f, --basename

restore in one directory, despite hierarchy.

Restore by the base file name only, rather than path. This option causes only file names to be used, which is useful when building a shar from several directories, or another directory. Note that if a directory name is passed to shar, the substructure of that directory will be restored whether this option is specified or not.

Opciones de internacionalización

--no-i18n

do not internationalize.

No producir archivos shell internacionalizados, usar mensajes predeterminados en inglés. Por defecto, shar produce archivos que intentarán mostrar mensajes en el idioma preferido del descompresor (según lo determinado por las variables de entorno LANG/LC_MESSAGES) cuando se descompriman. Si no se encuentra ningún archivo de mensajes para el idioma del descompresor en el momento de la descompresión, los mensajes estarán en inglés.

--print-text-domain-dir

print directory with shar messages.

Imprime el directorio en el que shar busca los archivos de mensajes para diferentes idiomas, y luego sale inmediatamente.

ADVERTENCIAS

No se hace ningún intento de restaurar las protecciones y las fechas de modificación de los directorios, incluso si esto se hace por defecto para los archivos. Por lo tanto, si se le pasa un directorio a shar, la protección y las fechas de modificación del directorio descomprimido correspondiente pueden no coincidir con las del original.

Si se pasa un directorio a shar, puede ser escaneado más de una vez, para conservar memoria. Por lo tanto, no cambie el contenido del directorio mientras shar se está ejecutando.

Tenga cuidado de que los archivos de salida no se incluyan en las entradas, o shar puede entrar en un bucle hasta que el disco se llene. Tenga especial cuidado cuando se pasa un directorio a shar, para que los archivos de salida no estén en ese directorio o en un subdirectorio del mismo.

El uso de las opciones de compresión y codificación ralentizará el proceso de archivo, quizás considerablemente.

El uso de --query-user produce archivos shar que *causarán* problemas con muchos procedimientos de descompresión. Use esta función solo para archivos que se pasarán entre partes de mutuo acuerdo. Ciertamente, query-user NO es para archivos shell que se distribuirán por la red. El uso de compresión en archivos shar de red provocará que se le critiquen ferozmente. No usar las opciones --no-timestamp o --force-prefix también puede provocar quejas ocasionales. Ponga estas opciones en su archivo ~/.sharrc.
