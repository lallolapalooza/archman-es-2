SHARDS(1) Manual de Shards SHARDS(1)

NOMBRE

shards - gestor de dependencias para el lenguaje Crystal

SINOPSIS

shards [<opciones_generales>...] [<comando>] [<opciones_del_comando>...]

DESCRIPCIÓN

Gestiona las dependencias para proyectos y librerías de Crystal con instalaciones reproducibles en diferentes ordenadores y sistemas.

USO

shards requiere la presencia de un archivo shard.yml en la carpeta del proyecto (directorio de trabajo). Este archivo describe el proyecto y lista las dependencias necesarias para construirlo. Consulta shard.yml(5) para más información sobre su formato. Un archivo por defecto puede crearse ejecutando shards init.

Ejecutar shards install resuelve e instala las dependencias especificadas. Las versiones instaladas se escriben en un archivo shard.lock para usar las mismas versiones exactas de las dependencias al ejecutar shards install de nuevo.

Si tu shard construye una aplicación, tanto shard.yml como shard.lock deberían incluirse en el control de versiones para proporcionar instalaciones de dependencias reproducibles. Si es solo una librería para que otros shards dependan de ella, shard.lock *no* debería incluirse, solo shard.yml. Es una buena práctica añadirlo a .gitignore.

COMANDOS

Si no se proporciona ningún comando, el comando install se ejecutará por defecto.

Para ver las opciones disponibles para un comando particular, usa --help después del comando.

build [<objetivos>] [<opciones_de_compilación>...]

Compila los <objetivos> especificados en la ruta bin. Si no se especifican objetivos, se compilan todos. Este comando asegura que todas las dependencias estén instaladas, por lo que no es necesario ejecutar shards install antes.

Todas las <opciones_de_compilación> que sigan al comando se delegarán a crystal build.

check

Verifica que todas las dependencias estén instaladas y que los requisitos se cumplan.

Estado de salida:

0

Las dependencias se cumplen.

1

Las dependencias no se cumplen.

init

Inicializa un archivo shard.yml por defecto en la carpeta actual.

install [--frozen] [--without-development] [--production] [--skip-postinstall] [--skip-executables] [--jobs=N]

Resuelve e instala las dependencias en la carpeta lib. Si no existe, genera un archivo shard.lock a partir de las dependencias resueltas, fijando números de versión o commits de Git.

Lee y aplica las versiones fijadas y los commits si existe un archivo shard.lock. El comando install puede fallar si una versión fijada no coincide con un requisito, pero puede tener éxito si se agregó una nueva dependencia, siempre que no genere un conflicto, generando así un nuevo archivo shard.lock.

--frozen

Instala estrictamente las versiones fijadas desde shard.lock. Falla si shard.lock falta.

--without-development

No instala dependencias de desarrollo.

--production

igual que --frozen y --without-development

--skip-postinstall

No ejecuta la postinstalación de las dependencias.

--skip-executables

No instala ejecutables.

--jobs

Número de descargas de repositorios a realizar en paralelo (por defecto: 8). Actualmente solo para git.

list [--tree]

Lista las dependencias instaladas y sus versiones.

Especificar --tree organiza las dependencias anidadas en un árbol, en lugar de una lista plana.

lock [--update [<shards>...]]

Resuelve las dependencias y crea o actualiza el archivo shard.lock según el comando install, pero nunca instala las dependencias.

Especificar --update sigue la misma semántica que el comando update.

outdated [--pre]

Lista las dependencias que están desactualizadas.

Cuando se especifica --pre, también se consideran las versiones de pre-lanzamiento.

prune

Elimina las dependencias no utilizadas de la carpeta lib.

update [<shards>...]

Resuelve y actualiza todas las dependencias en la carpeta lib, independientemente de las versiones fijadas en el archivo shard.lock. Eventualmente genera un nuevo archivo shard.lock.

Especificar shards actualizará solo estas dependencias, intentando ser lo más conservador posible con otras dependencias, respetando las versiones fijadas en el archivo shard.lock.

version [<ruta>]

Imprime la versión actual del shard ubicado en ruta (por defecto el directorio actual).

Para ver las opciones disponibles para un comando particular, usa --help después de un comando.

OPCIONES GENERALES

--version

Imprime la versión de shards.

-h, --help

Imprime la sintaxis de uso.

--no-color

Deshabilita la salida con colores.

--local

No actualiza la caché del repositorio remoto. En su lugar, Shards utilizará las copias locales ya presentes en la caché (ver SHARDS_CACHE_PATH). El comando fallará si una dependencia no está disponible en la caché.

-q, --quiet

Disminuye la verbosidad del registro, imprimiendo solo advertencias y errores.

-v, --verbose

Aumenta la verbosidad del registro, imprimiendo todas las declaraciones de depuración.

INSTALACIÓN

Shards suele distribuirse con Crystal. Alternativamente, un paquete separado de shards puede estar disponible para tu sistema.

Para instalar desde el código fuente, descarga o clona el repositorio https://github.com/crystal-lang/shards y ejecuta make CRFLAGS=--release. El binario compilado está en bin/shards y debería añadirse a PATH.

VARIABLES DE ENTORNO

SHARDS_OPTS

Permite pasar opciones generales como variable de entorno. Ejemplo: SHARDS_OPTS="--no-color" shards update

SHARDS_CACHE_PATH

Define la ubicación de la caché. En esta carpeta, shards almacena copias locales de repositorios remotos. Por defecto es .cache/shards en el directorio de inicio ($XDG_CACHE_HOME o $HOME) o en el directorio actual.

SHARDS_INSTALL_PATH

Define la ubicación donde se instalan las dependencias. Por defecto es lib.

SHARDS_BIN_PATH

Define la ubicación donde se instalan los ejecutables. Por defecto es bin.

CRYSTAL_VERSION

Define la versión de Crystal para la que se deben resolver las dependencias. Por defecto es la salida de crystal env CRYSTAL_VERSION.

SHARDS_OVERRIDE

Define una ubicación alternativa para shard.override.yml.

ARCHIVOS

shard.yml

Describe un proyecto de shard incluyendo sus dependencias. Ver shard.yml(5) para la documentación.

shard.override.yml

Permite sobrescribir la fuente y la restricción de las dependencias. Una ubicación alternativa puede configurarse con la variable de entorno SHARDS_OVERRIDE.

El archivo contiene un documento YAML con una única clave dependencies. Tiene la misma semántica que en shard.yml. La configuración de dependencias tiene prioridad sobre la configuración en shard.yml o en el shard.yml de cualquier dependencia.

Los casos de uso son copias de trabajo locales, forzar una versión específica de una dependencia a pesar de las restricciones incompatibles, corregir una dependen

shard.lock

Archivo de bloqueo que almacena información sobre las versiones instaladas.

Si tu shard compila una aplicación, shard.lock debe ser gestionado en el control de versiones para proporcionar instalaciones de dependencias reproducibles.

Si solo es una biblioteca para que otros shards dependan de ella, shard.lock no debe ser gestionado, solo shard.yml. Es un buen consejo añadirlo a .gitignore.
