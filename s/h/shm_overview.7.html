NOMBRE

shm_overview - descripción general de la memoria compartida POSIX

DESCRIPCIÓN

La API de memoria compartida POSIX permite a los procesos comunicar información compartiendo una región de memoria.

Las interfaces empleadas en la API son:

shm_open(3)
Crear y abrir un nuevo objeto, o abrir un objeto existente. Esto es análogo a open(2). La llamada devuelve un descriptor de archivo para su uso por las otras interfaces listadas a continuación.
ftruncate(2)
Establecer el tamaño del objeto de memoria compartida. (Un objeto de memoria compartida recién creado tiene una longitud de cero).
mmap(2)
Mapear el objeto de memoria compartida en el espacio de direcciones virtual del proceso que llama.
munmap(2)
Desmapear el objeto de memoria compartida del espacio de direcciones virtual del proceso que llama.
shm_unlink(3)
Eliminar un nombre de objeto de memoria compartida.
close(2)
Cerrar el descriptor de archivo asignado por shm_open(3) cuando ya no se necesite.
fstat(2)
Obtener una estructura stat que describe el objeto de memoria compartida. Entre la información devuelta por esta llamada se encuentran el tamaño del objeto (st_size), los permisos (st_mode), el propietario (st_uid) y el grupo (st_gid).
fchown(2)
Para cambiar la propiedad de un objeto de memoria compartida.
fchmod(2)
Para cambiar los permisos de un objeto de memoria compartida.

Versiones

La memoria compartida POSIX es compatible desde Linux 2.4 y glibc 2.2.

Persistencia

Los objetos de memoria compartida POSIX tienen persistencia en el kernel: un objeto de memoria compartida existirá hasta que el sistema se apague, o hasta que todos los procesos hayan desmapeado el objeto y este haya sido eliminado con shm_unlink(3).

Enlace

Los programas que utilicen la API de memoria compartida POSIX deben compilarse con cc -lrt para enlazar con la biblioteca de tiempo real, librt.

Acceso a objetos de memoria compartida a través del sistema de archivos

En Linux, los objetos de memoria compartida se crean en un sistema de archivos virtual (tmpfs(5)), normalmente montado bajo /dev/shm. Desde Linux 2.6.19, Linux soporta el uso de listas de control de acceso (ACLs) para controlar los permisos de los objetos en el sistema de archivos virtual.

NOTAS

Típicamente, los procesos deben sincronizar su acceso a un objeto de memoria compartida, utilizando, por ejemplo, semáforos POSIX.

La memoria compartida System V (shmget(2), shmop(2), etc.) es una API de memoria compartida más antigua. La memoria compartida POSIX proporciona una interfaz más simple y mejor diseñada; por otro lado, la memoria compartida POSIX está algo menos disponible (especialmente en sistemas antiguos) que la memoria compartida System V.
