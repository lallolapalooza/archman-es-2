shmctl(2) Manual de llamadas al sistema shmctl(2)

NOMBRE

shmctl - control de memoria compartida System V

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/shm.h>
int shmctl(int shmid, int op, struct shmid_ds *buf);

DESCRIPCIÓN

shmctl() realiza la operación de control especificada por op en el segmento de memoria compartida System V cuyo identificador se proporciona en shmid.

El argumento buf es un puntero a una estructura shmid_ds, definida en <sys/shm.h> de la siguiente manera:


struct shmid_ds {
    struct ipc_perm shm_perm;    /* Propiedad y permisos */
    size_t          shm_segsz;   /* Tamaño del segmento (bytes) */
    time_t          shm_atime;   /* Hora del último adjunto */
    time_t          shm_dtime;   /* Hora del último desadjunto */
    time_t          shm_ctime;   /* Hora de creación/última
                                    modificación mediante shmctl() */
    pid_t           shm_cpid;    /* PID del creador */
    pid_t           shm_lpid;    /* PID del último shmat(2)/shmdt(2) */
    shmatt_t        shm_nattch;  /* Nº de adjuntos actuales */
    ...
};

Los campos de la estructura shmid_ds son los siguientes:

shm_perm
Esta es una estructura ipc_perm (ver más abajo) que especifica los permisos de acceso al segmento de memoria compartida.
shm_segsz
Tamaño en bytes del segmento de memoria compartida.
shm_atime
Hora de la última llamada al sistema shmat(2) que adjuntó este segmento.
shm_dtime
Hora de la última llamada al sistema shmdt(2) que desadjuntó este segmento.
shm_ctime
Hora de creación del segmento o hora de la última operación IPC_SET de shmctl().
shm_cpid
ID del proceso que creó el segmento de memoria compartida.
shm_lpid
ID del último proceso que ejecutó una llamada al sistema shmat(2) o shmdt(2) en este segmento.
shm_nattch
Número de procesos que tienen este segmento adjunto.

La estructura ipc_perm se define de la siguiente manera (los campos resaltados se pueden establecer usando IPC_SET):


struct ipc_perm {
    key_t          __key;    /* Clave proporcionada a shmget(2) */
    uid_t          uid;      /* UID efectivo del propietario */
    gid_t          gid;      /* GID efectivo del propietario */
    uid_t          cuid;     /* UID efectivo del creador */
    gid_t          cgid;     /* GID efectivo del creador */
    unsigned short mode;     /* Permisos + flags SHM_DEST y
                                SHM_LOCKED */
    unsigned short __seq;    /* Número de secuencia */
};

Los 9 bits menos significativos del campo mode de la estructura ipc_perm definen los permisos de acceso para el segmento de memoria compartida. Los bits de permiso son los siguientes:

0400 Lectura por usuario
0200 Escritura por usuario
0040 Lectura por grupo
0020 Escritura por grupo
0004 Lectura por otros
0002 Escritura por otros

Los bits 0100, 0010 y 0001 (los bits de ejecución) no son utilizados por el sistema. (No es necesario tener permiso de ejecución en un segmento para realizar una llamada a shmat(2) con el flag SHM_EXEC.)

Los valores válidos para op son:

IPC_STAT
Copia la información de la estructura de datos del kernel asociada con shmid a la estructura shmid_ds apuntada por buf. El llamante debe tener permiso de lectura en el segmento de memoria compartida.
IPC_SET
Escribe los valores de algunos miembros de la estructura shmid_ds apuntada por buf en la estructura de datos del kernel asociada con este segmento de memoria compartida, actualizando también su miembro shm_ctime.
Se actualizan los siguientes campos: shm_perm.uid, shm_perm.gid, y (los 9 bits menos significativos de) shm_perm.mode.
El UID efectivo del proceso llamante debe coincidir con el propietario (shm_perm.uid) o creador (shm_perm.cuid) del segmento de memoria compartida, o el llamante debe tener privilegios.
IPC_RMID
Marca el segmento para ser destruido. El segmento se destruirá realmente solo después de que el último proceso lo desadjunte (es decir, cuando el miembro shm_nattch de la estructura asociada shmid_ds sea cero). El llamante debe ser el propietario o creador del segmento, o tener privilegios. El argumento buf se ignora.
Si un segmento ha sido marcado para destrucción, entonces el flag (no estándar) SHM_DEST del campo shm_perm.mode en la estructura de datos asociada recuperada por IPC_STAT se establecerá.
El llamante *debe* asegurarse de que un segmento sea destruido eventualmente; de lo contrario, sus páginas que se cargaron de forma "fault" permanecerán en memoria o en swap.
Ver también la descripción de /proc/sys/kernel/shm_rmid_forced en proc(5).
IPC_INFO (específico de Linux)
Devuelve información sobre los límites y parámetros globales del sistema de memoria compartida en la estructura apuntada por buf. Esta estructura es de tipo shminfo (por lo tanto, se requiere una conversión), definida en <sys/shm.h> si se define el macro de prueba de funcionalidad _GNU_SOURCE:

struct shminfo {
    unsigned long shmmax; /* Tamaño máximo del segmento */
    unsigned long shmmin; /* Tamaño mínimo del segmento;
                             siempre 1 */
    unsigned long shmmni; /* Número máximo de segmentos */
    unsigned long shmseg; /* Número máximo de segmentos
                             que un proceso puede adjuntar;
                             no utilizado dentro del kernel */
    unsigned long shmall; /* Número máximo de páginas de
                             memoria compartida, en todo el sistema */
};

Los ajustes shmmni, shmmax y shmall se pueden cambiar a través de archivos /proc con el mismo nombre; ver proc(5) para detalles.
SHM_INFO (específico de Linux)
Devuelve una estructura shm_info cuyos campos contienen información sobre los recursos del sistema consumidos por la memoria compartida. Esta estructura se define en <sys/shm.h> si se define el macro de prueba de funcionalidad _GNU_SOURCE:

struct shm_info {
    int           used_ids; /* Nº de segmentos existentes
                               actualmente */
    unsigned long shm_tot;  /* Número total de páginas de
                               memoria compartida */
    unsigned long shm_rss;  /* Nº de páginas de memoria compartida
                               residentes */
    unsigned long shm_swp;  /* Nº de páginas de memoria compartida
                               en swap */
    unsigned long swap_attempts;
                            /* No utilizado desde Linux 2.4 */
    unsigned long swap_successes;
                            /* No utilizado desde Linux 2.4 */
};

SHM_STAT (específico de Linux)
Devuelve una estructura shmid_ds como para IPC_STAT. Sin embargo, el argumento shmid no es un identificador de segmento, sino un índice en el array interno del kernel que mantiene información sobre todos los segmentos de memoria compartida del sistema.

DESCRIPCIÓN

El comando cmd especifica la operación que se va a realizar en el segmento de memoria compartida identificado por shmid.

IPC_STAT
Copia la información de estado sobre el segmento de memoria compartida en la estructura shmid_ds a la que apunta buf.
IPC_SET
Establece los valores de los campos shm_perm.uid, shm_perm.gid y shm_perm.mode de la estructura shmid_ds del segmento de memoria compartida a los valores de los campos correspondientes en la estructura a la que apunta buf. Solo el superusuario o un proceso con la capacidad CAP_SYS_ADMIN puede cambiar el propietario o el grupo. Solo el propietario o el superusuario pueden cambiar los bits de modo. Solo se pueden cambiar los bits de modo que no sean fijos por la implementación. La llamada actual shmctl(2) no permite cambiar ningún campo de modo. Esta operación solo está disponible para versiones de Linux posteriores a la 2.2.
IPC_RMID
Marca el segmento de memoria compartida para su eliminación. El sistema eliminará el segmento y su estructura asociada tan pronto como el último proceso se desvincule de él (ver shmdt(2)). El valor del campo shm_perm.nattch para el segmento será incrementado por el sistema, y se decrementará cuando un proceso se desvincule. La eliminación es permanente una vez que se marca. El propietario o el superusuario pueden realizar esta operación. Consulte también shmop(2) para obtener más información sobre el comportamiento de la eliminación.
SHM_INFO (Since Linux 2.3.10)
Devuelve información sobre todos los segmentos de memoria compartida en el sistema. El valor de shmid se ignora. El argumento buf debe apuntar a una estructura shminfo (definida en <sys/ipc.h>), que contendrá el número máximo de segmentos de memoria compartida en el sistema (en el campo shmmni) y el número máximo de bytes permitidos para un segmento (en el campo shmmax).
SHM_STAT (Linux-specific)
Devuelve una estructura shmid_ds como para IPC_STAT. Sin embargo, shmid se interpreta como un índice en la matriz interna del kernel de segmentos de memoria compartida, en lugar de un ID de segmento.
SHM_STAT_ANY (Linux-specific, since Linux 4.17)
Devuelve una estructura shmid_ds como para SHM_STAT. Sin embargo, shm_perm.mode no se comprueba para acceso de lectura para shmid, lo que significa que cualquier usuario puede emplear esta operación (al igual que cualquier usuario puede leer /proc/sysvipc/shm para obtener la misma información).

El llamante puede evitar o permitir la paginación de un segmento de memoria compartida con los siguientes valores op:

SHM_LOCK (Linux-specific)
Evita la paginación del segmento de memoria compartida. El llamante debe cargar en memoria todas las páginas que se requieran para estar presentes después de que el bloqueo esté habilitado. Si un segmento ha sido bloqueado, entonces la bandera (no estándar) SHM_LOCKED del campo shm_perm.mode en la estructura de datos asociada recuperada por IPC_STAT se establecerá.
SHM_UNLOCK (Linux-specific)
Desbloquea el segmento, permitiendo que sea paginado.

Antes de Linux 2.6.10, solo un proceso privilegiado podía emplear SHM_LOCK y SHM_UNLOCK. Desde Linux 2.6.10, un proceso no privilegiado puede emplear estas operaciones si su UID efectivo coincide con el UID propietario o creador del segmento, y (para SHM_LOCK) la cantidad de memoria a bloquear cae dentro del límite de recursos RLIMIT_MEMLOCK (ver setrlimit(2)).

VALOR DE RETORNO

Una operación exitosa IPC_INFO o SHM_INFO devuelve el índice de la entrada más alta utilizada en la matriz interna del kernel que registra información sobre todos los segmentos de memoria compartida. (Esta información se puede usar con operaciones repetidas SHM_STAT o SHM_STAT_ANY para obtener información sobre todos los segmentos de memoria compartida en el sistema). Una operación exitosa SHM_STAT devuelve el identificador del segmento de memoria compartida cuyo índice se dio en shmid. Otras operaciones devuelven 0 si tienen éxito.

En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EACCES
Se solicita IPC_STAT o SHM_STAT y shm_perm.mode no permite el acceso de lectura para shmid, y el proceso que llama no tiene la capacidad CAP_IPC_OWNER en el espacio de nombres de usuario que rige su espacio de nombres IPC.
EFAULT
El argumento op tiene el valor IPC_SET o IPC_STAT pero la dirección apuntada por buf no es accesible.
EIDRM
shmid apunta a un identificador eliminado.
EINVAL
shmid no es un identificador válido, o op no es una operación válida. O: para una operación SHM_STAT o SHM_STAT_ANY, el valor del índice especificado en shmid se refirió a una ranura de matriz que actualmente no está en uso.
ENOMEM
(Desde Linux 2.6.9), se especificó SHM_LOCK y el tamaño del segmento a bloquear significaría que los bytes totales en segmentos de memoria compartida bloqueados excederían el límite para el ID de usuario real del proceso que llama. Este límite se define por el límite de recursos blandos RLIMIT_MEMLOCK (ver setrlimit(2)).
EOVERFLOW
Se intenta IPC_STAT, y el valor GID o UID es demasiado grande para ser almacenado en la estructura apuntada por buf.
EPERM
Se intenta IPC_SET o IPC_RMID, y el ID de usuario efectivo del proceso que llama no es el del creador (encontrado en shm_perm.cuid), o el propietario (encontrado en shm_perm.uid), y el proceso no tenía privilegios (Linux: no tenía la capacidad CAP_SYS_ADMIN).
O (antes de Linux 2.6.9), se especificó SHM_LOCK o SHM_UNLOCK, pero el proceso no tenía privilegios (Linux: no tenía la capacidad CAP_IPC_LOCK). (Desde Linux 2.6.9, este error también puede ocurrir si RLIMIT_MEMLOCK es 0 y el llamante no tiene privilegios.)

VERSIONES

Linux permite a un proceso adjuntar (shmat(2)) un segmento de memoria compartida que ya ha sido marcado para su eliminación usando shmctl(IPC_RMID). Esta característica no está disponible en otras implementaciones de UNIX; las aplicaciones portátiles deben evitar depender de ella.

ESTANDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, SVr4.

Varios campos en una struct shmid_ds estaban tipificados como short en Linux 2.2 y se han convertido en long en Linux 2.4. Para aprovechar esto, una recompilación bajo glibc-2.1.91 o posterior debería ser suficiente. (El kernel distingue llamadas antiguas y nuevas por una bandera IPC_64 en op.)

NOTAS

Las operaciones IPC_INFO, SHM_STAT y SHM_INFO son utilizadas por el programa ipcs(1) para proporcionar información sobre los recursos asignados. En el futuro, estas pueden ser modificadas o trasladadas a una interfaz del sistema de archivos /proc.
