DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) calculan una o más reducciones en arreglos simétricos en múltiples PEs virtuales. Una reducción realiza una operación binaria asociativa en un conjunto de valores. Para una lista de otras rutinas de reducción de SHMEM, consulte intro_shmem(3).

Al igual que con todas las rutinas colectivas de SHMEM, cada una de estas rutinas asume que solo los PEs del conjunto activo llaman a la rutina. Si un PE que no está en el conjunto activo llama a una rutina colectiva de SHMEM, el resultado es indefinido.

El argumento nreduce determina el número de reducciones separadas a realizar. El arreglo fuente en todos los PEs del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en el arreglo destino en todos los PEs del conjunto activo. El conjunto activo se define por el triplete PE_start, logPE_stride, PE_size.

Los arreglos fuente y destino pueden ser el mismo arreglo, pero no pueden ser arreglos superpuestos.

Los argumentos son los siguientes:

target
Un arreglo simétrico de longitud nreduce elementos para recibir los resultados de las operaciones de reducción. El tipo de dato de target varía con la versión de la rutina de reducción que se llama. Al llamar desde C/C++, consulte la sección RESUMEN para obtener información sobre los tipos de datos. Al llamar desde Fortran, los tipos de datos destino son los siguientes:

shmem_int4_min_to_all: Entero, con un tamaño de elemento de 4 bytes

shmem_int8_min_to_all: Entero, con un tamaño de elemento de 8 bytes

shmem_real4_min_to_all: Real, con un tamaño de elemento de 4 bytes

shmem_real8_min_to_all: Real, con un tamaño de elemento de 8 bytes

shmem_real16_min_to_all: Real, con un tamaño de elemento de 16 bytes

source Un arreglo simétrico: de longitud nreduce elementos, que contiene un
elemento para cada operación de reducción separada. El argumento fuente debe tener el mismo tipo de dato que target.
nreduce
El número de elementos en los arreglos destino y fuente. nreduce debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
PE_start
El número de PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
logPE_stride
El logaritmo (base 2) del paso entre números de PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
pWrk
Un arreglo de trabajo simétrico. El argumento pWrk debe tener el mismo tipo de dato que target. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Un arreglo de trabajo simétrico. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Si está utilizando Fortran, debe ser un valor entero predeterminado. Cada elemento de este arreglo debe inicializarse con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran) antes de que cualquiera de los PEs del conjunto activo entre en la rutina de reducción.

Los valores de los argumentos nreduce, PE_start, logPE_stride y PE_size deben ser iguales en todos los PEs del conjunto activo. Los mismos arreglos destino y fuente, y los mismos arreglos de trabajo pWrk y pSync, deben pasarse a todos los PEs del conjunto activo.

Antes de que cualquier PE llame a una rutina de reducción, debe asegurarse de que se cumplan las siguientes condiciones (a menudo se necesita sincronización mediante una barrera u otro método para garantizar esto): Los arreglos pWrk y pSync en todos los PEs del conjunto activo ya no están en uso desde una llamada anterior a una rutina colectiva de SHMEM. El arreglo destino en todos los PEs del conjunto activo está listo para aceptar los resultados de la reducción.

Al regresar de una rutina de reducción, se aplican lo siguiente al PE local: El arreglo destino se actualiza. Los valores en el arreglo pSync se restauran a los valores originales.

NOTAS

Los términos colectivo, simétrico y alineado en caché se definen en intro_shmem(3). Todas las rutinas de reducción de SHMEM restauran los valores en pSync antes de devolverlos, por lo que un arreglo pSync particular solo necesita inicializarse la primera vez que se utiliza.

Debe asegurarse de que el arreglo pSync no esté siendo actualizado en ningún PE del conjunto activo mientras alguno de los PEs participa en el procesamiento de una rutina de reducción de SHMEM. Tenga cuidado con las siguientes situaciones: Si el arreglo pSync se inicializa en tiempo de ejecución, se necesita algún tipo de sincronización para asegurar que todos los PEs del conjunto de trabajo hayan inicializado pSync antes de que alguno de ellos entre en una rutina de SHMEM llamada con el arreglo de sincronización pSync. Un arreglo pSync o pWrk puede reutilizarse en una llamada posterior a la rutina de reducción solo si ninguno de los PEs del conjunto activo todavía está procesando una llamada anterior a la rutina de reducción que utilizó los mismos arreglos pSync o pWrk. En general, esto solo se puede garantizar mediante algún tipo de sincronización. Sin embargo, en el caso especial de las rutinas de reducción llamadas con el mismo conjunto activo, puede asignar dos arreglos pSync y pWrk y alternar entre ellos en llamadas sucesivas.

DESCRIPTION

These symmetric reductions compute the element-wise minimum of source elements from a specified set of processing elements (PEs) and places the result in the target element on all participating PEs. The reduction operation is only performed on PEs that are part of the specified reduction group.

The set of PEs participating in the reduction is determined by PE_start, logPE_stride, and PE_size.

  • target: The target element on the local PE where the result will be stored. For Fortran, this is the result of the reduction. For C/C++, the value of the target variable is preserved for other PEs. For complex numbers, target_real and target_imag are used to specify the real and imaginary parts.

  • source: The source element on the local PE. For Fortran, this is the input value for the reduction. For C/C++, the value of the source variable is used for the reduction. For complex numbers, source_real and source_imag are used.

  • nreduce: The number of elements to reduce. This corresponds to the number of elements in the source and target arrays.

  • PE_start: The first PE in the reduction group. If PE_start is negative, it is assumed to be MY_PE() + PE_start.

  • logPE_stride: The log base 2 of the stride between PEs in the reduction group. A logPE_stride of 0 means that consecutive PEs are used.

  • PE_size: The number of PEs in the reduction group. If PE_size is negative, it is assumed to be 2^logPE_stride.

  • pWrk: A pointer to a working array. The size of this array depends on the collective operation and the number of PEs. The minimum required size is determined by the compile-time constant SHMEM_REDUCE_MIN_WRKDATA_SIZE. This array must be aligned to an 8-byte boundary.

  • pSync: A pointer to a synchronization array. This array must be the size of SHMEM_REDUCE_SYNC_SIZE and initialized with SHMEM_SYNC_VALUE. This argument is optional and is provided in C/C++ interfaces only. If this argument is not provided, an internal synchronization array is used.

The reduction is performed over the PEs specified by PE_start, logPE_stride, and PE_size. The nreduce elements from the source on each participating PE are reduced using the minimum operation. The result is placed in the corresponding target element on all participating PEs.

The shmem_complexd_min_to_all and shmem_complexf_min_to_all functions operate on complex numbers represented by their real and imaginary parts.

The Fortran interfaces are simplified and assume that the reduction is performed on all PEs (PE_start=0, logPE_stride=0, PE_size=-1).

NOTES

The shmem_*_min_to_all routines are symmetric, meaning that each PE must call the routine.

The pWrk and pSync arguments must be of the correct type and size for the specific reduction operation.

The synchronization array pSync is used to ensure that all PEs have completed the reduction operation before proceeding. If the pSync argument is omitted in the C/C++ interface, Open MPI provides an internal synchronization mechanism.

For Fortran, the pWrk array is passed implicitly and its size is determined by the compiler based on the SHMEM_REDUCE_MIN_WRKDATA_SIZE macro.

The PE_size parameter can be used to perform reductions on a subset of PEs. For example, to perform a reduction on even-numbered PEs, one could set PE_start = 0, logPE_stride = 1, and PE_size = num_pes()/2.

EXAMPLES

Example 1: Fortran code to find the minimum value of FOO across all even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOMIN, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOMIN, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_REAL8_MIN_TO_ALL(FOOMIN, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOMIN
ENDIF

Example 2: Consider the following C/C++ call:

shmem_int_min_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_int_min_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_min_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_min_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Note that two sets of pWrk and pSync arrays are used alternately because no synchronization is done between calls.
