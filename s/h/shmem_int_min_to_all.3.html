DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) computan una o más reducciones a través de arreglos simétricos en múltiples PEs virtuales. Una reducción realiza una operación binaria asociativa a través de un conjunto de valores. Para una lista de otras rutinas de reducción de SHMEM, ver intro_shmem(3).

Como con todas las rutinas colectivas de SHMEM, cada una de estas rutinas asume que solo los PEs en el conjunto activo llaman a la rutina. Si un PE que no está en el conjunto activo llama a una rutina colectiva de SHMEM, el resultado es indefinido.

El argumento nreduce determina el número de reducciones separadas a realizar. El arreglo fuente en todos los PEs del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en el arreglo objetivo en todos los PEs del conjunto activo. El conjunto activo se define por el trío PE_start, logPE_stride, PE_size.

Los arreglos fuente y objetivo pueden ser el mismo arreglo, pero no pueden ser arreglos superpuestos.

Los argumentos son los siguientes:

objetivo
Un arreglo simétrico de longitud nreduce elementos para recibir los resultados de las operaciones de reducción. El tipo de datos del objetivo varía con la versión de la rutina de reducción que se está llamando. Al llamar desde C/C++, consulte la sección SINOPSIS para obtener información sobre el tipo de datos. Al llamar desde Fortran, los tipos de datos objetivo son los siguientes:

shmem_int4_min_to_all: Entero, con un tamaño de elemento de 4 bytes

shmem_int8_min_to_all: Entero, con un tamaño de elemento de 8 bytes

shmem_real4_min_to_all: Real, con un tamaño de elemento de 4 bytes

shmem_real8_min_to_all: Real, con un tamaño de elemento de 8 bytes

shmem_real16_min_to_all: Real, con un tamaño de elemento de 16 bytes

fuente Un arreglo simétrico: de longitud nreduce elementos, que contiene un
elemento para cada operación de reducción separada. El argumento fuente debe tener el mismo tipo de datos que el objetivo.
nreduce
El número de elementos en los arreglos objetivo y fuente. nreduce debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
PE_start
El número PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
logPE_stride
El logaritmo (base 2) del paso entre números PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está usando Fortran, debe ser un valor entero por defecto.
pWrk
Un arreglo de trabajo simétrico. El argumento pWrk debe tener el mismo tipo de datos que el objetivo. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Un arreglo de trabajo simétrico. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Si está usando Fortran, debe ser un valor entero por defecto. Cada elemento de este arreglo debe inicializarse con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran) antes de que cualquiera de los PEs en el conjunto activo entre en la rutina de reducción.

Los valores de los argumentos nreduce, PE_start, logPE_stride y PE_size deben ser iguales en todos los PEs del conjunto activo. Los mismos arreglos objetivo y fuente, y los mismos arreglos de trabajo pWrk y pSync, deben pasarse a todos los PEs del conjunto activo.

Antes de que cualquier PE llame a una rutina de reducción, debe asegurarse de que se cumplan las siguientes condiciones (la sincronización mediante una barrera u otro método a menudo es necesaria para asegurar esto): Los arreglos pWrk y pSync en todos los PEs del conjunto activo no estén todavía en uso de una llamada anterior a una rutina colectiva de SHMEM. El arreglo objetivo en todos los PEs del conjunto activo esté listo para aceptar los resultados de la reducción.

Al regresar de una rutina de reducción, lo siguiente es cierto para el PE local: El arreglo objetivo se actualiza. Los valores en el arreglo pSync se restauran a los valores originales.

NOTAS

Los términos colectivo, simétrico y alineado en caché se definen en intro_shmem(3). Todas las rutinas de reducción de SHMEM restablecen los valores en pSync antes de devolverlos, por lo que un búfer pSync particular solo necesita inicializarse la primera vez que se usa.

Debe asegurarse de que el arreglo pSync no esté siendo actualizado en ningún PE del conjunto activo mientras cualquiera de los PEs participa en el procesamiento de una rutina de reducción de SHMEM. Tenga cuidado con las siguientes situaciones: Si el arreglo pSync se inicializa en tiempo de ejecución, se necesita algún tipo de sincronización para asegurar que todos los PEs del conjunto de trabajo hayan inicializado pSync antes de que alguno de ellos entre en una rutina de SHMEM llamada con el arreglo de sincronización pSync. Un arreglo pSync o pWrk puede reutilizarse en una llamada de rutina de reducción posterior solo si ninguno de los PEs del conjunto activo todavía está procesando una llamada de rutina de reducción anterior que utilizó los mismos arreglos pSync o pWrk. En general, esto solo se puede garantizar mediante algún tipo de sincronización. Sin embargo, en el caso especial de rutinas de reducción que se llaman con el mismo conjunto activo, puede asignar dos arreglos pSync y pWrk y alternar entre ellos en llamadas sucesivas.

EJEMPLOS

Ejemplo 1: Este ejemplo de Fortran inicializa estáticamente el arreglo pSync

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

y encuentra el valor mínimo de la variable real FOO en todos los PEs pares.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOMIN, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOMIN, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_REAL8_MIN_TO_ALL(FOOMIN, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOMIN
ENDIF

Ejemplo 2: Considere la siguiente llamada C/C++:

shmem_int_min_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

La llamada anterior es más eficiente, pero semánticamente equivalente a, la combinación de las siguientes llamadas:

shmem_int_min_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_min_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_min_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);

Tenga en cuenta que se utilizan dos conjuntos de arrays pWrk y pSync alternativamente porque no se realiza ninguna sincronización entre las llamadas.
