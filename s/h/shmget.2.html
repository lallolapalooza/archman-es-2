shmget(2) Manual de llamadas al sistema shmget(2)

NOMBRE

shmget - asigna un segmento de memoria compartida del Sistema V

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/shm.h>
int shmget(key_t key, size_t size, int shmflg);

DESCRIPCIÓN

shmget() devuelve el identificador del segmento de memoria compartida del Sistema V asociado al valor del argumento key. Puede ser utilizado tanto para obtener el identificador de un segmento de memoria compartida previamente creado (cuando shmflg es cero y key no tiene el valor IPC_PRIVATE), como para crear un nuevo conjunto.

Se crea un nuevo segmento de memoria compartida, con un tamaño igual al valor de size redondeado al múltiplo más cercano de PAGE_SIZE, si key tiene el valor IPC_PRIVATE o key no es IPC_PRIVATE, no existe ningún segmento de memoria compartida correspondiente a key, y IPC_CREAT está especificado en shmflg.

Si shmflg especifica tanto IPC_CREAT como IPC_EXCL y ya existe un segmento de memoria compartida para key, entonces shmget() falla con errno establecido a EEXIST. (Esto es análogo al efecto de la combinación O_CREAT | O_EXCL para open(2)).

El valor shmflg se compone de:

IPC_CREAT
Crea un nuevo segmento. Si no se usa esta bandera, shmget() encontrará el segmento asociado a key y verificará si el usuario tiene permiso para acceder al segmento.
IPC_EXCL
Esta bandera se usa con IPC_CREAT para asegurar que esta llamada cree el segmento. Si el segmento ya existe, la llamada falla.
SHM_HUGETLB (desde Linux 2.6)
Asigna el segmento usando páginas "grandes" (huge pages). Vea el archivo fuente del kernel de Linux Documentation/admin-guide/mm/hugetlbpage.rst para más información.
SHM_HUGE_2MB
SHM_HUGE_1GB (desde Linux 3.8)
Usado en conjunto con SHM_HUGETLB para seleccionar tamaños de página hugetlb alternativos (respectivamente, 2 MB y 1 GB) en sistemas que admiten múltiples tamaños de página hugetlb.
Más generalmente, el tamaño de página hugetlb deseado puede configurarse codificando el logaritmo en base 2 del tamaño de página deseado en los seis bits en el desplazamiento SHM_HUGE_SHIFT. Por lo tanto, las dos constantes anteriores se definen como:

#define SHM_HUGE_2MB    (21 << SHM_HUGE_SHIFT)
#define SHM_HUGE_1GB    (30 << SHM_HUGE_SHIFT)

Para algunos detalles adicionales, vea la discusión de las constantes con nombre similar en mmap(2).
SHM_NORESERVE (desde Linux 2.6.15)
Esta bandera cumple el mismo propósito que la bandera MAP_NORESERVE de mmap(2). No reserve espacio de intercambio (swap) para este segmento. Cuando se reserva espacio de intercambio, se tiene la garantía de que es posible modificar el segmento. Cuando no se reserva espacio de intercambio, se podría recibir una SIGSEGV al escribir si no hay memoria física disponible. Vea también la discusión del archivo /proc/sys/vm/overcommit_memory en proc_sys_vm(5).

Además de las banderas anteriores, los 9 bits menos significativos de shmflg especifican los permisos otorgados al propietario, al grupo y a otros. Estos bits tienen el mismo formato y el mismo significado que el argumento mode de open(2). Actualmente, los permisos de ejecución no son utilizados por el sistema.

Cuando se crea un nuevo segmento de memoria compartida, su contenido se inicializa a cero y su estructura de datos asociada, shmid_ds (ver shmctl(2)), se inicializa de la siguiente manera:

•
shm_perm.cuid y shm_perm.uid se establecen al ID de usuario efectivo del proceso llamante.
•
shm_perm.cgid y shm_perm.gid se establecen al ID de grupo efectivo del proceso llamante.
•
Los 9 bits menos significativos de shm_perm.mode se establecen al bit menos significativo de 9 bits de shmflg.
•
shm_segsz se establece al valor de size.
•
shm_lpid, shm_nattch, shm_atime y shm_dtime se establecen a 0.
•
shm_ctime se establece a la hora actual.

Si el segmento de memoria compartida ya existe, se verifican los permisos y se comprueba si está marcado para su destrucción.

VALOR DE RETORNO

En caso de éxito, se devuelve un identificador de memoria compartida válido. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EACCES
El usuario no tiene permiso para acceder al segmento de memoria compartida y no tiene la capacidad CAP_IPC_OWNER en el espacio de nombres del usuario que rige su espacio de nombres IPC.
EEXIST
Se especificaron IPC_CREAT y IPC_EXCL en shmflg, pero ya existe un segmento de memoria compartida para key.
EINVAL
Se iba a crear un nuevo segmento y size es menor que SHMMIN o mayor que SHMMAX.
EINVAL
Existe un segmento para la key dada, pero size es mayor que el tamaño de dicho segmento.
ENFILE
Se ha alcanzado el límite de archivos abiertos en todo el sistema.
ENOENT
No existe un segmento para la key dada y no se especificó IPC_CREAT.
ENOMEM
No se pudo asignar memoria para la sobrecarga del segmento.
ENOSPC
Se han agotado todos los identificadores de memoria compartida posibles (SHMMNI), o la asignación de un segmento del tamaño solicitado provocaría que el sistema excediera el límite global del sistema de memoria compartida (SHMALL).
EPERM
Se especificó la bandera SHM_HUGETLB, pero el llamante no tenía privilegios (no tenía la capacidad CAP_IPC_LOCK) y no es miembro del grupo hugetlb_shm_group; vea la descripción de /proc/sys/vm/hugetlb_shm_group en proc_sys_vm(5).

ESTANDARES

POSIX.1-2024.

SHM_HUGETLB y SHM_NORESERVE son extensiones de Linux.

HISTORIA

POSIX.1-2001, SVr4.

NOTAS

IPC_PRIVATE no es un campo de bandera sino un tipo key_t. Si se usa este valor especial para key, la llamada al sistema ignora todos los bits excepto los 9 bits menos significativos de shmflg y crea un nuevo segmento de memoria compartida.

Límites de memoria compartida

Los siguientes límites en los recursos de los segmentos de memoria compartida afectan a la llamada shmget():

SHMALL
Límite global del sistema de mem
