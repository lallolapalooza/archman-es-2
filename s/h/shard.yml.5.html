shard.yml(5)

SHARD.YML(5) Formatos de archivo SHARD.YML(5)

NOMBRE

shard.yml - metadatos para proyectos gestionados por shards(1)

DESCRIPCIÓN

El archivo shard.yml es un archivo YAML con metadatos sobre un proyecto gestionado por shards, conocido como un shard. Debe contener al menos los atributos name y version, además de atributos adicionales opcionales.

Tanto las bibliotecas como las aplicaciones se beneficiarán de shard.yml.

Se espera que los metadatos de las bibliotecas tengan más información (por ejemplo, lista de autores, descripción, licencia) que las aplicaciones, que pueden tener solo un nombre, versión y dependencias.

FORMATO

El archivo debe llamarse shard.yml y ser un archivo YAML válido con codificación UTF-8. No debe contener atributos duplicados en ninguna mapeo. Debe usar una indentación de 2 espacios. No debe usar características YAML avanzadas, solo mapeos simples, secuencias y cadenas (Esquema a prueba de fallos).

ATRIBUTOS REQUERIDOS

name

El nombre del proyecto (cadena, requerido).
•Debe ser único.
•Debe tener 50 caracteres o menos.
•Debe estar en minúsculas (a-z).
•No debe contener crystal.
•Puede contener dígitos (0-9) pero no empezar con uno.
•Puede contener guiones bajos o guiones, pero no empezar/terminar con uno.
•No debe tener guiones bajos o guiones consecutivos.

Ejemplos: minitest, mysql2, battery-horse.

version

El número de versión del proyecto (cadena, requerido).
•Debe contener dígitos.
•Puede contener puntos y guiones, pero no consecutivos.
•Puede contener una letra para convertirla en una 'pre-release'.

Ejemplos: 1.2.3, 2.0.0.1, 1.0.0.alpha 2.0.0-rc1 o 2016.09.

Aunque Shards no lo impone, se recomienda encarecidamente seguir un esquema de versionado racional como Versionado Semántico http://semver.org/ o Versionado de Calendario http://calver.org/.

ATRIBUTOS OPCIONALES

authors

Una lista de autores, junto con su correo electrónico de contacto (opcional) (secuencia de cadenas).
•Cada autor debe tener un nombre.
•Cada autor puede tener una dirección de correo electrónico, dentro de corchetes angulares (caracteres < y >).

Ejemplo:

authors:
- Ary
- Julien Portalier <julien@example.org>

crystal

Una restricción para indicar qué versiones de crystal son compatibles. Esto normalmente expresará restricciones de límite inferior y superior (cadena, recomendado).

Al resolver dependencias, esta información no se utiliza. Después de determinar las dependencias, shards verifica que todas ellas funcionen con la versión actual de crystal. Si no es así, aparece una advertencia para las dependencias que lo causan. Las versiones resueltas se instalan y se pueden usar bajo su propio riesgo.

Los valores válidos son en su mayoría los mismos que para dependencies.version:

•Un número de versión prefijado por un operador: <, <=, >, >=, != o ~>.
•Simplemente "*" si cualquier versión sirve (este es el valor predeterminado si no se especifica).
•Se pueden separar varios requisitos por comas.

Existe un comportamiento especial heredado (su uso está desaconsejado) cuando solo se utiliza un número de versión como valor: funciona exactamente igual que una verificación >=: x.y.z se interpreta como ">= x.y.z"

Le invitamos a especificar también el límite superior para que sea inferior a la próxima (futura) versión principal de Crystal, ya que no hay garantía de que no rompa su biblioteca.

Ejemplo:

crystal: ">= 0.35, < 2.0"

dependencies

Una lista de dependencias requeridas (mapeo).

Cada dependencia comienza con el nombre de la dependencia como clave (cadena), luego una lista de atributos (mapeo) que dependen del tipo de resolver.

Ejemplo:

dependencies:
  minitest:
    github: ysbaddaden/minitest.cr
    version: 0.1.0

development_dependencies

Una lista de dependencias requeridas para trabajar en el proyecto, pero no necesarias para construir y ejecutar el proyecto (mapeo).

Se instalarán para el proyecto principal o la biblioteca en sí. Cuando la biblioteca se instala como dependencia para otro proyecto, las dependencias de desarrollo nunca se instalarán.

Las dependencias de desarrollo siguen el mismo esquema que las dependencias.

Ejemplo:

development_dependencies:
  minitest:
    github: ysbaddaden/minitest.cr
    version: ~> 0.1.3

description

Una descripción en una sola línea del proyecto (cadena, recomendado).

documentation

La URL de un sitio web que proporciona la documentación del proyecto para navegación en línea (cadena).

executables

Una lista de ejecutables que se instalarán (secuencia).

Los ejecutables pueden ser de cualquier tipo o idioma (por ejemplo, shell, binario, ruby), deben existir en la carpeta bin del Shard y tener el bit de ejecutable establecido (en plataformas POSIX). Cuando se instalan como dependencia para otro proyecto, los ejecutables se copiarán a la carpeta bin de ese proyecto.

Los ejecutables siempre se instalan al final, después de ejecutar el script postinstall, para que las bibliotecas puedan compilar los ejecutables cuando sean instalados por Shards. La instalación se puede deshabilitar pasando la opción --skip-executables.

Ejemplo:

executables:
- micrate
- icr

homepage

La URL de la página principal del repositorio canónico del proyecto (cadena).

libraries

Una lista de bibliotecas compartidas a las que el shard intenta enlazar (mapeo).

Este campo es puramente informativo. Sirve como una forma canónica de descubrir dependencias no-Crystal en shards, tanto para herramientas como para humanos.

Un shard solo debe listar las bibliotecas a las que enlaza directamente, no debe incluir bibliotecas que solo son referenciadas por dependencias. Debe incluir todas las bibliotecas a las que enlaza directamente, independientemente de si una dependencia también lo hace.

Debe mapear desde el soname sin ninguna extensión, ruta o versión, por ejemplo libsqlite3 para /usr/lib/libsqlite3.so.0.8.6, a una restricción de versión.

La restricción de versión tiene el siguiente formato:

•Puede ser un número de versión.
•Puede ser "*" si cualquier versión sirve.
•El número de versión puede ir prefijado por un operador: <, <=, >, >=, != o ~>.
libraries:
  libQt5Gui: "*"
  libQt5Help: "~> 5.7"
  libQtBus: ">= 4.8"

license

Una expresión de licencia SPDX https://spdx.github.io/spdx-spec/v3.0.1/annexes/spdx-license-expressions/ o una URL a un archivo de licencia (cadena, recomendado).

La OSI publica una lista https://opensource.org/licenses-old/category de licencias de código abierto y sus identificadores SPDX correspondientes.

Ejemplos: Apache-2.0, GPL-3.0-or-later, Apache-2.0 OR MIT, Apache-2.0 WITH Swift-exception, https://example.com/LICENSE.

repository

La URL del repositorio canónico del proyecto (cadena, recomendado).

La URL debe ser compatible con herramientas VCS típicas sin modif

Shards will then install the latest tagged version (or HEAD if no tagged version available). * The version number may be prefixed by an operator: `<`, `<=`, `>`, `>=`, `!=` or `~>`. * Multiple requirements can be separated by commas. .PP Examples: `1.2.3`, `>= 1.0.0`, `>= 1.0.0, < 2.0` or `~> 2.0`. .PP Most of the version operators, like `>= 1.0.0`, are self-explanatory, but the `~>` operator has a special meaning. SHARD.YML(5)

SHARD.YML es el archivo de configuración principal para el gestor de dependencias de Crystal, Shard. Contiene metadatos del proyecto y las dependencias que Shard gestionará.

SECCIÓN

El archivo shard.yml está estructurado en secciones principales:

name

El nombre de tu proyecto. Debe ser único.

version

La versión actual de tu proyecto, en formato de versionado semántico (SemVer).

authors

Una lista de los autores del proyecto.

description

Una breve descripción de tu proyecto.

license

La licencia bajo la cual se distribuye tu proyecto.

dependencies

Una sección para listar las dependencias de tu proyecto. Cada dependencia tiene un nombre y una versión especificada.

development_dependencies

Dependencias necesarias solo para el desarrollo, como herramientas de prueba o análisis de código.

git

Especifica la URL del repositorio Git de tu proyecto.

scripts

Define scripts personalizados que pueden ser ejecutados con `shards run `.

EJEMPLO

name: mi_proyecto
version: 0.1.0
authors:
  - Tu Nombre <tu.email@example.com>
description: |
  Una breve descripción de mi proyecto.
license: MIT
git: https://github.com/tu_usuario/mi_proyecto.git

dependencies:
  json:
    github: crystal-lang/crystal-json
    branch: master

development_dependencies:
  minitest:
    github: jgoguen/minitest.cr
    version: "~> 0.5.0"

scripts:
  test: crystal spec
