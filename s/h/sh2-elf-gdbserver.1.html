NOMBRE

gdbserver - Servidor remoto para el Depurador GNU

SINOPSIS

gdbserver comm prog [args...]

gdbserver --attach comm pid

gdbserver --multi comm

DESCRIPCIÓN

gdbserver es un programa que permite ejecutar GDB en una máquina diferente a la que está ejecutando el programa que se está depurando.

Uso (lado del servidor (objetivo)):

Primero, necesitas tener una copia del programa que quieres depurar en el sistema objetivo. El programa puede ser despojado (stripped) para ahorrar espacio si es necesario, ya que a gdbserver no le importan los símbolos. Todo el manejo de símbolos lo realiza el GDB que se ejecuta en el sistema host.

Para usar el servidor, inicia sesión en el sistema objetivo y ejecuta el programa gdbserver. Debes indicarle (a) cómo comunicarse con GDB, (b) el nombre de tu programa y (c) sus argumentos. La sintaxis general es:

objetivo> gdbserver <comm> <programa> [<args> ...]

Por ejemplo, usando un puerto serie, podrías decir:

objetivo> gdbserver /dev/com1 emacs foo.txt

Esto le indica a gdbserver que depure emacs con el argumento foo.txt, y que se comunique con GDB a través de /dev/com1. gdbserver ahora espera pacientemente a que el GDB host se comunique con él.

Para usar una conexión TCP, podrías decir:

objetivo> gdbserver host:2345 emacs foo.txt

Esto dice prácticamente lo mismo que el último ejemplo, excepto que nos comunicaremos con el GDB "host" a través de TCP. El argumento "host:2345" significa que esperamos ver una conexión TCP desde "host" al puerto TCP local 2345. (Actualmente, la parte "host" se ignora.) Puedes elegir cualquier número para el puerto siempre que no entre en conflicto con otros puertos TCP existentes en el sistema objetivo. El mismo número de puerto debe usarse en el comando "target remote" del GDB host, que se describirá en breve. Ten en cuenta que si eliges un número de puerto que entra en conflicto con otro servicio, gdbserver imprimirá un mensaje de error y saldrá.

gdbserver también puede adjuntarse a programas en ejecución. Esto se logra a través del argumento --attach. La sintaxis es:

objetivo> gdbserver --attach <comm> <pid>

pid es el ID del proceso de un proceso en ejecución. No es necesario apuntar gdbserver a un binario para el proceso en ejecución.

Para iniciar "gdbserver" sin suministrar un comando inicial para ejecutar o un ID de proceso al que adjuntarse, usa la opción de línea de comandos --multi. En tal caso, debes conectarte usando "target extended-remote" para iniciar el programa que quieres depurar.

objetivo> gdbserver --multi <comm>

Uso (lado del host):

Necesitas una copia sin despojar del programa objetivo en tu sistema host, ya que GDB necesita examinar sus tablas de símbolos y demás. Inicia GDB como lo harías normalmente, con el programa objetivo como primer argumento. (Es posible que necesites usar la opción --baud si la línea serie funciona a algo diferente de 9600 baudios). Es decir, "gdb PROG-OBJETIVO", o "gdb --baud BAUD PROG-OBJETIVO". Después de eso, el único comando nuevo que necesitas conocer es "target remote" (o "target extended-remote"). Su argumento es un nombre de dispositivo (generalmente un dispositivo serie, como /dev/ttyb), o un descriptor "HOST:PUERTO". Por ejemplo:

(gdb) target remote /dev/ttyb

se comunica con el servidor a través de la línea serie /dev/ttyb, y:

(gdb) target remote host_objetivo:2345

se comunica a través de una conexión TCP al puerto 2345 en el host `host_objetivo', donde previamente ejecutaste gdbserver con el mismo número de puerto. Ten en cuenta que para las conexiones TCP, debes iniciar gdbserver antes de usar el comando `target remote', de lo contrario, puedes recibir un error como `Connection refused'.

gdbserver también puede depurar múltiples inferiors a la vez, descrito en el manual de GDB en el nodo "Inferiors Connections and Programs" -- comando de shell "info -f gdb -n 'Inferiors Connections and Programs'". En tal caso, usa la variante del comando GDB "extended-remote":

(gdb) target extended-remote host_objetivo:2345

La opción --multi de gdbserver puede o no usarse en tal caso.

OPCIONES

Hay tres modos diferentes para invocar gdbserver:

  • Depurar un programa específico especificado por su nombre: 
    gdbserver <comm> <prog> [<args>...]

    El parámetro comm especifica cómo debe comunicarse el servidor con GDB; es el nombre de un dispositivo (para usar una línea serie), un número de puerto TCP (":1234"), o "-" o "stdio" para usar la entrada/salida estándar de "gdbserver". Especifica el nombre del programa a depurar en prog. Cualquier argumento restante se pasará al programa sin cambios. Cuando el programa termine, GDB cerrará la conexión y "gdbserver" saldrá.

  • Depurar un programa específico especificando el ID del proceso de un programa en ejecución: 
    gdbserver --attach <comm> <pid>

    El parámetro comm se describe como arriba. Proporciona el ID del proceso de un programa en ejecución en pid; GDB hará el resto. Al igual que con el modo anterior, cuando el proceso pid termine, GDB cerrará la conexión y "gdbserver" saldrá.

  • Modo multiproceso -- depurar más de un programa/proceso: 
    gdbserver --multi <comm>

    En este modo, GDB puede instruir a gdbserver qué(es) comando(s) ejecutar. A diferencia de los otros 2 modos, GDB no cerrará la conexión cuando un proceso depurado termine, por lo que puedes depurar varios procesos en la misma sesión.

En cada uno de los modos puedes especificar estas opciones:

--help
Lista todas las opciones, con explicaciones breves.
--version
Esta opción hace que gdbserver imprima su número de versión y salga.
--attach
gdbserver se adjuntará a un programa en ejecución. La sintaxis es: 
objetivo> gdbserver --attach <comm> <pid>

pid es el ID del proceso de un proceso en ejecución. No es necesario apuntar gdbserver a un binario para el proceso en ejecución.

--multi
Para iniciar "gdbserver" sin proporcionar un comando inicial para ejecutar o un ID de proceso al que adjuntarse, usa esta opción de línea de comandos. Luego puedes conectarte usando "target extended-remote" e iniciar el programa que deseas depurar. La sintaxis es: 
objetivo> gdbserver --multi <comm>
--debug[=opcion1,opcion2,...]
Instruye a "gdbserver" para que muestre información de estado adicional sobre el proceso de depuración. Esta opción está destinada al desarrollo de "gdbserver" y para reportar errores a los desarrolladores.

Cada opción es el nombre de un componente para el cual debe habilitarse la depuración. La lista de opciones posibles es all, threads, event-loop, remote. La opción especial all habilita todos los componentes. La lista de opciones se procesa de izquierda a derecha, y una opción puede ir precedida del carácter "-" para deshabilitar la salida para ese componente, por lo que podrías escribir:

objetivo> gdbserver --debug=all,-event-loop

para activar la salida de depuración para todos los componentes excepto event-loop. Si no se pasan opciones a --debug, se trata como equivalente a --debug=threads< sh2-elf-gdbserver(1) — Arch manual pages

NAME

gdbserver — support for remote debugging with GDB

SYNOPSIS

gdbserver [options] [--multi] listen-address program [program-args...]

gdbserver [options] --attach listen-address pid

DESCRIPTION

gdbserver es un programa que se ejecuta en la máquina remota y que permite depurar un programa ejecutándose en esa máquina remota usando GDB en la máquina local. Actualmente gdbserver soporta depuración remota de programas en sistemas que admiten sockets de red.

En su forma más simple, gdbserver se ejecuta en la máquina remota y se le indica que puerto debe escuchar (el que gdbserver usa para comunicarse con gdb) y el nombre del programa a depurar. gdbserver inicia el programa y espera a que una conexión de gdb se conecte.

El gdb local puede conectarse a gdbserver usando la opción del comando de gdb target remote.

Con la opción --multi, gdbserver se ejecutará indefinidamente, esperando conexiones de GDB para depurar diferentes procesos. Cada vez que se conecte una instancia de GDB, gdbserver esperará a que se desconecte antes de aceptar la siguiente conexión.

Si se utiliza la opción --attach, gdbserver se conectará a un proceso ya existente (identificado por pid) en lugar de iniciar uno nuevo. La depuración comenzará cuando gdb se conecte.

OPTIONS

--debug
Instruct "gdbserver" to send any debug output to standard error. This option is intended for "gdbserver" development and for bug reports to the developers.
--debug-file=filename
Instruct "gdbserver" to send any debug output to the given filename. This option is intended for "gdbserver" development and for bug reports to the developers.
--debug-file=filename
Instruct "gdbserver" to send any debug output to the given filename. This option is intended for "gdbserver" development and for bug reports to the developers.
--debug-format=option1[,option2,...]
Instruct "gdbserver" to include extra information in each line of debugging output.
--wrapper
Specify a wrapper to launch programs for debugging. The option should be followed by the name of the wrapper, then any command-line arguments to pass to the wrapper, then "--" indicating the end of the wrapper arguments.
--once
By default, gdbserver keeps the listening TCP port open, so that additional connections are possible. However, if you start "gdbserver" with the --once option, it will stop listening for any further connection attempts after connecting to the first GDB session.

info gdb

should give you access to the complete manual.
