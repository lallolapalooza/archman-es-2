DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) calculan una o más reducciones a través de arreglos simétricos en múltiples PEs virtuales. Una reducción realiza una operación binaria asociativa a través de un conjunto de valores. Para obtener una lista de otras rutinas de reducción SHMEM, consulte intro_shmem(3).

Al igual que con todas las rutinas colectivas SHMEM, cada una de estas rutinas asume que solo los PEs del conjunto activo llaman a la rutina. Si un PE que no está en el conjunto activo llama a una rutina colectiva SHMEM, el resultado es indefinido.

El argumento nreduce determina el número de reducciones separadas a realizar. El arreglo fuente en todos los PEs del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en el arreglo destino en todos los PEs del conjunto activo. El conjunto activo se define por el triplete PE_start, logPE_stride, PE_size.

Los arreglos fuente y destino pueden ser el mismo arreglo, pero no pueden ser arreglos superpuestos.

Los argumentos son los siguientes:

objetivo
El objeto de datos entero accesible remotamente que se actualizará en el PE remoto. Si está utilizando C/C++, el tipo de objetivo debe coincidir con el implícito en la sección SINOPSIS. Si está utilizando el compilador Fortran, debe ser de tipo entero con un tamaño de elemento de 4 bytes para SHMEM_INT4_ADD y 8 bytes para SHMEM_INT8_ADD.
valor
El valor a añadir atómicamente a objetivo. Si está utilizando C/C++, el tipo de valor debe coincidir con el implícito en la sección SINOPSIS. Si está utilizando Fortran, debe ser de tipo entero con un tamaño de elemento igual al de objetivo.
pe
Un entero que indica el número de PE en el que se actualizará objetivo. Si está utilizando Fortran, debe ser un valor entero predeterminado.
objetivo
Un arreglo simétrico de longitud nreduce elementos para recibir los resultados
de las operaciones de reducción.
El tipo de datos de objetivo varía con la versión de la rutina de reducción
que se llama y el idioma utilizado. Al llamar desde C/C++, consulte la
sección SINOPSIS para obtener información sobre el tipo de datos.
Al llamar desde Fortran, los tipos de datos de objetivo son los siguientes:

shmem_comp4_sum_to_all:** COMPLEX(KIND=4).

shmem_comp8_sum_to_all:** Complejo. Si está utilizando Fortran, debe ser
un valor complejo predeterminado.

shmem_int4_sum_to_all:** INTEGER(KIND=4).

shmem_int8_sum_to_all:** Entero. Si está utilizando Fortran, debe ser un
valor entero predeterminado.

shmem_real4_sum_to_all:** REAL(KIND=4).

shmem_real8_sum_to_all:** Real. Si está utilizando Fortran, debe ser un
valor real predeterminado.
shmem_real16_sum_to_all:** Real. Si está utilizando Fortran, debe ser un
valor real predeterminado.
fuente
Un arreglo simétrico, de longitud nreduce elementos, que contiene un elemento para cada operación de reducción separada. El argumento fuente debe tener el mismo tipo de datos que objetivo.
nreduce
El número de elementos en los arreglos objetivo y fuente. nreduce debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
PE_start
El número de PE más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
logPE_stride
El logaritmo (base 2) del paso entre números de PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
pWrk
Un arreglo de trabajo simétrico. El argumento pWrk debe tener el mismo tipo de datos que objetivo. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Un arreglo de trabajo simétrico. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Debe ser un valor entero predeterminado. Cada elemento de este arreglo debe inicializarse con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran) antes de que alguno de los PEs del conjunto activo entre en la rutina de reducción.

SYNOPSIS

C:

#include <openshmem.h>
void shmem_double_sum_to_all(double *target, double *source, int nreduce,
     int PE_start, int logPE_stride, int PE_size, double *pWrk,
     long *pSync);
void shmem_double_sum_all(double *target, double *source, int nreduce,
     int PE_start, int logPE_stride, int PE_size, double *pWrk,
     long *pSync);

Fortran:

INCLUDE "mpp/shmem.fh"
INTEGER (KIND=SHMEM_REDUCE_SYNC_SIZE) PSYNC
INTEGER (KIND=SHMEM_REDUCE_MIN_WRKDATA_SIZE) PWRK
CALL SHMEM_DOUBLE_SUM_TO_ALL(TARGET, SOURCE, NREDUCE, PE_START,
     LOGPE_STRIDE, PE_SIZE, PWRK, PSYNC)
CALL SHMEM_DOUBLE_SUM_ALL(TARGET, SOURCE, NREDUCE, PE_START,
     LOGPE_STRIDE, PE_SIZE, PWRK, PSYNC)

DESCRIPTION

These routines compute the sum of values from the source arrays on the participating processing elements (PEs) and place the result in the target arrays. The PEs that participate in the reduction are specified by the arguments PE_start, logPE_stride, and PE_size.

All arguments are the same for all PEs in the active set, except for the target and source arrays, which are processed independently on each PE. The size of the target and source arrays are specified by nreduce.

The PE_start, logPE_stride, and PE_size arguments specify the active set of PEs. The active set is the set of PEs that participate in the reduction. The set consists of PEs indexed by PE_start, PE_start + 2^logPE_stride, PE_start + 2*2^logPE_stride, ..., PE_start + (PE_size-1)*2^logPE_stride.

The pWrk array is a work array used for intermediate storage during the reduction. The size of the pWrk array must be at least MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE) elements for Fortran, where NR is the number of elements in the source array. For C, the size of the pWrk array must be at least NR/2+1 elements.

The pSync array is a synchronization array that is used to ensure that all PEs in the active set have completed the reduction. The size of the pSync array must be at least SHMEM_REDUCE_SYNC_SIZE elements for Fortran, and SHMEM_REDUCE_SYNC_SIZE for C.

All arguments except target and source must be equal on all PEs in the active set. The same target and source arrays, and the same pWrk and pSync work arrays, must be passed to all PEs in the active set.

Before any PE calls a reduction routine, you must ensure that the following conditions exist (synchronization via a barrier or some other method is often needed to ensure this): The pWrk and pSync arrays on all PEs in the active set are not still in use from a prior call to a collective SHMEM routine. The target array on all PEs in the active set is ready to accept the results of the reduction.

Upon return from a reduction routine, the following are true for the local PE: The target array is updated. The values in the pSync array are restored to the original values.

NOTES

The terms collective, symmetric, and cache aligned are defined in intro_shmem(3).

All SHMEM reduction routines reset the values in pSync before they return, so a particular pSync buffer need only be initialized the first time it is used.

You must ensure that the pSync array is not being updated on any PE in the active set while any of the PEs participate in processing of a SHMEM reduction routine. Be careful of the following situations: If the pSync array is initialized at run time, some type of synchronization is needed to ensure that all PEs in the working set have initialized pSync before any of them enter a SHMEM routine called with the pSync synchronization array. A pSync or pWrk array can be reused in a subsequent reduction routine call only if none of the PEs in the active set are still processing a prior reduction routine call that used the same pSync or pWrk arrays. In general, this can be assured only by doing some type of synchronization. However, in the special case of reduction routines being called with the same active set, you can allocate two pSync and pWrk arrays and alternate between them on successive calls.

EXAMPLES

Example 1: This Fortran example statically initializes the pSync array and finds the sum of the real variable FOO across all even PEs.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOSUM, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOSUM, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_INT4_SUM_TO_ALL(FOOSUM, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOSUM
ENDIF

Example 2: Consider the following C/C++ call:

shmem_int_sum_to_all( target, source, 3, 0, 0, 8, pwrk, psync );

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_int_sum_to_all(&(target[0]), &(source[0]), 1, 0, 0, 8,
  pwrk1, psync1);
shmem_int_sum_to_all(&(target[1]), &(source[1]), 1, 0, 0, 8,
  pwrk2, psync2);
shmem_int_sum_to_all(&(target[2]), &(source[2]), 1, 0, 0, 8,
  pwrk1, psync1);
Note that two sets of pWrk and pSync arrays are used alternately because no
synchronization is done between calls.
