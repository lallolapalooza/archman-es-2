DESCRIPCIÓN

Las rutinas de obtención con stride recuperan datos de array disponibles en la dirección source en el PE remoto (pe). Los elementos del array source están separados por un stride sst. Una vez recibidos los datos, se almacenan en la dirección de memoria local target, separados por el stride tst. Las rutinas regresan cuando los datos han sido copiados al array local target.

Los argumentos son los siguientes:

target
Array que se actualizará en el PE local.
source
Array que contiene los datos a copiar en el PE remoto.
tst
El stride entre elementos consecutivos del array de destino. El stride se escala por el tamaño del elemento del array de destino. Un valor de 1 indica datos contiguos. tst debe ser de tipo entero. Si llamas desde Fortran, debe ser un valor entero predeterminado.
sst
El stride entre elementos consecutivos del array de origen. El stride se escala por el tamaño del elemento del array de origen. Un valor de 1 indica datos contiguos. sst debe ser de tipo entero. Si llamas desde Fortran, debe ser un valor entero predeterminado.
len
Número de elementos en los arrays de destino y origen. len debe ser de tipo entero. Si usas Fortran, debe ser una constante, variable o elemento de array de tipo entero predeterminado.
pe
Número de PE del PE remoto. pe debe ser de tipo entero. Si usas Fortran, debe ser una constante, variable o elemento de array de tipo entero predeterminado.

Los objetos de datos de destino y origen deben cumplir con las restricciones de tipo, que son las siguientes:

shmem_iget32, shmem_iget4: Cualquier tipo no caracter que tenga un tamaño de almacenamiento
igual a 32 bits.
shmem_iget64, shmem_iget8: Cualquier tipo no caracter que tenga un tamaño de almacenamiento
igual a 64 bits.
shmem_iget128: Cualquier tipo no caracter que tenga un tamaño de almacenamiento igual a
128 bits.

shmem_short_iget: Elementos de tipo short.

shmem_int_iget: Elementos de tipo int.

shmem_long_iget: Elementos de tipo long.

shmem_longlong_iget: Elementos de tipo long long.

shmem_float_iget: Elementos de tipo float.

shmem_double_iget: Elementos de tipo double.

shmem_longdouble_iget: Elementos de tipo long double.

SHMEM_COMPLEX_IGET: Elementos de tipo complex de tamaño predeterminado.

SHMEM_DOUBLE_IGET: (Fortran) Elementos de tipo double precision.

SHMEM_INTEGER_IGET: Elementos de tipo integer.

SHMEM_LOGICAL_IGET: Elementos de tipo logical.

SHMEM_REAL_IGET: Elementos de tipo real.

shmem_longdouble_iget: Elementos de tipo long double.

SHMEM_COMPLEX_IGET: Elementos de tipo complex de tamaño predeterminado.

SHMEM_DOUBLE_IGET: (Fortran) Elementos de tipo double precision.

SHMEM_INTEGER_IGET: Elementos de tipo integer.

SHMEM_LOGICAL_IGET: Elementos de tipo logical.

SHMEM_REAL_IGET: Elementos de tipo real.

Si estás usando Fortran, los tipos de datos deben ser de tamaño predeterminado. Por ejemplo, una variable real debe declararse como REAL, REAL*4 o REAL(KIND=4).

NOTAS

Ver intro_shmem(3) para una definición del término accesible de forma remota.

EJEMPLOS

El siguiente ejemplo simple utiliza shmem_logical_iget en un programa Fortran. Compila este ejemplo con la opción de compilador -lsma.

PROGRAM STRIDELOGICAL
  LOGICAL SOURCE(10), TARGET(5)
  SAVE SOURCE ! SAVE HACE QUE SEA ACCESIBLE DE FORMA REMOTA
  DATA SOURCE /.T.,.F.,.T.,.F.,.T.,.F.,.T.,.F.,.T.,.F./
  DATA TARGET / 5*.F. /
  CALL START_PES(2)
  IF (MY_PE() .EQ. 0) THEN
    CALL SHMEM_LOGICAL_IGET(TARGET, SOURCE, 1, 2, 5, 1)
    PRINT*,'TARGET DESPUÉS DE SHMEM_LOGICAL_IGET:',TARGET
  ENDIF
  CALL SHMEM_BARRIER_ALL
END
