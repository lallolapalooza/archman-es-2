shmem_longlong_xor_to_all(3)

Paquete: openmpi

Licencias: BSD-3-Clause AND LicenseRef-MPICH

SHMEM_LONGLONG_XOR_TO_ALL(3) Open MPI SHMEM_LONGLONG_XOR_TO_ALL(3)

shmem_comp4_xor_to_all(3), shmem_int_xor_to_all(3), shmem_int4_xor_to_all(3), shmem_int8_xor_to_all(3), shmem_long_xor_to_all(3), shmem_longlong_xor_to_all(3), shmem_short_xor_to_all(3) - Realiza una operación XOR a nivel de bits en arrays simétricos sobre el conjunto activo de PEs.

SINAPSIS

C o C++:

#include <mpp/shmem.h>
void shmem_int_xor_to_all(int *target, const int *source,
  int nreduce, int PE_start, int logPE_stride, int PE_size,
  int *pWrk, long *pSync)
void shmem_long_xor_to_all(long *target, const long *source,
  int nreduce, int PE_start, int logPE_stride, int PE_size,
  long *pWrk, long *pSync)
void shmem_longlong_xor_to_all(long long *target,
  const long long *source, int nreduce, int PE_start, int logPE_stride,
  int PE_size, long long *pWrk, long *pSync)
void shmem_short_xor_to_all(short *target, const short *source,
  int nreduce, int PE_start, int logPE_stride, int PE_size,
  short *pWrk, long *pSync)

Fortran:

INCLUDE "mpp/shmem.fh"
INTEGER pSync(SHMEM_REDUCE_SYNC_SIZE)
INTEGER nreduce, PE_start, logPE_stride, PE_size
CALL SHMEM_COMP4_XOR_TO_ALL(target, source, nreduce,
& PE_start, logPE_stride, PE_size, pWrk, pSync)
CALL SHMEM_INT4_XOR_TO_ALL(target, source, nreduce,
& PE_start, logPE_stride, PE_size, pWrk, pSync)
CALL SHMEM_INT8_XOR_TO_ALL(target, source, nreduce,
& PE_start, logPE_stride, PE_size, pWrk, pSync)

DESCRIPCIÓN

Las rutinas de reducción de memoria compartida (SHMEM) calculan una o más reducciones sobre arrays simétricos en múltiples PEs virtuales. Una reducción realiza una operación binaria asociativa sobre un conjunto de valores. Para una lista de otras rutinas de reducción de SHMEM, consulte intro_shmem(3).

Como con todas las rutinas colectivas de SHMEM, cada una de estas rutinas asume que solo los PEs en el conjunto activo llaman a la rutina. Si un PE no en el conjunto activo llama a una rutina colectiva de SHMEM, el comportamiento resultante es indefinido.

El argumento nreduce determina el número de reducciones separadas a realizar. El array fuente en todos los PEs del conjunto activo proporciona un elemento para cada reducción. Los resultados de las reducciones se colocan en el array destino en todos los PEs del conjunto activo. El conjunto activo se define por el triplete PE_start, logPE_stride, PE_size.

Los arrays fuente y destino pueden ser el mismo array, pero no pueden ser arrays superpuestos.

Los argumentos son los siguientes:

target
Un array simétrico de longitud nreduce elementos para recibir los resultados de las operaciones de reducción. El tipo de datos de target varía con la versión de la rutina de reducción que se llama y el lenguaje utilizado. Al llamar desde C/C++, consulte la sección SINAPSIS para obtener información sobre el tipo de datos. Al llamar desde Fortran, los tipos de datos de destino son los siguientes:
shmem_comp8_xor_to_all:** Complejo, con un tamaño de elemento igual a dos valores reales de 8
bytes
shmem_comp4_xor_to_all:** Complejo, con un tamaño de elemento igual a dos valores reales de 4
bytes

shmem_int8_xor_to_all:** Entero, con un tamaño de elemento de 8 bytes

shmem_int4_xor_to_all:** Entero, con un tamaño de elemento de 4 bytes

shmem_real8_xor_to_all:** Real, con un tamaño de elemento de 8 bytes

shmem_real4_xor_to_all:** Real, con un tamaño de elemento de 4 bytes

source
Un array simétrico, de longitud nreduce elementos, que contiene un elemento para cada operación de reducción separada. El argumento fuente debe tener el mismo tipo de datos que target.
nreduce
El número de elementos en los arrays target y source. nreduce debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
PE_start
El número de PE virtual más bajo del conjunto activo de PEs. PE_start debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
logPE_stride
El logaritmo (base 2) del paso entre números de PE virtuales consecutivos en el conjunto activo. logPE_stride debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
PE_size
El número de PEs en el conjunto activo. PE_size debe ser de tipo entero. Si está utilizando Fortran, debe ser un valor entero predeterminado.
pWrk
Un array de trabajo simétrico. El argumento pWrk debe tener el mismo tipo de datos que target. En C/C++, contiene max(nreduce/2 + 1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos. En Fortran, contiene max(nreduce/2 + 1, SHMEM_REDUCE_MIN_WRKDATA_SIZE) elementos.
pSync
Un array de trabajo simétrico. En C/C++, pSync es de tipo long y tamaño _SHMEM_REDUCE_SYNC_SIZE. En Fortran, pSync es de tipo entero y tamaño SHMEM_REDUCE_SYNC_SIZE. Si está utilizando Fortran, debe ser un valor entero predeterminado. Cada elemento de este array debe inicializarse con el valor _SHMEM_SYNC_VALUE (en C/C++) o SHMEM_SYNC_VALUE (en Fortran) antes de que cualquiera de los PEs del conjunto activo entre en la rutina de reducción.

Los valores de los argumentos nreduce, PE_start, logPE_stride y PE_size deben ser iguales en todos los PEs del conjunto activo. Los mismos arrays target y source, y los mismos arrays de trabajo pWrk y pSync, deben pasarse a todos los PEs del conjunto activo.

Antes de que cualquier PE llame a una rutina de reducción, debe asegurarse de que se cumplan las siguientes condiciones (la sincronización mediante una barrera u otro método es a menudo necesaria para asegurar esto): Los arrays pWrk y pSync en todos los PEs del conjunto activo ya no se están utilizando de una llamada anterior a una rutina colectiva de SHMEM. El array target en todos los PEs del conjunto activo está listo para aceptar los resultados de la reducción.

Al regresar de una rutina de reducción, lo siguiente es cierto para el PE local: El array target se actualiza. Los valores en el array pSync se restauran a los valores originales.

NOTAS

Los términos colectivo, simétrico y alineado en caché se definen en intro_shmem(3). Todas las rutinas de reducción de SHMEM restauran los valores en pSync antes de regresar, por lo que un buffer pSync particular solo necesita ser inicializado la primera vez que se utiliza.

Debe asegurarse de que el array pSync no esté siendo actualizado en ningún PE del conjunto activo mientras alguno de los PEs participa en el procesamiento de una rutina de reducción de SHMEM. Tenga cuidado con las siguientes situaciones: Si el array pSync se inicializa en tiempo de ejecución, se necesita algún tipo de sincronización para asegurar que todos los PEs del conjunto de trabajo hayan inicializado pSync antes de que cualquiera de ellos entre en una rutina de SHMEM llamada con el array de sincronización pSync. Un array pSync o pWrk puede reutilizarse en una llamada posterior a una rutina de reducción solo si ninguno de los PEs del conjunto activo todavía está procesando una rutina de reducción anterior que utilizó los mismos arrays pSync o pWrk. En general, esto solo se puede asegurar realizando algún tipo de sincronización. Sin embargo, en el caso especial de las rutinas de reducción que se llaman con el mismo conjunto activo, puede asignar dos arrays pSync y pWrk y alternar entre ellos en llamadas sucesivas.

EJEMPLOS

Ejemplo 1: Este ejemplo de Fortran inicializa estáticamente el array pSync y calcula el XOR exclusivo de la variable FOO en todos los PEs pares.

INCLUDE "mpp/shmem.fh"
INTEGER PSYNC(SHMEM_REDUCE_SYNC_SIZE)
DATA PSYNC /SHMEM_REDUCE_SYNC_SIZE*SHMEM_SYNC_VALUE/
PARAMETER (NR=1)
REAL FOO, FOOXOR, PWRK(MAX(NR/2+1,SHMEM_REDUCE_MIN_WRKDATA_SIZE))
COMMON /COM/ FOO, FOOXOR, PWRK
INTRINSIC MY_PE
IF ( MOD(MY_PE(),2) .EQ. 0) THEN
  CALL SHMEM_REAL8_XOR_TO_ALL(FOOXOR, FOO, NR, 0, 1, N$PES/2,
  & PWRK, PSYNC)
  PRINT *, 'Result on PE ', MY_PE(), ' is ', FOOXOR
ENDIF

Ejemplo 2: Considere la siguiente llamada C/C++:

#include <stdlib.h>
#include <stdio.h>
#include <mpp/shmem.h>

int main(void) {
    long long source[1], target[1];
    long long *pWrk;
    long *pSync;
    int i;

    pSync = (long *) shmem_calloc(_SHMEM_REDUCE_SYNC_SIZE, sizeof(long));
    pWrk = (long long *) shmem_calloc(MAX(1/2+1, _SHMEM_REDUCE_MIN_WRKDATA_SIZE),
                                      sizeof(long long));

    for (i=0; i < _SHMEM_REDUCE_SYNC_SIZE; i++) {
        pSync[i] = _SHMEM_SYNC_VALUE;
    }

    source[0] = 12345;
    target[0] = 0;

    shmem_longlong_xor_to_all(target, source, 1, 0, 0, num_pes(), pWrk, pSync);

    if (my_pe() == 0) {
        printf("XOR reduction result: %lld\n", target[0]);
    }

    shmem_free(pWrk);
    shmem_free(pSync);
    return 0;
}

SYNOPSIS 

int shmem_longlong_xor_to_all(long long *target, const long long *source,
     int nlonglong, int PE_start, int logPE_stride, int PE_size,
     shmem_op_t op, long long *pSync);

DESCRIPTION

The shmem_longlong_xor_to_all routine performs a symmetric, inter-process reduction and XOR operation.

The reduction is performed on the array of long long integers specified by the source argument. The result is placed in the array specified by the target argument.

The operation is performed across the set of PEs specified by PE_start, logPE_stride, and PE_size.

nlonglong specifies the number of long long elements in the source and target arrays.

The arguments PE_start, logPE_stride, and PE_size determine the set of PEs across which the reduction is performed. The set of PEs involved in the reduction is { PE_start + logPE_stride * i : 0 <= i < PE_size }. This set must be a subset of the total PEs in the execution group.

The reduction is performed on the elements of the source array within each PE. The result is written to the target array within each PE.

The op argument is currently ignored. The reduction operation is always XOR.

The argument pSync is a pointer to a synchronous barrier array. This array must be initialized to all -1 and is used by the system to synchronize the reduction operation.

This routine is a collective call and must be invoked by all PEs in the group.

The shmem_longlong_xor_to_all routine is equivalent to the following sequence:

shmem_longlong_xor_all(target, source, nlonglong, PE_start, logPE_stride, PE_size, pSync);

This routine is also equivalent to the following sequence:

shmem_longlong_xor_to_all(target, source, 1, PE_start, logPE_stride, PE_size, pSync);
shmem_longlong_xor_to_all(target, source, nlonglong - 1, PE_start, logPE_stride, PE_size, pSync);

Where the second call starts processing at the second element of the arrays.

The above is a simplification. The actual implementation may combine multiple calls.

NOTES

shmem_longlong_xor_to_all is functionally equivalent to shmem_xor_to_all with sizeof(long long) as the element size, but may be more efficient.

EXAMPLES

The following code performs an XOR reduction on 3 elements of type long long across all PEs.

shmem_longlong_t target, source[3];
long long pSync[shmem_SYMMETRIC_SIZE];

... initialize source ...

shmem_longlong_xor_to_all(target, source, 3, 0, 0, shmem_n_pes(), pSync);

The preceding call is more efficient, but semantically equivalent to, the combination of the following calls:

shmem_longlong_xor_to_all(&(target[0]), &(source[0]), 1, 0, 0, shmem_n_pes(),
  pSync1);
shmem_longlong_xor_to_all(&(target[1]), &(source[1]), 1, 0, 0, shmem_n_pes(),
  pSync2);
shmem_longlong_xor_to_all(&(target[2]), &(source[2]), 1, 0, 0, shmem_n_pes(),
  pSync1);

Note that two sets of pSync arrays are used alternately because no synchronization is done between calls.
