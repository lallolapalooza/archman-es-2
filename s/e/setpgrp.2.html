setpgid(2) System Calls Manual setpgid(2)

NOMBRE

setpgid, getpgid, setpgrp, getpgrp - establecer/obtener grupo de procesos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int setpgid(pid_t pid, pid_t pgid);
pid_t getpgid(pid_t pid);
pid_t getpgrp(void);                            /* Versión POSIX.1 */
[[deprecated]] pid_t getpgrp(pid_t pid);        /* Versión BSD */
int setpgrp(void);                              /* Versión System V */
[[deprecated]] int setpgrp(pid_t pid, pid_t pgid);  /* Versión BSD */
Requisitos de Macro de Prueba de Funcionalidad para glibc (ver feature_test_macros(7)):

getpgid():

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.12: */ _POSIX_C_SOURCE >= 200809L

setpgrp() (POSIX.1):

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _SVID_SOURCE

setpgrp() (BSD), getpgrp() (BSD):

    [Estas solo están disponibles antes de glibc 2.19]
    _BSD_SOURCE &&
        ! (_POSIX_SOURCE || _POSIX_C_SOURCE || _XOPEN_SOURCE
            || _GNU_SOURCE || _SVID_SOURCE)

DESCRIPCIÓN

Todas estas interfaces están disponibles en Linux y se utilizan para obtener y establecer el ID del grupo de procesos (PGID) de un proceso. Las formas preferidas y especificadas por POSIX.1 para hacerlo son: getpgrp(void), para recuperar el PGID del proceso que llama; y setpgid(), para establecer el PGID de un proceso.

setpgid() establece el PGID del proceso especificado por pid a pgid. Si pid es cero, se utiliza el ID del proceso del proceso que llama. Si pgid es cero, el PGID del proceso especificado por pid se hace igual a su ID de proceso. Si setpgid() se utiliza para mover un proceso de un grupo de procesos a otro (como lo hacen algunos shells al crear pipelines), ambos grupos de procesos deben formar parte de la misma sesión (ver setsid(2) y credentials(7)). En este caso, pgid especifica un grupo de procesos existente al que unirse y el ID de sesión de ese grupo debe coincidir con el ID de sesión del proceso que se une.

La versión de POSIX.1 de getpgrp(), que no toma argumentos, devuelve el PGID del proceso que llama.

getpgid() devuelve el PGID del proceso especificado por pid. Si pid es cero, se utiliza el ID del proceso del proceso que llama. (Rara vez es necesario recuperar el PGID de un proceso que no sea el llamante, y se prefiere getpgrp() de POSIX.1 para esa tarea).

El setpgrp() de estilo System V, que no toma argumentos, es equivalente a setpgid(0, 0).

La llamada setpgrp() específica de BSD, que toma los argumentos pid y pgid, es una función de envoltura que llama a


setpgid(pid, pgid)

Desde glibc 2.19, la función setpgrp() específica de BSD ya no se expone a través de <unistd.h>; las llamadas deben reemplazarse con la llamada setpgid() que se muestra arriba.

La llamada getpgrp() específica de BSD, que toma un único argumento pid, es una función de envoltura que llama a


getpgid(pid)

Desde glibc 2.19, la función getpgrp() específica de BSD ya no se expone a través de <unistd.h>; las llamadas deben reemplazarse con llamadas a getpgrp() de POSIX.1, que no toma argumentos (si la intención es obtener el PGID del llamante), o con la llamada getpgid() que se muestra arriba.

VALOR DE RETORNO

En caso de éxito, setpgid() y setpgrp() devuelven cero. En caso de error, devuelven -1 y errno se establece para indicar el error.

El getpgrp() de POSIX.1 siempre devuelve el PGID del llamante.

getpgid(), y el getpgrp() específico de BSD devuelven un grupo de procesos en caso de éxito. En caso de error, devuelven -1 y errno se establece para indicar el error.

ERRORES

EACCES
Se intentó cambiar el ID del grupo de procesos de uno de los hijos del proceso que llama y el hijo ya había realizado una execve(2) (setpgid(), setpgrp()).
EINVAL
pgid es menor que 0 (setpgid(), setpgrp()).
EPERM
Se intentó mover un proceso a un grupo de procesos en una sesión diferente, o cambiar el ID del grupo de procesos de uno de los hijos del proceso que llama y el hijo estaba en una sesión diferente, o cambiar el ID del grupo de procesos de un líder de sesión (setpgid(), setpgrp()).
EPERM
El grupo de procesos de destino no existe. (setpgid(), setpgrp()).
ESRCH
Para getpgid(): pid no coincide con ningún proceso. Para setpgid(): pid no es el proceso que llama ni un hijo del proceso que llama.

NOTAS

Un hijo creado a través de fork(2) hereda el ID del grupo de procesos de su padre. El PGID se conserva a través de una execve(2).

Cada grupo de procesos es miembro de una sesión y cada proceso es miembro de la sesión de la que forma parte su grupo de procesos. (Ver credentials(7)).

Una sesión puede tener una terminal de control. En cualquier momento, uno (y solo uno) de los grupos de procesos de la sesión puede ser el grupo de procesos en primer plano para la terminal; los grupos de procesos restantes están en segundo plano. Si se genera una señal desde la terminal (por ejemplo, al presionar la tecla de interrupción para generar SIGINT), esa señal se envía al grupo de procesos en primer plano. (Ver termios(3) para una descripción de los caracteres que generan señales). Solo el grupo de procesos en primer plano puede leer(2) de la terminal; si un grupo en segundo plano intenta leer(2) de la terminal, entonces al grupo se le envía una señal SIGTTIN, que lo suspende. Las funciones tcgetpgrp(3) y tcsetpgrp(3) se utilizan para obtener/establecer el grupo de procesos en primer plano de la terminal de control.

Las llamadas setpgid() y getpgrp() son utilizadas por programas como bash(1) para crear grupos de procesos con el fin de implementar el control de trabajos del shell.

setpgrp(2) - Linux man-pages (es)

NOMBRE

setpgrp, setpgid, getpgrp, getpgid - establecer o obtener el ID del grupo de procesos

BIBLIOTECA

Biblioteca C estándar (libc)

Conforme a POSIX.1-2001, POSIX.1-2008, POSIX.1-2017.

SINOPSIS

#include <unistd.h>

pid_t getpgrp(void);
pid_t getpgid(pid_t pid);

int setpgrp(void);
int setpgid(pid_t pid, pid_t pgid);

DESCRIPCIÓN

Cada proceso en un sistema Unix pertenece a un grupo de procesos. El grupo de procesos se identifica mediante un ID de grupo de procesos (PGID). El PGID es el PID (ID de proceso) del proceso que fundó el grupo de procesos.

Un grupo de procesos es una colección de uno o más grupos de procesos que han sido puestos en el mismo grupo de trabajos. El grupo de trabajo se utiliza para la entrega de señales (por ejemplo, SIGHUP y SIGQUIT). El grupo de trabajo de un proceso es el grupo de procesos cuyo líder es el proceso con el PID que coincide con el PGID del proceso.

El grupo de procesos de un proceso se establece cuando el proceso se crea, usando fork(2). Inicialmente, un proceso recién creado tiene el mismo grupo de procesos que su padre.

Una sesión es una colección de uno o más grupos de procesos. Una sesión se crea cuando un proceso llama a setsid(2). El líder de la sesión es el proceso que llama a setsid(2). El líder de la sesión se convierte en el único miembro de su propio grupo de procesos, y este grupo de procesos se convierte en el único grupo de procesos de la nueva sesión. El líder de la sesión tiene un PID que coincide con su PGID.

GETPGRP

getpgrp() devuelve el ID de grupo de procesos del proceso que realiza la llamada.

getpgid() devuelve el ID de grupo de procesos del proceso especificado por pid. Si pid es 0, se devuelve el PGID del proceso que realiza la llamada. Si pid es un PID de un proceso de otro grupo de trabajo, o si el proceso especificado por pid es un proceso de un grupo de trabajo en una sesión diferente a la del proceso que realiza la llamada, el comportamiento es indefinido.

SETPGRP

setpgrp() hace que el proceso que realiza la llamada se convierta en el líder de un nuevo grupo de procesos. El proceso que realiza la llamada se convierte en el único miembro de este nuevo grupo de procesos. El nuevo grupo de procesos se crea dentro de la misma sesión que el proceso que realiza la llamada. El PGID del nuevo grupo de procesos es el PID del proceso que realiza la llamada.

setpgid() hace que el proceso especificado por pid se una al grupo de procesos especificado por pgid. Si pid es 0, se utiliza el PID del proceso que realiza la llamada. Si pgid es 0, se utiliza el PID del proceso especificado por pid (o el PID del proceso que realiza la llamada si pid es 0).

Los siguientes requisitos se aplican a setpgid():

  • El proceso especificado por pid debe ser un proceso hijo del proceso que realiza la llamada, o un proceso en el mismo grupo de procesos.
  • El proceso especificado por pid debe estar en la misma sesión que el proceso que realiza la llamada.
  • Un proceso no puede unirse a un grupo de procesos que se encuentra en una sesión diferente.
  • Un proceso no puede convertirse en el líder de un nuevo grupo de procesos si ya está en un grupo de procesos.
  • Si pid es el PID del proceso que realiza la llamada, y pgid es 0, entonces el proceso que realiza la llamada se convierte en el líder de un nuevo grupo de procesos.

El primer proceso de un grupo de trabajos se denomina líder del grupo de trabajos. El líder del grupo de trabajos es el proceso cuyo PID coincide con el PGID del grupo de trabajos.

Un grupo de procesos está huérfano si el padre de cada miembro del grupo de procesos es, o bien un miembro del grupo de procesos, o bien un miembro de un grupo de procesos en una sesión diferente. Cuando un grupo de procesos se queda huérfano, se envía una señal SIGHUP seguida de una señal SIGCONT a cada proceso del grupo de procesos huérfano.

VALOR DE RETORNO

getpgrp() y getpgid() devuelven el PGID apropiado en caso de éxito, o -1 en caso de error.

setpgrp() y setpgid() devuelven 0 en caso de éxito y -1 en caso de error.

ERRORES

Las siguientes condiciones pueden ocurrir en getpgid() y setpgid():

EPERM
El proceso especificado por pid no es un hijo del proceso que realiza la llamada, ni está en el mismo grupo de procesos, o el proceso especificado por pid está en una sesión diferente a la del proceso que realiza la llamada.
ESRCH
No se encontró ningún proceso con el PID especificado por pid.

ESTáNDARES

getpgrp() y setpgrp() están definidos en POSIX.1-2001 y versiones posteriores.

getpgid() y setpgid() están definidos en POSIX.1-2001 y versiones posteriores.

HISTORIA

setpgrp() apareció por primera vez en la versión 3 de AT&T UNIX.

setpgid() apareció por primera vez en la versión 4.3 de BSD UNIX.

NOTAS

La llamada a setpgrp() es equivalente a una llamada a setpgid(0, 0).

En la mayoría de los sistemas modernos, cuando un proceso que realiza la llamada envíe una señal SIGHUP seguida de una señal SIGCONT, se enviará a cada proceso del grupo de procesos huérfano.
