NOMBRE

send-uucp - Envía artículos de Usenet vía UUCP

SINOPSIS

send-uucp [sitio ...]

DESCRIPCIÓN

El programa send-uucp procesa archivos por lotes escritos por innd(8) para enviar artículos de Usenet a sitios UUCP. Lee un archivo de configuración para controlar cómo se comporta con varios sitios. Normalmente, se ejecuta periódicamente mediante cron para agrupar lotes y enviarlos a sitios UUCP remotos.

Hace posible reducir el uso de ancho de banda y enviar noticias a sitios UUCP remotos que no pueden recibir una transmisión en tiempo real (por ejemplo, si están en conexiones de acceso telefónico).

OPCIONES

Cualquier argumento proporcionado al programa se interpreta como una lista de sitios especificados en send-uucp.cf para los cuales se deben generar lotes. Si no se proporcionan argumentos, se generarán lotes para todos los sitios listados en ese archivo de configuración.

CONFIGURACIÓN

Los sitios a los que se deben enviar las noticias deben configurarse en el archivo de configuración send-uucp.cf en el directorio pathetc, tal como se establece en inn.conf. Cada sitio se especifica con una línea de la forma:

sitio[:host[:embudo]] [compresor [tamañomax [tiempolote]]]
sitio
El nombre del sitio de noticias que se está configurando. Debe coincidir con un nombre de sitio de newsfeeds(5).
host
El nombre del host UUCP al que se deben enviar los lotes para este sitio. Si se omite, se utilizará el nombre del sitio de noticias como nombre del host UUCP.
embudo
En el caso de un sitio configurado como embudo (funnel), send-uucp necesita vaciar el canal (o exploder) que se utiliza como destino del embudo en lugar de vaciar el sitio. Esta es la forma de indicar a send-uucp el nombre del canal o exploder que se vaciará para este sitio. Si no se especifica, por defecto vacía el sitio.
compresor
El método de compresión a utilizar para los lotes. Debe ser uno de "bzip2", "compress", "gzip" o "none". Los argumentos para el comando de compresión se pueden especificar usando "_" en lugar de espacios. Por ejemplo, "gzip_-9". El valor predeterminado es "gzip".
tamañomax
El tamaño máximo en bytes de un solo lote *antes* de la compresión. El valor predeterminado es 500000 bytes.
tiempolote
Una lista separada por comas de las horas durante las cuales se deben generar lotes para un sitio determinado. Cuando se ejecuta send-uucp, un sitio solo se procesará si la hora actual coincide con una de las horas en tiempolote. El valor predeterminado es no limitar cuándo generar lotes.

Los campos están separados por espacios y solo es necesario especificar el nombre del sitio, utilizando los valores predeterminados para los valores no especificados. Si el primer carácter de una línea es un signo de almohadilla ("#"), se ignora el resto de la línea.

EJEMPLO

Aquí hay un ejemplo para el archivo de configuración send-uucp.cf:

zoetermeer      gzip            1048576         5,18,22
hoofddorp       gzip            1048576         5,18,22
pa3ebv          gzip            1048576         5,18,22
drinkel         bzip2           1048576         5,6,18,20,22,0,2
manhole         compress        1048576         5,18,22
owl             compress        1048576
able
pern::MYFUNNEL!

Esto define ocho sitios UUCP. Los tres primeros y los dos últimos usan compresión "gzip", el cuarto sitio ("drinkel") usa "bzip2" y los sitios restantes ("manhole" y "owl") usan "compress". Los seis primeros usan un tamaño de lote de 1 MB, y los dos últimos sitios ("able" y "pern") usan el valor predeterminado de 500.000 bytes. A "zoetermeer", "hoofddorp", "pa3ebv" y "manhole" solo se les generarán lotes durante las horas 05:00, 18:00 y 22:00, y al sitio "drinkel" solo se le generarán lotes durante esas horas y las 06:00, 20:00, 00:00 y 02:00. No hay restricciones sobre cuándo se generan lotes para "owl", "able" y "pern".

El sitio "pern" está configurado como un embudo hacia "MYFUNNEL!". send-uucp emitirá "ctlinnd flush MYFUNNEL!" en lugar de "ctlinnd flush pern".

En cuanto al archivo newsfeeds, las banderas habituales utilizadas para una alimentación UUCP son "Tf,Wnb". Aquí hay una entrada típica para "zoetermeer", donde el lotes se mantiene entre 4 KB y 1 KB:

zoetermeer\
    :*,!junk,!control,!control.*/!foo\
    :Tf,Wnb,B4096/1024:

CONFIGURACIÓN DE ALIMENTACIONES UUCP

Aquí están los pasos a seguir para configurar una alimentación UUCP sobre SSH entre dos servidores de noticias, utilizando la implementación UUCP disponible en Debian como el paquete "uucp". Los mecanismos descritos a continuación deben transponerse si utiliza otra implementación UUCP. (Y si lo hace, informe a los mantenedores de INN sobre cómo configurar una alimentación con otra implementación UUCP, para que pueda agregarse a esta documentación).).

1.
Antes que nada, asegúrese de que rnews esté correctamente instalado setuid "news", propiedad del grupo "uucp" y con modo 4550. Esto permitirá que el subsistema UUCP ejecute rnews para procesar lotes UUCP de artículos de noticias. El indicador de "configure" --enable-uucp-rnews se encarga de ello al instalar INN. De lo contrario, tendrá que cambiar manualmente los permisos de rnews.
2.
Instale el paquete "uucp". Proporcionará notablemente uucico(8) y uux(1).
3.
Configure en /etc/uucp/Poll los servidores de noticias remotos a los que consultar y las horas durante las cuales se consultarán. Por ejemplo, si envía lotes de noticias a "news.server.to.feed" cada 4 horas, puede usar: 
schedule news.server.to.feed 00
poll news.server.to.feed 00 04 08 12 16 20

Si el envío es cada hora, simplemente liste todas las horas.

4.
Configure en /etc/uucp/call las credenciales (nombres de usuario y contraseñas) a utilizar al autenticarse en servidores de noticias remotos, una por línea. Por ejemplo: 
news.server.to.feed login password
5.
Configure en /etc/uucp/config el nombre UUCP del servidor de noticias local. Por ejemplo: 
nodename my.news.server
6.
Verifique que /etc/uucp/expire se ajuste a sus necesidades en cuanto al número de días que se retienen los lotes, así como la configuración de informes diarios. Los valores predeterminados suelen estar bien, aunque es posible que desee recibir un informe diario solo si ocurren cosas inusuales (y en ese caso, simplemente establezca $important_only en 1).
7.
Configure en /etc/uucp/passwd las credenciales (nombres de usuario y contraseñas separados por una tabulación) que los servidores de noticias remotos utilizan al autenticarse en el servidor de noticias local, una por línea. Por ejemplo: 
login<TAB>password
8.
Configure en /etc/uucp/sys cómo

send-uucp(8) — Arch Linux man pages

NAME

send-uucp

creates news batches for sending via UUCP

SYNOPSIS

send-uucp [-h]

DESCRIPTION

The send-uucp utility prepares batches of news articles to be sent to remote news servers via UUCP. It scans the outgoing news directories, compresses the articles as specified in its configuration file, and creates the batch files that will be transferred by UUCP programs like uucico.

OPTIONS

-h
Prints a short usage message and exits.

CONFIGURATION

The behavior of send-uucp is controlled by the file pathetc/send-uucp.cf.

This file consists of lines, each specifying how to handle a particular remote news server. The general format of a line is:

site_name compression_method max_batch_size batch_interval

site_name
The name of the remote news server (e.g., news.server.to.feed).
compression_method
The compression method to use. Supported methods include none, gzip, bzip2, and lz4.
max_batch_size
The maximum size of a news batch in bytes. Larger batches can be more efficient but may take longer to transfer.
batch_interval
A comma-separated list of minutes past the hour at which batches should be generated for this site. For example, 3,7,11,15,19,23 means batches will be generated at minutes 3, 7, 11, 15, 19, and 23 of every hour.

Comments start with a # and extend to the end of the line.

EXAMPLE

A typical configuration line in pathetc/send-uucp.cf might look like this:

news.server.to.feed   bzip2      1048576   3,7,11,15,19,23

This line specifies that for the remote server news.server.to.feed, batches should be compressed using bzip2, have a maximum size of 1048576 bytes (1 MiB), and be generated at minutes 3, 7, 11, 15, 19, and 23 of each hour.

SETTING UP UUCP FEEDS

To set up UUCP feeds for news articles, follow these steps:

1.
Ensure you have a working UUCP installation and that the inn package is properly configured to send and receive news. This typically involves configuring files like /etc/uucp/config, /etc/uucp/sys, and /etc/uucp/poll.
2.
Configure how local news servers connect to remote news servers. Edit /etc/uucp/newsrequests and add entries for each remote server you want to feed. For example:
news.server.to.feed     /usr/bin/rnews
3.
Configure how remote news servers connect to your local news server. Edit /etc/uucp/remote.unknown and add entries for each remote server. This file typically contains commands to execute when a remote server connects, such as calling rnews to process incoming articles.
4.
Define the connections to remote news servers in /etc/uucp/port. A typical entry for an SSH connection might look like this, where pathbin should be replaced with the actual path to rnews:
system news.server.to.feed
   local-uucp-program /usr/bin/uucico
   protocol-version 2
   port ssh.news.server.to.feed
   max-commands 1
   send-batch-request
   send-batch-reply

port ssh.news.server.to.feed
   type pipe
   command /bin/ssh -a -x -q -l uucp news.server.to.feed
   reliable true
   protocol etyig
5.
Set up the UUCP system definitions. In /etc/uucp/sys, define the remote news servers. For example:
news.server.to.feed
   time any
   port ssh.news.server.to.feed
   protocol i
   address news.server.to.feed
   peer-uucp-uid uucp
   peek-remote
6.
Ensure that SSH keys are set up correctly for the uucp user. On the local server, the private key (e.g., /var/spool/uucp/.ssh/id_private_key) should be used for connecting to the remote server. On the remote server, the corresponding public key must be added to the /var/spool/uucp/.ssh/authorized_keys file for the uucp user. This ensures that the SSH connection is restricted to UUCP-related operations.
7.
Make sure the private key file (id_private_key) is accessible only by the uucp user.
8.
Manually test the SSH connection as the uucp user to create the known_hosts file and verify the SSH setup:
/bin/ssh -a -x -q -i <key> -l uucp news.server.to.feed
9.
Define how to send news to remote servers in the newsfeeds file. A typical entry to generate batches in pathoutgoing is:
news.server.to.feed/pathname:*:Tf,Wnb,B4096/1024:
10.
Configure compression, batch sizes, and generation times in send-uucp.cf (located in pathetc). For example:
news.server.to.feed   bzip2      1048576   3,7,11,15,19,23
11.
Ensure that send-uucp is run periodically by the news user, typically via cron. For instance, in /etc/cron.d/inn2:
52 * * * * news <pathbin>/send-uucp

It's advisable to stagger the execution times with remote servers to improve batch exchange frequency.

12.
Verify that UUCP programs are automatically started by cron. Usually, uudemon.hr is called hourly (e.g., in /etc/cron.d/uucp) to poll remote servers, and uudemon.day daily (e.g., in /etc/cron.daily/uucp).

Adjust the start times of these daemons to optimize the frequency and freshness of exchanged batches.

13.
Check the logs in /var/log/uucp to confirm that both polling and sending operations are working correctly. send-uucp prepares batches (e.g., D.0I8Y) for rnews, which are then queued by uux. When uucico runs, it transfers these batches and simultaneously retrieves any available batches from remote sites. These received batches are processed by uuxqt, which in turn calls rnews to inject them.

That's all!

FILES

pathbin/send-uucp
The Perl script itself used to create news batches from the outgoing files.
pathetc/send-uucp.cf
The configuration file which specifies a list of sites to be processed.
pathlog/send-uucp.log
The log file used if the syslog facility is not available.
