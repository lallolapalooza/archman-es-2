set_tid_address(2) Manual de llamadas al sistema set_tid_address(2)

NOMBRE

set_tid_address - establecer puntero al ID del hilo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/syscall.h>      /* Definición de constantes SYS_* */
#include <unistd.h>
pid_t syscall(SYS_set_tid_address, int *tidptr);

Nota: glibc no proporciona un envoltorio para set_tid_address(), lo que requiere el uso de syscall(2).

DESCRIPCIÓN

Para cada hilo, el kernel mantiene dos atributos (direcciones) llamados set_child_tid y clear_child_tid. Estos dos atributos contienen el valor NULL por defecto.

set_child_tid
Si se inicia un hilo usando clone(2) con la bandera CLONE_CHILD_SETTID, set_child_tid se establece al valor pasado en el argumento ctid de esa llamada al sistema.
Cuando set_child_tid está establecido, lo primero que hace el nuevo hilo es escribir su ID de hilo en esta dirección.
clear_child_tid
Si se inicia un hilo usando clone(2) con la bandera CLONE_CHILD_CLEARTID, clear_child_tid se establece al valor pasado en el argumento ctid de esa llamada al sistema.

La llamada al sistema set_tid_address() establece el valor clear_child_tid para el hilo que llama a tidptr.

Cuando un hilo cuyo clear_child_tid no es NULL termina, entonces, si el hilo comparte memoria con otros hilos, se escribe 0 en la dirección especificada en clear_child_tid y el kernel realiza la siguiente operación:


futex(clear_child_tid, FUTEX_WAKE, 1, NULL, NULL, 0);

El efecto de esta operación es despertar a un solo hilo que está realizando una espera futex en la ubicación de memoria. Los errores de la operación de despertar futex se ignoran.

VALOR DE RETORNO

set_tid_address() siempre devuelve el ID del hilo del llamante.

ERRORES

set_tid_address() siempre tiene éxito.

ESTÁNDARES

Linux.

HISTORIA

Linux 2.5.48.

Los detalles proporcionados aquí son válidos desde Linux 2.5.49.

VER TAMBIÉN

clone(2), futex(2), gettid(2)
