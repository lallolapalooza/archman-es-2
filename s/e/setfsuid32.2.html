setfsuid(2) Manual de llamadas al sistema setfsuid(2)

NOMBRE

setfsuid - establece la identidad de usuario utilizada para las comprobaciones del sistema de archivos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/fsuid.h>
[[deprecated]] int setfsuid(uid_t fsuid);

DESCRIPCIÓN

En Linux, un proceso tiene tanto un ID de usuario del sistema de archivos como un ID de usuario efectivo. El ID de usuario del sistema de archivos (específico de Linux) se utiliza para la comprobación de permisos al acceder a objetos del sistema de archivos, mientras que el ID de usuario efectivo se utiliza para varios otros tipos de comprobaciones de permisos (consulte credentials(7)).

Normalmente, el valor del ID de usuario del sistema de archivos del proceso es el mismo que el valor de su ID de usuario efectivo. Esto se debe a que cada vez que se cambia el ID de usuario efectivo de un proceso, el kernel también cambia el ID de usuario del sistema de archivos para que sea igual al nuevo valor del ID de usuario efectivo. Un proceso puede hacer que el valor de su ID de usuario del sistema de archivos difiera del de su ID de usuario efectivo utilizando setfsuid() para cambiar su ID de usuario del sistema de archivos al valor dado en fsuid.

Las llamadas explícitas a setfsuid() y setfsgid(2) eran (son) normalmente utilizadas solo por programas como el servidor NFS de Linux que necesitan cambiar qué ID de usuario y grupo se utiliza para el acceso a archivos sin un cambio correspondiente en los ID de usuario y grupo reales y efectivos. Un cambio en los ID de usuario normales para un programa como el servidor NFS era (es) un agujero de seguridad que podía exponerlo a señales no deseadas. (Sin embargo, este problema es histórico; consulte más abajo).

setfsuid() solo tendrá éxito si el llamante es el superusuario o si fsuid coincide con el ID de usuario real del llamante, el ID de usuario efectivo, el ID de usuario guardado del conjunto, o el ID de usuario actual del sistema de archivos.

VALOR DE RETORNO

Tanto en caso de éxito como de error, esta llamada devuelve el ID de usuario del sistema de archivos anterior del llamante.

ESTANDARES

Linux.

HISTORIA

Linux 1.2.

Cuando se introdujo esta llamada al sistema, un proceso podía enviar una señal a otro proceso con el mismo ID de usuario efectivo. Esto significaba que si un proceso privilegiado cambiaba su ID de usuario efectivo con el propósito de la comprobación de permisos de archivos, entonces podía quedar vulnerable a recibir señales enviadas por otro proceso (no privilegiado) con el mismo ID de usuario. Por lo tanto, se añadió el atributo de ID de usuario del sistema de archivos para permitir que un proceso cambiara su ID de usuario para fines de comprobación de permisos de archivos sin volverse vulnerable al mismo tiempo a recibir señales de procesos no deseados. Desde Linux 2.0, el manejo de permisos de señales es diferente (consulte kill(2)), con el resultado de que un proceso puede cambiar su ID de usuario efectivo sin ser vulnerable a recibir señales de procesos no deseados. Por lo tanto, setfsuid() hoy en día es innecesario y debe evitarse en aplicaciones nuevas (lo mismo para setfsgid(2)).

La llamada al sistema original de Linux setfsuid() solo admitía ID de usuario de 16 bits. Posteriormente, Linux 2.4 añadió setfsuid32() que admitía ID de 32 bits. La función de envoltura setfsuid() de glibc maneja de forma transparente la variación entre versiones del kernel.

Diferencias biblioteca C/kernel

En glibc 2.15 y anteriores, cuando la envoltura de esta llamada al sistema determina que el argumento no puede pasarse al kernel sin truncamiento de enteros (porque el kernel es antiguo y no admite ID de usuario de 32 bits), devolverá -1 y establecerá errno a EINVAL sin intentar la llamada al sistema.

ERRORES

No se devuelven indicaciones de error de ningún tipo al llamante, y el hecho de que tanto las llamadas exitosas como las fallidas devuelvan el mismo valor hace imposible determinar directamente si la llamada tuvo éxito o falló. En su lugar, el llamante debe recurrir a examinar el valor de retorno de una llamada adicional como setfsuid(-1) (que siempre fallará), para determinar si una llamada previa a setfsuid() cambió el ID de usuario del sistema de archivos. Como mínimo, se debería devolver EPERM cuando la llamada falla (porque el llamante carece de la capacidad CAP_SETUID).

VER TAMBIÉN

kill(2), setfsgid(2), capabilities(7), credentials(7)
