SED(1P) Manual del Programador de POSIX SED(1P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador de POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

sed — editor de flujos

SINOPSIS

sed [-n] script [archivo...]
sed [-n] -e script [-e script]... [-f archivo_script]... [archivo...]
sed [-n] [-e script]... -f archivo_script [-f archivo_script]... [archivo...]

DESCRIPCIÓN

La utilidad sed es un editor de flujos que leerá uno o más archivos de texto, realizará cambios de edición de acuerdo con un script de comandos de edición, y escribirá los resultados en la salida estándar. El script se obtendrá de la cadena del operando script o de una combinación de los argumentos de opción de las opciones -e script y -f archivo_script.

OPCIONES

La utilidad sed cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis de Utilidades, excepto que el orden de presentación de las opciones -e y -f es significativo.

Se soportarán las siguientes opciones:

-e script
Añade los comandos de edición especificados por el argumento de opción script al final del script de comandos de edición.
-f archivo_script
Añade los comandos de edición del archivo archivo_script al final del script de comandos de edición.
-n
Suprime la salida predeterminada (en la que cada línea, después de ser examinada para edición, se escribe en la salida estándar). Solo se escriben las líneas explícitamente seleccionadas para su salida.

Si se especifican opciones -e o -f, el script de comandos de edición estará inicialmente vacío. Los comandos especificados por cada opción -e o -f se añadirán al script en el orden especificado. Cuando se realice cada adición, si la adición anterior (si hubo alguna) provino de una opción -e, se insertará un <salto de línea> antes de la nueva adición. El script resultante tendrá las mismas propiedades que el operando script, descrito en la sección OPERANDOS.

OPERANDOS

Se soportarán los siguientes operandos:

archivo
Un nombre de ruta de un archivo cuyo contenido se lee y edita. Si se especifican varios operandos archivo, los archivos nombrados se leerán en el orden especificado y se editará la concatenación. Si no se especifican operandos archivo, se utilizará la entrada estándar.
script
Una cadena que se utilizará como script de comandos de edición. La aplicación no presentará un script que viole las restricciones de un archivo de texto, excepto que el carácter final no necesita ser un <salto de línea>.

ENTRADA ESTÁNDAR

La entrada estándar se utilizará si no se especifican operandos archivo, y se utilizará si un operando archivo es '-' y la implementación trata el '-' como entrada estándar. De lo contrario, la entrada estándar no se utilizará. Consulte la sección ARCHIVOS DE ENTRADA.

ARCHIVOS DE ENTRADA

Los archivos de entrada serán archivos de texto. Los archivo_scripts nombrados por la opción -f consistirán en comandos de edición.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de sed:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_COLLATE

Determina la localización para el comportamiento de rangos, clases de equivalencia y elementos de ordenación multicarácter dentro de expresiones regulares.
LC_CTYPE
Determina la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en argumentos y archivos de entrada), y el comportamiento de las clases de caracteres dentro de expresiones regulares.
LC_MESSAGES

Determina la localización que debe utilizarse para afectar al formato y contenido de los mensajes de diagnóstico escritos en la salida de error estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASINCRONOS

Predeterminado.

SALIDA ESTÁNDAR

Los archivos de entrada se escribirán en la salida estándar, con los comandos de edición especificados en el script aplicados. Si se especifica la opción -n, solo se escribirán en la salida estándar las líneas de entrada seleccionadas por el script.

SALIDA DE ERROR ESTÁNDAR

La salida de error estándar se utilizará solo para mensajes de diagnóstico y advertencia.

ARCHIVOS DE SALIDA

Los archivos de salida serán archivos de texto cuyos formatos dependen de los comandos de edición dados.

DESCRIPCIÓN EXTENDIDA

El script consistirá en comandos de edición de la siguiente forma:

[direccion[,direccion]]funcion

donde funcion representa un comando de un solo carácter de la lista en Comandos de Edición en sed, seguido de los argumentos aplicables.

El comando puede ir precedido por caracteres de espacio en blanco y/o caracteres de punto y coma. La función puede ir precedida por caracteres de espacio en blanco. Estos caracteres opcionales no tendrán ningún efecto.

En la operación predeterminada, sed anexa cíclicamente una línea de entrada, sin su carácter de terminación <salto de línea>, al espacio de patrón. La lectura de la entrada se omitirá si un <salto de línea> estaba en el espacio de patrón antes de un comando D que finalizaba el ciclo anterior. La utilidad sed aplicará entonces en secuencia todos los comandos cuyas direcciones seleccionen ese espacio de patrón, hasta que un comando inicie el siguiente ciclo o termine. Si ningún comando inició explícitamente un nuevo ciclo, entonces al final del script, el espacio de patrón se copiará a la salida estándar (excepto cuando se especifica -n) y el espacio de patrón se eliminará. Siempre que el espacio de patrón se escriba en la salida estándar o en un archivo con nombre, sed lo seguirá inmediatamente con un <salto de línea>.

Algunos de los comandos de edición utilizan un espacio de retención para guardar todo o parte del espacio de patrón para su posterior recuperación. Los espacios de patrón y de retención podrán contener al menos 8192 bytes.

COMMANDS

[1addr]a
Append text space, after the pattern space, up to the first <newline>, to standard output.
[1addr]c
Change the pattern space to the text that follows, up to the next <newline>. Any character other than <backslash> or <newline> can be used instead of a <slash> to delimit the text. Within the text, the delimiter itself can be used as a literal character if it is preceded by a <backslash>. A followed by a is treated as a literal .
[1addr]d
Delete the pattern space from the work space. Start the next cycle.
[1addr]D
Delete the pattern space from the work space, up to the first <newline>. Start the next cycle.
[1addr]i
Insert text space, after the pattern space, up to the first <newline>, to standard output.
[1addr]q
Branch to the end of the script and quit without starting a new cycle.
[1addr]r rfile
Copy the contents of rfile to standard output as described previously. If rfile does not exist or cannot be read, it shall be treated as if it were an empty file, causing no error condition.
[2addr]s/BRE/replacement/flags

Substitute the replacement string for instances of the BRE in the pattern space. Any character other than <backslash> or <newline> can be used instead of a <slash> to delimit the BRE and the replacement. Within the BRE and the replacement, the BRE delimiter itself can be used as a literal character if it is preceded by a <backslash>.

The replacement string shall be scanned from beginning to end. An <ampersand> ('&') appearing in the replacement shall be replaced by the string matching the BRE. The special meaning of '&' in this context can be suppressed by preceding it by a <backslash>. The characters "\n", where n is a digit, shall be replaced by the text matched by the corresponding back-reference expression. If the corresponding back-reference expression does not match, then the characters "\n" shall be replaced by the empty string. The special meaning of "\n" where n is a digit in this context, can be suppressed by preceding it by a <backslash>. For each other <backslash> encountered, the following character shall lose its special meaning (if any).

A line can be split by substituting a <newline> into it. The application shall escape the <newline> in the replacement by preceding it by a <backslash>.

The meaning of an unescaped <backslash> immediately followed by any character other than '&', <backslash>, a digit, <newline>, or the delimiter character used for this command, is unspecified.

A substitution shall be considered to have been performed even if the replacement string is identical to the string that it replaces. Any <backslash> used to alter the default meaning of a subsequent character shall be discarded from the BRE or the replacement before evaluating the BRE or using the replacement.

The value of flags shall be zero or more of:

n
Substitute for the nth occurrence only of the BRE found within the pattern space.
g
Globally substitute for all non-overlapping instances of the BRE rather than just the first one. If both g and n are specified, the results are unspecified.
p
Write the pattern space to standard output if a replacement was made.
w wfile
Write. Append the pattern space to wfile if a replacement was made. A conforming application shall precede the wfile argument with one or more <blank> characters. If the w flag is not the last flag value given in a concatenation of multiple flag values, the results are undefined.
[2addr]t [label]

Test. Branch to the : command verb bearing the label if any substitutions have been made since the most recent reading of an input line or execution of a t. If label is not specified, branch to the end of the script.
[2addr]w wfile

Append (write) the pattern space to wfile.
[2addr]x
Exchange the contents of the pattern and hold spaces.
[2addr]y/string1/string2/

Replace all occurrences of characters in string1 with the corresponding characters in string2. If a <backslash> followed by an 'n' appear in string1 or string2, the two characters shall be handled as a single <newline>. If the number of characters in string1 and string2 are not equal, or if any of the characters in string1 appear more than once, the results are undefined. Any character other than <backslash> or <newline> can be used instead of <slash> to delimit the strings. If the delimiter is not 'n', within string1 and string2, the delimiter itself can be used as a literal character if it is preceded by a <backslash>. If a <backslash> character is immediately followed by a <backslash> character in string1 or string2, the two <backslash> characters shall be counted as a single literal <backslash> character. The meaning of a <backslash> followed by any character that is not 'n', a <backslash>, or the delimiter character is undefined.
[0addr]:label
Do nothing. This command bears a label to which the b and t commands branch.
[1addr]=
Write the following to standard output:
"%d\n", <current line number>
[0addr]
Ignore this empty command.
[0addr]#
Ignore the '#' and the remainder of the line (treat them as a comment), with the single exception that if the first two characters in the script are "#n", the default output shall be suppressed; this shall be the equivalent of specifying -n on the command line.

CONSECUENCIAS DE LOS ERRORES

Por defecto.

Las siguientes secciones son informativas.

USO DE LA APLICACIÓN

Las expresiones regulares coinciden con cadenas completas, no solo con líneas individuales, pero un <salto de línea> coincide con '\n' en un RE de sed; un <salto de línea> no está permitido por la definición general de expresión regular en POSIX.1-2008. Tenga en cuenta también que '\n' no se puede utilizar para que coincida con un <salto de línea> al final de una línea de entrada arbitraria; los caracteres de <salto de línea> aparecen en el espacio de patrones como resultado del comando de edición N.

Al utilizar sed para procesar nombres de ruta, se recomienda que LC_ALL, o al menos LC_CTYPE y LC_COLLATE, se establezcan en POSIX o C en el entorno, ya que los nombres de ruta pueden contener secuencias de bytes que no forman caracteres válidos en algunas configuraciones regionales, en cuyo caso el comportamiento de la utilidad no estaría definido. En la configuración regional POSIX, cada byte es un carácter válido de un solo byte y, por lo tanto, este problema se evita.

EJEMPLOS

Este script de sed simula el comando cat -s de BSD, comprimiendo líneas vacías excesivas de la entrada estándar.

sed -n '
# Escribe líneas no vacías.
/./ {
    p
    d
    }
# Escribe una sola línea vacía, luego busca más líneas vacías.
/^$/    p
# Obtiene la siguiente línea, descarta la línea vacía conservada (<salto de línea>),
# y busca más líneas vacías.
:Empty
/^$/    {
    N
    s/.//
    b Empty
    }
# Escribe la línea no vacía antes de volver a buscar
# la primera de un conjunto de líneas vacías.
    p
'

El siguiente comando sed es un método mucho más simple para comprimir líneas vacías, aunque no es exactamente lo mismo que cat -s ya que elimina las líneas vacías iniciales:

sed -n '/./,/^$/p'

FUNDAMENTO

Este volumen de POSIX.1-2017 requiere que las implementaciones admitan al menos diez wfiles distintos, lo que coincide con la práctica histórica en muchas implementaciones. Se anima a las implementaciones a admitir más, pero las aplicaciones que cumplan no deben exceder este límite.

Los códigos de estado de salida especificados aquí son diferentes de los de System V. System V devuelve 2 para comandos sed corruptos, pero devuelve cero con su mensaje de uso o si el archivo de entrada no se pudo abrir. Los desarrolladores del estándar consideraron que esto era un error.

La forma en que el comando l escribe caracteres no imprimibles se modificó para evitar el método histórico de retroceso y sobreescritura, y se agregaron otros requisitos para lograr una salida inequívoca. Consulte el FUNDAMENTO de ed para obtener detalles sobre el formato elegido, que es el mismo que el elegido para sed.

Este volumen de POSIX.1-2017 requiere que las implementaciones proporcionen espacios de patrón y retención de al menos 8192 bytes, más que los espacios de 4000 bytes utilizados por algunas implementaciones históricas, pero menos que el límite de 20480 bytes utilizado en una propuesta temprana. Se anima a las implementaciones a asignar dinámicamente espacios de patrón y retención más grandes según sea necesario.

Los requisitos para la aceptación de caracteres de <espacio en blanco> y <espacio> en las líneas de comandos se han hecho más explícitos que en propuestas anteriores para describir claramente la práctica histórica y eliminar la confusión sobre la frase ``proteger los espacios en blanco iniciales [sic] y las tabulaciones de la eliminación que se realiza en cada línea del script'' que aparece en gran parte de la documentación histórica de la descripción de texto de la utilidad sed. (No se sabe que todas las implementaciones hayan eliminado caracteres de <espacio en blanco> de las líneas de texto, aunque todas han permitido caracteres de <espacio en blanco> iniciales precediendo la dirección en una línea de comando).

El tratamiento de los comentarios '#' difiere del SVID, que solo permite un comentario como la primera línea del script, pero coincide con las implementaciones derivadas de BSD. El carácter de comentario se trata como un comando, y tiene las mismas propiedades en términos de ser aceptado con caracteres de <espacio en blanco> iniciales; la implementación de BSD históricamente ha admitido esto.

Las propuestas anteriores requerían que un archivo_script tuviera al menos una línea que no fuera un comentario. Algunas implementaciones históricas se han comportado de maneras inesperadas si este no fuera el caso. Los desarrolladores del estándar consideraron que esto era incorrecto.

APPLICATION USAGE

The sed utility is intended for use by shell-script maintainers and application developers.

EXAMPLES

#!/bin/sh
# Example of how to delete all lines containing "DELETE"
sed '/DELETE/d' < input.file > output.file

# Example of how to replace all occurrences of "old" with "new"
sed 's/old/new/g' < input.file > output.file

# Example of how to replace the first occurrence of "old" on each line
# with "new".
sed 's/old/new/' < input.file > output.file

# Example of how to replace the first occurrence of "old" on lines 1 through 5
# with "new".
sed '1,5s/old/new/' < input.file > output.file

# Example of how to replace the third occurrence of "old" on each line
# with "new".
sed 's/old/new/3' < input.file > output.file

# Example of how to replace all occurrences of "old" with "new" only
# on lines that contain "MATCHME".
sed '/MATCHME/s/old/new/g' < input.file > output.file

# Example of how to replace all occurrences of "old" with "new" on lines
# that do not contain "NOMATCH".
sed '/NOMATCH/!s/old/new/g' < input.file > output.file

# Example of how to print only lines that contain "PRINTME".
sed -n '/PRINTME/p' < input.file > output.file

# Example of how to append the string "appended" to lines that contain
# "ENDME".
sed '/ENDME/s/$/appended/' < input.file > output.file

# Example of how to prepend the string "prepended" to lines that contain
# "STARTME".
sed '/STARTME/s/^/prepended/' < input.file > output.file

# Example of how to delete leading and trailing white space from lines.
sed -e 's/^[[:space:]]*//' -e 's/[[:space:]]*$//' < input.file > output.file

# Example of how to delete leading and trailing white space from lines.
# This example uses the '-e' option multiple times.
sed -e 's/^[[:space:]]*//' -e 's/[[:space:]]*$//' < input.file > output.file

# Example of how to delete leading and trailing white space from lines.
# This example uses semicolons to separate commands.
sed 's/^[[:space:]]*//; s/[[:space:]]*$//' < input.file > output.file

# Example of how to read commands from a file.
sed -f commands.sed < input.file > output.file

# Example of how to read commands from a file and process
# the results with inline commands.
sed -f commands.sed -e 's/a/A/g' < input.file > output.file

# Example of how to use branching.
sed '
    /start/ b next_step
    /end/ b
    d
    :next_step
    s/foo/bar/
' < input.file > output.file

RATIONALE

The standard developers considered allowing an empty file name for the -f option, but decided against it because it would have been ambiguous. It is not clear whether an empty file name should refer to standard input or to an empty script file. Both are permitted by the standard.

The POSIX.1-2017 standard requires that an empty script file be permitted. This is based on the behavior of the historical 4.3 Berkeley Software Distribution (BSD) version of sed. It is reasonable for application developers to expect that an empty script file should have no effect on the input, and that application developers should not have to avoid this feature. A correct implementation of this volume of POSIX.1-2017 shall permit script_files that consist only of comment lines.

Early proposals indicated that if -e and -f options were intermixed, all -e options were processed before any -f options. This has been changed to process them in the order presented because it matches historical practice and is more intuitive.

The treatment of the p flag to the s command differs between System V and BSD-based systems when the default output is suppressed. In the two examples:

echo a | sed    's/a/A/p'
echo a | sed -n 's/a/A/p'

this volume of POSIX.1-2017, BSD, System V documentation, and the SVID indicate that the first example should write two lines with A, whereas the second should write one. Some System V systems write the A only once in both examples because the p flag is ignored if the -n option is not specified.

This is a case of a diametrical difference between systems that could not be reconciled through the compromise of declaring the behavior to be unspecified. The SVID/BSD/System V documentation behavior was adopted for this volume of POSIX.1-2017 because:

*
No known documentation for any historic system describes the interaction between the p flag and the -n option.
*
The selected behavior is more correct as there is no technical justification for any interaction between the p flag and the -n option. A relationship between -n and the p flag might imply that they are only used together, but this ignores valid scripts that interrupt the cyclical nature of the processing through the use of the D, d, q, or branching commands. Such scripts rely on the p suffix to write the pattern space because they do not make use of the default output at the ``bottom'' of the script.
*
Because the -n option makes the p flag unnecessary, any interaction would only be useful if sed scripts were written to run both with and without the -n option. This is believed to be unlikely. It is even more unlikely that programmers have coded the p flag expecting it to be unnecessary. Because the interaction was not documented, the likelihood of a programmer discovering the interaction and depending on it is further decreased.
*
Finally, scripts that break under the specified behavior produce too much output instead of too little, which is easier to diagnose and correct.

The form of the substitute command that uses the n suffix was limited to the first 512 matches in an early proposal. This limit has been removed because there is no reason an editor processing lines of {LINE_MAX} length should have this restriction. The command s/a/A/2047 should be able to substitute the 2047th occurrence of a on a line.

The b, t, and : commands are documented to ignore leading white space, but no mention is made of trailing white space. Historical implementations of sed assigned different locations to the labels 'x' and "x ". This is not useful, and leads to subtle programming errors, but it is historical practice, and changing it could theoretically break working scripts. Implementors are encouraged to provide warning messages about labels that are never referenced by a b or t command, jumps to labels that do not exist, and label arguments that are subject to truncation.

Earlier versions of this standard allowed for implementations with bytes other than eight bits, but this has been modified in this version.
