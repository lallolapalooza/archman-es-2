getgroups(2) System Calls Manual getgroups(2)

NOMBRE

getgroups, setgroups - obtener/establecer lista de IDs de grupo suplementarios

LIBRERÍA

Biblioteca estándar C (libc, -lc)

SINOPSIS

#include <unistd.h>
int getgroups(int size, gid_t list[_Nullable size]);
#include <grp.h>
int setgroups(size_t size, const gid_t list[size]);
Requisitos de Macro de Prueba de Funcionalidad para glibc (ver feature_test_macros(7)):

setgroups():

    Desde glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 y anteriores:
        _BSD_SOURCE

DESCRIPCIÓN

getgroups() devuelve los IDs de grupo suplementarios del proceso que llama en list. El argumento size debe establecerse al número máximo de elementos que se pueden almacenar en el búfer al que apunta list. Si el proceso que llama es miembro de más de size grupos suplementarios, se produce un error.

No está especificado si el ID de grupo efectivo del proceso que llama está incluido en la lista devuelta. (Por lo tanto, una aplicación también debería llamar a getegid(2) y agregar o quitar el valor resultante).

Si size es cero, list no se modifica, pero se devuelve el número total de IDs de grupo suplementarios del proceso. Esto permite al llamador determinar el tamaño de una list asignada dinámicamente para ser utilizada en una llamada adicional a getgroups().

setgroups() establece los IDs de grupo suplementarios para el proceso que llama. Se requieren privilegios apropiados (ver la descripción del error EPERM, abajo). El argumento size especifica el número de IDs de grupo suplementarios en el búfer al que apunta list. Un proceso puede eliminar todos sus grupos suplementarios con la llamada:


setgroups(0, (gid_t [0]){});

VALOR DE RETORNO

En caso de éxito, getgroups() devuelve el número de IDs de grupo suplementarios. En caso de error, se devuelve -1 y se establece errno para indicar el error.

En caso de éxito, setgroups() devuelve 0. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EFAULT
list tiene una dirección inválida.

getgroups() puede fallar adicionalmente con el siguiente error:

EINVAL
size es menor que el número de IDs de grupo suplementarios, pero no es cero.

setgroups() puede fallar adicionalmente con los siguientes errores:

EINVAL
size es mayor que NGROUPS_MAX (32 antes de Linux 2.6.4; 65536 desde Linux 2.6.4).
ENOMEM
Falta de memoria.
EPERM
El proceso que llama tiene privilegios insuficientes (el llamador no tiene la capacidad CAP_SETGID en el espacio de nombres de usuario en el que reside).
EPERM (desde Linux 3.19)
El uso de setgroups() está denegado en este espacio de nombres de usuario. Ver la descripción de /proc/pid/setgroups en user_namespaces(7).

VERSIÓNES

Diferencias entre la biblioteca C y el kernel

A nivel de kernel, los IDs de usuario y grupo son un atributo por hilo. Sin embargo, POSIX requiere que todos los hilos de un proceso compartan las mismas credenciales. La implementación de hilos NPTL maneja los requisitos de POSIX proporcionando funciones de envoltura para las diversas llamadas al sistema que cambian los UID y GID del proceso. Estas funciones de envoltura (incluida la de setgroups()) emplean una técnica basada en señales para garantizar que cuando un hilo cambia las credenciales, todos los demás hilos del proceso también cambien sus credenciales. Para más detalles, ver nptl(7).

ESTÁNDARES

getgroups()
POSIX.1-2024.
setgroups()
Ninguno.

HISTORIA

getgroups()
SVr4, 4.3BSD, POSIX.1-2001.
setgroups()
SVr4, 4.3BSD. Dado que setgroups() requiere privilegios, no está cubierto por POSIX.1.

La llamada al sistema original getgroups() de Linux solo admitía IDs de grupo de 16 bits. Posteriormente, Linux 2.4 agregó getgroups32(), que admite IDs de 32 bits. La función de envoltura getgroups() de glibc maneja de forma transparente la variación entre versiones del kernel.

NOTAS

Un proceso puede tener hasta NGROUPS_MAX IDs de grupo suplementarios además del ID de grupo efectivo. La constante NGROUPS_MAX se define en <limits.h>. El conjunto de IDs de grupo suplementarios se hereda del proceso padre y se preserva a través de una llamada a execve(2).

El número máximo de IDs de grupo suplementarios se puede encontrar en tiempo de ejecución usando sysconf(3):


long ngroups_max;
ngroups_max = sysconf(_SC_NGROUPS_MAX);

El valor máximo de retorno de getgroups() no puede ser mayor que uno más que este valor. Desde Linux 2.6.4, el número máximo de IDs de grupo suplementarios también se expone a través del archivo de solo lectura específico de Linux, /proc/sys/kernel/ngroups_max.

EJEMPLOS

#include <err.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
#define MALLOC(n, T)  ((T *) reallocarray(NULL, n, sizeof(T)))
static gid_t *agetgroups(size_t *ngids);
int
main(void)
{
    gid_t   *gids;
    size_t  n;
    gids = agetgroups(&n);
    if (gids == NULL)
        err(EXIT_FAILURE, "agetgroups");
    if (n != 0) {
        printf("%jd", (intmax_t) gids[0]);
        for (size_t i = 1; i < n; i++)
            printf(" %jd", (intmax_t) gids[i]);
    }
    puts("");
    free(gids);
    exit(EXIT_SUCCESS);
}
static gid_t *
agetgroups(size_t *ngids)
{
    int    n;
    gid_t  *gids;
    n = getgroups(0, NULL);
    if (n == -1)
        return NULL;
    gids = MALLOC(n, gid_t);
    if (gids == NULL)
        return NULL;
    n = getgroups(n, gids);
    if (n == -1) {
        free(gids);
        return NULL;
    }
    *ngids = n;
    return gids;
}
