SET(1P) Manual del Programador POSIX SET(1P)

PROLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

set — establecer o anular opciones y parámetros posicionales

SINOPSIS

set [-abCefhmnuvx] [-o opción] [argumento...]
set [+abCefhmnuvx] [+o opción] [argumento...]
set -- [argumento...]
set -o
set +o

DESCRIPCIÓN

Si no se especifican opciones ni argumentos, set escribirá los nombres y valores de todas las variables del shell en la secuencia de ordenación de la configuración regional actual. Cada nombre comenzará en una línea separada, utilizando el formato:

"%s=%s\n", <nombre>, <valor>

La cadena valor se escribirá con el entrecomillado apropiado; consulte la descripción del entrecomillado del shell en la Sección 2.2, Entrecomillado. La salida será adecuada para reingresar al shell, estableciendo o restableciendo, en la medida de lo posible, las variables que estén actualmente establecidas; las variables de solo lectura no se pueden restablecer.

Cuando se especifican opciones, establecerán o anularán atributos del shell, como se describe a continuación. Cuando se especifican argumentos, estos causarán que los parámetros posicionales se establezcan o anulen, como se describe a continuación. El establecimiento o anulación de atributos y parámetros posicionales no son acciones necesariamente relacionadas, pero pueden combinarse en una única invocación de set.

La utilidad interna especial set deberá admitir las Definiciones Base del volumen POSIX.1‐2017, Sección 12.2, Guías de Sintaxis de Utilidades, excepto que las opciones pueden especificarse con un guion inicial <guion-menos> (lo que significa habilitar la opción) o un signo más <signo-mas> (lo que significa deshabilitarla), a menos que se especifique lo contrario.

Las implementaciones deberán admitir las opciones de la lista siguiente en sus formas de <guion-menos> y <signo-mas>. Estas opciones también pueden especificarse como opciones para sh.

-a
Cuando esta opción esté activada, el atributo export se establecerá para cada variable a la que se realice una asignación; consulte el volumen Definiciones Base de POSIX.1‐2017, Sección 4.23, Asignación de Variables. Si la asignación precede a un nombre de utilidad en un comando, el atributo export no persistirá en el entorno de ejecución actual después de que la utilidad se complete, con la excepción de que preceder a una de las utilidades internas especiales hace que el atributo export persista después de que la interna se complete. Si la asignación no precede a un nombre de utilidad en el comando, o si la asignación es el resultado de la operación de las utilidades getopts o read, el atributo export persistirá hasta que la variable sea anulada.
-b
Esta opción deberá admitirse si la implementación admite la opción Utilidades de Portabilidad de Usuario. Causará que el shell notifique al usuario de forma asíncrona sobre la finalización de trabajos en segundo plano. El siguiente mensaje se escribirá en el error estándar:
"[%d]%c %s%s\n", <número-de-trabajo>, <actual>, <estado>, <nombre-del-trabajo>

donde los campos serán los siguientes:

<actual>
El carácter '+' identifica el trabajo que se usaría como predeterminado para las utilidades fg o bg; este trabajo también se puede especificar usando el id-de-trabajo "%+" o "%%". El carácter '-' identifica el trabajo que se convertiría en predeterminado si el trabajo predeterminado actual saliera; este trabajo también se puede especificar usando el id-de-trabajo "%-". Para otros trabajos, este campo es un <espacio>. Como máximo, un trabajo puede identificarse con '+' y como máximo, un trabajo puede identificarse con '-'. Si hay algún trabajo suspendido, el trabajo actual será un trabajo suspendido. Si hay al menos dos trabajos suspendidos, entonces el trabajo anterior también será un trabajo suspendido.
<número-de-trabajo>
Un número que puede usarse para identificar el grupo de procesos a las utilidades wait, fg, bg y kill. Usando estas utilidades, el trabajo puede identificarse anteponiendo el número de trabajo con '%'.
<estado>
No especificado.
<nombre-del-trabajo>
No especificado.

Cuando el shell notifique al usuario que un trabajo ha finalizado, puede eliminar el ID del proceso del trabajo de la lista de los conocidos en el entorno de ejecución del shell actual; consulte la Sección 2.9.3.1, Ejemplos. La notificación asíncrona no estará habilitada por defecto.

-C
(C mayúscula). Evita que los archivos existentes sean sobrescritos por el operador de redirección '>' del shell (consulte la Sección 2.7.2, Redirección de Salida); el operador de redirección ">|" anulará esta opción noclobber para un archivo individual.
-e
Cuando esta opción esté activada, cuando cualquier comando falle (por cualquiera de las razones enumeradas en la Sección 2.8.1, Consecuencias de Errores del Shell o al devolver un estado de salida mayor que cero), el shell saldrá inmediatamente, como si ejecutara la utilidad interna especial exit sin argumentos, con las siguientes excepciones:
1.
El fallo de cualquier comando individual en una canalización de múltiples comandos no hará que el shell salga. Solo se considerará el fallo de la canalización en sí.
2.
La configuración -e se ignorará al ejecutar la lista compuesta que sigue a la palabra reservada while, until, if, o elif, una canalización que comience con la palabra reservada !, o cualquier comando de una lista AND-OR que no sea el último.
3.
Si el estado de salida de un comando compuesto que no sea un comando de subshell fue el resultado de un fallo mientras se ignoraba -e, entonces -e no se aplicará a este comando.

Este requisito se aplica al entorno del shell y a cada entorno de subshell por separado. Por ejemplo, en:

set -e; (false; echo one) | cat; echo two

el comando false hace que el subshell salga sin ejecutar echo one; sin embargo, se ejecuta echo two porque el estado de salida de la canalización (false; echo one) | cat es cero.

-f
El shell deshabilitará la expansión de nombres de archivo.
-h
Localiza y recuerda las utilidades invocadas por las funciones a medida que se definen las funciones (las utilidades normalmente se localizan cuando se ejecuta la función).
-m
Esta opción deberá admitirse si la implementación admite la opción Utilidades de Portabilidad de Usuario. Todos los trabajos se ejecutarán en sus propios grupos de procesos. Inmediatamente antes de que el shell emita un aviso después de la finalización del trabajo en segundo plano, se escribirá un mensaje que informe el estado de salida del trabajo en segundo plano en el error estándar. Si un trabajo en primer plano se detiene, el shell escribirá un mensaje en el error estándar a tal efecto, formateado como se describe en la utilidad jobs. Además, si un trabajo cambia de estado además de salir (por ejemplo, si se detiene por entrada o salida o se detiene con una señal SIGSTOP), el shell escribirá un mensaje similar inmediatamente antes de escribir el siguiente aviso. Esta opción está habilitada por defecto para shells interactivos.
-n
El shell leerá comandos pero no los ejecutará; esto se puede usar para verificar si hay errores de sintaxis en scripts de shell. Un shell interactivo puede ignorar esta opción.
-o
Escribe la configuración actual de las opciones en la salida estándar en un formato no especificado.
+o
Escribe la configuración actual de las opciones en la salida estándar en un formato que sea adecuado para reingresar al shell como comandos que logren la misma configuración de opciones.

Cuando se especifican las opciones -o opción, el comportamiento es idéntico a la especificación de la opción correspondiente con un guion.

-u
Tratar las variables de shell no definidas y las variables de entorno no definidas como un error al realizar la expansión de parámetros. Se escribirá un mensaje de diagnóstico en el error estándar y el shell saldrá si se encuentra una variable no definida. Una variable que se establezca en un valor nulo no se considera no definida.
-v
Imprime las líneas de entrada del shell después de leerlas. Esta opción está habilitada por defecto para shells interactivos.
-x
Imprime cada comando, después de la expansión de parámetros y la sustitución de comando, pero antes de que se ejecute. Esto se utiliza para la depuración de scripts. Los argumentos de la línea de comandos que preceden a una utilidad se imprimen con la salida de depuración. Si la opción x está activada, la salida de depuración se escribirá en el error estándar.

Los argumentos que no son opciones se utilizan para establecer los parámetros posicionales del shell. Si no se especifican opciones, los parámetros posicionales existentes se eliminarán y se establecerán los nuevos parámetros posicionales. Si se especifican opciones, los parámetros posicionales existentes se eliminarán y se establecerán los nuevos parámetros posicionales después de que se hayan procesado las opciones y se hayan encontrado todos los argumentos que no sean opciones.

El primer argumento que no sea una opción se convierte en $1, el segundo en $2, y así sucesivamente. Si no se especifican argumentos, los parámetros posicionales se eliminan.

La utilidad interna set puede usarse para establecer o anular las opciones del shell. Si solo se especifica la opción -o, se escribe la configuración actual de las opciones en el error estándar. Si solo se especifica la opción +o, se escribe la configuración actual de las opciones en la salida estándar en un formato que es adecuado para reingresar al shell como comandos que logren la misma configuración de opciones.

Los nombres de las opciones pueden ser precedidos por - o + para habilitar o deshabilitar la opción, respectivamente. Si no se especifica ni - ni +, la opción se habilita.

Si se especifica --, se procesan todos los argumentos restantes como argumentos y no como opciones. Si se especifican argumentos después de --, los parámetros posicionales se establecen en esos argumentos.

EXIT STATUS

Se devolverá 0 si se realiza una operación con éxito, o un valor mayor que 0 si se produce un error.

set +C

USO DE LA APLICACIÓN

Los desarrolladores de aplicaciones deben evitar depender de set -e dentro de las funciones. Por ejemplo, en el siguiente script:

set -e
start() {
    some_server
    echo some_server started successfully
}
start || echo >&2 some_server failed

la configuración -e se ignora dentro del cuerpo de la función (porque la función es un comando en una lista AND-OR que no es el último). Por lo tanto, si some_server falla, la función continúa para mostrar "some_serverstartedsuccessfully", y el estado de salida de la función es cero (lo que significa que no se muestra "some_serverfailed").

EJEMPLOS

Mostrar todas las variables y sus valores:

set

Establecer $1, $2 y $3 y establecer "$#" en 3:

set c a b

Activar las opciones -x y -v:

set -xv

Desestablecer todos los parámetros posicionales:

set --

Establecer $1 en el valor de x, incluso si comienza con '-' o '+':

set -- "$x"

Establecer los parámetros posicionales en la expansión de x, incluso si x se expande con un '-' o '+' inicial:

set -- $x

FUNDAMENTACIÓN

La forma set -- se enumera específicamente en el SYNOPSIS aunque este uso se infiere de las Directrices de sintaxis de utilidad. La explicación de esta característica elimina cualquier ambigüedad sobre si la forma set -- podría malinterpretarse como equivalente a set sin opciones ni argumentos. La funcionalidad de esta forma se ha adoptado de KornShell. En System V, set -- solo desestablece parámetros si hay al menos un argumento; la única forma de desestablecer todos los parámetros es usar shift. Usar la versión de KornShell no debería afectar a los scripts de System V porque no debería haber ninguna razón para emitirla deliberadamente sin argumentos; si se emitiera como, por ejemplo:

set -- "$@"

y en realidad no hubiera argumentos resultantes de "$@", desestablecer los parámetros no tendría ningún resultado.

La forma set + en las primeras propuestas se omitió por ser una duplicación innecesaria de set solo y no una práctica histórica extendida.

La opción noclobber se modificó para permitir set -C, así como la opción set -o noclobber. Se agregó la versión de un solo carácter para que el paradigma histórico "$-" no se rompiera; véase Section 2.5.2, Special Parameters.

La descripción de la opción -e está destinada a coincidir con el comportamiento de la versión de 1988 de KornShell.

El flag -h está relacionado con el hash de nombres de comandos. Véase hash.

Los siguientes flags de set se omitieron intencionalmente con la siguiente justificación:

-k
El flag -k fue agregado originalmente por el autor del shell Bourne para facilitar la vida a los usuarios de versiones de pre-lanzamiento del shell. En las primeras versiones del shell Bourne, la construcción set name=value tenía que usarse para asignar valores a las variables del shell. El problema con -k es que el comportamiento afecta al análisis sintáctico, lo que prácticamente impide escribir compiladores. Para explicar el comportamiento de -k, es necesario describir el algoritmo de análisis sintáctico, que depende de la implementación. Por ejemplo:
set -k; echo name=value

y:

set -k
echo name=value

se comportan de manera diferente. La interacción con las funciones es aún más compleja. Además, el flag -k nunca es necesario, ya que la línea de comandos podría haber sido reordenada.

-t
El flag -t es difícil de especificar y casi nunca se usa. El único uso conocido podría hacerse con here-documents. Además, el comportamiento con ksh y sh difiere. La página de referencia dice que sale después de leer y ejecutar un comando. ¿Qué es un comando? Si la entrada es date;date, sh ejecuta ambos comandos date mientras que ksh solo hace el primero.

RATIONALE

El utilitario unset debe usarse para desestablecer opciones en lugar de usar la sintaxis de +option no getopt()-able. Sin embargo, se llegó a la conclusión de que la práctica histórica de usar +option era satisfactoria y que no había una razón convincente para modificar una práctica histórica tan extendida.

La opción -o se adoptó de KornShell para abordar las necesidades de los usuarios. Además de su interfaz generalmente amigable, -o es necesaria para proporcionar el modo de edición de línea de comandos vi, para el cual la práctica histórica no ofrece un nombre de opción de una sola letra. (Aunque podría haber sido posible inventar tal letra, se reconoció que se desarrollarían otros modos de edición y -o proporciona un amplio espacio de nombres para describir tales extensiones).

Las implementaciones históricas son inconsistentes en el formato utilizado para la notificación del estado de la opción -o. Se agregó el formato +o sin un argumento de opción para permitir el acceso portátil a las opciones que se pueden guardar y luego restaurar más tarde usando, por ejemplo, un script de punto.

Históricamente, sh rastreaba el comando set +x, pero ksh no.

La configuración ignoreeof evita cierres de sesión accidentales cuando se ingresa el carácter de fin de archivo (típicamente <control>‐D). Un usuario deberá salir explícitamente para abandonar el shell interactivo.

La opción set -m se agregó para aplicarse solo a UPE porque se aplica principalmente al uso interactivo, no a las aplicaciones de script de shell.

La capacidad de realizar notificaciones asíncronas estuvo disponible en la versión de 1988 de KornShell. Para que ocurriera, el usuario tenía que emitir el comando:

trap "jobs -n" CLD

El shell C proporciona dos niveles diferentes de capacidad de notificación asíncrona. La variable de entorno notify es análoga a lo que se hace en set -b o set -o notify. Cuando se establece, notifica al usuario inmediatamente sobre la finalización de trabajos en segundo plano. Cuando se desestablece, esta capacidad se desactiva.

La otra capacidad de notificación proviene del utilitario incorporado notify. La sintaxis es:

notify [%job ... ]

Al emitir notify sin operandos, hace que el shell C notifique al usuario de forma asíncrona cuando cambia el estado del trabajo actual. Si se proporcionan operandos, notify informa asíncronamente al usuario sobre los cambios en los estados de los trabajos especificados.

Para agregar notificación asíncrona al shell POSIX, ni las extensiones de KornShell para trap, ni la variable de entorno notify del shell C parecían apropiadas (notify no es un nombre de variable de entorno POSIX adecuado).

Se seleccionó la opción set -b como compromiso.

Se consideró que el incorporado notify tenía más funcionalidad de la requerida para una simple notificación asíncrona.

Históricamente, algunos shells aplicaban la opción -u a todos los parámetros, incluidos $@ y $*. Los desarrolladores del estándar sintieron que esto era un error, ya que es normal y común usar $@ y $* en scripts de shell independientemente de si se les pasaron argumentos. Tratar estos usos como un error cuando no se pasan argumentos reduce el valor de -u para su propósito previsto de encontrar errores tipográficos en los nombres de variables y usos de parámetros posicionales no establecidos.
