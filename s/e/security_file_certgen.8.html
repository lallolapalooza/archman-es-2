NOMBRE

security_file_certgen - Generador de certificados SSL para Squid.

Versión 1.1

SINOPSIS

security_file_certgen [-cdhv] [-s directorio -M tamaño ] [-b tamaño_bloque_fs ]

DESCRIPCIÓN

security_file_certgen es un binario instalado.

Dado que la generación y firma de certificados SSL lleva tiempo, Squid puede usar esta utilidad como un proceso externo para gestionar el trabajo. La comunicación se realiza a través de sockets TCP enlazados a la interfaz de loopback. Esta utilidad puede usar una caché en disco de certificados para mejorar los tiempos de respuesta en solicitudes repetidas. También puede operar sin caché, generando nuevos certificados en cada solicitud.

OPCIONES

-b tamaño_bloque_fs
Tamaño del bloque del sistema de archivos en bytes. Necesario para procesar el tamaño natural del certificado en disco. El valor predeterminado es 2048 bytes. Se aceptan los siguientes sufijos: B, KB, MB, GB. Cuando no se establece sufijo, se asume B.
-c
Inicializa la base de datos de almacenamiento SSL y sale. Requiere las opciones -s y -M para determinar la ubicación y el tamaño del almacenamiento que se está creando.
-d
Escribe información de depuración en stderr.
-h
Muestra la ayuda del binario y la sintaxis de la línea de comandos usando stderr.
-s directorio
Ruta del directorio de la base de datos de almacenamiento SSL. Requiere la opción -M.
-M tamaño
Tamaño máximo del almacenamiento en disco de certificados SSL. Se pueden usar los mismos sufijos soportados por la opción -b.
-v
Muestra los detalles de la versión del binario usando stderr.

PROBLEMAS CONOCIDOS

Errores SSL después de cambiar la CA

Los certificados se almacenan en esta base de datos en forma firmada. Después de cualquier cambio en la CA firmante en squid.conf, asegúrate de borrar y reinicializar la base de datos de certificados.

Encadenamiento de certificados

Las versiones 1.0 a 1.1 de esta utilidad no añadirán certificados intermedios de CA encadenados. El cliente debe tener una cadena de confianza completa desde la CA raíz hasta el certificado final generado por este programa. Firmar con una CA intermedia requiere instalar la CA pública raíz y la intermedia en los clientes.

CONFIGURACIÓN

Antes de que esta utilidad pueda ser utilizada con almacenamiento en disco, el área de almacenamiento para nuevos certificados debe ser inicializada manualmente. Esto se hace desde la línea de comandos usando el parámetro -c.

Por ejemplo:

/usr/lib/squid/security_file_certgen -c -s /var/cache/squid/ssl_db -M 4MB

Los certificados se almacenan en esta base de datos en forma firmada. Después de cualquier cambio en la CA firmante en squid.conf, asegúrate de borrar y reinicializar la base de datos de certificados.

Para una configuración simple, se pueden usar los valores predeterminados de la utilidad. Solo se requieren las opciones del puerto de escucha HTTP para habilitar la generación y establecer el certificado de CA firmante.

Por ejemplo:

http_port 3128 ssl-bump generate-host-certificates=on dynamic_cert_mem_cache_size=4MB cert=/etc/squid/ssl_cert/example.com.pem

Para una configuración más personalizada, la ubicación del directorio de almacenamiento de certificados de la utilidad y su tamaño se pueden modificar con la directiva de configuración sslcrtd_program. El número de procesos de utilidad en ejecución se puede configurar con la directiva de configuración ssl_crtd_children.

Por ejemplo:

sslcrtd_program /usr/lib/squid/security_file_certgen -s /var/cache/squid/ssl_db -M 4MB
sslcrtd_children 5

Para operar sin almacenamiento en disco, la utilidad debe ser configurada explícitamente sin los parámetros -s y -M.

Por ejemplo:

sslcrtd_program /usr/lib/squid/security_file_certgen
