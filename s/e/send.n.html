send(n) Comandos integrados de Tk send(n)

NOMBRE

send - Ejecutar un comando en una aplicación diferente

SINOPSIS

send ?opciones? app cmd ?arg arg ...?

DESCRIPCIÓN

Este comando organiza la ejecución de cmd (y los argumentos) en la aplicación nombrada por app. Devuelve el resultado o el error de la ejecución de ese comando. App puede ser el nombre de cualquier aplicación cuya ventana principal esté en la pantalla que contiene la ventana principal del remitente; no tiene que estar dentro del mismo proceso. Si no hay argumentos arg presentes, entonces el comando a ejecutar está contenido completamente dentro del argumento cmd. Si hay uno o más argumentos arg presentes, se concatenan para formar el comando a ejecutar, al igual que para el comando eval.

Si los argumentos iniciales del comando comienzan con “-” se tratan como opciones. Actualmente se definen las siguientes opciones:

-async
Solicita invocación asíncrona. En este caso, el comando send se completará inmediatamente sin esperar a que cmd se complete en la aplicación de destino; no habrá resultado disponible y los errores en el comando enviado serán ignorados. Si la aplicación de destino está en el mismo proceso que la aplicación remitente, la opción -async se ignora.
-displayof rutaNombre
Especifica que la ventana principal de la aplicación de destino está en la pantalla de la ventana dada por rutaNombre, en lugar de la pantalla que contiene la ventana principal de la aplicación.
--
No tiene otro propósito que terminar la lista de opciones. Esta opción solo es necesaria si app pudiera contener un carácter “-” al principio.

NOMBRES DE APLICACIÓN

El nombre de una aplicación se establece inicialmente a partir del nombre del programa o script que creó la aplicación. Puedes consultar y cambiar el nombre de una aplicación con el comando tk appname.

DESACTIVAR ENVÍOS

Si el comando send se elimina de una aplicación (por ejemplo, con el comando rename send {}) entonces la aplicación no responderá a las solicitudes de envío entrantes, ni podrá emitir solicitudes salientes. La comunicación se puede reactivar invocando el comando tk appname.

SEGURIDAD

El comando send es potencialmente una seria laguna de seguridad. En Unix, cualquier aplicación que pueda conectarse a tu servidor X puede enviar scripts a tus aplicaciones. Estos scripts entrantes pueden usar Tcl para leer y escribir tus archivos e invocar subprocesos en tu nombre. El control de acceso basado en host, como el proporcionado por xhost, es particularmente inseguro, ya que permite que cualquiera con una cuenta en hosts particulares se conecte a tu servidor y, si se deshabilita, permite que cualquiera en cualquier lugar se conecte a tu servidor. Para proporcionar al menos una pequeña medida de seguridad, Tk verifica el control de acceso que está utilizando el servidor y rechaza los envíos entrantes a menos que (a) el control de acceso de estilo xhost esté habilitado (es decir, solo ciertos hosts pueden establecer conexiones) y (b) la lista de hosts habilitados esté vacía. Esto significa que las aplicaciones no pueden conectarse a tu servidor a menos que utilicen alguna otra forma de autorización, como la proporcionada por xauth. En Windows, send está actualmente deshabilitado. La mayor parte de la funcionalidad se proporciona en su lugar mediante el comando dde.

EJEMPLO

Este fragmento de script se puede usar para hacer una aplicación que solo se ejecute una vez en una pantalla determinada.

if {[tk appname FoobarApp] ne "FoobarApp"} {
    send -async FoobarApp RemoteStart $argv
    exit
}
# El comando que se llamará remotamente, que eleva
# la ventana principal de la aplicación y abre los archivos solicitados
proc RemoteStart args {
    raise .
    foreach filename $args {
        OpenFile $filename
    }
}
