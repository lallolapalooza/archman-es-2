getutent(3) Manual de funciones de biblioteca getutent(3)

NOMBRE

getutent, getutid, getutline, pututline, setutent, endutent, utmpname - acceder a las entradas del archivo utmp

BIBLIOTECA

Biblioteca estándar C (libc, -lc)

SINOPSIS

#include <utmp.h>
struct utmp *getutent(void);
struct utmp *getutid(const struct utmp *ut);
struct utmp *getutline(const struct utmp *ut);
struct utmp *pututline(const struct utmp *ut);
void setutent(void);
void endutent(void);
int utmpname(const char *path);

DESCRIPCIÓN

Las nuevas aplicaciones deberían usar las versiones de estas funciones "utmpx" especificadas por POSIX.1; ver NORMAS.

utmpname() establece la ruta del archivo en formato utmp para que otras funciones utmp accedan. Si no se usa utmpname() para establecer la ruta antes de usar las otras funciones, asumen _PATH_UTMP, como se define en <paths.h>.

setutent() rebobina el puntero del archivo al principio del archivo utmp. Generalmente, es una buena idea llamarla antes que a cualquiera de las otras funciones.

endutent() cierra el archivo utmp. Debe llamarse cuando el código del usuario haya terminado de acceder al archivo con las otras funciones.

getutent() lee una línea de la posición actual del archivo en el archivo utmp. Devuelve un puntero a una estructura que contiene los campos de la línea. La definición de esta estructura se muestra en utmp(5).

getutid() busca hacia adelante desde la posición actual del archivo en el archivo utmp basándose en ut. Si ut->ut_type es uno de RUN_LVL, BOOT_TIME, NEW_TIME, o OLD_TIME, getutid() encontrará la primera entrada cuyo campo ut_type coincida con ut->ut_type. Si ut->ut_type es uno de INIT_PROCESS, LOGIN_PROCESS, USER_PROCESS, o DEAD_PROCESS, getutid() encontrará la primera entrada cuyo campo ut_id coincida con ut->ut_id.

getutline() busca hacia adelante desde la posición actual del archivo en el archivo utmp. Escanea las entradas cuyo ut_type es USER_PROCESS o LOGIN_PROCESS y devuelve la primera cuyo campo ut_line coincida con ut->ut_line.

pututline() escribe la estructura utmp ut en el archivo utmp. Utiliza getutid() para buscar el lugar apropiado en el archivo para insertar la nueva entrada. Si no puede encontrar una ranura adecuada para ut, pututline() añadirá la nueva entrada al final del archivo.

VALOR DE RETORNO

getutent(), getutid() y getutline() devuelven un puntero a una struct utmp en caso de éxito, y NULL en caso de fallo (lo que incluye el caso de "registro no encontrado"). Esta struct utmp se asigna en almacenamiento estático y puede ser sobrescrita por llamadas posteriores.

En caso de éxito, pututline() devuelve ut; en caso de fallo, devuelve NULL.

utmpname() devuelve 0 si el nuevo nombre se almacenó correctamente, o -1 en caso de fallo.

En caso de fallo, estas funciones establecen errno para indicar el error.

ERRORES

ENOMEM
Memoria agotada.
ESRCH
Registro no encontrado.

setutent(), pututline() y las funciones getut*() también pueden fallar por las razones descritas en open(2).

ARCHIVOS

/var/run/utmp
base de datos de usuarios actualmente conectados
/var/log/wtmp
base de datos de inicios de sesión de usuarios pasados

ATRIBUTOS

Para una explicación de los términos utilizados en esta sección, consulte attributes(7).

Interfaz Atributo Valor
getutent () Seguridad de hilos MT-Unsafe init race:utent race:utentbuf sig:ALRM timer
getutid (), getutline () Seguridad de hilos MT-Unsafe init race:utent sig:ALRM timer
pututline () Seguridad de hilos MT-Unsafe race:utent sig:ALRM timer

En la tabla anterior, utent en race:utent indica que si alguna de las funciones setutent(), getutent(), getutid(), getutline(), pututline(), utmpname(), o endutent() se utilizan en paralelo en diferentes hilos de un programa, podrían ocurrir carreras de datos.

NORMAS

Ninguna.

HISTORIA

XPG2, SVr4.

En XPG2 y SVID 2, la función pututline() se documenta como void, y eso es lo que hace en muchos sistemas (AIX, HP-UX). HP-UX introduce una nueva función _pututline() con el prototipo dado arriba para pututline().

Todas estas funciones están ahora obsoletas en sistemas que no son Linux. POSIX.1-2001 y POSIX.1-2008, siguiendo SUSv1, no tienen ninguna de estas funciones, sino que utilizan

#include <utmpx.h>
struct utmpx *getutxent(void);
struct utmpx *getutxid(const struct utmpx *);
struct utmpx *getutxline(const struct utmpx *);
struct utmpx *pututxline(const struct utmpx *);
void setutxent(void);
void endutxent(void);

Estas funciones son proporcionadas por glibc y realizan la misma tarea que sus equivalentes sin la "x", pero usan struct utmpx, definida en Linux como igual a struct utmp. Para completar, glibc también proporciona utmpxname(), aunque esta función no está especificada por POSIX.1.

En otros sistemas, la estructura utmpx es un superconjunto de la estructura utmp, con campos adicionales y versiones más grandes de los campos existentes, y se mantienen archivos paralelos, a menudo /var/*/utmpx y /var/*/wtmpx.

Por otro lado, glibc de Linux no utiliza un archivo utmpx paralelo ya que su estructura utmp es lo suficientemente grande. Las funciones "x" listadas arriba son solo alias de sus contrapartes sin la "x" (por ejemplo, getutxent() es un alias de getutent()).

NOTAS

Notas de glibc

Las funciones anteriores no son seguras para hilos. glibc añade versiones reentrantes

#include <utmp.h>
int getutent_r(struct utmp *ubuf, struct utmp **ubufp);
int getutid_r(struct utmp *ut,
              struct utmp *ubuf, struct utmp **ubufp);
int getutline_r(struct utmp *ut,
                struct utmp *ubuf, struct utmp **ubufp);

Requisitos de Macro de Prueba de Funciones para glibc (ver feature_test_macros(7)):

getutent_r(), getutid_r(), getutline_r():

    _GNU_SOURCE
        || /* Desde glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */    _SVID_SOURCE || _BSD_SOURCE

Estas funciones son extensiones de GNU, análogos de las funciones del mismo nombre sin el sufijo _r. El argumento ubuf proporciona a estas funciones un lugar para almacenar su resultado. En caso de éxito, devuelven 0, y se escribe un puntero al resultado en *ubufp. En caso de error, estas funciones devuelven -1. No existen equivalentes de utmpx de las funciones anteriores. (POSIX.1 no especifica tales funciones.)

setutxent(3) - Arch Linux man pages

NAME

setutxent, getutxent, pututxline, endutxent, utmpxname - manipulate user accounting database

LIBRARY

Standard C Library (libc, -lc)

SYNOPSIS

#include <utmp.h>
void setutxent(void);
struct utmp *getutxent(void);
struct utmp *getutxid(const struct utmp *id);
struct utmp *getutxline(const struct utmp *line);
int pututxline(const struct utmp *utmp);
void endutxent(void);
int utmpxname(const char *filename);

DESCRIPTION

The functions described here form a library for accessing and modifying the user accounting database, usually located at /var/run/utmp. The database contains records of currently logged-in users and recently logged-out users.

setutxent() opens the database file (or resets the file pointer to the beginning if it is already open).

getutxent() reads and returns the next record from the database. If the end of the file is reached, it returns NULL.

getutxid() searches the database for a record whose type and ID match the type and ID fields of the argument id. The ut_type field determines which records are searched. For example, if ut_type is UT_UNKNOWN, then ut_id is used for the match.

getutxline() searches the database for a record whose terminal line matches the ut_line field of the argument line.

pututxline() writes the structure utmp to the database at the current file position. If the ut_type is DEAD_PROCESS or UT_UNKNOWN, the record is considered deleted and is removed from the database.

endutxent() closes the database file.

utmpxname() changes the name of the file accessed by the other functions to filename. The default name is typically /var/run/utmp. This function should be called before setutxent().

The functions described here are generally used in conjunction with the login() or utmpname() library functions.

The utmp structure is defined in <utmp.h> and contains at least the following fields:

char ut_user[UT_NAMESIZE];     /* Name of person logging in */
char ut_id[UT_IDSIZE];         /* padding or remote host name */
char ut_line[UT_LINESIZE];     /* the project name or tty name */
char ut_host[UT_HOSTSIZE];     /* hostname for remote login */
time_t ut_time;                /* the time they logged in */
int ut_pid;                    /* process id */
short ut_type;                 /* type of entry */
int ut_pad;                    /* extra space, alignment */
int ut_reserved[UT_PADSIZE];   /* reserved for future use */

ut_type can be one of the following values:

EMPTY               (0) no valid data in the structure
RUN_LVL             (1) run-level messages
BOOT_TIME           (2) time of system boot
OLD_TIME            (3) time before system clock change
NEW_TIME            (4) time after system clock change
INIT_PROCESS        (5) process started by init
LOGIN_PROCESS       (6) a login process
USER_PROCESS        (7) a user process
DEAD_PROCESS        (8) a process that has died
ACCOUNTING          (9) process accounting
UT_UNKNOWN          (10) getutmp(3) uses this value

RETURN VALUE

getutxent(), getutxid(), and getutxline() return a pointer to a static utmp structure, or NULL if the end of the file is reached or an error occurs.

pututxline() returns a pointer to the written utmp structure on success, and NULL on failure.

utmpxname() returns 0 on success and -1 on failure.

ERRORS

The following errors may be set by these functions:

  • EACCES
    Permission denied to read or write the utmp file.
  • EINTR
    An interrupt occurred while reading from or writing to the utmp file.
  • EMFILE
    Too many file descriptors are open.
  • ENFILE
    The maximum number of files allowed on the system is currently open.
  • ENOENT
    The utmp file does not exist.
  • ENOMEM
    Insufficient memory available.
  • ENOTDIR
    A component of the path prefix of the utmp file is not a directory.
  • ELOOP
    Too many symbolic links encountered in resolving the utmp file.
  • ENAMETOOLONG
    A component of a file name is longer than the operating system maximum, or the entire path prefixed to a file name when that file name is resolved is longer than the system maximum.
  • ENFILE
    The maximum number of files allowed on the system is currently open.
  • ENOMEM
    Insufficient memory available.
  • ENOTDIR
    A component of the path prefix of the utmp file is not a directory.
  • EROFS
    The utmp file is on a read-only filesystem.
  • ETXTBSY
    Text file busy.

FILES

/var/run/utmp
The default utmp database file.
/dev/tty*
Device files for terminals.

ATTRIBUTES

For an explanation of the terms used in this section, see attributes(7).

Interface Attribute
setutxent, getutxent, pututxline, endutxent, utmpxname, getutxid, getutxline Thread safety

Note that the static data structures returned by getutxent(), getutxid(), and getutxline() are not thread-safe. If you need thread safety, use the functions described in getutent_r(3).

STANDARDS

These functions are expected to conform to Version 2 of the Single UNIX Specification.

HISTORY

These functions first appeared in AT&T System V UNIX.

NOTES

The fields ut_user, ut_line, ut_host, and ut_id are fixed-size character arrays. The size of these arrays is defined by the macros UT_NAMESIZE, UT_LINESIZE, UT_HOSTSIZE, and UT_IDSIZE, respectively. It is important to ensure that any strings copied into these fields are null-terminated and do not exceed the defined sizes. Using strncpy() is recommended for copying strings into these fields.

It is important to call endutxent() when finished with the utmp database to release any resources held open.

The pututxline() function is used to add and delete entries. To add an entry, fill in the appropriate fields of the utmp structure and call pututxline(). To delete an entry, set the ut_type field to DEAD_PROCESS or UT_UNKNOWN, and call pututxline().

The getutxid() and getutxline() functions are not guaranteed to be efficient, as they may have to scan the entire database.

EXAMPLES

The following example adds and removes a utmp record, assuming it is run from within a pseudo terminal. For usage in a real application, you should check the return values of getpwuid(3) and ttyname(3).

#include <err.h>
#include <pwd.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>
#include <utmp.h>
int
main(void)
{
    struct utmp entry;
    if (system("echo before adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = USER_PROCESS;
    entry.ut_pid = getpid();
    strcpy(entry.ut_line, ttyname(STDIN_FILENO) + strlen("/dev/"));
    /* only correct for ptys named /dev/tty[pqr][0-9a-z] */
    strcpy(entry.ut_id, ttyname(STDIN_FILENO) + strlen("/dev/tty"));
    entry.ut_time = time(NULL);
    strcpy(entry.ut_user, getpwuid(getuid())->pw_name);
    memset(entry.ut_host, 0, UT_HOSTSIZE);
    entry.ut_addr = 0;
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo after adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = DEAD_PROCESS;
    memset(entry.ut_line, 0, UT_LINESIZE);
    entry.ut_time = 0;
    memset(entry.ut_user, 0, UT_NAMESIZE);
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo after removing entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    endutent();
    exit(EXIT_SUCCESS);
}
