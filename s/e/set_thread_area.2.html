set_thread_area(2) Manual de llamadas al sistema set_thread_area(2)

NOMBRE

get_thread_area, set_thread_area - manipula la información de almacenamiento local de hilos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/syscall.h>     /* Definición de constantes SYS_* */
#include <unistd.h>
#if defined __i386__ || defined __x86_64__
# include <asm/ldt.h>        /* Definición de struct user_desc */
int syscall(SYS_get_thread_area, struct user_desc *u_info);
int syscall(SYS_set_thread_area, struct user_desc *u_info);
#elif defined __m68k__
int syscall(SYS_get_thread_area);
int syscall(SYS_set_thread_area, unsigned long tp);
#elif defined __mips__ || defined __csky__
int syscall(SYS_set_thread_area, unsigned long addr);
#endif

Nota: glibc no proporciona envoltorios para estas llamadas al sistema, lo que hace necesario el uso de syscall(2).

DESCRIPCIÓN

Estas llamadas proporcionan soporte específico de arquitectura para una implementación de almacenamiento local de hilos. Por el momento, set_thread_area() está disponible en m68k, MIPS, C-SKY y x86 (tanto variantes de 32 bits como de 64 bits); get_thread_area() está disponible en m68k y x86.

En m68k, MIPS y C-SKY, set_thread_area() permite almacenar un puntero arbitrario (proporcionado en el argumento tp en m68k y en el argumento addr en MIPS y C-SKY) en la estructura de datos del kernel asociada con el hilo que llama; este puntero puede recuperarse posteriormente utilizando get_thread_area() (ver también NOTAS para obtener información sobre cómo obtener el puntero de hilo en MIPS).

En x86, Linux dedica tres entradas de la tabla de descriptores globales (GDT) para el almacenamiento local de hilos. Para más información sobre la GDT, consultar el Manual del Desarrollador de Software de Intel o el Manual de Programación de la Arquitectura AMD.

Ambas llamadas al sistema toman un argumento que es un puntero a una estructura del siguiente tipo:


struct user_desc {
    unsigned int  entry_number;
    unsigned int  base_addr;
    unsigned int  limit;
    unsigned int  seg_32bit:1;
    unsigned int  contents:2;
    unsigned int  read_exec_only:1;
    unsigned int  limit_in_pages:1;
    unsigned int  seg_not_present:1;
    unsigned int  useable:1;
#ifdef __x86_64__
    unsigned int  lm:1;
#endif
};

get_thread_area() lee la entrada GDT indicada por u_info->entry_number y rellena el resto de los campos en u_info.

set_thread_area() establece una entrada TLS en la GDT.

La entrada de la matriz TLS establecida por set_thread_area() corresponde al valor de u_info->entry_number pasado por el usuario. Si este valor está dentro de los límites, set_thread_area() escribe el descriptor TLS apuntado por u_info en la matriz TLS del hilo.

Cuando a set_thread_area() se le pasa un entry_number de -1, busca una entrada TLS libre. Si set_thread_area() encuentra una entrada TLS libre, el valor de u_info->entry_number se establece al retornar para indicar qué entrada se modificó.

Un user_desc se considera "vacío" si read_exec_only y seg_not_present están establecidos a 1 y todos los demás campos son 0. Si se pasa un descriptor "vacío" a set_thread_area(), la entrada TLS correspondiente se borrará. Ver BUGS para más detalles.

Desde Linux 3.19, set_thread_area() no se puede usar para escribir segmentos no presentes, segmentos de 16 bits o segmentos de código, aunque borrar un segmento sigue siendo aceptable.

VALOR DE RETORNO

En x86, estas llamadas al sistema retornan 0 en caso de éxito y -1 en caso de error, con errno establecido para indicar el error.

En C-SKY, MIPS y m68k, set_thread_area() siempre retorna 0. En m68k, get_thread_area() retorna el valor del puntero del área del hilo (establecido previamente a través de set_thread_area()).

ERRORES

EFAULT
u_info es un puntero inválido.
EINVAL
u_info->entry_number está fuera de los límites.
ENOSYS
Se invocó a get_thread_area() o set_thread_area() como una llamada al sistema de 64 bits.
ESRCH
(set_thread_area()) No se pudo localizar una entrada TLS libre.

ESTÁNDARES

Linux.

HISTORIA

set_thread_area()
Linux 2.5.29.
get_thread_area()
Linux 2.5.32.

NOTAS

Estas llamadas al sistema están generalmente destinadas a ser utilizadas solo por bibliotecas de hilos.

arch_prctl(2) puede interferir con set_thread_area() en x86. Ver arch_prctl(2) para más detalles. Esto normalmente no es un problema, ya que arch_prctl(2) normalmente solo es utilizado por programas de 64 bits.

En MIPS, el valor actual del puntero del área del hilo se puede obtener usando la instrucción:


rdhwr dest, $29

Esta instrucción causa una interrupción y es manejada por el kernel.

BUGS

En kernels de 64 bits anteriores a Linux 3.19, uno de los bits de relleno en user_desc, si estaba establecido, impedía que el descriptor se considerara vacío (ver modify_ldt(2)). Como resultado, la única forma confiable de borrar una entrada TLS es usar memset(3) para poner a cero toda la estructura user_desc, incluidos los bits de relleno, y luego establecer los bits read_exec_only y seg_not_present. En Linux 3.19, un user_desc que consiste completamente en ceros excepto por entry_number también se interpretará como una solicitud para borrar una entrada TLS, pero esto se comportó de manera diferente en kernels anteriores.

Anteriormente a Linux 3.19, los registros de segmento DS y ES no deben referenciar entradas TLS.

VER TAMBIÉN

arch_prctl(2), modify_ldt(2), ptrace(2) (PTRACE_GET_THREAD_AREA y PTRACE_SET_THREAD_AREA)
