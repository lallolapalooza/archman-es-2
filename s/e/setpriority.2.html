getpriority(2) Manual de llamadas al sistema getpriority(2)

NOMBRE

getpriority, setpriority - obtener/establecer la prioridad de planificación de un programa

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/resource.h>
int getpriority(int which, id_t who);
int setpriority(int which, id_t who, int prio);

DESCRIPCIÓN

La prioridad de planificación del proceso, grupo de procesos o usuario, tal como se indica en which y who, se obtiene con la llamada getpriority() y se establece con la llamada setpriority(). El atributo del proceso que manejan estas llamadas al sistema es el mismo atributo (también conocido como valor de "nice") que maneja nice(2).

El valor which es uno de PRIO_PROCESS, PRIO_PGRP o PRIO_USER, y who se interpreta en relación con which (un identificador de proceso para PRIO_PROCESS, un identificador de grupo de procesos para PRIO_PGRP y un ID de usuario para PRIO_USER). Un valor cero para who denota (respectivamente) el proceso que llama, el grupo de procesos del proceso que llama o el ID de usuario real del proceso que llama.

El argumento prio es un valor en el rango de -20 a 19 (pero ver NOTAS más abajo), siendo -20 la prioridad más alta y 19 la prioridad más baja. Los intentos de establecer una prioridad fuera de este rango se limitan silenciosamente dentro del rango. La prioridad predeterminada es 0; los valores más bajos otorgan a un proceso una mayor prioridad de planificación.

La llamada getpriority() devuelve la prioridad más alta (valor numérico más bajo) disfrutada por cualquiera de los procesos especificados. La llamada setpriority() establece las prioridades de todos los procesos especificados al valor especificado.

Tradicionalmente, solo un proceso privilegiado podía disminuir el valor de nice (es decir, establecer una prioridad más alta). Sin embargo, desde Linux 2.6.12, un proceso no privilegiado puede disminuir el valor de nice de un proceso de destino que tiene un límite suave RLIMIT_NICE adecuado; consulte getrlimit(2) para obtener más detalles.

VALOR DE RETORNO

En caso de éxito, getpriority() devuelve el valor de nice del hilo que llama, que puede ser un número negativo. En caso de error, devuelve -1 y establece errno para indicar el error.

Dado que una llamada exitosa a getpriority() puede devolver legítimamente el valor -1, es necesario borrar errno antes de la llamada, y luego verificar errno después para determinar si -1 es un error o un valor legítimo.

setpriority() devuelve 0 en caso de éxito. En caso de error, devuelve -1 y establece errno para indicar el error.

ERRORES

EACCES
El llamador intentó establecer un valor de nice más bajo (es decir, una prioridad de proceso más alta), pero no tenía el privilegio requerido (en Linux: no tenía la capacidad CAP_SYS_NICE).
EINVAL
which no era uno de PRIO_PROCESS, PRIO_PGRP o PRIO_USER.
EPERM
Se encontró un proceso, pero su ID de usuario efectivo no coincidía con el ID de usuario efectivo ni con el ID de usuario real del llamador, y no estaba privilegiado (en Linux: no tenía la capacidad CAP_SYS_NICE). Pero vea HISTORIA más abajo.
ESRCH
No se encontró ningún proceso utilizando los valores which y who especificados.

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, SVr4, 4.4BSD (estas interfaces aparecieron por primera vez en 4.2BSD).

Los detalles de la condición para EPERM dependen del sistema. La descripción anterior es lo que dice POSIX.1-2001, y parece ser seguida en todos los sistemas tipo System V. Los kernels de Linux anteriores a Linux 2.6.12 requerían que el ID de usuario real o efectivo del llamador coincidiera con el usuario real del proceso who (en lugar de su ID de usuario efectivo). Linux 2.6.12 y posteriores requieren que el ID de usuario efectivo del llamador coincida con el ID de usuario real o efectivo del proceso who. Todos los sistemas tipo BSD (SunOS 4.1.3, Ultrix 4.2, 4.3BSD, FreeBSD 4.3, OpenBSD-2.5, ...) se comportan de la misma manera que Linux 2.6.12 y posteriores.

NOTAS

Para más detalles sobre el valor de nice, consulte sched(7).

Nota: la adición de la función "autogroup" en Linux 2.6.38 significa que el valor de nice ya no tiene su efecto tradicional en muchas circunstancias. Para más detalles, consulte sched(7).

Un hijo creado por fork(2) hereda el valor de nice de su padre. El valor de nice se conserva durante execve(2).

Diferencias biblioteca C/kernel

La llamada al sistema getpriority devuelve valores de nice traducidos al rango 40..1, ya que un valor de retorno negativo se interpretaría como un error. La función de envoltura glibc para getpriority() traduce el valor de vuelta según la fórmula unice = 20 - knice (por lo tanto, el rango 40..1 devuelto por el kernel corresponde al rango -20..19 tal como lo ve el espacio de usuario).

ERRORES CONOCIDOS

Según POSIX, el valor de nice es un ajuste por proceso. Sin embargo, bajo la implementación actual de hilos POSIX en Linux/NPTL, el valor de nice es un atributo por hilo: diferentes hilos en el mismo proceso pueden tener diferentes valores de nice. Las aplicaciones portátiles deben evitar depender del comportamiento de Linux, que puede hacerse compatible con los estándares en el futuro.

    NAME

    setpriority - establecer la prioridad de uno o más procesos

    SYNOPSIS

    #include <sys/time.h>

    #include <sys/resource.h>

    int setpriority(int which, id_t who, int priority);

    DESCRIPTION

    La llamada al sistema setpriority() establece la prioridad de planificación de uno o más procesos, grupos de procesos o usuarios. El argumento which especifica la categoría de las entidades que se van a modificar, y who especifica un descriptor de la entidad o entidades. El argumento priority es el valor de prioridad deseado.

    Los valores posibles para which son:

    PRIO_PROCESS
    El argumento who es un ID de proceso (pid_t). Si who es 0, se refiere al proceso que realiza la llamada.
    PRIO_PGRP
    El argumento who es un ID de grupo de procesos (pid_t). Si who es 0, se refiere al grupo de procesos del proceso que realiza la llamada.
    PRIO_USER
    El argumento who es un ID de usuario real (uid_t). Si who es 0, se refiere al usuario del proceso que realiza la llamada.

    La entrada priority es un entero entre -20 (la prioridad más alta) y 19 (la prioridad más baja). El valor predeterminado para la mayoría de los procesos es 0.

    Si un proceso intenta establecer la prioridad de otro proceso, grupo de procesos o usuario, solo se le permite si el ID de usuario efectivo del proceso que realiza la llamada es 0 (típicamente el usuario root) o si el ID de usuario efectivo del proceso que realiza la llamada coincide con el ID de usuario real o efectivo del objetivo y el valor de prioridad es mayor o igual que el valor de prioridad actual.

    La llamada al sistema getpriority() se utiliza para obtener valores de prioridad.

    RETURN VALUE

    En caso de éxito, setpriority() devuelve 0. En caso de error, devuelve -1 y errno se establece para indicar el error.

    ERRORS

    EPERM
    Se intentó establecer la prioridad de otra entidad pero no se permitieron los permisos.
    ESRCH
    El proceso, grupo de procesos o usuario especificado por who no se encontró.

    CONFORMING TO

    Estas funciones se ajustan a POSIX.1-2001 y POSIX.1-2008.

    NOTES

    En Linux, las prioridades se establecen y obtienen utilizando setpriority() y getpriority(). Sin embargo, los valores de prioridad son relativos y no absolutos. El valor de prioridad se desplaza desde un valor base. Los valores de prioridad negativos se asignan a las prioridades de planificación más altas, mientras que los valores positivos se asignan a las prioridades de planificación más bajas.

    El rango de prioridades es de -20 a 19. Un valor más bajo significa una prioridad más alta.

    La llamada a setpriority() puede fallar con EPERM si un usuario normal intenta aumentar la prioridad de un proceso o grupo de procesos.

    BUGS

    La interfaz de setpriority() puede ser confusa para los principiantes. La descripción de los argumentos which y who puede no ser lo suficientemente clara.
