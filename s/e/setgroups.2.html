getgroups(2) Manual de llamadas al sistema getgroups(2)

NOMBRE

getgroups, setgroups - obtener/establecer lista de IDs de grupo suplementarios

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int getgroups(int size, gid_t list[_Nullable size]);
#include <grp.h>
int setgroups(size_t size, const gid_t list[size]);
Requisitos de macros de prueba de características para glibc (ver feature_test_macros(7)):

setgroups():

    Desde glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 y anteriores:
        _BSD_SOURCE

DESCRIPCIÓN

getgroups() devuelve los IDs de grupo suplementarios del proceso que llama en list. El argumento size debe establecerse al número máximo de elementos que se pueden almacenar en el búfer al que apunta list. Si el proceso que llama es miembro de más de size grupos suplementarios, se produce un error.

No se especifica si el ID de grupo efectivo del proceso que llama se incluye en la lista devuelta. (Por lo tanto, una aplicación también debe llamar a getegid(2) y agregar o quitar el valor resultante).

Si size es cero, list no se modifica, pero se devuelve el número total de IDs de grupo suplementarios para el proceso. Esto permite al llamador determinar el tamaño de una list asignada dinámicamente para ser utilizada en una llamada posterior a getgroups().

setgroups() establece los IDs de grupo suplementarios para el proceso que llama. Se requieren privilegios apropiados (ver la descripción del error EPERM, abajo). El argumento size especifica el número de IDs de grupo suplementarios en el búfer al que apunta list. Un proceso puede eliminar todos sus grupos suplementarios con la llamada:


setgroups(0, (gid_t [0]){});

VALOR DE RETORNO

En caso de éxito, getgroups() devuelve el número de IDs de grupo suplementarios. En caso de error, devuelve -1 y errno se establece para indicar el error.

En caso de éxito, setgroups() devuelve 0. En caso de error, devuelve -1 y errno se establece para indicar el error.

ERRORES

EFAULT
list tiene una dirección inválida.

getgroups() puede fallar adicionalmente con el siguiente error:

EINVAL
size es menor que el número de IDs de grupo suplementarios, pero no es cero.

setgroups() puede fallar adicionalmente con los siguientes errores:

EINVAL
size es mayor que NGROUPS_MAX (32 antes de Linux 2.6.4; 65536 desde Linux 2.6.4).
ENOMEM
Memoria insuficiente.
EPERM
El proceso que llama tiene privilegios insuficientes (el llamador no tiene la capacidad CAP_SETGID en el espacio de nombres de usuario en el que reside).
EPERM (desde Linux 3.19)
El uso de setgroups() está denegado en este espacio de nombres de usuario. Ver la descripción de /proc/pid/setgroups en user_namespaces(7).

VERSIÓNES

Diferencias biblioteca C/núcleo

A nivel de núcleo, los IDs de usuario y los IDs de grupo son un atributo por hilo. Sin embargo, POSIX requiere que todos los hilos de un proceso compartan las mismas credenciales. La implementación de hilos NPTL maneja los requisitos de POSIX proporcionando funciones envoltorio para las diversas llamadas al sistema que cambian los UID y GID del proceso. Estas funciones envoltorio (incluida la de setgroups()) emplean una técnica basada en señales para garantizar que cuando un hilo cambia las credenciales, todos los demás hilos del proceso también cambien sus credenciales. Para obtener detalles, ver nptl(7).

ESTÁNDARES

getgroups()
POSIX.1-2024.
setgroups()
Ninguno.

HISTORIAL

getgroups()
SVr4, 4.3BSD, POSIX.1-2001.
setgroups()
SVr4, 4.3BSD. Dado que setgroups() requiere privilegios, no está cubierto por POSIX.1.

La llamada al sistema getgroups() original de Linux solo admitía IDs de grupo de 16 bits. Posteriormente, Linux 2.4 agregó getgroups32(), que admite IDs de 32 bits. La función envoltorio getgroups() de glibc maneja de forma transparente la variación entre las versiones del núcleo.

NOTAS

Un proceso puede tener hasta NGROUPS_MAX IDs de grupo suplementarios además del ID de grupo efectivo. La constante NGROUPS_MAX se define en <limits.h>. El conjunto de IDs de grupo suplementarios se hereda del proceso padre y se conserva en una execve(2).

El número máximo de IDs de grupo suplementarios se puede encontrar en tiempo de ejecución usando sysconf(3):


long ngroups_max;
ngroups_max = sysconf(_SC_NGROUPS_MAX);

El valor máximo de retorno de getgroups() no puede ser mayor que uno más que este valor. Desde Linux 2.6.4, el número máximo de IDs de grupo suplementarios también está expuesto a través del archivo de solo lectura específico de Linux, /proc/sys/kernel/ngroups_max.

EJEMPLOS

#include <err.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
#define MALLOC(n, T)  ((T *) reallocarray(NULL, n, sizeof(T)))
static gid_t *agetgroups(size_t *ngids);
int
main(void)
{
    gid_t   *gids;
    size_t  n;
    gids = agetgroups(&n);
    if (gids == NULL)
        err(EXIT_FAILURE, "agetgroups");
    if (n != 0) {
        printf("%jd", (intmax_t) gids[0]);
        for (size_t i = 1; i < n; i++)
            printf(" %jd", (intmax_t) gids[i]);
    }
    puts("");
    free(gids);
    exit(EXIT_SUCCESS);
}
static gid_t *
agetgroups(size_t *ngids)
{
    int    n;
    gid_t  *gids;
    n = getgroups(0, NULL);
    if (n == -1)
        return NULL;
    gids = MALLOC(n, gid_t);
    if (gids == NULL)
        return NULL;
    n = getgroups(n, gids);
    if (n == -1) {
        free(gids);
        return NULL;
    }
    *ngids = n;
    return gids;
}

NOMBRE

setgroups - establecer la lista de GID complementarios de un proceso

LIBRERÍA

Librería C estándar (libc)

SINOPSIS

#include <grp.h>

int setgroups(size_t ngroups, const gid_t groups[]);

DESCRIPCIÓN

La llamada al sistema setgroups establece la lista de GID (Group IDs) complementarios de el llamador. La lista de GID complementarios se utiliza para la verificación de permisos en sistemas que soportan GID complementarios. El primer argumento, ngroups, indica el número de elementos en la matriz groups. El segundo argumento, groups, es un puntero a una matriz de gid_t que contiene los GID que se establecerán como la lista de GID complementarios del llamador.

Solo un proceso con privilegios de superusuario (root) puede llamar a setgroups. Si el llamador no es un superusuario, setgroups fallará y devolverá un error.

La lista de GID complementarios se puede utilizar para permitir que un usuario pertenezca a múltiples grupos a la vez. Esto puede ser útil en escenarios donde un usuario necesita acceder a recursos que pertenecen a diferentes grupos.

Es importante tener en cuenta que setgroups establece la lista de GID complementarios para el proceso llamador. Los procesos hijos creados después de llamar a setgroups heredarán esta lista de GID complementarios.

VALOR DE RETORNO

En caso de éxito, setgroups devuelve 0. En caso de error, devuelve -1 y configura errno para indicar el error.

ERRORES

EPERM
El llamador no es un superusuario.
EINVAL
ngroups es mayor que el número máximo de GID complementarios permitidos por el sistema, o bien groups contiene GID duplicados.
EFAULT
groups apunta a una dirección de memoria inválida.

VERSIÓN

La llamada al sistema setgroups está disponible desde Linux 2.0.

ESTÁNDARES

La llamada al sistema setgroups es parte de POSIX.1-2008.

HISTORIA

La llamada al sistema setgroups fue introducida en sistemas Unix en los años 80.

NOTAS

En muchos sistemas modernos, la gestión de grupos se realiza a través de la llamada al sistema initgroups, que inicializa la lista de GID complementarios basándose en la información de los archivos de contraseñas y grupos.

setgroups es una operación privilegiada y solo debe ser utilizada por administradores del sistema o por programas que requieran un control explícito sobre los GID complementarios de un proceso.

EJEMPLOS

Aquí tienes un ejemplo simple de cómo usar setgroups en C:

#include <stdio.h>
#include <stdlib.h>
#include <grp.h>
#include <unistd.h>
#include <errno.h>

int main() {
    // Asegúrate de que el programa se ejecuta como root
    if (geteuid() != 0) {
        fprintf(stderr, "Este programa necesita ser ejecutado como root.\n");
        return 1;
    }

    // Definir una lista de GID complementarios (ejemplo)
    gid_t supplemental_groups[] = {1001, 1002, 1003};
    size_t num_groups = sizeof(supplemental_groups) / sizeof(gid_t);

    // Llamar a setgroups
    if (setgroups(num_groups, supplemental_groups) == -1) {
        perror("setgroups");
        return 1;
    }

    printf("Lista de GID complementarios establecida con éxito.\n");

    // Puedes verificar los GID establecidos usando getgroups()
    int actual_ngroups = getgroups(0, NULL); // Obtener el número de grupos
    if (actual_ngroups < 0) {
        perror("getgroups");
        return 1;
    }

    gid_t *actual_groups = malloc(actual_ngroups * sizeof(gid_t));
    if (actual_groups == NULL) {
        perror("malloc");
        return 1;
    }

    if (getgroups(actual_ngroups, actual_groups) == -1) {
        perror("getgroups");
        free(actual_groups);
        return 1;
    }

    printf("GID complementarios actuales:\n");
    for (int i = 0; i < actual_ngroups; i++) {
        printf("- %d\n", actual_groups[i]);
    }

    free(actual_groups);
    return 0;
}
