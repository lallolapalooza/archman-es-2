gettimeofday(2) Manual de llamadas al sistema gettimeofday(2)

NOMBRE

gettimeofday, settimeofday - obtener / establecer hora

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/time.h>
[[deprecated]]
int gettimeofday(struct timeval *restrict tv,
                 struct timezone *_Nullable restrict tz);
[[deprecated]]
int settimeofday(const struct timeval *tv,
                 const struct timezone *_Nullable tz);
Requisitos de la macro de prueba de características para glibc (ver feature_test_macros(7)):

settimeofday():

    Desde glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 y anteriores:
        _BSD_SOURCE

DESCRIPCIÓN

Las funciones gettimeofday() y settimeofday() pueden obtener y establecer la hora, así como la zona horaria.

El argumento tv es un struct timeval (como se especifica en <sys/time.h>):


struct timeval {
    time_t      tv_sec;     /* segundos */
    suseconds_t tv_usec;    /* microsegundos */
};

y proporciona el número de segundos y microsegundos desde la Época (ver time(2)).

El argumento tz es un struct timezone:


struct timezone {
    int tz_minuteswest;     /* minutos al oeste de Greenwich */
    int tz_dsttime;         /* tipo de corrección de horario de verano */
};

Si tv o tz es NULL, la estructura correspondiente no se establece ni se devuelve. (Sin embargo, se generarán advertencias de compilación si tv es NULL).

El uso de la estructura timezone está obsoleto; el argumento tz normalmente debería especificarse como NULL. Ver VERSIONES.

En Linux, existen algunas peculiaridades de semántica de "reloj de alarma" asociadas a la llamada al sistema settimeofday() si en la primera llamada (después del arranque) que tiene un argumento tz no NULL, el argumento tv es NULL y el campo tz_minuteswest es distinto de cero. (El campo tz_dsttime debe ser cero para este caso.) En tal caso, se asume que el reloj CMOS está en hora local, y que debe incrementarse en esta cantidad para obtener la hora del sistema UTC. Sin duda, es una mala idea usar esta característica.

VALOR DE RETORNO

gettimeofday() y settimeofday() devuelven 0 en caso de éxito. En caso de error, devuelven -1 y errno se establece para indicar el error.

ERRORES

EFAULT
Uno de los argumentos tv o tz apuntaba fuera del espacio de direcciones accesible.
EINVAL
(settimeofday()): timezone es inválida.
EINVAL
(settimeofday()): tv.tv_sec es negativo o tv.tv_usec está fuera del rango [0, 999,999].
EINVAL (desde Linux 4.3)
(settimeofday()): Se intentó establecer la hora a un valor menor que el valor actual del reloj CLOCK_MONOTONIC (ver clock_gettime(2)).
EPERM
El proceso que llama tiene privilegios insuficientes para llamar a settimeofday(); en Linux se requiere la capacidad CAP_SYS_TIME.

VERSIONES

Diferencias biblioteca C/kernel

En algunas arquitecturas, se proporciona una implementación de gettimeofday() en el vdso(7).

El kernel acepta NULL para tv y tz. El argumento de zona horaria es ignorado por glibc y musl, y no se pasa al/desde el kernel. El bionic de Android pasa el argumento de zona horaria al/desde el kernel, pero Android no actualiza la zona horaria del kernel según la zona horaria del dispositivo en Configuración, por lo que la zona horaria del kernel es típicamente UTC.

ESTÁNDARES

Ninguno.

HISTORIA

SVr4, 4.3BSD. POSIX.1-2001 describía gettimeofday() pero no settimeofday(). POSIX.1-2008 marcó gettimeofday() como obsoleto, recomendando el uso de clock_gettime(2) en su lugar. De manera similar, clock_settime(2) debería usarse en lugar de settimeofday(). POSIX.1-2024 eliminó gettimeofday().

Tradicionalmente, los campos de struct timeval eran de tipo long.

El campo tz_dsttime

En un kernel no Linux, con glibc, el campo tz_dsttime de struct timezone se establecerá en un valor distinto de cero por gettimeofday() si la zona horaria actual ha tenido alguna vez o tendrá una regla de horario de verano aplicada. En este sentido, refleja exactamente el significado de daylight(3) para la zona actual. En Linux, con glibc, la configuración del campo tz_dsttime de struct timezone nunca ha sido utilizada por settimeofday() o gettimeofday(). Por lo tanto, lo siguiente es puramente de interés histórico.

En sistemas antiguos, el campo tz_dsttime contiene una constante simbólica (los valores se dan a continuación) que indica en qué parte del año está en vigor el horario de verano. (Nota: este valor es constante durante todo el año: no indica que el horario de verano esté en vigor, solo selecciona un algoritmo). Los algoritmos de horario de verano definidos son los siguientes:


DST_NONE     /* no en horario de verano */
DST_USA      /* horario de verano estilo EE. UU. */
DST_AUST     /* horario de verano estilo australiano */
DST_WET      /* horario de verano de Europa Occidental */
DST_MET      /* horario de verano de Europa Central */
DST_EET      /* horario de verano de Europa Oriental */
DST_CAN      /* Canadá */
DST_GB       /* Gran Bretaña e Irlanda */
DST_RUM      /* Rumania */
DST_TUR      /* Turquía */
DST_AUSTALT  /* estilo australiano con cambio en 1986 */

Por supuesto, resultó que el período en el que está en vigor el horario de verano no se puede dar con un algoritmo simple, uno por país; de hecho, este período está determinado por decisiones políticas impredecibles. Así que este método de representación de zonas horarias ha sido abandonado.

NOTAS

La hora devuelta por gettimeofday() se ve afectada por saltos discontinuos en la hora del sistema (por ejemplo, si el administrador del sistema cambia manualmente la hora del sistema). Si necesita un reloj monótonamente creciente, consulte clock_gettime(2).

Las macros para operar en estructuras timeval se describen en timeradd(3).
