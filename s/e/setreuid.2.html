setreuid(2) Manual de llamadas al sistema setreuid(2)

NOMBRE

setreuid, setregid - establecer el ID de usuario o grupo real y/o efectivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int setreuid(uid_t ruid, uid_t euid);
int setregid(gid_t rgid, gid_t egid);
Requisitos de Macro de Prueba de Funciones para glibc (ver feature_test_macros(7)):

setreuid(), setregid():

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _BSD_SOURCE

DESCRIPCIÓN

setreuid() establece los IDs de usuario real y efectivo del proceso que realiza la llamada.

Proporcionar un valor de -1 para el ID de usuario real o efectivo hace que el sistema deje ese ID sin cambios.

Los procesos no privilegiados solo pueden establecer el ID de usuario efectivo al ID de usuario real, el ID de usuario efectivo, o el ID de usuario con set guardado.

Los usuarios no privilegiados solo pueden establecer el ID de usuario real al ID de usuario real o al ID de usuario efectivo.

Si se establece el ID de usuario real (es decir, ruid no es -1) o el ID de usuario efectivo se establece a un valor no igual al ID de usuario real anterior, el ID de usuario con set guardado se establecerá al nuevo ID de usuario efectivo.

De forma completamente análoga, setregid() establece los IDs de grupo reales y efectivos del proceso que realiza la llamada, y todo lo anterior se mantiene con "grupo" en lugar de "usuario".

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y se establece errno para indicar el error.

Nota: hay casos en los que setreuid() puede fallar incluso cuando el llamante tiene UID 0; omitir la verificación de un retorno de fallo de setreuid() es un grave error de seguridad.

ERRORES

EAGAIN
La llamada cambiaría el UID real del llamante (es decir, ruid no coincide con el UID real del llamante), pero hubo un fallo temporal al asignar las estructuras de datos necesarias del kernel.
EAGAIN
ruid no coincide con el UID real del llamante y esta llamada superaría el límite de recursos RLIMIT_NPROC del llamante para los procesos que pertenecen al UID real ruid. Desde Linux 3.1, este caso de error ya no ocurre (pero las aplicaciones robustas deben verificar este error); ver la descripción de EAGAIN en execve(2).
EINVAL
Uno o más de los IDs de usuario o grupo de destino no son válidos en este espacio de nombres de usuario.
EPERM
El proceso que realiza la llamada no está privilegiado (en Linux, no tiene la capacidad necesaria en su espacio de nombres de usuario: CAP_SETUID en el caso de setreuid(), o CAP_SETGID en el caso de setregid()) y se especificó un cambio distinto de (i) intercambiar el ID de usuario (grupo) efectivo con el ID de usuario (grupo) real, o (ii) establecer uno al valor del otro, o (iii) establecer el ID de usuario (grupo) efectivo al valor del ID de usuario (grupo) con set guardado.

VERSIONES

POSIX.1 no especifica todos los cambios de UID que Linux permite para un proceso no privilegiado. Para setreuid(), el ID de usuario efectivo puede hacerse igual al ID de usuario real o al ID de usuario con set guardado, y no se especifica si los procesos no privilegiados pueden establecer el ID de usuario real al ID de usuario real, al ID de usuario efectivo, o al ID de usuario con set guardado. Para setregid(), el ID de grupo real puede cambiarse al valor del ID de grupo con set guardado, y el ID de grupo efectivo puede cambiarse al valor del ID de grupo real o al ID de grupo con set guardado. Los detalles precisos de qué cambios de ID están permitidos varían según la implementación.

POSIX.1 no hace ninguna especificación sobre el efecto de estas llamadas en el ID de usuario con set guardado y el ID de grupo con set guardado.

ESTANDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, 4.3BSD (apareció por primera vez en 4.2BSD).

Establecer el ID de usuario (grupo) efectivo al ID de usuario (grupo) con set guardado es posible desde Linux 1.1.37 (1.1.38).

Las llamadas al sistema originales setreuid() y setregid() de Linux solo admitían IDs de usuario y grupo de 16 bits. Posteriormente, Linux 2.4 añadió setreuid32() y setregid32(), que admiten IDs de 32 bits. Las funciones envoltorio setreuid() y setregid() de glibc manejan de forma transparente las variaciones entre versiones del kernel.

Diferencias de la biblioteca C/kernel

A nivel de kernel, los IDs de usuario y grupo son un atributo por hilo. Sin embargo, POSIX requiere que todos los hilos de un proceso compartan las mismas credenciales. La implementación de hilos NPTL maneja los requisitos de POSIX proporcionando funciones envoltorio para las diversas llamadas al sistema que cambian los UID y GID del proceso. Estas funciones envoltorio (incluidas las de setreuid() y setregid()) emplean una técnica basada en señales para garantizar que cuando un hilo cambia las credenciales, todos los demás hilos del proceso también cambien sus credenciales. Para más detalles, ver nptl(7).

NOMBRE

setreuid - establecer el ID de usuario real, efectivo y guardado

SINOPSIS

#include <unistd.h>

int setreuid(int real, int effective, int saved);

DESCRIPCIÓN

La llamada al sistema setreuid() establece los IDs de usuario real, efectivo y guardado del proceso que realiza la llamada.

Los argumentos real, effective y saved especifican los nuevos valores para los IDs de usuario real, efectivo y guardado, respectivamente.

Solo el proceso con privilegios de superusuario (con el bit CAP_SETUID establecido) puede establecer cualquiera de los IDs en un valor arbitrario. Un proceso no privilegiado puede realizar las siguientes acciones:

  • Si real no es -1, entonces real debe ser igual al ID de usuario real actual, al ID de usuario efectivo actual o al ID de usuario guardado actual. Si real se establece, el nuevo ID de usuario real se establece en el valor de real.
  • Si effective no es -1, entonces effective debe ser igual al ID de usuario real actual, al ID de usuario efectivo actual o al ID de usuario guardado actual. Si effective se establece, el nuevo ID de usuario efectivo se establece en el valor de effective.
  • Si saved no es -1, entonces saved debe ser igual al ID de usuario real actual, al ID de usuario efectivo actual o al ID de usuario guardado actual. Si saved se establece, el nuevo ID de usuario guardado se establece en el valor de saved.

Si un argumento es -1, el ID de usuario correspondiente no se cambia.

Una característica importante de setreuid() es que un proceso puede intercambiar sus IDs de usuario real y efectivo proporcionando sus IDs actuales para los argumentos correspondientes. Esto es útil para que un programa con privilegios limite temporalmente sus privilegios estableciendo su ID de usuario real en un UID no privilegiado y luego, si es necesario, restaurando su ID de usuario efectivo original.

VALOR DE RETORNO

En caso de éxito, setreuid() devuelve 0.

En caso de error, devuelve -1 y establece errno para indicar el error.

ERRORES

EAGAIN
Se intentó establecer un ID de usuario real, pero el ID de usuario real actual es un UID no privilegiado y el nuevo ID de usuario real solicitado también es un UID no privilegiado, pero diferente del actual. (Esto solo se aplica en sistemas que implementan el comportamiento de setuid() de Linux, que es establecer el ID real solo cuando se intenta establecer en un UID no privilegiado).
EINVAL
Se especificó un valor de argumento inválido (por ejemplo, un ID de usuario negativo que no sea -1).
EPERM
Se intentó establecer un ID de usuario en un valor que no está permitido por las reglas de un proceso no privilegiado, y el proceso no tiene privilegios de superusuario.

CONFORME A

Esta llamada al sistema es específica de Linux. No forma parte de ninguna norma POSIX.

NOTAS

En la mayoría de los sistemas Unix, la llamada al sistema setuid() se utiliza para establecer el ID de usuario efectivo y, opcionalmente, el ID de usuario real y guardado. setreuid() proporciona un control más fino sobre estos tres IDs.

La diferencia clave entre setreuid() y setuid() (y seteuid()) es que setreuid() permite establecer los tres IDs de usuario (real, efectivo y guardado) de forma independiente, mientras que las otras dos llamadas solo permiten establecer el ID efectivo y, en algunos casos, el ID real o guardado de forma limitada.

El ID de usuario guardado (saved user ID) es un atributo que se utiliza en sistemas que implementan la "ejecución con privilegios limitados" (unprivileged execution). Cuando un programa se ejecuta con privilegios elevados, su ID de usuario efectivo es 0 (root), pero su ID de usuario real y guardado son el UID del usuario que lo inició. Al hacer un setuid() a un UID no privilegiado, el ID de usuario efectivo se cambia, pero el ID de usuario guardado permanece igual. Esto permite que el programa vuelva a sus privilegios originales si es necesario.

EJEMPLO

El siguiente ejemplo muestra cómo un programa puede usar setreuid() para cambiar temporalmente su ID de usuario efectivo a uno no privilegiado y luego restaurarlo:

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <errno.h>

int main() {
    uid_t ruid, euid, suid;

    // Obtener los IDs de usuario actuales
    if (getresuid(&ruid, &euid, &suid) == -1) {
        perror("getresuid");
        return 1;
    }
    printf("Antes: RUID=%d, EUID=%d, SUID=%d\n", ruid, euid, suid);

    // Intentar cambiar el ID de usuario efectivo a un UID no privilegiado (por ejemplo, 1000)
    // Para que esto funcione sin ser root, el UID guardado debe ser 1000.
    // En un escenario real, este programa probablemente se ejecutaría con setuid().
    // Aquí, para demostración, asumiremos que EUID y SUID son 1000.
    // Si EUID es 0 (root), necesitarías permisos de root para establecer un EUID no privilegiado.

    uid_t target_uid = 1000; // Un UID no privilegiado de ejemplo

    // Intentar cambiar el EUID a target_uid.
    // Si el SUID es target_uid, esto debería funcionar para un proceso no root.
    if (setreuid(ruid, target_uid) == -1) {
        // Si EUID es 0, podemos intentar cambiar EUID y RUID a target_uid
        // y SUID se mantendrá como el EUID original (0).
        if (euid == 0) {
            printf("Soy root, intentando cambiar EUID y RUID a %d\n", target_uid);
            if (setreuid(target_uid, target_uid) == -1) {
                perror("setreuid (root)");
                return 1;
            }
        } else {
            perror("setreuid");
            return 1;
        }
    }

    // Verificar los IDs después del cambio
    if (getresuid(&ruid, &euid, &suid) == -1) {
        perror("getresuid");
        return 1;
    }
    printf("Después del cambio: RUID=%d, EUID=%d, SUID=%d\n", ruid, euid, suid);

    // Restablecer los IDs de usuario (si somos root)
    if (euid == 0) {
        printf("Restableciendo IDs de usuario a los originales...\n");
        if (setreuid(ruid, euid) == -1) { // RUID original, EUID original (root)
            perror("setreuid (restore)");
            return 1;
        }
        if (getresuid(&ruid, &euid, &suid) == -1) {
            perror("getresuid");
            return 1;
        }
        printf("Después de restablecer: RUID=%d, EUID=%d, SUID=%d\n", ruid, euid, suid);
    } else {
        // Si no somos root, solo podemos volver al SUID original si lo tenemos
        printf("Intentando volver al SUID original...\n");
        if (setreuid(-1, suid) == -1) {
            perror("setreuid (restore non-root)");
            return 1;
        }
        if (getresuid(&ruid, &euid, &suid) == -1) {
            perror("getresuid");
            return 1;
        }
        printf("Después de intentar volver: RUID=%d, EUID=%d, SUID=%d\n", ruid, euid, suid);
    }


    return 0;
}

ERRORES

Las comprobaciones de errores para setreuid() pueden ser confusas, especialmente en lo que respecta a la diferencia entre IDs de usuario privilegiados y no privilegiados. La documentación de setuid() y seteuid() puede ser útil para comprender el comportamiento de los IDs de usuario en Linux.
