getitimer(2) Manual de llamadas al sistema getitimer(2)

NOMBRE

getitimer, setitimer - obtener o establecer el valor de un temporizador de intervalo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/time.h>
int getitimer(int which, struct itimerval *curr_value);
int setitimer(int which, const struct itimerval *restrict new_value,
              struct itimerval *_Nullable restrict old_value);

DESCRIPCIÓN

Estas llamadas al sistema proporcionan acceso a temporizadores de intervalo, es decir, temporizadores que expiran inicialmente en algún momento futuro y (opcionalmente) a intervalos regulares después de eso. Cuando un temporizador expira, se genera una señal para el proceso que llama, y el temporizador se restablece al intervalo especificado (si el intervalo es distinto de cero).

Se proporcionan tres tipos de temporizadores, especificados a través del argumento which, cada uno de los cuales cuenta contra un reloj diferente y genera una señal diferente al expirar el temporizador:

ITIMER_REAL
Este temporizador cuenta hacia atrás en tiempo real (es decir, reloj de pared). En cada expiración, se genera una señal SIGALRM.
ITIMER_VIRTUAL
Este temporizador cuenta hacia atrás contra el tiempo de CPU en modo de usuario consumido por el proceso. (La medición incluye el tiempo de CPU consumido por todos los hilos del proceso.) En cada expiración, se genera una señal SIGVTALRM.
ITIMER_PROF
Este temporizador cuenta hacia atrás contra el tiempo total de CPU (tanto de usuario como del sistema) consumido por el proceso. (La medición incluye el tiempo de CPU consumido por todos los hilos del proceso.) En cada expiración, se genera una señal SIGPROF.
En conjunción con ITIMER_VIRTUAL, este temporizador se puede utilizar para perfilar el tiempo de CPU de usuario y del sistema consumido por el proceso.

Un proceso tiene solo uno de cada uno de los tres tipos de temporizadores.

Los valores de los temporizadores se definen mediante las siguientes estructuras:


struct itimerval {
    struct timeval it_interval; /* Intervalo para temporizador periódico */
    struct timeval it_value;    /* Tiempo hasta la próxima expiración */
};
struct timeval {
    time_t      tv_sec;         /* segundos */
    suseconds_t tv_usec;        /* microsegundos */
};

getitimer()

La función getitimer() coloca el valor actual del temporizador especificado por which en el búfer apuntado por curr_value.

La subestructura it_value se rellena con la cantidad de tiempo restante hasta la próxima expiración del temporizador especificado. Este valor cambia a medida que el temporizador cuenta hacia atrás y se restablecerá a it_interval cuando expire el temporizador. Si ambos campos de it_value son cero, entonces este temporizador está actualmente desarmado (inactivo).

La subestructura it_interval se rellena con el intervalo del temporizador. Si ambos campos de it_interval son cero, entonces este es un temporizador de disparo único.

setitimer()

La función setitimer() arma o desarma el temporizador especificado por which, estableciendo el temporizador al valor especificado por new_value. Si old_value no es NULL, el búfer al que apunta se utiliza para devolver el valor anterior del temporizador (es decir, la misma información que devuelve getitimer()).

Si alguno de los campos de new_value.it_value es distinto de cero, entonces el temporizador se arma para que expire inicialmente en el tiempo especificado. Si ambos campos de new_value.it_value son cero, entonces el temporizador se desarma.

El campo new_value.it_interval especifica el nuevo intervalo para el temporizador; si ambos de sus subcampos son cero, el temporizador es de disparo único.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EFAULT
new_value, old_value o curr_value no es un puntero válido.
EINVAL
which no es uno de ITIMER_REAL, ITIMER_VIRTUAL o ITIMER_PROF; o (desde Linux 2.6.22) uno de los campos tv_usec en la estructura apuntada por new_value contiene un valor fuera del rango [0, 999999].

VERSIÓNES

Los estándares no especifican el significado de la llamada:


setitimer(which, NULL, &old_value);

Muchos sistemas (Solaris, los BSDs y quizás otros) tratan esto como equivalente a:


getitimer(which, &old_value);

En Linux, esto se trata como equivalente a una llamada en la que los campos new_value son cero; es decir, el temporizador se deshabilita. No utilice esta característica errónea de Linux: no es portable y es innecesaria.

ESTÁNDARES

Ninguno.

HISTORIA

POSIX.1-2001, SVr4, 4.4BSD (esta llamada apareció por primera vez en 4.2BSD). POSIX.1-2008 marcó getitimer() y setitimer() como obsoletas, recomendando el uso de la API de temporizadores POSIX (timer_gettime(2), timer_settime(2), etc.) en su lugar. POSIX.1-2024 las eliminó.

NOTAS

Los temporizadores nunca expirarán antes de la hora solicitada, pero pueden expirar poco tiempo después, lo que depende de la resolución del temporizador del sistema y de la carga del sistema; consulte time(7). (Pero consulte ERRORES a continuación). Si el temporizador expira mientras el proceso está activo (siempre cierto para ITIMER_VIRTUAL), la señal se entregará inmediatamente cuando se genere.

Un hijo creado a través de fork(2) no hereda los temporizadores de intervalo de su padre. Los temporizadores de intervalo se conservan a través de una execve(2).

POSIX.1 deja sin especificar la interacción entre setitimer() y las tres interfaces alarm(2), sleep(3) y usleep(3).

ERRORES DE PROGRAMACIÓN

La generación y entrega de una señal son distintas, y solo puede haber una instancia pendiente de cada una de las señales mencionadas anteriormente para un proceso. Bajo una carga muy alta, un temporizador ITIMER_REAL puede expirar antes de que se entregue la señal de una expiración anterior. La segunda señal en tal evento se perderá.

Antes de Linux 2.6.16, los valores de los temporizadores se representan en jiffies. Si se realiza una solicitud para establecer un temporizador con un valor cuya representación en jiffies excede MAX_SEC_IN_JIFFIES (definido en include/linux/jiffies.h), entonces el temporizador se trunca silenciosamente a este valor máximo. En Linux/i386 (donde, desde Linux 2.6.13, el jiffy predeterminado es 0.004 segundos), esto significa que el valor máximo para un temporizador es de aproximadamente 99.42 días. Desde Linux 2.6.16, el kernel utiliza una representación interna diferente para los tiempos y se elimina este máximo.

En ciertos sistemas (incluido i386), los kernels de Linux anteriores a Linux 2.6.12 tienen un error que producirá expiraciones prematuras de temporizador de hasta un jiffy en algunas circunstancias. Este error se corrige en Linux 2.6.12.

POSIX.1-2001 dice que setitimer() debería fallar si se especifica un valor tv_usec que está fuera del rango [0, 999999]. Sin embargo, hasta Linux 2.6.21 inclusive, Linux no genera un error, sino que ajusta silenciosamente el valor de segundos correspondiente para el temporizador. A partir de Linux 2.6.22, esta no conformidad se ha reparado: un valor tv_usec incorrecto da como resultado un error EINVAL.
