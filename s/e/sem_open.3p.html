SEM_OPEN(3P) Manual del programador POSIX SEM_OPEN(3P)

PRÓLOGO

Esta página del manual es parte del Manual del Programador POSIX. La implementación en Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

sem_open — inicializar y abrir un semáforo con nombre

SINOPSIS

#include <semaphore.h>
sem_t *sem_open(const char *name, int oflag, ...);

DESCRIPCIÓN

La función sem_open() establecerá una conexión entre un semáforo con nombre y un proceso. Después de una llamada a sem_open() con el nombre de semáforo name, el proceso puede referenciar el semáforo asociado con name utilizando la dirección devuelta por la llamada. Este semáforo puede ser utilizado en llamadas posteriores a sem_wait(), sem_timedwait(), sem_trywait(), sem_post() y sem_close(). El semáforo permanece utilizable por este proceso hasta que el semáforo sea cerrado por una llamada exitosa a sem_close(), _exit(), o una de las funciones exec.

El argumento oflag controla si el semáforo se crea o simplemente se accede mediante la llamada a sem_open(). Las siguientes banderas pueden establecerse en oflag:

O_CREAT
Esta bandera se utiliza para crear un semáforo si aún no existe. Si O_CREAT está establecida y el semáforo ya existe, entonces O_CREAT no tiene efecto, excepto como se indica en O_EXCL. De lo contrario, sem_open() crea un semáforo con nombre. La bandera O_CREAT requiere un tercer y cuarto argumento: mode, que es de tipo mode_t, y value, que es de tipo unsigned. El semáforo se crea con un valor inicial de value. Los valores iniciales válidos para los semáforos son menores o iguales a {SEM_VALUE_MAX}.

El ID de usuario del semáforo se establecerá en el ID de usuario efectivo del proceso. El ID de grupo del semáforo se establecerá en el ID de grupo efectivo del proceso; sin embargo, si el argumento name es visible en el sistema de archivos, el ID de grupo puede establecerse en el ID de grupo del directorio contenedor. Los bits de permiso del semáforo se establecerán en el valor del argumento mode, excepto aquellos establecidos en la máscara de creación de modo de archivo del proceso. Cuando se especifican bits en mode distintos de los bits de permiso de archivo, el efecto no está especificado.

Después de que el semáforo llamado name haya sido creado por sem_open() con la bandera O_CREAT, otros procesos pueden conectarse al semáforo llamando a sem_open() con el mismo valor de name.

O_EXCL
Si O_EXCL y O_CREAT están establecidas, sem_open() falla si el semáforo name existe. La comprobación de la existencia del semáforo y la creación del semáforo si no existe son atómicas con respecto a otros procesos que ejecutan sem_open() con O_EXCL y O_CREAT establecidas. Si O_EXCL está establecida y O_CREAT no está establecida, el efecto es indefinido.

Si se especifican banderas distintas de O_CREAT y O_EXCL en el parámetro oflag, el efecto no está especificado.

El argumento name apunta a una cadena que nombra un objeto semáforo. No está especificado si el nombre aparece en el sistema de archivos y es visible para las funciones que toman rutas como argumentos. El argumento name se ajusta a las reglas de construcción para una ruta, excepto que la interpretación de los caracteres <barra> distintos del carácter <barra> inicial en name está definida por la implementación, y que los límites de longitud para el argumento name están definidos por la implementación y no necesitan ser los mismos que los límites de ruta {PATH_MAX} y {NAME_MAX}. Si name comienza con el carácter <barra>, entonces los procesos que llaman a sem_open() con el mismo valor de name se referirán al mismo objeto semáforo, mientras ese nombre no haya sido eliminado. Si name no comienza con el carácter <barra>, el efecto está definido por la implementación.

Si un proceso realiza múltiples llamadas exitosas a sem_open() con el mismo valor para name, se devolverá la misma dirección de semáforo para cada llamada exitosa, siempre que no haya habido llamadas a sem_unlink() para este semáforo, y al menos una llamada exitosa previa a sem_open() para este semáforo no haya sido emparejada con una llamada a sem_close().

Las referencias a copias del semáforo producen resultados indefinidos.

VALOR DE RETORNO

Al completarse con éxito, la función sem_open() devolverá la dirección del semáforo. De lo contrario, devolverá un valor de SEM_FAILED y establecerá errno para indicar el error. El símbolo SEM_FAILED está definido en la cabecera <semaphore.h>. Ningún retorno exitoso de sem_open() devolverá el valor SEM_FAILED.

ERRORES

Si ocurre alguna de las siguientes condiciones, la función sem_open() devolverá SEM_FAILED y establecerá errno al valor correspondiente:

EACCES
El semáforo con nombre existe y se deniegan los permisos especificados por oflag, o el semáforo con nombre no existe y se deniega el permiso para crear el semáforo con nombre.
EEXIST
O_CREAT y O_EXCL están establecidas y el semáforo con nombre ya existe.
EINTR
La operación sem_open() fue interrumpida por una señal.
EINVAL
La operación sem_open() no es compatible con el nombre dado, o O_CREAT se especificó en oflag y value fue mayor que {SEM_VALUE_MAX}.
EMFILE
Demasiados descriptores de semáforo o descriptores de archivo están siendo utilizados actualmente por este proceso.
ENFILE
Demasiados semáforos están abiertos actualmente en el sistema.
ENOENT
O_CREAT no está establecida y el semáforo con nombre no existe.
ENOMEM
No hay suficiente memoria para la creación del nuevo semáforo con nombre.
ENOSPC
No hay suficiente espacio en un dispositivo de almacenamiento para la creación del nuevo semáforo con nombre.

Si ocurre alguna de las siguientes condiciones, la función sem_open() puede devolver SEM_FAILED y establecer errno al valor correspondiente:

ENAMETOOLONG

La longitud del argumento name excede {_POSIX_PATH_MAX} en sistemas que no soportan la opción XSI o excede {_XOPEN_PATH_MAX} en sistemas XSI, o tiene un componente de ruta que es más largo que {_POSIX_NAME_MAX} en sistemas que no soportan la opción XSI o más largo que {_XOPEN_NAME_MAX} en sistemas XSI.

FUNDAMENTO

Borradores anteriores requerían un valor de retorno de error de -1 con el tipo sem_t * para la función sem_open(), lo cual no está garantizado que sea portable entre implementaciones. El texto revisado proporciona el código de error simbólico SEM_FAILED para eliminar el conflicto de tipos.

DIRECCIONES FUTURAS

Una versión futura podría requerir que las funciones sem_open() y sem_unlink() tengan semántica similar a las operaciones normales del sistema de archivos.

sem_open(3p) — Arch Linux man pages

NAME

sem_open, sem_close, sem_post, sem_trywait, sem_timedwait, sem_unlink - named semaphore operations

SYNOPSIS

#include <semaphore.h>

sem_t *sem_open(const char *name, int oflag, ...);
int sem_close(sem_t *sem);
int sem_post(sem_t *sem);
int sem_trywait(sem_t *sem);
int sem_timedwait(sem_t *sem, const struct timespec *abs_timeout);
int sem_unlink(const char *name);

DESCRIPTION

These functions operate on named semaphores. Named semaphores are system-wide semaphores that can be accessed by multiple unrelated processes. Unnamed semaphores (see sem_init(3)) are initialized in memory and can only be shared by threads within a process or by related processes (e.g., parent and child after a fork(2)).

The name argument is a string that identifies the semaphore. The interpretation of the name depends on the implementation. For POSIX semaphores, the name is typically a unique path name relative to the filesystem root (e.g., “/mysemaphore”). A leading slash is required for POSIX semaphores. Some implementations might support other name spaces.

The sem_open() function establishes a connection between a named semaphore and the calling process. If oflag specifies O_CREAT, the semaphore is created if it does not already exist. If O_CREAT is specified, sem_open() takes two additional arguments: mode and value.

The mode argument specifies the permissions for the new semaphore, in the same way as open(2). If O_CREAT is specified, and the semaphore does not exist, then it is created with this mode. The mode is modified by the process's umask.

The value argument specifies the initial value of the new semaphore. This value must be a non-negative integer. If O_CREAT is specified, and the semaphore does not exist, then it is created with this initial value. If O_CREAT is not specified, the value argument is ignored.

If oflag specifies both O_CREAT and O_EXCL, and the semaphore already exists, sem_open() fails and sets errno to EEXIST.

If oflag does not specify O_CREAT, then name must refer to an existing semaphore. If oflag does not specify O_CREAT, the mode and value arguments are ignored.

The sem_open() function returns a pointer to a sem_t object representing the named semaphore. This pointer is used in subsequent calls to other semaphore functions. On error, sem_open() returns SEM_FAILED and sets errno to indicate the error.

The sem_close() function decrements the count of processes that have the specified semaphore open. When the count reaches zero, the semaphore is destroyed, and any associated system resources are released. The calling process must have successfully opened the semaphore using sem_open().

The sem_post() function increments the value of the semaphore pointed to by sem. If any processes or threads are blocked waiting on the semaphore (by calling sem_wait(3), sem_timedwait(), or sem_trywait()), one of them is unblocked. The order in which waiting processes or threads are unblocked is implementation-dependent.

The sem_trywait() function is similar to sem_wait(3), but it does not block. If the semaphore value is greater than zero, sem_trywait() decrements the semaphore value and returns immediately. If the semaphore value is zero, sem_trywait() returns immediately with an error value set to errno = EAGAIN.

The sem_timedwait() function is similar to sem_wait(3), but it allows specifying a maximum time to wait. The abs_timeout argument points to a structure that specifies the amount of time to wait. If the semaphore value is greater than zero, sem_timedwait() decrements the semaphore value and returns immediately. If the semaphore value is zero, sem_timedwait() blocks until either the semaphore value becomes greater than zero, or the timeout expires. The timeout is an absolute time. If the timeout expires before the semaphore is posted, sem_timedwait() returns with an error value set to errno = ETIMEDOUT.

The sem_unlink() function removes the named semaphore indicated by name. When all processes have closed the semaphore (using sem_close()), the semaphore is destroyed, and any associated system resources are released. If the semaphore does not exist, sem_unlink() fails and sets errno to ENOENT.

RETURN VALUE

On success, sem_open() returns a pointer to a sem_t object. On failure, it returns SEM_FAILED and sets errno. On success, sem_close(), sem_post(), sem_trywait(), sem_timedwait(), and sem_unlink() return 0. On failure, they return -1 and set errno to indicate the error.

ERRORS

The errors documented below are common to most of these functions. Specific functions may have additional errors.

EACCES

    Permission denied for opening or unlinking the semaphore.

EAGAIN

    The semaphore could not be locked immediately in sem_trywait().
    Resource temporarily unavailable (e.g., too many semaphores open).

EINTR

    A signal interrupted the operation.

EINVAL

    Invalid semaphore name, invalid flags, invalid initial value, or invalid
    timeout specified.

EMFILE

    Too many file descriptors are open by the calling process. (This error
    can occur in sem_open() if semaphores are implemented using files.)

ENAMETOOLONG

    The length of the name string exceeds the system limit.

ENOENT

    The semaphore specified by name does not exist, and O_CREAT was not
    specified in sem_open().

ENOMEM

    Insufficient memory available to create the semaphore.

ENOSPC

    The system limit for the number of named semaphores has been reached.

ENOSYS

    The underlying system does not support named semaphores.

EPERM

    The caller does not have permission to unlink the semaphore.

ETIMEDOUT

    The timeout expired in sem_timedwait() before the semaphore could be
    acquired.

Additional errors may be returned by underlying system calls (e.g., `open`, `unlink`).

EXAMPLES

The following example shows how to create a semaphore, wait for it, post it, and then unlink it.

Create a semaphore named /mysem with an initial value of 1, open it for writing, wait for it, post it, close it, and then unlink it.

#include <fcntl.h>        /* For O_* constants */
#include <semaphore.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>     /* For mode constants */
#include <time.h>          /* For timespec structure */
#include <errno.h>

int main(void) {
    sem_t *sem;
    const char *name = "/mysem";
    unsigned int value = 1;
    struct timespec ts;

    /* Create the semaphore with initial value 1 */
    sem = sem_open(name, O_CREAT | O_EXCL, 0644, value);
    if (sem == SEM_FAILED) {
        if (errno == EEXIST) {
            /* Semaphore already exists, open it without creating */
            sem = sem_open(name, 0);
            if (sem == SEM_FAILED) {
                perror("sem_open (existing)");
                exit(EXIT_FAILURE);
            }
        } else {
            perror("sem_open (new)");
            exit(EXIT_FAILURE);
        }
    }

    printf("Semaphore opened.\n");

    /* Wait for the semaphore (decrement count) */
    printf("Waiting for semaphore...\n");
    if (sem_wait(sem) == -1) {
        perror("sem_wait");
        sem_close(sem);
        sem_unlink(name);
        exit(EXIT_FAILURE);
    }
    printf("Semaphore acquired.\n");

    /* Example of timed wait */
    // Get current time + 1 second
    if (clock_gettime(CLOCK_REALTIME, &ts) == -1) {
        perror("clock_gettime");
        sem_close(sem);
        sem_unlink(name);
        exit(EXIT_FAILURE);
    }
    ts.tv_sec += 1;

    printf("Trying timed wait...\n");
    if (sem_timedwait(sem, &ts) == -1) {
        if (errno == ETIMEDOUT) {
            printf("Timed wait timed out.\n");
            // Note: If timedwait timed out, the semaphore value was not decremented
        } else {
            perror("sem_timedwait");
            sem_close(sem);
            sem_unlink(name);
            exit(EXIT_FAILURE);
        }
    } else {
        printf("Timed wait succeeded.\n");
        // If timedwait succeeded, the semaphore value was decremented.
        // We need to post it twice to compensate.
        if (sem_post(sem) == -1) {
             perror("sem_post (timedwait success)");
        }
    }


    /* Post the semaphore (increment count) */
    printf("Posting semaphore...\n");
    if (sem_post(sem) == -1) {
        perror("sem_post");
        sem_close(sem);
        sem_unlink(name);
        exit(EXIT_FAILURE);
    }
    printf("Semaphore posted.\n");

    /* Close the semaphore */
    if (sem_close(sem) == -1) {
        perror("sem_close");
        /* Attempt to unlink even if close failed */
        if (sem_unlink(name) == -1) {
            perror("sem_unlink");
        }
        exit(EXIT_FAILURE);
    }
    printf("Semaphore closed.\n");

    /* Unlink the semaphore */
    if (sem_unlink(name) == -1) {
        perror("sem_unlink");
        exit(EXIT_FAILURE);
    }
    printf("Semaphore unlinked.\n");

    return 0;
}

APPLICATION USAGE

Named semaphores are typically used for inter-process synchronization. They are created and managed using system-wide resources, making them suitable for situations where processes do not share memory.

The name space for semaphores is usually mapped to the filesystem. Therefore, the permissions on the semaphore names in the filesystem typically control access to the semaphores. For POSIX semaphores, the name is expected to be an absolute path starting with '/'.

It is important to ensure that semaphores are properly unlinked when they are no longer needed. Otherwise, they may persist in the system and consume resources. If a program crashes before calling sem_unlink(), the semaphore might remain. A robust application might check for existing semaphores at startup and attempt to clean them up or handle them appropriately.

The initial value passed to sem_open() should be carefully chosen. A value of 1 is typical for binary semaphores used as mutexes.

RATIONALE

Named semaphores provide a mechanism for interprocess synchronization that does not rely on shared memory. This makes them more flexible than unnamed semaphores in certain scenarios, particularly when dealing with unrelated processes.

The POSIX standard defines the interface for named semaphores. The implementation details, such as the underlying mechanism used (e.g., file system objects, message queues, or dedicated kernel objects), are left to the operating system.

The use of file system paths for semaphore names is a common approach that leverages existing kernel mechanisms for naming and access control. This allows administrators to manage semaphore access using standard file permissions.

The inclusion of sem_timedwait() provides a way to avoid deadlocks by limiting the time a process waits for a semaphore. This is crucial for building robust concurrent applications.

FUTURE DIRECTIONS

Future versions of POSIX may standardize additional features related to named semaphores, such as mechanisms for controlling their lifetime or properties beyond the initial value and permissions.

The interaction between named semaphores and other synchronization primitives, as well as potential security implications, might be further explored and standardized.
