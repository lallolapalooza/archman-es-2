NOMBRE

seccomp_notify_alloc, seccomp_notify_free, seccomp_notify_receive, seccomp_notify_respond, seccomp_notify_id_valid, seccomp_notify_fd - Gestionar notificaciones de seccomp

SINOPSIS

#include <seccomp.h>

int seccomp_notify_alloc(struct seccomp_notif **req, struct seccomp_notif_resp **resp)
void seccomp_notify_free(struct seccomp_notif *req, struct seccomp_notif_resp *resp)
int seccomp_notify_receive(int fd, struct seccomp_notif *req)
int seccomp_notify_respond(int fd, struct seccomp_notif_resp *resp)
int seccomp_notify_id_valid(int fd, uint64_t id)
int seccomp_notify_fd(const scmp_filter_ctx ctx)

Enlazar con -lseccomp.

DESCRIPCIÓN

La función seccomp_notify_alloc() asigna dinámicamente suficiente memoria para una notificación de seccomp y su respuesta. Tenga en cuenta que siempre se deben usar estas funciones y no depender de los tamaños de las estructuras en las cabeceras, ya que el tamaño puede variar según la versión del kernel. Esta función se encarga de preguntar al kernel qué tan grande debe ser cada estructura y asigna la cantidad correcta de memoria. La función seccomp_notify_free() libera la memoria asignada por seccomp_notify_alloc().

La función seccomp_notify_receive() recibe una notificación de un descriptor de archivo de notificación de seccomp (obtenido de seccomp_notify_fd()).

La función seccomp_notify_respond() envía una respuesta a una notificación particular. El campo id debe ser el mismo que el id de la solicitud, para que el kernel sepa a qué solicitud corresponde esta respuesta.

La función seccomp_notify_id_valid() comprueba si la llamada al sistema de una solicitud de notificación dada sigue siendo válida, es decir, si la tarea todavía está viva. Consulte NOTAS a continuación para obtener más detalles sobre las condiciones de carrera.

La función seccomp_notify_fd() devuelve el descriptor de archivo de notificación de un filtro después de que haya sido cargado.

VALOR DE RETORNO

La función seccomp_notify_fd() devuelve el descriptor de archivo de notificación del filtro cargado, -1 si aún no se ha creado un descriptor de archivo de notificación y -EINVAL si el contexto del filtro es inválido.

La función seccomp_notify_id_valid() devuelve 0 si el id es válido y -ENOENT si no lo es.

Las funciones seccomp_notify_alloc(), seccomp_notify_receive() y seccomp_notify_respond() devuelven cero si tienen éxito, o uno de los siguientes códigos de error en caso de fallo:

-ECANCELED
Hubo un fallo del sistema más allá del control de la biblioteca, consulte el valor de errno para obtener más información.
-EFAULT
Fallo interno de libseccomp.
-ENOMEM
La biblioteca no pudo asignar suficiente memoria.
-EOPNOTSUPP
La biblioteca no admite la operación en particular.

NOTAS

Se debe tener cuidado para evitar dos errores diferentes de tiempo de comprobación/tiempo de uso. Primero, después de abrir cualquier recurso relevante para el pid de una notificación (por ejemplo, /proc/pid/mem para leer la memoria del tracee para tomar decisiones de política), las aplicaciones deben llamar a seccomp_notify_id_valid() para asegurarse de que los recursos que la aplicación ha abierto corresponden al pid correcto, es decir, que el pid no murió y una tarea diferente lo reemplazó.

Segundo, también se debe evitar el clásico problema de tiempo de comprobación/tiempo de uso con la memoria de seccomp: las aplicaciones deben copiar cualquier memoria que deseen utilizar para tomar decisiones del tracee a su propio espacio de direcciones antes de aplicar cualquier decisión de política, ya que un tracee multihilo puede editar la memoria en cualquier momento, incluso después de que se haya utilizado para tomar una decisión de política.

Un ejemplo completo de cómo evitar estas dos carreras está disponible en el árbol de fuentes del kernel de Linux en /samples/seccomp/user-trap.c.
