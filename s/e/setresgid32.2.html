setresuid(2) Manual de Llamadas al Sistema setresuid(2)

NOMBRE

setresuid, setresgid - establecer el ID de usuario o grupo real, efectivo y guardado

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE         /* Ver feature_test_macros(7) */
#include <unistd.h>
int setresuid(uid_t ruid, uid_t euid, uid_t suid);
int setresgid(gid_t rgid, gid_t egid, gid_t sgid);

DESCRIPCIÓN

setresuid() establece el ID de usuario real, el ID de usuario efectivo y el ID de usuario guardado del proceso que llama.

Un proceso no privilegiado puede cambiar su UID real, UID efectivo y UID guardado, cada uno a uno de: el UID real actual, el UID efectivo actual o el UID guardado actual.

Un proceso privilegiado (en Linux, uno que tenga la capacidad CAP_SETUID) puede establecer su UID real, UID efectivo y UID guardado a valores arbitrarios.

Si uno de los argumentos es igual a -1, el valor correspondiente no se cambia.

Independientemente de los cambios que se realicen en el UID real, UID efectivo y UID guardado, el UID del sistema de archivos siempre se establece al mismo valor que el UID (posiblemente nuevo) efectivo.

De forma completamente análoga, setresgid() establece el GID real, GID efectivo y GID guardado del proceso que llama (y siempre modifica el GID del sistema de archivos para que sea el mismo que el GID efectivo), con las mismas restricciones para los procesos no privilegiados.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

Nota: existen casos en los que setresuid() puede fallar incluso cuando el llamador tiene UID 0; es un grave error de seguridad omitir la comprobación de un valor de retorno de error de setresuid().

ERRORES

EAGAIN
La llamada cambiaría el UID real del llamador (es decir, ruid no coincide con el UID real del llamador), pero hubo un fallo temporal al asignar las estructuras de datos necesarias del kernel.
EAGAIN
ruid no coincide con el UID real del llamador y esta llamada superaría el límite de recursos RLIMIT_NPROC del usuario real ruid. Desde Linux 3.1, este caso de error ya no ocurre (pero las aplicaciones robustas deben comprobar este error); ver la descripción de EAGAIN en execve(2).
EINVAL
Uno o más de los IDs de usuario o grupo de destino no son válidos en este espacio de nombres de usuario.
EPERM
El proceso que llama no tiene privilegios (no tenía la capacidad necesaria en su espacio de nombres de usuario) e intentó cambiar los IDs a valores que no están permitidos. Para setresuid(), la capacidad necesaria es CAP_SETUID; para setresgid(), es CAP_SETGID.

VERSIÓNES

diferencias biblioteca C/kernel

A nivel del kernel, los IDs de usuario y grupo son un atributo por hilo. Sin embargo, POSIX requiere que todos los hilos de un proceso compartan las mismas credenciales. La implementación de hilos NPTL maneja los requisitos de POSIX proporcionando funciones envoltorio para las diversas llamadas al sistema que cambian los UIDs y GIDs de los procesos. Estas funciones envoltorio (incluyendo las de setresuid() y setresgid()) emplean una técnica basada en señales para garantizar que cuando un hilo cambia las credenciales, todos los demás hilos del proceso también cambien sus credenciales. Para más detalles, ver nptl(7).

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2024. Linux 2.1.44, glibc 2.3.2. HP-UX, FreeBSD.

Las llamadas al sistema originales de Linux setresuid() y setresgid() solo admitían IDs de usuario y grupo de 16 bits. Posteriormente, Linux 2.4 añadió setresuid32() y setresgid32(), que admitían IDs de 32 bits. Las funciones envoltorio de glibc setresuid() y setresgid() manejan de forma transparente las variaciones entre versiones del kernel.
