setns(2) Manual de Llamadas al Sistema setns(2)

NOMBRE

setns - Reasociar hilo con un espacio de nombres

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE             /* Ver feature_test_macros(7) */
#include <sched.h>
int setns(int fd, int nstype);

DESCRIPCIÓN

La llamada al sistema setns() permite al hilo que la llama moverse a diferentes espacios de nombres. El argumento fd es uno de los siguientes:

•
un descriptor de archivo que hace referencia a uno de los enlaces mágicos en un directorio /proc/pid/ns/ (o a un montaje bind a dicho enlace);
•
un descriptor de archivo PID (ver pidfd_open(2)).

El argumento nstype se interpreta de manera diferente en cada caso.

fd hace referencia a un enlace /proc/pid/ns/

Si fd hace referencia a un enlace /proc/pid/ns/, entonces setns() reasocia el hilo que llama con el espacio de nombres asociado a ese enlace, sujeto a las restricciones impuestas por el argumento nstype. En este uso, cada llamada a setns() cambia solo una de las membresías de espacio de nombres del llamador.

El argumento nstype especifica qué tipo de espacio de nombres puede unirse el hilo que llama. Este argumento puede tener *uno* de los siguientes valores:

0
Permite unirse a cualquier tipo de espacio de nombres.
CLONE_NEWCGROUP (desde Linux 4.6)
fd debe referirse a un espacio de nombres cgroup.
CLONE_NEWIPC (desde Linux 3.0)
fd debe referirse a un espacio de nombres IPC.
CLONE_NEWNET (desde Linux 3.0)
fd debe referirse a un espacio de nombres de red.
CLONE_NEWNS (desde Linux 3.8)
fd debe referirse a un espacio de nombres de montaje.
CLONE_NEWPID (desde Linux 3.8)
fd debe referirse a un espacio de nombres PID descendiente.
CLONE_NEWTIME (desde Linux 5.8)
fd debe referirse a un espacio de nombres de tiempo.
CLONE_NEWUSER (desde Linux 3.8)
fd debe referirse a un espacio de nombres de usuario.
CLONE_NEWUTS (desde Linux 3.0)
fd debe referirse a un espacio de nombres UTS.

Especificar nstype como 0 es suficiente si el llamador sabe (o no le importa) qué tipo de espacio de nombres se refiere fd. Especificar un valor distinto de cero para nstype es útil si el llamador no sabe qué tipo de espacio de nombres se refiere fd y desea asegurarse de que el espacio de nombres sea de un tipo particular. (El llamador podría no saber el tipo del espacio de nombres al que se refiere fd si el descriptor de archivo fue abierto por otro proceso y, por ejemplo, se pasó al llamador a través de un socket de dominio UNIX.)

fd es un descriptor de archivo PID

Desde Linux 5.8, fd puede referirse a un descriptor de archivo PID obtenido de pidfd_open(2) o clone(2). En este uso, setns() mueve atómicamente el hilo que llama a uno o más de los mismos espacios de nombres que el hilo al que se refiere fd.

El argumento nstype es una máscara de bits especificada OReando *uno o más* de las constantes CLONE_NEW* de espacio de nombres listadas arriba. El llamador se mueve a cada uno de los espacios de nombres del hilo destino especificados en nstype; las membresías del llamador en los espacios de nombres restantes no se modifican.

Por ejemplo, el siguiente código movería al llamador a los mismos espacios de nombres de usuario, red y UTS que el PID 1234, pero dejaría sin cambios las otras membresías de espacio de nombres del llamador:


int fd = pidfd_open(1234, 0);
setns(fd, CLONE_NEWUSER | CLONE_NEWNET | CLONE_NEWUTS);

Detalles para tipos específicos de espacios de nombres

Tenga en cuenta los siguientes detalles y restricciones al reasociarse con tipos específicos de espacios de nombres:

Espacios de nombres de usuario
Un proceso que se reasocia con un espacio de nombres de usuario debe tener la capacidad CAP_SYS_ADMIN en el espacio de nombres de usuario de destino. (Esto implica necesariamente que solo es posible unirse a un espacio de nombres de usuario descendiente.) Al unirse con éxito a un espacio de nombres de usuario, un proceso recibe todas las capacidades en ese espacio de nombres, independientemente de sus IDs de usuario y grupo.
Un proceso multihilo no puede cambiar el espacio de nombres de usuario con setns().
No está permitido usar setns() para volver a entrar al espacio de nombres de usuario actual del llamador. Esto evita que un llamador que ha perdido capacidades las recupere mediante una llamada a setns().
Por razones de seguridad, un proceso no puede unirse a un nuevo espacio de nombres de usuario si está compartiendo atributos relacionados con el sistema de archivos (los atributos cuya compartición se controla mediante el flag CLONE_FS de clone(2)) con otro proceso.
Para más detalles sobre los espacios de nombres de usuario, ver user_namespaces(7).
Espacios de nombres de montaje
Cambiar el espacio de nombres de montaje requiere que el llamador posea las capacidades CAP_SYS_CHROOT y CAP_SYS_ADMIN en su propio espacio de nombres de usuario y CAP_SYS_ADMIN en el espacio de nombres de usuario que posee el espacio de nombres de montaje de destino.
Un proceso no puede unirse a un nuevo espacio de nombres de montaje si está compartiendo atributos relacionados con el sistema de archivos (los atributos cuya compartición se controla mediante el flag CLONE_FS de clone(2)) con otro proceso.
Ver user_namespaces(7) para detalles sobre la interacción de los espacios de nombres de usuario y de montaje.
Espacios de nombres PID
Para reasociarse con un nuevo espacio de nombres PID, el llamador debe tener la capacidad CAP_SYS_ADMIN tanto en su propio espacio de nombres de usuario como en el espacio de nombres de usuario que posee el espacio de nombres PID de destino.
Reasociar el espacio de nombres PID tiene un comportamiento ligeramente diferente al de otros tipos de espacios de nombres. Reasociar el hilo que llama con un espacio de nombres PID solo cambia el espacio de nombres PID en el que se colocarán los procesos hijos creados posteriormente por el llamador; no cambia el espacio de nombres PID del propio llamador.
La reasociación con un espacio de nombres PID solo está permitida si el espacio de nombres PID de destino es un descendiente (hijo, nieto, etc.) de, o es el mismo que, el espacio de nombres PID actual del llamador.
Para más detalles sobre los espacios de nombres PID, ver pid_namespaces(7).
Espacios de nombres Cgroup
Para reasociarse con un nuevo espacio de nombres cgroup, el llamador debe tener la capacidad CAP_SYS_ADMIN tanto en su propio espacio de nombres de usuario como en el espacio de nombres de usuario que posee el espacio de nombres cgroup de destino.
Usar setns() para cambiar el espacio de nombres cgroup del llamador no cambia las membresías cgroup del llamador.
Espacios de nombres de tiempo
Para reasociarse con un nuevo espacio de nombres de tiempo, el llamador debe tener la capacidad CAP_SYS_ADMIN tanto en su propio espacio de nombres de usuario como en el espacio de nombres de usuario que posee el espacio de nombres de destino.
Un proceso multihilo no puede cambiar el espacio de nombres de ti

setns(2) - Linux manual pages

NAME

setns

associate a thread with another process's namespace

LIBRARY

Linux manual pages

SYNOPSIS

#define _GNU_SOURCE
int setns(int fd, int nstype);

DESCRIPTION

The setns() system call allows a thread to join an existing namespace of a specified type. The namespace to join is identified by a file descriptor, fd, which must refer to a namespace file in the /proc/pid/ns/ directory of the process whose namespace is to be joined.

The nstype argument specifies the type of the namespace referred to by fd. It should be one of the following constants:

CLONE_NEWNS
Mount namespace.
CLONE_NEWIPC
IPC namespace.
CLONE_NEWNET
Network namespace.
CLONE_NEWPID
PID namespace.
CLONE_NEWUSER
User namespace.
CLONE_NEWUTS
UTS namespace.
CLONE_NEWCGROUP
cgroup namespace.

If nstype is 0, then setns() infers the namespace type from the type of the namespace file referred to by fd. This is the recommended usage.

The file descriptor fd must have been opened with the O_RDONLY flag. If the file descriptor is opened with O_CLOEXEC, it will be closed automatically after the call to setns() even if the call fails.

A thread can join a new namespace of a given type if it has the necessary capabilities. The specific capabilities required depend on the namespace type and the relationship between the calling thread's user namespace and the target namespace's user namespace.

Mount namespace
To join a new mount namespace, the calling thread must have the CAP_SYS_ADMIN capability in its own user namespace. Additionally, if the target mount namespace is owned by a different user namespace than the calling thread, the calling thread must also have the CAP_SYS_ADMIN capability in the user namespace that owns the target mount namespace.
PID, User, and Cgroup namespaces
To join a new PID, user, or cgroup namespace, the calling thread must have the CAP_SYS_ADMIN capability in its own user namespace. If the target namespace is owned by a different user namespace, the calling thread must also have the CAP_SYS_ADMIN capability in the user namespace that owns the target namespace.
Network, IPC, and UTS namespaces
In order to reassociate itself with a new network, IPC, time, or UTS namespace, the caller must have the CAP_SYS_ADMIN capability both in its own user namespace and in the user namespace that owns the target namespace.

RETURN VALUE

On success, setns() returns 0. On failure, -1 is returned and errno is set to indicate the error.

ERRORS

EBADF
fd is not a valid file descriptor.
EINVAL
fd refers to a namespace whose type does not match that specified in nstype.
EINVAL
There is a problem with reassociating the thread with the specified namespace.
EINVAL
The caller tried to join an ancestor (parent, grandparent, and so on) PID namespace.
EINVAL
The caller attempted to join the user namespace in which it is already a member.
EINVAL
The caller shares filesystem (CLONE_FS) state (in particular, the root directory) with other processes and tried to join a new user namespace.
EINVAL
The caller is multithreaded and tried to join a new user namespace.
EINVAL
fd is a PID file descriptor and nstype is invalid (e.g., it is 0).
ENOMEM
Cannot allocate sufficient memory to change the specified namespace.
EPERM
The calling thread did not have the required capability for this operation.
ESRCH
fd is a PID file descriptor but the process it refers to no longer exists (i.e., it has terminated and been waited on).

STANDARDS

Linux.

VERSIONS

Linux 3.0, glibc 2.14.

NOTES

For further information on the /proc/pid/ns/ magic links, see namespaces(7).

Not all of the attributes that can be shared when a new thread is created using clone(2) can be changed using setns().

EXAMPLES

The program below takes two or more arguments. The first argument specifies the pathname of a namespace file in an existing /proc/pid/ns/ directory. The remaining arguments specify a command and its arguments. The program opens the namespace file, joins that namespace using setns(), and executes the specified command inside that namespace.

The following shell session demonstrates the use of this program (compiled as a binary named ns_exec) in conjunction with the CLONE_NEWUTS example program in the clone(2) man page (complied as a binary named newuts).

We begin by executing the example program in clone(2) in the background. That program creates a child in a separate UTS namespace. The child changes the hostname in its namespace, and then both processes display the hostnames in their UTS namespaces, so that we can see that they are different.


$ su;                   # Need privilege for namespace operations
Password:
# ./newuts bizarro &
[1] 3549
clone() returned 3550
uts.nodename in child:  bizarro
uts.nodename in parent: antero
# uname -n;             # Verify hostname in the shell
antero

We then run the program shown below, using it to execute a shell. Inside that shell, we verify that the hostname is the one set by the child created by the first program:


# ./ns_exec /proc/3550/ns/uts /bin/bash;
# uname -n;             # Executed in shell started by ns_exec
bizarro

Program source

#define _GNU_SOURCE
#include <err.h>
#include <fcntl.h>
#include <sched.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int fd;
    if (argc < 3) {
        fprintf(stderr, "%s /proc/PID/ns/FILE cmd args...\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    /* Get file descriptor for namespace; the file descriptor is opened
       with O_CLOEXEC so as to ensure that it is not inherited by the
       program that is later executed.  */
    fd = open(argv[1], O_RDONLY | O_CLOEXEC);
    if (fd == -1)
        err(EXIT_FAILURE, "open");
    if (setns(fd, 0) == -1)       /* Join that namespace */
        err(EXIT_FAILURE, "setns");
    execvp(argv[2], &argv[2]);    /* Execute a command in namespace */
    err(EXIT_FAILURE, "execvp");
}
