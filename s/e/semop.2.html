semop(2) Manual de Llamadas al Sistema semop(2)

NOMBRE

semop, semtimedop - operaciones de semáforos de System V

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/sem.h>
int semop(int semid, struct sembuf *sops, size_t nsops);
int semtimedop(int semid, struct sembuf *sops, size_t nsops,
               const struct timespec *_Nullable timeout);
Requisitos de macros de prueba de características para glibc (ver feature_test_macros(7)):

semtimedop():

    _GNU_SOURCE

DESCRIPCIÓN

Cada semáforo en un conjunto de semáforos de System V tiene los siguientes valores asociados:


unsigned short  semval;   /* valor del semáforo */
unsigned short  semzcnt;  /* # esperando a cero */
unsigned short  semncnt;  /* # esperando incremento */
pid_t           sempid;   /* PID del proceso que modificó
                             por última vez el valor del semáforo */

semop() realiza operaciones sobre semáforos seleccionados en el conjunto indicado por semid. Cada uno de los nsops elementos en el array apuntado por sops es una estructura que especifica una operación a realizar en un solo semáforo. Los elementos de esta estructura son de tipo struct sembuf, conteniendo los siguientes miembros:


unsigned short sem_num;  /* número de semáforo */
short          sem_op;   /* operación del semáforo */
short          sem_flg;  /* banderas de operación */

Las banderas reconocidas en sem_flg son IPC_NOWAIT y SEM_UNDO. Si una operación especifica SEM_UNDO, se deshace automáticamente cuando el proceso termina.

El conjunto de operaciones contenido en sops se realiza en orden de array y de forma atómica, es decir, las operaciones se realizan ya sea como una unidad completa o no se realizan en absoluto. El comportamiento de la llamada al sistema si no se pueden realizar todas las operaciones de inmediato depende de la presencia de la bandera IPC_NOWAIT en los campos individuales de sem_flg, como se indica a continuación.

Cada operación se realiza sobre el semáforo número sem_num del conjunto de semáforos, donde el primer semáforo del conjunto tiene el número 0. Hay tres tipos de operación, que se distinguen por el valor de sem_op.

Si sem_op es un entero positivo, la operación suma este valor al valor del semáforo (semval). Además, si se especifica SEM_UNDO para esta operación, el sistema resta el valor sem_op al valor de ajuste del semáforo (semadj) para este semáforo. Esta operación siempre puede proceder, nunca obliga a un hilo a esperar. El proceso que llama debe tener permiso de alteración sobre el conjunto de semáforos.

Si sem_op es cero, el proceso debe tener permiso de lectura sobre el conjunto de semáforos. Esta es una operación de "esperar a cero": si semval es cero, la operación puede proceder inmediatamente. De lo contrario, si se especifica IPC_NOWAIT en sem_flg, semop() falla con errno establecido en EAGAIN (y ninguna de las operaciones en sops se realiza). De lo contrario, se incrementa semzcnt (el recuento de hilos que esperan hasta que el valor de este semáforo sea cero) en uno y el hilo duerme hasta que ocurra uno de los siguientes:

•
semval se convierte en 0, momento en el cual el valor de semzcnt se decrementa.
•
El conjunto de semáforos se elimina: semop() falla, con errno establecido en EIDRM.
•
El hilo que llama captura una señal: el valor de semzcnt se decrementa y semop() falla, con errno establecido en EINTR.

Si sem_op es menor que cero, el proceso debe tener permiso de alteración sobre el conjunto de semáforos. Si semval es mayor o igual al valor absoluto de sem_op, la operación puede proceder inmediatamente: el valor absoluto de sem_op se resta de semval y, si se especifica SEM_UNDO para esta operación, el sistema suma el valor absoluto de sem_op al valor de ajuste del semáforo (semadj) para este semáforo. Si el valor absoluto de sem_op es mayor que semval, y se especifica IPC_NOWAIT en sem_flg, semop() falla, con errno establecido en EAGAIN (y ninguna de las operaciones en sops se realiza). De lo contrario, se incrementa semncnt (el contador de hilos que esperan a que aumente el valor de este semáforo) en uno y el hilo duerme hasta que ocurra uno de los siguientes:

•
semval se vuelve mayor o igual al valor absoluto de sem_op: la operación ahora procede, como se describe arriba.
•
El conjunto de semáforos se elimina del sistema: semop() falla, con errno establecido en EIDRM.
•
El hilo que llama captura una señal: el valor de semncnt se decrementa y semop() falla, con errno establecido en EINTR.

Al completarse con éxito, el valor sempid para cada semáforo especificado en el array apuntado por sops se establece en el ID de proceso del llamador. Además, la sem_otime se establece en la hora actual.

semtimedop()

semtimedop() se comporta de manera idéntica a semop() excepto que en aquellos casos en los que el hilo que llama dormiría, la duración de ese sueño está limitada por la cantidad de tiempo transcurrido especificado por la estructura timespec cuya dirección se pasa en el argumento timeout. (Este intervalo de sueño se redondeará hacia arriba a la granularidad del reloj del sistema y los retrasos de planificación del kernel significan que el intervalo puede excederse por una pequeña cantidad). Si el límite de tiempo especificado se ha alcanzado, semtimedop() falla con errno establecido en EAGAIN (y ninguna de las operaciones en sops se realiza). Si el argumento timeout es NULL, entonces semtimedop() se comporta exactamente como semop().

Tenga en cuenta que si semtimedop() es interrumpido por una señal, lo que hace que la llamada falle con el error EINTR, el contenido de timeout permanece sin cambios.

VALOR DE RETORNO

En caso de éxito, semop() y semtimedop() devuelven 0. En caso de fallo, devuelven -1 y establecen errno para indicar el error.

ERRORES

E2BIG
El argumento nsops es mayor que SEMOPM, el número máximo de operaciones permitidas por llamada al sistema.
EACCES
El proceso que llama no tiene los permisos necesarios para realizar las operaciones de semáforo especificadas y no tiene la capacidad CAP_IPC_OWNER en el espacio de nombres del usuario que rige su espacio de nombres IPC.
EAGAIN
Una operación no pudo proceder de inmediato y o bien se especificó IPC_NOWAIT en sem_flg o bien expiró el límite de tiempo especificado en timeout.
EFAULT
Una dirección especificada en el argumento sops o timeout no es accesible.
EFBIG
Para alguna operación, el valor de sem_num es menor que 0 o mayor o igual que el número de semáforos en el conjunto.
EIDRM
Se eliminó el conjunto de semáforos.
EINTR
Mientras estaba bloqueado en esta llamada al sistema, el hilo capturó una señal; ver signal(7).
EINVAL
El conjunto de semáforos no existe, o semid es menor que cero, o nsops tiene un valor no positivo.
ENOMEM

ESTÁNDARES

POSIX.1-2024.

VERSIONES

Linux 2.5.52 (retroportado a Linux 2.4.22), glibc 2.3.3. POSIX.1-2001, SVr4.

NOTAS

Las estructuras sem_undo de un proceso no son heredadas por el hijo producido por fork(2), pero sí son heredadas a través de una llamada al sistema execve(2).

semop() nunca se reinicia automáticamente después de ser interrumpida por un manejador de señales, independientemente de la configuración del flag SA_RESTART al establecer un manejador de señales.

Un valor de ajuste de semáforo (semadj) es un entero por proceso, por semáforo que es la suma negada de todas las operaciones realizadas en un semáforo especificando el flag SEM_UNDO. Cada proceso tiene una lista de valores semadj — un valor por cada semáforo sobre el que ha operado usando SEM_UNDO. Cuando un proceso termina, cada uno de sus valores semadj por semáforo se suma al semáforo correspondiente, deshaciendo así el efecto de las operaciones de ese proceso sobre el semáforo (pero véase ERRORES más abajo). Cuando el valor de un semáforo se establece directamente usando la petición SETVAL o SETALL a semctl(2), los valores semadj correspondientes en todos los procesos se limpian. El flag CLONE_SYSVSEM de clone(2) permite que más de un proceso comparta una lista semadj; véase clone(2) para más detalles.

Los valores semval, sempid, semzcnt y semnct de un semáforo pueden recuperarse todos usando llamadas apropiadas a semctl(2).

Límites de semáforos

Los siguientes límites sobre los recursos de conjuntos de semáforos afectan a la llamada semop():

SEMOPM
Número máximo de operaciones permitidas para una llamada semop(). Antes de Linux 3.19, el valor predeterminado para este límite era 32. Desde Linux 3.19, el valor predeterminado es 500. En Linux, este límite se puede leer y modificar a través del tercer campo de /proc/sys/kernel/sem. Nota: este límite no debe aumentarse por encima de 1000, debido al riesgo de que semop() falle debido a la fragmentación de memoria del kernel al asignar memoria para copiar el array sops.
SEMVMX
Valor máximo permitido para semval: dependiente de la implementación (32767).

La implementación no tiene límites intrínsecos para el valor máximo de ajuste al salir (SEMAEM), el número máximo de estructuras de deshacer a nivel de sistema (SEMMNU) y los parámetros del sistema de entradas máximas de deshacer por proceso.

ERRORES

Cuando un proceso termina, su conjunto de estructuras semadj asociadas se utiliza para deshacer el efecto de todas las operaciones de semáforo que realizó con el flag SEM_UNDO. Esto plantea una dificultad: si uno (o más) de estos ajustes de semáforo resultaran en un intento de disminuir el valor de un semáforo por debajo de cero, ¿qué debería hacer una implementación? Un enfoque posible sería bloquear hasta que todos los ajustes de semáforo pudieran realizarse. Esto, sin embargo, es indeseable ya que podría forzar la terminación del proceso a bloquearse durante períodos de duración arbitraria. Otra posibilidad es que dichos ajustes de semáforo puedan ser ignorados por completo (de forma análoga a fallar cuando se especifica IPC_NOWAIT para una operación de semáforo). Linux adopta un tercer enfoque: disminuir el valor del semáforo tanto como sea posible (es decir, hasta cero) y permitir que la terminación del proceso proceda inmediatamente.

En Linux 2.6.x, x <= 10, hay un error que en algunas circunstancias impide que un hilo que está esperando a que el valor de un semáforo sea cero sea despertado cuando el valor efectivamente llega a cero. Este error está corregido en Linux 2.6.11.

EJEMPLOS

El siguiente segmento de código utiliza semop() para esperar atmicamente a que el valor del semáforo 0 sea cero, y luego incrementar el valor del semáforo en uno.


struct sembuf sops[2];
int semid;
/* Código para establecer semid omitido */
sops[0].sem_num = 0;        /* Operar en el semáforo 0 */
sops[0].sem_op = 0;         /* Esperar a que el valor sea igual a 0 */
sops[0].sem_flg = 0;
sops[1].sem_num = 0;        /* Operar en el semáforo 0 */
sops[1].sem_op = 1;         /* Incrementar el valor en uno */
sops[1].sem_flg = 0;
if (semop(semid, sops, 2) == -1) {
    perror("semop");
    exit(EXIT_FAILURE);
}

Un ejemplo adicional del uso de semop() se puede encontrar en shmop(2).
