selection(n) Tk Built-In Commands selection(n)

NOMBRE

selection - Manipular la selección X

SINOPSIS

selection opción ?arg arg ...?

DESCRIPCIÓN

Este comando proporciona una interfaz Tcl al mecanismo de selección X e implementa la funcionalidad completa de selección descrita en el Manual de Convenciones de Comunicación Inter-Cliente de X (ICCCM).

Tenga en cuenta que para la gestión de la selección CLIPBOARD (ver más abajo), el comando clipboard también puede ser utilizado.

El primer argumento a selection determina el formato del resto de los argumentos y el comportamiento del comando. Las siguientes formas son soportadas actualmente:

selection clear ?-displayof ventana? ?-selection selección?
Si selección existe en algún lugar de la pantalla de ventana, la borra para que ninguna ventana posea la selección. Selección especifica la selección X que debe ser borrada, y debe ser un nombre de átomo como PRIMARY o CLIPBOARD; consulte el Manual de Convenciones de Comunicación Inter-Cliente para detalles completos. Selección por defecto es PRIMARY y ventana por defecto es “.”.. Retorna una cadena vacía.
selection get ?-displayof ventana? ?-selection selección? ?-type tipo?
Recupera el valor de selección de la pantalla de ventana y lo retorna como resultado. Selección por defecto es PRIMARY y ventana por defecto es “.”.. Tipo especifica el formato en el que la selección debe ser retornada (el “target” deseado para conversión, en terminología ICCCM), y debe ser un nombre de átomo como STRING o FILE_NAME; consulte el Manual de Convenciones de Comunicación Inter-Cliente para detalles completos. Tipo por defecto es STRING. El propietario de la selección puede elegir retornar la selección en varios formatos de representación diferentes, como STRING, UTF8_STRING, ATOM, INTEGER, etc. (este formato es diferente del tipo de selección; consulte el ICCCM para todos los detalles confusos). Si la selección es retornada en un formato no-cadena, como INTEGER o ATOM, el comando selection lo convierte a formato de cadena como una colección de campos separados por espacios: los átomos se convierten a sus nombres textuales, y cualquier otra cosa se convierte a enteros hexadecimales. Tenga en cuenta que selection get no recupera la selección en formato UTF8_STRING a menos que se le indique.
selection handle ?-selection s? ?-type t? ?-format f? ventana comando
Crea un manejador para solicitudes de selección, de modo que comando será ejecutado cada vez que la selección s sea propiedad de ventana y alguien intente recuperarla en el formato dado por el tipo t (por ejemplo, t se especifica en el comando selection get). S por defecto es PRIMARY, t por defecto es STRING, y f por defecto es STRING. Si comando es una cadena vacía, entonces cualquier manejador existente para ventana, t, y s es eliminado. Tenga en cuenta que cuando la selección se maneja como tipo STRING, también se maneja automáticamente como tipo UTF8_STRING.

Cuando se solicita selección, ventana es el propietario de la selección, y tipo es el tipo solicitado, comando será ejecutado como un comando Tcl con dos números adicionales añadidos (con separadores de espacio). Los dos números adicionales son offset y maxChars: offset especifica una posición de carácter de inicio en la selección y maxChars da el número máximo de caracteres a recuperar. El comando debe retornar un valor que consista en como máximo maxChars de la selección, comenzando en la posición offset. Para selecciones muy grandes (mayores que maxChars) la selección será recuperada usando varias invocaciones de comando con valores de offset crecientes. Si comando retorna una cadena cuya longitud es menor que maxChars, el valor de retorno se asume que incluye todo el resto de la selección; si la longitud del resultado de comando es igual a maxChars, entonces comando será invocado de nuevo, hasta que eventualmente retorne un resultado más corto que maxChars. El valor de maxChars siempre será relativamente grande (miles de caracteres).

Si comando retorna un error, la recuperación de la selección se rechaza como si la selección no existiera en absoluto.

El argumento formato especifica la representación que debe usarse para transmitir la selección al solicitante (la segunda columna de la Tabla 2 del ICCCM), y por defecto es STRING. Si formato es STRING, la selección se transmite como caracteres ASCII de 8 bits (es decir, simplemente en la forma retornada por comando, en el encoding del sistema; el formato UTF8_STRING siempre usa UTF-8 como su encoding). Si formato es ATOM, entonces el valor de retorno de comando se divide en campos separados por espacios en blanco; cada campo se convierte a su valor de átomo, y el valor de átomo de 32 bits se transmite en lugar del nombre del átomo. Para cualquier otro formato, el valor de retorno de comando se divide en campos separados por espacios en blanco y cada campo se convierte a un entero de 32 bits; se transmite un array de enteros al solicitante de la selección.

El argumento formato solo es necesario para la compatibilidad con los solicitantes de selección que no usan Tk. Si se está usando Tk para recuperar la selección, el valor se convierte de nuevo a una cadena en el extremo del solicitante, por lo que formato es irrelevante.

selection own ?-displayof ventana? ?-selection selección?
selection own ?-command comando? ?-selection selección? ventana
La primera forma de selection own retorna el nombre de ruta de la ventana en esta aplicación que posee selección en la pantalla que contiene ventana, o una cadena vacía si ninguna ventana en esta aplicación posee la selección. Selección por defecto es PRIMARY y ventana por defecto es “.”.

La segunda forma de selection own hace que ventana se convierta en el nuevo propietario de selección en la pantalla de ventana, retornando una cadena vacía como resultado. El propietario existente, si lo hay, es notificado de que ha perdido la selección. Si se especifica comando, es un script Tcl para ejecutar cuando otra ventana reclama la propiedad de la selección a ventana. Selección por defecto es PRIMARY.

FACILIDADES DEL WIDGET

Los widgets text, entry, ttk::entry, listbox, spinbox y ttk::spinbox tienen la opción -exportselection. Si un widget tiene esta opción establecida a booleano true, entonces (en un intérprete seguro) una selección hecha en el widget se escribe automáticamente en la selección PRIMARY.

Un evento GUI, por ejemplo <<PasteSelection>>, puede copiar la selección PRIMARY a ciertos widgets. Esta copia se implementa mediante una vinculación de widget al evento. El script de vinculación realiza llamadas apropiadas al comando selection.

PROBLEMAS DE PORTABILIDAD

En X11, la selección PRIMARY es una característica del servidor X a nivel de sistema, permitiendo la comunicación entre diferentes procesos que son clientes X11.

En Windows, la selección PRIMARY no es proporcionada por el sistema, sino solo por Tk, y por lo tanto solo se comparte entre ventanas de un intérprete padre y sus intérpretes hijos. No se comparte entre intérpretes en diferentes procesos o diferentes hilos. Cada intérprete padre tiene una selección PRIMARY separada que se comparte solo con sus intérpretes hijos que no son intérpretes seguros.

selection(n)

NAME

selection – obtain and release selections between applications

SYNOPSIS

selection get ?-selection selection? ?-type type? ?-timestamp timestamp?

selection handle ?-selection selection? ?-type type? ?-priority priority? ?-command command? ?-cancel command?

selection own ?-command command? ?-selection selection? ?-timestamp timestamp?

selection clear ?-selection selection?

selection info ?-selection selection?

DESCRIPTION

The selection command provides a mechanism for Tk applications to exchange data with other applications using the X selection mechanism. This is a standard mechanism on the X Window System for cut-and-paste operations.

There are several standard selections, including PRIMARY, SECONDARY, and CLIPBOARD. Tk applications typically use the PRIMARY selection for immediate cut/paste (e.g., selecting text in one window and pasting it into another) and the CLIPBOARD selection for explicit copy/paste operations. The SECONDARY selection is less commonly used.

The selection command supports the following subcommands:

selection get ?-selection selection? ?-type type? ?-timestamp timestamp?
Requests data from the selection specified by selection (defaults to PRIMARY). The type argument specifies the desired data type (defaults to TARGETS). Tk will attempt to retrieve the data in the requested type. If the TARGETS type is requested, the command returns a list of data types supported by the current owner of the selection. If the selection owner does not support the requested type, an error is returned. The timestamp argument is typically unused by Tk itself but may be required by some selection protocols. Returns the data from the selection in the requested format. The format of the returned data depends on the type requested.
selection handle ?-selection selection? ?-type type? ?-priority priority? ?-command command? ?-cancel command?
Registers a handler to provide data for a selection. When another application requests data from the specified selection (defaults to PRIMARY) in the specified type (defaults to TEXT), the command procedure will be invoked. The command procedure will be called with two arguments: the offset and the maximum number of characters to return. It should return the requested portion of the data. The priority argument (an integer) determines the order in which handlers are considered; higher values have higher priority. The cancel command is invoked if the application loses ownership of the selection while data is being transferred.
selection own ?-command command? ?-selection selection? ?-timestamp timestamp?
Claims ownership of the specified selection (defaults to PRIMARY). If another application already owns the selection, ownership is not claimed. The command procedure is invoked if the application loses ownership of the selection. The timestamp argument is typically unused by Tk itself but may be required by some selection protocols.
selection clear ?-selection selection?
Releases ownership of the specified selection (defaults to PRIMARY). If the application does not own the selection, this command has no effect.
selection info ?-selection selection?
Returns information about the specified selection (defaults to PRIMARY). The information is returned as a list of strings, describing the owner application, the data type, and other relevant details.

WIDGET FACILITIES

Most Tk widgets that can display or edit text (e.g., entry, text, label) have an option called -exportselection. When this option is set to boolean true, the widget automatically participates in the selection mechanism. For example, if -exportselection is true for a text widget, selecting text within that widget will place the selected text onto the PRIMARY selection. Similarly, if the widget can accept pasted text, it will automatically paste data from the PRIMARY selection when requested.

By default, -exportselection is true for most text-displaying widgets.

PORTABILITY ISSUES

The selection mechanism described here is specific to the X Window System. On other platforms, Tk may simulate some aspects of the selection mechanism using the native clipboard facilities, but the behavior may not be identical.

SECURITY

Tk provides a mechanism for creating "safe interpreters" that can run untrusted Tcl code. In a safe interpreter, certain Tcl commands are restricted or disabled to prevent malicious code from harming the system. The selection command is affected by these restrictions.

Specifically, within a safe interpreter:

  • The selection get command can only retrieve data of type TEXT. Retrieving other data types is disabled.
  • The selection own and selection handle commands are completely disabled. This means that code running in a safe interpreter cannot claim ownership of a selection or provide data for a selection.

These restrictions are in place because selections can contain sensitive information. Allowing untrusted code to read arbitrary selections or to provide data for selections could pose a security risk. For example, untrusted code could try to read passwords or other sensitive data from the CLIPBOARD selection.

A Tk widget can have its option -exportselection set to boolean true, but in a safe interpreter this option has no effect: writing from the widget to the PRIMARY selection is disabled.

These are security features. A safe interpreter may run untrusted code, and it is a security risk if this untrusted code can read or write the PRIMARY selection used by other interpreters.

EXAMPLES

On X11 platforms, one of the standard selections available is the SECONDARY selection. Hardly anything uses it, but here is how to read it using Tk:

set selContents [selection get -selection SECONDARY]

Many different types of data may be available for a selection; the special type TARGETS allows you to get a list of available types:

foreach type [selection get -type TARGETS] {
   puts "Selection PRIMARY supports type $type"
}

To claim the selection, you must first set up a handler to supply the data for the selection. Then you have to claim the selection...

# Set up the data handler ready for incoming requests
set foo "This is a string with some data in it... blah blah"
selection handle -selection SECONDARY .getData
proc getData {offset maxChars} {
   puts "Retrieving selection starting at $offset"
   return [string range $::foo $offset [expr {$offset+$maxChars-1}]]
}
# Now we grab the selection itself
puts "Claiming selection"
selection own -command lost -selection SECONDARY .
proc lost {} {
   puts "Lost selection"
}
