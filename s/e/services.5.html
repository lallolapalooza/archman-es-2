services(5) Manual de Formatos de Archivo services(5)

NOMBRE

services - lista de servicios de red de Internet

DESCRIPCIÓN

services es un archivo de texto plano que proporciona un mapeo entre nombres textuales amigables para el ser humano para servicios de Internet y sus números de puerto y tipos de protocolo subyacentes asignados. Cada programa de red debe consultar este archivo para obtener el número de puerto (y protocolo) para su servicio. Las rutinas de la biblioteca C getservent(3), getservbyname(3), getservbyport(3), setservent(3) y endservent(3) admiten la consulta de este archivo desde programas.

Los números de puerto son asignados por la IANA (Internet Assigned Numbers Authority), y su política actual es asignar ambos protocolos, TCP y UDP, al asignar un número de puerto. Por lo tanto, la mayoría de las entradas tendrán dos entradas, incluso para servicios solo TCP.

Los números de puerto inferiores a 1024 (los llamados puertos de "bajo número") solo pueden ser enlazados por el usuario root (ver bind(2), tcp(7) y udp(7)). Esto es para que los clientes que se conectan a puertos de bajo número puedan confiar en que el servicio que se ejecuta en el puerto es la implementación estándar y no un servicio malicioso ejecutado por un usuario de la máquina. Los números de puerto bien conocidos especificados por la IANA se encuentran normalmente en este espacio reservado solo para root.

La presencia de una entrada para un servicio en el archivo services no significa necesariamente que el servicio se esté ejecutando actualmente en la máquina. Consulte inetd.conf(5) para la configuración de los servicios de Internet ofrecidos. Tenga en cuenta que no todos los servicios de red son iniciados por inetd(8), por lo que no aparecerán en inetd.conf(5). En particular, los servidores de noticias (NNTP) y correo (SMTP) a menudo se inicializan desde los scripts de arranque del sistema.

La ubicación del archivo services se define por _PATH_SERVICES en <netdb.h>. Esto suele establecerse en /etc/services.

Cada línea describe un servicio y tiene el siguiente formato:

nombre-servicio   puerto/protocolo   [alias ...]
donde:
nombre-servicio
es el nombre amigable por el cual se conoce el servicio y bajo el cual se busca. Es sensible a mayúsculas y minúsculas. A menudo, el programa cliente se llama por el nombre-servicio.
puerto
es el número de puerto (en decimal) a utilizar para este servicio.
protocolo
es el tipo de protocolo a utilizar. Este campo debe coincidir con una entrada en el archivo protocols(5). Los valores típicos incluyen tcp y udp.
alias
es una lista opcional separada por espacios o tabulaciones de otros nombres para este servicio. Nuevamente, los nombres son sensibles a mayúsculas y minúsculas.

Se pueden usar espacios o tabulaciones para separar los campos.

Los comentarios se inician con el signo de almohadilla (#) y continúan hasta el final de la línea. Las líneas en blanco se omiten.

El nombre-servicio debe comenzar en la primera columna del archivo, ya que los espacios iniciales no se eliminan. Los nombres-de-servicio pueden ser cualquier carácter imprimible, excluyendo el espacio y la tabulación. Sin embargo, se debe usar una elección conservadora de caracteres para minimizar problemas de compatibilidad. Por ejemplo, a-z, 0-9 y el guion (-) parecerían una opción sensata.

No deben existir líneas que no coincidan con este formato en el archivo. (Actualmente, son omitidas silenciosamente por getservent(3), getservbyname(3) y getservbyport(3). Sin embargo, no se debe confiar en este comportamiento.)

Este archivo podría distribuirse a través de una red utilizando un servicio de nombres a nivel de red como Yellow Pages/NIS o BIND/Hesiod.

Un ejemplo de archivo services podría verse así:


netstat         15/tcp
qotd            17/tcp          quote
msp             18/tcp          # message send protocol
msp             18/udp          # message send protocol
chargen         19/tcp          ttytst source
chargen         19/udp          ttytst source
ftp             21/tcp
# 22 - sin asignar
telnet          23/tcp
