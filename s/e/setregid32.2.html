setreuid(2) Manual de llamadas al sistema setreuid(2)

NOMBRE

setreuid, setregid - establecer el ID de usuario o grupo real y/o efectivo

BIBLIOTECA

Biblioteca estándar C (libc, -lc)

SINOPSIS

#include <unistd.h>
int setreuid(uid_t ruid, uid_t euid);
int setregid(gid_t rgid, gid_t egid);
Requisitos de Macro de Prueba de Funciones para glibc (ver feature_test_macros(7)):

setreuid(), setregid():

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _BSD_SOURCE

DESCRIPCIÓN

setreuid() establece los IDs de usuario real y efectivo del proceso que llama.

Suministrar un valor de -1 para el ID de usuario real o efectivo hace que el sistema deje ese ID sin cambios.

Los procesos no privilegiados solo pueden establecer el ID de usuario efectivo al ID de usuario real, el ID de usuario efectivo o el ID de usuario establecido guardado.

Los usuarios no privilegiados solo pueden establecer el ID de usuario real al ID de usuario real o al ID de usuario efectivo.

Si se establece el ID de usuario real (es decir, ruid no es -1) o el ID de usuario efectivo se establece a un valor no igual al ID de usuario real anterior, el ID de usuario establecido guardado se establecerá al nuevo ID de usuario efectivo.

De forma completamente análoga, setregid() establece los IDs de grupo reales y efectivos del proceso que llama, y todo lo anterior se aplica con "grupo" en lugar de "usuario".

VALOR DE RETORNO

Al éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

Nota: hay casos en los que setreuid() puede fallar incluso cuando el que llama tiene UID 0; omitir la comprobación de un valor de retorno de error de setreuid() es un grave error de seguridad.

ERRORES

EAGAIN
La llamada cambiaría el UID real del que llama (es decir, ruid no coincide con el UID real del que llama), pero hubo una falla temporal al asignar las estructuras de datos necesarias del kernel.
EAGAIN
ruid no coincide con el UID real del que llama y esta llamada superaría el límite de recursos RLIMIT_NPROC del que llama para el número de procesos que pertenecen al ID de usuario real ruid. Desde Linux 3.1, este caso de error ya no ocurre (pero las aplicaciones robustas deben verificar este error); ver la descripción de EAGAIN en execve(2).
EINVAL
Uno o más de los IDs de usuario o grupo de destino no son válidos en este espacio de nombres de usuario.
EPERM
El proceso que llama no tiene privilegios (en Linux, no tiene la capacidad necesaria en su espacio de nombres de usuario: CAP_SETUID en el caso de setreuid(), o CAP_SETGID en el caso de setregid()) y se especificó un cambio distinto de (i) intercambiar el ID efectivo de usuario (grupo) con el ID real de usuario (grupo), o (ii) establecer uno al valor del otro, o (iii) establecer el ID efectivo de usuario (grupo) al valor del ID de usuario (grupo) establecido guardado.

VERSIÓNES

POSIX.1 no especifica todos los cambios de UID que Linux permite para un proceso no privilegiado. Para setreuid(), el ID de usuario efectivo puede ser el mismo que el ID de usuario real o el ID de usuario establecido guardado, y no está especificado si los procesos no privilegiados pueden establecer el ID de usuario real al ID de usuario real, el ID de usuario efectivo o el ID de usuario establecido guardado. Para setregid(), el ID de grupo real puede cambiarse al valor del ID de grupo establecido guardado, y el ID de grupo efectivo puede cambiarse al valor del ID de grupo real o al ID de grupo establecido guardado. Los detalles precisos de los cambios de ID permitidos varían entre implementaciones.

POSIX.1 no hace ninguna especificación sobre el efecto de estas llamadas en el ID de usuario establecido guardado y el ID de grupo establecido guardado.

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, 4.3BSD (apareció por primera vez en 4.2BSD).

Establecer el ID efectivo de usuario (grupo) al ID de usuario (grupo) establecido guardado es posible desde Linux 1.1.37 (1.1.38).

Las llamadas al sistema setreuid() y setregid() originales de Linux admitían solo IDs de usuario y grupo de 16 bits. Posteriormente, Linux 2.4 agregó setreuid32() y setregid32(), que admiten IDs de 32 bits. Las funciones de envoltura setreuid() y setregid() de glibc manejan de forma transparente las variaciones entre las versiones del kernel.

Diferencias entre la biblioteca C y el kernel

A nivel del kernel, los IDs de usuario y grupo son un atributo por hilo. Sin embargo, POSIX requiere que todos los hilos de un proceso compartan las mismas credenciales. La implementación de subprocesos NPTL maneja los requisitos de POSIX proporcionando funciones de envoltura para las diversas llamadas al sistema que cambian los UID y GID del proceso. Estas funciones de envoltura (incluidas las de setreuid() y setregid()) utilizan una técnica basada en señales para garantizar que cuando un hilo cambia las credenciales, todos los demás hilos del proceso también cambien sus credenciales. Para obtener más detalles, ver nptl(7).
