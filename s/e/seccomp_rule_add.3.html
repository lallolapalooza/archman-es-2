NOMBRE

seccomp_rule_add, seccomp_rule_add_exact - Añadir una regla de filtro seccomp

SINOPSIS

#include <seccomp.h>

typedef void * scmp_filter_ctx;

int SCMP_SYS(nombre_llamada_syscall);

struct scmp_arg_cmp SCMP_CMP(unsigned int arg,
                             enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A0(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A1(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A2(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A3(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A4(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A5(enum scmp_compare op, ...);

struct scmp_arg_cmp SCMP_CMP64(unsigned int arg,
                             enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A0_64(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A1_64(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A2_64(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A3_64(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A4_64(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A5_64(enum scmp_compare op, ...);

struct scmp_arg_cmp SCMP_CMP32(unsigned int arg,
                             enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A0_32(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A1_32(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A2_32(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A3_32(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A4_32(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A5_32(enum scmp_compare op, ...);

int seccomp_rule_add(scmp_filter_ctx ctx, uint32_t accion,
                     int syscall, unsigned int arg_cnt, ...);
int seccomp_rule_add_exact(scmp_filter_ctx ctx, uint32_t accion,
                           int syscall, unsigned int arg_cnt, ...);

int seccomp_rule_add_array(scmp_filter_ctx ctx,
                           uint32_t accion, int syscall,
                           unsigned int arg_cnt,
                           const struct scmp_arg_cmp *array_arg);
int seccomp_rule_add_exact_array(scmp_filter_ctx ctx,
                                 uint32_t accion, int syscall,
                                 unsigned int arg_cnt,
                                 const struct scmp_arg_cmp *array_arg);

Enlace con -lseccomp.

DESCRIPCIÓN

Las funciones seccomp_rule_add(), seccomp_rule_add_array(), seccomp_rule_add_exact() y seccomp_rule_add_exact_array() añaden todas una nueva regla de filtro al filtro seccomp actual. Las funciones seccomp_rule_add() y seccomp_rule_add_array() harán un "esfuerzo máximo" para añadir la regla según lo especificado, pero podrían alterar ligeramente la regla debido a especificidades de la arquitectura (por ejemplo, reescritura interna de llamadas syscall multiplexadas, como las funciones socket e ipc en x86). Las funciones seccomp_rule_add_exact() y seccomp_rule_add_exact_array() intentarán añadir la regla exactamente como se especificó, por lo que pueden comportarse de manera diferente en diferentes arquitecturas. Si bien no garantiza un conjunto de reglas de filtro exacto, seccomp_rule_add() y seccomp_rule_add_array() garantizan el mismo comportamiento independientemente de la arquitectura.

La regla de filtro recién añadida no tendrá efecto hasta que todo el filtro se cargue en el kernel usando seccomp_load(3). Al añadir reglas a un filtro, es importante considerar el impacto de los filtros cargados previamente; ver la documentación de seccomp_load(3) para más información.

Todas las reglas de filtro proporcionadas por la aplicación llamante se combinan en una unión, con lógica adicional para eliminar filtros de syscall redundantes. Por ejemplo, si se añade una regla que permite una determinada llamada syscall con un conjunto específico de valores de argumento y luego se añade una regla que permite la misma llamada syscall independientemente de los valores de argumento, la primera regla, más específica, se elimina efectivamente del filtro por la segunda regla, más genérica.

Las macros SCMP_CMP(), SCMP_CMP64(), SCMP_A{0-5}() y SCMP_A{0-5}_64() generan una estructura scmp_arg_cmp para usarla con las funciones anteriores. Las macros SCMP_CMP() y SCMP_CMP64() permiten al llamante especificar un argumento arbitrario junto con el operador de comparación, la máscara de 64 bits y los valores de dato, mientras que las macros SCMP_A{0-5}() y SCMP_A{0-5}_64() son específicas para un argumento determinado.

Las macros SCMP_CMP32() y SCMP_A{0-5}_32() son similares a las variantes anteriores, pero toman máscaras de 32 bits y valores de dato de 32 bits.

Se recomienda que siempre que sea posible los desarrolladores eviten usar las macros SCMP_CMP() y SCMP_A{0-5}() y usen las variantes que son explícitamente de 32 o 64 bits. Esto debería ayudar a eliminar problemas causados por una extensión de signo no deseada de valores de dato negativos.

Si se incluyen comparaciones de argumentos de llamadas syscall en la regla de filtro, todas las comparaciones deben ser verdaderas para que la regla coincida.

Al añadir comparaciones de argumentos de llamadas syscall al filtro, es importante recordar que, si bien es posible tener múltiples comparaciones en una sola regla, solo se puede comparar cada argumento una vez en una sola regla. En otras palabras, no se pueden tener múltiples comparaciones del tercer argumento de la llamada syscall en una sola regla.

En un filtro que contiene múltiples arquitecturas, es un error añadir una regla de filtro para una llamada syscall que no existe en todas las arquitecturas del filtro.

Si bien es posible especificar el valor de la llamada syscall directamente usando los valores estándar __NR_syscall, para asegurar un funcionamiento correcto en múltiples arquitecturas, se recomienda encarecidamente utilizar la macro SCMP_SYS() en su lugar. Ver la sección EJEMPLOS a continuación. También es importante recordar que independientemente de las arquitecturas presentes en el filtro, los números de syscall utilizados en las reglas de filtro se interpretan en el contexto de la arquitectura nativa.

A partir de Linux v4.8, puede ser necesario crear una regla con un valor de syscall de -1 para permitir que los programas de depuración omitan una invocación de syscall; para crear una regla con un valor de syscall de -1, es necesario primero establecer el atributo SCMP_FLTATR_API_TSKIP. Ver seccomp_attr_set(3) para más información.

El contexto de filtro ctx es el valor devuelto por la llamada a seccomp_init(3).

Los valores válidos de accion son los siguientes:

SCMP_ACT_KILL
El hilo será eliminado por el kernel cuando llame a una syscall que coincida con la regla de filtro.
SCMP_ACT_KILL_PROCESS
El proceso será eliminado por el kernel cuando llame a una syscall que coincida con la regla de filtro.
SCMP_ACT_TRAP
El hilo lanzará una señal SIGSYS cuando llame a una syscall que coincida con la regla de filtro.
SCMP_ACT_ERRNO(uint16_t errno)
El hilo recibirá un valor de retorno de errno cuando llame a una syscall que coincida con la regla de filtro.
SCMP_ACT_TRACE(uint16_t msg_num)
Si el hilo está siendo depurado y el proceso de depuración especificó la opción PTRACE_O_TRACESECCOMP en la llamada a ptrace(2), el proceso de depuración será notificado, a través de PTRACE_EVENT_SECCOMP, y el valor proporcionado en msg_num se puede recuperar usando la opción PTRACE_GETEVENTMSG.
SCMP_ACT_LOG
Si el log de auditoría del kernel está habilitado y el filtro se está ejecutando con SECCOMP_FILTER_LOG habilitado, la llamada syscall se registrará en el log de auditoría.

Las constantes de comparación de argumentos de llamada syscall son las siguientes:

SCMP_CMP_EQ
Igual a.
SCMP_CMP_NEQ
No igual a.
SCMP_CMP_LT
Menor que.
SCMP_CMP_LE
Menor o igual que.
SCMP_CMP_GT
Mayor que.
SCMP_CMP_GE
Mayor o igual que.
SCMP_CMP_MASKED_EQ
Igual a enmascarado.
SCMP_CMP_MASKED_NEQ
No igual a enmascarado.

Las constantes de comparación de argumentos para 64 bits son las mismas que las anteriores, pero se aplican a comparaciones de 64 bits.

Las constantes de comparación de argumentos para 32 bits son las mismas que las anteriores, pero se aplican a comparaciones de 32 bits.

Las funciones seccomp_rule_add() y seccomp_rule_add_exact() aceptan un número variable de argumentos después de arg_cnt. Estos argumentos son estructuras `scmp_arg_cmp` que describen las comparaciones de argumentos de la llamada syscall. Si arg_cnt es 0, entonces no se especifican argumentos de llamada syscall.

Las funciones seccomp_rule_add_array() y seccomp_rule_add_exact_array() toman un puntero a un array de estructuras `scmp_arg_cmp` en lugar de argumentos variables.

Las funciones seccomp_rule_add() y seccomp_rule_add_array() devolverán 0 si la regla se añadió correctamente, o un número negativo si fallaron. Las funciones seccomp_rule_add_exact() y seccomp_rule_add_exact_array() seguirán el mismo patrón de retorno.

En caso de error, se establecerá una variable de error adecuada.

EJEMPLOS

El siguiente ejemplo muestra cómo añadir una regla que permite la llamada syscall `openat` solo si el segundo argumento es menor que 1024.

    scmp_filter_ctx ctx;

    ctx = seccomp_init(SCMP_ACT_KILL);
    if (ctx == NULL)
        return 1;

    /*
     * Allow openat() only if the second argument is less than 1024.
     */
    if (seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(openat), 1,
                          SCMP_CMP(1, SCMP_CMP_LT, 1024)) < 0) {
        fprintf(stderr, "failed to add rule\n");
        goto err_rule;
    }

    /*
     * Load the filter.
     */
    if (seccomp_load(ctx) < 0) {
        fprintf(stderr, "failed to load filter\n");
        goto err_load;
    }

    /* ... rest of application ... */

    seccomp_reset(ctx);
    return 0;

err_load:
    seccomp_reset(ctx);
err_rule:
    return 1;

El siguiente ejemplo muestra cómo añadir una regla que permite la llamada syscall `write` solo si el primer argumento es 1 (stdout).

    scmp_filter_ctx ctx;

    ctx = seccomp_init(SCMP_ACT_KILL);
    if (ctx == NULL)
        return 1;

    /*
     * Allow write() only if the first argument is 1 (stdout).
     */
    if (seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(write), 1,
                          SCMP_A0(SCMP_CMP_EQ, 1)) < 0) {
        fprintf(stderr, "failed to add rule\n");
        goto err_rule;
    }

    /*
     * Load the filter.
     */
    if (seccomp_load(ctx) < 0) {
        fprintf(stderr, "failed to load filter\n");
        goto err_load;
    }

    /* ... rest of application ... */

    seccomp_reset(ctx);
    return 0;

err_load:
    seccomp_reset(ctx);
err_rule:
    return 1;

El siguiente ejemplo muestra cómo añadir una regla que permite la llamada syscall `read` solo si el primer argumento es 0 (stdin) y el segundo argumento es mayor que 0.

    scmp_filter_ctx ctx;
    struct scmp_arg_cmp args[] = {
        SCMP_A0(SCMP_CMP_EQ, 0),
        SCMP_A1(SCMP_CMP_GT, 0)
    };

    ctx = seccomp_init(SCMP_ACT_KILL);
    if (ctx == NULL)
        return 1;

    /*
     * Allow read() only if the first argument is 0 and the second is > 0.
     */
    if (seccomp_rule_add_array(ctx, SCMP_ACT_ALLOW, SCMP_SYS(read), 2, args) < 0) {
        fprintf(stderr, "failed to add rule\n");
        goto err_rule;
    }

    /*
     * Load the filter.
     */
    if (seccomp_load(ctx) < 0) {
        fprintf(stderr, "failed to load filter\n");
        goto err_load;
    }

    /* ... rest of application ... */

    seccomp_reset(ctx);
    return 0;

err_load:
    seccomp_reset(ctx);
err_rule:
    return 1;

NAME

seccomp_rule_add, seccomp_rule_add_array, seccomp_rule_add_exact, seccomp_rule_add_exact_array - add a seccomp filter rule

SYNOPSIS

#include <libseccomp.h>

int seccomp_rule_add(scmp_filter_ctx ctx, uint32_t action, int syscall, unsigned int arg_cnt, ...);

int seccomp_rule_add_array(scmp_filter_ctx ctx, uint32_t action, syscall, unsigned int arg_cnt, const struct scmp_arg_cmp *arg_array);

int seccomp_rule_add_exact(scmp_filter_ctx ctx, uint32_t action, int syscall, unsigned int arg_cnt, ...);

int seccomp_rule_add_exact_array(scmp_filter_ctx ctx, uint32_t action, syscall, unsigned int arg_cnt, const struct scmp_arg_cmp *arg_array);

DESCRIPTION

The seccomp filter system, exposed through the libseccomp library, allows a process to define a set of rules that restrict the system calls that may be made by the process.

The seccomp_rule_add*() functions are used to add a single rule to an existing seccomp filter context. A seccomp filter context is created by a call to seccomp_init(3).

The seccomp_rule_add() and seccomp_rule_add_exact() functions accept a variable number of arguments after the arg_cnt argument. These arguments are of type struct scmp_arg_cmp and are constructed using the SCMP_A*() macros. The seccomp_rule_add_array() and seccomp_rule_add_exact_array() functions accept a pointer to an array of struct scmp_arg_cmp instead.

The action argument specifies the action to take when a system call matches the rule. The available actions are:

SCMP_ACT_KILL
The seccomp filter will terminate the thread calling the syscall if it matches the filter rule.
SCMP_ACT_KILL_PROCESS
The seccomp filter will terminate the calling process if it matches the filter rule.
SCMP_ACT_TRAP
The seccomp filter will send a SIGSYS signal to the calling thread if it matches the filter rule.
SCMP_ACT_ERRNO
The seccomp filter will return an error code to the calling thread if it matches the filter rule. The error code is specified in the seccomp_rule_add functions via the SCMP_ERROR*() macros.
SCMP_ACT_LOG
The seccomp filter will have no effect on the thread calling the syscall if it matches the filter rule but the syscall will be logged.
SCMP_ACT_ALLOW
The seccomp filter will have no effect on the thread calling the syscall if it matches the filter rule.
SCMP_ACT_NOTIFY
A monitoring process will be notified when a process running the seccomp filter calls a syscall that matches the filter rule. The process that invokes the syscall waits in the kernel until the monitoring process has responded via seccomp_notify_respond(3).

When a filter utilizing SCMP_ACT_NOTIFY is loaded into the kernel, the kernel generates a notification fd that must be used to communicate between the monitoring process and the process(es) being filtered. See seccomp_notif_fd(3) for more information.

Valid comparison op values are as follows:

SCMP_CMP_NE
Matches when the argument value is not equal to the datum value, example:

SCMP_CMP( arg , SCMP_CMP_NE , datum )

SCMP_CMP_LT
Matches when the argument value is less than the datum value, example:

SCMP_CMP( arg , SCMP_CMP_LT , datum )

SCMP_CMP_LE
Matches when the argument value is less than or equal to the datum value, example:

SCMP_CMP( arg , SCMP_CMP_LE , datum )

SCMP_CMP_EQ
Matches when the argument value is equal to the datum value, example:

SCMP_CMP( arg , SCMP_CMP_EQ , datum )

SCMP_CMP_GE
Matches when the argument value is greater than or equal to the datum value, example:

SCMP_CMP( arg , SCMP_CMP_GE , datum )

SCMP_CMP_GT
Matches when the argument value is greater than the datum value, example:

SCMP_CMP( arg , SCMP_CMP_GT , datum )

SCMP_CMP_MASKED_EQ
Matches when the masked argument value is equal to the masked datum value, example:

SCMP_CMP( arg , SCMP_CMP_MASKED_EQ , mask , datum )

RETURN VALUE

The SCMP_SYS() macro returns a value suitable for use as the syscall value in the seccomp_rule_add*() functions. In a similar manner, the SCMP_CMP() and SCMP_A*() macros return values suitable for use as argument comparisons in the seccomp_rule_add() and seccomp_rule_add_exact() functions.

The seccomp_rule_add(), seccomp_rule_add_array(), seccomp_rule_add_exact(), and seccomp_rule_add_exact_array() functions return zero on success or one of the following error codes on failure:

-EDOM
Architecture specific failure.
-EEXIST
The rule already exists.
-EACCES
The rule conflicts with the filter (for example, the rule action equals the default action of the filter).
-EFAULT
Internal libseccomp failure.
-EINVAL
Invalid input, either the context or architecture token is invalid.
-ENOMEM
The library was unable to allocate enough memory.
-EOPNOTSUPP
The library doesn't support the particular operation.

EXAMPLES

#include <fcntl.h>
#include <seccomp.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <stddef.h>
#define BUF_SIZE	256
int main(int argc, char *argv[])
{
	int rc = -1;
	scmp_filter_ctx ctx;
	struct scmp_arg_cmp arg_cmp[] = { SCMP_A0(SCMP_CMP_EQ, 2) };
	int fd;
	unsigned char buf[BUF_SIZE];
	ctx = seccomp_init(SCMP_ACT_KILL);
	if (ctx == NULL)
		goto out;
	/* ... */
	fd = open("file.txt", 0);
	/* ... */
	rc = seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(close), 0);
	if (rc < 0)
		goto out;
	rc = seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(exit_group), 0);
	if (rc < 0)
		goto out;
	rc = seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(exit), 0);
	if (rc < 0)
		goto out;
	rc = seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(read), 3,
			      SCMP_A0(SCMP_CMP_EQ, fd),
			      SCMP_A1(SCMP_CMP_EQ, (scmp_datum_t)buf),
			      SCMP_A2(SCMP_CMP_LE, BUF_SIZE));
	if (rc < 0)
		goto out;
	rc = seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(write), 1,
			      SCMP_CMP(0, SCMP_CMP_EQ, fd));
	if (rc < 0)
		goto out;
	rc = seccomp_rule_add_array(ctx, SCMP_ACT_ALLOW, SCMP_SYS(write), 1,
			            arg_cmp);
	if (rc < 0)
		goto out;
	rc = seccomp_load(ctx);
	if (rc < 0)
		goto out;
	/* ... */
out:
	seccomp_release(ctx);
	return -rc;
}

NOTES

While the seccomp filter can be generated independent of the kernel, kernel support is required to load and enforce the seccomp filter generated by libseccomp.

The libseccomp project site, with more information and the source code repository, can be found at https://github.com/seccomp/libseccomp. This tool, as well as the libseccomp library, is currently under development, please report any bugs at the project site or directly to the author.

BUGS

The runtime behavior of seccomp filters is dependent upon the kernel version, the processor architecture, and other libraries including libc. This could affect the return code of a seccomp filter.

*
PowerPC glibc will not return a negative number when the getpid() syscall is invoked. If a seccomp filter has been created where getpid() will return a negative number from the kernel, then PowerPC glibc will return the absolute value of the errno. In this case, it is very difficult for an application to distinguish between the errno and a valid pid.
