NOMBRE

send — enviar un mensaje a un socket

SINTAXIS

#include <sys/socket.h>
ssize_t send(int socket, const void *buffer, size_t length, int flags);

DESCRIPCIÓN

La función send() inicia la transmisión de un mensaje desde el socket especificado a su par. La función send() envía un mensaje solo cuando el socket está conectado. Si el socket es de modo sin conexión, el mensaje se enviará a la dirección del par preespecificada.

La función send() toma los siguientes argumentos:

socket
Especifica el descriptor de archivo del socket.
buffer
Punta al búfer que contiene el mensaje a enviar.
length
Especifica la longitud del mensaje en bytes.
flags
Especifica el tipo de transmisión del mensaje. Los valores de este argumento se forman mediante OR lógico de cero o más de las siguientes banderas:
MSG_EOR
Termina un registro (si es soportado por el protocolo).
MSG_OOB
Envía datos fuera de banda en sockets que soportan comunicaciones fuera de banda. El significado y la semántica de los datos fuera de banda son específicos del protocolo.
MSG_NOSIGNAL
Solicita no enviar la señal SIGPIPE si se intenta enviar en un socket orientado a flujo que ya no está conectado. El error [EPIPE] aún se devolverá.

La longitud del mensaje a enviar se especifica mediante el argumento length. Si el mensaje es demasiado largo para pasar a través del protocolo subyacente, send() fallará y no se transmitirá ningún dato.

La finalización exitosa de una llamada a send() no garantiza la entrega del mensaje. Un valor de retorno de -1 solo indica errores detectados localmente.

Si no hay espacio disponible en el socket de envío para contener el mensaje a transmitir, y el descriptor de archivo del socket no tiene O_NONBLOCK establecido, send() se bloqueará hasta que haya espacio disponible. Si no hay espacio disponible en el socket de envío para contener el mensaje a transmitir, y el descriptor de archivo del socket tiene O_NONBLOCK establecido, send() fallará. Las funciones select() y poll() se pueden usar para determinar cuándo es posible enviar más datos.

El socket en uso puede requerir que el proceso tenga los privilegios apropiados para usar la función send().

VALOR DE RETORNO

Tras una finalización exitosa, send() devolverá el número de bytes enviados. De lo contrario, se devolverá -1 y se establecerá errno para indicar el error.

ERRORES

La función send() fallará si:

EAGAIN o EWOULDBLOCK

El descriptor de archivo del socket está marcado como O_NONBLOCK y la operación solicitada bloquearía.
EBADF
El argumento socket no es un descriptor de archivo válido.
ECONNRESET
Una conexión fue cerrada forzosamente por un par.
EDESTADDRREQ

El socket no es de modo conexión y no se ha establecido ninguna dirección de par.
EINTR
Una señal interrumpió send() antes de que se transmitiera algún dato.
EMSGSIZE
El mensaje es demasiado grande para ser enviado de una vez, como lo requiere el socket.
ENOTCONN
El socket no está conectado.
ENOTSOCK
El argumento socket no se refiere a un socket.
EOPNOTSUPP
El argumento socket está asociado con un socket que no soporta uno o más de los valores establecidos en flags.
EPIPE
El socket está cerrado para escritura, o el socket es de modo conexión y ya no está conectado. En este último caso, y si el socket es de tipo SOCK_STREAM o SOCK_SEQPACKET y la bandera MSG_NOSIGNAL no está establecida, se genera la señal SIGPIPE al hilo que llama.

La función send() puede fallar si:

EACCES
El proceso que llama no tiene los privilegios apropiados.
EIO
Ocurrió un error de E/S al leer o escribir en el sistema de archivos.
ENETDOWN
La interfaz de red local utilizada para llegar al destino está caída.
ENETUNREACH

No hay ruta a la red presente.
ENOBUFS
No había recursos suficientes disponibles en el sistema para realizar la operación.

USO DE APLICACIONES

Si el argumento socket se refiere a un socket de modo conexión, la función send() es equivalente a sendto() (con cualquier valor para los argumentos dest_addr y dest_len, ya que se ignoran en este caso). Si el argumento socket se refiere a un socket y el argumento flags es 0, la función send() es equivalente a write().

NAME

send - enviar datos a un socket

SYNOPSIS

#include <sys/types.h>
#include <sys/socket.h>

ssize_t send(int sockfd, const void *buf, size_t len, int flags);

DESCRIPTION

La llamada al sistema send() se utiliza para enviar datos a través de un socket conectado. El descriptor de archivo sockfd especifica el socket a través del cual se enviarán los datos. El puntero buf apunta a los datos que se van a enviar, y len especifica el número de bytes a enviar desde ese búfer.

El argumento flags controla el comportamiento de la llamada al sistema. Los valores posibles para flags son:

  • MSG_DONTROUTE: no realiza un enrutamiento normal; es decir, se utiliza la interfaz de destino para enviar el mensaje.
  • MSG_EOR: marca el final del registro de datos.
  • MSG_OOB: envía datos fuera de banda.
  • MSG_NOSIGNAL: no generar el error EPIPE si el socket está cerrado.

Si sockfd está conectado a un socket de flujo (por ejemplo, SOCK_STREAM), send() puede enviar menos bytes que los solicitados en len. En este caso, send() devuelve el número de bytes que realmente se enviaron, y se debe volver a llamar a send() para enviar los datos restantes.

Si sockfd está conectado a un socket de datagrama (por ejemplo, SOCK_DGRAM), send() normalmente enviará todos los datos solicitados en una sola operación, a menos que ocurra un error.

RETURN VALUE

Al éxito, send() devuelve el número de bytes enviados. Al fracaso, devuelve -1 y establece errno para indicar el error.

ERRORS

Los siguientes valores pueden establecerse en errno:

  • EBADF: El descriptor de archivo sockfd no es válido.
  • ECONNRESET: La conexión se ha reiniciado inesperadamente.
  • EDESTADDRREQ: El socket no está conectado y no se especificó ninguna dirección.
  • EFAULT: La dirección del búfer es inaccesible.
  • EINTR: La llamada al sistema fue interrumpida por una señal.
  • EINVAL: El argumento flags es inválido.
  • EISCONN: El socket ya está conectado.
  • EMSGSIZE: El mensaje es demasiado grande para ser enviado.
  • ENETDOWN: Se detectó un error en la red.
  • ENETUNREACH: La red de destino no es accesible.
  • ENOBUFS: No hay suficiente espacio en el búfer del sistema para completar la operación.
  • ENOTCONN: El socket no está conectado.
  • ENOTSOCK: El descriptor de archivo sockfd no es un socket.
  • EPIPE: Escribir en un socket con una conexión de solo cierre (por ejemplo, SOCK_STREAM) cuando se ha realizado un cierre ordenado por el otro extremo.
  • EWOULDBLOCK o EAGAIN: El socket está marcado como no bloqueante y la operación enviaría datos pero se bloquearía.

EXAMPLES

El siguiente ejemplo muestra cómo enviar datos a un socket conectado:


#include <sys/types.h>
#include <sys/socket.h>
#include <string.h>
#include <unistd.h>

int main() {
    int sock_fd;
    const char *message = "¡Hola, servidor!";
    ssize_t bytes_sent;

    // Supongamos que sock_fd es un descriptor de archivo de socket válido y conectado
    // ... (código para crear y conectar el socket) ...

    bytes_sent = send(sock_fd, message, strlen(message), 0);

    if (bytes_sent == -1) {
        perror("send");
        // Manejar el error
    } else if (bytes_sent < strlen(message)) {
        fprintf(stderr, "Se enviaron menos bytes de los esperados.\n");
        // Manejar la retransmisión si es necesario
    }

    close(sock_fd);
    return 0;
}

APPLICATION USAGE

La llamada al sistema send() es una interfaz fundamental para la comunicación basada en sockets. Se utiliza para enviar datos de aplicación a través de una red. Es importante manejar correctamente los valores de retorno y los posibles errores, especialmente el caso en que se envían menos bytes de los solicitados en sockets de flujo.

RATIONALE

La llamada al sistema send() proporciona un mecanismo genérico para enviar datos a través de sockets. La inclusión del argumento flags permite un control fino sobre el comportamiento del envío, como el envío de datos fuera de banda o la supresión de la señal EPIPE. La diferencia en el comportamiento entre sockets de flujo y datagrama refleja la naturaleza subyacente de estos protocolos.

FUTURE DIRECTIONS

Las funcionalidades de send() están bien establecidas. Las futuras direcciones podrían centrarse en optimizaciones de rendimiento o en la integración con mecanismos de notificación de eventos más avanzados.
