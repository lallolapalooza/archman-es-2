getcontext(3) Manual de Funciones de Biblioteca getcontext(3)

NOMBRE

getcontext, setcontext - obtener o establecer el contexto del usuario

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <ucontext.h>
int getcontext(ucontext_t *ucp);
int setcontext(const ucontext_t *ucp);

DESCRIPCIÓN

En un entorno tipo System V, se tienen los tipos mcontext_t y ucontext_t definidos en <ucontext.h> y las cuatro funciones getcontext(), setcontext(), makecontext(3) y swapcontext(3) que permiten la conmutación de contexto a nivel de usuario entre múltiples hilos de control dentro de un proceso.

El tipo mcontext_t depende de la máquina y es opaco. El tipo ucontext_t es una estructura que tiene al menos los siguientes campos:


typedef struct ucontext_t {
    struct ucontext_t *uc_link;
    sigset_t          uc_sigmask;
    stack_t           uc_stack;
    mcontext_t        uc_mcontext;
    ...
} ucontext_t;

con sigset_t y stack_t definidos en <signal.h>. Aquí uc_link apunta al contexto que será reanudado cuando el contexto actual termine (en caso de que el contexto actual se haya creado usando makecontext(3)), uc_sigmask es el conjunto de señales bloqueadas en este contexto (ver sigprocmask(2)), uc_stack es la pila utilizada por este contexto (ver sigaltstack(2)), y uc_mcontext es la representación específica de la máquina del contexto guardado, que incluye los registros de la máquina del hilo que llama.

La función getcontext() inicializa la estructura apuntada por ucp al contexto actualmente activo.

La función setcontext() restaura el contexto del usuario apuntado por ucp. Una llamada exitosa no retorna. El contexto debería haber sido obtenido por una llamada a getcontext(), o makecontext(3), o recibido como tercer argumento de un manejador de señales (ver la discusión de la bandera SA_SIGINFO en sigaction(2)).

Si el contexto se obtuvo por una llamada a getcontext(), la ejecución del programa continúa como si esa llamada acabara de retornar.

Si el contexto se obtuvo por una llamada a makecontext(3), la ejecución del programa continúa con una llamada a la función func especificada como segundo argumento de esa llamada a makecontext(3). Cuando la función func retorna, continuamos con el miembro uc_link de la estructura ucp especificada como primer argumento de esa llamada a makecontext(3). Cuando este miembro es NULL, el hilo finaliza.

Si el contexto se obtuvo por una llamada a un manejador de señales, entonces el texto antiguo estándar dice que "la ejecución del programa continúa con la instrucción del programa siguiente a la instrucción interrumpida por la señal". Sin embargo, esta frase fue eliminada en SUSv2, y el veredicto actual es "el resultado no está especificado".

VALOR DE RETORNO

Cuando tiene éxito, getcontext() retorna 0 y setcontext() no retorna. En caso de error, ambas retornan -1 y establecen errno para indicar el error.

ERRORES

Ninguno definido.

ATRIBUTOS

Para una explicación de los términos utilizados en esta sección, ver attributes(7).

Interfaz Atributo Valor
getcontext (), setcontext () Seguridad de hilos MT-Safe race:ucp

ESTÁNDARES

Ninguno.

HISTORIA

SUSv2, POSIX.1-2001.

POSIX.1-2008 elimina estas funciones, citando problemas de portabilidad, y recomendando que las aplicaciones se reescriban para usar hilos POSIX en su lugar.

NOTAS

La primera encarnación de este mecanismo fue el mecanismo setjmp(3)/longjmp(3). Dado que este no define el manejo del contexto de señales, la siguiente etapa fue el par sigsetjmp(3)/siglongjmp(3). El mecanismo actual ofrece mucho más control. Por otro lado, no hay una forma fácil de detectar si un retorno de getcontext() proviene de la primera llamada o a través de una llamada setcontext(). El usuario tiene que inventar su propio dispositivo de contabilidad, y una variable de registro no servirá ya que los registros se restauran.

Cuando ocurre una señal, se guarda el contexto del usuario actual y se crea un nuevo contexto para el manejador de señales por el kernel. No salgas del manejador usando longjmp(3): no está especificado qué sucedería con los contextos. Usa siglongjmp(3) o setcontext() en su lugar.

VER TAMBIÉN

sigaction(2), sigaltstack(2), sigprocmask(2), longjmp(3), makecontext(3), sigsetjmp(3), signal(7)
