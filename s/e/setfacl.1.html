SETFACL(1) Listas de Control de Acceso SETFACL(1)

NOMBRE

setfacl - establecer listas de control de acceso de archivos

SINOPSIS

setfacl [-bkndRLPvh] [{-m|-x} acl_spec] [{-M|-X} acl_file] archivo ...

setfacl --restore={archivo|-}

DESCRIPCIÓN

Esta utilidad establece Listas de Control de Acceso (ACLs) de archivos y directorios. En la línea de comandos, una secuencia de comandos es seguida por una secuencia de archivos (que a su vez puede ser seguida por otra secuencia de comandos, ...).

Las opciones -m y -x esperan una ACL en la línea de comandos. Múltiples entradas de ACL se separan por comas (`,'). Las opciones -M y -X leen una ACL de un archivo o de la entrada estándar. El formato de la entrada ACL se describe en la Sección ENTRADAS ACL.

Las opciones --set y --set-file establecen la ACL de un archivo o directorio. La ACL anterior se reemplaza. Las entradas ACL para esta operación deben incluir permisos.

Las opciones -m (--modify) y -M (--modify-file) modifican la ACL de un archivo o directorio. Las entradas ACL para esta operación deben incluir permisos.

Las opciones -x (--remove) y -X (--remove-file) eliminan entradas ACL. No es un error eliminar una entrada que no existe. Solo se aceptan como parámetros las entradas ACL sin el campo perms, a menos que POSIXLY_CORRECT esté definido.

Al leer desde archivos usando las opciones -M y -X, setfacl acepta la salida que produce getfacl. Hay como máximo una entrada ACL por línea. Después de un signo de almohadilla (`#'), todo hasta el final de la línea se trata como un comentario.

Si setfacl se usa en un sistema de archivos que no soporta ACLs, setfacl opera sobre los bits de permisos del modo de archivo. Si la ACL no cabe completamente en los bits de permisos, setfacl modifica los bits de permisos del modo de archivo para reflejar la ACL lo más fielmente posible, escribe un mensaje de error en la salida estándar y regresa con un estado de salida mayor que 0.

PERMISOS

El propietario del archivo y los procesos capaces de CAP_FOWNER tienen el derecho de modificar las ACLs de un archivo. Esto es análogo a los permisos requeridos para acceder al modo de archivo. (En los sistemas Linux actuales, root es el único usuario con la capacidad CAP_FOWNER).

OPCIONES

-b, --remove-all
Elimina todas las entradas ACL extendidas. Se conservan las entradas ACL base del propietario, grupo y otros.
-k, --remove-default
Elimina la ACL Predeterminada. Si no existe ninguna ACL Predeterminada, no se emiten advertencias.
-n, --no-mask
No recalcula la máscara de derechos efectivos. El comportamiento por defecto de setfacl es recalcular la entrada de máscara ACL, a menos que se haya proporcionado explícitamente una entrada de máscara. La entrada de máscara se establece en la unión de todos los permisos del grupo propietario y todas las entradas de usuario y grupo con nombre. (Estas son exactamente las entradas afectadas por la entrada de máscara).
--mask
Recalcula la máscara de derechos efectivos, incluso si se proporcionó explícitamente una entrada de máscara ACL. (Ver la opción -n).
-d, --default
Todas las operaciones se aplican a la ACL Predeterminada. Las entradas ACL regulares en el conjunto de entrada se promueven a entradas de ACL Predeterminada. Las entradas de ACL Predeterminada en el conjunto de entrada se descartan. (Se emite una advertencia si eso sucede).
--restore={archivo|-}
Restaura una copia de seguridad de permisos creada por `getfacl -R' o similar. Todos los permisos de un subárbol de directorios completo se restauran usando este mecanismo. Si la entrada contiene comentarios de propietario o grupo, setfacl intenta restaurar el propietario y el grupo propietario. Si la entrada contiene comentarios de flags (que definen los bits setuid, setgid y sticky), setfacl establece esos tres bits en consecuencia; de lo contrario, los limpia. Esta opción no se puede mezclar con otras opciones excepto `--test'. Si el archivo especificado es '-', entonces se leerá desde la entrada estándar.
--test
Modo de prueba. En lugar de cambiar las ACLs de cualquier archivo, se listan las ACLs resultantes.
-R, --recursive
Aplica operaciones a todos los archivos y directorios recursivamente. Esta opción no se puede mezclar con `--restore'.
-L, --logical
Recorrido lógico, sigue enlaces simbólicos a directorios. El comportamiento por defecto es seguir los argumentos de enlaces simbólicos, y omitir los enlaces simbólicos encontrados en subdirectorios. Solo efectivo en combinación con -R. Esta opción no se puede mezclar con `--restore'.
-P, --physical
Recorrido físico, no sigue enlaces simbólicos a directorios. Esto también omite los argumentos de enlaces simbólicos. Solo efectivo en combinación con -R. Esta opción no se puede mezclar con `--restore'.
-v, --version
Imprime la versión de setfacl y sale.
-h, --help
Imprime ayuda explicando las opciones de la línea de comandos.
--
Fin de las opciones de la línea de comandos. Todos los parámetros restantes se interpretan como nombres de archivo, incluso si comienzan con un guion.
-
Si el parámetro del nombre de archivo es un guion único, setfacl lee una lista de archivos de la entrada estándar.

ENTRADAS ACL

La utilidad setfacl reconoce los siguientes formatos de entrada ACL (espacios insertados para mayor claridad):

[d[efault]:] [u[ser]:]uid [:perms]
Permisos de un usuario con nombre. Permisos del propietario del archivo si uid está vacío.
[d[efault]:] g[roup]:gid [:perms]
Permisos de un grupo con nombre. Permisos del grupo propietario si gid está vacío.
[d[efault]:] m[ask][:] [:perms]
Máscara de derechos efectivos
[d[efault]:] o[ther][:] [:perms]
Permisos de otros.

Los espacios en blanco entre caracteres delimitadores y caracteres no delimitadores se ignoran.

Las entradas ACL adecuadas que incluyen permisos se utilizan en las operaciones de modificación y establecimiento. (opciones -m, -M, --set y --set-file). Las entradas sin el campo perms se usan para la eliminación de entradas (opciones -x y -X).

Para uid y gid puedes especificar un nombre o un número. Los caracteres literales pueden especificarse con una barra invertida seguida de tres dígitos octales que corresponden al código ASCII del carácter (por ejemplo, \101 para 'A'). Si el nombre contiene una barra invertida literal seguida de 3 dígitos, la barra invertida debe escaparse (es decir, \\).

El campo perms es una combinación de caracteres que indican los permisos de lectura (r), escritura (w), ejecución (x). Los guiones en el campo perms (-) se ignoran. El carácter X representa el permiso de ejecución si el archivo es un directorio o ya tiene permiso de ejecución para algún usuario. Alternativamente, el campo perms puede definir los permisos numéricamente, como una combinación bit a bit de lectura (4), escritura (2) y ejecución (1). Los campos perms cero o los campos perms que solo consisten en guiones indican ningún permiso.

ENTRADAS CREADAS AUTOMÁTICAMENTE

Inicialmente, los archivos y directorios contienen solo las tres entradas ACL base para el propietario, el grupo y otros. Hay algunas reglas que deben cumplirse para que una ACL sea válida:

  • Las tres entradas base no se pueden eliminar. Debe haber exactamente una entrada de cada uno de estos tipos de entrada base.
  • Siempre que una ACL contenga entradas de usuario con nombre u objetos de grupo con nombre, también debe contener una máscara de derechos efectivos.
  • Siempre que una ACL contenga entradas de ACL Predeterminada, también deben existir las tres entradas base de ACL Predeterminada (propietario predeterminado, grupo predeterminado y otros predeterminados).
  • Siempre que una ACL Predeterminada contenga entradas de usuario con nombre o objetos de grupo con nombre, también debe contener una máscara de derechos efectivos predeterminada.

setfacl(1) - Arch Linux Manual Pages

NAME

setfacl

set file access control lists

SYNOPSIS

setfacl [ -bkdpmsm ] [ -R ] [ -L | -H ] [ --set=acl file...

setfacl [ -bkdpmsm ] [ -R ] [ -L | -H ] [ --setacl=file file...

setfacl [ -x –X ] [ -R ] [ -L | -H ] acl file...

setfacl [ -d ] [ -b ] [ -k ] [ -R ] [ -L | -H ] [ --set=acl dir...

setfacl [ -d ] [ -b ] [ -k ] [ -R ] [ -L | -H ] [ --setacl=file dir...

setfacl [ -x –X ] [ -R ] [ -L | -H ] dir...

setfacl [ -m –M ] [ -R ] [ -L | -H ] acl file...

setfacl [ -m –M ] [ -R ] [ -L | -H ] [ --set-file=file file...

setfacl [ -d –D ] [ -R ] [ -L | -H ] [ -m –M ] [ --set-file=file dir...

DESCRIPTION

setfacl is used to administer Access Control Lists (ACLs) on file systems that support them. The ACL information is stored extended attribute of the file. This command can be used to grant or revoke access to files.

An ACL specifies, in granular fashion, who can access what resources. An ACL entry can specify access for a specific user, a specific group, or for all users.

The default ACL is a set of rules that are used to determine the ACL for files that are created within a directory. The default ACL is only effective for directories.

When you modify the ACL entries of a file, the effective rights mask might be modified as well. The effective rights mask is a mechanism to limit the maximum permissions that can be granted. It is represented by the setgid bit in the file mode, and can be specified with the setfacl command as m::rwx, for example.

The file mode bits (user, group, other) are not affected by the setfacl command. They are only used to calculate the effective rights mask, if no explicit mask entry is specified.

OPTIONS

-b, --remove-all
Remove all extended ACL entries.
-k, --remove-default
Remove the Default ACL.
-d, --default
Modify the Default ACL instead of the file's ACL.
-m, --modify
Modify the file's ACLs.
-M, --set-file
Modify the file's ACLs.
-x, --remove
Remove specified ACL entries.
-X, --remove-file
Remove specified ACL entries.
-n, --no-mask
Do not recalculate the effective rights mask.
-R, --recursive
Modify ACLs recursively.
-L, --follow-symlinks
Follow symbolic links.
-H, --no-follow-symlinks
Do not follow symbolic links.
--set=acl
Set the ACL to the specified value.
--setacl=file
Set the ACL to the value specified in the file.
--modify-acl=file
Modify the ACL with the value specified in the file.
--restore=file
Restore ACLs that were previously saved into a file.

CONDITION

  • If an ACL contains named user or named group entries, and no mask entry exists, a mask entry containing the same permissions as the group entry is created. Unless the -n option is given, the permissions of the mask entry are further adjusted to include the union of all permissions affected by the mask entry. (See the -n option description).
  • If a Default ACL entry is created, and the Default ACL contains no owner, owning group, or others entry, a copy of the ACL owner, owning group, or others entry is added to the Default ACL.
  • If a Default ACL contains named user entries or named group entries, and no mask entry exists, a mask entry containing the same permissions as the default Default ACL's group entry is added. Unless the -n option is given, the permissions of the mask entry are further adjusted to include the union of all permissions affected by the mask entry. (See the -n option description).

EXAMPLES

Granting an additional user read access

setfacl -m u:lisa:r file

Revoking write access from all groups and all named users (using the effective rights mask)

setfacl -m m::rx file

Removing a named group entry from a file's ACL

setfacl -x g:staff file

Copying the ACL of one file to another

getfacl file1 | setfacl --set-file=- file2

Copying the access ACL into the Default ACL

getfacl --access dir | setfacl -d -M- dir

CONFORMANCE TO POSIX 1003.1e DRAFT STANDARD 17

If the environment variable POSIXLY_CORRECT is defined, the default behavior of setfacl changes as follows: All non-standard options are disabled. The ``default:'' prefix is disabled. The -x and -X options also accept permission fields (and ignore them).
