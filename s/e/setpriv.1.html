SETPRIV(1) Comandos de usuario SETPRIV(1)

NOMBRE

setpriv - ejecuta un programa con diferentes configuraciones de privilegios de Linux

SINOPSIS

setpriv [opciones] programa [argumentos]

DESCRIPCIÓN

Establece o consulta varios ajustes de privilegios de Linux que se heredan a través de execve(2).

En comparación con su(1) y runuser(1), setpriv no utiliza PAM ni solicita una contraseña. Es un envoltorio simple, no de ID de usuario establecido, alrededor de execve(2), y puede utilizarse para reducir privilegios de la misma manera que setuidgid(8) de daemontools, chpst(8) de runit o herramientas similares proporcionadas por otros gestores de servicios.

OPCIONES

--clear-groups

Borra los grupos suplementarios.

-d, --dump

Vuelca el estado de privilegios actual. Esta opción se puede especificar varias veces para mostrar información adicional, en su mayoría inútil. Incompatible con todas las demás opciones.

--groups grupo...

Establece grupos suplementarios. El argumento es una lista separada por comas de GID o nombres.

--inh-caps (+|-)cap..., --ambient-caps (+|-)cap..., --bounding-set (+|-)cap...

Establece las capacidades heredables, las capacidades ambientales o el conjunto de límites de capacidades. Ver capabilities(7). El argumento es una lista separada por comas de entradas +cap y -cap, que añaden o eliminan una entrada respectivamente. cap puede ser un nombre legible por humanos tal como se ve en capabilities(7) sin el prefijo cap_ o con el formato cap_N, donde N es el índice interno de capacidad utilizado por Linux. +all y -all se pueden usar para añadir o eliminar todas las caps.

El conjunto de capacidades comienza como el conjunto heredable actual para --inh-caps, el conjunto ambiental actual para --ambient-caps y el conjunto de límites actual para --bounding-set.

Tenga en cuenta las siguientes restricciones (detalladas en capabilities(7)) con respecto a las modificaciones de estos conjuntos de capacidades:

•Una capacidad se puede añadir al conjunto heredable solo si está presente actualmente en el conjunto de límites.
•Una capacidad se puede añadir al conjunto ambiental solo si está presente actualmente tanto en los conjuntos permitidos como en los heredables.
•A pesar de la sintaxis ofrecida por setpriv, el kernel no permite añadir capacidades al conjunto de límites.

Si elimina una capacidad del conjunto de límites sin eliminarla también del conjunto heredable, es probable que se confunda. No lo haga.

--keep-groups

Conserva los grupos suplementarios. Solo útil en conjunción con --rgid, --egid o --regid.

--init-groups

Inicializa grupos suplementarios usando initgroups3. Solo útil en conjunción con --ruid o --reuid.

--list-caps

Lista todas las capacidades conocidas. Esta opción debe especificarse sola.

--no-new-privs

Establece el bit no_new_privs. Con este bit establecido, execve(2) no otorgará nuevos privilegios. Por ejemplo, los bits set-user-ID y set-group-ID, así como las capacidades de archivo, se deshabilitarán. (La ejecución de binarios con estos bits establecidos aún funcionará, pero no obtendrán privilegios. Ciertos LSM, especialmente AppArmor, pueden resultar en fallos al ejecutar ciertos programas). Este bit se hereda en los procesos hijos y no se puede desmarcar. Ver prctl(2) y Documentation/prctl/no_new_privs.txt en el código fuente del kernel de Linux.

El bit no_new_privs es compatible desde Linux 3.5.

--rgid gid, --egid gid, --regid gid

Establece los GID reales, efectivos o ambos. El argumento gid se puede proporcionar como un nombre de grupo textual.

Por seguridad, debe especificar uno de --clear-groups, --groups, --keep-groups o --init-groups si establece algún gid primario.

--ruid uid, --euid uid, --reuid uid

Establece los UID reales, efectivos o ambos. El argumento uid se puede proporcionar como un nombre de inicio de sesión textual.

Establecer un uid o gid no cambia las capacidades, aunque la llamada exec al final podría cambiar las capacidades. Esto significa que, si es root, probablemente querrá hacer algo como:

setpriv --reuid=1000 --regid=1000 --inh-caps=-all

--securebits (+|-)securebit...

Establece o borra los securebits. El argumento es una lista separada por comas. Los securebits válidos son noroot, noroot_locked, no_setuid_fixup, no_setuid_fixup_locked y keep_caps_locked. keep_caps es borrado por execve(2) y por lo tanto no está permitido.

--pdeathsig keep|clear|<señal>

Conserva, borra o establece la señal de muerte del padre. Algunos LSM, especialmente SELinux y AppArmor, borran la señal cuando las credenciales del proceso cambian. Usar --pdeathsig keep restaurará la señal de muerte del padre después de cambiar las credenciales para remediar esa situación.

--ptracer pid|any|none

Cuando el modo de ptrace restringido de Yama está en efecto (es decir, cuando /proc/sys/kernel/yama/ptrace_scope está establecido en 1), permite ser rastreado mediante ptrace(2) por el proceso con el PID especificado, o cualquier proceso, o ningún proceso. Ver PR_SET_PTRACER(2const). (Tenga en cuenta que esto no se hereda en los procesos hijos, aunque se conserva en las llamadas execve(2).) Esta opción no tiene efecto cuando Yama no está habilitado o está en un modo distinto al de ptrace restringido.

--selinux-label etiqueta

Solicita una transición SELinux particular (usando una transición en exec, no dyntrans). Esto fallará y hará que setpriv aborte si SELinux no está en uso, y la transición puede ser ignorada o provocar que execve(2) falle a capricho de SELinux. (En particular, es poco probable que funcione junto con no_new_privs.) Esto es similar a runcon(1).

--apparmor-profile perfil

Solicita un perfil AppArmor particular (usando una transición en exec). Esto fallará y hará que setpriv aborte si AppArmor no está en uso, y la transición puede ser ignorada o provocar que execve(2) falle a capricho de AppArmor.

--landlock-access acceso

Habilita restricciones landlock para un conjunto específico de accesos al sistema. Para permitir subconjuntos específicos de accesos, use --landlock-rule.

Bloquea todo acceso al sistema de archivos:

setpriv --landlock-access fs

Bloquea todas las eliminaciones de archivos y creaciones de directorios:

setpriv --landlock-access fs:remove-file,make-dir

Para un conjunto completo de categorías de acceso admitidas, use setpriv --help.

--landlock-rule regla

Permite un acceso específico de las categorías bloqueadas por --landlock-access.

La sintaxis es la siguiente:

--landlock-rule $ruletype:$access:$rulearg

Por ejemplo, conceder acceso de lectura de archivos a todo lo que esté debajo de /boot:

--landlock-rule path-beneath:read-file:/boot

--seccomp-filter archivo

Carga código de filtro seccomp BPF en bruto desde un archivo.

Los filtros se pueden crear, por ejemplo, con enosys.

--reset-env

Borra todas las variables de entorno excepto TERM; inicializa las variables de entorno HOME, SHELL, USER, LOGNAME de acuerdo con la entrada passwd del usuario; establece PATH

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

to /usr/local/bin:/bin:/usr/bin para un usuario normal y a /usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin para el usuario root.

La variable de entorno PATH puede ser diferente en sistemas donde /bin y /sbin se fusionan en /usr. La variable de entorno SHELL por defecto es /bin/sh si no se especifica ninguna en la entrada passwd del usuario.

-h, --help

Muestra el texto de ayuda y sale.

-V, --version

Muestra la versión y sale.

NOTAS

Si la aplicación de alguna opción especificada falla, program no será ejecutado y setpriv devolverá el estado de salida 127.

Tenga cuidado con esta herramienta; puede tener consecuencias de seguridad inesperadas. Por ejemplo, establecer no_new_privs y luego ejecutar un programa que esté confinado por SELinux (como haría esta herramienta) puede impedir que las restricciones de SELinux surtan efecto.

EJEMPLOS

Si busca un comportamiento similar a su(1)/runuser(1), o sudo(8) (sin la opción -g), pruebe algo como:

setpriv --reuid=1000 --regid=1000 --init-groups

Si desea imitar setuid(8) de daemontools, pruebe:

setpriv --reuid=1000 --regid=1000 --clear-groups
