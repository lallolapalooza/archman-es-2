setpgid(2) Manual de Llamadas al Sistema setpgid(2)

NOMBRE

setpgid, getpgid, setpgrp, getpgrp - establecer/obtener grupo de procesos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int setpgid(pid_t pid, pid_t pgid);
pid_t getpgid(pid_t pid);
pid_t getpgrp(void);                            /* Versión POSIX.1 */
[[deprecated]] pid_t getpgrp(pid_t pid);        /* Versión BSD */
int setpgrp(void);                              /* Versión System V */
[[deprecated]] int setpgrp(pid_t pid, pid_t pgid);  /* Versión BSD */
Requisitos de Macro de Prueba de Funcionalidad para glibc (ver feature_test_macros(7)):

getpgid():

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.12: */ _POSIX_C_SOURCE >= 200809L

setpgrp() (POSIX.1):

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _SVID_SOURCE

setpgrp() (BSD), getpgrp() (BSD):

    [Estos solo están disponibles antes de glibc 2.19]
    _BSD_SOURCE &&
        ! (_POSIX_SOURCE || _POSIX_C_SOURCE || _XOPEN_SOURCE
            || _GNU_SOURCE || _SVID_SOURCE)

DESCRIPCIÓN

Todas estas interfaces están disponibles en Linux y se utilizan para obtener y establecer el ID del grupo de procesos (PGID) de un proceso. Las formas preferidas y especificadas por POSIX.1 para hacer esto son: getpgrp(void), para obtener el PGID del proceso que llama; y setpgid(), para establecer el PGID de un proceso.

setpgid() establece el PGID del proceso especificado por pid a pgid. Si pid es cero, se utiliza el ID del proceso del proceso que llama. Si pgid es cero, el PGID del proceso especificado por pid se hace igual a su ID de proceso. Si setpgid() se usa para mover un proceso de un grupo de procesos a otro (como lo hacen algunos shells al crear canalizaciones), ambos grupos de procesos deben ser parte de la misma sesión (ver setsid(2) y credentials(7)). En este caso, pgid especifica un grupo de procesos existente al que unirse y el ID de sesión de ese grupo debe coincidir con el ID de sesión del proceso que se une.

La versión POSIX.1 de getpgrp(), que no toma argumentos, devuelve el PGID del proceso que llama.

getpgid() devuelve el PGID del proceso especificado por pid. Si pid es cero, se utiliza el ID del proceso del proceso que llama. (Obtener el PGID de un proceso que no sea el llamante rara vez es necesario, y el getpgrp() de POSIX.1 es preferible para esa tarea).

El setpgrp() de estilo System V, que no toma argumentos, es equivalente a setpgid(0, 0).

La llamada setpgrp() específica de BSD, que toma los argumentos pid y pgid, es una función envoltorio que llama a


setpgid(pid, pgid)

Desde glibc 2.19, la función setpgrp() específica de BSD ya no es expuesta por <unistd.h>; las llamadas deben reemplazarse por la llamada setpgid() mostrada anteriormente.

La llamada getpgrp() específica de BSD, que toma un solo argumento pid, es una función envoltorio que llama a


getpgid(pid)

Desde glibc 2.19, la función getpgrp() específica de BSD ya no es expuesta por <unistd.h>; las llamadas deben reemplazarse por llamadas a getpgrp() de POSIX.1 que no toma argumentos (si la intención es obtener el PGID del llamante), o con la llamada getpgid() mostrada anteriormente.

VALOR DE RETORNO

En caso de éxito, setpgid() y setpgrp() devuelven cero. En caso de error, devuelven -1 y errno se establece para indicar el error.

El getpgrp() de POSIX.1 siempre devuelve el PGID del llamante.

getpgid() y el getpgrp() específico de BSD devuelven un grupo de procesos en caso de éxito. En caso de error, devuelven -1 y errno se establece para indicar el error.

ERRORES

EACCES
Se intentó cambiar el ID del grupo de procesos de uno de los hijos del proceso que llama y el hijo ya había realizado una execve(2) (setpgid(), setpgrp()).
EINVAL
pgid es menor que 0 (setpgid(), setpgrp()).
EPERM
Se intentó mover un proceso a un grupo de procesos en una sesión diferente, o cambiar el ID del grupo de procesos de uno de los hijos del proceso que llama y el hijo estaba en una sesión diferente, o cambiar el ID del grupo de procesos de un líder de sesión (setpgid(), setpgrp()).
EPERM
El grupo de procesos de destino no existe. (setpgid(), setpgrp()).
ESRCH
Para getpgid(): pid no coincide con ningún proceso. Para setpgid(): pid no es el proceso que llama ni un hijo del proceso que llama.

NOTAS

Un hijo creado a través de fork(2) hereda el ID del grupo de procesos de su padre. El PGID se conserva a través de una execve(2).

Cada grupo de procesos es miembro de una sesión y cada proceso es miembro de la sesión de la que forma parte su grupo de procesos. (Ver credentials(7)).

Una sesión puede tener una terminal de control. En cualquier momento, uno (y solo uno) de los grupos de procesos de la sesión puede ser el grupo de procesos en primer plano para la terminal; los grupos de procesos restantes están en segundo plano. Si se genera una señal desde la terminal (por ejemplo, al escribir la tecla de interrupción para generar SIGINT), esa señal se envía al grupo de procesos en primer plano. (Ver termios(3) para una descripción de los caracteres que generan señales.) Solo el grupo de procesos en primer plano puede leer(2) de la terminal; si un grupo en segundo plano intenta leer(2) de la terminal, se envía una señal SIGTTIN al grupo, lo que lo suspende. Las funciones tcgetpgrp(3) y tcsetpgrp(3)

se utilizan para obtener/establecer el grupo de procesos en primer plano de la terminal de control.

Las llamadas setpgid() y getpgrp() son utilizadas por programas como bash(1) para crear grupos de procesos con el fin de implementar el control de trabajos del shell.

Si la terminación de un proceso provoca que un grupo de procesos quede huérfano, y si algún miembro del grupo de procesos recién huérfano está detenido, entonces se enviará una señal SIGHUP seguida de una señal SIGCONT a cada proceso del grupo de procesos recién huérfano. Un grupo de procesos huérfano es aquel en el que el padre de cada miembro del grupo de procesos es, a su vez, miembro del grupo de procesos o es miembro de un grupo de procesos en una sesión diferente (ver también credentials(7)).
