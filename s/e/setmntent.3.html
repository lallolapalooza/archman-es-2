getmntent(3) Manual de funciones de biblioteca getmntent(3)

NOMBRE

getmntent, setmntent, addmntent, endmntent, hasmntopt, getmntent_r - obtener entrada del archivo de descriptor de sistemas de archivos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <stdio.h>
#include <mntent.h>
FILE *setmntent(const char *path, const char *type);
struct mntent *getmntent(FILE *stream);
int addmntent(FILE *restrict stream,
              const struct mntent *restrict mnt);
int endmntent(FILE *streamp);
char *hasmntopt(const struct mntent *mnt, const char *opt);
/* Extensión de GNU */
#include <mntent.h>
struct mntent *getmntent_r(int size;
              FILE *restrict streamp,
              struct mntent *restrict mntbuf,
              char buf[restrict size], int size);
Requisitos de macro de prueba de características para glibc (ver feature_test_macros(7)):

getmntent_r():

    Desde glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 y anteriores:
        _BSD_SOURCE || _SVID_SOURCE

DESCRIPCIÓN

Estas rutinas se utilizan para acceder al archivo de descripción de sistemas de archivos /etc/fstab y al archivo de descripción de sistemas de archivos montados /etc/mtab.

La función setmntent() abre el archivo de descripción de sistemas de archivos path y devuelve un puntero de archivo que puede ser utilizado por getmntent(). El argumento type es el tipo de acceso requerido y puede tomar los mismos valores que el argumento mode de fopen(3). El flujo devuelto debe cerrarse usando endmntent() en lugar de fclose(3).

La función getmntent() lee la siguiente línea del archivo de descripción de sistemas de archivos desde stream y devuelve un puntero a una estructura que contiene los campos desglosados de una línea del archivo. El puntero apunta a un área de memoria estática que se sobrescribe con llamadas posteriores a getmntent().

La función addmntent() agrega la estructura mntent mnt al final del stream abierto.

La función endmntent() cierra el stream asociado con el archivo de descripción de sistemas de archivos.

La función hasmntopt() escanea el campo mnt_opts (ver más abajo) de la estructura mntent mnt en busca de una subcadena que coincida con opt. Consulte <mntent.h> y mount(8) para opciones de montaje válidas.

La función reentrante getmntent_r() es similar a getmntent(), pero almacena la estructura mntent en el *mntbuf proporcionado, y almacena las cadenas apuntadas por las entradas en esa estructura en el array buf proporcionado de tamaño size.

La estructura mntent se define en <mntent.h> como sigue:


struct mntent {
    char *mnt_fsname;   /* nombre del sistema de archivos montado */
    char *mnt_dir;      /* prefijo de ruta del sistema de archivos */
    char *mnt_type;     /* tipo de montaje (ver mntent.h) */
    char *mnt_opts;     /* opciones de montaje (ver mntent.h) */
    int   mnt_freq;     /* frecuencia de volcado en días */
    int   mnt_passno;   /* número de pasada en fsck paralelo */
};

Dado que los campos en los archivos mtab y fstab están separados por espacios en blanco, se utilizan escapes octales para representar los caracteres espacio (\040), tabulación (\011), nueva línea (\012) y barra invertida (\\) en esos archivos cuando ocurren en una de las cuatro cadenas de una estructura mntent. Las rutinas addmntent() y getmntent() convertirán de la representación de cadena a la representación escapada y viceversa. Al convertir de la representación escapada, la secuencia \134 también se convierte en una barra invertida.

VALOR DE RETORNO

Las funciones getmntent() y getmntent_r() devuelven un puntero a la estructura mntent o NULL en caso de fallo.

La función addmntent() devuelve 0 en caso de éxito y 1 en caso de fallo.

La función endmntent() siempre devuelve 1.

La función hasmntopt() devuelve la dirección de la subcadena si se encuentra una coincidencia y NULL en caso contrario.

ESTÁNDARES

HISTORIA

Las funciones no reentrantes son de SunOS 4.1.3. Una rutina getmntent_r() se introdujo en HP-UX 10, pero devuelve un int. El prototipo mostrado es solo de glibc.

System V también tiene una función getmntent(), pero la secuencia de llamada difiere y la estructura devuelta es diferente. Bajo System V se utiliza /etc/mnttab. 4.4BSD y Digital UNIX tienen una rutina getmntinfo(), una envoltura de la llamada al sistema getfsstat().
