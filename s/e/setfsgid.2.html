setfsgid(2) Manual de llamadas al sistema setfsgid(2)

NOMBRE

setfsgid - establecer la identidad de grupo utilizada para las comprobaciones del sistema de archivos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/fsuid.h>
[[deprecated]] int setfsgid(gid_t fsgid);

DESCRIPCIÓN

En Linux, un proceso tiene tanto un ID de grupo del sistema de archivos como un ID de grupo efectivo. El ID de grupo del sistema de archivos (específico de Linux) se utiliza para comprobar los permisos al acceder a objetos del sistema de archivos, mientras que el ID de grupo efectivo se utiliza para otros tipos de comprobaciones de permisos (consulte credentials(7)).

Normalmente, el valor del ID de grupo del sistema de archivos de un proceso es el mismo que el valor de su ID de grupo efectivo. Esto se debe a que siempre que se cambia el ID de grupo efectivo de un proceso, el kernel también cambia el ID de grupo del sistema de archivos para que sea igual al nuevo valor del ID de grupo efectivo. Un proceso puede hacer que el valor de su ID de grupo del sistema de archivos difiera de su ID de grupo efectivo utilizando setfsgid() para cambiar su ID de grupo del sistema de archivos al valor proporcionado en fsgid.

setfsgid() tendrá éxito solo si el llamador es el superusuario o si fsgid coincide con el ID de grupo real del llamador, el ID de grupo efectivo, el ID de grupo de conjunto guardado o el ID de usuario del sistema de archivos actual.

VALOR DE RETORNO

Tanto en caso de éxito como de error, esta llamada devuelve el ID de grupo del sistema de archivos anterior del llamador.

ESTÁNDARES

Linux.

HISTORIA

Linux 1.2.

Diferencias entre biblioteca C y kernel

En glibc 2.15 y anteriores, cuando el envoltorio de esta llamada al sistema determina que el argumento no se puede pasar al kernel sin truncamiento entero (porque el kernel es antiguo y no soporta ID de grupo de 32 bits), devolverá -1 y establecerá errno a EINVAL sin intentar la llamada al sistema.

NOTAS

El concepto de ID de grupo del sistema de archivos y la llamada al sistema setfsgid() se inventaron por razones históricas que ya no son relevantes en los kernels modernos de Linux. Consulte setfsuid(2) para una discusión sobre por qué el uso de setfsuid() y setfsgid() ya no es necesario hoy en día.

La llamada al sistema original setfsgid() de Linux solo soportaba ID de grupo de 16 bits. Posteriormente, Linux 2.4 añadió setfsgid32() que soporta ID de 32 bits. La función envoltorio setfsgid() de glibc maneja de forma transparente la variación entre versiones del kernel.

ERRORES

No se devuelven indicaciones de error de ningún tipo al llamador, y el hecho de que tanto las llamadas exitosas como las fallidas devuelvan el mismo valor hace imposible determinar directamente si la llamada tuvo éxito o falló. En su lugar, el llamador debe recurrir a observar el valor de retorno de una llamada adicional como setfsgid(-1) (que siempre fallará), para determinar si una llamada anterior a setfsgid() cambió el ID de grupo del sistema de archivos. Como mínimo, se debería devolver EPERM cuando la llamada falla (porque el llamador carece de la capacidad CAP_SETGID).

VER TAMBIÉN

kill(2), setfsuid(2), capabilities(7), credentials(7)
