setreuid(2) Manual de llamadas al sistema setreuid(2)

NOMBRE

setreuid, setregid - establecer el ID de usuario o grupo real y/o efectivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int setreuid(uid_t ruid, uid_t euid);
int setregid(gid_t rgid, gid_t egid);
Requisitos de macro de prueba de características para glibc (ver feature_test_macros(7)):

setreuid(), setregid():

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _BSD_SOURCE

DESCRIPCIÓN

setreuid() establece los IDs de usuario real y efectivo del proceso que llama.

Proporcionar un valor de -1 para el ID de usuario real o efectivo hace que el sistema deje ese ID sin cambios.

Los procesos no privilegiados solo pueden establecer el ID de usuario efectivo al ID de usuario real, el ID de usuario efectivo o el ID de usuario del conjunto guardado.

Los usuarios no privilegiados solo pueden establecer el ID de usuario real al ID de usuario real o al ID de usuario efectivo.

Si se establece el ID de usuario real (es decir, ruid no es -1) o el ID de usuario efectivo se establece a un valor no igual al ID de usuario real anterior, el ID de usuario del conjunto guardado se establecerá al nuevo ID de usuario efectivo.

De forma completamente análoga, setregid() establece los IDs de grupo real y efectivo del proceso que llama, y todo lo anterior se aplica con "grupo" en lugar de "usuario".

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

Nota: hay casos en los que setreuid() puede fallar incluso cuando el llamador es UID 0; es un grave error de seguridad omitir la comprobación de un valor de retorno de fallo de setreuid().

ERRORES

EAGAIN
La llamada cambiaría el UID real del llamador (es decir, ruid no coincide con el UID real del llamador), pero hubo un fallo temporal al asignar las estructuras de datos necesarias del kernel.
EAGAIN
ruid no coincide con el UID real del llamador y esta llamada superaría el límite de recursos RLIMIT_NPROC del llamador para los procesos que pertenecen al UID real ruid. Desde Linux 3.1, este caso de error ya no ocurre (pero las aplicaciones robustas deben verificar este error); ver la descripción de EAGAIN en execve(2).
EINVAL
Uno o más de los IDs de usuario o grupo objetivo no son válidos en este espacio de nombres de usuario.
EPERM
El proceso llamador no tiene privilegios (en Linux, no tiene la capacidad necesaria en su espacio de nombres de usuario: CAP_SETUID en el caso de setreuid(), o CAP_SETGID en el caso de setregid()) y se especificó un cambio distinto de (i) intercambiar el ID de usuario (grupo) efectivo con el ID de usuario (grupo) real, o (ii) establecer uno al valor del otro, o (iii) establecer el ID de usuario (grupo) efectivo al valor del ID de usuario (grupo) del conjunto guardado.

VERSIÓNES

POSIX.1 no especifica todos los cambios de UID que Linux permite para un proceso no privilegiado. Para setreuid(), el ID de usuario efectivo puede hacerse igual al ID de usuario real o al ID de usuario del conjunto guardado, y no se especifica si los procesos no privilegiados pueden establecer el ID de usuario real al ID de usuario real, el ID de usuario efectivo o el ID de usuario del conjunto guardado. Para setregid(), el ID de grupo real puede cambiarse al valor del ID de grupo del conjunto guardado, y el ID de grupo efectivo puede cambiarse al valor del ID de grupo real o al ID de grupo del conjunto guardado. Los detalles precisos de qué cambios de ID están permitidos varían entre implementaciones.

POSIX.1 no hace ninguna especificación sobre el efecto de estas llamadas en el ID de usuario del conjunto guardado y el ID de grupo del conjunto guardado.

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, 4.3BSD (apareció por primera vez en 4.2BSD).

El establecimiento del ID de usuario (grupo) efectivo al ID de usuario (grupo) del conjunto guardado es posible desde Linux 1.1.37 (1.1.38).

Las llamadas al sistema setreuid() y setregid() originales de Linux admitían solo IDs de usuario y grupo de 16 bits. Posteriormente, Linux 2.4 añadió setreuid32() y setregid32(), que admiten IDs de 32 bits. Las funciones envoltorio setreuid() y setregid() de glibc manejan de forma transparente las variaciones entre versiones del kernel.

Diferencias biblioteca C/kernel

A nivel de kernel, los IDs de usuario y grupo son un atributo por hilo. Sin embargo, POSIX requiere que todos los hilos de un proceso compartan las mismas credenciales. La implementación de hilos NPTL maneja los requisitos de POSIX proporcionando funciones envoltorio para las diversas llamadas al sistema que cambian las UIDs y GIDs del proceso. Estas funciones envoltorio (incluidas las de setreuid() y setregid()) utilizan una técnica basada en señales para garantizar que cuando un hilo cambia las credenciales, todos los demás hilos del proceso también cambian sus credenciales. Para más detalles, ver nptl(7).
