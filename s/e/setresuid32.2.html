setresuid(2) Manual de llamadas al sistema setresuid(2)

NOMBRE

setresuid, setresgid - establecer ID de usuario o grupo real, efectivo y guardado

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE         /* Ver feature_test_macros(7) */
#include <unistd.h>
int setresuid(uid_t ruid, uid_t euid, uid_t suid);
int setresgid(gid_t rgid, gid_t egid, gid_t sgid);

DESCRIPCIÓN

setresuid() establece el ID de usuario real, el ID de usuario efectivo y el ID de usuario del conjunto guardado del proceso llamante.

Un proceso no privilegiado puede cambiar su UID real, UID efectivo y UID del conjunto guardado, cada uno a uno de: el UID real actual, el UID efectivo actual o el UID del conjunto guardado actual.

Un proceso privilegiado (en Linux, uno que tenga la capacidad CAP_SETUID) puede establecer su UID real, UID efectivo y UID del conjunto guardado a valores arbitrarios.

Si uno de los argumentos es igual a -1, el valor correspondiente no cambia.

Independientemente de los cambios realizados en el UID real, UID efectivo y UID del conjunto guardado, el UID del sistema de archivos siempre se establece al mismo valor que el UID (posiblemente nuevo) efectivo.

De forma completamente análoga, setresgid() establece el GID real, GID efectivo y GID del conjunto guardado del proceso llamante (y siempre modifica el GID del sistema de archivos para que sea el mismo que el GID efectivo), con las mismas restricciones para procesos no privilegiados.

VALOR DE RETORNO

Al éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

Nota: hay casos en los que setresuid() puede fallar incluso cuando el llamante es UID 0; omitir la comprobación de un valor de retorno de error de setresuid() es un grave error de seguridad.

ERRORES

EAGAIN
La llamada cambiaría el UID real del llamante (es decir, ruid no coincide con el UID real del llamante), pero hubo un fallo temporal al asignar las estructuras de datos necesarias del kernel.
EAGAIN
ruid no coincide con el UID real del llamante y esta llamada superaría el límite de recursos RLIMIT_NPROC del llamante para los procesos que pertenecen al UID real ruid. Desde Linux 3.1, este caso de error ya no ocurre (pero las aplicaciones robustas deben verificar este error); ver la descripción de EAGAIN en execve(2).
EINVAL
Uno o más de los IDs de usuario o grupo de destino no son válidos en este espacio de nombres de usuario.
EPERM
El proceso llamante no está privilegiado (no tenía la capacidad necesaria en su espacio de nombres de usuario) y intentó cambiar los IDs a valores que no están permitidos. Para setresuid(), la capacidad necesaria es CAP_SETUID; para setresgid(), es CAP_SETGID.

VERSIÓNES

diferencias entre la biblioteca C y el kernel

A nivel de kernel, los IDs de usuario y los IDs de grupo son un atributo por hilo. Sin embargo, POSIX requiere que todos los hilos de un proceso compartan las mismas credenciales. La implementación de hilos NPTL maneja los requisitos de POSIX proporcionando funciones de envoltura para las diversas llamadas al sistema que cambian los UID y GID de los procesos. Estas funciones de envoltura (incluidas las de setresuid() y setresgid()) emplean una técnica basada en señales para garantizar que cuando un hilo cambia las credenciales, todos los demás hilos del proceso también cambian sus credenciales. Para más detalles, ver nptl(7).

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2024. Linux 2.1.44, glibc 2.3.2. HP-UX, FreeBSD.

Las llamadas al sistema originales setresuid() y setresgid() de Linux solo admitían IDs de usuario y grupo de 16 bits. Posteriormente, Linux 2.4 añadió setresuid32() y setresgid32(), que admitían IDs de 32 bits. Las funciones de envoltura setresuid() y setresgid() de glibc manejan de forma transparente las variaciones entre versiones del kernel.
