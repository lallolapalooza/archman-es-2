NOMBRE

seccomp_syscall_resolve_name - Resolver el nombre de una llamada al sistema

SINOPSIS

#include <seccomp.h>

int seccomp_syscall_resolve_name(const char *name);
int seccomp_syscall_resolve_name_arch(uint32_t arch_token,
                                      const char *name);
int seccomp_syscall_resolve_name_rewrite(uint32_t arch_token,
                                         const char *name);
char *seccomp_syscall_resolve_num_arch(uint32_t arch_token, int num);

Enlace con -lseccomp.

DESCRIPCIÓN

Las funciones seccomp_syscall_resolve_name(), seccomp_syscall_resolve_name_arch() y seccomp_syscall_resolve_name_rewrite() resuelven el nombre comúnmente utilizado de una llamada al sistema al número de llamada al sistema utilizado por el kernel y el resto de la API de libseccomp, con seccomp_syscall_resolve_name_rewrite() reescribiendo el número de llamada al sistema para arquitecturas que modifican la llamada al sistema. La reescritura de llamadas al sistema generalmente ocurre en caso de una llamada al sistema multiplexada, como socketcall(2) o ipc(2) en x86. La función seccomp_syscall_resolve_num_arch() resuelve el número de llamada al sistema utilizado por el kernel al nombre comúnmente utilizado de la llamada al sistema.

El llamante es responsable de liberar la cadena devuelta por seccomp_syscall_resolve_num_arch().

VALOR DE RETORNO

En el caso de seccomp_syscall_resolve_name(), seccomp_syscall_resolve_name_arch() y seccomp_syscall_resolve_name_rewrite() se devuelve el número de llamada al sistema asociado, con el número de llamada al sistema pseudo-negativo devolviéndose en casos donde la llamada al sistema dada no existe para la arquitectura. El valor __NR_SCMP_ERROR se devuelve en caso de error. En todos los casos, el valor de retorno es adecuado para su uso en cualquier función de la API de libseccomp que requiera el número de llamada al sistema, como ejemplos se incluyen seccomp_rule_add() y seccomp_rule_add_exact().

En el caso de seccomp_syscall_resolve_num_arch() se devuelve el nombre de llamada al sistema asociado y sigue siendo responsabilidad del llamante liberar la cadena devuelta mediante free(3).

EJEMPLOS

#include <seccomp.h>
int main(int argc, char *argv[])
{
	int rc = -1;
	scmp_filter_ctx ctx;
	ctx = seccomp_init(SCMP_ACT_KILL);
	if (ctx == NULL)
		goto out;
	/* ... */
	rc = seccomp_rule_add(ctx, SCMP_ACT_ALLOW,
	                      seccomp_syscall_resolve_name("open"), 0);
	if (rc < 0)
		goto out;
	/* ... */
	rc = seccomp_load(ctx);
	if (rc < 0)
		goto out;
	/* ... */
out:
	seccomp_release(ctx);
	return -rc;
}

NOTAS

En caso de llamadas al sistema directas implementadas sobre una llamada al sistema multiplexada, seccomp_syscall_resolve_name() y seccomp_syscall_resolve_name_arch() se pueden usar para verificar si una llamada al sistema directa está implementada para una arquitectura específica, mientras que seccomp_syscall_resolve_name_rewrite() se puede usar para determinar la llamada al sistema multiplexada subyacente.

Aunque el filtro seccomp puede generarse independientemente del kernel, se requiere soporte del kernel para cargar y aplicar el filtro seccomp generado por libseccomp.

El sitio del proyecto libseccomp, con más información y el repositorio del código fuente, se puede encontrar en https://github.com/seccomp/libseccomp. Esta herramienta, así como la biblioteca libseccomp, se encuentra actualmente en desarrollo, por favor, informe cualquier error en el sitio del proyecto o directamente al autor.
