SED(1) Comandos de Usuario SED(1)

NOMBRE

sed - editor de flujos para filtrar y transformar texto

SINOPSIS

sed [-V] [--version] [--help] [-n] [--quiet] [--silent]
    [-l N] [--line-length=N] [-u] [--unbuffered]
    [-E] [-r] [--regexp-extended]
    [-e script] [--expression=script]
    [-f script-file] [--file=script-file]
    [script-si-no-hay-otro-script]
    [archivo...]

DESCRIPCIÓN

Sed es un editor de flujos. Un editor de flujos se utiliza para realizar transformaciones básicas de texto en un flujo de entrada (un archivo o entrada de una tubería). Aunque en algunos aspectos similar a un editor que permite ediciones con guión (como ed), sed funciona realizando solo una pasada sobre las entradas, y consecuentemente es más eficiente. Pero es la capacidad de sed para filtrar texto en una tubería lo que distingue particularmente de otros tipos de editores.

-n, --quiet, --silent

suprimir la impresión automática del espacio de patrones

--debug

anotar la ejecución del programa

-e script, --expression=script

añadir el script a los comandos a ejecutar

-f script-file, --file=script-file

añadir el contenido de script-file a los comandos a ejecutar

--follow-symlinks

seguir enlaces simbólicos al procesar in situ

-i[SUFIJO], --in-place[=SUFIJO]

editar archivos in situ (hace copia de seguridad si se proporciona SUFIJO)

-l N, --line-length=N

especificar la longitud de salto de línea deseada para el comando `l'

--posix

deshabilitar todas las extensiones de GNU.

-E, -r, --regexp-extended

usar expresiones regulares extendidas en el script (para portabilidad, usar el -E de POSIX).

-s, --separate

considerar los archivos como separados en lugar de como un único y largo flujo continuo.

--sandbox

operar en modo sandbox (deshabilitar comandos e/r/w).

-u, --unbuffered

cargar cantidades mínimas de datos de los archivos de entrada y vaciar los búferes de salida con más frecuencia

-z, --null-data

separar líneas por caracteres NUL
--help
mostrar esta ayuda y salir
--version
mostrar información de versión y salir

Si no se proporciona ninguna opción -e, --expression, -f o --file, entonces el primer argumento que no es una opción se toma como el script de sed a interpretar. Todos los argumentos restantes son nombres de archivos de entrada; si no se especifican archivos de entrada, se lee la entrada estándar.

Página principal de GNU sed: https://www.gnu.org/software/sed/. Ayuda general sobre el uso de software GNU: https://www.gnu.org/gethelp/. Envía informes de errores por correo electrónico a: <bug-sed@gnu.org>.

SINÓPSIS DE COMANDOS

Esta es solo una breve sinopsis de los comandos de sed para servir como recordatorio para aquellos que ya conocen sed; se deben consultar otras documentaciones (como el documento texinfo) para obtener descripciones más completas.

Comandos de dirección cero ``

:etiqueta
Etiqueta para los comandos b y t.
#comentario
El comentario se extiende hasta la siguiente nueva línea (o el final de un fragmento de script -e).
}
El corchete de cierre de un bloque { }.

Comandos de dirección cero o una

=
Imprime el número de línea actual.
a \
texto
Añade texto, donde cada nueva línea incrustada va precedida de una barra invertida.
i \
texto
Inserta texto, donde cada nueva línea incrustada va precedida de una barra invertida.
q [código-salida]
Sale inmediatamente del script sed sin procesar más entrada, excepto que si la impresión automática no está deshabilitada, se imprimirá el espacio de patrones actual. El argumento de código de salida es una extensión de GNU.
Q [código-salida]
Sale inmediatamente del script sed sin procesar más entrada. Esta es una extensión de GNU.
r nombre-archivo
Añade texto leído del nombre-archivo.
R nombre-archivo
Añade una línea leída del nombre-archivo. Cada invocación del comando lee una línea del archivo. Esta es una extensión de GNU.

Comandos que aceptan rangos de dirección

{
Inicia un bloque de comandos (termina con }).
b etiqueta
Salta a etiqueta; si etiqueta se omite, salta al final del script.
c \
texto
Reemplaza las líneas seleccionadas con texto, donde cada nueva línea incrustada va precedida de una barra invertida.
d
Elimina el espacio de patrones. Inicia el siguiente ciclo.
D
Si el espacio de patrones no contiene una nueva línea, inicia un ciclo normal como si se hubiera emitido el comando d. De lo contrario, elimina el texto en el espacio de patrones hasta la primera nueva línea, y reinicia el ciclo con el espacio de patrones resultante, sin leer una nueva línea de entrada.
h H
Copia/añade el espacio de patrones al espacio de retención.
g G
Copia/añade el espacio de retención al espacio de patrones.
l
Lista la línea actual en un formato ``visiblemente inequívoco''.
l ancho
Lista la línea actual en un formato ``visiblemente inequívoco'', rompiéndola en ancho caracteres. Esta es una extensión de GNU.
n N
Lee/añade la siguiente línea de entrada al espacio de patrones.
p
Imprime el espacio de patrones actual.
P
Imprime hasta la primera nueva línea incrustada del espacio de patrones actual.
s/expresion_regular/reemplazo/
Intenta hacer coincidir expresion_regular con el espacio de patrones. Si tiene éxito, reemplaza la porción coincidente con reemplazo. El reemplazo puede contener el carácter especial & para referirse a la porción del espacio de patrones que coincidió, y las secuencias de escape especiales \1 a \9 para referirse a las subexpresiones coincidentes correspondientes en la expresion_regular.
t etiqueta
Si una s/// ha realizado una sustitución exitosa desde que se leyó la última línea de entrada y desde el último comando t o T, entonces salta a etiqueta; si etiqueta se omite, salta al final del script.
T etiqueta
Si ninguna s/// ha realizado una sustitución exitosa desde que se leyó la última línea de entrada y desde el último comando t

sed(1)

a stream editor

SYNOPSIS

sed [OPTION]... {SCRIPT-FILE}...
sed [OPTION]... 'COMMAND'...
sed [OPTION]... -f SCRIPT-FILE...

DESCRIPTION

GNU sed manipulates streams of data the way that ed(1) manipulates files; that is, sed reads input line by line, applies a script of one or more editing commands to each line, and outputs the resulting lines. The input can be read from standard input or from a file.

The sed command syntax is:

      sed [OPTION]... [SCRIPT] [INPUTFILE]...

Where:

  • OPTION is one or more of the options described below.
  • SCRIPT is the editing commands to be executed. If it's not preceded by -f, it is the first non-option argument.
  • INPUTFILE is a file to be processed. If no INPUTFILE is given, or if INPUTFILE is specified as -, standard input is read.

The GNU sed command language is a superset of the POSIX sed specification. Refer to the POSIX specification for details about compatibility.

COMMAND SYNOPSIS

In the synopsis for commands below, the following conventions are used:

a
Append text after the line.
i
Insert text before the line.
c
Change the matched line.
d
Delete the pattern space.
D
Delete the pattern space up to the first newline character.
h
Copy the pattern space to the hold space.
H
Append the pattern space to the hold space.
g
Copy the hold space to the pattern space.
G
Append the hold space to the pattern space.
l
List the current pattern space in a \-and M-x like format.
n
Output the current pattern space, then read the next line of input into the pattern space.
N
Append the next line of input, with an embedded newline, to the pattern space.
p
Print the current pattern space.
P
Print the current pattern space up to the first newline character.
r
Read file named filename and append it after the pattern space.
R
Read a line from filename and append it after the pattern space. This is a GNU extension.
s
Substitute.
t
Branch to a label if a substitution was made since the last input line was read and the last t command. If label is omitted, branch to the end of the script. This is a GNU extension.
w
Write the current pattern space to filename.
W
Write the first line of the current pattern space to filename. This is a GNU extension.
x
Exchange the contents of the hold and pattern spaces.
y/source/dest/
Transliterate the characters in the pattern space which appear in source to the corresponding character in dest.

Addresses

Sed commands can be given with no addresses, in which case the command will be executed for all input lines; with one address, in which case the command will only be executed for input lines which match that address; or with two addresses, in which case the command will be executed for all input lines which match the inclusive range of lines starting from the first address and continuing to the second address. Three things to note about address ranges: the syntax is addr1,addr2 (i.e., the addresses are separated by a comma); the line which addr1 matched will always be accepted, even if addr2 selects an earlier line; and if addr2 is a regexp, it will not be tested against the line that addr1 matched.

After the address (or address-range), and before the command, a ! may be inserted, which specifies that the command shall only be executed if the address (or address-range) does not match.

The following address types are supported:

number
Match only the specified line number (which increments cumulatively across files, unless the -s option is specified on the command line).
first~step
Match every step'th line starting with line first. For example, ``sed -n 1~2p'' will print all the odd-numbered lines in the input stream, and the address 2~5 will match every fifth line, starting with the second. first can be zero; in this case, sed operates as if it were equal to step. (This is an extension.)
$
Match the last line.
/regexp/
Match lines matching the regular expression regexp. Matching is performed on the current pattern space, which can be modified with commands such as ``s///''.
\cregexpc
Match lines matching the regular expression regexp. The c may be any character.

GNU sed also supports some special 2-address forms:

0,addr2
Start out in "matched first address" state, until addr2 is found. This is similar to 1,addr2, except that if addr2 matches the very first line of input the 0,addr2 form will be at the end of its range, whereas the 1,addr2 form will still be at the beginning of its range. This works only when addr2 is a regular expression.
addr1,+N
Will match addr1 and the N lines following addr1.
addr1,~N
Will match addr1 and the lines following addr1 until the next line whose input line number is a multiple of N.

REGULAR EXPRESSIONS

POSIX.2 BREs should be supported, but they aren't completely because of performance problems. The \n sequence in a regular expression matches the newline character, and similarly for \a, \t, and other sequences. The -E option switches to using extended regular expressions instead; it has been supported for years by GNU sed, and is now included in POSIX.
