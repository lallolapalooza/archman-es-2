Advertencia

Esto es material avanzado y complejo. No lo necesitas a menos que sepas realmente lo que estás haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionaba acceso al sistema de archivos físico y a los archivos dentro de ese sistema de archivos. Sin embargo, a veces se necesita más potencia que esto. Quizás necesites proporcionar un archivo que esté completamente contenido en la RAM, o necesites enlazar alguna otra API de E/S de archivos a PhysicsFS, o necesites traducir los bits (quizás tengas un archivo .zip estándar que esté cifrado, y necesites descifrarlo sobre la marcha para el desarchivaador zip desprevenido).

Un PHYSFS_Io es la interfaz que utilizan los Archiveros para obtener datos de archivo. Históricamente, esto se ha mapeado a la E/S de archivos al sistema de archivos físico, pero a partir de PhysicsFS 2.1, las aplicaciones pueden proporcionar sus propias implementaciones de E/S en tiempo de ejecución.

Esta interfaz no es necesariamente un buen ajuste universal para la E/S. Hay algunos requisitos a tener en cuenta:

  • Solo hacen E/S bloqueante (al menos, por ahora).
  • Necesitan poder duplicarse. Si tienes un manejador de archivos de fopen(), necesitas poder crear un clon único de él (para que tengamos dos manejadores para el mismo archivo que puedan buscar/leer/etc. sin pisarse unos a otros).
  • Necesitan conocer el tamaño de todo su conjunto de datos.
  • Necesitan poder buscar y rebobinar bajo demanda.

...en resumen, probablemente no vas a escribir una implementación HTTP.

Seguridad de hilos: No se garantiza que las implementaciones de PHYSFS_Io sean seguras para hilos por sí mismas. Bajo el capó, donde PhysicsFS las utiliza, la biblioteca proporciona sus propios bloqueos. Si planeas usarlas directamente desde hilos separados, debes usar mutexes para protegerlas, o no usar el mismo PHYSFS_Io desde dos hilos al mismo tiempo.

void(* PHYSFS_Io::destroy) (struct PHYSFS_Io *io)

Limpia y desasigna la instancia de E/S. Libera los recursos asociados, incluido (opaque) si es aplicable.

Esta función siempre debe tener éxito: como tal, devuelve void. El sistema puede llamar a tu método flush() antes de esto. Puedes reportar un error allí si es necesario. Este método aún puede ser llamado si flush() falla, en cuyo caso tendrás que abandonar los datos no cerrados y otras condiciones fallidas y limpiar.

Una vez que se llama a este método para una instancia dada, el sistema asumirá que es inseguro tocar esa instancia nuevamente y descartará cualquier referencia a ella.

Parámetros

s La instancia de E/S a destruir.

struct PHYSFS_Io *(* PHYSFS_Io::duplicate) (struct PHYSFS_Io *io)

Duplica esta instancia de E/S. Esto debe resultar en una copia completa de este PHYSFS_Io, que pueda vivir completamente de forma independiente. La copia debe poder realizar todas sus operaciones sin alterar el original, incluyendo que cualquiera de los objetos sea destruido por separado (por lo tanto, por ejemplo: no pueden compartir un manejador de archivo; cada uno necesita el suyo).

Si no puedes duplicar un manejador, es legal devolver NULL, pero casi con seguridad necesitarás esta funcionalidad si quieres usar este PHYSFS_Io para respaldar un archivo.

Parámetros

io La instancia de E/S a duplicar.

Devoluciones

Un nuevo valor para el campo (opaque) de un stream, o NULL en caso de error.

int(* PHYSFS_Io::flush) (struct PHYSFS_Io *io)

Cierra los recursos en el medio, o donde sea. Esta es la oportunidad de reportar fallos en escrituras que habían afirmado éxito anteriormente, pero que aún tenían la posibilidad de fallar. Este método puede ser NULL si el cierre no es necesario.

Esta función puede ser llamada antes de destroy(), ya que puede reportar fallos y destroy() no puede. También puede ser llamada en otros momentos.

Parámetros

io La instancia de E/S a cerrar.

Devoluciones

Cero en caso de error, distinto de cero en caso de éxito.

PHYSFS_sint64(* PHYSFS_Io::length) (struct PHYSFS_Io *io)

Determina el tamaño del conjunto de datos de la instancia de E/S. Devuelve el número de bytes disponibles en el archivo, o -1 si no puedes determinarlo. Un fallo será casi seguro fatal para el uso posterior de este stream, por lo que no puedes dejar esto sin implementar.

Parámetros

io La instancia de E/S a consultar.

Devoluciones

Tamaño total, en bytes, del conjunto de datos.

void* PHYSFS_Io::opaque

Datos de instancia para esta estructura. Cada instancia tiene un puntero asociado que se puede utilizar para almacenar lo que desee. Este puntero es por instancia del stream, por lo que presumiblemente cambiará al llamar a duplicate(). Esto puede ser desasignado durante el método destroy().

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buf, PHYSFS_uint64 len)

Lee más datos. Lee (len) bytes de la interfaz, en la posición actual de E/S, y almacena en (buffer). La posición actual de E/S debe avanzar por el número de bytes leídos con éxito.

No tienes que implementar esto; establécelo en NULL si no está implementado. Esto solo se usará si el archivo se abre para lectura. Si se establece en NULL, se utilizará una implementación predeterminada que reporta inmediatamente un error.

Parámetros

io La instancia de E/S de la que leer.
buf El buffer donde almacenar los datos. Debe tener al menos (len) bytes de longitud y no puede ser NULL.
len El número de bytes a leer de la interfaz.

Devoluciones

número de bytes leídos del archivo, 0 en fin de archivo (EOF), -1 en caso de fallo completo.

Reporta la posición actual de E/S. Devuelve el número de bytes desde el inicio del archivo hasta la posición actual de E/S. El valor de retorno debe ser -1 en caso de error, y debe ser un número de bytes leídos de forma segura.

No tienes que implementar esto; establécelo en NULL si no está implementado. Esto solo se usará si el archivo se abre para escritura. Si se establece en NULL, se utilizará una implementación predeterminada que reporta inmediatamente un error.

buffer El buffer que contiene los datos a escribir. No puede ser NULL.

NAME

PHYSFS_Io

structure for abstracted file i/o

SYNOPSIS

#include <physfs.h>

struct PHYSFS_Io { ... };

Detailed Description

This structure defines the interface for abstracted file i/o operations. It is intended to allow PhysFS to use various storage mechanisms (like ZIP files, archives, network streams, etc.) transparently.

When an archive is opened, PhysFS will typically create an instance of a concrete implementation of this structure, fill in the function pointers, and return it to the caller. The caller can then use the function pointers to interact with the archive's contents.

Some fields are function pointers that *must* be implemented for any usable i/o mechanism. Others are optional and can be set to NULL.

PhysFS does not allow arbitrary i/o instances to be created. You can only get PHYSFS_Io structs from PhysFS calls like PHYSFS_openWrite(), PHYSFS_openRead(), etc. Also, there is no way to get a PHYSFS_Io structure for a directory.

Field Documentation

void(* PHYSFS_Io::close) (struct PHYSFS_Io *io)

Close the i/o stream and free any resources associated with it. This function *must* be implemented.

Parameters

io The i/o instance to close.

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buffer, PHYSFS_uint64 len)

Read data from the stream. Read up to (len) bytes from the current i/o position into (buffer). The current i/o position should move ahead by the number of bytes successfully read. You are allowed to return fewer bytes than requested if the end of the stream is reached.

This function *must* be implemented. A failure to read will be treated as an error.

Parameters

io The i/o instance to read from.
buffer The buffer to read data into. It must be at least (len) bytes long and can't be NULL.
len The maximum number of bytes to read.

Returns

The number of bytes successfully read into (buffer), or -1 if a fatal error occurred.

PHYSFS_sint64(* PHYSFS_Io::seek) (struct PHYSFS_Io *io, PHYSFS_sint64 offset)

Set the i/o position. Change the current i/o position to the byte offset specified by (offset). The offset is relative to the beginning of the file. This function *must* be implemented.

You are allowed to return non-zero on failure, but PhysFS assumes that a seek operation will always succeed unless explicitly told otherwise. If a seek fails, it will be treated as an error.

Parameters

io The i/o instance to seek.
offset The new byte offset for the i/o position.

Returns

non-zero on success, zero on error.

PHYSFS_sint64(* PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Report current i/o position. Return bytes offset, or -1 if you aren't able to determine. A failure will almost certainly be fatal to further use of this stream, so you may not leave this unimplemented.

Parameters

io The i/o instance to query.

Returns

The current byte offset for the i/o position, -1 if unknown.

PHYSFS_uint32 PHYSFS_Io::version

Binary compatibility information. This must be set to zero at this time. Future versions of this struct will increment this field, so we know what a given implementation supports. We'll presumably keep supporting older versions as we offer new features, though.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Write more data. Write (len) bytes from (buffer) to the interface at the current i/o position. The current i/o position should move ahead by the number of bytes successfully written.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for writing. If set to NULL, a default implementation that immediately reports failure will be used.

You are allowed to buffer; a write can succeed here and then later fail when flushing. Note that PHYSFS_setBuffer() may be operating a level above your i/o, so you should usually not implement your own buffering routines.

Parameters

io The i/o instance to write to.
buffer The buffer to read data from. It must be at least (len) bytes long and can't be NULL.
len The number of bytes to read from (buffer).

Returns

number of bytes written to file, -1 if complete failure.
