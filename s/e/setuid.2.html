setuid(2) Manual de llamadas al sistema setuid(2)

NOMBRE

setuid - establecer la identidad del usuario

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int setuid(uid_t uid);

DESCRIPCIÓN

setuid() establece el ID de usuario efectivo del proceso llamante. Si el proceso llamante tiene privilegios (más precisamente: si el proceso tiene la capacidad CAP_SETUID en su espacio de nombres de usuario), también se establecen el ID de usuario real y el ID de usuario efectivo guardado.

En Linux, setuid() se implementa de forma similar a la versión POSIX con la característica _POSIX_SAVED_IDS. Esto permite que un programa set-user-ID (distinto de root) renuncie a todos sus privilegios de usuario, realice algunos trabajos no privilegiados y luego vuelva a activar la identidad original del usuario efectivo de forma segura.

Si el usuario es root o el programa es set-user-ID-root, se debe tener especial cuidado: setuid() comprueba el ID de usuario efectivo del llamante y, si es el superusuario, todos los ID de usuario relacionados con el proceso se establecen en uid. Una vez que esto ocurre, es imposible que el programa recupere los privilegios de root.

Por lo tanto, un programa set-user-ID-root que desee renunciar temporalmente a los privilegios de root, asumir la identidad de un usuario no privilegiado y luego recuperar los privilegios de root después, no puede utilizar setuid(). Puede lograr esto con seteuid(2).

VALOR DE RETORNO

Al tener éxito, se devuelve cero. En caso de error, se devuelve -1 y se establece errno para indicar el error.

Nota: existen casos en los que setuid() puede fallar incluso cuando el llamante tiene UID 0; omitir la comprobación de un retorno de error de setuid() es un grave error de seguridad.

ERRORES

EAGAIN
La llamada cambiaría el ID de usuario real del llamante (es decir, uid no coincide con el ID de usuario real del llamante), pero hubo un fallo temporal al asignar las estructuras de datos del kernel necesarias.
EAGAIN
uid no coincide con el ID de usuario real del llamante y esta llamada llevaría el número de procesos pertenecientes al ID de usuario real uid por encima del límite de recursos RLIMIT_NPROC del llamante. Desde Linux 3.1, este caso de error ya no ocurre (pero las aplicaciones robustas deben comprobar este error); véase la descripción de EAGAIN en execve(2).
EINVAL
El ID de usuario especificado en uid no es válido en este espacio de nombres de usuario.
EPERM
El usuario no tiene privilegios (Linux: no tiene la capacidad CAP_SETUID en su espacio de nombres de usuario) y uid no coincide con el ID de usuario real o el ID de usuario efectivo guardado del proceso llamante.

VERSIÓNES

Diferencias entre la biblioteca C y el kernel

A nivel de kernel, los ID de usuario y grupo son atributos por hilo. Sin embargo, POSIX requiere que todos los hilos de un proceso compartan las mismas credenciales. La implementación de hilos NPTL maneja los requisitos de POSIX proporcionando funciones envoltorio para las diversas llamadas al sistema que cambian los UID y GID del proceso. Estas funciones envoltorio (incluida la de setuid()) emplean una técnica basada en señales para garantizar que cuando un hilo cambia las credenciales, todos los demás hilos del proceso también cambien sus credenciales. Para más detalles, véase nptl(7).

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, SVr4.

No es del todo compatible con la llamada 4.4BSD, que establece todos los ID de usuario, real, guardado y efectivo.

La llamada al sistema setuid() original de Linux solo admitía ID de usuario de 16 bits. Posteriormente, Linux 2.4 añadió setuid32() compatible con IDs de 32 bits. La función envoltorio setuid() de glibc se encarga de forma transparente de la variación entre versiones del kernel.

NOTAS

Linux tiene el concepto de ID de usuario del sistema de archivos, normalmente igual al ID de usuario efectivo. La llamada setuid() también establece el ID de usuario del sistema de archivos del proceso llamante. Véase setfsuid(2).

Si uid es diferente del UID efectivo anterior, el proceso tendrá prohibido generar volcados de memoria (core dumps).
