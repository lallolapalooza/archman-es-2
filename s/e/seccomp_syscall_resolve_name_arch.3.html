NOMBRE

seccomp_syscall_resolve_name - Resuelve un nombre de syscall

SINOPSIS

#include <seccomp.h>

int seccomp_syscall_resolve_name(const char *name);
int seccomp_syscall_resolve_name_arch(uint32_t arch_token,
                                      const char *name);
int seccomp_syscall_resolve_name_rewrite(uint32_t arch_token,
                                         const char *name);
char *seccomp_syscall_resolve_num_arch(uint32_t arch_token, int num);

Enlazar con -lseccomp.

DESCRIPCIÓN

Las funciones seccomp_syscall_resolve_name(), seccomp_syscall_resolve_name_arch() y seccomp_syscall_resolve_name_rewrite() resuelven el nombre de syscall comúnmente utilizado al número de syscall utilizado por el kernel y el resto de la API de libseccomp, con seccomp_syscall_resolve_name_rewrite() reescribiendo el número de syscall para arquitecturas que modifican la syscall. La reescritura de syscalls típicamente ocurre en caso de una syscall multiplexada, como socketcall(2) o ipc(2) en x86. La función seccomp_syscall_resolve_num_arch() resuelve el número de syscall utilizado por el kernel al nombre de syscall comúnmente utilizado.

El llamador es responsable de liberar la cadena devuelta por seccomp_syscall_resolve_num_arch().

VALOR DE RETORNO

En el caso de seccomp_syscall_resolve_name(), seccomp_syscall_resolve_name_arch() y seccomp_syscall_resolve_name_rewrite() se devuelve el número de syscall asociado, y se devuelve el número de pseudo syscall negativo en casos donde la syscall dada no existe para la arquitectura. El valor __NR_SCMP_ERROR se devuelve en caso de error. En todos los casos, el valor de retorno es adecuado para su uso en cualquier función de API de libseccomp que requiera el número de syscall, ejemplos incluyen seccomp_rule_add() y seccomp_rule_add_exact().

En el caso de seccomp_syscall_resolve_num_arch() se devuelve el nombre de syscall asociado y sigue siendo responsabilidad del llamador liberar la cadena devuelta mediante free(3).

EJEMPLOS

#include <seccomp.h>
int main(int argc, char *argv[])
{
	int rc = -1;
	scmp_filter_ctx ctx;
	ctx = seccomp_init(SCMP_ACT_KILL);
	if (ctx == NULL)
		goto out;
	/* ... */
	rc = seccomp_rule_add(ctx, SCMP_ACT_ALLOW,
	                      seccomp_syscall_resolve_name("open"), 0);
	if (rc < 0)
		goto out;
	/* ... */
	rc = seccomp_load(ctx);
	if (rc < 0)
		goto out;
	/* ... */
out:
	seccomp_release(ctx);
	return -rc;
}

NOTAS

En el caso de syscalls desnudas implementadas sobre una syscall multiplexada, seccomp_syscall_resolve_name() y seccomp_syscall_resolve_name_arch() pueden usarse para verificar si una syscall desnuda está implementada para una arquitectura específica, mientras que seccomp_syscall_resolve_name_rewrite() puede usarse para determinar la syscall multiplexada subyacente.

Aunque el filtro seccomp puede generarse independientemente del kernel, se requiere soporte del kernel para cargar y aplicar el filtro seccomp generado por libseccomp.

El sitio del proyecto libseccomp, con más información y el repositorio de código fuente, se puede encontrar en https://github.com/seccomp/libseccomp. Esta herramienta, así como la biblioteca libseccomp, se encuentra actualmente en desarrollo, por favor, informe cualquier error en el sitio del proyecto o directamente al autor.
