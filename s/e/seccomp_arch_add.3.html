seccomp_arch_add(3)

Licencias: LGPL-2.1-only

seccomp_arch_add(3) Documentación de libseccomp seccomp_arch_add(3)

NOMBRE

seccomp_arch_add, seccomp_arch_remove, seccomp_arch_exist, seccomp_arch_native - Gestionar arquitecturas de filtros seccomp

SINOPSIS

#include <seccomp.h>

typedef void * scmp_filter_ctx;

#define SCMP_ARCH_NATIVE
#define SCMP_ARCH_X86
#define SCMP_ARCH_X86_64
#define SCMP_ARCH_X32
#define SCMP_ARCH_ARM
#define SCMP_ARCH_AARCH64
#define SCMP_ARCH_MIPS
#define SCMP_ARCH_MIPS64
#define SCMP_ARCH_MIPS64N32
#define SCMP_ARCH_MIPSEL
#define SCMP_ARCH_MIPSEL64
#define SCMP_ARCH_MIPSEL64N32
#define SCMP_ARCH_PPC
#define SCMP_ARCH_PPC64
#define SCMP_ARCH_PPC64LE
#define SCMP_ARCH_S390
#define SCMP_ARCH_S390X
#define SCMP_ARCH_PARISC
#define SCMP_ARCH_PARISC64
#define SCMP_ARCH_RISCV64

uint32_t seccomp_arch_resolve_name(const char *arch_name);
uint32_t seccomp_arch_native();
int seccomp_arch_exist(const scmp_filter_ctx ctx, uint32_t arch_token);
int seccomp_arch_add(scmp_filter_ctx ctx, uint32_t arch_token);
int seccomp_arch_remove(scmp_filter_ctx ctx, uint32_t arch_token);

Enlace con -lseccomp.

DESCRIPCIÓN

La función seccomp_arch_exist() comprueba si una arquitectura dada ha sido añadida al filtro seccomp en ctx, donde seccomp_arch_add() y seccomp_arch_remove() añaden y eliminan, respectivamente, arquitecturas del filtro seccomp. En las tres funciones, los valores de arquitectura dados en arch_token deben ser las constantes definidas SCMP_ARCH_*; con la constante SCMP_ARCH_NATIVE refiriéndose siempre a la arquitectura nativa compilada. La función seccomp_arch_native() devuelve la arquitectura del sistema de tal manera que coincida con una de las constantes SCMP_ARCH_*. Mientras que la función seccomp_arch_resolve_name() también devuelve una constante SCMP_ARCH_*, el token devuelto coincide con el nombre de la arquitectura pasada como argumento a la función.

Cuando se inicializa un filtro seccomp con la llamada a seccomp_init(3), la arquitectura nativa se añade automáticamente al filtro.

Aunque es posible eliminar todas las arquitecturas de un filtro, la mayoría de las API de libseccomp fallarán si el filtro no contiene al menos una arquitectura.

Al añadir una nueva arquitectura a un filtro existente, las reglas existentes no se añadirán a la nueva arquitectura. Sin embargo, las reglas añadidas después de añadir la nueva arquitectura se añadirán a todas las arquitecturas del filtro.

VALOR DE RETORNO

Las funciones seccomp_arch_add(), seccomp_arch_remove() y seccomp_arch_exist() devuelven cero si la operación es exitosa o uno de los siguientes códigos de error en caso de fallo:

-EDOM
Fallo específico de la arquitectura.
-EEXIST
En el caso de seccomp_arch_add() la arquitectura ya existe y en el caso de seccomp_arch_remove() la arquitectura no existe.
-EINVAL
Entrada inválida, ya sea el contexto o el token de arquitectura es inválido.
-ENOMEM
La biblioteca no pudo asignar suficiente memoria.

EJEMPLOS

#include <seccomp.h>
int main(int argc, char *argv[])
{
	int rc = -1;
	scmp_filter_ctx ctx;
	ctx = seccomp_init(SCMP_ACT_KILL);
	if (ctx == NULL)
		goto out;
	if (seccomp_arch_exist(ctx, SCMP_ARCH_X86) == -EEXIST) {
		rc = seccomp_arch_add(ctx, SCMP_ARCH_X86);
		if (rc != 0)
			goto out_all;
		rc = seccomp_arch_remove(ctx, SCMP_ARCH_NATIVE);
		if (rc != 0)
			goto out_all;
	}
	/* ... */
out:
	seccomp_release(ctx);
	return -rc;
}

NOTAS

Aunque el filtro seccomp puede generarse independientemente del núcleo, se requiere soporte del núcleo para cargar y aplicar el filtro seccomp generado por libseccomp.

El sitio del proyecto libseccomp, con más información y el repositorio de código fuente, se puede encontrar en https://github.com/seccomp/libseccomp. Esta herramienta, así como la biblioteca libseccomp, está actualmente en desarrollo, por favor, informe de cualquier error en el sitio del proyecto o directamente al autor.
