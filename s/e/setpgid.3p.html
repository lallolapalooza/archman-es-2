Esta página del manual es parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

setpgid — establecer el ID del grupo de procesos para el control de trabajos

SINÓPSIS

#include <unistd.h>
int setpgid(pid_t pid, pid_t pgid);

DESCRIPCIÓN

La función setpgid() unirá un grupo de procesos existente o creará un nuevo grupo de procesos dentro de la sesión del proceso que llama.

El ID del grupo de procesos de un líder de sesión no cambiará.

Al completarse con éxito, el ID del grupo de procesos del proceso con un ID de proceso que coincida con pid se establecerá en pgid.

Como caso especial, si pid es 0, se utilizará el ID del proceso del proceso que llama. Además, si pgid es 0, se utilizará el ID del proceso del proceso indicado.

VALOR DE RETORNO

Al completarse con éxito, setpgid() devolverá 0; de lo contrario, se devolverá -1 y se establecerá errno para indicar el error.

ERRORES

La función setpgid() fallará si:

EACCES
El valor del argumento pid coincide con el ID del proceso de un proceso hijo del proceso que llama y el proceso hijo ha ejecutado con éxito una de las funciones exec.
EINVAL
El valor del argumento pgid es menor que 0, o no es un valor soportado por la implementación.
EPERM
El proceso indicado por el argumento pid es un líder de sesión.
EPERM
El valor del argumento pid coincide con el ID del proceso de un proceso hijo del proceso que llama y el proceso hijo no está en la misma sesión que el proceso que llama.
EPERM
El valor del argumento pgid es válido pero no coincide con el ID del proceso del proceso indicado por el argumento pid y no hay ningún proceso con un ID de grupo de procesos que coincida con el valor del argumento pgid en la misma sesión que el proceso que llama.
ESRCH
El valor del argumento pid no coincide con el ID del proceso del proceso que llama o de un proceso hijo del proceso que llama.

FUNDAMENTO

La función setpgid() agrupará procesos con el propósito de señalización, colocación en primer plano o segundo plano, y otras acciones de control de trabajos.

La función setpgid() es similar a la función setpgrp() de 4.2 BSD, excepto que 4.2 BSD permitía que el nuevo grupo de procesos especificado asumiera cualquier valor. Esto presenta ciertos problemas de seguridad y es más flexible de lo necesario para soportar el control de trabajos.

Para proporcionar una seguridad más estricta, setpgid() solo permite al proceso que llama unirse a un grupo de procesos ya en uso dentro de su sesión o crear un nuevo grupo de procesos cuyo ID de grupo de procesos sea igual a su ID de proceso.

Cuando un shell de control de trabajos inicia un nuevo trabajo, los procesos del trabajo deben colocarse en un nuevo grupo de procesos mediante setpgid(). Hay dos restricciones de tiempo involucradas en esta acción:

1.
El nuevo proceso debe colocarse en el nuevo grupo de procesos antes de que se ejecute el programa apropiado a través de una de las funciones exec.
2.
El nuevo proceso debe colocarse en el nuevo grupo de procesos antes de que el shell pueda enviar señales correctamente al nuevo grupo de procesos.

Para abordar estas restricciones, se realizan las siguientes acciones. Los nuevos procesos llaman a setpgid() para modificar sus propios grupos de procesos después de fork() pero antes de exec. Esto satisface la primera restricción. Bajo 4.3 BSD, la segunda restricción se satisface mediante la propiedad de sincronización de vfork(); es decir, el shell se suspende hasta que el hijo completa el exec, asegurando así que el hijo ha completado el setpgid(). Se consideró una nueva versión de fork() con esta misma propiedad de sincronización, pero se decidió en cambio simplemente permitir que el proceso shell padre ajuste el grupo de procesos de sus hijos mediante setpgid(). Ambas restricciones de tiempo ahora se satisfacen haciendo que tanto el shell padre como el hijo intenten ajustar el grupo de procesos del proceso hijo; no importa cuál tenga éxito primero.

Dado que sería confuso para una aplicación que su grupo de procesos cambie después de que comience a ejecutarse (es decir, después de exec), y dado que el proceso hijo ya habría ajustado su grupo de procesos antes de esto, se agregó el error [EACCES] para prohibir esto.

Un uso no obvio de setpgid() es permitir que un shell de control de trabajos se devuelva a su grupo de procesos original (el que estaba en vigor cuando se ejecutó el shell de control de trabajos). Un shell de control de trabajos hace esto antes de devolver el control a su padre cuando está terminando o suspendiéndose a sí mismo como una forma de restaurar su "estado" de control de trabajos a lo que su padre esperaría. (Tenga en cuenta que el grupo de procesos original del shell de control de trabajos generalmente coincide con el grupo de procesos de su padre, pero esto no es necesariamente siempre el caso.)

NOMBRE

setpgid - establecer o obtener el ID del grupo de procesos

SINOPSIS

#include <unistd.h>

pid_t setpgid(pid_t pid, pid_t pgid);

DESCRIPCIÓN

La llamada al sistema setpgid() establece el ID del grupo de procesos del proceso especificado por pid al valor especificado por pgid.

El valor de pid puede ser el ID del proceso del llamante (si pid es 0) o el ID de un proceso descendiente del llamante (si pid es distinto de cero).

El valor de pgid puede ser un ID de grupo de procesos existente o un ID de grupo de procesos que el llamante esté dispuesto a crear. Si pgid es distinto de cero, se convierte en el nuevo ID de grupo de procesos para el proceso especificado por pid.

Si pid es 0 y pgid es 0, el llamante establece su propio ID de grupo de procesos al ID de su propio proceso.

Si pid es distinto de cero y pgid es 0, el nuevo ID de grupo de procesos es el ID del proceso especificado por pid.

Si pid es distinto de cero y pgid es distinto de cero, el proceso especificado por pid se une al grupo de procesos especificado por pgid.

Para que setpgid() tenga éxito:

  • Si pid es 0, el proceso llamante debe tener los privilegios necesarios (CAP_SYS_ADMIN) o el proceso especificado por pid debe ser un descendiente del llamante.
  • El pgid especificado debe ser un ID de grupo de procesos existente, o el proceso especificado por pid debe ser un descendiente del llamante y el pgid especificado debe ser igual al ID del proceso especificado por pid.

Si pid es el ID del proceso del llamante, el llamante puede establecer su propio grupo de procesos a cualquier pgid que sea igual a su propio ID de proceso, o a cualquier pgid que sea el ID de un grupo de procesos existente, siempre que no esté intentando realizar un "conjunto de grupo de procesos de nivel superior" (vea setlogin(2)).

El llamante puede establecer el grupo de procesos de un proceso descendiente solo si el pgid especificado es igual al ID del proceso descendiente.

VALOR DEVUELTO

En caso de éxito, setpgid() devuelve el nuevo ID de grupo de procesos del proceso especificado por pid.

En caso de error, setpgid() devuelve -1 y errno se establece para indicar el error.

ERRORES

EACCES
El proceso especificado por pid no es un descendiente del llamante, y el llamante no tiene CAP_SYS_ADMIN. Además, pgid especificado no es un ID de grupo de procesos existente, ni es igual al ID del proceso especificado por pid.
EINVAL
El valor de pid o pgid no es válido.
ENOCHPID
El proceso especificado por pid no existe.
ENOSYS
La llamada al sistema setpgid() no está implementada en el sistema.
EPERM
El proceso especificado por pid es un descendiente del llamante, pero el llamante no tiene CAP_SYS_ADMIN y pgid no es igual al ID del proceso especificado por pid.
ESRCH
El proceso especificado por pid no existe.

EJEMPLOS

Para poner el proceso actual en su propio grupo de procesos:

if (setpgid(0, 0) < 0) {
        perror("setpgid");
        exit(EXIT_FAILURE);
    }

Para poner el proceso actual en un grupo de procesos con el mismo ID que su padre:

if (setpgid(0, getpgrp()) < 0) {
        perror("setpgid");
        exit(EXIT_FAILURE);
    }

USO DE LA APLICACIÓN

La llamada al sistema setpgid() es utilizada por los programas para gestionar grupos de procesos, lo cual es fundamental para el control de trabajos en shells y otros programas interactivos. Permite mover un proceso a un nuevo grupo de procesos o unirlo a uno existente.

FUNDAMENTACIÓN

La función setpgid() es parte de la interfaz de control de procesos de POSIX. Su propósito es permitir que los programas modifiquen la pertenencia de los grupos de procesos. Esto es importante para que la señalización y la gestión de trabajos funcionen correctamente. Por ejemplo, cuando se presiona Ctrl+C en un terminal, se envía una señal SIGINT a todos los procesos del grupo de procesos del terminal.

DIRECCIONES FUTURAS

No se esperan cambios significativos en la funcionalidad básica de setpgid().
