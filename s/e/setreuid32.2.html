setreuid(2) Manual de Llamadas al Sistema setreuid(2)

NOMBRE

setreuid, setregid - establecer el ID de usuario o grupo real y/o efectivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int setreuid(uid_t ruid, uid_t euid);
int setregid(gid_t rgid, gid_t egid);
Requisitos de macro de prueba de características para glibc (ver feature_test_macros(7)):

setreuid(), setregid():

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _BSD_SOURCE

DESCRIPCIÓN

setreuid() establece los IDs de usuario real y efectivo del proceso que llama.

Suministrar un valor de -1 para el ID de usuario real o efectivo hace que el sistema deje ese ID sin cambios.

Los procesos no privilegiados solo pueden establecer el ID de usuario efectivo al ID de usuario real, el ID de usuario efectivo o el ID de usuario de conjunto guardado.

Los usuarios no privilegiados solo pueden establecer el ID de usuario real al ID de usuario real o al ID de usuario efectivo.

Si se establece el ID de usuario real (es decir, ruid no es -1) o el ID de usuario efectivo se establece a un valor no igual al ID de usuario real anterior, el ID de usuario de conjunto guardado se establecerá al nuevo ID de usuario efectivo.

De forma completamente análoga, setregid() establece los IDs de grupo real y efectivo del proceso que llama, y todo lo anterior se aplica con "grupo" en lugar de "usuario".

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y se establece errno para indicar el error.

Nota: hay casos en los que setreuid() puede fallar incluso cuando el llamante es UID 0; es un grave error de seguridad omitir la verificación de un valor de retorno de fallo de setreuid().

ERRORES

EAGAIN
La llamada cambiaría el ID de usuario real del llamante (es decir, ruid no coincide con el ID de usuario real del llamante), pero hubo un fallo temporal al asignar las estructuras de datos del kernel necesarias.
EAGAIN
ruid no coincide con el ID de usuario real del llamante y esta llamada superaría el límite de recursos RLIMIT_NPROC del llamante para los procesos que pertenecen al ID de usuario real ruid. Desde Linux 3.1, este caso de error ya no ocurre (pero las aplicaciones robustas deben verificar este error); ver la descripción de EAGAIN en execve(2).
EINVAL
Uno o más de los IDs de usuario o grupo de destino no son válidos en este espacio de nombres de usuario.
EPERM
El proceso que llama no tiene privilegios (en Linux, no tiene la capacidad necesaria en su espacio de nombres de usuario: CAP_SETUID en el caso de setreuid(), o CAP_SETGID en el caso de setregid()) y se especificó un cambio distinto de (i) intercambiar el ID efectivo de usuario (grupo) con el ID real de usuario (grupo), o (ii) establecer uno al valor del otro, o (iii) establecer el ID efectivo de usuario (grupo) al valor del ID de usuario (grupo) de conjunto guardado.

VERSIONES

POSIX.1 no especifica todos los cambios de UID que Linux permite para un proceso no privilegiado. Para setreuid(), el ID de usuario efectivo puede ser el mismo que el ID de usuario real o el ID de usuario de conjunto guardado, y no se especifica si los procesos no privilegiados pueden establecer el ID de usuario real al ID de usuario real, el ID de usuario efectivo o el ID de usuario de conjunto guardado. Para setregid(), el ID de grupo real puede cambiarse al valor del ID de grupo de conjunto guardado, y el ID de grupo efectivo puede cambiarse al valor del ID de grupo real o el ID de grupo de conjunto guardado. Los detalles precisos de qué cambios de ID están permitidos varían entre implementaciones.

POSIX.1 no hace ninguna especificación sobre el efecto de estas llamadas en el ID de usuario de conjunto guardado y el ID de grupo de conjunto guardado.

ESTANDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, 4.3BSD (apareció por primera vez en 4.2BSD).

Establecer el ID efectivo de usuario (grupo) al ID de usuario (grupo) de conjunto guardado es posible desde Linux 1.1.37 (1.1.38).

Las llamadas al sistema originales de Linux setreuid() y setregid() solo admitían IDs de usuario y grupo de 16 bits. Posteriormente, Linux 2.4 agregó setreuid32() y setregid32(), que admiten IDs de 32 bits. Las funciones de envoltura setreuid() y setregid() de glibc manejan de forma transparente las variaciones entre versiones del kernel.

Diferencias biblioteca C/kernel

A nivel del kernel, los IDs de usuario y grupo son un atributo por hilo. Sin embargo, POSIX requiere que todos los hilos de un proceso compartan las mismas credenciales. La implementación de hilos NPTL maneja los requisitos de POSIX al proporcionar funciones de envoltura para las diversas llamadas al sistema que cambian los UID y GID del proceso. Estas funciones de envoltura (incluidas las de setreuid() y setregid()) emplean una técnica basada en señales para garantizar que cuando un hilo cambia las credenciales, todos los demás hilos del proceso también cambien sus credenciales. Para más detalles, ver nptl(7).
