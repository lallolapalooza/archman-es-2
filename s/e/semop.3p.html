NOMBRE

semop — operaciones de semáforo XSI

SINOPSIS

#include <sys/sem.h>
int semop(int semid, struct sembuf *sops, size_t nsops);

DESCRIPCIÓN

La función semop() opera sobre semáforos XSI (consulte el volumen de Definiciones Base de POSIX.1-2017, Sección 4.17, Semáforo). No se especifica si esta función interactúa con las facilidades de comunicación entre procesos en tiempo real definidas en la Sección 2.8, Tiempo Real.

La función semop() realizará atómicamente un array definido por el usuario de operaciones de semáforo en orden de array sobre el conjunto de semáforos asociado al identificador de semáforo especificado por el argumento semid.

El argumento sops es un puntero a un array definido por el usuario de estructuras de operaciones de semáforo. La implementación no modificará los elementos de este array a menos que la aplicación utilice extensiones definidas por la implementación.

El argumento nsops es el número de dichas estructuras en el array.

Cada estructura, sembuf, incluye los siguientes miembros:

Tipo de miembro Nombre del miembro Descripción
unsigned short sem_num Número de semáforo.
short sem_op Operación de semáforo.
short sem_flg Flags de operación.

Cada operación de semáforo especificada por sem_op se realizará en el semáforo correspondiente especificado por semid y sem_num.

La variable sem_op especifica una de las tres operaciones de semáforo:

1.
Si sem_op es un entero negativo y el proceso que llama tiene permiso de alteración, ocurrirá una de las siguientes cosas:
*
Si semval (consulte <sys/sem.h>) es mayor o igual que el valor absoluto de sem_op, el valor absoluto de sem_op se restará de semval. Además, si (sem_flg &SEM_UNDO) es distinto de cero, el valor absoluto de sem_op se sumará al valor semadj del proceso que llama para el semáforo especificado.
*
Si semval es menor que el valor absoluto de sem_op y (sem_flg &IPC_NOWAIT) es distinto de cero, semop() devolverá inmediatamente.
*
Si semval es menor que el valor absoluto de sem_op y (sem_flg &IPC_NOWAIT) es 0, semop() incrementará el semncnt asociado con el semáforo especificado y suspenderá la ejecución del hilo que llama hasta que ocurra una de las siguientes condiciones:
--
El valor de semval es mayor o igual que el valor absoluto de sem_op. Cuando esto ocurre, el valor de semncnt asociado con el semáforo especificado se decrementará, el valor absoluto de sem_op se restará de semval y, si (sem_flg &SEM_UNDO) es distinto de cero, el valor absoluto de sem_op se sumará al valor semadj del proceso que llama para el semáforo especificado.
--
El semid para el cual el hilo que llama está esperando una acción se elimina del sistema. Cuando esto ocurre, errno se establecerá en [EIDRM] y se devolverá -1.
--
El hilo que llama recibe una señal que debe ser capturada. Cuando esto ocurre, el valor de semncnt asociado con el semáforo especificado se decrementará, y el hilo que llama reanudará la ejecución de la manera prescrita en sigaction().
2.
Si sem_op es un entero positivo y el proceso que llama tiene permiso de alteración, el valor de sem_op se sumará a semval y, si (sem_flg &SEM_UNDO) es distinto de cero, el valor de sem_op se restará del valor semadj del proceso que llama para el semáforo especificado.
3.
Si sem_op es 0 y el proceso que llama tiene permiso de lectura, ocurrirá una de las siguientes cosas:
*
Si semval es 0, semop() devolverá inmediatamente.
*
Si semval es distinto de cero y (sem_flg &IPC_NOWAIT) es distinto de cero, semop() devolverá inmediatamente.
*
Si semval es distinto de cero y (sem_flg &IPC_NOWAIT) es 0, semop() incrementará el semzcnt asociado con el semáforo especificado y suspenderá la ejecución del hilo que llama hasta que ocurra una de las siguientes cosas:
--
El valor de semval se convierte en 0, momento en el cual el valor de semzcnt asociado con el semáforo especificado se decrementará.
--
El semid para el cual el hilo que llama está esperando una acción se elimina del sistema. Cuando esto ocurre, errno se establecerá en [EIDRM] y se devolverá -1.
--
El hilo que llama recibe una señal que debe ser capturada. Cuando esto ocurre, el valor de semzcnt asociado con el semáforo especificado se decrementará, y el hilo que llama reanudará la ejecución de la manera prescrita en sigaction().

Al completarse con éxito, el valor de sempid para cada semáforo especificado en el array apuntado por sops se establecerá en el ID de proceso del proceso que llama. Además, la marca de tiempo sem_otime se establecerá en la hora actual, como se describe en la Sección 2.7.1, Descripción General de IPC.

VALOR DEVUELTO

Al completarse con éxito, semop() devolverá 0; de lo contrario, devolverá -1 y establecerá errno para indicar el error.

ERRORES

La función semop() fallará si:

E2BIG
El valor de nsops es mayor que el máximo impuesto por el sistema.
EACCES
Se niega el permiso de operación al proceso que llama; consulte la Sección 2.7, Comunicación entre procesos XSI.
EAGAIN
La operación resultaría en la suspensión del proceso que llama, pero (sem_flg &IPC_NOWAIT) es distinto de cero.
EFBIG
El valor de sem_num es mayor o igual que el número de semáforos en el conjunto asociado con semid.
EIDRM
El identificador del semáforo semid se elimina del sistema.
EINTR
La función semop() fue interrumpida por una señal.
EINVAL
El valor de semid no es un identificador de semáforo válido, o el número de semáforos individuales para los que el proceso que llama solicita un SEM_UNDO excedería el límite impuesto por el sistema.
ENOSPC
Se excedería el límite en el número de procesos individuales que solicitan un SEM_UNDO.
ERANGE
Una operación causaría que un semval excediera el límite impuesto por el sistema, o una operación causaría que un valor semadj excediera el límite impuesto por el sistema.

NAME

semop, semtimedop — manipulate semaphores

SYNOPSIS

#include <sys/sem.h>
int semop(int semid, struct sembuf *sops, size_t nsops);
int semtimedop(int semid, struct sembuf *sops, size_t nsops,
               struct timespec *timeout);

DESCRIPTION

Semaphores are an IPC mechanism defined by POSIX.1 and are available on many UNIX systems. They are implemented using the System V IPC mechanisms (semget(2), semctl(2), and semop(2)).

A semaphore is a control structure, along with a unique identifier (a semaphore ID, semid), that contains a set of semaphores. A semaphore within this set is a simple integer value.

The semid argument is a semaphore identifier obtained via semget(2).

The sops argument points to an array of one or more semaphore operations to be performed. The array is described by the sembuf structure:

struct sembuf {
    unsigned short sem_num;  /* semaphore number */
    short          sem_op;   /* semaphore operation */
    short          sem_flg;  /* flags */
};
sem_num
Specifies the semaphore number within the set (starting from 0).
sem_op
Specifies the operation to perform on the semaphore identified by sem_num.
sem_op = 0
Check if the semaphore value is zero. This is used to wait for a semaphore to become zero. If the semaphore value is not zero, the process sleeps until the semaphore value becomes zero or until the call is interrupted.
sem_op > 0
Add sem_op to the semaphore value. This is used to release a resource. If sem_flg includes IPC_NOWAIT, and the semaphore value plus sem_op would exceed the system limit (SEMVMX), then semop() fails and sets errno to EAGAIN.
sem_op < 0
Subtract sem_op (a positive value) from the semaphore value. This is used to acquire a resource. If the semaphore value is less than the absolute value of sem_op, and IPC_NOWAIT is specified in sem_flg, then semop() fails and sets errno to EAGAIN. Otherwise, the calling process sleeps until the semaphore value is greater than or equal to the absolute value of sem_op, or until the call is interrupted.
sem_flg
Can be a bitwise OR of zero or more of the following flags:
IPC_NOWAIT
Do not wait for the operation to complete. If the operation cannot be performed immediately, semop() returns immediately with a return value of -1 and errno set to EAGAIN.
SEM_UNDO
Perform an automatic undo of the operation when the process terminates. The system maintains a table of undo information for each process. If SEM_UNDO is specified for an operation, the system adjusts the semaphore value by the negative of the sem_op value when the process exits. This is useful for ensuring that semaphores are always released, even if the program terminates abnormally. Multiple SEM_UNDO operations on the same semaphore in a single semop() call are not permitted.

The nsops argument specifies the number of elements in the array pointed to by sops.

semtimedop() is similar to semop(), but it allows specifying a timeout. If the requested operations cannot be completed within the specified timeout interval, the call fails and returns -1 with errno set to EAGAIN.

The timeout argument is a pointer to a timespec structure, specifying the number of seconds and nanoseconds to wait. If timeout is NULL, semtimedop() behaves like semop().

All operations within a single call to semop() or semtimedop() are performed atomically. If any operation in the request cannot be satisfied, no operations are performed. The system performs a maximum of NOGROUP (usually 16) operations per call.

The calling process must have read and write permissions on the semaphore set. The permissions are checked by semget(2).

RETURN VALUE

On success, semop() and semtimedop() return 0. On failure, they return -1 and set errno to indicate the error.

ERRORS

EAGAIN
IPC_NOWAIT was specified and the operation could not be completed immediately, or the timeout expired for semtimedop().
ECHILD
SEM_UNDO was specified and the process has no undo information.
EIDRM
The semaphore set was removed while processing the request.
EINTR
The call was interrupted by a signal.
EINVAL
Invalid semid or sem_num. SEM_UNDO was specified more than once for the same semaphore in a single call.
ENOMSG
Could not perform the requested operation (e.g., sem_op < 0 and the semaphore value is insufficient).
ENOSPC
SEM_UNDO was specified and the system-wide limit on undo entries has been reached.
ENOSYS
The function semtimedop() is not supported by the kernel.
EOVERFLOW
sem_op > 0 and the operation would cause the semaphore value to exceed the system limit SEMVMX.
EPERM
The calling process does not have permission to access the semaphore set.

EXAMPLES

Setting Values in Semaphores

The following example sets the values of the two semaphores associated with the semid identifier to the values contained in the sb array.

#include <sys/sem.h>
...
int semid;
struct sembuf sb[2];
int nsops = 2;
int result;
/* Code to initialize semid. */
...
/* Adjust value of semaphore in the semaphore array semid. */
sb[0].sem_num = 0;
sb[0].sem_op = -1;
sb[0].sem_flg = SEM_UNDO | IPC_NOWAIT;
sb[1].sem_num = 1;
sb[1].sem_op = 1;
sb[1].sem_flg = 0;
result = semop(semid, sb, nsops);

Creating a Semaphore Identifier

The following example gets a unique semaphore key using the ftok() function, then gets a semaphore ID associated with that key using the semget() function (the first call also tests to make sure the semaphore exists). If the semaphore does not exist, the program creates it, as shown by the second call to semget(). In creating the semaphore for the queuing process, the program attempts to create one semaphore with read/write permission for all. It also uses the IPC_EXCL flag, which forces semget() to fail if the semaphore already exists.

After creating the semaphore, the program uses calls to semctl() and semop() to initialize it to the values in the sbuf array. The number of processes that can execute concurrently without queuing is initially set to 2. The final call to semget() creates a semaphore identifier that can be used later in the program.

Processes that obtain semid without creating it check that sem_otime is non-zero, to ensure that the creating process has completed the semop() initialization.

The final call to semop() acquires the semaphore and waits until it is free; the SEM_UNDO option releases the semaphore when the process exits, waiting until there are less than two processes running concurrently.

#include <stdio.h>
#include <sys/sem.h>
#include <sys/stat.h>
#include <errno.h>
#include <stdlib.h>
...
key_t semkey;
int semid;
struct sembuf sbuf;
union semun {
    int val;
    struct semid_ds *buf;
    unsigned short *array;
} arg;
struct semid_ds ds;
...
/* Get unique key for semaphore. */
if ((semkey = ftok("/tmp", 'a')) == (key_t) -1) {
    perror("IPC error: ftok"); exit(1);
}
/* Get semaphore ID associated with this key. */
if ((semid = semget(semkey, 0, 0)) == -1) {
    /* Semaphore does not exist - Create. */
    if ((semid = semget(semkey, 1, IPC_CREAT | IPC_EXCL | S_IRUSR |
        S_IWUSR | S_IRGRP | S_IWGRP | S_IROTH | S_IWOTH)) != -1)
    {
        /* Initialize the semaphore. */
        arg.val = 0;
        sbuf.sem_num = 0;
        sbuf.sem_op = 2;  /* This is the number of runs without queuing. */
        sbuf.sem_flg = 0;
        if (semctl(semid, 0, SETVAL, arg) == -1
            || semop(semid, &sbuf, 1) == -1) {
            perror("IPC error: semop"); exit(1);
        }
    }
    else if (errno == EEXIST) {
        if ((semid = semget(semkey, 0, 0)) == -1) {
            perror("IPC error 1: semget"); exit(1);
        }
        goto check_init;
    }
    else {
        perror("IPC error 2: semget"); exit(1);
    }
}
else
{
    /* Check that semid has completed initialization. */
    /* An application can use a retry loop at this point rather than
       exiting. */
    check_init:
    arg.buf = &ds;
    if (semctl(semid, 0, IPC_STAT, arg) < 0) {
        perror("IPC error 3: semctl"); exit(1);
    }
    if (ds.sem_otime == 0) {
        perror("IPC error 4: semctl"); exit(1);
    }
}
...
sbuf.sem_num = 0;
sbuf.sem_op = -1;
sbuf.sem_flg = SEM_UNDO;
if (semop(semid, &sbuf, 1) == -1) {
    perror("IPC Error: semop"); exit(1);
}

APPLICATION USAGE

The POSIX Realtime Extension defines alternative interfaces for interprocess communication. Application developers who need to use IPC should design their applications so that modules using the IPC routines described in Section 2.7, XSI Interprocess Communication can be easily modified to use the alternative interfaces.
