SENDMAIL(1) Manual de comandos generales SENDMAIL(1)

NOMBRE

sendmail - Interfaz de compatibilidad de Postfix con Sendmail

SINOPSIS

sendmail [opción ...] [destinatario ...]
mailq
sendmail -bp
newaliases
sendmail -I

DESCRIPCIÓN


El comando sendmail(1) de Postfix implementa la interfaz de compatibilidad de Postfix con Sendmail. Por razones de compatibilidad con aplicaciones existentes, se reconocen algunas opciones de línea de comandos de Sendmail pero se ignoran silenciosamente.

Por defecto, el sendmail(1) de Postfix lee un mensaje de la entrada estándar hasta el final del archivo (EOF) o hasta que lee una línea con solo un carácter ., y organiza su entrega. El sendmail(1) de Postfix se basa en el comando postdrop(1) para crear un archivo de cola en el directorio maildrop.

Se proporcionan alias de comandos específicos para otros modos de operación comunes:

mailq
Lista la cola de correo. Cada entrada muestra el ID del archivo de cola, el tamaño del mensaje, la hora de llegada, el remitente y los destinatarios que aún necesitan ser entregados. Si el correo no pudo ser entregado en el último intento, se muestra la razón del fallo. La cadena del ID de cola va seguida de un carácter de estado opcional:
*
El mensaje está en la cola activa, es decir, el mensaje está seleccionado para su entrega.
!
El mensaje está en la cola de retención, es decir, no se volverá a intentar la entrega hasta que el correo se retire de la retención.
#
El mensaje se fuerza a expirar. Consulte las opciones -e o -f del postsuper(1).
Este modo de operación se implementa ejecutando el comando postqueue(1).
newaliases
Inicializa la base de datos de alias. Si no se especifica ningún archivo de entrada (con la opción -oA, ver más abajo), el programa procesa los archivos especificados con el parámetro de configuración alias_database. Si no se especifica ningún tipo de base de datos de alias, el programa utiliza el tipo especificado con el parámetro de configuración default_database_type. Este modo de operación se implementa ejecutando el comando postalias(1).

Nota: la actualización de una base de datos de alias puede tardar aproximadamente un minuto en ser visible. Utilice el comando "postfix reload" para eliminar este retraso.

Estas y otras características se pueden seleccionar especificando la combinación apropiada de opciones de línea de comandos. Algunas características se controlan mediante parámetros en el archivo de configuración main.cf.

Se reconocen las siguientes opciones:

-Am (ignorado)
-Ac (ignorado)
El sendmail de Postfix utiliza el mismo archivo de configuración independientemente de si un mensaje es una sumisión inicial o no.
-B tipo_cuerpo
El tipo MIME del cuerpo del mensaje: 7BIT u 8BITMIME.
-bd
Entrar en modo demonio. Este modo de operación se implementa ejecutando el comando "postfix start".
-bh (ignorado)
-bH (ignorado)
Postfix no tiene una base de datos de estado de host persistente.
-bi
Inicializar base de datos de alias. Consulte el comando newaliases anterior.
-bl
Entrar en modo demonio. Para aceptar solo conexiones locales, como con la opción -bl de Sendmail, especifique "inet_interfaces = loopback" en el archivo de configuración main.cf de Postfix.
-bm
Leer correo de la entrada estándar y organizar su entrega. Este es el modo de operación por defecto.
-bp
Listar la cola de correo. Consulte el comando mailq anterior.
-bs
Modo servidor SMTP independiente. Leer comandos SMTP de la entrada estándar y escribir respuestas en la salida estándar. En el modo servidor SMTP independiente, la retransmisión de correo y otros controles de acceso están desactivados por defecto. Para habilitarlos, ejecute el proceso como el usuario mail_owner.

Este modo de operación se implementa ejecutando el demonio smtpd(8).

-bv
No recopilar ni entregar un mensaje. En su lugar, enviar un informe por correo después de verificar cada dirección de destinatario. Esto es útil para probar la reescritura de direcciones y las configuraciones de enrutamiento.

Esta característica está disponible en Postfix versión 2.1 y posteriores.

-C archivo_configuración
-C directorio_configuración
La ruta del archivo main.cf de Postfix, o de su directorio padre. Esta información se ignora en las versiones de Postfix anteriores a la 2.3.

Con las versiones 3.2 y posteriores de Postfix, un directorio no predeterminado debe estar autorizado en el archivo main.cf predeterminado, a través de los parámetros alternate_config_directories o multi_instance_directories.

Con todas las versiones de Postfix, puede especificar una ruta de directorio con la variable de entorno MAIL_CONFIG para anular la ubicación de los archivos de configuración.

-F nombre_completo
Establece el nombre completo del remitente. Esto anula la variable de entorno NAME y solo se utiliza con mensajes que no tienen una cabecera de mensaje From:.
-f remitente
Establece la dirección del remitente del sobre. Esta es la dirección a la que se envían los problemas de entrega. Con las versiones de Postfix anteriores a la 2.1, la cabecera del mensaje Errors-To: anula la dirección de retorno de errores.
-G
Envío de puerta de enlace (retransmisión), en contraposición al envío de usuario inicial. No reescribir las direcciones en absoluto, o actualizar las direcciones incompletas con la información del dominio especificada con remote_header_rewrite_domain.

Esta opción se ignora antes de la versión 2.3 de Postfix.

-h recuento_saltos (ignorado)
Límite de recuento de saltos. Utilice el parámetro de configuración hopcount_limit en su lugar.
-I
Inicializar base de datos de alias. Consulte el comando newaliases anterior.
-i
Al leer un mensaje de la entrada estándar, no tratar una línea con solo un carácter . como el final de la entrada.
-L etiqueta (ignorado)
La etiqueta de registro. Utilice el parámetro de configuración syslog_name en su lugar.
-m (ignorado)
Compatibilidad hacia atrás.
-N dsn (predeterminado: 'delay, failure')
Control de notificación de estado de entrega. Especifique una lista separada por comas con uno o más de failure (enviar notificación cuando la entrega falla), delay (enviar notificación cuando la entrega se retrasa) o success (enviar notificación cuando el mensaje se entrega); o especifique never (no enviar ninguna notificación en absoluto).

Esta característica está disponible en Postfix 2.3 y posteriores.

-n (ignorado)
Compatibilidad hacia atrás.
-oAbase_datos_alias
Base de datos de alias no predeterminada. Especifique ruta o tipo:ruta. Consulte postalias(1) para obtener más detalles.
-O opción=valor (ignorado)
Establece la opción nombrada a valor. Utilice el parámetro de configuración equivalente en main.cf en su lugar.
-o7 (ignorado)
-o8 (ignorado)
Para enviar contenido de 8 bits o binario, utilice un apropiado

OPTIONS

-B mtype
Specify the MIME encapsulation type for the message body. The valid types are: "text", "html" and "mixed". If the message body is not specified with the -b command line option, then Postfix will determine the content type from the message headers. See also the -b option below.
-b format
Specify the message body format. The valid formats are: "ascii" (default), "822", "mixed", "single" and "utf8".

The "ascii" format supports only 7-bit ASCII characters.

The "822" format supports only 7-bit ASCII characters, and expects the message to be RFC 822 compliant.

The "mixed" format supports 8-bit content, and will try to determine the appropriate MIME encapsulation type for the message body. See also the -B option above.

The "single" format supports 8-bit content, and will use the specified MIME encapsulation type for the message body. See also the -B option above.

The "utf8" format supports 8-bit content, and will use UTF-8 encoding for the message body.

When using the "mixed" or "single" formats, you may need to specify the appropriate MIME encapsulation type with the -B command-line option.

-c config_dir
Use specified config_dir for the Postfix configuration files. The default configuration directory is /etc/postfix/.
-D debugger_command (ignored)
Run with debugger_command. Use the debugger_command configuration parameter instead.
-e
Exit successfully after processing the mail queue. This is the default behavior when the command is not invoked with the -o option.
-F sender_name
Set the sender's real name. This is used only when no From: message header is present. See also the NAME environment variable.
-h
Send a report on the first delivery attempt for each recipient. This is the default behavior. See also the -v option.
-i
Ignore the sender address in the message envelope. This is intended for use with the sendmail command.
-m
Disable alias and \"~/.forward\" file expansion. This is intended for use with the sendmail command.
-M template
Use the specified template for generating delivery status notifications. The available templates are: "full", "hdr" and "off". "full" includes the entire message, "hdr" includes only the headers, and "off" disables notifications.
-o option=value
Overrides a specific configuration parameter. Use the equivalent configuration parameter in main.cf instead.
-oi
When reading a message from standard input, don't treat a line with only a . character as the end of input.
-om (ignored)
The sender is never eliminated from alias etc. expansions.
-o x value (ignored)
Set option x to value. Use the equivalent configuration parameter in main.cf instead.
-r sender
Set the envelope sender address. This is the address where delivery problems are sent to. With Postfix versions before 2.1, the Errors-To: message header overrides the error return address.
-R return
Delivery status notification control. Specify "hdrs" to return only the header when a message bounces, "full" to return a full copy (the default behavior).

The -R option specifies an upper bound; Postfix will return only the header, when a full copy would exceed the bounce_size_limit setting.

This option is ignored before Postfix version 2.10.

-q
Attempt to deliver all queued mail. This is implemented by executing the postqueue(1) command.

Warning: flushing undeliverable mail frequently will result in poor delivery performance of all other mail.

-qinterval (ignored)
The interval between queue runs. Use the queue_run_delay configuration parameter instead.
-qIqueueid
Schedule immediate delivery of mail with the specified queue ID. This option is implemented by executing the postqueue(1) command, and is available with Postfix version 2.4 and later.
-qRsite
Schedule immediate delivery of all mail that is queued for the named site. This option accepts only site names that are eligible for the "fast flush" service, and is implemented by executing the postqueue(1) command. See flush(8) for more information about the "fast flush" service.
-qSsite
This command is not implemented. Use the slower "sendmail -q" command instead.
-t
Extract recipients from message headers. These are added to any recipients specified on the command line.

With Postfix versions prior to 2.1, this option requires that no recipient addresses are specified on the command line.

-U (ignored)
Initial user submission.
-V envid
Specify the envelope ID for notification by servers that support DSN.

This feature is available in Postfix 2.3 and later.

-XV (Postfix 2.2 and earlier: -V)
Variable Envelope Return Path. Given an envelope sender address of the form owner-listname@origin, each recipient user@domain receives mail with a personalized envelope sender address.

By default, the personalized envelope sender address is owner-listname+user=domain@origin. The default + and = characters are configurable with the default_verp_delimiters configuration parameter.

-XVxy (Postfix 2.2 and earlier: -Vxy)
As -XV, but uses x and y as the VERP delimiter characters, instead of the characters specified with the default_verp_delimiters configuration parameter.
-v
Send an email report of the first delivery attempt (Postfix versions 2.1 and later). Mail delivery always happens in the background. When multiple -v options are given, enable verbose logging for debugging purposes.
-X log_file (ignored)
Log mailer traffic. Use the debug_peer_list and debug_peer_level configuration parameters instead.

SEGURIDAD

Por diseño, este programa no tiene el id de usuario (o grupo) establecido. Está preparado para manejar contenido de mensajes de usuarios no confiables, posiblemente remotos.

Sin embargo, como la mayoría de los programas de Postfix, este programa no hace cumplir una política de seguridad en sus argumentos de línea de comandos. En su lugar, se basa en el sistema UNIX para hacer cumplir las políticas de acceso basadas en los IDs de usuario y grupo efectivos del proceso. Concretamente, esto significa que ejecutar comandos de Postfix como root (desde sudo o equivalente) en nombre de un usuario que no es root probablemente creará oportunidades de escalada de privilegios.

Si una aplicación ejecuta programas de Postfix en nombre de usuarios que no tienen acceso normal al shell a los comandos de Postfix, esa aplicación DEBE restringir los argumentos de línea de comandos especificados por el usuario para evitar la escalada de privilegios.

  • Filtre todos los argumentos de la línea de comandos, por ejemplo, argumentos que contengan una ruta de archivo o que especifiquen un método de acceso a la base de datos. Estas comprobaciones de ruta de archivo deben rechazar enlaces simbólicos o enlaces duros controlados por el usuario a archivos sensibles y no deben ser vulnerables a ataques de carrera TOCTOU.
  • Deshabilite el procesamiento de opciones de comandos para todos los argumentos de comandos que contengan datos especificados por el usuario. Por ejemplo, la línea de comandos de Postfix sendmail(1) DEBE estructurarse de la siguiente manera: 
        /ruta/a/sendmail argumentos-del-sistema -- argumentos-del-usuario

    Aquí, el "--" deshabilita el procesamiento de opciones de comandos para todos los argumentos-del-usuario que siguen.

Sin el "--", un usuario malintencionado podría habilitar las opciones del comando sendmail(1) de Postfix, al especificar una dirección de correo electrónico que comience con "-".

DIAGNÓSTICOS


Los problemas se registran en syslogd(8) o postlogd(8), y en el flujo de error estándar.

ENTORNO

MAIL_CONFIG
Directorio con los archivos de configuración de Postfix.
MAIL_VERBOSE (el valor no importa)
Habilita el registro detallado con fines de depuración.
MAIL_DEBUG (el valor no importa)
Habilita la depuración con un comando externo, según lo especificado con el parámetro de configuración debugger_command.
NAME
El nombre completo del remitente. Esto solo se usa con mensajes que no tienen una cabecera de mensaje From:. Consulte también la opción -F anterior.

PARÁMETROS DE CONFIGURACIÓN

Los siguientes parámetros de main.cf son especialmente relevantes para este programa. El texto a continuación solo proporciona un resumen de los parámetros. Consulte postconf(5) para obtener más detalles, incluidos ejemplos.

CONTROLES DE COMPATIBILIDAD

Disponible con Postfix 2.9 y posteriores:

sendmail_fix_line_endings (siempre)
Controla cómo el comando sendmail de Postfix convierte los finales de línea de los mensajes de correo electrónico de <CR><LF> al formato UNIX (<LF>).

CONTROLES DE RESOLUCIÓN DE PROBLEMAS

El archivo DEBUG_README proporciona ejemplos de cómo solucionar problemas de un sistema Postfix.

debugger_command (vacío)
El comando externo a ejecutar cuando un programa daemon de Postfix se invoca con la opción -D.
debug_peer_level (2)
El incremento en el nivel de registro detallado cuando un destino nexthop, nombre de cliente o servidor remoto o dirección de red coincide con un patrón dado con el parámetro debug_peer_list.
debug_peer_list (vacío)
Lista opcional de patrones de destino nexthop, nombre de cliente o servidor remoto o dirección de red que, si coinciden, hacen que el nivel de registro detallado aumente en la cantidad especificada en $debug_peer_level.

CONTROLES DE ACCESO

Disponible en Postfix versión 2.2 y posteriores:

authorized_flush_users (estático: cualquiera)
Lista de usuarios autorizados a vaciar la cola.
authorized_mailq_users (estático: cualquiera)
Lista de usuarios autorizados a ver la cola.
authorized_submit_users (estático: cualquiera)
Lista de usuarios autorizados a enviar correo con el comando sendmail(1) (y con el comando auxiliar privilegiado postdrop(1)).

CONTROLES DE RECURSOS Y TASAS

bounce_size_limit (50000)
La cantidad máxima de texto del mensaje original que se envía en una notificación de no entrega.

TROUBLE SHOOTING CONTROLS

fork_attempts (5)
El número máximo de intentos para crear un proceso hijo con fork().
fork_delay (1s)
El retraso entre intentos de crear un proceso hijo con fork().
hopcount_limit (50)
El número máximo de encabezados de mensaje Received: que se permiten en los encabezados del mensaje principal.
queue_run_delay (300s)
El tiempo entre escaneos de colas diferidas por el gestor de colas; antes de Postfix 2.4, el valor predeterminado era 1000s.

CONTROLES DE FLUSH RÁPIDO

El archivo ETRN_README describe los detalles de configuración y operación del servicio de "flush rápido" de Postfix.

fast_flush_domains ($relay_domains)
Lista opcional de destinos que son elegibles para archivos de registro por destino con correo que se pone en cola para esos destinos.

CONTROLES VERP

El archivo VERP_README describe los detalles de configuración y operación del soporte de Postfix para direcciones de ruta de retorno de sobre variables.

default_verp_delimiters (+=)
Los dos caracteres delimitadores VERP predeterminados.
verp_delimiter_filter (-=+)
Los caracteres que Postfix acepta como caracteres delimitadores VERP en la línea de comandos de sendmail(1) de Postfix y en los comandos SMTP.

CONTROLES MISCELÁNEOS

alias_database (ver la salida de 'postconf -d')
Las bases de datos de alias para la entrega de local(8) que se actualizan con "newaliases" o con "sendmail -bi".
command_directory (ver la salida de 'postconf -d')
La ubicación de todos los comandos administrativos de postfix.
config_directory (ver la salida de 'postconf -d')
La ubicación predeterminada de los archivos de configuración main.cf y master.cf de Postfix.
daemon_directory (ver la salida de 'postconf -d')
El directorio con los programas de soporte y los programas demonio de Postfix.
default_database_type (ver la salida de 'postconf -d')
El tipo de base de datos predeterminado para usar en los comandos newaliases(1), postalias(1) y postmap(1).
delay_warning_time (0h)
El tiempo después del cual el remitente recibe una copia de los encabezados del mensaje del correo que todavía está en cola.
import_environment (ver la salida de 'postconf -d')
La lista de variables de entorno que un proceso privilegiado de Postfix importará de un proceso padre que no sea de Postfix, o anulaciones de entorno nombre=valor.
mail_owner (postfix)
La cuenta del sistema UNIX que posee la cola de Postfix y la mayoría de los procesos demonio de Postfix.
queue_directory (ver la salida de 'postconf -d')
La ubicación del directorio de cola de nivel superior de Postfix.
remote_header_rewrite_domain (vacío)
Reescribe o agrega encabezados de mensaje en el correo de clientes remotos si el valor del parámetro remote_header_rewrite_domain no está vacío, actualizando direcciones incompletas con el dominio especificado en el parámetro remote_header_rewrite_domain, y agregando encabezados que faltan.
syslog_facility (mail)
La instalación de syslog del registro de Postfix.
syslog_name (ver la salida de 'postconf -d')
Un prefijo que se antepone al nombre del proceso en los registros de syslog, de modo que, por ejemplo, "smtpd" se convierte en "prefix/smtpd".

Postfix 3.2 y posterior:

alternate_config_directories (vacío)
Una lista de directorios de configuración de Postfix no predeterminados que pueden especificarse con "-c config_directory" en la línea de comandos (en el caso de sendmail(1), con la opción "-C"), o a través del parámetro de entorno MAIL_CONFIG.
multi_instance_directories (vacío)
Una lista opcional de directorios de configuración de Postfix no predeterminados; estos directorios pertenecen a instancias adicionales de Postfix que comparten los archivos ejecutables y la documentación de Postfix con la instancia predeterminada de Postfix, y que se inician, detienen, etc., junto con la instancia predeterminada de Postfix.
