NOMBRE

seccomp_rule_add, seccomp_rule_add_exact - Añadir una regla de filtro seccomp

SINOPSIS

#include <seccomp.h>

typedef void * scmp_filter_ctx;

int SCMP_SYS(nombre_llamada_sistema);

struct scmp_arg_cmp SCMP_CMP(unsigned int arg,
                             enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A0(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A1(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A2(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A3(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A4(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A5(enum scmp_compare op, ...);

struct scmp_arg_cmp SCMP_CMP64(unsigned int arg,
                             enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A0_64(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A1_64(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A2_64(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A3_64(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A4_64(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A5_64(enum scmp_compare op, ...);

struct scmp_arg_cmp SCMP_CMP32(unsigned int arg,
                             enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A0_32(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A1_32(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A2_32(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A3_32(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A4_32(enum scmp_compare op, ...);
struct scmp_arg_cmp SCMP_A5_32(enum scmp_compare op, ...);

int seccomp_rule_add(scmp_filter_ctx ctx, uint32_t accion,
                     int syscall, unsigned int arg_cnt, ...);
int seccomp_rule_add_exact(scmp_filter_ctx ctx, uint32_t accion,
                           int syscall, unsigned int arg_cnt, ...);

int seccomp_rule_add_array(scmp_filter_ctx ctx,
                           uint32_t accion, int syscall,
                           unsigned int arg_cnt,
                           const struct scmp_arg_cmp *array_arg);
int seccomp_rule_add_exact_array(scmp_filter_ctx ctx,
                                 uint32_t accion, int syscall,
                                 unsigned int arg_cnt,
                                 const struct scmp_arg_cmp *array_arg);

Enlaza con -lseccomp.

DESCRIPCIÓN

Las funciones seccomp_rule_add(), seccomp_rule_add_array(), seccomp_rule_add_exact() y seccomp_rule_add_exact_array() añaden una nueva regla de filtro al filtro seccomp actual. Las funciones seccomp_rule_add() y seccomp_rule_add_array() harán un "esfuerzo máximo" para añadir la regla como se especifica, pero pueden alterar ligeramente la regla debido a especificidades de la arquitectura (por ejemplo, reescritura interna de llamadas al sistema multiplexadas, como las funciones socket e ipc en x86). Las funciones seccomp_rule_add_exact() y seccomp_rule_add_exact_array() intentarán añadir la regla exactamente como se especifica, por lo que pueden comportarse de manera diferente en distintas arquitecturas. Aunque no garantiza un conjunto de reglas de filtro exacto, seccomp_rule_add() y seccomp_rule_add_array() garantizan el mismo comportamiento independientemente de la arquitectura.

La nueva regla de filtro añadida no surtirá efecto hasta que todo el filtro se cargue en el kernel usando seccomp_load(3). Al añadir reglas a un filtro, es importante considerar el impacto de los filtros cargados previamente; véase la documentación de seccomp_load(3) para más información.

Todas las reglas de filtro proporcionadas por la aplicación llamante se combinan en una unión, con lógica adicional para eliminar filtros de llamadas al sistema redundantes. Por ejemplo, si se añade una regla que permite una llamada al sistema dada con un conjunto específico de valores de argumentos y posteriormente se añade una regla que permite la misma llamada al sistema independientemente de los valores de los argumentos, la primera regla, más específica, se elimina efectivamente del filtro por la segunda regla, más genérica.

Las macros SCMP_CMP(), SCMP_CMP64(), SCMP_A{0-5}(), y SCMP_A{0-5}_64() generan una estructura scmp_arg_cmp para su uso con las funciones anteriores. Las macros SCMP_CMP() y SCMP_CMP64() permiten al llamante especificar un argumento arbitrario junto con el operador de comparación, máscara de 64 bits y valores de datos, mientras que las macros SCMP_A{0-5}() y SCMP_A{0-5}_64() son específicas para un argumento determinado.

Las macros SCMP_CMP32() y SCMP_A{0-5}_32() son similares a las variantes anteriores, pero toman máscaras de 32 bits y valores de datos de 32 bits.

Se recomienda que, siempre que sea posible, los desarrolladores eviten usar las macros SCMP_CMP() y SCMP_A{0-5}() y utilicen las variantes que sean explícitamente de 32 o 64 bits. Esto debería ayudar a eliminar problemas causados por una extensión de signo no deseada de valores negativos.

Si se incluyen comparaciones de argumentos de llamadas al sistema en la regla de filtro, todas las comparaciones deben ser verdaderas para que la regla coincida.

Al añadir comparaciones de argumentos de llamadas al sistema al filtro, es importante recordar que, aunque es posible tener múltiples comparaciones en una sola regla, solo se puede comparar cada argumento una vez en una sola regla. En otras palabras, no se pueden tener múltiples comparaciones del 3er argumento de la llamada al sistema en una sola regla.

En un filtro que contiene múltiples arquitecturas, es un error añadir una regla de filtro para una llamada al sistema que no existe en todas las arquitecturas del filtro.

Si bien es posible especificar el valor syscall directamente utilizando los valores estándar __NR_syscall, para garantizar el correcto funcionamiento en múltiples arquitecturas se recomienda encarecidamente usar la macro SCMP_SYS() en su lugar. Véase la sección EJEMPLOS más abajo. También es importante recordar que, independientemente de las arquitecturas presentes en el filtro, los números de llamada al sistema utilizados en las reglas de filtro se interpretan en el contexto de la arquitectura nativa.

A partir de Linux v4.8, puede ser necesario crear una regla con un valor de llamada al sistema de -1 para permitir que los programas de rastreo omitan una invocación de llamada al sistema; para crear una regla con un valor de llamada al sistema de -1, es necesario primero establecer el atributo SCMP_FLTATR_API_TSKIP. Véase seccomp_attr_set(3) para más información.

El contexto del filtro ctx es el valor devuelto por la llamada a seccomp_init(3).

Los valores válidos de action son los siguientes:

SCMP_ACT_KILL
El hilo será terminado por el kernel cuando llame a una llamada al sistema que coincida con la regla de filtro.
SCMP_ACT_KILL_PROCESS
El proceso será terminado por el kernel cuando llame a una llamada al sistema que coincida con la regla de filtro.
SCMP_ACT_TRAP
El hilo lanzará una señal SIGSYS cuando llame a una llamada al sistema que coincida con la regla de filtro.
SCMP_ACT_ERRNO(uint16_t errno)
El hilo recibirá un valor de retorno de errno cuando llame a una llamada al sistema que coincida con la regla de filtro.
SCMP_ACT_TRACE(uint16_t msg_num)
Si el hilo está siendo rastreado y el proceso de rastreo especificó la opción PTRACE_O_TRACESECCOMP en la llamada a ptrace(2), el proceso de rastreo será notificado, a través de PTRACE_EVENT_SECCOMP, y el valor proporcionado en msg_num puede ser recuperado usando la opción PTRACE_GETEVENTMSG.
SCMP_ACT_LOG
Si el registro del kernel está habilitado, la llamada al sistema se registrará en el registro del kernel.

El parámetro syscall es el número de la llamada al sistema a filtrar. Se recomienda el uso de la macro SCMP_SYS() para la portabilidad entre arquitecturas.

El parámetro arg_cnt es el número de comparaciones de argumentos que siguen en la lista de argumentos variable. Si no hay comparaciones de argumentos, este valor debe ser 0.

Los argumentos variables son estructuras scmp_arg_cmp generadas por las macros SCMP_CMP, SCMP_CMP64, SCMP_CMP32, SCMP_A{0-5}, SCMP_A{0-5}_64 y SCMP_A{0-5}_32.

En el caso de las funciones seccomp_rule_add_array y seccomp_rule_add_exact_array, el argumento arg_array es un puntero a un array de estructuras scmp_arg_cmp que describe las comparaciones de argumentos a realizar.

Los valores válidos para el campo op dentro de struct scmp_arg_cmp son:

SCMP_CMP_NEQ
No igual.
SCMP_CMP_EQ
Igual.
SCMP_CMP_LT
Menor que.
SCMP_CMP_LE
Menor o igual que.
SCMP_CMP_GT
Mayor que.
SCMP_CMP_GE
Mayor o igual que.
SCMP_CMP_MASKED_EQ
Igual con máscara.

Los campos mask y data dentro de struct scmp_arg_cmp contienen la máscara y el valor a comparar para el argumento de la llamada al sistema especificado.

Las macros SCMP_CMP64, SCMP_A{0-5}_64, SCMP_CMP32, y SCMP_A{0-5}_32 especifican explícitamente si se debe utilizar una máscara y un valor de 64 bits o de 32 bits. Si no se especifica, las macros SCMP_CMP y SCMP_A{0-5} intentarán inferir el tamaño correcto basándose en la arquitectura, pero se recomienda el uso de las variantes explícitas para evitar la extensión de signo de valores negativos.

El campo arg en SCMP_CMP, SCMP_CMP64 y SCMP_CMP32 especifica qué argumento de la llamada al sistema se está comparando (0 para el primer argumento, 1 para el segundo, etc.). Las macros SCMP_A{0-5}, SCMP_A{0-5}_64 y SCMP_A{0-5}_32 son atajos para comparar los primeros seis argumentos.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven el número de reglas de filtro que se han añadido al contexto del filtro. En caso de error, devuelven -1 y el número de error apropiado se establece en la variable global errno.

ERRORES

EINVAL
El contexto del filtro es inválido, o la acción especificada es inválida, o el número de argumentos es incorrecto.
ENOMEM
No hay suficiente memoria disponible para añadir la regla de filtro.
ENOSYS
El número de llamada al sistema especificado no existe en la arquitectura actual o se está intentando añadir una regla de filtro que no es válida para todas las arquitecturas especificadas en el contexto del filtro.
ENOTSUP
La acción especificada no está soportada por la versión actual del kernel.

EJEMPLO

#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
#include <seccomp.h>

int
main(int argc, char **argv)
{
	scmp_filter_ctx ctx;
	int ret;

	// Inicializar el contexto del filtro con las acciones predeterminadas
	// (permitir todo)
	ctx = seccomp_init(SCMP_ACT_ALLOW);
	if (ctx == NULL) {
		fprintf(stderr, "Error al inicializar el contexto de seccomp.\n");
		return 1;
	}

	// Añadir una regla para permitir la llamada al sistema 'write'
	ret = seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(write), 0);
	if (ret < 0) {
		fprintf(stderr, "Error al añadir la regla de seccomp: %d\n", ret);
		seccomp_release(ctx);
		return 1;
	}

	// Añadir una regla para denegar explícitamente la llamada al sistema
	// 'fork'
	ret = seccomp_rule_add(ctx, SCMP_ACT_KILL, SCMP_SYS(fork), 0);
	if (ret < 0) {
		fprintf(stderr, "Error al añadir la regla de seccomp: %d\n", ret);
		seccomp_release(ctx);
		return 1;
	}

	// Añadir una regla para permitir la llamada al sistema 'read' sólo
	// si el primer argumento (fd) es mayor o igual a 3 (stdout)
	ret = seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(read),
			       1, SCMP_CMP(0, SCMP_CMP_GE, 3));
	if (ret < 0) {
		fprintf(stderr, "Error al añadir la regla de seccomp: %d\n", ret);
		seccomp_release(ctx);
		return 1;
	}

	// Cargar el filtro en el kernel
	ret = seccomp_load(ctx);
	if (ret < 0) {
		fprintf(stderr, "Error al cargar el filtro de seccomp: %d\n", ret);
		seccomp_release(ctx);
		return 1;
	}

	printf("Filtro seccomp cargado con éxito.\n");

	// Liberar el contexto del filtro
	seccomp_release(ctx);

	return 0;
}

seccomp_rule_add_array(3) — libseccomp

NAME

seccomp_rule_add_array, seccomp_rule_add_exact_array - add a seccomp filter rule

SYNOPSIS

int seccomp_rule_add_array(scmp_filter_ctx *ctx, uint32_t action, int syscall, unsigned int arg_cnt, ...)

int seccomp_rule_add_exact_array(scmp_filter_ctx *ctx, uint32_t action, int syscall, unsigned int arg_cnt, ...)

DESCRIPTION

The seccomp_rule_add_array() and seccomp_rule_add_exact_array() functions are used to add a new seccomp filter rule to the seccomp filter context specified by ctx. The new rule is associated with the seccomp system call syscall and will take the specified action when triggered. The rule is defined by arg_cnt argument clauses, followed by the argument clauses themselves. The argument clauses are specified as a variable argument list. Each argument clause is defined using one of the SCMP_A* macros. These macros allow for the specification of seccomp arguments, arguments that are compared against a specific value using one of the SCMP_CMP* operators.

The seccomp_rule_add_array() and seccomp_rule_add_exact_array() functions differ in how they handle the comparison of arguments. The exact comparison of arguments is enforced by seccomp_rule_add_exact_array(), while seccomp_rule_add_array() allows for more flexible comparisons.

Valid action values are as follows:

SCMP_ACT_LOG
The seccomp filter will have no effect on the thread calling the syscall if it matches the filter rule but the syscall will be logged.
SCMP_ACT_ALLOW
The seccomp filter will have no effect on the thread calling the syscall if it matches the filter rule.
SCMP_ACT_NOTIFY
A monitoring process will be notified when a process running the seccomp filter calls a syscall that matches the filter rule. The process that invokes the syscall waits in the kernel until the monitoring process has responded via seccomp_notify_respond (3) .

When a filter utilizing SCMP_ACT_NOTIFY is loaded into the kernel, the kernel generates a notification fd that must be used to communicate between the monitoring process and the process(es) being filtered. See seccomp_notif_fd (3) for more information.

Valid comparison op values are as follows:

SCMP_CMP_NE
Matches when the argument value is not equal to the datum value, example:

SCMP_CMP( arg , SCMP_CMP_NE , datum )

SCMP_CMP_LT
Matches when the argument value is less than the datum value, example:

SCMP_CMP( arg , SCMP_CMP_LT , datum )

SCMP_CMP_LE
Matches when the argument value is less than or equal to the datum value, example:

SCMP_CMP( arg , SCMP_CMP_LE , datum )

SCMP_CMP_EQ
Matches when the argument value is equal to the datum value, example:

SCMP_CMP( arg , SCMP_CMP_EQ , datum )

SCMP_CMP_GE
Matches when the argument value is greater than or equal to the datum value, example:

SCMP_CMP( arg , SCMP_CMP_GE , datum )

SCMP_CMP_GT
Matches when the argument value is greater than the datum value, example:

SCMP_CMP( arg , SCMP_CMP_GT , datum )

SCMP_CMP_MASKED_EQ
Matches when the masked argument value is equal to the masked datum value, example:

SCMP_CMP( arg , SCMP_CMP_MASKED_EQ , mask , datum )

RETURN VALUE

The SCMP_SYS() macro returns a value suitable for use as the syscall value in the seccomp_rule_add*() functions. In a similar manner, the SCMP_CMP() and SCMP_A*() macros return values suitable for use as argument comparisons in the seccomp_rule_add() and seccomp_rule_add_exact() functions.

The seccomp_rule_add(), seccomp_rule_add_array(), seccomp_rule_add_exact(), and seccomp_rule_add_exact_array() functions return zero on success or one of the following error codes on failure:

-EDOM
Fallo específico de la arquitectura.
-EEXIST
La regla ya existe.
-EACCCES
La regla entra en conflicto con el filtro (por ejemplo, la acción de la regla es igual a la acción predeterminada del filtro).
-EFAULT
Fallo interno de libseccomp.
-EINVAL
Entrada inválida, ya sea que el contexto o el token de arquitectura no sean válidos.
-ENOMEM
La biblioteca no pudo asignar suficiente memoria.
-EOPNOTSUPP
La biblioteca no soporta la operación en particular.

EXAMPLES

#include <fcntl.h>
#include <seccomp.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <stddef.h>
#define BUF_SIZE	256
int main(int argc, char *argv[])
{
	int rc = -1;
	scmp_filter_ctx ctx;
	struct scmp_arg_cmp arg_cmp[] = { SCMP_A0(SCMP_CMP_EQ, 2) };
	int fd;
	unsigned char buf[BUF_SIZE];
	ctx = seccomp_init(SCMP_ACT_KILL);
	if (ctx == NULL)
		goto out;
	/* ... */
	fd = open("file.txt", 0);
	/* ... */
	rc = seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(close), 0);
	if (rc < 0)
		goto out;
	rc = seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(exit_group), 0);
	if (rc < 0)
		goto out;
	rc = seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(exit), 0);
	if (rc < 0)
		goto out;
	rc = seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(read), 3,
			      SCMP_A0(SCMP_CMP_EQ, fd),
			      SCMP_A1(SCMP_CMP_EQ, (scmp_datum_t)buf),
			      SCMP_A2(SCMP_CMP_LE, BUF_SIZE));
	if (rc < 0)
		goto out;
	rc = seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(write), 1,
			      SCMP_CMP(0, SCMP_CMP_EQ, fd));
	if (rc < 0)
		goto out;
	rc = seccomp_rule_add_array(ctx, SCMP_ACT_ALLOW, SCMP_SYS(write), 1,
			            arg_cmp);
	if (rc < 0)
		goto out;
	rc = seccomp_load(ctx);
	if (rc < 0)
		goto out;
	/* ... */
out:
	seccomp_release(ctx);
	return -rc;
}

NOTES

Aunque el filtro seccomp puede generarse independientemente del kernel, se requiere soporte del kernel para cargar y aplicar el filtro seccomp generado por libseccomp.

El sitio del proyecto libseccomp, con más información y el repositorio de código fuente, se puede encontrar en https://github.com/seccomp/libseccomp. Esta herramienta, así como la biblioteca libseccomp, se encuentra actualmente en desarrollo, por favor reporte cualquier error en el sitio del proyecto o directamente al autor.

BUGS

El comportamiento en tiempo de ejecución de los filtros seccomp depende de la versión del kernel, la arquitectura del procesador y otras bibliotecas, incluyendo libc. Esto podría afectar el código de retorno de un filtro seccomp.

*
PowerPC glibc no devolverá un número negativo cuando se invoque la llamada al sistema getpid(). Si se ha creado un filtro seccomp donde getpid() devolverá un número negativo desde el kernel, entonces PowerPC glibc devolverá el valor absoluto del errno. En este caso, es muy difícil para una aplicación distinguir entre el errno y un pid válido.
