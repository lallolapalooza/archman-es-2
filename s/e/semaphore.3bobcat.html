FBB::Semaphore(3bobcat) Semáforo de Dijkstra FBB::Semaphore(3bobcat)

NOMBRE

FBB::Semaphore - Implementa el tipo Semáforo diseñado por Dijkstra

SINOPSIS

#include <bobcat/semaphore>

Opción de enlace: -lpthread -lbobcat

DESCRIPCIÓN

Según http://en.wikipedia.org/wiki/Semaphore_(programming), un semáforo es una variable o tipo de dato abstracto que se utiliza para controlar el acceso, por múltiples procesos, a un recurso común en un entorno de programación paralela o multiusuario. El Semaphore como tipo de dato fue diseñado alrededor de 1962 por Edsger Dijkstra.

Una forma útil de pensar en un semáforo es como un registro de cuántas unidades de un recurso particular están disponibles, junto con operaciones para ajustar de forma segura (es decir, sin condiciones de carrera) ese registro a medida que las unidades se requieren o quedan libres y, si es necesario, esperar hasta que una unidad del recurso esté disponible.

Los semáforos son una herramienta útil para la prevención de condiciones de carrera. Los semáforos que permiten un recuento arbitrario de recursos se denominan semáforos contadores, mientras que los semáforos restringidos a los valores 0 y 1 (o bloqueado/desbloqueado, no disponible/disponible) se denominan semáforos binarios. Ambos tipos son compatibles con la implementación de Bobcat.

CONSTRUCTORES

o
Semaphore(size_t nAvailable):
El constructor define el estado inicial del semáforo. Con un semáforo contador, nAvailable define, por ejemplo, el número de ubicaciones disponibles en un área de almacenamiento. El bloqueo/desbloqueo, el soporte de instalaciones para notificar a otros hilos en espera se implementa a través de semáforos binarios, que se inicializan a 1 o 0. Un semáforo que contiene el valor 0 bloquea. Es decir, su miembro wait espera hasta que su valor sea incrementado por otro hilo, llamando a uno de los miembros notify del semáforo.

Los constructores de copia y movimiento (y los operadores de asignación) no están disponibles.

FUNCIONES MIEMBRO

o
void notify():
El valor available mantenido internamente se incrementa y se notifica a un hilo en espera (ver los miembros wait a continuación), reactivando ese hilo.
o
void notify_all():
El valor available mantenido internamente se incrementa y se notifican todos los hilos en espera (ver los miembros wait a continuación). Solo un hilo en espera podrá obtener el bloqueo del semáforo y reducir available, y ese hilo en particular será reactivado.
o
void set(size_t available):
Este miembro se bloquea hasta que ha obtenido el bloqueo del std::mutex que se mantiene internamente en el objeto Semaphore. A continuación, el valor available del Semaphore recibe el valor del argumento del miembro, y el bloqueo se libera.
o
size_t size() const:
Sin intentar bloquear el mutex del objeto Semaphore, se devuelve el valor actual del valor available del Semaphore.
o
void wait():
Este miembro se bloquea mientras el valor almacenado internamente (available) sea igual a cero. Al regresar de wait, el hilo actual mantiene el bloqueo del std::mutex que se mantiene internamente en el objeto Semaphore. Los miembros Notify se utilizan para incrementar available e informar a wait de que puede regresar. Cuando varios hilos están esperando, solo un hilo dejará de esperar, mientras que los hilos restantes continuarán esperando otra notificación.
o
bool wait(Fun fun, Params &&...args):
Esta es una plantilla de miembro, donde Fun es una función (objeto) que recibe el argumento pasado a wait y devuelve un bool. Este miembro se bloquea hasta que ha obtenido el bloqueo del mutex del Semaphore, luego, mientras su valor available sea igual a 0, espera hasta ser notificado. Una vez que ha reanudado el bloqueo después de ser notificado, se llama a fun, recibiendo los argumentos restantes de wait reenviados perfectamente. Este miembro devuelve false si fun devuelve false. Devuelve true si fun devuelve true y available era distinto de cero después de que fun devolviera true. Por lo tanto, la función puede realizar tareas fuera del entorno local del Semaphore, que incluso podrían implicar la actualización del valor available del Semaphore.
o
std::cv_status wait_for(std::chrono::duration<Rep, Period> const &relTime):
Este miembro se bloquea mientras el valor almacenado internamente (available) sea igual a cero y no haya transcurrido el tiempo especificado por relTime. Si esto último ocurre, se devuelve std::cv_status::timeout, de lo contrario se devuelve std::cv_status::no_timeout, en cuyo caso el hilo actual mantiene el bloqueo del std::mutex que se mantiene internamente en el objeto Semaphore. Los miembros Notify se utilizan para incrementar available e informar a wait de que puede regresar. Cuando varios hilos están esperando, solo un hilo dejará de esperar, mientras que los hilos restantes continuarán esperando otra notificación.
o
std::cv_status wait_until(std::chrono::time_point<Clock, Duration> const &absTime):
Este miembro se bloquea mientras el valor almacenado internamente (available) sea igual a cero y no se haya alcanzado el tiempo especificado por absTime. Si esto último ocurre (o si absTime está en el pasado), se devuelve std::cv_status::timeout, de lo contrario se devuelve std::cv_status::no_timeout, en cuyo caso el hilo actual mantiene el bloqueo del std::mutex que se mantiene internamente en el objeto Semaphore. Los miembros Notify se utilizan para incrementar available e informar a wait de que puede regresar. Cuando varios hilos están esperando, solo un hilo dejará de esperar, mientras que los hilos restantes continuarán esperando otra notificación.

EJEMPLO

    #include <bobcat/semaphore>
    using namespace FBB;
    Semaphore produce(10);          // tamaño del área de almacenamiento
    Semaphore consume(0);           // # de elementos en la tienda
    std::queue itemQueue;           // cola de almacenamiento
    void consumer()
    {
        while (true)
        {
            consume.wait();          // esperar hasta que haya un elemento en la tienda
                // bloquear la cola con múltiples consumidores
            size_t item = itemQueue.front();
            itemQueue.pop();
            produce.notify();   // notificar al productor
            process(item);      // no implementado
        }
    }
    void producer()
    {
        size_t item = 0;
        while (true)
        {
            ++item;
            produce.wait();     // esperar espacio en el almacenamiento
                // bloquear la cola con múltiples consumidores
            itemQueue.push(item);
            consume.notify();   // notificar al consumidor
        }
    }
    int main()
    {
        thread cons(consumer);
        thread prod(producer);
        cons.join();            // terminar los hilos no implementado
        prod.join();
    }
