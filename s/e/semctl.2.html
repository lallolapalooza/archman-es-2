semctl(2) Manual de llamadas al sistema semctl(2)

NOMBRE

semctl - operaciones de control de semáforos System V

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/sem.h>
int semctl(int semid, int semnum, int op, ...);

DESCRIPCIÓN

semctl() realiza la operación de control especificada por op en el conjunto de semáforos System V identificado por semid, o en el semáforo número semnum de ese conjunto. (Los semáforos de un conjunto se numeran a partir de 0).

Esta función tiene tres o cuatro argumentos, dependiendo de op. Cuando hay cuatro, el cuarto tiene el tipo union semun. El programa llamante debe definir esta unión de la siguiente manera:


union semun {
    int              val;    /* Valor para SETVAL */
    struct semid_ds *buf;    /* Buffer para IPC_STAT, IPC_SET */
    unsigned short  *array;  /* Array para GETALL, SETALL */
    struct seminfo  *__buf;  /* Buffer para IPC_INFO
                                (específico de Linux) */
};

La estructura de datos semid_ds se define en <sys/sem.h> de la siguiente manera:


struct semid_ds {
    struct ipc_perm sem_perm;  /* Propiedad y permisos */
    time_t          sem_otime; /* Última hora de semop */
    time_t          sem_ctime; /* Hora de creación o última
                                  modificación con semctl() */
    unsigned long   sem_nsems; /* Número de semáforos en el conjunto */
};

Los campos de la estructura semid_ds son los siguientes:

sem_perm
Esta es una estructura ipc_perm (ver más abajo) que especifica los permisos de acceso al conjunto de semáforos.
sem_otime
Hora de la última llamada al sistema semop(2).
sem_ctime
Hora de creación del conjunto de semáforos o hora de la última operación IPCSET, SETVAL o SETALL de semctl().
sem_nsems
Número de semáforos en el conjunto. Cada semáforo del conjunto se referencia mediante un entero no negativo que va desde 0 hasta sem_nsems-1.

La estructura ipc_perm se define de la siguiente manera (los campos resaltados son modificables con IPC_SET):


struct ipc_perm {
    key_t          __key; /* Clave proporcionada a semget(2) */
    uid_t          uid;   /* UID efectivo del propietario */
    gid_t          gid;   /* GID efectivo del propietario */
    uid_t          cuid;  /* UID efectivo del creador */
    gid_t          cgid;  /* GID efectivo del creador */
    unsigned short mode;  /* Permisos */
    unsigned short __seq; /* Número de secuencia */
};

Los 9 bits menos significativos del campo mode de la estructura ipc_perm definen los permisos de acceso para el segmento de memoria compartida. Los bits de permiso son los siguientes:

0400 Lectura por el usuario
0200 Escritura por el usuario
0040 Lectura por el grupo
0020 Escritura por el grupo
0004 Lectura por otros
0002 Escritura por otros

En efecto, "escritura" significa "alterar" para un conjunto de semáforos. Los bits 0100, 0010 y 0001 (los bits de ejecución) no son utilizados por el sistema.

Los valores válidos para op son:

IPC_STAT
Copia información de la estructura de datos del kernel asociada a semid a la estructura semid_ds apuntada por arg.buf. El argumento semnum se ignora. El proceso llamante debe tener permiso de lectura sobre el conjunto de semáforos.
IPC_SET
Escribe los valores de algunos miembros de la estructura semid_ds apuntada por arg.buf en la estructura de datos del kernel asociada a este conjunto de semáforos, actualizando también su miembro sem_ctime.
Se actualizan los siguientes miembros de la estructura: sem_perm.uid, sem_perm.gid y (los 9 bits menos significativos de) sem_perm.mode.
El UID efectivo del proceso llamante debe coincidir con el propietario (sem_perm.uid) o creador (sem_perm.cuid) del conjunto de semáforos, o el llamante debe tener privilegios. El argumento semnum se ignora.
IPC_RMID
Elimina inmediatamente el conjunto de semáforos, despertando a todos los procesos bloqueados en llamadas a semop(2) sobre el conjunto (con un retorno de error y errno establecido a EIDRM). El UID efectivo del proceso llamante debe coincidir con el creador o propietario del conjunto de semáforos, o el llamante debe tener privilegios. El argumento semnum se ignora.
IPC_INFO (específico de Linux)
Devuelve información sobre los límites y parámetros de los semáforos en todo el sistema en la estructura apuntada por arg.__buf. Esta estructura es de tipo seminfo, definida en <sys/sem.h> si el macro de prueba de características _GNU_SOURCE está definido:

struct seminfo {
    int semmap;  /* Número de entradas en el mapa
                    de semáforos; no utilizado dentro del kernel */
    int semmni;  /* Número máximo de conjuntos de semáforos */
    int semmns;  /* Número máximo de semáforos en todos
                    los conjuntos de semáforos */
    int semmnu;  /* Número máximo de estructuras de deshacer
                    en todo el sistema; no utilizado dentro del kernel */
    int semmsl;  /* Número máximo de semáforos en un
                    conjunto */
    int semopm;  /* Número máximo de operaciones para
                    semop(2) */
    int semume;  /* Número máximo de entradas de deshacer por
                    proceso; no utilizado dentro del kernel */
    int semusz;  /* Tamaño de struct sem_undo */
    int semvmx;  /* Valor máximo del semáforo */
    int semaem;  /* Valor máximo que se puede registrar para
                    el ajuste de semáforos (SEM_UNDO) */
};

Los ajustes semmsl, semmns, semopm y semmni pueden modificarse a través de /proc/sys/kernel/sem; consulte proc(5) para más detalles.
SEM_INFO (específico de Linux)
Devuelve una estructura seminfo que contiene la misma información que para IPC_INFO, excepto que los siguientes campos devuelven información sobre los recursos del sistema consumidos por los semáforos: el campo semusz devuelve el número de conjuntos de semáforos que actualmente existen en el sistema; y el campo semaem devuelve el número total de semáforos en todos los conjuntos de semáforos del sistema.
SEM_STAT (específico de Linux)
Devuelve una estructura semid_ds como para IPC_STAT. Sin embargo, el argumento semid no es un identificador de semáforo, sino un índice en la matriz interna del kernel que mantiene información sobre todos los conjuntos de semáforos del sistema.
SEM_STAT_ANY (específico de Linux, desde Linux 4.17)
Devuelve una estructura semid_ds como para SEM_STAT. Sin embargo, no se comprueba el permiso de lectura para semid en sem_perm.mode, lo que significa que cualquier usuario puede utilizar esta operación (al igual que cualquier usuario puede leer /proc/sysvipc/sem para obtener la misma información).
GETALL
Devuelve semval (es decir, el valor actual) para todos los semáforos del conjunto en arg.array. El argumento semnum se ignora. El proceso llamante debe tener permiso de lectura sobre el conjunto de semáforos.
GETNCNT
Devuelve el valor semncnt para el semáforo número semnum del conjunto (es decir, el número de procesos que esperan a que aumente el valor del semáforo). El proceso llamante debe tener permiso de lectura sobre el conjunto de semáforos.

semctl(2)

NAME

semctl - semaphore control operations

LIBRARY

System V IPC (libc, -lc)

SYNOPSIS

#include <sys/sem.h>

union semun {
    int                 sem_num;
    struct semid_ds *sem_ds;
    unsigned short *sem_array;
    struct seminfo *sem_info;
};

int
semctl( int semid, int semnum, int cmd, ... );

DESCRIPTION

The semctl() system call performs the operation specified by cmd on the semaphore set specified by semid. The argument semnum specifies which semaphore within the set is affected by the operation (zero-based); its interpretation depends on the value of cmd.

The cmd argument can be one of the following values:

GETALL
Return the semval values for all semaphores in the set using arg.array. The argument semnum is ignored. The calling process must have read permission on the semaphore set.
GETNCNT
Return the semncnt value for the semnum-th semaphore of the set (i.e., the number of processes waiting for the semaphore value to increase). The calling process must have read permission on the semaphore set.
GETPID
Return the sempid value for the semnum-th semaphore of the set. This is the PID of the process that last performed an operation on that semaphore (but see VERSIONS). The calling process must have read permission on the semaphore set.
GETVAL
Return semval (i.e., the semaphore value) for the semnum-th semaphore of the set. The calling process must have read permission on the semaphore set.
GETZCNT
Return the semzcnt value for the semnum-th semaphore of the set (i.e., the number of processes waiting for the semaphore value to become 0). The calling process must have read permission on the semaphore set.
SETALL
Set the semval values for all semaphores of the set using arg.array, updating also the sem_ctime member of the semid_ds structure associated with the set. Undo entries (see semop(2)) are cleared for altered semaphores in all processes. If the changes to semaphore values would permit blocked semop(2) calls in other processes to proceed, then those processes are woken up. The argument semnum is ignored. The calling process must have alter (write) permission on the semaphore set.
SETVAL
Set the semaphore value (semval) to arg.val for the semnum-th semaphore of the set, updating also the sem_ctime member of the semid_ds structure associated with the set. Undo entries are cleared for altered semaphores in all processes. If the changes to semaphore values would permit blocked semop(2) calls in other processes to proceed, then those processes are woken up. The calling process must have alter permission on the semaphore set.

Additionally, the following operations can be performed:

IPC_RMID
Remove the semaphore set. The calling process must have administer permission (see capabilities(7)). This operation is only valid for a semaphore set identifier, not for a specific semaphore within the set. The argument semnum is ignored.
IPC_SET
Set the values of the sem_perm.uid, sem_perm.gid, and sem_perm.mode members of the semaphore set's associated semid_ds structure using the values from the buffer pointed to by arg.buf. The sem_perm.mode bits are set to the low 9 bits of the mode argument. Only the effective user ID of the calling process can be the creator ID of the semaphore set or the owner ID of the semaphore set. This operation is only valid for a semaphore set identifier, not for a specific semaphore within the set. The argument semnum is ignored.
IPC_STAT
Return a copy of the semid_ds structure associated with the given semaphore set identifier in the buffer pointed to by arg.buf. The argument semnum is ignored. The calling process must have read permission on the semaphore set.
SEM_STAT
This is a Linux-specific operation. It is similar to IPC_STAT, but it takes an index semid and returns information about the semaphore set at that index.
SEM_STAT_ANY
This is a Linux-specific operation. It is similar to SEM_STAT, but it does not require read permission on the semaphore set. This is useful for tools like ipcs(1) that need to list all semaphore sets.
SEM_INFO
This is a Linux-specific operation. It returns system-wide semaphore information in the buffer pointed to by arg.sem_info. The semid and semnum arguments are ignored.
IPC_INFO
This is a Linux-specific operation. It is similar to SEM_INFO, but it returns information about all semaphore sets in the buffer pointed to by arg.buf (which should be a pointer to a struct sem_info). The semid and semnum arguments are ignored.

For operations that require a pointer to a struct semid_ds or struct sem_info, or a pointer to an array of unsigned shorts, the fourth argument to semctl() should be a pointer to the relevant structure or array. For operations that do not require a fourth argument, it can be 0.

The semid_ds structure is defined in <sys/sem.h> as:

struct ipc_perm {
    key_t          key;
    uid_t          uid;
    gid_t          gid;
    uid_t          cuid;
    gid_t          cgid;
    mode_t         mode;
    unsigned long  seq;
};

struct semid_ds {
    struct ipc_perm sem_perm;
    time_t         sem_otime;    /* Last semop operation time */
    time_t         sem_ctime;    /* Last change time */
    unsigned long  sem_nsems;    /* No. of semaphores in set */
    ...             /* other members */
};

The sem_otime field is not reliably set by the kernel. The sem_perm field contains the access permissions and identifiers for the semaphore set.

sem_num specifies the semaphore index within the set. semval is the semaphore value. sempid is the process ID of the last process to perform an operation on the semaphore. semncnt is the count of processes waiting for the semaphore value to become greater than zero. semzcnt is the count of processes waiting for the semaphore value to become zero.

The semun union is used to pass the fourth argument (if any) to semctl().

The sempid value

POSIX.1 defines sempid as the "process ID of [the] last operation" on a semaphore, and explicitly notes that this value is set by a successful semop(2) call, with the implication that no other interface affects the sempid value.

While some implementations conform to the behavior specified in POSIX.1, others do not. (The fault here probably lies with POSIX.1 inasmuch as it likely failed to capture the full range of existing implementation behaviors.) Various other implementations also update sempid for the other operations that update the value of a semaphore: the SETVAL and SETALL operations, as well as the semaphore adjustments performed on process termination as a consequence of the use of the SEM_UNDO flag (see semop(2)).

Linux also updates sempid for SETVAL operations and semaphore adjustments. However, somewhat inconsistently, up to and including Linux 4.5, the kernel did not update sempid for SETALL operations. This was rectified in Linux 4.6.

RETURN VALUE

On success, semctl() returns a nonnegative value depending on cmd as follows:

GETNCNT
the value of semncnt.
GETPID
the value of sempid.
GETVAL
the value of semval.
GETZCNT
the value of semzcnt.
IPC_INFO
the index of the highest used entry in the kernel's internal array recording information about all semaphore sets. (This information can be used with repeated SEM_STAT or SEM_STAT_ANY operations to obtain information about all semaphore sets on the system.)
SEM_INFO
as for IPC_INFO.
SEM_STAT
the identifier of the semaphore set whose index was given in semid.
SEM_STAT_ANY
as for SEM_STAT.

All other cmd values return 0 on success.

On failure, semctl() returns -1 and sets errno to indicate the error.

ERRORS

EACCES
The argument cmd has one of the values GETALL, GETPID, GETVAL, GETNCNT, GETZCNT, IPC_STAT, SEM_STAT, SEM_STAT_ANY, SETALL, or SETVAL and the calling process does not have the required permissions on the semaphore set and does not have the CAP_IPC_OWNER capability in the user namespace that governs its IPC namespace.
EFAULT
The address pointed to by arg.buf or arg.array isn't accessible.
EIDRM
The semaphore set was removed.
EINVAL
Invalid value for cmd or semid. Or: for a SEM_STAT operation, the index value specified in semid referred to an array slot that is currently unused.
EPERM
The argument cmd has the value IPC_SET or IPC_RMID but the effective user ID of the calling process is not the creator (as found in sem_perm.cuid) or the owner (as found in sem_perm.uid) of the semaphore set, and the process does not have the CAP_SYS_ADMIN capability.
ERANGE
The argument cmd has the value SETALL or SETVAL and the value to which semval is to be set (for some semaphore of the set) is less than 0 or greater than the implementation limit SEMVMX.

VERSIONS

POSIX.1 specifies the sem_nsems field of the semid_ds structure as having the type unsigned short, and the field is so defined on most other systems. It was also so defined on Linux 2.2 and earlier, but, since Linux 2.4, the field has the type unsigned long.

The sempid value

POSIX.1 defines sempid as the "process ID of [the] last operation" on a semaphore, and explicitly notes that this value is set by a successful semop(2) call, with the implication that no other interface affects the sempid value.

While some implementations conform to the behavior specified in POSIX.1, others do not. (The fault here probably lies with POSIX.1 inasmuch as it likely failed to capture the full range of existing implementation behaviors.) Various other implementations also update sempid for the other operations that update the value of a semaphore: the SETVAL and SETALL operations, as well as the semaphore adjustments performed on process termination as a consequence of the use of the SEM_UNDO flag (see semop(2)).

Linux also updates sempid for SETVAL operations and semaphore adjustments. However, somewhat inconsistently, up to and including Linux 4.5, the kernel did not update sempid for SETALL operations. This was rectified in Linux 4.6.

STANDARDS

POSIX.1-2024.

HISTORY

POSIX.1-2001, SVr4.

Various fields in a struct semid_ds were typed as short under Linux 2.2 and have become long under Linux 2.4. To take advantage of this, a recompilation under glibc-2.1.91 or later should suffice. (The kernel distinguishes old and new calls by an IPC_64 flag in cmd.)

In some earlier versions of glibc, the semun union was defined in <sys/sem.h>, but POSIX.1 requires that the caller define this union. On versions of glibc where this union is not defined, the macro _SEM_SEMUN_UNDEFINED is defined in <sys/sem.h>.

NOTES

The IPC_INFO, SEM_STAT, and SEM_INFO operations are used by the ipcs(1) program to provide information on allocated resources. In the future these may modified or moved to a /proc filesystem interface.

The following system limit on semaphore sets affects a semctl() call:

SEMVMX
Maximum value for semval: implementation dependent (32767).

For greater portability, it is best to always call semctl() with four arguments.

EXAMPLES

See shmop(2).

semctl - semáforo de control de operaciones

NAME

semctl - semáforo de control de operaciones

SYNOPSIS

#include <sys/sem.h>

int semctl(int semid, int semnum, int cmd, ...);

DESCRIPTION

semctl realiza las operaciones especificadas por cmd en el conjunto de semáforos identificado por semid. El argumento semnum especifica el semáforo dentro del conjunto al que se aplica la operación (los semáforos se numeran de 0 a nsem-1, donde nsem es el número de semáforos en el conjunto). La operación puede requerir un argumento adicional opcional, que se pasa en la parte variable de la lista de argumentos (...). Este argumento es un puntero a una unión de tipo union semun.

La unión semun se define como:

union semun {
    int              val;    /* Valor utilizado para SETVAL o GETVAL */
    struct semid_ds *buf;    /* Buffer utilizado para IPC_STAT o IPC_SET */
    unsigned short  *array;  /* Array utilizado para GETALL o SETALL */
    struct seminfo  *__buf;  /* Información específica del sistema */
};

Los valores de cmd que se pueden utilizar son:

GETVAL
Devuelve el valor del semáforo especificado por semnum. No se requiere ningún argumento opcional.
SETVAL
Establece el valor del semáforo especificado por semnum al valor especificado en semun.val. Solo un superusuario puede cambiar el valor de un semáforo (consulte semop(2) para más detalles).
GETPID
Devuelve el ID del proceso que realizó la última operación en el semáforo especificado por semnum. No se requiere ningún argumento opcional.
GETNCNT
Devuelve el número de procesos que esperan a que el valor del semáforo especificado por semnum aumente. No se requiere ningún argumento opcional.
GETZCNT
Devuelve el número de procesos que esperan a que el valor del semáforo especificado por semnum sea cero. No se requiere ningún argumento opcional.
GETALL
Copia los valores de todos los semáforos del conjunto en el array especificado por semun.array. No se requiere ningún argumento opcional.
SETALL
Establece los valores de todos los semáforos del conjunto a partir de los valores del array especificado por semun.array. Solo un superusuario puede cambiar el valor de un semáforo (consulte semop(2) para más detalles).
IPC_STAT
Copia las estadísticas asociadas con el conjunto de semáforos especificado por semid en la estructura apuntada por semun.buf. No se requiere ningún argumento opcional.
IPC_SET
Establece los valores de los miembros de la estructura struct semid_ds especificada por semun.buf. Solo el superusuario o el propietario del ID de acceso a IPC pueden realizar esta operación. Los miembros que se pueden cambiar son sem_perm.uid, sem_perm.gid y sem_perm.mode (los 9 bits inferiores).
IPC_RMID
Elimina el conjunto de semáforos especificado por semid. Solo el superusuario o el propietario del ID de acceso a IPC pueden realizar esta operación. No se requiere ningún argumento opcional.

RETURN VALUE

En caso de éxito, el valor devuelto depende del valor de cmd:

  • Para GETVAL, GETPID, GETNCNT y GETZCNT, se devuelve el valor solicitado.
  • Para SETVAL, SETALL, IPC_STAT, IPC_SET y IPC_RMID, se devuelve 0.
  • Para GETALL, se devuelve 0 si la operación se realiza correctamente.

En caso de error, se devuelve -1 y errno se establece en un valor apropiado.

ERRORS

EACCES
Se intentó acceder a un semáforo sin los permisos necesarios.
EAGAIN
IPC_STAT o IPC_SET se intentó con IPC_NOWAIT y la operación no pudo completarse inmediatamente.
EINRANGE
semnum estaba fuera del rango [0, nsem-1].
EPERM
Se intentó realizar una operación que requiere privilegios de superusuario (como SETVAL o SETALL) sin tenerlos.
EEXIST
semctl con SETVAL o SETALL falló porque el semáforo ya existía y no se podía sobrescribir.
EINVAL
semid no es válido o cmd no es un comando válido.
ENOMEM
No hay suficiente memoria en el sistema para satisfacer la solicitud (por ejemplo, al intentar realizar IPC_STAT).
ENOSPC
Se intentó crear un nuevo semáforo pero se ha alcanzado el límite máximo de semáforos en el sistema.
ENOTTY
El argumento cmd no se aplica al conjunto de semáforos.

CONFORMING TO

POSIX.1-2001, POSIX.1-2008, SUSv2, SVr4, X/Open.

HISTORY

POSIX.1-2001.

NOTES

La unión semun se define en <sys/sem.h>. Algunas implementaciones de la biblioteca C pueden requerir que se defina _SEM_SEMUN_UNDEFINED para que esta unión se defina correctamente.

semid es un identificador de semáforo, que se obtiene mediante una llamada a semget(2).

El valor devuelto por semctl es un entero. Sin embargo, para los comandos que devuelven un puntero (como IPC_STAT), el valor devuelto debe ser tratado como un puntero a la estructura correspondiente.

La estructura struct semid_ds contiene información sobre el conjunto de semáforos, incluyendo el ID del propietario, el ID del grupo, el modo de acceso, el número de semáforos en el conjunto y el tiempo de la última operación.

La estructura struct seminfo contiene información específica del sistema sobre los límites de los semáforos.

EXAMPLES

Obtener el valor del primer semáforo en un conjunto:

#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/sem.h>
#include <stdio.h>
#include <stdlib.h>

int main() {
    int semid;
    union semun arg;
    int value;

    /* Supongamos que semid se ha obtenido previamente mediante semget() */
    semid = semget(IPC_PRIVATE, 1, IPC_CREAT | 0666);
    if (semid == -1) {
        perror("semget");
        exit(EXIT_FAILURE);
    }

    arg.val = 10;
    if (semctl(semid, 0, SETVAL, arg) == -1) {
        perror("semctl SETVAL");
        exit(EXIT_FAILURE);
    }

    value = semctl(semid, 0, GETVAL);
    if (value == -1) {
        perror("semctl GETVAL");
        exit(EXIT_FAILURE);
    }

    printf("El valor del semáforo es: %d\n", value);

    /* Eliminar el conjunto de semáforos */
    if (semctl(semid, 0, IPC_RMID) == -1) {
        perror("semctl IPC_RMID");
        exit(EXIT_FAILURE);
    }

    return 0;
}
