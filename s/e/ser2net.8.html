NOMBRE

ser2net - Proxy de serie a red

SINOPSIS

ser2net [-c archivo_config] [-C dir_conf_sys] [-Y linea_conf_yaml] [-p puerto_control] [-n] [-d] [-b] [-v] [-P archivo_pid]

DESCRIPCIÓN

El demonio ser2net permite establecer sesiones telnet y tcp con los puertos serie de una unidad o con una interfaz IPMI Serial Over LAN (SOL).

El programa se inicia normalmente como un demonio, abre los puertos de red especificados en el archivo de configuración y espera las conexiones. Una vez que ocurre una conexión, el programa intenta establecer la conexión y abrir el puerto serie. Si otro usuario ya está utilizando la conexión o el puerto serie, la conexión se rechaza con un mensaje de error.

OPCIONES

-c archivo_config
Establece el archivo de configuración en uno diferente del predeterminado dir_conf_sys/ser2net/ser2net.yaml. Si el archivo_config es -, entonces la entrada estándar se lee como archivo de configuración. Ver -C para información sobre dir_conf_sys.
-C dir_conf_sys
Establece el directorio donde se almacenan el archivo de configuración y las claves SSL. Generalmente es /etc/ser2net en sistemas tipo Unix; en Windows es ../etc/ser2net desde la ubicación del ejecutable por defecto.
-a dir_autenticacion
Establece el directorio predeterminado donde se almacena la información de autenticación. Generalmente es /usr/share/ser2net en sistemas tipo Unix; en Windows es ../share/ser2net desde la ubicación del ejecutable por defecto. Esto puede ser reemplazado en el archivo de configuración. Ver ser2net.yaml.5 para información sobre lo que hace esto.
-A dir_autenticacion_admin
Establece el directorio predeterminado donde se almacena la información de autenticación del administrador. Es dir_conf_sys/auth por defecto. Esto puede ser reemplazado en el archivo de configuración. Ver ser2net.yaml.5 para información sobre lo que hace esto.
-Y cadena_config_yaml
Agrega una cadena de configuración YAML al final de las cadenas a procesar. Esto puede ser especificado múltiples veces para múltiples cadenas. Estas se agregan al final de un archivo de configuración YAML; aunque si esto se especifica, el archivo de configuración predeterminado se deshabilita y debes habilitarlo con la opción -c.

Para facilitar el manejo, cualquier # en la cadena de configuración que no esté entre comillas (lo que normalmente iniciaría un comentario en YAML) se convierte en una nueva línea. Además, se agrega una nueva línea después de cada cadena de configuración separada. Así, por ejemplo:


-Y 'conexion: &con01# aceptador: tcp,2013'
-Y ' conector: serialdev,/dev/ttyEcho0,9600n81,local'
-Y ' opciones:# banner: "### Un Banner ###\r\n"'

se puede poner en la línea de comandos de ser2net.

-n
Impide que el demonio se bifurque y se desvincule de la terminal de control. Esto es útil para ejecutar desde init.
-d
Al igual que -n, pero también envía los registros del sistema a la salida estándar. Esto es muy útil para fines de depuración.
-P archivo_pid
Si se especifica, coloca el ID del proceso (pid) de ser2net en el archivo pid, reemplazando lo que hubiera en ese archivo previamente. No se crea un archivo pid por defecto; debes especificar esto para crearlo. Ten en cuenta también que este nombre de archivo debe ser específico con la ruta completa, ya que ser2net cambiará de directorio a "/" cuando se convierta en un demonio.
-u
Si el bloqueo UUCP está habilitado, esto deshabilitará el uso de bloqueos UUCP.
-b
Cisco IOS utiliza un mecanismo diferente para especificar las velocidades en baudios que el mecanismo descrito en RFC2217. Esta opción establece la versión IOS de la configuración de las velocidades en baudios. La predeterminada es la de RFC2217. Ten en cuenta que esta capacidad ahora se maneja automáticamente y esta opción se ignora.
-v
Imprime la versión del programa y sale.
-t <num hilos>
Genera el número de hilos dado para que los use ser2net. El valor predeterminado es 1. Solo es válido si pthreads está habilitado en el momento de la compilación.
-p <aceptador_admin>
Habilita la interfaz de administración en la especificación del aceptador dada. Ver "CONEXIÓN DE ADMINISTRACIÓN" en ser2net.yaml(5) para más detalles sobre cómo configurar esto, y "INTERFAZ DE ADMINISTRACIÓN" a continuación para detalles sobre cómo usarlo.
-s firma
Especifica la firma RFC2217 predeterminada.

INTERFAZ DE ADMINISTRACIÓN

La interfaz de administración proporciona una interfaz simple para controlar los puertos y ver su estado. Para lograr esto, tiene los siguientes comandos:

mostrarpuerto [<puerto_red>]
Muestra información sobre un puerto. Si no se proporciona un puerto, se muestran todos los puertos.
mostrarcortopuertos [<puerto_red>]
Muestra información sobre un puerto, cada puerto en una línea. Si no se proporciona un puerto, se muestran todos los puertos. Esto puede producir una salida muy ancha.
ayuda
Muestra una lista corta y un resumen de los comandos.
salir
Desconecta del puerto de control.
yaml
Entra en modo de salida YAML. Ver MODOS YAML a continuación.
version
Muestra la versión de este programa.
monitor <tipo> <puerto_red>
Muestra toda la entrada para un puerto dado en el puerto de control que llama. Solo se puede monitorear una dirección a la vez. El campo tipo puede ser tcp o term y especifica si se deben monitorear datos del puerto de red o del puerto serie. Ten en cuenta que el monitoreo de datos se realiza según el mejor esfuerzo; si el puerto controlador no puede mantenerse, los datos se descartarán silenciosamente. Un controlador solo puede monitorear una cosa y un puerto solo puede ser monitoreado por un controlador.
monitor stop
Detiene el monitor actual.
desconectar <puerto_red>
Desconecta la conexión TCP en el puerto.
establecerpuertotiempo <puerto_red> <tiempo_espera>
Establece la cantidad de tiempo en segundos antes de que la conexión del puerto se cierre si no se ha visto actividad en el puerto.
establecerconfigpuerto <puerto_red> <config>
Establece la configuración del puerto como en la configuración del dispositivo en el archivo /etc/ser2net/ser2net.yaml. Si se especifican opciones conflictivas, la última opción será la utilizada. Ten en cuenta que estas no cambiarán hasta que el puerto se desconecte y se vuelva a conectar. Las opciones 300, 1200, 2400, 4800, 9600, 19200, 38400, 57600, 115200 establecen las diversas velocidades en baudios. Las siguientes velocidades pueden estar disponibles si tu sistema tiene los valores definidos y tu hardware lo soporta: 230400, 460800, 500000, 576000, 921600, 1000000, 1152000, 1500000, 2000000, 2500000, 3000000, 3500000, 4000000. La paridad, los bits de datos y los bits de parada se pueden especificar de la manera clásica después de la velocidad, como en 9600N81. Esto tiene el siguiente formato: <velocidad>[N|E|O|M|S[5|6|7|8[1|2]]]. Establecer opciones serie de esta manera no funciona en SOL; SOL tiene opciones serie N81 fijas. EVEN, ODD, NONE (MARK y SPACE si son compatibles) establecen la paridad. 1STOPBIT, 2STOPBITS establecen el número de bits de parada. 7DATABITS, 8DATABITS establecen el número de bits de datos. [-]XONXOFF activa (- desactiva) el soporte XON/XOFF. [-]RTSCTS activa (- desactiva) el control de flujo de hardware. [-]LOCAL ignora (- comprueba) las líneas de control del módem (DCD, DTR, etc.)
establecercontrolpuerto <puerto_red> <controles>
Modifica los controles dinámicos del puerto. Estos no permanecen entre c

INTERFAZ DE ADMINISTRACIÓN

ser2net tiene una interfaz de administración incorporada que permite la manipulación de las conexiones mientras está en funcionamiento. La interfaz se puede iniciar con la opción -a del comando.

La interfaz de administración es un socket de dominio de UNIX y la ruta a él se especifica en el archivo de configuración. La interfaz se configura en el archivo ser2net.yaml con la clave control.

Los comandos disponibles son:

exit
Sale de la interfaz de administración.
version
Muestra la versión de ser2net.
showport
Muestra todas las configuraciones de los puertos y sus estados actuales.
disconnect <network port>
Cierra la conexión de red especificada.
setporttimeout <network port> <timeout>
Establece el tiempo de espera para la conexión de red especificada. El tiempo de espera está en segundos.
setportcontrol <network port> DTRHI
Activa la línea DTR.
DTRLO Desactiva la línea DTR.
RTSHI Activa la línea RTS.
RTSLO Desactiva la línea RTS.
setportenable <network port> <enable state>
Establece el estado de operación del puerto. Los estados válidos son: off para cerrar el puerto de red, raw para habilitar la transferencia de todas las E/S del puerto de red tal como están, rawlp para habilitar la entrada del puerto de red y la salida del dispositivo sin configuración termios, y telnet para habilitar el puerto de red y ejecutar el protocolo de negociación telnet en el puerto.
reload
Hace que ser2net recargue su configuración. Cualquier error de salida aparecerá, además de ir a syslog.

MODOS YAML

Si se emite el comando "yaml", el eco se desactiva y toda la salida cumple con el formato YAML. La forma es básicamente la misma que la salida no YAML, con algunos ajustes menores para hacerla compatible con YAML. Además, todas las respuestas tienen el siguiente formato:


%YAML 1.1
---
response:
<información de respuesta aquí>
...

Si hay un error, se devuelve en la respuesta con la clave "error". Si el comando tuvo éxito, no habrá una clave "error" en el mapeo de respuesta. Los "..." estarán al final de todas las respuestas.

Los siguientes comandos están disponibles en el modo de salida YAML: exit, version, showport, disconnect, setporttimeout, setportenable, setportcontrol, reload,

Si se ve "%YAML" en la entrada, se activan los modos de entrada y salida YAML, se desactiva el eco y se espera que toda la entrada tenga el siguiente formato:


---
command:
name: <nombre del comando>
id: <id opcional>
parms: [ parm1 [, parm2 [...]]]
...

El id es opcional y simplemente se devolverá en la respuesta. Los parms también son opcionales, a menos que el comando los requiera. Los parms adicionales se ignoran, al igual que las claves desconocidas en el mapeo principal.

Tenga en cuenta que debe lidiar con el "->" que se emite cuando se establece la conexión, antes de entrar en modo YAML, ya que YAML no lo maneja bien.

En el modo de salida YAML, recibirá informes asíncronos de conexiones y desconexiones en el siguiente formato:


%YAML 1.1
---
new connection:
name: !!str 'con1'
remaddr: !!str 'ipv6,::1,59072'
...


%YAML 1.1
---
disconnect:
name: !!str 'con1'
remaddr: !!str 'ipv6,::1,59072'
...

CONFIGURACIÓN

La configuración se realiza a través del archivo /etc/ser2net/ser2net.yaml. Se puede especificar un archivo con otro nombre o ruta usando la opción -c.

El archivo de configuración YAML se describe en ser2net.yaml(5)

SEÑALES

SIGHUP
Si ser2net recibe una señal SIGHUP, volverá a leer su archivo de configuración y realizará los cambios apropiados. Si una conexión en uso se cambia o se elimina, el cambio real no se producirá hasta que el puerto se desconecte, excepto que si deshabilita una conexión, expulsará a los usuarios.

ser2net utiliza el nombre (el alias de la conexión) para determinar si es nueva, modificada o eliminada. Si el nuevo archivo de configuración tiene una conexión con el mismo nombre, se trata como un cambio.

Esto tiene algunas interacciones inusuales con las conexiones que permiten más de una conexión simultánea. Funciona igual que el otro puerto, pero el aceptador está deshabilitado y no se aceptarán nuevas conexiones hasta que se cierren todas las conexiones existentes.

ERRORES

Toda la salida de error después del inicio va a syslog, no a la salida estándar, a menos que use la opción -d.
