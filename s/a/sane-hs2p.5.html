sane-hs2p(5) SANE Scanner Access Now Easy sane-hs2p(5)

NOMBRE

sane-hs2p - backend de SANE para escáneres planos/ADF SCSI de Ricoh

DESCRIPCIÓN

La biblioteca sane-hs2p implementa un backend de SANE (Scanner Access Now Easy) que proporciona acceso a la familia de escáneres Ricoh IS450. También debería funcionar con los escáneres IS420, IS410 e IS430, pero estos no han sido probados. Por favor, contacte con el mantenedor o la lista de correo sane-devel si posee un escáner de este tipo.

Este backend es de calidad alfa. Puede tener errores y algunos escáneres no han sido probados en absoluto. Tenga cuidado y desconecte el enchufe si el escáner produce ruidos inusuales.

NOMBRES DE DISPOSITIVO

Este backend espera nombres de dispositivo del tipo:

especial

Donde especial es la ruta del nombre del dispositivo que corresponde a un escáner SCSI. El programa sane-find-scanner(1) ayuda a descubrir el dispositivo correcto. En Linux, un nombre de dispositivo así podría ser /dev/sg0 o /dev/sga, por ejemplo. Consulte sane-scsi(5) para obtener más detalles.

CONFIGURACIÓN

El contenido del archivo hs2p.conf es una lista de nombres de dispositivo que corresponden a escáneres SCSI. Las líneas vacías y las líneas que comienzan con un signo de almohadilla (#) se ignoran. Consulte sane-scsi(5) sobre los detalles de lo que constituye un nombre de dispositivo válido.

ARCHIVOS

/etc/sane.d/hs2p.conf
El archivo de configuración del backend (ver también la descripción de SANE_CONFIG_DIR más abajo).
/usr/lib/sane/libsane-hs2p.a
La biblioteca estática que implementa este backend.
/usr/lib/sane/libsane-hs2p.so
La biblioteca compartida que implementa este backend (presente en sistemas que soportan carga dinámica).

ENTORNO

SANE_CONFIG_DIR
Esta variable de entorno especifica la lista de directorios que pueden contener el archivo de configuración. En sistemas *NIX, los directorios están separados por dos puntos (`:'), en OS/2, están separados por un punto y coma (`;'). Si esta variable no está establecida, el archivo de configuración se busca en dos directorios predeterminados: primero, el directorio de trabajo actual (".") y luego en /etc/sane.d. Si el valor de la variable de entorno termina con el carácter separador de directorios, entonces los directorios predeterminados se buscan después de los directorios especificados explícitamente. Por ejemplo, establecer SANE_CONFIG_DIR en "/tmp/config:" resultaría en la búsqueda de los directorios tmp/config, . y /etc/sane.d (en este orden).
SANE_DEBUG_HS2P
Si la biblioteca fue compilada con soporte de depuración habilitado, esta variable de entorno controla el nivel de depuración para este backend. Un valor de 255 imprime toda la salida de depuración. Valores más pequeños reducen la verbosidad.

ESTADO ACTUAL

El backend sane-hs2p está ahora en la versión 1.00. Todas las características principales relacionadas con el escaneo son compatibles, excepto aquellas que requieren la IPU opcional. Se admite el escaneo desde el alimentador plano o ADF (ya sea simplex o dúplex). Se admiten lineart, trama, escala de grises de 4 bits y escala de grises de 8 bits. Se admiten tablas gamma y patrones de trama preestablecidos, así como brillo, umbral y contraste. También se admiten el modo de espera de escaneo, el filtrado binario y de escala de grises, el escaneo negativo y la configuración blanca absoluta o relativa. El estampado con el endosador opcional también es compatible.

FUNCIONALIDAD PLANIFICADA

Este escáner puede escanear desde el ADF en modo simplex continuo. Sorprendentemente, muchos escáneres escanean un documento completo desde el ADF a la memoria antes de expulsar la hoja. Por lo tanto, si el documento es demasiado largo, el escáner no puede retener todos los datos de imagen en memoria. Pero si el escáner enviara sus datos de imagen cuando su memoria se llenara, y luego leyera el siguiente bloque de datos, se podría lograr un escaneo continuo.

FUNCIONALIDAD FALTANTE

Los comandos SCSI para subir (2AH) o descargar (28H) patrones de trama personalizados (02H) y vectores gamma (03H) deberían funcionar, pero requieren la implementación del código de Opción-Valor de SANE para permitir al usuario crear las tablas que se subirán al escáner. No se planea soporte para Datos de Mantenimiento (80H) ya que esta funcionalidad es más adecuada para una utilidad independiente que será utilizada por un técnico al reemplazar la lámpara o la unidad ADF. Tampoco se planea soporte para leer o cambiar los parámetros y ajustes de la IPU (93H), ya que mi IS450 carece de dicha unidad. Las estructuras Auto Photo/Letter de 31 bytes y Dynamic threshold de 21 bytes están documentadas en el archivo hs2p-scsi.h en caso de que alguien desee usar su IPU para el procesamiento de datos de imagen.
