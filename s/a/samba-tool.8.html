SAMBA-TOOL(8) Herramientas de administración del sistema SAMBA-TOOL(8)

NOMBRE

samba-tool - Herramienta principal de administración de Samba.

SINOPSIS

samba-tool [-h] [-W mi_grupo_trabajo] [-U usuario] [-d nivel_depuracion] [--v]

DESCRIPCIÓN

Esta herramienta forma parte del conjunto de samba(7).

OPCIONES

Samba-tool consta de muchos subcomandos, cada uno con su propio conjunto de opciones. Las opciones listadas en esta sección son comunes a varios subcomandos.

-h|--help

Muestra un mensaje de ayuda y sale.

-r|--realm=REALM

Establece el reino para el dominio.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro realm en el archivo /etc/samba/smb.conf.

--simple-bind-dn=DN

DN a utilizar para una vinculación simple.

--password

Especifica la contraseña en la línea de comandos.

Tenga cuidado al incluir contraseñas en scripts o al pasar valores proporcionados por el usuario a la línea de comandos. Por seguridad, es mejor dejar que la herramienta cliente de Samba solicite la contraseña si es necesario, u obtenga la contraseña una vez con kinit.

Si no se especifica --password, la herramienta comprobará la variable de entorno PASSWD, seguida de PASSWD_FD, que se espera que contenga un número de descriptor de archivo (FD) abierto.

Finalmente, comprobará PASSWD_FILE (que contiene una ruta de archivo a abrir). El archivo solo debe contener la contraseña. ¡Asegúrese de que los permisos del archivo restrinjan el acceso a usuarios no deseados!

Aunque Samba intentará eliminar la contraseña del título del proceso (como se ve en ps), esto ocurre después del inicio y está sujeto a una condición de carrera.

-U|--user=[DOMINIO\]NOMBRE_USUARIO[%CONTRASEÑA]

Establece el nombre de usuario SMB o el nombre de usuario y contraseña.

Si no se especifica %CONTRASEÑA, se le pedirá al usuario. El cliente comprobará primero la variable de entorno USER (que también puede contener la contraseña separada por un %) y luego la variable LOGNAME (que no puede contener una contraseña) y si alguna existe, se utilizará el valor. Si no se encuentran estas variables de entorno, se puede utilizar el nombre de usuario encontrado en una caché de credenciales de Kerberos.

Una tercera opción es usar un archivo de credenciales que contenga la contraseña en texto plano del nombre de usuario y la contraseña. Esta opción se proporciona principalmente para scripts donde el administrador no desea pasar las credenciales en la línea de comandos o a través de variables de entorno. Si se utiliza este método, asegúrese de que los permisos del archivo restrinjan el acceso a usuarios no deseados. Consulte la opción -A para obtener más detalles.

Tenga cuidado al incluir contraseñas en scripts o al pasar valores proporcionados por el usuario a la línea de comandos. Por seguridad, es mejor dejar que la herramienta cliente de Samba solicite la contraseña si es necesario, u obtenga la contraseña una vez con kinit.

Aunque Samba intentará eliminar la contraseña del título del proceso (como se ve en ps), esto ocurre después del inicio y está sujeto a una condición de carrera.

-W|--workgroup=GRUPO_TRABAJO

Establece el dominio SMB del nombre de usuario. Esto anula el dominio predeterminado, que es el dominio definido en smb.conf. Si el dominio especificado es el mismo que el nombre NetBIOS del servidor, hace que el cliente inicie sesión utilizando el SAM local del servidor (en lugar del SAM del dominio).

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro workgroup en el archivo /etc/samba/smb.conf.

-N|--no-pass

Si se especifica, este parámetro suprime la solicitud normal de contraseña del cliente al usuario. Esto es útil al acceder a un servicio que no requiere contraseña.

A menos que se especifique una contraseña en la línea de comandos o se especifique este parámetro, el cliente solicitará una contraseña.

Si se especifica una contraseña en la línea de comandos y también se define esta opción, la contraseña en la línea de comandos será ignorada silenciosamente y no se utilizará ninguna contraseña.

--use-kerberos=deseado|requerido|apagado

Este parámetro determina si las herramientas cliente de Samba intentarán autenticarse usando Kerberos. Para la autenticación Kerberos, debe usar nombres DNS en lugar de direcciones IP al conectarse a un servicio. Por defecto, las herramientas cliente de Samba intentarán usar la caché de credenciales Kerberos (ccache) predeterminada. En caso de que la ccache no exista o se haya especificado la opción -U|--user, los clientes pedirán introducir una contraseña y obtendrán un ticket Kerberos (kinit) para usted. Si desea utilizar una caché de credenciales Kerberos alternativa, use la opción --use-krb5-ccache.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro client use kerberos en el archivo /etc/samba/smb.conf.

--use-krb5-ccache=CCACHE

Especifica la ubicación de la caché de credenciales para la autenticación Kerberos.

Esto forzará --use-kerberos=requerido.

-A|--authentication-file=nombre_archivo

Esta opción le permite especificar un archivo del que leer el nombre de usuario y la contraseña utilizados en la conexión. El formato del archivo es: 
username = <valor>
password = <valor>
domain   = <valor>

¡Asegúrese de que los permisos del archivo restrinjan el acceso a usuarios no deseados!

-H URL, --URL=URL

URL LDB para la base de datos o el servidor de destino.

La URL puede ser una ruta de archivo simple o utilizar uno de los esquemas listados aquí. Si se utiliza una ruta simple, se trata como si se hubiera usado 'tdb://'.

tdb://RUTA

RUTA es la ubicación de una base de datos TDB.

mdb://RUTA

RUTA es la ubicación de una base de datos LMDB.

ldb://RUTA

RUTA es la ubicación de una base de datos LDB, en formato LMDB o TDB. Los formatos se intentarán uno tras otro hasta que uno tenga éxito o todos fallen. Es seguro usar esto si no conoce el formato del archivo.

ldap://NOMBRE_HOST, ldaps://NOMBRE_HOST

El backend LDB es el servidor LDAP con nombre. ldaps:// envuelve la conexión en TLS.

ldapi://SOCKET

El servidor backend es un servidor LDAP local que utiliza un socket de dominio Unix.

--color=siempre|nunca|auto

usar color si está disponible (predeterminado: auto)

--ipaddress=DIRECCION_IP

Dirección IP del servidor

-s ARCHIVO, --configfile=ARCHIVO

Utiliza este archivo de configuración smb.conf.

--color=siempre|nunca|auto

Indica si samba-tool debe usar códigos de color ANSI en su salida. Si es 'auto' (el predeterminado), samba-tool usará color cuando su salida se dirija a una terminal, a menos que la variable de entorno NO_COLOR esté establecida y no esté vacía.

Los valores 'yes' y 'force' se aceptan como sinónimos de 'always'; 'no' y 'none' para 'never'; y 'tty' y 'if-tty' para 'auto'.

Tenga en cuenta que pedir color no significa que samba-tool sea muy colorido. Muchos comandos son muy monocromáticos, especialmente cuando tienen éxito.

-V, --version

Muestra el número de versión y sale.

-d|--debuglevel=nivel

nivel es un entero de 0 a 10. El valor predeterminado si no se especifica este parámetro es 1 para las aplicaciones cliente.

Cuanto mayor sea este valor, más detalles se registrarán en los archivos de registro sobre las actividades del servidor. En el nivel 0, solo se registrarán errores críticos y advertencias graves. El nivel 1 es un nivel razonable para el funcionamiento diario: genera una pequeña cantidad de información sobre las operaciones realizadas.

Los niveles superiores a 1 generarán una cantidad considerable de datos de registro y solo deben usarse al investigar un problema. Los niveles superiores a 3 están diseñados solo para uso de desarrolladores y generan ENORMES cantidades de datos de registro, la mayoría de los cuales son extremadamente crípticos.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro log level en el archivo /etc/samba/smb.conf.

--debug-stdout

Esto redirigirá la salida de depuración a STDOUT. Por defecto, todos los clientes registran en STDERR.

COMANDOS

computadora

Gestiona las cuentas de equipos.

Añade una cuenta de equipo al dominio.

Crea un nuevo dominio.

grupos_de_seguridad

Gestiona grupos de seguridad.

Gestiona usuarios.

usuarios_agregar_nombre_usuario_[opciones]

Añade un nuevo usuario.

Elimina un usuario.

usuarios_modificar_nombre_usuario_[opciones]

Modifica un usuario existente.

EJEMPLOS

Para ver una lista completa de todos los comandos disponibles, simplemente ejecute:

$ samba-tool --help

Para ver la ayuda de un comando específico, por ejemplo, 'usuarios', ejecute:

$ samba-tool users --help

Para añadir un nuevo usuario llamado "testuser" al dominio "MYDOMAIN" con la contraseña "password123", ejecute:

$ samba-tool users add testuser --password=password123 --domain=MYDOMAIN

Para eliminar un usuario llamado "testuser" del dominio "MYDOMAIN", ejecute:

$ samba-tool users delete testuser --domain=MYDOMAIN

Para mostrar información sobre un usuario llamado "testuser" en el dominio "MYDOMAIN", ejecute:

$ samba-tool users show testuser --domain=MYDOMAIN

user addunixattrs username uid-number [options]

Add RFC2307 attributes to a user.

This command adds Unix attributes to a user account in the Active Directory domain.

The username specified on the command is the sAMaccountName.

You must supply a unique uid.

Unix (RFC2307) attributes will be added to the user account.

If you supply a group id with '--gid-number', this will be used for the users Unix 'gidNumber' attribute.

If '--gid-number' is not supplied, the users Unix gidNumber will be set to the one found in 'Domain Users', this means Domain Users must have a gidNumber attribute.

If '--unix-home' is not supplied, the users Unix home directory will be set to /home/DOMAIN/username.

If '--login-shell' is not supplied, the users Unix login shell will be set to '/bin/sh'

If ---gecos' is not supplied, the users Unix gecos field will be set to the user's 'CN' attribute.

Add 'idmap_ldb:use rfc2307 = Yes' to the smb.conf on DCs to use these attributes for UID/GID mapping.

The command may be run from the root userid or another authorised userid. The -H or --URL= option can be used to execute the command against a remote server.

Example1:

samba-tool user addunixattrs User1 10001

Example1 shows how to add RFC2307 attributes to a domain enabled user account, Domain Users will be set as the users gidNumber.

The users Unix ID will be set to '10001', provided this ID isn't already in use.

Example2:

samba-tool user addunixattrs User2 10002 --gid-number=10001 --unix-home=/home/User2

Example2 shows how to add RFC2307 attributes to a domain enabled user account.

The users Unix ID will be set to '10002', provided this ID isn't already in use.

The users gidNumber attribute will be set to '10001'

The users Unix home directory will be set to '/home/user2'

Example3:

samba-tool user addunixattrs User3 10003 --gid-number=10001 --login-shell=/bin/false --gecos='User3 test'

Example3 shows how to add RFC2307 attributes to a domain enabled user account.

The users Unix ID will be set to '10003', provided this ID isn't already in use. The users gidNumber attribute will be set to '10001'. The users Unix login shell will be set to '/bin/false'. The users gecos field will be set to 'User3 test'.
