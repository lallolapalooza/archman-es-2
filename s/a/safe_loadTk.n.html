Paquete: tk

Safe Tk(n) Comandos integrados de Tk Safe Tk(n)

NOMBRE

safe::loadTk - Carga Tk en un intérprete seguro.

SINOPSIS

safe::loadTk hijo ?-use windowId? ?-display nombrePantalla?

DESCRIPCIÓN

Safe Tk se basa en Safe Tcl, que proporciona un mecanismo que permite un acceso restringido y mediado a la carga automática y a los paquetes para intérpretes seguros. Safe Tk añade la capacidad de configurar el intérprete para operaciones seguras de Tk y cargar Tk en intérpretes seguros.

El comando safe::loadTk inicializa las estructuras de datos requeridas en el intérprete seguro nombrado y luego carga Tk en él. El intérprete debe haber sido creado con safe::interpCreate o haber sido inicializado con safe::interpInit. El comando devuelve el nombre del intérprete seguro. Si se especifica -use, la ventana identificada por el identificador dependiente del sistema windowId se utiliza para contener la ventana “.” del intérprete seguro; puede ser cualquier id válido, haciendo referencia eventualmente a una ventana perteneciente a otra aplicación. Como conveniencia, si la ventana que planeas usar es una Ventana Tk de la aplicación, puedes usar el nombre de la ventana (ej. “.x.y”) en lugar de su Id de ventana (ej. desde winfo id .x.y). Cuando no se especifica -use, se crea una nueva ventana de nivel superior para la ventana “.” del intérprete seguro. En X11, si quieres que la ventana incrustada utilice una pantalla diferente a la predeterminada, especifícala con -display. Consulta la sección PROBLEMAS DE SEGURIDAD a continuación para ver detalles de implementación.

PROBLEMAS DE SEGURIDAD

Por favor, lee la página del manual de safe para Tcl para aprender sobre las consideraciones básicas de seguridad para Safe Tcl.

safe::loadTk añade el valor de tk_library tomado del intérprete padre a la ruta de acceso virtual del intérprete seguro para que la carga automática funcione en el intérprete seguro.

La inicialización de Tk es ahora segura con respecto a no confiar en el estado del hijo para el arranque. safe::loadTk registra el nombre del hijo para que cuando se llame a la inicialización de Tk (Tk_SafeInit) y ésta a su vez llame a safe::InitTk del padre, devuelva el equivalente deseado de argv (-use windowId, -display correcto, etc.).

Cuando no se usa -use, la nueva ventana de nivel superior creada está especialmente decorada para que el usuario sea siempre consciente de que la interfaz de usuario presentada proviene de un código potencialmente inseguro y pueda eliminar fácilmente el intérprete correspondiente.

En X11, una combinación conflictiva de -use y -display probablemente generará un error fatal de X.
