NOMBRE

sane-plustek_pp - Backend de SANE para escáneres planos Plustek con puerto paralelo

DESCRIPCIÓN

La biblioteca sane-plustek_pp implementa un backend SANE (Scanner Access Now Easy) que proporciona acceso a escáneres planos Plustek con puerto paralelo basados en ASIC 9600[1/3] y P9800[1/3].

NOMBRES DE DISPOSITIVO

El dispositivo predeterminado de este backend es:

0x378

Este "dispositivo predeterminado" se utilizará si no se encuentra ningún archivo de configuración. Es la dirección base del puerto paralelo en las máquinas i386.

Como el backend soporta hasta cuatro dispositivos, es posible especificarlos en el archivo de configuración

/etc/sane.d/plustek_pp.conf

Ver este archivo para obtener ejemplos.

CONFIGURACIÓN

Esta sección describe las entradas del archivo de configuración del backend. El archivo se encuentra en: /etc/sane.d/plustek_pp.conf

Para una configuración adecuada, necesitarás al menos dos entradas:

[direct]
device 0x378

direct le dice al backend que el nombre de dispositivo siguiente (aquí 0x378) debe interpretarse como un dispositivo escáner de puerto paralelo. De hecho, es la dirección a usar. Alternativamente, puedes usar /dev/parport0 si el backend ha sido compilado con soporte para libieee1284.

Opciones adicionales:

option warmup t

t especifica el período de calentamiento en segundos

option lampOff t

t es el tiempo en segundos para apagar las lámparas en modo de espera

option lOffonEnd b

b especifica el comportamiento al cerrar el backend, 1 --> apagar las lámparas, 0 --> no cambiar el estado de las lámparas

option mov m

m es el interruptor de anulación del modelo, que solo funciona en modo directo.
m = 0
predeterminado: sin anulación
m = 1
Anulación OpticPro 9630PL (funciona si se detectó OP9630) fuerza tamaño legal (14")
m = 2
Anulación Primax 4800Direct (funciona si se detectó OP600) intercambia rojo/verde
m = 3
Anulación OpticPro 9636 (funciona si se detectó OP9636) deshabilita las capacidades de transparencia/negativo del backend
m = 4
Anulación OpticPro 9636P (funciona si se detectó OP9636) deshabilita las capacidades de transparencia/negativo del backend
m = 5
Anulación OpticPro A3I (funciona si se detectó OP12000) habilita el escaneo A3
m = 6
Anulación OpticPro 4800P (funciona si se detectó OP600) intercambia rojo/verde
m = 7
Anulación Primax 4800Direct 30bit (funciona si se detectó OP4830)

Ver el archivo plustek_pp.conf para obtener ejemplos.

MODOS DE PUERTO PARALELO

El controlador actual funciona mejor cuando el puerto paralelo se configura en modo EPP. Al detectar cualquier otro modo como ECP o PS/2, el controlador intenta configurarlo en un modo más rápido y soportado. Si esto falla, utilizará el modo SPP, ya que este modo debería funcionar con todos los puertos paralelos soportados por Linux. En caso de duda, entre a su BIOS y configúrelo en cualquier modo excepto ECP.

Los modelos de escáner Plustek anteriores (4830, 9630) suministraban una tarjeta adaptadora de puerto paralelo ISA. Esta tarjeta **no** está soportada por el controlador.

Los modelos basados en ASIC 96001/3 a veces tienen problemas con los modos de alta resolución. Si encuentra imágenes corruptas esporádicas (partes duplicadas o desplazadas horizontalmente), cierre todas las demás aplicaciones antes de escanear y (si hay suficiente memoria disponible) deshabilite el intercambio (swapping).

Ver el archivo plustek_pp.conf para obtener ejemplos.

ENTORNO

SANE_CONFIG_DIR
Esta variable de entorno especifica la lista de directorios que pueden contener el archivo de configuración. En sistemas *NIX, los directorios están separados por dos puntos (`:`), bajo OS/2, están separados por un punto y coma (`;'). Si esta variable no está establecida, el archivo de configuración se busca en dos directorios predeterminados: primero, el directorio de trabajo actual (".") y luego en /etc/sane.d. Si el valor de la variable de entorno termina con el carácter separador de directorios, entonces los directorios predeterminados se buscan después de los directorios especificados explícitamente. Por ejemplo, establecer SANE_CONFIG_DIR a "/tmp/config:" resultaría en la búsqueda de los directorios tmp/config, . y /etc/sane.d (en este orden).

ENVIRONMENT

The SANE_DEBUG_PLUSTEK_PP environment variable controls the debug level for this backend. Higher debug levels increase the verbosity of the output.

Example: export SANE_DEBUG_PLUSTEK_PP=10

CONTACT AND BUG-REPORTS

Please send any information and bug-reports to:
SANE Mailing List

Additional info and hints can be obtained from our mailing-List archive at: http://www.sane-project.org/mailing-lists.html.

To obtain debug messages from the backend, please set the environment-variable SANE_DEBUG_PLUSTEK_PP before calling your favorite SANE frontend (e.g. xscanimage(1)):

export SANE_DEBUG_PLUSTEK_PP=20 ; xscanimage

The value controls the verbosity of the output.

KNOWN BUGS & RESTRICTIONS

* The Halftoning works, but the quality is poor

* Printers (especially HP models) will start to print during scanning. This in fact is a problem to other printers too, using bidirectional protocol (see www.plustek.com (TAIWAN) page for further details)

* The driver does not support these manic scalings up to 16 times the physical resolution. The only scaling is done on resolutions between the physical resolution of the CCD-sensor and the stepper motor i.e. you have a 600x1200 dpi scanner and you are scanning using 800dpi, so scaling is necessary, because the sensor only delivers 600dpi but the motor is capable to perform 800dpi steps.

* On some devices, the pictures seems bluish

ASIC 98001 based models:

* The 300dpi transparency and negative mode does not work correctly.

* There is currently no way to distinguish a model with and without transparency unit.

* The scanned images seem to be too dark (P9636T)

ASIC 96003/1 based models:

* 30bit mode is currently not supported.

* On low end systems under heavy system load the driver may lose data, which can result in picture corruption or cause the sensor to hit the scan bed.

* The scanning speed on 600x1200 dpi models is slow.

* The scanning quality of the A3I is poor.
