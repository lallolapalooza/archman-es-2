NOMBRE

sane-coolscan2 - Backend de SANE para escáneres de película Nikon Coolscan

DESCRIPCIÓN

La biblioteca sane-coolscan2 implementa un backend de SANE (Scanner Access Now Easy) que proporciona acceso a los escáneres de película Nikon Coolscan. Algunas funciones de este backend deben considerarse software de calidad beta. La mayoría de las funciones han sido estables durante mucho tiempo, pero por supuesto, el nuevo desarrollo no puede y no funcionará correctamente desde el primer día. Por favor, informe de cualquier comportamiento extraño al mantenedor del backend.

Actualmente, se sabe que los siguientes escáneres funcionan con este backend:

Modelo:                       Tipo de Conexión
---------------------------  -------------------
LS-30 (Coolscan III)         SCSI
LS-2000                      SCSI
LS-40 ED (Coolscan IV)       USB
LS-4000 ED                   IEEE 1394
LS-8000 ED                   IEEE 1394

Por favor, envíe un correo electrónico al autor del backend (andras@users.sourceforge.net) para informar de éxitos o fracasos.

OPCIONES

Las opciones que soporta el backend se pueden seleccionar a través de opciones de línea de comandos para programas como scanimage(1) o a través de elementos de GUI en xscanimage(1) o xsane(1).

Las opciones válidas de línea de comandos y su sintaxis se pueden listar usando:

scanimage --help -d coolscan2:<interfaz>:<dispositivo>

donde <interfaz> y <dispositivo> especifican el dispositivo en cuestión, como en el archivo de configuración (ver sección siguiente). El parámetro -d y su argumento se pueden omitir para obtener información sobre el primer escáner identificado. Use el comando:

scanimage -L

para listar todos los dispositivos reconocidos por su instalación de SANE.

Las opciones estarán completamente descritas por la descripción o las descripciones emergentes proporcionadas por el frontend. Aquí hay una descripción de algunas de las opciones más importantes, en la sintaxis con la que deben suministrarse a scanimage(1):

--frame <n>
Esta opción especifica en qué fotograma operar, si se utilizan un alimentador motorizado de tiras de película o un adaptador APS. El número de fotograma <n> varía de 1 al número de fotogramas disponibles, que se detecta cada vez que se inicializa el backend (generalmente cada vez que inicia el frontend).
--subframe <x>
Esta opción desplaza la ventana de escaneo la cantidad especificada (la unidad predeterminada es mm).
--infrared=sí/no
Si se establece en "sí", el escáner leerá el canal infrarrojo, permitiendo así la eliminación de defectos por software. La imagen infrarroja se lee durante un segundo escaneo, sin alterar ninguna opción. El backend no debe reiniciarse entre escaneos. Si usa scanimage(1), realice un escaneo por lotes con --batch-count=2 para obtener la información IR.
--depth <n>
Aquí <n> puede ser 8 o el número máximo de bits admitidos por el escáner (10, 12 o 14). Especifica si el escáner reduce o no los datos escaneados a 8 bits antes de enviarlos al backend. Si se usan 8 bits, se pierde información y, por lo tanto, calidad de imagen, pero la cantidad de datos es menor en comparación con profundidades mayores. Además, muchos programas de imágenes y formatos de imagen no pueden manejar profundidades mayores a 8 bits.
--autofocus
Realiza la operación de enfoque automático. A menos que se especifique lo contrario con las otras opciones ( --focus-on-centre y similares), el enfoque se realiza en el centro del área de escaneo seleccionada.
--ae-wb
--ae
Realiza un pre-escaneo para calcular los valores de exposición automáticamente. --ae-wb mantendrá el balance de blancos, mientras que --ae ajustará cada canal por separado.
--exposure
Multiplica todos los tiempos de exposición por este valor. Esto permite la corrección de la exposición sin modificar el balance de blancos.
--load
Carga la siguiente diapositiva al usar el cargador de diapositivas (solo se aplica al alimentador de lotes SF-200).
--eject
Expulsa la tira de película o la diapositiva montada al usar el cargador de diapositivas.
--reset
Reinicia el escáner. El escáner realizará la misma acción que al encenderse: expulsará la diapositiva (con el alimentador de lotes SF-200) y se calibrará. Use esto siempre que el escáner se niegue a cargar una diapositiva correctamente, lo que resulta en que --eject no funcione.

ARCHIVO DE CONFIGURACIÓN

El archivo de configuración /etc/sane.d/coolscan2.conf especifica los dispositivos que utilizará el backend. Debido a la naturaleza de los tipos de conexión admitidos SCSI, USB e IEEE 1394, el archivo de configuración predeterminado que se suministra con la distribución SANE debería funcionar sin necesidad de editarlo.

Cada línea en el archivo de configuración es de uno de los siguientes tipos, donde todas las entradas distinguen entre mayúsculas y minúsculas:

línea en blanco o que comience con un carácter '#'
Estas líneas se ignoran, por lo tanto, '#' se puede usar para incluir comentarios.
que contenga solo la palabra "auto"
Esto indica al backend que busque un escáner escaneando los buses en busca de dispositivos con identificadores conocidos. Esta es la acción predeterminada cuando no hay un archivo de configuración presente.
una línea del formato <interfaz>:<dispositivo>
Aquí <interfaz> puede ser "scsi" o "usb", y <dispositivo> es el archivo del dispositivo del escáner. Tenga en cuenta que los dispositivos IEEE 1394 son manejados por el módulo SBP-2 en el kernel y aparecen para SANE como dispositivos SCSI.

ARCHIVOS

/usr/lib/sane/libsane-coolscan2.a
La biblioteca estática que implementa este backend.
/usr/lib/sane/libsane-coolscan2.so
La biblioteca compartida que implementa este backend (presente en sistemas que admiten carga dinámica).
/etc/sane.d/coolscan2.conf
Archivo de configuración para este backend, leído cada vez que se inicializa el backend.

ENTORNO

SANE_DEBUG_COOLSCAN2
Si la biblioteca se compiló con soporte de depuración habilitado, esta variable de entorno controla el nivel de depuración para este backend. Por ejemplo, un valor de 128 solicita que se imprima toda la salida de depuración. Niveles más bajos reducen la verbosidad.

ERRORES

Actualmente, el protocolo SANE no permite actualizar automáticamente las opciones cuando el hardware cambia. Por lo tanto, el número de opciones para la opción --frame se fijará cuando se inicialice el backend (generalmente cuando el usuario ejecuta el frontend). En particular, si no hay una tira de película en el alimentador automático de tiras de película cuando se inicializa el backend, la opción --frame no aparecerá en absoluto. Además, se recomienda encarecidamente reiniciar el frontend después de cambiar los adaptadores de película.

Los kernels de Linux anteriores a 2.4.19 tenían un parche que truncaba los datos de INQUIRY de los escáneres IEEE 1394 a 36 bytes, descartando información vital sobre el escáner. Por lo tanto, los modelos IEEE 1394 solo funcionan con 2.4.19 o posterior.

Actualmente no hay errores reales conocidos
