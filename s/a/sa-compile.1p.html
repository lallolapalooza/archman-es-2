NOMBRE

sa-compile - compilar el conjunto de reglas de SpamAssassin a código nativo

SINOPSIS

sa-compile [opciones]

Opciones:

--list                        Mostrar la lista de cadenas base en STDOUT
--sudo                        Usar 'sudo' para la escalada de privilegios
--keep-tmps                   Mantener los archivos temporales en lugar de eliminarlos
-C path, --configpath=path, --config-file=path
                              Ruta al directorio de configuración estándar
-p prefs, --prefspath=file, --prefs-file=file
                              Establecer el archivo de preferencias del usuario
--siteconfigpath=path         Ruta para configuraciones del sitio
                              (predeterminado: /usr/etc/mail/spamassassin)
--updatedir=path              Directorio donde colocar las actualizaciones
        (predeterminado: /var/lib/spamassassin/compiled/<perlversion>/4.000001)
--cf='config line'            Línea de configuración adicional
-D, --debug [area=n,...]      Imprimir mensajes de depuración
-V, --version                 Imprimir versión
-h, --help                    Imprimir mensaje de uso

DESCRIPCIÓN

sa-compile utiliza "re2c" para compilar las partes del conjunto de reglas de SpamAssassin de todo el sitio. Ninguna parte de user_prefs ni ningún archivo incluido desde user_prefs puede ser incorporado al conjunto compilado.

Este conjunto compilado es utilizado luego por el plugin "Mail::SpamAssassin::Plugin::Rule2XSBody" para acelerar la operación de SpamAssassin, cuando sea posible, y cuando ese plugin esté cargado.

"re2c" puede hacer coincidir cadenas mucho más rápido que el código perl, construyendo un DFA para hacer coincidir muchas cadenas simples en paralelo, y compilando eso a código nativo. No todas las reglas de SpamAssassin son susceptibles a esta conversión, sin embargo.

Esto requiere que "re2c" (ver "https://re2c.org/"), y el compilador C utilizado para construir módulos XS de Perl, estén instalados.

Tenga en cuenta que ejecutar esto, y crear un conjunto de reglas compilado, no tendrá ningún efecto en la velocidad de escaneo de SpamAssassin a menos que también edite su archivo "v320.pre" y se asegure de que esta línea no esté comentada:

loadplugin Mail::SpamAssassin::Plugin::Rule2XSBody

Además, "sa-compile" no reiniciará "spamd" ni causará automáticamente que un escáner recargue el conjunto de reglas ahora compilado.

OPCIONES

--list
Mostrar las cadenas base extraídas en STDOUT, en lugar de generar el código de extensión C.
--sudo
Usar sudo(8) para ejecutar código como 'root' al escribir archivos en el área de almacenamiento de reglas compiladas (que es "/var/lib/spamassassin/compiled/5.042/4.000001" por defecto).
--quiet
Producir menos salida de diagnóstico. Los errores aún se mostrarán.
--keep-tmps
Mantener los archivos temporales después de que el script complete, en lugar de eliminarlos.
-C ruta, --configpath=ruta, --config-file=ruta
Usar la ruta especificada para localizar los archivos de configuración distribuidos. Ignorar los directorios predeterminados (generalmente "/usr/share/spamassassin" o similar).
--siteconfigpath=ruta
Usar la ruta especificada para localizar los archivos de configuración específicos del sitio. Ignorar los directorios predeterminados (generalmente "/etc/mail/spamassassin" o similar).
--updatedir
Por defecto, "sa-compile" utilizará el directorio de actualización de reglas a nivel de sistema: 
/var/lib/spamassassin/compiled/5.042/4.000001

Si las actualizaciones deben almacenarse en otra ubicación, especifíquela aquí.

Tenga en cuenta que no se recomienda el uso de esta opción; si sa-compile está colocando las reglas compiladas en el directorio incorrecto, probablemente necesite recompilar SpamAssassin con argumentos diferentes de "Makefile.PL", en lugar de anular el comportamiento en tiempo de ejecución de sa-compile.

--cf='línea de configuración'
Añadir líneas de configuración adicionales directamente desde la línea de comandos, analizadas después de leer los archivos de configuración. Se pueden usar múltiples argumentos --cf, y cada uno se considerará una línea de configuración separada.
-p prefs, --prefspath=prefs, --prefs-file=prefs
Leer las preferencias de puntuación del usuario desde prefs (generalmente "$HOME/.spamassassin/user_prefs").
-D [área,...], --debug [área,...]
Producir salida de depuración. Si no se enumeran áreas, se imprime toda la información de depuración. La salida de diagnóstico también se puede habilitar para cada área individualmente; área es el área del código a instrumentar.

Para más información sobre qué áreas (también conocidas como canales) están disponibles, por favor vea la documentación en https://wiki.apache.org/spamassassin/DebugChannels.

-h, --help
Imprimir mensaje de ayuda y salir.
-V, --version
Imprimir la versión de sa-compile y salir.

NAME

sa-compile - compile spamassassin rules into a binary format

SYNOPSIS

sa-compile [options] [rule-file...]

DESCRIPTION

The sa-compile command compiles SpamAssassin(1) rules from text files into a more efficient binary format. This can significantly speed up the rule checking process. The compiled rules are stored in files with the extension .psbin..

If no rule files are specified on the command line, sa-compile will attempt to compile all the rules found in the standard SpamAssassin configuration directories.

OPTIONS

-h, --help
Show a help message and exit.
-V, --version
Show version information and exit.
-v, --verbose
Increase verbosity.
-D, --debug [debug-level]
Enable debugging output. The debug-level can be a comma-separated list of subsystems to debug.
-p, --progress
Show progress indicators.
-f, --force
Force recompilation even if the binary file is newer than the source.
-q, --quiet
Suppress informational messages.
-k, --keep-source
Do not remove the source rule files after successful compilation.
-P, --precompile-dir directory
Use the specified directory for storing precompiled rules.
-R, --rules-dir directory
Use the specified directory as the source of rules.
-H, --hashed-dir directory
Use the specified directory for hashed rules.

EXAMPLES

Compile all rules in the current directory: 

sa-compile

Compile a specific rule file: 

sa-compile myspamrules.cf

Compile rules and store them in a specific directory: 

sa-compile -P /etc/spamassassin/compiled/

ENVIRONMENT

The following environment variables can affect sa-compile:

SPAMASSASSIN_DATA
Specifies the directory containing SpamAssassin data files, including default rule sets. If not set, SpamAssassin will use its default installation paths.

FILES

/etc/spamassassin/
Default directory for SpamAssassin configuration and rule files.
/usr/share/spamassassin/
Default directory for SpamAssassin's distributed rule sets.
*.cf
Rule files typically end with the .cf. extension.
*.psbin
Compiled binary rule files.
