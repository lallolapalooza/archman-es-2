SAR2PCP(1) Manual de Comandos Generales SAR2PCP(1)

NOMBRE

sar2pcp - importar datos sar y crear un archivo PCP

SINOPSIS

sar2pcp archivo_entrada archivo_salida

DESCRIPCIÓN

sar2pcp está destinado a leer un archivo binario de informes de actividad del sistema (sar) tal como lo crea sadc(1) (archivo_entrada) y traducirlo a un archivo Performance Co-Pilot (PCP) con el nombre base archivo_salida.

Sin embargo, si archivo_entrada tiene el sufijo ``.xml'', entonces se considerará que ya está en formato XML y sar2pcp operará directamente sobre él.

El archivo PCP resultante puede ser utilizado con todas las herramientas cliente de PCP para graficar subconjuntos de los datos usando pmchart(1), realizar reducción y generación de informes de datos, filtrar con el motor de inferencia de PCP pmie(1), etc.

Se crearán una serie de archivos físicos con el prefijo archivo_salida. Estos son archivo_salida.0 (los datos de rendimiento), archivo_salida.meta (los metadatos que describen los datos de rendimiento) y archivo_salida.index (un índice temporal para mejorar la eficiencia de las operaciones de reproducción del archivo). Si alguno de estos archivos ya existe, entonces sar2pcp **no** los sobrescribirá y saldrá con un mensaje de error con la forma

_&__pmLogNewFile: ``blah.0'' ya existe, no se sobrescribe

sar2pcp es un script de Perl que utiliza el wrapper de Perl PCP::LogImport sobre la biblioteca PCP libpcp_import, y como tal podría ser utilizado como ejemplo para desarrollar nuevas herramientas para importar otros tipos de datos de rendimiento y crear archivos PCP. También está disponible un módulo wrapper de Python.

NOTAS

A partir de la versión 12.0.5 de sysstat, sadc(1) ha añadido funcionalidad para escribir directamente archivos de archivo PCP. Para producir archivos de archivo desde sar, ejecute:

$ sadf -l -O pcparchive=NOMBRE_ARCHIVO sar.dat -- -A

ADVERTENCIAS

Cuando no se utiliza la opción de entrada XML, sar2pcp requiere que archivo_entrada haya sido creado por una versión de sadc(1) de http://sebastien.godard.pagesperso-orange.fr/ que incluya la utilidad sadf(1) para traducir archivo_entrada a un flujo XML (cualquiera desde la versión 6); sar2pcp ejecutará automáticamente sadf(1) y traducirá el XML resultante a un archivo PCP.

Al usar archivos sadc binarios, es importante asegurarse de que el sadf instalado sea compatible con la versión de sadc que generó originalmente los archivos binarios. Simplemente asumir que una versión instalada más reciente funcionará es, desafortunadamente, demasiado optimista, ni se debe asumir que los datos binarios de diferentes plataformas (por ejemplo, diferente endianidad) funcionarán; estos problemas se deben a limitaciones en sadc y sadf, y no en sar2pcp en sí mismo.

Afortunadamente, el mensaje de sadf que indica que se ha detectado una incompatibilidad es consistente en todas las versiones y siempre está precedido por

Archivo de actividad del sistema inválido

Usar un archivo_entrada XML tiene la ventaja de que se omite por completo la versión instalada de sadf. sar2pcp se compromete a transformar cualquier XML válido producido por cualquiera de las diferentes variaciones de sadf en un archivo PCP válido. Cualquier versión de PCP podrá interpretar los archivos de archivo producidos por cualquier versión de sar2pcp, y también puede mover libremente el archivo binario PCP entre diferentes plataformas, hardware diferente, incluso sistemas operativos diferentes; ¡Simplemente Funciona (TM)!

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede ser utilizada para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

Para las variables de entorno que afectan a las herramientas de PCP, consulte pmGetOptions(3).
