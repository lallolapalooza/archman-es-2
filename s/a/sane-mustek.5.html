NOMBRE

sane-mustek - Backend SANE para escáneres planos SCSI Mustek (y algunos otros dispositivos)

DESCRIPCIÓN

La biblioteca sane-mustek implementa un backend SANE (Scanner Access Now Easy) que proporciona acceso a escáneres planos SCSI y de puerto paralelo Mustek (y algunos Trust y Primax remarcados). Actualmente, se sabe que los siguientes escáneres funcionan más o menos con este backend:

Paragon MFS-6000CX
Paragon MFS-12000CX
Paragon MFC-600S, 600 II CD, ScanMagic 600 II SP
Paragon MFC-800S, 800 II SP
Paragon MFS-6000SP
Paragon MFS-8000SP
Paragon MFS-1200SP, MFS-12000SP
ScanExpress 6000SP
ScanExpress 12000SP, 12000SP Plus, Paragon 1200 III SP, ScanMagic 9636S, 9636S Plus
Paragon 1200 LS
ScanExpress A3 SP
Paragon 1200 SP Pro
Paragon 1200 A3 Pro/1200 A3 Pro
Paragon 600 II EP
Paragon 600 II N
Trust Imagery 1200
Trust Imagery 1200 SP
Trust Imagery 4800 SP
Trust SCSI Connect 19200
Primax Compact 4800 SCSI

Puede encontrar más detalles en la página principal del backend SCSI de Mustek http://www.meier-geinitz.de/sane/mustek-backend/.

¡No mezcle los modelos MFS (Paragon), Pro y ScanExpress! Son completamente diferentes. ¡Verifique el nombre exacto del modelo! Tenga en cuenta que hemos encontrado algunos modelos Mustek que no tienen la marca Paragon específicamente (por ejemplo, "1200 A3 Pro"), pero que también se sabe que funcionan.

Tenga en cuenta que la mayoría de los escáneres mencionados anteriormente vienen con una interfaz SCSI. Los únicos escáneres no SCSI que tienen algún soporte en este momento son los escáneres 600 II N y 600 II EP. El primero viene con su propio adaptador de puerto paralelo (es decir, no se conecta al puerto de la impresora). Ambos escáneres también usan el protocolo SCSI internamente. Encontrará más información sobre cómo usar estos escáneres de puerto paralelo en la sección ESCÁNERES DE PUERTO PARALELO a continuación. Otros escáneres de puerto paralelo no son soportados por este backend, pero puede tener éxito utilizando el backend de puerto paralelo Mustek mustek_pp, consulte sane-mustek_pp(5). Los escáneres USB tampoco son soportados por este backend, pero los backends ma1509, mustek_usb, gt68xx y plustek incluyen soporte para algunos de ellos, consulte sane-ma1509(5), sane-mustek_usb(5), sane-gt68xx(5) y sane-plustek(5).

Los escáneres Mustek no tienen protección contra la superación del área física de escaneo en altura. Es decir, si se intenta un escaneo con una altura que excede la altura de la superficie de escaneo, el escáner comenzará a hacer ruidos fuertes y el mecanismo de escaneo puede dañarse. Por lo tanto, si escucha un ruido de este tipo, apague INMEDIATAMENTE el escáner. Esto no debería ocurrir si su escáner está en la lista de escáneres conocidos. Hay más información en el archivo /usr/share/doc/sane/PROBLEMS.

Si usted posee un escáner Mustek (o Trust) que no sea uno de los listados anteriormente que funcione con este backend, por favor háganoslo saber enviando el nombre exacto del modelo del escáner (mírelo al frente y al dorso del escáner) y una salida de depuración a sane-devel@alioth-lists.debian.net. Puede obtener la salida de depuración configurando la variable de entorno SANE_DEBUG_MUSTEK a 5 y mostrando la lista de escáneres disponibles con scanimage -L. Por favor, envíe todo a la lista de correo. Debe estar suscrito a sane-devel antes de poder enviar correo a la lista. Consulte http://www.sane-project.org/mailing-lists.html para más detalles.

NOMBRES DE DISPOSITIVO

Este backend espera nombres de dispositivo del tipo:

especial

Donde especial es el nombre de ruta del dispositivo especial que corresponde a un escáner SCSI o el número de puerto en el que se pueden encontrar los escáneres de puerto paralelo (ver sección ESCÁNERES DE PUERTO PARALELO a continuación). Para escáneres SCSI, el nombre del dispositivo especial debe ser un dispositivo SCSI genérico o un enlace simbólico a dicho dispositivo. El programa sane-find-scanner(1) ayuda a averiguar el dispositivo correcto. En Linux, un nombre de dispositivo así podría ser /dev/sg0 o /dev/sg3, por ejemplo. Consulte sane-scsi(5) para más detalles.

CONFIGURACIÓN

El contenido del archivo mustek.conf es una lista de opciones y nombres de dispositivos que corresponden a los escáneres Mustek. Las líneas vacías y las líneas que comienzan con un signo de almohadilla (#) se ignoran. Consulte sane-scsi(5) sobre los detalles de lo que constituye un nombre de dispositivo válido.

Las opciones soportadas son linedistance-fix, lineart-fix, legal-size, buffersize, blocksize, strip-height, disable-double-buffering, disable-backtracking y force-wait.

Las opciones vienen en dos sabores: globales y posicionales. Las opciones globales se aplican a todos los dispositivos administrados por el backend, mientras que las opciones posicionales se aplican solo al dispositivo mencionado más recientemente. ¡Tenga en cuenta que el orden en que aparecen las opciones es importante!

La opción linedistance-fix es posicional y soluciona un problema que ocurre con algunos controladores SCSI (notablemente el controlador ncr810 bajo Linux). Si los escaneos en color tienen rayas horizontales y/o los colores están apagados, es probable que su controlador sufra este problema. Activar esta opción generalmente soluciona el problema.

La opción lineart-fix es posicional y soluciona un problema de temporización que parece existir con ciertos escáneres MFS-12000SP. El problema se manifiesta en líneas perdidas al escanear en modo lineart. Activar esta opción debería solucionar el problema, pero puede ralentizar un poco el escaneo.

La opción legal-size es posicional y establece el tamaño del área de escaneo al formato Legal. Configure esta opción si posee un Paragon 12000 LS. No puede distinguirse por software de un ScanExpress 12000 SP (formato ISO A4).

La opción buffersize es una opción posicional que anula el valor predeterminado establecido para el tamaño del búfer SCSI. El tamaño del búfer se especifica en kilobytes. El valor predeterminado es 128. Debido a la doble búferización, el búfer que se envía realmente al escáner es la mitad del tamaño de este valor. Intente aumentar este valor para lograr mayores velocidades de escaneo. Tenga en cuenta que algunos escáneres ScanExpress no aceptan tamaños de búfer superiores a 64 kb (buffersize = 128). Si su controlador sg no puede establecer tamaños de búfer SCSI en tiempo de ejecución, es posible que también tenga que cambiar ese valor. Consulte sane-scsi(5) para más detalles.

La opción blocksize es una opción posicional que anula el valor predeterminado establecido para la cantidad máxima de datos escaneados en un solo bloque. El tamaño del búfer se especifica en kilobytes. Algunos escáneres se congelan si este valor es mayor que 2048. El valor predeterminado es 1 GB (por lo tanto, efectivamente sin límite) para la mayoría de los escáneres. No cambie este valor si no sabe exactamente lo que está haciendo.

La opción strip-height es una opción global que limita la altura máxima de la tira escaneada con un solo comando de lectura SCSI. La altura se especifica en pulgadas y puede contener una parte fraccionaria (por ejemplo, 1.5). Establecer la altura de la tira a un valor pequeño (una pulgada, por ejemplo) reduce la probabilidad de encontrar problemas con los tiempos de espera del controlador SCSI y/o tiempos de espera con otros dispositivos en el mismo bus SCSI. Desafortunadamente, también aumenta los tiempos de escaneo. Con los adaptadores y controladores SCSI actuales, esta opción ya no debería ser necesaria.

La opción disable-double-buffering es una opción global. Si se establece, el backend enviará solo un búfer a la vez al escáner. Pruebe esta opción si tiene problemas al escanear, por ejemplo, errores SCSI, congelamientos o si los primeros centímetros se repiten una y otra vez en su imagen.

La opción disable-backtracking es una opción posicional. Si se establece, el escáner no retrocederá su deslizador después de que se llene cada búfer SCSI (`backtracking'). Establecer esta opción dará como resultado escaneos más rápidos, pero también puede producir rayas horizontales. Esta opción no funciona con todos los escáneres (solo algunos de los modelos Paragon pueden modificar el backtracking).

Finalmente, force-wait es una opción global. Si se establece, el backend esperará hasta que el dispositivo esté listo antes de enviar el comando de consulta. Además, el backend forzará que el deslizador del escáner regrese a su posición inicial (no implementado para todos los escáneres). Esta opción puede ser necesaria con el 600 II N o cuando se utiliza scanimage(1) varias veces (por ejemplo, en scripts). El valor predeterminado es desactivado (n

This backend does not support USB scanners. Use the sane-mustek_usb(5) backend for those.

DEVICE NAMES

This backend supports scanners attached through a parallel port or through a SCSI adapter.

For parallel port scanners, device names are of the form /dev/parportX, where X is the parallel port number (usually 0 or 1). If you don't know the correct value, you can try scanimage(1) with the -L option.

For SCSI scanners, device names are typically of the form /dev/sgX or /dev/sge. You can find the correct device name using the sane-find-scanner(1) command.

CONFIGURATION

The configuration file for the Mustek backend is located in /etc/sane.d/mustek.conf. The file contains configuration options that are effective for all scanners supported by this backend. A sample configuration file is shown below:

# limit strip height of all scanners to 1.5 inches:
option strip-height 1.5
/dev/scanner # first Mustek scanner
# 1 MB buffer for /dev/scanner:
option buffersize 1024
/dev/sge # second Mustek scanner
# turn on fixes for /dev/sge:
option lineart-fix
option linedistance-fix

SCSI ADAPTER TIPS

You need a SCSI adapter for the SCSI scanners. Even if the connector is the same as that of parallel port scanners, connecting it to the computers parallel port will NOT work.

Mustek SCSI scanners are typically delivered with an ISA SCSI adapter. Unfortunately, that adapter is not worth much since it is not interrupt driven. It is (sometimes) possible to get the supplied card to work, but without interrupt line, scanning will be very slow and put so much load on the system, that it becomes almost unusable for other tasks.

If you already have a working SCSI controller in your system, you should consider that Mustek scanners do not support the SCSI-2 disconnect/reconnect protocol and hence tie up the SCSI bus while a scan is in progress. This means that no other SCSI device on the same bus can be accessed while a scan is in progress.

Because the Mustek-supplied adapter is not worth much and because Mustek scanners do not support the SCSI-2 disconnect/reconnect protocol, it is recommended to install a separate (cheap) SCSI controller for Mustek scanners. For example, ncr810 based cards are known to work fine and cost as little as fifty US dollars.

For Mustek scanners, it is typically necessary to configure the low-level SCSI driver to disable synchronous transfers (sync negotiation), tagged command queuing, and target disconnects. See sane-scsi(5) for driver- and platform-specific information.

The ScanExpress models have sometimes trouble with high resolution color mode. If you encounter sporadic corrupted images (parts duplicated or shifted horizontally) kill all other applications before scanning and (if sufficient memory is available) disable swapping.

Details on how to get the Mustek SCSI adapters and other cards running can be found at http://www.meier-geinitz.de/sane/mustek-backend/#SCSI.

PARALLEL PORT SCANNERS

This backend has support for the Paragon 600 II EP and Paragon 600 II N parallel port scanners. Note that the latter scanner comes with its own ISA card that implements a funky parallel port (in other words, the scanner does not connected to the printer parallel port).

These scanners can be configured by listing the port number of the adapter or the parallel port in the mustek.conf file. Valid port numbers for the 600 II N are 0x26b, 0x2ab, 0x2eb, 0x22b, 0x32b, 0x36b, 0x3ab, 0x3eb. For the 600 II EP use one of these: parport0, parport1, parport2, 0x378, 0x278, 0x3bc. Pick one that doesn't conflict with the other hardware in your computer. Put only one number on a single line. Example:

0x3eb

Note that for these scanners usually root privileges are required to access the I/O ports. Thus, either make frontends such as scanimage(1) and xscanimage(1) setuid root (generally not recommended for security reasons) or, alternatively, access this backend through the network daemon saned(8).

If the Mustek backend blocks while sending the inquiry command to the scanner, add the option force-wait to mustek.conf.

Also note that after a while of no activity, some scanners themselves (not the SANE backend) turns off their CCFL lamps. This shutdown is not always perfect with the result that the lamp sometimes continues to glow dimly at one end. This doesn't appear to be dangerous since as soon as you use the scanner again, the lamp turns back on to the normal high brightness. However, the first image scanned after such a shutdown may have stripes and appear to be over-exposed. When this happens, just take another scan, and the image will be fine.

ENVIRONMENT

SANE_CONFIG_DIR
This environment variable specifies the list of directories that may contain the configuration file. On *NIX systems, the directories are separated by a colon (`:'), under OS/2, they are separated by a semi-colon (`;'). If this variable is not set, the configuration file is searched in two default directories: first, the current working directory (".") and then in /etc/sane.d. If the value of the environment variable ends with the directory separator character, then the default directories are searched after the explicitly specified directories. For example, setting SANE_CONFIG_DIR to "/tmp/config:" would result in directories tmp/config, ., and /etc/sane.d being searched (in this order).
SANE_DEBUG_MUSTEK
If the library was compiled with debug support enabled, this environment variable controls the debug level for this backend. Higher debug levels increase the verbosity of the output. 
Value  Description
0      no output
1      print fatal errors
2      print important messages
3      print non-fatal errors and less important messages
4      print all but debugging messages
5      print everything

Example: export SANE_DEBUG_MUSTEK=4

BUGS

Scanning with the SCSI adapters supplied by Mustek is very slow at high resolutions and wide scan areas.

Some scanners (e.g. Paragon 1200 A3 + Pro, SE A3) need more testing.

The gamma table supports only 256 colors, even if some scanners can do more.

More detailed bug information is available at the Mustek backend homepage: http://www.meier-geinitz.de/sane/mustek-backend/.
