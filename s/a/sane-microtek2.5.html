NOMBRE

sane-microtek2 - Backend SANE para escáneres Microtek con conjunto de comandos SCSI-2

DESCRIPCIÓN

La biblioteca sane-microtek2 implementa un backend SANE (Scanner Access Now Easy) que proporciona acceso a escáneres Microtek con un conjunto de comandos SCSI-2. Este backend puede considerarse de alfa a beta. Se informa que algunos modelos de escáner funcionan bien, otros no.

Existe un backend diferente para escáneres Microtek con conjunto de comandos SCSI-1. Consulte sane-microtek(5) para más detalles.

Y hay progreso parcial para el ScanMaker 3600. Ver http://sourceforge.net/projects/sm3600.

En la actualidad, los siguientes escáneres se sabe que funcionan correctamente con este backend:

Microtek   X6                SCSI
Microtek   X6EL              SCSI
Microtek   X6USB             USB
Microtek   ScanMaker V300    Parport y SCSI
Microtek   ScanMaker V310    Parport y SCSI
Microtek   ScanMaker V600    Parport y SCSI
Microtek   ScanMaker 330     SCSI
Microtek   ScanMaker 630     SCSI
Microtek   ScanMaker 636     SCSI
Microtek   ScanMaker 9600XL  SCSI; ¿solo modo plano?
Microtek   Phantom 330CX     Parport

Microtek   Phantom 636       SCSI

Se puede encontrar información adicional en http://www.sane-project.org/.

Si posee un escáner Microtek diferente a los enumerados anteriormente, ¡puede que funcione o no con SANE! Debido a que escáneres equivalentes se venden bajo diferentes nombres en diferentes países, su modelo puede ser equivalente a uno de los anteriores.

Los escáneres parport funcionan con los módulos del kernel ppscsi + onscsi. Consulte http://cyberelk.net/tim/parport/ppscsi.html y http://penguin-breeder.org/kernel/download/.

Los escáneres USB funcionan con el módulo del kernel microtek. Es posible que tenga que añadir los códigos de proveedor y modelo a microtek.c si aún no están listados allí.

¡Tanto los escáneres parport como los USB necesitan el soporte SCSI genérico, así que compruebe si ha cargado los módulos scsi_mod y sg!

Si prueba su escáner por primera vez, manténgalo vigilado. Si recibe comandos que no entiende, el cabezal de escaneo puede ir más allá del área de escaneo. El escáner entonces hace ruidos extraños. ¡En este caso, apague inmediatamente el escáner o desconecte su cable de alimentación para evitar daños!

Si su escáner es diferente a los modelos mencionados anteriormente y está funcionando, por favor informe al autor. Sería bueno si añadiera un archivo de registro a esta información (creación del archivo de registro: ver abajo).

Si su escáner no funciona correctamente, también debería crear un archivo de registro y enviárselo al autor. Él utilizará la información para mejorar el backend y posiblemente hacer que su escáner funcione.

¿Cómo crear el archivo de registro?

- poner la línea

"option dump 2" en su archivo microtek2.conf o cambiar el "option dump" existente a "2"
- en una terminal (bash) escribir

"export SANE_DEBUG_MICROTEK2=30" y luego
"scanimage -l0 -t0 -x100 -y20 2>scan.log >sout.pnm"
Obtiene dos archivos: scan.log contiene el archivo de registro y sout.pnm la imagen escaneada (si se escaneó algo). Comprímalo antes de enviarlo.

OPCIONES DEL FRONTEND

Este backend habilita dinámicamente las opciones para el frontend, que son compatibles con el escáner en dependencia del modo de escaneo y otras opciones. Las opciones no compatibles se deshabilitan.

Las siguientes opciones son compatibles con el controlador sane-microtek2:

Escaneos en color, escala de grises, tramado y lineart.

Control de luces altas, tonos medios, sombras, contraste, brillo, tiempo de exposición, corrección gamma, umbral (dependiente del modo de escaneo y de las capacidades del escáner)

Adaptador de medios de transparencia, alimentador automático de documentos

Se pueden habilitar o deshabilitar opciones adicionales en el archivo microtek2.conf. Consulte la sección de configuración de esta página de manual.

NOMBRES DE DISPOSITIVO

Este backend espera nombres de dispositivo del tipo:

especial

Donde especial es la ruta de acceso UNIX al dispositivo especial que corresponde al escáner. El nombre del dispositivo especial debe ser un dispositivo SCSI genérico o un enlace simbólico a dicho dispositivo. En Linux, un nombre de dispositivo así podría ser /dev/sga o /dev/sge, por ejemplo.

CONFIGURACIÓN

El archivo de configuración para este backend reside en /etc/sane.d/microtek2.conf.

Su contenido es una lista de nombres de dispositivo que corresponden a escáneres Microtek con interfaz SCSI-2. Las líneas vacías y las líneas que comienzan con un signo de almohadilla (#) se ignoran.

El archivo de configuración también puede contener opciones. Las opciones globales que son válidas para todos los dispositivos se colocan antes de los nombres de dispositivo. Las opciones específicas del dispositivo se colocan debajo del nombre del dispositivo. Tenga en cuenta que, excepto para la opción dump <n> y la opción strip-height <n>, la entrada en el archivo microtek2.conf solo habilita la opción correspondiente para ser mostrada en el frontend. Allí, en el frontend, puede activar y desactivar las opciones. Actualmente, las siguientes opciones son compatibles:

option dump <n>
option strip-height <n>
option no-backtrack-option <on/off>
option lightlid-35 <on/off>
option toggle-lamp <on/off>
option lineart-autoadjust <on/off>
option backend-calibration <on/off>
option colorbalance-adjust <on/off>

option dump <n> habilita la impresión de información adicional sobre los comandos SCSI que se envían al escáner a la salida de error estándar. Esta opción es principalmente útil para fines de depuración. Esta opción debe ser una opción global y se coloca mejor en la parte superior del archivo microtek2.conf.

Si n=1, el contenido de los bloques de comandos y los resultados para el comando INQUIRY y READ SCANNER ATTRIBUTES se imprimen en la salida de error estándar.

Si n=2, el contenido de los bloques de comandos para todos los demás comandos SCSI también se imprime en la salida de error estándar. Si n=3, el contenido de la tabla gamma también se imprime. Si n=4, todos los datos de escaneo se imprimen adicionalmente en la salida de error estándar.

El valor predeterminado es n=1.

option strip-height <n> , donde <n> es un número de punto flotante, limita la cantidad de datos que se leen del escáner con un solo comando de lectura. La unidad es pulgadas y <n> por defecto es 1.0, si esta opción no se establece en el archivo de configuración. Si menos de <n> pulgadas de datos caben en el búfer SCSI, entonces se utiliza el valor menor y esta opción no tiene efecto.

Si su sistema tiene un búfer SCSI grande y desea utilizar todo el búfer, aumente el valor de <n>. Por ejemplo, si <n> se establece en 14.0, no se aplican restricciones para escáneres con un área de escaneo de tamaño carta, legal o A4.

Las siguientes opciones habilitan o deshabilitan opciones adicionales del frontend. Si una opción se establece en <on>, aparecerá una opción apropiada en el frontend.

option no-backtrack-option <on/off> evita que el cabezal del escáner retroceda entre los comandos de lectura. Esto acelera el escaneo. Pruébelo.

option lightlid-35 <on/off> Si utiliza el adaptador de transparencia LightLid-35, obtendrá una opción avanzada que apaga la lámpara del escáner plano durante el escaneo.

option toggle-lamp <on/off> Obtendrá un botón en el frontend donde podrá encender y apagar la lámpara del escáner plano.

option lineart-autoadjust <on/off> Puede indicar al backend que intente determinar un buen valor para el umbral del lineart

NOMBRE

sane-microtek2 - SANE backend para escáneres Microtek

DESCRIPCIÓN

El backend microtek2 es una biblioteca compartida que implementa la interfaz del backend SANE API versión 1 para los escáneres de la marca Microtek.

Actualmente este backend soporta los siguientes escáneres:

  • Microtek ScanMaker V 300
  • Microtek ScanMaker V 600
  • Microtek ScanMaker 3300
  • Microtek ScanMaker 3450
  • Microtek ScanMaker 3550
  • Microtek ScanMaker 3600
  • Microtek ScanMaker 3650
  • Microtek ScanMaker 3750
  • Microtek ScanMaker 4550
  • Microtek ScanMaker 4750
  • Microtek ScanMaker 5550
  • Microtek ScanMaker 5750
  • Microtek ScanMaker 6000
  • Microtek ScanMaker 6400
  • Microtek ScanMaker 6450
  • Microtek ScanMaker 6600
  • Microtek ScanMaker 6650
  • Microtek ScanMaker 8000
  • Microtek ScanMaker 8400
  • Microtek ScanMaker 8500
  • Microtek ScanMaker 9000
  • Microtek ScanMaker 9500
  • Microtek Phantom 330 CX
  • Microtek Phantom 636 CX
  • Microtek ScanPort 1200
  • Microtek ScanPort 2000
  • Microtek ScanPort 4000
  • Microtek ScanPort 5000

Es posible que otros escáneres Microtek también funcionen.

OPCIONES DEL FRONTEND

Los frontends pueden usar las siguientes opciones para controlar el backend:

option dump <0/1>
Si se establece en 1, el backend volcará los datos crudos del escáner a un archivo. El nombre del archivo será /tmp/microtek2.dump.
option strip-height <valor>
Establece la altura de las tiras en píxeles. El valor predeterminado es 1.0. Los escáneres más recientes a menudo requieren un valor más alto (por ejemplo, 14.0). Este valor también puede afectar la velocidad de escaneo.
option no-backtrack-option <on/off>
Algunos escáneres más antiguos necesitan que la opción de retroceso se desactive. Si su escáner no funciona, intente habilitar esta opción.
option lightlid-35 <on/off>
Esta opción activa el soporte para el adaptador de diapositivas/negativos de Microtek. Si no está usando el adaptador de diapositivas, asegúrese de que esta opción esté desactivada para obtener la mejor calidad de imagen.
option toggle-lamp <on/off>
Si está activada, la lámpara del escáner se apagará después de un escaneo y se volverá a encender antes del siguiente. Esto puede ser útil para prolongar la vida útil de la lámpara.
option lineart-autoadjust <on/off>
Si está activada, el backend intentará ajustar automáticamente el umbral de línea para los escaneos en modo lineart.
option backend-calibration <on/off>
Algunos escáneres (por ejemplo, Phantom 330CX y 636CX) necesitan que los datos sean calibrados por el backend. Pruebe esta opción si ve rayas verticales en sus imágenes.
option colorbalance-adjust <on/off>
Algunos escáneres (por ejemplo, Phantom 330CX y 636CX) necesitan tener balanceado el color corregido. Si esta opción está habilitada, obtendrá opciones avanzadas donde podrá balancear los colores. Y tendrá un botón para usar los valores que proporciona el firmware del escáner.

A continuación se muestra un archivo de configuración de ejemplo:

option dump 1
option strip-height 1.0
/dev/scanner
option no-backtrack-option on
# este es un comentario
/dev/sge
option lightlid-35 on

Este backend también soporta el nuevo formato de archivo de configuración que facilita la detección de escáneres bajo Linux. Si solo tiene un escáner, sería mejor usar el siguiente archivo de configuración para este backend:

option dump 1
option strip-height 14.0
option no-backtrack-option on
option backend-calibration on
option lightlid-35 on
option toggle-lamp on
option lineart-autoadjust on
option colorbalance-adjust off
scsi * * Scanner

En este caso, todos los escáneres SCSI deberían detectarse automáticamente debido a la línea

scsi * * Scanner

.

ARCHIVOS

/etc/sane.d/microtek2.conf
El archivo de configuración del backend.
/usr/lib/sane/libsane-microtek2.a
La biblioteca estática que implementa este backend.
/usr/lib/sane/libsane-microtek2.so
La biblioteca compartida que implementa este backend (presente en sistemas que soportan carga dinámica).

MEDIO AMBIENTE

SANE_DEBUG_MICROTEK2
Si la biblioteca fue compilada con soporte de depuración habilitado, esta variable de entorno controla el nivel de depuración para este backend. Por ejemplo, un valor de 255 solicita que se imprima toda la salida de depuración. Niveles más pequeños reducen la verbosidad. Para ver mensajes de error en stderr, establezca SANE_DEBUG_MICROTEK2 en 1 (Nota: Los niveles de depuración en su conjunto deberían revisarse mejor).
Por ejemplo, solo diga:
export SANE_DEBUG_MICROTEK2=128
