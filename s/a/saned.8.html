saned(8) SANE Scanner Access Now Easy saned(8)

NOMBRE

saned - demonio de acceso a escáner SANE

SINOPSIS

saned [ -a [ nombre_usuario ] ] [ -u nombre_usuario ] [ -b dirección ] [ -p puerto ] [ -l ] [ -D ] [ -o ] [ -d n ] [ -e ] [ -h ] [ -B tamaño-buffer ]

DESCRIPCIÓN

saned es el demonio SANE (Scanner Access Now Easy) que permite a los clientes remotos acceder a los dispositivos de adquisición de imágenes disponibles en el host local.

OPCIONES

saned reconoce las siguientes opciones:

-a [nombre_usuario], --alone[=nombre_usuario]
es equivalente a la combinación de las opciones -l -D -u nombre_usuario. Sin embargo, nombre_usuario es opcional y el usuario que ejecuta solo se establecerá cuando se especifique.
-u nombre_usuario, --user=nombre_usuario
solicita que saned despoje de privilegios de root y se ejecute como el usuario (y grupo) asociado con nombre_usuario después de la conexión.
-b dirección, --bind=dirección
indica a saned que se conecte a la dirección dada.
-p puerto, --port=puerto
indica a saned que escuche en el puerto dado. Un valor de 0 indica a saned que elija un puerto no utilizado. El valor predeterminado es el puerto sane (6566).
-l, --listen
solicita que saned se ejecute en modo demonio autónomo. En este modo, saned escuchará las conexiones entrantes de clientes; inetd(8) no es necesario para las operaciones de saned en este modo.
-D, --daemonize
solicitará que saned se desconecte de la consola y se ejecute en segundo plano.
-n, --allow-network
permite a saned usar escáneres de red. Por defecto, esto está prohibido para evitar que saned se llame a sí mismo. Cuando está habilitado, la configuración del backend de sane-net(5) no debe mencionar la dirección en la que saned está escuchando.
-o, --once
solicita que saned salga después de que el primer cliente se desconecte. Esto es útil para depuración.
-d n, --debug=n
establece el nivel de salida de depuración de saned en n. Cuando se compila con la depuración habilitada, esta bandera puede ir seguida de un número para solicitar más o menos información de depuración. Cuanto mayor sea el número, más detallada será la salida de depuración. Por ejemplo, -d128 solicitará la salida de toda la información de depuración. Un nivel de 0 no produce ninguna salida. El valor predeterminado es 2.
-e, --stderr
redirigirá la salida de depuración de saned a stderr en lugar de la configuración predeterminada de syslog.
-B, --buffer-size=tamaño-buffer
especifica el tamaño del búfer de lectura utilizado para la comunicación con el backend en KB. El valor predeterminado es 1 MB.
-h, --help
muestra un mensaje de ayuda corto.

CONFIGURACIÓN

El archivo de configuración saned.conf contiene tanto opciones para el demonio como la lista de acceso.

data_portrange = puerto_min - puerto_max
Especifica el rango de puertos a utilizar para la conexión de datos. Elija un rango de puertos entre 1024 y 65535; no elija un rango de puertos demasiado grande, ya que puede tener problemas de rendimiento. Utilice esta opción si su servidor saned se encuentra detrás de un firewall. Si ese firewall es una máquina Linux, recomendamos encarecidamente utilizar el módulo nf_conntrack_sane de Netfilter en su lugar.
data_connect_timeout = tiempo_espera
Especifica el tiempo en milisegundos que saned esperará una conexión de datos. Sin esta opción, si la conexión de datos no se completa antes de que el escáner llegue al final del escaneo, el escáner continuará escaneando más allá del final y puede dañarse dependiendo del backend. Especifique cero para tener el comportamiento anterior. El valor predeterminado es 4000 ms.

La lista de acceso es una lista de nombres de host, direcciones IP o subredes IP (notación CIDR) a las que se les permite usar dispositivos SANE locales. Las direcciones IPv6 deben estar entre corchetes y siempre deben especificarse en su forma comprimida. Las conexiones desde localhost siempre están permitidas. Las líneas vacías y las líneas que comienzan con un signo de almohadilla (#) se ignoran. Una línea que contiene el único carácter "+" se interpreta como una coincidencia para cualquier nombre de host. Esto permite que cualquier máquina remota utilice su escáner y puede presentar un riesgo de seguridad, por lo que no debe usarse a menos que sepa lo que está haciendo.

Un archivo de configuración de ejemplo se muestra a continuación:

# Opciones del demonio
data_portrange = 10000 - 10100
# Lista de acceso
scan-client.somedomain.firm
# este es un comentario
192.168.0.1
192.168.2.12/29
[::1]
[2001:db8:185e::42:12]/64

La capitalización de los nombres de host no importa, por lo que AHost.COM se considera idéntico a ahost.com.

ARCHIVOS

/etc/hosts.equiv
Los hosts listados en este archivo tienen permitido el acceso a todos los dispositivos SANE locales. Advertencia: este archivo impone serios riesgos de seguridad y no se recomienda su uso.
/etc/sane.d/saned.conf
Contiene una lista de hosts a los que se les permite acceder a los dispositivos SANE locales (ver también la descripción de SANE_CONFIG_DIR a continuación).
/etc/sane.d/saned.users
Si este archivo contiene líneas del formato

usuario:contraseña:backend

el acceso a los backends listados está restringido. Un backend puede ser listado varias veces para diferentes combinaciones de usuario/contraseña. El servidor utiliza el hash MD5 si es compatible con el cliente.

ENTORNO

SANE_CONFIG_DIR
Esta variable de entorno especifica la lista de directorios que pueden contener el archivo de configuración. En sistemas *NIX, los directorios están separados por dos puntos (`:'), bajo OS/2, están separados por un punto y coma (`;'). Si esta variable no está configurada, el archivo de configuración se busca en dos directorios predeterminados: primero, el directorio de trabajo actual (".") y luego en /etc/sane.d. Si el valor de la variable de entorno termina con el carácter separador de directorio, entonces los directorios predeterminados se buscan después de los directorios especificados explícitamente. Por ejemplo, configurar SANE_CONFIG_DIR a "/tmp/config:" resultaría en la búsqueda de los directorios tmp/config, ., y /etc/sane.d (en este orden).

NOTAS

saned *no* proporciona confidencialidad al comunicarse con los clientes. Si saned se expone directamente en la red, otros usuarios pueden interceptar imágenes escaneadas o conocer contraseñas para conectarse a saned con poco esfuerzo. Los sistemas cliente deberían conectarse a saned a través de un túnel seguro al servidor en su lugar.

saned no es un programa de confianza y no debería ejecutarse con privilegios de root.

Consulte /usr/share/doc/sane/saned/saned.install.md para obtener detalles sobre la configuración de saned como servicio.
