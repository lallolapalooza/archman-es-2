NOMBRE

sane-umax_pp - Backend SANE para escáneres planos Umax de puerto paralelo

DESCRIPCIÓN

La biblioteca sane-umax_pp implementa un backend SANE (Scanner Access Now Easy) que proporciona acceso a escáneres planos Umax de puerto paralelo. Los siguientes escáneres funcionan con este backend:

Modelo:
--------------------
Astra 610P
Astra 1220P
HP3200C
Astra 1600P
Astra 2000P
Genius ColorPage-Life Pro

Este backend maneja resoluciones de escaneo de 75x75, 150x150, 300x300, 600x600 y 600x1200 ppp para 1220P/1600P/2000P, y 75x75, 150x150, 300x300 y 300x600 ppp para 610P. En niveles de color y gris, existe un modo de dibujo lineal por software.

Los modelos de nueva generación comparten una versión más nueva del ASIC 610P integrado en un chip EPAT. Solo partes como CCD y ADC cambian de un modelo a otro. Incluso todos informan ser UMAX Astra 1220P a través de IEEE1284. No hay un método de software para reconocerlos correctamente. En Windows, el modelo se establece mediante el controlador instalado, independientemente del hardware.

SOLO MODOS EPP/ECP
La versión actual del backend utiliza solo el modo EPP o ECP para comunicarse con el escáner. El modo PS/2 no está implementado. El 610P solo usa SPP. Se recomienda configurar el puerto paralelo en EPP en la BIOS con la versión actual de este backend. Puedes dejarlo en ECP o ECP+EPP, pero en ese caso es posible que no uses ppdev sino solo acceso directo al hardware si tienes que usar ECP. ECPEPP solo funcionará si usas un kernel 2.4 o 2.6 con soporte para el dispositivo de caracteres ppdev.

Este backend soporta el uso compartido de parport solo si tienes un kernel con soporte para ppdev.

Ten en cuenta que si no usas el dispositivo de caracteres ppdev, el backend necesita ejecutarse como root. Para permitir el acceso de usuario al escáner, ejecuta el backend a través de la interfaz de red (ver saned(8) y sane-net(5)). Una solución más flexible (en términos de seguridad) es añadir el bit suid al frontend (ver chmod(1)). El backend suelta los privilegios de root tan pronto como puede, justo después de obtener acceso directo a los puertos de E/S, lo que reduce el riesgo de ser root.

NOMBRES DE DISPOSITIVO

Este backend espera nombres de dispositivo del tipo:

puerto valor

Donde valor es:

auto
autodetecta todos los puertos paralelos y los sondea en busca de escáneres
safe-auto
autodetecta todos los puertos paralelos y los sondea en busca de escáneres, pero no intenta acceso directo al hardware
/dev/ppi0
usa el dispositivo ppi de *BSD, dependiendo del número de puertos paralelos disponibles, debes usar /dev/ppi1, /dev/ppi2, ...
/dev/parport0
usa el dispositivo ppdev de Linux, dependiendo del número de puertos paralelos disponibles, debes usar /dev/parport1, /dev/parport2, ...
0x378
realiza acceso directo al hardware en la dirección dada. Los valores habituales son 0x378, 0x278, 0x3BC. En este caso, debes ejecutar el backend como root (*BSD y Linux), o con 'IOPL=yes' en OS/2

NOTA: en todos los casos, debes tener suficientes privilegios para acceder al dispositivo o dirección elegidos. Dependiendo de la configuración de seguridad, los dispositivos pueden no estar disponibles para todos los usuarios. Debes cambiar los permisos de los dispositivos /dev/ppi* o /dev/parport*.
Puedes renombrar cualquier dispositivo usando las opciones

nombre nombre_dispositivo
modelo modelo
fabricante fabricante

Estas opciones se aplican a la última opción de puerto.

CONFIGURACIÓN

Asegúrate de editar umax_pp.conf antes de usar el backend.

El contenido del archivo umax_pp.conf es una lista de opciones y nombres de dispositivo que corresponden a los escáneres Umax. Las líneas vacías y las líneas que comienzan con un signo de almohadilla (#) se ignoran.

Las ocho opciones admitidas son red-gain, green-gain, blue-gain, red-offset, green-offset, blue-offset, astra y buffer.

Las opciones red-gain, green-gain y blue-gain te permiten ajustar la sensibilidad de tu escáner para el color dado. Los valores oscilan entre 0 (ganancia más baja) y 15 (más alta). Si la opción avanzada "Gain" no está marcada en el frontend, el backend realiza una calibración automática de ganancia y no utiliza los valores proporcionados por el usuario.

Las opciones red-offset, green-offset y blue-offset te permiten ajustar el desplazamiento de tu escáner para el color dado. Los valores oscilan entre 0 (desplazamiento más bajo) y 15 (más alto).

La opción astra te permite cambiar el modelo de tu escáner. La detección automática actual se basa en efectos secundarios al escanear al usar el conjunto de comandos 1220P en otros modelos, por lo que puede fallar en combinaciones de hardware desconocidas. Los valores válidos son 610, 1220, 1600 y 2000. Solo es útil cuando la autodetección falla al detectar correctamente el modelo de tu escáner. Si tu escáner funciona correctamente pero se informa incorrectamente, déjalo así. El único caso válido para cambiar el modelo es cuando tu escáner produce escaneos "negros" o "invertidos". En este caso, puedes introducir el modelo. Ten en cuenta que esto impedirá la autodetección del modelo del escáner.

La opción buffer te permite cambiar el tamaño del búfer de escaneo. El tamaño debe especificarse en bytes. El valor predeterminado es 2 megabytes. Reducir este valor mejorará la fluidez de la barra de progreso en el frontend, pero bloqueará el escaneo con más frecuencia.

ARCHIVOS

/etc/sane.d/umax_pp.conf
El archivo de configuración del backend (ver también la descripción de SANE_CONFIG_DIR más abajo).
/usr/lib/sane/libsane-umax_pp.a
La biblioteca estática que implementa este backend.
/usr/lib/sane/libsane-umax_pp.so
La biblioteca compartida que implementa este backend (presente en sistemas que admiten carga dinámica).

ENTORNO

SANE_CONFIG_DIR
Esta variable de entorno especifica la lista de directorios que pueden contener el archivo de configuración. En sistemas *NIX, los directorios están separados por dos puntos (`:'), en OS/2, están separados por un punto y coma (`;'). Si esta variable no está establecida, el archivo de configuración se busca en dos directorios predeterminados: primero, el directorio de trabajo actual (".") y luego en /etc/sane.d. Si el valor de la variable de entorno termina con el carácter separador de directorio, entonces se buscan los directorios predeterminados después de los directorios especificados explícitamente. Por ejemplo, establecer SANE_CONFIG_DIR a "/tmp/config:" resultaría en la búsqueda de los directorios tmp/config, . y /etc/sane.d (en este orden).
SANE_DEBUG_UMAX_PP
Si la biblioteca se compiló con soporte de depuración habilitado, esta variable de entorno controla el nivel de depuración para este backend. Por ejemplo, un valor de 128 solicita que se imprima toda la salida de depuración. Niveles más bajos reducen la verbosidad. 
nivel   salida de depuración
------- ------------------------------
 0       nada
 1       errores
 2       advertencias y errores menores
 3       información adicional
 4       información de depuración
 5       flujo de código (aún no soportado)
 6       información de depuración especial
SANE_DEBUG_UMAX_PP_LOW
Esta variable establece el nivel de depuración para la interfaz SANE del ASIC Umax. Ten en cuenta que habilitarla generará millones de líneas de salida de depuración en tu terminal. 
nivel   salida de depuración
------- -------------------------------
 0       nada
 1       errores
 8       bloques de comandos
 16      flujo de código detallado
 32      volcar archivos de datos
 255     todo

REPORTES DE ERRORES

Si algo no funciona, por favor contácteme. Pero necesito información sobre su escáner para poder ayudarlo...

Versión de SANE
Ejecute scanimage -V para determinarla
la versión del backend y el hardware de su escáner
Ejecute SANE_DEBUG_UMAX_PP=255 scanimage -L 2>log como root. Si no obtiene ninguna salida del backend sane-umax_pp, asegúrese de que la línea "umax_pp" esté incluida en su archivo /etc/sane.d/dll.conf. Si su escáner no es detectado, asegúrese de haber definido la dirección de puerto correcta, o el dispositivo correcto en su archivo umax_pp.conf.
el nombre de su escáner/vendedor
también es información valiosa. Por favor, incluya también la resolución óptica y el tipo de lámpara de su escáner, ambos se pueden encontrar en el manual de su escáner.
cualquier comentario adicional
si tiene comentarios sobre la documentación (qué se podría mejorar), o si cree que debería saber algo, por favor inclúyalo.
