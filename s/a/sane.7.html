sane(7) SANE Scanner Access Now Easy sane(7)

NOMBRE

sane - Scanner Access Now Easy: API para acceder a escáneres

DESCRIPCIÓN

SANE es una interfaz de programación de aplicaciones (API) que proporciona acceso estandarizado a cualquier hardware de escáner de imágenes rasterizadas. La interfaz estandarizada hace posible escribir solo un controlador para cada dispositivo escáner en lugar de un controlador para cada escáner y aplicación.

Si bien SANE está dirigido principalmente a un entorno UNIX, el estándar ha sido diseñado cuidadosamente para hacer posible la implementación de la API en prácticamente cualquier hardware o sistema operativo.

Esta página del manual proporciona un resumen de la información disponible sobre SANE.

Si tiene problemas para que su escáner sea detectado, lea la sección PROBLEMAS.

TERMINOLOGÍA

Una aplicación que utiliza la interfaz SANE se llama frontend SANE. Un controlador que implementa la interfaz SANE se llama backend SANE. Un meta backend proporciona algunos medios para gestionar uno o más backends.

PAQUETES DE SOFTWARE

El paquete sane-backends contiene backends, documentación, soporte de red y el frontend de línea de comandos scanimage(1). Los frontends xscanimage(1), xcam(1) y scanadf(1) están incluidos en el paquete sane-frontends. Ambos paquetes se pueden descargar de la página de inicio de SANE (http://www.sane-project.org/). También se puede encontrar información sobre otros frontends y backends en la página de inicio de SANE.

CAMBIANDO EL BACKEND DE NIVEL SUPERIOR

Por defecto, todos los backends (drivers) de SANE son cargados dinámicamente por el meta-backend sane-dll. Si tiene alguna pregunta sobre la carga dinámica, lea sane-dll(5). Los frontends de SANE también pueden enlazarse directamente a otros backends copiando o enlazando un backend a libsane.so en /usr/lib/sane.

DOCUMENTACIÓN PARA DESARROLLADORES

No es difícil escribir un backend de SANE. Puede llevar tiempo, sin embargo. Debería tener conocimientos básicos de C y suficiente paciencia para revisar la documentación y averiguar cómo funciona su escáner. A continuación se incluye una lista de algunos documentos que ayudan a escribir backends y frontends.

El estándar SANE define la interfaz de programación de aplicaciones (API) que se utiliza para comunicarse entre frontends y backends. Se puede encontrar en http://sane-project.gitlab.io/standard/.

Hay más información para programadores en /usr/share/doc/sane/backend-writing.txt. La mayoría de las rutinas internas de SANE (sanei) están documentadas usando doxygen: http://www.sane-project.org/sanei/. Antes de iniciar un nuevo proyecto de backend o frontend, eche un vistazo a /usr/share/doc/sane/PROJECTS para ver los proyectos que están planificados o que aún no están incluidos en la distribución de SANE, y a nuestro sistema de seguimiento de errores: http://www.http://www.sane-project.org/bugs.html.

Hay algunos enlaces sobre cómo averiguar el protocolo de un escáner: http://www.meier-geinitz.de/sane/misc/develop.html.

Si comienza a escribir un backend o frontend o cualquier otra parte de SANE, póngase en contacto con la lista de correo sane-devel para coordinar, de modo que no se duplique el trabajo.

PROBLEMAS

Si su dispositivo no se encuentra pero sabe que está soportado, asegúrese de que sea detectado por su sistema operativo. Para escáneres SCSI y USB, utilice la utilidad sane-find-scanner(1). Imprime una línea por cada escáner que ha detectado y algunos comentarios (#). Si sane-find-scanner(1) encuentra su escáner solo como root pero no como usuario normal, los permisos para los archivos de dispositivo no están ajustados correctamente. Si el escáner no se encuentra en absoluto, el sistema operativo no lo ha detectado y puede necesitar ayuda. Dependiendo del tipo de su escáner, lea sane-usb(5) o sane-scsi(5). Si su escáner (u otro dispositivo) no está conectado a través del bus SCSI o USB, lea la página del manual del backend para obtener detalles sobre cómo configurarlo.

¿Su escáner es detectado por el sistema operativo pero no por SANE? Pruebe scanimage -L. Si el escáner no se encuentra, verifique que el nombre del backend esté mencionado en /etc/sane.d/dll.conf. Algunos backends están comentados por defecto. Elimine el signo de comentario para su backend en este caso. Además, algunos backends no se compilan si falta uno de sus prerrequisitos. Los ejemplos incluyen dc210, dc240, canon_pp, hpsj5s, gphoto2, pint, qcam, v4l, net, sm3600, snapscan, pnm. Si necesita uno de estos backends y no está disponible, lea las instrucciones de compilación en el archivo README y las páginas del manual individuales de los backends.

Otra razón por la que no sea detectado por scanimage -L puede ser una configuración faltante o incorrecta en el archivo de configuración del backend. Wh

PROBLEMS

Aunque SANE intenta encontrar automáticamente la mayoría de los escáneres, algunos no se pueden configurar correctamente sin la intervención del administrador. Además, en algunos sistemas operativos, la detección automática puede no funcionar. Consulte la página del manual del backend para obtener detalles.

Si su escáner aún no se encuentra, intente configurar las diversas variables de entorno disponibles para ayudar en la depuración. Las variables de entorno se documentan en las páginas del manual correspondientes. Por ejemplo, para obtener la máxima cantidad de información de depuración al probar un escáner SCSI Mustek, establezca las variables de entorno SANE_DEBUG_DLL, SANE_DEBUG_MUSTEK y SANE_DEBUG_SANEI_SCSI en 128 y luego invoque scanimage -L. Los mensajes de SANE_DEBUG_DLL indican si el backend de sane-mustek(5) se encontró y se cargó en absoluto. Los mensajes de SANE_DEBUG_MUSTEK explican lo que está haciendo el backend, mientras que la depuración de SANE_DEBUG_SCSI muestra el manejo de bajo nivel. Si no puede averiguar qué está sucediendo revisando cuidadosamente los mensajes, póngase en contacto con la lista de correo sane-devel para obtener ayuda (ver REPORTAR ERRORES abajo).

Ahora que su escáner es encontrado por scanimage -L, intente hacer un escaneo: scanimage >image.pnm. Este comando inicia un escaneo para el escáner predeterminado con la configuración predeterminada. Todas las opciones disponibles se enumeran ejecutando scanimage --help. Si el escaneo se interrumpe con un mensaje de error, active la depuración como se mencionó anteriormente. Quizás el archivo de configuración necesite algún ajuste, por ejemplo, para configurar la ruta a un firmware que necesiten algunos escáneres. Consulte la página del manual del backend para obtener detalles. Si no puede averiguar qué está mal, póngase en contacto con sane-devel.

Para verificar que las bibliotecas SANE estén instaladas correctamente, puede usar el backend de prueba, incluso si no tiene un escáner u otro dispositivo SANE:

scanimage -d test -T

Debería obtener una lista de pruebas PASADAS. Puede hacer lo mismo con su backend cambiando "test" por el nombre de su backend.

Así que ahora la digitalización con scanimage (1) funciona y desea utilizar una de las interfaces gráficas como xsane(1), xscanimage(1), o quiteinsane(1) pero esas interfaces no detectan su escáner? Una razón puede ser que haya instalado dos versiones de SANE. Por ejemplo, la versión instalada por su distribución en /usr y una que instaló desde la fuente en /usr/local/. Asegúrese de que solo una versión esté instalada. Otra razón posible es que el cargador dinámico de su sistema no pueda encontrar las bibliotecas SANE. Para Linux, asegúrese de que /etc/ld.so.conf contenga /usr/local/lib y **no** contenga /usr/local/lib/sane. Consulte también la documentación de las interfaces.
