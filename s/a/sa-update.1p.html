SA-UPDATE(1p) Documentación Perl contribuida por el usuario SA-UPDATE(1p)

NOMBRE

sa-update - automatiza las actualizaciones de reglas de SpamAssassin

SINOPSIS

sa-update [opciones]

Opciones:

--channel canal         Recuperar actualizaciones de este canal
                        Usar varias veces para múltiples canales
--channelfile archivo      Recuperar actualizaciones de los canales en el archivo
--checkonly             Comprobar solo si hay actualizaciones, no instalar
--install archivo       Instalar actualizaciones directamente desde este archivo. La verificación de la firma usará "archivo.asc", o "archivo.sha512"
                        o "archivo.sha256".
--allowplugins          Permitir que las actualizaciones carguen código de plugin (PELIGROSO)
--gpgkey clave          Confiar en el id de clave para firmar lanzamientos
                        Usar varias veces para múltiples claves
--gpgkeyfile archivo      Confiar en los ids de clave en el archivo para firmar lanzamientos
--gpghomedir ruta         Almacenar el llavero GPG en este directorio
--gpg y --nogpg          Usar (o no usar) GPG para verificar actualizaciones
                        (se asume --gpg al usar las opciones anteriores
                        --gpgkey y --gpgkeyfile)
--import archivo        Importar clave(s) GPG desde el archivo al llavero
                        de sa-update. Usar varias veces para múltiples archivos
--updatedir ruta        Directorio donde colocar las actualizaciones, por defecto es el
                        directorio de reglas del sitio de SpamAssassin
                        (por defecto: /var/lib/spamassassin/4.000001)
--refreshmirrors        Forzar la actualización del archivo MIRRORED.BY
--forcemirror url       Usar un mirror específico en lugar de descargar de
                        mirrors oficiales
--httputil util         Forzar la herramienta de descarga utilizada. Por defecto, la primera que se encuentre
                        entre estas se usará: curl, wget, fetch, lwp
--score-multiplier x.x  Ajustar todas las puntuaciones del canal de actualización, multiplicar
                        por el valor dado (entero o flotante).
--score-limit x.x       Ajustar todas las puntuaciones del canal de actualización, limitar
                        al valor dado (entero o flotante). El límite
                        se aplica después de la posible operación de multiplicación.
-D, --debug [area=n,...]  Imprimir mensajes de depuración
-v, --verbose           Ser detallado, como imprimir nombres de canales actualizados;
                        Para más detalle, especificar varias veces
-V, --version           Imprimir versión
-h, --help              Imprimir mensaje de uso
-4                      Forzar el uso del protocolo inet (IPv4), no inet6
-6                      Forzar el uso del protocolo inet6 (IPv6), no inet

DESCRIPCIÓN

sa-update automatiza el proceso de descarga e instalación de nuevas reglas y configuración, basado en canales. El canal por defecto es updates.spamassassin.org, que tiene reglas actualizadas desde el lanzamiento anterior.

NOTA: los nombres de los canales son nombres de dominio, pero NO suelen tener registros DNS aparte de (quizás) registros NS. Hay un árbol de registros debajo de ese nombre que denota la versión de SpamAssassin y resuelve ese nombre al número de versión de las últimas reglas, por ejemplo, para encontrar el número de versión de la última actualización para SpamAssassin v4.0.0:

$ host -t txt 0.0.4.updates.spamassassin.org
0.0.4.updates.spamassassin.org es un alias de 3.3.3.updates.spamassassin.org.
3.3.3.updates.spamassassin.org texto descriptivo "1907730"

Eso también ilumina el hecho de que el conjunto de reglas actual se supone que es retrocompatible con la v3.3.3.

Los archivos de actualización se verifican mediante firmas GPG por defecto. Si GPG está deshabilitado (no recomendado), la integridad del archivo se verifica con sumas de verificación SHA512 o SHA256.

Tenga en cuenta que "sa-update" no reiniciará "spamd" ni provocará que un escáner recargue automáticamente el conjunto de reglas ahora actualizado. En su lugar, "sa-update" se suele utilizar en algo parecido a lo siguiente:

sa-update && /etc/init.d/spamassassin reload

Esto funciona porque "sa-update" solo devuelve un estado de salida de 0 si ha descargado e instalado correctamente un conjunto de reglas actualizado.

El programa sa-update utiliza la configuración umask del sistema operativo subyacente para los archivos de reglas actualizados que instala. Es posible que desee ejecutar sa-update desde un script que establezca la umask antes de llamar a sa-update. Por ejemplo:

#!/bin/sh
umask 022
sa-update

OPCIONES

--channel
sa-update puede actualizar múltiples canales al mismo tiempo. Por defecto, solo accederá a "updates.spamassassin.org", pero se pueden especificar más canales a través de esta opción. Si hay varios canales adicionales, use la opción varias veces, una por canal. es decir: 
sa-update --channel foo.example.com --channel bar.example.com
--channelfile
Similar a la opción --channel, excepto que especifica los canales adicionales en un archivo en lugar de en la línea de comandos. Esto es útil cuando hay muchos canales adicionales.
--checkonly
Solo comprueba si hay una actualización disponible, no la descarga ni la instala realmente. El código de salida será 0 o 1 como se describe a continuación.
--install
Instala actualizaciones "sin conexión", desde el archivo tar.gz especificado, en lugar de realizar búsquedas DNS e invocaciones HTTP.

Los archivos llamados archivo.asc, archivo.sha512 o archivo.sha256 se utilizarán para la firma GPG, y las sumas de verificación SHA256 y SHA512, respectivamente. El nombre de archivo proporcionado debe contener un número de versión de al menos 3 dígitos, que se utilizará como número de versión de actualización del canal.

No se pueden usar múltiples interruptores --channel con --install. Para instalar múltiples canales desde archivos tar, ejecute "sa-update" varias veces con interruptores --channel y --install diferentes, por ejemplo:

sa-update --channel foo.example.com --install foo-34958.tgz
sa-update --channel bar.example.com --install bar-938455.tgz
--allowplugins
Permite que las actualizaciones descargadas activen plugins. Por defecto, no se activan plugins; cualquier línea "loadplugin" o "tryplugin" se comentará en los archivos de reglas de actualización descargados.

Nunca debes habilitar esto para canales de actualización de terceros, ya que los plugins pueden ejecutar código sin restricciones en tu sistema, ¡incluso posiblemente como root! Esto incluye las actualizaciones oficiales de spamassassin, que no necesitan incluir código en ejecución.

Usa la opción --reallyallowplugins para omitir las advertencias y que funcione.

--gpg, --nogpg
sa-update por defecto verificará los archivos de actualización mediante la firma GPG.

Si deseas omitir la verificación GPG (muy inseguro), puedes usar la opción --nogpg para deshabilitar su uso. El uso de las siguientes opciones relacionadas con gpgkey anulará --nogpg y mantendrá la verificación GPG habilitada.

Si GPG está deshabilitado, solo se utilizan sumas de verificación SHA512 o SHA256 para verificar si el archivo descargado se ha corrompido, pero no ofrece ninguna forma de seguridad en cuanto a si el archivo descargado es legítimo (es decir, no modificado por malhechores).

Nota: Solo se admite GnuPG (es decir, no otro software PGP).

--gpgkey
sa-update tiene el concepto de claves GPG "confiables para lanzamientos". Cuando se descarga un archivo y se verifica la firma, sa-update requiere que la firma sea de una de estas claves "confiables para lanzamientos" o la verificación fallará. Esto evita que terceros manipulen los archivos en un mirror, por ejemplo, y firmen con su propia clave.

Por defecto, sa-update confía en los ids de clave "24F434CE" y "5244EC45", que son la clave de lanzamiento estándar de SpamAssassin y su subclave. Usa esta opción para confiar en claves adicionales. Consulta la opción --import para saber cómo añadir claves al llavero de sa-update. Para que sa-update use una clave, debe estar en el llavero de sa-update y ser confiable.

Para múltiples claves, usa la opción varias veces. es decir:

sa-update --gpgkey E580B363 --gpgkey 298BC7D0

Nota: el uso de esta opción habilita automáticamente la verificación GPG.

sa-update(1p) — Apache SpamAssassin manual

NAME

sa-update

actualiza reglas de SpamAssassin y el software de apoyo

SYNOPSIS

sa-update [options]

DESCRIPTION

Actualiza automáticamente las reglas de SpamAssassin y el software de apoyo, y genera las reglas y el código Perl necesarios para que se carguen.

La primera vez que se ejecute sa-update, se pondrá en marcha y descargará las reglas de SpamAssassin y el software de apoyo.

Para más detalles, consulte la página de documentación en línea: https://wiki.apache.org/spamassassin/RuleUpdates.

OPTIONS

--gpgkeyfile
Similar a la opción --gpgkey, excepto que especifica las claves adicionales en un archivo en lugar de en la línea de comandos. Esto es extremadamente útil cuando hay muchas claves adicionales que desea confiar.
--gpghomedir
Especifica una ruta de directorio para usar como área de almacenamiento para el keyring GPG de "sa-update". Por defecto, es 
/etc/mail/spamassassin/sa-update-keys
--import
Se usa para importar clave(s) GPG de un archivo al keyring de sa-update que se encuentra en el directorio especificado por --gpghomedir. Antes de usar canales de fuentes de terceros, debe usar esta opción para importar la(s) clave(s) GPG utilizada(s) por esos canales. Todavía debe usar las opciones --gpgkey o --gpgkeyfile anteriores para que sa-update confíe en las claves importadas.

Para importar múltiples claves, use la opción varias veces. es decir:

sa-update --import channel1-GPG.KEY --import channel2-GPG.KEY

Nota: el uso de esta opción habilita automáticamente la verificación GPG.

--refreshmirrors
Fuerza la actualización de la lista de espejos de sa-update para cada canal, almacenada en el archivo MIRRORED.BY. Por defecto, el archivo MIRRORED.BY se almacenará en caché hasta por 7 días después de cada descarga.
--forcemirror
Fuerza la descarga desde un host específico en lugar de depender de los espejos listados en MIRRORED.BY.
--updatedir
Por defecto, "sa-update" usará el directorio de actualización de reglas a nivel de sistema: 
/var/lib/spamassassin/4.000001

Si las actualizaciones deben almacenarse en otra ubicación, especifíquelo aquí.

Tenga en cuenta que no se recomienda el uso de esta opción; si solo está utilizando sa-update para descargar reglas actualizadas para un escáner, y sa-update está colocando las actualizaciones en el directorio incorrecto, probablemente necesite reconstruir SpamAssassin con argumentos diferentes de "Makefile.PL", en lugar de anular el comportamiento de tiempo de ejecución de sa-update.

-D [área,...], --debug [área,...]
Produce salida de depuración. Si no se enumeran áreas, se imprime toda la información de depuración. La salida de diagnóstico también se puede habilitar para cada área individualmente; área es el área del código a instrumentar. Por ejemplo, para producir salida de diagnóstico en canal, gpg e http, use: 
sa-update -D channel,gpg,http

Para obtener más información sobre qué áreas (también conocidas como canales) están disponibles, consulte la documentación en https://wiki.apache.org/spamassassin/DebugChannels.

-h, --help
Imprime el mensaje de ayuda y sale.
-V, --version
Imprime la versión de sa-update y sale.

CÓDIGOS DE SALIDA

En ausencia de una opción --checkonly, un código de salida de 0 significa: había una actualización disponible, y fue descargada e instalada con éxito. Si se especificó --checkonly, un código de salida de 0 significa: había una actualización disponible.

Un código de salida de 1 significa que no había actualizaciones frescas disponibles.

Un código de salida de 2 significa que al menos una actualización está disponible, pero que una verificación de lint de los archivos de sitio pre falló. Los archivos de sitio pre deben pasar una verificación de lint antes de que se intenten las actualizaciones.

Un código de salida de 3 significa que al menos una actualización tuvo éxito mientras que otros canales fallaron. Si está usando sa-compile, debe proceder con él.

Un código de salida de 4 o superior, indica que ocurrieron errores al intentar descargar y extraer actualizaciones, y ningún canal se actualizó.
