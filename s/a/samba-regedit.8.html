SAMBA-REGEDIT(8) Herramientas de administración del sistema SAMBA-REGEDIT(8)

NOMBRE

samba-regedit - herramienta basada en ncurses para administrar el registro de Samba

SINOPSIS

samba-regedit [-?|--help] [--usage] [-d|--debuglevel=NIVEL_DEBUG] [--debug-stdout] [--configfile=ARCHIVO_CONFIG] [--option=nombre=valor] [-l|--log-basename=BASE_LOG] [--leak-report] [--leak-report-full] [-R|--name-resolve=ORDEN_RESOLUCION_NOMBRES] [-O|--socket-options=OPCIONES_SOCKET] [-m|--max-protocol=PROTOCOLO_MAXIMO] [-n|--netbiosname=NOMBRE_NETBIOS] [--netbios-scope=AMBITO] [-W|--workgroup=GRUPO_TRABAJO] [--realm=DOMINIO] [-U|--user=[DOMINIO/]NOMBRE_USUARIO[%CONTRASEÑA]] [-N|--no-pass] [--password=CADENA] [--pw-nt-hash] [-A|--authentication-file=ARCHIVO] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=deseado|requerido|apagado] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=firmar|cifrar|apagado] [-V|--version]

DESCRIPCIÓN

Esta herramienta forma parte del conjunto samba(7).

samba-regedit es una herramienta basada en ncurses para administrar el registro de Samba. Se puede utilizar para mostrar/editar claves/subclaves del registro y sus valores.

OPCIONES

-?|--help

Imprime un resumen de las opciones de la línea de comandos.

--usage

Muestra un breve mensaje de uso.

-d|--debuglevel=nivel

nivel es un entero entre 0 y 10. El valor predeterminado si no se especifica este parámetro es 1 para las aplicaciones cliente.

Cuanto mayor sea este valor, más detalle se registrará en los archivos de registro sobre las actividades del servidor. Con el nivel 0, solo se registrarán errores críticos y advertencias graves. El nivel 1 es un nivel razonable para el uso diario: genera una pequeña cantidad de información sobre las operaciones realizadas.

Los niveles superiores a 1 generarán una cantidad considerable de datos de registro y solo deben usarse al investigar un problema. Los niveles superiores a 3 están diseñados solo para uso de desarrolladores y generan ENORMES cantidades de datos de registro, la mayoría de los cuales son extremadamente crípticos.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro log level en el archivo /etc/samba/smb.conf.

--debug-stdout

Redirigirá la salida de depuración a STDOUT. Por defecto, todos los clientes registran en STDERR.

--configfile=<archivo de configuración>

El archivo especificado contiene los detalles de configuración requeridos por el cliente. La información en este archivo puede ser general para cliente y servidor o proporcionar solo opciones específicas del cliente como client smb encrypt. Consulte /etc/samba/smb.conf para más información. El nombre del archivo de configuración predeterminado se determina en tiempo de compilación.

--option=<nombre>=<valor>

Establece la opción smb.conf(5) "<nombre>" al valor "<valor>" desde la línea de comandos. Esto anula los valores predeterminados compilados y las opciones leídas del archivo de configuración. Si un nombre o un valor incluye un espacio, envuelva todo --option=nombre=valor entre comillas.

-l|--log-basename=directorio_log

Nombre base del directorio para los archivos de registro/depuración. Se añadirá la extensión ".nombre_programa" (por ejemplo, log.smbclient, log.smbd, etc.). El cliente nunca elimina el archivo de registro.

--leak-report

Habilita el informe de fugas de talloc al salir.

--leak-report-full

Habilita el informe completo de fugas de talloc al salir.

-V|--version

Imprime el número de versión del programa.

-R|--name-resolve=ORDEN_RESOLUCION_NOMBRES

Esta opción se utiliza para determinar qué servicios de nombres y en qué orden resolver nombres de host a direcciones IP. La opción toma una cadena separada por espacios de diferentes opciones de resolución de nombres. Lo mejor es envolver todo --name-resolve=ORDEN_RESOLUCION_NOMBRES entre comillas.

Las opciones son: "lmhosts", "host", "wins" y "bcast". Hacen que los nombres se resuelvan de la siguiente manera:

•lmhosts: Busca una dirección IP en el archivo lmhosts de Samba. Si la línea en lmhosts no tiene un tipo de nombre asociado al nombre NetBIOS (consulte lmhosts(5) para detalles) entonces cualquier tipo de nombre coincide para la búsqueda.
•host: Realiza una resolución estándar de nombre de host a dirección IP, utilizando las búsquedas de DNS, NIS o el archivo /etc/hosts del sistema. Este método de resolución de nombres depende del sistema operativo, por ejemplo, en IRIX o Solaris esto puede ser controlado por el archivo /etc/nsswitch.conf). Tenga en cuenta que este método solo se usa si el tipo de nombre NetBIOS que se consulta es el tipo de nombre 0x20 (servidor), de lo contrario se ignora.
•wins: Consulta un nombre con la dirección IP listada en el parámetro wins server. Si no se ha especificado ningún servidor WINS, este método se ignorará.
•bcast: Realiza una difusión en cada una de las interfaces locales conocidas listadas en el parámetro interfaces. Este es el método de resolución de nombres menos confiable, ya que depende de que el host de destino esté en una subred conectada localmente.
Si este parámetro no está establecido, se utilizará el orden de resolución de nombres definido en el parámetro del archivo /etc/samba/smb.conf (name resolve order).

El orden predeterminado es lmhosts, host, wins, bcast. Sin este parámetro o cualquier entrada en el parámetro name resolve order del archivo /etc/samba/smb.conf, se intentarán los métodos de resolución de nombres en este orden.

-O|--socket-options=OPCIONES_SOCKET

Opciones de socket TCP para establecer en el socket del cliente. Consulte el parámetro de opciones de socket en la página del manual de /etc/samba/smb.conf para ver la lista de opciones válidas.

-m|--max-protocol=PROTOCOLO_MAXIMO

El valor del parámetro (una cadena) es el nivel de protocolo más alto que será compatible con el cliente.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro client max protocol en el archivo /etc/samba/smb.conf.

-n|--netbiosname=NOMBRE_NETBIOS

Esta opción le permite anular el nombre NetBIOS que Samba utiliza para sí mismo. Esto es idéntico a establecer el parámetro netbios name en el archivo /etc/samba/smb.conf. Sin embargo, una configuración en la línea de comandos tendrá prioridad sobre las configuraciones en /etc/samba/smb.conf.

--netbios-scope=AMBITO

Esto especifica un ámbito NetBIOS que nmblookup usará para comunicarse al generar nombres NetBIOS. Para obtener detalles sobre el uso de ámbitos NetBIOS, consulte rfc1001.txt y rfc1002.txt. Los ámbitos NetBIOS se usan *muy* raramente, solo establezca este parámetro si usted es el administrador del sistema a cargo de todos los sistemas NetBIOS con los que se comunica.

-W|--workgroup=GRUPO_TRABAJO

Establece el dominio SMB del nombre de usuario. Esto anula el dominio predeterminado, que es el dominio definido en smb.conf. Si el dominio especificado es el mismo que el nombre NetBIOS del servidor, hace que el cliente inicie sesión utilizando el SAM local del servidor (en contraposición al SAM del dominio).

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro workgroup en el archivo /etc/samba/smb.conf.

-r|--realm=DOMINIO

Establece el dominio para el dominio.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro realm en el archivo /etc/samba/smb.conf.

-U|--user=[DOMINIO\]NOMBRE_USUARIO[%CONTRASEÑA]

Establece el nombre de usuario SMB o el nombre de usuario y contraseña.

Si no se especifica %CONTRASEÑA, se le pedirá al usuario. El cliente primero verificará la variable de entorno USER (que también puede contener la contraseña separada por un %), luego la variable LOGNAME (que no puede contener una contraseña) y si alguna existe, se utilizará su valor. Si no se encuentran estas variables de entorno, se podría usar el nombre de usuario encontrado en una caché de credenciales de Kerberos.

Una tercera opción es usar un archivo de credenciales que contenga el texto plano del nombre de usuario y la contraseña. Esta opción se proporciona principalmente para scripts en los que el administrador no desea pasar las credenciales en la línea de comandos o a través de variables de entorno. Si se utiliza este método, asegúrese de que los permisos del archivo restrinjan el acceso a usuarios no deseados. Consulte la opción -A para obtener más detalles.

Tenga cuidado al incluir contraseñas en scripts o al pasar valores proporcionados por el usuario en la línea de comandos. Por motivos de seguridad, es mejor dejar que la herramienta cliente de Samba solicite la contraseña si es necesario, u obtener la contraseña una vez con kinit.

Si bien Samba intentará eliminar la contraseña del título del proceso (como se ve en ps), esto ocurre después del inicio

samba-regedit(8) — Arch manual pages

NAME

samba-regedit

edit Samba's registry from a remote machine

SYNOPSIS

samba-regedit [-U|--user=USERNAME] [-S|--server=SERVERNAME] [-N|--no-pass] [--password=PASSWORD] [--pw-nt-hash] [-A|--authentication-file=FILENAME] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=desired|required|off] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=sign|encrypt|off] [--option=name=value]

DESCRIPTION

The samba-regedit utility is a remote registry editor for Samba. It allows you to connect to a remote Samba server and edit its registry database. The registry is stored in a text file (see registry.tdb(5) for details) which is located in the Samba configuration directory (usually /usr/local/samba/private/). You can edit it locally or remotely.

This man page details the options available for the samba-regedit command line tool.

OPTIONS

-U|--user=USERNAME

Specify the username to use when connecting to the server. If not specified, the current logged in user is used.

-S|--server=SERVERNAME

Specify the server to connect to. If not specified, the default Samba server is used.

-N|--no-pass

If specified, this parameter suppresses the normal password prompt from the client to the user. This is useful when accessing a service that does not require a password.

Unless a password is specified on the command line or this parameter is specified, the client will request a password.

If a password is specified on the command line and this option is also defined the password on the command line will be silently ignored and no password will be used.

--password

Specify the password on the commandline.

Be cautious about including passwords in scripts or passing user-supplied values onto the command line. For security it is better to let the Samba client tool ask for the password if needed, or obtain the password once with kinit.

If --password is not specified, the tool will check the PASSWD environment variable, followed by PASSWD_FD which is expected to contain an open file descriptor (FD) number.

Finally it will check PASSWD_FILE (containing a file path to be opened). The file should only contain the password. Make certain that the permissions on the file restrict access from unwanted users!

While Samba will attempt to scrub the password from the process title (as seen in ps), this is after startup and so is subject to a race.

--pw-nt-hash

The supplied password is the NT hash.

-A|--authentication-file=filename

This option allows you to specify a file from which to read the username and password used in the connection. The format of the file is: 
username = <value>
password = <value>
domain   = <value>

Make certain that the permissions on the file restrict access from unwanted users!

-P|--machine-pass

Use stored machine account password.

--simple-bind-dn=DN

DN to use for a simple bind.

--use-kerberos=desired|required|off

This parameter determines whether Samba client tools will try to authenticate using Kerberos. For Kerberos authentication you should use DNS names instead of IP addresses when connecting to a service. By default Samba client tools will try to use the default Kerberos credential cache (ccache). In case the ccache does not exist or -U|--user option was specified, clients will ask to enter a password and will obtain a Kerberos ticket (kinit) for you. If you want to use an alternative Kerberos credentical cache, use the --use-krb5-ccache option.

Note that specifying this parameter here will override the client use kerberos parameter in the /etc/samba/smb.conf file.

--use-krb5-ccache=CCACHE

Specifies the credential cache location for Kerberos authentication.

This will enforce --use-kerberos=required.

--use-winbind-ccache

Try to use the credential cache by winbind.

--client-protection=sign|encrypt|off

Sets the connection protection the client tool should use.

Note that specifying this parameter here will override the client protection parameter in the /etc/samba/smb.conf file.

In case you need more fine grained control you can use: --option=clientsmbencrypt=OPTION, --option=clientipcsigning=OPTION, --option=clientsigning=OPTION.
