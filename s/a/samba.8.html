NOMBRE

samba - Servidor para proporcionar servicios AD y SMB/CIFS a clientes

SINOPSIS

samba [-D|--daemon] [-F|--foreground] [-i|--interactive] [-M|--model=MODEL] [--maximum-runtime=seconds] [-b|--show-build] [--no-process-group] [-d|--debuglevel=DEBUGLEVEL] [--debug-stdout] [--configfile=CONFIGFILE] [--option=name=value] [-l|--log-basename=LOGFILEBASE] [--leak-report] [--leak-report-full] [-V|--version]

DESCRIPCIÓN

Este programa es parte del conjunto de herramientas de samba(7).

samba es el demonio servidor que proporciona servicios de Active Directory, compartición de archivos e impresión a los clientes. El servidor proporciona servicios de espacio de archivos y directorios a los clientes utilizando el protocolo SMB (o CIFS) y otros protocolos relacionados como DCE/RPC, LDAP y Kerberos.

Los clientes soportados incluyen MSCLIENT 3.0 para DOS, Windows for Workgroups, Windows 95/98/ME, Windows NT, Windows 2000/XP/2003, OS/2, DAVE para Macintosh y cifsfs para Linux.

Una descripción extensa de los servicios que el servidor puede proporcionar se encuentra en la página man del archivo de configuración que controla los atributos de dichos servicios (ver smb.conf(5). Esta página man no describirá los servicios, sino que se centrará en los aspectos administrativos de la ejecución del servidor.

Tenga en cuenta que la ejecución de este servidor tiene implicaciones de seguridad significativas, y la página del manual de smb.conf(5) debe considerarse lectura obligatoria antes de proceder con la instalación.

OPCIONES

-D|--daemon

Si se especifica, este parámetro hace que el servidor opere como un demonio. Es decir, se desvincula y se ejecuta en segundo plano, atendiendo peticiones en los puertos apropiados. Operar el servidor como un demonio es la forma recomendada de ejecutar samba para servidores que proporcionan servicios de archivos e impresión para más de un uso casual. Este interruptor se asume si samba se ejecuta en la línea de comandos de una shell.

-F|--foreground

Si se especifica, este parámetro hace que el proceso de samba no se convierta en un demonio, es decir, no realice un doble fork y no se desvincule de la terminal.

-i|--interactive

Si se especifica este parámetro, hace que el servidor se ejecute "interactivamente", no como un demonio, incluso si el servidor se ejecuta en la línea de comandos de una shell. Establecer este parámetro anula el modo demonio implícito cuando se ejecuta desde la línea de comandos. Samba también registra en la salida estándar, como si se hubiera dado el parámetro -S.

-M|--model

Este parámetro se puede usar para especificar el "modelo de proceso" que samba debe usar. Esto determina cómo se manejan los clientes concurrentes. Los modelos de proceso disponibles incluyen:
•single

Todos los servicios de Samba se ejecutan en un solo proceso. Esto no se recomienda para configuraciones de producción.

•standard

Se crea un proceso para cada servicio de Samba, y para aquellos servicios que lo soportan (actualmente solo LDAP y NETLOGON) se inicia un nuevo proceso por cada nueva conexión de cliente.

Históricamente, esta era la forma "estándar" en que Samba se comportaba hasta la v4.10. Tenga en cuenta que este modelo puede consumir muchos recursos si tiene un gran número de conexiones de clientes.

•prefork

El valor predeterminado. Se inicia un proceso para cada servicio de Samba, y se inician un número fijo de procesos de trabajo para aquellos servicios que lo soportan (actualmente LDAP, NETLOGON y KDC). Las conexiones de clientes se comparten entre los procesos de trabajo. Las peticiones de servicios que no soportan prefork son atendidas por un solo proceso para dicho servicio.

El número de procesos de trabajo de prefork iniciados se controla mediante el parámetro prefork children de smb.conf(5), que por defecto es 4.

--maximum-runtime=seconds

Establece el tiempo máximo de ejecución del proceso del servidor hasta la auto-terminación en segundos.

-b|--show-build

Imprime información sobre cómo se compiló Samba.

-d|--debuglevel=level

level es un número entero de 0 a 10. El valor por defecto si no se especifica este parámetro es 0.

Cuanto mayor sea este valor, más detalle se registrará en los archivos de registro sobre las actividades del servidor. En el nivel 0, solo se registrarán errores críticos y advertencias serias. El nivel 1 es un nivel razonable para el uso diario: genera una pequeña cantidad de información sobre las operaciones realizadas.

Los niveles superiores a 1 generarán una cantidad considerable de datos de registro y solo deben usarse al investigar un problema. Los niveles superiores a 3 están diseñados solo para desarrolladores y generan una ENORME cantidad de datos de registro, la mayoría de los cuales son extremadamente crípticos.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro log level en el archivo /etc/samba/smb.conf.

--debug-stdout

Esto redirigirá la salida de depuración a STDOUT. Por defecto, los demonios del servidor registran en un archivo de registro.

--configfile=CONFIGFILE

El archivo especificado contiene los detalles de configuración requeridos por el servidor. La información en este archivo incluye información específica del servidor, como qué archivo printcap usar, así como descripciones de todos los servicios que el servidor debe proporcionar. Ver /etc/samba/smb.conf para más información. El nombre del archivo de configuración por defecto se determina en tiempo de compilación.

--option=<name>=<value>

Establece la opción smb.conf(5) "<name>" al valor "<value>" desde la línea de comandos. Esto anula los valores predeterminados compilados y las opciones leídas del archivo de configuración. Si un nombre o un valor incluyen un espacio, envuelva todo --option=name=value entre comillas.

-l|--log-basename=logdirectory

Nombre base del directorio para los archivos de registro/depuración. La extensión ".progname" se añadirá (por ejemplo, log.smbclient, log.smbd, etc...). El archivo de registro nunca es eliminado por el cliente.

--leak-report

Habilita el informe de fugas de talloc al salir.

--leak-report-full

Habilita el informe completo de fugas de talloc al salir.

-V|--version

Imprime el número de versión del programa.

-?|--help

Imprime un resumen de las opciones de línea de comandos.

--usage

Muestra un breve mensaje de uso.

ARCHIVOS

/etc/rc

o el script de inicialización que su sistema utilice.

Si se ejecuta el servidor como un demonio al inicio, este archivo deberá contener una secuencia de inicio apropiada para el servidor.

/etc/services

Si se ejecuta el servidor a través del meta-demonio inetd, este archivo debe contener un mapeo del nombre del servicio (por ejemplo, netbios-ssn) al puerto del servicio (por ejemplo, 139) y al tipo de protocolo (por ejemplo, tcp).

/usr/local/samba/lib/smb.conf

Esta es la ubicación por defecto del archivo de configuración del servidor smb.conf(5). Otros lugares comunes donde los sistemas instalan este archivo son /usr/samba/lib/smb.conf y /etc/samba/smb.conf.

Este archivo describe todos los servicios que el servidor debe poner a disposición de los clientes. Ver smb.conf(5) para más información.

DIAGNÓSTICOS

La mayoría de los diagnósticos emitidos por el servidor se registran en un archivo de registro especificado. El nombre del archivo de registro se especifica en tiempo de compilación, pero puede ser anulado en la línea de comandos.

El número y la naturaleza de los diagnósticos disponibles dependen del nivel de depuración utilizado por el servidor. Si tiene problemas, establezca el nivel de depuración a 3 y revise los archivos de registro.

La mayoría de los mensajes son razonablemente autoexplicativos. Desafortunadamente, en el momento en que se creó esta página man, hay demasiados diagnósticos disponibles en el código fuente para justificar la descripción de cada uno de ellos. En esta etapa, su mejor opción sigue siendo buscar en el código fuente e inspeccionar las condiciones que dieron lugar a los diagnósticos que está viendo.
