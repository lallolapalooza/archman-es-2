NOMBRE

sane-mustek_pp - Backend de SANE para escáneres planos de puerto paralelo Mustek

DESCRIPCIÓN

La biblioteca sane-mustek_pp implementa un backend de SANE (Scanner Access Now Easy) que proporciona acceso a escáneres planos de puerto paralelo de Mustek y versiones OEM.

Hay 2 clases de escáneres de puerto paralelo Mustek: escáneres regulares CCD (dispositivo de cátodo frío) y escáneres CIS (sensor de imagen de contacto).

La versión actual de este backend soporta escáneres de tipo CCD y de tipo CIS.

(***) Posiblemente, el parámetro engine_delay tenga que configurarse a 1 ms para movimientos precisos del motor.

Tenga en cuenta que este backend aún está en construcción. Ciertos modelos actualmente no son compatibles y algunos quizás nunca lo sean porque el protocolo de comunicación aún es desconocido (por ejemplo, SE 12000 P).

Algunos escáneres funcionan más rápido cuando EPP/ECP está habilitado en la BIOS. Sin embargo, el modo EPP puede provocar bloqueos irrecuperables en algunos sistemas Linux. Si ese es su caso, puede deshabilitar ECP/EPP en su BIOS o deshabilitarlo en el propio backend (ver OPCIONES GLOBALES).

Tenga en cuenta que el backend necesita ejecutarse como root o tener los permisos de acceso apropiados a /dev/parport* si se compila el soporte de libieee1284. Para permitir el acceso de usuario al escáner, ejecute el backend a través de la interfaz de red (ver saned(8) y sane-net(5)). Tenga en cuenta también que el backend *no* soporta *compartición de parport*, es decir, si intenta imprimir mientras escanea, su ordenador puede colgarse. Para habilitar la compartición de parport, debe habilitar libieee1284(3) en tiempo de compilación. También puede tener que habilitar explícitamente el backend en su dll.conf. Simplemente elimine el símbolo de almohadilla en la línea "mustek_pp".

DEFINICIÓN DE DISPOSITIVO

Este backend permite definir y configurar múltiples dispositivos a través del archivo mustek_pp.conf (incluso simultáneamente, siempre que estén conectados a puertos paralelos diferentes). Asegúrese de editar este archivo antes de usar el backend.

Un dispositivo se puede definir de la siguiente manera:

escáner <nombre> <nombre del puerto> <driver>

donde

<nombre> es un nombre arbitrario para el dispositivo, opcionalmente entre comillas dobles, por ejemplo "LifeTec 9350".

<nombre del puerto> es el nombre del puerto paralelo al que está conectado el dispositivo. En caso de que se utilice libieee1284 para la comunicación con el puerto (configuración por defecto), los nombres de puerto válidos son parport0, parport1 y parport2.

En caso de que el backend esté configurado para E/S cruda (configuración antigua), se deben usar direcciones de puerto en lugar de nombres de puerto: 0x378, 0x278 o 0x3BC. El mapeo de puertos paralelos (lp0, lp1 y lp2) a estas direcciones puede ser diferente para diferentes versiones del kernel de Linux. Por ejemplo, si está utilizando un Kernel 2.2.x o superior y solo tiene un puerto paralelo, este puerto se llama lp0 independientemente de la dirección base. Sin embargo, este backend requiere la dirección base de su puerto. Si no está seguro de a qué puerto está conectado su escáner, eche un vistazo a su /etc/conf.modules, /etc/modules.conf y/o /proc/ioports.

Si no está seguro de qué puerto usar, puede usar el valor mágico * para sondear su escáner.

<driver> es el driver a usar para este dispositivo. Los drivers actualmente disponibles son:

cis600 : para 600 CP, 96 CP y versiones OEM
cis1200 : para 1200 CP y versiones OEM
cis1200+ : para 1200 CP+ y versiones OEM
ccd300 : para 600 IIIE P y versión OEM
¡Elegir el driver incorrecto puede dañar su escáner!
Especialmente, usar la configuración de 1200CP en un 600CP puede ser perjudicial. Si el escáner empieza a hacer un ruido fuerte, ¡¡¡apáguelo inmediatamente!!!

Usar el driver cis600 en un 1200CP o un 1200CP+ probablemente no sea peligroso. El driver cis1200+ también funciona para el 1200CP, y usar el driver cis1200 en un 1200CP+ normalmente resultará en escaneos que cubren solo la mitad del ancho del área de escaneo (tampoco es peligroso).

Si no está seguro del modelo exacto de su versión OEM, verifique la resolución óptica en el manual o en la caja: el 600CP tiene una resolución óptica máxima de 300x600 DPI, mientras que el 1200CP y el 1200CP+ tienen una resolución óptica máxima de 600x1200 DPI.

Ejemplos:

escáner "LifeTec 9350" 0x378 cis1200

escáner Mustek_600CP 0x378 cis600

escáner Mustek_600IIIEP * ccd300

Si tiene dudas sobre qué puerto debe usar, o si su escáner se detecta en absoluto, puede usar sane-find-scanner -p para sondear todos los puertos configurados.

CONFIGURACIÓN

El contenido del archivo mustek_pp.conf es una lista de definiciones de dispositivos y opciones de dispositivos que corresponden a los escáneres Mustek. Las líneas vacías y las líneas que comienzan con un signo de almohadilla (#) se ignoran. Las opciones tienen el siguiente formato:

opción <nombre> [<valor>]

Dependiendo de la naturaleza de la opción, un valor puede estar presente o no. Las opciones siempre se aplican a la definición del escáner que les precede. No hay opciones globales. Las opciones también son específicas del driver: no todos los drivers soportan todas las opciones posibles.

Opciones comunes

Las siguientes opciones están disponibles para todos los drivers (CCD y CIS):

engine_delay
Establece el tiempo de espera del motor, en milisegundos. El valor por defecto es 5 ms. Para los escáneres CIS más rápidos, el tiempo de espera puede ser reducido a 1 ms. Para algunos escáneres CCD más antiguos, puede ser necesario aumentar este valor. Si su escáner muestra rayas o tiene problemas con el movimiento del cabezal, pruebe a ajustar este valor.
strip_height
Establece la altura de las tiras de escaneo en píxeles. El valor por defecto es 0, lo que significa que el backend intentará determinar la altura de la tira por sí mismo (si es posible). Este ajuste es útil para escáneres que no anuncian correctamente su altura de tira (por ejemplo, el Mustek 1200 CP+).
no_calibration
Desactiva el procedimiento de calibración al inicio del escaneo. Esto puede ser útil para algunos escáneres que tienen problemas de calibración. Sin embargo, desactivar la calibración puede resultar en escaneos con colores incorrectos.
speed_calibration
Activa la calibración de velocidad. Esto puede mejorar la precisión de la calibración para algunos escáneres.

Opciones específicas del driver

ccd300

Este driver tiene las siguientes opciones:

ccd_mode
Establece el modo CCD. Los valores posibles son 0 (normal) y 1 (alta calidad). El modo de alta calidad puede producir mejores resultados pero es más lento.

(cis1200+)

Este driver tiene las siguientes opciones:

scan_line_delay
Establece el retraso entre líneas de escaneo en microsegundos. El valor por defecto es 100 microsegundos. Si experimenta problemas con líneas faltantes o incorrectas, puede intentar ajustar este valor.

EJEMPLOS

Para configurar un escáner Mustek 600 CP conectado al primer puerto paralelo (dirección 0x378), agregue la siguiente línea a /etc/sane.d/mustek_pp.conf:

scanner Mustek_600CP 0x378 cis600

Para configurar un escáner LifeTec 9350 conectado al segundo puerto paralelo (nombre parport1), agregue la siguiente línea:

scanner "LifeTec 9350" parport1 cis1200

Para configurar un escáner Mustek 600 IIIEP para usar el driver CCD y sondear el puerto, agregue la siguiente línea:

scanner Mustek_600IIIEP * ccd300

Para deshabilitar la calibración para el escáner Mustek 600 CP, agregue la opción no_calibration después de la definición del dispositivo:

scanner Mustek_600CP 0x378 cis600 no_calibration

DIAGNÓSTICOS

El backend sane-mustek_pp produce mensajes de depuración cuando se invoca con el nivel de depuración SANE_DEBUG_MUSTEK_PP (por ejemplo, ejecutando el comando `scanimage -L` con la variable de entorno `SANE_DEBUG_SANE_BACKENDS=32` establecida).

OPTIONS

This backend supports the following options:

Common options

bw <value>
Valor de discriminación blanco/negro que se utilizará durante el escaneo de lineart. Se asume que los valores de píxel por debajo de este valor son negros, y los valores por encima son blancos.
Valor predeterminado: 127
Mínimo: 0
Máximo: 255

Ejemplo: opción bw 150

Opciones del controlador CIS

top_adjust <valor>
Ajuste vertical del origen, expresado en milímetros (punto flotante). Esta opción se puede utilizar para calibrar la posición del origen, dentro de ciertos límites. Tenga en cuenta que los escáneres CIS son probablemente sensibles a la temperatura y que cierta imprecisión puede ser difícil de evitar. Las diferencias en el desplazamiento entre ejecuciones del orden de 1 a 2 mm no son inusuales.
Valor predeterminado: 0.0
Mínimo: -5.0
Máximo: 5.0

Ejemplo: opción top_adjust -2.5

slow_skip
Desactiva el salto rápido al inicio de la región de escaneo. Cuando la región a escanear no comienza en el origen, el controlador intentará mover el cabezal de escaneo a la velocidad más rápida posible hasta el área de escaneo. En algunos modelos, esto puede no funcionar, lo que resulta en grandes imprecisiones (hasta centímetros). Al configurar esta opción, el controlador se ve obligado a utilizar la velocidad normal durante el salto, lo que puede evitar los problemas de precisión. Actualmente, no hay modelos para los que se conozcan estos problemas de imprecisión.

Por defecto, se utiliza el salto rápido.

Ejemplo: opción slow_skip

engine_delay <valor>
En circunstancias normales, es suficiente que el controlador espere la señalización del escáner de que el motor está estable antes de que se pueda transmitir un nuevo comando del motor. En casos raros, ciertos escáneres y/o conjuntos de chips de puerto paralelo parecen impedir la detección confiable del estado del motor. Como resultado, los comandos del motor se transmiten demasiado pronto y el movimiento del cabezal del escáner se vuelve poco confiable. Se han reportado imprecisiones de hasta 10 cm en todo el rango de escaneo vertical. Para solucionar este problema, se puede configurar la opción engine_delay. Si está configurada, el controlador espera un tiempo adicional después de cada comando del motor, igual al parámetro engine_delay, expresado en milisegundos. En la práctica, un engine_delay de 1 ms suele ser suficiente. El retardo máximo es de 100 ms.

Tenga en cuenta que cada ms adicional de retardo puede sumar hasta 14 segundos al tiempo total de escaneo (la resolución más alta), por lo que se prefiere un valor lo más pequeño posible.

Valor predeterminado: 0
Mínimo: 0
Máximo: 100

Ejemplo: opción engine_delay 1

Opciones del controlador CCD

top <valor>
Número de líneas de escaneo a omitir hasta el inicio del área de escaneo. El número puede ser cualquier entero positivo. Los valores que conozco son 47 y 56.

Valor predeterminado: 47
Mínimo: 0
Máximo: ninguno

Ejemplo: opción top 56

waitbank <valor>
Los microsegundos a esperar para un cambio de banco. En realidad, no deberías tocar este valor. Puede ser cualquier entero positivo.

Valor predeterminado: 700
Mínimo: 0
Máximo: ninguno

Ejemplo: opción waitbank 700

A continuación, se muestra un archivo de configuración de ejemplo:

#

scanner "LifeTec 9350" 0x378 cis1200

#
# Un Mustek 600CP en el puerto 0x3BC
#
scanner "Mustek 600CP" 0x3BC cis600
# Algunas opciones de calibración (¡ejemplos!).
option bw 120
option top_skip 1.2
#
# Un Mustek 1200CP+ en el puerto 0x278
#
scanner "Mustek 1200CP plus" 0x278 cis1200+
# Algunas opciones de calibración (¡ejemplos!).
option bw 130
option top_skip 0.2
#
# Un Mustek 600 III EPP en el puerto parport0
#
scanner "Mustek 600 III EPP" parport0 ccd300
# Algunas opciones de calibración (¡ejemplos!).

OPCIONES GLOBALES

Puedes controlar el comportamiento general del backend sane-stek_pp mediante opciones globales que preceden a cualquier definición de escáner en el archivo mustek_pp.conf.

Actualmente, solo hay una opción global:

Opciones globales

no_epp
Desactiva el modo EPP del puerto paralelo: soluciona un error conocido en el código del puerto paralelo de Linux. Habilita esta opción si el backend se cuelga al intentar acceder al puerto paralelo en modo EPP.

Valor predeterminado: usar EPP

Ejemplo: opción no_epp

ENTORNO

SANE_CONFIG_DIR
Esta variable de entorno especifica la lista de directorios que pueden contener el archivo de configuración. En sistemas *NIX, los directorios están separados por dos puntos (`:'), en OS/2, están separados por punto y coma (`;'). Si esta variable no está configurada, el archivo de configuración se busca en dos directorios predeterminados: primero, el directorio de trabajo actual (".") y luego en /etc/sane.d. Si el valor de la variable de entorno termina con el carácter separador de directorios, entonces los directorios predeterminados se buscan después de los directorios especificados explícitamente. Por ejemplo, configurar SANE_CONFIG_DIR a "/tmp/config:" daría como resultado la búsqueda en los directorios tmp/config, . y /etc/sane.d (en este orden).
SANE_DEBUG_MUSTEK_PP
Si la biblioteca se compiló con soporte de depuración habilitado, esta variable de entorno controla el nivel de depuración para este backend. Por ejemplo, un valor de 128 solicita que se imprima toda la salida de depuración. Niveles más bajos reducen la verbosidad. 
nivel   salida de depuración
--------------------------------------
 0      nada
 1      errores
 2      advertencias y errores menores
 3      información adicional
 4      información de depuración
 5      flujo de código (aún no soportado)
 6      información de depuración especial
SANE_DEBUG_SANEI_PA4S2
Esta variable establece el nivel de depuración para la interfaz SANE del chipset Mustek A4S2. Tenga en cuenta que habilitar esto inundará su terminal con un millón de líneas de salida de depuración. 
nivel   salida de depuración
----------------------------
 0      nada
 1      errores
 2      advertencias
 3      cosas que es bueno saber
 4      flujo de código
 5      flujo de código detallado
 6      todo

BUG REPORTS

When reporting bugs, please include the following information:

The output of scanimage -L, as root.
This will help to verify that the backend is loaded and can detect your scanner.
The output of SANE_DEBUG_MUSTEK_PP=128 scanimage -L, as root.
This will show detailed information about the communication between the backend and your scanner hardware.
The model name and vendor of your scanner.
This information is usually found on the scanner itself or in its documentation.
The optical resolution and lamp type of your scanner.
These details can be found in the scanner's manual.
Any further comments.
Include any additional information that you think might be relevant, such as details about your operating system, scanner connection (parallel, USB), or any specific issues you are experiencing.
If you have comments about the documentation (what could be done better), or you think I should know something, please include it.
