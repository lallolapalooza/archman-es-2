sane-st400(5) Acceso Fácil a Escáneres SANE sane-st400(5)

NOMBRE

sane-st400 - Backend de SANE para escáneres planos Siemens ST/Highscan

DESCRIPCIÓN

La biblioteca sane-st400 implementa un backend de SANE (Scanner Access Now Easy) que proporciona acceso a escáneres planos Siemens ST400 y compatibles. Actualmente, los siguientes escáneres son compatibles con este backend:

Siemens ST400 (escala de grises de 6 bits)
Siemens ST800 (escala de grises de 6 bits)

El controlador soporta escaneos de línea de arte y escala de grises hasta 8bpp.

La serie Siemens ST/Highscan incluye varios modelos más, p.ej. el ST300 y el ST600. Si posees uno de estos escáneres, o un escáner distinto a los mencionados que funcione con este backend, por favor házmelo saber enviando el nombre del modelo del escáner, la ID SCSI y la revisión del firmware a sane-devel@alioth-lists.debian.net. Echa un vistazo a http://www.sane-project.org/mailing-lists.html para suscribirte a sane-devel.

NOMBRES DE DISPOSITIVO

Este backend espera nombres de dispositivo del tipo:

especial

Donde especial es la ruta del dispositivo especial que corresponde a un escáner SCSI. Para escáneres SCSI, el nombre del dispositivo especial debe ser un dispositivo SCSI genérico o un enlace simbólico a dicho dispositivo. En Linux, un nombre de dispositivo así podría ser /dev/sga o /dev/sge, por ejemplo. Consulta sane-scsi(5) para más detalles.

CONFIGURACIÓN

El contenido del archivo st400.conf es una lista de nombres de dispositivo que corresponden a escáneres Siemens. Las líneas vacías y las líneas que comienzan con un signo de almohadilla (#) son ignoradas. A continuación se muestra un ejemplo de archivo de configuración:

/dev/scanner
# esto es un comentario
/dev/sge

El archivo de configuración predeterminado que se distribuye con SANE se ve así:

scsi SIEMENS "ST 400" Scanner * * 3 0

En esta configuración, el controlador solo puede acceder al modelo ST400 en la ID SCSI 3 LUN 0 (ver sección BUGS más abajo para la razón). Para usar el controlador con otros modelos de escáner, añade una línea apropiada al archivo de configuración. Por ejemplo, para usarlo con un ST800 en la ID SCSI 3 LUN 0, añade la línea:

scsi SIEMENS "ST 800" Scanner * * 3 0

ARCHIVOS

/etc/sane.d/st400.conf
El archivo de configuración del backend (ver también la descripción de SANE_CONFIG_DIR más abajo).
/usr/lib/sane/libsane-st400.a
La biblioteca estática que implementa este backend.
/usr/lib/sane/libsane-st400.so
La biblioteca compartida que implementa este backend (presente en sistemas que soportan carga dinámica).

ENTORNO

SANE_CONFIG_DIR
Esta variable de entorno especifica la lista de directorios que pueden contener el archivo de configuración. En sistemas *NIX, los directorios están separados por dos puntos (`:'), en OS/2, están separados por un punto y coma (`;'). Si esta variable no está establecida, el archivo de configuración se busca en dos directorios predeterminados: primero, el directorio de trabajo actual (".") y luego en /etc/sane.d. Si el valor de la variable de entorno termina con el carácter separador de directorio, entonces los directorios predeterminados se buscan después de los directorios especificados explícitamente. Por ejemplo, establecer SANE_CONFIG_DIR a "/tmp/config:" resultaría en la búsqueda de los directorios tmp/config, ., y /etc/sane.d (en ese orden).
SANE_DEBUG_ST400
Si la biblioteca fue compilada con soporte de depuración habilitado, esta variable de entorno controla el nivel de depuración para este backend. Por ejemplo, un valor de 128 solicita que se imprima toda la salida de depuración. Niveles más bajos reducen la verbosidad.

FUNCIONALIDAD FALTANTE

Todo excepto lo más básico.

BUGS

Actualmente, el backend no comprueba si el dispositivo adjunto es realmente un ST400. Aceptará felizmente cualquier cosa que coincida con las entradas de configuración. Esto facilita la prueba del backend con otros escáneres: simplemente añade una línea apropiada al archivo de configuración. El archivo de configuración tal como se distribuye (ver arriba) solo funciona con el ST400. Ten cuidado: si no hay ningún archivo de configuración, el backend utiliza por defecto /dev/scanner.

El ST400 responde en todas las ocho LUN SCSI. Normalmente esto no es un problema, ya que el soporte de LUN suele estar deshabilitado en los controladores SCSI, pero si estás viendo múltiples instancias del escáner en una lista de dispositivos, deshabilita las LUN en tu configuración SCSI o cambia la entrada en el archivo de configuración para que coincida solo con la LUN 0.

DEPURACIÓN

Si encuentras un error, por favor establece la variable de entorno SANE_DEBUG_ST400 a 128 e intenta reproducir el problema. Luego envíame un informe con el registro adjunto.

Si encuentras un error en el bus SCSI o imágenes recortadas y/o desplazadas, por favor, también establece la variable de entorno SANE_DEBUG_SANEI_SCSI a 128 antes de enviarme el informe.
