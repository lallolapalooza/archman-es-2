NOMBRE

safe - Creación y manipulación de intérpretes seguros

SINOPSIS

::safe::interpCreate ?hijo? ?opciones...?

::safe::interpInit hijo ?opciones...?

::safe::interpConfigure hijo ?opciones...?

::safe::interpDelete hijo

::safe::interpAddToAccessPath hijo directorio

::safe::interpFindInAccessPath hijo directorio

::safe::setLogCmd ?cmd arg...?

OPCIONES

?-accessPath listaRutas? ?-statics booleano? ?-noStatics? ?-nested booleano? ?-nestedLoadOk? ?-deleteHook script?

DESCRIPCIÓN

Safe Tcl es un mecanismo para ejecutar scripts Tcl no confiables de forma segura y para proporcionar acceso mediado por dichos scripts a funcionalidades potencialmente peligrosas.

Safe Tcl asegura que los scripts Tcl no confiables no puedan dañar la aplicación anfitriona. Previene ataques de integridad y privacidad. Se impide que los scripts Tcl no confiables corrompan el estado de la aplicación anfitriona o del equipo. También se impide que los scripts no confiables divulguen información almacenada en el equipo anfitrión o en la aplicación anfitriona a ninguna parte.

Safe Tcl permite a un intérprete padre crear intérpretes seguros y restringidos que contienen un conjunto de alias predefinidos para los comandos source, load, file, encoding y exit, y que son capaces de utilizar los mecanismos de carga automática y de paquetes.

No se filtra ningún conocimiento de la estructura del sistema de archivos al intérprete seguro, ya que solo tiene acceso a una ruta virtualizada que contiene tokens. Cuando el intérprete seguro solicita cargar un archivo, utiliza el token en la ruta virtual como parte del nombre del archivo a cargar; el intérprete padre traduce de forma transparente el token a un nombre de directorio real y ejecuta la operación solicitada (ver la sección SEGURIDAD a continuación para más detalles). Se pueden seleccionar diferentes niveles de seguridad utilizando los indicadores opcionales de los comandos descritos a continuación.

Todos los comandos proporcionados en el intérprete padre por Safe Tcl residen en el espacio de nombres safe.

COMANDOS

Los siguientes comandos se proporcionan en el intérprete padre:

::safe::interpCreate ?hijo? ?opciones...?
Crea un intérprete seguro, instala los alias descritos en la sección ALIAS e inicializa el mecanismo de carga automática y de paquetes según lo especificado por las opciones proporcionadas. Consulte la sección OPCIONES a continuación para una descripción de los argumentos opcionales. Si se omite el argumento hijo, se generará un nombre. ::safe::interpCreate siempre devuelve el nombre del intérprete.

El nombre del intérprete hijo puede incluir separadores de espacios de nombres, pero no puede tener separadores de espacios de nombres al principio o al final, ni caracteres de dos puntos excesivos en los separadores de espacios de nombres. El nombre del intérprete se califica en relación con el espacio de nombres global ::, no con el espacio de nombres en el que se evalúa el comando ::safe::interpCreate.

::safe::interpInit hijo ?opciones...?
Este comando es similar a interpCreate excepto en que no crea el intérprete seguro. hijo debe haber sido creado por algún otro medio, como interp create -safe. El nombre del intérprete hijo puede incluir separadores de espacios de nombres, sujeto a las mismas restricciones que para interpCreate.
::safe::interpConfigure hijo ?opciones...?
Si no se proporcionan opciones, devuelve la configuración de todas las opciones para el intérprete seguro nombrado como una lista de opciones y sus valores actuales para ese hijo. Si se proporciona un único argumento adicional, devolverá una lista de 2 elementos nombre y valor donde nombre es el nombre completo de esa opción y valor el valor actual para esa opción y el hijo. Si se proporcionan más de dos argumentos adicionales, reconfigurará el intérprete seguro y cambiará cada una y solo las opciones proporcionadas. Consulte la sección OPCIONES a continuación para la descripción de las opciones. Ejemplo de uso:
# Crear un nuevo intérprete con la misma configuración que "$i0":
set i1 [safe::interpCreate {*}[safe::interpConfigure $i0]]
# Obtener el deleteHook actual
set dh [safe::interpConfigure $i0  -del]
# Cambiar (solo) el atributo statics loading ok de un
# intérprete y su deleteHook (dejando el resto sin cambios):
safe::interpConfigure $i0  -delete {foo bar} -statics 0
::safe::interpDelete hijo
Elimina el intérprete seguro y limpia las estructuras de datos correspondientes del intérprete padre. Si se especificó un script deleteHook para este intérprete, se evalúa antes de que se elimine el intérprete, con el nombre del intérprete como argumento adicional.
::safe::interpFindInAccessPath hijo directorio
Este comando busca y devuelve el token para el directorio real directorio en la ruta de acceso virtual actual del intérprete seguro. Genera un error si no se encuentra el directorio. Ejemplo de uso:
$hijo eval [list set tk_library \
      [::safe::interpFindInAccessPath $nombre $tk_library]]
::safe::interpAddToAccessPath hijo directorio
Este comando agrega directorio a la ruta virtual mantenida para el intérprete seguro en el padre, y devuelve el token que se puede usar en el intérprete seguro para obtener acceso a los archivos en ese directorio. Si el directorio ya está en la ruta virtual, solo devuelve el token sin agregar el directorio nuevamente a la ruta virtual. Ejemplo de uso:
$hijo eval [list set tk_library \
      [::safe::interpAddToAccessPath $nombre $tk_library]]
::safe::setLogCmd ?cmd arg...?
Este comando instala un script que se llamará cuando ocurran eventos interesantes en el ciclo de vida de un intérprete seguro. Cuando se llama sin argumentos, devuelve el script instalado actualmente. Cuando se llama con un argumento, una cadena vacía, el script instalado actualmente se elimina y se desactiva el registro. El script se invocará con un argumento adicional, una cadena que describe el evento de interés. El propósito principal es ayudar en la depuración de intérpretes seguros. Usando esta facilidad puede obtener mensajes de error completos mientras que el intérprete seguro solo recibe mensajes de error genéricos. Esto evita que un intérprete seguro vea mensajes sobre fallos y otros eventos que puedan contener información sensible como nombres de directorios reales.

Ejemplo de uso:

::safe::setLogCmd puts stderr

A continuación se muestra la salida de una sesión de ejemplo en la que un intérprete seguro intentó cargar un archivo no encontrado en su ruta de acceso virtual. Tenga en cuenta que el intérprete seguro solo recibió un mensaje de error diciendo que el archivo no se encontró:

NOTICE for child interp10 : Created
NOTICE for child interp10 : Setting accessPath=(/foo/bar) staticsok=1 nestedok=0 deletehook=()
NOTICE for child interp10 : auto_path in interp10 has been set to {$p(:0:)}
ERROR for child interp10 : /foo/bar/init.tcl: no such file or directory

OPCIONES

Las siguientes opciones son comunes a ::safe::interpCreate, ::safe::interpInit y ::safe::interpConfigure. Cualquier nombre de opción se puede abreviar a su nombre mínimo no ambiguo. Los nombres de opción no distinguen entre mayúsculas y minúsculas.

-accessPath listaDirectorios
Esta opción establece la lista de directorios desde los cuales el intérprete seguro puede source y load archivos. Si esta opción no se especifica, o si se proporciona como una lista vacía, el intérprete seguro utilizará los mismos directorios que su padre para la carga automática. Consulte la sección SEGURIDAD a continuación para más detalles sobre rutas virtuales, tokens y control de acceso.

safe(n) — Arch manual pages

NAME

safe — Create and manage safe interpreters

SYNOPSIS

::safe::interpCreate ?name? ?options...?

::safe::interpInit interpName ?options...?

::safe::interpConfigure interpName ?options...?

::safe::interpDelete interpName

::safe::interpFind ?pattern?

DESCRIPTION

The safe Tcl package is a collection of Tcl commands that allow the creation and management of new interpreters that are restricted in their capabilities. These interpreters, referred to as safe interpreters, can be used to evaluate untrusted Tcl code in a controlled environment. Safe Tcl provides a mechanism for restricting access to commands, variables, file system operations, and other potentially dangerous operations. This is achieved by creating interpreters that have a restricted set of available commands, and by mediating access to sensitive operations through the parent interpreter.

The commands provided by Safe Tcl are:

::safe::interpCreate
Creates a new safe interpreter and returns its name.
::safe::interpInit
Initializes an existing interpreter to be a safe interpreter.
::safe::interpConfigure
Configures the security properties of a safe interpreter.
::safe::interpDelete
Deletes a safe interpreter.
::safe::interpFind
Finds existing safe interpreters.

COMMANDS

::safe::interpCreate ?name? ?options...?
Creates a new interpreter and initializes it to be a safe interpreter. If name is provided, it is used as the name of the new interpreter. If name is not provided, a name is automatically generated. The new interpreter is created using the interp create command. The interpreter is then initialized using the ::safe::interpInit command with the given options. The command returns the name of the newly created safe interpreter.

::safe::interpInit interpName ?options...?
Initializes an existing interpreter, named interpName, to be a safe interpreter. The interpreter must already exist. This command removes all commands from the interpreter except for a minimal set required for basic operation and then installs a restricted set of commands and aliases. See the ALIASES section for a list of available commands and aliases. The available options are:
-accessPath list
This option specifies a list of directories that the safe interpreter is allowed to access. The elements of the list are treated as tokens that are translated into real path names by the parent interpreter. This prevents the safe interpreter from learning about the structure of the file system. The default value is an empty list, which allows the safe interpreter to access packages in the same way the parent interpreter does (subject to other restrictions). See the SECURITY section for more details.
-deleteHook script
When this option is given a non-empty script, it will be evaluated in the parent with the name of the safe interpreter as an additional argument just before actually deleting the safe interpreter. Giving an empty value removes any currently installed deletion hook script for that safe interpreter. The default value ({}) is not to have any deletion call back.
-globTk boolean
This option controls whether the safe interpreter is allowed to load Tk related extensions. The default value is true: safe interpreters are allowed to load Tk extensions.
-loadTk boolean
This option controls whether the safe interpreter is allowed to load Tk related extensions. The default value is true: safe interpreters are allowed to load Tk extensions.
-nested boolean
This option specifies if the safe interpreter will be allowed to load packages into its own sub-interpreters. The default value is false : safe interpreters are not allowed to load packages into their own sub-interpreters.
-nestedLoadOk
This option is a convenience shortcut for -nested true and thus specifies the safe interpreter will be allowed to load packages into its own sub-interpreters.
-noStatics
This option is a convenience shortcut for -statics false and thus specifies that the safe interpreter will not be allowed to load statically linked packages.
-statics boolean
This option controls whether the safe interpreter is allowed to load statically linked packages. The default value is true : safe interpreters are allowed to load statically linked packages.
::safe::interpConfigure interpName ?options...?
Configures the security properties of an existing safe interpreter. The available options are the same as for ::safe::interpInit. The command returns a list of the current configuration options if no options are specified, otherwise it returns an empty string.

::safe::interpDelete interpName
Deletes the specified safe interpreter. If a delete hook script was registered using the -deleteHook option, it is evaluated just before the interpreter is deleted.

::safe::interpFind ?pattern?
Returns a list of the names of all existing safe interpreters that match the given pattern. If pattern is not provided, all safe interpreters are returned. The pattern matching is done using the standard Tcl globbing rules.

ALIASES

The following aliases are provided in a safe interpreter:

source fileName
The requested file, a Tcl source file, is sourced into the safe interpreter if it is found. The source alias can only source files from directories in the virtual path for the safe interpreter. The source alias requires the safe interpreter to use one of the token names in its virtual path to denote the directory in which the file to be sourced can be found. See the section on SECURITY for more discussion of restrictions on valid filenames.
load fileName
The requested file, a shared object file, is dynamically loaded into the safe interpreter if it is found. The filename must contain a token name mentioned in the virtual path for the safe interpreter for it to be found successfully. Additionally, the shared object file must contain a safe entry point; see the manual page for the load command for more details.
file ?subCmd args...?
The file alias provides access to a safe subset of the subcommands of the file command; it allows only dirname, join, extension, root, tail, pathtype and split subcommands. For more details on what these subcommands do see the manual page for the file command.
encoding ?subCmd args...?
The encoding alias provides access to a safe subset of the subcommands of the encoding command; it disallows setting of the system encoding, but allows all other subcommands including system to check the current encoding.
exit
The calling interpreter is deleted and its computation is stopped, but the Tcl process in which this interpreter exists is not terminated.

SECURITY

Safe Tcl does not attempt to completely prevent annoyance and denial of service attacks. These forms of attack prevent the application or user from temporarily using the computer to perform useful work, for example by consuming all available CPU time or all available screen real estate. These attacks, while aggravating, are deemed to be of lesser importance in general than integrity and privacy attacks that Safe Tcl is to prevent.

The commands available in a safe interpreter, in addition to the safe set as defined in interp manual page, are mediated aliases for source, load, exit, and safe subsets of file and encoding. The safe interpreter can also auto-load code and it can request that packages be loaded.

Because some of these commands access the local file system, there is a potential for information leakage about its directory structure. To prevent this, commands that take file names as arguments in a safe interpreter use tokens instead of the real directory names. These tokens are translated to the real directory name while a request to, e.g., source a file is mediated by the parent interpreter. This virtual path system is maintained in the parent interpreter for each safe interpreter created by ::safe::interpCreate or initialized by ::safe::interpInit and the path maps tokens accessible in the safe interpreter into real path names on the local file system thus preventing safe interpreters from gaining knowledge about the structure of the file system of the host on which the interpreter is executing. The only valid file names arguments for the source and load aliases provided to the child are path in the form of [file join token filename] (i.e. when using the native file path formats: token/filename on Unix and token\filename on Windows), where token is representing one of the directories of the accessPath list and filename is one file in that directory (no sub directories access are allowed).

When a token is used in a safe interpreter in a request to source or load a file, the token is checked and translated to a real path name and the file to be sourced or loaded is located on the file system. The safe interpreter never gains knowledge of the actual path name under which the file is stored on the file system.

To further prevent potential information leakage from sensitive files that are accidentally included in the set of files that can be sourced by a safe interpreter, the source alias restricts access to files meeting the following constraints: the file name must fourteen characters or shorter, must not contain more than one dot (“.”), must end up with the extension (“.tcl”) or be called (“tclIndex”.)

Each element of the initial access path list will be assigned a token that will be set in the child auto_path and the first element of that list will be set as the tcl_library for that child.

If the access path argument is not given or is the empty list, the default behavior is to let the child access the same packages as the parent has access to (Or to be more precise: only packages written in Tcl (which by definition cannot be dangerous as they run in the child interpreter) and C extensions that provides a _SafeInit entry point). For that purpose, the parent's auto_path will be used to construct the child access path. In order that the child successfully loads the Tcl library files (which includes the auto-loading mechanism itself) the tcl_library will be added or moved to the first position if necessary, in the child access path, so the child tcl_library will be the same as the parent's (its real path will still be invisible to the child though). In order that auto-loading works the same for the child and the parent in this by default case, the first-level sub directories of each directory in the parent auto_path will also be added (if not already included) to the child access path. You can always specify a more restrictive path for which sub directories will never be searched by explicitly specifying your directory list with the -accessPath flag instead of relying on this default mechanism.

When the accessPath is changed after the first creation or initialization (i.e. through interpConfigure -accessPath list), an auto_reset is automatically evaluated in the safe interpreter to synchronize its auto_index with the new token list.
