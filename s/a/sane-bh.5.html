NOMBRE

sane-bh - Backend SANE para escáneres de documentos Bell+Howell Copiscan II series

DESCRIPCIÓN

La biblioteca sane-bh implementa un backend SANE (Scanner Access Now Easy) que proporciona acceso a los escáneres de documentos Bell+Howell Copiscan II series. El Copiscan II 6338 ha sido el modelo de escáner principal utilizado durante el desarrollo y las pruebas, pero dado que la interfaz de programación para toda la serie es coherente, el backend debería funcionar para los siguientes modelos de escáner:

COPISCAN II 6338 Duplex Scanner con ACE
COPISCAN II 2135 Simplex Scanner
COPISCAN II 2137(A) Simplex Scanner (con ACE)
COPISCAN II 2138A Simplex Scanner con ACE
COPISCAN II 3238 Simplex Scanner
COPISCAN II 3338(A) Simplex Scanner (con ACE)

Si tiene un escáner Bell+Howell y puede probarlo con este backend, póngase en contacto con sane-devel@alioth-lists.debian.net con el número de modelo y los resultados de las pruebas. Eche un vistazo a http://www.sane-project.org/mailing-lists.html sobre la suscripción a sane-devel. Además, el autor tiene curiosidad sobre la probabilidad de usar este backend con las series de escáneres más nuevas 4000 y 8000. Si tiene uno de esos, por favor hágame saber.

Los escáneres de documentos Bell+Howell Copiscan II series son escáneres de alto volumen y alto rendimiento diseñados para aplicaciones de escaneo de documentos. Como tales, son escáneres de línea/escala de grises que admiten un número fijo de resoluciones bastante bajas (por ejemplo, 200/240/300 ppp). Sin embargo, tienen una serie de características interesantes y útiles adecuadas a las necesidades de las aplicaciones de imagen documental. Este backend intenta admitir tantas de estas características como sea posible.

La principal referencia técnica utilizada en la escritura de este backend es el Bell and Howell Copiscan II Remote SCSI Controller (RSC) OEM Manual Técnico Versión 1.5. El HOWTO de programación SCSI de Linux, la documentación de la API de SANE y el código fuente de SANE también fueron recursos extremadamente valiosos.

La última versión del backend, información adicional y consejos útiles están disponibles en la página principal del backend:

http://www.martoneconsulting.com/sane-bh.html

NOMBRES DE DISPOSITIVO

Este backend espera nombres de dispositivo del tipo:

especial

Donde especial es el nombre de ruta del dispositivo especial que corresponde a un escáner SCSI. Para escáneres SCSI, el nombre del dispositivo especial debe ser un dispositivo SCSI genérico o un enlace simbólico a dicho dispositivo. En Linux, un nombre de dispositivo de este tipo tiene un formato como /dev/sga o /dev/sg0, por ejemplo. Vea sane-scsi(5) para más detalles.

OPCIONES

Opciones de modo de escaneo:
--vista-preliminar[=(sí|no)] [no]
Solicita un escaneo de calidad de vista preliminar. Cuando la vista preliminar se establece en sí, la compresión de imagen se deshabilita y la imagen se entrega en un fotograma SANE_FRAME_GRAY.
--modo lineart|halftone [lineart]
Selecciona el modo de escaneo (por ejemplo, lineart, monocromo o color).
--resolución 200|240|300dpi [200]
Establece la resolución de la imagen escaneada. Cada modelo de escáner admite una lista de resoluciones estándar; solo se pueden utilizar estas resoluciones.
--compresión none|g31d|g32d|g42d [none]
Establece el modo de compresión del escáner. Determina el tipo de datos devueltos por el escáner. Los valores son:

none - datos sin comprimir - entregados en un fotograma SANE_FRAME_GRAY
g31d - CCITT G3 1 dimensión (MH) - entregado en un fotograma SANE_FRAME_G31D
g32d - CCITT G3 2 dimensiones (MR, K=4) - entregado en un fotograma SANE_FRAME_G32D
g42d - CCITT G4 (MMR) - entregado en un fotograma SANE_FRAME_G42D

NOTA: El uso de los valores de compresión g31d, g32d y g42d hace que el backend genere formatos de fotograma opcionales que pueden no ser compatibles con todos los frontends SANE.

Opciones de geometría:
--borde-automático[=(sí|no)] [sí]
Habilita/deshabilita la detección automática de bordes de imagen. Cuando está habilitado, la unidad RSC detecta automáticamente el área de la imagen y establece la geometría de la ventana para que coincida.
--tamaño-papel Custom|Letter|Legal|A3|A4|A5|A6|B4|B5 [Custom]
Especifica la geometría de la ventana de escaneo especificando el tamaño del papel de los documentos a escanear.
--pi-x 0..297.18mm [0]
Posición X superior izquierda del área de escaneo.
--pi-y 0..431.8mm [0]
Posición Y superior izquierda del área de escaneo.
--id-x 0..297.18mm [297.18]
Posición X inferior derecha del área de escaneo.
--id-y 0..431.8mm [431.8]
Posición Y inferior derecha del área de escaneo.
Opciones del alimentador:
--fuente Alimentador Automático de Documentos|Bandeja de Alimentación Manual [Alimentador Automático de Documentos]
Selecciona la fuente de escaneo (como un alimentador de documentos). Esta opción se proporciona para permitir múltiples escaneos de imágenes con xsane(1); no tiene otro propósito.
--lote[=(sí|no)] [no]
Habilita/deshabilita el escaneo en modo lote. El modo lote permite escanear a máxima velocidad mediante almacenamiento en búfer dentro de la unidad RSC. Se recomienda esta opción al realizar escaneos de varias páginas hasta que se vacíe el alimentador.
--dúplex[=(sí|no)] [no]
Habilita el escaneo dúplex (a doble cara). El escáner toma una imagen de cada lado del documento durante una sola pasada por el escáner. Se entrega la página frontal seguida de la página posterior. La mayoría de las opciones, como la compresión, afectan a ambas páginas, la frontal y la posterior.
--tiempo-de-espera-adf 0..255 [0]
Establece el tiempo de espera en segundos para el alimentador automático de documentos (ADF). El valor 0 especifica el valor predeterminado de hardware que varía según el modelo del escáner.
--tiempo-de-espera-manual 0..255 [0]
Establece el tiempo de espera en segundos para el alimentador semiautomático. El valor 0 especifica el valor predeterminado de hardware que varía según el modelo del escáner.
--verificar-adf[=(sí|no)] [no]
Verifica el estado del ADF antes de iniciar el escaneo utilizando el comando OBJECT POSITION. Tenga en cuenta que esta función requiere el nivel de firmware RSC 1.5 o superior y el interruptor DIP 4 debe estar en la posición encendida. NOTA: Esta opción no ha sido probada extensamente y puede producir resultados indeseables.
Mejora:
--panel-de-control[=(sí|no)] [sí]
Habilita el panel de control del escáner para seleccionar parámetros de mejora de imagen. Cuando la opción se establece en no, las siguientes opciones se utilizan para controlar la mejora de imagen. Consulte la guía del usuario del escáner Bell+Howell para obtener información completa sobre la funcionalidad ACE.
--funcion-ace -4..4 [3]
Especifica la función de mejora automática del contraste (ACE).
--sensibilidad-ace 0..9 [5]
Especifica la sensibilidad de mejora automática del contraste (ACE).
--brillo 0..255 [0]
Controla el brillo de la imagen adquirida. Se ignora para escáneres compatibles con ACE.
--umbral 0..255 [0]
Selecciona el brillo mínimo para ge

SUPPORTED FEATURES

Compression
The backend can directly receive G3/G4 compressed data from the scanner over the SCSI bus. The backend supports these compression formats via the --g31d, --g32d, --g42d options, respectively. Many SANE frontends are not equipped to deal with these formats, however. The SANE frontend scanadf(1) supports these optional frame formats. The compressed image data is written directly to a file and can then be processed by a scan-script using the --scan-script option. Examples of this are given on the scanadf(1) homepage.
Detección Automática de Bordes
El escáner puede detectar automáticamente el tamaño del papel y ajustar la geometría de la ventana de escaneo apropiadamente. El backend soporta esta útil característica con la opción --autoborder. Está habilitada por defecto.
Escaneo en Modo Batch
El modo de escaneo batch permite un máximo rendimiento. Los parámetros de Set Window deben permanecer constantes durante todo el batch.
Generación de Iconos
La función Icon genera una miniatura de la imagen de página completa, que puede ser transferida como si fuera una página separada. Esto permite al host mostrar rápidamente una representación en miniatura durante la operación de escaneo. Quizás esta sería una excelente manera de implementar un escaneo de previsualización, pero dado que un escaneo normal es tan rápido, podría no valer la pena el esfuerzo.
Secciones Múltiples
Se pueden definir múltiples secciones (ventanas de escaneo secundarias) para las páginas frontales y traseras. Cada sección puede tener características diferentes (por ejemplo, geometría, compresión). Las secciones se devuelven como si fueran imágenes escaneadas por separado. Además, las secciones pueden utilizarse para mejorar enormemente la precisión y eficiencia del proceso de decodificación de códigos de barras/ códigos de parche limitando el área de búsqueda a un pequeño subconjunto de la página. La mayoría de los escáneres de la serie Copiscan II soportan hasta 8 secciones definidas por el usuario.
Soporte para Decodificación de Códigos de Barras/Parche
La unidad RSC puede reconocer Códigos de Barras y Parches de varios tipos incrustados en la imagen escaneada. Los códigos se decodifican y los datos se devuelven al frontend como un marco de texto. El texto está codificado en xml y contiene una gran cantidad de información sobre los datos decodificados, como la ubicación donde se encontró, su orientación y el tiempo que tardó en encontrarse. Puede encontrar más información sobre el contenido de este marco de texto, así como algunos ejemplos de decodificación de códigos de barras, en la página de inicio del backend.

LIMITACIONES

Decodificación de un solo tipo de código de barras por escaneo
La unidad RSC puede buscar hasta seis tipos diferentes de códigos de barras a la vez. Si bien el código generalmente soporta esto también, la opción --barcode-search-bar solo permite al usuario especificar un único tipo de código de barras. Quizás se podría agregar otra opción que permita una lista de códigos de tipo de barras separados por comas para abordar esto.
Escaneo de un número fijo de páginas en modo batch
La separación de la funcionalidad del frontend y el backend en SANE presenta un problema para soportar la funcionalidad de 'cancelar batch' en el escáner. En modo batch, el escáner siempre está una página por delante del host. El host, sabiendo de antemano qué página será la última, puede cancelar el modo batch antes de iniciar el último comando de escaneo. Actualmente, no hay ningún mecanismo disponible para que el frontend pase este conocimiento al backend. Si el modo batch está habilitado y --end-count termina una sesión de scanadf(1), se pasará una página adicional a través del escáner, pero no se leerá ni se entregará al frontend. El problema se puede evitar especificando --batch=no al escanear un número fijo de páginas.
Detector de Parches Revisión 1.2
Existe un algoritmo mejorado de detección de códigos de parche en el RSC con revisión 1.2 o superior que es más rápido y confiable que el decodificador estándar de códigos de Barras/Parches. Esto no es compatible actualmente.

BUGS

Los informes detallados de errores son bienvenidos, ¡y esperados! ;)

Si ha encontrado algo que cree que es un error, por favor intente reproducirlo con la variable de entorno SANE_DEBUG_BH configurada a 255, y envíe un informe detallando las condiciones que rodean el error a sane-devel@alioth-lists.debian.net.
