NOMBRE

sane-genesys - Backend SANE para escáneres planos USB basados en GL646, GL841, GL843, GL847 y GL124

DESCRIPCIÓN

La biblioteca sane-genesys implementa un backend SANE (Scanner Access Now Easy) que proporciona acceso a escáneres planos USB basados en los chips Genesys GL646, GL841, GL843, GL847 y GL124. En la actualidad, se sabe que los siguientes escáneres funcionan con este backend:

Canon LiDE 35/40/50/60/100/110/120/200/210/220/700
Hewlett-Packard HP2300C/HP2400/HP3670/HP3690/G4010/G4050
Medion MD5345/MD6228/MD6274
Panasonic KV-SS080
Plustek OpticBook 3600
Pentax DSmobile 600
Syscan/Ambir DocketPORT 467/485/487/665/685
Visioneer OneTouch 7100/Strobe XP100 (rev3)/XP200/XP300/Roadwarrior
Xerox Travel Scanner 100, OneTouch 2400

Este es software estable para modelos compatibles. Pero si prueba escáneres nuevos o no probados, mantenga la mano en el enchufe del escáner y desconéctelo si el cabezal choca al final del área de escaneo.

Si posee un escáner distinto a los mencionados anteriormente que funcione con este backend, por favor, hágame saber enviando el nombre exacto del modelo del escáner y los IDs de vendedor y producto USB (por ejemplo, desde /proc/bus/usb/devices, sane-find-scanner o syslog) a la lista de correo sane-devel. Incluso si el nombre del escáner es solo ligeramente diferente de los modelos mencionados anteriormente, por favor, hágame saber.

Si posee un escáner que no es detectado por el backend genesys pero tiene un chipset GL646, GL841, GL843, GL847 o GL124, puede intentar añadirlo al backend.

CALIBRACIÓN

Para dar una calidad de imagen correcta, los escáneres alimentados por hojas necesitan ser calibrados usando la hoja de calibración que se vende con el escáner. Para realizar la calibración, debe insertar este objetivo en el alimentador y luego iniciar la calibración pasando la opción --calibrate a scanimage(1) o haciendo clic en el botón 'calibrate' disponible en las 'opciones avanzadas' en un frontend gráfico. El resultado de la calibración se almacena en un archivo en el directorio principal del usuario que la realiza. Si conecta el escáner en otra máquina o lo usa con otra cuenta, la calibración tendrá que rehacerse, a menos que use la opción --calibration-file. Si no se define ningún directorio principal, se usará USERAPPPROFILE, luego TMPDIR o TMP. Si ninguno de estos directorios existe, el backend intentará escribir en el directorio de trabajo actual. Los escáneres planos también usan el archivo de calibración como caché para evitar la calibración antes de cada escaneo. El nombre del archivo de calibración es el nombre del modelo del escáner si se detecta un solo escáner. En el caso de varios modelos idénticos, el nombre del archivo será el nombre del dispositivo USB lógico. El tiempo de expiración gestiona el tiempo que una calibración es válida en caché. Un valor de -1 significa para siempre, 0 significa sin caché.

OPCIONES EXTRA DE ESCANEO

--lamp-off-time número
La lámpara se apagará después del tiempo indicado (en minutos). Un valor de 0 significa que la lámpara no se apagará.
--threshold porcentaje
0..100% (en pasos de 1). Selecciona el brillo mínimo para obtener un punto blanco. Los píxeles con brillo por debajo de este valor se escanearán como negros.
--brightness valor
-100..100 (en pasos de 1). Establece la mejora de brillo. 0 para ninguna mejora, valores negativos para disminuir el brillo y valores positivos para aumentarlo.
--contrast valor
-100..100 (en pasos de 1). Establece la mejora de contraste. 0 para ninguna mejora, valores negativos para disminuir el contraste y valores positivos para aumentarlo.
--disable-interpolation sí|no
Al usar altas resoluciones donde la resolución horizontal es menor que la resolución vertical, los datos se expanden por software para preservar la geometría de la imagen. Esto se puede deshabilitar con esta opción para obtener datos escaneados reales.
--disable-dynamic-lineart sí|no
Deshabilita el uso de un algoritmo adaptable de software para generar arte lineal y se basa en el arte lineal del hardware.
--color-filter Ninguno|Rojo|Verde|Azul
Al usar escala de grises o arte lineal, esta opción selecciona el color utilizado. Usar un filtro de color dará un escaneo monocromático. Los escáneres basados en CIS pueden hacer escala de grises verdadera cuando no se selecciona ningún filtro (valor Ninguno).
--lamp-off-scan
La lámpara se apagará durante el escaneo. La calibración todavía se realizará con la lámpara encendida.
--clear-calibration
Borra los datos de caché de calibración, lo que desencadenará una nueva calibración para el dispositivo cuando ocurra el próximo escaneo.
--calibration-file
Especifica el nombre del archivo de calibración a usar. Al menos el directorio que contiene el archivo debe existir, ya que no se creará. Esta opción está deshabilitada si el backend se ejecuta como root. Puede ser utilizada en el caso de escáneres alimentados por hojas para compartir un archivo de calibración para varios usuarios.
--expiration-time
Especifica el tiempo (en minutos) que una calibración en caché se considera válida. Si es más antigua que el valor indicado, se realiza una nueva calibración. Un valor de -1 significa sin expiración y los valores en caché se conservan para siempre a menos que el usuario los borre con la opción de borrado de calibración. Un valor de 0 significa que la caché está deshabilitada.

Además, el backend expone varias opciones de 'software'. Estas son reimplementaciones de características proporcionadas nativamente por escáneres más grandes, pero ejecutándose en la computadora host. Esto permite que máquinas más pequeñas tengan capacidades similares. Tenga en cuenta que estas características son algo simplistas y pueden no funcionar tan bien como las implementaciones nativas. Tenga en cuenta también que todas estas características requieren que el controlador almacene en caché toda la imagen en memoria. Esto casi seguramente resultará en una reducción de la velocidad de escaneo.

--swcrop
Solicita al controlador que detecte los extremos del papel dentro de la imagen más grande y recorte los bordes vacíos.
--swdeskew
Solicita al controlador que detecte la rotación del papel dentro de la imagen más grande y contrarreste la rotación.
--swdespeck --despeck X
Solicita al controlador que encuentre y elimine puntos de diámetro X o menor de la imagen, y rellene el espacio con el color circundante promedio.
--swskip 0..100% (en pasos de 1) [0]
Solicita al controlador que descarte páginas con un bajo número de píxeles oscuros.
--swderotate[=(sí|no)] [no]
Solicita al controlador que detecte y corrija la rotación de imagen de 90 grados.

PROBLEMAS DEL SISTEMA

Este backend necesita tener instalada la biblioteca libusb-0.1.6 o posterior, y no ha sido probado en otra configuración que no sea un kernel de Linux 2.6.9 o superior. Sin embargo, debería funcionar en cualquier sistema con libusb donde se pueda compilar el paquete SANE. Para configurar permisos e información general sobre USB, consulte sane-usb(5).

CONFIGURACIÓN

El contenido del archivo genesys.conf es una lista de líneas usb que contienen los IDs de vendedor y producto que corresponden a los escáneres USB. El archivo también puede contener líneas de opciones. Las líneas vacías y las líneas que comienzan con un signo de almohadilla (#) se ignoran. Los escáneres se detectan automáticamente mediante declaraciones usb vendor_id product_id que ya están incluidas en genesys.conf. "vendor_id" y "product_id" son números hexadecimales que identifican el escáner.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

ARCHIVOS

/etc/sane.d/genesys.conf
El archivo de configuración del backend (ver también la descripción de SANE_CONFIG_DIR abajo).
/usr/lib/sane/libsane-genesys.a
La librería estática que implementa este backend.
/usr/lib/sane/libsane-genesys.so
La librería compartida que implementa este backend (presente en sistemas que soportan carga dinámica).

MEDIO AMBIENTE

SANE_CONFIG_DIR
Esta variable de entorno especifica la lista de directorios que pueden contener el archivo de configuración. En sistemas *NIX, los directorios se separan por dos puntos (`:'), en OS/2, se separan por un punto y coma (`;'). Si esta variable no está establecida, el archivo de configuración se busca en dos directorios predeterminados: primero, el directorio de trabajo actual (".") y luego en /etc/sane.d. Si el valor de la variable de entorno termina con el carácter separador de directorios, entonces los directorios predeterminados se buscan después de los directorios especificados explícitamente. Por ejemplo, establecer SANE_CONFIG_DIR a "/tmp/config:" resultaría en la búsqueda de los directorios tmp/config, ., y /etc/sane.d (en este orden).
SANE_DEBUG_GENESYS
Si la librería fue compilada con soporte de depuración habilitado, esta variable de entorno controla el nivel de depuración para este backend. Niveles de depuración más altos aumentan la verbosidad de la salida. Si el nivel de depuración se establece en 1 o superior, algunas opciones de depuración se vuelven disponibles que normalmente están ocultas. Manéjalas con cuidado. Esto imprimirá mensajes relacionados con las funciones principales de genesys.
SANE_DEBUG_GENESYS_IMAGE
Si la librería fue compilada con soporte de depuración habilitado, esta variable de entorno habilita el registro de datos de imagen intermedios. Para habilitar este modo, establece la variable de entorno a 1.

Ejemplo (salida completa y muy verbosa para gl646):
export SANE_DEBUG_GENESYS=255

LIMITACIONES

El ahorro de energía no está implementado para escáneres basados en gl646. El modo dinámico (emulado a partir de datos en escala de grises y con tramado) no está habilitado para escáneres gl646. El modo de línea de arte de hardware está limitado hasta 600 dpi para escáneres basados en gl847, debido a la forma en que se construyen los sensores de imagen.

Este backend será mucho más lento si no se utiliza libusb-1.0. Así que asegúrate de que sane-backends esté compilado con la opción --enable-libusb_1_0.

ERRORES

Para el LiDE 200, los datos escaneados a 4800 dpi se obtienen "tal cual" del sensor. Parece que el controlador de Windows realiza algún procesamiento digital para mejorarlo, lo cual no está implementado en el backend.
