sane-microtek(5) Acceso fácil a escáneres SANE sane-microtek(5)

NOMBRE

sane-microtek - backend SANE para escáneres Microtek

DESCRIPCIÓN

La biblioteca sane-microtek implementa un backend SANE (Scanner Access Now Easy) que proporciona acceso a los escáneres Microtek de "segunda generación". Actualmente, se sabe que el siguiente hardware funciona con este backend:

Microtek ScanMaker E2, E3, E6
Microtek ScanMaker II, IIG, IIHR, IISP, III
Microtek ScanMaker 35t, 35t+, 45t
Microtek ScanMaker 600GS, 600ZS (ver notas de errores)
Agfa StudioScan
Agfa StudioScan II, StudioScan IIsi
Agfa Arcus II (pero no el "Arcus")
Agfa DuoScan (preliminar)
Vobis "Highscreen Realscan"
Microtek Color PageWiz (preliminar)

Adaptador de medios transparentes
Alimentador automático de documentos

El controlador admite escaneos de línea artística, semitonos, escala de grises de 8bpp y color de 24bpp a resoluciones normales y "expandidas" (es decir, 1200x1200 en un E6), escaneos rápidos para previsualizaciones en color y tablas gamma descargables.

Los escáneres compatibles son todos escáneres SCSI. Sin embargo, algunos modelos de puerto paralelo pueden funcionar (en Linux), si utilizan un chip parport->scsi y si puedes encontrar un controlador scsi->parport. Se sabe que este es el caso del Color PageWiz.

El controlador no admite los escáneres Microtek más recientes, como el V330 y el V660, que utilizan un conjunto de comandos SCSI-II nuevo y muy diferente. Para esos, prueba el backend alternativo microtek2(5). La mayoría de los escáneres que no son SCSI utilizarían el nuevo conjunto de comandos. La mayoría de los escáneres más nuevos que el Scanmaker E6 utilizarían el nuevo conjunto de comandos.

Si tienes un escáner Microtek que no sea los enumerados anteriormente, infórmanos qué sucede --- consulta la sección ERRORES al final de este documento.

Aunque esta página del manual generalmente se actualiza con cada lanzamiento, la información actualizada sobre nuevos lanzamientos y consejos útiles adicionales están disponibles en la página principal del backend:

http://www.mir.com/mtek/

NOMBRES DE DISPOSITIVO

Este backend espera nombres de dispositivo de la forma:

especial

Donde especial es el nombre de ruta UNIX para el dispositivo especial que corresponde al escáner. El nombre del dispositivo especial debe ser un dispositivo SCSI genérico o un enlace simbólico a dicho dispositivo. En Linux, un nombre de dispositivo así podría ser /dev/sga o /dev/sge, por ejemplo.

CONFIGURACIÓN

El contenido del archivo microtek.conf es una lista de nombres de dispositivo que corresponden a escáneres Microtek. Las líneas vacías y las líneas que comienzan con un signo de almohadilla (#) se ignoran. A continuación se muestra un archivo de configuración de ejemplo:

/dev/scanner
# este es un comentario
/dev/sge

El archivo de configuración también puede contener los tokens especiales norealcal o noprecal. norealcal deshabilitará el uso de comandos de calibración mágicos y no documentados del escáner que se sabe que funcionan en el E6, pero que pueden no funcionar con otros modelos. noprecal deshabilitará la lógica que intenta evitar la precalibración del escáner. Esta lógica solo se habría activado si el código de calibración mágico estuviera desactivado.

ARCHIVOS

/etc/sane.d/microtek.conf
El archivo de configuración del backend (ver también la descripción de SANE_CONFIG_DIR a continuación).
/usr/lib/sane/libsane-microtek.a
La biblioteca estática que implementa este backend.
/usr/lib/sane/libsane-microtek.so
La biblioteca compartida que implementa este backend (presente en sistemas que admiten carga dinámica).

ENTORNO

SANE_CONFIG_DIR
Esta variable de entorno especifica la lista de directorios que pueden contener el archivo de configuración. En sistemas *NIX, los directorios se separan por dos puntos (`:'), en OS/2, se separan por punto y coma (`;'). Si esta variable no está establecida, el archivo de configuración se busca en dos directorios predeterminados: primero, el directorio de trabajo actual (".") y luego en /etc/sane.d. Si el valor de la variable de entorno termina con el carácter separador de directorios, entonces se buscan los directorios predeterminados después de los directorios especificados explícitamente. Por ejemplo, establecer SANE_CONFIG_DIR a "/tmp/config:" resultaría en la búsqueda de los directorios tmp/config, . y /etc/sane.d (en este orden).
SANE_DEBUG_MICROTEK
Si la biblioteca se compiló con soporte de depuración habilitado, esta variable de entorno controla el nivel de depuración para este backend. Un valor de 128 solicita una salida de depuración máximamente detallada; niveles más pequeños reducen la verbosidad.

ERRORES

Los errores/limitaciones conocidos son:

Brillo y contraste rotos.
El 600GS solo es en escala de grises y se bloqueará si seleccionas color. (Desafortunadamente, el 600GS y el 600ZS son indistinguibles por software).

es decir, no te quejes de estos; pero si el brillo y/o el contraste funcionan para ti, por favor házmelo saber.

Si tu escáner se bloquea, intenta establecer la opción norealcal o noprecal en el archivo de configuración (primero una, luego ambas), y mira si ayuda. (Si lo hace, repórtalo).

Envía informes de errores extensos e información sobre escáneres nuevos a mtek-bugs@mir.com. Todos los informes de errores y consultas sobre escáneres nuevos deben incluir un archivo de registro de errores. Puedes generar una salida stderr copiosa estableciendo la variable de entorno SANE_DEBUG_MICROTEK descrita anteriormente. Por ejemplo:

setenv SANE_DEBUG_MICROTEK 128

Comentarios más generales, sugerencias y consultas sobre frontends o SANE deben enviarse a sane-devel@alioth-lists.debian.net, la lista de correo de desarrolladores de SANE. Echa un vistazo a http://www.sane-project.org/mailing-lists.html sobre la suscripción a sane-devel.
