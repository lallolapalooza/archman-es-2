sacct(1) Comandos de Slurm sacct(1)

NOMBRE

sacct - muestra datos de contabilidad de todos los trabajos y pasos de trabajo en el archivo de registro de contabilidad de trabajos de Slurm o en la base de datos de Slurm

SINOPSIS

sacct [OPCIONES...]

DESCRIPCIÓN

La información de contabilidad de los trabajos invocados con Slurm se registra en el archivo de registro de contabilidad de trabajos o se guarda en la base de datos de Slurm, según se configure con el parámetro AccountingStorageType.

El comando sacct muestra datos de contabilidad de trabajos almacenados en el archivo de registro de contabilidad de trabajos o en la base de datos de Slurm en una variedad de formatos para su análisis. El comando sacct muestra por defecto información sobre trabajos, pasos de trabajo, estado y códigos de salida. Puede personalizar la salida utilizando la opción --format= para especificar los campos que se mostrarán.

Los registros de trabajos consisten en una entrada principal para el trabajo en su conjunto, así como entradas para los pasos de trabajo. La página Job Launch tiene una descripción más detallada de cada tipo de paso de trabajo. https://slurm.schedmd.com/job_launch.html#job_record

Para el usuario root, el comando sacct muestra datos de contabilidad de trabajos para todos los usuarios, aunque existen opciones para filtrar la salida y mostrar solo los trabajos de un usuario o grupo específico.

Para el usuario no root, el comando sacct limita por defecto la visualización de datos de contabilidad de trabajos a los trabajos que fueron lanzados con su propio identificador de usuario (UID). Los datos de otros usuarios se pueden mostrar con las opciones --allusers, --user o --uid.

Los campos de tiempo transcurrido se presentan como [días-]horas:minutos:segundos[.microsegundos]. Solo los campos 'CPU' tendrán microsegundos.

NOTA: Si se designa, la opción PrivateData del archivo slurmdbd.conf puede restringir aún más los datos de contabilidad visibles para los usuarios que no sean SlurmUser, root o un usuario con AdminLevel=Admin. Consulte la página del manual de slurmdbd.conf para obtener información adicional sobre cómo restringir el acceso a los datos de contabilidad.

NOTA: El contenido de la base de datos de Slurm se mantiene en minúsculas. Esto puede hacer que la salida de sacct difiera de la de otros comandos de Slurm.

NOTA: Gran parte de los datos informados por sacct han sido generados por las llamadas al sistema wait3() y getrusage(). Algunos sistemas recopilan y reportan información incompleta para estas llamadas; sacct reporta valores de 0 para estos datos faltantes. Consulte la página del manual de getrusage (3) de su sistema para obtener información sobre qué datos están realmente disponibles en su sistema.

OPCIONES

-A, --cuentas=<lista_cuentas>
Muestra trabajos cuando se proporciona una lista de cuentas separadas por comas como argumento.
--array
Expande arreglos de trabajos. Muestra todas las tareas de arreglos en líneas separadas en lugar de mostrar grupos de tareas de arreglos en líneas únicas.
-L, --todoslosclusters
Muestra trabajos ejecutados en todos los clústeres. Por defecto, solo se muestran los trabajos ejecutados en el clúster desde el que se llama a sacct.
-X, --asignaciones
Solo muestra estadísticas relevantes para la asignación del trabajo en sí, sin tener en cuenta los pasos.

NOTA: Sin incluir los pasos, las estadísticas de utilización para la(s) asignación(es) del trabajo se informarán como cero.

-a, --todoslosusuarios
Muestra trabajos de todos los usuarios cuando es ejecutado por el usuario root o si PrivateData no está configurado como jobs. De lo contrario, muestra los trabajos del usuario actual.
-x, --asociaciones=<lista_asociaciones>
Muestra las estadísticas solo para los trabajos ejecutados bajo los IDs de asociación especificados por el operando lista_asociaciones, que es una lista de IDs de asociación separados por comas. No se permiten espacios en lista_asociaciones. El valor predeterminado es todas las asociaciones.
-B, --script-batch
Esta opción imprimirá el script de lote del trabajo si el trabajo utilizó uno. Si el trabajo no tenía un script, se mostrará 'NONE'.
NOTA: Se requiere AccountingStoreFlags=job_script para esto.
NOTA: Se requiere solicitar trabajos específicos con '-j' para esto.
-b, --breve
Muestra una lista breve que consta de JobID, State y ExitCode.
-M, --clusters=<lista_clusters>
Muestra las estadísticas solo para los trabajos iniciados en los clústeres especificados por el operando lista_clusters, que es una lista de clústeres separados por comas. No se permiten espacios en lista_clusters. Un valor de 'all' consultará para ejecutarse en todos los clústeres. El valor predeterminado es el clúster actual en el que se está ejecutando el comando sacct o todos los clústeres en la federación cuando se ejecuta en un clúster federado. Esta opción establece implícitamente la opción --local.
-c, --finalización
Utiliza datos de finalización de trabajos en lugar de contabilidad de trabajos. El parámetro JobCompType en el archivo slurm.conf debe estar definido a una opción que no sea none. No admite información de clústeres federados (solo datos locales).
-C, --restricciones=<lista_restricciones>
Lista separada por comas para filtrar trabajos según las restricciones/características que solicitó el trabajo. Se tratarán múltiples opciones como 'y' y no como 'o', por lo que el trabajo debería tener todas las restricciones especificadas para ser devuelto, no una u otra.
--delimitador=<caracteres>
Caracteres ASCII utilizados para separar los campos al especificar las opciones -p o -P. El delimitador predeterminado es '|'. Esta opción se ignora si no se especifican las opciones -p o -P.
-D, --duplicados
Si los IDs de trabajo de Slurm se reinician, es probable que algunos números de trabajo aparezcan más de una vez en el archivo de registro de contabilidad, pero se refieran a trabajos diferentes. Dichos trabajos se pueden distinguir por la marca de tiempo de "envío" en los registros de datos.

Cuando se solicitan datos para trabajos específicos con la opción --jobs, sacct devuelve el trabajo más reciente con ese número. Este comportamiento se puede anular especificando --duplicates, en cuyo caso se devolverán todos los registros que coincidan con los criterios de selección.

NOTA: Los trabajos hermanos federados revocados se ocultan a menos que se especifique la opción --duplicates.

-E, --hora-final=<hora_final>
Selecciona trabajos en cualquier estado antes de la hora especificada. Si se indican estados con la opción -s, devuelve trabajos en ese estado antes de este período. Consulte la sección VENTANA DE TIEMPO PREDETERMINADA (abajo) para obtener detalles sobre cómo se determinan los valores predeterminados de --hora-inicio y --hora-final.

Los formatos de tiempo válidos son:
HH:MM[:SS][AM|PM]
MMDD[AA][-HH:MM[:SS]]
MM.DD[.AA][-HH:MM[:SS]]
MM/DD[/AA][-HH:MM[:SS]]
AAAA-MM-DD[THH:MM[:SS]]
hoy, medianoche, mediodía, once (11 AM), fika (3 PM), té (4 PM)
ahora[{+|-}cuenta[segundos(predeterminado)|minutos|horas|días|semanas]]

-s, --state=<lista_estados>
Selecciona trabajos basándose en su estado durante el período de tiempo dado. A menos que se especifique lo contrario, la hora de inicio y fin será la hora actual cuando se especifique la opción --state y solo se podrán mostrar los trabajos en ejecución. Se debe especificar una hora de inicio y/o fin para ver información sobre trabajos que no se están ejecutando. Consulte la sección CÓDIGOS DE ESTADO DEL TRABAJO (abajo) para obtener una lista de los designadores de estado. Se pueden especificar varios nombres de estado usando separadores de coma. Se puede usar la forma corta o larga del nombre del estado (por ejemplo, CA o CANCELLED) y el nombre no distingue entre mayúsculas y minúsculas (es decir, ca y CA funcionan).

NOTA: Para que se seleccione un trabajo en el estado PENDING, debe tener "EligibleTime" en el intervalo de tiempo solicitado o ser diferente de "Unknown". El "EligibleTime" se muestra con el comando "scontrol show job". Por ejemplo, los trabajos enviados con la opción "--hold" tendrán "EligibleTime=Unknown" ya que están pendientes indefinidamente.

NOTA: Al especificar estados y no se proporciona hora de inicio, la hora de inicio predeterminada es 'now'. Esto es solo cuando no se usa -j. Si se usa -j, la hora de inicio será 'Epoch' por predeterminado. En ambos casos, si no se proporciona hora de fin, será 'now' por defecto. Consulte la sección VENTANA DE TIEMPO PREDETERMINADA (abajo) para obtener detalles sobre cómo esta opción cambia los valores predeterminados para --starttime y --endtime.

Truncar tiempo. Por lo tanto, si un trabajo comenzó antes de --starttime, la hora de inicio se truncará a --starttime. Lo mismo para la hora de fin y --endtime.

Usar esta lista separada por comas de UID o nombres de usuario para seleccionar trabajos a mostrar. Por defecto, se utiliza el UID del usuario que ejecuta el comando.

--usage
Mostrar un resumen del uso del comando.

Utilice este comando para que Slurm utilice una llamada al sistema para obtener el UID del nombre de usuario. Esta opción puede ser útil en un entorno con múltiples clústeres y una base de datos donde los UID no son los mismos en todos los clústeres.
-v, --verbose
Principalmente con fines de depuración, informa sobre el estado de varias variables durante el procesamiento.
-V, --version
Imprimir versión.
-W, --wckeys=<lista_wckey>
Muestra las estadísticas solo para los trabajos iniciados en los wckeys especificados por el operando lista_wckey, que es una lista separada por comas de nombres de wckey. No se permiten espacios en la lista_wckey. El valor predeterminado es todos los wckeys.
--whole-hetjob[=yes|no]
Al consultar y filtrar trabajos heterogéneos con --jobs, Slurm recuperará por defecto información sobre todos los componentes del trabajo si se selecciona el id del trabajo heterogéneo (id del líder). Si se selecciona un id de componente de trabajo heterogéneo no líder, entonces solo se recupera ese componente por defecto. Este comportamiento se puede cambiar usando esta opción. Si se establece en 'yes' (o sin argumento), entonces se recuperará información sobre todos los componentes sin importar qué componente se seleccione en el filtro de trabajo. Si se establece en 'no', solo se recuperarán los componentes de trabajo heterogéneos seleccionados, incluso al seleccionar el líder.
--yaml, --yaml=lista, --yaml=<plugin_analizador_datos>
Volcar información del trabajo como YAML utilizando el plugin data_parser predeterminado o un data_parser explícito con parámetros. Los argumentos de ordenación y formato se ignorarán.

Campos de Contabilidad de Trabajos

Las descripciones de cada opción de campo se encuentran a continuación. Tenga en cuenta que los campos de contabilidad Ave*, Max* y Min* observan los valores de todas las tareas de cada paso de un trabajo y devuelven los valores promedio, máximo o mínimo de la tarea para ese paso de trabajo. Por ejemplo, para MaxRSS, el valor devuelto es el consumo máximo de memoria visto por una de las tareas del paso, y MaxRSSTask muestra qué tarea es.

ALL
Imprimir todos los campos enumerados a continuación.
Account
Cuenta bajo la cual se ejecutó el trabajo.
AdminComment
Una cadena de comentarios sobre un trabajo que debe ser establecida por un administrador, el UsuarioSlurm o root.
AllocCPUs
Recuento de CPUs asignados. Equivalente a NCPUS.
AllocNodes
Número de nodos asignados al trabajo/paso. 0 si el trabajo está pendiente.
AllocTres
Recursos rastreables. Estos son los recursos asignados al trabajo/paso después de que el trabajo comenzó a ejecutarse. Para trabajos pendientes, esto debería estar en blanco. Para más detalles, consulte AccountingStorageTRES en slurm.conf.

NOTA: Cuando un recurso genérico se configura con el indicador no_consume, la asignación se imprimirá con un cero.

AssocID
Referencia a la asociación de usuario, cuenta y clúster.
AveCPU
Tiempo promedio de CPU (sistema + usuario) de todas las tareas en el trabajo.
AveCPUFreq
Frecuencia de CPU ponderada promedio de todas las tareas en el trabajo, en kHz.
AveDiskRead
Número promedio de bytes leídos por todas las tareas en el trabajo.
AveDiskWrite
Número promedio de bytes escritos poy todas las tareas en el trabajo.
AvePages
Número promedio de fallos de página de todas las tareas en el trabajo.
AveRSS
Tamaño medio del conjunto residente de todas las tareas en el trabajo.
AveVMSize
Tamaño medio de memoria virtual de todas las tareas en el trabajo.
BlockID
El nombre del bloque a utilizar (utilizado con sistemas Blue Gene).
Cluster
Nombre del clúster.
Comment
La cadena de comentario del trabajo cuando el parámetro AccountingStoreFlags en el archivo slurm.conf contiene 'job_comment'. La cadena de comentario se puede modificar invocando sacctmgr modify job o el comando especializado sjobexitmod.
Constraints
Característica(s) solicitadas por el trabajo como restricción.
ConsumedEnergy
Energía total consumida por todas las tareas en un trabajo, en julios. El valor puede incluir un prefijo de unidad (K,M,G,T,P). Nota: Solo en el caso de una asignación de trabajo exclusiva, este valor refleja el consumo de energía real del trabajo.
ConsumedEnergyRaw
Energía total consumida por todas las tareas en un trabajo, en julios. Nota: Solo en el caso de una asignación de trabajo exclusiva, este valor refleja el consumo de energía real del trabajo.
Container
Ruta al paquete de contenedor OCI solicitado.
CPUTime
Tiempo utilizado (tiempo transcurrido * número de CPU) por un trabajo o paso en formato HH:MM:SS.
CPUTimeRAW
Tiempo utilizado (tiempo transcurrido * número de CPU) por un trabajo o paso en segundos de CPU.
DBIndex
Índice de base de datos único para las entradas en la tabla de trabajos.
DerivedExitCode
El código de salida más alto devuelto por los pasos del trabajo (invocaciones de srun). Después de los dos puntos se encuentra la señal que provocó la terminación del proceso si fue terminado por una señal. El DerivedExitCode se puede modificar invocando sacctmgr modify job o el comando especializado sjobexitmod.
Elapsed
El tiempo transcurrido del trabajo.

El formato de la salida de este campo es el siguiente:

[DD-[HH:]]MM:SS

definido por lo siguiente:
DD
días
hh
horas
mm
minutos
ss
segundos
ElapsedRaw

VENTANA DE TIEMPO PREDETERMINADA

Las opciones --starttime y --endtime definen la ventana de tiempo entre la cual sacct va a buscar. Por razones históricas y prácticas, sus valores predeterminados (es decir, la ventana de tiempo predeterminada) dependen de otras opciones: --jobs y --state.

Dependiendo de si se especifican --jobs y/o --state, los valores predeterminados de las opciones --starttime y --endtime son:

SIN especificar --jobs NI --state:
--starttime por defecto es Medianoche.
--endtime por defecto es Ahora.

CON --jobs Y SIN --state especificado:
--starttime por defecto es Época 0.
--endtime por defecto es Ahora.

SIN --jobs Y CON --state especificado:
--starttime por defecto es Ahora.
--endtime por defecto es --starttime y Ahora si no se especifica --starttime.

CON AMBAS opciones --jobs Y --state especificadas:
--starttime por defecto es Época 0.
--endtime por defecto es --starttime o Ahora si no se especifica --starttime.

NOTA: Con -v/--verbose se muestra un mensaje sobre la ventana de tiempo real en uso.

RENDIMIENTO

La ejecución de sacct envía una llamada de procedimiento remoto a slurmdbd. Si llegan suficientes llamadas de sacct u otros comandos cliente de Slurm que envían llamadas de procedimiento remoto al demonio slurmdbd al mismo tiempo, esto puede resultar en una degradación del rendimiento del demonio slurmdbd, lo que podría provocar una denegación de servicio.

No ejecute sacct u otros comandos cliente de Slurm que envíen llamadas de procedimiento remoto a slurmdbd desde bucles en scripts de shell u otros programas. Asegúrese de que los programas limiten las llamadas a sacct al mínimo necesario para la información que intenta recopilar.

Para otras fechas del año actual, imprime la "hora:minuto" precedida por "Mañana", "Ayer", el nombre del día de la semana siguiente (por ejemplo, "Lun", "Mar", etc.), de lo contrario la fecha (por ejemplo, "25 Abr"). Para otros años, devuelve una fecha mes y año sin hora (por ejemplo, "6 Jun 2012"). Todas las marcas de tiempo utilizan formato de 24 horas.

También se puede especificar un formato strftime() válido. Por ejemplo, un valor de "%a %T" informará el día de la semana y una marca de tiempo (por ejemplo, "Lun 12:34:56").

pretty Salida YAML en formato bonito para hacerlo más legible.

DESCRIPCIÓN

sacct es un comando de Slurm para recopilar y ver información sobre trabajos y trabajos por lotes. Los datos de trabajos se recopilan a medida que se completan los trabajos y se almacenan en un archivo de registro de contabilidad. sacct recupera esta información e imprime la información solicitada.

sacct leerá el archivo de registro de contabilidad especificado en la configuración de Slurm (consulte slurm.conf y el parámetro JobAcctGatherType en la página man de slurm.conf(5)). Por defecto, este es el archivo /var/log/slurm_accounting.log.

Por defecto, sacct imprimirá un informe de todos los trabajos que han comenzado o terminado durante el período de tiempo especificado por las opciones -S y -E. Si no se especifican estas opciones, sacct usará la hora actual para el inicio y el fin.

La salida de sacct se puede filtrar y formatear mediante las diversas opciones disponibles para el comando. La salida por defecto incluirá el ID del trabajo, el nombre del trabajo, el nombre de usuario, el estado, las tiempos de inicio y fin, y el tiempo total de CPU.

VENTANA DE TIEMPO PREDETERMINADA

Si no se especifican las opciones -S y -E, el período de tiempo predeterminado es la hora actual. El inicio se establecerá en la hora actual y el final se establecerá en la hora actual.

Si solo se especifica la opción -S, el final se establecerá en la hora actual. Si solo se especifica la opción -E, el inicio se establecerá en la hora actual.

RENDIMIENTO

El comando sacct puede ser intensivo en recursos si se consulta un gran número de trabajos. Se recomienda utilizar las opciones de filtrado apropiadas para limitar el alcance de la consulta.

El uso de la opción -T (truncar) puede mejorar el rendimiento al reducir la cantidad de datos que deben procesarse. Esto se debe a que los tiempos de inicio y fin se truncan a las marcas de tiempo especificadas, lo que puede reducir el número de trabajos que se incluyen en la consulta.

EJEMPLOS

Mostrar todos los trabajos completados en el último día:

sacct -S $(date --date="yesterday" +%Y-%m-%d) -o jobid,jobname,user,state,start,end

Mostrar trabajos que se ejecutaron en una partición específica:

sacct -p normal -o jobid,jobname,user,state,start,end

Mostrar trabajos que finalizaron con un código de salida específico:

sacct -e $(date +%Y-%m-%d-%H:%M:%S) -o jobid,jobname,user,state,exitcode --state=failed

Mostrar el tiempo de ejecución de los trabajos dentro de un período de tiempo específico, truncando los tiempos de inicio y fin:

Sin la opción -T (operación normal), la salida de sacct sería la siguiente.

# sacct -S2014-07-03-11:40 -E2014-07-03-12:00 -X -ojobid,start,end,state
    JobID                 Start                  End        State
--------- --------------------- -------------------- ------------
2         2014-07-03T11:33:16   2014-07-03T11:59:01   COMPLETED
3         2014-07-03T11:35:21   Unknown               RUNNING
4         2014-07-03T11:35:21   2014-07-03T11:45:21   COMPLETED
5         2014-07-03T11:41:01   Unknown               RUNNING

Al añadir la opción -T, los tiempos de inicio y fin del trabajo se truncan para reflejar solo el tiempo solicitado. Si un trabajo comenzó después de la hora de inicio solicitada o finalizó antes de la hora de finalización solicitada, esos tiempos no se alteran. La opción -T es útil cuando se determinan los tiempos de ejecución exactos durante cualquier período dado.

# sacct -T -S2014-07-03-11:40 -E2014-07-03-12:00 -X -ojobid,jobname,user,start,end,state
    JobID                 Start                  End        State
--------- --------------------- -------------------- ------------
2         2014-07-03T11:40:00   2014-07-03T11:59:01   COMPLETED
3         2014-07-03T11:40:00   2014-07-03T12:00:00   RUNNING
4         2014-07-03T11:40:00   2014-07-03T11:45:21   COMPLETED
5         2014-07-03T11:41:01   2014-07-03T12:00:00   RUNNING

NOTA: Si no se proporciona la opción -s (--state), sacct mostrará los trabajos elegibles durante el período de tiempo especificado; de lo contrario, devolverá los trabajos que estaban en el estado solicitado durante ese período de tiempo.

Este ejemplo demuestra las diferencias al ejecutar sacct con y sin el indicador --state para el mismo período de tiempo. Sin la opción --state, se muestran todos los trabajos elegibles en ese período de tiempo.

# sacct -S11:20:00 -E11:25:00 -X -ojobid,start,end,state
       JobID               Start                 End      State
------------ ------------------- ------------------- ----------
2955                    11:15:12            11:20:12  COMPLETED
2956                    11:20:13            11:25:13  COMPLETED

Con la opción --state=pending, solo se mostrará el trabajo 2956 porque tenía una dependencia del 2955 y todavía estaba PENDING desde las 11:20:00 hasta que comenzó a las 11:21:13. Tenga en cuenta que, aunque solicitamos trabajos PENDING, el Estado se muestra como COMPLETED porque ese es el Estado actual del trabajo.

# sacct --state=pending -S11:20:00 -E11:25:00 -X -ojobid,start,end,state
       JobID               Start                 End      State
------------ ------------------- ------------------- ----------
2956                    11:20:13            11:25:13  COMPLETED
