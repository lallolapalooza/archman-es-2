NOMBRE

sane-test - Backend SANE para probar interfaces gráficas

DESCRIPCIÓN

La biblioteca sane-test implementa un backend SANE (Scanner Access Now Easy) que permite probar la instalación de SANE y las interfaces gráficas de SANE. Proporciona acceso a un número (casi) ilimitado de dispositivos virtuales. No hay soporte para escáneres o cámaras reales. Sin embargo, el backend simula el escaneo y la configuración de opciones.

La idea no es solo encontrar errores en las interfaces gráficas, sino también mostrar todas las capacidades de SANE. Por lo tanto, sane-test implementa funciones y opciones que no se encuentran (o rara vez se encuentran) en otros backends.

El backend está comentado en /etc/sane.d/dll.conf, por lo que se debe eliminar el carácter de comentario o llamar explícitamente al backend. Por ejemplo, scanimage -d test o xscanimage test.

OPCIONES DE MODO DE ESCANEO

La opción mode selecciona el modo de escaneo (Gris o Color).

La opción depth determina el número de bits por muestra (1, 8 o 16). Tenga en cuenta que este valor se refiere a la muestra, no al píxel. Por lo tanto, depth=16 da como resultado 48 bits por píxel en modo color. Las combinaciones más comunes son mode=Gray, depth=1 para lineart, mode=Gray, depth=8 para escala de grises y mode=Color, depth=8 para modo color. La combinación de color y modo de 1 bit es bastante oscura (8 colores) pero permitida en el estándar SANE. Sin embargo, el significado de los bits no está definido. Actualmente se usa 1 = alta intensidad y 0 = baja intensidad.

Establecer la opción hand-scanner hace que el backend de prueba se comporte como un escáner manual. Los escáneres manuales no conocen la altura de la imagen a priori. En cambio, devuelven una altura de -1. Establecer esta opción permite probar si una interfaz gráfica puede manejar esto correctamente. Esta opción también habilita un ancho fijo de 11 cm.

Establecer la opción three-pass simula un escáner de tres pasadas. Los escáneres de color más antiguos necesitaban escanear la imagen una vez por color (rojo/verde/azul) para obtener la imagen completa. Por lo tanto, en este modo, se transmiten tres fotogramas individuales en modo color.

La opción three-pass-order proporciona soporte para cambiar el orden de los tres fotogramas (ver la opción three-pass arriba). Una interfaz gráfica debe admitir todos los órdenes.

La opción resolution establece la resolución de la imagen en puntos por pulgada.

La opción source se puede utilizar para simular un Alimentador Automático de Documentos (ADF). Después de 10 escaneos, el ADF estará "vacío".

OPCIONES ESPECIALES

La opción test-picture permite establecer la imagen que se devuelve a la interfaz gráfica. Mientras que "Blanco sólido" y "Negro sólido" son bastante obvios, las otras opciones necesitan más explicación. Los patrones de color se utilizan para determinar si todos los modos y sus colores son representados correctamente por la interfaz gráfica. La cuadrícula debería verse igual en todos los modos y resoluciones. Una tabla de todas las imágenes de prueba se puede encontrar en: http://www.meier-geinitz.de/sane/test-backend/test-pictures.html.

Si se establece la opción invert-endianness, se intercambian los bytes superior e inferior de los datos de la imagen en modos de 16 bits. Esta opción se puede utilizar para probar los modos de 16 bits de las interfaces gráficas, por ejemplo, si la interfaz gráfica utiliza la endianness correcta.

Si se establece la opción read-limit, se limita la cantidad máxima de datos transferidos con cada llamada a sane_read().

La opción read-limit-size establece el límite para la opción read-limit. Un límite bajo ralentiza el escaneo. Se puede utilizar para detectar errores en la interfaz gráfica que ocurren debido a suposiciones incorrectas sobre el tamaño del búfer o problemas de tiempo.

La opción read-delay habilita el retraso de datos a la interfaz gráfica.

La opción read-delay-duration selecciona el número de microsegundos que el backend espera después de cada transferencia de un búfer. Esta opción es útil para encontrar errores relacionados con el tiempo, especialmente si se usa a través de la red.

Si la opción read-return-value es diferente de "Default", el estado seleccionado será devuelto por cada llamada a sane_read(). Esto es útil para probar el manejo de los estados SANE por parte de la interfaz gráfica.

Si la opción ppl-loss es diferente de 0, determina el número de píxeles que se "pierden" al final de cada línea. Es decir, las líneas se rellenan con datos no utilizados.

La opción fuzzy-parameters selecciona que se devuelvan parámetros difusos (inexactos) mientras el escaneo no haya comenzado. Esta opción se puede utilizar para probar si la interfaz gráfica utiliza los parámetros que recibió antes del inicio del escaneo (lo cual no debería hacer).

La opción non-blocking determina si se debe utilizar E/S no bloqueante para sane_read() si es compatible con la interfaz gráfica.

Si se establece la opción select-fd, el backend ofrece un descriptor de archivo select para detectar si sane_read() devolverá datos.

Si se establece la opción enable-test-options, se habilita una lista bastante grande de opciones para probar los diversos tipos de opciones SANE.

La opción print-options se puede utilizar para imprimir una lista de todas las opciones en la salida de error estándar.

OPCIONES DE GEOMETRÍA

La opción tl-x determina la posición x de la esquina superior izquierda del área de escaneo.

La opción tl-y determina la posición y de la esquina superior izquierda del área de escaneo.

La opción br-x determina la posición x de la esquina inferior derecha del área de escaneo.

La opción br-y determina la posición y de la esquina inferior derecha del área de escaneo.

OPCIONES DE PRUEBA BOOLEANA

Hay 6 opciones de prueba booleanas en total. Cada opción está numerada. (3/6) significa: esta es la opción 3 de 6. El esquema de numeración está destinado a la detección más fácil de opciones que no se muestran en la interfaz gráfica (debido a la falta de soporte o errores).

La opción bool-soft-select-soft-detect (1/6) es una opción de prueba booleana que tiene capacidades de selección suave y detección suave (y avanzadas). Esa es solo una opción booleana normal.

La opción bool-hard-select-soft-detect (2/6) es una opción de prueba booleana que tiene capacidades de selección dura y detección suave (y avanzadas). Esto significa que la opción no puede ser establecida por la interfaz gráfica, sino por el usuario (por ejemplo, presionando un botón en el dispositivo).

La opción bool-hard-select (3/6) es una opción de prueba booleana que tiene capacidades de selección dura (y avanzadas). Esto significa que la opción no puede ser establecida por la interfaz gráfica, sino por el usuario (por ejemplo, presionando un botón en el dispositivo) y no puede ser leída por la interfaz gráfica.

La opción bool-soft-detect (4/6) es una opción de prueba booleana que tiene capacidades de detección suave (y avanzadas). Esto significa que la opción es de solo lectura.

La opción bool-soft-select-soft-detect-emulated (5/6) es una opción de prueba booleana que tiene capacidades de selección suave, detección suave y emulada (y avanzadas).

La opción bool-soft-select-soft-detect-auto (6/6) es una opción de prueba booleana que tiene capacidades de selección suave, detección suave y automática (y avanzadas). Esta opción puede ser establecida automáticamente por el backend.

OPCIONES DE PRUEBA ENTERAS

Hay 7 opciones de prueba enteras en total.

La opción int (1/7) es una opción de prueba entera sin unidad ni restricción establecida.

La opción int-constraint-range (2/7) es una opción de prueba entera con unidad de píxel y rango de restricción establecido. El mínimo es 4, el máximo 192 y la cuantía es 2.

La opción int-constraint-word-list (3/7) es una opción de prueba entera con unidad de bits y lista de palabras de restricción establecida.

La opción int-constraint-array (4/7) es una opción de prueba entera con unidad de mm y usando una matriz sin restricciones.

La opción int-constraint-array-constraint-range (5/7) es una opción de prueba entera con unidad de mm y usando una matriz con una restricción de rango. El mínimo es 4, el máximo 192 y la cuantía es 2.

La opción int-constraint-array-constraint-word-list (6/7) es una opción de prueba entera con unidad de porcentaje y usando una matriz o una lista de palabras de restricción.

La opción int-inexact (7/7) es una opción de prueba entera que incrementa el valor solicitado y devuelve el indicador SANE_INFO_INEXACT.

sane-test.5.en

NAME

sane-test - configuration file for the test backend

DESCRIPTION

The sane-test backend is a dummy backend that can be used to test SANE frontend functionalities. It supports a lot of options to simulate a real scanner. Most of the options are simple integers, floats, or strings. Some options may have constraints like range or word lists. This backend does not support any real scanner hardware.

This man page describes the configuration file for the sane-test backend.

SCAN MODE OPTIONS

These options are part of the standard SANE scan mode interface.

x-resolution
Sets the x-resolution. Valid range is 1 to 1000000. Default is 300.
y-resolution
Sets the y-resolution. Valid range is 1 to 1000000. Default is 300.
x-offset
Sets the x-offset. Default is 0.
y-offset
Sets the y-offset. Default is 0.
x-scan-size
Sets the x-scan-size. Default is 2150.
y-scan-size
Sets the y-scan-size. Default is 2970.
mode
Sets the scan mode. Valid values are: Lineart, Gray, Color. Default is Gray.
format
Sets the image format. Valid values are: 8-bit, 1-bit, 24-bit. Default is 8-bit.
color-mode
Sets the color mode. Valid values are: normal, reverse. Default is normal.
halting-speed
Sets the halting speed. Default is 1.0.
halting-distance
Sets the halting distance. Default is 0.
brightness
Sets the brightness. Valid range is -100 to 100. Default is 0.
contrast
Sets the contrast. Valid range is -100 to 100. Default is 0.
red-gamma
Sets the red gamma. Default is 1.0.
green-gamma
Sets the green gamma. Default is 1.0.
blue-gamma
Sets the blue gamma. Default is 1.0.
auto-white-balance
Enables or disables auto white balance. Default is disabled.
auto-sharpen
Enables or disables auto sharpen. Default is disabled.
auto-black-point-compensation
Enables or disables auto black point compensation. Default is disabled.
threshold
Sets the threshold for lineart mode. Valid range is 0 to 255. Default is 127.
color-balance
Sets the color balance. Default is 0.
preview
Enables or disables preview mode. Default is disabled.

SPECIAL OPTIONS

number-of-devices
Sets the number of devices to be simulated. Default is 1.
device-status
Sets the status of the device. Valid values are: online, offline, busy. Default is online.
error-code
Sets the error code to be returned. Default is 0.
error-text
Sets the error text to be returned. Default is empty.
scsi-command-error
Sets the SCSI command error code. Default is 0.
buffer-size
Sets the buffer size for the scanned data. Default is 65536.
force-preview-size
Forces the preview size. Default is 0.
disable-autofeature
Disables automatic feature detection. Default is disabled.
use-halting-speed
Enables or disables the halting speed option. Default is disabled.
force-negative-scan
Forces a negative scan. Default is disabled.
disable-auto-frame-detection
Disables automatic frame detection. Default is disabled.
force-empty-preview
Forces an empty preview. Default is disabled.
fake-warmup-time
Sets a fake warm-up time in seconds. Default is 0.
fake-lamp-off-time
Sets a fake lamp-off time in seconds. Default is 0.
auto-frame-layout
Sets the auto frame layout. Valid values are: none, A4, Letter. Default is none.

GEOMETRY OPTIONS

geometry-mode
Sets the geometry mode. Valid values are: none, full, center. Default is full.
geometry-x
Sets the x-coordinate of the geometry. Default is 0.
geometry-y
Sets the y-coordinate of the geometry. Default is 0.
geometry-width
Sets the width of the geometry. Default is 2150.
geometry-height
Sets the height of the geometry. Default is 2970.

Option bool (1/3) is a bool test option.

Option bool-constraint-word-list (2/3) is a bool test option with constraint word list.

Option bool-constraint-range (3/3) is a bool test option with constraint range. Min value is 0, max value is 1.

FILES

/etc/sane.d/test.conf
The backend configuration file (see also description of SANE_CONFIG_DIR below). The initial values of most of the basic SANE options can be configured in this file. A template containing all the default values is provided together with this backend. One of the more interesting values may be number_of_devices. It can be used to check the frontend's ability to show a long list of devices. The config values concerning resolution and geometry can be useful to test the handling of big file sizes.
/usr/lib/sane/libsane-test.a
The static library implementing this backend.
/usr/lib/sane/libsane-test.so
The shared library implementing this backend (present on systems that support dynamic loading).

ENVIRONMENT

SANE_CONFIG_DIR
This environment variable specifies the list of directories that may contain the configuration file. On *NIX systems, the directories are separated by a colon (`:'), under OS/2, they are separated by a semi-colon (`;'). If this variable is not set, the configuration file is searched in two default directories: first, the current working directory (".") and then in /etc/sane.d. If the value of the environment variable ends with the directory separator character, then the default directories are searched after the explicitly specified directories. For example, setting SANE_CONFIG_DIR to "/tmp/config:" would result in directories tmp/config, ., and /etc/sane.d being searched (in this order).
SANE_DEBUG_TEST
If the library was compiled with debug support enabled, this environment variable controls the debug level for this backend. Higher debug levels increase the verbosity of the output.

Example: export SANE_DEBUG_TEST=4
