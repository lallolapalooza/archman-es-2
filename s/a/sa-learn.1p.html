NOMBRE

sa-learn - entrena el clasificador bayesiano de SpamAssassin

SINOPSIS

sa-learn [opciones] [archivo]...

sa-learn [opciones] --dump [ all | data | magic ]

Opciones:

--ham                 Entrenar los siguientes mensajes como ham (no spam)
--spam                Entrenar los siguientes mensajes como spam
--forget              Olvida los siguientes mensajes
--use-ignores         Utilizar bayes_ignore_from y bayes_ignore_to
--sync                Sincronizar la base de datos y el diario si es necesario
--force-expire        Forzar una ejecución de sincronización y expiración de la base de datos
--dbpath <ruta>       Permite anular en la línea de comandos (en formato bayes_path)
                      dónde leer la Base de Datos Bayes de
--dump [all|data|magic]  Mostrar el contenido de la base de datos Bayes
                      Toma un argumento opcional para qué mostrar
 --regexp <re>        Solo para dump, especifica qué tokens mostrar
                      basado en una expresión regular.
-f archivo, --folders=archivo  Leer la lista de archivos/directorios desde el archivo
--dir                 Ignorado; compatibilidad histórica
--file                Ignorado; compatibilidad histórica
--mbox                Las fuentes de entrada están en formato mbox
--mbx                 Las fuentes de entrada están en formato mbx
--max-size <b>        Omitir mensajes de más de b bytes;
                      por defecto 500 KB, 0 implica sin límite
--showdots            Mostrar progreso usando puntos
--progress            Mostrar progreso usando barra de progreso
--no-sync             Omitir la sincronización de la base de datos y el diario
                      después de entrenar
-L, --local           Operar localmente, sin accesos a la red. Se
                      recomienda el uso de esta opción, ver documentación.
--import              Migrar datos de versiones anteriores/bases de datos no
                      basadas en DB_File
--clear               Limpiar la base de datos existente
--backup              Realizar una copia de seguridad, a STDOUT, de la base de datos existente
--restore <archivo>  Restaurar una base de datos desde el archivo
-u nombre de usuario, --username=nombre de usuario
                      Anular el nombre de usuario tomado del entorno

-C ruta, --configpath=ruta, --config-file=archivo
                      Ruta al directorio de configuración estándar

-D, --debug [área,...]  Imprimir mensajes de depuración
-V, --version         Imprimir versión

DESCRIPCIÓN

Dada una selección típica de tu correo entrante clasificado como spam o ham (no spam), esta herramienta alimentará cada correo a SpamAssassin, permitiéndole "aprender" qué señales son probables de significar spam, y cuáles son probables de significar ham.

Simplemente ejecuta este comando una vez por cada una de tus carpetas de correo, y éste "aprenderá" del correo que contengan.

Ten en cuenta que se admite el *globbing* al estilo csh en los nombres de las carpetas de correo; en otras palabras, listar un nombre de carpeta como "*" escaneará todas las carpetas que coincidan. Véase "Mail::SpamAssassin::ArchiveIterator" para más detalles.

Si estás usando buzones en un formato distinto a maildir deberías usar los parámetros --mbox o --mbx.

Los archivos comprimidos con gzip/bzip2/xz/lz4/lzip/lzo se descomprimen automáticamente. Véase "Mail::SpamAssassin::ArchiveIterator" para más detalles.

SpamAssassin recuerda qué mensajes de correo ya ha aprendido, y no los volverá a aprender, a menos que uses la opción --forget. Los mensajes aprendidos como spam tendrán el marcado de SpamAssassin eliminado, sobre la marcha.

Si cometes un error y escaneas un correo como ham cuando es spam, o viceversa, simplemente vuelve a ejecutar este comando con la clasificación correcta, y el error se corregirá. SpamAssassin "olvidará" automáticamente las indicaciones previas.

Los usuarios de "spamd" que deseen realizar entrenamientos de forma remota, a través de una red, deberían investigar el modificador "spamc -L".

OPCIONES

--ham
Entrena los mensajes de entrada en los archivos siguientes a la opción como ham. Si previamente has entrenado alguno de los mensajes como spam, SpamAssassin lo olvidará primero y luego lo reentrenará como ham. Alternativamente, si previamente lo has entrenado como ham, lo omitirá esta vez. Si los mensajes ya han sido filtrados a través de SpamAssassin, el aprendiz ignorará cualquier modificación que SpamAssassin pueda haber realizado.
--spam
Entrena los mensajes de entrada en los archivos siguientes a la opción como spam. Si previamente has entrenado alguno de los mensajes como ham, SpamAssassin lo olvidará primero y luego lo reentrenará como spam. Alternativamente, si previamente lo has entrenado como spam, lo omitirá esta vez. Si los mensajes ya han sido filtrados a través de SpamAssassin, el aprendiz ignorará cualquier modificación que SpamAssassin pueda haber realizado.
--folders=nombre de archivo, -f nombre de archivo
sa-learn leerá la lista de carpetas del archivo especificado, una carpeta por línea en el archivo. Si la carpeta está precedida por "ham:tipo:" o "spam:tipo:", sa-learn entrenará esa carpeta apropiadamente, de lo contrario se asumirá que las carpetas son del tipo especificado por --ham o --spam.

"tipo" arriba es opcional, pero es el mismo que el estándar para ArchiveIterator: mbox, mbx, dir, file, o detect (el valor por defecto si no se especifica).

--mbox
sa-learn leerá los archivos que contienen los correos electrónicos a entrenar, y los procesará en formato mbox (uno o más correos por archivo).
--mbx
sa-learn leerá los archivos que contienen los correos electrónicos a entrenar, y los procesará en formato mbx (uno o más correos por archivo).
--use-ignores
No entrenar el mensaje si una dirección de remitente coincide con el elemento del archivo de configuración "bayes_ignore_from" o una dirección de destinatario coincide con "bayes_ignore_to". La opción podría usarse al entrenar desde un archivo grande de mensajes del cual no se han eliminado los mensajes de spam con características de ham o los mensajes de ham con características de spam.
--sync
Sincronizar el diario y las bases de datos. Tras sincronizar exitosamente la base de datos con las entradas del diario, el archivo del diario se elimina.
--force-expire
Forza un intento de expiración, independientemente de si puede ser necesario o no. Nota: Esto no significa que ningún token expirará realmente. Por favor, consulta la sección de EXPIRACIÓN más abajo.

Nota: "--force-expire" también provoca que los datos del diario se sincronicen en las bases de datos Bayes.

--forget
Olvidar los mensajes de entrada en los archivos siguientes a la opción como previamente aprendidos.
--dbpath
Permite anular en la línea de comandos la opción de configuración bayes_path.
--dump opción
Mostrar el contenido de la base de datos Bayes. Sin una opción o con la opción all, se mostrarán todos los tokens mágicos y de datos. magic solo mostrará los tokens mágicos, y data solo mostrará los tokens de datos.

También puede usar la opción --regexp RE para especificar qué tokens mostrar basándose en una expresión regular.

--clear
Limpiar una base de datos Bayes existente eliminando todos los rastros de la base de datos.

ADVERTENCIA: Esto es destructivo y debe usarse con cuidado.

--backup
Realiza un volcado de la base de datos Bayes en formato legible por máquina/humano.

El volcado incluirá datos de tokens y vistos. Es adecuado para ser introducido de nuevo en el comando --restore.

--restore=nombre de archivo
Realiza una restauración de la base de datos Bayes d

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

definido por nombre_archivo.

ADVERTENCIA: Esta es una operación destructiva, los datos de Bayes anteriores se borrarán.

-h, --help
Imprime el mensaje de ayuda y sale.
-u nombre_usuario, --username=nombre_usuario
Si se especifica, este nombre de usuario anulará el nombre de usuario tomado del entorno de ejecución. Puede usar esta opción para especificar usuarios en una configuración de usuarios virtuales cuando se utiliza SQL como backend de Bayes.

NOTA: Esta opción no cambiará al nombre_usuario dado, solo intentará actuar en nombre de ese usuario. Debido a esto, necesitará tener los permisos adecuados para poder cambiar archivos propiedad de nombre_usuario. En el caso de SQL, esto generalmente no es un problema.

-C ruta, --configpath=ruta, --config-file=ruta
Utiliza la ruta especificada para localizar los archivos de configuración distribuidos. Ignora los directorios predeterminados (generalmente "/usr/share/spamassassin" o similar).
--siteconfigpath=ruta
Utiliza la ruta especificada para localizar archivos de configuración específicos del sitio. Ignora los directorios predeterminados (generalmente "/etc/mail/spamassassin" o similar).
--cf='línea de configuración'
Añade líneas adicionales de configuración directamente desde la línea de comandos, analizadas después de que se lean los archivos de configuración. Se pueden usar múltiples argumentos de --cf, y cada uno se considerará una línea de configuración separada.
-p preferencias, --prefspath=preferencias, --prefs-file=preferencias
Lee las preferencias de puntuación del usuario desde preferencias (generalmente "$HOME/.spamassassin/user_prefs").
--progress
Imprime una barra de progreso (a STDERR) que muestra el progreso actual. En el caso en que no se encuentre una terminal válida, esta opción se comportará de manera muy similar a la opción --showdots.
-D [área,...], --debug [área,...]
Produce salida de depuración. Si no se enumeran áreas, se imprime toda la información de depuración. La salida de diagnóstico también se puede habilitar para cada área individualmente; área es el área del código a instrumentar. Por ejemplo, para producir salida de diagnóstico en bayes, learn y dns, use: 
spamassassin -D bayes,learn,dns

Use una cadena vacía (-D '') para indicar ninguna área cuando el siguiente elemento en la línea de comandos es una ruta, para evitar que la ruta se analice como un área.

Para obtener más información sobre las áreas (también conocidas como canales) disponibles, consulte la documentación en:

C<https://wiki.apache.org/spamassassin/DebugChannels>

Los mensajes informativos de mayor prioridad que son adecuados para el registro en circunstancias normales están disponibles con un área de "info".

--no-sync
Omite el lento paso de sincronización que normalmente tiene lugar después de cambiar las entradas de la base de datos. Si planea aprender de muchas carpetas en un lote, o aprender muchos mensajes individuales uno por uno, es más rápido usar este interruptor y ejecutar "sa-learn --sync" una vez que todas las carpetas hayan sido escaneadas.

Aclaración: El estado de --no-sync anula la opción de configuración bayes_learn_to_journal. Si no se especifica, sa-learn aprenderá directamente en la base de datos. Si se especifica, sa-learn aprenderá en el archivo de registro.

Nota: --sync y --no-sync se pueden especificar en la misma línea de comandos, lo cual es un poco confuso. En este caso, la opción --no-sync se ignora ya que no hay operación de aprendizaje.

-L, --local
No realice ningún acceso a la red al aprender detalles sobre los mensajes de correo. Esto debería usarse normalmente, ya que realmente no hay nada que Bayes pueda aprender de los resultados de la búsqueda en la red. Los complementos oficiales de SpamAssassin actualmente no realizan búsquedas en la red al aprender, pero es posible que los de terceros sí lo hagan.
--import
Si anteriormente utilizó el aprendiz bayesiano de SpamAssassin sin el módulo "DB_File" instalado, habrá creado archivos en otros formatos, como "GDBM_File", "NDBM_File" o "SDBM_File". Este interruptor le permite migrar esos datos antiguos al formato "DB_File". Sobrescribirá cualquier dato actualmente en "DB_File".

También se puede usar con la opción --dbpath ruta para especificar la ubicación de los archivos de Bayes a utilizar.

MIGRACIÓN

Ahora hay varios módulos de almacenamiento backend disponibles para almacenar los datos bayesianos de los usuarios. Como tales, es posible que desee migrar de un backend a otro. Aquí hay un procedimiento simple para migrar de un backend a otro.

Tenga en cuenta que si tiene bases de datos de usuarios individuales, deberá realizar un procedimiento similar para cada una de ellas.

sa-learn --sync
Esto sincronizará cualquier entrada de registro pendiente.
sa-learn --backup > backup.txt
Esto guardará todos sus datos de Bayes en un archivo de texto plano.
sa-learn --clear
Esto es opcional, pero bueno hacerlo para borrar la base de datos antigua.
¡Repetir!
En este punto, si tiene varias bases de datos, debe realizar el procedimiento anterior para cada una de ellas. (es decir, la base de datos de cada usuario debe ser respaldada antes de continuar).
Cambiar de backend
Una vez que haya respaldado todas las bases de datos, puede actualizar su configuración para el nuevo backend de base de datos. Esto implicará al menos la opción de configuración bayes_store_module y puede implicar algunas opciones de configuración adicionales dependiendo de lo que requiera el módulo. (Por ejemplo, puede que necesite configurar una base de datos SQL).
sa-learn --restore backup.txt
De nuevo, debe hacer esto para cada base de datos.

Si está migrando a SQL, puede utilizar la opción -u nombre_usuario en sa-learn para poblar la base de datos de cada usuario. De lo contrario, debe ejecutar sa-learn como el usuario cuya base de datos está restaurando.

INTRODUCCIÓN AL FILTRADO BAYESIANO

(¡Gracias a Michael Bell por esta sección!)

Para una descripción más extensa de cómo funciona, vaya a http://www.paulgraham.com/ y vea "A Plan for Spam". Es razonablemente legible, incluso si las estadísticas me provocan urticaria.

La versión corta y semi-inexacta: Dado el entrenamiento, un motor de heurística de spam puede tomar las palabras más "spammy" y "hammy" y aplicar análisis probabilístico. Además, una vez que se tiene una base para el análisis, el motor puede continuar aprendiendo iterativamente aplicando tanto las reglas no bayesianas como las bayesianas juntas para crear una "inteligencia" en evolución.

SpamAssassin 2.50 y posteriores soporta análisis bayesiano de spam, en la forma de las reglas BAYES. Esta es una nueva característica, bastante potente, y está deshabilitada hasta que se hayan aprendido suficientes mensajes.

Los pros del análisis bayesiano de spam:

Puede reducir enormemente los falsos positivos y falsos negativos.
Aprende de su correo, por lo que está adaptado a su flujo de correo electrónico único.
Una vez que comienza a aprender, puede continuar aprendiendo de SpamAssassin y mejorar con el tiempo.

Y los contras:

Se requiere un número decente de mensajes antes de que los resultados sean útiles para la determinación de ham/spam.
Es difícil explicar por qué un mensaje es o no se marca como spam.
es decir: una regla sencilla, que coincide, por ejemplo, con "VIAGRA" es fácil de entender. Si genera un falso positivo o un falso negativo, es bastante fácil entender por qué.

Con el análisis bayesiano, todo son probabilidades: "porque el pasado dice que es probable ya que esto cae dentro de una distribución probabilística común al spam pasado en sus sistemas". ¡Dígaselo a sus usuarios! Dígaselo al cliente cuando pregunte "¿qué puedo hacer para cambiar esto?". (Por cierto, la respuesta en este caso es "usar welcomelisting".)

Ocupará espacio en disco y memoria.
Las bases de datos que mantiene requieren bastantes recursos para almacenar y usar.

EMPEZANDO

¿Todavía interesado? Bien, aquí están las pautas para que esto funcione.

Primero, una visión general:

Crea una muestra significativa tanto de ham como de spam.
Sugiero varios miles de cada uno, colocados en directorios o buzones de SPAM y HAM. Sí, DEBE clasificar esto manualmente, de lo contrario los resultados no serán mucho mejores que los de SpamAssassin por sí solo. Verifique la espameidad/hamicidad de CADA mensaje. Se le insta a evitar usar un corpus (muestra) disponible públicamente: esto debe tomarse de SU servidor de correo, si va a ser estadísticamente útil. De lo contrario, los resultados pueden estar bastante sesgados.
Usa esta herramienta para enseñar SpamAssassin sobre estas muestras, así:
sa-learn --spam /ruta/a/carpeta/de/spam
sa-learn --ham /ruta/a/carpeta/de/ham
sa-learn --ham ruta_ham1 ruta_ham2 --spam ruta_spam1 ruta_spam2
...

Deja que SpamAssassin proceda, aprendiendo cosas. Cuando encuentre ham y spam, agregará los "tokens interesantes" a la base de datos.

Si necesita que SpamAssassin olvide mensajes específicos,
use the --forget option.
Esto se puede aplicar tanto a ham (correo legítimo) como a spam que ha pasado por los procesos de sa-learn. En realidad, es un poco drástico, ya que reduce el peso de los tokens específicos en ese mensaje (solo si ese mensaje ha sido procesado antes).
El aprendizaje de mensajes individuales usa un comando como este:
sa-learn --ham --no-sync mailmessage

Esto es útil para vincularlo a una tecla en su agente de usuario de correo. Es muy rápido, ya que todo el trabajo que consume tiempo se pospone hasta que ejecute la opción "--sync".

El autoaprendizaje está habilitado por defecto
Si no tiene un corpus de correo guardado para aprender, puede dejar que SpamAssassin aprenda automáticamente el correo que recibe. Si está aprendiendo automáticamente desde cero, la cantidad de correo que reciba determinará cuánto tiempo hasta que las reglas BAYES_* se activen.

ENTRENAMIENTO EFECTIVO

Los filtros de aprendizaje requieren entrenamiento para ser efectivos. Si no los entrena, no funcionarán. Además, necesita entrenarlos con mensajes nuevos regularmente para mantenerlos actualizados, o sus datos se volverán obsoletos e afectarán la precisión.

Debe entrenar tanto con correos de spam como de ham. Un solo tipo de correo no tendrá ningún efecto.

Tenga en cuenta que si sus carpetas de correo contienen cosas como spam reenviado, discusiones sobre reglas de detección de spam, etc., esto causará problemas. Debería evitar escanear esos mensajes si es posible. (Una forma fácil de hacerlo es moverlos a un lado, a una carpeta que no se escanee).

Si los mensajes de los que está aprendiendo ya han sido filtrados por SpamAssassin, el aprendiz compensará esto. En efecto, aprende cómo se vería cada mensaje si hubiera ejecutado "spamassassin -d" sobre él de antemano.

Otra cosa a tener en cuenta es que, por lo general, debería intentar entrenar con al menos 1000 mensajes de spam y 1000 mensajes de ham, si es posible. Más es mejor, pero cualquier cosa por encima de unos 5000 mensajes no mejora significativamente la precisión en nuestras pruebas.

Tenga cuidado de entrenar desde la misma fuente; por ejemplo, si entrena con spam antiguo, pero con correo ham nuevo, el clasificador pensará que un correo con una marca de tiempo antigua es probable que sea spam.

También vale la pena señalar que entrenar con una cantidad muy pequeña de ham producirá resultados atroces. Debe intentar entrenar con al menos la misma cantidad (¡o más si es posible!) de datos de ham que de spam.

De forma continua, es mejor seguir entrenando el filtro para asegurarse de que tiene datos frescos con los que trabajar. Hay varias maneras de hacer esto:

1. Aprendizaje supervisado
Esto significa mantener una copia de todo o la mayoría de su correo, separado en pilas de spam y ham, y reentrenar periódicamente usando esas pilas. Produce los mejores resultados, pero requiere más trabajo de su parte, el usuario.

(Una forma fácil de hacerlo, por cierto, es crear una nueva carpeta para mensajes 'eliminados', y en lugar de eliminarlos de otras carpetas, simplemente muévalos allí. Luego mantenga todo el spam en una carpeta separada y nunca lo elimine. Mientras recuerde mover los correos mal clasificados al conjunto de carpetas correcto, es lo suficientemente fácil de mantener actualizado.)

2. Aprendizaje no supervisado desde clasificación bayesiana
Otra forma de entrenar es encadenar los resultados del clasificador bayesiano de nuevo en el entrenamiento, para que refuerce sus propias decisiones. Esto solo es seguro si luego lo reentrena basándose en cualquier error que descubra.

SpamAssassin no admite este método, debido a resultados experimentales que indican fuertemente que no funciona bien, y dado que Bayes es solo una parte de la puntuación resultante presentada al usuario (mientras que Bayes puede haber tomado la decisión incorrecta sobre un correo, puede haber sido anulado por otro sistema).

3. Aprendizaje no supervisado desde reglas de SpamAssassin
También llamado 'autoaprendizaje' en SpamAssassin. Basado en el análisis estadístico de las tasas de éxito de SpamAssassin, podemos entrenar automáticamente la base de datos bayesiana con un cierto grado de confianza de que nuestros datos de entrenamiento son precisos.

Debe complementarse con algo de entrenamiento supervisado adicional, si es posible.

Este es el predeterminado, pero se puede desactivar estableciendo el parámetro de configuración de SpamAssassin "bayes_auto_learn" a 0.

4. Entrenamiento basado en errores
Esto significa entrenar con un número pequeño de correos, y luego entrenar solo con mensajes que SpamAssassin clasifica incorrectamente. Esto funciona, pero lleva más tiempo obtener los resultados correctos que una sesión de entrenamiento completa.

ARCHIVOS

sa-learn y las otras partes del aprendiz bayesiano de SpamAssassin, usan un conjunto de archivos de base de datos persistentes para almacenar los tokens aprendidos, como se indica a continuación.

bayes_toks
La base de datos de tokens, que contiene los tokens aprendidos, su recuento de ocurrencias en ham y spam, y la marca de tiempo cuando el token se vio por última vez en un mensaje.

Esta base de datos también contiene algunos tokens 'mágicos', como los siguientes: el número de versión de la base de datos, el número de mensajes ham y spam aprendidos, el número de tokens en la base de datos, y marcas de tiempo de: la última sincronización del diario, la última ejecución de expiración, el último recuento de reducción de tokens de expiración, el último delta de marca de tiempo de expiración, la marca de tiempo del token más antiguo en la base de datos, y la marca de tiempo del token más nuevo en la base de datos.

Este es un archivo de base de datos, que utiliza "DB_File". El 'número de versión de la base de datos' es 0 para bases de datos de 2.5x, 1 para bases de datos de ciertas versiones de desarrollo 2.6x, 2 para 2.6x, y 3 para versiones 3.0 y posteriores.

bayes_seen
Un mapa de Message-Id y algunos datos de las cabeceras y el cuerpo a cómo se aprendió ese mensaje. Esto se usa para que SpamAssassin pueda evitar reaprender un mensaje que ya ha visto, y para que pueda revertir el entrenamiento si más tarde decide que ese mensaje se aprendió incorrectamente.

Este es un archivo de base de datos, que utiliza "DB_File".

bayes_journal
Mientras SpamAssassin escanea correos, necesita rastrear qué tokens utiliza en sus cálculos. Para evitar la contención de que cada proceso de SpamAssassin intente obtener acceso de escritura a la DB de Bayes, las marcas de tiempo de los tokens se escriben en un archivo de 'diario' que más tarde (ya sea automáticamente o mediante "sa-learn --sync") se utilizará para sincronizar la DB de Bayes.

Además, mediante el uso de "bayes_learn_to_journal", o al usar la opción "--no-sync" con sa-learn, los datos de aprendizaje reales se colocarán en el diario para su posterior sincronización. Esto suele ser útil para sitios con mucho tráfico para evitar la misma contención mencionada anteriormente.

EXPIRACIÓN

Dado que SpamAssassin puede aprender mensajes automáticamente, los archivos de la base de datos de Bayes podrían aumentar perpetuamente hasta llenar su disco. Para controlar esto, SpamAssassin realiza la sincronización del diario y la expiración de bayes periódicamente cuando se cumplen ciertos criterios (enumerados a continuación).

SpamAssassin puede sincronizar el diario y expirar los tokens de la DB ya sea manualmente o de forma oportunista. Una sincronización del diario está pendiente si se pasa --sync a sa-learn (manual), o si lo siguiente es cierto (oportunista):

- bayes_journal_max_size no es igual a 0 (significa no sincronizar)
- existe el archivo del diario

y además:

- el archivo del diario tiene un tamaño mayor que bayes_journal_max_size

o

- se ha realizado previamente una sincronización del diario, y ha pasado al menos 1 día desde esa sincronización

La expiración está pendiente si se pasa --force-expire a sa-learn (manual), o si se cumplen todas las siguientes condiciones (oportunista):

- la última expiración se intentó hace al menos 12 horas
- bayes_auto_expire no es igual a 0
- el número de tokens en la DB es > 100.000
- el número de tokens en la DB es > bayes_expiry_max_db_size
- hay una diferencia de al menos 12 horas entre los atimes del token más antiguo y el más nuevo

LÓGICA DE EXPIRACIÓN

Si el método manual u oportunista inicia una ejecución de expiración, esta es la lógica que se utiliza:

- calcular cuántos tokens mantener. se toma el mayor entre bayes_expiry_max_db_size * 75% o 100.000 tokens. por lo tanto, la reducción objetivo es el número de tokens - el número de tokens a mantener.
- si el número de reducción es < 1000 tokens, abortar (no vale la pena el esfuerzo).
- si ya se ha realizado una expiración antes, estimar el nuevo delta de atime basándose en el delta de atime anterior. (nuevo_delta_atime = delta_atime_anterior * recuento_reducción_anterior / objetivo)
- si no se ha realizado ninguna expiración antes, o la última expiración parece "extraña", realizar un pase de estimación. La definición de "extraño" es:
- la última expiración hace más de 30 días
- el delta de atime anterior fue < 12 horas

DESCRIPTION

The sa-learn command is used to train SpamAssassin's Bayesian text classifier. It is used to mark messages as spam or not-spam. By default, it learns from files specified on the command line, assuming they are not-spam. It can also be used to forget messages, sync the database, backup the database, restore the database, or perform other maintenance tasks.

The Bayesian classifier works by keeping track of the probability that certain tokens (words or phrases) appear in spam versus non-spam (ham) messages. By learning from a set of messages you mark as spam, and a set you mark as not-spam, the classifier can be used to automatically classify future messages.

It is important to use a diverse and representative set of messages for training. Training on only a few messages, or on messages that are not typical of the spam and non-spam you receive, will result in poor performance.

The sa-learn command can process the content of files or directories specified on the command line. If a directory is specified, sa-learn will recursively process all files within that directory.

The options --spam, --ham, and --forget can be used to specify the type of learning to perform. If none of these options are specified, sa-learn defaults to learning messages as ham.

The Bayesian classifier is stored in a database. The location of this database can be specified with the -d dbpath option. If not specified, it defaults to ~/.spamassassin/bayes_toks.

The database can be updated atomically using a journal file. The journal file is created in the same directory as the main database. This allows SpamAssassin to recover from crashes during learning or expiry.

The -s state option can be used to specify the desired state of the classifier. The possible states are:

normal
Learn and forget messages as usual.
test
Learn messages but do not update the database. This is useful for testing different training sets without affecting the production database.
forget
Forget messages without updating the database. This is useful for testing forgetting operations.

The -R reportdir option can be used to specify a directory where reports will be generated. These reports can include statistics on the database size, token counts, and other information.

The -t token option can be used to specify a specific token to learn or forget. This is useful for advanced users who want to manually manipulate the classifier.

The -U user option can be used to specify the user under which to run sa-learn. This is useful when running sa-learn from a script or cron job.

The -B backend option can be used to specify the database backend to use. The default is DB_File. Other possible backends include SQLite, MySQL, and PostgreSQL.

The -m dbmapping option can be used to specify a mapping of database names to backend connection strings. This is useful when using multiple database backends.

The -p pref option can be used to specify a preferences file to load. This file can contain settings that affect the behavior of sa-learn, such as the database location and the learning thresholds.

The -C option forces sa-learn to use the default configuration file (/etc/mail/spamassassin/local.cf) instead of trying to find a user-specific configuration file.

The -H option tells sa-learn to use the user's home directory as the base for finding configuration files and the database.

The -L option tells sa-learn to use a temporary database file instead of the main database. This is useful for testing purposes.

The -f logfile option specifies a file to which all output should be logged. This is useful for capturing the output of sa-learn for later analysis.

The -r option enables recursive learning. This means that if a directory is specified on the command line, sa-learn will learn from all files within that directory and its subdirectories.

The -E option enables expiry. This means that sa-learn will attempt to expire old tokens from the database after learning. This is a way to keep the database size under control.

The -D[debugmask] option enables debugging output. The optional debugmask can be used to control the level of debugging output. Higher values mean more output.

INTRODUCTION TO BAYESIAN FILTERING

Bayesian filtering is a probabilistic approach to spam filtering. It works by calculating the probability that a message is spam based on the words it contains. The more spam-like words a message contains, the higher the probability that it is spam.

The Bayesian filter in SpamAssassin works by maintaining a database of token probabilities. Tokens are words or phrases that appear in messages. For each token, the database stores the probability that the token appears in a spam message and the probability that it appears in a non-spam (ham) message.

When a message is classified, the probabilities of its tokens are used to calculate the overall probability that the message is spam. This probability is then compared to a threshold to determine whether the message should be flagged as spam.

The accuracy of the Bayesian filter depends on the quality and quantity of the training data. The more messages you train the filter with, and the more representative those messages are of the spam and ham you receive, the better the filter will perform.

GETTING STARTED

To get started with Bayesian filtering, you need to train the classifier with some examples of spam and ham. You can do this by creating two directories, one for spam messages and one for ham messages, and then running sa-learn on each directory.

For example, to train the classifier with messages in the ~/mail/spam directory as spam, and messages in the ~/mail/ham directory as ham, you would run:

sa-learn --spam -f ~/mail/spam/*

sa-learn --ham -f ~/mail/ham/*

Replace ~/mail/spam and ~/mail/ham with the actual paths to your spam and ham directories.

It is recommended to start with at least 200 messages of each type. More training data will generally lead to better results.

EFFECTIVE TRAINING

To achieve the best results from Bayesian filtering, follow these guidelines:

  • Use representative data: Train the filter with messages that are typical of the spam and ham you actually receive. Avoid training on sample spam or ham collections that may not reflect your own email flow.

  • Use a sufficient quantity of data: Start with at least 200 messages of each type (spam and ham). The more data you provide, the more accurate the filter will become. Aim for thousands of messages of each type for optimal performance.

  • Train regularly: Spammers constantly change their tactics, so it's important to keep the filter updated. Periodically retrain the filter with new examples of spam and ham.

  • Be careful with forgetting: Use the --forget option only when necessary. Forgetting too many messages, or forgetting messages that were correctly classified, can degrade the filter's performance.

  • Check for false positives/negatives: Regularly review messages that are flagged as spam (false positives) and messages that are allowed through as ham (false negatives). If you find incorrectly classified messages, use sa-learn to retrain the filter with the correct classification.

  • Avoid training on emails with unusual formatting or languages: If you receive emails in a language or format that is rare for you, it might be best not to use them for training, as they may not be representative of your typical email.

EXPIRATION

The Bayes database can grow quite large over time, consuming disk space and potentially slowing down performance. To manage the size of the database, SpamAssassin implements an automatic expiration mechanism.

When sa-learn is run with the -E option, or when spamass-milter or spamd processes messages, it may trigger an expiration run if certain conditions are met.

The goal of expiration is to remove old, less useful tokens from the database, keeping the total number of tokens within a configured limit. This helps maintain a balance between having enough training data and keeping the database size manageable.

The expiration process works by selecting an "atime delta", which is a time duration. Tokens older than this delta are candidates for removal. The process iteratively tries different deltas, starting from a large one, to determine the optimal delta that will remove a significant number of tokens without exceeding the configured maximum database size or the desired token count reduction.

EXPIRY CALCULATIONS

The following conditions are checked to determine if an expiration run should occur and how many tokens to remove:

- the delta between the newest token and the oldest token is < 12 hrs
- the delta between the newest token and the oldest token is < 24 hrs
- the delta between the newest token and the oldest token is < 48 hrs
- the delta between the newest token and the oldest token is < 96 hrs
- the delta between the newest token and the oldest token is < 192 hrs
- the difference between the last reduction count and the goal reduction count is > 50%

ESTIMATION PASS LOGIC

Go through each of the DB's tokens. Starting at 12hrs, calculate whether or not the token would be expired (based on the difference between the token's atime and the db's newest token atime) and keep the count. Work out from 12hrs exponentially by powers of 2. ie: 12hrs * 1, 12hrs * 2, 12hrs * 4, 12hrs * 8, and so on, up to 12hrs * 512 (6144hrs, or 256 days).

The larger the delta, the smaller the number of tokens that will be expired. Conversely, the number of tokens goes up as the delta gets smaller. So starting at the largest atime delta, figure out which delta will expire the most tokens without going above the goal expiration count. Use this to choose the atime delta to use, unless one of the following occurs:

- the largest atime (smallest reduction count) would expire too many tokens. this means the learned tokens are mostly old and there needs to be new tokens learned before an expire can occur.
- all of the atime choices result in 0 tokens being removed. this means the tokens are all newer than 12 hours and there needs to be new tokens learned before an expire can occur.
- the number of tokens that would be removed is < 1000. the benefit isn't worth the effort. more tokens need to be learned.

If the expire run gets past this point, it will continue to the end. A new DB is created since the majority of DB libraries don't shrink the DB file when tokens are removed. So we do the "create new, migrate old to new, remove old, rename new" shuffle.

EXPIRY RELATED CONFIGURATION SETTINGS

"bayes_auto_expire" is used to specify whether or not SpamAssassin ought to opportunistically attempt to expire the Bayes database. The default is 1 (yes).
"bayes_expiry_max_db_size" specifies both the auto-expire token count point, as well as the resulting number of tokens after expiry as described above. The default value is 150,000, which is roughly equivalent to a 6Mb database file if you're using DB_File.
"bayes_journal_max_size" specifies how large the Bayes journal will grow before it is opportunistically synced. The default value is 102400.
