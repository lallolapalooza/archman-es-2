SAFENET(8) Manual de NUT SAFENET(8)

NOMBRE

safenet - Controlador para equipos SAI compatibles con SafeNet

SINOPSIS

safenet -h

safenet -a NOMBRE_SAI [OPCIONES]


Nota

Esta página del manual solo documenta las características específicas del hardware del controlador safenet. Para obtener información sobre el controlador principal, consulte nutupsdrv(8).

HARDWARE SOPORTADO

Este controlador soporta equipos SAI que pueden ser controlados a través de SafeNet v1.0 para Windows (solo interfaz serie).

ARGUMENTOS ADICIONALES

Este controlador soporta las siguientes opciones en el archivo ups.conf(5):

fabricante=valor

La autodetección de este parámetro aún no es posible (y probablemente nunca lo será). Por lo tanto, esta cadena definida por el usuario acepta cualquier nombre. El valor predeterminado es desconocido.

modeloname=valor

Al igual que el fabricante anterior. El valor predeterminado es desconocido.

numeroserie=valor

Al igual que el fabricante anterior. El valor predeterminado es desconocido.

ondelay=valor

Tiempo de espera antes de encender el SAI (minutos). Por defecto es 1 minuto.

offdelay=valor

Tiempo de espera antes de apagar el SAI (segundos). Por defecto son 30 segundos.

COMANDOS INSTANTÁNEOS

Este controlador soporta algunos comandos instantáneos (consulte upscmd(8)):

test.battery.start

Iniciar autocomprobación del SAI

test.battery.stop

Cancelar autocomprobación del SAI

test.failure.start

Iniciar fallo de energía simulado

test.failure.stop

Cancelar fallo de energía simulado

beeper.enable

Habilitar el zumbador del SAI

beeper.mute

Silenciar temporalmente el zumbador del SAI

beeper.toggle

Activar/desactivar el zumbador del SAI

shutdown.return

Apagar la carga y esperar a que vuelva la energía. Utiliza el temporizador definido por offdelay.

shutdown.reboot

Apagar la carga y regresar. Utiliza los temporizadores definidos por offdelay y ondelay.

PROBLEMAS CONOCIDOS

Si ejecuta el comando shutdown.return con la red presente, la salida puede permanecer encendida o apagarse y no volver a encenderse. El comando shutdown.reboot encenderá incondicionalmente la carga nuevamente (con o sin red presente).

Si el controlador se llama con la opción -k (o a través de upsdrvctl shutdown), intenta detectar qué comando se debe usar en un intento de permanecer apagado hasta que la red esté presente nuevamente o de ciclar la salida si la energía regresó mientras tanto. Esto no es infalible y debe estar preparado para que la energía no se apague, o para que no regrese cuando vuelva la energía.
