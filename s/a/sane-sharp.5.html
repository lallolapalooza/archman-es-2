NOMBRE

sane-sharp - Backend de SANE para escáneres SHARP

DESCRIPCIÓN

La biblioteca sane-sharp implementa un backend SANE (Scanner Access Now Easy) que proporciona acceso a escáneres SCSI SHARP. ¡Este backend debe considerarse software de **calidad beta**! En su estado actual se sabe que funciona con los escáneres JX-610 y JX-250. Está preparado para su uso con los escáneres de la serie JX-330, pero no podemos probarlo con estos dispositivos.

Para otros escáneres Sharp, puede funcionar o no.

Actualmente, se sabe que los siguientes escáneres funcionan con este backend.

Vendor  Product id:
-----   -----------
Sharp   JX-610
Sharp   JX-250
Sharp   JX-320
Sharp   JX-330
Sharp   JX-350

Los siguientes escáneres son detectados por el backend, pero no probados:

Vendor  Product id:
-----   -----------
Sharp   JX-325

NOMBRES DE DISPOSITIVO

Este backend espera nombres de dispositivo del tipo:

especial

donde especial es la ruta del dispositivo especial que corresponde a un escáner SCSI. El nombre del dispositivo especial debe ser un dispositivo SCSI genérico o un enlace simbólico a dicho dispositivo. En Linux, un nombre de dispositivo de este tipo podría ser /dev/sga o /dev/sge, por ejemplo. Consulte sane-scsi(5) para obtener detalles.

OPCIONES DE ESCANEO

--mode
Modo de escaneo. Los ajustes posibles son: Lineart (escaneos en blanco y negro de 1 bit), Gray (escaneos en escala de grises de 8 bits), Lineart Color (escaneos de color bi-nivel) y Color (escaneos RGB de 8 bits). El valor predeterminado es Color.
--halftone-pattern
Patrón de tramado. Disponible solo para los escáneres de la serie JX-330. Los ajustes posibles son: none, Dither Bayer, Dither Spiral, Dither Dispersed y Error Diffusion. El valor predeterminado es none.
--source
Fuente de papel. Esta opción solo está disponible si se instala un alimentador automático de documentos o un adaptador de transparencias. Los ajustes posibles son: Flatbed, Automatic Document Feeder y Transparency Adapter. Si se instala un ADF o un adaptador de transparencias, su uso es la selección predeterminada.
--custom-gamma
Gamma personalizada. Esta opción determina si se utiliza una tabla gamma integrada o una tabla personalizada. Los ajustes posibles son: yes (habilita tablas gamma personalizadas) o no (habilita una tabla gamma integrada).
--gamma
Gamma. Esta opción solo está disponible si Custom Gamma está configurado en no. Los valores posibles son: 1.0 o 2.2. El valor predeterminado es 2.2. (El JX-250 y JX-350 no tienen corrección gamma integrada; para estos escáneres, el backend descarga una tabla gamma en el escáner).
--gamma-table
Tabla Gamma. Valores permitidos: 0..255; se deben definir 256 números. Los valores predeterminados son 0, 1, 2, .. 255 (es decir, gamma == 1). Esta tabla solo se utiliza para escaneos en escala de grises.
--red-gamma-table
Tabla Gamma Roja. Valores permitidos: 0..255; se deben definir 256 números. Los valores predeterminados son 0, 1, 2, .. 255 (es decir, gamma == 1).
--green-gamma-table
Tabla Gamma Verde. Valores permitidos: 0..255; se deben definir 256 números. Los valores predeterminados son 0, 1, 2, .. 255 (es decir, gamma == 1).
--blue-gamma-table
Tabla Gamma Azul. Valores permitidos: 0..255; se deben definir 256 números. Los valores predeterminados son 0, 1, 2, .. 255 (es decir, gamma == 1).
--resolution
Selecciona la resolución de la imagen escaneada. Valores permitidos: 30..600 (JX-330, JX-350 y JX-610) y 30..400 (JX-250). El valor predeterminado es 150.
-l, -t, -x, -y
Ventana de Escaneo. Posición x superior izquierda del área de escaneo (-l), posición y superior izquierda del área de escaneo (-t), posición x inferior derecha del área de escaneo (-x) y posición y inferior derecha del área de escaneo (-y). Los ajustes posibles dependen del modelo de escáner y, para el JX-250 y el JX-350, también del uso del alimentador automático de documentos o del adaptador de transparencias. Consulte los valores permitidos por xscanimage(1), o xsane(1). Con scanimage(1), introduzca uno de los siguientes comandos para ver los valores de parámetros permitidos para la ventana de escaneo:
scanimage -d sharp --source "Automatic Document Feeder" --help

scanimage -d sharp --source Flatbed --help

scanimage -d sharp --source "Transparency Adapter" --help

--edge emphasis
Énfasis de borde. Esta opción no está disponible para el JX-250 y el JX-350. Los ajustes posibles son: None, Middle, Strong y Blur. El valor predeterminado es None.
--threshold
Establece el umbral para píxeles en blanco y negro en modo lineart. Los valores posibles son 1..255. El valor predeterminado es 128. Esta opción solo está disponible en el modo de escaneo lineart.
--threshold-red
Establece el umbral para el componente rojo de un píxel en modo de escaneo de color lineart. Los valores posibles son 1..255. El valor predeterminado es 128. Esta opción solo está disponible en el modo de escaneo de color lineart.
--threshold-green
Establece el umbral para el componente verde de un píxel en modo de escaneo de color lineart. Los valores posibles son 1..255. El valor predeterminado es 128. Esta opción solo está disponible en el modo de escaneo de color lineart.
--threshold-blue
Establece el umbral para el componente azul de un píxel en modo de escaneo de color lineart. Los valores posibles son 1..255. El valor predeterminado es 128. Esta opción solo está disponible en el modo de escaneo de color lineart.
--lightcolor
Establece el color de la fuente de luz. Los valores posibles son white, red, green y blue. El valor predeterminado es white. Esta opción solo está disponible en los modos de escaneo lineart color y color.

USO DEL ADF

Si ocurre un atasco de papel, la cubierta de mantenimiento *debe* abrirse y cerrarse, incluso si el papel atascado se puede quitar sin abrir la cubierta de mantenimiento. De lo contrario, la condición de error no se borrará.

CONFIGURACIÓN

El contenido del archivo sharp.conf es una lista de opciones y nombres de dispositivo que corresponden a los escáneres Sharp. Las líneas vacías y las líneas que comienzan con una almohadilla (#) se ignoran. Consulte sane-scsi(5) para obtener detalles sobre los nombres de dispositivo.

Las líneas que establecen una opción comienzan con la palabra clave option, seguida del nombre de la opción y su valor. Actualmente, se definen tres opciones: buffers, buffersize y readqueue.

Las opciones definidas al principio de sharp.conf se aplican a todos los dispositivos; las opciones definidas después de un nombre de dispositivo se aplican a ese dispositivo.

Las opciones buffers y readqueue solo son significativas si el backend se ha compilado de modo que para cada escaneo se desdobla un segundo proceso (interruptor USE_FORK en sharp.c). Este proceso lee los datos del escaneo del escáner y escribe estos datos en un bloque de memoria compartida. El proceso principal lee los datos de este bloque de memoria y los entrega al frontend. CONFIGURATION

Las siguientes opciones pueden ser establecidas en el archivo de configuración ~/.sane/sharp.conf o en /etc/sane.d/sharp.conf. Estas opciones controlan el tamaño y uso de este bloque de memoria compartida.

option buffers define el número de buffers utilizados. El número más pequeño permitido es 2.

option buffersize define el tamaño de un buffer. Dado que cada buffer se llena con un solo comando de lectura enviado al escáner, su tamaño está limitado automáticamente al tamaño permitido por el sistema operativo o por la biblioteca Sane SCSI para los comandos de lectura SCSI. Se recomienda un tamaño de buffer de 128 kB o 256 kB para resoluciones de escaneo de 300 ppp y superiores.

option readqueue define cuántos comandos de lectura se enviarán al escáner en cola. En este momento, la biblioteca Sane SCSI solo admite comandos de lectura en cola para Linux. Para otros sistemas operativos, option readqueue debe configurarse a 0. Para Linux, option readqueue debe configurarse a 2. Valores mayores que 2 para option readqueue no son razonables en la mayoría de los casos. option buffers debe ser mayor que option readqueue.

Consideraciones de Rendimiento

Esta sección se enfoca en el problema de las paradas del carro del escáner durante un escaneo. Las paradas del carro ocurren principalmente con el JX-250. Este escáner obviamente tiene un buffer interno pequeño en comparación con su velocidad. Eso significa que el backend debe leer los datos lo más rápido posible del escáner para evitar paradas del carro.

Incluso el JX-250 necesita menos de 10 segundos para un escaneo A4 en escala de grises a 400 ppp, lo que resulta en una tasa de transferencia de datos de más de 1.6 MB por segundo. Esto significa que los datos producidos por el escáner deben procesarse bastante rápido. Debido al pequeño buffer interno del JX-250, el backend debe emitir una solicitud de lectura para el siguiente bloque de datos tan pronto como sea posible después de leer un bloque de datos para evitar paradas del carro.

Las paradas del carro pueden ser causadas por las siguientes razones:

- demasiado "tráfico" en el bus SCSI,
- respuestas lentas del backend al escáner,
- un programa que procesa los datos adquiridos por el backend es demasiado lento.

Demasiado "tráfico" en el bus SCSI: Esto ocurre, por ejemplo, si los discos duros están conectados al mismo bus SCSI que el escáner, y cuando la transferencia de datos desde/hacia estos discos duros requiere una parte considerable del ancho de banda SCSI durante un escaneo. Si este es el caso, debería considerar conectar el escáner a un adaptador SCSI separado.

Respuestas lentas del backend al escáner: Desafortunadamente, los sistemas operativos tipo UNIX generalmente no tienen capacidades de tiempo real. Por lo tanto, no hay garantía de que el backend pueda, en ninguna circunstancia, comunicarse con el escáner tan rápido como sea necesario. Para minimizar este problema, el backend debe compilarse de manera que se genere un proceso de lectura separado: Asegúrese de que USE_FORK esté definido cuando compile sharp.c. Si las respuestas lentas del backend siguen siendo un problema, podría intentar reducir la carga del sistema. Aunque el backend y el proceso de lectura solo necesitan una pequeña cantidad de tiempo de procesador, otros procesos en ejecución pueden causar un aumento en el tiempo de espera entre dos fragmentos de tiempo asignados al proceso de lectura. En sistemas más lentos, un aumento de este retraso puede ser suficiente para causar una parada del carro con el JX-250. Para Linux, se recomienda el uso del controlador SG versión 2.1.36 o superior, ya que soporta, en combinación con la biblioteca SCSI de Sane versión 1.0.2, la cola de comandos dentro del kernel. Esta implementación de cola, combinada con un tamaño de buffer de al menos 128 kB, debería evitar la mayoría de las paradas del carro.

Procesamiento lento de los datos de escaneo: Un ejemplo de esta situación es el acceso al escáner a través de una red Ethernet de 10 MBit, que es definitivamente demasiado lenta para transferir los datos de escaneo tan rápido como son producidos por el escáner. Si tiene suficiente memoria disponible, puede aumentar option buffers, de modo que una imagen completa pueda almacenarse en estos buffers.

Para ver si el backend es demasiado lento o si el procesamiento posterior de los datos es demasiado lento, configure la variable de entorno SANE_DEBUG_SHARP a 1. Cuando un escaneo termina, el backend escribe la línea "buffer full conditions: nn" en stderr. Si nn es cero, las paradas del carro son causadas por respuestas demasiado lentas del backend o demasiado "tráfico" en el bus SCSI. Si nn es mayor que cero, el backend tuvo que esperar nn veces hasta que un buffer fuera procesado por el frontend. (Tenga en cuenta que option buffers debe ser mayor que option readqueue para obtener una salida útil para "buffer full conditions").

ARCHIVOS

El archivo de configuración del backend.
/usr/lib/sane/libsane-sharp.a
La biblioteca estática que implementa este backend.
/usr/lib/sane/libsane-sharp.so
La biblioteca compartida que implementa este backend (presente en sistemas que soportan carga dinámica).

ENTORNO

SANE_DEBUG_SHARP
Si la biblioteca fue compilada con soporte de depuración habilitado, esta variable de entorno controla el nivel de depuración para este backend. Por ejemplo, un valor de 128 solicita que se imprima toda la salida de depuración. Niveles más pequeños reducen la verbosidad.

PROBLEMAS CONOCIDOS

1. Modo ADF

Después de varios escaneos ADF, el escáner mueve el carro a la posición inactiva y de vuelta a la posición de escaneo ADF, antes de que comience un escaneo. No sabemos si esto es un problema del escáner o un error del backend. En este momento, el escáner debe apagarse y encenderse para detener este comportamiento molesto.

2. El nivel de umbral no funciona (solo JX-610)

3. La resolución máxima está limitada a 600 ppp (JX-610 soporta hasta 1200 ppp) o 400 ppp (JX-250)

4. Si el JX-250 se usa con un ADF, puede ocurrir la siguiente situación: Después de varios escaneos, el escáner mueve, después de cargar una nueva hoja de papel, el carro a la posición inactiva y luego de vuelta a la posición utilizada para escaneos ADF. Esto sucede para *cada* escaneo, a diferencia de la calibración, que se realiza después de 10 escaneos. (Para la calibración, el carro también se mueve a la posición inactiva). No sabemos si este comportamiento es causado por el backend, o si es un error en el firmware del escáner.

5. Se admite el uso de un adaptador de transparencia (unidad de escaneo de película), pero no se ha probado.
