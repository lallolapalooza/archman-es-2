sane-avision(5) SANE Scanner Access Now Easy sane-avision(5)

NOMBRE

sane-avision - Backend SANE para escáneres planos y de película de marca Avision y Avision OEM (HP, Minolta, Mitsubishi, UMAX y posiblemente más).

DESCRIPCIÓN

La biblioteca sane-avision implementa un backend SANE (Scanner Access Now Easy) que proporciona acceso a varios escáneres Avision y escáneres OEM Avision etiquetados por HP, Minolta, Mitsubishi o Fujitsu.

Es totalmente consciente del big-endian y en uso diario en sistemas PowerPC y SPARC.

¡Sugiero que mantengas una mano en el botón de encendido del escáner mientras realizas los primeros escaneos, especialmente con escáneres de película!

CONFIGURACIÓN

El archivo de configuración para este backend reside en /etc/sane.d/avision.conf.

Su contenido es una lista de nombres de dispositivos que corresponden a escáneres compatibles con Avision y Avision, y opciones del backend. Las líneas vacías y las líneas que comienzan con un signo de almohadilla (#) se ignoran. A continuación se muestra un archivo de configuración de ejemplo:

 # esto es un comentario
 option force-a4
 option force-a3
 option skip-adf
 option disable-gamma-table
 option disable-calibration
 #scsi Vendor Model Type Bus Channel ID LUN
 scsi AVISION
 scsi HP
 scsi /dev/scanner
 usb 0x03f0 0x0701
force-a4:
Fuerza al backend a sobrescribir el área escaneable devuelta por el escáner a ISO A4. Los escáneres que se sabe que devuelven datos erróneos están marcados en el backend, por lo que si necesita esta opción, por favor infórmelo al mantenedor del backend. ¡ÚSELO CON CUIDADO!
force-a3:
Fuerza al backend a sobrescribir el área escaneable devuelta por el escáner a ISO A3. Los escáneres que se sabe que devuelven datos erróneos están marcados en el backend, por lo que si necesita esta opción, por favor infórmelo al mantenedor del backend. ¡ÚSELO CON CUIDADO!
skip-adf:
Fuerza al backend a ignorar un estado ADF inconsistente devuelto por el escáner (ADF no presente, pero el número de modelo del ADF no es cero). Sin esta opción, el backend intentará varias veces restablecer el ADF y reintentar la consulta en esta situación, y fallará con un error de "no soportado" si el ADF aún no responde.
disable-gamma-table:
Deshabilita el uso de la tabla gamma del escáner. Puede intentar esto si sus escaneos se cuelgan o solo producen basura aleatoria.
disable-calibration:
Deshabilita la calibración de color del escáner. Puede intentar esto si sus escaneos se cuelgan o solo producen basura aleatoria.
Nota:
Cualquier opción anterior modifica el flujo de código predeterminado para su escáner. Las opciones solo deben usarse cuando encuentre problemas con el comportamiento predeterminado del backend. Por favor, informe la necesidad de estas opciones al autor del backend para que el backend pueda ser corregido lo antes posible.

NOMBRES DE DISPOSITIVO

Este backend espera nombres de dispositivo del tipo:

scsi scsi-spec

usb usb-spec

Donde scsi-spec es el nombre de ruta a un dispositivo especial o un ID de dispositivo que corresponde a un escáner SCSI. El nombre del dispositivo especial debe ser un dispositivo SCSI genérico o un enlace simbólico a dicho dispositivo, por ejemplo, en Linux /dev/scanner o /dev/sg0. El ID del dispositivo es el ID devuelto por el escáner, por ejemplo, "HP" o "AVISION". Consulte sane-scsi(5) para obtener detalles.

Nota:
Dado que el backend ahora incluye acceso USB nativo, ya no es necesario, incluso se considera obsoleto, acceder a escáneres USB a través de la emulación SCSI (llamada hpusbscsi en Linux) para dispositivos USB Avision como HP 53xx, HP 74xx o escáneres de película Minolta.

usb-spec es el nombre del dispositivo USB, el par ID de proveedor/producto o el nombre utilizado por libusb correspondiente al escáner USB. Por ejemplo, "0x03f0 0x0701" o "libusb:002:003". Consulte sane-usb(5) para obtener detalles.

El programa sane-find-scanner(1) ayuda a averiguar el nombre correcto del dispositivo scsi o usb.

Una lista de dispositivos compatibles está integrada en el backend avision, por lo que normalmente no es necesario especificar un ID.

ARCHIVOS

/etc/sane.d/avision.conf
El archivo de configuración del backend (ver también la descripción de SANE_CONFIG_DIR a continuación).
/usr/lib/sane/libsane-avision.a
La biblioteca estática que implementa este backend.
/usr/lib/sane/libsane-avision.so
La biblioteca compartida que implementa este backend (presente en sistemas que soportan carga dinámica).

ENTORNO

SANE_CONFIG_DIR
Esta variable de entorno especifica la lista de directorios que pueden contener el archivo de configuración. En sistemas *NIX, los directorios están separados por dos puntos (`:'), en OS/2, están separados por punto y coma (`;'). Si esta variable no está configurada, el archivo de configuración se busca en dos directorios predeterminados: primero, el directorio de trabajo actual (".") y luego en /etc/sane.d. Si el valor de la variable de entorno termina con el carácter separador de directorios, entonces los directorios predeterminados se buscan después de los directorios explícitamente especificados. Por ejemplo, configurar SANE_CONFIG_DIR a "/tmp/config:" resultaría en la búsqueda de los directorios tmp/config, . y /etc/sane.d (en este orden).
SANE_DEBUG_AVISION
Si la biblioteca se compiló con soporte de depuración habilitado, esta variable de entorno controla el nivel de depuración para este backend. Niveles de depuración más altos aumentan la verbosidad de la salida. El nivel de depuración 7 es el valor preferido por el autor para depurar problemas del backend.

Ejemplo: export SANE_DEBUG_AVISION=7
