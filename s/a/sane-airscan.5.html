SANE-AIRSCAN(5) Backend SANE para AirScan (eSCL) y WSD SANE-AIRSCAN(5)

NOMBRE

sane-airscan - Backend SANE para escáneres y MFP AirScan (eSCL) y WSD

DESCRIPCIÓN

El sane-airscan es el backend universal para escaneo de documentos "sin controladores". Actualmente soporta dos protocolos:

1. eSCL, también conocido como AirScan o escaneo AirPrint
2. WSD, también conocido como WS-Scan

CONFIGURACIÓN

sane-airscan carga sus archivos de configuración desde los siguientes lugares:

1. /etc/sane.d/airscan.conf
2. /etc/sane.d/airscan.d/*

La sintaxis del archivo de configuración es muy similar a la sintaxis de archivos .INI. Consta de secciones, cada sección contiene algunas variables. Los comentarios se inician con los caracteres # o ; y continúan hasta el final de la línea.

# Este es un comentario
[sección 1]
variable 1 = valor 1  ; y otro comentario
variable 2 = valor 2

Los espacios iniciales y finales del nombre y valor de la variable se eliminan. Si desea conservarlos, ponga el nombre o el valor entre comillas ("así").

CONFIGURACIÓN DE DISPOSITIVOS

Si el escáner y el ordenador están conectados al mismo segmento de LAN, todo debería funcionar "tal cual", sin necesidad de configuración manual.

Sin embargo, en algunos casos, la configuración manual puede ser útil. Por ejemplo:

1. Si el ordenador y el escáner están conectados a través de un router IP
2. Hay muchos dispositivos en una red corporativa, pero
   solo unos pocos de ellos son interesantes
3. El descubrimiento automático funciona de forma poco fiable

Para configurar manualmente un dispositivo, añada la siguiente sección al archivo de configuración:

[dispositivos]
"Kyocera eSCL" = http://192.168.1.102:9095/eSCL, eSCL
"Kyocera WSD" = http://192.168.1.102:5358/WSDScanner, WSD
"Dispositivo que no quiero ver" = disable

La sección [dispositivos] contiene todos los dispositivos configurados manualmente, una línea por dispositivo, y cada línea contiene un nombre de dispositivo a la izquierda de la ecuación y una URL del dispositivo a la derecha, seguido del protocolo (eSCL o WSD). Si se omite el protocolo, se asume eSCL. También puede deshabilitar un dispositivo particular usando la palabra clave disable en lugar de una URL.

Además, puede configurar manualmente un dispositivo pasando directamente su URL en un nombre de dispositivo sin añadirlo al archivo de configuración. Esto toma el formato protocolo:NombreDispositivo:URL. Los ejemplos anteriores podrían escribirse como escl:Kyocera eSCL:http://192.168.1.102:9095/eSCL y wsd:Kyocera WSD:http://192.168.1.102:5358/WSDScanner.

Para averiguar las URL de los dispositivos disponibles, la forma más sencilla es ejecutar la herramienta airscan-discover(1) suministrada en un ordenador conectado al mismo segmento de LAN que el escáner. En caso de éxito, este programa volcará a su salida estándar una lista de dispositivos descubiertos en un formato adecuado para su inclusión en el archivo de configuración.

Si no es posible ejecutar airscan-discover(1) en el mismo segmento de LAN que un escáner, tendrá que seguir un camino más difícil. Su administrador debe conocer la dirección IP del dispositivo, consultar el manual de su dispositivo para el puerto eSCL, y la parte de la ruta de la URL probablemente sea "/eSCL", aunque en algunos dispositivos puede diferir. Descubrir las URL de WSD de esta manera es mucho más difícil, porque es muy complicado adivinar el puerto TCP y la ruta de la URL, que en el caso de eSCL.

Para dispositivos eSCL, la URL también puede usar el esquema unix://, como unix://scanner.sock/eSCL. El "host" de la URL es un nombre de archivo que se buscará en el directorio especificado por socket_dir (ver más abajo). Al conectarse al escáner, todo el tráfico se enviará al socket UNIX especificado en lugar de a una conexión TCP.

Por defecto, sane-airscan trata a todos los escáneres como dispositivos remotos. Esto puede ser indeseable si se configura un proxy que traduce de eSCL/WSD al protocolo SANE, ya que saned(8) ignora cualquier dispositivo que no esté conectado localmente. Al establecer pretend-local = true, sane-airscan puede hacer que sus dispositivos sean accesibles para el daemon de red SANE.

OPCIONES DE CONFIGURACIÓN

Opciones varias van a la sección [opciones]. Actualmente se soportan las siguientes opciones:

[opciones]
; Si hay muchos escáneres alrededor y solo estás
; interesado en unos pocos, deshabilita el descubrimiento automático y
; configura los escáneres manualmente.
descubrimiento = habilitar | deshabilitar
; Elige qué mostrarán las aplicaciones SANE en la lista de dispositivos:
; el nombre de red del escáner (por defecto) o el nombre del modelo de hardware.
modelo = red | hardware
; Si el dispositivo soporta ambos protocolos eSCL y WSD, sane-airscan
; puede elegir el protocolo "mejor" automáticamente, o
; exponer todas las variantes para el usuario, permitiendo la selección manual del protocolo.
; El valor por defecto es "auto".
protocolo = auto | manual
; El descubrimiento de dispositivos WSD puede ser "rápido" o "completo". El modo "rápido"
; funciona tan rápido como el descubrimiento DNS-SD, pero en algunos casos
; puede ser poco fiable. El modo "completo" es lento y fiable.
; También es posible deshabilitar el descubrimiento automático
; de dispositivos WSD. El valor por defecto es "rápido".
ws-descubrimiento = rápido | completo | apagado
; Los escáneres que usan el esquema unix:// en su URL solo pueden
; especificar un nombre de socket (no una ruta completa). El nombre se buscará
; en el directorio especificado aquí.
; El valor por defecto es /var/run.
dir_socket = /ruta/al/directorio
; Configura si los dispositivos eSCL y WSD deben ser tratados como
; si estuvieran conectados localmente. El comportamiento por defecto considera
; que son dispositivos remotos a los que se accede a través de la red.
; Esta opción debe cambiarse al exportar un escáner a través de
; saned. El valor por defecto es "falso"
pretender-local = falso | verdadero

BLOQUEO DE DISPOSITIVOS

Esta función puede ser útil si te encuentras en una red muy grande y tienes muchos dispositivos cerca, mientras que solo te interesan unos pocos de ellos.

[bloqueo]
modelo = "Xerox*"       ; bloqueo por nombre de modelo
nombre  = "HP*"          ; bloqueo por nombre de red
ip    = 192.168.0.1    ; bloqueo por dirección
ip    = 192.168.0.0/24 ; bloqueo de toda la subred

Los nombres de red provienen de DNS-SD, WS-Discovery no proporciona esta información. Para que el filtrado por nombre de red funcione, Avahi debe estar habilitado y el dispositivo debe ser descubrible a través de DNS-SD (no necesariamente como escáner, basta con que un escáner WSD sea descubrible como impresora a través de DNS-SD).

El bloqueo solo afecta al descubrimiento automático y no afecta a los dispositivos configurados manualmente.

DEPURACIÓN

sane-airscan proporciona una excelente instrumentación para la resolución de problemas sin acceso físico al dispositivo problemático.

Las instalaciones de depuración se pueden controlar utilizando la sección [debug] del archivo de configuración:

[debug]
; Habilita o deshabilita el registro en consola
habilitar = falso | verdadero
; Habilita el rastreo del protocolo y configura el directorio de salida
; para los archivos de rastreo. Como en el shell, para especificar una ruta relativa al
; directorio de inicio, comiénzala con un carácter de tilde, seguido
; de una barra, es decir, "~/airscan/rastreo". El directorio se
; creará automáticamente.
rastreo = ruta
; Volcado hexadecimal de todo el tráfico al archivo de rastreo (¡muy verboso!)
volcado_hex = falso | verdadero

ENTORNO

SANE_DEBUG_AIRSCAN
Esta variable, si se establece en true o en un valor numérico distinto de cero, habilita mensajes de depuración que se imprimen en stderr.
SANE_CONFIG_DIR
Esta variable altera la ruta de búsqueda de archivos de configuración. Es una lista de directorios separada por dos puntos. Estos directorios se buscan para encontrar el archivo de configuración airscan.conf y el subdirectorio airscan.d, antes de buscar en la ruta estándar (/etc/sane.d).
SANE_AIRSCAN_DEVICE
Esta variable, si se establece, anula todos los dispositivos configurados manualmente en los archivos de configuración y deshabilita el descubrimiento automático.
Consiste en tres parámetros, delimitados por dos puntos (:):
"PROTO:NOMBRE_DISPOSITIVO:URL"
Donde:
- PROTO es escl o wsd.
- NOMBRE_DISPOSITIVO aparecerá en la lista de dispositivos.
- URL es la URL del dispositivo, utilizando esquemas http: o https:.
Ejemplos:
"escl:Kyocera eSCL:http://192.168.1.102:9095/eSCL" (eSCL)
"wsd:Kyocera WSD:http://192.168.1.102:5358/WSDScanner" (WSD)
El propósito principal de esta variable es la prueba automatizada del backend sane-airscan.
