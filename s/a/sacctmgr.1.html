NOMBRE

sacctmgr - Se utiliza para ver y modificar información de cuentas de Slurm.

SINOPSIS

sacctmgr [OPCIONES...] [COMANDO...]

DESCRIPCIÓN

sacctmgr se utiliza para ver o modificar información de cuentas de Slurm. La información de las cuentas se mantiene dentro de una base de datos con la interfaz proporcionada por slurmdbd (demonio de base de datos de Slurm). Esta base de datos puede servir como un almacén central de información de usuarios y computadoras para múltiples computadoras en un solo sitio. La información de cuentas de Slurm se registra en función de cuatro parámetros que forman lo que se conoce como una asociación. Estos parámetros son usuario, cluster, partición y cuenta. usuario es el nombre de inicio de sesión. cluster es el nombre de un clúster administrado por Slurm, según lo especificado por el parámetro ClusterName en el archivo de configuración slurm.conf. partición es el nombre de una partición de Slurm en ese clúster. cuenta es la cuenta para un trabajo. El modo de operación previsto es iniciar el comando sacctmgr, agregar, eliminar, modificar y/o listar registros de asociación, luego confirmar los cambios y salir.

NOTA: El contenido de la base de datos de Slurm se mantiene en minúsculas. Esto puede hacer que algunas salidas de sacctmgr difieran de las de otros comandos de Slurm.

OPCIONES

-s, --asociaciones
Usar con mostrar o listar para mostrar asociaciones con la entidad. Esto es equivalente al comando asociaciones.
-h, --ayuda
Imprimir un mensaje de ayuda que describa el uso de sacctmgr. Esto es equivalente al comando ayuda.
-i, --inmediato
Confirmar los cambios inmediatamente sin pedir confirmación.
--json, --json=lista, --json=<analizador_datos>
Volcar información como JSON usando el plugin analizador_datos predeterminado o un analizador_datos explícito con parámetros. Los argumentos de ordenación y formato se ignorarán. Esta opción no está disponible para todos los comandos.
-n, --sinencabezado
No se agregará un encabezado al principio de la salida.
-p, --analizable
La salida estará delimitada por '|' con un '|' al final.
-P, --analizable2
La salida estará delimitada por '|' sin un '|' al final.
-Q, --silencioso
No imprimir mensajes aparte de los de error. Esto es equivalente al comando silencioso.
-r, --sololec
Hace que el sacctmgr en ejecución no pueda modificar la información de contabilidad. La opción sololec es para usar en modo interactivo.
--yaml, --yaml=lista, --yaml=<analizador_datos>
Volcar información como YAML usando el plugin analizador_datos predeterminado o un analizador_datos explícito con parámetros. Los argumentos de ordenación y formato se ignorarán. Esta opción no está disponible para todos los comandos.
-v, --detallado
Habilitar registro detallado. Esto es equivalente al comando detallado.
-V, --version
Mostrar número de versión. Esto es equivalente al comando version.

Escribir información de la base de datos en un archivo plano o cargar información que previamente haya sido escrita en un archivo.

Limpiar las estadísticas del servidor.

Agregar una entidad. Idéntico al comando añadir.

Eliminar las entidades especificadas. Idéntico al comando quitar.

Mostrar una descripción de las opciones y comandos de sacctmgr.

Mostrar información sobre la entidad especificada. Por defecto, se muestran todas las entradas; puedes acotar los resultados especificando ESPECIFICACIONES en tu consulta. Idéntico al comando mostrar.
cargar <NOMBRE_ARCHIVO>
Cargar datos del clúster desde el archivo especificado. Este es un archivo de configuración generado al ejecutar el comando sacctmgr volcar. Este comando no carga datos de archivo; consulta en su lugar la opción sacctmgr archivo cargar.
modificar <ENTIDAD> donde <ESPECIFICACIONES> establecer <ESPECIFICACIONES>
Modificar una entidad.
ping
Ping a slurmdbd.
reconfigurar
Reconfigura SlurmDBD si se está ejecutando con uno.
quitar <ENTIDAD> donde <ESPECIFICACIONES>
Eliminar las entidades especificadas. Idéntico al comando eliminar.
mostrar <ENTIDAD> [<ESPECIFICACIONES>]
Mostrar información sobre la entidad especificada. Por defecto, se muestran todas las entradas; puedes acotar los resultados especificando ESPECIFICACIONES en tu consulta. Idéntico al comando listar.
apagar
Apagar el servidor.
ver <ENTITY> [<SPECS>]
Ver información sobre la entidad especificada. Por defecto, se muestran todas las entradas, puedes acotar los resultados especificando SPECS en tu consulta. Idéntico al comando listar o mostrar.
ver tareas [<SPECS>]
Ver información de tareas. Las especificaciones solo pueden ser utilizadas para filtrar por nombre de tarea y estado.
ver trabajos [<SPECS>]
Ver información de trabajos. Las especificaciones solo pueden ser utilizadas para filtrar por nombre de trabajo y estado.
configurar
Carga el archivo de configuración especificado para el Daemon de la base de datos de Slurm.
ajustes
Muestra los ajustes de Slurm.

EJEMPLOS

Listar todas las cuentas y sus asociaciones:

sacctmgr show account with associations

Listar todos los clústeres:

sacctmgr show cluster

Crear una nueva cuenta llamada 'newaccount' y establecer que todos los usuarios puedan usarla:

sacctmgr create account Name=newaccount

Modificar una cuenta existente llamada 'oldaccount' para que la prioridad sea 10:

sacctmgr modify account Name=oldaccount set Priority=10

Eliminar la cuenta 'todelete':

sacctmgr delete account Name=todelete

Mostrar todos los trabajos en los que 'myuser' está asociado con la cuenta 'myaccount':

sacctmgr show job where User=myuser Account=myaccount

Mostrar todas las asociaciones para el usuario 'myuser':

sacctmgr show user where Name=myuser format=User,Account,GrpCPURunMins,GrpJobs

Mostrar todos los trabajos y tareas en espera del usuario 'myuser':

sacctmgr show job,task where User=myuser State=PENDING

ENTIDADES

account
Una cuenta, típicamente especificada en el momento de envío de un trabajo usando la opción --account=. Estas pueden organizarse de forma jerárquica, por ejemplo, las cuentas 'chemistry' y 'physics' pueden ser hijos de la cuenta 'science'. La jerarquía puede tener una profundidad arbitraria.
association
La entidad utilizada para agrupar información que consta de cuatro parámetros: account, cluster, partition (opcional) y user. Se utiliza solo con los comandos list o show. La adición, modificación y eliminación deben realizarse en una entidad de usuario, cuenta o clúster, lo que a su vez actualizará las asociaciones subyacentes. Se permite la modificación de atributos como los límites para una asociación, pero no la modificación de los cuatro atributos principales de una asociación. No se puede cambiar la configuración de la partición (o establecer una si no se ha establecido) para una asociación existente. En su lugar, deberá crear una nueva asociación que incluya la partición. Puede mantener la asociación anterior sin partición definida o eliminarla. Tenga en cuenta que estas asociaciones recién agregadas son entidades únicas y la información de uso existente no se transferirá a la nueva asociación.
cluster
El parámetro ClusterName en el archivo de configuración slurm.conf, utilizado para diferenciar cuentas en diferentes máquinas.
configuration
Se utiliza solo con los comandos list o show para informar la configuración actual del sistema.
coordinator
Un usuario especial con privilegios, generalmente un administrador de cuenta, que puede agregar usuarios o subcuentas a la cuenta de la que es coordinador. Esta debe ser una persona de confianza, ya que pueden cambiar los límites en las asociaciones de cuentas y usuarios, así como cancelar, poner en cola o reasignar cuentas de trabajos dentro de su ámbito.
event
Eventos como nodos caídos o en cola en clústeres. Tenga en cuenta que esto no incluye estados transitorios como DRAINING.
federation
Un grupo de clústeres que trabajan juntos para programar trabajos.
job
Se utiliza para modificar campos específicos de un trabajo: Código de salida derivado, Comentario, Comentario_admin, Extra, Comentario_sistema, TRES o WCKey.
problem
Úselo con show o list para mostrar problemas de la entidad.
qos
Calidad de Servicio.
reservation
Una colección de recursos reservados para su uso por una cuenta, usuario o grupo de usuarios particular durante un período de tiempo determinado.
resource
Recursos de software para el sistema. Estas son licencias de software compartidas entre clústeres.
RunawayJobs
Se utiliza solo con los comandos list o show para informar trabajos actuales que han quedado huérfanos en el clúster local y ahora están descontrolados. Si hay trabajos en este estado, también le dará la opción de "arreglarlos". Esto establece la hora de finalización de cada trabajo en la más tardía entre la hora de inicio, la hora elegible y la hora de envío del trabajo, y establece el estado en completado por defecto. Una vez corregido, esto activa el SlurmDBD para recalcular el uso desde antes de la hora de envío más temprana de todos los trabajos descontrolados. NOTA: Esto puede llevar mucho tiempo y sreport puede no devolver datos hasta que se complete el recálculo. NOTA: Debe tener un AdminLevel de al menos Operator para realizar esta acción.
stats
Se utiliza con los comandos list o show para ver las estadísticas del servidor. Acepta argumentos opcionales de ave_time o total_time para ordenar por esos campos. Por defecto, ordena por el campo de recuento de RPC en orden ascendente.
transaction
Lista de transacciones que han ocurrido durante un período de tiempo determinado.
tres
Se utiliza con los comandos list o show para ver una lista de Recursos Rastreables (Trackable RESources) configurados en el sistema.
user
El nombre de inicio de sesión. Los nombres de usuario no distinguen entre mayúsculas y minúsculas (se fuerzan a minúsculas) a menos que la opción PreserveCaseUser se haya establecido en el archivo de configuración de SlurmDBD.
wckeys
Clave de Caracterización de Carga de Trabajo (Workload Characterization Key). Una cadena arbitraria para agrupar cuentas ortogonales.

ESPECIFICACIONES GENERALES PARA ENTIDADES BASADAS EN ASOCIACIONES

NOTA: Los límites de grupo (GrpJobs, GrpTRES, etc.) se prueban cuando se está considerando un trabajo para la asignación de recursos. Si iniciar un trabajo causara que se exceda alguno de sus límites de grupo, ese trabajo no se considerará para la programación, incluso si ese trabajo pudiera desplazar a otros trabajos que liberarían suficientes recursos de grupo para que el trabajo pendiente pudiera iniciarse.

NOTA: Las modificaciones de límites de TRES de cualquier tipo utilizando la sintaxis "+=" o "-=" siempre producirán un valor entre 0 y 18446744073709551600. Intentar establecer un valor negativo usando "-=" establecerá ese TRES en 0, incluso si no había un límite de TRES presente de antemano.

DefaultQOS=<default_qos>
La QOS que esta asociación y sus hijos usarán por defecto si se permite en la lista QosLevel mencionada a continuación. Esto se anula si se establece directamente en un usuario. Para borrar un valor existente, establezca un nuevo valor de -1.
Fairshare={<fairshare_number>|parent}
Share={<fairshare_number>|parent}
Recursos compartidos asignados utilizados para el cálculo de la participación justa (fairshare). También puede ser la cadena parent, que se interpreta de manera diferente si se establece en un usuario o en una cuenta. Si se establece en un usuario, la asociación principal se utiliza para la participación justa. Si se establece en una cuenta, los hijos de esa cuenta se re-asociarán efectivamente para los cálculos de participación justa a la primera asociación principal de su padre que no sea Fairshare=parent. Los límites permanecen iguales, solo su valor de participación justa se ve afectado. Para borrar un valor existente, establezca un nuevo valor de -1.
GrpJobs=<max_jobs>
Número máximo de trabajos en ejecución en agregado para esta asociación y sus hijos. Para borrar un valor existente, establezca un nuevo valor de -1.
GrpJobsAccrue=<max_jobs>
Número máximo de trabajos pendientes en agregado capaces de acumular prioridad de antigüedad para esta asociación y sus hijos. Para borrar un valor existente, establezca un nuevo valor de -1.
GrpSubmit=<max_jobs>
GrpSubmitJobs=<max_jobs>
Número máximo de trabajos en estado pendiente o en ejecución en cualquier momento, en agregado, para esta asociación y sus hijos. Para borrar un valor existente, establezca un nuevo valor de -1.
GrpTRES=TRES[+|-]=<max_TRES>[,TRES[+|-]=<max_TRES>,...]
Número máximo de TRES que pueden ser asignados por trabajos en ejecución en agregado para esta asociación y sus hijos.

Consulte la sección Información de TRES a continuación para más detalles.

GrpTRESMins=TRES[+|-]=<minutes>[,TRES[+|-]=<minutes>,...]
Número máximo de minutos de TRES que pueden ser utilizados por trabajos pasados, presentes y futuros en esta asociación y sus hijos.

Consulte la sección Información de TRES a continuación para más detalles.

NOTA: Este límite no se aplica si se establece en la asociación raíz de un clúster. Por lo tanto, aunque pueda aparecer en la salida de sacctmgr, no se aplicará.

NOTA: Este límite solo se aplica cuando se utiliza el plugin de multifactor de prioridad. El tiempo se degrada utilizando el valor de PriorityDecayHalfLife o PriorityUsageResetPeriod según se establece en slurm.conf. Cuando se alcanza este límite, todos los trabajos asociados en ejecución serán terminados y todos los trabajos futuros enviados con asociaciones en el grupo se retrasarán hasta que puedan ejecutarse dentro del límite.

GrpTRESRunMins=TRES[+|-]=<minutes>[,TRES[+|-]=<minutes>,...]
Número máximo de minutos de TRES que pueden ser asignados por trabajos en ejecución en esta asociación y sus hijos. Esto tiene en cuenta el límite de tiempo de los trabajos en ejecución y lo consume. Si se alcanza el límite, no se inician nuevos trabajos hasta que otros trabajos finalicen para permitir la liberación de tiempo.

Consulte la sección Información de TRES a continuación para más detalles.

GrpWall=<max_wall>
Tiempo máximo de reloj de pared que puede ser asignado por trabajos en ejecución en agregado en esta asociación y sus hijos. El formato de GrpWall es <min> o <min>:<sec> o <hr>:<min>:<sec> o <days>-<hr>:<min>:<sec> o <days>-<hr>. El valor se registra en minutos con redondeo según sea necesario. Para borrar un valor existente, establezca un nuevo valor de -1.

NOTA: Aunque pueda aparecer en la salida de sacctmgr, este límite no se aplicará si se establece en la asociación raíz de un clúster.

NOTA: Este límite solo se aplica cuando se utiliza el plugin de multifactor de prioridad. El tiempo se degrada utilizando el valor de PriorityDecayHalfLife o PriorityUsageResetPeriod según se establece en slurm.conf. Cuando se alcanza este límite, todos los trabajos asociados en ejecución serán terminados y todos los trabajos futuros enviados con asociaciones en el grupo se retrasarán hasta que puedan ejecutarse dentro del límite.

MaxJobs=<max_jobs>
Número máximo de trabajos en ejecución por usuario en esta asociación. Esto se anula si se establece directamente en un usuario. El valor predeterminado es el límite del clúster. Para borrar un valor existente, establezca un nuevo valor de -1.
MaxJobsAccrue=<max_jobs>
Número máximo de trabajos pendientes que pueden acumular prioridad de antigüedad en un momento dado en esta asociación. Esto se anula si se establece directamente en un usuario. El valor predeterminado es el límite del clúster. Para borrar un valor existente, establezca un nuevo valor de -1.
MaxSubmit=<max_jobs>
MaxSubmitJobs=<max_jobs>
Número máximo de trabajos en estado pendiente o en ejecución en cualquier momento en esta asociación. El valor predeterminado es el límite del clúster. Para borrar un valor existente, establezca un nuevo valor de -1.
MaxTRES=TRES[+|-]=<max_TRES>[,TRES[+|-]=<max_TRES>,...]
MaxTRESPJ=TRES[+|-]=<max_TRES>[,TRES[+|-]=<max_TRES>,...]
MaxTRESPerJob=TRES[+|-]=<max_TRES>[,TRES[+|-]=<max_TRES>,...]
Número máximo de TRES que cada trabajo puede usar en esta asociación. Esto se anula si se establece directamente en un usuario. El valor predeterminado es el límite del clúster.

Para borrar un valor existente, establezca un nuevo valor de -1.

NOTA: Cambiar este valor no tendrá ningún efecto en ningún trabajo en ejecución o pendiente.

Priority
Factor de prioridad de la asociación a ser utilizado por el plugin de prioridad/multifactor. Esto se anula si se establece directamente en un usuario. No está establecido por defecto, lo que indica que no se otorga prioridad adicional. Para borrar un valor existente, establezca un nuevo valor de -1.
QosLevel<operator><lista_separada_por_comas_de_nombres_qos>
Lista de nombres QOS disponibles para los trabajos que se ejecutan en esta asociación. Para obtener una lista de QOS válidos, use 'sacctmgr list qos'. Establecer un QosLevel a '' (dos comillas simples sin nada entre ellas) restaura su configuración predeterminada. =

Agrega el valor <qos> especificado al QosLevel actual. La cuenta tendrá acceso a este QOS y a cualquier otro asignado previamente.
-=
Elimina el valor <qos> especificado del QosLevel actual.

The federation that this cluster should be a member of. A cluster can only be a member of one federation at a time.

Comma-separated list of numeric RPC values.

Display information with previously deleted data. Clusters that are deleted within 24 hours of being created and did not have a job run in the cluster during that time will be removed from the database. Otherwise, the cluster will be marked as deleted and will be viewable with the WithDeleted flag.

Sacctmgr has the capability to archive to a flatfile and or load that data if needed later. The archiving is usually done by the slurmdbd and it is highly recommended you only do it through sacctmgr if you completely understand what you are doing. For slurmdbd options see "man slurmdbd" for more information. Loading data into the database can be done from these files to either view old data or regenerate rolled up data. For information about configuring an archive server see https://slurm.schedmd.com/accounting.html#archive.

archive dump

Dump accounting data to file. Data will not be archived unless the corresponding purge option is included in this command or in slurmdbd.conf. This operation cannot be rolled back once executed. If one of the following options is not specified when sacctmgr is called, the value configured in slurmdbd.conf is used.

Directory=
The directory in which to write the archive file.
Filename=
The name of the archive file.
Purge=
Purge accounting data from the database after it has been written to the archive file. This option should not be used.
StartTime=
The earliest time to include in the archive. Format is YYYY-MM-DD [HH:MM:SS].
EndTime=
The latest time to include in the archive. Format is YYYY-MM-DD [HH:MM:SS].

archive restore

Archivar datos de suspensión. Si no se especifica y PurgeSuspendAfter está configurado, todos los datos de suspensión eliminados se perderán permanentemente.

archive load

Cargar en la base de datos datos previamente archivados. El archivo no se cargará si los registros ya existen en la base de datos, por lo tanto, intentar cargar un archivo más de una vez resultará en un error. Cuando estos datos se archiven y se eliminen de la base de datos nuevamente, si el archivo antiguo todavía está en el directorio ArchiveDir, se creará un nuevo archivo (consulte ArchiveDir en la página man de slurmdbd.conf), por lo que el archivo antiguo no se sobrescribirá y estos archivos tendrán registros duplicados.

Los archivos de un lanzamiento actual o anterior de Slurm pueden ser cargados a través de archive load.

File=
Archivo a cargar en la base de datos. El archivo especificado debe existir en el host slurmdbd, que no es necesariamente la máquina que ejecuta el comando.
Insert=
SQL para insertar directamente en la base de datos. Esto debe usarse con mucha precaución, ya que está escribiendo su sql en la base de datos.

RENDIMIENTO

La ejecución de sacctmgr envía una llamada de procedimiento remoto a slurmdbd. Si suficientes llamadas de sacctmgr u otros comandos cliente de Slurm que envían llamadas de procedimiento remoto al demonio slurmdbd llegan a la vez, puede resultar en una degradación del rendimiento del demonio slurmdbd, lo que posiblemente resulte en una denegación de servicio.

No ejecute sacctmgr u otros comandos cliente de Slurm que envíen llamadas de procedimiento remoto a slurmdbd desde bucles en scripts de shell u otros programas. Asegúrese de que los programas limiten las llamadas a sacctmgr al mínimo necesario para la información que está intentando recopilar.

NOTA: Hay un orden para configurar las asociaciones de contabilidad. Debe definir los clústeres antes de agregar cuentas y debe agregar cuentas antes de poder agregar usuarios.

$ sacctmgr create cluster tux
$ sacctmgr create account name=science fairshare=50
$ sacctmgr create account name=chemistry parent=science fairshare=30
$ sacctmgr create account name=physics parent=science fairshare=20
$ sacctmgr create user name=adam cluster=tux account=physics fairshare=10
$ sacctmgr delete user name=adam cluster=tux account=physics
$ sacctmgr delete user name=adam cluster=tux account=science partition=\"\"
$ sacctmgr delete account name=physics cluster=tux
$ sacctmgr modify user where name=adam cluster=tux account=physics set maxjobs=2 maxwall=30:00
$ sacctmgr add user brian account=chemistry
$ sacctmgr list associations cluster=tux format=Account,Cluster,User,Fairshare tree withd
$ sacctmgr list transactions Action=\"Add Users\" Start=11/03-10:30:00 format=Where,Time
$ sacctmgr dump cluster=tux file=tux_data_file
$ sacctmgr load tux_data_file

La cuenta de un usuario no se puede modificar directamente. Se debe crear una nueva asociación para el usuario con la nueva cuenta. Luego, la asociación con la cuenta antigua puede eliminarse.

Al modificar un objeto, colocar las palabras clave 'set' y el 'where' opcional es crítico para realizar correctamente, a continuación se muestran ejemplos para producir resultados correctos. Como regla general, todo lo que coloque antes de 'set' se utilizará como cuantificador. Si desea colocar un cuantificador después de la palabra clave 'set', debe usar la palabra clave 'where'. Lo siguiente es incorrecto:

$ sacctmgr modify user name=adam set fairshare=10 cluster=tux

Esto producirá un error ya que la línea anterior se lee como modificar usuario adam establecer fairshare=10 y cluster=tux. Cualquiera de los siguientes es correcto:

$ sacctmgr modify user name=adam cluster=tux set fairshare=10
$ sacctmgr modify user name=adam set fairshare=10 where cluster=tux

Al cambiar qos para algo, use solo el operador '=' cuando desee establecer explícitamente el qos a algo. En la mayoría de los casos, querrá usar el operador '+=' o '-=' para agregar o eliminar del qos existente ya en vigor.

Si un usuario ya tiene qos de normal,standby para un padre o fue establecido explícitamente, debe usar qos+=expedite para agregarlo a la lista de esta manera.

Si solo desea agregar el qos expedite solo a una cuenta o clúster específico, puede hacerlo especificándolos en la línea de sacctmgr.

$ sacctmgr modify user name=adam set qos+=expedite

o

$ sacctmgr modify user name=adam acct=this cluster=tux set qos+=expedite

Demos un ejemplo de cómo agregar QOS a las cuentas de usuario. Liste todos los QOS disponibles en el clúster.

$ sacctmgr show qos format=name
       Name
  ---------
     normal
   expedite

Liste todas las asociaciones en el clúster.

$ sacctmgr show assoc format=cluster,account,qos
   Cluster     Account                  QOS
  --------  ---------- --------------------
     zebra        root               normal
     zebra        root               normal
     zebra           g               normal
     zebra          g1               normal

Agregue el QOS expedite a la cuenta G1 y muestre el resultado. Usando el operador += el QOS se agregará junto con el QOS existente a esta cuenta.

$ sacctmgr modify account name=g1 set qos+=expedite
$ sacctmgr show assoc format=cluster,account,qos
   Cluster     Account                  QOS
  --------  ---------- --------------------
     zebra        root               normal
     zebra        root               normal
     zebra           g               normal
