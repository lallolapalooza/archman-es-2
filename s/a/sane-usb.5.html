sane-usb(5) Acceso Sencillo a Escáneres SANE sane-usb(5)

NOMBRE

sane-usb - consejos de configuración USB para SANE

DESCRIPCIÓN

Esta página del manual contiene información sobre cómo acceder a escáneres con interfaz USB. Se centra en dos temas principales: conseguir que el escáner sea detectado por el kernel del sistema operativo y su uso con SANE.

Esta página se aplica a la mayoría de los backends y escáneres USB, ya que utilizan la interfaz genérica sanei_usb. Sin embargo, hay una excepción: los escáneres USB compatibles con el backend sane-microtek2(5) necesitan un driver de kernel USB especial.

ARRANQUE RÁPIDO

Esta es una sección corta tipo HOWTO. Para obtener todos los detalles, lea las siguientes secciones. El objetivo de esta sección es conseguir que el escáner sea detectado por sane-find-scanner(1).

Ejecute sane-find-scanner(1). Si lista su escáner con los identificadores de proveedor y producto correctos, habrá terminado. Consulte la sección PROBLEMAS DE SANE para obtener más detalles.

¿sane-find-scanner(1) no lista su escáner? ¿Funciona como root? Si es así, hay un problema de permisos. Consulte la sección LIBUSB para obtener más detalles.

¿Nada se encuentra, ni siquiera como root? Compruebe que su kernel soporta USB y que libusb está instalado (consulte la sección LIBUSB).

MÉTODOS DE ACCESO USB

Para acceder a dispositivos USB, se utiliza la biblioteca USB libusb. Solía existir otro método para acceder a dispositivos USB: el driver de escáner del kernel. El método del driver de escáner del kernel está obsoleto y ya no debería utilizarse. Puede ser eliminado de SANE en cualquier momento. En Linux, el driver de escáner del kernel se eliminó en la serie de kernels 2.6.*. Solo el acceso a través de libusb se documenta en esta página del manual.

LIBUSB

SANE solo puede utilizar libusb 0.1.6 o posterior. Debe estar instalado en tiempo de compilación. Las distribuciones Linux modernas y otros sistemas operativos vienen con libusb.

Libusb solo puede acceder a su escáner si no está reclamado por el driver de escáner del kernel. Si desea utilizar libusb, descargue el driver del kernel (por ejemplo, rmmod scanner en Linux) o desactive el driver al compilar un nuevo kernel. Para Linux, su kernel necesita soporte para el sistema de archivos USB (usbfs). Para kernels anteriores a 2.4.19, reemplace "usbfs" con "usbdevfs" porque el nombre ha cambiado. Este sistema de archivos debe estar montado. Esto se hace automáticamente al arrancar si /etc/fstab contiene una línea como esta:

none /proc/bus/usb usbfs defaults 0 0

Los permisos para los archivos de dispositivo utilizados por libusb deben ajustarse para el acceso de usuarios. De lo contrario, solo root podrá usar los dispositivos SANE. Para Linux, los dispositivos se encuentran en /proc/bus/usb/ o en /dev/bus/usb, si utiliza udev. Hay directorios con nombres como "001" (el nombre del bus) que contienen archivos "001", "002", etc. (los archivos de dispositivo). Los archivos de dispositivo correctos se pueden averiguar ejecutando: scanimage -L: como root. Sin embargo, la configuración de permisos con chmod(1) no es permanente. Se restablecerán después de reiniciar o reconectar el escáner.

Normalmente se utilizan las utilidades udev(7) o, para distribuciones más antiguas, las utilidades hotplug, que admiten la configuración dinámica de permisos de acceso. SANE incluye scripts de udev y hotplug en los directorios tools/udev y tools/hotplug. Se pueden utilizar para configurar permisos; consulte /usr/share/doc/sane/README.linux, tools/README y el README en el directorio tools/hotplug para obtener más detalles.

Para los BSDs, los archivos de dispositivo utilizados por libusb se denominan /dev/ugen*. Utilice chmod(1) para aplicar los permisos apropiados.

PROBLEMAS DE SANE

Esta sección asume que su escáner es detectado por sane-find-scanner(1). No tiene sentido continuar si este no es el caso. Si bien sane-find-scanner(1) puede detectar cualquier escáner USB, el escaneo real solo funcionará si el escáner es compatible con un backend SANE. La información sobre el nivel de soporte se puede encontrar en la página web de SANE (http://www.sane-project.org/) y en las páginas del manual de los backends individuales.

La mayoría de los backends pueden detectar escáneres USB automáticamente utilizando líneas de configuración de "usb". Este método permite identificar escáneres por los números de proveedor y producto USB. La sintaxis para especificar un escáner de esta manera es:

usb PROVEEDOR PRODUCTO

donde PROVEEDOR es el ID del proveedor USB y PRODUCTO es el ID del producto USB del escáner. Ambos IDs son números enteros no negativos en formato decimal o hexadecimal. Los valores correctos para estos campos se pueden encontrar ejecutando sane-find-scanner(1), buscando en el syslog (por ejemplo, /var/log/messages) o, en Linux, emitiendo el comando cat /proc/bus/usb/devices. Este es un ejemplo de una línea de archivo de configuración:

usb 0x055f 0x0006

tendría el efecto de que todos los dispositivos USB del sistema con un ID de proveedor de 0x55f y un ID de producto de 0x0006 serían consultados y reconocidos por el backend.

Si su escáner no se detecta automáticamente, puede ser necesario editar el archivo de configuración del backend apropiado antes de usar SANE por primera vez. Para una descripción detallada del archivo de configuración de cada backend, consulte la página del manual del backend correspondiente (por ejemplo, sane-mustek_usb(5) para escáneres USB Mustek).

NO cree un enlace simbólico de /dev/scanner al dispositivo USB porque este enlace lo utilizan los backends SCSI. El escáner puede confundirse si recibe comandos SCSI.

AMBIENTE

SANE_DEBUG_SANEI_USB
Si la biblioteca se compiló con soporte de depuración habilitado, esta variable de entorno controla el nivel de depuración para el subsistema de E/S USB. Por ejemplo, un valor de 128 solicita que se imprima toda la salida de depuración. Niveles más bajos reducen la verbosidad. Los valores mayores que 4 habilitan la depuración de libusb (si está disponible). Ejemplo: export SANE_DEBUG_SANEI_USB=4.
SANE_USB_WORKAROUND
Si su escáner no funciona cuando está conectado a un puerto USB3, intente establecer la variable de entorno SANE_USB_WORKAROUND a 1. Esto puede solucionar problemas que ocurren con versiones de kernel específicas. Ejemplo: export SANE_USB_WORKAROUND=1.
SANE_XEROX_USB_HALT_WORKAROUND
Si su escáner Xerox / Samsung / HP antiguo (anterior a 2010) solo se detecta una vez y los usos posteriores requieren volver a conectar el cable, intente establecer la variable de entorno SANE_XEROX_USB_HALT_WORKAROUND a 1. Esto puede solucionar problemas que ocurren con controladores USB específicos. Ejemplo: export SANE_XEROX_USB_HALT_WORKAROUND=1.
