NOMBRE

sane-coolscan3 - Backend SANE para escáneres de película Nikon Coolscan

DESCRIPCIÓN

La biblioteca sane-coolscan3 implementa un backend SANE (Scanner Access Now Easy) que proporciona acceso a los escáneres de película Nikon Coolscan. Algunas funciones de este backend deben considerarse software de calidad beta. La mayoría de las funciones han sido estables durante mucho tiempo, pero, por supuesto, el nuevo desarrollo no puede y no funcionará correctamente desde el primer día.

Actualmente, se sabe que los siguientes escáneres funcionan con este backend:

Modelo:                       Tipo de Conexión
---------------------------  -------------------
LS-30 (Coolscan III)         SCSI
LS-40 ED (Coolscan IV)       USB
LS-50 ED (Coolscan V)        USB
LS-2000                      SCSI
LS-4000 ED                   IEEE 1394
LS-8000 ED                   IEEE 1394

Por favor, envíe un correo electrónico a sane-devel@alioth-lists.debian.net para informar de éxitos o fracasos.

OPCIONES

Las opciones que el backend soporta pueden ser seleccionadas a través de opciones de línea de comandos a programas como scanimage(1) o a través de elementos GUI en xscanimage(1) o xsane(1).

Las opciones válidas de línea de comandos y su sintaxis se pueden listar usando:

scanimage --help -d coolscan3:<interfaz>:<dispositivo>

donde <interfaz> y <dispositivo> especifican el dispositivo en cuestión, como en el archivo de configuración (ver sección siguiente). El parámetro -d y su argumento pueden omitirse para obtener información sobre el primer escáner identificado. Utilice el comando:

scanimage -L

para listar todos los dispositivos reconocidos por su instalación SANE.

Las opciones deberían estar completamente descritas por la descripción o las indicaciones dadas por el frontend. Aquí hay una descripción de algunas de las opciones más importantes, en la sintaxis con la que deben proporcionarse a scanimage(1):

--frame <n>
Esta opción especifica en qué fotograma operar, si se utiliza un alimentador motorizado de película o un adaptador APS. El número de fotograma <n> varía de 1 al número de fotogramas disponibles, que se detecta cada vez que se inicializa el backend (normalmente cada vez que inicia el frontend).
--subframe <x>
Esta opción desplaza la ventana de escaneo la cantidad especificada (la unidad predeterminada es mm).
--infrared=sí/no
Si se establece en "sí", el escáner leerá el canal infrarrojo, lo que permitirá la eliminación de defectos por software. La imagen infrarroja se lee durante un segundo escaneo, sin que se alteren las opciones. El backend no debe reiniciarse entre los escaneos. Si utiliza scanimage(1), realice un escaneo por lotes con --batch-count=2 para obtener la información IR.
--depth <n>
Aquí <n> puede ser 8 o el número máximo de bits admitido por el escáner (10, 12 o 14). Especifica si el escáner reduce los datos escaneados a 8 bits antes de enviarlos al backend. Si se usan 8 bits, se pierde información y, por lo tanto, calidad de imagen, pero la cantidad de datos es menor en comparación con profundidades mayores. Además, muchos programas de imagen y formatos de imagen no pueden manejar profundidades mayores de 8 bits.
--autofocus
Realiza una operación de enfoque automático. A menos que se especifique lo contrario mediante las otras opciones ( --focus-on-centre y similares), el enfoque se realiza en el centro del área de escaneo seleccionada.
--ae-wb
Realiza un pre-escaneo para calcular automáticamente los valores de exposición y mantener el balance de blancos.
--ae
Realiza un pre-escaneo para calcular automáticamente los valores de exposición. Ajustará cada canal por separado.
--exposure
Multiplica todos los tiempos de exposición por este valor. Esto permite la corrección de la exposición sin modificar el balance de blancos.
--load
Carga la siguiente diapositiva cuando se utiliza el cargador de diapositivas (solo cargador masivo SF-200).
--eject
Expulsa la película o la diapositiva montada cuando se utiliza el cargador de diapositivas.
--reset
Reinicia el escáner. El escáner realizará la misma acción que al encenderse: expulsará la diapositiva (con el cargador masivo SF-200) y se calibrará. Úselo siempre que el escáner se niegue a cargar una diapositiva correctamente, lo que provoca que --eject no funcione.

ARCHIVO DE CONFIGURACIÓN

El archivo de configuración /etc/sane.d/coolscan3.conf especifica el(los) dispositivo(s) que utilizará el backend. Debido a la naturaleza de los tipos de conexión admitidos (SCSI, USB e IEEE 1394), el archivo de configuración predeterminado que se distribuye con SANE debería funcionar sin necesidad de editarlo.

Cada línea en el archivo de configuración es una de las siguientes, donde todas las entradas distinguen entre mayúsculas y minúsculas:

línea en blanco o que comienza con un carácter '#'
Estas líneas se ignoran, por lo que '#' se puede usar para incluir comentarios.
línea que contiene solo la palabra "auto"
Esto indica al backend que busque un escáner escaneando los buses en busca de dispositivos con identificadores conocidos. Esta es la acción predeterminada cuando no hay un archivo de configuración presente.
una línea del tipo <interfaz>:<dispositivo>
Aquí <interfaz> puede ser "scsi" o "usb", y <dispositivo> es el archivo del dispositivo del escáner. Tenga en cuenta que los dispositivos IEEE 1394 son manejados por el módulo SBP-2 del kernel y aparecen para SANE como dispositivos SCSI.

ARCHIVOS

/usr/lib/sane/libsane-coolscan3.a
La biblioteca estática que implementa este backend.
/usr/lib/sane/libsane-coolscan3.so
La biblioteca compartida que implementa este backend (presente en sistemas que admiten carga dinámica).
/etc/sane.d/coolscan3.conf
Archivo de configuración para este backend, se lee cada vez que se inicializa el backend.

ENTORNO

SANE_DEBUG_COOLSCAN3
Si la biblioteca se compiló con soporte de depuración habilitado, esta variable de entorno controla el nivel de depuración para este backend. Por ejemplo, un valor de 128 solicita que se imprima toda la salida de depuración. Niveles más bajos reducen la verbosidad.

ERRORES CONOCIDOS

Actualmente, el protocolo SANE no permite la actualización automática de las opciones cada vez que el hardware cambia. Por lo tanto, el número de opciones para la opción --frame se fijará cuando se inicialice el backend (normalmente cuando el usuario ejecuta el frontend). En particular, si no hay ninguna película en el alimentador automático de películas cuando se inicializa el backend, la opción --frame no aparecerá en absoluto. Además, se recomienda encarecidamente reiniciar el frontend después de cambiar los adaptadores de película.

Los kernels de Linux anteriores a 2.4.19 tenían un parche que truncaba los datos de INQUIRY de los escáneres IEEE 1394 a 36 bytes, descartando información vital sobre el escáner. Por lo tanto, los modelos IEEE 1394 solo funcionan con la versión 2.4.19 o posterior.

Actualmente no se conocen errores reales, por favor informe de cualquier error a la lista de desarrolladores de SANE.
