NOMBRE

sd_bus_set_description, sd_bus_get_description, sd_bus_set_anonymous, sd_bus_is_anonymous, sd_bus_set_trusted, sd_bus_is_trusted, sd_bus_set_allow_interactive_authorization, sd_bus_get_allow_interactive_authorization, sd_bus_get_scope, sd_bus_get_tid, sd_bus_get_unique_name - Establecer o consultar propiedades de un objeto de bus

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_set_description(sd_bus *bus, const char *description);

int sd_bus_get_description(sd_bus *bus, const char **description);

int sd_bus_set_anonymous(sd_bus *bus, int b);

int sd_bus_is_anonymous(sd_bus *bus);

int sd_bus_set_trusted(sd_bus *bus, int b);

int sd_bus_is_trusted(sd_bus *bus);

int sd_bus_set_allow_interactive_authorization(sd_bus *bus, int b);

int sd_bus_get_allow_interactive_authorization(sd_bus *bus);

int sd_bus_get_scope(sd_bus *bus, const char **scope);

int sd_bus_get_tid(sd_bus *bus, pid_t *tid);

int sd_bus_get_unique_name(sd_bus *bus, const char **unique);

DESCRIPCIÓN

sd_bus_set_description() establece la cadena de descripción que se utiliza en el registro a la cadena especificada. La cadena se copia internamente y se libera cuando el objeto de bus se desasigna. El argumento description puede ser NULL, en cuyo caso la descripción se anula. Esta función debe llamarse antes de que el bus se inicie.

sd_bus_get_description() devuelve una cadena de descripción en description. Esta cadena puede haber sido establecida previamente con sd_bus_set_description() o sd_bus_open_with_description(3) o similar. Si no se establece de esta manera, se devolverá una cadena predeterminada como "system" o "user" para los buses del sistema o del usuario, y -ENXIO en caso contrario.

sd_bus_set_anonymous() habilita o deshabilita la "autenticación anónima", es decir, la falta de autenticación, del par del bus. Esta función debe llamarse antes de que el bus se inicie. Consulte la sección Mecanismos de Autenticación de D-Bus[1] de la especificación de D-Bus para obtener detalles.

sd_bus_is_anonymous() devuelve verdadero si la conexión del bus permite la autenticación anónima (en el sentido descrito en el párrafo anterior).

sd_bus_set_trusted() establece el estado de "confiable" en el objeto bus. Si es verdadero, todas las conexiones en el bus son confiables y se concede acceso a todos los métodos privilegiados y no privilegiados. Esta función debe llamarse antes de que el bus se inicie.

sd_bus_is_trusted() devuelve verdadero si la conexión del bus es confiable (en el sentido descrito en el párrafo anterior).

sd_bus_set_allow_interactive_authorization() habilita o deshabilita la autorización interactiva para llamadas a métodos. Si es verdadero, los mensajes se marcan con la bandera ALLOW_INTERACTIVE_AUTHORIZATION especificada por la especificación de D-Bus[2], informando al lado receptor que el llamador está preparado para esperar la autorización interactiva, lo que puede tardar un tiempo considerable en completarse. Si esta bandera está establecida, se le puede solicitar al usuario contraseñas o confirmación a través de polkit[3] o un marco similar.

sd_bus_get_allow_interactive_authorization() devuelve verdadero si se permite la autorización interactiva y falso si no.

sd_bus_get_scope() almacena el alcance del objeto de bus dado en scope. El alcance del bus del sistema es "system". El alcance de un bus de sesión de usuario es "user". Si el objeto de bus dado no es el bus del sistema o el bus de una sesión de usuario, sd_bus_get_scope() devuelve un error.

sd_bus_get_tid() almacena el id. de hilo del kernel del hilo asociado con el objeto de bus dado en tid. Si bus es un objeto de bus predeterminado obtenido al llamar a una de las funciones de la familia sd_bus_default(3), almacena el id. de hilo del hilo en el que se creó el objeto de bus. De lo contrario, si el objeto de bus está adjunto a un bucle de eventos, almacena el id. de hilo del hilo en el que se creó el objeto del bucle de eventos. Si bus no es un objeto de bus predeterminado y no está adjunto a un bucle de eventos, sd_bus_get_tid() devuelve un error.

sd_bus_get_unique_name() almacena el nombre único del objeto de bus en el bus en unique. Consulte La especificación D-Bus[4] para obtener más información sobre los nombres de bus. Tenga en cuenta que el llamador no es propietario de la cadena almacenada en unique y no debe liberarla.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un entero no negativo. En caso de error, devuelven un código de error negativo del tipo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Un argumento es inválido.

-ENOPKG

El bus no se puede resolver.

-EPERM

El bus ya se ha iniciado.

-ECHILD

El bus se creó en un proceso, biblioteca o instancia de módulo diferente.

-ENOMEM

Fallo en la asignación de memoria.

-ENODATA

El objeto de bus pasado a sd_bus_get_scope() no era un bus del sistema ni de sesión de usuario.

Añadido en la versión 246.

-ENXIO

El objeto de bus pasado a sd_bus_get_tid() no era un objeto de bus predeterminado y no está adjunto a un bucle de eventos.

El objeto de bus pasado a sd_bus_get_description() no tenía una description.

Añadido en la versión 246.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y vincular con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

sd_bus_set_description(), sd_bus_get_description(), sd_bus_set_anonymous(), sd_bus_set_trusted(), sd_bus_set_allow_interactive_authorization() y sd_bus_get_allow_interactive_authorization() se añadieron en la versión 240.

sd_bus_is_anonymous(), sd_bus_is_trusted(), sd_bus_get_scope(), sd_bus_get_tid() y sd_bus_get_unique_name() se añadieron en la versión 246.

Las claves de bus se utilizan para identificar de forma única objetos, servicios o interfaces dentro de un bus D-Bus. Las claves de bus para objetos se basan en las rutas de objetos de D-Bus. Las claves de bus para servicios y interfaces se basan en los nombres de bus de D-Bus.

Tenga en cuenta que sd_bus_is_anonymous() no comprueba si la ruta del objeto existe realmente en el bus. Solo comprueba si está en un formato válido para una ruta de objeto anónima.

NOTES

El uso de rutas de objetos anónimas es peligroso. Si un servicio expone rutas de objetos anónimas, puede ser aprovechado por un atacante malintencionado para interactuar con objetos no deseados. Siempre que sea posible, utilice nombres de objetos o rutas de objetos con nombre explícito.

El bus del sistema D-Bus expone varios objetos anónimos importantes, como el servicio de auditoría, el servicio de registro y el servicio de autenticación. El bus de la sesión del usuario D-Bus también expone varios objetos anónimos, como el servicio de registro y el servicio de autenticación.

HISTORY

La función sd_bus_is_anonymous() se añadió en systemd versión 231.
