NOMBRE

sd_journal_query_unique, sd_journal_enumerate_unique, sd_journal_enumerate_available_unique, sd_journal_restart_unique, SD_JOURNAL_FOREACH_UNIQUE - Leer campos de datos únicos del journal

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_query_unique(sd_journal *j, const char *field);

int sd_journal_enumerate_available_unique(sd_journal *j, const void **data, size_t *length);

int sd_journal_enumerate_unique(sd_journal *j, const void **data, size_t *length);

void sd_journal_restart_unique(sd_journal *j);

SD_JOURNAL_FOREACH_UNIQUE(sd_journal *j, const void *data, size_t length);

DESCRIPCIÓN

sd_journal_query_unique() consulta el journal para obtener todos los valores únicos que el campo especificado puede tomar. Toma dos argumentos: el journal a consultar y el nombre del campo a buscar. Los nombres de campo conocidos se enumeran en systemd.journal-fields(7), pero se puede especificar cualquier campo. Los nombres de campo deben especificarse sin un "=" al final. Después de que esta función se haya ejecutado con éxito, los valores de campo se podrán consultar utilizando sd_journal_enumerate_unique() y sd_journal_enumerate_available_unique(). Invocar una de estas llamadas cambiará el nombre del campo que se está consultando y restablecerá el índice de enumeración al primer valor de campo que coincida.

sd_journal_enumerate_unique() se puede utilizar para iterar a través de todos los campos de datos que coinciden con el nombre de campo previamente seleccionado, como se estableció con sd_journal_query_unique(). En cada invocación, se devuelve el siguiente dato de campo coincidente. El orden de los campos de datos devueltos no está definido. Toma tres argumentos: el objeto del journal, más un par de punteros a punteros/variables de tamaño donde se almacenarán el objeto de datos y su tamaño. Los datos devueltos se encuentran en un mapa de memoria de solo lectura y solo son válidos hasta la próxima invocación de sd_journal_enumerate_unique(). Tenga en cuenta que los datos devueltos irán precedidos por el nombre del campo y "=". Tenga en cuenta que esta llamada está sujeta al umbral de tamaño de datos del campo, controlado por sd_journal_set_data_threshold(), y solo se devuelve la parte inicial del campo hasta el umbral. Se devuelve un error para los campos que no se pueden recuperar. Consulte la lista de errores a continuación para obtener detalles.

sd_journal_enumerate_available_unique() es similar a sd_journal_enumerate_unique(), pero omite silenciosamente cualquier campo que pueda ser válido, pero sea demasiado grande o no sea compatible con la implementación actual.

sd_journal_restart_unique() restablece el índice de enumeración de datos al principio de la lista. La próxima invocación de sd_journal_enumerate_unique() devolverá nuevamente el primer dato de campo que coincida con el nombre del campo.

Tenga en cuenta que la macro SD_JOURNAL_FOREACH_UNIQUE() se puede utilizar como un práctico envoltorio alrededor de sd_journal_restart_unique() y sd_journal_enumerate_available_unique().

Tenga en cuenta que estas funciones actualmente no se ven influenciadas por las coincidencias establecidas con sd_journal_add_match(), pero esto podría cambiar en una versión posterior de este software.

Para enumerar todos los nombres de campo actualmente en uso (y, por lo tanto, todos los parámetros de campo adecuados para sd_journal_query_unique()), utilice la llamada sd_journal_enumerate_fields(3).

VALOR DE RETORNO

sd_journal_query_unique() devuelve 0 en caso de éxito o un código de error negativo de estilo errno. sd_journal_enumerate_unique() y sd_journal_query_available_unique() devuelven un entero positivo si se ha leído el siguiente dato de campo, 0 cuando no quedan más campos, o un código de error negativo de estilo errno. sd_journal_restart_unique() no devuelve nada.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Uno de los parámetros requeridos es NULL o inválido.

Añadido en la versión 246.

-ECHILD

El objeto del journal se creó en un proceso, biblioteca o instancia de módulo diferente.

Añadido en la versión 246.

-EADDRNOTAVAIL

El puntero de lectura no está posicionado en una entrada válida; sd_journal_next(3) o una llamada relacionada no se ha llamado al menos una vez.

Añadido en la versión 246.

-ENOENT

La entrada actual no incluye el campo especificado.

Añadido en la versión 246.

-ENOBUFS

Una entrada comprimida es demasiado grande.

Añadido en la versión 246.

-E2BIG

El campo de datos es demasiado grande para la arquitectura de este ordenador (por ejemplo, superior a 4 GB en una arquitectura de 32 bits).

Añadido en la versión 246.

-EPROTONOSUPPORT

El journal está comprimido con un método no compatible o el journal utiliza una característica no compatible.

Añadido en la versión 246.

-EBADMSG

El journal está corrupto (posiblemente solo la entrada que se está iterando).

Añadido en la versión 246.

-EIO

El kernel informó un error de E/S.

Añadido en la versión 246.

NOTAS

Todas las funciones enumeradas aquí son agnósticas a los hilos y solo un hilo puede operar en un objeto determinado en cualquier momento. Diferentes hilos pueden acceder al mismo objeto en diferentes momentos. Se pueden utilizar múltiples objetos independientes desde diferentes hilos en paralelo.

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

EJEMPLOS

Utilice la macro SD_JOURNAL_FOREACH_UNIQUE() para iterar a través de todos los valores que un campo del journal puede tomar (y que son accesibles en la arquitectura dada y no están comprimidos con un mecanismo no compatible). El siguiente ejemplo enumera todos los nombres de unidad a los que se hace referencia en el journal:

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <stdio.h>
#include <systemd/sd-journal.h>
int main(int argc, char *argv[]) {
  sd_journal *j;
  const void *d;
  size_t l;
  int r;
  r = sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);
  if (r < 0) {
    fprintf(stderr, "Failed to open journal: %s\n", strerror(-r));
    return 1;
  }
  r = sd_journal_query_unique(j, "_SYSTEMD_UNIT");
  if (r < 0) {
    fprintf(stderr, "Failed to query journal: %s\n", strerror(-r));
    return 1;
  }
  SD_JOURNAL_FOREACH_UNIQUE(j, d, l)
    printf("%.*s\n", (int) l, (const char*) d);
  sd_journal_close(j);
  return 0;
}

NAME

sd_journal_query_unique — Query for unique values of a journal field

SYNOPSIS

int sd_journal_query_unique(const char *field, const char *value);

DESCRIPTION

The sd_journal_query_unique() function may be used to query the journal for all unique values of a specific field. It is the inverse operation of sd_journal_get_data(), and might be useful to discover what values are available for a certain field, e.g. to provide auto-completion.

The field parameter should be the name of the field to query (e.g. "MESSAGE", "PRIORITY", "COMM").

The value parameter is not used by this function.

This function is a stub and does nothing. It is intended for future use.

RETURN VALUE

This function currently always returns 0.

NOTES

This function is a stub and does nothing. It is intended for future use.

The Journal API is designed to be implemented in userspace and is loaded dynamically by applications that need it. See sd-journal.h for more details.

EXAMPLES

This function currently has no practical use, therefore no examples are provided.

HISTORY

sd_journal_query_unique() was added in version 225.
