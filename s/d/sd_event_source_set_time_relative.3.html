NOMBRE

#include <systemd/sd-event.h>

typedef int (*sd_event_time_handler_t)(sd_event_source *s, uint64_t usec, void *userdata);

int sd_event_add_time(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_add_time_relative(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_source_get_time(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time(sd_event_source *source, uint64_t usec);

int sd_event_source_set_time_relative(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_accuracy(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time_accuracy(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_clock(sd_event_source *source, clockid_t *ret);

DESCRIPCIÓN

sd_event_add_time() añade una nueva fuente de eventos de temporizador a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro clock toma un identificador de reloj, uno de CLOCK_REALTIME, CLOCK_MONOTONIC, CLOCK_BOOTTIME, CLOCK_REALTIME_ALARM, o CLOCK_BOOTTIME_ALARM. Véase timerfd_create(2) para más detalles sobre los diversos tipos de relojes. El parámetro usec especifica la hora más temprana, en microsegundos (&#x03BC;s), relativa al punto de época del reloj, en la que se activará el temporizador. Si se especifica una hora que ya ha pasado (incluido 0), esta fuente de temporizador se "dispara" inmediatamente y está lista para ser despachada. Si el parámetro se especifica como UINT64_MAX, el evento del temporizador nunca se cumplirá, lo que puede usarse como alternativa para deshabilitar explícitamente una fuente de evento de temporizador con sd_event_source_set_enabled(3). El parámetro accuracy especifica un valor de precisión adicional en μs, indicando cuánto puede retrasarse el evento del temporizador. Use 0 para seleccionar la precisión por defecto (250ms). Use 1μs para la máxima precisión. Considere especificar 60000000μs (1 minuto) o más para eventos de larga duración que puedan retrasarse sustancialmente. Elegir valores de precisión más altos permite al sistema agrupar eventos de temporizador de forma más agresiva, mejorando la eficiencia energética.

El handler es una función a llamar cuando el temporizador se cumpla o NULL. El puntero userdata se pasará a la función manejadora, y puede ser elegido libremente por el llamador. El tiempo de activación configurado también se pasa al manejador, incluso si la llamada ocurre realmente un poco más tarde, sujeto al valor de precisión especificado, el tiempo de espera del temporizador del kernel (véase prctl(2)), y latencias de planificación adicionales. Para consultar la hora real en que se llamó al manejador, use sd_event_now(3). El manejador puede devolver un valor negativo para señalar un error (véase más abajo), otros valores de retorno se ignoran. Si handler es NULL, se usará un manejador por defecto que llama a sd_event_exit(3).

Por defecto, el temporizador se cumplirá una vez (SD_EVENT_ONESHOT), pero esto puede cambiarse con sd_event_source_set_enabled(3). Si la función manejadora devuelve un código de error negativo, será deshabilitada después de la invocación, incluso si se solicitó el modo SD_EVENT_ON antes, o provocará que el bucle termine, véase sd_event_source_set_exit_on_failure(3). Tenga en cuenta que un evento de temporizador configurado en SD_EVENT_ON se disparará continuamente a menos que su tiempo configurado se actualice usando sd_event_source_set_time().

sd_event_add_time_relative() es como sd_event_add_time(), pero toma una especificación de tiempo relativo. Es relativo al tiempo actual de la iteración del bucle de eventos, como se devuelve por sd_event_now(3).

Para destruir un objeto de fuente de eventos, use sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se sueltan todas las referencias a ella. Para asegurarse de que una fuente de eventos no se dispare más, incluso si todavía está referenciada, deshabilite la fuente de eventos usando sd_event_source_set_enabled(3) con SD_EVENT_OFF.

Si el segundo parámetro de sd_event_add_time() es NULL, no se devuelve ninguna referencia al objeto de fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando el propio bucle de eventos sea destruido.

Si el parámetro handler de sd_event_add_time() es NULL, y la fuente de eventos se dispara, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a un entero, se pasa como el parámetro de código de salida a sd_event_exit(3).

Use CLOCK_BOOTTIME_ALARM y CLOCK_REALTIME_ALARM para definir fuentes de eventos que puedan despertar al sistema de la suspensión.

Para configurar temporizadores relativos (es decir, relativos al tiempo actual), recupere la hora actual a través de sd_event_now(3), sume el intervalo de tiempo deseado, y use el resultado como el parámetro usec para sd_event_add_time().

Para configurar temporizadores repetitivos (es decir, temporizadores que se activan en intervalos regulares), configure el temporizador normalmente, para la primera invocación. Cada vez que se invoca el manejador de eventos, actualice el tiempo de activación del temporizador con sd_event_source_set_time(3) para la próxima iteración del temporizador, y reactive el temporizador usando sd_event_source_set_enabled(). Para calcular el próximo punto en el tiempo a pasar a sd_event_source_set_time(), use como base el parámetro usec pasado a la llamada de retorno del temporizador, o la marca de tiempo devuelta por sd_event_now(). En el primer caso, los eventos del temporizador serán regulares, mientras que en el segundo caso, la latencia de planificación seguirá acumulándose en el temporizador.

sd_event_source_get_time() recupera el valor de tiempo configurado de una fuente de eventos creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar el tiempo, relativo al punto de época del reloj seleccionado, en μs. El valor devuelto es relativo al punto de época, incluso si la fuente de eventos se creó con un tiempo relativo a través de sd_event_add_time_relative().

sd_event_source_set_time() cambia la hora de una fuente de eventos creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de eventos y un tiempo relativo al punto de época del reloj seleccionado, en μs.

sd_event_source_set_time_relative() es similar a sd_event_source_set_time(), pero toma un tiempo relativo al tiempo actual de la iteración del bucle de eventos, como se devuelve por sd_event_now().

sd_event_source_get_time_accuracy() recupera el valor de precisión configurado de una fuente de eventos creada previamente con sd_event_add_time(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar la precisión. La precisión se especifica en μs.

sd_event_source_set_time_accuracy() cambia la precisión configurada de una fuente de eventos de temporizador

NOMBRE

sd_event_source_set_time_relative, sd_event_source_get_time_relative, sd_event_source_set_time_accuracy, sd_event_source_get_time_accuracy, sd_event_source_set_time_clock, sd_event_source_get_time_clock - Establecer y obtener la configuración de tiempo de una fuente de eventos de tiempo

SINOPSIS

#include <systemd/sd-event.h>
int sd_event_source_set_time_relative(sd_event_source *source, uint64_t usec);
int sd_event_source_get_time_relative(sd_event_source *source, uint64_t *usec);
int sd_event_source_set_time_accuracy(sd_event_source *source, uint64_t usec);
int sd_event_source_get_time_accuracy(sd_event_source *source, uint64_t *usec);
int sd_event_source_set_time_clock(sd_event_source *source, clockid_t clock);
int sd_event_source_get_time_clock(sd_event_source *source, clockid_t *clock);

DESCRIPCIÓN

Estas funciones gestionan la configuración de fuentes de eventos de tiempo (creadas con sd_event_add_time()). Las fuentes de eventos de tiempo son activadas en un momento específico en el futuro.

sd_event_source_set_time_relative() configura la fuente de eventos source para que se active después de usec microsegundos. El tiempo se calcula a partir del momento en que se llama a esta función. El valor máximo permitido para usec es LLONG_MAX.

sd_event_source_get_time_relative() recupera el tiempo relativo configurado de una fuente de eventos de tiempo creada previamente con sd_event_add_time(). Devuelve el tiempo en microsegundos en usec.

sd_event_source_set_time_accuracy() configura la precisión deseada para una fuente de eventos de tiempo. usec debe ser positivo y indica el número de microsegundos que el sistema puede desviarse del tiempo objetivo. Cuanto menor sea el valor, más precisa será la activación, pero también consumirá más energía. Si se pasa 0, se utiliza la precisión por defecto.

sd_event_source_get_time_accuracy() recupera la precisión configurada de una fuente de eventos de tiempo. Devuelve la precisión en microsegundos en usec.

sd_event_source_set_time_clock() configura el reloj a usar para determinar el tiempo de activación de la fuente de eventos. Consulte clock_gettime(2) para obtener una lista de los posibles valores de clock. Por defecto, se utiliza CLOCK_MONOTONIC.

sd_event_source_get_time_clock() recupera el reloj configurado de una fuente de eventos de tiempo. Devuelve el identificador del reloj en clock.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo al estilo errno.

Errores

Los valores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento inválido.

-ESTALE

El bucle de eventos ya ha sido terminado.

-ECHILD

El bucle de eventos se creó en un proceso, biblioteca o instancia de módulo diferente.

-EOPNOTSUPP

La implementación del bucle de eventos no soporta el reloj seleccionado.

-EDOM

La fuente de eventos pasada no es una fuente de eventos de temporizador.

-EOVERFLOW

El tiempo relativo pasado está fuera del rango permitido para los valores de tiempo (es decir, el valor especificado sumado al tiempo actual está fuera del rango del entero sin signo de 64 bits).

Añadido en la versión 247.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para su uso en múltiples hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar las llamadas a setenv() solo en una fase temprana del programa cuando no se hayan iniciado otros hilos.
