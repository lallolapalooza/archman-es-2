sd_bus_message_open_container(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_MESSAGE_OPEN_CONTAINER(3) sd_bus_message_open_container SD_BUS_MESSAGE_OPEN_CONTAINER(3)

NOMBRE

sd_bus_message_open_container, sd_bus_message_close_container, sd_bus_message_enter_container, sd_bus_message_exit_container - Crear y moverse entre contenedores en mensajes D-Bus

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_open_container(sd_bus_message *m, char type, const char *contents);

int sd_bus_message_close_container(sd_bus_message *m);

int sd_bus_message_enter_container(sd_bus_message *m, char type, const char *contents);

int sd_bus_message_exit_container(sd_bus_message *m);

DESCRIPCIÓN

sd_bus_message_open_container() añade un nuevo contenedor al mensaje m. Después de abrir un nuevo contenedor, puede ser llenado con contenido usando sd_bus_message_append(3) y funciones similares. Los contenedores se comportan como una pila. Para anidar contenedores dentro de otros, llame a sd_bus_message_open_container() múltiples veces sin llamar a sd_bus_message_close_container() entre ellas. Cada contenedor se anidará dentro del contenedor anterior. type representa el tipo de contenedor y debe ser uno de "r", "a", "v" o "e" como se describe en sd_bus_message_append(3). En lugar de literales, también se pueden usar las constantes correspondientes SD_BUS_TYPE_STRUCT, SD_BUS_TYPE_ARRAY, SD_BUS_TYPE_VARIANT o SD_BUS_TYPE_DICT_ENTRY. contents describe el tipo de los elementos del contenedor y debe ser una cadena de tipo D-Bus siguiendo las reglas descritas en sd_bus_message_append(3).

sd_bus_message_close_container() cierra el último contenedor abierto con sd_bus_message_open_container(). En caso de éxito, el puntero de escritura del mensaje m se posiciona después del contenedor cerrado en su contenedor padre o en m mismo si no hay contenedor padre.

sd_bus_message_enter_container() entra en el siguiente contenedor del mensaje m para leerlo. Se comporta de forma muy similar a sd_bus_message_open_container(). Entrar en un contenedor permite leer su contenido con sd_bus_message_read(3) y funciones similares. type y contents son los mismos que en sd_bus_message_open_container().

sd_bus_message_exit_container() sale del ámbito del último contenedor entrado con sd_bus_message_enter_container(). Se comporta de forma muy similar a sd_bus_message_close_container(). Tenga en cuenta que sd_bus_message_exit_container() solo puede llamarse después de iterar por todos los miembros del contenedor, es decir, leyéndolos o saltándolos. Use sd_bus_message_skip(3) para saltarse campos de un contenedor y así poder salir del contenedor con sd_bus_message_exit_container() sin leer todos los miembros.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un entero no negativo. sd_bus_message_open_container() y sd_bus_message_close_container() devuelven 0. sd_bus_message_enter_container() devuelve 1 si abrió con éxito un nuevo contenedor, y 0 si no fue posible porque se alcanzó el final del contenedor abierto actual o del mensaje. sd_bus_message_exit_container() devuelve 1 en caso de éxito. En caso de fallo, todas estas funciones devuelven un código de error negativo de estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

m o contents son NULL o type es inválido.

Añadido en la versión 246.

-EBADMSG

El mensaje m tiene una estructura inválida.

Añadido en la versión 254.

-ENXIO

El mensaje m no tiene un contenedor del tipo type en la posición actual, o el contenido no coincide con contents.

Añadido en la versión 254.

-EPERM

El mensaje m ya está sellado.

Añadido en la versión 246.

-ESTALE

El mensaje m está en un estado inválido.

Añadido en la versión 246.

-ENOMEM

Fallo en la asignación de memoria.

Añadido en la versión 246.

-EBUSY

Se llamó a sd_bus_message_exit_container() pero quedan miembros no leídos en el contenedor.

Añadido en la versión 247.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar contra y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que está declarado como no seguro para subprocesos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer las llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

EJEMPLOS

Ejemplo 1. Añadir un array de cadenas a un mensaje

/* SPDX-License-Identifier: MIT-0 */
#include <systemd/sd-bus.h>
int append_strings_to_message(sd_bus_message *m, const char *const *arr) {
  const char *s;
  int r;
  r = sd_bus_message_open_container(m, 'a', "s");
  if (r < 0)
    return r;
  for (s = *arr; *s; s++) {
    r = sd_bus_message_append(m, "s", s);
    if (r < 0)
      return r;
  }
  return sd_bus_message_close_container(m);
}

Ejemplo 2. Leer un array de cadenas de un mensaje

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <systemd/sd-bus.h>
int read_strings_from_message(sd_bus_message *m) {
  int r;
  r = sd_bus_message_enter_container(m, 'a', "s");
  if (r < 0)
    return r;
  for (;;) {
    const char *s;
    r = sd_bus_message_read(m, "s", &s);
    if (r < 0)
      return r;
    if (r == 0)
      break;
    printf("%s\n", s);
  }
  return sd_bus_message_exit_container(m);
}
