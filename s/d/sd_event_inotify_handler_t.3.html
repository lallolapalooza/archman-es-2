NOMBRE

sd_event_add_inotify, sd_event_add_inotify_fd, sd_event_source_get_inotify_mask, sd_event_source_get_inotify_path, sd_event_inotify_handler_t - Añadir una fuente de eventos de inodo de sistema de archivos "inotify" a un bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_inotify_handler_t)(sd_event_source *s, const struct inotify_event *event, void *userdata);

int sd_event_add_inotify(sd_event *event, sd_event_source **source, const char *path, uint32_t mask, sd_event_inotify_handler_t handler, void *userdata);

int sd_event_add_inotify_fd(sd_event *event, sd_event_source **source, int fd, uint32_t mask, sd_event_inotify_handler_t handler, void *userdata);

int sd_event_source_get_inotify_mask(sd_event_source *source, uint32_t *ret);

int sd_event_source_get_inotify_path(sd_event_source *source, const char **ret);

DESCRIPCIÓN

sd_event_add_inotify() añade una nueva fuente de eventos de inodo de sistema de archivos inotify(7) a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro path especifica la ruta del inodo del sistema de archivos a vigilar. El parámetro mask especifica qué tipos de eventos de inodo vigilar específicamente. Debe contener una combinación OR de banderas como IN_ACCESS, IN_ATTRIB, IN_CLOSE_WRITE, etc. Consulte inotify(7) para más información.

El parámetro handler debe referenciar una función a llamar cuando el inodo cambie o NULL. La función manejadora recibirá el puntero userdata, que puede ser elegido libremente por el llamador. El manejador también recibe un puntero a una estructura `struct inotify_event` que contiene información sobre el evento del inodo. El manejador puede devolver un valor negativo para indicar un error (ver abajo), otros valores de retorno se ignoran. Si handler es NULL, se utilizará un manejador por defecto que llama a sd_event_exit(3).

sd_event_add_inotify_fd() es idéntico a sd_event_add_inotify(), excepto que toma un descriptor de archivo para un inodo (posiblemente uno de tipo O_PATH, pero cualquiera otro también servirá) en lugar de una ruta en el sistema de archivos.

Si se instalan múltiples fuentes de eventos para el mismo inodo, el descriptor de vigilancia inotify subyacente se comparte automáticamente. El parámetro `mask` puede contener cualquier bandera definida por la API de inotify, con la excepción de IN_MASK_ADD.

El manejador se habilita continuamente (SD_EVENT_ON), pero esto puede cambiarse con sd_event_source_set_enabled(3). Alternativamente, la bandera de máscara IN_ONESHOT puede usarse para solicitar el modo SD_EVENT_ONESHOT. Si la función manejadora devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si el modo SD_EVENT_ON se solicitó anteriormente.

Como limitación especial, la prioridad de las fuentes de eventos inotify solo puede modificarse (ver sd_event_source_set_priority(3)) en el intervalo entre la creación del objeto de la fuente de eventos con sd_event_add_inotify() y el inicio de la siguiente iteración del bucle de eventos. Los intentos de cambiar la prioridad más tarde serán rechazados. Considere liberar y asignar una nueva fuente de eventos inotify para cambiar la prioridad en ese momento.

Para destruir un objeto de fuente de eventos, use sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se sueltan todas las referencias a ella. Para asegurarse de que una fuente de eventos no se active más, incluso cuando todavía hay una referencia a ella, considere deshabilitarla con sd_event_source_set_enabled(3).

Si el segundo parámetro de sd_event_add_inotify() se pasa como NULL, no se devuelve ninguna referencia al objeto de la fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando el propio bucle de eventos se destruya.

Si el parámetro handler de sd_event_add_inotify() es NULL, y la fuente de eventos se activa, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a un entero, se pasa como el parámetro de código de salida a sd_event_exit(3).

sd_event_source_get_inotify_mask() recupera la máscara de vigilancia inotify configurada de una fuente de eventos creada previamente con sd_event_add_inotify(). Toma el objeto de la fuente de eventos como parámetro source y un puntero a una variable de tipo uint32_t para devolver la máscara.

sd_event_source_get_inotify_path() recupera la ruta de destino de la vigilancia inotify configurada de una fuente de eventos creada previamente con sd_event_add_inotify(). Toma el objeto de la fuente de eventos como parámetro source y un puntero a una variable de tipo const char ** para devolver la ruta. El llamador no debe liberar la ruta devuelta.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de fallo, devuelven un código de error negativo al estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento inválido. Esto incluye especificar una máscara con IN_MASK_ADD establecido.

-ESTALE

Devuelto por sd_event_source_add_inotify() o sd_event_source_add_inotify_fd() cuando el bucle de eventos ya está terminado. Devuelto por sd_event_source_get_inotify_path() cuando no hay datos de inodo activos asignados a la fuente de eventos, por ejemplo, cuando la fuente de eventos está deshabilitada.

-ECHILD

El bucle de eventos se creó en un proceso, biblioteca o instancia de módulo diferente.

-EDOM

La fuente de eventos pasada no es una fuente de eventos de proceso inotify.

-EBADF

El descriptor de archivo pasado no es válido.

-ENOSYS

Se llamó a sd_event_add_inotify_fd() o sd_event_source_get_inotify_path() sin montar /proc/.

EJEMPLOS

Ejemplo 1. Un programa simple que usa inotify para monitorear uno o dos directorios

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <string.h>
#include <sys/inotify.h>
#include <systemd/sd-event.h>
#define _cleanup_(f) __attribute__((cleanup(f)))
static int inotify_handler(sd_event_source *source,
                           const struct inotify_event *event,
                           void *userdata) {
  const char *desc = NULL;
  sd_event_source_get_description(source, &desc);
  if (event->mask & IN_Q_OVERFLOW)
    printf("inotify-handler <%s>: overflow\n", desc);
  else if (event->mask & IN_CREATE)
    printf("inotify-handler <%s>: create on %s\n", desc, event->name);
  else if (event->mask & IN_DELETE)
    printf("inotify-handler <%s>: delete on %s\n", desc, event->name);
  else if (event->mask & IN_MOVED_TO)
    printf("inotify-handler <%s>: moved-to on %s\n", desc, event->name);
  /* Terminate the program if an "exit" file appears */
  if ((event->mask & (IN_CREATE|IN_MOVED_TO)) &&
      strcmp(event->name, "exit") == 0)
    sd_event_exit(sd_event_source_get_event(source), 0);
  return 1;
}
int main(int argc, char **argv) {
  _cleanup_(sd_event_unrefp) sd_event *event = NULL;
  _cleanup_(sd_event_source_unrefp) sd_event_source *source1 = NULL, *source2 = NULL;
  const char *path1 = argc > 1 ? argv[1] : "/tmp";
  const char *path2 = argc > 2 ? argv[2] : "/var";
  int r;
  /* Create a new event loop */
  r = sd_event_new(&event);
  if (r < 0) {
    fprintf(stderr, "Failed to create event loop: %s\n", strerror(-r));
    goto finish;
  }
  /* Add the first directory to watch */
  r = sd_event_add_inotify(event, &source1, path1,
                           IN_CREATE|IN_DELETE|IN_MOVED_TO,
                           inotify_handler,
                           "first directory");
  if (r < 0) {
    fprintf(stderr, "Failed to add inotify source for %s: %s\n", path1, strerror(-r));
    goto finish;
  }
  sd_event_source_set_description(source1, path1);
  /* Add the second directory to watch */
  r = sd_event_add_inotify(event, &source2, path2,
                           IN_CREATE|IN_DELETE|IN_MOVED_TO,
                           inotify_handler,
                           "second directory");
  if (r < 0) {
    fprintf(stderr, "Failed to add inotify source for %s: %s\n", path2, strerror(-r));
    goto finish;
  }
  sd_event_source_set_description(source2, path2);
  /* Run the event loop */
  printf("Monitoring %s and %s. Create/delete/move files to see events. Create file named 'exit' to quit.\n", path1, path2);
  r = sd_event_loop(event);
  printf("Event loop finished with return code %d.\n", r);
finish:
  return r < 0 ? EXIT_FAILURE : EXIT_SUCCESS;
}
