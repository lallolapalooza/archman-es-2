SD_JOURNAL_GET_DATA(3) sd_journal_get_data SD_JOURNAL_GET_DATA(3)

NOMBRE

sd_journal_get_data, sd_journal_enumerate_data, sd_journal_enumerate_available_data, sd_journal_restart_data, SD_JOURNAL_FOREACH_DATA, sd_journal_set_data_threshold, sd_journal_get_data_threshold - Leer campos de datos de la entrada actual del journal

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_get_data(sd_journal *j, const char *field, const void **data, size_t *length);

int sd_journal_enumerate_data(sd_journal *j, const void **data, size_t *length);

int sd_journal_enumerate_available_data(sd_journal *j, const void **data, size_t *length);

void sd_journal_restart_data(sd_journal *j);

SD_JOURNAL_FOREACH_DATA(sd_journal *j, const void *data, size_t length);

int sd_journal_set_data_threshold(sd_journal *j, size_t sz);

int sd_journal_get_data_threshold(sd_journal *j, size_t *sz);

DESCRIPCIÓN

sd_journal_get_data() obtiene el objeto de datos asociado a un campo específico de la entrada actual del journal. Toma cuatro argumentos: el objeto de contexto del journal, una cadena con el nombre del campo a solicitar, más un par de punteros a punteros/variables de tamaño donde se almacenarán el objeto de datos y su tamaño. El nombre del campo debe ser un nombre de campo de entrada. Los nombres de campo conocidos se enumeran en systemd.journal-fields(7), pero se puede especificar cualquier campo. Los datos devueltos están en un mapa de memoria de solo lectura y solo son válidos hasta la próxima invocación de sd_journal_get_data(), sd_journal_enumerate_data(), sd_journal_enumerate_available_data(), o cuando se altera el puntero de lectura. Tenga en cuenta que los datos devueltos irán precedidos del nombre del campo y "=". Tenga en cuenta también que, por defecto, los campos de datos mayores de 64K pueden ser truncados a 64K. Este umbral puede ser cambiado y desactivado con sd_journal_set_data_threshold() (ver abajo).

sd_journal_enumerate_data() puede ser utilizada para iterar a través de todos los campos de la entrada actual. En cada invocación se devuelven los datos del siguiente campo. El orden de estos campos no está definido. Los datos devueltos están en el mismo formato que con sd_journal_get_data() y también siguen la misma semántica de ciclo de vida.

sd_journal_enumerate_available_data() es similar a sd_journal_enumerate_data(), pero omite silenciosamente cualquier campo que pueda ser válido, pero sea demasiado grande o no sea compatible con la implementación actual.

sd_journal_restart_data() restablece el índice de enumeración de datos al principio de la entrada. La próxima invocación de sd_journal_enumerate_data() devolverá nuevamente el primer campo de la entrada.

Tenga en cuenta que la macro SD_JOURNAL_FOREACH_DATA() puede ser utilizada como un práctico envoltorio alrededor de sd_journal_restart_data() y sd_journal_enumerate_available_data().

Tenga en cuenta que estas funciones no funcionarán antes de que sd_journal_next(3) (o una llamada relacionada) se haya llamado al menos una vez, para posicionar el puntero de lectura en una entrada válida.

sd_journal_set_data_threshold() puede ser utilizada para cambiar el umbral del tamaño del campo de datos para los datos devueltos por sd_journal_get_data(), sd_journal_enumerate_data() y sd_journal_enumerate_unique(). Este umbral es solo una indicación: indica que el programa cliente solo está interesado en las partes iniciales de los campos de datos, hasta el umbral de tamaño; pero la biblioteca puede seguir devolviendo objetos de datos más grandes. Esto significa que las aplicaciones no deben depender exclusivamente de esta configuración para limitar el tamaño de los campos de datos devueltos, sino que también deben aplicar un límite de tamaño explícito a los datos devueltos. Este umbral predeterminado es de 64K. Para recuperar los campos de datos completos, este umbral debe desactivarse estableciéndolo en 0, de modo que la biblioteca siempre devuelva los objetos de datos completos. Se recomienda establecer este umbral lo más bajo posible, ya que esto libera a la biblioteca de tener que descomprimir objetos de datos grandes comprimidos en su totalidad.

sd_journal_get_data_threshold() devuelve el umbral del tamaño del campo de datos configurado actualmente.

VALOR DE RETORNO

sd_journal_get_data() devuelve 0 en caso de éxito o un código de error negativo al estilo errno. sd_journal_enumerate_data() y sd_journal_enumerate_available_data() devuelven un entero positivo si el siguiente campo ha sido leído, 0 cuando no quedan más campos, o un código de error negativo al estilo errno. sd_journal_restart_data() no devuelve nada. sd_journal_set_data_threshold() y sd_journal_get_threshold() devuelven 0 en caso de éxito o un código de error negativo al estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Uno de los parámetros requeridos es NULL o inválido.

Añadido en la versión 246.

-ECHILD

El objeto del journal fue creado en un proceso, biblioteca o instancia de módulo diferente.

Añadido en la versión 246.

-EADDRNOTAVAIL

El puntero de lectura no está posicionado en una entrada válida; sd_journal_next(3) o una llamada relacionada no se ha realizado al menos una vez.

Añadido en la versión 246.

-ENOENT

La entrada actual no incluye el campo especificado.

Añadido en la versión 246.

-ENOMEM

Fallo en la asignación de memoria.

Añadido en la versión 246.

-ENOBUFS

Una entrada comprimida es demasiado grande.

Añadido en la versión 246.

-E2BIG

El campo de datos es demasiado grande para esta arquitectura de computadora (por ejemplo, superior a 4 GB en una arquitectura de 32 bits).

Añadido en la versión 246.

-EPROTONOSUPPORT

El journal está comprimido con un método no soportado o el journal utiliza una característica no soportada.

Añadido en la versión 246.

-EBADMSG

El journal está corrupto (posiblemente solo la entrada que se está iterando).

Añadido en la versión 246.

-EIO

El kernel reportó un error de E/S.

Añadido en la versión 246.

NOTAS

Todas las funciones listadas aquí son independientes de hilos y solo un hilo puede operar en un objeto dado en un momento dado. Diferentes hilos pueden acceder al mismo objeto en diferentes momentos. Múltiples objetos independientes pueden ser utilizados desde diferentes hilos en paralelo.

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

EJEMPLOS

Ver sd_journal_next(3) para un ejemplo completo de cómo usar sd_journal_get_data().

Use la macro SD_JOURNAL_FOREACH_DATA() para iterar a través de todos los campos de la entrada actual del journal:

...
int print_fields(sd_journal *j) {
  const void *data;
  size_t length;
  SD_JOURNAL_FOREACH_DATA(j, data, length)
    printf("%.*s\n", (int) length, data);
}
...

HISTORIA

sd_journal_get_data(), sd_journal_enumerate_data(), sd_journal_restart_data(), y SD_JOURNAL_FOREACH_DATA() se añadieron en la versión 187.

sd_journal_set_data_threshold() y sd_journal_get_data_threshold() se añadieron en la versión 196.

sd_journal_enumerate_available_data() se añadió en la versión 246.
