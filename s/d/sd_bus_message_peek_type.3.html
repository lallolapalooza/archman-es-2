sd_bus_message_peek_type(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_MESSAGE_READ(3) sd_bus_message_read SD_BUS_MESSAGE_READ(3)

NOMBRE

sd_bus_message_read, sd_bus_message_readv, sd_bus_message_peek_type - Leer una secuencia de valores de un mensaje

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_read(sd_bus_message *m, const char *types, ...);

int sd_bus_message_readv(sd_bus_message *m, const char *types, va_list ap);

int sd_bus_message_peek_type(sd_bus_message *m, char *type, const char **contents);

DESCRIPCIÓN

sd_bus_message_read() lee una secuencia de campos del objeto de mensaje D-Bus m y avanza la posición de lectura en el mensaje. La cadena de tipos types describe los tipos de elementos esperados en el mensaje y los argumentos de campo que siguen. La cadena de tipos puede ser NULL o vacía, en cuyo caso no se lee nada.

La cadena de tipos se compone de los elementos descritos en sd_bus_message_append(3), es decir, tipos básicos y contenedores. Debe contener cero o más "tipos completos" individuales. La cadena de tipos está terminada en NUL.

Por cada tipo especificado en la cadena de tipos, se debe especificar uno o más argumentos después del parámetro types, en el mismo orden. Los argumentos deben ser punteros a los tipos apropiados (un puntero a int8_t para una "y" en la cadena de tipos, un puntero a int32_t para una "i", un puntero a const char* para una "s", ...) que se establecen basándose en los valores del mensaje. Como excepción, en el caso de tipos de array y variantes, el primer argumento es un argumento de "entrada" que especifica además cómo se debe leer el mensaje. Consulte la tabla a continuación para obtener una lista completa de los argumentos permitidos y sus tipos. Tenga en cuenta que, si el tipo básico es un puntero (por ejemplo, const char * en el caso de una cadena), el argumento es un puntero a un puntero, y también el valor del puntero que se escribe solo se presta y el contenido debe copiarse si se va a utilizar después del final del tiempo de vida del mensaje. Si el tipo es "h" (descriptor de archivo UNIX), el descriptor no se duplica con esta llamada y el descriptor devuelto permanece en posesión del objeto del mensaje, y debe ser duplicado por el llamador para mantener una referencia abierta a él después de que el objeto del mensaje sea liberado.

Cada argumento también puede ser NULL, en cuyo caso el valor se lee y se ignora.

Si los objetos de los tipos especificados no están presentes en la posición actual del mensaje, se devuelve un error.

sd_bus_message_readv() es equivalente a sd_bus_message_read(), excepto que se llama con un "va_list" en lugar de un número variable de argumentos. Esta función no llama a la macro va_end(). Dado que invoca la macro va_arg(), el valor de ap es indefinido después de la llamada.

sd_bus_message_peek_type() determina el tipo del siguiente elemento en m que será leído por sd_bus_message_read() o funciones similares. Con éxito, el tipo se almacena en type, si no es NULL. Si el tipo es un tipo contenedor, el tipo de sus elementos se almacena en contents, si no es NULL. Si esta función determina exitosamente el tipo del siguiente elemento en m, devuelve un entero positivo. Si no hay más elementos para leer, devuelve cero.

VALOR DE RETORNO

Con éxito, estas funciones devuelven un entero no negativo. En caso de error, devuelven un código de error negativo de estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

La cadena de tipos especificada es inválida o el parámetro del mensaje es NULL.

-ENXIO

El mensaje no contiene el tipo especificado en la posición actual.

-EBADMSG

El mensaje no se puede analizar.

-EBUSY

Al leer de un contenedor, este error se devolverá si quedan elementos sin leer en el contenedor.

Añadido en la versión 251.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un subproceso paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros subprocesos.

EJEMPLOS

Leer un tipo básico único (un entero de 64 bits):

sd_bus_message *m;
int64_t x;
sd_bus_message_read(m, "x", &x);

Leer un valor booleano:

sd_bus_message *m;
int x; /* No usar el tipo "bool" de C99 aquí, típicamente es más pequeño
          en memoria y podría causar corrupción de memoria */
sd_bus_message_read(m, "b", &x);

Leer todos los tipos de enteros:

uint8_t y;
int16_t n;
uint16_t q;
int32_t i;
uint32_t u;
int64_t x;
uint64_t t;
double d;
sd_bus_message_read(m, "ynqiuxtd", &y, &n, &q, &i, &u, &x, &t, &d);

Leer una estructura compuesta por una cadena y una ruta D-Bus:

const char *s, *p;
sd_bus_message_read(m, "(so)", &s, &p);

Leer una variante, con el tipo real "gt" (firma, entero sin signo):

const char *s;
uint64_t *v;
sd_bus_message_read(m, "v", "gt", &s, &v);

Leer un diccionario que contiene tres pares de tipo {entero=>cadena}:

int i, j, k;
const char *s, *t, *u;
sd_bus_message_read(m, "a{is}", 3, &i, &s, &j, &t, &k, &u);

Leer un descriptor de archivo único y duplicarlo para mantenerlo abierto después de que el mensaje sea liberado.

sd_bus_message *m;
int fd, fd_copy;
sd_bus_message_read(m, "h", &fd);
fd_copy = fcntl(fd, FD_DUPFD_CLOEXEC, 3);

HISTORIA

sd_bus_message_read() y sd_bus_message_readv() se añadieron en la versión 240.

sd_bus_message_peek_type() se añadió en la versión 246.
