SD_EVENT_ADD_TIME(3) sd_event_add_time SD_EVENT_ADD_TIME(3)

NOMBRE

sd_event_add_time, sd_event_add_time_relative, sd_event_source_get_time, sd_event_source_set_time, sd_event_source_set_time_relative, sd_event_source_get_time_accuracy, sd_event_source_set_time_accuracy, sd_event_source_get_time_clock, sd_event_time_handler_t - Añadir una fuente de eventos de temporizador a un bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_time_handler_t)(sd_event_source *s, uint64_t usec, void *userdata);

int sd_event_add_time(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_add_time_relative(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_source_get_time(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time(sd_event_source *source, uint64_t usec);

int sd_event_source_set_time_relative(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_accuracy(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time_accuracy(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_clock(sd_event_source *source, clockid_t *ret);

DESCRIPCIÓN

sd_event_add_time() añade una nueva fuente de eventos de temporizador a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro clock toma un identificador de reloj, uno de CLOCK_REALTIME, CLOCK_MONOTONIC, CLOCK_BOOTTIME, CLOCK_REALTIME_ALARM, o CLOCK_BOOTTIME_ALARM. Ver timerfd_create(2) para detalles sobre los varios tipos de relojes. El parámetro usec especifica la hora más temprana, en microsegundos (μs), relativa a la época del reloj, cuando el temporizador debe ser activado. Si se especifica una hora ya pasada (incluyendo **0**), esta fuente de temporizador se "dispara" inmediatamente y está lista para ser despachada. Si el parámetro se especifica como **UINT64_MAX** el evento del temporizador nunca transcurrirá, lo cual puede ser usado como una alternativa para deshabilitar explícitamente una fuente de evento de temporizador con sd_event_source_set_enabled(3). El parámetro accuracy especifica un valor adicional de precisión en μs indicando cuánto puede retrasarse el evento del temporizador. Usar **0** para seleccionar la precisión por defecto (250ms). Usar 1μs para la máxima precisión. Considerar especificar 60000000μs (1min) o más grande para eventos de larga duración que puedan retrasarse sustancialmente. Elegir valores de precisión más altos permite al sistema agrupar eventos de temporizador de forma más agresiva, mejorando la eficiencia energética.

El handler es una función a llamar cuando el temporizador transcurra o **NULL**. El puntero userdata será pasado a la función handler, y puede ser elegido libremente por el llamador. La hora de activación configurada también se pasa al handler, incluso si la llamada ocurre realmente un poco más tarde, sujeta al valor de precisión especificado, al tiempo de espera del temporizador del kernel (ver prctl(2)), y latencias de planificación adicionales. Para consultar la hora real en que se llamó al handler usar sd_event_now(3). El handler puede retornar negativo para señalar un error (ver abajo), otros valores de retorno son ignorados. Si handler es **NULL**, se usará un handler por defecto que llama a sd_event_exit(3).

Por defecto, el temporizador transcurrirá una vez (**SD_EVENT_ONESHOT**), pero esto puede ser cambiado con sd_event_source_set_enabled(3). Si la función handler retorna un código de error negativo, será deshabilitada después de la invocación, incluso si el modo **SD_EVENT_ON** fue solicitado antes, o causará que el bucle termine, ver sd_event_source_set_exit_on_failure(3). Nota que un evento de temporizador configurado como **SD_EVENT_ON** se activará continuamente a menos que su hora configurada sea actualizada usando sd_event_source_set_time().

sd_event_add_time_relative() es similar a sd_event_add_time(), pero toma una especificación de tiempo relativo. Es relativo a la hora actual de la iteración del bucle de eventos, como retornado por sd_event_now(3).

Para destruir un objeto de fuente de eventos usar sd_event_source_unref(3), pero nota que la fuente de eventos solo es removida del bucle de eventos cuando todas las referencias a la fuente de eventos son liberadas. Para asegurarse de que una fuente de eventos no se active más, incluso si todavía está referenciada, deshabilita la fuente de eventos usando sd_event_source_set_enabled(3) con **SD_EVENT_OFF**.

Si el segundo parámetro de sd_event_add_time() es **NULL**, no se devuelve ninguna referencia al objeto de la fuente de eventos. En este caso, la fuente de eventos se considera "flotante", y será destruida implícitamente cuando el propio bucle de eventos sea destruido.

Si el parámetro handler para sd_event_add_time() es **NULL**, y la fuente de eventos se activa, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, casteado a un entero, se pasa como parámetro de código de salida a sd_event_exit(3).

Usar CLOCK_BOOTTIME_ALARM y CLOCK_REALTIME_ALARM** para definir fuentes de eventos que puedan despertar al sistema de la suspensión.

Para configurar temporizadores relativos (es decir, relativos a la hora actual), obtener la hora actual vía sd_event_now(3), sumar el intervalo de tiempo deseado, y usar el resultado como el parámetro usec para sd_event_add_time().

Para configurar temporizadores repetitivos (es decir, temporizadores que se activan en intervalos regulares), configurar el temporizador normalmente, para la primera invocación. Cada vez que se invoca el handler del evento, actualizar la hora de activación del temporizador con sd_event_source_set_time(3) para la próxima iteración del temporizador, y re-habilitar el temporizador usando sd_event_source_set_enabled(). Para calcular el próximo punto en el tiempo a pasar a sd_event_source_set_time(), usar como base el parámetro usec pasado al callback del temporizador, o la marca de tiempo devuelta por sd_event_now(). En el primer caso los eventos del temporizador serán regulares, mientras que en el último caso, la latencia de planificación seguirá acumulándose en el temporizador.

sd_event_source_get_time() recupera el valor de tiempo configurado de una fuente de eventos creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar la hora, relativa a la época del reloj seleccionado, en μs. El valor retornado es relativo a la época, incluso si la fuente de eventos fue creada con un tiempo relativo vía sd_event_add_time_relative().

sd_event_source_set_time() cambia la hora de una fuente de eventos creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de eventos y una hora relativa a la época del reloj seleccionado, en μs.

sd_event_source_set_time_relative() es similar a sd_event_source_set_time(), pero toma una hora relativa a la hora actual de la iteración del bucle de eventos, como retornado por sd_event_now().

sd_event_source_get_time_accuracy() recupera el valor de precisión configurado de una fuente de eventos creada previamente con sd_event_add_time(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar la precisión. La precisión se especifica en μs.

sd_event_source_set_time_accuracy() cambia la precisión configurada de una fuente de evento de temporizador

created previously with sd_event_add_time(). Se toma el objeto de origen del evento y la precisión, en μs.

sd_event_source_get_time_clock() recupera el reloj configurado de un origen de evento creado previamente con sd_event_add_time(). Toma el objeto de origen del evento y un puntero a una variable para almacenar el identificador del reloj.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo al estilo errno.

Errores

Los valores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento no válido.

-ESTALE

El bucle de eventos ya está terminado.

-ECHILD

El bucle de eventos se ha creado en un proceso, biblioteca o instancia de módulo diferente.

-EOPNOTSUPP

El reloj seleccionado no es compatible con la implementación del bucle de eventos.

-EDOM

El origen de evento pasado no es un origen de evento de temporizador.

-EOVERFLOW

El tiempo relativo pasado está fuera del rango permitido para valores de tiempo (es decir, el valor especificado sumado al tiempo actual está fuera del rango de enteros sin signo de 64 bits).

Añadido en la versión 247.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un subproceso paralelo. Se recomienda hacer solo llamadas a setenv() desde una fase temprana del programa cuando no se hayan iniciado otros subprocesos.
