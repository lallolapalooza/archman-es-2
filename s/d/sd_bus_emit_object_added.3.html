NOMBRE

SINOPSIS

#include <systemd/sd-bus-vtable.h>

int sd_bus_emit_signal(sd_bus *bus, const char *path, const char *interface, const char *member, const char *types, ...);

int sd_bus_emit_signal_tov(sd_bus *bus, const char *destination, const char *path, const char *interface, const char *member, const char *types, va_list ap);

int sd_bus_emit_interfaces_added(sd_bus *bus, const char *path, const char *interface, ...);

int sd_bus_emit_interfaces_added_strv(sd_bus *bus, const char *path, char **interfaces);

int sd_bus_emit_interfaces_removed(sd_bus *bus, const char *path, const char *interface, ...);

int sd_bus_emit_interfaces_removed_strv(sd_bus *bus, const char *path, char **interfaces);

int sd_bus_emit_properties_changed(sd_bus *bus, const char *path, const char *interface, const char *name, ...);

int sd_bus_emit_properties_changed_strv(sd_bus *bus, const char *path, const char *interface, char **names);

int sd_bus_emit_object_added(sd_bus *bus, const char *path);

int sd_bus_emit_object_removed(sd_bus *bus, const char *path);

DESCRIPCIÓN

sd_bus_emit_signal() es una función de conveniencia para inicializar un objeto de mensaje de bus y emitir la señal D-Bus correspondiente. Combina las funciones sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) en una única llamada a función. sd_bus_emit_signalv() es equivalente a sd_bus_message_append(), excepto que se llama con un "va_list" en lugar de un número variable de argumentos.

sd_bus_emit_signal_to() y sd_bus_emit_signal_tov() son idénticas a sd_bus_emit_signal() y sd_bus_emit_signalv(), excepto que pueden emitir la señal a un único destino. Pase destination como NULL para difundir la señal.

sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() se utilizan para implementar las señales InterfacesAdded y InterfacesRemoved de la interfaz org.freedesktop.DBus.ObjectManager. Toman como argumento una ruta cuyas interfaces han sido modificadas y una lista variable de interfaces que se han añadido o eliminado, respectivamente. El argumento final pasado a sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() debe ser NULL. Esto permite que ambas funciones determinen de forma segura el número de argumentos de interfaz pasados. sd_bus_emit_interfaces_added_strv() y sd_bus_emit_interfaces_removed_strv() son idénticas a sus respectivas contrapartes, pero ambas toman la lista de interfaces como un único argumento en lugar de un número variable de argumentos.

sd_bus_emit_properties_changed() se utiliza para implementar la señal PropertiesChanged de la interfaz org.freedesktop.DBus.Properties. Toma una ruta de objeto, una interfaz y una lista variable de nombres de propiedades como argumentos. El argumento final pasado a sd_bus_emit_properties_changed() debe ser NULL. Esto permite determinar de forma segura el número de nombres de propiedades pasados. sd_bus_emit_properties_changed_strv() es idéntica a sd_bus_emit_properties_changed() pero toma la lista de nombres de propiedades como un único argumento en lugar de un número variable de argumentos.

sd_bus_emit_object_added() y sd_bus_emit_object_removed() son funciones de conveniencia para emitir las señales InterfacesAdded o InterfacesRemoved para todas las interfaces registradas en una ruta de objeto específica, respectivamente. Esto incluye cualquier tabla de sustitución (fallback) padre si no son anuladas por una tabla de sustitución hija más aplicable. También incluye todas las interfaces D-Bus estándar implementadas por sd-bus mismo en cualquier objeto registrado.

Tenga en cuenta que sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() y sd_bus_emit_object_removed() requieren que se haya registrado un gestor de objetos en la ruta de objeto dada o en una de sus rutas de objeto padre utilizando sd_bus_add_object_manager(3).

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un entero no negativo. En caso de error, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Uno de los parámetros requeridos es NULL o inválido. Se pasó una interfaz D-Bus reservada como parámetro interface.

-ENOPKG

No se puede resolver el bus.

-ECHILD

El bus se creó en un proceso, biblioteca o instancia de módulo diferente.

-ENOMEM

Fallo al asignar memoria.

-ESRCH

Se llamó a una de las funciones sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() o sd_bus_emit_object_removed() en un objeto sin un gestor de objetos registrado en su propia ruta de objeto o en una de sus rutas de objeto padre.

Consulte las páginas man de sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) para errores adicionales posibles.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

sd_bus_emit_object_added(3)

NAME

sd_bus_emit_object_added, sd_bus_emit_object_removed, sd_bus_emit_properties_changed, sd_bus_emit_properties_changed_strv, sd_bus_emit_signal_to, sd_bus_emit_signal_tov, sd_bus_emit_signalv, sd_bus_emit_interfaces_removed, sd_bus_emit_interfaces_removed_strv - Emit D-Bus signals related to object and property changes

SYNOPSIS

#include <systemd/sd-bus.h>
int sd_bus_emit_object_added(sd_bus *bus, const char *path);
int sd_bus_emit_object_removed(sd_bus *bus, const char *path);
int sd_bus_emit_properties_changed(sd_bus *bus, const char *path, const char *interface, sd_bus_error *error, const char *name, ...);
int sd_bus_emit_properties_changed_strv(sd_bus *bus, const char *path, const char *interface, sd_bus_error *error, const char *name, char **const argv);
int sd_bus_emit_interfaces_removed(sd_bus *bus, const char *path, const char *interface, ...);
int sd_bus_emit_interfaces_removed_strv(sd_bus *bus, const char *path, const char *interface, char **const argv);
int sd_bus_emit_signalv(sd_bus *bus, const char *path, const char *interface, const char *member, sd_bus_error *error, const char *types, va_list ap);
int sd_bus_emit_signal_to(sd_bus *bus, const char *destination, const char *path, const char *interface, const char *member, sd_bus_error *error, const char *types, ...);
int sd_bus_emit_signal_tov(sd_bus *bus, const char *destination, const char *path, const char *interface, const char *member, sd_bus_error *error, const char *types, va_list ap);

DESCRIPTION

These functions may be used to emit D-Bus signals. They are convenience functions that construct and send the signal message atomically.

sd_bus_emit_object_added() and sd_bus_emit_object_removed() emit the ObjectAdded and ObjectRemoved signals respectively. These signals are defined by the Object Manager specification and are used to notify observers about changes in the object tree.

sd_bus_emit_properties_changed() and sd_bus_emit_properties_changed_strv() emit the PropertiesChanged signal. This signal is used to notify observers about changes to properties of an object. The `path`, `interface`, and `member` parameters specify the object path, interface name, and the name of the property that changed. The subsequent arguments specify the new value of the property. The `types` string must match the type of the property value.

sd_bus_emit_interfaces_removed() and sd_bus_emit_interfaces_removed_strv() emit the InterfacesRemoved signal. This signal is used to notify observers that one or more interfaces have been removed from an object. The `path` and `interface` parameters specify the object path and the name of the interface that was removed. The subsequent arguments specify any additional information about the removal, such as the reason.

sd_bus_emit_signalv(), sd_bus_emit_signal_to(), and sd_bus_emit_signal_tov() emit a generic D-Bus signal. The `destination`, `path`, `interface`, and `member` parameters specify the target bus, object path, interface name, and signal name, respectively. The `types` string specifies the types of the arguments to the signal. The arguments themselves are passed either as a va_list or as individual arguments.

These functions are thread-safe.

RETURN VALUE

On success, these functions return a non-negative integer. On failure, they return a negative error number.

NOTES

These functions are intended for use in service implementations that expose objects and interfaces via D-Bus. They simplify the process of emitting signals related to object and property changes, reducing boilerplate code.

It is important to ensure that the `types` string correctly matches the types of the arguments being passed to the signal. Mismatched types can lead to D-Bus protocol errors.

HISTORY
