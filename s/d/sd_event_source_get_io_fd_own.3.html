NOMBRE

sd_event_add_io, sd_event_source_get_io_events, sd_event_source_set_io_events, sd_event_source_get_io_revents, sd_event_source_get_io_fd, sd_event_source_set_io_fd, sd_event_source_get_io_fd_own, sd_event_source_set_io_fd_own, sd_event_source, sd_event_io_handler_t - Añadir una fuente de eventos de E/S a un bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_io_handler_t)(sd_event_source *s, int fd, uint32_t revents, void *userdata);

int sd_event_add_io(sd_event *event, sd_event_source **source, int fd, uint32_t events, sd_event_io_handler_t handler, void *userdata);

int sd_event_source_get_io_events(sd_event_source *source, uint32_t *ret);

int sd_event_source_set_io_events(sd_event_source *source, uint32_t events);

int sd_event_source_get_io_revents(sd_event_source *source, uint32_t *ret);

int sd_event_source_get_io_fd(sd_event_source *source);

int sd_event_source_set_io_fd(sd_event_source *source, int fd);

int sd_event_source_get_io_fd_own(sd_event_source *source);

int sd_event_source_set_io_fd_own(sd_event_source *source, int b);

DESCRIPCIÓN

sd_event_add_io() añade una nueva fuente de eventos de E/S a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro fd toma el descriptor de archivo UNIX a observar, que puede referirse a un socket, una FIFO, una cola de mensajes, una conexión serie, un dispositivo de caracteres, o cualquier otro descriptor de archivo compatible con epoll(7) de Linux. El parámetro events toma una máscara de bits de los eventos a observar, una combinación de las siguientes banderas de eventos: EPOLLIN, EPOLLOUT, EPOLLRDHUP, EPOLLPRI, y EPOLLET, ver epoll_ctl(2) para detalles. Tenga en cuenta que no todos los descriptores de archivo son compatibles con epoll, por ejemplo, los archivos o directorios normales no lo son. Si esta función se llama con un descriptor de archivo que no soporta epoll, se devuelve -EPERM (ver también más abajo). En la mayoría de los casos, dichos descriptores de archivo pueden tratarse como siempre legibles o siempre escribibles, por lo que la observación de eventos de E/S es innecesaria.

El handler es una función a llamar cuando la fuente de eventos se activa o NULL. El puntero userdata se pasará a la función manejadora, y puede ser elegido libremente por el llamante. A la manejadora también se le pasará el descriptor de archivo en el que se vio el evento, así como las banderas de evento reales. Generalmente es un subconjunto de los eventos observados, sin embargo, puede incluir adicionalmente EPOLLERR y EPOLLHUP. La manejadora puede devolver un valor negativo para indicar un error (ver más abajo), otros valores de retorno se ignoran. Si handler es NULL, se utilizará una manejadora por defecto que llama a sd_event_exit(3).

Por defecto, una fuente de eventos permanecerá habilitada continuamente (SD_EVENT_ON), pero esto puede cambiarse con sd_event_source_set_enabled(3). Si la función manejadora devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si se solicitó el modo SD_EVENT_ON antes, o provocará que el bucle termine, ver sd_event_source_set_exit_on_failure(3). Tenga en cuenta que una fuente de eventos configurada como SD_EVENT_ON se activará continuamente a menos que se lean o escriban datos en el descriptor de archivo para restablecer la máscara de eventos vistos.

Establecer la máscara de eventos de E/S a 0 no significa que la fuente de eventos no se activará más, ya que EPOLLHUP y EPOLLERR pueden activarse incluso con una máscara de eventos cero. Para deshabilitar temporalmente una fuente de eventos de E/S, utilice sd_event_source_set_enabled(3) con SD_EVENT_OFF en su lugar.

Para destruir un objeto de fuente de eventos utilice sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se liberan todas las referencias a la fuente de eventos. Para asegurarse de que una fuente de eventos no se active más, incluso si todavía se hace referencia a ella, deshabilite la fuente de eventos usando sd_event_source_set_enabled(3) con SD_EVENT_OFF.

Si el segundo parámetro de sd_event_add_io() es NULL, no se devuelve ninguna referencia al objeto de la fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando se destruya el propio bucle de eventos.

Si el handler de sd_event_add_io() es NULL, y la fuente de eventos se activa, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a entero, se pasa como parámetro del código de salida a sd_event_exit(3).

Tenga en cuenta que esta llamada no toma posesión del descriptor de archivo pasado, la propiedad (y por lo tanto el deber de cerrarlo cuando ya no sea necesario) permanece con el llamante. Sin embargo, con la llamada sd_event_source_set_io_fd_own() (ver más abajo) la fuente de eventos puede tomar opcionalmente posesión del descriptor de archivo después de que la fuente de eventos haya sido creada. En ese caso, el descriptor de archivo se cierra automáticamente tan pronto como se libera la fuente de eventos.

Se recomienda usar sd_event_add_io() solo en conjunción con descriptores de archivo que tengan O_NONBLOCK configurado, para asegurar que todas las operaciones de E/S de las manejadoras invocadas sean adecuadamente asíncronas y no bloqueantes. El uso de descriptores de archivo sin O_NONBLOCK podría resultar en una inanición inesperada de otras fuentes de eventos. Ver fcntl(2) para más detalles sobre cómo habilitar el modo O_NONBLOCK.

sd_event_source_get_io_events() recupera la máscara configurada de eventos de E/S observados de una fuente de eventos creada previamente con sd_event_add_io(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar la máscara.

sd_event_source_set_io_events() configura la máscara de eventos de E/S observados de una fuente de eventos creada previamente con sd_event_add_io(). Toma el objeto de la fuente de eventos y la nueva máscara de eventos.

sd_event_source_get_io_revents() recupera la máscara de eventos de E/S de eventos actualmente vistos pero no despachados de una fuente de eventos creada previamente con sd_event_add_io(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar la máscara de eventos. Cuando se llama desde una función manejadora en el objeto de la fuente de eventos de la manejadora, esto devolverá la misma máscara que se pasó al parámetro revents de la manejadora. Esta llamada es principalmente útil para comprobar eventos no despachados de una fuente de eventos desde la manejadora de una fuente de eventos no relacionada (posiblemente de mayor prioridad). Tenga en cuenta la relación entre sd_event_source_get_pending() y sd_event_source_get_io_revents(): ambas funciones informarán resultados no nulos cuando haya un evento pendiente para la fuente de eventos, pero la primera se aplica a todos los tipos de fuentes de eventos, la segunda solo a fuentes de eventos de E/S.

sd_event_source_get_io_fd() recupera el descriptor de archivo UNIX de una fuente de eventos creada previamente con sd_event_add_io(). Toma el objeto de la fuente de eventos y devuelve el descriptor de archivo no negativo o un número de error negativo en caso de error (ver más abajo).

sd_event_source_set_io_fd() cambia el descriptor de archivo UNIX de una fuente de eventos de E/S creada previamente con sd_event_add_io(). Toma el objeto de la fuente de eventos y el nuevo descriptor de archivo como parámetros. Si la fuente de eventos poseía el descriptor de archivo anterior, es decir, si se había llamado a sd_event_source_set_io_fd_own() para la fuente de eventos con un valor distinto de cero, entonces el descriptor de archivo anterior se cerrará y la fuente de eventos también tomará posesión del nuevo descriptor de archivo en caso de éxito.

sd_event_source_set_io_fd_own() controla si el descriptor de archivo de la fuente de eventos debe tomar posesión del descriptor de archivo. Toma un parámetro booleano b. Cuando es verdadero (distinto de cero)

, el descriptor de archivo se cerrará automáticamente cuando la fuente de eventos se libere o cuando el descriptor de archivo sea reemplazado por sd_event_source_set_io_fd(). Por defecto, el descriptor no es propiedad de la fuente de eventos y la aplicación debe cerrarlo por sí misma si es necesario.

sd_event_source_get_io_fd_own() puede ser utilizado para consultar la configuración actual del flag booleano de propiedad del descriptor de archivo, tal como se estableció con sd_event_source_set_io_fd_own(). Devuelve un valor positivo si el descriptor de archivo se cierra automáticamente cuando la fuente de eventos se destruye, cero si no, y un valor negativo en caso de error.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de fallo, devuelven un código de error negativo estilo errno.

Errores

Los valores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento inválido.

-ESTALE

El bucle de eventos ya ha terminado.

-ECHILD

El bucle de eventos se creó en un proceso, librería o instancia de módulo diferente.

-EDOM

La fuente de eventos pasada no es una fuente de eventos de E/S.

-EPERM

El descriptor de archivo pasado no soporta la API de epoll(7), por ejemplo, porque es un archivo o directorio regular. Consulte epoll_ctl(2) para más detalles.

Añadido en la versión 255.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que está declarado como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda solo realizar llamadas a setenv() desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
