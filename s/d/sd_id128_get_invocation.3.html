NOMBRE

sd_id128_get_machine, sd_id128_get_app_specific, sd_id128_get_machine_app_specific, sd_id128_get_boot, sd_id128_get_boot_app_specific, sd_id128_get_invocation - Recuperar IDs de 128 bits

SINOPSIS

#include <systemd/sd-id128.h>

int sd_id128_get_machine(sd_id128_t *ret);

int sd_id128_get_app_specific(sd_id128_t base, sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_machine_app_specific(sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_boot(sd_id128_t *ret);

int sd_id128_get_boot_app_specific(sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_invocation(sd_id128_t *ret);

int sd_id128_get_invocation_app_specific(sd_id128_t app_id, sd_id128_t *ret);

DESCRIPCIÓN

sd_id128_get_machine() devuelve el ID de máquina del host en ejecución. Esto lee y analiza el archivo machine-id(5). Esta función almacena en caché el ID de máquina internamente para hacer de la recuperación del ID de máquina una operación barata. Este ID puede usarse donde se necesite un identificador único para el sistema local. Sin embargo, se recomienda usar este ID tal cual solo en entornos confiables. En entornos no confiables, se recomienda derivar un ID específico de la aplicación de este ID de máquina, de forma irreversible (criptográficamente segura). Para facilitar esto, se proporciona sd_id128_get_machine_app_specific(), ver más abajo.

sd_id128_get_app_specific() devuelve un ID de máquina que es una combinación de los parámetros base y app_id. Internamente, esta función calcula HMAC-SHA256 del parámetro app_id con clave del parámetro base, y trunca este resultado para que quepa en sd_id128_t y lo convierte en un UUID válido de Variante 1 Versión 4, de acuerdo con la **RFC 4122**[1]. Ninguno de los dos parámetros de entrada puede ser calculado a partir del parámetro de salida ret.

sd_id128_get_machine_app_specific() es similar a sd_id128_get_machine(), pero recupera un ID de máquina que es específico para la aplicación identificada por el ID de aplicación indicado. Se recomienda usar esta función en lugar de sd_id128_get_machine() al pasar un ID a entornos no confiables, para asegurar que el ID de máquina original no pueda ser determinado externamente. De esta manera, el ID utilizado por la aplicación permanece estable en una máquina dada, pero no puede correlacionarse fácilmente con los IDs utilizados en otras aplicaciones en la misma máquina. El ID específico de la aplicación debe generarse mediante una herramienta como **systemd-id128 new**, y puede compilarse en la aplicación. Esta función devolverá el mismo ID específico de la aplicación para cada combinación de ID de máquina y ID de aplicación. Internamente, esta función llama a sd_id128_get_app_specific() con el resultado de sd_id128_get_machine() y el parámetro app_id.

sd_id128_get_boot() devuelve el ID de arranque del kernel en ejecución. Esto lee y analiza el archivo /proc/sys/kernel/random/boot_id expuesto por el kernel. Se genera aleatoriamente al inicio del arranque y es único para cada instancia de kernel en ejecución. Vea random(4) para más información. Esta función también almacena en caché internamente el ID devuelto para hacer de esta llamada una operación barata. Se recomienda usar este ID tal cual solo en entornos confiables. En entornos no confiables, se recomienda derivar un ID específico de la aplicación utilizando sd_id128_get_boot_app_specific(), ver más abajo.

sd_id128_get_boot_app_specific() es análogo a sd_id128_get_machine_app_specific(), pero devuelve un ID que cambia entre reinicios. Algunas máquinas pueden usarse durante mucho tiempo sin reiniciar, por lo tanto, el ID de arranque puede permanecer constante durante mucho tiempo, y tiene propiedades similares al ID de máquina durante ese tiempo.

sd_id128_get_invocation() devuelve el ID de invocación del servicio actualmente ejecutado. En su implementación actual, intenta leer y analizar lo siguiente:

•La variable de entorno $INVOCATION_ID que el gestor de servicios establece al activar un servicio.
•Una entrada en la tabla de claves del kernel que el gestor de servicios del sistema establece al activar un servicio.

Vea systemd.exec(5) para más detalles. El ID se almacena en caché internamente. En el futuro, puede que se añada un mecanismo diferente para determinar el ID de invocación.

sd_id128_get_invocation_app_specific() deriva un ID específico de la aplicación del ID de invocación.

Tenga en cuenta que sd_id128_get_machine_app_specific(), sd_id128_get_boot(), sd_id128_get_boot_app_specific(), sd_id128_get_invocation() y sd_id128_get_invocation_app_specific siempre devuelven IDs compatibles con UUID Variante 1 Versión 4. sd_id128_get_machine() también devolverá un ID compatible con UUID Variante 1 Versión 4 en instalaciones nuevas, pero podría no hacerlo en las antiguas. Es posible convertir el ID de máquina de forma no reversible a uno compatible con UUID Variante 1 Versión 4. Para más información, vea machine-id(5). Por lo tanto, se garantiza que estas funciones nunca devolverán el ID que consiste en todos los bits cero o todos los bits uno (SD_ID128_NULL, SD_ID128_ALLF) — con la posible excepción de sd_id128_get_machine(), como se mencionó.

Para más información sobre el tipo "sd_id128_t" vea sd-id128(3).

VALOR DE RETORNO

Estas llamadas devuelven 0 en caso de éxito (en cuyo caso ret se rellena), o un código de error negativo de estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOENT

Devuelto por sd_id128_get_machine() y sd_id128_get_machine_app_specific() cuando falta /etc/machine-id.

Añadido en la versión 242.

-ENOMEDIUM

Devuelto por sd_id128_get_machine() y sd_id128_get_machine_app_specific() cuando /etc/machine-id está vacío o es todo ceros. También devuelto por sd_id128_get_invocation() cuando el ID de invocación es todo ceros.

Añadido en la versión 242.

-ENOPKG

Devuelto por sd_id128_get_machine() y sd_id128_get_machine_app_specific() cuando el contenido de /etc/machine-id es "no inicializado".

Añadido en la versión 253.

-ENOSYS

Devuelto por sd_id128_get_boot() y sd_id128_get_boot_app_specific() cuando /proc/ no está montado.

Añadido en la versión 253.

-ENXIO

Devuelto por sd_id128_get_invocation() si no hay ningún ID de invocación establecido. También devuelto por sd_id128_get_app_specific(), sd_id128_get_machine_app_specific() y sd_id128_get_boot_app_specific() cuando el parámetro app_id es todo ceros.

Añadido en la versión 242.

-EUCLEAN

Devuelto por cualquiera de las funciones descritas aquí cuando el valor configurado tiene un formato inválido.

Añadido en la versión 253.

-EPERM

La información solicitada no pudo recuperarse debido a permisos insuficientes.

Añadido en la versión 242.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que está declarado como no seguro para múltiples hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda llamar a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

EJEMPLOS

Ejemplo 1. ID de máquina específico de la aplicación

Primero, genera el ID de la aplicación:

$ systemd-id128 new my-app
xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

Luego, en tu código:

#include <stdio.h>
#include <stdlib.h>
#include <systemd/sd-id128.h>

int main(int argc, char *argv[]) {
    sd_id128_t app_id;
    sd_id128_t machine_app_id;
    int r;

    if (argc != 2) {
        fprintf(stderr, "Usage: %s <app-id>\n", argv[0]);
        return 1;
    }

    r = sd_id128_from_string(argv[1], &app_id);
    if (r < 0) {
        fprintf(stderr, "Failed to parse application ID '%s': %s\n", argv[1], strerror(-r));
        return 1;
    }

    r = sd_id128_get_machine_app_specific(app_id, &machine_app_id);
    if (r < 0) {
        fprintf(stderr, "Failed to get machine-specific application ID: %s\n", strerror(-r));
        return 1;
    }

    printf("Machine-specific application ID: ");
    sd_id128_to_file(stdout, machine_app_id);
    printf("\n");

    return 0;
}

NAME

sd_id128_get_invocation, sd_id128_get_boot, sd_id128_get_machine, sd_id128_get_app_specific, sd_id128_get_invocation_app_specific, sd_id128_get_boot_app_specific, sd_id128_get_machine_app_specific - Obtain unique identifiers

SYNOPSIS

#include <systemd/sd-id128.h>

sd_id128_t sd_id128_get_invocation(void);

sd_id128_t sd_id128_get_boot(void);

sd_id128_t sd_id128_get_machine(void);

sd_id128_t sd_id128_get_app_specific(const sd_id128_t *id);

sd_id128_t sd_id128_get_invocation_app_specific(const sd_id128_t *id);

sd_id128_t sd_id128_get_boot_app_specific(const sd_id128_t *id);

sd_id128_t sd_id128_get_machine_app_specific(const sd_id128_t *id);

DESCRIPTION

These functions retrieve various identifiers that are unique on a varying scope. The returned type `sd_id128_t` is a structure type enclosing a 128-bit value. It should be treated as opaque.

sd_id128_get_invocation() returns the identifier for the current invocation of the systemd manager. This identifier changes with every reboot.

sd_id128_get_boot() returns the identifier for the current boot. This identifier is generated once per boot and is thus the same for all processes running during the same boot.

sd_id128_get_machine() returns the identifier for the current host. This identifier is read from the machine-id(5) file and is consistent across reboots.

sd_id128_get_app_specific() takes an identifier and derives a new one. The new identifier is a UUID generated based on the provided input UUID and the namespace UUID `a3c77a0c-9124-43f9-874c-6730678f24e3`. This is useful for generating consistent IDs for application-specific data related to a particular base ID. Note that the input ID is currently ignored and a new UUID is generated each time.

sd_id128_get_invocation_app_specific(), sd_id128_get_boot_app_specific(), and sd_id128_get_machine_app_specific() are similar to sd_id128_get_app_specific(), but derive their namespace UUID from the invocation, boot, or machine ID, respectively. This allows creating IDs that are specific to a particular application and a particular instance of invocation, boot, or machine, without needing to pass the base ID explicitly.

The functions are generally available in all processes. However, some of the identifiers might not be available in certain restricted environments (like certain systemd-nspawn containers or virtual machines). In such cases, these functions might return the null identifier (all bits zero).

Use the sd-id128(3) family of functions like `sd_id128_to_string(3)` to convert the `sd_id128_t` type to a string representation for logging or display.

RETURN VALUE

On success, the above functions return the generated 128-bit identifier. If an identifier could not be determined (e.g., because the system is running in a restricted environment), the null identifier (`SD_ID128_NULL`) is returned.

NOTES

All these functions are thread-safe.

The identifiers returned by these functions are generally intended for internal use by systemd components and related services. Relying on them in external applications is discouraged, as their behavior and availability might change between systemd versions.

For generating new, random 128-bit identifiers, use `sd_id128_randomize(3)`.

EXAMPLES

#include <stdio.h>
#include <systemd/sd-id128.h>
int main(int argc, char *argv[]) {
  sd_id128_t id;
  id = sd_id128_get_boot();
  printf("Boot ID: %s\n", sd_id128_to_string(id));
  id = sd_id128_get_machine();
  printf("Machine ID: %s\n", sd_id128_to_string(id));
  id = sd_id128_get_invocation();
  printf("Invocation ID: %s\n", sd_id128_to_string(id));
  return 0;
}

Generating a unique application ID for the current invocation:

$ systemd-id128 new
As string:
c273277323db454ea63bb96e79b53e97
As UUID:
c2732773-23db-454e-a63b-b96e79b53e97
As man:sd-id128(3) macro:
#define MESSAGE_XYZ SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
...

Then use the new identifier in an example application:

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <systemd/sd-id128.h>
#define OUR_APPLICATION_ID SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
int main(int argc, char *argv[]) {
  sd_id128_t id;
  sd_id128_get_machine_app_specific(OUR_APPLICATION_ID, &id);
  printf("Our application ID: " SD_ID128_FORMAT_STR "\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}
