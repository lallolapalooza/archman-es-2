#include <systemd/sd-bus.h>

DESCRIPCIÓN

sd_bus_default() adquiere un objeto de conexión de bus al bus de usuario cuando se invoca desde una rebanada de usuario (cualquier sesión bajo "user-*.slice", por ejemplo: "user@1000.service"), o al bus del sistema en caso contrario. El objeto de conexión está asociado al hilo llamador. Cada vez que se invoca la función desde el mismo hilo, se devuelve el mismo objeto, pero su recuento de referencias aumenta en uno, siempre que se mantenga al menos una referencia. Cuando se suelta la última referencia a la conexión, (usando la llamada sd_bus_unref(3)), la conexión se termina. Tenga en cuenta que la conexión no se termina automáticamente cuando finaliza el hilo asociado. Es importante soltar la última referencia a la conexión del bus explícitamente antes de que finalice el hilo, ya que de lo contrario, la conexión tendrá fugas. Además, los mensajes en cola pero no leídos o no escritos mantienen la referencia al bus, ver más abajo.

sd_bus_default_user() devuelve un objeto de conexión del bus de usuario asociado al hilo llamador. sd_bus_default_system() es similar, pero se conecta al bus del sistema. Tenga en cuenta que sd_bus_default() es idéntico a estas dos llamadas, dependiendo del contexto de ejecución.

sd_bus_open() crea una nueva conexión de bus independiente al bus de usuario cuando se invoca en contexto de usuario, o al bus del sistema en caso contrario. sd_bus_open_user() es similar, pero se conecta solo al bus de usuario. sd_bus_open_system() hace lo mismo, pero se conecta al bus del sistema. A diferencia de sd_bus_default(), sd_bus_default_user() y sd_bus_default_system(), estas llamadas devuelven objetos de conexión nuevos e independientes que no están asociados con el hilo que los invoca y no se comparten entre múltiples invocaciones. Se recomienda compartir conexiones por hilo para hacer un uso eficiente de los recursos disponibles. Por lo tanto, se recomienda utilizar sd_bus_default(), sd_bus_default_user() y sd_bus_default_system() para conectarse a los buses de usuario o del sistema.

sd_bus_open_with_description(), sd_bus_open_user_with_description() y sd_bus_open_system_with_description() son similares a sd_bus_open(), sd_bus_open_user() y sd_bus_open_system(), pero permiten establecer una cadena de descripción, ver sd_bus_set_description(3). description puede ser NULL, en cuyo caso esta función es equivalente a sd_bus_open(). Esta cadena de descripción se utiliza en mensajes de registro sobre el objeto del bus, y la inclusión de un "nombre" para el bus hace que sean más fáciles de entender. Algunos mensajes se emiten durante la inicialización del bus, por lo que el uso de esta función es preferible a establecer la descripción más tarde con sd_bus_open_with_description(). El argumento se copia internamente y no se referenciará después de que la función devuelva.

Si la variable de entorno $DBUS_SESSION_BUS_ADDRESS está establecida (cf. environ(7)), se utilizará como dirección del bus de usuario. Esta variable puede contener múltiples direcciones separadas por ";". Si esta variable no está establecida, se utilizará un valor predeterminado adecuado para la instancia de D-Bus de usuario predeterminada.

Si la variable de entorno $DBUS_SYSTEM_BUS_ADDRESS está establecida, se utilizará como dirección del bus del sistema. Esta variable utiliza la misma sintaxis que $DBUS_SESSION_BUS_ADDRESS. Si esta variable no está establecida, se utilizará un valor predeterminado adecuado para la instancia de D-Bus del sistema predeterminada.

sd_bus_open_system_remote() se conecta al bus del sistema en el host especificado usando ssh(1). host consiste en un nombre de usuario opcional seguido del símbolo "@", y el nombre del host, opcionalmente seguido por un ":" y un puerto, opcionalmente seguido por un "/" y un nombre de máquina. Si se proporciona el nombre de la máquina, se crea una conexión al bus del sistema en el contenedor especificado en la máquina remota, y de lo contrario, se crea una conexión al bus del sistema en el host especificado.

Tenga en cuenta que entrar en un contenedor es una operación privilegiada y probablemente solo funcionará para el usuario root en la máquina remota.

sd_bus_open_system_machine() se conecta al bus del sistema en la máquina especificada, donde máquina es el nombre de un contenedor local, posiblemente prefijado por un nombre de usuario y un separador "@". Si el nombre del contenedor se especifica como la cadena especial ".host", la conexión se realiza al sistema local. Esto es útil para conectarse al bus del sistema local como un usuario específico, por ejemplo, "foobar@.host" para conectarse al bus del sistema local como el usuario local "foobar". Si se utiliza la sintaxis "@", se puede omitir el lado izquierdo o el derecho (pero no ambos) en cuyo caso se implica el nombre de usuario local o ".host". Si no se utiliza la sintaxis "@", la conexión siempre se realiza como usuario root. Ver sd_bus_set_address(3) para una descripción de la sintaxis de la dirección, y machinectl(1) para más información sobre el concepto de "máquina". Tenga en cuenta que las conexiones a contenedores locales solo están disponibles para procesos privilegiados en este momento.

sd_bus_open_user_machine() es similar a sd_bus_open_system_machine(), pero se conecta al bus de usuario del usuario root, o si se utiliza la sintaxis "@", del usuario especificado.

Estas llamadas asignan un objeto de conexión de bus e inician la conexión a un bus bien conocido de algún tipo. Una alternativa a usar estas llamadas de alto nivel es crear un objeto de bus no conectado con sd_bus_new(3) y conectarlo con sd_bus_start(3).

PROPIEDAD DE REFERENCIA

Las funciones sd_bus_open(), sd_bus_open_user(), sd_bus_open_user_machine(), sd_bus_open_system(), sd_bus_open_system_remote() y sd_bus_open_system_machine() devuelven un nuevo objeto de conexión y el llamador posee la única referencia. Cuando ya no se necesite, esta referencia debe destruirse con sd_bus_unref(3).

Las funciones sd_bus_default(), sd_bus_default_user() y sd_bus_default_system() no crean necesariamente un nuevo objeto, sino que incrementan la referencia de conexión de un objeto de conexión existente en uno. Use sd_bus_unref(3) para soltar la referencia.

Los mensajes en cola pero no escritos/leídos mantienen una referencia a su objeto de conexión de bus. Por esta razón, incluso si una aplicación soltó todas las referencias a una conexión de bus, es posible que no se destruya de inmediato. Hasta que se lean todos los mensajes en cola entrantes, y hasta que se escriban todos los mensajes salientes no escritos, el objeto del bus permanecerá activo. sd_bus_flush() se puede usar para escribir todos los mensajes en cola salientes para que suelten sus referencias.

Para vaciar los mensajes entrantes no leídos, usa sd_bus_close(), que también cerrará la conexión del bus. Cuando se usa la lógica de bus predeterminada, es una buena idea invocar primero sd_bus_flush() seguido de sd_bus_close() cuando un hilo o proceso termina, y por lo tanto su objeto de conexión de bus debe ser liberado.

Normalmente, los objetos de ranura (como los creados por sd_bus_add_match(3) y llamadas similares) también mantienen una referencia a su objeto de conexión de bus. Por lo tanto, mientras un objeto de ranura de bus permanezca referenciado, su objeto de bus también permanecerá asignado. Opcionalmente, los objetos de ranura de bus pueden colocarse en modo "flotante". Cuando están en modo flotante, el ciclo de vida del objeto de ranura de bus está vinculado al objeto de bus, es decir, cuando el objeto de bus se libera, el objeto de ranura de bus también se desenreferencia automáticamente. El estado flotante de un objeto de ranura puede controlarse explícitamente con sd_bus_slot_set_floating(3), aunque normalmente los objetos de ranura de bus flotantes se crean pasando NULL como parámetro slot de sd_bus_add_match() y llamadas relacionadas, indicando así que el llamador no está directamente interesado en referenciar y gestionar el objeto de ranura de bus.

El ciclo de vida de la conexión de bus predeterminada debe ser responsabilidad del código que crea/posee el hilo al que está asociado el objeto de conexión de bus predeterminada. El código de biblioteca no debe llamar ni a sd_bus_flush() ni a sd_bus_close() en objetos de bus predeterminados, a menos que lo haga en su propio hilo privado y auto-asignado. El código de biblioteca no debe usar el objeto de bus predeterminado en otros hilos, a menos que esté claro que el programa que lo utiliza gestionará el ciclo de vida del objeto de conexión de bus y lo vaciará y cerrará antes de salir del hilo. En bibliotecas donde no está claro que el programa llamante gestionará el ciclo de vida del objeto de conexión de bus, se recomienda por lo tanto usar sd_bus_open_system() en lugar de sd_bus_default_system() y llamadas relacionadas.

VALOR DE RETORNO

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, estas llamadas devuelven un código de error negativo de estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Los parámetros especificados son inválidos.

-ENOMEDIUM

El tipo de bus solicitado no está disponible debido a un entorno inválido (por ejemplo, el bus de sesión de usuario no está disponible porque $XDG_RUNTIME_DIR no está configurado).

-ENOMEM

Fallo en la asignación de memoria.

-ESOCKTNOSUPPORT

La versión del protocolo requerida para conectarse al bus seleccionado no es compatible.

Además, pueden devolverse otros errores relacionados con la conexión. Ver sd_bus_send(3).

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se han iniciado otros hilos.
