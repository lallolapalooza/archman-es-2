NOMBRE

sd_event_add_time, sd_event_add_time_relative, sd_event_source_get_time, sd_event_source_set_time, sd_event_source_set_time_relative, sd_event_source_get_time_accuracy, sd_event_source_set_time_accuracy, sd_event_source_get_time_clock, sd_event_time_handler_t - Añadir una fuente de evento de temporizador a un bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_time_handler_t)(sd_event_source *s, uint64_t usec, void *userdata);

int sd_event_add_time(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_add_time_relative(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_source_get_time(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time(sd_event_source *source, uint64_t usec);

int sd_event_source_set_time_relative(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_accuracy(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time_accuracy(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_clock(sd_event_source *source, clockid_t *ret);

DESCRIPCIÓN

sd_event_add_time() añade una nueva fuente de evento de temporizador a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de evento se devuelve en el parámetro source. El parámetro clock toma un identificador de reloj, uno de CLOCK_REALTIME, CLOCK_MONOTONIC, CLOCK_BOOTTIME, CLOCK_REALTIME_ALARM, o CLOCK_BOOTTIME_ALARM. Ver timerfd_create(2) para más detalles sobre los varios tipos de relojes. El parámetro usec especifica la hora más temprana, en microsegundos (μs), relativa a la época del reloj, cuando el temporizador deberá dispararse. Si se especifica una hora que ya ha pasado (incluyendo 0), esta fuente de temporizador se "dispara" inmediatamente y está lista para ser despachada. Si el parámetro se especifica como UINT64_MAX, el evento del temporizador nunca expirará, lo que puede usarse como alternativa para deshabilitar explícitamente una fuente de evento de temporizador con sd_event_source_set_enabled(3). El parámetro accuracy especifica un valor de precisión adicional en μs, indicando cuánto puede retrasarse el evento del temporizador. Usar 0 para seleccionar la precisión por defecto (250ms). Usar 1μs para precisión máxima. Considerar especificar 60000000μs (1min) o más para eventos de larga duración que puedan retrasarse sustancialmente. Elegir valores de precisión más altos permite al sistema fusionar eventos de temporizador de forma más agresiva, mejorando la eficiencia energética.

El handler es una función a llamar cuando el temporizador expira, o NULL. El puntero userdata se pasará a la función handler y puede ser elegido libremente por el llamador. La hora de disparo configurada también se pasa al handler, incluso si la llamada ocurre un poco más tarde, sujeta al valor de precisión especificado, el retardo del temporizador del kernel (ver prctl(2)), y latencias de planificación adicionales. Para consultar la hora real en que se llamó al handler, usar sd_event_now(3). El handler puede devolver un valor negativo para señalar un error (ver más abajo), otros valores de retorno se ignoran. Si handler es NULL, se usará un handler por defecto que llama a sd_event_exit(3).

Por defecto, el temporizador expirará una vez (SD_EVENT_ONESHOT), pero esto puede cambiarse con sd_event_source_set_enabled(3). Si la función handler devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si el modo SD_EVENT_ON fue solicitado anteriormente, o causará que el bucle termine, ver sd_event_source_set_exit_on_failure(3). Tener en cuenta que un evento de temporizador configurado a SD_EVENT_ON se disparará continuamente a menos que su hora configurada se actualice usando sd_event_source_set_time().

sd_event_add_time_relative() es como sd_event_add_time(), pero toma una especificación de tiempo relativo. Es relativo a la hora actual de la iteración del bucle de eventos, como la devuelve sd_event_now(3).

Para destruir un objeto de fuente de evento usar sd_event_source_unref(3), pero tener en cuenta que la fuente de evento solo se elimina del bucle de eventos cuando se descartan todas las referencias a ella. Para asegurarse de que una fuente de evento ya no se dispare, incluso si todavía está referenciada, deshabilitar la fuente de evento usando sd_event_source_set_enabled(3) con SD_EVENT_OFF.

Si el segundo parámetro de sd_event_add_time() es NULL, no se devuelve ninguna referencia al objeto de la fuente de evento. En este caso, la fuente de evento se considera "flotante" y se destruirá implícitamente cuando el propio bucle de eventos se destruya.

Si el parámetro handler para sd_event_add_time() es NULL, y la fuente de evento se dispara, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, casteado a un entero, se pasa como parámetro de código de salida a sd_event_exit(3).

Usar CLOCK_BOOTTIME_ALARM y CLOCK_REALTIME_ALARM para definir fuentes de evento que puedan despertar al sistema de la suspensión.

Para configurar temporizadores relativos (es decir, relativos a la hora actual), obtener la hora actual a través de sd_event_now(3), sumarle el lapso de tiempo deseado y usar el resultado como parámetro usec para sd_event_add_time().

Para configurar temporizadores repetitivos (es decir, temporizadores que se disparan en intervalos regulares), configurar el temporizador normalmente, para la primera invocación. Cada vez que se invoca el handler del evento, actualizar la hora de disparo del temporizador con sd_event_source_set_time(3) para la próxima iteración del temporizador, y reactivar el temporizador usando sd_event_source_set_enabled(). Para calcular el próximo punto en el tiempo a pasar a sd_event_source_set_time(), usar como base ya sea el parámetro usec pasado al callback del temporizador, o la marca de tiempo devuelta por sd_event_now(). En el primer caso, los eventos del temporizador serán regulares, mientras que en el último caso, la latencia de planificación seguirá acumulándose en el temporizador.

sd_event_source_get_time() recupera el valor de tiempo configurado de una fuente de evento creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de evento y un puntero a una variable para almacenar la hora, relativa a la época del reloj seleccionado, en μs. El valor devuelto es relativo a la época, incluso si la fuente de evento fue creada con un tiempo relativo a través de sd_event_add_time_relative().

sd_event_source_set_time() cambia la hora de una fuente de evento creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de evento y una hora relativa a la época del reloj seleccionado, en μs.

sd_event_source_set_time_relative() es similar a sd_event_source_set_time(), pero toma una hora relativa a la hora actual de la iteración del bucle de eventos, como la devuelve sd_event_now().

sd_event_source_get_time_accuracy() recupera el valor de precisión configurado de una fuente de evento creada previamente con sd_event_add_time(). Toma el objeto de la fuente de evento y un puntero a una variable para almacenar la precisión. La precisión se especifica en μs.

sd_event_source_set_time_accuracy() cambia la precisión configurada de una fuente de evento de temporizador

DESCRIPCIÓN

El bucle de eventos se puede configurar para que despierte un evento de tiempo específico. Este evento de tiempo se puede configurar para que se active en un momento absoluto en el tiempo (es decir, una fecha y hora específicas), o en un momento relativo al instante en que se llama a la función.

sd_event_add_time() registra un nuevo evento de tiempo para el bucle de eventos event. Se llamará al manejador de eventos callback, que toma userdata como argumento, en el reloj clock especificado cuando la hora actual supere la hora usec. El tiempo usec debe ser un tiempo absoluto en el reloj seleccionado, expresado en microsegundos.

sd_event_add_time_relative() es similar a sd_event_add_time(), pero usec se interpreta como un tiempo relativo al instante actual.

Las funciones sd_event_source_set_time() y sd_event_source_set_time_relative() permiten modificar la hora de activación de un evento de tiempo existente. Los argumentos son los mismos que para sd_event_add_time() y sd_event_add_time_relative(), respectivamente.

sd_event_source_get_time() recupera la hora de activación configurada de un evento de tiempo creado previamente con sd_event_add_time(). Toma el objeto fuente del evento y un puntero a una variable para almacenar la hora en microsegundos.

sd_event_source_get_time_relative() recupera el desplazamiento de tiempo relativo configurado de un evento de tiempo creado previamente con sd_event_add_time_relative(). Toma el objeto fuente del evento y un puntero a una variable para almacenar el desplazamiento de tiempo en microsegundos.

sd_event_source_set_time_accuracy() configura la precisión deseada para un evento de tiempo. La precisión se especifica en microsegundos en el parámetro accuracy_usec.

sd_event_source_get_time_accuracy() recupera la precisión configurada de un evento de tiempo creado previamente con sd_event_add_time(). Toma el objeto fuente del evento y un puntero a una variable para almacenar la precisión en microsegundos.

sd_event_source_get_time_clock() recupera el reloj configurado de un evento de tiempo creado previamente con sd_event_add_time(). Toma el objeto fuente del evento y un puntero a una variable para almacenar el identificador del reloj.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo al estilo errno.

Errores

Los valores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento no válido.

-ESTALE

El bucle de eventos ya ha finalizado.

-ECHILD

El bucle de eventos se creó en un proceso, biblioteca o instancia de módulo diferente.

-EOPNOTSUPP

El reloj seleccionado no es compatible con la implementación del bucle de eventos.

-EDOM

La fuente de eventos pasada no es una fuente de eventos de temporizador.

-EOVERFLOW

El tiempo relativo pasado está fuera del rango permitido para los valores de tiempo (es decir, el valor especificado sumado al tiempo actual está fuera del rango del entero sin signo de 64 bits).

Añadido en la versión 247.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
