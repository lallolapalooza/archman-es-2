DESCRIPCIÓN

sd_event_add_child() añade una nueva fuente de eventos de cambio de estado de proceso hijo a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro pid especifica el PID del proceso a vigilar, que debe ser un proceso hijo directo del proceso invocador. El parámetro options determina qué cambios de estado se vigilarán. Debe contener una máscara OR de WEXITED (vigilar la terminación del proceso hijo), WSTOPPED (vigilar que el proceso hijo se detenga por una señal) y WCONTINUED (vigilar que el proceso hijo se reanude por una señal). Ver waitid(2) para más información.

El handler debe ser una función a llamar cuando el proceso cambie de estado o NULL. A la función manejadora se le pasará el puntero userdata, que puede ser elegido libremente por el llamador. El manejador también recibe un puntero a una estructura siginfo_t que contiene información sobre el evento del proceso hijo. El manejador puede devolver un valor negativo para señalar un error (ver más abajo), otros valores de retorno se ignoran. Si handler es NULL, se utilizará un manejador por defecto que llama a sd_event_exit(3).

Solo se puede instalar un manejador para un proceso hijo específico. El manejador está habilitado para un solo evento (SD_EVENT_ONESHOT), pero esto puede cambiarse con sd_event_source_set_enabled(3). Si la función manejadora devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si el modo SD_EVENT_ON fue solicitado anteriormente, o provocará que el bucle termine, ver sd_event_source_set_exit_on_failure(3).

Para destruir un objeto de fuente de eventos, use sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se sueltan todas las referencias a ella. Para asegurarse de que una fuente de eventos no se active más, incluso cuando todavía hay una referencia a ella, considere establecer la fuente de eventos en SD_EVENT_OFF con sd_event_source_set_enabled(3).

La señal SIGCHLD debe estar bloqueada en todos los hilos antes de llamar a esta función (usando sigprocmask(2) o pthread_sigmask(3)).

Si el segundo parámetro de sd_event_add_child() se pasa como NULL, no se devuelve ninguna referencia al objeto de la fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando el propio bucle de eventos sea destruido.

Tenga en cuenta que la función handler se invoca en un momento en que el proceso hijo aún no ha sido recogido (y por lo tanto el kernel todavía lo expone como un proceso zombie). Sin embargo, el hijo será recogido automáticamente después de que la función devuelva. Los procesos hijos para los cuales no se instalan fuentes de eventos de cambio de estado de proceso hijo no serán recogidos por la implementación del bucle de eventos.

Si el parámetro handler de sd_event_add_child() es NULL, y la fuente de eventos se dispara, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a un entero, se pasa como parámetro de código de salida a sd_event_exit(3).

Si se instala una fuente de eventos de cambio de estado de proceso hijo y una fuente de eventos de señal SIGCHLD en el mismo bucle de eventos, las prioridades configuradas de las fuentes de eventos deciden qué fuente de eventos se despacha primero. Si se procesa primero el manejador de señal, este debería dejar sin recoger los procesos hijos para los cuales se han instalado fuentes de eventos de cambio de estado de proceso hijo.

sd_event_add_child_pidfd() es similar a sd_event_add_child() pero toma un descriptor de archivo que hace referencia al proceso ("pidfd") en lugar del PID numérico. Se puede obtener un descriptor de archivo adecuado a través de pidfd_open(2) y llamadas relacionadas. El descriptor de archivo pasado no se cierra cuando la fuente de eventos se libera de nuevo, a menos que se utilice sd_event_source_set_child_pidfd_own() para activar este comportamiento. Tenga en cuenta que independientemente de si se utiliza sd_event_add_child() o sd_event_add_child_pidfd() para asignar una fuente de eventos, el proceso vigilado debe ser un proceso hijo directo del proceso invocador. Además, en ambos casos, SIGCHLD debe estar bloqueado en el proceso invocador.

sd_event_source_get_child_pid() recupera el PID configurado de una fuente de eventos de cambio de estado de proceso hijo creada previamente con sd_event_add_child(). Toma el objeto de la fuente de eventos como parámetro source y un puntero a una variable pid_t para devolver el ID del proceso.

sd_event_source_get_child_pidfd() recupera el descriptor de archivo que hace referencia al proceso vigilado ("pidfd"). El bucle de eventos utiliza internamente pidfds para vigilar los procesos hijos, independientemente de si las fuentes de eventos individuales se asignan a través de sd_event_add_child() o sd_event_add_child_pidfd(). Si la última llamada se utilizó para asignar la fuente de eventos, esta función devuelve el descriptor de archivo original utilizado para la asignación. Esta llamada toma el objeto de la fuente de eventos como parámetro source y devuelve el descriptor de archivo numérico.

sd_event_source_get_child_pidfd_own() se puede usar para consultar si el pidfd que encapsula la fuente de eventos debe cerrarse cuando se libere la fuente de eventos. Esta función devuelve cero si el pidfd debe dejarse abierto y positivo si debe cerrarse automáticamente. Por defecto, esta configuración es activa si la fuente de eventos se asignó a través de sd_event_add_child() y desactivada si se asignó a través de sd_event_add_child_pidfd(). La función sd_event_source_set_child_pidfd_own() se puede usar para cambiar la configuración y toma un parámetro booleano con la nueva configuración.

sd_event_source_get_child_process_own() se puede usar para consultar si el proceso que vigila la fuente de eventos debe ser matado (con SIGKILL) y recogido cuando se libere la fuente de eventos. Esta función devuelve cero si el proceso debe dejarse en ejecución y positivo si debe ser matado y recogido automáticamente. Por defecto, esta configuración es desactivada. DESCRIPTION

These functions manage event sources for child processes. They allow registering handlers for events related to a child process, sending signals to the child process, and querying properties of the child process event source.

sd_event_add_child(), sd_event_add_child(3), is used to register a handler for state changes of a child process. The event source is created using the child's PID. The options parameter is a bitmask of flags, which must be a combination of WEXITED, WSTOPPED, and WCONTINUED.

sd_event_add_child_pidfd() is similar to sd_event_add_child(), but it takes a pidfd_open(2) file descriptor instead of a PID. This allows tracking processes that may change PIDs (e.g. after a user namespace transition).

sd_event_source_set_child_pidfd_own() and sd_event_source_get_child_pidfd_own() control whether the event source should take ownership of the pidfd_open(2) file descriptor. If set to true, the event source will close the file descriptor when it is destroyed. By default, ownership is not taken.

sd_event_source_set_child_process_own() and sd_event_source_get_child_process_own() control whether the event source should take ownership of the child process. If set to true, the event source will automatically call waitid(2) when the child process exits or stops. By default, ownership is not taken.

sd_event_source_get_child_pidfd() retrieves the event source associated with a child process PID.

sd_event_source_get_child_pidfd_pid() retrieves the PID associated with a child process event source.

sd_event_source_get_child_pidfd_pidfd() retrieves the pidfd file descriptor associated with a child process event source. This file descriptor is owned by the caller unless sd_event_source_set_child_pidfd_own() has been called with true.

sd_event_source_send_child_signal() may be used to send a UNIX signal to the watched process via pidfd_send_signal(2). The specified parameters match those of the underlying system call, except that the info is never modified (and is thus declared constant). Like for the underlying system call, the flags parameter currently must be zero.

RETURN VALUE

On success, these functions return 0 or a positive integer. On failure, they return a negative errno-style error code.

Errors

Returned errors may indicate the following problems:

-ENOMEM

Not enough memory to allocate an object.

-EINVAL

An invalid argument has been passed. This includes specifying an empty mask in options or a mask which contains values different than a combination of WEXITED, WSTOPPED, and WCONTINUED.

-EBUSY

A handler is already installed for this child process, or SIGCHLD is not blocked.

-ESTALE

The event loop is already terminated.

-ECHILD

The event loop has been created in a different process, library or module instance.

-EDOM

The passed event source is not a child process event source.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.

EXAMPLE

Example 1. Exit loop when the child terminates

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <assert.h>
#include <stdio.h>
#include <unistd.h>
#include <systemd/sd-event.h>
int main(int argc, char **argv) {
  pid_t pid = fork();
  assert(pid >= 0);
  /* SIGCHLD signal must be blocked for sd_event_add_child to work */
  sigset_t ss;
  sigemptyset(&ss);
  sigaddset(&ss, SIGCHLD);
  sigprocmask(SIG_BLOCK, &ss, NULL);
  if (pid == 0)  /* child */
    sleep(1);
  else {         /* parent */
    sd_event *e = NULL;
    int r;
    /* Create the default event loop */
    sd_event_default(&e);
    assert(e);
    /* We create a floating child event source (attached to 'e').
     * The default handler will be called with 666 as userdata, which
     * will become the exit value of the loop. */
    r = sd_event_add_child(e, NULL, pid, WEXITED, NULL, (void*) 666);
    assert(r >= 0);
    r = sd_event_loop(e);
    assert(r == 666);
    sd_event_unref(e);
  }
  return 0;
}
