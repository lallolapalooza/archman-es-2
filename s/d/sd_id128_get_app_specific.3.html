NOMBRE

sd_id128_get_machine, sd_id128_get_app_specific, sd_id128_get_machine_app_specific, sd_id128_get_boot, sd_id128_get_boot_app_specific, sd_id128_get_invocation - Recuperar IDs de 128 bits

SINOPSIS

#include <systemd/sd-id128.h>

int sd_id128_get_machine(sd_id128_t *ret);

int sd_id128_get_app_specific(sd_id128_t base, sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_machine_app_specific(sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_boot(sd_id128_t *ret);

int sd_id128_get_boot_app_specific(sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_invocation(sd_id128_t *ret);

int sd_id128_get_invocation_app_specific(sd_id128_t app_id, sd_id128_t *ret);

DESCRIPCIÓN

sd_id128_get_machine() devuelve el ID de máquina del host en ejecución. Lee y analiza el archivo machine-id(5). Esta función almacena en caché el ID de máquina internamente para hacer que recuperar el ID de máquina sea una operación barata. Este ID puede usarse dondequiera que se necesite un identificador único para el sistema local. Sin embargo, se recomienda usar este ID tal cual solo en entornos de confianza. En entornos no confiables, se recomienda derivar un ID específico de la aplicación de este ID de máquina, de forma irreversible (criptográficamente segura). Para facilitar esto, se proporciona sd_id128_get_machine_app_specific(), ver más abajo.

sd_id128_get_app_specific() devuelve un ID de máquina que es una combinación de los parámetros base y app_id. Internamente, esta función calcula HMAC-SHA256 del parámetro app_id usando el parámetro base como clave, trunca este resultado para que quepa en sd_id128_t y lo convierte en un UUID válido de Variante 1 Versión 4, de acuerdo con RFC 4122[1]. Ninguno de los dos parámetros de entrada puede calcularse a partir del parámetro de salida ret.

sd_id128_get_machine_app_specific() es similar a sd_id128_get_machine(), pero recupera un ID de máquina que es específico de la aplicación identificada por el ID de aplicación indicado. Se recomienda usar esta función en lugar de sd_id128_get_machine() al pasar un ID a entornos no confiables, para asegurarse de que el ID de máquina original no pueda determinarse externamente. De esta manera, el ID utilizado por la aplicación permanece estable en una determinada máquina, pero no puede correlacionarse fácilmente con los IDs utilizados en otras aplicaciones de la misma máquina. El ID específico de la aplicación debe generarse con una herramienta como systemd-id128 new y puede compilarse en la aplicación. Esta función devolverá el mismo ID específico de la aplicación para cada combinación de ID de máquina e ID de aplicación. Internamente, esta función llama a sd_id128_get_app_specific() con el resultado de sd_id128_get_machine() y el parámetro app_id.

sd_id128_get_boot() devuelve el ID de arranque del kernel en ejecución. Lee y analiza el archivo /proc/sys/kernel/random/boot_id expuesto por el kernel. Se genera aleatoriamente al principio del arranque y es único para cada instancia del kernel en ejecución. Ver random(4) para más información. Esta función también almacena en caché internamente el ID devuelto para que esta llamada sea una operación barata. Se recomienda usar este ID tal cual solo en entornos de confianza. En entornos no confiables, se recomienda derivar un ID específico de la aplicación usando sd_id128_get_boot_app_specific(), ver más abajo.

sd_id128_get_boot_app_specific() es análogo a sd_id128_get_machine_app_specific(), pero devuelve un ID que cambia entre arranques. Algunas máquinas pueden usarse durante mucho tiempo sin reiniciar, por lo tanto, el ID de arranque puede permanecer constante durante mucho tiempo y tiene propiedades similares al ID de máquina durante ese tiempo.

sd_id128_get_invocation() devuelve el ID de invocación del servicio actualmente ejecutado. En su implementación actual, intenta leer y analizar lo siguiente:

•La variable de entorno $INVOCATION_ID que el gestor de servicios establece al activar un servicio.
•Una entrada en el keyring del kernel que el gestor de servicios del sistema establece al activar un servicio.

Ver systemd.exec(5) para detalles. El ID se almacena en caché internamente. En el futuro, puede agregarse un mecanismo diferente para determinar el ID de invocación.

sd_id128_get_invocation_app_specific() deriva un ID específico de la aplicación del ID de invocación.

Tenga en cuenta que sd_id128_get_machine_app_specific(), sd_id128_get_boot(), sd_id128_get_boot_app_specific(), sd_id128_get_invocation() y sd_id128_get_invocation_app_specific siempre devuelven IDs compatibles con UUID Variante 1 Versión 4. sd_id128_get_machine() también devolverá un ID compatible con UUID Variante 1 Versión 4 en instalaciones nuevas, pero podría no hacerlo en las antiguas. Es posible convertir el ID de máquina de forma no reversible en uno compatible con UUID Variante 1 Versión 4. Para más información, ver machine-id(5). Por lo tanto, está garantizado que estas funciones nunca devolverán el ID que consta de todos los bits cero o todos los bits uno (SD_ID128_NULL, SD_ID128_ALLF) — con la posible excepción de sd_id128_get_machine(), como se mencionó.

Para más información sobre el tipo "sd_id128_t" ver sd-id128(3).

VALOR DE RETORNO

Estas llamadas devuelven 0 en caso de éxito (en cuyo caso ret se rellena), o un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOENT

Devuelto por sd_id128_get_machine() y sd_id128_get_machine_app_specific() cuando falta /etc/machine-id.

Añadido en la versión 242.

-ENOMEDIUM

Devuelto por sd_id128_get_machine() y sd_id128_get_machine_app_specific() cuando /etc/machine-id está vacío o son todos ceros. También devuelto por sd_id128_get_invocation() cuando el ID de invocación son todos ceros.

Añadido en la versión 242.

-ENOPKG

Devuelto por sd_id128_get_machine() y sd_id128_get_machine_app_specific() cuando el contenido de /etc/machine-id es "sin inicializar".

Añadido en la versión 253.

-ENOSYS

Devuelto por sd_id128_get_boot() y sd_id128_get_boot_app_specific() cuando /proc/ no está montado.

Añadido en la versión 253.

-ENXIO

Devuelto por sd_id128_get_invocation() si no hay ningún ID de invocación establecido. También devuelto por sd_id128_get_app_specific(), sd_id128_get_machine_app_specific(), y sd_id128_get_boot_app_specific() cuando el parámetro app_id son todos ceros.

Añadido en la versión 242.

-EUCLEAN

Devuelto por cualquiera de las funciones descritas aquí cuando el valor configurado tiene un formato inválido.

Añadido en la versión 253.

-EPERM

La información solicitada no pudo recuperarse debido a permisos insuficientes.

Añadido en la versión 242.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que está declarado como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

EJEMPLOS

Ejemplo 1. ID de máquina específico de la aplicación

Primero, genera el ID de la aplicación:

$ systemd-id128 new
f7f1001835994a13b25e7d76547a391e

Luego, úsalo en tu programa C:

#include <stdio.h>
#include <stdlib.h>
#include <systemd/sd-id128.h>

int main(int argc, char **argv) {
    sd_id128_t app_id;
    sd_id128_t machine_app_id;
    int r;

    if (argc < 2) {
        fprintf(stderr, "Usage: %s APP_ID\n", argv[0]);
        return 1;
    }

    r = sd_id128_from_string(argv[1], &app_id);
    if (r < 0) {
        fprintf(stderr, "Failed to parse application ID: %s\n", strerror(-r));
        return 1;
    }

    r = sd_id128_get_machine_app_specific(app_id, &machine_app_id);
    if (r < 0) {
        fprintf(stderr, "Failed to get machine-specific application ID: %s\n", strerror(-r));
        return 1;
    }

    printf("Machine-specific application ID: ");
    sd_id128_printn(stdout, machine_app_id, 0);
    printf("\n");

    return 0;
}

sd_id128_get_app_specific(3) — systemd — Arch manual pages

NAME

sd_id128_get_app_specific - obtener un identificador de aplicación específico del host

SYNOPSIS

#include <systemd/sd-id128.h>

sd_id128_t sd_id128_get_app_specific(sd_id128_t id);
sd_id128_t sd_id128_get_machine_app_specific(sd_id128_t id);
sd_id128_t sd_id128_get_boot_app_specific(sd_id128_t id);
sd_id128_t sd_id128_get_invocation_app_specific(sd_id128_t id);
int sd_id128_get_machine(sd_id128_t *id);
int sd_id128_get_boot(sd_id128_t *id);
int sd_id128_get_invocation(sd_id128_t *id);

DESCRIPTION

Estas funciones recuperan varios identificadores de 128 bits específicos de la máquina o del sistema, generalmente en forma de UUID.

La información del identificador se almacena en memoria y se genera la primera vez que se solicita. La información generada se almacena en el caché y se devuelve en las llamadas posteriores. Los identificadores generados de esta manera son consistentes en todos los reinicios del sistema, pero pueden cambiar si el sistema se reimplementa o si se modifican los datos subyacentes. La función sd_id128_get_machine_app_specific() recupera el identificador de la máquina en particular, que está asociado con /etc/machine-id.

La función sd_id128_get_boot_app_specific() recupera un identificador único para el arranque actual del sistema. Se genera basándose en el registro de arranque de firmware y los datos de tiempo de ejecución del kernel.

La función sd_id128_get_invocation_app_specific() recupera un identificador único para la invocación actual del proceso. Se basa en el identificador de arranque y el identificador de la máquina.

Las funciones sd_id128_get_machine_app_specific(), sd_id128_get_boot_app_specific() y sd_id128_get_invocation_app_specific() combinan el identificador dado id con el identificador de máquina, de arranque o de invocación, respectivamente. Esto permite crear identificadores únicos basados en los identificadores de máquina, arranque o invocación.

Las funciones sd_id128_get_machine(), sd_id128_get_boot() y sd_id128_get_invocation() recuperan los identificadores de máquina, arranque e invocación, respectivamente. Devuelven un código de error positivo en caso de éxito o un código de error negativo en caso de fallo.

Los identificadores se devuelven a través del puntero id. Los identificadores devueltos son de tipo sd_id128_t y pueden ser formateados e impresos usando las macros SD_ID128_FORMAT_STR y SD_ID128_FORMAT_VAL.

RETURN VALUE

Las funciones sd_id128_get_machine(), sd_id128_get_boot() y sd_id128_get_invocation() devuelven 0 en caso de éxito, o un código de error negativo en caso de fallo. Las funciones sd_id128_get_app_specific(), sd_id128_get_machine_app_specific(), sd_id128_get_boot_app_specific() y sd_id128_get_invocation_app_specific() devuelven el identificador solicitado.

NOTES

Estos identificadores solo deben usarse para fines de identificación de la máquina, el arranque o la invocación. No se deben usar para fines de autenticación o seguridad.

Los identificadores específicos de la aplicación, como los devueltos por sd_id128_get_machine_app_specific(), se generan combinando un identificador de aplicación definido por el usuario con un identificador de máquina específico del host. Esto garantiza que los identificadores generados sean únicos en todas las máquinas, incluso si el mismo identificador de aplicación se utiliza en varias máquinas.

Para generar un nuevo identificador de aplicación específico para un caso de uso particular, puede utilizar la utilidad systemd-id128(1).

$ systemd-id128 -p new
As string:
c273277323db454ea63bb96e79b53e97
As UUID:
c2732773-23db-454e-a63b-b96e79b53e97
As man:sd-id128(3) macro:
#define MESSAGE_XYZ SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
...

Luego use el nuevo identificador en una aplicación de ejemplo:

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <systemd/sd-id128.h>
#define OUR_APPLICATION_ID SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
int main(int argc, char *argv[]) {
  sd_id128_t id;
  sd_id128_get_machine_app_specific(OUR_APPLICATION_ID, &id);
  printf("Our application ID: " SD_ID128_FORMAT_STR "\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}
