NOMBRE

sd_event_wait, sd_event_prepare, sd_event_dispatch, sd_event_get_state, sd_event_get_iteration, SD_EVENT_INITIAL, SD_EVENT_PREPARING, SD_EVENT_ARMED, SD_EVENT_PENDING, SD_EVENT_RUNNING, SD_EVENT_EXITING, SD_EVENT_FINISHED - Operaciones de bajo nivel del bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>
enum {
        SD_EVENT_INITIAL,
        SD_EVENT_PREPARING,
        SD_EVENT_ARMED,
        SD_EVENT_PENDING,
        SD_EVENT_RUNNING,
        SD_EVENT_EXITING,
        SD_EVENT_FINISHED,
};

int sd_event_prepare(sd_event *event);

int sd_event_wait(sd_event *event, uint64_t usec);

int sd_event_dispatch(sd_event *event);

int sd_event_get_state(sd_event *event);

int sd_event_get_iteration(sd_event *event, uint64_t *ret);

DESCRIPCIÓN

Las funciones de bajo nivel sd_event_prepare(), sd_event_wait() y sd_event_dispatch() pueden ser utilizadas para ejecutar fases específicas de un bucle de eventos. Ver sd_event_run(3) y sd_event_loop(3) para funciones de nivel superior que ejecutan iteraciones individuales pero completas de un bucle de eventos o lo ejecutan continuamente.

sd_event_prepare() comprueba eventos pendientes y arma los temporizadores necesarios. Si hay eventos listos para ser procesados ("pendientes"), devuelve un valor positivo distinto de cero, y el llamador debe procesar estos eventos con sd_event_dispatch().

sd_event_dispatch() procesa la fuente de eventos de mayor prioridad que tiene un evento pendiente. Con éxito, sd_event_dispatch() devuelve cero, lo que indica que no se pueden procesar más fuentes de eventos y se solicitó la salida del bucle de eventos a través de sd_event_exit(3); o un valor positivo distinto de cero, lo que significa que se procesó una fuente de eventos y el bucle volvió a su estado inicial, y el llamador debe iniciar la siguiente iteración del bucle de eventos invocando de nuevo sd_event_prepare().

En caso de que sd_event_prepare() devolviera cero, sd_event_wait() debe ser llamado para esperar más eventos o un tiempo de espera. Si hay eventos listos para ser procesados, devuelve un valor positivo distinto de cero, y los eventos deben ser procesados con sd_event_dispatch(). De lo contrario, el bucle de eventos volvió a su estado inicial y la siguiente iteración del bucle de eventos debe ser iniciada invocando de nuevo sd_event_prepare().

sd_event_get_state() puede ser utilizado para determinar el estado actual del bucle de eventos. Devuelve uno de los estados descritos a continuación.

sd_event_get_iteration() puede ser utilizado para determinar la iteración actual del bucle de eventos. Devuelve un entero sin signo de 64 bits que contiene un contador que aumenta monótonamente con cada iteración del bucle de eventos, comenzando en 0. El contador se incrementa en el momento de la invocación de sd_event_prepare().

Las cinco funciones toman, como primer argumento, el objeto del bucle de eventos event que ha sido creado con sd_event_new(). El tiempo de espera para sd_event_wait() se especifica en usec en microsegundos. (uint64_t) -1 puede ser utilizado para especificar un tiempo de espera infinito.

MÁQUINA DE ESTADOS

El bucle de eventos conoce los siguientes estados, que pueden ser consultados con sd_event_get_state().

SD_EVENT_INITIAL

El estado inicial del bucle de eventos, antes de cada iteración del bucle de eventos. Usa sd_event_prepare() para transicionar el bucle de eventos a los estados SD_EVENT_ARMED o SD_EVENT_PENDING.

Añadido en la versión 229.

SD_EVENT_PREPARING

Actualmente se está preparando una fuente de eventos, es decir, el manejador de preparación se está ejecutando, tal como se estableció con sd_event_source_set_prepare(3). Este estado solo se ve en el manejador de preparación de eventos que se invoca desde la llamada a sd_event_prepare() y es seguido inmediatamente por SD_EVENT_ARMED o SD_EVENT_PENDING.

Añadido en la versión 229.

SD_EVENT_ARMED

Se ha llamado a sd_event_prepare() y ninguna fuente de eventos estaba lista para ser procesada. Usa sd_event_wait() para esperar nuevos eventos y transicionar a SD_EVENT_PENDING o de vuelta a SD_EVENT_INITIAL.

Añadido en la versión 229.

SD_EVENT_PENDING

Se ha llamado a sd_event_prepare() o sd_event_wait() y había fuentes de eventos con eventos pendientes. Usa sd_event_dispatch() para procesar la fuente de eventos de mayor prioridad y volver a SD_EVENT_INITIAL, o a SD_EVENT_FINISHED.

Añadido en la versión 229.

SD_EVENT_RUNNING

Actualmente se está procesando una fuente de eventos regular. Este estado solo se ve en el manejador de fuente de eventos que se invoca desde la llamada a sd_event_dispatch(), y es seguido inmediatamente por SD_EVENT_INITIAL o SD_EVENT_FINISHED tan pronto como el manejador de fuente de eventos regresa. Ten en cuenta que durante el procesamiento de fuentes de eventos de salida, se ve el estado SD_EVENT_EXITING en su lugar.

Añadido en la versión 229.

SD_EVENT_EXITING

Similar a SD_EVENT_RUNNING pero es el estado en efecto mientras se procesan fuentes de eventos de salida. Es seguido por SD_EVENT_INITIAL o SD_EVENT_FINISHED tan pronto como el manejador de eventos regresa.

Añadido en la versión 229.

SD_EVENT_FINISHED

El bucle de eventos ha salido. Todas las fuentes de eventos de salida se han ejecutado. Si el bucle de eventos está en este estado, ya no sirve para nada y debe ser liberado.

Añadido en la versión 229.

Un diagrama de flujo simplificado de los estados y las llamadas para transicionar entre ellos se muestra a continuación. Ten en cuenta que SD_EVENT_PREPARING, SD_EVENT_RUNNING y SD_EVENT_EXITING no se muestran aquí.

          INITIAL <---<---<---<---<---<---<---<---<---<---<---<---\
             |                                                     |
             |                                                     ^
             |                                                     |
             v                 ret == 0                            |
      sd_event_prepare() >--->--->--->---> ARMED                  |
             |                                |                    ^
             | ret > 0                        |                    |
             |                                |                    |
             v                                v          ret == 0  |
          PENDING <---<---<---<---< sd_event_wait() >--->--->--+
             |           ret > 0                                   ^
             |                                                     |
             |                                                     |
             v                                                     |
      sd_event_dispatch() >--->--->--->--->--->--->--->--->--->--->/
             |                             ret > 0
             | ret == 0
             |
             v
          FINISHED

VALOR DE RETORNO

Con éxito, estas funciones devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo estilo errno. En caso de sd_event_prepare() y sd_event_wait(), un código de retorno positivo y distinto de cero indica que hay eventos listos para ser procesados y cero indica que no hay eventos listos. En caso de sd_event_dispatch(), un código de retorno positivo y distinto de cero indica que el bucle de eventos volvió a su estado inicial y cero indica que el bucle de eventos ha salido. sd_event_get_state() devuelve un estado positivo o cero con éxito.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

El parámetro event es inválido o es NULL.

-EBUSY

El objeto del bucle de eventos no está en el estado correcto.

-ESTALE

El bucle de eventos ya está terminado.

-ENOMEM

No hay suficiente memoria disponible.

NAME

sd_event_prepare, sd_event_wait, sd_event_dispatch, sd_event_get_state, sd_event_get_iteration — Loop execution control

SYNOPSIS

#include <systemd/sd-event.h>

int sd_event_prepare(sd_event *u);
int sd_event_wait(sd_event *u, uint64_t usec);
int sd_event_dispatch(sd_event *u);
int sd_event_get_state(sd_event *u);
uint64_t sd_event_get_iteration(sd_event *u);

DESCRIPTION

The functions sd_event_prepare, sd_event_wait, and sd_event_dispatch are the core loop execution functions. They are typically called repeatedly by sd_event_run(3) to process events.

sd_event_prepare should be called before waiting for new events. It enters the idle state and invokes the prepare handlers registered with sd_event_source_set_prepare(3). If this function returns a value less than zero, the loop should terminate immediately.

sd_event_wait waits for events to occur. The usec parameter specifies the maximum time to wait in microseconds. If usec is 0, it will wait indefinitely until an event occurs. If it returns a value less than zero, the loop should terminate.

sd_event_dispatch processes the events that have occurred. It invokes the event handlers registered with the event sources. If it returns a value less than zero, the loop should terminate.

sd_event_get_state returns the current state of the event loop. This can be one of the following values:

SD_EVENT_INITIAL
The loop is being initialized.
SD_EVENT_PREPARE
The loop is in the prepare phase.
SD_EVENT_WAIT
The loop is waiting for events.
SD_EVENT_DISPATCH
The loop is dispatching events.
SD_EVENT_FINISH
The loop is finishing up.

sd_event_get_iteration returns the current iteration count of the event loop. This value is incremented each time the loop goes through the prepare-wait-dispatch cycle.

STATE MACHINE

The typical execution flow of an event loop is as follows:

  1. Initialize the loop using sd_event_new(3).
  2. Optionally, add event sources using functions like sd_event_add_io(3), sd_event_add_time(3), sd_event_add_signal(3), sd_event_add_child(3), sd_event_add_inotify(3), sd_event_add_defer(3).
  3. Start the event loop, typically by calling sd_event_run(3). Internally, sd_event_run repeatedly calls:

    1. sd_event_prepare
    2. sd_event_wait
    3. sd_event_dispatch

    This cycle continues until an error occurs or the loop is explicitly exited.

  4. Clean up the loop using sd_event_unref(3).

RETURN VALUE

On success, sd_event_prepare, sd_event_wait, and sd_event_dispatch return 0. On failure, they return a negative error number. Refer to sd-daemon(7) for a list of common error codes.

sd_event_get_state returns the current state of the event loop.

sd_event_get_iteration returns the current iteration count.

Possible errors include:

ECHILD
The event loop has been created in a different process, library or module instance.

Other errors are possible, too.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
