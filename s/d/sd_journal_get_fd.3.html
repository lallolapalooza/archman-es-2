NOMBRE

sd_journal_get_fd, sd_journal_get_events, sd_journal_get_timeout, sd_journal_process, sd_journal_wait, sd_journal_reliable_fd, SD_JOURNAL_NOP, SD_JOURNAL_APPEND, SD_JOURNAL_INVALIDATE - Interfaz de notificación de cambios del Journal

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_get_fd(sd_journal *j);

int sd_journal_get_events(sd_journal *j);

int sd_journal_get_timeout(sd_journal *j, uint64_t *timeout_usec);

int sd_journal_process(sd_journal *j);

int sd_journal_wait(sd_journal *j, uint64_t timeout_usec);

int sd_journal_reliable_fd(sd_journal *j);

DESCRIPCIÓN

sd_journal_get_fd() devuelve un descriptor de archivo que puede ser consultado de forma asíncrona en un bucle de eventos externo y que se activa tan pronto como el journal cambie, debido a que se añadieron nuevas entradas o archivos, se realizó una rotación, o se eliminaron archivos, etc. El descriptor de archivo es adecuado para su uso en poll(2). Use sd_journal_get_events() para una máscara de eventos a vigilar. La llamada toma un argumento: el objeto de contexto del journal. Tenga en cuenta que no todos los sistemas de archivos son capaces de generar los eventos necesarios para que las activaciones de este descriptor de archivo notifiquen los cambios inmediatamente. En particular, los sistemas de archivos de red no generan eventos de cambio de archivo adecuados en todos los casos. Estos casos se pueden detectar con sd_journal_reliable_fd(), más abajo. sd_journal_get_timeout() se asegurará en estos casos de que las activaciones ocurran con suficiente frecuencia para que los cambios sean notificados, aunque con cierta latencia.

sd_journal_get_events() devolverá la máscara de poll() a esperar. Esta función devolverá una combinación de POLLIN y POLLOUT y similares para rellenar el campo ".events" de struct pollfd.

sd_journal_get_timeout() devolverá un valor de tiempo de espera para usar en poll(). Devuelve un valor en microsegundos desde la época de CLOCK_MONOTONIC para agotar el tiempo de espera de poll() en timeout_usec. Consulte clock_gettime(2) para más detalles sobre CLOCK_MONOTONIC. Si no hay tiempo de espera, esto rellenará con (uint64_t) -1. Tenga en cuenta que poll() toma un tiempo de espera relativo en milisegundos en lugar de un tiempo de espera absoluto en microsegundos. Para convertir el tiempo de espera absoluto 'us' a 'ms' relativo, use código como el siguiente:

uint64_t t;
int msec;
sd_journal_get_timeout(m, &t);
if (t == (uint64_t) -1)
  msec = -1;
else {
  struct timespec ts;
  uint64_t n;
  clock_gettime(CLOCK_MONOTONIC, &ts);
  n = (uint64_t) ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
  msec = t > n ? (int) ((t - n + 999) / 1000) : 0;
}

El código anterior no realiza ninguna comprobación de errores por brevedad. El entero msec calculado se puede pasar directamente como parámetro de tiempo de espera de poll().

Después de cada activación de poll(), se debe llamar a sd_journal_process() para procesar los eventos. Esta llamada también indicará qué tipo de cambio se ha detectado (ver abajo; tenga en cuenta que son posibles activaciones espurias).

Una alternativa síncrona para usar sd_journal_get_fd(), sd_journal_get_events(), sd_journal_get_timeout() y sd_journal_process() es sd_journal_wait(). Esperará síncronamente hasta que el journal cambie. El tiempo máximo que esta llamada duerme puede controlarse con el parámetro timeout_usec. Pase (uint64_t) -1 para esperar indefinidamente. Internamente, esta llamada simplemente combina sd_journal_get_fd(), sd_journal_get_events(), sd_journal_get_timeout(), poll() y sd_journal_process() en una sola.

sd_journal_reliable_fd() se puede utilizar para comprobar si los eventos de activación del descriptor de archivo devuelto por sd_journal_get_fd() se activan rápidamente. En ciertos sistemas de archivos donde no hay eventos de cambio de archivo disponibles del sistema operativo (como NFS), los cambios deben ser consultados repetidamente, y por lo tanto solo se detectan con una latencia considerable. Esta llamada devolverá un valor positivo si los cambios del journal se detectan rápidamente y cero si se necesita consultarlos. Tenga en cuenta que generalmente no hay necesidad de invocar esta función directamente, ya que sd_journal_get_timeout() solicitará tiempos de espera apropiados de todas formas.

Tenga en cuenta que ninguna de las interfaces de notificación de cambios anteriores informa los cambios al instante. Se introducen latencias por múltiples razones: como se mencionó, ciertos backends de almacenamiento requieren sondeos basados en tiempo, en otros casos las activaciones se optimizan fusionando eventos, y el sistema operativo introduce latencias adicionales de planificación de E/S/CPU.

VALOR DE RETORNO

sd_journal_get_fd() devuelve un descriptor de archivo válido en caso de éxito o un código de error negativo estilo errno.

sd_journal_get_events() devuelve una combinación de POLLIN, POLLOUT y similares en caso de éxito o un código de error negativo estilo errno.

sd_journal_reliable_fd() devuelve un entero positivo si el descriptor de archivo devuelto por sd_journal_get_fd() generará activaciones inmediatas para todos los cambios del journal. Devuelve 0 si puede haber una latencia involucrada.

sd_journal_process() y sd_journal_wait() devuelven un código de error negativo estilo errno, o uno de SD_JOURNAL_NOP, SD_JOURNAL_APPEND o SD_JOURNAL_INVALIDATE en caso de éxito:

•Si se devuelve SD_JOURNAL_NOP, el journal no ha cambiado desde la última invocación.
•Si se devuelve SD_JOURNAL_APPEND, se han añadido nuevas entradas al final del journal. En este caso, es suficiente simplemente continuar leyendo en la ubicación final anterior del journal para leer las entradas recién añadidas.
•Si se devuelve SD_JOURNAL_INVALIDATE, se han añadido o eliminado archivos del journal del conjunto de archivos del journal que se están vigilando (por ejemplo, debido a rotación o limpieza), y por lo tanto las entradas pueden haber aparecido o desaparecido en lugares arbitrarios del flujo de registro, posiblemente antes o después del final anterior del flujo de registro. Si se devuelve SD_JOURNAL_INVALIDATE, las interfaces de vista en vivo que deseen reflejar en pantalla el estado preciso de los datos del registro en disco probablemente deberían actualizar toda su pantalla (en relación con el cursor de la entrada del registro en la parte superior de la pantalla). Los programas que solo estén interesados en un flujo estrictamente secuencial de datos de registro pueden tratar SD_JOURNAL_INVALIDATE de la misma manera que SD_JOURNAL_APPEND, ignorando así cualquier cambio en la vista del registro anterior al final anterior del flujo del registro.

SEGURIDAD DE SEÑALES

En general, sd_journal_get_fd(), sd_journal_get_events() y sd_journal_get_timeout() *no* son "seguras para señales asíncronas" en el sentido de signal-safety(7). Sin embargo, solo la primera llamada a cualquiera de estas tres funciones realiza operaciones inseguras, por lo que las llamadas posteriores *son* seguras.

sd_journal_process() y sd_journal_wait() no son seguras. sd_journal_reliable_fd() es segura.

NOTAS

Todas las funciones descritas aquí son agnósticas a hilos y solo un único hilo puede operar en un objeto dado en un momento dado. Diferentes hilos pueden acceder al mismo objeto en diferentes momentos. Múltiples objetos independientes pueden ser utilizados desde diferentes hilos en paralelo.

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd de pkg-config(1).

NAME

sd_journal_get_fd, sd_journal_get_events, sd_journal_get_timeout, sd_journal_process, sd_journal_wait, sd_journal_reliable_fd - monitor journal for new data

SYNOPSIS

#include <systemd/sd-journal.h>

int sd_journal_get_fd(sd_journal *j);

int sd_journal_get_events(sd_journal *j);

int sd_journal_get_timeout(sd_journal *j, uint64_t *usec);

int sd_journal_process(sd_journal *j);

int sd_journal_wait(sd_journal *j, uint64_t timeout_usec);

int sd_journal_reliable_fd(sd_journal *j);

DESCRIPTION

The functions described here allow monitoring the system journal for new entries. This is useful when implementing clients that want to process journal entries as they are written, without constantly polling the journal.

sd_journal_get_fd() retrieves the file descriptor that the journal monitor logic should be attached to. This file descriptor may be used with poll(2), select(2), or similar mechanisms to wait for journal changes.

sd_journal_get_events() retrieves the event mask that should be registered for the file descriptor returned by sd_journal_get_fd(). This mask should be used with poll(2) or similar functions.

sd_journal_get_timeout() retrieves the maximum time in microseconds to wait for journal changes. If the journal is configured to not block on writes (see sd_journal_stream_fd(3)), this might return a finite timeout. Otherwise, it returns (uint64_t)-1, indicating infinite wait. This value may be used as the timeout parameter for poll(2).

sd_journal_process() must be called after the file descriptor returned by sd_journal_get_fd() becomes ready (i.e., after poll(2) returns successfully). It processes any pending journal events and returns the number of new entries that have been scanned. If a negative value is returned, an error occurred.

sd_journal_wait() is a convenience function that combines poll(2) and sd_journal_process(). It waits until the file descriptor becomes ready, or until the specified timeout_usec has elapsed. If timeout_usec is 0, it checks immediately without blocking. If timeout_usec is (uint64_t)-1, it blocks indefinitely. It returns the number of new entries scanned, or a negative error code.

sd_journal_reliable_fd() retrieves a second file descriptor, similar to sd_journal_get_fd(), but this one is guaranteed to deliver all journal messages reliably, even if the journal is rotated or the client application stalls for a long time. This file descriptor should be used with the same event mask as returned by sd_journal_get_events(). Use of this function implies that you intend to read all messages, and do not want to miss any. Note that this may increase latency and memory usage.

RETURN VALUE

sd_journal_get_fd(), sd_journal_get_events(), sd_journal_reliable_fd() return the file descriptor or event mask on success, or a negative error code on failure. sd_journal_get_timeout() returns 0 on success, or a negative error code on failure. The timeout value is returned in *usec.

sd_journal_process() returns the number of new entries scanned on success, or a negative error code on failure. If no new entries are available, it returns 0.

sd_journal_wait() returns the number of new entries scanned on success, or a negative error code on failure. If the timeout expired without any new entries, it returns 0.

On success, these functions return a non-negative integer. On failure, they return a negative errno-style error code.

Possible error codes are:

-ENOMEM: Out of memory.

-ECHILD: The journal object is associated with a different process or thread.

-ESTALE: The journal file has been rotated and the monitor is no longer valid. This can only happen if you use sd_journal_reliable_fd(). In this case, you should close the journal object and reopen it.

-EBADFD: The journal object is invalid.

SIGNAL SAFETY

sd_journal_get_fd(), sd_journal_get_events(), sd_journal_get_timeout(), sd_journal_process(), sd_journal_wait(), and sd_journal_reliable_fd() are thread-safe.

sd_journal_process(), sd_journal_wait(), and sd_journal_reliable_fd() are not async-signal-safe. They should not be called from signal handlers.

NOTES

These functions operate on a journal object created with sd_journal_open(3).

It is recommended to use sd_journal_wait() instead of manually combining poll(2) and sd_journal_process(), as it is simpler and less error-prone.

If sd_journal_process() or sd_journal_wait() returns a positive value, it means new journal entries are available. You should then iterate through them using sd_journal_next(3) and related functions. After processing all available entries, you should call sd_journal_process() or sd_journal_wait() again to wait for more entries.

If sd_journal_process() or sd_journal_wait() returns 0, it means either the timeout expired or no new entries are available. You should call sd_journal_process() or sd_journal_wait() again to wait for more entries.

If sd_journal_reliable_fd() returns -ESTALE, it means the journal has been rotated. You need to close the current journal object and reopen it to continue processing from the beginning of the new journal.

EXAMPLES

Reading new entries continuously:

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <systemd/sd-journal.h>
int main(int argc, char *argv[]) {
  sd_journal *j = NULL;
  sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);
  sd_journal_add_filter(j, "PRIORITY=3"); /* Only informational messages */
  for (;;) {
    int r;
    /* Wait for new entries */
    r = sd_journal_wait(j, (uint64_t) -1);
    if (r < 0) {
      fprintf(stderr, "Failed to wait for journal entries: %s\n", strerror(-r));
      break;
    }
    /* Process new entries */
    while ((r = sd_journal_next(j)) > 0) {
      const char *d;
      size_t l;
      /* Get the MESSAGE field */
      r = sd_journal_get_data(j, "MESSAGE", &d, &l);
      if (r < 0) {
        fprintf(stderr, "Failed to get MESSAGE field: %s\n", strerror(-r));
        continue;
      }
      printf("%.*s\n", (int) l, d);
    }
    if (r < 0) {
      fprintf(stderr, "Failed to iterate journal: %s\n", strerror(-r));
      break;
    }
  }
  sd_journal_close(j);
  return 0;
}

Waiting with poll():

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <poll.h>
#include <time.h>
#include <systemd/sd-journal.h>
int wait_for_changes(sd_journal *j) {
  uint64_t t;
  int msec;
  struct pollfd pollfd;
  sd_journal_get_timeout(j, &t);
  if (t == (uint64_t) -1)
    msec = -1;
  else {
    struct timespec ts;
    uint64_t n;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    n = (uint64_t) ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
    msec = t > n ? (int) ((t - n + 999) / 1000) : 0;
  }
  pollfd.fd = sd_journal_get_fd(j);
  pollfd.events = sd_journal_get_events(j);
  poll(&pollfd, 1, msec);
  return sd_journal_process(j);
}
