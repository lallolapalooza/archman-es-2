sd_event_source_set_priority(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_EVENT_SOURCE_SET_PRIORITY(3) sd_event_source_set_priority SD_EVENT_SOURCE_SET_PRIORITY(3)

NOMBRE

sd_event_source_set_priority, sd_event_source_get_priority, SD_EVENT_PRIORITY_IMPORTANT, SD_EVENT_PRIORITY_NORMAL, SD_EVENT_PRIORITY_IDLE - Establecer u obtener la prioridad de las fuentes de eventos

SINOPSIS

#include <systemd/sd-event.h>
enum {
        SD_EVENT_PRIORITY_IMPORTANT = -100,
        SD_EVENT_PRIORITY_NORMAL = 0,
        SD_EVENT_PRIORITY_IDLE = 100,
};

int sd_event_source_set_priority(sd_event_source *source, int64_t priority);

int sd_event_source_get_priority(sd_event_source *source, int64_t *priority);

DESCRIPCIÓN

sd_event_source_set_priority() se puede usar para establecer la prioridad del objeto de fuente de eventos especificado como source. La prioridad se especifica como un entero arbitrario con signo de 64 bits. La prioridad se inicializa a SD_EVENT_PRIORITY_NORMAL (0) cuando la fuente de eventos se asigna con una llamada como sd_event_add_io(3) o sd_event_add_time(3), y se puede cambiar con esta llamada. Si múltiples fuentes de eventos han recibido eventos al mismo tiempo, se despachan en el orden indicado por las prioridades de las fuentes de eventos. Las fuentes de eventos con valores de prioridad más pequeños se despachan primero. Como puntos de referencia conocidos, las constantes SD_EVENT_PRIORITY_IMPORTANT (-100), SD_EVENT_PRIORITY_NORMAL (0) y SD_EVENT_PRIORITY_IDLE (100) se pueden usar para indicar fuentes de eventos que se despacharán temprano, normalmente o tarde. Se recomienda especificar las prioridades basándose en estas definiciones, y en relación con ellas; sin embargo, el rango completo de enteros con signo de 64 bits está disponible para ordenar las fuentes de eventos.

Las prioridades definen el orden en el que se despachan las fuentes de eventos que han recibido eventos. Se debe tener cuidado para asegurar que las fuentes de eventos de alta prioridad (aquellas con valores de prioridad negativos asignados) no causen inanición de fuentes de eventos de baja prioridad (aquellas con valores de prioridad positivos asignados).

El orden en que se despachan las fuentes de eventos con la misma prioridad no está definido, pero el bucle de eventos generalmente intenta despacharlas en el orden en que se enteró de los eventos en ellas. Como los primitivos del kernel subyacentes no proporcionan información precisa sobre el orden en que ocurrieron los eventos, esto no es necesariamente confiable. Sin embargo, se garantiza que si se ven eventos en múltiples fuentes de eventos de la misma prioridad al mismo tiempo, cada una no se despacha de nuevo hasta que todas las demás se hayan despachado una vez. Este comportamiento garantiza que dentro de cada prioridad particular, las fuentes de eventos no se mueren de hambre ni dominan el bucle de eventos.

La prioridad de las fuentes de eventos se puede cambiar en cualquier momento de su ciclo de vida, con la excepción de las fuentes de eventos inotify (es decir, aquellas creadas con sd_event_add_inotify(3)) cuya prioridad solo se puede cambiar en el tiempo entre su creación inicial y la primera iteración posterior del bucle de eventos.

sd_event_source_get_priority() se puede usar para consultar la prioridad actual asignada al objeto de fuente de eventos source.

VALOR DE RETORNO

En caso de éxito, sd_event_source_set_priority() y sd_event_source_get_priority() devuelven un entero no negativo. En caso de error, devuelven un código de error negativo de estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

source no es un puntero válido a un objeto sd_event_source.

-ENOMEM

No hay suficiente memoria.

-ESTALE

El bucle de eventos ya está terminado.

-ECHILD

El bucle de eventos se ha creado en un proceso, biblioteca o instancia de módulo diferente.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y vincular con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar solo llamadas a setenv() desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIAL

sd_event_source_set_priority() y sd_event_source_get_priority() se agregaron en la versión 229.
