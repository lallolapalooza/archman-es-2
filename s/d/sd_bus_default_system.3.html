DESCRIPCIÓN

sd_bus_default() adquiere un objeto de conexión de bus al bus de usuario cuando se invoca dentro de una "slice" de usuario (cualquier sesión bajo "user-*.slice", por ejemplo: "user@1000.service"), o al bus del sistema en caso contrario. El objeto de conexión está asociado al hilo llamador. Cada vez que la función se invoca desde el mismo hilo, se devuelve el mismo objeto, pero su contador de referencias se incrementa en uno, siempre que se mantenga al menos una referencia. Cuando se suelta la última referencia a la conexión (usando la llamada sd_bus_unref(3)), la conexión se termina. Tenga en cuenta que la conexión no se termina automáticamente cuando finaliza el hilo asociado. Es importante soltar la última referencia a la conexión del bus explícitamente antes de que finalice el hilo, ya que de lo contrario, la conexión se filtrará. Además, los mensajes en cola pero no leídos o no escritos mantienen una referencia al bus, ver más abajo.

sd_bus_default_user() devuelve un objeto de conexión al bus de usuario asociado al hilo llamador. sd_bus_default_system() es similar, pero se conecta al bus del sistema. Tenga en cuenta que sd_bus_default() es idéntico a estas dos llamadas, dependiendo del contexto de ejecución.

sd_bus_open() crea una nueva conexión de bus independiente al bus de usuario cuando se invoca en contexto de usuario, o al bus del sistema en caso contrario. sd_bus_open_user() es similar, pero solo se conecta al bus de usuario. sd_bus_open_system() hace lo mismo, pero se conecta al bus del sistema. A diferencia de sd_bus_default(), sd_bus_default_user() y sd_bus_default_system(), estas llamadas devuelven objetos de conexión nuevos e independientes que no están asociados con el hilo que los invoca y no se comparten entre múltiples invocaciones. Se recomienda compartir conexiones por hilo para utilizar eficientemente los recursos disponibles. Por lo tanto, se recomienda utilizar sd_bus_default(), sd_bus_default_user() y sd_bus_default_system() para conectarse a los buses de usuario o sistema.

sd_bus_open_with_description(), sd_bus_open_user_with_description() y sd_bus_open_system_with_description() son similares a sd_bus_open(), sd_bus_open_user() y sd_bus_open_system(), pero permiten establecer una cadena de descripción, ver sd_bus_set_description(3). description puede ser NULL, en cuyo caso esta función es equivalente a sd_bus_open(). Esta cadena de descripción se utiliza en los mensajes de registro sobre el objeto del bus, y la inclusión de un "nombre" para el bus facilita su comprensión. Algunos mensajes se emiten durante la inicialización del bus, por lo que el uso de esta función es preferible a establecer la descripción más tarde con sd_bus_open_with_description(). El argumento se copia internamente y no se referenciará después de que la función regrese.

Si la variable de entorno $DBUS_SESSION_BUS_ADDRESS está establecida (ver environ(7)), se utilizará como la dirección del bus de usuario. Esta variable puede contener múltiples direcciones separadas por ";". Si esta variable no está establecida, se utilizará un valor predeterminado adecuado para la instancia predeterminada del bus D de usuario.

Si la variable de entorno $DBUS_SYSTEM_BUS_ADDRESS está establecida, se utilizará como la dirección del bus del sistema. Esta variable utiliza la misma sintaxis que $DBUS_SESSION_BUS_ADDRESS. Si esta variable no está establecida, se utilizará un valor predeterminado adecuado para la instancia predeterminada del bus D del sistema.

sd_bus_open_system_remote() se conecta al bus del sistema en el host especificado utilizando ssh(1). host consiste en un nombre de usuario opcional seguido del símbolo "@", y el nombre del host, opcionalmente seguido de ":" y un puerto, opcionalmente seguido de "/" y un nombre de máquina. Si se proporciona el nombre de la máquina, se crea una conexión al bus del sistema en el contenedor especificado en la máquina remota, y de lo contrario, se crea una conexión al bus del sistema en el host especificado.

Tenga en cuenta que entrar en un contenedor es una operación privilegiada y probablemente solo funcionará para el usuario root en la máquina remota.

sd_bus_open_system_machine() se conecta al bus del sistema en la máquina especificada, donde máquina es el nombre de un contenedor local, posiblemente prefijado por un nombre de usuario y un separador "@". Si el nombre del contenedor se especifica como la cadena especial ".host", la conexión se realiza al sistema local. Esto es útil para conectarse al bus del sistema local como un usuario específico, por ejemplo, "foobar@.host" para conectarse al bus del sistema local como el usuario local "foobar". Si se utiliza la sintaxis "@", se puede omitir el lado izquierdo o el derecho (pero no ambos), en cuyo caso se implica el nombre de usuario local o ".host". Si no se utiliza la sintaxis "@", la conexión siempre se realiza como usuario root. Consulte sd_bus_set_address(3) para obtener una descripción de la sintaxis de la dirección, y machinectl(1) para obtener más información sobre el concepto de "máquina". Tenga en cuenta que las conexiones a contenedores locales solo están disponibles para procesos privilegiados en este momento.

sd_bus_open_user_machine() es similar a sd_bus_open_system_machine(), pero se conecta al bus de usuario del usuario root, o si se utiliza la sintaxis "@", del usuario especificado.

Estas llamadas asignan un objeto de conexión de bus e inician la conexión a un bus bien conocido de algún tipo. Una alternativa a usar estas llamadas de alto nivel es crear un objeto de bus no conectado con sd_bus_new(3) y conectarlo con sd_bus_start(3).

PROPIEDAD DE REFERENCIA

Las funciones sd_bus_open(), sd_bus_open_user(), sd_bus_open_user_machine(), sd_bus_open_system(), sd_bus_open_system_remote() y sd_bus_open_system_machine() devuelven un nuevo objeto de conexión y el llamador posee la única referencia. Cuando ya no sea necesario, esta referencia debe destruirse con sd_bus_unref(3).

Las funciones sd_bus_default(), sd_bus_default_user() y sd_bus_default_system() no necesariamente crean un nuevo objeto, sino que incrementan la referencia de conexión de un objeto de conexión existente en uno. Use sd_bus_unref(3) para soltar la referencia.

Los mensajes en cola pero no escritos/leídos mantienen una referencia a su objeto de conexión de bus. Por esta razón, incluso si una aplicación soltó todas las referencias a una conexión de bus, es posible que no se destruya de inmediato. Hasta que se lean todos los mensajes entrantes en cola y hasta que se escriban todos los mensajes salientes no escritos, el objeto del bus permanecerá activo. sd_bus_flush() puede usarse para escribir todos los mensajes salientes en cola para que suelten sus referencias. DESCRIPTION

El objeto bus de D-Bus gestionado por systemd se puede obtener con varias funciones. Las funciones sd_bus_default_system(), sd_bus_default_user() y sd_bus_default_login() devuelven punteros a objetos bus preconfigurados para el bus del sistema, el bus del usuario activo o el bus de inicio de sesión, respectivamente. Estos objetos bus son gestionados por la biblioteca y sus vidas están vinculadas a la del hilo o proceso de llamada. No se recomienda llamar a sd_bus_close() en estos objetos bus devueltos por las funciones `default`; en su lugar, se deben liberar automáticamente al terminar el hilo o proceso, o al llamar a sd_bus_unref().

Las funciones sd_bus_open(), sd_bus_open_user() y sd_bus_open_system() crean una nueva conexión bus independiente. El objeto bus devuelto debe ser liberado explícitamente llamando a sd_bus_unref() cuando ya no se necesite, o a sd_bus_close() para cerrar la conexión e inmediatamente después sd_bus_unref() para liberar el objeto.

sd_bus_open_system_remote() es similar a sd_bus_open_system(), pero se conecta a un bus del sistema remoto especificado por el parámetro destination. El parámetro destination debe especificar el nombre de la máquina remota (por ejemplo, un nombre de host o una dirección IP). La conexión se realiza a través de un túnel SSH.

sd_bus_open_system_machine() y sd_bus_open_user_machine() son similares a sd_bus_open_system() y sd_bus_open_user(), respectivamente, pero se conectan al bus D-Bus de una máquina específica gestionada por systemd-machined(8), según lo identificado por el parámetro machine.

sd_bus_open_with_description(), sd_bus_open_user_with_description() y sd_bus_open_system_with_description() son similares a sd_bus_open(), sd_bus_open_user() y sd_bus_open_system(), respectivamente, pero permiten especificar una cadena de descripción opcional para la conexión bus. Esta descripción puede ser útil para fines de depuración y monitoreo.

Las funciones sd_bus_default_*() devuelven un puntero a un objeto bus existente o crean uno nuevo si no existe uno asociado con el hilo actual. Este objeto bus es un singleton por hilo. Al llamar a sd_bus_unref() en un objeto bus devuelto por sd_bus_default_*(), no se libera la conexión bus hasta que el último hilo que referencia ese objeto bus llame a sd_bus_unref(). Si se requiere la finalización explícita de la conexión bus (por ejemplo, al cerrar una aplicación), se debe llamar primero a sd_bus_flush() y luego a sd_bus_close().

REFERENCE OWNERSHIP

Las funciones sd_bus_open_*() devuelven un nuevo objeto bus que el llamante debe poseer y liberar. La referencia se incrementa una vez, y se debe llamar a sd_bus_unref() para liberarla. Las funciones sd_bus_default_*() devuelven un puntero a un objeto bus existente que ya está referenciado. El llamante puede usarlo sin llamar a sd_bus_ref(), pero aún debe llamar a sd_bus_unref() cuando ya no lo necesite.

Cuando se trabaja con el bus por defecto y es necesario asegurarse de que todos los mensajes salientes se han enviado antes de cerrar la conexión, es una buena práctica invocar primero sd_bus_flush() y luego sd_bus_close() al terminar un hilo o proceso que debería liberar su objeto de conexión bus.

Normalmente, los objetos de slot (como los creados por sd_bus_add_match(3) y llamadas similares) también mantienen una referencia a su objeto de conexión bus. Por lo tanto, mientras un objeto de slot bus permanezca referenciado, su objeto bus también permanecerá asignado. Opcionalmente, los objetos de slot bus pueden colocarse en modo "flotante". Cuando está en modo flotante, el ciclo de vida del objeto de slot bus está ligado al objeto bus, es decir, cuando el objeto bus se libera, el objeto de slot bus también se desreferencia automáticamente. El estado flotante de un objeto de slot puede controlarse explícitamente con sd_bus_slot_set_floating(3), aunque normalmente los objetos de slot bus flotantes se crean pasando NULL como parámetro slot de sd_bus_add_match() y llamadas relacionadas, indicando así que el llamante no está directamente interesado en referenciar y gestionar el objeto de slot bus.

El ciclo de vida de la conexión bus por defecto debe ser responsabilidad del código que crea/posee el hilo con el que se asocia el objeto de conexión bus por defecto. El código de la biblioteca no debe llamar a sd_bus_flush() ni a sd_bus_close() en objetos bus por defecto, a menos que lo haga en su propio hilo privado y auto-asignado. El código de la biblioteca no debe usar el objeto bus por defecto en otros hilos, a menos que esté claro que el programa que lo utiliza gestionará el ciclo de vida del objeto de conexión bus y lo vaciará y cerrará antes de salir del hilo. Por lo tanto, en bibliotecas donde no está claro que el programa que llama gestionará el ciclo de vida del objeto de conexión bus, se recomienda usar sd_bus_open_system() en lugar de sd_bus_default_system() y llamadas relacionadas.

RETURN VALUE

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, estas llamadas devuelven un código de error negativo estilo errno.

Errors

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Los parámetros especificados no son válidos.

-ENOMEDIUM

El tipo de bus solicitado no está disponible debido a un entorno inválido (por ejemplo, el bus de sesión del usuario no está disponible porque $XDG_RUNTIME_DIR no está configurado).

-ENOMEM

Fallo de asignación de memoria.

-ESOCKTNOSUPPORT

La versión del protocolo requerida para conectarse al bus seleccionado no es compatible.

Además, pueden devolverse otros errores relacionados con la conexión. Véase sd_bus_send(3).

NOTES

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para múltiples hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
