NOMBRE

sd_bus_creds_new_from_pid, sd_bus_creds_new_from_pidfd, sd_bus_creds_get_mask, sd_bus_creds_get_augmented_mask, sd_bus_creds_ref, sd_bus_creds_unref, sd_bus_creds_unrefp - Recuperar el objeto de credenciales para el PID especificado

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_creds_new_from_pid(pid_t pid, uint64_t creds_mask, sd_bus_creds **ret);

int sd_bus_creds_new_from_pidfd(int pidfd, uint64_t creds_mask, sd_bus_creds **ret);

sd_bus_creds *sd_bus_creds_unref(sd_bus_creds *c);

void sd_bus_creds_unrefp(sd_bus_creds **c);

DESCRIPCIÓN

sd_bus_creds_new_from_pid() crea un nuevo objeto de credenciales y lo rellena con información sobre el proceso pid. El puntero a este objeto se almacenará en el puntero ret. Tenga en cuenta que los objetos de credenciales también pueden crearse y recuperarse a través de sd_bus_get_name_creds(3), sd_bus_get_owner_creds(3) y sd_bus_message_get_creds(3).

sd_bus_creds_new_from_pidfd() es idéntico a sd_bus_creds_new_from_pid(), pero toma un descriptor de archivo de PID en lugar de un PID numérico como referencia al proceso. Véase pidfd_open(2).

La información que se almacenará viene determinada por creds_mask. Puede contener un subconjunto de constantes ORed SD_BUS_CREDS_PID, SD_BUS_CREDS_PPID, SD_BUS_CREDS_TID, SD_BUS_CREDS_UID, SD_BUS_CREDS_EUID, SD_BUS_CREDS_SUID, SD_BUS_CREDS_FSUID, SD_BUS_CREDS_GID, SD_BUS_CREDS_EGID, SD_BUS_CREDS_SGID, SD_BUS_CREDS_FSGID, SD_BUS_CREDS_SUPPLEMENTARY_GIDS, SD_BUS_CREDS_COMM, SD_BUS_CREDS_TID_COMM, SD_BUS_CREDS_EXE, SD_BUS_CREDS_CMDLINE, SD_BUS_CREDS_CGROUP, SD_BUS_CREDS_UNIT, SD_BUS_CREDS_SLICE, SD_BUS_CREDS_USER_UNIT, SD_BUS_CREDS_USER_SLICE, SD_BUS_CREDS_SESSION, SD_BUS_CREDS_OWNER_UID, SD_BUS_CREDS_EFFECTIVE_CAPS, SD_BUS_CREDS_PERMITTED_CAPS, SD_BUS_CREDS_INHERITABLE_CAPS, SD_BUS_CREDS_BOUNDING_CAPS, SD_BUS_CREDS_SELINUX_CONTEXT, SD_BUS_CREDS_AUDIT_SESSION_ID, SD_BUS_CREDS_AUDIT_LOGIN_UID, SD_BUS_CREDS_TTY, SD_BUS_CREDS_UNIQUE_NAME, SD_BUS_CREDS_WELL_KNOWN_NAMES, SD_BUS_CREDS_DESCRIPTION, y SD_BUS_CREDS_PIDFD. Utilice el valor especial _SD_BUS_CREDS_ALL para solicitar todos los campos compatibles. La constante SD_BUS_CREDS_AUGMENT no puede OR-earse en la máscara para las invocaciones de sd_bus_creds_new_from_pid() o sd_bus_creds_new_from_pidfd().

Los campos se pueden recuperar del objeto de credenciales usando sd_bus_creds_get_pid(3) y otras funciones que corresponden directamente a las constantes listadas anteriormente.

Una máscara de los campos que se recuperaron con éxito se puede obtener con sd_bus_creds_get_mask(). Si el objeto de credenciales se creó con sd_bus_creds_new_from_pid() o sd_bus_creds_new_from_pidfd(), será un subconjunto de los campos solicitados en creds_mask.

Similar a sd_bus_creds_get_mask(), la función sd_bus_creds_get_augmented_mask() devuelve una máscara de bits de los campos. La máscara indica qué campos de credenciales se recuperaron de forma no atómica. Para objetos de credenciales creados a través de sd_bus_creds_new_from_pid() o sd_bus_creds_new_from_pidfd(), esta máscara será idéntica a la máscara devuelta por sd_bus_creds_get_mask(). Sin embargo, para objetos de credenciales recuperados a través de sd_bus_get_name_creds(), esta máscara se establecerá para los campos de credenciales que no pudieron determinarse atómicamente en el momento de la conexión del par, y que posteriormente se añadieron leyendo datos de credenciales de aumento de /proc/. De manera similar, para objetos de credenciales recuperados a través de sd_bus_get_owner_creds(), la máscara se establece para los campos que no pudieron determinarse atómicamente en el momento de la creación del bus, pero que se han aumentado. De manera similar, para objetos de credenciales recuperados a través de sd_bus_message_get_creds(), la máscara se establece para los campos que no pudieron determinarse atómicamente en el momento del envío del mensaje, pero que se han aumentado. La máscara devuelta por sd_bus_creds_get_augmented_mask() es siempre un subconjunto de (o idéntica a) la máscara devuelta por sd_bus_creds_get_mask() para el mismo objeto. La última llamada, por lo tanto, devuelve todos los campos de credenciales disponibles en el objeto de credenciales, la primera marca el subconjunto de aquellos que se han aumentado. Tenga en cuenta que los campos aumentados no son adecuados para decisiones de autorización, ya que pueden recuperarse en momentos diferentes, estando sujetos a condiciones de carrera. Por lo tanto, los campos aumentados deben usarse exclusivamente con fines informativos.

sd_bus_creds_ref() crea una nueva referencia al objeto de credenciales c. Este objeto no se destruirá hasta que sd_bus_creds_unref() se haya llamado tantas veces más una vez. Una vez que el contador de referencias ha caído a cero, c ya no puede usarse, por lo que las llamadas posteriores a sd_bus_creds_ref(c) o sd_bus_creds_unref(c) son ilegales.

sd_bus_creds_unref() destruye una referencia a c.

sd_bus_creds_unrefp() es similar a sd_bus_creds_unref() pero toma un puntero a un puntero a un objeto sd_bus_creds. Esta llamada es útil en conjunción con el Atributo de Variable de Limpieza de GCC y LLVM[1]. Tenga en cuenta que esta función se define como una función en línea.

sd_bus_creds_ref(), sd_bus_creds_unref() y sd_bus_creds_unrefp() no realizan ninguna operación si el objeto de credenciales del bus pasado es NULL.

VALOR DE RETORNO

En caso de éxito, sd_bus_creds_new_from_pid() y sd_bus_creds_new_from_pidfd() devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo estilo errno.

sd_bus_creds_get_mask() devuelve la máscara de campos adquiridos con éxito.

sd_bus_creds_get_augmented_mask() devuelve la máscara de campos que se han aumentado a partir de datos en /proc/, y por lo tanto no son adecuados para decisiones de autorización.

sd_bus_creds_ref() siempre devuelve el argumento.

sd_bus_creds_unref() siempre devuelve NULL.

PROPIEDAD DE REFERENCIA

Las funciones sd_bus_creds_new_from_pid() y sd_bus_creds_new_from_pidfd() crean un nuevo objeto y el llamador posee la única referencia. Cuando ya no se necesite, esta referencia debe destruirse con sd_bus_creds_unref(3).

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ESRCH

No se pudo encontrar el pid especificado.

-EPERM

El proceso especificado no pertenece al mismo usuario efectivo que el proceso de llamada.

-EACCES

Se denegó el acceso a la información del proceso especificado.

-ENOENT

El descriptor de archivo pidfd no es válido.

-EINVAL

Se proporcionó un valor creds_mask inválido.

-ENOMEM

Memoria insuficiente para el objeto de credenciales.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, la cual se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar las llamadas a setenv() solo desde una fase temprana del programa cuando aún no se han iniciado otros hilos.
