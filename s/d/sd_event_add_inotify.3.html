sd_event_add_inotify(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_EVENT_ADD_INOTIFY(3) sd_event_add_inotify SD_EVENT_ADD_INOTIFY(3)

NOMBRE

sd_event_add_inotify, sd_event_add_inotify_fd, sd_event_source_get_inotify_mask, sd_event_source_get_inotify_path, sd_event_inotify_handler_t - Añadir una fuente de eventos de inodo del sistema de archivos "inotify" a un bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_inotify_handler_t)(sd_event_source *s, const struct inotify_event *event, void *userdata);

int sd_event_add_inotify(sd_event *event, sd_event_source **source, const char *path, uint32_t mask, sd_event_inotify_handler_t handler, void *userdata);

int sd_event_add_inotify_fd(sd_event *event, sd_event_source **source, int fd, uint32_t mask, sd_event_inotify_handler_t handler, void *userdata);

int sd_event_source_get_inotify_mask(sd_event_source *source, uint32_t *ret);

int sd_event_source_get_inotify_path(sd_event_source *source, const char **ret);

DESCRIPCIÓN

sd_event_add_inotify() añade una nueva fuente de eventos de inodo del sistema de archivos inotify(7) a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro path especifica la ruta del inodo del sistema de archivos a vigilar. El parámetro mask especifica qué tipos de eventos de inodo vigilar específicamente. Debe contener una combinación OR-eada de las banderas IN_ACCESS, IN_ATTRIB, IN_CLOSE_WRITE, etc. Consulte inotify(7) para más información.

El parámetro handler debe referenciar una función a llamar cuando el inodo cambie o NULL. La función manejadora recibirá el puntero userdata, que puede ser elegido libremente por el llamador. La manejadora también recibe un puntero a una estructura inotify_event que contiene información sobre el evento del inodo. La manejadora puede devolver un valor negativo para señalar un error (ver abajo), otros valores de retorno se ignoran. Si handler es NULL, se utilizará una manejadora por defecto que llama a sd_event_exit(3).

sd_event_add_inotify_fd() es idéntica a sd_event_add_inotify(), excepto que toma un descriptor de archivo a un inodo (posiblemente uno O_PATH, pero cualquiera otro también servirá) en lugar de una ruta en el sistema de archivos.

Si se instalan múltiples fuentes de eventos para el mismo inodo, el descriptor de vigilancia inotify subyacente se comparte automáticamente. El parámetro mask puede contener cualquier bandera definida por la API de inotify, con la excepción de IN_MASK_ADD.

La manejadora está habilitada continuamente (SD_EVENT_ON), pero esto puede cambiarse con sd_event_source_set_enabled(3). Alternativamente, la bandera de máscara IN_ONESHOT puede usarse para solicitar el modo SD_EVENT_ONESHOT. Si la función manejadora devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si se solicitó el modo SD_EVENT_ON previamente.

Como limitación especial, la prioridad de las fuentes de eventos inotify solo puede modificarse (ver sd_event_source_set_priority(3)) en el tiempo entre la creación del objeto de fuente de eventos con sd_event_add_inotify() y el inicio de la siguiente iteración del bucle de eventos. Los intentos de cambiar la prioridad más tarde serán rechazados. Considere liberar y asignar una nueva fuente de eventos inotify para cambiar la prioridad en ese momento.

Para destruir un objeto de fuente de eventos, use sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se liberan todas las referencias a ella. Para asegurarse de que una fuente de eventos no se active más, incluso cuando todavía hay una referencia a ella, considere deshabilitarla con sd_event_source_set_enabled(3).

Si el segundo parámetro de sd_event_add_inotify() se pasa como NULL, no se devuelve ninguna referencia al objeto de fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando el propio bucle de eventos sea destruido.

Si el parámetro handler de sd_event_add_inotify() es NULL, y la fuente de eventos se activa, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a entero, se pasa como parámetro de código de salida a sd_event_exit(3).

sd_event_source_get_inotify_mask() recupera la máscara de vigilancia inotify configurada de una fuente de eventos creada previamente con sd_event_add_inotify(). Toma el objeto de fuente de eventos como parámetro source y un puntero a una variable uint32_t para devolver la máscara.

sd_event_source_get_inotify_path() recupera la ruta de destino de la vigilancia inotify configurada de una fuente de eventos creada previamente con sd_event_add_inotify(). Toma el objeto de fuente de eventos como parámetro source y un puntero a una variable const char ** para devolver la ruta. El llamador no debe liberar la ruta devuelta.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay memoria suficiente para asignar un objeto.

-EINVAL

Se ha pasado un argumento inválido. Esto incluye especificar una máscara con IN_MASK_ADD establecida.

-ESTALE

Devuelto por sd_event_source_add_inotify() o sd_event_source_add_inotify_fd() cuando el bucle de eventos ya está terminado. Devuelto por sd_event_source_get_inotify_path() cuando no hay datos de inodo activos asignados a la fuente de eventos, p.ej. cuando la fuente de eventos está deshabilitada.

-ECHILD

El bucle de eventos se creó en un proceso, biblioteca o instancia de módulo diferente.

-EDOM

La fuente de eventos pasada no es una fuente de eventos de proceso inotify.

-EBADF

El descriptor de archivo pasado no es válido.

-ENOSYS

Se llamó a sd_event_add_inotify_fd() o sd_event_source_get_inotify_path() sin montar /proc/.

EJEMPLOS

Ejemplo 1. Un programa simple que usa inotify para monitorizar uno o dos directorios

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <string.h>
#include <sys/inotify.h>
#include <systemd/sd-event.h>
#define _cleanup_(f) __attribute__((cleanup(f)))
static int inotify_handler(sd_event_source *source,
                           const struct inotify_event *event,
                           void *userdata) {
  const char *desc = NULL;
  sd_event_source_get_description(source, &desc);
  if (event->mask & IN_Q_OVERFLOW)
    printf("inotify-handler <%s>: overflow\n", desc);
  else if (event->mask & IN_CREATE)
    printf("inotify-handler <%s>: create on %s\n", desc, event->name);
  else if (event->mask & IN_DELETE)
    printf("inotify-handler <%s>: delete on %s\n", desc, event->name);
  else if (event->mask & IN_MOVED_TO)
    printf("inotify-handler <%s>: moved-to on %s\n", desc, event->name);
  /* Terminar el programa si aparece un archivo "exit" */
  if ((event->mask & (IN_CREATE|IN_MOVED_TO)) &&
      strcmp(event->name, "exit") == 0)
    sd_event_exit(sd_event_source_get_event(source), 0);
  return 1;
}
int main(int argc, char **argv) {
  _cleanup_(sd_event_unrefp) sd_event *event = NULL;
  _cleanup_(sd_event_source_unrefp) sd_event_source *source1 = NULL, *source2 = NULL;
  const char *path1 = argc > 1 ? argv[1] : "/tmp";
const char *path2 = argc > 2 ? argv[2] : NULL; /* Nota: el manejo de errores se omite por brevedad */ sd_event_default(&event); sd_event_add_inotify(event, &source1, path1, IN_CREATE | IN_DELETE | IN_MODIFY | IN_MOVED_TO, inotify_handler, NULL); if (path2) sd_event_add_inotify(event, &source2, path2, IN_CREATE | IN_DELETE | IN_MODIFY | IN_MOVED_TO, inotify_handler, NULL); sd_event_loop(event); return 0; } ```

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un subproceso paralelo. Se recomienda realizar solo llamadas a setenv() desde una fase temprana del programa cuando aún no se han iniciado otros subprocesos.
