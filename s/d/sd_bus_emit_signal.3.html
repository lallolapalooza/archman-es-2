NOMBRE

sd_bus_emit_signal, sd_bus_emit_signalv, sd_bus_emit_signal_to, sd_bus_emit_signal_tov, sd_bus_emit_interfaces_added, sd_bus_emit_interfaces_added_strv, sd_bus_emit_interfaces_removed, sd_bus_emit_interfaces_removed_strv, sd_bus_emit_properties_changed, sd_bus_emit_properties_changed_strv, sd_bus_emit_object_added, sd_bus_emit_object_removed - Funciones de conveniencia para emitir señales D-Bus (estándar)

#include <systemd/sd-bus-vtable.h>

int sd_bus_emit_signal(sd_bus *bus, const char *path, const char *interface, const char *member, const char *types, ...);

int sd_bus_emit_object_removed(sd_bus *bus, const char *path);

DESCRIPCIÓN

sd_bus_emit_signal() es una función de conveniencia para inicializar un objeto de mensaje de bus y emitir la señal D-Bus correspondiente. Combina las funciones sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) en una única llamada a función. sd_bus_emit_signalv() es equivalente a sd_bus_message_append(), excepto que se llama con una "va_list" en lugar de un número variable de argumentos.

sd_bus_emit_signal_to() y sd_bus_emit_signal_tov() son idénticas a sd_bus_emit_signal() y sd_bus_emit_signalv(), excepto que pueden emitir la señal a un único destino. Proporcione destination como NULL para difundir la señal.

sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() se utilizan para implementar las señales InterfacesAdded y InterfacesRemoved de la interfaz org.freedesktop.DBus.ObjectManager. Toman una ruta de objeto cuyas interfaces han sido modificadas como argumento y una lista variable de interfaces que se han añadido o eliminado, respectivamente. El último argumento pasado a sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() debe ser NULL. Esto permite que ambas funciones determinen de forma segura el número de argumentos de interfaz pasados. sd_bus_emit_interfaces_added_strv() y sd_bus_emit_interfaces_removed_strv() son idénticas a sus contrapartes respectivas pero ambas toman la lista de interfaces como un único argumento en lugar de un número variable de argumentos.

sd_bus_emit_properties_changed() se utiliza para implementar la señal PropertiesChanged de la interfaz org.freedesktop.DBus.Properties. Toma una ruta de objeto, una interfaz y una lista variable de nombres de propiedades como sus argumentos. El último argumento pasado a sd_bus_emit_properties_changed() debe ser NULL. Esto le permite determinar de forma segura el número de nombres de propiedad pasados. sd_bus_emit_properties_changed_strv() es idéntica a sd_bus_emit_properties_changed() pero toma la lista de nombres de propiedad como un único argumento en lugar de un número variable de argumentos.

sd_bus_emit_object_added() y sd_bus_emit_object_removed() son funciones de conveniencia para emitir las señales InterfacesAdded o InterfacesRemoved para todas las interfaces registradas en una ruta de objeto específica, respectivamente. Esto incluye cualquier vtable de reserva padre si no se anulan mediante una vtable hija más aplicable. También incluye todas las interfaces D-Bus estándar implementadas por el propio sd-bus en cualquier objeto registrado.

Tenga en cuenta que sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() y sd_bus_emit_object_removed() requieren que se haya registrado un gestor de objetos en la ruta de objeto dada o en una de sus rutas de objeto padre utilizando sd_bus_add_object_manager(3).

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un entero no negativo. En caso de error, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Uno de los parámetros requeridos es NULL o inválido. Se pasó una interfaz D-Bus reservada como parámetro interface.

-ENOPKG

El bus no se puede resolver.

-ECHILD

El bus se creó en un proceso, biblioteca o instancia de módulo diferente.

-ENOMEM

Fallo en la asignación de memoria.

-ESRCH

Se llamó a uno de los sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() o sd_bus_emit_object_removed() en un objeto sin un gestor de objetos registrado en su propia ruta de objeto o en una de sus rutas de objeto padre.

Consulte las páginas del manual de sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) para ver más posibles errores.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y vincular con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

sd_bus_emit_signal(3) — systemd libs

NAME

sd_bus_emit_signal, sd_bus_emit_signalv, sd_bus_emit_signal_to, sd_bus_emit_signal_tov - Enviar una señal de bus

SYNOPSIS

#include <systemd/sd-bus.h>
int sd_bus_emit_signal(sd_bus *bus, const char *path, const char *interface, const char *member, const char *fmt, ...);
int sd_bus_emit_signalv(sd_bus *bus, const char *path, const char *interface, const char *member, const char *fmt, va_list ap);
int sd_bus_emit_signal_to(sd_bus *bus, const char *destination, const char *path, const char *interface, const char *member, const char *fmt, ...);
int sd_bus_emit_signal_tov(sd_bus *bus, const char *destination, const char *path, const char *interface, const char *member, const char *fmt, va_list ap);

DESCRIPTION

These functions may be used to send a D-Bus signal.

The signal is constructed from the arguments provided. The path, interface, and member arguments specify the object path, the interface name, and the member name of the signal. The fmt string describes the types of the arguments to the signal, and the remaining arguments are the values themselves. The formatting string syntax is identical to that of sd_bus_message_append(3).

The bus parameter is the bus connection to use. The signal is sent via this connection.

If destination is not NULL in sd_bus_emit_signal_to() and sd_bus_emit_signal_tov(), the signal will only be delivered to that specific bus name. Otherwise, it is sent to all listeners.

sd_bus_emit_signal() and sd_bus_emit_signal_to() are variadic functions. sd_bus_emit_signalv() and sd_bus_emit_signal_tov() are similar but take the arguments in a va_list.

The arguments are appended to the message body in the order they appear in the fmt string. The fmt string itself uses the same type specifiers as sd_bus_message_append(3).

After the signal message is constructed, it is sent to the bus daemon using sd_bus_send(3). The function call will block until the message is sent or an error occurs.

RETURN VALUE

On success, these functions return a non-negative integer representing the serial number of the message sent. On failure, they return a negative error number.

NOTES

These functions are convenient wrappers around sd_bus_message_new_signal(3), sd_bus_message_append(3), and sd_bus_send(3).

For asynchronous sending of signals, consider using sd_bus_message_new_signal(3) and sd_bus_send(3) directly.

Signals are immutable messages. Once created, they cannot be modified. This means that they should be created and sent in a single operation.

The path, interface, member, and destination strings are copied by the function. They do not need to be persistent after the call returns.

HISTORY
