sd_journal_seek_realtime_usec(3)

SD_JOURNAL_SEEK_HEAD(3) sd_journal_seek_head SD_JOURNAL_SEEK_HEAD(3)

NOMBRE

sd_journal_seek_head, sd_journal_seek_tail, sd_journal_seek_monotonic_usec, sd_journal_seek_realtime_usec, sd_journal_seek_cursor - Buscar una posición en el journal

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_seek_head(sd_journal *j);

int sd_journal_seek_tail(sd_journal *j);

int sd_journal_seek_monotonic_usec(sd_journal *j, sd_id128_t boot_id, uint64_t usec);

int sd_journal_seek_realtime_usec(sd_journal *j, uint64_t usec);

int sd_journal_seek_cursor(sd_journal *j, const char *cursor);

DESCRIPCIÓN

sd_journal_seek_head() busca al principio del journal, es decir, a la posición anterior a la entrada más antigua disponible.

De forma similar, sd_journal_seek_tail() puede usarse para buscar al final del journal, es decir, a la posición posterior a la entrada más reciente disponible.

sd_journal_seek_monotonic_usec() busca a una posición con la marca de tiempo monotónica especificada, es decir, CLOCK_MONOTONIC. Dado que el tiempo monotónico se reinicia en cada reinicio, también se debe especificar un ID de arranque.

sd_journal_seek_realtime_usec() busca a una posición con la marca de tiempo de tiempo real (reloj de pared) especificada, es decir, CLOCK_REALTIME. Tenga en cuenta que el reloj de tiempo real no es necesariamente monotónico. Si una marca de tiempo de tiempo real es ambigua, no se define a qué posición se busca.

sd_journal_seek_cursor() busca a la posición de la cadena de cursor especificada. Para obtener detalles sobre los cursores, consulte sd_journal_get_cursor(3). Si no se encuentra ninguna entrada que coincida con el cursor especificado, la llamada buscará la entrada más cercana en su lugar (en términos de tiempo).

Tenga en cuenta que estas llamadas en realidad no hacen que ninguna entrada sea la nueva entrada actual; esto debe hacerse en un paso separado con una invocación posterior de sd_journal_next(3) (o una llamada similar). Solo entonces, los datos de la entrada pueden ser recuperados a través de sd_journal_get_data(3) o un cursor de entrada puede ser recuperado a través de sd_journal_get_cursor(3). Si no existe ninguna entrada que coincida exactamente con la dirección de búsqueda especificada, se buscará la más cercana. Si se utiliza sd_journal_next(3), se buscará la entrada siguiente más cercana; si se utiliza sd_journal_previous(3), se buscará la entrada anterior más cercana.

Después de realizar la búsqueda y haber realizado sd_journal_next(3) o una llamada similar, sd_journal_test_cursor(3) puede usarse para verificar si la entrada recién seleccionada realmente coincide con el cursor.

VALOR DE RETORNO

Las funciones devuelven 0 si la operación tuvo éxito o un código de error negativo estilo errno.

NOTAS

Todas las funciones aquí descritas son agnósticas a hilos y solo un hilo puede operar en un objeto dado en un momento dado. Diferentes hilos pueden acceder al mismo objeto en diferentes momentos. Se pueden utilizar múltiples objetos independientes desde diferentes hilos en paralelo.

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

HISTORIAL

sd_journal_seek_head(), sd_journal_seek_tail(), sd_journal_seek_monotonic_usec(), sd_journal_seek_realtime_usec(), y sd_journal_seek_cursor() se añadieron en la versión 187.
