sd_bus_slot_get_destroy_callback(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_SLOT_SET_DESTROY_CALLBACK(3) sd_bus_slot_set_destroy_callback SD_BUS_SLOT_SET_DESTROY_CALLBACK(3)

NOMBRE

sd_bus_slot_set_destroy_callback, sd_bus_slot_get_destroy_callback, sd_bus_track_set_destroy_callback, sd_bus_track_get_destroy_callback, sd_bus_destroy_t - Definir la función de retorno de llamada para la limpieza de recursos

SINOPSIS

#include <systemd/sd-bus.h>

typedef int (*sd_bus_destroy_t)(void *userdata);

int sd_bus_slot_set_destroy_callback(sd_bus_slot *slot, sd_bus_destroy_t callback);

int sd_bus_slot_get_destroy_callback(sd_bus_slot *slot, sd_bus_destroy_t *callback);

int sd_bus_track_set_destroy_callback(sd_bus_track *track, sd_bus_destroy_t callback);

int sd_bus_track_get_destroy_callback(sd_bus_track *track, sd_bus_destroy_t *callback);

DESCRIPCIÓN

sd_bus_slot_set_destroy_callback() establece callback como la función de retorno de llamada que se llamará justo antes de que el objeto de ranura de bus slot sea desasignado. El puntero userdata del objeto de ranura se pasará como parámetro userdata. Este puntero puede ser establecido por un argumento a las funciones constructoras, ver sd_bus_add_match(3), o directamente, ver sd_bus_slot_set_userdata(3). Esta función de retorno de llamada se invoca incluso si userdata es NULL. Tenga en cuenta que este retorno de llamada se invoca en un momento en que el objeto de ranura de bus en sí ya está invalidado, y no está permitido ejecutar operaciones ni tomar nuevas referencias al objeto de ranura de bus.

sd_bus_slot_get_destroy_callback() devuelve el retorno de llamada actual para slot en el parámetro callback.

sd_bus_track_set_destroy_callback() y sd_bus_track_get_destroy_callback() proporcionan funcionalidad equivalente para el puntero userdata asociado con objetos de seguimiento de pares de bus. Para más detalles sobre objetos de seguimiento de pares de bus, ver sd_bus_track_new(3).

VALOR DE RETORNO

En caso de éxito, sd_bus_slot_set_destroy_callback() y sd_bus_track_set_destroy_callback() devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo estilo errno.

sd_bus_slot_get_destroy_callback() y sd_bus_track_get_destroy_callback() devuelven un valor positivo si la función de retorno de llamada de destrucción está establecida, 0 si no. En caso de error, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

El parámetro slot o track es NULL.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para múltiples hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

sd_bus_destroy_t(), sd_bus_slot_set_destroy_callback(), sd_bus_slot_get_destroy_callback(), sd_bus_track_set_destroy_callback(), y sd_bus_track_get_destroy_callback() fueron añadidas en la versión 239.
