DESCRIPCIÓN

sd_event_add_child() añade una nueva fuente de eventos de cambio de estado de proceso hijo a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro pid especifica el PID del proceso a observar, que debe ser un proceso hijo directo del proceso invocador. El parámetro options determina qué cambios de estado se observarán. Debe contener una máscara OR-ed de WEXITED (observar la terminación del proceso hijo), WSTOPPED (observar la detención del proceso hijo por una señal), y WCONTINUED (observar la reanudación del proceso hijo por una señal). Ver waitid(2) para más información.

El handler debe ser una función a llamar cuando el proceso cambie de estado o NULL. A la función manejadora se le pasará el puntero userdata, que puede ser elegido libremente por el llamador. El manejador también recibe un puntero a una estructura siginfo_t que contiene información sobre el evento del proceso hijo. El manejador puede devolver un valor negativo para indicar un error (ver abajo), otros valores de retorno se ignoran. Si handler es NULL, se utilizará un manejador predeterminado que llama a sd_event_exit(3).

Solo se puede instalar un manejador para un proceso hijo específico. El manejador está habilitado para un único evento (SD_EVENT_ONESHOT), pero esto se puede cambiar con sd_event_source_set_enabled(3). Si la función manejadora devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si el modo SD_EVENT_ON se solicitó previamente, o provocará la terminación del bucle, ver sd_event_source_set_exit_on_failure(3).

Para destruir un objeto de fuente de eventos, use sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se sueltan todas las referencias a ella. Para asegurarse de que una fuente de eventos no se dispare más, incluso cuando todavía hay una referencia a ella, considere establecer la fuente de eventos en SD_EVENT_OFF con sd_event_source_set_enabled(3).

La señal SIGCHLD debe estar bloqueada en todos los hilos antes de llamar a esta función (usando sigprocmask(2) o pthread_sigmask(3)).

Si se pasa el segundo parámetro de sd_event_add_child() como NULL, no se devolverá ninguna referencia al objeto de la fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando el propio bucle de eventos se destruya.

Tenga en cuenta que la función handler se invoca en un momento en que el proceso hijo aún no ha sido recogido (y por lo tanto aún es expuesto como un proceso zombi por el kernel). Sin embargo, el hijo será recogido automáticamente después de que la función devuelva. Los procesos hijos para los que no se instalan fuentes de eventos de cambio de estado no serán recogidos por la implementación del bucle de eventos.

Si el parámetro handler de sd_event_add_child() es NULL, y la fuente de eventos se dispara, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a un entero, se pasa como parámetro de código de salida a sd_event_exit(3).

Si se instalan tanto una fuente de eventos de cambio de estado de proceso hijo como una fuente de eventos de señal SIGCHLD en el mismo bucle de eventos, las prioridades de la fuente de eventos configuradas deciden qué fuente de eventos se despacha primero. Si el manejador de señales se procesa primero, debería dejar los procesos hijos para los que se han instalado fuentes de eventos de cambio de estado de proceso hijo sin recoger.

sd_event_add_child_pidfd() es similar a sd_event_add_child() pero toma un descriptor de archivo que hace referencia al proceso ("pidfd") en lugar del PID numérico. Se puede obtener un descriptor de archivo adecuado a través de pidfd_open(2) y llamadas relacionadas. El descriptor de archivo pasado no se cierra cuando la fuente de eventos se libera de nuevo, a menos que se utilice sd_event_source_set_child_pidfd_own() para activar este comportamiento. Tenga en cuenta que independientemente de si se utiliza sd_event_add_child() o sd_event_add_child_pidfd() para asignar una fuente de eventos, el proceso observado debe ser un proceso hijo directo del proceso invocador. También en ambos casos SIGCHLD debe estar bloqueado en el proceso invocador.

sd_event_source_get_child_pid() recupera el PID configurado de una fuente de eventos de cambio de estado de proceso hijo creada previamente con sd_event_add_child(). Toma el objeto de la fuente de eventos como parámetro source y un puntero a una variable pid_t para devolver el ID del proceso.

sd_event_source_get_child_pidfd() recupera el descriptor de archivo que hace referencia al proceso observado ("pidfd"). El bucle de eventos utiliza internamente pidfds para observar procesos hijos, independientemente de si las fuentes de eventos individuales se asignan a través de sd_event_add_child() o sd_event_add_child_pidfd(). Si la última llamada se utilizó para asignar la fuente de eventos, esta función devuelve el descriptor de archivo original utilizado para la asignación. Esta llamada toma el objeto de la fuente de eventos como parámetro source y devuelve el descriptor de archivo numérico.

sd_event_source_get_child_pidfd_own() se puede usar para consultar si el pidfd que encapsula la fuente de eventos debe cerrarse cuando se libere la fuente de eventos. Esta función devuelve cero si el pidfd debe dejarse abierto, y positivo si debe cerrarse automáticamente. Por defecto, esta configuración es activada si la fuente de eventos se asignó a través de sd_event_add_child() y desactivada si se asignó a través de sd_event_add_child_pidfd(). La función sd_event_source_set_child_pidfd_own() se puede usar para cambiar la configuración y toma un parámetro booleano con la nueva configuración.

sd_event_source_get_child_process_own() se puede usar para consultar si el proceso que observa la fuente de eventos debe ser matado (con SIGKILL) y recogido cuando se libere la fuente de eventos. Esta función devuelve cero si el proceso debe dejarse ejecutándose, y positivo si debe ser matado y recogido automáticamente. Por defecto, esta configuración es desactivada. DESCRIPCIÓN

Estas funciones proporcionan un medio para gestionar el monitoreo de procesos hijos y enviarles señales.

sd_event_add_child_pidfd() es similar a sd_event_add_child(3), pero en lugar de usar el PID de un proceso hijo, usa un file descriptor de proceso (pidfd) abierto para el proceso hijo. Para obtener un pidfd, use la llamada al sistema pidfd_open(2). El parámetro events es una máscara de bits de las banderas WCONTINUED, WEXITED y WSTOPPED, tal como se define en waitid(2). Los eventos para el pidfd son igualmente monitoreados. Si source no es NULL, el puntero al nuevo objeto de evento de proceso hijo se almacena allí. El handler será llamado cuando ocurra uno de los eventos especificados.

sd_event_source_get_child_pidfd() devuelve el pidfd asociado con el fuente de evento hijo.

sd_event_source_get_child_pidfd_own() y sd_event_source_set_child_pidfd_own() se utilizan para consultar y establecer si el objeto de evento de proceso hijo es el propietario del pidfd. Si es el propietario, el pidfd se cerrará cuando se desreferencie el objeto de evento. Por defecto, el objeto de evento no posee el pidfd.

sd_event_source_get_child_process_own() y sd_event_source_set_child_process_own() se utilizan para consultar y establecer si el objeto de evento de proceso hijo es el propietario del proceso hijo. Si es el propietario, el objeto de evento intentará tomar posesión del proceso hijo (usando pr_set_pdeathsig(2) y prctl(2)) de modo que el proceso hijo sea terminado cuando el proceso del objeto de evento sea terminado. Por defecto, el objeto de evento no es propietario del proceso hijo.

sd_event_source_send_child_signal() puede ser usado para enviar una señal UNIX al proceso hijo observado a través de pidfd_send_signal(2). Los parámetros especificados coinciden con los de la llamada al sistema subyacente, excepto que info nunca se modifica (y por lo tanto se declara constante). Al igual que con la llamada al sistema subyacente, el parámetro flags actualmente debe ser cero.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento inválido. Esto incluye especificar una máscara vacía en options o una máscara que contenga valores diferentes a una combinación de WEXITED, WSTOPPED y WCONTINUED.

-EBUSY

Ya hay un manejador instalado para este proceso hijo, o SIGCHLD no está bloqueado.

-ESTALE

El bucle de eventos ya ha terminado.

-ECHILD

El bucle de eventos se creó en un proceso, biblioteca o instancia de módulo diferente.

-EDOM

La fuente de evento pasada no es una fuente de evento de proceso hijo.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd de pkg-config(1).

El código descrito aquí usa getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

EJEMPLO

Ejemplo 1. Salir del bucle cuando el hijo termina

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <assert.h>
#include <stdio.h>
#include <unistd.h>
#include <systemd/sd-event.h>
int main(int argc, char **argv) {
  pid_t pid = fork();
  assert(pid >= 0);
  /* La señal SIGCHLD debe estar bloqueada para que sd_event_add_child funcione */
  sigset_t ss;
  sigemptyset(&ss);
  sigaddset(&ss, SIGCHLD);
  sigprocmask(SIG_BLOCK, &ss, NULL);
  if (pid == 0)  /* hijo */
    sleep(1);
  else {         /* padre */
    sd_event *e = NULL;
    int r;
    /* Crear el bucle de eventos predeterminado */
    sd_event_default(&e);
    assert(e);
    /* Creamos una fuente de evento hijo flotante (adjunta a 'e').
     * El manejador predeterminado será llamado con 666 como userdata, que
     * se convertirá en el valor de salida del bucle. */
    r = sd_event_add_child(e, NULL, pid, WEXITED, NULL, (void*) 666);
    assert(r >= 0);
    r = sd_event_loop(e);
    assert(r == 666);
    sd_event_unref(e);
  }
  return 0;
}
