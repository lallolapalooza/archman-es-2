DESCRIPCIÓN

sd_event_add_time() añade una nueva fuente de eventos de temporizador a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro clock toma un identificador de reloj, uno de CLOCK_REALTIME, CLOCK_MONOTONIC, CLOCK_BOOTTIME, CLOCK_REALTIME_ALARM o CLOCK_BOOTTIME_ALARM. Ver timerfd_create(2) para más detalles sobre los diversos tipos de relojes. El parámetro usec especifica el tiempo más temprano, en microsegundos (µs), relativo a la época del reloj, cuando el temporizador debe activarse. Si se especifica una hora ya pasada (incluyendo 0), esta fuente de temporizador se "dispara" inmediatamente y está lista para ser despachada. Si el parámetro se especifica como UINT64_MAX, el evento del temporizador nunca se cumplirá, lo que puede utilizarse como alternativa para deshabilitar explícitamente una fuente de eventos de temporizador con sd_event_source_set_enabled(3). El parámetro accuracy especifica un valor de precisión adicional en µs, indicando cuánto puede retrasarse el evento del temporizador. Usar 0 para seleccionar la precisión por defecto (250ms). Usar 1µs para la máxima precisión. Considerar especificar 60000000µs (1 min) o más para eventos de larga duración que puedan retrasarse sustancialmente. Elegir valores de precisión más altos permite al sistema agrupar eventos de temporizador de forma más agresiva, mejorando la eficiencia energética.

El handler es una función a llamar cuando el temporizador se cumple o NULL. El puntero userdata se pasará a la función manejadora, y puede ser elegido libremente por el llamador. El tiempo de activación configurado también se pasa al manejador, incluso si la llamada ocurre un poco más tarde, sujeto al valor de precisión especificado, el tiempo de espera del temporizador del kernel (ver prctl(2)), y latencias de programación adicionales. Para consultar la hora real en que se llamó al manejador, usar sd_event_now(3). El manejador puede devolver un valor negativo para señalar un error (ver abajo), otros valores de retorno se ignoran. Si handler es NULL, se usará un manejador por defecto que llama a sd_event_exit(3).

Por defecto, el temporizador se cumplirá una vez (SD_EVENT_ONESHOT), pero esto puede cambiarse con sd_event_source_set_enabled(3). Si la función manejadora devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si se solicitó el modo SD_EVENT_ON antes, o provocará que el bucle termine, ver sd_event_source_set_exit_on_failure(3). Tener en cuenta que un evento de temporizador configurado como SD_EVENT_ON se activará continuamente a menos que su hora configurada se actualice usando sd_event_source_set_time().

sd_event_add_time_relative() es como sd_event_add_time(), pero toma una especificación de tiempo relativo. Es relativo al tiempo actual de la iteración del bucle de eventos, como devuelve sd_event_now(3).

Para destruir un objeto de fuente de eventos, usar sd_event_source_unref(3), pero tener en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se sueltan todas las referencias a la fuente de eventos. Para asegurarse de que una fuente de eventos no se active más, incluso si todavía está referenciada, deshabilitar la fuente de eventos usando sd_event_source_set_enabled(3) con SD_EVENT_OFF.

Si el segundo parámetro de sd_event_add_time() es NULL, no se devuelve ninguna referencia al objeto de fuente de eventos. En este caso, la fuente de eventos se considera "flotante", y se destruirá implícitamente cuando el propio bucle de eventos sea destruido.

Si el parámetro handler para sd_event_add_time() es NULL, y la fuente de eventos se dispara, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a entero, se pasa como parámetro de código de salida a sd_event_exit(3).

Usar CLOCK_BOOTTIME_ALARM y CLOCK_REALTIME_ALARM para definir fuentes de eventos que puedan despertar el sistema de la suspensión.

Para configurar temporizadores relativos (es decir, relativos al tiempo actual), obtener el tiempo actual a través de sd_event_now(3), sumar el intervalo de tiempo deseado, y usar el resultado como parámetro usec para sd_event_add_time().

Para configurar temporizadores repetitivos (es decir, temporizadores que se activan en intervalos regulares), configurar el temporizador normalmente, para la primera invocación. Cada vez que se invoca al manejador de eventos, actualizar el tiempo de activación del temporizador con sd_event_source_set_time(3) para la próxima iteración del temporizador, y reactivar el temporizador usando sd_event_source_set_enabled(). Para calcular el próximo punto en el tiempo a pasar a sd_event_source_set_time(), usar como base el parámetro usec pasado al callback del temporizador, o la marca de tiempo devuelta por sd_event_now(). En el primer caso, los eventos del temporizador serán regulares, mientras que en el último caso, la latencia de programación seguirá acumulándose en el temporizador.

sd_event_source_get_time() recupera el valor de tiempo configurado de una fuente de eventos creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar el tiempo, relativo a la época del reloj seleccionado, en µs. El valor devuelto es relativo a la época, incluso si la fuente de eventos se creó con un tiempo relativo a través de sd_event_add_time_relative().

sd_event_source_set_time() cambia la hora de una fuente de eventos creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de eventos y una hora relativa a la época del reloj seleccionado, en µs.

sd_event_source_set_time_relative() es similar a sd_event_source_set_time(), pero toma una hora relativa al tiempo actual de la iteración del bucle de eventos, como devuelve sd_event_now().

sd_event_source_get_time_accuracy() recupera el valor de precisión configurado de una fuente de eventos creada previamente con sd_event_add_time(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar la precisión. La precisión se especifica en µs.

sd_event_source_set_time_accuracy() cambia la precisión configurada de una fuente de eventos de temporizador

int sd_event_add_time(sd_event *event, sd_event_source **sourcep, clockid_t clock_id, uint64_t usec, uint64_t accuracy_usec, sd_event_time_handler_t handler, void *userdata);

int sd_event_add_time_relative(sd_event *event, sd_event_source **sourcep, clockid_t clock_id, uint64_t usec, uint64_t accuracy_usec, sd_event_time_handler_t handler, void *userdata);

int sd_event_source_set_time(sd_event_source *source, uint64_t usec);

int sd_event_source_set_time_relative(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time(const sd_event_source *source, uint64_t *usecp);

int sd_event_source_set_time_accuracy(sd_event_source *source, uint64_t accuracy_usec);

int sd_event_source_get_time_accuracy(const sd_event_source *source, uint64_t *accuracy_usecp);

int sd_event_source_get_time_clock(const sd_event_source *source, clockid_t *clock_idp);

DESCRIPCIÓN

El objeto de evento event es un bucle de eventos, como el devuelto por sd_event_new.

sd_event_add_time crea una nueva fuente de evento de temporizador en el bucle de eventos event. El manejador handler será invocado con el identificador id y el tiempo usec (en microsegundos) cuando la hora del reloj clock_id alcance la hora especificada. El tiempo usec se especifica en relación con la hora de inicio del reloj clock_id. La exactitud deseada accuracy_usec se puede usar para informar al sistema sobre la tolerancia de latencia del temporizador, lo que permite al sistema agrupar temporizadores con exactitudes similares para ahorrar energía. Si sourcep no es NULL, se almacenará un puntero a la nueva fuente de evento en él.

sd_event_add_time_relative es similar a sd_event_add_time, pero el tiempo usec especifica un retardo relativo desde el momento actual, en lugar de una hora absoluta. Tenga en cuenta que el tiempo que se pasa a handler seguirá siendo la hora absoluta en la que se activó el temporizador.

sd_event_source_set_time modifica el tiempo de activación de una fuente de evento de temporizador existente creada previamente con sd_event_add_time. El tiempo usec se especifica en relación con el tiempo de inicio del reloj clock_id. El temporizador se recalcula.

sd_event_source_set_time_relative modifica el tiempo de activación de una fuente de evento de temporizador existente creada previamente con sd_event_add_time_relative. El tiempo usec se especifica como un retardo relativo desde el momento actual.

sd_event_source_get_time recupera el tiempo de activación configurado de una fuente de evento de temporizador existente. El tiempo se almacena en la variable a la que apunta usecp, en microsegundos.

sd_event_source_set_time_accuracy modifica la exactitud deseada de una fuente de evento de temporizador existente. La exactitud accuracy_usec se especifica en microsegundos.

sd_event_source_get_time_accuracy recupera la exactitud deseada de una fuente de evento de temporizador existente. La exactitud se almacena en la variable a la que apunta accuracy_usecp, en microsegundos.

sd_event_source_get_time_clock recupera el reloj configurado de una fuente de evento de temporizador creada previamente con sd_event_add_time. Toma el objeto de fuente de evento y un puntero a una variable para almacenar el identificador del reloj.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de fallo, devuelven un código de error negativo al estilo errno.

Errores

Los valores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento inválido.

-ESTALE

El bucle de eventos ya ha terminado.

-ECHILD

El bucle de eventos se ha creado en un proceso, biblioteca o instancia de módulo diferente.

-EOPNOTSUPP

El reloj seleccionado no es compatible con la implementación del bucle de eventos.

-EDOM

La fuente de evento pasada no es una fuente de evento de temporizador.

-EOVERFLOW

El tiempo relativo pasado está fuera del rango permitido para los valores de tiempo (es decir, el valor especificado más la hora actual está fuera del rango del entero sin signo de 64 bits).

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar solo llamadas a setenv() desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
