DESCRIPCIÓN

sd_bus_emit_signal() es una función de conveniencia para inicializar un objeto de mensaje de bus y emitir la señal D-Bus correspondiente. Combina las funciones sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) en una única llamada a función. sd_bus_emit_signalv() es equivalente a sd_bus_message_append(), excepto que se llama con una lista "va_list" en lugar de un número variable de argumentos.

sd_bus_emit_signal_to() y sd_bus_emit_signal_tov() son idénticas a sd_bus_emit_signal() y sd_bus_emit_signalv(), excepto que pueden emitir la señal a un único destino. Proporcione destination como NULL para transmitir la señal en difusión.

sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() se utilizan para implementar las señales InterfacesAdded y InterfacesRemoved de la interfaz org.freedesktop.DBus.ObjectManager. Toman una ruta cuyos interfaces se han modificado como argumento y una lista variable de interfaces que se han añadido o eliminado, respectivamente. El último argumento pasado a sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() debe ser NULL. Esto permite que ambas funciones determinen de forma segura el número de argumentos de interfaz pasados. sd_bus_emit_interfaces_added_strv() y sd_bus_emit_interfaces_removed_strv() son idénticas a sus contrapartes respectivas pero ambas toman la lista de interfaces como un único argumento en lugar de un número variable de argumentos.

sd_bus_emit_properties_changed() se utiliza para implementar la señal PropertiesChanged de la interfaz org.freedesktop.DBus.Properties. Toma una ruta de objeto, una interfaz y una lista variable de nombres de propiedades como argumentos. El último argumento pasado a sd_bus_emit_properties_changed() debe ser NULL. Esto le permite determinar de forma segura el número de nombres de propiedad pasados. sd_bus_emit_properties_changed_strv() es idéntica a sd_bus_emit_properties_changed() pero toma la lista de nombres de propiedad como un único argumento en lugar de un número variable de argumentos.

sd_bus_emit_object_added() y sd_bus_emit_object_removed() son funciones de conveniencia para emitir las señales InterfacesAdded o InterfacesRemoved para todos los interfaces registrados en una ruta de objeto específica, respectivamente. Esto incluye cualquier vtable de reserva padre si no son anulados por una vtable hija más aplicable. También incluye todos los interfaces D-Bus estándar implementados por el propio sd-bus en cualquier objeto registrado.

Tenga en cuenta que sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() y sd_bus_emit_object_removed() requieren que se haya registrado un gestor de objetos en la ruta de objeto dada o en una de sus rutas de objeto padre utilizando sd_bus_add_object_manager(3).

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un entero no negativo. En caso de error, devuelven un código de error negativo de estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Uno de los parámetros requeridos es NULL o inválido. Se pasó un interfaz D-Bus reservado como parámetro interface.

-ENOPKG

El bus no se puede resolver.

-ECHILD

El bus se creó en un proceso, biblioteca o instancia de módulo diferente.

-ENOMEM

Fallo en la asignación de memoria.

-ESRCH

Se llamó a sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() o sd_bus_emit_object_removed() en un objeto sin un gestor de objetos registrado en su propia ruta de objeto o en una de sus rutas de objeto padre.

Consulte las páginas man de sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) para errores adicionales posibles.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para uso en entornos multihilo. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

Emit D-Bus signals

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_emit_interfaces_removed(sd_bus *bus, const char *path, const char *interfaces[]);

int sd_bus_emit_objects_removed(sd_bus *bus, const char *path, const char *interfaces[]);

int sd_bus_emit_object_added(sd_bus *bus, const char *path, const char *interface, sd_bus_error *error);

int sd_bus_emit_property_changed(sd_bus *bus, const char *path, const char *interface, const char *member, sd_bus_error *error);

int sd_bus_emit_signal(sd_bus *bus, const char *path, const char *interface, const char *member, sd_bus_error *error);

int sd_bus_emit_signalv(sd_bus *bus, const char *path, const char *interface, const char *member, va_list ap, sd_bus_error *error);

int sd_bus_emit_signal_to(sd_bus *bus, const char *destination, const char *path, const char *interface, const char *member, sd_bus_error *error);

int sd_bus_emit_signal_tov(sd_bus *bus, const char *destination, const char *path, const char *interface, const char *member, va_list ap, sd_bus_error *error);

int sd_bus_emit_properties_changed(sd_bus *bus, const char *path, const char *interface, sd_bus_error *error, const char *member, ...);

int sd_bus_emit_interfaces_added(sd_bus *bus, const char *path, const char *interfaces[]);

DESCRIPTION

These functions may be used to emit D-Bus signals. They construct, serialize, and send a D-Bus message of type signal.

The functions vary in how they specify the arguments for the signal. Some take a va_list argument, which should be filled with the arguments to be serialized and sent. Others take a variable number of arguments, which are then serialized and sent.

sd_bus_emit_signal(), sd_bus_emit_signalv(), sd_bus_emit_signal_to(), and sd_bus_emit_signal_tov() are used to emit generic signals.

sd_bus_emit_properties_changed() emits a PropertiesChanged signal. It takes the name of the interface whose properties changed, followed by pairs of property names and their new values. The list of members should be NULL terminated.

sd_bus_emit_interfaces_added() emits an InterfacesAdded signal. It takes a NULL-terminated array of interface names.

sd_bus_emit_interfaces_removed() emits an InterfacesRemoved signal. It takes a NULL-terminated array of interface names.

sd_bus_emit_objects_removed() emits an ObjectRemoved signal. It takes a NULL-terminated array of interface names that were removed from the object at path.

sd_bus_emit_object_added() emits an ObjectAdded signal. It takes the interface name that was added to the object at path.

Signals are typically emitted on the bus specified by the bus parameter. If destination is not NULL, the signal is sent directly to that destination.

Signals are emitted from the specified path, interface, and member.

The sd_bus_emit_property_changed() function is a convenience function for emitting a org.freedesktop.DBus.Properties.PropertiesChanged signal.

The sd_bus_emit_interfaces_added() function is a convenience function for emitting an org.freedesktop.DBus.ObjectManager.InterfacesAdded signal.

The sd_bus_emit_interfaces_removed() function is a convenience function for emitting an org.freedesktop.DBus.ObjectManager.InterfacesRemoved signal.

The sd_bus_emit_objects_removed() function is a convenience function for emitting an org.freedesktop.DBus.ObjectManager.ObjectsRemoved signal.

The sd_bus_emit_object_added() function is a convenience function for emitting an org.freedesktop.DBus.ObjectManager.ObjectAdded signal.

RETURN VALUE

On success, these functions return a non-negative integer. On failure, they return a negative errno value.

NOTES

These functions are usually used in conjunction with sd_bus_add_object(3) and sd_bus_add_object_manager(3).

The sd_bus_emit_signal(), sd_bus_emit_property_changed(), sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_objects_removed(), and sd_bus_emit_object_added() functions are shorthand for creating a new signal message, appending the arguments, and sending it.

The sd_bus_emit_signalv() and sd_bus_emit_signal_tov() functions are similar to sd_bus_emit_signal() and sd_bus_emit_signal_to() respectively, but they take a va_list argument for the signal arguments.
