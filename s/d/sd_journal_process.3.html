NOMBRE

sd_journal_get_fd, sd_journal_get_events, sd_journal_get_timeout, sd_journal_process, sd_journal_wait, sd_journal_reliable_fd, SD_JOURNAL_NOP, SD_JOURNAL_APPEND, SD_JOURNAL_INVALIDATE - Interfaz de notificación de cambios en el journal

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_get_fd(sd_journal *j);

int sd_journal_get_events(sd_journal *j);

int sd_journal_get_timeout(sd_journal *j, uint64_t *timeout_usec);

int sd_journal_process(sd_journal *j);

int sd_journal_wait(sd_journal *j, uint64_t timeout_usec);

int sd_journal_reliable_fd(sd_journal *j);

DESCRIPCIÓN

sd_journal_get_fd() devuelve un descriptor de archivo que puede ser escaneado asincrónicamente en un bucle de eventos externo y que se señaliza tan pronto como el journal cambia, porque se añadieron nuevas entradas o archivos, tuvo lugar una rotación, o se eliminaron archivos, y similares. El descriptor de archivo es adecuado para su uso en poll(2). Use sd_journal_get_events() para una máscara de eventos a vigilar. La llamada toma un argumento: el objeto de contexto del journal. Tenga en cuenta que no todos los sistemas de archivos son capaces de generar los eventos necesarios para las activaciones desde este descriptor de archivo para que los cambios se noten de inmediato. En particular, los sistemas de archivos de red no generan eventos de cambio de archivo adecuados en todos los casos. Casos como estos se pueden detectar con sd_journal_reliable_fd(), más abajo. sd_journal_get_timeout() se asegurará en estos casos de que las activaciones ocurran con suficiente frecuencia para que los cambios se noten, aunque con cierta latencia.

sd_journal_get_events() devolverá la máscara de poll() a esperar. Esta función devolverá una combinación de POLLIN y POLLOUT y similares para rellenar en el campo ".events" de struct pollfd.

sd_journal_get_timeout() devolverá un valor de tiempo de espera para su uso en poll(). Esto devuelve un valor en microsegundos desde la época de CLOCK_MONOTONIC para esperar poll() en timeout_usec. Consulte clock_gettime(2) para obtener detalles sobre CLOCK_MONOTONIC. Si no hay tiempo de espera, rellenará (uint64_t) -1 en su lugar. Tenga en cuenta que poll() toma un tiempo de espera relativo en milisegundos en lugar de un tiempo de espera absoluto en microsegundos. Para convertir el tiempo de espera absoluto 'us' en 'ms' relativos, use código como el siguiente:

uint64_t t;
int msec;
sd_journal_get_timeout(m, &t);
if (t == (uint64_t) -1)
  msec = -1;
else {
  struct timespec ts;
  uint64_t n;
  clock_gettime(CLOCK_MONOTONIC, &ts);
  n = (uint64_t) ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
  msec = t > n ? (int) ((t - n + 999) / 1000) : 0;
}

El código anterior no realiza ninguna comprobación de errores por brevedad. El entero msec calculado se puede pasar directamente como parámetro de tiempo de espera de poll().

Después de cada activación de poll(), es necesario llamar a sd_journal_process() para procesar los eventos. Esta llamada también indicará qué tipo de cambio se ha detectado (ver abajo; tenga en cuenta que son posibles activaciones espurias).

Una alternativa síncrona para usar sd_journal_get_fd(), sd_journal_get_events(), sd_journal_get_timeout() y sd_journal_process() es sd_journal_wait(). Esperará sincrónicamente hasta que el journal cambie. El tiempo máximo que esta llamada duerme puede ser controlado con el parámetro timeout_usec. Pase (uint64_t) -1 para esperar indefinidamente. Internamente, esta llamada simplemente combina sd_journal_get_fd(), sd_journal_get_events(), sd_journal_get_timeout(), poll() y sd_journal_process() en una sola.

sd_journal_reliable_fd() puede usarse para verificar si los eventos de activación del descriptor de archivo devuelto por sd_journal_get_fd() se activan rápidamente. En ciertos sistemas de archivos donde los eventos de cambio de archivo del sistema operativo no están disponibles (como NFS), los cambios deben ser escaneados repetidamente, y por lo tanto solo se detectan con una latencia considerable. Esta llamada devolverá un valor positivo si los cambios del journal se detectan rápidamente y cero cuando necesitan ser escaneados. Tenga en cuenta que generalmente no hay necesidad de invocar esta función directamente, ya que sd_journal_get_timeout() solicitará tiempos de espera apropiados de todos modos.

Tenga en cuenta que ninguna de las interfaces de notificación de cambios anteriores informa los cambios instantáneamente. Se introducen latencias por varias razones: como se mencionó, algunos backends de almacenamiento requieren sondeo basado en tiempo, en otros casos las activaciones se optimizan agrupando eventos, y el SO introduce latencias adicionales de programación de E/S/CPU.

VALOR DE RETORNO

sd_journal_get_fd() devuelve un descriptor de archivo válido en caso de éxito o un código de error negativo estilo errno.

sd_journal_get_events() devuelve una combinación de POLLIN, POLLOUT y similares en caso de éxito o un código de error negativo estilo errno.

sd_journal_reliable_fd() devuelve un entero positivo si el descriptor de archivo devuelto por sd_journal_get_fd() generará activaciones inmediatas para todos los cambios del journal. Devuelve 0 si podría haber una latencia involucrada.

sd_journal_process() y sd_journal_wait() devuelven un código de error negativo estilo errno, o uno de SD_JOURNAL_NOP, SD_JOURNAL_APPEND o SD_JOURNAL_INVALIDATE en caso de éxito:

•Si se devuelve SD_JOURNAL_NOP, el journal no ha cambiado desde la última invocación.
•Si se devuelve SD_JOURNAL_APPEND, se han añadido nuevas entradas al final del journal. En este caso, es suficiente con seguir leyendo en la ubicación final anterior del journal para leer las entradas recién añadidas.
•Si se devuelve SD_JOURNAL_INVALIDATE, se han añadido o eliminado archivos del journal del conjunto de archivos del journal vigilados (por ejemplo, debido a rotación o limpieza), y por lo tanto las entradas podrían haber aparecido o desaparecido en lugares arbitrarios del flujo de registro, posiblemente antes o después del final anterior del flujo de registro. Si se devuelve SD_JOURNAL_INVALIDATE, las interfaces de vista en vivo que deseen reflejar en pantalla el estado preciso de los datos de registro en el disco probablemente deberían actualizar toda su pantalla (en relación con el cursor de la entrada de registro en la parte superior de la pantalla). Los programas que solo estén interesados en un flujo de datos de registro estrictamente secuencial pueden tratar SD_JOURNAL_INVALIDATE de la misma manera que SD_JOURNAL_APPEND, ignorando así cualquier cambio en la vista del registro anterior al final antiguo del flujo de registro.

SEGURIDAD DE SEÑALES

En general, sd_journal_get_fd(), sd_journal_get_events() y sd_journal_get_timeout() *no* son "seguras para señales asíncronas" en el sentido de signal-safety(7). Sin embargo, solo la primera llamada a cualquiera de estas tres funciones realiza operaciones inseguras, por lo que las llamadas subsiguientes *son* seguras.

sd_journal_process() y sd_journal_wait() no son seguras. sd_journal_reliable_fd() es segura.

NOTAS

Todas las funciones descritas aquí son agnósticas a los hilos y solo un hilo puede operar en un objeto dado en un momento dado. Diferentes hilos pueden acceder al mismo objeto en diferentes momentos. Se pueden usar múltiples objetos independientes desde diferentes hilos en paralelo.

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd de pkg-config(1).

sd_journal_process(3) - systemd-libs - Arch Linux

NAME

sd_journal_process, sd_journal_wait, sd_journal_get_fd, sd_journal_get_events, sd_journal_get_timeout, sd_journal_reliable_fd - Process journal entries and wait for new entries

SYNOPSIS

#include <systemd/sd-journal.h>

int sd_journal_process(sd_journal *j);
int sd_journal_wait(sd_journal *j, uint64_t timeout_usec);
int sd_journal_get_fd(sd_journal *j);
int sd_journal_get_events(sd_journal *j);
int sd_journal_get_timeout(sd_journal *j, uint64_t *timeout_usec);
int sd_journal_reliable_fd(sd_journal *j);

DESCRIPTION

These functions operate on an journal enumeration context j, created with sd_journal_open(3).

sd_journal_process() should be called periodically to check for new journal entries. If new entries are available, it reads them, updates the internal state of the journal enumeration context, and returns positive. If no new entries are available, it returns 0. If an error occurs, a negative error code is returned.

sd_journal_wait() is similar to sd_journal_process(), but it blocks until new journal entries are available or the specified timeout_usec has elapsed. If timeout_usec is (uint64_t) -1, it blocks indefinitely. This function internally uses polling on the file descriptor returned by sd_journal_get_fd().

sd_journal_get_fd() returns the file descriptor that can be used for polling, as described in poll(2). This file descriptor is suitable for polling for journal entry readiness. Note that this file descriptor might be unreliable, see sd_journal_reliable_fd().

sd_journal_get_events() returns the set of events that should be polled for on the file descriptor returned by sd_journal_get_fd(). This is intended to be used with poll(2).

sd_journal_get_timeout() retrieves the maximum time in microseconds to wait for new journal entries. If the journal is configured to wait indefinitely, (uint64_t) -1 is returned. Otherwise, the timeout in microseconds is returned in timeout_usec. This value should be used as the timeout for poll(2).

sd_journal_reliable_fd() returns a file descriptor that is guaranteed to be valid and not reset by systemd-journald.newly started daemon. This file descriptor should be used for polling instead of the one returned by sd_journal_get_fd() if reliability is required. The events to poll for are the same as returned by sd_journal_get_events().

RETURN VALUE

On success, sd_journal_process() returns a positive integer if new journal entries were read, 0 if no new entries were available, and a negative error code on failure.

On success, sd_journal_wait() returns a positive integer if new journal entries are available, 0 if the timeout elapsed, and a negative error code on failure.

On success, sd_journal_get_fd(), sd_journal_get_events(), and sd_journal_reliable_fd() return the respective file descriptor or event mask. On failure, they return a negative error code.

On success, sd_journal_get_timeout() returns 0 and sets timeout_usec to the timeout value. On failure, it returns a negative error code.

The specific error codes are detailed in sd-journal(3).

SIGNAL SAFETY

sd_journal_process(), sd_journal_wait(), sd_journal_get_fd(), sd_journal_get_events(), sd_journal_get_timeout(), and sd_journal_reliable_fd() are async-signal-safe.

NOTES

To poll for new journal entries, you should typically use sd_journal_get_fd(), sd_journal_get_events(), and sd_journal_get_timeout() with poll(2). After poll(2) indicates that the file descriptor is ready, you should call sd_journal_process() to read the new entries. If sd_journal_process() returns 0, it means that the file descriptor became ready spuriously, and you should poll again.

If you need to reliably wait for new journal entries without missing any, use sd_journal_reliable_fd() instead of sd_journal_get_fd().

The function sd_journal_wait() is a convenience wrapper around polling and calling sd_journal_process().

EXAMPLES

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <systemd/sd-journal.h>
int main(int argc, char *argv[]) {
  sd_journal *j = NULL;
  int r;
  /* Open the journal and seek to the end */
  r = sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);
  if (r < 0) {
    fprintf(stderr, "Failed to open journal: %s\n", strerror(-r));
    return 1;
  }
  sd_journal_seek_tail(j);
  /* Enter a loop to read new messages */
  for (;;) {
    /* Wait for new entries (or until an error occurs) */
    r = sd_journal_wait(j, (uint64_t) -1);
    if (r < 0) {
      fprintf(stderr, "Failed to wait for journal entries: %s\n", strerror(-r));
      break;
    }
    /* Process all available new entries */
    while ((r = sd_journal_next(j)) > 0) {
      const char *d;
      size_t l;
      /* Get the MESSAGE field */
      r = sd_journal_get_data(j, "MESSAGE", &d, &l);
      if (r < 0) {
        fprintf(stderr, "Failed to get MESSAGE field: %s\n", strerror(-r));
        continue;
      }
      /* Print the message */
      printf("%.*s\n", (int) l, d);
    }
    if (r < 0) {
      fprintf(stderr, "Failed to iterate journal: %s\n", strerror(-r));
      break;
    }
  }
  sd_journal_close(j);
  return 0;
}

Waiting with poll() (this example lacks all error checking for the sake of simplicity):

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <poll.h>
#include <time.h>
#include <systemd/sd-journal.h>
int wait_for_changes(sd_journal *j) {
  uint64_t t;
  int msec;
  struct pollfd pollfd;
  sd_journal_get_timeout(j, &t);
  if (t == (uint64_t) -1)
    msec = -1;
  else {
    struct timespec ts;
    uint64_t n;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    n = (uint64_t) ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
    msec = t > n ? (int) ((t - n + 999) / 1000) : 0;
  }
  pollfd.fd = sd_journal_get_fd(j);
  pollfd.events = sd_journal_get_events(j);
  poll(&pollfd, 1, msec);
  return sd_journal_process(j);
}
