Paquete: systemd-libs

SD_BUS_MESSAGE_READ(3) sd_bus_message_read SD_BUS_MESSAGE_READ(3)

NOMBRE

sd_bus_message_read, sd_bus_message_readv, sd_bus_message_peek_type - Leer una secuencia de valores de un mensaje

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_read(sd_bus_message *m, const char *types, ...);

int sd_bus_message_readv(sd_bus_message *m, const char *types, va_list ap);

int sd_bus_message_peek_type(sd_bus_message *m, char *type, const char **contents);

DESCRIPCIÓN

sd_bus_message_read() lee una secuencia de campos del objeto de mensaje D-Bus m y avanza la posición de lectura en el mensaje. La cadena de tipos types describe los tipos de elementos esperados en el mensaje y los argumentos de campo que siguen. La cadena de tipos puede ser NULL o vacía, en cuyo caso no se lee nada.

La cadena de tipos se compone de los elementos descritos en sd_bus_message_append(3), es decir, tipos básicos y contenedores. Debe contener cero o más "tipos completos" individuales. La cadena de tipos está terminada en NUL.

Por cada tipo especificado en la cadena de tipos, se deben especificar uno o más argumentos después del parámetro types, en el mismo orden. Los argumentos deben ser punteros a tipos apropiados (un puntero a int8_t para una "y" en la cadena de tipos, un puntero a int32_t para una "i", un puntero a const char* para una "s", ...) que se establecen según los valores del mensaje. Como excepción, en el caso de tipos de arreglos y variantes, el primer argumento es un argumento de "entrada" que especifica además cómo se debe leer el mensaje. Consulte la tabla a continuación para obtener una lista completa de los argumentos permitidos y sus tipos. Tenga en cuenta que, si el tipo básico es un puntero (por ejemplo, const char * en el caso de una cadena), el argumento es un puntero a un puntero, y además el valor del puntero que se escribe solo se presta y el contenido debe copiarse si se va a utilizar después de la vida útil del mensaje. Si el tipo es "h" (descriptor de archivo UNIX), el descriptor no se duplica con esta llamada y el descriptor devuelto permanece en posesión del objeto del mensaje, y debe ser duplicado por el llamador para mantener una referencia abierta a él después de que el objeto del mensaje sea liberado.

Cada argumento también puede ser NULL, en cuyo caso el valor se lee y se ignora.

Si los objetos de los tipos especificados no están presentes en la posición actual del mensaje, se devuelve un error.

sd_bus_message_readv() es equivalente a sd_bus_message_read(), excepto que se llama con una "va_list" en lugar de un número variable de argumentos. Esta función no llama a la macro va_end(). Debido a que invoca a la macro va_arg(), el valor de ap no está definido después de la llamada.

sd_bus_message_peek_type() determina el tipo del siguiente elemento en m a ser leído por sd_bus_message_read() o funciones similares. En caso de éxito, el tipo se almacena en type, si no es NULL. Si el tipo es un tipo contenedor, el tipo de sus elementos se almacena en contents, si no es NULL. Si esta función determina con éxito el tipo del siguiente elemento en m, devuelve un entero positivo. Si no quedan más elementos para leer, devuelve cero.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un entero no negativo. En caso de fallo, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

La cadena de tipo especificada es inválida o el parámetro del mensaje es NULL.

-ENXIO

El mensaje no contiene el tipo especificado en la posición actual.

-EBADMSG

El mensaje no se puede analizar.

-EBUSY

Al leer de un contenedor, este error se devolverá si quedan elementos sin leer en el contenedor.

Añadido en la versión 251.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

sd_bus_message_read(3)

NAME

sd_bus_message_read, sd_bus_message_readv, sd_bus_message_peek_type - Leer datos de un mensaje de D-Bus

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_read(sd_bus_message *m, const char *signature, ...);
int sd_bus_message_readv(sd_bus_message *m, const char *signature, va_list ap);
int sd_bus_message_peek_type(sd_bus_message *m, char *type, uint64_t *idx);

DESCRIPTION

El método sd_bus_message_read() lee los datos de un mensaje de D-Bus m. La cadena signature especifica los tipos de los datos a leer, y los argumentos posteriores son punteros a las variables donde se almacenarán los datos leídos. La cadena de firma puede contener tipos básicos, contenedores (arrays, estructuras, variantes y diccionarios) y tipos compuestos de D-Bus.

Los tipos básicos admitidos son:

'y'
Un entero sin signo de 8 bits.
'b'
Un valor booleano (0 o 1).
'n'
Un entero con signo de 16 bits.
'q'
Un entero sin signo de 16 bits.
'i'
Un entero con signo de 32 bits.
'u'
Un entero sin signo de 32 bits.
'x'
Un entero con signo de 64 bits.
't'
Un entero sin signo de 64 bits.
'd'
Un número de punto flotante de doble precisión (64 bits).
's'
Una cadena de caracteres (const char *).
'o'
Una ruta de objeto de D-Bus (const char *).
'g'
Una firma de tipo de D-Bus (const char *).
'h'
Un descriptor de archivo (int). El descriptor de archivo leído se cierra después de que el mensaje es liberado, a menos que se duplique explícitamente.

Los tipos de contenedor se representan mediante:

'a'
Un array. Se espera un argumento entero adicional que especifica el número de elementos del array. Por ejemplo, para leer un array de 3 enteros de 32 bits, usaría "ai" y un argumento extra para el número de elementos: sd_bus_message_read(m, "ai", 3, &var1, &var2, &var3);. Para leer un array de estructuras, cada estructura debe descomponerse después de usar sd_bus_message_enter_container().
'{' ... '}'
Un diccionario. Se espera un argumento entero adicional que especifica el número de entradas del diccionario. Cada entrada consiste en una clave y un valor. Por ejemplo, a{is} representa un diccionario de enteros de 32 bits a cadenas. Para leer un diccionario de 3 entradas, usaría "a{is}" y un argumento extra para el número de entradas: sd_bus_message_read(m, "a{is}", 3, &key1, &val1, &key2, &val2, &key3, &val3);.
'(' ... ')'
Una estructura. Se espera que los argumentos de la firma se lean secuencialmente. Por ejemplo, (sd) representa una estructura de una cadena y un entero de 32 bits. Para leerla, usaría sd_bus_message_read(m, "(sd)", &str_var, &int_var);.
'v'
Una variante. La firma de una variante debe ser la primera cadena en el argumento. Por ejemplo, v puede leerse como sd_bus_message_read(m, "v", "gt", &sig_var, &val_var);, donde sig_var contendrá la cadena de firma de la variante y val_var será un puntero al valor de la variante (el tipo real del valor dependerá de la firma).

El método sd_bus_message_readv() es funcionalmente idéntico a sd_bus_message_read(), pero toma un argumento va_list en lugar de argumentos de variable para la lista de firmas.

El método sd_bus_message_peek_type() inspecciona el tipo del siguiente elemento en el mensaje sin consumirlo. Si el tipo es un contenedor, el índice idx se establece en el número de elementos de ese contenedor. El tipo se devuelve como un solo carácter en type. Esto es útil para iterar sobre contenedores, ya que permite determinar el tipo y el tamaño de los elementos antes de leerlos.

RETURN VALUE

En caso de éxito, sd_bus_message_read() y sd_bus_message_readv() devuelven 0. En caso de error, devuelven un código de error negativo.

sd_bus_message_peek_type() devuelve 0 en caso de éxito, o un código de error negativo en caso de error.

NOTES

Al leer tipos de punto flotante, se recomienda usar `double` para evitar la pérdida de precisión.

Al leer tipos de entero, se debe usar el tipo C apropiado según la firma de D-Bus. Por ejemplo, para 'i' (entero de 32 bits), se usa `int32_t`; para 'u' (entero sin signo de 32 bits), se usa `uint32_t`.

Los tipos booleanos en D-Bus se representan como enteros sin signo de 8 bits ('b'). Sin embargo, al leerlos con sd_bus_message_read(), se deben pasar punteros a tipos de C como `int` o `int32_t`. Usar el tipo `bool` de C99 puede provocar corrupción de memoria si el tamaño de `bool` es menor que el de un byte.

Los descriptores de archivo leídos se cierran cuando se libera el mensaje. Si necesita mantener el descriptor de archivo abierto después de que el mensaje sea liberado, debe duplicarlo explícitamente usando `fcntl(fd, FD_DUPFD_CLOEXEC, 3);` o una llamada similar.

Para leer contenedores anidados (como arrays de arrays o diccionarios de estructuras), deberá usar sd_bus_message_enter_container() y sd_bus_message_exit_container() para navegar por la estructura del mensaje.

Es importante asegurarse de que la cadena de firma coincida exactamente con los datos en el mensaje. Una discrepancia puede provocar errores de lectura o corrupción de memoria.

EXAMPLES

Leer un único tipo básico (un entero de 64 bits):

sd_bus_message *m;
int64_t x;
sd_bus_message_read(m, "x", &x);

Leer un valor booleano:

sd_bus_message *m;
int x; /* ¡No use el tipo "bool" de C99 aquí, típicamente es más pequeño
          en memoria y causaría corrupción de memoria! */
sd_bus_message_read(m, "b", &x);

Leer todos los tipos de enteros:

uint8_t y;
int16_t n;
uint16_t q;
int32_t i;
uint32_t u;
int64_t x;
uint64_t t;
double d;
sd_bus_message_read(m, "ynqiuxtd", &y, &n, &q, &i, &u, &x, &t, &d);

Leer una estructura compuesta por una cadena y una ruta de D-Bus:

const char *s, *p;
sd_bus_message_read(m, "(so)", &s, &p);

Leer una variante, con el tipo real "gt" (firma, entero sin signo):

const char *s;
uint64_t *v;
sd_bus_message_read(m, "v", "gt", &s, &v);

Leer un diccionario que contiene tres pares de tipo {entero=>cadena}:

int i, j, k;
const char *s, *t, *u;
sd_bus_message_read(m, "a{is}", 3, &i, &s, &j, &t, &k, &u);

Leer un único descriptor de archivo, y duplicarlo para mantenerlo abierto después de liberar el mensaje.

sd_bus_message *m;
int fd, fd_copy;
sd_bus_message_read(m, "h", &fd);
fd_copy = fcntl(fd, FD_DUPFD_CLOEXEC, 3);

HISTORY

sd_bus_message_read() y sd_bus_message_readv() se añadieron en la versión 240.

sd_bus_message_peek_type() se añadió en la versión 246.
