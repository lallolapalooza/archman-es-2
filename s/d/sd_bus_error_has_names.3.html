DESCRIPCIÓN

La estructura sd_bus_error transporta información sobre una condición de error de D-Bus, o la falta de ella. Las funciones descritas a continuación pueden usarse para establecer y consultar campos en esta estructura.

•El campo nombre contiene un identificador corto de un error. Debe seguir las reglas para nombres de error descritas en la especificación D-Bus, subsección Nombres D-Bus Válidos[1]. Un número de nombres de error comunes y estandarizados se describen en sd-bus-errors(3), pero las aplicaciones pueden definir errores adicionales específicos del dominio.
•El campo mensaje generalmente contiene una cadena legible por humanos que describe los detalles, pero puede ser NULL.

Una estructura sd_bus_error no establecida debe tener ambos campos inicializados a NULL, y significa falta de error, es decir, éxito. Asigne SD_BUS_ERROR_NULL a la estructura para inicializar ambos campos a NULL. Cuando ya no sean necesarios, los recursos mantenidos por la estructura sd_bus_error deben destruirse con sd_bus_error_free().

sd_bus_error_set() establece una estructura de error con los nombres y mensajes especificados. Las cadenas se copiarán en memoria interna recién asignada. Es esencial liberar el contenido nuevamente cuando ya no se necesiten (ver arriba). No use esta llamada en estructuras de error que ya hayan sido establecidas. Si tiene la intención de reutilizar una estructura de error, libere los datos antiguos almacenados en ella con sd_bus_error_free() primero.

sd_bus_error_set() devolverá un valor similar a errno (ver errno(3)) determinado por el nombre de error especificado nombre. Si nombre es NULL, se asume que no ocurrió ningún error y se devuelve 0. Si nombre no es nulo, siempre se devuelve un valor negativo. Si e es NULL, no se inicializa ninguna estructura de error, pero nombre todavía se convierte en un valor de estilo errno.

Varios errores D-Bus bien conocidos se convierten en sus contrapartes errno bien conocidas, y los demás a -EIO. Consulte sd-bus-errors(3) para obtener una lista de nombres de error bien conocidos. Se pueden definir mapeos de error adicionales con sd_bus_error_add_map(3).

sd_bus_error_set() está diseñado para usarse cómodamente en una sentencia return. Si mensaje es NULL, no se establece ningún mensaje. Esta llamada puede fallar si no se puede asignar memoria para las cadenas de nombre y mensaje, en cuyo caso se establecerá un error SD_BUS_ERROR_NO_MEMORY y se devolverá -ENOMEM.

sd_bus_error_setf() y sd_bus_error_setfv() son similares a sd_bus_error_set(), pero toman una cadena de formato printf(3) y argumentos correspondientes para generar el campo mensaje. sd_bus_error_setf() usa argumentos variádicos, y sd_bus_error_setfv() acepta los argumentos como una lista de parámetros va_arg(3).

sd_bus_error_set_const() es similar a sd_bus_error_set(), pero los parámetros de cadena no se copian internamente y, por lo tanto, deben permanecer constantes y válidos durante la vida útil de e. Use esta llamada para evitar asignaciones de memoria al establecer estructuras de error. Dado que esta llamada no asigna memoria, no fallará con una condición de falta de memoria como puede ocurrir con sd_bus_error_set(), como se describe anteriormente. Alternativamente, la macro SD_BUS_ERROR_MAKE_CONST() se puede usar para generar una estructura de error literal y constante sobre la marcha.

sd_bus_error_set_errno() devolverá inmediatamente 0 si el parámetro de error especificado error es 0. De lo contrario, establecerá nombre a partir de un valor similar a errno que se convierte a un error D-Bus. strerror_r(3) se utilizará para establecer mensaje. Se utilizarán nombres de error bien conocidos de D-Bus para nombre si corresponde, de lo contrario, se generará un nombre en el espacio de nombres "System.Error.". Se ignora el signo del número de error especificado y se utiliza implícitamente el valor absoluto. Si el error especificado error no es cero, la llamada siempre devuelve un valor negativo, para un uso conveniente en sentencias return. Esta llamada puede fallar debido a falta de memoria, en cuyo caso se establece un error SD_BUS_ERROR_NO_MEMORY en su lugar y se devuelve -ENOMEM.

sd_bus_error_set_errnof() y sd_bus_error_set_errnof() son similares a sd_bus_error_set_errno(), pero además de error, toman una cadena de formato printf(3) y argumentos correspondientes. El campo mensaje se generará a partir de formato y los argumentos. sd_bus_error_set_errnof() usa argumentos variádicos, y sd_bus_error_set_errnofv() acepta los argumentos como una lista de parámetros va_arg(3).

sd_bus_error_get_errno() convierte el campo nombre de una estructura de error a un valor (positivo) similar a errno utilizando las mismas reglas que sd_bus_error_set(). Si e es NULL, se devolverá 0.

sd_bus_error_copy() inicializará dst utilizando los valores en e, si e se ha establecido previamente con un valor de error. De lo contrario, devolverá inmediatamente. Si las cadenas en e se establecieron usando sd_bus_error_set_const(), se compartirán. De lo contrario, se copiarán. Antes de esta llamada, dst debe no estar establecido, es decir, recién inicializado con NULL o restablecido usando sd_bus_error_free().

sd_bus_error_copy() generalmente devuelve 0 o un valor negativo similar a errno basado en el parámetro de entrada e: 0 si no estaba establecido y un entero negativo si estaba establecido en algún error, de manera similar a sd_bus_error_set(). DESCRIPTION

El tipo sd_bus_error representa un error de D-Bus. Contiene dos campos, name y message, ambos de tipo `const char *`. El campo name contiene el nombre del error, y message contiene una descripción textual de él. Ver sd-bus-errors(3) para una lista de nombres de error comunes.

Al principio, se supone que una estructura de error no tiene ningún error establecido. Esto se indica estableciendo ambos campos name y message a NULL. Si se llama a sd_bus_error_free() en una estructura no configurada, no se realiza ninguna operación.

sd_bus_error_set() configura la estructura de error error con el nombre name y el mensaje message. Tenga en cuenta que se hace una copia de estos valores de cadena. Si name o message son NULL, se tratan como cadenas vacías. Si error ya estaba configurado, el error anterior se libera y se sobrescribe. La función devuelve el código de error de D-Bus convertido, o un valor negativo similar a errno.

sd_bus_error_setf() y sd_bus_error_setfv() son similares a sd_bus_error_set(), pero permiten formatear el mensaje de error usando una cadena de formato y argumentos de variable. La función sd_bus_error_setfv() es una variante que toma una lista de argumentos de variable directamente.

sd_bus_error_set_const() es como sd_bus_error_set(), pero toma posesión de las cadenas pasadas. Esto significa que las cadenas pasadas para name y message no deben ser liberadas por el llamador y deben ser cadenas estáticas o asignadas dinámicamente que se mantendrán válidas hasta que el error sea liberado con sd_bus_error_free(). Esto es útil si desea evitar una copia innecesaria de la cadena.

sd_bus_error_set_errno(), sd_bus_error_set_errnof() y sd_bus_error_set_errnofv() son similares a las funciones de establecimiento de errores anteriores, pero configuran el nombre del error basándose en un código de error errno dado. El nombre del error de D-Bus se genera a partir del número errnum. Si errnum es 0, se establece un error genérico apropiado. El mensaje de error se puede formatear de forma similar a sd_bus_error_setf() y sd_bus_error_setfv().

sd_bus_error_get_errno() intenta mapear el nombre del error de D-Bus e->name de vuelta a un código de error errno. Si el mapeo tiene éxito, se devuelve el código errno positivo. De lo contrario, se devuelve 0. Si e es NULL, se devuelve false.

sd_bus_error_copy() copia la información del error de src a dst. Si src no tiene un error establecido, dst se establece en no tener un error establecido. Si se produce un error durante la asignación de memoria, se devuelve un código de error negativo.

sd_bus_error_move() es similar a sd_bus_error_copy(), pero moverá cualquier información de error de e a dst, reiniciando el primero. Esta función no puede fallar, ya que no se asigna memoria nueva. Tenga en cuenta que si e no está establecido, dst se inicializa a SD_BUS_ERROR_NULL. Además, si dst es NULL no se realiza ninguna operación sobre él y los recursos que e tiene se liberan y se reinician. Devuelve un valor de error convertido similar a errno, no positivo.

sd_bus_error_is_set() devolverá un valor distinto de cero si e no es NULL y se ha establecido un error, false en caso contrario.

sd_bus_error_has_name() devolverá un valor distinto de cero si e no es NULL y se ha establecido un error con el mismo name, false en caso contrario.

sd_bus_error_has_names_sentinel() es similar a sd_bus_error_has_name(), pero toma varios nombres para comprobar. La lista debe terminar con NULL. sd_bus_error_has_names() es un envoltorio macro alrededor de sd_bus_error_has_names_sentinel() que agrega el centinela NULL automáticamente.

sd_bus_error_free() destruirá los recursos en poder de e. El parámetro en sí no se desasignará y deberá ser free(3)do por el llamador si es necesario. La función también puede llamarse de forma segura en errores no establecidos (estructuras de error con ambos campos establecidos a NULL), en cuyo caso no realiza ninguna operación. Esta llamada reiniciará la estructura de error después de liberar los datos, de modo que todos los campos se establezcan en NULL. La estructura puede ser reutilizada posteriormente.

REFERENCE OWNERSHIP

sd_bus_error no tiene recuento de referencias. Los usuarios deben destruir los recursos que tiene llamando a sd_bus_error_free(). Normalmente, las estructuras de error se asignan en la pila o se pasan como parámetros de función, pero también pueden asignarse dinámicamente, en cuyo caso es deber del llamador free(3) la memoria que tiene la estructura en sí misma después de liberar su contenido con sd_bus_error_free().

RETURN VALUE

Las funciones sd_bus_error_set(), sd_bus_error_setf(), y sd_bus_error_set_const() siempre devuelven 0 cuando el valor de error especificado es NULL, y un valor negativo similar a errno correspondiente al parámetro name en caso contrario. Las funciones sd_bus_error_set_errno(), sd_bus_error_set_errnof() y sd_bus_error_set_errnofv(), devuelven 0 cuando el valor de error especificado es 0, y un valor negativo similar a errno correspondiente al parámetro error en caso contrario. Si ocurre un error internamente, se devolverá uno de los valores de error negativos enumerados a continuación. Esto permite que estas funciones se utilicen convenientemente en una declaración return, véase el ejemplo a continuación.

sd_bus_error_get_errno() devuelve false cuando e es NULL, y un valor positivo errno mapeado desde e->name en caso contrario.

sd_bus_error_copy() y sd_bus_error_move() devuelven un valor de error negativo convertido del error de origen, y cero si el error no se ha establecido. Esto permite que estas funciones se utilicen convenientemente en una declaración return, véase el ejemplo a continuación.

sd_bus_error_is_set() devuelve un valor distinto de cero cuando e y el campo name no son NULL, cero en caso contrario.

sd_bus_error_has_name(), sd_bus_error_has_names(), y sd_bus_error_has_names_sentinel() devuelven un valor distinto de cero cuando e no es NULL y el campo name es igual a uno de los nombres dados, cero en caso contrario.

Errors

El valor de retorno puede indicar los siguientes problemas en la invocación de la propia función:

-EINVAL

El error ya estaba establecido en la estructura sd_bus_error cuando se llamó a una de las funciones de establecimiento de errores.

-ENOMEM

Fallo en la asignación de memoria.

En caso de éxito, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy(), y sd_bus_error_move() devolverán un valor negativo de errno convertido, o 0 si el parámetro de error es NULL o no está establecido. Los errores de D-Bus se convierten al valor integral de errno, y el mecanismo de mapeo es extensible, véase la discusión anterior. Esto significa efectivamente que casi cualquier valor negativo de errno puede ser devuelto.

EXAMPLES

Ejemplo 1. Uso del valor de retorno negativo para propagar un error

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "Hello, World!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* En caso de éxito, devuelve el número de bytes escritos, posiblemente 0. */
  /* En caso de error, inicializa la estructura de error, y también propaga el valor errno
   * que write(2) estableció para nosotros. */
  return sd_bus_error_set_errnof(error, errno, "Error al escribir en fd %i: %s", fd, strerror(errno));
}

NOTES

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que está declarado como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones aquí descritas no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
