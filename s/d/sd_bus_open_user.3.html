DESCRIPCIÓN

sd_bus_default() adquiere un objeto de conexión de bus al bus de usuario cuando se invoca dentro de una partición de usuario (cualquier sesión bajo "user-*.slice", por ejemplo: "user@1000.service"), o al bus del sistema en caso contrario. El objeto de conexión está asociado con el hilo que llama. Cada vez que la función se invoca desde el mismo hilo, se devuelve el mismo objeto, pero su contador de referencias se incrementa en uno, siempre que se mantenga al menos una referencia. Cuando la última referencia a la conexión se suelta (usando la llamada sd_bus_unref(3)), la conexión se termina. Tenga en cuenta que la conexión no se termina automáticamente cuando el hilo asociado finaliza. Es importante soltar explícitamente la última referencia a la conexión del bus antes de que el hilo finalice, de lo contrario, la conexión tendrá una fuga. Además, los mensajes en cola pero no leídos o no escritos mantienen una referencia al bus, véase más abajo.

sd_bus_default_user() devuelve un objeto de conexión del bus de usuario asociado con el hilo que llama. sd_bus_default_system() es similar, pero se conecta al bus del sistema. Tenga en cuenta que sd_bus_default() es idéntico a estas dos llamadas, dependiendo del contexto de ejecución.

sd_bus_open() crea una nueva conexión de bus independiente al bus de usuario cuando se invoca en contexto de usuario, o al bus del sistema en caso contrario. sd_bus_open_user() es similar, pero solo se conecta al bus de usuario. sd_bus_open_system() hace lo mismo, pero se conecta al bus del sistema. En contraste con sd_bus_default(), sd_bus_default_user() y sd_bus_default_system(), estas llamadas devuelven objetos de conexión nuevos e independientes que no están asociados con el hilo que los invoca y no se comparten entre invocaciones múltiples. Se recomienda compartir conexiones por hilo para utilizar eficientemente los recursos disponibles. Por lo tanto, se recomienda usar sd_bus_default(), sd_bus_default_user() y sd_bus_default_system() para conectarse a los buses de usuario o sistema.

sd_bus_open_with_description(), sd_bus_open_user_with_description() y sd_bus_open_system_with_description() son similares a sd_bus_open(), sd_bus_open_user() y sd_bus_open_system(), pero permiten establecer una cadena de descripción, véase sd_bus_set_description(3). description puede ser NULL, en cuyo caso esta función es equivalente a sd_bus_open(). Esta cadena de descripción se utiliza en mensajes de registro sobre el objeto del bus, y la inclusión de un "nombre" para el bus los hace más fáciles de entender. Algunos mensajes se emiten durante la inicialización del bus, por lo tanto, el uso de esta función es preferible a establecer la descripción más tarde con sd_bus_open_with_description(). El argumento se copia internamente y no se referenciará después de que la función devuelva.

Si la variable de entorno $DBUS_SESSION_BUS_ADDRESS está establecida (véase environ(7)), se utilizará como la dirección del bus de usuario. Esta variable puede contener múltiples direcciones separadas por ";". Si esta variable no está establecida, se utilizará un valor predeterminado adecuado para la instancia predeterminada de D-Bus de usuario.

Si la variable de entorno $DBUS_SYSTEM_BUS_ADDRESS está establecida, se utilizará como la dirección del bus del sistema. Esta variable utiliza la misma sintaxis que $DBUS_SESSION_BUS_ADDRESS. Si esta variable no está establecida, se utilizará un valor predeterminado adecuado para la instancia predeterminada de D-Bus del sistema.

sd_bus_open_system_remote() se conecta al bus del sistema en el host especificado utilizando ssh(1). host consiste en un nombre de usuario opcional seguido del símbolo "@", y el nombre del host, opcionalmente seguido de un ":" y un puerto, opcionalmente seguido de un "/" y un nombre de máquina. Si se proporciona el nombre de la máquina, se crea una conexión al bus del sistema en el contenedor especificado en la máquina remota, y de lo contrario, se crea una conexión al bus del sistema en el host especificado.

Tenga en cuenta que entrar en un contenedor es una operación privilegiada y es probable que solo funcione para el usuario root en la máquina remota.

sd_bus_open_system_machine() se conecta al bus del sistema en la máquina especificada, donde máquina es el nombre de un contenedor local, posiblemente prefijado por un nombre de usuario y un separador "@". Si el nombre del contenedor se especifica como la cadena especial ".host", la conexión se realiza al sistema local. Esto es útil para conectarse al bus del sistema local como un usuario específico, por ejemplo, "foobar@.host" para conectarse al bus del sistema local como el usuario local "foobar". Si se utiliza la sintaxis "@", se puede omitir el lado izquierdo o el lado derecho (pero no ambos) en cuyo caso se implica el nombre de usuario local o ".host". Si no se utiliza la sintaxis "@", la conexión se realiza siempre como usuario root. Consulte sd_bus_set_address(3) para obtener una descripción de la sintaxis de la dirección, y machinectl(1) para obtener más información sobre el concepto de "máquina". Tenga en cuenta que las conexiones a contenedores locales solo están disponibles para procesos privilegiados en este momento.

sd_bus_open_user_machine() es similar a sd_bus_open_system_machine(), pero se conecta al bus de usuario del usuario root, o si se utiliza la sintaxis "@", del usuario especificado.

Estas llamadas asignan un objeto de conexión de bus e inician la conexión a un bus bien conocido de alguna forma. Una alternativa a usar estas llamadas de alto nivel es crear un objeto de bus no conectado con sd_bus_new(3) y conectarlo con sd_bus_start(3).

PROPIEDAD DE REFERENCIA

Las funciones sd_bus_open(), sd_bus_open_user(), sd_bus_open_user_machine(), sd_bus_open_system(), sd_bus_open_system_remote() y sd_bus_open_system_machine() devuelven un nuevo objeto de conexión y el llamador posee la única referencia. Cuando ya no sea necesario, esta referencia debe destruirse con sd_bus_unref(3).

Las funciones sd_bus_default(), sd_bus_default_user() y sd_bus_default_system() no crean necesariamente un nuevo objeto, sino que incrementan la referencia de conexión de un objeto de conexión existente en uno. Utilice sd_bus_unref(3) para soltar la referencia.

Los mensajes en cola pero no escritos/leídos mantienen una referencia a su objeto de conexión de bus. Por esta razón, incluso si una aplicación ha soltado todas las referencias a una conexión de bus, es posible que no se destruya de inmediato. Hasta que se lean todos los mensajes entrantes en cola, y hasta que se escriban todos los mensajes salientes no escritos, el objeto del bus permanecerá activo. sd_bus_flush() puede usarse para escribir todos los mensajes salientes en cola para que suelten sus referencias. sd_bus_open_user(3) — systemd — Arch Linux

NAME

sd_bus_open_user, sd_bus_open_system, sd_bus_open_system_remote, sd_bus_open_system_machine, sd_bus_default_user, sd_bus_default_system, sd_bus_default - Conectar a un bus D-Bus del sistema o de usuario

SYNOPSIS

    #include <systemd/sd-bus.h>

    int sd_bus_open_user(sd_bus **bus);
    int sd_bus_open_system(sd_bus **bus);
    int sd_bus_open_system_remote(sd_bus **bus, const char *path);
    int sd_bus_open_system_machine(sd_bus **bus, const char *machine);
    int sd_bus_default_user(sd_bus **bus);
    int sd_bus_default_system(sd_bus **bus);
    int sd_bus_default(sd_bus **bus);

DESCRIPTION

sd_bus_open_user() se conecta al bus de la sesión del usuario actual. El bus de la sesión se utiliza típicamente para la comunicación entre las aplicaciones del escritorio y los servicios del sistema específicos del usuario. El bus del sistema, devuelto por sd_bus_open_system(), se utiliza para la comunicación entre los servicios del sistema y a veces entre las aplicaciones del escritorio y los servicios del sistema.

sd_bus_open_system() se conecta al bus del sistema global. Este bus es utilizado por la mayoría de los servicios del sistema, como systemd y udev. También puede ser utilizado por las aplicaciones de usuario para solicitar la ejecución de acciones privilegiadas.

sd_bus_open_system_remote() se conecta a un bus del sistema remoto a través de una conexión SSH. El parámetro path debe contener la ruta al socket del bus del sistema en la máquina remota. Tenga en cuenta que la conexión SSH se gestionará a través del mecanismo de ssh(1) y de systemd-machined.service(8) si está disponible. La autenticación se realizará utilizando las claves SSH configuradas para el usuario actual. La máquina remota debe ser accesible y configurada para permitir el acceso al bus del sistema a través de SSH.

sd_bus_open_system_machine() se conecta al bus del sistema de una máquina específica dentro de un entorno de contenedores o máquinas virtuales gestionado por machinectl(1). El parámetro machine especifica el nombre de la máquina cuyo bus del sistema se desea conectar. Esto es útil para interactuar con servicios que se ejecutan dentro de máquinas aisladas.

sd_bus_default_user(), sd_bus_default_system() y sd_bus_default() son versiones convenientes de las funciones sd_bus_open_*() que utilizan la lógica de bus predeterminada. Estas funciones son útiles cuando se necesita un acceso rápido al bus de usuario o del sistema, y no se requiere una configuración de conexión específica. sd_bus_default() intenta conectarse primero al bus del sistema y, si falla, se conecta al bus del usuario.

Estas funciones devuelven un objeto sd_bus que representa la conexión al bus. Este objeto debe ser liberado utilizando sd_bus_unref(3) cuando ya no sea necesario.

REFERENCE OWNERSHIP

El objeto sd_bus devuelto por estas funciones es un objeto de referencia, como se describe en sd_bus_ref(3). Inicialmente, tiene una referencia. Debe llamar a sd_bus_unref(3) cuando ya no necesite el objeto sd_bus para liberar la memoria asociada. Para mantener la conexión abierta después de que la referencia original sea liberada, debe duplicarla usando sd_bus_ref(3).

Para cerrar la conexión del bus y liberar los recursos asociados, llame a sd_bus_close(3). Si está utilizando la lógica de bus predeterminada, es una buena idea invocar primero sd_bus_flush(3) seguido de sd_bus_close(3) cuando un hilo o proceso termina, y por lo tanto su objeto de conexión de bus debe ser liberado.

Normalmente, los objetos de slot (como los creados por sd_bus_add_match(3) y llamadas similares) también mantienen una referencia a su objeto de conexión de bus. Por lo tanto, mientras un objeto de slot de bus permanezca referenciado, su objeto de bus también permanecerá asignado. Opcionalmente, los objetos de slot de bus pueden colocarse en modo "flotante". Cuando está en modo flotante, el ciclo de vida del objeto de slot de bus está vinculado al objeto de bus, es decir, cuando el objeto de bus se libera, el objeto de slot de bus también se desreferencia automáticamente. El estado flotante de un objeto de slot puede controlarse explícitamente con sd_bus_slot_set_floating(3), aunque normalmente los objetos de slot de bus flotantes se crean pasando NULL como parámetro slot de sd_bus_add_match(3) y llamadas relacionadas, indicando así que el llamador no está directamente interesado en referenciar y gestionar el objeto de slot de bus.

El ciclo de vida de la conexión de bus predeterminada debe ser responsabilidad del código que crea/posee el hilo con el que está asociado el objeto de conexión de bus predeterminada. El código de la biblioteca no debe llamar a sd_bus_flush(3) ni a sd_bus_close(3) en objetos de bus predeterminados, a menos que lo haga en su propio hilo privado y autoasignado. El código de la biblioteca no debe utilizar el objeto de bus predeterminado en otros hilos, a menos que esté claro que el programa que lo utiliza gestionará el ciclo de vida del objeto de conexión de bus y lo vaciará y cerrará antes de salir del hilo. Por lo tanto, en bibliotecas donde no está claro que el programa llamante gestionará el ciclo de vida del objeto de conexión de bus, se recomienda usar sd_bus_open_system(3) en lugar de sd_bus_default_system(3) y llamadas relacionadas.

RETURN VALUE

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, estas llamadas devuelven un código de error negativo de estilo errno.

Errors

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Los parámetros especificados no son válidos.

-ENOMEDIUM

El tipo de bus solicitado no está disponible debido a un entorno inválido (por ejemplo, el bus de sesión del usuario no está disponible porque $XDG_RUNTIME_DIR no está establecido).

-ENOMEM

Falló la asignación de memoria.

-ESOCKTNOSUPPORT

La versión del protocolo requerida para conectarse al bus seleccionado no es compatible.

Además, pueden devolverse otros errores relacionados con la conexión. Consulte sd_bus_send(3).

NOTES

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar solo llamadas a setenv() desde una fase temprana del programa, cuando aún no se han iniciado otros hilos.
