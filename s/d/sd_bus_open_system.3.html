DESCRIPCIÓN

sd_bus_default() adquiere un objeto de conexión de bus al bus de usuario cuando se invoca desde una unidad de usuario (cualquier sesión bajo "user-*.slice", por ejemplo: "user@1000.service"), o al bus del sistema en caso contrario. El objeto de conexión está asociado con el hilo que realiza la llamada. Cada vez que la función se invoca desde el mismo hilo, se devuelve el mismo objeto, pero su contador de referencias se incrementa en uno, siempre que se mantenga al menos una referencia. Cuando se suelta la última referencia a la conexión (usando la llamada sd_bus_unref(3)), la conexión se termina. Tenga en cuenta que la conexión no se termina automáticamente cuando finaliza el hilo asociado. Es importante soltar explícitamente la última referencia a la conexión del bus antes de que finalice el hilo, ya que de lo contrario, la conexión tendrá una fuga. Además, los mensajes en cola pero no leídos o no escritos mantienen una referencia al bus, véase más abajo.

sd_bus_default_user() devuelve un objeto de conexión de bus de usuario asociado con el hilo que realiza la llamada. sd_bus_default_system() es similar, pero se conecta al bus del sistema. Tenga en cuenta que sd_bus_default() es idéntico a estas dos llamadas, dependiendo del contexto de ejecución.

sd_bus_open() crea una nueva conexión de bus independiente al bus de usuario cuando se invoca en contexto de usuario, o al bus del sistema en caso contrario. sd_bus_open_user() es similar, pero solo se conecta al bus de usuario. sd_bus_open_system() hace lo mismo, pero se conecta al bus del sistema. A diferencia de sd_bus_default(), sd_bus_default_user() y sd_bus_default_system(), estas llamadas devuelven objetos de conexión nuevos e independientes que no están asociados con el hilo que los invoca y no se comparten entre múltiples invocaciones. Se recomienda compartir conexiones por hilo para utilizar eficientemente los recursos disponibles. Por lo tanto, se recomienda utilizar sd_bus_default(), sd_bus_default_user() y sd_bus_default_system() para conectarse a los buses de usuario o del sistema.

sd_bus_open_with_description(), sd_bus_open_user_with_description() y sd_bus_open_system_with_description() son similares a sd_bus_open(), sd_bus_open_user() y sd_bus_open_system(), pero permiten establecer una cadena de descripción, véase sd_bus_set_description(3). description puede ser NULL, en cuyo caso esta función es equivalente a sd_bus_open(). Esta cadena de descripción se utiliza en mensajes de registro sobre el objeto de bus, y la inclusión de un "nombre" para el bus facilita su comprensión. Algunos mensajes se emiten durante la inicialización del bus, por lo que el uso de esta función es preferible a establecer la descripción más tarde con sd_bus_open_with_description(). El argumento se copia internamente y no se referenciará después de que la función devuelva.

Si la variable de entorno $DBUS_SESSION_BUS_ADDRESS está establecida (cf. environ(7)), se utilizará como la dirección del bus de usuario. Esta variable puede contener múltiples direcciones separadas por ";". Si esta variable no está establecida, se utilizará un valor predeterminado adecuado para la instancia de D-Bus de usuario predeterminada.

Si la variable de entorno $DBUS_SYSTEM_BUS_ADDRESS está establecida, se utilizará como la dirección del bus del sistema. Esta variable utiliza la misma sintaxis que $DBUS_SESSION_BUS_ADDRESS. Si esta variable no está establecida, se utilizará un valor predeterminado adecuado para la instancia de D-Bus del sistema predeterminada.

sd_bus_open_system_remote() se conecta al bus del sistema en el host especificado utilizando ssh(1). host consiste en un nombre de usuario opcional seguido del símbolo "@", y el nombre del host, opcionalmente seguido de un ":" y un puerto, opcionalmente seguido de un "/" y un nombre de máquina. Si se proporciona el nombre de la máquina, se crea una conexión al bus del sistema en el contenedor especificado en la máquina remota, y de lo contrario, se crea una conexión al bus del sistema en el host especificado.

Tenga en cuenta que entrar en un contenedor es una operación privilegiada, y probablemente solo funcionará para el usuario root en la máquina remota.

sd_bus_open_system_machine() se conecta al bus del sistema en la máquina especificada, donde máquina es el nombre de un contenedor local, posiblemente prefijado por un nombre de usuario y un separador "@". Si el nombre del contenedor se especifica como la cadena especial ".host", la conexión se realiza al sistema local. Esto es útil para conectarse al bus del sistema local como un usuario específico, por ejemplo, "foobar@.host" para conectarse al bus del sistema local como el usuario local "foobar". Si se utiliza la sintaxis "@", se puede omitir el lado izquierdo o el lado derecho (pero no ambos), en cuyo caso se implica el nombre de usuario local o ".host". Si no se utiliza la sintaxis "@", la conexión siempre se realiza como usuario root. Consulte sd_bus_set_address(3) para obtener una descripción de la sintaxis de la dirección, y machinectl(1) para obtener más información sobre el concepto de "máquina". Tenga en cuenta que las conexiones a contenedores locales solo están disponibles para procesos privilegiados en este momento.

sd_bus_open_user_machine() es similar a sd_bus_open_system_machine(), pero se conecta al bus de usuario del usuario root, o si se utiliza la sintaxis "@", al de usuario especificado.

Estas llamadas asignan un objeto de conexión de bus e inician la conexión a un bus bien conocido de algún tipo. Una alternativa a usar estas llamadas de alto nivel es crear un objeto de bus no conectado con sd_bus_new(3) y conectarlo con sd_bus_start(3).

PROPIEDAD DE LA REFERENCIA

Las funciones sd_bus_open(), sd_bus_open_user(), sd_bus_open_user_machine(), sd_bus_open_system(), sd_bus_open_system_remote() y sd_bus_open_system_machine() devuelven un nuevo objeto de conexión y el llamante es el propietario de la única referencia. Cuando ya no se necesite, esta referencia debe destruirse con sd_bus_unref(3).

Las funciones sd_bus_default(), sd_bus_default_user() y sd_bus_default_system() no crean necesariamente un nuevo objeto, sino que incrementan la referencia de conexión de un objeto de conexión existente en uno. Utilice sd_bus_unref(3) para soltar la referencia.

Los mensajes en cola pero no escritos/leídos mantienen una referencia a su objeto de conexión de bus. Por esta razón, incluso si una aplicación soltó todas las referencias a una conexión de bus, es posible que no se destruya de inmediato. Hasta que se lean todos los mensajes en cola entrantes, y hasta que se escriban todos los mensajes salientes no escritos, el objeto de bus permanecerá vivo. sd_bus_flush() se puede utilizar para escribir todos los mensajes en cola salientes para que suelten sus referencias. SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_open_system(sd_bus **bus);

int sd_bus_open_user(sd_bus **bus);

int sd_bus_open_system_remote(sd_bus **bus, const char *path);

int sd_bus_open_system_machine(sd_bus **bus, const char *machine_name);

int sd_bus_open_with_description(sd_bus **bus, const char *description);

int sd_bus_open_user_with_description(sd_bus **bus, const char *description);

int sd_bus_open_system_with_description(sd_bus **bus, const char *description);

int sd_bus_open_user_machine(sd_bus **bus, const char *machine_name);

int sd_bus_default(sd_bus **bus);

int sd_bus_default_user(sd_bus **bus);

int sd_bus_default_system(sd_bus **bus);

DESCRIPTION

These functions are used to obtain a reference to a bus connection object, representing a connection to a D-Bus message bus. The bus connection object is returned in the bus parameter. The reference count of the bus connection object is initially one.

sd_bus_open_system() connects to the system bus. This is typically the bus used for system-wide services. It may require root privileges, depending on the bus setup.

sd_bus_open_user() connects to the session bus of the current user. This is typically the bus used for user services and applications.

sd_bus_open_system_remote() connects to a remote system bus, specified by path. This is typically used to connect to a system bus running on another host, possibly over SSH. See ssh(1) for details on the format of path.

sd_bus_open_system_machine() connects to the system bus of a specific system, identified by machine_name. This is used when connecting to buses of virtual machines or containers managed by systemd-machined.service(8). See machinectl(1) for details on machine_name.

sd_bus_open_with_description(), sd_bus_open_user_with_description(), and sd_bus_open_system_with_description() behave like sd_bus_open(), sd_bus_open_user(), and sd_bus_open_system() respectively, but use the bus address string specified in description instead of trying to determine it from environment variables or default paths. This allows for more explicit control over which bus to connect to.

sd_bus_open_user_machine() is an alias for sd_bus_open_user() and is provided for consistency with sd_bus_open_system_machine().

sd_bus_default(), sd_bus_default_user(), and sd_bus_default_system() are convenience functions that return a reference to a bus connection object that is associated with the current thread. If no such object exists yet, it is created. These functions should primarily be used from the main thread of a process. For library code, it is generally recommended to use sd_bus_open_system() or sd_bus_open_user() instead, to avoid issues with the bus connection object's lifetime management.

The bus connection object obtained should be freed using sd_bus_unref(3) when it is no longer needed. If the bus connection is explicitly closed with sd_bus_close(3), it should be flushed first using sd_bus_flush(3).

REFERENCE OWNERSHIP

All bus connection objects obtained from these functions have a reference count of one. The caller is responsible for decreasing the reference count using sd_bus_unref(3) when the object is no longer needed. When the reference count drops to zero, the bus connection is closed and the object is freed.

When using the default bus logic (i.e., sd_bus_default(), sd_bus_default_user(), sd_bus_default_system()), the bus connection object is associated with the calling thread. If the thread terminates, the bus connection is implicitly closed and the object is freed. It is still recommended to explicitly close the bus connection using sd_bus_close(), which will also close the bus connection. When using the default bus logic, it is a good idea to first invoke sd_bus_flush() followed by sd_bus_close() when a thread or process terminates, and thus its bus connection object should be freed.

Normally, slot objects (as created by sd_bus_add_match(3) and similar calls) keep a reference to their bus connection object, too. Thus, as long as a bus slot object remains referenced its bus object will remain allocated too. Optionally, bus slot objects may be placed in "floating" mode. When in floating mode the life cycle of the bus slot object is bound to the bus object, i.e. when the bus object is freed the bus slot object is automatically unreferenced too. The floating state of a slot object may be controlled explicitly with sd_bus_slot_set_floating(3), though usually floating bus slot objects are created by passing NULL as the slot parameter of sd_bus_add_match() and related calls, thus indicating that the caller is not directly interested in referencing and managing the bus slot object.

The life cycle of the default bus connection should be the responsibility of the code that creates/owns the thread the default bus connection object is associated with. Library code should neither call sd_bus_flush() nor sd_bus_close() on default bus objects unless it does so in its own private, self-allocated thread. Library code should not use the default bus object in other threads unless it is clear that the program using it will life cycle the bus connection object and flush and close it before exiting from the thread. In libraries where it is not clear that the calling program will life cycle the bus connection object, it is hence recommended to use sd_bus_open_system() instead of sd_bus_default_system() and related calls.

RETURN VALUE

On success, these calls return 0 or a positive integer. On failure, these calls return a negative errno-style error code.

Errors

Returned errors may indicate the following problems:

-EINVAL

The specified parameters are invalid.

-ENOMEDIUM

The requested bus type is not available because of invalid environment (for example the user session bus is not available because $XDG_RUNTIME_DIR is not set).

-ENOMEM

Memory allocation failed.

-ESOCKTNOSUPPORT

The protocol version required to connect to the selected bus is not supported.

In addition, other connection-related errors may be returned. See sd_bus_send(3).

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
