SD_EVENT_ADD_MEMORY_PRESSURE(3) sd_event_add_memory_pressure SD_EVENT_ADD_MEMORY_PRESSURE(3)

NOMBRE

sd_event_add_memory_pressure, sd_event_source_set_memory_pressure_type, sd_event_source_set_memory_pressure_period, sd_event_trim_memory - Añadir y configurar una fuente de eventos que se ejecuta como resultado de la presión de memoria

SINOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

int sd_event_add_memory_pressure(sd_event *event, sd_event_source **ret_source, sd_event_handler_t handler, void *userdata);

int sd_event_source_set_memory_pressure_type(sd_event_source *source, const char *type);

int sd_event_source_set_memory_pressure_period(sd_event_source *source, uint64_t threshold_usec, uint64_t window_usec);

int sd_event_trim_memory(void);

DESCRIPCIÓN

sd_event_add_memory_pressure() añade una nueva fuente de eventos que se activa cuando se detecta presión de memoria. Esta funcionalidad está construida alrededor de la lógica de Información de Bloqueo de Presión (PSI)[1] del kernel de Linux.

Espera un objeto de bucle de eventos como primer parámetro y devuelve el objeto de fuente de eventos asignado en el segundo parámetro, si tiene éxito. El parámetro handler es una función a llamar cuando se detecta presión de memoria, o NULL. La función handler recibirá el puntero userdata, que puede ser elegido libremente por el llamante. El handler puede devolver un valor negativo para indicar un error (ver abajo), otros valores de retorno son ignorados. Si handler es NULL, se usará un handler por defecto que compacta las cachés de asignación mantenidas por libsystemd así como por glibc (a través de malloc_trim(3)).

Para destruir un objeto de fuente de eventos usa sd_event_source_unref(3), pero ten en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se eliminan todas las referencias a la fuente de eventos. Para asegurarte de que una fuente de eventos no se active más, incluso si todavía está referenciada, deshabilita la fuente de eventos usando sd_event_source_set_enabled(3) con SD_EVENT_OFF.

Si el segundo parámetro de sd_event_add_memory_pressure() es NULL, no se devuelve ninguna referencia al objeto de fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando el propio bucle de eventos sea destruido.

La fuente de eventos se activará según la siguiente lógica:

1.Si las variables de entorno $MEMORY_PRESSURE_WATCH/$MEMORY_PRESSURE_WRITE están definidas en el momento en que se establece la fuente de eventos, vigilará el archivo, FIFO o socket AF_UNIX especificado a través de $MEMORY_PRESSURE_WATCH (que debe contener un nombre de ruta absoluto) para eventos POLLPRI (en caso de ser un archivo regular) o POLLIN (de lo contrario). Después de abrir el inode, escribirá los datos Base64 (decodificados) proporcionados a través de $MEMORY_PRESSURE_WRITE en él antes de comenzar a consultar (la variable puede no estar definida, en cuyo caso esto se omite). Típicamente, si se usa, $MEMORY_PRESSURE_WATCH contendrá una ruta como /proc/pressure/memory o una ruta a un archivo memory.pressure específico en el sistema de archivos de control de grupos (cgroupfs).
2.Si estas variables de entorno no están definidas, se utilizará el archivo de interfaz PSI local memory.pressure del grupo de control en el que se está ejecutando el proceso invocador.
3.Si dicho archivo no existe, se vigilará en su lugar el archivo de interfaz PSI a nivel de sistema /proc/pressure/memory.

O en otras palabras: preferiblemente se utiliza cualquier configuración explícita pasada por un gestor de servicios (o similar) como fuente de notificación, antes de recurrir a notificaciones locales del servicio y, finalmente, a notificaciones globales del sistema.

Se recomienda que los servicios y aplicaciones que se comportan correctamente reaccionen a los eventos de presión de memoria ejecutando una o más de las siguientes operaciones, para garantizar un comportamiento óptimo incluso en sistemas cargados y con recursos limitados:

•Liberar cachés de asignación como malloc_trim() o similar, tanto implementadas en las bibliotecas consumidas por el programa como en cachés de asignación privadas del propio programa.
•Liberar cualquier otra forma de caché en memoria que pueda recuperarse fácilmente si es necesario (por ejemplo, cachés de navegador).
•Terminar hilos o procesos de trabajo inactivos, o similar.
•Incluso salir completamente del programa si está inactivo y puede iniciarse automáticamente cuando sea necesario (por ejemplo, mediante activación por socket o bus).

Cualquiera de las operaciones sugeridas debería ayudar a aliviar las situaciones de presión de memoria y permitir que el sistema avance reclamando la memoria para otros fines.

Esta fuente de eventos típicamente se activa en bloqueos de presión de memoria, es decir, cuando ya se ha visto latencia operativa por encima de un umbral configurado. Esto debe tenerse en cuenta al discutir si la latencia posterior para readquirir cualquier recurso liberado es aceptable: generalmente es más importante pensar en las latencias que ya ocurrieron que en las que surgirán en el futuro.

Las funciones sd_event_source_set_memory_pressure_type() y sd_event_source_set_memory_pressure_period() se pueden usar para ajustar los parámetros de PSI para las notificaciones de presión. La primera toma "some" o "full" como segundo parámetro, la segunda toma umbrales y períodos de tiempo en microsegundos. Para más detalles sobre estos tres parámetros, ver la documentación de PSI. Tenga en cuenta que estas dos llamadas deben invocarse inmediatamente después de asignar la fuente de eventos, ya que deben configurarse antes de que comience la consulta. Tenga en cuenta también que estas llamadas fallarán si los parámetros de presión de memoria se han pasado a través de las variables de entorno $MEMORY_PRESSURE_WATCH/$MEMORY_PRESSURE_WRITE (o en otras palabras: la configuración proporcionada por un gestor de servicios gana sobre la configuración interna).

La función sd_event_trim_memory() libera varias cachés de asignación internas mantenidas por libsystemd e invoca malloc_trim(3) de glibc. Esto hace que la operación ejecutada cuando el parámetro de función handler de sd_event_add_memory_pressure se pasa como NULL sea directamente accesible para su invocación en cualquier momento (ver arriba). Esta función registrará un mensaje de registro estructurado a nivel LOG_DEBUG (con el ID de mensaje f9b0be465ad540d0850ad32172d57c21) sobre la operación de presión de memoria.

Para más detalles, consulte Manejo de Presión de Memoria en systemd[2].

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo al estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOMEM

Memoria insuficiente para asignar un objeto.

Añadido en la versión 254.

-EINVAL

Se ha pasado un argumento no válido.

Añadido en la versión 254.

-EHOSTDOWN

La variable $MEMORY_PRESSURE_WATCH se ha establecido en la cadena literal /dev/null, para deshabilitar explícitamente el manejo de presión de memoria.

Añadido en la versión 254.

-EBADMSG

La variable $MEMORY_PRESSURE_WATCH se ha establecido en una cadena inválida, por ejemplo, una ruta relativa en lugar de absoluta.

Añadido en la versión 254.

-ENOTTY

La variable $MEMORY_PRESSURE_WATCH apunta a un archivo regular fuera de los sistemas de archivos procfs o cgroupfs.

Añadido en la versión 254.

-EOPNOTSUPP

No se ha especificado ninguna configuración a través de $MEMORY_PRESSURE_WATCH y el kernel local no soporta la interfaz PSI.

Añadido en la versión 254.

-EBUSY

Esto es devuelto por sd_event_source_set_memory_pressure_type() y sd_event_source_set_memory_pressure_period() si se invocan en fuentes de eventos en un momento posterior a inmediatamente después de asignarlas.

Añadido en la versión 254.

-ESTALE

El bucle de eventos ya está terminado.

Añadido en la versión 254.

ERRORES

-ECHILD

El bucle de eventos se ha creado en un proceso, biblioteca o instancia de módulo diferente.

Añadido en la versión 254.

-EDOM

La fuente de eventos pasada no es una fuente de eventos de señal.

Añadido en la versión 254.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para múltiples hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar solo llamadas a setenv() desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
