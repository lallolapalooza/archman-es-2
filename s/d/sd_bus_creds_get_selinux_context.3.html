DESCRIPCIÓN

Estas funciones devuelven información de credenciales de un objeto sd_bus_creds. Los objetos de credenciales se pueden crear con sd_bus_creds_new_from_pid(3), en cuyo caso describen las credenciales del proceso identificado por el PID especificado, con sd_bus_get_name_creds(3), en cuyo caso describen las credenciales de un par del bus identificado por el nombre de bus especificado, con sd_bus_get_owner_creds(3), en cuyo caso describen las credenciales del creador de un bus, o con sd_bus_message_get_creds(3), en cuyo caso describen las credenciales del remitente del mensaje.

No todos los campos de credenciales forman parte de cada objeto "sd_bus_creds". Utilice sd_bus_creds_get_mask(3) para determinar la máscara de campos disponibles.

sd_bus_creds_get_pid() recuperará el PID (identificador de proceso). De manera similar, sd_bus_creds_get_ppid() recuperará el PID del padre. Tenga en cuenta que el PID 1 no tiene proceso padre, en cuyo caso se devuelve -ENXIO.

sd_bus_creds_get_pidfd_dup() recuperará el descriptor de archivo PID (pidfd), consulte pidfd_open(2) para obtener más detalles. El descriptor de archivo se duplica y, por lo tanto, debe ser cerrado por el llamador.

sd_bus_creds_get_tid() recuperará el TID (identificador de hilo).

sd_bus_creds_get_uid() recuperará el UID numérico (identificador de usuario). De manera similar, sd_bus_creds_get_euid() devuelve el UID efectivo, sd_bus_creds_get_suid() el UID guardado y sd_bus_creds_get_fsuid() el UID del sistema de archivos.

sd_bus_creds_get_gid() recuperará el GID numérico (identificador de grupo). De manera similar, sd_bus_creds_get_egid() devuelve el GID efectivo, sd_bus_creds_get_sgid() el GID guardado y sd_bus_creds_get_fsgid() el GID del sistema de archivos.

sd_bus_creds_get_supplementary_gids() recuperará la lista de GIDs suplementarios.

sd_bus_creds_get_comm() recuperará el campo comm (nombre truncado del ejecutable, tal como se almacena en /proc/pid/comm).

sd_bus_creds_get_tid_comm() recuperará el campo comm del hilo (tal como se almacena en /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() recuperará la ruta al ejecutable del programa (tal como se almacena en el enlace /proc/pid/exe, pero con el sufijo " (eliminado)" eliminado). Tenga en cuenta que los hilos del kernel no tienen una ruta ejecutable, en cuyo caso se devuelve -ENXIO. Tenga en cuenta que esta propiedad no debe utilizarse para más que información explicativa, en particular no debe utilizarse para decisiones relacionadas con la seguridad. Esto se debe a que el ejecutable podría haber sido reemplazado o eliminado para cuando el valor pueda ser procesado. DESCRIPCIÓN

Las funciones sd_bus_creds_get_*() y sd_bus_creds_has_*() proporcionan acceso a varios campos de credenciales del D-Bus peer (como se define en la documentación de sd_bus_creds_new_from_pid(3)) o del proceso local. Estas funciones son útiles para implementar políticas de seguridad o para obtener información sobre el interlocutor D-Bus.

Los campos de credenciales disponibles son:

PID
sd_bus_creds_get_pid() recupera el ID del proceso (PID) del peer. Esto puede fallar si el peer es un hilo del kernel.
TID
sd_bus_creds_get_tid() recupera el ID del hilo (TID) del peer. Esto puede fallar si el peer es un hilo del kernel.
PPID
sd_bus_creds_get_ppid() recupera el PID del proceso padre.
UID
sd_bus_creds_get_uid() recupera el ID de usuario real (RUID) del peer. Vea credentials(7).
EUID
sd_bus_creds_get_euid() recupera el ID de usuario efectivo (EUID) del peer.
SUID
sd_bus_creds_get_suid() recupera el ID de usuario guardado (SUID) del peer.
FUID
sd_bus_creds_get_fsuid() recupera el ID de usuario de sistema de archivos (FSUID) del peer.
GID
sd_bus_creds_get_gid() recupera el ID de grupo real (RGID) del peer.
EGID
sd_bus_creds_get_egid() recupera el ID de grupo efectivo (EGID) del peer.
SGID
sd_bus_creds_get_sgid() recupera el ID de grupo guardado (SGID) del peer.
FSGID
sd_bus_creds_get_fsgid() recupera el ID de grupo de sistema de archivos (FSGID) del peer.
Supplementary GIDs
sd_bus_creds_get_supplementary_gids() recupera la lista de IDs de grupo suplementarios del peer.
Comm
sd_bus_creds_get_comm() recupera el nombre corto del comando de 16 bytes del proceso del peer. Vea task_struct(5).
TID Comm
sd_bus_creds_get_tid_comm() recupera el nombre corto del hilo del proceso del peer.
Exe
sd_bus_creds_get_exe() recupera la ruta del ejecutable del proceso. Nota: los hilos del kernel no tienen un ejecutable, en cuyo caso se devuelve -ENXIO.
Cmdline
sd_bus_creds_get_cmdline() recupera una matriz de argumentos de la línea de comandos (tal como se almacena en /proc/pid/cmdline). Nota: los hilos del kernel no tienen línea de comandos, en cuyo caso se devuelve -ENXIO.
Cgroup
sd_bus_creds_get_cgroup() recupera la ruta del grupo de control. Vea Control Groups v2[1].
Unit
sd_bus_creds_get_unit() recupera el nombre de la unidad systemd (en la instancia del sistema de systemd) de la que forma parte el proceso. Vea systemd.unit(5). Para procesos que no forman parte de una unidad, devuelve -ENXIO.
User Unit
sd_bus_creds_get_user_unit() recupera el nombre de la unidad systemd (en la instancia del usuario de systemd) de la que forma parte el proceso. Vea systemd.unit(5). Para procesos que no forman parte de una unidad de usuario, devuelve -ENXIO.
Slice
sd_bus_creds_get_slice() recupera la slice systemd (una unidad en la instancia del sistema de systemd) de la que forma parte el proceso. Vea systemd.slice(5). De manera similar, sd_bus_creds_get_user_slice() recupera la slice systemd del proceso, en la instancia del usuario de systemd.
Session
sd_bus_creds_get_session() recupera el identificador de la sesión de inicio de sesión de la que forma parte el proceso. Tenga en cuenta que la sesión de inicio de sesión puede limitarse a uno o dos procesos stub. Los procesos de usuario pueden iniciarse en su lugar desde su gestor de usuarios systemd, por ejemplo, aplicaciones gráficas iniciadas mediante activación DBus, así como procesos de servicio que se comparten entre múltiples inicios de sesión del mismo usuario. Para procesos que no forman parte de una sesión, devuelve -ENXIO.
Owner UID
sd_bus_creds_get_owner_uid() recupera el UID numérico (identificador de usuario) del usuario que es propietario de la unidad de usuario o sesión de inicio de sesión de la que forma parte el proceso. Vea systemd-logind.service(8). Para procesos que no forman parte de una unidad de usuario o sesión, devuelve -ENXIO.
Effective Capability
sd_bus_creds_has_effective_cap() comprueba si la capacidad especificada por capability estaba establecida en la máscara de capacidades efectivas. Un valor de retorno positivo significa que estaba establecida, cero significa que no estaba establecida, y un valor de retorno negativo indica un error. Vea capabilities(7) y los ajustes AmbientCapabilities= y CapabilityBoundingSet= en systemd.exec(5).
Permitted Capability
sd_bus_creds_has_permitted_cap() es similar a sd_bus_creds_has_effective_cap(), pero comprobará la máscara de capacidades permitidas.
Inheritable Capability
sd_bus_creds_has_inheritable_cap() es similar a sd_bus_creds_has_effective_cap(), pero comprobará la máscara de capacidades heredables.
Bounding Capability
sd_bus_creds_has_bounding_cap() es similar a sd_bus_creds_has_effective_cap(), pero comprobará la máscara de capacidades delimitadoras.
SELinux Context
sd_bus_creds_get_selinux_context() recupera el contexto de seguridad SELinux (etiqueta) del proceso.
Audit Session ID
sd_bus_creds_get_audit_session_id() recupera el identificador de sesión de auditoría del proceso. Devuelve -ENXIO para procesos que no forman parte de una sesión de auditoría.
Audit Login UID
sd_bus_creds_get_audit_login_uid() recupera el identificador de inicio de sesión de usuario de auditoría (el identificador del usuario que es "responsable" de la sesión). Devuelve -ENXIO para procesos que no forman parte de una sesión de auditoría.
TTY
sd_bus_creds_get_tty() recupera el TTY de control, sin el prefijo "/dev/". Devuelve -ENXIO para procesos que no tienen TTY de control.
Unique Name
sd_bus_creds_get_unique_name() recupera el nombre único de D-Bus. Vea La especificación D-Bus[2].
Well-Known Names
sd_bus_creds_get_well_known_names() recupera el conjunto de nombres bien conocidos de D-Bus. Vea La especificación D-Bus[2].
Description
sd_bus_creds_get_description() recupera un nombre descriptivo de la conexión D-Bus del peer. Este nombre es útil para discernir múltiples conexiones D-Bus del mismo peer, y puede ser alterado por el peer con la llamada sd_bus_set_description(3).
Pidfd
sd_bus_creds_get_pidfd_dup() recupera un descriptor de archivo de proceso (pidfd) duplicado del peer. El pidfd devuelto puede usarse con funciones como pidfd_open(2). El pidfd devuelto debe cerrarse explícitamente con close(2).

Todas las funciones que toman un parámetro const char** almacenarán la respuesta allí como la dirección de una cadena terminada en NUL. Será válida mientras c siga siendo válida, y no debe ser liberada ni modificada por el llamador.

Todas las funciones que toman un parámetro char*** o const char*** almacenarán la respuesta allí como la dirección de una matriz de cadenas. Cada cadena individual está terminada en NUL, y la matriz está terminada en NULL en su conjunto. Será válida mientras c siga siendo válida, y no debe ser liberada ni modificada por el llamador.

VALOR DE RETORNO

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, estas llamadas devuelven un código de error negativo de estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENODATA

El campo dado no está disponible en el objeto de credenciales c.

-ENXIO

El campo dado no está especificado para el proceso o peer descrito. Esto será devuelto por sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), y sd_bus_creds_get_session() si el proceso no forma parte de una unidad del sistema systemd, unidad de usuario systemd, slice systemd, o sesión logind. Será devuelto por sd_bus_creds_get_owner_uid() si el proceso no forma parte de una unidad de usuario systemd o sesión logind. También será devuelto por sd_bus_creds_get_exe() y sd_bus_creds_get_cmdline() para hilos del kernel (ya que estos no se inician desde un binario ejecutable, ni tienen una línea de comandos), y por sd_bus_creds_get_audit_session_id() y sd_bus_creds_get_audit_login_uid() cuando el proceso no forma parte de una sesión de auditoría, y sd_bus_creds_get_tty() si el proceso no tiene TTY de control.

-EINVAL

El parámetro de puntero especificado es NULL.

-ENOMEM

Fallo en la asignación de memoria.

-EBADFD

Se devolvió un pidfd inválido en sd_bus_creds_get_pidfd_dup().

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara no seguro para subprocesos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer solo llamadas a setenv() desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
