sd_bus_message_append_array_memfd(3)

Paquete: systemd-libs

SD_BUS_MESSAGE_APPEND_ARRAY(3) sd_bus_message_append_array SD_BUS_MESSAGE_APPEND_ARRAY(3)

NOMBRE

sd_bus_message_append_array, sd_bus_message_append_array_memfd, sd_bus_message_append_array_iovec, sd_bus_message_append_array_space - Añadir un array de campos a un mensaje D-Bus

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_append_array(sd_bus_message *m, char type, const void *ptr, size_t size);

int sd_bus_message_append_array_memfd(sd_bus_message *m, char type, int memfd, uint64_t offset, uint64_t size);

int sd_bus_message_append_array_iovec(sd_bus_message *m, char type, const struct iovec *iov, unsigned n);

int sd_bus_message_append_array_space(sd_bus_message *m, char type, size_t size, void **ptr);

DESCRIPCIÓN

La función sd_bus_message_append_array() añade un array a un mensaje D-Bus m. Se abrirá un contenedor, se añadirán los contenidos del array y se cerrará el contenedor. El parámetro type determina cómo se interpreta el puntero p. type debe ser uno de los tipos "triviales" "y", "n", "q", "i", "u", "x", "t", "d" (pero no "b"), tal como se define en la sección de Tipos Básicos de D-Bus[1] de la especificación de D-Bus, y que se lista en sd_bus_message_append_basic(3). El puntero p debe apuntar a un array de tamaño size bytes que contiene elementos del tipo respectivo. El tamaño size debe ser un múltiplo del tamaño del tipo type. Como caso especial, p puede ser NULL, si size es 0. La memoria apuntada por p se copia al área de memoria que contiene el mensaje y permanece en posesión del llamante. Por lo tanto, el llamante puede modificar libremente los datos después de esta llamada sin afectar al mensaje al que se añadió el array.

La función sd_bus_message_append_array_memfd() añade un array de un tipo trivial al mensaje m, de forma similar a sd_bus_message_append_array(). Los contenidos del descriptor de archivo de memoria memfd, comenzando en el desplazamiento especificado y con el tamaño especificado, se utilizan como los contenidos del array. El desplazamiento y el tamaño deben ser múltiplos del tamaño del tipo type. Sin embargo, como una excepción especial, si el desplazamiento se especifica como cero y el tamaño como UINT64_MAX, se utilizarán los contenidos completos del descriptor de archivo de memoria. El descriptor de archivo de memoria se sella con esta llamada si aún no se ha sellado, y no se puede modificar después de esta llamada. Consulte memfd_create(2) para obtener detalles sobre los descriptores de archivo de memoria. La adición de arrays con descriptores de archivo de memoria permite una transferencia de datos eficiente de cero copias, ya que el descriptor de archivo de memoria puede pasarse tal cual al destino, sin copiar la memoria contenida en él al proceso de destino. No todos los transportes de protocolo admiten el paso de descriptores de archivo de memoria entre participantes, en cuyo caso esta llamada recurrirá automáticamente a la copia. Además, dado que el paso de descriptores de archivo de memoria es ineficiente para pequeñas cantidades de datos, la copia puede seguir siendo forzada incluso donde se admite el paso de descriptores de archivo de memoria.

La función sd_bus_message_append_array_iovec() añade un array de un tipo trivial al mensaje m, de forma similar a sd_bus_message_append_array(). Los contenidos del array de vectores de E/S iov se utilizan como los contenidos del array. El tamaño total de la carga útil de iov (la suma de los campos iov_len) debe ser un múltiplo del tamaño del tipo type. El argumento iov debe apuntar a n estructuras de vector de E/S. Cada estructura puede tener el campo iov_base establecido, en cuyo caso la memoria apuntada se copiará en el mensaje, o no establecido (establecido en cero), en cuyo caso se insertará un bloque de ceros de longitud de bytes iov_len. La memoria apuntada por iov puede modificarse después de esta llamada.

La función sd_bus_message_append_array_space() reserva espacio para un array de un tipo trivial en el mensaje m. Se comporta de forma similar a sd_bus_message_append_array(), pero en lugar de copiar los elementos al mensaje, devuelve un puntero al área de destino al llamante en el puntero p. Posteriormente, el llamante debe escribir los contenidos del array en esta memoria. Las modificaciones en la memoria apuntada solo deben realizarse hasta que se invoque la siguiente operación en el mensaje del bus. Lo más importante es que la memoria ya no debe alterarse cuando se ha añadido otro campo al mensaje o cuando el mensaje se ha sellado.

VALOR DE RETORNO

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo de tipo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

El parámetro especificado no es válido.

-EPERM

El mensaje ha sido sellado.

-ESTALE

El mensaje está en estado inválido.

-ENXIO

El mensaje no se puede añadir.

-ENOMEM

Fallo en la asignación de memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos concurrentes. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar solo llamadas a setenv() desde una fase temprana del programa, cuando aún no se han iniciado otros hilos.

sd_bus_message_append_array_memfd(3)

sd_bus_message_append_array_memfd - Añade un array de tipo básico a un mensaje de bus

Resumen

#include <systemd/sd_bus.h>

int sd_bus_message_append_array_memfd(sd_bus_message *m, char type, const void *p, size_t size);

Descripción

sd_bus_message_append_array_memfd() añade un array de tipo básico al mensaje de bus m. El array se marcará como un manejador de archivo de memoria (memfd) y se enviará como un objeto de tipo 'h'.

type es el carácter que describe el tipo de elementos del array. Vea sd_bus_message_append_basic(3) para una lista de tipos válidos.

p es un puntero a los datos del array a añadir.

size es el tamaño del array en bytes.

Este tipo de dato memfd sólo se puede usar al enviar objetos de tipo 'h'. No se puede usar para enviar datos de tipo simple.

Este tipo de dato memfd no se puede usar para enviar datos de tipo simple. El manejador de archivo de memoria se transferirá al receptor.

Si el tipo type no es un tipo básico válido, la llamada fallará.

Valor de retorno

En caso de éxito, se devuelve 0 o un número positivo. En caso de fallo, se devuelve un número negativo.

Notas

Si m es NULL, la llamada fallará.

Este tipo de dato memfd sólo se puede usar al enviar objetos de tipo 'h'.

sd_bus_message_append_basic(3), sd_bus_message_append_array(3), sd_bus_message_append_memfd(3)

Notas

Este tipo de dato memfd sólo se puede usar al enviar objetos de tipo 'h'.
