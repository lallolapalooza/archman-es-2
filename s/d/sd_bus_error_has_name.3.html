DESCRIPCIÓN

La estructura sd_bus_error contiene información sobre una condición de error de D-Bus, o la ausencia de ella. Las funciones descritas a continuación pueden ser utilizadas para establecer y consultar campos en esta estructura.

•El campo name contiene un identificador corto de un error. Debe seguir las reglas para nombres de error descritas en la especificación de D-Bus, subsección Nombres D-Bus Válidos[1]. Un número de nombres de error comunes y estandarizados se describen en sd-bus-errors(3), pero las aplicaciones pueden definir errores adicionales específicos del dominio.
•El campo message usualmente contiene una cadena legible por humanos que describe los detalles, pero puede ser NULL.

Una estructura sd_bus_error no establecida debe tener ambos campos inicializados a NULL, y significa ausencia de error, es decir, éxito. Asigne SD_BUS_ERROR_NULL a la estructura para inicializar ambos campos a NULL. Cuando ya no sean necesarios, los recursos que posee la estructura sd_bus_error deben ser destruidos con sd_bus_error_free().

sd_bus_error_set() establece una estructura de error a los nombres y mensajes especificados. Las cadenas se copiarán a memoria interna recién asignada. Es esencial liberar el contenido de nuevo cuando ya no se necesiten (ver arriba). No utilice esta llamada en estructuras de error que ya hayan sido establecidas. Si tiene la intención de reutilizar una estructura de error, libere los datos antiguos almacenados en ella con sd_bus_error_free() primero.

sd_bus_error_set() devolverá un valor tipo errno (ver errno(3)) determinado a partir del nombre de error especificado name. Si name es NULL, se asume que no ocurrió ningún error, y se devuelve 0. Si name no es nulo, siempre se devuelve un valor negativo. Si e es NULL, no se inicializa ninguna estructura de error, pero name aún se convierte en un valor estilo errno.

Varios errores de D-Bus bien conocidos se convierten en sus contrapartes errno bien conocidas, y los demás a -EIO. Ver sd-bus-errors(3) para una lista de nombres de error bien conocidos. Se pueden definir mapeos de error adicionales con sd_bus_error_add_map(3).

sd_bus_error_set() está diseñado para ser utilizado convenientemente en una declaración return. Si message es NULL, no se establece ningún mensaje. Esta llamada puede fallar si no se puede asignar memoria para las cadenas de nombre y mensaje, en cuyo caso se establecerá un error SD_BUS_ERROR_NO_MEMORY en su lugar y se devolverá -ENOMEM.

sd_bus_error_setf() y sd_bus_error_setfv() son similares a sd_bus_error_set(), pero toman una cadena de formato printf(3) y argumentos correspondientes para generar el campo message. sd_bus_error_setf() usa argumentos variádicos, y sd_bus_error_setfv() acepta los argumentos como una lista de parámetros va_arg(3).

sd_bus_error_set_const() es similar a sd_bus_error_set(), pero los parámetros de cadena no se copian internamente, y por lo tanto deben permanecer constantes y válidos durante la vida útil de e. Use esta llamada para evitar asignaciones de memoria al establecer estructuras de error. Dado que esta llamada no asigna memoria, no fallará con una condición de falta de memoria como puede hacerlo sd_bus_error_set(), como se describe arriba. Alternativamente, la macro SD_BUS_ERROR_MAKE_CONST() puede usarse para generar una estructura de error literal y constante sobre la marcha.

sd_bus_error_set_errno() devolverá inmediatamente 0 si el parámetro de error especificado error es 0. De lo contrario, establecerá name a partir de un valor tipo errno que se convierte a un error de D-Bus. Se usará strerror_r(3) para establecer message. Se usarán nombres de error de D-Bus bien conocidos para name si es aplicable, de lo contrario se generará un nombre en el espacio de nombres "System.Error.". Se ignora el signo del número de error especificado y se usa implícitamente el valor absoluto. Si el error especificado error no es cero, la llamada siempre devuelve un valor negativo, para un uso conveniente en sentencias return. Esta llamada puede fallar debido a falta de memoria, en cuyo caso se establece un error SD_BUS_ERROR_NO_MEMORY en su lugar, y se devuelve -ENOMEM.

sd_bus_error_set_errnof() y sd_bus_error_set_errnof() son similares a sd_bus_error_set_errno(), pero además de error, toman una cadena de formato printf(3) y argumentos correspondientes. El campo message se generará a partir de format y los argumentos. sd_bus_error_set_errnof() usa argumentos variádicos, y sd_bus_error_set_errnofv() acepta los argumentos como una lista de parámetros va_arg(3).

sd_bus_error_get_errno() convierte el campo name de una estructura de error a un valor tipo errno (positivo) usando las mismas reglas que sd_bus_error_set(). Si e es NULL, se devolverá 0.

sd_bus_error_copy() inicializará dst usando los valores en e, si e se ha establecido previamente con un valor de error. De lo contrario, devolverá inmediatamente. Si las cadenas en e fueron establecidas usando sd_bus_error_set_const(), se compartirán. De lo contrario, se copiarán. Antes de esta llamada, dst debe no estar establecido, es decir, recién inicializado con NULL o reiniciado usando sd_bus_error_free().

sd_bus_error_copy() generalmente devuelve 0 o un valor tipo errno negativo basado en el parámetro de entrada e: 0 si no estaba establecido y un entero negativo si estaba establecido a algún error, de manera similar a sd_bus_error_set(). DESCRIPTION

Las estructuras `sd_bus_error` se utilizan para reportar errores de D-Bus. Tienen dos campos: `name` y `message`. El campo `name` es una cadena que identifica el tipo de error (por ejemplo, `org.freedesktop.DBus.Error.ResourceNotFound`), y `message` es una cadena que describe el error en lenguaje natural.

sd_bus_error_set() establece un nuevo error en la estructura `e`. Si `e` ya tenía un error establecido, será sobrescrito. Si `name` es `NULL`, el campo `name` de `e` se establecerá a `NULL`. Si `message` es `NULL`, el campo `message` de `e` se establecerá a `NULL`. Si se asigna nueva memoria para `name` o `message`, la llamada puede fallar devolviendo un valor negativo similar a `errno`, por ejemplo, -ENOMEM si la asignación de memoria falla.

sd_bus_error_setf() es similar a sd_bus_error_set(), pero utiliza una cadena de formato y argumentos variables para construir el mensaje de error, de forma similar a `printf(3)`. El argumento `name` no puede ser `NULL`.

sd_bus_error_set_const() es idéntica a sd_bus_error_set(), pero asume que `name` y `message` son cadenas literales constantes y no hace copias de ellas. Esto es útil si el llamador ya sabe que estas cadenas vivirán más que la estructura de error.

sd_bus_error_set_errno(), sd_bus_error_set_errnof() y sd_bus_error_set_errnofv() son similares a sd_bus_error_set(), sd_bus_error_setf() y sd_bus_error_setfv() respectivamente, pero también establecen el campo `error` de la estructura `e` con el valor proporcionado. Esto es útil para mapear errores de `errno` a errores de D-Bus.

sd_bus_error_setfv() es una variante de sd_bus_error_setf() que acepta una lista de argumentos variable `va_list` en lugar de argumentos variables directos.

sd_bus_error_get_errno() recupera el valor `errno` mapeado de la estructura de error `e`. Si `e` no está establecido o el nombre del error no se puede mapear a un valor `errno`, devuelve `false`.

sd_bus_error_copy() copia el contenido de la estructura de error `src` a `dst`. Si `dst` ya contenía un error, este será liberado. Si `src` no está establecido, `dst` se inicializará como no establecido. Esta función puede fallar si la asignación de memoria falla, devolviendo un valor similar a `errno`, por ejemplo, -ENOMEM si falla la asignación de memoria.

sd_bus_error_move() es similar a sd_bus_error_copy(), pero moverá cualquier información de error de `e` a `dst`, restableciendo el primero. Esta función no puede fallar, ya que no se asigna nueva memoria. Tenga en cuenta que si `e` no está establecido, `dst` se inicializa como SD_BUS_ERROR_NULL. Además, si `dst` es `NULL`, no se realiza ninguna operación sobre él y los recursos en poder de `e` se liberan y restablecen. Devuelve un valor de error convertido similar a `errno`, no positivo.

sd_bus_error_is_set() devolverá un valor distinto de cero si `e` no es `NULL` y se ha establecido un error, `false` en caso contrario.

sd_bus_error_has_name() devolverá un valor distinto de cero si `e` no es `NULL` y se ha establecido un error con el mismo `name`, `false` en caso contrario.

sd_bus_error_has_names_sentinel() es similar a sd_bus_error_has_name(), pero toma múltiples nombres para comparar. La lista debe terminar con `NULL`. sd_bus_error_has_names() es un macro envoltorio alrededor de sd_bus_error_has_names_sentinel() que añade el terminador `NULL` automáticamente.

sd_bus_error_free() destruirá los recursos en poder de `e`. El parámetro en sí no se desasignará y deberá ser liberado por el llamador usando free(3) si es necesario. La función también puede llamarse de forma segura en errores no establecidos (estructuras de error con ambos campos establecidos a `NULL`), en cuyo caso no realiza ninguna operación. Esta llamada restablecerá la estructura de error después de liberar los datos, de modo que todos los campos se establezcan a `NULL`. La estructura puede reutilizarse posteriormente.

REFERENCE OWNERSHIP

Las estructuras `sd_bus_error` no tienen conteo de referencias. Los usuarios deben destruir los recursos que contienen llamando a sd_bus_error_free(). Normalmente, las estructuras de error se asignan en la pila o se pasan como parámetros de función, pero también pueden asignarse dinámicamente, en cuyo caso es deber del llamador liberar la memoria que contiene la estructura después de liberar su contenido con sd_bus_error_free().

RETURN VALUE

Las funciones sd_bus_error_set(), sd_bus_error_setf() y sd_bus_error_set_const() siempre devuelven 0 cuando el valor del error especificado es `NULL`, y un valor negativo similar a `errno` correspondiente al parámetro `name` en caso contrario. Las funciones sd_bus_error_set_errno(), sd_bus_error_set_errnof() y sd_bus_error_set_errnofv() devuelven 0 cuando el valor del error especificado es 0, y un valor negativo similar a `errno` correspondiente al parámetro `error` en caso contrario. Si ocurre un error internamente, se devolverá uno de los valores de error negativos que se enumeran a continuación. Esto permite que estas funciones se utilicen convenientemente en una sentencia return, vea el ejemplo a continuación.

sd_bus_error_get_errno() devuelve false cuando `e` es `NULL`, y un valor `errno` positivo mapeado desde `e->name` en caso contrario.

sd_bus_error_copy() y sd_bus_error_move() devuelven un valor de error negativo convertido del error de origen, y cero si el error no ha sido establecido. Esto permite que estas funciones se utilicen convenientemente en una sentencia return, vea el ejemplo a continuación.

sd_bus_error_is_set() devuelve un valor distinto de cero cuando `e` y el campo `name` no son `NULL`, cero en caso contrario.

sd_bus_error_has_name(), sd_bus_error_has_names() y sd_bus_error_has_names_sentinel() devuelven un valor distinto de cero cuando `e` no es `NULL` y el campo `name` es igual a uno de los nombres dados, cero en caso contrario.

Errores

El valor de retorno puede indicar los siguientes problemas en la invocación de la propia función:

-EINVAL

El error ya estaba establecido en la estructura sd_bus_error cuando se llamó a una de las funciones de establecimiento de errores.

-ENOMEM

Fallo en la asignación de memoria.

En caso de éxito, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy() y sd_bus_error_move() devolverán un valor negativo convertido estilo errno, o 0 si el parámetro de error es `NULL` o no está establecido. Los errores de D-Bus se convierten al valor integral estilo errno, y el mecanismo de mapeo es extensible, vea la discusión anterior. Esto efectivamente significa que casi cualquier valor negativo estilo errno puede ser devuelto.

EXAMPLES

Ejemplo 1. Usando el valor de retorno negativo para propagar un error

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "Hello, World!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* En caso de éxito, devolver el número de bytes escritos, posiblemente 0. */
  /* En caso de error, inicializar la estructura de error, y también propagar el valor de errno
   * que write(2) estableció para nosotros. */
  return sd_bus_error_set_errnof(error, errno, "Failed to write to fd %i: %s", fd, strerror(errno));
}

NOTES

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
