SD_BUS_MESSAGE_GET_MONOTONIC_USEC(3) sd_bus_message_get_monotonic_usec SD_BUS_MESSAGE_GET_MONOTONIC_USEC(3)

NOMBRE

sd_bus_message_get_monotonic_usec, sd_bus_message_get_realtime_usec, sd_bus_message_get_seqnum - Recuperar las marcas de tiempo del remitente y el número de secuencia de un mensaje

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_get_monotonic_usec(sd_bus_message *message, uint64_t *usec);

int sd_bus_message_get_realtime_usec(sd_bus_message *message, uint64_t *usec);

int sd_bus_message_get_seqnum(sd_bus_message *message, uint64_t *seqnum);

DESCRIPCIÓN

sd_bus_message_get_monotonic_usec() devuelve la marca de tiempo monotónica del momento en que se envió el mensaje. Este valor está en microsegundos desde la época de CLOCK_MONOTONIC, consulte clock_gettime(2) para obtener más detalles.

De manera similar, sd_bus_message_get_realtime_usec() devuelve la marca de tiempo de tiempo real (reloj de pared) del momento en que se envió el mensaje. Este valor está en microsegundos desde el 1 de enero de 1970, es decir, en el reloj CLOCK_REALTIME.

sd_bus_message_get_seqnum() devuelve el número de secuencia asignado por el kernel del mensaje. El kernel asigna un número de secuencia global y monótonamente creciente a todos los mensajes transmitidos en el sistema local, en el momento en que se envió el mensaje. Este número de secuencia es útil para determinar el orden de envío de los mensajes, incluso entre diferentes buses del sistema local. El número de secuencia combinado con el ID de arranque del sistema (tal como lo devuelve sd_id128_get_boot(3)) es un identificador único global adecuado para mensajes de bus.

Tenga en cuenta que el orden de envío y el orden de recepción de los mensajes pueden diferir, en particular para los mensajes de difusión. Esto significa que el número de secuencia y las marcas de tiempo de los mensajes que lee un cliente no son necesariamente monótonamente crecientes.

Estas marcas de tiempo y el número de secuencia son adjuntados a cada mensaje por el kernel y no pueden ser manipulados por el remitente.

Tenga en cuenta que estas marcas de tiempo solo están disponibles en algunos transportes de bus, y solo después de que se haya negociado la compatibilidad con ellas mediante la llamada a sd_bus_negotiate_timestamp(3).

VALOR DE RETORNO

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, estas llamadas devuelven un código de error negativo al estilo errno.

En caso de éxito, la marca de tiempo o el número de secuencia se devuelven en la variable de entero sin signo de 64 bits especificada.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Un parámetro especificado es inválido.

-ENODATA

No hay información de marca de tiempo o número de secuencia adjunta al mensaje pasado. Este error se devuelve si el transporte subyacente no admite marcas de tiempo o asignación de números de secuencia, o si esta característica no se ha negociado con sd_bus_negotiate_timestamp(3).

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo pkg-config de libsystemd. Consulte pkg-config(1) para obtener más información.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer solo llamadas a setenv() desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIAL

sd_bus_message_get_monotonic_usec(), sd_bus_message_get_realtime_usec() y sd_bus_message_get_seqnum() se agregaron en la versión 209.
