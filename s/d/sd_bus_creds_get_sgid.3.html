DESCRIPCIÓN

Estas funciones devuelven información de credenciales de un objeto sd_bus_creds. Los objetos de credenciales pueden crearse con sd_bus_creds_new_from_pid(3), en cuyo caso describen las credenciales del proceso identificado por el PID especificado, con sd_bus_get_name_creds(3), en cuyo caso describen las credenciales de un par del bus identificado por el nombre del bus especificado, con sd_bus_get_owner_creds(3), en cuyo caso describen las credenciales del creador de un bus, o con sd_bus_message_get_creds(3), en cuyo caso describen las credenciales del remitente del mensaje.

No todos los campos de credenciales forman parte de cada objeto "sd_bus_creds". Utilice sd_bus_creds_get_mask(3) para determinar la máscara de campos disponibles.

sd_bus_creds_get_pid() recuperará el PID (identificador de proceso). De manera similar, sd_bus_creds_get_ppid() recuperará el PID del padre. Tenga en cuenta que el PID 1 no tiene proceso padre, en cuyo caso se devuelve -ENXIO.

sd_bus_creds_get_pidfd_dup() recuperará el descriptor de archivo PID (pidfd), consulte pidfd_open(2) para más detalles. El descriptor de archivo se duplica y, por lo tanto, debe ser cerrado por el llamador.

sd_bus_creds_get_tid() recuperará el TID (identificador de hilo).

sd_bus_creds_get_uid() recuperará el UID numérico (identificador de usuario). De manera similar, sd_bus_creds_get_euid() devuelve el UID efectivo, sd_bus_creds_get_suid() el UID guardado y sd_bus_creds_get_fsuid() el UID del sistema de archivos.

sd_bus_creds_get_gid() recuperará el GID numérico (identificador de grupo). De manera similar, sd_bus_creds_get_egid() devuelve el GID efectivo, sd_bus_creds_get_sgid() el GID guardado y sd_bus_creds_get_fsgid() el GID del sistema de archivos.

sd_bus_creds_get_supplementary_gids() recuperará la lista de GIDs suplementarios.

sd_bus_creds_get_comm() recuperará el campo comm (nombre truncado del ejecutable, tal como se almacena en /proc/pid/comm).

sd_bus_creds_get_tid_comm() recuperará el campo comm del hilo (tal como se almacena en /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() recuperará la ruta al ejecutable del programa (tal como se almacena en el enlace /proc/pid/exe, pero con el sufijo " (deleted)" eliminado). Tenga en cuenta que los hilos del kernel no tienen una ruta ejecutable, en cuyo caso se devuelve -ENXIO. Tenga en cuenta que esta propiedad no debe utilizarse para más que información explicativa, en particular no debe utilizarse para decisiones relevantes para la seguridad. Esto se debe a que el ejecutable podría haber sido reemplazado o eliminado en el momento en que se pueda procesar el valor. DESCRIPCIÓN

La estructura sd_bus_creds (ver sd_bus_creds(3)) representa las credenciales de un proceso o una conexión de bus D-Bus. Las funciones descritas en esta página son para obtener información específica de estas credenciales.

sd_bus_creds_get_pid(), sd_bus_creds_get_tid(), sd_bus_creds_get_ppid(), sd_bus_creds_get_uid(), sd_bus_creds_get_euid(), sd_bus_creds_get_suid(), sd_bus_creds_get_fsuid(), sd_bus_creds_get_gid(), sd_bus_creds_get_egid(), sd_bus_creds_get_sgid(), y sd_bus_creds_get_fsgid() recuperarán el ID del proceso, ID del hilo, ID del proceso padre, ID de usuario real, ID de usuario efectivo, ID de usuario guardado, ID de usuario del sistema de archivos, ID de grupo real, ID de grupo efectivo, ID de grupo guardado y ID de grupo del sistema de archivos, respectivamente. Para los procesos que se ejecutan como parte de un servicio systemd o una sesión de inicio de sesión, esta información podría estar incompleta o ser diferente de la del proceso inicial, si el servicio/sesión fue iniciado con systemd-run(1) y credenciales alteradas, o si el proceso se lanzó fuera de un hilo de ejecución de proceso (por ejemplo, un demonio que se bifurca).

sd_bus_creds_get_supplementary_gids() recuperará la lista de IDs de grupo suplementarios del proceso.

sd_bus_creds_get_comm() recuperará el nombre de la tarea del proceso (la cadena que aparece en la columna COMMAND del comando top). Este nombre suele estar truncado a 15 caracteres y puede modificarse con prctl(2) (PR_SET_NAME).

sd_bus_creds_get_tid_comm() recuperará el nombre de la tarea asociado con el hilo específico. Esto es similar a sd_bus_creds_get_comm(), pero puede devolver un nombre diferente si el hilo tiene su propio nombre de tarea.

sd_bus_creds_get_exe() recuperará la ruta al ejecutable del proceso (tal como se almacena en /proc/pid/exe). Tenga en cuenta que los hilos del kernel no tienen un ejecutable, en cuyo caso se devuelve -ENXIO.

sd_bus_creds_get_cmdline() recuperará una matriz de argumentos de línea de comandos (tal como se almacena en /proc/pid/cmdline). Tenga en cuenta que los hilos del kernel no tienen una línea de comandos, en cuyo caso se devuelve -ENXIO.

sd_bus_creds_get_cgroup() recuperará la ruta del grupo de control. Ver Control Groups v2[1].

sd_bus_creds_get_unit() recuperará el nombre de la unidad systemd (en la instancia del sistema de systemd) de la que forma parte el proceso. Ver systemd.unit(5). Para los procesos que no forman parte de una unidad, devuelve -ENXIO.

sd_bus_creds_get_user_unit() recuperará el nombre de la unidad systemd (en la instancia de usuario de systemd) de la que forma parte el proceso. Ver systemd.unit(5). Para los procesos que no forman parte de una unidad de usuario, devuelve -ENXIO.

sd_bus_creds_get_slice() recuperará el slice systemd (una unidad en la instancia del sistema de systemd) del que forma parte el proceso. Ver systemd.slice(5). De manera similar, sd_bus_creds_get_user_slice() recupera el slice systemd del proceso, en la instancia de usuario de systemd.

sd_bus_creds_get_session() recuperará el identificador de la sesión de inicio de sesión de la que forma parte el proceso. Tenga en cuenta que la sesión de inicio de sesión puede limitarse a uno o dos procesos "stub". Los procesos de usuario pueden iniciarse en su lugar desde su gestor de usuario de systemd, por ejemplo, aplicaciones gráficas iniciadas utilizando la activación de DBus, así como procesos de servicio que se comparten entre varios inicios de sesión del mismo usuario. Para los procesos que no forman parte de una sesión, devuelve -ENXIO.

sd_bus_creds_get_owner_uid() recuperará el UID numérico (identificador de usuario) del usuario que es propietario de la unidad de usuario o sesión de inicio de sesión de la que forma parte el proceso. Ver systemd-logind.service(8). Para los procesos que no forman parte de una unidad de usuario o sesión, devuelve -ENXIO.

sd_bus_creds_has_effective_cap() comprobará si la capacidad especificada por capability estaba establecida en la máscara de capacidades efectivas. Un valor de retorno positivo significa que estaba establecida, cero significa que no estaba establecida, y un valor de retorno negativo indica un error. Ver capabilities(7) y la configuración AmbientCapabilities= y CapabilityBoundingSet= en systemd.exec(5).

sd_bus_creds_has_permitted_cap() es similar a sd_bus_creds_has_effective_cap(), pero comprobará la máscara de capacidades permitidas.

sd_bus_creds_has_inheritable_cap() es similar a sd_bus_creds_has_effective_cap(), pero comprobará la máscara de capacidades heredables.

sd_bus_creds_has_bounding_cap() es similar a sd_bus_creds_has_effective_cap(), pero comprobará la máscara de capacidades delimitadoras.

sd_bus_creds_get_selinux_context() recuperará el contexto de seguridad SELinux (etiqueta) del proceso.

sd_bus_creds_get_audit_session_id() recuperará el identificador de sesión de auditoría del proceso. Devuelve -ENXIO para procesos que no forman parte de una sesión de auditoría.

sd_bus_creds_get_audit_login_uid() recuperará el identificador de inicio de sesión de usuario de auditoría (el identificador del usuario que es "responsable" de la sesión). Devuelve -ENXIO para procesos que no forman parte de una sesión de auditoría.

sd_bus_creds_get_tty() recuperará el TTY de control, sin el prefijo "/dev/". Devuelve -ENXIO para procesos que no tienen un TTY de control.

sd_bus_creds_get_unique_name() recuperará el nombre único de D-Bus. Ver La especificación de D-Bus[2].

sd_bus_creds_get_well_known_names() recuperará el conjunto de nombres conocidos de D-Bus. Ver La especificación de D-Bus[2].

sd_bus_creds_get_description() recuperará un nombre descriptivo de la conexión de bus del par. Este nombre es útil para distinguir múltiples conexiones de bus del mismo par, y puede ser alterado por el par con la llamada sd_bus_set_description(3).

Todas las funciones que toman un parámetro const char** almacenarán la respuesta allí como una dirección de una cadena terminada en NUL. Será válida mientras c siga siendo válida, y no debe ser liberada ni modificada por el llamante.

Todas las funciones que toman un parámetro char*** almacenarán la respuesta allí como una dirección de una matriz de cadenas. Cada cadena individual está terminada en NUL, y la matriz está terminada en NULL en su conjunto. Será válida mientras c siga siendo válida, y no debe ser liberada ni modificada por el llamante.

VALOR DE RETORNO

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, estas llamadas devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENODATA

El campo dado no está disponible en el objeto de credenciales c.

-ENXIO

El campo dado no está especificado para el proceso o par descrito. Esto será devuelto por sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice() y sd_bus_creds_get_session() si el proceso no forma parte de una unidad del sistema systemd, una unidad de usuario de systemd, un slice de systemd o una sesión de logind. Será devuelto por sd_bus_creds_get_owner_uid() si el proceso no forma parte de una unidad de usuario de systemd o una sesión de logind. También será devuelto por sd_bus_creds_get_exe() y sd_bus_creds_get_cmdline() para hilos del kernel (ya que estos no se inician desde un ejecutable binario, ni tienen una línea de comandos), y por sd_bus_creds_get_audit_session_id() y sd_bus_creds_get_audit_login_uid() cuando el proceso no forma parte de una sesión de auditoría, y sd_bus_creds_get_tty() si el proceso no tiene un TTY de control.

-EINVAL

El parámetro de puntero especificado es NULL.

-ENOMEM

Fallo en la asignación de memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
