NOMBRE

sd_id128_get_machine, sd_id128_get_app_specific, sd_id128_get_machine_app_specific, sd_id128_get_boot, sd_id128_get_boot_app_specific, sd_id128_get_invocation - Recuperar IDs de 128 bits

SINOPSIS

#include <systemd/sd-id128.h>

int sd_id128_get_machine(sd_id128_t *ret);

int sd_id128_get_app_specific(sd_id128_t base, sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_machine_app_specific(sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_boot(sd_id128_t *ret);

int sd_id128_get_boot_app_specific(sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_invocation(sd_id128_t *ret);

int sd_id128_get_invocation_app_specific(sd_id128_t app_id, sd_id128_t *ret);

DESCRIPCIÓN

sd_id128_get_machine() devuelve el ID de máquina del host en ejecución. Lee y analiza el archivo machine-id(5). Esta función almacena en caché el ID de máquina internamente para que recuperarlo sea una operación rápida. Este ID puede usarse dondequiera que se necesite un identificador único para el sistema local. Sin embargo, se recomienda usar este ID tal cual solo en entornos confiables. En entornos no confiables, se recomienda derivar un ID específico de la aplicación a partir de este ID de máquina, de forma irreversible (criptográficamente segura). Para facilitar esto, se proporciona sd_id128_get_machine_app_specific(), ver más abajo.

sd_id128_get_app_specific() devuelve un ID de máquina que es una combinación de los parámetros base y app_id. Internamente, esta función calcula HMAC-SHA256 del parámetro app_id usando el parámetro base como clave, y trunca este resultado para que quepa en sd_id128_t y lo convierte en un UUID válido de Variante 1 Versión 4, de acuerdo con **RFC 4122**[1]. Ninguno de los dos parámetros de entrada puede ser calculado a partir del parámetro de salida ret.

sd_id128_get_machine_app_specific() es similar a sd_id128_get_machine(), pero recupera un ID de máquina que es específico para la aplicación identificada por el ID de aplicación indicado. Se recomienda usar esta función en lugar de sd_id128_get_machine() al pasar un ID a entornos no confiables, para asegurarse de que el ID de máquina original no pueda determinarse externamente. De esta manera, el ID utilizado por la aplicación permanece estable en una determinada máquina, pero no puede correlacionarse fácilmente con los IDs utilizados en otras aplicaciones en la misma máquina. El ID específico de la aplicación debe generarse a través de una herramienta como systemd-id128 new y puede compilarse en la aplicación. Esta función devolverá el mismo ID específico de la aplicación para cada combinación de ID de máquina e ID de aplicación. Internamente, esta función llama a sd_id128_get_app_specific() con el resultado de sd_id128_get_machine() y el parámetro app_id.

sd_id128_get_boot() devuelve el ID de arranque del kernel en ejecución. Lee y analiza el archivo /proc/sys/kernel/random/boot_id expuesto por el kernel. Se genera aleatoriamente al principio del arranque y es único para cada instancia del kernel en ejecución. Consulte random(4) para más información. Esta función también almacena en caché internamente el ID devuelto para que esta llamada sea una operación rápida. Se recomienda usar este ID tal cual solo en entornos confiables. En entornos no confiables, se recomienda derivar un ID específico de la aplicación usando sd_id128_get_boot_app_specific(), ver más abajo.

sd_id128_get_boot_app_specific() es análogo a sd_id128_get_machine_app_specific(), pero devuelve un ID que cambia entre reinicios. Algunas máquinas pueden usarse durante mucho tiempo sin reiniciar, por lo tanto, el ID de arranque puede permanecer constante durante mucho tiempo y tiene propiedades similares al ID de máquina durante ese tiempo.

sd_id128_get_invocation() devuelve el ID de invocación del servicio actualmente ejecutado. En su implementación actual, intenta leer y analizar lo siguiente:

•La variable de entorno $INVOCATION_ID que el gestor de servicios establece al activar un servicio.
•Una entrada en la keyring del kernel que el gestor de servicios del sistema establece al activar un servicio.

Consulte systemd.exec(5) para obtener más detalles. El ID se almacena en caché internamente. En el futuro, se puede agregar un mecanismo diferente para determinar el ID de invocación.

sd_id128_get_invocation_app_specific() deriva un ID específico de la aplicación del ID de invocación.

Tenga en cuenta que sd_id128_get_machine_app_specific(), sd_id128_get_boot(), sd_id128_get_boot_app_specific(), sd_id128_get_invocation() y sd_id128_get_invocation_app_specific siempre devuelven IDs compatibles con UUID Variante 1 Versión 4. sd_id128_get_machine() también devolverá un ID compatible con UUID Variante 1 Versión 4 en instalaciones nuevas, pero puede que no en las antiguas. Es posible convertir el ID de máquina de forma no reversible en uno compatible con UUID Variante 1 Versión 4. Para obtener más información, consulte machine-id(5). Por lo tanto, se garantiza que estas funciones nunca devolverán el ID que consiste en todos los bits cero o todos los bits uno (**SD_ID128_NULL**, **SD_ID128_ALLF**) — con la posible excepción de sd_id128_get_machine(), como se mencionó.

Para obtener más información sobre el tipo "sd_id128_t", consulte sd-id128(3).

VALOR DE RETORNO

Estas llamadas devuelven 0 en caso de éxito (en cuyo caso ret se rellena), o un código de error negativo de estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOENT

Devuelto por sd_id128_get_machine() y sd_id128_get_machine_app_specific() cuando falta /etc/machine-id.

Añadido en la versión 242.

-ENOMEDIUM

Devuelto por sd_id128_get_machine() y sd_id128_get_machine_app_specific() cuando /etc/machine-id está vacío o es todo ceros. También devuelto por sd_id128_get_invocation() cuando el ID de invocación es todo ceros.

Añadido en la versión 242.

-ENOPKG

Devuelto por sd_id128_get_machine() y sd_id128_get_machine_app_specific() cuando el contenido de /etc/machine-id es "sin inicializar".

Añadido en la versión 253.

-ENOSYS

Devuelto por sd_id128_get_boot() y sd_id128_get_boot_app_specific() cuando /proc/ no está montado.

Añadido en la versión 253.

-ENXIO

Devuelto por sd_id128_get_invocation() si no hay un ID de invocación establecido. También devuelto por sd_id128_get_app_specific(), sd_id128_get_machine_app_specific(), y sd_id128_get_boot_app_specific() cuando el parámetro app_id es todo ceros.

Añadido en la versión 242.

-EUCLEAN

Devuelto por cualquiera de las funciones descritas aquí cuando el valor configurado tiene un formato inválido.

Añadido en la versión 253.

-EPERM

La información solicitada no se pudo recuperar debido a permisos insuficientes.

Añadido en la versión 242.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para multihilo. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

sd_id128_get_machine_app_specific(3) — systemd libs documentation

NAME

sd_id128_get_machine_app_specific, sd_id128_get_boot_app_specific, sd_id128_get_invocation_app_specific, sd_id128_get_app_specific — Get application-specific ID128 identifiers

SYNOPSIS

#include <systemd/sd-id128.h>

sd_id128_t sd_id128_get_machine_app_specific(sd_id128_t app_specific_id);
sd_id128_t sd_id128_get_boot_app_specific(sd_id128_t app_specific_id);
sd_id128_t sd_id128_get_invocation_app_specific(sd_id128_t app_specific_id);
sd_id128_t sd_id128_get_app_specific(sd_id128_t app_specific_id);

DESCRIPTION

These functions retrieve a 128-bit identifier (UUID) that is derived from an application-specific identifier and a hardware or boot-related identifier.

Specifically:

  • sd_id128_get_machine_app_specific() derives an identifier from the machine identifier (see machine-id(5)) and the provided app_specific_id. The machine identifier is a persistent identifier for the host.
  • sd_id128_get_boot_app_specific() derives an identifier from the boot identifier and the provided app_specific_id. The boot identifier is a persistent identifier for the current boot.
  • sd_id128_get_invocation_app_specific() derives an identifier from the invocation identifier and the provided app_specific_id. The invocation identifier is a unique identifier for the current systemd manager process invocation.
  • sd_id128_get_app_specific() is a convenience function that combines the machine identifier, boot identifier, and invocation identifier with the provided app_specific_id to create a unique identifier for a specific application instance.

The app_specific_id should be a 128-bit value representing the application's unique ID. This can be generated using systemd-id128(1) or any other UUID generation mechanism.

These functions are useful for creating unique, reproducible IDs for application-specific events or states that should be tied to the host, the current boot, or a specific process invocation.

The returned ID is a 128-bit value of type sd_id128_t. This type can be printed using the SD_ID128_FORMAT_STR macro and passed to SD_ID128_FORMAT_VAL.

RETURN VALUE

All these functions return the generated 128-bit identifier on success. If any of the underlying identifiers cannot be determined (which is unlikely in a running systemd environment), a zeroed sd_id128_t value is returned.

NOTES

The generated identifiers are based on RFC 4122, section 4.1.3 "Name Based Identifiers". The specific algorithm used is a combination of hashing the provided application ID and XORing it with the relevant system identifier (machine, boot, or invocation).

For sd_id128_get_app_specific(), the order of combination is machine ID, boot ID, invocation ID, and then the application ID. This ensures a high degree of uniqueness.

EXAMPLES

To generate and use an application-specific identifier tied to the machine ID:

#include <stdio.h>
#include <systemd/sd-id128.h>

First, generate a unique ID for your application using systemd-id128(1):

$ systemd-id128 -p new
As string:
c273277323db454ea63bb96e79b53e97
As UUID:
c2732773-23db-454e-a63b-b96e79b53e97
As man:sd-id128(3) macro:
#define MESSAGE_XYZ SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
...

Then use the new identifier in an example application:

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <systemd/sd-id128.h>
#define OUR_APPLICATION_ID SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
int main(int argc, char *argv[]) {
  sd_id128_t id;
  sd_id128_get_machine_app_specific(OUR_APPLICATION_ID, &id);
  printf("Our application ID: " SD_ID128_FORMAT_STR "\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}
