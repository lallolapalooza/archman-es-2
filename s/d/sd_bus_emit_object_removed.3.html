SD_BUS_EMIT_SIGNAL(3) sd_bus_emit_signal SD_BUS_EMIT_SIGNAL(3)

NOMBRE

sd_bus_emit_signal, sd_bus_emit_signalv, sd_bus_emit_signal_to, sd_bus_emit_signal_tov, sd_bus_emit_interfaces_added, sd_bus_emit_interfaces_added_strv, sd_bus_emit_interfaces_removed, sd_bus_emit_interfaces_removed_strv, sd_bus_emit_properties_changed, sd_bus_emit_properties_changed_strv, sd_bus_emit_object_added, sd_bus_emit_object_removed - Funciones de conveniencia para emitir señales D-Bus (estándar)

SINOPSIS

#include <systemd/sd-bus-vtable.h>

int sd_bus_emit_signal(sd_bus *bus, const char *path, const char *interface, const char *member, const char *types, ...);

int sd_bus_emit_signalv(sd_bus *bus, const char *path, const char *interface, const char *member, const char *types, va_list ap);

int sd_bus_emit_signal_to(sd_bus *bus, const char *destination, const char *path, const char *interface, const char *member, const char *types, ...);

int sd_bus_emit_signal_tov(sd_bus *bus, const char *destination, const char *path, const char *interface, const char *member, const char *types, va_list ap);

int sd_bus_emit_interfaces_added(sd_bus *bus, const char *path, const char *interface, ...);

int sd_bus_emit_interfaces_added_strv(sd_bus *bus, const char *path, char **interfaces);

int sd_bus_emit_interfaces_removed(sd_bus *bus, const char *path, const char *interface, ...);

int sd_bus_emit_interfaces_removed_strv(sd_bus *bus, const char *path, char **interfaces);

int sd_bus_emit_properties_changed(sd_bus *bus, const char *path, const char *interface, const char *name, ...);

int sd_bus_emit_properties_changed_strv(sd_bus *bus, const char *path, const char *interface, char **names);

int sd_bus_emit_object_added(sd_bus *bus, const char *path);

int sd_bus_emit_object_removed(sd_bus *bus, const char *path);

DESCRIPCIÓN

sd_bus_emit_signal() es una función de conveniencia para inicializar un objeto de mensaje de bus y emitir la señal D-Bus correspondiente. Combina las funciones sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) en una única llamada a función. sd_bus_emit_signalv() es equivalente a sd_bus_message_append(), excepto que se llama con una "va_list" en lugar de un número variable de argumentos.

sd_bus_emit_signal_to() y sd_bus_emit_signal_tov() son idénticas a sd_bus_emit_signal() y sd_bus_emit_signalv(), excepto que pueden emitir la señal a un único destino. Proporcione destination como NULL para emitir la señal en difusión.

sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() se utilizan para implementar las señales InterfacesAdded y InterfacesRemoved de la interfaz org.freedesktop.DBus.ObjectManager. Toman una ruta cuyo interfaz ha sido modificado como argumento y una lista variable de interfaces que han sido añadidas o eliminadas, respectivamente. El último argumento pasado a sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() debe ser NULL. Esto permite que ambas funciones determinen de forma segura el número de argumentos de interfaz pasados. sd_bus_emit_interfaces_added_strv() y sd_bus_emit_interfaces_removed_strv() son idénticas a sus respectivas contrapartes, pero ambas toman la lista de interfaces como un único argumento en lugar de un número variable de argumentos.

sd_bus_emit_properties_changed() se utiliza para implementar la señal PropertiesChanged de la interfaz org.freedesktop.DBus.Properties. Toma una ruta de objeto, un interfaz y una lista variable de nombres de propiedades como argumentos. El último argumento pasado a sd_bus_emit_properties_changed() debe ser NULL. Esto permite determinar de forma segura el número de nombres de propiedad pasados. sd_bus_emit_properties_changed_strv() es idéntica a sd_bus_emit_properties_changed() pero toma la lista de nombres de propiedad como un único argumento en lugar de un número variable de argumentos.

sd_bus_emit_object_added() y sd_bus_emit_object_removed() son funciones de conveniencia para emitir las señales InterfacesAdded o InterfacesRemoved para todas las interfaces registradas en una ruta de objeto específica, respectivamente. Esto incluye cualquier vtable de fallback padre si no son anuladas por una vtable hija más aplicable. También incluye todas las interfaces D-Bus estándar implementadas por el propio sd-bus en cualquier objeto registrado.

Tenga en cuenta que sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() y sd_bus_emit_object_removed() requieren que se haya registrado un gestor de objetos en la ruta de objeto dada o en una de sus rutas de objeto padre usando sd_bus_add_object_manager(3).

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un entero no negativo. En caso de fallo, devuelven un código de error negativo de estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Uno de los parámetros requeridos es NULL o inválido. Se pasó una interfaz D-Bus reservada como parámetro interface.

-ENOPKG

El bus no se puede resolver.

-ECHILD

El bus se creó en un proceso, biblioteca o instancia de módulo diferente.

-ENOMEM

Fallo en la asignación de memoria.

-ESRCH

Se llamó a sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() o sd_bus_emit_object_removed() en un objeto sin un gestor de objetos registrado en su propia ruta de objeto o en una de sus rutas de objeto padre.

Consulte las páginas del manual de sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) para ver más errores posibles.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

sd_bus_emit_object_removed(3) — systemd libs

NAME

sd_bus_emit_object_added, sd_bus_emit_object_removed, sd_bus_emit_interfaces_removed_strv, sd_bus_emit_properties_changed, sd_bus_emit_properties_changed_strv, sd_bus_emit_signalv, sd_bus_emit_signal_to, sd_bus_emit_signal_tov — emit bus signals

SYNOPSIS

#include <systemd/sd-bus.h>

int sd_bus_emit_object_added(sd_bus *bus, const char *path, const char *interface);
int sd_bus_emit_object_removed(sd_bus *bus, const char *path, const char *interface);
int sd_bus_emit_interfaces_removed_strv(sd_bus *bus, const char *path, const char *const *interfaces);
int sd_bus_emit_properties_changed(sd_bus *bus, const char *path, const char *interface, sd_bus_error *error, const char *first_property, ...);
int sd_bus_emit_properties_changed_strv(sd_bus *bus, const char *path, const char *interface, sd_bus_error *error, const char *const *properties);
int sd_bus_emit_signalv(sd_bus *bus, const char *path, const char *interface, const char *member, sd_bus_error *error, va_list ap);
int sd_bus_emit_signal_to(sd_bus *bus, const char *path, const char *interface, const char *member, sd_bus_error *error, const char *sender, ...);
int sd_bus_emit_signal_tov(sd_bus *bus, const char *path, const char *interface, const char *member, sd_bus_error *error, const char *sender, va_list ap);

DESCRIPTION

These functions may be used to emit D-Bus signals from an object.

Emitting a signal involves constructing a message object, filling it with the signal's arguments, and sending it over the bus.

sd_bus_emit_object_added may be used to emit the org.freedesktop.DBus.ObjectManager.InterfacesAdded signal. It is emitted when a new object appears on the bus, or when an existing object gains new interfaces.

sd_bus_emit_object_removed may be used to emit the org.freedesktop.DBus.ObjectManager.InterfacesRemoved signal. It is emitted when an object is removed from the bus, or when an existing object loses some of its interfaces.

sd_bus_emit_properties_changed and sd_bus_emit_properties_changed_strv may be used to emit the org.freedesktop.DBus.Properties.PropertiesChanged signal. This signal is emitted when one or more properties of an object change their value.

sd_bus_emit_properties_changed_strv takes an array of strings for the properties, and is intended for cases where the list of properties is known at compile time.

sd_bus_emit_signalv, sd_bus_emit_signal_to, and sd_bus_emit_signal_tov may be used to emit arbitrary signals.

All these functions construct the appropriate message internally, and then call sd_bus_send(3) to send it.

The sd_bus_emit_signal_to and sd_bus_emit_signal_tov variants allow specifying a particular sender service to send the signal to.

RETURN VALUE

On success, these functions return a non-negative integer. On failure, they return a negative error number.

NOTES

These functions are simplified wrappers around the more general bus message construction and sending functions. For more complex signal emission, consider using sd_bus_message_new_signal(3) directly.

The sd_bus_emit_properties_changed and sd_bus_emit_signal_to variants use the ellipsis (`...`) notation, and expect the arguments to be passed in the same way as for printf(3). See sd_bus_message_append(3) for the supported types.

The sd_bus_emit_signalv, sd_bus_emit_signal_tov variants accept a va_list argument for the signal arguments. This is useful when implementing functions that wrap signal emission.

HISTORY

sd_bus_emit_interfaces_removed_strv(), sd_bus_emit_properties_changed(), sd_bus_emit_properties_changed_strv(), were added in version 221.

sd_bus_emit_object_added(), and sd_bus_emit_object_removed() were added in version 222.

sd_bus_emit_signalv() was added in version 246.

sd_bus_emit_signal_to() and sd_bus_emit_signal_tov() were added in version 253.
