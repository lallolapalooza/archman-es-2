DESCRIPCIÓN

La estructura sd_bus_error contiene información sobre una condición de error de D-Bus, o la ausencia de ella. Las funciones descritas a continuación pueden ser utilizadas para establecer y consultar campos en esta estructura.

•El campo nombre contiene un identificador corto de un error. Debe seguir las reglas para nombres de error descritas en la especificación D-Bus, subsección Nombres Válidos de D-Bus[1]. Un número de nombres de error comunes y estandarizados se describe en sd-bus-errors(3), pero las aplicaciones pueden definir errores adicionales específicos del dominio.
•El campo mensaje generalmente contiene una cadena legible por humanos que describe los detalles, pero puede ser NULL.

Una estructura sd_bus_error no establecida debe tener ambos campos inicializados a NULL, y significa la ausencia de un error, es decir, éxito. Asigne SD_BUS_ERROR_NULL a la estructura para inicializar ambos campos a NULL. Cuando ya no sean necesarios, los recursos que mantiene la estructura sd_bus_error deben ser liberados con sd_bus_error_free().

sd_bus_error_set() establece una estructura de error a los nombres y mensajes especificados. Las cadenas se copiarán en memoria interna recién asignada. Es esencial liberar el contenido de nuevo cuando ya no se requiera (ver arriba). No use esta llamada en estructuras de error que ya hayan sido establecidas. Si tiene la intención de reutilizar una estructura de error, primero libere los datos antiguos almacenados en ella con sd_bus_error_free().

sd_bus_error_set() devolverá un valor similar a errno (ver errno(3)) determinado a partir del nombre de error especificado nombre. Si nombre es NULL, se asume que no ocurrió ningún error y se devuelve 0. Si nombre no es nulo, siempre se devolverá un valor negativo. Si e es NULL, no se inicializa ninguna estructura de error, pero nombre todavía se convierte en un valor tipo errno.

Varios errores bien conocidos de D-Bus se convierten en sus contrapartes errno bien conocidas, y los demás a -EIO. Ver sd-bus-errors(3) para una lista de nombres de error bien conocidos. Se pueden definir mapeos de errores adicionales con sd_bus_error_add_map(3).

sd_bus_error_set() está diseñado para ser usado convenientemente en una sentencia return. Si mensaje es NULL, no se establece ningún mensaje. Esta llamada puede fallar si no se puede asignar memoria para las cadenas de nombre y mensaje, en cuyo caso se establecerá un error SD_BUS_ERROR_NO_MEMORY y se devolverá -ENOMEM.

sd_bus_error_setf() y sd_bus_error_setfv() son similares a sd_bus_error_set(), pero toman una cadena de formato printf(3) y argumentos correspondientes para generar el campo mensaje. sd_bus_error_setf() utiliza argumentos variádicos, y sd_bus_error_setfv() acepta los argumentos como una lista de parámetros va_arg(3).

sd_bus_error_set_const() es similar a sd_bus_error_set(), pero los parámetros de cadena no se copian internamente y, por lo tanto, deben permanecer constantes y válidos durante la vida útil de e. Use esta llamada para evitar asignaciones de memoria al establecer estructuras de error. Dado que esta llamada no asigna memoria, no fallará con una condición de falta de memoria como puede hacerlo sd_bus_error_set(), como se describe anteriormente. Alternativamente, la macro SD_BUS_ERROR_MAKE_CONST() puede ser utilizada para generar una estructura de error literal y constante sobre la marcha.

sd_bus_error_set_errno() devolverá inmediatamente 0 si el parámetro de error especificado error es 0. De lo contrario, establecerá nombre a partir de un valor similar a errno que se convierte a un error de D-Bus. Se utilizará strerror_r(3) para establecer mensaje. Se utilizarán nombres de error bien conocidos de D-Bus para nombre si es aplicable, de lo contrario se generará un nombre en el espacio de nombres "System.Error.". Se ignora el signo del número de error especificado y se utiliza implícitamente su valor absoluto. Si el error especificado error no es cero, la llamada siempre devuelve un valor negativo, para un uso conveniente en sentencias return. Esta llamada puede fallar debido a falta de memoria, en cuyo caso se establecerá un error SD_BUS_ERROR_NO_MEMORY y se devolverá -ENOMEM.

sd_bus_error_set_errnof() y sd_bus_error_set_errnofv() son similares a sd_bus_error_set_errno(), pero además de error, toman una cadena de formato printf(3) y argumentos correspondientes. El campo mensaje se generará a partir de formato y los argumentos. sd_bus_error_set_errnof() utiliza argumentos variádicos, y sd_bus_error_set_errnofv() acepta los argumentos como una lista de parámetros va_arg(3).

sd_bus_error_get_errno() convierte el campo nombre de una estructura de error a un valor (positivo) similar a errno utilizando las mismas reglas que sd_bus_error_set(). Si e es NULL, se devolverá 0.

sd_bus_error_copy() inicializará dst utilizando los valores de e, si e ha sido establecido previamente con un valor de error. De lo contrario, devolverá inmediatamente. Si las cadenas en e fueron establecidas usando sd_bus_error_set_const(), serán compartidas. De lo contrario, serán copiadas. Antes de esta llamada, dst debe estar sin establecer, es decir, recién inicializado con NULL o reiniciado usando sd_bus_error_free().

sd_bus_error_copy() generalmente devuelve 0 o un valor negativo similar a errno basado en el parámetro de entrada e: 0 si no estaba establecido y un entero negativo si estaba establecido a algún error, similar a sd_bus_error_set(). Sin embargo, también puede devolver un error generado internamente

, por ejemplo -ENOMEM si falla una asignación de memoria.

sd_bus_error_move() es similar a sd_bus_error_copy(), pero moverá cualquier información de error de e a dst, reiniciando la primera. Esta función no puede fallar, ya que no se asigna memoria nueva. Tenga en cuenta que si e no está establecido, dst se inicializa a SD_BUS_ERROR_NULL. Además, si dst es NULL, no se ejecuta ninguna operación sobre él y los recursos mantenidos por e se liberan y reinician. Devuelve un valor de error no positivo similar a errno convertido.

sd_bus_error_is_set() devolverá un valor distinto de cero si e no es NULL y se ha establecido un error, false en caso contrario.

sd_bus_error_has_name() devolverá un valor distinto de cero si e no es NULL y se ha establecido un error con el mismo name, false en caso contrario.

sd_bus_error_has_names_sentinel() es similar a sd_bus_error_has_name(), pero toma varios nombres para comprobar. La lista debe terminar con NULL. sd_bus_error_has_names() es un envoltorio macro para sd_bus_error_has_names_sentinel() que añade el terminador NULL automáticamente.

sd_bus_error_free() destruirá los recursos mantenidos por e. El parámetro en sí no se liberará y deberá ser liberado por el llamante si es necesario, usando free(3). La función también se puede llamar de forma segura en errores no establecidos (estructuras de error con ambos campos establecidos a NULL), en cuyo caso no realiza ninguna operación. Esta llamada reiniciará la estructura de error después de liberar los datos, de modo que todos los campos se establezcan a NULL. La estructura puede ser reutilizada posteriormente.

PROPIEDAD DE REFERENCIA

sd_bus_error no tiene contador de referencias. Los usuarios deben destruir los recursos que mantiene llamando a sd_bus_error_free(). Normalmente, las estructuras de error se asignan en la pila o se pasan como parámetros de función, pero también pueden asignarse dinámicamente, en cuyo caso es deber del llamante liberar la memoria mantenida por la propia estructura usando free(3) después de liberar su contenido con sd_bus_error_free().

VALOR DE RETORNO

Las funciones sd_bus_error_set(), sd_bus_error_setf() y sd_bus_error_set_const() siempre devuelven 0 cuando el valor de error especificado es NULL, y un valor negativo similar a errno correspondiente al parámetro name en caso contrario. Las funciones sd_bus_error_set_errno(), sd_bus_error_set_errnof() y sd_bus_error_set_errnofv(), devuelven 0 cuando el valor de error especificado es 0, y un valor negativo similar a errno correspondiente al parámetro error en caso contrario. Si ocurre un error interno, se devolverá uno de los valores de error negativos listados a continuación. Esto permite que esas funciones se utilicen convenientemente en una instrucción return, vea el ejemplo a continuación.

sd_bus_error_get_errno() devuelve false cuando e es NULL, y un valor positivo de errno mapeado desde e->name en caso contrario.

sd_bus_error_copy() y sd_bus_error_move() devuelven un valor de error negativo convertido del error de origen, y cero si el error no se ha establecido. Esto permite que esas funciones se utilicen convenientemente en una instrucción return, vea el ejemplo a continuación.

sd_bus_error_is_set() devuelve un valor distinto de cero cuando e y el campo name no son NULL, cero en caso contrario.

sd_bus_error_has_name(), sd_bus_error_has_names() y sd_bus_error_has_names_sentinel() devuelven un valor distinto de cero cuando e no es NULL y el campo name es igual a uno de los nombres dados, cero en caso contrario.

Errores

El valor de retorno puede indicar los siguientes problemas en la invocación de la propia función:

-EINVAL

El error ya estaba establecido en la estructura sd_bus_error cuando se llamó a una de las funciones de establecimiento de errores.

-ENOMEM

Fallo en la asignación de memoria.

En caso de éxito, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy() y sd_bus_error_move() devolverán un valor estilo errno negativo convertido, o 0 si el parámetro de error es NULL o no está establecido. Los errores de D-Bus se convierten al valor integral estilo errno, y el mecanismo de mapeo es extensible, vea la discusión anterior. Esto significa efectivamente que casi cualquier valor negativo estilo errno puede ser devuelto.

EJEMPLOS

Ejemplo 1. Uso del valor de retorno negativo para propagar un error

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "¡Hola, Mundo!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* En caso de éxito, devolver el número de bytes escritos, posiblemente 0. */
  /* En caso de error, inicializar la estructura de error y también propagar
   * el valor errno que write(2) estableció para nosotros. */
  return sd_bus_error_set_errnof(error, errno, "Error al escribir en fd %i: %s", fd, strerror(errno));
}

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando aún no se han iniciado otros hilos.
