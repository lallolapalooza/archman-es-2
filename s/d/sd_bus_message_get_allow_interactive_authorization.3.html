sd_bus_message_get_allow_interactive_authorization(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_MESSAGE_SET_EXPECT_REPLY(3) sd_bus_message_set_expect_reply SD_BUS_MESSAGE_SET_EXPECT_REPLY(3)

NOMBRE

sd_bus_message_set_expect_reply, sd_bus_message_get_expect_reply, sd_bus_message_set_auto_start, sd_bus_message_get_auto_start, sd_bus_message_set_allow_interactive_authorization, sd_bus_message_get_allow_interactive_authorization - Establecer y consultar metadatos de mensajes del bus

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_set_expect_reply(sd_bus_message *mensaje, int b);

int sd_bus_message_get_expect_reply(sd_bus_message *mensaje);

int sd_bus_message_set_auto_start(sd_bus_message *mensaje, int b);

int sd_bus_message_get_auto_start(sd_bus_message *mensaje);

int sd_bus_message_set_allow_interactive_authorization(sd_bus_message *mensaje, int b);

int sd_bus_message_get_allow_interactive_authorization(sd_bus_message *mensaje);

DESCRIPCIÓN

sd_bus_message_set_expect_reply() establece o borra la bandera NO_REPLY_EXPECTED en el mensaje m. Esta bandera solo es relevante para mensajes de llamada a métodos y se utiliza para especificar que no se espera una respuesta de retorno de método o un error. Se ignora para otros tipos. Por lo tanto, para un mensaje de llamada a método, llamar

sd_bus_message_set_expect_reply(..., 0)

establece la bandera y suprime la respuesta.

sd_bus_message_get_expect_reply() comprueba si la bandera NO_REPLY_EXPECTED está establecida en el mensaje m. Devolverá un valor positivo si no está establecida y cero si lo está.

sd_bus_message_set_auto_start() establece o borra la bandera NO_AUTO_START en el mensaje m. Cuando la bandera está establecida, el bus no debe iniciar un propietario para el nombre de destino en respuesta a este mensaje. Llamar

sd_bus_message_set_auto_start(..., 0)

establece la bandera.

sd_bus_message_get_auto_start() comprueba si la bandera NO_AUTO_START está establecida en el mensaje m. Devolverá un valor positivo si no está establecida y cero si lo está.

sd_bus_message_set_allow_interactive_authorization() establece o borra la bandera ALLOW_INTERACTIVE_AUTHORIZATION en el mensaje m. Establecer esta bandera informa al receptor que el llamante está preparado para esperar autorización interactiva a través de polkit o un marco similar. Tenga en cuenta que establecer esta bandera no garantiza que el receptor realizará efectivamente la autorización interactiva. Además, asegúrese de establecer un tiempo de espera de mensaje adecuado al usar esta bandera, ya que la autorización interactiva podría tomar mucho tiempo ya que depende de la entrada del usuario. Si b no es cero, la bandera se establece.

sd_bus_message_get_allow_interactive_authorization() comprueba si la bandera ALLOW_INTERACTIVE_AUTHORIZATION está establecida en el mensaje m. Devolverá un entero positivo si la bandera está establecida. De lo contrario, devolverá cero.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un entero no negativo. En caso de fallo, devuelven un código de error negativo al estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

El parámetro mensaje es NULL.

-EPERM

El mensaje mensaje está sellado al intentar establecer una bandera.

El mensaje mensaje tiene el tipo incorrecto.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

sd_bus_message_set_expect_reply(), sd_bus_message_get_expect_reply(), sd_bus_message_set_auto_start() y sd_bus_message_get_auto_start() se añadieron en la versión 240.

sd_bus_message_set_allow_interactive_authorization() y sd_bus_message_get_allow_interactive_authorization() se añadieron en la versión 246.
