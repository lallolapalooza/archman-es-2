SD_JOURNAL_STREAM_FD(3) sd_journal_stream_fd SD_JOURNAL_STREAM_FD(3)

NOMBRE

sd_journal_stream_fd, sd_journal_stream_fd_with_namespace - Crear un descriptor de archivo de flujo de registro para el journal

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_stream_fd(const char *identifier, int priority, int level_prefix);

int sd_journal_stream_fd_with_namespace(const char *name_space, const char *identifier, int priority, int level_prefix);

DESCRIPCIÓN

sd_journal_stream_fd() se puede utilizar para crear un descriptor de archivo de flujo de registro. Los mensajes de registro escritos en este descriptor de archivo como simples cadenas de texto separadas por saltos de línea se escriben en el journal. Este descriptor de archivo puede ser utilizado internamente por las aplicaciones o convertirse en la salida estándar o el error estándar de otros procesos ejecutados.

sd_journal_stream_fd() toma un identificador corto del programa como primer argumento, que se escribirá en el journal como el campo SYSLOG_IDENTIFIER= para cada entrada de registro (ver systemd.journal-fields(7) para más información). El segundo argumento será el nivel de prioridad predeterminado para todos los mensajes. El nivel de prioridad es uno de LOG_EMERG, LOG_ALERT, LOG_CRIT, LOG_ERR, LOG_WARNING, LOG_NOTICE, LOG_INFO, LOG_DEBUG, como se define en syslog.h, ver syslog(3) para detalles. El tercer argumento es un booleano: si es verdadero, se interpretan los prefijos de nivel de registro de estilo de kernel (como SD_WARNING), ver sd-daemon(3) para más información.

sd_journal_stream_fd_with_namespace() es similar a sd_journal_stream_fd(), pero toma un parámetro adicional name_space que especifica en qué espacio de nombres del journal operar. Si se especifica como NULL, la llamada es idéntica a sd_journal_stream_fd(). Para obtener detalles sobre los espacios de nombres del journal, ver systemd-journald.service(8).

Se recomienda que las aplicaciones registren solo mensajes UTF-8 con esta API, pero esto no se impone.

Cada invocación de estas funciones asigna un nuevo descriptor de archivo de flujo de registro, que no se comparte con invocaciones anteriores o posteriores. El descriptor de archivo es de solo escritura (su dirección de lectura se cierra) y O_NONBLOCK se desactiva inicialmente.

VALOR DEVUELTO

La llamada devuelve un descriptor de archivo de solo escritura válido en caso de éxito o un código de error negativo de estilo errno.

SEGURIDAD DE SEÑAL

sd_journal_stream_fd() y sd_journal_stream_fd_with_namespace() son "seguros para señales asíncronas" en el sentido de signal-safety(7).

NOTAS

Todas las funciones enumeradas aquí son seguras para hilos y pueden ser llamadas en paralelo desde múltiples hilos.

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo pkg-config(1) de libsystemd.

EJEMPLOS

Creando un flujo de registro adecuado para fprintf(3):

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <errno.h>
#include <syslog.h>
#include <stdio.h>
#include <unistd.h>
#include <systemd/sd-journal.h>
#include <systemd/sd-daemon.h>
int main(int argc, char *argv[]) {
  int fd;
  FILE *log;
  fd = sd_journal_stream_fd("test", LOG_INFO, 1);
  if (fd < 0) {
    fprintf(stderr, "Fallo al crear el fd de flujo: %s\n", strerror(-fd));
    return 1;
  }
  log = fdopen(fd, "w");
  if (!log) {
    fprintf(stderr, "Fallo al crear el objeto archivo: %s\n", strerror(errno));
    close(fd);
    return 1;
  }
  fprintf(log, "¡Hola Mundo!\n");
  fprintf(log, SD_WARNING "¡Esto es una advertencia!\n");
  fclose(log);
  return 0;
}
