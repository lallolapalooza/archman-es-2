sd_is_fifo(3)

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_IS_FIFO(3) sd_is_fifo SD_IS_FIFO(3)

NOMBRE

sd_is_fifo, sd_is_socket, sd_is_socket_inet, sd_is_socket_unix, sd_is_socket_sockaddr, sd_is_mq, sd_is_special - Comprobar el tipo de un descriptor de archivo

SINOPSIS

#include <systemd/sd-daemon.h>

int sd_is_fifo(int fd, const char *path);

int sd_is_socket(int fd, int family, int type, int listening);

int sd_is_socket_inet(int fd, int family, int type, int listening, uint16_t port);

int sd_is_socket_sockaddr(int fd, int type, const struct sockaddr *addr, unsigned addr_len, int listening);

int sd_is_socket_unix(int fd, int type, int listening, const char *path, size_t length);

int sd_is_mq(int fd, const char *path);

int sd_is_special(int fd, const char *path);

DESCRIPCIÓN

sd_is_fifo() puede ser llamada para comprobar si el descriptor de archivo especificado se refiere a una FIFO o tubería. Si el parámetro path no es NULL, se comprueba si la FIFO está enlazada a la ruta del sistema de archivos especificada.

sd_is_socket() puede ser llamada para comprobar si el descriptor de archivo especificado se refiere a un socket. Si el parámetro family no es AF_UNSPEC, se comprueba si el socket es de la familia especificada (AF_UNIX, AF_INET, ...). Si el parámetro type no es 0, se comprueba si el socket es del tipo especificado (SOCK_STREAM, SOCK_DGRAM, ...). Si el parámetro listening es positivo, se comprueba si el socket está en modo de aceptación, es decir, si se ha llamado a listen() para él. Si listening es 0, se comprueba si el socket no está en este modo. Si el parámetro es negativo, no se realiza dicha comprobación. El parámetro listening solo debe usarse para sockets de flujo y debe establecerse en un valor negativo en caso contrario.

sd_is_socket_inet() es similar a sd_is_socket(), pero opcionalmente comprueba el número de puerto IPv4 o IPv6 al que está enlazado el socket, a menos que port sea cero. Para esta llamada, family debe pasarse como AF_UNSPEC, AF_INET o AF_INET6.

sd_is_socket_sockaddr() es similar a sd_is_socket_inet(), pero comprueba si el socket está enlazado a la dirección especificada por addr. La family especificada por addr debe ser AF_INET o AF_INET6 y addr_len debe ser lo suficientemente grande para esa familia. Si addr especifica un puerto distinto de cero, también se comprueba si el socket está enlazado a ese puerto. Además, para IPv6, si addr especifica sin6_flowinfo o sin6_scope_id distintos de cero, se comprueba si el socket tiene los mismos valores.

sd_is_socket_unix() es similar a sd_is_socket() pero opcionalmente comprueba la ruta AF_UNIX a la que está enlazado el socket, a menos que el parámetro path sea NULL. Para sockets normales de espacio de nombres de archivos AF_UNIX, establezca el parámetro length a 0. Para sockets de espacio de nombres abstractos de Linux, establezca length al tamaño de la dirección, incluyendo el byte 0 inicial, y establezca path al byte 0 inicial de la dirección del socket.

sd_is_mq() puede ser llamada para comprobar si el descriptor de archivo especificado se refiere a una cola de mensajes POSIX. Si el parámetro path no es NULL, se comprueba si la cola de mensajes está enlazada al nombre especificado.

sd_is_special() puede ser llamada para comprobar si el descriptor de archivo especificado se refiere a un archivo especial. Si el parámetro path no es NULL, se comprueba si el descriptor de archivo está enlazado al nombre de archivo especificado. Los archivos especiales en este contexto son nodos de dispositivos de caracteres y archivos en /proc/ o /sys/.

VALOR DE RETORNO

En caso de error, estas llamadas devuelven un código de error negativo estilo errno. Si el descriptor de archivo es del tipo especificado y está enlazado a la dirección especificada, se devuelve un valor positivo, de lo contrario cero.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo libsystemd pkg-config(1).

Internamente, estas funciones utilizan una combinación de fstat(2) y getsockname(2) para comprobar el tipo de descriptor de archivo y a qué está enlazado.

HISTORIAL

sd_is_special() se añadió en la versión 209.

sd_is_socket_sockaddr() se añadió en la versión 233.
