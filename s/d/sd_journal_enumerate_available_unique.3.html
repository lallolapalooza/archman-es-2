sd_journal_enumerate_available_unique(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_JOURNAL_QUERY_UNIQUE(3) sd_journal_query_unique SD_JOURNAL_QUERY_UNIQUE(3)

NOMBRE

sd_journal_query_unique, sd_journal_enumerate_unique, sd_journal_enumerate_available_unique, sd_journal_restart_unique, SD_JOURNAL_FOREACH_UNIQUE - Leer campos de datos únicos del journal

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_query_unique(sd_journal *j, const char *field);

int sd_journal_enumerate_available_unique(sd_journal *j, const void **data, size_t *length);

int sd_journal_enumerate_unique(sd_journal *j, const void **data, size_t *length);

void sd_journal_restart_unique(sd_journal *j);

SD_JOURNAL_FOREACH_UNIQUE(sd_journal *j, const void *data, size_t length);

DESCRIPCIÓN

sd_journal_query_unique() consulta el journal para obtener todos los valores únicos que el campo especificado puede tomar. Toma dos argumentos: el journal a consultar y el nombre del campo a buscar. Los nombres de campo conocidos se listan en systemd.journal-fields(7), pero se puede especificar cualquier campo. Los nombres de campo deben especificarse sin un "=" final. Después de que esta función se haya ejecutado con éxito, los valores de campo se pueden consultar utilizando sd_journal_enumerate_unique() y sd_journal_enumerate_available_unique(). Invocar una de estas llamadas cambiará el nombre del campo que se está consultando y reiniciará el índice de enumeración al primer valor de campo que coincida.

sd_journal_enumerate_unique() puede usarse para iterar a través de todos los campos de datos que coinciden con el nombre de campo seleccionado previamente establecido con sd_journal_query_unique(). En cada invocación se devuelve el siguiente dato de campo que coincide con el nombre del campo. El orden de los campos de datos devueltos no está definido. Toma tres argumentos: el objeto del journal, más un par de punteros a punteros/tamaños donde se deben almacenar el objeto de datos y su tamaño. Los datos devueltos están en un mapa de memoria de solo lectura y solo son válidos hasta la siguiente invocación de sd_journal_enumerate_unique(). Tenga en cuenta que los datos devueltos estarán precedidos por el nombre del campo y "=". Tenga en cuenta que esta llamada está sujeta al umbral de tamaño del campo de datos controlado por sd_journal_set_data_threshold() y solo se devuelve la parte inicial del campo hasta el umbral. Se devuelve un error para los campos que no se pueden recuperar. Consulte la lista de errores a continuación para obtener más detalles.

sd_journal_enumerate_available_unique() es similar a sd_journal_enumerate_unique(), pero omite silenciosamente cualquier campo que pueda ser válido, pero que sea demasiado grande o no sea compatible con la implementación actual.

sd_journal_restart_unique() reinicia el índice de enumeración de datos al principio de la lista. La próxima invocación de sd_journal_enumerate_unique() devolverá nuevamente el primer dato de campo que coincida con el nombre del campo.

Tenga en cuenta que la macro SD_JOURNAL_FOREACH_UNIQUE() puede usarse como un práctico envoltorio alrededor de sd_journal_restart_unique() y sd_journal_enumerate_available_unique().

Tenga en cuenta que estas funciones actualmente no están influenciadas por las coincidencias establecidas con sd_journal_add_match(), pero esto podría cambiar en una versión posterior de este software.

Para enumerar todos los nombres de campo actualmente en uso (y por lo tanto, todos los parámetros de campo adecuados para sd_journal_query_unique()), use la llamada sd_journal_enumerate_fields(3).

VALOR DE RETORNO

sd_journal_query_unique() devuelve 0 en caso de éxito o un código de error negativo al estilo errno. sd_journal_enumerate_unique() y sd_journal_query_available_unique() devuelven un entero positivo si se ha leído el siguiente dato del campo, 0 cuando no quedan más campos, o un código de error negativo al estilo errno. sd_journal_restart_unique() no devuelve nada.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Uno de los parámetros requeridos es NULL o inválido.

Añadido en la versión 246.

-ECHILD

El objeto del journal se creó en un proceso, biblioteca o instancia de módulo diferente.

Añadido en la versión 246.

-EADDRNOTAVAIL

El puntero de lectura no está posicionado en una entrada válida; sd_journal_next(3) o una llamada relacionada no se ha llamado al menos una vez.

Añadido en la versión 246.

-ENOENT

La entrada actual no incluye el campo especificado.

Añadido en la versión 246.

-ENOBUFS

Una entrada comprimida es demasiado grande.

Añadido en la versión 246.

-E2BIG

El campo de datos es demasiado grande para la arquitectura de este ordenador (por ejemplo, por encima de 4 GB en una arquitectura de 32 bits).

Añadido en la versión 246.

-EPROTONOSUPPORT

El journal está comprimido con un método no compatible o el journal utiliza una característica no compatible.

Añadido en la versión 246.

-EBADMSG

El journal está corrupto (posiblemente solo la entrada que se está iterando).

Añadido en la versión 246.

-EIO

El kernel reportó un error de E/S.

Añadido en la versión 246.

NOTAS

Todas las funciones listadas aquí son agnósticas a los hilos y solo un hilo puede operar en un objeto determinado en un momento dado. Diferentes hilos pueden acceder al mismo objeto en diferentes momentos. Se pueden usar múltiples objetos independientes desde diferentes hilos en paralelo.

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo pkg-config(1) de libsystemd.

EJEMPLOS

Use la macro SD_JOURNAL_FOREACH_UNIQUE() para iterar a través de todos los valores que un campo del journal puede tomar (y que son accesibles en la arquitectura dada y no están comprimidos con un mecanismo no compatible). El siguiente ejemplo lista todos los nombres de unidad referenciados en el journal:

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <stdio.h>
#include <systemd/sd-journal.h>
int main(int argc, char *argv[]) {
  sd_journal *j;
  const void *d;
  size_t l;
  int r;
  r = sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);
  if (r < 0) {
    fprintf(stderr, "Failed to open journal: %s\n", strerror(-r));
    return 1;
  }
  r = sd_journal_query_unique(j, "_SYSTEMD_UNIT");
  if (r < 0) {
    fprintf(stderr, "Failed to query journal: %s\n", strerror(-r));
    return 1;
  }
  SD_JOURNAL_FOREACH_UNIQUE(j, d, l)
    printf("%.*s\n", (int) l, (const char*) d);
  sd_journal_close(j);
  return 0;
}

HISTORIA

sd_journal_query_unique(), sd_journal_enumerate_unique(), sd_journal_restart_unique(), y SD_JOURNAL_FOREACH_UNIQUE() se añadieron en la versión 195.

sd_journal_enumerate_available_unique() se añadió en la versión 246.
