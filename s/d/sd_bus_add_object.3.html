DESCRIPCIÓN

sd_bus_add_object_vtable() se utiliza para declarar atributos para la ruta de objeto path conectada a la conexión de bus bus bajo la interfaz interface. La tabla vtable puede contener declaraciones de propiedades usando SD_BUS_PROPERTY() o SD_BUS_WRITABLE_PROPERTY(), declaraciones de métodos usando SD_BUS_METHOD(), SD_BUS_METHOD_WITH_NAMES(), SD_BUS_METHOD_WITH_OFFSET(), o SD_BUS_METHOD_WITH_NAMES_OFFSET(), y declaraciones de señales usando SD_BUS_SIGNAL_WITH_NAMES() o SD_BUS_SIGNAL(), ver más abajo. El parámetro userdata contiene un puntero que se pasará a varias funciones de devolución de llamada. Puede especificarse como NULL si no se necesita ningún valor. A una interfaz se le pueden adjuntar cualquier número de tablas vtable.

sd_bus_add_fallback_vtable() es similar a sd_bus_add_object_vtable(), pero se utiliza para registrar atributos de "fallback". Al buscar una declaración de atributo, primero se comprueban las rutas de objetos de bus registradas con sd_bus_add_object_vtable(). Si no se encuentra ninguna coincidencia, se comprueban las tablas vtable de fallback para cada prefijo de la ruta del objeto de bus, es decir, se eliminan sucesivamente los últimos componentes separados por barras. Esto permite que la tabla vtable se utilice para un número arbitrario de objetos creados dinámicamente.

El parámetro find es una función que se utiliza para localizar el objeto de destino basándose en la ruta del objeto de bus path. Debe devolver 1 y establecer el parámetro de salida ret_found si se encuentra el objeto, devolver 0 si el objeto no se encontró, y devolver un código de error negativo estilo errno o inicializar la estructura de error ret_error en caso de error. El puntero pasado en ret_found se utilizará como parámetro userdata para las funciones de devolución de llamada (desplazado por los desplazamientos offset según se especifica en las entradas de la tabla vtable).

sd_bus_add_object() adjunta una devolución de llamada directamente a la ruta del objeto path. A una ruta de objeto se le pueden adjuntar cualquier número de devoluciones de llamada. Cada devolución de llamada se antepone a la lista de devoluciones de llamada que siempre se llaman en orden. sd_bus_add_fallback() es similar a sd_bus_add_object() pero se aplica a rutas de fallback en su lugar.

sd_bus_add_filter() instala una devolución de llamada que se invoca para cada mensaje D-Bus entrante. Los filtros se pueden utilizar para manejar lógica común a todos los mensajes recibidos por un servicio (por ejemplo, autenticación o autorización).

Cuando se recibe una solicitud, se llaman secuencialmente las devoluciones de llamada asociadas hasta que una devolución de llamada devuelve un entero distinto de cero. Devuelva cero desde una devolución de llamada para dar a otras devoluciones de llamada la oportunidad de procesar la solicitud. Las devoluciones de llamada se llaman en el siguiente orden: primero, se llaman las devoluciones de llamada globales instaladas con sd_bus_add_filter(). Segundo, se llaman las devoluciones de llamada adjuntas directamente a la ruta del objeto de solicitud, seguidas de las devoluciones de llamada de métodos D-Bus adjuntas a la ruta del objeto de solicitud, interfaz y miembro. Finalmente, se llaman las devoluciones de llamada de propiedad adjuntas a la ruta del objeto de solicitud, interfaz y miembro. Si la devolución de llamada final devuelve cero, se enviará una respuesta de error

Tenga en cuenta que puede devolver un entero positivo desde una devolución de llamada de *método* sin enviar inmediatamente una respuesta. Esto informa a sd-bus que esta devolución de llamada se hará responsable de responder a la solicitud sin forzar a la devolución de llamada a producir una respuesta de inmediato. Esto permite que una devolución de llamada realice cualquier número de operaciones asíncronas necesarias para construir una respuesta. Sin embargo, si la producción de una respuesta lleva demasiado tiempo, la llamada al método agotará el tiempo de espera en el llamador. Esto solo está disponible para métodos y no para propiedades.

Si se invocó una devolución de llamada para manejar una solicitud que espera una respuesta y la devolución de llamada devuelve un valor negativo, el valor se interpreta como un código de error negativo de estilo errno y se devuelve al llamador como un error D-Bus como si se hubiera llamado a sd_bus_reply_method_errno(3). Además, todas las devoluciones de llamada toman un parámetro de salida sd_bus_error que se puede utilizar para proporcionar información de error más detallada. Si *ret_error* se establece cuando la devolución de llamada finaliza, el error D-Bus correspondiente se devuelve al llamador como si se hubiera llamado a sd_bus_reply_method_error(3). Cualquier error almacenado en *ret_error* tiene prioridad sobre cualquier valor negativo devuelto por la misma devolución de llamada al determinar qué error enviar de vuelta al llamador. Utilice sd_bus_error_set(3) o una de sus variantes para establecer *ret_error* y devolver un entero negativo desde una devolución de llamada con una sola llamada a función. Para enviar una respuesta de error después de que una devolución de llamada haya finalizado, utilice sd_bus_reply_method_errno(3) o una de sus variantes.

Para todas las funciones, se crea una ranura de coincidencia internamente. Si el parámetro de salida *slot* es NULL, se crea un objeto de ranura "flotante", consulte sd_bus_slot_set_floating(3). De lo contrario, se devuelve un puntero al objeto de ranura. En ese caso, la referencia al objeto de ranura debe liberarse cuando la vtable ya no sea necesaria, consulte sd_bus_slot_unref(3).

El array sd_bus_vtable

El array consta de las estructuras de tipo sd_bus_vtable, pero nunca debe rellenarse manualmente, sino a través de una de las siguientes macros:

SD_BUS_VTABLE_START(flags), SD_BUS_VTABLE_END

Estos deben ser siempre el primer y el último elemento. El parámetro flags se puede utilizar para establecer atributos que se aplican a todo el array; consulte la sección "Flags" a continuación.

SD_BUS_METHOD_WITH_ARGS_OFFSET(), SD_BUS_METHOD_WITH_ARGS()

Declara un método D-Bus con el nombre *member*, argumentos *args* y resultado *result*. *args* espera una secuencia de pares de tipo/nombre de argumento envueltos en la macro SD_BUS_ARGS(). Los elementos en índices pares de esta lista describen los tipos de los argumentos del método. La firma del parámetro del método es la concatenación de todos los literales de cadena en índices pares en *args*. Si un método no tiene parámetros, pase SD_BUS_NO_ARGS a *args*. Los elementos en índices impares describen los nombres de los argumentos del método. *result* espera una secuencia de pares de tipo/nombre envueltos en la macro SD_BUS_RESULT() en el mismo formato que SD_BUS_ARGS(). La firma del resultado del método es la concatenación de todos los literales de cadena en índices pares en *result*. Si un método no tiene resultado, pase SD_BUS_NO_RESULT a *result*. Tenga en cuenta que se espera que los tipos de los argumentos sean literales de cadena entre comillas y los nombres de los argumentos sean literales de cadena sin comillas. Consulte a continuación un ejemplo completo.

La función manejadora *handler* debe ser de tipo sd_bus_message_handler_t. Se llamará para manejar los mensajes entrantes que llamen a este método. Recibe un puntero que es el parámetro *userdata* pasado a la función de registro con un desplazamiento de *offset* bytes. Esto puede usarse para pasar punteros a diferentes campos en la misma estructura de datos a diferentes métodos en la misma vtable. Para enviar una respuesta desde *handler*, llame a sd_bus_reply_method_return(3) con el mensaje con el que se invocó la devolución de llamada. El parámetro *flags* es una combinación de flags, consulte a continuación.

SD_BUS_METHOD_WITH_ARGS() es una abreviatura para llamar a SD_BUS_METHOD_WITH_ARGS_OFFSET() con un desplazamiento de cero.

SD_BUS_METHOD_WITH_NAMES_OFFSET(), SD_BUS_METHOD_WITH_NAMES(), SD_BUS_METHOD_WITH_OFFSET(), SD_BUS_METHOD()

Declara un método D-Bus con el nombre *member*, firma de parámetros *signature*, firma de resultado *result*. Los parámetros *in_names* y *out_names* especifican los nombres de los argumentos de los argumentos de entrada y salida en la firma de la función. *in_names* y *out_names* deben crearse utilizando la macro SD_BUS_PARAM(), consulte a continuación. En todos los demás aspectos, esta macro se comporta exactamente igual que SD_BUS_METHOD_WITH_ARGS_OFFSET().

SD_BUS_METHOD_WITH_NAMES(), SD_BUS_METHOD_WITH_OFFSET() y SD_BUS_METHOD() son variantes que especifican desplazamiento cero (el parámetro *userdata* se pasa sin cambios), dejan los nombres sin establecer (es decir, sin nombres de parámetros) o ambos.

Prefiera usar SD_BUS_METHOD_WITH_ARGS_OFFSET() y SD_BUS_METHOD_WITH_ARGS() sobre estas macros, ya que permiten especificar tipos y nombres de argumentos uno al lado del otro, lo que es menos propenso a errores que especificar primero todos los tipos de argumentos seguidos de la especificación de todos los nombres de argumentos.

SD_BUS_SIGNAL_WITH_ARGS()

Declara una señal D-Bus con el nombre *member* y argumentos *args*. *args* espera una secuencia de pares de tipo/nombre de argumento envueltos en la macro SD_BUS_ARGS(). Los elementos en índices pares de esta lista describen los tipos de los argumentos de la señal. La firma del parámetro de la señal es la concatenación de todos los literales de cadena en índices pares en *args*. Si una señal no tiene parámetros, pase SD_BUS_NO_ARGS a *args*. Los elementos en índices impares describen los nombres de los argumentos de la señal. El parámetro *flags* es una combinación de flags. Consulte a continuación un ejemplo completo.

SD_BUS_SIGNAL_WITH_NAMES(), SD_BUS_SIGNAL()

Declara una señal D-Bus con el nombre *member*, firma de parámetros *signature* y nombres de argumentos *names*. *names* debe crearse utilizando la macro SD_BUS_PARAM(), consulte a continuación. El parámetro *flags* es una combinación de flags, consulte a continuación.

SD_BUS_SIGNAL() es equivalente a SD_BUS_SIGNAL_WITH_NAMES() con el parámetro *names* sin establecer (es decir, sin nombres de parámetros).

Prefiera usar SD_BUS_SIGNAL_WITH_ARGS() sobre estas macros, ya que permite especificar tipos y nombres de argumentos uno al lado del otro, lo que es menos propenso a errores que especificar primero todos los tipos de argumentos seguidos de la especificación de todos los nombres de argumentos.

SD_BUS_WRITABLE_PROPERTY(), SD_BUS_PROPERTY()

Declara una propiedad D-Bus con el nombre *member* y firma de valor *signature*. Los parámetros *get* y *set* son los métodos de obtención y establecimiento. Se llaman con un puntero que es el parámetro *userdata* pasado a la función de registro con un desplazamiento de *offset* bytes. Esto se puede utilizar para pasar punteros a diferentes campos en la misma estructura de datos a diferentes establecedores y obtenedores en la misma vtable. El parámetro *flags* es una combinación de flags, consulte a continuación.

Los métodos de establecimiento y obtención se pueden omitir (especificándose como NULL), si la propiedad es de uno de los tipos básicos o "as" en el caso de propiedades de solo lectura. En esos casos, los parámetros *userdata* y *offset* deben apuntar juntos a una variable válida del tipo correspondiente. Se proporcionará un establecedor y obtenedor predeterminado, que simplemente copiará el argumento entre esta variable y el mensaje.

SD_BUS_PROPERTY() se utiliza para definir una propiedad de solo lectura.

SD_BUS_PARAM()

Los nombres de los parámetros deben envolverse en esta macro, consulte el ejemplo a continuación.

Flags

El parámetro *flags* se utiliza para especificar una combinación de **Anotaciones de D-Bus**[1].

SD_BUS_VTABLE_DEPRECATED

Marca esta entrada de vtable como obsoleta utilizando la anotación org.freedesktop.DBus.Deprecated en los datos de introspección. Si se especifica para SD_BUS_VTABLE_START(), la anotación se aplica a la interfaz contenedora.

SD_BUS_VTABLE_HIDDEN

Oculta esta entrada de vtable. No se mostrará en los datos de introspección. Si se especifica para SD_BUS_VTABLE_START(), se ocultan todas las entradas del array.

SD_BUS_VTABLE_METHOD_NO_REPLY

Marca esta entrada de método como un método que no devolverá una respuesta utilizando la anotación org.freedesktop.DBus.Method.NoReply en los datos de introspección.

SD_BUS_VTABLE_PROPERTY_CONST, SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE, SD_BUS_VTABLE_PROPERTY_EMITS_INVALIDATION

Estos tres flags corresponden a diferentes valores de la anotación org.freedesktop.DBus.Property.EmitsChangedSignal, que especifica si la señal org.freedesktop.DBus.Properties.PropertiesChanged se emite cada vez que cambia la propiedad. SD_BUS_VTABLE_PROPERTY_CONST corresponde a const y significa que la propiedad nunca cambia durante la vida útil del objeto al que pertenece, por lo que no es necesario emitir ninguna señal. SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE corresponde a true y significa que la señal se emite. SD_BUS_VTABLE_PROPERTY_EMITS_INVALIDATION corresponde a invalidates y significa que la señal se emite, pero el valor no se incluye en la señal.

SD_BUS_VTABLE_PROPERTY_EXPLICIT

Marca esta entrada de propiedad de vtable como que requiere una solicitud explícita para que se muestre el valor (generalmente porque el valor es grande o lento de calcular). Esta entrada no se puede combinar con SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE y no se mostrará en las listas de propiedades por defecto (por ejemplo, busctl introspect). Esto corresponde a la anotación org.freedesktop.systemd1.Explicit en los datos de introspección.

SD_BUS_VTABLE_SENSITIVE

Marca esta entrada de método de vtable como que procesa datos sensibles. Cuando se establece, los mensajes de llamada de método entrantes y sus mensajes de respuesta salientes se marcan como sensibles utilizando sd_bus_message_sensitive(3), para que se borren de la memoria cuando se liberan.
