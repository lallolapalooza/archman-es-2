sd_varlink_push_dup_fd(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_VARLINK_PUSH_FD(3) sd_varlink_push_dup_fd SD_VARLINK_PUSH_FD(3)

NOMBRE

sd_varlink_push_fd, sd_varlink_push_dup_fd - Enviar un descriptor de archivo para que se envíe con el próximo mensaje Varlink saliente

SINOPSIS

#include <systemd/sd-varlink.h>

int sd_varlink_push_fd(sd_varlink *link, int fd);

int sd_varlink_push_dup_fd(sd_varlink *link, int fd);

DESCRIPCIÓN

sd_varlink_push_fd() envía un descriptor de archivo para que se envíe con el próximo mensaje Varlink saliente. Toma un objeto de conexión Varlink y un descriptor de archivo como parámetro. El descriptor de archivo no se duplica, y por lo tanto la propiedad del descriptor de archivo se transfiere al objeto de conexión Varlink (solo en caso de éxito; en caso de fallo, el llamante conserva la propiedad). Una vez que el descriptor de archivo se ha escrito en el socket de transporte subyacente, se cierra automáticamente. El código de la aplicación que llama no debe manipular el descriptor de archivo ni cerrarlo por sí mismo, de lo contrario, interferirá con la implementación del protocolo Varlink. Esta llamada solo se admite si el transporte subyacente admite el paso de descriptores de archivo (efectivamente, esto significa que la funcionalidad se admite solo en AF_UNIX locales), y el concepto no forma parte del protocolo Varlink, sino simplemente una característica del transporte subyacente.

sd_varlink_push_dup_fd() es idéntico a sd_varlink_push_fd(), excepto que el descriptor de archivo se duplica automáticamente, y por lo tanto el código de la aplicación que llama conserva la propiedad del descriptor de archivo proporcionado y debe cerrarlo por sí mismo.

Tenga en cuenta que el paso de descriptores de archivo solo está permitido después de una llamada a sd_varlink_set_allow_fd_passing_output() que lo habilite, de lo contrario, estas llamadas fallarán con -EPERM.

Tenga en cuenta que en Linux se puede poner en cola un máximo de 253 descriptores de archivo en sockets AF_UNIX a la vez. Intentar poner en cola más en un solo mensaje Varlink fallará con -ENOBUFS.

VALOR DE RETORNO

En caso de éxito, sd_varlink_push_fd() y sd_varlink_push_dup_fd() devuelven un entero no negativo. En caso de fallo, devuelven un código de error negativo de tipo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Un argumento es inválido.

-EBADF

El descriptor de archivo proporcionado no es válido.

-EPERM

El paso de descriptores de archivo no ha sido habilitado a través de sd_varlink_set_allow_fd_passing_output().

-ENOBUFS

Ya se ha enviado el máximo de 253 descriptores de archivo para el próximo mensaje Varlink saliente, no se pueden poner más descriptores en cola para este mensaje.

-ENOMEM

Fallo en la asignación de memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para subprocesos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un subproceso paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando aún no se han iniciado otros subprocesos.

HISTORIA

sd_varlink_push_fd() y sd_varlink_push_dup_fd() se añadieron en la versión 257.
