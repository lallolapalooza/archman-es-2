sd_bus_message_new_method_errnof(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_MESSAGE_NEW_METHOD_ERRNOF(3) sd_bus_message_new_method_errnof SD_BUS_MESSAGE_NEW_METHOD_ERRNOF(3)

NOMBRE

sd_bus_message_new_method_error, sd_bus_message_new_method_errorf, sd_bus_message_new_method_errno, sd_bus_message_new_method_errnof - Crear una respuesta de error para una llamada a método

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_new_method_error(sd_bus_message *call, sd_bus_message **m, const sd_bus_error *e);

int sd_bus_message_new_method_errorf(sd_bus_message *call, sd_bus_message **m, const char *name, const char *format, ...);

int sd_bus_message_new_method_errno(sd_bus_message *call, sd_bus_message **m, int error, const sd_bus_error *p);

int sd_bus_message_new_method_errnof(sd_bus_message *call, sd_bus_message **m, int error, const char *format, ...);

DESCRIPCIÓN

La función sd_bus_message_new_method_error() crea un nuevo objeto de mensaje de bus que es una respuesta de error al mensaje call, y lo devuelve en el parámetro de salida m. La información del error de la estructura e se anexa: el campo name de e se usa como el identificador de error en la cabecera de la respuesta (por ejemplo, un nombre de error como "org.freedesktop.DBus.Error.NotSupported" o el símbolo equivalente SD_BUS_ERROR_NOT_SUPPORTED), y el campo message se establece como la cadena de mensaje de error legible por humanos si está presente. La estructura de error e debe tener el campo name establecido, vea sd_bus_error_is_set(3).

La función sd_bus_message_new_method_errorf() crea una respuesta de error de manera similar a sd_bus_message_new_method_error(), pero en lugar de una estructura de error lista, toma una cadena identificadora de error name, más una cadena de formato printf(3) format y argumentos correspondientes. Se envía una respuesta de error con el identificador de error name y la cadena formateada como el mensaje. name y format no deben ser NULL.

La función sd_bus_message_new_method_errno() crea una respuesta de error de manera similar a sd_bus_message_new_method_error(), pero además de la estructura de error p, toma un valor de error errno(3) en el parámetro error. Si la estructura de error p está establecida (vea sd_bus_error_is_set(3)), se usa en la respuesta. De lo contrario, error se traduce a un identificador de error y se usa para crear una nueva estructura de error usando sd_bus_error_set_errno(3) y que se usa en la respuesta. (Si error es cero, en realidad no se establece ningún error, y se crea una respuesta de error sin información.)

La función sd_bus_message_new_method_errnof() crea una respuesta de error de manera similar a sd_bus_message_new_method_error(). Toma un valor de error errno(3) en el parámetro error, más una cadena de formato printf(3) format y argumentos correspondientes. "%m" puede ser usado en la cadena de formato para referirse a la cadena de error correspondiente al código errno especificado. El mensaje de error se inicializa usando el identificador de error generado a partir de error y la cadena formateada. (Si error es cero, en realidad no se establece ningún error, y se crea una respuesta de error sin información.)

VALOR DE RETORNO

Estas funciones devuelven 0 si la respuesta de error se creó con éxito, y un código de error negativo estilo errno en caso contrario.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

El mensaje de llamada call o el parámetro de salida m son NULL.

El mensaje call no es un mensaje de llamada a método.

El parámetro de error e de sd_bus_message_new_method_error() no está establecido, vea sd_bus_error_is_set(3).

-EPERM

El mensaje call ha sido sellado.

-ENOTCONN

El bus al que está adjunto el mensaje call no está conectado.

-ENOMEM

Fallo en la asignación de memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un subproceso paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros subprocesos.
