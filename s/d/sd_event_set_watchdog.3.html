SD_EVENT_SET_WATCHDOG(3) sd_event_set_watchdog SD_EVENT_SET_WATCHDOG(3)

NOMBRE

sd_event_set_watchdog, sd_event_get_watchdog - Habilitar soporte de vigilancia (watchdog) para el bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>

int sd_event_set_watchdog(sd_event *event, int b);

int sd_event_get_watchdog(sd_event *event);

DESCRIPCIÓN

sd_event_set_watchdog() se puede usar para habilitar o deshabilitar el soporte de notificación automática de vigilancia (watchdog) en el objeto del bucle de eventos especificado en el parámetro event. Específicamente, dependiendo del argumento booleano b, esto asegurará que el bucle de eventos se despierte en intervalos regulares y envíe mensajes de notificación de vigilancia al gestor de servicios, si esto fue solicitado por el gestor de servicios. El soporte de vigilancia se determina con sd_watchdog_enabled(3), y los mensajes de vigilancia se envían con sd_notify(3). Ver la opción WatchdogSec= en systemd.service(5) para detalles sobre cómo habilitar el soporte de vigilancia para un servicio y el protocolo utilizado. El intervalo de despertar se elige como la mitad del tiempo de espera de la vigilancia declarado por el gestor de servicios a través de la variable de entorno $WATCHDOG_USEC. Si el gestor de servicios no solicitó notificaciones de vigilancia, o si el proceso no fue invocado por el gestor de servicios, esta llamada con un parámetro b verdadero no realiza ninguna operación. Pasar un parámetro b falso deshabilitará el envío automático de mensajes de notificación de vigilancia si estaba habilitado antes. Los objetos de bucle de eventos recién asignados tienen esta función deshabilitada.

El primer mensaje de notificación de vigilancia se envía inmediatamente cuando se invoca sd_event_set_watchdog() con un parámetro b verdadero.

La lógica de vigilancia está diseñada para permitir que el gestor de servicios detecte automáticamente los servicios que han dejado de procesar eventos entrantes, y por lo tanto parecen "colgados". Las notificaciones de vigilancia solo se envían al comienzo de cada iteración del bucle de eventos. Por lo tanto, si una función de despacho de fuente de evento se bloquea durante un tiempo excesivo y no devuelve la ejecución al bucle de eventos rápidamente, esto podría causar que el mensaje de notificación se retrase, y posiblemente resulte en una terminación anormal del programa, según lo configurado en el archivo de unidad del servicio.

sd_event_get_watchdog() se puede usar para determinar si el soporte de vigilancia fue solicitado previamente por una llamada a sd_event_set_watchdog() con un parámetro b verdadero y se habilitó correctamente.

VALOR DE RETORNO

En caso de éxito, sd_event_set_watchdog() y sd_event_get_watchdog() devuelven un entero positivo distinto de cero si el gestor de servicios solicitó soporte de vigilancia y este se habilitó correctamente. Devuelven cero si el gestor de servicios no solicitó soporte de vigilancia, o si el soporte de vigilancia se deshabilitó explícitamente con un parámetro b falso. En caso de fallo, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ECHILD

El bucle de eventos se ha creado en un proceso, biblioteca o instancia de módulo diferente.

-EINVAL

El objeto de bucle de eventos pasado no es válido.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

sd_event_set_watchdog() y sd_event_get_watchdog() se añadieron en la versión 229.
