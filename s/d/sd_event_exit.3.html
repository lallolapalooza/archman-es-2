SD_EVENT_EXIT(3) sd_event_exit SD_EVENT_EXIT(3)

NOMBRE

sd_event_exit, sd_event_get_exit_code - Solicitar la salida del bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>

int sd_event_exit(sd_event *event, int code);

int sd_event_get_exit_code(sd_event *event, int *ret);

DESCRIPCIÓN

sd_event_exit() solicita al bucle de eventos especificado en el objeto de bucle de eventos event que salga. El parámetro code puede ser cualquier valor entero y es devuelto tal cual por sd_event_loop(3) después de la última iteración del bucle de eventos. También puede ser consultado usando sd_event_get_exit_code(), ver más abajo.

Cuando se solicita la salida, el bucle de eventos dejará de escuchar y de procesar las fuentes de eventos regulares. En su lugar, procederá a ejecutar solo las fuentes de eventos registradas con sd_event_add_exit(3) en el orden definido por su prioridad. Después de que todas las fuentes de eventos de salida hayan sido procesadas, el bucle de eventos terminará.

Si se invoca sd_event_exit() por segunda vez mientras el bucle de eventos todavía está procesando las fuentes de eventos de salida, se actualiza el código de salida almacenado en el objeto del bucle de eventos, pero no se ejecuta ninguna otra operación.

sd_event_get_exit_code() puede ser utilizado para consultar el código de salida pasado a una llamada anterior de sd_event_exit(). El parámetro de retorno ret puede establecerse a NULL, para simplemente comprobar si sd_event_exit() ha sido llamado antes (ya que sd_event_get_exit_code() falla con -ENODATA si no es así, ver más abajo).

Si bien todo el rango de enteros positivos y negativos puede ser utilizado para el código de salida, se debe tener cuidado de no elegir códigos de salida que entren en conflicto con los códigos de salida regulares devueltos por sd_event_loop(), si estos códigos de salida deben ser distinguibles.

Tenga en cuenta que para la mayoría de los tipos de fuentes de eventos, pasar el puntero de la función de retorno de llamada como NULL en la llamada constructora respectiva (es decir, en sd_event_add_time(3), sd_event_add_signal(3), ...) tiene el efecto de que se invoque sd_event_exit() una vez que la fuente de eventos se active, con el puntero de datos de usuario especificado, convertido a un entero, como parámetro del código de salida. Esto es útil para terminar automáticamente un bucle de eventos después de alguna condición, como un tiempo de espera o la recepción de SIGTERM o similar. Consulte la documentación de la llamada constructora respectiva para obtener detalles.

VALOR DE RETORNO

En caso de éxito, sd_event_exit() y sd_event_get_exit_code() devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

El objeto del bucle de eventos o el puntero al código de error son inválidos.

-ECHILD

El bucle de eventos fue creado en un proceso, biblioteca o instancia de módulo diferente.

-ESTALE

El bucle de eventos ya ha salido y todos los manejadores de salida ya han sido procesados.

-ENODATA

Devuelto por sd_event_get_exit_code() en caso de que el bucle de eventos aún no haya sido solicitado para salir.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para múltiples hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

sd_event_exit() y sd_event_get_exit_code() se añadieron en la versión 229.
