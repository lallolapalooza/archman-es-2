NOMBRE

sd_bus_creds_new_from_pid, sd_bus_creds_new_from_pidfd, sd_bus_creds_get_mask, sd_bus_creds_get_augmented_mask, sd_bus_creds_ref, sd_bus_creds_unref, sd_bus_creds_unrefp - Recuperar objeto de credenciales para el PID especificado

#include <systemd/sd-bus.h>

int sd_bus_creds_new_from_pid(pid_t pid, uint64_t creds_mask, sd_bus_creds **ret);

DESCRIPCIÓN

sd_bus_creds_new_from_pid() crea un nuevo objeto de credenciales y lo rellena con información sobre el proceso pid. El puntero a este objeto se almacenará en el puntero ret. Tenga en cuenta que los objetos de credenciales también pueden crearse y recuperarse a través de sd_bus_get_name_creds(3), sd_bus_get_owner_creds(3) y sd_bus_message_get_creds(3).

sd_bus_creds_new_from_pidfd() es idéntico a sd_bus_creds_new_from_pid(), pero toma un descriptor de archivo PID en lugar de un PID numérico como referencia al proceso. Véase pidfd_open(2).

La información que se almacenará está determinada por creds_mask. Puede contener un subconjunto de constantes ORed SD_BUS_CREDS_PID, SD_BUS_CREDS_PPID, SD_BUS_CREDS_TID, SD_BUS_CREDS_UID, SD_BUS_CREDS_EUID, SD_BUS_CREDS_SUID, SD_BUS_CREDS_FSUID, SD_BUS_CREDS_GID, SD_BUS_CREDS_EGID, SD_BUS_CREDS_SGID, SD_BUS_CREDS_FSGID, SD_BUS_CREDS_SUPPLEMENTARY_GIDS, SD_BUS_CREDS_COMM, SD_BUS_CREDS_TID_COMM, SD_BUS_CREDS_EXE, SD_BUS_CREDS_CMDLINE, SD_BUS_CREDS_CGROUP, SD_BUS_CREDS_UNIT, SD_BUS_CREDS_SLICE, SD_BUS_CREDS_USER_UNIT, SD_BUS_CREDS_USER_SLICE, SD_BUS_CREDS_SESSION, SD_BUS_CREDS_OWNER_UID, SD_BUS_CREDS_EFFECTIVE_CAPS, SD_BUS_CREDS_PERMITTED_CAPS, SD_BUS_CREDS_INHERITABLE_CAPS, SD_BUS_CREDS_BOUNDING_CAPS, SD_BUS_CREDS_SELINUX_CONTEXT, SD_BUS_CREDS_AUDIT_SESSION_ID, SD_BUS_CREDS_AUDIT_LOGIN_UID, SD_BUS_CREDS_TTY, SD_BUS_CREDS_UNIQUE_NAME, SD_BUS_CREDS_WELL_KNOWN_NAMES, SD_BUS_CREDS_DESCRIPTION, y SD_BUS_CREDS_PIDFD. Utilice el valor especial _SD_BUS_CREDS_ALL para solicitar todos los campos admitidos. La constante SD_BUS_CREDS_AUGMENT no puede combinarse con un OR en la máscara para invocaciones de sd_bus_creds_new_from_pid() o sd_bus_creds_new_from_pidfd().

Los campos se pueden recuperar del objeto de credenciales utilizando sd_bus_creds_get_pid(3) y otras funciones que corresponden directamente a las constantes enumeradas anteriormente.

Una máscara de los campos que se recuperaron realmente con éxito se puede obtener con sd_bus_creds_get_mask(). Si el objeto de credenciales se creó con sd_bus_creds_new_from_pid() o sd_bus_creds_new_from_pidfd(), este será un subconjunto de los campos solicitados en creds_mask.

De forma similar a sd_bus_creds_get_mask(), la función sd_bus_creds_get_augmented_mask() devuelve una máscara de bits de constantes de campo. La máscara indica qué campos de credenciales se han recuperado de forma no atómica. Para objetos de credenciales creados a través de sd_bus_creds_new_from_pid() o sd_bus_creds_new_from_pidfd(), esta máscara será idéntica a la máscara devuelta por sd_bus_creds_get_mask(). Sin embargo, para objetos de credenciales recuperados a través de sd_bus_get_name_creds(), esta máscara se establecerá para los campos de credenciales que no pudieron determinarse de forma atómica en el momento de la conexión del par, y que posteriormente se añadieron leyendo datos de credenciales de aumento de /proc/. Del mismo modo, para objetos de credenciales recuperados a través de sd_bus_get_owner_creds(), la máscara se establece para los campos que no pudieron determinarse de forma atómica en el momento de la creación del bus, pero que se han aumentado. De forma similar, para objetos de credenciales recuperados a través de sd_bus_message_get_creds(), la máscara se establece para los campos que no pudieron determinarse de forma atómica en el momento del envío del mensaje, pero que se han aumentado. La máscara devuelta por sd_bus_creds_get_augmented_mask() es siempre un subconjunto de (o idéntica a) la máscara devuelta por sd_bus_creds_get_mask() para el mismo objeto. La última llamada, por lo tanto, devuelve todos los campos de credenciales disponibles en el objeto de credenciales, la primera marca entonces el subconjunto de aquellos que han sido aumentados. Tenga en cuenta que los campos aumentados no son adecuados para decisiones de autorización, ya que pueden recuperarse en momentos diferentes, estando así sujetos a condiciones de carrera. Por lo tanto, los campos aumentados deben usarse exclusivamente con fines informativos.

sd_bus_creds_ref() crea una nueva referencia al objeto de credenciales c. Este objeto no se destruirá hasta que sd_bus_creds_unref() se haya llamado tantas veces más una. Una vez que el contador de referencias haya caído a cero, c ya no podrá utilizarse, por lo que las llamadas posteriores a sd_bus_creds_ref(c) o sd_bus_creds_unref(c) son ilegales.

sd_bus_creds_unref() destruye una referencia a c.

sd_bus_creds_unrefp() es similar a sd_bus_creds_unref() pero toma un puntero a un puntero a un objeto sd_bus_creds. Esta llamada es útil en conjunción con el Atributo de Variables de Limpieza de GCC y LLVM[1]. Tenga en cuenta que esta función se define como una función inline.

sd_bus_creds_ref(), sd_bus_creds_unref() y sd_bus_creds_unrefp() no realizan ninguna operación si el objeto de credenciales de bus pasado es NULL.

VALOR DE RETORNO

En caso de éxito, sd_bus_creds_new_from_pid() y sd_bus_creds_new_from_pidfd() devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo estilo errno.

sd_bus_creds_get_mask() devuelve la máscara de los campos adquiridos con éxito.

sd_bus_creds_get_augmented_mask() devuelve la máscara de los campos que se han aumentado a partir de datos en /proc/, y por lo tanto no son adecuados para decisiones de autorización.

sd_bus_creds_ref() siempre devuelve el argumento.

sd_bus_creds_unref() siempre devuelve NULL.

PROPIEDAD DE REFERENCIA

Las funciones sd_bus_creds_new_from_pid() y sd_bus_creds_new_from_pidfd() crean un nuevo objeto y el llamador posee la única referencia. Cuando ya no sea necesario, esta referencia debe destruirse con sd_bus_creds_unref(3).

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ESRCH

No se pudo encontrar el pid especificado.

-EACCESS

No se tienen los permisos necesarios para leer la información de credenciales del proceso especificado.

-EINVAL

Se pasó un valor no válido a una función.

-ENOMEM

No hay suficiente memoria disponible.

-EPERM

No se tienen los permisos necesarios para abrir el descriptor de archivo PID.

NAME

sd_bus_creds_ref, sd_bus_creds_unref, sd_bus_creds_unrefp, sd_bus_creds_get_mask, sd_bus_creds_get_augmented_mask, sd_bus_creds_new_from_pid, sd_bus_creds_new_from_pidfd - Gestionar la información de credenciales de un bus

SYNOPSIS

#include <systemd/sd-bus.h>

sd_bus_creds *sd_bus_creds_ref(sd_bus_creds *creds);
void sd_bus_creds_unref(sd_bus_creds *creds);
int sd_bus_creds_unrefp(sd_bus_creds **creds);
int sd_bus_creds_get_mask(sd_bus_creds *creds, uint32_t *mask);
int sd_bus_creds_get_augmented_mask(sd_bus_creds *creds, uint32_t *mask);
int sd_bus_creds_new_from_pid(pid_t pid, sd_bus_creds **creds);
int sd_bus_creds_new_from_pidfd(int pidfd, sd_bus_creds **creds);

DESCRIPTION

La información de credenciales de un bus se puede obtener para un proceso específico (vía sd_bus_creds_new_from_pid(3)) o para un descriptor de archivo de proceso (vía sd_bus_creds_new_from_pidfd(3)).

Las funciones sd_bus_creds_ref() y sd_bus_creds_unref() se utilizan para incrementar y decrementar el contador de referencias de un objeto sd_bus_creds. La función sd_bus_creds_unrefp() es similar a sd_bus_creds_unref(), pero también establece el puntero a NULL después de liberar la memoria.

La función sd_bus_creds_get_mask() devuelve la máscara de capacidades del proceso que se pasó a sd_bus_creds_new_from_pid() o sd_bus_creds_new_from_pidfd().

La función sd_bus_creds_get_augmented_mask() devuelve la máscara de capacidades aumentada para el proceso, que incluye capacidades que pueden haber sido otorgadas al proceso en tiempo de ejecución por medio de sd_bus_slot_set_cred(3). Esto es útil cuando se verifican permisos de forma proactiva.

RETURN VALUE

Las funciones sd_bus_creds_new_from_pid() y sd_bus_creds_new_from_pidfd() devuelven 0 si el éxito, o un código de error negativo.

La función sd_bus_creds_ref() siempre devuelve el argumento creds.

Las funciones sd_bus_creds_unref() y sd_bus_creds_unrefp() no devuelven ningún valor.

Las funciones sd_bus_creds_get_mask() y sd_bus_creds_get_augmented_mask() devuelven 0 si el éxito, o un código de error negativo.

Los posibles códigos de error son:

-EINVAL

Parámetro especificado inválido (NULL en caso de parámetros de salida).

-ENOMEM

Fallo en la asignación de memoria.

-EOPNOTSUPP

Uno de los campos solicitados es desconocido para el sistema local.

REFERENCE OWNERSHIP

Las funciones sd_bus_creds_new_from_pid() y sd_bus_creds_new_from_pidfd() devuelven una nueva referencia al objeto de credenciales. El llamador es responsable de liberar esta referencia utilizando sd_bus_creds_unref().

La función sd_bus_creds_ref() incrementa el contador de referencias y devuelve una nueva referencia al objeto de credenciales.

La función sd_bus_creds_unref() decrementa el contador de referencias y libera la memoria si el contador llega a cero. La función sd_bus_creds_unrefp() hace lo mismo, pero también establece el puntero a NULL.

NOTES

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada contra y enlazada con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar solo llamadas a setenv() desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
