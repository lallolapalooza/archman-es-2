sd_uid_get_login_time(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_UID_GET_STATE(3) sd_uid_get_state SD_UID_GET_STATE(3)

NOMBRE

sd_uid_get_state, sd_uid_is_on_seat, sd_uid_get_sessions, sd_uid_get_seats, sd_uid_get_display, sd_uid_get_login_time - Determinar el estado de inicio de sesión de un identificador de usuario Unix específico

SINOPSIS

#include <systemd/sd-login.h>

int sd_uid_get_state(uid_t uid, char **state);

int sd_uid_is_on_seat(uid_t uid, int require_active, const char *seat);

int sd_uid_get_sessions(uid_t uid, int require_active, char ***sessions);

int sd_uid_get_seats(uid_t uid, int require_active, char ***seats);

int sd_uid_get_display(uid_t uid, char **session);

int sd_uid_get_login_time(uid_t uid, uint64_t *usec);

DESCRIPCIÓN

sd_uid_get_state() se puede utilizar para determinar el estado de inicio de sesión de un identificador de usuario Unix específico. Los siguientes estados se conocen actualmente: "offline" (usuario no conectado en absoluto), "lingering" (usuario no conectado, pero algunos servicios de usuario en ejecución), "online" (usuario conectado, pero no activo, es decir, no tiene una sesión en primer plano), "active" (usuario conectado y tiene al menos una sesión activa, es decir, una sesión en primer plano), "closing" (usuario no conectado y no persistente, pero todavía hay algunos procesos alrededor). En el futuro, se podrían definir estados adicionales; el código del cliente debe estar escrito para ser robusto ante cadenas de estado adicionales devueltas. La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso.

sd_uid_is_on_seat() se puede utilizar para determinar si un usuario específico ha iniciado sesión o está activo en un asiento específico. Acepta un identificador de usuario de Unix y una cadena identificadora de asiento como parámetros. El parámetro require_active es un valor booleano. Si no es cero (verdadero), esta función probará si el usuario está activo (es decir, tiene una sesión que está en primer plano y acepta la entrada del usuario) en el asiento especificado; de lo contrario (falso), solo si el usuario ha iniciado sesión (y posiblemente inactivo) en el asiento especificado.

sd_uid_get_sessions() se puede utilizar para determinar las sesiones actuales del usuario especificado. Acepta un identificador de usuario de Unix como parámetro. El parámetro require_active controla si la lista devuelta consistirá solo en aquellas sesiones en las que el usuario está actualmente activo (> 0), en las que el usuario está actualmente en línea pero posiblemente inactivo (= 0), o conectado pero posiblemente cerrando la sesión (< 0). La llamada devuelve una matriz de cadenas terminadas en NULL de identificadores de sesión en sessions que deben ser liberadas por el llamante con la llamada free(3) de libc después de su uso, incluidas todas las cadenas a las que se hace referencia. Si el parámetro de matriz de cadenas se pasa como NULL, la matriz no se rellenará, pero el código de retorno aún indicará el número de sesiones actuales. Tenga en cuenta que en lugar de una matriz vacía, se puede devolver NULL y debe considerarse equivalente a una matriz vacía.

De manera similar, sd_uid_get_seats() se puede utilizar para determinar la lista de asientos en los que el usuario tiene actualmente sesiones. Se aplican semánticas similares, sin embargo, tenga en cuenta que el usuario puede tener múltiples sesiones en el mismo asiento, así como sesiones sin asiento adjunto y, por lo tanto, el número de entradas en la matriz devuelta puede diferir del devuelto por sd_uid_get_sessions().

sd_uid_get_display() devuelve el nombre de la sesión "primaria" de un usuario. Si el usuario tiene sesiones gráficas, será la sesión gráfica más antigua. De lo contrario, será la sesión abierta más antigua.

sd_uid_get_login_time() se puede utilizar para determinar el momento en que se invocó el gestor de servicios del usuario, que es el momento en que comenzó la primera sesión activa del usuario, desde la cual se mantuvo conectado continuamente. El usec está en microsegundos desde la época (CLOCK_REALTIME). Esta llamada fallará con -ENXIO si el usuario no está conectado actualmente.

VALOR DE RETORNO

En caso de éxito, sd_uid_get_state() y sd_uid_get_login_time() devuelven 0 o un entero positivo. Si la prueba tiene éxito, sd_uid_is_on_seat() devuelve un entero positivo; si falla, 0. sd_uid_get_sessions() y sd_uid_get_seats() devuelven el número de entradas en las matrices devueltas. sd_uid_get_display() devuelve un código no negativo en caso de éxito. En caso de error, estas llamadas devuelven un código de error negativo al estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENODATA

El campo dado no está especificado para el usuario descrito.

-ENXIO

El asiento especificado es desconocido.

-EINVAL

Un parámetro de entrada era inválido (fuera de rango o NULL, donde eso no es aceptado). Esto también se devuelve si el ID de usuario pasado es 0xFFFF o 0xFFFFFFFF, que no están definidos en Linux.

-ENOMEM

Fallo en la asignación de memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un subproceso paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se han iniciado otros subprocesos.

HISTORIA

sd_uid_get_display() se añadió en la versión 213.

sd_uid_get_login_time() se añadió en la versión 254.
