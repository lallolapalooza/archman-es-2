sd_journal_add_match(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_JOURNAL_ADD_MATCH(3) sd_journal_add_match SD_JOURNAL_ADD_MATCH(3)

NOMBRE

sd_journal_add_match, sd_journal_add_disjunction, sd_journal_add_conjunction, sd_journal_flush_matches - Añadir o eliminar coincidencias de entrada

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_add_match(sd_journal *j, const void *data, size_t size);

int sd_journal_add_disjunction(sd_journal *j);

int sd_journal_add_conjunction(sd_journal *j);

void sd_journal_flush_matches(sd_journal *j);

DESCRIPCIÓN

sd_journal_add_match() añade una coincidencia para filtrar las entradas del archivo de registro. Las coincidencias aplicadas con esta llamada filtrarán lo que se puede iterar y leer del archivo de registro a través de llamadas como sd_journal_next(3) y sd_journal_get_data(3). El parámetro data debe tener el formato "CAMPO=valor", donde la parte CAMPO es una cadena corta en mayúsculas que consiste únicamente en 0–9, A–Z y el guion bajo; no puede comenzar con dos guiones bajos ni ser una cadena vacía. La parte valor puede ser cualquier cosa, incluido binario. El parámetro size especifica el número de bytes en data (es decir, la longitud de CAMPO, más uno, más la longitud de valor). El parámetro size también puede especificarse como 0, en cuyo caso data debe ser una cadena terminada en NUL, y los bytes antes del cero terminador se usan como la coincidencia.

Si se aplica una coincidencia, solo se iterarán las entradas con este campo establecido. Varias coincidencias pueden estar activas al mismo tiempo: si se aplican a campos diferentes, solo se iterarán las entradas con ambos campos establecidos de esta manera. Si se aplican a los mismos campos, solo se iterarán las entradas donde el campo tome uno de los valores especificados. Los campos conocidos se documentan en systemd.journal-fields(7). Cada vez que se añade una nueva coincidencia, la posición de entrada actual se restablece, y sd_journal_next(3) (o una llamada similar) debe ser llamada antes de que las entradas puedan ser leídas nuevamente.

sd_journal_add_disjunction() puede usarse para insertar una disyunción (es decir, OR lógico) en la lista de coincidencias. Si se invoca esta llamada, todas las coincidencias añadidas previamente desde la última invocación de sd_journal_add_disjunction() o sd_journal_add_conjunction() se combinan en un OR con todas las coincidencias añadidas posteriormente, hasta que sd_journal_add_disjunction() o sd_journal_add_conjunction() se invoque de nuevo para comenzar el siguiente término OR o AND.

sd_journal_add_conjunction() puede usarse para insertar una conjunción (es decir, AND lógico) en la lista de coincidencias. Si se invoca esta llamada, todas las coincidencias añadidas previamente desde la última invocación de sd_journal_add_conjunction() se combinan en un AND con todas las coincidencias añadidas posteriormente, hasta que sd_journal_add_conjunction() se invoque de nuevo para comenzar el siguiente término AND. La combinación de sd_journal_add_match(), sd_journal_add_disjunction() y sd_journal_add_conjunction() puede usarse para construir términos de búsqueda complejos, aunque no se dispone de expresiones lógicas completas. Tenga en cuenta que sd_journal_add_conjunction() opera un nivel 'más alto' que sd_journal_add_disjunction(). Por lo tanto, es posible construir una expresión de términos AND, que consisten en términos OR, que consisten en términos AND, que consisten en términos OR de coincidencias (esta última expresión OR se crea implícitamente para coincidencias con el mismo nombre de campo, ver arriba).

sd_journal_flush_matches() puede usarse para eliminar todas las coincidencias y términos de disyunción y conjunción nuevamente. Después de esta llamada, se elimina todo el filtrado y se iterarán todas las entradas del registro.

Tenga en cuenta que el filtrado a través de coincidencias solo se aplica a la forma en que se lee el registro, no tiene ningún efecto sobre el almacenamiento en disco.

VALOR DE RETORNO

sd_journal_add_match(), sd_journal_add_disjunction() y sd_journal_add_conjunction() devuelven 0 en caso de éxito o un código de error negativo en estilo errno. sd_journal_flush_matches() no devuelve nada.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para multihilo. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

EJEMPLOS

El siguiente ejemplo añade coincidencias a un objeto de contexto de registro para iterar solo a través de los mensajes generados por el servicio Avahi en los cuatro niveles de registro de errores, más todos los mensajes con el ID de mensaje 03bb1dab98ab4ecfbf6fff2738bdd964 provenientes de cualquier servicio (este ejemplo carece de la comprobación de errores necesaria):

...
int add_matches(sd_journal *j) {
  sd_journal_add_match(j, "_SYSTEMD_UNIT=avahi-daemon.service", 0);
  sd_journal_add_match(j, "PRIORITY=0", 0);
  sd_journal_add_match(j, "PRIORITY=1", 0);
  sd_journal_add_match(j, "PRIORITY=2", 0);
  sd_journal_add_match(j, "PRIORITY=3", 0);
  sd_journal_add_disjunction(j);
  sd_journal_add_match(j, "MESSAGE_ID=03bb1dab98ab4ecfbf6fff2738bdd964", 0);
}

HISTORIA

sd_journal_add_match(), sd_journal_add_disjunction() y sd_journal_flush_matches() se añadieron en la versión 187.

sd_journal_add_conjunction() se añadió en la versión 202.
