DESCRIPCIÓN

sd_event_add_time() añade una nueva fuente de eventos de temporizador a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro clock toma un identificador de reloj, uno de CLOCK_REALTIME, CLOCK_MONOTONIC, CLOCK_BOOTTIME, CLOCK_REALTIME_ALARM, o CLOCK_BOOTTIME_ALARM. Consulte timerfd_create(2) para obtener más detalles sobre los diversos tipos de relojes. El parámetro usec especifica el momento más temprano, en microsegundos (µs), relativo a la época del reloj, en que el temporizador se disparará. Si se especifica un tiempo ya pasado (incluido 0), esta fuente de temporizador se "dispara" inmediatamente y está lista para ser despachada. Si el parámetro se especifica como UINT64_MAX el evento del temporizador nunca transcurrirá, lo que puede usarse como alternativa para deshabilitar explícitamente una fuente de eventos de temporizador con sd_event_source_set_enabled(3). El parámetro accuracy especifica un valor de precisión adicional en µs indicando cuánto puede retrasarse el evento del temporizador. Use 0 para seleccionar la precisión por defecto (250ms). Use 1µs para máxima precisión. Considere especificar 60000000µs (1min) o más para eventos de larga duración que puedan retrasarse considerablemente. Elegir valores de precisión más altos permite al sistema agrupar eventos de temporizador de forma más agresiva, mejorando la eficiencia energética.

El handler es una función a llamar cuando el temporizador transcurre o NULL. El puntero userdata se pasará a la función handler, y puede ser elegido libremente por el llamador. El tiempo de disparo configurado también se pasa al handler, incluso si la llamada ocurre en realidad un poco más tarde, sujeto al valor de precisión especificado, el retardo del temporizador del kernel (ver prctl(2)), y latencias de programación adicionales. Para consultar el tiempo real en que se llamó al handler use sd_event_now(3). El handler puede devolver negativo para señalar un error (ver abajo), otros valores de retorno se ignoran. Si handler es NULL, se usará un handler por defecto que llama a sd_event_exit(3).

Por defecto, el temporizador transcurrirá una vez ( SD_EVENT_ONESHOT), pero esto puede cambiarse con sd_event_source_set_enabled(3). Si la función handler devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si se solicitó el modo SD_EVENT_ON antes, o provocará que el bucle termine, ver sd_event_source_set_exit_on_failure(3). Tenga en cuenta que un evento de temporizador configurado como SD_EVENT_ON se disparará continuamente a menos que su tiempo configurado se actualice usando sd_event_source_set_time().

sd_event_add_time_relative() es similar a sd_event_add_time(), pero toma una especificación de tiempo relativa. Es relativa al tiempo actual de la iteración del bucle de eventos, tal como lo devuelve sd_event_now(3).

Para destruir un objeto de fuente de eventos use sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se sueltan todas las referencias a la fuente de eventos. Para asegurarse de que una fuente de eventos no se dispare más, incluso si todavía se hace referencia a ella, deshabilite la fuente de eventos usando sd_event_source_set_enabled(3) con SD_EVENT_OFF.

Si el segundo parámetro de sd_event_add_time() es NULL, no se devuelve ninguna referencia al objeto de fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando el propio bucle de eventos sea destruido.

Si el parámetro handler para sd_event_add_time() es NULL, y la fuente de eventos se dispara, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a entero, se pasa como parámetro de código de salida a sd_event_exit(3).

Utilice CLOCK_BOOTTIME_ALARM y CLOCK_REALTIME_ALARM para definir fuentes de eventos que puedan despertar al sistema de la suspensión.

Para configurar temporizadores relativos (es decir, relativos al tiempo actual), obtenga el tiempo actual a través de sd_event_now(3), sume el lapso de tiempo deseado a él, y use el resultado como parámetro usec para sd_event_add_time().

Para configurar temporizadores repetitivos (es decir, temporizadores que se disparan en intervalos regulares), configure el temporizador normalmente, para la primera invocación. Cada vez que se invoca la función handler del evento, actualice el tiempo de disparo del temporizador con sd_event_source_set_time(3) para la próxima iteración del temporizador, y reactive el temporizador usando sd_event_source_set_enabled(). Para calcular el próximo punto en el tiempo a pasar a sd_event_source_set_time(), use como base el parámetro usec pasado al callback del temporizador, o la marca de tiempo devuelta por sd_event_now(). En el primer caso, los eventos del temporizador serán regulares, mientras que en el segundo caso, la latencia de programación seguirá acumulándose en el temporizador.

sd_event_source_get_time() recupera el valor de tiempo configurado de una fuente de eventos creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar el tiempo, relativo a la época del reloj seleccionado, en µs. El valor devuelto es relativo a la época, incluso si la fuente de eventos se creó con un tiempo relativo a través de sd_event_add_time_relative().

sd_event_source_set_time() cambia el tiempo de una fuente de eventos creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de eventos y un tiempo relativo a la época del reloj seleccionado, en µs.

sd_event_source_set_time_relative() es similar a sd_event_source_set_time(), pero toma un tiempo relativo al tiempo actual de la iteración del bucle de eventos, tal como lo devuelve sd_event_now().

sd_event_source_get_time_accuracy() recupera el valor de precisión configurado de una fuente de eventos creada previamente con sd_event_add_time(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar la precisión. La precisión se especifica en µs.

sd_event_source_set_time_accuracy() cambia la precisión configurada de una fuente de eventos de temporizador

DESCRIPTION

These functions are used to add and manage timer event sources. A timer event source is triggered when a specific time is reached or after a relative delay has passed. The event loop will call the specified handler function handler when the timer expires.

sd_event_add_time() añade un nuevo evento de tiempo al bucle de eventos event. El evento se activará en el tiempo absoluto especificado por ts, utilizando el reloj especificado por clock. El parámetro delta especifica el tiempo de anticipación en el que el evento debería ser activado; esto es útil para la precisión y la gestión de retrasos. Si delta es cero, el evento se activará tan pronto como sea posible después de ts. Si source no es NULL, se apuntará a la nueva fuente de evento.

sd_event_add_time_relative() es similar a sd_event_add_time(), pero delta especifica un tiempo relativo (un retraso) desde el momento actual en que el evento se activará. ts se ignora.

sd_event_source_set_time() modifica la hora de activación de una fuente de evento de tiempo existente source para que sea la hora absoluta especificada por ts.

sd_event_source_set_time_relative() modifica el retraso relativo de una fuente de evento de tiempo existente source para que sea el retraso especificado por delta.

sd_event_source_get_time() recupera la hora de activación configurada de una fuente de evento de tiempo. El tiempo se devuelve en ts.

sd_event_source_set_time_accuracy() establece la precisión deseada para la activación de la fuente de evento de tiempo source. El parámetro accuracy debe ser un valor de struct timespec que represente la diferencia máxima permitida desde la hora de activación deseada. Esto puede ser útil para ahorrar energía en sistemas que lo soporten, ya que permite agrupar temporizadores con tiempos de activación similares. El valor por defecto es cero, lo que significa que no hay precisión deseada y el evento se activará exactamente a la hora especificada.

sd_event_source_get_time_accuracy() recupera la precisión configurada de una fuente de evento de tiempo creada previamente con sd_event_add_time(). Toma el objeto de la fuente de evento y un puntero a una variable para almacenar la precisión en.

sd_event_source_get_time_clock() recupera el reloj configurado de una fuente de evento creada previamente con sd_event_add_time(). Toma el objeto de la fuente de evento y un puntero a una variable para almacenar el identificador del reloj.

RETURN VALUE

Al tener éxito, estas funciones devuelven 0 o un entero positivo. Al fallar, devuelven un código de error negativo de estilo errno.

Errors

Los valores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento inválido.

-ESTALE

El bucle de eventos ya ha sido terminado.

-ECHILD

El bucle de eventos se creó en un proceso, biblioteca o instancia de módulo diferente.

-EOPNOTSUPP

El bucle de eventos no soporta el reloj seleccionado.

-EDOM

La fuente de evento proporcionada no es una fuente de evento de temporizador.

-EOVERFLOW

El tiempo relativo proporcionado está fuera del rango permitido para los valores de tiempo (es decir, el valor especificado sumado al tiempo actual está fuera del rango del entero sin signo de 64 bits).

Añadido en la versión 247.

NOTES

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer las llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
