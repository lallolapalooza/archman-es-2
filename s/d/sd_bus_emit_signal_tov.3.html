DESCRIPCIÓN

sd_bus_emit_signal() es una función de conveniencia para inicializar un objeto de mensaje de bus y emitir la señal D-Bus correspondiente. Combina las funciones sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) en una única llamada a función. sd_bus_emit_signalv() es equivalente a sd_bus_message_append(), excepto que se llama con una lista "va_list" en lugar de un número variable de argumentos.

sd_bus_emit_signal_to() y sd_bus_emit_signal_tov() son idénticas a sd_bus_emit_signal() y sd_bus_emit_signalv(), excepto que pueden emitir la señal a un único destino. Proporcione destination como NULL para transmitir la señal.

sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() se utilizan para implementar las señales InterfacesAdded y InterfacesRemoved de la interfaz org.freedesktop.DBus.ObjectManager. Toman una ruta de objeto cuyos interfaces han sido modificadas como argumento y una lista variable de interfaces que se han añadido o eliminado, respectivamente. El último argumento pasado a sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() *debe* ser NULL. Esto permite que ambas funciones determinen de forma segura el número de argumentos de interfaz pasados. sd_bus_emit_interfaces_added_strv() y sd_bus_emit_interfaces_removed_strv() son idénticas a sus contrapartes respectivas pero ambas toman la lista de interfaces como un solo argumento en lugar de un número variable de argumentos.

sd_bus_emit_properties_changed() se utiliza para implementar la señal PropertiesChanged de la interfaz org.freedesktop.DBus.Properties. Toma una ruta de objeto, una interfaz y una lista variable de nombres de propiedades como argumentos. El último argumento pasado a sd_bus_emit_properties_changed() *debe* ser NULL. Esto le permite determinar de forma segura el número de nombres de propiedad pasados. sd_bus_emit_properties_changed_strv() es idéntica a sd_bus_emit_properties_changed() pero toma la lista de nombres de propiedad como un solo argumento en lugar de un número variable de argumentos.

sd_bus_emit_object_added() y sd_bus_emit_object_removed() son funciones de conveniencia para emitir las señales InterfacesAdded o InterfacesRemoved para todas las interfaces registradas en una ruta de objeto específica, respectivamente. Esto incluye cualquier vtable de respaldo padre si no son anuladas por una vtable hija más aplicable. También incluye todas las interfaces D-Bus estándar implementadas por el propio sd-bus en cualquier objeto registrado.

Tenga en cuenta que sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() y sd_bus_emit_object_removed() requieren que se haya registrado un gestor de objetos en la ruta de objeto dada o en una de sus rutas de objeto padre utilizando sd_bus_add_object_manager(3).

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un entero no negativo. En caso de error, devuelven un código de error negativo al estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Uno de los parámetros requeridos es NULL o inválido. Se pasó una interfaz D-Bus reservada como parámetro interface.

-ENOPKG

El bus no se puede resolver.

-ECHILD

El bus se creó en un proceso, biblioteca o instancia de módulo diferente.

-ENOMEM

Falló la asignación de memoria.

-ESRCH

Se llamó a una de las funciones sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() o sd_bus_emit_object_removed() en un objeto sin un gestor de objetos registrado en su propia ruta de objeto o en una de sus rutas de objeto padre.

Consulte las páginas del manual de sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) para ver errores más posibles.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y vincular con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

DESCRIPTION

These functions may be used to emit signals and property change notifications on the D-Bus. They are wrappers around sd_bus_message_new_signal(3), sd_bus_message_append(3), and sd_bus_send(3).

sd_bus_emit_signal(), sd_bus_emit_signalv(), sd_bus_emit_signal_strv(), and sd_bus_emit_signal_tov() all emit a D-Bus signal. The signal is identified by the path, interface, and member parameters. The types string describes the types of the arguments that follow. The arguments themselves are then passed as variadic arguments (for sd_bus_emit_signal()), a va_list (for sd_bus_emit_signalv() and sd_bus_emit_signal_tov()), or a NULL-terminated array of strings (for sd_bus_emit_signal_strv()).

sd_bus_emit_properties_changed(), sd_bus_emit_properties_changed_strv(), sd_bus_emit_interfaces_removed(), and sd_bus_emit_interfaces_removed_strv() emit a org.freedesktop.DBus.Properties.PropertiesChanged or org.freedesktop.DBus.ObjectManager.InterfacesRemoved signal, respectively. The path parameter specifies the object whose properties are being changed or whose interfaces are being removed. The interface parameter specifies the interface whose properties are being changed or removed. For sd_bus_emit_properties_changed() and sd_bus_emit_interfaces_removed(), the changed or removed properties/interfaces are passed as variadic arguments. For sd_bus_emit_properties_changed_strv() and sd_bus_emit_interfaces_removed_strv(), they are passed as a NULL-terminated array of strings.

sd_bus_emit_object_added() and sd_bus_emit_object_removed() emit org.freedesktop.DBus.ObjectManager.InterfacesAdded and org.freedesktop.DBus.ObjectManager.InterfacesRemoved signals, respectively. The path parameter identifies the object.

RETURN VALUE

On success, these functions return 0 or a positive integer. On failure, they return a negative error number.

NOTES

These functions are convenience wrappers and may not expose all features of the underlying D-Bus message API. For more complex scenarios, use sd_bus_message_new_signal(3) directly.

The types string must be a valid D-Bus type string. See sd_bus_message_append(3) for details.

For sd_bus_emit_properties_changed(), sd_bus_emit_interfaces_removed(), the variadic arguments should be pairs of property names (or interface names for InterfacesRemoved) and their values (or NULL for removed interfaces). The list must be terminated by a NULL pointer.

For sd_bus_emit_properties_changed_strv() and sd_bus_emit_interfaces_removed_strv(), the strv array must contain alternating property names (or interface names) and their values (or NULL), and must be terminated by a NULL pointer.
