int sd_path_lookup(uint64_t type, const char *suffix, char **paths);

int sd_path_lookup_strv(uint64_t type, const char *suffix, char ***paths);

DESCRIPCIÓN

sd_path_lookup() y sd_bus_path_lookup_strv() devuelven una ruta única o un conjunto de rutas de sistema de archivos especificadas por el argumento type. En el caso de sd_path_lookup() se devuelve una única cadena terminada en NUL. Cuando type especifica un conjunto de rutas, estas se concatenan usando ":" como separador (como se hace tradicionalmente para, por ejemplo, $PATH o $LD_LIBRARY_PATH). En el caso de sd_path_lookup_strv() se devuelve una matriz de cadenas terminada en NULL (strv). Si se proporciona el sufijo suffix, se concatena a cada una de las rutas después de una barra ("/"). Todas las rutas devueltas son absolutas.

Para las rutas que se refieren a directorios de usuario, se sigue el estándar XDG relevante, con soporte para variables de entorno como $XDG_DOCUMENTS_DIR, $XDG_DESKTOP_DIR, ..., y configuración explícita en /etc/xdg/user-dirs.conf o ${XDG_CONFIG_HOME}/user-dirs.dirs. Consulte la Especificación de directorios base de XDG[1] para obtener más detalles.

systemd-path(1) es un envoltorio alrededor de sd_path_lookup() y permite consultar el mismo conjunto de rutas.

VALOR DE RETORNO

En caso de éxito, sd_path_lookup() y sd_path_lookup_strv() devuelven un entero no negativo. En caso de fallo, cualquiera de las funciones devuelve un número de error negativo estilo errno.

La cadena o matriz de cadenas (strv) devuelta debe ser liberada con free(3) por el llamador.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EOPNOTSUPP

Identificador type desconocido.

Añadido en la versión 246.

-EINVAL

El argumento de salida es NULL.

Añadido en la versión 246.

-ENXIO

La consulta falló debido a una variable de entorno indefinida (por ejemplo, para SD_PATH_USER_RUNTIME cuando $XDG_RUNTIME_DIR no está definida).

Añadido en la versión 246.

-ENOMEM

Fallo en la asignación de memoria.

Añadido en la versión 246.

EJEMPLOS

Buscar la ubicación de ~/Documents

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <stdlib.h>
#include <systemd/sd-path.h>
int main(void) {
  int r;
  char *t;
  r = sd_path_lookup(SD_PATH_USER_DOCUMENTS, NULL, &t);
  if (r < 0)
    return EXIT_FAILURE;
  printf("~/Documents: %s\n", t);
  free(t);
  return EXIT_SUCCESS;
}

Tenga en cuenta que la respuesta predeterminada $HOME/Documents puede ser anulada por user-dirs.conf o $XDG_DOCUMENTS_DIR.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un subproceso paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros subprocesos.

HISTORIA

sd_path_lookup() y sd_path_lookup_strv() se añadieron en la versión 246.
