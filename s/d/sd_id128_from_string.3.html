sd_id128_from_string(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_ID128_TO_STRING(3) sd_id128_to_string SD_ID128_TO_STRING(3)

NOMBRE

sd_id128_to_string, SD_ID128_TO_STRING, SD_ID128_STRING_MAX, sd_id128_to_uuid_string, SD_ID128_TO_UUID_STRING, SD_ID128_UUID_STRING_MAX, sd_id128_from_string - Formatear o analizar IDs de 128 bits como cadenas

SINOPSIS

#include <systemd/sd-id128.h>
#define SD_ID128_STRING_MAX 33U
#define SD_ID128_UUID_STRING_MAX 37U
#define SD_ID128_TO_STRING(id) ...
#define SD_ID128_TO_UUID_STRING(id) ...

char *sd_id128_to_string(sd_id128_t id, char s[static SD_ID128_STRING_MAX]);

char *sd_id128_to_uuid_string(sd_id128_t id, char s[static SD_ID128_UUID_STRING_MAX]);

int sd_id128_from_string(const char *s, sd_id128_t *ret);

DESCRIPCIÓN

sd_id128_to_string() formatea un ID de 128 bits como una cadena de caracteres. Espera el ID y un array de cadenas capaz de almacenar 33 caracteres (SD_ID128_STRING_MAX). El ID se formateará como 32 dígitos hexadecimales en minúsculas y se terminará con un byte NUL.

SD_ID128_TO_STRING() es una macro que envuelve a sd_id128_to_string() y pasa un buffer de tamaño adecuado como segundo argumento, asignado como una construcción literal C99. Cada uso adquirirá implícitamente un buffer adecuado en la pila que permanecerá válido hasta el final del bloque de código actual. Esta suele ser la forma más sencilla de obtener una representación en cadena de un ID de 128 bits en un buffer válido en el bloque de código actual.

sd_id128_to_uuid_string() y SD_ID128_TO_UUID_STRING() son similares a estas dos funciones/macros, pero formatean los valores de 128 bits como UUIDs RFC4122, es decir, una serie de 36 dígitos hexadecimales en minúsculas y guiones, terminados por un byte NUL.

sd_id128_from_string() implementa la operación inversa: toma una cadena de 33 caracteres con 32 dígitos hexadecimales (en minúsculas o mayúsculas, terminada en NUL) y los analiza de nuevo en un ID de 128 bits devuelto en ret. Alternativamente, esta llamada también puede analizar una cadena de 37 caracteres con un ID de 128 bits formateado como UUID RFC. Si se pasa ret como NULL, la función validará la cadena de ID proporcionada, pero no la devolverá en formato analizado.

Tenga en cuenta que al formatear y analizar UUIDs de 36 caracteres, esto se hace estrictamente en orden de bytes Big Endian, es decir, de acuerdo con las reglas de la variante 1 de RFC4122[1], incluso si el UUID codifica una variante diferente. Esto coincide con el comportamiento de varias otras herramientas del espacio de usuario de Linux. Probablemente sea prudente evitar UUIDs de otros tipos de variante.

Para más información sobre el tipo "sd_id128_t", consulte sd-id128(3). Tenga en cuenta que estas llamadas operan de la misma manera en todas las arquitecturas, es decir, los resultados no dependen del endianness.

Al formatear un ID de 128 bits en una cadena, a menudo es más fácil usar una cadena de formato para printf(3). Esto se hace fácilmente utilizando las macros SD_ID128_FORMAT_STR y SD_ID128_FORMAT_VAL(). Para más información, consulte sd-id128(3).

VALOR DE RETORNO

sd_id128_to_string() siempre tiene éxito y devuelve un puntero a la matriz de cadenas pasada. sd_id128_from_string() devuelve 0 en caso de éxito, en cuyo caso ret se rellena, o un código de error negativo de estilo errno.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para múltiples hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

sd_id128_to_string() y sd_id128_from_string() se añadieron en la versión 187.

sd_id128_to_uuid_string() se añadió en la versión 251.
