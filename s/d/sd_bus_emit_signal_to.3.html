NOMBRE

sd_bus_emit_signal, sd_bus_emit_signalv, sd_bus_emit_signal_to, sd_bus_emit_signal_tov, sd_bus_emit_interfaces_added, sd_bus_emit_interfaces_added_strv, sd_bus_emit_interfaces_removed, sd_bus_emit_interfaces_removed_strv, sd_bus_emit_properties_changed, sd_bus_emit_properties_changed_strv, sd_bus_emit_object_added, sd_bus_emit_object_removed - Funciones de conveniencia para emitir señales (estándar) de D-Bus

#include <systemd/sd-bus-vtable.h>

int sd_bus_emit_signal(sd_bus *bus, const char *path, const char *interface, const char *member, const char *types, ...);

int sd_bus_emit_interfaces_removed_strv(sd_bus *bus, const char *path, char **interfaces);

int sd_bus_emit_object_removed(sd_bus *bus, const char *path);

DESCRIPCIÓN

sd_bus_emit_signal() es una función de conveniencia para inicializar un objeto de mensaje de bus y emitir la señal D-Bus correspondiente. Combina las funciones sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) en una única llamada a función. sd_bus_emit_signalv() es equivalente a sd_bus_message_append(), excepto que se llama con una lista "va_list" en lugar de un número variable de argumentos.

sd_bus_emit_signal_to() y sd_bus_emit_signal_tov() son idénticas a sd_bus_emit_signal() y sd_bus_emit_signalv(), excepto que pueden emitir la señal a un único destino. Proporcione destination como NULL para transmitir la señal en difusión.

sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() se utilizan para implementar las señales InterfacesAdded y InterfacesRemoved de la interfaz org.freedesktop.DBus.ObjectManager. Toman como argumento una ruta de objeto cuyas interfaces han sido modificadas y una lista variable de interfaces que se han añadido o eliminado, respectivamente. El argumento final pasado a sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() *debe* ser NULL. Esto permite que ambas funciones determinen de forma segura el número de argumentos de interfaz pasados. sd_bus_emit_interfaces_added_strv() y sd_bus_emit_interfaces_removed_strv() son idénticas a sus homólogas respectivas, pero ambas toman la lista de interfaces como un único argumento en lugar de un número variable de argumentos.

sd_bus_emit_properties_changed() se utiliza para implementar la señal PropertiesChanged de la interfaz org.freedesktop.DBus.Properties. Toma como argumentos una ruta de objeto, una interfaz y una lista variable de nombres de propiedades. El argumento final pasado a sd_bus_emit_properties_changed() *debe* ser NULL. Esto permite determinar de forma segura el número de nombres de propiedades pasados. sd_bus_emit_properties_changed_strv() es idéntica a sd_bus_emit_properties_changed() pero toma la lista de nombres de propiedades como un único argumento en lugar de un número variable de argumentos.

sd_bus_emit_object_added() y sd_bus_emit_object_removed() son funciones de conveniencia para emitir las señales InterfacesAdded o InterfacesRemoved para todas las interfaces registradas en una ruta de objeto específica, respectivamente. Esto incluye cualquier vtable de respaldo padre si no son anuladas por una vtable hija más aplicable. También incluye todas las interfaces estándar de D-Bus implementadas por el propio sd-bus en cualquier objeto registrado.

Tenga en cuenta que sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() y sd_bus_emit_object_removed() requieren que se haya registrado un gestor de objetos en la ruta de objeto dada o en una de sus rutas de objeto padre utilizando sd_bus_add_object_manager(3).

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un entero no negativo. En caso de error, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Uno de los parámetros requeridos es NULL o inválido. Se pasó una interfaz D-Bus reservada como parámetro interface.

-ENOPKG

El bus no se puede resolver.

-ECHILD

El bus se creó en un proceso, biblioteca o instancia de módulo diferente.

-ENOMEM

Fallo en la asignación de memoria.

-ESRCH

Se llamó a uno de sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() o sd_bus_emit_object_removed() en un objeto sin un gestor de objetos registrado en su propia ruta de objeto o en una de sus rutas de objeto padre.

Consulte las páginas man de sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) para ver posibles errores adicionales.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

DESCRIPTION

These functions may be used to emit D-Bus signals.

The functions sd_bus_emit_signal_to and sd_bus_emit_signal_tov emit a signal to a specific destination. The signal is identified by the destination bus name, object path, interface name, and member name. The types string describes the types of the arguments that follow (or are in the va_list for sd_bus_emit_signal_tov), using the standard D-Bus type specifiers. The arguments themselves follow the types string in the case of sd_bus_emit_signal_to.

The functions sd_bus_emit_object_added and sd_bus_emit_object_removed emit the org.freedesktop.DBus.ObjectManager.ObjectAdded and org.freedesktop.DBus.ObjectManager.ObjectRemoved signals, respectively. These signals are used by the D-Bus Object Manager specification (org.freedesktop.DBus.ObjectManager(5)).

The function sd_bus_emit_properties_changed emits the org.freedesktop.DBus.Properties.PropertiesChanged signal. This signal is emitted when one or more properties of an object change. The path and interface parameters specify the object and interface whose properties have changed. The properties that have changed are described in the message body. The actual properties and their new values are not directly passed to this function, but are rather expected to be serialized into the outgoing message by the D-Bus implementation. If error is not NULL, it will be filled with a sd_bus_error in case of an error.

The function sd_bus_emit_properties_changed_strv is similar to sd_bus_emit_properties_changed, but it takes an array of strings properties, where each string is a property name that has changed. The D-Bus implementation will then serialize the property names into the message body.

The function sd_bus_emit_interfaces_removed emits the org.freedesktop.DBus.ObjectManager.InterfacesRemoved signal. This signal is emitted when one or more interfaces are removed from an object. The path and interface parameters specify the object and the first interface that was removed. The remaining interfaces that were removed are described in the message body.

The function sd_bus_emit_interfaces_removed_strv is similar to sd_bus_emit_interfaces_removed, but it takes an array of strings interfaces, where each string is an interface name that has been removed from the object specified by path. The D-Bus implementation will then serialize the interface names into the message body.

The function sd_bus_emit_signalv emits a signal to all destinations. It is similar to sd_bus_emit_signal_tov, but without the destination parameter.

RETURN VALUE

On success, these functions return a non-negative integer. On failure, they return a negative errno code.

NOTES

These functions are convenience wrappers around lower-level functions like sd_bus_message_new_signal(3), sd_bus_message_append(3), and sd_bus_send(3).

For the sd_bus_emit_properties_changed and sd_bus_emit_properties_changed_strv functions, the properties and their values are not directly passed to the function. Instead, the D-Bus implementation automatically serializes the property names and their current values into the outgoing message body. This means that the object must be properly implemented to provide this information when requested.

The org.freedesktop.DBus.ObjectManager interface is a standard D-Bus interface that allows clients to discover and manage objects and their properties on a remote service. Services that implement this interface need to emit the corresponding signals when objects or interfaces are added or removed, or when properties change.
