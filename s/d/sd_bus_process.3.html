SD_BUS_PROCESS(3) sd_bus_process SD_BUS_PROCESS(3)

NOMBRE

sd_bus_process - Impulsar la conexión

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_process(sd_bus *bus, sd_bus_message **ret);

DESCRIPCIÓN

sd_bus_process() impulsa la conexión entre el cliente y el bus de mensajes. Es decir, se encarga de la conexión, la autenticación y el procesamiento de mensajes. Cuando se invoca, se ejecuta el trabajo de E/S pendiente y los mensajes entrantes en cola se despachan a las llamadas a funciones registradas. Cada vez que se invoca, se ejecuta una única operación. Devuelve cero cuando no había operaciones pendientes y un valor positivo si se procesó un mensaje. Cuando se devuelve cero, el llamador debe esperar eventos de E/S antes de volver a llamar a sd_bus_process(). Para ello, utilice la llamada simple y bloqueante sd_bus_wait(3), o enganche el objeto de conexión del bus a un bucle de eventos externo o manual utilizando sd_bus_get_fd(3).

sd_bus_process() procesa como máximo un mensaje entrante por llamada. Si el parámetro ret no es NULL y la llamada procesó un mensaje, *ret se establece en este mensaje. El llamador es propietario de una referencia a este mensaje y debe llamar a sd_bus_message_unref(3) cuando el mensaje ya no sea necesario. Si ret no es NULL y se avanzó, pero no se procesó ningún mensaje, *ret se establece en NULL. Tenga en cuenta que solo los mensajes que no hayan sido manejados por los diversos tipos de manejadores de mensajes registrados (es decir, por filtros registrados a través de sd_bus_add_filter(3), manejadores de objetos registrados a través de sd_bus_add_object(3), coincidencias registradas a través de sd_bus_add_match(3) y relacionados) se devolverán a través de este parámetro. Tenga en cuenta también que si dicho manejador de mensajes devuelve un valor cero (en contraposición a algún valor > 0), un mensaje entrante no se considerará manejado y se pasará a otros manejadores adecuados (hasta que uno devuelva > > 0), o será devuelto por sd_bus_process() (en caso de que ninguno devuelva > 0).

Si el objeto del bus está conectado a un bucle de eventos sd-event(3) (con sd_bus_attach_event(3)), no es necesario llamar directamente a sd_bus_process(), ya que se invoca automáticamente cuando sea necesario.

VALOR DE RETORNO

Si se realizó progreso, se devuelve un entero positivo. Si no se realizó progreso, se devuelve 0. Si ocurre un error, se devuelve un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Se pasó un objeto de bus inválido.

-ECHILD

La conexión del bus se asignó en un proceso padre y se está reutilizando en un proceso hijo después de fork().

-ENOTCONN

La conexión del bus ya ha sido terminada.

-ECONNRESET

La conexión del bus ha sido terminada hace poco.

-EBUSY

Esta función ya se está llamando, es decir, sd_bus_process() ha sido llamada desde una función de devolución de llamada que a su vez fue llamada por sd_bus_process().

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para múltiples hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar solo llamadas a setenv() desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

sd_bus_process() se añadió en la versión 221.
