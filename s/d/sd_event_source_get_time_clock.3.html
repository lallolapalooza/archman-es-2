DESCRIPCIÓN

sd_event_add_time() añade una nueva fuente de evento de temporizador a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de evento se devuelve en el parámetro source. El parámetro clock toma un identificador de reloj, uno de CLOCK_REALTIME, CLOCK_MONOTONIC, CLOCK_BOOTTIME, CLOCK_REALTIME_ALARM o CLOCK_BOOTTIME_ALARM. Véase timerfd_create(2) para detalles sobre los varios tipos de relojes. El parámetro usec especifica la hora más temprana, en microsegundos (μs), relativa a la época del reloj, cuando el temporizador se activará. Si se especifica una hora ya pasada (incluyendo 0), esta fuente de temporizador "se dispara" inmediatamente y está lista para ser despachada. Si el parámetro se especifica como UINT64_MAX, el evento del temporizador nunca expirará, lo que puede usarse como alternativa para deshabilitar explícitamente una fuente de evento de temporizador con sd_event_source_set_enabled(3). El parámetro accuracy especifica un valor de precisión adicional en μs indicando cuánto puede retrasarse el evento del temporizador. Use 0 para seleccionar la precisión por defecto (250ms). Use 1μs para precisión máxima. Considere especificar 60000000μs (1 minuto) o más para eventos de larga duración que puedan retrasarse sustancialmente. Elegir valores de precisión más altos permite al sistema agrupar eventos de temporizador de forma más agresiva, mejorando la eficiencia energética.

El handler es una función a llamar cuando el temporizador expira o NULL. El puntero userdata se pasará a la función handler, y puede ser elegido libremente por el llamador. La hora de activación configurada también se pasa al handler, incluso si la llamada ocurre realmente un poco más tarde, sujeta al valor de precisión especificado, el tiempo de espera del temporizador del kernel (ver prctl(2)), y latencias de planificación adicionales. Para consultar la hora real en que se llamó al handler, use sd_event_now(3). El handler puede devolver negativo para señalar un error (ver abajo), otros valores de retorno se ignoran. Si handler es NULL, se usará un handler por defecto que llama a sd_event_exit(3).

Por defecto, el temporizador expirará una vez (SD_EVENT_ONESHOT), pero esto puede cambiarse con sd_event_source_set_enabled(3). Si la función handler devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si se solicitó el modo SD_EVENT_ON antes, o causará que el bucle termine, ver sd_event_source_set_exit_on_failure(3). Tenga en cuenta que un evento de temporizador configurado como SD_EVENT_ON se disparará continuamente a menos que su hora configurada se actualice usando sd_event_source_set_time().

sd_event_add_time_relative() es como sd_event_add_time(), pero toma una especificación de hora relativa. Es relativa a la hora actual de la iteración del bucle de eventos, como la devuelta por sd_event_now(3).

Para destruir un objeto de fuente de evento, use sd_event_source_unref(3), pero tenga en cuenta que la fuente de evento solo se elimina del bucle de eventos cuando se sueltan todas las referencias a la fuente de evento. Para asegurarse de que una fuente de evento no se dispare más, incluso si todavía está referenciada, deshabilite la fuente de evento usando sd_event_source_set_enabled(3) con SD_EVENT_OFF.

Si el segundo parámetro de sd_event_add_time() es NULL, no se devuelve ninguna referencia al objeto de la fuente de evento. En este caso, la fuente de evento se considera "flotante" y se destruirá implícitamente cuando se destruya el propio bucle de eventos.

Si el parámetro handler de sd_event_add_time() es NULL, y la fuente de evento se dispara, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a entero, se pasa como parámetro de código de salida a sd_event_exit(3).

Use CLOCK_BOOTTIME_ALARM y CLOCK_REALTIME_ALARM para definir fuentes de evento que puedan despertar al sistema de la suspensión.

Para configurar temporizadores relativos (es decir, relativos a la hora actual), obtenga la hora actual a través de sd_event_now(3), sume el intervalo de tiempo deseado y use el resultado como parámetro usec para sd_event_add_time().

Para configurar temporizadores repetitivos (es decir, temporizadores que se activan en intervalos regulares), configure el temporizador normalmente, para la primera invocación. Cada vez que se invoca el manejador de eventos, actualice la hora de activación del temporizador con sd_event_source_set_time(3) para la próxima iteración del temporizador, y reactive el temporizador usando sd_event_source_set_enabled(). Para calcular el próximo punto en el tiempo a pasar a sd_event_source_set_time(), use como base el parámetro usec pasado al callback del temporizador, o la marca de tiempo devuelta por sd_event_now(). En el primer caso, los eventos del temporizador serán regulares, mientras que en el segundo caso, la latencia de planificación seguirá acumulándose en el temporizador.

sd_event_source_get_time() recupera el valor de tiempo configurado de una fuente de evento creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de evento y un puntero a una variable para almacenar el tiempo, relativo a la época del reloj seleccionado, en μs. El valor devuelto es relativo a la época, incluso si la fuente de evento se creó con un tiempo relativo a través de sd_event_add_time_relative().

sd_event_source_set_time() cambia la hora de una fuente de evento creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de evento y un tiempo relativo a la época del reloj seleccionado, en μs.

sd_event_source_set_time_relative() es similar a sd_event_source_set_time(), pero toma un tiempo relativo a la hora actual de la iteración del bucle de eventos, como la devuelta por sd_event_now().

sd_event_source_get_time_accuracy() recupera el valor de precisión configurado de una fuente de evento creada previamente con sd_event_add_time(). Toma el objeto de la fuente de evento y un puntero a una variable para almacenar la precisión. La precisión se especifica en μs.

sd_event_source_set_time_accuracy() cambia la precisión configurada de un evento de temporizador

DESCRIPCIÓN

Estas funciones programan un evento para que ocurra en un momento determinado en el futuro. El momento se define en relación con el reloj especificado por clock. El valor usec es el tiempo absoluto en microsegundos desde el inicio de la época del reloj.

El argumento clock debe ser uno de los identificadores de reloj definidos en clock_gettime(2), como CLOCK_REALTIME o CLOCK_MONOTONIC. Tenga en cuenta que el reloj CLOCK_MONOTONIC es preferible para la programación de intervalos de tiempo, ya que no se ve afectado por cambios en la hora del sistema.

El argumento accuracy_usec define la precisión deseada para la activación del temporizador en microsegundos. El sistema intentará activar el temporizador dentro de esta ventana de tiempo alrededor del tiempo especificado. Un valor de 0 indica que no se requiere ninguna precisión especial.

El argumento handler es un puntero a una función de devolución de llamada que se llamará cuando expire el temporizador. La función de devolución de llamada recibe el objeto de origen del evento, el tiempo actual en microsegundos y los datos de usuario proporcionados. Si la función de devolución de llamada devuelve un valor negativo, se considerará un error y el bucle de eventos se detendrá.

El argumento userdata es un puntero de datos de usuario opcional que se pasará a la función de devolución de llamada.

La función sd_event_add_time programa un evento para que ocurra en un momento absoluto especificado por usec. La función sd_event_add_time_relative programa un evento para que ocurra un intervalo de tiempo especificado por usec después del momento actual.

Las funciones sd_event_source_set_time y sd_event_source_get_time establecen y obtienen el tiempo absoluto objetivo para una fuente de evento existente creada previamente con sd_event_add_time.

Las funciones sd_event_source_set_time_relative y sd_event_source_get_time establecen y obtienen el tiempo relativo objetivo para una fuente de evento existente creada previamente con sd_event_add_time_relative.

Las funciones sd_event_source_set_time_accuracy y sd_event_source_get_time_accuracy establecen y obtienen la precisión configurada de una fuente de evento creada previamente con sd_event_add_time. Toma el objeto de origen del evento y la precisión, en μs.

sd_event_source_get_time_clock() recupera el reloj configurado de una fuente de evento creada previamente con sd_event_add_time(). Toma el objeto de origen del evento y un puntero a una variable para almacenar el identificador del reloj.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo de estilo errno.

Errores

Los valores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento no válido.

-ESTALE

El bucle de eventos ya está terminado.

-ECHILD

El bucle de eventos se ha creado en un proceso, biblioteca o instancia de módulo diferente.

-EOPNOTSUPP

La implementación del bucle de eventos no admite el reloj seleccionado.

-EDOM

La fuente de evento pasada no es una fuente de evento de temporizador.

-EOVERFLOW

El tiempo relativo pasado está fuera del rango permitido para los valores de tiempo (es decir, el valor especificado agregado al tiempo actual está fuera del rango de enteros sin signo de 64 bits).

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar contra y vincular con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
