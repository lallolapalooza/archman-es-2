SD_LOGIN_MONITOR_NEW(3) sd_login_monitor_new SD_LOGIN_MONITOR_NEW(3)

NOMBRE

sd_login_monitor_new, sd_login_monitor_unref, sd_login_monitor_unrefp, sd_login_monitor_flush, sd_login_monitor_get_fd, sd_login_monitor_get_events, sd_login_monitor_get_timeout, sd_login_monitor - Monitorizar inicios de sesión, asientos, usuarios y máquinas virtuales/contenedores

SINOPSIS

#include <systemd/sd-login.h>

int sd_login_monitor_new(const char *category, sd_login_monitor **ret);

sd_login_monitor *sd_login_monitor_unref(sd_login_monitor *m);

void sd_login_monitor_unrefp(sd_login_monitor **m);

int sd_login_monitor_flush(sd_login_monitor *m);

int sd_login_monitor_get_fd(sd_login_monitor *m);

int sd_login_monitor_get_events(sd_login_monitor *m);

int sd_login_monitor_get_timeout(sd_login_monitor *m, uint64_t *timeout_usec);

DESCRIPCIÓN

sd_login_monitor_new() puede ser utilizado para monitorizar inicios de sesión, usuarios, asientos y máquinas virtuales/contenedores. Mediante un objeto monitor, un descriptor de archivo puede ser integrado en un bucle de eventos definido por la aplicación, el cual es activado cada vez que un usuario inicia o cierra sesión, o un asiento es añadido o eliminado, o un inicio de sesión, usuario, asiento o máquina virtual/contenedor cambia de estado. El primer parámetro toma una cadena que puede ser "seat" (para recibir solo notificaciones sobre asientos que son añadidos, eliminados o cambiados), "session" (para recibir solo notificaciones sobre inicios de sesión que son creados, eliminados o cambiados), "uid" (para recibir solo notificaciones cuando un usuario cambia de estado en respecto a los inicios de sesión) o "machine" (para recibir solo notificaciones cuando una máquina virtual o contenedor se inicia o se detiene). Si se deben generar notificaciones en todas estas condiciones, se puede pasar NULL. Tenga en cuenta que en el futuro pueden definirse categorías adicionales. El segundo parámetro devuelve un objeto monitor y necesita ser liberado con la llamada sd_login_monitor_unref() después de su uso.

sd_login_monitor_unref() puede ser utilizado para destruir un objeto monitor. Tenga en cuenta que esto invalidará cualquier descriptor de archivo devuelto por sd_login_monitor_get_fd().

sd_login_monitor_unrefp() es similar a sd_login_monitor_unref() pero toma un puntero a un puntero a un objeto sd_login_monitor. Esta llamada es útil en conjunción con el **Attribute de Variable de Limpieza**[1] de GCC y LLVM. Tenga en cuenta que esta función se define como una función en línea. Use una declaración como la siguiente, para asignar un objeto monitor de inicio de sesión que se libera automáticamente al salir del bloque de código:

{
  __attribute__((cleanup(sd_login_monitor_unrefp))) sd_login_monitor *m = NULL;
  int r;
  ...
  r = sd_login_monitor_new(NULL, &m);
  if (r < 0) {
    errno = -r;
    fprintf(stderr, "Fallo al asignar el objeto monitor de inicio de sesión: %m\n");
  }
  ...
}

sd_login_monitor_flush() puede ser utilizado para resetear el estado de activación del objeto monitor. Cada vez que un evento cause que el monitor active el bucle de eventos a través del descriptor de archivo, esta función debe ser llamada para resetear el estado de activación. Si esta llamada no se invoca, el descriptor de archivo activará inmediatamente de nuevo el bucle de eventos.

sd_login_monitor_unref() y sd_login_monitor_unrefp() no realizan ninguna operación si el objeto monitor pasado es NULL.

sd_login_monitor_get_fd() puede ser utilizado para recuperar el descriptor de archivo del objeto monitor que puede ser integrado en un bucle de eventos definido por la aplicación, basado en poll(2) o una interfaz similar. La aplicación debe incluir el descriptor de archivo devuelto como fuente de activación para la máscara de eventos devuelta por sd_login_monitor_get_events(). Debe pasar un valor de tiempo de espera como el devuelto por sd_login_monitor_get_timeout(). Cada vez que se active una activación, el descriptor de archivo debe ser reseteado a través de sd_login_monitor_flush(). Una aplicación necesita releer el estado de inicio de sesión con una función como sd_get_seats(3) o similar para determinar qué cambió.

sd_login_monitor_get_events() devolverá la máscara de poll() para esperar. Esta función devolverá una combinación de POLLIN, POLLOUT y similares para rellenar el campo ".events" de struct pollfd.

sd_login_monitor_get_timeout() devolverá un valor de tiempo de espera para su uso en poll(). Esto devuelve un valor en microsegundos desde la época de CLOCK_MONOTONIC para el tiempo de espera de poll() en timeout_usec. Véase clock_gettime(2) para detalles sobre CLOCK_MONOTONIC. Si no hay tiempo de espera, esto rellenará (uint64_t) -1 en su lugar. Tenga en cuenta que poll() toma un tiempo de espera relativo en milisegundos en lugar de un tiempo de espera absoluto en microsegundos. Para convertir el tiempo de espera absoluto 'μs' en tiempo de espera relativo 'ms', use código como el siguiente:

uint64_t t;
int msec;
sd_login_monitor_get_timeout(m, &t);
if (t == (uint64_t) -1)
  msec = -1;
else {
  struct timespec ts;
  uint64_t n;
  clock_gettime(CLOCK_MONOTONIC, &ts);
  n = (uint64_t) ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
  msec = t > n ? (int) ((t - n + 999) / 1000) : 0;
}

El código anterior no realiza ninguna comprobación de errores por brevedad. El entero msec calculado se puede pasar directamente como parámetro de tiempo de espera de poll().

VALOR DE RETORNO

En caso de éxito, sd_login_monitor_new(), sd_login_monitor_flush() y sd_login_monitor_get_timeout() devuelven 0 o un entero positivo. En caso de éxito, sd_login_monitor_get_fd() devuelve un descriptor de archivo Unix. En caso de éxito, sd_login_monitor_get_events() devuelve una combinación de POLLIN, POLLOUT y similares. En caso de error, estas llamadas devuelven un código de error negativo estilo errno.

sd_login_monitor_unref() siempre devuelve NULL.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Un parámetro de entrada era inválido (fuera de rango, o NULL, donde no se acepta). La categoría especificada para observar no se conoce.

-ENOMEM

Falló la asignación de memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando no se han iniciado otros hilos.

HISTORIA

sd_login_monitor_get_events() y sd_login_monitor_get_timeout() se añadieron en la versión 201.

sd_login_monitor_unrefp() se añadió en la versión 229.

sd_login_monitor_get_events(3)

NOMBRE

sd_login_monitor_get_events - Obtener los eventos de inicio de sesión pendientes para un monitor

SINOPSIS

#include <systemd/sd-login.h>

int sd_login_monitor_get_events(sd_login_monitor *monitor, uint64_t *events);

DESCRIPCIÓN

El método sd_login_monitor_get_events() obtiene el conjunto de eventos de inicio de sesión pendientes, como se notifica a través del objeto monitor.

Los eventos se devuelven como un campo de bits en la variable events. Los bits individuales se definen en la tabla de esta página.

Este método solo debe llamarse si sd_login_monitor_wait() devolvió un valor distinto de cero, indicando que hay eventos pendientes.

VALOR DE RETORNO

En caso de éxito, sd_login_monitor_get_events() devuelve cero. En caso de error, devuelve un código de error negativo en el formato definido en systemd/error.h.

NOTAS

Los eventos de inicio de sesión se notifican a través de sd_login_monitor_wait(). Si este método devuelve un valor mayor que cero, significa que hay al menos un evento que se puede leer con sd_login_monitor_get_events(). Si sd_login_monitor_wait() devuelve cero, significa que no hay eventos pendientes, pero que se estableció una conexión con el demonio de inicio de sesión y el objeto monitor está listo para el uso posterior.

Este método está disponible como una biblioteca dinámica en el paquete systemd.

Para obtener más información sobre los eventos y cómo usarlos, consulta sd_login_monitor_new(3).

HISTORIAL

La función sd_login_monitor_get_events() está disponible a partir de systemd v227.

VER TAMBIÉN
