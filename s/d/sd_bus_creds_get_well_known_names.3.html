DESCRIPCIÓN

Estas funciones devuelven información de credenciales de un objeto sd_bus_creds. Los objetos de credenciales se pueden crear con sd_bus_creds_new_from_pid(3), en cuyo caso describen las credenciales del proceso identificado por el PID especificado, con sd_bus_get_name_creds(3), en cuyo caso describen las credenciales de un par del bus identificado por el nombre del bus especificado, con sd_bus_get_owner_creds(3), en cuyo caso describen las credenciales del creador de un bus, o con sd_bus_message_get_creds(3), en cuyo caso describen las credenciales del remitente del mensaje.

No todos los campos de credenciales forman parte de cada objeto "sd_bus_creds". Utilice sd_bus_creds_get_mask(3) para determinar la máscara de campos disponibles.

sd_bus_creds_get_pid() recuperará el PID (identificador de proceso). De manera similar, sd_bus_creds_get_ppid() recuperará el PID padre. Tenga en cuenta que el PID 1 no tiene proceso padre, en cuyo caso se devuelve -ENXIO.

sd_bus_creds_get_pidfd_dup() recuperará el descriptor de archivo PID (pidfd), consulte pidfd_open(2) para más detalles. El descriptor de archivo se duplica y, por lo tanto, debe ser cerrado por el llamador.

sd_bus_creds_get_tid() recuperará el TID (identificador de hilo).

sd_bus_creds_get_uid() recuperará el UID numérico (identificador de usuario). De manera similar, sd_bus_creds_get_euid() devuelve el UID efectivo, sd_bus_creds_get_suid() el UID guardado y sd_bus_creds_get_fsuid() el UID del sistema de archivos.

sd_bus_creds_get_gid() recuperará el GID numérico (identificador de grupo). De manera similar, sd_bus_creds_get_egid() devuelve el GID efectivo, sd_bus_creds_get_sgid() el GID guardado y sd_bus_creds_get_fsgid() el GID del sistema de archivos.

sd_bus_creds_get_supplementary_gids() recuperará la lista de GIDs suplementarios.

sd_bus_creds_get_comm() recuperará el campo comm (nombre truncado del ejecutable, tal como se almacena en /proc/pid/comm).

sd_bus_creds_get_tid_comm() recuperará el campo comm del hilo (tal como se almacena en /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() recuperará la ruta al ejecutable del programa (tal como se almacena en el enlace /proc/pid/exe, pero con el sufijo " (deleted)" eliminado). Tenga en cuenta que los hilos del kernel no tienen una ruta ejecutable, en cuyo caso se devuelve -ENXIO. Tenga en cuenta que esta propiedad no debe utilizarse para más que información explicativa, en particular no debe utilizarse para decisiones relevantes para la seguridad. Esto se debe a que el ejecutable podría haber sido reemplazado o eliminado en el momento en que se pueda procesar el valor. DESCRIPTION

Estas funciones se utilizan para extraer varios campos de metadatos de un objeto de credenciales de bus D-Bus, como los creados por sd_bus_creds_new_from_pid(3) o sd_bus_get_creds(3).

Tenga en cuenta que la mayoría de estos campos solo son accesibles para el proceso que los solicita si dicho proceso tiene los permisos adecuados para leerlos (por ejemplo, si el proceso que solicita pertenece a la misma sesión de usuario o es un proceso privilegiado).

sd_bus_creds_get_exe() recuperará la ruta del ejecutable del proceso. Si el proceso no tiene un ejecutable (por ejemplo, un hilo del kernel), se devuelve -ENXIO.

sd_bus_creds_get_pidfd_dup() crea un nuevo descriptor de archivo para el proceso referido en el objeto de credenciales. El descriptor de archivo es un "pidfd" que puede usarse para rastrear el ciclo de vida del proceso, incluso si su PID se reutiliza. El descriptor de archivo devuelto está listo para ser usado. El llamador es responsable de cerrarlo. Si el campo no está disponible, se devuelve -ENODATA.

sd_bus_creds_get_cmdline() recuperará una matriz de argumentos de línea de comandos (tal como se almacena en /proc/pid/cmdline). Tenga en cuenta que los hilos del kernel no tienen línea de comandos, en cuyo caso se devuelve -ENXIO.

sd_bus_creds_get_cgroup() recuperará la ruta del grupo de control. Ver Control Groups v2[1].

sd_bus_creds_get_unit() recuperará el nombre de la unidad systemd (en la instancia del sistema de systemd) de la que forma parte el proceso. Ver systemd.unit(5). Para los procesos que no forman parte de una unidad, devuelve -ENXIO.

sd_bus_creds_get_user_unit() recuperará el nombre de la unidad systemd (en la instancia de usuario de systemd) de la que forma parte el proceso. Ver systemd.unit(5). Para los procesos que no forman parte de una unidad de usuario, devuelve -ENXIO.

sd_bus_creds_get_slice() recuperará la "slice" de systemd (una unidad en la instancia del sistema de systemd) de la que forma parte el proceso. Ver systemd.slice(5). De manera similar, sd_bus_creds_get_user_slice() recupera la "slice" de systemd del proceso, en la instancia de usuario de systemd.

sd_bus_creds_get_session() recuperará el identificador de la sesión de inicio de sesión de la que forma parte el proceso. Tenga en cuenta que la sesión de inicio de sesión puede limitarse a uno o dos procesos "stub". Los procesos de usuario pueden iniciarse en su lugar desde su gestor de usuario systemd, por ejemplo, aplicaciones gráficas iniciadas usando activación DBus, así como procesos de servicio que se comparten entre múltiples inicios de sesión del mismo usuario. Para los procesos que no forman parte de una sesión, devuelve -ENXIO.

sd_bus_creds_get_owner_uid() recuperará el UID numérico (identificador de usuario) del usuario que es propietario de la unidad de usuario o sesión de inicio de sesión de la que forma parte el proceso. Ver systemd-logind.service(8). Para los procesos que no forman parte de una unidad de usuario o sesión, devuelve -ENXIO.

sd_bus_creds_has_effective_cap() verificará si la capacidad especificada por capability estaba establecida en la máscara de capacidades efectivas. Un valor de retorno positivo significa que estaba establecida, cero significa que no estaba establecida y un valor de retorno negativo indica un error. Ver capabilities(7) y los ajustes AmbientCapabilities= y CapabilityBoundingSet= en systemd.exec(5).

sd_bus_creds_has_permitted_cap() es similar a sd_bus_creds_has_effective_cap(), pero verificará la máscara de capacidades permitidas.

sd_bus_creds_has_inheritable_cap() es similar a sd_bus_creds_has_effective_cap(), pero verificará la máscara de capacidades heredables.

sd_bus_creds_has_bounding_cap() es similar a sd_bus_creds_has_effective_cap(), pero verificará la máscara de capacidades de limitación.

sd_bus_creds_get_selinux_context() recuperará el contexto de seguridad SELinux (etiqueta) del proceso.

sd_bus_creds_get_audit_session_id() recuperará el identificador de sesión de auditoría del proceso. Devuelve -ENXIO para procesos que no forman parte de una sesión de auditoría.

sd_bus_creds_get_audit_login_uid() recuperará el identificador de inicio de sesión de usuario de auditoría (el identificador del usuario que es "responsable" de la sesión). Devuelve -ENXIO para procesos que no forman parte de una sesión de auditoría.

sd_bus_creds_get_tty() recuperará el TTY de control, sin el prefijo "/dev/". Devuelve -ENXIO para procesos que no tienen TTY de control.

sd_bus_creds_get_unique_name() recuperará el nombre único de D-Bus. Ver The D-Bus specification[2].

sd_bus_creds_get_well_known_names() recuperará el conjunto de nombres conocidos de D-Bus. Ver The D-Bus specification[2].

sd_bus_creds_get_description() recuperará un nombre descriptivo de la conexión de bus del par. Este nombre es útil para discernir múltiples conexiones de bus del mismo par y puede ser modificado por el par con la llamada sd_bus_set_description(3).

Todas las funciones que toman un parámetro const char** almacenarán la respuesta allí como una dirección de una cadena terminada en NUL. Será válida mientras c permanezca válido y no debe ser liberada ni modificada por el llamador.

Todas las funciones que toman un parámetro char*** almacenarán la respuesta allí como una dirección de una matriz de cadenas. Cada cadena individual está terminada en NUL y la matriz está terminada en NULL en su conjunto. Será válida mientras c permanezca válido y no debe ser liberada ni modificada por el llamador.

RETURN VALUE

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, estas llamadas devuelven un código de error negativo al estilo errno.

Errors

Los errores devueltos pueden indicar los siguientes problemas:

-ENODATA

El campo dado no está disponible en el objeto de credenciales c.

-ENXIO

El campo dado no está especificado para el proceso o par descrito. Esto será devuelto por sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice() y sd_bus_creds_get_session() si el proceso no forma parte de una unidad de sistema systemd, unidad de usuario systemd, "slice" de systemd o sesión de logind. Será devuelto por sd_bus_creds_get_owner_uid() si el proceso no forma parte de una unidad de usuario systemd o sesión de logind. También será devuelto por sd_bus_creds_get_exe() y sd_bus_creds_get_cmdline() para hilos del kernel (ya que estos no se inician desde un binario ejecutable, ni tienen una línea de comandos), y por sd_bus_creds_get_audit_session_id() y sd_bus_creds_get_audit_login_uid() cuando el proceso no forma parte de una sesión de auditoría, y sd_bus_creds_get_tty() si el proceso no tiene TTY de control.

-EINVAL

El parámetro de puntero especificado es NULL.

-ENOMEM

Fallo en la asignación de memoria.

NOTES

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

NAME

sd_bus_creds_get_well_known_names - Get the well-known bus names associated with credentials

SYNOPSIS


    #include <systemd/sd-bus.h>

    int sd_bus_creds_get_well_known_names(sd_bus_creds *creds, const char ***names);

DESCRIPTION

The sd_bus_creds_get_well_known_names() function retrieves the list of well-known bus names that are associated with the credentials object creds. These are the names registered on the bus by the owner of the credentials, such as "org.freedesktop.hostname1".

The returned list is a NULL-terminated array of strings. The array itself is allocated by this function and must be freed using sd_bus_creds_free(). The strings inside the array are owned by the creds object and must not be freed individually.

This function is only meaningful when the credentials object was populated from a message received on the system bus, as only system bus messages contain information about well-known bus names.

PARAMETERS

creds
A pointer to the sd_bus_creds object. This object should have been initialized and populated, typically by sd_bus_get_creds().
names
A pointer to a const char *** where the array of well-known bus names will be stored. This array will be NULL if no well-known names are associated with the credentials or if the credentials object does not contain this information.

RETURN VALUE

On success, sd_bus_creds_get_well_known_names() returns a non-negative integer. The value 1 is returned if well-known names were found, and 0 is returned if no well-known names were associated with the credentials.

On failure, a negative errno-compatible error code is returned.

SEE ALSO

sd_bus_creds(3), sd_bus_get_creds(3), sd_bus_creds_free(3)

NOTES

The sd_bus_creds_get_well_known_names() function and the entire API it is part of is available as a shared library, which can be compiled and linked to with the pkg-config(1) package whose name is systemd. The C compile flags and linker C flags that must be used are specified by the output of pkg-config --cflags systemd and pkg-config --libs systemd.

The list of well-known names is only populated when the credentials object is obtained from a message on the system bus. It will be empty or NULL if obtained from a message on the session bus or through other means.
