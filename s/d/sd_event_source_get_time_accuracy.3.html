NOMBRE

sd_event_add_time, sd_event_add_time_relative, sd_event_source_get_time, sd_event_source_set_time, sd_event_source_set_time_relative, sd_event_source_get_time_accuracy, sd_event_source_set_time_accuracy, sd_event_source_get_time_clock, sd_event_time_handler_t - Añadir una fuente de eventos de temporizador a un bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_time_handler_t)(sd_event_source *s, uint64_t usec, void *userdata);

int sd_event_add_time(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_add_time_relative(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_source_get_time(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time(sd_event_source *source, uint64_t usec);

int sd_event_source_set_time_relative(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_accuracy(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time_accuracy(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_clock(sd_event_source *source, clockid_t *ret);

DESCRIPCIÓN

sd_event_add_time() añade una nueva fuente de eventos de temporizador a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro clock toma un identificador de reloj, uno de CLOCK_REALTIME, CLOCK_MONOTONIC, CLOCK_BOOTTIME, CLOCK_REALTIME_ALARM o CLOCK_BOOTTIME_ALARM. Consulte timerfd_create(2) para obtener detalles sobre los distintos tipos de relojes. El parámetro usec especifica la hora más temprana, en microsegundos (μs), relativa a la época del reloj, en la que el temporizador se disparará. Si se especifica una hora ya pasada (incluido 0), esta fuente de temporizador se "activa" inmediatamente y está lista para ser despachada. Si el parámetro se especifica como UINT64_MAX el evento del temporizador nunca transcurrirá, lo que puede usarse como alternativa a la desactivación explícita de una fuente de eventos de temporizador con sd_event_source_set_enabled(3). El parámetro accuracy especifica un valor de precisión adicional en μs que indica cuánto puede retrasarse el evento del temporizador. Use 0 para seleccionar la precisión por defecto (250ms). Use 1μs para máxima precisión. Considere especificar 60000000μs (1min) o más para eventos de larga duración que pueden retrasarse sustancialmente. Elegir valores de precisión más altos permite al sistema agrupar eventos de temporizador de forma más agresiva, mejorando la eficiencia energética.

El handler es una función a llamar cuando el temporizador transcurre o NULL. El puntero userdata se pasará a la función manejadora y puede ser elegido libremente por el llamador. La hora de disparo configurada también se pasa al manejador, incluso si la llamada ocurre ligeramente más tarde, sujeta al valor de precisión especificado, el retraso del temporizador del kernel (ver prctl(2)) y latencias de planificación adicionales. Para consultar la hora real en la que se llamó al manejador use sd_event_now(3). El manejador puede devolver un valor negativo para señalar un error (ver abajo), otros valores de retorno son ignorados. Si handler es NULL, se utilizará un manejador por defecto que llama a sd_event_exit(3).

Por defecto, el temporizador transcurrirá una vez (SD_EVENT_ONESHOT), pero esto puede cambiarse con sd_event_source_set_enabled(3). Si la función manejadora devuelve un código de error negativo, será deshabilitada después de la invocación, incluso si el modo SD_EVENT_ON fue solicitado antes, o causará que el bucle termine, ver sd_event_source_set_exit_on_failure(3). Tenga en cuenta que un evento de temporizador configurado a SD_EVENT_ON se disparará continuamente a menos que su hora configurada se actualice usando sd_event_source_set_time(3).

sd_event_add_time_relative() es como sd_event_add_time(), pero toma una especificación de tiempo relativo. Es relativo a la hora actual de la iteración del bucle de eventos, tal como la devuelve sd_event_now(3).

Para destruir un objeto de fuente de eventos use sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se descartan todas las referencias a la fuente de eventos. Para asegurarse de que una fuente de eventos no se dispare más, incluso si todavía está referenciada, desactive la fuente de eventos usando sd_event_source_set_enabled(3) con SD_EVENT_OFF.

Si el segundo parámetro de sd_event_add_time() es NULL no se devuelve ninguna referencia al objeto de la fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando el propio bucle de eventos sea destruido.

Si el parámetro handler de sd_event_add_time() es NULL, y la fuente de eventos se dispara, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a entero, se pasa como parámetro de código de salida a sd_event_exit(3).

Use CLOCK_BOOTTIME_ALARM y CLOCK_REALTIME_ALARM para definir fuentes de eventos que puedan despertar al sistema de la suspensión.

Para configurar temporizadores relativos (es decir, relativos a la hora actual), obtenga la hora actual a través de sd_event_now(3), añada el intervalo de tiempo deseado y use el resultado como parámetro usec para sd_event_add_time().

Para configurar temporizadores repetitivos (es decir, temporizadores que se disparan en intervalos regulares), configure el temporizador normalmente, para la primera invocación. Cada vez que se invoca el manejador de eventos, actualice la hora de disparo del temporizador con sd_event_source_set_time(3) para la próxima iteración del temporizador y reactive el temporizador usando sd_event_source_set_enabled(). Para calcular el próximo punto en el tiempo para pasar a sd_event_source_set_time(), use como base el parámetro usec pasado al callback del temporizador, o la marca de tiempo devuelta por sd_event_now(). En el primer caso, los eventos del temporizador serán regulares, mientras que en el segundo caso, la latencia de planificación seguirá acumulándose en el temporizador.

sd_event_source_get_time() recupera el valor de hora configurado de una fuente de eventos creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar la hora, relativa a la época del reloj seleccionado, en μs. El valor devuelto es relativo a la época, incluso si la fuente de eventos se creó con un tiempo relativo a través de sd_event_add_time_relative().

sd_event_source_set_time() cambia la hora de una fuente de eventos creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de eventos y una hora relativa a la época del reloj seleccionado, en μs.

sd_event_source_set_time_relative() es similar a sd_event_source_set_time(), pero toma una hora relativa a la hora actual de la iteración del bucle de eventos, tal como la devuelve sd_event_now().

sd_event_source_get_time_accuracy() recupera el valor de precisión configurado de una fuente de eventos creada previamente con sd_event_add_time(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar la precisión. La precisión se especifica en μs.

sd_event_source_set_time_accuracy() cambia la precisión configurada de un evento de temporizador

NAME

sd_event_source_get_time_accuracy, sd_event_source_set_time_accuracy, sd_event_source_get_time_clock, sd_event_add_time_relative, sd_event_source_set_time_relative - Get and set timer event source time and accuracy

SYNOPSIS

#include <systemd/sd-event.h>

;; sd_event_source *sd_event_add_time(sd_event *event, clockid_t clock_id, const struct timespec *ts, sd_event_time_handler_t *callback, void *userdata);

;; int sd_event_source_set_time(sd_event_source *source, const struct timespec *ts);

;; int sd_event_source_get_time(sd_event_source *source, struct timespec *ts);

;; int sd_event_source_set_time_accuracy(sd_event_source *source, uint64_t accuracy_usec);

;; int sd_event_source_get_time_accuracy(sd_event_source *source, uint64_t *accuracy_usec);

;; int sd_event_source_get_time_clock(sd_event_source *source, clockid_t *clock_id);

;; sd_event_source *sd_event_add_time_relative(sd_event *event, clockid_t clock_id, const struct timespec *ts, sd_event_time_handler_t *callback, void *userdata);

;; int sd_event_source_set_time_relative(sd_event_source *source, const struct timespec *ts);

DESCRIPTION

sd_event_add_time() may be used to register a timer event source with the event loop event. The timer will trigger when the specified time ts has passed, relative to the specified monotonic or real-time clock clock_id. The callback function will be invoked when the time is reached, with the userdata pointer userdata passed along. If ts is NULL, the timer is enabled immediately.

sd_event_source_set_time() may be used to change the trigger time of an existing timer event source source. The time is specified in the same way as for sd_event_add_time().

sd_event_source_get_time() retrieves the currently set trigger time of a timer event source source.

sd_event_source_set_time_accuracy() sets the accuracy of the timer event source source. The accuracy is specified in microseconds (accuracy_usec). This is a hint to the kernel for how accurate the timer needs to be. This feature relies on the TFD_TIMER_ABSTIME and TFD_TIMER_CANCEL_ON_SET flags of timerfd_create(2) and may not be supported on all systems or for all clocks. If accuracy_usec is 0, the accuracy is reset to the system default. This function only works on timer event sources created with sd_event_add_time().

sd_event_source_get_time_accuracy() retrieves the configured accuracy of a timer event source source. The accuracy is returned in microseconds in the accuracy_usec variable.

sd_event_source_get_time_clock() retrieves the configured clock of a timer event source source.

sd_event_add_time_relative() is similar to sd_event_add_time(), but the time ts is interpreted as a relative time interval from now, instead of an absolute time. The interval specified is added to the current time read from the specified clock clock_id to determine the absolute trigger time. The maximum allowed value for the time interval is limited by the range of unsigned 64-bit integers.

sd_event_source_set_time_relative() is similar to sd_event_source_set_time(), but changes the trigger time by setting a new relative time interval, instead of an absolute time. The interval specified is added to the current time read from the clock specified when the event source was created to determine the new absolute trigger time.

The callback function type is defined in sd-event(3).

For a description of the parameters and return value, see sd_event_add_source(3).

The following functions are only available when timerfd is supported (see timerfd_create(2)):

sd_event_source_set_time_accuracy() sets the accuracy of an event source created previously with sd_event_add_time(). It takes the event source object and accuracy, in μs.

sd_event_source_get_time_accuracy() retrieves the configured accuracy of an event source created previously with sd_event_add_time(). It takes the event source object and accuracy, in μs.

sd_event_source_get_time_clock() retrieves the configured clock of an event source created previously with sd_event_add_time(). It takes the event source object and a pointer to a variable to store the clock identifier in.

RETURN VALUE

On success, these functions return 0 or a positive integer. On failure, they return a negative errno-style error code.

Errors

Returned values may indicate the following problems:

-ENOMEM

Not enough memory to allocate an object.

-EINVAL

An invalid argument has been passed.

-ESTALE

The event loop is already terminated.

-ECHILD

The event loop has been created in a different process, library or module instance.

-EOPNOTSUPP

The selected clock is not supported by the event loop implementation.

-EDOM

The passed event source is not a timer event source.

-EOVERFLOW

The passed relative time is outside of the allowed range for time values (i.e. the specified value added to the current time is outside the 64 bit unsigned integer range).

Added in version 247.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
