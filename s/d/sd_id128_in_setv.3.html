DESCRIPCIÓN

sd-id128.h forma parte de libsystemd(3) y proporciona APIs para generar, convertir y comparar valores de ID de 128 bits. Los valores de ID de 128 bits procesados y generados por estas APIs son una generalización de los UUID de OSF definidos por la RFC 4122[1] pero utilizan un formato de cadena más simple. Estas funciones no imponen ninguna estructura en los IDs utilizados, a diferencia de los UUID de OSF o los GUID de Microsoft, pero son mayormente compatibles con esos tipos de IDs.

Un ID de 128 bits se implementa como la siguiente unión de tipos:

typedef union sd_id128 {
  uint8_t bytes[16];
  uint64_t qwords[2];
} sd_id128_t;

Esta unión de tipos permite acceder al ID de 128 bits como 16 bytes separados o dos palabras de 64 bits. Generalmente es más seguro acceder a los componentes del ID por su array de 8 bits para evitar problemas de endianness. Esta unión está pensada para ser pasada por valor (en lugar de por referencia) y puede ser manipulada directamente por los clientes.

Se definen un par de macros para denotar y decodificar IDs de 128 bits:

SD_ID128_MAKE() se utiliza para escribir un ID constante en el código fuente. Un uso común es asignar un nombre a un ID usando esta macro:

#define SD_MESSAGE_COREDUMP SD_ID128_MAKE(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)

SD_ID128_NULL define un ID que consiste solo en bytes NUL (es decir, todos los bits a cero).

SD_ID128_ALLF define un ID que consiste solo en bytes 0xFF (es decir, todos los bits a uno).

SD_ID128_MAKE_STR() es similar a SD_ID128_MAKE(), pero crea una expresión const char* que se puede usar convenientemente en formatos de mensajes y similares:

#include <stdio.h>
#define SD_MESSAGE_COREDUMP_STR SD_ID128_MAKE_STR(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)
int main(int argc, char **argv) {
  puts("Match for coredumps: MESSAGE_ID=" SD_MESSAGE_COREDUMP_STR);
}

SD_ID128_CONST_STR() convierte IDs constantes en cadenas constantes para su salida. El siguiente código de ejemplo mostrará la cadena "fc2e22bc6ee647b6b90729ab34a250b1":

int main(int argc, char *argv[]) {
  puts("Match for coredumps: %s", SD_ID128_CONST_STR(SD_MESSAGE_COREDUMP));
}

SD_ID128_FORMAT_STR y SD_ID128_FORMAT_VAL() se utilizan para formatear un ID en una cadena de formato printf(3), como se muestra en el siguiente ejemplo:

int main(int argc, char *argv[]) {
  sd_id128_t id;
  id = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  printf("The ID encoded in this C file is " SD_ID128_FORMAT_STR ".\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}

SD_ID128_UUID_FORMAT_STR y SD_ID128_MAKE_UUID_STR() son similares a SD_ID128_FORMAT_STR y SD_ID128_MAKE_STR(), pero incluyen guiones separadores para cumplir con la "representación canónica de UUID[2]". Formatean la cadena basándose en las reglas de la Variante 1 de la RFC4122[1], es decir, convirtiendo desde el orden de bytes Big Endian. Esto coincide con el comportamiento de la mayoría de la infraestructura del espacio de usuarios de Linux. Probablemente sea mejor evitar UUIDs de otras variantes para no crear ambigüedades innecesarias. Todos los IDs de 128 bits generados por las APIs sd-id128 se ajustan estrictamente a los UUIDs de Variante 1 Versión 4, según la RFC 4122.

sd_id128_equal() compara dos IDs de 128 bits:

int main(int argc, char *argv[]) {
  sd_id128_t a, b, c;
  a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  b = SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e);
  c = a;
  assert(sd_id128_equal(a, c));
  assert(!sd_id128_equal(a, b));
  return 0;
}

sd_id128_string_equal() es similar a sd_id128_equal(), pero el primer ID se formatea como const char*. Se aplican las mismas restricciones que al primer argumento de sd_id128_from_string().

sd_id128_is_null() comprueba si un ID consiste solo en bytes NUL:

assert(sd_id128_is_null(SD_ID128_NULL));

De manera similar, sd_id128_is_allf() comprueba si un ID consiste solo en bytes 0xFF (todos los bits a uno):

assert(sd_id128_is_allf(SD_ID128_ALLF));

sd_id128_in_set_sentinel() toma una lista de IDs y devuelve true si el primer argumento es igual a alguno de los argumentos posteriores. La lista de argumentos está terminada por un centinela SD_ID128_NULL, que debe estar presente.

sd_id128_in_set() es una función de conveniencia que toma una lista de IDs y devuelve true si el primer argumento es igual a alguno de los argumentos posteriores:

int main(int argc, char *argv[]) {
  sd_id12_t a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  assert(sd_id128_in_set(a, a));
  assert(sd_id128_in_set(a, a, a));
  assert(!sd_id128_in_set(a));
  assert(!sd_id128_in_set(a,
                          SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e)
                          SD_ID128_MAKE(2f,88,28,5f,9c,44,09,9d,d7,15,77,04,bc,85,7e,e3)
                          SD_ID128_ALLF));
  return 0;
}

sd_id128_in_set() está definida como una macro sobre sd_id128_in_set_sentinel(), añadiendo el centinela SD_ID128_NULL automáticamente. Dado que sd_id128_in_set_sentinel() utiliza SD_ID128_NULL como centinela, SD_ID128_NULL no puede colocarse de otra manera en la lista de argumentos.

sd_id128_in_setv() es similar a sd_id128_in_set_sentinel(), pero toma un argumento struct varargs.

Se pueden generar nuevos IDs aleatorios con el comando new de systemd-id128(1).

IMPLEMENTED FUNCTIONS

The functions described here are implemented by libsystemd(3).

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
