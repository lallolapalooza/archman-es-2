SD_LOGIN_MONITOR_NEW(3) sd_login_monitor_new SD_LOGIN_MONITOR_NEW(3)

NOMBRE

sd_login_monitor_new, sd_login_monitor_unref, sd_login_monitor_unrefp, sd_login_monitor_flush, sd_login_monitor_get_fd, sd_login_monitor_get_events, sd_login_monitor_get_timeout, sd_login_monitor - Monitorizar sesiones de inicio de sesión, asientos, usuarios y máquinas virtuales/contenedores

SINOPSIS

#include <systemd/sd-login.h>

int sd_login_monitor_new(const char *category, sd_login_monitor **ret);

sd_login_monitor *sd_login_monitor_unref(sd_login_monitor *m);

void sd_login_monitor_unrefp(sd_login_monitor **m);

int sd_login_monitor_flush(sd_login_monitor *m);

int sd_login_monitor_get_fd(sd_login_monitor *m);

int sd_login_monitor_get_events(sd_login_monitor *m);

int sd_login_monitor_get_timeout(sd_login_monitor *m, uint64_t *timeout_usec);

DESCRIPCIÓN

sd_login_monitor_new() puede utilizarse para monitorizar sesiones de inicio de sesión, usuarios, asientos y máquinas virtuales/contenedores. A través de un objeto monitor se puede integrar un descriptor de archivo en un bucle de eventos definido por la aplicación, el cual se activa cada vez que un usuario inicia o cierra sesión o se añade o elimina un asiento, o cuando un estado de sesión, usuario, asiento o máquina virtual/contenedor cambia. El primer parámetro toma una cadena que puede ser "seat" (para recibir solo notificaciones sobre asientos añadidos, eliminados o cambiados), "session" (para recibir solo notificaciones sobre sesiones creadas, eliminadas o cambiadas), "uid" (para recibir solo notificaciones cuando un usuario cambia de estado en relación con los inicios de sesión) o "machine" (para recibir solo notificaciones cuando una máquina virtual o contenedor se inicia o detiene). Si se deben generar notificaciones en todas estas condiciones, se puede pasar NULL. Tenga en cuenta que en el futuro pueden definirse categorías adicionales. El segundo parámetro devuelve un objeto monitor y debe liberarse con la llamada a sd_login_monitor_unref() después de su uso.

sd_login_monitor_unref() puede utilizarse para destruir un objeto monitor. Tenga en cuenta que esto invalidará cualquier descriptor de archivo devuelto por sd_login_monitor_get_fd().

sd_login_monitor_unrefp() es similar a sd_login_monitor_unref() pero toma un puntero a un puntero a un objeto sd_login_monitor. Esta llamada es útil en conjunción con el Attribute de Variable de Limpieza de GCC y LLVM[1]. Tenga en cuenta que esta función está definida como una función inline. Utilice una declaración como la siguiente para asignar un objeto monitor de inicio de sesión que se liberará automáticamente al salir del bloque de código:

{
  __attribute__((cleanup(sd_login_monitor_unrefp))) sd_login_monitor *m = NULL;
  int r;
  ...
  r = sd_login_monitor_new(NULL, &m);
  if (r < 0) {
    errno = -r;
    fprintf(stderr, "Falló la asignación del objeto monitor de inicio de sesión: %m\n");
  }
  ...
}

sd_login_monitor_flush() puede utilizarse para restablecer el estado de activación del objeto monitor. Cada vez que un evento provoca que el monitor active el bucle de eventos a través del descriptor de archivo, esta función debe ser llamada para restablecer el estado de activación. Si no se invoca esta llamada, el descriptor de archivo activará de nuevo el bucle de eventos inmediatamente.

sd_login_monitor_unref() y sd_login_monitor_unrefp() no realizan ninguna operación si el objeto monitor pasado es NULL.

sd_login_monitor_get_fd() puede utilizarse para recuperar el descriptor de archivo del objeto monitor que puede integrarse en un bucle de eventos definido por la aplicación, basado en poll(2) o una interfaz similar. La aplicación debe incluir el descriptor de archivo devuelto como fuente de activación para la máscara de eventos devuelta por sd_login_monitor_get_events(). Debe pasar un valor de tiempo de espera como el devuelto por sd_login_monitor_get_timeout(). Cada vez que se produzca una activación, el descriptor de archivo deberá restablecerse mediante sd_login_monitor_flush(). Una aplicación necesita releer el estado de inicio de sesión con una función como sd_get_seats(3) o similar para determinar qué ha cambiado.

sd_login_monitor_get_events() devolverá la máscara de poll() para esperar. Esta función devolverá una combinación de POLLIN, POLLOUT y similares para rellenar el campo ".events" de struct pollfd.

sd_login_monitor_get_timeout() devolverá un valor de tiempo de espera para su uso en poll(). Devuelve un valor en microsegundos desde la época de CLOCK_MONOTONIC para agotar el tiempo de espera de poll() en timeout_usec. Consulte clock_gettime(2) para obtener detalles sobre CLOCK_MONOTONIC. Si no hay tiempo de espera, llenará (uint64_t) -1 en su lugar. Tenga en cuenta que poll() toma un tiempo de espera relativo en milisegundos en lugar de un tiempo de espera absoluto en microsegundos. Para convertir el tiempo de espera absoluto de 'µs' en un tiempo de espera relativo de 'ms', utilice código como el siguiente:

uint64_t t;
int msec;
sd_login_monitor_get_timeout(m, &t);
if (t == (uint64_t) -1)
  msec = -1;
else {
  struct timespec ts;
  uint64_t n;
  clock_gettime(CLOCK_MONOTONIC, &ts);
  n = (uint64_t) ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
  msec = t > n ? (int) ((t - n + 999) / 1000) : 0;
}

El código anterior no realiza ninguna comprobación de errores por brevedad. El entero msec calculado puede pasarse directamente como parámetro de tiempo de espera de poll().

VALOR DE RETORNO

En caso de éxito, sd_login_monitor_new(), sd_login_monitor_flush() y sd_login_monitor_get_timeout() devuelven 0 o un entero positivo. En caso de éxito, sd_login_monitor_get_fd() devuelve un descriptor de archivo Unix. En caso de éxito, sd_login_monitor_get_events() devuelve una combinación de POLLIN, POLLOUT y similares. En caso de error, estas llamadas devuelven un código de error negativo estilo errno.

sd_login_monitor_unref() siempre devuelve NULL.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Un parámetro de entrada era inválido (fuera de rango o NULL, donde no se acepta). La categoría especificada a vigilar no se conoce.

-ENOMEM

Fallo en la asignación de memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo pkg-config de libsystemd. pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIAL

sd_login_monitor_get_events() y sd_login_monitor_get_timeout() se añadieron en la versión 201.

sd_login_monitor_unrefp() se añadió en la versión 229.
