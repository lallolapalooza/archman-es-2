sd_bus_call_async(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_CALL(3) sd_bus_call SD_BUS_CALL(3)

NOMBRE

sd_bus_call, sd_bus_call_async - Invocar una llamada a un método de D-Bus

SINOPSIS

#include <systemd/sd-bus.h>

typedef int (*sd_bus_message_handler_t)(sd_bus_message *m, void *userdata, sd_bus_error *ret_error);

int sd_bus_call(sd_bus *bus, sd_bus_message *m, uint64_t usec, sd_bus_error *ret_error, sd_bus_message **reply);

int sd_bus_call_async(sd_bus *bus, sd_bus_slot **slot, sd_bus_message *m, sd_bus_message_handler_t callback, void *userdata, uint64_t usec);

DESCRIPCIÓN

sd_bus_call() toma un objeto de mensaje de bus completo y invoca el método D-Bus correspondiente. En caso de éxito, la respuesta se almacena en reply. usec indica el tiempo de espera en microsegundos. Si ret_error no es NULL y sd_bus_call() falla (ya sea por un error interno o porque recibió una respuesta de error de D-Bus), ret_error se inicializa a una instancia de sd_bus_error que describe el error.

sd_bus_call_async() es similar a sd_bus_call() pero funciona de forma asíncrona. callback indica la función a llamar cuando llega la respuesta. El puntero userdata se pasará a la función de callback y puede ser elegido libremente por el llamador. Si slot no es NULL y sd_bus_call_async() tiene éxito, slot se establece a un objeto de slot que puede usarse para cancelar la llamada al método más tarde usando sd_bus_slot_unref(3). Si slot es NULL, la vida útil de la llamada al método está ligada a la vida útil del propio objeto de bus, y no se puede cancelar de forma independiente. Ver sd_bus_slot_set_floating(3) para más detalles. callback se llama cuando llega una respuesta con la respuesta, userdata y un parámetro de salida sd_bus_error como sus argumentos. A diferencia de sd_bus_call(), el parámetro de salida sd_bus_error pasado al callback estará vacío. Para determinar si la llamada al método tuvo éxito, use sd_bus_message_is_method_error(3) en el mensaje de respuesta pasado al callback en su lugar. Si el callback devuelve cero y el parámetro de salida sd_bus_error todavía está vacío cuando el callback termina, otros manejadores registrados con funciones como sd_bus_add_filter(3) o sd_bus_add_match(3) tienen la oportunidad de procesar el mensaje. Si el callback devuelve un valor distinto de cero o el parámetro de salida sd_bus_error no está vacío cuando el callback termina, no se realiza ningún procesamiento adicional del mensaje. Generalmente, querrá devolver cero desde el callback para dar a otros manejadores registrados la oportunidad de procesar la respuesta también. (Tenga en cuenta que el parámetro sd_bus_error es un parámetro de salida de la función callback, no un parámetro de entrada; se puede usar para propagar errores desde el manejador del callback, no recibirá ningún error que se haya recibido como respuesta del método.)

El mensaje m pasado al callback solo se presta, es decir, el callback no debe llamar a sd_bus_message_unref(3) en él. Si el callback desea conservar el mensaje más allá de la vida útil del callback, necesita llamar a sd_bus_message_ref(3) para crear una nueva referencia.

Si usec es cero, se utiliza el tiempo de espera de llamada al método D-Bus predeterminado. Ver sd_bus_get_method_call_timeout(3).

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un entero no negativo. En caso de fallo, devuelven un código de error negativo de estilo errno.

Errores

Cuando sd_bus_call() recibe internamente una respuesta de error de D-Bus, establecerá ret_error si no es NULL, y devolverá un valor negativo mapeado desde la respuesta del error, ver sd_bus_error_get_errno(3).

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

El parámetro de entrada m es NULL.

El parámetro de entrada m no es una llamada a método de D-Bus. Para crear una nueva llamada a método de D-Bus, use sd_bus_message_new_method_call(3).

El parámetro de entrada m tiene el indicador BUS_MESSAGE_NO_REPLY_EXPECTED establecido.

El parámetro de entrada error no es NULL pero no se estableció a SD_BUS_ERROR_NULL.

-ECHILD

La conexión de bus se asignó en un proceso padre y se está reutilizando en un proceso hijo después de fork().

-ENOTCONN

El parámetro de entrada bus es NULL o el bus no está conectado.

-ECONNRESET

La conexión de bus se cerró mientras se esperaba la respuesta.

-ETIMEDOUT

No se recibió una respuesta dentro del tiempo de espera dado.

-ELOOP

El mensaje m se dirige a su propio cliente.

-ENOMEM

Fallo al asignar memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

sd_bus_call() y sd_bus_call_async() se añadieron en la versión 221.
