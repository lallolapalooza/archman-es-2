sd_event_source_get_signal(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_EVENT_ADD_SIGNAL(3) sd_event_add_signal SD_EVENT_ADD_SIGNAL(3)

NOMBRE

sd_event_add_signal, sd_event_source_get_signal, sd_event_signal_handler_t, SD_EVENT_SIGNAL_PROCMASK - Añadir una fuente de eventos de señal de proceso UNIX a un bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;
SD_EVENT_SIGNAL_PROCMASK

typedef int (*sd_event_signal_handler_t)(sd_event_source *s, const struct signalfd_siginfo *si, void *userdata);

int sd_event_add_signal(sd_event *event, sd_event_source **source, int signal, sd_event_signal_handler_t handler, void *userdata);

int sd_event_source_get_signal(sd_event_source *source);

DESCRIPCIÓN

sd_event_add_signal() añade una nueva fuente de eventos de señal de proceso UNIX a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, y el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro signal especifica la señal numérica a manejar (ver signal(7)).

El parámetro handler es una función a llamar cuando se reciba la señal o NULL. La función manejadora recibirá el puntero userdata, que puede ser elegido libremente por el llamador. La manejadora también recibe un puntero a una estructura signalfd_siginfo que contiene información sobre la señal recibida. Ver signalfd(2) para más información. La manejadora puede devolver un valor negativo para señalar un error (ver más abajo), otros valores de retorno se ignoran. Si handler es NULL, se utilizará una manejadora predeterminada que llama a sd_event_exit(3).

Solo se puede instalar una manejadora para una señal específica. La señal debe estar bloqueada en todos los hilos antes de llamar a esta función (usando sigprocmask(2) o pthread_sigmask(3)). Para conveniencia, si la bandera especial SD_EVENT_SIGNAL_PROCMASK se ORea en la señal especificada, la señal se enmascarará automáticamente según sea necesario, para el hilo llamador. Tenga en cuenta que esto solo funciona de manera confiable si la señal ya está enmascarada en todos los demás hilos del proceso, o si no hay otros hilos en el momento de la invocación.

Por defecto, la fuente de eventos se habilita permanentemente (SD_EVENT_ON), pero esto puede cambiarse con sd_event_source_set_enabled(3). Si la función manejadora devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si se solicitó el modo SD_EVENT_ON antes, o provocará que el bucle termine, ver sd_event_source_set_exit_on_failure(3).

Para destruir un objeto de fuente de eventos, use sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se sueltan todas las referencias a ella. Para asegurarse de que una fuente de eventos no se active más, incluso si todavía se hace referencia a ella, deshabilite la fuente de eventos usando sd_event_source_set_enabled(3) con SD_EVENT_OFF.

Si el segundo parámetro de sd_event_add_signal() es NULL, no se devuelve ninguna referencia al objeto de la fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando se destruya el propio bucle de eventos.

Si el parámetro handler de sd_event_add_signal() es NULL, y la fuente de eventos se activa, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a entero, se pasa como parámetro de código de salida a sd_event_exit(3).

sd_event_source_get_signal() devuelve el número de señal configurado de una fuente de eventos creada previamente con sd_event_add_signal(). Toma el objeto de la fuente de eventos como el parámetro source.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento no válido.

-EBUSY

Ya hay una manejadora instalada para esta señal o la señal no estaba bloqueada previamente.

-ESTALE

El bucle de eventos ya está terminado.

-ECHILD

El bucle de eventos se ha creado en un proceso, biblioteca o instancia de módulo diferente.

-EDOM

La fuente de eventos pasada no es una fuente de eventos de señal.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que está declarado como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

sd_event_add_signal(), sd_event_signal_handler_t(), y sd_event_source_get_signal() se añadieron en la versión 217.
