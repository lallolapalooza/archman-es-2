DESCRIPCIÓN

La estructura sd_bus_error lleva información sobre una condición de error de D-Bus, o la falta de ella. Las funciones descritas a continuación pueden ser usadas para establecer y consultar campos en esta estructura.

•El campo name contiene un identificador corto de un error. Debe seguir las reglas para nombres de error descritas en la especificación de D-Bus, subsección Nombres D-Bus Válidos[1]. Una serie de nombres de error comunes y estandarizados se describen en sd-bus-errors(3), pero las aplicaciones pueden definir errores adicionales específicos del dominio.
•El campo message generalmente contiene una cadena legible por humanos describiendo los detalles, pero podría ser NULL.

Una estructura sd_bus_error no establecida debe tener ambos campos inicializados a NULL, y significa la falta de un error, es decir, éxito. Asigna SD_BUS_ERROR_NULL a la estructura para inicializar ambos campos a NULL. Cuando ya no sean necesarios, los recursos mantenidos por la estructura sd_bus_error deben ser destruidos con sd_bus_error_free().

sd_bus_error_set() establece una estructura de error a los nombres y mensajes especificados. Las cadenas se copiarán en memoria interna recién asignada. Es esencial liberar los contenidos nuevamente cuando ya no se necesiten (ver arriba). No uses esta llamada en estructuras de error que ya se hayan establecido. Si pretendes reutilizar una estructura de error, libera los datos antiguos almacenados en ella con sd_bus_error_free() primero.

sd_bus_error_set() devolverá un valor similar a errno (ver errno(3)) determinado a partir del nombre de error especificado name. Si name es NULL, se asume que no ocurrió ningún error, y se devuelve 0. Si name no es nulo, siempre se devuelve un valor negativo. Si e es NULL, no se inicializa ninguna estructura de error, pero name aún se convierte en un valor estilo errno.

Varios errores conocidos de D-Bus se convierten en sus contrapartes conocidas de errno, y los demás a -EIO. Ver sd-bus-errors(3) para una lista de nombres de error conocidos. Se pueden definir mapeos de error adicionales con sd_bus_error_add_map(3).

sd_bus_error_set() está diseñado para ser utilizado convenientemente en una sentencia return. Si message es NULL, no se establece ningún mensaje. Esta llamada puede fallar si no se puede asignar memoria para las cadenas de nombre y mensaje, en cuyo caso se establecerá un error SD_BUS_ERROR_NO_MEMORY en su lugar y se devolverá -ENOMEM.

sd_bus_error_setf() y sd_bus_error_setfv() son similares a sd_bus_error_set(), pero toman una cadena de formato printf(3) y los argumentos correspondientes para generar el campo message. sd_bus_error_setf() utiliza argumentos variádicos, y sd_bus_error_setfv() acepta los argumentos como una lista de parámetros va_arg(3).

sd_bus_error_set_const() es similar a sd_bus_error_set(), pero los parámetros de cadena no se copian internamente, y por lo tanto deben permanecer constantes y válidos durante la vida de e. Usa esta llamada para evitar asignaciones de memoria al establecer estructuras de error. Como esta llamada no asigna memoria, no fallará con una condición de falta de memoria como puede hacerlo sd_bus_error_set(), como se describe anteriormente. Alternativamente, la macro SD_BUS_ERROR_MAKE_CONST() puede ser utilizada para generar una estructura de error literal y constante sobre la marcha.

sd_bus_error_set_errno() devolverá inmediatamente 0 si el parámetro de error especificado error es 0. De lo contrario, establecerá name a partir de un valor similar a errno que se convierte a un error D-Bus. Se utilizará strerror_r(3) para establecer message. Se utilizarán nombres de error conocidos de D-Bus para name si son aplicables, de lo contrario se generará un nombre en el espacio de nombres "System.Error.". Se ignora el signo del número de error especificado y se usa implícitamente su valor absoluto. Si el error especificado error es distinto de cero, la llamada siempre devuelve un valor negativo, para un uso conveniente en sentencias return. Esta llamada puede fallar debido a falta de memoria, en cuyo caso se establecerá un error SD_BUS_ERROR_NO_MEMORY en su lugar, y se devolverá -ENOMEM.

sd_bus_error_set_errnof() y sd_bus_error_set_errnof() son similares a sd_bus_error_set_errno(), pero además de error, toman una cadena de formato printf(3) y los argumentos correspondientes. El campo message se generará a partir de format y los argumentos. sd_bus_error_set_errnof() utiliza argumentos variádicos, y sd_bus_error_set_errnofv() acepta los argumentos como una lista de parámetros va_arg(3).

sd_bus_error_get_errno() convierte el campo name de una estructura de error a un valor similar a errno (positivo) utilizando las mismas reglas que sd_bus_error_set(). Si e es NULL, se devolverá 0.

sd_bus_error_copy() inicializará dst usando los valores en e, si e se ha establecido previamente con un valor de error. De lo contrario, devolverá inmediatamente. Si las cadenas en e se establecieron usando sd_bus_error_set_const(), se compartirán. De lo contrario, se copiarán. Antes de esta llamada, dst debe estar sin establecer, es decir, recién inicializado con NULL o restablecido usando sd_bus_error_free().

sd_bus_error_move(3)

NAME

sd_bus_error_copy, sd_bus_error_move, sd_bus_error_free, sd_bus_error_is_set, sd_bus_error_has_name, sd_bus_error_has_names_sentinel, sd_bus_error_has_names - manage sd_bus_error objects

SYNOPSIS

#include <systemd/sd-bus.h>
int sd_bus_error_copy(sd_bus_error *dst, const sd_bus_error *src);
int sd_bus_error_move(sd_bus_error *dst, sd_bus_error *src);
void sd_bus_error_free(sd_bus_error *e);
int sd_bus_error_is_set(const sd_bus_error *e);
int sd_bus_error_has_name(const sd_bus_error *e, const char *name);
int sd_bus_error_has_names_sentinel(sd_bus_error *e, const char *name, ...);
int sd_bus_error_has_names(sd_bus_error *e, const char *name, ...);

DESCRIPTION

The sd_bus_error structure is used to store D-Bus error information, consisting of a name and a message. It may also store an errno-like integer error code. If the structure is not used, it should be initialized to SD_BUS_ERROR_NULL. This is a special value that initializes the structure so that both fields are set to NULL.

sd_bus_error_copy() copies an error from src to dst. If src is not set, then dst is reset to SD_BUS_ERROR_NULL. If dst is not set, it is initialized. This function may fail with -ENOMEM if a memory allocation fails.

sd_bus_error_move() is similar to sd_bus_error_copy(), but will move any error information from e into dst, resetting the former. This function cannot fail, as no new memory is allocated. Note that if e is not set, dst is initialized to SD_BUS_ERROR_NULL. Moreover, if dst is NULL no operation is executed on it and resources held by e are freed and reset. Returns a converted errno-like, non-positive error value.

sd_bus_error_is_set() will return a non-zero value if e is non-NULL and an error has been set, false otherwise.

sd_bus_error_has_name() will return a non-zero value if e is non-NULL and an error with the same name has been set, false otherwise.

sd_bus_error_has_names_sentinel() is similar to sd_bus_error_has_name(), but takes multiple names to check against. The list must be terminated with NULL. sd_bus_error_has_names() is a macro wrapper around sd_bus_error_has_names_sentinel() that adds the NULL sentinel automatically.

sd_bus_error_free() will destroy resources held by e. The parameter itself will not be deallocated, and must be free(3)d by the caller if necessary. The function may also be called safely on unset errors (error structures with both fields set to NULL), in which case it performs no operation. This call will reset the error structure after freeing the data, so that all fields are set to NULL. The structure may be reused afterwards.

REFERENCE OWNERSHIP

sd_bus_error is not reference-counted. Users should destroy resources held by it by calling sd_bus_error_free(). Usually, error structures are allocated on the stack or passed in as function parameters, but they may also be allocated dynamically, in which case it is the duty of the caller to free(3) the memory held by the structure itself after freeing its contents with sd_bus_error_free().

RETURN VALUE

The functions sd_bus_error_set(), sd_bus_error_setf(), and sd_bus_error_set_const() always return 0 when the specified error value is NULL, and a negative errno-like value corresponding to the name parameter otherwise. The functions sd_bus_error_set_errno(), sd_bus_error_set_errnof() and sd_bus_error_set_errnofv(), return 0 when the specified error value is 0, and a negative errno-like value corresponding to the error parameter otherwise. If an error occurs internally, one of the negative error values listed below will be returned. This allows those functions to be conveniently used in a return statement, see the example below.

sd_bus_error_get_errno() returns false when e is NULL, and a positive errno value mapped from e->name otherwise.

sd_bus_error_copy() and sd_bus_error_move() return a negative error value converted from the source error, and zero if the error has not been set. This allows those functions to be conveniently used in a return statement, see the example below.

sd_bus_error_is_set() returns a non-zero value when e and the name field are non-NULL, zero otherwise.

sd_bus_error_has_name(), sd_bus_error_has_names(), and sd_bus_error_has_names_sentinel() return a non-zero value when e is non-NULL and the name field is equal to one of the given names, zero otherwise.

Errors

Return value may indicate the following problems in the invocation of the function itself:

-EINVAL

Error was already set in the sd_bus_error structure when one the error-setting functions was called.

-ENOMEM

Memory allocation failed.

On success, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy(), and sd_bus_error_move() will return a negative converted errno-style value, or 0 if the error parameter is NULL or unset. D-Bus errors are converted to the integral errno-style value, and the mapping mechanism is extensible, see the discussion above. This effectively means that almost any negative errno-style value can be returned.

EXAMPLES

Example 1. Using the negative return value to propagate an error

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "Hello, World!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* On success, return the number of bytes written, possibly 0. */
  /* On error, initialize the error structure, and also propagate the errno
   * value that write(2) set for us. */
  return sd_bus_error_set_errnof(error, errno, "Failed to write to fd %i: %s", fd, strerror(errno));
}

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
