DESCRIPCIÓN

sd_bus_default() adquiere un objeto de conexión de bus al bus de usuario cuando se invoca dentro de un slice de usuario (cualquier sesión bajo "user-*.slice", por ejemplo: "user@1000.service"), o al bus del sistema en caso contrario. El objeto de conexión está asociado con el hilo que llama. Cada vez que la función se invoca desde el mismo hilo, se devuelve el mismo objeto, pero su recuento de referencias se incrementa en uno, siempre que se mantenga al menos una referencia. Cuando se suelta la última referencia a la conexión (usando la llamada sd_bus_unref(3)), la conexión se termina. Tenga en cuenta que la conexión no se termina automáticamente cuando el hilo asociado finaliza. Es importante soltar la última referencia a la conexión de bus explícitamente antes de que finalice el hilo, ya que, de lo contrario, la conexión tendrá una fuga. Además, los mensajes en cola pero no leídos o no escritos mantienen una referencia al bus, ver más abajo.

sd_bus_default_user() devuelve un objeto de conexión de bus de usuario asociado con el hilo que llama. sd_bus_default_system() es similar, pero se conecta al bus del sistema. Tenga en cuenta que sd_bus_default() es idéntico a estas dos llamadas, dependiendo del contexto de ejecución.

sd_bus_open() crea una nueva conexión de bus independiente al bus de usuario cuando se invoca en contexto de usuario, o al bus del sistema en caso contrario. sd_bus_open_user() es similar, pero se conecta solo al bus de usuario. sd_bus_open_system() hace lo mismo, pero se conecta al bus del sistema. En contraste con sd_bus_default(), sd_bus_default_user() y sd_bus_default_system(), estas llamadas devuelven objetos de conexión nuevos e independientes que no están asociados con el hilo que invoca y no se comparten entre múltiples invocaciones. Se recomienda compartir conexiones por hilo para aprovechar eficientemente los recursos disponibles. Por lo tanto, se recomienda usar sd_bus_default(), sd_bus_default_user() y sd_bus_default_system() para conectarse a los buses de usuario o del sistema.

sd_bus_open_with_description(), sd_bus_open_user_with_description() y sd_bus_open_system_with_description() son similares a sd_bus_open(), sd_bus_open_user() y sd_bus_open_system(), pero permiten establecer una cadena de descripción, ver sd_bus_set_description(3). description puede ser NULL, en cuyo caso esta función es equivalente a sd_bus_open(). Esta cadena de descripción se utiliza en mensajes de registro sobre el objeto de bus, y la inclusión de un "nombre" para el bus los hace más fáciles de entender. Algunos mensajes se emiten durante la inicialización del bus, por lo que usar esta función es preferible a establecer la descripción más tarde con sd_bus_open_with_description(). El argumento se copia internamente y no se referenciará después de que la función devuelva.

Si la variable de entorno $DBUS_SESSION_BUS_ADDRESS está establecida (consulte environ(7)), se utilizará como la dirección del bus de usuario. Esta variable puede contener múltiples direcciones separadas por ";". Si esta variable no está establecida, se utilizará un valor predeterminado adecuado para la instancia predeterminada de D-Bus de usuario.

Si la variable de entorno $DBUS_SYSTEM_BUS_ADDRESS está establecida, se utilizará como la dirección del bus del sistema. Esta variable utiliza la misma sintaxis que $DBUS_SESSION_BUS_ADDRESS. Si esta variable no está establecida, se utilizará un valor predeterminado adecuado para la instancia predeterminada de D-Bus del sistema.

sd_bus_open_system_remote() se conecta al bus del sistema en el host especificado utilizando ssh(1). host consta de un nombre de usuario opcional seguido del símbolo "@", y el nombre de host, opcionalmente seguido de un ":" y un puerto, opcionalmente seguido de un "/" y un nombre de máquina. Si se proporciona el nombre de la máquina, se crea una conexión al bus del sistema en el contenedor especificado en la máquina remota, y de lo contrario, se crea una conexión al bus del sistema en el host especificado.

Tenga en cuenta que entrar en un contenedor es una operación privilegiada, y probablemente solo funcionará para el usuario root en la máquina remota.

sd_bus_open_system_machine() se conecta al bus del sistema en la machine especificada, donde machine es el nombre de un contenedor local, posiblemente prefijado por un nombre de usuario y un separador "@". Si el nombre del contenedor se especifica como la cadena especial ".host", la conexión se realiza al host local. Esto es útil para conectarse al bus del sistema local como un usuario específico, por ejemplo, "foobar@.host" para conectarse al bus del sistema local como el usuario local "foobar". Si se utiliza la sintaxis "@", se puede omitir el lado izquierdo o el derecho (pero no ambos) en cuyo caso se implica el nombre de usuario local o ".host". Si no se utiliza la sintaxis "@", la conexión siempre se realiza como usuario root. Vea sd_bus_set_address(3) para una descripción de la sintaxis de la dirección, y machinectl(1) para más información sobre el concepto de "máquina". Tenga en cuenta que las conexiones a contenedores locales solo están disponibles para procesos privilegiados en este momento.

sd_bus_open_user_machine() es similar a sd_bus_open_system_machine(), pero se conecta al bus de usuario del usuario root, o si se utiliza la sintaxis "@", del usuario especificado.

Estas llamadas asignan un objeto de conexión de bus e inician la conexión a un bus bien conocido de algún tipo. Una alternativa a usar estas llamadas de alto nivel es crear un objeto de bus no conectado con sd_bus_new(3) y conectarlo con sd_bus_start(3).

PROPIEDAD DE REFERENCIAS

Las funciones sd_bus_open(), sd_bus_open_user(), sd_bus_open_user_machine(), sd_bus_open_system(), sd_bus_open_system_remote() y sd_bus_open_system_machine() devuelven un nuevo objeto de conexión y el llamante posee la única referencia. Cuando ya no se necesite, esta referencia debe destruirse con sd_bus_unref(3).

Las funciones sd_bus_default(), sd_bus_default_user() y sd_bus_default_system() no crean necesariamente un nuevo objeto, sino que aumentan la referencia de conexión de un objeto de conexión existente en uno. Use sd_bus_unref(3) para soltar la referencia.

Los mensajes en cola pero no escritos/leídos mantienen una referencia a su objeto de conexión de bus. Por esta razón, incluso si una aplicación soltó todas las referencias a una conexión de bus, es posible que no se destruya de inmediato. Hasta que se lean todos los mensajes entrantes en cola y hasta que se escriban todos los mensajes salientes no escritos, el objeto de bus permanecerá activo. sd_bus_flush() puede usarse para escribir todos los mensajes salientes en cola para que suelten sus referencias. Para vaciar los mensajes entrantes que no se han leído, el lector del bus debe leerlos. Si un hilo finaliza, su conexión de bus compartida se mantendrá activa como resultado de las referencias de los mensajes en cola no leídos/escritos.

DESCRIPCIÓN

Estas funciones se utilizan para obtener una conexión a un bus de mensajes de D-Bus. El bus de mensajes de D-Bus se utiliza para la comunicación entre procesos en sistemas tipo Unix.

La familia de funciones sd_bus_default_* devuelve una conexión al bus por defecto para el usuario o el sistema. El bus por defecto es un bus de D-Bus que está disponible globalmente y que se puede utilizar para la comunicación general entre procesos. El bus por defecto se gestiona automáticamente y su ciclo de vida está ligado al del proceso o hilo que lo creó.

Las funciones sd_bus_open_* devuelven una conexión a un bus de D-Bus específico. Estos buses pueden ser el bus del usuario, el bus del sistema, un bus de un sistema remoto o un bus asociado a una máquina concreta gestionada por systemd-machined.

El parámetro bus apunta a un puntero sd_bus que se inicializará con la nueva conexión al bus. Si la operación tiene éxito, el puntero bus apuntará a una estructura de conexión al bus válida. Si falla, se establecerá a NULL.

Las funciones sd_bus_open_with_description, sd_bus_open_user_with_description y sd_bus_open_system_with_description permiten especificar una descripción para la conexión del bus. Esta descripción se utilizará al registrar la conexión del bus en el demonio de D-Bus.

La función sd_bus_open_system_remote permite conectar a un bus de sistema en un host remoto especificado por hostname.

La función sd_bus_open_system_machine y sd_bus_open_user_machine permiten conectar a un bus de un sistema contenido (por ejemplo, un contenedor de systemd) identificado por machine.

Es responsabilidad del código que llama liberar la conexión al bus una vez que ya no se necesite. Esto se hace llamando a sd_bus_unref(3). Antes de liberar la conexión, se recomienda llamar a sd_bus_flush(3) para asegurarse de que todos los mensajes pendientes se envían.

En el caso de los buses por defecto, es importante tener en cuenta que el ciclo de vida de la conexión al bus está ligado al hilo o proceso que la creó. Si se necesita un ciclo de vida independiente, se deben usar las funciones sd_bus_open_* y gestionar explícitamente la conexión.

Si se utiliza el bus por defecto, es una buena práctica invocar primero sd_bus_flush() seguido de sd_bus_close() cuando un hilo o proceso termina, y por lo tanto su objeto de conexión al bus debe liberarse.

Normalmente, los objetos de slot (como los creados por sd_bus_add_match(3) y llamadas similares) también conservan una referencia a su objeto de conexión al bus. Por lo tanto, mientras un objeto de slot del bus permanezca referenciado, su objeto de bus también permanecerá asignado. Opcionalmente, los objetos de slot del bus pueden colocarse en modo "flotante". Cuando está en modo flotante, el ciclo de vida del objeto de slot del bus está ligado al objeto del bus, es decir, cuando el objeto del bus se libera, el objeto de slot del bus también se desreferencia automáticamente. El estado flotante de un objeto de slot puede controlarse explícitamente con sd_bus_slot_set_floating(3), aunque normalmente los objetos de slot de bus flotantes se crean pasando NULL como parámetro slot de sd_bus_add_match() y llamadas relacionadas, indicando así que el llamador no está directamente interesado en referenciar y gestionar el objeto de slot del bus.

El ciclo de vida de la conexión al bus por defecto debe ser responsabilidad del código que crea/posee el hilo al que está asociada la conexión al bus por defecto. El código de la biblioteca no debe llamar a sd_bus_flush() ni a sd_bus_close() en los objetos de bus por defecto, a menos que lo haga en su propio hilo privado y autoasignado. El código de la biblioteca no debe utilizar el objeto de bus por defecto en otros hilos a menos que esté claro que el programa que lo utiliza gestionará el ciclo de vida del objeto de conexión al bus y lo vaciará y cerrará antes de salir del hilo. En bibliotecas donde no está claro que el programa que llama gestionará el ciclo de vida del objeto de conexión al bus, se recomienda utilizar sd_bus_open_system() en lugar de sd_bus_default_system() y llamadas relacionadas.

VALOR DE RETORNO

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, estas llamadas devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Los parámetros especificados no son válidos.

-ENOMEDIUM

El tipo de bus solicitado no está disponible debido a un entorno inválido (por ejemplo, el bus de sesión del usuario no está disponible porque $XDG_RUNTIME_DIR no está establecido).

-ENOMEM

Fallo en la asignación de memoria.

-ESOCKTNOSUPPORT

La versión del protocolo requerida para conectarse al bus seleccionado no es compatible.

Además, pueden devolverse otros errores relacionados con la conexión. Véase sd_bus_send(3).

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar solo llamadas a setenv() desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
