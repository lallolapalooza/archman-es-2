SD_EVENT_EXIT(3) sd_event_exit SD_EVENT_EXIT(3)

NOMBRE

sd_event_exit, sd_event_get_exit_code - Solicitar la salida del bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>

int sd_event_exit(sd_event *event, int code);

int sd_event_get_exit_code(sd_event *event, int *ret);

DESCRIPCIÓN

sd_event_exit() solicita que el bucle de eventos especificado en el objeto de bucle de eventos event finalice. El parámetro code puede ser cualquier valor entero y es devuelto tal cual por sd_event_loop(3) después de la última iteración del bucle de eventos. También puede ser consultado usando sd_event_get_exit_code(), véase más abajo.

Cuando se solicita la salida, el bucle de eventos dejará de escuchar y despachar fuentes de eventos regulares. En su lugar, procederá con la ejecución solo de las fuentes de eventos registradas con sd_event_add_exit(3) en el orden definido por su prioridad. Después de que todas las fuentes de eventos de salida hayan sido despachadas, el bucle de eventos se terminará.

Si se invoca sd_event_exit() por segunda vez mientras el bucle de eventos todavía está procesando las fuentes de eventos de salida, el código de salida almacenado en el objeto del bucle de eventos se actualiza, pero por lo demás no se ejecuta ninguna otra operación.

sd_event_get_exit_code() puede ser utilizado para consultar el código de salida pasado a una llamada anterior de sd_event_exit(). El parámetro de retorno ret puede ser establecido a NULL, para simplemente verificar si sd_event_exit() ha sido llamado antes (ya que sd_event_get_exit_code() falla con -ENODATA si ese no es el caso, véase más abajo).

Mientras que el rango completo de enteros positivos y negativos puede ser utilizado para el código de salida, se debe tener cuidado de no elegir códigos de salida que entren en conflicto con los códigos de salida regulares devueltos por sd_event_loop(), si estos códigos de salida deben ser distinguibles.

Tenga en cuenta que para la mayoría de los tipos de fuentes de eventos, pasar el puntero de la función de retorno de llamada como NULL en la llamada del constructor respectivo (es decir, en sd_event_add_time(3), sd_event_add_signal(3), ...) tiene el efecto de que se invoque sd_event_exit() una vez que la fuente de eventos se active, con el puntero de datos de usuario especificado convertido a un entero como parámetro del código de salida. Esto es útil para terminar automáticamente un bucle de eventos después de alguna condición, como un tiempo de espera agotado o la recepción de SIGTERM o similar. Consulte la documentación de la llamada al constructor respectivo para obtener más detalles.

VALOR DE RETORNO

En caso de éxito, sd_event_exit() y sd_event_get_exit_code() devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

El objeto del bucle de eventos o el puntero del código de error no son válidos.

-ECHILD

El bucle de eventos se creó en un proceso, biblioteca o instancia de módulo diferente.

-ESTALE

El bucle de eventos ya ha finalizado y todos los manejadores de salida ya han sido procesados.

-ENODATA

Devuelto por sd_event_get_exit_code() en caso de que el bucle de eventos aún no haya sido solicitado para salir.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

sd_event_exit() y sd_event_get_exit_code() se añadieron en la versión 229.
