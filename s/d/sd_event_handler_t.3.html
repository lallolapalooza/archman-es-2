sd_event_handler_t(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_EVENT_ADD_DEFER(3) sd_event_add_defer SD_EVENT_ADD_DEFER(3)

NOMBRE

sd_event_add_defer, sd_event_add_post, sd_event_add_exit, sd_event_handler_t - Añadir fuentes de eventos estáticas a un bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_handler_t)(sd_event_source *s, void *userdata);

int sd_event_add_defer(sd_event *event, sd_event_source **source, sd_event_handler_t handler, void *userdata);

int sd_event_add_post(sd_event *event, sd_event_source **source, sd_event_handler_t handler, void *userdata);

int sd_event_add_exit(sd_event *event, sd_event_source **source, sd_event_handler_t handler, void *userdata);

DESCRIPCIÓN

Estas tres funciones añaden nuevas fuentes de eventos estáticas a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de eventos se devuelve en el parámetro source. Las fuentes de eventos se habilitan estáticamente y se "activarán" cuando se ejecute el bucle de eventos y se cumplan las condiciones descritas a continuación.

El handler es una función a llamar o NULL. La función manejadora recibirá el puntero userdata, que puede ser elegido libremente por el llamador. El manejador puede devolver un valor negativo para indicar un error (ver más abajo), otros valores de retorno se ignoran. Si handler es NULL, se utilizará un manejador por defecto que llama a sd_event_exit(3).

sd_event_add_defer() añade una nueva fuente de eventos que se despachará instantáneamente, antes de que el bucle de eventos vuelva a dormir y espere nuevos eventos. Por defecto, el manejador se llamará una vez (SD_EVENT_ONESHOT). Tenga en cuenta que si la fuente de eventos se establece en SD_EVENT_ON, el bucle de eventos nunca volverá a dormir, sino que llamará continuamente al manejador, posiblemente intercalado con otras fuentes de eventos.

sd_event_add_post() añade una nueva fuente de eventos que se ejecuta antes de que el bucle de eventos duerma y espere nuevos eventos, pero solo después de que se haya despachado al menos otra fuente de eventos no post. Por defecto, la fuente está habilitada permanentemente (SD_EVENT_ON). Tenga en cuenta que este tipo de fuente de eventos aún permitirá que el bucle de eventos duerma de nuevo, incluso si se establece en SD_EVENT_ON, siempre que nunca se active ninguna otra fuente de eventos.

sd_event_add_exit() añade una nueva fuente de eventos que se despachará cuando el bucle de eventos se termine con sd_event_exit(3).

La función sd_event_source_set_enabled(3) puede ser utilizada para habilitar la fuente de eventos permanentemente (SD_EVENT_ON) o para hacer que se active solo una vez (SD_EVENT_ONESHOT).

Si la función manejadora devuelve un código de error negativo, será deshabilitada después de la invocación, incluso si se solicitó el modo SD_EVENT_ON anteriormente, o causará que el bucle termine, ver sd_event_source_set_exit_on_failure(3).

Para destruir un objeto de fuente de eventos use sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se sueltan todas las referencias al objeto de fuente de eventos. Para asegurarse de que una fuente de eventos no se active más, incluso cuando todavía hay una referencia a ella, considere establecer la fuente de eventos en SD_EVENT_OFF con sd_event_source_set_enabled(3).

Si el segundo parámetro de estas funciones se pasa como NULL, no se devuelve ninguna referencia al objeto de fuente de eventos. En este caso, la fuente de eventos se considera "flotante", y se destruirá implícitamente cuando el propio bucle de eventos se destruya.

Si el parámetro handler a sd_event_add_defer() o sd_event_add_post() es NULL, y la fuente de eventos se activa, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a un entero, se pasa como el parámetro de código de salida a sd_event_exit(3). Una funcionalidad similar no está disponible para sd_event_add_exit(), ya que estos tipos de fuentes de eventos solo se despachan al salir de todos modos.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de fallo, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento inválido.

-ESTALE

El bucle de eventos ya está terminado.

-ECHILD

El bucle de eventos se ha creado en un proceso, biblioteca o instancia de módulo diferente.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIAL

sd_event_add_defer(), sd_event_add_post(), sd_event_add_exit(), y sd_event_handler_t() se añadieron en la versión 217.
