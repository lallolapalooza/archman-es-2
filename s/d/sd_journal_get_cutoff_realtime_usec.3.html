SD_JOURNAL_GET_CUTOFF_REALTIME_USEC(3) sd_journal_get_cutoff_realtime_usec SD_JOURNAL_GET_CUTOFF_REALTIME_USEC(3)

NOMBRE

sd_journal_get_cutoff_realtime_usec, sd_journal_get_cutoff_monotonic_usec - Leer marcas de tiempo de corte de la entrada actual del journal

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_get_cutoff_realtime_usec(sd_journal *j, uint64_t *from, uint64_t *to);

int sd_journal_get_cutoff_monotonic_usec(sd_journal *j, sd_id128_t boot_id, uint64_t *from, uint64_t *to);

DESCRIPCIÓN

sd_journal_get_cutoff_realtime_usec() recupera las marcas de tiempo en tiempo real (reloj de pared) de las primeras y últimas entradas accesibles en el journal. Toma tres argumentos: el objeto de contexto del journal j y dos punteros from y to que apuntan a enteros sin signo de 64 bits para almacenar las marcas de tiempo. Las marcas de tiempo están en microsegundos desde la época, es decir, CLOCK_REALTIME. Cualquiera de los dos argumentos de marca de tiempo puede pasarse como NULL en caso de que la marca de tiempo no sea necesaria, pero no ambos.

sd_journal_get_cutoff_monotonic_usec() recupera las marcas de tiempo monotónicas de las primeras y últimas entradas accesibles en el journal. Toma tres argumentos: el objeto de contexto del journal j, un identificador de 128 bits para el arranque boot_id, y dos punteros a enteros sin signo de 64 bits para almacenar las marcas de tiempo, from y to. Las marcas de tiempo están en microsegundos desde el arranque de un arranque específico, es decir, CLOCK_MONOTONIC. Dado que el reloj monotónico comienza de nuevo con cada reinicio, solo define un punto en el tiempo bien definido cuando se usa junto con un identificador que identifica el arranque, vea sd_id128_get_boot(3) para más información. La función devolverá las marcas de tiempo para el arranque identificado por el ID de arranque pasado. Cualquiera de los dos argumentos de marca de tiempo puede pasarse como NULL en caso de que la marca de tiempo no sea necesaria, pero no ambos.

VALOR DE RETORNO

sd_journal_get_cutoff_realtime_usec() y sd_journal_get_cutoff_monotonic_usec() devuelven 1 en caso de éxito, 0 si no hay entradas adecuadas en el journal o un código de error negativo estilo errno.

Las ubicaciones apuntadas por los parámetros from y to se establecerán solo si el valor de retorno es positivo, y obviamente, los parámetros no son nulos.

NOTAS

Todas las funciones listadas aquí son independientes de los hilos y solo un hilo puede operar en un objeto dado en un momento dado. Diferentes hilos pueden acceder al mismo objeto en diferentes momentos. Múltiples objetos independientes pueden usarse desde diferentes hilos en paralelo.

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo libsystemd pkg-config(1).

HISTORIA

sd_journal_get_cutoff_realtime_usec() y sd_journal_get_cutoff_monotonic_usec() se agregaron en la versión 187.
