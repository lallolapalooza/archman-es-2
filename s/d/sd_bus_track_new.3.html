void* sd_bus_track_set_userdata(sd_bus_track *t, void *userdata);

DESCRIPCIÓN

sd_bus_track_new() crea un nuevo objeto de rastreo de pares del bus. El objeto se asigna para el bus especificado y se devuelve en el parámetro *ret. Después de su uso, el objeto debe liberarse de nuevo soltando la referencia adquirida con sd_bus_track_unref() (ver más adelante). Un objeto de rastreo de pares del bus puede usarse para hacer seguimiento de los pares en un bus IPC específico, para casos en los que los pares hacen uso de uno o más objetos locales, con el fin de controlar el ciclo de vida de los objetos locales y garantizar que permanezcan mientras los pares que los necesitan estén presentes, y se desreferencien (y posiblemente se destruyan) tan pronto como todos los pares relevantes hayan desaparecido. Cada objeto de rastreo de pares del bus puede usarse para rastrear cero, uno o más pares a la vez. Las referencias a pares de bus específicos se añaden a través de sd_bus_track_add_name(3) o sd_bus_track_add_sender(). Pueden ser eliminadas de nuevo a través de sd_bus_track_remove_name() y sd_bus_track_remove_sender(). Alternativamente, las referencias a los pares se eliminan automáticamente cuando se desconectan del bus. Si no es NULL, el handler puede especificar una función que se invoca cada vez que se suelta la última referencia, independientemente de si la referencia se suelta explícitamente a través de sd_bus_track_remove_name() o implícitamente porque el par se desconectó del bus. El argumento final userdata puede usarse para adjuntar un puntero de datos de usuario genérico al objeto. Este puntero se pasa a la función de devolución de llamada del manejador cuando se invoca.

sd_bus_track_ref() crea una nueva referencia a un objeto de rastreo de pares del bus. Este objeto no se destruirá hasta que se haya llamado a sd_bus_track_unref() tantas veces más una. Una vez que el contador de referencias ha caído a cero, el objeto especificado ya no puede usarse, y las llamadas posteriores a sd_bus_track_ref() o sd_bus_track_unref() sobre el mismo objeto son ilegales.

sd_bus_track_unref() destruye una referencia a un objeto de rastreo de pares del bus.

sd_bus_track_unrefp() es similar a sd_bus_track_unref() pero toma un puntero a un puntero a un objeto sd_bus_track. Esta llamada es útil en conjunción con el **Atributo de Variable de Limpieza**[1] de GCC y LLVM. Tenga en cuenta que esta función está definida como una función en línea.

sd_bus_track_ref(), sd_bus_track_unref() y sd_bus_track_unrefp() no ejecutan ninguna operación si el objeto de rastreo de pares del bus proporcionado es NULL.

Los objetos de rastreo de pares del bus pueden existir en dos modos: por defecto operan en modo no recursivo, pero opcionalmente pueden cambiarse a modo recursivo. Si se opera en el modo no recursivo por defecto, un par se rastrea o no se rastrea. En este modo, invocar sd_bus_track_add_name() varias veces seguidas para el mismo par es completamente equivalente a llamarlo solo una vez, ya que la llamada añade el par al conjunto de pares rastreados si es necesario, y no ejecuta ninguna operación si el par ya está siendo rastreado. Una única invocación de sd_bus_track_remove_name() elimina la referencia al par nuevamente, independientemente de cuántas veces se llamó a sd_bus_track_add_name() antes. Si se opera en modo recursivo, el número de veces que se invoca sd_bus_track_add_name() para el mismo nombre de par se cuenta y se debe llamar a sd_bus_track_remove_name() el mismo número de veces antes de que el par ya no sea rastreado, con la excepción de cuando el par rastreado desaparece del bus, en cuyo caso el recuento es irrelevante y el rastreo del par específico se elimina inmediatamente. sd_bus_track_get_recursive() puede usarse para determinar si el objeto de rastreo de pares del bus está operando en modo recursivo. sd_bus_track_set_recursive() puede usarse para habilitar o deshabilitar el modo recursivo. Por defecto, un objeto de rastreo de pares del bus opera en modo no recursivo, y sd_bus_track_get_recursive() para un objeto recién asignado, por lo tanto, devuelve un valor igual a cero. Use sd_bus_track_set_recursive() para habilitar el modo recursivo, justo después de la asignación. Toma un argumento booleano para habilitar o deshabilitar el modo recursivo. Tenga en cuenta que los objetos de rastreo para los cuales sd_bus_track_add_name() ya se ha invocado al menos una vez (y que, por lo tanto, rastrean uno o más pares) ya no pueden cambiarse de modo recursivo a no recursivo.

sd_bus_track_get_bus() devuelve el objeto de bus al que pertenece el objeto de rastreo de pares del bus. Devuelve el objeto de bus inicialmente pasado a sd_bus_track_new() cuando se asignó el objeto.

sd_bus_track_get_userdata() devuelve el puntero de datos de usuario genérico establecido en el objeto de rastreo de pares del bus en el momento de la creación usando sd_bus_track_new() o en un momento posterior, usando sd_bus_track_set_userdata().

VALOR DE RETORNO

En caso de éxito, sd_bus_track_new() y sd_bus_track_set_recursive() devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo estilo errno.

sd_bus_track_ref() siempre devuelve el argumento.

sd_bus_track_unref() siempre devuelve NULL.

sd_bus_track_get_recursive() devuelve 0 si se selecciona el modo no recursivo (por defecto), y mayor que 0 si se selecciona el modo recursivo. En caso de error, se devuelve un código de error negativo estilo errno.

sd_bus_track_get_bus() devuelve el objeto de bus asociado al objeto de rastreo de pares del bus.

sd_bus_track_get_userdata() devuelve el puntero de datos de usuario genérico asociado con el objeto de rastreo de pares del bus. sd_bus_track_set_userdata() devuelve el puntero de datos de usuario previo establecido.

PROPIEDAD DE LA REFERENCIA

La función sd_bus_track_new() crea un nuevo objeto y el llamador posee la única referencia. Cuando ya no sea necesaria, esta referencia debe destruirse con sd_bus_track_unref().

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EBUSY

Ya se han añadido pares del bus al objeto de rastreo de pares del bus y se llamó a sd_bus_track_set_recursive() para cambiar el modo de rastreo.

-EINVAL

El parámetro especificado es inválido (NULL en el caso de los parámetros de salida).

-ENOMEM

Fallo en la asignación de memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para multihilo. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer solo llamadas a setenv() desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

El rastreo de pares del bus y las funciones relacionadas se añadieron en systemd versión 248.

sd_bus_track_new(3) — systemd 258.2

NAME

sd_bus_track_new, sd_bus_track_handler_t, sd_bus_track_ref, sd_bus_track_unref, sd_bus_track_unrefp, sd_bus_track_get_recursive, sd_bus_track_set_recursive, sd_bus_track_get_bus, sd_bus_track_get_userdata, sd_bus_track_set_userdata - Create and manage bus object tracking structures

SYNOPSIS

#include <systemd/sd-bus.h>
int sd_bus_track_new(sd_bus *bus, sd_bus_track **track, sd_bus_track_handler_t handler, void *userdata);
typedef int (*sd_bus_track_handler_t)(sd_bus_track *track, uint32_t flags, void *userdata);
sd_bus_track *sd_bus_track_ref(sd_bus_track *track);
void sd_bus_track_unref(sd_bus_track *track);
int sd_bus_track_unrefp(sd_bus_track **trackp);
int sd_bus_track_get_recursive(sd_bus_track *track);
int sd_bus_track_set_recursive(sd_bus_track *track, int recursive);
sd_bus *sd_bus_track_get_bus(sd_bus_track *track);
void *sd_bus_track_get_userdata(sd_bus_track *track);
int sd_bus_track_set_userdata(sd_bus_track *track, void *userdata);

DESCRIPTION

The sd_bus_track_* family of functions provide a mechanism for tracking specific object paths on a D-Bus connection and receiving notifications when messages are sent to these paths. This is useful for observing changes to specific objects or services without needing to register a separate listener for each individual message.

sd_bus_track_new() creates a new tracking structure associated with the given D-Bus connection bus. The handler function will be called with userdata whenever a message is sent to any of the paths registered with this track.

sd_bus_track_handler_t is the type for the callback function. It receives the tracking structure, flags (currently unused), and the user data associated with the track.

sd_bus_track_ref() and sd_bus_track_unref() manage the reference count of the tracking structure. sd_bus_track_unrefp() is a convenience function to set a pointer to NULL after unreferencing.

sd_bus_track_get_recursive() and sd_bus_track_set_recursive() control whether the tracking should be recursive. If set to non-zero, tracking will apply to all sub-paths of the registered paths as well.

sd_bus_track_get_bus() returns the D-Bus connection associated with the tracking structure.

sd_bus_track_get_userdata() and sd_bus_track_set_userdata() allow retrieving and setting arbitrary user data associated with the tracking structure.

RETURN VALUE

sd_bus_track_new() returns 0 on success, or a negative errno value on failure.

sd_bus_track_unrefp() returns a positive value if the pointer was not NULL and the tracking structure was freed, 0 otherwise.

sd_bus_track_get_recursive() returns 1 if recursive tracking is enabled, 0 otherwise.

sd_bus_track_get_bus() returns a pointer to the associated sd_bus object on success, and NULL on failure.

sd_bus_track_get_userdata() returns the user data pointer associated with the tracking structure.

REFERENCE OWNERSHIP

In order to use a sd_bus_track object, you must hold a reference to it. Call sd_bus_track_ref() to increment the reference count of an existing object. sd_bus_track_unref() must be called for each reference that is no longer needed. When the reference count drops to zero, the object is destroyed.

If you are passed a pointer to a sd_bus_track object from the library, the library does not hold a reference to it. You must call sd_bus_track_ref() immediately if you want to keep the object around.

If you are storing a sd_bus_track pointer in a variable, and want to pass ownership of the reference to the variable to a function, you may use sd_bus_track_unrefp(). This function will pass ownership of the reference in the variable to the function, and then set the variable to NULL.

NOTES

The handler function registered with sd_bus_track_new() is called asynchronously when messages are sent. The application should not block inside the handler function.

The specific paths to track must be added using sd_bus_track_add_name() after the track object has been created.

The userdata parameter can be used to associate arbitrary data with the tracking structure, for example, to pass context to the handler function.
