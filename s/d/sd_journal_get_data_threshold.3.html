SD_JOURNAL_GET_DATA(3) sd_journal_get_data SD_JOURNAL_GET_DATA(3)

NOMBRE

sd_journal_get_data, sd_journal_enumerate_data, sd_journal_enumerate_available_data, sd_journal_restart_data, SD_JOURNAL_FOREACH_DATA, sd_journal_set_data_threshold, sd_journal_get_data_threshold - Leer campos de datos de la entrada actual del registro

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_get_data(sd_journal *j, const char *field, const void **data, size_t *length);

int sd_journal_enumerate_data(sd_journal *j, const void **data, size_t *length);

int sd_journal_enumerate_available_data(sd_journal *j, const void **data, size_t *length);

void sd_journal_restart_data(sd_journal *j);

SD_JOURNAL_FOREACH_DATA(sd_journal *j, const void *data, size_t length);

int sd_journal_set_data_threshold(sd_journal *j, size_t sz);

int sd_journal_get_data_threshold(sd_journal *j, size_t *sz);

DESCRIPCIÓN

sd_journal_get_data() obtiene el objeto de datos asociado a un campo específico de la entrada actual del registro. Toma cuatro argumentos: el objeto de contexto del registro, una cadena con el nombre del campo a solicitar, más un par de punteros a variables de puntero/tamaño donde se almacenarán el objeto de datos y su tamaño. El nombre del campo debe ser un nombre de campo de entrada. Los nombres de campo conocidos se enumeran en systemd.journal-fields(7), pero se puede especificar cualquier campo. Los datos devueltos están en un mapa de memoria de solo lectura y solo son válidos hasta la próxima invocación de sd_journal_get_data(), sd_journal_enumerate_data(), sd_journal_enumerate_available_data(), o cuando el puntero de lectura se modifica. Tenga en cuenta que los datos devueltos irán precedidos por el nombre del campo y "=". Tenga en cuenta también que, por defecto, los campos de datos de más de 64K pueden truncarse a 64K. Este umbral puede modificarse y desactivarse con sd_journal_set_data_threshold() (ver más abajo).

sd_journal_enumerate_data() puede utilizarse para iterar a través de todos los campos de la entrada actual. En cada invocación se devuelven los datos del siguiente campo. El orden de estos campos no está definido. Los datos devueltos están en el mismo formato que con sd_journal_get_data() y también siguen la misma semántica de vida útil.

sd_journal_enumerate_available_data() es similar a sd_journal_enumerate_data(), pero omite silenciosamente cualquier campo que pueda ser válido, pero sea demasiado grande o no sea compatible con la implementación actual.

sd_journal_restart_data() reinicia el índice de enumeración de datos al principio de la entrada. La próxima invocación de sd_journal_enumerate_data() devolverá de nuevo el primer campo de la entrada.

Tenga en cuenta que la macro SD_JOURNAL_FOREACH_DATA() puede utilizarse como un práctico envoltorio alrededor de sd_journal_restart_data() y sd_journal_enumerate_available_data().

Tenga en cuenta que estas funciones no funcionarán antes de que sd_journal_next(3) (o llamada relacionada) se haya llamado al menos una vez, para posicionar el puntero de lectura en una entrada válida.

sd_journal_set_data_threshold() puede utilizarse para cambiar el umbral de tamaño de campo de datos para los datos devueltos por sd_journal_get_data(), sd_journal_enumerate_data() y sd_journal_enumerate_unique(). Este umbral es solo una pista: indica que el programa cliente solo está interesado en las partes iniciales de los campos de datos, hasta el umbral de tamaño; pero la biblioteca aún podría devolver objetos de datos más grandes. Eso significa que las aplicaciones no deben depender exclusivamente de esta configuración para limitar el tamaño de los campos de datos devueltos, sino que también deben aplicar un límite explícito de tamaño a los datos devueltos. Este umbral es de 64K por defecto. Para recuperar los campos de datos completos, este umbral debe desactivarse estableciéndolo en 0, de modo que la biblioteca siempre devuelva los objetos de datos completos. Se recomienda establecer este umbral lo más bajo posible, ya que esto libera a la biblioteca de tener que descomprimir objetos de datos grandes y comprimidos en su totalidad.

sd_journal_get_data_threshold() devuelve el umbral de tamaño de campo de datos configurado actualmente.

VALOR DE RETORNO

sd_journal_get_data() devuelve 0 en caso de éxito o un código de error negativo de estilo errno. sd_journal_enumerate_data() y sd_journal_enumerate_available_data() devuelven un entero positivo si se ha leído el siguiente campo, 0 cuando no quedan más campos o un código de error negativo de estilo errno. sd_journal_restart_data() no devuelve nada. sd_journal_set_data_threshold() y sd_journal_get_threshold() devuelven 0 en caso de éxito o un código de error negativo de estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Uno de los parámetros requeridos es NULL o inválido.

Añadido en la versión 246.

-ECHILD

El objeto de registro se creó en un proceso, biblioteca o instancia de módulo diferente.

Añadido en la versión 246.

-EADDRNOTAVAIL

El puntero de lectura no está posicionado en una entrada válida; sd_journal_next(3) o una llamada relacionada no se ha llamado al menos una vez.

Añadido en la versión 246.

-ENOENT

La entrada actual no incluye el campo especificado.

Añadido en la versión 246.

-ENOMEM

Fallo en la asignación de memoria.

Añadido en la versión 246.

-ENOBUFS

Una entrada comprimida es demasiado grande.

Añadido en la versión 246.

-E2BIG

El campo de datos es demasiado grande para este equipo (por ejemplo, superior a 4 GB en una arquitectura de 32 bits).

Añadido en la versión 246.

-EPROTONOSUPPORT

El registro está comprimido con un método no compatible o el registro utiliza una característica no compatible.

Añadido en la versión 246.

-EBADMSG

El registro está corrupto (posiblemente solo la entrada que se está iterando).

Añadido en la versión 246.

-EIO

El kernel informó de un error de E/S.

Añadido en la versión 246.

NOTAS

Todas las funciones aquí descritas son independientes de hilos y solo un hilo puede operar en un objeto dado en un momento dado. Diferentes hilos pueden acceder al mismo objeto en diferentes momentos. Se pueden utilizar múltiples objetos independientes desde diferentes hilos en paralelo.

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo libsystemd pkg-config(1).

EJEMPLOS

Ver sd_journal_next(3) para un ejemplo completo de cómo usar sd_journal_get_data().

Use la macro SD_JOURNAL_FOREACH_DATA() para iterar a través de todos los campos de la entrada actual del registro:

...
int print_fields(sd_journal *j) {
  const void *data;
  size_t length;
  SD_JOURNAL_FOREACH_DATA(j, data, length)
    printf("%.*s\n", (int) length, data);
}
...

sd_journal_get_data_threshold.3.en

NAME

sd_journal_get_data_threshold, sd_journal_set_data_threshold — get and set journal data size limits

SYNOPSIS

#include <systemd/sd-journal.h>

int sd_journal_get_data_threshold(const struct sd_journal *j, const char *field, size_t *ret_size);

int sd_journal_set_data_threshold(struct sd_journal *j, const char *field, size_t value);

DESCRIPTION

These functions allow querying and setting size limits for the data associated with journal fields. The sd_journal_get_data_threshold() function retrieves the current size limit for the journal field specified by field. The size limit is stored in the ret_size variable. If field is NULL, the limit for all fields is returned.

sd_journal_set_data_threshold() sets the size limit for the journal field specified by field to value. If field is NULL, the limit is set for all fields. A value of 0 disables the size limit.

The journal object j is the journal handle obtained from a previous call to sd_journal_open(3).

The field parameter refers to a journal field name, like "MESSAGE" or "CODE_FILE".

RETURN VALUE

On success, these functions return 0 or a positive integer. On failure, they return a negative errno-based error code.

sd_journal_get_data_threshold() returns -ENOMSG if no limit is set for the specified field.

NOTES

These functions are available as a library of the libsystemd. To link against it, use pkg-config(1) and pass --libs systemd to your compiler flags.

The size limits are applied per field for each journal entry. If a field's data exceeds the limit, it might be truncated or rejected, depending on the journal implementation.

EXAMPLES

Get the size limit for the MESSAGE field:

    struct sd_journal *j;
    size_t limit;
    int r;

    r = sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);
    if (r < 0) {
        fprintf(stderr, "Failed to open journal: %s\n", strerror(-r));
        exit(EXIT_FAILURE);
    }

    r = sd_journal_get_data_threshold(j, "MESSAGE", &limit);
    if (r == -ENOMSG) {
        printf("No specific limit set for MESSAGE.\n");
    } else if (r < 0) {
        fprintf(stderr, "Failed to get data threshold: %s\n", strerror(-r));
    } else {
        printf("Size limit for MESSAGE: %zu bytes\n", limit);
    }

    sd_journal_close(j);

Set the size limit for all fields to 1KB:

    struct sd_journal *j;
    int r;

    r = sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);
    if (r < 0) {
        fprintf(stderr, "Failed to open journal: %s\n", strerror(-r));
        exit(EXIT_FAILURE);
    }

    r = sd_journal_set_data_threshold(j, NULL, 1024);
    if (r < 0) {
        fprintf(stderr, "Failed to set data threshold: %s\n", strerror(-r));
    } else {
        printf("Global data threshold set to 1024 bytes.\n");
    }

    sd_journal_close(j);

HISTORY

The sd_journal_get_data_threshold() and sd_journal_set_data_threshold() functions were introduced in version 255.
