#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_io_handler_t)(sd_event_source *s, int fd, uint32_t revents, void *userdata);

int sd_event_add_io(sd_event *event, sd_event_source **source, int fd, uint32_t events, sd_event_io_handler_t handler, void *userdata);

DESCRIPCIÓN

sd_event_add_io() añade una nueva fuente de evento I/O a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de evento se devuelve en el parámetro source. El parámetro fd toma el descriptor de archivo UNIX a vigilar, que puede referirse a un socket, una FIFO, una cola de mensajes, una conexión serie, un dispositivo de caracteres, o cualquier otro descriptor de archivo compatible con epoll(7) de Linux. El parámetro events toma una máscara de bits de eventos a vigilar, una combinación de las siguientes banderas de evento: EPOLLIN, EPOLLOUT, EPOLLRDHUP, EPOLLPRI y EPOLLET, véase epoll_ctl(2) para más detalles. Tenga en cuenta que no todos los descriptores de archivo son compatibles con epoll, por ejemplo, los archivos regulares o directorios no lo son. Si esta función se llama con un descriptor de archivo que no soporta epoll, se devuelve -EPERM (también véase abajo). En la mayoría de los casos, dichos descriptores de archivo pueden tratarse como siempre-legibles o siempre-escribibles, por lo que la vigilancia de eventos I/O es innecesaria.

El handler es una función a llamar cuando la fuente de evento se dispara o NULL. El puntero userdata se pasará a la función manejadora, y puede ser elegido libremente por el llamador. Al manejador también se le pasará el descriptor de archivo en el que se vio el evento, así como las banderas de evento reales. Generalmente es un subconjunto de los eventos vigilados, sin embargo, puede incluir adicionalmente EPOLLERR y EPOLLHUP. El manejador puede devolver un valor negativo para señalar un error (véase abajo), otros valores de retorno se ignoran. Si handler es NULL, se usará un manejador por defecto que llama a sd_event_exit(3).

Por defecto, una fuente de evento permanece habilitada continuamente (SD_EVENT_ON), pero esto puede cambiarse con sd_event_source_set_enabled(3). Si la función manejadora devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si el modo SD_EVENT_ON se solicitó anteriormente, o provocará la terminación del bucle, véase sd_event_source_set_exit_on_failure(3). Tenga en cuenta que una fuente de evento configurada en SD_EVENT_ON se disparará continuamente a menos que se lean o escriban datos en el descriptor de archivo para restablecer la máscara de eventos vistos.

Establecer la máscara de eventos I/O a vigilar a 0 no significa que la fuente de evento no se disparará más, ya que EPOLLHUP y EPOLLERR pueden dispararse incluso con una máscara de eventos cero. Para deshabilitar temporalmente una fuente de evento I/O, use sd_event_source_set_enabled(3) con SD_EVENT_OFF en su lugar.

Para destruir un objeto de fuente de evento use sd_event_source_unref(3), pero tenga en cuenta que la fuente de evento solo se elimina del bucle de eventos cuando se sueltan todas las referencias a la fuente de evento. Para asegurarse de que una fuente de evento no se dispare más, incluso si todavía se referencia, deshabilite la fuente de evento usando sd_event_source_set_enabled(3) con SD_EVENT_OFF.

Si el segundo parámetro de sd_event_add_io() es NULL, no se devuelve ninguna referencia al objeto de la fuente de evento. En este caso, la fuente de evento se considera "flotante", y se destruirá implícitamente cuando el propio bucle de eventos sea destruido.

Si el handler de sd_event_add_io() es NULL, y la fuente de evento se dispara, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a entero, se pasa como parámetro de código de salida a sd_event_exit(3).

Tenga en cuenta que esta llamada no toma posesión del descriptor de archivo pasado, la propiedad (y por lo tanto el deber de cerrarlo cuando ya no se necesite) permanece con el llamador. Sin embargo, con la llamada sd_event_source_set_io_fd_own() (véase abajo) la fuente de evento puede opcionalmente tomar posesión del descriptor de archivo después de que la fuente de evento haya sido creada. En ese caso, el descriptor de archivo se cierra automáticamente tan pronto como se libera la fuente de evento.

Se recomienda usar sd_event_add_io() solo en conjunción con descriptores de archivo que tengan O_NONBLOCK establecido, para asegurar que todas las operaciones de I/O de los manejadores invocados sean adecuadamente asíncronas y no bloqueantes. El uso de descriptores de archivo sin O_NONBLOCK podría resultar en un hambre inesperada de otras fuentes de evento. Véase fcntl(2) para más detalles sobre cómo habilitar el modo O_NONBLOCK.

sd_event_source_get_io_events() recupera la máscara configurada de eventos I/O vigilados de una fuente de evento creada previamente con sd_event_add_io(). Toma el objeto de la fuente de evento y un puntero a una variable para almacenar la máscara.

sd_event_source_set_io_events() configura la máscara de eventos I/O vigilados de una fuente de evento creada previamente con sd_event_add_io(). Toma el objeto de la fuente de evento y la nueva máscara de eventos.

sd_event_source_get_io_revents() recupera la máscara de eventos I/O de eventos actualmente vistos pero no despachados de una fuente de evento creada previamente con sd_event_add_io(). Toma el objeto de la fuente de evento y un puntero a una variable para almacenar la máscara de eventos. Cuando se llama desde una función manejadora en el objeto de la fuente de evento del manejador, esto devolverá la misma máscara que se pasó al parámetro revents del manejador. Esta llamada es principalmente útil para verificar eventos no despachados de una fuente de evento desde el manejador de una fuente de evento no relacionada (posiblemente de mayor prioridad). Tenga en cuenta la relación entre sd_event_source_get_pending() y sd_event_source_get_io_revents(): ambas funciones informarán de resultados no nulos cuando haya un evento pendiente para la fuente de evento, pero la primera se aplica a todos los tipos de fuentes de evento, la segunda solo a las fuentes de evento I/O.

sd_event_source_get_io_fd() recupera el descriptor de archivo UNIX de una fuente de evento creada previamente con sd_event_add_io(). Toma el objeto de la fuente de evento y devuelve el descriptor de archivo no negativo o un número de error negativo en caso de error (véase abajo).

sd_event_source_set_io_fd() cambia el descriptor de archivo UNIX de una fuente de evento I/O creada previamente con sd_event_add_io(). Toma el objeto de la fuente de evento y el nuevo descriptor de archivo como parámetros. Si la fuente de evento poseía el descriptor de archivo anterior, es decir, si se había llamado a sd_event_source_set_io_fd_own() para la fuente de evento con un valor distinto de cero, entonces el descriptor de archivo anterior se cerrará y la fuente de evento también tomará la propiedad del nuevo descriptor de archivo en caso de éxito.

DESCRIPCIÓN

El descriptor de archivo dado se cerrará automáticamente cuando el origen del evento sea liberado o cuando el descriptor de archivo sea reemplazado por sd_event_source_set_io_fd(). Por defecto, el descriptor no es propiedad del origen del evento, y la aplicación tiene que cerrarlo por sí misma si es necesario.

sd_event_source_get_io_fd_own() puede ser utilizado para consultar la configuración actual del indicador booleano de propiedad del descriptor de archivo, tal como se estableció con sd_event_source_set_io_fd_own(). Devuelve un valor positivo si el descriptor de archivo se cierra automáticamente cuando el origen del evento se destruye, cero si no es así, y un valor negativo en caso de error.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de fallo, devuelven un código de error negativo estilo errno.

Errores

Los valores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento inválido.

-ESTALE

El bucle de eventos ya ha terminado.

-ECHILD

El bucle de eventos se creó en un proceso, biblioteca o instancia de módulo diferente.

-EDOM

El origen de eventos pasado no es un origen de eventos de E/S.

-EPERM

El descriptor de archivo pasado no soporta la API de epoll(7), por ejemplo porque es un archivo regular o un directorio. Véase epoll_ctl(2) para más detalles.

Añadido en la versión 255.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda solo llamar a setenv() desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
