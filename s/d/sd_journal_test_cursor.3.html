SD_JOURNAL_GET_CURSOR(3) sd_journal_get_cursor SD_JOURNAL_GET_CURSOR(3)

NOMBRE

sd_journal_get_cursor, sd_journal_test_cursor - Obtener una cadena de cursor para o probar una cadena de cursor contra la entrada del journal actual

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_get_cursor(sd_journal *j, char **ret_cursor);

int sd_journal_test_cursor(sd_journal *j, const char *cursor);

DESCRIPCIÓN

sd_journal_get_cursor() devuelve una cadena de cursor para la entrada del journal actual. Un cursor es una serialización de la posición actual del journal formateada como texto. La cadena solo contiene caracteres imprimibles y se puede pasar en forma de texto. El cursor identifica una entrada del journal de forma global y estable, y puede usarse para buscarla más tarde a través de sd_journal_seek_cursor(3). La cadena del cursor debe considerarse opaca y no ser analizada por los clientes. La búsqueda en una posición de cursor sin que la entrada específica esté disponible localmente buscará la entrada disponible más cercana (en términos de tiempo). La llamada toma dos argumentos: un contexto del journal y un puntero a un puntero de cadena donde se colocará la cadena del cursor. La cadena se asigna mediante malloc(3) de libc y debe liberarse después de su uso con free(3). El parámetro ret_cursor puede pasarse como NULL, en cuyo caso no se generará la cadena del cursor; sin embargo, el valor de retorno indicará si el contexto del journal está actualmente posicionado en una entrada y, por lo tanto, tiene un cursor asociado.

sd_journal_test_cursor() se puede usar para comprobar si la posición actual en el journal coincide con el cursor especificado. Esto es útil ya que las cadenas de cursor no identifican una entrada de forma única: la misma entrada puede ser referenciada por varias cadenas de cursor diferentes, y por lo tanto, no es posible comparar cadenas de cursores. Use esta llamada para verificar después de una invocación de sd_journal_seek_cursor(3) si la entrada buscada se encontró realmente en el journal o si se utilizó la entrada más cercana en su lugar.

Tenga en cuenta que sd_journal_get_cursor() y sd_journal_test_cursor() no funcionarán antes de que sd_journal_next(3) (o una de las otras funciones que se mueven a una entrada) se haya llamado al menos una vez para posicionar el puntero de lectura en una entrada válida.

VALOR DE RETORNO

sd_journal_get_cursor() devuelve 0 en caso de éxito o un código de error negativo de estilo errno. sd_journal_test_cursor() devuelve un valor positivo si la entrada actual coincide con el cursor especificado, 0 si no coincide con el cursor especificado o un código de error negativo de estilo errno en caso de fallo.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EADDRNOTAVAIL

El contexto del journal no está posicionado actualmente en ninguna entrada, y por lo tanto, no se puede generar ninguna cadena de cursor.

-EINVAL

El parámetro del contexto del journal es NULL.

-ECHILD

El objeto del contexto del journal se asignó en un proceso diferente al que se está utilizando ahora.

NOTAS

Todas las funciones listadas aquí son agnósticas a hilos y solo un hilo puede operar en un objeto dado en un momento dado. Diferentes hilos pueden acceder al mismo objeto en diferentes momentos. Se pueden usar múltiples objetos independientes desde diferentes hilos en paralelo.

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo libsystemd pkg-config(1).
