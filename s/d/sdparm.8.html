NOMBRE

sdparm - accede a las páginas de modo SCSI; lee páginas VPD; envía comandos SCSI simples.

SINOPSIS

sdparm [--all] [--dbd] [--examine] [--flexible] [--get=STR] [--hex] [--long] [--num-desc] [--out-mask=OM] [--page=PG[,SPG]] [--quiet] [--readonly] [--six] [--transport=TN] [--vendor=VN] [--verbose] DISPOSITIVO [DISPOSITIVO...]

sdparm [--clear=STR] [--defaults] [--dummy] [--flexible] [--page=PG[,SPG]] [--quiet] [--readonly] [--save] [--set=STR] [--six] [--transport=TN] [--vendor=VN] [--verbose] DISPOSITIVO [DISPOSITIVO...]

sdparm --command=CMD [--hex] [--long] [--readonly] [--verbose] DISPOSITIVO [DISPOSITIVO...]

sdparm --inquiry [--all] [--examine] [--flexible] [--hex] [--num-desc] [--page=PG[,SPG]] [--quiet] [--readonly] [--transport=TN] [--verbose] DISPOSITIVO [DISPOSITIVO...]

sdparm --enumerate [--all] [--inquiry] [--long] [--page=PG[,SPG]] [--transport=TN] [--vendor=VN]

sdparm --inhex=FN [--all] [--flexible] [--hex] [--inquiry] [--long] [--pdt=DT] [--raw] [--six] [--transport=TN] [--vendor=VN] [--verbose]

sdparm --wscan [--verbose]

sdparm [--help] [--version]

DESCRIPCIÓN

Esta utilidad recupera y potencialmente cambia las páginas de modo de dispositivos SCSI (por ejemplo, discos). También se pueden mostrar datos de consulta, incluyendo páginas de Datos de Producto Vital (VPD). Algunos comandos asociados con el inicio y parada del medio; carga y descarga del medio; y otras funciones de mantenimiento también pueden ser emitidos por esta utilidad.

La primera invocación mostrada en la sinopsis es para acceder (es decir, leer) campos de páginas de modo en el DISPOSITIVO. La segunda forma es para cambiar campos de páginas de modo en el DISPOSITIVO. La tercera forma es para ejecutar algunos comandos SCSI simples. La cuarta forma (es decir, la forma '--inquiry' ... DISPOSITIVO) es para recuperar y decodificar páginas VPD del DISPOSITIVO dado. La forma --enumerate es para listar los datos de campos de modo o VPD que mantiene esta utilidad (y si se proporciona un DISPOSITIVO, se ignora). La forma '--inhex=FN' decodifica datos de respuesta de modo o VPD proporcionados en el archivo nombrado (o desde la entrada estándar si se proporciona FN=-); esos datos pueden estar en hexadecimal o binario. La penúltima forma es solo para Windows y lista los nombres de dispositivos de almacenamiento disponibles; consulte la entrada de OPCIONES para --wscan. La forma final es para proporcionar ayuda en la línea de comandos o el número de versión (y fecha) de esta utilidad.

Si no se proporcionan opciones (aparte de DISPOSITIVO), se enumeran una selección de campos de página de modo comunes para ese dispositivo. Si también se proporciona la opción --long, se coloca una descripción de los campos a la derecha de cada línea. Si se proporciona la opción --all, se enumeran todos los campos de página de modo conocidos para ese dispositivo. Los campos individuales se pueden mostrar con la opción --get=STR (por ejemplo, '--get=WCE' para obtener el estado del campo Writeback Cache Enable).

Esta utilidad completa con un estado de salida de 0 cuando tiene éxito. Para otros valores, consulte la sección ESTADO DE SALIDA a continuación.

Se pueden proporcionar uno o más argumentos DISPOSITIVO. La utilidad aplicará esencialmente las opciones dadas a cada DISPOSITIVO de la lista. Si se detecta un error, se anota y la utilidad continúa. El valor de error 5 (problema al abrir o cerrar el archivo) se trata como de menor prioridad cuando se detectan otros errores. El estado de salida es el valor de error detectado más recientemente (excluyendo el valor de error 5 si se han detectado otros errores). Si todas las acciones tienen éxito, el estado de salida es cero.

Por defecto, esta utilidad muestra páginas de modo que son comunes a todos los protocolos de transporte. Estas se denominan páginas de modo "genéricas". Si no hay coincidencia en un nombre o campo de página de modo genérico, se comprueban las páginas específicas del transporte SAS. Las páginas de modo específicas del protocolo de transporte se seleccionan con la opción --transport=TN. Consulte la sección TRANSPORTE a continuación. Las páginas de modo específicas del proveedor se seleccionan con la opción --vendor=VN. Consulte la sección PROVEEDORES a continuación.

Aunque originalmente para discos SCSI (o dispositivos de almacenamiento que aparecen al SO como discos SCSI), muchas de las páginas de modo son para otros tipos de dispositivos SCSI. Estos incluyen reproductores de CD/DVD que utilizan el transporte ATAPI (o cualquier otro), unidades de cinta SCSI y gabinetes SCSI.

Cuando se proporciona la opción --inquiry sin un número de página, se solicita la página VPD de Identificación del Dispositivo (número de página 0x83) y si se encuentra, se decodifica y se muestra. Si no se proporciona un número de página y se proporciona la opción --all, se muestra una lista de nombres de páginas VPD (pero no su contenido) compatibles con el DISPOSITIVO. Cuando tanto las opciones --inquiry como --page=PG se proporcionan, la página VPD se puede especificar como una abreviatura (por ejemplo, "sp" para la página VPD de puertos SCSI) o numéricamente (por ejemplo, "0x88"). Si el DISPOSITIVO devuelve una página VPD pero sdparm no puede decodificarla o se proporciona la opción --hex, se muestra en formato hexadecimal.

OPCIONES

Los argumentos obligatorios para las opciones largas son obligatorios también para las opciones cortas. Si una opción toma un argumento numérico, ese argumento se asume decimal a menos que se indique lo contrario (por ejemplo, con un prefijo "0x" o un sufijo "h"). Las opciones están en orden alfabético, basado en el nombre de la opción larga.

-a, --all
muestra todos los campos reconocidos para el tipo de dispositivo (por ejemplo, disco) del DISPOSITIVO. Sin esta opción (o la opción --page=PG[,SPG]), la acción predeterminada es mostrar un número relativamente pequeño de campos de uso común de diferentes páginas. Cuando se proporciona un número de página (de modo) específico con la opción --page=PG[,SPG], se muestran todos los campos de esa página (independientemente del ajuste de esta opción). Para la acción de esta opción cuando se usa con la opción --enumerate, consulte la sección ENUMERATE.
Cuando se usa junto con la opción --inquiry y un DISPOSITIVO, se muestra la página VPD Páginas VPD Soportadas (página 0x0). Cuando se usa esta opción dos veces (forma corta: '-iaa'), se muestran todas las páginas VPD (listadas en la página VPD Páginas VPD Soportadas).
Por defecto, --inhex=FN solo decodificará la primera página de modo encontrada en FN. Con esta opción, se decodificarán más páginas de modo si están presentes. Cuando también se proporciona --transport=TN o --vendor=VN, si una página de modo dada no está definida para ese transporte o proveedor, se decodifica como una página de modo genérica.
-c, --clear=STR
En su forma más simple, STR contiene un acrónimo_nombre de campo o un descriptor numérico de campo. En ausencia de un argumento de valor explícito (por ejemplo, '--clear=WCE=1'), el campo tiene su valor limpiado a cero. Consulte la sección PARÁMETROS.
-C, --command=CMD
Realiza el CMD dado. Consulte la sección COMANDOS más abajo. Para enumerar comandos soportados, use '-e -C x' (usando cualquier nombre de CMD, válido o no).
-B, --dbd
deshabilita descriptores de bloque. Este es un bit en los cdb MODE SENSE que rara vez necesita ser establecido. Un caso conocido es un MODE SENSE 6 emitido a un dispositivo de Comandos de Bloque Reducido (RBC) donde el estándar RBC dice que debe ser establecido.
-D, --defaults
establece la página de modo dada a sus valores predeterminados. Requiere que se proporcione la opción --page=PG[,SPG] para especificar la página de modo. Para que los valores predeterminados de la página de modo también sean los valores guardados, use también la opción --save.
cuando esta opción se usa dos veces, los valores actuales en todas las páginas de modo se revierten a sus valores predeterminados. Si la opción --save también se proporciona, entonces los valores actuales y guardados en todas las páginas de modo se revierten a sus valores predeterminados. Esta característica utiliza el bit RTD en el comando MODE SELECT que se agregó en el borrador SPC-5 revisión 11.
-d, --dummy
cuando se establece, inhibe los cambios que se colocan en la página de modo del DISPOSITIVO. En su lugar, los datos de modo que se habrían enviado t

-e, --enumerate
enumera información descriptiva sobre las páginas y campos conocidos por esta utilidad. Ignora el argumento DEVICE y otras opciones aparte de --all, --inquiry, --long, --page=PG[,SPG], --transport=TN y --vendor=VN. Si se proporciona --enumerate sin otras opciones, se enumeran las páginas de modo conocidas (genéricas). Consulte la sección ENUMERATE a continuación.
-E, --examine
para las páginas de modo, solo se sondean aquellas con nombres de campo conocidos cuando se proporciona la opción --all. Para las páginas VPD, solo se decodifican las páginas enumeradas en "Supported VPD pages page". En ambos casos, es posible que falten algunas páginas. Con esta opción (es decir, --examine) se pueden sondear todas las páginas de modo y VPD.
Para las páginas de modo, esta opción sondeará todas las páginas de modo desde el número de página 0x0 hasta 0x3e. Para sondear subpáginas de modo, proporcione un número de página de modo con --page=PG y luego se sondearán todas las subpáginas (de 0x0 a 0xfe).
Para las páginas VPD, use esta opción con --inquiry. Esto hará que se sonden todas las páginas VPD de 0x0 a 0xc0 por defecto. Se puede sondear una secuencia de páginas VPD con --page=PG[,SPG], en cuyo caso se sondearán las páginas VPD desde PG (número inferior) hasta SPG (número superior) inclusive. Las páginas VPD específicas del proveedor van de 0xc0 a 0xff y se pueden sondear configurando SPG de 0xc0 a 0xff.
-f, --flexible
Algunos dispositivos, puentes y/o controladores intentan transformaciones rudimentarias entre comandos de modo de 6 y 10 bytes sin reconstruir correctamente la respuesta. Esto hará que la respuesta se interprete incorrectamente (generalmente con un error que indica que la respuesta está mal formada). Con esta opción, se verifica la longitud de la respuesta y, si parece incorrecta, se intentan varias correcciones. Esta opción también permitirá enumerar páginas de modo que no pertenezcan al tipo de periférico del dispositivo actual.
-g, --get=STR
En su forma más simple, STR contiene un acrónimo de campo o un descriptor numérico de campo. El campo se recupera de la página de modo. Consulte la sección PARÁMETROS a continuación. Las opciones --long y --hex afectan el formato de salida. Además, si se proporciona un valor de "1" (por ejemplo, '--get=WCE=1'), solo se muestra el valor actual (es decir, no la máscara de cambio, el valor predeterminado y el valor guardado).
-h, --help
muestra el mensaje de uso y sale.
-H, --hex
en lugar de intentar decodificar páginas de modo (o VPD), las muestra en hexadecimal. Cuando se usa con la opción --get=STR, los valores actuales, modificables, predeterminados y guardados correspondientes se muestran en hexadecimal, precedidos por "0x" y separados por espacios. Si se proporciona un valor de "1" con la opción --get=STR (por ejemplo, '--get=WCE=1'), solo se muestra el valor actual en hexadecimal, precedido por "0x". Si se proporciona un valor de "2" con la opción --get=STR, solo se muestra el valor actual como un entero (con signo). Esta opción se puede usar varias veces (por ejemplo, '-HH'). Útil con la página VPD de información ATA, que generalmente muestra su respuesta IDENTIFY (PACKET) DEVICE en palabras hexadecimales de 16 bits; con '-HH' muestra esa respuesta en bytes hexadecimales; con '-HHH' muestra la misma respuesta en un formato adecuado para que 'hdparm --Istdin' la decodifique.
La salida de la página de modo con la opción '-HHH' es adecuada para una invocación posterior de sdparm con la opción --inhex=FN.
-i, --inquiry
muestra una página VPD que se encuentra en la respuesta de un comando SCSI INQUIRY enviado a DEVICE. En ausencia de esta opción, la acción predeterminada es mostrar páginas de modo. Si se proporciona la opción --inquiry sin la opción --page=PG[,SPG], se decodifica y muestra la página VPD de identificación del dispositivo (0x83). Si se proporcionan esta opción y la opción --all, se decodifica y muestra la página de páginas VPD admitidas (0x0).
Si se proporcionan esta opción y la opción --all, se decodifica y muestra la página de páginas VPD admitidas (0x0).
-I, --inhex=FN
FN se espera que sea un nombre de archivo (o '-' para stdin) que contenga hexadecimal ASCII (o binario) que represente la respuesta a MODE SENSE(10). Si también se proporciona --six, se asume la respuesta de MODE SENSE(6). Una respuesta MODE SENSE contiene una cabecera de parámetros de modo, luego 0 o más descriptores de bloque seguidos de una o más páginas de modo. Esta utilidad solo decodificará la primera página de modo a menos que se proporcione la opción --all. Para decodificar una página de modo, a menudo se necesita el tipo de dispositivo periférico y se puede suministrar con la opción --pdt=DT. Si no se proporciona --pdt=DT, una página de modo encontrada en dos estándares de tipo de dispositivo (por ejemplo, SBC y SSC) puede decodificarse dos veces.
Si se proporciona --inquiry, FN se interpreta como los datos de respuesta de una única página VPD.
El hexadecimal en FN debe organizarse como 1 o 2 dígitos que representen un byte cada uno, separados por espacios en blanco o comas. Se ignora todo desde un signo de almohadilla hasta el final de la línea. Si se proporciona la opción --raw, FN se trata como binario.
-l, --long
muestra información adicional. En el caso de los campos de la página de modo, se muestra una descripción (con unidades si corresponde) a la derecha. Si se usa dos veces, entonces para algunos campos se proporciona más información sobre sus valores en una o más líneas siguientes, cada una precedida por un carácter de tabulación. Para su uso con --enumerate, consulte la sección ENUMERATE a continuación.
Cuando esta opción se usa junto con --command=capacity, se envía el comando READ CAPACITY(16) a DEVICE y, si tiene éxito, se muestra su respuesta extendida.
-n, --num-desc
para una página de modo que pueda tener descriptores, se muestra el número de descriptores para la página dada en DEVICE. De lo contrario, se muestra 0.
-o, --out-mask=OM
OM es una máscara de bits para selecciones de páginas de modo que se imprimirán/mostrarán. El valor 0x1 es para los valores 'actuales', 0x2 es para los valores 'modificables', 0x4 es para los valores 'predeterminados' y 0x8 es para los valores 'guardables'. El valor predeterminado es 0xf (es decir, el OR de los cuatro valores establecidos). La opción es útil para limitar la cantidad de salida con '-HHH'.
-p, --page=PG[,SPG]
suministra el número de página (PG) y opcionalmente el número de subpágina (SPG) de la página de modo (o VPD) a recuperar. Estos números se interpretan como decimales a menos que vayan precedidos por "0x" o un sufijo. Los números de subpágina solo son válidos para las páginas de modo (no para las páginas VPD). Alternativamente, se puede proporcionar una abreviatura para una página (ver siguiente entrada).
-p, --page=STR
se puede proporcionar una abreviatura de dos o tres letras para una página. Primero se buscan las abreviaturas de página de modo conocidas, seguidas de las abreviaturas de página VPD conocidas. Por ejemplo, '--page=ca' corresponde a la página de modo de almacenamiento en caché. Si no se encuentra ninguna coincidencia, se emite un error y se proporciona una lista de posibilidades en el contexto actual (por lo que '-p x' puede ser bastante útil). Si STR coincide con una abreviatura de página VPD conocida, se asume la opción --inquiry. Para su uso con --enumerate, consulte la sección ENUMERATE a continuación.
-P, --pdt=DT
Esta opción solo está activa cuando se proporciona la opción --inhex=FN. DT es el Tipo de Dispositivo periférico, un valor entre 0 y 31 y se puede encontrar en la respuesta al comando INQUIRY. El valor predeterminado es -1 (que también se puede proporcionar para DT) y se interpreta como SPC (es decir, páginas de modo comunes) o como un comodín. Si está disponible, esta opción debe proporcionarse con la opción --inhex=FN.
-q, --quiet
suprime la salida del nombre del dispositivo seguido de las cadenas del fabricante, producto y revisión obtenidas de una respuesta INQUIRY. Sin esta opción, dicha línea suele ser la primera línea que muestra sdparm. Reduce la salida de la página VPD de identificación del dispositivo, típicamente a una línea (o ninguna) para cada uno de di_lu, di_port, di_target y di_asis.
Si esta opción se usa dos veces, además suprime en la salida de las páginas de modo los valores modificables, predeterminados y guardados que generalmente se muestran entre corchetes, si están disponibles.
-r, --readonly
anula otra lógica para abrir DEVICE en modo de solo lectura. La configuración predeterminada del modo de apertura de solo lectura/lectura-escritura depende de la operación solicitada (por ejemplo, una operación --set=STR intentará por defecto abrir DEVICE en modo de lectura-escritura). Esta opción puede ser útil si un comando se envía a un disco ATA a través de un conjunto de comandos SCSI. Por ejemplo, en Linux, '-C stop' puede requerir esta opción para evitar que un disco ATA se reinicie inmediatamente.
-R, --raw
esta opción solo está activa cuando se usa con la opción --inhex=FN. Cuando se proporciona esta opción, el archivo FN se interpreta como binario; la acción predeterminada (es decir, cuando no se proporciona esta opción) es interpretar FN como hexadecimal ASCII.
-S, --save
cuando se está modificando una página de modo (usando las opciones --clear=STR y/o --set=STR), la acción predeterminada es modificar solo la página de valores actuales. Cuando se proporciona esta opción, también se cambian los valores correspondientes en la página de valores guardados. La próxima vez que el dispositivo se reinicie (o se restablezca), la página de valores guardados se convierte en (es decir, se copia a) la página de valores actuales. Esta opción establece el campo SP en el comando MODE SELECT. Consulte la sección NOTAS a continuación.
-s, --set=STR
en su forma más simple, STR contiene un acrónimo de campo o un descriptor numérico de campo. En ausencia de un valor explícito, cada acrónimo tiene su valor establecido en unos (todos). Esto significa que un campo de 16 bits se establecerá en 0xffff, que son 65535 en decimal. Alternativamente, cada acrónimo o descriptor numérico puede ir seguido de "=<n>", donde <n> es el valor al que se establecerá ese campo. Consulte la sección PARÁMETROS a continuación.
-6, --six
La acción predeterminada de esta utilidad es emitir comandos SCSI MODE SENSE y MODE SELECT con CDB de 10 bytes. Cuando se proporciona esta opción, se usan las variantes de CDB de 6 bytes. RBC y dispositivos SCSI antiguos
que esta opción. Este utilidad produce una sugerencia para usar esta opción si el estado SCSI indica que la variante de cdb de 10 bytes no es compatible.
El estándar SPC-4 (y los borradores de SPC-5) incluyen una nota que indica que los implementadores migran de los comandos SCSI MODE SELECT(6) y MODE SENSE(6) a favor de las variantes de 10 bytes (por ejemplo, MODE SEMSE(10)).
-t, --transport=TN
Especifica el protocolo de transporte donde TN es un número en el rango de 0 a 15 (inclusive) o una abreviatura (por ejemplo, "fcp" para el Protocolo Fibre Channel). Algunos transportes aceptan múltiples abreviaturas, por ejemplo, srp (SCSI RDMA Protocol) e ib (abreviatura de InfiniBand) son aceptados para el protocolo de transporte 0x4. También se aceptan mayúsculas y minúsculas, por lo que iscsi e iSCSI son aceptados para el protocolo de transporte 0x5. Una forma de listar los números de protocolos de transporte disponibles y sus abreviaturas asociadas es dar un nombre de protocolo de transporte no válido como '-t x'; otra forma es '-e -l'. Nota: La opción --all aún puede ser necesaria para mostrar todos los campos disponibles.
-M, --vendor=VN
Especifica el proveedor (es decir, el fabricante) donde VN es un número (0 o más) o una abreviatura (por ejemplo, "sea" para el proveedor específico de discos Seagate). Para unidades de cinta "lto5" y "lto6" se tratan como proveedores. Una forma de listar los números de proveedor disponibles y sus abreviaturas asociadas es dar un número de proveedor no válido como '-M x'; otra forma es '-e -l'.
Esta opción solo afecta a la decodificación de páginas de modo, no a las páginas VPD. Para páginas VPD específicas del proveedor, consulte la utilidad sg_vpd.
-v, --verbose
aumenta el nivel de verbosidad (es decir, salida de depuración). En algunos casos, se realiza una decodificación adicional (por ejemplo, campos dentro de una respuesta INQUIRY estándar).
-V, --version
imprime la cadena de versión y luego sale.
-w, --wscan
esta opción solo está disponible en Windows. Enumera los nombres de los dispositivos de almacenamiento y los volúmenes correspondientes, si los hay. Cuando se usa dos veces, agrega el "tipo de bus" del transporte más cercano (por ejemplo, un disco SATA en una carcasa conectada por USB tiene el tipo de bus Usb). Cuando se usa tres veces, se agrega un escaneo del adaptador SCSI. Cuando se usa cuatro veces, solo se muestra un escaneo del adaptador SCSI. Consulte los ejemplos a continuación y la sección "Win32 port" en el archivo README.

NOTAS

El documento de referencia utilizado para interpretar las páginas de modo y VPD (y la respuesta estándar INQUIRY) es T10/BSR INCITS 502 Revisión 17 (SPC-5, 19 de septiembre de 2017) que se encuentra en http://www.t10.org . Los elementos obsoletos y reservados en la salida de la respuesta estándar INQUIRY se muestran entre corchetes. También se utilizan borradores recientes de otros documentos T10: SBC-4 (discos), SSC-5 (cintas), SPL-5 (transporte SAS) y SAT-4 (Traducción SCSI a ATA).

Una página de modo para la que no se conoce abreviatura (por ejemplo, una página de modo específica del proveedor) se puede mostrar en hexadecimal utilizando la combinación de opciones '--page=PG --hex'.

Los números introducidos en sdparm (por ejemplo, en los argumentos de la línea de comandos) se asumen en decimal a menos que haya un indicador hexadecimal. Un indicador hexadecimal es '0x' o '0X' (es decir, la convención del lenguaje C) o una 'h' o 'H' al final (es decir, la convención utilizada en www.t10.org). En el caso de --page= se espera una cadena o un número, por lo que los números hexadecimales como 'ch' (12) deben ir precedidos de un cero (por ejemplo, '0ch').

El borrador SPC-4 (rev 2) dice que los dispositivos que no implementan ninguna distinción entre páginas actuales y guardadas pueden devolver un error (SOLICITUD ILEGAL, campo no válido en cdb) si el bit SP (que corresponde a la opción --save) NO está establecido. En tales casos, se debe dar la opción --save.

Si se proporciona la opción --save pero la página de modo existente indica (a través de su bit PS) que la página no se puede guardar, entonces esta utilidad genera un mensaje de error. Ese mensaje sugiere volver a intentarlo sin la opción --save.

Dado que la página VPD de identificación del dispositivo (nombre de acrónimo "di") contiene potencialmente muchos designadores diversos, hay varios acrónimos asociados disponibles. Son "di_lu" para los designadores asociados con la unidad lógica direccionada, "di_port" para los designadores asociados con el puerto de destino (a través del cual llegó el comando) y "di_target" para los designadores asociados con el dispositivo de destino. Cuando se usa "di", los designadores se agrupan por lu, luego por puerto y luego por dispositivo de destino. Para ver todos los designadores decodificados en el orden en que aparecen en la página VPD, use "di_asis".

Esta utilidad solo decodifica las páginas VPD definidas por t10.org. SPC-4 reserva los códigos de páginas VPD de 0xc0 a 0xff (inclusive) para páginas específicas del proveedor, algunas de las cuales se decodifican en la utilidad sg_vpd.

Para ver todas las páginas VPD compatibles con un DISPOSITIVO, use 'sg_vpd --all'.

En el kernel de Linux de las series 2.6 y 3, cualquier nodo de dispositivo que entienda un conjunto de comandos SCSI (por ejemplo, discos SCSI y unidades de CD/DVD) puede especificarse. Más precisamente, el controlador que "posee" el nodo del dispositivo debe admitir el ioctl SG_IO. En la serie lk 2.4, solo los nodos de dispositivo genéricos SCSI (sg) admiten el ioctl SG_IO. Sin embargo, en la serie lk 2.4, otros nodos de dispositivo SCSI se mapean dentro de esta utilidad a sus nodos de dispositivo sg correspondientes. Por lo tanto, si hay un disco SCSI en /dev/sda, entonces 'sdparm /dev/sda' funcionará tanto en la serie lk 2.4 como en las posteriores. Sin embargo, si hay una unidad de CD/DVD ATAPI en /dev/hdc, entonces 'sdparm /dev/hdc' solo funcionará en la serie lk 2.6 y posteriores.

En Linux 2.6 y 3, especialmente con discos ATA, usar sdparm para detener (apagar) un disco puede no ser suficiente y otros mecanismos pueden volver a iniciar el disco poco tiempo después. El usuario podría marcar adicionalmente el disco como "offline" con 'echo offline > /sys/block/sda/device/state' donde sda es el nombre del bloque del disco. Para reiniciar el disco, "offline" se puede reemplazar con "running".

PARÁMETROS

En su forma más simple, las opciones --clear=, --get= y --set= (o sus formas cortas) toman un nombre de acrónimo como "WCE". En el caso de '--get=WCE', se obtendrá el valor de "Writeback Cache Enable" en la página de modo de caché. En el caso de '--set=WCE', ese bit se establecerá (a uno). En el caso de '--clear=WCE', ese bit se borrará (a cero). Cuando se proporciona un nombre de acrónimo, la página de modo se infiere de ese nombre de acrónimo (por ejemplo, WCE está en la página de modo de caché).

En lugar de un nombre de acrónimo, un campo dentro de una página de modo se puede describir numéricamente con una tupla <byte_inicio>:<bit_inicio>:<num_bits>. Estos son el <byte_inicio> (origen 0) dentro de la página de modo, un <bit_inicio> (0 a 7 inclusive) y <num_bits> (1 a 64 inclusive). Por ejemplo, la representación de bajo nivel del bit RCD (el bit "Read Cache Disable" en la página de modo de caché) es "2:0:1". El <byte_inicio> se puede dar opcionalmente en hexadecimal (por ejemplo, '--set=0x2:0:1' o '--set=2h:0:1'). Con esta forma, la opción --page= es necesaria para establecer qué página de modo se va a utilizar.

Cualquiera de las formas puede ir seguida opcionalmente de "=<val>". Por defecto, <val> está en decimal, pero se puede proporcionar en hexadecimal de la forma habitual. Aquí hay algunos ejemplos: '--set=2h:0:1=1h' y '-s MRIE=0x3'. Cuando el nombre de acrónimo o la forma numérica que sigue a --clear= no se proporciona un '=<val>' explícito, el valor por defecto es cero. Cuando el nombre de acrónimo o la forma numérica que sigue a --set= no se proporciona un '=<val>' explícito, el valor por defecto es "todos unos" (es decir, tantos como permita <num_bits>). Por ejemplo, '--clear=WCE' y '--clear=WCE=0' tienen el mismo significado: borrar Writeback Cache Enable o, dicho de forma más sencilla: desactivar la caché de escritura diferida.

Se pueden cambiar varios campos dentro de la misma página de modo proporcionando una lista separada por comas de nombres de acrónimos y/o la forma numérica. Por ejemplo: '--set=TEST,MRIE=6'.

Algunas páginas de modo tienen múltiples descriptores. Típicamente tienen una sección de encabezado fija al principio de la página de modo que incluye un campo que contiene el número de descriptores que siguen. Después del encabezado hay un número variable de descriptores. Un ejemplo es la página de modo SAS Phy Control and Discover. Un nombre de acrónimo puede incluir un '.<num>' al final, donde "<num>" es un número de descriptor (origen 0). Por ejemplo, '-t sas -g PHID.0' y '-t sas -g PHID' producirán el identificador de phy del primer descriptor de la página de modo anterior; '-t sas -g PHID.1' producirá el identificador de phy del segundo descriptor.

PARÁMETROS DE MODO

Los parámetros de modo para los cuales num_bits es mayor que 1 se pueden ver como enteros sin signo. A menudo, los campos de 16 y 32 bits se establecen en 0xffff y 0xffffffff respectivamente (todos unos), lo que generalmente tiene un significado especial (ver borradores). Esta utilidad muestra dichos valores como "-1" para ahorrar espacio (en lugar de sus equivalentes de entero sin signo). "-1" también se puede proporcionar como el valor para un acrónimo de campo de página de modo (por ejemplo, '--set=INTT=-1' establece el campo del temporizador de intervalo en la página de modo de control de excepciones de información en 0xffffffff).

TRANSPORTES

Los protocolos de transporte SCSI son un área relativamente especializada que puede ser ignorada de forma segura por la mayoría de los usuarios.

Algunos protocolos de transporte tienen páginas de modo específicas del protocolo. Estas son generalmente las páginas de modo de desconexión-reconexión (0x2), unidad lógica específica del protocolo (0x18) y puerto específico del protocolo (0x19). En algunos casos, esta última página de modo tiene varias subpáginas. Las abreviaturas de protocolos de transporte más comunes que probablemente se utilizarán son "fcp", "spi" y "sas".

Muchos de los nombres de campo se reutilizan en la misma posición, por lo que los espacios de nombres de acrónimos se han dividido entre páginas de modo genéricas (es decir, cuando la opción --transport= _no_ se proporciona) y un espacio de nombres para cada protocolo de transporte. Se incluyen un campo LUPID de la unidad lógica específica del protocolo (0x18) y el campo PPID del puerto específico del protocolo (0x19) en las páginas de modo genéricas; esto es para que se puedan ver los identificadores de protocolo (de transporte) respectivos. En la mayoría de los casos, el usuario sabrá cuál es el transporte del "puerto" (es decir, el mismo transporte que la HBA en la computadora), pero el transporte de la unidad lógica podría ser diferente.

PROVEEDORES

SCSI deja mucho espacio para información específica del proveedor. A menudo, esto se describe en los manuales del producto. La opción --vendor=VN (o -M=VN) permite examinar y/o modificar páginas de modo conocidas específicas del proveedor por acrónimo.

En esta utilidad, la sintaxis y la semántica de las páginas de modo específicas del proveedor son muy similares a las de las páginas de modo específicas del protocolo de transporte. No se pueden especificar ambas juntas. Las páginas de modo específicas del proveedor aún se pueden acceder numéricamente (como se muestra al final de la sección EJEMPLOS).

COMANDOS

La opción de comando envía un comando SCSI al DEVICE. Si el comando falla, esto se refleja en el estado de salida no nulo. Para obtener más información sobre el error, utilice la opción -v.

capacidad
envía un comando READ CAPACITY(10) (válido para discos y medios de cd/dvd) por defecto. Si tiene éxito, produce "bloques: " [el número de bloques], "longitud_bloque: " [típicamente 512 o 2048] y "capacidad_mib: " [capacidad en MebiBytes (unidades de 1048576 bytes)].

Si el número de bloques es demasiado grande para caber en el campo de 4 bytes proporcionado por READ CAPACITY(10) o si se proporciona la opción --long, se envía el comando READ CAPACITY(16). Si se proporciona la opción --long, se muestran los campos adicionales encontrados en la respuesta de READ CAPACITY(16).

expulsar
detiene el medio y lo expulsa del dispositivo. Tenga en cuenta que la expulsión (por comando o botón) puede ser impedida, en cuyo caso el comando 'desbloquear' puede ser útil en casos extremos. Típicamente, solo es apropiado para unidades de cd/dvd y unidades de disco con medios extraíbles. Objetos si se envía a otro tipo de dispositivo periférico (pero la objeción se puede anular con la opción '-f').
cargar
carga el medio y lo inicia (es decir, lo hace girar). Consulte el comando 'expulsar' para conocer los tipos de dispositivos compatibles.
perfil
enumera los diversos formatos que admite una unidad de CD/DVD/HD-DVD/BD. Estos se llaman "perfiles" en el estándar MMC. Los perfiles se enumeran uno por línea. Si hay medios en la unidad, el perfil que coincide con los medios (si lo hay) tiene un "*" a la derecha de la línea.
listo
envía el comando SCSI "Test Unit Ready" al DEVICE. No se informa ningún error si el dispositivo responderá a las solicitudes de datos (por ejemplo, READ) en un tiempo razonable. Por ejemplo, si un disco está detenido, informará "no listo". Todos los dispositivos deben responder a este comando.
sentido
envía un comando REQUEST SENSE. Informa si se ha superado un umbral de hardware, una advertencia o una condición de baja potencia si se marca. Si hay una indicación de progreso (por ejemplo, durante un formato), se mostrará como un porcentaje. Produce un estado de proceso de 0 si el comando tiene éxito y la clave de sentido es 0; de lo contrario, produce 1. La opción --quiet se puede usar para reducir la salida, y --hex para mostrar los datos de sentido en hexadecimal.
velocidad=VELOCIDAD
permite que la velocidad de un disco CD, DVD, HD_DVD o BD en una unidad se establezca (o al menos se influencie). Tiene este formato: --command=speed=VELOCIDAD donde VELOCIDAD está en kilobytes por segundo. En este caso, un kilobyte es 1000 bytes. La velocidad "por uno" para un CD es de 176.4 kB/s, para un DVD es de 1350 kB/s y para HD-DVD y BD es de 4500 kB/s. Si VELOCIDAD es cero, la unidad se establece a la velocidad que considera que proporciona un rendimiento óptimo. Este comando envía un comando multimedia SET STREAMING (MMC) a la unidad. El bit EXACT se borra, por lo que la unidad redondeará la VELOCIDAD dada según sea necesario. El comando está diseñado para controlar la velocidad de lectura; la configuración de la velocidad de escritura debe dejarse a los programas de "grabado".
iniciar
inicia el medio (es decir, lo hace girar). Inofensivo si el medio ya se ha iniciado. Consulte el comando 'expulsar' para conocer los tipos de dispositivos compatibles. Si el DEVICE es un disco ATA en Linux, puede ser necesaria la opción '--readonly'.
detener
detiene el medio (es decir, lo apaga). Inofensivo si el medio ya se ha detenido. Consulte el comando 'expulsar' para conocer los tipos de dispositivos compatibles. Si el DEVICE es un disco ATA en Linux, puede ser necesaria la opción '--readonly'. Consulte la sección NOTAS anterior.
sincronizar
envía un comando SYNCHRONIZE CACHE. El dispositivo debe vaciar los datos que tenga en sus búferes (volátiles) a los medios.
desbloquear
indica a un dispositivo que permita la extracción del medio. Utiliza el comando SCSI "prevent allow medium removal". Esto es un último recurso, que posiblemente anula una prevención aplicada por el sistema operativo en un sistema de archivos montado. La utilidad "eject" (del paquete "eject") es más elegante y debe probarse primero. Este comando solo es apropiado para dispositivos con medios extraíbles.

Para cargar y expulsar cintas, se debe utilizar la utilidad mt (es decir, no estos comandos). El comando 'ready' es válido para dispositivos de cinta.

EJEMPLOS

Para listar los parámetros de modo comunes (genéricos) de un disco:


sdparm /dev/sda

Para listar los designadores dentro de la página VPD de identificación del dispositivo de un disco:


sdparm --inquiry /dev/sda

Para ver todos los parámetros de la página de modo de caché:


sdparm --page=ca /dev/sda

Para ver todos los parámetros de la página de modo de caché con descripciones de parámetros a la derecha:


sdparm --page=ca --long /dev/sda

Para obtener los valores WCE (actuales, cambiables, predeterminados y guardados) en hexadecimal:


sdparm -g WCE -H /dev/sda
0x01 0x00 0x01 0x01

Para obtener el valor actual de WCE en hexadecimal:


sdparm -g WCE=1 -H /dev/sda
0x01

Para establecer el bit "Writeback Cache Enable" en la página de valores actuales:


sdparm --set=WCE /dev/sda

Para establecer el bit "Writeback Cache Enable" en la página de valores actuales y guardados:


sdparm --set=WCE --save /dev/sda

Para establecer "Writeback Cache Enable" y borrar "Read Cache Disable":


sdparm --set=WCE --clear=RCD --save /dev/sda

El ejemplo anterior también se puede escribir como:


sdparm -s WCE=1,RCD=0 -S /dev/sda

Para restablecer los valores predeterminados del fabricante en los valores actuales y guardados de la página de modo de caché:


sdparm --page=ca --defaults --save /dev/sda

Si una unidad de cd/dvd ATAPI está en /dev/hdc, sus parámetros de modo comunes podrían enumerarse en las series lk 2.6 y 3 con:


sdparm /dev/hdc

Si hay un DVD en la unidad en /dev/hdc, se podría expulsar en las series lk 2.6 y 3 con:


sdparm --command=eject /dev/hdc

Si la expulsión está siendo impedida por software, esto se puede anular con:


sdparm --command=unlock /dev/hdc

Un proveedor de discos tiene un bit de "Modo de Rendimiento" (PM) en la página de modo de atención de unidad específica del proveedor [0x0,0x0]. PM=0 es modo servidor (el predeterminado) mientras que PM=1 es modo escritorio. El modo de escritorio se puede establecer (valores actuales y guardados) con:


sdparm --page=0 --set=2:7:1=1 --save /dev/sda

El cambio resultante se puede ver en hexadecimal con la opción --hex ya que todavía no hay acrónimos para extensiones de proveedor. El bit PM ahora está cubierto por páginas de modo específicas del proveedor y lo anterior también se puede lograr con:


sdparm --vendor=sea --set=PM --save /dev/sda

A continuación se muestran algunos ejemplos de Windows que utilizan la opción '--wscan'. La idea es enumerar los nombres de los dispositivos de almacenamiento en el sistema que podrían ser invocados por otros usos de sdparm.


# sdparm --wscan
PD0 [C] FUJITSU MHY2160BH 0000
PD1 [DF] WD 2500BEV External 1.05 WD-WXE90
CDROM0 [E] MATSHITA DVD/CD

RW UJDA775 CB03

So 'sdparm -a CDROM0' y 'sdparm -a E' mostrarán todos los campos (conocidos) de página de modo para la unidad DVD/CD Matshita. Utilizando la opción '--wscan' dos veces, se añade el tipo de bus (visto por el SO) a la salida:


# sdparm -ww
PD0 [C] <Ata > FUJITSU MHY2160BH 0000
PD1 [DF] <Usb > WD 2500BEV External 1.05 WD-WXE90
CDROM0 [E] <Atapi> MATSHITA DVD/CDRW UJDA775 CB03

Y el patrón continúa añadiendo un escaneo de adaptador SCSI. Esto puede ser útil si hay dispositivos especializados relacionados con el almacenamiento (por ejemplo, un dispositivo SES en una carcasa), pero en este caso no añade mucha información adicional.


# sdparm -www
PD0 [C] <Ata > FUJITSU MHY2160BH 0000
PD1 [DF] <Usb > WD 2500BEV External 1.05 WD-WXE90
CDROM0 [E] <Atapi> MATSHITA DVD/CDRW UJDA775 CB03

SCSI0:0,0,0 reclamado=1 pdt=0h FUJITSU MHY2160BH 0000
SCSI1:0,0,0 reclamado=1 pdt=5h MATSHITA DVD/CDRW UJDA775 CB03

ESTADO DE SALIDA

Para ayudar a los scripts que llaman a sdparm, el estado de salida se establece para indicar éxito (0) o fallo (1 o más). Tenga en cuenta que algunos de los valores más bajos corresponden a los valores de clave de sentido SCSI. Los valores del estado de salida son:

0
éxito
1
error de sintaxis. Opciones de línea de comandos ilegales, opciones con argumentos incorrectos o una combinación de opciones que no está permitida.
2
el DISPOSITIVO informa que no está listo para la operación solicitada. El dispositivo puede estar en proceso de estar listo (por ejemplo, girando pero no a la velocidad) por lo que la utilidad puede funcionar después de una espera.
3
el DISPOSITIVO informa un error de medio o hardware (o un chequeo en blanco). Por ejemplo, un intento de leer un bloque corrupto en un disco producirá este valor.
5
el DISPOSITIVO informa una "solicitud ilegal" con un código de sentido adicional distinto de "código de operación inválido". A menudo se trata de un comando soportado con un campo establecido que solicita una capacidad no soportada. Para comandos que requieren un campo de "acción de servicio", este valor puede indicar que el comando no es compatible.
6
el DISPOSITIVO informa una condición de "atención de unidad". Esto generalmente indica que algo no relacionado con el comando solicitado ha ocurrido (por ejemplo, un reinicio del dispositivo) potencialmente antes de que se enviara el comando SCSI actual. El dispositivo no ha ejecutado el comando solicitado. Tenga en cuenta que las condiciones de atención de unidad generalmente solo son reportadas una vez por un dispositivo.
7
el DISPOSITIVO informa una clave de sentido de "protección de datos". Esto implica que algún mecanismo ha bloqueado las escrituras (o posiblemente todo el acceso al medio).
9
el DISPOSITIVO informa una solicitud ilegal con un código de sentido adicional de "código de operación inválido", lo que significa que no soporta el comando solicitado.
10
el DISPOSITIVO informa una "copia abortada". Esto implica que otro comando o problema del dispositivo ha detenido una operación de copia. La familia de comandos EXTENDED COPY (incluyendo WRITE USING TOKEN) puede devolver esta clave de sentido.
11
el DISPOSITIVO informa un comando abortado. En algunos casos, los comandos abortados se pueden reintentar inmediatamente (por ejemplo, si el transporte abortó el comando debido a congestión).
14
el DISPOSITIVO informa una clave de sentido de "comparación errónea". Los comandos VERIFY y COMPARE AND WRITE pueden reportar esto.
15
la utilidad no puede abrir, cerrar o usar el DISPOSITIVO dado. El nombre de archivo dado podría ser incorrecto o puede haber problemas de permisos. Añadir la opción -v puede dar más información.
20
el DISPOSITIVO informa que tiene una condición de chequeo pero "sin sentido". Algunos comandos de sondeo (por ejemplo, REQUEST SENSE) pueden reaccionar de esta manera. Es poco probable que este valor ocurra como estado de salida.
21
el DISPOSITIVO informa un "error recuperado". El comando solicitado fue exitoso. Lo más probable es que una utilidad informe un error recuperado a stderr y continúe, dejando probablemente la utilidad con un estado de salida de 0.
22
el DISPOSITIVO informa que el comando actual o sus parámetros implican una dirección de bloque lógica (LBA) que está fuera de rango.
24
el DISPOSITIVO informa un estado SCSI de "conflicto de reserva". Esto significa que el acceso al DISPOSITIVO con el comando actual ha sido bloqueado porque otra máquina (HBA o "iniciador" SCSI) tiene una reserva en este DISPOSITIVO. En los sistemas SCSI modernos, esto está relacionado con el uso de la familia de comandos PERSISTENT RESERVATION.
25
el DISPOSITIVO informa un estado SCSI de "condición cumplida". Actualmente, solo el comando PRE-FETCH (ver SBC-4) produce este estado.
26
el DISPOSITIVO informa un estado SCSI de "ocupado". SAM-5 define este estado como que la unidad lógica no está temporalmente en condiciones de procesar un comando. Se recomienda volver a emitir el comando.
27
el DISPOSITIVO informa un estado SCSI de "conjunto de tareas lleno".
28
el DISPOSITIVO informa un estado SCSI de "ACA activo". ACA es "auto contingent allegiance" y rara vez se usa.
29
el DISPOSITIVO informa un estado SCSI de "tarea abortada". SAM-5 dice: "Este estado se devolverá si un comando es abortado por una función de comando o gestión de tareas en otro nexo I_T y el bit TAS de la página de modo Control está establecido en uno".
33
el comando enviado al DISPOSITIVO ha caducado. Esto ocurre solo en Linux; en otros puertos, un tiempo de espera de comando aparecerá como un error de transporte (o SO).
40
el comando enviado al DISPOSITIVO ha recibido una clave de sentido de "comando abortado" con un código de sentido adicional de 0x10. Este valor está relacionado con problemas de información de protección (PI o DIF). Por ejemplo, este error puede ocurrir al leer un bloque en una unidad que nunca se ha escrito (o no está mapeada) si esa unidad fue formateada con protección de tipo 1, 2 o 3.
48
este es un mensaje interno que indica que un campo de estado NVMe (SF) es distinto de cero después de que se ha ejecutado un comando (es decir, algo salió mal). El trabajo en esta área es actualmente experimental.
49
el controlador de bajo nivel informa que el recuento residual de una respuesta (es decir, el número de bytes realmente recibidos por la HBA es 'bytes_solicitados - recuento_residual') es demasiado alto. Por lo tanto, no se puede realizar ningún procesamiento útil con esa respuesta.
50 + <número_de_error_so>
Las llamadas del sistema SO que fallan a menudo devuelven un número entero pequeño para ayudar a indicar cuál es el error. Por ejemplo, en Unix, la incapacidad de una llamada del sistema para asignar memoria devuelve (en 'errno') ENOMEM, que a menudo se asocia con el entero 12. Por lo tanto, se puede devolver 62 (es decir, '50 + 12') por una utilidad en este caso.
97
la respuesta a un comando SCSI falló las comprobaciones de cordura.
98
el DISPOSITIVO informa que tiene una condición de chequeo pero el error no encaja en ninguna de las categorías anteriores.
99
cualquier error que no se pueda categorizar en los valores 1 a 98 puede producir este valor. Esto incluye errores de transporte y del sistema operativo después de que el comando se haya enviado al dispositivo.
126
se encontró la utilidad pero no se pudo ejecutar. Eso podría ocurrir si el ejecutable no tiene permisos de ejecución.
127
Este es el estado de salida para la utilidad no encontrada. Eso podría ocurrir cuando un script llama a una utilidad en este paquete pero la variable de entorno PATH no se ha configurado correctamente, por lo que el script no puede encontrar el ejecutable.
128 + <núm_señal>
Si una señal mata una utilidad, el estado de salida es 128 más el número de señal. Por ejemplo, si ocurre un fallo de segmentación, una utilidad típicamente es matada por SIGSEGV que, según 'man 7 signal', tiene un número de señal asociado de 11; por lo tanto, el estado de salida será 139.
255
la utilidad intentó producir un estado de salida de 255 o superior. Eso no debería suceder; se proporciona aquí por completitud.

La mayoría de las condiciones de error reportadas anteriormente serán repetibles (un ejemplo de una que no lo es es "atención de unidad"), por lo que la utilidad se puede ejecutar de nuevo con la opción -v (o varias) para obtener más información.
