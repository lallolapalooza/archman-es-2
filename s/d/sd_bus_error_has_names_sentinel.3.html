DESCRIPCIÓN

La estructura sd_bus_error contiene información sobre una condición de error de D-Bus, o la falta de ella. Las funciones descritas a continuación pueden ser utilizadas para establecer y consultar campos en esta estructura.

•El campo nombre contiene un identificador corto de un error. Debe seguir las reglas para nombres de error descritas en la especificación D-Bus, subsección Nombres D-Bus Válidos[1]. Un número de nombres de error comunes y estandarizados se describen en sd-bus-errors(3), pero las aplicaciones pueden definir errores adicionales específicos del dominio.
•El campo mensaje generalmente contiene una cadena legible por humanos que describe los detalles, pero puede ser NULL.

Una estructura sd_bus_error no establecida debe tener ambos campos inicializados a NULL, y significa la falta de un error, es decir, éxito. Asigna SD_BUS_ERROR_NULL a la estructura para inicializar ambos campos a NULL. Cuando ya no sean necesarios, los recursos retenidos por la estructura sd_bus_error deben ser destruidos con sd_bus_error_free().

sd_bus_error_set() establece una estructura de error a los nombres y mensajes especificados. Las cadenas se copiarán en memoria interna, recién asignada. Es esencial liberar el contenido nuevamente cuando ya no sean requeridos (ver arriba). No uses esta llamada en estructuras de error que ya hayan sido establecidas. Si pretendes reutilizar una estructura de error, libera los datos antiguos almacenados en ella con sd_bus_error_free() primero.

sd_bus_error_set() devolverá un valor similar a errno (ver errno(3)) determinado a partir del nombre del error especificado nombre. Si nombre es NULL, se asume que no ocurrió ningún error, y se devuelve 0. Si nombre no es nulo, siempre se devolverá un valor negativo. Si e es NULL, no se inicializa ninguna estructura de error, pero nombre aún se convierte en un valor de estilo errno.

Varios errores D-Bus bien conocidos se convierten en contrapartes errno bien conocidas, y los demás a -EIO. Ver sd-bus-errors(3) para una lista de nombres de error bien conocidos. Se pueden definir mapeos de errores adicionales con sd_bus_error_add_map(3).

sd_bus_error_set() está diseñado para ser utilizado convenientemente en una instrucción return. Si mensaje es NULL, no se establece ningún mensaje. Esta llamada puede fallar si no se puede asignar memoria para las cadenas de nombre y mensaje, en cuyo caso se establecerá un error SD_BUS_ERROR_NO_MEMORY y se devolverá -ENOMEM.

sd_bus_error_setf() y sd_bus_error_setfv() son similares a sd_bus_error_set(), pero toman una cadena de formato printf(3) y argumentos correspondientes para generar el campo mensaje. sd_bus_error_setf() usa argumentos variádicos, y sd_bus_error_setfv() acepta los argumentos como una lista de parámetros va_arg(3).

sd_bus_error_set_const() es similar a sd_bus_error_set(), pero los parámetros de cadena no se copian internamente, y por lo tanto deben permanecer constantes y válidos durante la vida útil de e. Usa esta llamada para evitar asignaciones de memoria al establecer estructuras de error. Dado que esta llamada no asigna memoria, no fallará con una condición de falta de memoria como puede hacerlo sd_bus_error_set(), como se describe anteriormente. Alternativamente, la macro SD_BUS_ERROR_MAKE_CONST() puede ser utilizada para generar una estructura de error literal y constante sobre la marcha.

sd_bus_error_set_errno() devolverá inmediatamente 0 si el parámetro de error especificado error es 0. De lo contrario, establecerá nombre a partir de un valor similar a errno que se convierte a un error D-Bus. Se utilizará strerror_r(3) para establecer mensaje. Se utilizarán nombres de error D-Bus bien conocidos para nombre si es aplicable, de lo contrario se generará un nombre en el espacio de nombres "System.Error.". Se ignora el signo del número de error especificado y se utiliza implícitamente su valor absoluto. Si el error especificado error no es cero, la llamada siempre devuelve un valor negativo, para un uso conveniente en sentencias return. Esta llamada podría fallar debido a falta de memoria, en cuyo caso se establece un error SD_BUS_ERROR_NO_MEMORY y se devuelve -ENOMEM.

sd_bus_error_set_errnof() y sd_bus_error_set_errnof() son similares a sd_bus_error_set_errno(), pero además de error, toman una cadena de formato printf(3) y argumentos correspondientes. El campo mensaje se generará a partir de formato y los argumentos. sd_bus_error_set_errnof() usa argumentos variádicos, y sd_bus_error_set_errnofv() acepta los argumentos como una lista de parámetros va_arg(3).

sd_bus_error_get_errno() convierte el campo nombre de una estructura de error a un valor (positivo) similar a errno utilizando las mismas reglas que sd_bus_error_set(). Si e es NULL, se devolverá 0.

sd_bus_error_copy() inicializará dst usando los valores en e, si e se estableció previamente con un valor de error. De lo contrario, devolverá inmediatamente. Si las cadenas en e se establecieron usando sd_bus_error_set_const(), se compartirán. De lo contrario, se copiarán. Antes de esta llamada, dst debe estar no establecida, es decir, recién inicializada con NULL o restablecida usando sd_bus_error_free().

sd_bus_error_move() es similar a sd_bus_error_copy(), pero moverá cualquier información de error de e a dst, reiniciando la primera. Esta función no puede fallar, ya que no se asigna nueva memoria. Tenga en cuenta que si e no está configurado, dst se inicializa a SD_BUS_ERROR_NULL. Además, si dst es NULL, no se realiza ninguna operación sobre él y se liberan y reinician los recursos mantenidos por e. Devuelve un valor de error no positivo, similar a errno, convertido.

sd_bus_error_is_set() devolverá un valor distinto de cero si e no es NULL y se ha establecido un error, de lo contrario devolverá false.

sd_bus_error_has_name() devolverá un valor distinto de cero si e no es NULL y se ha establecido un error con el mismo name, de lo contrario devolverá false.

sd_bus_error_has_names_sentinel() es similar a sd_bus_error_has_name(), pero toma varios nombres para comparar. La lista debe terminar con NULL. sd_bus_error_has_names() es un envoltorio de macro alrededor de sd_bus_error_has_names_sentinel() que agrega el centinela NULL automáticamente.

sd_bus_error_free() destruirá los recursos mantenidos por e. El parámetro en sí no se desasignará y el llamante deberá free(3)lo si es necesario. La función también se puede llamar de forma segura en errores no establecidos (estructuras de error con ambos campos establecidos a NULL), en cuyo caso no realiza ninguna operación. Esta llamada reiniciará la estructura de error después de liberar los datos, de modo que todos los campos se establezcan en NULL. La estructura se puede reutilizar después.

PROPIEDAD DE LA REFERENCIA

sd_bus_error no tiene conteo de referencias. Los usuarios deben destruir los recursos que mantiene llamando a sd_bus_error_free(). Por lo general, las estructuras de error se asignan en la pila o se pasan como parámetros de función, pero también se pueden asignar dinámicamente, en cuyo caso es responsabilidad del llamante liberar la memoria mantenida por la propia estructura después de liberar su contenido con sd_bus_error_free().

VALOR DE RETORNO

Las funciones sd_bus_error_set(), sd_bus_error_setf() y sd_bus_error_set_const() siempre devuelven 0 cuando el valor de error especificado es NULL, y un valor negativo similar a errno correspondiente al parámetro name en caso contrario. Las funciones sd_bus_error_set_errno(), sd_bus_error_set_errnof() y sd_bus_error_set_errnofv(), devuelven 0 cuando el valor de error especificado es 0, y un valor negativo similar a errno correspondiente al parámetro error en caso contrario. Si ocurre un error internamente, se devolverá uno de los valores de error negativos que se enumeran a continuación. Esto permite que estas funciones se utilicen convenientemente en una declaración return, vea el ejemplo a continuación.

sd_bus_error_get_errno() devuelve false cuando e es NULL, y un valor de errno positivo mapeado desde e->name en caso contrario.

sd_bus_error_copy() y sd_bus_error_move() devuelven un valor de error negativo convertido del error de origen, y cero si el error no se ha establecido. Esto permite que estas funciones se utilicen convenientemente en una declaración return, vea el ejemplo a continuación.

sd_bus_error_is_set() devuelve un valor distinto de cero cuando e y el campo name no son NULL, de lo contrario cero.

sd_bus_error_has_name(), sd_bus_error_has_names() y sd_bus_error_has_names_sentinel() devuelven un valor distinto de cero cuando e no es NULL y el campo name es igual a uno de los nombres dados, de lo contrario cero.

Errores

El valor de retorno puede indicar los siguientes problemas en la invocación de la propia función:

-EINVAL

El error ya estaba establecido en la estructura sd_bus_error cuando se llamó a una de las funciones de establecimiento de error.

-ENOMEM

Fallo en la asignación de memoria.

En caso de éxito, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy() y sd_bus_error_move() devolverán un valor negativo convertido al estilo errno, o 0 si el parámetro de error es NULL o no está establecido. Los errores de D-Bus se convierten al valor integral al estilo errno, y el mecanismo de mapeo es extensible, vea la discusión anterior. Esto significa efectivamente que casi cualquier valor negativo al estilo errno puede ser devuelto.

EJEMPLOS

Ejemplo 1. Uso del valor de retorno negativo para propagar un error

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "Hello, World!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* En caso de éxito, devolver el número de bytes escritos, posiblemente 0. */
  /* En caso de error, inicializar la estructura de error y también propagar el valor de errno
   * que write(2) estableció para nosotros. */
  return sd_bus_error_set_errnof(error, errno, "Failed to write to fd %i: %s", fd, strerror(errno));
}

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y vincular con el archivo libsystemd de pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando aún no se han iniciado otros hilos.
