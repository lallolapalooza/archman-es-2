DESCRIPCIÓN

La estructura sd_bus_error contiene información sobre una condición de error D-Bus, o la ausencia de ella. Las funciones descritas a continuación pueden ser utilizadas para establecer y consultar campos en esta estructura.

•El campo name contiene un identificador corto de un error. Debe seguir las reglas para nombres de error descritas en la especificación D-Bus, subsección Nombres Válidos de D-Bus[1]. Una serie de nombres de error comunes y estandarizados se describen en sd-bus-errors(3), pero las aplicaciones pueden definir errores adicionales específicos del dominio.
•El campo message generalmente contiene una cadena legible por humanos que describe los detalles, pero puede ser NULL.

Una estructura sd_bus_error no establecida debe tener ambos campos inicializados a NULL, y significa la ausencia de un error, es decir, éxito. Asigne SD_BUS_ERROR_NULL a la estructura para inicializar ambos campos a NULL. Cuando ya no sean necesarios, los recursos en poder de la estructura sd_bus_error deben ser destruidos con sd_bus_error_free().

sd_bus_error_set() establece una estructura de error a los nombres y mensajes especificados. Las cadenas se copiarán en memoria interna recién asignada. Es esencial liberar el contenido nuevamente cuando ya no se requieran (ver arriba). No utilice esta llamada en estructuras de error que ya hayan sido establecidas. Si tiene la intención de reutilizar una estructura de error, primero libere los datos antiguos almacenados en ella con sd_bus_error_free().

sd_bus_error_set() devolverá un valor similar a errno (ver errno(3)) determinado a partir del nombre de error name especificado. Si name es NULL, se asume que no ocurrió ningún error y se devuelve 0. Si name no es nulo, siempre se devuelve un valor negativo. Si e es NULL, no se inicializa ninguna estructura de error, pero name todavía se convierte en un valor de estilo errno.

Varios errores D-Bus bien conocidos se convierten a sus contrapartes errno bien conocidas, y los demás a -EIO. Vea sd-bus-errors(3) para una lista de nombres de error bien conocidos. Se pueden definir mapeos de errores adicionales con sd_bus_error_add_map(3).

sd_bus_error_set() está diseñado para ser utilizado convenientemente en una sentencia return. Si message es NULL, no se establece ningún mensaje. Esta llamada puede fallar si no se puede asignar memoria para las cadenas de nombre y mensaje, en cuyo caso se establecerá un error SD_BUS_ERROR_NO_MEMORY y se devolverá -ENOMEM.

sd_bus_error_setf() y sd_bus_error_setfv() son similares a sd_bus_error_set(), pero toman una cadena de formato printf(3) y argumentos correspondientes para generar el campo message. sd_bus_error_setf() utiliza argumentos variádicos, y sd_bus_error_setfv() acepta los argumentos como una lista de parámetros va_arg(3).

sd_bus_error_set_const() es similar a sd_bus_error_set(), pero los parámetros de cadena no se copian internamente y, por lo tanto, deben permanecer constantes y válidos durante la vida útil de e. Utilice esta llamada para evitar asignaciones de memoria al establecer estructuras de error. Dado que esta llamada no asigna memoria, no fallará con una condición de falta de memoria como puede hacerlo sd_bus_error_set(), como se describe anteriormente. Alternativamente, la macro SD_BUS_ERROR_MAKE_CONST() puede ser utilizada para generar una estructura de error literal y constante sobre la marcha.

sd_bus_error_set_errno() devolverá inmediatamente 0 si el parámetro de error error especificado es 0. De lo contrario, establecerá name a partir de un valor similar a errno que se convierte a un error D-Bus. Se utilizará strerror_r(3) para establecer message. Se utilizarán nombres de error D-Bus bien conocidos para name si corresponde, de lo contrario se generará un nombre en el espacio de nombres "System.Error.". Se ignora el signo del número de error especificado y se utiliza implícitamente su valor absoluto. Si el error especificado error no es cero, la llamada siempre devuelve un valor negativo, para un uso conveniente en sentencias return. Esta llamada puede fallar debido a la falta de memoria, en cuyo caso se establecerá en su lugar un error SD_BUS_ERROR_NO_MEMORY y se devolverá -ENOMEM.

sd_bus_error_set_errnof() y sd_bus_error_set_errnof() son similares a sd_bus_error_set_errno(), pero además de error, toman una cadena de formato printf(3) y argumentos correspondientes. El campo message se generará a partir de format y los argumentos. sd_bus_error_set_errnof() utiliza argumentos variádicos, y sd_bus_error_set_errnofv() acepta los argumentos como una lista de parámetros va_arg(3).

sd_bus_error_get_errno() convierte el campo name de una estructura de error a un valor (positivo) similar a errno usando las mismas reglas que sd_bus_error_set(). Si e es NULL, se devolverá 0.

sd_bus_error_copy() inicializará dst usando los valores de e, si e ha sido establecido previamente con un valor de error. De lo contrario, devolverá inmediatamente. Si las cadenas en e se establecieron usando sd_bus_error_set_const(), se compartirán. De lo contrario, se copiarán. Antes de esta llamada, dst debe estar sin establecer, es decir, recién inicializado con NULL o restablecido usando sd_bus_error_free().

sd_bus_error_copy() generalmente devuelve 0 o un valor negativo similar a errno basado en el parámetro de entrada e: 0 si no estaba establecido y un entero negativo si estaba establecido a algún error, de manera similar a sd_bus_error_set(). EJEMPLOS

Ejemplo 1. Uso del valor de retorno negativo para propagar un error

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "¡Hola, Mundo!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* En caso de éxito, devuelve el número de bytes escritos, posiblemente 0. */
  /* En caso de error, inicializa la estructura de error y también propaga el valor errno
   * que write(2) estableció para nosotros. */
  return sd_bus_error_set_errnof(error, errno, "Error al escribir en el fd %i: %s", fd, strerror(errno));
}

PROPIEDAD DE REFERENCIA

sd_bus_error no tiene contador de referencias. Los usuarios deben destruir los recursos que contiene llamando a sd_bus_error_free(). Normalmente, las estructuras de error se asignan en la pila o se pasan como parámetros de función, pero también pueden asignarse dinámicamente, en cuyo caso es deber del llamador liberar la memoria de la propia estructura usando free(3) después de liberar su contenido con sd_bus_error_free().

VALOR DE RETORNO

Las funciones sd_bus_error_set(), sd_bus_error_setf() y sd_bus_error_set_const() siempre devuelven 0 cuando el valor de error especificado es NULL, y un valor negativo similar a errno correspondiente al parámetro name en caso contrario. Las funciones sd_bus_error_set_errno(), sd_bus_error_set_errnof() y sd_bus_error_set_errnofv(), devuelven 0 cuando el valor de error especificado es 0, y un valor negativo similar a errno correspondiente al parámetro error en caso contrario. Si ocurre un error internamente, se devolverá uno de los valores de error negativos listados a continuación. Esto permite que esas funciones se utilicen convenientemente en una declaración return, véase el ejemplo a continuación.

sd_bus_error_get_errno() devuelve false cuando e es NULL, y un valor errno positivo mapeado desde e->name en caso contrario.

sd_bus_error_copy() y sd_bus_error_move() devuelven un valor de error negativo convertido del error de origen, y cero si el error no se ha establecido. Esto permite que estas funciones se utilicen convenientemente en una declaración return, véase el ejemplo a continuación.

sd_bus_error_is_set() devuelve un valor distinto de cero cuando e y el campo name no son NULL, y cero en caso contrario.

sd_bus_error_has_name(), sd_bus_error_has_names() y sd_bus_error_has_names_sentinel() devuelven un valor distinto de cero cuando e no es NULL y el campo name es igual a uno de los nombres dados, y cero en caso contrario.

Errores

El valor de retorno puede indicar los siguientes problemas en la invocación de la propia función:

-EINVAL

El error ya estaba establecido en la estructura sd_bus_error cuando se llamó a una de las funciones de establecimiento de errores.

-ENOMEM

Falló la asignación de memoria.

En caso de éxito, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy() y sd_bus_error_move() devolverán un valor negativo convertido al estilo errno, o 0 si el parámetro de error es NULL o no está establecido. Los errores de D-Bus se convierten al valor integral al estilo errno, y el mecanismo de mapeo es extensible, véase la discusión anterior. Esto significa efectivamente que casi cualquier valor negativo al estilo errno puede ser devuelto.

DESCRIPCIÓN

La estructura sd_bus_error se utiliza para pasar errores de D-Bus entre funciones. El error se describe mediante un nombre (una cadena ASCII que sigue a las reglas de los nombres de interfaz de D-Bus, véase la nota 1) y una descripción (una cadena ASCII que explica el error). Si el nombre del error es una cadena de error común de D-Bus (por ejemplo, org.freedesktop.DBus.Error.ServiceUnknown), se puede mapear a un valor positivo de errno. Esto permite que el código de llamada compruebe los errores comunes de D-Bus de forma eficiente y segura, y proporciona un mecanismo para extender este mapeo. Por defecto, solo se mapean los errores comunes de D-Bus; para mapear otros errores, use sd_bus_error_add_map(3). Si se intenta establecer un error y la estructura sd_bus_error ya contiene un error, se devuelve -EINVAL. Si se intenta reservar memoria y falla, se devuelve -ENOMEM. Las funciones que establecen errores devuelven 0 en caso de éxito.

sd_bus_error_set() establece el error en e con el nombre y la descripción dados. Si name es NULL, el error se considera no establecido y se liberan los recursos anteriores. Si description es NULL, se usa una cadena vacía en su lugar. Si el error se establece correctamente, se devuelve 0. Si el error e ya estaba establecido, se devuelve -EINVAL. Si falla la asignación de memoria, se devuelve -ENOMEM. Note que si e es NULL, no se realiza ninguna operación.

sd_bus_error_setf() es similar a sd_bus_error_set(), pero permite formatear la descripción usando una cadena de formato estilo printf(3). Tenga cuidado de que la cadena de formato no sea demasiado larga. Tenga en cuenta que este formato solo se utiliza si name no es NULL. Si name es NULL, el error se considera no establecido y se liberan los recursos anteriores.

sd_bus_error_setfv() es similar a sd_bus_error_setf(), pero toma una lista de argumentos de variable en lugar de una cadena de formato y argumentos.

sd_bus_error_set_const() es idéntica a sd_bus_error_set(), pero asume que name y description son punteros a cadenas de memoria de solo lectura, y no intentará copiarlas o hacer copias privadas de ellas. Esto puede mejorar el rendimiento al evitar asignaciones de memoria innecesarias.

sd_bus_error_set_errno() establece el error en e según el valor errno dado. Si errno es 0, el error se considera no establecido y se liberan los recursos anteriores. Si errno no es 0, se busca un nombre de error de D-Bus asociado con ese valor errno. Si se encuentra uno, se utiliza. Si no, se utiliza el nombre de error genérico "Failed". Los errores se convierten primero a un valor numérico negativo, y este valor se utiliza como errno interno para la comprobación de errores.

sd_bus_error_set_errnof() y sd_bus_error_set_errnofv() son similares a sd_bus_error_set_errno(), pero permiten formatear la descripción del error utilizando una cadena de formato estilo printf(3) o una lista de argumentos de variable, respectivamente.

sd_bus_error_get_errno() intenta convertir el error establecido en e a un valor errno positivo. Si no se establece ningún error, o si el nombre del error no se puede mapear a un valor errno, se devuelve 0. Si el campo name de e es NULL, se devuelve false.

sd_bus_error_copy() copia el contenido del error de src a dst. Si dst ya tiene un error establecido, se liberará primero. Si src no tiene un error establecido, dst se inicializará a SD_BUS_ERROR_NULL. Si se produce un error de asignación de memoria, se devuelve -ENOMEM. Si el error se copia correctamente, se devuelve 0. Si src y dst son iguales, no se hace nada y se devuelve 0. Si se intenta asignar memoria y falla, se devuelve -ENOMEM. Si dst es NULL, no se realiza ninguna operación.

sd_bus_error_move() es similar a sd_bus_error_copy(), pero moverá cualquier información de error de e a dst, restableciendo el primero. Esta función no puede fallar, ya que no se asigna memoria nueva. Tenga en cuenta que si e no está establecido, dst se inicializa a SD_BUS_ERROR_NULL. Además, si dst es NULL no se realiza ninguna operación sobre él y se liberan y restablecen los recursos mantenidos por e. Devuelve un valor de error no positivo similar a errno convertido.

sd_bus_error_is_set() devolverá un valor distinto de cero si e no es NULL y se ha establecido un error, y false en caso contrario.

sd_bus_error_has_name() devolverá un valor distinto de cero si e no es NULL y se ha establecido un error con el mismo name, y false en caso contrario.

sd_bus_error_has_names_sentinel() es similar a sd_bus_error_has_name(), pero toma varios nombres para comprobar. La lista debe terminar con NULL. sd_bus_error_has_names() es un macro envoltorio alrededor de sd_bus_error_has_names_sentinel() que añade el terminador NULL automáticamente.

sd_bus_error_free() destruirá los recursos mantenidos por e. El parámetro en sí no será desasignado y debe ser liberado por el llamador usando free(3) si es necesario. La función también puede ser llamada de forma segura en errores no establecidos (estructuras de error con ambos campos establecidos a NULL), en cuyo caso no realiza ninguna operación. Esta llamada restablecerá la estructura de error después de liberar los datos, de modo que todos los campos se establezcan a NULL. La estructura puede ser reutilizada posteriormente.
