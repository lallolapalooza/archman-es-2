DESCRIPCIÓN

sd-id128.h es parte de libsystemd(3) y proporciona API para generar, convertir y comparar valores de ID de 128 bits. Los valores de ID de 128 bits procesados y generados por estas API son una generalización de los UUID de OSF, tal como se define en RFC 4122[1], pero utilizan un formato de cadena más simple. Estas funciones no imponen ninguna estructura en los IDs utilizados, a diferencia de los UUID de OSF o los GUID de Microsoft, pero son mayormente compatibles con esos tipos de IDs.

Un ID de 128 bits se implementa como la siguiente unión de tipos:

typedef union sd_id128 {
  uint8_t bytes[16];
  uint64_t qwords[2];
} sd_id128_t;

Esta unión de tipos permite acceder al ID de 128 bits como 16 bytes separados o dos palabras de 64 bits. En general, es más seguro acceder a los componentes del ID a través de su array de 8 bits para evitar problemas de endianness. Esta unión está pensada para ser pasada por valor (en lugar de por referencia) y puede ser manipulada directamente por los clientes.

Se definen un par de macros para denotar y decodificar IDs de 128 bits:

SD_ID128_MAKE() se utiliza para escribir un ID constante en el código fuente. Un uso común es asignar un nombre a un ID usando esta macro:

#define SD_MESSAGE_COREDUMP SD_ID128_MAKE(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)

SD_ID128_NULL define un ID que consiste únicamente en bytes NUL (es decir, todos los bits a cero).

SD_ID128_ALLF define un ID que consiste únicamente en bytes 0xFF (es decir, todos los bits a uno).

SD_ID128_MAKE_STR() es similar a SD_ID128_MAKE(), pero crea una expresión const char* que puede ser utilizada convenientemente en formatos de mensajes y similares:

#include <stdio.h>
#define SD_MESSAGE_COREDUMP_STR SD_ID128_MAKE_STR(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)
int main(int argc, char **argv) {
  puts("Match for coredumps: MESSAGE_ID=" SD_MESSAGE_COREDUMP_STR);
}

SD_ID128_CONST_STR() convierte IDs constantes en cadenas constantes para su salida. El siguiente ejemplo de código mostrará la cadena "fc2e22bc6ee647b6b90729ab34a250b1":

int main(int argc, char *argv[]) {
  puts("Match for coredumps: %s", SD_ID128_CONST_STR(SD_MESSAGE_COREDUMP));
}

SD_ID128_FORMAT_STR y SD_ID128_FORMAT_VAL() se utilizan para dar formato a un ID en una cadena de formato printf(3), como se muestra en el siguiente ejemplo:

int main(int argc, char *argv[]) {
  sd_id128_t id;
  id = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  printf("The ID encoded in this C file is " SD_ID128_FORMAT_STR ".\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}

SD_ID128_UUID_FORMAT_STR y SD_ID128_MAKE_UUID_STR() son similares a SD_ID128_FORMAT_STR y SD_ID128_MAKE_STR(), pero incluyen guiones separadores para cumplir con la "representación canónica de UUID[2]". Dan formato a la cadena basándose en las reglas de la Variante 1 de RFC4122[1], es decir, convirtiendo desde el orden de bytes Big Endian. Esto coincide con el comportamiento de la mayoría de las infraestructuras de espacio de usuario de Linux. Probablemente sea mejor evitar UUIDs de otras variantes para evitar ambigüedades innecesarias. Todos los IDs de 128 bits generados por las API de sd-id128 se ajustan estrictamente a los UUID de Variante 1, Versión 4, según RFC 4122.

sd_id128_equal() compara dos IDs de 128 bits:

int main(int argc, char *argv[]) {
  sd_id128_t a, b, c;
  a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  b = SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e);
  c = a;
  assert(sd_id128_equal(a, c));
  assert(!sd_id128_equal(a, b));
  return 0;
}

sd_id128_string_equal() es similar a sd_id128_equal(), pero el primer ID tiene el formato de const char*. Se aplican las mismas restricciones que al primer argumento de sd_id128_from_string().

sd_id128_is_null() comprueba si un ID consiste únicamente en bytes NUL:

assert(sd_id128_is_null(SD_ID128_NULL));

De manera similar, sd_id128_is_allf() comprueba si un ID consiste únicamente en bytes 0xFF (todos los bits a uno):

assert(sd_id128_is_allf(SD_ID128_ALLF));

sd_id128_in_set_sentinel() toma una lista de IDs y devuelve true si el primer argumento es igual a alguno de los argumentos posteriores. La lista de argumentos está terminada por un centinela SD_ID128_NULL, que debe estar presente.

sd_id128_in_set() es una función de conveniencia que toma una lista de IDs y devuelve true si el primer argumento es igual a alguno de los argumentos posteriores:

int main(int argc, char *argv[]) {
  sd_id12_t a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  assert(sd_id128_in_set(a, a));
  assert(sd_id128_in_set(a, a, a));
  assert(!sd_id128_in_set(a));
  assert(!sd_id128_in_set(a,
                          SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e)
                          SD_ID128_MAKE(2f,88,28,5f,9c,44,09,9d,d7,15,77,04,bc,85,7e,e3)
                          SD_ID128_ALLF));
  return 0;
}

sd_id128_in_set() está definida como una macro sobre sd_id128_in_set_sentinel(), añadiendo el centinela SD_ID128_NULL automáticamente. Dado que sd_id128_in_set_sentinel() utiliza SD_ID128_NULL como centinela, SD_ID128_NULL no puede colocarse de otra manera en la lista de argumentos.

sd_id128_in_setv() es similar a sd_id128_in_set_sentinel(), pero toma un argumento de tipo struct varargs.

Se pueden generar nuevos IDs aleatorios con el comando new de systemd-id128(1).

NAME

Check if a 128-bit ID is contained in a set of IDs

SYNOPSIS

#include <systemd/sd-id128.h>

int sd_id128_in_set_sentinel(const sd_id128_t id, const sd_id128_t *set,
                             sd_id128_t sentinel);
int sd_id128_in_set(const sd_id128_t id, const sd_id128_t *set, size_t n);

DESCRIPTION

sd_id128_in_set_sentinel() checks if the 128-bit identifier id is present in the null-terminated array set. The array set is terminated by the special sentinel value sentinel.

sd_id128_in_set() checks if the 128-bit identifier id is present in the array set of size n.

These functions are useful for checking if a given ID is part of a predefined set of IDs. They are commonly used with machine IDs, boot IDs, or other identifiers generated by sd-id128(3).

The comparison is done by comparing the 128-bit values directly. No string conversion is performed.

The set of IDs can be composed of any valid 128-bit identifiers, including the null ID (all zeros) or the all-ones ID.

If id is found in the set, the functions return 1. Otherwise, they return 0.

If the set is empty (e.g., n is 0 or the first element is the sentinel), the functions return 0.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
