sd_bus_message_close_container(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_MESSAGE_OPEN_CONTAINER(3) sd_bus_message_open_container SD_BUS_MESSAGE_OPEN_CONTAINER(3)

NOMBRE

sd_bus_message_open_container, sd_bus_message_close_container, sd_bus_message_enter_container, sd_bus_message_exit_container - Crear y mover entre contenedores en mensajes D-Bus

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_open_container(sd_bus_message *m, char type, const char *contents);

int sd_bus_message_close_container(sd_bus_message *m);

int sd_bus_message_enter_container(sd_bus_message *m, char type, const char *contents);

int sd_bus_message_exit_container(sd_bus_message *m);

DESCRIPCIÓN

sd_bus_message_open_container() añade un nuevo contenedor al mensaje m. Después de abrir un nuevo contenedor, puede llenarse con contenido usando sd_bus_message_append(3) y funciones similares. Los contenedores se comportan como una pila. Para anidar contenedores unos dentro de otros, llame a sd_bus_message_open_container() varias veces sin llamar a sd_bus_message_close_container() entre ellas. Cada contenedor se anidará dentro del contenedor anterior. type representa el tipo de contenedor y debe ser uno de "r", "a", "v" o "e" como se describe en sd_bus_message_append(3). En lugar de literales, también se pueden usar las constantes correspondientes SD_BUS_TYPE_STRUCT, SD_BUS_TYPE_ARRAY, SD_BUS_TYPE_VARIANT o SD_BUS_TYPE_DICT_ENTRY. contents describe el tipo de los elementos del contenedor y debe ser una cadena de tipo D-Bus siguiendo las reglas descritas en sd_bus_message_append(3).

sd_bus_message_close_container() cierra el último contenedor abierto con sd_bus_message_open_container(). Al tener éxito, el puntero de escritura del mensaje m se posiciona después del contenedor cerrado en su contenedor padre o en m si no hay un contenedor padre.

sd_bus_message_enter_container() entra en el siguiente contenedor del mensaje m para leerlo. Se comporta en gran medida como sd_bus_message_open_container(). Entrar en un contenedor permite leer su contenido con sd_bus_message_read(3) y funciones similares. type y contents son iguales que en sd_bus_message_open_container().

sd_bus_message_exit_container() sale del ámbito del último contenedor entrado con sd_bus_message_enter_container(). Se comporta en gran medida como sd_bus_message_close_container(). Tenga en cuenta que sd_bus_message_exit_container() solo puede llamarse después de iterar sobre todos los miembros del contenedor, es decir, leyéndolos o saltándolos. Use sd_bus_message_skip(3) para saltar campos de un contenedor con el fin de poder salir del contenedor con sd_bus_message_exit_container() sin leer todos los miembros.

VALOR DE RETORNO

Al tener éxito, estas funciones devuelven un entero no negativo. sd_bus_message_open_container() y sd_bus_message_close_container() devuelven 0. sd_bus_message_enter_container() devuelve 1 si abrió con éxito un nuevo contenedor, y 0 si no fue posible porque se alcanzó el final del contenedor actualmente abierto o del mensaje. sd_bus_message_exit_container() devuelve 1 al tener éxito. En caso de error, todas estas funciones devuelven un código de error negativo de estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

m o contents son NULL o type es inválido.

Añadido en la versión 246.

-EBADMSG

El mensaje m tiene una estructura inválida.

Añadido en la versión 254.

-ENXIO

El mensaje m no tiene un contenedor del tipo type en la posición actual, o el contenido no coincide con contents.

Añadido en la versión 254.

-EPERM

El mensaje m ya está sellado.

Añadido en la versión 246.

-ESTALE

El mensaje m está en un estado inválido.

Añadido en la versión 246.

-ENOMEM

Fallo al asignar memoria.

Añadido en la versión 246.

-EBUSY

Se llamó a sd_bus_message_exit_container() pero quedan miembros sin leer en el contenedor.

Añadido en la versión 247.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se han iniciado otros hilos.

EJEMPLOS

Ejemplo 1. Añadir un array de cadenas a un mensaje

/* SPDX-License-Identifier: MIT-0 */
#include <systemd/sd-bus.h>
int append_strings_to_message(sd_bus_message *m, const char *const *arr) {
  const char *s;
  int r;
  r = sd_bus_message_open_container(m, 'a', "s");
  if (r < 0)
    return r;
  for (s = *arr; *s; s++) {
    r = sd_bus_message_append(m, "s", s);
    if (r < 0)
      return r;
  }
  return sd_bus_message_close_container(m);
}

Ejemplo 2. Leer un array de cadenas de un mensaje

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <systemd/sd-bus.h>
int read_strings_from_message(sd_bus_message *m) {
  int r;
  r = sd_bus_message_enter_container(m, 'a', "s");
  if (r < 0)
    return r;
  for (;;) {
    const char *s;
    r = sd_bus_message_read(m, "s", &s);
    if (r < 0)
      return r;
    if (r == 0)
      break;
    printf("%s\n", s);
  }
  return sd_bus_message_exit_container(m);
}

NOMBRE

sd_bus_message_close_container - Cierra un contenedor dentro de un mensaje de bus.

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_close_container(sd_bus_message *m);

DESCRIPCIÓN

sd_bus_message_close_container() se utiliza para cerrar un contenedor que fue abierto previamente con sd_bus_message_open_container(). Esto se utiliza para escribir la longitud del contenedor en el mensaje. Después de llamar a esta función, el objeto de mensaje ya no puede ser modificado o escrito de forma arbitraria.

El contenedor que se cierra debe ser el último contenedor abierto que se estaba escribiendo. Si se intentan cerrar contenedores en el orden incorrecto, el resultado es indefinido.

VALOR DE RETORNO

En caso de éxito, se devuelve 0. En caso de error, se devuelve un número negativo que indica un código de error.

NOTAS

Esta función es una parte importante de la construcción de mensajes de bus que contienen estructuras de datos complejas, como arrays de diccionarios o arrays de arrays.

EJEMPLOS

Ejemplo de uso:

sd_bus_message *message = NULL;
sd_bus_message *container = NULL;
int r;

r = sd_bus_message_new_method_call(bus, "org.example.Service", "/org/example/Object", "org.example.Interface", "SomeMethod", &message);
// ... añadir argumentos ...

r = sd_bus_message_open_container(message, 'a', "{sv}"); // Abrir un array de diccionarios
// ... añadir elementos al contenedor ...

r = sd_bus_message_close_container(message); // Cerrar el contenedor
// ... añadir más argumentos si es necesario ...

r = sd_bus_send(bus, message, NULL);
sd_bus_message_unref(message);

VER TAMBIEN

sd_bus_message_new_method_call(3), sd_bus_message_open_container(3), sd_bus_send(3), sd_bus_message_unref(3)

NOTAS

sd_bus_message_close_container() debe ser llamado para cada contenedor abierto con sd_bus_message_open_container() antes de que el mensaje sea enviado o desecha. La falta de cerrar un contenedor puede llevar a mensajes mal formados y errores de comunicación.
