sd_bus_message_new_signal_to(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_MESSAGE_NEW_SIGNAL(3) sd_bus_message_new_signal SD_BUS_MESSAGE_NEW_SIGNAL(3)

NOMBRE

sd_bus_message_new_signal, sd_bus_message_new_signal_to - Crear un mensaje de señal

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_new_signal(sd_bus *bus, sd_bus_message **m, const char *path, const char *interface, const char *member);

int sd_bus_message_new_signal_to(sd_bus *bus, sd_bus_message **m, const char *destination, const char *path, const char *interface, const char *member);

DESCRIPCIÓN

La función sd_bus_message_new_signal() crea un nuevo objeto de mensaje de bus que encapsula una señal D-Bus, y lo devuelve en el parámetro de salida m. La señal se enviará a la ruta path, en la interfaz interface, miembro member. Cuando se envíe este mensaje, no se espera respuesta. Véase sd_bus_message_new_method_call(3) para una breve descripción del significado de los parámetros path, interface y member.

sd_bus_message_new_signal_to() es una forma abreviada de crear un nuevo mensaje de bus a un destino específico. Su comportamiento es similar a llamar a sd_bus_message_new_signal() seguido de llamar a sd_bus_message_set_destination(3).

VALOR DE RETORNO

Esta función devuelve 0 si el objeto de mensaje se creó con éxito, y un código de error negativo de estilo errno en caso contrario.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

El parámetro de salida m es NULL.

El parámetro path no es una ruta D-Bus válida ("/an/object/path"), el parámetro interface no es un nombre de interfaz D-Bus válido ("an.interface.name"), o el parámetro member no es un miembro D-Bus válido ("Name").

-ENOTCONN

El parámetro de bus bus es NULL o el bus no está conectado.

-ENOMEM

Fallo en la asignación de memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar contra y enlazar con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

EJEMPLOS

Ejemplo 1. Enviar una señal simple

/* SPDX-License-Identifier: MIT-0 */
#include <systemd/sd-bus.h>
#define _cleanup_(f) __attribute__((cleanup(f)))
int send_unit_files_changed(sd_bus *bus) {
  _cleanup_(sd_bus_message_unrefp) sd_bus_message *message = NULL;
  int r;
  r = sd_bus_message_new_signal(bus, &message,
                                "/org/freedesktop/systemd1",
                                "org.freedesktop.systemd1.Manager",
                                "UnitFilesChanged");
  if (r < 0)
    return r;
  return sd_bus_send(bus, message, NULL);
}

Esta función en las fuentes de systemd se utiliza para emitir la señal "UnitFilesChanged" cuando los archivos de unidad han cambiado.
