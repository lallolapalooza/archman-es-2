sd_event_source_get_inotify_path(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_EVENT_ADD_INOTIFY(3) sd_event_add_inotify SD_EVENT_ADD_INOTIFY(3)

NOMBRE

sd_event_add_inotify, sd_event_add_inotify_fd, sd_event_source_get_inotify_mask, sd_event_source_get_inotify_path, sd_event_inotify_handler_t - Añadir una fuente de eventos de inodo del sistema de archivos "inotify" a un bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_inotify_handler_t)(sd_event_source *s, const struct inotify_event *event, void *userdata);

int sd_event_add_inotify(sd_event *event, sd_event_source **source, const char *path, uint32_t mask, sd_event_inotify_handler_t handler, void *userdata);

int sd_event_add_inotify_fd(sd_event *event, sd_event_source **source, int fd, uint32_t mask, sd_event_inotify_handler_t handler, void *userdata);

int sd_event_source_get_inotify_mask(sd_event_source *source, uint32_t *ret);

int sd_event_source_get_inotify_path(sd_event_source *source, const char **ret);

DESCRIPCIÓN

sd_event_add_inotify() añade una nueva fuente de eventos de inodo del sistema de archivos inotify(7) a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, y el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro path especifica la ruta del inodo del sistema de archivos a vigilar. El parámetro mask especifica qué tipos de eventos de inodo vigilar específicamente. Debe contener una combinación OR-ed de las banderas IN_ACCESS, IN_ATTRIB, IN_CLOSE_WRITE, ... . Consulte inotify(7) para más información.

El handler debe referenciar una función a llamar cuando el inodo cambie o NULL. La función manejadora recibirá el puntero userdata, que puede ser elegido libremente por el llamador. El manejador también recibe un puntero a una estructura inotify_event que contiene información sobre el evento del inodo. El manejador puede devolver un valor negativo para señalar un error (ver abajo), otros valores de retorno se ignoran. Si handler es NULL, se usará un manejador predeterminado que llama a sd_event_exit(3).

sd_event_add_inotify_fd() es idéntico a sd_event_add_inotify(), excepto que toma un descriptor de archivo de un inodo (posiblemente uno de tipo O_PATH, pero cualquiera otro también sirve) en lugar de una ruta en el sistema de archivos.

Si se instalan múltiples fuentes de eventos para el mismo inodo, el descriptor de vigilancia inotify subyacente se comparte automáticamente. El parámetro mask puede contener cualquier bandera definida por la API de inotify, con la excepción de IN_MASK_ADD.

El manejador se habilita continuamente (SD_EVENT_ON), pero esto puede cambiarse con sd_event_source_set_enabled(3). Alternativamente, la bandera de máscara IN_ONESHOT puede usarse para solicitar el modo SD_EVENT_ONESHOT. Si la función manejadora devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si se solicitó el modo SD_EVENT_ON antes.

Como limitación especial, la prioridad de las fuentes de eventos inotify solo puede alterarse (ver sd_event_source_set_priority(3)) en el tiempo entre la creación del objeto de fuente de eventos con sd_event_add_inotify() y el inicio de la siguiente iteración del bucle de eventos. Los intentos de cambiar la prioridad más tarde serán rechazados. Considere liberar y asignar una nueva fuente de eventos inotify para cambiar la prioridad en ese momento.

Para destruir un objeto de fuente de eventos, use sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se sueltan todas las referencias a la fuente de eventos. Para asegurarse de que una fuente de eventos no se active más, incluso cuando todavía hay una referencia a ella, considere deshabilitarla con sd_event_source_set_enabled(3).

Si se pasa el segundo parámetro de sd_event_add_inotify() como NULL, no se devuelve ninguna referencia al objeto de la fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando el propio bucle de eventos se destruya.

Si el parámetro handler para sd_event_add_inotify() es NULL, y la fuente de eventos se activa, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a entero, se pasa como parámetro de código de salida a sd_event_exit(3).

sd_event_source_get_inotify_mask() recupera la máscara de vigilancia inotify configurada de una fuente de eventos creada previamente con sd_event_add_inotify(). Toma el objeto de la fuente de eventos como parámetro source y un puntero a una variable uint32_t para devolver la máscara.

sd_event_source_get_inotify_path() recupera la ruta de destino de la vigilancia inotify configurada de una fuente de eventos creada previamente con sd_event_add_inotify(). Toma el objeto de la fuente de eventos como parámetro source y un puntero a una variable const char ** para devolver la ruta. El llamador no debe liberar la ruta devuelta.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se pasó un argumento inválido. Esto incluye especificar una máscara con IN_MASK_ADD activado.

-ESTALE

Devuelto por sd_event_source_add_inotify() o sd_event_source_add_inotify_fd() cuando el bucle de eventos ya está terminado. Devuelto por sd_event_source_get_inotify_path() cuando no hay datos de inodo activos asignados a la fuente de eventos, por ejemplo, cuando la fuente de eventos está deshabilitada.

-ECHILD

El bucle de eventos se creó en un proceso, biblioteca o instancia de módulo diferente.

-EDOM

La fuente de eventos pasada no es una fuente de eventos de proceso inotify.

-EBADF

El descriptor de archivo pasado no es válido.

-ENOSYS

Se llamó a sd_event_add_inotify_fd() o sd_event_source_get_inotify_path() sin tener montado /proc/.

Ejemplo 1. Un programa simple que usa inotify para monitorear uno o dos directorios

#include <stdio.h>
#include <string.h>
#include <sys/inotify.h>
#include <systemd/sd-event.h>
#define _cleanup_(f) __attribute__((cleanup(f)))
static int inotify_handler(sd_event_source *source,
                           const struct inotify_event *event,
                           void *userdata) {
  const char *desc = NULL;
  sd_event_source_get_description(source, &desc);
  if (event->mask & IN_Q_OVERFLOW)
    printf("inotify-handler <%s>: overflow\n", desc);
  else if (event->mask & IN_CREATE)
    printf("inotify-handler <%s>: create on %s\n", desc, event->name);
  else if (event->mask & IN_DELETE)
    printf("inotify-handler <%s>: delete on %s\n", desc, event->name);
  else if (event->mask & IN_MOVED_TO)
    printf("inotify-handler <%s>: moved-to on %s\n", desc, event->name);
  /* Terminate the program if an "exit" file appears */
  if ((event->mask & (IN_CREATE|IN_MOVED_TO)) &&
      strcmp(event->name, "exit") == 0)
    sd_event_exit(sd_event_source_get_event(source), 0);
  return 1;
}

sd_event_source_get_inotify_path(3)

NAME

sd_event_source_get_inotify_path, sd_event_add_inotify, sd_event_add_inotify_fd, sd_event_source_get_inotify_mask - Añadir un objeto de evento de tipo inotify a un bucle de eventos

SYNOPSIS

#include <systemd/sd-event.h>
int sd_event_add_inotify(sd_event *event, sd_event_source **source,
                         const char *path, uint32_t events,
                         sd_event_handler_t handler, void *userdata);
int sd_event_add_inotify_fd(sd_event *event, sd_event_source **source,
                            int fd, uint32_t events,
                            sd_event_handler_t handler, void *userdata);
int sd_event_source_get_inotify_mask(sd_event_source *source, uint32_t *ret_mask);
int sd_event_source_get_inotify_path(sd_event_source *source, const char **ret_path);

DESCRIPTION

El bucle de eventos sd-event (ver sd-event(3)) permite registrar objetos de evento para recibir notificaciones sobre varios tipos de eventos asíncronos. El tipo de evento inotify permite recibir notificaciones sobre cambios en el sistema de archivos.

La función sd_event_add_inotify() añade un nuevo objeto de evento que observa los cambios en el directorio o archivo especificado por path. Cuando ocurre uno de los eventos especificados en events en path, se llama a la función handler con el objeto source y el dato de usuario userdata. El nuevo objeto de evento se devuelve en source. La llamada a esta función crea un nuevo descriptor de archivo inotify interno.

La función sd_event_add_inotify_fd() es similar, pero en lugar de un nombre de ruta, espera un descriptor de archivo fd preexistente que ya está configurado para la supervisión de inotify. Esto es útil si el descriptor de archivo ya ha sido creado y configurado, por ejemplo, por otra biblioteca o por el propio programa.

Los bits de evento disponibles son los definidos en el encabezado <sys/inotify.h>:

IN_ACCESS
Se accedió a un archivo.
IN_ATTRIB
Se modificaron los metadatos de un archivo (permisos, hora, etc.), pero no el contenido.
IN_CLOSE_NOWRITE
Se cerró un archivo que no estaba abierto para escribir.
IN_CLOSE_WRITE
Se cerró un archivo que estaba abierto para escribir.
IN_CREATE
Se creó un archivo en el directorio observado.
IN_DELETE
Se eliminó un archivo del directorio observado.
IN_DELETE_SELF
Se eliminó el propio directorio observado.
IN_MODIFY
Se modificó un archivo.
IN_MOVE_SELF
Se movió el propio directorio observado.
IN_MOVED_FROM
Se movió un archivo desde el directorio observado.
IN_MOVED_TO
Se movió un archivo al directorio observado.
IN_OPEN
Se abrió un archivo.
IN_CLOEXEC
Los descriptores de archivo inotify se crean con el flag O_CLOEXEC.
IN_NONBLOCK
Los descriptores de archivo inotify se crean con el flag O_NONBLOCK.
IN_DONT_FOLLOW
No seguir enlaces simbólicos.
IN_EXCL_UNLINK
No generar eventos para archivos eliminados que aún no han sido cerrados.
IN_MASK_ADD
Añadir eventos a una máscara de eventos existente para un descriptor de archivo dado.
IN_ONLYDIR
Solo supervisar si el nombre de la ruta es un directorio.

La combinación de los bits de evento forma la máscara de eventos que se pasará a events. Se recomienda utilizar IN_CREATE | IN_DELETE | IN_MODIFY | IN_MOVED_TO para la mayoría de los casos de uso.

La función sd_event_source_get_inotify_mask() recupera la máscara de eventos utilizada para configurar el objeto de evento source.

La función sd_event_source_get_inotify_path() recupera la ruta del sistema de archivos observada por el objeto de evento source. Si el objeto de evento se creó con sd_event_add_inotify_fd(), esta función devolverá NULL.

El manejador de eventos handler debe tener la siguiente firma:

typedef int (*sd_event_handler_t)(sd_event_source *source, void *userdata);

El manejador puede devolver un valor negativo para indicar un error, 0 para continuar el bucle de eventos sin realizar ninguna acción especial, o un valor positivo para especificar un tiempo de espera en segundos para la próxima ejecución del manejador (lo que lo convierte en un evento periódico, aunque esto no es común para eventos inotify).

El descriptor de archivo inotify subyacente se cerrará automáticamente cuando el objeto de evento se elimine del bucle de eventos.

RETURN VALUE

sd_event_add_inotify() y sd_event_add_inotify_fd() devuelven 0 si tienen éxito, o un código de error negativo en caso de fallo. Los errores posibles incluyen ECHILD, EINVAL, ENOMEM, EACCES, ELOOP, ENAMETOOLONG, ENOENT, ENOTDIR, y ERANGE.

sd_event_source_get_inotify_mask() y sd_event_source_get_inotify_path() devuelven 0 si tienen éxito, o un código de error negativo en caso de fallo. Los errores posibles incluyen EINVAL y ENOTSUP.

EXAMPLES

Este ejemplo crea un bucle de eventos y observa los cambios en el directorio /tmp y /tmp/subdir. Cuando ocurre un evento, se llama a inotify_handler.

int inotify_handler(sd_event_source *source, void *userdata) {
    const char *path;
    uint32_t mask;
    int r;

    r = sd_event_source_get_inotify_path(source, &path);
    if (r < 0) {
        fprintf(stderr, "Failed to get inotify path: %s\n", strerror(-r));
        return r;
    }

    r = sd_event_source_get_inotify_mask(source, &mask);
    if (r < 0) {
        fprintf(stderr, "Failed to get inotify mask: %s\n", strerror(-r));
        return r;
    }

    printf("inotify event detected on path '%s' with mask 0x%X\n", path, mask);

    /*
     * In a real application, you would read events from the inotify file descriptor
     * using read() and process them accordingly.
     * For simplicity, we just print a message here and keep the source enabled.
     */

    return 0;
}

int main(int argc, char *argv[]) {
    sd_event *event = NULL;
    sd_event_source *source1 = NULL;
    sd_event_source *source2 = NULL;
    const char *path1 = "/tmp";
    const char *path2 = argc > 2 ? argv[2] : NULL;
    /* Note: failure handling is omitted for brevity */
    sd_event_default(&event);
    sd_event_add_inotify(event, &source1, path1,
                       IN_CREATE | IN_DELETE | IN_MODIFY | IN_MOVED_TO,
                       inotify_handler, NULL);
    if (path2)
        sd_event_add_inotify(event, &source2, path2,
                           IN_CREATE | IN_DELETE | IN_MODIFY | IN_MOVED_TO,
                           inotify_handler, NULL);
    sd_event_loop(event);
    return 0;
}

NOTES

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo pkg-config de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
