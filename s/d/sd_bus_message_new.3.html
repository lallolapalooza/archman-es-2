sd_bus_message_new(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_MESSAGE_NEW(3) sd_bus_message_new SD_BUS_MESSAGE_NEW(3)

NOMBRE

sd_bus_message_new, sd_bus_message_ref, sd_bus_message_unref, sd_bus_message_unrefp, SD_BUS_MESSAGE_METHOD_CALL, SD_BUS_MESSAGE_METHOD_RETURN, SD_BUS_MESSAGE_METHOD_ERROR, SD_BUS_MESSAGE_SIGNAL, sd_bus_message_get_bus - Crear un nuevo objeto de mensaje de bus y crear o destruir referencias a él

SINOPSIS

#include <systemd/sd-bus.h>
enum {
      SD_BUS_MESSAGE_METHOD_CALL,
      SD_BUS_MESSAGE_METHOD_RETURN,
      SD_BUS_MESSAGE_METHOD_ERROR,
      SD_BUS_MESSAGE_SIGNAL,
};

int sd_bus_message_new(sd_bus *bus, sd_bus_message **m, uint8_t type);

sd_bus_message *sd_bus_message_ref(sd_bus_message *m);

sd_bus_message *sd_bus_message_unref(sd_bus_message *m);

void sd_bus_message_unrefp(sd_bus_message **mp);

sd_bus *sd_bus_message_get_bus(sd_bus_message *m);

DESCRIPCIÓN

sd_bus_message_new() crea un nuevo objeto de mensaje de bus adjunto al bus bus y lo devuelve en el parámetro de salida m. Este objeto tiene un contador de referencias y se destruirá cuando todas las referencias desaparezcan. Inicialmente, el llamador de esta función posee la única referencia al objeto del mensaje. Tenga en cuenta que el objeto del mensaje mantiene una referencia al objeto del bus, por lo que el objeto del bus no se destruirá mientras exista el mensaje.

Nota: esta es una llamada de bajo nivel. En la mayoría de los casos, funciones como sd_bus_message_new_method_call(3), sd_bus_message_new_method_error(3), sd_bus_message_new_method_return(3), y sd_bus_message_new_signal(3) que crean un mensaje de un tipo determinado e inicializan varios campos son más fáciles de usar.

El parámetro type especifica el tipo del mensaje. Debe ser uno de SD_BUS_MESSAGE_METHOD_CALL — una llamada a método, SD_BUS_MESSAGE_METHOD_RETURN — una respuesta a una llamada a método, SD_BUS_MESSAGE_METHOD_ERROR — una respuesta de error a una llamada a método, SD_BUS_MESSAGE_SIGNAL — un mensaje de difusión sin respuesta.

La bandera para permitir la autorización interactiva se inicializa basándose en el valor actual establecido en el objeto del bus, consulte sd_bus_set_allow_interactive_authorization(3). Esto se puede cambiar usando sd_bus_message_set_allow_interactive_authorization(3).

sd_bus_message_ref() incrementa el contador interno de referencias de m en uno.

sd_bus_message_unref() decrementa el contador interno de referencias de m en uno. Una vez que el contador de referencias ha caído a cero, el objeto del mensaje se destruye y no se puede usar más, por lo que las llamadas posteriores a sd_bus_message_ref() o sd_bus_message_unref() son ilegales.

sd_bus_message_unrefp() es similar a sd_bus_message_unref() pero toma un puntero a un puntero a un objeto sd_bus_message. Esta llamada es útil junto con el Atributo de variable de limpieza de GCC y LLVM[1]. Consulte sd_bus_new(3) para ver un ejemplo de cómo usar el atributo de limpieza.

sd_bus_message_ref() y sd_bus_message_unref() no realizan ninguna operación si la dirección del objeto del mensaje de bus proporcionada es NULL. sd_bus_message_unrefp() primero desreferenciará su argumento, que no debe ser NULL, y no realizará ninguna operación si *ese* es NULL.

sd_bus_message_get_bus() devuelve el objeto del bus al que está adjunto el mensaje m.

VALOR DE RETORNO

En caso de éxito, sd_bus_message_new() devuelve 0 o un entero positivo. En caso de fallo, devuelve un código de error negativo de estilo errno.

sd_bus_message_ref() siempre devuelve el argumento.

sd_bus_message_unref() siempre devuelve NULL.

sd_bus_message_get_bus() siempre devuelve el objeto del bus.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

El type especificado es inválido.

-ENOTCONN

El parámetro del bus bus es NULL o el bus no está conectado.

-ENOMEM

Fallo en la asignación de memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo libsystemd de pkg-config(1).

El código descrito aquí utiliza getenv(3), que está declarado como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando aún no se han iniciado otros hilos.

HISTORIAL

sd_bus_message_new(), sd_bus_message_ref(), sd_bus_message_unref(), sd_bus_message_unrefp(), y sd_bus_message_get_bus() se añadieron en la versión 240.
