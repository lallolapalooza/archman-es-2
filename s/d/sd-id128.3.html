DESCRIPCIÓN

sd-id128.h es parte de libsystemd(3) y proporciona APIs para generar, convertir y comparar valores de ID de 128 bits. Los valores de ID de 128 bits procesados y generados por estas APIs son una generalización de los UUIDs de OSF tal como se definen en RFC 4122[1] pero utilizan un formato de cadena más simple. Estas funciones no imponen ninguna estructura en los IDs utilizados, a diferencia de los UUIDs de OSF o los GUIDs de Microsoft, pero son mayormente compatibles con esos tipos de IDs.

Un ID de 128 bits se implementa como el siguiente tipo unión:

typedef union sd_id128 {
  uint8_t bytes[16];
  uint64_t qwords[2];
} sd_id128_t;

Esta unión permite acceder al ID de 128 bits como 16 bytes separados o dos palabras de 64 bits. Generalmente es más seguro acceder a los componentes del ID a través de su arreglo de 8 bits para evitar problemas de endianness. Esta unión está destinada a ser pasada por valor (en lugar de por referencia) y puede ser manipulada directamente por los clientes.

Se definen un par de macros para denotar y decodificar IDs de 128 bits:

SD_ID128_MAKE() se utiliza para escribir un ID constante en el código fuente. Un modismo comúnmente utilizado es asignar un nombre a un ID usando esta macro:

#define SD_MESSAGE_COREDUMP SD_ID128_MAKE(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)

SD_ID128_NULL define un ID que consiste únicamente en bytes NUL (es decir, todos los bits apagados).

SD_ID128_ALLF define un ID que consiste únicamente en bytes 0xFF (es decir, todos los bits encendidos).

SD_ID128_MAKE_STR() es similar a SD_ID128_MAKE(), pero crea una expresión const char* que puede ser utilizada convenientemente en formatos de mensajes y similares:

#include <stdio.h>
#define SD_MESSAGE_COREDUMP_STR SD_ID128_MAKE_STR(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)
int main(int argc, char **argv) {
  puts("Match for coredumps: MESSAGE_ID=" SD_MESSAGE_COREDUMP_STR);
}

SD_ID128_CONST_STR() convierte IDs constantes en cadenas constantes para su salida. El siguiente código de ejemplo generará la cadena "fc2e22bc6ee647b6b90729ab34a250b1":

int main(int argc, char *argv[]) {
  puts("Match for coredumps: %s", SD_ID128_CONST_STR(SD_MESSAGE_COREDUMP));
}

SD_ID128_FORMAT_STR y SD_ID128_FORMAT_VAL() se utilizan para formatear un ID en una cadena de formato printf(3), como se muestra en el siguiente ejemplo:

int main(int argc, char *argv[]) {
  sd_id128_t id;
  id = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  printf("The ID encoded in this C file is " SD_ID128_FORMAT_STR ".\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}

SD_ID128_UUID_FORMAT_STR y SD_ID128_MAKE_UUID_STR() son similares a SD_ID128_FORMAT_STR y SD_ID128_MAKE_STR(), pero incluyen guiones separadores para cumplir con la "representación canónica de UUID[2]". Forman la cadena basándose en las reglas del Variante 1 Versión 4 de RFC4122[1], es decir, convirtiendo desde el orden de bytes Big Endian. Esto coincide con el comportamiento de la mayoría de la infraestructura del espacio de usuario de Linux. Probablemente sea mejor evitar UUIDs de otros variantes para evitar ambigüedades innecesarias. Todos los IDs de 128 bits generados por las APIs de sd-id128 se conforman estrictamente a UUIDs de Variante 1 Versión 4, según RFC 4122.

sd_id128_equal() compara dos IDs de 128 bits:

int main(int argc, char *argv[]) {
  sd_id128_t a, b, c;
  a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  b = SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e);
  c = a;
  assert(sd_id128_equal(a, c));
  assert(!sd_id128_equal(a, b));
  return 0;
}

sd_id128_string_equal() es similar a sd_id128_equal(), pero el primer ID se formatea como const char*. Se aplican las mismas restricciones que al primer argumento de sd_id128_from_string().

sd_id128_is_null() comprueba si un ID consta únicamente de bytes NUL:

assert(sd_id128_is_null(SD_ID128_NULL));

De manera similar, sd_id128_is_allf() comprueba si un ID consta únicamente de bytes 0xFF (todos los bits encendidos):

assert(sd_id128_is_allf(SD_ID128_ALLF));

sd_id128_in_set_sentinel() toma una lista de IDs y devuelve true si el primer argumento es igual a cualquiera de los argumentos subsiguientes. La lista de argumentos está terminada por un centinela SD_ID128_NULL, que debe estar presente.

sd_id128_in_set() es una función de conveniencia que toma una lista de IDs y devuelve true si el primer argumento es igual a cualquiera de los argumentos subsiguientes:

int main(int argc, char *argv[]) {
  sd_id12_t a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  assert(sd_id128_in_set(a, a));
  assert(sd_id128_in_set(a, a, a));
  assert(!sd_id128_in_set(a));
  assert(!sd_id128_in_set(a,
                          SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e)
                          SD_ID128_MAKE(2f,88,28,5f,9c,44,09,9d,d7,15,77,04,bc,85,7e,e3)
                          SD_ID128_ALLF));
  return 0;
}

sd_id128_in_set() se define como una macro sobre sd_id128_in_set_sentinel(), añadiendo automáticamente el centinela SD_ID128_NULL. Dado que sd_id128_in_set_sentinel() utiliza SD_ID128_NULL como centinela, SD_ID128_NULL no puede ser colocado de otra manera en la lista de argumentos.

sd_id128_in_setv() es similar a sd_id128_in_set_sentinel(), pero toma un argumento de tipo varargs de struct.

Se pueden generar nuevos IDs aleatorios con el comando new de systemd-id128(1).

Consulte sd_id128_to_string(3), sd_id128_randomize(3) y sd_id128_get_machine(3) para obtener información sobre otras impleme

sd-id128.3.en

NAME

sd_id128_equal, sd_id128_string_equal, sd_id128_is_null, sd_id128_is_allf, sd_id128_in_setv, sd_id128_in_set_sentinel, sd_id128_in_set — Compare and check 128-bit identifiers

SYNOPSIS

#include <systemd/sd-id128.h>

int sd_id128_equal(const sd_id128_t *a, const sd_id128_t *b);
int sd_id128_string_equal(const char *a, const char *b);
int sd_id128_is_null(const sd_id128_t *id);
int sd_id128_is_allf(const sd_id128_t *id);
int sd_id128_in_setv(const sd_id128_t *id, const sd_id128_t * const *set);
int sd_id128_in_set_sentinel(const sd_id128_t *id, const sd_id128_t * const *set, const sd_id128_t *sentinel);
int sd_id128_in_set(const sd_id128_t *id, ...);

DESCRIPTION

These functions are used to compare and check 128-bit identifiers, which are commonly used for UUIDs (Universally Unique Identifiers).

The sd_id128_t type is an opaque type representing a 128-bit identifier. It is usually initialized using functions like sd_id128_randomize(3), sd_id128_get_machine(3), or parsed from a string representation using sd_id128_to_string(3).

The sd_id128_equal() function compares two sd_id128_t identifiers a and b. It returns a positive value if they are equal, zero if they are not equal, and a negative value on error.

The sd_id128_string_equal() function compares two string representations of 128-bit identifiers a and b. It returns a positive value if they are equal, zero if they are not equal, and a negative value on error. This function is a wrapper around sd_id128_equal() that parses the strings first. It may fail if the strings are not valid representations.

The sd_id128_is_null() function checks if the given sd_id128_t identifier id is the null identifier (all bits zero). It returns 1 if it is the null identifier, 0 otherwise, and a negative value on error.

The sd_id128_is_allf() function checks if the given sd_id128_t identifier id is the "all ones" identifier (all bits set to 1). It returns 1 if it is the all ones identifier, 0 otherwise, and a negative value on error.

The sd_id128_in_setv() function checks if the sd_id128_t identifier id is present in the set of identifiers passed in the null-terminated array set. It returns 1 if the identifier is found, 0 otherwise, and a negative value on error.

The sd_id128_in_set_sentinel() function is similar to sd_id128_in_setv(), but uses a specific sentinel identifier to mark the end of the set instead of a null pointer. This can be useful if the null identifier itself needs to be part of the set.

The sd_id128_in_set() function is a variadic function that takes a sd_id128_t identifier id followed by a list of sd_id128_t identifiers and a NULL pointer to terminate the list. It checks if id is present in the provided list. It returns 1 if the identifier is found, 0 otherwise, and a negative value on error.

The comparison functions return a non-negative value on success and a negative value on error. For the boolean check functions (sd_id128_is_null, sd_id128_is_allf, sd_id128_in_setv, sd_id128_in_set_sentinel, sd_id128_in_set), the return value is 1 for true, 0 for false, and a negative value on error.

All functions take pointers to sd_id128_t objects as arguments, except for sd_id128_string_equal() and sd_id128_in_set().

The functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config file. For details, see pkg-config(1).

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.
