DESCRIPCIÓN

Estas funciones devuelven información de credenciales de un objeto sd_bus_creds. Los objetos de credenciales se pueden crear con sd_bus_creds_new_from_pid(3), en cuyo caso describen las credenciales del proceso identificado por el PID especificado, con sd_bus_get_name_creds(3), en cuyo caso describen las credenciales de un par del bus identificado por el nombre del bus especificado, con sd_bus_get_owner_creds(3), en cuyo caso describen las credenciales del creador de un bus, o con sd_bus_message_get_creds(3), en cuyo caso describen las credenciales del remitente del mensaje.

No todos los campos de credenciales forman parte de cada objeto "sd_bus_creds". Utilice sd_bus_creds_get_mask(3) para determinar la máscara de campos disponibles.

sd_bus_creds_get_pid() recuperará el PID (identificador de proceso). Del mismo modo, sd_bus_creds_get_ppid() recuperará el PID padre. Tenga en cuenta que el PID 1 no tiene proceso padre, en cuyo caso se devuelve -ENXIO.

sd_bus_creds_get_pidfd_dup() recuperará el descriptor de archivo PID (pidfd), consulte pidfd_open(2) para más detalles. El descriptor de archivo se duplica y, por lo tanto, el llamante debe cerrarlo.

sd_bus_creds_get_tid() recuperará el TID (identificador de hilo).

sd_bus_creds_get_uid() recuperará el UID numérico (identificador de usuario). Del mismo modo, sd_bus_creds_get_euid() devuelve el UID efectivo, sd_bus_creds_get_suid() el UID guardado y sd_bus_creds_get_fsuid() el UID del sistema de archivos.

sd_bus_creds_get_gid() recuperará el GID numérico (identificador de grupo). Del mismo modo, sd_bus_creds_get_egid() devuelve el GID efectivo, sd_bus_creds_get_sgid() el GID guardado y sd_bus_creds_get_fsgid() el GID del sistema de archivos.

sd_bus_creds_get_supplementary_gids() recuperará la lista de GIDs suplementarios.

sd_bus_creds_get_comm() recuperará el campo comm (nombre truncado del ejecutable, tal como se almacena en /proc/pid/comm).

sd_bus_creds_get_tid_comm() recuperará el campo comm del hilo (tal como se almacena en /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() recuperará la ruta al ejecutable del programa (tal como se almacena en el enlace /proc/pid/exe, pero con el sufijo " (deleted)" eliminado). Tenga en cuenta que los hilos del kernel no tienen una ruta ejecutable, en cuyo caso se devuelve -ENXIO. Tenga en cuenta que esta propiedad no debe utilizarse para más que información explicativa, en particular no debe utilizarse para decisiones relevantes para la seguridad. Esto se debe a que el ejecutable podría haber sido reemplazado o eliminado en el momento en que se pueda procesar el valor. DESCRIPTION

La estructura `sd_bus_creds` es una abstracción para obtener información sobre los credenciales de un proceso o conexión de bus. Se crea típicamente con `sd_bus_creds_new_from_pid(3)` o `sd_bus_creds_new_from_fd(3)` para obtener los credenciales de un proceso en ejecución, o es devuelto por funciones de `sd-bus(3)` como `sd_bus_get_creds(3)` para representar los credenciales del par de una conexión de bus. La memoria de la estructura `sd_bus_creds` debe ser liberada por el llamante usando `sd_bus_creds_unref(3)`.

Estas funciones recuperan campos específicos de la estructura `sd_bus_creds`. Si los datos solicitados no están disponibles en los credenciales, o si no se pueden obtener por alguna otra razón, se devuelve un código de error negativo.

sd_bus_creds_get_pidfd_dup() duplicará el descriptor de archivo PID del proceso, permitiendo su uso para la monitorización del ciclo de vida del proceso o para acceder a `/proc/[pid]/...` archivos. Se devuelve un descriptor de archivo de solo lectura si el par tiene un PID y el descriptor de archivo está disponible. Si no, se devuelve -ENXIO.

sd_bus_creds_get_pid(), sd_bus_creds_get_tid(), sd_bus_creds_get_ppid(), sd_bus_creds_get_uid(), sd_bus_creds_get_euid(), sd_bus_creds_get_suid(), sd_bus_creds_get_fsuid(), sd_bus_creds_get_gid(), sd_bus_creds_get_egid(), sd_bus_creds_get_sgid(), sd_bus_creds_get_fsgid() recuperarán el ID de proceso, ID de hilo, PID padre, UID real, UID efectivo, UID guardado, UID del sistema de archivos, GID real, GID efectivo, GID guardado y GID del sistema de archivos, respectivamente.

sd_bus_creds_get_supplementary_gids() recuperará la lista de GIDs suplementarios del proceso. El array devuelto es terminado en NULL y el puntero individual de GID se puede pasar a getgrgid(3).

sd_bus_creds_get_comm() recuperará el nombre de comandos del proceso. Este es típicamente el nombre del ejecutable, truncado a 15 bytes.

sd_bus_creds_get_tid_comm() recuperará el nombre de comandos del hilo.

sd_bus_creds_get_exe() recuperará la ruta de acceso del archivo ejecutable del proceso (en `/proc/pid/exe`). Tenga en cuenta que los hilos del kernel no tienen un ejecutable, en cuyo caso se devuelve -ENXIO.

sd_bus_creds_get_cmdline() recuperará un array de argumentos de línea de comandos (tal como se almacena en `/proc/pid/cmdline`). Tenga en cuenta que los hilos del kernel no tienen una línea de comandos, en cuyo caso se devuelve -ENXIO.

sd_bus_creds_get_cgroup() recuperará la ruta del grupo de control. Ver Control Groups v2[1].

sd_bus_creds_get_unit() recuperará el nombre de la unidad de systemd (en la instancia del sistema de systemd) de la que forma parte el proceso. Ver systemd.unit(5). Para procesos que no forman parte de una unidad, devuelve -ENXIO.

sd_bus_creds_get_user_unit() recuperará el nombre de la unidad de systemd (en la instancia del usuario de systemd) de la que forma parte el proceso. Ver systemd.unit(5). Para procesos que no forman parte de una unidad de usuario, devuelve -ENXIO.

sd_bus_creds_get_slice() recuperará la slice de systemd (una unidad en la instancia del sistema de systemd) de la que forma parte el proceso. Ver systemd.slice(5). De manera similar, sd_bus_creds_get_user_slice() recuperará la slice de systemd del proceso, en la instancia del usuario de systemd.

sd_bus_creds_get_session() recuperará el identificador de la sesión de inicio de sesión de la que forma parte el proceso. Tenga en cuenta que la sesión de inicio de sesión puede limitarse a uno o dos procesos "stub". Los procesos de usuario pueden ser iniciados en su lugar desde su gestor de usuarios systemd, por ejemplo, aplicaciones GUI iniciadas usando activación DBus, así como procesos de servicio que se comparten entre múltiples inicios de sesión del mismo usuario. Para procesos que no forman parte de una sesión, devuelve -ENXIO.

sd_bus_creds_get_owner_uid() recuperará el UID numérico (identificador de usuario) del usuario que posee la unidad de usuario o sesión de inicio de sesión de la que forma parte el proceso. Ver systemd-logind.service(8). Para procesos que no forman parte de una unidad de usuario o sesión, devuelve -ENXIO.

sd_bus_creds_has_effective_cap() comprobará si la capacidad especificada por capability estaba establecida en la máscara de capacidades efectivas. Un valor de retorno positivo significa que estaba establecida, cero significa que no estaba establecida, y un valor de retorno negativo indica un error. Ver capabilities(7) y los ajustes AmbientCapabilities= y CapabilityBoundingSet= en systemd.exec(5).

sd_bus_creds_has_permitted_cap() es similar a sd_bus_creds_has_effective_cap(), pero comprobará la máscara de capacidades permitidas.

sd_bus_creds_has_inheritable_cap() es similar a sd_bus_creds_has_effective_cap(), pero comprobará la máscara de capacidades heredables.

sd_bus_creds_has_bounding_cap() es similar a sd_bus_creds_has_effective_cap(), pero comprobará la máscara de capacidades de delimitación.

sd_bus_creds_get_selinux_context() recuperará el contexto de seguridad SELinux (etiqueta) del proceso.

sd_bus_creds_get_audit_session_id() recuperará el identificador de sesión de auditoría del proceso. Devuelve -ENXIO para procesos que no forman parte de una sesión de auditoría.

sd_bus_creds_get_audit_login_uid() recuperará el identificador de inicio de sesión de usuario de auditoría (el identificador del usuario que es "responsable" de la sesión). Devuelve -ENXIO para procesos que no forman parte de una sesión de auditoría.

sd_bus_creds_get_tty() recuperará el TTY de control, sin el prefijo "/dev/". Devuelve -ENXIO para procesos que no tienen un TTY de control.

sd_bus_creds_get_description() recuperará un nombre descriptivo de la conexión de bus del par. Este nombre es útil para discernir múltiples conexiones de bus del mismo par, y puede ser alterado por el par con la llamada sd_bus_set_description(3).

sd_bus_creds_get_unique_name() recuperará el nombre único de D-Bus. Ver The D-Bus specification[2].

sd_bus_creds_get_well_known_names() recuperará el conjunto de nombres bien conocidos de D-Bus. Ver The D-Bus specification[2].

Todas las funciones que toman un parámetro const char** almacenarán la respuesta allí como una dirección de una cadena terminada en NUL. Será válida mientras c siga siendo válida, y no debe ser liberada ni modificada por el llamante.

Todas las funciones que toman un parámetro char*** almacenarán la respuesta allí como una dirección de un array de cadenas. Cada cadena individual está terminada en NUL, y el array está terminado en NULL en su conjunto. Será válida mientras c siga siendo válida, y no debe ser liberada ni modificada por el llamante.

RETURN VALUE

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, estas llamadas devuelven un código de error negativo estilo errno.

Errors

Los errores devueltos pueden indicar los siguientes problemas:

-ENODATA

El campo dado no está disponible en el objeto de credenciales c.

-ENXIO

El campo dado no está especificado para el proceso o par descrito. Esto será devuelto por sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), y sd_bus_creds_get_session() si el proceso no forma parte de una unidad de sistema systemd, unidad de usuario systemd, slice systemd, o sesión logind. Será devuelto por sd_bus_creds_get_owner_uid() si el proceso no forma parte de una unidad de usuario systemd o sesión logind. También será devuelto por sd_bus_creds_get_exe() y sd_bus_creds_get_cmdline() para hilos del kernel (ya que estos no se inician desde un binario ejecutable, ni tienen una línea de comandos), y por sd_bus_creds_get_audit_session_id() y sd_bus_creds_get_audit_login_uid() cuando el proceso no forma parte de una sesión de auditoría, y sd_bus_creds_get_tty() si el proceso no tiene un TTY de control.

-EINVAL

El parámetro de puntero especificado es NULL.

-ENOMEM

Fallo en la asignación de memoria.

NOTES

Las funciones descritas aquí están disponibles como una biblioteca compartida, la cual puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

El código descrito aquí usa getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda solo realizar llamadas a setenv() desde una fase temprana del programa cuando no se han iniciado otros hilos.
