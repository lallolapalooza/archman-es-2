sd_bus_message_append_array(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_MESSAGE_APPEND_ARRAY(3) sd_bus_message_append_array SD_BUS_MESSAGE_APPEND_ARRAY(3)

NOMBRE

sd_bus_message_append_array, sd_bus_message_append_array_memfd, sd_bus_message_append_array_iovec, sd_bus_message_append_array_space - Añadir un array de campos a un mensaje D-Bus

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_append_array(sd_bus_message *m, char type, const void *ptr, size_t size);

int sd_bus_message_append_array_memfd(sd_bus_message *m, char type, int memfd, uint64_t offset, uint64_t size);

int sd_bus_message_append_array_iovec(sd_bus_message *m, char type, const struct iovec *iov, unsigned n);

int sd_bus_message_append_array_space(sd_bus_message *m, char type, size_t size, void **ptr);

DESCRIPCIÓN

La función sd_bus_message_append_array() añade un array a un mensaje D-Bus m. Se abrirá un contenedor, se añadirán los contenidos del array y se cerrará el contenedor. El parámetro type determina cómo se interpreta el puntero p. type debe ser uno de los tipos "triviales" "y", "n", "q", "i", "u", "x", "t", "d" (pero no "b"), según se define en la sección Tipos Básicos de D-Bus[1] de la especificación D-Bus, y listados en sd_bus_message_append_basic(3). El puntero p debe apuntar a un array de tamaño size bytes que contenga elementos del tipo respectivo. El tamaño size debe ser un múltiplo del tamaño del tipo type. Como caso especial, p puede ser NULL, si size es 0. La memoria apuntada por p se copia al área de memoria que contiene el mensaje y permanece en posesión del llamante. Por lo tanto, el llamante puede modificar libremente los datos después de esta llamada sin afectar al mensaje al que se añadió el array.

La función sd_bus_message_append_array_memfd() añade un array de un tipo trivial al mensaje m, similar a sd_bus_message_append_array(). Los contenidos del descriptor de archivo de memoria memfd comenzando en la posición especificada y del tamaño especificado se utilizan como los contenidos del array. La posición y el tamaño deben ser un múltiplo del tamaño del tipo type. Sin embargo, como una excepción especial, si la posición se especifica como cero y el tamaño especificado como UINT64_MAX, se utiliza el contenido completo del descriptor de archivo de memoria. El descriptor de archivo de memoria se sella mediante esta llamada si aún no se ha sellado, y no se puede modificar después de esta llamada. Consulte memfd_create(2) para obtener detalles sobre los descriptores de archivo de memoria. Añadir arrays con descriptores de archivo de memoria permite la transferencia eficiente de datos sin copias, ya que el descriptor de archivo de memoria puede pasarse tal cual al destino, sin copiar la memoria en él al proceso de destino. No todos los transportes de protocolo admiten el paso de descriptores de archivo de memoria entre participantes, en cuyo caso esta llamada recurrirá automáticamente a la copia. Además, dado que el paso de descriptores de archivo de memoria es ineficiente para cantidades pequeñas de datos, la copia puede seguir siendo forzada incluso donde se admite el paso de descriptores de archivo de memoria.

La función sd_bus_message_append_array_iovec() añade un array de un tipo trivial al mensaje m, similar a sd_bus_message_append_array(). Los contenidos del array de vectores de E/S iov se utilizan como los contenidos del array. El tamaño total de la carga útil de iov (la suma de los campos iov_len) debe ser un múltiplo del tamaño del tipo type. El argumento iov debe apuntar a n estructuras de vector de E/S. Cada estructura puede tener el campo iov_base establecido, en cuyo caso la memoria apuntada se copiará en el mensaje, o no establecido (establecido a cero), en cuyo caso se insertará un bloque de ceros de longitud iov_len bytes. La memoria apuntada por iov puede modificarse después de esta llamada.

La función sd_bus_message_append_array_space() añade espacio para un array de un tipo trivial al mensaje m. Se comporta igual que sd_bus_message_append_array(), pero en lugar de copiar los elementos al mensaje, devuelve un puntero al área de destino al llamante en el puntero p. Posteriormente, el llamante debe escribir los contenidos del array en esta memoria. Las modificaciones en la memoria apuntada solo deben realizarse hasta que se invoque la siguiente operación en el mensaje del bus. Lo más importante es que la memoria ya no debe alterarse cuando se ha añadido otro campo al mensaje o el mensaje se ha sellado.

VALOR DE RETORNO

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Parámetro especificado es inválido.

-EPERM

Mensaje ha sido sellado.

-ESTALE

Mensaje está en estado inválido.

-ENXIO

El mensaje no puede ser añadido.

-ENOMEM

Error de asignación de memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar contra y enlazar con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
