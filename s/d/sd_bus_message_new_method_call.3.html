sd_bus_message_new_method_call(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_MESSAGE_NEW_METHOD_CALL(3) sd_bus_message_new_method_call SD_BUS_MESSAGE_NEW_METHOD_CALL(3)

NOMBRE

sd_bus_message_new_method_call, sd_bus_message_new_method_return - Crear un mensaje de llamada a método

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_new_method_call(sd_bus *bus, sd_bus_message **m, const char *destination, const char *path, const char *interface, const char *member);

int sd_bus_message_new_method_return(sd_bus_message *call, sd_bus_message **m);

DESCRIPCIÓN

La función sd_bus_message_new_method_call() crea un nuevo objeto de mensaje de bus que encapsula una llamada a método D-Bus y lo devuelve en el parámetro de salida m. La llamada se realizará al destino destination, en la ruta path, en la interfaz interface, y con el miembro member.

Brevemente, el destination es un nombre separado por puntos que identifica un servicio conectado al bus. El path es un identificador separado por barras de un objeto dentro del destino que se parece a una ruta de sistema de archivos. El significado de esta ruta lo define el destino. La interface es un nombre separado por puntos que se parece a un nombre de interfaz de Java que identifica un grupo de métodos y señales soportadas por el objeto identificado por la ruta. Los métodos y señales se denominan colectivamente miembros y se identifican por un nombre simple compuesto por letras ASCII, números y guiones bajos. Consulte el Tutorial de D-Bus[1] para una explicación en profundidad.

El parámetro destination puede ser NULL. El parámetro interface puede ser NULL, si el destino tiene un solo miembro con el nombre dado y no hay ambigüedad si se omite el nombre de la interfaz.

Tenga en cuenta que esta es una interfaz de bajo nivel. Consulte sd_bus_call_method(3) para una forma más conveniente de llamar a métodos D-Bus.

La función sd_bus_message_new_method_return() crea un nuevo objeto de mensaje de bus que es una respuesta a la llamada de método call y lo devuelve en el parámetro de salida m. El parámetro call debe ser un mensaje de llamada a método. El remitente de call se utiliza como destino.

VALOR DEVUELTO

En caso de éxito, estas funciones devuelven un entero no negativo. En caso de error, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

El parámetro de salida m es NULL.

El parámetro destination no es nulo y no es un nombre de servicio D-Bus válido ("org.somewhere.Something"), el parámetro path no es una ruta D-Bus válida ("/an/object/path"), el parámetro interface no es nulo y no es un nombre de interfaz D-Bus válido ("an.interface.name"), o el parámetro member no es un miembro D-Bus válido ("Name").

El parámetro call no es un objeto de llamada a método.

-ENOTCONN

El parámetro de bus bus es NULL o el bus no está conectado.

-ENOMEM

Fallo de asignación de memoria.

-EPERM

El parámetro call no está sellado.

-EOPNOTSUPP

El mensaje call no tiene una cookie.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un subproceso paralelo. Se recomienda realizar llamadas a setenv() solo en una fase temprana del programa cuando no se hayan iniciado otros subprocesos.

EJEMPLOS

Ejemplo 1. Realizar una llamada a un método D-Bus que toma un solo parámetro

/* SPDX-License-Identifier: MIT-0 */
/* Esto es equivalente a:
 * busctl call org.freedesktop.systemd1 /org/freedesktop/systemd1 \
 *       org.freedesktop.systemd1.Manager GetUnitByPID $$
 *
 * Compilar con 'cc print-unit-path.c -lsystemd'
 */
#include <errno.h>
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
#define _cleanup_(f) __attribute__((cleanup(f)))
#define DESTINATION "org.freedesktop.systemd1"
#define PATH        "/org/freedesktop/systemd1"
#define INTERFACE   "org.freedesktop.systemd1.Manager"
#define MEMBER      "GetUnitByPID"
static int log_error(int error, const char *message) {
  fprintf(stderr, "%s: %s\n", message, strerror(-error));
  return error;
}
int main(int argc, char **argv) {
  _cleanup_(sd_bus_flush_close_unrefp) sd_bus *bus = NULL;
  _cleanup_(sd_bus_error_free) sd_bus_error error = SD_BUS_ERROR_NULL;
  _cleanup_(sd_bus_message_unrefp) sd_bus_message *reply = NULL, *m = NULL;
  int r;
  r = sd_bus_open_system(&bus);
  if (r < 0)
    return log_error(r, "Failed to acquire bus");
  r = sd_bus_message_new_method_call(bus, &m,
                                     DESTINATION, PATH, INTERFACE, MEMBER);
  if (r < 0)
    return log_error(r, "Failed to create bus message");
  r = sd_bus_message_append(m, "u", (unsigned) getpid());
  if (r < 0)
    return log_error(r, "Failed to append to bus message");
  r = sd_bus_call(bus, m, -1, &error, &reply);
  if (r < 0)
    return log_error(r, MEMBER " call failed");
  const char *ans;
  r = sd_bus_message_read(reply, "o", &ans);
  if (r < 0)
    return log_error(r, "Failed to read reply");
  printf("Unit path is \"%s\".\n", ans);
  return 0;
}

Esto define un programa mínimamente útil que abrirá una conexión al bus, creará un objeto de mensaje, lo enviará, esperará la respuesta y finalmente extraerá e imprimirá la respuesta. Maneja errores y la gestión adecuada de la memoria.
