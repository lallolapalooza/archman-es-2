SD_BUS_ADD_MATCH(3) sd_bus_add_match SD_BUS_ADD_MATCH(3)

NOMBRE

sd_bus_add_match, sd_bus_add_match_async, sd_bus_match_signal, sd_bus_match_signal_async - Añadir una regla de coincidencia para la distribución de mensajes entrantes

SINOPSIS

#include <systemd/sd-bus.h>

typedef int (*sd_bus_message_handler_t)(sd_bus_message *m, void *userdata, sd_bus_error *ret_error);

int sd_bus_add_match(sd_bus *bus, sd_bus_slot **slot, const char *match, sd_bus_message_handler_t callback, void *userdata);

int sd_bus_add_match_async(sd_bus *bus, sd_bus_slot **slot, const char *match, sd_bus_message_handler_t callback, sd_bus_message_handler_t install_callback, void *userdata);

int sd_bus_match_signal(sd_bus *bus, sd_bus_slot **slot, const char *sender, const char *path, const char *interface, const char *member, sd_bus_message_handler_t callback, void *userdata);

int sd_bus_match_signal_async(sd_bus *bus, sd_bus_slot **slot, const char *sender, const char *path, const char *interface, const char *member, sd_bus_message_handler_t callback, sd_bus_message_handler_t install_callback, void *userdata);

DESCRIPCIÓN

sd_bus_add_match() instala una regla de coincidencia para mensajes recibidos en el objeto de conexión de bus especificado bus. La sintaxis de la expresión de la regla de coincidencia pasada en match se describe en la Especificación de D-Bus[1]. La función manejadora especificada callback se llama para cada mensaje entrante que coincida con la expresión especificada, el parámetro userdata se pasa tal cual a la función de devolución de llamada. La coincidencia se instala de forma síncrona cuando se conecta a un intermediario de bus, es decir, la llamada envía un mensaje de control solicitando que la coincidencia se añada al intermediario y espera hasta que el intermediario confirme que la coincidencia se ha instalado correctamente.

sd_bus_add_match_async() opera de manera muy similar a sd_bus_add_match(), sin embargo, instala la coincidencia de forma asíncrona, sin bloqueo: se envía una solicitud al intermediario, pero la llamada no espera una respuesta. La función install_callback se llama cuando la respuesta se recibe más tarde, con el mensaje de respuesta del intermediario como parámetro. Si esta función se especifica como NULL, se utiliza una implementación predeterminada que termina la conexión del bus si falla la instalación de la coincidencia.

sd_bus_match_signal() es muy similar a sd_bus_add_match(), pero solo coincide con señales, y en lugar de una expresión de coincidencia, acepta cuatro parámetros: sender (el nombre del servicio del remitente), path (la ruta del objeto del objeto emisor), interface (la interfaz a la que pertenece la señal), member (el nombre de la señal), a partir de los cuales la cadena de coincidencia se genera internamente. Opcionalmente, estos parámetros pueden especificarse como NULL, en cuyo caso el campo relevante de las señales entrantes no se prueba.

sd_bus_match_signal_async() combina la lógica de coincidencia de señales de sd_bus_match_signal() con el comportamiento asíncrono de sd_bus_add_match_async().

En caso de éxito, y si no es NULL, el parámetro de retorno slot se establecerá en un objeto de ranura que puede utilizarse como referencia a la coincidencia instalada y puede utilizarse para eliminarla más adelante con sd_bus_slot_unref(3). Si se especifica como NULL, la vida útil de la coincidencia está ligada a la vida útil del objeto de bus en sí, y la coincidencia generalmente no se elimina independientemente. Consulte sd_bus_slot_set_floating(3) para obtener más detalles.

El mensaje m pasado a la devolución de llamada solo se presta, es decir, la devolución de llamada no debe llamar a sd_bus_message_unref(3). Si la devolución de llamada desea conservar el mensaje más allá de la vida útil de la devolución de llamada, necesita llamar a sd_bus_message_ref(3) para crear una nueva referencia.

Si ocurre un error durante la invocación de la devolución de llamada, la devolución de llamada debe devolver un número de error negativo (opcionalmente, se puede devolver un error más preciso en ret_error). Si desea que se llamen otras devoluciones de llamada que coincidan con la misma regla, debe devolver 0. De lo contrario, debe devolver un entero positivo.

Si el bus se refiere a una conexión directa (es decir, no a una conexión de bus, como se establece con sd_bus_set_bus_client(3)), la coincidencia solo se instala en el lado del cliente, y las funciones síncronas y asíncronas operan de la misma manera.

VALOR DE RETORNO

En caso de éxito, sd_bus_add_match() y las otras llamadas devuelven 0 o un entero positivo. En caso de fallo, devuelven un código de error negativo estilo errno.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para subprocesos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se han iniciado otros hilos.

HISTORIA

sd_bus_add_match() y sd_bus_message_handler_t() se añadieron en la versión 221.

sd_bus_add_match_async(), sd_bus_match_signal(), y sd_bus_match_signal_async() se añadieron en la versión 237.
