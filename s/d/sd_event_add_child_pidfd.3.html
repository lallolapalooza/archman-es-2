#include <systemd/sd-event.h>

DESCRIPCIÓN

sd_event_add_child() añade una nueva fuente de eventos de cambio de estado de proceso hijo a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro pid especifica el PID del proceso a vigilar, que debe ser un hijo directo del proceso invocador. El parámetro options determina qué cambios de estado se vigilarán. Debe contener una máscara OR de WEXITED (vigilar la terminación del proceso hijo), WSTOPPED (vigilar la detención del proceso hijo por una señal) y WCONTINUED (vigilar la reanudación del proceso hijo por una señal). Ver waitid(2) para más información.

El handler debe ser una función a llamar cuando el proceso cambie de estado o NULL. A la función manejadora se le pasará el puntero userdata, que puede ser elegido libremente por el llamador. El manejador también recibe un puntero a una estructura siginfo_t que contiene información sobre el evento del proceso hijo. El manejador puede devolver un valor negativo para indicar un error (ver abajo), otros valores de retorno se ignoran. Si handler es NULL, se usará un manejador por defecto que llama a sd_event_exit(3).

Solo se puede instalar un manejador para un proceso hijo específico. El manejador está habilitado para un solo evento (SD_EVENT_ONESHOT), pero esto puede cambiarse con sd_event_source_set_enabled(3). Si la función manejadora devuelve un código de error negativo, será deshabilitada después de la invocación, incluso si se solicitó el modo SD_EVENT_ON previamente, o causará la terminación del bucle, ver sd_event_source_set_exit_on_failure(3).

Para destruir un objeto de fuente de eventos, use sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se liberan todas las referencias a ella. Para asegurarse de que una fuente de eventos no se dispare más, incluso cuando todavía hay una referencia a ella, considere establecer la fuente de eventos en SD_EVENT_OFF con sd_event_source_set_enabled(3).

La señal SIGCHLD debe estar bloqueada en todos los hilos antes de llamar a esta función (usando sigprocmask(2) o pthread_sigmask(3)).

Si el segundo parámetro de sd_event_add_child() se pasa como NULL, no se devuelve ninguna referencia al objeto de la fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando se destruya el propio bucle de eventos.

Tenga en cuenta que la función handler se invoca en un momento en que el proceso hijo aún no ha sido recolectado (y por lo tanto todavía es expuesto como un proceso zombi por el kernel). Sin embargo, el hijo será recolectado automáticamente después de que la función retorne. Los procesos hijos para los cuales no se instalan fuentes de eventos de cambio de estado de proceso hijo no serán recolectados por la implementación del bucle de eventos.

Si el parámetro handler de sd_event_add_child() es NULL, y la fuente de eventos se dispara, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a un entero, se pasa como parámetro de código de salida a sd_event_exit(3).

Si tanto una fuente de eventos de cambio de estado de proceso hijo como una fuente de eventos de señal SIGCHLD están instaladas en el mismo bucle de eventos, las prioridades de las fuentes de eventos configuradas deciden qué fuente de eventos se despacha primero. Si el manejador de señales se procesa primero, debe dejar los procesos hijos para los que se han instalado fuentes de eventos de cambio de estado de proceso hijo sin recolectar.

sd_event_add_child_pidfd() es similar a sd_event_add_child() pero toma un descriptor de archivo que hace referencia al proceso ("pidfd") en lugar del PID numérico. Un descriptor de archivo adecuado puede obtenerse a través de pidfd_open(2) y llamadas relacionadas. El descriptor de archivo pasado no se cierra cuando la fuente de eventos se libera de nuevo, a menos que se use sd_event_source_set_child_pidfd_own() para activar este comportamiento. Tenga en cuenta que independientemente de si se usó sd_event_add_child() o sd_event_add_child_pidfd() para asignar una fuente de eventos, el proceso vigilado debe ser un proceso hijo directo del proceso invocador. También en ambos casos, SIGCHLD debe estar bloqueada en el proceso invocador.

sd_event_source_get_child_pid() recupera el PID configurado de una fuente de eventos de cambio de estado de proceso hijo creada previamente con sd_event_add_child(). Toma el objeto de la fuente de eventos como parámetro source y un puntero a una variable pid_t para devolver el ID del proceso.

sd_event_source_get_child_pidfd() recupera el descriptor de archivo que hace referencia al proceso vigilado ("pidfd"). El bucle de eventos utiliza internamente pidfds para vigilar procesos hijos, independientemente de si las fuentes de eventos individuales se asignan a través de sd_event_add_child() o sd_event_add_child_pidfd(). Si esta última llamada se utilizó para asignar la fuente de eventos, esta función devuelve el descriptor de archivo original utilizado para la asignación. Esta llamada toma el objeto de la fuente de eventos como parámetro source y devuelve el descriptor de archivo numérico.

sd_event_source_get_child_pidfd_own() puede usarse para consultar si el pidfd que encapsula la fuente de eventos debe cerrarse cuando se libera la fuente de eventos. Esta función devuelve cero si el pidfd debe dejarse abierto, y positivo si debe cerrarse automáticamente. Por defecto, esta configuración se establece en activo si la fuente de eventos se asignó mediante sd_event_add_child() y en inactivo si se asignó mediante sd_event_add_child_pidfd(). La función sd_event_source_set_child_pidfd_own() puede usarse para cambiar la configuración y toma un parámetro booleano con la nueva configuración.

sd_event_source_get_child_process_own() puede usarse para consultar si el proceso que vigila la fuente de eventos debe ser terminado (con SIGKILL) y recolectado cuando se libera la fuente de eventos. Esta función devuelve cero si el proceso debe dejarse ejecutándose, y positivo si debe ser terminado y recolectado automáticamente. Por defecto, esta configuración se establece en inactivo. La función sd_event_source_set_child_process_own() puede usarse para cambiar la configuración y toma un parámetro booleano con la nueva configuración.

sd_event_source_send_child_signal() envía una señal específica a un proceso hijo vigilado. El parámetro sig especifica el número de señal a enviar. El parámetro info es un puntero opcional a una estructura siginfo_t, que se pasará al proceso hijo junto con la señal. El parámetro flags puede contener SA_SIGINFO, que indica que info debe ser utilizado para enviar información adicional de la señal.

NAME

sd_event_add_child, sd_event_add_child_pidfd, sd_event_child_handler_t, sd_event_source_get_child_pid, sd_event_source_get_child_pidfd, sd_event_source_get_child_pidfd_own, sd_event_source_set_child_pidfd_own, sd_event_source_get_child_process_own, sd_event_source_set_child_process_own, sd_event_source_send_child_signal - Añadir un evento para vigilar un proceso hijo

SYNOPSIS

#include <systemd/sd-event.h>
int sd_event_add_child(sd_event *event, sd_event_source **ret, pid_t pid, int flags, sd_event_child_handler_t callback, void *userdata);
int sd_event_add_child_pidfd(sd_event *event, sd_event_source **ret, pid_t pid, int pidfd, int flags, sd_event_child_handler_t callback, void *userdata);
typedef int (*sd_event_child_handler_t)(sd_event *event, siginfo_t *si, void *userdata);
pid_t sd_event_source_get_child_pid(sd_event_source *source);
int sd_event_source_get_child_pidfd(sd_event_source *source);
int sd_event_source_get_child_pidfd_own(sd_event_source *source);
int sd_event_source_set_child_pidfd_own(sd_event_source *source, int own);
int sd_event_source_get_child_process_own(sd_event_source *source);
int sd_event_source_set_child_process_own(sd_event_source *source, int own);
int sd_event_source_send_child_signal(sd_event_source *source, int signum, const siginfo_t *info, int flags);

DESCRIPTION

sd_event_add_child() registra un nuevo evento en el bucle de eventos dado event que se dispara cuando el proceso hijo con PID pid cambia de estado (se detiene, continúa o termina). El evento se dispara al recibir la señal SIGCHLD.

El argumento flags es una máscara de bits que contiene opciones para la vigilancia. Actualmente, sólo se soportan los siguientes flags: WEXITED, WSTOPPED, y WCONTINUED. Consulte waitid(2) para más detalles. Tenga en cuenta que WEXITED y WCONTINUED sólo pueden ser usados en combinación con WSTOPPED.

Cuando el evento se dispara, la función de retorno de llamada callback es invocada con el bucle de eventos, un puntero a una estructura siginfo_t (que contiene información sobre el hijo) y el dato de usuario userdata. Si callback retorna un valor negativo, se considerará un error y el evento se deshabilitará. Si retorna un valor positivo (distinto de cero), se interpretará como el valor de salida del bucle de eventos, y el bucle se terminará. Si retorna cero, el evento se deshabilitará pero el bucle continuará. Si callback es NULL, se usará un gestor por defecto que simplemente termina el bucle de eventos.

El puntero ret se usa para almacenar el puntero al objeto del evento recién creado. Si se pasa NULL, el evento no se retorna.

sd_event_add_child_pidfd() es similar a sd_event_add_child(), pero en lugar de un PID, toma un descriptor de archivo de proceso (pidfd) pidfd. Este descriptor de archivo debe haber sido creado previamente usando pidfd_open(2). El uso de pidfd es preferible ya que permite la vigilancia de procesos incluso si su PID se reutiliza o si el proceso es huérfano.

El flag PIDFD_NONBLOCK puede ser pasado en flags para que las llamadas a pidfd_open(2) sean no bloqueantes. Esto sólo tiene sentido si pidfd se crea dentro de esta misma llamada, lo cual no es el caso para sd_event_add_child_pidfd().

El flag PIDFD_ALLOW_REEnlaces puede ser pasado en flags para permitir que el pidfd sea re-enlazado a otro proceso. Esto es útil para el seguimiento de procesos que son clonados.

El argumento pidfd se puede pasar como -1 si no se desea usar un pidfd específico, por ejemplo, si solo se está usando el PID. En este caso, la función se comportará como sd_event_add_child().

El argumento own en sd_event_source_set_child_pidfd_own() y sd_event_source_set_child_process_own() controla si el descriptor de archivo del pidfd o el descriptor del proceso hijo deben ser cerrados (y liberados) cuando la fuente del evento sea desreferenciada. Por defecto, no son poseídos.

sd_event_source_get_child_pid() retorna el PID del proceso hijo asociado a la fuente de evento source. Si la fuente de evento no es una fuente de proceso hijo, retorna -1. Tenga en cuenta que si se usa un pidfd, este PID puede no ser el PID actual del proceso si el PID ha sido reutilizado.

sd_event_source_get_child_pidfd() retorna el descriptor de archivo del pidfd asociado a la fuente de evento source. Si la fuente de evento no se creó con un pidfd, o si está asociada a un PID en lugar de un pidfd, retorna -1.

sd_event_source_get_child_pidfd_own() y sd_event_source_get_child_process_own() retornan si la fuente de evento source es dueña del pidfd o del proceso hijo, respectivamente. Retornan un valor distinto de cero si es dueña, cero si no lo es.

sd_event_source_set_child_pidfd_own() y sd_event_source_set_child_process_own() configuran si la fuente de evento source debe ser dueña del pidfd o del proceso hijo, respectivamente. El parámetro own debe ser distinto de cero para activar la propiedad, y cero para desactivarla. Si se activa la propiedad, el descriptor de archivo se cerrará automáticamente cuando la fuente del evento sea desreferenciada.

sd_event_source_send_child_signal() puede ser usada para enviar una señal UNIX al proceso vigilado a través de pidfd_send_signal(2). Los parámetros especificados coinciden con los de la llamada al sistema subyacente, excepto que el argumento info nunca se modifica (y por lo tanto se declara constante). Al igual que para la llamada al sistema subyacente, el parámetro flags actualmente debe ser cero.

Nota: actualmente si el proceso que llama termina de forma anómala, el proceso vigilado podría sobrevivir aunque la fuente del evento deje de existir. Este comportamiento podría cambiar eventualmente.

RETURN VALUE

En caso de éxito, estas funciones retornan 0 o un entero positivo. En caso de error, retornan un código de error negativo estilo errno.

Errors

Los errores retornados pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento inválido. Esto incluye especificar una máscara vacía en options o una máscara que contenga valores distintos de una combinación de WEXITED, WSTOPPED y WCONTINUED.

-EBUSY

Ya hay un gestor instalado para este proceso hijo, o SIGCHLD no está bloqueado.

-ESTALE

El bucle de eventos ya ha terminado.

-ECHILD

El bucle de eventos se ha creado en un proceso, biblioteca o instancia de módulo diferente.

-EDOM

La fuente de evento pasada no es una fuente de evento de proceso hijo.

NOTES

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo en una fase temprana del programa cuando no se hayan iniciado otros hilos.

EXAMPLE

Ejemplo 1. Terminar el bucle cuando el hijo termine

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <assert.h>
#include <stdio.h>
#include <unistd.h>
#include <systemd/sd-event.h>
int main(int argc, char **argv) {
  pid_t pid = fork();
  assert(pid >= 0);
  /* La señal SIGCHLD debe estar bloqueada para que sd_event_add_child funcione */
  sigset_t ss;
  sigemptyset(&ss);
  sigaddset(&ss, SIGCHLD);
  sigprocmask(SIG_BLOCK, &ss, NULL);
  if (pid == 0)  /* hijo */
    sleep(1);
  else {         /* padre */
    sd_event *e = NULL;
    int r;
    /* Crear el bucle de eventos por defecto */
    sd_event_default(&e);
    assert(e);
    /* Creamos una fuente de evento hijo flotante (adjunta a 'e').
     * El gestor por defecto será llamado con 666 como userdata, que
     * se convertirá en el valor de salida del bucle. */
    r = sd_event_add_child(e, NULL, pid, WEXITED, NULL, (void*) 666);
    assert(r >= 0);
    r = sd_event_loop(e);
    assert(r == 666);
    sd_event_unref(e);
  }
  return 0;
}
