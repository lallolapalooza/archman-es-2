DESCRIPCIÓN

sd_event_add_child() añade una nueva fuente de eventos de cambio de estado de proceso hijo a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro pid especifica el PID del proceso a vigilar, que debe ser un proceso hijo directo del proceso invocador. El parámetro options determina qué cambios de estado se vigilarán. Debe contener una máscara OR de WEXITED (vigilar la terminación del proceso hijo), WSTOPPED (vigilar si el proceso hijo es detenido por una señal) y WCONTINUED (vigilar si el proceso hijo se reanuda por una señal). Ver waitid(2) para más información.

El handler debe ser una función a llamar cuando el proceso cambie de estado o NULL. A la función handler se le pasará el puntero userdata, que puede ser elegido libremente por el llamador. El handler también recibe un puntero a una estructura siginfo_t que contiene información sobre el evento del proceso hijo. El handler puede devolver un valor negativo para indicar un error (ver más abajo), otros valores de retorno se ignoran. Si handler es NULL, se utilizará un handler predeterminado que llama a sd_event_exit(3).

Solo se puede instalar un handler para un proceso hijo específico. El handler está habilitado para un único evento (SD_EVENT_ONESHOT), pero esto se puede cambiar con sd_event_source_set_enabled(3). Si la función handler devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si se solicitó el modo SD_EVENT_ON anteriormente, o provocará que el bucle termine, ver sd_event_source_set_exit_on_failure(3).

Para destruir un objeto de fuente de eventos use sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se sueltan todas las referencias a la fuente de eventos. Para asegurarse de que una fuente de eventos no se dispare más, incluso cuando todavía hay una referencia a ella, considere establecer la fuente de eventos en SD_EVENT_OFF con sd_event_source_set_enabled(3).

La señal SIGCHLD debe estar bloqueada en todos los hilos antes de llamar a esta función (usando sigprocmask(2) o pthread_sigmask(3)).

Si el segundo parámetro de sd_event_add_child() se pasa como NULL, no se devuelve ninguna referencia al objeto de la fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando el propio bucle de eventos se destruya.

Tenga en cuenta que la función handler se invoca en un momento en que el proceso hijo aún no ha sido recolectado (y por lo tanto todavía está expuesto como un proceso zombie por el kernel). Sin embargo, el hijo será recolectado automáticamente después de que la función regrese. Los procesos hijos para los cuales no se instalan fuentes de eventos de cambio de estado de proceso hijo no serán recolectados por la implementación del bucle de eventos.

Si el parámetro handler de sd_event_add_child() es NULL, y la fuente de eventos se dispara, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a un entero, se pasa como parámetro de código de salida a sd_event_exit(3).

Si tanto una fuente de eventos de cambio de estado de proceso hijo como una fuente de eventos de señal SIGCHLD están instaladas en el mismo bucle de eventos, las prioridades de las fuentes de eventos configuradas deciden qué fuente de eventos se despacha primero. Si el manejador de señales se procesa primero, debe dejar los procesos hijos para los que se instalan fuentes de eventos de cambio de estado de proceso hijo sin recolectar.

sd_event_add_child_pidfd() es similar a sd_event_add_child() pero toma un descriptor de archivo que hace referencia al proceso ("pidfd") en lugar del PID numérico. Un descriptor de archivo adecuado puede obtenerse mediante pidfd_open(2) y llamadas relacionadas. El descriptor de archivo pasado no se cierra cuando la fuente de eventos se libera de nuevo, a menos que se utilice sd_event_source_set_child_pidfd_own() para activar este comportamiento. Tenga en cuenta que independientemente de si se utiliza sd_event_add_child() o sd_event_add_child_pidfd() para asignar una fuente de eventos, el proceso vigilado debe ser un proceso hijo directo del proceso invocador. También en ambos casos SIGCHLD debe estar bloqueado en el proceso invocador.

sd_event_source_get_child_pid() recupera el PID configurado de una fuente de eventos de cambio de estado de proceso hijo creada previamente con sd_event_add_child(). Toma el objeto de la fuente de eventos como parámetro source y un puntero a una variable pid_t para devolver el ID del proceso.

sd_event_source_get_child_pidfd() recupera el descriptor de archivo que hace referencia al proceso vigilado ("pidfd"). El bucle de eventos utiliza internamente pidfds para vigilar procesos hijos, independientemente de si las fuentes de eventos individuales se asignan a través de sd_event_add_child() o sd_event_add_child_pidfd(). Si la última llamada se utilizó para asignar la fuente de eventos, esta función devuelve el descriptor de archivo original utilizado para la asignación. Esta llamada toma el objeto de la fuente de eventos como parámetro source y devuelve el descriptor de archivo numérico.

sd_event_source_get_child_pidfd_own() puede utilizarse para consultar si el pidfd que encapsula la fuente de eventos debe cerrarse cuando se libera la fuente de eventos. Esta función devuelve cero si el pidfd debe dejarse abierto y positivo si debe cerrarse automáticamente. Por defecto, esta configuración se establece en activado si la fuente de eventos se asignó a través de sd_event_add_child() y en desactivado si se asignó a través de sd_event_add_child_pidfd(). La función sd_event_source_set_child_pidfd_own() puede utilizarse para cambiar la configuración y toma un parámetro booleano con la nueva configuración.

sd_event_source_get_child_process_own() puede utilizarse para consultar si el proceso que vigila la fuente de eventos debe ser matado (con SIGKILL) y recolectado cuando se libera la fuente de eventos. Esta función devuelve cero si el proceso debe dejarse en ejecución y positivo si debe ser matado y recolectado automáticamente. Por defecto, esta configuración se establece en desactivado. La función sd_event_source_set_child_process_own() puede utilizarse

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo al estilo de errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento no válido. Esto incluye especificar una máscara vacía en options o una máscara que contiene valores distintos de una combinación de WEXITED, WSTOPPED y WCONTINUED.

-EBUSY

Ya hay un manejador instalado para este proceso hijo, o SIGCHLD no está bloqueado.

-ESTALE

El bucle de eventos ya está terminado.

-ECHILD

El bucle de eventos se ha creado en un proceso, biblioteca o instancia de módulo diferente.

-EDOM

La fuente de eventos pasada no es una fuente de eventos de proceso hijo.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo pkg-config de libsystemd.

El código descrito aquí utiliza getenv(3), que está declarado como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar solo llamadas a setenv() desde una fase temprana del programa, cuando no se hayan iniciado otros hilos.

EJEMPLO

Ejemplo 1. Salir del bucle cuando el hijo termina

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <assert.h>
#include <stdio.h>
#include <unistd.h>
#include <systemd/sd-event.h>
int main(int argc, char **argv) {
  pid_t pid = fork();
  assert(pid >= 0);
  /* La señal SIGCHLD debe estar bloqueada para que sd_event_add_child funcione */
  sigset_t ss;
  sigemptyset(&ss);
  sigaddset(&ss, SIGCHLD);
  sigprocmask(SIG_BLOCK, &ss, NULL);
  if (pid == 0)  /* hijo */
    sleep(1);
  else {         /* padre */
    sd_event *e = NULL;
    int r;
    /* Crear el bucle de eventos predeterminado */
    sd_event_default(&e);
    assert(e);
    /* Creamos una fuente de eventos hijo flotante (adjunta a 'e').
     * El manejador predeterminado se llamará con 666 como userdata, que
     * se convertirá en el valor de salida del bucle. */
    r = sd_event_add_child(e, NULL, pid, WEXITED, NULL, (void*) 666);
    assert(r >= 0);
    r = sd_event_loop(e);
    assert(r == 666);
    sd_event_unref(e);
  }
  return 0;
}
