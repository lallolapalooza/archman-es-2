sd_journal_print(3)

SD_JOURNAL_PRINT(3) sd_journal_print SD_JOURNAL_PRINT(3)

NOMBRE

sd_journal_print, sd_journal_printv, sd_journal_send, sd_journal_sendv, sd_journal_perror, SD_JOURNAL_SUPPRESS_LOCATION, sd_journal_print_with_location, sd_journal_printv_with_location, sd_journal_send_with_location, sd_journal_sendv_with_location, sd_journal_perror_with_location - Enviar entradas de registro a la journal

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_print(int prioridad, const char *formato, ...);

int sd_journal_printv(int prioridad, const char *formato, va_list ap);

int sd_journal_send(const char *formato, ...);

int sd_journal_sendv(const struct iovec *iov, int n);

int sd_journal_perror(const char *mensaje);

int sd_journal_print_with_location(int prioridad, const char *archivo, const char *linea, const char *func, const char *formato, ...);

int sd_journal_printv_with_location(int prioridad, const char *archivo, const char *linea, const char *func, const char *formato, va_list ap);

int sd_journal_send_with_location(const char *archivo, const char *linea, const char *func, const char *formato, ...);

int sd_journal_sendv_with_location(const char *archivo, const char *linea, const char *func, const struct iovec *iov, int n);

int sd_journal_perror_with_location(const char *archivo, const char *linea, const char *func, const char *mensaje);

DESCRIPCIÓN

sd_journal_print() puede ser usado para enviar entradas de registro simples de texto plano al journal del sistema. El primer argumento es un valor de prioridad. A esto le sigue una cadena de formato y sus parámetros, similar a printf(3) o syslog(3). Nótese que actualmente el mensaje resultante será truncado a LINE_MAX - 8. El valor de prioridad es uno de LOG_EMERG, LOG_ALERT, LOG_CRIT, LOG_ERR, LOG_WARNING, LOG_NOTICE, LOG_INFO, LOG_DEBUG, como se define en syslog.h, véase syslog(3) para detalles. Se recomienda usar esta llamada para enviar mensajes de registro en la configuración regional de la aplicación o la configuración regional del sistema y en formato UTF-8, pero no se imponen tales restricciones. Nótese que generalmente no se espera que los mensajes de registro escritos con esta función terminen en un carácter de nueva línea. Sin embargo, como todo espacio en blanco final (incluyendo espacios, nuevas líneas, tabuladores y retornos de carro) se elimina automáticamente de la cadena registrada, es aceptable especificar uno (o más). Las líneas vacías (después de la eliminación de espacios en blanco finales) se suprimen. En líneas no vacías, el espacio en blanco inicial (así como el espacio en blanco interior) se deja sin modificar.

sd_journal_printv() es similar a sd_journal_print() pero toma una lista de argumentos variables encapsulada en un objeto de tipo va_list (véase stdarg(3) para más información) en lugar de la cadena de formato. Es equivalente en comportamiento en cualquier otro aspecto.

sd_journal_send() puede ser usado para enviar entradas de registro estructuradas al journal del sistema. Toma una serie de cadenas de formato, cada una seguida inmediatamente por sus parámetros asociados, terminadas por NULL. Las cadenas pasadas deben ser del formato "VARIABLE=valor". El nombre de la variable debe estar en mayúsculas y consistir solo de caracteres, números y guiones bajos, y no puede comenzar con un guion bajo. (Todas las asignaciones que no sigan esta sintaxis serán ignoradas.) El valor puede ser de cualquier tamaño y formato. Es muy recomendable enviar solo cadenas de texto formateadas en la codificación de caracteres UTF-8, y enviar campos binarios solo cuando no sea sensato formatear en cadenas UTF-8. Se definen varios campos bien conocidos, véase systemd.journal-fields(7) para detalles, pero se pueden usar campos adicionales definidos por la aplicación. A una variable se le puede asignar más de un valor por entrada. Si se usa esta función, los espacios en blanco finales se eliminan automáticamente de cada campo formateado.

sd_journal_sendv() es similar a sd_journal_send() pero toma un array de struct iovec (como se define en uio.h, véase readv(3) para detalles) en lugar de la cadena de formato. Cada estructura debe referenciar un campo de la entrada a enviar. El segundo argumento especifica el número de estructuras en el array. sd_journal_sendv() es particularmente útil para enviar objetos binarios al journal donde sea necesario. Nótese que esta función no eliminará los espacios en blanco finales de los campos pasados, sino que transmitirá los datos especificados sin modificar. Esto es diferente tanto de sd_journal_print() como de sd_journal_send() descritos anteriormente, que se basan en cadenas de formato y sí eliminan los espacios en blanco finales.

sd_journal_perror() es similar a perror(3) y escribe un mensaje en el journal que consiste en la cadena pasada, seguida de ": " y una representación legible por humanos del código de error actual almacenado en errno(3). Si la cadena de mensaje se pasa como NULL o cadena vacía, solo se escribirá la representación de la cadena de error, sin prefijo. Se incluye un campo adicional del journal ERRNO= en la entrada que contiene el código de error numérico formateado como cadena decimal. La prioridad de registro utilizada es LOG_ERR (3).

Nótese que sd_journal_send() es un envoltorio para sd_journal_sendv() para hacerlo más fácil de usar cuando solo se deben enviar cadenas de texto. Además, las siguientes dos llamadas son en gran medida equivalentes:

sd_journal_print(LOG_INFO, "Hola Mundo, ¡este es el PID %lu!", (unsigned long) getpid());
sd_journal_send("MESSAGE=Hola Mundo, ¡este es el PID %lu!", (unsigned long) getpid(),
                "PRIORITY=%i", LOG_INFO,
                NULL);

Nótese que estas llamadas añaden implícitamente campos para el archivo de origen, el nombre de la función y la línea de código donde se invocaron. Esto se implementa con macros. Si esto no se desea, se puede desactivar definiendo SD_JOURNAL_SUPPRESS_LOCATION antes de incluir sd-journal.h.

sd_journal_print_with_location(), sd_journal_printv_with_location(), sd_journal_send_with_location(), sd_journal_sendv_with_location() y sd_journal_perror_with_location() son similares a sus contrapartes sin "_with_location", pero aceptan parámetros adicionales para establecer explícitamente el nombre del archivo de origen, la función y la línea. Los argumentos "archivo" y "línea" deben contener entradas válidas del journal incluyendo el nombre de la variable, por ejemplo "CODE_FILE=src/foo.c" y "CODE_LINE=666", mientras que "func" solo debe contener el nombre de la función, es decir, el valor sin "CODE_FUNC=". Estas variantes son principalmente útiles al escribir envoltorios personalizados, por ejemplo en enlaces para un idioma diferente.

syslog(3) y sd_journal_print() pueden ser usados en gran medida de forma intercambiable en cuanto a funcionalidad. Sin embargo, nótese que los mensajes de registro registrados a través del primero toman una ruta diferente al servidor del journal que los registrados a través del segundo, y por lo tanto el orden cronológico global entre los dos flujos no puede ser garantizado. Usar sd_journal_print() tiene el beneficio de registrar la línea de código fuente, los nombres de archivo y las funciones como metadatos junto con todas las entradas, y garantizar el orden cronológico con las entradas de registro estructuradas que se generan a través de sd_journal_send(). Usar syslog() tiene el beneficio de ser más portable.

Estas funciones implementan un cliente para el Protocolo Nativo de Journal[1].

VALOR DE RETORNO

Las diez funciones devuelven 0 en caso de éxito o un código de error negativo estilo errno. La variable errno(3) su

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven el número de bytes escritos en el socket del journal. En caso de error, devuelven un valor negativo de errno.

Si systemd-journald(8) no se está ejecutando (el socket no está presente), estas funciones no hacen nada y también devuelven 0.

SEGURIDAD EN HILOS

Todas las funciones listadas aquí son seguras para hilos y pueden ser llamadas en paralelo desde múltiples hilos.

sd_journal_sendv() y sd_journal_sendv_with_location() son "seguras para señales asíncronas" en el sentido de signal-safety(7).

sd_journal_print(), sd_journal_printv(), sd_journal_send(), sd_journal_perror() y sus contrapartes con "_with_location" no son seguras para señales asíncronas.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para múltiples hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa, cuando aún no se han iniciado otros hilos.

HISTORIA

sd_journal_perror() se añadió en la versión 188.
