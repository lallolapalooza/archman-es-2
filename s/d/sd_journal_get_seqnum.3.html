SD_JOURNAL_GET_SEQNUM(3) sd_journal_get_seqnum SD_JOURNAL_GET_SEQNUM(3)

NOMBRE

sd_journal_get_seqnum - Leer el número de secuencia de la entrada actual del journal

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_get_seqnum(sd_journal *j, uint64_t *ret_seqnum, sd_id128_t *ret_seqnum_id);

DESCRIPCIÓN

sd_journal_get_seqnum() devuelve el número de secuencia de la entrada actual del journal. Toma tres argumentos: el objeto de contexto del journal, un puntero a un entero sin signo de 64 bits para almacenar el número de secuencia y un búfer para devolver el ID del número de secuencia de 128 bits.

Al escribir entradas del journal en el disco, cada instancia de systemd-journald las numerará secuencialmente, comenzando desde 1 para la primera entrada escrita después de la inicialización del subsistema. Cada serie de números de secuencia de este tipo se asocia con un ID de número de secuencia de 128 bits que se inicializa aleatoriamente, una vez al inicializar systemd-journal. Por lo tanto, mientras que múltiples instancias de systemd-journald asignarán los mismos números de secuencia a sus entradas del journal escritas, tendrán IDs de número de secuencia distintos. El número de secuencia se asigna en el momento de escribir la entrada en el disco. Si las entradas de registro se reescriben (por ejemplo, porque los registros volátiles de /run/log/ se vuelcan a /var/log/ a través de systemd-journald-flush.service), se les asignarán nuevos números de secuencia.

Los números de secuencia se pueden utilizar para ordenar las entradas (las entradas asociadas con el mismo ID de número de secuencia y números de secuencia más bajos deben ordenarse cronológicamente antes que aquellas con números de secuencia más altos) y para detectar entradas perdidas. Tenga en cuenta que las instancias del servicio de journal suelen escribir en múltiples archivos de journal en paralelo (por ejemplo, porque se utiliza SplitMode=), en cuyo caso cada archivo de journal solo contendrá un subconjunto de los números de secuencia. Para recuperar el flujo completo de entradas del journal, los archivos deben combinarse ("entrelazarse"), un proceso que se basa principalmente en los números de secuencia. Cuando los archivos del journal se rotan (debido a límites de tamaño o tiempo), la serie de números de secuencia continúa en los archivos de reemplazo. Todos los archivos del journal generados a partir de la misma instancia del journal tendrán el mismo ID de número de secuencia.

Dado que los números de secuencia se asignan en el momento de escribir las entradas del journal en el disco, no existen si el almacenamiento está deshabilitado a través de SplitMode=.

Los parámetros ret_seqnum y ret_seqnum_id pueden especificarse como NULL, en cuyo caso los datos relevantes no se devuelven (pero la llamada tendrá éxito de todos modos).

Tenga en cuenta que estas funciones no funcionarán antes de que sd_journal_next(3) (o llamada relacionada) se haya llamado al menos una vez, para posicionar el puntero de lectura en una entrada válida.

VALOR DE RETORNO

sd_journal_get_seqnum() devuelve 0 si la operación es exitosa o un código de error negativo de estilo errno.

NOTAS

Todas las funciones enumeradas aquí son agnósticas a hilos y solo un hilo puede operar en un objeto determinado en un momento dado. Diferentes hilos pueden acceder al mismo objeto en diferentes momentos. Se pueden utilizar múltiples objetos independientes desde diferentes hilos en paralelo.

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

HISTORIA

sd_journal_get_seqnum() se añadió en la versión 254.
