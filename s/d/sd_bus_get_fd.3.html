SD_BUS_GET_FD(3) sd_bus_get_fd SD_BUS_GET_FD(3)

NOMBRE

sd_bus_get_fd, sd_bus_get_events, sd_bus_get_timeout - Obtener el descriptor de archivo, eventos de E/S y tiempo de espera para esperar de un objeto de bus de mensajes

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_get_fd(sd_bus *bus);

int sd_bus_get_events(sd_bus *bus);

int sd_bus_get_timeout(sd_bus *bus, uint64_t *timeout_usec);

DESCRIPCIÓN

sd_bus_get_fd() devuelve el descriptor de archivo utilizado para comunicarse desde un objeto de bus de mensajes. Este descriptor puede ser utilizado con poll(3) o una función similar para esperar eventos de E/S en el objeto de conexión de bus especificado. Si el objeto de bus fue configurado con la función sd_bus_set_fd(), entonces se devuelve el descriptor de archivo input_fd utilizado en esa llamada.

sd_bus_get_events() devuelve los eventos de E/S para esperar, adecuados para pasar a poll() o una llamada similar. Devuelve una combinación de eventos POLLIN, POLLOUT, ..., o negativo en caso de error.

sd_bus_get_timeout() devuelve el tiempo de espera *absoluto* en µs, desde el cual se puede derivar el tiempo de espera relativo para pasar a poll() (o una llamada similar) al esperar eventos en la conexión de bus especificada. El tiempo de espera devuelto puede ser cero, en cuyo caso una llamada posterior de sondeo de E/S debería invocarse en modo no bloqueante. El tiempo de espera devuelto puede ser UINT64_MAX, en cuyo caso la llamada de sondeo de E/S puede bloquearse indefinidamente, sin ningún tiempo de espera aplicado. Tenga en cuenta que el tiempo de espera devuelto solo debe considerarse como un tiempo máximo de suspensión. Es permisible (e incluso esperado) que se utilicen tiempos de espera más cortos por el programa que llama, en caso de que se sondeen otras fuentes de eventos en el mismo bucle de eventos. Tenga en cuenta que el valor de tiempo devuelto es absoluto, basado en CLOCK_MONOTONIC y especificado en microsegundos. Al convertir este valor para pasarlo como tercer argumento a poll() (que espera milisegundos relativos), se debe tener cuidado de convertir a un tiempo relativo y usar una división que redondee hacia arriba para garantizar que la operación de sondeo de E/S no duerma por menos tiempo del necesario, lo que podría resultar en un bucle ocupado no deseado (alternativamente, use ppoll(2) en lugar de poll() simple, que entiende los tiempos de espera con granularidad de nanosegundos).

Estas tres funciones son útiles para conectar un objeto de conexión de bus con un bucle de eventos externo o manual que involucre poll() o una llamada de sondeo de E/S similar. Antes de cada invocación de la llamada de sondeo de E/S, se deben invocar las tres funciones: el descriptor de archivo devuelto por sd_bus_get_fd() debe ser consultado para los eventos indicados por sd_bus_get_events(), y la llamada de E/S debe bloquearse hasta el tiempo de espera devuelto por sd_bus_get_timeout(). Después de cada llamada de sondeo de E/S, la conexión de bus necesita procesar datos entrantes o salientes, invocando sd_bus_process(3).

Tenga en cuenta que estas funciones son solo una de las tres formas admitidas para implementar el manejo de eventos de E/S para las conexiones de bus. Alternativamente, use sd_bus_attach_event(3) para adjuntar una conexión de bus a un bucle de eventos de sd-event(3). O use sd_bus_wait(3) como una llamada simple de espera de E/S bloqueante y síncrona.

VALOR DE RETORNO

En caso de éxito, sd_bus_get_fd() devuelve el descriptor de archivo utilizado para la comunicación. En caso de fallo, devuelve un código de error negativo al estilo errno.

En caso de éxito, sd_bus_get_events() devuelve la máscara de eventos de E/S a usar para la vigilancia de eventos de E/S. En caso de fallo, devuelve un código de error negativo al estilo errno.

En caso de éxito, sd_bus_get_timeout() devuelve un entero no negativo. En caso de fallo, devuelve un código de error negativo al estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Se pasó un objeto de bus inválido.

-ECHILD

La conexión de bus se asignó en un proceso padre y se está reutilizando en un proceso hijo después de fork().

-ENOTCONN

La conexión de bus ha finalizado.

-EPERM

Se pasaron dos descriptores de archivo distintos para entrada y salida usando sd_bus_set_fd(), que sd_bus_get_fd() no puede devolver.

-ENOPKG

No se puede resolver el bus.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

sd_bus_get_fd(), sd_bus_get_events() y sd_bus_get_timeout() se agregaron en la versión 221.
