#include <systemd/sd-journal.h>

DESCRIPCIÓN

sd_journal_print() puede ser utilizado para enviar entradas de registro simples de texto plano al journal del sistema. El primer argumento es un valor de prioridad. Le sigue una cadena de formato y sus parámetros, similar a printf(3) o syslog(3). Tenga en cuenta que actualmente el mensaje resultante se truncará a LINE_MAX - 8. El valor de prioridad es uno de LOG_EMERG, LOG_ALERT, LOG_CRIT, LOG_ERR, LOG_WARNING, LOG_NOTICE, LOG_INFO, LOG_DEBUG, como se definen en syslog.h, consulte syslog(3) para más detalles. Se recomienda usar esta llamada para enviar mensajes de registro en la configuración regional de la aplicación o la configuración regional del sistema y en formato UTF-8, pero no se aplican restricciones tales. Tenga en cuenta que los mensajes de registro escritos usando esta función generalmente no se espera que terminen en un carácter de nueva línea. Sin embargo, como se eliminan automáticamente todos los espacios en blanco finales (incluidos espacios, nuevas líneas, tabuladores y retornos de carro) de la cadena registrada, es aceptable especificar uno (o más). Las líneas vacías (después de la eliminación de los espacios en blanco finales) se suprimen. En las líneas no vacías, los espacios en blanco iniciales (así como los espacios en blanco internos) se dejan sin modificar.

sd_journal_printv() es similar a sd_journal_print() pero toma una lista de argumentos variables encapsulada en un objeto de tipo va_list (consulte stdarg(3) para más información) en lugar de la cadena de formato. En su comportamiento es equivalente.

sd_journal_send() puede ser utilizado para enviar entradas de registro estructuradas al journal del sistema. Toma una serie de cadenas de formato, cada una seguida inmediatamente por sus parámetros asociados, terminadas con NULL. Las cadenas pasadas deben tener el formato "VARIABLE=valor". El nombre de la variable debe estar en mayúsculas y consistir únicamente en caracteres, números y guiones bajos, y no puede comenzar con un guion bajo. (Todas las asignaciones que no sigan esta sintaxis serán ignoradas.) El valor puede ser de cualquier tamaño y formato. Se recomienda encarecidamente enviar cadenas de texto formateadas solo en codificación de caracteres UTF-8, y enviar campos binarios solo cuando no sea sensato formatear en cadenas UTF-8. Se definen una serie de campos conocidos, consulte systemd.journal-fields(7) para más detalles, pero se pueden usar campos adicionales definidos por la aplicación. Una variable puede asignarse más de un valor por entrada. Si se utiliza esta función, los espacios en blanco finales se eliminan automáticamente de cada campo formateado.

sd_journal_sendv() es similar a sd_journal_send() pero toma un array de struct iovec (como se define en uio.h, consulte readv(3) para más detalles) en lugar de la cadena de formato. Cada estructura debe hacer referencia a un campo de la entrada a enviar. El segundo argumento especifica el número de estructuras en el array. sd_journal_sendv() es particularmente útil para enviar objetos binarios al journal cuando sea necesario. Tenga en cuenta que esta función no eliminará los espacios en blanco finales de los campos pasados, sino que pasará los datos especificados sin modificar. Esto es diferente tanto de sd_journal_print() como de sd_journal_send() descritas anteriormente, que se basan en cadenas de formato y eliminan los espacios en blanco finales.

sd_journal_perror() es similar a perror(3) y escribe un mensaje en el journal que consiste en la cadena pasada, seguida de ": " y una representación legible por humanos del código de error actual almacenado en errno(3). Si se pasa la cadena de mensaje como NULL o cadena vacía, solo se escribirá la representación de la cadena de error, sin prefijo. Un campo adicional del journal ERRNO= se incluye en la entrada que contiene el código de error numérico formateado como una cadena decimal. La prioridad de registro utilizada es LOG_ERR (3).

Tenga en cuenta que sd_journal_send() es un wrapper alrededor de sd_journal_sendv() para facilitar su uso cuando solo se deben enviar cadenas de texto. Además, las siguientes dos llamadas son en gran medida equivalentes:

sd_journal_print(LOG_INFO, "Hola Mundo, ¡este es el PID %lu!", (unsigned long) getpid());
sd_journal_send("MESSAGE=Hola Mundo, ¡este es el PID %lu!", (unsigned long) getpid(),
                "PRIORITY=%i", LOG_INFO,
                NULL);

Tenga en cuenta que estas llamadas agregan implícitamente campos para el archivo de origen, el nombre de la función y la línea de código donde se invocan. Esto se implementa con macros. Si no se desea esto, se puede desactivar definiendo SD_JOURNAL_SUPPRESS_LOCATION antes de incluir sd-journal.h.

sd_journal_print_with_location(), sd_journal_printv_with_location(), sd_journal_send_with_location(), sd_journal_sendv_with_location(), y sd_journal_perror_with_location() son similares a sus contrapartes sin "_with_location", pero aceptan parámetros adicionales para establecer explícitamente el nombre del archivo de origen, la función y la línea. Los argumentos "file" y "line" deben contener entradas válidas del journal, incluyendo el nombre de la variable, por ejemplo, "CODE_FILE=src/foo.c" y "CODE_LINE=666", mientras que "func" solo debe contener el nombre de la función, es decir, el valor sin "CODE_FUNC=". Estas variantes son principalmente útiles cuando se escriben wrappers personalizados, por ejemplo, en enlaces para un idioma diferente.

syslog(3) y sd_journal_print() pueden ser utilizados en gran medida indistintamente en cuanto a funcionalidad. Sin embargo, tenga en cuenta que los mensajes de registro registrados a través del primero toman una ruta diferente al servidor del journal que los últimos, y por lo tanto, no se puede garantizar un orden cronológico global entre los dos flujos. Usar sd_journal_print() tiene el beneficio de registrar la línea de código fuente, nombres de archivo y funciones como metadatos junto con todas las entradas, y garantizar el orden cronológico con las entradas de registro estructuradas que se generan a través de sd_journal_send(). Usar syslog() tiene el beneficio de ser más portátil.

Estas funciones implementan un cliente para el Protocolo Nativo del Journal[1].

sd_journal_send_with_location(3)

send journal messages with source code location

2023-10-29

NAME

sd_journal_send_with_location, sd_journal_print_with_location, sd_journal_printv_with_location, sd_journal_perror_with_location, sd_journal_send, sd_journal_print, sd_journal_printv, sd_journal_perror — send messages to the journal

SYNOPSIS

#include <systemd/sd-journal.h>

int sd_journal_send_with_location(const char *file, int line, const char *func,
                                  const char *format, ...);
int sd_journal_print_with_location(const char *file, int line, const char *func,
                                   const char *format, ...);
int sd_journal_printv_with_location(const char *file, int line,
                                    const char *func, va_list ap);
int sd_journal_perror_with_location(const char *file, int line,
                                    const char *func, const char *format, ...);
int sd_journal_send(const char *format, ...);
int sd_journal_print(const char *format, ...);
int sd_journal_printv(va_list ap);
int sd_journal_perror(const char *format, ...);

DESCRIPTION

These functions are used to send messages to the systemd journal. The functions with the suffix _with_location additionally record the source code location (file name, line number, and function name) from which the call was made. This information is stored in the journal fields _SOURCE_FILE, _SOURCE_LINE, and _SOURCE_FUNC, respectively.

sd_journal_send_v(...) and sd_journal_send_with_location(...) send a list of key=value pairs to the journal. The arguments are processed similarly to printf(3), and the format string must contain only valid journal fields. The last argument must be NULL. The pairs are NULL-terminated strings. If a value contains a newline character, it is encoded using the native journal protocol.

sd_journal_print_v(...) and sd_journal_print_with_location(...) are similar to sd_journal_send_v(...), but they implicitly add the MESSAGE= field. The message string is formatted using printf(3) and is added as the MESSAGE= field. It is important to note that the message string itself is *not* added as a separate field, but rather as the value of the MESSAGE= field. The pairs are NULL-terminated strings. The last argument must be NULL.

sd_journal_printv(...) and sd_journal_printv_with_location(...) are similar to sd_journal_sendv_with_location(...) and sd_journal_sendv(...), respectively, but they implicitly add the MESSAGE= field. The message is taken from the `va_list ap` and formatted into a single string, which is then added as the value of the MESSAGE= field. The pairs are NULL-terminated strings. The last argument must be NULL.

sd_journal_perror_v(...) and perror_with_location(...) are similar to sd_journal_print_v(...) and sd_journal_print_with_location(...), but they also append the current error message description obtained via strerror(3) to the message.

The sd_journal_send(), sd_journal_print(), sd_journal_printv(), and sd_journal_perror() functions are variants without source code location information.

If systemd-journald(8) is not running (the socket is not present), these functions do nothing and return 0.

RETURN VALUE

On success, these functions return a non-negative integer. On failure, they return a negative errno value.

If sd_journal_send_v(...), sd_journal_send_with_location(...), sd_journal_print_v(...), sd_journal_print_with_location(...), sd_journal_printv(...), sd_journal_printv_with_location(...), sd_journal_perror_v(...), or sd_journal_perror_with_location(...) are called and the journal daemon is not running, they return 0. The formatting of the message string is performed, but the variable itself is not altered.

If systemd-journald(8) is not running (the socket is not present), those functions do nothing, and also return 0.

THREAD SAFETY

All functions listed here are thread-safe and may be called in parallel from multiple threads.

sd_journal_sendv() and sd_journal_sendv_with_location() are "async signal safe" in the meaning of signal-safety(7).

sd_journal_print(), sd_journal_printv(), sd_journal_send(), sd_journal_perror(), and their counterparts with "_with_location" are not async signal safe.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.

HISTORY

sd_journal_print(), sd_journal_printv(), sd_journal_send(), and sd_journal_sendv() were added in version 187.

sd_journal_perror() was added in version 188.

sd_journal_print_with_location(), sd_journal_printv_with_location(), sd_journal_send_with_location(), sd_journal_sendv_with_location(), and sd_journal_perror_with_location() were added in version 246.
