sd_watchdog_enabled(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_WATCHDOG_ENABLED(3) sd_watchdog_enabled SD_WATCHDOG_ENABLED(3)

NOMBRE

sd_watchdog_enabled - Comprueba si el gestor de servicios espera notificaciones de pulso de supervisión (watchdog) por parte de un servicio

SINOPSIS

#include <systemd/sd-daemon.h>

int sd_watchdog_enabled(int unset_environment, uint64_t *usec);

DESCRIPCIÓN

sd_watchdog_enabled() puede ser llamada por un servicio para detectar si el gestor de servicios espera eventos regulares de notificación de pulso de supervisión (keep-alive watchdog) por parte de él, y el tiempo de espera después del cual el gestor actuará sobre el servicio si no recibió dicha notificación.

Si la variable de entorno $WATCHDOG_USEC está establecida, y la variable $WATCHDOG_PID no está establecida o está establecida al PID del proceso actual, el gestor de servicios espera notificaciones de este proceso. El gestor generalmente terminará un servicio cuando no reciba un mensaje de notificación dentro del tiempo especificado después del inicio y después de cada mensaje anterior. Se recomienda que un demonio envíe un mensaje de notificación de pulso de supervisión al gestor de servicios cada mitad del tiempo devuelto aquí. Los mensajes de notificación pueden ser enviados con sd_notify(3) con una cadena de mensaje de "WATCHDOG=1".

Si el parámetro unset_environment es distinto de cero, sd_watchdog_enabled() anulará las variables de entorno $WATCHDOG_USEC y $WATCHDOG_PID antes de devolver (independientemente de si la propia llamada a la función tuvo éxito o no). Estas variables ya no se heredarán por los procesos hijos. Las llamadas posteriores a sd_watchdog_enabled() también devolverán cero.

Si el parámetro usec no es NULL, sd_watchdog_enabled() escribirá el tiempo de espera en μs para la lógica del watchdog en él.

Para habilitar la supervisión de servicios con la lógica del watchdog, use WatchdogSec= en los archivos de servicio. Vea systemd.service(5) para más detalles.

Use sd_event_set_watchdog(3) para habilitar el soporte automático de watchdog en bucles de eventos basados en sd-event(3).

VALOR DE RETORNO

En caso de error, esta llamada devuelve un código de error negativo estilo errno. Si el gestor de servicios espera que se envíen mensajes de notificación de pulso de supervisión (keep-alive watchdog), se devuelve > 0, de lo contrario se devuelve 0. Solo si el valor de retorno es > 0, el parámetro usec es válido después de la llamada.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

Internamente, esta función analiza las variables de entorno $WATCHDOG_PID y $WATCHDOG_USEC. La llamada ignorará estas variables si $WATCHDOG_PID no contiene el PID del proceso actual, bajo el supuesto de que en ese caso, las variables fueron establecidas para un proceso diferente en la parte superior del árbol de procesos.

ENTORNO

$WATCHDOG_PID

Establecida por el gestor del sistema para el proceso supervisado para el cual se habilita el soporte de watchdog, y contiene el PID de dicho proceso. Ver arriba para más detalles.

Añadido en la versión 209.

$WATCHDOG_USEC

Establecida por el gestor del sistema para el proceso supervisado para el cual se habilita el soporte de watchdog, y contiene el tiempo de espera del watchdog en μs. Ver arriba para más detalles.

Añadido en la versión 209.

HISTORIAL

sd_watchdog_enabled() fue añadida en la versión 209.
