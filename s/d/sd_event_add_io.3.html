NOMBRE

SINOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_io_handler_t)(sd_event_source *s, int fd, uint32_t revents, void *userdata);

int sd_event_add_io(sd_event *event, sd_event_source **source, int fd, uint32_t events, sd_event_io_handler_t handler, void *userdata);

int sd_event_source_get_io_events(sd_event_source *source, uint32_t *ret);

int sd_event_source_set_io_events(sd_event_source *source, uint32_t events);

int sd_event_source_get_io_revents(sd_event_source *source, uint32_t *ret);

int sd_event_source_get_io_fd(sd_event_source *source);

int sd_event_source_set_io_fd(sd_event_source *source, int fd);

int sd_event_source_get_io_fd_own(sd_event_source *source);

int sd_event_source_set_io_fd_own(sd_event_source *source, int b);

DESCRIPCIÓN

sd_event_add_io() añade una nueva fuente de eventos de E/S a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, y el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro fd toma el descriptor de archivo UNIX a observar, que puede referirse a un socket, una FIFO, una cola de mensajes, una conexión serie, un dispositivo de caracteres o cualquier otro descriptor de archivo compatible con epoll(7) de Linux. El parámetro events toma una máscara de bits de eventos a observar, una combinación de las siguientes banderas de evento: EPOLLIN, EPOLLOUT, EPOLLRDHUP, EPOLLPRI y EPOLLET, consulte epoll_ctl(2) para más detalles. Tenga en cuenta que no todos los descriptores de archivo son compatibles con epoll, por ejemplo, los archivos regulares o directorios no lo son. Si esta función se llama con un descriptor de archivo que no admite epoll, se devuelve -EPERM (véase también más abajo). En la mayoría de los casos, dichos descriptores de archivo pueden tratarse como siempre legibles o siempre escribibles, por lo que la supervisión de eventos de E/S es innecesaria.

handler es una función a llamar cuando la fuente de eventos se active o NULL. El puntero userdata se pasará a la función manejadora, y puede ser elegido libremente por el llamante. Al manejador también se le pasará el descriptor de archivo en el que se vio el evento, así como las banderas de evento reales. Generalmente es un subconjunto de los eventos observados, sin embargo, puede incluir adicionalmente EPOLLERR y EPOLLHUP. El manejador puede devolver un valor negativo para indicar un error (ver más abajo), otros valores de retorno se ignoran. Si handler es NULL, se utilizará un manejador por defecto que llama a sd_event_exit(3).

Por defecto, una fuente de eventos permanecerá habilitada continuamente (SD_EVENT_ON), pero esto puede cambiarse con sd_event_source_set_enabled(3). Si la función manejadora devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si el modo SD_EVENT_ON se solicitó anteriormente, o provocará que el bucle termine, véase sd_event_source_set_exit_on_failure(3). Tenga en cuenta que una fuente de eventos configurada como SD_EVENT_ON se activará continuamente a menos que se lean o escriban datos en el descriptor de archivo para restablecer la máscara de eventos vistos.

Establecer la máscara de eventos de E/S a observar en 0 no significa que la fuente de eventos no se activará más, ya que EPOLLHUP y EPOLLERR pueden activarse incluso con una máscara de eventos cero. Para deshabilitar temporalmente una fuente de eventos de E/S, utilice sd_event_source_set_enabled(3) con SD_EVENT_OFF en su lugar.

Para destruir un objeto de fuente de eventos, utilice sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se liberan todas las referencias a ella. Para asegurarse de que una fuente de eventos no se active más, incluso si todavía se hace referencia a ella, deshabilite la fuente de eventos utilizando sd_event_source_set_enabled(3) con SD_EVENT_OFF.

Si el segundo parámetro de sd_event_add_io() es NULL, no se devuelve ninguna referencia al objeto de la fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando el propio bucle de eventos sea destruido.

Si el handler para sd_event_add_io() es NULL, y la fuente de eventos se activa, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a un entero, se pasa como parámetro de código de salida a sd_event_exit(3).

Tenga en cuenta que esta llamada no toma posesión del descriptor de archivo pasado, la propiedad (y por lo tanto la obligación de cerrarlo cuando ya no sea necesario) permanece con el llamante. Sin embargo, con la llamada sd_event_source_set_io_fd_own() (ver más abajo) la fuente de eventos puede opcionalmente tomar posesión del descriptor de archivo después de que se haya creado la fuente de eventos. En ese caso, el descriptor de archivo se cierra automáticamente tan pronto como se libera la fuente de eventos.

Se recomienda utilizar sd_event_add_io() solo en conjunción con descriptores de archivo que tengan O_NONBLOCK establecido, para garantizar que todas las operaciones de E/S de los manejadores invocados sean adecuadamente asíncronas y no bloqueantes. El uso de descriptores de archivo sin O_NONBLOCK podría provocar una inanición inesperada de otras fuentes de eventos. Consulte fcntl(2) para más detalles sobre la habilitación del modo O_NONBLOCK.

sd_event_source_get_io_events() recupera la máscara configurada de eventos de E/S observados de una fuente de eventos creada previamente con sd_event_add_io(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar la máscara.

sd_event_source_set_io_events() configura la máscara de eventos de E/S observados de una fuente de eventos creada previamente con sd_event_add_io(). Toma el objeto de la fuente de eventos y la nueva máscara de eventos.

sd_event_source_get_io_revents() recupera la máscara de eventos de E/S de eventos actualmente vistos pero no despachados de una fuente de eventos creada previamente con sd_event_add_io(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar la máscara de eventos. Cuando se llama desde una función manejadora en el objeto de la fuente de eventos del manejador, esto devolverá la misma máscara que se pasó al parámetro revents del manejador. Esta llamada es principalmente útil para comprobar eventos no despachados de una fuente de eventos desde el manejador de una fuente de eventos no relacionada (posiblemente de mayor prioridad). Tenga en cuenta la relación entre sd_event_source_get_pending() y sd_event_source_get_io_revents(): ambas funciones informarán de resultados no nulos cuando haya un evento pendiente para la fuente de eventos, pero la primera se aplica a todos los tipos de fuentes de eventos, la segunda solo a las fuentes de eventos de E/S.

sd_event_source_get_io_fd() recupera el descriptor de archivo UNIX de una fuente de eventos creada previamente con sd_event_add_io(). Toma el objeto de la fuente de eventos y devuelve el descriptor de archivo no negativo o un número de error negativo en caso de error (ver más abajo).

sd_event_source_set_io_fd() cambia el descriptor de archivo UNIX de una fuente de eventos de E/S creada previamente con sd_event_add_io(). Toma el objeto de la fuente de eventos y el nuevo descriptor de archivo como parámetros. NAME

sd_event_add_io, sd_event_source_get_io_events, sd_event_source_set_io_events, sd_event_source_get_io_revents, sd_event_source_get_io_fd, sd_event_source_set_io_fd, sd_event_source_get_io_fd_own, sd_event_source_set_io_fd_own — añadir y gestionar manejadores de eventos de E/S para bucles de eventos

SYNOPSIS

#include <systemd/sd-event.h>

int sd_event_add_io(sd_event *event, sd_event_source **source,
                    int fd, uint32_t events,
                    sd_event_handler_t callback, void *userdata);

int sd_event_source_get_io_events(sd_event_source *source,
                                  uint32_t *events);
int sd_event_source_set_io_events(sd_event_source *source,
                                  uint32_t events);
int sd_event_source_get_io_revents(sd_event_source *source,
                                   uint32_t *revents);
int sd_event_source_get_io_fd(sd_event_source *source, int *fd);
int sd_event_source_set_io_fd(sd_event_source *source, int fd);
int sd_event_source_get_io_fd_own(sd_event_source *source, bool *own);
int sd_event_source_set_io_fd_own(sd_event_source *source, bool own);

DESCRIPTION

El bucle de eventos sd_event (sd-event(3)) permite registrar manejadores para varios tipos de eventos. sd_event_add_io() añade un nuevo manejador de eventos de E/S al bucle de eventos especificado por event.

El descriptor de archivo fd se vigila para los eventos especificados en events. Los eventos válidos son una combinación de EPOLLIN (hay datos para leer), EPOLLPRI (hay datos urgentes para leer), EPOLLOUT (listo para escribir), EPOLLERR (error en el descriptor de archivo) y EPOLLHUP (canal cerrado). Véase epoll(7) para más detalles.

Cuando se detecta alguno de los eventos solicitados en fd, se llama a la función callback. userdata es un puntero arbitrario que se pasa a la función de devolución de llamada.

sd_event_add_io() crea un objeto sd_event_source que representa el manejador de E/S. Si source es distinto de NULL, se almacena un puntero al objeto fuente recién creado en source.

El descriptor de archivo fd debe ser válido y compatible con epoll(7). Los bucles de eventos no asumen la propiedad del descriptor de archivo pasado por defecto. Esto significa que la aplicación debe cerrar el descriptor de archivo ella misma cuando ya no sea necesario, a menos que se indique lo contrario con sd_event_source_set_io_fd_own().

sd_event_source_get_io_events() devuelve los eventos de E/S solicitados para la fuente de eventos dada. Estos son los mismos eventos que se pasaron a sd_event_add_io() o se establecieron posteriormente con sd_event_source_set_io_events().

sd_event_source_set_io_events() establece los eventos de E/S solicitados para la fuente de eventos dada. Si el manejador de eventos está actualmente habilitado, los nuevos eventos se activarán de inmediato.

sd_event_source_get_io_revents() devuelve los eventos de E/S que ocurrieron realmente para la fuente de eventos dada. Esto solo es válido dentro de la función de devolución de llamada de E/S y solo contendrá los eventos que activaron la devolución de llamada. Los eventos válidos son EPOLLIN, EPOLLPRI, EPOLLOUT, EPOLLERR, EPOLLHUP y EPOLLRDHUP.

sd_event_source_get_io_fd() devuelve el descriptor de archivo asociado a la fuente de eventos dada.

sd_event_source_set_io_fd() cambia el descriptor de archivo asociado a la fuente de eventos dada. El nuevo fd debe ser válido y compatible con epoll(7). El descriptor de archivo antiguo se cerrará automáticamente si la fuente de eventos tenía la propiedad establecida (véase sd_event_source_set_io_fd_own()). Si el descriptor de archivo antiguo no era propiedad de la fuente de eventos, la aplicación sigue siendo responsable de cerrarlo.

sd_event_source_set_io_fd_own() establece una bandera booleana que determina si la fuente de eventos debe cerrar el descriptor de archivo asociado automáticamente cuando la fuente de eventos es liberada (es decir, cuando se llama a sd_event_source_unref() o sd_event_destroy()). Si own es distinto de cero, el descriptor de archivo se cerrará automáticamente cuando la fuente de eventos se libere o cuando el descriptor de archivo sea reemplazado por sd_event_source_set_io_fd(). Por defecto, el descriptor de archivo no es propiedad de la fuente de eventos, y la aplicación debe cerrarlo por sí misma si es necesario.

sd_event_source_get_io_fd_own() puede utilizarse para consultar la configuración actual de la bandera booleana de propiedad del descriptor de archivo, tal como se estableció con sd_event_source_set_io_fd_own(). Devuelve un valor positivo si el descriptor de archivo se cierra automáticamente cuando se destruye la fuente de eventos, cero si no, y negativo en caso de error.

RETURN VALUE

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de fallo, devuelven un código de error negativo estilo errno.

Errors

Los valores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento no válido.

-ESTALE

El bucle de eventos ya ha terminado.

-ECHILD

El bucle de eventos se creó en un proceso, biblioteca o instancia de módulo diferente.

-EDOM

La fuente de eventos pasada no es una fuente de eventos de E/S.

-EPERM

El descriptor de archivo pasado no admite la API de epoll(7), por ejemplo, porque es un archivo o directorio regular. Véase epoll_ctl(2) para más detalles.

Añadido en la versión 255.

NOTES

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo pkg-config de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar solo llamadas a setenv() desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
