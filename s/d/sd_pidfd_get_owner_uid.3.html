DESCRIPCIÓN

sd_pid_get_owner_uid() puede ser utilizado para determinar el UID de Unix (identificador de usuario) que posee la sesión de inicio de sesión o la unidad de usuario de systemd de un proceso identificado por el PID especificado. Para procesos que no forman parte de una sesión de inicio de sesión y no son gestionados por un gestor de usuarios, esta función fallará con -ENODATA.

sd_pid_get_session() puede ser utilizado para determinar el identificador de la sesión de inicio de sesión de un proceso identificado por el identificador de proceso especificado. El identificador de sesión es una cadena corta, adecuada para su uso en rutas del sistema de archivos. Tenga en cuenta que la sesión de inicio de sesión puede limitarse a un proceso stub o dos. Los procesos de usuario pueden iniciarse en su lugar desde su gestor de usuarios de systemd, por ejemplo, aplicaciones gráficas iniciadas mediante activación DBus, así como procesos de servicio que se comparten entre múltiples inicios de sesión del mismo usuario. Para procesos que no forman parte de una sesión de inicio de sesión, esta función fallará con -ENODATA. La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso.

sd_pid_get_user_unit() puede ser utilizado para determinar el identificador de la unidad de usuario de systemd (es decir, servicio de usuario o unidad de ámbito) de un proceso identificado por el PID especificado. El nombre de la unidad es una cadena corta, adecuada para su uso en rutas del sistema de archivos. Para procesos que no son gestionados por un gestor de usuarios, esta función fallará con -ENODATA. La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso.

sd_pid_get_unit() puede ser utilizado para determinar el identificador de la unidad del sistema de systemd (es decir, servicio del sistema o unidad de ámbito) de un proceso identificado por el PID especificado. El nombre de la unidad es una cadena corta, adecuada para su uso en rutas del sistema de archivos. Tenga en cuenta que no todos los procesos forman parte de una unidad/servicio del sistema. Para procesos que no forman parte de una unidad del sistema de systemd, esta función fallará con -ENODATA. (Más específicamente, esta llamada no funcionará para hilos del kernel). La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso.

sd_pid_get_machine_name() puede ser utilizado para determinar el nombre de la VM o contenedor del que es miembro. El nombre de la máquina es una cadena corta, adecuada para su uso en rutas del sistema de archivos. La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso. Para procesos que no forman parte de una VM o contenedor, esta función falla con -ENODATA.

sd_pid_get_slice() puede ser utilizado para determinar la unidad slice de la que es miembro el proceso. Ver systemd.slice(5) para más detalles sobre los slices. La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso.

De manera similar, sd_pid_get_user_slice() devuelve el slice de usuario (gestionado por la instancia de systemd del usuario) de un proceso.

sd_pid_get_cgroup() devuelve la ruta del grupo de control del proceso especificado, relativa a la raíz de la jerarquía. Devuelve la ruta sin barra final, excepto para procesos ubicados en el grupo de control raíz, donde se devuelve "/". Para encontrar la ruta real del grupo de control en el sistema de archivos, la ruta devuelta debe ir precedida por /sys/fs/cgroup/.

Si el parámetro pid de cualquiera de estas funciones se pasa como 0, la operación se ejecuta para el proceso que realiza la llamada.

Las llamadas sd_pidfd_get_owner_uid(), sd_pidfd_get_session(), sd_pidfd_get_user_unit(), sd_pidfd_get_unit(), sd_pidfd_get_machine_name(), sd_pidfd_get_slice(), sd_pidfd_get_user_slice() y sd_pidfd_get_cgroup() operan de manera similar a sus homólogos PID, pero aceptan un PIDFD en lugar de un PID, lo que significa que no están sujetas a condiciones de carrera de reciclaje ya que el proceso está fijado por el descriptor de archivo durante toda la duración de la invocación. Tenga en cuenta que estas requieren un kernel que soporte PIDFD. Se puede adquirir un descriptor de archivo adecuado a través de pidfd_open(2).

Las llamadas sd_peer_get_owner_uid(), sd_peer_get_session(), sd_peer_get_user_unit(), sd_peer_get_unit(), sd_peer_get_machine_name(), sd_peer_get_slice(), sd_peer_get_user_slice() y sd_peer_get_cgroup() operan de manera similar a sus homólogos PID, pero aceptan un socket AF_UNIX conectado y recuperan información sobre el proceso par conectado. Tenga en cuenta que estos campos se recuperan a través de /proc/, y por lo tanto no son adecuados para fines de autorización, ya que están sujetos a condiciones de carrera.

VALOR DE RETORNO

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de fallo, estas llamadas devuelven un código de error negativo de estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ESRCH

El PID especificado no se refiere a un proceso en ejecución.

-EBADF

El descriptor de archivo especificado no es válido.

-ENODATA

El campo especificado no está definido para el proceso o par descrito.

-EINVAL

sd_pidfd_get_owner_uid(3)

NAME

sd_pidfd_get_owner_uid, sd_pidfd_get_session, sd_pidfd_get_unit, sd_pidfd_get_user_unit, sd_pidfd_get_machine_name, sd_pidfd_get_slice, sd_pidfd_get_user_slice, sd_pidfd_get_cgroup, sd_pid_get_owner_uid, sd_pid_get_session, sd_pid_get_unit, sd_pid_get_user_unit, sd_pid_get_machine_name, sd_pid_get_slice, sd_pid_get_user_slice, sd_pid_get_cgroup - obtener información de contexto de un proceso

#include <systemd/sd-daemon.h>

int sd_pidfd_get_user_unit(pidfd_t pidfd, const char **user_unit);

int sd_pidfd_get_machine_name(pidfd_t pidfd, const char **machine_name);

int sd_pidfd_get_slice(pidfd_t pidfd, const char **slice);

int sd_pidfd_get_user_slice(pidfd_t pidfd, const char **user_slice);

int sd_pidfd_get_cgroup(pidfd_t pidfd, const char **cgroup);

int sd_pid_get_user_slice(pid_t pid, const char **user_slice);

int sd_pid_get_cgroup(pid_t pid, const char **cgroup);

DESCRIPTION

These functions retrieve metadata associated with a process. They can operate on a process identifier or a file descriptor referring to a process.

The functions starting with sd_pidfd_ operate on a process descriptor pidfd (as returned by pidfd_open(2)). The functions starting with sd_pid_ operate on a process identifier pid.

sd_pidfd_get_owner_uid() and sd_pid_get_owner_uid() retrieve the effective user ID of the owner of the process.

sd_pidfd_get_session() and sd_pid_get_session() retrieve the login session identifier string of the process.

sd_pidfd_get_unit() and sd_pid_get_unit() retrieve the systemd unit name (e.g. "init.scope", "user@1000.service") with which the process is associated.

sd_pidfd_get_user_unit() and sd_pid_get_user_unit() retrieve the systemd user unit name of the process.

sd_pidfd_get_machine_name() and sd_pid_get_machine_name() retrieve the machine name string from the machine that owns the process. This is useful when dealing with processes running inside containers or virtual machines managed by systemd-machined.service(8).

sd_pidfd_get_slice() and sd_pid_get_slice() retrieve the systemd slice unit name (e.g. "machine.slice", "user.slice") that the process belongs to.

sd_pidfd_get_user_slice() and sd_pid_get_user_slice() retrieve the systemd user slice unit name of the process.

sd_pidfd_get_cgroup() and sd_pid_get_cgroup() retrieve the cgroup path of the process.

For functions that return a string, the string is allocated by the library and the caller must free it using free(3). If the requested information is not available or the process is not associated with the requested context, these functions return 0 and set the output pointer to NULL.

The returned session identifier may be an empty string if the process is not associated with any login session.

The returned unit, user unit, slice, and user slice names may be empty strings if the process is not associated with any such unit.

The returned cgroup path may be an empty string if the process is not associated with any cgroup.

The returned machine name may be an empty string if the process is not associated with any machine.

RETURN VALUE

On success, sd_pidfd_get_owner_uid() and sd_pid_get_owner_uid() return the owner UID. For all other functions, they return a non-negative integer on success. On failure, they return a negative value, with the specific error code being:

-EINVAL

An input parameter was invalid (out of range, or NULL, where that is not accepted).

-ENOMEM

Memory allocation failed.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

Note that the login session identifier as returned by sd_pid_get_session() is completely unrelated to the process session identifier as returned by getsid(2).
