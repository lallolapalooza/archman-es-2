sd_journal_close(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_JOURNAL_OPEN(3) sd_journal_open SD_JOURNAL_OPEN(3)

NOMBRE

sd_journal_open, sd_journal_open_directory, sd_journal_open_directory_fd, sd_journal_open_files, sd_journal_open_files_fd, sd_journal_open_namespace, sd_journal_close, sd_journal, SD_JOURNAL_LOCAL_ONLY, SD_JOURNAL_RUNTIME_ONLY, SD_JOURNAL_SYSTEM, SD_JOURNAL_CURRENT_USER, SD_JOURNAL_OS_ROOT, SD_JOURNAL_ALL_NAMESPACES, SD_JOURNAL_INCLUDE_DEFAULT_NAMESPACE, SD_JOURNAL_TAKE_DIRECTORY_FD - Abre el journal del sistema para lectura

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_open(sd_journal **ret, int flags);

int sd_journal_open_namespace(sd_journal **ret, const char *namespace, int flags);

int sd_journal_open_directory(sd_journal **ret, const char *path, int flags);

int sd_journal_open_directory_fd(sd_journal **ret, int fd, int flags);

int sd_journal_open_files(sd_journal **ret, const char **paths, int flags);

int sd_journal_open_files_fd(sd_journal **ret, int fds[], unsigned n_fds, int flags);

void sd_journal_close(sd_journal *j);

DESCRIPCIÓN

sd_journal_open() abre el journal de logs para lectura. Encontrará todos los archivos del journal automáticamente y los intercalará automáticamente al leer. Como primer argumento toma un puntero a un puntero sd_journal, que, en caso de éxito, contendrá un objeto de contexto del journal. El segundo argumento es un campo de flags, que puede consistir en las siguientes flags ORed juntas: SD_JOURNAL_LOCAL_ONLY asegura que solo se abrirán los archivos del journal generados en la máquina local. SD_JOURNAL_RUNTIME_ONLY asegura que solo se abrirán los archivos del journal volátiles, excluyendo aquellos que se almacenan en almacenamiento persistente. SD_JOURNAL_SYSTEM hará que se abran los archivos del journal de servicios del sistema y del kernel (en oposición a los procesos de sesión de usuario). SD_JOURNAL_CURRENT_USER hará que se abran los archivos del journal del usuario actual. Si no se especifica ni SD_JOURNAL_SYSTEM ni SD_JOURNAL_CURRENT_USER, se abrirán todos los tipos de archivos del journal.

sd_journal_open_namespace() es similar a sd_journal_open() pero toma un parámetro adicional namespace que especifica en qué namespace del journal operar. Si se especifica como NULL la llamada es idéntica a sd_journal_open(). Si no es NULL solo se accederá a los datos del namespace identificado por el parámetro especificado. Esta llamada entiende dos flags adicionales: si se especifica SD_JOURNAL_ALL_NAMESPACES el parámetro namespace se ignora y se accede a todos los namespaces definidos simultáneamente; si se especifica SD_JOURNAL_INCLUDE_DEFAULT_NAMESPACE se accede al namespace especificado y al namespace por defecto pero a ninguno más (este flag no tiene efecto cuando se pasa namespace como NULL). Para más detalles sobre namespaces de journal, consulte systemd-journald.service(8).

sd_journal_open_directory() es similar a sd_journal_open() pero toma una ruta de directorio absoluta como argumento. Todos los archivos del journal en este directorio se abrirán e intercalarán automáticamente. Esta llamada también toma un argumento de flags. Los parámetros de flags aceptados por esta llamada son SD_JOURNAL_OS_ROOT, SD_JOURNAL_SYSTEM, y SD_JOURNAL_CURRENT_USER. Si se especifica SD_JOURNAL_OS_ROOT, los archivos del journal se buscarán debajo de los habituales /var/log/journal y /run/log/journal relativos a la ruta especificada, en lugar de directamente debajo de ella. Los otros dos flags limitan qué archivos se abren, lo mismo que para sd_journal_open().

sd_journal_open_directory_fd() es similar a sd_journal_open_directory(), pero toma un descriptor de archivo que referencia un directorio en el sistema de archivos en lugar de una ruta absoluta del sistema de archivos. Además de los flags aceptados por sd_journal_open_directory(), esta función también acepta SD_JOURNAL_TAKE_DIRECTORY_FD. Si se especifica SD_JOURNAL_TAKE_DIRECTORY_FD, la función tomará la propiedad del descriptor de archivo especificado en caso de éxito, y será cerrado por sd_journal_close(), por lo tanto, el llamador de la función no debe cerrar el descriptor de archivo. Cuando el flag no se especifica, sd_journal_close() no cerrará el descriptor de archivo, por lo que el llamador debería cerrarlo después de sd_journal_close().

sd_journal_open_files() es similar a sd_journal_open() pero toma una lista terminada en NULL de rutas de archivo para abrir. Todos los archivos se abrirán e intercalarán automáticamente. Esta llamada también toma un argumento de flags, pero debe pasarse como 0 ya que actualmente no se entienden flags para esta llamada. Tenga en cuenta que en el caso de un journal en vivo, esta función solo es útil para depuración, ya que los archivos individuales del journal pueden rotarse en cualquier momento, y la apertura de archivos específicos es inherentemente competitiva.

sd_journal_open_files_fd() es similar a sd_journal_open_files() pero toma un array de descriptores de archivo abiertos que deben referenciar archivos del journal, en lugar de un array de rutas del sistema de archivos. Pase el array de descriptores de archivo como segundo argumento, y el número de entradas del array en el tercero. El parámetro flags debe pasarse como 0.

Los objetos sd_journal no pueden usarse en el hijo después de un fork. Las funciones que toman un objeto de journal como argumento (sd_journal_next() y otras) devolverán -ECHILD después de un fork.

sd_journal_close() cerrará el contexto del journal asignado con sd_journal_open() o sd_journal_open_directory() y liberará sus recursos.

Al abrir el journal, solo se abrirán los archivos del journal accesibles para el usuario que llama. Si los archivos del journal no son accesibles para el llamador, esto se ignorará silenciosamente.

Consulte sd_journal_next(3) para un ejemplo de cómo iterar a través del journal después de abrirlo con sd_journal_open().

Un objeto de contexto de journal devuelto por sd_journal_open() referencia una entrada de journal específica como entrada *actual*, similar a un índice de búsqueda de archivo en un archivo de sistema de archivos clásico, pero sin posiciones absolutas. Puede ser alterado con sd_journal_next(3) y sd_journal_seek_head(3) y llamadas relacionadas. La posición de la entrada actual puede exportarse en cadenas de *cursor*, como se accede a través de sd_journal_get_cursor(3). Las cadenas de cursor pueden usarse para identificar globalmente una entrada de journal específica de manera estable y luego para buscarla (o si la entrada específica no está disponible localmente, a su entrada más cercana en el tiempo) sd_journal_seek_cursor(3).

La notificación de cambios en el journal está disponible a través de sd_journal_get_fd() y llamadas relacionadas.

VALOR DE RETORNO

Las llamadas sd_journal_open(), sd_journal_open_directory(), y sd_journal_open_files() devuelven 0 en caso de éxito o un código de error negativo estilo errno. sd_journal_close() no devuelve nada.

NOTAS

Todas las funciones aquí descritas son agnósticas a hilos y solo un único hilo puede operar en un objeto dado en un momento dado. Hilos diferentes pueden acceder al mismo objeto en diferentes momentos. Múltiples objetos independientes pueden usarse desde diferentes hilos en paralelo.

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar contra y enlazar con el archivo libsystemd de pkg-config(1).

HISTORIA

sd_journal_open(), sd_journal_open_directory(), y sd_journal_close() se añadieron en la versión 187.

sd_journal_open_files() se añadió en la versión 205.

sd_journal_open_directory_fd() y sd_journal_open_files_fd() se añadieron en la versión 230.

sd_journal_open_namespace() se añadió en la versión 245.
