DESCRIPCIÓN

Estas funciones devuelven información de credenciales de un objeto sd_bus_creds. Los objetos de credenciales pueden ser creados con sd_bus_creds_new_from_pid(3), en cuyo caso describen las credenciales del proceso identificado por el PID especificado, con sd_bus_get_name_creds(3), en cuyo caso describen las credenciales de un par del bus identificado por el nombre del bus especificado, con sd_bus_get_owner_creds(3), en cuyo caso describen las credenciales del creador de un bus, o con sd_bus_message_get_creds(3), en cuyo caso describen las credenciales del remitente del mensaje.

No todos los campos de credenciales forman parte de cada objeto "sd_bus_creds". Usa sd_bus_creds_get_mask(3) para determinar la máscara de campos disponibles.

sd_bus_creds_get_pid() recuperará el PID (identificador de proceso). De manera similar, sd_bus_creds_get_ppid() recuperará el PID padre. Ten en cuenta que el PID 1 no tiene proceso padre, en cuyo caso se devuelve -ENXIO.

sd_bus_creds_get_pidfd_dup() recuperará el descriptor de archivo PID (pidfd), consulta pidfd_open(2) para más detalles. El descriptor de archivo se duplica y, por lo tanto, debe ser cerrado por el llamador.

sd_bus_creds_get_tid() recuperará el TID (identificador de hilo).

sd_bus_creds_get_uid() recuperará el UID numérico (identificador de usuario). De manera similar, sd_bus_creds_get_euid() devuelve el UID efectivo, sd_bus_creds_get_suid() el UID guardado y sd_bus_creds_get_fsuid() el UID del sistema de archivos.

sd_bus_creds_get_gid() recuperará el GID numérico (identificador de grupo). De manera similar, sd_bus_creds_get_egid() devuelve el GID efectivo, sd_bus_creds_get_sgid() el GID guardado y sd_bus_creds_get_fsgid() el GID del sistema de archivos.

sd_bus_creds_get_supplementary_gids() recuperará la lista de GIDs suplementarios.

sd_bus_creds_get_comm() recuperará el campo comm (nombre truncado del ejecutable, tal como se almacena en /proc/pid/comm).

sd_bus_creds_get_tid_comm() recuperará el campo comm del hilo (tal como se almacena en /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() recuperará la ruta al ejecutable del programa (tal como se almacena en el enlace /proc/pid/exe, pero con el sufijo " (deleted)" eliminado). Ten en cuenta que los hilos del kernel no tienen una ruta ejecutable, en cuyo caso se devuelve -ENXIO. Ten en cuenta que esta propiedad no debe usarse para más que información explicativa, en particular no debe usarse para decisiones relevantes para la seguridad. Eso es porque el ejecutable podría haber sido reemplazado o eliminado para cuando el valor pueda ser procesado. DESCRIPCIÓN

Estas funciones se utilizan para obtener información de credenciales de un objeto de credenciales de bus sd_bus_creds. Este objeto se puede crear a partir de un PID usando sd_bus_creds_new_from_pid(3), o a partir de un mensaje de bus entrante usando sd_bus_message_get_creds(3). Si la información solicitada no está disponible, se devolverá un código de error negativo.

Las siguientes funciones recuperan campos numéricos individuales del objeto de credenciales:

sd_bus_creds_get_pid()
Obtiene el ID del proceso.
sd_bus_creds_get_ppid()
Obtiene el ID del proceso padre.
sd_bus_creds_get_tid()
Obtiene el ID del hilo.
sd_bus_creds_get_uid()
Obtiene el ID de usuario real.
sd_bus_creds_get_gid()
Obtiene el ID de grupo real.
sd_bus_creds_get_euid()
Obtiene el ID de usuario efectivo.
sd_bus_creds_get_suid()
Obtiene el ID de usuario guardado.
sd_bus_creds_get_fsuid()
Obtiene el ID de usuario del sistema de archivos.
sd_bus_creds_get_egid()
sd_bus_creds_get_sgid()
sd_bus_creds_get_fsgid()
Obtiene los IDs de grupo efectivos, guardados y del sistema de archivos, respectivamente.
sd_bus_creds_get_supplementary_gids()
Obtiene la lista de IDs de grupo suplementarios.
sd_bus_creds_get_pidfd_dup()
Duplica el descriptor de archivo pidfd para el proceso. El descriptor de archivo devuelto debe cerrarse explícitamente con la llamada a close(2).

Las siguientes funciones recuperan cadenas de caracteres de los credenciales:

sd_bus_creds_get_comm()
Obtiene el nombre del comando truncado del proceso (tal como se almacena en /proc/pid/comm).
sd_bus_creds_get_tid_comm()
Obtiene el nombre del comando truncado del hilo (tal como se almacena en /proc/pid/task/tid/comm).
sd_bus_creds_get_exe()
Obtiene la ruta del ejecutable del proceso (tal como se almacena en /proc/pid/exe). Tenga en cuenta que los hilos del kernel no tienen un ejecutable, en cuyo caso se devuelve -ENXIO.
sd_bus_creds_get_cmdline()
sd_bus_creds_get_cmdline() recuperará una matriz de argumentos de línea de comandos (tal como se almacena en /proc/pid/cmdline). Tenga en cuenta que los hilos del kernel no tienen una línea de comandos, en cuyo caso se devuelve -ENXIO.
sd_bus_creds_get_cgroup()
sd_bus_creds_get_cgroup() recuperará la ruta del grupo de control. Ver Control Groups v2[1].
sd_bus_creds_get_unit()
sd_bus_creds_get_unit() recuperará el nombre de la unidad de systemd (en la instancia del sistema de systemd) de la que forma parte el proceso. Ver systemd.unit(5). Para procesos que no forman parte de una unidad, devuelve -ENXIO.
sd_bus_creds_get_user_unit()
sd_bus_creds_get_user_unit() recuperará el nombre de la unidad de systemd (en la instancia de usuario de systemd) de la que forma parte el proceso. Ver systemd.unit(5). Para procesos que no forman parte de una unidad de usuario, devuelve -ENXIO.
sd_bus_creds_get_slice()
sd_bus_creds_get_slice() recuperará la slice de systemd (una unidad en la instancia del sistema de systemd) de la que forma parte el proceso. Ver systemd.slice(5). De manera similar, sd_bus_creds_get_user_slice() recupera la slice de systemd del proceso, en la instancia de usuario de systemd.
sd_bus_creds_get_session()
Obtendrá el identificador de la sesión de inicio de sesión de la que forma parte el proceso. Tenga en cuenta que la sesión de inicio de sesión puede limitarse a uno o dos procesos de stub. Los procesos de usuario pueden ser iniciados desde su gestor de usuario de systemd, por ejemplo, aplicaciones gráficas iniciadas usando activación por DBus, así como procesos de servicio que se comparten entre varios inicios de sesión del mismo usuario. Para procesos que no forman parte de una sesión, devuelve -ENXIO.
sd_bus_creds_get_owner_uid()
Obtendrá el UID numérico (identificador de usuario) del usuario que es propietario de la unidad de usuario o sesión de inicio de sesión de la que forma parte el proceso. Ver systemd-logind.service(8). Para procesos que no forman parte de una unidad de usuario o sesión de usuario, devuelve -ENXIO.
sd_bus_creds_has_effective_cap()
Comprobará si la capacidad especificada por capability se estableció en la máscara de capacidades efectivas. Un valor de retorno positivo significa que se estableció, cero significa que no se estableció y un valor de retorno negativo indica un error. Ver capabilities(7) y los ajustes AmbientCapabilities= y CapabilityBoundingSet= en systemd.exec(5).
sd_bus_creds_has_permitted_cap()
Es similar a sd_bus_creds_has_effective_cap(), pero comprobará la máscara de capacidades permitidas.
sd_bus_creds_has_inheritable_cap()
Es similar a sd_bus_creds_has_effective_cap(), pero comprobará la máscara de capacidades heredables.
sd_bus_creds_has_bounding_cap()
Es similar a sd_bus_creds_has_effective_cap(), pero comprobará la máscara de capacidades delimitadoras.
sd_bus_creds_get_selinux_context()
Obtendrá el contexto de seguridad SELinux (etiqueta) del proceso.
sd_bus_creds_get_audit_session_id()
Obtendrá el identificador de sesión de auditoría del proceso. Devuelve -ENXIO para procesos que no forman parte de una sesión de auditoría.
sd_bus_creds_get_audit_login_uid()
Obtendrá el identificador de inicio de sesión de auditoría del usuario (el identificador del usuario que es "responsable" de la sesión). Devuelve -ENXIO para procesos que no forman parte de una sesión de auditoría.
sd_bus_creds_get_tty()
Obtendrá el TTY de control, sin el prefijo "/dev/". Devuelve -ENXIO para procesos que no tienen un TTY de control.
sd_bus_creds_get_unique_name()
Obtendrá el nombre único de D-Bus. Ver The D-Bus specification[2].
sd_bus_creds_get_well_known_names()
Obtendrá el conjunto de nombres conocidos de D-Bus. Ver The D-Bus specification[2].
sd_bus_creds_get_description()
Obtendrá un nombre descriptivo de la conexión de bus del par. Este nombre es útil para distinguir múltiples conexiones de bus del mismo par y puede ser modificado por el par con la llamada a sd_bus_set_description(3).

Todas las funciones que toman un parámetro const char** almacenarán la respuesta allí como una dirección de una cadena terminada en NUL. Será válida mientras c permanezca válida, y no debe ser liberada ni modificada por el llamante.

Todas las funciones que toman un parámetro char*** almacenarán la respuesta allí como una dirección de una matriz de cadenas. Cada cadena individual está terminada en NUL, y la matriz está terminada en NULL en su conjunto. Será válida mientras c permanezca válida, y no debe ser liberada ni modificada por el llamante.

VALOR DE RETORNO

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, estas llamadas devuelven un código de error negativo de estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENODATA

El campo especificado no está disponible en el objeto de credenciales c.

-ENXIO

El campo especificado no está definido para el proceso o par descrito. Esto será devuelto por sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), y sd_bus_creds_get_session() si el proceso no forma parte de una unidad de sistema de systemd, unidad de usuario de systemd, slice de systemd o sesión de logind. Será devuelto por sd_bus_creds_get_owner_uid() si el proceso no forma parte de una unidad de usuario de systemd o sesión de logind. También será devuelto por sd_bus_creds_get_exe() y sd_bus_creds_get_cmdline() para hilos del kernel (ya que estos no se inician desde un binario ejecutable, ni tienen una línea de comandos), y por sd_bus_creds_get_audit_session_id() y sd_bus_creds_get_audit_login_uid() cuando el proceso no forma parte de una sesión de auditoría, y sd_bus_creds_get_tty() si el proceso no tiene un TTY de control.

-EINVAL

El parámetro de puntero especificado es NULL.

-ENOMEM

Fallo en la asignación de memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar solo llamadas a setenv() desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
