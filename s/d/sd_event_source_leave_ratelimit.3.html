sd_event_source_leave_ratelimit(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_EVENT_SOURCE_SET_RATELIMIT(3) sd_event_source_set_ratelimit SD_EVENT_SOURCE_SET_RATELIMIT(3)

NOMBRE

sd_event_source_set_ratelimit, sd_event_source_get_ratelimit, sd_event_source_is_ratelimited, sd_event_source_set_ratelimit_expire_callback, sd_event_source_leave_ratelimit - Configurar limitación de velocidad en fuentes de eventos

SINOPSIS

#include <systemd/sd-event.h>

int sd_event_source_set_ratelimit(sd_event_source *source, uint64_t interval_usec, unsigned burst);

int sd_event_source_get_ratelimit(sd_event_source *source, uint64_t* ret_interval_usec, unsigned* ret_burst);

int sd_event_source_is_ratelimited(sd_event_source *source);

int sd_event_source_set_ratelimit_expire_callback(sd_event_source *source, sd_event_handler_tcallback);

int sd_event_source_leave_ratelimit(sd_event_source *source);

DESCRIPCIÓN

sd_event_source_set_ratelimit() se puede usar para aplicar limitación de velocidad a una fuente de eventos. Cuando se usa, una fuente de eventos se desactivará temporalmente cuando se active más a menudo que un número de ráfaga especificado dentro de un intervalo de tiempo especificado. Esto es útil como un mecanismo simple para evitar la inanición de fuentes de eventos si las fuentes de eventos de alta prioridad se activan con mucha frecuencia.

Pase la fuente de eventos a operar como primer argumento, un intervalo de tiempo en microsegundos como segundo argumento y un límite máximo de despacho ("ráfaga") como tercer parámetro. Cada vez que la fuente de eventos se despacha más a menudo que la ráfaga especificada dentro del intervalo especificado, se coloca en un modo similar a ser deshabilitada con sd_event_source_set_enabled(3) y el parámetro SD_EVENT_OFF. Sin embargo, solo se deshabilita temporalmente; una vez que el intervalo especificado ha terminado, la operación regular se reanuda. Se vuelve a deshabilitar temporalmente una vez que se alcanza la limitación de velocidad especificada la próxima vez. Si el intervalo o el valor de ráfaga se especifican como cero, la limitación de velocidad se desactiva. Por defecto, las fuentes de eventos no tienen habilitada la limitación de velocidad. Tenga en cuenta que la limitación de velocidad y la deshabilitación mediante sd_event_source_set_enabled() son independientes entre sí, y una fuente de eventos solo afectará a los despertares del bucle de eventos y se despachará mientras esté habilitada y la limitación de velocidad no esté en efecto.

sd_event_source_get_ratelimit() se puede usar para consultar los parámetros actuales de limitación de velocidad establecidos en el objeto de fuente de eventos source. Los valores de intervalo y ráfaga establecidos previamente se devuelven en el segundo y tercer argumento.

sd_event_source_is_ratelimited() se puede usar para consultar si la fuente de eventos está actualmente afectada por la limitación de velocidad, es decir, si ha alcanzado recientemente el límite de velocidad y está actualmente deshabilitada temporalmente debido a ello.

sd_event_source_set_ratelimit_expire_callback() se puede usar para establecer una función de callback que se invoca cada vez que la fuente de eventos sale del estado de limitación de velocidad. Tenga en cuenta que la función se llama en la misma iteración del bucle de eventos en la que ocurrió la transición de estado.

sd_event_source_leave_ratelimit() se puede usar para reactivar inmediatamente una fuente de eventos que fue deshabilitada temporalmente debido a la limitación de velocidad. Esto restablecerá los contadores de limitación de velocidad para el intervalo de tiempo actual.

La limitación de velocidad está implementada actualmente para fuentes de eventos de E/S, temporizadores, señales, diferidos e inotify.

VALOR DE RETORNO

En caso de éxito, sd_event_source_set_ratelimit(), sd_event_source_set_ratelimit_expire_callback y sd_event_source_get_ratelimit() devuelven un entero no negativo. En caso de error, devuelven un código de error negativo estilo errno. sd_event_source_is_ratelimited() devuelve cero si la limitación de velocidad no está actualmente en efecto y un valor mayor que cero si está en efecto; devuelve un código de error negativo estilo errno en caso de error. sd_event_source_leave_ratelimit() devuelve cero si la limitación de velocidad no estaba en efecto en la fuente de eventos especificada, y un valor positivo si lo estaba y la limitación de velocidad ahora está desactivada nuevamente; devuelve un código de error negativo estilo errno en caso de error.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

source no es un puntero válido a un objeto sd_event_source.

Añadido en la versión 248.

-ECHILD

El bucle de eventos se ha creado en un proceso, biblioteca o instancia de módulo diferente.

Añadido en la versión 248.

-EDOM

Se intentó usar la característica de limitación de velocidad en un tipo de fuente de eventos que no admite la limitación de velocidad.

Añadido en la versión 248.

-ENOEXEC

Se llamó a sd_event_source_get_ratelimit() en una fuente de eventos que no tiene configurada la limitación de velocidad.

Añadido en la versión 248.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos (thread-safe). Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar solo llamadas a setenv() desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

sd_event_source_set_ratelimit(), sd_event_source_get_ratelimit() y sd_event_source_is_ratelimited() se añadieron en la versión 248.

sd_event_source_set_ratelimit_expire_callback() se añadió en la versión 250.

sd_event_source_leave_ratelimit() se añadió en la versión 254.
