NOMBRE

sd_event_add_time, sd_event_add_time_relative, sd_event_source_get_time, sd_event_source_set_time, sd_event_source_set_time_relative, sd_event_source_get_time_accuracy, sd_event_source_set_time_accuracy, sd_event_source_get_time_clock, sd_event_time_handler_t - Añadir una fuente de eventos de temporizador a un bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_time_handler_t)(sd_event_source *s, uint64_t usec, void *userdata);

int sd_event_add_time(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_add_time_relative(sd_event *event, sd_event_source **source, clockid_t clock, uint64_t usec, uint64_t accuracy, sd_event_time_handler_t handler, void *userdata);

int sd_event_source_get_time(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time(sd_event_source *source, uint64_t usec);

int sd_event_source_set_time_relative(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_accuracy(sd_event_source *source, uint64_t *ret);

int sd_event_source_set_time_accuracy(sd_event_source *source, uint64_t usec);

int sd_event_source_get_time_clock(sd_event_source *source, clockid_t *ret);

DESCRIPCIÓN

sd_event_add_time() añade una nueva fuente de eventos de temporizador a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro clock acepta un identificador de reloj, uno de CLOCK_REALTIME, CLOCK_MONOTONIC, CLOCK_BOOTTIME, CLOCK_REALTIME_ALARM o CLOCK_BOOTTIME_ALARM. Consulte timerfd_create(2) para obtener detalles sobre los diversos tipos de relojes. El parámetro usec especifica la hora más temprana, en microsegundos (μs), en relación con la época del reloj, a la que se activará el temporizador. Si se especifica una hora que ya ha pasado (incluyendo 0), esta fuente de temporizador se dispara inmediatamente y está lista para ser despachada. Si el parámetro se especifica como UINT64_MAX, el evento del temporizador nunca transcurrirá, lo que puede utilizarse como alternativa para desactivar explícitamente una fuente de eventos de temporizador con sd_event_source_set_enabled(3). El parámetro accuracy especifica un valor de precisión adicional en μs que indica cuánto puede retrasarse el evento del temporizador. Utilice 0 para seleccionar la precisión por defecto (250ms). Utilice 1μs para la máxima precisión. Considere la especificación de 60000000μs (1 min) o más para eventos de larga duración que puedan retrasarse considerablemente. La elección de valores de precisión más altos permite al sistema agrupar eventos de temporizador de forma más agresiva, mejorando la eficiencia energética.

El handler es una función a la que llamar cuando transcurre el temporizador, o NULL. El puntero userdata se pasará a la función manejadora, y puede ser elegido libremente por el llamador. La hora de activación configurada también se pasa al manejador, incluso si la llamada se produce realmente un poco más tarde, sujeta al valor de precisión especificado, a la latencia del temporizador del kernel (consulte prctl(2)) y a latencias de programación adicionales. Para consultar la hora real en que se llamó al manejador, utilice sd_event_now(3). El manejador puede devolver un valor negativo para indicar un error (consulte más abajo), otros valores de retorno se ignoran. Si handler es NULL, se utilizará un manejador por defecto que llama a sd_event_exit(3).

Por defecto, el temporizador transcurrirá una vez (SD_EVENT_ONESHOT), pero esto puede cambiarse con sd_event_source_set_enabled(3). Si la función manejadora devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si se solicitó el modo SD_EVENT_ON antes, o provocará la terminación del bucle, consulte sd_event_source_set_exit_on_failure(3). Tenga en cuenta que un evento de temporizador configurado a SD_EVENT_ON se activará continuamente a menos que su hora configurada se actualice usando sd_event_source_set_time(3).

sd_event_add_time_relative() es similar a sd_event_add_time(), pero acepta una especificación de tiempo relativo. Es relativo a la hora actual de la iteración del bucle de eventos, tal como la devuelve sd_event_now(3).

Para destruir un objeto de fuente de eventos utilice sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se liberan todas las referencias a la fuente de eventos. Para asegurarse de que una fuente de eventos ya no se active, incluso si todavía se hace referencia a ella, desactive la fuente de eventos usando sd_event_source_set_enabled(3) con SD_EVENT_OFF.

Si el segundo parámetro de sd_event_add_time() es NULL, no se devuelve ninguna referencia al objeto de la fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando se destruya el propio bucle de eventos.

Si el parámetro handler de sd_event_add_time() es NULL, y la fuente de eventos se activa, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a un entero, se pasa como parámetro de código de salida a sd_event_exit(3).

Utilice CLOCK_BOOTTIME_ALARM y CLOCK_REALTIME_ALARM para definir fuentes de eventos que puedan despertar al sistema de la suspensión.

Para configurar temporizadores relativos (es decir, relativos a la hora actual), obtenga la hora actual a través de sd_event_now(3), súmele el intervalo de tiempo deseado y utilice el resultado como parámetro usec para sd_event_add_time().

Para configurar temporizadores repetitivos (es decir, temporizadores que se activan a intervalos regulares), configure el temporizador normalmente, para la primera invocación. Cada vez que se invoque el manejador de eventos, actualice la hora de activación del temporizador con sd_event_source_set_time(3) para la siguiente iteración del temporizador y reactive el temporizador usando sd_event_source_set_enabled(). Para calcular el siguiente punto en el tiempo a pasar a sd_event_source_set_time(), utilice como base el parámetro usec pasado a la devolución de llamada del temporizador, o la marca de tiempo devuelta por sd_event_now(). En el primer caso, los eventos del temporizador serán regulares, mientras que en el segundo caso, la latencia de programación continuará acumulándose en el temporizador.

sd_event_source_get_time() recupera el valor de tiempo configurado de una fuente de eventos creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar el tiempo, en relación con la época del reloj seleccionado, en μs. El valor devuelto es relativo a la época, incluso si la fuente de eventos se creó con un tiempo relativo a través de sd_event_add_time_relative().

sd_event_source_set_time() cambia la hora de una fuente de eventos creada previamente con sd_event_add_time() o sd_event_add_time_relative(). Toma el objeto de la fuente de eventos y una hora relativa a la época del reloj seleccionado, en μs.

sd_event_source_set_time_relative() es similar a sd_event_source_set_time(), pero toma una hora relativa a la hora actual de la iteración del bucle de eventos, tal como la devuelve sd_event_now().

sd_event_source_get_time_accuracy() recupera el valor de precisión configurado de una fuente de eventos creada previamente con sd_event_add_time(). Toma el objeto de la fuente de eventos y un puntero a una variable para almacenar la precisión. La precisión se especifica en μs.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo al estilo errno.

Errores

Los valores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento no válido.

-ESTALE

El bucle de eventos ya ha finalizado.

-ECHILD

El bucle de eventos se ha creado en un proceso, biblioteca o instancia de módulo diferente.

-EOPNOTSUPP

El reloj seleccionado no es compatible con la implementación del bucle de eventos.

-EDOM

El origen de evento pasado no es un origen de evento de temporizador.

-EOVERFLOW

El tiempo relativo pasado está fuera del rango permitido para los valores de tiempo (es decir, el valor especificado sumado al tiempo actual está fuera del rango de enteros sin signo de 64 bits).

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
