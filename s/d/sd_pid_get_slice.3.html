DESCRIPCIÓN

sd_pid_get_owner_uid() puede usarse para determinar la UID de Unix (identificador de usuario) que es propietaria de la sesión de inicio de sesión o de la unidad de usuario de systemd de un proceso identificado por el PID especificado. Para procesos que no forman parte de una sesión de inicio de sesión y no son gestionados por un gestor de usuarios, esta función fallará con -ENODATA.

sd_pid_get_session() puede usarse para determinar el identificador de sesión de inicio de sesión de un proceso identificado por el identificador de proceso especificado. El identificador de sesión es una cadena corta, adecuada para su uso en rutas de sistemas de archivos. Tenga en cuenta que la sesión de inicio de sesión puede limitarse a un proceso stub o dos. Los procesos de usuario pueden iniciarse en su lugar desde su gestor de usuario de systemd, por ejemplo, aplicaciones GUI iniciadas usando activación por DBus, así como procesos de servicio que se comparten entre múltiples inicios de sesión del mismo usuario. Para procesos que no forman parte de una sesión de inicio de sesión, esta función fallará con -ENODATA. La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso.

sd_pid_get_user_unit() puede usarse para determinar el identificador de unidad de usuario de systemd (es decir, servicio de usuario o unidad de ámbito) de un proceso identificado por el PID especificado. El nombre de la unidad es una cadena corta, adecuada para su uso en rutas de sistemas de archivos. Para procesos que no son gestionados por un gestor de usuarios, esta función fallará con -ENODATA. La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso.

sd_pid_get_unit() puede usarse para determinar el identificador de unidad del sistema de systemd (es decir, servicio del sistema o unidad de ámbito) de un proceso identificado por el PID especificado. El nombre de la unidad es una cadena corta, adecuada para su uso en rutas de sistemas de archivos. Tenga en cuenta que no todos los procesos forman parte de una unidad/servicio del sistema. Para procesos que no forman parte de una unidad del sistema de systemd, esta función fallará con -ENODATA. (Más específicamente, esta llamada no funcionará para hilos del kernel.) La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso.

sd_pid_get_machine_name() puede usarse para determinar el nombre de la VM o contenedor del que un proceso es miembro. El nombre de la máquina es una cadena corta, adecuada para su uso en rutas de sistemas de archivos. La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso. Para procesos que no forman parte de una VM o contenedor, esta función falla con -ENODATA.

sd_pid_get_slice() puede usarse para determinar la unidad slice de la que forma parte un proceso. Consulte systemd.slice(5) para obtener detalles sobre los slices. La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso.

De manera similar, sd_pid_get_user_slice() devuelve el slice de usuario (gestionado por la instancia de systemd del usuario) de un proceso.

sd_pid_get_cgroup() devuelve la ruta del grupo de control del proceso especificado, relativa a la raíz de la jerarquía. Devuelve la ruta sin la barra final, excepto para procesos ubicados en el grupo de control raíz, donde se devuelve "/". Para encontrar la ruta real del grupo de control en el sistema de archivos, la ruta devuelta debe prefijarse con /sys/fs/cgroup/.

Si el parámetro pid de cualquiera de estas funciones se pasa como 0, la operación se ejecuta para el proceso que realiza la llamada.

Las llamadas sd_pidfd_get_owner_uid(), sd_pidfd_get_session(), sd_pidfd_get_user_unit(), sd_pidfd_get_unit(), sd_pidfd_get_machine_name(), sd_pidfd_get_slice(), sd_pidfd_get_user_slice() y sd_pidfd_get_cgroup() operan de manera similar a sus contrapartes de PID, pero aceptan un PIDFD en lugar de un PID, lo que significa que no están sujetas a condiciones de carrera de reciclaje, ya que el proceso está anclado por el descriptor de archivo durante toda la invocación. Tenga en cuenta que estas requieren un kernel que admita PIDFD. Se puede adquirir un descriptor de archivo adecuado a través de pidfd_open(2).

Las llamadas sd_peer_get_owner_uid(), sd_peer_get_session(), sd_peer_get_user_unit(), sd_peer_get_unit(), sd_peer_get_machine_name(), sd_peer_get_slice(), sd_peer_get_user_slice() y sd_peer_get_cgroup() operan de manera similar a sus contrapartes de PID, pero aceptan un socket AF_UNIX conectado y recuperan información sobre el proceso par conectado. Tenga en cuenta que estos campos se recuperan a través de /proc/, y por lo tanto, no son adecuados para fines de autorización, ya que están sujetos a condiciones de carrera.

VALOR DEVUELTO

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, estas llamadas devuelven un código de error negativo de estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ESRCH

El PID especificado no se refiere a un proceso en ejecución.

-EBADF

El descriptor de archivo especificado no es válido.

-ENODATA

El campo dado no está especificado para el proceso o par descrito.

-EINVAL

DESCRIPTION

The functions described in this page retrieve information about the control group (cgroup), systemd unit, login session, owner UID, machine name, or slice associated with a process.

The functions starting with sd_pid_ take a process ID (PID) as the first argument, while the functions starting with sd_pidfd_ take a file descriptor referring to the process (obtained using pidfd_open(2)). For most use cases, using the file descriptor variants is preferred, as they are more robust and can correctly identify the process even if its PID is recycled.

The second argument for the functions returning strings (e.g. sd_pid_get_slice) is a pointer to a `char *`. On success, this pointer will be updated to point to a newly allocated string containing the requested information. The caller is responsible for freeing this string using free(3).

For functions returning a UID (sd_pid_get_owner_uid and sd_pidfd_get_owner_uid), the second argument is a pointer to a `uid_t`. On success, the UID will be written to the location pointed to by this argument.

The exact meaning of "slice" and "unit" depends on the context. Typically, "slice" refers to the machine resource control group slice (e.g., system.slice, user.slice), and "unit" refers to the systemd system or user unit the process belongs to (e.g., sshd.service, session-1.scope).

sd_pid_get_user_slice() and sd_pidfd_get_user_slice() retrieve the user slice of the process. This is usually user-UID.slice.

sd_pid_get_user_unit() and sd_pidfd_get_user_unit() retrieve the user unit of the process. This is usually a scope unit like session-*.scope.

sd_pid_get_session() and sd_pidfd_get_session() retrieve the login session identifier of the process. This is the identifier of the systemd login session the process belongs to, if any. The format is typically `session-*.scope`.

sd_pid_get_owner_uid() and sd_pidfd_get_owner_uid() retrieve the UID of the user who owns the login session the process belongs to, if any.

sd_pid_get_machine_name() and sd_pidfd_get_machine_name() retrieve the name of the systemd-nspawn container or other virtual machine the process belongs to, if any.

sd_pid_get_cgroup() and sd_pidfd_get_cgroup() retrieve the full path to the control group the process belongs to.

RETURN VALUE

On success, these functions return 0 or a positive integer. On failure, they return a negative errno-based error code.

ENOMEM

Memory allocation failed.

EINVAL

An input parameter was invalid (out of range, or NULL, where that is not accepted).

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

Note that the login session identifier as returned by sd_pid_get_session() is completely unrelated to the process session identifier as returned by getsid(2).
