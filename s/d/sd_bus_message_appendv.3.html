sd_bus_message_appendv(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_MESSAGE_APPEND(3) sd_bus_message_append SD_BUS_MESSAGE_APPEND(3)

NOMBRE

sd_bus_message_append, sd_bus_message_appendv - Adjuntar campos a un mensaje D-Bus basándose en una cadena de tipos

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_append(sd_bus_message *m, const char *types, ...);

int sd_bus_message_appendv(sd_bus_message *m, const char *types, va_list ap);

DESCRIPCIÓN

La función sd_bus_message_append() adjunta una secuencia de campos al objeto de mensaje D-Bus m. La cadena de tipos types describe los tipos de los argumentos de campo que siguen. Por cada tipo especificado en la cadena de tipos, se debe especificar uno o más argumentos, en el mismo orden en que se declaran en la cadena de tipos.

La cadena de tipos se compone de los elementos que se muestran en la tabla siguiente. Contiene cero o más "tipos completos" individuales. Cada tipo completo puede ser uno de los tipos básicos o un tipo contenedor completamente descrito. Un tipo contenedor puede ser una estructura con los tipos contenidos, una variante, un array con su tipo de elemento, o una entrada de diccionario con los tipos contenidos. La cadena de tipos termina en NUL.

En caso de un tipo básico, se espera un argumento del tipo correspondiente.

Una estructura se denota por una secuencia de tipos completos entre "(" y ")". Esta secuencia no puede estar vacía; debe contener al menos un tipo. Los argumentos correspondientes a esta secuencia anidada siguen las mismas reglas como si no estuvieran anidados.

Una variante se denota por "v". Los argumentos correspondientes deben comenzar con una cadena de tipos que denote un tipo completo, y a continuación, los argumentos correspondientes al tipo especificado.

Un array se denota por "a" seguido de un tipo completo. Los argumentos correspondientes deben comenzar con el número de entradas en el array, seguido de las entradas mismas, coincidiendo con el tipo de elemento del array.

Un diccionario es un array de entradas de diccionario, denotado por "a" seguido de un par de tipos completos entre "{" y "}". El primero de esos tipos debe ser un tipo básico. Los argumentos correspondientes deben comenzar con el número de entradas del diccionario, seguido de un par de valores para cada entrada que coincida con el tipo de elemento de las entradas del diccionario.

sd_bus_message_appendv() es equivalente a sd_bus_message_append(), excepto que se llama con un "va_list" en lugar de un número variable de argumentos. Esta función no llama a la macro va_end(). Dado que invoca a la macro va_arg(), el valor de ap no está definido después de la llamada.

Para más detalles sobre el sistema de tipos D-Bus, por favor consulte la Especificación D-Bus[1].

"s" SD_BUS_TYPE_STRING cadena Unicode variable char[]
"o" SD_BUS_TYPE_OBJECT_PATH ruta de objeto variable char[]
"g" SD_BUS_TYPE_SIGNATURE firma variable char[]
"h" SD_BUS_TYPE_UNIX_FD descriptor de archivo UNIX 4 bytes int
"a" SD_BUS_TYPE_ARRAY array determinado por el tipo y tamaño del array int, seguido del contenido del array
"v" SD_BUS_TYPE_VARIANT variante determinado por el argumento de tipo cadena de firma, seguido del contenido de la variante

")" SD_BUS_TYPE_STRUCT_END fin de array

"}" SD_BUS_TYPE_DICT_ENTRY_END fin de entrada de diccionario

Para los tipos
"s" y "g" (cadena unicode o firma), el puntero puede ser NULL, lo que es equivalente a una cadena vacía. Para "h" (descriptor de archivo UNIX), el descriptor se duplica con esta llamada y el descriptor pasado permanece en posesión del llamador. Véase sd_bus_message_append_basic(3) para la interpretación precisa de esos y otros tipos.

GRAMÁTICA DE CADENA DE TIPOS

tipos ::= complete_type*
complete_type ::= basic_type | variant | structure | array | dictionary
basic_type ::= "y" | "n" | "q" | "u" | "i" | "x" | "t" | "d" |
               "b" | "h" |
               "s" | "o" | "g"
variant ::= "v"
structure ::= "(" complete_type+ ")"
array ::= "a" complete_type
dictionary ::= "a" "{" basic_type complete_type "}"

EJEMPLOS

Adjuntar un único tipo básico (la cadena "una cadena"):

sd_bus_message *m;
...
sd_bus_message_append(m, "s", "una cadena");

Adjuntar todos los tipos de enteros:

uint8_t y = 1;
int16_t n = 2;
uint16_t q = 3;
int32_t i = 4;
uint32_t u = 5;
int32_t x = 6;
uint32_t t = 7;
double d = 8.0;
sd_bus_message_append(m, "ynqiuxtd", y, n, q, i, u, x, t, d);

Adjuntar una estructura compuesta por una cadena y una ruta de D-Bus:

sd_bus_message_append(m, "(so)", "una cadena", "/una/ruta");

Adjuntar un array de descriptores de archivo UNIX:

sd_bus_message_append(m, "ah", 3, STDIN_FILENO, STDOUT_FILENO, STDERR_FILENO);

Adjuntar una variante, con el tipo real "g" (firma), y valor "sdbusisgood":

sd_bus_message_append(m, "v", "g", "sdbusisgood");

Adjuntar un diccionario que contiene el mapeo {1=>"a", 2=>"b", 3=>""}:

sd_bus_message_append(m, "a{is}", 3, 1, "a", 2, "b", 3, NULL);

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un entero no negativo. En caso de error, devuelven un código de error negativo estilo errno.

ERRORES

Se pueden devolver los siguientes errores:

  -EINVAL La cadena de tipos no es válida o faltan argumentos.

  -ENOMEM No hay suficiente memoria disponible.

  -EBADF Se pasó un descriptor de archivo inválido para el tipo "h".

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

El parámetro especificado es inválido.

-EPERM

El mensaje ha sido sellado.

-ESTALE

El mensaje está en un estado inválido.

-ENXIO

El mensaje no se puede anexar.

-ENOMEM

Fallo al asignar memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar las llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.
