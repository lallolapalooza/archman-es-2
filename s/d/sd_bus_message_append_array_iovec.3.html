NOMBRE

sd_bus_message_append_array, sd_bus_message_append_array_memfd, sd_bus_message_append_array_iovec, sd_bus_message_append_array_space - Añadir un array de campos a un mensaje D-Bus

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_append_array(sd_bus_message *m, char type, const void *ptr, size_t size);

int sd_bus_message_append_array_memfd(sd_bus_message *m, char type, int memfd, uint64_t offset, uint64_t size);

int sd_bus_message_append_array_iovec(sd_bus_message *m, char type, const struct iovec *iov, unsigned n);

int sd_bus_message_append_array_space(sd_bus_message *m, char type, size_t size, void **ptr);

DESCRIPCIÓN

La función sd_bus_message_append_array() añade un array a un mensaje D-Bus m. Se abrirá un contenedor, se añadirán los contenidos del array y se cerrará el contenedor. El parámetro type determina cómo se interpreta el puntero p. type debe ser uno de los tipos "triviales" "y", "n", "q", "i", "u", "x", "t", "d" (pero no "b"), tal como se definen en la sección Tipos Básicos de D-Bus[1] de la especificación D-Bus, y listados en sd_bus_message_append_basic(3). El puntero p debe apuntar a un array de tamaño size bytes que contenga elementos del tipo respectivo. El tamaño size debe ser un múltiplo del tamaño del tipo type. Como caso especial, p puede ser NULL, si size es 0. La memoria apuntada por p se copia al área de memoria que contiene el mensaje y queda en posesión del llamador. Por lo tanto, el llamador puede modificar libremente los datos después de esta llamada sin afectar al mensaje al que se añadió el array.

La función sd_bus_message_append_array_memfd() añade un array de un tipo trivial al mensaje m, de forma similar a sd_bus_message_append_array(). Los contenidos del descriptor de archivo de memoria memfd, comenzando en el desplazamiento especificado y del tamaño especificado, se utilizan como contenidos del array. El desplazamiento y el tamaño deben ser múltiplos del tamaño del tipo type. Sin embargo, como excepción especial, si el desplazamiento se especifica como cero y el tamaño se especifica como UINT64_MAX, se utiliza el contenido completo del descriptor de archivo de memoria. El descriptor de archivo de memoria se sella con esta llamada si aún no se ha sellado y no puede modificarse después de esta llamada. Consulte memfd_create(2) para más detalles sobre los descriptores de archivo de memoria. La adición de arrays con descriptores de archivo de memoria permite la transferencia eficiente de datos sin copias, ya que el descriptor de archivo de memoria puede pasarse tal cual al destino, sin copiar la memoria en él al proceso de destino. No todos los transportes de protocolo admiten el paso de descriptores de archivo de memoria entre participantes, en cuyo caso esta llamada automáticamente recurrirá a la copia. Además, como el paso de descriptores de archivo de memoria es ineficiente para pequeñas cantidades de datos, es posible que la copia se imponga incluso donde se admite el paso de descriptores de archivo de memoria.

La función sd_bus_message_append_array_iovec() añade un array de un tipo trivial al mensaje m, de forma similar a sd_bus_message_append_array(). Los contenidos del array de vectores de E/S iov se utilizan como contenidos del array. El tamaño total de la carga útil de iov (la suma de los campos iov_len) debe ser un múltiplo del tamaño del tipo type. El argumento iov debe apuntar a n estructuras de vector de E/S. Cada estructura puede tener el campo iov_base establecido, en cuyo caso la memoria apuntada se copiará en el mensaje, o no establecido (establecido en cero), en cuyo caso se insertará un bloque de ceros de longitud iov_len bytes. La memoria apuntada por iov puede modificarse después de esta llamada.

La función sd_bus_message_append_array_space() reserva espacio para un array de un tipo trivial en el mensaje m. Se comporta igual que sd_bus_message_append_array(), pero en lugar de copiar los elementos al mensaje, devuelve un puntero al área de destino al llamador en el puntero p. Posteriormente, el llamador deberá escribir los contenidos del array en esta memoria. Las modificaciones en la memoria apuntada solo deben realizarse hasta la próxima operación en el mensaje de bus invocada. Lo más importante es que la memoria ya no debe alterarse cuando se ha añadido otro campo al mensaje o cuando el mensaje ha sido sellado.

VALOR DE RETORNO

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Parámetro especificado inválido.

-EPERM

Mensaje sellado.

-ESTALE

Mensaje en estado inválido.

-ENXIO

El mensaje no se puede añadir.

-ENOMEM

Error de asignación de memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando aún no se han iniciado otros hilos.

NAME

sd_bus_message_append_array_iovec - Añade un array de elementos de tipo simple al mensaje BUS

SYNOPSIS


#include <systemd/sd-bus.h>

int sd_bus_message_append_array_iovec(sd_bus_message *m, char type, const struct iovec *iov, size_t iovcnt, size_t element_size);

DESCRIPTION

El método sd_bus_message_append_array_iovec() añade un array de elementos de tipo simple al mensaje BUS {@code m}.

El parámetro {@code type} debe ser un único carácter que describa el tipo de los elementos del array. Los tipos permitidos son los mismos que los utilizados por sd_bus_message_append_basic(3). Por ejemplo, para añadir un array de enteros de 32 bits, {@code type} debe ser 'i'. Para añadir un array de cadenas de caracteres, {@code type} debe ser 's'.

Los datos del array se leen de {@code iovcnt} estructuras de {@code iovec} especificadas en {@code iov}. Cada estructura de {@code iovec} describe un buffer de memoria a través de sus miembros {@code iov_base} (un puntero al buffer) y {@code iov_len} (el tamaño del buffer en bytes).

El parámetro {@code element_size} especifica el tamaño de cada elemento individual del array en bytes. Esto es importante para que el bus pueda calcular correctamente el número de elementos en el array y para realizar la serialización/deserialización adecuada. Por ejemplo, si está añadiendo un array de enteros de 32 bits y {@code type} es 'i', {@code element_size} debe ser {@code sizeof(int32_t)}.

Esta función es útil cuando los datos que desea serializar ya están divididos en varios buffers o cuando desea evitar copiar los datos en un único buffer contiguo.

ARGUMENTS

sd_bus_message *m
Un puntero al mensaje de BUS al que se va a añadir el array.
char type
El carácter que describe el tipo de los elementos del array.
const struct iovec *iov
Un puntero a un array de estructuras {@code iovec} que describen los buffers de datos.
size_t iovcnt
El número de estructuras {@code iovec} en el array {@code iov}.
size_t element_size
El tamaño en bytes de cada elemento individual del array.

RETURN VALUE

En caso de éxito, devuelve 0 o un valor positivo. En caso de error, devuelve un errno negativo código.

NOTES

Esta función asume que los datos proporcionados en {@code iov} forman un array contiguo en términos lógicos, aunque puedan estar divididos en múltiples buffers físicos.

La función realiza la serialización de los datos según el tipo especificado. Asegúrese de que el {@code element_size} proporcionado coincide con el tamaño del tipo de datos que está serializando para evitar corrupción de datos.

Los tipos de datos simples que se pueden serializar incluyen: {@code 'y'} (int8_t), {@code 'b'} (uint8_t), {@code 'n'} (int16_t), {@code 'q'} (uint16_t), {@code 'i'} (int32_t), {@code 'u'} (uint32_t), {@code 'x'} (int64_t), {@code 't'} (uint64_t), {@code 'd'} (double), {@code 's'} (cadena de caracteres), {@code 'o'} (ruta de objeto), {@code 'g'} (firma de tipo).
