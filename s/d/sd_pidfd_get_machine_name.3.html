DESCRIPCIÓN

sd_pid_get_owner_uid() puede usarse para determinar la UID de Unix (identificador de usuario) que posee la sesión de inicio de sesión o la unidad de usuario de systemd de un proceso identificado por el PID especificado. Para procesos que no forman parte de una sesión de inicio de sesión y no son gestionados por un gestor de usuarios, esta función fallará con -ENODATA.

sd_pid_get_session() puede usarse para determinar el identificador de sesión de inicio de sesión de un proceso identificado por el identificador de proceso especificado. El identificador de sesión es una cadena corta, adecuada para su uso en rutas de sistemas de archivos. Tenga en cuenta que la sesión de inicio de sesión puede limitarse a un proceso stub o dos. Los procesos de usuario pueden iniciarse en su lugar desde su gestor de usuarios de systemd, por ejemplo, aplicaciones gráficas iniciadas mediante activación de DBus, así como procesos de servicio que se comparten entre múltiples inicios de sesión del mismo usuario. Para procesos que no forman parte de una sesión de inicio de sesión, esta función fallará con -ENODATA. La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso.

sd_pid_get_user_unit() puede usarse para determinar el identificador de unidad de usuario de systemd (es decir, servicio de usuario o unidad de ámbito) de un proceso identificado por el PID especificado. El nombre de la unidad es una cadena corta, adecuada para su uso en rutas de sistemas de archivos. Para procesos que no son gestionados por un gestor de usuarios, esta función fallará con -ENODATA. La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso.

sd_pid_get_unit() puede usarse para determinar el identificador de unidad del sistema de systemd (es decir, servicio del sistema o unidad de ámbito) de un proceso identificado por el PID especificado. El nombre de la unidad es una cadena corta, adecuada para su uso en rutas de sistemas de archivos. Tenga en cuenta que no todos los procesos forman parte de una unidad/servicio del sistema. Para procesos que no forman parte de una unidad del sistema de systemd, esta función fallará con -ENODATA. (Más específicamente, esta llamada no funcionará para hilos del kernel). La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso.

sd_pid_get_machine_name() puede usarse para determinar el nombre de la VM o contenedor del que es miembro un proceso. El nombre de la máquina es una cadena corta, adecuada para su uso en rutas de sistemas de archivos. La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso. Para procesos que no forman parte de una VM o contenedor, esta función falla con -ENODATA.

sd_pid_get_slice() puede usarse para determinar la unidad slice de la que es miembro el proceso. Consulte systemd.slice(5) para obtener detalles sobre los slices. La cadena devuelta debe liberarse con la llamada free(3) de libc después de su uso.

De forma similar, sd_pid_get_user_slice() devuelve el slice de usuario (gestionado por la instancia de systemd del usuario) de un proceso.

sd_pid_get_cgroup() devuelve la ruta del grupo de control del proceso especificado, relativa a la raíz de la jerarquía. Devuelve la ruta sin una barra final, excepto para procesos ubicados en el grupo de control raíz, donde se devuelve "/". Para encontrar la ruta real del grupo de control en el sistema de archivos, la ruta devuelta debe ir precedida por /sys/fs/cgroup/.

Si el parámetro pid de cualquiera de estas funciones se pasa como 0, la operación se ejecuta para el proceso llamante.

Las llamadas sd_pidfd_get_owner_uid(), sd_pidfd_get_session(), sd_pidfd_get_user_unit(), sd_pidfd_get_unit(), sd_pidfd_get_machine_name(), sd_pidfd_get_slice(), sd_pidfd_get_user_slice() y sd_pidfd_get_cgroup() operan de manera similar a sus contrapartes de PID, pero aceptan un PIDFD en lugar de un PID, lo que significa que no están sujetas a condiciones de carrera de reciclaje, ya que el proceso se fija por el descriptor de archivo durante toda la invocación. Tenga en cuenta que estas requieren un kernel que soporte PIDFD. Se puede obtener un descriptor de archivo adecuado a través de pidfd_open(2).

Las llamadas sd_peer_get_owner_uid(), sd_peer_get_session(), sd_peer_get_user_unit(), sd_peer_get_unit(), sd_peer_get_machine_name(), sd_peer_get_slice(), sd_peer_get_user_slice() y sd_peer_get_cgroup() operan de manera similar a sus contrapartes de PID, pero aceptan un socket AF_UNIX conectado y recuperan información sobre el proceso par conectado. Tenga en cuenta que estos campos se recuperan a través de /proc/ y, por lo tanto, no son adecuados para fines de autorización, ya que están sujetos a condiciones de carrera.

VALOR DE RETORNO

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, estas llamadas devuelven un código de error negativo al estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ESRCH

El PID especificado no se refiere a un proceso en ejecución.

-EBADF

El descriptor de archivo especificado no es válido.

-ENODATA

El campo especificado no está definido para el proceso o par descrito.

-EINVAL

El descriptor de archivo especificado no es un socket AF_UNIX o no está conectado.

-ENOMEM

No hay suficiente memoria para asignar la cadena devuelta.

-EACCES

El proceso que llama no tiene permiso para leer la información de /proc/ para el PID dado.

EJEMPLO

Por ejemplo, para obtener la unidad de systemd del proceso actual:

#include <stdio.h>
#include <stdlib.h>
#include <systemd/sd-login.h>

int main(void) {
    char *unit_name = NULL;
    int ret;

    ret = sd_pid_get_unit(0, &unit_name);
    if (ret < 0) {
        fprintf(stderr, "Failed to get unit name for current process: %s\n", strerror(-ret));
        return 1;
    }

    printf("Unit name: %s\n", unit_name);
    free(unit_name);

    return 0;
}
