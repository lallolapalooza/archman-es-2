NOMBRE

sd_journal_print, sd_journal_printv, sd_journal_send, sd_journal_sendv, sd_journal_perror, SD_JOURNAL_SUPPRESS_LOCATION, sd_journal_print_with_location, sd_journal_printv_with_location, sd_journal_send_with_location, sd_journal_sendv_with_location, sd_journal_perror_with_location - Enviar entradas de registro a la journal

SINOPSIS

#include <systemd/sd-journal.h>

int sd_journal_print(int prioridad, const char *formato, ...);

int sd_journal_printv(int prioridad, const char *formato, va_list ap);

int sd_journal_send(const char *formato, ...);

int sd_journal_sendv(const struct iovec *iov, int n);

int sd_journal_perror(const char *mensaje);

int sd_journal_print_with_location(int prioridad, const char *archivo, const char *linea, const char *func, const char *formato, ...);

int sd_journal_printv_with_location(int prioridad, const char *archivo, const char *linea, const char *func, const char *formato, va_list ap);

int sd_journal_send_with_location(const char *archivo, const char *linea, const char *func, const char *formato, ...);

int sd_journal_sendv_with_location(const char *archivo, const char *linea, const char *func, const struct iovec *iov, int n);

int sd_journal_perror_with_location(const char *archivo, const char *linea, const char *func, const char *mensaje);

DESCRIPCIÓN

sd_journal_print() puede ser utilizado para enviar entradas de registro simples y de texto plano al journal del sistema. El primer argumento es un valor de prioridad. A esto le sigue una cadena de formato y sus parámetros, similar a printf(3) o syslog(3). Tenga en cuenta que actualmente el mensaje resultante se truncará a LINE_MAX - 8. El valor de prioridad es uno de LOG_EMERG, LOG_ALERT, LOG_CRIT, LOG_ERR, LOG_WARNING, LOG_NOTICE, LOG_INFO, LOG_DEBUG, como se define en syslog.h, consulte syslog(3) para más detalles. Se recomienda usar esta llamada para enviar mensajes de registro en el idioma de la aplicación o el idioma del sistema y en formato UTF-8, pero no se imponen tales restricciones. Tenga en cuenta que los mensajes de registro escritos utilizando esta función generalmente no se espera que terminen en un carácter de nueva línea. Sin embargo, como todo espacio en blanco final (incluidos espacios, nuevas líneas, tabuladores y retornos de carro) se elimina automáticamente de la cadena registrada, es aceptable especificar uno (o más). Las líneas vacías (después de la eliminación del espacio en blanco final) se suprimen. En las líneas no vacías, el espacio en blanco inicial (así como el espacio en blanco interno) se deja sin modificar.

sd_journal_printv() es similar a sd_journal_print() pero toma una lista de argumentos variables encapsulada en un objeto de tipo va_list (consulte stdarg(3) para más información) en lugar de la cadena de formato. Por lo demás, es equivalente en comportamiento.

sd_journal_send() puede ser utilizado para enviar entradas de registro estructuradas al journal del sistema. Toma una serie de cadenas de formato, cada una seguida inmediatamente por sus parámetros asociados, terminadas por NULL. Las cadenas pasadas deben tener el formato "VARIABLE=valor". El nombre de la variable debe estar en mayúsculas y consistir únicamente en caracteres, números y guiones bajos, y no puede comenzar con un guion bajo. (Se ignorarán todas las asignaciones que no sigan esta sintaxis.) El valor puede ser de cualquier tamaño y formato. Se recomienda encarecidamente enviar solo cadenas de texto formateadas en la codificación de caracteres UTF-8, y enviar campos binarios solo cuando no sea sensato el formateo en cadenas UTF-8. Se definen una serie de campos conocidos, consulte systemd.journal-fields(7) para más detalles, pero se pueden usar campos adicionales definidos por la aplicación. Una variable puede asignarse más de un valor por entrada. Si se utiliza esta función, el espacio en blanco final se elimina automáticamente de cada campo formateado.

sd_journal_sendv() es similar a sd_journal_send() pero toma un array de struct iovec (tal como se define en uio.h, consulte readv(3) para más detalles) en lugar de la cadena de formato. Cada estructura debe hacer referencia a un campo de la entrada a enviar. El segundo argumento especifica el número de estructuras en el array. sd_journal_sendv() es particularmente útil para enviar objetos binarios al journal cuando sea necesario. Tenga en cuenta que esta función no eliminará el espacio en blanco final de los campos pasados, sino que transmitirá los datos especificados sin modificar. Esto es diferente tanto de sd_journal_print() como de sd_journal_send() descritas anteriormente, que se basan en cadenas de formato y eliminan el espacio en blanco final.

sd_journal_perror() es similar a perror(3) y escribe un mensaje en el journal que consiste en la cadena pasada, seguida de ": " y una representación legible por humanos del código de error actual almacenado en errno(3). Si la cadena del mensaje se pasa como NULL o como una cadena vacía, solo se escribirá la representación de la cadena de error, sin prefijo. Un campo adicional de journal ERRNO= se incluye en la entrada que contiene el código de error numérico formateado como una cadena decimal. La prioridad de registro utilizada es LOG_ERR (3).

Tenga en cuenta que sd_journal_send() es un envoltorio alrededor de sd_journal_sendv() para que sea más fácil de usar cuando solo se deban enviar cadenas de texto. Además, las dos llamadas siguientes son en gran medida equivalentes:

sd_journal_print(LOG_INFO, "Hola Mundo, ¡esto es PID %lu!", (unsigned long) getpid());
sd_journal_send("MESSAGE=Hola Mundo, ¡esto es PID %lu!", (unsigned long) getpid(),
                "PRIORITY=%i", LOG_INFO,
                NULL);

Tenga en cuenta que estas llamadas agregan implícitamente campos para el archivo de origen, el nombre de la función y la línea de código donde se invocaron. Esto se implementa con macros. Si no se desea esto, se puede desactivar definiendo SD_JOURNAL_SUPPRESS_LOCATION antes de incluir sd-journal.h.

sd_journal_print_with_location(), sd_journal_printv_with_location(), sd_journal_send_with_location(), sd_journal_sendv_with_location(), y sd_journal_perror_with_location() son similares a sus contrapartes sin "_with_location", pero aceptan parámetros adicionales para establecer explícitamente el nombre del archivo de origen, la función y la línea. Los argumentos "archivo" y "línea" deben contener entradas de journal válidas que incluyan el nombre de la variable, por ejemplo, "CODE_FILE=src/foo.c" y "CODE_LINE=666", mientras que "func" solo debe contener el nombre de la función, es decir, el valor sin "CODE_FUNC=". Estas variantes son principalmente útiles al escribir envoltorios personalizados, por ejemplo, en enlaces para un lenguaje diferente.

syslog(3) y sd_journal_print() pueden ser utilizados en gran medida de forma intercambiable en cuanto a funcionalidad. Sin embargo, tenga en cuenta que los mensajes de registro registrados a través del primero toman una ruta diferente al servidor de journal que el segundo, y por lo tanto, no se puede garantizar el orden cronológico global entre los dos flujos. Usar sd_journal_print() tiene el beneficio de registrar la línea de código fuente, los nombres de archivo y las funciones como metadatos junto con todas las entradas, y garantizar el orden cronológico con las entradas de registro estructuradas que se generan a través de sd_journal_send(). Usar syslog() tiene el beneficio de ser más portable.

Estas funciones implementan un cliente para el Protocolo Journal Nativo[1].

VALOR DE RETORNO

Las diez funciones devuelven 0 en caso de éxito o un código de error negativo estilo errno. La variable errno(3) es a

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un número de identificador de entrada de registro no negativo. En caso de error, devuelven un número negativo de error.

Si systemd-journald(8) no se está ejecutando (el socket no está presente), esas funciones no hacen nada y también devuelven 0.

SEGURIDAD EN HILOS

Todas las funciones listadas aquí son seguras para hilos y pueden ser llamadas en paralelo desde múltiples hilos.

sd_journal_sendv() y sd_journal_sendv_with_location() son "seguras para señales asíncronas" en el sentido de signal-safety(7).

sd_journal_print(), sd_journal_printv(), sd_journal_send(), sd_journal_perror(), y sus contrapartes con "_with_location" no son seguras para señales asíncronas.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando aún no se han iniciado otros hilos.
