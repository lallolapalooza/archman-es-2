SD_ID128_GET_MACHINE(3) sd_id128_get_machine SD_ID128_GET_MACHINE(3)

NOMBRE

sd_id128_get_machine, sd_id128_get_app_specific, sd_id128_get_machine_app_specific, sd_id128_get_boot, sd_id128_get_boot_app_specific, sd_id128_get_invocation - Recuperar identificadores de 128 bits

SINOPSIS

#include <systemd/sd-id128.h>

int sd_id128_get_machine(sd_id128_t *ret);

int sd_id128_get_app_specific(sd_id128_t base, sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_machine_app_specific(sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_boot(sd_id128_t *ret);

int sd_id128_get_boot_app_specific(sd_id128_t app_id, sd_id128_t *ret);

int sd_id128_get_invocation(sd_id128_t *ret);

int sd_id128_get_invocation_app_specific(sd_id128_t app_id, sd_id128_t *ret);

DESCRIPCIÓN

sd_id128_get_machine() devuelve el ID de máquina del host en ejecución. Lee y analiza el archivo machine-id(5). Esta función almacena en caché el ID de máquina internamente para que la recuperación del ID de máquina sea una operación barata. Este ID puede ser utilizado dondequiera que se necesite un identificador único para el sistema local. Sin embargo, se recomienda usar este ID tal cual solo en entornos confiables. En entornos no confiables, se recomienda derivar un ID específico de la aplicación a partir de este ID de máquina, de forma irreversible (criptográficamente segura). Para facilitar esto, se proporciona sd_id128_get_machine_app_specific(), véase más abajo.

sd_id128_get_app_specific() devuelve un ID de máquina que es una combinación de los parámetros base y app_id. Internamente, esta función calcula HMAC-SHA256 del parámetro app_id usando el parámetro base como clave, trunca este resultado para que quepa en sd_id128_t y lo convierte en un UUID válido de Variante 1 Versión 4, de acuerdo con RFC 4122[1]. Ninguno de los dos parámetros de entrada puede ser calculado a partir del parámetro de salida ret.

sd_id128_get_machine_app_specific() es similar a sd_id128_get_machine(), pero recupera un ID de máquina que es específico para la aplicación identificada por el ID de aplicación indicado. Se recomienda usar esta función en lugar de sd_id128_get_machine() al pasar un ID a entornos no confiables, para asegurarse de que el ID de máquina original no pueda ser determinado externamente. De esta manera, el ID utilizado por la aplicación permanece estable en una máquina dada, pero no puede correlacionarse fácilmente con los IDs utilizados en otras aplicaciones en la misma máquina. El ID específico de la aplicación debe generarse a través de una herramienta como systemd-id128 new y puede ser compilado en la aplicación. Esta función devolverá el mismo ID específico de la aplicación para cada combinación de ID de máquina y ID de aplicación. Internamente, esta función llama a sd_id128_get_app_specific() con el resultado de sd_id128_get_machine() y el parámetro app_id.

sd_id128_get_boot() devuelve el ID de arranque del kernel en ejecución. Lee y analiza el archivo /proc/sys/kernel/random/boot_id expuesto por el kernel. Se genera aleatoriamente al inicio del arranque y es único para cada instancia de kernel en ejecución. Consulte random(4) para más información. Esta función también almacena en caché internamente el ID devuelto para hacer que esta llamada sea una operación barata. Se recomienda usar este ID tal cual solo en entornos confiables. En entornos no confiables, se recomienda derivar un ID específico de la aplicación usando sd_id128_get_boot_app_specific(), véase más abajo.

sd_id128_get_boot_app_specific() es análogo a sd_id128_get_machine_app_specific(), pero devuelve un ID que cambia entre arranques. Algunas máquinas pueden ser utilizadas durante mucho tiempo sin reiniciarse, por lo que el ID de arranque puede permanecer constante durante mucho tiempo y tiene propiedades similares al ID de máquina durante ese tiempo.

sd_id128_get_invocation() devuelve el ID de invocación del servicio actualmente ejecutado. En su implementación actual, intenta leer y analizar lo siguiente:

•La variable de entorno $INVOCATION_ID que el gestor de servicios establece al activar un servicio.
•Una entrada en el keyring del kernel que el gestor de servicios del sistema establece al activar un servicio.

Consulte systemd.exec(5) para detalles. El ID se almacena en caché internamente. En el futuro, puede añadirse un mecanismo diferente para determinar el ID de invocación.

sd_id128_get_invocation_app_specific() deriva un ID específico de la aplicación a partir del ID de invocación.

Tenga en cuenta que sd_id128_get_machine_app_specific(), sd_id128_get_boot(), sd_id128_get_boot_app_specific(), sd_id128_get_invocation() y sd_id128_get_invocation_app_specific siempre devuelven IDs compatibles con UUID Variante 1 Versión 4. sd_id128_get_machine() también devolverá un ID compatible con UUID Variante 1 Versión 4 en nuevas instalaciones, pero podría no hacerlo en instalaciones antiguas. Es posible convertir el ID de máquina de forma no reversible en uno compatible con UUID Variante 1 Versión 4. Para más información, consulte machine-id(5). Por lo tanto, se garantiza que estas funciones nunca devolverán el ID compuesto por todos los bits cero o todos los bits uno (SD_ID128_NULL, SD_ID128_ALLF) — con la posible excepción de sd_id128_get_machine(), como se mencionó.

Para más información sobre el tipo "sd_id128_t", consulte sd-id128(3).

VALOR DE RETORNO

Estas llamadas devuelven 0 en caso de éxito (en cuyo caso ret se rellena) o un código de error negativo tipo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOENT

Devuelto por sd_id128_get_machine() y sd_id128_get_machine_app_specific() cuando falta /etc/machine-id.

Añadido en la versión 242.

-ENOMEDIUM

Devuelto por sd_id128_get_machine() y sd_id128_get_machine_app_specific() cuando /etc/machine-id está vacío o es todo ceros. También devuelto por sd_id128_get_invocation() cuando el ID de invocación es todo ceros.

Añadido en la versión 242.

-ENOPKG

Devuelto por sd_id128_get_machine() y sd_id128_get_machine_app_specific() cuando el contenido de /etc/machine-id es "uninitialized".

Añadido en la versión 253.

-ENOSYS

Devuelto por sd_id128_get_boot() y sd_id128_get_boot_app_specific() cuando /proc/ no está montado.

Añadido en la versión 253.

-ENXIO

Devuelto por sd_id128_get_invocation() si no se establece ningún ID de invocación. También devuelto por sd_id128_get_app_specific(), sd_id128_get_machine_app_specific(), y sd_id128_get_boot_app_specific() cuando el parámetro app_id es todo ceros.

Añadido en la versión 242.

-EUCLEAN

Devuelto por cualquiera de las funciones aquí descritas cuando el valor configurado tiene un formato inválido.

Añadido en la versión 253.

-EPERM

La información solicitada no pudo ser recuperada debido a permisos insuficientes.

Añadido en la versión 242.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada contra y enlazada con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que está declarado como no seguro para subprocesos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un subproceso paralelo. Se recomienda solo hacer llamadas a setenv() desde una fase temprana del programa cuando no se han iniciado otros subprocesos.

EJEMPLOS

Ejemplo 1. ID de máquina específico de la aplicación

Primero, genera el ID de la aplicación:

$ systemd-id128 -p new
Como cadena:
c273277323db454ea63bb96e79b53e97
Como UUID:
c2732773-23db-454e-a63b-b96e79b53e97
Como macro de man:sd-id128(3):
#define MESSAGE_XYZ SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
...

Luego, utilice el nuevo identificador en una aplicación de ejemplo:

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <systemd/sd-id128.h>
#define OUR_APPLICATION_ID SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
int main(int argc, char *argv[]) {
  sd_id128_t id;
  sd_id128_get_machine_app_specific(OUR_APPLICATION_ID, &id);
  printf("Our application ID: " SD_ID128_FORMAT_STR "\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}
