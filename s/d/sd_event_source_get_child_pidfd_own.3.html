sd_event_source_get_child_pidfd_own(3)

NOMBRE

sd_event_add_child, sd_event_add_child_pidfd, sd_event_source_get_child_pid, sd_event_source_get_child_pidfd, sd_event_source_get_child_pidfd_own, sd_event_source_set_child_pidfd_own, sd_event_source_get_child_process_own, sd_event_source_set_child_process_own, sd_event_source_send_child_signal, sd_event_child_handler_t - Añadir una fuente de eventos de cambio de estado de proceso hijo a un bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event_source sd_event_source;

typedef int (*sd_event_child_handler_t)(sd_event_source *s, const siginfo_t *si, void *userdata);

int sd_event_add_child(sd_event *event, sd_event_source **source, pid_t pid, int options, sd_event_child_handler_t handler, void *userdata);

int sd_event_add_child_pidfd(sd_event *event, sd_event_source **source, int pidfd, int options, sd_event_child_handler_t handler, void *userdata);

int sd_event_source_get_child_pid(sd_event_source *source, pid_t *ret);

int sd_event_source_get_child_pidfd(sd_event_source *source);

int sd_event_source_get_child_pidfd_own(sd_event_source *source);

int sd_event_source_set_child_pidfd_own(sd_event_source *source, int own);

int sd_event_source_get_child_process_own(sd_event_source *source);

int sd_event_source_set_child_process_own(sd_event_source *source, int own);

int sd_event_source_send_child_signal(sd_event_source *source, int sig, const siginfo_t *info, unsigned flags);

DESCRIPCIÓN

sd_event_add_child() añade una nueva fuente de eventos de cambio de estado de proceso hijo a un bucle de eventos. El objeto del bucle de eventos se especifica en el parámetro event, el objeto de la fuente de eventos se devuelve en el parámetro source. El parámetro pid especifica el PID del proceso a observar, que debe ser un proceso hijo directo del proceso invocador. El parámetro options determina qué cambios de estado se observarán. Debe contener una máscara OR de WEXITED (observar la terminación del proceso hijo), WSTOPPED (observar la detención del proceso hijo por una señal) y WCONTINUED (observar la reanudación del proceso hijo por una señal). Ver waitid(2) para más información.

El handler debe ser una función a llamar cuando el proceso cambie de estado o NULL. A la función manejadora se le pasará el puntero userdata, que puede ser elegido libremente por el llamador. La manejadora también recibe un puntero a una estructura siginfo_t que contiene información sobre el evento del proceso hijo. La manejadora puede devolver un valor negativo para señalar un error (ver más abajo), otros valores de retorno se ignoran. Si handler es NULL, se usará una manejadora predeterminada que llama a sd_event_exit(3).

Solo puede instalarse una manejadora para un proceso hijo específico. La manejadora se habilita para un solo evento (SD_EVENT_ONESHOT), pero esto puede cambiarse con sd_event_source_set_enabled(3). Si la función manejadora devuelve un código de error negativo, se deshabilitará después de la invocación, incluso si se solicitó el modo SD_EVENT_ON antes, o provocará la terminación del bucle, ver sd_event_source_set_exit_on_failure(3).

Para destruir un objeto de fuente de eventos, use sd_event_source_unref(3), pero tenga en cuenta que la fuente de eventos solo se elimina del bucle de eventos cuando se eliminan todas las referencias a ella. Para asegurarse de que una fuente de eventos no se dispare más, incluso cuando todavía hay una referencia a ella, considere establecer la fuente de eventos en SD_EVENT_OFF con sd_event_source_set_enabled(3).

La señal SIGCHLD debe estar bloqueada en todos los hilos antes de llamar a esta función (usando sigprocmask(2) o pthread_sigmask(3)).

Si el segundo parámetro de sd_event_add_child() se pasa como NULL, no se devuelve ninguna referencia al objeto de la fuente de eventos. En este caso, la fuente de eventos se considera "flotante" y se destruirá implícitamente cuando el propio bucle de eventos se destruya.

Tenga en cuenta que la función handler se invoca en un momento en que el proceso hijo aún no ha sido recolectado (y por lo tanto todavía está expuesto como un proceso zombi por el kernel). Sin embargo, el hijo será recolectado automáticamente después de que la función devuelva. Los procesos hijos para los cuales no se instalan fuentes de eventos de cambio de estado de proceso hijo no serán recolectados por la implementación del bucle de eventos.

Si el parámetro handler para sd_event_add_child() es NULL, y la fuente de eventos se dispara, esto se considerará una solicitud para salir del bucle de eventos. En este caso, el parámetro userdata, convertido a un entero, se pasa como el parámetro de código de salida a sd_event_exit(3).

Si tanto una fuente de eventos de cambio de estado de proceso hijo como una fuente de eventos de señal SIGCHLD están instaladas en el mismo bucle de eventos, las prioridades configuradas de la fuente de eventos deciden qué fuente de eventos se despacha primero. Si se procesa primero la manejadora de señales, esta debe dejar los procesos hijos para los cuales se instalan fuentes de eventos de cambio de estado de proceso hijo sin recolectar.

sd_event_add_child_pidfd() es similar a sd_event_add_child() pero toma un descriptor de archivo que hace referencia al proceso ("pidfd") en lugar del PID numérico. Un descriptor de archivo adecuado puede adquirirse mediante pidfd_open(2) y llamadas relacionadas. El descriptor de archivo pasado no se cierra cuando la fuente de eventos se libera de nuevo, a menos que se use sd_event_source_set_child_pidfd_own() para activar este comportamiento. Tenga en cuenta que independientemente de si se usa sd_event_add_child() o sd_event_add_child_pidfd() para asignar una fuente de eventos, el proceso observado debe ser un proceso hijo directo del proceso invocador. En ambos casos, SIGCHLD debe estar bloqueado en el proceso invocador.

sd_event_source_get_child_pid() recupera el PID configurado de una fuente de eventos de cambio de estado de proceso hijo creada previamente con sd_event_add_child(). Toma el objeto de la fuente de eventos como parámetro source y un puntero a una variable pid_t para devolver el ID del proceso.

sd_event_source_get_child_pidfd() recupera el descriptor de archivo que hace referencia al proceso observado ("pidfd"). El bucle de eventos utiliza internamente pidfds para observar procesos hijos, independientemente de si las fuentes de eventos individuales se asignan a través de sd_event_add_child() o sd_event_add_child_pidfd(). Si se utilizó la última llamada para asignar la fuente de eventos, esta función devuelve el descriptor de archivo original utilizado para la asignación. Esta llamada toma el objeto de la fuente de eventos como parámetro source y devuelve el descriptor de archivo numérico.

sd_event_source_get_child_pidfd_own() puede usarse para consultar si el pidfd que encapsula la fuente de eventos debe cerrarse cuando se libera la fuente de eventos. Esta función devuelve cero si el pidfd debe dejarse abierto y positivo si debe cerrarse automáticamente. Por defecto, esta configuración es activada si la fuente de eventos se asignó mediante sd_event_add_child() y desactivada si se asignó mediante sd_event_add_child_pidfd(). La función sd_event_source_set_child_pidfd_own() puede usarse para cambiar la configuración y toma un parámetro booleano con la nueva configuración.

sd_event_source_get_child_process_own() puede usarse para consultar si el proceso que observa la fuente de eventos debe ser terminado (con SIGKILL) y recolectado cuando se libera la fuente de eventos. Esta función devuelve cero si el proceso debe dejarse en ejecución y positivo si debe ser terminado y recolectado automáticamente. Por defecto, esta configuración está desactivada. La función sd_event_source_set_child_process_own() puede usarse para cambiar la configuración y toma un parámetro booleano con la nueva configuración.

sd_event_source_send_child_signal() puede usarse para enviar una señal al proceso hijo observado. El parámetro sig especifica la señal a enviar, y el parámetro info es un puntero opcional a una estructura siginfo_t que se usará para el envío de la señal. El parámetro flags puede contener 0 o SA_SIGINFO.

En caso de éxito, estas funciones devuelven 0, o un código de error positivo en caso de fallo. Los códigos de error posibles son:

Códigos de error de errno(3)

Los códigos de error devueltos por estas funciones son códigos de error de POSIX. Si un manejador devuelve un código de error negativo, la función de bucle de eventos puede devolver este código de error también (ver sd_event_source_set_exit_on_failure(3)).

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo de estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar un objeto.

-EINVAL

Se ha pasado un argumento no válido. Esto incluye especificar una máscara vacía en options o una máscara que contiene valores diferentes a una combinación de WEXITED, WSTOPPED y WCONTINUED.

-EBUSY

Ya hay un manejador instalado para este proceso hijo, o SIGCHLD no está bloqueado.

-ESTALE

El bucle de eventos ya ha terminado.

-ECHILD

El bucle de eventos se creó en un proceso, biblioteca o instancia de módulo diferente.

-EDOM

La fuente de eventos pasada no es una fuente de eventos de proceso hijo.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

EJEMPLO

Ejemplo 1. Salida del bucle cuando el hijo termina

/* SPDX-License-Identifier: MIT-0 */
#define _GNU_SOURCE 1
#include <assert.h>
#include <stdio.h>
#include <unistd.h>
#include <systemd/sd-event.h>
int main(int argc, char **argv) {
  pid_t pid = fork();
  assert(pid >= 0);
  /* SIGCHLD signal must be blocked for sd_event_add_child to work */
  sigset_t ss;
  sigemptyset(&ss);
  sigaddset(&ss, SIGCHLD);
  sigprocmask(SIG_BLOCK, &ss, NULL);
  if (pid == 0)  /* child */
    sleep(1);
  else {         /* parent */
    sd_event *e = NULL;
    int r;
    /* Create the default event loop */
    sd_event_default(&e);
    assert(e);
    /* We create a floating child event source (attached to 'e').
     * The default handler will be called with 666 as userdata, which
     * will become the exit value of the loop. */
    r = sd_event_add_child(e, NULL, pid, WEXITED, NULL, (void*) 666);
    assert(r >= 0);
    r = sd_event_loop(e);
    assert(r == 666);
    sd_event_unref(e);
  }
  return 0;
}
