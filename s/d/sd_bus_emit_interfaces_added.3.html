DESCRIPCIÓN

sd_bus_emit_signal() es una función de conveniencia para inicializar un objeto de mensaje de bus y emitir la señal D-Bus correspondiente. Combina las funciones sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) en una única llamada a función. sd_bus_emit_signalv() es equivalente a sd_bus_message_append(), excepto que se llama con una "va_list" en lugar de un número variable de argumentos.

sd_bus_emit_signal_to() y sd_bus_emit_signal_tov() son idénticas a sd_bus_emit_signal() y sd_bus_emit_signalv(), excepto que pueden emitir la señal a un único destino. Proporcione destination como NULL para transmitir la señal en difusión.

sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() se utilizan para implementar las señales InterfacesAdded e InterfacesRemoved de la interfaz org.freedesktop.DBus.ObjectManager. Toman una ruta cuyos interfaces han sido modificados como argumento y una lista variable de interfaces que han sido añadidos o eliminados, respectivamente. El último argumento pasado a sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() *debe* ser NULL. Esto permite que ambas funciones determinen de forma segura el número de argumentos de interfaz pasados. sd_bus_emit_interfaces_added_strv() y sd_bus_emit_interfaces_removed_strv() son idénticas a sus contrapartes respectivas pero ambas toman la lista de interfaces como un solo argumento en lugar de un número variable de argumentos.

sd_bus_emit_properties_changed() se utiliza para implementar la señal PropertiesChanged de la interfaz org.freedesktop.DBus.Properties. Toma una ruta de objeto, interfaz y una lista variable de nombres de propiedades como sus argumentos. El último argumento pasado a sd_bus_emit_properties_changed() *debe* ser NULL. Esto permite determinar de forma segura el número de nombres de propiedades pasados. sd_bus_emit_properties_changed_strv() es idéntica a sd_bus_emit_properties_changed() pero toma la lista de nombres de propiedades como un solo argumento en lugar de un número variable de argumentos.

sd_bus_emit_object_added() y sd_bus_emit_object_removed() son funciones de conveniencia para emitir las señales InterfacesAdded o InterfacesRemoved para todos los interfaces registrados en una ruta de objeto específica, respectivamente. Esto incluye cualquier tabla de búsqueda (vtable) de reserva principal si no son anuladas por una tabla de búsqueda (vtable) hija más aplicable. También incluye todos los interfaces D-Bus estándar implementados por el propio sd-bus en cualquier objeto registrado.

Tenga en cuenta que sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() y sd_bus_emit_object_removed() requieren que se haya registrado un gestor de objetos en la ruta de objeto dada o en una de sus rutas de objeto principales usando sd_bus_add_object_manager(3).

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un entero no negativo. En caso de error, devuelven un código de error negativo estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Uno de los parámetros requeridos es NULL o inválido. Se pasó una interfaz D-Bus reservada como parámetro interface.

-ENOPKG

No se puede resolver el bus.

-ECHILD

El bus se creó en un proceso, biblioteca o instancia de módulo diferente.

-ENOMEM

Falló la asignación de memoria.

-ESRCH

Se llamó a una de las funciones sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() o sd_bus_emit_object_removed() en un objeto sin un gestor de objetos registrado en su propia ruta de objeto o en una de sus rutas de objeto principales.

Consulte las páginas del manual de sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) para ver más posibles errores.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que está declarado como no seguro para subprocesos (multi-thread-safe). Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando aún no se han iniciado otros hilos.

DESCRIPTION

These functions construct and emit D-Bus signals to announce changes in the object tree or object properties, or arbitrary signals.

sd_bus_emit_object_added() emits the org.freedesktop.DBus.ObjectManager.InterfacesAdded signal. The signal is emitted on the bus with the given bus object, for the object at the D-Bus path path. The signal is emitted by the service itself, and contains an array of dictionaries, where each dictionary maps an interface name to a dictionary of properties of that interface.

sd_bus_emit_object_removed() emits the org.freedesktop.DBus.ObjectManager.InterfacesRemoved signal. The signal is emitted on the bus with the given bus object, for the object at the D-Bus path path. The signal is emitted by the service itself, and contains an array of interface names.

sd_bus_emit_interfaces_added() emits the org.freedesktop.DBus.ObjectManager.InterfacesAdded signal. The signal is emitted on the bus with the given bus object, for the object at the D-Bus path path. The signal is emitted by the service itself, and contains an array of interface names.

sd_bus_emit_interfaces_removed() emits the org.freedesktop.DBus.ObjectManager.InterfacesRemoved signal. The signal is emitted on the bus with the given bus object, for the object at the D-Bus path path. The signal is emitted by the service itself, and contains an array of interface names.

sd_bus_emit_properties_changed() emits the org.freedesktop.DBus.Properties.PropertiesChanged signal. The signal is emitted on the bus with the given bus object, for the object at the D-Bus path path. The signal is emitted by the service itself, and contains the interface name interface, and a dictionary of properties that have changed. The properties are specified using a printf-style format string fmt and subsequent arguments. See sd_bus_message_append(3) for details on the format string.

sd_bus_emit_properties_changed_strv() is similar to sd_bus_emit_properties_changed(), but takes the properties as a null-terminated array of strings strv.

sd_bus_emit_signal() and sd_bus_emit_signalv() emit an arbitrary D-Bus signal. The signal is emitted on the bus with the given bus object, for the object at the D-Bus path path. The signal belongs to the interface interface and is named name. The signal arguments are specified using a printf-style format string fmt and subsequent arguments (for sd_bus_emit_signal()) or a va_list (for sd_bus_emit_signalv()). The serial number of the emitted signal is not returned.

sd_bus_emit_signal_to() and sd_bus_emit_signal_tov() are similar to sd_bus_emit_signal() and sd_bus_emit_signalv() respectively, but also take a serial number and a sender name as arguments. The serial number is used to identify the signal, and the sender name is the D-Bus name of the service emitting the signal.

These functions are convenience wrappers around sd_bus_message_new_signal(3), sd_bus_message_append(3), and sd_bus_send(3).

RETURN VALUE

On success, these functions return a non-negative integer. On failure, they return a negative errno value.

NOTES

These functions use the default bus connection. For specific bus connections, use the corresponding `sd_bus_message_new_signal_xxx` and `sd_bus_send` functions.

The `sd_bus_emit_properties_changed` and `sd_bus_emit_signal` functions are variadic and require a printf-style format string describing the types of the arguments. See sd_bus_message_append(3) for details.

The interfaces argument for sd_bus_emit_interfaces_added() and sd_bus_emit_interfaces_removed() must be a null-terminated array of strings.

The strv argument for sd_bus_emit_properties_changed_strv() must be a null-terminated array of strings, where each string is a property name and its value, separated by an equals sign (e.g., "PropertyName=PropertyValue").
