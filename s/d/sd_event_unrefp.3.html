Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_EVENT_NEW(3) sd_event_new SD_EVENT_NEW(3)

NOMBRE

sd_event_new, sd_event_default, sd_event_ref, sd_event_unref, sd_event_unrefp, sd_event_get_tid, sd_event - Adquirir y liberar un objeto de bucle de eventos

SINOPSIS

#include <systemd/sd-event.h>
typedef struct sd_event sd_event;

int sd_event_new(sd_event **event);

int sd_event_default(sd_event **event);

sd_event *sd_event_ref(sd_event *event);

sd_event *sd_event_unref(sd_event *event);

void sd_event_unrefp(sd_event **event);

int sd_event_get_tid(sd_event *event, pid_t *ret);

DESCRIPCIÓN

sd_event_new() asigna un nuevo objeto de bucle de eventos. El objeto de bucle de eventos se devuelve en el parámetro event. Después de su uso, libere la referencia devuelta con sd_event_unref(). Cuando la última referencia se libera, el objeto se libera.

sd_event_default() adquiere una referencia al objeto de bucle de eventos predeterminado del hilo que llama, posiblemente asignando un nuevo objeto si aún no se ha asignado ningún objeto de bucle de eventos predeterminado para el hilo. Después de su uso, libere la referencia devuelta con sd_event_unref(). Cuando la última referencia se libera, el bucle de eventos se libera. Si esta función se llama mientras el objeto devuelto por una llamada anterior del mismo hilo todavía está referenciado, se devuelve el mismo objeto, pero la referencia aumenta en uno. Se recomienda utilizar esta llamada en lugar de sd_event_new() para compartir objetos de bucle de eventos entre varios componentes que se distribuyen en el mismo hilo. Todos los hilos tienen exactamente cero o un objeto de bucle de eventos predeterminado asociado, pero nunca más.

Después de asignar un objeto de bucle de eventos, agregue fuentes de eventos a él con sd_event_add_io(3), sd_event_add_time(3), sd_event_add_signal(3), sd_event_add_child(3), sd_event_add_inotify(3), sd_event_add_defer(3), sd_event_add_post(3) o sd_event_add_exit(3), y luego ejecute el bucle de eventos usando sd_event_loop(3).

sd_event_ref() aumenta el contador de referencias del objeto de bucle de eventos especificado en uno.

sd_event_unref() disminuye el contador de referencias del objeto de bucle de eventos especificado en uno. Si el contador llega a cero, el objeto se libera. Tenga en cuenta que se libera independientemente de si es el objeto de bucle de eventos predeterminado para un hilo o no. Esto significa que la asignación de un bucle de eventos con sd_event_default(), luego su liberación, y luego la adquisición de uno nuevo con sd_event_default() dará como resultado dos objetos distintos. Tenga en cuenta que, para liberar un objeto de bucle de eventos, todas las fuentes de eventos restantes del bucle de eventos también deben liberarse, ya que cada una mantiene una referencia a él.

sd_event_unrefp() es similar a sd_event_unref(), pero toma un puntero a un puntero a un objeto sd_event. Esta llamada es útil junto con el Attribute de variable de limpieza de GCC y LLVM[1]. Tenga en cuenta que esta función se define como una función en línea. Use una declaración como la siguiente, para asignar un objeto de bucle de eventos que se liberará automáticamente al salir del bloque de código:

{
        __attribute__((cleanup(sd_event_unrefp))) sd_event *event = NULL;
        int r;
        ...
        r = sd_event_default(&event);
        if (r < 0) {
          errno = -r;
          fprintf(stderr, "Falló la asignación del bucle de eventos: %m\n");
        }
        ...
}

sd_event_ref(), sd_event_unref() y sd_event_unrefp() no realizan ninguna operación si el objeto de bucle de eventos pasado es NULL.

sd_event_get_tid() recupera el identificador del hilo ("TID") con el que está asociado el objeto de bucle de eventos especificado. Esta llamada solo se admite para bucles de eventos asignados con sd_event_default() y devuelve el identificador del hilo del que el bucle de eventos es el bucle de eventos predeterminado. Consulte gettid(2) para obtener más información sobre los identificadores de hilo.

VALOR DE RETORNO

En caso de éxito, sd_event_new(), sd_event_default() y sd_event_get_tid() devuelven 0 o un entero positivo. En caso de error, devuelven un código de error negativo estilo errno. sd_event_ref() siempre devuelve un puntero al objeto de bucle de eventos pasado. sd_event_unref() siempre devuelve NULL.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOMEM

No hay suficiente memoria para asignar el objeto.

-EMFILE

Se ha asignado el número máximo de bucles de eventos.

-ENXIO

Se invocó sd_event_get_tid() en un objeto de bucle de eventos que no fue asignado con sd_event_default().

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que está declarado como no seguro para hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

sd_event_new(), sd_event_default(), sd_event_ref() y sd_event_unref() se agregaron en la versión 213.

sd_event_unrefp() y sd_event_get_tid() se agregaron en la versión 229.

sd_event_unrefp(3) - Manual de Linux

NOMBRE

sd_event_unrefp - Libera una referencia a un objeto de evento, y opcionalmente libera el objeto entero.

SINOPSIS

        #include <systemd/sd-event.h>

        int sd_event_unrefp(sd_event **event);

DESCRIPCIÓN

sd_event_unrefp() se utiliza para liberar una referencia a un objeto sd_event. Los objetos sd_event utilizan un esquema de conteo de referencias. Cada llamada a sd_event_ref(3) incrementa el contador de referencias en uno. Cada llamada a sd_event_unrefp() decrementa el contador de referencias en uno.

Si el contador de referencias cae a cero como resultado de una llamada a sd_event_unrefp(), la memoria del objeto sd_event se libera. El puntero pasado en event se establece a NULL después de la llamada.

Esta función es una forma conveniente de manejar la liberación de recursos, ya que el puntero se establece automáticamente a NULL, evitando así la doble liberación accidental.

VALOR DE RETORNO

Devuelve 0 si la operación fue exitosa. En caso de error, devuelve un código de error negativo.

NOTAS

  • Si el puntero event es NULL o apunta a NULL, la función no hace nada y devuelve 0.
  • Es la forma recomendada de liberar referencias a sd_event cuando se ha pasado el puntero a una función que podría haberlo retenido.

HISTORIA

La función sd_event_unrefp() fue introducida en systemd versión 233.

VER TAMBIÉN

sd_event_new(3), sd_event_ref(3), sd_event_get_fd(3)
