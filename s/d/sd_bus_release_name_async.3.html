sd_bus_release_name_async(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_REQUEST_NAME(3) sd_bus_request_name SD_BUS_REQUEST_NAME(3)

NOMBRE

sd_bus_request_name, sd_bus_request_name_async, sd_bus_release_name, sd_bus_release_name_async - Solicitar o liberar un nombre de servicio bien conocido en un bus

SINOPSIS

#include <systemd/sd-bus.h>

typedef int (*sd_bus_message_handler_t)(sd_bus_message *m, void *userdata, sd_bus_error *ret_error);

int sd_bus_request_name(sd_bus *bus, const char *name, uint64_t flags);

int sd_bus_request_name_async(sd_bus *bus, sd_bus_slot **slot, const char *name, uint64_t flags, sd_bus_message_handler_t callback, void *userdata);

int sd_bus_release_name(sd_bus *bus, const char *name);

int sd_bus_release_name_async(sd_bus *bus, sd_bus_slot **slot, const char *name, sd_bus_message_handler_t callback, void *userdata);

DESCRIPCIÓN

sd_bus_request_name() solicita un nombre de servicio bien conocido en un bus. Toma una conexión de bus, un nombre de bus válido y un parámetro de flags. El parámetro de flags es una combinación de cero o más de los siguientes flags:

SD_BUS_NAME_ALLOW_REPLACEMENT

Después de adquirir el nombre con éxito, permite que otros pares tomen el nombre cuando intenten adquirirlo con el flag SD_BUS_NAME_REPLACE_EXISTING establecido. Si SD_BUS_NAME_ALLOW_REPLACEMENT no está establecido en la solicitud original, dicha solicitud por parte de otros pares será denegada.

Añadido en la versión 209.

SD_BUS_NAME_REPLACE_EXISTING

Toma el nombre si ya fue adquirido por otro par, y ese otro par permitió la toma estableciendo SD_BUS_NAME_ALLOW_REPLACEMENT mientras lo adquiría.

Añadido en la versión 209.

SD_BUS_NAME_QUEUE

Pone en cola la adquisición del nombre cuando el nombre ya está ocupado.

Añadido en la versión 209.

sd_bus_request_name() opera de forma síncrona: se envía un mensaje solicitando el nombre al broker del bus, y la llamada espera hasta que el broker responde.

sd_bus_request_name_async() es una versión asíncrona de sd_bus_request_name(). En lugar de esperar a que la solicitud se complete, el mensaje de solicitud se pone en cola. La función de *callback* especificada será llamada cuando se reciba la respuesta del broker. Si el parámetro se especifica como NULL, se usa una implementación por defecto en su lugar, que terminará la conexión cuando el nombre no pueda ser adquirido. La función devuelve un objeto slot en su parámetro *slot* — si se pasa como no-NULL — que puede ser usado como referencia a la operación de solicitud de nombre. Use sd_bus_slot_unref(3) para destruir esta referencia. Tenga en cuenta que destruir la referencia no anulará el registro del nombre, sino que simplemente asegurará que la función de callback especificada ya no sea llamada.

sd_bus_release_name() libera un nombre bien conocido adquirido. Toma una conexión de bus y un nombre de bus válido como parámetros. Esta función opera de forma síncrona, enviando un mensaje de solicitud de liberación al broker del bus y esperando a que responda.

sd_bus_release_name_async() es una versión asíncrona de sd_bus_release_name(). La función de callback especificada es llamada cuando el nombre ha sido liberado con éxito. Si se especifica como NULL, se utiliza una implementación genérica que ignora el resultado de la operación. Como se mencionó anteriormente, el *slot* (si no es NULL) se establece en un objeto que puede ser utilizado para referenciar la operación.

Estas funciones solo son compatibles con conexiones de bus, es decir, conexiones a un broker de bus y no a conexiones directas.

VALOR DE RETORNO

En caso de éxito, estas llamadas devuelven 0 o un entero positivo. En caso de error, estas llamadas devuelven un código de error negativo estilo errno.

Si se especifica SD_BUS_NAME_QUEUE, sd_bus_request_name() devolverá 0 cuando el nombre ya está ocupado por otro par y el cliente ha sido añadido a la cola para el nombre. En ese caso, el llamador puede suscribirse a señales "NameOwnerChanged" para ser notificado cuando el nombre sea adquirido con éxito. sd_bus_request_name() devuelve > 0 cuando el nombre ha sido adquirido inmediatamente con éxito.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EALREADY

El llamador ya es el propietario del nombre especificado.

-EEXIST

El nombre ya ha sido adquirido por un par diferente, y no se especificó SD_BUS_NAME_REPLACE_EXISTING o el otro par no especificó SD_BUS_NAME_ALLOW_REPLACEMENT mientras adquiría el nombre.

-ESRCH

Se intentó liberar un nombre que actualmente no está registrado en el bus.

-EADDRINUSE

Se intentó liberar un nombre que pertenece a un par diferente en el bus.

-EINVAL

Un parámetro especificado es inválido. Esto también se genera cuando el nombre solicitado es un nombre de servicio especial reservado por la especificación D-Bus, o cuando la operación se solicita en una conexión que no se refiere a un bus.

-ENOTCONN

La conexión del bus se ha desconectado.

-ECHILD

La conexión del bus se creó en un proceso diferente al actual.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd de pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara no ser seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer las llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

sd_bus_request_name() y sd_bus_release_name() se añadieron en la versión 209.

sd_bus_request_name_async() y sd_bus_release_name_async() se añadieron en la versión 237.
