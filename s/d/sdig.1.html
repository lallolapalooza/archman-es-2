SDIG(1) Servidor Autoritativo de PowerDNS SDIG(1)

NOMBRE

sdig - Realiza una consulta DNS y muestra los resultados

SINOPSIS

sdig DIRECCION-IP-O-URL-DOH PUERTO NOMBRE-CONSULTA TIPO-CONSULTA [OPCION]

DESCRIPCIÓN

sdig envía una consulta DNS a DIRECCION-IP-O-URL-DOH en el puerto PUERTO y muestra la respuesta de forma formateada. Si la dirección comienza con h, se asume que es un punto final DoH, y se ignora el PUERTO. Si nombre-consulta y tipo-consulta son ambos - y se usa tcp, se leen múltiples líneas desde la entrada estándar, donde cada línea contiene un nombre-consulta y un tipo. Si la dirección es stdin, se lee un paquete DNS desde la entrada estándar en lugar de la red, y se ignora el PUERTO. Toda la entrada es literal y sensible a mayúsculas y minúsculas. Las consultas necesitan la opción recurse para esperar una respuesta de registro de recursos si no se sabe que el servidor de consulta es el servidor autoritativo para ese registro.

OPCIONES

Estas opciones se pueden añadir a la línea de comandos en cualquier orden.

clase NUMCLASE
Envía la consulta en la clase numerada (como 3 para CHAOS) en lugar de la 1 (para IN) por defecto.
dnssec
Establece el bit DO para solicitar información DNSSEC.
ednssubnet SUBRED
Envía SUBRED en la opción edns-client-subnet. Si esta opción no está establecida, no se establece ninguna opción edns-client-subnet en la consulta.
ocultarsoadetalles
No muestra el serial SOA en la respuesta.
ocultarttl
Reemplaza los TTL con [ttl] en la respuesta.
proxy TCP? SRC DST
Envuelve la consulta con el protocolo PROXYv2 con estos parámetros. El primer parámetro acepta 0 para UDP y 1 para TCP. El segundo y el tercero toman direcciones IP y puerto.
recurse
Establece el bit RD en la pregunta.
mostrarcambios
Muestra los flags NSEC3 en la respuesta (están ocultos por defecto).
volcarluaraw
Muestra el contenido de los registros en un formato adecuado para SpoofRawAction de dnsdist.
tcp
Usa TCP en lugar de UDP para enviar la consulta.
dot
Usa DoT en lugar de UDP para enviar una consulta. Implica tcp.
inseguro
Al usar DoT, no valida el certificado del servidor.
fastOpen
Al usar TCP o DoT, habilita TCP Fast Open.
nombreSubjecto nombre
Al usar DoT, verifica que el certificado del servidor esté emitido para nombre. El proveedor openssl aceptará un nombre vacío y aun así se asegurará de que el certificado sea emitido por una CA de confianza, gnutls solo realizará la validación si se proporciona un nombre. El valor por defecto es el nombre vacío. Además, ten en cuenta que las bibliotecas de proveedores más antiguas podrían no validar en absoluto.
almacenCA archivo
Al usar DoT, lee los certificados de CA de confianza de archivo. El valor por defecto es usar el almacén de CA proporcionado por el sistema.
proveedorTLS nombre
Al usar DoT, utiliza el proveedor TLS nombre. Actualmente soportados (si se compilan): openssl y gnutls. El valor por defecto es openssl si está disponible.
opcode NUMOP
Usa el opcode NUMOP en lugar de 0 (Query). Por ejemplo, sdig 192.0.2.1 53 example.com SOA opcode 4 envía una notificación NOTIFY.
cookie COOKIE
si COOKIE es - envía una cookie de cliente aleatoria. De lo contrario, envía la cookie dada, que debe ser una cadena hexadecimal recibida de un servidor anteriormente.
traceid TraceID
incluye un TraceID y un valor SpanID vacío en los datos EDNS. Si TraceID es -, se genera un TraceID aleatorio; de lo contrario, es una cadena hexadecimal.

EJEMPLOS

Consultas simples a resolutores locales
sdig 127.0.0.1 53 example.com AAAA recurse

sdig ::1 53 example.com A recurse

Consulta a un servidor DNS-over-HTTPS solicitando dnssec y recursión
sdig https://dns.example.net/dns-query 443 example.com A dnssec recurse
