DESCRIPCIÓN

La estructura sd_bus_error transporta información sobre una condición de error de D-Bus, o la ausencia de ella. Las funciones descritas a continuación pueden usarse para establecer y consultar campos en esta estructura.

•El campo name contiene un identificador corto de un error. Debería seguir las reglas para nombres de error descritas en la especificación de D-Bus, subsección Nombres Válidos de D-Bus[1]. Varios nombres de error comunes y estandarizados se describen en sd-bus-errors(3), pero las aplicaciones pueden definir errores adicionales específicos del dominio.
•El campo message generalmente contiene una cadena legible por humanos que describe los detalles, pero podría ser NULL.

Una estructura sd_bus_error no establecida debe tener ambos campos inicializados a NULL y significa ausencia de error, es decir, éxito. Asigne SD_BUS_ERROR_NULL a la estructura para inicializar ambos campos a NULL. Cuando ya no sean necesarios, los recursos mantenidos por la estructura sd_bus_error deben ser destruidos con sd_bus_error_free().

sd_bus_error_set() establece una estructura de error a los nombres y mensajes especificados. Las cadenas se copiarán en memoria interna recién asignada. Es esencial liberar el contenido nuevamente cuando ya no se necesiten (ver arriba). No use esta llamada en estructuras de error que ya hayan sido establecidas. Si tiene la intención de reutilizar una estructura de error, libere los datos antiguos almacenados en ella con sd_bus_error_free() primero.

sd_bus_error_set() devolverá un valor similar a errno (ver errno(3)) determinado por el nombre de error especificado name. Si name es NULL, se asume que no ocurrió ningún error y se devuelve 0. Si name no es nulo, siempre se devuelve un valor negativo. Si e es NULL, no se inicializa ninguna estructura de error, pero name aún se convierte en un valor estilo errno.

Varios errores de D-Bus bien conocidos se convierten en sus homólogos errno bien conocidos, y los otros a -EIO. Vea sd-bus-errors(3) para una lista de nombres de error bien conocidos. Se pueden definir mapeos de error adicionales con sd_bus_error_add_map(3).

sd_bus_error_set() está diseñado para ser utilizado convenientemente en una sentencia return. Si message es NULL, no se establece ningún mensaje. Esta llamada puede fallar si no se puede asignar memoria para las cadenas de nombre y mensaje, en cuyo caso se establecerá un error SD_BUS_ERROR_NO_MEMORY en su lugar y se devolverá -ENOMEM.

sd_bus_error_setf() y sd_bus_error_setfv() son similares a sd_bus_error_set(), pero toman una cadena de formato printf(3) y argumentos correspondientes para generar el campo message. sd_bus_error_setf() usa argumentos variádicos, y sd_bus_error_setfv() acepta los argumentos como una lista de parámetros va_arg(3).

sd_bus_error_set_const() es similar a sd_bus_error_set(), pero los parámetros de cadena no se copian internamente y, por lo tanto, deben permanecer constantes y válidos durante la vida útil de e. Use esta llamada para evitar asignaciones de memoria al establecer estructuras de error. Dado que esta llamada no asigna memoria, no fallará con una condición de falta de memoria como puede hacerlo sd_bus_error_set(), como se describió anteriormente. Alternativamente, la macro SD_BUS_ERROR_MAKE_CONST() puede usarse para generar una estructura de error literal y constante sobre la marcha.

sd_bus_error_set_errno() devolverá inmediatamente 0 si el parámetro de error especificado error es 0. De lo contrario, establecerá name a partir de un valor similar a errno que se convierte a un error D-Bus. Se usará strerror_r(3) para establecer message. Se utilizarán nombres de error D-Bus bien conocidos para name si es aplicable, de lo contrario se generará un nombre en el espacio de nombres "System.Error.". El signo del número de error especificado se ignora y se usa implícitamente su valor absoluto. Si el error especificado error no es cero, la llamada siempre devuelve un valor negativo, para un uso conveniente en sentencias return. Esta llamada puede fallar debido a falta de memoria, en cuyo caso se establece un error SD_BUS_ERROR_NO_MEMORY en su lugar, y se devuelve -ENOMEM.

sd_bus_error_set_errnof() y sd_bus_error_set_errnof() son similares a sd_bus_error_set_errno(), pero además de error, toman una cadena de formato printf(3) y argumentos correspondientes. El campo message se generará a partir de format y los argumentos. sd_bus_error_set_errnof() usa argumentos variádicos, y sd_bus_error_set_errnofv() acepta los argumentos como una lista de parámetros va_arg(3).

sd_bus_error_get_errno() convierte el campo name de una estructura de error a un valor similar a errno (positivo) usando las mismas reglas que sd_bus_error_set(). Si e es NULL, se devolverá 0.

sd_bus_error_copy() inicializará dst utilizando los valores de e, si e ha sido establecido previamente con un valor de error. De lo contrario, regresará inmediatamente. Si las cadenas en e fueron establecidas usando sd_bus_error_set_const(), se compartirán. De lo contrario, se copiarán. Antes de esta llamada, dst debe estar sin establecer, es decir, recién inicializado con NULL o restablecido usando sd_bus_error_free().

sd_bus_error_copy() generalmente devuelve 0 o un valor negativo similar a errno basado en el parámetro de entrada e: 0 si no estaba establecido y un entero negativo si estaba establecido a algún error, de manera similar a sd_bus_error_set(). Sin embargo, también puede devolver un error generado internamente.

sd_bus_error_move() es similar a sd_bus_error_copy(), pero en lugar de copiar los valores de e, los moverá. Después de esta llamada, e quedará sin establecer y debe ser tratado como si fuera nuevo.

sd_bus_error_is_set() devuelve verdadero si la estructura de error e está establecida, es decir, si tanto name como message no son NULL, o si solo name no es NULL.

sd_bus_error_has_name() devuelve verdadero si el campo name de la estructura e coincide exactamente con el nombre especificado name.

sd_bus_error_has_names_sentinel() y la macro sd_bus_error_has_names() devuelven verdadero si el campo name de la estructura e coincide con cualquiera de los nombres de error especificados en la lista variádica. La lista debe terminar con un puntero NULL. Esta función se utiliza principalmente para la comprobación de múltiples nombres de error de forma concisa.

Si e es NULL, todas estas funciones devuelven falso (o 0).

Para obtener la lista de todos los errores bien conocidos y sus significados, consulte sd-bus-errors(3).

VALOR DE RETORNO

Las funciones de establecimiento de errores devuelven 0 en caso de éxito, o un valor negativo de tipo errno en caso de fallo. sd_bus_error_set(), sd_bus_error_set_errno() y sus variantes devuelven un valor negativo de tipo errno si se estableció un error (es decir, si name o error no fueron NULL o 0 respectivamente). Si no se estableció ningún error (es decir, si name o error fueron NULL o 0), devuelven 0.

Las funciones de consulta (como sd_bus_error_get_errno(), sd_bus_error_is_set(), etc.) devuelven un valor diferente de cero si la condición es verdadera, y 0 en caso contrario. sd_bus_error_get_errno() devuelve un valor positivo similar a errno.

Por ejemplo, -ENOMEM si una asignación de memoria falla.

sd_bus_error_move() es similar a sd_bus_error_copy(), pero moverá cualquier información de error de e a dst, reiniciando la anterior. Esta función no puede fallar, ya que no se asigna nueva memoria. Tenga en cuenta que si e no está configurado, dst se inicializa a SD_BUS_ERROR_NULL. Además, si dst es NULL, no se realiza ninguna operación sobre él y los recursos mantenidos por e se liberan y reinician. Devuelve un valor de error similar a errno, no positivo.

sd_bus_error_is_set() devolverá un valor distinto de cero si e no es NULL y se ha establecido un error, false en caso contrario.

sd_bus_error_has_name() devolverá un valor distinto de cero si e no es NULL y se ha establecido un error con el mismo name, false en caso contrario.

sd_bus_error_has_names_sentinel() es similar a sd_bus_error_has_name(), pero toma múltiples nombres para verificar. La lista debe terminar con NULL. sd_bus_error_has_names() es un envoltorio macro alrededor de sd_bus_error_has_names_sentinel() que agrega el terminador NULL automáticamente.

sd_bus_error_free() destruirá los recursos mantenidos por e. El parámetro en sí no se liberará y debe ser free(3) por el llamador si es necesario. La función también puede llamarse de forma segura en errores no establecidos (estructuras de error con ambos campos establecidos a NULL), en cuyo caso no realiza ninguna operación. Esta llamada reiniciará la estructura de error después de liberar los datos, de modo que todos los campos se establezcan a NULL. La estructura puede reutilizarse posteriormente.

PROPIEDAD DE REFERENCIA

sd_bus_error no tiene conteo de referencias. Los usuarios deben destruir los recursos mantenidos por él llamando a sd_bus_error_free(). Normalmente, las estructuras de error se asignan en la pila o se pasan como parámetros de función, pero también pueden asignarse dinámicamente, en cuyo caso es deber del llamador free(3) la memoria mantenida por la propia estructura después de liberar su contenido con sd_bus_error_free().

VALOR DE RETORNO

Las funciones sd_bus_error_set(), sd_bus_error_setf() y sd_bus_error_set_const() siempre devuelven 0 cuando el valor de error especificado es NULL, y un valor negativo similar a errno correspondiente al parámetro name en caso contrario. Las funciones sd_bus_error_set_errno(), sd_bus_error_set_errnof() y sd_bus_error_set_errnofv(), devuelven 0 cuando el valor de error especificado es 0, y un valor negativo similar a errno correspondiente al parámetro error en caso contrario. Si ocurre un error internamente, se devolverá uno de los valores de error negativos enumerados a continuación. Esto permite que estas funciones se utilicen cómodamente en una instrucción return, vea el ejemplo a continuación.

sd_bus_error_get_errno() devuelve false cuando e es NULL, y un valor errno positivo mapeado desde e->name en caso contrario.

sd_bus_error_copy() y sd_bus_error_move() devuelven un valor de error negativo convertido del error de origen, y cero si el error no se ha establecido. Esto permite que estas funciones se utilicen convenientemente en una instrucción return, vea el ejemplo a continuación.

sd_bus_error_is_set() devuelve un valor distinto de cero cuando e y el campo name no son NULL, cero en caso contrario.

sd_bus_error_has_name(), sd_bus_error_has_names() y sd_bus_error_has_names_sentinel() devuelven un valor distinto de cero cuando e no es NULL y el campo name es igual a uno de los nombres dados, cero en caso contrario.

Errores

El valor de retorno puede indicar los siguientes problemas en la invocación de la propia función:

-EINVAL

El error ya estaba establecido en la estructura sd_bus_error cuando se llamó a una de las funciones de establecimiento de errores.

-ENOMEM

Fallo en la asignación de memoria.

En caso de éxito, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy() y sd_bus_error_move() devolverán un valor negativo convertido de estilo errno, o 0 si el parámetro de error es NULL o no establecido. Los errores de D-Bus se convierten en un valor integral de estilo errno, y el mecanismo de mapeo es extensible, vea la discusión anterior. Esto significa efectivamente que casi cualquier valor negativo de estilo errno puede ser devuelto.

EJEMPLOS

Ejemplo 1. Uso del valor de retorno negativo para propagar un error

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "¡Hola, Mundo!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* En caso de éxito, devuelve el número de bytes escritos, posiblemente 0. */
  /* En caso de error, inicializa la estructura de error y también propaga el valor de errno
   * que write(2) estableció para nosotros. */
  return sd_bus_error_set_errnof(error, errno, "No se pudo escribir en el fd %i: %s", fd, strerror(errno));
}

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar solo llamadas a setenv() desde una fase temprana del programa cuando aún no se han iniciado otros hilos.
