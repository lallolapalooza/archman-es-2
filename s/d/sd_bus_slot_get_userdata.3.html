sd_bus_slot_get_userdata(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_SLOT_SET_USERDATA(3) sd_bus_slot_set_userdata SD_BUS_SLOT_SET_USERDATA(3)

NOMBRE

sd_bus_slot_set_userdata, sd_bus_slot_get_userdata - Establecer y consultar el valor en el campo "userdata"

SINOPSIS

#include <systemd/sd-bus.h>

void* sd_bus_slot_set_userdata(sd_bus_slot* slot, void* userdata);

void* sd_bus_slot_get_userdata(sd_bus_slot* slot);

DESCRIPCIÓN

El puntero userdata permite pasar datos entre el punto donde se registra una función de retorno de llamada, por ejemplo, cuando se añade un filtro usando sd_bus_add_filter(3) o se realiza una llamada a una función asíncrona usando sd_bus_call_async(3), y el punto donde se llama a la función de retorno de llamada, sin tener ningún estado global. El puntero tiene el tipo void* y no es utilizado por las funciones de sd-bus de ninguna manera, excepto para pasarlo a la función de retorno de llamada.

Normalmente, el campo userdata se establece cuando el objeto slot se registra inicialmente. sd_bus_slot_set_userdata() se puede utilizar para cambiarlo más tarde para el objeto slot slot. Se devuelve el valor anterior del campo. El argumento y el valor devuelto pueden ser NULL. Se pasará como argumento userdata a la función de retorno de llamada adjunta al slot.

sd_bus_slot_get_userdata() obtiene el valor del campo userdata en el objeto slot slot.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven el valor del campo userdata antes de la llamada a la función. Si el objeto slot es NULL, se devolverá NULL para indicar un error, pero esto no se puede distinguir del valor del campo userdata que es NULL.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar y enlazar con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para múltiples hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer solo llamadas a setenv() desde una fase temprana del programa cuando aún no se han iniciado otros hilos.

HISTORIAL

sd_bus_slot_set_userdata() y sd_bus_slot_get_userdata() se añadieron en la versión 240.
