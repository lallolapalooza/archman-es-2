DESCRIPCIÓN

Estas funciones devuelven información de credenciales de un objeto sd_bus_creds. Los objetos de credenciales se pueden crear con sd_bus_creds_new_from_pid(3), en cuyo caso describen las credenciales del proceso identificado por el PID especificado, con sd_bus_get_name_creds(3), en cuyo caso describen las credenciales de un par del bus identificado por el nombre de bus especificado, con sd_bus_get_owner_creds(3), en cuyo caso describen las credenciales del creador de un bus, o con sd_bus_message_get_creds(3), en cuyo caso describen las credenciales del remitente del mensaje.

No todos los campos de credenciales forman parte de cada objeto "sd_bus_creds". Utilice sd_bus_creds_get_mask(3) para determinar la máscara de campos disponibles.

sd_bus_creds_get_pid() recuperará el PID (identificador de proceso). De manera similar, sd_bus_creds_get_ppid() recuperará el PID padre. Tenga en cuenta que el PID 1 no tiene proceso padre, en cuyo caso se devuelve -ENXIO.

sd_bus_creds_get_pidfd_dup() recuperará el descriptor de archivo PID (pidfd), vea pidfd_open(2) para más detalles. El descriptor de archivo se duplica y, por lo tanto, debe ser cerrado por el llamador.

sd_bus_creds_get_tid() recuperará el TID (identificador de hilo).

sd_bus_creds_get_uid() recuperará el UID numérico (identificador de usuario). De manera similar, sd_bus_creds_get_euid() devuelve el UID efectivo, sd_bus_creds_get_suid() el UID guardado y sd_bus_creds_get_fsuid() el UID del sistema de archivos.

sd_bus_creds_get_gid() recuperará el GID numérico (identificador de grupo). De manera similar, sd_bus_creds_get_egid() devuelve el GID efectivo, sd_bus_creds_get_sgid() el GID guardado y sd_bus_creds_get_fsgid() el GID del sistema de archivos.

sd_bus_creds_get_supplementary_gids() recuperará la lista de GIDs suplementarios.

sd_bus_creds_get_comm() recuperará el campo comm (nombre truncado del ejecutable, tal como se almacena en /proc/pid/comm).

sd_bus_creds_get_tid_comm() recuperará el campo comm del hilo (tal como se almacena en /proc/pid/task/tid/comm).

sd_bus_creds_get_exe() recuperará la ruta al ejecutable del programa (tal como se almacena en el enlace /proc/pid/exe, pero con el sufijo " (eliminado)" eliminado). Tenga en cuenta que los hilos del kernel no tienen una ruta ejecutable, en cuyo caso se devuelve -ENXIO. Tenga en cuenta que esta propiedad no debe usarse para más que información explicativa, en particular no debe usarse para decisiones relevantes para la seguridad. Esto se debe a que el ejecutable podría haber sido reemplazado o eliminado para cuando el valor pueda ser procesado. DESCRIPTION

These functions retrieve various pieces of information about the credentials of a process or a D-Bus peer. The c parameter is a pointer to an sd_bus_creds(3) object, which should have been created with sd_bus_creds_new_from_pid(3), sd_bus_creds_new_from_peer(3), or sd_bus_message_get_creds(3).

The following functions retrieve numeric identifiers:

sd_bus_creds_get_pid()
Retrieves the process ID.
sd_bus_creds_get_tid()
Retrieves the thread ID. This is usually the same as the process ID, except for multi-threaded processes.
sd_bus_creds_get_ppid()
Retrieves the parent process ID.
sd_bus_creds_get_uid()
Retrieves the real user ID.
sd_bus_creds_get_euid()
Retrieves the effective user ID.
sd_bus_creds_get_suid()
Retrieves the saved set-user-ID.
sd_bus_creds_get_fsuid()
Retrieves the effective file system user ID. On some architectures, this is the same as the effective user ID.
sd_bus_creds_get_gid()
Retrieves the real group ID.
sd_bus_creds_get_egid()
Retrieves the effective group ID.
sd_bus_creds_get_sgid()
Retrieves the saved set-group-ID.
sd_bus_creds_get_fsgid()
Retrieves the effective file system group ID. On some architectures, this is the same as the effective group ID.
sd_bus_creds_get_supplementary_gids()
Retrieves the array of supplementary group IDs. The array is NULL-terminated.
sd_bus_creds_get_audit_session_id()
Retrieves the audit session identifier. Returns -ENXIO for processes that are not part of an audit session.
sd_bus_creds_get_audit_login_uid()
Retrieves the audit login identifier (the identifier of the user who is "responsible" for the session). Returns -ENXIO for processes that are not part of an audit session.
sd_bus_creds_get_pidfd_dup()
Retrieves a duplicate file descriptor referring to the process specified by the credentials. This is useful for various kernel operations that require a pidfd, and is an alternative to using the process's PID directly, which might be recycled.

The following functions retrieve string information:

sd_bus_creds_get_comm()
Retrieves the command name of the process (as stored in /proc/pid/comm). This is typically the first 15 characters of the command line, but may be truncated.
sd_bus_creds_get_tid_comm()
Retrieves the command name of the thread (as stored in /proc/pid/task/tid/comm). This is typically the first 15 characters of the command line, but may be truncated.
sd_bus_creds_get_exe()
Retrieves the absolute path to the executable. Note that kernel threads do not have an executable path, in which case -ENXIO is returned.
sd_bus_creds_get_cmdline()
Will retrieve an array of command line arguments (as stored in /proc/pid/cmdline). Note that kernel threads do not have a command line, in which case -ENXIO is returned.
sd_bus_creds_get_cgroup()
Will retrieve the control group path. See Control Groups v2[1].
sd_bus_creds_get_unit()
Will retrieve the systemd unit name (in the system instance of systemd) that the process is a part of. See systemd.unit(5). For processes that are not part of a unit, returns -ENXIO.
sd_bus_creds_get_user_unit()
Will retrieve the systemd unit name (in the user instance of systemd) that the process is a part of. See systemd.unit(5). For processes that are not part of a user unit, returns -ENXIO.
sd_bus_creds_get_slice()
Will retrieve the systemd slice (a unit in the system instance of systemd) that the process is a part of. See systemd.slice(5). Similarly, sd_bus_creds_get_user_slice() retrieves the systemd slice of the process, in the user instance of systemd.
sd_bus_creds_get_session()
Will retrieve the identifier of the login session that the process is a part of. Please note the login session may be limited to a stub process or two. User processes may instead be started from their systemd user manager, e.g. GUI applications started using DBus activation, as well as service processes which are shared between multiple logins of the same user. For processes that are not part of a session, returns -ENXIO.
sd_bus_creds_get_owner_uid()
Will retrieve the numeric UID (user identifier) of the user who owns the user unit or login session that the process is a part of. See systemd-logind.service(8). For processes that are not part of a user unit or session, returns -ENXIO.
sd_bus_creds_has_effective_cap()
Will check whether the capability specified by capability was set in the effective capabilities mask. A positive return value means that it was set, zero means that it was not set, and a negative return value indicates an error. See capabilities(7) and the AmbientCapabilities= and CapabilityBoundingSet= settings in systemd.exec(5).
sd_bus_creds_has_permitted_cap()
Is similar to sd_bus_creds_has_effective_cap(), but will check the permitted capabilities mask.
sd_bus_creds_has_inheritable_cap()
Is similar to sd_bus_creds_has_effective_cap(), but will check the inheritable capabilities mask.
sd_bus_creds_has_bounding_cap()
Is similar to sd_bus_creds_has_effective_cap(), but will check the bounding capabilities mask.
sd_bus_creds_get_selinux_context()
Will retrieve the SELinux security context (label) of the process.
sd_bus_creds_get_tty()
Will retrieve the controlling TTY, without the prefixing "/dev/". Returns -ENXIO for processes that have no controlling TTY.
sd_bus_creds_get_unique_name()
Will retrieve the D-Bus unique name. See The D-Bus specification[2].
sd_bus_creds_get_well_known_names()
Will retrieve the set of D-Bus well-known names. See The D-Bus specification[2].
sd_bus_creds_get_description()
Will retrieve a descriptive name of the bus connection of the peer. This name is useful to discern multiple bus connections by the same peer, and may be altered by the peer with the sd_bus_set_description(3) call.

All functions that take a const char** parameter will store the answer there as an address of a NUL-terminated string. It will be valid as long as c remains valid, and should not be freed or modified by the caller.

All functions that take a char*** parameter will store the answer there as an address of an array of strings. Each individual string is NUL-terminated, and the array is NULL-terminated as a whole. It will be valid as long as c remains valid, and should not be freed or modified by the caller.

RETURN VALUE

On success, these calls return 0 or a positive integer. On failure, these calls return a negative errno-style error code.

Errors

Returned errors may indicate the following problems:

-ENODATA

The given field is not available in the credentials object c.

-ENXIO

The given field is not specified for the described process or peer. This will be returned by sd_bus_creds_get_unit(), sd_bus_creds_get_slice(), sd_bus_creds_get_user_unit(), sd_bus_creds_get_user_slice(), and sd_bus_creds_get_session() if the process is not part of a systemd system unit, systemd user unit, systemd slice, or logind session. It will be returned by sd_bus_creds_get_owner_uid() if the process is not part of a systemd user unit or logind session. It will also be returned by sd_bus_creds_get_exe() and sd_bus_creds_get_cmdline() for kernel threads (since these are not started from an executable binary, nor have a command line), and by sd_bus_creds_get_audit_session_id() and sd_bus_creds_get_audit_login_uid() when the process is not part of an audit session, and sd_bus_creds_get_tty() if the process has no controlling TTY.

-EINVAL

Specified pointer parameter is NULL.

-ENOMEM

Memory allocation failed.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.

sd_bus_creds_has_permitted_cap(3)

sd_bus_creds_has_permitted_cap

sd_bus_creds_has_permitted_cap - Comprueba si un conjunto de credenciales de bus tiene un CAP específico permitido.

SINTAXIS

#include <systemd/sd-bus.h>
int sd_bus_creds_has_permitted_cap(sd_bus_creds *creds, int cap);

DESCRIPCIÓN

La función sd_bus_creds_has_permitted_cap() comprueba si el conjunto de credenciales del bus especificado por creds tiene permitido el CAP especificado por cap. El valor de cap debe ser uno de los valores de la familia CAP_*. Ver CAP_TO_INDEX(3) y capabilities(7) para más detalles.

Si las credenciales tienen permitido el CAP, la función devuelve un valor positivo. Si el CAP no está permitido, devuelve 0. Si ocurre un error, devuelve un valor negativo.

VALOR DE RETORNO

Devuelve un valor positivo si el CAP está permitido, 0 si no lo está, y un valor negativo en caso de error.

EJEMPLO

#include <stdio.h>
#include <systemd/sd-bus.h>

int main(int argc, char *argv[]) {
    sd_bus_creds *creds = NULL;
    int r;

    r = sd_bus_creds_new_pid(getpid(), true, &creds);
    if (r < 0) {
        fprintf(stderr, "Failed to obtain credentials for PID %d: %s\n", getpid(), strerror(-r));
        return 1;
    }

    r = sd_bus_creds_has_permitted_cap(creds, CAP_NET_RAW);
    if (r < 0) {
        fprintf(stderr, "Failed to check capabilities: %s\n", strerror(-r));
    } else if (r > 0) {
        printf("PID %d has CAP_NET_RAW permitted.\n", getpid());
    } else {
        printf("PID %d does not have CAP_NET_RAW permitted.\n", getpid());
    }

    sd_bus_creds_unref(creds);
    return 0;
}

VER TAMBIÉN

sd_bus_creds_new_pid(3), sd_bus_creds_unref(3), capabilities(7)

NOTAS

Las capacidades son un mecanismo de Linux para granularizar los privilegios de root. Un proceso puede tener tres conjuntos de capacidades: Permitted (Permitido), Effective (Efectivo) e Inheritable (Heredable). La función sd_bus_creds_has_permitted_cap() comprueba el conjunto Permitted.

Se necesita la cabecera <systemd/sd-bus.h> para usar esta función.
