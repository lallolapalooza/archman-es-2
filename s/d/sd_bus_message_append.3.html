sd_bus_message_append(3)

Paquete: systemd-libs

Licencias: LGPL-2.1-or-later, CC0-1.0, GPL-2.0-or-later WITH Linux-syscall-note

SD_BUS_MESSAGE_APPEND(3) sd_bus_message_append SD_BUS_MESSAGE_APPEND(3)

NOMBRE

sd_bus_message_append, sd_bus_message_appendv - Adjuntar campos a un mensaje D-Bus basándose en una cadena de tipos

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_message_append(sd_bus_message *m, const char *types, ...);

int sd_bus_message_appendv(sd_bus_message *m, const char *types, va_list ap);

DESCRIPCIÓN

La función sd_bus_message_append() adjunta una secuencia de campos al objeto de mensaje D-Bus m. La cadena de tipos types describe los tipos de los argumentos de campo que siguen. Por cada tipo especificado en la cadena de tipos, se deben proporcionar uno o más argumentos, en el mismo orden en que se declaran en la cadena de tipos.

La cadena de tipos se compone de los elementos que se muestran en la siguiente tabla. Contiene cero o más "tipos completos" individuales. Cada tipo completo puede ser uno de los tipos básicos o un tipo contenedor completamente descrito. Un tipo contenedor puede ser una estructura con los tipos contenidos, una variante, una matriz con su tipo de elemento, o una entrada de diccionario con los tipos contenidos. La cadena de tipos termina en NUL.

En caso de un tipo básico, se espera un argumento del tipo correspondiente.

Una estructura se denota por una secuencia de tipos completos entre "(" y ")". Esta secuencia no puede estar vacía; debe contener al menos un tipo. Los argumentos correspondientes a esta secuencia anidada siguen las mismas reglas que si no estuvieran anidados.

Una variante se denota por "v". Los argumentos correspondientes deben comenzar con una cadena de tipos que denote un tipo completo, y después de eso, los argumentos correspondientes al tipo especificado.

Una matriz se denota por "a" seguido de un tipo completo. Los argumentos correspondientes deben comenzar con el número de elementos en la matriz, seguido de los elementos mismos, coincidiendo con el tipo de elemento de la matriz.

Un diccionario es una matriz de entradas de diccionario, denotado por "a" seguido de un par de tipos completos entre "{" y "}". El primero de esos tipos debe ser un tipo básico. Los argumentos correspondientes deben comenzar con el número de entradas de diccionario, seguido de un par de valores para cada entrada que coincida con el tipo de elemento de las entradas del diccionario.

sd_bus_message_appendv() es equivalente a sd_bus_message_append(), excepto que se llama con una "va_list" en lugar de un número variable de argumentos. Esta función no llama a la macro va_end(). Debido a que invoca a la macro va_arg(), el valor de ap no está definido después de la llamada.

Para más detalles sobre el sistema de tipos D-Bus, consulte la Especificación D-Bus[1].

"h" SD_BUS_TYPE_UNIX_FD descriptor de archivo UNIX 4 bytes int
"a" SD_BUS_TYPE_ARRAY matriz determinado por el tipo y tamaño de la matriz int, seguido del contenido de la matriz
"v" SD_BUS_TYPE_VARIANT variante determinado por el argumento de tipo cadena de firma, seguido del contenido de la variante

"}" SD_BUS_TYPE_DICT_ENTRY_END fin de entrada de diccionario

Para los tipos
"s" y "g" (cadena unicode o firma), el puntero puede ser NULL, lo que equivale a una cadena vacía. Para "h" (descriptor de archivo UNIX), el descriptor es duplicado por esta llamada y el descriptor pasado permanece en posesión del llamador. Consulte sd_bus_message_append_basic(3) para la interpretación precisa de esos y otros tipos.

GRAMÁTICA DE LA CADENA DE TIPOS

tipos ::= tipo_completo*
tipo_completo ::= tipo_basico | variante | estructura | matriz | diccionario
tipo_basico ::= "y" | "n" | "q" | "u" | "i" | "x" | "t" | "d" |
               "b" | "h" |
               "s" | "o" | "g"
variante ::= "v"
estructura ::= "(" tipo_completo+ ")"
matriz ::= "a" tipo_completo
diccionario ::= "a" "{" tipo_basico tipo_completo "}"

EJEMPLOS

Adjuntar un único tipo básico (la cadena "una cadena"):

sd_bus_message *m;
...
sd_bus_message_append(m, "s", "una cadena");

Adjuntar todos los tipos de enteros:

uint8_t y = 1;
int16_t n = 2;
uint16_t q = 3;
int32_t i = 4;
uint32_t u = 5;
int32_t x = 6;
uint32_t t = 7;
double d = 8.0;
sd_bus_message_append(m, "ynqiuxtd", y, n, q, i, u, x, t, d);

Adjuntar una estructura compuesta por una cadena y una ruta de D-Bus:

sd_bus_message_append(m, "(so)", "una cadena", "/una/ruta");

Adjuntar una matriz de descriptores de archivo UNIX:

sd_bus_message_append(m, "ah", 3, STDIN_FILENO, STDOUT_FILENO, STDERR_FILENO);

Adjuntar una variante, con el tipo real "g" (firma), y el valor "sdbusisgood":

sd_bus_message_append(m, "v", "g", "sdbusisgood");

Adjuntar un diccionario que contenga el mapeo {1=>"a", 2=>"b", 3=>""}:

sd_bus_message_append(m, "a{is}", 3, 1, "a", 2, "b", 3, NULL);

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un entero no negativo. En caso de error, devuelven un código de error negativo al estilo errno.

ERRORES

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

El parámetro especificado no es válido.

-EPERM

El mensaje ha sido sellado.

-ESTALE

El mensaje está en un estado inválido.

-ENXIO

El mensaje no puede ser añadido.

-ENOMEM

La asignación de memoria falló.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que se puede compilar contra y enlazar con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara que no es seguro para hilos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando aún no se han iniciado otros hilos.
