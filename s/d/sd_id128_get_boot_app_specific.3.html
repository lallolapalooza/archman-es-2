DESCRIPCIÓN

sd_id128_get_machine() devuelve el ID de la máquina del host en ejecución. Lee y analiza el archivo machine-id(5). Esta función almacena en caché el ID de la máquina internamente para que la recuperación del ID de la máquina sea una operación barata. Este ID puede ser utilizado donde sea que se necesite un identificador único para el sistema local. Sin embargo, se recomienda usar este ID tal cual solo en entornos de confianza. En entornos no confiables, se recomienda derivar un ID específico de la aplicación a partir de este ID de máquina, de una manera irreversible (criptográficamente segura). Para facilitar esto, se proporciona sd_id128_get_machine_app_specific(), ver más abajo.

sd_id128_get_app_specific() devuelve un ID de máquina que es una combinación de los parámetros base y app_id. Internamente, esta función calcula HMAC-SHA256 del parámetro app_id utilizando como clave el parámetro base, y trunca este resultado para que encaje en sd_id128_t y lo convierte en un UUID válido de Variante 1 Versión 4, de acuerdo con RFC 4122[1]. Ninguno de los dos parámetros de entrada puede ser calculado a partir del parámetro de salida ret.

sd_id128_get_machine_app_specific() es similar a sd_id128_get_machine(), pero recupera un ID de máquina que es específico de la aplicación identificada por el ID de aplicación indicado. Se recomienda utilizar esta función en lugar de sd_id128_get_machine() al pasar un ID a entornos no confiables, para asegurarse de que el ID de máquina original no pueda ser determinado externamente. De esta manera, el ID utilizado por la aplicación permanece estable en una máquina dada, pero no puede ser correlacionado fácilmente con IDs utilizados en otras aplicaciones en la misma máquina. El ID específico de la aplicación debe ser generado mediante una herramienta como systemd-id128 new, y puede ser compilado en la aplicación. Esta función devolverá el mismo ID específico de la aplicación para cada combinación de ID de máquina e ID de aplicación. Internamente, esta función llama a sd_id128_get_app_specific() con el resultado de sd_id128_get_machine() y el parámetro app_id.

sd_id128_get_boot() devuelve el ID de arranque del kernel en ejecución. Lee y analiza el archivo /proc/sys/kernel/random/boot_id expuesto por el kernel. Se genera aleatoriamente al inicio del arranque y es único para cada instancia de kernel en ejecución. Ver random(4) para más información. Esta función también almacena en caché internamente el ID devuelto para que esta llamada sea una operación barata. Se recomienda usar este ID tal cual solo en entornos de confianza. En entornos no confiables, se recomienda derivar un ID específico de la aplicación utilizando sd_id128_get_boot_app_specific(), ver más abajo.

sd_id128_get_boot_app_specific() es análogo a sd_id128_get_machine_app_specific(), pero devuelve un ID que cambia entre reinicios. Algunas máquinas pueden usarse durante mucho tiempo sin reiniciar, por lo que el ID de arranque puede permanecer constante durante mucho tiempo, y tiene propiedades similares al ID de máquina durante ese tiempo.

sd_id128_get_invocation() devuelve el ID de invocación del servicio que se está ejecutando actualmente. En su implementación actual, intenta leer y analizar lo siguiente:

•La variable de entorno $INVOCATION_ID que el gestor de servicios establece al activar un servicio.
•Una entrada en la keyring del kernel que el gestor de servicios del sistema establece al activar un servicio.

Ver systemd.exec(5) para detalles. El ID se almacena en caché internamente. En el futuro, puede añadirse un mecanismo diferente para determinar el ID de invocación.

sd_id128_get_invocation_app_specific() deriva un ID específico de la aplicación del ID de invocación.

Tenga en cuenta que sd_id128_get_machine_app_specific(), sd_id128_get_boot(), sd_id128_get_boot_app_specific(), sd_id128_get_invocation() y sd_id128_get_invocation_app_specific siempre devuelven IDs compatibles con UUID Variante 1 Versión 4. sd_id128_get_machine() también devolverá un ID compatible con UUID Variante 1 Versión 4 en instalaciones nuevas, pero podría no hacerlo en las antiguas. Es posible convertir el ID de máquina de forma no reversible a uno compatible con UUID Variante 1 Versión 4. Para más información, ver machine-id(5). Por lo tanto, se garantiza que estas funciones nunca devolverán el ID que consiste en todos los bits cero o todos los bits uno (SD_ID128_NULL, SD_ID128_ALLF) — con la posible excepción de sd_id128_get_machine(), como se mencionó.

Para más información sobre el tipo "sd_id128_t", ver sd-id128(3).

VALOR DE RETORNO

Estas llamadas devuelven 0 en caso de éxito (en cuyo caso ret se rellena), o un código de error negativo del tipo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOENT

Devuelto por sd_id128_get_machine() y sd_id128_get_machine_app_specific() cuando /etc/machine-id falta.

Añadido en la versión 242.

-ENOMEDIUM

Devuelto por sd_id128_get_machine() y sd_id128_get_machine_app_specific() cuando /etc/machine-id está vacío o es todo ceros. También devuelto por sd_id128_get_invocation() cuando el ID de invocación es todo ceros.

Añadido en la versión 242.

-ENOPKG

Devuelto por sd_id128_get_machine() y sd_id128_get_machine_app_specific() cuando el contenido de /etc/machine-id es "uninitialized".

Añadido en la versión 253.

-ENOSYS

Devuelto por sd_id128_get_boot() y sd_id128_get_boot_app_specific() cuando /proc/ no está montado.

Añadido en la versión 253.

-ENXIO

Devuelto por sd_id128_get_invocation() si no se ha establecido ningún ID de invocación. También devuelto por sd_id128_get_app_specific(), sd_id128_get_machine_app_specific(), y sd_id128_get_boot_app_specific() cuando el parámetro app_id es todo ceros.

Añadido en la versión 242.

-EUCLEAN

Devuelto por cualquiera de las funciones aquí descritas cuando el valor configurado tiene un formato inválido.

Añadido en la versión 253.

-EPERM

La información solicitada no pudo ser recuperada debido a permisos insuficientes.

Añadido en la versión 242.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para múltiples hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se han iniciado otros hilos.

EJEMPLOS

Ejemplo 1. ID de máquina específico de la aplicación

Primero, genera el ID de la aplicación

$ systemd-id128 new

Esto imprimirá el ID de aplicación en la salida estándar, por ejemplo:

f1b3a4b2-c5d6-e7f8-a9b0-c1d2e3f4a5b6

Compila este ID en tu aplicación, por ejemplo, como una cadena de caracteres:

const char *app_id_str = "f1b3a4b2-c5d6-e7f8-a9b0-c1d2e3f4a5b6";

Y luego úsalo en tu código C:

sd_id128_t machine_app_id;
int r;

r = sd_id128_get_machine_app_specific(app_id_str, &machine_app_id);
if (r < 0) {
    fprintf(stderr, "Failed to get application-specific machine ID: %s\n", strerror(-r));
    // ...
}

// use machine_app_id ...

DESCRIPCIÓN

Estas funciones proporcionan una abstracción de los identificadores únicos de 128 bits definidos por el sistema systemd. Los identificadores de 128 bits se utilizan para identificar de forma única entidades como el inicio del sistema, la máquina, un proceso específico o una CPU.

Los identificadores de 128 bits se representan mediante el tipo sd_id128_t. Las funciones devuelven el identificador solicitado o un identificador nulo si no se pudo obtener.

sd_id128_get_boot()
Devuelve un identificador único de 128 bits para el inicio actual del sistema. Este identificador se mantiene igual durante la vida útil de un proceso de inicio específico.
sd_id128_get_machine()
Devuelve un identificador único de 128 bits para la máquina.
sd_id128_get_invocation()
Devuelve un identificador único de 128 bits para la invocación actual del proceso. Esto es útil para rastrear una invocación específica de un servicio o proceso.
sd_id128_get_machine_app_specific(sd_id128_t app_id, sd_id128_t *ret)
Combina el identificador de máquina con un identificador específico de la aplicación app_id y almacena el resultado en ret. Esto es útil para generar identificadores únicos para aplicaciones que se ejecutan en diferentes máquinas pero que necesitan compartir un prefijo común.
sd_id128_get_boot_app_specific(sd_id128_t app_id, sd_id128_t *ret)
Combina el identificador de inicio del sistema con un identificador específico de la aplicación app_id y almacena el resultado en ret.
sd_id128_get_app_specific(sd_id128_t app_id, sd_id128_t *ret)
Genera un identificador específico de la aplicación combinando un identificador de máquina o inicio (según el contexto) con un identificador específico de la aplicación app_id. El resultado se almacena en ret.
sd_id128_get_invocation_app_specific(sd_id128_t app_id, sd_id128_t *ret)
Combina el identificador de invocación del proceso con un identificador específico de la aplicación app_id y almacena el resultado en ret.
sd_id128_randomize(sd_id128_t *ret)
Genera un identificador de 128 bits aleatorio y lo almacena en ret.
sd_id128_pid_get_container(pid_t pid, sd_id128_t *ret)
Obtiene el identificador de 128 bits del contenedor asociado con el PID especificado y lo almacena en ret.
sd_id128_pid_get_host(pid_t pid, sd_id128_t *ret)
Obtiene el identificador de 128 bits del host asociado con el PID especificado y lo almacena en ret.
sd_id128_get_cpu_path(int cpu, sd_id128_t *ret)
Obtiene el identificador de 128 bits de la ruta de la CPU especificada y lo almacena en ret.
SD_ID128_FORMAT_STR
SD_ID128_FORMAT_VAL(sd_id128_t id)
SD_ID128_NULL_STR
Macros para formatear e imprimir identificadores de 128 bits como cadenas de texto. SD_ID128_FORMAT_STR es la cadena de formato para printf, y SD_ID128_FORMAT_VAL es la macro para pasar el valor del identificador. SD_ID128_NULL_STR es una cadena que representa un identificador nulo.
SD_ID128_IS_NULL(sd_id128_t id)
sd_id128_is_null(sd_id128_t id)
Macros y funciones para comprobar si un identificador de 128 bits es nulo.
sd_id128_equal(sd_id128_t id1, sd_id128_t id2)
Comprueba si dos identificadores de 128 bits son iguales.
sd_id128_to_string(sd_id128_t id, char *str)
Convierte un identificador de 128 bits a su representación de cadena y la almacena en str. Se debe asignar suficiente memoria para str (al menos 33 bytes).
sd_id128_from_string(const char *str, sd_id128_t *ret)
Convierte una cadena de representación de identificador de 128 bits a su valor sd_id128_t y lo almacena en ret.
SD_ID128_MAKE(...)
Macro para construir un identificador de 128 bits a partir de sus bytes individuales.

VALOR DE RETORNO

Las funciones sd_id128_get_* y sd_id128_randomize devuelven el identificador de 128 bits solicitado o un identificador nulo si se produce un error.

Las funciones que toman un puntero sd_id128_t *ret devuelven un valor distinto de cero en caso de éxito, y cero en caso de error.

La función sd_id128_equal devuelve 1 si los identificadores son iguales, 0 en caso contrario.

Las funciones sd_id128_to_string y sd_id128_from_string devuelven un valor distinto de cero en caso de éxito, y cero en caso de error.

NOTAS

El identificador de máquina se almacena en /etc/machine-id y se inicializa durante la instalación del sistema. El identificador de inicio se deriva del ID de inicio del kernel.

Los identificadores específicos de la aplicación se pueden crear utilizando la macro SD_ID128_MAKE o mediante la utilidad de línea de comandos systemd-id128(1).

Se recomienda el uso de identificadores aleatorios generados por sd_id128_randomize() para fines generales de identificación única donde no se requiere un identificador específico de máquina o inicio.

EJEMPLOS

Generar un nuevo identificador de aplicación utilizando systemd-id128:

$ systemd-id128 -p new
As string:
c273277323db454ea63bb96e79b53e97
As UUID:
c2732773-23db-454e-a63b-b96e79b53e97
As man:sd-id128(3) macro:
#define MESSAGE_XYZ SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
...

Luego, utilice el nuevo identificador en una aplicación de ejemplo:

/* SPDX-License-Identifier: MIT-0 */
#include <stdio.h>
#include <systemd/sd-id128.h>
#define OUR_APPLICATION_ID SD_ID128_MAKE(c2,73,27,73,23,db,45,4e,a6,3b,b9,6e,79,b5,3e,97)
int main(int argc, char *argv[]) {
  sd_id128_t id;
  sd_id128_get_machine_app_specific(OUR_APPLICATION_ID, &id);
  printf("Our application ID: " SD_ID128_FORMAT_STR "\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}
