sd_bus_unrefp(3)

Paquete: systemd-libs

SD_BUS_NEW(3) sd_bus_new SD_BUS_NEW(3)

NOMBRE

sd_bus_new, sd_bus_ref, sd_bus_unref, sd_bus_unrefp, sd_bus_close_unref, sd_bus_close_unrefp, sd_bus_flush_close_unref, sd_bus_flush_close_unrefp - Crear un nuevo objeto de bus y crear o destruir referencias a él

SINOPSIS

#include <systemd/sd-bus.h>

int sd_bus_new(sd_bus **bus);

sd_bus *sd_bus_ref(sd_bus *bus);

sd_bus *sd_bus_unref(sd_bus *bus);

sd_bus *sd_bus_close_unref(sd_bus *bus);

sd_bus *sd_bus_flush_close_unref(sd_bus *bus);

void sd_bus_unrefp(sd_bus **busp);

void sd_bus_close_unrefp(sd_bus **busp);

void sd_bus_flush_close_unrefp(sd_bus **busp);

DESCRIPCIÓN

sd_bus_new() crea un nuevo objeto de bus. Este objeto tiene un contador de referencias y se destruirá cuando todas las referencias hayan desaparecido. Inicialmente, el llamador de esta función posee la única referencia y el objeto de bus no estará conectado a ningún bus. Para conectarlo a un bus, asegúrese de establecer una dirección con sd_bus_set_address(3) o una llamada relacionada, y luego inicie la conexión con sd_bus_start(3).

En la mayoría de los casos, es mejor usar sd_bus_default_user(3), sd_bus_default_system(3) o llamadas relacionadas en lugar de las llamadas de más bajo nivel sd_bus_new() y sd_bus_start(). Las funciones de nivel superior no solo asignan un objeto de bus, sino que también inician la conexión a un bus bien conocido en una sola llamada a función.

sd_bus_ref() incrementa el contador de referencias de bus en uno.

sd_bus_unref() decrementa el contador de referencias de bus en uno. Una vez que el contador de referencias ha caído a cero, bus se destruye y no se puede volver a usar, por lo que las llamadas posteriores a sd_bus_ref() o sd_bus_unref() son ilegales.

sd_bus_unrefp() es similar a sd_bus_unref() pero toma un puntero a un puntero a un objeto sd_bus. Esta llamada es útil en conjunción con el **Atributo de Variable de Limpieza**[1] de GCC y LLVM. Tenga en cuenta que esta función está definida como una función en línea. Use una declaración como la siguiente para asignar un objeto de bus que se libera automáticamente al salir del bloque de código:

{
  __attribute__((cleanup(sd_bus_unrefp))) sd_bus *bus = NULL;
  int r;
  ...
  r = sd_bus_default(&bus);
  if (r < 0) {
    errno = -r;
    fprintf(stderr, "Fallo al asignar bus: %m\n");
  }
  ...
}

sd_bus_ref() y sd_bus_unref() no realizan ninguna operación si el argumento es NULL. sd_bus_unrefp() primero desreferenciará su argumento, que no debe ser NULL, y no realizará ninguna operación si *ese* es NULL.

sd_bus_close_unref() es similar a sd_bus_unref(), pero primero ejecuta sd_bus_close(3), asegurando que la conexión se cierra antes de que se libere la referencia a la conexión y posiblemente el objeto.

sd_bus_flush_close_unref() es similar a sd_bus_unref(), pero primero ejecuta sd_bus_flush(3) así como sd_bus_close(3), asegurando que los mensajes pendientes se envían sincrónicamente antes de que se libere la referencia a la conexión y posiblemente el objeto. Esta llamada es particularmente útil inmediatamente antes de salir de un programa, ya que asegura que los mensajes salientes pendientes se escriban y los mensajes entrantes no procesados pero en cola se liberen antes de que la conexión se cierre y se libere.

sd_bus_close_unrefp() es similar a sd_bus_close_unref(), pero puede usarse en el Atributo de Variable de Limpieza de GCC y LLVM, véase arriba. De manera similar, sd_bus_flush_close_unrefp() es similar a sd_bus_flush_close_unref().

VALOR DE RETORNO

En caso de éxito, sd_bus_new() devuelve 0 o un entero positivo. En caso de fallo, devuelve un código de error negativo de estilo errno.

sd_bus_ref() siempre devuelve el argumento.

sd_bus_unref() y sd_bus_flush_close_unref() siempre devuelven NULL.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-ENOMEM

Fallo al asignar memoria.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede ser compilada y enlazada con el archivo libsystemd pkg-config(1).

El código descrito aquí utiliza getenv(3), que se declara como no seguro para hilos. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda hacer llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

HISTORIA

sd_bus_new(), sd_bus_ref() y sd_bus_unref() se añadieron en la versión 209.

sd_bus_unrefp() se añadió en la versión 229.

sd_bus_flush_close_unref() y sd_bus_flush_close_unrefp() se añadieron en la versión 240.

sd_bus_close_unref() y sd_bus_close_unrefp() se añadieron en la versión 241.
