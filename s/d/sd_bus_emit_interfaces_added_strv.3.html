NOMBRE

sd_bus_emit_signal, sd_bus_emit_signalv, sd_bus_emit_signal_to, sd_bus_emit_signal_tov, sd_bus_emit_interfaces_added, sd_bus_emit_interfaces_added_strv, sd_bus_emit_interfaces_removed, sd_bus_emit_interfaces_removed_strv, sd_bus_emit_properties_changed, sd_bus_emit_properties_changed_strv, sd_bus_emit_object_added, sd_bus_emit_object_removed - Funciones de conveniencia para emitir señales D-Bus (estándar)

#include <systemd/sd-bus-vtable.h>

int sd_bus_emit_signal(sd_bus *bus, const char *path, const char *interface, const char *member, const char *types, ...);

DESCRIPCIÓN

sd_bus_emit_signal() es una función de conveniencia para inicializar un objeto de mensaje de bus y emitir la señal D-Bus correspondiente. Combina las funciones sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) en una única llamada a función. sd_bus_emit_signalv() es equivalente a sd_bus_message_append(), excepto que se llama con una "va_list" en lugar de un número variable de argumentos.

sd_bus_emit_signal_to() y sd_bus_emit_signal_tov() son idénticas a sd_bus_emit_signal() y sd_bus_emit_signalv(), excepto que pueden emitir la señal a un único destino. Proporcione destination como NULL para transmitir la señal.

sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() se utilizan para implementar las señales InterfacesAdded y InterfacesRemoved de la interfaz org.freedesktop.DBus.ObjectManager. Toman una ruta cuyo interfaz se ha modificado como argumento y una lista variable de interfaces que se han añadido o eliminado, respectivamente. El argumento final pasado a sd_bus_emit_interfaces_added() y sd_bus_emit_interfaces_removed() debe ser NULL. Esto permite que ambas funciones determinen de forma segura el número de argumentos de interfaz pasados. sd_bus_emit_interfaces_added_strv() y sd_bus_emit_interfaces_removed_strv() son idénticas a sus respectivas contrapartes, pero ambas toman la lista de interfaces como un único argumento en lugar de un número variable de argumentos.

sd_bus_emit_properties_changed() se utiliza para implementar la señal PropertiesChanged de la interfaz org.freedesktop.DBus.Properties. Toma una ruta de objeto, una interfaz y una lista variable de nombres de propiedades como sus argumentos. El argumento final pasado a sd_bus_emit_properties_changed() debe ser NULL. Esto permite determinar de forma segura el número de nombres de propiedades pasados. sd_bus_emit_properties_changed_strv() es idéntica a sd_bus_emit_properties_changed() pero toma la lista de nombres de propiedades como un único argumento en lugar de un número variable de argumentos.

sd_bus_emit_object_added() y sd_bus_emit_object_removed() son funciones de conveniencia para emitir las señales InterfacesAdded o InterfacesRemoved para todas las interfaces registradas en una ruta de objeto específica, respectivamente. Esto incluye cualquier tabla de búsqueda (vtable) principal si no son anuladas por una tabla de búsqueda hija más aplicable. También incluye todas las interfaces D-Bus estándar implementadas por sd-bus en cualquier objeto registrado.

Tenga en cuenta que sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() y sd_bus_emit_object_removed() requieren que se haya registrado un gestor de objetos en la ruta de objeto dada o en una de sus rutas de objeto principales utilizando sd_bus_add_object_manager(3).

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven un entero no negativo. En caso de fallo, devuelven un código de error negativo al estilo errno.

Errores

Los errores devueltos pueden indicar los siguientes problemas:

-EINVAL

Uno de los parámetros requeridos es NULL o inválido. Se pasó una interfaz D-Bus reservada como parámetro interface.

-ENOPKG

El bus no se puede resolver.

-ECHILD

El bus se creó en un proceso, biblioteca o instancia de módulo diferente.

-ENOMEM

Fallo en la asignación de memoria.

-ESRCH

Se llamó a una de las funciones sd_bus_emit_interfaces_added(), sd_bus_emit_interfaces_removed(), sd_bus_emit_object_added() o sd_bus_emit_object_removed() en un objeto sin un gestor de objetos registrado en su propia ruta de objeto o en una de sus rutas de objeto principales.

Consulte las páginas man de sd_bus_message_new_signal(3), sd_bus_message_append(3) y sd_bus_send(3) para errores más posibles.

NOTAS

Las funciones descritas aquí están disponibles como una biblioteca compartida, que puede compilarse y enlazarse con el archivo pkg-config(1) de libsystemd.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para subprocesos múltiples. Esto significa que el código que llama a las funciones descritas aquí no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

DESCRIPTION

These functions may be used to emit D-Bus signals.

A D-Bus message consists of a header and a body. The header contains metadata such as the sender, destination, path, interface, member and signal name. The body contains the arguments for the signal.

The sd_bus_emit_* functions encapsulate the process of creating a new message, serializing arguments into its body, and sending it out on the bus.

Signals are broadcast messages and are not typically directed to a specific recipient. However, if a destination is specified using sd_bus_emit_signal_to() or sd_bus_emit_signal_tov(), the message will only be delivered to that specific recipient.

sd_bus_emit_interfaces_added_strv() and sd_bus_emit_interfaces_removed_strv() emit org.freedesktop.DBus.ObjectManager.InterfacesAdded and org.freedesktop.DBus.ObjectManager.InterfacesRemoved respectively. These signals are used by the Object Manager interface to notify clients about changes to the interfaces implemented by objects.

sd_bus_emit_properties_changed() and sd_bus_emit_properties_changed_strv() emit org.freedesktop.DBus.Properties.PropertiesChanged signals. These signals are used to notify clients about changes to object properties.

sd_bus_emit_object_added() and sd_bus_emit_object_removed() emit org.freedesktop.DBus.ObjectManager.ObjectAdded and org.freedesktop.DBus.ObjectManager.ObjectRemoved respectively. These signals are used by the Object Manager interface to notify clients about objects being added or removed.

sd_bus_emit_signalv(), sd_bus_emit_signal_to() and sd_bus_emit_signal_tov() emit generic D-Bus signals. The types string specifies the types of the arguments, and the arguments themselves are passed using a variable argument list (...) or a va_list.

The sd_bus_emit_signalv() function emits a signal without a specific destination. The signal is broadcast to all interested peers.

The sd_bus_emit_signal_to() function emits a signal to a specific destination bus name. If destination is NULL, the signal is broadcast. This function is a convenience wrapper around sd_bus_emit_signal_tov().

The sd_bus_emit_signal_tov() function emits a signal to a specific destination bus name. If destination is NULL, the signal is broadcast. It takes the signal arguments via a va_list.

RETURN VALUE

On success, these functions return a non-negative integer. On failure, they return a negative error number.

NOTES

These functions are intended for use by bus implementing services. Applications usually need to call sd_bus_message_new_signal(3), sd_bus_message_append(3), and sd_bus_send(3).

The types string format is described in sd_bus_message_append(3).
