SIGWAIT(3P) Manual del programador POSIX SIGWAIT(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

sigwait — espera señales encoladas

SINOPSIS

#include <signal.h>
int sigwait(const sigset_t *restrict set, int *restrict sig);

DESCRIPCIÓN

La función sigwait() seleccionará una señal pendiente de set, la eliminará atómicamente del conjunto de señales pendientes del sistema y devolverá ese número de señal en la ubicación a la que apunta sig. Si antes de la llamada a sigwait() existen múltiples instancias pendientes de un único número de señal, dependerá de la implementación si tras una devolución exitosa quedan señales pendientes para ese número de señal. Si la implementación soporta señales encoladas y hay múltiples señales encoladas para el número de señal seleccionado, la primera de estas señales encoladas provocará una devolución de sigwait() y el resto permanecerán encoladas. Si ninguna señal en set está pendiente en el momento de la llamada, el hilo se suspenderá hasta que una o más se vuelvan pendientes. Las señales definidas por set deben haber estado bloqueadas en el momento de la llamada a sigwait(); de lo contrario, el comportamiento es indefinido. El efecto de sigwait() en las acciones de señal para las señales en set no está especificado.

Si más de un hilo está utilizando sigwait() para esperar la misma señal, no más de uno de estos hilos devolverá el número de señal de sigwait(). Si más de un hilo está bloqueado en sigwait() para una señal cuando esa señal se genera para el proceso, no está especificado cuál de los hilos en espera devolverá de sigwait(). Si la señal se genera para un hilo específico, como con pthread_kill(), solo ese hilo devolverá.

Si se seleccionan varias señales pendientes en el rango SIGRTMIN a SIGRTMAX, será la de menor número. El orden de selección entre señales reales y no reales, o entre múltiples señales no reales pendientes, no está especificado.

VALOR DE RETORNO

Tras una finalización exitosa, sigwait() almacenará el número de señal de la señal recibida en la ubicación referenciada por sig y devolverá cero. De lo contrario, se devolverá un número de error para indicar el error.

ERRORES

La función sigwait() puede fallar si:

EINVAL
El argumento set contiene un número de señal no válido o no soportado.

JUSTIFICACIÓN

Para proporcionar una forma conveniente para que un hilo espere una señal, este volumen de POSIX.1‐2017 proporciona la función sigwait(). Para la mayoría de los casos en los que un hilo tiene que esperar una señal, la función sigwait() debería ser bastante cómoda, eficiente y adecuada.

Sin embargo, se hicieron solicitudes de una primitiva de nivel más bajo que sigwait() y de semáforos que pudieran ser utilizados por los hilos. Después de alguna consideración, se permitió a los hilos usar semáforos y sem_post() se definió como seguro para señales asíncronas.

En resumen, cuando sea necesario que el código ejecutado en respuesta a una señal asíncrona notifique a un hilo, se debe usar sigwait() para manejar la señal. Alternativamente, si la implementación proporciona semáforos, también se pueden usar, ya sea después de sigwait() o dentro de una rutina de manejo de señales registrada previamente con sigaction().
