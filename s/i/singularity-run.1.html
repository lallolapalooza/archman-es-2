NOMBRE

apptainer-run - Ejecuta el comando por defecto definido por el usuario dentro de un contenedor

SINOPSIS

apptainer run [opciones-de-ejecucion...] [argumentos...]

DESCRIPCIÓN

Este comando iniciará un contenedor Apptainer y ejecutará un script de ejecución
si está definido para ese contenedor. El script de ejecución es un archivo de metadatos dentro
del contenedor que contiene comandos de shell. Si el archivo está presente (y
es ejecutable), este comando ejecutará ese archivo dentro del contenedor
automáticamente. Todos los argumentos que sigan al nombre del contenedor se pasarán
directamente al script de ejecución.

apptainer run acepta los siguientes formatos de contenedor:

*.sif Formato de Imagen Singularity (SIF). Nativo de Singularity
(3.0+) y Apptainer (v1.0.0+)

*.sqsh Formato SquashFS. Nativo de Singularity 2.4+

*.img Formato ext3. Nativo de versiones de Singularity < 2.4.

directorio/ Formato sandbox. Directorio que contiene un sistema de archivos raíz válido
y opcionalmente metadatos de Apptainer.

instance://* Una instancia local en ejecución de un contenedor. (Ver el grupo
de comandos instance.)

library://* Un contenedor SIF alojado en una Biblioteca (sin predeterminar)

docker://* Un contenedor Docker/OCI alojado en Docker Hub u otro
registro OCI.

shub://* Un contenedor alojado en Singularity Hub.

oras://* Un contenedor SIF alojado en un registro OCI que soporta
la especificación OCI Registry As Storage (ORAS).

OPCIONES

--add-caps="" una lista de capacidades separadas por comas para añadir

--allow-setuid[=false] permite binarios setuid en el contenedor (solo root)

--app="" establece una aplicación a ejecutar dentro de un contenedor

--apply-cgroups="" aplica cgroups desde un archivo para procesos del contenedor (solo root)

--authfile="" archivo de autenticación tipo Docker a usar para leer/escribir credenciales del registro OCI

-B, --bind=[] una especificación de montaje de enlace (bind) definida por el usuario. spec tiene el formato src[:dest[:opts]], donde src y dest son rutas externas e internas. Si no se proporciona dest, se establece igual a src. Las opciones de montaje ('opts') pueden especificarse como 'ro' (solo lectura) o 'rw' (lectura/escritura, que es el valor predeterminado). Se pueden especificar múltiples montajes de enlace mediante una lista separada por comas.

--blkio-weight=0 peso relativo de E/S de bloque en el rango 10-1000, 0 para deshabilitar

--blkio-weight-device=[] peso relativo de E/S de bloque específico del dispositivo

-e, --cleanenv[=false] limpia el entorno antes de ejecutar el contenedor

--compat[=false] aplica configuraciones para una mayor compatibilidad OCI/Docker. Infiere --containall, --no-init, --no-umask, --no-eval, --writable-tmpfs.

-c, --contain[=false] usa un /dev mínimo y vacía otros directorios (por ejemplo, /tmp y $HOME) en lugar de compartir sistemas de archivos de tu host

-C, --containall[=false] contiene no solo sistemas de archivos, sino también PID, IPC y entorno

--cpu-shares=-1 shares de CPU para el contenedor

--cpus="" Número de CPUs disponibles para el contenedor

--cpuset-cpus="" Lista de CPUs del host disponibles para el contenedor

--cpuset-mems="" Lista de nodos de memoria del host disponibles para el contenedor

--cwd="" directorio de trabajo inicial para el proceso payload dentro del contenedor (sinónimo de --pwd)

--disable-cache[=false] no usar ni crear caché

--dns="" lista de servidores DNS separados por comas para añadir en resolv.conf

--docker-host="" especifica un host daemon Docker personalizado

--docker-login[=false] inicia sesión en un Repositorio Docker interactivamente

--drop-caps="" una lista de capacidades separadas por comas para descartar

--env=[] pasa una variable de entorno al proceso contenido

--env-file=[] pasa variables de entorno desde un archivo al proceso contenido

-f, --fakeroot[=false] ejecuta el contenedor con la apariencia de ejecutarse como root

--fusemount=[] una especificación de montaje de sistema de archivos FUSE de la forma ': ' - donde es 'container' o 'host', especificando dónde se realizará el montaje ('container-daemon' o 'host-daemon' ejecutarán el proceso FUSE desacoplado). es la ruta al ejecutable FUSE, más opciones para el montaje. es la ubicación en el contenedor donde se adjuntará el montaje FUSE. Por ejemplo, 'container:sshfs 10.0.0.1:/ /sshfs'. Implica --pid.

-h, --help[=false] ayuda para run

-H, --home="/build" una especificación de directorio home. spec puede ser una ruta src o un par src:dest. src es la ruta de origen del directorio home fuera del contenedor y dest reemplaza el directorio home dentro del contenedor.

--hostname="" establece el nombre de host del contenedor

-i, --ipc[=false] ejecuta el contenedor en un nuevo espacio de nombres IPC

--keep-privs[=false] permite que el usuario root conserve privilegios en el contenedor (solo root)

--memory="" límite de memoria en bytes

--memory-reservation="" límite blando de memoria en bytes

--memory-swap="" límite de swap, usa -1 para swap ilimitado

--mount=[] una especificación de montaje por ejemplo, 'type=bind,source=/opt,destination=/hostopt'.

-n, --net[=false] ejecuta el contenedor en un nuevo espacio de nombres de red (configura una interfaz de red bridge por defecto)

--netns-path="" une el espacio de nombres de red en la ruta especificada (como root, o si está permitido en apptainer.conf)

--network="" especifica el tipo de red deseado separado por comas, cada red levantará una interfaz dedicada dentro del contenedor

--network-args=[] especifica argumentos de red para pasar a los plugins CNI

--no-eval[=false] no evalúa shell para variables de entorno o CMD/ENTRYPOINT/ARGS del contenedor OCI

--no-home[=false] NO monta el directorio home del usuario si /home no es el directorio de trabajo actual

--no-https[=false] usa http en lugar de https para las URIs docker://, oras:// y library:///...

--no-init[=false] NO inicia el proceso shim con --pid

--no-mount=[] deshabilita una o más opciones 'mount xxx' establecidas en apptainer.conf y/o especifica una ruta de destino absoluta para deshabilitar una entrada de ruta de enlace (bind path), o 'bind-paths' para deshabilitar todas las entradas de ruta de enlace.

--no-pid[=false] no ejecuta el contenedor en un nuevo espacio de nombres PID

--no-privs[=false] descarta todos los privilegios del usuario root en el contenedor)

--no-umask[=false] no propaga umask al contenedor, establece umask predeterminada 0022

--nv[=false] habilita soporte Nvidia

--nvccli[=false] usa nvidia-container-cli para la configuración de GPU (experimental)

--oom-kill-disable[=false] Deshabilita el killer OOM

-o, --overlay=[] usa una imagen overlayFS para almacenamiento persistente de datos o como capa de solo lectura del contenedor

--passphrase[=false] solicita una contraseña de cifrado

--pem-path="" introduce la ruta a una clave RSA con formato PEM para un contenedor cifrado

-p, --pid[=false] ejecuta el contenedor en un nuevo espacio de nombres PID

--pids-limit=0 Límite de PIDs del contenedor, usa -1 para ilimitado

--rocm[=false] habilita soporte experimental Rocm

--runscript-timeout="" establece la duración del tiempo de espera para el script de ejecución (predeterminado 1m)

-S, --scratch=[] incluye un directorio scratch dentro del contenedor que está enlazado a un directorio temporal (usa -W para forzar la ubicación)

--security=[] habilita características de seguridad (SELinux, Apparmor, Seccomp)

--sharens[=false] comparte el espacio de nombres y la imagen con otros contenedores lanzados desde el mismo proceso padre

--unsquash[=false] Convierte el archivo SIF a un sandbox temporal antes de ejecutar

-u, --userns[=false] ejecuta el contenedor en un nuevo espacio de nombres de usuario

--uts[=false] ejecuta el contenedor en un nuevo espacio de nombres UTS

-W, --workdir="" directorio de trabajo a ser utilizado para /tmp, /var/tmp y $HOME (si también se usó -c/--contain)

apptainer-run(1) — Apptainer User Guide

NAME

apptainer-run(1) — Apptainer User Guide

SYNOPSIS

apptainer run [run options] IMAGE [run arguments ...]

DESCRIPTION

The apptainer run command executes the default runscript (if any) within the container. If a runscript is not defined, it will execute the executable specified in the container.

The execution of the runscript may be chained. If the runscript is composed of multiple lines, they will be executed in order.

If the container defines a runscript, the apptainer run command will execute it. If the container does not define a runscript, it will execute the default executable specified within the container's definition file.

Arguments passed after the image file are forwarded to the runscript or the default executable.

OPTIONS

--app APP
Specify the name of the application within the container to execute. If not specified, the default runscript or executable is used.
--compat
Enable OCI runtime compatibility. This flag allows Apptainer to run OCI containers with Apptainer's runtime.
--no-home
Do not mount the user's home directory inside the container.
--no-mount host-path
Do not mount the specified host path inside the container.
--nv
Use the NVIDIA Container Toolkit to mount the NVIDIA driver into the container. This requires the NVIDIA drivers to be installed on the host system.
--overlay OVERLAY-FS
Use an overlay file system on top of the container's file system. The overlay file system is read-write, while the container's file system is read-only. This option can be specified multiple times to layer multiple overlay file systems.
--writable, -w
By default, all Apptainer containers are available as read-only. This option makes the file system accessible as read/write.
--writable-tmpfs
Makes the file system accessible as read-write with non-persistent data (with overlay support only).

EXAMPLE

  # Here we see that the runscript prints "Hello world: "
  $ apptainer exec /tmp/debian.sif cat /apptainer
  #!/bin/sh
  echo "Hello world: "
  # It runs with our inputs when we run the image
  $ apptainer run /tmp/debian.sif one two three
  Hello world: one two three
  # Note that this does the same thing
  $ ./tmp/debian.sif one two three
