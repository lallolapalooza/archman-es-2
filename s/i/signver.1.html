SIGNVER(1) Herramientas de seguridad NSS SIGNVER(1)

NOMBRE

signver - Verifica una firma PKCS#7 desprendida para un archivo.

SINOPSIS

signtool -A | -V -d directorio [-a] [-i archivo_entrada] [-o archivo_salida] [-s archivo_firma] [-v]

ESTADO

Esta documentación todavía está en proceso. Por favor, contribuya a la revisión inicial en bug 836477 de Mozilla NSS[1]

DESCRIPCIÓN

La Herramienta de Verificación de Firma, signver, es una utilidad simple de línea de comandos que desempaqueta un objeto firmado PKCS#7 codificado en base64 y verifica la firma digital utilizando técnicas criptográficas estándar. La Herramienta de Verificación de Firma también puede mostrar el contenido del objeto firmado.

OPCIONES

-A

Muestra toda la información en la firma PKCS#7.

-V

Verifica la firma digital.

-d directorio

Especifica el directorio de la base de datos que contiene los certificados y claves.

signver soporta dos tipos de bases de datos: las bases de datos de seguridad heredadas (cert8.db, key3.db y secmod.db) y las nuevas bases de datos SQLite (cert9.db, key4.db y pkcs11.txt). Si el prefijo dbm: no se usa, entonces la herramienta asume que las bases de datos dadas están en formato SQLite.

-a

Establece que el archivo de firma dado está en formato ASCII.

-i archivo_entrada

Proporciona el archivo de entrada para el objeto con datos firmados.

-o archivo_salida

Proporciona el archivo de salida al que se escribirán los resultados.

-s archivo_firma

Proporciona el archivo de entrada para la firma digital.

-v

Habilita la salida detallada.

EJEMPLOS EXTENDIDOS

Verificando una Firma

La opción -V verifica que la firma en un archivo de firma dado es válida cuando se usa para firmar el objeto dado (del archivo de entrada).

signver -V -s archivo_firma -i archivo_firmado -d /home/mi/sharednssdb
signatureValid=yes

Imprimiendo Datos de Firma

La opción -A imprime toda la información contenida en un archivo de firma. Usar la opción -o imprime la información del archivo de firma en el archivo de salida dado en lugar de stdout.

signver -A -s archivo_firma -o archivo_salida

TIPOS DE BASE DE DATOS NSS

Originalmente, NSS utilizaba bases de datos BerkeleyDB para almacenar información de seguridad. Las últimas versiones de estas bases de datos heredadas son:

•cert8.db para certificados
•key3.db para claves
•secmod.db para información del módulo PKCS #11

BerkeleyDB tiene limitaciones de rendimiento, lo que dificulta su uso simultáneo por varias aplicaciones. NSS tiene cierta flexibilidad que permite a las aplicaciones usar su propio motor de base de datos independiente, manteniendo una base de datos compartida y sorteando los problemas de acceso. Aun así, NSS requiere más flexibilidad para proporcionar una base de datos de seguridad verdaderamente compartida.

En 2009, NSS introdujo un nuevo conjunto de bases de datos que son bases de datos SQLite en lugar de BerkleyDB. Estas nuevas bases de datos ofrecen más accesibilidad y rendimiento:

•cert9.db para certificados
•key4.db para claves
•pkcs11.txt, que es una lista de todos los módulos PKCS #11 contenidos en un nuevo subdirectorio en el directorio de bases de datos de seguridad

Dado que las bases de datos SQLite están diseñadas para ser compartidas, este es el tipo de base de datos compartida. El tipo de base de datos compartida es preferido; el formato heredado se incluye para compatibilidad hacia atrás.

Por defecto, las herramientas (certutil, pk12util, modutil) asumen que las bases de datos de seguridad proporcionadas usan el tipo SQLite. El uso de las bases de datos heredadas debe especificarse manualmente usando el prefijo dbm: con el directorio de seguridad proporcionado. Por ejemplo:

# signver -A -s firma -d dbm:/home/mi/sharednssdb

Para establecer el tipo de base de datos heredada como el tipo predeterminado para las herramientas, establezca la variable de entorno NSS_DEFAULT_DB_TYPE a dbm:

export NSS_DEFAULT_DB_TYPE="dbm"

Esta línea se puede agregar al archivo ~/.bashrc para hacer el cambio permanente para el usuario.
