SIGROK-CLI(1) General Commands Manual SIGROK-CLI(1)

NOMBRE

sigrok-cli - Cliente de línea de comandos para el software sigrok

SINOPSIS

sigrok-cli [OPCIONES] [COMANDO]

DESCRIPCIÓN

sigrok-cli es una utilidad de línea de comandos multiplataforma para el software sigrok.

No puede mostrar salida gráfica, pero aun así es suficiente para ejecutar todo el proceso de inicialización de hardware, adquisición, decodificación de protocolos y guardado de la sesión.

Es útil para ejecutarse en sistemas remotos o integrados, netbooks, PDAs y para varios otros casos de uso. Puede mostrar muestras en la salida estándar o guardarlas en varios formatos de archivo.

OPCIONES

-h, --help
Muestra un texto de ayuda y sale.
-V, --version
Muestra la versión de sigrok-cli y las versiones de las bibliotecas utilizadas.
-L, --list-supported
Muestra información sobre los controladores de hardware, formatos de archivo de entrada, formatos de archivo de salida y decodificadores de protocolo compatibles.
--list-supported-wiki
Muestra información sobre los decodificadores de protocolo compatibles en sintaxis de MediaWiki. Esto generalmente solo lo utilizan los desarrolladores para actualizar fácilmente la lista de decodificadores de protocolo compatibles en la wiki de sigrok.
-d, --driver <nombre_controlador>
A menos que se esté realizando un escaneo global, los usuarios normalmente seleccionan uno de los controladores disponibles. Esto puede acelerar el inicio del programa y evitar coincidencias erróneas para configuraciones ambiguas. La selección de un controlador también permite pasar más opciones específicas del controlador. Use la opción -L (--list-supported) para obtener una lista de los controladores disponibles.

Los controladores pueden tomar opciones, en forma de clave=valor separadas por dos puntos.

Los controladores que se comunican con el hardware a través de un puerto serie siempre necesitan que el puerto se especifique como la opción conn. Por ejemplo, para usar el analizador lógico Openbench:

$ sigrok-cli --driver=ols:conn=/dev/ttyACM0 [...]

Algunos dispositivos USB no utilizan una combinación única de VendorID/ProductID, y por lo tanto necesitan que también se especifique. Tenga en cuenta que se utilizan dos puntos para separar el nombre del controlador de la opción conn, por lo tanto, los dos puntos no se pueden usar dentro del argumento de la opción conn. Para seleccionar un dispositivo USB específico, use VendorID.ProductID o bus.address:

Ejemplo de VendorID.ProductID USB:

$ sigrok-cli --driver=uni-t-ut61e:conn=1a86.e008 [...]

Ejemplo de bus.address USB:

$ sigrok-cli --driver=uni-t-ut61e:conn=4.6 [...]

-D, --dont-scan
No escanear automáticamente los controladores de dispositivos en ausencia de una especificación de -d (--driver).
-c, --config <opción_dispositivo>
Una lista de opciones de dispositivo separadas por dos puntos, donde cada opción tiene el formato clave=valor. Se admiten múltiples ocurrencias de la opción --config. El primer elemento en la lista de opciones puede tener el formato channel_group=<nombre> lo que anularía la especificación --channel-group para esta lista de opciones. Otras listas de opciones en otras ocurrencias de --config no se ven afectadas por el nombre del grupo de canales de esta lista.

Por ejemplo, para establecer la tasa de muestreo en 1MHz en un dispositivo soportado por el controlador fx2lafw, podría especificar

$ sigrok-cli -d fx2lafw --config samplerate=1m [...]

Samplerate es una opción común a la mayoría de los analizadores lógicos. El argumento especifica la tasa de muestreo en Hz. También puede especificar la tasa de muestreo en kHz, MHz o GHz. Los siguientes son todos equivalentes:

$ sigrok-cli -d fx2lafw --config samplerate=1000000 [...]

$ sigrok-cli -d fx2lafw --config samplerate=1m [...]

$ sigrok-cli -d fx2lafw --config "samplerate=1 MHz" [...]

Estos ejemplos especifican opciones dentro de un grupo de canales. Los primeros dos son equivalentes.

$ sigrok-cli -d demo --channel-group Logic --config pattern=random [...]

$ sigrok-cli -d demo --config channel_group=Logic:pattern=random [...]

$ sigrok-cli -d demo --config samplerate=1m --config channel_group=Logic:pattern=random [...]

-i, --input-file <nombre_archivo>
Carga la entrada desde un archivo en lugar de un dispositivo de hardware. Puede especificar "-" para usar stdin como entrada. Si la opción --input-format no se suministra, sigrok-cli intenta autodetectar el formato de archivo de entrada.

Ejemplo para cargar un archivo de sesión sigrok:

$ sigrok-cli -i example.sr [...]

Ejemplo para cargar un archivo WAV (autodetectar formato de entrada):

$ sigrok-cli -i example.wav [...]

Ejemplo para cargar un archivo VCD desde stdin (autodetectar formato de entrada):

$ cat example.vcd | sigrok-cli -i - [...]

-I, --input-format <formato>
Al cargar un archivo de entrada, asume que está en el formato especificado. Si esta opción no se suministra (además de --input-file), sigrok-cli intenta autodetectar el formato de archivo de entrada. Utilice la opción -L (--list-supported) para ver una lista de los formatos de entrada disponibles.

El nombre del formato puede ir seguido opcionalmente por una lista de opciones separadas por dos puntos, donde cada opción tiene el formato clave=valor.

Ejemplo para cargar un archivo binario con opciones:

$ sigrok-cli -i example.bin
-I binary:numchannels=4:samplerate=1mhz [...]

-o, --output-file <nombre_archivo>
Guarda la salida en un archivo en lugar de escribirla en stdout. El formato predeterminado que se utiliza al guardar es el formato de archivo de sesión de sigrok. Esto se puede cambiar con la opción --output-format.

Ejemplo para guardar datos en el formato de sesión sigrok:

$ sigrok-cli [...] -o example.sr

-O, --output-format <formato>
Establece el formato de salida a utilizar. Utilice la opción -L (--list-supported) para ver una lista de los formatos de salida disponibles.

El nombre del formato puede ir seguido opcionalmente por una lista de opciones separadas por dos puntos, donde cada opción tiene el formato clave=valor.

Por ejemplo, los formatos bits o hex, para una visualización de bits ASCII o hexadecimal ASCII, pueden tomar una opción "width", que especifica el número de muestras (en bits) a mostrar por línea. Por lo tanto, -O hex:width=128 mostrará 128 bits por línea, en hexadecimal:


0:ffff ffff ffff ffff ffff ffff ffff ffff
1:ff00 ff00 ff00 ff00 ff00 ff00 ff00 ff00

Las líneas siempre comienzan con el número de canal (o nombre, si está definido), seguido de dos puntos. Si no se especifica ningún formato, por defecto es bits:width=64, así:


0:11111111 11111111 11111111 11111111 [...]
1:11111111 00000000 11111111 00000000 [...]

Ejemplo para guardar datos en formato CSV con opciones:

$ sigrok-cli [...] -o example.csv -O csv:dedup:header=false

Tenga en cuenta que las opciones booleanas son true cuando no se proporciona ningún valor.

-C, --channels <lista_canales>
Una lista de canales separada por comas que se utilizará en la sesión.

Tenga en cuenta que sigrok siempre nombra los canales según cómo se muestran en la carcasa del hardware. Si su analizador lógico numera los canales 0-15, así es como debe especificarlos con esta opción. Los canales de un osciloscopio generalmente se denominarían "CH1", "CH2", etc. Utilice la opción --show para ver una lista de nombres de canales para su dispositivo.

El valor predeterminado es utilizar todos los canales disponibles en un dispositivo. Puede nombrar un canal así: 1=CLK. También se puede usar un rango de canales

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Tanto los nombres de canal como los números de canal se pueden especificar. El número de canal se da en forma 1-5.

Ejemplo:

$ sigrok-cli --driver fx2lafw --samples 100
--channels 1=CLK,2-4,7
CLK:11111111 11111111 11111111 11111111 [...]
2:11111111 11111111 11111111 11111111 [...]
3:11111111 11111111 11111111 11111111 [...]
4:11111111 11111111 11111111 11111111 [...]
7:11111111 11111111 11111111 11111111 [...]

La lista separada por comas se procesa de izquierda a derecha, es decir, los elementos más a la derecha anulan los anteriores. Por ejemplo, 1=CS,CS=MISO establecerá el nombre del canal 1 como MISO.

-g, --channel-group <grupo de canales>
Especifica el grupo de canales sobre el que operar. Algunos dispositivos organizan los canales en grupos, cuyos ajustes solo se pueden cambiar como grupo. La lista de grupos de canales, si los hay, se muestra con el comando --show.

Ejemplos:

$ sigrok-cli -g CH1 [...]

$ sigrok-cli -d demo -g Logic -c pattern=graycode [...]

Las especificaciones del grupo de canales en las opciones --get o --config tienen prioridad sobre los nombres de los grupos de canales en --channel-group, de modo que una sola invocación de sigrok-cli pueda admitir la consulta o manipulación de múltiples opciones del dispositivo que residen en diferentes grupos de canales.

-t, --triggers <lista de disparadores>
Una lista de disparadores a usar, separada por comas, con el formato <canal>=<disparador>. Puedes usar el nombre o el número del canal, y el disparador en sí es una serie de caracteres:

0 o 1: Un valor bajo o alto en el pin.
r o f: Un valor ascendente o descendente en el pin. Una r corresponde efectivamente a 01.
e: Cualquier tipo de cambio en un pin (un flanco ascendente o descendente).

No todos los dispositivos admiten todos estos tipos de disparadores. Usa el comando --show para ver qué disparadores admite tu dispositivo.

-w, --wait-trigger
No generar ninguna dato de muestra (incluso si se recibe del hardware) antes de que se cumpla la condición del disparador. En otras palabras, no generar datos previos al disparador. Esta opción es útil si no te importan los datos que llegaron antes del disparador (pero el hardware entrega estos datos a sigrok de todos modos).
-P, --protocol-decoders <lista>
Esta opción permite al usuario especificar una lista de decodificadores de protocolo, separados por comas, que se utilizarán en esta sesión. Los decodificadores se especifican por su ID, como se muestra en la salida de -L (--list-supported).

Ejemplo:


$ sigrok-cli -i <archivo.sr> -P i2c

Cada decodificador de protocolo puede ir seguido opcionalmente por una lista de opciones separadas por dos puntos, donde cada opción tiene el formato clave=valor.

Ejemplo:


$ sigrok-cli -i <archivo.sr>
-P uart:baudrate=115200:parity_type=odd

La lista de opciones compatibles depende completamente del decodificador de protocolo. Cada decodificador de protocolo tiene diferentes opciones compatibles.

Cualquier "opción" especificada para un decodificador de protocolo que no sea una opción compatible real, se interpretará como asignaciones de nombre/número de canal.

Ejemplo:


$ sigrok-cli -i <archivo.sr>
-P spi:wordsize=9:miso=1:mosi=5:clk=3:cs=0

En este ejemplo, wordsize es una opción compatible con el decodificador de protocolo spi. Además, el usuario indica a sigrok que decodifique el protocolo SPI utilizando el canal 1 como señal MISO para SPI, el canal 5 como MOSI, el canal 3 como CLK y el canal 0 como señal CS#.

Observe que la aplicación sigrok-cli no admite la "coincidencia de nombres". En su lugar, se supone que las trazas en el flujo de entrada coinciden con el orden de las señales de entrada del decodificador, o que los usuarios especifican explícitamente el mapeo de canal de entrada a señal del decodificador.

Cuando se especifican varios decodificadores en la misma opción -P, se apilarán uno encima del otro en el orden especificado.

Ejemplo:


$ sigrok-cli -i <archivo.sr> -P i2c,eeprom24xx
$ sigrok-cli -i <archivo.sr> -P uart:baudrate=31250,midi

Cuando se especifican varias opciones -P, cada una de ellas crea una pila de decodificadores, que se ejecuta en paralelo a otras pilas de decodificadores.

Ejemplo:


$ sigrok-cli -i <archivo.sr> -P uart:tx=D0:rx=D1 -P timing:data=D2

-A, --protocol-decoder-annotations <anotaciones>
Por defecto, se muestra toda la salida de anotaciones de todos los decodificadores de protocolo. Con esta opción se pueden seleccionar las anotaciones de un decodificador específico para su visualización, especificando el ID del decodificador:


$ sigrok-cli -i <archivo.sr> -P i2c,i2cfilter,edid -A i2c

Si un decodificador de protocolo tiene varias clases de anotación, también puede especificar cuál de ellas mostrar especificando su descripción corta de esta manera:


$ sigrok-cli -i <archivo.sr> -P i2c,i2cfilter,edid
-A i2c=data-read

Seleccione varias clases de anotación separándolas con dos puntos:


$ sigrok-cli -i <archivo.sr> -P i2c,i2cfilter,edid
-A i2c=data-read:data-write

Los nombres de las filas de anotaciones se resolverán a su respectiva lista de clases. Los nombres de fila y clase se pueden usar en combinación. Cuando los nombres son ambiguos, las clases tienen prioridad.


$ sigrok-cli -i <archivo.sr> -P i2c
-A i2c=addr-data:warnings

También puede seleccionar varios decodificadores de protocolo, con clases de anotación opcionalmente seleccionadas para cada uno, separándolos con comas:


$ sigrok-cli -i <archivo.sr> -P i2c,i2cfilter,edid
-A i2c=data-read:data-write,edid

-M, --protocol-decoder-meta <nombre del decodificador de protocolo>
Cuando se proporciona, muestra la salida meta del decodificador de protocolo en lugar de las anotaciones. El argumento es el nombre del decodificador cuya salida meta se debe mostrar.


$ sigrok-cli -i <archivo.sr> -M i2c

No todos los decodificadores generan salida meta.

-B, --protocol-decoder-binary <especificación binaria>
Cuando se proporciona, los datos "crudos" del decodificador de varios tipos se escriben en stdout en lugar de anotaciones (esto podrían ser bytes UART/SPI crudos, o archivos WAV, archivos PCAP, archivos PNG, o cualquier otra cosa; esto depende completamente del decodificador y de qué tipos de salida binaria tengan sentido para ese decodificador).

No se imprime ninguna otra información en stdout, por lo que es adecuado para canalizar a otros programas o guardar en un archivo.

Los decodificadores de protocolo que admiten salida binaria publican una lista de clases binarias, por ejemplo, el decodificador UART podría tener "TX" y "RX". Para seleccionar TX para la salida, el argumento a esta opción sería:


$ sigrok-cli -i <archivo.sr> -B uart=tx

Si solo se especifica el decodificador de protocolo, sin clase binaria, todas las clases se escriben en stdout:


$ sigrok-cli -i <archivo.sr> -B uart

(esto solo es útil en casos raros, generalmente especificaría una clase binaria particular que le interese)

No todos los decodificadores generan salida binaria.

--protocol-decoder-samplenum
Cuando se proporciona, las anotaciones del decodificador también incluirán números de muestra. Esto permite a los consumidores recibir información de temporización legible por máquina.
-l, --loglevel <nivel>
Establece el nivel de registro de libsigrok y libsigrokdecode. En este momento, sigrok-cli no admite el establecimiento independiente de los dos niveles de registro. Cuanto mayor sea el número, más salida de depuración se imprimirá. Los niveles de registro válidos son:

0 Ninguno
1 Error
2 Advertencias
3 Informativo
4 Depuración
5 Chispeo

--show

Muestra información sobre la opción seleccionada. Por ejemplo, para ver las opciones de un dispositivo fx2lafw conectado:


$ sigrok-cli --driver fx2lafw --show

Para obtener correctamente las opciones del dispositivo para su hardware, algunos controladores podrían necesitar un puerto serie especificado:


$ sigrok-cli --driver ols:conn=/dev/ttyACM0 --show

Esto también funciona para decodificadores de protocolo, módulos de entrada y módulos de salida:


$ sigrok-cli --protocol-decoders i2c --show
$ sigrok-cli --input-format csv --show
$ sigrok-cli --output-format bits --show

Esto también funciona para archivos de entrada, incluyendo especificaciones opcionales de formato de entrada:


$ sigrok-cli --input-file <archivo.sr> --show
$ sigrok-cli --input-file <archivo.vcd> --input-format vcd --show

--scan
Busca dispositivos que se puedan detectar automáticamente.

Ejemplo:


$ sigrok-cli --scan
Los siguientes dispositivos fueron encontrados:
demo - Dispositivo de demostración con 12 canales: D0 D1 D2 D3 D4 D5 D6 D7 A0 A1 A2 A3
fx2lafw:conn=3.26 - CWAV USBee SX con 8 canales: 0 1 2 3 4 5 6 7

Sin embargo, no todos los dispositivos son autodete ctables (p.ej., los basados en puertos serie). Para estos, deberá proporcionar una opción conn, véase más arriba.


$ sigrok-cli --driver digitek-dt4000zc:conn=/dev/ttyUSB0 --scan
Los siguientes dispositivos fueron encontrados:
Digitek DT4000ZC con 1 canal: P1

--time <ms>
Muestra for <ms> milisegundos, luego salir.

Opcionalmente, puede seguir el número con s para especificar el tiempo de muestreo en segundos.

Por ejemplo, --time 2s tomará muestras durante dos segundos.

--samples <numsamples>
Adquiera <numsamples> muestras, luego salir.

Opcionalmente, puede seguir el número con k, m o g para especificar el número de muestras en kilosamples, megasamples o gigasamples, respectivamente.

Por ejemplo, --samples 3m adquirirá 3000000 muestras.

--frames <numframes>
Adquiera <numframes> fotogramas, luego salir.
--continuous
Muestrear continuamente hasta que se detenga. No todos los dispositivos soportan esto.
--get <variable>
Obtenga el valor de <variable> del dispositivo especificado e imprímalo. Se pueden especificar varios nombres de variables separados por dos puntos. La lista de nombres de variables opcionalmente puede ir precedida por channel_group=<name>, lo que anulará la especificación --channel-group. Se admiten múltiples ocurrencias de --get en una sola invocación de sigrok-cli.


$ sigrok-cli -d demo --get samplerate:averaging --get channel_group=Logic:pattern

--set
Establezca una o más variables especificadas con la opción --config, sin realizar ninguna adquisición.

EJEMPLOS

Para obtener exactamente 100 muestras del hardware del analizador lógico compatible con fx2lafw conectado, ejecute el siguiente comando:

sigrok-cli --driver fx2lafw --samples 100
Si desea tomar muestras de datos durante 3 segundos (3000 ms), utilice:
sigrok-cli --driver fx2lafw --time 3000
Alternativamente, también puede utilizar:
sigrok-cli --driver fx2lafw --time 3s
Para capturar datos de los primeros 4 canales utilizando el Openbench Logic Sniffer durante 100 ms a 10 MHz comenzando en la condición de activación
0:alto, 1:ascendente, 2:bajo, 3:alto, utilice:
sigrok-cli --driver ols:conn=/dev/ttyACM0 --config samplerate=10m \
--output-format bits --channels 0-3 --wait-trigger \
--triggers 0=1,1=r,2=0,3=1 --time 100
Para activar el registro interno en un dispositivo de la serie Lascar EL-USB:
sigrok-cli --driver lascar-el-usb:conn=10c4.0002 \
--config datalog=on --set

ESTADO DE SALIDA

sigrok-cli sale con 0 en caso de éxito, 1 en la mayoría de los fallos.
