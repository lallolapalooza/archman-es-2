SIEGE(1) Probador de carga Siege SIEGE(1)

NOMBRE

siege es una utilidad de prueba de carga y benchmarking HTTP/FTP.

SINOPSIS

siege [opciones]
siege [opciones] <URL>
siege [opciones] -g <URL>
siege [opciones] -f urls.txt

DESCRIPCIÓN

siege es una utilidad de prueba de carga y benchmarking HTTP/FTP multihilo. Soporta la mayoría de las características detalladas en las RFCs 2616 (HTTP) y 959 (FTP). Las propiedades se pueden establecer tanto desde la línea de comandos como en un archivo de configuración. Cuando la misma propiedad se establece en ambas ubicaciones, la línea de comandos tiene precedencia.

El archivo de configuración predeterminado es $HOME/.siege/siege.conf. Si no tienes un directorio $HOME/.siege y un archivo siege.conf y cookies.txt, siege generará un nuevo directorio de configuración cuando se ejecute. Puedes generar tu directorio de configuración con el siguiente comando: siege.config

OPCIONES

Sintaxis de opciones

siege soporta opciones largas y cortas. Las opciones cortas se ven así:
-c 25
-c25

Las opciones largas se ven así:
--concurrent=25

Valores de opciones

-V, --version
Muestra la versión de lanzamiento de siege y la información de copyright.
-h, --help
Imprime un mensaje de ayuda que describe las opciones de línea de comandos de siege.
-C, --config
Imprime un resumen detallado de todas las opciones configuradas actualmente, la mayoría de las cuales se envían en $HOME/.siege/siege.conf
-v, --verbose
Esta directiva pone a siege en modo detallado, que es en realidad una configuración predeterminada. Esta opción de línea de comandos es útil cuando el archivo de configuración está configurado como 'verbose = false', ya que te permitirá anular eso.

Por defecto, la salida detallada de siege se muestra en un estilo codificado por colores.
* HTTP 2xx está codificado en azul
* HTTP 3xx está codificado en cian
* HTTP 4xx está codificado en magenta
* HTTP 5xx está codificado en rojo
* HTTP en caché está codificado en negro

NOTA: Puedes desactivar el color en siege.conf así: 'color = off'

-q, --quiet
Esta directiva silencia a siege. Se utiliza principalmente para scripting y a menudo se usa junto con -g/--get. Puedes detectar el éxito o fracaso de la ejecución con su código de salida. 
siege --quiet -g www.joedog.org
if [ $? -eq 0 ] ; then
  echo "Éxito"
else
  echo "Fallo"
fi
-g URL, --get=URL
Esta opción te permite solicitar una URL y observar la transacción de encabezado. Hay una directiva de archivo de configuración correspondiente que te permite establecer el método de solicitud para estas solicitudes: gmethod = HEAD|GET 
$ siege -g "https://www.joedog.org/"

-c NUM, --concurrent=NUM
Esta opción te permite establecer el número de usuarios concurrentes. El número total de usuarios está técnicamente limitado por los recursos de tu computadora.

No deberías configurar más usuarios de los que tu servidor web está configurado para manejar. Por ejemplo, la configuración predeterminada de Apache está limitada a 255 hilos. Si ejecutas siege con -c 1024, entonces 769 usuarios de siege se quedarán esperando un manejador de Apache.

Por esta razón, la configuración predeterminada de siege está limitada a 255 usuarios. Puedes aumentar ese número dentro de siege.conf, pero si causas un problema, no nos culpes.

-r NUM, --reps=NUM|once
Esta opción le dice a cada usuario de siege cuántas veces debe ejecutarse. El valor generalmente debe ser un número mayor que cero, pero puede ser la palabra clave 'once'.

Si --reps=3, cada usuario de siege se ejecutará tres veces antes de salir. Sin embargo, si --reps=once, cada usuario recorrerá el archivo urls.txt exactamente una vez.

Para más información sobre el archivo urls.txt, ver la opción -f <archivo>, --file=<archivo>

-t NUMm, --time=NUMm
Esta opción es similar a --reps pero en lugar de especificar el número de veces que cada usuario debe ejecutarse, especifica la cantidad de tiempo que cada uno debe ejecutarse.

El formato del valor es "NUMm", donde "NUM" es una cantidad de tiempo y el modificador "m" es S, M o H para segundos, minutos y horas. Para ejecutar siege durante una hora, puedes seleccionar cualquiera de las siguientes combinaciones: -t3600S, -t60M, -t1H. El modificador no distingue entre mayúsculas y minúsculas, pero no requiere espacio entre el número y él mismo.

-d NUM, --delay=NUM
Esta opción instruye a siege cuánto tiempo esperar entre cada solicitud de página. El valor NUM representa el número de segundos entre cada una. Este número puede ser un valor decimal. De hecho, el valor predeterminado es medio segundo (--delay=0.5).

El tiempo entre solicitudes de retraso NO se tiene en cuenta en el tiempo de transacción. Si dos transacciones de 0.1 segundos tienen un retraso de 2 segundos entre ellas, su tiempo de transacción promedio es de 0.1 segundos. Se tiene en cuenta en el tiempo total transcurrido. En esta situación, el tiempo transcurrido sería de 2.2 segundos.

NOTA: cuando el analizador está habilitado (ver: -p/--parser), no hay retraso entre la página y sus elementos, es decir, hojas de estilo, javascripts, etc. El retraso es solo entre solicitudes de página.

-b, --benchmark
Esta directiva le indica a siege que entre en modo de benchmark. Esto significa que no hay retraso entre iteraciones.
-i, --internet
Esta opción pone a siege en lo que llamamos modo internet. Realiza solicitudes del archivo urls.txt (ver: -f <archivo> / --file=<archivo>) en orden aleatorio.
-f FILE, --file=FILE
Esta opción le dice a siege que trabaje con una lista de URLs dentro de un archivo de texto. Las URLs se listan una por línea. A diferencia de las URLs que se pasan como argumento de línea de comandos, las URLs en este archivo no deben entrecomillarse.

El analizador de urls.txt de siege soporta comentarios y variables. Dado que siege usa el signo de dólar ($) como prefijo para las variables escalares, deberías escapar cualquier variable que quieras enviar al servidor:

https://$(HOST)/siege/jsoner.php POS

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

T {"precio": "$10 por milla"}
-R FILE, --rc=FILE
Esta directiva te permite establecer un archivo de recursos alternativo. Por defecto, el archivo siegerc es $HOME/.siege/siege.conf Con esta directiva, puedes anular el valor predeterminado y usar un archivo alternativo .
-L FILE, --log=FILE
El archivo de registro predeterminado es $prefix/var/log/siege.log. Esta directiva te permite especificar un archivo alternativo para el registro.
-m "string", --mark="string"
Esta opción te permite registrar un mensaje en el archivo de registro antes de que tus estadísticas se escriban allí. Generalmente se usa para identificar la ejecución que procede. Podrías, por ejemplo, marcar el archivo con los parámetros de tu línea de comandos para que se entienda qué configuración generó los datos siguientes.
-H "encabezado: valor", --header="Encabezado: valor"
Esta opción te permite establecer un encabezado personalizado en la solicitud. Generalmente hablando, este encabezado anulará un encabezado existente. El encabezado Cookie es un caso especial. Si estableces -H "Cookie: valor" entonces siege enviará esa cookie además de las otras.
-A "string", --agent="string"
Esta opción te permite anular el user-agent predeterminado con uno personalizado. 
siege --agent="JoeDog Jr. en la onda"

Establecerá este encabezado:

User-agent: JoeDog Jr. en la onda

Alternativamente, podrías establecer el User-agent con la opción -H/--header anterior.

-T "texto", --content-type="texto"
Este es otro atajo para establecer encabezados. Usas esta opción para anular el encabezado de solicitud Content-type predeterminado.
--no-parser
Desactiva el analizador HTML. Cuando siege descarga una página, la analiza para elementos de página adicionales como hojas de estilo, javascript e imágenes. Hará solicitudes adicionales para cualquier elemento que encuentre. Con esta opción activada, siege se detendrá después de descargar la página principal.
--no-follow
Esta directiva le indica a siege que no siga las redirecciones 3xx.

FORMATO DE URL

siege admite los formatos de URL RFC 1738, pero se esfuerza por implementar atajos de uso común para tu conveniencia. Además de los formatos RFC 1738, siege introduce su propio formato de URL para indicar el método del protocolo.

Una URL RFC 1738 se ve así:
<esquema>://<usuario>:<contraseña>@<host>:<puerto>/<ruta>;<parámetros>?<consulta>#<fragmento>

Una URL de siege con un indicador de método se ve así:
<esquema>://<usuario>:<contraseña>@<host>:<puerto>/<ruta> POST <consulta>

También puedes enviar el contenido de un archivo usando el carácter de redirección de esta manera:
<esquema>://<usuario>:<contraseña>@<host>:<puerto>/<ruta> POST </home/jeff/haha.txt

Aquí hay dos ejemplos con el indicador de método de siege:
http://www.joedog.org/ POST haha=papa&dada=mama
ftp://ftp.armstrong.com/ PUT </home/jdfulmer/etc/tests/bbc.jpg

NOTA: Si estableces URLs con indicadores de método en la línea de comandos, entonces DEBES citar el argumento o tu shell lo tratará como tres argumentos separados. Si la URL está en un archivo urls.txt, entonces no deberías citarla.

Como se mencionó anteriormente, siege se esfuerza mucho para permitir atajos comúnmente utilizados a los que estás acostumbrado en la mayoría de las implementaciones de navegador. Trata muchas partes de la URL 1738 como opcionales. En este ejemplo, las partes entre corchetes son opcionales:
[esquema://] host.dominio.xxx [:puerto] [/ruta/archivo]

Cuando siege recibe un nombre de host, construye la URL con suposiciones predeterminadas. www.joedog.org se convierte en http://www.joedog.org:80/

ARCHIVO URLS.txt

De la sección Sintaxis de Opciones de arriba aprendemos que siege puede tomar una URL como argumento. siege -c -r2 www.joedog.org solicitará la página de índice de JoeDog dos veces. ¿Pero qué pasa si quieres acceder a grandes porciones del sitio? siege te permitirá llenar un archivo con URLs para que pueda recorrer la lista.

El formato para el archivo es una URL por línea:
https://www.joedog.org/
https://www.joedog.org/haha/
https://www.joedog.org/haha/ POST homer=simpson&marge=doestoo

El archivo también admite comentarios al estilo UNIX:
# El comentario se ve así
https://www.joedog.org/
https://www.joedog.org/haha/
https://www.joedog.org/haha/ POST homer=simpson&marge=doestoo

Admite la declaración y referencia de variables al estilo shell. Esto es conveniente si quieres ejecutar la misma prueba en dos niveles diferentes o dos esquemas diferentes:

ESQUEMA=https
HOST=bart.joedog.org
$(ESQUEMA)://$(HOST)/
$(ESQUEMA)://$(HOST)/haha/
$(ESQUEMA)://$(HOST)/haha/ POST homer=simpson&marge=doestoo

Puedes informarle a siege sobre este archivo con la opción -f/--file:
siege -c1 -r50 -f /home/jeff/urls.txt

ESTADÍSTICAS DE RENDIMIENTO

Cuando finaliza su ejecución, siege recopila datos de rendimiento de todos sus clientes y los resume después de la ejecución. (También puedes optar por registrar estos números). La salida de la línea de comandos está modelada según el script torture.pl de Lincoln Stein:

Transacciones:                   2000 accesos
Disponibilidad:                 100.00 %
Tiempo transcurrido:                  58.57 segs
Datos transferidos:               5.75 MB
Tiempo de respuesta:                0.25 segs
Tasa de transacciones:             34.15 trans/seg
Rendimiento:                     0.10 MB/seg
Concurrencia:                     8.45
Transacciones exitosas:        2000
Transacciones fallidas:               0
Transacción más larga:            4.62
Transacción más corta:            0.00
Transacciones
    Este número representa el número total de solicitudes HTTP. En este
    ejemplo, ejecutamos 25 usuarios simulados [-c25] y cada uno ejecutó diez veces
    [-r10]. Veinticinco veces diez es igual a 250, entonces ¿por qué el total de transacciones
    es 2000? Eso es porque siege cuenta cada solicitud. Esta ejecución
    incluyó una redirección META, una redirección 301 y la página que solicitó
    contenía varios elementos que también se descargaron.
Disponibilidad
    Este es el porcentaje de conexiones de socket manejadas con éxito
    por el servidor. Es el resultado de fallos de conexión (incluyendo
    tiempos de espera agotados) dividido por la suma de todos los intentos de conexión. Este
    número no incluye errores de servidor de nivel 400 y 500 que se registran
    en "Transacciones fallidas", descritas a continuación.
Tiempo transcurrido
    La duración de toda la prueba de siege. Se mide desde el
    momento en que el usuario invoca siege hasta que el último usuario simulado
    completa sus transacciones. Como se muestra arriba, la prueba tardó 58.57
    segundos en completarse.
Datos transferidos
    La suma de los datos transferidos a cada usuario simulado de siege. Incluye
    la información del encabezado así como el contenido. Debido a que incluye
    información del encabezado, el número reportado por siege será mayor que el número
    reportado por el servidor. En modo internet, que accede a URLs aleatorias en una configuración
    de archivo, se espera que este número varíe de una ejecución a otra.
Tiempo de respuesta
    El tiempo promedio que tardó en responder a las solicitudes de cada usuario simulado.
Tasa de transacciones
    El número promedio de transacciones que el servidor pudo manejar
    por segundo, en pocas palabras: es el recuento de todas las transacciones
    dividido por el tiempo transcurrido.
Rendimiento
    El número promedio de bytes transferidos cada segundo desde
    el servidor a todos los usuarios simulados.
Concurrencia
    Este es el número promedio de conexiones simultáneas. La métrica
    se calcula de esta manera: la suma de todos los tiempos de transacción dividida
    por el tiempo transcurrido (cuánto tiempo se ejecutó siege).
Transacciones exitosas
    El número de veces que el servidor respondió con un código de retorno < 400.
Transacciones fallidas
    El número de veces que fallaron las transacciones de socket, lo que incluye
    tiempos de espera agotados de socket.
Transacción más larga
    La mayor cantidad de tiempo que tomó una sola transacción, de
    todas las transacciones.
Transacción más corta
    La menor cantidad de tiempo que tomó una sola transacción, de
    todas las transacciones.
