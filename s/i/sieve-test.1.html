Paquete: pigeonhole

SIEVE-TEST(1) Dovecot SIEVE-TEST(1)

NOMBRE

sieve-test - probador de scripts Sieve de Pigeonhole

SINOPSIS

sieve-test [opciones] archivo-script archivo-correo

DESCRIPCIÓN


El comando sieve-test forma parte de Pigeonhole (pigeonhole(7)), que añade soporte para Sieve (RFC 5228) y ManageSieve (RFC 5804) a Dovecot (dovecot(1)).

Utilizando el comando sieve-test, se puede probar la ejecución de scripts Sieve. Esto evalúa el script para el mensaje proporcionado, produciendo un conjunto de acciones Sieve. A menos que se especifique la opción -e, en realidad no ejecuta estas acciones, lo que significa que no almacena ni reenvía el mensaje a ningún sitio. En su lugar, imprime una lista detallada de las acciones que normalmente se llevarían a cabo. Tenga en cuenta que, incluso cuando se especifica -e, nunca se transmiten mensajes a destinatarios SMTP remotos. Los mensajes salientes siempre se imprimen en stdout.

Esta es una herramienta muy útil para depurar la ejecución de scripts Sieve. Se puede utilizar para verificar que los scripts recién instalados se comportan según lo previsto y puede proporcionar información más detallada sobre los problemas de ejecución de scripts que son reportados por el plugin Sieve, por ejemplo, rastreando la ejecución y evaluación de comandos y pruebas respectivamente.

OPCIONES

-a direccion-destinatario-original

La dirección original del destinatario del sobre. Esto es lo que la prueba de sobre de Sieve comparará cuando se solicite la parte del sobre "to". Algunas pruebas y acciones también usarán esto como la dirección de correo electrónico del propietario del script. Si se omite esta opción, la dirección del destinatario se recupera de las cabeceras del mensaje "Envelope-To:" o "To:". Si tampoco está presente ninguna de estas cabeceras, la dirección del destinatario por defecto es recipient@example.com.

-c archivo-config

Ruta alternativa al archivo de configuración de Dovecot.

-C

Si la marca de tiempo de compilación es más reciente que la del archivo de script, se utiliza y no se vuelve a compilar el script. Esta opción fuerza la compilación del script, ignorando así cualquier binario presente. Consulte sievec(1) para obtener más información sobre la compilación de Sieve.

-D

Habilita la depuración de Sieve.

-d archivo-volcado

Provoca que se escriba un volcado del código generado en el archivo especificado. Esto es idéntico al volcado producido por sieve-dump(1). Usar '-' como nombre de archivo provoca que el volcado se escriba en stdout.

-e

Habilita la ejecución real del conjunto de acciones que resultan de la ejecución del script. Utilice el parámetro -o para especificar el controlador de correo (`mail_driver`), la ruta del correo (`mail_path`) y otras configuraciones de almacenamiento necesarias. Esto permite probar la entrega real de mensajes. Tenga en cuenta que esto no transmitirá ningún mensaje a destinatarios SMTP remotos. Dichas acciones solo imprimen el mensaje saliente en stdout.

-f remitente-sobre

La dirección del remitente del sobre (ruta de retorno). Esto es lo que la prueba de sobre de Sieve comparará cuando se solicite la parte del sobre "from". Además, es a donde se 'envían' los mensajes de respuesta. Si se omite esta opción, la dirección del remitente se recupera de las cabeceras del mensaje "Return-Path:", "Sender:" o "From:". Si tampoco está presente ninguna de estas cabeceras, la dirección del sobre del remitente por defecto es sender@example.com.

-m buzón-predeterminado

El buzón donde la acción `keep` almacena el mensaje. Es "INBOX" por defecto.

-o configuracion=valor

Anula la configuracion del archivo /etc/dovecot/dovecot.conf y de la base de datos de usuarios con el valor dado. Para anular múltiples configuraciones, la opción -o puede especificarse varias veces.

-r direccion-destinatario

La dirección final del destinatario del sobre. Algunas pruebas y acciones usarán esto como la dirección de correo electrónico del propietario del script. Por ejemplo, esto es lo que utiliza la acción `vacation` para comprobar si una respuesta es apropiada. Si se omite la opción -r, se utilizará la dirección original del destinatario del sobre (ver opción -a para más información).

-s archivo-script

Especifica scripts adicionales que se ejecutarán antes del script principal. Se permiten múltiples argumentos -s y los scripts especificados se ejecutan secuencialmente en el orden especificado en la línea de comandos.

-t archivo-traza

Habilita la depuración de traza en tiempo de ejecución. La depuración de traza proporciona información detallada sobre las operaciones realizadas por el script Sieve. Consulte la sección de depuración de traza en tiempo de ejecución a continuación. La información de traza se escribe en el archivo especificado. Usar '-' como nombre de archivo hace que los datos de traza se escriban en stdout.

-T opcion-traza

Configura la depuración de traza en tiempo de ejecución, que se habilita con la opción -t. Consulte la sección de depuración de traza en tiempo de ejecución a continuación.

-u usuario/mascara

Ejecuta el comando solo para el usuario dado. También es posible usar comodines '*' y '?' (por ejemplo, -u *example.org).

-x info-autenticacion

info-autenticacion especifica condiciones adicionales para el comando user. La cadena de opción info-autenticacion debe darse como un par nombre = valor. Para múltiples condiciones, la opción -x podría proporcionarse varias veces.

Los nombres posibles para info-autenticacion son:

service

El servicio para el que se debe probar la búsqueda en la base de datos de usuarios (`userdb`). El valor puede ser el nombre de un servicio, comúnmente utilizado con Dovecot. Por ejemplo: imap, pop3 o smtp.

session

Identificador de sesión.

lip

La dirección IP local (servidor) para la prueba.

rip

La dirección IP remota (cliente) para la prueba.

lport

El puerto local, por ejemplo, 143

rport

El puerto remoto, por ejemplo, 24567

real_lip

La IP local a la que el cliente se conectó en este host.

real_rip

La IP remota desde la que el cliente se conectó a este host.

real_lport

El puerto local al que el cliente se conectó a este host.

real_rport

El puerto remoto desde el que el cliente se conectó a este host.

forward_<campo>

Campo a reenviar como %{forward:campo} al proceso de autenticación.

ARGUMENTOS

archivo-script

Especifica el script a (compilar y) ejecutar.

Tenga en cuenta que esta herramienta busca un archivo binario precompilado con extensión .svbin y con nombre base y ruta idénticos al script especificado. Utilice la opción -C para deshabilitar este comportamiento forzando la compilación del script en un nuevo binario.

archivo-correo

Especifica el archivo que contiene el mensaje de correo electrónico para probar.

USO

RUNTIME TRACE DEBUGGING

Usando la opción -t, la herramienta sieve-test puede ser configurada para imprimir información detallada de rastreo sobre la ejecución del script Sieve a un archivo o a la salida estándar. Por ejemplo, se pueden imprimir los comandos encontrados, las pruebas realizadas y los valores coincidentes.

El rastreo en tiempo de ejecución puede configurarse usando la opción -T, que puede especificarse múltiples veces. Se puede usar de la siguiente manera:

-T level=...

Establece el nivel de detalle de la depuración de rastreo. Uno de los siguientes valores puede ser suministrado:

actions (por defecto) : Solo imprime comandos de acción ejecutados, como keep, fileinto, reject y redirect.

commands : Imprime cualquier comando ejecutado, excluyendo comandos de prueba.

tests : Imprime todos los comandos ejecutados y las pruebas realizadas.

matching : Imprime todos los comandos ejecutados, las pruebas realizadas y los valores coincidentes en esas pruebas.

-T debug

Imprime también mensajes de depuración. Esto suele ser útil solo para desarrolladores y probablemente producirá una salida desordenada.

-T addresses


opción o por el comando sieve-dump(1).

DEBUG EXTENSIÓN SIEVE

Para mejorar la depuración de scripts, esta implementación de Sieve soporta una extensión de lenguaje Sieve personalizada llamada 'vnd.dovecot.debug'. Añade el comando debug_log que permite registrar mensajes de depuración.

Ejemplo:

require "vnd.dovecot.debug";
if header :contains "subject" "hello" {
  debug_log "Subject header contains hello!";
}

, sievec(1) y sieve-dump(1) tienen soporte para la extensión vnd.dovecot.debug habilitada por defecto y no es necesario habilitar ni es posible deshabilitar la disponibilidad de la extensión de depuración con la

En contraste, para el plugin Sieve real para el LDA de Dovecot (dovecot-lda(1)) la extensión vnd.dovecot.debug necesita ser habilitada explícitamente usando la configuración sieve_extensions o la configuración sieve_global_extensions. Los mensajes se registrarán entonces en el archivo de registro de scripts privado del usuario. Si se usa en un script global, los mensajes se registrarán a través de la instalación de registro predeterminada de Dovecot.

ESTADO DE SALIDA

sieve-test saldrá con uno de los siguientes valores:

0

La ejecución fue exitosa. (EX_OK, EXIT_SUCCESS)

1

La operación falló. Esto se devuelve para casi todos los fallos. (EXIT_FAILURE)

64

Se proporcionó un parámetro inválido. (EX_USAGE)

/etc/dovecot/conf.d/90-sieve.conf

Configuración del intérprete Sieve (incluido desde el archivo de configuración principal de Dovecot)

REPORTE DE ERRORES

Reporte errores, incluyendo la salida de doveconf -n, a la Lista de Correo de Dovecot ⟨dovecot@dovecot.org⟩. La información sobre cómo reportar errores está disponible en: https://dovecot.org/bugreport.html
