NOMBRE

apptainer-test - Ejecutar las pruebas definidas por el usuario dentro de un contenedor

SINOPSIS

apptainer test [opciones de ejecución...]

DESCRIPCIÓN

El comando 'test' te permite ejecutar un script de prueba (si está disponible) dentro de
un contenedor dado.

NOTA:
En el caso de instancias si hay un proceso demonio ejecutándose dentro del contenedor,
los comandos subsiguientes del contenedor se ejecutarán dentro de los mismos
espacios de nombres. Esto significa que las opciones --writable y --contain no
serán honradas ya que los espacios de nombres ya han sido configurados por el
comando 'apptainer start'.

OPCIONES

--add-caps="" una lista de capacidades separadas por comas para añadir

--allow-setuid[=false] permitir binarios setuid en el contenedor (solo root)

--app="" establecer una aplicación para ejecutar dentro de un contenedor

--apply-cgroups="" aplicar cgroups desde un archivo para los procesos del contenedor (solo root)

--authfile="" archivo de autenticación estilo Docker para usar al escribir/leer credenciales de registro OCI

-B, --bind=[] una especificación de ruta de montaje de usuario. La especificación tiene el formato src[:dest[:opts]], donde src y dest son rutas externas e internas. Si no se proporciona dest, se establece igual a src. Las opciones de montaje ('opts') pueden especificarse como 'ro' (solo lectura) o 'rw' (lectura/escritura, que es el valor por defecto). Se pueden dar múltiples rutas de montaje mediante una lista separada por comas.

--blkio-weight=0 peso relativo de Block IO en el rango 10-1000, 0 para deshabilitar

--blkio-weight-device=[] peso relativo de Block IO específico del dispositivo

-e, --cleanenv[=false] limpiar el entorno antes de ejecutar el contenedor

--compat[=false] aplicar configuraciones para una mayor compatibilidad OCI/Docker. Infiere --containall, --no-init, --no-umask, --no-eval, --writable-tmpfs.

-c, --contain[=false] usar /dev mínimo y vaciar otros directorios (por ejemplo, /tmp y $HOME) en lugar de compartir sistemas de archivos de tu host

-C, --containall[=false] contener no solo sistemas de archivos, sino también PID, IPC y entorno

--cpu-shares=-1 cuotas de CPU para el contenedor

--cpus="" Número de CPUs disponibles para el contenedor

--cpuset-cpus="" Lista de CPUs del host disponibles para el contenedor

--cpuset-mems="" Lista de nodos de memoria del host disponibles para el contenedor

--cwd="" directorio de trabajo inicial para el proceso de carga útil dentro del contenedor (sinónimo de --pwd)

--disable-cache[=false] no usar ni crear caché

--dns="" lista de servidores DNS separados por comas para añadir en resolv.conf

--docker-host="" especificar un host demonio Docker personalizado

--docker-login[=false] iniciar sesión en un Repositorio Docker interactivamente

--drop-caps="" una lista de capacidades separadas por comas para eliminar

--env=[] pasar variable de entorno al proceso contenido

--env-file=[] pasar variables de entorno desde un archivo al proceso contenido

-f, --fakeroot[=false] ejecutar el contenedor con la apariencia de estar ejecutándose como root

--fusemount=[] una especificación de montaje de sistema de archivos FUSE del formato ': ' - donde es 'container' o 'host', especificando dónde se realizará el montaje ('container-daemon' o 'host-daemon' ejecutarán el proceso FUSE de forma desvinculada). es la ruta al ejecutable FUSE, más opciones para el montaje. es la ubicación en el contenedor donde se adjuntará el montaje FUSE. Por ejemplo: 'container:sshfs 10.0.0.1:/ /sshfs'. Implica --pid.

-h, --help[=false] ayuda para test

-H, --home="/build" una especificación de directorio home. La especificación puede ser una ruta src o un par src:dest. src es la ruta de origen del directorio home fuera del contenedor y dest sobrescribe el directorio home dentro del contenedor.

--hostname="" establecer el nombre de host del contenedor

-i, --ipc[=false] ejecutar el contenedor en un nuevo espacio de nombres IPC

--keep-privs[=false] permitir que el usuario root conserve privilegios en el contenedor (solo root)

--memory="" límite de memoria en bytes

--memory-reservation="" límite suave de memoria en bytes

--memory-swap="" límite de swap, usar -1 para swap ilimitado

--mount=[] una especificación de montaje por ejemplo 'type=bind,source=/opt,destination=/hostopt'.

-n, --net[=false] ejecutar el contenedor en un nuevo espacio de nombres de red (configura una interfaz de red bridge por defecto)

--netns-path="" unirse al espacio de nombres de red en la ruta especificada (como root, o si está permitido en apptainer.conf)

--network="" especificar el tipo de red deseado separado por comas, cada red activará una interfaz dedicada dentro del contenedor

--network-args=[] especificar argumentos de red para pasar a los plugins CNI

--no-eval[=false] no evaluar variables de entorno ni comandos/entradas/argumentos del contenedor OCI mediante shell

--no-home[=false] NO montar el directorio home del usuario si /home no es el directorio de trabajo actual

--no-https[=false] usar http en lugar de https para URIs docker://, oras:// y library:///...

--no-init[=false] NO iniciar el proceso shim con --pid

--no-mount=[] deshabilitar una o más opciones 'mount xxx' establecidas en apptainer.conf y/o especificar una ruta de destino absoluta para deshabilitar una entrada de ruta de enlace, o 'bind-paths' para deshabilitar todas las entradas de ruta de enlace.

--no-pid[=false] no ejecutar el contenedor en un nuevo espacio de nombres PID

--no-privs[=false] eliminar todos los privilegios del usuario root en el contenedor)

--no-umask[=false] no propagar umask al contenedor, establecer umask por defecto 0022

--nv[=false] habilitar soporte Nvidia

--nvccli[=false] usar nvidia-container-cli para la configuración de GPU (experimental)

--oom-kill-disable[=false] Deshabilitar el asesino OOM

-o, --overlay=[] usar una imagen overlayFS para almacenamiento persistente de datos o como capa de solo lectura del contenedor

--passphrase[=false] solicitar una frase de contraseña de cifrado

--pem-path="" introducir una ruta a una clave RSA con formato PEM para un contenedor cifrado

-p, --pid[=false] ejecutar el contenedor en un nuevo espacio de nombres PID

--pids-limit=0 limitar el número de PIDs del contenedor, usar -1 para ilimitado

--rocm[=false] habilitar soporte Rocm experimental

-S, --scratch=[] incluir un directorio de rascado dentro del contenedor que está enlazado a un directorio temporal (usar -W para forzar la ubicación)

--security=[] habilitar características de seguridad (SELinux, Apparmor, Seccomp)

--sharens[=false] compartir el espacio de nombres y la imagen con otros contenedores lanzados desde el mismo proceso padre

--unsquash[=false] convertir archivo SIF a sandbox temporal antes de ejecutar

-u, --userns[=false] ejecutar el contenedor en un nuevo espacio de nombres de usuario

--uts[=false] ejecutar el contenedor en un nuevo espacio de nombres UTS

-W, --workdir="" directorio de trabajo a ser utilizado para /tmp, /var/tmp y $HOME (si también se usó -c/--contain)

-w, --writable[=false] por defecto, todos los contenedores de Apptainer están disponibles como solo lectura. Esta opción hace que el sistema de archivos sea accesible como lectura/escritura.

--writable-tmpfs[=false] hace que el sistema de archivos sea accesible como lectura/escritura con datos no persistentes (solo con soporte overlay)

EJEMPLO

  Establece la sección '%test' con un archivo de definición como este:
  %test
      echo "hola desde test" "$@"
  $ apptainer test /tmp/debian.sif comando
      hola desde test comando
