NOMBRE

apptainer-exec - Ejecutar un comando dentro de un contenedor

SINOPSIS

apptainer exec [opciones-ejecutar...]

DESCRIPCIÓN

apptainer exec soporta los siguientes formatos:

*.sif Formato de imagen Singularity (SIF). Nativo de Singularity
(3.0+) y Apptainer (v1.0.0+)

*.sqsh Formato SquashFS. Nativo de Singularity 2.4+

*.img Formato ext3. Nativo de versiones de Singularity < 2.4.

directorio/ Formato de sandbox. Directorio que contiene un sistema de archivos raíz válido
y opcionalmente metadatos de Apptainer.

instance://* Una instancia local en ejecución de un contenedor. (Ver el grupo
de comandos instance.)

library://* Un contenedor SIF alojado en una Biblioteca (ninguna por defecto)

docker://* Un contenedor Docker/OCI alojado en Docker Hub o en otro
registro OCI.

shub://* Un contenedor alojado en Singularity Hub.

oras://* Un contenedor SIF alojado en un registro OCI que soporta
la especificación OCI Registry As Storage (ORAS).

OPCIONES

--add-caps="" una lista de capacidades separada por comas para añadir

--allow-setuid[=false] permite binarios setuid en el contenedor (solo root)

--app="" establece una aplicación para ejecutar dentro de un contenedor

--apply-cgroups="" aplica cgroups de un archivo para los procesos del contenedor (solo root)

--authfile="" archivo de autenticación estilo Docker para usar al escribir/leer credenciales del registro OCI

-B, --bind=[] una especificación de ruta de montaje de usuario. la especificación tiene el formato src[:dest[:opts]], donde src y dest son rutas externas e internas. Si dest no se proporciona, se establece igual a src. Las opciones de montaje ('opts') pueden especificarse como 'ro' (solo lectura) o 'rw' (lectura/escritura, que es el valor predeterminado). Se pueden dar múltiples rutas de montaje como una lista separada por comas.

--blkio-weight=0 peso relativo de I/O de bloque en el rango 10-1000, 0 para deshabilitar

--blkio-weight-device=[] peso relativo de I/O de bloque específico del dispositivo

-e, --cleanenv[=false] limpia el entorno antes de ejecutar el contenedor

--compat[=false] aplica configuraciones para mayor compatibilidad OCI/Docker. Infiere --containall, --no-init, --no-umask, --no-eval, --writable-tmpfs.

-c, --contain[=false] usa un /dev mínimo y vacía otros directorios (por ejemplo, /tmp y $HOME) en lugar de compartir sistemas de archivos del host

-C, --containall[=false] contiene no solo sistemas de archivos, sino también PID, IPC y entorno

--cpu-shares=-1 comparticiones de CPU para el contenedor

--cpus="" número de CPUs disponibles para el contenedor

--cpuset-cpus="" lista de CPUs del host disponibles para el contenedor

--cpuset-mems="" lista de nodos de memoria del host disponibles para el contenedor

--cwd="" directorio de trabajo inicial para el proceso de carga útil dentro del contenedor (sinónimo de --pwd)

--disable-cache[=false] no usar ni crear caché

--dns="" lista de servidores DNS separados por comas para añadir en resolv.conf

--docker-host="" especifica un host de demonio Docker personalizado

--docker-login[=false] inicia sesión en un repositorio Docker interactivamente

--drop-caps="" una lista de capacidades separada por comas para eliminar

--env=[] pasa la variable de entorno al proceso contenido

--env-file=[] pasa variables de entorno desde un archivo al proceso contenido

-f, --fakeroot[=false] ejecuta el contenedor con la apariencia de ejecutarse como root

--fusemount=[] una especificación de montaje de sistema de archivos FUSE del formato ': ' - donde es 'container' o 'host', especificando dónde se realizará el montaje ('container-daemon' o 'host-daemon' ejecutará el proceso FUSE de forma separada). es la ruta al ejecutable FUSE, más las opciones para el montaje. es la ubicación en el contenedor donde se adjuntará el montaje FUSE. Por ejemplo, 'container:sshfs 10.0.0.1:/ /sshfs'. Implica --pid.

-h, --help[=false] ayuda para exec

-H, --home="/build" una especificación de directorio home. src puede ser una ruta o un par src:dest. src es la ruta de origen del directorio home fuera del contenedor y dest reemplaza el directorio home dentro del contenedor.

--hostname="" establece el nombre de host del contenedor

-i, --ipc[=false] ejecuta el contenedor en un nuevo espacio de nombres IPC

--keep-privs[=false] permite al usuario root mantener privilegios en el contenedor (solo root)

--memory="" límite de memoria en bytes

--memory-reservation="" límite suave de memoria en bytes

--memory-swap="" límite de swap, usa -1 para swap ilimitado

--mount=[] una especificación de montaje, por ejemplo, 'type=bind,source=/opt,destination=/hostopt'.

-n, --net[=false] ejecuta el contenedor en un nuevo espacio de nombres de red (configura una interfaz de red bridge por defecto)

--netns-path="" une al espacio de nombres de red en la ruta especificada (como root, o si está permitido en apptainer.conf)

--network="" especifica el tipo de red deseado separado por comas, cada red levantará una interfaz dedicada dentro del contenedor

--network-args=[] especifica argumentos de red para pasar a los plugins CNI

--no-eval[=false] no evalúa shell para variables de entorno o CMD/ENTRYPOINT/ARGS del contenedor OCI

--no-home[=false] NO monta el directorio home del usuario si /home no es el directorio de trabajo actual

--no-https[=false] usa http en lugar de https para las URIs docker://, oras:// y library://...

--no-init[=false] NO inicia el proceso shim con --pid

--no-mount=[] deshabilita una o más opciones 'mount xxx' establecidas en apptainer.conf y/o especifica una ruta de destino absoluta para deshabilitar una entrada de ruta de montaje, o 'bind-paths' para deshabilitar todas las entradas de rutas de montaje.

--no-pid[=false] no ejecuta el contenedor en un nuevo espacio de nombres PID

--no-privs[=false] elimina todos los privilegios del usuario root en el contenedor)

--no-umask[=false] no propaga umask al contenedor, establece la umask predeterminada 0022

--nv[=false] habilita el soporte Nvidia

--nvccli[=false] usa nvidia-container-cli para la configuración de GPU (experimental)

--oom-kill-disable[=false] deshabilita el killer OOM

-o, --overlay=[] usa una imagen overlayFS para almacenamiento persistente de datos o como capa de solo lectura del contenedor

--passphrase[=false] solicita una contraseña de cifrado

--pem-path="" introduce una ruta a una clave RSA en formato PEM para un contenedor cifrado

-p, --pid[=false] ejecuta el contenedor en un nuevo espacio de nombres PID

--pids-limit=0 limita el número de PIDs del contenedor, usa -1 para ilimitado

--rocm[=false] habilita el soporte experimental Rocm

-S, --scratch=[] incluye un directorio scratch dentro del contenedor que está enlazado a un directorio temporal (usa -W para forzar la ubicación)

--security=[] habilita características de seguridad (SELinux, Apparmor, Seccomp)

--sharens[=false] comparte el espacio de nombres y la imagen con otros contenedores iniciados desde el mismo proceso padre

--unsquash[=false] convierte el archivo SIF a un sandbox temporal antes de ejecutar

-u, --userns[=false] ejecuta el contenedor en un nuevo espacio de nombres de usuario

--uts[=false] ejecuta el contenedor en un nuevo espacio de nombres UTS

-W, --workdir="" directorio de trabajo a usar para /tmp, /var/tmp y $HOME (si también se usó -c/--contain)

-w, --writable[=false] por defecto, todos los contenedores Apptainer están disponibles como solo lectura. Esta opción hace que el sistema de archivos sea accesible como lectura/escritura.

--writable-tmpfs[=false] hace que el sistema de archivos sea accesible como lectura/escritura con datos no persistentes (solo con soporte overlay)

EJEMPLO

  $ apptainer exec /tmp/debian.sif cat /etc/debian_version
  $ apptainer exec /tmp/debian.sif python ./hello_world.py
  $ cat hello_world.py | apptainer exec /tmp/debian.sif python
  $ sudo apptainer exec --writa

NOMBRE

apptainer-exec - Ejecuta un comando en un contenedor de Apptainer

SINOPSIS

apptainer exec [ejecución]
apptainer exec [opciones] imagen [argumentos...]

DESCRIPCIÓN

El comando apptainer exec ejecuta un comando específico dentro de un contenedor especificado.

Si no se proporcionan argumentos de comando, se ejecutará el comando shell predeterminado o el shell especificado por $SHELL dentro del contenedor.

En el modo de ejecución de instancia, apptainer exec ejecutará el comando dentro de la instancia especificada.

OPCIONES

--config ruta
Especifique un archivo de configuración de Apptainer alternativo.
--contain
Ejecuta el contenedor de forma contenida, es decir, con todos los enlaces de la sesión y los puntos de montaje deshabilitados.
--containall
Ejecuta el contenedor de forma totalmente contenida, es decir, con todos los enlaces de la sesión, puntos de montaje y el directorio home deshabilitados.
--env-file ruta
Carga las variables de entorno del archivo especificado.
--help
Ayuda sobre apptainer-exec.
--home ruta
Establece la variable de entorno HOME dentro del contenedor.
--hostname nombre_host
Establece el nombre de host dentro del contenedor.
--no-home
No montar el directorio home del host dentro del contenedor.
--no-mount tipo
No montar el tipo especificado (por ejemplo, home, tmpfs, system).
--no-privs
Ejecuta el contenedor sin privilegios.
--overlay ruta
Utiliza un overlay en la imagen especificada.
--password archivo
Archivo que contiene la contraseña para desbloquear un contenedor cifrado.
--pid-namespace ns
Especifica el espacio de nombres PID para el contenedor. Las opciones válidas son host o private.
--quiet
Suprime la salida detallada.
--remote
Ejecuta un contenedor remoto.
--shell ruta_shell
Especifica el shell a usar dentro del contenedor.
--security perfil
Permite especificar un perfil de seguridad (por ejemplo, seccomp).
--writable espacio
Hace que la imagen especificada sea escribible.

EJEMPLO

Para ejecutar el comando ls -l dentro de un contenedor de Debian:

  $ apptainer exec /ruta/a/debian.sif ls -l

Para ejecutar el comando apt-get update dentro de un contenedor de Debian como una instancia llamada my_instance:

  $ apptainer exec instance://my_instance apt-get update
  $ apptainer exec instance://my_instance ps -ef
  $ apptainer exec library://centos cat /etc/os-release
