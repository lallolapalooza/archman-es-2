signalfd(2) System Calls Manual signalfd(2)

NOMBRE

signalfd - crea un descriptor de archivo para aceptar señales

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/signalfd.h>
int signalfd(int fd, const sigset_t *mask, int flags);

DESCRIPCIÓN

signalfd() crea un descriptor de archivo que se puede usar para aceptar señales dirigidas al llamante. Esto proporciona una alternativa al uso de un manejador de señales o sigwaitinfo(2), y tiene la ventaja de que el descriptor de archivo puede ser monitoreado por select(2), poll(2) y epoll(7).

El argumento mask especifica el conjunto de señales que el llamante desea aceptar a través del descriptor de archivo. Este argumento es un conjunto de señales cuyos contenidos pueden ser inicializados usando las macros descritas en sigsetops(3). Normalmente, el conjunto de señales que se recibirán a través del descriptor de archivo debe ser bloqueado usando sigprocmask(2), para evitar que las señales sean manejadas de acuerdo con sus disposiciones predeterminadas. No es posible recibir las señales SIGKILL o SIGSTOP a través de un descriptor de archivo signalfd; estas señales se ignoran silenciosamente si se especifican en mask.

Si el argumento fd es -1, entonces la llamada crea un nuevo descriptor de archivo y asocia el conjunto de señales especificado en mask con ese descriptor de archivo. Si fd no es -1, entonces debe especificar un descriptor de archivo signalfd válido existente, y mask se usa para reemplazar el conjunto de señales asociado con ese descriptor de archivo.

A partir de Linux 2.6.27, los siguientes valores pueden ser ORados bitwise en flags para cambiar el comportamiento de signalfd():

SFD_NONBLOCK
Establece la bandera de estado de archivo O_NONBLOCK en la descripción de archivo (ver open(2)) referida por el nuevo descriptor de archivo. Usar esta bandera ahorra llamadas adicionales a fcntl(2) para lograr el mismo resultado.
SFD_CLOEXEC
Establece la bandera de cierre al ejecutar (FD_CLOEXEC) en el nuevo descriptor de archivo. Ver la descripción de la bandera O_CLOEXEC en open(2) para las razones por las que esto puede ser útil.

Hasta Linux 2.6.26, el argumento flags no se usa y debe especificarse como cero.

signalfd() devuelve un descriptor de archivo que soporta las siguientes operaciones:

read(2)
Si una o más de las señales especificadas en mask están pendientes para el proceso, entonces el búfer suministrado a read(2) se usa para devolver una o más estructuras signalfd_siginfo (ver abajo) que describen las señales. La lectura(2) devuelve información para tantas señales como estén pendientes y quepan en el búfer suministrado. El búfer debe tener al menos sizeof(struct signalfd_siginfo) bytes. El valor de retorno de la lectura(2) es el número total de bytes leídos.
Como consecuencia de la lectura(2), las señales se consumen, de modo que ya no están pendientes para el proceso (es decir, no serán capturadas por manejadores de señales, ni podrán ser aceptadas usando sigwaitinfo(2)).
Si ninguna de las señales en mask está pendiente para el proceso, entonces la lectura(2) se bloquea hasta que una de las señales en mask se genere para el proceso, o falla con el error EAGAIN si el descriptor de archivo se ha puesto en modo no bloqueante.
poll(2)
select(2)
(y similares)
El descriptor de archivo es legible (el argumento readfds de select(2); la bandera POLLIN de poll(2)) si una o más de las señales en mask están pendientes para el proceso.
El descriptor de archivo signalfd también soporta las otras APIs de multiplexación de descriptores de archivo: pselect(2), ppoll(2) y epoll(7).
close(2)
Cuando el descriptor de archivo ya no sea necesario, debe ser cerrado. Cuando todos los descriptores de archivo asociados con el mismo objeto signalfd hayan sido cerrados, los recursos para el objeto son liberados por el kernel.

La estructura signalfd_siginfo

El formato de las estructuras signalfd_siginfo devueltas por las lecturas(2) desde un descriptor de archivo signalfd es el siguiente:


struct signalfd_siginfo {
    uint32_t ssi_signo;    /* Signal number */
    int32_t  ssi_errno;    /* Error number (unused) */
    int32_t  ssi_code;     /* Signal code */
    uint32_t ssi_pid;      /* PID of sender */
    uint32_t ssi_uid;      /* Real UID of sender */
    int32_t  ssi_fd;       /* File descriptor (SIGIO) */
    uint32_t ssi_tid;      /* Kernel timer ID (POSIX timers)
    uint32_t ssi_band;     /* Band event (SIGIO) */
    uint32_t ssi_overrun;  /* POSIX timer overrun count */
    uint32_t ssi_trapno;   /* Trap number that caused signal */
    int32_t  ssi_status;   /* Exit status or signal (SIGCHLD) */
    int32_t  ssi_int;      /* Integer sent by sigqueue(3) */
    uint64_t ssi_ptr;      /* Pointer sent by sigqueue(3) */
    uint64_t ssi_utime;    /* User CPU time consumed (SIGCHLD) */
    uint64_t ssi_stime;    /* System CPU time consumed
                              (SIGCHLD) */
    uint64_t ssi_addr;     /* Address that generated signal
                              (for hardware-generated signals) */
    uint16_t ssi_addr_lsb; /* Least significant bit of address
                              (SIGBUS; since Linux 2.6.37) */
    uint8_t  pad[X];       /* Pad size to 128 bytes (allow for
                              additional fields in the future) */
};

Cada uno de los campos de esta estructura es análogo al campo con el mismo nombre en la estructura siginfo_t. La estructura siginfo_t se describe en sigaction(2). No todos los campos en la estructura signalfd_siginfo devuelta serán válidos para una señal específica; el conjunto de campos válidos se puede determinar a partir del valor devuelto en el campo ssi_code. Este campo es el análogo del campo si_code de siginfo_t; ver sigaction(2) para más detalles.

Semántica de fork(2)

Después de un fork(2), el hijo hereda una copia del descriptor de archivo signalfd. Una lectura(2) del descriptor de archivo en el hijo devolverá información sobre las señales puestas en cola para el hijo.

Semántica del paso de descriptores de archivo

Al igual que con otros descriptores de archivo, los descriptores de archivo signalfd pueden ser pasados a otro proceso a través de un socket de dominio UNIX (ver unix(7)). En el proceso receptor, una lectura(2) del descriptor de archivo recibido devolverá información sobre las señales puestas en cola para ese proceso.

Semántica de execve(2)

Al igual que cualquier otro descriptor de archivo, un descriptor de archivo signalfd permanece abierto a través de un execve(2), a menos que haya sido marcado para cierre al ejecutar (ver fcntl(2)). Las señales que estaban disponibles para lectura antes del execve(2) permanecen disponibles para el programa recién cargado. (Esto es análogo a la semántica tradicional de señales, donde una señal bloqueada que está pendiente permanece pendiente a través de un execve(2).)

NOMBRE

signalfd - crear un descriptor de archivo para la recopilación de señales

SINOPSIS

#include <sys/signalfd.h>
int signalfd(int fd, const sigset_t *mask, int flags);

Según lo requerido por la interfaz de C, también:

#include <sys/types.h>
int signalfd(int fd, const sigset_t *mask, int flags);

DESCRIPCIÓN

La llamada al sistema signalfd() crea un nuevo descriptor de archivo o reutiliza un descriptor de archivo existente que se refiere a un dispositivo de E/S anónimo especial. Este descriptor de archivo se puede utilizar para recopilar señales que se enviarán al proceso.

El argumento fd es un descriptor de archivo existente o -1. Si fd es -1, entonces signalfd() crea un nuevo descriptor de archivo. Si fd es un descriptor de archivo existente, debe ser un descriptor de archivo de señal previamente creado; en este caso, se puede cambiar la máscara de señales y las banderas asociadas con él. Al cerrar el descriptor de archivo existente, se liberará el recurso asociado.

El argumento mask especifica un conjunto de señales que se recopilarán. Las señales especificadas en mask deben estar bloqueadas en el proceso o en el hilo que llama. Si una señal que se especifica en mask no está bloqueada, el comportamiento es indefinido.

El argumento flags es una máscara de bits que se utiliza para controlar el comportamiento del descriptor de archivo de señal. Los únicos valores de bandera permitidos actualmente son 0.

Cada vez que una señal especificada en mask se entrega al proceso, se genera un evento que se puede leer del descriptor de archivo de señal. La lectura desde el descriptor de archivo de señal devolverá una estructura struct signalfd_siginfo que contiene información sobre la señal. La estructura se define como sigue:

struct signalfd_siginfo {
    siginfo_t ssi_signo;   /* Número de señal */
    siginfo_t ssi_errno;   /* Número de error si aplica */
    siginfo_t ssi_lcore;   /* Número de CPU que recibió la señal (a partir de Linux 3.9) */
    siginfo_t ssi_pid;     /* PID del remitente (a partir de Linux 3.9) */
    siginfo_t ssi_uid;     /* UID del remitente (a partir de Linux 3.9) */
    siginfo_t ssi_fd;      /* Descriptor de archivo si la señal fue enviada vía
                                  splice(2) o tee(2) (a partir de Linux 3.9) */
    siginfo_t ssi_tid;     /* ID del hilo que envió la señal (a partir de Linux 3.9) */
    siginfo_t ssi_band;    /* Evento de I/O si la señal fue enviada por
                                  aio_read(3) o similar (a partir de Linux 3.9) */
    siginfo_t ssi_overrun; /* Contador de sobrecarga para señales de temporizador
                                  (a partir de Linux 3.9) */
    siginfo_t ssi_trapno;  /* Número de interrupción de hardware (a partir de Linux 3.9) */
    siginfo_t ssi_status;  /* Estado de salida o señal de terminación del
                                  proceso hijo (a partir de Linux 3.9) */
    siginfo_t ssi_int;     /* Valor entero pasado con sigqueue(3) (a partir de Linux 3.9) */
    siginfo_t ssi_ptr;     /* Puntero pasado con sigqueue(3) (a partir de Linux 3.9) */
    siginfo_t ssi_utime;   /* Tiempo de CPU del usuario del proceso hijo
                                  terminado (a partir de Linux 3.9) */
    siginfo_t ssi_stime;  /* Tiempo de CPU del sistema del proceso hijo
                                  terminado (a partir de Linux 3.9) */
    siginfo_t ssi_addr;    /* Dirección de memoria implicada en la señal
                                  (a partir de Linux 3.9) */
    siginfo_t ssi_syscall; /* Nombre de la llamada al sistema que causó la señal
                                  (a partir de Linux 3.9) */
    siginfo_t ssi_call_addr; /* Dirección de la llamada al sistema que causó la señal
                                  (a partir de Linux 3.9) */
    siginfo_t ssi_seq;     /* Secuencia de la llamada al sistema que causó la señal
                                  (a partir de Linux 3.9) */
    siginfo_t ssi_timer;   /* ID del temporizador que generó la señal (a partir
                                  de Linux 3.9) */
    siginfo_t ssi_overrun; /* Contador de sobrecarga para temporizadores (a
                                  partir de Linux 3.9) */
};

Los campos de ssi_signo, ssi_errno, ssi_addr, y otros campos no son parte de la estructura siginfo_t definida en <signal.h>, pero son campos adicionales en la estructura signalfd_siginfo.

Los campos ssi_int y ssi_ptr están disponibles a partir de Linux 2.6.26. Antes de eso, solo se rellenaban si se enviaba una señal con sigqueue().

Los campos ssi_pid, ssi_uid, ssi_tid, ssi_band, ssi_overrun, ssi_trapno, ssi_status, ssi_int, ssi_ptr, ssi_utime, ssi_stime, ssi_addr, ssi_syscall, ssi_call_addr, ssi_seq, ssi_timer, ssi_overrun y ssi_lcore están disponibles a partir de Linux 3.9.

La lectura de un descriptor de archivo de señal se bloqueará si no hay ninguna señal pendiente para ser leída. Si se leen múltiples señales entre dos lecturas, se pueden agrupar en una sola lectura del descriptor de archivo de señal.

Un descriptor de archivo de señal soporta las operaciones de E/S estándar, incluyendo la lectura, la escritura (que falla con EINVAL), la operación ioctl (que falla con ENOTTY), la espera con poll(2) y epoll(7), y la apertura con fcntl(2).

Es posible tener varios descriptores de archivo de señal para el mismo proceso. Si se produce una señal que está presente en la máscara de varios descriptores de archivo de señal, se puede leer (una vez) de cualquiera de ellos.

Las señales SIGKILL y SIGSTOP no se pueden recopilar y se ignoran silenciosamente si se incluyen en la máscara.

Semántica de hilos

La semántica de los descriptores de archivo de señal en un programa multihilo refleja la semántica estándar para las señales. En otras palabras, cuando un hilo lee de un descriptor de archivo de señal, leerá las señales que están dirigidas al propio hilo y las señales que están dirigidas al proceso (es decir, a todo el grupo de hilos). (Un hilo no podrá leer señales que estén dirigidas a otros hilos del proceso).

Semántica de epoll(7)

Si un proceso añade (a través de epoll_ctl(2)) un descriptor de archivo de señal a una instancia de epoll(7), entonces epoll_wait(2) devuelve eventos solo para señales enviadas a ese proceso. En particular, si el proceso utiliza fork(2) para crear un proceso hijo, entonces el hijo podrá leer (usando read(2)) las señales que se le envían utilizando el descriptor de archivo de señal, pero epoll_wait(2) no indicará que el descriptor de archivo de señal está listo. En este escenario, una posible solución es que después de la llamada a fork(2), el proceso hijo cierre el descriptor de archivo de señal que heredó del proceso padre y luego cree otro descriptor de archivo de señal y lo añada a la instancia de epoll. Alternativamente, el padre y el hijo podrían retrasar la creación de sus descriptores de archivo de señal (separados) y añadirlos a la instancia de epoll hasta después de la llamada a fork(2).

VALOR DE RETORNO

En caso de éxito, signalfd() devuelve un descriptor de archivo de señal; este es bien un nuevo descriptor de archivo (si fd era -1), o fd si fd era un descriptor de archivo de señal válido. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EBADF
El descriptor de archivo fd no es un descriptor de archivo válido.
EINVAL
fd no es un descriptor de archivo de señal válido.
EINVAL
flags es inválido; o, en Linux 2.6.26 o anterior, flags es distinto de cero.
EMFILE
Se ha alcanzado el límite por proceso en el número de descriptores de archivo abiertos.
ENFILE
Se ha alcanzado el límite del sistema en el número total de archivos abiertos.
ENODEV
No se pudo montar el dispositivo de inode anónimo (interno).
ENOMEM
No había suficiente memoria para crear un nuevo descriptor de archivo de señal.

VERSIÓNES

Diferencias entre la biblioteca C y el kernel

La llamada al sistema subyacente de Linux requiere un argumento adicional, size_t sizemask, que especifica el tamaño del argumento mask. La función envoltorio signalfd() de glibc no incluye este argumento, ya que proporciona el valor requerido para la llamada al sistema subyacente.

Hay dos llamadas al sistema subyacentes de Linux: signalfd() y la más reciente signalfd4(). La primera llamada al sistema no implementa un argumento flags. La segunda llamada al sistema implementa los valores de flags descritos anteriormente. A partir de glibc 2.9, la función envoltorio signalfd() utilizará signalfd4() donde esté disponible.

NOTAS

Un proceso puede crear múltiples descriptores de archivo de señal. Esto hace posible aceptar diferentes señales en diferentes descriptores de archivo. (Esto puede ser útil si se supervisan los descriptores de archivo utilizando select(2), poll(2), o epoll(7): la llegada de diferentes señales hará que diferentes descriptores de archivo estén listos). Si una señal aparece en la mask de más de uno de los descriptores de archivo, entonces las ocurrencias de esa señal se pueden leer (una vez) de cualquiera de los descriptores de archivo.

Los intentos de incluir SIGKILL y SIGSTOP en mask se ignoran silenciosamente.

La máscara de señales empleada por un descriptor de archivo de señal se puede ver a través de la entrada del descriptor de archivo correspondiente en el directorio /proc/pid/fdinfo del proceso. Consulte proc(5) para obtener más detalles.

Limitaciones

El mecanismo signalfd no se puede utilizar para recibir señales que se generan de forma síncrona, como la señal SIGSEGV que resulta del acceso a una dirección de memoria inválida o la señal SIGFPE que resulta de un error aritmético. Dichas señales solo se pueden capturar mediante un manejador de señales.

Como se describió anteriormente, en el uso normal, se bloquean las señales que se aceptarán a través de signalfd(). Si se genera un proceso hijo para ejecutar un programa auxiliar (que no necesita el descriptor de archivo de señal), entonces, después de la llamada a fork(2), normalmente querrá desbloquear esas señales antes de llamar a execve(2), para que el programa auxiliar pueda ver cualquier señal que espere ver. Sin embargo, tenga en cuenta que esto no será posible en el caso de un programa auxiliar generado en segundo plano por cualquier función de biblioteca que el programa pueda llamar. En tales casos, se debe recurrir al uso de un manejador de señales tradicional que escriba en un descriptor de archivo supervisado por select(2), poll(2), o epoll(7).

ERRORES CONOCIDOS

Antes de Linux 2.6.25, los campos ssi_ptr y ssi_int no se rellenan con los datos que acompañan a una señal enviada por sigqueue(3).

EJEMPLOS

El programa siguiente acepta las señales SIGINT y SIGQUIT a través de un descriptor de archivo de señal. El programa termina después de aceptar una señal SIGQUIT. La siguiente sesión de terminal demuestra el uso del programa:


$ ./signalfd_demo
^C                   # Control-C genera SIGINT
Got SIGINT
^C
Got SIGINT
^\                    # Control-\ genera SIGQUIT
Got SIGQUIT
$

Código fuente del programa

#include <err.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/signalfd.h>
#include <sys/types.h>
#include <unistd.h>
int
main(void)
{
    int                      sfd;
    ssize_t                  s;
    sigset_t                 mask;
    struct signalfd_siginfo  fdsi;
    sigemptyset(&mask);
    sigaddset(&mask, SIGINT);
    sigaddset(&mask, SIGQUIT);
    /* Bloquear señales para que no sean manejadas
       según sus disposiciones predeterminadas.  */
    if (sigprocmask(SIG_BLOCK, &mask, NULL) == -1)
        err(EXIT_FAILURE, "sigprocmask");
    sfd = signalfd(-1, &mask, 0);
    if (sfd == -1)
        err(EXIT_FAILURE, "signalfd");
    for (;;) {
        s = read(sfd, &fdsi, sizeof(fdsi));
        if (s != sizeof(fdsi))
            err(EXIT_FAILURE, "read");
        if (fdsi.ssi_signo == SIGINT) {
            printf("Got SIGINT\n");
        } else if (fdsi.ssi_signo == SIGQUIT) {
            printf("Got SIGQUIT\n");
            exit(EXIT_SUCCESS);
        } else {
            printf("Read unexpected signal\n");
        }
    }
}
