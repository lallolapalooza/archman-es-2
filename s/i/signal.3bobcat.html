FBB::Signal(3bobcat) manejador de señales FBB::Signal(3bobcat)

NOMBRE

FBB::Signal - Manejador de señales

SINOPSIS

#include <bobcat/signal>
Opción de enlazado: -lbobcat

DESCRIPCIÓN

Las señales tienen el conocido inconveniente de que llegan sin contexto. Por ejemplo, supongamos que un programa ejecuta un bucle de control de flujo como este:

void Class::run()
{
    while (d_continue)
        handleTasks();
    cleanup();
}

Si el programa necesita reconocer una señal de terminación, el manejador de señales típico se ve así:

void signalHandler(int signal)
{
    // realizar acciones requeridas
}

Dado que signalHandler se llama de forma asíncrona, no hay contexto disponible, y la forma habitual de comunicarse entre objetos y manejadores de señales es a través de variables estáticas, como esta:

// declarado como bool estático s_continue;
bool Class::s_continue = true;
void Class::run()
{
    while (s_continue)
        handleTasks();
    cleanup();
}
// declarado como void estático signalHander(int signal);
void Class::signalHandler(int signal)
{
    s_continue = false;
}

La clase Signal permite que el manejador de señales opere en el contexto de una clase. La ventaja de esto es que ya no se requieren miembros de datos estáticos y que la señal puede usarse para controlar miembros de datos de objetos individuales.

La señal ahora es manejada por un objeto, cuya clase debe definir un miembro

    void signalHandler(size_t signum) override;
y esta función es responsable de manejar la señal recibida. Como es una función miembro, puede afectar las variables locales de su objeto y puede llamar a las funciones miembro de su objeto. Ya no se requieren miembros de datos estáticos (ver más abajo para un ejemplo).

Tenga en cuenta que, dado que la señal puede llegar en momentos impredecibles, los miembros de datos que pueden ser modificados por signalHandler deben declararse usando el modificador volatile. Además, los datos que pueden ser modificados por el miembro signalHandler y por otros miembros de clase deben protegerse con mutexes (consulte la clase std::mutex de C++-11 o pthread_mutex_lock(3posix)).

ESPACIO DE NOMBRES

FBB
Todos los constructores, miembros, operadores y manipuladores mencionados en esta página del manual están definidos en el espacio de nombres FBB.

HEREDA DE

Signal no se deriva de otras clases, pero las clases para las cuales se deben manejar las señales por Signal deben derivarse públicamente de la clase FBB::SignalHandler e implementar un miembro

    void signalHandler(size_t signum) override;

que maneje la señal recibida.

CONSTRUCTORES Y OPERADORES SOBRECARGADOS

Signal se define como un singleton, y no ofrece constructores públicos ni protegidos, ni operadores sobrecargados.

FUNCIÓN MIEMBRO ESTÁTICA

o
static Signal &instance():
Este miembro estático se puede usar para acceder a una referencia al único objeto Signal del programa.

FUNCIONES MIEMBRO

Todas las funciones miembro de Signal solo se pueden llamar a través de una referencia al objeto Signal del programa, devolviendo una referencia al único objeto Signal del programa:

o
void add(size_t signum, SignalHandler &object):
El SignalHandler object se activa al recibir la señal signum. Si se deben llamar varios objetos SignalHandler, se pueden proporcionar múltiples llamadas a Signal::add, y los diversos miembros SignalHandler::signalHandler se llaman en el mismo orden que sus respectivas llamadas a Signal::add. Si uno de los miembros signalHandler anteriores termina el programa, los miembros signalHandler posteriores ya no se activan. Si Signal::add es llamado por, por ejemplo, el constructor de un objeto, su destructor debe llamar a Signal::remove para evitar que el manejador de señales del objeto sea llamado después de su destrucción.
o
void remove(size_t signum, SignalHandler &object):
El SignalHandler object para la señal signum se elimina del objeto Signal. Es responsabilidad de object darse de baja de Signal justo antes de que object salga del ámbito. Los objetos solo pueden darse de baja si se han registrado previamente usando add.
o
void ignore(size_t signum):
Cualquier objeto SignalHandler instalado previamente ya no se activará al recibir la señal signum. Además, si es posible, la señal signum se ignora por completo (algunas señales no se pueden capturar, bloquear o ignorar, como SIGKILL y SIGSTOP (consulte signal(7))).
o
void reset(size_t signum):
Cualquier objeto SignalHandler instalado previamente ya no se activará al recibir la señal signum. Además, se reinstala la acción predeterminada que toma el programa al recibir la señal signum (consulte signal(7)).

Si el valor signum que se pasa a los miembros de Signal no es un valor de señal definido, se lanza una excepción FBB::Exception.

EJEMPLO

#include <sys/types.h>
#include <unistd.h>
#include <iostream>
#include "../signal"
class SignalDemo: public FBB::SignalHandler
{
    volatile size_t d_signal;
    volatile bool d_continue;
    pid_t d_pid;
    public:
        SignalDemo();
        void run();
    private:
        void signalHandler(size_t signum) override;
};
using namespace std;
using namespace FBB;
SignalDemo::SignalDemo()
:
    d_signal(0),
    d_continue(true),
    d_pid(getpid())
{}
void SignalDemo::run()
{
    while (d_continue)
    {
        cout << "Enviar SIGINT (2) o SIGTERM (15) ... al proceso " <<
                    d_pid << endl;
        sleep(1);
    }
    cout << "Terminando `run’ después de recibir la señal " << d_signal << endl;
}
void SignalDemo::signalHandler(size_t signal)
{
    if (signal == SIGINT)
        cout << "El proceso " << d_pid << " recibió SIGINT" << endl;
    else if (signal == SIGTERM)
    {
        cout << "El proceso " << d_pid << " recibió SIGTERM" << endl;
        d_signal = SIGTERM;
        d_continue = false;
    }
}
int main()
{
    SignalDemo signalDemo;
    Signal::instance().add(SIGINT, signalDemo);
    Signal::instance().add(SIGTERM, signalDemo);
    signalDemo.run();
}
