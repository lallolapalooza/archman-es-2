SIGNAL(3P) Manual de Programador de POSIX SIGNAL(3P)

PRÓLOGO

Esta página del manual forma parte del Manual de Programador de POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

signal — gestión de señales

SINOPSIS

#include <signal.h>
void (*signal(int sig, void (*func)(int)))(int);

DESCRIPCIÓN

La funcionalidad descrita en esta página de referencia está alineada con el estándar ISO C. Cualquier conflicto entre los requisitos descritos aquí y el estándar ISO C es no intencional. Este volumen de POSIX.1‐2017 se remite al estándar ISO C.

La función signal() elige una de las tres formas en que se debe gestionar posteriormente la recepción del número de señal sig. Si el valor de func es SIG_DFL, se producirá el manejo por defecto para esa señal. Si el valor de func es SIG_IGN, la señal será ignorada. De lo contrario, la aplicación deberá asegurarse de que func apunta a una función que se llamará cuando ocurra esa señal. Una invocación de dicha función debido a una señal, o (recursivamente) de cualquier función adicional llamada por esa invocación (que no sean funciones de la biblioteca estándar), se denomina "gestor de señales".

Cuando ocurre una señal y func apunta a una función, es definición de la implementación si se ejecuta el equivalente a:

signal(sig, SIG_DFL);

o si la implementación evita que ocurran ciertos conjuntos de señales definidos por la implementación (que incluyan al menos sig) hasta que se complete el manejo de la señal actual. (Si el valor de sig es SIGILL, la implementación puede definir alternativamente que no se tome ninguna acción). A continuación, se ejecuta el equivalente a:

(*func)(sig);

Si la función retorna y cuándo retorna, si el valor de sig fue SIGFPE, SIGILL, o SIGSEGV o cualquier otro valor definido por la implementación que corresponda a una excepción computacional, el comportamiento es indefinido. De lo contrario, el programa reanudará la ejecución en el punto en que fue interrumpido. El estándar ISO C impone una restricción a las aplicaciones en relación con el uso de raise() desde los gestores de señales. Esta restricción no se aplica a las aplicaciones POSIX, ya que POSIX.1‐2008 requiere que raise() sea seguro para señales asíncronas (consulte la Sección 2.4.3, Acciones de señal).

Si el proceso es multihilo, o si el proceso es de un solo hilo y se ejecuta un gestor de señales que no sea como resultado de:

*
la llamada del proceso a abort(), raise(), kill(), pthread_kill(), o sigqueue() para generar una señal que no esté bloqueada
*
una señal pendiente que no esté bloqueada y que se entregue antes de que retorne la llamada que la desbloqueó

el comportamiento es indefinido si el gestor de señales hace referencia a cualquier objeto que no sea errno con duración de almacenamiento estática, excepto asignando un valor a un objeto declarado como volatile sig_atomic_t, o si el gestor de señales llama a cualquier función definida en este estándar que no sea una de las funciones listadas en la Sección 2.4, Conceptos de señal.

Al inicio del programa, se ejecuta el equivalente a:

signal(sig, SIG_IGN);

para algunas señales, y se ejecuta el equivalente a:

signal(sig, SIG_DFL);

para todas las demás señales (consulte exec).

La función signal() no deberá cambiar la configuración de errno si tiene éxito.

VALOR DE RETORNO

Si la solicitud puede ser atendida, signal() devolverá el valor de func para la llamada más reciente a signal() para la señal especificada sig. De lo contrario, se devolverá SIG_ERR y se almacenará un valor positivo en errno.

ERRORES

La función signal() fallará si:

EINVAL
El argumento sig no es un número de señal válido o se intenta capturar una señal que no se puede capturar o ignorar una señal que no se puede ignorar.

La función signal() puede fallar si:

EINVAL
Se intentó establecer la acción a SIG_DFL para una señal que no se puede capturar o ignorar (o ambas).

USO DE APLICACIONES

La función sigaction() proporciona un mecanismo más completo y confiable para controlar las señales; las nuevas aplicaciones deben usar sigaction() en lugar de signal().
