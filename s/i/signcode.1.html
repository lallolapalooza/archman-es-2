Mono(signcode) Mono(signcode)

NOMBRE

signcode - Firma digitalmente un ejecutable PE usando un certificado X.509.

SINOPSIS

signcode [opciones] archivo

DESCRIPCIÓN

Firma digitalmente un ejecutable PE (ensamblado CLR, EXE o DLL de Win32) usando un certificado X.509 y su clave privada asociada. La firma es compatible con Authenticode(r) y puede ser validada con chktrust (ya sea en Windows o en cualquier plataforma compatible con Mono).

OPCIONES

-spc archivo_spc
El Archivo Publicador de Software (spc) que contiene la cadena de certificados X.509 utilizada para firmar digitalmente el ejecutable PE.
-v archivo_pvk
El Archivo de Clave Privada (pvk) que contiene la clave privada utilizada para firmar digitalmente el ejecutable PE. Esta clave privada debe coincidir con la clave pública dentro del certificado X.509 del publicador.
-a sha1 | md5 | sha2 | sha256 | sha384 | sha512
El algoritmo de hash utilizado en la firma digital del ejecutable PE. El algoritmo predeterminado es SHA1.
-$ individual | comercial
Agrega información sobre el publicador, es decir, si la firma es generada por un individuo o una entidad comercial.
-n descripción
Agrega una descripción textual del archivo firmado.
-i url
Agrega una URL asociada al publicador o al archivo firmado.
-t url
URL de un servicio de marca de tiempo para contrasegurar el ejecutable PE. La contraseguro es necesario si desea que la firma del ejecutable PE sea válida después de que el certificado del publicador expire. El contraseguro demuestra que el publicador tenía un certificado válido (no caducado) cuando se firmó el ejecutable PE.
-tr #
Número de reintentos para obtener una marca de tiempo para el contraseguro.
-tw #
Retraso (en segundos) entre los reintentos para obtener una marca de tiempo para el contraseguro.
-k nombre
Nombre del contenedor de claves de CryptoAPI (cuando no se usa -v).
-p nombre
Nombre del proveedor de CryptoAPI (cuando no se usa -v).
-y #
Tipo de proveedor de CryptoAPI (cuando no se usa -v o -p).
-ky firma | intercambio | #
Tipo de clave de CryptoAPI (cuando no se usa -v).
-r machineLocal | usuarioActual
Ubicación de la clave de CryptoAPI (cuando no se usa -v).
-help , -h , -? , /?
Muestra ayuda sobre esta herramienta.

OTRAS TECNOLOGÍAS DE FIRMA DE CÓDIGO

Los ensamblados son archivos PE que también pueden tener un nombre seguro utilizando la herramienta sn.exe. El orden de la firma del código es importante si un archivo requiere una firma Authenticode y un nombre seguro. El nombre seguro debe aplicarse antes de la firma Authenticode. Aplicar un nombre seguro después de la firma Authenticode, como volver a firmar un ensamblado (por ejemplo, firma retardada), invalidará la firma Authenticode.

RESTRICCIONES CONOCIDAS

signcode no puede generar firmas Authenticode para archivos CAB.
