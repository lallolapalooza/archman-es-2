NOMBRE

apptainer-build - Construye una imagen de Apptainer

SINOPSIS

apptainer build [opciones locales...]

DESCRIPCIÓN

RUTA DE IMAGEN:

Cuando Apptainer construye el contenedor, la salida puede ser de uno de varios formatos:

  predeterminado:    El formato de imagen de solo lectura comprimida de Apptainer (predeterminado)
  sandbox:    Es un contenedor de lectura/escritura dentro de una estructura de directorios

nota: Es un flujo de trabajo común utilizar el modo "sandbox" para el desarrollo del
contenedor, y luego construirlo como una imagen predeterminada de Apptainer para
uso en producción. El formato predeterminado es inmutable.

ESPECIFICACIÓN DE CONSTRUCCIÓN:

El objetivo de la especificación de construcción es un archivo de definición (def), una imagen local o una URI que puede
ser utilizada para crear un contenedor de Apptainer. Existen varios formatos de
objetivo local diferentes:

  archivo def  : Es una receta para construir un contenedor (ejemplos a continuación)
  directorio:  Una estructura de directorios que contiene un sistema de archivos (ch)root
  imagen:      Una imagen local en tu máquina (se convertirá a sif si
              es un formato obsoleto)

Los objetivos también pueden ser remotos y definirse mediante una URI de los siguientes formatos:

  library://  una biblioteca de imágenes (predeterminada ninguna)
  docker://   un registro Docker/OCI (predeterminado Docker Hub)
  shub://     un registro de Apptainer (predeterminado Singularity Hub)
  oras://     un registro OCI que contiene archivos SIF usando ORAS

Archivos temporales:

La ubicación utilizada para los directorios temporales es '/tmp' por predeterminado, pero
puede ser anulada por la variable de entorno TMPDIR, y esta puede ser anulada
por la variable de entorno APPTAINER_TMPDIR. El
directorio temporal utilizado durante una construcción debe estar en un sistema
de archivos que tenga suficiente espacio para contener toda la imagen del
contenedor, descomprimida, incluyendo cualquier archivo temporal que se cree y
luego se elimine durante la construcción. Puede que necesites establecer APPTAINER_TMPDIR o TMPDIR al
construir un contenedor grande en un sistema que tenga un sistema de archivos /tmp
pequeño.

OPCIONES

--arch="amd64" arquitectura para la que construir

--arch-variant="" variante de arquitectura para la que construir

--authfile="" archivo de autenticación estilo Docker para usar para escribir/leer credenciales de registro OCI

-B, --bind=[] una especificación de ruta de enlace de usuario. spec tiene el formato src[:dest[:opts]], donde src y dest son rutas externas e internas. Si dest no se da, se establece igual a src. Las opciones de montaje ('opts') pueden especificarse como 'ro' (solo lectura) o 'rw' (lectura/escritura, que es el valor predeterminado). Se pueden dar múltiples rutas de enlace mediante una lista separada por comas.

--build-arg=[] define variable=valor para reemplazar las entradas {{ variable }} en el archivo de definición de construcción

--build-arg-file="" especifica un archivo que contiene líneas variable=valor para reemplazar '{{ variable }}' con valor en los archivos de definición de construcción

--disable-cache[=false] no usar caché ni crear caché

--docker-host="" especifica un host de demonio Docker personalizado

--docker-login[=false] iniciar sesión en un Repositorio Docker interactivamente

-e, --encrypt[=false] construir una imagen con un sistema de archivos cifrado

-f, --fakeroot[=false] construir con la apariencia de estar ejecutándose como root (predeterminado al construir desde un archivo de definición sin privilegios)

--fix-perms[=false] asegura que el propietario tenga permisos rwX en todo el contenido del contenedor para fuentes oci/docker

-F, --force[=false] sobrescribir un archivo de imagen si existe

-h, --help[=false] ayuda para construir

--json[=false] interpretar la definición de construcción como JSON

--library="" URL de la biblioteca de contenedores

--mksquashfs-args="" argumentos adicionales para pasar a mksquashfs al crear archivos SIF

--mount=[] una especificación de montaje, por ejemplo 'type=bind,source=/opt,destination=/hostopt'.

--no-cleanup[=false] NO limpiar el paquete después de una construcción fallida, puede ser útil para depurar

--no-https[=false] usar http en lugar de https para las URIs docker://, oras:// y library:///...

-T, --notest[=false] construir sin ejecutar pruebas en la sección %test

--nv[=false] inyectar bibliotecas Nvidia del host durante la construcción para las secciones post y test

--nvccli[=false] usar nvidia-container-cli para la configuración de GPU (experimental)

--passphrase[=false] solicitar una frase de contraseña de cifrado

--pem-path="" introducir una ruta a una clave RSA con formato PEM para un contenedor cifrado

--rocm[=false] inyectar bibliotecas Rocm del host durante la construcción para las secciones post y test

-s, --sandbox[=false] construir la imagen en formato sandbox (estructura de directorios chroot)

--section=[all] ejecutar solo secciones específicas del archivo def (setup, post, files, environment, test, labels, none)

-u, --update[=false] ejecutar la definición sobre el contenedor existente (omite la cabecera)

--userns[=false] construir sin usar setuid aunque esté disponible

--warn-unused-build-args[=false] muestra advertencia en lugar de mensaje fatal cuando los argumentos de construcción no coinciden exactamente

--writable-tmpfs[=false] durante la sección %test, hace que el sistema de archivos sea accesible como lectura/escritura con datos no persistentes (solo con soporte de overlay)

EJEMPLO

  SISTEMA OPERATIVO BASE DE ARCHIVO DEF:
      Biblioteca:
          Bootstrap: library
          From: debian:9
      Docker:
          Bootstrap: docker
          From: tensorflow/tensorflow:latest
          IncludeCmd: yes # Usa el CMD como script de ejecución en lugar de ENTRYPOINT
      Singularity Hub:
          Bootstrap: shub
          From: singularityhub/centos
      YUM/RHEL:
          Bootstrap: yum
          OSVersion: 7
          MirrorURL: http://mirror.centos.org/centos-%{OSVERSION}/%{OSVERSION}/os/x86_64/
          Include: yum
      SUSE:
          Bootstrap: zypper # en sistemas SLE se usa el registro del host de construcción
          Include: zypper
      openSUSE:
          Bootstrap: zypper
          MirrorURL: http://download.opensuse.org/distribution/openSUSE-stable/repo/oss
          Include: zypper
      Debian/Ubuntu:
          Bootstrap: debootstrap
          OSVersion: trusty
          MirrorURL: http://us.archive.ubuntu.com/ubuntu/
      Imagen Local:
          Bootstrap: localimage
          From: /home/dave/starter.img
      Scratch:
          Bootstrap: scratch # Rellena el contenedor con un rootfs mínimo en %setup
  SECCIONES DE ARCHIVO DEF:
  Las siguientes secciones se presentan en el orden de procesamiento, con la excepción
  de que las etiquetas y el entorno también pueden ser manipulados en %post.
      %pre
          echo "Este es un scriptlet que se ejecutará en el host, como root antes de que"
          echo "el contenedor haya sido iniciado. Esta sección no se usa comúnmente."
      %setup
          echo "Este es un scriptlet que se ejecutará en el host, como root, después de que"
          echo "el contenedor haya sido iniciado. Para instalar cosas dentro del contenedor"
          echo "referencia la ubicación del sistema de archivos con $APPTAINER_ROOTFS."
      %files
          /ruta/en/host/archivo.txt /ruta/en/contenedor/archivo.txt
          archivo_relativo.txt /ruta/en/contenedor/archivo_relativo.txt
      %post
          echo "Esta sección de scriptlet se ejecutará desde dentro del contenedor después de que"
          echo "la base/arranque haya sido creada y configurada."
      %environment
          LUKE=goodguy
          VADER=badguy
          HAN=someguy
          export HAN VADER LUKE
      %test
          echo "Define cualquier comando de prueba que deba ejecutarse después de que el contenedor haya sido"
          echo "construido. Este scriptlet se ejecutará desde dentro del contenedor en ejecución"
          echo "como usuario root. Presta atención al valor de salida/retorno de este scriptlet,"
          echo "ya que cualquier código de salida distinto de cero se asumirá como fallo."
          exit 0
      %runscript
          echo "Define acciones para el contenedor a ser ejecutadas con el comando run o"
          echo "cuando se ejecuta el contenedor."
      %startscript
          echo "Define acciones para que el contenedor las realice cuando se inicie como una instancia."
      %labels
          HELLO MOTO
          KEY VALUE
      %help
          Este es un archivo de texto que se mostrará con el comando run-help.

NAME

apptainer-build - build Apptainer containers

SYNOPSIS

apptainer build [build options] SPECIFICATION IMAGE

apptainer build --sandbox DIR SPECIFICATION

DESCRIPTION

Builds an Apptainer container image. The SPECIFICATION can be a path to a build definition file or a remote source for the image.

If the IMAGE is given as a directory path, it will be built as a sandbox. This is useful for building and modifying images iteratively.

OPTIONS

--architecture ARCH
Build for a specific architecture, overriding the host architecture.
--disable-cache
Do not use the build cache, and do not save cache for this build.
--force, -F
Overwrite existing image or sandbox directory without prompting.
--group GROUP
Build as a specific group. Defaults to the primary group of the user running Apptainer.
--http-proxy PROXY
Use the specified HTTP proxy server.
--https-proxy PROXY
Use the specified HTTPS proxy server.
--json
Output build information in JSON format.
--mount TYPE=SOURCE[=DEST][,OPTIONS]
Mount host directory/file into the build environment.
--no-net
Do not use network access during build (e.g. for offline builds).
--no-writable
Build a read-only image (SIF format).
--not-user USER
Build as a specific user. Defaults to the user running Apptainer.
--outformat FORMAT
Build image in the specified format (e.g. sif, sandbox). Default is sif.
--pull-library LIBRARY
Specify a library to pull images from. Defaults to library://.
--remote
Use remote build service.
--sandbox
Build image as a sandbox directory.
--section SECTION
Only build specified section(s) of the definition file.
--skip-licenses
Do not add license information to the image.
--ssl-verify [BOOLEAN]
Verify the TLS certificate of the remote registry. Default is true.
--tmpdir DIR
Specify a temporary directory for build operations.
--user USER
Build as a specific user. Defaults to the user running Apptainer.
--uuid
Add a UUID to the built image.
--verbose, -v
Enable verbose output.
--working-dir DIR
Set the working directory within the container build.

EXAMPLE

r build /tmp/debian1.sif library://debian:latest
      Build a base sandbox from DockerHub, make changes to it, then build sif
          $ apptainer build --sandbox /tmp/debian docker://debian:latest
          $ apptainer exec --writable /tmp/debian apt-get install python
          $ apptainer build /tmp/debian2.sif /tmp/debian
