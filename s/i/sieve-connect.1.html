NOMBRE

sieve-connect - cliente de línea de comandos managesieve

SINOPSIS

sieve-connect [-s <hostname>] [-p <portspec>] [-u <usuario>] [a <authzid>]
              [-m <authmech>] [-r realm] [-e execscript]
              [... longopts ...]
sieve-connect [--localsieve <script>] [--remotesieve <script>]
              [--debug] [--dumptlsinfo]
              [--server <hostname>] [--port <portspec>] [--4|--6]
              [--user <authentication_id>] [--authzid <authzid>]
              [--realm <realm>] [--passwordfd <n>]
              [--clientkey <file> --clientcert <file>]|[--clientkeycert <file>]
              [--notlsverify|--nosslverify]
              [--tlscertfingerprint|--sslcertfingerprint <dgsttype:digest>]
              [--tlscapath <ca_directory>]|[--tlscafile <ca_file>]
              [--tlshostname <hostname>]
              [--noclearauth] [--noclearchan] [--clearchan]
              [--authmech <mechanism>]
              [--ignoreserverversion]
              [--upload|--download|--list|--delete|--checkscript|--edit|
               --activate|--deactivate]|[--exec <script>]
              [--help|--man]

DESCRIPCIÓN

sieve-connect es un cliente para el protocolo "MANAGESIEVE", que es un protocolo especificado por RFC para la manipulación de scripts "Sieve" en un repositorio. Más simplemente, sieve-connect te permite controlar tus archivos de reglas de filtrado de correo en un servidor de correo.

sieve-connect puede invocarse con una acción desde la línea de comandos para facilitar la creación de scripts de acciones únicas, se le puede proporcionar un archivo de script o puede entrar en un bucle interactivo de comandos, donde admite autocompletado (si el módulo Perl de soporte está disponible) y navegación básica del sistema de archivos local al estilo de los clientes "FTP".

sieve-connect soporta el uso de "TLS" a través del comando "STARTTLS", incluyendo la autenticación mediante certificados de cliente. "sieve-connect" también soporta los mecanismos "SASL" que tu biblioteca Authen::SASL::Perl proporcione, siempre que no requieran capas de protección SASL.

En modo interactivo, un comando "help" está disponible. Los parámetros de comando con un "%" son examinados para ver si coinciden con %KEYWORD, donde "KEYWORD" siempre está en mayúsculas. La lista de palabras clave puede recuperarse con el comando "keywords" e incluye elementos como %DATE, %USER, etc.

OPCIONES

Los nombres de las opciones pueden darse como el prefijo único más corto.

El nombre del script de sieve remoto por defecto es el mismo que el nombre del script de sieve local, así que especifica solo el local si solo se necesita uno; fue una decisión deliberada tener los valores por defecto de esta manera, para hacer pensar a la gente en los nombres en el sistema de archivos local. No hay un nombre de script por defecto.

La opción --debug activa rastreos de diagnóstico. La opción --debugsasl solicita depuración a la biblioteca SASL. La opción --dumptlsinfo muestra la información del par TLS (SSL); si se especifica junto con --debug, el certificado PEM del servidor se proporcionará como rastreo de depuración.

La opción --version muestra información de la versión. Cuando se combina con --debug, mostrará las versiones de las dependencias de implementación. Las opciones --help y --man proporcionan información de uso.

El servidor puede ser un host o una dirección IP, IPv4 o IPv6.

Si se proporciona un servidor mediante --server, este tendrá precedencia. Si esa opción no está presente, se comprueba la variable de entorno $IMAP_SERVER y, si no es una ruta de socket de dominio Unix, se utiliza con cualquier especificación de puerto eliminada.

Para la verificación TLS, este es el nombre utilizado por defecto para los nombres de host (tanto SNI como verificación); actualmente no se utiliza ninguna información derivada de DNS como identificador de nombre de host de confianza. (Esto está sujeto a cambios en el futuro, dado DNSSEC). La opción --tlshostname puede usarse para anular el nombre utilizado para TLS.

A continuación, a menos que se especifique --nosrv, se realizan comprobaciones de registros SRV para buscar un servidor por defecto; si el módulo Perl Mozilla::PublicSuffix está disponible, estas comprobaciones se realizan para cada nivel del nombre de host hasta (pero sin incluir) el sufijo público. Si ese módulo no está disponible, se utiliza una heurística cruda: mientras haya tres puntos en el nombre de host, se prueban los registros SRV para la parte del nombre de host después del primer punto. Si esto es inapropiado, instala Mozilla::PublicSuffix.

Si no se encuentran registros SRV que apunten a un servicio de protocolo 'sieve', 'imaps' o 'imap', o si se encuentra un registro que dice "no such service in this domain" (al tener un objetivo de "."), entonces el servidor por defecto final es localhost.

El puerto puede ser cualquier especificación de puerto de Perl, el valor por defecto es sieve(4190). Un puerto de un registro SRV tendrá precedencia. La especificación de Perl proporciona un nombre para buscar en la base de datos de servicios del sistema (/etc/services) seguido entre paréntesis por un valor por defecto a usar si el nombre no se encuentra. Por lo tanto, este valor por defecto respetará un valor de 2000 de /etc/services.

Las opciones --4 o --6 pueden usarse para forzar IPv4 o IPv6.

Por defecto, se toma el servidor como un dominio, para el cual se buscan registros SRV; usa --nosrv para inhibir la búsqueda de registros SRV.

La opción --user será requerida a menos que estés en un sistema Unix con getpwuid() disponible y tu nombre de cuenta Cyrus coincida con tu nombre de cuenta del sistema. --authmech se puede usar para forzar un mecanismo de autenticación particular. --authzid se puede usar para solicitar autorización para actuar como el id especificado. --realm se puede usar para intentar pasar información de realm al mecanismo de autenticación. Si quieres proporcionar una contraseña programáticamente, usa --passwordfd para indicar desde qué descriptor de archivo (típicamente 0) se puede leer la contraseña. Todo hasta el salto de línea antes del EOF es la contraseña, por lo que puede contener saltos de línea incrustados. No proporciones contraseñas en una línea de comandos o en el entorno de un proceso.

A menos que se modifiquen en el momento de la instalación/empaquetado, por defecto se buscan certificados de autoridad de certificados SSL. El primer intento es buscar, en orden, las variables de entorno $SSL_CERT_DIR y $SSL_CERT_FILE, que son los nombres soportados por la biblioteca OpenSSL y por lo tanto a menudo soportados por comandos cliente. A continuación, si el comando OpenSSL "version" está disponible y la salida "OPENSSLDIR" puede ser analizada y el directorio "certs" existe dentro de ese directorio, entonces se usará esa ubicación. Finalmente, se busca una lista fija de ubicaciones comunes y se usa la primera que exista. Invocar con --debug mostrará más detalles durante la fase de "setup:".

La precedencia sobre estos valores por defecto se da a la opción --tlscafile si se proporciona, de lo contrario a la opción --tlscapath si se proporciona. El primero es un archivo que contiene certificados, el segundo es un directorio.

Alternativamente, si estás dispuesto a aceptar el riesgo de ataques activos de hombre en el medio y no puedes organizar la disponibilidad del certificado de autoridad de certificados relevante, entonces puedes reducir tu seguridad con la opción --notlsverify, también escrita como --nosslverify.

Si se solicita verificación (por defecto) pero TLS no está disponible, no se recurre a comunicaciones inseguras en texto plano. Usa --clearchan para cambiar eso, o establece $SIEVECONNECT_INSECURE_CLEARTEXT_FALLBACK no vacío en el entorno.

Si no quieres depender (solo) de sistemas CA, puedes establecer explícitamente una huella digital esperada del certificado del servidor usando la opción --tlscertfingerprint, también escrita como --sslcertfingerprint. Si deseas ignorar la validación CA, aún necesitas deshabilitarla explícitamente (ver arriba), ya que el valor por defecto es agregar una restricción adicional (fijación, dentro de los certificados CA válidos). Esta opción especifica la huella digital del certificado X.509 (no una huella digital de clave pública), tal como la proporciona OpenSSL.
