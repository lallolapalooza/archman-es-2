NOMBRE

apptainer-shell - Ejecuta un shell dentro de un contenedor

SINOPSIS

apptainer shell [opciones del shell...]

DESCRIPCIÓN

apptainer shell soporta los siguientes formatos:

*.sif Formato de Imagen Singularity (SIF). Nativo de Singularity
(3.0+) y Apptainer (v1.0.0+)

*.sqsh Formato SquashFS. Nativo de Singularity 2.4+

*.img Formato ext3. Nativo de versiones de Singularity < 2.4.

directorio/ Formato sandbox. Directorio que contiene un sistema de archivos raíz válido
y opcionalmente metadatos de Apptainer.

instance://* Una instancia local en ejecución de un contenedor. (Ver el grupo de comandos
instance.)

library://* Un contenedor SIF alojado en una Biblioteca (sin predeterminado)

docker://* Un contenedor Docker/OCI alojado en Docker Hub o en otro
registro OCI.

shub://* Un contenedor alojado en Singularity Hub.

oras://* Un contenedor SIF alojado en un registro OCI que soporta
la especificación OCI Registry As Storage (ORAS).

OPCIONES

--add-caps="" una lista de capacidades separadas por comas para añadir

--allow-setuid[=false] permite binarios setuid en el contenedor (solo root)

--app="" establece una aplicación para ejecutar dentro de un contenedor

--apply-cgroups="" aplica cgroups desde un archivo para los procesos del contenedor (solo root)

--authfile="" archivo de autenticación tipo Docker para usar para leer/escribir credenciales de registro OCI

-B, --bind=[] una especificación de ruta de montaje de enlace para el usuario. La especificación tiene el formato src[:dest[:opts]], donde src y dest están fuera y dentro de las rutas. Si dest no se proporciona, se establece igual a src. Las opciones de montaje ('opts') pueden especificarse como 'ro' (solo lectura) o 'rw' (lectura/escritura, que es el valor predeterminado). Se pueden proporcionar múltiples rutas de enlace mediante una lista separada por comas.

--blkio-weight=0 peso relativo de E/S de bloque en el rango 10-1000, 0 para deshabilitar

--blkio-weight-device=[] peso relativo de E/S de bloque específico del dispositivo

-e, --cleanenv[=false] limpia el entorno antes de ejecutar el contenedor

--compat[=false] aplica configuraciones para mayor compatibilidad OCI/Docker. Infiere --containall, --no-init, --no-umask, --no-eval, --writable-tmpfs.

-c, --contain[=false] usa un /dev mínimo y vacía otros directorios (por ejemplo, /tmp y $HOME) en lugar de compartir sistemas de archivos de tu host

-C, --containall[=false] contiene no solo sistemas de archivos, sino también PID, IPC y entorno

--cpu-shares=-1 comparticiones de CPU para el contenedor

--cpus="" Número de CPUs disponibles para el contenedor

--cpuset-cpus="" Lista de CPUs del host disponibles para el contenedor

--cpuset-mems="" Lista de nodos de memoria del host disponibles para el contenedor

--cwd="" directorio de trabajo inicial para el proceso de carga útil dentro del contenedor (sinónimo de --pwd)

--disable-cache[=false] no usar ni crear caché

--dns="" lista de servidores DNS separados por comas para añadir en resolv.conf

--docker-host="" especifica un host de demonio Docker personalizado

--docker-login[=false] inicia sesión en un Repositorio Docker interactivamente

--drop-caps="" una lista de capacidades separadas por comas para eliminar

--env=[] pasa la variable de entorno al proceso contenido

--env-file=[] pasa variables de entorno desde un archivo al proceso contenido

-f, --fakeroot[=false] ejecuta el contenedor con la apariencia de ejecutarse como root

--fusemount=[] una especificación de montaje de sistema de archivos FUSE del formato ': ' - donde es 'container' o 'host', especificando dónde se realizará el montaje ('container-daemon' o 'host-daemon' ejecutarán el proceso FUSE de forma desvinculada). es la ruta al ejecutable FUSE, más las opciones para el montaje. es la ubicación en el contenedor donde se adjuntará el montaje FUSE. Por ejemplo: 'container:sshfs 10.0.0.1:/ /sshfs'. Implica --pid.

-h, --help[=false] ayuda para shell

-H, --home="/build" una especificación de directorio home. La especificación puede ser una ruta src o un par src:dest. src es la ruta de origen del directorio home fuera del contenedor y dest anula el directorio home dentro del contenedor.

--hostname="" establece el nombre de host del contenedor

-i, --ipc[=false] ejecuta el contenedor en un nuevo espacio de nombres IPC

--keep-privs[=false] permite que el usuario root conserve privilegios en el contenedor (solo root)

--memory="" límite de memoria en bytes

--memory-reservation="" límite blando de memoria en bytes

--memory-swap="" límite de swap, usa -1 para swap ilimitado

--mount=[] una especificación de montaje, por ejemplo, 'type=bind,source=/opt,destination=/hostopt'.

-n, --net[=false] ejecuta el contenedor en un nuevo espacio de nombres de red (configura una interfaz de red bridge por defecto)

--netns-path="" une el espacio de nombres de red en la ruta especificada (como root, o si está permitido en apptainer.conf)

--network="" especifica el tipo de red deseado separado por comas, cada red activará una interfaz dedicada dentro del contenedor

--network-args=[] especifica argumentos de red para pasar a los plugins CNI

--no-eval[=false] no evalúa variables de entorno ni COMANDO/ENTRYPOINT/ARGS de contenedor OCI en el shell

--no-home[=false] NO monta el directorio home del usuario si /home no es el directorio de trabajo actual

--no-https[=false] usa http en lugar de https para las URI docker://, oras:// y library:///...

--no-init[=false] NO inicia el proceso shim con --pid

--no-mount=[] deshabilita una o más opciones 'mount xxx' establecidas en apptainer.conf y/o especifica una ruta de destino absoluta para deshabilitar una entrada de ruta de enlace, o 'bind-paths' para deshabilitar todas las entradas de ruta de enlace.

--no-pid[=false] no ejecuta el contenedor en un nuevo espacio de nombres PID

--no-privs[=false] elimina todos los privilegios del usuario root en el contenedor)

--no-umask[=false] no propaga umask al contenedor, establece umask predeterminada 0022

--nv[=false] habilita soporte Nvidia

--nvccli[=false] usa nvidia-container-cli para la configuración de GPU (experimental)

--oom-kill-disable[=false] Deshabilita el asesino OOM

-o, --overlay=[] usa una imagen overlayFS para almacenamiento persistente de datos o como capa de solo lectura del contenedor

--passphrase[=false] solicita una contraseña de cifrado

--pem-path="" introduce una ruta a una clave RSA formateada en PEM para un contenedor cifrado

-p, --pid[=false] ejecuta el contenedor en un nuevo espacio de nombres PID

--pids-limit=0 Límita el número de PIDs del contenedor, usa -1 para ilimitado

--rocm[=false] habilita soporte Rocm experimental

-S, --scratch=[] incluye un directorio scratch dentro del contenedor que está enlazado a un directorio temporal (usa -W para forzar la ubicación)

--security=[] habilita características de seguridad (SELinux, Apparmor, Seccomp)

--sharens[=false] comparte el espacio de nombres y la imagen con otros contenedores lanzados desde el mismo proceso padre

-s, --shell="" ruta al programa para usar como shell interactivo

--unsquash[=false] Convierte el archivo SIF a una sandbox temporal antes de ejecutar

-u, --userns[=false] ejecuta el contenedor en un nuevo espacio de nombres de usuario

--uts[=false] ejecuta el contenedor en un nuevo espacio de nombres UTS

-W, --workdir="" directorio de trabajo a utilizar para /tmp, /var/tmp y $HOME (si también se usó -c/--contain)

-w, --writable[=false] por defecto, todos los contenedores de Apptainer son de solo lectura. Esta opción hace que el sistema de archivos sea accesible como lectura/escritura.

--writable-tmpfs[=false] hace que el sistema de archivos sea accesible como lectura/escritura con datos no persistentes (solo con soporte overlay)

EJEMPLO

  $ apptainer shell /tmp/Debian.sif
  Apptainer/Debian.sif> pwd
  /home/gmk/test
  Apptainer/Deb
