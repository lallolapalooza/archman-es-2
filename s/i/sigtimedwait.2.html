sigwaitinfo(2) Manual de Llamadas al Sistema sigwaitinfo(2)

NOMBRE

sigwaitinfo, sigtimedwait, rt_sigtimedwait - esperar de forma síncrona señales en cola

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <signal.h>
int sigwaitinfo(const sigset_t *restrict set,
                siginfo_t *_Nullable restrict info);
int sigtimedwait(const sigset_t *restrict set,
                siginfo_t *_Nullable restrict info,
                const struct timespec *restrict timeout);
Requisitos de macro de prueba de características para glibc (véase feature_test_macros(7)):

sigwaitinfo(), sigtimedwait():

    _POSIX_C_SOURCE >= 199309L

DESCRIPCIÓN

sigwaitinfo() suspende la ejecución del hilo que la llama hasta que una de las señales en set esté pendiente (Si una de las señales en set ya está pendiente para el hilo que la llama, sigwaitinfo() retornará inmediatamente.)

sigwaitinfo() elimina la señal del conjunto de señales pendientes y devuelve el número de señal como resultado de la función. Si el argumento info no es NULL, entonces el búfer al que apunta se utiliza para devolver una estructura de tipo siginfo_t (véase sigaction(2)) que contiene información sobre la señal.

Si varias señales en set están pendientes para el llamador, la señal que se recupera mediante sigwaitinfo() se determina según las reglas de ordenación habituales; véase signal(7) para más detalles.

sigtimedwait() opera exactamente de la misma manera que sigwaitinfo() excepto que tiene un argumento adicional, timeout, que especifica el intervalo durante el cual el hilo se suspende esperando una señal. (Este intervalo se redondeará al alza hasta la granularidad del reloj del sistema, y los retrasos de planificación del kernel significan que el intervalo puede excederse en una pequeña cantidad.) Este argumento es una estructura timespec(3).

Si ambos campos de esta estructura se especifican como 0, se realiza una encuesta: sigtimedwait() retorna inmediatamente, ya sea con información sobre una señal que estaba pendiente para el llamador, o con un error si ninguna de las señales en set estaba pendiente.

VALOR DE RETORNO

En caso de éxito, tanto sigwaitinfo() como sigtimedwait() devuelven un número de señal (es decir, un valor mayor que cero). En caso de error, ambas llamadas devuelven -1, con errno establecido para indicar el error.

ERRORES

EAGAIN
Ninguna señal en set se volvió pendiente dentro del período timeout especificado a sigtimedwait().
EINTR
La espera fue interrumpida por un manejador de señales; véase signal(7). (Este manejador era para una señal distinta de las de set.)
EINVAL
timeout era inválido.

VERSIÓNES

Diferencias biblioteca C/núcleo

En Linux, sigwaitinfo() es una función de biblioteca implementada sobre sigtimedwait().

Las funciones envoltorio de glibc para sigwaitinfo() y sigtimedwait() ignoran silenciosamente los intentos de esperar las dos señales de tiempo real que se utilizan internamente en la implementación de hilos NPTL. Véase nptl(7) para detalles.

La llamada al sistema original de Linux se llamaba sigtimedwait(). Sin embargo, con la adición de señales de tiempo real en Linux 2.2, el tipo sigset_t de tamaño fijo y 32 bits soportado por esa llamada al sistema ya no era adecuado. En consecuencia, se añadió una nueva llamada al sistema, rt_sigtimedwait(), para soportar un tipo sigset_t ampliado. La nueva llamada al sistema toma un cuarto argumento, size_t sigsetsize, que especifica el tamaño en bytes del conjunto de señales en set. Este argumento debe tener actualmente el valor sizeof(sigset_t) (o se produce el error EINVAL). La función envoltorio sigtimedwait() de glibc oculta estos detalles, llamando transparentemente a rt_sigtimedwait() cuando el kernel la proporciona.

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001.

NOTAS

En el uso normal, el programa que llama bloquea las señales en set mediante una llamada previa a sigprocmask(2) (para que la disposición por defecto para estas señales no ocurra si se vuelven pendientes entre llamadas sucesivas a sigwaitinfo() o sigtimedwait()) y no establece manejadores para estas señales. En un programa multihilo, la señal debe bloquearse en todos los hilos, para evitar que la señal se trate de acuerdo con su disposición por defecto en un hilo distinto al que llama a sigwaitinfo() o sigtimedwait().

El conjunto de señales que está pendiente para un hilo dado es la unión del conjunto de señales que está pendiente específicamente para ese hilo y el conjunto de señales que está pendiente para el proceso en su conjunto (véase signal(7)).

Los intentos de esperar SIGKILL y SIGSTOP se ignoran silenciosamente.

Si varios hilos de un proceso están bloqueados esperando las mismas señales en sigwaitinfo() o sigtimedwait(), entonces exactamente uno de los hilos recibirá la señal si se vuelve pendiente para el proceso en su conjunto; cuál de los hilos recibe la señal es indeterminado.

sigwaitinfo() o sigtimedwait() no se pueden utilizar para recibir señales que se generan de forma síncrona, como la señal SIGSEGV que resulta del acceso a una dirección de memoria inválida o la señal SIGFPE que resulta de un error aritmético. Dichas señales solo se pueden capturar mediante un manejador de señales.

POSIX deja sin especificar el significado de un valor NULL para el argumento timeout de sigtimedwait(), lo que permite la posibilidad de que esto tenga el mismo significado que una llamada a sigwaitinfo(), y de hecho esto es lo que se hace en Linux.

sigtimedwait(2)

NOMBRE

sigtimedwait — espera síncronamente por algunas señales

BIBLIOTECA

Librería de C estándar (libc, -lc)

SINÓPSIS

#define _GNU_SOURCE             /* Ver feature_test_macros(7) */
       #include <signal.h>

       int sigtimedwait(const sigset_t *set, siginfo_t *info,
                        const struct timespec *timeout);

DESCRIPCIÓN

La función sigtimedwait() examina la máscara de señales del hilo que llama. Si el conjunto de señales especificadas por el argumento set no contiene ninguna señal que esté bloqueada en ese momento para el hilo que llama, entonces sigtimedwait() retorna inmediatamente.

Si el conjunto set contiene una o más señales que están bloqueadas, sigtimedwait() selecciona una de estas señales.

Si se proporciona el puntero info (no es NULL), entonces la información sobre la señal seleccionada se almacena en la estructura siginfo_t apuntada por info. Ver signal(7) para más detalles sobre la estructura siginfo_t.

Si se proporciona el puntero timeout (no es NULL), entonces sigtimedwait() se bloquea durante un máximo de la cantidad de tiempo especificada por timeout. timeout apunta a una estructura timespec que especifica el número de segundos y nanosegundos. Si timeout es NULL, entonces sigtimedwait() se bloquea indefinidamente hasta que llegue una señal.

La señal seleccionada se elimina de las señales pendientes del hilo. Las señales que no están bloqueadas no se ven afectadas.

Si se reciben múltiples instancias de la misma señal, estas se acumulan si se está utilizando el mecanismo de colas de señales (sigqueue(3)). sigtimedwait() puede retornar múltiples instancias de la misma señal si se especifica info no es NULL, en cuyo caso el campo si_overrun en la estructura siginfo_t contendrá el número de instancias perdidas.

Si la señal seleccionada se entrega junto con información adicional (por ejemplo, una señal generada por sigqueue(3)), esta información se devuelve en la estructura info. De lo contrario, los campos de info no especificados se establecen en 0.

Si la operación de tiempo de espera expira antes de que llegue una señal, sigtimedwait() retorna un valor de error y establece errno a EAGAIN. La máscara de señales del hilo no se modifica en este caso.

Si una llamada interrumpida a sigtimedwait() se reanuda (por ejemplo, después de ser interrumpida por una señal no bloqueada), el valor de tiempo de espera se actualiza para reflejar el tiempo transcurrido. Esto no es un comportamiento POSIX, sino una extensión de Linux.

Si la máscara de señales del hilo cambia durante la llamada, el comportamiento es indefinido.

La máscara de señales del hilo siempre incluye SIGKILL y SIGSTOP, que no se pueden bloquear.

VALOR DE RETORNO

En caso de éxito, sigtimedwait() retorna el número de la señal que se recibió.

En caso de error, sigtimedwait() retorna -1 y establece errno para indicar el error.

ERRORES

EAGAIN
El tiempo de espera expiró antes de que llegara una señal.
EINTR
La llamada fue interrumpida por una llamada a una función del sistema o un manejador de señales. El valor de tiempo de espera se actualizará para reflejar el tiempo transcurrido.
EINVAL
El argumento timeout especifica un tiempo negativo.
ENOMEM
No hay suficiente memoria disponible.

VERSIÓNES

La opción _GNU_SOURCE es necesaria para habilitar esta función.

ESTÁNDARES

Esta función es específica de Linux. No es parte de ningún estándar POSIX.

HISTORIA

Linux 2.6.15.

NOTAS

La función sigtimedwait() es similar a sigwaitinfo(3), pero con un argumento de tiempo de espera. El conjunto de señales set especifica las señales que deben ser esperadas. Las señales que no están incluidas en set se ignoran y se manejan como de costumbre (es decir, si no están bloqueadas, se les aplica su acción por defecto, se llama a su manejador o se ignora).

Se puede usar sigtimedwait() para esperar señales de forma síncrona. Esto es útil para evitar las complejidades de los manejadores de señales, por ejemplo, garantizando que las operaciones de señalización sean atómicas con respecto a otras operaciones del hilo.

Para usar sigtimedwait(), primero debes bloquear las señales que quieres esperar usando pthread_sigmask(3) o sigprocmask(2). Si no bloqueas las señales, la acción por defecto para esas señales (normalmente, terminar el proceso) podría ser invocada antes de que sigtimedwait() pueda capturarlas.

Si se llama a sigtimedwait() en un hilo, se aplicará a la máscara de señales de ese hilo. Si el proceso tiene múltiples hilos, cada hilo tiene su propia máscara de señales.

El campo si_code en la estructura siginfo_t puede contener un valor adicional que indica la causa de la señal (por ejemplo, SI_KERNEL si la señal fue enviada por el kernel).

VER TAMBIÉN
