DESCRIPCIÓN

La Herramienta de Firma, signtool, crea firmas digitales y utiliza un archivo JAR (Java Archive) para asociar las firmas con los archivos en un directorio. La distribución electrónica de software a través de cualquier red implica problemas de seguridad potenciales. Para ayudar a abordar algunos de estos problemas, puede asociar firmas digitales con los archivos en un archivo JAR. Las firmas digitales permiten a los clientes habilitados para SSL realizar dos operaciones importantes:

* Confirmar la identidad del individuo, empresa u otra entidad cuya firma digital está asociada con los archivos

* Comprobar si los archivos han sido manipulados desde que fueron firmados

Si tiene un certificado de firma, puede usar Netscape Signing Tool para firmar digitalmente archivos y empaquetarlos como un archivo JAR. Un certificado de firma de objeto es un tipo especial de certificado que le permite asociar su firma digital con uno o más archivos.

Un archivo individual puede ser firmado potencialmente con múltiples firmas digitales. Por ejemplo, un desarrollador de software comercial podría firmar los archivos que constituyen un producto de software para demostrar que los archivos son realmente de una empresa en particular. Un administrador de red podría firmar los mismos archivos con una firma digital adicional basada en un certificado generado por la empresa para indicar que el producto está aprobado para su uso dentro de la empresa.

La importancia de una firma digital es comparable a la importancia de una firma manuscrita. Una vez que haya firmado un archivo, es difícil afirmar más tarde que no lo firmó. En algunas situaciones, una firma digital puede considerarse legalmente vinculante como una firma manuscrita. Por lo tanto, debe tener mucho cuidado para asegurarse de que puede respaldar cualquier archivo que firme y distribuya.

Por ejemplo, si es un desarrollador de software, debe probar su código para asegurarse de que está libre de virus antes de firmarlo. Del mismo modo, si es un administrador de red, debe asegurarse, antes de firmar cualquier código, de que proviene de una fuente confiable y se ejecutará correctamente con el software instalado en las máquinas a las que lo está distribuyendo.

Antes de poder usar Netscape Signing Tool para firmar archivos, debe tener un certificado de firma de objeto, que es un certificado especial cuya clave privada asociada se utiliza para crear firmas digitales. Solo para fines de prueba, puede crear un certificado de firma de objeto con Netscape Signing Tool 1.3. Cuando las pruebas finalicen y esté listo para distribuir su software, debe obtener un certificado de firma de objeto de uno de los dos tipos de fuentes:

* Una autoridad de certificación (CA) independiente que autentica su identidad y le cobra una tarifa. Normalmente obtiene un certificado de una CA independiente si desea firmar software que se distribuirá a través de Internet.

* Software de servidor CA que se ejecuta en su intranet o extranet corporativa. Netscape Certificate Management System proporciona una solución completa de gestión para crear, implementar y administrar certificados, incluidas las CA que emiten certificados de firma de objeto.

También debe tener un certificado para la CA que emite su certificado de firma antes de poder firmar archivos. Si el certificado de la autoridad de certificación no está ya instalado en su copia de Communicator, normalmente lo instala haciendo clic en el enlace apropiado en el sitio web de la autoridad de certificación, por ejemplo, en la página desde la que inició la inscripción para su certificado de firma. Este es el caso de algunos certificados de prueba, así como de los certificados emitidos por Netscape Certificate Management System: debe descargar el certificado de la CA además de obtener su propio certificado de firma. Los certificados de CA para varias autoridades de certificación están preinstalados en la base de datos de certificados de Communicator.

Cuando recibe un certificado de firma de objeto para su propio uso, se instala automáticamente en su copia del software cliente Communicator. Communicator admite el estándar de cifrado de clave pública conocido como PKCS #12, que rige la portabilidad de claves. Puede, por ejemplo, mover un certificado de firma de objeto y su clave privada asociada de una computadora a otra en un dispositivo del tamaño de una tarjeta de crédito llamado tarjeta inteligente.

OPCIONES

-b nombrebase

Especifica el nombre base de los archivos .rsa y .sf en el directorio META-INF para cumplir con el formato JAR. Por ejemplo, -b firmas hace que los archivos se llamen signatures.rsa y signatures.sf. El valor predeterminado es signtool.

-c#

Especifica el nivel de compresión para la opción -J o -Z. El símbolo # representa un número de 0 a 9, donde 0 significa sin compresión y 9 significa compresión máxima. Cuanto mayor sea el nivel de compresión, menor será la salida pero más tiempo tardará la operación. Si la opción -c# no se usa con la opción -J ni con la opción -Z, el valor de compresión predeterminado utilizado por ambas opciones es 6.

-d dir-cert

Especifica el directorio de su base de datos de certificados; es decir, el directorio en el que colocó sus archivos key3.db y cert7.db. Para especificar el directorio actual, use "-d." (incluido el punto). La versión de Unix de signtool asume ~/.netscape a menos que se indique lo contrario. La versión de NT de signtool siempre requiere el uso de la opción -d para especificar dónde se encuentran los archivos de la base de datos.

-e extensión

Indica a signtool que firme solo archivos con la extensión dada; por ejemplo, use -e".class" para firmar solo archivos .class de Java. Tenga en cuenta que con Netscape Signing Tool versión 1.1 y posteriores, esta opción puede aparecer varias veces en una sola línea de comandos, lo que permite especificar varios tipos de archivos o clases a incluir.

-f archivo-comando

Especifica un archivo de texto que contiene opciones y argumentos de Netscape Signing Tool en formato clave=valor. Todas las opciones y argumentos se pueden expresar a través de este archivo. Para obtener más información sobre la sintaxis utilizada con este archivo, consulte "Consejos y Técnicas".

-G apodo

Genera un nuevo par de claves pública-privada y un certificado de firma de objeto correspondiente con el apodo dado. Las claves y el certificado recién generados se instalan en las bases de datos de claves y certificados en el directorio especificado por la opción -d. Con la versión NT de Netscape Signing Tool, debe usar la opción -d con la opción -G. Con la versión Unix de Netscape Signing Tool, omitir la opción -d hará que la herramienta instale las claves y el certificado en las bases de datos de claves y certificados de Communicator. Si está instalando las claves y el certificado en las bases de datos de Communicator, debe salir de Communicator antes de usar esta opción; de lo contrario, corre el riesgo de corromper las bases de datos. En todos los casos, el certificado también se emite a un archivo llamado x509.cacert, que tiene el tipo MIME application/x-x509-ca-cert. A diferencia de los certificados que normalmente se usan para firmar código terminado que se distribuirá a través de una red, un certificado de prueba creado con -G no está firmado por una autoridad de certificación reconocida. En su lugar, está autofirmado. Además, un único certificado de firma de prueba funciona tanto como certificado de firma de objeto como CA. Cuando lo usa para firmar objetos, se comporta como un certificado de firma de objeto. Cuando se importa en software de navegador como Communicator, se comporta como una CA de firma de objeto y no se puede usar para firmar objetos. La opción -G está disponible solo en Netscape Signing Tool versión 1.0 y posteriores. Por defecto, produce solo certificados RSA con claves de 1024 bytes en el token interno. Sin embargo, puede usar la opción -s para especificar el tamaño de clave requerido y la opción -t para especificar el token.

-i nombre-script

Especifica el nombre de un script instalador para SmartUpdate. Este script instala archivos del archivo JAR en el sistema local después de que SmartUpdate haya validado la firma digital.
Para más detalles, consulte la descripción de -m que sigue. La opción -i proporciona una forma sencilla de proporcionar esta información si no necesita especificar metadatos que no sean un script instalador.

-J

Firma un directorio de archivos HTML que contienen JavaScript y crea tantos archivos de archivo como se especifican en las etiquetas HTML. Incluso si signtool crea más de un archivo de archivo, solo necesita proporcionar la contraseña de la base de datos de claves una vez. La opción -J solo está disponible en Netscape Signing Tool 1.0 y versiones posteriores. La opción -J no se puede usar al mismo tiempo que la opción -Z. Si la opción -c# no se utiliza con la opción -J, el valor de compresión predeterminado es 6. Tenga en cuenta que las versiones 1.1 y posteriores de Netscape Signing Tool reconocen correctamente el atributo CODEBASE, permiten que las rutas se expresen para los atributos CLASS y SRC en lugar de solo nombres de archivo, procesan las etiquetas LINK y analizan HTML correctamente, y ofrecen mensajes de error más claros.

-j directorio

Especifica un directorio especial de JavaScript. Esta opción hace que el directorio especificado se firme y etiqueta sus entradas como JavaScript en línea. Este tipo especial de entrada no tiene que aparecer en el propio archivo JAR. En su lugar, se encuentra en la página HTML que contiene los scripts en línea. Cuando utiliza signtool -v, estas entradas se muestran con la cadena NO PRESENTE.

-k clave ... directorio

Especifica el apodo (clave) del certificado con el que desea firmar y firma los archivos en el directorio especificado. El directorio a firmar siempre se especifica como el último argumento de la línea de comandos. Por lo tanto, es posible escribir signtool -k MyCert -d . signdir Puede tener problemas si el apodo contiene una comilla simple. Para evitar problemas, escapa la comilla utilizando las convenciones de escape para su plataforma. También es posible utilizar la opción -k sin firmar ningún archivo ni especificar un directorio. Por ejemplo, puede usarla con la opción -l para obtener información detallada sobre un certificado de firma particular.

-l

Enumera los certificados de firma, incluidas las AC emisoras. Si alguno de sus certificados está caducado o no es válido, la lista lo especificará. Esta opción se puede usar con la opción -k para enumerar información detallada sobre un certificado de firma particular. La opción -l solo está disponible en Netscape Signing Tool 1.0 y versiones posteriores.

-L

Enumera los certificados de su base de datos. Aparece un asterisco a la izquierda del apodo de cualquier certificado que se pueda usar para firmar objetos con signtool.

--leavearc

Conserva los directorios temporales .arc (archivo) que crea la opción -J. Estos directorios se borran automáticamente de forma predeterminada. Conservar los directorios temporales puede ayudar a depurar.

-m metaarchivo

Especifica el nombre de un archivo de control de metadatos. Los metadatos son información firmada adjunta al propio archivo JAR o a los archivos dentro del archivo. Estos metadatos pueden ser cualquier cadena ASCII, pero se utilizan principalmente para especificar un script instalador. El archivo de metadatos contiene una entrada por línea, cada una con tres campos: campo n.º 1: especificación de archivo, o + si desea especificar metadatos globales (es decir, metadatos sobre el propio archivo JAR o todas las entradas del archivo) campo n.º 2: el nombre de los datos que está especificando; por ejemplo: Script-Instalar campo n.º 3: datos correspondientes al nombre en el campo n.º 2 Por ejemplo, la opción -i usa el equivalente de esta línea: + Script-Instalar: script.js Este ejemplo asocia un tipo MIME con un archivo: movie.qt Tipo-MIME: video/quicktime Para obtener información sobre la forma en que la información del script instalador aparece en el archivo de manifiesto de un archivo JAR, consulte El formato JAR en Netscape DevEdge.

-M

Enumera los módulos PKCS #11 disponibles para signtool, incluidas las tarjetas inteligentes. La opción -M solo está disponible en Netscape Signing Tool 1.0 y versiones posteriores. Para obtener información sobre el uso de Netscape Signing Tool con tarjetas inteligentes, consulte "Uso de Netscape Signing Tool con tarjetas inteligentes". Para obtener información sobre el uso de la opción -M para verificar el modo validado FIPS-140-1, consulte "Netscape Signing Tool y FIPS-140-1".

--norecurse

Bloquea la recursión en subdirectorios al firmar el contenido de un directorio o al analizar HTML.

-o

Optimiza el archivo para su tamaño. Úselo solo si está firmando archivos muy grandes que contienen cientos de archivos. Esta opción hace que los archivos de manifiesto (requeridos por el formato JAR) sean considerablemente más pequeños, pero contienen un poco menos de información.

--outfile archivoSalida

Especifica un archivo para recibir la salida redirigida de Netscape Signing Tool.

-p contraseña

Especifica una contraseña para la base de datos de claves privadas. Tenga en cuenta que la contraseña introducida en la línea de comandos se muestra en texto plano.

-s tamañoClave

Especifica el tamaño de la clave para el certificado generado. Utilice la opción -M para averiguar qué tokens están disponibles. La opción -s solo se puede usar con la opción -G.

-t token

Especifica qué token disponible debe generar la clave y recibir el certificado. Utilice la opción -M para averiguar qué tokens están disponibles. La opción -t solo se puede usar con la opción -G.

-v archivo

Muestra el contenido de un archivo y verifica la integridad criptográfica de las firmas digitales que contiene y los archivos con los que están asociados. Esto incluye verificar que el certificado del emisor del certificado de firma de objetos figura en la base de datos de certificados, que la firma digital de la AC sobre el certificado de firma de objetos es válida, que los certificados relevantes no han caducado, etc.

--verbosity valor

Establece la cantidad de información que Netscape Signing Tool genera en operación. Un valor de 0 (cero) es el predeterminado y proporciona información completa. Un valor de -1 suprime la mayoría de los mensajes, pero no los mensajes de error.

-w archivo

Muestra los nombres de los firmantes de cualquier archivo en el archivo.

-x directorio

Excluye el directorio especificado de la firma. Tenga en cuenta que con Netscape Signing Tool versión 1.1 y posteriores, esta opción se puede especificar varias veces en una misma línea de comandos, lo que permite especificar varios directorios concretos a excluir.

-z

Indica a signtool que no almacene la hora de firma en la firma digital. Esta opción es útil si desea que la fecha de vencimiento de la firma se compruebe con la fecha y hora actuales en lugar de con la hora en que se firmaron los archivos.

-Z archivoJar

Crea un archivo JAR con el nombre especificado. Debe especificar esta opción si desea que signtool cree el archivo JAR; no lo hace automáticamente. Si no especifica -Z, debe utilizar una herramienta ZIP externa para crear el archivo JAR. La opción -Z no se puede usar al mismo tiempo que la opción -J. Si la opción -c# no se utiliza con la opción -Z, el valor de compresión predeterminado es 6.

FORMATO DEL ARCHIVO DE COMANDOS

Las entradas en un archivo de comandos de Netscape Signing Tool tienen este formato general: palabraClave=valor Todo lo que está antes del signo = en una sola línea es una palabra clave, y todo desde el signo = hasta el final de la línea es un valor. El valor puede incluir signos =; solo el primer signo = en una línea se interpreta. Las líneas en blanco se ignoran, pero los espacios en blanco en una línea con palabras clave y valores se asumen como parte de la palabra clave (si están antes del signo igual) o como parte del valor (si están después del primer signo igual). Las palabras clave no distinguen mayúsculas y minúsculas, los valores generalmente distinguen mayúsculas y minúsculas. Dado que el signo = y el salto de línea delimitan el valor, no debe estar entre comillas.

NAME

signtool

Netscape Signing Tool

SYNOPSIS

signtool [options] [file ...]

DESCRIPTION

The signtool program is a tool for signing JavaScript files, Java applets, and other code modules that will be distributed over the network.

It works by creating a JAR (Java Archive) file containing the code to be signed, along with a manifest, signature files, and a signature block. The signature files are created using information from a digital certificate and a private key.

Listing Certificates

To list the object-signing certificates currently available to signtool, use the -l option:

signtool -l
using certificate directory: /u/jsmith/.netscape
Object signing certificates
---------------------------------------
Verisign Object Signing Cert
    Issued by: VeriSign, Inc. - Verisign, Inc.
    Expires: Tue May 19, 1998
test object signing cert
    Issued by: test object signing cert (Signtool 1.0 Testing
Certificate (960187691))
    Expires: Sun May 17, 1998
---------------------------------------

Para obtener una lista que incluya las AC, utiliza la opción -L.

Firmando un Archivo

1. Crea un directorio vacío.

mkdir signdir

2. Coloca algún archivo en él.

echo boo > signdir/test.f

3. Especifica el nombre de tu certificado de firma de objetos y firma el directorio.

signtool -k MySignCert -Z testjar.jar signdir
using key "MySignCert"
using certificate directory: /u/jsmith/.netscape
Generating signdir/META-INF/manifest.mf file..
--> test.f
adding signdir/test.f to testjar.jar
Generating signtool.sf file..
Enter Password or Pin for "Communicator Certificate DB":
adding signdir/META-INF/manifest.mf to testjar.jar
adding signdir/META-INF/signtool.sf to testjar.jar
adding signdir/META-INF/signtool.rsa to testjar.jar
tree "signdir" signed successfully

4. Prueba el archivo que acabas de crear.

signtool -v testjar.jar
using certificate directory: /u/jsmith/.netscape
archive "testjar.jar" has passed crypto verification.
           status   path
     ------------   -------------------
         verified   test.f

Uso de Netscape Signing Tool con una Utilidad ZIP

Para usar Netscape Signing Tool con una utilidad ZIP, debes tener la utilidad en tu variable de entorno PATH. Debes usar la utilidad zip.exe en lugar de pkzip.exe, la cual no puede manejar nombres de archivo largos. Puedes usar una utilidad ZIP en lugar de la opción -Z para empaquetar un archivo firmado en un archivo JAR después de haberlo firmado:

cd signdir
  zip -r ../myjar.jar *
  adding: META-INF/ (stored 0%)
  adding: META-INF/manifest.mf (deflated 15%)
  adding: META-INF/signtool.sf (deflated 28%)
  adding: META-INF/signtool.rsa (stored 0%)
  adding: text.txt (stored 0%)

Generación de Claves y Certificados

La opción -G de signtool genera un nuevo par de claves pública-privada y un certificado. Toma el alias del nuevo certificado como argumento. Las claves y el certificado recién generados se instalan en las bases de datos de claves y certificados en el directorio especificado por la opción -d. Con la versión NT de Netscape Signing Tool, debes usar la opción -d con la opción -G. Con la versión Unix de Netscape Signing Tool, omitir la opción -d hace que la herramienta instale las claves y el certificado en las bases de datos de claves y certificados de Communicator. En todos los casos, el certificado también se exporta a un archivo llamado x509.cacert, que tiene el tipo MIME application/x-x509-ca-cert.

Los certificados contienen información estándar sobre la entidad que identifican, como el nombre común y el nombre de la organización. Netscape Signing Tool te pide esta información cuando ejecutas el comando con la opción -G. Sin embargo, todos los campos solicitados son opcionales para los certificados de prueba. Si no ingresas un nombre común, la herramienta proporciona un nombre predeterminado. En el siguiente ejemplo, la entrada del usuario está en negrita:

signtool -G MyTestCert
using certificate directory: /u/someuser/.netscape
Enter certificate information. All fields are optional. Acceptable
characters are numbers, letters, spaces, and apostrophes.
certificate common name: Test Object Signing Certificate
organization: Netscape Communications Corp.
organization unit: Server Products Division
state or province: California
country (must be exactly 2 characters): US
username: someuser
email address: someuser@netscape.com
Enter Password or Pin for "Communicator Certificate DB": [Password will not echo]
generated public/private key pair
certificate request generated
certificate has been signed
certificate "MyTestCert" added to database
Exported certificate to x509.raw and x509.cacert.

La información del certificado se lee de la entrada estándar. Por lo tanto, la información puede leerse de un archivo utilizando el operador de redirección (<) en algunos sistemas operativos. Para crear un archivo con este propósito, ingresa cada uno de los siete campos de entrada, en orden, en una línea separada. Asegúrate de que haya un carácter de nueva línea al final de la última línea. Luego ejecuta signtool con la entrada estándar redirigida desde tu archivo de la siguiente manera:

signtool -G MyTestCert inputfile

Los prompts aparecen en la pantalla, pero las respuestas se leerán automáticamente del archivo. La contraseña todavía se leerá de la consola a menos que uses la opción -p para proporcionar la contraseña en la línea de comandos.

Uso de Netscape Signing Tool y una Tarjeta Inteligente para Firmar Archivos

El comando signtool normalmente toma un argumento de la opción -k para especificar un certificado de firma. Para firmar con una tarjeta inteligente, solo proporcionas el nombre completo del certificado.

Para ver los nombres completos de los certificados cuando ejecutas Communicator, haz clic en el botón Seguridad en Navigator, luego haz clic en Tus bajo Certificados en el marco izquierdo. Los nombres completos tienen el formato tarjeta inteligente:certificado, por ejemplo "MyCard:My Signing Cert". Usas este nombre con el argumento -k de la siguiente manera:

signtool -k "MyCard:My Signing Cert" directory

Verificación del Modo FIPS

Usa la opción -M para verificar que estás utilizando el módulo FIPS-140-1.

signtool -d "c:\netscape\users\jsmith" -M
using certificate directory: c:\netscape\users\jsmith
Listing of PKCS11 modules
-----------------------------------------------
  1. Netscape Internal PKCS #11 Module
          (this module is internally loaded)
          slots: 2 slots attached
          status: loaded
    slot: Communicator Internal Cryptographic Services Version 4.0
   token: Communicator Generic Crypto Svcs
    slot: Communicator User Private Key and Certificate Services
   token: Communicator Certificate DB
-----------------------------------------------

Este ejemplo de Unix muestra que Netscape Signing Tool está utilizando un módulo FIPS-140-1:

signtool -d "c:\netscape\users\jsmith" -M
using certificate directory: c:\netscape\users\jsmith
Enter Password or Pin for "Communicator Certificate DB": [password will not echo]
Listing of PKCS11 modules
-----------------------------------------------
1. Netscape Internal FIPS PKCS #11 Module
(this module is internally loaded)
slots: 1 slots attached
status: loaded

token: Communicator Certificate DB
