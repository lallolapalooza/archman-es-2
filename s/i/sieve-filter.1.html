NOMBRE

sieve-filter - Herramienta de filtrado de buzón Sieve de Pigeonhole

Esta herramienta todavía está en fase experimental. Lea este manual detenidamente y haga una copia de seguridad de cualquier correo importante antes de usar esta herramienta. Tenga en cuenta también que algunas de las características descritas aquí aún no están implementadas; esto se indica claramente donde corresponde.

SINOPSIS

sieve-filter [opciones] archivo-script buzón-origen [acción-descarte]

DESCRIPCIÓN


El comando forma parte de Pigeonhole (pigeonhole(7)), que añade soporte para Sieve (RFC 5228) y ManageSieve (RFC 5804) a Dovecot (dovecot(1)).

El lenguaje Sieve se diseñó originalmente para filtrar mensajes al momento de la entrega. Sin embargo, hay ocasiones en las que es deseable filtrar mensajes que ya están almacenados en un buzón, por ejemplo, cuando un error en un script Sieve provocó que muchos mensajes se entregaran incorrectamente. Utilizando la herramienta sieve-filter, es posible aplicar un script Sieve a todos los mensajes de un buzón-origen particular, lo que permite eliminar mensajes, almacenarlos en un buzón diferente, cambiar su contenido y cambiar las banderas e palabras clave asignadas de IMAP. Los intentos de enviar mensajes al mundo exterior se ignoran por defecto por razones obvias, pero, utilizando las opciones de línea de comandos adecuadas, es posible capturar y manejar también el correo saliente.

Si no se especifican opciones, el comando sieve-filter se ejecuta en modo de simulación, en el que solo imprime lo que se realizaría, sin hacer nada en realidad. Utilice la opción -e para activar la ejecución real del script. Además, el buzón-origen se abre en modo de solo lectura por defecto, lo que significa que normalmente siempre permanece sin cambios. Utilice la opción -W para permitir cambios en el buzón-origen.

Incluso con la opción -W habilitada, los mensajes en el buzón-origen solo se modifican potencialmente o se mueven a una carpeta diferente. Los mensajes nunca se pierden a menos que se especifique un argumento acción-descarte distinto de keep (el valor predeterminado). Si el filtro Sieve decide almacenar el mensaje en el buzón-origen, donde obviamente ya existe, nunca se duplica allí. En ese caso, las banderas IMAP del mensaje original pueden ser modificadas por el intérprete Sieve utilizando la extensión imap4flags, siempre que se especifique -W. Si el mensaje en sí es modificado por el intérprete Sieve (por ejemplo, utilizando la extensión editheader), se almacena un nuevo mensaje y el antiguo se expulsa. Sin embargo, si se omite -W, el mensaje original se deja intacto y las modificaciones se descartan.

PRECAUCIÓN

Aunque esta es una herramienta muy útil, también puede ser muy destructiva si se usa incorrectamente. Un pequeño error en su script Sieve en combinación con las opciones de línea de comandos incorrectas podría hacer que descarte los correos equivocados. E, incluso si el buzón-origen se abre en modo de solo lectura para evitar tales percances, todavía puede llenar otros buzones con copias espurias de sus correos electrónicos si su script Sieve decide hacerlo. Por lo tanto, se aconseja a los usuarios leer este manual detenidamente y usar primero el modo de simulación para verificar lo que hará el script. Y, por supuesto:

¡HACER UNA COPIA DE SEGURIDAD ES IMPRESCINDIBLE PARA CUALQUIER CORREO IMPORTANTE!

OPCIONES

-c archivo-config

Ruta alternativa al archivo de configuración de Dovecot.

-C


y su hora de modificación es más reciente que el archivo de script, se utiliza y el script no se compila de nuevo. Esta opción fuerza la compilación del script, ignorando así cualquier binario presente. Consulte sievec(1) para obtener más información sobre la compilación de Sieve.

-d archivo-volcado

Provoca que se escriba un volcado del código generado en el archivo especificado. Esto es idéntico al volcado producido por sieve-dump(1). Usar '-' como nombre de archivo hace que el volcado se escriba en

-D

Habilita la depuración de Sieve.

-e

Activa el modo de ejecución. Por defecto, el comando sieve-filter se ejecuta en modo de simulación, en el que no cambia nada, lo que significa que ningún buzón se modifica de ninguna manera y no se realizan acciones. Solo imprime lo que se haría. Al usar esta opción, el comando sieve-filter se activa y realiza las acciones solicitadas.

-m buzón-predeterminado

El buzón donde la acción Sieve keep (implícita) almacena los mensajes. Este es igual al buzón-origen por defecto. Especificar una carpeta diferente tendrá el efecto de mover (o copiar si se omite -W) todos los mensajes conservados a la carpeta indicada, en lugar de simplemente dejarlos en el buzón-origen. Consulte la explicación del argumento buzón-origen para obtener más información sobre la nomenclatura de buzones.

-o ajuste=valor

Anula el ajuste de configuración de /etc/dovecot/dovecot.conf y de la base de datos de usuarios con el valor dado. Para anular varios ajustes, la opción -o puede especificarse varias veces.

-q buzón-salida [aún no implementado]

Almacena el correo saliente en el buzón-salida indicado. Por defecto, el comando sieve-filter ignora las acciones de Sieve como redirect, reject, vacation y notify, pero usando esta opción los mensajes salientes se pueden añadir al buzón indicado. Esta opción no tiene efecto en modo de simulación. Las banderas de los mensajes redirigidos no se conservan.

-Q comando-correo [aún no implementado]

Envía el correo saliente (por ejemplo, producido por redirect, reject y vacation) a través del programa especificado. Por defecto, el comando sieve-filter ignora las acciones de Sieve como redirect, reject, vacation y notify, pero usando esta opción los mensajes salientes se pueden alimentar a la stdin de un comando externo de shell. Esta opción no tiene efecto en modo de simulación. A menos que realmente sepa lo que está haciendo, ¡NO USE ESTO PARA ENVIAR CORREO A SENDMAIL!.

-s archivo-script [aún no implementado]

Especifica scripts adicionales que se ejecutarán antes del script principal. Se permiten múltiples argumentos -s y los scripts especificados se ejecutan secuencialmente en el orden en que se especifican en la línea de comandos.

-u usuario/máscara

Ejecuta el comando solo para el usuario dado. También es posible usar los comodines '*' y '?' (por ejemplo, -u *@example.org).

-v

Produce salida detallada durante el filtrado.

-W

Habilita el acceso de escritura al buzón-origen. Esto permite (re)mover los mensajes del buzón-origen, cambiar su contenido y cambiar las banderas e palabras clave asignadas de IMAP.

-x auth_info

auth_info especifica condiciones adicionales para la búsqueda de la base de datos de usuarios. La cadena de opción auth_info debe darse como un par nombre = valor. Para múltiples condiciones, la opción -x podría proporcionarse varias veces.

Los nombres posibles para auth_info son:

service

El servicio para el cual se debe probar la búsqueda en la base de datos de usuarios. El valor puede ser el nombre de un servicio, comúnmente utilizado con Dovecot. Por ejemplo: imap, pop3 o smtp.

session

Identificador de sesión.

lip

La dirección IP local (servidor) para la prueba.

rip

La dirección IP remota (cliente) para la prueba.

lport

Ele puerto local, por ejemplo, 143

rport

El puerto remoto, por ejemplo, 24567

real_lip

La IP local a la que se conectó el cliente en este host.

real_rip

La IP remota desde la que se conectó el cliente a este host.

real_lport

El puerto local al que se conectó el cliente a este host.

real_rport

El puerto remoto desde el que se conectó el cliente a este host.

forward_<field>

Campo para reenviar como %{forward:campo} al proceso de autenticación.

ARGUMENTOS

script-archivo

Especifica el script Sieve a (compilar y) ejecutar.

Tenga en cuenta que esta herramienta busca un archivo binario precompilado con una extensión .svbin y con el mismo nombre base y ruta que el script especificado. Utilice la opción -C para deshabilitar este comportamiento forzando la compilación del script a un nuevo binario.

buzón-fuente

Especifica el buzón de origen que contiene los mensajes sobre los que actuará el filtro Sieve.

Este es el nombre de un buzón, tal como lo ven los clientes IMAP, excepto en formato UTF-8. El separador de jerarquía entre un buzón padre e hijo suele ser '/' o '.', pero esto depende del formato de almacenamiento de buzones seleccionado y de la configuración del espacio de nombres. Los nombres de buzón también pueden requerir un prefijo de espacio de nombres.

Este buzón no se modifica a menos que se especifique la opción -W.

accion-descarte

Especifica qué se hace con los mensajes en el buzón-fuente que no fueron conservados o almacenados de otra manera por el script Sieve; es decir, aquellos mensajes que normalmente se descartarían si el script Sieve se ejecutara en la entrega. El parámetro accion-descarte acepta uno de

los siguientes valores:

keep (predeterminado) : Conservar los mensajes descartados en el buzón de origen.

move buzon : Mover los mensajes descartados al buzón indicado. Esto es útil, por ejemplo, para mover mensajes a un buzón de Papelera. Consulte la explicación del argumento buzón-fuente para obtener más información sobre la nomenclatura de buzones.

delete : Marcar los mensajes descartados como \DELETED.

expunge : Eliminar los mensajes descartados, lo que significa que se eliminan irreversiblemente cuando la herramienta termina de filtrar.

Cuando la opción -W no se especifica, el buzón-fuente es inmutable y la accion-descarte especificada no tiene ningún efecto. Esto significa que los mensajes se copian como máximo a una nueva ubicación. En contraste, cuando se especifica -W, los mensajes que se almacenan correctamente en otro lugar mediante el script Sieve se siempre eliminan del buzón-fuente, con el efecto de que se mueven a la nueva ubicación. Esto ocurre independientemente de la accion-descarte especificada. Recuerde: solo los mensajes descartados se ven afectados por la accion-descarte especificada.

ESTADO DE SALIDA

sieve-filter saldrá con uno de los siguientes valores:

0

Filtro Sieve aplicado con éxito. (EX_OK, EXIT_SUCCESS)

64

Error en el uso de la línea de comandos.

65

Error de formato de datos o la operación no es posible.

67

El usuario no existe.

68

No se encontró el archivo de entrada, la dirección u otro recurso.

73

No se pudo crear el archivo de salida.

75

Hubo algún error temporal, consulte los registros.

76

Error de protocolo durante la conexión con el host remoto.

77

Error de permiso.

78

Error de configuración.

127

Error desconocido.
