sigaction(2) Manual de llamadas al sistema sigaction(2)

NOMBRE

sigaction, rt_sigaction - examinar y cambiar una acción de señal

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <signal.h>
int sigaction(int signum,
              const struct sigaction *_Nullable restrict act,
              struct sigaction *_Nullable restrict oldact);
Requisitos de Macro de Prueba de Funciones para glibc (ver feature_test_macros(7)):

sigaction():

    _POSIX_C_SOURCE

siginfo_t:

    _POSIX_C_SOURCE >= 199309L

DESCRIPCIÓN

La llamada al sistema sigaction() se utiliza para cambiar la acción que toma un proceso al recibir una señal específica. (Ver signal(7) para una visión general de las señales.)

signum especifica la señal y puede ser cualquier señal válida excepto SIGKILL y SIGSTOP.

Si act no es NULL, la nueva acción para la señal signum se instala desde act. Si oldact no es NULL, la acción anterior se guarda en oldact.

La estructura sigaction se define como algo parecido a:


struct sigaction {
    void     (*sa_handler)(int);
    void     (*sa_sigaction)(int, siginfo_t *, void *);
    sigset_t   sa_mask;
    int        sa_flags;
    void     (*sa_restorer)(void);
};

En algunas arquitecturas interviene una unión: no asignes a sa_handler ni a sa_sigaction.

El campo sa_restorer no está destinado al uso por parte de la aplicación. (POSIX no especifica un campo sa_restorer). Algunos detalles adicionales sobre el propósito de este campo se pueden encontrar en sigreturn(2).

sa_handler especifica la acción a asociar con signum y puede ser una de las siguientes:

•
SIG_DFL para la acción predeterminada.
•
SIG_IGN para ignorar esta señal.
•
Un puntero a una función manejadora de señales. Esta función recibe el número de señal como único argumento.

Si se especifica SA_SIGINFO en sa_flags, entonces sa_sigaction (en lugar de sa_handler) especifica la función manejadora de señales para signum. Esta función recibe tres argumentos, como se describe a continuación.

sa_mask especifica una máscara de señales que deben bloquearse (es decir, añadirse a la máscara de señales del hilo en el que se invoca el manejador de señales) durante la ejecución del manejador de señales. Además, la señal que desencadenó el manejador se bloqueará, a menos que se utilice la bandera SA_NODEFER.

sa_flags especifica un conjunto de banderas que modifican el comportamiento de la señal. Se forma mediante la operación OR a nivel de bits de cero o más de las siguientes:

SA_NOCLDSTOP
Si signum es SIGCHLD, no recibir notificación cuando los hijos se detienen (es decir, cuando reciben SIGSTOP, SIGTSTP, SIGTTIN o SIGTTOU) o se reanudan (es decir, cuando reciben SIGCONT) (ver wait(2)). Esta bandera solo es significativa cuando se establece un manejador para SIGCHLD.
SA_NOCLDWAIT (desde Linux 2.6)
Si signum es SIGCHLD, no transformar a los hijos en zombies cuando terminan. Ver también waitpid(2). Esta bandera solo es significativa cuando se establece un manejador para SIGCHLD, o cuando se establece la disposición de esa señal a SIG_DFL.
Si la bandera SA_NOCLDWAIT se establece al registrar un manejador para SIGCHLD, POSIX.1 deja sin especificar si se genera una señal SIGCHLD cuando un proceso hijo termina. En Linux, en este caso se genera una señal SIGCHLD; en otras implementaciones, no.
SA_NODEFER
No añadir la señal a la máscara de señales del hilo mientras se ejecuta el manejador de señales, a menos que la señal se especifique en act.sa_mask. En consecuencia, se puede entregar otra instancia de la señal al hilo mientras se está ejecutando el manejador. Esta bandera solo es significativa cuando se establece un manejador de señales.
SA_NOMASK es un sinónimo obsoleto y no estándar de esta bandera.
SA_ONSTACK
Llamar al manejador de señales en una pila de señales alternativa proporcionada por sigaltstack(2). Si no hay una pila alternativa disponible, se utilizará la pila predeterminada. Esta bandera solo es significativa cuando se establece un manejador de señales.
SA_RESETHAND
Restaurar la acción de la señal a la predeterminada al entrar en el manejador de señales. Esta bandera solo es significativa cuando se establece un manejador de señales.
SA_ONESHOT es un sinónimo obsoleto y no estándar de esta bandera.
SA_RESTART
Proporcionar un comportamiento compatible con la semántica de señales BSD haciendo que ciertas llamadas al sistema sean reiniciables después de las señales. Esta bandera solo es significativa cuando se establece un manejador de señales. Ver signal(7) para una discusión sobre el reinicio de llamadas al sistema.
SA_RESTORER
No destinado al uso por parte de la aplicación. Esta bandera la utilizan las bibliotecas C para indicar que el campo sa_restorer contiene la dirección de un "trampolín de señal". Ver sigreturn(2) para más detalles.
SA_SIGINFO (desde Linux 2.2)
El manejador de señales toma tres argumentos, no uno. En este caso, se debe establecer sa_sigaction en lugar de sa_handler. Esta bandera solo es significativa cuando se establece un manejador de señales.
SA_UNSUPPORTED (desde Linux 5.11)
Se utiliza para sondeos dinámicos de soporte de bits de bandera.
Si un intento de registrar un manejador tiene éxito con esta bandera establecida en act->sa_flags junto con otras banderas que potencialmente no son compatibles con el kernel, y una llamada posterior inmediata a sigaction() que especifica el mismo número de señal y con un argumento oldact no nulo devuelve SA_UNSUPPORTED despejado en oldact->sa_flags, entonces oldact->sa_flags puede usarse como una máscara de bits que describe qué banderas potencialmente no compatibles son, de hecho, compatibles. Ver la sección "Sondeo dinámico de soporte de bits de bandera" a continuación para más detalles.
SA_EXPOSE_TAGBITS (desde Linux 5.11)
Normalmente, al entregar una señal, se limpian un conjunto de bits de etiqueta específicos de la arquitectura del campo si_addr de siginfo_t. Si esta bandera está establecida, se conservará un subconjunto específico de la arquitectura de los bits de etiqueta en si_addr.
Los programas que necesiten ser compatibles con versiones de Linux anteriores a la 5.11 deben usar SA_UNSUPPORTED para sondear el soporte.

El argumento siginfo_t a un manejador SA_SIGINFO

Cuando se especifica la bandera SA_SIGINFO en act.sa_flags, la dirección del manejador de señales se pasa a través del campo act.sa_sigaction. Este manejador toma tres argumentos, como sigue:


void
handler(int sig, siginfo_t *info, void *ucontext)
{
    ...
}

NAME

sigaction - examine and change signal actions

SYNOPSIS

#include <signal.h>

int sigaction(int sig, const struct sigaction *restrict act, struct sigaction *restrict oldact);

DESCRIPTION

The sigaction() system call is used to change the action taken when a signal is delivered. The argument sig is the signal number. The behavior of sigaction() depends on the value of sig and the values of the fields in the structure pointed to by act.

If act is not NULL, it points to a structure that specifies the new action to be taken when the signal sig is delivered. If oldact is not NULL, the previous action for the signal is stored in the location pointed to by oldact.

The sigaction structure contains at least the following fields:

sa_handler
Signal handler function. This must be either a pointer to a function that accepts a single integer argument (the signal number), or SIG_DFL (the default action), or SIG_IGN (ignore the signal).
sa_sigaction
An alternative signal handler function that is invoked if the SA_SIGINFO flag is set in sa_flags. This function takes three arguments.
sa_mask
Additional signals to be blocked during execution of the signal handler. The signals in sa_mask are added to the signal mask of the thread before the handler is invoked, and are restored to the previous mask when the handler returns. If SA_NODEFER is set in sa_flags, then sig itself is not added to the mask.
sa_flags
Flags that modify the behavior of the signal handling. The following flags are defined:
SA_NODEFER: Do not automatically block the signal being handled (i.e., sig itself) during the execution of the handler.
SA_NOCLDSTOP: If sig is SIGCHLD, do not send it when a child process stops (i.e., undergoes SIGSTOP, SIGTSTP, SIGTTIN, or SIGTTOU), but only when it terminates or resumes.
SA_NOCLDWAIT: If sig is SIGCHLD, do not put the child process in a zombie state when it terminates. This flag is meaningful only when handling SIGCHLD. If this flag is set, the system does not create a zombie process entry for the terminated child; the child's exit status is discarded. The system automatically reclaims the process table entry for the child process.
SA_RESETHAND: Restore the default signal handler for the signal after entering the handler. The default action for the signal is performed if the signal is delivered again after the handler has returned.
SA_RESTART: Ensure that certain system calls that are interrupted by this signal are automatically restarted instead of returning an error of EINTR. This flag can be used with either sa_handler or sa_sigaction. The set of system calls that are restarted is implementation-dependent. On Linux, the following system calls are restarted if this flag is set: read(2), write(2), ioctl(2), select(2), poll(2), epoll_wait(2), nanosleep(2), accept(2), connect(2), sendfile(2), pipe(2), futex(2), getmsg(2), pause(2), recv(2), send(2), sendto(2), sendmsg(2), sendmmsg(2), splice(2), epoll_pwait(2), mq_receive(2), mq_timedreceive(2), msgrcv(2), aio_read(3p), aio_write(3p), lio_listio(3p), sigwaitinfo(2), sigtimedwait(2), pread(2), pwrite(2), get_current_dir_name(3), sendfile64(2), pread64(2), pwrite64(2), aio_read_64(3p), aio_write_64(3p), preadv(2), pwritev(2), recvmmsg(2), mq_timedreceive(2), close(2), open(2), fcntl(2), ioctl(2), readv(2), writev(2), sendmsg(2), recvmsg(2), preadv2(2), pwritev2(2), stat(2), fstat(2), lstat(2), stat64(2), fstat64(2), lstat64(2), getdents(2), getdents64(2), flock(2), fcntl(2), accept4(2), readlink(2), readlinkat(2), rename(2), renameat(2), renameat2(2).
SA_SIGINFO: Use the sa_sigaction field to specify the signal handler. This allows the handler to receive more information about the signal, as described below.

If the SA_SIGINFO flag is specified in sa_flags, then the signal handler must be pointed to by sa_sigaction, and it will be invoked with three arguments:

sig
The number of the signal that caused the invocation of the handler.
info
A pointer to a siginfo_t, which is a structure containing further information about the signal, as described below.
ucontext
This is a pointer to a ucontext_t structure, cast to void *. The structure pointed to by this field contains signal context information that was saved on the user-space stack by the kernel; for details, see sigreturn(2). Further information about the ucontext_t structure can be found in getcontext(3) and signal(7). Commonly, the handler function doesn't make any use of the third argument.

The siginfo_t data type is a structure with the following fields:


siginfo_t {
    int      si_signo;     /* Signal number */
    int      si_errno;     /* An errno value */
    int      si_code;      /* Signal code */
    int      si_trapno;    /* Trap number that caused
                              hardware-generated signal
                              (unused on most architectures) */
    pid_t    si_pid;       /* Sending process ID */
    uid_t    si_uid;       /* Real user ID of sending process */
    int      si_status;    /* Exit value or signal */
    clock_t  si_utime;     /* User time consumed */
    clock_t  si_stime;     /* System time consumed */
    union sigval si_value; /* Signal value */
    int      si_int;       /* POSIX.1b signal */
    void    *si_ptr;       /* POSIX.1b signal */
    int      si_overrun;   /* Timer overrun count;
                              POSIX.1b timers */
    int      si_timerid;   /* Timer ID; POSIX.1b timers */
    void    *si_addr;      /* Memory location which caused fault */
    long     si_band;      /* Band event (was int in
                              glibc 2.3.2 and earlier) */
    int      si_fd;        /* File descriptor */
    short    si_addr_lsb;  /* Least significant bit of address
                              (since Linux 2.6.32) */
    void    *si_lower;     /* Lower bound when address violation
                              occurred (since Linux 3.19) */
    void    *si_upper;     /* Upper bound when address violation
                              occurred (since Linux 3.19) */
    int      si_pkey;      /* Protection key on PTE that caused
                              fault (since Linux 4.6) */
    void    *si_call_addr; /* Address of system call instruction
                              (since Linux 3.5) */
    int      si_syscall;   /* Number of attempted system call
                              (since Linux 3.5) */
    unsigned int si_arch;  /* Architecture of attempted system call
                              (since Linux 3.5) */
}

si_signo, si_errno and si_code are defined for all signals. (si_errno is generally unused on Linux.) The rest of the struct may be a union, so that one should read only the fields that are meaningful for the given signal:

•
Signals sent with kill(2) and sigqueue(3) fill in si_pid and si_uid. In addition, signals sent with sigqueue(3) fill in si_int and si_ptr with the values specified by the sender of the signal; see sigqueue(3) for more details.
•
Signals sent by POSIX.1b timers (since Linux 2.6) fill in si_overrun and si_timerid. The si_timerid field is an internal ID used by the kernel to identify the timer; it is not the same as the timer ID returned by timer_create(2). The si_overrun field is the timer overrun count; this is the same information as is obtained by a call to timer_getoverrun(2). These fields are nonstandard Linux extensions.
•
Signals sent for message queue notification (see the description of SIGEV_SIGNAL in mq_notify(3)) fill in si_int/si_ptr, with the sigev_value supplied to mq_notify(3); si_pid, with the process ID of the message sender; and si_uid, with the real user ID of the message sender.
•
SIGCHLD fills in si_pid, si_uid, si_status, si_utime, and si_stime, providing information about the child. The si_pid field is the process ID of the child; si_uid is the child's real user ID. The si_status field contains the exit status of the child (if si_code is CLD_EXITED), or the signal number that caused the process to change state. The si_utime and si_stime contain the user and system CPU time used by the child process; these fields do not include the times used by waited-for children (unlike getrusage(2) and times(2)). Up to Linux 2.6, and since Linux 2.6.27, these fields report CPU time in units of sysconf(_SC_CLK_TCK). In Linux 2.6 kernels before Linux 2.6.27, a bug meant that these fields reported time in units of the (configurable) system jiffy (see time(7)).
•
SIGILL, SIGFPE, SIGSEGV, SIGBUS, and SIGTRAP fill in si_addr with the address of the fault. On some architectures, these signals also fill in the si_trapno field.
Some suberrors of SIGBUS, in particular BUS_MCEERR_AO and BUS_MCEERR_AR, also fill in si_addr_lsb. This field indicates the least significant bit of the reported address and therefore the extent of the corruption. For example, if a full page was corrupted, si_addr_lsb contains log2(sysconf(_SC_PAGESIZE)). When SIGTRAP is delivered in response to a ptrace(2) event (PTRACE_EVENT_foo), si_addr is not populated, but si_pid and si_uid are populated with the respective process ID and user ID responsible for delivering the trap. In the case of seccomp(2), the tracee will be shown as delivering the event. BUS_MCEERR_* and si_addr_lsb are Linux-specific extensions.
The SEGV_BNDERR suberror of SIGSEGV populates si_lower and si_upper.
The SEGV_PKUERR suberror of SIGSEGV populates si_pkey.
•
SIGIO/SIGPOLL (the two names are synonyms on Linux) fills in si_band and si_fd. The si_band event is a bit mask containing the same values as are filled in the revents field by poll(2). The si_fd field indicates the file descriptor for which the I/O event occurred; for further details, see the description of F_SETSIG in fcntl(2).
•
SIGSYS, generated (since Linux 3.5) when a seccomp filter returns SECCOMP_RET_TRAP, fills in si_call_addr, si_syscall, si_arch, si_errno, and other fields as described in seccomp(2).

The si_code field

The si_code field inside the siginfo_t argument that is passed to a SA_SIGINFO signal handler is a value (not a bit mask) indicating why this signal was sent. For a ptrace(2) event, si_code will contain SIGTRAP and have the ptrace event in the high byte:


(SIGTRAP | PTRACE_EVENT_foo << 8).

•
_XOPEN_SOURCE with the value 500 or greater;
•
_XOPEN_SOURCE and _XOPEN_SOURCE_EXTENDED; or
•
_POSIX_C_SOURCE with the value 200809L or greater.

For the TRAP_* constants, the symbol definitions are provided only in the first two cases. Before glibc 2.20, no feature test macros were required to obtain these symbols.

RETURN VALUE

On success, 0 is returned. On failure, -1 is returned, and errno is set to indicate the error.

ERRORS

The sigaction() call can fail for the following reasons:

EINVAL
An invalid signal number was specified.
ENOTSUP
The signal specified is not supported by the system.

STANDARDS

The sigaction() system call conforms to the POSIX.1-2008 standard.

The sa_flags values SA_NODEFER, SA_NOCLDSTOP, SA_NOCLDWAIT, SA_RESETHAND, and SA_RESTART are described in POSIX.1-2001 and later. The SA_SIGINFO flag is also described in POSIX.1-2001 and later.

The siginfo_t structure fields si_errno, si_code, si_pid, si_uid, si_status, si_utime, si_stime, si_value, si_int, si_ptr, si_overrun, si_timerid, si_addr, si_band, and si_fd are described in POSIX.1-2001 and later. The codes SI_USER, SI_KERNEL, SI_QUEUE, SI_TIMER, SI_ASYNCIO, SI_SIGIO, SI_TKILL, SI_ASYNCNL, ILL_ILLOPC, ILL_ILLOPN, ILL_ILLADR, ILL_ILLTRP, ILL_PRVOPC, ILL_COPROC, ILL_BADSTK, FPE_INTDIV, FPE_INTOVF, FPE_FLTDIV, FPE_FLTOVF, FPE_FLTUND, FPE_FLTRES, FPE_FLTINV, FPE_FLTSUB, SEGV_MAPERR, SEGV_ACCERR, BUS_ADRALN, BUS_ADRFMT, BUS_OBJERR, CLD_EXITED, CLD_KILLED, CLD_DUMPED, CLD_STOPPED, CLD_TRAPPED, POLL_IN, POLL_PRI, POLL_OUT, POLL_ERR, POLL_HUP, POLL_RDNORM, POLL_RDBAND, and POLL_WRBAND are described in POSIX.1-2001 and later.

The siginfo_t fields si_addr_lsb, si_lower, si_upper, si_pkey, si_call_addr, si_syscall, and si_arch, and the codes BUS_MCEERR_AO, BUS_MCEERR_AR, SEGV_BNDERR, SEGV_PKUERR, CLD_CONTINUED, and SYS_SECCOMP are specific to Linux.

HISTORY

The sigaction() system call first appeared in POSIX.1.

The sa_flags field and the associated flags have evolved over time. The siginfo_t structure and its fields have also evolved.

SYNOPSIS

#include <signal.h>

int sigaction(int sig, const struct sigaction *restrict act, struct sigaction *restrict oldact);

DESCRIPTION

The sigaction() system call is used to change the action taken when a signal is delivered to a process. The argument sig is the signal number to which this action applies. This can be a signal defined in <signal.h> (e.g., SIGINT), but it cannot be SIGKILL or SIGSTOP.

The argument act points to a structure that specifies the new action to be taken. If act is NULL, then the current action for the signal is not changed.

The argument oldact points to a buffer where the previous action for the signal is to be stored. If oldact is NULL, then the previous action is not saved.

The struct sigaction structure contains at least the following fields:

void (*sa_handler)(int);
The signal-handling function, or SIG_DFL for the default action, or SIG_IGN to ignore the signal.
sigset_t sa_mask;
A signal mask that defines the set of signals to be blocked during the execution of the signal handler. In addition to the signals specified in sa_mask, the signal being handled is also automatically blocked during the execution of the handler. If SA_NODEFER is specified in sa_flags, then the signal being handled is not automatically blocked.
int sa_flags;
Flags that modify the behavior of the signal handling. See below.
void (*sa_restorer)(void);
This field is present only on some architectures (e.g., i386, x86_64, ARM, MIPS). If not NULL, it points to a handler that will be invoked to restore the execution context after the signal handler returns. If SA_RESTORER is not specified in sa_flags, this field is ignored.

The following values may be set for sa_flags:

SA_NOCLDSTOP
If the signal is SIGCHLD, do not send it to the parent process when a child process stops (is suspended) or stops because it is being traced. The signal is only sent to the parent when a child process terminates.
SA_NOCLDWAIT
If the signal is SIGCHLD, prevent the system from performing the default action of destroying the child process termination status when the signal is delivered. This is useful for implementing uninterruptible waits for child processes. The process will need to reap its children using waitpid(2).
SA_SIGINFO
Provide more detailed information to the signal handler. Instead of sa_handler, the handler must be specified by sa_sigaction, which has the signature:

void handler(int sig, siginfo_t *info, void *ucontext);

The info argument points to a siginfo_t structure, which provides details about why the signal was generated. The ucontext argument points to a ucontext_t structure, which provides the context of the interrupted code. The siginfo_t structure contains at least the following fields:

int si_signo;
Signal number.
int si_errno;
If non-zero, contains a system error number associated with this signal, as shown in errno(3).
int si_code;
Signal code. The meaning of this field depends on the signal number.
uid_t si_uid;
Real user ID of the sender, or 0 if from the kernel.

The following values can be placed in si_code for a SIGILL signal:

ILL_ILLOPC
Illegal opcode.
ILL_ILLTRP
Illegal trap.
ILL_PRVOPC
Privileged opcode.

SYNOPSIS

«include <signal.h>

int sigaction(int sig, const struct sigaction *restrict act, struct sigaction *restrict oldact);

DESCRIPTION

The C library function sigaction() is used to change the action taken when a signal is delivered. The calling process may examine or modify the action for each signal specified by the argument sig. The argument act points to a structure that specifies the new action to be taken, or to zero if the signal is to be left unchanged. The argument oldact points to a location where the old action is to be stored, or to zero if it is not needed.

The struct sigaction structure contains at least the following fields:

    void (*sa_handler)(int);
    void (*sa_sigaction)(int, siginfo_t *, void *);
    sigset_t sa_mask;
    int sa_flags;
    void (*sa_restorer)(void);

If act is not NULL, then sa_handler is the address of the signal-handling function, or one of the special values SIG_DFL (default action) or SIG_IGN (ignore signal).

If sa_flags includes the SA_SIGINFO flag, then sa_sigaction is used as the signal handler (and sa_handler is ignored). This handler receives three arguments: the signal number, a pointer to a siginfo_t structure containing detailed information about the signal, and a pointer to a ucontext_t structure (see getcontext(3)).

If sa_flags does not include SA_SIGINFO, then sa_handler is used as the signal handler, and it receives only one argument: the signal number. The sa_sigaction field is ignored.

The sa_mask field specifies a mask of signals to be blocked during the execution of the signal handler. When the signal handler returns, the set of blocked signals is restored to its state prior to the delivery of the signal. If sa_flags includes SA_NODEFER, then the signal being delivered is not added to the set of blocked signals.

The sa_flags field specifies a set of flags that modify the behavior of the signal handling.

The following flags are defined:
SA_NOCLDSTOP
If the signal is SIGCHLD, do not send a notification when a child process stops (until it is resumed). By default, SIGCHLD is sent when a child stops or terminates.
SA_NOCLDWAIT
If the signal is SIGCHLD, do not create zombie processes when a child terminates. The system reclaims the resources of the terminated child as soon as it has passed the final status to the parent via a wait(2) call (or if the parent explicitly ignores SIGCHLD).
SA_NODEFER
Do not automatically block the signal being delivered during the execution of its handler. By default, the signal being delivered is added to the set of blocked signals for the duration of the handler's execution.
SA_ONSTACK
Execute the handler on a different stack. This flag is supported only if a signal stack has been explicitly set up using sigaltstack(2).
SA_RESETHAND
Restore the signal handler to SIG_DFL when the signal is delivered. The handler will be reset after it has been executed. This flag is useful for signals that should only be processed once.
SA_RESTART
Some system calls may return prematurely when a signal is caught. If SA_RESTART is set, such system calls are automatically restarted if they return due to a signal. This behavior depends on the signal and the system call; see signal(7) for details.
SA_SIGINFO
The signal handler should be called with three arguments (signal number, pointer to siginfo_t, pointer to ucontext_t) rather than one (signal number). See the description of sa_sigaction above.
SA_EXPOSE_TAGBITS
(Since Linux 5.14) If this flag is set, and the signal is delivered via a pidfd_send_signal(2) call, then the top bits of the signal number are exposed in the si_signo field of the siginfo_t structure.

If sa_flags includes SA_SIGINFO, then the system call used is actually rt_sigaction(), which is a Linux-specific system call that handles extended signal sets. The glibc wrapper function transparently handles this, mapping it to the older sigaction() when necessary. The argument sa_restorer is used internally by glibc to manage the trampoline code required for signal handling. When SA_RESTORER is set in act.sa_flags, the glibc wrapper function for sigaction() places the address of the trampoline code in the act.sa_restorer field and sets the SA_RESTORER flag in the act.sa_flags field. See sigreturn(2).

The original Linux system call was named sigaction(). However, with the addition of real-time signals in Linux 2.2, the fixed-size, 32-bit sigset_t type supported by that system call was no longer fit for purpose. Consequently, a new system call, rt_sigaction(), was added to support an enlarged sigset_t type. The new system call takes a fourth argument, size_t sigsetsize, which specifies the size in bytes of the signal sets in act.sa_mask and oldact.sa_mask. This argument is currently required to have the value sizeof(sigset_t) (or the error EINVAL results). The glibc sigaction() wrapper function hides these details from us, transparently calling rt_sigaction() when the kernel provides it.

RETURN VALUE

On success, sigaction() returns 0. On error, it returns -1, and errno is set to indicate the error.

ERRORS

EINVAL
The signal number is invalid, or sigsetsize was not sizeof(sigset_t) when calling rt_sigaction().
ENOTSUP
sigsetsize was not sizeof(sigset_t) and the kernel does not support the older, fixed-size sigaction() system call.

VERSIONS

The SA_RESTART flag was added in Linux 2.1.116. The SA_NODEFER, SA_NOCLDWAIT, SA_ONSTACK, SA_RESETHAND, and SA_SIGINFO flags were added in Linux 2.2. The SA_EXPOSE_TAGBITS flag was added in Linux 5.14.

The rt_sigaction() system call was introduced in Linux 2.2. The glibc wrapper function transparently handles the transition to rt_sigaction() when available.

STANDARDS

POSIX.1-2024.

HISTORY

POSIX.1-2001, SVr4.

POSIX.1-1990 disallowed setting the action for SIGCHLD to SIG_IGN. POSIX.1-2001 and later allow this possibility, so that ignoring SIGCHLD can be used to prevent the creation of zombies (see wait(2)). Nevertheless, the historical BSD and System V behaviors for ignoring SIGCHLD differ, so that the only completely portable method of ensuring that terminated children do not become zombies is to catch the SIGCHLD signal and perform a wait(2) or similar.

POSIX.1-1990 specified only SA_NOCLDSTOP. POSIX.1-2001 added SA_NOCLDWAIT, SA_NODEFER, SA_ONSTACK, SA_RESETHAND, SA_RESTART, and SA_SIGINFO as XSI extensions. POSIX.1-2008 moved SA_NODEFER, SA_RESETHAND, SA_RESTART, and SA_SIGINFO to the base specifications. Use of these latter values in sa_flags may be less portable in applications intended for older UNIX implementations.

The SA_RESETHAND flag is compatible with the SVr4 flag of the same name.

The SA_NODEFER flag is compatible with the SVr4 flag of the same name under kernels 1.3.9 and later. On older kernels the Linux implementation allowed the receipt of any signal, not just the one we are installing (effectively overriding any sa_mask settings).

NOTES

A child created via fork(2) inherits a copy of its parent's signal dispositions. During an execve(2), the dispositions of handled signals are reset to the default; the dispositions of ignored signals are left unchanged.

According to POSIX, the behavior of a process is undefined after it ignores a SIGFPE, SIGILL, or SIGSEGV signal that was not generated by kill(2) or raise(3). Integer division by zero has undefined result. On some architectures it will generate a SIGFPE signal. (Also dividing the most negative integer by -1 may generate SIGFPE.) Ignoring this signal might lead to an endless loop.

sigaction() can be called with a NULL second argument to query the current signal handler. It can also be used to check whether a given signal is valid for the current machine by calling it with NULL second and third arguments.

It is not possible to block SIGKILL or SIGSTOP (by specifying them in sa_mask). Attempts to do so are silently ignored.

See sigsetops(3) for details on manipulating signal sets.

See signal-safety(7) for a list of the async-signal-safe functions that can be safely called inside from inside a signal handler.

POSIX only guarantees SI_TIMER for signals created by timer_create(2). Implementations are free to also provide it for other types of timers. The Linux behaviour matches NetBSD.

Undocumented

Before the introduction of SA_SIGINFO, it was also possible to get some additional information about the signal. This was done by providing an sa_handler signal handler with a second argument of type struct sigcontext, which is the same structure as the one that is passed in the uc_mcontext field of the ucontext structure that is passed (via a pointer) in the third argument of the sa_sigaction handler. See the relevant Linux kernel sources for details. This use is obsolete now.

BUGS

When delivering a signal resulting from a hardware exception with a SA_SIGINFO handler, the kernel does not always provide meaningful values for all of the fields of the siginfo_t that are relevant for that signal. For example, when the x86 int instruction is called with a forbidden argument (any number other than 3 or 128), a SIGSEGV signal is delivered, but the siginfo_t passed to the signal handler has all its fields besides si_signo and si_code set to zero, even if other fields should be set (as an example, si_addr should be non-zero for all SIGSEGV signals).

Up to and including Linux 2.6.13, specifying SA_NODEFER in sa_flags prevents not only the delivered signal from being masked during execution of the handler, but also the signals specified in sa_mask. This bug was fixed in Linux 2.6.14.

EXAMPLES

See mprotect(2).

Probing for flag support

The following example program exits with status EXIT_SUCCESS if SA_EXPOSE_TAGBITS is determined to be supported, and EXIT_FAILURE otherwise.

#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
static void
handler(int signo, siginfo_t *info, void *context)
{
    struct sigaction oldact;
    if (sigaction(SIGSEGV, NULL, &oldact) == -1
        || (oldact.sa_flags & SA_UNSUPPORTED)
        || !(oldact.sa_flags & SA_EXPOSE_TAGBITS))
    {
        _exit(EXIT_FAILURE);
    }
    _exit(EXIT_SUCCESS);
}
int
main(void)
{
    struct sigaction act = { 0 };
    act.sa_flags = SA_SIGINFO | SA_UNSUPPORTED | SA_EXPOSE_TAGBITS;
    act.sa_sigaction = &handler;
    if (sigaction(SIGSEGV, &act, NULL) == -1) {
        perror("sigaction");
        exit(EXIT_FAILURE);
    }
    raise(SIGSEGV);
}
