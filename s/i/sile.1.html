SILE(1) General Commands Manual SILE(1)

NOMBRE

SILE - El componedor SILE lee archivo(s) de entrada y compone el contenido en un formato de documento renderizado, típicamente PDF

SINOPSIS

sile [-b|--backend] [-c|--class] [-d|--debug] [-e|--evaluate] [-E|--evaluate-after] [-f|--fontmanager] [--luarocks-tree] [-m|--makedeps] [-o|--output] [-O|--option] [-p|--preamble] [-P|--postamble] [-u|--use] [-q|--quiet] [-t|--traceback] [-h|--help] [ENTRADA]

DESCRIPCIÓN

El componedor SILE lee archivo(s) de entrada y compone el contenido en un formato de documento renderizado, típicamente PDF.

Por defecto, los archivos de entrada pueden estar en marcado SIL declarativo, XML estructurado, o Lua programático. El formato de entrada se detecta automáticamente por los módulos activos. Por defecto, la salida será un archivo con el mismo nombre que el primer archivo de entrada, con la extensión cambiada a .pdf. El nombre del archivo de salida puede ser sobrescrito con el argumento `--output`. Usando `--backend` se puede cambiar a un formato de salida diferente (o un controlador diferente para el mismo formato). Formatos de entrada o salida adicionales pueden ser manejados cargando un módulo de terceros que los soporte añadiendo el argumento `--use` en la línea de comandos (lo cual se cargará antes de intentar leer los documentos de entrada).

OPCIONES

-b, --backend=BACKEND
Especificar el backend de salida.

El valor por defecto es `libtexpdf` y es adecuado para la mayoría de la salida PDF. Alternativas soportadas de fábrica incluyen `text`, `debug`, `dummy`, `cairo`, y `podofo`. Otros formateadores de salida pueden ser habilitados mediante `--use`.

-c, --class=CLASE
Sobrescribir la clase de documento por defecto o especificada.

La clase por defecto para documentos que no especifican una en la etiqueta raíz es `plain`. Esto se puede usar para cambiar la clase por defecto o para sobrescribir la clase realmente especificada en un documento. Otras clases incluidas son `base`, `bible`, `book`, `diglot`, `docbook`, `docbook`, `jbook`, `jplain`, `letter`, `pecha`, `tbook`, `tplain`, y `triglot`. Otras se cargarán dinámicamente desde la ruta del módulo.

-d, --debug=FLAGDEBUG[,FLAGDEBUG]
Mostrar información de depuración para aspectos etiquetados de la operación de SILE.

Se pueden dar múltiples flags de depuración como una lista separada por comas. Mientras que los paquetes pueden definir sus propios flags de depuración, los más usados comúnmente son `typesetter`, `pagebuilder`, `vboxes`, `break`, `frames`, `profile`, y `versions`. Se puede especificar más de una vez.

-e, --evaluate=EXPRESION
Evaluar la expresión Lua antes de procesar la entrada.

Se puede especificar más de una vez.

-E, --evaluate-after=EXPRESION
Evaluar la expresión Lua después de procesar la entrada.

Se puede especificar más de una vez.

-f, --fontmanager=GESTORFUENTES
Especificar qué gestor de fuentes usar.

El gestor de fuentes es responsable de descubrir las ubicaciones de los archivos de fuentes en el sistema dado un nombre de fuente. El gestor de fuentes por defecto es `fontconfig` en sistemas que no son macOS y `macfonts` en macOS.

--luarocks-tree=ARBOL_LUAROCKS
Añadir una ruta a la lista de árboles de LuaRocks buscados para módulos.

Al instalar módulos SILE de terceros a través de LuaRocks existen varias ubicaciones de instalación posibles. Pueden ser instalados en el sistema anfitrión, en el directorio de inicio del usuario, en una ruta local del proyecto, o en cualquier ubicación arbitraria. En el caso del sistema o una ruta local del proyecto llamada exactamente `lua_modules` se encontrarán automáticamente. En el caso de cualquier otra ruta, SILE necesita ser informado dónde encontrarlos. Esto se puede hacer exportando una variable de entorno LUA_PATH antes de ejecutar SILE, o usando esta opción.

-m, --makedeps=ARCHIVO
Generar una lista de dependencias en formato Makefile y escribirlas a un archivo.

Esto rastrea todos los archivos (archivos de entrada, bibliotecas Lua, fuentes, imágenes, etc.) utilizados durante el proceso de composición. Después de la finalización, la lista se escribe en ARCHIVO en el formato de una lista de dependencias para un objetivo en un Makefile. Esto se puede usar más tarde para determinar si un PDF necesita ser renderizado de nuevo en función de si alguna entrada ha cambiado.

-o, --output=ARCHIVO
Establecer explícitamente el nombre del archivo de salida.

Por defecto, el nombre base del primer archivo de entrada se usará como el nombre del archivo de salida. Se elegirá una extensión basada en el backend de salida, típicamente .pdf. Con esta opción se puede dar cualquier nombre y ruta arbitraria. Adicionalmente `-` puede ser usado para escribir la salida a STDOUT.

-O, --option=OPCION
Establecer o sobrescribir opciones de la clase de documento.

Se puede usar para cambiar las opciones por defecto o sobrescribir las especificadas en un documento. Por ejemplo, establecer `--option papersize=letter` sobrescribiría tanto el tamaño de papel por defecto A4 como cualquier otro específico establecido en las opciones del documento. Se puede especificar más de una vez.

-p, --preamble=ARCHIVO
Incluir el contenido de un archivo SIL, XML u otro recurso antes del contenido del documento de entrada.

El valor debe ser un nombre de archivo completo con una ruta relativa a PWD o una ruta absoluta. Se puede especificar más de una vez.

-P, --postamble=ARCHIVO
Incluir el contenido de un archivo SIL, XML u otro recurso después del contenido del documento de entrada.

El valor debe ser un nombre de archivo completo con una ruta relativa a PWD o una ruta absoluta. Se puede especificar más de una vez.

-u, --use=MODULO[[PARAMETRO=VALOR[,PARAMETRO=VALOR]]]
Cargar e inicializar una clase, un importador, un modelador de fuentes u otro módulo antes de procesar la entrada principal.

El valor debe ser un nombre de módulo cargable (sin extensión, usando `.` como separador de ruta) y se cargará usando la ruta de búsqueda de módulos de SILE. Se pueden pasar opciones al módulo encerrando pares `clave=valor` en corchetes después del nombre del módulo. Esto es particularmente útil cuando el documento de entrada no es SIL o un esquema XML reconocido nativamente y SILE necesita ser enseñado trucos nuevos antes incluso de intentar leer el archivo de entrada. Si el módulo es una clase de documento, reemplazará `plain` como la clase por defecto para procesar documentos que no identifican específicamente una para usar. Dado que esto se ejecuta antes de cargar el documento, incluso puede añadir un analizador de entrada o modificar uno existente para soportar nuevos formatos de archivo. Los módulos de paquete se añadirán al preámbulo para ser cargados después de que la clase sea inicializada. Se puede especificar más de una vez.

-q, --quiet
Suprimir advertencias y mensajes informativos durante el procesamiento
-t, --traceback
Mostrar un rastro detallado de la ubicación en errores y advertencias
-h, --help
Imprimir ayuda (ver un resumen con '-h')
[ENTRADA]
Nombre(s) del archivo(s) del documento de entrada, por defecto en formatos SIL, XML o Lua.

Uno o más archivos de entrada de los cuales procesar contenido. El primer archivo listado se considera el documento maestro, otros se procesan en secuencia. Otros formatos de importadores pueden ser habilitados vía `--use`. Usar `-` para leer un flujo de contenido desde STDIN.

SILE

NAME

sile - A typesetting system with an imperative approach

SYNOPSIS

sile [options] [filename]

DESCRIPTION

Sile is a typesetting system that allows you to create documents using an imperative programming language. It aims to provide a more flexible and powerful alternative to traditional typesetting systems like TeX.

With Sile, you can define document structures, layouts, and typographic elements using a scripting language. This allows for dynamic content generation, complex formatting, and easy integration with other programming tools.

OPTIONS

sile accepts the following options:

-h, --help
Show help message and exit.
-v, --version
Show program's version number and exit.
-o, --output FILENAME
Specify the output file name. If not provided, the output will be sent to standard output.
-p, --preview
Enable preview mode, showing intermediate steps of the typesetting process.
--pdf
Output in PDF format. This is the default format.
--html
Output in HTML format.
