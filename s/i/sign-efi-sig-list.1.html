SIGN-EFI-SIG-LIST(1) Comandos de usuario SIGN-EFI-SIG-LIST(1)

NOMBRE

sign-efi-sig-list - herramienta de firma para variables seguras como Listas de Firmas EFI

SINOPSIS

sign-efi-sig-list [-r] [-m] [-a] [-g <guid>] [-o] [-t <timestamp>] [-i <archivo_entrada>] [-c <archivo_crt>] [-k <archivo_clave>] [-e <motor>] <variable> <archivo lista_sig_efi> <archivo_salida>

DESCRIPCIÓN

Produce un archivo de salida con una cabecera de autenticación para actualización directa a una variable segura. Esta salida puede ser firmada por las claves habituales directamente o puede ser dividida para firma externa usando las opciones -o y -i.

OPCIONES

-r
el certificado es rsa2048 en lugar de x509 [NO IMPLEMENTADO]
-m
Usar un contador monotónico en lugar de una marca de tiempo [NO IMPLEMENTADO]
-a
Prepara la variable para APPEND_WRITE en lugar de reemplazo
-o
No firmar, sino generar un archivo del paquete exacto a firmar
-t <timestamp>
Usa <timestamp> como la marca de tiempo de la actualización de variable con marca de tiempo. Si no está presente, la marca de tiempo se tomará del tiempo del sistema. Nota: debes usar esta opción al hacer firma separada, de lo contrario la firma será incorrecta debido a discrepancias en la marca de tiempo.
-i <archivo_entrada>
Toma una firma separada (en formato PEM) del paquete producido por -o y completa la creación de la actualización
-g <guid>
Usa <guid> como el GUID propietario de la firma
-c <crt>
<crt> es el archivo que contiene el certificado de firma en formato PEM
-k <clave>
<clave> es el archivo que contiene la clave para <crt> en formato PEM
-e <motor>
Usa el motor openssl <motor> para la clave privada

EJEMPLOS

Para firmar una simple actualización de adjuntar a db que ha sido preparada como una Lista de Firmas EFI en DB.esl y producir el resultado con la cabecera de autenticación en DB.auth

sign-efi-sig-list -a -c KEK.crt -k KEK.key db DB.esl DB.auth

Para hacer una firma separada de la misma manera

sign-efi-sig-list -a -t 'Jul 21 09:39:37 BST 2012' -o db DB.esl DB.forsig

Ahora firma el archivo DB.forsig de la manera estándar de openssl. Nota que los estándares requieren sha256 como el algoritmo de firma

openssl smime -sign -binary -in DB.forsig -out DB.signed -signer KEK.crt -inkey KEK.key -outform DER -md sha256

Lo que produce una firma separada PKCS7 en DB.signed. Ahora alimenta esto de vuelta al programa, recordando mantener la misma marca de tiempo (y el flag -a):

sign-efi-sig-list -a -i DB.signed -t 'Jul 21 09:39:37 BST 2012' db DB.auth

Para eliminar una clave, simplemente firma un archivo de lista de firmas EFI vacío, así para producir una actualización de variable que eliminará la PK:

> null.esl

Y luego fírnala de la manera estándar (no debe ser una actualización de escritura de adjuntar):

sign-efi-sig-list -c PK.crt -k PK.key PK null.esl PK.auth

Una vez que tengas el archivo .auth transmitido a la plataforma UEFI, puedes usar el programa UpdateVars.efi para aplicarlo

UpdateVars [-a] db DB.auth

Donde el flag -a debe estar presente si el archivo DB.auth fue creado como una actualización de escritura de adjuntar y ausente si está reemplazando la variable.

VER TAMBIÉN

cert-to-efi-sig-list(1) para detalles sobre cómo producir listas de firmas EFI.
