sigaltstack(2) Manual de llamadas al sistema sigaltstack(2)

NOMBRE

sigaltstack - establecer y/o obtener el contexto de la pila de señales

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <signal.h>
int sigaltstack(const stack_t *_Nullable restrict ss,
                stack_t *_Nullable restrict old_ss);
Requisitos de Macro de Prueba de Funciones para glibc (ver feature_test_macros(7)):

sigaltstack():

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.12: */ _POSIX_C_SOURCE >= 200809L
        || /* glibc <= 2.19: */ _BSD_SOURCE

DESCRIPCIÓN

sigaltstack() permite a un hilo definir una nueva pila de señales alternativa y/o recuperar el estado de una pila de señales alternativa existente. Una pila de señales alternativa se utiliza durante la ejecución de un manejador de señales si el establecimiento de dicho manejador (ver sigaction(2)) lo solicitó.

La secuencia normal de eventos para usar una pila de señales alternativa es la siguiente:

1.
Asignar un área de memoria para ser utilizada como pila de señales alternativa.
2.
Usar sigaltstack() para informar al sistema de la existencia y ubicación de la pila de señales alternativa.
3.
Al establecer un manejador de señales usando sigaction(2), informar al sistema de que el manejador de señales debe ejecutarse en la pila de señales alternativa especificando la bandera SA_ONSTACK.

El argumento ss se utiliza para especificar una nueva pila de señales alternativa, mientras que el argumento old_ss se utiliza para recuperar información sobre la pila de señales actualmente establecida. Si solo estamos interesados en realizar una de estas tareas, el otro argumento puede especificarse como NULL.

El tipo stack_t utilizado para escribir los argumentos de esta función se define de la siguiente manera:


typedef struct {
    void  *ss_sp;     /* Dirección base de la pila */
    int    ss_flags;  /* Banderas */
    size_t ss_size;   /* Número de bytes en la pila */
} stack_t;

Para establecer una nueva pila de señales alternativa, los campos de esta estructura se configuran de la siguiente manera:

ss.ss_flags
Este campo contiene 0 o la siguiente bandera:
SS_AUTODISARM (desde Linux 4.7)
Borra la configuración de la pila de señales alternativa al entrar al manejador de señales. Cuando el manejador de señales retorna, se restaura la configuración anterior de la pila de señales alternativa.
Esta bandera se añadió para hacer seguro el cambio desde el manejador de señales con swapcontext(3). Sin esta bandera, una señal manejada posteriormente corromperá el estado del manejador de señales cambiado. En núcleos donde esta bandera no es soportada, sigaltstack() falla con el error EINVAL cuando se proporciona esta bandera.
ss.ss_sp
Este campo especifica la dirección de inicio de la pila. Cuando se invoca un manejador de señales en la pila alternativa, el núcleo alinea automáticamente la dirección dada en ss.ss_sp a un límite de dirección adecuado para la arquitectura de hardware subyacente.
ss.ss_size
Este campo especifica el tamaño de la pila. La constante SIGSTKSZ se define para que sea lo suficientemente grande como para cubrir los requisitos de tamaño habituales de una pila de señales alternativa, y la constante MINSIGSTKSZ define el tamaño mínimo requerido para ejecutar un manejador de señales.

Para deshabilitar una pila existente, especifique ss.ss_flags como SS_DISABLE. En este caso, el núcleo ignora cualquier otra bandera en ss.ss_flags y los campos restantes en ss.

Si old_ss no es NULL, se utiliza para devolver información sobre la pila de señales alternativa que estaba en vigor antes de la llamada a sigaltstack(). Los campos old_ss.ss_sp y old_ss.ss_size devuelven la dirección de inicio y el tamaño de dicha pila. El campo old_ss.ss_flags puede devolver uno de los siguientes valores:

SS_ONSTACK
El hilo se está ejecutando actualmente en la pila de señales alternativa. (Tenga en cuenta que no es posible cambiar la pila de señales alternativa si el hilo ya se está ejecutando en ella).
SS_DISABLE
La pila de señales alternativa está actualmente deshabilitada.
Alternativamente, este valor se devuelve si el hilo se está ejecutando actualmente en una pila de señales alternativa que se estableció usando la bandera SS_AUTODISARM. En este caso, es seguro cambiar desde el manejador de señales con swapcontext(3). También es posible configurar una pila de señales alternativa diferente mediante una llamada adicional a sigaltstack().
SS_AUTODISARM
La pila de señales alternativa se ha marcado para ser autodesactivada como se describe anteriormente.

Al especificar ss como NULL, y old_ss como un valor no NULL, se pueden obtener la configuración actual de la pila de señales alternativa sin cambiarla.

VALOR DE RETORNO

sigaltstack() devuelve 0 si tiene éxito, o -1 en caso de error con errno establecido para indicar el error.

ERRORES

EFAULT
Ya sea ss u old_ss no son NULL y apuntan a un área fuera del espacio de direcciones del proceso.
EINVAL
ss no es NULL y el campo ss_flags contiene una bandera inválida.
ENOMEM
El tamaño especificado de la nueva pila de señales alternativa ss.ss_size era menor que MINSIGSTKSZ.
EPERM
Se intentó cambiar la pila de señales alternativa mientras estaba activa (es decir, el hilo ya se estaba ejecutando en la pila de señales alternativa actual).

NOTAS

El uso más común de una pila de señales alternativa es para manejar la señal SIGSEGV que se genera si el espacio disponible para la pila estándar se agota: en este caso, un manejador de señales para SIGSEGV no puede ser invocado en la pila estándar; si deseamos capturarlo, debemos usar una pila de señales alternativa.

Establecer una pila de señales alternativa es útil si un hilo espera agotar su pila estándar. Esto puede ocurrir, por ejemplo, porque la pila crece tanto que encuentra el heap que crece hacia arriba, o alcanza un límite establecido por una llamada a setrlimit(RLIMIT_STACK, &rlim). Si se agota la pila estándar, el núcleo envía al hilo una señal SIGSEGV. En estas circunstancias, la única forma de capturar esta señal es en una pila de señales alternativa.

sigaltstack(2) — Arch Linux

NOTES

Functions called from a signal handler executing on an alternate signal stack will also use the alternate signal stack. (This also applies to any handlers invoked for other signals while the thread is executing on the alternate signal stack.) Unlike the standard stack, the system does not automatically extend the alternate signal stack. Exceeding the allocated size of the alternate signal stack will lead to unpredictable results.

A successful call to execve(2) removes any existing alternate signal stack. A child process created via fork(2) inherits a copy of its parent's alternate signal stack settings. The same is also true for a child process created using clone(2), unless the clone flags include CLONE_VM and do not include CLONE_VFORK, in which case any alternate signal stack that was established in the parent is disabled in the child process.

sigaltstack() supersedes the older sigstack() call. For backward compatibility, glibc also provides sigstack(). All new applications should be written using sigaltstack().

History

4.2BSD had a sigstack() system call. It used a slightly different struct, and had the major disadvantage that the caller had to know the direction of stack growth.

BUGS

In Linux 2.2 and earlier, the only flag that could be specified in ss.sa_flags was SS_DISABLE. In the lead up to the release of the Linux 2.4 kernel, a change was made to allow sigaltstack() to allow ss.ss_flags==SS_ONSTACK with the same meaning as ss.ss_flags==0 (i.e., the inclusion of SS_ONSTACK in ss.ss_flags is a no-op). On other implementations, and according to POSIX.1, SS_ONSTACK appears only as a reported flag in old_ss.ss_flags. On Linux, there is no need ever to specify SS_ONSTACK in ss.ss_flags, and indeed doing so should be avoided on portability grounds: various other systems give an error if SS_ONSTACK is specified in ss.ss_flags.

EXAMPLES

The following code segment demonstrates the use of sigaltstack() (and sigaction(2)) to install an alternate signal stack that is employed by a handler for the SIGSEGV signal:


stack_t ss;
ss.ss_sp = malloc(SIGSTKSZ);
if (ss.ss_sp == NULL) {
    perror("malloc");
    exit(EXIT_FAILURE);
}
ss.ss_size = SIGSTKSZ;
ss.ss_flags = 0;
if (sigaltstack(&ss, NULL) == -1) {
    perror("sigaltstack");
    exit(EXIT_FAILURE);
}
sa.sa_flags = SA_ONSTACK;
sa.sa_handler = handler();      /* Address of a signal handler */
sigemptyset(&sa.sa_mask);
if (sigaction(SIGSEGV, &sa, NULL) == -1) {
    perror("sigaction");
    exit(EXIT_FAILURE);
}
