SORT(1P) Manual de Programador de POSIX SORT(1P)

PROLOG

Esta página del manual es parte del Manual de Programador de POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

sort — ordenar, fusionar o verificar secuencias de archivos de texto

SINOPSIS

sort [-m] [-o salida] [-bdfinru] [-t car] [-k clave_def]... [archivo...]
sort [-c|-C] [-bdfinru] [-t car] [-k clave_def] [archivo]

DESCRIPCIÓN

El comando sort realizará una de las siguientes funciones:

1.
Ordenar las líneas de todos los archivos nombrados juntos y escribir el resultado en la salida especificada.
2.
Fusionar las líneas de todos los archivos nombrados (ya ordenados) juntos y escribir el resultado en la salida especificada.
3.
Verificar que un único archivo de entrada esté correctamente preordenado.

Las comparaciones se basarán en una o más claves de ordenación extraídas de cada línea de entrada (o, si no se especifican claves de ordenación, la línea completa hasta, pero sin incluir, el carácter de nueva línea de terminación), y se realizarán utilizando la secuencia de ordenación de la configuración regional actual. Si esta secuencia de ordenación no tiene un orden total de todos los caracteres (consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 7.3.2, LC_COLLATE), las líneas de entrada que ordenen de forma igual deberán compararse adicionalmente byte a byte utilizando la secuencia de ordenación para la configuración regional POSIX.

OPCIONES

El comando sort se ajustará a las Directrices de Sintaxis de Utilidad del volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, excepto la Directriz 9, y la opción -k clave_def deberá seguir a las opciones -b, -d, -f, -i, -n y -r. Además, '+' puede reconocerse como un delimitador de opción además de '-'.

Se admitirán las siguientes opciones:

-c
Verificar que el único archivo de entrada esté ordenado según lo especificado por los argumentos y la secuencia de ordenación de la configuración regional actual. La salida no se enviará a la salida estándar. El código de salida indicará si se detectó desorden o si ocurrió un error. Si se detecta desorden (o, con -u, una clave duplicada), se enviará un mensaje de advertencia a la salida de error estándar indicando dónde se encontró el desorden o la clave duplicada.
-C
Igual que -c, excepto que no se enviará un mensaje de advertencia a la salida de error estándar si se detecta desorden o, con -u, una clave duplicada.
-m
Solo fusionar; se asumirá que el archivo de entrada ya está ordenado.
-o salida
Especificar el nombre de un archivo de salida que se utilizará en lugar de la salida estándar. Este archivo puede ser el mismo que uno de los archivos de entrada.
-u
Único: suprimir todas las líneas excepto una en cada conjunto de líneas con claves iguales. Si se usa con la opción -c, verificar que no haya líneas con claves duplicadas, además de verificar que el archivo de entrada esté ordenado.

Las siguientes opciones anularán las reglas de ordenación predeterminadas. Cuando las opciones de ordenación aparecen independientemente de cualquier especificación de campo clave, las reglas de ordenación solicitadas se aplicarán globalmente a todas las claves de ordenación. Cuando se adjuntan a una clave específica (consulte -k), las opciones de ordenación especificadas anularán todas las opciones de ordenación globales para esa clave.

-d
Especificar que solo los caracteres de <espacio> y los caracteres alfanuméricos, según la configuración actual de LC_CTYPE, serán significativos en las comparaciones. El comportamiento no está definido para una clave de ordenación a la que también se aplican -i o -n.
-f
Considerar todos los caracteres en minúsculas que tengan equivalentes en mayúsculas, según la configuración actual de LC_CTYPE, como el equivalente en mayúsculas a efectos de comparación.
-i
Ignorar todos los caracteres que no sean imprimibles, según la configuración actual de LC_CTYPE. El comportamiento no está definido para una clave de ordenación para la que también se aplica -n.
-n
Restringir la clave de ordenación a una cadena numérica inicial, que consta de <espacio> opcionales, un carácter de <guión-menos> opcional y cero o más dígitos con un carácter de radix y separadores de miles opcionales (según se definen en la configuración regional actual), que se ordenarán por valor aritmético. Una cadena de dígitos vacía se tratará como cero. Los ceros iniciales y los signos en los ceros no afectarán la ordenación.
-r
Invertir el sentido de las comparaciones.

El tratamiento de los separadores de campo se puede alterar utilizando las opciones:

-b
Ignorar los caracteres de <espacio> iniciales al determinar las posiciones de inicio y fin de una clave de ordenación restringida. Si la opción -b se especifica antes de la primera opción -k, se aplicará a todas las opciones -k. De lo contrario, la opción -b se puede adjuntar independientemente a cada argumento de opción campo_inicio o campo_fin de -k (consulte a continuación).
-t car
Usar car como el carácter separador de campo; car no se considerará parte de un campo (aunque puede incluirse en una clave de ordenación). Cada ocurrencia de car será significativa (por ejemplo, <car><car> delimita un campo vacío). Si no se especifica -t, se utilizarán los caracteres de <espacio> como separadores de campo predeterminados; cada secuencia máxima no vacía de caracteres de <espacio> que sigue a un no <espacio> será un separador de campo.

Las claves de ordenación se pueden especificar utilizando las opciones:

-k clave_def
El argumento clave_def es una definición restringida de campo de clave de ordenación. El formato de esta definición es:
inicio_campo[tipo][,fin_campo[tipo]]

donde inicio_campo y fin_campo definen un campo clave restringido a una porción de la línea (consulte la sección DESCRIPCIÓN EXTENDIDA), y tipo es uno o más modificadores de la lista de caracteres 'b', 'd', 'f', 'i', 'n', 'r'. El modificador 'b' se comportará como la opción -b, pero solo se aplicará a inicio_campo o fin_campo al que se adjunte. Los otros modificadores se comportarán como las opciones correspondientes, pero solo se aplicarán al campo clave al que se adjuntan; tendrán este efecto si se especifican con inicio_campo, fin_campo, o ambos. Si se adjunta algún modificador a un inicio_campo o a un fin_campo, ninguna opción se aplicará a ninguno de ellos. Las implementaciones deberán admitir al menos nueve ocurrencias de la opción -k, que serán significativas en el orden de la línea de comandos. Si no se especifica ninguna opción -k, se utilizará una clave de ordenación predeterminada de toda la línea.

Cuando hay varios campos clave, las claves posteriores solo se compararán después de que todas las claves anteriores comparen igual. Excepto cuando se especifica la opción -u, las líneas que de lo contrario comparan igual se ordenarán como si ninguna de las opciones -d, -f, -i, -n o -k estuviera presente (pero con -r aún en vigor, si se especificó) y con todos los bytes de las líneas significativos para la comparación. El orden en que se escriben las líneas que todavía comparan igual no está especificado.

Sección: descripciones Sección: archivo_entrada El estándar de entrada se utilizará solo si no se especifican operandos de archivo, o si un operando de archivo es el carácter '-', vea la sección ARCHIVO DE ENTRADA . Sección: archivos_entrada Los archivos de entrada serán archivos de texto, excepto que la utilidad `sort` agregará una nueva línea al final de un archivo que termine con una última línea incompleta. Sección: variables_entorno Las siguientes variables de entorno afectarán la ejecución de `sort`: LANG: Proporciona un valor predeterminado para las variables de internacionalización que no están definidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1-2017, Sección 8.2, Variables de internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localidad). LC_ALL: Si se establece en una cadena de valor no vacía, anula los valores de todas las demás variables de internacionalización. LC_COLLATE: Determina la localidad para las reglas de ordenación. LC_CTYPE: Determina la localidad para la interpretación de secuencias de bytes de datos de texto (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en argumentos y archivos de entrada) y el comportamiento de la clasificación de caracteres para las opciones `-b`, `-d`, `-f`, `-i` y `-n`. LC_MESSAGES: Determina la localidad que debe usarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos a la salida estándar de error. LC_NUMERIC: Determina la localidad para la definición del carácter decimal y el separador de miles para la opción `-n`. NLSPATH: Determina la ubicación de los catálogos de mensajes para el procesamiento de `LC_MESSAGES`. Sección: eventos_asincronos Predeterminado. Sección: salida_estandar A menos que las opciones `-o` o `-c` estén en vigor, la salida estándar contendrá la entrada ordenada. Sección: error_estandar La salida estándar de error se utilizará para mensajes de diagnóstico. Cuando se especifica `-c`, si se detecta desorden (o si también se especifica `-u` y se detecta una clave duplicada), se escribirá un mensaje en la salida estándar de error que identifica la línea de entrada en la que se detectó el desorden (o una clave duplicada). Se puede generar un mensaje de advertencia sobre la corrección de una última línea incompleta de un archivo de entrada, pero no es necesario que afecte el estado de salida final. Sección: archivos_salida Si la opción `-o` está en vigor, la entrada ordenada se escribirá en el archivo `output`. Sección: descripciones_extendidas La notación: -k inicio_campo[tipo][,fin_campo[tipo]] definirá un campo clave que comienza en `inicio_campo` y termina en `fin_campo` inclusive, a menos que `inicio_campo` caiga más allá del final de la línea o después de `fin_campo`, en cuyo caso el campo clave estará vacío. Un `fin_campo` faltante significará el último carácter de la línea. Un campo comprende una secuencia máxima de caracteres no separadores y, en ausencia de la opción `-t`, cualquier separador de campo anterior. La parte `inicio_campo` del argumento de opción `keydef` tendrá la forma: número_campo[.primer_carácter] Los campos y caracteres dentro de los campos se numerarán a partir de 1. Las piezas `número_campo` y `primer_carácter`, interpretadas como enteros decimales positivos, especificarán el primer carácter que se utilizará como parte de una clave de ordenación. Si se omite `.primer_carácter`, se referirá al primer carácter del campo. La parte `fin_campo` del argumento de opción `keydef` tendrá la forma: número_campo[.último_carácter] El `número_campo` será como se describió anteriormente para `inicio_campo`. El `último_carácter`, interpretado como un entero decimal no negativo, especificará el último carácter que se utilizará como parte de la clave de ordenación. Si `último_carácter` se evalúa a cero o se omite `.último_carácter`, se referirá al último carácter del campo especificado por `número_campo`. Si la opción `-b` o el modificador de tipo `b` está en vigor, los caracteres dentro de un campo se contarán desde el primer no espacio en blanco del campo. (Esto se aplicará por separado a `primer_carácter` y `último_carácter`). Sección: estado_salida Se devolverán los siguientes valores de salida: 0: Todos los archivos de entrada se produjeron correctamente, o se especificó `-c` y el archivo de entrada estaba ordenado correctamente. 1: Bajo la opción `-c`, el archivo no estaba ordenado como se especificó, o si las opciones `-c` y `-u` se especificaron ambas, se encontraron dos líneas de entrada con claves iguales. >1: Ocurrió un error. Sección: consecuencias_de_errores Se aplicarán los requisitos predeterminados, excepto que si `sort` encuentra un error al abrir o leer un operando de archivo, puede salir sin escribir ninguna salida a la salida estándar ni procesar operandos posteriores. El siguiente comando ordena, en orden inverso, el contenido de infile1 y infile2, colocando la salida en outfile y utilizando el segundo carácter del segundo campo como clave de ordenación (suponiendo que el primer carácter del segundo campo es el separador de campos):

3.
El siguiente comando ordena el contenido de infile1 y infile2 utilizando el segundo carácter que no es un espacio en blanco del segundo campo como clave de ordenación:
sort -k 2.2b,2.2b infile1 infile2
4.
El siguiente comando imprime el archivo de contraseñas del sistema V (base de datos de usuarios) ordenado por el ID numérico de usuario (el tercer campo separado por dos puntos):
sort -t : -k 3,3n /etc/passwd
5.
El siguiente comando imprime las líneas del archivo ya ordenado infile, suprimiendo todas menos una ocurrencia de líneas que tengan el mismo tercer campo:
sort -um -k 3.1,3.0 infile

FUNDAMENTO

Los ejemplos en algunas documentaciones históricas indican que las opciones -um con un archivo de entrada conservan el primero de cada conjunto de líneas con claves iguales. Este comportamiento se consideró un artefacto de implementación y no se estandarizó.

La opción -z se omitió; no es una práctica estándar en la mayoría de los sistemas y es inconsistente con el uso de sort para ordenar varios archivos individualmente y luego fusionarlos. El texto relativo a -z en la documentación histórica parecía requerir que las implementaciones determinaran la longitud de búfer adecuada durante la fase de ordenación de la operación, pero no durante la fusión.

La opción -y se omitió debido a su falta de portabilidad. La opción -M, presente en System V, se omitió debido a su falta de portabilidad en el uso internacional.

Existe una opción -T no documentada en algunas implementaciones. Se utiliza para especificar un directorio para archivos intermedios. Se anima a las implementaciones a que admitan el uso de la variable de entorno TMPDIR en lugar de añadir una opción para soportar esta funcionalidad.

La opción -k se añadió para satisfacer dos objeciones. En primer lugar, el conteo basado en cero utilizado por sort no es consistente con otras convenciones de utilidades. En segundo lugar, no cumplía los requisitos de las directrices de sintaxis.

La documentación histórica indica que "establecer -n implica -b". La descripción de -n ya indica que los espacios en blanco iniciales opcionales se toleran al realizar la comparación. Si -b se habilita, en lugar de implicarse, por -n, esto tiene efectos secundarios inusuales. Cuando se utiliza un desplazamiento de carácter en una columna de números (por ejemplo, para ordenar por módulo 100), ese desplazamiento se mide en relación con el dígito más significativo, no con la columna. Basándose en una recomendación del autor de la utilidad sort original, la implicación de -b se ha omitido de este volumen de POSIX.1-2017, y una aplicación que desee lograr los efectos secundarios mencionados anteriormente debe codificar explícitamente la opción -b.

Las versiones anteriores de este estándar permitían que la opción -o apareciera después de los operandos. La práctica histórica permitía que todas las opciones se intercalaran con los operandos. Esta versión del estándar permite a las implementaciones aceptar opciones después de los operandos, pero las aplicaciones que cumplan no deben usar esta forma.

Las versiones anteriores de este estándar también permitían las opciones -número y +número. Estas opciones ya no se especifican en POSIX.1-2008, pero pueden estar presentes en algunas implementaciones.

Las implementaciones históricas producían un mensaje en la salida estándar cuando se especificaba -c y se detectaba desorden, y cuando se especificaban -c y -u y se detectaba una clave duplicada. Una versión anterior de este estándar contenía una redacción que no dejaba claro que este mensaje estuviera permitido, y algunas implementaciones eliminaron este mensaje para asegurarse de que cumplían los requisitos del estándar. Ante esta diferencia de comportamiento, los usuarios interactivos que querían asegurarse de obtener retroalimentación visual en lugar de solo el código de salida 1 podían usar un comando como:

sort -c file || echo disorder

independientemente de si la utilidad sort proporcionaba un mensaje en este caso. Pero, no era fácil para un usuario encontrar dónde ocurría el desorden o la clave duplicada en implementaciones que no producían un mensaje, especialmente cuando algunas partes de la línea de entrada no formaban parte de la clave y cuando una o más de las opciones -b, -d, -f, -i, -n o -r o los modificadores de tipo keydef estaban en uso. POSIX.1-2008 requiere que se produzca un mensaje en este caso. POSIX.1-2008 también contiene la opción -C que ofrece a los usuarios la posibilidad de elegir cualquiera de los comportamientos.

Cuando se encuentra un desorden o un duplicado al especificar la opción -c, algunas implementaciones imprimen un mensaje que contiene la primera línea que está desordenada o contiene una clave duplicada; otras imprimen un mensaje que especifica el número de línea de la línea infractora. Este estándar permite ambos tipos de mensajes.

Se anima a las implementaciones a realizar la comparación recomendada byte a byte de líneas que se ordenan por igual, aunque esto pueda afectar a la eficiencia. El impacto en la eficiencia se puede mitigar realizando la comparación adicional solo si la secuencia de ordenación de la configuración regional actual no tiene un orden total de todos los caracteres (si la implementación proporciona una forma de consultarlo) o realizando la comparación adicional solo si el nombre de la configuración regional asociado con la categoría LC_COLLATE tiene un modificador '@' en el nombre (ya que las configuraciones regionales sin un modificador '@' deberían tener un orden total de todos los caracteres; véase el volumen de Definiciones Base de POSIX.1-2017, Sección 7.3.2, LC_COLLATE). Tenga en cuenta que si la implementación proporciona una opción de ordenación estable como extensión (generalmente -s), la comparación adicional no debe realizarse cuando se ha especificado esta opción.

DIRECCIONES FUTURAS

Una versión futura de este estándar puede requerir que si la secuencia de ordenación de la configuración regional actual no tiene un orden total de todos los caracteres, cualquier línea de entrada que se ordene por igual al compararlas como líneas completas se comparará posteriormente byte a byte utilizando la secuencia de ordenación para la configuración regional POSIX.
