SOCKDEBUG(8) Manual de NUT SOCKDEBUG(8)

NOMBRE

sockdebug - Utilidad simple de ayuda para desarrolladores/solución de problemas para comunicarse con un controlador de NUT usando el protocolo de socket

SINOPSIS

sockdebug nombre_socket

Por ejemplo (compilaciones WIN32 y POSIX):

:; sockdebug.exe dummy-ups-UPS1

Por ejemplo (sistemas compatibles con POSIX que utilizan una ruta de estado alternativa):

:; sockdebug /var/state/ups/dummy-ups-UPS1

DESCRIPCIÓN

sockdebug es una herramienta creada cuando NUT se configura con --with-dev habilitado. Alternativamente, puede ser creada llamando a make sockdebug en la raíz del espacio de trabajo de compilación. Los archivos fuente reales utilizados dependen de la plataforma.

Se utiliza para conectarse a un controlador de NUT usando el protocolo de socket en un socket Unix o en una tubería de Windows, de manera similar a cómo el servidor de datos upsd(8) habla con los controladores que se ejecutan localmente para representarlos en la red usando además el protocolo común de NUT del proyecto Network UPS Tools, o cómo los programas de controlador pueden comunicarse con sus instancias ya en ejecución para implementar comandos como recarga en vivo o errores.

Esta herramienta permite a un desarrollador o solucionador de problemas observar las actualizaciones de difusión emitidas por el controlador, así como emitir comandos unicast y recibir respuestas (durante una sesión de investigación interactiva, puede que desee comandar NOBROADCAST primero).

Para más detalles, consulte el archivo docs/sock-protocol.txt en las fuentes de NUT.

OPCIONES

sockdebug acepta (y requiere) la siguiente opción:

nombre_socket

Ya sea una ruta completa (en compilaciones POSIX) o el nombre base del socket/tubería del dispositivo (en todas las plataformas), compuesto por una tupla de nombre_controlador-nombre_dispositivo, por ejemplo, dummy-ups-UPS1 para una instancia de controlador dummy-ups que maneja una configuración de dispositivo UPS1 (que a su vez puede originarse en el archivo ups.conf o construirse dinámicamente para pruebas llamando al programa controlador con una opción CLI -s TMP).

En sistemas POSIX, si este argumento solo representa un nombre base y no una ruta completa al archivo de socket Unix, la herramienta primero debe buscar el archivo en el directorio actual y luego recurrir a la ruta de estado configurada (incorporada) o al valor de la variable de entorno NUT_STATEPATH, si está configurada; por ejemplo:

:; NUT_STATEPATH=/tmp ./server/sockdebug dummy-ups-UPS1
