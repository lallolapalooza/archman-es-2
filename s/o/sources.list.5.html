SOURCES.LIST(5) APT SOURCES.LIST(5)

NOMBRE

sources.list - Lista de fuentes de datos APT configuradas

DESCRIPCIÓN

La lista de fuentes /etc/apt/sources.list y los archivos contenidos en /etc/apt/sources.list.d/ están diseñados para soportar cualquier número de fuentes activas y una variedad de medios de origen. Los archivos listan una fuente por línea (estilo de una línea) o contienen estrofas de varias líneas que definen una o más fuentes por estrofa (estilo deb822), con la fuente más preferida listada primero (en caso de que una única versión esté disponible en más de una fuente). La información disponible de las fuentes configuradas es adquirida por apt-get update (o por un comando equivalente de otro front-end de APT).

Si se utilizan múltiples listas de fuentes, las fuentes más preferidas son las listadas en /etc/apt/sources.list, seguidas por cada archivo en /etc/apt/sources.list.d/ en orden lexicográfico: por ejemplo, 00-alta-preferencia.list es más preferido que 50-media-preferencia.sources que es más preferido que z-baja-preferencia.list.

SOURCES.LIST.D

El directorio /etc/apt/sources.list.d proporciona una forma de agregar entradas de sources.list en archivos separados. Se permiten dos formatos de archivo diferentes, como se describe en las siguientes dos secciones. Los nombres de archivo deben tener la extensión .list o .sources dependiendo del formato contenido. Los nombres de archivo solo pueden contener letras (a-z y A-Z), dígitos (0-9), guion bajo (_), guion (-) y punto (.). De lo contrario, APT imprimirá un aviso de que ha ignorado un archivo, a menos que ese archivo coincida con un patrón en la lista de configuración Dir::Ignore-Files-Silently, en cuyo caso será ignorado silenciosamente.

El nombre de archivo sugerido para nuevos sistemas es /etc/apt/sources.list.d/vendor.sources, donde vendor es el resultado de dpkg-vendor --query Vendor | tr A-Z a-z, en formato estilo deb822. Por ejemplo, Ubuntu usa /etc/apt/sources.list.d/ubuntu.sources.

FORMATO ESTILO DE UNA LINEA

Los archivos en este formato tienen la extensión .list. Cada línea que especifica una fuente comienza con un tipo (por ejemplo, deb-src) seguido de opciones y argumentos para este tipo. Las entradas individuales no se pueden continuar en la línea siguiente. Las líneas vacías se ignoran, y un carácter # en cualquier lugar de una línea marca el resto de esa línea como un comentario. En consecuencia, una entrada se puede deshabilitar comentando toda la línea. Si se deben proporcionar opciones, estas se separan con espacios y todas juntas se encierran entre corchetes ([]) incluidos en la línea después del tipo, separados de él por un espacio. Si una opción permite múltiples valores, estos se separan entre sí con una coma (,). Un nombre de opción se separa de su(s) valor(es) por un signo igual (=). Las opciones multivalor también tienen -= y += como separadores, que en lugar de reemplazar el valor predeterminado con el(los) valor(es) dados, modifican el(los) valor(es) predeterminado(s) para eliminar o incluir los valores dados.

Este es el formato tradicional y es compatible con todas las versiones de apt. Tenga en cuenta que no todas las opciones descritas a continuación son compatibles con todas las versiones de apt. Tenga en cuenta también que algunas aplicaciones antiguas que analizan este formato por sí mismas podrían no esperar encontrar opciones, ya que eran poco comunes antes de la introducción del soporte multiarquitectura.

Este formato está obsoleto y puede ser eliminado eventualmente, pero no antes de 2029.

FORMATO ESTILO DEB822

Los archivos en este formato tienen la extensión .sources. El formato es similar en sintaxis a otros archivos utilizados por Debian y sus derivados, como los archivos de metadatos que apt descargará de las fuentes configuradas o el archivo debian/control en un paquete fuente de Debian. Las entradas individuales están separadas por una línea vacía; las líneas vacías adicionales se ignoran, y un carácter # al principio de la línea marca toda la línea como un comentario. Por lo tanto, una entrada puede deshabilitarse comentando cada línea perteneciente a la estrofa, pero generalmente es más fácil agregar el campo "Enabled: no" a la estrofa para deshabilitar la entrada. Eliminar el campo o establecerlo en yes lo vuelve a habilitar. Las opciones tienen la misma sintaxis que cualquier otro campo: un nombre de campo separado por dos puntos (:) y opcionalmente espacios de su(s) valor(es). Tenga en cuenta especialmente que los valores múltiples se separan con espacios en blanco (como espacios, tabulaciones y saltos de línea), no con comas como en el formato de una línea. Los campos multivalor como Architectures también tienen Architectures-Add y Architectures-Remove para modificar el valor predeterminado en lugar de reemplazarlo.

Este es un nuevo formato compatible con apt desde la versión 1.1. Las versiones anteriores ignoran dichos archivos con un mensaje de aviso, como se describió anteriormente. Está destinado a hacer que este formato sea gradualmente el formato predeterminado, desechando el formato de estilo de una línea descrito anteriormente, ya que es más fácil de crear, extender y modificar tanto para humanos como para máquinas, especialmente si hay muchas fuentes y/o opciones involucradas. Se alienta encarecidamente a los desarrolladores que trabajan y/o analizan fuentes de apt a agregar soporte para este formato y a contactar al equipo de APT para coordinar y compartir este trabajo. Los usuarios pueden adoptar libremente este formato ya, pero pueden encontrar problemas con el software que aún no lo soporta.

LOS TIPOS DEB Y DEB-SRC: FORMATO GENERAL

El tipo deb hace referencia a un archivo Debian típico de dos niveles, distribución/componente. La distribución es generalmente un nombre de suite como stable o testing o un nombre en clave como trixie o forky, mientras que componente es uno de main, contrib, non-free o non-free-firmware. El tipo deb-src hace referencia al código fuente de una distribución Debian en la misma forma que el tipo deb. Se requiere una línea deb-src para obtener los índices de fuentes.

El formato para dos entradas de estilo de una línea utilizando los tipos deb y deb-src es:

deb [ opción1=valor1 opción2=valor2 ] uri suite [componente1] [componente2] [...]
deb-src [ opción1=valor1 opción2=valor2 ] uri suite [componente1] [componente2] [...]

Alternativamente, la entrada equivalente en estilo deb822 se ve así:

     Tipos: deb deb-src
     URIs: uri
     Suites: suite
     Componentes: [componente1] [componente2] [...]
     opción1: valor1
     opción2: valor2

La URI para el tipo deb debe especificar la base de la distribución Debian, desde la cual APT encontrará la información que necesita. suite puede especificar una ruta exacta, en cuyo caso los componentes deben omitirse y suite debe terminar con una barra (/). Esto es útil en el caso en que solo interesa un subdirectorio particular del archivo denotado por la URI. Si suite no especifica una ruta exacta, debe estar presente al menos un componente.

suite también puede contener una variable, $(ARCH), que se expande a la arquitectura Debian (como amd64 o armel) utilizada en el sistema. Esto permite usar archivos sources.list independientes de la arquitectura. En general, esto solo es de interés cuando se especifica una ruta exacta; APT generará automáticamente una URI con la arquitectura actual en caso contrario.

Especialmente en el formato de una línea, dado que solo se puede especificar una distribución por línea, puede ser necesario tener múltiples líneas para la misma URI si se desea un subconjunto de todas las distribuciones o componentes disponibles en esa ubicación. APT ordenará la lista de URI después de haber generado un conjunto completo internamente, y colapsará múltiples referencias al mismo host de Internet, por ejemplo, en una sola conexión, de modo que no establezca de manera ineficiente una conexión, la cierre, haga otra cosa y luego restablezca una conexión al mismo host. APT también paraleliza las conexiones a diferentes hosts para lidiar más efectivamente con sitios con bajo ancho de banda.

Es importante listar las fuentes en orden de preferencia, con la fuente más preferida listada primero. Típicamente, esto resultará en un ordenamiento de más rápido a más lento (CD-ROM seguido de hosts en una red local, seguido de hosts distantes de Internet, por ejemplo).

Como ejemplo, las fuentes para su distribución podrían verse así en el formato obsoleto de una línea:

deb [signed-by=/usr/share/keyrings/debian-archive-keyring.gpg] http://deb.debian.org/debian trixie main contrib non-free non-free-firmware
deb [signed-by=/usr/share/keyrings/debian-archive-keyring.gpg] http://deb.debian.org/debian trixie-updates main contrib non-free non-free-firmware

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

CONFIGURACIÓN DE FUENTES DEL SISTEMA

Los archivos en los que se puede añadir un repositorio son:

  • /etc/apt/sources.list
  • /etc/apt/sources.list.d/*.list

El archivo/etc/apt/sources.listpuede contener líneas de estilo de una sola línea o entradas en formato deb822. El archivo/etc/apt/sources.list.d/*.listsolo puede contener entradas en formato deb822. Por favor, refiérase a sources.list(5) para más información sobre el formato y la disponibilidad de las opciones.

Ejemplo en estilo de una sola línea:

deb [signed-by=/usr/share/keyrings/debian-archive-keyring.gpg] http://deb.debian.org/debian trixie main contrib non-free non-free-firmware
deb [signed-by=/usr/share/keyrings/debian-archive-keyring.gpg] http://deb.debian.org/debian-security trixie-security main contrib non-free non-free-firmware

o como esto en formato deb822:

Types: deb
URIs: http://deb.debian.org
Suites: trixie trixie-updates
Components: main contrib non-free non-free-firmware
Signed-By: /usr/share/keyrings/debian-archive-keyring.gpg
Types: deb
URIs: http://deb.debian.org/debian-security
Suites: trixie-security
Components: main contrib non-free non-free-firmware
Signed-By: /usr/share/keyrings/debian-archive-keyring.gpg

LOS TIPOS DEB Y DEB-SRC: OPCIONES

Cada entrada de fuente puede tener opciones especificadas para modificar qué fuente se accede y cómo se adquieren los datos de ella. El formato, la sintaxis y los nombres de las opciones varían entre los formatos de estilo de una sola línea y de estilo deb822, pero ambos tienen las mismas opciones disponibles. Por simplicidad, enumeramos el nombre del campo deb822 y proporcionamos el nombre de una sola línea entre corchetes. Recuerde que además de establecer opciones multivalor explícitamente, también existe la opción de modificarlas basándose en el valor predeterminado, pero no estamos enumerando esos nombres explícitamente aquí. Las opciones no admitidas son ignoradas silenciosamente por todas las versiones de APT.

•Include (include) es una opción multivalor que define qué paquetes deben usarse de este repositorio. Los demás no se analizan.
•Exclude (exclude) es una opción multivalor que define qué paquetes no deben usarse de este repositorio. No se analizarán. Esta opción es mutuamente excluyente con Include.
•Architectures (arch) es una opción multivalor que define para qué arquitecturas se debe descargar información. Si esta opción no está establecida, el valor predeterminado son todas las arquitecturas definidas por la opción de configuración APT::Architectures.
•Languages (lang) es una opción multivalor que define para qué idiomas se debe descargar información, como descripciones de paquetes traducidas. Si esta opción no está establecida, el valor predeterminado son todos los idiomas definidos por la opción de configuración Acquire::Languages.
•Targets (target) es una opción multivalor que define qué destinos de descarga intentará adquirir apt de esta fuente. Si no se especifica, el conjunto predeterminado se define por el ámbito de configuración Acquire::IndexTargets (los destinos se especifican por su nombre en el campo Created-By). Además, los destinos se pueden habilitar o deshabilitar utilizando el campo Identifier como una opción con un valor booleano en lugar de usar esta opción multivalor.
•PDiffs (pdiffs) es un valor sí/no que controla si APT debe intentar usar PDiffs para actualizar índices antiguos en lugar de descargar los índices nuevos por completo. El valor de esta opción se ignora si el repositorio no anuncia la disponibilidad de PDiffs. Por defecto, toma el valor de la opción del mismo nombre para un archivo de índice específico definido en el ámbito Acquire::IndexTargets, que a su vez toma el valor de la opción de configuración Acquire::PDiffs, que por defecto es sí.
•By-Hash (by-hash) puede tener el valor sí, no o forzar, y controla si APT debe intentar adquirir índices a través de una URI construida a partir de una suma de verificación del archivo esperado en lugar de usar el nombre de archivo conocido del índice. Usar esto puede evitar discrepancias en las sumas de verificación, pero requiere un espejo compatible. Un valor sí o no activa/desactiva el uso de esta función si esta fuente indica que la admite, mientras que forzar habilitará la función independientemente de lo que indique la fuente. Por defecto, toma el valor de la opción del mismo nombre para un archivo de índice específico definido en el ámbito Acquire::IndexTargets, que a su vez toma el valor de la opción de configuración Acquire::By-Hash, que por defecto es sí.

Además, hay opciones que, si se establecen, afectan a *todas* las fuentes con la misma URI y Suite, por lo que deben establecerse en todas las entradas correspondientes y no pueden variar entre diferentes componentes. APT intentará detectar y generar un error en tales anomalías.

•Allow-Insecure (allow-insecure), Allow-Weak (allow-weak) y Allow-Downgrade-To-Insecure (allow-downgrade-to-insecure) son valores booleanos que por defecto son no. Si se establecen en sí, eluden partes de apt-secure(8) y, por lo tanto, ¡no deben usarse a la ligera!
•Trusted (trusted) es un valor de tres estados que por defecto es decisión de APT si una fuente se considera confiable o si se deben generar advertencias antes de, por ejemplo, instalar paquetes de esta fuente. Esta opción puede usarse para anular esa decisión. El valor sí indica a APT que siempre considere esta fuente como confiable, incluso si no pasa las comprobaciones de autenticación. Deshabilita partes de apt-secure(8) y, por lo tanto, solo debe usarse en un contexto local y confiable (si es que se usa), ya que de lo contrario se viola la seguridad. El valor no hace lo contrario, haciendo que la fuente se maneje como no confiable incluso si las comprobaciones de autenticación pasaron con éxito. El valor predeterminado no se puede establecer explícitamente.
•Signed-By (signed-by) es una opción para exigir que un repositorio pase la verificación de apt-secure(8) con un conjunto específico de claves en lugar de todas las claves confiables que APT tiene configuradas. Se especifica como una lista de rutas absolutas a archivos de keyring (deben ser accesibles y legibles para el usuario del sistema _apt, por lo que asegúrese de que todos tengan permisos de lectura sobre el archivo) y huellas digitales de claves para seleccionar de estos keyrings. Las ubicaciones recomendadas para los keyrings son /usr/share/keyrings para keyrings administrados por paquetes y /etc/apt/keyrings para keyrings administrados por el operador del sistema. Si no se especifican archivos de keyring, el valor predeterminado es el keyring trusted.gpg y todos los keyrings en el directorio trusted.gpg.d/. Si no se especifica ninguna huella digital, se seleccionan todas las claves de los keyrings. Una huella digital aceptará también todas las firmas de una subclave de esta clave, si esto no se desea, se puede añadir un signo de exclamación (!) a la huella digital para deshabilitar este comportamiento. La opción toma por defecto el valor de la opción del mismo nombre si se establece en el archivo Release adquirido previamente de este repositorio (solo se pueden especificar huellas digitales allí). De lo contrario, todas las claves en los keyrings confiables se consideran firmantes válidos para este repositorio. La opción también se puede establecer directamente a un bloque de clave pública GPG incrustado. Se requiere especial cuidado para codificar la línea vacía con espacios iniciales y ".".

•Check-Valid-Until (check-valid-until) es un valor sí/no que controla si APT debe intentar detectar ataques de repetición. El creador de un repositorio puede declarar un tiempo hasta el cual los datos proporcionados en el repositorio deben considerarse válidos, y si se alcanza este tiempo, pero no se proporcionan nuevos datos, los datos se consideran caducados y se genera un error. Además de aumentar la seguridad, ya que un atacante malicioso no puede enviar datos antiguos para siempre para evitar que un usuario actualice a una nueva versión, esto también ayuda a los usuarios a identificar espejos que ya no se actualizan. Sin embargo, algunos repositorios, como los archivos históricos, no se actualizan más por diseño, por lo que esta verificación se puede deshabilitar estableciendo esta opción en no. Por defecto, toma el valor de la opción de configuración Acquire::Check-Valid-Until, que a su vez por defecto es sí.
•Valid-Until-Min (valid-until-min) y Valid-Until-Max (valid-until-max) se pueden usar para aumentar o disminuir el período de tiempo en segundos durante el cual los datos de este repositorio se consideran válidos. -Max puede ser especialmente útil si el repositorio no proporciona un campo Valid-Until en su archivo Release para establecer su propio valor, mientras que -Min se puede usar para aumentar el tiempo de validez en espejos (locales) raramente actualizados de un archivo más frecuentemente actualizado pero menos accesible (que también está en sources.list) en lugar de deshabilitar la verificación por completo. Por defecto, toman el valor de las opciones de configuración Acquire::Min-ValidTime y Acquire::Max-ValidTime, que ambas no están establecidas por defecto.
•Check-Date (check-date) es un valor sí/no que controla si APT debe considerar correcta la hora de la máquina y, por lo tanto, realizar comprobaciones relacionadas con la hora, como verificar que un archivo Release no sea del futuro. Deshabilitarlo también deshabilita la opción Check-Valid-Until mencionada anteriormente.
•Date-Max-Future (date-max-future) controla cuánto puede estar adelantado un repositorio con respecto al futuro. Por defecto, toma el valor de la opción de configuración Acquire::Max-FutureTime, que es de 10 segundos por defecto.
•InRelease-Path (inrelease-path) determina la ruta al archivo InRelease, relativa a la posición normal de un archivo InRelease. Por defecto, esta opción no está establecida y APT intentará obtener un archivo InRelease o, si falla, un archivo Release y su archivo Release.gpg asociado. Al establecer esta opción, se intentará la ruta especificada en lugar del archivo InRelease, y se deshabilitará la opción de respaldo a archivos Release.
•Snapshot (snapshot) permite seleccionar una versión anterior del archivo del servicio de instantáneas. Los valores admitidos son: habilitar (por defecto) para permitir seleccionar una instantánea con la opción --snapshot, ID, o deshabilitar para excluir el repositorio.

Las ID de instantánea suelen ser marcas de tiempo en el formato AAAA MM DDTHHMMSSZ, como 20220102T030405Z, que es el 2 de enero de 2022 a las 03:04:05 UTC; sin embargo, los servidores pueden admitir tipos de ID adicionales, y APT no realiza ninguna verificación hasta ahora.

ESPECIFICACIÓN DE URI

Los tipos de URI actualmente reconocidos son:

http (apt-transport-http(1))

El esquema http especifica un servidor HTTP para un archivo y es el método más utilizado. La URI puede incluir directamente información de inicio de sesión si el archivo la requiere, pero se debe preferir el uso de apt_auth.conf(5). El método también admite proxies SOCKS5 y HTTP(S), ya sea configurados a través de la configuración específica de apt o especificados por la variable de entorno http_proxy en el formato (asumiendo un proxy HTTP que requiere autenticación) http://user:pass@server:port/. Los detalles de autenticación para proxies también se pueden proporcionar a través de apt_auth.conf(5)

ESPECIFICACIÓN DE URI

APT soporta los siguientes esquemas de URI:

http (apt-transport-http(1))

El esquema http especifica un servidor HTTP para un archivo. Las opciones disponibles son las mismas que las del método de transporte ftp, pero se puede usar un servidor proxy si se configura el Acquire::http::Proxy o el proxy estándar del sistema. Si se especifica la autenticación básica HTTP se usará la información de nombre de usuario y contraseña dada en la URI.

HTTP Basic Authentication

Como se mencionó en la descripción del esquema http, la autenticación básica se puede usar especificando un nombre de usuario y contraseña en la URI. Por ejemplo, http://user:password@host.com/. Sin embargo, estos métodos de autenticación son inseguros, ya que toda la comunicación con el servidor remoto (o proxy) no está cifrada, por lo que un atacante suficientemente capaz puede observar y registrar el inicio de sesión, así como todas las demás interacciones. El atacante *no* puede modificar la comunicación, ya que el modelo de seguridad de datos de APT es independiente del método de transporte elegido. Consulte apt-secure(8) para obtener más detalles.

https (apt-transport-https(1))

El esquema https especifica un servidor HTTPS para un archivo y es muy similar en uso y opciones disponibles al esquema http. La principal diferencia es que la comunicación entre apt y el servidor (o proxy) está cifrada. Tenga en cuenta que el cifrado no impide que un atacante sepa con qué servidor (o proxy) se está comunicando apt, y un análisis más profundo puede revelar qué datos se descargaron. Si esto es una preocupación, los esquemas basados en Tor mencionados más adelante pueden ser una alternativa adecuada.

mirror, mirror+scheme (apt-transport-mirror(1))

El esquema mirror especifica la ubicación de una lista de espejos. Por defecto, el esquema utilizado para la ubicación es http, pero se puede usar cualquier otro esquema a través de mirror+scheme. La lista de espejos puede contener muchas URIs diferentes para espejos entre las que el cliente APT puede elegir, seleccionar y fallar transparentemente, con el objetivo de ayudar tanto a distribuir la carga entre los espejos disponibles como a garantizar que los clientes puedan adquirir datos incluso si algunos espejos configurados no están disponibles.

file

El esquema file permite que un directorio arbitrario en el sistema de archivos sea considerado un archivo. Esto es útil para montajes NFS y espejos o archivos locales.

cdrom

El esquema cdrom permite a APT utilizar un CD-ROM, DVD o unidad USB local con intercambio de medios. Utilice el programa apt-cdrom(8) para crear entradas de cdrom en la lista de fuentes.

copy

El esquema copy es idéntico al esquema file, excepto que los paquetes se copian en el directorio de caché en lugar de usarse directamente en su ubicación. Esto es útil para las personas que usan medios extraíbles para copiar archivos con APT.

añadiendo tipos de URI más reconocibles

APT se puede extender con más métodos distribuidos en paquetes opcionales, que deben seguir el esquema de nombres apt-transport-method. Por ejemplo, el equipo de APT también mantiene el paquete apt-transport-tor, que proporciona métodos de acceso para URIs HTTP y HTTPS enrutadas a través de la red Tor.

EJEMPLOS

Utiliza el archivo almacenado localmente (o montado vía NFS) en /home/apt/debian para stable/main, stable/contrib, stable/non-free y stable/non-free-firmware.

deb file:/home/apt/debian stable main contrib non-free non-free-firmware
Tipos: deb
URIs: file:/home/apt/debian
Suites: stable
Componentes: main contrib non-free non-free-firmware

Como arriba, excepto que esto usa la distribución inestable (de desarrollo).

deb file:/home/apt/debian unstable main contrib non-free non-free-firmware
Tipos: deb
URIs: file:/home/apt/debian
Suites: unstable
Componentes: main contrib non-free non-free-firmware

Especificación de fuentes para lo anterior.

deb-src file:/home/apt/debian unstable main contrib non-free non-free-firmware
Tipos: deb-src
URIs: file:/home/apt/debian
Suites: unstable
Componentes: main contrib non-free non-free-firmware

La primera línea obtiene información de paquetes para las arquitecturas en APT::Architectures, mientras que la segunda recupera siempre amd64 y armel.

deb http://deb.debian.org/debian trixie main
deb [ arch=amd64,armel ] http://deb.debian.org/debian trixie main
Tipos: deb
URIs: http://deb.debian.org/debian
Suites: trixie
Componentes: main
Tipos: deb
URIs: http://deb.debian.org/debian
Suites: trixie

Utiliza HTTP para acceder al archivo en ftp.tlh.debian.org, bajo el directorio universe, y solo usa archivos encontrados en unstable/binary-i386 en máquinas i386, unstable/binary-amd64 en amd64, y así sucesivamente para otras arquitecturas soportadas. [Nota: este ejemplo solo ilustra cómo usar la variable de sustitución; los archivos oficiales de debian no están estructurados de esta manera]

deb http://ftp.tlh.debian.org/universe unstable/binary-$(ARCH)/

deb http://deb.debian.org/debian stable main contrib

deb-src http://deb.debian.org/debian testing main contrib
deb http://deb.debian.org/debian unstable main contrib
deb-src http://deb.debian.org/debian unstable main contrib
