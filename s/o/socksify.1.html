SOCKSIFY(1) Manual de Comandos Generales SOCKSIFY(1)

NOMBRE

socksify - socksificación en tiempo de ejecución de programas seleccionados

DESCRIPCIÓN

El script de shell socksify está diseñado para ayudar a usar socks con binarios dinámicos ya compilados. Esto se logra estableciendo la variable de entorno LD_PRELOAD a libdsocks. Luego intentará envolver todas las llamadas del sistema relacionadas con la red.

Cuando se usa, el script puede hacer socksify un programa simplemente prefijando el programa dado y sus argumentos con el script socksify, como en el ejemplo a continuación.

$ socksify ftp ftp.example.org

ENTORNO

El script socksify, y la biblioteca socks de Dante utilizada por el script socksify, pueden interpretar varias variables de entorno.

SOCKS_CONF
Indica el nombre del archivo socks.conf. Por defecto es /etc/socks.conf, a menos que haya sido cambiado al compilar las bibliotecas libsocks de Dante.

La creación de un socks.conf es la forma recomendada de usar socksify, pero socksify también se puede usar para la mayoría de las configuraciones simples sin ningún archivo socks.conf, siempre que el servidor proxy a usar esté configurado en una de las variables de entorno admitidas.

SOCKS_DEBUG
Habilita el registro de depuración. El valor dado debe ser un número, uno o superior, que indique el nivel de depuración proporcionado.
SOCKS_LOGOUTPUT
Este valor controla a dónde envía la biblioteca cliente la salida del registro. Puede ser syslog, stdout, stderr, un nombre de archivo o una combinación. El valor predeterminado es ninguno.
SOCKS_USERNAME
Utiliza el valor de SOCKS_USERNAME como nombre de usuario al realizar la autenticación de nombre de usuario.
SOCKS_PASSWORD
Utiliza el valor de SOCKS_PASSWORD como contraseña al realizar la autenticación de nombre de usuario. No se recomienda, ya que otros usuarios en el sistema podrían ver su contraseña.
SOCKS_SERVER, SOCKS4_SERVER, SOCKS5_SERVER,
Estas variables permiten especificar la dirección del servidor sin usar un archivo socks.conf. Si está presente un archivo socks.conf, se ignora si alguna de estas variables está establecida.

El formato aceptado es <dirección_ip>:<puerto>. Si se establece el valor de SOCKS_SERVER, indica que el servidor especificado admite todas las versiones de socks compatibles con Dante. Si se utiliza alguna de las otras dos variables, indican que el servidor socks dado solo admite la versión de socks correspondiente, v4 o v5. Tenga en cuenta que si el servidor socks requiere alguna forma de autenticación, debe usar SOCKS5_SERVER, ya que v4 no admite autenticación.

HTTP_CONNECT_PROXY
Esta variable se puede usar para especificar la ubicación de un proxy HTTP que admita la solicitud connect. El formato utilizado para especificar un proxy HTTP es http://<dirección_ip>:<puerto>.
UPNP_IGD
Esta variable se puede usar para especificar la ubicación de un enrutador IGD habilitado para UPNP. Hay tres valores posibles para esta variable: una URL completa, el nombre de la interfaz a través de la cual el enrutador es accesible, o el valor "broadcast" para buscar el IGD en todas las interfaces apropiadas.
Tenga en cuenta que si alguna de las variables de entorno anteriores, que indican el
servidor proxy a usar están establecidas, el cliente Dante no analizará el socks.conf archivo.
SOCKS_AUTOADD_LANROUTES
Si esta variable se establece en "no", el cliente no intentará agregar automáticamente rutas directas para todas las direcciones en la LAN. El valor predeterminado es agregarlas.
SOCKS_DISABLE_THREADLOCK
Si esta variable se establece, el cliente no realizará bloqueo de hilos. El valor predeterminado es que el cliente intente determinar por sí mismo si la aplicación a socksify necesita bloqueo de hilos o no.
SOCKS_DIRECTROUTE_FALLBACK
Si esto se establece en "yes", el cliente recurrirá a intentar una conexión directa si la ruta proxy falla. El valor predeterminado es "no".
