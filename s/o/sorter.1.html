SORTER(1) Manual de comandos generales SORTER(1)

NOMBRE

sorter - Ordena archivos en una imagen en categorías basadas en el tipo de archivo

SINOPSIS

[-b tamaño ] [-e] [-E] [-h] [-l] [-md5] [-s] [-sha1] [-U] [-v] [-V] [-a alerta_hash ] [-c config ] [-C config ] [-d dir ] [-m mnt ] [-n db_nsrl ] [-x excluye_hash ] [-i tip_img] [-o offset_img ] [-f tip_fs ] imagen [imagen] [dir_meta]

DESCRIPCIÓN

sorter es un script de Perl que analiza un sistema de archivos para organizar los archivos asignados y no asignados por tipo de archivo. Ejecuta el comando 'file' en cada archivo y organiza los archivos según las reglas en los archivos de configuración. También se realiza la comparación de extensiones para identificar archivos 'ocultos'. También se pueden proporcionar bases de datos de hashes para archivos que se sabe que son correctos y pueden ignorarse, y para archivos que se sabe que son incorrectos y deberían ser alertados.

Por defecto, el programa utiliza los archivos de configuración en el directorio donde se instaló The Sleuth Kit. Estos pueden ser anulados con opciones en tiempo de ejecución. Hay un archivo de configuración estándar para todos los tipos de sistemas de archivos y luego uno específico para un sistema operativo dado.

ARGUMENTOS

Los argumentos requeridos son los siguientes. Esto analizará una o más imágenes y guardará los resultados en el directorio '-d' o listará los resultados en STDOUT (si se da '-l').

-d dir
Especifica la ubicación donde se deben escribir todos los archivos. Esto incluye los archivos de índice y los subdirectorios si se da el indicador '-s'. ESTO DEBE darse, a menos que se dé el indicador de lista '-l'.
-l
Lista información en STDOUT (nunca se escriben archivos). Esto es útil para Respuesta a Incidentes, con el uso de 'netcat'. Esto no se puede usar si se usa '-d'.
imagen [imágenes]
La imagen del disco o partición a leer, cuyo formato se da con '-i'. Se pueden dar varios nombres de archivo de imagen si la imagen está dividida en varios segmentos. Si solo se da un archivo de imagen, y su nombre es el primero en una secuencia (por ejemplo, indicado por terminar en '.001'), los segmentos de imagen subsiguientes se incluirán automáticamente.

Las opciones son las siguientes:

-f tip_fs
Especifica el tipo de sistema de archivos de la(s) imagen(es). Este es el mismo tipo que usa The Sleuth Kit.
-i tip_img
Especifica el tipo de imagen en la que se encuentra el sistema de archivos. Este es el mismo tipo que usa The Sleuth Kit.
-o offset_img
Especifica el desplazamiento del sector desde el principio de la imagen hasta el inicio del sistema de archivos.
-b tamaño
Especifica el tamaño mínimo de archivo a procesar. Todos los archivos menores que este tamaño serán ignorados.
-c config
Especifica la ubicación de un archivo de configuración adicional. Este archivo se cargará además de los estándar en el directorio de instalación. Estas configuraciones tendrán prioridad sobre los archivos estándar.
-C config
Especifica la ubicación del ÚNICO archivo de configuración. Los archivos de configuración estándar no se cargarán si se da esta opción. Por ejemplo, en el directorio ´share/sort´ hay un archivo llamado 'images.sort'. Este archivo contiene solo reglas sobre imágenes gráficas. Si se especifica con -C, entonces solo se guardarán imágenes sobre la imagen.
-m mnt
Especifica el punto de montaje de la imagen que se está analizando. Esto es solo por razones estéticas. Cuando se escriban las entradas en los archivos de salida, los archivos tendrán la ruta completa en lugar de solo la ruta relativa. Si se da esto, entonces solo se puede dar una imagen.
-a alerta_hash
Especifica la ubicación de una base de datos de hashes con entradas de archivos 'malos' conocidos. Si se encuentra algún archivo con un valor de hash MD5 en esta base de datos, se colocará en un archivo especial de alerta. Esta base de datos debe haber sido indexada para MD5 usando 'hfind' en The Sleuth Kit antes de ser utilizada por sorter.
-n db_nsrl
Especifica la ubicación de la base de datos de la NIST National Software Reference Library (NSRL) (www.nsrl.nist.org). Cualquier archivo encontrado en la NSRL será ignorado y no se colocará en una categoría. La base de datos debe estar indexada para MD5 con 'hfind' en The Sleuth Kit antes de ser utilizada por sorter. El archivo de base de datos se llama actualmente 'NSRLFile.txt'.
-x excluye_hash
Especifica la ubicación de una base de datos de hashes con entradas de archivos 'buenos' conocidos. Si se encuentra algún archivo con un valor de hash MD5 en esta base de datos, será ignorado y no se procesará ni se guardará en los archivos de categoría. Esta base de datos debe haber sido indexada para MD5 usando 'hfind' en The Sleuth Kit antes de ser utilizada por sorter.
-e
Realiza comprobaciones de discrepancia de extensiones (no se generan archivos de índice de categoría)
-U
No guarde datos sobre tipos de archivo desconocidos. Por defecto, se crea un archivo 'desconocido' para archivos donde la salida de 'file' no se conoce. Esto permite refinar su configuración. Si esto no se desea, use este indicador.
-h
Crea archivos de categoría en HTML
-md5
Calcula el valor MD5 para cada archivo y lo guarda en el archivo de categoría. Esto se hará automáticamente cuando se proporcionen las bases de datos.
-sha1
Calcula el valor SHA-1 para cada archivo y lo guarda en el archivo de categoría.
-s
Guarda el contenido real del archivo en subdirectorios en el directorio especificado por '-d'. Por ejemplo, todos los archivos JPG y GIF se guardarían realmente en el directorio 'images'. Si también se da '-h', también se crean miniaturas de imágenes gráficas.
-v
Muestra información detallada
-V
Muestra la versión.
[dir_meta]
La dirección de metadatos del directorio para comenzar. Por defecto, se utiliza el directorio raíz. Si se da esto, entonces solo se puede dar una imagen.

VISIÓN GENERAL DE ALTO NIVEL DEL PROCESO

sorter es un script de Perl que interactúa con otras herramientas de The Sleuth Kit. Comienza leyendo los archivos de configuración del directorio de instalación. Hay un archivo de configuración general y uno específico para cada sistema operativo. El específico se determina a partir del indicador '-f'. Cada archivo de configuración contiene reglas para procesar la salida del comando 'file'. Un tipo de línea identifica a qué categoría (es decir, 'imágenes') pertenece una salida dada de 'file' (es decir, ´datos de imagen´) (usando expresiones regulares). Otra regla muestra las extensiones de archivo (es decir, .txt) que pertenecen a una salida de 'file' (es decir, ASCII(.*?)texto). Consulte la sección Reglas a continuación.

Luego, el programa ejecuta la herramienta 'fls' en The Sleuth Kit para identificar los archivos en la imagen del sistema de archivos. Cada archivo identificado se ve usando la herramienta 'icat'. Si se proporciona una base de datos de hashes, se calcula el hash del archivo y se busca. Si se encuentra en una base de datos de 'alertas', se agrega a un archivo especial 'alert.txt'. Si se encuentra en la NSRL o en la base de datos de 'exclusión', se ignora como un archivo conocido bueno. Los archivos excluidos se registran en un archivo de 'exclusión' para referencia futura, pero no se guardan en los archivos de categoría.

Luego se ejecuta el comando 'file' para identificar el tipo de archivo (basado en la información de la cabecera). Las reglas del archivo de configuración se utilizan para identificar a qué categoría pertenece. Se agrega una entrada al archivo de categoría correspondiente (en el directorio '-d dir'). Si se da el indicador '-s', entonces se guarda una copia del archivo en un subdirectorio con el mismo nombre que la categoría. Si se utiliza el formato HTML, los hipervínculos permitirán ver fácilmente los archivos guardados y ver qué hay en cada categoría.

Los archivos que no tienen una categoría se registran en la categoría 'desconocido' y la categoría 'datos'. 'datos' es para archivos con una estructura que 'file' no conoce y 'desconocido' es para archivos con una estructura que 'file' conoce. Estos se guardan para el futu

DESCRIPTION

The sorter program is designed to organize files based on their type. It utilizes file system information, hash databases, and user-defined configuration files to categorize files. By default, it scans a disk image and categorizes files based on information from the 'file' command and hash databases. Files that are not recognized or fall into a known category are placed in an 'unknown' category. The program can be configured to ignore certain file types or to save categorized files to specific directories.

The program can also analyze the contents of unallocated file space by using the output of the 'ils' command. This allows it to identify and categorize data that might otherwise be overlooked.

ARGUMENTS

The following arguments are available:

  • -a hash_db
  • Adds a hash database to the list of known good files. This database will be used to identify files that are known good.
  • -c config_file
  • Adds a configuration file to the list of rules. These rules define how files are categorized.
  • -C config_file
  • Replaces all existing configuration files with the specified one.
  • -d output_dir
  • Specifies the directory where the sorted files will be saved. This is used in conjunction with the '-s' flag.
  • -f fs_type
  • Specifies the file system type (e.g., ntfs, ext3).
  • -h
  • Identifies files based on hash databases only. This flag disables the use of the 'file' command for categorization.
  • -i img_type
  • Specifies the image file type (e.g., raw).
  • -n hash_db
  • Adds a hash database to the list of known good files. This database will be used to identify files that are known good. This is the same functionality as the '-a' flag.
  • -o offset
  • Specifies the offset into the image file to start processing.
  • -s
  • Saves the categorized files to disk. Files are saved in a subdirectory named after their category.
  • -U
  • Ignores files that are in the unknown category.
  • -v
  • Enables verbose output, showing more detailed information about the sorting process.
  • -x hash_db
  • Excludes files listed in the specified hash database. These files will not be processed or categorized.

HIGH-LEVEL OVERVIEW OF PROCESS

The sorter program processes files from a given disk image. It determines the file type using the 'file' command and compares this information against user-defined rules and hash databases. Files can be categorized into predefined groups (e.g., images, documents) or placed in an 'unknown' category if they don't match any known rules. The program can also save the categorized files to disk, creating subdirectories for each category. Additionally, it checks file extensions against defined rules and flags any mismatches. The program can also examine unallocated file space using the 'ils' command to identify and categorize data within it. Files found in known good hash databases are handled specially. Unknown categories can be ignored using the '-U' flag.

When files are saved using the '-s' flag, they are stored in a subdirectory named after their category. The filenames are constructed using the file system image name, followed by the meta data address, and the original file extension. A category index file can be used to translate the actual filename to the saved filename. HTML formatting is used for easier viewing, with links from the category index file to each individual file.

The program also enforces rules regarding file extensions. If a file has an extension that is not recognized according to the defined rules for its file type, it is flagged as a 'mismatch'. Files without extensions are not checked, even if their file type has associated valid extensions. This extension check is performed regardless of whether the file is found in a known good hash database. If a file is found in such a database, it is placed in a special file. Files of type 'data' are exempt from extension checks by default, as their structure is typically unknown.

The sorter program repeats these procedures using the output of the 'ils' command. This allows it to analyze the contents of unallocated file space that still have pointers to data units, although not all file systems may yield data from this step.

CONFIGURATION FILES

Configuration files are essential for defining file type categories and valid extensions for each file type. These files are typically distributed with the 'sorter' tool and are located in the 'share/sorter' directory within the installation path.

The 'default.sort' file serves as a general configuration for all file system types and includes entries for common file types. Additionally, OS-specific configuration files exist, which are useful for handling extensions unique to particular operating systems. By default, both the 'default.sort' file and the relevant OS-specific file are utilized. The '-c' flag allows for the inclusion of an additional configuration file, while the '-C' flag restricts the program to use only the specified configuration file.

Configuration files contain two types of rules: category rules and extension rules. Each rule begins with a header indicating its type ('category' or 'ext'). Both rule types consist of two additional columns separated by any whitespace.

A category rule specifies the category name in the second column and a Perl regular expression in the third column. The category name must consist only of alphanumeric characters and cannot contain spaces. The regular expression is used to analyze the output of the 'file' command and is applied case-insensitively. Multiple rules can apply to a single category, but a given file output can only belong to one category. For example:

The following rule categorizes any file output containing 'image data' into the 'images' category:
category images image data

This rule categorizes file output that has 'ASCII', followed by any characters, and then 'text' into the 'text' category:
category text ASCII(.*?)text

This rule categorizes file output that consists solely of 'data' into the 'data' category. The '^' and '$' characters in Perl denote the beginning and end of the string, respectively. The term 'data' is often found in the output of the 'file' command for unknown binary data.
category data ^data?

A special category named 'ignore' is available to exclude specific file types from processing, serving as a means to save time and disk space.

Extension rules function similarly, with the second column listing the extensions associated with a file type. Multiple rules can be defined for the same file type, and comparisons are case-insensitive. If no extensions are valid for a particular file type, an explicit rule is not necessary, as this is the default assumption.

For instance, since ASCII text files can have various extensions, the following rules could be established:


ext txt,log ASCII(.*?)text
ext c,cpp,h,js ASCII(.*?)text

Users are encouraged to submit any useful rules for standard investigations via email to the author (carrier at sleuthkit dot org) for potential inclusion in future releases.

EXAMPLES

To run sorter without any hash databases:


# sorter -f ntfs -d data/sorter images/hda1.dd
# sorter -d data/sorter images/hda1.dd


# sorter -i raw -f ntfs -o 63 -d data/sorter images/hda.dd

To include the NSRL, an exclude hash database, and an alert hash database:


# sorter -f ntfs -d data/sorter -a /usr/hash/rootkit.db -x /usr/hash/win2k.db -n /usr/hash/nsrl/NSRLFile.txt images/hda1.dd

To identify only images using the supplied 'images.sort' file:


# sorter -f ntfs -C /usr/local/sleuthkit/share/sort/images.sort -d data/sorter -h -s images/hda1.dd
