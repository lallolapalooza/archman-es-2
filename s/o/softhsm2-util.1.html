SOFTHSM2-UTIL(1) Manual de Comandos Generales SOFTHSM2-UTIL(1)

NOMBRE

softhsm2-util - herramienta de soporte para libsofthsm2

SINOPSIS

softhsm2-util --show-slots

softhsm2-util --init-token --free --label texto \ [--so-pin PIN --pin PIN]

softhsm2-util --import ruta [--file-pin PIN] --token etiqueta \ [--pin PIN --no-public-key] --label texto --id hex

softhsm2-util --import ruta --aes --token etiqueta \ [--pin PIN] --label texto --id hex

softhsm2-util --delete-token --token texto

DESCRIPCIÓN

softhsm2-util es una herramienta de soporte principalmente para libsofthsm2. También se puede usar con otras bibliotecas PKCS#11 usando la opción --module

Lea las secciones a continuación para obtener más información sobre libsofthsm2 y PKCS#11. La mayoría de las aplicaciones asumen que el token que desean usar ya está inicializado. Entonces, depende del usuario inicializar el token PKCS#11. Esto se hace usando la interfaz PKCS#11, pero en lugar de escribir su propia herramienta, puede usar la herramienta softhsm2-util.

Las claves generalmente se crean directamente en el token, pero el usuario puede querer usar un par de claves existente. Las claves se pueden importar a un token usando la interfaz PKCS#11, pero esta herramienta también se puede usar si el usuario tiene el par de claves en un archivo PKCS#8. Si necesita convertir claves del formato .private-key de BIND a PKCS#8, puede usar softhsm2-keyconv.

La biblioteca libsofthsm2, conocida como SoftHSM, proporciona funcionalidad criptográfica utilizando la API PKCS#11. Fue desarrollada como parte del proyecto OpenDNSSEC, por lo tanto, diseñada para cumplir con los requisitos de OpenDNSSEC, pero también puede funcionar junto con otro software que desee utilizar la funcionalidad de la API PKCS#11.

SoftHSM es una implementación de software de un dispositivo criptográfico genérico con una interfaz PKCS#11. Estos dispositivos a menudo se denominan tokens. Lea en el manual softhsm2.conf(5) cómo crear estos tokens y cómo se agregan a una ranura en SoftHSM.

La API PKCS#11 se puede utilizar para manejar y almacenar claves criptográficas. Esta interfaz especifica cómo comunicarse con dispositivos criptográficos como HSM (Módulos de Seguridad de Hardware) y tarjetas inteligentes. El propósito de estos dispositivos es, entre otras cosas, generar claves criptográficas y firmar información sin revelar material de clave privada al mundo exterior. A menudo están diseñados para funcionar bien en estas tareas específicas en comparación con procesos ordinarios en una computadora normal.

ACCIONES

--delete-token
Elimina el token en una ranura dada. Úselo con --token o --serial. Cualquier contenido en el token será borrado.
--help, -h
Muestra la información de ayuda.
--import ruta
Importa un par de claves desde la ruta dada. El archivo debe estar en formato PKCS#8.
Úselo con --slot o --token o --serial, --file-pin, --pin, --no-public-key, --label, y --id.
También se puede usar con --aes para usar el archivo tal cual e importarlo como AES.
--init-token
Inicializa el token en una ranura dada, etiqueta de token o número de serie de token. Si el token ya está inicializado, este comando lo reinicializará, borrando así todos los objetos del token. El PIN del Administrador de Seguridad (SO) correspondiente también debe proporcionarse al reinicializar. Los tokens inicializados se reasignarán a otra ranura (basado en el número de serie del token).
Úselo con --slot o --token o --serial o --free, --label, --so-pin, y --pin.
--show-slots
Muestra todas las ranuras disponibles y su estado actual.
--version, -v
Muestra la información de la versión.

OPCIONES

--aes
Se usa para indicar a la importación que use el archivo tal cual y lo importe como AES.
--file-pin PIN
El PIN se usará para descifrar el archivo PKCS#8. Si no se proporciona, se asume que el archivo PKCS#8 no está cifrado.
--force
Use esta opción para anular las advertencias y forzar la acción dada.
--free
Utiliza el primer token libre/no inicializado.
--id hex
Elige un ID para el par de claves. El ID está en hexadecimal con longitud variable. Úselo con --force al importar un par de claves si el ID ya existe.
--label texto
Define la etiqueta del objeto o del token que se establecerá.
--module ruta
Usa una biblioteca PKCS#11 diferente a SoftHSM.
--no-public-key
No importa la clave pública.
--pin PIN
El PIN para el usuario normal.
--serial número
Usará el token con un número de serie coincidente.
--slot número
La ranura donde se encuentra el token.
--so-pin PIN
El PIN para el Administrador de Seguridad (SO).
--token etiqueta
Usará el token con una etiqueta de token coincidente.

EJEMPLOS

El token se puede inicializar usando este comando:

softhsm2-util --init-token --slot 1 --label "mi token"

Un par de claves se puede importar usando la herramienta softhsm, donde usted especifica la ruta al archivo de clave, el número de ranura, la etiqueta y el ID de los nuevos objetos, y el PIN del usuario. El archivo debe estar en formato PKCS#8.

softhsm2-util --import key1.pem --token "mi token" --label "Mi clave" \
--id A1B2 --pin 123456
(Agregue --file-pin PIN si el archivo de clave está cifrado.)

NOMBRE

softhsm2-util — Utilidades de Softhsm

SINOPSIS

softhsm2-util [opciones] [acción]

DESCRIPCIÓN

El comando softhsm2-util se utiliza para gestionar el dispositivo Softhsm.

ACCIONES

Las acciones disponibles son:

  • list-slots: Lista las ranuras disponibles.
  • create-token: Crea un nuevo token en una ranura.
  • delete-token: Elimina un token de una ranura.
  • login: Inicia sesión en un token.
  • logout: Cierra la sesión del token.
  • list-objects: Lista los objetos (claves, certificados) en un token.
  • create-object: Crea un nuevo objeto en un token.
  • delete-object: Elimina un objeto de un token.
  • import-cert: Importa un certificado a un token.
  • export-cert: Exporta un certificado de un token.
  • generate-key: Genera una nueva clave en un token.
  • get-attribute: Obtiene el valor de un atributo de un objeto.
  • set-attribute: Establece el valor de un atributo de un objeto.
  • change-pin: Cambia el PIN del token.
  • initialize-pin: Inicializa el PIN del token.
  • reset-token: Restablece un token.
  • gen-sym-key: Genera una clave simétrica.
  • wrap-key: Envuelve una clave.
  • unwrap-key: Desenvuelve una clave.

OPCIONES

Las opciones disponibles incluyen:

  • -a, --attribute: Especifica un atributo para un objeto.
  • -c, --cert: Especifica el archivo de certificado.
  • -d, --domain: Especifica el dominio para la clave.
  • -e, --exportable: Indica si la clave es exportable.
  • -f, --file: Especifica un archivo.
  • -h, --help: Muestra la ayuda.
  • -i, --id: Especifica el ID del objeto.
  • -k, --key: Especifica el archivo de clave.
  • -l, --label: Especifica la etiqueta del token.
  • -m, --mechanism: Especifica el mecanismo de criptografía.
  • -n, --new-pin: Especifica el nuevo PIN.
  • -o, --object: Especifica el tipo de objeto.
  • -p, --pin: Especifica el PIN del token.
  • -q, --quiet: Modo silencioso.
  • -r, --read-from: Lee la entrada desde un archivo.
  • -s, --slot: Especifica el número de ranura.
  • -t, --token: Especifica el ID del token.
  • -u, --url: Especifica la URL del dispositivo PKCS#11.
  • -v, --verbose: Modo detallado.
  • --key-type: Especifica el tipo de clave.
  • --key-size: Especifica el tamaño de la clave.
  • --pin-len: Especifica la longitud del PIN.

EJEMPLOS

Ejemplo de creación de un token:

softhsm2-util --slot 1 --label mytoken --pin 1234 --initialize-pin

Ejemplo de inicio de sesión en un token:

softhsm2-util --slot 1 --pin 1234 --login

Ejemplo de generación de una clave RSA:

softhsm2-util --generate-key --key-type RSA --key-size 2048 --label mykey
