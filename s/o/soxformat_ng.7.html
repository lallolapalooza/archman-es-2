NOMBRE

SoX - Sound eXchange_ng, otro paquete de herramientas para la manipulación de audio

DESCRIPCIÓN

Este manual describe los formatos de archivo y los tipos de dispositivos de audio compatibles con SoX; el conjunto de manuales de SoX comienza con sox_ng(1).

Los tipos de formato que SoX puede determinar por la extensión de un nombre de archivo se enumeran con sus nombres precedidos por un punto. Los tipos de formato que se integran opcionalmente en SoX están marcados como `(opcional)'.

Los tipos de formato que son manejados por la biblioteca externa sndfile están marcados como `(con sndfile)' y los tipos de formato que solo se pueden leer usando el programa externo ffmpeg están marcados como `(con ffmpeg)'

Los formatos para los cuales SoX tiene controladores internos pero que también son compatibles con sndfile o ffmpeg están marcados como (también con -t sndfile) o (también con -t ffmpeg). Esto podría ser útil si tiene un archivo que no funciona con los lectores y escritores integrados de SoX.

Para ver si SoX tiene soporte para un formato o dispositivo opcional, ingrese sox_ng -h y busque su nombre en `FORMATOS DE ARCHIVO DE AUDIO' o `CONTROLADORES DE DISPOSITIVOS DE AUDIO'.

Para saber todo sobre un formato, ya sea que lo lea o lo escriba, o ambos, y qué codificaciones puede escribir, ingrese algo como --help-format wav o, para ver detalles de todos los formatos, --help-format all.

FORMATOS & CONTROLADORES DE DISPOSITIVOS

.raw (también con -t sndfile), .f32, .f64, .s8, .s16, .s24, .s32, .u8, .u16, .u24, .u32, .ul, .al, .lu, .la
Archivos de audio sin formato (sin encabezado). Para raw, la frecuencia de muestreo y la codificación de datos deben proporcionarse mediante opciones de formato en la línea de comandos; para los otros tipos enumerados, la frecuencia de muestreo tiene un valor predeterminado de 8 kHz y la codificación de datos se define por el sufijo dado. Por lo tanto, f32 y f64 indican archivos codificados como PCM de punto flotante IEEE-754 de 32 y 64 bits respectivamente; s8, s16, s24 y s32 indican PCM de entero con signo de 8, 16, 24 y 32 bits respectivamente; u8, u16, u24 y u32 indican PCM de entero sin signo de 8, 16, 24 y 32 bits respectivamente; ul indica `μ-law' (8 bits), al indica `A-law' (8 bits) y lu y la son `μ-law' y `A-law' respectivamente con orden de bits inverso. Para todos los formatos sin formato, el número de canales tiene un valor predeterminado de 1.

Los archivos de audio sin encabezado en una computadora SPARC probablemente sean del formato ul; en una Mac, probablemente sean u8 pero con una frecuencia de muestreo de 11025 o 22050 Hz.

Ver .ima y .vox para formatos ADPCM sin formato y .cdda para audio digital de CD sin formato.

.f4, .f8, .s1, .s2, .s3, .s4, .u1, .u2, .u3, .u4, .sb, .sw, .sl, .ub, .uw
Alias obsoletos para .f32, .f64, .s8, .s16, .s24, .s32, .u8, .u16, .u24, .u32, .s8, .s16, .s32, .u8 y .u16 respectivamente.

.aiff, .aif (también con -t sndfile o -t ffmpeg)
Archivos AIFF como se usan en Macs antiguos, Apple IIc/IIgs y SGI. El soporte AIFF de SoX no incluye múltiples fragmentos de audio ni el formato de descripción de instrumentos musicales 8SVX. Los archivos AIFF son archivos multimedia y pueden tener múltiples fragmentos de audio e imagen; es posible que necesite un archivador separado para trabajar con ellos. En MacOS X, AIFF ha sido reemplazado por CAF.
.aiffc, .aifc (también con -t sndfile)
AIFF-C se basa en AIFF pero también maneja audio comprimido. También puede manejar datos lineales sin comprimir little-endian que a menudo se denominan codificación sowt. Esta codificación se ha convertido en el formato predeterminado producido por las Macs modernas, así como por iTunes en cualquier plataforma. Los archivos AIFF-C producidos por otras aplicaciones suelen tener la extensión de archivo .aif y requieren examinar su encabezado para detectar el formato real. sowt, a-law y u-law son las únicas codificaciones que SoX puede leer y escribir de forma nativa; para otros tipos de compresión como GSM, intente -t ffmpeg.

AIFF-C está definido en DAVIC 1.4 Parte 9 Anexo B. Este formato se hace referencia desde ARIB STD-B24, que se especifica para la transmisión de datos japonesa. No se admiten fragmentos privados.

alsa (opcional)
El controlador de dispositivo Advanced Linux Sound Architecture admite la reproducción y grabación de audio. ALSA solo se utiliza en sistemas operativos basados en Linux, aunque estos a menudo también admiten OSS (ver más abajo). Ejemplos: 
	sox_ng infile -t alsa
	sox_ng infile -t alsa default
	sox_ng infile -t alsa plughw:0,0
	sox_ng -b 16 -t alsa hw:1 outfile
.amb
Ambisonic B-Format es una especialización de .wav con entre 3 y 16 canales de audio para usar con un decodificador Ambisonic. Ver http://www.ambisonia.com/Members/mleese/file-format-for-b-format para detalles. Depende de usted juntar los canales en el orden correcto y con la amplitud correcta.
.amr-nb, .amr-wb (ambos opcionales, también con -t ffmpeg)
Adaptive Multi Rate Narrow y Wide Band son formatos con pérdida para voz utilizados en la telefonía móvil de tercera generación y definidos en 3GPP TS 26.071 y TS 26.171.

sox_ng-formats

sox_ng-formats — formatos de archivo de audio que SoX puede leer y escribir

FORMATOS DE AUDIO

SoX es capaz de leer y escribir un gran número de formatos de audio. Los formatos se especifican con la opción -t (tipo). Si esta opción se omite, SoX intentará deducir el formato del nombre del archivo (si tiene una extensión conocida) o de los datos de audio crudos (si se proporciona una cabecera).

A continuación se presenta una lista de los formatos conocidos por SoX. La disponibilidad de algunos de estos formatos depende de si se han instalado las bibliotecas o programas externos correspondientes, como ffmpeg o sndfile .

.3gp, .3g2 (con ffmpeg)
Formatos de archivo multimedia 3GPP y 3GPP2.
.a, .snd (con sndfile, también con -t ffmpeg)
Formato de audio de Sun Microsystems. Consulte .au .
.aace (con ffmpeg)
Formato de audio comprimido de Apple (AAC).
.aiff, .aif (con sndfile, también con -t ffmpeg)
Formato de archivo de audio de Intercambio de Archivos de Audio (AIFF), utilizado en plataformas Apple Macintosh.
.alaw
Formato de audio de ley-A sin cabecera. Consulte .ul .
.alsapar (con alsamodul)
Interfaz de sonido ALSA. Utilice este formato para enviar audio a un dispositivo de sonido ALSA. La selección de dispositivos se realiza mediante la variable de entorno ALSADEV . Por ejemplo: 
		export ALSADEV=default
		sox_ng -n -t alsapar output.wav
Si la variable de entorno no está establecida, se utilizará el dispositivo predeterminado de ALSA.
.amb (con ffmpeg)
Formato de audio de Amuse-Bouche.
.amr (con ffmpeg)
Formato de audio de Banda Ancha Adaptativa Multi-tasa (AMR), utilizado a menudo en telefonía móvil.
.aob
Formato de audio de Amiga. Se utiliza para el audio de Amiga, que puede ser sin compresión (PCM) o comprimido (8-bit u 8-bit unsigned). El formato de la cabecera permite la identificación del tipo de compresión y la frecuencia de muestreo. sox_ng infile -t aob outfile
.ape (con ffmpeg)
Formato Monkey's Audio.
.apcm
Formato PCM de Apple. Formato de audio sin cabecera, con muestras PCM de 16 bits y orden de bytes little-endian. La frecuencia de muestreo debe especificarse con -r . sox_ng infile -t apcm -r 44100 outfile
.apm (con ffmpeg)
Formato APM de Ubisoft Rayman 2.
.aptx (con ffmpeg)
Formato de Tecnología de Procesamiento de Audio para Bluetooth.

SoX solo puede autodetectar este tipo de archivo por su extensión; si se lee desde la `entrada estándar' (stdin) o desde un archivo cuyo nombre no termina en `.aptx', deberá prefijarlo con -t ffmpeg .

.argo_asf (con ffmpeg)
Formato ASF de Argonaut Games.
.asf (con ffmpeg)
Formato de Flujo de Audio Avanzado / Activo (ASF).
.ast (con ffmpeg)
Formato de Flujo de Audio AST.
.au, .snd (también con -t sndfile o -t ffmpeg)
Archivos AU de Sun Microsystems. Hay muchos tipos de archivo AU; DEC inventó el suyo propio con un número mágico y un orden de bytes diferentes. Para escribir un archivo DEC, utilice la opción de archivo de salida -L (little-endian).

Se sabe que algunos archivos .au tienen cabeceras AU inválidas; estos son probablemente archivos originales de Sun μ-law de 8000 Hz y se pueden tratar con el formato .ul .

Es posible anular la información de la cabecera del archivo AU con las opciones -r (frecuencia de muestreo) y -c (número de canales), en cuyo caso SoX emitirá una advertencia sobre la discrepancia.

.avi (con ffmpeg)
Formato de Intercalado de Audio y Vídeo (AVI).
.avr (también con -t ffmpeg)
Formato Audio Visual Research, utilizado por varios paquetes comerciales en Mac.
.caf (con sndfile, también con -t ffmpeg)
Formato de Archivo de Audio Core de Apple.
.cdda, .cdr
Audio Digital de Disco Compacto (CDDA) "Red Book" (audio crudo). CDDA tiene dos canales de audio formateados como enteros con signo big-endian de 16 bits a una frecuencia de muestreo de 44.1 kHz. El número de muestras estéreo en cada pista CDDA es siempre un múltiplo de 588.
coreaudio (opcional)
El controlador de dispositivo CoreAudio de MacOS X soporta tanto la reproducción como la grabación. Si un nombre de archivo no es específico o si el nombre es "default", se selecciona el dispositivo de audio predeterminado. Cualquier otro nombre se utilizará para seleccionar un dispositivo específico. Los nombres válidos se pueden ver en el menú Preferencias del Sistema->Sonido y luego en las pestañas Salida y Entrada.

Ejemplos: 

		sox_ng infile -t coreaudio
		sox_ng infile -t coreaudio default
		sox_ng infile -t coreaudio "Internal Speakers"
.cvsd, .cvs
La modulación de pendiente variable continua (CVSD) es un formato sin cabecera utilizado para comprimir audio de voz para aplicaciones como el correo de voz con una tasa de bits fija de 8 kHz. Este formato se utiliza a veces con muestras invertidas de bits; la opción -X puede utilizarse para establecer el orden de bits.
.cvu
La modulación de pendiente variable continua sin filtrar es un manejador alternativo para CVSD que no está filtrado pero que se puede utilizar con cualquier frecuencia de muestreo. Como es un formato sin cabecera, debe especificar la frecuencia de muestreo con -r si es diferente de 8 kHz. 
		sox_ng infile outfile.cvu rate 28k
		play -r 28k outfile.cvu sinc -3.4k
.dat
Los archivos de datos de texto contienen una representación textual de los datos de muestra. Hay una línea al principio que contiene la frecuencia de muestreo y otra que contiene el número de canales. Las líneas subsiguientes contienen dos o más elementos de datos numéricos: el tiempo desde el inicio de la primera muestra y el valor de la muestra para cada canal.

Los valores se normalizan para que el máximo y el mínimo sean 1 y -1. Este formato de archivo se puede utilizar para crear archivos de datos para programas externos como analizadores FFT o rutinas gráficas. SoX también puede convertir un archivo en este formato de nuevo a uno de los otros formatos.

Ejemplo que contiene solo 2 muestras estéreo de silencio: 

    ; Frecuencia de Muestreo 8012
    ; Canales 2
                0	0	0
    0.00012481278	0	0

Formato DFPWM1a.

.dff
El formato de Archivo de Intercambio de Flujo Digital Directo (DSDIFF) es un formato definido por Philips para almacenar datos DSD de 1 bit, utilizado en la masterización SACD y ocasionalmente para la distribución en línea.
.dts (con ffmpeg)
Formato Digital Theatre Systems.

SoX solo puede autodetectar este tipo de archivo por su extensión; si se lee desde la `entrada estándar' (stdin) o desde un archivo cuyo nombre no termina en `.dts', deberá prefijarlo con -t ffmpeg .

Otro nombre para .mov .

Ver .paf .
ffmpeg (opcional)
Este es un pseudotipo que utiliza el programa externo ffmpeg si está instalado. Solo puede leer archivos, no escribirlos, y extraerá la pista de sonido de muchos formatos de archivo de vídeo. ffmpeg deduce el tipo de archivo real a partir del contenido del archivo con un algoritmo mucho más avanzado que el utilizado por SoX, que solo reconoce hasta dos secuencias de bytes fijas en posiciones fijas.
.flac (opcional; también con -t sndfile o -t ffmpeg)
Códec de Audio Libre y sin Pérdidas (FLAC) comprimido de Xiph.org. FLAC es un códec abierto y libre de patentes diseñado para comprimir música. Es similar a MP3 y Ogg Vorbis pero sin pérdidas, por lo que el audio se comprime sin pérdida de calidad.

SoX puede leer archivos FLAC nativos (.flac) pero solo puede leer archivos FLAC Ogg ( .oga ) si ffmpeg está instalado.

Consulte .ogg a continuación para obtener información sobre el soporte de archivos Ogg Vorbis.

SoX puede escribir archivos FLAC nativos según un nivel de compresión dado o predeterminado. 8 es el nivel de compresión predeterminado y proporciona la mejor (pero más lenta) compresión; 0 da la menor (pero más rápida) compresión. El nivel de compresión se selecciona utilizando la opción -C (consulte sox_ng(1) ) con un número entero de 0 a 8.

Formato de Vídeo Flash de Macromedia.
.fssd
Formato de Datos Flexible Sound Studio, un formato crudo que por defecto es .u8 a 8 kHz.

Archivos de tono de llamada Grandstream. Si bien este formato de archivo puede contener audio codificado en A-Law, μ-law, GSM, G.722, G.723, G.726, G.728 o iLBC, SoX admite la lectura y escritura solo de A-Law y μ-law. Por ejemplo: 
   sox_ng music.wav -t gsrt ring.bin
   play ring.bin
.gsm (opcional; también con -t sndfile o -t ffmpeg))
Compresión de Voz con Pérdidas GSM 06.10. Un formato con pérdidas para comprimir voz que se utiliza en el Estándar Global para Telecomunicaciones Móviles (GSM). Es bueno para su propósito, reduciendo el tamaño de los datos de audio, pero introducirá mucho ruido cuando una señal de audio se codifique y decodifique varias veces. Este formato es utilizado por algunas aplicaciones de correo de voz y consume bastante CPU.

.mp1, .m1a, .mp2 (opcional, también con -t sndfile o -t ffmpeg)
Audio comprimido MP1, MP2 y MP3 (MPEG 1 Capas 1, 2 y 3) forman parte de los estándares MPEG para compresión de audio y video cuyas patentes han expirado. Son formatos de compresión con pérdida que logran buenas tasas de compresión con poca pérdida de calidad.

libmad, que SoX utiliza para decodificar archivos MPEG, no funciona en archivos con una tasa de bits superior a 192K, pero puedes leerlos con -t sndfile o -t ffmpeg.

SoX utiliza twolame para escribir archivos MP2, y la tasa de bits de destino se establece usando la opción -C en kbps: 32, 48, 56, 64, 80, 96, 112, 128, 160 o 192 para una tasa de bits constante (CBR) para archivos mono y el doble para estéreo. La codificación con tasa de bits variable (VBR) se selecciona mediante valores de −50 a 50 (de los cuales solo se dice que −10 a 10 son útiles); si realmente quieres VBR con calidades 32 o 48, usa algo como 32.01 o 48.01.

Desafortunadamente, twolame genera 0.005 segundos de silencio basura al principio y trunca el final en 0.002 segundos.

SoX no solo puede leer archivos MP1, sino que tampoco puede escribirlos.

.mp3 (opcional, también con -t sndfile o -t ffmpeg)
SoX utiliza libmad para decodificar archivos MP3; para decodificar usando libmpg123, que generalmente ofrece mejores resultados de calidad y es mejor decodificando archivos dañados o corruptos, usa -t sndfile, mientras que -t ffmpeg usa otro decodificador MPEG, `mpglib'.

SoX decodifica archivos MP2 y MP3 con una precisión de 28 bits pero por defecto declara una precisión de 16 bits, de modo que la decodificación de MP3 a WAV proporciona la calidad de CD que la mayoría de la gente espera. Puedes especificar una precisión mayor para el archivo de salida para conservar esta información adicional.

SoX utiliza liblame al escribir archivos MP3 y puede usar hasta 25 bits de precisión.

Actualmente, el uso de liblame por parte de SoX añade 0.01 segundos de silencio basura al principio y al final; la codificación con -t sndfile ajusta la longitud y no genera basura.

Los parámetros de compresión MP3 se pueden seleccionar usando la opción -C de SoX de la siguiente manera:

El parámetro principal del codificador LAME MP3 es la tasa de bits. Si el valor de la opción -C es un entero positivo, se toma como la tasa de bits en kbps (por ejemplo, si especificas 128, usa 128 kbps).

El segundo parámetro más importante es la "calidad", que permite equilibrar la velocidad de codificación frente a la calidad. En LAME, 0 especifica la máxima calidad pero es muy lento, mientras que 9 selecciona una calidad pobre, pero es rápido. (5 es el valor predeterminado y se recomienda 2 como un buen compromiso para codificaciones de alta calidad).

Dado que el valor de -C es un número flotante, la parte fraccionaria se usa para seleccionar la calidad. 128.2 selecciona codificación de 128 kbps con una calidad de 2. Hay un problema con este enfoque. Necesitamos 128 para especificar codificación de 128 kbps con calidad predeterminada, por lo que 0 significa usar la predeterminada. En lugar de 0, tienes que usar .01 (o .99) para especificar la calidad más alta o más baja (128.01 o 128.99).

LAME usa la tasa de bits para especificar una tasa de bits constante, pero se puede lograr una mayor calidad usando Tasa de Bits Variable (VBR). La calidad de VBR (realmente el tamaño) se selecciona con un número de 0 a 9. Usa un valor de 0 para alta calidad, archivos más grandes y 9 para archivos más pequeños de menor calidad. 4 es el valor predeterminado.

Para incorporar la selección de VBR en el valor de -C, usamos números negativos para seleccionar VBR. -4.2 seleccionaría codificación VBR predeterminada (tamaño) con alta calidad (velocidad). Un caso especial es 0, que es un parámetro de codificación VBR válido pero no una tasa de bits válida. El valor de compresión 0 siempre se trata como VBR de alta calidad, como resultado tanto -0.2 como 0.2 se tratan como VBR de máxima calidad (tamaño) y alta calidad (velocidad).

TXW es un formato de archivo del teclado sampler Yamaha TX-16W que escribía muestras en disquetes de formato IBM/PC de 3,5" a frecuencias de muestreo de 16 kHz, 33 kHz y 50 kHz, todos divisores exactos de 100 kHz. Cuando se decodifican a archivos WAV u otros formatos que solo representan frecuencias de muestreo enteras, se declaran como 16667 y 33333, pero en archivos WAV el campo de tasa de bytes es incorrecto con 66667.

SoX maneja la lectura de archivos que no tienen el campo de tasa de muestreo configurado en una de las tasas esperadas mirando otros bytes en los campos de longitud de ataque/bucle y por defecto a 33 kHz si la tasa de muestreo aún es desconocida.

.voc (también con -t sndfile o -t ffmpeg)
Los archivos VOC de Sound Blaster son multiparte y contienen partes de silencio, bucles y diferentes frecuencias de muestreo para diferentes bloques. En la entrada, se rellenan las partes de silencio, se rechazan los bucles y se rechazan los datos de muestra con una nueva frecuencia de muestreo. Se genera silencio con una frecuencia de muestreo diferente de forma apropiada. En la salida, no se detecta silencio ni frecuencias de muestreo imposibles. .vox
Los archivos sin encabezado de datos de audio ADPCM Dialogic/OKI suelen venir con la extensión .vox. Estos datos ADPCM tienen una precisión de 12 bits empaquetada en solo 4 bits.

Nota: algún hardware Dialogic temprano no reinicia siempre el codificador ADPCM al principio de cada archivo vox. Esto puede resultar en problemas de recorte y/o desplazamiento DC al decodificar el audio. Aunque hay poco que se pueda hacer sobre el recorte, un desplazamiento DC se puede eliminar pasando el audio decodificado a través de un filtro pasa-altos, por ejemplo:

	sox_ng input.vox output.wav highpass 10
.w64 (con sndfile, también con -t ffmpeg)
Formato RIFF/WAV de 64 bits de Sonic Foundry.

SoX solo puede autodetectar este tipo de archivo por su extensión de nombre de archivo; si se lee desde la `entrada estándar' (stdin) o desde un archivo cuyo nombre no termina en `.w64', deberá prefijarlo con `-t w64'.

.wav (también con -t sndfile o -t ffmpeg)
Los archivos RIFF .WAV de Microsoft son el formato de archivo de audio nativo de Windows y se usan ampliamente para audio sin comprimir.

Normalmente, los archivos .wav tienen toda la información de formato en sus encabezados, por lo que normalmente no se necesita especificar opciones de formato para los archivos de entrada. Si se hace, anulan el encabezado del archivo y se le advertirá de ello. Las opciones de formato de salida provocarán una conversión de formato y el .wav se escribirá apropiadamente.

SoX puede leer y escribir muestras codificadas en PCM lineal, punto flotante, μ-law, A-law, MS ADPCM e IMA (o DVI) ADPCM. Los archivos WAV también pueden contener audio codificado de otras maneras no soportadas actualmente por SoX (por ejemplo, MP3); en algunos casos, dicho archivo aún puede ser leído por SoX anulando el tipo de archivo, por ejemplo:

   play -t mp3 mp3-encoded.wav

De forma nativa, SoX solo puede leer archivos WAV con una profundidad de bits de 8, 16, 24 o 32; los archivos con otras profundidades de bits pueden ser leídos prefijándolos con -t sndfile.

También se admiten versiones big-endian de archivos RIFF, llamadas RIFX. Para escribir un archivo RIFX, use la opción de archivo de salida -B.

Ver también .wavpcm.

waveaudio (opcional)
El controlador de dispositivos de audio nativo de MS-Windows. Ejemplos: 
	sox_ng infile -t waveaudio
	sox_ng infile -t waveaudio default
	sox_ng infile -t waveaudio 1
	sox_ng infile -t waveaudio "High Definition Audio Device"
Si se omite el nombre del dispositivo, se usa -1 o default, se obtiene el dispositivo `Microsoft Wave Mapper'. Wave Mapper significa `usar los dispositivos de audio predeterminados del sistema' y puede controlar lo que significa `predeterminado' a través del Panel de Control del sistema operativo.

Si el nombre del dispositivo dado es otro número, se obtiene ese dispositivo de audio por su índice, por lo que grabar con el nombre de dispositivo 0 obtendría el primer dispositivo de entrada (quizás el micrófono), 1 obtendría el segundo (quizás línea de entrada), etc. La reproducción usando el nombre de dispositivo 0 obtendría el primer dispositivo de salida (generalmente el único dispositivo de audio).

Si el nombre del dispositivo dado es algo distinto de un número, SoX intenta compararlo (hasta un máximo de 31 caracteres) con los nombres de los dispositivos disponibles.

.wavpcm
Una variante no estándar pero ampliamente utilizada de .wav. Algunas aplicaciones no pueden leer un encabezado de archivo WAV estándar para datos codificados en PCM con un tamaño de muestra superior a 16 bits o con más de dos canales, pero pueden leer un encabezado WAV no estándar. Es probable que dichas aplicaciones se actualicen eventualmente para soportar el encabezado estándar, pero mientras tanto, este formato de SoX puede usarse para crear archivos con el encabezado no estándar que deberían funcionar con estas aplicaciones. SoX detectará y leerá automáticamente archivos WAV con un encabezado no estándar.

El uso más común de este tipo de archivo es probablemente el siguiente:

	sox_ng infile.any -t wavpcm -e signed-integer outfile.wav
