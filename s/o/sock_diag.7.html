sock_diag(7) Manual de información miscelánea sock_diag(7)

NOMBRE

sock_diag - obtener información sobre sockets

SINOPSIS

#include <sys/socket.h>
#include <linux/sock_diag.h>
#include <linux/unix_diag.h> /* para sockets de dominio UNIX */
#include <linux/inet_diag.h> /* para sockets IPv4 e IPv6 */
diag_socket = socket(AF_NETLINK, tipo_socket, NETLINK_SOCK_DIAG);

DESCRIPCIÓN

El subsistema netlink sock_diag proporciona un mecanismo para obtener información sobre sockets de varias familias de direcciones del kernel. Este subsistema puede ser utilizado para obtener información sobre sockets individuales o solicitar una lista de sockets.

En la solicitud, el llamante puede especificar información adicional que le gustaría obtener sobre el socket, por ejemplo, información de memoria o información específica de la familia de direcciones.

Al solicitar una lista de sockets, el llamante puede especificar filtros que serán aplicados por el kernel para seleccionar un subconjunto de sockets a reportar. Por ahora, solo existe la capacidad de filtrar sockets por estado (conectado, escuchando, etc.).

Tenga en cuenta que sock_diag solo reporta aquellos sockets que tienen un nombre; es decir, sockets enlazados explícitamente con bind(2) o sockets que fueron enlazados automáticamente a una dirección (por ejemplo, mediante connect(2)). Este es el mismo conjunto de sockets que está disponible a través de /proc/net/unix, /proc/net/tcp, /proc/net/udp, y similares.

Solicitud

La solicitud comienza con un encabezado struct nlmsghdr descrito en netlink(7) con el campo nlmsg_type establecido a SOCK_DIAG_BY_FAMILY. Le sigue un encabezado específico para la familia de direcciones que comienza con una parte común compartida por todas las familias de direcciones:


struct sock_diag_req {
    __u8 sdiag_family;
    __u8 sdiag_protocol;
};

Los campos de esta estructura son los siguientes:

sdiag_family
Una familia de direcciones. Debe establecerse en la constante AF_* apropiada.
sdiag_protocol
Depende de sdiag_family. Debe establecerse en la constante IPPROTO_* apropiada para AF_INET y AF_INET6, y en 0 en caso contrario.

Si el campo nlmsg_flags del encabezado struct nlmsghdr tiene la bandera NLM_F_DUMP establecida, significa que se está solicitando una lista de sockets; de lo contrario, es una consulta sobre un socket individual.

Respuesta

La respuesta comienza con un encabezado struct nlmsghdr y le sigue una matriz de objetos específicos para la familia de direcciones. La matriz debe accederse con las macros estándar NLMSG_* de la API de netlink(3).

Cada objeto es una lista NLA (atributos netlink) que debe accederse con las macros RTA_* de la API de rtnetlink(3).

Sockets de dominio UNIX

Para los sockets de dominio UNIX, la solicitud se representa en la siguiente estructura:


struct unix_diag_req {
    __u8    sdiag_family;
    __u8    sdiag_protocol;
    __u16   pad;
    __u32   udiag_states;
    __u32   udiag_ino;
    __u32   udiag_show;
    __u32   udiag_cookie[2];
};

Los campos de esta estructura son los siguientes:

sdiag_family
La familia de direcciones; debe establecerse en AF_UNIX.

sdiag_protocol

pad
Estos campos deben establecerse en 0.
udiag_states
Esta es una máscara de bits que define un filtro de estados de sockets. Solo se reportarán aquellos sockets cuyos estados estén en esta máscara. Se ignora al consultar un socket individual. Los valores soportados son:
1 << TCP_ESTABLISHED

1 << TCP_LISTEN

udiag_ino
Este es un número de inodo al consultar un socket individual. Se ignora al consultar una lista de sockets.
udiag_show
Este es un conjunto de banderas que definen qué tipo de información reportar. Cada tipo de información solicitada se reporta como un atributo netlink como se describe a continuación:
UDIAG_SHOW_NAME
El atributo reportado en respuesta a esta solicitud es UNIX_DIAG_NAME. La carga útil asociada con este atributo es la ruta del archivo a la que el socket fue enlazado (una secuencia de bytes de hasta el tamaño UNIX_PATH_MAX).
UDIAG_SHOW_VFS
El atributo reportado en respuesta a esta solicitud es UNIX_DIAG_VFS. La carga útil asociada con este atributo se representa en la siguiente estructura:

struct unix_diag_vfs {
    __u32 udiag_vfs_dev;
    __u32 udiag_vfs_ino;
};

Los campos de esta estructura son los siguientes:
udiag_vfs_dev
El número de dispositivo del inodo del socket correspondiente en disco.
udiag_vfs_ino
El número de inodo del inodo del socket correspondiente en disco.
UDIAG_SHOW_PEER
El atributo reportado en respuesta a esta solicitud es UNIX_DIAG_PEER. La carga útil asociada con este atributo es un valor __u32 que es el número de inodo del par. Este atributo se reporta solo para sockets conectados.
UDIAG_SHOW_ICONS
El atributo reportado en respuesta a esta solicitud es UNIX_DIAG_ICONS. La carga útil asociada con este atributo es una matriz de valores __u32 que son los números de inodo de los sockets que han pasado la llamada connect(2), pero aún no han sido procesados con accept(2). Este atributo se reporta solo para sockets en escucha.
UDIAG_SHOW_RQLEN
El atributo reportado en respuesta a esta solicitud es UNIX_DIAG_RQLEN. La carga útil asociada con este atributo se representa en la siguiente estructura:

struct unix_diag_rqlen {
    __u32 udiag_rqueue;
    __u32 udiag_wqueue;
};

Los campos de esta estructura son los siguientes:
udiag_rqueue
Para sockets en escucha: el número de conexiones pendientes. El tamaño de la matriz asociada con el atributo de respuesta UNIX_DIAG_ICONS es igual a este valor.
Para sockets establecidos: la cantidad de datos en la cola entrante.
udiag_wqueue
Para sockets en escucha: el tamaño del backlog, que es igual al valor pasado como segundo argumento a listen(2).
Para sockets establecidos: la cantidad de memoria disponible para enviar.
UDIAG_SHOW_MEMINFO
El atributo reportado en respuesta a esta solicitud es UNIX_DIAG_MEMINFO. La carga útil asociada con este atributo es una matriz de valores __u32 descrita a continuación en la subsección "Información de memoria del socket".

NAME

ss - show socket information

SYNOPSIS

ss [ -a-h-m-n-o-p-t-u-x ] [ filter ]

ss [OPTIONS] [[FILTER]

DESCRIPTION

This utility is used to investigate sockets. It can display information about both TCP and UDP, SCTP, and UNIX domain sockets that are used by the system. The ss utility is intended as a simpler, more informative replacement for programs like netstat(8). The output of ss can be quite verbose, so this manual page omits some of the less common options and detailed explanations of the output fields.

OPTIONS

-a, --all
Display all sockets. Without this option only active sockets are displayed.
-h, --help
Print a help message and exit.
-m, --memory
Show socket memory usage.
-n, --numeric
Do not try to resolve service names.
-o, --options
Display timer information.
-p, --processes
Display the process (pid/name) owning the socket.
-t, --tcp
Display TCP sockets.
-u, --udp
Display UDP sockets.
-x, --unix
Display UNIX domain sockets.

FILTER

A filter is a boolean expression allowing to select sockets to display. It is composed of one or more of the following primitives, combined with boolean operators:

family
Selects sockets of a given address family.
state
Selects sockets in a specific state.
port
Selects sockets with a specific port.
host
Selects sockets with a specific address.

The available operators are:

and, or, not
Boolean operators.
( expression )
Group expressions.

Address family and protocol

The address family and protocol are specified using the following constants:

AF_UNIX
UNIX domain sockets.
AF_INET
IPv4 sockets.
AF_INET6
IPv6 sockets.
IPPROTO_TCP
TCP protocol.
IPPROTO_UDP
UDP protocol.

Socket state

The state of a TCP socket is described by the following constants:

TCP_ESTABLISHED
The socket is established.
TCP_LISTEN
The socket is listening for incoming connections.
TCP_CLOSE_WAIT
The remote end has shut down; waiting for the local end to close.
TCP_SYN_SENT
The local end has initiated a connection.
TCP_SYN_RECV
The local end received initial connection request.
TCP_FIN_WAIT1
The local end has closed the connection, and the socket is waiting for a FIN from the remote end.
TCP_FIN_WAIT2
The socket is waiting for a FIN from the remote end.
TCP_CLOSING
Both sides have initiated a connection shutdown.
TCP_LAST_ACK
The local end has shut down; it is waiting for all outstanding data to be sent and for an ACK from the remote end.
TCP_TIME_WAIT
The local end has shut down and the socket is waiting for all outstanding data to be sent and acknowledged.

The state of a UNIX domain socket is described by the following constants:

UNIX_LISTEN
The socket is listening for incoming connections.
UNIX_CONNECTED
The socket is connected.
UNIX_DISCONNECTED
The socket is disconnected.

The state of a UDP socket is described by the following constants:

UDP_BOUND
The socket is bound to an address and port.
UDP_CONNECTED
The socket is connected to a remote address and port.

Socket options

The following options can be used to filter sockets based on specific criteria:

UNIX_DIAG_QUERY_V0
Query for UNIX domain sockets.
UNIX_DIAG_SHUTDOWN
The payload associated with this attribute is __u8 value which represents bits of shutdown(2) state.

udiag_cookie

This is an array of opaque identifiers that could be used along with udiag_ino to specify an individual socket. It is ignored when querying for a list of sockets, as well as when all its elements are set to -1.

The response to a query for UNIX domain sockets is represented as an array of


struct unix_diag_msg {
    __u8    udiag_family;
    __u8    udiag_type;
    __u8    udiag_state;
    __u8    pad;
    __u32   udiag_ino;
    __u32   udiag_cookie[2];
};

followed by netlink attributes.

The fields of this structure are as follows:

udiag_family
This field has the same meaning as in struct unix_diag_req.
udiag_type
This is set to one of SOCK_PACKET, SOCK_STREAM, or SOCK_SEQPACKET.
udiag_state
This is set to one of TCP_LISTEN or TCP_ESTABLISHED.
pad
This field is set to 0.
udiag_ino
This is the socket inode number.
udiag_cookie
This is an array of opaque identifiers that could be used in subsequent queries.

IPv4 and IPv6 sockets

For IPv4 and IPv6 sockets, the request is represented in the following structure:


struct inet_diag_req_v2 {
    __u8    sdiag_family;
    __u8    sdiag_protocol;
    __u8    idiag_ext;
    __u8    pad;
    __u32   idiag_states;
    struct inet_diag_sockid id;
};

where struct inet_diag_sockid is defined as follows:


struct inet_diag_sockid {
    __be16  idiag_sport;
    __be16  idiag_dport;
    __be32  idiag_src[4];
    __be32  idiag_dst[4];
    __u32   idiag_if;
    __u32   idiag_cookie[2];
};

The fields of struct inet_diag_req_v2 are as follows:

sdiag_family
This should be set to either AF_INET or AF_INET6 for IPv4 or IPv6 sockets respectively.
sdiag_protocol
This should be set to one of IPPROTO_TCP, IPPROTO_UDP, or IPPROTO_UDPLITE.
idiag_ext
This is a set of flags defining what kind of extended information to report. Each requested kind of information is reported back as a netlink attribute as described below:
INET_DIAG_TOS
The payload associated with this attribute is a __u8 value which is the TOS of the socket.
INET_DIAG_TCLASS
The payload associated with this attribute is a __u8 value which is the TClass of the socket. IPv6 sockets only. For LISTEN and CLOSE sockets, this is followed by INET_DIAG_SKV6ONLY attribute with associated __u8 payload value meaning whether the socket is IPv6-only or not.
INET_DIAG_MEMINFO
The payload associated with this attribute is represented in the following structure:

struct inet_diag_meminfo {
    __u32 idiag_rmem;
    __u32 idiag_wmem;
    __u32 idiag_fmem;
    __u32 idiag_tmem;
};

The fields of this structure are as follows:
idiag_rmem
The amount of data in the receive queue.
idiag_wmem
The amount of data that is queued by TCP but not yet sent.
idiag_fmem
The amount of memory scheduled for future use (TCP only).
idiag_tmem
The amount of data in send queue.
INET_DIAG_SKMEMINFO
The payload associated with this attribute is an array of __u32 values described below in the subsection "Socket memory information".
INET_DIAG_INFO
The payload associated with this attribute is specific to the address family. For TCP sockets, it is an object of type struct tcp_info.
INET_DIAG_CONG
The payload associated with this attribute is a string that describes the congestion control algorithm used. For TCP sockets only.
pad
This should be set to 0.
idiag_states
This is a bit mask that defines a filter of socket states. Only those sockets whose states are in this mask will be reported. Ignored when querying for an individual socket.
id
This is a socket ID object that is used in dump requests, in queries about individual sockets, and is reported back in each response. Unlike UNIX domain sockets, IPv4 and IPv6 sockets are identified using addresses and ports. All values are in network byte order.

The fields of struct inet_diag_sockid are as follows:

idiag_sport
The source port.
idiag_dport
The destination port.
idiag_src
The source address.
idiag_dst
The destination address.
idiag_if
The interface number the socket is bound to.
idiag_cookie
This is an array of opaque identifiers that could be used along with other fields of this structure to specify an individual socket. It is ignored when querying for a list of sockets, as well as when all its elements are set to -1.

The response to a query for IPv4 or IPv6 sockets is represented as an array of


struct inet_diag_msg {
    __u8    idiag_family;
    __u8    idiag_state;
    __u8    idiag_timer;
    __u8    idiag_retrans;
    struct inet_diag_sockid id;
    __u32   idiag_expires;
    __u32   idiag_rqueue;
    __u32   idiag_wqueue;
    __u32   idiag_uid;
    __u32   idiag_inode;
};

followed by netlink attributes.

The fields of this structure are as follows:

idiag_family
This is the same field as in struct inet_diag_req_v2.
idiag_state
This denotes socket state as in struct inet_diag_req_v2.
idiag_timer
For TCP sockets, this field describes the type of timer that is currently active for the socket. It is set to one of the following constants:
0
no timer is active
1
a retransmit timer
2
a keep-alive timer
3
a TIME_WAIT timer
4
a zero window probe timer
For non-TCP sockets, this field is set to 0.
idiag_retrans
For idiag_timer values 1, 2, and 4, this field contains the number of retransmits. For other idiag_timer values, this field is set to 0.
idiag_expires
For TCP sockets that have an active timer, this field describes its expiration time in milliseconds. For other sockets, this field is set to 0.
idiag_rqueue
For listening sockets: the number of pending connections.
For other sockets: the amount of data in the incoming queue.
idiag_wqueue
For listening sockets: the backlog size.
For other sockets: the amount of memory available for sending.
idiag_uid
This is the socket owner UID.
idiag_inode
This is the socket inode number.

Socket memory information

The payload associated with UNIX_DIAG_MEMINFO and INET_DIAG_SKMEMINFO netlink attributes is an array of the following __u32 values:

SK_MEMINFO_RMEM_ALLOC
The amount of data in receive queue.
SK_MEMINFO_RCVBUF
The receive socket buffer as set by SO_RCVBUF.
SK_MEMINFO_WMEM_ALLOC
The amount of data that is queued by TCP but not yet sent.
SK_MEMINFO_WND
The current send window size.
SK_MEMINFO_Forward xmit
The amount of data currently being transmitted.
SK_MEMINFO_Forward xmit alloc
The total amount of memory allocated for transmission.

EXAMPLES

To display all TCP sockets:

ss -t -a

To display all listening TCP sockets:

ss -t -l

To display process information for all TCP sockets:

ss -t -p

To display all UDP sockets:

ss -u -a

To display all UNIX domain sockets:

ss -x -a

To display all established TCP sockets:

ss -t state established

To display all TCP sockets with remote port 80:

ss -t dport = :80

To display all TCP sockets with local port 22:

ss -t sport = :22

To display all TCP sockets with local address 192.168.0.1:

ss -t src 192.168.0.1

To display all TCP sockets with remote address 192.168.0.2:

ss -t dst 192.168.0.2

To display all TCP sockets with local address 192.168.0.1 and remote port 80:

ss -t src 192.168.0.1 dst :80

To display all TCP sockets with local port 80 or remote port 22:

ss -t sport = :80 or dport = :22

To display all TCP sockets that are not in the ESTABLISHED state:

ss -t not state established

DESCRIPTION

The NETLINK_SOCK_DIAG generic netlink family is used to query socket information. Currently, it supports the following protocols:

AF_UNIX
Unix domain sockets. See unix(7).
AF_INET
IP sockets. See ip(7).
AF_INET6
IP v6 sockets. See ipv6(7).

The SOCK_DIAG_BY_FAMILY request is used to dump socket information for a given address family. The request structure is struct sock_diag_req, defined in <linux/sock_diag.h>.

struct sock_diag_req {
    __u8    sdiag_family;
    __u8    sdiag_protocol;
    __u16   __pad;
    __u32   udiag_states;
    __u32   udiag_show;
};

The sdiag_family field specifies the address family (e.g., AF_UNIX, AF_INET, AF_INET6). The sdiag_protocol field can be used to filter by protocol within the address family, or set to 0 to dump all protocols. The udiag_states field is used for protocols that have connection states (e.g., TCP states) and can be set to -1 to dump all states.

The udiag_show field is a bitmask to request specific information about the sockets. The following flags are supported:

UDG_SHOW_PEER
Show peer address information.
UDG_SHOW_NAME
Show socket name (path for AF_UNIX).
UDG_SHOW_UID
Show socket owner's UID.
UDG_SHOW_TIMEOUT
Show socket timeouts.

The response messages contain a header of type SOCK_DIAG_BY_FAMILY followed by a protocol-specific message. For AF_UNIX sockets, the message is of type struct unix_diag_msg.

struct unix_diag_msg {
    __u8    udiag_family;
    __u8    udiag_state;
    __u16   __pad;
    __u32   udiag_ino;
};

The message is followed by attributes containing additional information. The following attributes are supported for AF_UNIX:

UNIX_DIAG_NAME
The socket name (path). The payload is a null-terminated string.
UNIX_DIAG_PEER
The inode number of the peer socket.
UNIX_DIAG_UID
The UID of the socket owner.
UNIX_DIAG_STATE
The socket state. This is currently unused for AF_UNIX.
UNIX_DIAG_FREE
Amount of memory in the socket's receive queue.
UNIX_DIAG_MEMINFO
Socket memory information. The payload is a struct unix_diag_meminfo.
struct unix_diag_meminfo {
    __u32   idiag_mem;
    __u32   idiag_maxmem;
    __u32   idiag_hiwat;
    __u32   idiag_lowat;
    __u32   idiag_mmap_send;
    __u32   idiag_mmap_recv;
    __u32   idiag_wmem_alloc;
    __u32   idiag_rmem_alloc;
    __u32   idiag_wmem_queued;
    __u32   idiag_rmem_queued;
    __u32   idiag_optmem;
    __u32   idiag_backlog;
};

The following constants are used for the fields in struct unix_diag_meminfo:

SK_MEMINFO_RMEM_ALLOC
The amount of memory allocated for the receive queue.
SK_MEMINFO_RMEM_QUEUED
The amount of data queued by the receiver, but not yet processed.
SK_MEMINFO_WMEM_ALLOC
The amount of data in send queue.
SK_MEMINFO_SNDBUF
The send socket buffer as set by SO_SNDBUF.
SK_MEMINFO_FWD_ALLOC
The amount of memory scheduled for future use (TCP only).
SK_MEMINFO_WMEM_QUEUED
The amount of data queued by TCP, but not yet sent.
SK_MEMINFO_OPTMEM
The amount of memory allocated for the socket's service needs (e.g., socket filter).
SK_MEMINFO_BACKLOG
The amount of packets in the backlog (not yet processed).
