NOMBRE

soju - bouncer de IRC

SINOPSIS

soju [opciones...]

DESCRIPCIÓN

soju es un bouncer de IRC fácil de usar. Se conecta a servidores IRC externos en nombre del usuario para proporcionar funcionalidades adicionales.

  • Múltiples usuarios separados compartiendo el mismo bouncer, cada uno con sus propios servidores externos
  • Envío del backlog (mensajes recibidos mientras el usuario estaba desconectado del bouncer), con búferes por cliente

Para conectarse al bouncer, use el nombre de usuario y la contraseña del bouncer. Para usar un cliente que no soporte la extensión IRC de soju.im/bouncer-networks, configure una conexión por cada servidor configurado en soju, e indique el nombre de la red en el nombre de usuario: "<usuario>/<red>". Luego los canales pueden ser unidos y abandonados como si estuviera conectado directamente al servidor externo.

Para que el historial por cliente funcione en clientes que no soportan la extensión IRCv3 chathistory, los clientes deben indicar su nombre. Esto se puede hacer añadiendo un sufijo "@<cliente>" al nombre de usuario.

Al unirse a un canal, el canal se guardará y se unirá automáticamente en la próxima conexión. Al registrarse o autenticarse con NickServ, las credenciales se guardarán y se usarán automáticamente en la próxima conexión si el servidor soporta SASL. Al abandonar un canal con la razón "detach", el canal se desconectará en lugar de ser dejado.

Si una red especificada en el nombre de usuario no existe, y el nombre de la red es un nombre de host válido, la red se añadirá automáticamente.

Cuando todos los clientes están desconectados del bouncer, el usuario se marca automáticamente como ausente por defecto.

soju recargará el archivo de configuración, el certificado/clave TLS y el archivo MOTD cuando reciba la señal HUP. Las opciones de configuración listen, db y log no se pueden recargar.

Los administradores pueden transmitir un mensaje a todos los usuarios del bouncer a través de /notice $<hostname> <texto>, o a través de /notice $* <texto> si la conexión no está vinculada a una red en particular. Todos los usuarios del bouncer conectados actualmente recibirán el mensaje del servicio especial BouncerServ.

OPCIONES

-h, -help

Muestra el mensaje de ayuda y sale.

-config <ruta>

Ruta al archivo de configuración. Si no se establece, se usa un archivo de configuración predeterminado.

-debug

Habilita el registro de depuración (esto filtrará información sensible como contraseñas). Esto puede ser anulado en tiempo de ejecución con el comando de servicio server debug.

-listen <uri>

URI de escucha (predeterminado: ":6697"). Se puede especificar varias veces.

ARCHIVO DE CONFIGURACIÓN

El archivo de configuración tiene una directiva por línea.

Ejemplo:

listen ircs://
tls cert.pem key.pem
hostname example.org

Las siguientes directivas son compatibles:

listen <uri>

URI de escucha (predeterminado: ":6697").

Las siguientes URIs son compatibles:

  • [ircs://][host][:puerto] escucha con TLS sobre TCP (puerto predeterminado si se omite: 6697)
  • irc://localhost[:puerto] escucha con texto plano sobre TCP (puerto predeterminado si se omite: 6667, el host debe ser "localhost")
  • irc+insecure://[host][:puerto] escucha con texto plano sobre TCP (puerto predeterminado si se omite: 6667)
  • unix://<ruta> escucha en un socket de dominio Unix
  • https://[host][:puerto] escucha conexiones HTTPS (puerto predeterminado: 443) y maneja las siguientes solicitudes:
  • /socket para WebSocket
  • /uploads (y subdirectorios) para cargas de archivos
  • http://localhost[:puerto] escucha conexiones HTTP de texto plano (puerto predeterminado: 80, el host debe ser "localhost") y maneja solicitudes como https://
  • http+insecure://[host][:puerto] escucha conexiones HTTP de texto plano (puerto predeterminado: 80) y maneja solicitudes como https:// hace
  • http+unix://<ruta> escucha conexiones HTTP de texto plano en un socket de dominio Unix y maneja solicitudes como https:// hace
  • wss://[host][:puerto] escucha conexiones WebSocket sobre TLS (puerto predeterminado: 443)
  • ws://localhost[:puerto] escucha conexiones WebSocket de texto plano (puerto predeterminado: 80, el host debe ser "localhost")
  • ws+insecure://[host][:puerto] escucha conexiones WebSocket de texto plano (puerto predeterminado: 80)
  • ws+unix://<ruta> escucha conexiones WebSocket de texto plano en un socket de dominio Unix
  • ident://[host][:puerto] escucha conexiones ident de texto plano (puerto predeterminado: 113)
  • http+prometheus://localhost:<puerto> escucha conexiones HTTP de texto plano y sirve métricas de Prometheus (el host debe ser "localhost")
  • http+pprof://localhost:<puerto> escucha conexiones HTTP de texto plano y sirve datos de perfilado de ejecución pprof (el host debe ser "localhost"). Para más información, ver: https://pkg.go.dev/net/http/pprof.
  • unix+admin://[ruta] escucha en un socket de dominio Unix para conexiones administrativas, como sojuctl (ruta predeterminada: /run/soju/admin)

Si se omite el esquema, se asume "ircs". Si se especifican múltiples directivas listen, soju escuchará en cada una de ellas.

hostname <nombre>

Nombre de host del servidor (predeterminado: nombre de host del sistema).

Debería establecerse como un nombre de dominio completo.

title <título>

Título del servidor. Esto se enviará como el valor de ISUPPORT NETWORK cuando los clientes no seleccionen una red específica.

tls <cert> <key>

Habilita el soporte TLS. Los archivos de certificado y clave deben estar codificados en PEM.

db <driver> <fuente>

Establece la ubicación de la base de datos para el almacenamiento de usuarios, redes y canales. Por defecto, se abre una base de datos sqlite3 en "./soju.db".

Controladores soportados:

  • sqlite3 espera que fuente sea una ruta al archivo SQLite
  • postgres espera que fuente sea una lista separada por espacios de parámetros clave=valor, por ejemplo: db postgres "host=/run/postgresql dbname=soju". Nótese que sslmode es require por defecto. Para más información sobre cadenas de conexión, ver: https://pkg.go.dev/github.com/lib/pq#hdr-Connection_String_Parameters.

message-store <driver> [fuente]

Establece la ubicación de la base de datos para los mensajes IRC. Por defecto, se usa db.

Controladores soportados:

  • db almacena mensajes en la base de datos. Se usa un índice de búsqueda de texto completo para acelerar las consultas de búsqueda.
  • fs almacena mensajes en disco, en el mismo formato que ZNC. Se requiere fuente y es la ruta del directorio raíz para la base de datos. Este formato en disco no es completo: algunos mensajes IRCv3 (por ejemplo, TAGMSG) y todas las etiquetas de mensajes se descartan.
  • memory almacena mensajes en memoria. Para cada canal/usuario, solo se conservan los últimos 4K mensajes en memoria, los mensajes más antiguos se descartan. Este controlador es muy básico y no soporta funcionalidades como la extensión chathistory y la búsqueda.

(log es un alias obsoleto para esta directiva.)

file-upload <driver> [fuente]

Establece la ubicación de la base de datos para los archivos subidos.

La carga de archivos requiere configurar un oyente HTTP (ver las URIs https:// y http+insecure:// en la directiva listen).

Controladores soportados:

  • fs almacena archivos subidos en disco. Se requiere fuente.
  • http almacena archivos subidos a través de un servicio HTTP externo. Se requiere fuente y debe ser una URL HTTP. Al recibir un archivo, soju enviará una solicitud HTTP POST a esa URL, enviando el archivo tal cual en el cuerpo de la solicitud HTTP; un

CONFIGURACIÓN

soju utiliza un archivo de configuración para ajustar su comportamiento. Las directivas se leen desde el archivo de configuración en el orden en que aparecen. Los comentarios se introducen con un símbolo de almohadilla (#) y continúan hasta el final de la línea.

Si soju se invoca con un argumento, se intentará usarlo como ruta de archivo de configuración. Si se proporcionan varios archivos, se leerán en orden.

soju [archivo...]

debug true|false

Habilita o deshabilita el registro detallado. Por defecto, está deshabilitado.

log <ruta>

Especifique la ruta de un archivo para registrar mensajes del bouncer. El archivo se creará si no existe. Por defecto, los mensajes se registran en stderr.

pid-file <ruta>

Especifique la ruta de un archivo para escribir el identificador de proceso (PID) del demonio. El archivo se creará si no existe. Por defecto, no se crea ningún archivo PID.

listen <dirección>[:<puerto>]

Escucha las conexiones entrantes en la dirección y el puerto especificados. La dirección puede ser una dirección IP o un nombre de host. Si se omite el puerto, se utiliza el valor predeterminado (6697 para IRC, 700 para IRCs). Se pueden especificar varios argumentos de escucha.

http-listen <dirección>[:<puerto>]

Escucha las conexiones HTTP entrantes en la dirección y el puerto especificados. Por defecto, no se escucha en ningún puerto HTTP. Se pueden especificar varios argumentos de http-listen.

upload-dir <ruta>

Directorio donde se almacenarán los archivos subidos. El directorio se creará si no existe. Por defecto, no se permite la subida de archivos.

http-username <nombre de usuario>

Nombre de usuario para la autenticación HTTP Basic. Requiere que upload-dir esté configurado.

http-password <contraseña>

Contraseña para la autenticación HTTP Basic. Requiere que upload-dir esté configurado.

http-origin <patrones...>

Lista de orígenes HTTP permitidos para los oyentes de WebSocket. Los parámetros se interpretan como patrones de shell, consulte glob(7).

Por defecto, solo se autoriza el host de la solicitud. Use esta directiva para habilitar WebSockets de orígenes cruzados.

http-ingress <url>

URL externa en la que se exponen los oyentes HTTPS.

Por defecto, es https://<hostname>.

accept-proxy-ip <cidr...>

Permite que las IPs especificadas actúen como proxy. Los proxies tienen la capacidad de sobrescribir las direcciones de conexión remota y local (a través del protocolo PROXY, el campo de encabezado HTTP Forwarded definido en RFC 7239 o los campos de encabezado HTTP X-Forwarded-*). El nombre especial "localhost" acepta las direcciones de loopback 127.0.0.0/8 y ::1/128.

Por defecto, se rechazan todas las IPs.

max-user-networks <límite>

Número máximo de redes habilitadas por usuario. Por defecto, no hay límite.

motd <ruta>

Ruta al archivo MOTD. El MOTD del bouncer se envía a los clientes que no están vinculados a una red específica. Por defecto, no se envía ningún MOTD.

upstream-user-ip <cidr...>

Habilita direcciones IP por usuario. Se puede especificar un rango IPv4 y/o un rango IPv6 en notación CIDR. Se asignará una dirección IP por rango a cada usuario y se utilizará como dirección de origen al conectarse a una red upstream.

Esto puede ser útil para evitar que el bouncer completo sea baneado de una red upstream debido a un usuario malicioso.

disable-inactive-user <duración>

Deshabilita a los usuarios inactivos después de la duración especificada.

Un usuario está inactivo cuando se cierra la última conexión downstream.

La duración es un número decimal positivo seguido de la unidad "d" (días). Por ejemplo, "30d" deshabilita a los usuarios 30 días después de que se desconecten por última vez del bouncer.

enable-user-on-auth true|false

Habilita a los usuarios cuando se autentican correctamente.

Esto se puede usar junto con disable-inactive-user para deshabilitar y volver a habilitar usuarios sin problemas durante largos períodos de inactividad.

Cuando se utiliza autenticación externa (por ejemplo, auth oauth2), los usuarios del bouncer se crean automáticamente después de una autenticación exitosa.

auth <driver> ...

Establece el método de autenticación. Por defecto, se utiliza la autenticación interna.

Drivers soportados:

auth internal

Utiliza autenticación interna.
auth http <url>
Utiliza autenticación HTTP Basic externa. Se realiza una solicitud HTTP a la URL, pasando las credenciales del usuario en un encabezado Authorization Basic. Las credenciales se consideran válidas con HTTP 200; inválidas con HTTP 403; y cualquier otro código de error significa que ocurrió un error.
auth oauth2 <url>
Utiliza autenticación OAuth 2.0 externa. Se debe proporcionar la URL del servidor de autorización. El ID de cliente y el secreto del cliente se pueden proporcionar como nombre de usuario y contraseña en la URL. El servidor de autorización debe admitir OAuth 2.0 Authorization Server Metadata (RFC 8414) e OAuth 2.0 Token Introspection (RFC 7662).
auth pam
Utiliza autenticación PAM.

SERVICIO IRC

soju expone un servicio IRC llamado BouncerServ para administrar el bouncer. Los comandos se pueden enviar a través de mensajes privados regulares (/msg BouncerServ <comando> [argumentos...]). Los comandos pueden escribirse en su forma completa o abreviada, por ejemplo, network se puede abreviar como net o simplemente n.

Los comandos se analizan según las reglas del shell POSIX. En particular, las palabras se pueden entrecomillar (con comillas dobles o simples) y una barra invertida escapa al siguiente carácter.

help [comando]

Muestra una lista de comandos. Si se especifica comando, muestra un mensaje de ayuda para el comando.

network create -addr <dirección> [opciones...]

Conéctate a una nueva red en dirección. -addr es obligatorio.

dirección admite varios tipos de conexión:

  • [ircs://]<host>[:puerto] se conecta con TLS sobre TCP
  • irc+insecure://<host>[:puerto] se conecta con TCP de texto plano
  • irc+unix:///<ruta> se conecta a un socket Unix

Por ejemplo, para conectarse a Libera Chat:

net create -addr irc.libera.chat

Otras opciones son:

-name <nombre>

Nombre corto de la red. Se utilizará en lugar de dirección para referirse a la red.

-username <nombre de usuario>

Conéctate con el nombre de usuario especificado. Por defecto, se utiliza el nickname.

-pass <contraseña>

Conéctate con la contraseña del servidor especificada.

-realname <nombre real>

Conéctate con el nombre real especificado. Por defecto, se utiliza el nombre real de la cuenta si está configurado, de lo contrario, se utiliza el nickname de la red.

-certfp <huella digital>

En lugar de utilizar autoridades de certificación para verificar el certificado TLS del servidor, verifica si el certificado del servidor coincide con la huella digital proporcionada. Esto se puede utilizar para conectarse a servidores que utilizan certificados autofirmados. El formato de la huella digital es SHA512. Una cadena vacía elimina cualquier huella digital anterior.

El siguiente comando se puede utilizar para obtener la huella digital del certificado de un servidor IRC:

openssl s_client -connect irc.example.org:6697 -verify_quiet </dev/null | openssl x509 -fingerprint -sha512 -noout -in /dev/stdin

-nick <nickname>

Conéctate con el nickname especificado. Por defecto, se utiliza el nombre de usuario de la cuenta.

-auto-away true|false

Habilita o deshabilita la función de auto-away. Si la función está habilitada, el usuario será marcado como ausente cuando todos los clientes se desconecten del bouncer. Por defecto, auto-away está habilitado.

-enabled true|false

Habilita o deshabilita la red. Si la red está deshabilitada, el bouncer no se conectará a ella. Por defecto, la red está habilitada.

-ignore-limit true|false

Ignora el límite máximo de redes para este comando. Solo los usuarios administradores pueden ignorar el límite.

-connect-command <comando>

Envía la cadena entrecomillada especificada como un comando IRC sin procesar inmediatamente después de conectarse al servidor. Esto se puede utilizar para identificarse en una cuenta cuando el servidor no admite SASL.

Por ejemplo, para identificarse con NickServ, se puede utilizar el siguiente comando:

"PRIVMSG NickServ :IDENTIFY <contraseña>"

El flag se puede especificar varias veces para enviar múltiples mensajes IRC. Para borrar todos los comandos, establécelo en la cadena vacía.

network update [nombre] [opciones...]

Actualiza una red existente. Las opciones son las mismas que en el comando network create.

Cuando se ejecuta este comando, soju se desconectará y se volverá a conectar a la red.

Si no se especifica nombre, se actualiza la red actual.

network delete [nombre]

Desconecta y elimina una red.

Si no se especifica nombre, se elimina la red actual.

network quote [nombre] <comando>

Envía una línea IRC sin procesar tal cual a una red.

Si no se especifica nombre, el comando se envía a la red actual.

network status

Muestra una lista de las redes guardadas y su estado actual.

channel status [opciones...]

Muestra una lista de los canales guardados y su estado actual.

Opciones:

-network <nombre>

Mostrar solo canales para la red especificada. Por defecto, solo se muestran los canales de la red actual.

channel create <nombre> [opciones...]

Únete a un nuevo canal.

Unirse a un canal normalmente debería hacerse con un simple join desde el cliente, pero este comando se puede usar para unir a otro usuario a un canal cuando se usa con user run.

Las opciones son:

-detached true|false

Adjunta o desadjunta este canal.

Un canal desadjunto se une pero es ocultado por el bouncer. Esto es útil para, por ejemplo, recopilar registros y resúmenes en canales de bajo interés o de alto tráfico.

-relay-detached <modo>

Establece cuándo reenviar mensajes de canales desadjuntos al usuario con un NOTICE de BouncerServ.

Los modos son:

message

Reenvía cualquier mensaje de este canal cuando esté desadjunto.

highlight

Reenvía solo los mensajes que te mencionan cuando está desadjunto.

none

No reenvíes ningún mensaje de este canal cuando esté desadjunto.

default

Actualmente igual que highlight. Este es el comportamiento por defecto.

-reattach-on <modo>

Establece cuándo volver a adjuntar automáticamente a canales desadjuntos.

Los modos son:

message

Vuelve a adjuntar a este canal cuando se reciba cualquier mensaje.

highlight

Vuelve a adjuntar a este canal cuando se reciba cualquier mensaje que te mencione.

none

Nunca volver a adjuntar automáticamente a este canal.

default

Actualmente igual que none. Este es el comportamiento por defecto.

-detach-after <duración>

Desadjunta automáticamente este canal después de que haya transcurrido la duración especificada sin recibir ningún mensaje correspondiente a -detach-on.

Ejemplos de valores de duración: 1h30m, 30s, 2.5h.

Establecer este valor en 0 deshabilitará este comportamiento, es decir, este canal nunca se desadjuntará automáticamente. Este es el comportamiento por defecto.

OPTIONS

channel join <channel> [options...]

Join a channel.

Options are:

-autodeath <duration>

Automatically leave the channel after duration seconds of inactivity. duration can be specified in seconds (e.g. 300), or in minutes (e.g. 5m), hours (e.g. 1h), or days (e.g. 1d). A value of 0 disables this feature.

-detach-after <duration>

Automatically detach from the network after duration seconds of inactivity. duration can be specified in seconds (e.g. 300), or in minutes (e.g. 5m), hours (e.g. 1h), or days (e.g. 1d). A value of 0 disables this feature.

-detach-on <mode>

Set when to reset the auto-detach timer used by -detach-after, causing it to wait again for the auto-detach duration timer before detaching. Joining, reattaching, sending a message, or changing any channel option will reset the timer, in addition to the messages specified by the mode.

Modes are:

message

Receiving any message from this channel will reset the auto-detach timer.

highlight

Receiving any message mentioning you from this channel will reset the auto-detach timer.

none

Receiving messages from this channel will not reset the auto-detach timer. Sending messages or joining the channel will still reset the timer.

default

Currently same as message. This is the default behaviour.

channel update <name> [options...]

Update the options of an existing channel. The options are the same as the network create command.

channel delete <name>

Leave and forget a channel.

certfp generate [options...]

Generate self-signed certificate and use it for authentication (via SASL EXTERNAL).

Generates a 3072-bit RSA private key by default.

Note, reconnection to the upstream network is required to use the newly generated certificate.

Options are:

-network <name>

Select a network. By default, the current network is selected, if any.

-key-type <type>

Private key algorithm to use. Valid values are: rsa, ecdsa and ed25519. ecdsa uses the NIST P-521 curve.

-bits <bits>

Size of RSA key to generate. Ignored for other key types.

certfp fingerprint [options...]

Show SHA-1 and SHA-256 fingerprints for the certificate currently used with the network.

Options are:

-network <name>

Select a network. By default, the current network is selected, if any.

sasl status [options...]

Show current SASL status.

Options are:

-network <name>

Select a network. By default, the current network is selected, if any.

sasl set-plain [options...] <username> <password>

Set SASL PLAIN credentials.

Note, reconnection to the upstream network is required to apply the new settings.

Options are:

-network <name>

Select a network. By default, the current network is selected, if any.

sasl reset [options...]

Disable SASL authentication and remove stored credentials.

Note, reconnection to the upstream network is required to apply the new settings.

Options are:

-network <name>

Select a network. By default, the current network is selected, if any.

user status [username]

Show a list of users on this server. Only admins can query this information.

If username is specified, statistics are only displayed for this user.

user create -username <username> -password <password> [options...]

Create a new soju user. Only admin users can create new accounts. The -username and -password flags are mandatory.

Options are:

-username <username>

The bouncer username. This cannot be changed after the user has been created.

-password <password>

The bouncer password.

-disable-password

Disable password authentication. The user will be unable to login.

-admin true|false

Make the new user an administrator.

-nick <nick>

Set the user's nickname. This is used as a fallback if there is no nickname set for a network.

-realname <realname>

Set the user's realname. This is used as a fallback if there is no realname set for a network.

-enabled true|false

Enable or disable the user. If the user is disabled, the bouncer will not connect to any of their networks, and downstream connections will be immediately closed. By default, users are enabled.

-max-networks <max-networks>

Set a limit on the number of enabled networks this user can use. A limit of 0 means no network, and -1 means to default to the global max-user-networks configuration value.

user update [username] [options...]

Update a user. The options are the same as the user create command.

If username is omitted, the current user is updated. Only admins can update other users.

Not all flags are valid in all contexts:

  • The -username flag is never valid, usernames are immutable.
  • The -nick and -realname flag are only valid when updating the current user.
  • The -admin, -enabled and -max_networks flags are only valid when updating another user.

user delete <username> [confirmation token]

Delete a soju user.

Only admins can delete other users.

user run <username> <command...>

Execute a command as another user.

Only admins can use this command.

server status

Show some bouncer statistics. Only admins can query this information.

server notice <message>

Broadcast a notice. All currently connected bouncer users will receive the message from the special BouncerServ service. Only admins can broadcast a notice.

server debug <true|false>

Enable/disable debug logging (this will leak sensitive information). This overrides any value passed to soju in -debug.
