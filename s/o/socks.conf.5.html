SOCKS.CONF(5) Manual de Formatos de Archivos SOCKS.CONF(5)

NOMBRE

socks.conf - sintaxis del archivo de configuración del cliente socks

DESCRIPCIÓN

El archivo de configuración para la biblioteca del cliente socks permite el control sobre el registro y la selección del servidor. Está dividido en dos partes; configuración global y rutas. Una línea puede ser comentada usando el carácter estándar de comentario #.

FORMATO

La configuración global tiene la forma de una palabra clave seguida de dos puntos y el valor.

debug
Establecer este campo a 1 activa la depuración.
logoutput
Este valor controla dónde la biblioteca del cliente envía la salida de registro. Puede ser syslog, stdout, stderr, un nombre de archivo, o una combinación. El valor por defecto es no registrar. Tenga en cuenta que el valor syslog puede entrar en conflicto con el programa que se está usando socks si el programa también usa syslog.
resolveprotocol
El protocolo utilizado para resolver nombres de host. Los valores válidos son udp, tcp y fake. El valor por defecto es udp.
route.badexpire
Cuánto tiempo la marca de "mala" de una ruta permanecerá establecida antes de ser eliminada. Por defecto son 300 segundos.
route.maxfail
Cuántas veces una ruta puede fallar antes de ser marcada como mala. Por defecto es 1.
timeout.connect
El número de segundos que el cliente esperará a que se complete una conexión al servidor proxy. El valor por defecto es 0, lo que indica que el cliente debe usar el valor predeterminado del sistema.

RUTAS

Las rutas se especifican con la palabra clave route. Dentro de un par de paréntesis ({}) un conjunto de palabras clave controlan el comportamiento de la ruta. Cada route puede contener tres especificaciones de dirección; from, to y via. Una ruta se selecciona para una conexión basándose en los valores dentro del bloque route.

Al buscar una ruta que coincida con la solicitud del cliente, la biblioteca primero buscará una ruta direct. Luego una ruta socks_v4, una ruta socks_v5, una ruta http, y por último una ruta upnp.

Dependiendo de cómo esté configurada la biblioteca y las variables de entorno establecidas (ver el manual de socksify(1)), puede haber o no una opción de respaldo automático a una ruta direct generada automáticamente si no se encuentra ninguna otra ruta.

DIRECCIONES
Cada campo de dirección puede consistir en una dirección IP (y donde sea significativo, una máscara de red, separada de la dirección IP por un signo '/'), un nombre de host, un nombre de dominio (designado por el prefijo '.'), o un nombre de interfaz (donde sea significativo). Cada dirección puede ir seguida de un especificador de puerto opcional.
from
La ruta se usa solo para solicitudes que provienen de la dirección dada como valor.
to
La ruta se usa solo para solicitudes que van a la dirección dada como valor.
via
Dirección del servidor proxy que debe usarse como puerta de enlace para la conexión, o el valor especial direct para indicar que la conexión debe ser directa en lugar de pasar por un servidor proxy.

En el caso de upnp, la dirección también puede ser el nombre de la interfaz a utilizar para descubrir el punto de control upnp, si la URL completa del IGD aún no se conoce, o el valor especial broadcast para indicar que el cliente debe transmitir en busca de un router upnp en todas las interfaces de red disponibles.

port
Parámetro para from, to y via. Acepta las palabras clave eq/=, ne/!=, ge/>=, le/<=, gt/>, lt/< seguidas de un número. También se puede dar un rango de puertos como "port <inicio #> - <fin #>", que coincidirá con todos los números de puerto dentro del rango <inicio #> y <fin #>.

Opciones

clientcompatibility
Habilita ciertas opciones para compatibilidad con servidores defectuosos. Los valores válidos son: necgssapi, para compatibilidad con servidores que implementan gssapi al estilo NEC socks.
command
El servidor admite los comandos dados. Los comandos válidos son bind, bindreply, connect, udpassociate y udpreply. El valor por defecto es todos los comandos admitidos por los protocolos establecidos para la ruta.

Se puede usar en lugar de, o para complementar, protocol.

gssapi.enctype
Qué cifrado imponer para la comunicación autenticada con GSSAPI. Los valores posibles son clear, integrity, o confidentiality. El valor por defecto es intentar confidencialidad, pero aceptar lo que sea que el servidor ofrezca excepto clear, ya que clear no es parte del estándar SOCKS GSSAPI.
gssapi.servicename
Qué nombre de servicio usar al involucrar GSSAPI. El valor por defecto es "rcmd".
method
Lista de métodos de autenticación que el cliente admite y cuáles ofrecer al servidor. Los valores actualmente admitidos son none, gssapi y username. El valor por defecto son todos los métodos admitidos.
protocol
Los protocolos que el servidor admite. Los valores admitidos son tcp y udp. El valor por defecto son todos los protocolos admitidos.
proxyprotocol
Los protocolos proxy que el servidor admite. Los valores actualmente admitidos son socks_v4, socks_v5, http y upnp. El valor por defecto es socks_v4 y socks_v5. Tenga en cuenta que si el servidor socks requiere alguna forma de autenticación, debe establecer esto explícitamente a socks_v5, ya que v4 no admite autenticación.

ENTORNO

SOCKS_USERNAME
Usa el valor de SOCKS_USERNAME como nombre de usuario al realizar la autenticación por nombre de usuario.
SOCKS_PASSWORD
Usa el valor de SOCKS_PASSWORD como contraseña al realizar la autenticación por nombre de usuario. No recomendado ya que otros usuarios del sistema podrían ver tu contraseña.
SOCKS_AUTOADD_LANROUTES
Si esta variable está configurada como "no", el cliente no intentará agregar automáticamente rutas directas para todas las direcciones en la LAN. El valor por defecto es agregarlas.
SOCKS_DISABLE_THREADLOCK
Si esta variable está configurada, el cliente no realizará bloqueo de hilos. El valor por defecto es que el cliente intente determinar por sí mismo si la aplicación que se va a socksificar necesita bloqueo de hilos o no.

Algunas variables de entorno adicionales se documentan en socksify(1).
