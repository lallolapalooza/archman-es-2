NOMBRE

socomec_jbus - Driver para UPS Socomec JBUS con conexión serie RS-232 Modbus.

SINOPSIS

socomec_jbus -h

socomec_jbus -a NOMBRE_DISPOSITIVO [OPCIONES]


Nota

Esta página del manual solo documenta las características específicas del hardware del driver socomec_jbus. Para obtener información sobre el driver principal, consulte nutupsdrv(8).

HARDWARE SOPORTADO

Este driver soporta la serie Socomec JBUS, UPS online (doble conversión) con las siguientes características.

1. UPS monofásico y trifásico
2. Conexión: RS-232

Estos suelen venir con una tarjeta de gestión WEB/SNMP Netvision / caja externa a la que sería mejor dar servicio con el driver snmp-ups(8). En caso de que Netvision no esté disponible, puede conectar la UPS directamente a través del puerto serie y usar este driver.

Actualmente, solo se ha probado en el siguiente modelo.

•DIGYS 3/3 15kVA

En teoría, cualquier modelo Socomec JBUS debería funcionar. Debería ser descubierto como "Unknown Socomec JBUS" con un ID numérico que necesitaré para añadirlo a la lista de UPSs soportadas.

Lamentablemente, Socomec solo menciona DELPHYS MX y DELPHYS MX elite en su documentación y tengo el ID de mi propio DIGYS, por lo que es probable que su modelo no sea reconocido pero probablemente funcione en su mayor parte. Por favor, informe de resultados exitosos o fallidos al rastreador de errores o a la lista de correo. Asegúrese de incluir el número de modelo completo de su UPS manualmente en su informe.

socomec_jbus utiliza el proyecto libmodbus, para la implementación de Modbus.

CABLEADO

La UPS tiene un puerto RS-232 que debe conectarse con un cable NULL-modem a un puerto serie de un PC. La UPS probada tiene un conector DB9 hembra, así que si construye el cable usted mismo, tenga en cuenta el tipo de conector para evitar usar cambiadores de género.

RS-232 está soportado en todos los sistemas operativos, ya sea a través de un puerto serie integrado en su ordenador, o utilizando un convertidor externo USB a RS-232. Si planea usar un convertidor USB a RS-232, asegúrese de que esté soportado por su sistema operativo.

INSTALACIÓN

Este driver debería compilarse por defecto si libmodbus y las cabeceras de desarrollo están disponibles. Puede forzar al script de configuración a compilarlo con los siguientes argumentos:

:; ./configure --with-serial=yes --with-modbus=yes

También necesita dar permisos adecuados (R/W) sobre el archivo del dispositivo serie local para permitir que el usuario de tiempo de ejecución del driver NUT acceda a él. Esto puede requerir configuración adicional para scripts de inicio, reglas de udev o upower, para aplicar los derechos en cada arranque — especialmente si sus nodos de dispositivo son rastreados por un sistema de archivos virtual.

Por ejemplo, un convertidor USB a serie puede ser identificado como /dev/ttyACM0 o /dev/ttyUSB0 en Linux, o /dev/ttyU0 en FreeBSD (nota la "U" mayúscula). Un puerto serie integrado puede ser identificado como /dev/ttyS0 en Linux o uno de los nombres /dev/cua* en FreeBSD.

COMANDOS INSTANTÁNEOS

Este driver no soporta (¿todavía?) el envío de comandos a la UPS.

VARIABLES

Este driver no soporta variables de tiempo de ejecución escribibles (ver upsrw(8)): por las mismas razones. Ambas deberían ser triviales de implementar, pero como ya he encontrado una o dos inconsistencias en la documentación, me abstengo de intentarlas.

ERRORES Y BUGS CONOCIDOS

Bueno, es una versión alfa en el mejor de los casos, pero hasta ahora parece que informa del estado de la UPS de forma fiable. Principalmente basado en el trabajo de Yifeng Li <tomli@tomli.me> en el huawei-ups2000(8) en ese mismo árbol de fuentes.

Fallo de lectura en algunas direcciones JBUS

El driver consulta todas las direcciones JBUS documentadas, y es muy posible que su modelo de UPS no soporte una de ellas (por ejemplo, el Digys no soporta la dirección 0x1020 que debería proporcionar el estado actual de la UPS). Esto debería registrarse con LOG_ERR desde modbus_read_input_registers() junto con la dirección que produjo el error.

Datos obsoletos

Bajo ciertas circunstancias, algunos registros pueden devolver valores inválidos y desencadenar un error de "datos obsoletos". Una vez que ha ocurrido un error de datos obsoletos, debería ver mensajes de error similares al ejemplo a continuación en el registro del sistema.

socomec_jbus: modbus_read_input_registers(addr:XXXX, count:Z):
    Illegal data address
upsd: Data for UPS [socomec] is stale - check driver
upsd: UPS [socomec] data is no longer stale

Hasta ahora, todos los problemas conocidos han sido corregidos por el autor, pero no se puede descartar uno desconocido. Si ha encontrado problemas de "datos obsoletos" durante el uso normal, por favor, presente un informe de error con los registros completos adjuntos.

Antes de solucionar problemas o informar de un problema, es importante consultar su registro dmesg para ver los eventos de conexión y desconexión de USB para evitar perder tiempo en el driver NUT cuando el problema real es USB. Por ejemplo, si alguien tira del cable del puerto USB, o si un nuevo dispositivo USB se conecta a un host/hub USB que tiene problemas para alimentar sus puertos (común en ordenadores de placa única como Raspberry Pi), o si tiene cables inestables o ruido EMI, el convertidor serie puede desconectarse de USB, al menos brevemente. Esto crea datos obsoletos permanentes, el driver debe reiniciarse (volver a conectar el USB no lo solucionará, ya que el driver sigue usando el dispositivo serie inexistente). Estos problemas de USB generalmente no tienen nada que ver con NUT. Si este es el caso, debe resolver el problema subyacente de USB — compruebe el cable, compruebe el convertidor, pruebe un hub USB alimentado, pruebe un aislador USB de velocidad completa, etc.
