SOCKET(3P) Manual de Programador POSIX SOCKET(3P)

PROLOGO

Esta página del manual forma parte del Manual de Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

socket — crear un punto final de comunicación

SINOPSIS

#include <sys/socket.h>
int socket(int domain, int type, int protocol);

DESCRIPCIÓN

La función socket() crea un socket sin vincular en un dominio de comunicaciones y devuelve un descriptor de archivo que puede ser utilizado en llamadas posteriores que operen en sockets. El descriptor de archivo se asignará según se describe en la Sección 2.14, Asignación de Descriptores de Archivo.

La función socket() toma los siguientes argumentos:

domain
Especifica el dominio de comunicaciones en el que se va a crear un socket.
type
Especifica el tipo de socket que se va a crear.
protocol
Especifica un protocolo particular que se utilizará con el socket. Especificar un protocol de 0 hace que socket() utilice un protocolo predeterminado no especificado adecuado para el tipo de socket solicitado.

El argumento domain especifica la familia de direcciones utilizada en el dominio de comunicaciones. Las familias de direcciones admitidas por el sistema dependen de la implementación.

Las constantes simbólicas que se pueden utilizar para el argumento domain se definen en el archivo de cabecera <sys/socket.h>.

El argumento type especifica el tipo de socket, que determina la semántica de la comunicación a través del socket. Los siguientes tipos de socket están definidos; las implementaciones pueden especificar tipos de socket adicionales:

SOCK_STREAM
Proporciona flujos de bytes secuenciados, fiables, bidireccionales y en modo de conexión, y puede proporcionar un mecanismo de transmisión para datos fuera de banda.
SOCK_DGRAM
Proporciona datagramas, que son mensajes no conectados y no fiables de longitud máxima fija.
SOCK_SEQPACKET

Proporciona vías de transmisión de registros secuenciadas, fiables y bidireccionales en modo de conexión. Un registro puede enviarse utilizando una o más operaciones de salida y recibirse utilizando una o más operaciones de entrada, pero una única operación nunca transfiere parte de más de un registro. Los límites de registro son visibles para el receptor a través de la bandera MSG_EOR.

Si el argumento protocol no es cero, especificará un protocolo que sea compatible con la familia de direcciones. Si el argumento protocol es cero, se utilizará el protocolo predeterminado para esta familia de direcciones y tipo. Los protocolos compatibles con el sistema dependen de la implementación.

El proceso puede necesitar tener privilegios adecuados para utilizar la función socket() o para crear algunos sockets.

VALOR DE RETORNO

Al completarse con éxito, socket() devolverá un entero no negativo, el descriptor de archivo del socket. De lo contrario, se devolverá un valor de -1 y se establecerá errno para indicar el error.

ERRORES

La función socket() fallará si:

EAFNOSUPPORT

La implementación no admite la familia de direcciones especificada.
EMFILE
Todos los descriptores de archivo disponibles para el proceso están actualmente abiertos.
ENFILE
No hay más descriptores de archivo disponibles para el sistema.
EPROTONOSUPPORT

El protocolo no es compatible con la familia de direcciones, o el protocolo no es compatible con la implementación.
EPROTOTYPE
El tipo de socket no es compatible con el protocolo.

La función socket() puede fallar si:

EACCES
El proceso no tiene los privilegios adecuados.
ENOBUFS
No había recursos suficientes disponibles en el sistema para realizar la operación.
ENOMEM
No había memoria suficiente disponible para satisfacer la solicitud.

USO DE APLICACIONES

La documentación de las familias de direcciones específicas especifica qué protocolos admite cada familia de direcciones. La documentación de los protocolos específicos especifica qué tipos de socket admite cada protocolo.

La aplicación puede determinar si una familia de direcciones es compatible intentando crear un socket con domain establecido en el protocolo en cuestión.
