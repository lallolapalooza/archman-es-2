socket(n)

Paquete: tcl

Licencias: TCL

socket(n) Comandos integrados de Tcl socket(n)

NOMBRE

socket - Abrir una conexión de red TCP

SINOPSIS

socket ?opciones? host puerto

socket -server comando ?opciones? puerto

DESCRIPCIÓN

Este comando abre un socket de red y devuelve un identificador de canal que puede ser utilizado en futuras invocaciones de comandos como read, puts y flush. En este momento solo se admite el protocolo de red TCP sobre IPv4 e IPv6; futuras versiones pueden incluir soporte para protocolos adicionales. El comando socket puede ser utilizado para abrir el lado cliente o servidor de una conexión, dependiendo de si se especifica el modificador -server.

Tenga en cuenta que la codificación por defecto para *todos* los sockets es la codificación del sistema, tal como se devuelve en encoding system. La mayoría de las veces, necesitará usar chan configure para cambiar esto a otra cosa, como utf-8 (ideal para comunicarse con otros procesos Tcl) o iso8859-1 (útil para muchos protocolos de red, especialmente los más antiguos).

SOCKETS DE CLIENTE

Si no se especifica la opción -server, se abre el lado del cliente de una conexión y el comando devuelve un identificador de canal que puede ser utilizado tanto para leer como para escribir. Puerto y host especifican un puerto al que conectarse; debe haber un servidor aceptando conexiones en este puerto. Puerto es un número de puerto entero (o nombre de servicio, donde es compatible y entendido por el sistema operativo anfitrión) y host es un nombre estilo dominio como www.tcl.tk o una dirección numérica IPv4 o IPv6 como 127.0.0.1 o 2001:DB8::1. Use localhost para referirse al host en el que se invoca el comando.

Las siguientes opciones también pueden estar presentes antes de host para especificar información adicional sobre la conexión:

-myaddr dir
Dir proporciona el nombre estilo dominio o la dirección IP numérica de la interfaz de red del lado del cliente a utilizar para la conexión. Esta opción puede ser útil si la máquina cliente tiene múltiples interfaces de red. Si se omite la opción, el software del sistema elegirá la interfaz del lado del cliente.
-myport puerto
Puerto especifica un número de puerto entero (o nombre de servicio, donde es compatible y entendido por el sistema operativo anfitrión) a utilizar para el lado del cliente de la conexión. Si se omite esta opción, el número de puerto del cliente será elegido al azar por el software del sistema.
-async
Esta opción hará que el socket del cliente se conecte de forma asíncrona. Esto significa que el socket se creará inmediatamente pero puede que aún no esté conectado al servidor cuando la llamada a socket retorne.

Cuando se realiza un gets o flush en el socket antes de que el intento de conexión tenga éxito o falle, si el socket está en modo bloqueante, la operación esperará hasta que la conexión se complete o falle. Si el socket está en modo no bloqueante y se realiza un gets o flush en el socket antes de que el intento de conexión tenga éxito o falle, la operación retorna inmediatamente y fblocked en el socket devuelve 1. Los sockets de cliente síncronos pueden cambiarse (después de que se hayan conectado) a modo asíncrono usando:

chan configure canal -blocking 0

Consulte el comando chan configure para más detalles.

El bucle de eventos de Tcl debe estar en ejecución mientras una conexión asíncrona está en progreso, ya que puede tener que realizar varios intentos de conexión en segundo plano. Ejecutar el bucle de eventos también le permite configurar un evento de canal escribible en el socket para ser notificado cuando la conexión asíncrona haya tenido éxito o fallado. Consulte vwait y los comandos chan para más detalles sobre el bucle de eventos y los eventos de canal.

La opción chan configure -connecting puede ser usada para verificar si la conexión sigue en curso. Para verificar una conexión exitosa, la opción -error puede ser verificada cuando -connecting devolvió 0.

La operación sin la cola de eventos requiere por el momento llamadas a chan configure para avanzar la máquina de estados interna.

SOCKETS DE SERVIDOR

Si se especifica la opción -server, el nuevo socket será un servidor que escucha en el puerto dado (ya sea un entero o un nombre de servicio, donde es compatible y entendido por el sistema operativo anfitrión; si puerto es cero, el sistema operativo asignará un puerto libre al socket servidor que puede ser descubierto usando chan configure para leer la opción -sockname). Si el host soporta ambos, IPv4 e IPv6, el socket escuchará en ambas familias de direcciones. Tcl aceptará automáticamente conexiones al puerto dado. Por cada conexión, Tcl creará un nuevo canal que puede ser usado para comunicarse con el cliente. Tcl luego invoca comando (que debe ser una lista de prefijo de comando, ver los EJEMPLOS abajo) con tres argumentos adicionales: el nombre del nuevo canal, la dirección, en notación de dirección de red, del host del cliente y el número de puerto del cliente.

La siguiente opción adicional también puede ser especificada antes de puerto:

-myaddr dir
Dir proporciona el nombre estilo dominio o la dirección IP numérica de la interfaz de red del lado del servidor a utilizar para la conexión. Esta opción puede ser útil si la máquina del servidor tiene múltiples interfaces de red. Si se omite la opción, el socket del servidor se enlazará a la dirección comodín para que pueda aceptar conexiones desde cualquier interfaz. Si dir es un nombre de dominio que se resuelve a múltiples direcciones IP que están disponibles en la máquina local, el socket escuchará en todas ellas.

Los canales de servidor no pueden ser usados para entrada o salida; su único uso es aceptar nuevas conexiones de clientes. Los canales creados para cada conexión de cliente entrante se abren para entrada y salida. Cerrar el canal del servidor apaga el servidor para que no se acepten nuevas conexiones; sin embargo, las conexiones existentes no se verán afectadas.

Los sockets de servidor dependen del mecanismo de eventos de Tcl para saber cuándo se abren nuevas conexiones. Si la aplicación no entra en el bucle de eventos, por ejemplo, invocando el comando vwait o llamando a la función C Tcl_DoOneEvent, no se aceptarán conexiones.

Si puerto se especifica como cero, el sistema operativo asignará un puerto no utilizado para usarlo como socket de servidor. El número de puerto realmente asignado puede recuperarse del socket de servidor creado usando el comando chan configure para recuperar la opción -sockname, como se describe a continuación.

OPCIONES DE CONFIGURACIÓN

El comando chan configure puede ser usado para consultar varias opciones de configuración de solo lectura para canales de socket:

-error
Esta opción obtiene el estado actual del error del socket dado. Esto es útil cuando necesita determinar si una operación de conexión asíncrona tuvo éxito. Si hubo un error, se devuelve el mensaje de error. Si no hubo error, se devuelve una cadena vacía.

Tenga en cuenta que el estado del error se restablece mediante la operación de lectura; esto imita la llamada subyacente getsockopt(SO_ERROR).

-sockname
Para sockets de cliente (incluidos los canales que se crean cuando un cliente se conecta a un socket de servidor) esta opción devuelve una lista de tres elementos: la dirección, el nombre del host y el número de puerto para el socket. Si no se puede calcular el nombre del host, el segundo elemento es idéntico a la dirección, el primer elemento de la lista.

Para sockets de servidor, esta opción devuelve una lista de un múltiplo de tres elementos, cada grupo de los cuales tiene el mismo significado que se describe anteriormente. La lista contiene más de un grupo cuando el socket del servidor se creó sin -myaddr o con el argumento a -myaddr siendo un nombre de dominio que se resuelve a múltiples direcciones IP que son locales al host invocador.

-peername
Esta opción no es compatible con los sockets del servidor. Para sockets de cliente y aceptados, esta opción devuelve una lista de tres elementos; estos son la dirección, el nombre del host y el puerto al que está conectado o enlazado el socket del par. Si el nombre del host no se puede calcular, el segundo elemento de la lista es idéntico a la dirección, su primer elemento.
-connecting
Esta opción no es compatible con los sockets del servidor. Para sockets de cliente, esta opción devuelve 1 si una conexión asíncrona todavía está en curso, 0 en caso contrario.

EJEMPLOS

Aquí hay un servidor de tiempo muy simple:

proc Server {startTime channel clientaddr clientport} {
    puts "Conexión desde $clientaddr registrada"
    set now [clock seconds]
    puts $channel [clock format $now]
    puts $channel "[expr {$now - $startTime}] desde el inicio"
    close $channel
}
socket -server [list Server [clock seconds]] 9900
vwait forever

Y aquí está el cliente correspondiente para hablar con el servidor y extraer alguna información:

set server localhost
set sockChan [socket $server 9900]
gets $sockChan line1
gets $sockChan line2
close $sockChan
puts "La hora en $server es $line1"
puts "Eso es [lindex $line2 0]s desde que el servidor se inició"
