SOCKATMARK(3P) Manual del programador POSIX SOCKATMARK(3P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

sockatmark — determinar si un socket está en la marca de datos out-of-band

SINOPSIS

#include <sys/socket.h>
int sockatmark(int s);

DESCRIPCIÓN

La función sockatmark() determinará si el socket especificado por el descriptor s se encuentra en la marca de datos out-of-band (consulte la Sección 2.10.12, Estado de los datos out-of-band del socket). Si el protocolo para el socket admite datos out-of-band marcando el flujo con una marca de datos out-of-band, la función sockatmark() devolverá 1 cuando todos los datos precedentes a la marca se hayan leído y la marca de datos out-of-band sea el primer elemento en la cola de recepción. La función sockatmark() no eliminará la marca del flujo.

VALOR DEVUELTO

Al completarse con éxito, la función sockatmark() devolverá un valor que indica si el socket se encuentra en una marca de datos out-of-band. Si el protocolo ha marcado el flujo de datos y se han leído todos los datos que preceden a la marca, el valor devuelto será 1; si no hay marca, o si datos preceden a la marca en la cola de recepción, la función sockatmark() devolverá 0. De lo contrario, devolverá un valor de -1 y establecerá errno para indicar el error.

ERRORES

La función sockatmark() fallará si:

EBADF
El argumento s no es un descriptor de archivo válido.
ENOTTY
El archivo asociado con el argumento s no es un socket.

USO DE LA APLICACIÓN

El uso de esta función entre operaciones de recepción permite a una aplicación determinar qué datos recibidos preceden a los datos out-of-band y cuáles siguen a los datos out-of-band.

Existe una condición de carrera inherente en el uso de esta función. En una cola de recepción vacía, la lectura actual de la ubicación podría estar en la marca, pero el sistema no tiene forma de saber que el siguiente segmento de datos que llegará desde la red llevará la marca, y sockatmark() devolverá falso, y la siguiente operación de lectura consumirá silenciosamente la marca.

Por lo tanto, esta función solo se puede usar de manera fiable cuando la aplicación ya sabe que el sistema ha visto los datos out-of-band o que se sabe que hay datos esperando ser leídos en el socket (a través de SIGURG o select()). Consulte la Sección 2.10.11, Cola de recepción del socket, la Sección 2.10.12, Estado de los datos out-of-band del socket, la Sección 2.10.14, Señales y pselect() para obtener detalles.

FUNDAMENTACIÓN

La función sockatmark() reemplaza el comando histórico SIOCATMARK para ioctl() que implementaba la misma funcionalidad en muchas implementaciones. El uso de una función de envoltorio sigue las convenciones adoptadas para evitar especificar comandos a la función ioctl(), aparte de aquellos ahora incluidos para dar soporte a XSI STREAMS. La función sockatmark() podría implementarse de la siguiente manera:

#include <sys/ioctl.h>
int sockatmark(int s)
{
    int val;
    if (ioctl(s,SIOCATMARK,&val)==-1)
        return(-1);
    return(val);
}

El uso de [ENOTTY] para indicar un tipo de descriptor incorrecto coincide con el comportamiento histórico de SIOCATMARK.
