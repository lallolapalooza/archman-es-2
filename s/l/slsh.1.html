NOMBRE

slsh - Intérprete para scripts S-Lang

SINOPSIS

slsh [ --help ] [ --version ] [ -g ] [ -n ] [ --init archivo ] [ --no-readline ] [ -e cadena ] [ -i ] [ -q, --quiet ] [ -t ] [ -v ] [ -|archivo-script argumentos... ]

DESCRIPCIÓN

slsh es un programa simple para interpretar scripts S-Lang. Soporta la carga dinámica de módulos S-Lang e incluye una interfaz readline para uso interactivo.

OPCIONES

--help
Muestra un resumen de las opciones
--version
Muestra información de la versión de slsh
-g
Compila con código de depuración, trazas, etc.
-n
No carga el archivo de inicialización personal
--init archivo
Usa este archivo en lugar de ~/.slshrc
--no-readline
No usar una interfaz readline para el modo interactivo
-e cadena
Ejecuta ``cadena'' como código S-Lang.
-i
Forzar modo interactivo. Normalmente slsh entrará en modo interactivo si tanto la entrada estándar como la salida estándar están conectadas a una terminal.
-q, --quiet
Inicia en silencio sin imprimir la información de versión y copyright.
-t
Normalmente, slsh llamará a slsh_main si está definida. Esta opción evita que eso suceda, haciéndola útil para verificar errores de sintaxis.
-v
Muestra mensajes de carga detallados. Esto es útil para ver qué archivos se están cargando.

INICIALIZACIÓN

Al iniciar, el programa intentará cargar slsh.rc de la siguiente manera. Si las variables de entorno SLSH_CONF_DIR o SLSH_LIB_DIR existen, entonces slsh buscará en los directorios correspondientes slsh.rc. De lo contrario, buscará en:

$(prefijo)/etc/ (como se especifica en el Makefile)

/usr/local/etc/

/usr/local/etc/slsh/

/etc/

/etc/slsh/

El archivo slsh.rc puede cargar otros archivos del directorio de bibliotecas de slsh de la manera descrita a continuación.

Una vez cargado slsh.rc, slsh cargará $HOME/.slshrc si existe. Finalmente, cargará el script especificado en la línea de comandos. Si el nombre del script es -, entonces se leerá desde la entrada estándar. Si el nombre del script no está presente, o no se especificó una cadena a ejecutar usando la opción -e, entonces slsh entrará en modo interactivo y leerá la entrada de la terminal. Si el script está presente y define una función llamada slsh_main, se llamará a esa función.

CARGA DE ARCHIVOS

Cuando un script carga un archivo a través de la función incorporada evalfile o la función require (cargada automáticamente por slsh.rc), el archivo se busca a lo largo de SLSH_PATH como se especifica en el Makefile. Se puede especificar una ruta alternativa por la variable de entorno SLSH_PATH.

La ruta de búsqueda puede ser consultada y establecida en tiempo de ejecución a través de las funciones get_slang_load_path y set_slang_load_path, por ejemplo,

   set_slang_load_path ("/home/bill/lib/slsh:/usr/share/slsh");

MODO INTERACTIVO

Cuando slsh se invoca sin un script o se le da el argumento de línea de comandos -i, entrará en modo interactivo. En este modo, se le pedirá al usuario que ingrese datos. El programa saldrá de este modo y finalizará si ve un EOF (Ctrl-D) o el usuario sale emitiendo el comando quit.

Si ocurre una excepción no capturada durante la ejecución de un comando, se mostrará el mensaje de error y se le pedirá al usuario más entrada.

Cualquier objeto que quede en la pila después de un comando se imprimirá y la pila se limpiará. Esto hace que el modo interactivo sea útil como una calculadora, por ejemplo,

     slsh> 3*10;
     30
     slsh> x = [1:20];
     slsh> sum (sin(x)-cos(x));
     0.458613
     slsh> quit;
Tenga en cuenta que en este modo, las variables se declaran automáticamente.

El modo interactivo también soporta el registro de comandos. El registro se habilita con la función start_log. La función stop_log desactivará el registro. El archivo predeterminado donde se escribirán los datos de registro es slsh.log. Se puede especificar una alternativa como argumento opcional a la función start_log:

     slsh> start_log;
     Logging input to slsh.log
        .
        .
     slsh> stop_log;
     slsh> start_log("foo.log");
     Logging input to foo.log
        .
        .
     slsh> stop_log;
     slsh> start_log;
     Logging input to foo.log

De manera similar, la función save_input puede usarse para guardar la entrada anterior en un archivo especificado:

     slsh> save_input;
     Input saved to slsh.log
     slsh> save_input ("foo.log");
     Input saved to foo.log

Como indican los ejemplos anteriores, las líneas deben terminar en punto y coma. Esta es una característica básica del lenguaje y permite que los comandos abarquen múltiples líneas, por ejemplo,

     slsh> x = [
            1,2,3,
            4,5,6];
     slsh> sum(x);
Para mayor comodidad, algunos usuarios prefieren que los comandos se terminen automáticamente con un punto y coma. Para que un punto y coma se agregue silenciosamente al final de una línea de entrada, coloque lo siguiente en el archivo $HOME/.slshrc: 
    #ifdef __INTERACTIVE__
    slsh_append_semicolon (1);
    #endif

El modo interactivo también admite escapes del shell. Para pasar un comando al shell, prefíjelo con !, por ejemplo,

    slsh> !pwd
    /grandpa/d1/src/slang2/slsh
    slsh> !cd doc/tm
    slsh> !pwd
    /grandpa/d1/src/slang2/slsh/doc/tm

Finalmente, el modo interactivo admite una función de ayuda y apropos:

    slsh> apropos list
    apropos list ==>
    List_Type
    list_append
    list_delete
       .
       .
    slsh> help list_append
    list_append
     SINOPSIS
       Append an object to a list
     USAGE
       list_append (List_Type, object, Int_Type nth)
       .
       .
Para mayor comodidad, las funciones help y apropos no requieren las restricciones sintácticas de las otras funciones.

MECANISMO DE HISTORIAL DE LECTURA

Por defecto, slsh está compilado para usar la interfaz readline de S-Lang, que incluye una finalización de comandos personalizable y un mecanismo de historial. Cuando slsh (o cualquier aplicación S-Lang que utilice esta característica) se inicia en modo interactivo, buscará un archivo en el directorio de inicio del usuario llamado .slrlinerc y lo cargará si existe. Este archivo permite al usuario personalizar la interfaz readline y habilitar que el historial se guarde entre sesiones. Como ejemplo, aquí hay una versión del archivo .slrlinerc del autor:

     % Load some basic functions that implement the history mechanism
     () = evalfile ("rline/slrline.rc");
     % The name of the history file -- expands to .slsh_hist for slsh
     RLine_History_File = "$HOME/.${name}_hist";
     % Some addition keybindings.  Some of these functions are defined
     % in rline/editfuns.sl, loaded by rline/slrline.rc
     rline_unsetkey ("^K");
     rline_setkey ("bol",   "^B");
     rline_setkey ("eol",   "^E");
     rline_setkey (&rline_kill_eol,  "^L");
     rline_setkey (&rline_set_mark,  "^K^B");
     rline_setkey (&rline_copy_region, "^Kk");
     rline_setkey (&rline_kill_region, "^K^V");
     rline_setkey (&rline_yank,  "^K^P");
     rline_setkey ("redraw",   "^R");
     #ifexists rline_up_hist_search
     % Map the up/down arrow to the history search mechanism
     rline_setkey (&rline_up_hist_search, "\e[A");
     rline_setkey (&rline_down_hist_search, "\e[B");
     #endif
     #ifexists rline_edit_history
     rline_setkey (&rline_edit_history, "^Kj");
     #endif

READLINE HISTORY MECHANISM

     % Add a new function
     private define double_line ()
     {
        variable p = rline_get_point ();
        variable line = rline_get_line ();
        rline_eol ();
        variable pend = rline_get_point ();
        rline_ins (line);
        rline_set_point (pend + p);
     }
    rline_setkey (&double_line,  "^K^L");

MISCELLANEOUS SCRIPTS

Several useful example scripts are located in $prefix/share/slsh/scripts/, where $prefix represents the slsh installation prefix (/usr, /usr/local,...). These scripts include:

sldb
A script that runs the S-Lang debugger.
jpegsize
Reports the size of a jpeg file.
svnsh
A shell for browsing an SVN repository.
