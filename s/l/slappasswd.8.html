SLAPPASSWD(8C) SLAPPASSWD(8C)

NOMBRE

slappasswd - utilidad de contraseñas de OpenLDAP

SINÓPSIS

/usr/bin/slappasswd [-v] [-u] [-g|-s secreto|-T archivo] [-h hash] [-c formato-sal] [-n] [-o opción[=valor]]

DESCRIPCIÓN

Slappasswd se utiliza para generar un valor de userPassword adecuado para usar con ldapmodify(1), la directiva de configuración rootpw de slapd.conf(5) o la directiva de configuración olcRootPW de slapd-config(5).

OPCIONES

-v
habilitar modo detallado.
-u
Generar valores userPassword RFC 2307 (el valor predeterminado). Las versiones futuras de este programa pueden generar sintaxis alternativas por predeterminado. Esta opción se proporciona para compatibilidad futura.
-s secreto
El secreto a codificar. Si este, -g y -T están ausentes, se le pedirá al usuario el secreto a codificar. -s, -g y -T son flags mutuamente excluyentes.
-g
Generar el secreto. Si este, -s y -T están ausentes, se le pedirá al usuario el secreto a codificar. -s, -g y -T son flags mutuamente excluyentes. Si este está presente, {CLEARTEXT} se usa como esquema. -g y -h son flags mutuamente excluyentes.
-T "archivo"
Codificar el contenido del archivo. Si este, -g y -s están ausentes, se le pedirá al usuario el secreto a codificar. -s, -g y -T son flags mutuamente excluyentes.
-h "esquema"
Si se especifica -h, se puede especificar uno de los siguientes esquemas RFC 2307: {CRYPT}, {MD5}, {SMD5}, {SSHA} y {SHA}. El valor predeterminado es {SSHA}.

Tenga en cuenta que los nombres de los esquemas pueden necesitar protección, debido a { y }, contra la expansión por parte del intérprete de comandos del usuario.

{SHA} y {SSHA} usan el algoritmo SHA-1 (FIPS 160-1), el último con una semilla.

{MD5} y {SMD5} usan el algoritmo MD5 (RFC 1321), el último con una semilla.

{CRYPT} usa crypt(3).

{CLEARTEXT} indica que la nueva contraseña debe añadirse a userPassword como texto plano. A menos que se use {CLEARTEXT}, este flag es incompatible con la opción -g.

-c formato-sal-crypt
Especificar el formato de la sal que se pasa a crypt(3) al generar contraseñas {CRYPT}. Esta cadena debe estar en formato sprintf(3) y puede incluir una (y solo una) conversión %s. Esta conversión será sustituida por una cadena de caracteres aleatorios de [A-Za-z0-9./]. Por ejemplo, '%.2s' proporciona una sal de dos caracteres y '$1$%.8s' indica a algunas versiones de crypt(3) que usen un algoritmo MD5 y proporciona 8 caracteres aleatorios de sal. El valor predeterminado es '%s', que proporciona 31 caracteres de sal.
-n
Omitir la nueva línea final; útil para canalizar las credenciales a un comando.
-o opción[=valor]
Especificar una opción con un valor (opcional). Las posibles opciones/valores genéricos son:
              module-path=<rutaespecificación> (ver `modulepath' en slapd.conf(5))
              module-load="<nombrearchivo> [<argumentos>...]" (ver `moduleload' en slapd.conf(5))
Puede cargar un módulo de codificación de contraseñas cargable dinámicamente usando esta opción.

LIMITACIONES

La práctica de almacenar contraseñas codificadas en userPassword viola las especificaciones del esquema Standard Track (RFC 4519) y puede obstaculizar la interoperabilidad. Se ha definido un nuevo tipo de atributo, authPassword, para almacenar contraseñas codificadas (RFC 3112), pero aún no está implementado en slapd(8).

También se debe tener en cuenta que el comportamiento de crypt(3) es específico de la plataforma.

CONSIDERACIONES DE SEGURIDAD

El uso de contraseñas codificadas no protege las contraseñas durante la transferencia del protocolo. Se deben implementar TLS u otras protecciones contra la escucha clandestina antes de usar el bind simple de LDAP.

Los valores de las contraseñas codificadas deben protegerse como si fueran contraseñas de texto plano.
