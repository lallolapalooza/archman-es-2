NOMBRE

slapd.overlays - overlays para slapd, el demonio LDAP autónomo

DESCRIPCIÓN

El demonio slapd(8) puede usar una variedad de overlays diferentes para alterar o extender el comportamiento normal de un backend de base de datos. Los overlays pueden ser compilados estáticamente en slapd, o cuando se habilita el soporte de módulos, pueden ser cargados dinámicamente. La mayoría de los overlays solo se permiten configurar en bases de datos individuales, pero algunos también pueden configurarse globalmente.

Las opciones de configuración para cada overlay se documentan por separado en las páginas del manual correspondientes slapo-<overlay>(5).

accesslog
Registro de Acceso. Este overlay puede registrar accesos a una base de datos dada en otra base de datos.
auditlog
Registro de Auditoría. Este overlay registra cambios en una base de datos dada en un archivo de registro LDIF. Por defecto, no se compila.
autoca
Overlay de Autoridad de Certificación Automática. Este overlay puede generar pares de certificado/clave X.509 para entradas en el directorio si slapd está enlazado a OpenSSL. Por defecto, no se compila.
chain
Encadenamiento. Este overlay permite el seguimiento automático de referencias cuando se devolvería una referencia, ya sea configurado por el servidor o solicitado por el cliente.
collect
Atributos Colectivos. Este overlay implementa los atributos colectivos RFC 3671; estos atributos comparten valores comunes sobre todos los miembros de la colección heredados de una entrada ancestral.
constraint
Restricción. Este overlay aplica una restricción de expresión regular a todos los valores de atributos especificados. Se utiliza para aplicar una sintaxis más rigurosa cuando la sintaxis del atributo subyacente es demasiado general.
dds
Servicios de Directorio Dinámicos. Este overlay soporta objetos dinámicos, que tienen una vida útil limitada después de la cual expiran y se eliminan automáticamente.
deref
Control de Desreferenciación. Este overlay implementa el control de Desreferenciación en borrador. El overlay puede usarse con cualquier backend o globalmente para todos los backends.
dyngroup
Grupo Dinámico. Este es un overlay de demostración que extiende la operación Compare para detectar miembros de un grupo dinámico. No tiene efecto en ninguna otra operación.
dynlist
Lista Dinámica. Este overlay permite la expansión de grupos dinámicos y más.
homedir
Aprovisionamiento de Directorio de Inicio. Este overlay gestiona la creación/eliminación de directorios de inicio para cuentas Unix basadas en LDAP.
memberof
MemberOf. Este overlay mantiene valores automáticos de pertenencia inversa a grupos, típicamente almacenados en un atributo llamado memberOf. Este overlay está obsoleto y debería ser reemplazado por dynlist.
otp
Módulo OATH de Contraseña de Un Solo Uso. Este módulo permite que la contraseña de un solo uso basada en tiempo, también conocida como "estilo autenticador", y la autenticación de contraseña de un solo uso basada en HMAC se utilicen junto con una contraseña LDAP estándar para la autenticación de dos factores.
pbind
Proxybind. Este overlay reenvía solicitudes de bind simple en una base de datos local a un servidor LDAP remoto.
pcache
Proxycache. Este overlay permite el almacenamiento en caché de solicitudes de búsqueda LDAP en una base de datos local. Se utiliza más a menudo con los backends slapd-ldap(5) o slapd-meta(5).
ppolicy
Política de Contraseñas. Este overlay proporciona una variedad de mecanismos de control de contraseñas, por ejemplo, envejecimiento de contraseñas, control de reutilización y duplicación de contraseñas, restablecimientos de contraseñas obligatorios, etc.
refint
Integridad Referencial. Este overlay se puede utilizar con una base de datos backend como slapd-mdb(5) para mantener la cohesión de un esquema que utiliza atributos de referencia.
remoteauth
Autenticación Remota. Este overlay delega las solicitudes de autenticación a directorios remotos.
retcode
Código de Retorno. Este overlay es útil para probar el comportamiento de los clientes cuando ocurren respuestas erróneas y/o inusuales generadas por el servidor.
rwm
Rewrite/remap. Este overlay es experimental. Realiza reescritura básica de DN/datos y mapeo de objectClass/attributeType.
sssvlv
Clasificación del Lado del Servidor y Vistas de Lista Virtual. Este overlay implementa los controles de clasificación del lado del servidor RFC2891 y los controles de vista de lista virtual, y reemplaza la implementación de resultados paginados RFC2696 para garantizar que funcione con la técnica de clasificación.
syncprov
Proveedor Syncrepl. Este overlay implementa el soporte del lado del proveedor para la replicación syncrepl, incluyendo la funcionalidad de búsqueda persistente.
translucent
Proxy Translúcido. Este overlay se puede utilizar con una base de datos backend como slapd-mdb(5) para crear un "proxy translúcido". El contenido de las entradas recuperadas de un servidor LDAP remoto puede ser parcialmente anulado por la base de datos.
unique
Unicidad de Atributo. Este overlay se puede utilizar con una base de datos backend como slapd-mdb(5) para aplicar la unicidad de algunos o todos los atributos dentro de un subárbol.
valsort
Clasificación de Valores. Este overlay se puede utilizar para aplicar un orden específico a los valores de un atributo cuando se devuelven en una búsqueda.

NAME

slapd.overlays - Overlays for the LDAP server

DESCRIPTION

The OpenLDAP distribution supports an overlay mechanism which allows additional functionality to be added to the LDAP server without modifying the core server code. Overlays are processed in order, and each overlay can modify or intercept requests before they reach the backend or pass them on to the next overlay or backend.

The following overlays are supported:

  • acl: Access control list overlay. This overlay allows for fine-grained control over access to directory entries and attributes.
  • audit: Audit logging overlay. This overlay logs all operations performed on the directory.
  • constraint: Constraint checking overlay. This overlay enforces schema constraints, such as attribute uniqueness and syntax validation.
  • dsml: DSML (Directory Services Markup Language) overlay. This overlay allows clients to interact with the LDAP server using DSML.
  • homedir: Home directory overlay. This overlay can be used to automatically create home directories for users upon login.
  • lastbind: Last bind overlay. This overlay records the time and client address of the last successful bind operation.
  • lazybind: Lazy bind overlay. This overlay defers the bind operation until an operation that requires authentication is performed.
  • manage: Management overlay. This overlay provides management operations for the directory, such as adding and deleting entries.
  • pbind: Proxy bind overlay. This overlay allows clients to bind to the LDAP server using credentials for another LDAP server.
  • ppolicy: Password policy overlay. This overlay enforces password policies, such as password expiration and complexity requirements.
  • ref: Referral overlay. This overlay handles referrals to other LDAP servers.
  • retcode: Return code overlay. This overlay allows for customization of return codes for certain operations.
  • rwm: Rename/move overlay. This overlay allows for renaming and moving of entries within the directory.
  • schema_purge: Schema purge overlay. This overlay automatically removes schema definitions that are no longer in use.
  • syncprov: Synchronization provider overlay. This overlay implements the LDAP synchronization service (RFC 4533).
  • transient: Transient entry overlay. This overlay allows for the creation of transient entries that exist only for the duration of a session.
  • unique: Unique attribute overlay. This overlay ensures that specified attributes are unique across the directory.
  • valsort: Value sort overlay. This overlay sorts attribute values before returning them to the client.

The specific configuration options for each overlay are detailed in their respective manual pages.

You can find more information about OpenLDAP Software at https://www.openldap.org/. OpenLDAP Software is derived from the University of Michigan LDAP 3.3 Release.
