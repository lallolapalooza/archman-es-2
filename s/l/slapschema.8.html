NOMBRE

slapschema - Utilidad de comprobación de esquemas en la base de datos de SLAPD

SINOPSIS

/usr/bin/slapschema [-afiltro] [-bsufijo] [-c] [-dnivel-debug] [-fslapd.conf] [-Fconfdir] [-g] [-HURI] [-larchivo-errores] [-nnum-db] [-oopcion[=valor]] [-ssubárbol-dn] [-v]

DESCRIPCIÓN

Slapschema se utiliza para comprobar el cumplimiento del esquema del contenido de una base de datos slapd(8). Abre la base de datos especificada, determinada por el número de base de datos o el sufijo, y comprueba el cumplimiento de su contenido con el esquema correspondiente. Los errores se escriben en la salida estándar o en el archivo especificado. Las bases de datos configuradas como subordinadas de esta también se incluyen en la salida, a menos que se especifique -g.

Los administradores pueden necesitar modificar elementos de esquema existentes, incluyendo la adición de nuevos atributos requeridos a objectClasses, la eliminación de atributos requeridos o permitidos de objectClasses, la eliminación completa de objectClasses, o cualquier otro cambio que pueda resultar en que entradas perfectamente válidas dejen de cumplir el esquema modificado. La ejecución de la herramienta slapschema después de modificar el esquema puede señalar inconsistencias que de otro modo solo aparecerían cuando las entradas inconsistentes necesiten ser modificadas.

Los registros de entrada se comprueban en orden de base de datos, no en orden de superior primero. Los registros de entrada se comprobarán considerando todos los atributos (de usuario y operativos) almacenados en la base de datos. Los atributos generados dinámicamente (como subschemaSubentry) no se considerarán.

OPCIONES

-a filtro
Solo comprueba las entradas que coinciden con el filtro especificado. Por ejemplo

slapschema -a \
"(!(entryDN:dnSubtreeMatch:=ou=People,dc=example,dc=com))"

comprobará todos los subárboles excepto el "ou=People,dc=example,dc=com" de la base de datos "dc=example,dc=com". Obsoleto; use -H ldap:///???(filtro) en su lugar.

-b sufijo
Utilice el sufijo especificado para determinar qué base de datos comprobar. Por defecto, se utiliza la primera base de datos que admite la operación solicitada. La opción -b no se puede utilizar junto con la opción -n.
-c
Habilita el modo de continuación (ignorar errores).
-d nivel-debug
Habilita mensajes de depuración según lo definido por el nivel-debug especificado; consulte slapd(8) para obtener detalles.
-f slapd.conf
Especifique un archivo slapd.conf(5) alternativo.
-F confdir
especifique un directorio de configuración. Si se especifican tanto -f como -F, el archivo de configuración se leerá y se convertirá al formato de directorio de configuración y se escribirá en el directorio especificado. Si no se especifica ninguna de las opciones, se intentará leer el directorio de configuración predeterminado antes de intentar usar el archivo de configuración predeterminado. Si existe un directorio de configuración válido, se ignorará el archivo de configuración predeterminado.
-g
Deshabilita la unión de subordinados. Solo se procesará la base de datos especificada, y no sus subordinados unidos (si los hay).
-H  URI
Utiliza el dn, el alcance y el filtro de la URI para procesar solo las entradas coincidentes.
-l archivo-errores
Escriba los errores en el archivo especificado en lugar de la salida estándar.
-n num-db
Comprueba la base de datos número num-db listada en el archivo de configuración. La base de datos de configuración slapd-config(5), es siempre la primera base de datos, así que use -n 0

La opción -n no se puede utilizar junto con la opción -b.

-o opcion[=valor]
Especifique una opción con un valor (opcional). Las opciones genéricas/valores posibles son:
              syslog=<subsistemas>  (ver `-s' en slapd(8))
              syslog-level=<nivel> (ver `-S' en slapd(8))
              syslog-user=<usuario>   (ver `-l' en slapd(8))
-s subárbol-dn
Solo comprueba las entradas en el subárbol especificado por este DN. Implica -b subárbol-dn si no se da ninguna opción -b ni -n. Obsoleto; use -H ldap:///subárbol-dn en su lugar.
-v
Habilita el modo detallado.

LIMITACIONES

Para algunos tipos de backend, su slapd(8) no debería estar en ejecución (al menos, no en modo de lectura/escritura) cuando haga esto para garantizar la consistencia de la base de datos. Siempre es seguro ejecutar slapschema con los backends slapd-mdb(5) y slapd-null(5).

EJEMPLOS

Para comprobar el cumplimiento del esquema de su base de datos SLAPD después de realizar modificaciones en el esquema, y guardar cualquier error en un archivo llamado errors.ldif, introduzca el comando:

/usr/bin/slapschema -l errors.ldif
