SLAPO-NSSOV(5) Manual de Formatos de Archivo SLAPO-NSSOV(5)

NOMBRE

slapo-nssov - peticiones NSS y PAM a través de un socket de dominio Unix local

SINOPSIS

ETCDIR/slapd.conf

DESCRIPCIÓN

El overlay nssov para slapd(8) sirve peticiones NSS y PAM a través de un socket de dominio Unix local. Utiliza el mismo protocolo IPC que el nss-pam-ldapd de Arthur de Jong. Un extracto del código fuente de nss-ldapd está incluido junto con el código fuente de nssov para permitir que el overlay se comunique con las bibliotecas cliente de nss-pam-ldapd.

El uso de un protocolo IPC separado para peticiones NSS y PAM elimina las dependencias/conflictos de libldap que sufren todas las soluciones actuales de pam_ldap/nss_ldap. Tanto la solución original nss-ldapd como esta solución nssov están libres de estos problemas de bibliotecas.

A diferencia de nss-pam-ldapd, dado que este overlay se ejecuta dentro de slapd, permite la posibilidad de un almacenamiento en caché sofisticado, sin ninguna de las debilidades de nscd y otras soluciones de almacenamiento en caché relacionadas. Por ejemplo, se puede acceder a una base de datos LDAP remota utilizando back-ldap con almacenamiento en caché proxy (ver slapd-ldap(5) y slapo-pcache(5)) para aprovechar la agrupación de conexiones de back-ldap, así como el almacenamiento en caché persistente de pcache, para proporcionar un alto rendimiento y una medida de soporte para operaciones desconectadas. Alternativamente, las consideraciones de almacenamiento en caché se pueden eliminar por completo ejecutando una base de datos regular con syncrepl para mantener la sincronización con una base de datos LDAP remota.

Otro beneficio importante de nssov es que permite que toda la política de seguridad se administre centralmente a través de LDAP, en lugar de tener reglas frágiles dispersas en múltiples archivos planos. Como tal, no hay configuración del lado del cliente en absoluto para las bibliotecas cliente de NSS/PAM. (Las bibliotecas cliente se comunican con el servidor a través de un socket de dominio Unix cuya ruta está codificada a NSLCDPATH). Como beneficio secundario, esto puede finalmente eliminar la confusión perpetua entre el archivo ldap.conf de OpenLDAP en ETCDIR/ldap.conf y los archivos con nombres similares que suelen utilizar pam_ldap y nss_ldap.

La autenticación de usuarios se realiza mediante enlaces simples internos. La autorización de usuarios aprovecha el motor ACL de slapd, que ofrece mucha más potencia y flexibilidad que las simples comprobaciones de grupo/nombre de host en el antiguo código pam_ldap.

Para utilizar este código, necesitará la biblioteca cliente de nss-pam-ldapd. Puede obtenerla en: http://arthurdejong.org/nss-pam-ldapd No necesitará el demonio nslcd; este overlay reemplaza esa parte. Para deshabilitar la compilación del demonio nslcd en nss-pam-ldapd, agregue la opción --disable-nslcd al script configure de nss-pam-ldapd. Ya debería estar familiarizado con el esquema RFC2307 y RFC2307bis para utilizar este overlay. Consulte el README de nss-pam-ldapd para obtener más información sobre el esquema y qué características se soportan.

También deberá incluir el esquema nis en su configuración de slapd para soporte RFC2307. Si desea utilizar RFC2307bis necesitará un esquema ligeramente diferente. También necesitará el esquema ldapns para la gestión de autorización PAM.

Debe seleccionar ldap en los servicios apropiados en /etc/nsswitch.conf para que estas características de NSS surtan efecto. Del mismo modo, debe habilitar pam_ldap para los servicios de autenticación, cuenta, sesión y contraseña en /etc/pam.conf o /etc/pam.d para que estas características de PAM surtan efecto.

overlay nssov
Esta directiva agrega el overlay nssov al backend actual.
nssov-ssd <servicio> <url>
Esta directiva configura un Descriptor de Búsqueda de Servicio (SSD) para cada servicio NSS que se utilizará. El <servicio> puede ser uno de
    aliases
    ethers
    group
    hosts
    netgroup
    networks
    passwd
    protocols
    rpc
    services
    shadow
y la <url> debe tener la forma
ldap:///[<basedn>][??[<scope>][?<filter>]]
El <basedn> por defecto será el primer sufijo de la base de datos actual. El <scope> por defecto es "subtree". El <filter> por defecto depende del servicio que se esté utilizando.
nssov-map <servicio> <orig> <new>
Si la base de datos local es en realidad un proxy a un servidor LDAP externo, puede ser necesario algún mapeo de esquema. Esta directiva permite realizar algunas sustituciones simples de atributos. Consulte el nss-ldapd/README para ver los nombres de atributos originales utilizados en este código.
nssov-pam <opción> [...]
Esta directiva determina una serie de comportamientos de PAM. Se pueden utilizar múltiples opciones a la vez, y los niveles disponibles son:
userhost
comprobar el atributo host en la entrada del usuario para autorización
userservice
comprobar el atributo authorizedService en la entrada del usuario para autorización
usergroup
comprobar que el usuario es miembro de un grupo específico para autorización
hostservice
comprobar el atributo authorizedService en la entrada del host para autorización
authz2dn
usar mapeo authz-regexp para mapear uid a DN de LDAP
uid2dn
usar SSD de passwd de NSS para mapear uid a DN de LDAP

Establecer las opciones userhost, userservice y usergroup duplica el comportamiento de autorización original de pam_ldap.

El enfoque recomendado es usar hostservice en su lugar. En este caso, se deben crear entradas ipHost para todos los hosts que se estén gestionando, y también deben tener la clase authorizedServiceObject para permitir el uso de atributos authorizedService. También se debe configurar el SSD de hosts de NSS para que se puedan encontrar las entradas ipHost. La autorización se comprueba realizando una operación LDAP Compare buscando el nombre del servicio PAM en el atributo authorizedService. Las ACL de slapd deben establecerse para otorgar o denegar el privilegio Compare a los usuarios o grupos apropiados según se desee.

Si se establece la opción authz2dn, se utilizarán mapeos authz-regexp para mapear el nombre de usuario PAM a un DN de LDAP. El DN de autenticación será de la forma

cn=<servicio>+uid=<usuario>,cn=<nombre_host>,cn=pam,cn=auth

Si no se encuentra ningún mapeo para este DN de autenticación, este mapeo se ignorará.

Si se establece la opción uid2dn, se utilizará el SSD de passwd de NSS para mapear el nombre de usuario PAM a un DN de LDAP. El SSD de passwd debe haberse configurado previamente para que este mapeo tenga éxito.

Si ni el mapeo authz2dn ni el mapeo uid2dn tienen éxito, el módulo devolverá un código de fallo PAM_USER_UNKNOWN. Si se establecen ambas opciones, se intenta primero el mapeo authz; si tiene éxito, se omitirá el mapeo uid2dn.

Por defecto, solo está establecida la opción uid2dn.

nssov-pam-defhost <nombre_host>
Especifica un nombre de host por defecto a comprobar si no se encuentra una entrada ipHost para el nombre de host actual. Esta configuración solo es relevante si se ha establecido la opción hostservice.
nssov-pam-group-dn <DN>
Especifica el DN de un grupo LDAP a comprobar para la autorización. El usuario LDAP debe ser miembro de este grupo para que se permita el inicio de sesión. No hay valor por defecto. Esta configuración solo es relevante si se ha establecido la opción usergroup.
nssov-pam-group-ad <atributo>
Especifica el atributo a utilizar para las comprobaciones de pertenencia a grupo. No hay valor por defecto. Esta configuración solo es relevante si se ha establecido la opción usergroup.
nssov-pam-min-uid <entero>
Especifica un uid mínimo que tiene permitido iniciar sesión. Se denegará el acceso a los usuarios con un uidNumber inferior a este valor.

slapo-nssov(5) — OpenLDAP — Manual pages

NAME

slapo-nssov — NSS (Name Service Switch) overlay

SYNOPSIS

ETCDIR/slapd.conf

overlay nssov

ETCDIR/slapd.conf

olcOverlay={0}nssov

DESCRIPTION

The NSS overlay handles the Name Service Switch (NSS) functionality for services such as passwd, group, and host. It allows these services to query information from LDAP. The NSS overlay works by mapping the standard NSS requests to LDAP searches and returning the results. When the NSS overlay is configured, it can be used to provide various services that are normally handled by files such as /etc/passwd, /etc/group, and /etc/hosts.

The overlay supports the following configuration directives:

nssov-uri <uri>
Specify a URI for the LDAP server that will be used to retrieve NSS information. This directive can be specified multiple times to provide multiple server URIs. The default is ldap:///.
nssov-filter <filter>
Specify a filter to be used for the search. This can be used to restrict the entries that are returned. The default is (objectClass=*).
nssov-binddn <dn>
Specify the bind DN to use when connecting to the LDAP server. If not specified, an anonymous bind will be performed.
nssov-bindpwd <pwd>
Specify the bind password to use when connecting to the LDAP server. This should be used in conjunction with nssov-binddn.
nssov-passwd <attribute>
Specify the attribute containing user information. Defaults to uid.
nssov-passwd-filter <filter>
Specify a filter to use when searching for user information. Defaults to (&(objectClass=posixAccount)(uid=%s)).
nssov-group <attribute>
Specify the attribute containing group information. Defaults to cn.
nssov-group-filter <filter>
Specify a filter to use when searching for group information. Defaults to (&(objectClass=posixGroup)(cn=%s)).
nssov-host <attribute>
Specify the attribute containing host information. Defaults to cn.
nssov-host-filter <filter>
Specify a filter to use when searching for host information. Defaults to (&(objectClass=ipHost)(cn=%s)).
nssov-pam <service>
Specify a PAM service name that will use the NSS overlay for authentication. The configured services will use the attributes specified in nssov-passwd and nssov-group to retrieve user and group information from LDAP.
nssov-pam-default-host <host>
Specify a default host to use when no host information is found in the user's entry. This is used for services like login.
nssov-pam-min-uid <integer>
Specify a minimum uid that is allowed to login. Users with a uidNumber lower than this value will be denied access. The default is zero, which disables this setting.
nssov-pam-max-uid <integer>
Specify a maximum uid that is allowed to login. Users with a uidNumber higher than this value will be denied access. The default is zero, which disables this setting.
nssov-pam-template-ad <attribute>
Specify an attribute to check in a user's entry for a template login name. The template login feature is used by FreeBSD's PAM framework. It can be viewed as a form of proxying, where a user can authenticate with one username/password pair, but is assigned the identity and credentials of the template user. This setting is disabled by default.
nssov-pam-template <name>
Specify a default username to be used if no template attribute is found in the user's entry. The nssov-pam-template-ad directive must be configured for this setting to have any effect.
nssov-pam-session <service>
Specify a PAM service name whose sessions will be recorded. For the configured services, logins will be recorded in the
loginStatus
operational attribute of the user's entry. The attribute's values are of the form
<generalizedTime> <host> <service> <tty> (<ruser@rhost>)
Upon logout the corresponding value will be deleted. This feature allows a single LDAP Search to be used to check which users are logged in across all the hosts of a network. The rootdn of the database is used to perform the updates of the loginStatus attribute, so a rootdn must already be configured for this feature to work. By default no services are configured.

The PAM functions support LDAP Password Policy as well. If the password policy overlay is in use (see slapo-ppolicy(5)), policy information (e.g. password expiration, password quality, etc.) may be returned to the PAM client as a result of authentication, account management, and password modification requests.

The overlay also supports dynamic configuration in cn=config. An example of the config entry is

    dn: olcOverlay={0}nssov,ocDatabase={1}mdb,cn=config
    objectClass: olcOverlayConfig
    objectClass: olcNssOvConfig
    olcOverlay: {0}nssov
    olcNssSsd: passwd ldap:///ou=users,dc=example,dc=com??one
    olcNssMap: passwd uid accountName
    olcNssPam: hostservice uid2dn
    olcNssPamDefHost: defaulthost
    olcNssPamMinUid: 500
    olcNssPamMaxUid: 32000
    olcNssPamSession: login
    olcNssPamSession: sshd

which enables the passwd service, and uses the accountName attribute to fetch what is usually retrieved from the uid attribute. It also enables some PAM authorization controls, and specifies that the PAM login and sshd services should have their logins recorded.
