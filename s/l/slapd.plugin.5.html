SLAPD.PLUGIN(5) Manual de formatos de archivo SLAPD.PLUGIN(5)

NOMBRE

slapd.plugin - configuración de plugins para slapd, el demonio LDAP autónomo

SINOPSIS

/etc/openldap/slapd.conf

DESCRIPCIÓN

El archivo slapd.conf(5) contiene información de configuración para el demonio slapd(8). Este archivo de configuración también es utilizado por las herramientas de SLAPD slapadd(8), slapcat(8), slapmodify(8), y slapindex(8).

El archivo slapd.conf consiste en una serie de opciones de configuración globales que se aplican a slapd en su conjunto (incluyendo todos los backends), seguidas de cero o más definiciones de backends de base de datos que contienen información específica de una instancia de backend.

El formato general de slapd.conf es el siguiente:

    # comentario - estas opciones se aplican a cada base de datos
    <opciones de configuración globales>
    # primera definición de base de datos y opciones de configuración
    database    <tipo de backend 1>
    <opciones de configuración específicas del backend 1>
    # definiciones de bases de datos subsiguientes y opciones de configuración
    ...

Si slapd está compilado con --enable-slapi, se admite el soporte para plugins según las Directivas de Plugins de Netscape Directory Server. Actualmente se implementa la versión 4 de la API, con algunas extensiones de la versión 5.

Tanto los datos globales como los específicos de la base de datos pueden contener información de plugins. Los plugins asociados con una base de datos específica se llaman antes que los plugins globales. Esta página del manual detalla las sentencias de configuración de slapd(8) que afectan a la carga de los plugins de SLAPI.

Los argumentos que deben ser reemplazados por texto real se muestran entre corchetes <>.

La estructura de las directivas de plugin es

plugin <tipo> <ruta_libreria> <funcion_inicializacion> [<argumentos>]
Carga un plugin del tipo especificado para la base de datos actual.

El <tipo> puede ser uno de preoperation, que se ejecuta antes de procesar la operación para la base de datos especificada, postoperation, que se ejecuta después de que la operación para la base de datos especificada haya sido procesada, extendedop, que se usa al ejecutar una operación extendida, o object. Este último se usa para tipos misceláneos como plugins de ACL, atributos calculados y reescritores de filtros de búsqueda.

El argumento <ruta_libreria> especifica la ruta al objeto cargable del plugin; si se proporciona una ruta relativa, el objeto se busca según el paquete de carga dinámica subyacente (se usa ltdl de libtool).

El argumento <funcion_inicializacion> especifica qué símbolo debe ser llamado cuando el plugin se carga por primera vez. Esta función debe registrar las funciones proporcionadas por el plugin para las operaciones deseadas. Cabe señalar que es esta función de inicialización, no el tipo de plugin especificado como primer argumento, lo que determina cuándo y para qué operaciones se invocará el plugin. La lista opcional de <argumentos> se pasa a la función de inicialización.

pluginlog <archivo>
Especifica una ruta alternativa para el archivo de registro de plugins (el predeterminado es /var/lib/openldap/errors).
modulepath <espec_ruta>
Esta sentencia establece la ruta de carga de módulos para backends cargables dinámicamente, como se describe en slapd.conf(5); sin embargo, dado que tanto los backends cargables dinámicamente como los plugins SLAPI usan la misma biblioteca subyacente (ltdl de libtool), su valor también afecta la ruta de búsqueda de plugins. En general, la ruta de búsqueda está compuesta por rutas separadas por dos puntos; generalmente se busca primero la ruta definida por el usuario; luego se usa el valor de la variable de entorno LTDL_LIBRARY_PATH, si está definida; finalmente, se intenta la ruta de carga dinámica específica del sistema (por ejemplo, en Linux el valor de la variable de entorno LD_LIBRARY_PATH). Por favor, lea atentamente la documentación de ltdl porque su comportamiento depende mucho de la plataforma.

ARCHIVOS
