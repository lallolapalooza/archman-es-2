NOMBRE

slapo-refint - superposición de integridad referencial para slapd

SINOPSIS

/etc/openldap/slapd.conf

DESCRIPCIÓN

La superposición de Integridad Referencial se puede usar con una base de datos de backend como slapd-mdb(5) para mantener la cohesión de un esquema que utiliza atributos de referencia.

La integridad se mantiene actualizando los registros de la base de datos que contienen los atributos especificados para que coincidan con los resultados de una operación modrdn o delete. Por ejemplo, si el atributo de integridad se configurara como manager, la eliminación del registro "uid=robert,ou=people,dc=example,dc=com" desencadenaría una búsqueda de todos los demás registros que tengan un atributo manager que contenga ese DN. Las entradas que coincidan con esa búsqueda tendrían su atributo manager eliminado. O, renombrar el mismo registro a "uid=george,ou=people,dc=example,dc=com" desencadenaría una búsqueda de todos los demás registros que tengan un atributo manager que contenga ese DN. Las entradas que coincidan con esa búsqueda tendrían su atributo manager eliminado y reemplazado por el nuevo DN.

Se debe establecer rootdn para la base de datos. refint se ejecuta como rootdn para obtener acceso y realizar sus actualizaciones. No se necesita rootpw.

CONFIGURACIÓN

Estas opciones de slapd.conf se aplican a la superposición de Integridad Referencial. Deben aparecer después de la directiva overlay.

refint_attributes <atributo> [...]
Especifica uno o más atributos para los cuales se mantendrá la integridad como se describe anteriormente.
refint_nothing <cadena>
Especifica un valor arbitrario que se utilizará como marcador de posición cuando el último valor se elimine de un atributo. Esto puede ser útil en casos donde el esquema requiere la existencia de un atributo para el cual se aplica la integridad referencial. El intento de eliminar un atributo requerido de lo contrario resultaría en una Violación de Clase de Objeto, haciendo que la solicitud falle. La cadena debe ser un DN válido.
refint_modifiersname <DN>
Especifica el DN que se utilizará como modifiersName de las modificaciones internas realizadas por la superposición. Por defecto es "cn=Referential Integrity Overlay".

Las modificaciones realizadas por esta superposición no se propagan durante la replicación. Esta superposición debe configurarse idénticamente en los consumidores de replicación para mantener una sincronización completa con el proveedor.
