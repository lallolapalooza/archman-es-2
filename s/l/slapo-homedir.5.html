SLAPO-HOMEDIR(5) Manual de Formatos de Archivo SLAPO-HOMEDIR(5)

NOMBRE

slapo-homedir - Overlay de aprovisionamiento de directorios personales

SINOPSIS

/etc/openldap/slapd.conf

DESCRIPCIÓN

El overlay homedir hace que slapd(8) detecte cambios que involucran objetos de usuario estilo RFC-2307bis y realice los cambios apropiados en el sistema de archivos local. Esto se puede realizar tanto en sistemas maestros como en réplicas, por lo que es posible realizar el aprovisionamiento de directorios personales remotos.

CONFIGURACIÓN

Se admite tanto la configuración estilo slapd.conf como la estilo back-config.

overlay homedir
Esta directiva agrega el overlay homedir a la base de datos actual, o al frontend, si se usa antes de cualquier instanciación de base de datos; vea slapd.conf(5) para más detalles.
homedir-skeleton-path <ruta>
olcSkeletonPath: ruta
Estas opciones establecen la ruta al directorio esqueleto de la cuenta. (Generalmente, /etc/skel) Los archivos en este directorio se copiarán en los directorios personales recién creados. La copia es recursiva y maneja symlinks y fifos, pero omitirá la mayoría de los especiales.
homedir-min-uidnumber <número de id de usuario>
olcMinimumUidNumber: número
Estas opciones configuran el userid mínimo a usar en cualquier intento de directorio personal. Esta es una medida de seguridad básica para evitar el uso accidental de cuentas del sistema. Consulte REPLICACIÓN para opciones más flexibles para seleccionar cuentas.
homedir-regexp <expresión regular> <ruta>
olcHomedirRegexp: expresión regular ruta
Estas opciones configuran un conjunto de expresiones regulares a usar para comparar y opcionalmente remapear valores de atributos homeDirectory entrantes a rutas en el sistema de archivos local. Se admite la expansión $número para acceder a los valores capturados entre paréntesis.

Por ejemplo, para aceptar cualquier directorio que comience con home y usarlo textualmente en el sistema de archivos local:

homedir-regexp ^(/home/[-_/a-z0-9]+)$ $1

Para comparar el mismo conjunto de directorios, pero crearlos en su lugar bajo exporthome, como es popular en los servidores NFS de Solaris:

homedir-regexp ^(/home/[-_/a-z0-9]+)$ /export/$1

homedir-delete-style estilo
olcHomedirDeleteStyle: estilo
Estas opciones configuran cómo se manejan las eliminaciones de entradas posixAccount o sus atributos; los estilos válidos son IGNORE, que no hace nada, y DELETE, que realiza inmediatamente una eliminación recursiva en el directorio personal, y ARCHIVE, que archiva el contenido del directorio personal en un archivo TAR para su posterior examen. El valor predeterminado es IGNORE. Úselo con precaución. ARCHIVE requiere que se establezca homedir-archive-path, o funciona de manera similar a IGNORE.
homedir-archive-path <ruta>
olcHomedirArchivePath: ruta
Estas opciones especifican la ruta de destino para los archivos TAR creados por el estilo de eliminación ARCHIVE.

REPLICACIÓN

El overlay homedir puede operar en sistemas maestros o réplicas sin cambios. Consulte slapd.conf(5) o slapd-config(5) para más información sobre cómo configurar syncrepl.

La replicación parcial (por ejemplo, con filtros) es especialmente útil para proporcionar diferentes opciones de aprovisionamiento a diferentes conjuntos de usuarios.

EJEMPLO

El siguiente LDIF podría usarse para agregar este overlay a cn=config (ajuste según sea necesario)

dn: cn=module{0},cn=config
changetype: modify
add: olcModuleLoad
olcModuleLoad: homedir
dn: olcOverlay=homedir,olcDatabase={1}mdb,cn=config
changetype: add
objectClass: olcOverlayConfig
objectClass: olcHomedirConfig
olcOverlay: homedir
olcSkeletonPath: /etc/skel
olcMinimumUidNumber: 1000
olcHomedirRegexp: ^(/home/[-_/a-z0-9]+)$ /export/$1
olcHomedirDeleteStyle: ARCHIVE
olcHomedirArchivePath: /archive

ERRORES

Las operaciones DELETE, MOD y MODRDN que eliminan los atributos unix cuando el estilo de eliminación se establece en DELETE eliminarán recursivamente el directorio personal (modificado por regex) del disco. Tenga precaución al eliminar o cambiar valores.

MOD y MODRDN responderán correctamente a los cambios de homeDirectory y realizarán una operación rename() no destructiva en el sistema de archivos, pero esto no se reintenta correctamente con una copia recursiva al moverse entre sistemas de archivos.

Las funciones de copia/eliminación/chown/tar recursivas no son conscientes de las ACL, atributos extendidos, forks, archivos dispersos o enlaces duros. La archivación de dispositivos de bloques y caracteres no es portátil, pero no debería ser un problema en los directorios personales, esperemos.

La copia y el archivado pueden no admitir archivos de más de 2GiB en algunas arquitecturas. Los archivos UStar POSIX simples no pueden admitir archivos internos de más de 8GiB. El generador de tar actual no intenta resolver uid/gid en nombres simbólicos.

No se intenta intentar mkdir() los directorios padre necesarios para un directorio personal o ruta de archivo dada.

ARCHIVOS

/etc/openldap/slapd.conf
archivo de configuración predeterminado de slapd
/etc/skel (o similar)
fuente de nuevos archivos de directorio personal.

VER TAMBIÉN

slapd.conf(5), slapd-config(5), slapd(8), RFC-2307, RFC-2307bis.
