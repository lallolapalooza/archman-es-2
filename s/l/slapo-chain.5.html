SLAPO-CHAIN(5) Manual de Formatos de Archivo SLAPO-CHAIN(5)

NOMBRE

slapo-chain - overlay de cadena para slapd

SINOPSIS

/etc/openldap/slapd.conf

DESCRIPCIÓN

El overlay chain para slapd(8) permite el seguimiento automático de referencias. Cada vez que se devuelve una referencia (excepto para operaciones de bind), se sigue utilizando una instancia del backend ldap. Si las operaciones se realizan con una identidad (es decir, después de un bind), esa identidad puede ser afirmada mientras se siguen las referencias mediante la característica de afirmación de identidad de back-ldap (ver slapd-ldap(5) para más detalles), que se basa esencialmente en el control de autorización proxy [RFC 4370]. El seguimiento de referencias puede ser controlado por el cliente emitiendo el control chaining (ver draft-sermersheim-ldap-chaining para más detalles).

Las directivas de configuración específicas del overlay chain están prefijadas con chain-, para evitar conflictos potenciales con directivas específicas de la base de datos subyacente u otros overlays apilados.

Hay muy pocas directivas específicas del overlay chain; sin embargo, las directivas relacionadas con las instancias del backend ldap que pueden ser instanciadas implícitamente por el overlay pueden asumir un significado especial cuando se usan junto con este overlay. Se describen en slapd-ldap(5), y también necesitan prefijarse con chain-.

Nota: este overlay está integrado en el backend ldap; no es un módulo separado.

overlay chain
Esta directiva añade el overlay chain al backend actual. El overlay chain puede usarse con cualquier backend, pero está destinado principalmente a usarse con backends de almacenamiento local que puedan devolver referencias. Es inútil en conjunto con los backends slapd-ldap y slapd-meta porque ya explotan la característica de seguimiento de referencias específica de libldap. [Nota: esto puede cambiar en el futuro, ya que los backends ldap(5) y meta(5) podrían dejar de seguir referencias por sí mismos.]
chain-cache-uri {FALSE|true}
Esta directiva instruye al overlay chain para que almacene en caché las conexiones a URIs analizadas a partir de referencias que no están predefinidas, para reutilizarlas posteriormente. Estas URIs heredan las propiedades configuradas para el slapd-ldap(5) subyacente antes de cualquier aparición de la directiva chain-uri; básicamente, se encadenan anónimamente.
chain-chaining [resolve=<r>] [continuation=<c>] [critical]
Esta directiva habilita el control chaining (ver draft-sermersheim-ldap-chaining para más detalles) con los comportamientos de resolución y continuación deseados y criticidad. El parámetro resolve se refiere al comportamiento al descubrir un recurso, es decir, al acceder al objeto indicado por el DN de la solicitud; el parámetro continuation se refiere al comportamiento al manejar respuestas intermedias, lo cual es principalmente significativo para la operación de búsqueda, pero puede afectar a operaciones extendidas que devuelven respuestas intermedias. Los valores r y c pueden ser cualquiera de chainingPreferred, chainingRequired, referralsPreferred, referralsRequired. Si el flag critical afecta a la criticidad del control si se proporciona. [Este control es experimental y su soporte puede cambiar en el futuro.]
chain-max-depth <n>
En caso de que se devuelva una referencia durante el seguimiento de referencias, el seguimiento adicional ocurre como máximo a una profundidad de <n> niveles. Establecido a 1 (el valor predeterminado) para deshabilitar el seguimiento adicional de referencias.
chain-return-error {FALSE|true}
En caso de que falle el seguimiento de referencias, se devuelve el error real en lugar de la referencia original. En caso de que haya varias URIs de referencia, solo se devuelve el primer error. Este comportamiento puede no ser siempre apropiado ni deseable, ya que los fallos en el seguimiento de referencias podrían resolverse mejor por el cliente (por ejemplo, cuando son causados por problemas de autenticación distribuida).
chain-uri <ldapuri>
Esta directiva instancia una nueva base de datos ldap subyacente y le indica qué URI contactar para seguir las referencias. A diferencia de lo indicado en slapd-ldap(5), solo puede aparecer una URI después de esta directiva; todas las directivas posteriores de slapd-ldap(5) prefijadas con chain- se refieren a esta instancia específica de un servidor remoto.

También pueden ser necesarias directivas para configurar la base de datos ldap subyacente, como se muestra en este ejemplo:

overlay                 chain
chain-rebind-as-user    FALSE
chain-uri               "ldap://ldap1.example.com"
chain-rebind-as-user    TRUE
chain-idassert-bind     bindmethod="simple"
                        binddn="cn=Auth,dc=example,dc=com"
                        credentials="secret"
                        mode="self"
chain-uri               "ldap://ldap2.example.com"
chain-idassert-bind     bindmethod="simple"
                        binddn="cn=Auth,dc=example,dc=com"
                        credentials="secret"
                        mode="none"

Se pueden utilizar directivas válidas para la base de datos ldap; ver slapd-ldap(5) para más detalles. Pueden aparecer múltiples ocurrencias de la directiva chain-uri, para definir múltiples URIs "confiables" donde se siguen las operaciones con afirmación de identidad. Todas las URIs no listadas en la configuración se siguen anónimamente. Todas las directivas de slapd-ldap(5) que aparecen antes de la primera ocurrencia de chain-uri son heredadas por todas las URIs, a menos que se anulen específicamente dentro de la configuración de cada URI.

ARCHIVOS

archivo de configuración predeterminado de slapd

VER TAMBIÉN
