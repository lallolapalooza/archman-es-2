SLAQR4 calcula los valores propios de una matriz de Hessenberg, y opcionalmente las matrices de la descomposición de Schur.

Propósito:

!>
!>    SLAQR4 implementa un nivel de recursión para SLAQR0.
!>    Es una implementación completa del algoritmo QR multi-shift de burbuja pequeña.
!>    Puede ser llamado por SLAQR0 y, para un tamaño de ventana de deflación suficientemente grande,
!>    puede ser llamado por SLAQR3. Esta subrutina es idéntica a SLAQR0 excepto que llama a SLAQR2
!>    en lugar de SLAQR3.
!>
!>    SLAQR4 calcula los valores propios de una matriz de Hessenberg H
!>    y, opcionalmente, las matrices T y Z de la descomposición de Schur
!>    H = Z T Z**T, donde T es una matriz cuasi-triangular superior (la
!>    forma de Schur), y Z es la matriz ortogonal de vectores de Schur.
!>
!>    Opcionalmente, Z puede ser postmultiplicado en una matriz ortogonal de entrada
!>    Q para que esta rutina pueda dar la factorización de Schur
!>    de una matriz A que ha sido reducida a la forma de Hessenberg H
!>    por la matriz ortogonal Q: A = Q*H*Q**T = (QZ)*T*(QZ)**T.
!>

Parámetros

WANTT 
!>          WANTT es LOGICAL
!>          = .TRUE. : se requiere la forma de Schur completa T;
!>          = .FALSE.: solo se requieren los valores propios.
!>

WANTZ

!>          WANTZ es LOGICAL
!>          = .TRUE. : se requiere la matriz de vectores de Schur Z;
!>          = .FALSE.: no se requieren vectores de Schur.
!>

N

!>          N es INTEGER
!>           El orden de la matriz H.  N >= 0.
!>

ILO

!>          ILO es INTEGER
!>

IHI

!>          IHI es INTEGER
!>           Se asume que H ya es triangular superior en las filas
!>           y columnas 1:ILO-1 e IHI+1:N y, si ILO > 1,
!>           H(ILO,ILO-1) es cero. ILO e IHI normalmente son establecidos por una
!>           llamada previa a SGEBAL, y luego pasados a SGEHRD cuando la
!>           matriz de salida de SGEBAL se reduce a la forma de Hessenberg.
!>           De lo contrario, ILO e IHI deben establecerse en 1 y N,
!>           respectivamente.  Si N > 0, entonces 1 <= ILO <= IHI <= N.
!>           Si N = 0, entonces ILO = 1 e IHI = 0.
!>

H

!>          H es array REAL, dimension (LDH,N)
!>           En la entrada, la matriz de Hessenberg superior H.
!>           En la salida, si INFO = 0 y WANTT es .TRUE., entonces H contiene
!>           la matriz cuasi-triangular superior T de la descomposición
!>           de Schur (la forma de Schur); los bloques diagonales de 2x2
!>           (correspondientes a pares de valores propios complejos conjugados)
!>           se devuelven en forma estándar, con H(i,i) = H(i+1,i+1)
!>           y H(i+1,i)*H(i,i+1) < 0. Si INFO = 0 y WANTT es
!>           .FALSE., entonces el contenido de H no está especificado en la salida.
!>           (El valor de salida de H cuando INFO > 0 se describe a continuación
!>           en la descripción de INFO.)
!>
!>           Esta subrutina puede establecer explícitamente H(i,j) = 0 para i > j y
!>           j = 1, 2, ... ILO-1 o j = IHI+1, IHI+2, ... N.
!>

LDH

!>          LDH es INTEGER
!>           La dimensión principal del array H. LDH >= max(1,N).
!>

WR

!>          WR es array REAL, dimension (IHI)
!>

WI

!>          WI es array REAL, dimension (IHI)
!>           Las partes real e imaginaria, respectivamente, de los valores propios
!>           calculados de H(ILO:IHI,ILO:IHI) se almacenan en WR(ILO:IHI)
!>           y WI(ILO:IHI). Si dos valores propios se calculan como un
!>           par conjugado complejo, se almacenan en elementos consecutivos
!>           de WR y WI, por ejemplo, el i-ésimo y el (i+1)-ésimo, con
!>           WI(i) > 0 y WI(i+1) < 0. Si WANTT es .TRUE., entonces
!>           los valores propios se almacenan en el mismo orden que en la
!>           diagonal de la forma de Schur devuelta en H, con
!>           WR(i) = H(i,i) y, si H(i:i+1,i:i+1) es un bloque diagonal de 2x2,
!>           WI(i) = sqrt(-H(i+1,i)*H(i,i+1)) y
!>           WI(i+1) = -WI(i).
!>

ILOZ

!>          ILOZ es INTEGER
!>

IHIZ

!>          IHIZ es INTEGER
!>           Especifican las filas de Z a las que se deben aplicar transformaciones
!>           si WANTZ es .TRUE..
!>           1 <= ILOZ <= ILO; IHI <= IHIZ <= N.
!>

Z

!>          Z es array REAL, dimension (LDZ,IHI)
!>           Si WANTZ es .FALSE., entonces Z no se referencia.
!>           Si WANTZ es .TRUE., entonces Z(ILO:IHI,ILOZ:IHIZ) se reemplaza por
!>           Z(ILO:IHI,ILOZ:IHIZ)*U donde U es el factor de Schur ortogonal
!>           de H(ILO:IHI,ILO:IHI).
!>           (El valor de salida de Z cuando INFO > 0 se describe a continuación
!>           en la descripción de INFO.)
!>

LDZ

!>          LDZ es INTEGER
!>           La dimensión principal del array Z.  Si WANTZ es .TRUE.
!>           entonces LDZ >= MAX(1,IHIZ).  De lo contrario, LDZ >= 1.
!>

WORK

!>          WORK es array REAL, dimension LWORK
!>           En la salida, si LWORK = -1, WORK(1) devuelve una estimación de
!>           el valor óptimo para LWORK.
!>

LWORK

!>          LWORK es INTEGER
!>           La dimensión del array WORK.  LWORK >= max(1,N)
!>           es suficiente, pero LWORK típicamente tan grande como 6*N puede
!>           ser requerido para un rendimiento óptimo. Se recomienda una consulta
!>           de espacio de trabajo para determinar el tamaño óptimo del espacio de trabajo.
!>
!>           Si LWORK = -1, entonces SLAQR4 realiza una consulta de espacio de trabajo.
!>           En este caso, SLAQR4 verifica los parámetros de entrada y estima
!>           el tamaño óptimo del espacio de trabajo para los valores dados
!>           de N, ILO e IHI. La estimación se devuelve en WORK(1).
!>           XERBLA no emite ningún mensaje de error relacionado con LWORK.
!>           Ni H ni Z son accedidos.
!>

INFO

!>          INFO es INTEGER
!> \verbatim
!>          INFO es INTEGER
!>             = 0:  salida exitosa
!>             > 0:  si INFO = i, SLAQR4 falló en calcular todos los
!>                valores propios. Los elementos 1:ilo-1 e i+1:n de WR
!>                y WI contienen los valores propios que se han calculado
!>                con éxito. (Los fallos son raros.)
!>
!>                Si INFO > 0 y WANTT es .FALSE., entonces en la salida,
!>                los valores propios no convergidos restantes son los valores
!>                propios de la matriz de Hessenberg superior, filas y
!>                columnas ILO a través de INFO del valor de salida final
!>                de H.
!>
!>                Si INFO > 0 y WANTT es .TRUE., entonces en la salida
!>
!>           (*)  (H de entrada)*U  = U*(H de salida)
!>
!>                donde U es una matriz ortogonal. H de salida
!>                es de Hessenberg superior y triangular en
!>                filas y columnas INFO+1 a IHI.
!>
!>                Si INFO > 0 y WANTZ es .TRUE., entonces en la salida
!>
!>                  (Z de salida(ILO:IHI,ILOZ:IHIZ)
!>                   =  (Z de entrada(ILO:IHI,ILOZ:IHIZ)*U
!>
!>                donde U es la matriz ortogonal en (*) (independientement
!>                del valor de WANTT).
!>

SYNOPSIS

 SUBROUTINE SLAQR4(WANTT, WANTZ, N, ILO, IHI, SCALE, SUM, RESL,
 &                   AB, LDAB, Z, LDZ, WORK, INFO)

 LOGICAL WANTT, WANTZ
 INTEGER N, ILO, IHI, LDAB, LDZ, INFO
 REAL SCALE, SUM

Function/Subroutine Documentation

SLAQR4 is a Fortran subroutine that implements part of the QR algorithm for finding the eigenvalues and Schur decomposition of a general matrix.

Purpose

SLAQR4 uses the QR algorithm to compute the eigenvalues and optionally the Schur vectors of a quasitriangular matrix. It is typically called by the inverse iteration routine.

The matrix AB is deflated in this routine. If deflation is not possible, the routine will expect that there is an anecdote or a sequence of anecdotes, which are transformed into zeros on the subdiagonal. If there is only one anecdote, then the matrix is deflated and the subproblem is solved.

If there are more than one anecdotes, then the matrix is split into two sub-blocks using the block shifts and the subproblems are solved recursively.

Arguments

WANTT (Input) Logical. If true, Schur vectors of AB are computed.

WANTZ (Input) Logical. If true, Schur vectors of AB are computed.

N (Input) Integer. The order of the matrix AB.

ILO (Input) Integer. The starting index of the top-left element of the sub-block for which the QR algorithm is to be applied.

IHI (Input) Integer. The ending index of the top-left element of the sub-block for which the QR algorithm is to be applied.

SCALE (Input) Real. The scaling factor for the eigenvalues.

SUM (Input) Real. The sum of the squared magnitude of the eigenvalues.

RESL (Input) Real. The desired accuracy of the eigenvalues.

AB (Input/Output) Real array, dimension (LDAB,*) On entry, the upper quasitriangular matrix.

LDAB (Input) Integer. The leading dimension of the array AB.

Z (Input/Output) Real array, dimension (LDZ,*) On entry, the unitary matrix Q. On exit, Z*Q.

LDZ (Input) Integer. The leading dimension of the array Z.

WORK (Workspace) Real array, dimension (4*N). This array is used for storing intermediate results.

INFO (Output) Integer.

INFO = 0: successful exit.

INFO < 0: if INFO = -i, then the i-th argument had an illegal value.

INFO > 0: if INFO = i, then the QR algorithm failed to converge at the i-th iteration.

Auxiliary Routines

This routine calls the following auxiliary routines:

slacpy, slaset, slasrt, slaswp, slaszp, slazzs, slatm1, slatm2, slatm3, slatrs, slarrv, slarrvx, slaszs.

Algorithm

The routine implements the multi-shift QR algorithm with aggressive early deflation. It attempts to deflate the matrix by finding and transforming subdiagonal elements to zero. If deflation is successful, the problem is reduced in size. If not, it splits the problem into two smaller subproblems using block shifts and solves them recursively.

The routine relies on the fact that if a matrix is quasi-triangular, then its eigenvalues are on the diagonal. The routine attempts to transform the matrix into a triangular matrix by zeroing out the subdiagonal elements.

The routine uses a sequence of shifts to accelerate the convergence of the QR algorithm. These shifts are chosen based on the eigenvalues of 2-by-2 submatrices on the diagonal.

The routine also employs aggressive early deflation, which means that it attempts to deflate the matrix as soon as possible, even if the subdiagonal elements are not exactly zero. This is achieved by using a criterion based on the relative magnitudes of the eigenvalues.
