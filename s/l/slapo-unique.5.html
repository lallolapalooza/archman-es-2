NOMBRE

slapo-unique - Superposición de Unicidad de Atributos para slapd

SINOPSIS

/etc/openldap/slapd.conf

DESCRIPCIÓN

La superposición de Unicidad de Atributos se puede usar con una base de datos de backend como slapd-mdb(5) para forzar la unicidad de algunos o todos los atributos dentro de un ámbito. Este subárbol tiene por defecto todos los objetos dentro del subárbol de la base de datos para la cual está configurada la superposición de Unicidad.

La unicidad se aplica buscando en el subárbol para asegurar que los valores de todos los atributos presentados con una operación de add, modify o modrdn sean únicos dentro del ámbito. Por ejemplo, si se forzara la unicidad para el atributo uid, se buscaría en el subárbol cualquier otro registro que también tenga un atributo uid que contenga el mismo valor. Si se encuentra alguno, la solicitud es rechazada.

La búsqueda se realiza utilizando el rootdn de la base de datos, para evitar problemas con las ACLs que impidan que la superposición vea todos los datos relevantes. Como tal, la base de datos debe tener configurado un rootdn.

CONFIGURACIÓN

Estas opciones de slapd.conf se aplican a la superposición de Unicidad de Atributos. Deben aparecer después de la directiva overlay.

unique_uri <[strict ][ignore ][serialize ]URI[[ URI...]...]>
Configura la base, los atributos, el ámbito y el filtro para la verificación de unicidad. Se pueden especificar múltiples URIs dentro de un dominio, permitiendo selecciones complejas de objetos. Múltiples sentencias unique_uri o valores de atributo olcUniqueURI crearán dominios independientes, cada uno con sus propias listas independientes de URIs y configuraciones de ignore/strict.

Las palabras clave strict, ignore y serialize deben ir entre comillas (") junto con la URI cuando se usen configuraciones obsoletas de slapd.conf.

La sintaxis URI LDAP es un subconjunto de RFC-4516 y toma la forma:

ldap:///[dn base]?[atributos...]?[ámbito]?[filtro]

El dn base por defecto es el de la base de datos de backend. Los dns base especificados deben estar dentro del subárbol de la base de datos de backend.

Si no se especifican atributos, la URI se aplica a todos los atributos no operativos.

El componente de ámbito es efectivamente obligatorio, ya que las URIs LDAP por defecto tienen el ámbito base, lo cual no es válido para la unicidad, ya que los grupos de un solo objeto son siempre únicos. Los ámbitos sub (para subárbol) y one (para un nivel) son válidos.

El componente de filtro hace que el dominio aplique restricciones de unicidad solo a los objetos que coincidan. Por ejemplo, ldap:///?cn?sub?(sn=e*) requeriría atributos cn únicos para todos los objetos en el subárbol de la base de datos de backend cuyo sn comience por una e.

Es posible afirmar la unicidad en todos los atributos no operativos, excepto aquellos listados, anteponiendo la palabra clave ignore. Si no se configura, todos los atributos no operativos (por ejemplo, del sistema) deben ser únicos. Tenga en cuenta que la lista de atributos de una URI ignore generalmente debería contener los atributos objectClass, dc, ou y o, ya que estos generalmente no serán únicos, ni son atributos operativos.

Es posible configurar una verificación estricta para el dominio de unicidad anteponiendo la palabra clave strict. Por defecto, la unicidad no se aplica a los valores nulos. Habilitar el modo strict extiende el concepto de unicidad para incluir valores nulos, de modo que solo un atributo dentro de un subárbol podrá tener un valor nulo. La estrictez se aplica a todas las URIs dentro de un dominio de unicidad, pero algunos dominios pueden ser estrictos mientras que otros no.

Es posible forzar la serialización estricta de las modificaciones anteponiendo la palabra clave serialize. Por defecto, no se realiza ninguna serialización, por lo que múltiples modificaciones que ocurran casi simultáneamente pueden ver resultados de unicidad incompletos. Usar serialize forzará a que las operaciones de escritura individuales se completen antes de permitir que otras procedan, para asegurar que las verificaciones de unicidad de cada operación sean consistentes.

No es posible configurar URIs y parámetros de configuración de slapo-unique heredados simultáneamente. En general, las opciones de configuración heredadas controlan partes de un único dominio de subárbol sin filtrar.

unique_base <basedn>
Este parámetro de configuración heredado debe convertirse en el componente dn base del parámetro de estilo unique_uri mencionado anteriormente.
unique_ignore <atributo...>
Este parámetro de configuración heredado debe convertirse en un parámetro unique_uri con la palabra clave ignore, como se describe anteriormente.
unique_attributes <atributo...>
Este parámetro de configuración heredado debe convertirse en un parámetro unique_uri, como se describe anteriormente.
unique_strict <atributo...>
Este parámetro de configuración heredado debe convertirse en una palabra clave strict antepuesta a un parámetro unique_uri, como se describe anteriormente.

ADVERTENCIAS

unique_uri no se puede usar con el estilo antiguo de configuración, y viceversa. Sin embargo, unique_uri puede implementar todo lo que el sistema antiguo puede hacer.

Los atributos típicos para las URIs ignore ldap:///... no están codificados de forma fija intencionadamente en la superposición para permitir la máxima flexibilidad en el cumplimiento de requisitos específicos del sitio.

La replicación y las operaciones con el control relax tienen permiso para eludir esta aplicación. Por lo tanto, es importante que todos los servidores que aceptan escrituras tengan configurada esta superposición para mantener la unicidad en un DIT replicado.

ARCHIVOS

/etc/openldap/slapd.conf
archivo de configuración predeterminado de slapd
