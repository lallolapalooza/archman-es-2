SLEEP(3P) Manual del programador POSIX SLEEP(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

sleep — suspende la ejecución durante un intervalo de tiempo

SINOPSIS

#include <unistd.h>
unsigned sleep(unsigned segundos);

DESCRIPCIÓN

La función sleep() suspenderá el hilo que la llama de la ejecución hasta que hayan transcurrido los segundos de tiempo real especificados por el argumento segundos o se entregue una señal al hilo que la llama y su acción sea invocar una función de captura de señales o terminar el proceso. El tiempo de suspensión puede ser mayor que el solicitado debido a la planificación de otra actividad por parte del sistema.

En programas monotarea, sleep() puede utilizar SIGALRM. En programas multihilo, sleep() no utilizará SIGALRM y el resto de esta DESCRIPCIÓN no se aplica.

Si se genera una señal SIGALRM para el proceso que llama durante la ejecución de sleep() y si la señal SIGALRM está siendo ignorada o su entrega está bloqueada, es indeterminado si sleep() retorna cuando la señal SIGALRM está programada. Si la señal está bloqueada, también es indeterminado si permanece pendiente después de que sleep() retorne o si se descarta.

Si se genera una señal SIGALRM para el proceso que llama durante la ejecución de sleep(), excepto como resultado de una llamada previa a alarm(), y si la señal SIGALRM no está siendo ignorada o su entrega está bloqueada, es indeterminado si esa señal tiene algún efecto aparte de hacer que sleep() retorne.

Si una función de captura de señales interrumpe sleep() y examina o cambia la hora en que se programa la generación de un SIGALRM, la acción asociada con la señal SIGALRM, o si la señal SIGALRM está bloqueada para su entrega, los resultados son indeterminados.

Si una función de captura de señales interrumpe sleep() y llama a siglongjmp() o longjmp() para restaurar un entorno guardado antes de la llamada a sleep(), la acción asociada con la señal SIGALRM y la hora en que se programa la generación de una señal SIGALRM son indeterminadas. También es indeterminado si la señal SIGALRM está bloqueada, a menos que la máscara de señales del proceso se restaure como parte del entorno.

Las interacciones entre sleep() y setitimer() son indeterminadas.

VALOR DE RETORNO

Si sleep() retorna porque ha transcurrido el tiempo solicitado, el valor devuelto será 0. Si sleep() retorna debido a la entrega de una señal, el valor de retorno será la cantidad de tiempo "no dormido" (tiempo solicitado menos tiempo realmente dormido) en segundos.

ERRORES

No se definen errores.

FUNDAMENTO RACIONAL

Existen dos enfoques generales para la implementación de la función sleep(). Uno es utilizar la función alarm() para programar una señal SIGALRM y luego suspender el hilo que llama esperando esa señal. El otro es implementar una facilidad independiente. Este volumen de POSIX.1‐2017 permite cualquiera de los enfoques en programas monotarea, pero la simple implementación de alarma/suspensión no es apropiada para programas multihilo.

Para cumplir con el requisito de que ninguna primitiva cambie un atributo del proceso a menos que se describa explícitamente en este volumen de POSIX.1‐2017, una implementación que utiliza SIGALRM debe tener en cuenta cuidadosamente cualquier señal SIGALRM programada por llamadas anteriores a alarm(), la acción establecida previamente para SIGALRM y si SIGALRM estaba bloqueada. Si se ha programado una SIGALRM antes de que sleep() se complete normalmente, sleep() debe acortarse a ese tiempo y se debe generar una SIGALRM (posiblemente simulada mediante la invocación directa de la función de captura de señales) antes de que sleep() retorne. Si se ha programado una SIGALRM después de que sleep() se complete normalmente, debe reprogramarse para la misma hora antes de que sleep() retorne. La acción y el bloqueo de SIGALRM deben guardarse y restaurarse.

Las implementaciones históricas a menudo implementan la versión basada en SIGALRM utilizando alarm() y pause(). Una de esas implementaciones es propensa a bloqueos infinitos, como se describe en pause(). Otra implementación utiliza las funciones del lenguaje C setjmp() y longjmp() para evitar esa ventana. Esa implementación introduce un problema diferente: cuando la señal SIGALRM interrumpe una función de captura de señales instalada por el usuario para capturar otra señal, longjmp() aborta esa función de captura de señales. Una implementación basada en sigprocmask(), alarm() y sigsuspend() puede evitar estos problemas.

A pesar de toda la diligencia razonable, existen varias diferencias muy sutiles, pero detectables e inevitables, entre los dos tipos de implementaciones. Estos son los casos mencionados en este volumen de POSIX.1‐2017 donde ocurre alguna otra actividad relacionada con SIGALRM, y los resultados se declaran como indeterminados. Todos estos casos son lo suficientemente inusuales como para no preocupar a la mayoría de las aplicaciones.

Consulte también la discusión del término tiempo real en alarm().

Dado que sleep() se puede implementar utilizando alarm(), la discusión sobre las alarmas que ocurren temprano bajo alarm() se aplica también a sleep().

Los desarrolladores de aplicaciones deben tener en cuenta que el tipo del argumento segundos y el valor de retorno de sleep() es unsigned. Esto significa que una Aplicación de Interfaces de Sistemas POSIX Estrictamente Conforme no puede pasar un valor mayor que el valor mínimo garantizado para {UINT_MAX}, que el estándar ISO C establece en 65535, y cualquier aplicación que pase un valor mayor está restringiendo su portabilidad. Se consideró un tipo diferente, pero las implementaciones históricas, incluidas aquellas con un tipo int de 16 bits, utilizan consistentemente unsigned o int.

Los retrasos en la planificación pueden hacer que el proceso retorne de la función sleep() significativamente después del tiempo solicitado. En tales casos, el valor de retorno debe establecerse en cero, ya que la fórmula (tiempo solicitado menos tiempo transcurrido) produce un número negativo y sleep() devuelve un unsigned.

DIRECCIONES FUTURAS

Una versión futura de este estándar puede requerir que sleep() no utilice SIGALRM en todos los programas, no solo en los multihilo.

NAME

sleep - suspend execution for an interval of time

SYNOPSIS

#include <unistd.h>

unsigned int sleep(unsigned int seconds);

DESCRIPTION

The sleep() function shall cause the calling process (or thread) to be suspended for the number of seconds specified by seconds. The actual suspension time may be less than that requested because of the system's scheduling resolution and the actions of other processes or threads. If the value of seconds is zero, sleep() shall return immediately.

If sleep() is interrupted by a signal, it shall return the amount of time remaining in seconds.

The system's concept of time of day is not affected by sleep().

On some systems, sleep() might be implemented using timers that are not affected by changes to the system's time-of-day clock. On other systems, it might be implemented using timers that are affected by such changes. Refer to the system's documentation for details.

RETURN VALUE

The sleep() function shall return the number of seconds remaining in the interval if the suspension was interrupted by a signal. If the interval expired normally, it shall return 0.

ERRORS

No errors are defined.

EXAMPLES

None.

APPLICATION USAGE

The sleep() function is suitable for use by both processes and threads.

RATIONALE

None.
