SLAPO-REMOTEAUTH(5) Manual de formatos de archivo SLAPO-REMOTEAUTH(5)

NOMBRE

slapo-remoteauth - Delegar solicitudes de autenticación a directorios remotos, p. ej., Active Directory

SINOPSIS

/etc/openldap/slapd.conf

DESCRIPCIÓN

El overlay remoteauth de slapd(8) proporciona autenticación de paso a servidores de directorio remotos, p. ej., Active Directory, para operaciones de enlace simple LDAP. La entrada LDAP local referenciada en la operación de enlace se mapea a su contraparte en el directorio remoto. Se realiza una operación de enlace LDAP contra el directorio remoto y los resultados se devuelven basándose en los de la operación remota.

Un servidor slapd configurado con el overlay remoteauth maneja una solicitud de autenticación basándose en la presencia de userPassword en la entrada local. Si userPassword está presente, la autenticación se realiza localmente; de lo contrario, el overlay remoteauth realiza la solicitud de autenticación al servidor de directorio remoto configurado.

CONFIGURACIÓN

Las siguientes opciones se pueden aplicar al overlay remoteauth dentro del archivo slapd.conf. Todas las opciones deben seguir la directiva overlay remoteauth.

overlay remoteauth
Esta directiva agrega el overlay remoteauth a la base de datos actual, ver slapd.conf(5) para más detalles.
remoteauth_dn_attribute <dnattr>
Atributo en la entrada local que se utiliza para almacenar el DN de enlace a un servidor de directorio remoto.
remoteauth_mapping <dominio> <hostname|URI LDAP|file:///ruta/a/lista/de/hostnames>
Para una implementación que no sea de Windows, un dominio puede considerarse una colección de uno o más hosts contra los cuales el servidor slapd se autentica en nombre de los usuarios que se autentican. Para un nombre de dominio dado, el mapeo especifica el(los) servidor(es) de destino, por ejemplo, controlador(es) de dominio de Active Directory, con los que conectarse a través de LDAP. El segundo argumento puede proporcionarse como un nombre de host, una URI LDAP o un archivo que contenga una lista de nombres de host/URI, uno por línea. Los nombres de host se prueban en secuencia hasta que la conexión tenga éxito.

Esta opción se puede proporcionar más de una vez para proporcionar información de mapeo para diferentes dominios. Por ejemplo:

    remoteauth_mapping americas file:///ruta/a/hosts/dominio/americas
    remoteauth_mapping asiapacific file:///ruta/a/hosts/dominio/asiapacific
    remoteauth_mapping emea emeadc1.emea.example.com
remoteauth_domain_attribute <attr>
Atributo en la entrada local que especifica el nombre del dominio, se ignora cualquier texto después de "\" o ":".
remoteauth_default_domain <dominio predeterminado>
Dominio predeterminado.
remoteauth_default_realm <servidor>
Servidor de reserva al que conectarse para dominios no especificados en remoteauth_mapping.
remoteauth_retry_count <num>
Número de reintentos de conexión. El valor predeterminado es 3.
remoteauth_store <on|off>
Si se debe almacenar la contraseña en la entrada local tras un enlace exitoso. El valor predeterminado es 'off'.

remoteauth_tls [starttls=yes] [tls_cert=<archivo>] [tls_key=<archivo>] [tls_cacert=<archivo>] [tls_cacertdir=<ruta>] [tls_reqcert=never|allow|try|demand] [tls_reqsan=never|allow|try|demand] [tls_cipher_suite=<cifrados>] [tls_ecname=<nombres>] [tls_crlcheck=none|peer|all]

Configuración TLS específica de remoteauth, ver slapd.conf(5) para más detalles sobre cada uno de los parámetros y valores predeterminados.
remoteauth_tls_peerkey_hash <hostname> <nombrehash>:<base64 del hash de la clave pública>
Mapeo entre los nombres de host del servidor remoto y sus hashes de clave pública. Solo se admite un mapeo por nombre de host y, si se especifican pines, todos los hosts deben estar anclados. Si se establece, el anclaje está en vigor independientemente de si la validación del nombre del certificado está habilitada o no por tls_reqcert.

EJEMPLO

A continuación se muestra un ejemplo típico de configuración del overlay remoteauth para AD (como un fragmento de slapd.conf(5)):

   database <base de datos>
   #...
   overlay remoteauth
   remoteauth_dn_attribute seeAlso
   remoteauth_domain_attribute associatedDomain
   remoteauth_default_realm americas.example.com
   remoteauth_mapping americas file:///home/ldap/etc/remoteauth.americas
   remoteauth_mapping emea emeadc1.emea.example.com
   remoteauth_tls starttls=yes tls_reqcert=demand tls_cacert=/home/ldap/etc/example-ca.pem
   remoteauth_tls_peerkey_hash ldap.americas.tld sha256:Bxv3MkLoDm6gt/iDfeGNdNNqa5TTpPDdIwvZM/cIgeo=

Donde seeAlso contiene el DN de enlace de AD para el usuario, associatedDomain contiene el ID de Dominio de Windows en el formato <nombre de dominio NT>:<nombre de usuario NT>, en el que se ignora todo lo que sigue, incluido ":".
