NOMBRE

slapo-otp - Módulo de contraseñas de un solo uso (OTP) de OATH

SINOPSIS

moduleload otp.la

DESCRIPCIÓN

El módulo otp permite utilizar la autenticación de contraseña de un solo uso basada en tiempo (también conocida como "estilo autenticador") y basada en HMAC junto con una contraseña LDAP estándar para la autenticación de dos factores.

Con este módulo, los usuarios usarían su contraseña, seguida de la contraseña de un solo uso en la solicitud de contraseña para autenticarse.

La contraseña necesaria para que un usuario se autentique se calcula basándose en un contador (tiempo actual en caso de TOTP) y una clave que se referencia en la entrada LDAP del usuario. Dado que la contraseña se basa en el tiempo o el número de usos, cambia periódicamente. Una vez utilizada, no se puede volver a usar, por lo que se frustran los keyloggers y los espías por encima del hombro. Una aplicación de teléfono móvil, como Google Authenticator o YubiKey (un prover), se puede usar para calcular la contraseña de un solo uso actual del usuario, que se expresa como un número (generalmente de seis dígitos).

Alternativamente, el valor puede ser calculado por alguna otra aplicación con acceso a la clave del usuario y entregado al usuario a través de SMS o algún otro canal. Cuando se le solicite autenticarse, el usuario simplemente agrega el código proporcionado por el prover al final de su contraseña al autenticarse.

Esta implementación cumple con RFC 4226 HOTP HMAC-Based One Time Passwords y RFC 6238 TOTP Time-based One Time Passwords e incluye soporte para los algoritmos HMAC SHA-1, SHA-256 y SHA-512.

La clave HMAC utilizada en el cálculo de OTP se almacena en la entrada oathOTPToken referenciada en la entrada LDAP del usuario, y los parámetros se almacenan en la entrada oathOTPParams de LDAP referenciada en el token.

CONFIGURACIÓN

Una vez que el módulo está configurado en la base de datos, interceptará los enlaces simples LDAP para usuarios cuya entrada LDAP tenga alguna de las clases de objetos derivadas de oathOTPUser adjuntas a ella. Los atributos que enlazan al usuario y al secreto compartido son:

oathTOTPToken: <dn>
Obligatorio para oathTOTPUser, indica que la entrada nombrada está destinada a contener el secreto compartido de contraseña de un solo uso basada en tiempo y la última contraseña utilizada.
oathHOTPToken: <dn>
Obligatorio para oathHOTPUser, indica que la entrada nombrada está destinada a contener el secreto compartido de contraseña de un solo uso y la última contraseña utilizada.
oathTOTPParams: <dn>
Obligatorio para oathTOTPToken, indica que la entrada nombrada está destinada a contener los parámetros para generar el secreto compartido de contraseña de un solo uso basada en tiempo: su longitud y el algoritmo a utilizar, así como la longitud de cada paso de tiempo y el período de gracia.
oathHOTPParams: <dn>
Obligatorio para oathHOTPToken, indica que la entrada nombrada está destinada a contener los parámetros para generar el secreto compartido de contraseña de un solo uso: su longitud y el algoritmo a utilizar, así como el número permitido de contraseñas a omitir.

Se implementan las siguientes partes del esquema OATH-LDAP.

Atributos generales:

oathSecret: <datos>
El secreto compartido se almacena aquí como bytes crudos.
oathOTPLength: <longitud>
La longitud de la contraseña, generalmente 6.
oathHMACAlgorithm: <OID>
El OID del algoritmo hash a utilizar según se define en RFC 8018. Los algoritmos compatibles incluyen SHA1, SHA224, SHA256, SHA384 y SHA512.

Los atributos HOTP:

oathHOTPLookAhead: <número>
El número de tokens HOTP sucesivos que se pueden omitir.
oathHOTPCounter: <número>
El orden del último token HOTP canjeado con éxito por el usuario.

Los atributos TOTP:

oathTOTPTimeStepPeriod: <segundos>
La duración del período de paso de tiempo para el cálculo de TOTP.
oathTOTPLastTimeStep: <número>
El orden del último token TOTP canjeado con éxito por el usuario.
oathTOTPTimeStepWindow: <número>
El número de períodos de tiempo alrededor de la hora actual a probar al verificar la contraseña proporcionada por el usuario.
oathTOTPTimeStepDrift: <número>
Si el cliente no proporcionó el token correcto pero aun así encajó con oathTOTPTimeStepWindow arriba, este atributo registra el desplazamiento actual para proporcionar la deriva lenta del reloj del dispositivo cliente.
