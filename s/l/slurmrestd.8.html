slurmrestd(8) Daemon REST de Slurm slurmrestd(8)

NOMBRE

slurmrestd - Interfaz a Slurm a través de la API REST.

SINOPSIS

slurmrestd [OPCIONES...] <[host]:puerto|unix:/ruta/a/socket>...

DESCRIPCIÓN

slurmrestd es una interfaz de API REST para Slurm. Puede usarse en dos modos:

Modo Inetd: slurmrestd leerá y escribirá en STDIO. Si STDIN es un descriptor de archivo de socket, slurmrestd lo detectará y usará la funcionalidad relevante. Este modo está diseñado para funcionar con entrada redirigida, inetd, xinetd o activación de socket systemd.

Modo de escucha: slurmrestd abrirá un socket de escucha en cada par host:puerto o socket UNIX solicitado.

OPCIONES

[https://][host]:puerto
Nombre de host y puerto contra los que escuchar. host puede ser una IP IPv4/IPv6 o un nombre de host resoluble. Los nombres de host solo se buscan al inicio y no cambian durante la vida del proceso. host es opcional; si no se proporciona, slurmrestd escuchará en todas las interfaces de red. https:// es opcional; si no se proporciona, slurmrestd usará automáticamente el plugin TLS para cifrar el tráfico cuando sea posible. Si se especifica https://; slurmrestd requerirá que el plugin TLS configurado cifre el tráfico.
unix:///ruta/a/socket
Escuchar en un socket UNIX local. Debe tener permisos para crear el socket en el sistema de archivos.
-a <plugin>[,plugin]...
Lista separada por comas de plugins de autenticación a cargar. Por defecto, se cargarán todos los plugins de autenticación disponibles.
list
Muestra una lista de los plugins posibles a cargar.
rest_auth/local
Permite la autenticación a través de sockets UNIX cuando auth/munge está activo.
NOTA: slurmrestd y los procesos cliente deben ejecutarse bajo la misma UID o se rechazarán las solicitudes del cliente.
rest_auth/jwt
Permite la autenticación a través de sockets TCP y UNIX cuando AuthAltTypes=auth/jwt está activo. El usuario debe especificar las siguientes cookies HTTP con cada solicitud:
X-SLURM-USER-NAME:<nombre de usuario>
X-SLURM-USER-TOKEN:<JSON Web Token>
NOTA: Los tokens normalmente se generan llamando a "scontrol token".
-d <plugin>[,plugin]...
Lista separada por comas de plugins data_parser, que determinarán el formato de salida. Puede incluir flags opcionales denotados por el símbolo '+'. Por defecto, se cargarán todos los plugins data_parser disponibles sin flags opcionales. Ver también -s para los plugins OpenAPI que controlan el contenido disponible. Por defecto: todos los plugins data_parser integrados soportados.
list[+flags]
Muestra una lista de los plugins posibles a cargar.
latest
Reemplazado automáticamente con la última versión del plugin. Ver el plugin relevante para su descripción y posibles flags.
[data_parser/]v0.0.40[+fast]
Carga el plugin data_parser/]v0.0.40 para el formato de datos. Solo compatible con los plugins de contenido openapi/slurmctld y openapi/slurmdbd.
+fast
Desactiva advertencias integradas y otra lógica para validar estrictamente las solicitudes entrantes. Solo debe usarse en un entorno de producción con clientes muy bien probados y las solicitudes potencialmente mal formateadas se aceptarán tal cual y no se generarán advertencias sobre campos o valores ignorados o incorrectos.
[data_parser/]v0.0.41[+fast][+prefer_refs]
Carga el plugin data_parser/]v0.0.41 para el formato de datos. Solo compatible con los plugins de contenido openapi/slurmctld y openapi/slurmdbd.
+fast
Desactiva advertencias integradas y otra lógica para validar estrictamente las solicitudes entrantes. Solo debe usarse en un entorno de producción con clientes muy bien probados y las solicitudes potencialmente mal formateadas se aceptarán tal cual y no se generarán advertencias sobre campos o valores ignorados o incorrectos.

OPTIONS

-f <file>
Leer la configuración de Slurm del archivo especificado. Ver NOTAS a continuación.
--generate-openapi-spec
Volcar la especificación OpenAPI en formato JSON a la salida estándar y salir inmediatamente. Carga los plugins mínimos requeridos. Todos los campos de "content" estarán solo en formato JSON, incluso si el plugin serializer/yaml está presente y es cargable. La carga de slurm.conf(5) puede ser deshabilitada pasando los argumentos adicionales -f /dev/null o estableciendo SLURM_CONF=/dev/null en el entorno.
-g <id de grupo>
Cambiar el id de grupo (y descartar grupos suplementarios) antes de procesar la solicitud del cliente. Este debe ser un grupo único sin acceso de escritura ni permisos especiales. No lo establezcas al grupo que pertenece a SlurmUser o root, o el demonio no se iniciará con la configuración por defecto.
-h, --help
Ayuda; imprime un resumen breve de las opciones del comando.
--max-connections <contador>
Establece el número máximo de conexiones a procesar en cualquier momento. Esto es independiente del número de conexiones que pueden conectarse a slurmrestd en cualquier momento. El kernel permite que cualquier número de conexiones esté pendiente para ser procesado en cualquier momento cuando las cookies SYN están activas.
Precaución:
Cada conexión podría causar una RPC a los demonios controladores, llevando a una sobrecarga potencial del controlador. Cada conexión también puede mantener memoria durante la vida de la conexión. Tener demasiadas conexiones procesándose a la vez podría consumir considerablemente más memoria. Los límites de procesos (ulimit(3)) podrían requerir ajuste cuando este valor se incrementa.
Por defecto: 124
-s <plugin>[,plugin]...
Lista separada por comas de plugins OpenAPI a cargar, que determinarán el contenido disponible. Por defecto, los plugins OpenAPI cargados serán slurmctld,slurmdbd cuando AccountingStorageType=accounting_storage/slurmdbd esté configurado en slurm.conf(5) o slurmctld para cualquier otra configuración. Ver también -d para los plugins data_parser que controlan el formato de salida.
list
Muestra una lista de los plugins posibles a cargar.
[openapi/]slurmctld
Proporciona endpoints 'slurm/' para los plugins data_parser cargados.
[openapi/]slurmdbd
Proporciona endpoints 'slurmdb/' para los plugins data_parser cargados. Este plugin fallará si accounting_storage/slurmdbd no se usa en el cluster.
[openapi/]util
Proporciona endpoints 'util/' para los plugins data_parser cargados. Util es acrónimo de utilidad. Proporciona utilidades disponibles directamente a través de slurmrestd.
-t <NÚMERO DE HILOS>
Especifica el número de hilos a usar para procesar conexiones de clientes. Ignorado en modo inetd.
-u <id de usuario>
Cambia el id de usuario antes de procesar la solicitud del cliente. Este debe ser un grupo único sin acceso de escritura ni permisos especiales. No establezcas este usuario a SlurmUser o root, o el demonio no se iniciará con la configuración por defecto.
-v
Operación detallada. Se pueden especificar múltiples v's, con cada 'v' más allá del primero incrementando la verbosidad, hasta 6 veces (es decir, -vvvvvv). Niveles de verbosidad más altos tendrán un impacto significativo en el rendimiento. Ver SLURMRESTD_DEBUG para la descripción de los destinos de registro.
-V
Imprime la información de la versión y sale.

TLS

slurmrestd soporta cifrado TLS a través de la interfaz de plugin TLS. Para una descripción detallada del soporte TLS en Slurm, ver https://slurm.schedmd.com/tls.html.

slurmrestd soporta cifrado TLS para conexiones HTTPS entrantes independientemente de cómo esté configurado TLSType en slurm.conf(5). La configuración de TLSParameters en slurm.conf(5) siempre se aplica. Esto permite que la capa RPC de Slurm permanezca sin cifrar a través de TLS, mientras que permite a slurmrestd servir solicitudes HTTPS a través de TLS.

slurmrestd incluye detección automática de conexiones TLS entrantes. Si el plugin TLS está completamente configurado y se carga con éxito al inicio, entonces todas las nuevas conexiones entrantes serán marcadas para apretones de manos SSLv3 (según RFC#6101) y TLSv1.x (según RFC#8446). Tras una coincidencia de marca, cada conexión entrante será entonces cifrada a través del plugin TLS configurado durante la duración de la conexión. El soporte para TLS se maneja independientemente de si la conexión es un [unix(2)] socket(2) o pipe(2) (en modo INETD). Las conexiones de escucha creadas con https:// requerirán ser cifradas a través del plugin TLS. Cualquier conexión entrante a estos oyentes sin cifrado TLS será cerrada inmediatamente sin enviar una respuesta de error al cliente.

El soporte TLS en slurmrestd depende de los requisitos del plugin TLS. slurmrestd intentará cargar el primer plugin TLS disponible (excepto tls/none) automáticamente al inicio. Los requisitos para cada plugin se enumeran a continuación:

tls/s2n
Los siguientes archivos deben estar presentes y ser legibles por el usuario que invoca (antes de que se aplique -u <id de usuario>) al inicio:
restd_cert_file.pem
Certificado público del servidor TLS x509. Debe ser firmado por una CA confiable por los clientes. El CN (nombre común) del certificado debe coincidir con el nombre del host. slurmrestd ignora el host en las solicitudes HTTP del cliente, pero la mayoría de los clientes TLS requerirán que coincidan.

Nota: El archivo del certificado debe colocarse en el directorio de instalación de la variable sysconfdir de autoconf(1), que puede ser anulado estableciendo TLSParameters=restd_cert_file=/ruta/a/restd_cert_file.pem en slurm.conf(5).

restd_cert_key_file.pem
Clave privada para restd_cert_file.pem. Este archivo debe ser únicamente legible por el usuario de slurmrestd.

Nota: El archivo del certificado debe colocarse en el directorio de instalación de la variable sysconfdir de autoconf(1), que puede ser anulado estableciendo TLSParameters=restd_cert_key_file=/ruta/a/restd_cert_key.pem en slurm.conf(5).

VARIABLES DE ENTORNO

Las siguientes variables de entorno pueden ser usadas para anular la configuración compilada en slurmrestd.

ABORT_ON_FATAL
Cuando se detecta un error fatal, usa abort() en lugar de exit() para terminar el proceso. Esto permite capturar rastreos sin recompilar Slurm.
SLURM_CONF
La ubicación del archivo de configuración de Slurm.
SLURM_DEBUG_FLAGS
Especifica las banderas de depuración que slurmrestd debe usar. Ver DebugFlags en la página del manual de slurm.conf(5) para una lista completa de banderas. La variable de entorno tiene precedencia sobre la configuración en slurm.conf.
SLURM_DEBUG
Establece el nivel de depuración explícitamente. Los valores válidos son 0-9, o los mismos valores de cadena que las opciones de depuración como SlurmctldDebug en slurm.conf(5). Se incrementa si se pasa -v como argumento durante la invocación. Se ignora si SLURMRESTD_DEBUG o SLURMRESTD_DEBUG_STDERR o SLURMRESTD_DEBUG_SYSLOG están establecidos en el entorno. Ver SLURMRESTD_DEBUG para la descripción de los destinos de registro.
SLURMRESTD_JSON o SLURM_JSON
Controla la serialización JSON:
compact
Produce JSON lo más compacto posible.
pretty
Produce JSON en formato bonito para hacerlo más legible.
SLURM_JWT
Esta variable debe configurarse para usar la autenticación por token JWT.
SLURMRESTD_AUTH_TYPES
Establece los tipos de autenticación permitidos. Ver -a
SLURMRESTD_DEBUG
Establece el nivel de depuración explícitamente. Los valores válidos son 0-9, o los mismos valores de cadena que las opciones de depuración como SlurmctldDebug en slurm.conf(5). Si se detecta una TTY de control, el modo interactivo se activará automáticamente para proporcionar información de registro adicional a stderr. Si no se detecta una TTY de control, los registros se envían a syslog. Se incrementa si se pasa -v como argumento durante la invocación. Se ignora si SLURMRESTD_DEBUG_STDERR o SLURMRESTD_DEBUG_SYSLOG se establecen en el entorno.
SLURMRESTD_DEBUG_STDERR
Establece el nivel de depuración explícitamente para el registro en STDERR. Los valores válidos son 0-9, o los mismos valores de cadena que las opciones de depuración como SlurmctldDebug en slurm.conf(5). Se incrementa si se pasa -v como argumento durante la invocación.
SLURMRESTD_DEBUG_SYSLOG
Establece el nivel de depuración explícitamente para el registro en syslog. Los valores válidos son 0-9, o los mismos valores de cadena que las opciones de depuración como SlurmctldDebug en slurm.conf(5). Se incrementa si se pasa -v como argumento durante la invocación.
SLURMRESTD_DATA_PARSER_PLUGINS
Lista de plugins data_parser separados por comas para cargar. Ver -d
SLURMRESTD_LISTEN
Lista de pares host:puerto o sockets unix separados por comas en los que escuchar.
SLURMRESTD_MAX_CONNECTIONS
Establece el número máximo de conexiones a procesar en un momento dado. Ver --max-connections
SLURMRESTD_OPENAPI_PLUGINS
Lista de plugins OpenAPI separados por comas para cargar. Ver -s
SLURMRESTD_RESPONSE_STATUS_CODES
Lista de respuestas de métodos OpenAPI separadas por comas para generar en la especificación OpenAPI. Predeterminado: 200,default
SLURMRESTD_SECURITY
Controla la funcionalidad de seguridad de slurmrestd utilizando los siguientes valores separados por comas:
become_user
Permite que slurmrestd se ejecute como root para convertirse en el usuario solicitante para todas las solicitudes. Cuando se combina con rest_auth/local, cuando un usuario se conecta a través de un socket UNIX denominado, slurmrestd realizará un setuid()/setgid() en ese usuario/grupo y luego completará todas las solicitudes como el usuario dado. Este modo solo está previsto para el modo inet, ya que el cambio de usuario es permanente durante la vida del proceso. Este modo es incompatible con rest_auth/jwt y se sugiere iniciar slurmrestd con los argumentos ""-a rest_auth/local"".
disable_unshare_files
Deshabilita la desvinculación de descriptores de archivo con el proceso padre.
disable_unshare_sysv
Deshabilita la desvinculación del espacio de nombres SYSV.
disable_user_check
Deshabilita la verificación de que slurmrestd no se está ejecutando como root o SlurmUser, o con el grupo principal de root o SlurmUser. Deshabilitar esta verificación permitirá que slurmrestd se ejecute como root o SlurmUser, lo que permitirá que cualquiera que pueda comunicarse con este demonio ejecute cualquier cosa como el usuario root en el clúster.
SLURMRESTD_YAML o SLURM_YAML
Controla la serialización YAML:
compact
Genera YAML lo más compacto posible.
no_tag
Genera YAML sin etiquetas !! de tipo de datos.
pretty
Genera YAML en formato bonito para que sea más legible.

SEÑALES

SIGINT
slurmrestd se apagará limpiamente.
SIGPIPE
Esta señal se ignora explícitamente.
SIGPROF
Registra el estado del gestor de conexiones cuando el nivel de depuración es al menos info.

NOTAS

Los plugins SPANK y clifilter no son compatibles en slurmrestd debido a su falta de seguridad en hilos. Los plugins SPANK activos y los JobSubmitPlugins en slurmctld son independientes de slurmrestd y se pueden utilizar para aplicar políticas del sitio en las presentaciones de trabajos.

EJEMPLOS

Generar el esquema OpenAPI sin configuración

$ slurmrestd -f /dev/null  --generate-openapi-spec -s slurmdbd,slurmctld -d v0.0.42 > openapi.json

Iniciar slurmrestd con un socket UNIX en modo escucha:

$ export SLURMRESTD=/var/spool/slurm/restd/rest
$ slurmrestd -s slurmctld,slurmdbd -d v0.0.42 unix:$SLURMRESTD

Verificar la conectividad con slurmctld con un ping, con slurmrestd ejecutándose en modo escucha:

$ export $(scontrol token)
$ curl --unix-socket "${SLURMRESTD}" -H "X-SLURM-USER-TOKEN:${SLURM_JWT}" 'http://ignored_with_unix_sockets/slurm/v0.0.42/ping' | jq '.pings'
