slurmctld(8) Daemon de Slurm slurmctld(8)

NOMBRE

slurmctld - El daemon de gestión central de Slurm.

SINOPSIS

slurmctld [OPCIONES...]

DESCRIPCIÓN

slurmctld es el daemon de gestión central de Slurm. Monitoriza todos los demás daemons y recursos de Slurm, acepta trabajos (jobs) y asigna recursos a esos trabajos. Dada la funcionalidad crítica de slurmctld, puede haber un servidor de respaldo para asumir estas funciones en caso de que falle el servidor principal.

OPCIONES

-c
Borra todo el estado previo de slurmctld de su último checkpoint. Con esta opción, todos los trabajos, tanto en ejecución como en cola, y todos los estados de los nodos, se eliminarán. Sin esta opción, los trabajos ejecutados previamente se conservarán junto con el estado del nodo DOWN, DRAINED y DRAINING y el campo Reason asociado a esos nodos. NOTA: Es raro que quieras usar esto en producción, ya que todos los trabajos serán eliminados.
-D
Ejecuta slurmctld en primer plano con el registro copiado a stderr. Esto limita la resiliencia de 'scontrol reconfigure' y debe evitarse en producción.
-f <archivo>
Lee la configuración del archivo especificado. Ver NOTAS abajo.
-h
Ayuda; imprime un breve resumen de las opciones del comando.
-i
Ignora los errores encontrados al leer los archivos de estado al inicio. Advertencia: El uso de esta opción significará la pérdida de los datos que no se pudieron recuperar de los archivos de estado.
-L <archivo>
Escribe los mensajes de registro en el archivo especificado.
-n <valor>
Establece el valor de "nice" del daemon al valor especificado, típicamente un número negativo.
-r
Recupera el estado parcial del último checkpoint: trabajos y estado DOWN/DRAIN de los nodos e información de razón. No se recupera el estado de ninguna partición. Esta es la acción por defecto.
-R
Recupera el estado completo del último checkpoint: trabajos, nodos, estado de particiones y configuraciones de ahorro de energía. Sin esta opción, los trabajos ejecutados previamente se conservarán junto con el estado del nodo DOWN, DRAINED y DRAINING y el campo Reason asociado a esos nodos. No se conservará ningún otro estado de nodo o partición.
-s
Cambia el directorio de trabajo de slurmctld a la ruta de SlurmctldLogFile si es posible, o a Slurm's StateSaveLocation en caso contrario. Si ambos fallan, recurrirá a /var/tmp.
--systemd
Úselo al iniciar el daemon con systemd. Esto permitirá a slurmctld notificar a systemd el nuevo PID al usar 'scontrol reconfigure'.

NOTA: Los parámetros User y Group en el archivo de unidad systemd de slurmctld deben especificar ambos el SlurmUser.

-v
Operación detallada. Se pueden especificar múltiples v, donde cada 'v' adicional al primero aumenta la verbosidad, hasta 6 veces (es decir, -vvvvvv).
-V
Imprime información de la versión y sale.

VARIABLES DE ENTORNO

Las siguientes variables de entorno pueden usarse para sobrescribir la configuración compilada en slurmctld.

ABORT_ON_FATAL
Cuando se detecta un error fatal, usa abort() en lugar de exit() para terminar el proceso. Esto permite capturar rastreos de pila sin recompilar Slurm.
SLURM_CONF
La ubicación del archivo de configuración de Slurm. Esto se ve anulado al especificar explícitamente un archivo de configuración en la línea de comandos.
SLURM_DEBUG_FLAGS
Especifica las banderas de depuración que usará el planificador. Consulte DebugFlags en la página del manual de slurm.conf(5) para obtener una lista completa de las banderas. La variable de entorno tiene prioridad sobre la configuración en slurm.conf.

Servidor HTTP

A menos que se deshabilite mediante CommunicationParameters=disable_http en slurm.conf, slurmctld aceptará solicitudes entrantes conformes a HTTP/1.1 en cualquier socket que esté escuchando, según lo configurado por SlurmctldPort en slurm.conf. La autenticación de las solicitudes HTTP no está soportada. El envoltorio TLS se soporta opcionalmente sin requerir TLSType en slurm.conf. Los siguientes endpoints son compatibles actualmente:

GET /
Obtener la lista de endpoints.
GET /healthz
Comprueba si slurmctld se cargó correctamente.
GET /livez
Comprueba si slurmctld se cargó correctamente.
GET /readyz
Comprueba si slurmctld está listo para aceptar RPCs entrantes.
GET /metrics/jobs
Obtener métricas de trabajos.
GET /metrics/nodes
Obtener métricas de nodos.
GET /metrics/partitions
Obtener métricas de particiones.
GET /metrics/scheduler
Devolver métricas del planificador.
GET /metrics/jobs-users-accts
Devolver métricas de trabajos de usuarios y cuentas.

UBICACIÓN DEL ARCHIVO CORE

Si slurmctld se inicia con la opción -D, el archivo core se escribirá en el directorio de trabajo actual. De lo contrario, si SlurmctldLogFile es un nombre de ruta completamente calificado (que comienza con una barra inclinada), el archivo core se escribirá en el mismo directorio que el archivo de registro, siempre que SlurmUser tenga permiso de escritura en el directorio. CORE FILE LOCATION

The location for core files is set by the CoreFileLocation parameter in slurm.conf(5). If this parameter is not set, then the core file will be placed in the directory specified by the StateSaveLocation, or "/var/tmp/" as a last resort. If none of the above directories have write permission for SlurmUser, no core file will be produced.

SIGNALS

SIGTERM SIGINT SIGQUIT
slurmctld se cerrará limpiamente, guardando su estado actual en el directorio de guardado de estado.
SIGABRT
slurmctld se cerrará limpiamente, guardando su estado actual y realizando un volcado de memoria (core dump).
SIGHUP
Recarga los archivos de configuración de slurm, similar a 'scontrol reconfigure'.
SIGTSTP
Detiene el proceso desde una terminal. Esto también detiene slurmscriptd.
SIGUSR2
Vuelve a leer el nivel de registro de las configuraciones y luego reabre el archivo de registro. Esto debe usarse al configurar logrotate(8).
SIGPROF
Registra el estado del administrador de conexiones cuando el nivel de depuración es al menos info.
SIGCHLD SIGUSR1 SIGXCPU SIGPIPE SIGALRM
Estas señales se ignoran explícitamente.

NOTAS

Puede ser útil experimentar con diferentes parámetros de configuración específicos de slurmctld utilizando un archivo de configuración distinto (por ejemplo, tiempos de espera). Sin embargo, este archivo de configuración especial no será utilizado por el demonio slurmd ni por los programas de Slurm, a menos que se les indique específicamente que lo usen. Si desea cambiar los puertos de comunicación, la ubicación del sistema de archivos temporal u otros parámetros utilizados por otros componentes de Slurm, cambie el archivo de configuración común, slurm.conf.
