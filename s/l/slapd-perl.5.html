SLAPD-PERL(5) Manual de formatos de archivo SLAPD-PERL(5)

NOMBRE

slapd-perl - Backend de Perl para slapd

SINOPSIS

/etc/openldap/slapd.conf

DESCRIPCIÓN

El backend de Perl para slapd(8) funciona incrustando un intérprete de perl(1) en slapd(8). Cualquier sección de base de datos de Perl del archivo de configuración slapd.conf(5) debe especificar qué módulo de Perl utilizar. Slapd crea entonces un nuevo objeto Perl que maneja todas las solicitudes para esa instancia particular del backend.

Deberás crear un método para cada una de las siguientes acciones:

  * new        # crea un nuevo objeto,
  * search     # realiza la búsqueda ldap,
  * compare    # realiza una comparación,
  * modify     # modifica una entrada,
  * add        # añade una entrada al backend,
  * modrdn     # modifica el rdn de una entrada,
  * delete     # elimina una entrada ldap,
  * config     # directivas de configuración específicas del módulo,
  * init       # se llama después de inicializar el backend.

A menos que se especifique lo contrario, los métodos devuelven el código de resultado que se devolverá al cliente. Las acciones no implementadas pueden simplemente devolver unwillingToPerform (53).

new
Este método se llama cuando el archivo de configuración encuentra una línea perlmod. El módulo de esa línea se 'usa' efectivamente en el intérprete de Perl, y luego se llama al método new para crear un nuevo objeto. Ten en cuenta que se pueden instanciar múltiples instancias de ese objeto, como con cualquier objeto Perl. El método new recibe el nombre de la clase como argumento.
search
Este método se llama cuando llega una solicitud de búsqueda de un cliente. Sus argumentos son los siguientes: 
  * referencia al objeto
  * DN base
  * ámbito
  * política de desreferenciación de alias
  * límite de tamaño
  * límite de tiempo
  * cadena de filtro
  * solo atributos (1 para sí)
  * lista de atributos a devolver (puede estar vacía)

Valor de retorno: (código_resultado, entrada_ldif, entrada_ldif, ...)

compare
Este método se llama cuando llega una solicitud de comparación de un cliente. Sus argumentos son los siguientes. 
  * referencia al objeto
  * dn
  * cadena de aserción de atributo
modify
Este método se llama cuando llega una solicitud de modificación de un cliente. Sus argumentos son los siguientes. 
  * referencia al objeto
  * dn
  * una lista formateada como sigue
    ({ "ADD" | "DELETE" | "REPLACE" },
     tipo_atributo, valor...)...
add
Este método se llama cuando llega una solicitud de adición de un cliente. Sus argumentos son los siguientes. 
  * referencia al objeto
  * entrada en formato de cadena
modrdn
Este método se llama cuando llega una solicitud de modrdn de un cliente. Sus argumentos son los siguientes. 
  * referencia al objeto
  * dn
  * nuevo rdn
  * indicar si se elimina el DN antiguo (1 significa sí)
delete
Este método se llama cuando llega una solicitud de eliminación de un cliente. Sus argumentos son los siguientes. 
  * referencia al objeto
  * dn
config
Este método se llama una vez por cada línea perlModuleConfig en el archivo de configuración slapd.conf(5). Sus argumentos son los siguientes. 
  * referencia al objeto
  * matriz de argumentos en la línea

Valor de retorno: distinto de cero si esta no es una opción válida.

init
Este método se llama después de inicializar el backend. Su argumento es el siguiente. 
  * referencia al objeto

Valor de retorno: distinto de cero si la inicialización falló.

CONFIGURACIÓN

Estas opciones de slapd.conf se aplican a la base de datos del backend PERL. Es decir, deben seguir una línea "database perl" y venir antes de cualquier línea posterior de "backend" o "database". Otras opciones de base de datos se describen en la página del manual slapd.conf(5).

perlModulePath /ruta/a/libs
Añade la ruta a la variable @INC.
perlModule NombreMod
'Usa' el nombre del módulo NombreMod de ModName.pm
filterSearchResults
Los resultados de la búsqueda son candidatos que necesitan ser filtrados (con el filtro en la solicitud de búsqueda), en lugar de ser resultados de búsqueda que se devuelven directamente al cliente.
perlModuleConfig <argumentos>
Invoca el método config del módulo con los argumentos dados.

EJEMPLO

Hay un módulo Perl de ejemplo `SampleLDAP' en el directorio slapd/back-perl/ del árbol de código fuente de OpenLDAP.

CONTROL DE ACCESO

El backend perl no respeta ninguna de las semánticas de control de acceso descritas en slapd.access(5); todo el control de acceso se delega a la programación PERL subyacente. Solo se respeta el acceso de lectura (=r) al pseudoatributo entry y a los valores de otros atributos de las entradas devueltas por la operación search, que es realizada por el frontend.

ADVERTENCIA

La interfaz de este backend con el módulo perl PUEDE cambiar. Cualquier sugerencia sería muy apreciada.

Nota: en versiones anteriores, las líneas no reconocidas en el archivo slapd.conf se pasaban al método config del módulo perl. Este comportamiento está obsoleto (pero todavía permitido por compatibilidad con versiones anteriores), y la directiva perlModuleConfig debe usarse en su lugar para invocar el método config del módulo. Esta característica de compatibilidad se eliminará en una fecha futura.

ARCHIVOS

/etc/openldap/slapd.conf
archivo de configuración por defecto de slapd

VER TAMBIÉN

slapd.conf(5), slapd(8), perl(1).

slapd-perl - módulo de backend de base de datos de Archivo de Perl

slapd-perl - módulo de backend de base de datos de Archivo de Perl

SINOPSIS

slapd-perl

DESCRIPCIÓN

El backend de base de datos perl permite que slapd mantenga sus datos en un archivo de texto plano, pero con el acceso y la manipulación de datos dirigidos a través de un script de Perl.

Para obtener más información sobre el formato del archivo y los scripts de Perl, consulte la documentación del backend de la base de datos perl.

CONFIGURACIÓN

Un backend de base de datos perl se configura en el archivo slapd.conf utilizando la siguiente directiva:

database perl
    perl-interpreter <ruta-del-script>
    perl-database <nombre-de-la-base-de-datos>
perl-interpreter <ruta-del-script>
Especifica la ruta al script de Perl que implementa el backend de la base de datos. Este script debe definir una clase Perl adecuada para manejar las operaciones de la base de datos.
perl-database <nombre-de-la-base-de-datos>
Especifica el nombre de la base de datos que se va a utilizar dentro del script de Perl. Esto permite que un único script de Perl maneje varias bases de datos.

MÓDULOS

No hay módulos Perl específicos que deban cargarse explícitamente, ya que el script de Perl proporcionado es responsable de definir toda la funcionalidad.

OPCIONES

Además de las opciones genéricas del backend de base de datos (consulte slapd-config(5)), el backend perl admite:

perl-interpreter <ruta-del-script>
Ruta al script de Perl que implementa el backend de la base de datos.
perl-database <nombre-de-la-base-de-datos>
Nombre de la base de datos a utilizar dentro del script de Perl.

FORMATO

El formato del archivo de datos para el backend perl es completamente definido por el script de Perl proporcionado. El script debe ser capaz de analizar y escribir los datos en el formato elegido.

EJEMPLOS

Aquí hay un ejemplo de una entrada slapd.conf que utiliza el backend perl:

database perl
    perl-interpreter /etc/ldap/scripts/my_perl_db.pl
    perl-database users

En este ejemplo, el script /etc/ldap/scripts/my_perl_db.pl se utiliza para gestionar la base de datos LDAP denominada "users".

HISTORIA

El backend de base de datos perl se introdujo en OpenLDAP 2.4.39.

AUTORES

El backend de base de datos perl fue desarrollado por el equipo de desarrollo de OpenLDAP.

VER TAMBIÉN

slapd.conf(5), slapd-config(5), slapd(8)
