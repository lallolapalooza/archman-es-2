NOMBRE

slurmd - El demonio del nodo de cómputo para Slurm.

SINOPSIS

slurmd [OPCIONES...]

DESCRIPCIÓN

slurmd es el demonio del nodo de cómputo de Slurm. Supervisa todas las tareas que se ejecutan en el nodo de cómputo, acepta trabajo (tareas), lanza tareas y detiene las tareas en ejecución previa solicitud.

OPCIONES

--authinfo
Se usa con configless para establecer un parámetro AuthInfo alternativo que se utilizará para establecer la comunicación con slurmctld antes de que se recupere el archivo de configuración. (Por ejemplo, para especificar una ubicación alternativa del socket MUNGE).
-b
Informa que el nodo se reinició cuando se reinició el demonio. Se utiliza con fines de prueba.
-c
Borra los bloqueos del sistema según sea necesario. Esto puede ser requerido si slurmd terminó de forma anormal.
-C
Imprime la configuración real del hardware (no la configuración del archivo slurm.conf) y sale. El formato de salida es el mismo que se usa en slurm.conf para describir la configuración de un nodo más su tiempo de actividad. Puede usar --parameters para especificar opciones como 'l3cache_as_socket' que pueden alterar la topología del nodo informada.
--ca-cert-file <archivo>
Ruta absoluta al certificado CA utilizado para obtener la configuración al ejecutar sin configuración en un clúster habilitado para TLS.
--conf <parámetros del nodo>
Se usa junto con la opción -Z. Se utiliza para anular o definir parámetros adicionales de un nodo dinámico utilizando la misma sintaxis y parámetros que se usan para definir nodos en slurm.conf. Especificar cualquiera de CPUs, Boards, SocketsPerBoard, CoresPerSocket o ThreadsPerCore anulará los valores predeterminados definidos por la opción -C. NodeName y Port no son compatibles. Esto también se puede usar para especificar la topología de un nodo en la nube, en cuyo caso la bandera -Z no debe usarse (por ejemplo, --conf="topology=topo-switch:s1")

Por ejemplo, si slurmd -C informa

NodeName=node1 CPUs=16 Boards=1 SocketsPerBoard=1 CoresPerSocket=8 ThreadsPerCore=2 RealMemory=31848

las siguientes especificaciones de --conf generarán las definiciones de nodo correspondientes:

--conf "Gres=gpu:2"
NodeName=node1 CPUs=16 Boards=1 SocketsPerBoard=1 CoresPerSocket=8 ThreadsPerCore=2 RealMemory=31848 Gres=gpu:2
--conf "RealMemory=30000"
NodeName=node1 CPUs=16 Boards=1 SocketsPerBoard=1 CoresPerSocket=8 ThreadsPerCore=2 RealMemory=30000
--conf "CPUs=16"
NodeName=node1 CPUs=16 RealMemory=331848
--conf "CPUs=16 RealMemory=30000 Gres=gpu:2"
NodeName=node1 CPUs=16 RealMemory=30000 Gres=gpu:2"
--conf-server <host|dirección ip>[:<puerto>]
Lista separada por comas de controladores, siendo el primero el slurmctld primario. Se puede especificar (opcionalmente) un puerto para cada controlador. Estos hosts son de donde slurmd obtendrá la configuración cuando se ejecute en modo "configless". NOTA: Si se especifica una dirección IPv6, envuelva la <dirección ip> en [] para distinguir la dirección del puerto. Esto es obligatorio incluso si no se especifica ningún puerto.
-d <archivo>
Especifica la ruta completa al programa slurmstepd que se utilizará para supervisar los pasos de trabajos de usuario. Esto puede ser útil con fines de prueba.
-D
Ejecuta slurmd en primer plano con el registro copiado a stderr.
--extra <cadena arbitraria>
Establece datos "extra" al inicio del nodo. Si esta es una cadena json y se establece SchedulerParameters=extra_constraints en slurm.conf, entonces los trabajos pueden usar la opción --extra para filtrar según estos datos "extra".
-f <archivo>
Lee la configuración del archivo especificado. Ver NOTAS abajo.
-F[característica]
Inicia este nodo como un nodo de Futuro Dinámico. Intentará hacer coincidir una definición de nodo con el estado FUTURE, utilizando opcionalmente la característica especificada para hacer coincidir la definición del nodo.
-G
Imprime la configuración de Recursos Genéricos (GRES) (basada en slurm.conf GRES fusionada con el contenido de gres.conf para este nodo) y sale.
-h
Ayuda; imprime un breve resumen de las opciones del comando.
--instance-id <id de instancia en la nube>
Establece el ID de instancia en la nube al inicio del nodo.
--instance-type <tipo de instancia en la nube>
Establece el tipo de instancia en la nube al inicio del nodo.
-L <archivo>
Escribe los mensajes de registro en el archivo especificado.
-M
Bloquea las páginas de slurmd en la memoria del sistema usando mlockall (2) para deshabilitar la paginación del proceso slurmd. Esto puede ayudar en casos donde los nodos se marcan como DOWN durante períodos de actividad intensa de intercambio. Si la llamada al sistema mlockall (2) no está disponible, se imprimirá un error en el registro y slurmd continuará con normalidad.

Se sugiere establecer LaunchParameters=slurmstepd_memlock en slurm.conf(5) al establecer -M.

-n <valor>
Establece el valor de nice del demonio al valor especificado, típicamente un número negativo. Tenga en cuenta también el parámetro de configuración PropagatePrioProcess.
-N <nombre del nodo>
Ejecuta el demonio con el nombre del nodo dado. Se utiliza para emular un sistema más grande con más de un demonio slurmd por nodo. Requiere que Slurm se construya usando la opción de configuración --enable-multiple-slurmd.
--parameters <parámetros de slurmd>
Permite cambios temporales específicos del nodo en SlurmdParameters. Se puede usar junto con -C para especificar opciones como 'l3cache_as_socket' que pueden alterar la topología del nodo informada. Estos parámetros se agregan a cualquier Parámetro específico del nodo definido en slurm.conf.
-s
Cambia el directorio de trabajo de slurmd a la ruta de SlurmdLogFile si es posible, o a SlurmdSpoolDir en caso contrario. Si ambos fallan, recurrirá a /var/tmp.

NOMBRE

slurmd ― Slurm daemon

SINOPSIS

slurmd [-a | --all]
slurmd [-c | --daemonize]
slurmd [-C | --conf_check]
slurmd [-d | --debug]
slurmd [-f configuration file | --conf configuration file]
slurmd [-h | --help]
slurmd [-i | --no-fail-on-error]
slurmd [-k | --kill-nodes]
slurmd [-L log file | --file-log log file]
slurmd [-m | --show-rc]
slurmd [-M machinefile | --machine-file machinefile]
slurmd [-n | --no-srun-no-tty-check]
slurmd [-N node name | --node-name node name]
slurmd [-o | --once]
slurmd [-p | --no-srun-log-level]
slurmd [-P pidfile | --pid-file pidfile]
slurmd [-q | --quiet]
slurmd [-r | --reboot-nodes]
slurmd [-R | --reduce_cpu]
slurmd [-s | --signal-nodes]
slurmd [-S | --systemd]
slurmd [-v | --verbose]
slurmd [-V | --version]
slurmd [-Z]

DESCRIPCIÓN

The slurmd daemon is executed on each compute node in the cluster. It is responsible for starting and terminating process initiation on behalf of slurmctld. The slurmd daemon manages the node's execution of jobs. It communicates with the slurmctld daemon to receive job steps and report status information.

The slurmd daemon is configured by the slurm.conf configuration file. If the configuration file is not specified, then the default location is used.

The slurmd daemon can be started in one of two modes: foreground or background. If the -c or --daemonize option is specified, then slurmd will run in the background as a daemon. Otherwise, it will run in the foreground. The default is to run in the background.

The slurmd daemon can be started with or without the slurm.conf configuration file. If the configuration file is not specified, then slurmd will use the default configuration file location. If the configuration file is specified using the -f or --conf option, then that configuration file will be used.

OPCIONES

-a, --all
When restarting the nodes, attempt to restart all nodes. This is the default behavior.
-c, --daemonize
Run slurmd in the background as a daemon.
-C, --conf_check
Check the configuration file for errors and exit without starting the daemon.
-d, --debug
Enable debug logging. See DebugFlags in the slurm.conf(5) man page for a full list of flags. This option will be overridden by the SLURM_DEBUG_FLAGS environment variable if it is set.
-f configuration file, --conf configuration file
Specify the configuration file to use. If not specified, then slurmd will use the default configuration file location.
-h, --help
Print a help message and exit.
-i, --no-fail-on-error
Do not fail on errors. This option is not recommended for production environments.
-k, --kill-nodes
When restarting the nodes, kill any running jobs before restarting the nodes. This is the default behavior.
-L log file, --file-log log file
Specify the log file to use. If not specified, then slurmd will log to standard error.
-m, --show-rc
Print the return codes of the last RPC to slurmctld and exit.
-M machinefile, --machine-file machinefile
Specify the machine file to use. This file contains a list of nodes to be managed by slurmd. If not specified, then slurmd will manage all nodes specified in the slurm.conf configuration file.
-n, --no-srun-no-tty-check
Disable the check for tty allocation when using srun.
-N node name, --node-name node name
Specify the name of the node to be managed by slurmd. This option is used when slurmd is run on a non-compute node, such as a login node.
-o, --once
Run slurmd only once. This option is used when starting slurmd from a script or other process that will manage the daemon's lifecycle.
-p, --no-srun-log-level
Disable the logging of job step information when using srun.
-P pidfile, --pid-file pidfile
Specify the PID file to use. If not specified, then slurmd will use the default PID file location.
-q, --quiet
Suppress informational messages. Only errors will be logged.
-r, --reboot-nodes
When restarting the nodes, reboot the nodes before restarting them. This is the default behavior.
-R, --reduce_cpu
Reduce the CPU count for jobs that are running on the node. This option is used to conserve CPU resources when the node is not fully utilized.
-s, --signal-nodes
When restarting the nodes, signal the nodes to restart. This is the default behavior.
-S, --systemd
Utilizar cuando se inicia el demonio con systemd. Esto permitirá que slurmd notifique a systemd del nuevo PID al usar 'scontrol reconfigure'.
-v, --verbose
Operación detallada. Múltiples -v aumentan la verbosidad.
-V, --version
Imprimir información de la versión y salir.
-Z
Iniciar este nodo como un nodo normal dinámico. Si no se especifica --conf, entonces slurmd se registrará con la misma configuración de hardware (excepto GRES) que se define con la opción -C.

VARIABLES DE ENTORNO

Las siguientes variables de entorno pueden usarse para anular la configuración compilada en slurmd.

ABORT_ON_FATAL
Cuando se detecta un error fatal, usar abort() en lugar de exit() para terminar el proceso. Esto permite capturar trazas de pila sin recompilar Slurm.
SLURM_CONF
La ubicación del archivo de configuración de Slurm. Esto se anula al nombrar explícitamente un archivo de configuración en la línea de comandos.
SLURM_DEBUG_FLAGS
Especificar las banderas de depuración que debe usar slurmd. Ver DebugFlags en la página man de slurm.conf(5) para una lista completa de banderas. La variable de entorno tiene prioridad sobre la configuración en slurm.conf.

Servidor HTTP

A menos que se deshabilite mediante CommunicationParameters=disable_http en slurm.conf, slurmd aceptará solicitudes entrantes compatibles con HTTP/1.1 en cualquier socket que esté escuchando, según lo configurado por SlurmdPort en slurm.conf. No se admite la autenticación de solicitudes HTTP. Opcionalmente se admite el encapsulado TLS sin requerir TLSType en slurm.conf. Los siguientes endpoints son compatibles actualmente:

GET /
Obtener la lista de endpoints.
GET /healthz
Comprobar si slurmd se cargó correctamente.
GET /livez
Comprobar si slurmd se cargó correctamente.
GET /readyz
Comprobar si slurmd está listo para aceptar RPCs entrantes.

SEÑALES

SIGTERM SIGINT SIGQUIT
slurmd se apagará limpiamente.
SIGHUP
Recarga los archivos de configuración de slurm, similar a 'scontrol reconfigure'.
SIGUSR2
Relee el nivel de registro de las configuraciones y luego reabre el archivo de registro. Esto debería usarse al configurar logrotate(8).
SIGPIPE
Esta señal se ignora explícitamente.

UBICACIÓN DEL ARCHIVO CORE

Si slurmd se inicia con la opción -D, el archivo core se escribirá en el directorio de trabajo actual. De lo contrario, si SlurmdLogFile es un nombre de ruta completamente calificado (que comienza con una barra), el archivo core se escribirá en el mismo directorio que el archivo de registro. De lo contrario, el archivo core se escribirá en el directorio SlurmdSpoolDir, o en "/var/tmp/" como último recurso. Si ninguno de los directorios anteriores se puede escribir, no se producirá ningún archivo core.

NOTAS

Puede ser útil experimentar con diferentes parámetros de configuración específicos de slurmd utilizando un archivo de configuración distinto (por ejemplo, tiempos de espera). Sin embargo, este archivo de configuración especial no será utilizado por el demonio slurmctld ni por los programas de Slurm, a menos que se les indique específicamente que lo utilicen. Si desea cambiar los puertos de comunicación, la ubicación del sistema de archivos temporal u otros parámetros utilizados por otros componentes de Slurm, cambie el archivo de configuración común, slurm.conf.

Si está utilizando el modo sin configuración con un nodo de inicio de sesión que ejecuta muchos comandos cliente, puede considerar ejecutar slurmd en esa máquina para que pueda administrar una versión en caché de los archivos de configuración. De lo contrario, cada comando cliente utilizará el registro DNS para contactar al controlador y obtener la información de configuración, lo que podría generar una carga adicional en el controlador.
