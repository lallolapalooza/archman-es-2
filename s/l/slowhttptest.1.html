SLOWHTTPTEST(1) Manual de Comandos Generales SLOWHTTPTEST(1)

NOMBRE

slowhttptest — Simulador de ataques de Denegación de Servicio

SINOPSIS

slowhttptest [-H|B|R|X] [-g] [-a inicio del rango] [-b límite del rango] [-c número de conexiones] [-d todo el tráfico dirigido a través del proxy HTTP en host:puerto] [-e tráfico de sonda dirigido a través del proxy HTTP en host:puerto] [-f valor de cabecera Content-type] [-i intervalo en segundos] [-k factor de multiplicación de solicitudes] [-l duración de la prueba en segundos] [-m valor de cabecera Accept] [-n intervalo de lectura lenta en segundos] [-o ruta y/o nombre del archivo de salida] [-p tiempo de espera para la conexión de sonda en segundos] [-r conexiones por segundo] [-s valor de cabecera Content-Length] [-t verbo HTTP] [-u URL absoluta] [-v nivel de verbosidad de salida] [-w inicio del rango del tamaño de ventana publicitado] [-x longitud máxima de datos de seguimiento] [-y fin del rango del tamaño de ventana publicitado] [-z lectura lenta en bytes del búfer de recepción]

DESCRIPCIÓN

El slowhttptest implementa la mayoría de los ataques comunes de DoS a nivel de aplicación de bajo ancho de banda y produce archivos CSV y HTML con estadísticas de la prueba.

Actualmente, los ataques soportados son:

  • Slowloris
  • Slow HTTP POST
  • Rango de Cabecera de Apache
  • Lectura Lenta

Las opciones son las siguientes:

-g
Fuerza a slowhttptest a generar archivos CSV y HTML cuando la prueba finaliza con una marca de tiempo en el nombre del archivo.
-H
Inicia slowhttptest en modo SlowLoris, enviando solicitudes HTTP incompletas.
-B
Inicia slowhttptest en modo Slow POST, enviando cuerpos de mensajes HTTP incompletos.
-R
Inicia slowhttptest en modo de Cabecera de Rango, enviando datos maliciosos en la cabecera de Solicitud de Rango.
-X
Inicia slowhttptest en modo de Lectura Lenta, leyendo respuestas HTTP lentamente.
-a inicio
Establece el valor de inicio del especificador de rango para el ataque de Cabecera de Rango.
-b bytes
Establece el valor límite del especificador de rango para el ataque de Cabecera de Rango.
-c número de conexiones
Especifica el número objetivo de conexiones a establecer durante la prueba.
-d host:puerto del proxy HTTP
Especifica el servidor proxy HTTP al que conectarse para todas las conexiones.
-e host:puerto del proxy HTTP
Especifica el servidor proxy HTTP al que conectarse para las conexiones de sonda.
-f tipo-contenido
Especifica el valor de la cabecera Content-Type.
-i segundos
Especifica el intervalo entre los datos de seguimiento para las pruebas slowloris y Slow POST.
-k factor de canalización
Especifica cuántas veces se solicitaría el recurso por socket en la prueba de Lectura Lenta.
-l segundos
Especifica la duración de la prueba en segundos.
-m accept
Especifica el valor de la cabecera Accept.
-n segundos
Especifica el intervalo entre las operaciones de lectura para la prueba de Lectura Lenta.
-o nombre de archivo
Especifica un nombre de archivo personalizado, efectivo con -g.
-p segundos
Especifica el intervalo de espera para la respuesta HTTP en la conexión de sonda, antes de marcar el servidor como DoSed.
-r conexiones por segundo
Especifica la tasa de conexión.
-s bytes
Especifica el valor de la cabecera Content-Length para la prueba Slow POST.
-t verbo HTTP
Especifica el verbo a usar en la solicitud HTTP.
-u URL
Especifica la URL.
-v nivel
Especifica el nivel de verbosidad del registro.
-w bytes
Especifica el inicio del rango del cual se elegirá el tamaño de la ventana TCP publicitada en la prueba de Lectura Lenta.
-x bytes
Especifica la longitud máxima de los datos de seguimiento para las pruebas slowloris y Slow POST.
-y bytes
Especifica el final del rango del cual se elegirá el tamaño de la ventana TCP publicitada en la prueba de Lectura Lenta.
-z bytes
Especifica el número de bytes a leer del búfer de recepción con cada operación read().

EJEMPLOS

Iniciar una prueba slowloris del host host.example.com con 1000 conexiones, las estadísticas van a my_header_stats, el intervalo entre cabeceras de seguimiento es de 10 segundos y la tasa de conexión es de 200 conexiones por segundo:

$ slowhttptest -c 1000 -H -g -o my_header_stats -i 10 -r 200 -t GET -u https://host.example.com/index.html -x 24 -p 3

Iniciar prueba slow POST del host host.example.com con 3000 conexiones, las estadísticas van a my_body_stats, el intervalo entre cabeceras de seguimiento es de 110 segundos, la tasa de conexión es de 200 conexiones por segundo, el valor de la cabecera Content-Length es 8192, la longitud máxima de los datos de seguimiento es un valor aleatorio limitado a 10 bytes y las conexiones de sonda esperan 3 segundos por respuesta HTTP antes de marcar el servidor como DoSed:

NAME

slowhttptest - simple tool to test limits of web server

SYNOPSIS

slowhttptest [-A] [-a H_delay] [-b H_num] [-c num] [-d proxy_addr] [-e proxy_addr] [-f fuzz] [-g] [-h] [-i interval] [-k pipelining] [-l log_file] [-n F_interval] [-p probe_timeout] [-P] [-r rate] [-R] [-s buffer_size] [-S] [-t verb] [-u url] [-v verbosity] [-w W_delay] [-x max_conn] [-X]

DESCRIPTION

The slowhttptest utility is a simple tool designed to test the limits of web server by simulating slow HTTP attacks. The tool supports the Slowloris, Slow Read and Accept methods of DoS attacks. The tool is used for testing the DoS resistance of HTTP servers.

The application is implemented for GNU/Linux and macOS.

EXAMPLES

Start Slowloris test of host.example.com with 1000 connections, connection rate is 200 connections per second, and probe connection waits 10 seconds for HTTP response before marking server as DoSed:

$ slowhttptest -c 1000 -r 200 -t GET -u http://host.example.com/ -x 10 -p 10

Start Slowloris test of host.example.com on port 8080 with 3000 connections, use POST verb, connection rate is 200 connections per second, probe connection waits 3 seconds for HTTP response before marking server as DoSed, and probe connection uses 8192 bytes buffer size:

$ slowhttptest -c 3000 -B -g -o my_body_stats -i 110 -r 200 -s 8192 -t FAKEVERB -u http://host.example.com/loginform.html -x 10 -p 3

Start Range Header test of host.example.com with 1000 connections, use HEAD verb, and generate HTTP header Range:0-, x-1, x-2, x-3, ... x-y, where x is 10 and y is 3000, connection rate is 500: interval between follow up headers is 10 seconds and connection rate is 200 connections per second:

$ slowhttptest -R -u http://host.example.com/ -t HEAD -c 1000 -a 10 -b 3000 -r 500

Start Slow Read test of host.example.com with 8000 connections, no statistics is generated, connection rate is 200 connections per second, TCP advertised window size is a random value between 512 and 1024, slowhttptest reads 32 bytes from each connections every 5 seconds, 3 requests are pipelined per each connections, probe connection waits 3 seconds for HTTP response before marking server as DoSed:

$ slowhttptest -c 8000 -X -r 200 -w 512 -y 1024 -n 5 -z 32 -k 3 -u https://host.example.com/resources/index.html -p 3

Start Slow Read test of host.example.com through HTTP proxy server at 10.10.0.1:8080 with 8000 connections, no statistics is generated, the rest test values are default. slowhttptest most likely would test HTTP proxy server itself, rather than target server, but it all depends on the HTTP proxy server implementation:

$ slowhttptest -d 10.10.0.1:8080 -c 8000 -X -u https://host.example.com/resources/index.html

Start Slow Read test of host.example.com and direct probe traffic through HTTP proxy server at 10.10.0.1:8080 with 8000 connections, no statistics is generated, the rest test values are default. Specifying another connection channel for probe connections helps to make sure that slowhttptest shows valid statistics for availability of server under test:

$ slowhttptest -e 10.10.0.1:8080 -c 8000 -X -u https://host.example.com/resources/index.html
