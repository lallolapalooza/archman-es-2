NOMBRE

slapo-pcache - overlay de caché de proxy para slapd

SINOPSIS

/etc/openldap/slapd.conf

DESCRIPCIÓN

El overlay pcache para slapd(8) permite el almacenamiento en caché de solicitudes de búsqueda LDAP (consultas) en una base de datos local. Para una consulta entrante, la caché de proxy determina su plantilla correspondiente. Si la plantilla se especificó como almacenable en caché usando la directiva pcacheTemplate y la solicitud está contenida en una solicitud en caché, se responde desde la caché de proxy. De lo contrario, la búsqueda se realiza como de costumbre y los resultados de búsqueda almacenables en caché se guardan en la caché para su uso en consultas futuras.

Una plantilla se define mediante una cadena de filtro y un índice que identifica un conjunto de atributos. La cadena de plantilla para una consulta se puede obtener eliminando los valores de aserción de la representación RFC 4515 de su filtro de búsqueda. Una consulta pertenece a una plantilla si su cadena de plantilla y el conjunto de atributos proyectados corresponden a una plantilla almacenable en caché. Ejemplos de cadenas de plantilla son (mail=), (|(sn=)(cn=)), (&(sn=)(givenName=)).

Las directivas de configuración específicas del overlay pcache pueden ir prefijadas con pcache-, para evitar conflictos con directivas específicas de la base de datos subyacente o de otros overlays apilados. Esto puede ser particularmente útil para aquellas directivas que se refieren a la base de datos utilizada para el almacenamiento local. Las siguientes directivas específicas de caché se pueden utilizar para configurar la caché de proxy:

overlay pcache
Esta directiva añade el overlay de caché de proxy a la base de datos actual. El overlay de caché de proxy puede usarse con cualquier base de datos, pero está destinado a usarse con las bases de datos ldap, meta y sql. Tenga en cuenta que la base de datos subyacente debe tener configurado un rootdn.
pcache <base de datos> <max_entradas> <numconjuntos_atributos> <limite_entradas> <periodo_cc>
La directiva habilita el almacenamiento en caché de proxy en la base de datos actual y establece los parámetros generales de la caché. Se utilizará una base de datos <base de datos> internamente para mantener las entradas cacheadas. La base de datos elegida deberá estar configurada también, como se muestra a continuación. El reemplazo de caché se invoca cuando el tamaño de la caché crece hasta <max_entradas> entradas y continúa hasta que el tamaño de la caché cae por debajo de este tamaño. <numconjuntos_atributos> debe ser igual al número de las siguientes directivas pcacheAttrset. Las consultas solo se almacenan en caché si corresponden a una plantilla almacenable en caché (especificada por la directiva pcacheTemplate) y el número de entradas devueltas es menor que <limite_entradas>. La comprobación de consistencia se realiza cada <periodo_cc> duración (especificada en segundos). En cada ciclo, se eliminan las consultas con "tiempo de vida (TTL)" expirado. Una configuración de caché de ejemplo es:
pcache mdb 10000 1 50 100
pcacheAttrset <indice> <attrs...>
Se utiliza para asociar un conjunto de atributos <attrs..> con un <indice>. Cada conjunto de atributos se asocia con un entero de 0 a <numconjuntos_atributos>-1. Estos índices se utilizan en la directiva pcacheTemplate para definir plantillas almacenables en caché. Un conjunto de atributos no puede estar vacío. Un conjunto de atributos puede contener los atributos especiales "*" (todos los atributos de usuario), "+" (todos los atributos operativos) o ambos; en este último caso, cualquier otro atributo es redundante y debe evitarse por claridad. Un conjunto de atributos puede contener "1.1" como único atributo; en este caso, solo se almacena en caché la presencia de las entradas. Los atributos prefijados por "undef:" no necesitan estar presentes en el esquema. El palabra clave "undef" no se puede usar con la base de datos slapd-mdb(5) ya que requiere que todos los elementos del esquema estén completamente definidos.
pcacheMaxQueries <consultas>
Especifica el número máximo de consultas a almacenar en caché. El valor predeterminado es 10000.
pcacheValidate { TRUE | FALSE }
Comprueba si los resultados de una consulta que se está almacenando en caché pueden ser devueltos realmente desde la caché por el DSA proxy. Cuando está habilitado, las entradas que se devuelven almacenando los resultados de una consulta se comprueban para garantizar la consistencia con el esquema conocido por el DSA proxy. En caso de fallo, la consulta no se almacena en caché. Por defecto, la comprobación está desactivada.
pcacheOffline { TRUE | FALSE }
Establece la caché en modo sin conexión. Mientras está sin conexión, el comprobador de consistencia se detendrá y no ocurrirán expiraciones. Esto permite que el contenido de la caché se use indefinidamente mientras el proxy está desconectado de la red hacia el DSA remoto. El valor predeterminado es FALSE, es decir, se realizarán comprobaciones de consistencia y expiraciones.
pcachePersist { TRUE | FALSE }
Especifica si las consultas cacheadas deben guardarse entre reinicios del proxy de caché, para proporcionar un inicio en caliente de la caché. Solo se recargan las consultas no expiradas. El valor predeterminado es FALSE.

ADVERTENCIA: por supuesto, la configuración de la caché de proxy no debe cambiar entre reinicios; el overlay pcache no realiza ninguna comprobación de consistencia en este sentido. En detalle, esta opción debe deshabilitarse a menos que las directivas pcacheAttrset y pcacheTemplate existentes no se cambien ni en orden ni en contenido. Si se agregan nuevos conjuntos y plantillas, o si otros detalles de la configuración del overlay pcache cambiaron, esta característica no debería verse afectada.

pcacheTemplate <cadena_plantilla> <indice_conjunto_atributos> <ttl> [<negttl> [<limitttl> [<ttr>]]]
Especifica una plantilla almacenable en caché y el "tiempo de vida" <ttl> de las consultas que pertenecen a la plantilla. Un <negttl> opcional se puede usar para especificar que los resultados negativos (es decir, consultas que devolvieron cero entradas) también se almacenen en caché durante el tiempo especificado. Los resultados negativos no se almacenan en caché por defecto (<negttl> establecido en 0). Un <limitttl> opcional puede usarse para especificar que los resultados que alcanzan un límite de tamaño también se almacenen en caché durante el tiempo especificado. Los resultados que alcanzan un límite de tamaño no se almacenan en caché por defecto (<limitttl> establecido en 0). Un <ttr> "tiempo de refresco" opcional se puede usar para especificar que las entradas cacheadas deben refrescarse automáticamente después de un cierto tiempo. Las entradas solo se refrescarán mientras no hayan expirado, por lo que el <ttl> debe ser mayor que el <ttr> para que esta opción sea útil. Las entradas no se refrescan por defecto (<ttr> establecido en 0).
pcacheBind <plantilla_filtro> <indice_conjunto_atributos> <ttr> <ambito> <base>
Especifica una plantilla para almacenar en caché credenciales de Simple Bind basadas en una pcacheTemplate ya definida. La <plantilla_filtro> es similar a una <cadena_plantilla> excepto que puede tener algunos valores presentes. Su propósito es permitir que el overlay genere filtros similares a lo que hacen otras aplicaciones cuando realizan una Búsqueda inmediatamente antes de una Vinculación. Por ejemplo, si un cliente como nss_ldap está configurado para buscar un usuario con el filtro "(&(objectClass=posixAccount)(uid=<nombre_usuario>))" entonces la plantilla correspondiente "(&(objectClass=posixAccount)(uid=))" debería usarse aquí. Cuando se convierte a una plantilla regular, por ejemplo "(&(objectClass=)(uid=))", esta plantilla y el <indice_conjunto_atributos> deben coincidir con una cláusula pcacheTemplate ya definida. El "tiempo de refresco" <ttr> determina el intervalo de tiempo después del cual las credenciales cacheadas pueden ser refrescadas. La primera solicitud de Vinculación que ocurra después de ese tiempo desencadenará el intento de refresco. Los refrescos no se realizan cuando el overlay está Desconectado. No hay un parámetro de "tiempo de vida" para las credenciales de Vinculación; las credenciales expirarán según el ttl de pcacheTemplate. El <ambito> y la <base> deben coincidir con el ámbito de búsqueda y la base utilizados por los clientes de autenticación. Las credenciales cacheadas no se almacenan en texto plano, se hashean utilizando el hash de contraseña predeterminado. Por defecto, el almacenamiento en caché de Vinculación no está habilitado.
