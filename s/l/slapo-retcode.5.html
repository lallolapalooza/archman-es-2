SLAPO-RETCODE(5) Manual de formatos de archivo SLAPO-RETCODE(5)

NOMBRE

slapo-retcode - overlay de código de retorno para slapd

SINOPSIS

/etc/openldap/slapd.conf

DESCRIPCIÓN

El overlay retcode para slapd(8) es útil para probar el comportamiento de los clientes cuando ocurren respuestas erróneas y/o inusuales generadas por el servidor, por ejemplo, códigos de error, referencias, tiempos de respuesta excesivos, etc.

Las respuestas de error se generan de acuerdo con diferentes estrategias.

En el primer caso, todas las operaciones dirigidas a un subárbol configurable específico causan que el objeto relacionado con el DN de la solicitud sea buscado y verificado por datos de código de retorno: un código de respuesta, más un mensaje textual opcional, un retraso configurable opcional, un campo DN coincidente opcional y, cuando el código de respuesta es "referral", una (lista de) referencia(s).

Los códigos de respuesta conocidos de los documentos estándar se proporcionan en retcode.conf, que se puede incluir después de instanciar el overlay.

En el segundo caso, los objetos de clases heredadas de errAbsObject, como errObject o errAuxObject, cuando se devuelven como respuestas intermedias de una solicitud de búsqueda, se transforman en la respuesta dictada por su contenido.

Un tercer modo hace que los objetos se busquen en la base de datos subyacente para descubrir si su clase hereda de errABsObject; en ese caso, su contenido se utiliza para calcular la respuesta correspondiente.

El comportamiento se deshabilita utilizando el control manageDSAit (RFC 3296); en ese caso, el objeto resultante, ya sea presente en el directorio o generado dinámicamente por el overlay, o contenido en la solicitud, se maneja como de costumbre.

Las directivas de configuración que son específicas del overlay retcode deben ir precedidas de retcode-, para evitar conflictos con directivas específicas de la base de datos subyacente o de otros overlays apilados. Las siguientes directivas específicas se pueden utilizar para configurar el overlay retcode:

retcode-parent <DN>
Esta directiva define el DN padre donde residen las entradas generadas dinámicamente. Si no se define, se utiliza el sufijo de la base de datos.

retcode-item <RDN> <errCode> [op=<oplist>] [text=<mensaje>] [ref=<referencia>] [sleeptime=<seg>] [matched=<DN>] [unsolicited=<OID>[:<data>]] [flags=[pre|post-]disconnect[,...]]

Una entrada generada dinámicamente, ubicada debajo de retcode-parent. El errCode es el número del código de respuesta; puede estar en cualquier formato compatible con strtol(3). La oplist opcional es una lista de operaciones que causan la generación del código de respuesta; si está ausente, todas las operaciones se ven afectadas. El campo matched es el DN coincidente que se devuelve junto con el error, mientras que el campo text es un mensaje de diagnóstico opcional. El campo ref solo se permite para el código de respuesta referral. El campo sleeptime hace que slapd(8) duerma el número de segundos especificado antes de continuar con la operación. El campo unsolicited se puede usar para generar la devolución de un mensaje de respuesta no solicitada RFC 4511; si OID no es "0", se genera una respuesta extendida, con los datos opcionales agregados. Si flags contiene disconnect, o pre-disconnect, slapd(8) se desconecta abruptamente, sin previo aviso; post-disconnect causa la desconexión justo después de enviar la respuesta según corresponda.
retcode-indir
Habilita la explotación de errAbsObject almacenado en el directorio. Puede resultar en una gran sobrecarga innecesaria.
retcode-sleep [-]<n>
Define un tiempo de espera en segundos que se pasa antes de manejar realmente cualquier operación. Si es negativo, se utiliza un tiempo aleatorio entre 0 y el valor absoluto del argumento.

ESQUEMA

El overlay retcode utiliza el esquema de "código de retorno" descrito aquí. Este esquema está diseñado específicamente para su uso con este overlay y no está destinado a ser utilizado de otra manera. También se observa que el esquema descrito aquí es *un trabajo en curso*, y por lo tanto está sujeto a cambios sin previo aviso. El esquema es cargado automáticamente por el overlay.

El esquema incluye un número de clases de objetos y tipos de atributos asociados, como se describe a continuación.

El código de error:

( 1.3.6.1.4.1.4203.666.11.4.1.1
NAME ( 'errCode' )
DESC 'Código de error LDAP'
EQUALITY integerMatch
ORDERING integerOrderingMatch
SYNTAX 1.3.6.1.4.1.1466.115.121.1.27
SINGLE-VALUE )

Las operaciones que activan el código de respuesta:

( 1.3.6.1.4.1.4203.666.11.4.1.2
NAME ( 'errOp' )
DESC 'Operaciones a las que se aplica errObject'
EQUALITY caseIgnoreMatch
SUBSTR caseIgnoreSubstringsMatch
SYNTAX 1.3.6.1.4.1.1466.115.121.1.15 )

El mensaje de texto:

( 1.3.6.1.4.1.4203.666.11.4.1.3
NAME ( 'errText' )
DESC 'Descripción textual del error LDAP'
EQUALITY caseIgnoreMatch
SUBSTR caseIgnoreSubstringsMatch
SYNTAX 1.3.6.1.4.1.1466.115.121.1.15
SINGLE-VALUE )

El tiempo de espera antes de que la respuesta se devuelva realmente al cliente:

( 1.3.6.1.4.1.4203.666.11.4.1.4
NAME ( 'errSleepTime' )
DESC 'Tiempo de espera antes de devolver el error'
EQUALITY integerMatch
SYNTAX 1.3.6.1.4.1.1466.115.121.1.27
SINGLE-VALUE )

El DN coincidente devuelto al cliente:

( 1.3.6.1.4.1.4203.666.11.4.1.5
NAME ( 'errMatchedDN' )
DESC 'Valor a devolver como DN coincidente'
EQUALITY distinguishedNameMatch
SYNTAX 1.3.6.1.4.1.1466.115.121.1.12
SINGLE-VALUE )

El OID a devolver como OID de respuesta extendida en respuestas no solicitadas RFC 4511 ("0" genera una respuesta regular con msgid establecido en 0):

( 1.3.6.1.4.1.4203.666.11.4.1.6
NAME ( 'errUnsolicitedOID' )
DESC 'OID a devolver dentro de la respuesta no solicitada'
EQUALITY objectIdentifierMatch
SYNTAX 1.3.6.1.4.1.1466.115.121.1.38
SINGLE-VALUE )

La cadena de octetos a devolver como datos de respuesta extendida en respuestas no solicitadas RFC 4511:

( 1.3.6.1.4.1.4203.666.11.4.1.7
NAME ( 'errUnsolicitedData' )
DESC 'Datos a devolver dentro de la respuesta no solicitada'
SYNTAX 1.3.6.1.4.1.1466.115.121.1.40
SINGLE-VALUE )

Si es VERDADERO, slapd(8) se desconecta abruptamente sin previo aviso; si es FALSO, se desconecta después de enviar la respuesta según corresponda:

( 1.3.6.1.4.1.4203.666.11.4.1.8
NAME ( 'errDisconnect' )
DESC 'Desconectarse sin previo aviso'
SYNTAX 1.3.6.1.4.1.1466.115.121.1.7
SINGLE-VALUE )

La clase abstracta que activa el overlay:

( 1.3.6.1.4.1.4203.666.11.4.3.0
NAME ( 'errAbsObject' )
SUP top ABSTRACT
MUST ( errCode )
MAY ( cn $ description $ errOp $ errText $ errSleepTime
$ errMatchedDN ) )

La clase de objeto estructural independiente para datos creados específicamente:

( 1.3.6.1.4.1.4203.666.11.4.3.1
NAME ( 'errObject' )
SUP errAbsObject STRUCTURAL )

La clase de objeto auxiliar para alterar el comportamiento de los objetos existentes:

( 1.3.6.1.4.1.4203.666.11.4.3.2
NAME ( 'errAuxObject' )
SUP errAbsObject AUXILIARY )

EJEMPLO

overlay         retcode
retcode-parent  "ou=RetCodes,dc=example,dc=com"
# retcode.conf se encuentra en tests/data/ del árbol de fuentes
include         ./retcode.conf
# Espera 10 segundos y luego devuelve éxito (0x00)
retcode-item    "cn=Success after 10 seconds" 0x00 sleeptime=10
# Espera 10 segundos y luego devuelve timelimitExceeded (0x03)
retcode-item    "cn=Timelimit after 10 seconds" 0x03 sleeptime=10

ARCHIVOS

/etc/openldap/slapd.conf
archivo de configuración predeterminado de slapd

NAME

slapo-retcode - return code rewrite backend overlay for OpenLDAP

SYNOPSIS

slapo-retcode

DESCRIPTION

The return code rewrite overlay, slapo-retcode, is used to rewrite the return codes of search operations for specific entries.

This overlay is intended to make certain operations appear to return success (LDAP_SUCCESS) even when they might otherwise fail. This can be useful for specific client applications that do not handle certain error conditions gracefully.

The overlay operates by intercepting search operations. It maintains a list of DNs for which it should rewrite return codes. If a search operation targets one of these DNs, and the underlying backend would return a specific error code, the overlay can be configured to return LDAP_SUCCESS instead.

The configuration for this overlay is done through the standard OpenLDAP configuration mechanisms, typically within the cn=config database.

SCHEMA

The slapo-retcode overlay requires the following object classes and attributes to be defined in the schema:

    ( See the slapo-retcode schema file for details )

EXAMPLE

To configure the slapo-retcode overlay to rewrite the return code for the entry uid=test,dc=example,dc=com to always return LDAP_SUCCESS, even if the underlying backend returns an error, you might use a configuration like this:

    dn: cn=config
    changetype: modify
    add: olcOverlay
    olcOverlay: retcode
    -
    dn: olcOverlay=retcode,cn=config
    changetype: add
    objectClass: olcOverlayConfig
    objectClass: olcRetcodeConfig
    olcOverlay: retcode
    olcRetcodeDN: uid=test,dc=example,dc=com
