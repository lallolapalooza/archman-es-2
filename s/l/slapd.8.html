NOMBRE

slapd - Demonio LDAP autónomo

SINOPSIS

/usr/lib/slapd [-V[V[V]] [-4|-6] [-T {acl|a[dd]|auth|c[at]| d[n]|i[ndex]|m[odify]|p[asswd]|s[chema]|t[est]}] [-d nivel-depuracion] [-f archivo-config-slapd] [-F directorio-config-slapd] [-h URLs] [-n nombre-servicio] [-s nivel-syslog] [-l usuario-local-syslog] [-o opcion[=valor]] [-r directorio] [-u usuario] [-g grupo] [-c cookie]

DESCRIPCIÓN

Slapd es el demonio LDAP autónomo. Escucha conexiones LDAP en cualquier número de puertos (por defecto 389), respondiendo a las operaciones LDAP que recibe a través de estas conexiones. slapd se invoca típicamente al arrancar, usualmente desde /etc/rc.local. Al iniciarse, slapd normalmente se bifurca y se desasocia del tty que lo invocó. Si está configurado en el archivo de configuración (o directorio de configuración), el proceso slapd imprimirá su ID de proceso (ver getpid(2)) en un archivo .pid, así como las opciones de la línea de comandos durante la invocación en un archivo .args (ver slapd.conf(5)). Si se proporciona la opción -d, incluso con un argumento cero, slapd no se bifurcará ni se desasociará del tty que lo invocó.

Ver la "Guía del Administrador de OpenLDAP" para más detalles sobre slapd.

OPCIONES

-V[V[V]]
Imprime información de la versión y continúa con el inicio. Si se proporciona -VV, sale después de proporcionar la información de la versión. Si se proporciona -VVV, además proporciona información sobre superposiciones estáticas y backends.
-4
Escuchar solo en direcciones IPv4.
-6
Escuchar solo en direcciones IPv6.
-T herramienta
Ejecutar en modo Herramienta. El argumento herramienta selecciona si ejecutar como slapadd, slapcat, slapdn, slapindex, slapmodify, slappasswd, slapschema o slaptest (slapacl y slapauth necesitan que se escriba la opción completa acl y auth, ya que a está reservada para slapadd). Esta opción debe ser la primera opción especificada cuando se usa; las opciones restantes serán interpretadas por el programa de herramienta slap correspondiente, según las páginas de manual respectivas. Tenga en cuenta que estos programas de herramienta suelen ser enlaces simbólicos a slapd. Esta opción se proporciona para situaciones donde los enlaces simbólicos no se proporcionan o no son utilizables.
-d nivel-depuracion
Activa la depuración según lo definido por nivel-depuracion. Si se especifica esta opción, incluso con un argumento cero, slapd no se bifurcará ni se desasociará de la terminal que lo invocó. Algunos mensajes generales de operación y estado se imprimen para cualquier valor de nivel-depuracion. nivel-depuracion se toma como una cadena de bits, donde cada bit corresponde a un tipo diferente de información de depuración. Ver <ldap_log.h> para detalles. Se pueden especificar arrays separados por comas de nombres amigables para seleccionar la salida de depuración de la información de depuración correspondiente. Se admiten todos los nombres reconocidos por la directiva loglevel descrita en slapd.conf(5). Si nivel-depuracion es ?, se imprime una lista de los niveles de depuración instalados y slapd sale.

Recuerde que si activa el registro de paquetes, se volcarán los paquetes que contengan contraseñas de bind, por lo que si redirige el registro a un archivo de registro, ese archivo debe tener protección de lectura.

-s nivel-syslog
Esta opción le indica a slapd a qué nivel de depuración se deben registrar las declaraciones de depuración en la utilidad syslog(8). El valor nivel-syslog puede establecerse a cualquier valor o combinación permitida por el modificador -d. Slapd registra todos los mensajes seleccionados por nivel-syslog al nivel de gravedad de depuración DEBUG de syslog(3), en la unidad especificada con -l.
-n nombre-servicio
Especifica el nombre del servicio para el registro y otros propósitos. Por defecto es el nombre base de argv[0], es decir: "slapd".
-l usuario-local-syslog
Selecciona el usuario local de la utilidad syslog(8). El valor puede ser LOCAL0, hasta LOCAL7, así como USER y DAEMON. El valor por defecto es LOCAL4. Sin embargo, esta opción solo está permitida en sistemas que soportan usuarios locales con la utilidad syslog(8). El registro en syslog(8) ocurre al nivel de gravedad de depuración "DEBUG".
-f archivo-config-slapd
Especifica el archivo de configuración de slapd. El valor por defecto es /etc/openldap/slapd.conf.
-F directorio-config-slapd
Especifica el directorio de configuración de slapd. El valor por defecto es /etc/openldap/slapd.d. Si se especifican tanto -f como -F, el archivo de configuración se leerá y se convertirá al formato de directorio de configuración y se escribirá en el directorio especificado. Si no se especifica ninguna de las opciones, slapd intentará leer el directorio de configuración por defecto antes de intentar usar el archivo de configuración por defecto. Si existe un directorio de configuración válido, se ignorará el archivo de configuración por defecto. Todas las herramientas slap que utilizan las opciones de configuración observan este mismo comportamiento.
-h lista-URL
slapd servirá por defecto ldap:/// (LDAP sobre TCP en todas las interfaces en el puerto LDAP por defecto). Es decir, se enlazará usando INADDR_ANY y el puerto 389. La opción -h puede usarse para especificar URLs LDAP (y de otros esquemas) para servir. Por ejemplo, si a slapd se le da -h "ldap://127.0.0.1:9009/ ldaps:/// ldapi:///", escuchará en 127.0.0.1:9009 para LDAP, 0.0.0.0:636 para LDAP sobre TLS, y LDAP sobre IPC (sockets de dominio Unix). El host 0.0.0.0 representa INADDR_ANY (cualquier interfaz). Se espera una lista de URLs separada por espacios. Las URLs deben ser de los esquemas LDAP, PLDAP, LDAPS, PLDAPS o LDAPI, y generalmente sin un DN u otros parámetros opcionales (excepto como se discute a continuación). El soporte para los tres últimos esquemas depende de las opciones de configuración seleccionadas. Los hosts pueden especificarse por nombre o en formatos de dirección IPv4 e IPv6. Los puertos, si se especifican, deben ser numéricos. El puerto por defecto de ldap:// es 389 y el puerto por defecto de ldaps:// es 636, lo mismo para las variantes habilitadas para proxy.

Los esquemas de URL PLDAP y PLDAPS proporcionan soporte para el protocolo proxy HAProxy versión 2, que permite a un balanceador de carga o servidor proxy proporcionar la dirección IP del cliente remoto a slapd para su uso en control de acceso o registro. Los puertos configurados para PLDAP o PLDAPS solo aceptarán conexiones que incluyan la cabecera del protocolo proxy necesaria. Las conexiones a estos puertos deben restringirse a nivel de red solo a balanceadores de carga o proxies de confianza para evitar la suplantación de direcciones IP de clientes por parte de terceros.

Para LDAP sobre IPC, nombre es el nombre del socket, y no se requiere ni se permite puerto; tenga en cuenta que los separadores de directorio deben codificarse en URL, al igual que cualquier otro carácter especial para las URL; así, el socket


/usr/local/var/ldapi

debe especificarse como


ldapi://%2Fusr%2Flocal%2Fvar%2Fldapi

La ubicación por defecto para el socket IPC es /var/lib/openldap/run/ldapi

Los permisos del oyente se indican mediante "x-mod=-rwxrwxrwx", "x-mod=0777" o "x-mod=777", donde cualquiera de los "rwx" puede ser "-" para suprimir el permiso relacionado, mientras que cualquiera de los "7" puede ser cualquier dígito octal legal, según chmod(1). NAME

slapd ― standalone LDAP daemon

SYNOPSIS

/usr/lib/slapd [-4 | -6] [-A authz-mechanism] [-a binddn] [-b basedn] [-B socksbinddn] [-C connection_max] [-c cookie] [-d level] [-D rootdn] [-e errlog] [-f conffile] [-g group] [-h ldapscheme://addr] [-H ldapscheme://addr] [-i pidfile] [-j lockfile] [-k interval] [-l logfile] [-M modulepath] [-N threads] [-n dbname] [-o option[=value]] [-p port] [-P proxybinddn] [-r directory] [-R referralhopcount] [-s sizecrit] [-S socksaddr] [-T sockdir] [-U contextrules] [-u user] [-v] [-w rootpw] [-W rootpss] [-Y authmec] [-Z sockslevel]

DESCRIPTION

The slapd daemon is the OpenLDAP(8) server. It implements a general-purpose, multi-threaded, multi-layered LDAP server. It can be configured to use various back-ends for storage, such as the native MDB database, LMDB, SQL, LDAP, and more. slapd can also act as a proxy or gateway to other LDAP servers.

The daemon forks and detaches itself from the controlling terminal and enters a loop, listening for connections on configured network addresses. When a connection is accepted, it is handled by a separate thread.

Configuration is typically handled by the slapd.conf(5) file, or through the run-time configuration mechanism described in slapd-config(5).

The daemon may be started in the foreground, for debugging purposes, by specifying a non-zero debug level using the -d option and not forking. It will print verbose debugging messages to standard error.

OPTIONS

-4
Listen only on IPv4 interfaces.
-6
Listen only on IPv6 interfaces.
-A authz-mechanism
Specify the default authorization mechanism for simple binds. Supported mechanisms include - (no authorization), authz-regexp, authz-rules, and none.
-a binddn
Specify the DN to use for anonymous binds. Defaults to the empty string, which is typically the correct setting.
-b basedn
Specify the base DN for the server. This is used for the root DSE search and may be needed when the server is configured with multiple databases.
-B socksbinddn
Specify the DN to use for binding to the SOCKS server. This option is only relevant when using SOCKS proxying.
-C connection_max
Specify the maximum number of simultaneous connections allowed. Defaults to 10.
-c cookie
This option provides a cookie for the syncrepl replication consumer. The cookie is a comma separated list of name=value pairs. Currently supported syncrepl cookie fields are rid, sid, and csn. rid identifies a replication thread within the consumer server and is used to find the syncrepl specification in slapd.conf(5) or slapd-config(5) having the matching replication identifier in its definition. The rid must be provided in order for any other specified values to be used. sid is the server id in a multi-provider configuration. csn is the commit sequence number received by a previous synchronization and represents the state of the consumer content which the syncrepl engine will synchronize to the current provider content. In case of multi-provider replication agreement, multiple csn values, semicolon separated, can appear. Use only the rid part to force a full reload.
-d level
Specify the debug level. A non-zero level enables debugging output, which is printed to standard error. Higher levels provide more verbose output. The value is a bitmask composed of flags defined in <ldap_log.h> (e.g., LDAP_DEBUG_ANY (0xFFFF), LDAP_DEBUG_ARGS (0x0001), LDAP_DEBUG_CONNS (0x0002), LDAP_DEBUG_EDR (0x0004), LDAP_DEBUG_EVENT (0x0008), LDAP_DEBUG_ IONS (0x0010), LDAP_DEBUG_PARSE (0x0020), LDAP_DEBUG_CONFIG (0x0040), LDAP_DEBUG_ACL (0x0080), LDAP_DEBUG_SHELL (0x0100), LDAP_DEBUG_RPC (0x0200), LDAP_DEBUG_DELTASYNC (0x0400), LDAP_DEBUG_FILTER (0x0800), LDAP_DEBUG_SEARCH (0x1000), LDAP_DEBUG_CONFIG (0x4000), LDAP_DEBUG_METADATA (0x8000), LDAP_DEBUG_STATS (0x10000), LDAP_DEBUG_REMOTEOP (0x20000)). For example, -d 255 enables all flags up to bit 8.
-D rootdn
Specify the DN of the administrative user for the server. This DN is used for administrative tasks and may be required for certain configuration operations.
-e errlog
Specify the log file for error messages. If not specified, errors are written to standard error.
-f conffile
Specify the configuration file to use. If not specified, the default configuration file (“/etc/ldap/slapd.conf” or “/usr/local/etc/openldap/slapd.conf”) is used.
-g group
slapd will run with the specified group name or id. Note when used with -r, slapd will use the group database in the change root environment.
-h ldapscheme://addr
Specify the network address and port on which slapd should listen for connections. The ldapscheme can be ldap or ldaps. The addr can be a hostname, IP address, or a special keyword like any or any6. If not specified, slapd listens on port 389 for all network interfaces. Multiple -h options can be used to specify multiple listening addresses.
-H ldapscheme://addr
Same as -h, but used for specifying listening addresses for LDAP over TLS/SSL connections (ldaps).
-i pidfile
Specify the file in which to write the process ID (PID) of the running daemon. This is useful for managing the daemon.
-j lockfile
Specify the directory for lock files. This is used by some backends to prevent concurrent access.
-k interval
Specify the interval (in seconds) for periodic checks of configuration file changes. If not specified, configuration changes are not automatically reloaded.
-l logfile
Specify the log file for operation messages. If not specified, messages are written to standard error.
-M modulepath
Specify the directory where loadable modules are located. If not specified, the default module path is used.
-N threads
Specify the number of worker threads to use for handling connections. Defaults to 1.
-n dbname
Specify the name of the database to use. This is typically used when configuring multiple databases.
-o option[=value]
This option provides a generic means to specify options without the need to reserve a separate letter for them.

It supports the following options:

slp={on|off|slp-attrs}
When SLP support is compiled into slapd, disable it (off),
enable it by registering at SLP DAs without specific SLP attributes (on), or with specific SLP attributes slp-attrs that must be an SLP attribute list definition according to the SLP standard.

For example, "slp=(tree=production),(server-type=OpenLDAP),(server-version=2.4.15)" registers at SLP DAs with the three SLP attributes tree, server-type and server-version that have the values given above. This allows one to specifically query the SLP DAs for LDAP servers holding the production tree in case multiple trees are available.

In addition to the options listed above, slapd recognizes several access control options that can be used to control client access to the LDAP directory. These options are typically specified in the slapd.conf(5) file or through the run-time configuration mechanism. The format is usually:

access to attribute [by <authz-mechanism> <access-type> [by <authz-mechanism> <access-type> ...]] ...

Where:

  • attribute specifies the attribute or set of attributes to which access is being controlled.
  • authz-mechanism specifies the authorization mechanism used to grant access. This can include:
    • anonymous: Anonymous users.
    • users: Authenticated users.
    • userdn: Users matching a specific DN.
    • group: Users who are members of a specific group (this option is ignored).
    • self: The authenticated user itself.
    • dn.exact, dn.base, dn.children, dn.sub: Users matching specific DN patterns.
    • entry.own: The user who owns the entry.
    • entry.present: Entries where the attribute is present.
    • entry.types: Entries where the attribute types are present.
    • filter: Entries matching a specific filter.
    • peername: Clients connecting from a specific network address.
    • sockcred: Clients connecting via authenticated sockets.
  • access-type specifies the type of access granted. This can include:
    • read (r): Allows reading the attribute.
    • write (w): Allows modifying the attribute.
    • search (s): Allows searching for the attribute.
    • compare (c): Allows comparing the attribute.
    • add (a): Allows adding the attribute.
    • delete (d): Allows deleting the attribute.
    • moddn (m): Allows modifying the DN of the attribute.
    • all (x): Allows all operations.
    • none (-): Denies all operations.

For example, the following rule grants read and search access to all attributes for authenticated users, and read-only access to the `cn` attribute for anonymous users:

access to attr=“*”
        by users  read,search
        by anonymous read
access to attr=cn
        by users  write,add,delete,modrdn
        by anonymous read,search,compare,write,add,delete,modrdn

The ldap:/// prefix can be used to specify global access controls that apply to all operations unless overridden by more specific rules. The format is:

ldap:///????x-modrw-------

This means that read (r), write (w), add (a), delete (d), modify DN (m), and modify RDN (modrdn) operations are allowed only for authenticated connections. The '????' indicates that the rule applies to all databases. The 'x' signifies that bind is required for all operations. This feature is experimental and requires manual enabling during configuration.

-r directory
Specifies a directory to become the root directory. slapd will change the current working directory to this directory and then chroot(2) to this directory. This is done after opening listeners but before reading any configuration file or initializing any backend. When used as a security mechanism, it should be used in conjunction with -u and -g options.
-u user
slapd will run slapd with the specified user name or id, and that user's supplementary group access list as set with initgroups(3). The group ID is also changed to this user's gid, unless the -g option is used to override. Note when used with -r, slapd will use the user database in the change root environment.

Note that on some systems, running as a non-privileged user will prevent passwd back-ends from accessing the encrypted passwords. Note also that any shell back-ends will run as the specified non-privileged user.

-g group
slapd will run with the specified group name or id. Note when used with -r, slapd will use the group database in the change root environment.
-c cookie
This option provides a cookie for the syncrepl replication consumer. The cookie is a comma separated list of name=value pairs. Currently supported syncrepl cookie fields are rid, sid, and csn. rid identifies a replication thread within the consumer server and is used to find the syncrepl specification in slapd.conf(5) or slapd-config(5) having the matching replication identifier in its definition. The rid must be provided in order for any other specified values to be used. sid is the server id in a multi-provider configuration. csn is the commit sequence number received by a previous synchronization and represents the state of the consumer content which the syncrepl engine will synchronize to the current provider content. In case of multi-provider replication agreement, multiple csn values, semicolon separated, can appear. Use only the rid part to force a full reload.
-o option[=value]
This option provides a generic means to specify options without the need to reserve a separate letter for them.

It supports the following options:

slp={on|off|slp-attrs}
When SLP support is compiled into slapd, disable it (off),
enable it by registering at SLP DAs without specific SLP attributes (on), or with specific SLP attributes slp-attrs that must be an SLP attribute list definition according to the SLP standard.

For example, "slp=(tree=production),(server-type=OpenLDAP),(server-version=2.4.15)" registers at SLP DAs with the three SLP attributes tree, server-type and server-version that have the values given above. EXAMPLES

To start slapd and have it fork and detach from the terminal and start serving the LDAP databases defined in the default config file, just type:

/usr/lib/slapd

To start slapd with an alternate configuration file, and turn on voluminous debugging which will be printed on standard error, type:

/usr/lib/slapd -f /var/tmp/slapd.conf -d 255

To test whether the configuration file is correct or not, type:

/usr/lib/slapd -Tt
