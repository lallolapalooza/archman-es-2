NOMBRE

slurmdbd.conf — archivo de configuración del Demonio de la Base de Datos de Slurm (SlurmDBD)

DESCRIPCIÓN

slurmdbd.conf es un archivo de texto ASCII que describe la información de configuración del Demonio de la Base de Datos de Slurm (SlurmDBD). El archivo siempre se encontrará en el mismo directorio que slurm.conf.

El contenido del archivo no distingue entre mayúsculas y minúsculas, excepto los nombres de los nodos y archivos. Cualquier texto que siga a un carácter "#" en el archivo de configuración se tratará como un comentario hasta el final de esa línea. Los cambios en el archivo de configuración surtirán efecto al reiniciar SlurmDBD o al recibir el daemon la señal SIGHUP, a menos que se indique lo contrario.

Este archivo debe estar solo en la máquina donde se ejecuta SlurmDBD, ser propiedad del Usuario de Slurm o de root, y tener permisos establecidos en 600 o 640. Si el daemon slurmdbd se inicia como usuario root y cambia a otro ID de usuario, el archivo de configuración se leerá inicialmente como usuario root, pero se leerá con el otro ID de usuario en respuesta a una señal SIGHUP. Este archivo debe protegerse del acceso no autorizado ya que contiene una contraseña de base de datos. Los parámetros generales de configuración disponibles incluyen:

AllowNoDefAcct
Elimina el requisito de que los usuarios tengan una cuenta predeterminada. Booleano, sí para activarlo, no (predeterminado) para exigir cuentas predeterminadas.
AllResourcesAbsolute
Al agregar un recurso (licencia), trata los recuentos asignados/permitidos como números absolutos en lugar de porcentajes. Booleano, sí para activarlo, no (predeterminado) para usar los números como porcentajes.
ArchiveDir
Si ArchiveScript no está configurado, slurmdbd generará un archivo que se puede leer en cualquier momento con `sacctmgr load filename`. Este directorio es donde se colocará el archivo después de que ocurra un evento de purga y el archivo para ese elemento esté configurado como verdadero. El valor predeterminado es /tmp. El formato del nombre de este archivo es $ArchiveDir/$ClusterName_$ArchiveObject_archive_$BeginTimeStamp_$endTimeStamp. Limitamos los archivos de archivo a MaxPurgeLimit registros por archivo. Si existen más registros durante ese período de tiempo, se escribirán en un nuevo archivo. Los archivos de archivo subsiguientes durante el mismo período de tiempo tendrán el sufijo ".<número>", por ejemplo, .2, con el número aumentando en uno por cada archivo en el mismo período de tiempo.
ArchiveEvents
Al purgar eventos, también archívalos. Booleano, sí para archivar datos de eventos, no en caso contrario. El valor predeterminado es no.
ArchiveJobs
Al purgar trabajos, también archívalos. Booleano, sí para archivar datos de trabajos, no en caso contrario. El valor predeterminado es no.
ArchiveResvs
Al purgar reservas, también archívalas. Booleano, sí para archivar datos de reservas, no en caso contrario. El valor predeterminado es no.

Este script puede ejecutarse cada vez que ocurre un resumen (cada hora, día y mes), dependiendo de las opciones Purge\*After. Este script se utiliza para transferir registros de contabilidad de la base de datos a un archivo. Se utiliza en lugar del proceso interno para archivar objetos. El script se ejecuta sin argumentos y se establecen las siguientes variables de entorno.

El archivo de configuración slurmdbd.conf.

AuthCred
Establece el archivo de credenciales de autenticación. Las credenciales son claves que son utilizadas para la autenticación y pueden ser contraseñas, claves SSH, o claves JWT. Por defecto, se utiliza una clave HS256 y las claves de JWT no se cargan. Si este parámetro se establece, se espera que las claves sean de tipo RS256. Las claves deben ser propiedad del usuario Slurm o de root, legibles por el usuario Slurm, con permisos sugeridos de 0400. No deben ser escribibles por 'other'. Solo se admiten claves RS256, aunque otros tipos de claves pueden aparecer en el archivo. Si se establece, ninguna clave HS256 se cargará por defecto (y se deshabilitará la generación de tokens), aunque el parámetro jwt_key puede ser usado para re-habilitar explícitamente el uso de claves HS256 (y la generación de tokens).
jwt_key=
Ruta absoluta al archivo de claves JWT. La clave debe ser HS256. La clave debe ser propiedad del usuario Slurm o de root, debe ser legible por el usuario Slurm, con permisos sugeridos de 0400. No debe ser accesible por 'other'.
AuthInfo
Información adicional a ser utilizada para la autenticación de las comunicaciones con el demonio de control de Slurm (slurmctld) en cada clúster. La interpretación de esta opción es específica del AuthType configurado. Se pueden especificar múltiples opciones en una lista separada por comas. Si no se especifica, se utilizará la información de autenticación por defecto.
socket
Nombre de la ruta a un socket del demonio MUNGE a utilizar (ej. "socket=/var/run/munge/munge.socket.2"). El valor por defecto es "/var/run/munge/munge.socket.2". Utilizado por auth/munge y cred/munge.
ttl
Tiempo de vida de la credencial, en segundos (ej. "ttl=300"). El valor por defecto depende de la instalación de MUNGE, pero típicamente es de 300 segundos.
use_client_ids
Permite que el plugin auth/slurm autentique usuarios sin depender de la información del usuario de LDAP o del sistema operativo.
AuthType
Define el método de autenticación para las comunicaciones entre los componentes de Slurm. SlurmDBD debe ser terminado antes de cambiar el valor de AuthType y luego reiniciado. Esto debe coincidir con el AuthType usado en slurm.conf. Valores aceptables en este momento:
auth/munge
Indica que se usará MUNGE (por defecto). (Ver "https://dun.github.io/munge/" para más información).
auth/slurm
Utiliza el plugin de autenticación interno de Slurm.
CommitDelay
Cuántos segundos entre commits en una conexión de un Slurmctld. Esto acelera drásticamente las inserciones en la base de datos. Si está ejecutando un flujo de trabajos muy alto, debería considerar establecer esto. En pruebas, 1 segundo mejora drásticamente el rendimiento de slurmdbd y reduce la sobrecarga. Existe una pequeña probabilidad de pérdida de datos ya que esto crea una ventana en la que si slurmdbd sale anormalmente por cualquier razón, los datos no confirmados podrían perderse. Si bien esta situación debería ser muy rara, presenta un riesgo extremadamente pequeño, pero puede ser la única forma de operar en entornos extremadamente intensivos. En realidad, el riesgo es bastante bajo, pero todavía está presente.
CommunicationParameters
Opciones separadas por comas que identifican las opciones de comunicación.
DisableIPv4
Deshabilita la operación solo IPv4 para slurmdbd. Esto también debería establecerse en su archivo slurm.conf.
EnableIPv6
Habilita el uso de direcciones IPv6 para slurmdbd. Al usar tanto IPv4 como IPv6, las preferencias de familia de direcciones se basarán en su archivo /etc/gai.conf. Esto también debería establecerse en su archivo slurm.conf.
keepaliveinterval=Especifica el intervalo, en segundos, entre las sondas de keepalive en las conexiones
inactivas. Esto afecta a la mayoría de las conexiones salientes desde slurmdbd (ej. entre el primario y el de respaldo, o desde slurmdbd a slurmctld). El valor por defecto es 30 segundos.
keepaliveprobes=Especifica el número de sondas de keepalive no confirmadas enviadas antes de considerar
una conexión como rota. Esto afecta a la mayoría de las conexiones salientes desde slurmdbd (ej. entre el primario y el de respaldo, o desde slurmdbd a slurmctld). El valor por defecto es 3.
keepalivetime=Especifica cuánto tiempo, en segundos, una conexión debe estar inactiva antes de empezar a
enviar sondas de keepalive, así como cuánto tiempo retrasar el cierre de una conexión para procesar mensajes aún en la cola. Esto afecta a la mayoría de las conexiones salientes desde slurmdbd (ej. entre el primario y el de respaldo, o desde slurmdbd a slurmctld). El valor por defecto es 30 segundos.

Nombre por el cual DbdHost debe ser referido al establecer una ruta de comunicación. Este nombre se usará como argumento para la función getaddrinfo() para identificación. LogFile
Ruta de acceso completa de un archivo en el que se escriben los registros del Demonio de Base de Datos de Slurm. El valor predeterminado es ninguno (realiza el registro a través de syslog).
Consulte la sección LOGGING en la página man de slurm.conf si se especifica una ruta de acceso.
LogTimeFormat
Formato de la marca de tiempo en los archivos de registro de slurmdbd. Los valores de formato aceptados incluyen "iso8601", "iso8601_ms", "rfc5424", "rfc5424_ms", "rfc3339", "clock", "short" y "thread_id". Los valores que terminan en "_ms" difieren de los que no lo hacen en que se imprimen segundos fraccionarios con precisión de milisegundos. El valor predeterminado es "iso8601_ms". Los formatos "rfc5424" son los mismos que los formatos "iso8601" excepto que también se muestra el valor de la zona horaria. El formato "clock" muestra una marca de tiempo en microsegundos obtenida con la función clock() estándar de C. El formato "short" es un formato corto de fecha y hora. El formato "thread_id" muestra la marca de tiempo en la forma de la función ctime() estándar de C sin el año pero incluyendo los microsegundos, el ID de proceso del demonio y el nombre e ID del hilo actual.
MaxPurgeLimit
Al archivar y purgar registros, limite cada operación individual a este número de filas. Las operaciones se repetirán hasta que se procesen todas las filas de destino. Este límite asegura que los bloqueos se liberarán periódicamente, permitiendo que ocurran otras operaciones de base de datos. Un límite más bajo liberará los bloqueos con más frecuencia, lo que puede mejorar la capacidad de respuesta del sistema mientras se purgan registros de tablas grandes. Sin embargo, un límite más bajo también aumentará el tiempo total am

Devuelve un error si una consulta se realiza sobre un intervalo de tiempo demasiado grande, para evitar que consultas mal formadas causen problemas de rendimiento dentro de SlurmDBD. PurgeEventAfter
Los eventos se purgan de la base de datos después de que haya transcurrido esta cantidad de tiempo desde que finalizaron. Esto incluye tiempos de inactividad de nodos y similares. El tiempo es un valor numérico y representa un número de meses. Si desea purgar con más frecuencia, puede incluir "hours" o "days" detrás del valor numérico para obtener purgas más frecuentes (es decir, un valor de "12hours" purgaría todo lo anterior a 12 horas). La purga se realiza al inicio de cada intervalo de purga. Por ejemplo, si el tiempo de purga es de 2 meses, la purga ocurriría al comienzo de cada mes. Si no se establece (predeterminado), los registros de eventos nunca se purgan.

Los registros de suspensión de trabajos individuales se purgan de la base de datos después de que haya transcurrido esta cantidad de tiempo desde que finalizaron. La información agregada se conservará hasta "PurgeUsageAfter". El tiempo es un valor numérico y representa un número de meses. Si desea purgar con más frecuencia, puede incluir "hours" o "days" detrás del valor numérico para obtener purgas más frecuentes (es decir, un valor de "12hours" purgaría todo lo anterior a 12 horas). La purga se realiza al inicio de cada intervalo de purga. Por ejemplo, si el tiempo de purga es de 2 meses, la purga ocurriría al comienzo de cada mes. Si no se establece (predeterminado), los registros de suspensión nunca se purgan.
PurgeTXNAfter
Los registros de transacciones individuales se purgan de la base de datos después de que haya transcurrido esta cantidad de tiempo desde que ocurrieron. El tiempo es un valor numérico y representa un número de meses. Si desea purgar con más frecuencia, puede incluir "hours" o "days" detrás del valor numérico para obtener purgas más frecuentes (es decir, un valor de "12hours" purgaría todo lo anterior a 12 horas). La purga se realiza al inicio de cada intervalo de purga. Por ejemplo, si el tiempo de purga es de 2 meses, la purga ocurriría al comienzo de cada mes. Si no se establece (predeterminado), los registros de transacciones nunca se purgan.
PurgeUsageAfter
Los registros de uso (Clúster, Asociación, QOS y WCKey) se purgan de la base de datos después de que haya transcurrido esta cantidad de tiempo desde que fueron creados o modificados por última vez. Estas tablas son la fuente de los informes generados por el comando sreport(1). El tiempo es un valor numérico y representa un número de meses. Si desea purgar con más frecuencia, puede incluir "hours" o "days" detrás del valor numérico para obtener purgas más frecuentes (es decir, un valor de "12hours" purgaría todo lo anterior a 12 horas). La purga se realiza al inicio de cada intervalo de purga. Por ejemplo, si el tiempo de purga es de 2 meses, la purga ocurriría al comienzo de cada mes. Si no se establece (predeterminado), los registros de uso nunca se purgan.
SlurmUser
El nombre del usuario con el que se ejecuta el demonio slurmdbd. Este usuario debe coincidir con el SlurmUser utilizado para todas las instancias de slurmctld que informan a slurmdbd. Debe existir en la máquina que ejecuta el Demonio de Base de Datos Slurm y tener el mismo UID que los hosts en los que se ejecuta slurmctld. Por motivos de seguridad, se recomienda un usuario distinto de "root". El valor predeterminado es "root".

NOTA: Si el SlurmUser para slurmctld es root, aún puede usar un SlurmUser no root para slurmdbd (en cualquier otro caso, ambos SlurmUsers deben coincidir) estableciendo explícitamente el AdminLevel del usuario en Admin. Después de agregar un usuario de esta manera, debe reiniciar slurmctld.

StorageBackupHost
Define el nombre del host de copia de seguridad donde se está ejecutando la base de datos y donde se van a almacenar los datos. Esto se puede ver como una solución de copia de seguridad cuando StorageHost no responde. Depende de la solución de copia de seguridad garantizar la coherencia de la información de contabilidad entre los dos hosts. Con soluciones de base de datos agrupadas (HA activo/pasivo), no necesitaría usar esta función. El valor predeterminado es ninguno.
StorageHost
Define el nombre del host donde se está ejecutando la base de datos y donde se van a almacenar los datos. Este puede ser el host en el que se ejecuta slurmdbd, pero para sistemas más grandes, recomendamos mantener la base de datos en una máquina separada.
StorageLoc
Especifique el nombre de la base de datos como la ubicación donde se escriben los registros de contabilidad. El valor predeterminado es "slurm_acct_db".
StorageParameters
Lista separada por comas de parámetros clave-valor.
SSL_CERT
El nombre de ruta del archivo del certificado de clave pública del cliente.
SSL_CA
El nombre de ruta del archivo del certificado de Autoridad de Certificación (CA).
SSL_CAPATH
El nombre de ruta del directorio que contiene los archivos de certificado de CA SSL confiables.
SSL_KEY
El nombre de ruta del archivo de clave privada del cliente.
SSL_CIPHER
La lista de cifrados permitidos para la encriptación SSL.
token_duration
Duración en segundos para almacenar en caché las contraseñas de base de datos generadas antes de solicitar una nueva a StoragePassScript. Típicamente, el token debe actualizarse antes de la expiración real; en caso de fallo en la generación del token, se continuará utilizando el token almacenado en caché para evitar que los fallos transitorios de generación causen fallos de conexión. El valor predeterminado es 300 segundos (5 minutos).
StoragePass
Define la contraseña utilizada para acceder a la base de datos para almacenar los datos de contabilidad de trabajos. El carácter '#' no está permitido en una contraseña.
StoragePassScript
Ruta absoluta a un script ejecutable que genera tokens de autenticación efímeros para conexiones de base de datos que se utilizan en lugar de StoragePass. El script debe enviar la contraseña/token a stdout y salir con estado 0 en caso de éxito. Esto permite la generación dinámica de contraseñas, en lugar de almacenar credenciales estáticas en archivos de configuración. El script debe ser propiedad y ejecutable por SlurmUser.
Variables de entorno proporcionadas al script:
SLURM_STORAGE_HOSTNAME
Nombre de host de la base de datos
SLURM_STORAGE_PORT
Número de puerto de la base de datos
SLURM_STORAGE_USER
Nombre de usuario de la base de datos
Formato de salida esperado:
TOKEN=<token_de_autenticación>
El script debe salir con estado 0 en caso de éxito y con un valor distinto de cero en caso de fallo. Cualquier salida a stderr se registrará como un error. Si se especifica un host de copia de seguridad, el script seguirá recibiendo el nombre de host principal y el mismo token se utilizará para ambos hosts.
StoragePort
El número de puerto con el que el demonio de la base de datos de Slurm (slurmdbd) se comunica con la base de datos. El valor predeterminado es 3306.
StorageType
Define el tipo de mecanismo de almacenamiento de contabilidad. Los valores aceptables en este momento incluyen "accounting_storage/mysql". El valor "accounting_storage/mysql" indica que los registros de contabilidad deben escribirse en una base de datos MySQL o MariaDB especificada por el parámetro StorageLoc. Este valor debe especificarse.
StorageUser
Define el nombre del usuario con el que nos vamos a conectar a la base de datos para almacenar los datos de contabilidad de trabajos. Si no se especifica ningún valor, se utilizará el usuario que inició slurmdbd.
TCPTimeout
Tiempo permitido para que se establezca una conexión TCP. El valor predeterminado es 2 segundos.
TLSParameters
Opciones separadas por comas que identifican opciones TLS. Los valores admitidos incluyen:
ca_cert_file=
Ruta de la autoridad de certificación (CA) del certificado. Debe existir en todos los hosts y ser accesible por todos los componentes de Slurm. Los permisos del archivo deben ser 644 y ser propiedad de SlurmUser/root.

La ruta predeterminada es "ca_cert.pem" en el directorio de configuración de Slurm.

dbd_cert_file=
Ruta del certificado utilizado por slurmdbd. Debe encadenarse a ca_cert_file. Solo debe existir en el host que ejecuta slurmdbd. Los permisos del archivo deben ser 600 y ser propiedad de SlurmUser.

La ruta predeterminada es "dbd_cert.pem" en el directorio de configuración de Slurm.

dbd_cert_key_file=
Ruta de la clave privada que acompaña a dbd_cert_file. Solo debe existir en el host que ejecuta slurmdbd. Los permisos del archivo deben ser 600 y ser propiedad de SlurmUser.

La ruta predeterminada es "dbd_cert_key.pem" en el directorio de configuración de Slurm.

load_system_certificates
Carga los certificados encontrados en las ubicaciones del sistema predeterminadas (por ejemplo, /etc/ssl) en el almacén de confianza.

El valor predeterminado es no cargar los certificados del sistema y depender únicamente de ca_cert_file para establecer la confianza.

security_policy_version=
Versión de la política de seguridad utilizada por s2n. Consulte la documentación de s2n para obtener más detalles. La política de seguridad predeterminada es "20230317", que cumple con FIPS e incluye TLS 1.3.
TLSType
Especifique la implementación TLS que se utilizará. Los valores aceptables en este momento son:
tls/s2n
Utiliza el plugin TLS s2n.
TrackSlurmctldDown
Booleano sí o no. Si se establece, slurmdbd marcará todos los recursos inactivos del clúster como caídos cuando un slurmctld se desconecte o ya no sea accesible. El valor predeterminado es no.
TrackWCKey
Booleano sí o no. Se utiliza para establecer la visualización y el seguimiento de la Clave de Caracterización de Carga de Trabajo (Workload Characterization Key). Debe establecerse para realizar un seguimiento del uso de wckey. Esto debe establecerse para generar tablas de uso consolidadas a partir de WCKeys. NOTA: Si TrackWCKey se establece aquí y no en sus diversos archivos slurm.conf, todos los trabajos se atribuirán a su WCKey predeterminada.

slurmdbd.conf(5) — Slurm Configuration File

NAME

slurmdbd.conf — Slurm database daemon configuration file

DESCRIPTION

The slurmdbd.conf file is used to configure the Slurm database daemon (slurmdbd(8)). The configuration file is located at /etc/slurmdbd.conf. The file can be any text file. Blank lines and lines starting with # (comments) are ignored. Any text string in the configuration file may be case insensitive and enclosed in quote marks.

The configuration options are described in slurm.conf(5).

EXAMPLE

A sample configuration file can be found in /usr/share/doc/slurm-llnl/examples/slurmdbd.conf.
