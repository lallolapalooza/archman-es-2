NOMBRE

slapmodify - Modifica entradas en una base de datos SLAPD

SINOPSIS

/usr/bin/slapmodify [-b sufijo] [-c] [-d nivel-debug] [-f slapd.conf] [-F dir-conf] [-g] [-j num-línea] [-l archivo-ldif] [-n num-db] [-o opción[=valor]] [-q] [-s] [-S SID] [-u] [-v] [-w]

DESCRIPCIÓN

Slapmodify se utiliza para aplicar modificaciones especificadas en el formato LDIF (LDAP Directory Interchange Format) a una base de datos de slapd(8). Abre la base de datos dada, determinada por el número de base de datos o sufijo, y realiza las modificaciones correspondientes al LDIF proporcionado en la base de datos. Las bases de datos configuradas como subordinadas de esta también se actualizan, a menos que se especifique -g. La entrada LDIF se lee de la entrada estándar o del archivo especificado.

Todos los archivos creados eventualmente por slapmodify pertenecerán a la identidad con la que se ejecute slapmodify, así que asegúrate de ejecutar slapmodify con la misma identidad con la que se ejecutará slapd(8) (ver la opción -u en slapd(8)), o cambia la propiedad del archivo antes de ejecutar slapd(8).

Nota: slapmodify también realizará la indexación relevante mientras modifica la base de datos si hay alguna configurada. Para detalles específicos, consulte slapindex(8).

OPCIONES

-b sufijo
Utiliza el sufijo especificado para determinar a qué base de datos agregar las entradas. La opción -b no se puede usar junto con la opción -n.
-c
Habilita el modo de continuación (ignorar errores).
-d nivel-debug
Habilita mensajes de depuración según lo definido por el nivel-debug especificado; consulte slapd(8) para más detalles.
-f slapd.conf
Especifica un archivo slapd.conf(5) alternativo.
-F dir-conf
Especifica un directorio de configuración. Si se especifican tanto -f como -F, el archivo de configuración se leerá y se convertirá al formato de directorio de configuración y se escribirá en el directorio especificado. Si no se especifica ninguna de las opciones, se intentará leer el directorio de configuración predeterminado antes de intentar usar el archivo de configuración predeterminado. Si existe un directorio de configuración válido, se ignora el archivo de configuración predeterminado. Si también se especifica el modo de simulación, no se realizará ninguna conversión.
-g
Deshabilita la "pegadura" subordinada. Solo se procesará la base de datos especificada, y no sus subordinados pegados (si los hay).
-j num-línea
Salta a la línea especificada en el archivo LDIF antes de procesar cualquier entrada. Esto permite reanudar una modificación que se abortó debido a errores en el LDIF de entrada después de corregir los errores.
-l archivo-ldif
Lee LDIF del archivo especificado en lugar de la entrada estándar.
-n num-db
Realiza cambios en la base de datos número num-db listada en el archivo de configuración. La opción -n no se puede usar junto con la opción -b. Para manipular la base de datos de configuración slapd-config(5), usa -n 0 ya que siempre es la primera base de datos. Sin embargo, debe existir físicamente en el sistema de archivos antes.
-o opción[=valor]
Especifica una opción con un valor (opcional). Las opciones/valores genéricos posibles son:
              syslog=<subsistemas>  (ver `-s' en slapd(8))
              syslog-level=<nivel> (ver `-S' en slapd(8))
              syslog-user=<usuario>   (ver `-l' en slapd(8))
              schema-check={yes|no}
              value-check={yes|no}
La opción schema-check alterna la verificación del esquema (activada por
defecto); la opción value-check alterna la verificación de valores (desactivada
por defecto). Esta última es incompatible con -q.
-q
habilita el modo rápido (menos comprobaciones de integridad). Realiza
menos comprobaciones de consistencia en los datos de entrada, y ninguna
comprobación de consistencia al escribir la base de datos. Mejora el tiempo
de ejecución, pero si ocurren errores o interrupciones, la base de datos
resultante será inutilizable.
-s
deshabilita la verificación del esquema. Esta opción está destinada a
ser utilizada al manipular bases de datos que contienen objetos
especiales, como objetos fraccionales en una réplica parcial. La creación
de objetos normales que no se ajustan al esquema puede dar lugar a
comportamientos inesperados y erróneos.
-S SID
ID del servidor a utilizar en entryCSN generado. También se utiliza para
contextCSN si también se establece -w. Por defecto es 0.
-u
habilita el modo de simulación (no escribir en el backend).
-v
habilita el modo detallado.
-w
escribe información de contexto syncrepl. Después de que se agreguen
todas las entradas, contextCSN se actualizará con el CSN más grande en la
base de datos.

LIMITACIONES

Tu slapd(8) no debe estar ejecutándose cuando hagas esto para asegurar la consistencia de la base de datos.

No todos los backends admiten todos los tipos de modificación; el cambio de tipo modrdn en particular no está implementado para ninguno de los backends actuales.

slapmodify puede no proporcionar comprobaciones de nombres o de esquema. Es aconsejable usar ldapmodify(1) cuando sea posible.

EJEMPLOS

Para realizar modificaciones especificadas en el archivo ldif en tu base de datos slapd(8), ejecuta el comando:

/usr/bin/slapmodify -l ldif
