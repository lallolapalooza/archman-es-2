NOMBRE

slapo-constraint - Overlay de restricción de atributos para slapd

SINOPSIS

/etc/openldap/slapd.conf

DESCRIPCIÓN

El overlay de restricción se utiliza para garantizar que los valores de los atributos coincidan con ciertas restricciones más allá de la sintaxis básica de LDAP. Los atributos pueden tener múltiples restricciones aplicadas, y todas deben cumplirse al modificar un valor de atributo bajo restricción.

Este overlay está diseñado para forzar la regularidad sintáctica en ciertos datos representados como cadenas, que tienen formas canónicas bien conocidas, como números de teléfono, códigos postales, FQDNs, etc.

Solo restringe los comandos add, modify y rename de LDAP y solo busca controlar los valores add y replace de las solicitudes modify y rename.

No se aplican restricciones para operaciones realizadas con el control relax establecido.

CONFIGURACIÓN

Esta opción de slapd.conf se aplica al overlay de restricción. Debe aparecer después de la directiva overlay.

constraint_attribute <nombre_atributo>[,...] <tipo> <valor> [<extra> [...]]
Especifica la restricción que debe aplicarse a la lista de atributos separada por comas nombrada como el primer parámetro. Actualmente se admiten seis tipos de restricciones: regex, negregex, size, count, uri y set.

El parámetro que sigue al tipo regex o negregex es una expresión regular de estilo Unix (ver regex(7)). El parámetro que sigue al tipo uri es una URI LDAP. La URI se evaluará utilizando una búsqueda interna. No debe incluir un nombre de host y debe incluir una lista de atributos a evaluar.

El parámetro que sigue al tipo set es una cadena que se interpreta de acuerdo con la sintaxis en uso para los conjuntos de ACL. Esto permite construir restricciones basadas en el contenido de la entrada.

El tipo size se puede utilizar para imponer un límite a la longitud de un atributo, y el tipo count limita el número de valores de un atributo.

Los parámetros adicionales pueden aparecer en cualquier orden después de los descritos anteriormente.

<extra> : restrict=<uri>
Este parámetro adicional permite restringir la aplicación de la restricción correspondiente solo a las entradas que coinciden con las porciones de base, scope y filter de la URI LDAP. La base, si está presente, debe estar dentro del contexto de nombres de la base de datos. El scope solo se utiliza cuando la base está presente; por defecto es base. No se permiten los otros parámetros de la URI.

Cualquier intento de agregar o modificar un atributo nombrado como parte de la especificación del overlay de restricción que no se ajuste a la restricción listada fallará con un error LDAP_CONSTRAINT_VIOLATION.

EJEMPLOS

overlay constraint
constraint_attribute jpegPhoto size 131072
constraint_attribute userPassword count 3
constraint_attribute mail regex ^[[:alnum:]]+@mydomain.com$
constraint_attribute mail negregex ^[[:alnum:]]+@notallowed.com$
constraint_attribute title uri
  ldap:///dc=catalog,dc=example,dc=com?title?sub?(objectClass=titleCatalog)
constraint_attribute cn,sn,givenName set
  "(this/givenName + [ ] + this/sn) & this/cn"
  restrict="ldap:///ou=People,dc=example,dc=com??sub?(objectClass=inetOrgPerson)"

Una especificación como la anterior rechazaría cualquier atributo mail que no se pareciera a <cadena alfanumérica>@mydomain.com o que pareciera <cadena alfanumérica>@notallowed.com. También rechazaría cualquier atributo title cuyos valores no estuvieran listados en el atributo title de ninguna entrada titleCatalog dentro del ámbito dado. (Tenga en cuenta que el subárbol "dc=catalog,dc=example,dc=com" debería residir en una base de datos separada, de lo contrario, el conjunto inicial de entradas titleCatalog no podría poblarse mientras la restricción estuviera en vigor.) Finalmente, requiere que los valores del atributo cn se construyan emparejando valores de los atributos sn y givenName, separados por un espacio, pero solo para las entradas derivadas de objectClass inetOrgPerson.
