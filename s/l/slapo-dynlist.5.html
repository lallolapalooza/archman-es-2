SLAPO-DYNLIST(5) Manual de formatos de archivo SLAPO-DYNLIST(5)

NOMBRE

slapo-dynlist - Overlay de lista dinámica para slapd

SINOPSIS

/etc/openldap/slapd.conf

DESCRIPCIÓN

El overlay dynlist para slapd(8) permite la expansión de listas y grupos dinámicos. Cada vez que se devuelve una entrada con una objectClass específica (definida en la configuración del overlay) se expanden las ocurrencias del atributo específico (también definido en la configuración del overlay) con valor de URI LDAP en las entradas correspondientes.

Para una lista dinámica, los valores de los atributos listados en la URI se añaden desde las entradas coincidentes a la entrada original. No se permite recursión para evitar bucles infinitos potenciales. La entrada resultante debe cumplir con el modelo de datos LDAP, por lo que se aplican restricciones. Por ejemplo, si se lista un atributo de tipo SINGLE-VALUE, solo el primer valor encontrado durante la expansión de la lista aparece en la entrada final.

Para un grupo dinámico, los DN de las entradas coincidentes se añaden a un atributo de miembro en la entrada original.

Todo el comportamiento dinámico se deshabilita cuando se utiliza el control manageDSAit (RFC 3296). En ese caso, se devuelve el contenido de la entrada original; es decir, se devuelven las URLs en lugar de expandirse.

CONFIGURACIÓN

Las directivas de configuración que son específicas del overlay dynlist deben ir precedidas por dynlist-, para evitar posibles conflictos con directivas específicas de la base de datos subyacente o de otros overlays apilados.

overlay dynlist
Esta directiva añade el overlay dynlist a la base de datos actual, o al frontend, si se usa antes de cualquier instanciación de base de datos; ver slapd.conf(5) para detalles.

Esta opción de configuración de slapd.conf está definida para el overlay dynlist. Puede tener múltiples ocurrencias y debe aparecer después de la directiva overlay.

dynlist-attrset <group-oc> [<URI>] <URL-ad> [opciones]

El valor group-oc es el nombre de la objectClass que desencadena la expansión dinámica de los datos.

La URI opcional restringe la expansión solo a las entradas que coinciden con las porciones de DN, alcance y filtro de la URI.

El valor URL-ad es el nombre de la attributeDescription que contiene la URI que es expandida por el overlay; si no hay ninguna, no ocurre ninguna expansión. Si la intersección de los atributos solicitados por la operación de búsqueda (o el atributo afirmado para comparaciones) y los atributos listados en la URI está vacía, no ocurre ninguna expansión para esa URI específica. Debe ser un subtipo de labeledURI.

Las opciones restantes dependen de si se está configurando una lista dinámica o un grupo dinámico.

Para una lista dinámica, las opciones permitidas tienen la forma

[<mapped-ad>:<list-ad> ...]

El mapped-ad se puede usar para remapear atributos obtenidos a través de la expansión. El list-ad debe ser uno de los atributos devueltos en la expansión de las URIs en el atributo URL-ad de la entrada dinámica. Se pueden usar múltiples declaraciones de mapeo. Tenga en cuenta que para que las listas dinámicas sean utilizables en un filtro de búsqueda, los atributos dinámicos que se filtrarán deben mapearse explícitamente. Pueden mapearse a sí mismos si no se requiere ninguna transformación.

Para un grupo dinámico, las opciones permitidas son

<member-ad>[+<memberOf-ad>[@<static-oc>[*]]]

El member-ad es requerido; este atributo listará el DN de las entradas resultantes de la búsqueda interna. En este caso, la porción de attrs de las URIs en el atributo URL-ad debe estar ausente, y los DN de todas las entradas resultantes de la expansión de las URIs se listan como valores de este atributo. Las comparaciones que afirman el valor del atributo member-ad de las entradas con la objectClass group-oc se aplican como si el DN de las entradas resultantes de la expansión de la URI estuviera presente en la entrada group-oc como valores del atributo member-ad. Si el atributo opcional memberOf-ad también se especifica, entonces se poblará con los DN de los grupos dinámicos de los que una entrada es miembro. Si la objectClass opcional static-oc también se especifica, entonces el atributo memberOf también se poblará con los DN de los grupos estáticos de los que una entrada es miembro. Tenga en cuenta que usar la misma objectClass static-oc en más de una configuración de grupo dinámico no está soportado. Si el carácter opcional * también se especifica, entonces los valores de miembro y miembroDe se poblarán recursivamente, para grupos anidados. Tenga en cuenta que actualmente la anidación solo se soporta para Operaciones de Búsqueda, no para Comparaciones.

dynlist-simple TRUE | FALSE
Esta opción reduce el comportamiento del overlay dynlist de OpenLDAP 2.4. Deshabilita el procesamiento de memberOf, el soporte de grupos anidados y la evaluación de filtros de valores generados dinámicamente. El valor por defecto es FALSE.

El overlay dynlist puede usarse con cualquier backend, pero está principalmente destinado a usarse con backends de almacenamiento local. En caso de que la expansión de URI sea muy intensiva en recursos y ocurra frecuentemente con patrones bien definidos, se debe considerar añadir un proxycache más adelante en la pila de overlays.

AUTORIZACIÓN

Por defecto, las expansiones se realizan utilizando la identidad del usuario LDAP actual. Esta identidad puede ser anulada estableciendo el atributo dgIdentity en la entrada del grupo al DN de otro usuario LDAP. En ese caso, se usará dgIdentity al expandir las URIs en el objeto. Establecer dgIdentity a una cadena de longitud cero hará que las expansiones se realicen anónimamente. Tenga en cuenta que el atributo dgIdentity está definido en el esquema dyngroup, y este esquema debe cargarse antes de que la característica de autorización dgIdentity pueda ser utilizada. Si el atributo dgAuthz también está presente en la entrada del grupo, sus valores se utilizan para determinar qué identidades están autorizadas a usar el dgIdentity para expandir el grupo. Los valores del atributo dgAuthz deben cumplir con la sintaxis (experimental) de autorización de OpenLDAP. Al usar memberOf dinámico en filtros de búsqueda, se requiere acceso de búsqueda al pseudo-atributo entryDN.

EJEMPLO

Este ejemplo recopila todas las direcciones de correo electrónico de una base de datos en una sola entrada; en primer lugar, asegúrese de que slapd.conf contenga las directivas:

    include /path/to/dyngroup.schema
    # ...
    database <database>
    # ...
    overlay dynlist
    dynlist-attrset groupOfURLs memberURL

y que slapd cargue dynlist.la, si se compila como un módulo de tiempo de ejecución; luego añada a la base de datos una entrada como

    dn: cn=Lista Dinámica,ou=Grupos,dc=ejemplo,dc=com
    objectClass: groupOfURLs
    cn: Lista Dinámica
    memberURL: ldap:///ou=Personas,dc=ejemplo,dc=com?mail?sub?(objectClass=person)

Si no se proporcionan <attrs> en la URI, se recopilan todos los atributos (no operativos).

Los valores de la lista anterior no pueden ser evaluados en un filtro de búsqueda. Para habilitar la evaluación de filtros en la lista dinámica, la configuración debe modificarse para mapear explícitamente los atributos dinámicos que se filtrarán. En este caso, mail simplemente se mapea a sí mismo.

    include /path/to/dyngroup.schema
    # ...
    database <database>
    # ...
    overlay dynlist
    dynlist-attrset groupOfURLs memberURL mail:mail

Este ejemplo implementa la característica de grupo dinámico en el atributo member:

    include /path/to/dyngroup.schema
    # ...
    database <database>
    # ...
    overlay dynlist
    dynlist-attrset groupOfURLs memberURL member

Un grupo dinámico con autorización dgIdentity podría crearse con una entrada como

    dn: cn=Grupo Dinámico,ou=Grupos,dc=ejemplo,dc=com
    objectClass: groupOfURLs
    objectClass: dgIdentityAux
    cn: Grupo Dinámico
    memberURL: ldap:///ou=Personas,dc=ejemplo,dc=com??sub?(objectClass=person)
    dgIdentity: cn=Proxy de Grupo,ou=Servicios,dc=ejemplo,dc=com

Este ejemplo amplía la característica de grupo dinámico para añadir un dgMem dinámico

slapo-dynlist(5) — OpenLDAP netgroup overlay

NAME

slapo-dynlist — OpenLDAP dynamic list overlay

SYNOPSIS

  // LDAP protocols >= 3
  dn: cn=config
  cn: olcOverlay
  objectClass: olcOverlayConfig
  olcOverlay: dyngroup
  ...
  dn: olcOverlay=dyngroup,olcDatabase={...},cn=config
  cn: olcOverlay
  objectClass: olcDynGroupConfig
  olcOverlay: dyngroup
  olcDynGroupMemberAttr: member
  olcDynGroupMemberAttr: memberUid
  olcDynGroupMemberAttr: uniqueMember
  olcDynGroupMaxDepth: 10
          
  // LDAP protocols < 3
  dn: olcDatabase={...},cn=config
  objectClass: olcDatabaseConfig
  objectClass: olcDynGroupConfig
  olcDynGroupMemberAttr: member
  olcDynGroupMemberAttr: memberUid
  olcDynGroupMemberAttr: uniqueMember
  olcDynGroupMaxDepth: 10

DESCRIPTION

The dynlist overlay provides support for dynamic group memberships. It allows group memberships to be defined by search filters, rather than explicit membership lists. This feature is commonly referred to as dynamic group membership.

The overlay intercepts group modification operations and instead of modifying the group's member list, it stores the search filter used to define the group membership. When a group is accessed, the overlay performs the stored search filter to retrieve the members of the group dynamically.

The dynlist overlay supports dynamic group membership based on the memberURL attribute, similar to the dyngroup overlay. It allows groups to be defined by search filters stored in the group's entry.

The overlay provides support for defining group memberships using search filters specified in the memberURL attribute. When a group entry is accessed, the overlay dynamically evaluates the search filter associated with the memberURL attribute to determine the group's members.

It also supports the member, memberUid, and uniqueMember attributes for static group definitions, allowing for a mix of static and dynamic memberships within the same group.

The dynlist overlay can also be used to automatically add a memberOf attribute to entries that are members of groups. This feature is useful for applications that need to quickly determine the groups an entry belongs to, without having to search for all groups that contain the entry as a member.

CONFIGURATION

The dynlist overlay is configured using the olcOverlay directive in the slapd.conf file, or dynamically via the cn=config backend.

The following configuration options are available:

olcDynGroupMemberAttr:
Specifies the attribute used to store group memberships. This attribute can be member, memberUid, or uniqueMember. Multiple attributes can be specified.
olcDynGroupMaxDepth:
Specifies the maximum nesting depth for dynamic group memberships. The default value is 10.

When using memberURL, the overlay also supports the following options:

olcDynListAttrSet:
This is a multi-valued attribute that defines the set of attributes associated with a dynamic list. The format is: attribute=memberURL_attribute[,attribute=member_attribute]. The memberURL_attribute is the attribute containing the search filter, and the optional member_attribute is the attribute to be populated with the members found by the search filter. If not specified, the members are added to the default member attribute of the group.
olcDynListMaxDepth:
Maximum nesting depth for dynamic group memberships. Default is 10.

AUTHORIZATION

The dynlist overlay does not directly handle authorization. However, it can be used in conjunction with other overlays or access control mechanisms to enforce access control based on dynamic group memberships.

EXAMPLE

To enable dynamic group membership using the memberURL attribute, add the following to your slapd.conf file:

    include /path/to/dyngroup.schema
    # ...
    database <database>
    # ...
    overlay dynlist
    dynlist-attrset groupOfURLs memberURL member+dgMemberOf

This example extends the dynamic memberOf feature to add the memberOf attribute to all the members of both static and dynamic groups:

    include /path/to/dyngroup.schema
    # ...
    database <database>
    # ...
    overlay dynlist
    dynlist-attrset groupOfURLs memberURL member+memberOf@groupOfNames

This dynamic memberOf feature can fully replace the functionality of the slapo-memberof(5) overlay.

FILES

/etc/openldap/slapd.conf
default slapd configuration file

BACKWARD COMPATIBILITY

The dynlist overlay has been reworked with the 2.5 release to use a consistent namespace as with other overlays. As a side-effect the following cn=config parameters are deprecated and will be removed in a future release: olcDlAttrSet is replaced with olcDynListAttrSet olcDynamicList is replaced with olcDynListConfig

SEE ALSO

slapd.conf(5), slapd-config(5), slapd(8). The slapo-dynlist(5) overlay supports dynamic configuration via back-config.

BUGS

Filtering on dynamic groups may return incomplete results if the search operation uses the pagedResults control.
