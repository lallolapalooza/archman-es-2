NOMBRE

systemd-sleep.conf, sleep.conf.d - Archivo de configuración de suspensión e hibernación

SINOPSIS

/etc/systemd/sleep.conf
/run/systemd/sleep.conf
/usr/lib/systemd/sleep.conf
/etc/systemd/sleep.conf.d/*.conf
/run/systemd/sleep.conf.d/*.conf
/usr/lib/systemd/sleep.conf.d/*.conf

DESCRIPCIÓN

systemd soporta cuatro modos generales de ahorro de energía:

suspend

un estado de bajo consumo donde la ejecución del SO se pausa, y una pérdida completa de energía podría resultar en pérdida de datos, y que es rápido de entrar y salir. Esto corresponde a los estados de suspensión, espera o congelación según lo entiende el kernel.

Añadido en la versión 203.

hibernate

un estado de bajo consumo donde la ejecución del SO se pausa, y una pérdida completa de energía no resulta en pérdida de datos, y que puede ser lento de entrar y salir. Esto corresponde a la hibernación según lo entiende el kernel.

Añadido en la versión 203.

hybrid-sleep

un estado de bajo consumo donde la ejecución del SO se pausa, que puede ser lento de entrar, y en caso de pérdida completa de energía no resulta en pérdida de datos, pero puede ser más lento de salir en ese caso. Este modo se llama suspend-to-both (suspender a ambos) por el kernel.

Añadido en la versión 203.

suspend-then-hibernate

Un estado de bajo consumo donde el sistema se suspende inicialmente (el estado se almacena en RAM). Cuando el nivel de la batería es demasiado bajo (menos del 5%) o ha pasado un cierto período de tiempo, lo que ocurra primero, el sistema se activa automáticamente y luego se hiberna. Esto establece un equilibrio entre velocidad y seguridad.

Si el sistema no tiene batería, se hibernará después de que haya pasado HibernateDelaySec=. Si no está configurado, el valor predeterminado es "2h".

Si el sistema tiene batería y HibernateDelaySec= no está configurado, se intentan primero las alarmas de batería baja (ACPI _BTP) para detectar el porcentaje de la batería y despertar el sistema para la hibernación. Si no están disponibles, o si HibernateDelaySec= está configurado, el sistema se despertará periódicamente para comprobar la hora y detectar el porcentaje de la batería/tasa de descarga. La tasa se utiliza para programar la próxima detección. Si tampoco está disponible, SuspendEstimationSec= se utiliza como último recurso.

Añadido en la versión 239.

Los ajustes en estos archivos determinan qué cadenas se escribirán en /sys/power/disk y /sys/power/state por systemd-sleep(8) cuando systemd(1) intente suspender o hibernar la máquina. Consulte systemd.syntax(7) para una descripción general de la sintaxis.

DIRECTORIOS DE CONFIGURACIÓN Y PRECEDENCIA

La configuración predeterminada se establece durante la compilación, por lo que la configuración solo es necesaria cuando es necesario desviarse de esos valores predeterminados. El archivo de configuración principal se carga desde uno de los directorios listados en orden de prioridad, solo el primer archivo encontrado se utiliza: /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La versión del proveedor del archivo contiene entradas comentadas que muestran los valores predeterminados como guía para el administrador. Las anulaciones locales también se pueden crear creando archivos drop-in, como se describe a continuación. El archivo de configuración principal también se puede editar para este propósito (o una copia en /etc/ si se distribuye bajo /etc/), sin embargo, se recomienda el uso de archivos drop-in para la configuración local en lugar de modificar el archivo de configuración principal.

Además del archivo de configuración principal, se leen fragmentos de configuración drop-in de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, y /etc/systemd/*.conf.d/. Estos drop-ins tienen mayor precedencia y anulan el archivo de configuración principal. Los archivos en los subdirectorios de configuración *.conf.d/ se ordenan por su nombre de archivo en orden lexicográfico, independientemente de en qué subdirectorios residan. Cuando varios archivos especifican la misma opción, para las opciones que aceptan solo un valor único, la entrada en el archivo ordenado último tiene precedencia, y para las opciones que aceptan una lista de valores, las entradas se recopilan a medida que ocurren en los archivos ordenados.

Cuando los paquetes necesitan personalizar la configuración, pueden instalar drop-ins bajo /usr/. Los archivos en /etc/ están reservados para el administrador local, quien puede usar esta lógica para anular los archivos de configuración instalados por los paquetes del proveedor. Los drop-ins deben usarse para anular los drop-ins de paquetes, ya que el archivo de configuración principal tiene menor precedencia. Se recomienda prefijar todos los nombres de archivo en esos subdirectorios con un número de dos dígitos y un guion, para simplificar el ordenamiento. Esto también define un concepto de prioridades de drop-in para permitir que los proveedores de sistemas operativos distribuyan drop-ins dentro de un rango específico inferior al rango utilizado por los usuarios. Esto debería reducir el riesgo de que los drop-ins de paquetes anulen accidentalmente los drop-ins definidos por los usuarios. Se recomienda usar el rango 10-40 para drop-ins en /usr/ y el rango 60-90 para drop-ins en /etc/ y /run/, para asegurarse de que los drop-ins locales y transitorios tengan prioridad sobre los drop-ins distribuidos por el proveedor del sistema operativo.

Para deshabilitar un archivo de configuración proporcionado por el proveedor, la forma recomendada es colocar un enlace simbólico a /dev/null en el directorio de configuración en /etc/, con el mismo nombre de archivo que el archivo de configuración del proveedor.

OPCIONES

Las siguientes opciones se pueden configurar en la sección [Sleep] de /etc/systemd/sleep.conf o un archivo sleep.conf.d:

AllowSuspend=, AllowHibernation=, AllowHybridSleep=, AllowSuspendThenHibernate=

Por defecto, cualquier modo de ahorro de energía se anuncia si es posible (es decir, el kernel soporta ese modo, los recursos necesarios están disponibles). Estos interruptores se pueden usar para deshabilitar modos específicos.

Si se usa AllowHibernation=no o AllowSuspend=no, esto implica AllowSuspendThenHibernate=no y AllowHybridSleep=no, ya que estos métodos utilizan suspensión e hibernación internamente. AllowSuspendThenHibernate=yes y AllowHybridSleep=yes se pueden usar para anular y habilitar esos modos específicos.

Añadido en la versión 240.

SuspendState=

La cadena que se escribirá en /sys/power/state por systemd-suspend.service(8). Se pueden especificar varios valores separando múltiples valores con espacios en blanco. Se intentarán uno por uno, hasta que uno se escriba sin error. Si ninguna de las escrituras tiene éxito, la operación se abortará.

El conjunto de valores permitidos está determinado por el kernel y se muestra en el propio archivo (use cat /sys/power/state para mostrar). Consulte Basic sysfs Interfaces for System Suspend and Hibernation[2] para más detalles.

systemd-suspend-then-hibernate.service(8) utiliza este valor al suspender.

Añadido en la versión 203.

HibernateMode=

La cadena que se escribirá en /sys/power/disk por systemd-hibernate.service(8). Se pueden especificar varios valores separando múltiples valores con espacios en blanco. Se intentarán uno por uno, hasta que uno se escriba sin error. Si ninguna de las escrituras tiene éxito, la operación se abortará.

El conjunto de valores permitidos está determinado por el kernel y se muestra en el propio archivo (use cat /sys/power/disk para mostrar). Consulte la página de documentación del kernel Basic sysfs Interfaces for System Suspend and Hibernation[2] para más detalles.

systemd-suspend-then-hibernate.service(8) utiliza el valor de HibernateMode= al hibernar.

Añadido en la versión 203.

MemorySleepMode=

La cadena que se escribirá en /sys/power/mem_sleep cuando se utilice SuspendState=mem o hybrid-sleep. Se pueden especificar varios valores separando múltiples valores con espacios en blanco. Se intentarán uno por uno, hasta que uno se escriba sin error. Si ninguna de las escrituras tiene éxito, la operación se abortará. Por defecto está vacío, es decir, se respeta el valor predeterminado del kernel o la opción de línea de comandos del kernel mem_sleep_default=.

El conjunto de valores permitidos está determinado por el kernel y se muestra en el propio archivo (use cat /sys/power/mem_sleep para mostrar). Consulte la página de documentación del kernel Basic sysfs Int systemd.directives(7) — Arch manual pages

NAME

systemd.directives - Systemd directives

SYNOPSIS

sleep.conf

DESCRIPTION

Many systemd configuration files, especially those in .conf (5) format, share a common set of directives. This page lists and describes the most common directives that are applicable to multiple configuration file types, or that are specific to sleep/suspend/hibernate related configuration.

This page does not describe directives that are specific to a single configuration file type (e.g., journald.conf(5), systemd.exec(5)).

CONFIGURATION DIRECTORIES AND PRECEDENCE

Systemd directives can be configured in multiple locations, and systemd loads them in a specific order. The precedence order is:

  1. Configuration files in /etc/systemd/system/.
  2. Configuration files in /run/systemd/system/.
  3. Configuration files in /usr/lib/systemd/system/.

If multiple configuration files specify the same directive, the one in the highest-precedence directory takes effect. Files in the same directory are processed in alphabetical order.

For detailed information on how directives are loaded and how multiple configuration files are merged, see systemd.unit(5).

OPTIONS

The following directives are common across multiple configuration files or specific to sleep/suspend/hibernate:

General Options

DefaultCPUAccounting=, DefaultIOAccounting=, DefaultBlockIOAccounting=, DefaultMemoryAccounting=, DefaultIPAccounting=, DefaultNetClassify=, DefaultTasksAccounting=

See systemd.resource-control(5) for a description of these directives. They control the default resource control settings for all units.

DefaultTimerAccuracySec=

The default precision for timer units. See systemd.timer(5) for a description of this directive.

Sleep Options

The following options are used to configure the behavior of systemd's suspend, hibernate and hybrid-sleep targets.

SuspendState=

A space-separated list of states to try suspend in. Recognized states are freeze, idle, mem, disk.

The system will attempt to enter suspend in the listed order. The first state that succeeds will be used. The kernel's suspend code is used for mem and disk states, while freeze and idle are implemented in userspace. These are typically mapped to the system's suspend-to-idle and suspend-to-RAM states.

The default value is freeze mem disk.

For more details on the different suspend states, refer to the kernel documentation on Basic sysfs Interfaces for System Suspend and Hibernation [2].

Added in version 256.

HibernateDelaySec=

The amount of time the system spends in suspend mode before the system is automatically put into hibernate mode. Only used by systemd-suspend-then-hibernate.service(8). Refer to suspend-then-hibernate for details on how this option interacts with other options/system battery state.

Added in version 239.

HibernateOnACPower=

Whether to allow hibernation when the system has AC power. Only used by systemd-suspend-then-hibernate.service(8) when HibernateDelaySec= is set.

If this option is disabled, the countdown of HibernateDelaySec= starts only after AC power is disconnected, keeping the system in the suspend state otherwise.

This option is only effective on systems with a battery.

Added in version 257.

SuspendEstimationSec=

The RTC alarm will wake the system after the specified timespan to measure the system battery capacity level and estimate battery discharging rate. Only used by systemd-suspend-then-hibernate.service(8). Refer to suspend-then-hibernate for details on how this option interacts with other options/system battery state.

Added in version 253.

EXAMPLE: FREEZE

Example: to exploit the “freeze” mode added in Linux 3.9, one can use systemctl suspend with

[Sleep]
SuspendState=freeze
