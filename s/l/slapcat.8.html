NOMBRE

slapcat - Utilidad de base de datos SLAPD a LDIF

SINOPSIS

/usr/bin/slapcat [-afiltro] [-bsufijo] [-c] [-dnivel-debug] [-fslapd.conf] [-Fconfdir] [-g] [-HURI] [-larchivo-ldif] [-nnum-db] [-oopcion[=valor]] [-sdn-subarbol] [-v]

DESCRIPCIÓN

Slapcat se utiliza para generar una salida en formato LDIF (LDAP Directory Interchange Format) basada en el contenido de una base de datos de slapd(8). Abre la base de datos especificada, determinada por el número de base de datos o el sufijo, y escribe el LDIF correspondiente en la salida estándar o en el archivo especificado. Las bases de datos configuradas como subordinadas de esta también se exportan, a menos que se especifique -g.

Los registros de entrada se presentan en orden de base de datos, no en orden de superior primero. Los registros de entrada incluirán todos los atributos (de usuario y operacionales) almacenados en la base de datos. Los registros de entrada no incluirán atributos generados dinámicamente (como subschemaSubentry).

La salida de slapcat está destinada a ser utilizada como entrada para slapadd(8). La salida de slapcat generalmente no se puede utilizar como entrada para ldapadd(1) u otros clientes LDAP sin editar previamente la salida. Esta edición normalmente incluiría reordenar los registros en orden de superior primero y eliminar los atributos operacionales no modificables por el usuario.

OPCIONES

-a filtro
Solo exportar entradas que coincidan con el filtro especificado. Por ejemplo:

slapcat -a \
"(!(entryDN:dnSubtreeMatch:=ou=People,dc=example,dc=com))"

exportará todo excepto el subárbol "ou=People,dc=example,dc=com" de la base de datos "dc=example,dc=com". Obsoleto; usar -H ldap:///???(filtro) en su lugar.

-b sufijo
Usar el sufijo especificado para determinar qué base de datos generar. Por defecto, se utiliza la primera base de datos que admite la operación solicitada. La opción -b no se puede usar junto con la opción -n.
-c
Habilitar el modo de continuación (ignorar errores). Múltiples ocurrencias de -c hacen que slapcat(8) intente con más ahínco.
-d nivel-debug
Habilitar mensajes de depuración según lo definido por el nivel-debug especificado; ver slapd(8) para más detalles.
-f slapd.conf
Especificar un archivo slapd.conf(5) alternativo.
-F confdir
Especificar un directorio de configuración. Si se especifican tanto -f como -F, el archivo de configuración se leerá y se convertirá al formato de directorio de configuración y se escribirá en el directorio especificado. Si no se especifica ninguna de las opciones, se intentará leer el directorio de configuración predeterminado antes de intentar usar el archivo de configuración predeterminado. Si existe un directorio de configuración válido, se ignora el archivo de configuración predeterminado.
-g
Deshabilitar la unión subordinada. Solo se procesará la base de datos especificada, y no sus subordinadas unidas (si las hay).
-H  URI
Usar el DN, el ámbito y el filtro de la URI para manejar solo las entradas coincidentes.
-l archivo-ldif
Escribir LDIF en el archivo especificado en lugar de la salida estándar.
-n num-db
Generar la salida para la base de datos número num-db listada en el archivo de configuración. La base de datos de configuración slapd-config(5), siempre es la primera base de datos, así que use -n 0 para seleccionarla.

La opción -n no se puede usar junto con la opción -b.

-o opcion[=valor]
Especificar una opción con un valor (opcional). Las opciones/valores genéricos posibles son:
              syslog=<submódulos> (ver `-s' en slapd(8))
              syslog-level=<nivel> (ver `-S' en slapd(8))
              syslog-user=<usuario> (ver `-l' en slapd(8))
              ldif_wrap={no|<n>}
n es el número de columnas permitidas para la salida LDIF
(n igual a 0 usa el predeterminado, correspondiente a 78).
El mínimo es 2, dejando espacio para un carácter y un
carácter de continuación.
Usar no para no envolver.
-s dn-subarbol
Solo exportar entradas en el subárbol especificado por este DN.
Implica -b dn-subarbol si no se da la opción
-b
o
-n.
Obsoleto; usar -H ldap:///dn-subarbol en su lugar.
-v
Habilitar modo detallado.

LIMITACIONES

Para algunos tipos de backend, su slapd(8) no debería estar en ejecución (al menos, no en modo de lectura/escritura) cuando haga esto para garantizar la consistencia de la base de datos. Siempre es seguro ejecutar slapcat con los backends slapd-mdb(5) y slapd-null(5).

EJEMPLOS

Para hacer una copia de seguridad en texto de su base de datos SLAPD y ponerla en un archivo llamado ldif, ejecute el comando:

/usr/bin/slapcat -l ldif
