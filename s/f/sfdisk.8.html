SFDISK(8) Administración del Sistema SFDISK(8)

NOMBRE

sfdisk - mostrar o manipular una tabla de particiones de disco

SINOPSIS

sfdisk [opciones] dispositivo [-N número-de-partición]

sfdisk [opciones] comando

DESCRIPCIÓN

sfdisk es una herramienta orientada a scripts para particionar cualquier dispositivo de bloque. Se ejecuta en modo interactivo si se ejecuta en una terminal (stdin se refiere a una terminal).

Desde la versión 2.26, sfdisk soporta etiquetas de disco MBR (DOS), GPT, SUN y SGI, pero ya no proporciona ninguna funcionalidad para la dirección CHS (Cilindro-Cabezal-Sector). CHS nunca fue importante para Linux, y este concepto de direccionamiento no tiene ningún sentido para dispositivos nuevos.

sfdisk protege el primer sector del disco al crear una nueva etiqueta de disco. La opción --wipe always deshabilita esta protección. Tenga en cuenta que fdisk(8) y cfdisk(8) borran completamente esta área por defecto.

sfdisk (desde la versión 2.26) alinea el inicio y el final de las particiones a los límites de E/S del dispositivo de bloque cuando se especifican tamaños relativos, cuando se usan los valores predeterminados o cuando se usan sufijos multiplicativos (por ejemplo, MiB) para los tamaños. Es posible que el tamaño de la partición se optimice (se reduzca o se amplíe) debido a la alineación si el desplazamiento de inicio se especifica exactamente en sectores y el tamaño de la partición de forma relativa o con sufijos multiplicativos.

La forma recomendada es no especificar los desplazamientos de inicio y especificar el tamaño de la partición en MiB, GiB (o similar). En este caso, sfdisk alinea todas las particiones a los límites de E/S del dispositivo de bloque (o si los límites de E/S son demasiado pequeños, entonces a un límite de megabytes para mantener el diseño del disco portable). Si este comportamiento predeterminado no es deseado (generalmente para particiones muy pequeñas), entonces especifique los desplazamientos y los tamaños en sectores. En este caso, sfdisk sigue completamente los números especificados sin ninguna optimización.

sfdisk no crea las particiones del sistema estándar para las etiquetas de disco SGI y SUN como lo hace fdisk(8). Es necesario crear explícitamente todas las particiones, incluidas las particiones del disco completo del sistema.

sfdisk utiliza la llamada al sistema BLKRRPART (volver a leer la tabla de particiones) para asegurarse de que el dispositivo no está siendo utilizado por el sistema u otras herramientas (ver también --no-reread). Es posible que esta característica u otra actividad de sfdisk entre en conflicto con systemd-udevd(8). La forma recomendada para evitar posibles colisiones es usar la opción --lock. El bloqueo exclusivo hará que systemd-udevd omita el manejo de eventos en el dispositivo.

El prompt de sfdisk es solo una indicación para los usuarios y un número de partición mostrado no significa que se creará la misma entrada de tabla de particiones (si no se especifica -N), especialmente para tablas con huecos.

COMANDOS

Los comandos son mutuamente excluyentes.

[-N número-de-partición] dispositivo

El comando predeterminado de sfdisk es leer la especificación para la partición deseada del dispositivo desde la entrada estándar y luego crear una tabla de particiones de acuerdo con la especificación. Ver más abajo la descripción del formato de entrada. Si la entrada estándar es una terminal, entonces sfdisk inicia una sesión interactiva.

Si se especifica la opción -N, entonces los cambios se aplican a la partición a la que se accede mediante número-de-partición. Los campos no especificados de la partición no se modifican.

Tenga en cuenta que es posible acceder a una partición no utilizada con -N. Por ejemplo, un MBR siempre contiene 4 particiones, pero el número de particiones utilizadas puede ser menor. En este caso, sfdisk sigue los valores predeterminados de la tabla de particiones y no utiliza los valores predeterminados incorporados para la partición no utilizada dada con -N. Ver también --append.

-A, --activate dispositivo [número-de-partición...]

Activa el flag de arranque para las particiones especificadas y desactiva el flag de arranque en todas las particiones no especificadas. El marcador especial '-' puede usarse en lugar de los números de partición para desactivar el flag de arranque en todas las particiones.

El comando de activación es compatible con MBR y PMBR solamente. Si se detecta una etiqueta GPT, entonces sfdisk imprime una advertencia y entra automáticamente en PMBR.

Si no se especifica ningún número-de-partición, entonces enumera las particiones con un flag habilitado.

--backup-pt-sectors dispositivo

Copia de seguridad de los sectores de la tabla de particiones actual en formato binario y sale. Ver la sección COPIA DE SEGURIDAD DE LA TABLA DE PARTICIONES.

--delete dispositivo [número-de-partición...]

Elimina todas las particiones o las particiones especificadas.

-d, --dump dispositivo

Vuelca las particiones de un dispositivo en un formato que puede ser utilizado como entrada para sfdisk. Ver la sección COPIA DE SEGURIDAD DE LA TABLA DE PARTICIONES.

-g, --show-geometry [dispositivo...]

Lista la geometría de todos los dispositivos o de los dispositivos especificados. Para compatibilidad con versiones anteriores, la opción obsoleta --show-pt-geometry tiene el mismo significado que esta.

-J, --json dispositivo

Vuelca las particiones de un dispositivo en formato JSON. Tenga en cuenta que sfdisk no puede utilizar JSON como formato de entrada.

-l, --list [dispositivo...]

Lista las particiones de todos los dispositivos o de los dispositivos especificados. Este comando puede usarse junto con --verify.

-F, --list-free [dispositivo...]

Lista las áreas libres no particionadas en todos los dispositivos o en los dispositivos especificados.

--part-attrs dispositivo número-de-partición [atributos]

Cambia los bits de atributo de partición GPT. Si no se especifica atributos, entonces imprime la configuración actual de la partición. El argumento atributos es una lista de números de bits o nombres de bits separada por comas o espacios. Por ejemplo, la cadena "RequiredPartition,50,51" establece tres bits. Los bits de atributo actualmente compatibles son:

Bit 0 (RequiredPartition)

Si este bit está establecido, la partición es necesaria para el funcionamiento de la plataforma. El creador de la partición indica que la eliminación o modificación del contenido puede resultar en la pérdida de funciones de la plataforma o en un fallo al arrancar o operar la plataforma. El sistema no puede funcionar normalmente si se elimina esta partición, y debe considerarse parte del hardware del sistema.

Bit 1 (NoBlockIOProtocol)

El firmware EFI debe ignorar el contenido de la partición y no intentar leer de ella.

Bit 2 (LegacyBIOSBootable)

La partición puede ser arrancable por el firmware BIOS heredado.

Bits 3-47

No definidos y deben ser cero. Reservados para expansión por versiones futuras de la especificación UEFI.

Bits 48-63

Reservados para uso específico de GUID. El uso de estos bits variará según el tipo de partición. Por ejemplo, Microsoft usa el bit 60 para indicar solo lectura, 61 para copia sombra de otra partición, 62 para particiones ocultas y 63 para deshabilitar el montaje automático.

--part-label dispositivo número-de-partición [etiqueta]

Cambia el nombre (etiqueta) de la partición GPT. Si no se especifica etiqueta, entonces imprime la etiqueta actual de la partición.

--part-type dispositivo número-de-partición [tipo]

Cambia el tipo de partición. Si no se especifica tipo, entonces imprime el tipo actual de la partición.

El argumento tipo es hexadecimal para MBR, GUID para GPT, alias de tipo (por ejemplo, "linux") o atajo de tipo (por ejemplo, 'L'). Para compatibilidad con versiones anteriores, las opciones -c y --id tienen el mismo significado que esta.

--part-uuid dispositivo número-de-partición [uuid]

Cambia el UUID de la partición GPT. Si no se especifica uuid, entonces imprime el UUID actual de la partición.

--disk-id dispositivo [id]

Cambia el identificador del disco. Si no se especifica id
Especificado, luego imprime el identificador actual. El identificador es UUID para GPT o entero sin signo para MBR.

--discard-free dispositivo

Descarta cualquier sector no utilizado (no particionado) en el dispositivo. Utilice la opción --list-free para obtener una lista de las regiones libres. Consulte también blkdiscard(8).

Advertencia

¡Todos los datos en las regiones descartadas del dispositivo se perderán! Do no utilice esta opción si no está seguro.

Tenga en cuenta que el comando 'T' en fdisk proporciona un diálogo para especificar qué área no utilizada debe descartarse. Sin embargo, sfdisk siempre descarta todas las regiones no particionadas (excepto las áreas donde no es posible crear particiones, como el principio del dispositivo).

-r, --reorder dispositivo

Renumerar las particiones, ordenándolas por su desplazamiento de inicio.

-s, --show-size [dispositivo...]

Liste los tamaños de todos los dispositivos o de los especificados en unidades de 1024 bytes. Este comando está OBSOLETO en favor de blockdev(8).

-T, --list-types

Imprime todos los tipos compatibles para la etiqueta de disco actual o la etiqueta especificada por --label.

-V, --verify [dispositivo...]

Prueba si la tabla de particiones y las particiones parecen correctas.

--relocate oper dispositivo

Reubicar la cabecera de la tabla de particiones. Este comando es actualmente compatible solo con la cabecera GPT. El argumento oper puede ser:

gpt-bak-std

Mueve la cabecera de respaldo GPT a la ubicación estándar al final del dispositivo.

gpt-bak-mini

Mueve la cabecera de respaldo GPT detrás de la última partición. Tenga en cuenta que el estándar UEFI requiere la cabecera de respaldo al final del dispositivo y las herramientas de particionamiento pueden reubicar automáticamente la cabecera para seguir el estándar.

OPCIONES

-a, --append

No cree una nueva tabla de particiones, sino que solo agregue las particiones especificadas.

Tenga en cuenta que las particiones no utilizadas pueden ser reutilizadas en este caso, aunque no sea la última partición en la tabla de particiones. Consulte también -N para especificar una entrada en la tabla de particiones.

-b, --backup

Realiza una copia de seguridad de los sectores actuales de la tabla de particiones antes de iniciar el particionamiento. El nombre de archivo de copia de seguridad predeterminado es ~/sfdisk-<dispositivo>-<desplazamiento>.bak; para usar otro nombre consulte la opción -O, --backup-file. Consulte la sección RESPALDO DE LA TABLA DE PARTICIONES para más detalles.

--color[=cuándo]

Colorea la salida. El argumento opcional cuándo puede ser auto, nunca o siempre. Si se omite el argumento cuándo, se predetermina a auto. Los colores se pueden deshabilitar; para la configuración predeterminada integrada actual consulte la salida de --help. Consulte también la sección COLORES.

-f, --force

Deshabilita todas las comprobaciones de coherencia.

--Linux

Opción obsoleta e ignorada. El particionamiento compatible con Linux (y otros sistemas operativos modernos) es el predeterminado.

--lock[=modo]

Utiliza un bloqueo BSD exclusivo para el dispositivo o archivo en el que opera. El argumento opcional modo puede ser yes, no (o 1 y 0) o nonblock. Si se omite el argumento modo, se predetermina a yes. Esta opción sobrescribe la variable de entorno $LOCK_BLOCK_DEVICE. El valor predeterminado es no usar ningún bloqueo, pero se recomienda evitar colisiones con systemd-udevd(8) u otras herramientas.

-n, --no-act

Hace todo excepto escribir en el dispositivo.

--no-reread

No comprueba mediante la llamada ioctl re-read-partition-table si el dispositivo está en uso.

--no-tell-kernel

No informa al kernel sobre los cambios de partición. Esta opción se recomienda junto con --no-reread para modificar una partición en un disco en uso. La partición modificada no debe utilizarse (por ejemplo, montada).

-O, --backup-file ruta

Sobrescribe el nombre de archivo de copia de seguridad predeterminado. Tenga en cuenta que el nombre del dispositivo y el desplazamiento siempre se agregan al nombre del archivo.

--move-data[=ruta]

Mueve datos después de la reubicación de particiones, por ejemplo, al mover el principio de una partición a otro lugar en el disco. El tamaño de la partición debe permanecer igual, la nueva y la antigua ubicación pueden superponerse. Esta opción requiere la opción -N para ser procesada en una partición específica solamente.

El argumento opcional ruta especifica el nombre del archivo de registro. El archivo de registro contiene información sobre todas las operaciones de lectura/escritura en los datos de la partición. La palabra "default" como ruta obliga a sfdisk a usar ~/sfdisk-<nombre_disp>.move para el registro. El registro es opcional desde v2.35.

¡Tenga en cuenta que esta operación es arriesgada y no atómica. ¡No olvide hacer una copia de seguridad de sus datos!

Consulte también --move-use-fsync.

En el siguiente ejemplo, el primer comando crea un área libre de 100MiB antes de la primera partición y mueve los datos que contiene (por ejemplo, un sistema de archivos), el siguiente comando crea una nueva partición a partir del espacio libre (en el desplazamiento 2048) y el último comando reordena las particiones para que coincidan con el orden del disco (la sdc1 original se convertirá en sdc2).

echo '+100M,' | sfdisk --move-data /dev/sdc -N 1

echo '2048,' | sfdisk /dev/sdc --append

sfdisk /dev/sdc --reorder

--move-use-fsync

Utiliza la llamada al sistema fsync(2) después de cada escritura al mover datos a una nueva ubicación con --move-data.

-o, --output lista

Especifica qué columnas de salida imprimir. Utilice --help para obtener una lista de todas las columnas compatibles.

La lista predeterminada de columnas puede extenderse si lista se especifica en el formato +lista (por ejemplo, -o +UUID).

-q, --quiet

Suprime los mensajes informativos adicionales.

--sector-size tamaño_sector

Especifica el tamaño del sector del disco. Los valores válidos son 512, 1024, 2048 y 4096. El kernel es consciente del tamaño del sector para los dispositivos de bloque regulares. Utilice esta opción solo en kernels muy antiguos, al trabajar con imágenes de disco o para anular el tamaño de sector predeterminado del kernel. Desde util-linux-2.17, fdisk distingue entre el tamaño de sector lógico y físico. Esta opción cambia ambos tamaños de sector al tamaño_sector especificado.

-u, --unit S

Opción obsoleta. Solo se admite la unidad de sector. Esta opción no se admite al utilizar el comando --show-size.

-X, --label tipo

Especifica el tipo de etiqueta del disco (por ejemplo, dos, gpt, ...). Si no se proporciona esta opción, sfdisk utiliza por defecto la etiqueta existente, pero si aún no hay ninguna etiqueta en el dispositivo, el tipo se establece por defecto en dos. La etiqueta predeterminada o actual puede ser sobrescrita por la línea de encabezado del script "label: <nombre>". La opción --label no obliga a sfdisk a crear una etiqueta de disco vacía (consulte la sección ETIQUETA DE DISCO VACÍA a continuación).

-Y, --label-nested tipo

Fuerza la edición de una etiqueta de disco anidada. La etiqueta de disco principal debe existir previamente. Esta opción permite editar, por ejemplo, un MBR híbrido/protector en dispositivos con GPT.

-w, --wipe cuándo

Borra firmas de sistemas de archivos, RAID y tablas de particiones del dispositivo, para evitar posibles colisiones. El argumento cuándo puede ser auto, nunca o siempre. Cuando no se proporciona esta opción, el valor predeterminado es auto, en cuyo caso las firmas solo se borran cuando se está en modo interactivo; excepto las firmas de tablas de particiones antiguas que siempre se borran antes de crear una nueva tabla de particiones si el argumento cuándo no es nunca. El modo auto tampoco borra el primer sector (sector de arranque), es necesario usar el modo siempre para borrar esta área. En todos los casos, las firmas detectadas se informarán mediante mensajes de advertencia antes de crear una nueva tabla de particiones. Consulte también el comando wipefs(8).

-W, --wipe-partitions cuándo

Borra firmas de sistemas de archivos, RAID y tablas de particiones de una partición recién creada, para evitar posibles colisiones. El argumento cuándo puede ser auto, nunca o siempre. Cuando no se proporciona esta opción, el valor predeterminado es auto, en cuyo caso las firmas solo se borran cuando se está en modo interactivo y después de la confirmación del usuario. En todos los casos, las firmas detectadas se informarán mediante mensajes de advertencia después de crear una nueva partición. Consulte también wipefs(8).

-v, --version

Muestra la información de la versión y sale.

-h, --help

Muestra el texto de ayuda y sale.

FORMATOS DE ENTRADA

sfdisk admite dos formatos de entrada y líneas de encabezado genéricas.

Líneas de encabezado

Las líneas de encabezado opcionales especifican información genérica que se aplica a la tabla de particiones. El formato de la línea de encabezado es:

<nombre>: <valor>

Los encabezados actualmente reconocidos son:

unit

Especifica la unidad de particionamiento. La única unidad admitida es sectors.

label

Especifica el tipo de tabla de particiones. Por ejemplo dos o gpt.

label-id

Especifica el identificador de la tabla de particiones. Debe ser un número hexadecimal (con prefijo 0x) para MBR y un UUID para GPT.

first-lba

Especifica el primer sector utilizable para particiones GPT. Este encabezado se ignora si el tamaño de sector del script y del dispositivo difieren. En este caso sfdisk utiliza el valor predeterminado específico de la etiqueta.

last-lba

Especifica el último sector utilizable para particiones GPT. Este encabezado se ignora si el tamaño de sector del script y del dispositivo difieren. En este caso sfdisk utiliza el valor predeterminado específico de la etiqueta. El encabezado last-lba se ignora

OPTIONS

The sfdisk commands are all-or-nothing. Either it works for all specified partitions or it fails for the first incorrect partition. The entire partition table is rewritten at the end of the operation. The device is locked during the operation. The lock is released when the operation finishes or fails.

SCRIPT INPUT FORMAT

The input format for sfdisk scripts is very flexible. It supports two main formats: unnamed fields and named fields.

Header line

A script may start with an optional header line. The header line must be the first line in the script. The header line specifies the type of partition table to create. The supported header lines are:

label: gpt

Create a GPT partition table.

label: dos

Create an MBR (DOS) partition table.

label: loop

Create a loop device partition table.

label: bsd

Create a BSD partition table.

label: sun

Create a Sun partition table.

label: mac

Create a Mac partition table.

label: pc98

Create a PC98 partition table.

label: amiga

Create an Amiga partition table.

label: advancedec

Create an Advanced/286 Advanced partition table.

label: compat

Create a compatibility partition table.

If no header line is specified, sfdisk will try to guess the partition table type from the existing partition table on the device. If the device does not have a partition table, sfdisk will default to GPT.

It is also possible to specify the following header lines:

device: /dev/sdx

Specifies the device name. This is mainly used for documentation and may be ignored by sfdisk.

unit: unit

Specifies the unit used for partition sizes. The unit can be sectors, KiB, MiB, GiB, TiB, PiB, EiB, ZiB or YiB. The default is sectors.

sector-size: number

Specifies the sector size used in the input. sfdisk always internally uses the device sector size provided by the kernel for the block device, or as specified by the user on the command line (see --sector-size). Starting with version 2.39, sfdisk recalculates sizes from the input if the sector-size header and device sector size are different.

table-size: number

Specify the maximal number of GPT partitions.

grain: number

Specify minimal size in bytes used to calculate partitions alignment. The default is 1MiB and it’s strongly recommended to use the default. Do not modify this variable if you’re not sure.

--force

If --force is specified, making the script usable on disks with different sizes.

table-length

Specify the maximal number of GPT partitions.

grain

Specify minimal size in bytes used to calculate partitions alignment. The default is 1MiB and it’s strongly recommended to use the default. Do not modify this variable if you’re not sure.

sector-size

Specifies the sector size used in the input. sfdisk always internally uses the device sector size provided by the kernel for the block device, or as specified by the user on the command line (see --sector-size). Starting with version 2.39, sfdisk recalculates sizes from the input if the sector-size header and device sector size are different.

Note that it is only possible to use header lines before the first partition is specified in the input.

Unnamed-fields format

start size type bootable

where each line fills one partition descriptor.

Fields are separated by whitespace, comma (recommended) or semicolon possibly followed by whitespace; initial and trailing whitespace is ignored. Numbers can be octal, decimal or hexadecimal; decimal is the default. When a field is absent, empty or specified as '-' a default value is used. But when the -N option (change a single partition) is given, the default for each field is its previous value.

The default value of start is the first non-assigned sector aligned according to device I/O limits. The default start offset for the first partition is 1 MiB. If the offset is followed by the multiplicative suffixes (KiB, MiB, GiB, TiB, PiB, EiB, ZiB and YiB), then the number is interpreted as offset in bytes. Since v2.38 when the -N option (change a single partition) is given, a '+' can be used to enlarge partition by move start of the partition if there is a free space before the partition.

The default value of size indicates "as much as possible"; i.e., until the next partition or end-of-device. A numerical argument is by default interpreted as a number of sectors, however if the size is followed by one of the multiplicative suffixes (KiB, MiB, GiB, TiB, PiB, EiB, ZiB and YiB) then the number is interpreted as the size of the partition in bytes and it is then aligned according to the device I/O limits. A '+' can be used instead of a number to enlarge the partition as much as possible. Note '+' is equivalent to the default behaviour for a new partition; existing partitions will be resized as required.

The partition type is given in hex for MBR (DOS) where 0x prefix is optional; a GUID string for GPT; a shortcut or an alias. It’s recommended to use two letters for MBR hex codes to avoid collision between deprecated shortcut 'E' and '0E' MBR hex code. For backward compatibility sfdisk tries to interpret type as a shortcut as a first possibility in partitioning scripts although on other places (e.g. --part-type command) it tries shortcuts as the last possibility.

Since v2.36 libfdisk supports partition type aliases as extension to shortcuts. The alias is a simple human readable word (e.g. "linux").

Since v2.37 libfdisk supports partition type names on input, ignoring the case of the characters and all non-alphanumeric and non-digit characters in the name (e.g. "Linux /usr x86" is the same as "linux usr-x86").

Supported shortcuts and aliases:

L - alias 'linux'

Linux; means 83 for MBR and 0FC63DAF-8483-4772-8E79-3D69D8477DE4 for GPT.

S - alias 'swap'

swap area; means 82 for MBR and 0657FD6D-A4AB-43C4-84E5-0933C84B4F4F for GPT

Ex - alias 'extended'

MBR extended partition; means 05 for MBR. The original shortcut 'E' is deprecated due to collision with 0x0E MBR partition type.

H - alias 'home'

home partition; means 933AC7E1-2EB4-4F13-B844-0E14E2AEF915 for GPT

U - alias 'uefi'

EFI System partition, means EF for MBR and C12A7328-F81F-11D2-BA4B-00A0C93EC93B for GPT

R - alias 'raid'

Linux RAID; means FD for MBR and A19D880F-05FC-4D3B-A006-743F0F84911E for GPT

V - alias 'lvm'

LVM; means 8E for MBR and E6D6D379-F507-44C2-A23C-238F2A3DF928 for GPT

The default type value is linux.

The shortcut 'X' for Linux extended partition (85) is deprecated in favour of 'Ex'.

bootable is specified as [*|-], with as default not-bootable. The value of this field is irrelevant for Linux - when Linux runs it has been booted already - but it might play a role for certain boot loaders and for other operating systems.

Named-fields format

This format is more readable, robust, extensible and allows specifying additional information (e.g., a UUID). It is recommended to use this format to keep your scripts more readable.

[device :] name[=value], ...

The device field is optional. sfdisk extracts the partition number from the device name. It allows specifying the partitions in random order. This functionality is mostly used by --dump. Don’t use it if you are not sure.

The value can be between quotation marks (e.g., name="This is partition name"). The fields start= and size= support '+' and '-' in the same way as Unnamed-fields format.

The currently supported fields are:

start=number

The first non-assigned sector aligned according to device I/O limits. The default start offset for the first partition is 1 MiB. If the offset is followed by the multiplicative suffixes (KiB, MiB, GiB, TiB, PiB, EiB, ZiB and YiB), then the number is interpreted as offset in bytes.

size=number

Specify the partition size in sectors. The number may be followed by the multiplicative suffixes (KiB, MiB, GiB, TiB, PiB, EiB, ZiB and YiB), then it’s interpreted as size in bytes and the size is aligned according to device I/O limits.

bootable

Mark the partition as bootable.

attrs=string

Partition attributes, usually GPT partition attribute bits. See --part-attrs for more details about the GPT-bits string format.

uuid=string

GPT partition UUID.

name=string

GPT partition name.

type=code

A hexadecimal number (without 0x) for an MBR partition, a GUID for a GPT partition, a shortcut as for unnamed-fields format or a type name (e.g. type="Linux /usr (x86)"). See above the section about the unnamed-fields format for more details. For backward compatibility the Id= field has the same meaning.

EMPTY DISK LABEL

sfdisk does not create partition table without partitions by default. The lines with partitions are expected in the script by default. The empty partition table has to be explicitly requested by "label: <name>" script header line without any partitions lines. For example:

echo 'label: gpt' | sfdisk /dev/sdb

creates empty GPT partition table. Note that the --append disables this feature.

BACKING UP THE PARTITION TABLE

It is recommended to save the layout of your devices. sfdisk supports two ways.

Dump in sfdisk compatible format

Use the --dump command to save a description of the device layout to a text file. The dump format is suitable for later sfdisk input. For example:

sfdisk --dump /dev/sda > sda.dump

This can later be restored by:

sfdisk /dev/sda < sda.dump

Note that sfdisk completely restores partition types and partition UUIDs. This could potentially become problematic if you duplicate the same layout to different disks, as it may result in duplicate UUIDs within your system.

Full binary backup

If you want to do a full binary backup of all sectors where the partition table is stored, then use the --backup-pt-sectors command. It writes the sectors to ~/sfdisk-<device>-<offset>.bak files. The default name of the backup file can be changed with the --backup-file option. The backup files contain only raw data from the device. For example:

sfdisk --backup-pt-sectors /dev/sda

The GPT header can later be restored by:

dd if=~/sfdisk-sda-0x00000200.bak of=/dev/sda seek=$((0x00000200)) bs=1 conv=notrunc

It’s also possible to use the --backup option to create the same backup immediately after startup for other sfdisk commands. For example, backup partition table before deleting all partitions from partition table:

sfdisk --backup --delete /dev/sda

The same concept of backup files is used by wipefs(8).

Note that sfdisk since version 2.26 no longer provides the -I option to restore sectors. dd(1) provides all necessary functionality.

COLORS

The output colorization is implemented by terminal-colors.d(5) functionality. Implicit coloring can be disabled by an empty file

/etc/terminal-colors.d/zz-sfdisk.disable

Explicit coloring is enabled by a file

/etc/terminal-colors.d/sfdisk.colors

See terminal-colors.d(5) for more details.

COLORS

By default, colors are enabled for all output. Use the --color option (see sfdisk(8)) to override the default setting. The color scheme is defined by the configuration files in the terminal-colors.d directory. The configuration files are sorted lexicographically. For a given color name, the first configuration file which defines this color is used.

The configuration file is a simple file where lines define the color and potentially the text attributes. The format of a line is:

[color][:attribute...]

Only one color is supported, and the supported attributes are bold, dim, ul (underline), blink, reverse, and hidden.

The supported colors are black, red, green, yellow, blue, magenta, cyan, white, and default.

An empty line or a line starting with the '#' character is ignored.

The global configuration files are in the /etc/terminal-colors.d directory. The user-specific configuration files are in the $XDG_CONFIG_HOME/terminal-colors.d or $HOME/.config/terminal-colors.d directory.

The colorization can be disabled for a specific command by creating an empty file with the command name and the .disable suffix in one of the configuration directories. For example, to disable colorization

/etc/terminal-colors.d/sfdisk.disable

for the sfdisk command or for all tools by

/etc/terminal-colors.d/disable

Since version 2.41, the $NO_COLOR environment variable is also supported to disable output colorization unless explicitly enabled by a command-line option.

The user-specific $XDG_CONFIG_HOME/terminal-colors.d or $HOME/.config/terminal-colors.d overrides the global setting.

Note that the output colorization may be enabled by default, and in this case terminal-colors.d directories do not have to exist yet.

The logical color names supported by sfdisk are:

header

The header of the output tables.

warn

The warning messages.

welcome

The welcome message.

Since version 2.26 sfdisk no longer provides the -R or --re-read option to force the kernel to reread the partition table. Use blockdev --rereadpt instead.

EXAMPLES

sfdisk --list --label-nested=mbr /dev/sda

Print protective MBR on device with GPT disk label.

echo -e ',10M,L\n,10M,L\n,+,\n' | sfdisk /dev/sdc

Create three Linux partitions, with the default start, the size of the first two partitions is 10MiB, and the last partition fills all available space on the device.

echo -e 'size=10M, type=L\n size=10M, type=L\n size=+\n' | sfdisk /dev/sdc

The same as the previous example, but in named-fields format.

echo -e 'type=swap' | sfdisk -N 3 /dev/sdc

Set type of the 3rd partition to 'swap'.

sfdisk --part-type /dev/sdc 3 swap

The same as the previous example, but without script use.

sfdisk --delete /dev/sdc 2

Delete 2nd partition.

echo "+,+" | sfdisk -N 3 --move-data /dev/sdc

Enlarge 3rd partition in both directions, move start to use free space before the partition and enlarge the size to use all free space after to the partition, and move partition data too.
