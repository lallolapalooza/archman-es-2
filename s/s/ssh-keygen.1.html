DESCRIPCIÓN

ssh-keygen es una herramienta de OpenSSH que genera, convierte, gestiona y firma claves de autenticación SSH. Se puede usar para crear un par de claves (una privada y una pública) para la autenticación sin contraseña. También se puede usar para gestionar claves de host, claves de certificados y revocación de claves.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

id='DESCRIPTION'>DESCRIPCIÓN

ssh-keygen genera, administra y convierte claves de autenticación para ssh(1). ssh-keygen puede crear claves para ser utilizadas por SSH versión 2 del protocolo.

El tipo de clave a generar se especifica con la opción -t. Si se invoca sin argumentos, ssh-keygen generará una clave Ed25519.

ssh-keygen también se utiliza para generar grupos para su uso en el intercambio de grupos Diffie-Hellman (DH-GEX). Consulte la sección GENERACIÓN DE MÓDULOS para obtener detalles.

Finalmente, ssh-keygen se puede usar para generar y actualizar Listas de Revocación de Claves, y para probar si claves dadas han sido revocadas por alguna. Consulte la sección LISTAS DE REVOCACIÓN DE CLAVES para obtener detalles.

Normalmente, cada usuario que desee usar SSH con autenticación de clave pública ejecuta esto una vez para crear la clave de autenticación en ~/.ssh/id_ecdsa, ~/.ssh/id_ecdsa_sk, ~/.ssh/id_ed25519, ~/.ssh/id_ed25519_sk o ~/.ssh/id_rsa. Adicionalmente, el administrador del sistema puede usar esto para generar claves de host, como se ve en /etc/rc.

Normalmente este programa genera la clave y pregunta por un archivo en el que almacenar la clave privada. La clave pública se almacena en un archivo con el mismo nombre pero con ".pub" añadido. El programa también solicita una frase de contraseña. La frase de contraseña puede estar vacía para indicar que no hay frase de contraseña (las claves de host deben tener una frase de contraseña vacía), o puede ser una cadena de longitud arbitraria. Una frase de contraseña es similar a una contraseña, excepto que puede ser una frase con una serie de palabras, puntuación, números, espacios en blanco o cualquier cadena de caracteres que desee. Las buenas frases de contraseña tienen entre 10 y 30 caracteres de longitud, no son frases sencillas o fácilmente adivinables (la prosa en inglés tiene solo 1-2 bits de entropía por carácter y proporciona frases de contraseña muy malas), y contienen una mezcla de mayúsculas y minúsculas, números y caracteres no alfanuméricos. La frase de contraseña se puede cambiar más tarde usando la opción -p.

No hay forma de recuperar una frase de contraseña perdida. Si la frase de contraseña se pierde u olvida, se debe generar una nueva clave y copiar la clave pública correspondiente a otras máquinas.

ssh-keygen escribirá por defecto las claves en un formato específico de OpenSSH. Este formato es preferible ya que ofrece una mejor protección para las claves en reposo, además de permitir el almacenamiento de comentarios de clave dentro del propio archivo de clave privada. El comentario de clave puede ser útil para ayudar a identificar la clave. El comentario se inicializa a "user@host" cuando se crea la clave, pero se puede cambiar usando la opción -c.

Todavía es posible que ssh-keygen escriba las claves privadas en formato PEM utilizadas anteriormente usando la bandera -m. Esto se puede usar al generar nuevas claves, y las claves existentes de formato nuevo pueden convertirse usando esta opción en conjunción con la bandera -p (cambiar frase de contraseña).

Después de generar una clave, ssh-keygen preguntará dónde se deben colocar las claves para ser activadas.

Las opciones son las siguientes:

-A
Genera claves de host de todos los tipos de clave predeterminados (rsa, ecdsa y ed25519) si no existen ya. Las claves de host se generan con la ruta predeterminada del archivo de clave, una frase de contraseña vacía, bits predeterminados para el tipo de clave y un comentario predeterminado. Si también se ha especificado -f, su argumento se utiliza como prefijo de la ruta predeterminada para los archivos de clave de host resultantes. Esto lo utiliza /etc/rc para generar nuevas claves de host.
-a rondas
Al guardar una clave privada, esta opción especifica el número de rondas KDF (función de derivación de clave, actualmente bcrypt_pbkdf(3)) utilizadas. Un mayor número de rondas resulta en una verificación de frase de contraseña más lenta y una mayor resistencia a los ataques de fuerza bruta (en caso de que las claves sean robadas). El valor predeterminado es 16 rondas.
-B
Muestra el resumen bubblebabble del archivo de clave privada o pública especificado.
-b bits
Especifica el número de bits en la clave a crear. Para claves RSA, el tamaño mínimo es 1024 bits y el predeterminado es 3072 bits. En general, 3072 bits se considera suficiente. Para claves ECDSA, la bandera -b determina la longitud de la clave seleccionando entre uno de tres tamaños de curva elíptica: 256, 384 o 521 bits. Intentar utilizar longitudes de bits distintas de estos tres valores para claves ECDSA fallará. Las claves ECDSA-SK, Ed25519 y Ed25519-SK tienen una longitud fija y la bandera -b será ignorada.
-C comentario
Proporciona un nuevo comentario.
-c
Solicita cambiar el comentario en los archivos de clave privada y pública. El programa solicitará el archivo que contiene las claves privadas, la frase de contraseña si la clave tiene una, y el nuevo comentario.
-D pkcs11
Descarga las claves públicas proporcionadas por la biblioteca compartida PKCS#11 pkcs11. Cuando se utiliza en combinación con -s, esta opción indica que una clave CA reside en un token PKCS#11 (consulte la sección CERTIFICADOS para obtener detalles).
-E hash_huella_digital
Especifica el algoritmo de hash utilizado al mostrar las huellas digitales de la clave. Las opciones válidas son: "md5" y "sha256". El valor predeterminado es "sha256".
-e
Esta opción leerá un archivo de clave OpenSSH privada (o pública) y mostrará en stdout una clave pública en uno de los formatos especificados por la opción -m. El formato de exportación predeterminado es "RFC4716". Esta opción permite exportar claves OpenSSH para su uso por otros programas, incluyendo varias implementaciones SSH comerciales.
-F nombre_host | [nombre_host]:puerto
Busca el nombre_host especificado (con número de puerto opcional) en un archivo known_hosts, listando cualquier ocurrencia encontrada. Esta opción es útil para encontrar nombres de host o direcciones hasheadas y también puede usarse en conjunción con la opción -H para mostrar las claves encontradas en formato hasheado.
-f nombre_archivo
Especifica el nombre del archivo de clave.
-g
Usa el formato DNS genérico al mostrar registros de recursos de huella digital usando el comando -r.
-H
Hashea un archivo known_hosts. Esto reemplaza todos los nombres de host y direcciones con representaciones hasheadas dentro del archivo especificado; el contenido original se mueve a un archivo con sufijo .old. Estos hashes pueden ser usados normalmente por ssh y sshd, pero no revelan información de identificación en caso de que el contenido del archivo sea divulgado. Esta opción no modificará nombres de host hasheados existentes y, por lo tanto, es seguro usarla en archivos que mezclan nombres hasheados y no hasheados.
-h
Al firmar una clave, crea un certificado de host en lugar de un certificado de usuario. Consulte la sección CERTIFICADOS para obtener detalles.
-I identidad_certificado
Especifica la identidad de la clave al firmar una clave pública. Consulte la sección CERTIFICADOS para obtener detalles.
-i
Esta opción leerá una clave privada (o pública) sin cifrar en el formato especificado por la opción -m y mostrará una clave privada (o pública) compatible con OpenSSH en stdout. Esta opción permite importar claves de otro software, incluyendo varias implementaciones SSH comerciales. El formato de importación predeterminado es "RFC4716".
-K
Descarga claves residentes de un autenticador FIDO. Los archivos de clave pública y privada se escribirán en el directorio actual para cada clave descargada. Si hay varios autenticadores FIDO conectados, las claves se descargarán del primer autenticador tocado. Consulte la sección AUTENTICADOR FIDO para más información.
-k
Genera un archivo KRL. En este modo, ssh-keygen generará un archivo KRL en la ubicación especificada a través de la bandera -f que revoca cada clave o certificado presentado en la línea de comandos. Las claves/certificados a revocar se pueden especificar por archivo de clave pública o utilizando el formato descrito en la sección LISTAS DE REVOCACIÓN DE CLAVES.
-L
Muestra el contenido de uno o más certificados.
-l
Muestra la huella digital del archivo de clave pública especificado. ssh-keygen intentará encontrar el archivo de clave pública correspondiente y mostrará su huella digital. Si se combina con -v, se proporciona una representación visual en arte ASCII de la clave con la huella digital.
-M generate
Genera parámetros candidatos de intercambio de grupo Diffie-Hellman (DH-GEX) para su uso eventual por los métodos de intercambio de claves 'diffie-hellman-group-exchange-*'. Los números generados por esta operación deben ser filtrados adicionalmente antes de su uso. Consulte la sección GENERACIÓN DE MÓDULOS para más información.

ssh-keygen genera, convierte y gestiona claves de autenticación de clave pública para ssh(1).

ssh-keygen puede ser utilizado para crear claves de tipo rsa, ecdsa y ed25519. También genera claves de autenticación FIDO con tipos ecdsa-sk y ed25519-sk. La clave pública puede ser proporcionada a otros usuarios para que puedan añadirla a su lista de AuthorizedKeys.

La clave privada se guarda en un archivo y la clave pública se guarda en un archivo con el mismo nombre, pero con .pub añadido. ssh-keygen puede ser utilizado para generar claves sin una frase secreta. Si se desea una frase secreta, el programa la solicitará interactivamente.

Se pueden especificar varias opciones para controlar el tipo de clave, la longitud de bits, la frase secreta y el nombre del archivo.

En el caso de las claves de autenticación FIDO, el usuario será guiado a través del proceso de registro del dispositivo con la ayuda de la biblioteca libfido2.

ref="#w">-w provider
Especifica una ruta a una biblioteca que se utilizará al crear claves alojadas en el autenticador FIDO, anulando el valor predeterminado de usar el soporte interno USB HID.
-Y find-principals
Encuentra los principales asociados con la clave pública de una firma, proporcionada utilizando la bandera -s en un archivo de firmantes autorizados proporcionado utilizando la bandera -f. El formato del archivo de firmantes permitidos se documenta en la sección FIRMANTES PERMITIDOS a continuación. Si se encuentran uno o más principales coincidentes, se devuelven en la salida estándar.
-Y match-principals
Encuentra principales que coincidan con el nombre de principal proporcionado utilizando la bandera -I en el archivo de firmantes autorizados especificado usando la bandera -f. Si se encuentran uno o más principales coincidentes, se devuelven en la salida estándar.
-Y check-novalidate
Comprueba que una firma generada utilizando ssh-keygen -Y sign tenga una estructura válida. Esto no valida si una firma proviene de un firmante autorizado. Al probar una firma, ssh-keygen acepta un mensaje en la entrada estándar y un espacio de nombres de firma usando -n. También se debe proporcionar un archivo que contenga la firma correspondiente usando la bandera -s. La prueba exitosa de la firma se indica mediante el retorno de ssh-keygen con un estado de salida cero.
-Y sign
Firma criptográficamente un archivo o algunos datos utilizando una clave SSH. Al firmar, ssh-keygen acepta cero o más archivos para firmar en la línea de comandos; si no se especifican archivos, ssh-keygen firmará los datos presentados en la entrada estándar. Las firmas se escriben en la ruta del archivo de entrada con ".sig" añadido, o en la salida estándar si el mensaje a firmar se leyó de la entrada estándar.

La clave utilizada para firmar se especifica usando la opción -f y puede referirse a una clave privada, o a una clave pública con la parte privada disponible a través de ssh-agent(1). Un espacio de nombres de firma adicional, utilizado para prevenir confusiones de firma entre diferentes dominios de uso (por ejemplo, firma de archivos vs. firma de correo electrónico), debe proporcionarse a través de la bandera -n. Los espacios de nombres son cadenas arbitrarias y pueden incluir: "file" para firma de archivos, "email" para firma de correo electrónico. Para usos personalizados, se recomienda utilizar nombres que sigan el patrón NAMESPACE@YOUR.DOMAIN para generar espacios de nombres inequívocos.

-Y verify
Solicita la verificación de una firma generada utilizando ssh-keygen -Y sign como se describió anteriormente. Al verificar una firma, ssh-keygen acepta un mensaje en la entrada estándar y un espacio de nombres de firma usando -n. También se debe proporcionar un archivo que contenga la firma correspondiente usando la bandera -s, junto con la identidad del firmante usando -I y una lista de firmantes permitidos a través de la bandera -f. El formato del archivo de firmantes permitidos se documenta en la sección FIRMANTES PERMITIDOS a continuación. Se puede proporcionar un archivo que contenga claves revocadas usando la bandera -r. El archivo de revocación puede ser un KRL o una lista de claves públicas de una por línea. La verificación exitosa por un firmante autorizado se indica mediante el retorno de ssh-keygen con un estado de salida cero.
-y
Esta opción leerá un archivo privado en formato OpenSSH e imprimirá una clave pública OpenSSH en stdout.
-Z cifrado
Especifica el cifrado a utilizar para el cifrado al escribir un archivo de clave privada en formato OpenSSH. La lista de cifrados disponibles se puede obtener usando "ssh -Q cipher". El valor predeterminado es "aes256-ctr".
-z número_de_serie
Especifica un número de serie que se incrustará en el certificado para distinguir este certificado de otros de la misma CA. Si el número_de_serie está precedido por un carácter '+', el número de serie se incrementará para cada certificado firmado en una sola línea de comando. El número de serie predeterminado es cero.

Al generar un KRL, la bandera -z se utiliza para especificar un número de versión del KRL.

GENERACIÓN DE MÓDULOS

ssh-keygen puede usarse para generar grupos para el protocolo Diffie-Hellman Group Exchange (DH-GEX). La generación de estos grupos es un proceso de dos pasos: primero, se generan números primos candidatos utilizando un proceso rápido pero intensivo en memoria. Estos números primos candidatos luego se prueban para determinar su idoneidad (un proceso intensivo en CPU).

La generación de números primos se realiza utilizando la opción -M generate. La longitud deseada de los números primos se puede especificar mediante la opción -O bits. Por ejemplo:

# ssh-keygen -M generate -O bits=2048 moduli-2048.candidates

Por defecto, la búsqueda de números primos comienza en un punto aleatorio en el rango de longitud deseado. Esto puede anularse utilizando la opción -O start, que especifica un punto de inicio diferente (en hexadecimal).

Una vez generados los candidatos, deben ser filtrados para determinar su idoneidad. Esto puede realizarse utilizando la opción -M screen. En este modo, ssh-keygen leerá los candidatos de la entrada estándar (o de un archivo especificado usando la opción -f). Por ejemplo:

# ssh-keygen -M screen -f moduli-2048.candidates moduli-2048

Por defecto, cada candidato se someterá a 100 pruebas de primalidad. Esto puede anularse utilizando la opción -O prime-tests. El valor del generador DH se elegirá automáticamente para el número primo en consideración. Si se desea un generador específico, se puede solicitar utilizando la opción -O generator. Los valores de generador válidos son 2, 3 y 5.

Los grupos DH filtrados pueden instalarse en /etc/ssh/moduli. Es importante que este archivo contenga módulos de una variedad de longitudes de bits.

Hay varias opciones disponibles para la generación y filtrado de módulos a través de la bandera -O:

lines=número
Salir después de filtrar el número especificado de líneas mientras se realiza el filtrado de candidatos DH.
start-line=número_de_línea
Comenzar a filtrar en el número de línea especificado mientras se realiza el filtrado de candidatos DH.
checkpoint=nombre_de_archivo
Escribir la última línea procesada en el archivo especificado mientras se realiza el filtrado de candidatos DH. Esto se utilizará para omitir líneas en el archivo de entrada que ya se han procesado si el trabajo se reinicia.
start=valor_hex
Especificar el punto de inicio (en hexadecimal) al generar módulos candidatos para DH-GEX.
generator=valor
Especificar el generador deseado (en decimal) al probar módulos candidatos para DH-GEX.

CERTIFICADOS

ssh-keygen soporta la firma de claves para producir certificados que pueden ser utilizados para autenticación de usuarios o hosts. Los certificados consisten en una clave pública, información de identidad, cero o más nombres de principales (usuario o host) y un conjunto de opciones que son firmadas por una clave de Autoridad de Certificación (CA). Los clientes o servidores pueden entonces confiar solo en la clave CA y verificar su firma en un certificado en lugar de confiar en muchas claves de usuario/host. Tenga en cuenta que los certificados OpenSSH son un formato diferente y mucho más simple que los certificados X.509 utilizados en ssl(8).

ssh-keygen soporta dos tipos de certificados: de usuario y de host. Los certificados de usuario autentican a los usuarios ante los servidores, mientras que los certificados de host autentican los hosts del servidor ante los usuarios. Para generar un certificado de usuario:

$ ssh-keygen -s /ruta/a/ca_key -I id_clave /ruta/a/user_key.pub

El certificado resultante se colocará en /ruta/a/user_key-cert.pub. Un certificado de host requiere la opción -h:

$ ssh-keygen -s /ruta/a/ca_key -I id_clave -h /ruta/a/host_key.pub

El certificado de host se emitirá en /ruta/a/host_key-cert.pub.

Es posible firmar utilizando una clave CA almacenada en un token PKCS#11 proporcionando la biblioteca del token usando -D e identificando la clave CA proporcionando su mitad pública como argumento a -s:

$ ssh-keygen -s ca_key.pub -D libpkcs11.so -I id_clave user_key.pub

De manera similar, es posible que la clave CA esté alojada en un ssh-agent(1). Esto se indica con la bandera -U y, de nuevo, la clave CA debe identificarse por su mitad pública.

$ ssh-keygen -Us ca_key.pub -I id_clave user_key.pub

En todos los casos, id_clave es un "identificador de clave" que registra el servidor

CERTIFICATE OPTIONS

When the certificate is used for authentication.

Certificates may be limited to be valid for a set of principal (user/host) names. By default, generated certificates are valid for all users or hosts. To generate a certificate for a specified set of principals:

$ ssh-keygen -s ca_key -I key_id -n user1,user2 user_key.pub
$ ssh-keygen -s ca_key -I key_id -h -n host.domain host_key.pub

Additional limitations on the validity and use of user certificates may be specified through certificate options. A certificate option may disable features of the SSH session, may be valid only when presented from particular source addresses or may force the use of a specific command.

The options that are valid for user certificates are:

clear
Limpiar todos los permisos habilitados. Esto es útil para limpiar el conjunto predeterminado de permisos para que los permisos puedan agregarse individualmente.
critical:name[=contents]
 
extension:name[=contents]
Incluye una opción crítica o extensión de certificado arbitraria. El name especificado debe incluir un sufijo de dominio, p. ej. “name@example.com”. Si se especifica contents, entonces se incluye como el contenido de la extensión/opción codificada como cadena, de lo contrario, la extensión/opción se crea sin contenido (generalmente indicando una bandera). Las extensiones pueden ser ignoradas por un cliente o servidor que no las reconozca, mientras que las opciones críticas desconocidas provocarán que el certificado sea rechazado.
force-command=command
Fuerza la ejecución de command en lugar de cualquier shell o comando especificado por el usuario cuando el certificado se utiliza para autenticación.
no-agent-forwarding
Deshabilita el reenvío de ssh-agent(1) (permitido por defecto).
no-port-forwarding
Deshabilita el reenvío de puertos (permitido por defecto).
no-pty
Deshabilita la asignación de PTY (permitido por defecto).
no-user-rc
Deshabilita la ejecución de ~/.ssh/rc por sshd(8) (permitido por defecto).
no-x11-forwarding
Deshabilita el reenvío de X11 (permitido por defecto).
permit-agent-forwarding
Permite el reenvío de ssh-agent(1).
permit-port-forwarding
Permite el reenvío de puertos.
permit-pty
Permite la asignación de PTY.
permit-user-rc
Permite la ejecución de ~/.ssh/rc por sshd(8).
permit-X11-forwarding
Permite el reenvío de X11.
no-touch-required
No requerir que las firmas realizadas con esta clave incluyan la demostración de presencia del usuario (p. ej., haciendo que el usuario toque el autenticador). Esta opción solo tiene sentido para los algoritmos de autenticador FIDO ecdsa-sk y ed25519-sk.
source-address=address_list
Restringe las direcciones de origen desde las cuales se considera válida la certificación. La address_list es una lista separada por comas de uno o más pares de dirección/máscara de red en formato CIDR.
verify-required
Requerir que las firmas realizadas con esta clave indiquen que el usuario fue verificado primero, p. ej., por PIN o biometría en el token. Esta opción solo tiene sentido para los algoritmos de autenticador FIDO ecdsa-sk y ed25519-sk.

En este momento, no hay opciones estándar válidas para claves de host.

Finalmente, las certificaciones pueden definirse con una vida útil de validez. La opción -V permite especificar los tiempos de inicio y fin de la certificación. Una certificación que se presenta fuera de este rango no se considerará válida. Por defecto, las certificaciones son válidas desde la Época UNIX hasta un futuro lejano.

Para que las certificaciones se utilicen para la autenticación de usuarios o hosts, la clave pública de la CA debe ser confiable para sshd(8) o ssh(1). Consulte esas páginas de manual para obtener más detalles.

AUTENTICADOR FIDO

ssh-keygen es capaz de generar claves respaldadas por autenticadores FIDO, después de lo cual pueden usarse de manera similar a cualquier otro tipo de clave compatible con OpenSSH, siempre que el autenticador de hardware esté conectado cuando se utilicen las claves. Los autenticadores FIDO generalmente requieren que el usuario autorice explícitamente las operaciones tocándolos o pulsándolos. Las claves FIDO constan de dos partes: una parte de identificador de clave almacenada en el archivo de clave privada en disco, y una clave privada por dispositivo que es única para cada autenticador FIDO y que no se puede exportar del hardware del autenticador. Estas se combinan mediante el hardware en el momento de la autenticación para derivar la clave real que se utiliza para firmar los desafíos de autenticación. Los tipos de clave compatibles son ecdsa-sk y ed25519-sk.

Las opciones válidas para claves FIDO son:

application
Anula la cadena de aplicación/origen FIDO predeterminada de “ssh:”. Esto puede ser útil al generar claves residentes específicas del host o del dominio. La cadena de aplicación especificada debe comenzar con “ssh:”.
challenge=path
Especifica una ruta a una cadena de desafío que se pasará al autenticador FIDO durante la generación de claves. La cadena de desafío puede usarse como parte de un protocolo fuera de banda para la inscripción de claves (se usa un desafío aleatorio por defecto).
device
Especifica explícitamente un dispositivo fido(4) a utilizar, en lugar de permitir que el middleware del autenticador seleccione uno.
no-touch-required
Indica que la clave privada generada no debe requerir eventos de toque (presencia del usuario) al realizar firmas. Tenga en cuenta que sshd(8) rechazará dichas firmas por defecto, a menos que se anule mediante una opción authorized_keys.
resident
Indica que el identificador de clave debe almacenarse en el propio autenticador FIDO. Esto facilita el uso del autenticador en múltiples computadoras. Las claves residentes pueden ser compatibles con los autenticadores FIDO2 y generalmente requieren que se establezca un PIN en el autenticador antes de la generación. Las claves residentes pueden cargarse desde el autenticador usando ssh-add(1). Almacenar ambas partes de una clave en un autenticador FIDO aumenta la probabilidad de que un atacante pueda usar un dispositivo autenticador robado.
user
Un nombre de usuario que se asociará con una clave residente, anulando el nombre de usuario predeterminado vacío. Especificar un nombre de usuario puede ser útil al generar múltiples claves residentes para el mismo nombre de aplicación.
verify-required
Indica que esta clave privada debe requerir verificación del usuario para cada firma. No todos los autenticadores FIDO admiten esta opción. Actualmente, la autenticación por PIN es el único método de verificación compatible, pero otros métodos pueden ser compatibles en el futuro.
write-attestation=path
Se puede usar en el momento de la generación de claves para registrar los datos de atestación devueltos por los autenticadores FIDO durante la generación de claves. Esta información es potencialmente sensible. Por defecto, esta información se descarta.

LISTAS DE REVOCACIÓN DE CLAVES

ssh-keygen es capaz de administrar Listas de Revocación de Claves (KRLs) en formato OpenSSH. Estos archivos binarios especifican claves o certificados a revocar utilizando un formato compacto, ocupando tan solo un bit por certificado si se revocan por número de serie.

Las KRLs pueden generarse usando la bandera -k. Esta opción lee uno o más archivos de la línea de comandos y genera una nueva KRL. Los archivos pueden contener una especificación de KRL (ver más abajo) o claves públicas, listadas una por línea. Las claves públicas simples se revocan listando su hash o contenido en la KRL, y los certificados se revocan por número de serie o ID de clave (si el número de serie es cero o no está disponible).

Revocar claves usando una especificación de KRL ofrece control explícito sobre los tipos de registro utilizados para revocar claves y puede utilizarse para revocar directamente certificados por número de serie o ID de clave sin tener a mano el certificado original completo. NOMBRE

ssh-keygen ‐ clave de autenticación SSH, genera, administra y convierte.

SINOPSIS

ssh-keygen [-b bits] [-C comment] [-E digest-algo] [-f file] [-I id] [-K keydir] [-N passphrase] [-p] [-q] [-t type] [-w provider] [-X extension] [-Y extension] [-Z namespace] [-argument ...]

ssh-keygen [-c] [-e] [-F name] [-f file] [-I id] [-l] [-p] [-q] [-S sign_hostkey] [-t cert_type] [-U] [-v] [-W principal] [-w provider] [-X extension] [-Y extension] [-Z namespace] [krl] [allowed_signers] [-argument ...]

ssh-keygen [-l] [-f pkcs11_provider] [-t type] [-v] [-F name] [-D file] [-i] [-P passphrase] [-q] [-R file] [-v] [-u] [-E digest-algo] [-w provider] [-Z namespace] [krl] [keyfile]

ssh-keygen [-Q] [-f krl] [-w provider] [key ...]

DESCRIPCIÓN

ssh-keygen es una utilidad de línea de comandos para administrar claves de autenticación para iniciar sesión en máquinas remotas utilizando el protocolo Secure Shell (SSH).

El programa puede ser utilizado para las siguientes tareas:

  • Generar un par de claves pública/privada (con las opciones -t y -f).
  • Convertir pares de claves pública/privada a diferentes formatos (con las opciones -p y -f).
  • Obtener el FINGERPRINT de un par de claves (con la opción -l).
  • Generar un archivo moduli para parámetros Diffie-Hellman (con la opción -M).
  • Crear y convertir certificados de clave pública (con las opciones -s, -I, -n, -O, -V, y -s).
  • Administrar listas de revocación de claves (KRL) (con la opción -k).
  • Verificar que una clave es firmada por un signatario permitido (con las opciones -Y y -Z).
  • Cargar claves desde y descargar claves a un token FIDO (con las opciones -w y -K).

Cuando se invoca sin argumentos, ssh-keygen genera un par de claves RSA de 2048 bits y las guarda en los archivos ~/.ssh/id_rsa y ~/.ssh/id_rsa.pub.

Las opciones -s y -K no pueden ser usadas juntas.

Si se especifica un archivo de clave privada en el disco, ssh-keygen mostrará la información pública de la clave y la huella digital de la clave.

Si se especifica un archivo de clave pública, ssh-keygen mostrará la huella digital de la clave.

Si se especifica una clave pública con la opción -y, entonces ssh-keygen leerá la clave privada especificada y mostrará la clave pública correspondiente.

Si se especifica una clave pública con la opción -p, entonces ssh-keygen leerá la clave privada especificada y le permitirá cambiar la frase de paso.

Si se especifica una clave pública con la opción -c, entonces ssh-keygen leerá la clave pública especificada y le permitirá cambiar el comentario.

Si se especifica una clave pública con la opción -l, entonces ssh-keygen leerá la clave pública especificada y mostrará la huella digital de la clave.

Si se especifica una clave pública con la opción -i, entonces ssh-keygen leerá la clave pública especificada y la convertirá al formato de OpenSSH.

Si se especifica una clave pública con la opción -F, entonces ssh-keygen leerá la clave pública especificada y la convertirá al formato de authorized_keys.

Si se especifica una clave pública con la opción -P, entonces ssh-keygen leerá la clave privada especificada y la cifrará con la frase de paso proporcionada.

Si se especifica una clave pública con la opción -R, entonces ssh-keygen leerá la clave privada especificada y la descifrará.

Si se especifica una clave pública con la opción -u, entonces ssh-keygen leerá la clave privada especificada y la convertirá al formato de PKCS#11.

Si se especifica un archivo KRL con la opción -k, entonces ssh-keygen creará o actualizará el KRL. Los argumentos adicionales especifican las claves a revocar o agregar al KRL.

Si se especifica un archivo KRL con la opción -Q, entonces ssh-keygen verificará si las claves dadas han sido revocadas por el KRL.

Si se especifica un archivo de signatarios permitidos con la opción -Y, entonces ssh-keygen verificará que la clave dada es firmada por uno de los signatarios permitidos.

Si se especifica un token FIDO con la opción -w, entonces ssh-keygen generará un par de claves en el token FIDO.

Si se especifica un archivo con la opción -K, entonces ssh-keygen leerá las claves del archivo y las almacenará en el token FIDO.

GENERACIÓN DE MODULI

El comando ssh-keygen puede generar un archivo moduli que contiene grupos Diffie-Hellman (DH) utilizados para el intercambio de claves DH-GEX. El tamaño del grupo DH se especifica en bits con la opción -b.

La opción -M especifica el número de grupos DH a generar. Por defecto, se generan 2048 grupos DH.

La opción -v muestra el progreso de la generación.

El archivo moduli resultante se almacena en /etc/ssh/moduli.

CERTIFICADOS

ssh-keygen puede generar y firmar certificados de clave pública. Un certificado vincula una clave pública a una identidad, como un nombre de usuario o un nombre de host. Los certificados se utilizan para autenticación sin contraseña y para autorizar el acceso a recursos restringidos.

La opción -s se utiliza para firmar un certificado. El argumento signing_key es la clave privada utilizada para firmar el certificado. El argumento certfile es el archivo que contiene el certificado a firmar.

La opción -I establece el identificador del certificado. El identificador se utiliza para verificar que el certificado es emitido por la autoridad correcta.

La opción -n establece los principales permitidos para el certificado. Los principales son nombres de usuario o nombres de host que se autentican con el certificado.

La opción -O establece opciones adicionales para el certificado. Las opciones admitidas incluyen force-command, source-address, y valid-principals.

La opción -V establece el período de validez del certificado. El período se especifica como una marca de tiempo o un intervalo de tiempo. Las marcas de tiempo pueden estar en los formatos YYYYMMDD[Z] o YYYYMMDDHHMM[SS][Z].

La opción -w se usa para especificar el proveedor FIDO para claves de autenticador FIDO.

La opción -Z se usa para especificar el espacio de nombres del certificado.

Cuando se firma un certificado, los principales especificados deben coincidir con los principales incrustados en el certificado.

AUTENTICADOR FIDO

ssh-keygen puede generar y utilizar claves almacenadas en autenticadores FIDO (como llaves de seguridad USB).

La opción -w genera un nuevo par de claves en el autenticador FIDO especificado por provider. Si no se especifica un proveedor, se utilizará el proveedor predeterminado (generalmente, el dispositivo USB HID.

La opción -K carga claves desde el autenticador FIDO especificado por keydir en un archivo de clave de OpenSSH.

La opción -Z especifica el espacio de nombres de la clave FIDO.

La opción SSH_SK_PROVIDER puede ser utilizada para especificar una ruta a una biblioteca que se utilizará al cargar claves alojadas en autenticadores FIDO, anulando el soporte integrado de USB HID.

LISTAS DE REVOCACIÓN DE CLAVES

Una lista de revocación de claves (KRL) es un archivo que contiene una lista de claves que han sido revocadas y ya no deben ser aceptadas para la autenticación. Las KRL son generadas y mantenidas por una autoridad de certificación (CA).

La opción -k se utiliza para generar o actualizar una KRL. El argumento krl es el archivo que contendrá la KRL. Los argumentos adicionales especifican las claves a revocar o agregar a la KRL. Los siguientes tipos de entradas son admitidos en la línea de comandos:

serial: número_serie[-número_serie]
Revoca un certificado con el número de serie especificado. Los números de serie son valores de 64 bits, sin incluir cero y pueden expresarse en decimal, hexadecimal u octal. Si se especifican dos números de serie separados por un guion, entonces se revoca el rango de números de serie incluidos entre cada uno.
id: id_clave
Revoca un certificado con la cadena de ID de clave especificada.
key: clave_publica
Revoca la clave especificada. Si se lista un certificado, entonces se revoca como una clave pública simple.
sha1: clave_publica
Revoca la clave especificada incluyendo su hash SHA1 en la KRL.
sha256: clave_publica
Revoca la clave especificada incluyendo su hash SHA256 en la KRL. Las KRL que revocan claves por hash SHA256 no son compatibles con las versiones de OpenSSH anteriores a la 7.9.
hash: huella_digital
Revoca una clave utilizando un hash de huella digital, tal como se obtiene de un mensaje de registro de autenticación de sshd(8) o del indicador -l de ssh-keygen. Solo se admiten huellas digitales SHA256 aquí y las KRL resultantes no son compatibles con las versiones de OpenSSH anteriores a la 7.9.

Las KRL pueden actualizarse utilizando la opción -u además de -k. Cuando se especifica esta opción, las claves listadas en la línea de comandos se fusionan en la KRL, añadiéndose a las que ya existen.

También es posible, dado un KRL, probar si revoca una clave particular (o claves). La opción -Q consultará un KRL existente, probando cada clave especificada en la línea de comandos. Si alguna clave listada en la línea de comandos ha sido revocada (o se ha encontrado un error), entonces ssh-keygen saldrá con un estado de salida distinto de cero. Solo se devolverá un estado de salida cero si no se revocó ninguna clave.

SIGNATARIOS PERMITIDOS

Al verificar firmas, ssh-keygen utiliza una lista simple de identidades y claves para determinar si una firma proviene de una fuente autorizada. Este archivo de "signatarios permitidos" utiliza un formato similar al FORMATO DE ARCHIVO AUTHORIZED_KEYS descrito en sshd(8). Cada línea del archivo contiene los siguientes campos separados por espacios: principales, opciones, tipo de clave, clave codificada en base64. Las líneas vacías y las líneas que comienzan con un ‘#’ se ignoran como comentarios.

El campo principales es una lista de patrones (ver PATRONES en ssh_config(5)) que consiste en uno o más patrones de identidad USER@DOMAIN separados por comas que se aceptan para firmar. Al verificar, la identidad presentada a través de la opción -I debe coincidir con un patrón de principales para que la clave correspondiente sea considerada aceptable para la verificación.

Las opciones (si están presentes) consisten en especificaciones de opciones separadas por comas. No se permiten espacios, excepto dentro de comillas dobles. Se admiten las siguientes especificaciones de opciones (tenga en cuenta que las palabras clave de las opciones no distinguen entre mayúsculas y minúsculas):

cert-authority
Indica que esta clave se acepta como autoridad de certificación (CA) y que los certificados firmados por esta CA pueden ser aceptados para verificación.
namespaces=lista_de_espacios_de_nombres
Especifica una lista de patrones de espacios de nombres que se aceptan para esta clave. Si esta opción está presente, el espacio de nombres de la firma incrustado en el objeto de firma y presentado en la línea de comandos de verificación debe coincidir con la lista especificada antes de que la clave sea considerada aceptable.
valid-after=marca_de_tiempo
Indica que la clave es válida para su uso en o después de la marca de tiempo especificada, que puede ser una fecha u hora en los formatos YYYYMMDD[Z] o YYYYMMDDHHMM[SS][Z]. Las fechas y horas se interpretarán en la zona horaria del sistema actual a menos que se sufijen con un carácter Z, lo que hace que se interpreten en la zona horaria UTC.
valid-before=marca_de_tiempo
Indica que la clave es válida para su uso en o antes de la marca de tiempo especificada.

Al verificar firmas realizadas por certificados, el nombre de principal esperado debe coincidir tanto con el patrón de principales en el archivo de signatarios permitidos como con los principales incrustados en el propio certificado.

Un ejemplo de archivo de signatarios permitidos:

# Se permiten comentarios al inicio de la línea
user1@example.com,user2@example.com ssh-rsa AAAAX1...
# Una autoridad de certificación, confiable para todos los principales de un dominio.
*@example.com cert-authority ssh-ed25519 AAAB4...
# Una clave que se acepta solo para firmar archivos.
user2@example.com namespaces="file" ssh-ed25519 AAA41...

    ssh-keygen(1)

    Manual del programador de Linux y utilidades del sistema

    SYNOPSIS

    ssh-keygen [-b bits] [-C comment] [-f output_keyfile] [-P passphrase] [-q] [-t type] [-N new_passphrase] [-y]

    DESCRIPTION

    ssh-keygen es una herramienta para generar, convertir y gestionar claves SSH.

    Los pares de claves consisten en una clave pública y una clave privada. Las claves públicas se pueden distribuir libremente, mientras que las claves privadas deben mantenerse en secreto.

    OPTIONS

    -b bits
    Especifica el número de bits en la clave. El valor predeterminado es 3072 para RSA, 521 para ECDSA y 4096 para Ed25519.
    -C comment
    Añade un comentario a la clave pública. Útil para identificar la clave.
    -f output_keyfile
    Especifica la ruta del archivo donde se guardará la clave. Por defecto, se guarda en ~/.ssh/id_rsa, ~/.ssh/id_ecdsa o ~/.ssh/id_ed25519.
    -P passphrase
    Proporciona la frase de contraseña para la clave privada. Si no se proporciona, se le pedirá al usuario.
    -q
    Silencioso. No muestra el progreso ni las preguntas.
    -t type
    Especifica el tipo de clave a crear. Los tipos soportados son rsa, dsa, ecdsa y ed25519.
    -N new_passphrase
    Proporciona la nueva frase de contraseña para la clave privada existente. Se utiliza para cambiar la frase de contraseña.
    -y
    Lee una clave privada del archivo especificado por -f y muestra su clave pública correspondiente en la salida estándar.

    ALLOWED SIGNERS

    Esta sección no está disponible en la documentación original.

    ENVIRONMENT

    SSH_AUTH_SOCK: Si está establecido, indica el nombre del socket para el agente SSH.

    FILES

    ~/.ssh/id_rsa, ~/.ssh/id_ecdsa, ~/.ssh/id_ed25519
    Archivos de claves privadas predeterminadas.
    ~/.ssh/id_rsa.pub, ~/.ssh/id_ecdsa.pub, ~/.ssh/id_ed25519.pub
    Archivos de claves públicas correspondientes.
    ~/.ssh/config
    Archivo de configuración del cliente SSH.
