NOMBRE

sss_cache - realiza la limpieza de caché

SINOPSIS

sss_cache [opciones]

DESCRIPCIÓN

sss_cache invalida registros en la caché de SSSD. Los registros invalidados se forzarán a recargarse desde el servidor tan pronto como el backend de SSSD relacionado esté en línea. Las opciones que invalidan un solo objeto solo aceptan un único argumento proporcionado.

OPCIONES

-E,--everything

Invalida todas las entradas de caché.

-u,--user login

Invalida un usuario específico.

-U,--users

Invalida todos los registros de usuario. Esta opción anula la invalidación de un usuario específico si también se estableció.

-g,--group grupo

Invalida un grupo específico.

-G,--groups

Invalida todos los registros de grupo. Esta opción anula la invalidación de un grupo específico si también se estableció.

-n,--netgroup netgroup

Invalida una netgroup específica.

-N,--netgroups

Invalida todos los registros de netgroup. Esta opción anula la invalidación de una netgroup específica si también se estableció.

-s,--service servicio

Invalida un servicio específico.

-S,--services

Invalida todos los registros de servicio. Esta opción anula la invalidación de un servicio específico si también se estableció.

-a,--autofs-map mapa autofs

Invalida mapas autofs específicos.

-A,--autofs-maps

Invalida todos los mapas autofs. Esta opción anula la invalidación de un mapa específico si también se estableció.

-h,--ssh-host nombre de host

Invalida las claves públicas SSH de un host específico.

-H,--ssh-hosts

Invalida las claves públicas SSH de todos los hosts. Esta opción anula la invalidación de las claves públicas SSH de un host específico si también se estableció.

-r,--sudo-rule regla

Invalida una regla sudo particular.

-R,--sudo-rules

Invalida todas las reglas sudo cacheadas. Esta opción anula la invalidación de una regla sudo específica si también se estableció.

-d,--domain dominio

Restringe el proceso de invalidación solo a un dominio particular.

-?,--help

Muestra el mensaje de ayuda y sale.

EFECTOS EN LA CACHÉ DE MEMORIA RÁPIDA

sss_cache también invalida la caché de memoria. Dado que la caché de memoria es un archivo que se mapea en la memoria de cada proceso que llamó a SSSD para resolver usuarios o grupos, el archivo no se puede truncar. Se establece una bandera especial en la cabecera del archivo para indicar que el contenido es inválido y luego el archivo es eliminado por el respondedor NSS de SSSD y se crea un nuevo archivo de caché. Cada vez que un proceso realiza una nueva consulta para un usuario o grupo, verá la bandera, cerrará el antiguo archivo de caché de memoria y mapeará el nuevo en su memoria. Cuando todos los procesos que habían abierto el antiguo archivo de caché de memoria lo hayan cerrado mientras consultaban un usuario o grupo, el kernel podrá liberar el espacio en disco ocupado y el antiguo archivo de caché de memoria se eliminará finalmente por completo.

Un caso especial son los procesos de larga ejecución que realizan consultas de usuarios o grupos solo al inicio, por ejemplo, para determinar el nombre del usuario con el que se está ejecutando el proceso. Para esas consultas, el archivo de caché de memoria se mapea en la memoria del proceso. Pero como no habrá más consultas, este proceso nunca detectará si el archivo de caché de memoria se ha invalidado y, por lo tanto, se mantendrá en memoria y ocupará espacio en disco hasta que el proceso se detenga. Como resultado, llamar a sss_cache podría aumentar el uso del disco porque los archivos antiguos de caché de memoria no se pueden eliminar del disco ya que todavía están mapeados por procesos de larga ejecución.

Una posible solución para procesos de larga ejecución que consultan usuarios y grupos solo al inicio o muy raramente es ejecutarlos con la variable de entorno SSS_NSS_USE_MEMCACHE establecida en "NO" para que no utilicen la caché de memoria en absoluto y no mapeen el archivo de caché de memoria en la memoria. En general, una mejor solución es ajustar los parámetros de tiempo de espera de la caché para que cumplan las expectativas locales y no sea necesario llamar a sss_cache.
