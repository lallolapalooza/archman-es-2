NOMBRE

sshguard-setup - configuración de SSHGuard en tu sistema

DESCRIPCIÓN

Para configurar SSHGuard, escribe sshguard.conf y configura el backend, si es necesario. Las opciones de configuración se documentan en el archivo de configuración de ejemplo. Un buen punto de partida es copiarlo y realizar los cambios necesarios:

1.
Establece BACKEND. Es posible que también necesites configurarlo para que funcione con SSHGuard (ver BACKENDS).
2.
Establece FILES, LOGREADER, o ambos. Alternativamente, pasa a sshguard una lista de archivos para monitorizar como argumentos posicionales en la línea de comandos.

Usa FILES para especificar una lista separada por espacios de archivos de registro para monitorizar. Usa LOGREADER para especificar un comando de shell para ejecutar para obtener los registros. Ambas configuraciones se ignoran si se proporcionan archivos en la línea de comandos.

Los comandos de ejemplo de LOGREADER para journalctl(1) y macOS 10.12+ están disponibles en la configuración de ejemplo.

OTROS LOGS

syslog-ng

Para syslog-ng 2.x, añade las siguientes líneas a syslog-ng.conf:

# pasa solo entradas con facilidades auth+authpriv de programas distintos a sshguard
filter sshlogs { facility(auth, authpriv) and not match("sshguard"); };
# pasa a este proceso con esta plantilla (evita prefijos &lt;ID&gt;)
destination sshguardproc {
program("/usr/local/sbin/sshguard"
template("$DATE $FULLHOST $MESSAGE\n"));
};
log { source(src); filter(sshlogs); destination(sshguardproc); };

Para syslog-ng 3.x, añade las siguientes líneas a syslog-ng.conf:

# habilita el modo 3.x
@version:3.0
# pasa solo entradas con facilidades auth+authpriv de programas distintos a sshguard
filter f_sshguard { facility(auth, authpriv) and not program("sshguard"); };
# pasa entradas construidas con este formato
destination sshguard {
program("/usr/sbin/sshguard"
template("$DATE $FULLHOST $MSGHDR$MESSAGE\n")
);
};
log { source(src); filter(f_sshguard); destination(sshguard); };

Después de reiniciar syslog-ng, SSHGuard debería iniciarse tan pronto como llegue una entrada de registro con la facilidad auth o authpriv. Si estás monitorizando servicios distintos a sshd, añade las facilidades de registro apropiadas a syslog-ng.conf.

metalog

Añade las siguientes líneas a metalog.conf:

Stuff to protect from brute force attacks :
    # for ssh
    facility = "*"
    program = "sshd"
    # other services ...
    # log to /var/log/sshguard directory
    logdir = "/var/log/sshguard"

Después de reiniciar metalog, las entradas de registro aparecerán en /var/log/sshguard. Usa el polling de logs para monitorizar el registro actual.

BACKENDS

SSHGuard puede bloquear atacantes utilizando uno de varios backends de firewall que se selecciona en tiempo de compilación.

ADVERTENCIA:

Lee la documentación de tu firewall. Asegúrate de entender completamente cada regla o comando en los ejemplos a continuación antes de usarlos. Es posible que necesiten ajustarse para adaptarse a tu configuración particular.

pf

SSHGuard añade atacantes a la tabla <sshguard>. Crea la tabla y bloquea atacantes añadiendo las siguientes líneas al final de pf.conf:

table <sshguard> persist
block in proto tcp from <sshguard>

Después de recargar la configuración de pf, puedes inspeccionar el contenido de la tabla usando:

# pfctl -t sshguard -T show

ipfw

SSHGuard crea y añade atacantes a la tabla 22. La tabla puede usarse para bloquear atacantes en tu conjunto de reglas. Por ejemplo:

# ipfw add 5000 reset ip from table\(22\) to me

Puedes inspeccionar el contenido de la tabla usando:

# ipfw table 22 list

firewalld

Los atacantes bloqueados se añaden a dos ipsets llamados sshguard4 y sshguard6. Las entradas en los ipsets están bloqueadas por defecto en la zona de firewall predeterminada. Se pueden configurar zonas de firewall adicionales usando:

# firewall-cmd --zone=nombre-zona --permanent \
    --add-rich-rule="rule source ipset=sshguard4 drop"
# firewall-cmd --zone=nombre-zona --permanent \
    --add-rich-rule="rule source ipset=sshguard6 drop"

Puedes inspeccionar las entradas en los dos ipsets usando:

# firewall-cmd --permanent --info-ipset=sshguard4
# firewall-cmd --permanent --info-ipset=sshguard6

ipset

Los atacantes bloqueados se añaden a dos ipsets llamados sshguard4 y sshguard6. Por defecto no se bloquea nada, pero pueden usarse como fuente para iptables y otras herramientas. Por ejemplo:

# iptables  -I INPUT -m set --match-set sshguard4 src -j DROP
# ip6tables -I INPUT -m set --match-set sshguard6 src -j DROP

netfilter/iptables

Crea una cadena para SSHGuard:

# iptables -N sshguard      # para IPv4
# ip6tables -N sshguard     # para IPv6

Actualiza la cadena INPUT para que también pase el tráfico a la cadena sshguard al final de su procesamiento. Especifica en --dport todos los puertos de los servicios que protege tu sshguard. Si quieres evitar que los atacantes realicen cualquier tráfico hacia el host, elimina la opción por completo:

# bloquea cualquier tráfico de abusadores
iptables -A INPUT -j sshguard
ip6tables -A INPUT -j sshguard

O:

# bloquea a los abusadores solo para servicios SSH, FTP, POP, IMAP (usa el módulo "multiport")
iptables -A INPUT -m multiport -p tcp --destination-ports 21,22,110,143 -j sshguard
ip6tables -A INPUT -m multiport -p tcp --destination-ports 21,22,110,143 -j sshguard

Verifica que NO tienes una regla de permitir por defecto que pase todo el tráfico SSH más arriba en la cadena. Verifica que NO tienes una regla de negar por defecto que bloquee todo el tráfico SSH en tu firewall. En cualquier caso, ya tienes la habilidad para ajustar tu configuración de firewall.

Aquí tienes un conjunto de reglas de ejemplo que tiene sentido:

iptables -N sshguard
# bloquea lo que SSHGuard considere malo...
iptables -A INPUT -j sshguard
# habilita ssh, dns, http, https
iptables -A INPUT -p tcp --dport 22 -j ACCEPT
iptables -A INPUT -p udp --dport 53 -j ACCEPT
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT
# y bloquea todo lo demás (denegación por defecto)
iptables -P INPUT DROP

Al reiniciar, la mayoría de los sistemas reinician la configuración del firewall por defecto. Para conservar tu configuración, normalmente usas las utilidades iptables-save e iptables-restore. Sin embargo, cada variante de Linux tiene su propia "forma correcta".

nftables

SSHGuard crea tablas con alta prioridad y añade atacantes a un conjunto automáticamente.

Puedes inspeccionar el contenido de los conjuntos usando:

# nft list set ip sshguard attackers
# nft list set ip6 sshguard attackers

Además, puedes mostrar las tablas de sshguard con:

# nft list table ip sshguard
# nft list table ip6 sshguard

SOLUCIÓN DE PROBLEMAS

Si SSHGuard no está bloqueando atacantes:

1.
Asegúrate de que el backend de firewall está activado y funciona correctamente.
2.
Asegúrate de que el backend está configurado para que SSHGuard lo use. Comprueba la configuración de tu backend.
3.
Si estás usando syslog-ng, asegúrate de que está configurado para reenviar los registros relevantes a SSHGuard. Revisa los registros de syslog-ng para ver si hay errores.
4.
Asegúrate de que los archivos de registro que SSHGuard está monitorizando contienen las entradas de fallo de inicio de sesión esperadas. Por ejemplo, para sshd, deberías ver líneas que indiquen intentos de inicio de sesión fallidos.
5.
Si usas log polling, asegúrate de que los archivos de registro se están actualizando. Si no, configura syslog-ng o similar para que los actualice.

SOLUCIÓN DE PROBLEMAS

¿Está SSHGuard configurado correctamente?

Compruebe que los ARCHIVOS (o LOGREADER) y el BACKEND correctos estén configurados en sshguard.conf.

¿Está SSHGuard ejecutándose?

SSHGuard inicia una canalización de procesos cooperativos. Puede verificar que SSHGuard se ha iniciado correctamente viendo su lista de procesos usando ps o top. Aquí se muestran los procesos asociados con una configuración de ejemplo:

/bin/sh /opt/sshguard/sbin/sshguard
tail -F -n 0 /tmp/log.txt
/opt/sshguard/libexec/sshg-parser
/opt/sshguard/libexec/sshg-blocker -a 30 -p 120 -s 1800 -N 128 -n 32
/bin/sh /usr/local/libexec/sshg-fw-null

En orden:

  • SSHGuard, instalado en /opt/sshguard, está siendo interpretado por /bin/sh.
  • SSHGuard inició tail -F -n 0, que está monitorizando /tmp/log.txt.
  • El analizador predeterminado sshg-parser se está ejecutando.
  • El bloqueador se está ejecutando con las opciones -a 30 -p 120 -s 1800 -N 128 -n 32.
  • El cortafuegos sshg-fw-null se está ejecutando. El backend nulo no bloquea realmente ningún ataque.

¿Reconoce SSHGuard los ataques?

SSHGuard reconoce los ataques analizando los mensajes de registro. El formato de los mensajes de registro puede cambiar ocasionalmente. Si está utilizando el analizador de ataques predeterminado y preinstalado, puede comprobar si SSHGuard reconoce sus ataques ejecutando:

$ cat /var/log/auth.log | %PREFIX%/libexec/sshg-parser -a

Los mensajes de registro que se reconocen como ataques van precedidos por un '*' al principio de cada línea. Si un mensaje de registro que debería ser reconocido como un ataque no lo es, considere informarlo.

EJEMPLOS

Ignorar los ARCHIVOS y monitorizar estos archivos en su lugar:

# sshguard /var/log/auth.log /var/log/maillog
