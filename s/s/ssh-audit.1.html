ssh-audit(1)

SSH-AUDIT(1) Manual de comandos generales SSH-AUDIT(1)

NOMBRE

ssh-audit - Auditor de configuración de servidores y clientes SSH

SINOPSIS

ssh-audit [opciones] <host_objetivo>

DESCRIPCIÓN

ssh-audit analiza la configuración de servidores y clientes SSH, luego advierte al usuario sobre primitivas criptográficas débiles, obsoletas y/o no probadas. Es muy útil para reforzar túneles SSH, que por defecto tienden a estar optimizados para compatibilidad, no para seguridad.

Consulte https://www.ssh-audit.com/ para guías oficiales de refuerzo para plataformas comunes.

OPCIONES

-h, --help

Imprime un resumen corto de las opciones.
-1, --ssh1

Solo realiza una auditoría usando la versión 1 del protocolo SSH.
-2, --ssh2

Solo realiza una auditoría usando la versión 2 del protocolo SSH.
-4, --ipv4

Prioriza el uso de IPv4.
-6, --ipv6

Prioriza el uso de IPv6.
-b, --batch

Habilita la salida que se puede procesar con grep.
-c, --client-audit

Inicia un servidor en el puerto 2222 para auditar la configuración del software cliente. Usa -p/--port=<puerto> para cambiar el puerto y -t/--timeout=<segundos> para cambiar el tiempo de espera de escucha.
--conn-rate-test=N[:max_rate]

Realiza una prueba de tasa de conexión (útil para recopilar métricas relacionadas con la susceptibilidad a la vulnerabilidad DHEat [CVE-2002-20001]). Una conexión exitosa se cuenta cuando el servidor devuelve un banner SSH válido. La prueba se realiza con N sockets concurrentes con una tasa máxima opcional de conexiones por segundo.
-d, --debug

Habilita la salida de depuración.
--dheat=N[:kex[:e_len]]

Ejecuta el ataque de Denegación de Servicio DHEat (CVE-2002-20001) contra el servidor objetivo (lo que consumirá todos los recursos de CPU disponibles). El número de sockets concurrentes, N, necesario para lograr este efecto dependerá en gran medida de los recursos de CPU disponibles en el objetivo, así como de la latencia entre las máquinas de origen y destino. El intercambio de claves se elige automáticamente según cuál cause el máximo efecto, a menos que se elija explícitamente en el segundo campo. Por último, una opción (experimental) permite especificar la longitud en bytes del valor 'e' falso enviado al servidor en el tercer campo. Normalmente, la longitud de 'e' es aproximadamente la longitud del módulo del intercambio Diffie-Hellman (por lo tanto, se envía un valor 'e' de 8192 bits / 1024 bytes en cada conexión al apuntar al algoritmo diffie-hellman-group18-sha512). En cambio, se observó que muchas implementaciones SSH aceptan valores pequeños, como 4 bytes; esto resulta en un ataque mucho más eficiente en red.
-g, --gex-test=<x[,y,...] | min1:pref1:max1[,min2:pref2:max2,...] | x-y[:step]>

Ejecuta una prueba de tamaño de módulo de intercambio de grupo Diffie-Hellman contra un servidor.

Diffie-Hellman requiere que el cliente y el servidor acuerden un valor generador y un valor módulo. En la implementación de "Intercambio de Grupo" de Diffie-Hellman, el cliente especifica el tamaño del módulo en bits proporcionando al servidor valores mínimo, preferido y máximo. El servidor luego encuentra un grupo que se ajuste mejor a la solicitud del cliente, devolviendo el generador y módulo correspondientes. Para una explicación completa de este proceso, consulte RFC 4419 y sus sucesores.

Esta prueba actúa como un cliente al proporcionar a un servidor SSH el tamaño de un módulo y luego obtener el tamaño del módulo devuelto por el servidor.

Se admiten tres tipos de sintaxis:


1. <x[,y,...]>


Una lista de tamaños de módulo separados por comas.
Se realiza una prueba contra cada valor de la lista, actuando como tamaño mínimo, preferido y máximo del módulo.


2. <min:pref:max[,min:pref:max,...]>


Un conjunto de tres valores separados por dos puntos que denotan el tamaño mínimo, preferido y máximo del módulo.
Se realiza una prueba contra cada conjunto.
Se pueden especificar varios conjuntos como una lista separada por comas.


3. <x-y[:step]>


Un rango de tamaños de módulo con un valor de paso opcional. El paso predeterminado es 1 si se omite.
Si el valor izquierdo es mayor que el valor derecho, la secuencia opera de derecha a izquierda.
Se realiza una prueba contra cada valor del rango, actuando como tamaño mínimo, preferido y máximo del módulo.

Se excluyen los duplicados del valor de retorno.

-j, --json

Salida de resultados en formato JSON. Especifique dos veces (-jj) para habilitar la impresión con sangría (útil para depurar).
-l, --level=<info|warn|fail>

Especifica el nivel de salida mínimo. El valor predeterminado es info.
-L, --list-policies

Lista todas las políticas oficiales integradas para sistemas comunes. Sus nombres completos se pueden pasar luego a -P/--policy. Añada -v a -L para ver los registros de cambios de políticas.
--lookup=<alg1,alg2,...>

Busca la información de seguridad de un algoritmo (o algoritmos) en la base de datos interna. No se conecta a un servidor.
-m, --manual

Imprime la página del manual (solo compilaciones de Docker, PyPI, Snap y Windows).
-M, --make-policy=<custom_policy.txt>

Crea una política basada en el servidor objetivo. Útil cuando otros servidores deberían compararse con la configuración personalizada del servidor objetivo (es decir, un entorno de clúster). Tenga en cuenta que la política resultante se puede editar manualmente.
-n, --no-colors

Deshabilita la salida en color. Se establece automáticamente cuando la variable de entorno NO_COLOR está configurada.
-p, --port=<puerto>

El puerto TCP al que conectarse al auditar un servidor, o el puerto a escuchar al auditar un cliente.
-P, --policy=<"nombre de política integrada" | ruta/a/custom_policy.txt>

Ejecuta una auditoría de política contra un objetivo utilizando la política especificada (consulte la sección AUDITORÍA DE POLÍTICAS para obtener una descripción detallada de este modo de operación). Combine con -c/--client-audit para auditar una configuración de cliente en lugar de un servidor. Use -L/--list-policies para listar todas las políticas oficiales integradas para sistemas comunes.
--skip-rate-test

Omite la prueba de tasa de conexión durante las auditorías estándar. Por defecto, se crean unas pocas docenas de conexiones TCP con el host objetivo para ver si se implementa la limitación de conexión (esto puede inferir de forma segura si el objetivo es vulnerable al ataque DHEat; consulte CVE-2002-20001).
-t, --timeout=<segundos>

El tiempo de espera, en segundos, para crear conexiones y leer datos del socket. El valor predeterminado es 5.
-T, --targets=<hosts.txt>

Un archivo que contiene una lista de hosts objetivo. Cada línea debe tener un host, en el formato HOST[:PUERTO]. Use -p/--port para establecer el puerto predeterminado para todos los hosts. Use --threads para controlar los escaneos concurrentes.
--threads=<threads>

El número de hilos a utilizar al escanear múltiples objetivos (con -T/--targets). El valor predeterminado es 32.
-v, --verbose

Habilita la salida detallada, mostrando cada uno de los detalles que se están evaluando.
-V, --version

Muestra la información de la versión y sale.

EJEMPLO

Auditar un servidor SSH en el host "example.com":

$ ssh-audit example.com

AUDITORÍA DE POLÍTICAS

El modo de auditoría de políticas es un modo de auditoría de servidor que se utiliza para determinar si un servidor SSH se adhiere a los requisitos de seguridad de una política determinada. Este modo se utiliza comúnmente para garantizar que un servidor SSH cumpla con una política de seguridad corporativa o de la industria.

Se puede usar una de las siguientes opciones para especificar una política:


1. Una política integrada (por ejemplo, "CIS-2.0" o "Mozilla-SSH-2.0").
2. Una política personalizada almacenada en un archivo de texto plano.
Los archivos de política consisten en una serie de secciones, cada una de las cuales contiene una regla y un mensaje de alerta. Las reglas se escriben en un lenguaje de consulta simple, y solo los detalles que coinciden con la regla se informan como advertencias.

Por ejemplo, una sección de política podría verse así:

    # Advertir si se encuentran algoritmos de cifrado débiles
    ciphers: aes128-cbc,3des-cbc
    message: Se encontró un algoritmo de cifrado débil, elimínelo de la lista
    de algoritmos permitidos en sshd_config.

La directiva --make-policy puede ser utilizada para generar una política personalizada basada en la configuración de un servidor existente.

-v, --verbose


Habilita la salida detallada.

AUDITORÍA ESTÁNDAR

Por defecto, ssh-audit realiza una auditoría estándar. Es decir, enumera todos los tipos de claves de host, intercambios de claves, cifrados, MACs y otra información, y luego los codifica por colores en la salida para el usuario. Las primitivas criptográficas con problemas potenciales se muestran en amarillo; las primitivas con fallos graves se muestran en rojo.

AUDITORÍA DE POLÍTICAS

Cuando se utiliza la opción -P/--policy, ssh-audit realiza una auditoría de políticas. Los tipos de claves de host del objetivo, los intercambios de claves, los cifrados, los MACs y otra información se comparan con un conjunto de valores esperados definidos en el archivo de políticas especificado. Si todo coincide, solo se informa un mensaje corto indicando un resultado de aprobación. De lo contrario, se informan los campos que no coincidieron.

La auditoría de políticas es útil para garantizar que un grupo de servidores relacionados estén debidamente protegidos según una especificación exacta.

El conjunto de políticas integradas oficiales se puede ver con -L/--list-policies. Se pueden auditar varios servidores con -T/--targets=<servers.txt>. Se pueden crear políticas personalizadas a partir de un servidor objetivo ideal con -M/--make-policy=<custom_policy.txt>.

EJEMPLOS

Auditoría básica de servidor:

ssh-audit localhost
ssh-audit 127.0.0.1
ssh-audit 127.0.0.1:222
ssh-audit ::1
ssh-audit [::1]:222

Para realizar una auditoría estándar en muchos servidores (coloca los objetivos en servers.txt, uno por línea en el formato HOST[:PORT]):

ssh-audit -T servers.txt

Para auditar una configuración de cliente (escucha en el puerto 2222 por defecto; conéctate usando "ssh -p 2222 anything@localhost"):

ssh-audit -c

Para auditar una configuración de cliente, con un oyente en el puerto 4567:

ssh-audit -c -p 4567

Para listar todas las políticas integradas oficiales (pista: usa sus nombres completos con -P/--policy):

ssh-audit -L

Para realizar una auditoría de política integrada en un servidor (pista: usa -L para ver la lista de políticas integradas):

ssh-audit -P "Servidor Ubuntu 20.04 LTS Reforzado (versión 1)" servidorobjetivo

Para realizar una auditoría de política personalizada en un servidor (pista: usa -M/--make-policy para crear un archivo de política personalizado):

ssh-audit -P ruta/a/politica_servidor.txt servidorobjetivo

Para realizar una auditoría de política en un cliente:

ssh-audit -c -P ["nombre de política" | ruta/a/politica_cliente.txt]

Para realizar una auditoría de política en muchos servidores:

ssh-audit -T servers.txt -P ["nombre de política" | ruta/a/politica_servidor.txt]

Para crear una política basada en un servidor objetivo (que se puede editar manualmente; consulta las políticas integradas oficiales para ver ejemplos de sintaxis):

ssh-audit -M nueva_politica.txt servidorobjetivo

Para ejecutar una prueba del tamaño del módulo de intercambio de grupos Diffie-Hellman utilizando los valores de 2000 bits, 3000 bits, 4000 bits y 5000 bits:

ssh-audit servidorobjetivo --gex-test=2000,3000,4000,5000

Para ejecutar una prueba del tamaño del módulo de intercambio de grupos Diffie-Hellman donde 2048 bits es el mínimo, 3072 bits es el preferido y 5000 bits es el máximo:

ssh-audit servidorobjetivo --gex-test=2048:3072:5000

Para ejecutar una prueba del tamaño del módulo de intercambio de grupos Diffie-Hellman de 0 bits a 5120 bits en incrementos de 1024 bits:

ssh-audit servidorobjetivo --gex-test=0-5120:1024

Para ejecutar el ataque DHEat DoS (monitoriza el uso de la CPU del servidor objetivo para determinar el número óptimo de sockets concurrentes):

ssh-audit servidorobjetivo --dheat=10

Para ejecutar el ataque DHEat y apuntar manualmente al algoritmo diffie-hellman-group-exchange-sha256:

ssh-audit servidorobjetivo --dheat=10:diffie-hellman-group-exchange-sha256

Para ejecutar el ataque DHEat y apuntar manualmente al algoritmo diffie-hellman-group-exchange-sha256 con una longitud muy pequeña de e (resultando en el mismo efecto pero sin tener que enviar paquetes grandes):

ssh-audit servidorobjetivo --dheat=10:diffie-hellman-group-exchange-sha256:4

Para probar el número de conexiones exitosas por segundo que se pueden crear con el objetivo utilizando 8 hilos paralelos (útil para detectar si el objetivo implementa limitación de conexiones):

ssh-audit servidorobjetivo --conn-rate-test=8

Para utilizar 8 hilos paralelos para crear hasta 100 conexiones por segundo con el objetivo (útil para comprender cuánta carga de CPU causan las nuevas conexiones en el objetivo en comparación con la exponenciación modular excesiva al realizar el ataque DHEat):

ssh-audit servidorobjetivo --conn-rate-test=8:100

VALORES DE RETORNO

Cuando se establece una conexión exitosa y todos los algoritmos se califican como "buenos", ssh-audit devuelve 0. Otros valores de retorno posibles son:

1 = error de conexión
2 = se encontró al menos una advertencia de algoritmo
3 = se encontró al menos un fallo de algoritmo
<cualquier otro valor distinto de cero> = error desconocido
