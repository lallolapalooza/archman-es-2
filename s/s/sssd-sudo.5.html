NOMBRE

sssd-sudo - Configuración de sudo con el backend SSSD

DESCRIPCIÓN

Esta página del manual describe cómo configurar sudo(8) para que funcione con sssd(8) y cómo SSSD almacena en caché las reglas de sudo.

CONFIGURACIÓN DE SUDO PARA COOPERAR CON SSSD

Para habilitar SSSD como fuente de reglas de sudo, agregue sss a la entrada sudoers en nsswitch.conf(5).

Por ejemplo, para configurar sudo para que primero busque reglas en el archivo estándar sudoers(5) (que debería contener reglas que se aplican a usuarios locales) y luego en SSSD, el archivo nsswitch.conf debería contener la siguiente línea:

sudoers: files sss

Puede encontrar más información sobre la configuración del orden de búsqueda de sudoers desde el archivo nsswitch.conf, así como información sobre el esquema LDAP que se utiliza para almacenar las reglas de sudo en el directorio, en sudoers.ldap(5).

Nota: para poder utilizar grupos de red (netgroups) o grupos de hosts IPA en reglas de sudo, también debe configurar correctamente nisdomainname(1) con el nombre de su dominio NIS (que es igual al nombre de dominio IPA cuando se usan grupos de hosts).

CONFIGURACIÓN DE SSSD PARA OBTENER REGLAS DE SUDO

Toda la configuración necesaria en el lado de SSSD es extender la lista de services con "sudo" en la sección [sssd] de sssd.conf(5). Para acelerar las búsquedas LDAP, también puede establecer la base de búsqueda para las reglas de sudo usando la opción ldap_sudo_search_base.

El siguiente ejemplo muestra cómo configurar SSSD para descargar reglas de sudo de un servidor LDAP.

[sssd]
services = nss, pam, sudo
domains = EXAMPLE
[domain/EXAMPLE]
id_provider = ldap
sudo_provider = ldap
ldap_uri = ldap://example.com
ldap_sudo_search_base = ou=sudoers,dc=example,dc=com

Es importante tener en cuenta que en las plataformas donde se soporta systemd, no es necesario agregar el proveedor "sudo" a la lista de servicios, ya que se volvió opcional. Sin embargo, sssd-sudo.socket debe estar habilitado en su lugar.

Cuando SSSD está configurado para usar IPA como proveedor de ID, el proveedor sudo se habilita automáticamente. La base de búsqueda sudo se configura para usar el árbol LDAP nativo de IPA (cn=sudo,$SUFFIX). Si se define alguna otra base de búsqueda en sssd.conf, se utilizará este valor en su lugar. El árbol de compatibilidad (ou=sudoers,$SUFFIX) ya no es necesario para la funcionalidad sudo de IPA.

EL MECANISMO DE ALMACENAMIENTO EN CACHÉ DE REGLAS DE SUDO

El mayor desafío, al desarrollar soporte para sudo en SSSD, fue garantizar que ejecutar sudo con SSSD como fuente de datos proporcione la misma experiencia de usuario y sea tan rápido como sudo, pero siga proporcionando el conjunto de reglas más actual posible. Para satisfacer estos requisitos, SSSD utiliza tres tipos de actualizaciones. Se les conoce como actualización completa (full refresh), actualización inteligente (smart refresh) y actualización de reglas (rules refresh).

La actualización inteligente descarga periódicamente las reglas que son nuevas o fueron modificadas después de la última actualización. Su objetivo principal es mantener la base de datos en crecimiento al obtener solo pequeños incrementos que no generan grandes cantidades de tráfico de red.

La actualización completa simplemente elimina todas las reglas de sudo almacenadas en la caché y las reemplaza con todas las reglas que están almacenadas en el servidor. Esto se utiliza para mantener la coherencia de la caché eliminando cada regla que fue eliminada del servidor. Sin embargo, la actualización completa puede generar mucho tráfico y, por lo tanto, solo debe ejecutarse ocasionalmente dependiendo del tamaño y la estabilidad de las reglas de sudo.

La actualización de reglas garantiza que no otorgamos al usuario más permisos de los definidos. Se activa cada vez que el usuario ejecuta sudo. La actualización de reglas encontrará todas las reglas que se aplican a este usuario, verificará su tiempo de expiración y las volverá a descargar si han expirado. En caso de que falten algunas de estas reglas en el servidor, SSSD realizará una actualización completa fuera de banda porque es posible que se hayan eliminado más reglas (que se aplican a otros usuarios).

Si está habilitado, SSSD almacenará solo las reglas que se pueden aplicar a esta máquina. Esto significa reglas que contienen uno de los siguientes valores en el atributo sudoHost:

•palabra clave ALL
•comodín
•netgroup (en el formato "+netgroup")
•nombre de host o nombre de dominio completo de esta máquina
•una de las direcciones IP de esta máquina
•una de las direcciones IP de la red (en el formato "dirección/máscara")

Hay muchas opciones de configuración que se pueden usar para ajustar el comportamiento. Consulte "ldap_sudo_*" en sssd-ldap(5) y "sudo_*" en sssd.conf(5).

AJUSTE DEL RENDIMIENTO

SSSD utiliza diferentes tipos de mecanismos con filtros LDAP más o menos complejos para mantener actualizadas las reglas de sudo almacenadas en caché. La configuración predeterminada se establece en valores que deberían satisfacer a la mayoría de nuestros usuarios, pero los siguientes párrafos contienen algunos consejos sobre cómo ajustar la configuración a sus necesidades.

1. Indexar atributos LDAP. Asegúrese de que los siguientes atributos LDAP estén indexados: objectClass, cn, entryUSN o modifyTimestamp.

2. Establecer ldap_sudo_search_base. Establezca la base de búsqueda en el contenedor que contiene las reglas de sudo para limitar el alcance de la consulta.

3. Establecer el intervalo de actualización completa e inteligente. Si sus reglas de sudo no cambian a menudo y no requiere una actualización rápida de las reglas almacenadas en caché en sus clientes, puede considerar aumentar el ldap_sudo_full_refresh_interval y ldap_sudo_smart_refresh_interval. También puede considerar deshabilitar la actualización inteligente estableciendo ldap_sudo_smart_refresh_interval = 0.

4. Si tiene un gran número de clientes, puede considerar aumentar el valor de ldap_sudo_random_offset para distribuir mejor la carga en el servidor.
