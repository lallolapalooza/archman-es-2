NOMBRE

sserver - servidor de ejemplo de Kerberos versión 5

SINOPSIS

sserver [ -p puerto ] [ -S keytab ] [ puerto_servidor ]

DESCRIPCIÓN

sserver y sclient(1) son una aplicación cliente/servidor de demostración sencilla. Cuando sclient se conecta a sserver, realiza una autenticación Kerberos, y luego sserver devuelve a sclient el principal de Kerberos que se utilizó para la autenticación Kerberos. Sirve como una buena prueba para verificar que Kerberos se ha instalado correctamente en una máquina.

El nombre del servicio utilizado por sserver y sclient es `sample`. Por lo tanto, sserver requerirá que exista una entrada en el keytab para el servicio sample/hostname.domain.name@REALM.NAME. Este keytab se genera utilizando el programa kadmin(1). El archivo keytab se instala normalmente como FILE:/etc/krb5.keytab.

La opción -S permite especificar un keytab diferente al predeterminado.

sserver se invoca normalmente desde inetd(8), utilizando una línea en /etc/inetd.conf que se ve así:

sample stream tcp nowait root /usr/local/sbin/sserver sserver

Dado que sample normalmente no es un puerto definido en /etc/services, normalmente tendrá que añadir una línea a /etc/services que se vea así:

sample          13135/tcp

Al usar sclient, primero deberá tener una entrada en la base de datos Kerberos, utilizando kadmin(1), y luego obtener tickets Kerberos, utilizando kinit(1). Además, si está ejecutando el programa sclient en un host diferente al de sserver al que se conectará, asegúrese de que ambos hosts tengan una entrada en /etc/services para el puerto tcp `sample`, y que el mismo número de puerto esté en ambos archivos.

Cuando ejecute sclient, debería ver algo como esto:

sendauth succeeded, reply is:
reply len 32, contents:
You are nlgilman@JIMI.MIT.EDU

MENSAJES DE ERROR COMUNES

1.
kinit devuelve el error:
kinit: Client not found in Kerberos database while getting
       initial credentials

Esto significa que no ha creado una entrada para su nombre de usuario en la base de datos Kerberos.

2.
sclient devuelve el error:
unknown service sample/tcp; check /etc/services

Esto significa que no tiene una entrada en /etc/services para el puerto tcp `sample`.

3.
sclient devuelve el error:
connect: Connection refused

Esto probablemente significa que no editó /etc/inetd.conf correctamente, o que no reinició inetd después de editar /etc/inetd.conf.

4.
sclient devuelve el error:
sclient: Server not found in Kerberos database while using
         sendauth

Esto significa que el servicio sample/hostname@LOCAL.REALM no estaba definido en la base de datos Kerberos; debería crearse usando kadmin(1), y se debe generar un archivo keytab para hacer que la clave de ese principal de servicio esté disponible para sclient.

5.
sclient devuelve el error:
sendauth rejected, error reply is:
    "No such file or directory"

Esto probablemente significa que sserver no pudo encontrar el archivo keytab. Probablemente no se instaló en el directorio correcto.

AMBIENTE

Consulte kerberos(7) para una descripción de las variables de entorno de Kerberos.
