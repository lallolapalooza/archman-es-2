SSH-COPY-ID(1) Manual de Comandos Generales SSH-COPY-ID(1)

NOMBRE

ssh-copy-id — usa claves disponibles localmente para autorizar inicios de sesión en una máquina remota

SINOPSIS

ssh-copy-id [-f] [-n] [-s] [-x] [-i [archivo_identidad]] [-t ruta_destino] [-F config_ssh] [[-o opcion_ssh] ...] [-p puerto] [usuario@]nombre_host

ssh-copy-id -h | -?

DESCRIPCIÓN

ssh-copy-id es un script que utiliza ssh(1) para iniciar sesión en una máquina remota (presumiblemente usando una contraseña de inicio de sesión, por lo que la autenticación por contraseña debe estar habilitada, a menos que hayas hecho algún uso ingenioso de identidades múltiples). Ensambla una lista de una o más huellas digitales (como se describe a continuación) e intenta iniciar sesión con cada clave, para ver si alguna ya está instalada (por supuesto, si no estás usando ssh-agent(1) esto puede resultar en que se te pida repetidamente la frase secreta). Luego, ensambla una lista de aquellas que fallaron al iniciar sesión y, usando ssh(1), habilita los inicios de sesión con esas claves en el servidor remoto. Por defecto, agrega las claves añadiéndolas al archivo ~/.ssh/authorized_keys del usuario remoto (creando el archivo y el directorio si es necesario). También es capaz de detectar si el sistema remoto es un NetScreen y usar en su lugar su comando ‘set ssh pka-dsa key ...’.

Las opciones son las siguientes:

-i [archivo_identidad]
Usa solo la(s) clave(s) contenida(s) en archivo_identidad (en lugar de buscar identidades a través de ssh-add(1) o en el archivo_ID_predeterminado). Si el nombre del archivo no termina en .pub, se agrega. Si se omite el nombre del archivo, se usa el archivo_ID_predeterminado.

Ten en cuenta que esto se puede usar para asegurar que las claves copiadas tengan el comentario deseado y/o opciones adicionales aplicadas, asegurándose de que el archivo de claves tenga estas configuradas como preferidas antes de intentar la copia.

-f
Modo forzado: no verifica si las claves están presentes en el servidor remoto. Esto significa que no necesita la clave privada. Por supuesto, esto puede resultar en que se instale más de una copia de la clave en el sistema remoto.
-n
realizar una simulación (dry-run). En lugar de instalar claves en el sistema remoto, simplemente imprime la(s) clave(s) que se habrían instalado.
-s
Modo SFTP: normalmente, las claves públicas se instalan ejecutando comandos en el lado remoto. Con esta opción, se descargará el archivo ~/.ssh/authorized_keys del usuario, se modificará localmente y se subirá con sftp. Esta opción es útil si el servidor tiene restricciones sobre los comandos que se pueden usar en el lado remoto.
-t ruta_destino
la ruta en el sistema de destino donde se deben agregar las claves (el valor predeterminado es ".ssh/authorized_keys")
-p puerto
Especifica el puerto al que conectarse en el host remoto.
-F config_ssh, -o opcion_ssh
Estas opciones simplemente se pasan sin cambios (con su argumento) a ssh/sftp, permitiendo establecer un archivo de configuración alternativo u otras opciones, respectivamente.

En lugar de especificar estas como opciones de línea de comandos, a menudo es mejor usar configuraciones (por host) en el archivo de configuración de ssh(1): ssh_config(5).

-x
Esta opción es para depurar el script ssh-copy-id en sí. Establece el flag -x del shell, para que puedas ver los comandos que se están ejecutando.
-h, -?
Imprimir resumen de uso

El comportamiento predeterminado sin -i es verificar si ‘ssh-add -L’ proporciona alguna salida y, si es así, se usan esas claves. Ten en cuenta que esto resulta en que el comentario de la clave sea el nombre del archivo que se le dio a ssh-add(1) cuando la clave se cargó en tu ssh-agent(1), en lugar del comentario contenido en ese archivo, lo cual es una lástima. De lo contrario, si ssh-add(1) no proporciona ninguna clave, se usarán los contenidos del archivo_ID_predeterminado.

El archivo_ID_predeterminado es el archivo más reciente que coincide con: ~/.ssh/id*.pub (excluyendo aquellos que coinciden con ~/.ssh/*-cert.pub), por lo que si creas una clave que no es la que quieres que use ssh-copy-id, simplemente usa touch(1) en el archivo .pub de tu clave preferida para restablecerla como la más reciente.

EJEMPLOS

Si ya has instalado claves desde un sistema en muchos hosts remotos, y luego creas una nueva clave en una nueva máquina cliente, por ejemplo, puede ser difícil hacer un seguimiento de en qué sistemas has instalado la nueva clave. Una forma de lidiar con esto es cargar tanto la clave nueva como la(s) clave(s) antigua(s) en tu ssh-agent(1). Carga la clave nueva primero, sin la opción -c, luego carga una o más claves antiguas en el agente, posiblemente iniciando sesión en la máquina cliente que tiene esa clave antigua, usando la opción -A para permitir el reenvío del agente:

usuario@nuevocliente$ ssh-add
usuario@nuevocliente$ ssh -A antiguo.cliente
usuario@antiguo$ ssh-add -c
... se solicita la frase secreta ...
usuario@antiguo$ logoff
usuario@nuevocliente$ ssh algunservidor

Ahora, si la clave nueva está instalada en el servidor, se te permitirá el acceso sin pedirte nada, mientras que si solo tienes habilitada(s) la(s) clave(s) antigua(s), se te pedirá confirmación, lo cual es tu señal para cerrar la sesión nuevamente y ejecutar

usuario@nuevocliente$ ssh-copy-id -i algunservidor

La razón por la que podrías querer especificar la opción -i en este caso es para asegurar que el comentario en la clave instalada sea el del archivo .pub, en lugar de simplemente el nombre del archivo que se cargó en tu agente. También asegura que solo se instale la id que pretendías, en lugar de todas las claves que tienes en tu ssh-agent(1). Por supuesto, puedes especificar otra id o usar el contenido del ssh-agent(1) como prefieras.

Habiendo mencionado la opción -c de ssh-add(1), podrías considerar usar esto cada vez que uses reenvío de agente para evitar que tu clave sea secuestrada, pero es mucho mejor usar en su lugar el ProxyCommand y la opción -W de ssh(1), para rebotar a través de servidores remotos mientras siempre se realiza una autenticación de extremo a extremo directa.
