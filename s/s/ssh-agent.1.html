NOMBRE

ssh-agent — Agente de autenticación OpenSSH

SINOPSIS

ssh-agent [-c | -s] [-DdTU] [-a direccion_enlace] [-E hash_huella] [-O opcion] [-P proveedores_permitidos] [-t vida]

ssh-agent [-TU] [-a direccion_enlace] [-E hash_huella] [-O opcion] [-P proveedores_permitidos] [-t vida] comando [arg ...]

ssh-agent [-c | -s] -k

ssh-agent -u

DESCRIPCIÓN

ssh-agent es un programa para mantener claves privadas utilizadas para la autenticación de clave pública. Mediante el uso de variables de entorno, el agente puede ser localizado y utilizado automáticamente para la autenticación al iniciar sesión en otras máquinas usando ssh(1).

Las opciones son las siguientes:

-a direccion_enlace
Enlaza el agente al socket de dominio UNIX direccion_enlace. El valor predeterminado es crear un socket en una ruta aleatoria que coincide con $HOME/.ssh/agent/s.*.
-c
Genera comandos de shell C en la salida estándar. Este es el valor predeterminado si SHELL parece ser un shell de estilo csh.
-D
Modo de primer plano. Cuando se especifica esta opción, ssh-agent no se bifurcará.
-d
Modo de depuración. Cuando se especifica esta opción, ssh-agent no se bifurcará y escribirá información de depuración en la salida de error estándar.
-E hash_huella
Especifica el algoritmo de hash utilizado al mostrar las huellas digitales de las claves. Las opciones válidas son: “md5” y “sha256”. El valor predeterminado es “sha256”.
-k
Mata el agente actual (dado por la variable de entorno SSH_AGENT_PID).
-O opcion
Especifica una opción al iniciar ssh-agent. Las opciones admitidas son: allow-remote-pkcs11, no-restrict-websafe y websafe-allow.

La opción allow-remote-pkcs11 permite a los clientes de un ssh-agent reenviado cargar bibliotecas de proveedores PKCS#11 o FIDO. Por defecto, solo los clientes locales pueden realizar esta operación. Tenga en cuenta que el señalamiento de que un cliente de ssh-agent es remoto se realiza mediante ssh(1), y el uso de otras herramientas para reenviar el acceso al socket del agente puede eludir esta restricción.

La opción no-restrict-websafe indica a ssh-agent que permita firmas utilizando claves FIDO que podrían ser solicitudes de autenticación web. Por defecto, ssh-agent rechaza las solicitudes de firma para claves FIDO donde la cadena de aplicación de la clave no comienza con “ssh:” y cuando los datos a firmar no parecen ser una solicitud de autenticación de usuario de ssh(1) o una firma de ssh-keygen(1). El comportamiento predeterminado evita que el acceso reenviado a una clave FIDO también reenvíe implícitamente la capacidad de autenticarse en sitios web.

Alternativamente, la opción websafe-allow permite especificar una lista de patrones de cadenas de aplicación de clave para reemplazar la lista de aplicaciones permitidas predeterminada, por ejemplo: “websafe-allow=ssh:*,example.org,*.example.com”

Consulte PATTERNS en ssh_config(5) para obtener una descripción de la sintaxis de la lista de patrones.

-P proveedores_permitidos
Especifica una lista de patrones de rutas aceptables para bibliotecas compartidas de middleware de autenticación FIDO y proveedores PKCS#11 que pueden usarse con las opciones -S o -s de ssh-add(1). Se rechazarán las bibliotecas que no coincidan con la lista de patrones. La lista predeterminada es “usr/lib*/*,/usr/local/lib*/*”.

Consulte PATTERNS en ssh_config(5) para obtener una descripción de la sintaxis de la lista de patrones.

-s
Genera comandos de shell Bourne en la salida estándar. Este es el valor predeterminado si SHELL no parece ser un shell de estilo csh.
-T
Enlaza el socket del agente en un subdirectorio aleatorio con el formato $TMPDIR/ssh-XXXXXXXXXX/agent.<ppid>, en lugar del comportamiento predeterminado de usar un nombre aleatorio que coincida con $HOME/.ssh/agent/s.*.
-t vida
Establece un valor predeterminado para la vida útil máxima de las identidades añadidas al agente. La vida útil se puede especificar en segundos o en un formato de tiempo especificado en sshd_config(5). Una vida útil especificada para una identidad con ssh-add(1) anula este valor. Sin esta opción, la vida útil máxima predeterminada es para siempre.
-U
Indica a ssh-agent que no limpie los sockets de agente obsoletos en $HOME/.ssh/agent/.
-u
Indica a ssh-agent que solo limpie los sockets de agente obsoletos en $HOME/.ssh/agent/ y luego salga inmediatamente. Si esta opción se da dos veces, ssh-agent eliminará los sockets de agente obsoletos independientemente del nombre de host que los creó.
comando [arg ...]
Si se proporciona un comando (y argumentos opcionales), este se ejecuta como un subproceso del agente. El agente sale automáticamente cuando termina el comando dado en la línea de comandos.

Hay tres formas principales de configurar un agente. La primera es al inicio de una sesión X, donde todas las demás ventanas o programas se inician como hijos del programa ssh-agent. El agente inicia un comando bajo el cual se exportan sus variables de entorno, por ejemplo ssh-agent xterm &. Cuando el comando termina, el agente también lo hace.

El segundo método se utiliza para una sesión de inicio de sesión. Cuando se inicia ssh-agent, imprime los comandos de shell necesarios para configurar sus variables de entorno, que a su vez pueden ser evaluadas en el shell que llama, por ejemplo eval `ssh-agent -s`.

NAME

ssh-agent — authentication agent for OpenSSH

SYNOPSIS

ssh-agent [-c | -s] [-d path] [-a listening_socket] [-t lifecon_time] [-k] [-P password_program]

DESCRIPTION

ssh-agent is a background program that holds private keys used for public key authentication (typically for ssh(1)). When you log in to a remote server, ssh-agent can automatically provide your passphrase, eliminating the need to enter it every time. This is especially useful when using SSH certificates or automated processes.

There are several ways to run ssh-agent. The most common is to run it interactively from a shell, using either the -c (csh/tcsh) or -s (sh/bash/zsh) options. These options print shell commands to the standard output, which should be evaluated by the shell. For example:

sh/bash/zsh:

eval `ssh-agent -s`

csh/tcsh:

eval `ssh-agent -c`

These commands set the SSH_AUTH_SOCK and SSH_AGENT_PID environment variables, which are used by other SSH programs to communicate with the agent.

The third way to run ssh-agent is via socket activation from a supervising process, such as systemd. In this mode, the supervising process creates the listening socket and is responsible for starting ssh-agent as needed, and also for communicating the location of the socket listener to other programs in the user's session. Socket activation is used when ssh-agent is started with either of the -d or -D flags, no socket listening address specified by the -a flag, and both the LISTEN_FDS and LISTEN_PID environment variables correctly supplied by the supervising process.

The agent initially does not have any private keys. Keys are added using ssh-add(1) or by ssh(1) when AddKeysToAgent is set in ssh_config(5). Multiple identities may be stored in ssh-agent concurrently and ssh(1) will automatically use them if present. ssh-add(1) is also used to remove keys from ssh-agent and to query the keys that are held in one.

Connections to ssh-agent may be forwarded from further remote hosts using the -A option to ssh(1) (but see the caveats documented therein), avoiding the need for authentication data to be stored on other machines. Authentication passphrases and private keys never go over the network: the connection to the agent is forwarded over SSH remote connections and the result is returned to the requester, allowing the user access to their identities anywhere in the network in a secure fashion.

ssh-agent will delete all keys it has loaded upon receiving SIGUSR1.

ENVIRONMENT

SSH_AGENT_PID
When ssh-agent starts, it stores the name of the agent's process ID (PID) in this variable.
SSH_AUTH_SOCK
When ssh-agent starts, it creates a UNIX-domain socket and stores its pathname in this variable. It is accessible only to the current user, but is easily abused by root or another instance of the same user.

FILES

$HOME/.ssh/agent/s.*
UNIX-domain sockets used to contain the connection to the authentication agent. These sockets should only be readable by the owner. The sockets should get automatically removed when the agent exits.

ssh(1), ssh-add(1), ssh-keygen(1), ssh_config(5), sshd(8)
