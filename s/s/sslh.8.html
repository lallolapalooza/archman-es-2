NOMBRE

sslh - desmultiplexor de protocolos

SINOPSIS

sslh [-Farchivo de config] [-t num] [--transparent] [-p dirección de escucha [-p dirección de escucha ...] [--tls dirección de destino para TLS] [--ssh dirección de destino para SSH] [--openvpn dirección de destino para OpenVPN] [--http dirección de destino para HTTP] [--xmpp dirección de destino para XMPP] [--tinc dirección de destino para TINC] [--anyprot dirección de destino predeterminada] [--on-timeout nombre del protocolo] [-u nombre de usuario] [-C chroot] [-P archivo pid] [-v n] [-i] [-V] [-f] [-n]

DESCRIPCIÓN

sslh acepta conexiones en puertos especificados y las reenvía basándose en pruebas realizadas sobre el primer paquete de datos enviado por el cliente remoto.

Se implementan sondeos para HTTP, TLS, SSH, OpenVPN, tinc, XMPP, y cualquier otro protocolo que pueda ser probado usando una expresión regular. Un caso de uso típico es permitir servir varios servicios en el puerto 443 (por ejemplo, para conectarse a ssh desde dentro de un firewall corporativo, que casi nunca bloquea el puerto 443) mientras se sigue sirviendo HTTPS en ese puerto.

Por lo tanto, sslh actúa como un desmultiplexor de protocolos, o una centralita. Su nombre proviene de su función original de servir SSH y HTTPS en el mismo puerto.

Soporte Libwrap

Un inconveniente de sslh es que los servidores ya no ven la dirección IP original del cliente, ya que la conexión se reenvía a través de sslh.

Por esta razón, sslh puede compilarse con libwrap para verificar los accesos definidos en /etc/hosts.allow y /etc/hosts.deny. Los servicios de Libwrap se pueden definir usando el archivo de configuración.

Archivo de configuración

Se puede proporcionar un archivo de configuración a sslh. Los argumentos de la línea de comandos anulan la configuración del archivo. sslh utiliza libconfig para analizar el archivo de configuración, por lo que el formato general del archivo se indica en http://www.hyperrealm.com/libconfig/libconfig_manual.html. Consulte el archivo de configuración de ejemplo proporcionado con sslh para conocer el formato específico (las opciones tienen los mismos nombres que en la línea de comandos, excepto por la lista de puertos de escucha y la lista de protocolos).

El archivo de configuración permite especificar protocolos usando expresiones regulares: se proporciona una lista de expresiones regulares como parámetro regex_patterns, y si el primer paquete recibido del cliente coincide con alguna de estas expresiones, sslh se conecta a ese protocolo.

Protocolos de sondeo

Al recibir una conexión entrante, sslh leerá los primeros bytes enviados por el cliente de conexión. Luego sondeará el protocolo en el orden especificado en la línea de comandos (o en el archivo de configuración). Por lo tanto, --anyprot siempre debe usarse al final, ya que siempre tiene éxito y los protocolos posteriores nunca se intentarán.

Si el cliente no envía datos, sslh finalmente se agotará el tiempo de espera y se conectará al protocolo especificado con --on-timeout, o a ssh si no se especifica ninguno.

Registro en bitácora

Como programa de seguridad/autorización, sslh registra en la instalación LOG_AUTH, con prioridad LOG_INFO para conexiones normales y LOG_ERR para fallos.

OPCIONES

-Fnombre de archivo, --config nombre de archivo
Utiliza nombre de archivo como archivo de configuración. Si se especifican otras opciones de línea de comandos, anularán la configuración del archivo.
-t num, --timeout num
Tiempo de espera antes de reenviar la conexión al protocolo de tiempo de espera (que generalmente debería ser SSH). El valor predeterminado es 2s.
--on-timeout nombre del protocolo
Nombre del protocolo al que conectarse una vez finalizado el período de tiempo de espera. El valor predeterminado es reenviar al primer protocolo especificado. Generalmente tiene sentido especificar 'ssh' como protocolo de tiempo de espera, ya que la especificación SSH no indica quién debe hablar primero y un gran número de clientes SSH esperan que el servidor envíe su banner.
--transparent
Hace que sslh se comporte como un proxy transparente, es decir, el servicio receptor ve la dirección IP original del cliente. Esto solo funciona en Linux e implica configuraciones de iproute2. En algunos casos, también se necesitan configuraciones de iptables/nftables. Consulte el README o https://github.com/ftasnetamot/sslh/blob/2014-08-16--close-filehandles-with-detach/doc/simple_transparent_proxy.md para más información.
-p dirección de escucha, --listen dirección de escucha
Interfaz y puerto en el que escuchar, por ejemplo, foobar:443, donde foobar es el nombre de una interfaz (típicamente la dirección IP en la que termina la conexión a Internet).

Esto se puede especificar varias veces para enlazar sslh a varias direcciones.

--tls dirección de destino
Interfaz y puerto en el que reenviar la conexión SSL, típicamente localhost:443.

Tenga en cuenta que puede configurar sslh para que escuche en ip_externa:443 y httpd para que escuche en localhost:443: esto permite que los clientes dentro de su red se conecten directamente a httpd.

Además, sslh sondea los handshakes TLS y rechazará las conexiones de clientes que soliciten SSLv2. Esto cumple con RFC6176, que prohíbe el uso de SSLv2. Si desea aceptar SSLv2, use --anyprot en su lugar.

--ssh dirección de destino
Interfaz y puerto en el que reenviar las conexiones SSH, típicamente localhost:22.
--openvpn dirección de destino
Interfaz y puerto en el que reenviar las conexiones OpenVPN, típicamente localhost:1194.
--xmpp dirección de destino
Interfaz y puerto en el que reenviar las conexiones XMPP, típicamente localhost:5222.
--http dirección de destino
Interfaz y puerto en el que reenviar las conexiones HTTP, típicamente localhost:80.
--tinc dirección de destino
Interfaz y puerto en el que reenviar las conexiones tinc, típicamente localhost:655.

Esto es experimental. Si usa esta función, por favor informe de los resultados (¡incluso si funciona!).

--anyprot dirección de destino
Interfaz y puerto en el que reenviar si no se ha encontrado ningún otro protocolo. Dado que sslh prueba los protocolos en el orden especificado en la línea de comandos, esto debe especificarse al final. Si no se especifica ningún valor predeterminado, sslh reenviará los protocolos desconocidos al primer protocolo especificado.
-v, --verbose n
Anula toda la verbosidad. Consulte example.cfg para ver todas las sub-opciones de verbosidad.
-n, --numeric
No intente resolver nombres de host: los registros contendrán direcciones IP. Esto es útil principalmente si el DNS del sistema es lento y está ejecutando la variante sslh-select, ya que las solicitudes DNS bloquearán todas las conexiones.
-V
Imprime la versión de sslh.
-u nombre de usuario, --user nombre de usuario
Requiere ejecutarse bajo el nombre de usuario especificado.
-C chroot, --chroot chroot
Requiere r

NOMBRE

sslh - SSL/SSH multiplexer

SINOPSIS

sslh [-f|--foreground] [--background] [-P pidfile | --pidfile pidfile] [-p listen_addr | --listen listen_addr] [-u user | --user user] [-t chroot | --chroot chroot] [-v | --verbose] [-V | --version] [-h | --help] [-i | --inetd]

DESCRIPCIÓN

sslh es un multiplexor SSL/SSH. Permite que varios servicios (como OpenSSH, Postfix, etc.) compartan el mismo puerto. sslh escucha en un puerto y, basándose en la inspección de los datos entrantes, los reenvía al servicio apropiado.

Para que esto funcione, sslh debe ejecutarse en un puerto privilegiado (normalmente el puerto 443 o el 22). sslh está escrito en C y es muy pequeño.

sslh funciona bien con proxies transparentes, ya que no interfiere con la conexión de ninguna manera.

sslh se puede configurar para reenviar SSL y SSH a servicios diferentes. Los servicios están definidos en el archivo de configuración, que por defecto es /etc/default/sslh.

sslh también puede configurarse para hacer un túnel a otro servidor de sslh. Esto es útil si se ejecuta un único servidor SSL/SSH público pero se quieren direccionar varios servicios (y sus correspondientes archivos de certificado) a diferentes servidores.

sslh puede reescribir las cabeceras de las solicitudes HTTP, lo que permite usarlo como proxy transparente para servidores web.

sslh puede funcionar como un servidor inetd.

sslh se puede configurar para aceptar conexiones SSL, en cuyo caso debe ser capaz de realizar un handshake SSL. Para ello, se le pasa el número de puerto y el certificado que se utilizan en el servidor SSL.

Si sslh se ejecuta con un túnel, puede ser configurado para reenviar la conexión a otro servidor sslh en lugar de a un servicio local. Esto es útil si se desea direccionar diferentes conexiones SSL/SSH a diferentes servidores, o si se desea una solución de balanceo de carga simple.

Las configuraciones se pasan a sslh mediante el archivo de configuración /etc/default/sslh.

OPCIONES

-v, --verbose
Aumenta la verbosidad de la salida.
-V, --version
Muestra la versión de sslh y sale.
-h, --help
Muestra un mensaje de ayuda y sale.
-p listen_addr, --listen listen_addr
Dirección de escucha. Esto puede ser un nombre de host o una dirección IP, seguida opcionalmente por un número de puerto. Por defecto, localhost.
-u user, --user user
Cambia el usuario y grupo del servidor al especificado después de abrir el socket de escucha. Si se usa junto con chroot, el usuario y grupo se cambian después del chroot. Por defecto, el servidor se ejecuta como el usuario y grupo especificados en la configuración. Si no se especifica ningún usuario, el servidor se ejecuta como root.
-t chroot, --chroot chroot
Ejecuta el servidor bajo el chroot especificado.
-P pidfile, --pidfile pidfile
Especifica un archivo en el que escribir el PID del servidor principal.
-i, --inetd
Se ejecuta como un servidor inetd. Las opciones -P (archivo PID), -p (dirección de escucha), -u (usuario) se ignoran.
-f, --foreground
Se ejecuta en primer plano. El servidor no se bifurcará y permanecerá conectado a la terminal. Los mensajes que normalmente se envían a syslog también se enviarán a stderr.
--background
Se ejecuta en segundo plano. Esto anula foreground si se establece en el archivo de configuración (o en la línea de comandos, pero no tiene sentido establecer ambos en la línea de comandos a menos que se tenga un trastorno de personalidad).

ARCHIVOS

/etc/init.d/sslh
Script de inicio. Se admiten las acciones estándar start, stop y restart.
/etc/default/sslh
Configuración del servidor. Estas son variables de entorno cargadas por el script de inicio y pasadas a sslh como argumentos de línea de comandos. Consulte la sección OPCIONES para una explicación detallada de las variables utilizadas por sslh.
