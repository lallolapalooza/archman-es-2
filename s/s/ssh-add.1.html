SSH-ADD(1) Manual de comandos generales SSH-ADD(1)

NOMBRE

ssh-add — añade identidades de clave privada al agente de autenticación OpenSSH

SINOPSIS

ssh-add [-CcDdKkLlNqvXx] [-E hash_huella] [-H archivo_clave_host] [-h restriccion_destino] [-S proveedor] [-t vida] [archivo ...]

ssh-add -s pkcs11 [-Cv] [certificado ...]

ssh-add -e pkcs11

ssh-add -T pubkey ...

DESCRIPCIÓN

ssh-add añade identidades de clave privada al agente de autenticación, ssh-agent(1). Cuando se ejecuta sin argumentos, añade los archivos ~/.ssh/id_rsa, ~/.ssh/id_ecdsa, ~/.ssh/id_ecdsa_sk, ~/.ssh/id_ed25519 y ~/.ssh/id_ed25519_sk. Después de cargar una clave privada, ssh-add intentará cargar la información del certificado correspondiente del nombre de archivo obtenido añadiendo -cert.pub al nombre del archivo de clave privada. Se pueden dar nombres de archivo alternativos en la línea de comandos.

Si algún archivo requiere una contraseña, ssh-add solicita la contraseña al usuario. La contraseña se lee desde la terminal del usuario. ssh-add reintenta la última contraseña si se dan varios archivos de identidad.

El agente de autenticación debe estar en ejecución y la variable de entorno SSH_AUTH_SOCK debe contener el nombre de su socket para que ssh-add funcione.

Las opciones son las siguientes:

-C
Al cargar claves en el agente o eliminar claves de él, procesa solo certificados y omite claves normales.
-c
Indica que las identidades añadidas deben estar sujetas a confirmación antes de ser utilizadas para la autenticación. La confirmación se realiza mediante ssh-askpass(1). La confirmación exitosa se señala con un estado de salida cero de ssh-askpass(1), en lugar de texto introducido en el solicitante.
-D
Elimina todas las identidades del agente.
-d
En lugar de añadir identidades, elimina identidades del agente. Si ssh-add se ha ejecutado sin argumentos, se eliminarán las claves de las identidades predeterminadas y sus certificados correspondientes. De lo contrario, la lista de argumentos se interpretará como una lista de rutas a archivos de clave pública para especificar claves y certificados que se eliminarán del agente. Si no se encuentra ninguna clave pública en la ruta dada, ssh-add añadirá .pub y reintentará. Si la lista de argumentos consiste en “-”, entonces ssh-add leerá las claves públicas a eliminar de la entrada estándar.
-E hash_huella
Especifica el algoritmo de hash utilizado al mostrar las huellas dactilares de las claves. Las opciones válidas son: “md5” y “sha256”. El valor predeterminado es “sha256”.
-e pkcs11
Elimina las claves proporcionadas por la biblioteca compartida PKCS#11 pkcs11.
-H archivo_clave_host
Especifica un archivo de hosts conocidos para buscar claves de host al usar claves con restricciones de destino a través de la bandera -h. Esta opción puede especificarse varias veces para permitir la búsqueda en varios archivos. Si no se especifican archivos, ssh-add utilizará los archivos de hosts conocidos predeterminados de ssh_config(5): ~/.ssh/known_hosts, ~/.ssh/known_hosts2, /etc/ssh/ssh_known_hosts y /etc/ssh/ssh_known_hosts2.
-h restriccion_destino
Al añadir claves, restringe su uso solo a través de hosts específicos o a destinos específicos.

Las restricciones de destino del formato ‘[usuario@]nombre_host_destino’ permiten usar la clave solo desde el host de origen (el que ejecuta ssh-agent(1)) hacia el host de destino listado, con un nombre de usuario opcional.

Las restricciones del formato ‘nombre_host_origen>[usuario@]nombre_host_destino’ permiten que una clave disponible en un ssh-agent(1) reenviado se utilice a través de un host específico (tal como se especifica por ‘nombre_host_origen’) para autenticarse a otro host, especificado por ‘nombre_host_destino’.

Se pueden añadir múltiples restricciones de destino al cargar claves. Al intentar la autenticación con una clave que tiene restricciones de destino, se comprueba toda la ruta de conexión, incluido el reenvío de ssh-agent(1), contra esas restricciones, y cada salto debe estar permitido para que el intento tenga éxito. Por ejemplo, si una clave se reenvía a un host remoto, ‘host-b’, y se intenta autenticar a otro host, ‘host-c’, la operación tendrá éxito solo si ‘host-b’ estaba permitido desde el host de origen y el salto subsiguiente ‘host-b>host-c’ también está permitido por las restricciones de destino.

Los hosts se identifican por sus claves de host, y se buscan en los archivos de hosts conocidos por ssh-add. Se pueden usar patrones comodín para los nombres de host y se admiten las claves de host de certificados. Por defecto, las claves añadidas por ssh-add no tienen restricciones de destino.

Las restricciones de destino se añadieron en la versión 8.9 de OpenSSH. Se requiere compatibilidad tanto en el cliente SSH remoto como en el servidor al usar claves con restricciones de destino a través de un canal de ssh-agent(1) reenviado.

También es importante tener en cuenta que las restricciones de destino solo pueden ser aplicadas por ssh-agent(1) cuando se utiliza una clave, o cuando es reenviada por un cooperando ssh(1). Específicamente, no evita que un atacante con acceso a un SSH_AUTH_SOCK remoto lo reenvíe de nuevo y lo utilice en otro host (pero solo a un destino permitido).

-K
Carga claves residentes desde un autenticador FIDO.
-k
Al cargar claves en el agente o eliminar claves de él, procesa solo claves privadas normales y omite certificados.
-L
Lista los parámetros de clave pública de todas las identidades actualmente representadas por el agente.
-l
Lista las huellas dactilares de todas las identidades actualmente representadas por el agente.
-N
Al añadir certificados, por defecto ssh-add pedirá la contraseña de las claves privadas correspondientes.
-q
Modo silencioso. No se muestra ninguna advertencia.
-S proveedor
Especifica el proveedor de la biblioteca de autenticación. El valor puede ser un nombre o una ruta a una biblioteca compartida.
-s pkcs11
Añade claves proporcionadas por la biblioteca compartida PKCS#11 pkcs11.
-T pubkey ...
Revisa las claves públicas de las identidades representadas por el agente. Si se especifican argumentos, solo se revisan las claves públicas dadas.
-t vida
Establece un período de tiempo durante el cual la identidad añadida será válida. El valor vida se especifica como un entero seguido opcionalmente por un sufijo que indica la unidad de tiempo: “c” para segundos (predeterminado), “m” para minutos, “h” para horas, “d” para días, “w” para semanas y “y” para años. La sintaxis también permite un valor de “infinite”.
-v
Modo detallado. Hace que ssh-add imprima mensajes de depuración sobre su progreso.
-X
Cuando se eliminan claves del agente, procesa solo las claves públicas simples y omite los certificados.
-x
Cuando se eliminan claves del agente, procesa solo las claves de autenticadores FIDO y omite las claves públicas normales.

ssh-add(1) - Arch Linux man pages

SYNOPSIS

ssh-add [-c] [-D] [-d key_identity] [-e engine] [-L] [-l] [-t life] [-q] [-S pkcs11_provider] [-s pkcs11] [-T pubkey ...] [-v] [-X] [-x] [file ...]

DESCRIPTION

ssh-add aumenta la cantidad de claves de autenticación disponibles para ssh-agent(1).

Las claves privadas se utilizan para realizar operaciones de inicio de sesión sin contraseña en el host remoto.

El agente ssh-agent se inicia automáticamente cuando inicia sesión en una sesión gráfica.

Las claves se pueden agregar a ssh-agent proporcionando el nombre de archivo de la clave privada como argumento de la línea de comandos. Si no se proporcionan nombres de archivo, ssh-add carga las claves predeterminadas de ~/.ssh/id RSA, ~/.ssh/id DSA, ~/.ssh/id ECDSA, y ~/.ssh/id Ed25519. Si la clave se protege con una contraseña, ssh-add la solicitará.

Las siguientes opciones están disponibles:

-c
Hace que las claves cargadas en el agente deban ser confirmadas usando ssh-askpass(1) antes de usarlas. Esto es útil para protegerse contra el uso no autorizado de claves por parte de procesos maliciosos.
-D
Elimina todas las claves del agente.
-d key_identity
Elimina la clave especificada de ssh-agent. La key_identity puede ser un nombre de archivo o un valor derivado de la huella digital de la clave pública.
-e engine
Esto especifica un motor criptográfico a utilizar para las claves que se agregan usando la opción -s. La sintaxis es pkcs11-option:value, donde pkcs11-option es una opción conocida por el motor.
-L
Lista todas las claves que el agente puede usar para la autenticación. La salida es en el formato de archivo de clave pública de OpenSSH.
-l
Lista el fingerprint de todas las claves actualmente en el agente. Para los tipos de clave más antiguos, esta es la única forma de listar las claves. Para los tipos de clave más nuevos, -L puede ser más útil.
-q
Silencio después de una operación exitosa.
-S provider
Especifica una ruta a una biblioteca que se utilizará al agregar claves alojadas en un autenticador FIDO, reemplazando el valor predeterminado de usar soporte interno USB HID.
-s pkcs11
Agrega claves proporcionadas por la biblioteca compartida PKCS#11 pkcs11. Los archivos de certificado se pueden listar opcionalmente como argumentos de línea de comandos. Si están presentes, se cargarán en el agente utilizando las claves privadas correspondientes cargadas desde el token PKCS#11.
-T pubkey ...
Prueba si las claves privadas que corresponden a los archivos pubkey especificados son utilizables realizando operaciones de firma y verificación en cada una.
-t life
Establece una vida útil máxima al agregar identidades a un agente. La vida útil se puede especificar en segundos o en un formato de tiempo especificado en sshd_config(5).
-v
Modo verboso. Hace que ssh-add imprima mensajes de depuración sobre su progreso. Esto es útil para depurar problemas. Múltiples opciones -v aumentan la verbosidad. El máximo es 3.
-X
Desbloquea el agente.
-x
Bloquea el agente con una contraseña.

ENVIRONMENT

DISPLAY, SSH_ASKPASS y SSH_ASKPASS_REQUIRE
Si ssh-add necesita una frase de contraseña, leerá la frase de contraseña del terminal actual si se ejecutó desde un terminal. Si ssh-add no tiene un terminal asociado pero DISPLAY y SSH_ASKPASS están configurados, ejecutará el programa especificado por SSH_ASKPASS (por defecto “ssh-askpass”) y abrirá una ventana X11 para leer la frase de contraseña. Esto es particularmente útil al llamar a ssh-add desde un script .xsession o relacionado.

SSH_ASKPASS_REQUIRE permite un control adicional sobre el uso de un programa askpass. Si esta variable se establece en “never”, entonces ssh-add nunca intentará usar uno. Si se establece en “prefer”, entonces ssh-add preferirá usar el programa askpass en lugar del TTY al solicitar contraseñas. Finalmente, si la variable se establece en “force”, entonces el programa askpass se utilizará para toda la entrada de frase de contraseña, independientemente de si DISPLAY está configurado.

SSH_AUTH_SOCK
Identifica la ruta de un socket de dominio UNIX utilizado para comunicarse con el agente.
SSH_SK_PROVIDER
Especifica una ruta a una biblioteca que se utilizará al cargar claves alojadas en un autenticador FIDO, reemplazando el valor predeterminado de usar soporte interno USB HID.

FILES

~/.ssh/id_ecdsa
 
~/.ssh/id_ecdsa_sk
 
~/.ssh/id_ed25519
 
~/.ssh/id_ed25519_sk
 
~/.ssh/id_rsa
Contiene la identidad de autenticación ECDSA, ECDSA alojada en autenticador, Ed25519, Ed25519 alojada en autenticador o RSA del usuario.

Los archivos de identidad no deben ser legibles por nadie más que el usuario. Tenga en cuenta que ssh-add ignora los archivos de identidad si son accesibles por otros.

EXIT STATUS

El estado de salida es 0 si la operación es exitosa, 1 si el comando especificado falla, y 2 si ssh-add no puede contactar con el agente de autenticación.
