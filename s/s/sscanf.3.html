sscanf(3) Manual de funciones de biblioteca sscanf(3)

NOMBRE

sscanf, vsscanf - conversión de formato de entrada de cadena

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <stdio.h>
int sscanf(const char *restrict str,
           const char *restrict format, ...);
#include <stdarg.h>
int vsscanf(const char *restrict str,
           const char *restrict format, va_list ap);
Requisitos de Macro de Prueba de Funciones para glibc (ver feature_test_macros(7)):

vsscanf():

    _ISOC99_SOURCE || _POSIX_C_SOURCE >= 200112L

DESCRIPCIÓN

La familia de funciones sscanf() escanea la entrada con formato de acuerdo con format como se describe a continuación. Este formato puede contener especificaciones de conversión; los resultados de dichas conversiones, si los hay, se almacenan en las ubicaciones apuntadas por los argumentos puntero que siguen a format. Cada argumento puntero debe ser de un tipo apropiado para el valor devuelto por la especificación de conversión correspondiente.

Si el número de especificaciones de conversión en format excede el número de argumentos puntero, los resultados son indefinidos. Si el número de argumentos puntero excede el número de especificaciones de conversión, entonces los argumentos puntero excedentes se evalúan, pero por lo demás se ignoran.

sscanf() Estas funciones leen su entrada de la cadena apuntada por str.

La función vsscanf() es análoga a vsprintf(3).

La cadena format consiste en una secuencia de directivas que describen cómo procesar la secuencia de caracteres de entrada. Si el procesamiento de una directiva falla, no se lee más entrada, y sscanf() retorna. Un "fallo" puede ser cualquiera de los siguientes: fallo de entrada, lo que significa que no había caracteres de entrada disponibles, o fallo de coincidencia, lo que significa que la entrada era inapropiada (ver abajo).

Una directiva es una de las siguientes:

•
Una secuencia de caracteres de espacio en blanco (espacio, tabulación, nueva línea, etc.; ver isspace(3)). Esta directiva coincide con cualquier cantidad de espacio en blanco, incluyendo ninguno, en la entrada.
•
Un carácter ordinario (es decir, uno que no sea espacio en blanco o '%'). Este carácter debe coincidir exactamente con el siguiente carácter de la entrada.
•
Una especificación de conversión, que comienza con un carácter '%' (por ciento) o la secuencia de caracteres "%n$" (ver más abajo para la distinción) seguida por un carácter de conversión (ver más abajo).

Cada especificación de conversión en format comienza ya sea con el carácter '%' o con la secuencia de caracteres "%n$" (ver más abajo para la distinción) seguida por:

•
Un carácter opcional de supresión de asignación '*': sscanf() lee la entrada según lo dirigido por la especificación de conversión, pero descarta la entrada. No se requiere ningún argumento puntero correspondiente, y esta especificación no se incluye en el recuento de asignaciones exitosas devuelto por sscanf().
•
Para conversiones decimales, un carácter opcional de comilla ('). Esto especifica que el número de entrada puede incluir separadores de miles según lo definido por la categoría LC_NUMERIC de la configuración regional actual. (Ver setlocale(3)). El carácter de comilla puede preceder o seguir al carácter de supresión de asignación '*'.
•
Un carácter opcional 'm'. Esto se usa con conversiones de cadena (%s, %c, %[), y libera al llamador de la necesidad de asignar un búfer correspondiente para contener la entrada: en su lugar, sscanf() asigna un búfer de tamaño suficiente, y asigna la dirección de este búfer al argumento puntero correspondiente, que debería ser un puntero a una variable char * (esta variable no necesita inicializarse antes de la llamada). El llamador debe posteriormente free(3) este búfer cuando ya no sea necesario.
•
Un entero decimal opcional que especifica el ancho de campo máximo. La lectura de caracteres se detiene bien cuando se alcanza este máximo o cuando se encuentra un carácter no coincidente, lo que ocurra primero. La mayoría de las conversiones descartan los caracteres iniciales de espacio en blanco (se notan las excepciones), y estos caracteres descartados no cuentan para el ancho de campo máximo. Las conversiones de entrada de cadena almacenan un byte nulo terminador ('\0') para marcar el final de la entrada; el ancho de campo máximo no incluye este terminador.
•
Un carácter modificador de tipo opcional. Por ejemplo, el modificador de tipo l se usa con conversiones enteras como %d para especificar que el argumento puntero correspondiente se refiere a un long en lugar de un puntero a un int.
•
Un especificador de conversión que especifica el tipo de conversión de entrada que se realizará.

Las especificaciones de conversión en format son de dos formas, comenzando con '%' o comenzando con "%n$". Las dos formas no deben mezclarse en la misma cadena format, excepto que una cadena que contiene especificaciones "%n$" puede incluir %% y %*. Si format contiene especificaciones '%', entonces estas corresponden en orden con los argumentos puntero sucesivos. En la forma "%n$" (que se especifica en POSIX.1-2001, pero no en C99), n es un entero decimal que especifica que la entrada convertida debe colocarse en la ubicación a la que se refiere el n-ésimo argumento puntero después de format.

Conversiones

Los siguientes caracteres modificadores de tipo pueden aparecer en una especificación de conversión:

h
Indica que la conversión será una de d, i, o, u, x, X, o n, y el siguiente puntero es un puntero a short o unsigned short (en lugar de int).
hh
Como para h, pero el siguiente puntero es un puntero a signed char o unsigned char.
j
Como para h, pero el siguiente puntero es un puntero a intmax_t o uintmax_t. Este modificador se introdujo en C99.
l
Indica que la conversión será una de d, i, o, u, x, X, o n, y el siguiente puntero es un puntero a long o unsigned long (en lugar de int), o que la conversión será una de e, f, o g, y el siguiente puntero es un puntero a double (en lugar de float). Si se usa con %c o %s, el parámetro correspondiente se considera como un puntero a un carácter ancho o cadena de caracteres anchos, respectivamente.
ll
(elle-elle) Indica que la conversión será una de b, d, i, o, u, x, X, o n, y el siguiente puntero es un puntero a long long o unsigned long long (en lugar de int).
L
Indica que la conversión será e, f, o g, y el siguiente puntero es un puntero a long double o (como una extensión de GNU) la conversión será d, i, o, u, o x, y el siguiente puntero es un puntero a long long.
q
equivalente a L. Este especificador no existe en ANSI C.
t
Como para h, pero el siguiente puntero es un puntero a ptrdiff_t. Este modificador se introdujo en C99.

int sscanf(const char *str, const char *format,
...
);

int vscanf(const char *format, va_list args);

int vsscanf(const char *str, const char *format,
va_list args);

DESCRIPTION

The scanf(), fscanf(), and sscanf() functions read input from the standard input, a specified input stream, or a string, respectively. The format of the input is specified by format, which is a string that may contain:

  • One or more whitespace characters (space, tab, newline, etc.). In this case, the function reads and discards as many whitespace characters as possible until the next non-whitespace character.

  • One or more non-whitespace characters other than '%'. In this case, the function reads characters from the input until a non-whitespace character is encountered. If the next character in the input stream is different from the next character specified for the match, the function returns.

  • A conversion specification, which begins with a '%' character. This is followed by zero or more of the following characters, in the following order: an optional assignment-suppression character, an optional length modifier, and a conversion command character that indicates the type of conversion to be performed. Conversion specifications are described below.

All of the characters in format, except for whitespace characters and those beginning with '%', must match the corresponding non-whitespace characters in the input string. If the characters in format can be matched with characters from the input string, the input characters are consumed. If the characters cannot be matched, or if there is a mismatch between the expected input type for a conversion specification and the input, the function returns.

The functions vfscanf(), vscanf(), and vsscanf() are equivalent to their corresponding non-v functions, except that instead of variable argument list, they accept a parameter of type va_list, which must have been initialized using the va_start(3) macro (or va_copy(3)). This allows the functions to be used by code that also needs to process a variable argument list, such as a general-purpose function that needs to call scanf().

The assignment-suppression character is '*'

When this character follows a '%' character, the input field is read but is not assigned to any argument or returned by the function. The assignment-suppression character, if present, must appear immediately after the '%' character.

The length modifiers are:

h
Specifies that a following conversion command and a next argument point to type short int (for integer conversions) or float (for floating-point conversions). As of C99, this is specified to apply to integer conversions only.
l
Specifies that a following conversion command and a next argument point to type long int or unsigned long int (for integer conversions), or double (for floating-point conversions). As of C99, this is specified to apply to integer conversions only.
L
Specifies that a following conversion command and a next argument point to type long double (for floating-point conversions).
q
As for h, but the next pointer is a pointer to a long long int. This modifier was introduced in C99. (This is a GNU extension.)
ll
As for h, but the next pointer is a pointer to a size_t. This modifier was introduced in C99.

The following conversion specifiers are available:

%
Matches a literal '%'. That is, %% in the format string matches a single input '%' character. No conversion is done (but initial white space characters are discarded), and assignment does not occur.
d
Matches an optionally signed decimal integer; the next pointer must be a pointer to int.
i
Matches an optionally signed integer; the next pointer must be a pointer to int. The integer is read in base 16 if it begins with 0x or 0X, in base 8 if it begins with 0, and in base 10 otherwise. Only characters that correspond to the base are used.
o
Matches an unsigned octal integer; the next pointer must be a pointer to unsigned int.
u
Matches an unsigned decimal integer; the next pointer must be a pointer to unsigned int.
x
Matches an unsigned hexadecimal integer (that may optionally begin with a prefix of 0x or 0X, which is discarded); the next pointer must be a pointer to unsigned int.
X
Equivalent to x.
f
Matches an optionally signed floating-point number; the next pointer must be a pointer to float.
e
Equivalent to f.
g
Equivalent to f.
E
Equivalent to f.
a
(C99) Equivalent to f.
s
Matches a sequence of non-white-space characters; the next pointer must be a pointer to the initial element of a character array that is long enough to hold the input sequence and the terminating null byte ('\0'), which is added automatically. The input string stops at white space or at the maximum field width, whichever occurs first.
c
Matches a sequence of characters whose length is specified by the maximum field width (default 1); the next pointer must be a pointer to char, and there must be enough room for all the characters (no terminating null byte is added). The usual skip of leading white space is suppressed. To skip white space first, use an explicit space in the format.
[
Matches a nonempty sequence of characters from the specified set of accepted characters; the next pointer must be a pointer to char, and there must be enough room for all the characters in the string, plus a terminating null byte. The usual skip of leading white space is suppressed. The string is to be made up of characters in (or not in) a particular set; the set is defined by the characters between the open bracket [ character and a close bracket ] character. The set excludes those characters if the first character after the open bracket is a circumflex (^). To include a close bracket in the set, make it the first character after the open bracket or the circumflex; any other position will end the set. The hyphen character - is also special; when placed between two other characters, it adds all intervening characters to the set. To include a hyphen, make it the last character before the final close bracket. For instance, [^]0-9-] means the set "everything except close bracket, zero through nine, and hyphen". The string ends with the appearance of a character not in the (or, with a circumflex, in) set or when the field width runs out.
p
Matches a pointer value (as printed by %p in printf(3)); the next pointer must be a pointer to a pointer to void.
n
Nothing is expected; instead, the number of characters consumed thus far from the input is stored through the next pointer, which must be a pointer to int, or variant whose size matches the (optionally) supplied integer length modifier. This is not a conversion and does not increase the count returned by the function. The assignment can be suppressed with the * assignment-suppression character, but the effect on the return value is undefined. Therefore %*n conversions should not be used.

RETURN VALUE

On success, these functions return the number of input items successfully matched and assigned; this can be fewer than provided for, or even zero, in the event of an early matching failure.

The value EOF is returned if the end of input is reached before either the first successful conversion or a matching failure occurs.

ERRORS

EILSEQ
Input byte sequence does not form a valid character.
EINVAL
Not enough arguments; or format is NULL.
ENOMEM
Out of memory.

STANDARDS

HISTORY

C89, POSIX.1-2001.

The q specifier is the 4.4BSD notation for long long, while ll or the usage of L in integer conversions is the GNU notation.

The Linux version of these functions is based on the GNU libio library. Take a look at the info(1) documentation of GNU libc (glibc-1.08) for a more concise description.

NOTES

The 'a' assignment-allocation modifier

Originally, the GNU C library supported dynamic allocation for string inputs (as a nonstandard extension) via the a character. (This feature is present at least as far back as glibc 2.0.) Thus, one could write the following to have sscanf() allocate a buffer for a string, with a pointer to that buffer being returned in *buf:


char *buf;
sscanf(str, "%as", &buf);

The use of the letter a for this purpose was problematic, since a is also specified by the ISO C standard as a synonym for f (floating-point input). POSIX.1-2008 instead specifies the m modifier for assignment allocation (as documented in DESCRIPTION, above).

Note that the a modifier is not available if the program is compiled with gcc -std=c99 or gcc -D_ISOC99_SOURCE (unless _GNU_SOURCE is also specified), in which case the a is interpreted as a specifier for floating-point numbers (see above).

Support for the m modifier was added to glibc 2.7, and new programs should use that modifier instead of a.

As well as being standardized by POSIX, the m modifier has the following further advantages over the use of a:

•
It may also be applied to %c conversion specifiers (e.g., %3mc).
•
It avoids ambiguity with respect to the %a floating-point conversion specifier (and is unaffected by gcc -std=c99 etc.).

BUGS

Numeric conversion specifiers

Use of the numeric conversion specifiers produces undefined behavior for invalid input. See C11 7.21.6.2/10. This is a bug in the ISO C standard, and not an inherent design issue with the API. However, current implementations are not safe from that bug, so it is not recommended to use them. Instead, programs should use functions such as strtol(3) to parse numeric input. Alternatively, mitigate it by specifying a maximum field width.

Nonstandard modifiers

These functions are fully C99 conformant, but provide the additional modifiers q and a as well as an additional behavior of the L and ll modifiers. The latter may be considered to be a bug, as it changes the behavior of modifiers defined in C99.

Some combinations of the type modifiers and conversion specifiers defined by C99 do not make sense (e.g., %Ld). While they may have a well-defined behavior on Linux, this need not to be so on other systems. Therefore it usually is better to use modifiers that are not defined by C99 at all, that is, use q instead of L in combination with d, i, o, u, x, and X conversions or ll.

The usage of q is not the same as on 4.4BSD, as it may be used in float conversions equivalently to L.

EXAMPLES

To use the dynamic allocation conversion specifier, specify m as a length modifier (thus %ms or %m[range]). El llamador debe usar free(3) para liberar la cadena devuelta, como se muestra en el siguiente ejemplo:


char *p;
int n;
errno = 0;
n = sscanf(str, "%m[a-z]", &p);
if (n == 1) {
    printf("leído: %s\n", p);
    free(p);
} else if (errno != 0) {
    perror("sscanf");
} else {
    fprintf(stderr, "No se encontraron caracteres coincidentes\n");
}

Como se muestra en el ejemplo anterior, es necesario llamar a free(3) solo si la llamada a sscanf() leyó correctamente una cadena.
