SSTPC(8) Manual del Administrador del Sistema SSTPC(8)

NOMBRE

sstpc - Cliente SSTP

SINOPSIS

sstpc [<opciones-sstp>] <nombre-host> [opciones-ppp] ...

DESCRIPCIÓN

sstpc establece el lado del cliente de una Red Privada Virtual (VPN) utilizando el Protocolo de Túnel Seguro de Socket (SSTP). Utilice este programa para conectarse a una VPN basada en SSTP de su empleador cuando PPTP y L2TP no funcionen.

Por defecto, sstpc establece la llamada SSTP al servidor SSTP, y luego inicia una instancia de pppd para gestionar la transferencia de datos. Sin embargo, sstpc también puede ejecutarse como un gestor de conexión dentro de pppd.

OPCIONES

El primer argumento que no sea una opción en la línea de comandos de sstpc debe ser el nombre del host o la dirección IP del servidor SSTP.

Todas las opciones largas (que comienzan con "--") se interpretan como opciones de sstpc, y se produce un error fatal si se utiliza una opción no reconocida.

Todos los argumentos de línea de comandos que no comienzan con "-" se interpretan como opciones de ppp y se pasan tal cual a pppd a menos que se proporcione --nolaunchpppd.

--ca-cert
Especifica el certificado CA utilizado para verificar el servidor con
--ca-dir
Especifica el directorio de certificados que contiene el certificado CA. Si no se especifica nada, se utiliza el directorio general del sistema.
--cert-warn
Ignora las advertencias del certificado como el nombre común en lugar de terminar la conexión.
--host
Al conectarse a una dirección IP, el parámetro host proporcionará el nombre del host para http, proxy y tls-ext
--ipparam
Esto ayudará a especificar el socket de devolución de llamada al que pppd intentará conectarse de nuevo a sstpc para comunicar las claves MPPE según lo negociado. Las claves MPPE son necesarias para autenticarse contra el servidor en la capa SSL. Se pueden poner a cero si no se negoció MPPE. El nombre se forma basándose en /tmp/sstpc-<ipparam>.
--nolaunchpppd
No inicie pppd sino que utilice stdin como la conexión de red. Use esta bandera cuando incluya sstpc como un proceso de conexión de pppd utilizando la opción pty. Ver EJEMPLOS.
--password
Especifique una contraseña por línea de comandos en lugar de configurarla en un archivo de configuración para pppd en /etc/ppp/peers.
--proxy
Conéctese al servidor SSTP a través de un proxy en su red. La sintaxis es http://[<usuario>:<contraseña>@]<dominio>:puerto.
--priv-user
Especifique el usuario de separación de privilegios para ejecutar sstpc
--priv-group
Especifique el grupo de separación de privilegios para ejecutar sstpc
--priv-dir
Especifique el directorio de separación de privilegios para la cárcel chroot donde ejecutar sstpc
--user
Especifique el nombre de usuario para autenticarse en el servidor SSTP en lugar de configurarlo en un archivo de configuración para pppd en /etc/ppp/peers.
--save-server-route
Esto añadirá y eliminará automáticamente una ruta al servidor SSTP.
--uuid
Especifique un UUID para la conexión para simplificar la depuración en el lado del servidor.
--tls-ext
Esto habilitará la extensión de nombre de host TLS.

Solución de problemas

Las siguientes opciones están disponibles para ayudar a depurar sstpc

--log-level <nivel>
Establece el nivel de depuración para depurar el proceso sstpc. El nivel puede ser un valor entre 0 y 4.
--log-syslog
Registra mensajes en syslog (por defecto).
--log-stderr
Registra mensajes en la salida de error
--log-stdout
Registra mensajes en la salida estándar
--log-fileno
Incluye el número de archivo y línea con los mensajes de registro
--log-filter
Filtra los registros por un conjunto particular de archivos, por ejemplo: sstp-packet,sstp-state
--log-ident
Especifica la identidad que se utilizará al escribir registros en, por ejemplo, syslog

EJEMPLOS

Conexión a un servicio RAS de Microsoft Windows utilizando el protocolo SSTP

Configurar los scripts de par en /etc/ppp/peers, puede comenzar clonando uno de los scripts disponibles en su directorio de documentación, /usr/share/doc/sstp-client, o /usr/local/share/doc/sstp-client. El contenido general de este archivo será similar a lo siguiente:
# Contenido de ejemplo de /etc/ppp/peers/sstp-test
remotename sstp-test
linkname sstp-test
ipparam sstp-test
pty "sstpc --ipparam sstp-test --nolaunchpppd sstp-test.sudominio.com"
name eivnaes
plugin sstp-pppd-plugin.so
sstp-sock /var/run/sstpc/sstpc-sstp-test
usepeerdns
require-mppe
require-mschap-v2
refuse-eap
refuse-pap
refuse-chap
refuse-mschap
nobsdcomp
nodeflate
Tenga en cuenta que el archivo chap-secrets utilizado por pppd debe incluir una entrada para dominio\\nombre de usuario. Para el ejemplo sstp-test, el usuario eivnaes tendrá una entrada equivalente en el archivo /etc/ppp/chap-secrets.

# Secretos para autenticación usando CHAP
# cliente servidor secreto direcciones IP
eivnaes * xxxxxxx *

Iniciar sstp-test usando el script pon
sudo pon sstp-test
Invocar sstpc usando el comando call
sstpc --ipparam sstp-test sstp-test.sudominio.com call sstp-test-nopty
El sstp-test-nopty es un script de pppd que necesita crear en /etc/ppp/peers, y puede clonar el ejemplo sstp-test anterior; pero debe omitir la declaración pty en la configuración de pares.
