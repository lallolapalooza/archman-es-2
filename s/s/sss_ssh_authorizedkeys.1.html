NOMBRE

sss_ssh_authorizedkeys - obtener claves autorizadas de OpenSSH

SINOPSIS

sss_ssh_authorizedkeys [opciones] USUARIO

DESCRIPCIÓN

sss_ssh_authorizedkeys adquiere las claves públicas SSH para el usuario USUARIO y las muestra en formato authorized_keys de OpenSSH (consulte la sección "FORMATO DEL ARCHIVO AUTHORIZED_KEYS" de sshd(8) para más información).

sshd(8) se puede configurar para utilizar sss_ssh_authorizedkeys para la autenticación de usuarios mediante claves públicas si se compila con soporte para la opción "AuthorizedKeysCommand". Consulte la página del manual de sshd_config(5) para más detalles sobre esta opción.

Si se soporta "AuthorizedKeysCommand", sshd(8) se puede configurar para usarla añadiendo las siguientes directivas en sshd_config(5):

  AuthorizedKeysCommand /usr/bin/sss_ssh_authorizedkeys
  AuthorizedKeysCommandUser nobody

CLAVES DE CERTIFICADOS

Además de las claves públicas SSH para el usuario USUARIO, sss_ssh_authorizedkeys puede devolver claves públicas SSH derivadas de la clave pública de un certificado X.509.

Para habilitar esto, la opción "ssh_use_certificate_keys" debe establecerse en true (por defecto) en la sección [ssh] de sssd.conf. Si la entrada del usuario contiene certificados (ver "ldap_user_certificate" en sssd-ldap(5) para detalles) o hay un certificado en una entrada de anulación para el usuario (ver sss_override(8) o sssd-ipa(5) para detalles) y el certificado es válido, SSSD extraerá la clave pública del certificado y la convertirá al formato esperado por sshd.

Además de "ssh_use_certificate_keys", las opciones

•ca_db
•p11_child_timeout
•certificate_verification

se pueden usar para controlar cómo se validan los certificados (ver sssd.conf(5) para detalles).

La validación es el beneficio de usar certificados X.509 en lugar de claves SSH directamente, ya que, por ejemplo, da un mejor control sobre la vida útil de las claves. Cuando el cliente ssh está configurado para usar las claves privadas de una Smartcard con la ayuda de una biblioteca compartida PKCS#11 (ver ssh(1) para detalles), puede ser molesto que la autenticación siga funcionando incluso si el certificado X.509 relacionado en la Smartcard ya está caducado porque ni ssh ni sshd mirarán el certificado.

Cabe señalar que la clave pública SSH derivada todavía se puede añadir al archivo authorized_keys del usuario para eludir la validación del certificado si la configuración de sshd lo permite.

OPCIONES

-d,--domain DOMINIO

Busca claves públicas de usuario en el dominio SSSD DOMINIO.

-?,--help

Muestra el mensaje de ayuda y sale.

ESTADO DE SALIDA

En caso de éxito, se devuelve un valor de salida de 0. En caso contrario, se devuelve 1.
