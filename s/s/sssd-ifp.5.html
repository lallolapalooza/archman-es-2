NOMBRE

sssd-ifp - Responsable InfoPipe de SSSD

DESCRIPCIÓN

Esta página del manual describe la configuración del responsable InfoPipe para sssd(8). Para una referencia detallada de la sintaxis, consulte la sección “FORMATO DE ARCHIVO” de la página del manual de sssd.conf(5).

El responsable InfoPipe proporciona una interfaz pública de D-Bus accesible a través del bus del sistema. La interfaz permite al usuario consultar información sobre usuarios y grupos remotos a través del bus del sistema.

BUSCAR POR CERTIFICADO VÁLIDO

Las siguientes opciones se pueden utilizar para controlar cómo se validan los certificados al usar la API FindByValidCertificate():

•ca_db
•p11_child_timeout
•certificate_verification

Para más detalles sobre las opciones, consulte sssd.conf(5).

OPCIONES DE CONFIGURACIÓN

Estas opciones se pueden utilizar para configurar el responsable InfoPipe.

allowed_uids (cadena)

Especifica la lista separada por comas de valores UID o nombres de usuario que tienen permitido acceder al responsable InfoPipe. Los nombres de usuario se resuelven a UID al inicio.

Por defecto: 0 (solo el usuario root tiene permitido acceder al responsable InfoPipe)

Tenga en cuenta que aunque el UID 0 se usa por defecto, será sobrescrito con esta opción. Si aún desea permitir que el usuario root acceda al responsable InfoPipe, lo cual sería el caso típico, debe agregar 0 a la lista de UID permitidos también.

user_attributes (cadena)

Especifica la lista separada por comas de atributos en lista blanca o negra.

Por defecto, el responsable InfoPipe solo permite solicitar el conjunto predeterminado de atributos POSIX. Este conjunto es el mismo que devuelve getpwnam(3) e incluye:

name

nombre de inicio de sesión del usuario

uidNumber

ID de usuario

gidNumber

ID de grupo primario

gecos

información del usuario, típicamente nombre completo

homeDirectory

directorio principal

loginShell

shell del usuario

Es posible agregar otro atributo a este conjunto usando “+nombre_atributo” o eliminar explícitamente un atributo usando “-nombre_atributo”. Por ejemplo, para permitir “telephoneNumber” pero denegar “loginShell”, usaría la siguiente configuración:

user_attributes = +telephoneNumber, -loginShell

Por defecto: no establecido. Solo se permite el conjunto predeterminado de atributos POSIX.

wildcard_limit (entero)

Especifica un límite superior en el número de entradas que se descargan durante una búsqueda de comodín que anula el límite proporcionado por el llamador.

Por defecto: 0 (permite que el llamador establezca un límite superior)
