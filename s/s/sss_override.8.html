NOMBRE

sss_override - crear anulaciones locales de atributos de usuario y grupo

SINOPSIS

sss_override COMANDO [opciones]

DESCRIPCIÓN

sss_override permite crear una vista del lado del cliente y permite cambiar valores seleccionados de usuarios y grupos específicos. Este cambio solo tiene efecto en la máquina local.

Los datos de anulación se almacenan en la caché de SSSD. Si se elimina la caché, se pierden todas las anulaciones locales. Tenga en cuenta que después de crear la primera anulación mediante cualquiera de los siguientes comandos user-add, group-add, user-import o group-import. Es necesario reiniciar SSSD para que surta efecto. sss_override muestra un mensaje cuando se requiere un reinicio.

NOTA: Las opciones proporcionadas en esta página del manual solo funcionan con el “id_provider” “ldap” y “AD”. Las anulaciones de IPA se pueden administrar de forma centralizada en el servidor IPA.

COMANDOS DISPONIBLES

NOMBRE es el nombre del objeto original en todos los comandos. No es posible anular uid o gid a 0.

user-add NOMBRE [-n,--name NOMBRE] [-u,--uid UID] [-g,--gid GID] [-h,--home HOME] [-s,--shell SHELL] [-c,--gecos GECOS] [-x,--certificate CERTIFICADO CODIFICADO EN BASE64]

Anula los atributos de un usuario. Tenga en cuenta que llamar a este comando reemplazará cualquier anulación anterior para el usuario (con NOMBRE).

user-del NOMBRE

Elimina las anulaciones de usuario. Sin embargo, tenga en cuenta que los atributos anulados podrían ser devueltos de la caché de memoria. Consulte la opción de SSSD memcache_timeout para más detalles.

user-find [-d,--domain DOMINIO]

Lista todos los usuarios con anulaciones establecidas. Si se establece el parámetro DOMINIO, solo se listan los usuarios del dominio.

user-show NOMBRE

Muestra las anulaciones de usuario.

user-import ARCHIVO

Importa las anulaciones de usuario desde ARCHIVO. El formato de los datos es similar al archivo passwd estándar. El formato es:

nombre_original:nombre:uid:gid:gecos:home:shell:certificado_codificado_en_base64

donde nombre_original es el nombre original del usuario cuyos atributos deben ser anulados. El resto de los campos corresponden a los nuevos valores. Puede omitir un valor simplemente dejando el campo correspondiente vacío.

Ejemplos:

ckent:superman::::::

ckent@krypton.com::501:501:Superman:/home/earth:/bin/bash:

user-export ARCHIVO

Exporta todos los atributos anulados y los almacena en ARCHIVO. Consulte user-import para el formato de datos.

group-add NOMBRE [-n,--name NOMBRE] [-g,--gid GID]

Anula los atributos de un grupo. Tenga en cuenta que llamar a este comando reemplazará cualquier anulación anterior para el grupo (con NOMBRE).

group-del NOMBRE

Elimina las anulaciones de grupo. Sin embargo, tenga en cuenta que los atributos anulados podrían ser devueltos de la caché de memoria. Consulte la opción de SSSD memcache_timeout para más detalles.

group-find [-d,--domain DOMINIO]

Lista todos los grupos con anulaciones establecidas. Si se establece el parámetro DOMINIO, solo se listan los grupos del dominio.

group-show NOMBRE

Muestra las anulaciones de grupo.

group-import ARCHIVO

Importa las anulaciones de grupo desde ARCHIVO. El formato de los datos es similar al archivo group estándar. El formato es:

nombre_original:nombre:gid

donde nombre_original es el nombre original del grupo cuyos atributos deben ser anulados. El resto de los campos corresponden a los nuevos valores. Puede omitir un valor simplemente dejando el campo correspondiente vacío.

Ejemplos:

admins:administrators:

Domain Users:Users:501

group-export ARCHIVO

Exporta todos los atributos anulados y los almacena en ARCHIVO. Consulte group-import para el formato de datos.

OPCIONES COMUNES

Esas opciones están disponibles con todos los comandos.

--debug NIVEL

SSSD admite dos representaciones para especificar el nivel de depuración. La más simple es especificar un valor decimal de 0 a 9, que representa habilitar ese nivel y todos los mensajes de depuración de niveles inferiores. La opción más completa es especificar una máscara de bits hexadecimal para habilitar o deshabilitar niveles específicos (como si desea suprimir un nivel).

Niveles de depuración admitidos actualmente:

0, 0x0010: Fallos fatales. Cualquier cosa que impida que SSSD se inicie o haga que deje de ejecutarse.

1, 0x0020: Fallos críticos. Un error que no mata a SSSD, pero uno que indica que al menos una función importante no funcionará correctamente.

2, 0x0040: Fallos graves. Un error que anuncia que una solicitud u operación particular ha fallado.

3, 0x0080: Fallos menores. Estos son los errores que se propagarían hacia abajo para causar el fallo de operación de 2.

4, 0x0100: Configuraciones.

5, 0x0200: Datos de función.

6, 0x0400: Mensajes de rastreo para funciones de operación.

7, 0x1000: Mensajes de rastreo para funciones de control interno.

8, 0x2000: Contenido de variables internas de la función que pueden ser interesantes.

9, 0x4000: Información de rastreo de nivel muy bajo.

10, 0x10000: Información de rastreo libldb de nivel aún más bajo. Casi nunca es realmente necesario.

Para registrar los niveles de depuración requeridos por máscara de bits, simplemente sume sus números como se muestra en los siguientes ejemplos:

Ejemplo: Para registrar fallos fatales, fallos críticos, fallos graves y datos de función, use 0x0270.

Ejemplo: Para registrar fallos fatales, configuraciones, datos de función, mensajes de rastreo para funciones de control interno, use 0x1310.

Nota: El formato de máscara de bits de los niveles de depuración se introdujo en la versión 1.7.0.

Predeterminado: 0x0070 (es decir, fallos fatales, críticos y graves; corresponde a establecer 2 en notación decimal)

sss_override(8)

The sssd-utils package provides the sss_override utility. This utility can be used to manage override entries in SSSD. Override entries allow administrators to specify custom user attributes, group memberships, or even entire user/group records that override the information obtained from the identity provider.

NOMBRE

sss_override - Herramienta para gestionar entradas de anulación de SSSD

SINOPSIS

sss_override [options] <command> [command-specific options]

DESCRIPCIÓN

sss_override es una herramienta de línea de comandos para gestionar las entradas de anulación en el servicio SSSD (System Security Services Daemon). Las entradas de anulación permiten a los administradores modificar o reemplazar la información de usuarios y grupos que SSSD obtiene de los proveedores de identidad (como LDAP o Kerberos).

Esto es útil en escenarios donde se necesita personalizar información para usuarios o grupos específicos sin tener que modificar los datos en el sistema de origen. Por ejemplo, puede utilizar las anulaciones para:

  • Añadir o modificar atributos de usuario (p. ej., GECOS, shell, directorio home).
  • Establecer membresías de grupo personalizadas.
  • Crear entradas de usuario o grupo ficticias para propósitos de prueba o configuración.

Las entradas de anulación se almacenan en un archivo de configuración específico (normalmente en /etc/sssd/sssd.conf bajo la sección [nss], utilizando las opciones user_overrides_file y group_overrides_file). sss_override interactúa con estas anulaciones, permitiendo añadir, eliminar, listar o modificar entradas.

COMANDOS DISPONIBLES

Los comandos disponibles para sss_override incluyen:

user-add
Añade una nueva entrada de anulación de usuario.
user-del
Elimina una entrada de anulación de usuario.
user-mod
Modifica una entrada de anulación de usuario existente.
user-list
Lista todas las entradas de anulación de usuario.
group-add
Añade una nueva entrada de anulación de grupo.
group-del
Elimina una entrada de anulación de grupo.
group-mod
Modifica una entrada de anulación de grupo existente.
group-list
Lista todas las entradas de anulación de grupo.
group-mem-add
Añade un miembro a un grupo en una entrada de anulación de grupo.
group-mem-del
Elimina un miembro de un grupo en una entrada de anulación de grupo.

OPCIONES COMUNES

Aunque los detalles específicos de las opciones dependen del comando utilizado, algunas opciones generales que pueden estar disponibles incluyen:

-f, --force
Forzar la operación sin pedir confirmación.
-d, --debug
Activar la salida de depuración.
-h, --help
Mostrar mensaje de ayuda.

Para detalles sobre las opciones específicas de cada comando, consulte la documentación de sss_override o ejecute el comando con la opción --help.
