SSHD_CONFIG(5) Manual de Formatos de Archivo SSHD_CONFIG(5)

NOMBRE

sshd_config — archivo de configuración del demonio OpenSSH

DESCRIPCIÓN

sshd(8) lee datos de configuración de /etc/ssh/sshd_config (o el archivo especificado con -f en la línea de comandos). El archivo contiene pares palabra clave-argumento, uno por línea. A menos que se indique lo contrario, para cada palabra clave, se utilizará el primer valor obtenido. Las líneas que comienzan con ‘#’ y las líneas vacías se interpretan como comentarios. Los argumentos pueden ir opcionalmente entre comillas dobles (") para representar argumentos que contienen espacios.

Las palabras clave posibles y sus significados son las siguientes (tenga en cuenta que las palabras clave no distinguen entre mayúsculas y minúsculas, y los argumentos sí distinguen entre mayúsculas y minúsculas):

AcceptEnv
Especifica qué variables de entorno enviadas por el cliente se copiarán en el environ(7) de la sesión. Vea SendEnv y SetEnv en ssh_config(5) para saber cómo configurar el cliente. La variable de entorno TERM siempre se acepta cuando el cliente solicita un pseudoterminal, ya que es requerida por el protocolo. Las variables se especifican por nombre, que puede contener los caracteres comodín ‘*’ y ‘?’. Varias variables de entorno pueden separarse por espacios en blanco o distribuirse en varias directivas AcceptEnv. Tenga cuidado, ya que algunas variables de entorno podrían usarse para eludir entornos de usuario restringidos. Por esta razón, se debe tener cuidado en el uso de esta directiva. El valor predeterminado es no aceptar ninguna variable de entorno.
AddressFamily
Especifica qué familia de direcciones debe ser utilizada por sshd(8). Los argumentos válidos son any (el valor predeterminado), inet (usar solo IPv4) o inet6 (usar solo IPv6).
AllowAgentForwarding
Especifica si se permite el reenvío de ssh-agent(1). El valor predeterminado es yes. Tenga en cuenta que deshabilitar el reenvío de agentes no mejora la seguridad a menos que los usuarios también tengan denegado el acceso al shell, ya que siempre pueden instalar sus propios reenviadores.
AllowGroups
Esta palabra clave puede ir seguida de una lista de patrones de nombres de grupo, separados por espacios. Si se especifica, el inicio de sesión solo se permite para usuarios cuyo grupo principal o lista de grupos suplementarios coincida con uno de los patrones. Solo son válidos los nombres de grupo; no se reconoce un ID de grupo numérico. Por defecto, el inicio de sesión se permite para todos los grupos. Las directivas allow/deny de grupos se procesan en el siguiente orden: DenyGroups, AllowGroups.

Vea PATTERNS en ssh_config(5) para más información sobre patrones. Esta palabra clave puede aparecer varias veces en sshd_config, y cada instancia se añade a la lista.

AllowStreamLocalForwarding
Especifica si se permite el reenvío StreamLocal (socket de dominio Unix). Las opciones disponibles son yes (el valor predeterminado) o all para permitir el reenvío StreamLocal, no para impedir todo reenvío StreamLocal, local para permitir solo el reenvío local (desde la perspectiva de ssh(1)) o remote para permitir solo el reenvío remoto. Tenga en cuenta que deshabilitar el reenvío StreamLocal no mejora la seguridad a menos que los usuarios también tengan denegado el acceso al shell, ya que siempre pueden instalar sus propios reenviadores.
AllowTcpForwarding
Especifica si se permite el reenvío TCP. Las opciones disponibles son yes (el valor predeterminado) o all para permitir el reenvío TCP, no para impedir todo reenvío TCP, local para permitir solo el reenvío local (desde la perspectiva de ssh(1)) o remote para permitir solo el reenvío remoto. Tenga en cuenta que deshabilitar el reenvío TCP no mejora la seguridad a menos que los usuarios también tengan denegado el acceso al shell, ya que siempre pueden instalar sus propios reenviadores.
AllowUsers
Esta palabra clave puede ir seguida de una lista de patrones de nombres de usuario, separados por espacios. Si se especifica, el inicio de sesión solo se permite para nombres de usuario que coincidan con uno de los patrones. Solo son válidos los nombres de usuario; no se reconoce un ID de usuario numérico. Por defecto, el inicio de sesión se permite para todos los usuarios. Si el patrón toma la forma USER@HOST, entonces USER y HOST se verifican por separado, restringiendo los inicios de sesión a usuarios particulares desde hosts particulares. Los criterios de HOST pueden contener además direcciones para coincidir en formato CIDR de dirección/máscara. Las directivas allow/deny de usuarios se procesan en el siguiente orden: DenyUsers, AllowUsers.

Vea PATTERNS en ssh_config(5) para más información sobre patrones. Esta palabra clave puede aparecer varias veces en sshd_config, y cada instancia se añade a la lista.

AuthenticationMethods
Especifica los métodos de autenticación que deben completarse exitosamente para que se conceda acceso a un usuario. Esta opción debe ir seguida de una o más listas de nombres de métodos de autenticación separados por comas, o por la cadena única any para indicar el comportamiento predeterminado de aceptar cualquier método de autenticación individual. Si se anula el valor predeterminado, la autenticación exitosa requiere la finalización de cada método en al menos una de estas listas.

Por ejemplo, "publickey,password publickey,keyboard-interactive" requeriría que el usuario complete la autenticación de clave pública, seguida de autenticación por contraseña o interactiva de teclado. Solo los métodos que siguen en una o más listas se ofrecen en cada etapa, por lo que para este ejemplo no sería posible intentar la autenticación por contraseña o interactiva de teclado antes de la clave pública.

Para la autenticación interactiva de teclado, también es posible restringir la autenticación a un dispositivo específico añadiendo dos puntos seguidos del identificador del dispositivo bsdauth o pam, dependiendo de la configuración del servidor. Por ejemplo, "keyboard-interactive:bsdauth" restringiría la autenticación interactiva de teclado al dispositivo bsdauth.

Si el método publickey aparece más de una vez, sshd(8) verifica que las claves que se han utilizado con éxito no se reutilizan para autenticaciones posteriores. Por ejemplo, "publickey,publickey" requiere autenticación exitosa utilizando dos claves públicas diferentes.

Tenga en cuenta que cada método de autenticación listado debe también habilitarse explícitamente en la configuración.

Los métodos de autenticación disponibles son: "gssapi-with-mic", "hostbased", "keyboard-interactive", "none" (utilizado para el acceso a cuentas sin contraseña cuando PermitEmptyPasswords está habilitado), "password" y "publickey".

AuthorizedKeysCommand
Especifica un programa que se utilizará para buscar las claves públicas del usuario. El programa debe ser propiedad de root, no escribible por el grupo o por otros, y especificarse con una ruta absoluta. Los argumentos para AuthorizedKeysCommand aceptan la
tokens descritos en la sección TOKENS. Si no se especifican argumentos, se utiliza el nombre de usuario del usuario de destino.

El programa debería producir en la salida estándar cero o más líneas de salida de authorized_keys (consulte AUTHORIZED_KEYS en sshd(8)). AuthorizedKeysCommand se prueba después de los archivos habituales de AuthorizedKeysFile y no se ejecutará si se encuentra una clave coincidente allí. Por defecto, no se ejecuta ningún AuthorizedKeysCommand.

AuthorizedKeysCommandUser
Especifica el usuario bajo cuya cuenta se ejecuta el AuthorizedKeysCommand. Se recomienda utilizar un usuario dedicado que no tenga otra función en el host más que ejecutar comandos de claves autorizadas. Si se especifica AuthorizedKeysCommand pero no AuthorizedKeysCommandUser, entonces sshd(8) se negará a iniciar.
AuthorizedKeysFile
Especifica el archivo que contiene las claves públicas utilizadas para la autenticación de usuarios. El formato se describe en la sección FORMATO DEL ARCHIVO AUTHORIZED_KEYS de sshd(8). Los argumentos para AuthorizedKeysFile pueden incluir comodines y aceptan los tokens descritos en la sección TOKENS. Después de la expansión, AuthorizedKeysFile se considera una ruta absoluta o una relativa al directorio de inicio del usuario. Se pueden listar varios archivos, separados por espacios. Alternativamente, esta opción se puede establecer en none para omitir la verificación de claves de usuario en archivos. El valor predeterminado es ".ssh/authorized_keys .ssh/authorized_keys2".
AuthorizedPrincipalsCommand
Especifica un programa que se utilizará para generar la lista de principales de certificado permitidos según AuthorizedPrincipalsFile. El programa debe ser propiedad de root, no escribible por grupo ni por otros, y especificarse mediante una ruta absoluta. Los argumentos para AuthorizedPrincipalsCommand aceptan los tokens descritos en la sección TOKENS. Si no se especifican argumentos, se utiliza el nombre de usuario del usuario de destino.

El programa debe producir en la salida estándar cero o más líneas de salida de AuthorizedPrincipalsFile. Si se especifica AuthorizedPrincipalsCommand o AuthorizedPrincipalsFile, entonces los certificados ofrecidos por el cliente para la autenticación deben contener un principal que esté listado. Por defecto, no se ejecuta ningún AuthorizedPrincipalsCommand.

AuthorizedPrincipalsCommandUser
Especifica el usuario bajo cuya cuenta se ejecuta el AuthorizedPrincipalsCommand. Se recomienda utilizar un usuario dedicado que no tenga otra función en el host más que ejecutar comandos de principales autorizados. Si se especifica AuthorizedPrincipalsCommand pero no AuthorizedPrincipalsCommandUser, entonces sshd(8) se negará a iniciar.
AuthorizedPrincipalsFile
Especifica un archivo que lista los nombres de principales que se aceptan para la autenticación de certificados. Al utilizar certificados firmados por una clave listada en TrustedUserCAKeys, este archivo lista nombres, uno de los cuales debe aparecer en el certificado para que sea aceptado para la autenticación. Los nombres se listan uno por línea precedidos por opciones de clave (como se describe en el FORMATO DEL ARCHIVO AUTHORIZED_KEYS en sshd(8)). Las líneas vacías y los comentarios que comienzan con ‘#’ se ignoran.

Los argumentos para AuthorizedPrincipalsFile pueden incluir comodines y aceptan los tokens descritos en la sección TOKENS. Después de la expansión, AuthorizedPrincipalsFile se considera una ruta absoluta o una relativa al directorio de inicio del usuario. El valor predeterminado es none, es decir, no usar un archivo de principales; en este caso, el nombre de usuario del usuario debe aparecer en la lista de principales de un certificado para que sea aceptado.

Tenga en cuenta que AuthorizedPrincipalsFile solo se utiliza cuando la autenticación procede utilizando una CA listada en TrustedUserCAKeys y no se consulta para autoridades de certificación confiables a través de ~/.ssh/authorized_keys, aunque la opción de clave principals= ofrece una instalación similar (consulte sshd(8) para obtener detalles).

Banner
El contenido del archivo especificado se envía al usuario remoto antes de que se permita la autenticación. Si el argumento es none, no se muestra ningún banner. Por defecto, no se muestra ningún banner.
CASignatureAlgorithms
Especifica qué algoritmos están permitidos para la firma de certificados por autoridades de certificación (CA). El valor predeterminado es: 
ssh-ed25519,ecdsa-sha2-nistp256,
ecdsa-sha2-nistp384,ecdsa-sha2-nistp521,
sk-ssh-ed25519@openssh.com,
sk-ecdsa-sha2-nistp256@openssh.com,
rsa-sha2-512,rsa-sha2-256

Si la lista especificada comienza con un carácter ‘+’, entonces los algoritmos especificados se agregarán al conjunto predeterminado en lugar de reemplazarlo. Si la lista especificada comienza con un carácter ‘-’, entonces los algoritmos especificados (incluidos los comodines) se eliminarán del conjunto predeterminado en lugar de reemplazarlo.

Los certificados firmados con otros algoritmos no serán aceptados para autenticación por clave pública o basada en host.

ChannelTimeout
Especifica si y con qué rapidez sshd(8) debe cerrar los canales inactivos. Los tiempos de espera se especifican como uno o más pares "tipo=intervalo" separados por espacios, donde el "tipo" debe ser la palabra clave especial "global" o un nombre de tipo de canal de la lista a continuación, que opcionalmente contiene caracteres comodín.

El valor del tiempo de espera "intervalo" se especifica en segundos o puede usar cualquiera de las unidades documentadas en la sección FORMATO DE TIEMPO. Por ejemplo, "session=5m" haría que las sesiones interactivas terminen después de cinco minutos de inactividad. Especificar un valor cero desactiva el tiempo de espera de inactividad.

El tiempo de espera especial "global" se aplica a todos los canales activos, tomados en conjunto. El tráfico en cualquier canal activo restablecerá el tiempo de espera, pero cuando expire el tiempo de espera, todos los canales abiertos se cerrarán. Tenga en cuenta que este tiempo de espera global no coincide con comodines y debe especificarse explícitamente.

Los nombres de tipos de canal disponibles incluyen:

agent-connection
Conexiones abiertas a ssh-agent(1).
direct-tcpip, direct-streamlocal@openssh.com
Conexiones de sockets TCP o Unix abiertas (respectivamente) que se han establecido desde una redirección local de ssh(1), es decir, LocalForward o DynamicForward.
forwarded-tcpip, forwarded-streamlocal@openssh.com
Conexiones de sockets TCP o Unix abiertas (respectivamente) que se han establecido a un sshd(8) escuchando en nombre de una redirección remota de ssh(1), es decir, RemoteForward.
session
La sesión principal interactiva, incluida la sesión de shell, la ejecución de comandos, scp(1), sftp(1), etc.
tun-connection
Conexiones abiertas de TunnelForward.
x11-connection
Sesiones abiertas de reenvío X11.

Tenga en cuenta que en todos los casos anteriores, la terminación de una sesión inactiva no garantiza la eliminación de todos los recursos asociados con la sesión, por ejemplo, los procesos de shell o los clientes X11 relacionados con la sesión pueden seguir ejecutándose.

Además, la terminación de un canal o sesión inactivo no cierra necesariamente la conexión SSH, ni evita que un cliente solicite otro canal del mismo tipo. En particular, la expiración de una sesión de reenvío inactiva no evita que posteriormente se cree otra sesión de reenvío idéntica.

El valor predeterminado es no expirar canales de ningún tipo por inactividad.

ChrootDirectory
Especifica el nombre de ruta de un directorio para realizar chroot(2) después de la autenticación. Al inicio de la sesión, sshd(8) verifica que todos los componentes de la ruta sean directorios propiedad de root y que no sean escribibles por grupo ni por otros. Después del chroot, sshd(8) cambia el directorio de trabajo al directorio de inicio del usuario. Los argumentos para ChrootDirectory aceptan los tokens descritos en la sección TOKENS.

El ChrootDirectory debe contener los archivos y directorios necesarios para soportar la sesión del usuario. Para una sesión interactiva, esto requiere al menos un shell, típicamente sh(1), y nodos básicos de /dev como null(4), zero(4), stdin(4), stdout(4), stderr(4), y dispositivos tty(4). Para sesiones de transferencia de archivos usando SFTP, no se requiere configuración adicional del entorno si se utiliza el sftp-server en proceso, aunque las sesiones que utilizan registro pueden requerir /dev/log dentro del directorio chroot en algunos sistemas operativos (ver sftp-server(8) para detalles).

Por seguridad, es muy importante evitar que la jerarquía de directorios sea modificada por otros procesos en el sistema (especialmente aquellos fuera de la jail). Una mala configuración puede llevar a entornos inseguros que sshd(8) no puede detectar.

El valor por defecto es none, lo que indica no realizar chroot(2).

Ciphers
Especifica los cifrados permitidos. Múltiples cifrados deben estar separados por comas. Si la lista especificada comienza con el carácter ‘+’, entonces los cifrados especificados se añadirán al conjunto por defecto en lugar de reemplazarlo. Si la lista especificada comienza con el carácter ‘-’, entonces los cifrados especificados (incluyendo comodines) se eliminarán del conjunto por defecto en lugar de reemplazarlo. Si la lista especificada comienza con el carácter ‘^’, entonces los cifrados especificados se colocarán al principio del conjunto por defecto.

Los cifrados soportados son:

  • 3des-cbc
  • aes128-cbc
  • aes192-cbc
  • aes256-cbc
  • aes128-ctr
  • aes192-ctr
  • aes256-ctr
  • aes128-gcm@openssh.com
  • aes256-gcm@openssh.com
  • chacha20-poly1305@openssh.com

El valor por defecto es:

chacha20-poly1305@openssh.com,
aes128-gcm@openssh.com,aes256-gcm@openssh.com,
aes128-ctr,aes192-ctr,aes256-ctr

La lista de cifrados disponibles también se puede obtener usando "ssh -Q cipher".

ClientAliveCountMax
Establece el número de mensajes "client alive" (cliente vivo) que pueden enviarse sin que sshd(8) reciba ninguna respuesta del cliente. Si se alcanza este umbral mientras se envían mensajes "client alive", sshd desconectará al cliente, terminando la sesión. Es importante notar que el uso de mensajes "client alive" es muy diferente de TCPKeepAlive. Los mensajes "client alive" se envían a través del canal cifrado y, por lo tanto, no pueden ser suplantados. La opción TCP keepalive habilitada por TCPKeepAlive puede ser suplantada. El mecanismo "client alive" es valioso cuando el cliente o el servidor dependen de saber cuándo una conexión se ha vuelto no receptiva.

El valor por defecto es 3. Si ClientAliveInterval se establece en 15, y ClientAliveCountMax se deja en su valor por defecto, los clientes SSH no receptivos se desconectarán después de aproximadamente 45 segundos. Establecer ClientAliveCountMax a cero deshabilita la terminación de la conexión.

ClientAliveInterval
Establece un intervalo de tiempo de espera en segundos después del cual, si no se ha recibido ningún dato del cliente, sshd(8) enviará un mensaje a través del canal cifrado para solicitar una respuesta del cliente. El valor por defecto es 0, lo que indica que estos mensajes no se enviarán al cliente.
Compression
Especifica si la compresión está habilitada después de que el usuario se ha autenticado correctamente. El argumento debe ser yes, delayed (un sinónimo heredado de yes) o no. El valor por defecto es yes.
DenyGroups
Esta palabra clave puede ir seguida de una lista de patrones de nombres de grupo, separados por espacios. El inicio de sesión se deniega a los usuarios cuyo grupo principal o lista de grupos complementarios coincida con uno de los patrones. Solo son válidos los nombres de grupo; no se reconoce un ID de grupo numérico. Por defecto, el inicio de sesión está permitido para todos los grupos. Las directivas allow/deny groups se procesan en el siguiente orden: DenyGroups, AllowGroups.

Consulte PATTERNS en ssh_config(5) para más información sobre patrones. Esta palabra clave puede aparecer múltiples veces en sshd_config, y cada instancia se añadirá a la lista.

DenyUsers
Esta palabra clave puede ir seguida de una lista de patrones de nombres de usuario, separados por espacios. El inicio de sesión se deniega a los nombres de usuario que coincidan con uno de los patrones. Solo son válidos los nombres de usuario; no se reconoce un ID de usuario numérico. Por defecto, el inicio de sesión está permitido para todos los usuarios. Si el patrón tiene la forma USER@HOST, entonces USER y HOST se comprueban por separado, restringiendo los inicios de sesión a usuarios específicos de hosts específicos. Los criterios de HOST pueden contener además direcciones para coincidir en formato de dirección/longitud de máscara CIDR. Las directivas allow/deny users se procesan en el siguiente orden: DenyUsers, AllowUsers.

Consulte PATTERNS en ssh_config(5) para más información sobre patrones. Esta palabra clave puede aparecer múltiples veces en sshd_config, y cada instancia se añadirá a la lista.

DisableForwarding
Deshabilita todas las funciones de reenvío, incluyendo X11, ssh-agent(1), TCP y StreamLocal. Esta opción anula todas las demás opciones relacionadas con el reenvío y puede simplificar configuraciones restringidas.
ExposeAuthInfo
Escribe un archivo temporal que contiene una lista de métodos de autenticación y credenciales públicas (por ejemplo, claves) utilizadas para autenticar al usuario. La ubicación del archivo se expone a la sesión del usuario a través de la variable de entorno SSH_USER_AUTH. El valor por defecto es no.
FingerprintHash
Especifica el algoritmo de hash utilizado al registrar las huellas dactilares de las claves. Las opciones válidas son: md5 y sha256. El valor por defecto es sha256.
ForceCommand
Fuerza la ejecución del comando especificado por ForceCommand, ignorando cualquier comando suministrado por el cliente y ~/.ssh/rc si está presente. El comando se invoca utilizando el shell de inicio de sesión del usuario con la opción -c. Esto se aplica a la ejecución de shell, comando o subsistema. Es más útil dentro de un bloque Match. El comando suministrado originalmente por el cliente está disponible en la variable de entorno SSH_ORIGINAL_COMMAND. Especificar un comando de internal-sftp forzará el uso de un servidor SFTP en proceso que no requiere archivos de soporte cuando se utiliza con ChrootDirectory. El valor por defecto es none.
GatewayPorts
Especifica si se permite a los hosts remotos conectarse a los puertos reenviados para el cliente. Por defecto, sshd(8) enlaza los reenvíos de puertos remotos a la dirección de loopback. Esto evita que otros hosts remotos se conecten a los puertos reenviados. GatewayPorts se puede utilizar para especificar que sshd debe permitir que los reenvíos de puertos remotos se enlacen a direcciones no loopback, permitiendo así que otros hosts se conecten. El argumento puede ser no para forzar que los reenvíos de puertos remotos solo estén disponibles para el host local, yes para forzar que los reenvíos de puertos remotos se enlacen a la dirección comodín, o clientspecified para permitir que el cliente seleccione la dirección a la que se enlaza el reenvío. El valor por defecto es no.
GSSAPIAuthentication
Especifica si se permite la autenticación de usuario basada en GSSAPI. El valor por defecto es no.
GSSAPICleanupCredentials
Especifica si se deben destruir automáticamente la caché de credenciales del usuario al cerrar la sesión. El valor por defecto es yes.
GSSAPIStrictAcceptorCheck
Determina si se debe ser estricto con la identidad del acceptor GSSAPI contra el cual se autentica un cliente. Si se establece en yes, el cliente debe autenticarse contra el servicio del host en el nombre de host actual. Si se establece en no, el cliente puede autenticarse contra cualquier clave de servicio almacenada en la tienda por defecto de la máquina. Esta funcionalidad se proporciona para ayudar en la operación en máquinas con múltiples interfaces. El valor por defecto es yes.
HostbasedAcceptedAlgorithms
Especifica los algoritmos de firma que se aceptarán para la autenticación basada en host como una lista de patrones separados por comas. Alternativamente, si la lista especificada comienza con el carácter ‘+’, entonces los algoritmos de firma especificados se añadirán al conjunto por defecto en lugar de reemplazarlo. Si la lista especificada comienza con el carácter ‘-’ algoritmos de firma (incluyendo comodines) se eliminarán del conjunto predeterminado en lugar de reemplazarlos. Si la lista especificada comienza con un carácter ‘^’, entonces los algoritmos de firma especificados se colocarán al principio del conjunto predeterminado. El valor predeterminado para esta opción es: 
ssh-ed25519-cert-v01@openssh.com,
ecdsa-sha2-nistp256-cert-v01@openssh.com,
ecdsa-sha2-nistp384-cert-v01@openssh.com,
ecdsa-sha2-nistp521-cert-v01@openssh.com,
sk-ssh-ed25519-cert-v01@openssh.com,
sk-ecdsa-sha2-nistp256-cert-v01@openssh.com,
rsa-sha2-512-cert-v01@openssh.com,
rsa-sha2-256-cert-v01@openssh.com,
ssh-ed25519,
ecdsa-sha2-nistp256,ecdsa-sha2-nistp384,ecdsa-sha2-nistp521,
sk-ssh-ed25519@openssh.com,
sk-ecdsa-sha2-nistp256@openssh.com,
rsa-sha2-512,rsa-sha2-256

La lista de algoritmos de firma disponibles también se puede obtener usando "ssh -Q HostbasedAcceptedAlgorithms". Esto anteriormente se llamaba HostbasedAcceptedKeyTypes.

HostbasedAuthentication
Especifica si se permiten las autenticaciones rhosts o /etc/hosts.equiv junto con la autenticación de clave pública de host del cliente (autenticación basada en host). El valor predeterminado es no.
HostbasedUsesNameFromPacketOnly
Especifica si el servidor intentará realizar una búsqueda de nombre inversa al comparar el nombre en los archivos ~/.shosts, ~/.rhosts y /etc/hosts.equiv durante HostbasedAuthentication. Una configuración de yes significa que sshd(8) usa el nombre proporcionado por el cliente en lugar de intentar resolver el nombre a partir de la conexión TCP en sí. El valor predeterminado es no.
HostCertificate
Especifica un archivo que contiene un certificado de host público. La clave pública del certificado debe coincidir con una clave de host privada ya especificada por HostKey. El comportamiento predeterminado de sshd(8) es no cargar ningún certificado.
HostKey

Introduce un bloque condicional. Si todos los criterios de la línea Match se cumplen, las palabras clave de las líneas siguientes anulan las establecidas en la sección global del archivo de configuración, hasta que aparezca otra línea Match o el final del archivo. Si una palabra clave aparece en varios bloques Match que se cumplen, solo se aplica la primera instancia de la palabra clave.

Los argumentos de Match son uno o más pares criterio-patrón o uno de los criterios de token único: All, que coincide con todos los criterios, o Invalid-User, que coincide cuando el nombre de usuario solicitado no coincide con ninguna cuenta conocida. Los criterios disponibles son User, Group, Host, LocalAddress, LocalPort, Version, RDomain y Address (con RDomain representando el dominio de enrutamiento en el que se recibió la conexión).

Los patrones de coincidencia pueden consistir en entradas únicas o listas separadas por comas y pueden usar los operadores de comodines y negación descritos en la sección PATTERNS de ssh_config(5).

Los patrones en un criterio Address pueden contener adicionalmente direcciones para que coincidan en formato CIDR de dirección/longitud de máscara, como 192.0.2.0/24 o 2001:db8::/32. Por ejemplo, 192.0.2.0/33 y 192.0.2.0/8, respectivamente.

La palabra clave Version coincide con la cadena de versión de sshd(8), por ejemplo “OpenSSH_10.0”.

MaxAuthTries
Especifica el número máximo de intentos de autenticación permitidos por conexión. Una vez que el número de fallos alcanza la mitad de este valor, los fallos adicionales se registran. El valor predeterminado es 6.
MaxSessions
Especifica el número máximo de sesiones de shell, inicio de sesión o subsistema (por ejemplo, sftp) abiertas permitidas por conexión de red. Los clientes que admiten la multiplexación de conexiones pueden establecer varias sesiones. Establecer MaxSessions en 1 deshabilitará efectivamente la multiplexación de sesiones, mientras que establecerlo en 0 impedirá todas las sesiones de shell, inicio de sesión y subsistema, pero permitirá el reenvío. El valor predeterminado es 10.
MaxStartups
Especifica el número máximo de conexiones simultáneas sin autenticar con el demonio SSH. Las conexiones adicionales se descartarán hasta que la autenticación tenga éxito o expire el LoginGraceTime para una conexión. El valor predeterminado es 10:30:100.

Alternativamente, se puede habilitar el descarte temprano aleatorio especificando los tres valores separados por dos puntos: inicio:tasa:completo (por ejemplo, "10:30:60"). sshd(8) rechazará los intentos de conexión con una probabilidad de tasa/100 (30%) si hay actualmente inicio (10) conexiones sin autenticar. La probabilidad aumenta linealmente y se rechazan todos los intentos de conexión si el número de conexiones sin autenticar alcanza el valor completo (60).

PermitListen
Especifica las direcciones/puertos en los que se puede escuchar un reenvío de puerto TCP remoto. La especificación de escucha debe tener una de las siguientes formas:
  • PermitListen puerto
  • PermitListen host:puerto

Se pueden especificar varios permisos separándolos con espacios en blanco. Se puede usar un argumento any para eliminar todas las restricciones y permitir todas las solicitudes de escucha. Se puede usar un argumento none para prohibir todas las solicitudes de escucha. El nombre del host puede contener comodines como se describe en la sección PATTERNS de ssh_config(5). El comodín ‘*’ también se puede usar en lugar de un número de puerto para permitir todos los puertos. Por defecto, se permiten todas las solicitudes de escucha de reenvío de puertos. Tenga en cuenta que la opción GatewayPorts puede restringir aún más en qué direcciones se puede escuchar. Tenga en cuenta también que ssh(1) solicitará un host de escucha de “localhost” si no se solicitó explícitamente ningún host de escucha, y este nombre se trata de manera diferente a las direcciones explícitas de localhost de “127.0.0.1” y “::1”.

PermitOpen
Especifica los destinos a los que se permite el reenvío de puertos TCP. La especificación de reenvío debe tener una de las siguientes formas:
  • PermitOpen host:puerto
  • PermitOpen IPv4_addr:puerto
  • PermitOpen [IPv6_addr]:puerto

Se pueden especificar varios reenvíos separándolos con espacios en blanco. Se puede usar un argumento any para eliminar todas las restricciones y permitir todas las solicitudes de reenvío. Se puede usar un argumento none para prohibir todas las solicitudes de reenvío. El comodín ‘*’ se puede usar para hosts o puertos para permitir todos los hosts o puertos respectivamente. De lo contrario, no se realizan coincidencias de patrones ni búsquedas de direcciones en los nombres proporcionados. Por defecto, se permiten todas las solicitudes de reenvío de puertos.

PermitRootLogin
Especifica si root puede iniciar sesión usando ssh(1). El argumento debe ser yes, prohibit-password, forced-commands-only, o no. El valor predeterminado es prohibit-password.

Si esta opción se establece en prohibit-password (o su alias obsoleto, without-password), la autenticación por contraseña y la interactiva por teclado se deshabilitan para root.

Si esta opción se establece en forced-commands-only, se permitirá el inicio de sesión de root con autenticación de clave pública, pero solo si se ha especificado la opción command (lo que puede ser útil para realizar copias de seguridad remotas incluso si el inicio de sesión de root normalmente no está permitido). Todos los demás métodos de autenticación están deshabilitados para root.

Si esta opción se establece en no, no se permite que root inicie sesión.

PermitTunnel

DESCRIPTION

The sshd_config file provides configuration options for sshd(8), the OpenSSH daemon that listens for incoming SSH connections and authenticates and logs users.

The default location of the sshd_config file is /etc/ssh/sshd_config.

The syntax of the configuration file is:

A file consists of whitespace-separated keywords, followed by a value. The keywords are case-insensitive. The file may include comments starting with a '#' character. Lines starting with a '#' character are ignored.

A configuration option can be specified multiple times, and the last one will be used. Options are also inherited from the global defaults if not specified in the file.

Some options may accept a list of values, separated by commas or whitespace. If a value contains whitespace, it must be quoted.

The configuration options are:

AcceptEnv
Specifies which environment variables accessible to the user at login time will be sent to the server. FOO variables specified on the command line will be copied to the server. FOO by default, sshd(8) does not copy any environment variables. See also SendEnv in ssh_config(5).
AddressFamily
Specifies whether sshd(8) should use IPv4 or IPv6 addresses. The possible values are any, inet (for IPv4), or inet6 (for IPv6). The default is any.
AllowAgentForwarding
Specifies whether ssh(1) agent forwarding is permitted. The default is yes.
AllowTcpForwarding
Specifies whether TCP forwarding is permitted. The default is yes. If this option is set to local, only local and remote port forwarding is permitted. If set to remote, only remote port forwarding is permitted. If set to no, TCP forwarding is completely disabled.
AllowUsers
Specifies the users that are allowed to log in using sshd. The matches are checked against the username part of the user's principal name. See also DenyUsers.
AllowGroups
Specifies the groups that are allowed to log in using sshd. The matches are checked against the group name. See also DenyGroups.
AuthorizedKeysCommand
Specifies a command to be run to obtain the authorized keys for the remote user. See the AUTHORIZEDKEYSCOMMAND section for details. The default is to read the keys from ~/.ssh/authorized_keys.
AuthorizedKeysCommandUser
Specifies the user account to run the AuthorizedKeysCommand. The argument should be in the form user or user:group. The default is nobody.
AuthorizedKeysFile
Specifies the filename of the file that contains the public keys of authorized users. The default is .ssh/authorized_keys. This file is relative to the user's home directory.
Banner
Specifies a file containing a message to be printed on the remote terminal before the login prompt. The default is none.
ChallengeResponseAuthentication
Specifies whether to use challenge-response authentication. The default is yes.
ChrootDirectory
Specifies a path to which the user's chroot jail is restricted. See the CHROOTDIRECTORY section for details. The default is none.
ClientAliveCountMax
Sets a timeout interval in seconds after which if no data has been received from the client, sshd will send a message through the encrypted channel to request a response from the client in order to keep the connection alive. The response from the client is got via the mechanism defined by ClientAliveInterval. The default is 3.
ClientAliveInterval
Sets a timeout interval in seconds after which if no data has been received from the client, sshd will send a message through the encrypted channel to request a response from the client in order to keep the connection alive. The response from the client is got via the mechanism defined by ClientAliveInterval. The default is 0, which disables this behavior.
Compression
Specifies whether to use compression. The default is no.
DaemonCountMax
Specifies the maximum number of concurrent unauthenticated connections to the daemon. The default is 10.
DenyUsers
Specifies the users that are not allowed to log in using sshd. The matches are checked against the username part of the user's principal name. See also AllowUsers.
DenyGroups
Specifies the groups that are not allowed to log in using sshd. The matches are checked against the group name. See also AllowGroups.
DisableForwarding
Specifies whether to disable all forwarding. The default is no. If this option is set to yes, all forms of forwarding (agent, TCP, X11) will be disabled.
DsaReportFingerprint
Specifies whether to report the DSA host key fingerprint to the user. The default is yes.
GSSAPIAuthentication
Specifies whether to enable GSSAPI authentication. The default is no.
GSSAPICleanupCredentials
Specifies whether to delete all Kerberos tickets associated with the user's session when the user logs out. The default is yes.
HostbasedAuthentication
Specifies whether to allow host-based authentication. The default is no.
IgnoreUserGroups
Specifies whether to ignore the user's group memberships when checking access control. The default is no.
IgnoreUserKnownHosts
Specifies whether to ignore the user's known_hosts file when checking access control. The default is no.
KerberosGetOffTgt
Specifies whether to obtain a renewable ticket-granting ticket (TGT) when using Kerberos. The default is yes.
KerberosOrLocalPassword
Specifies whether to fall back to local password authentication if Kerberos authentication fails. The default is yes.
KerberosTicketLifetime
Specifies the maximum lifetime for Kerberos tickets. The default is 1h.
KexAlgorithms
Specifies the Diffie-Hellman key exchange algorithms that are supported. The default is diffie-hellman-group-exchange-sha1,diffie-hellman-group-exchange-sha256,diffie-hellman-group14-sha1.
ListenAddress
Specifies the local IP address and port that the daemon should listen on. The default is to listen on all interfaces, on the port specified by the Port keyword.
LoginGraceTime
Specifies the time during which a login must complete after authentication. If the login is not completed within this time, the connection will be terminated. The default is 2m.
LogFacility
Specifies the facility code that is used when logging messages from sshd(8). The default is AUTHPRIV.
LogLevel
Specifies the granularity of the logging. The possible values are QUIET, FATAL, ERROR, INFO, VERBOSE, DEBUG, DEBUG1, DEBUG2, DEBUG3. The default is INFO.
MACs
Specifies the MAC (message authentication code) algorithms that are supported. The default is hmac-md5,hmac-sha1,umac-64@openssh.com,hmac-ripemd160,hmac-sha1-96,hmac-md5-96.
MaxAuthTries
Specifies the maximum number of authentication attempts before disconnecting. The default is 6.
MaxSessions
Specifies the maximum number of open sessions permitted per network connection. The default is 10.
PasswordAuthentication
Specifies whether password authentication is allowed. The default is yes.
PermitEmptyCredentials
Specifies whether to permit the use of empty credentials. The default is no.
PermitTTY
Specifies whether pseudo-terminal allocation is permitted. The default is yes.
PermitRootLogin

Specifies the timeout interval in seconds for SFTP connections. The default is 0, which disables this feature.

Specifies the key generation algorithm used by the server. The default is rsa,dsa.

Specifies a subsystem, which is an external program that is started upon connection. The default is sftp /usr/lib/ssh/sftp-server.
SyslogFacility
Specifies the facility code that is used when logging messages from sshd(8). The default is AUTHPRIV.
TCPKeepAlive
Specifies whether TCP keepalive messages are sent by the system. The default is yes.
TrustedUserCAKeys
Specifies a file containing trusted user certificate authorities. See TrustedUserCAKeys in sshd(8) for more details.
UsePAM
Specifies whether to use PAM (Pluggable Authentication Modules) for authentication. The default is no.
UseDNS
Specifies whether to look up the remote host's host name. The default is yes.
X11AuthTries
Specifies the maximum number of X11 authentication attempts before disconnecting. The default is 3.
X11DisplayOffset
Specifies the base display number to use for X11 forwarding. The default is 10.
X11Forwarding
Specifies whether X11 forwarding is permitted. The default is no. If this option is set to yes, X11 forwarding is enabled. If set to no, X11 forwarding is disabled. Be aware that enabling X11 forwarding may expose users to attacks by unwittingly requesting X11 forwarding, which can warrant a no setting.

El dominio de enrutamiento en el que se recibió la conexión entrante.

El directorio principal del usuario.

El ID de clave en el certificado.

La clave CA codificada en base64.
