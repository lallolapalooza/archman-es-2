NOMBRE

sssd-idp - Proveedor IdP de SSSD

DESCRIPCIÓN

Esta página del manual describe la configuración del proveedor IdP para sssd(8). Para una referencia detallada de la sintaxis, consulte la sección “FORMATO DE ARCHIVO” de la página del manual sssd.conf(5).

El proveedor IdP es un backend utilizado para conectarse a un proveedor de identidad (IdP) basado en OAuth 2.0 y REST. Dado que los productos pueden tener implementaciones individuales de la API REST para buscar atributos de usuario y grupo, puede ser necesario código dedicado, consulte la opción “idp_type” para obtener más detalles.

Los IdP normalmente no proporcionan atributos POSIX como, por ejemplo, el ID de usuario (UID) o el directorio principal. El proveedor IdP de SSSD autogenerará los atributos necesarios. El algoritmo predeterminado para generar los IDs de usuario (UID) y los IDs de grupo (GID) tiene como objetivo crear IDs reproducibles en diferentes sistemas. Como inconveniente, puede ocurrir que el algoritmo asigne el mismo ID a diferentes objetos y solo el primero solicitado a través de SSSD estará disponible.

OPCIONES DE CONFIGURACIÓN

Consulte la sección “SECCIONES DE DOMINIO” de la página del manual sssd.conf(5) para obtener detalles sobre la configuración de un dominio SSSD.

idp_type (cadena)

Opción requerida que especifica el producto IdP. Actualmente se admiten Entra ID (entra_id) y Keycloak (keycloak).

Dependiendo del producto IdP, pueden seguir opciones adicionales específicas de la plataforma después del nombre, separadas por dos puntos (:). Por ejemplo, para Keycloak se debe proporcionar la URI base para la API REST de usuarios y grupos. Para Entra ID esto no es necesario porque hay un punto final genérico para todos los inquilinos.

Por defecto: No establecido (Requerido)

idp_client_id (cadena)

ID del cliente IdP utilizado por SSSD para autenticar usuarios y como cliente para buscar atributos de usuario y grupo. Este cliente debe ofrecer autorización de dispositivo según RFC-8628 y debe tener permisos para buscar y leer atributos de usuario y grupo.

Por defecto: No establecido (Requerido)

idp_client_secret (cadena)

Contraseña del cliente IdP. La contraseña es necesaria para el id_provider. Si solo se utiliza como auth_provider, depende de la configuración del lado del servidor si es necesaria o no.

Por defecto: No establecido

idp_token_endpoint (cadena)

Punto final del IdP para solicitar tokens de acceso.

Por defecto: No establecido (Requerido)

idp_device_auth_endpoint (cadena)

Punto final del IdP para la autorización de dispositivo según RFC-8628. Esto es necesario para la autenticación de usuarios.

Por defecto: No establecido

idp_userinfo_endpoint (cadena)

Punto final de información de usuario del IdP para solicitar atributos de usuario después de una autenticación exitosa del usuario. Requerido para la autenticación.

Por defecto: No establecido (Requerido)

idp_id_scope (cadena)

Ámbito requerido para buscar atributos de usuario y grupo con la API REST. Los ámbitos se utilizan en el servidor para determinar qué atributos/reclamaciones se devuelven al llamador.

Por defecto: No establecido

idp_auth_scope (cadena)

Ámbito requerido durante la autenticación. Los ámbitos se utilizan en el servidor para determinar qué atributos/reclamaciones se devuelven al llamador.

Actualmente, los tokens devueltos durante la autenticación del usuario no se utilizan para otros fines, por lo que la única reclamación importante es el identificador del sujeto 'sub' que se utiliza para verificar si el usuario autenticado es quien intenta iniciar sesión. Esto puede cambiar en el futuro.

Por defecto: No establecido

idp_request_timeout (entero)

Tiempo de espera en segundos para una solicitud individual al IdP.

Por defecto: 10

idmap_range_min (entero)

Especifica el límite inferior (inclusivo) del rango de IDs POSIX a utilizar para mapear usuarios y grupos IdP a IDs POSIX. Es el primer ID POSIX que se puede utilizar para el mapeo.

El intervalo entre “idmap_range_min” y “idmap_range_max” se dividirá en rangos más pequeños de tamaño “idmap_range_size” que serán utilizados por un dominio IdP individual.

Por defecto: 200000

idmap_range_max (entero)

Especifica el límite superior (exclusivo) del rango de IDs POSIX a utilizar para mapear usuarios y grupos IdP a IDs POSIX. Es el primer ID POSIX que no se utilizará para el mapeo de IDs POSIX.

Por defecto: 2000200000

idmap_range_size (entero)

Especifica el número de IDs POSIX disponibles para un solo dominio IdP.

Por defecto: 200000

EJEMPLO

[domain/entra_id]
id_provider = idp
idp_type = entra_id
idp_client_id = 12345678-abcd-0101-efef-ba9876543210
idp_client_secret = TU-SECRETO-DE-CLIENTE
idp_token_endpoint = https://login.microsoftonline.com/ID-DEL-INQUILINO/oauth2/v2.0/token
idp_userinfo_endpoint = https://graph.microsoft.com/v1.0/me
idp_device_auth_endpoint = https://login.microsoftonline.com/ID-DEL-INQUILINO/oauth2/v2.0/devicecode
idp_id_scope = https%3A%2F%2Fgraph.microsoft.com%2F.default
idp_auth_scope = openid profile email
[domain/keycloak]
idp_type = keycloak:https://master.keycloak.test:8443/auth/admin/realms/master/
id_provider = idp
idp_client_id = myclient
idp_client_secret = TU-SECRETO-DE-CLIENTE
idp_token_endpoint = https://master.keycloak.test:8443/auth/realms/master/protocol/openid-connect/token
idp_userinfo_endpoint = https://master.keycloak.test:8443/auth/realms/master/protocol/openid-connect/userinfo
idp_device_auth_endpoint = https://master.keycloak.test:8443/auth/realms/master/protocol/openid-connect/auth/device
idp_id_scope = profile
idp_auth_scope = openid profile email
