NOMBRE

ss - otra utilidad para investigar sockets

SINOPSIS

ss [opciones] [ FILTRO ]

DESCRIPCIÓN

ss se utiliza para volcar estadísticas de sockets. Permite mostrar información similar a netstat. Puede mostrar más información de TCP y de estado que otras herramientas.

OPCIONES

Cuando no se utiliza ninguna opción, ss muestra una lista de sockets abiertos que no están escuchando (por ejemplo, TCP/UNIX/UDP) y que tienen una conexión establecida.

-h, --help
Muestra un resumen de las opciones.
-V, --version
Muestra información de la versión.
-H, --no-header
Suprime la línea de encabezado.
-Q, --no-queues
Suprime las columnas de las colas de envío y recepción.
-O, --oneline
Imprime los datos de cada socket en una sola línea.
-n, --numeric
No intentes resolver nombres de servicio. Muestra valores exactos de ancho de banda, en lugar de valores legibles por humanos.
-r, --resolve
Intenta resolver direcciones/puertos numéricos.
-a, --all
Muestra sockets tanto en escucha como no en escucha (para TCP, esto significa conexiones establecidas).
-l, --listening
Muestra solo sockets en escucha (estos se omiten por defecto).
-B, --bound-inactive
Muestra solo sockets TCP conectados pero inactivos (no en escucha, no conectándose, etc.) (estos se omiten por defecto).
-o, --options
Muestra información de temporizadores. Para el protocolo TCP, el formato de salida es:

timer:(<nombre_del_temporizador>,<tiempo_de_expiración>,<retransmisión>)

<nombre_del_temporizador>
el nombre del temporizador, hay cinco tipos de nombres de temporizadores:

on : significa uno de estos temporizadores: temporizador de retransmisión TCP, temporizador de retransmisión temprana TCP y temporizador de sondeo de pérdida de cola

keepalive: temporizador de keep alive de TCP

timewait: temporizador de la etapa timewait

persist: temporizador de sondeo de ventana cero

unknown: ninguno de los temporizadores anteriores

<tiempo_de_expiración>
cuánto tiempo tardará en expirar el temporizador
<retransmisión>
cuántas veces ocurrió la retransmisión
-e, --extended
Muestra información detallada del socket. El formato de salida es:

uid:<número_uid> ino:<número_inodo> sk:<cookie>

<número_uid>
el id de usuario al que pertenece el socket
<número_inodo>
el número de inodo del socket en VFS
<cookie>
un uuid del socket
-m, --memory
Muestra el uso de memoria del socket. El formato de salida es:

skmem:(r<rmem_alloc>,rb<rcv_buf>,t<wmem_alloc>,tb<snd_buf>,

f<fwd_alloc>,w<wmem_queued>,o<opt_mem>,
bl<back_log>,d<sock_drop>)

<rmem_alloc>
la memoria asignada para recibir paquetes
<rcv_buf>
la memoria total que se puede asignar para recibir paquetes
<wmem_alloc>
la memoria utilizada para enviar paquetes (que se han enviado a la capa 3)
<snd_buf>
la memoria total que se puede asignar para enviar paquetes
<fwd_alloc>
la memoria asignada por el socket como caché, pero que aún no se ha utilizado para recibir/enviar paquetes. Si se necesita memoria para enviar/recibir paquetes, la memoria de esta caché se utilizará antes de asignar memoria adicional.
<wmem_queued>
La memoria asignada para enviar paquetes (que aún no se han enviado a la capa 3)
<opt_mem>
La memoria utilizada para almacenar opciones de socket, por ejemplo, la clave para la firma MD5 de TCP
<back_log>
La memoria utilizada para la cola de espera (backlog) del socket. En un contexto de proceso, si el proceso está recibiendo paquetes y se recibe un nuevo paquete, se pondrá en la cola de espera del socket, para que pueda ser recibido inmediatamente por el proceso.
<sock_drop>
el número de paquetes descartados antes de que se desmultiplexen en el socket
-p, --processes
Muestra el proceso que utiliza el socket.
-T, --threads
Muestra el hilo que utiliza el socket. Implica -p.
-i, --info
Muestra información interna de TCP. Pueden aparecer los siguientes campos:
ts
muestra la cadena "ts" si la opción de marca de tiempo está activada
sack
muestra la cadena "sack" si la opción de sack está activada
ecn
muestra la cadena "ecn" si la opción de notificación explícita de congestión está activada
ecnseen

fastopen

cong_alg

wscale:<snd_wscale>:<rcv_wscale>
si se utiliza la opción de escala de ventana, este campo muestra el factor de escala de envío y el factor de escala de recepción
rto:<icsk_rto>

backoff:<icsk_backoff>

SINTAXIS DEL HOST

La sintaxis general del host es [FAMILIA:]DIRECCIÓN[:PUERTO].

FAMILIA debe ser una de las familias soportadas por la opción -f. Si no se proporciona, se asume la familia dada con la opción -f, y si esta tampoco está presente, se asumirá inet o inet6. Tenga en cuenta que todas las condiciones de host en la expresión deben ser de la misma familia o solo inet e inet6. Si hay una mezcla de otras familias, los resultados probablemente serán inesperados.

La forma de DIRECCIÓN y PUERTO depende de la familia utilizada. "*" puede usarse como comodín para la dirección o el puerto. Los detalles para cada familia son los siguientes:

unix
DIRECCIÓN es un patrón glob (ver fnmatch(3)) que se comparará sin distinción entre mayúsculas y minúsculas con la dirección del socket unix. Se admiten nombres de ruta y nombres abstractos. Las direcciones Unix no soportan puerto, y "*" no puede usarse como comodín.
link
DIRECCIÓN es el nombre sin distinción entre mayúsculas y minúsculas de un protocolo Ethernet a comparar. PUERTO es el nombre de un dispositivo o un índice de dispositivo para el dispositivo de enlace deseado, tal como se ve en la salida de ip link.
netlink
DIRECCIÓN es un descriptor de la familia netlink. Los valores posibles provienen de /etc/iproute2/nl_protos. PUERTO es el id del puerto del socket, que generalmente es el mismo que el id del proceso propietario. El valor "kernel" puede usarse para representar el kernel (id de puerto 0).
vsock
DIRECCIÓN es un entero que representa la dirección CID, y PUERTO es el puerto.
inet y inet6
DIRECCIÓN es una dirección ip (v4 o v6 dependiendo de la familia) o un nombre de host DNS que se resuelve a una dirección ip de la versión requerida. Una dirección ipv6 debe encerrarse entre "[" y "]" para desambiguar el separador de puerto. La dirección adicionalmente puede tener una longitud de prefijo dada en notación CIDR (una barra seguida de la longitud del prefijo en bits). PUERTO es el puerto numérico del socket, o el nombre del servicio para el puerto a comparar.

EJEMPLOS DE USO

ss -t -a
Mostrar todos los sockets TCP.
ss -t -a -Z
Mostrar todos los sockets TCP con contextos de seguridad SELinux de procesos.
ss -u -a
Mostrar todos los sockets UDP.
ss -o state established '( dport = :ssh or sport = :ssh )'
Mostrar todas las conexiones ssh establecidas.
ss -x src /tmp/.X11-unix/*
Encontrar todos los procesos locales conectados al servidor X.
ss -o state fin-wait-1 '( sport = :http or sport = :https )' dst 193.233.7/24
Listar todos los sockets tcp en estado FIN-WAIT-1 para nuestro apache a la red 193.233.7/24 y observar sus temporizadores.
ss -a -A 'all,!tcp'
Listar sockets en todos los estados de todas las tablas de sockets excepto TCP.
