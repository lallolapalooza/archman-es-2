NOMBRE

sudo, sudoedit - ejecuta un comando como otro usuario

SINOPSIS

sudo -h | -K | -k | -V

sudo [-u usuario] [-g grupo] [-D directorio] [-BknS] [-i | -s] [VAR=valor] [<comando>]

sudo -v [-BknS] [-u usuario] [-g grupo]

sudo -l [-BknS] [-U usuario] [-u usuario] [-g grupo] [comando [arg ...]]

sudo -e [-BknS] [-u usuario] [-g grupo] archivo ...

sudoedit [-BknS] [-u usuario] [-g grupo] archivo ...

DESCRIPCIÓN

sudo permite a un usuario con permiso ejecutar un comando como otro usuario (por ejemplo, root). Los permisos se especifican mediante una política de seguridad definida en /etc/sudoers (ver sudoers(5)).

Sudo-rs es una reimplementación segura y con gestión de memoria de la implementación original de sudo por Todd Miller.

Cuando se ejecuta un comando, se almacena un registro de sesión para esa sesión específica, lo que permite a los usuarios ejecutar comandos adicionales sin tener que volver a autenticarse. El tiempo de espera para los registros de sesión se puede especificar en la política.

Se tiene cierto cuidado para pasar las señales recibidas por sudo-rs al proceso hijo, incluso si ese proceso se ejecuta en su propia terminal pseudo.

En sistemas donde sudo es el método principal para obtener privilegios de superusuario, es imperativo evitar errores de sintaxis en el archivo /etc/sudoers. Los cambios en este archivo deben hacerse utilizando la utilidad visudo(8), que se asegurará de que no se introduzcan errores de sintaxis.

OPCIONES

-B, --campana
Haz sonar la campana como parte de la solicitud de contraseña cuando haya una terminal presente.
-D directorio, --cambiar-directorio=directorio
Ejecuta el comando en el directorio especificado en lugar del directorio de trabajo actual. La política de seguridad puede devolver un error si el usuario no tiene permiso para especificar el directorio de trabajo.
-g grupo, --grupo=grupo
Usa este grupo como el grupo primario en lugar de usar el grupo primario especificado en la base de datos de contraseñas para el usuario de destino.
-h, --ayuda
Muestra un mensaje de ayuda.
-i, --inicio-sesion
Ejecuta el shell especificado en la entrada de la base de datos de contraseñas del usuario de destino como un shell de inicio de sesión. Esto significa que el shell leerá archivos de recursos específicos de inicio de sesión como .profile, .bash_profile o .login. Si se especifica un comando, se pasa al shell usando la opción -c.
-K, --eliminar-marca-tiempo
Elimina todos los registros de sesión en caché para el usuario, independientemente de dónde se ejecute el comando. La próxima vez que se ejecute sudo-rs, se realizará la autenticación si la política lo requiere. No se requiere contraseña para ejecutar este comando.
-k, --reiniciar-marca-tiempo
Cuando se usa sin un comando, invalida el registro de sesión del usuario para la sesión actual. La próxima vez que se ejecute sudo-rs, se realizará la autenticación si la política lo requiere.

Cuando se usa junto con un comando o una opción que puede requerir una contraseña, esta opción hará que sudo-rs ignore el registro de sesión del usuario. Como resultado, se realizará la autenticación si la política lo requiere. Cuando se usa junto con un comando, no se invalida ningún registro de sesión existente.

-n, --no-interactivo
Evita solicitar al usuario cualquier tipo de entrada. Si se requiere alguna entrada para que se ejecute el comando, sudo-rs mostrará un mensaje de error y saldrá.
-p, --prompt=prompt
Usa una solicitud de autenticación personalizada con secuencias de escape opcionales. Se admiten las siguientes secuencias de escape de porcentaje ('%'):
 %H  se expande al nombre del host local
 %h  se expande al nombre del host local sin el nombre de dominio
 %p  se expande al nombre del usuario cuya contraseña se está solicitando
     (esto respeta las banderas rootpw, targetpw)
 %U  se expande al nombre de inicio de sesión del usuario con el que se ejecutará el comando
     (por defecto es root a menos que también se especifique la opción -u)
 %u  se expande al nombre de inicio de sesión del usuario que invoca
 %%  dos caracteres '%' consecutivos se colapsan en un solo carácter '%'

La solicitud personalizada anulará la solicitud predeterminada o la especificada por la variable de entorno SUDO_PROMPT. Ningún prompt suprimirá la solicitud proporcionada por PAM, a menos que el prompt solicitado esté vacío ("")

-S, --stdin
Lee desde la entrada estándar en lugar de usar el dispositivo de terminal.
-s, --shell
Ejecuta el shell especificado por la variable de entorno SHELL. Si no se especificó ningún shell, se utilizará el shell de la entrada de la base de datos de contraseñas del usuario. Si se especifica un comando, se pasa al shell usando la opción -c.

-e, sudoedit

Edita uno o más archivos en lugar de ejecutar un comando. En lugar de un nombre de ruta, se utiliza la cadena "sudoedit" al consultar la política de seguridad. Si el usuario está autorizado por la política, se toman los siguientes pasos:
1. Se crean copias temporales de los archivos a editar, con el propietario establecido en el usuario que invoca.
2. Se ejecuta el editor especificado por la política para editar los archivos temporales. La política de sudoers utiliza las variables de entorno SUDO_EDITOR, VISUAL y EDITOR (en ese orden). Si ninguna de SUDO_EDITOR, VISUAL o EDITOR están establecidas, se utiliza el primer programa listado en la opción de editor de sudoers(5).
3. Si se han modificado, el contenido de los archivos temporales se copia de nuevo a los originales y las versiones temporales se eliminan.
Para ayudar a prevenir la edición de archivos no autorizados, se aplican las siguientes restricciones (a menos que el usuario sea root):
* No se pueden editar enlaces simbólicos.
* Si algún componente de la ruta que conduce al archivo es escribible por el usuario que invoca, el archivo no se puede editar.
* Los usuarios nunca tienen permitido editar archivos especiales de dispositivos.
Si el archivo especificado no existe, se creará. A diferencia de la mayoría de los comandos ejecutados por sudo, el editor se ejecuta con el entorno del usuario que invoca sin modificaciones. Si el archivo temporal queda vacío después de la edición, se le pedirá al usuario antes de que se instale.
-u usuario, --usuario=usuario
Ejecuta el comando como un usuario diferente al predeterminado (root).
-V, --versión
Muestra la versión actual de sudo-rs.
-v, --validar

DESCRIPCIÓN

sudo-rs se utiliza para ejecutar comandos como otro usuario (por defecto, el usuario root).

OPCIONES

-A, --ask-pass
Solicita la contraseña del usuario para actualizar el registro de la sesión, autenticando al usuario si es necesario.
-l, --list
Lista los privilegios del usuario o comprueba un comando específico; úsalo dos veces para un formato más largo.
-U, --other-user=usuario
Usado en modo de lista, muestra los privilegios de otro usuario.
--
Indica el final de las opciones de sudo-rs y el inicio del comando.

Las variables de entorno que se establecerán para el comando se pueden pasar en la línea de comandos en forma de VAR=valor. Las variables pasadas en la línea de comandos están sujetas a las restricciones impuestas por la política de seguridad. Las variables pasadas en la línea de comandos están sujetas a las mismas restricciones que las variables de entorno normales, con una excepción importante: si al comando que se va a ejecutar se le asigna la etiqueta SETENV o el comando coincide con ALL, el usuario puede establecer variables que de otro modo estarían prohibidas. Consulte sudoers(5) para obtener más información.
