SUPERMIN(1) Soporte de Virtualización SUPERMIN(1)

NOMBRE

supermin - Herramienta para crear y construir appliances supermin

SINOPSIS

supermin --prepare -o DIRECTORIO SALIDA PAQUETE [PAQUETE ...]
supermin --build -o DIRECTORIO SALIDA -f chroot|ext2 ENTRADA [ENTRADA ...]

EJEMPLO

supermin --prepare bash util-linux -o /tmp/supermin.d

cat > init <<EOF
#!/bin/sh
mount -t proc /proc /proc
mount -t sysfs /sys /sys
echo Bienvenido a supermin
bash -i
EOF

chmod +x init
tar zcf /tmp/supermin.d/init.tar.gz ./init

supermin --build /tmp/supermin.d -f ext2 -o /tmp/appliance.d

qemu-kvm -nodefaults -nographic \
         -kernel /tmp/appliance.d/kernel \
         -initrd /tmp/appliance.d/initrd \
         -hda /tmp/appliance.d/root \
         -serial stdio -append "console=ttyS0 root=/dev/sda"
...
Bienvenido a supermin
bash-4.3#

DESCRIPCIÓN

Supermin es una herramienta para construir appliances supermin. Estos son appliances diminutos (similares a máquinas virtuales), generalmente de alrededor de 100KB de tamaño, que se instancian completamente sobre la marcha en una fracción de segundo cuando se necesita arrancar uno de ellos.

Este programa solía llamarse febootstrap. Esta página del manual documenta supermin 5.x, que es una reescritura completa y bastante diferente de febootstrap 2.x. Si está buscando las herramientas de febootstrap 2.x, entonces este no es el lugar adecuado.

OPERACIÓN BÁSICA

La herramienta supermin se puede usar en dos modos: preparando un appliance supermin diminuto, lo que se hace en un sistema de compilación. Y construyendo, que toma el appliance supermin y construye un appliance completo y arrancable, lo que se hace en el sistema del usuario final.

Supermin no necesita ejecutarse como root, y generalmente no debería ejecutarse como root. No afecta al sistema anfitrión ni a los paquetes instalados en el sistema anfitrión.

MODO PREPARAR

--prepare crea el appliance supermin diminuto en el directorio de salida dado. Le proporciona una lista de paquetes que desea instalar, y supermin encontrará automáticamente las dependencias. La lista de paquetes debe estar instalada en la máquina anfitriona.

Por ejemplo:

supermin --prepare bash coreutils -o supermin.d

crea un appliance supermin que contiene los paquetes "bash" y "coreutils". Específicamente, crea algunos archivos en el directorio supermin.d. Este directorio es el appliance supermin. (Ver "APPLIANCES SUPERMIN" abajo).

Se pretende que el paso --prepare se haga en una máquina de compilación central, y el appliance supermin se distribuya a los usuarios finales (lo cual es fácil porque los appliances supermin son tan pequeños).

MODO CONSTRUIR

--build (anteriormente un programa separado llamado "supermin-helper") construye el appliance completo a partir del appliance supermin:

supermin --build --format ext2 supermin.d -o appliance.d

Esto creará archivos llamados appliance.d/kernel, appliance.d/root, etc., que es el appliance de tamaño completo arrancable.

Se pretende que el paso --build se realice en la máquina del usuario final en el último momento antes de que se necesite el appliance. Los paquetes del appliance supermin (los especificados cuando se preparó el appliance supermin) deben estar instalados en la máquina del usuario final.

Construir y caché

Normalmente querrás reconstruir el appliance en la máquina del usuario final solo bajo demanda. Supermin tiene opciones adicionales para facilitar esto:

supermin --build \
  --if-newer --lock /run/user/`id -u`/supermin.lock \
  --format ext2 supermin.d -o appliance.d

Si múltiples programas ejecutan este comando en paralelo, las instancias esperarán en el archivo de bloqueo. El appliance completo solo se reconstruirá si no existe o si es más antiguo que los archivos de entrada y la base de datos de paquetes del host.

Tenga en cuenta que el archivo de bloqueo no debe almacenarse dentro del directorio -o.

PAQUETES

Por "paquete" nos referimos al paquete RPM, Debian, (etc.), por ejemplo, "coreutils", "perl".

En todos los casos, supermin solo puede construir un appliance supermin que sea idéntico en distribución, versión y arquitectura al anfitrión. No realiza compilaciones cruzadas.

OPCIONES

--help
Muestra el uso breve de la línea de comandos y sale.
--build
Construye el appliance completo a partir del appliance supermin. Esto solía ser un programa separado llamado "supermin-helper".
--copy-kernel
(solo modo --build)

Copia el kernel (y el árbol de dispositivos, si se crea) en lugar de crear un enlace simbólico al kernel en /boot.

Esto es ligeramente más lento, pero es necesario si desea cambiar los permisos o la etiqueta SELinux del kernel o del árbol de dispositivos.

-f FORMATO
--format FORMATO
(solo modo --build)

Selecciona el formato de salida para el appliance completo.

No hay un valor predeterminado. Al usar --build, debes especificar la opción --format.

Los formatos posibles son:

chroot
Un árbol de directorios en el sistema de archivos del host.

El árbol del sistema de archivos se escribe en DIRECTORIO SALIDA (es decir, la opción -o).

Esto se llama "chroot" porque podrías literalmente hacer chroot(1) en este directorio después, aunque es una mejor idea usar una tecnología de contenedor (LXC, etc.).

No se genera kernel ni initrd en este modo porque se asume que ejecutarás el appliance usando el kernel del host.

ext2
Una imagen de disco de sistema de archivos ext2.

El kernel de salida se escribe en DIRECTORIO SALIDA/kernel, un pequeño initramfs que puede montar el appliance en DIRECTORIO SALIDA/initrd, y la imagen del sistema de archivos ext2 en DIRECTORIO SALIDA/root. (Donde DIRECTORIO SALIDA se especifica con la opción -o).

El sistema de archivos (DIRECTORIO SALIDA/root) tiene un tamaño predeterminado de 4 GB (ver también la opción --size).

--host-cpu CPU
(solo modo --build)

Especifica la CPU del host (ej. "i686", "x86_64"). Esto se usa como una coincidencia de subcadena al buscar kernels compatibles. Si no se especifica, por defecto es la CPU del host en la que se compiló supermin.

--if-newer
(solo modo --build)

Se verifica el directorio de salida y no se reconstruye a menos que sea necesario.

Esto se hace consultando las fechas de la base de datos de paquetes del host (/var/lib/rpm etc), los archivos supermin de entrada y el directorio de salida. La operación solo se realiza si la base de datos de paquetes del host o los archivos supermin de entrada son más recientes que el directorio de salida.

Ver también --lock abajo.

--include-packagelist
(solo modo --build)

Agrega un archivo /packagelist dentro del chroot generado o el sistema de archivos ext2, que contiene una lista ordenada de todos los paquetes utilizados para construir el appliance.

Principalmente útil para depuración, ya que facilita averiguar, por ejemplo, qué versión de un paquete se copió en el appliance.

--list-drivers
Lista los controladores del gestor de paquetes compilados en supermin y si el gestor de paquetes correspondiente se detecta en el sistema actual.
--lock ARCHIVOBLOQUEO
(solo modo --build)

Si múltiples ejecuciones paralelas de supermin necesitan construir un appliance completo, entonces

--lock LOCKFILE
Specify the lock file. Use the --lock option to ensure that they do not stomp on each other.

The lock file is used to provide mutual exclusion so only one instance of supermin will run at a time.

Note that the lock file must not be stored inside the output directory.

-o DIRECTORIOSALIDA
Seleccione el directorio de salida.

Al usar --prepare, este es el directorio donde se escribirá el appliance supermin. Al usar --build, este es el directorio donde se escribirán el appliance completo, el kernel, etc.

Cualquier contenido previo del directorio de salida se elimina, y se crea un nuevo directorio de salida.

El directorio de salida se crea (casi) de forma atómica construyendo un directorio temporal llamado algo como DIRECTORIOSALIDA.abc543, luego se renombra el directorio de salida antiguo (si existe) y se elimina, y luego se renombra el directorio temporal a DIRECTORIOSALIDA. Al combinar esta opción con --lock puede asegurarse de que múltiples ejecuciones paralelas de supermin no entren en conflicto.

--packager-config ARCHIVOCONFIGURACION
(solo modo --prepare)

Establezca el archivo de configuración para el gestor de paquetes. Esto le permite especificar repositorios de software alternativos.

Para ArchLinux, esto establece el archivo de configuración de pacman (predeterminado /etc/pacman.conf). Ver pacman.conf(5).

Para distribuciones Yum/RPM, esto establece el archivo de configuración de yum (predeterminado /etc/yum.conf). Ver yum.conf(5).

--prepare
Prepara el appliance supermin.
--use-installed
(solo modo --prepare)

Si los paquetes ya están instalados, use los contenidos (del sistema de archivos local) en lugar de descargarlos.

Tenga en cuenta que esto puede causar appliances mal formados si los archivos locales han sido modificados desde lo que originalmente estaba en el paquete. Esto es particularmente un problema para los archivos de configuración.

Sin embargo, esta opción es útil en algunas situaciones controladas: por ejemplo, cuando se usa supermin dentro de un chroot recién instalado, o si no tiene acceso a la red durante la compilación.

--size TAMANO
(solo modo --build)

Seleccione el tamaño del sistema de archivos ext2 de salida, donde el tamaño puede especificarse usando nombres comunes como "32G" (32 gigabytes), etc.

Si no se especifica el tamaño, se utiliza un tamaño predeterminado de 4 GB.

Para especificar el tamaño en bytes, el número debe ir seguido de la letra minúscula b, por ejemplo: "--size 10737418240b".

-v
--verbose
Habilita mensajes detallados.

Puede dar esta opción varias veces para habilitar aún más mensajes:

-v
Depuración de etapas generales.
-v -v
Información detallada dentro de cada etapa.
-v -v -v
Cantidades masivas de depuración (demasiado para un uso normal, pero útil si está intentando diagnosticar un error en supermin).
-V
--version
Imprime el nombre y número de versión del paquete, y sale.

APPLIANCES SUPERMIN

Los appliances supermin consisten en la información justa y necesaria para poder construir un appliance que contenga el mismo sistema operativo (versión de Linux, distro, release, etc.) que el sistema operativo host. Dado que el host y el appliance comparten muchos archivos comunes como /bin/bash y /lib/libc.so, no hay razón para enviar estos archivos en el appliance. Simplemente se pueden leer del host bajo demanda cuando se lanza el appliance. Por lo tanto, para ahorrar espacio, solo almacenamos los nombres de los paquetes que queremos del host y los copiamos (más dependencias) en el momento de la compilación.

Hay algunos archivos que no se pueden simplemente copiar del host de esta manera. Estos incluyen archivos de configuración que el administrador del host podría haber editado. Así, junto con la lista de archivos del host, también almacenamos una imagen base esquelética que contiene estos archivos y la estructura de directorios.

Por lo tanto, el appliance supermin normalmente consta de al menos dos archivos de control (packages y base.tar.gz).

packages
La lista de paquetes a copiar desde el host. Las dependencias se resuelven automáticamente.

El archivo es de texto plano, un nombre de paquete por línea.

base.tar
base.tar.gz
Este archivo tar (que puede estar comprimido) contiene el sistema de archivos esquelético. Principalmente contiene directorios y algunos archivos de configuración.

Todas las rutas en el archivo tar deben ser relativas al directorio raíz del appliance.

hostfiles
Cualquier otro archivo que deba copiarse desde el host. Este es un archivo de texto plano con un nombre de ruta por línea.

Las rutas pueden contener comodines, que se expanden cuando se crea el appliance, por ejemplo:

/etc/yum.repos.d/*.repo

copiaría todos los archivos *.repo en el appliance.

Cada nombre de ruta en el archivo debe comenzar con un carácter "/".

Supermin en sí mismo no crea hostfiles (aunque antes de la versión 5, este era el principal mecanismo utilizado para crear el appliance completo). Sin embargo, puede colocar uno o más de estos archivos en el directorio supermin si desea copiar archivos aleatorios sin empaquetar en el appliance completo.

excludefiles
Una lista de nombres de archivo, nombres de directorio o comodines prefijados con "-" que se excluyen del appliance final.

Esto es bastante drástico ya que simplemente elimina cosas, potencialmente rompiendo paquetes. Sin embargo, puede usarse como una forma conveniente de minimizar el tamaño del appliance final.

Supermin en sí mismo no crea excludefiles. Sin embargo, puede colocar uno o más de estos archivos en el directorio supermin para evitar que los archivos empaquetados se copien en el appliance completo.

Tenga en cuenta que los nombres anteriores son solo sugerencias. Puede usar los nombres que desee, ya que supermin detecta el contenido de cada archivo al reconstruir el appliance. También puede tener múltiples de cada tipo de archivo.

RECONSTRUCCIÓN DEL APPLIANCE

El modo separado "supermin --build" se utiliza para reconstruir un appliance a partir de los archivos del appliance supermin.

Este programa, de hecho, itera recursivamente sobre los archivos y directorios que se le pasan. Una disposición común podría verse así:

supermin.d/
supermin.d/base.tar.gz
supermin.d/extra.tar.gz
supermin.d/packages
supermin.d/zz-hostfiles

De esta manera, se pueden agregar archivos adicionales al appliance simplemente creando otro archivo tar (extra.tar.gz en el ejemplo anterior) y colocándolo en el directorio, y se pueden agregar archivos de host adicionales (zz-hostfiles en el ejemplo anterior). Cuando se construye el appliance, los archivos adicionales aparecerán en el appliance.

MINIMIZACIÓN DEL APPLIANCE SUPERMIN

Es posible que desee "minimizar" el appliance supermin para ahorrar tiempo y espacio cuando se instancia. Típicamente, es posible que desee eliminar documentación, archivos info, páginas de manual y locales.

Puede hacerlo creando un archivo excludefiles que enumere archivos, directorios o comodines que no desee incluir. Se omiten cuando se compila el appliance completo.

-/boot/*
-/lib/modules/*
-/usr/share/doc/*
-/usr/share/info/*
-/usr/share/man/*

Tenga cuidado con lo que elimina, ya que los archivos pueden ser necesarios para el funcionamiento correcto del appliance.

KERNEL Y MÓDULOS DEL KERNEL

Generalmente, el kernel y los módulos del kernel *no* se incluyen en el appliance supermin.

Cuando se compila el appliance completo, los módulos del kernel del host se copian y se arranca utilizando el kernel del host.

USO DE UN KERNEL Y MÓDULOS DEL KERNEL PERSONALIZADOS

Supermin puede elegir el mejor kernel del host disponible para arrancar el appliance. Sin embargo, puede anular esto estableciendo variables de entorno (ver "VARIABLES DE ENTORNO" a continuación).

Si compila un kernel personalizado (por ejemplo, compilando Linux desde fuente), debería hacer algo como esto:

mkdir /tmp/kmods
make bzImage
make modules
make modules_install INSTALL_MOD_PATH=/tmp/kmods

export SUPERMIN_KERNEL=/path/to/linux.git/arch/x86/boot/bzImage
export SUPERMIN_MODULES=/tmp/kmods/lib/modules/3.xx.yy

supermin --build -f ext2 [etc]

GARANTIZAR LA DISPONIBILIDAD DE PAQUETES

Supermin construye el appliance copiando los paquetes listados en packages. Para que esto funcione, esos paquetes deben estar disponibles. Normalmente, lo garantizamos añadiendo requisitos (por ejemplo, líneas "Requires:" de RPM) en el paquete que utiliza el appliance supermin, de modo que ese paquete no se pueda instalar sin incluir los paquetes dependientes y así asegurarse de que los paquetes están instalados para que supermin los use.

VARIABLES DE ENTORNO

SUPERMIN_KERNEL
Si esta variable de entorno está establecida, se omite la selección automática del kernel y se utiliza este kernel.

La variable de entorno debe apuntar a un archivo de kernel, por ejemplo, /boot/vmlinuz-3.0.x86_64

SUPERMIN_MODULES
Esto especifica el directorio de módulos del kernel a utilizar.

La variable de entorno debe apuntar a un directorio de módulos, por ejemplo, /lib/modules/3.0.x86_64/

SUPERMIN_KERNEL_VERSION
En arquitecturas no x86, es posible que necesite establecer esta variable de entorno si supermin no puede determinar la versión del kernel de "SUPERMIN_KERNEL" simplemente mirando el archivo.
