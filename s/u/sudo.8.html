Licencias: custom

SUDO(8) Manual del Administrador del Sistema SUDO(8)

NOMBRE

sudo, sudoedit — ejecutar un comando como otro usuario

SINOPSIS

sudo -h | -K | -k | -V

sudo -v [-ABkNnS] [-g grupo] [-h host] [-p prompt] [-u usuario]

sudo -l [-ABkNnS] [-g grupo] [-h host] [-p prompt] [-U usuario] [-u usuario] [comando [arg ...]]

sudo [-ABbEHnPS] [-C num] [-D directorio] [-g grupo] [-h host] [-p prompt] [-R directorio] [-T timeout] [-u usuario] [VAR=valor] [-i | -s] [comando [arg ...]]

sudoedit [-ABkNnS] [-C num] [-D directorio] [-g grupo] [-h host] [-p prompt] [-R directorio] [-T timeout] [-u usuario] archivo ...

DESCRIPCIÓN

sudo permite a un usuario autorizado ejecutar un comando como el superusuario u otro usuario, según lo especificado por la política de seguridad. El ID de usuario real del usuario que invoca (no el ID de usuario efectivo) se utiliza para determinar el nombre de usuario con el que consultar la política de seguridad.

sudo admite una arquitectura de plugins para políticas de seguridad, auditoría y registro de entrada/salida. Terceros pueden desarrollar y distribuir sus propios plugins para que funcionen sin problemas con el frontend de sudo. La política de seguridad predeterminada es sudoers, que se configura a través del archivo /etc/sudoers, o a través de LDAP. Consulte la sección Plugins para obtener más información.

La política de seguridad determina qué privilegios, si los hay, tiene un usuario para ejecutar sudo. La política puede requerir que los usuarios se autentiquen con una contraseña u otro mecanismo de autenticación. Si se requiere autenticación, sudo saldrá si la contraseña del usuario no se introduce dentro de un límite de tiempo configurable. Este límite depende de la política; el tiempo de espera predeterminado para la solicitud de contraseña para la política de seguridad sudoers es de 5 minutos.

Las políticas de seguridad pueden admitir el almacenamiento en caché de credenciales para permitir al usuario ejecutar sudo nuevamente durante un período de tiempo sin requerir autenticación. Por defecto, la política sudoers almacena en caché las credenciales por terminal durante 5 minutos. Consulte las opciones timestamp_type y timestamp_timeout en sudoers(5) para obtener más información. Al ejecutar sudo con la opción -v, un usuario puede actualizar las credenciales almacenadas en caché sin ejecutar un comando.

En sistemas donde sudo es el método principal para obtener privilegios de superusuario, es imperativo evitar errores de sintaxis en los archivos de configuración de la política de seguridad. Para la política de seguridad predeterminada, sudoers(5), los cambios en los archivos de configuración deben realizarse utilizando la utilidad visudo(8), que garantizará que no se introduzcan errores de sintaxis.

Cuando se invoca como sudoedit, se implica la opción -e (descrita a continuación).

Las políticas de seguridad y los plugins de auditoría pueden registrar los intentos exitosos y fallidos de ejecutar sudo. Si se configura un plugin de E/S, la entrada y salida del comando en ejecución también pueden registrarse.

Las opciones son las siguientes:

-A, --askpass
Normalmente, si sudo requiere una contraseña, la leerá desde la terminal del usuario. Si se especifica la opción -A (askpass), se ejecutará un programa auxiliar (posiblemente gráfico) para leer la contraseña del usuario y mostrarla en la salida estándar. Si la variable de entorno SUDO_ASKPASS está establecida, especifica la ruta al programa auxiliar. De lo contrario, si sudo.conf(5) contiene una línea que especifica el programa askpass, se utilizará ese valor. Por ejemplo: 
# Ruta al programa auxiliar askpass
Path askpass /usr/X11R6/bin/ssh-askpass

Si no hay un programa askpass disponible, sudo saldrá con un error.

-B, --bell
Hacer sonar la campana como parte de la solicitud de contraseña cuando hay una terminal presente. Esta opción no tiene efecto si se utiliza un programa askpass.
-b, --background
Ejecutar el comando dado en segundo plano. No es posible utilizar el control de trabajos del shell para manipular procesos en segundo plano iniciados por sudo. La mayoría de los comandos interactivos no funcionarán correctamente en modo de segundo plano.
-C num, --close-from=num
Cerrar todos los descriptores de archivo mayores o iguales a num antes de ejecutar un comando. No se permiten valores menores que tres. Por defecto, sudo cerrará todos los descriptores de archivo abiertos distintos de la entrada estándar, la salida estándar y el error estándar al ejecutar un comando. La política de seguridad puede restringir la capacidad del usuario para usar esta opción. La política sudoers solo permite el uso de la opción -C cuando el administrador ha habilitado la opción closefrom_override.
-D directorio, --chdir=directorio
Ejecutar el comando en el directorio especificado en lugar del directorio de trabajo actual. La política de seguridad puede devolver un error si el usuario no tiene permiso para especificar el directorio de trabajo.
-E, --preserve-env
Indica a la política de seguridad que el usuario desea conservar sus variables de entorno existentes. La política de seguridad puede devolver un error si el usuario no tiene permiso para conservar el entorno.
=list">--preserve-env=list
Indica a la política de seguridad que el usuario desea añadir la lista de variables de entorno separadas por comas a aquellas preservadas del entorno del usuario. La política de seguridad puede devolver un error si el usuario no tiene permiso para preservar el entorno. Esta opción puede especificarse varias veces.
-e, --edit
Edita uno o más archivos en lugar de ejecutar un comando. En lugar de un nombre de ruta, se utiliza la cadena "sudoedit" al consultar la política de seguridad. Si el usuario está autorizado por la política, se realizan los siguientes pasos:
  1. Se crean copias temporales de los archivos a editar con el propietario establecido al usuario que invoca.
  2. Se ejecuta el editor especificado por la política para editar los archivos temporales. La política de sudoers utiliza las variables de entorno SUDO_EDITOR, VISUAL y EDITOR (en ese orden). Si ninguna de las variables SUDO_EDITOR, VISUAL o EDITOR está establecida, se utiliza el primer programa listado en la opción editor de sudoers(5).
  3. Si han sido modificados, las copias temporales se copian de nuevo a su ubicación original y se eliminan las versiones temporales.

Para ayudar a prevenir la edición de archivos no autorizados, las siguientes restricciones se aplican a menos que se permitan explícitamente por la política de seguridad:

  • No se pueden editar enlaces simbólicos (versión 1.8.15 y superior).
  • No se siguen los enlaces simbólicos en la ruta a editar al escribir en el directorio padre si el usuario que invoca tiene permisos de escritura, a menos que ese usuario sea root (versión 1.8.16 y superior).
  • No se pueden editar archivos ubicados en un directorio que sea escribible por el usuario que invoca, a menos que ese usuario sea root (versión 1.8.16 y superior).

Los usuarios nunca tienen permitido editar archivos especiales de dispositivo.

Si el archivo especificado no existe, se creará. A diferencia de la mayoría de los comandos ejecutados por sudo, el editor se ejecuta con el entorno del usuario que invoca sin modificaciones. Si el archivo temporal queda vacío después de editarlo, se le pedirá al usuario que confirme su instalación. Si, por alguna razón, sudo no puede actualizar un archivo con su versión editada, el usuario recibirá una advertencia y la copia editada permanecerá en un archivo temporal.

-g grupo, --group=grupo
Ejecuta el comando con el grupo principal establecido en grupo en lugar del grupo principal especificado en la entrada de la base de datos de contraseñas del usuario de destino. El grupo puede ser un nombre de grupo o un ID de grupo numérico (GID) precedido por el carácter ‘#’ (por ejemplo, ‘#0’ para GID 0). Al ejecutar un comando como GID, muchos shells requieren que el ‘#’ sea escapado con una barra invertida (‘\’). Si no se especifica la opción -u, el comando se ejecutará como el usuario que invoca. En cualquier caso, el grupo principal se establecerá en grupo. La política de sudoers permite especificar cualquiera de los grupos del usuario de destino a través de la opción -g siempre que la opción -P no esté en uso.
-H, --set-home
Solicita que la política de seguridad establezca la variable de entorno HOME en el directorio de inicio especificado en la entrada de la base de datos de contraseñas del usuario de destino. Dependiendo de la política, este puede ser el comportamiento predeterminado.
-h, --help
Muestra un breve mensaje de ayuda en la salida estándar y sale.
-h host, --host=host
Ejecuta el comando en el host especificado si el plugin de política de seguridad admite comandos remotos. El plugin de sudoers no admite actualmente la ejecución de comandos remotos. Esto también se puede usar en conjunto con la opción -l para enumerar los privilegios de un usuario para el host remoto.
-i, --login
Ejecuta el shell especificado en la entrada de la base de datos de contraseñas del usuario de destino como un shell de inicio de sesión. Esto significa que los archivos de recursos específicos del inicio de sesión como .profile, .bash_profile, o .login serán leídos por el shell. Si se especifica un comando, se pasa al shell como un simple comando utilizando la opción -c. El comando y sus arg se concatenan, separados por espacios, después de escapar cada carácter (incluyendo espacios en blanco) con una barra invertida (‘\’) excepto alfanuméricos, guiones bajos, guiones e signos de dólar. Si no se especifica ningún comando, se ejecuta un shell interactivo. sudo intenta cambiar al directorio de inicio de ese usuario antes de ejecutar el shell. El comando se ejecuta con un entorno similar al que un usuario recibiría al iniciar sesión. La mayoría de los shells se comportan de manera diferente cuando se especifica un comando en comparación con una sesión interactiva; consulte el manual del shell para obtener detalles. La sección Entorno del comando en el manual de sudoers(5) documenta cómo la opción -i afecta al entorno en el que se ejecuta un comando cuando se utiliza la política de sudoers.
-K, --remove-timestamp
Similar a la opción -k, excepto que elimina todas las credenciales en caché del usuario, independientemente de la terminal o el ID del proceso padre. La próxima vez que se ejecute sudo, se deberá ingresar una contraseña si la política de seguridad requiere autenticación. No es posible usar la opción -K en conjunción con un comando u otra opción. Esta opción no requiere contraseña. No todas las políticas de seguridad admiten el almacenamiento en caché de credenciales.
-k, --reset-timestamp
Cuando se usa sin un comando, invalida las credenciales en caché del usuario para la sesión actual. La próxima vez que se ejecute sudo en la sesión, se deberá ingresar una contraseña si la política de seguridad requiere autenticación. Por defecto, la política de sudoers utiliza un registro separado en la caché de credenciales para cada terminal (o ID de proceso padre si no hay terminal presente). Esto evita que la opción -k interfiera con los comandos sudo ejecutados en una sesión de terminal diferente. Consulte la opción timestamp_type en sudoers(5) para obtener más información. Esta opción no requiere contraseña y se añadió para permitir que un usuario revoque los permisos de sudo desde un archivo .logout.

Cuando se usa en conjunción con un comando o una opción que pueda requerir una contraseña, esta opción hará que sudo ignore las credenciales en caché del usuario. Como resultado, sudo solicitará una contraseña (si la política de seguridad la requiere) y no actualizará las credenciales en caché del usuario.

No todas las políticas de seguridad admiten el almacenamiento en caché de credenciales.

-l, --list
Si no se especifica ningún comando, enumera los privilegios del usuario que invoca (o el usuario especificado por la opción -U) en el host actual. Se utiliza un formato de lista más largo si esta opción se especifica varias veces y la política de seguridad admite un formato de salida detallado.

Si se especifica un comando y está permitido por la política de seguridad para el usuario que invoca (o el usuario especificado por la opción -U) en el host actual, se mostrará la ruta completa al comando junto con sus args. Si se especifica -l más de una vez (y la política de seguridad lo admite), la regla coincidente se mostrará en formato detallado junto con el comando. Si se especifica un comando pero no está permitido por la política, sudo saldrá con un valor de estado de 1.

-N, --no-update
No actualiza las credenciales en caché del usuario, incluso si el usuario se autentica correctamente. A diferencia de la bandera -k, se utilizan las credenciales en caché existentes si son válidas. Para detectar cuándo las credenciales en caché del usuario son válidas (o cuándo no se requiere autenticación), se puede utilizar lo siguiente: 
sudo -Nnv

No todas las políticas de seguridad admiten el almacenamiento en caché de credenciales.

-n, --non-interactive
Evita solicitar al usuario cualquier tipo de entrada. Si se requiere una contraseña para que se ejecute el comando, sudo mostrará un mensaje de error y saldrá.
-P, --preserve-groups
Conserva el vector de grupos del usuario que invoca sin modificar. Por defecto, la política de sudoers inicializará el vector de grupos con la lista de grupos de los que el usuario destino es miembro. Sin embargo, los IDs de grupo reales y efectivos se seguirán configurando para que coincidan con el usuario destino.
-p prompt, --prompt=prompt
Utiliza un aviso de contraseña personalizado con secuencias de escape opcionales. Las siguientes secuencias de escape de porcentaje (‘%’) son compatibles con la política de sudoers:
%H
se expande al nombre del host incluyendo el nombre de dominio (solo si el nombre de host de la máquina está completamente cualificado o la opción fqdn está establecida en sudoers(5))
%h
se expande al nombre del host local sin el nombre de dominio
%p
se expande al nombre del usuario cuya contraseña se está solicitando (respeta las opciones rootpw, targetpw y runaspw en sudoers(5))
%U
se expande al nombre de inicio de sesión del usuario con el que se ejecutará el comando (por defecto es root a menos que también se especifique la opción -u)
%u
se expande al nombre de inicio de sesión del usuario que invoca
%%
dos caracteres ‘%’ consecutivos se contraen en un único carácter ‘%’

El aviso personalizado anulará el aviso por defecto especificado por la política de seguridad o la variable de entorno SUDO_PROMPT. En sistemas que utilizan PAM, el aviso personalizado también anulará el aviso especificado por un módulo PAM a menos que la opción passprompt_override esté deshabilitada en sudoers.

-R directorio, --chroot=directorio
Cambia al directorio raíz especificado directory (ver chroot(8)) antes de ejecutar el comando. La política de seguridad puede devolver un error si el usuario no tiene permiso para especificar el directorio raíz.

Esta opción está obsoleta y se eliminará en una futura versión de sudo.

-S, --stdin
Escribe el aviso en la salida de error estándar y lee la contraseña de la entrada estándar en lugar de usar el dispositivo de terminal.
-s, --shell
Ejecuta el shell especificado por la variable de entorno SHELL si está establecida o el shell especificado en la entrada de la base de datos de contraseñas del usuario que invoca. Si se especifica un comando, se pasa al shell como un comando simple utilizando la opción -c. El comando y cualquier arg se concatenan, separados por espacios, después de escapar cada carácter (incluido el espacio en blanco) con una barra invertida (‘\’) excepto alfanuméricos, guiones bajos, guiones y signos de dólar. Si no se especifica ningún comando, se ejecuta un shell interactivo. La mayoría de los shells se comportan de forma diferente cuando se especifica un comando en comparación con una sesión interactiva; consulte el manual del shell para obtener detalles.
-U usuario, --other-user=usuario
Se utiliza junto con la opción -l para listar los privilegios del usuario en lugar de los del usuario que invoca. La política de seguridad puede restringir la enumeración de privilegios de otros usuarios. Al utilizar la política de sudoers, la opción -U está restringida al usuario root y a los usuarios que tengan el privilegio de "listar" para el usuario especificado o la capacidad de ejecutar cualquier comando como root o como usuario en el host actual.
-T timeout, --command-timeout=timeout
Se utiliza para establecer un tiempo de espera para el comando. Si expira el tiempo de espera antes de que el comando haya terminado, el comando será terminado. La política de seguridad puede restringir la capacidad del usuario para establecer tiempos de espera. La política de sudoers requiere que los tiempos de espera especificados por el usuario estén explícitamente habilitados.
-u usuario, --user=usuario
Ejecuta el comando como un usuario distinto del usuario destino por defecto (normalmente root). El usuario puede ser un nombre de usuario o un ID numérico de usuario (UID) precedido por el carácter ‘#’ (por ejemplo, ‘#0’ para UID 0). Al ejecutar comandos como UID, muchos shells requieren que el ‘#’ se escape con una barra invertida (‘\’). Algunas políticas de seguridad pueden restringir los UID a los listados en la base de datos de contraseñas. La política de sudoers permite UID que no están en la base de datos de contraseñas siempre que la opción targetpw no esté establecida. Otras políticas de seguridad pueden no admitir esto.
-V, --version
Imprime la cadena de versión de sudo así como la cadena de versión de cualquier plugin configurado. Si el usuario que invoca ya es root, la opción -V mostrará las opciones pasadas a configure cuando se compiló sudo; los plugins pueden mostrar información adicional como opciones por defecto.
-v, --validate
Actualiza las credenciales en caché del usuario, autenticando al usuario si es necesario. Para el plugin de sudoers, esto extiende el tiempo de espera de sudo durante 5 minutos adicionales por defecto, pero no ejecuta un comando. No todas las políticas de seguridad admiten credenciales en caché.
--
El -- se utiliza para delimitar el final de las opciones de sudo. Las opciones subsiguientes se pasan al comando.

Las opciones que toman un valor solo pueden especificarse una vez, a menos que se indique lo contrario en la descripción. Esto es para ayudar a proteger contra problemas causados por scripts mal escritos que invocan sudo con entrada controlada por el usuario.

Las variables de entorno que se establecerán para el comando también se pueden pasar como opciones a sudo en el formato VAR=valor, por ejemplo LD_LIBRARY_PATH=/usr/local/pkg/lib. Las variables de entorno pueden estar sujetas a restricciones impuestas por el plugin de política de seguridad. La política de sudoers somete las variables de entorno pasadas como opciones a las mismas restricciones que las variables de entorno existentes, con una diferencia importante. Si la opción setenv está establecida en sudoers, el comando a ejecutar tiene la etiqueta SETENV establecida o el comando que coincide es ALL, el usuario puede establecer variables que de otro modo estarían prohibidas. Consulte sudoers(5) para obtener más información.

EJECUCION DE COMANDOS

Cuando sudo ejecuta un comando, la política de seguridad especifica el entorno de ejecución para el comando. Típicamente, los IDs de usuario y grupo reales y efectivos se establecen para que coincidan con los del usuario destino, como se especifica en la base de datos de contraseñas, y el vector de grupo se inicializa basándose en la base de datos de grupos (a menos que se haya especificado la opción -P).

Los siguientes parámetros pueden ser especificados por la política de seguridad:

  • ID de usuario real y efectivo
  • ID de grupo real y efectivo
  • IDs de grupo suplementarios
  • la lista de entorno
  • directorio de trabajo actual
  • máscara del modo de creación de archivos (umask)
  • prioridad de planificación (también conocido como valor nice)

Modelo de proceso

Hay dos formas distintas en que sudo puede ejecutar un comando.

Si un plugin de registro de E/S está configurado para registrar E/S de terminal, o si la política de seguridad lo solicita explícitamente, se asigna una nueva pseudo-terminal ("pty") y se utiliza fork(2) para crear un segundo proceso de sudo, denominado el monitor. El monitor crea una nueva sesión de terminal con él mismo como líder y el pty como su terminal de control, llama a fork(2) de nuevo, configura el entorno de ejecución como se describe arriba, y luego utiliza la llamada al sistema execve(2) para ejecutar el comando en el proceso hijo. El monitor existe para transmitir señales de control de trabajos entre la terminal del usuario y el pty en el que se está ejecutando el comando. Esto hace posible suspender y reanudar el comando normalmente. Sin el monitor, el comando estaría en lo que POSIX denomina un "grupo de procesos huérfano" y no recibiría ninguna señal de control de trabajos del kernel. Cuando el >comando sale o es terminado por una señal, el monitor pasa el estado de salida del comando al proceso principal de sudo y sale. Después de recibir el estado de salida del comando, el proceso principal de sudo pasa el estado de salida del comando a la función de cierre de la política de seguridad, así como a la función de cierre de cualquier plugin de auditoría configurado, y sale. Este modo es el predeterminado para las versiones de sudo 1.9.14 y posteriores cuando se utiliza la política sudoers.

Si no se utiliza una pty, sudo llama a fork(2), configura el entorno de ejecución como se describe anteriormente y utiliza la llamada al sistema execve(2) para ejecutar el comando en el proceso hijo. El proceso principal de sudo espera hasta que el comando haya completado, luego pasa el estado de salida del comando a la función de cierre de la política de seguridad, así como a la función de cierre de cualquier plugin de auditoría configurado, y sale. Como caso especial, si el plugin de política no define una función de cierre, sudo ejecutará el comando directamente en lugar de llamar primero a fork(2). El plugin de política de sudoers solo definirá una función de cierre cuando el registro de E/S esté habilitado, se requiera una pty, se especifique un rol SELinux, el comando tenga un tiempo de espera asociado, o las opciones pam_session o pam_setcred estén habilitadas. Tanto pam_session como pam_setcred están habilitados por defecto en sistemas que usan PAM. Este modo es el predeterminado para las versiones de sudo anteriores a 1.9.14 cuando se utiliza la política sudoers.

En sistemas que usan PAM, la función de cierre de la política de seguridad es responsable de cerrar la sesión PAM. También puede registrar el estado de salida del comando.

Manejo de señales

Cuando el comando se ejecuta como hijo del proceso sudo, sudo retransmitirá las señales que reciba al comando. Las señales SIGINT y SIGQUIT solo se retransmiten cuando el comando se está ejecutando en una nueva pty o cuando la señal fue enviada por un proceso de usuario, no por el kernel. Esto evita que el comando reciba SIGINT dos veces cada vez que el usuario introduce control-C. Algunas señales, como SIGSTOP y SIGKILL, no se pueden capturar y, por lo tanto, no se retransmitirán al comando. Como regla general, se debe usar SIGTSTP en lugar de SIGSTOP cuando se desee suspender un comando ejecutado por sudo.

Como caso especial, sudo no retransmitirá las señales que fueron enviadas por el comando que está ejecutando. Esto evita que el comando se mate accidentalmente. En algunos sistemas, la utilidad reboot(8) envía SIGTERM a todos los procesos no del sistema, excepto a sí misma, antes de reiniciar el sistema. Esto evita que sudo retransmita la señal SIGTERM que recibió de vuelta a reboot(8), lo que podría hacer que este saliera antes de que el sistema se reiniciara realmente, dejándolo en un estado semi-muerto similar al modo de un solo usuario. Tenga en cuenta, sin embargo, que esta comprobación solo se aplica al comando ejecutado por sudo y no a ningún otro proceso que el comando pueda crear. Como resultado, ejecutar un script que llama a reboot(8) o shutdown(8) a través de sudo puede hacer que el sistema termine en este estado indefinido, a menos que reboot(8) o shutdown(8) se ejecuten utilizando la familia de funciones exec() en lugar de system() (que interpone un shell entre el comando y el proceso que llama).

Plugins

Los plugins pueden especificarse mediante directivas de Plugin en el archivo sudo.conf(5). Pueden cargarse como objetos compartidos dinámicos (en sistemas que los admiten) o compilarse directamente en el binario de sudo. Si no hay un archivo sudo.conf(5) presente, o si no contiene ninguna línea de Plugin, sudo utilizará sudoers(5) para los plugins de política, auditoría y registro de E/S. Consulte el manual de sudo.conf(5) para obtener detalles sobre el archivo /etc/sudo.conf y el manual de sudo_plugin(5) para obtener más información sobre la arquitectura de plugins de sudo.

VALOR DE SALIDA

Tras la ejecución exitosa de un comando, el estado de salida de sudo será el estado de salida del programa que se ejecutó. Si el comando terminó debido a la recepción de una señal, sudo se enviará a sí mismo la misma señal que terminó el comando.

Si se especificó la opción -l sin un comando, sudo saldrá con un valor de 0 si al usuario se le permite ejecutar sudo y se autenticó correctamente (según lo requerido por la política de seguridad). Si se especifica un comando con la opción -l, el valor de salida solo será 0 si el comando está permitido por la política de seguridad, de lo contrario será 1.

Si hay un fallo de autenticación, un problema de configuración/permisos, o si el comando proporcionado no puede ser ejecutado, sudo sale con un valor de 1. En este último caso, la cadena de error se imprime en la salida estándar de error. Si sudo no puede stat(2) una o más entradas en el PATH del usuario, se imprime un error en la salida estándar de error. (Si el directorio no existe o si realmente no es un directorio, la entrada se ignora y no se imprime ningún error). Esto no debería suceder en circunstancias normales. La razón más común para que stat(2) devuelva "permiso denegado" es si está utilizando un montador automático y uno de los directorios en su PATH está en una máquina que actualmente no es accesible.

NOTAS DE SEGURIDAD

sudo intenta ser seguro al ejecutar comandos externos.

Para evitar la suplantación de comandos, sudo comprueba "." y "" (ambos denotan el directorio actual) en último lugar al buscar un comando en el PATH del usuario (si uno o ambos están en el PATH). Dependiendo de la política de seguridad, la variable de entorno PATH del usuario puede ser modificada, reemplazada o pasada sin cambios al programa que ejecuta sudo.

Los usuarios nunca deben tener privilegios de sudo para ejecutar archivos que sean escribibles por el usuario o que residan en un directorio que sea escribible por el usuario. Si el usuario puede modificar o reemplazar el comando, no hay forma de limitar qué comandos adicionales pueden ejecutar.

Por defecto, sudo solo registrará el comando que ejecuta explícitamente. Si un usuario ejecuta un comando como ' sudo su' o ' sudo sh', los comandos subsiguientes ejecutados desde ese shell no estarán sujetos a la política de seguridad de sudo. Lo mismo ocurre con los comandos que ofrecen escapes de shell (incluyendo la mayoría de los editores). Si el registro de E/S está habilitado, los comandos subsiguientes tendrán su entrada y/o salida registrada, pero no habrá registros tradicionales para esos comandos. Debido a esto, se debe tener cuidado al dar acceso a los usuarios a comandos a través de sudo para verificar que el comando no le dé inadvertidamente al usuario un shell root efectivo. Para obtener información sobre formas de abordar esto, consulte la sección Prevención de escapes de shell en sudoers(5).

Para evitar la divulgación de información potencialmente sensible, sudo deshabilita las volcados de núcleo por defecto mientras se está ejecutando (se vuelven a habilitar para el comando que se ejecuta). Esta práctica histórica se remonta a una época en la que la mayoría de los sistemas operativos permitían volcados de núcleo por defecto para procesos set-user-ID. Para ayudar a depurar las caídas de sudo, puede desear volver a habilitar los volcados de núcleo estableciendo "disable_coredump" en falso en el archivo sudo.conf(5) de la siguiente manera:

Set disable_coredump false

Consulte el manual de sudo.conf(5) para obtener más información.

EDITOR

ENVIRONMENT

Some variables are not preserved across a sudo command. The following variables are set when sudo is invoked:

HOME
Set to the home directory of the target user when the -i or -H options are specified, when the -s option is specified and set_home is set in sudoers, when always_set_home is enabled in sudoers, or when env_reset is enabled in sudoers and HOME is not present in the env_keep list.
MAIL
Set to the mail spool of the target user when the -i option is specified, or when env_reset is enabled in sudoers (unless MAIL is present in the env_keep list).
LOGNAME
Set to the login name of the target user when the -i option is specified, when the set_logname option is enabled in sudoers, or when the env_reset option is enabled in sudoers (unless LOGNAME is present in the env_keep list).
PATH
May be overridden by the security policy.
SHELL
Used to determine shell to run with -s option.
SUDO_ASKPASS
Specifies the path to a helper program used to read the password if no terminal is available or if the -A option is specified.
SUDO_COMMAND
Set to the command run by sudo, including any args. The args are truncated at 4096 characters to prevent a potential execution error.
SUDO_EDITOR
Default editor to use in -e (sudoedit) mode.
SUDO_GID
Set to the group-ID of the user who invoked sudo.
SUDO_HOME
Set to the home directory of the user who invoked sudo.
SUDO_PROMPT
Used as the default password prompt unless the -p option was specified.
SUDO_PS1
If set, PS1 will be set to its value for the program being run.
SUDO_TTY
Set to the terminal device of the user who invoked sudo, if one is present.
SUDO_UID
Set to the user-ID of the user who invoked sudo.
SUDO_USER
Set to the login name of the user who invoked sudo.
USER
Set to the same value as LOGNAME, described above.
VISUAL
Default editor to use in -e (sudoedit) mode if SUDO_EDITOR is not set.

EXAMPLES

The following examples assume a properly configured security policy.

To get a file listing of an unreadable directory:

$ sudo ls /usr/local/protected

To list the home directory of user yaz on a machine where the file system holding ~yaz is not exported as root:

$ sudo -u yaz ls ~yaz

To edit the index.html file as user www:

$ sudoedit -u www ~www/htdocs/index.html

To view system logs only accessible to root and users in the adm group:

$ sudo -g adm more /var/log/syslog

To run an editor as jim with a different primary group:

$ sudoedit -u jim -g audio ~jim/sound.txt

To shut down a machine:

$ sudo shutdown -r +15 "quick reboot"

To make a usage listing of the directories in the /home partition. The commands are run in a sub-shell to allow the ‘cd’ command and file redirection to work.

$ sudo sh -c "cd /home ; du -s * | sort -rn > USAGE"

DIAGNOSTICS

Error messages produced by sudo include:

editing files in a writable directory is not permitted

By default, sudoedit does not permit editing a file when any of the parent directories are writable by the invoking user. This avoids a race condition that could allow the user to overwrite an arbitrary file. See the sudoedit_checkdir option in sudoers(5) for more information.

editing symbolic links is not permitted

By default, sudoedit does not follow symbolic links when opening files. See the sudoedit_follow option in sudoers(5) for more information.

effective uid is not 0, is sudo installed setuid root?

sudo was not run with root privileges. The sudo binary must be owned by the root user and have the set-user-ID bit set. Also, it must not be located on a file system mounted with the ‘nosuid’ option or on an NFS file system that maps uid 0 to an unprivileged uid.

effective uid is not 0, is sudo on a file system with the 'nosuid' option set or an NFS file system without root privileges?

sudo was not run with root privileges. The sudo binary has the proper owner and permissions but it still did not run with root privileges. The most common reason for this is that the file system the sudo binary is located on is mounted with the ‘nosuid’ option or it is an NFS file system that maps uid 0 to an unprivileged uid.

fatal error, unable to load plugins

An error occurred while loading or initializing the plugins specified in sudo.conf(5).

invalid environment variable name

One or more environment variable names specified via the -E option contained an equal sign (‘=’). The arguments to the -E option should be environment variable names without an associated value.

no password was provided

When sudo tried to read the password, it did not receive any characters. This may happen if no terminal is available (or the -S option is specified) and the standard input has been redirected from /dev/null.

a terminal is required to read the password

sudo needs to read the password but there is no mechanism available for it to do so. Remote commands run via ssh(1) do not have a terminal available by default; passing the -t option to ssh(1) will cause it to allocate a terminal which should allow sudo to read the password. To allow sudo to run local commands without a terminal, the -S option can be used to read a password from the standard input, or an askpass helper can be configured via either the sudo.conf(5) file or by setting the SUDO_ASKPASS environment variable.

no writable temporary directory found

sudoedit was unable to find a usable temporary directory in which to store its intermediate files.

The “no new privileges” flag is set, which prevents sudo from running as root.

sudo was run by a process that has the Linux “no new privileges” flag is set. This causes the set-user-ID bit to be ignored when running an executable, which will prevent sudo from functioning. The most likely cause for this is running sudo within a container that sets this flag. Check the documentation to see if it is possible to configure the container such that the flag is not set.

sudo must be owned by uid 0 and have the setuid bit set

sudo was not run with root privileges. The sudo binary does not have the correct owner or permissions. It must be owned by the root user and have the set-user-ID bit set.

sudoedit is not supported on this platform

It is only possible to run sudoedit on systems that support setting the effective user-ID.

timed out reading password

The user did not enter a password before the password timeout (5 minutes by default) expired.

you do not exist in the passwd database

Your user
-El ID no aparece en la base de datos passwd del sistema.

no puede especificar variables de entorno en modo de edición

Solo es posible especificar variables de entorno al ejecutar un comando. Al editar un archivo, el editor se ejecuta con el entorno del usuario sin modificar.

ADVERTENCIAS

No hay una forma fácil de evitar que un usuario obtenga un shell de root si se le permite ejecutar comandos arbitrarios a través de sudo. Además, muchos programas (como los editores) permiten al usuario ejecutar comandos a través de escapes de shell, evitando así las comprobaciones de sudo. Sin embargo, en la mayoría de los sistemas es posible evitar los escapes de shell con la funcionalidad sudoers(5) del plugin noexec.

No tiene sentido ejecutar el comando ‘cd’ directamente a través de sudo, por ejemplo:

$ sudo cd /usr/local/protected

ya que cuando el comando salga, el proceso padre (tu shell) seguirá siendo el mismo. La opción -D se puede usar para ejecutar un comando en un directorio específico.

Ejecutar scripts de shell a través de sudo puede exponer los mismos errores del kernel que hacen que los scripts de shell con set-user-ID sean inseguros en algunos sistemas operativos (si tu sistema operativo tiene un directorio /dev/fd/, los scripts de shell con set-user-ID son generalmente seguros).
