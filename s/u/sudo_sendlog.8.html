SUDO_SENDLOG(8) Manual del Administrador del Sistema SUDO_SENDLOG(8)

NOMBRE

sudo_sendlog — envía el registro de I/O de sudo al servidor de registro

SINOPSIS

sudo_sendlog [-AnV] [-b paquete_ca] [-c archivo_cert] [-h host] [-i id_registro_io] [-k archivo_clave] [-p puerto] [-r punto_reinicio] [-R razon_rechazo] [-s punto_fin] [-t numero] ruta

DESCRIPCIÓN

sudo_sendlog se puede utilizar para enviar el registro de I/O de sudoers existente en la ruta a un servidor de registro remoto como sudo_logsrvd(8) para su almacenamiento central.

Las opciones son las siguientes:

-A, --accept-only
Envía solo el evento de aceptación, no el I/O asociado con el registro. Esto se puede utilizar para probar el registro de eventos de aceptación sin ningún I/O asociado.
-b, --ca-bundle
La ruta a un archivo de paquete de autoridad de certificación, en formato PEM, para usar en lugar de la base de datos de autoridad de certificación predeterminada del sistema al autenticar el servidor de registro. El valor predeterminado es usar la base de datos de autoridad de certificación predeterminada del sistema.
-c, --cert
La ruta al archivo de certificado del cliente en formato PEM. Esta configuración es necesaria cuando la conexión al servidor de registro remoto está asegurada con TLS.
--help
Muestra un breve mensaje de ayuda en la salida estándar y sale.
-h, --host
Conecta al host especificado en lugar de localhost.
-i, --iolog-id
Utiliza el id_registro_io especificado al reiniciar una transferencia de registro. El id_registro_io es informado por el servidor cuando crea el registro de I/O remoto. Esta opción solo se puede usar junto con la opción -r.
-k, --key
La ruta al archivo de clave privada del cliente en formato PEM. Esta configuración es necesaria cuando la conexión al servidor de registro remoto está asegurada con TLS.
-n, --no-verify
Si se especifica, el certificado del servidor no se verificará durante el apretón de manos TLS. Por defecto, sudo_sendlog verifica que el certificado del servidor sea válido y que contenga el nombre de host o la dirección IP del servidor. Esta configuración solo se admite cuando la conexión al servidor de registro remoto está asegurada con TLS.
-p, --port
Utiliza el puerto de red especificado al conectarse al servidor de registro en lugar del predeterminado, puerto 30344.
-r, --restart
Reinicia una conexión interrumpida al servidor de registro. El punto_reinicio especificado se utiliza para indicar al servidor el punto en el tiempo en el que debe continuar el registro. El punto_reinicio se especifica en el formato "segundos,nanosegundos" y suele ser el último punto de confirmación recibido del servidor. La opción -i también debe especificarse al reiniciar una transferencia.
-R, --reject
Envía un evento de rechazo para el comando utilizando la razon_rechazo especificada, aunque localmente haya sido aceptado. Esto se puede utilizar para probar el registro de eventos de rechazo; no se enviará ningún I/O.
-s, --stop-after
Deja de enviar registros y cierra la conexión cuando se alcanza el punto_fin. Esto se puede utilizar con fines de prueba para enviar un registro de I/O parcial al servidor. Los registros parciales se pueden reiniciar utilizando la opción -r. El punto_fin es un tiempo transcurrido especificado en el formato "segundos,nanosegundos".
-t, --test
Abre numero conexiones simultáneas al servidor de registro y envía el archivo de registro de I/O especificado en cada una. Esta opción es útil para pruebas de rendimiento.
-V, --version
Imprime la versión de sudo_sendlog y sale.

Depuración de sendlog

sudo_sendlog admite un marco de depuración flexible que se configura mediante líneas Depurar en el archivo sudo.conf(5).

Para obtener más información sobre la configuración de sudo.conf(5), consulte su manual.
