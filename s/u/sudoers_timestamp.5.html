SUDOERS_TIMESTAMP(5) Manual de Formatos de Archivo SUDOERS_TIMESTAMP(5)

NOMBRE

sudoers_timestamp — Formato de Marca de Tiempo de Sudoers

DESCRIPCIÓN

El plugin sudoers utiliza archivos de marca de tiempo por ID de usuario para el almacenamiento en caché de credenciales. Una vez que un usuario ha sido autenticado, puede usar sudo sin contraseña durante un corto período de tiempo (5 minutos a menos que se anule mediante la opción timestamp_timeout). Por defecto, sudoers utiliza un registro separado para cada terminal, lo que significa que las sesiones de inicio de sesión de un usuario se autentican por separado. La opción timestamp_type puede usarse para seleccionar el tipo de registro de marca de tiempo que usará sudoers.

Se introdujo un formato de archivo de marca de tiempo multi-registro en sudo 1.8.10 que utiliza un solo archivo por usuario. Anteriormente, se utilizaba un archivo separado para cada combinación de usuario y terminal, a menos que se deshabilitaran las marcas de tiempo basadas en tty. El nuevo formato es extensible y los registros de múltiples tipos y versiones pueden coexistir dentro del mismo archivo.

Todos los registros, independientemente del tipo o versión, comienzan con un número de versión de 16 bits y un tamaño de registro de 16 bits.

Los registros de marca de tiempo tienen la siguiente estructura:

/* Tipos de entrada de marca de tiempo */
#define TS_GLOBAL               0x01U   /* no restringido por tty o ppid */
#define TS_TTY                  0x02U   /* restringido por tty */
#define TS_PPID                 0x03U   /* restringido por ppid */
#define TS_LOCKEXCL             0x04U   /* registro de bloqueo especial */

/* Banderas de marca de tiempo */
#define TS_DISABLED             0x01U   /* entrada deshabilitada */
#define TS_ANYUID               0x02U   /* ignorar uid, solo válido en clave */

struct timestamp_entry {
    unsigned short version;     /* número de versión */
    unsigned short size;        /* tamaño de entrada */
    unsigned short type;        /* TS_GLOBAL, TS_TTY, TS_PPID */
    unsigned short flags;       /* TS_DISABLED, TS_ANYUID */
    uid_t auth_uid;             /* uid para autenticarse como */
    pid_t sid;                  /* ID de sesión asociado con tty/ppid */
    struct timespec start_time; /* hora de inicio de sesión/ppid */
    struct timespec ts;         /* marca de tiempo (CLOCK_MONOTONIC) */
    union {
        dev_t ttydev;           /* número de dispositivo tty */
        pid_t ppid;             /* pid padre */
    } u;
};

Los campos de la estructura timestamp_entry son los siguientes:

version
El número de versión de la estructura timestamp_entry. Se crean nuevas entradas con un número de versión 2. Los registros con diferentes números de versión pueden coexistir en el mismo archivo pero no son interoperables.
size
El tamaño del registro en bytes.
type
El tipo de registro, actualmente TS_GLOBAL, TS_TTY o TS_PPID.
flags
Cero o más banderas de registro que se pueden combinar mediante OR bit a bit. Las banderas admitidas son TS_DISABLED, para registros deshabilitados mediante sudo -k y TS_ANYUID, que solo se usa al comparar registros.
auth_uid
El ID de usuario que se utilizó para la autenticación. Dependiendo del valor de las opciones rootpw, runaspw y targetpw, el ID de usuario puede ser el del usuario que invoca, el usuario root, el usuario runas predeterminado o el usuario de destino.
sid
El ID de la sesión del terminal del usuario, si está presente. El ID de sesión solo se utiliza al comparar registros del tipo TS_TTY.
start_time
La hora de inicio del líder de sesión para registros del tipo TS_TTY o del proceso padre para registros del tipo TS_PPID. El start_time se utiliza para evitar la reutilización de un registro de marca de tiempo después de que un usuario se haya desconectado. No todos los sistemas admiten un método para recuperar fácilmente la hora de inicio de un proceso. El campo start_time se añadió en la versión sudoers 1.8.22 para la segunda revisión de la estructura timestamp_entry.
ts
La marca de tiempo real. Se utiliza una fuente de tiempo monotónico (que no retrocede) si el sistema la admite. Cuando es posible, sudoers utiliza un temporizador monotónico que se incrementa incluso mientras el sistema está suspendido. El valor de ts se actualiza cada vez que se ejecuta un comando a través de sudo. Si la diferencia entre ts y la hora actual es inferior al valor de la opción timestamp_timeout, no se requiere contraseña.
u.ttydev
El número de dispositivo del terminal asociado con la sesión para registros del tipo TS_TTY.
u.ppid
El ID del proceso padre para registros del tipo TS_PPID.

La utilidad tsdump, incluida en la distribución fuente de sudo, puede usarse para mostrar el contenido de un archivo de marca de tiempo de sudoers.

BLOQUEO

En las versiones de sudoers 1.8.10 a 1.8.14, todo el archivo de marca de tiempo se bloqueaba para acceso exclusivo al leer o escribir en el archivo. A partir de sudoers 1.8.15, se bloquean registros individuales en el archivo de marca de tiempo en lugar del archivo completo y el bloqueo se mantiene durante un período de tiempo más prolongado. Este esquema se describe a continuación.

El primer registro en el archivo de marca de tiempo es de tipo TS_LOCKEXCL y se utiliza como registro de bloqueo para evitar que más de un proceso de sudo añada un nuevo registro al mismo tiempo. Una vez que se localiza o crea (y bloquea) el registro de marca de tiempo deseado, el registro TS_LOCKEXCL se desbloquea. Sin embargo, el bloqueo sobre el registro de marca de tiempo individual se mantiene hasta que se completa la autenticación. Esto permite que sudoers evite solicitar una contraseña varias veces cuando se usa más de una vez en una canalización.

Los registros de tipo TS_GLOBAL no se pueden bloquear durante un período prolongado de tiempo, ya que hacerlo interferiría con otros procesos de sudo. En su lugar, se utiliza un registro de bloqueo separado para evitar que varios procesos de sudo que usan el mismo terminal (o ID de proceso padre) soliciten una contraseña al mismo tiempo.

VER TAMBIÉN

sudoers(5), sudo(8)

HISTORIA

Originalmente, sudo utilizaba un único archivo de longitud cero por usuario y la hora de modificación del archivo se utilizaba como marca de tiempo. Versiones posteriores de sudo agregaron restricciones sobre la propiedad de los archivos y directorios de marca de tiempo, así como comprobaciones sobre la validez de la marca de tiempo en sí. Se introdujeron cambios notables en las siguientes versiones de sudo:

1.4.0
Se agregó soporte para archivos de marca de tiempo basados en tty añadiendo el nombre del terminal al nombre del archivo de marca de tiempo.
1.6.2
El archivo de marca de tiempo fue reemplazado por un directorio por usuario que contenía cualquier archivo de marca de tiempo basado en tty.
1.6.3p2
Se añadió el nombre del usuario de destino al nombre del archivo de marca de tiempo cuando se configuró la opción targetpw.
1.7.3
La información sobre el dispositivo terminal se almacenó en archivos de marca de tiempo basados en tty para comprobaciones de validez. Esto incluía los números de dispositivo del terminal, el número de inodo y, en sistemas donde no se actualizaba al escribir en el dispositivo, la hora de cambio del inodo. Esto ayudó a prevenir la reutilización del archivo de marca de tiempo después del cierre de sesión.
1.8.6p7
Se añadió el ID de sesión del terminal a los archivos de marca de tiempo basados en tty para evitar la reutilización de la marca de tiempo por parte del mismo usuario en una sesión de terminal diferente. También ayudó a prevenir la reutilización del archivo de marca de tiempo en sistemas donde la hora de cambio del dispositivo del terminal se actualizaba mediante escritura.
1.8.10
Se introdujo un nuevo formato de archivo de marca de tiempo multi-registro que utiliza un solo archivo por usuario. La hora de cambio del dispositivo del terminal no se incluyó, ya que la mayoría de los sistemas ahora actualizan la hora de cambio
sudoers_timestamp(5) — sudo 1.9.17p2

NAME

sudoers_timestamp

sudoers timestamp file format

DESCRIPTION

The sudoers_timestamp file is used by sudo to store the time stamps of authentication sessions. When a user is successfully authenticated by sudo, the current time is stored in the timestamp file associated with the user. On subsequent calls to sudo within a short period, the user may not be required to re-enter their password.

The timestamp file is typically located in /var/run/sudo/ts/ or a similar directory, and is named after the user ID of the invoking user.

LOCKING

The sudo utility uses file locking to ensure that only one process modifies the timestamp file at a time. This prevents race conditions and ensures the integrity of the timestamp data.

SEE ALSO

sudo(8), sudoers(5)

HISTORY

1.6.2
Timestamp file locking was added.
1.7.0
The timestamp file is now created with appropriate permissions (0600) after a write is performed as required by POSIX.
1.8.15
Individual records are locked in the time stamp file instead of the entire file and the lock is held until authentication is complete.
1.8.22
The start time of the terminal session leader or parent process is now stored in non-global time stamp records. This prevents reuse of the time stamp file after logout in most cases.

Support was added for the kernel-based tty time stamps available in OpenBSD which do not use an on-disk time stamp file.

1.9.15
Time stamp file path names are now based on the invoking user-ID instead of the user name. This avoids problems with user names that include a path separator character.
