subpage_prot(2) Manual de llamadas al sistema subpage_prot(2)

NOMBRE

subpage_prot - define una protección de subpágina para un rango de direcciones

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/syscall.h>      /* Definición de constantes SYS_* */
#include <unistd.h>
int syscall(SYS_subpage_prot, unsigned long addr, unsigned long size,
            uint32_t *map);

Nota: glibc no proporciona un envoltorio para subpage_prot(), lo que hace necesario el uso de syscall(2).

DESCRIPCIÓN

La llamada al sistema específica de PowerPC subpage_prot() proporciona la facilidad de controlar los permisos de acceso en subpáginas individuales de 4 kB en sistemas configurados con un tamaño de página de 64 kB.

El mapa de protección se aplica a las páginas de memoria en la región que comienza en addr y continúa durante size bytes. Ambos argumentos deben estar alineados a un límite de 64 kB.

El mapa de protección se especifica en el búfer apuntado por map. El mapa tiene 2 bits por subpágina de 4 kB; por lo tanto, cada palabra de 32 bits especifica las protecciones de 16 subpáginas de 4 kB dentro de una página de 64 kB (así, el número de palabras de 32 bits apuntadas por map debe equivaler al número de páginas de 64 kB especificadas por size). Cada campo de 2 bits en el mapa de protección es 0 para permitir cualquier acceso, 1 para prevenir escrituras, o 2 o 3 para prevenir todos los accesos.

VALOR DE RETORNO

En caso de éxito, subpage_prot() devuelve 0. De lo contrario, se devuelve uno de los códigos de error especificados a continuación.

ERRORES

EFAULT
El búfer al que se refiere map no es accesible.
EINVAL
Los argumentos addr o size son incorrectos. Ambos argumentos deben estar alineados a un múltiplo del tamaño de página del sistema y no deben referirse a una región fuera del espacio de direcciones del proceso ni a una región que consista en páginas grandes.
ENOMEM
Sin memoria.

ESTÁNDARES

Linux.

HISTORIA

Linux 2.6.25 (PowerPC).

La llamada al sistema solo se proporciona si el kernel está configurado con CONFIG_PPC_64K_PAGES.

NOTAS

Las protecciones de página normales (a nivel de página de 64 kB) también se aplican; el mecanismo de protección de subpágina es una restricción adicional, por lo que poner 0 en un campo de 2 bits no permitirá escrituras en una página que de otro modo estaría protegida contra escritura.

Razón

Esta llamada al sistema se proporciona para ayudar a escribir emuladores que operan utilizando páginas de 64 kB en sistemas PowerPC. Al emular sistemas como x86, que utiliza un tamaño de página más pequeño, el emulador ya no puede utilizar la unidad de gestión de memoria (MMU) ni las llamadas al sistema normales para controlar las protecciones de página. (El emulador podría emular la MMU comprobando y posiblemente remapeando la dirección para cada acceso a memoria en software, pero eso es lento). La idea es que el emulador proporcione una matriz de máscaras de protección para aplicar a un rango especificado de direcciones virtuales. Estas máscaras se aplican en el nivel en el que las entradas de la tabla de páginas (PTE) del hardware se insertan en la tabla de páginas del hardware basándose en las PTE de Linux, por lo que las PTE de Linux no se ven afectadas. Implícito en esto es que las regiones del espacio de direcciones que están protegidas se cambian para usar páginas de hardware de 4 kB en lugar de páginas de hardware de 64 kB (en máquinas con soporte de páginas de hardware de 64 kB).
