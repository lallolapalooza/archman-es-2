sudo_logsrvd.conf(5) Manual de formatos de archivo sudo_logsrvd.conf(5)

NOMBRE

sudo_logsrvd.conf — configuración para sudo_logsrvd

DESCRIPCIÓN

El archivo sudo_logsrvd.conf se utiliza para configurar el servidor de registro sudo_logsrvd. Utiliza un formato de estilo INI compuesto por secciones entre corchetes y pares de “clave = valor” específicos para cada sección debajo del nombre de la sección. Dependiendo de la clave, los valores pueden ser enteros, booleanos o cadenas. Los nombres de sección y clave no distinguen mayúsculas y minúsculas, pero los valores sí.

El signo de almohadilla (‘#’) se utiliza para indicar un comentario. Tanto el carácter de comentario como cualquier texto posterior, hasta el final de la línea, se ignoran. Las líneas que comienzan con un punto y coma (‘;’) también se ignoran.

Las líneas largas se pueden continuar con una barra invertida (‘\’) como el último carácter de la línea. El espacio en blanco inicial se elimina del principio de las líneas incluso cuando se utiliza el carácter de continuación.

La sección EJEMPLOS contiene una copia del archivo de configuración predeterminado de sudo_logsrvd.conf.

Se reconocen las siguientes secciones de configuración:

  • server
  • relay
  • iolog
  • eventlog
  • syslog
  • logfile

Cada sección se describe en detalle a continuación.

server

La sección server configura la dirección y el puerto en los que escuchará el servidor. Se reconocen las siguientes claves:

listen_address = host[:puerto][(tls)]
El nombre del host o la dirección IP, el puerto opcional en el que escuchar y una bandera opcional de Capa de Transporte Seguro (TLS) entre paréntesis.

El host puede ser un nombre de host, una dirección IPv4, una dirección IPv6 entre corchetes o la entrada comodín ‘*’. Una configuración de host de ‘*’ hará que sudo_logsrvd escuche en todas las interfaces de red configuradas.

Si está presente la bandera tls opcional, sudo_logsrvd asegurará la conexión con TLS versión 1.2 o 1.3. Las versiones de TLS anteriores a la 1.2 no son compatibles. Consulte sudo_logsrvd(8) para obtener detalles sobre cómo generar claves y certificados TLS.

Si se especifica un puerto, puede ser un número de puerto o un nombre de servicio conocido, según se define en la base de datos de nombres de servicios del sistema. Si no se especifica ningún puerto, se utilizará el puerto 30343 para conexiones de texto plano y el puerto 30344 para conexiones TLS.

El valor predeterminado es:

listen_address = *:30343
listen_address = *:30344(tls)
lo que hará que escuche en todas las interfaces de red configuradas tanto para conexiones de texto plano como TLS. Se pueden especificar varias líneas listen_address para escuchar en más de un puerto o interfaz.
server_log = cadena
Dónde registrar mensajes de advertencia y error del servidor. Los valores soportados son none, stderr, syslog, o una ruta que comience con el carácter ‘/’. Un valor de stderr solo es efectivo cuando se usa junto con la opción -n. El valor predeterminado es syslog.
pid_file = ruta
La ruta al archivo que contiene el ID de proceso del sudo_logsrvd en ejecución. Si se establece en un valor vacío, o si sudo_logsrvd se ejecuta con la opción -n, no se creará ningún pid_file. Si pid_file se refiere a un enlace simbólico, se ignorará. El valor predeterminado es /run/sudo/sudo_logsrvd.pid.
tcp_keepalive = booleano
Si es verdadero, sudo_logsrvd habilitará la opción de socket keepalive de TCP en la conexión del cliente. Esto habilita la transmisión periódica de mensajes keepalive al cliente. Si el cliente no responde a un mensaje a tiempo, la conexión se cerrará. El valor predeterminado es true.
timeout = número
El tiempo, en segundos, que sudo_logsrvd esperará la respuesta del cliente. Un valor de 0 deshabilitará el tiempo de espera. El valor predeterminado es 30.
tls_cacert = ruta
La ruta a un archivo de paquete de autoridad de certificación, en formato PEM, para usar en lugar de la base de datos de autoridades de certificación predeterminada del sistema al autenticar clientes. El valor predeterminado es usar /etc/ssl/sudo/cacert.pem si existe, de lo contrario se utiliza la base de datos de autoridades de certificación predeterminada del sistema.
tls_cert = ruta
La ruta al archivo del certificado del servidor, en formato PEM. El valor predeterminado es /etc/ssl/sudo/certs/logsrvd_cert.pem.
tls_checkpeer = booleano
Si es verdadero, sudo_logsrvd validará los certificados de los clientes; los clientes sin un certificado válido no podrán conectarse. Si es falso, no se realizará ninguna validación de los certificados de los clientes. Si es verdadero y los certificados de los clientes se crean utilizando una autoridad de certificación privada, la configuración tls_cacert debe establecerse en un paquete de CA que contenga el certificado de CA utilizado para generar el certificado del cliente. El valor predeterminado es false.
tls_ciphers_v12 = cadena
Una lista de cifrados a usar solo para conexiones aseguradas por TLS versión 1.2, separadas por dos puntos (‘:’). Consulte la sección FORMATO DE LISTA DE CIFRADOS en openssl-ciphers(1) para obtener detalles completos. El valor predeterminado es “HIGH:!aNULL”, que consiste en conjuntos de cifrado de encriptación con longitudes de clave superiores a 128 bits y algunos conjuntos de cifrado con claves de 128 bits. Se excluyen los conjuntos de cifrado que no ofrecen autenticación.
tls_ciphers_v13 = cadena
Una lista de cifrados a usar solo para conexiones aseguradas por TLS versión 1.3, separadas por dos puntos (‘:’). Los conjuntos de cifrado admitidos dependen de la versión de OpenSSL utilizada, pero deberían incluir los siguientes:
TLS_AES_128_GCM_SHA256
 
TLS_AES_256_GCM_SHA384
 
TLS_CHACHA20_POLY1305_SHA256
 
TLS_AES_128_CCM_SHA256
 
TLS_AES_128_CCM_8_SHA256
 

El conjunto de cifrado predeterminado es “TLS_AES_256_GCM_SHA384”.

tls_dhparams = ruta
La ruta a un archivo que contiene parámetros Diffie-Hellman personalizados en formato PEM. Este archivo se puede crear con el siguiente comando: 
openssl dhparam -out /etc/sudo_logsrvd_dhparams.pem 2048

Por defecto, sudo_logsrvd utilizará los valores predeterminados de OpenSSL para la generación de claves Diffie-Hellman.

tls_key = ruta
La ruta al archivo de clave privada del servidor, en formato PEM. El valor predeterminado es /etc/ssl/sudo/private/logsrvd_key.pem.
tls_verify = booleano
Si es verdadero, sudo_logsrvd verificará su propio certificado al iniciar o cuando la configuración cambie. Si es falso, no se realizará ninguna verificación del certificado del servidor. Al usar certificados autofirmados sin una autoridad de certificación, esta configuración debe establecerse en falso. El valor predeterminado es true.

eventlog

La sección eventlog configura cómo (y si) se registran los eventos de política de seguridad.

log_type = cadena
Dónde registrar los eventos de aceptación, rechazo y alerta reportados por la política. Los valores admitidos son syslog, logfile, y none. El valor predeterminado es syslog.
log_exit = booleano
Si es verdadero, sudo_logsrvd registrará un evento cuando un comando termine o sea terminado por una señal. Predeterminado a false.
log_format = cadena
El formato del registro de eventos. Los formatos de registro admitidos son:
json
Actualmente, este es un alias para json_pretty. En una versión futura de sudo_logsrvd, json será equivalente a json_compact. Las entradas de registro JSON contienen el contenido completo de los mensajes de aceptación, rechazo, salida y alerta.
json_compact
Registra eventos en formato JSON "compacto" (minificado). Cada evento se escribe como un objeto JSON separado en una sola línea sin espacios en blanco adicionales. Debido a las limitaciones del protocolo, los eventos JSON enviados a través de syslog pueden ser truncados.
json_pretty
Registra eventos en formato JSON "pretty". Cuando se registra en un archivo, todo el archivo se trata como un único objeto JSON que consta de múltiples eventos, cada evento abarca varias líneas. Cuando se registra a través de syslog, no hay diferencia entre los formatos json_pretty y json_compact.
sudo
Registra eventos en el formato de registro tradicional al estilo sudo. Consulte la sección REGISTRO DE EVENTOS en sudoers(5) para obtener detalles.

El valor predeterminado es sudo.

syslog

La sección syslog configura cómo se registran los eventos a través de syslog(3).

facility = cadena
Facilidad de syslog si se está utilizando syslog para el registro. Predeterminado a auth.

Las siguientes facilidades de syslog son compatibles: authpriv (si tu SO lo soporta), auth, daemon, user, local0, local1, local2, local3, local4, local5, local6, y local7.

accept_priority = cadena
Prioridad de syslog a utilizar cuando al usuario se le permite ejecutar un comando y la autenticación es exitosa. Predeterminado a notice.

Las siguientes prioridades de syslog son compatibles: alert, crit, debug, emerg, err, info, notice, warning, y none. Configurar a un valor de none deshabilitará el registro de comandos exitosos.

reject_priority = cadena
Prioridad de syslog a utilizar cuando al usuario no se le permite ejecutar un comando o cuando la autenticación no es exitosa. Predeterminado a alert.

Ver accept_priority para la lista de prioridades de syslog compatibles.

alert_priority = cadena
Prioridad de syslog a utilizar para los mensajes de alerta del registro de eventos recibidos del cliente. Predeterminado a alert.

Ver accept_priority para la lista de prioridades de syslog compatibles.

maxlen = número
En muchos sistemas, syslog(3) tiene un búfer de registro relativamente pequeño. El RFC 5424 de IETF establece que los servidores de syslog deben soportar mensajes de al menos 480 bytes y deben soportar mensajes de hasta 2048 bytes. Por defecto, sudo_logsrvd crea mensajes de registro de hasta 960 bytes, lo que corresponde a la implementación histórica del sistema BSD syslog que utilizaba un búfer de 1024 bytes para almacenar el mensaje, la fecha, el nombre de host y el nombre del programa.

Para evitar que los mensajes de syslog se trunquen, sudo_logsrvd dividirá los mensajes de registro al estilo sudo que sean mayores que maxlen bytes. Cuando un mensaje se divide, las partes adicionales incluirán la cadena "(comando continuado)" después del nombre de usuario y antes de los argumentos de línea de comandos continuados. Las entradas de registro en formato JSON nunca se dividen y no se ven afectadas por maxlen.

server_facility = cadena
Facilidad de syslog si se está utilizando syslog para mensajes de advertencia del servidor. Ver arriba para una lista de facilidades compatibles. Predeterminado a daemon

logfile

La sección logfile consiste en configuraciones relacionadas con el registro en un archivo plano (no syslog).

path = cadena
La ruta al archivo de registro de eventos. Esta ruta debe estar completamente calificada y comenzar con un carácter '/'. El valor predeterminado es /var/log/sudo.log.
time_format = cadena
La cadena utilizada al formatear la fecha y hora para los registros de eventos basados en archivos. El formato se realiza a través de la función strftime(3) del sistema, por lo que cualquier secuencia de escape compatible con esa función se expandirá. El valor predeterminado es " %h %e %T ", que produce fechas como " Oct 3 07:15:24 " en la configuración regional de ' C '.

ARCHIVOS

/etc/sudo_logsrvd.conf
Archivo de configuración del servidor de registro de sudo

EJEMPLOS

#
# Configuración del demonio sudo logsrv
#

[server]
# El nombre de host o la dirección IP y el puerto en el que escuchar con un TLS opcional
# indicador. Si no se especifica un puerto, se utilizará el puerto 30343 para conexiones de texto plano
# y el puerto 30344 para conexiones TLS.
# Se aceptan las siguientes formas:
#   listen_address = hostname(tls)
#   listen_address = hostname:port(tls)
#   listen_address = IPv4_address(tls)
#   listen_address = IPv4_address:port(tls)
#   listen_address = [IPv6_address](tls)
#   listen_address = [IPv6_address]:port(tls)
#
# El sufijo (tls) debe omitirse para las conexiones de texto plano.
