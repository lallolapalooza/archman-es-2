SUDO(8) sudo-rs SUDO(8)

NOMBRE

sudo, sudoedit - ejecuta un comando como otro usuario

SINOPSIS

sudo -h | -K | -k | -V

sudo [-u usuario] [-g grupo] [-D directorio] [-BknS] [-i | -s] [VAR=valor] [<comando>]

sudo -v [-BknS] [-u usuario] [-g grupo]

sudo -l [-BknS] [-U usuario] [-u usuario] [-g grupo] [comando [arg ...]]

sudo -e [-BknS] [-u usuario] [-g grupo] archivo ...

sudoedit [-BknS] [-u usuario] [-g grupo] archivo ...

DESCRIPCIÓN

sudo permite a un usuario que tiene permiso para hacerlo ejecutar un comando como otro usuario (por ejemplo, root). Los permisos se especifican mediante una política de seguridad definida en /etc/sudoers (ver sudoers(5)).

Sudo-rs es una reimplementación de la implementación original de sudo por Todd Miller, orientada a la seguridad y segura en memoria.

Cuando se ejecuta un comando, se almacena un registro de sesión para esa sesión específica, lo que permite a los usuarios ejecutar comandos adicionales sin tener que volver a autenticarse. El tiempo de espera para los registros de sesión se puede especificar en la política.

Se presta especial atención a pasar las señales recibidas por sudo-rs al proceso hijo, incluso si ese proceso se ejecuta en su propia terminal pseudo.

En sistemas donde sudo es el método principal para obtener privilegios de superusuario, es imperativo evitar errores de sintaxis en el archivo /etc/sudoers. Los cambios en este archivo deben realizarse utilizando la utilidad visudo(8), que garantizará que no se introduzcan errores de sintaxis.

OPCIONES

-B, --campana
Suena la campana como parte de la solicitud de contraseña cuando hay una terminal presente.
-D directorio, --cambiar-directorio=directorio
Ejecuta el comando en el directorio especificado en lugar del directorio de trabajo actual. La política de seguridad puede devolver un error si el usuario no tiene permiso para especificar el directorio de trabajo.
-g grupo, --grupo=grupo
Usa este grupo como el grupo primario en lugar de usar el grupo primario especificado en la base de datos de contraseñas para el usuario de destino.
-h, --ayuda
Muestra un mensaje de ayuda.
-i, --login
Ejecuta el shell especificado en la entrada de la base de datos de contraseñas del usuario de destino como un shell de inicio de sesión. Esto significa que el shell leerá archivos de recursos específicos del inicio de sesión como .profile, .bash_profile o .login. Si se especifica un comando, se pasa al shell con la opción -c.
-K, --eliminar-marca-tiempo
Elimina todos los registros de sesión almacenados en caché del usuario, independientemente de dónde se ejecute el comando. La próxima vez que se ejecute sudo-rs, se realizará la autenticación si la política lo requiere. No se requiere contraseña para ejecutar este comando.
-k, --resetear-marca-tiempo
Cuando se usa sin un comando, invalida el registro de sesión del usuario para la sesión actual. La próxima vez que se ejecute sudo-rs, se realizará la autenticación si la política lo requiere.

Cuando se usa junto con un comando o una opción que pueda requerir una contraseña, esta opción hará que sudo-rs ignore el registro de sesión del usuario. Como resultado, se realizará la autenticación si la política lo requiere. Cuando se usa junto con un comando, no se invalidarán los registros de sesión existentes.

-n, --no-interactivo
Evita solicitar al usuario cualquier tipo de entrada. Si se requiere alguna entrada para que el comando se ejecute, sudo-rs mostrará un mensaje de error y saldrá.
-p, --prompt=prompt
Usa un prompt de autenticación personalizado con secuencias de escape opcionales. Las siguientes secuencias de escape de porcentaje (`%') son soportadas:
 %H  expandido al nombre de host local
 %h  expandido al nombre de host local sin el nombre de dominio
 %p  expandido al nombre del usuario al que se está solicitando la contraseña
     (esto respeta las banderas rootpw, targetpw)
 %U  expandido al nombre de inicio de sesión del usuario con el que se ejecutará
     el comando (por defecto es root a menos que también se especifique la
     opción -u)
 %u  expandido al nombre de inicio de sesión del usuario invocador
 %%  dos caracteres '%' consecutivos se colapsan en un solo carácter '%'

El prompt personalizado anulará el prompt predeterminado o el especificado por la variable de entorno SUDO_PROMPT. Ningún prompt suprimirá el prompt proporcionado por PAM, a menos que el prompt solicitado esté vacío ("")

-S, --stdin
Lee desde la entrada estándar en lugar de usar el dispositivo de terminal.
-s, --shell
Ejecuta el shell especificado por la variable de entorno SHELL. Si no se especificó ningún shell, se usará el shell de la entrada de la base de datos de contraseñas del usuario en su lugar. Si se especifica un comando, se pasa al shell usando la opción -c.

-e, sudoedit

Edita uno o más archivos en lugar de ejecutar un comando. En lugar de un nombre de ruta, se usa la cadena "sudoedit" al consultar la política de seguridad. Si el usuario está autorizado por la política, se toman los siguientes pasos:
1. Se hacen copias temporales de los archivos a editar con el propietario establecido en el usuario invocador.
2. Se ejecuta el editor especificado por la política para editar los archivos temporales. La política de sudoers utiliza las variables de entorno SUDO_EDITOR, VISUAL y EDITOR (en ese orden). Si ninguna de SUDO_EDITOR, VISUAL o EDITOR están establecidas, se usa el primer programa listado en la opción de editor de sudoers(5).
3. Si han sido modificados, el contenido de los archivos temporales se copia de vuelta a los originales y se eliminan las versiones temporales.
Para ayudar a prevenir la edición de archivos no autorizados, se aplican las siguientes restricciones (a menos que el usuario sea root):
* No se pueden editar enlaces simbólicos.
* Si algún componente de la ruta que conduce al archivo es escribible por el usuario invocador, el archivo no puede ser editado.
* Nunca se permite a los usuarios editar archivos especiales de dispositivos.
Si el archivo especificado no existe, se creará. A diferencia de la mayoría de los comandos ejecutados por sudo, el editor se ejecuta con el entorno del usuario invocador sin modificaciones. Si el archivo temporal queda vacío después de la edición, se le pedirá al usuario que confirme antes de instalarlo.
-u usuario, --usuario=usuario
Ejecuta el comando como un usuario diferente del predeterminado (root).
-V, --versión
Muestra la versión actual de sudo-rs.
-v, --validar
Actualiza la marca de tiempo de la sesión del usuario, extendiendo la sesión actual de sudo-rs. Si se especifica un comando, se usará para validar el registro de sesión del usuario.

sudo-rs(8)

NAME

sudo-rs - execute a command as another user

SYNOPSIS

sudo-rs [options] [-u user] [-g group] [-p prompt] [-i] [-s] [COMMAND]

sudo-rs [options] [-u user] [-g group] [-p prompt] [-i] [-s] [-l [COMMAND]]

sudo-rs [options] [-u user] [-g group] [-p prompt] [-i] [-s] [-U user]

DESCRIPTION

The sudo-rs utility is a tool to allow a permitted user to execute a command as another user, typically the superuser. The security policy is defined in the sudoers file. The sudo-rs utility is a reimplementation of the sudo command in Rust.

OPTIONS

-c, --command=COMMAND
Specify the command to be run. If not specified, sudo-rs will execute the command specified on the command line.
-g, --group=group
Run the command with the primary group of group. The group name or ID may be used.
-i, --login
Run the shell specified by the target user's login_shell attribute. If no login shell is specified, the shell is determined by the SHELL environment variable. The command is run with an environment resembling a normal login. This means that login-specific resource files such as .profile or .login would be read by the shell. If no command is specified, an interactive shell is started by the user.
-l, --list
List the allowed (and forbidden) commands associated with the invoking user, or check if a specific command is allowed; use twice for longer format.
-p, --prompt=prompt
Allow the user to specify a custom prompt string. The prompt is ``[sudo] password for %u@%h:%s ''.
-s, --shell
Run the shell specified by the SHELL environment variable. If SHELL is not set, the user's login shell is used. The command is run with an environment resembling that of the shell. If no command is specified, an interactive shell is started.
-U, --other-user=user
Used in list mode, display privileges for another user.
-u, --user=user
Run the command as the user specified by user. The user name or user ID may be used.
--
Indicates the end of the sudo-rs options and the start of the command.

Environment variables to be set for the command may be passed on the command line in the form of VAR=value. Variables passed on the command line are subject to restrictions imposed by the security policy. Variables passed on the command line are subject to the same restrictions as normal environment variables with one important exception: If the command to be run has the SETENV tag set or the command matched is ALL, the user may set variables that would otherwise be forbidden. See sudoers(5) for more information.
