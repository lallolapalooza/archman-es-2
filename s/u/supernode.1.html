supernode(1) COMANDOS DE USUARIO supernode(1)

NOMBRE

supernode - demonio de supernodo n2n

SINOPSIS

supernode <archivo de configuración>
supernode [OPCIÓN]...

DESCRIPCIÓN

N2N es un sistema VPN de igual a igual. Supernodo es un registro de introducción de nodos, conducto de difusión y nodo de retransmisión de paquetes para el sistema n2n. Al iniciar, supernodo comienza a escuchar en el puerto UDP especificado para registros de nodos y otros paquetes para enrutar. El supernodo puede dar servicio a cualquier número de comunidades y enruta paquetes solo entre miembros de la misma comunidad. El supernodo no tiene la clave de cifrado de la comunidad y, por lo tanto, no puede espiar ni inyectar paquetes en la comunidad.

Supernodo puede dar servicio a varias comunidades n2n de forma concurrente. El tráfico no cruza entre comunidades.

Todos los registros van a la salida estándar.

El archivo de configuración es similar a la línea de comandos, con una opción por línea. Las líneas que comienzan con un "#" se ignoran. Se debe usar un signo igual ('=') entre la clave y el valor. Ejemplo: -p=7777

OPCIONES PARA LA CONEXIÓN DE RED SUBYACENTE

-p <puerto_local>, --puerto-local=<puerto_local>
escuchar en este puerto UDP local fijo, por defecto 7654
-F <nombre_federacion>
nombre de la federación del supernodo, por defecto '*'Federation' (ver también N2N_FEDERATION en ENTORNO)
-l <host:puerto>
dirección IP o nombre y puerto del supernodo conocido
-m <direccion_mac>
dirección MAC fija para el supernodo, por ejemplo,
'-m 10:20:30:40:50:60', aleatoria en caso contrario
-M
deshabilitar la protección contra suplantación de dirección MAC e IP para todas las comunidades que no utilizan autenticación de nombre de usuario y contraseña
-V <cadena_version>
modifica la cadena de versión del supernodo que se distribuye a los extremos y se muestra en la salida de su puerto de gestión, hasta 19 caracteres

CONFIGURACIÓN DEL DISPOSITIVO TAP Y DE LA RED DE SUPERPOSICIÓN

-c <ruta>, --comunidades=<ruta>
archivo que contiene las comunidades permitidas y cualquier detalle de autenticación basado en usuario/contraseña (Ver sección ARCHIVO DE COMUNIDADES PERMITIDAS)
-a <red-red/n>, --autoip=<red-red/n>
rango de subred para el servicio de dirección IP automática,
ej. '-a 192.168.0.0-192.168.255.0/24',
por defecto '10.128.255.0-10.255.255.0/24'

OPCIONES LOCALES

-f, --foreground
deshabilita el modo demonio (UNIX) y se ejecuta en primer plano.
-t <puerto>, --puerto-gestion=<puerto>
puerto UDP de gestión, para múltiples supernodos en una máquina, por defecto 5645
--contraseña-gestion <contraseña>
establece la contraseña para acceder a la API JSON en el puerto de gestión, por defecto 'n2n'. Se debe proporcionar la contraseña para un acceso relevante a la API JSON en el puerto de gestión.
-v, --verbose
usa registro detallado
-u <UID>
ID de usuario numérico a usar cuando se reducen los privilegios
-g <GID>
ID de grupo numérico a usar cuando se reducen los privilegios
-h
muestra una referencia rápida incluyendo todas las opciones disponibles
--help
muestra la descripción detallada de los parámetros

ARCHIVO DE COMUNIDADES PERMITIDAS

Este archivo es un archivo de texto plano. Los comentarios se introducen con una almohadilla al principio de la línea. Una línea que comienza con un asterisco es una definición de autenticación de usuario y agrega un usuario permitido a la comunidad definida más recientemente. Las comunidades permitidas se pueden especificar con una expresión regular.

Ejemplo de archivo de comunidad:

# Lista de comunidades permitidas
mynetwork
netleo
* logan nHWum+r42k1qDXdIeH-WFKeylK5UyLStRzxofRNAgpG
* sister HwHpPrdMft+38tFDDiunUds6927t0+zhCMMkQdJafcC

Se encuentran más detalles sobre la creación del archivo de comunidades permitidas en la documentación de Communities.md y Authentication.md incluida con este paquete.

ENTORNO

N2N_FEDERATION
establece el nombre de la federación para que no sea visible en la línea de comandos

EJEMPLOS

supernode -p 7654 -v
Inicia supernodo escuchando en el puerto UDP 7654 con salida detallada.
echo | nc -w1 -u 127.0.0.1 5645
Muestra el estado de gestión de un supernodo en ejecución.

REINICIO

Cuando supernodo se reinicia, pierde toda la información de registro de los nodos extremos asociados. Puede tardar hasta cinco minutos en que los nodos extremos se vuelvan a registrar y se reanude el flujo normal del tráfico.

ESTADO DE SALIDA

supernode es un demonio y cualquier salida es un error
