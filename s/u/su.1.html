SU(1) Comandos de usuario SU(1)

NOMBRE

su - ejecutar un comando con ID de usuario y grupo sustituto

SINOPSIS

su [opciones] [-] [usuario [argumento...]]

DESCRIPCIÓN

su permite ejecutar comandos con un ID de usuario y grupo sustituto.

Cuando se llama sin especificar usuario, su por defecto ejecuta un shell interactivo como root. Cuando se especifica usuario, se pueden proporcionar argumentos adicionales, en cuyo caso se pasan al shell.

Por compatibilidad con versiones anteriores, su por defecto no cambia el directorio actual y solo establece las variables de entorno HOME y SHELL (más USER y LOGNAME si el usuario de destino no es root). Se recomienda siempre usar la opción --login (en lugar de su atajo -) para evitar efectos secundarios causados por la mezcla de entornos.

Esta versión de su utiliza PAM para la autenticación, gestión de cuentas y sesiones. Algunas opciones de configuración que se encuentran en otras implementaciones de su, como el soporte para un grupo `wheel`, deben configurarse a través de PAM.

su está diseñado principalmente para usuarios no privilegiados; la solución recomendada para usuarios privilegiados (por ejemplo, scripts ejecutados por root) es usar el comando no set-user-ID runuser(1) que no requiere autenticación y proporciona una configuración PAM separada. Si la sesión PAM no es necesaria en absoluto, la solución recomendada es usar el comando setpriv(1).

Tenga en cuenta que su en todos los casos utiliza PAM (pam_getenvlist(3)) para realizar la modificación final del entorno. Las opciones de línea de comandos como --login y --preserve-environment afectan al entorno antes de que sea modificado por PAM.

Desde la versión 2.38, su restablece los límites de recursos del proceso RLIMIT_NICE, RLIMIT_RTPRIO, RLIMIT_FSIZE, RLIMIT_AS y RLIMIT_NOFILE.

OPCIONES

-c, --command comando

Pasa comando al shell con la opción -c.

-f, --fast

Pasa -f al shell, lo que puede o no ser útil, dependiendo del shell.

-g, --group grupo

Especifica el grupo primario. Esta opción solo está disponible para el usuario root.

-G, --supp-group grupo

Especifica un grupo suplementario. Esta opción solo está disponible para el usuario root. El primer grupo suplementario especificado también se utiliza como grupo primario si no se especifica la opción --group.

-, -l, --login

Inicia el shell como un shell de inicio de sesión con un entorno similar a un inicio de sesión real.

Tenga en cuenta que en los sistemas basados en systemd, una nueva sesión puede definirse como un punto de entrada real al sistema. Sin embargo, su no crea una sesión real (desde el punto de vista de PAM). Necesita usar herramientas como systemd-run o machinectl para iniciar una sesión completa y real.

su realiza lo siguiente:

•borra todas las variables de entorno excepto TERM y las variables especificadas por --whitelist-environment
•inicializa las variables de entorno HOME, SHELL, USER, LOGNAME y PATH
•cambia al directorio personal del usuario de destino
•establece argv[0] del shell en '-' para hacer del shell un shell de inicio de sesión

-m, -p, --preserve-environment

Conserva todo el entorno, es decir, no establece HOME, SHELL, USER o LOGNAME. Esta opción se ignora si se especifica la opción --login.

-P, --pty

Crea un pseudo-terminal para la sesión. El terminal independiente proporciona mejor seguridad ya que el usuario no comparte un terminal con la sesión original. Esto puede usarse para evitar la inyección de comandos ioctl del terminal TIOCSTI y otros ataques de seguridad contra descriptores de archivo de terminal. Toda la sesión también puede moverse al segundo plano (por ejemplo, su --pty - usuario -c aplicación &). Si el pseudo-terminal está habilitado, entonces su funciona como un proxy entre las sesiones (sincroniza stdin y stdout).

Esta característica está diseñada principalmente para sesiones interactivas. Si la entrada estándar no es un terminal, sino por ejemplo una tubería (por ejemplo, echo "date" | su --pty), entonces el indicador ECHO para el pseudo-terminal se deshabilita para evitar salidas desordenadas.

-s, --shell shell

Ejecuta el shell especificado en lugar del predeterminado. Si el usuario de destino tiene un shell restringido (es decir, no listado en /etc/shells), las opciones --shell y la variable de entorno SHELL se ignoran a menos que el usuario que llama sea root.

El shell a ejecutar se selecciona según las siguientes reglas, en orden:

•el shell especificado con --shell
•el shell especificado en la variable de entorno SHELL, si se utiliza la opción --preserve-environment
•el shell listado en la entrada passwd del usuario de destino
•/bin/sh

--session-command=comando

Igual que -c, pero no crea una nueva sesión. (Desaconsejado).

-T, --no-pty

No crear un pseudo-terminal, lo opuesto a --pty y -P. Tenga en cuenta que ejecutar sin un pseudo-terminal presenta el riesgo de seguridad de escalada de privilegios a través de la inyección de comandos ioctl TIOCSTI/TIOCLINUX.

-w, --whitelist-environment lista

No restablecer las variables de entorno especificadas en la lista separada por comas al borrar el entorno para --login. La lista blanca se ignora para las variables de entorno HOME, SHELL, USER, LOGNAME y PATH.

-h, --help

Mostrar texto de ayuda y salir.

-V, --version

Mostrar versión y salir.

SEÑALES

Al recibir SIGINT, SIGQUIT o SIGTERM, su termina su hijo y luego se termina a sí mismo con la señal recibida. El hijo es terminado por SIGTERM, y después de un intento fallido y una demora de 2 segundos, el hijo es eliminado por SIGKILL.

ARCHIVOS DE CONFIGURACIÓN

su lee los archivos de configuración /etc/default/su y /etc/login.defs. Los siguientes elementos de configuración son relevantes para su:

FAIL_DELAY (número)

Retraso en segundos en caso de fallo de autenticación. El número debe ser un entero no negativo.

ENV_PATH (cadena)

Define la variable de entorno PATH para un usuario normal. El valor predeterminado es /usr/local/bin:/bin:/usr/bin.

ENV_ROOTPATH (cadena), ENV_SUPATH (cadena)

Define la variable de entorno PATH para root. ENV_SUPATH tiene prioridad. El valor predeterminado es /usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin.

ALWAYS_SET_PATH (booleano)

Si se establece en yes y no se especificaron --login y --preserve-environment, su inicializa PATH.

La variable de entorno PATH puede ser diferente en sistemas donde /bin y /sbin se fusionan en /usr; esta variable también se ve afectada por la opción de línea de comandos --login y la configuración del sistema PAM (por ejemplo, pam_env(8)).

ESTADO DE SALIDA

Retorna el estado de salida del comando ejecutado o el estado de salida del proceso hijo cuando se está ejecutando un shell.

Para obtener más información, consulte la página del manual original de su.

ESTADO DE SALIDA

su normalmente devuelve el estado de salida del comando que ejecutó. Si el comando fue terminado por una señal, su devuelve el número de la señal más 128.

Estados de salida generados por su mismo:

1

Error genérico antes de ejecutar el comando solicitado

126

El comando solicitado no se pudo ejecutar

127

El comando solicitado no se encontró

ARCHIVOS

/etc/pam.d/su-l

archivo de configuración PAM si se especifica --login

/etc/default/su

archivo de configuración de logindef específico del comando

/etc/login.defs

archivo de configuración global de logindef

NOTAS

Por razones de seguridad, su siempre registra los intentos de inicio de sesión fallidos en el archivo btmp, pero no escribe en el archivo lastlog en absoluto. Esta solución se puede usar para controlar el comportamiento de su mediante la configuración de PAM. Si desea usar el módulo pam_lastlog(8) para mostrar un mensaje de advertencia sobre los intentos de inicio de sesión fallidos, entonces pam_lastlog(8) debe configurarse para actualizar también el archivo lastlog. Por ejemplo:

session required pam_lastlog.so nowtmp
