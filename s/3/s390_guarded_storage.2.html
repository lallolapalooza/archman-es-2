s390_guarded_storage(2) Manual de llamadas al sistema s390_guarded_storage(2)

NOMBRE

s390_guarded_storage - operaciones con la instalación de almacenamiento protegido de z/Architecture

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <asm/guarded_storage.h> /* Definición de constantes GS_* */
#include <sys/syscall.h>         /* Definición de constantes SYS_* */
#include <unistd.h>
int syscall(SYS_s390_guarded_storage, int comando,
            struct gs_cb *gs_cb);

Nota: glibc no proporciona un envoltorio para s390_guarded_storage(), lo que hace necesario el uso de syscall(2).

DESCRIPCIÓN

La llamada al sistema s390_guarded_storage() habilita el uso de la Instalación de Almacenamiento Protegido (una característica específica de z/Architecture) para procesos de espacio de usuario.

La instalación de almacenamiento protegido es una característica de hardware que permite marcar hasta 64 regiones de memoria (a partir de z14) como protegidas; la lectura de un puntero con las instrucciones recién introducidas "Load Guarded" (LGG) o "Load Logical and Shift Guarded" (LLGFSG) provocará una comprobación de rango en el valor cargado e invocará a un manejador de espacio de usuario (previamente configurado) si una de las regiones protegidas se ve afectada.

El argumento comando indica qué función realizar. Los siguientes comandos son compatibles:

GS_ENABLE
Habilita la instalación de almacenamiento protegido para la tarea que llama. El contenido inicial del bloque de control de almacenamiento protegido será todo ceros. Después de habilitar, el código del espacio de usuario puede usar la instrucción "Load Guarded Storage Controls" (LGSC) (o el envoltorio de la función load_gs_cb() proporcionado en la cabecera asm/guarded_storage.h) para cargar un bloque de control arbitrario. Mientras una tarea está habilitada, el kernel guardará y restaurará el contenido de llamada de los registros de almacenamiento protegido en los cambios de contexto.
GS_DISABLE
Inhabilita el uso de la instalación de almacenamiento protegido para la tarea que llama. El kernel dejará de guardar y restaurar el contenido de los registros de almacenamiento protegido; el contenido específico de la tarea de estos registros se pierde.
GS_SET_BC_CB
Establece un bloque de control de almacenamiento protegido de difusión a partir del proporcionado en el argumento gs_cb. Esto se llama por hilo y asocia un bloque de control de almacenamiento protegido específico con la tarea que llama. Este bloque de control se utilizará en el comando de difusión GS_BROADCAST.
GS_CLEAR_BC_CB
Borra el bloque de control de almacenamiento protegido de difusión. El bloque de control de almacenamiento protegido ya no tendrá la asociación establecida por el comando GS_SET_BC_CB.
GS_BROADCAST
Envía una difusión a todos los hermanos de hilo de la tarea que llama. Cada hermano que haya establecido un bloque de control de almacenamiento protegido de difusión cargará este bloque de control y se habilitará para el almacenamiento protegido. El bloque de control de almacenamiento protegido de difusión se consume; una segunda difusión sin actualizar el bloque de control almacenado con GS_SET_BC_CB no tendrá ningún efecto.

El argumento gs_cb especifica la dirección de una estructura de bloque de control de almacenamiento protegido y actualmente solo se utiliza por el comando GS_SET_BC_CB; todos los demás comandos mencionados ignoran este argumento.

VALOR DE RETORNO

En caso de éxito, el valor de retorno de s390_guarded_storage() es 0.

En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EFAULT
comando fue GS_SET_BC_CB y la copia de la estructura del bloque de control de almacenamiento protegido apuntada por el argumento gs_cb ha fallado.
EINVAL
El valor proporcionado en el argumento comando no era válido.
ENOMEM
comando fue uno de GS_ENABLE o GS_SET_BC_CB, y la asignación de un nuevo bloque de control de almacenamiento protegido ha fallado.
EOPNOTSUPP
La instalación de almacenamiento protegido no es compatible con el hardware.

ESTÁNDARES

Linux en s390.

HISTORIA

Linux 4.12. System z14.

NOTAS

La descripción de la instalación de almacenamiento protegido junto con las instrucciones relacionadas y los diseños de las estructuras del Bloque de Control de Almacenamiento Protegido y la Lista de Parámetros de Eventos de Almacenamiento Protegido está disponible en "z/Architecture Principles of Operations" a partir de la duodécima edición.

La estructura gs_cb tiene un campo gsepla (Dirección de la Lista de Parámetros de Eventos de Almacenamiento Protegido), que es un puntero de espacio de usuario a una estructura de Lista de Parámetros de Eventos de Almacenamiento Protegido (que contiene la dirección del mencionado manejador de eventos en el campo gseha), y su diseño está disponible como una definición de tipo de estructura gs_epl en la cabecera asm/guarded_storage.h.
