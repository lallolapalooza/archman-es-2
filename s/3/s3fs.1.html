S3FS(1) Comandos de Usuario S3FS(1)

NOMBRE

S3FS - Sistema de archivos basado en FUSE respaldado por Amazon S3

SINOPSIS

montaje

s3fs bucket[:/path] punto_montaje [opciones]
s3fs punto_montaje [opciones (se debe especificar la opción bucket=)]

desmontaje

umount punto_montaje
Para root.
fusermount -u punto_montaje
Para usuario no privilegiado.

modo de utilidad (eliminar objetos de subida multiparte interrumpida)

s3fs --incomplete-mpu-list (-u) bucket
s3fs --incomplete-mpu-abort[=all | =<fecha_expiracion_formato>] bucket

DESCRIPCIÓN

s3fs es un sistema de archivos FUSE que permite montar un bucket de Amazon S3 como un sistema de archivos local. Almacena los archivos de forma nativa y transparente en S3 (es decir, puedes usar otros programas para acceder a los mismos archivos).

AUTENTICACIÓN

s3fs soporta el archivo de credenciales estándar de AWS (https://docs.aws.amazon.com/cli/latest/userguide/cli-config-files.html) almacenado en `${HOME}/.aws/credentials`. Alternativamente, s3fs soporta un archivo de contraseñas personalizado. Solo se puede usar el formato de archivo de credenciales de AWS cuando se requiere un token de sesión de AWS. El archivo de contraseñas de s3fs tiene este formato (usa este formato si solo tienes un conjunto de credenciales):

accessKeyId:secretAccessKey

Si tienes más de un conjunto de credenciales, también se reconoce esta sintaxis:

nombreBucket:accessKeyId:secretAccessKey

Los archivos de contraseñas se pueden almacenar en dos ubicaciones:


/etc/passwd-s3fs [0640]
$HOME/.passwd-s3fs [0600]

s3fs también reconoce las variables de entorno AWS_ACCESS_KEY_ID y AWS_SECRET_ACCESS_KEY.

OPCIONES

opciones generales

-h --help
muestra la ayuda
  --version
muestra la versión
-f
Opción FUSE en primer plano - no ejecutar como demonio.
-s
Opción FUSE de hilo único (deshabilita la operación multihilo)

opciones de montaje

Todas las opciones de s3fs deben darse en la forma donde "opt" es:

<nombre_opcion>=<valor_opcion>
-o bucket
si no se especifica el nombre del bucket (y la ruta) en la línea de comandos, se debe especificar esta opción después de la opción -o para el nombre del bucket.
-o default_acl (predeterminado="private")
la ACL predeterminada predefinida que se aplicará a todos los objetos de s3 escritos, p. ej., "private", "public-read". Ver https://docs.aws.amazon.com/AmazonS3/latest/dev/acl-overview.html#canned-acl para la lista completa de ACL predefinidas.
-o retries (predeterminado="5")
número de veces que se reintentará una transacción S3 fallida.
-o tmpdir (predeterminado="/tmp")
carpeta local para archivos temporales.
-o use_cache (predeterminado="", lo que significa deshabilitado)
carpeta local a utilizar para la caché de archivos local.
-o check_cache_dir_exist (predeterminado está deshabilitado)
Si se establece use_cache, comprueba si el directorio de caché existe. Si esta opción no se especifica, se creará en tiempo de ejecución cuando el directorio de caché no exista.
-o del_cache - elimina la caché de archivos local
elimina la caché de archivos local cuando s3fs se inicia y se sale.
-o storage_class (predeterminado="standard")
almacena el objeto con la clase de almacenamiento especificada. Valores posibles: standard, standard_ia, onezone_ia, reduced_redundancy, intelligent_tiering, glacier, glacier_ir, y deep_archive.
-o use_rrs (predeterminado está deshabilitado)
usa el Almacenamiento de Redundancia Reducida (Reduced Redundancy Storage) de Amazon. esta opción no se puede especificar con use_sse. (se puede especificar use_rrs=1 para versiones antiguas) esta opción ha sido reemplazada por la nueva opción storage_class.
-o use_sse (predeterminado está deshabilitado)
Especifica tres tipos de Cifrado del Lado del Servidor (Server-Side Encryption) de Amazon: SSE-S3, SSE-C o SSE-KMS. SSE-S3 utiliza claves de cifrado gestionadas por Amazon S3, SSE-C utiliza claves de cifrado proporcionadas por el cliente, y SSE-KMS utiliza la clave maestra que gestionas en AWS KMS. Puedes especificar "use_sse" o "use_sse=1" para habilitar el tipo SSE-S3 (use_sse=1 es un parámetro de tipo antiguo). En caso de establecer SSE-C, puedes especificar "use_sse=custom", "use_sse=custom:<ruta_archivo_clave_personalizada>" o "use_sse=<ruta_archivo_clave_personalizada>" (solo <ruta_archivo_clave_personalizada> especificada es un parámetro de tipo antiguo). Puedes usar "c" como abreviatura de "custom". El archivo de claves personalizadas debe tener permisos 600. El archivo puede tener varias líneas, cada línea es una clave SSE-C. La primera línea del archivo se utiliza como Claves de Cifrado Proporcionadas por el Cliente para subir y cambiar encabezados, etc. Si hay claves después de la primera línea, estas se utilizan para descargar objetos que están cifrados por una clave no inicial. Por lo tanto, puedes mantener todas las claves SSE-C en el archivo, que es el historial de claves SSE-C. Si especificas "custom" ("c") sin una ruta de archivo, necesitas establecer la clave personalizada mediante la opción load_sse_c o la variable de entorno AWSSSECKEYS (la variable de entorno AWSSSECKEYS tiene claves SSE-C con separador ":"). Para establecer SSE-KMS, especifica "use_sse=kmsid" o "use_sse=kmsid:<kms_id>". Puedes usar "k" como abreviatura de "kmsid". Si puedes especificar el tipo SSE-KMS con tu <kms_id> en AWS KMS, puedes configurarlo después de "kmsid:" (o "k:"). Si solo especificas "kmsid" ("k"), necesitas establecer la variable de entorno AWSSSEKMSID cuyo valor es <kms_id>. Debes tener cuidado ya que no puedes usar un ID de KMS que no sea de la misma región EC2. Además, si especificas SSE-KMS, tus puntos de conexión deben usar Secure Sockets Layer (SSL) o Transport Layer Security (TLS).
-o load_sse_c - especifica claves SSE-C
Especifica la ruta del archivo de claves de cifrado proporcionadas por el cliente para descifrar al descargar. Si usas la clave de cifrado proporcionada por el cliente al subir, la especificas con "use_sse=custom". El archivo tiene muchas líneas, una línea significa una clave personalizada. Por lo tanto, puedes mantener todas las claves SSE-C en el archivo, que es el historial de claves SSE-C. La variable de entorno AWSSSECKEYS tiene el mismo contenido que este archivo.
-o passwd_file (predeterminado="")
especifica la ruta al archivo de contraseñas, que tiene prioridad sobre las contraseñas en $HOME/.passwd-s3fs y /etc/passwd-s3fs
-o ahbe_conf (predeterminado="", lo que significa deshabilitado)

-o perfil (predeterminado="default")
Elige un perfil de ${HOME}/.aws/credentials para autenticarse contra S3. Tenga en cuenta que este formato coincide con el formato de la AWS CLI y difiere del formato de contraseña de s3fs.
-o cubo_público (predeterminado="" que significa deshabilitado)
monta anónimamente un cubo público cuando se establece en 1, ignora los archivos $HOME/.passwd-s3fs y /etc/passwd-s3fs. S3 no permite la API de copia de objetos para usuarios anónimos, por lo que s3fs establece la opción nocopyapi automáticamente cuando se especifica la opción public_bucket=1.
-o tiempo_de_conexión (predeterminado="300" segundos)
tiempo de espera para la conexión antes de rendirse.
-o tiempo_de_espera_lectura_escritura (predeterminado="120" segundos)
tiempo de espera entre actividad de lectura/escritura antes de rendirse.
-o max_list_object_keys (predeterminado="1000")
especifica el número máximo de claves devueltas por la API de S3 list object. El valor predeterminado es 1000. puede establecer este valor en 1000 o más.
-o tamaño_máximo_caché_stat (predeterminado="100.000" entradas (aproximadamente 40 MB))
número máximo de entradas en la caché de stat y la caché de enlaces simbólicos.
-o caducidad_caché_stat (predeterminado es 900)
especifica el tiempo de caducidad (segundos) para las entradas en la caché de stat y la caché de enlaces simbólicos. Este tiempo de caducidad indica el tiempo desde que se almacenó en caché.
-o caducidad_intervalo_caché_stat (predeterminado es 900)
especifica el tiempo de caducidad (segundos) para las entradas en la caché de stat y la caché de enlaces simbólicos. Este tiempo de caducidad se basa en el tiempo desde la última vez que se accedió a esa caché. Esta opción es exclusiva con stat_cache_expire y se mantiene por compatibilidad con versiones anteriores.
-o deshabilitar_caché_noobj (predeterminado es habilitar)
Por defecto, s3fs memoriza cuándo un objeto no existe hasta el tiempo de espera de la caché de stat. Este almacenamiento en caché puede causar desactualización para las aplicaciones. Si se deshabilita, s3fs no memorizará objetos y puede causar solicitudes adicionales de HeadObject y reducir el rendimiento.
-o no_verificar_certificado (por defecto esta opción está deshabilitada)
el certificado del servidor no se verificará contra las autoridades certificadoras disponibles.
-o ssl_verificar_hostname (predeterminado="2")
Cuando es 0, no verificar el certificado SSL contra el nombre de host.
-o cliente_cert_ssl (predeterminado="")
Especificar un certificado de cliente SSL. Especifique este parámetro opcional en el siguiente formato:
"<SSL Cert>[:<Tipo Cert>[:<Clave Privada>[:<Tipo Clave>
[:<Contraseña>]]]]"
<SSL Cert>: Certificado del cliente.
Especifique la ruta del archivo o NickName (para NSS, etc.).
<Tipo Cert>: Tipo de certificado, el predeterminado es "PEM"(opcional).
<Clave Privada>: Archivo de clave privada del certificado (opcional).
<Tipo Clave>: Tipo de clave privada, el predeterminado es "PEM"(opcional).
<Contraseña>: Frase de contraseña de la clave privada (opcional). También es posible omitir este valor y especificarlo mediante la variable de entorno "S3FS_SSL_PRIVKEY_PASSWORD".
-o nodnscache - deshabilitar la caché de DNS.
s3fs siempre utiliza la caché de DNS, esta opción deshabilita la caché de DNS.
-o nosscache - deshabilitar la caché de sesiones SSL.
s3fs siempre utiliza la caché de sesiones SSL, esta opción deshabilita la caché de sesiones SSL.
-o multireq_max (predeterminado="20")
número máximo de solicitudes paralelas para listar objetos.
-o recuento_paralelo (predeterminado="5")
número de solicitudes paralelas para cargar objetos grandes. s3fs carga objetos grandes (más de 25 MB por defecto) mediante solicitudes multipart post y envía solicitudes paralelas. Esta opción limita el número de solicitudes paralelas que s3fs solicita a la vez. Es necesario establecer este valor en función de la CPU y la banda de red.
-o tamaño_multipart (predeterminado="10")
tamaño de la parte, en MB, para cada solicitud multipart. El valor mínimo es de 5 MB y el valor máximo es de 5 GB.
-o tamaño_copia_multipart (predeterminado="512")
tamaño de la parte, en MB, para cada solicitud de copia multipart, utilizada para renombrar y mezclar cargas. El valor mínimo es de 5 MB y el valor máximo es de 5 GB. Debe ser de al menos 512 MB para copiar el tamaño máximo de objeto de 5 TB, pero valores inferiores pueden mejorar el rendimiento.
-o datos_sucios_máximos (predeterminado="5120")
Volcar datos sucios a S3 después de un cierto número de MB escritos. El valor mínimo es de 50 MB. El valor -1 significa deshabilitar. No se puede usar con nomixupload.
-o tamaño_cubo (predeterminado=valor entero largo máximo)
El tamaño del cubo con el que se rellenarán los elementos correspondientes de la estructura statvfs. El argumento de la opción es un entero opcionalmente seguido de un sufijo multiplicador (GB, GiB, TB, TiB, PB, PiB, EB, EiB) (sin espacios intermedios). Si no se proporciona ningún sufijo, se asumen bytes; por ejemplo: 20000000, 30GB, 45TiB. Tenga en cuenta que s3fs no calcula el tamaño real del volumen (demasiado caro): por defecto asumirá el tamaño máximo posible; sin embargo, dado que esto puede confundir a otro software que utiliza s3fs, el tamaño del cubo anunciado se puede establecer con esta opción.
-o asegurar_espacio_disco_libre (predeterminado 0)
establece MB para asegurar espacio libre en disco. Esta opción significa el umbral de tamaño de espacio libre en disco que se utiliza para el archivo de caché de s3fs. s3fs crea archivos para descargar, cargar y almacenar en caché. Si el espacio libre en disco es menor que este valor, s3fs no utilizará el espacio en disco tanto como sea posible a cambio de rendimiento.
-o ratio_espacio_libre (predeterminado="10")
establece el espacio libre mínimo en relación con el disco. El valor de esta opción puede estar entre 0 y 100. Controlará el tamaño de la caché según esta relación para garantizar que la relación inactiva del disco sea superior a este valor. Por ejemplo, cuando el espacio en disco es de 50 GB, el valor predeterminado garantizará que el disco reserve al menos 50 GB * 10 % = 5 GB de espacio restante.
-o umbral_multipart (predeterminado="25")
umbral, en MB, para usar carga multipart en lugar de una sola parte. Debe ser al menos 5 MB.
-o límite_copia_una_parte (predeterminado="512")
tamaño máximo, en MB, de una copia de una sola parte antes de intentar una copia multipart.
-o host (predeterminado="https://s3.amazonaws.com")
Establecer un host no de Amazon, por ejemplo, https://example.com.
-o ruta_servicio (predeterminado="/")
Establecer una ruta de servicio cuando el host no de Amazon requiera un prefijo.
-o url (predeterminado="https://s3.amazonaws.com")
establece la url a utilizar para acceder a Amazon S3. Si desea utilizar HTTP, puede establecer "url=http://s3.amazonaws.com". Si no usa https, especifique la URL con la opción url.
-o endpoint (predeterminado="us-east-1")
establece el punto final a utilizar en la firma versión 4. Si esta opción no se especifica, s3fs utiliza la región "us-east-1" como predeterminada. Si s3fs no puede conectarse a la región especificada por esta opción, s3fs no podrá ejecutarse. Pero si no especifica esta opción, y si no puede conectarse con la región predeterminada, s3fs intentará reconectarse automáticamente a otra región. Por lo tanto, s3fs puede conocer el nombre de la región correcta, ya que s3fs puede encontrarlo en un error del servidor S3.
-o sigv2 (predeterminado es firma versión 4 con retroceso a la versión 2)
establece la firma de las solicitudes de AWS utilizando solo la firma versión 2.
-o sigv4 (predeterminado es firma versión 4 con retroceso a la versión 2)
establece la firma de las solicitudes de AWS utilizando solo la firma versión 4.
-o mp_umask (predeterminado es "0000")
establece umask para el directorio del punto de montaje. Si la opción allow_other no está configurada, s3fs permite el acceso al punto de montaje solo al propietario. En el caso contrario, s3fs permite el acceso a todos los usuarios por defecto. Pero si se configura allow_other con esta opción, puede controlar los permisos del punto de montaje con esta opción como umask.
-o umask (predeterminado es "0000")
establece umask para los archivos bajo el punto de montaje. Esto puede permitir a usuarios distintos del usuario que monta leer y escribir en archivos que no crearon.
-o nomultipart - deshabilitar cargas multipart
-o streamupload (predeterminado está deshabilitado)
Habilita la carga en streaming. Si esta opción está habilitada, se realizará una carga secuencial
Se puede realizar en paralelo con la escritura desde la parte que se ha escrito durante una carga multipart. Se espera que esto proporcione un mejor rendimiento que otras funciones de carga. Tenga en cuenta que esta opción sigue siendo experimental y puede cambiar en el futuro.
-o max_thread_count (por defecto es "5")
Especifica el número de hilos que esperan por cargas de secuencias. Tenga en cuenta que esta opción y Carga de Secuencia siguen siendo experimentales y están sujetas a cambios en el futuro. Esta opción se fusionará con "parallel_count" en el futuro.
-o enable_content_md5 (por defecto es deshabilitado)
Permite al servidor S3 verificar la integridad de los datos de las cargas a través de la cabecera Content-MD5. Esto puede añadir sobrecarga de CPU a las transferencias.
-o enable_unsigned_payload (por defecto es deshabilitado)
No calcula Content-SHA256 para las cargas útiles de PutObject y UploadPart. Esto puede reducir la sobrecarga de CPU en las transferencias.
-o ecs (por defecto es deshabilitado)
Esta opción instruye a s3fs a consultar la dirección de metadatos de credenciales del contenedor ECS en lugar de la dirección de metadatos de la instancia.
-o iam_role (por defecto es ninguna rol IAM)
Esta opción requiere el nombre del rol IAM o "auto". Si especifica "auto", s3fs usará automáticamente los nombres de rol IAM que estén asignados a una instancia. Si especifica esta opción sin ningún argumento, es lo mismo que haber especificado "auto".
-o imdsv1only (por defecto es usar IMDSv2 con respaldo a v1)
El servicio de metadatos de instancias de AWS, utilizado con la autenticación de roles IAM, admite el uso de un token de API. Si está utilizando un rol IAM en un entorno que no admite IMDSv2, activar esta opción omitirá la recuperación y el uso del token de API al recuperar credenciales IAM.
-o ibm_iam_auth (por defecto es no usar autenticación IBM IAM)
Esta opción instruye a s3fs a utilizar la autenticación IBM IAM. En este modo, AWSAccessKey y AWSSecretKey se utilizarán como Service-Instance-ID y APIKey de IBM, respectivamente.
-o ibm_iam_endpoint (por defecto es https://iam.cloud.ibm.com)
Establece la URL a utilizar para la autenticación IBM IAM.
-o credlib (por defecto=
Especifica la biblioteca compartida que maneja las credenciales que contienen el token de autenticación. Si se especifica esta opción, la credencial y el procesamiento del token proporcionados por la biblioteca compartida se realizarán en lugar del procesamiento de credenciales incorporado. Esta opción no se puede especificar con las opciones passwd_file, profile, use_session_token, ecs, ibm_iam_auth, ibm_iam_endpoint, imdsv1only e iam_role.
-o credlib_opts (por defecto=
Especifica las opciones a pasar cuando la biblioteca compartida especificada en credlib se carga y luego se inicializa. Para la cadena especificada en esta opción, especifique la cadena definida por la biblioteca compartida.
-o use_xattr (por defecto es no manejar el atributo extendido)
Permite manejar el atributo extendido (xattrs). Si establece esta opción, puede utilizar el atributo extendido. Por ejemplo, encfs y ecryptfs necesitan admitir el atributo extendido. Aviso: si s3fs maneja el atributo extendido, s3fs no podrá funcionar con el comando copy con preserve=mode.
-o noxmlns - deshabilita el registro del espacio de nombres xml.
deshabilita el registro del espacio de nombres xml para la respuesta de ListBucketResult y ListVersionsResult, etc. El espacio de nombres por defecto se busca en "http://s3.amazonaws.com/doc/2006-03-01". Esta opción no debería especificarse ahora, ya que s3fs busca xmlns automáticamente después de la v1.66.
-o nomixupload - deshabilita la copia en cargas multipart.
Deshabilita el uso de PUT (api de copia) al subir objetos de gran tamaño en multipart. Por defecto, al realizar una carga multipart, el rango de datos sin cambios utilizará PUT (api de copia) siempre que sea posible. Cuando se especifica nocopyapi o norenameapi, el uso de PUT (api de copia) se invalida incluso si esta opción no se especifica.
-o nocopyapi - para otra compatibilidad incompleta de almacenamiento de objetos.
Para un almacenamiento de objetos distribuido que sea compatible con la API S3 sin PUT (api de copia). Si establece esta opción, s3fs no utilizará PUT con "x-amz-copy-source" (api de copia). Dado que el tráfico aumenta 2-3 veces con esta opción, no la recomendamos.
-o norenameapi - para otra compatibilidad incompleta de almacenamiento de objetos.
Para un almacenamiento de objetos distribuido que sea compatible con la API S3 sin PUT (api de copia). Esta opción es un subconjunto de la opción nocopyapi. La opción nocopyapi no utiliza la api de copia para todos los comandos (ej. chmod, chown, touch, mv, etc), pero esta opción no utiliza la api de copia solo para el comando de renombrar (ej. mv). Si esta opción se especifica junto con nocopyapi, s3fs la ignora.
-o use_path_request_style (usa el estilo de llamada API heredado)
Habilita la compatibilidad con APIs similares a S3 que no admiten el estilo de solicitud de host virtual, utilizando el estilo de solicitud de ruta más antiguo.
-o listobjectsv2 (usa ListObjectsV2)
Emite ListObjectsV2 en lugar de ListObjects, útil en almacenamientos de objetos sin soporte para ListObjects.
-o noua (suprime la cabecera User-Agent)
Normalmente s3fs genera la salida del User-Agent en formato "s3fs/ (hash de commit ; )". Si se especifica esta opción, s3fs suprime la salida del User-Agent.
-o cipher_suites
Personaliza la lista de conjuntos de cifrado TLS. Espera una lista de nombres de conjuntos de cifrado separados por dos puntos. Una lista de conjuntos de cifrado disponibles, dependiendo de su motor TLS, se puede encontrar en la documentación de la biblioteca CURL: https://curl.haxx.se/docs/ssl-ciphers.html
-o instance_name
El nombre de la instancia del punto de montaje s3fs actual. Este nombre se añadirá a los mensajes de registro y a las cabeceras del agente de usuario enviadas por s3fs.
-o complement_stat (complementa la falta de modo de archivo/directorio)
s3fs complementa la falta de información sobre el modo de archivo/directorio si un archivo o directorio no tiene la cabecera x-amz-meta-mode. Por defecto, s3fs no complementa la información stat para un objeto, entonces el objeto no podrá ser permitido listar/modificar.
-o compat_dir (habilita el soporte de nombres de directorio alternativos)
s3fs admite dos esquemas de nombres diferentes: "/" y "dir" para mapear nombres de directorio a objetos S3 y viceversa por defecto. Como tercera variante, los directorios pueden determinarse indirectamente si hay un objeto de archivo con una ruta (ej. "/dir/file") pero sin el directorio padre. Esta opción habilita una cuarta variante, "dir_$folder$", creada por aplicaciones más antiguas.
S3fs solo utiliza el primer esquema "dir/" para crear objetos S3 para directorios.
El soporte para estos diferentes esquemas de nombres provoca un mayor esfuerzo de comunicación.
Si no tiene permisos de acceso al bucket y especifica una ruta de directorio creada por un cliente distinto de s3fs para el punto de montaje, no podrá iniciarse porque s3fs no puede encontrar el directorio del punto de montaje. Pero al especificar esta opción, puede evitar este error.
-o use_wtf8 - soporte de codificación de sistema de archivos arbitraria.
S3 requiere que todos los nombres de objeto sean UTF-8 válidos. Pero algunos clientes, notablemente los clientes NFS de Windows, usan su propia codificación. Esta opción recodifica los nombres de objeto UTF-8 no válidos en UTF-8 válidos mapeando códigos ofensivos a una 'codepage privada' del conjunto Unicode. Útil en clientes que no usan UTF-8 como su codificación de sistema de archivos.
-o use_session_token - indica que se debe proporcionar un token de sesión.
Si las credenciales se proporcionan a través de variables de entorno, este interruptor fuerza la comprobación de la presencia de la variable AWS_SESSION_TOKEN. De lo contrario, se devuelve un error.
-o requester_pays (por defecto es deshabilitado)
Esta opción instruye a s3fs a habilitar solicitudes que involucren buckets de Requester Pays (Incluye la entrada 'x-amz-request-payer=requester' en la cabecera de la solicitud).
-o mime (por defecto es "/etc/mime.types")
Especifica la ruta del archivo mime.types. Si esta opción no se especifica, se comprueba la existencia de "/etc/mime.types", y ese archivo se carga como información mime. Si este archivo no existe en macOS, entonces también se comprueba "/etc/apache2/mime.types".
-o proxy (por defecto="")
Esta opción especifica un proxy al servidor S3. Especifique el proxy con el formato '[]'. Además, ':' también se puede omitir. Si se omite, se utiliza el puerto 443 para el esquema HTTPS, y se utiliza el puerto 1080 en caso contrario. Esta opción es lo mismo que la opción '--proxy(-x)' del comando curl y el flag 'CURLOPT_PROXY' de libcurl. Esta opción es equivalente y tiene prioridad sobre las variables de entorno 'http_proxy', 'all_proxy', etc.
-o proxy_cred_file (por defecto="")
Esta opción especifica el archivo que describe el nombre de usuario y la contraseña para la autenticación del proxy cuando se especifica un proxy de esquema HTTP mediante la opción 'proxy'. El nombre de usuario y la contraseña solo son válidos para el esquema HTTP. Si el proxy HTTP no requiere autenticación, esta opción no es necesaria. Separe el nombre de usuario y la contraseña con un carácter ':' y especifique cada uno como una cadena codificada en URL.
-o ipresolve (por defecto="whatever")
Selecciona qué tipo de direcciones IP utilizar al establecer una conexión.

OPTIONS

s3fs supports the following options:

-o allow_other
Allow other users besides the FUSE filesystem user to access filesystem. When this option is set, the filesystem is mounted based on the permissions of the calling user and the contents of the mount point.
-o use_ino
Enable the emulation of 64-bit inodes that is required by some applications. The inode numbers are generated by s3fs.
-o use_ipv4
Only use IPv4 addresses. By default (Default) all IP versions (IPv4 and IPv6) allowed by your system are used. If you specify IPv4, only IPv4 addresses are used. And when IPv6 is specified, only IPv6 addresses will be used.
-o logfile - specify the log output file.
s3fs outputs the log file to syslog. Alternatively, if s3fs is started with the "-f" option specified, the log will be output to the stdout/stderr. You can use this option to specify the log file that s3fs outputs. If you specify a log file with this option, it will reopen the log file when s3fs receives a SIGHUP signal. You can use the SIGHUP signal for log rotation.
-o dbglevel (default="crit")
Set the debug message level. set value as crit (critical), err (error), warn (warning), info (information) to debug level. default debug level is critical. If s3fs run with "-d" option, the debug level is set information. When s3fs catch the signal SIGUSR2, the debug level is bump up.
-o curldbg - put curl debug message
Put the debug message from libcurl when this option is specified. Specify "normal" or "body" for the parameter. If the parameter is omitted, it is the same as "normal". If "body" is specified, some API communication body data will be output in addition to the debug message output as "normal".
-o no_time_stamp_msg - no time stamp in debug message
The time stamp is output to the debug message by default. If this option is specified, the time stamp will not be output in the debug message. It is the same even if the environment variable "S3FS_MSGTIMESTAMP" is set to "no".
-o set_check_cache_sigusr1 (default is stdout)
If the cache is enabled, you can check the integrity of the cache file and the cache file's stats info file. This option is specified and when sending the SIGUSR1 signal to the s3fs process checks the cache status at that time. This option can take a file path as parameter to output the check result to that file. The file path parameter can be omitted. If omitted, the result will be output to stdout or syslog.
-o update_parent_dir_stat (default is disable)
The parent directory's mtime and ctime are updated when a file or directory is created or deleted (when the parent directory's inode is updated). By default, parent directory statistics are not updated.

utility mode options

-u or --incomplete-mpu-list
Lists multipart incomplete objects uploaded to the specified bucket.
--incomplete-mpu-abort all or date format (default="24H")
Delete the multipart incomplete object uploaded to the specified bucket. If "all" is specified for this option, all multipart incomplete objects will be deleted. If you specify no argument as an option, objects older than 24 hours (24H) will be deleted (This is the default value). You can specify an optional date format. It can be specified as year, month, day, hour, minute, second, and it is expressed as "Y", "M", "D", "h", "m", "s" respectively. For example, "1Y6M10D12h30m30s".

FUSE/MOUNT OPTIONS

Most of the generic mount options described in 'man mount' are supported (ro, rw, suid, nosuid, dev, nodev, exec, noexec, atime, noatime, sync, async, dirsync). Filesystems are mounted with '-onodev,nosuid' by default, which can only be overridden by a privileged user.
There are many FUSE specific mount options that can be specified. e.g. allow_other. See the FUSE README for the full set.

SERVER URL/REQUEST STYLE

Be careful when specifying the server endpoint(URL).

If your bucket name contains dots("."), you should use the path request style(using "use_path_request_style" option).
Also, if you are using a server other than Amazon S3, you need to specify the endpoint with the "url" option. At that time, depending on the server you are using, you may have to specify the path request style("use_path_request_style" option).

LOCAL STORAGE CONSUMPTION

s3fs requires local caching for operation. You can enable a local cache with "-o use_cache" or s3fs uses temporary files to cache pending requests to s3.
Apart from the requirements discussed below, it is recommended to keep enough cache resp. temporary storage to allow one copy each of all files open for reading and writing at any one time.

Local cache with "-o use_cache"

s3fs automatically maintains a local cache of files. The cache folder is specified by the parameter of "-o use_cache". It is only a local cache that can be deleted at any time. s3fs rebuilds it if necessary.
Whenever s3fs needs to read or write a file on S3, it first creates the file in the cache directory and operates on it.
The amount of local cache storage used can be indirectly controlled with "-o ensure_diskfree".

Without local cache

Since s3fs always requires some storage space for operation, it creates temporary files to store incoming write requests until the required s3 request size is reached and the segment has been uploaded. After that, this data is truncated in the temporary file to free up storage space.
Per file you need at least twice the part size (default 5MB or "-o multipart_size") for writing multipart requests or space for the whole file if single requests are enabled ("-o nomultipart").

PERFORMANCE CONSIDERATIONS

This section discusses settings to improve s3fs performance.
In most cases, backend performance cannot be controlled and is therefore not part of this discussion.
Details of the local storage usage is discussed in "LOCAL STORAGE CONSUMPTION".

CPU and Memory Consumption

s3fs is a multi-threaded application. Depending on the workload it may use multiple CPUs and a certain amount of memory. You can monitor the CPU and memory consumption with the "top" utility.

Performance of S3 requests

s3fs provides several options (e.g. "-o multipart_size", "-o parallel_count") to control behaviour and thus indirectly the performance. The possible combinations of these options in conjunction with the various S3 backends are so varied that there is no individual recommendation other than the default values. Improved individual settings can be found by testing and measuring.
The two options "Enable no object cache" ("-o enable_noobj_cache") and "Disable support of alternative directory names" ("-o notsup_compat_dir") can be used to control shared access to the same bucket by different applications:
•
Enable no object cache ("-o enable_noobj_cache")
If a bucket is used exclusively by an s3fs instance, you can enable the cache for non-existent files and directories with "-o enable_noobj_cache". This eliminates repeated requests to check the existence of an object, saving time and possibly money.
•
Enable support of alternative directory names ("-o compat_dir")
s3fs recognizes "dir/" objects as directories. Clients other than s3fs may use "dir", "dir_$folder$" objects as directories, or directory objects may not exist. In order for s3fs to recognize these as directories, you can specify the "compat_dir" option.

PERFORMANCE CONSIDERATIONS

The behavior of s3fs is highly dependent on the performance of Amazon S3, and the network connection. S3 is object storage, not a file system. It does not support operations like checking if a file exists before uploading it. This means that s3fs has to perform additional operations, or retry failed operations.
Amazon S3 does not store file attributes such as owner, group, and permissions. s3fs emulates these attributes, but they are not real. The owner and group are set to the user and group that mounted s3fs. The permissions are set to 777 by default. If the ACLs of an object are set, then s3fs will use the ACLs. If the ACLs are not set, s3fs will default to using the ACLs that are set for the bucket. If the owner or group are unknown to s3fs, then the files will not be displayed, etc.). By specifying the "complement_stat" option, s3fs can automatically complete this missing attribute information, and you can get the expected results.

NOTES

The maximum size of objects that s3fs can handle depends on Amazon S3. For example, up to 5 GB when using single PUT API. And up to 5 TB is supported when Multipart Upload API is used.
s3fs leverages /etc/mime.types to "guess" the "correct" content-type based on file name extension. This means that you can copy a website to S3 and serve it up directly from S3 with correct content-types!

BUGS

Due to S3's "eventual consistency" limitations, file creation can and will occasionally fail. Even after a successful create, subsequent reads can fail for an indeterminate time, even after one or more successful reads. Create and read enough files and you will eventually encounter this failure. This is not a flaw in s3fs and it is not something a FUSE wrapper like s3fs can work around. The retries option does not address this issue. Your application must either tolerate or compensate for these failures, for example by retrying creates or reads.
