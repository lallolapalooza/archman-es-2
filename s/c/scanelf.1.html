SCANELF(1) Documentación de pax-utils SCANELF(1)

NOMBRE

scanelf - utilidad de espacio de usuario para escanear archivos ELF

SINOPSIS

scanelf [opciones] ELFs o directorios

DESCRIPCIÓN

scanelf es una utilidad de espacio de usuario para escanear rápidamente archivos ELF dados, directorios o rutas de sistema comunes en busca de diferente información. Esto puede incluir tipos ELF, sus marcas PaX, TEXTRELs, etc...

OPCIONES

-A, --archives

Escanear archivos (.a)

-a, --all

Imprimir toda la información útil/simple

-B, --nobanner

No mostrar la cabecera

-b, --bind

Imprimir información de enlace de símbolos (lazy o now)

-D, --endian

Imprimir el endianness del ELF (big/little/...)

-E, --etype ETYPE

Imprimir solo archivos ELF que coincidan con el etype especificado (como ET_DYN, ET_EXEC, etc...)

-e, --header

Imprimir marcas GNU_STACK

-F, --format FORMAT

Usar el formato especificado para la salida; consulte la sección FORMATO para más información

-f, --from FILE

Leer el flujo de entrada del nombre de archivo especificado

-g, --gmatch

Usar strncmp para hacer coincidir bibliotecas (usar con -N). O regexp con coincidencia de símbolos

-h, --help

Mostrar uso condensado y salir

-I, --osabi

Imprimir OSABI

-i, --interp

Imprimir la información del intérprete (.interp/PT_INTERP)

-k, --section SECTION

Encontrar ELFs con la sección especificada. Puede ser especificado múltiples veces para hacer coincidir múltiples secciones simultáneamente. Consulte COINCIDENCIA DE SECCIÓN para más información.

-L, --ldcache

Utilizar información de ld.so.cache (usar con -r/-n)

-l, --ldpath

Escanear todos los directorios en /etc/ld.so.conf

-M, --bits BITS

Imprimir solo archivos ELF que coincidan con los bits numéricos especificados (como 32/64)

-m, --mount

No cruzar recursivamente los puntos de montaje

-N, --lib SONAME

Encontrar ELFs que necesiten el SONAME especificado. Puede ser especificado múltiples veces para hacer coincidir múltiples SONAMEs simultáneamente. Consulte COINCIDENCIA DE SONAME para más información.

-n, --needed

Imprimir bibliotecas con las que el ELF está enlazado (DT_NEEDED)

-O, --perms PERMS

Imprimir solo archivos ELF con los bits octales que coincidan especificados (como 755)

-o, --file FILE

Escribir el flujo de salida al nombre de archivo especificado

-p, --path

Escanear todos los directorios en la variable de entorno PATH

-q, --quiet

Solo emitir cosas 'malas'

-R, --recursive

Escanear directorios recursivamente

-r, --rpath

Imprimir runpaths codificados en el ELF (DT_RPATH/DT_RUNPATH)

-S, --soname

Imprimir el nombre de la biblioteca compartida del ELF (DT_SONAME)

-s, --symbol SYMBOL

Encontrar el símbolo especificado; consulte COINCIDENCIA DE SÍMBOLOS para más información

-T, --textrels

Localizar la causa de TEXTRELs mediante objdump

-t, --textrel

Imprimir información de TEXTREL

-V, --version

Imprimir versión y salir

-v, --verbose

Ser verboso (se puede usar más de una vez)

-X, --fix

Intentar 'arreglar' cosas malas (usar con -r/-e)

-x, --pax

Imprimir marcas PaX

-Y, --eabi

Imprimir EABI (solo importa para algunas arquitecturas)

-y, --symlink

No escanear enlaces simbólicos

-Z, --size SIZE

Imprimir el tamaño del archivo ELF

-z, --setpax FLAGS

Establece EI_PAX/PT_PAX_FLAGS a las banderas especificadas (usar con -Xx)

--use-ldpath

Usar las rutas de ld.so.conf para encontrar la ruta completa a las bibliotecas (usar junto con --needed).

--root PATH

Buscar en el árbol raíz especificado en lugar de /. Generalmente se empareja con opciones como -l o -p. Esto trata implícitamente todas las rutas especificadas en la línea de comandos como relativas a la raíz, así que asegúrate de omitirlo si estás listando explícitamente ELFs.

--ldcache PATH

Usar la ruta especificada en lugar de /etc/ld.so.cache. Generalmente se empareja con opciones como -L o -n.

FORMATO

La cadena de formato es muy parecida a una cadena printf en el sentido de que es una cadena literal con indicadores que solicitan diferente información. Por ejemplo, podrías usar una cadena de formato y esperar los siguientes resultados.

  # scanelf -BF "archivo %f necesita %n; hora funky" /bin/bash
  archivo bash necesita libncurses.so.5,libdl.so.2,libc.so.6; hora funky

Ten en cuenta que cuando usas una cadena de formato, generalmente se deben omitir las opciones relacionadas con la información. En otras palabras, no querrás intentar solicitar la salida NEEDED (-n) y especificar una salida de formato al mismo tiempo, ya que estas operaciones son mutuamente excluyentes. Cada indicador relacionado con la información tiene un especificador de conversión equivalente, así que úsalos en su lugar. Por supuesto, puedes seguir usando indicadores no relacionados con la información (como --verbose).

Hay tres caracteres que introducen especificadores de conversión.

• % - reemplazar con información

•
# - coincidencia booleana silenciosa
•
+ - coincidencia verbosa

Y hay una serie de especificadores de conversión. Intentamos hacer coincidir el especificador con la opción correspondiente.

• a - tipo de máquina (EM)

•
b - banderas de enlace
•
e - cabeceras de programa
•
D - endianness
•
I - osabi
•
Y - eabi
•
F - nombre de archivo largo
•
f - nombre de archivo corto
•
i - interp
•
k - sección
•
M - clase EI
•
N - needed especificado
•
n - bibliotecas needed
•
p - nombre de archivo (sin ruta)
•
o - etype
•
O - perms
•
r - runpaths
•
S - SONAME
•
s - símbolo
•
T - todos los textrels
•
t - estado de textrel
•
x - marcas pax

COINCIDENCIA DE SÍMBOLOS

La cadena especificada toma la forma [%[modificadores]%][[+-]<nombre de símbolo>][,[.....]].

Si el nombre de símbolo está vacío, entonces se hace coincidir todos los símbolos.

Si el nombre de símbolo es un comodín ("*"), entonces todos los símbolos se vuelcan en formato de depuración. No te fíes de la estructura de esta salida, ya que cambia cuando nos apetece.

SYMBOL MATCHING

The scanelf command can search for symbols within the ELF file. This search can be modified to show symbols that are defined (within the ELF object) or undefined (external references).

By default, without any modifiers, it will find all symbols.

A leading ! will negate the match. So !defined will match only undefined symbols. When we say "defined", we mean the symbol is defined in the ELF vs having an external reference.

Putting modifiers in between the percent signs ("%") allows for more in depth filters. There are groups of modifiers. If you don't specify a member of a group, then all types in that group are matched.

  • STT group (symbol type)
    • n - STT_NOTYPE
    • o - STT_OBJECT
    • f - STT_FUNC
    • F - STT_FILE
  • STB group (symbol binding)
    • l - STB_LOCAL
    • g - STB_GLOBAL
    • w - STB_WEAK
  • STV group (symbol visibility)
    • p - STV_DEFAULT
    • i - STV_INTERNAL
    • h - STV_HIDDEN
    • P - STV_PROTECTED
  • SHN group (section header)
    • d - defined
    • u - SHN_UNDEF
    • a - SHN_ABS
    • c - SHN_COMMON

You can search for multiple symbols simultaneously by using a comma (",") to separate different searches. Every symbol that matches will be displayed while unmatched symbols will not.

ELF ETYPES

You can narrow your search by specifying the ELF object file type (ETYPE). The commandline option takes the numeric value and or symbolic type. Multiple values can be passed comma separated. Example -E ET_EXEC,ET_DYN,1

Here is the normal list available for your pleasure. You of course are free to specify any numeric value you want.

  • 0 - ET_NONE - unknown type
  • 1 - ET_REL - relocatable file
  • 2 - ET_EXEC - executable file
  • 3 - ET_DYN - shared object
  • 4 - ET_CORE - core file

ELF BITS

You can also narrow your search by specifying the ELF bitsize. Again, specify the numeric value or the symbolic define.

  • 32 - ELFCLASS32 - 32bit ELFs
  • 64 - ELFCLASS64 - 64bit ELFs

SECTION MATCHING

A ! prefix will only show ELF's that do not have the specified section.

NEEDED SONAME MATCHING

A ! prefix will only show ELF's that do not depend on the specified library.
