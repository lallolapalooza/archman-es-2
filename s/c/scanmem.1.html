scanmem(1) Manual de Comandos Generales scanmem(1)

NOMBRE

scanmem - localiza y modifica variables en un proceso en ejecución.

SINOPSIS

scanmem [opciones] [pid-del-programa-objetivo]

DESCRIPCIÓN

scanmem es una utilidad de depuración interactiva que se puede utilizar para aislar la dirección de una variable en un proceso en ejecución, escaneando sucesivamente el espacio de direcciones del proceso en busca de valores coincidentes.
Al informar a scanmem de cómo cambia el valor de la variable con el tiempo, puede determinar la ubicación real (o ubicaciones) de la variable eliminando sucesivamente las no coincidencias.
scanmem determina dónde buscar buscando mapeos con permiso de lectura/escritura, estos se denominan regiones. Los usuarios pueden eliminar regiones que crean que no están relacionadas con la variable objetivo (por ejemplo, ubicadas en una biblioteca compartida no relacionada con la variable en cuestión), esto mejorará la velocidad del escaneo, que inicialmente puede ser bastante lento en programas grandes.

Una vez encontrada una variable, scanmem puede monitorear la variable o cambiarla a un valor especificado por el usuario, ya sea una vez o continuamente durante un período de tiempo.

scanmem funciona de manera similar a los "pokefinders" que alguna vez se usaron para hacer trampa en videojuegos; esta función es una buena demostración de cómo usar scanmem y se utiliza en la documentación.

USO

scanmem debe invocarse con el ID del proceso del programa que desea depurar como argumento. Una vez iniciado, scanmem acepta comandos interactivos. Estos se describen a continuación; sin embargo, introducir help en el prompt de > le permitirá acceder a la documentación en línea de scanmem.

El pid-del-programa-objetivo se puede especificar en decimal, hexadecimal u octal utilizando la notación estándar del lenguaje C (prefijo 0x para hexadecimal, prefijo 0 para octal, cualquier otra cosa se asume que es decimal).

-p, --pid=pid
Establece el pid-del-programa-objetivo.
-c, --command=cmd1[;cmd2][;...]
Ejecuta los comandos dados (separados por ";") antes de iniciar el shell interactivo.
-v, --version
Imprime la versión y sale.
-h, --help
Imprime una breve descripción de las opciones de la línea de comandos y sale.
-d, --debug
Ejecuta en modo de depuración, se mostrará más información.
-e, --errexit
Sale en caso de error en los comandos iniciales, se ignora durante el modo interactivo.

COMANDOS

Mientras está en modo interactivo, scanmem imprime un número decimal seguido de >; el número es la cantidad actual de candidatos posibles para la variable objetivo que se conocen. La ausencia de dicho número indica que aún no se han eliminado posibles variables.
El tipo de datos de escaneo predeterminado es "int". Se puede cambiar con el comando option.

n
Donde n representa cualquier número en decimal, octal o hexadecimal, este comando le dice a scanmem que el valor actual de la variable objetivo es exactamente n. scanmem comenzará una búsqueda en todo el espacio de direcciones, o en las coincidencias conocidas existentes (si las hay), eliminando cualquier variable que no tenga este valor.
n..m
Esto es como el comando n, pero scanmem busca un rango de números entre n y m inclusive en su lugar.
>, <, +, -, =, !=
Los siguientes comandos son extremadamente útiles para localizar una variable cuyo valor exacto no podemos ver, pero podemos ver cómo cambia con el tiempo, por ejemplo, una barra de salud. Estos comandos generalmente no se pueden usar para el primer escaneo, pero hay algunas excepciones: > n, < n, = n y != n.
> [n]
Si se proporciona n, busca valores mayores que n. De lo contrario, busca todos los valores que han aumentado.
< [n]
Si se proporciona n, busca valores menores que n. De lo contrario, busca todos los valores que han disminuido.
+ [n]
Si se proporciona n, busca valores que han aumentado en n. De lo contrario, busca todos los valores que han aumentado (igual que >).
- [n]
Si se proporciona n, busca valores que han disminuido en n. De lo contrario, busca todos los valores que han disminuido (igual que <).
= [n]
Si se proporciona n, busca valores iguales a n (igual que n). De lo contrario, busca todos los valores que no han cambiado.
!= [n]
Si se proporciona n, busca valores diferentes de n. De lo contrario, busca todos los valores que han cambiado.
snapshot
Busca cualquier valor. Esto es útil cuando no se conoce un valor o rango inicial para escaneos posteriores con >, <, +, -, = y !=.
" texto
Busca el texto proporcionado en la memoria si el tipo de datos de escaneo está establecido en "string".
update
Escanea el proceso actual, obteniendo los valores actuales de todas las coincidencias. Estos valores se pueden ver con list, y también son los valores antiguos con los que scanmem compara al usar >, < o =. Este comando es equivalente a un comando de búsqueda con el que coinciden todos los resultados actuales.
list [max_a_imprimir]
Lista hasta max_a_imprimir (predeterminado: 10k) candidatos posibles conocidos actualmente, incluyendo su dirección, ID de región, desplazamiento de coincidencia, tipo de región, último valor conocido y posibles tipos de valor. El valor en la primera columna es el ID de coincidencia y se puede usar junto con el comando delete para eliminar coincidencias.

El desplazamiento de coincidencia se determina restando la dirección de carga del archivo ELF asociado o la región de la dirección. Puede usarse para eludir el Aleatorización del Diseño del Espacio de Direcciones (ASLR).

delete conjunto_de_ids_de_coincidencia
Elimina las coincidencias en el conjunto_de_ids_de_coincidencia. Los ids_de_coincidencia se pueden encontrar en la salida del comando list. Notación de conjunto: [!][..a](,b..c | d, ...)[e..].
Para eliminar todas las coincidencias conocidas, consulte el comando reset.
Para eliminar todas las coincidencias asociadas con una biblioteca en particular, consulte el comando dregion, que también elimina las coincidencias asociadas.
Tenga en cuenta que los ID de coincidencia pueden recalcularse después de que se eliminen o agreguen coincidencias.
watch id_de_coincidencia
Monitorea el valor del id_de_coincidencia e imprime su valor a medida que cambia. Cada cambio se imprime junto con una marca de tiempo; puede interrumpir este comando con ^C para dejar de monitorear.
set [conjunto_de_ids_de_coincidencia=]valor[/retraso] [...]
Establece el valor en las coincidencias especificadas en el conjunto_de_ids_de_coincidencia, o si solo se especifica valor, en todas las coincidencias conocidas. El valor se puede especificar en notación estándar del lenguaje C. Todas las coincidencias conocidas, junto con sus ID de coincidencia, se pueden mostrar usando el comando list. Se pueden especificar múltiples conjuntos_de_ids_de_coincidencia, terminados con un signo de igualdad. Notación de conjunto: [!][..a](,b..c | d, ...)[e..].
Para establecer un valor continuamente, agregue un prefijo al comando con / seguido del número de segundos a esperar entre cada establecimiento. Puede interrumpir el comando set con ^C para volver al prompt de scanmem. Esto se puede usar para mantener el valor de una variable que disminuye con el tiempo, por ejemplo, un temporizador que se decrementa cada segundo se puede establecer en 100 cada 10 segundos para evitar que alguna propiedad cambie.

iable(s) una vez encontrados por eliminación. Tenga en cuenta que algunas aplicaciones almacenarán valores en múltiples ubicaciones.

write tipo_valor dirección valor
Establece manualmente el valor de la variable en la dirección especificada.
Los nombres de tipo_valor están sujetos a cambios en diferentes versiones de scanmem, vea más información usando el comando `help write`.
dump dirección longitud [nombre_archivo]
Vuelca la región de memoria que comienza en dirección con longitud longitud en un formato legible por humanos.

Si se proporciona nombre_archivo, los datos se guardarán en el archivo, de lo contrario, los datos se mostrarán en stdout.

pid [nuevo-pid]
Muestra el ID del proceso del programa objetivo actual, o cambia el objetivo a nuevo-pid, lo que restablecerá las regiones y coincidencias existentes.
reset
Olvidar todas las regiones y coincidencias conocidas y comenzar de nuevo.
lregions
Lista todas las regiones conocidas, esto se puede usar en combinación con el comando dregion para eliminar regiones que el usuario cree que no están relacionadas con la variable en cuestión, reduciendo así el espacio de direcciones requerido para buscar. El valor en la primera columna es el id_región que debe pasarse al comando dregion. Además de la dirección de inicio, también se imprimen el tamaño y la ruta (si corresponde). Esto se puede usar para eliminar regiones ubicadas en bibliotecas compartidas que probablemente no sean relevantes para la variable requerida.

Para expertos: También se muestran el tipo de región y la dirección de carga. Los tipos son "exe" (ejecutable), "code" (biblioteca), "heap", "stack" o "misc" (todo lo demás). La dirección de carga es la ubicación de memoria donde se ha cargado un archivo ELF (exe/lib). Esto ayuda a convertir entre las direcciones en memoria y en el archivo ELF asociado. Si la región no pertenece a un archivo ELF, entonces es igual a la dirección de inicio.

dregion conjunto_id_región
Elimina las regiones en conjunto_id_región, junto con cualquier coincidencia de la lista de coincidencias. Notación de conjuntos: [!][..a](,b..c | d, ...) [e..].
Los id_región se pueden encontrar en la salida del comando lregions.
option nombre valor
Cambia opciones en tiempo de ejecución. Por ejemplo, se puede cambiar el tipo de datos de escaneo. Ver `help option` para todos los nombres/valores posibles.
shell comando_shell
Ejecuta comando_shell usando /bin/sh, luego regresa.
show info
Muestra información relacionada con info. Ver `help show` para más detalles.
version
Muestra la versión de scanmem en uso.
help
Muestra un breve resumen de los comandos disponibles.
exit
Desconéctate del programa objetivo y sal inmediatamente.

EJEMPLOS

Hacer trampa en nethack, en sistemas donde nethack no está instalado con SGID.

Por favor, introduce el valor actual, o "help" para otros comandos.

Se encontraron 16 coincidencias potenciales. Esto también se muestra en el prompt. Muchas de ellas no están relacionadas, ya que forman parte de la pila, pertenecen a bibliotecas o archivos mapeados en memoria diversos. Incluso el heap es poco probable para un juego de línea de comandos muy antiguo. Podríamos hacer que scanmem las elimine manualmente usando el comando delete, sin embargo, solo esperar hasta que cambie la cantidad de oro y decirle a scanmem el nuevo valor debería ser suficiente. Encuentro más oro y le digo a scanmem el nuevo valor, 83.

16> 83
..........info: actualmente tenemos 1 coincidencia.
info: coincidencia identificada, usa "set" para modificar el valor.
info: introduce "help" para otros comandos.
1> list
[ 0]       7b09e0,  1 +       3b09e0,   exe, 83, [I64 I32 I16 I8 ]

Solo uno de los 16 candidatos originales ahora tiene el valor 83, por lo que debe ser aquí donde se almacena la cantidad de oro. Intentaré establecerlo en 10,000 piezas.

1> set 10000
info: estableciendo *0x7b09e0 a 0x2710...
1>

El estado resultante de nethack:

Dlvl:1  $:10000 HP:15(15) Pw:2(2) AC:7  Exp:1

Conclusión: Hemos encontrado y modificado el valor del oro como I32 en la memoria estática del ejecutable en la dirección de memoria virtual 0x7b09e0. Esta dirección pertenece a la región con id 1.

Ahora es importante saber si se trata de un ejecutable independiente de la posición (PIE). Listamos las regiones para esto y verificamos la dirección de carga del ejecutable.

1> lregions
[ 0]       79f000,   69632 bytes,   exe,       400000, rw-, /usr/lib/nethack/nethack.tty
[ 1]       7b0000,  114688 bytes,   exe,       400000, rw-, sin asociar
[ 2]      24d2000,  135168 bytes,  heap,      24d2000, rw-, [heap]
[ 3] 7fcc04baa000,   16384 bytes,  misc, 7fcc04baa000, rw-, sin asociar
[ 4] 7fcc04de1000,    4096 bytes,  misc, 7fcc04de1000, rw-, sin asociar
[ 5] 7fcc051f7000,   16384 bytes,  misc, 7fcc051f7000, rw-, sin asociar
[ 6] 7fcc05227000,   12288 bytes,  misc, 7fcc05227000, rw-, sin asociar
[ 7] 7fcc0522c000,    4096 bytes,  misc, 7fcc0522c000, rw-, sin asociar
[ 8] 7ffc8c113000,  135168 bytes, stack, 7ffc8c113000, rw-, [stack]

Estamos en x86_64 y 0x400000 es la dirección de carga estática para ejecutables allí. Esto significa que esto no es un PIE y el oro se almacena siempre en 0x7b09e0. Esto facilita el uso de un entrenador de juegos como GameConqueror, que rellena el valor del oro periódicamente.

Con un PIE, tenemos que usar el desplazamiento de la coincidencia (0x3b09e0 aquí) en su lugar y un entrenador de juegos avanzado con soporte PIE tiene que determinar y sumar la dirección de carga actual para obtener la dirección de memoria actual del valor del oro de la ejecución actual del juego.

NOTAS

scanmem ha sido probado en varios programas grandes, incluyendo el shoot-em-up 3D quake3 linux. scanmem también se prueba en plataformas ARM y viene con soporte para Android desde la versión 0.16.

Obviamente, scanmem puede bloquear su programa si se usa incorrectamente.

Algunos programas almacenan valores en múltiples ubicaciones, por eso set cambiará todas las coincidencias conocidas.

Aleatorización del espacio de direcciones (ASLR) junto con ejecutables independientes de la posición (PIE), código independiente de la posición (PIC) o memoria dinámica en el heap provocan que las variables se carguen en diferentes direcciones de memoria en cada inicio del juego. Se requieren entrenadores de juegos avanzados como ugtrain para rellenar periódicamente las variables en tales regiones de memoria.

PROBLEMAS CONOCIDOS

scanmem generalmente requiere privilegios de root para ptrace(2) porque los módulos de seguridad controlan las capacidades de ptrace(). En x86 y x86_64, generalmente existe el módulo de seguridad Yama que proporciona el archivo /proc/sys/kernel/yama/ptrace_scope. Está disponible desde Linux 3.4. Si este archivo contiene "1", entonces solo los padres pueden usar ptrace() a sus hijos sin privilegios de root. Esto significa que scanmem tendría que ejecutar el juego. Esto no es posible ya que requeriría grandes cambios de diseño. Así que ejecutamos scanmem como root.

El primer escaneo puede ser muy lento en programas grandes, esto no es un problema para escaneos posteriores ya que enormes porciones del espacio de direcciones se eliminan generalmente. Esto podría mejorarse en el futuro, quizás asumiendo que todos los enteros están alineados por defecto. Se aceptan sugerencias.

El comando snapshot utiliza la memoria de manera ineficiente y probablemente no debería usarse en programas grandes.
