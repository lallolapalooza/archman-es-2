scsi_logging_level(8)

Paquete: sg3_utils

Licencias: GPL, custom:BSD

SCSI_LOGGING_LEVEL(8) SG3_UTILS SCSI_LOGGING_LEVEL(8)

NOMBRE

scsi_logging_level - accede a la información del nivel de registro SCSI de Linux

SINOPSIS

scsi_logging_level [--all=LEV] [--create] [--error=LEV] [--get] [--help] [--highlevel=LEV] [--hlcomplete=LEV] [--hlqueue=LEV] [--ioctl=LEV] [--llcomplete=LEV] [--llqueue=LEV] [--lowlevel=LEV] [--midlevel=LEV] [--mlcomplete=LEV] [--mlqueue=LEV] [--scan=LEV] [--set] [--timeout=LEV] [--version]

DESCRIPCIÓN

Este script de shell bash accede al nivel de registro del subsistema SCSI de Linux. Los valores actuales se pueden mostrar (por ejemplo, con --get) o modificar (por ejemplo, con --set). Normalmente se requerirán permisos de superusuario para establecer el nivel de registro.

Se requiere una de estas opciones: --create, --get o --set. Solo se puede proporcionar una de ellas.

OPCIONES

Los argumentos para las opciones largas son obligatorios también para las opciones cortas.

-a, --all=LEV
LEV se utiliza para todos los campos de SCSI_LOG.
-c, --create
Las opciones se analizan y se colocan en campos internos que se muestran, pero no se modifican los niveles de registro dentro del kernel de Linux.
-E, --error=LEV
LEV se coloca en el campo SCSI_LOG_ERROR.
-g, --get
Recupera los niveles de registro SCSI actuales del kernel de Linux y los muestra.
-h, --help
imprime el mensaje de uso y sale.
-H, --highlevel=LEV
LEV se coloca en los campos SCSI_LOG_HLQUEUE y SCSI_LOG_HLCOMPLETE.
--hlcomplete=LEV
LEV se coloca en el campo SCSI_LOG_HLCOMPLETE.
--hlqueue=LEV
LEV se coloca en el campo SCSI_LOG_HLQUEUE.
-I, --ioctl=LEV
LEV se coloca en el campo SCSI_LOG_IOCTL.
--llcomplete=LEV
LEV se coloca en el campo SCSI_LOG_LLCOMPLETE.
--llqueue=LEV
LEV se coloca en el campo SCSI_LOG_LLQUEUE.
-L, --lowlevel=LEV
LEV se coloca en los campos SCSI_LOG_LLQUEUE y SCSI_LOG_LLCOMPLETE.
-M, --midlevel=LEV
LEV se coloca en los campos SCSI_LOG_MLQUEUE y SCSI_LOG_MLCOMPLETE.
--mlcomplete=LEV
LEV se coloca en el campo SCSI_LOG_MLCOMPLETE.
--mlqueue=LEV
LEV se coloca en el campo SCSI_LOG_MLQUEUE.
-S, --scan=LEV
LEV se coloca en el campo SCSI_LOG_SCAN.
-s, --set
Utiliza los campos especificados en las opciones de este comando y intenta aplicarlos a los niveles de registro del subsistema SCSI de Linux. Normalmente se requerirán permisos de superusuario para hacer esto.
-T, --timeout=LEV
LEV se coloca en el campo SCSI_LOG_TIMEOUT.
-v, --version
Muestra la información de la versión y sale.

NOTAS

Las opciones --get y --set acceden al archivo pseudo /proc/sys/dev/scsi/logging_level.

ESTADO DE SALIDA

El estado de salida de este script es 0 cuando tiene éxito. Cualquier otro estado de salida indica que ha ocurrido un error.

EJEMPLOS

Lo siguiente establecerá SCSI_LOG_ERROR en el nivel 5 en el kernel de Linux. Requiere permisos de root:


scsi_logging_level -s -E 5

Para no interferir con otros controladores de nivel superior del subsistema SCSI (ULDs) que probablemente estarán activos al mismo tiempo, el controlador sg de Linux utiliza SCSI_LOG_TIMEOUT para fines de registro. Para ver depuración completa y rastreo del controlador sg, use:


scsi_logging_level -s -T 7

La salida del controlador sg causada por esto irá a los registros del sistema (por ejemplo, /var/log/syslog). Para reducir la cantidad de salida, use un número menor que 7. Usar 0 desactivará el rastreo y la depuración.

Para activar el registro máximo del subsistema SCSI, use:


scsi_logging_level -s -a 7

Probablemente sea mejor hacerlo en un sistema que no utilice un dispositivo de comandos SCSI para alojar el sistema de archivos raíz, o el sistema de archivos que contiene el registro del sistema. Tenga en cuenta que los discos SATA y el almacenamiento conectado por USB casi siempre utilizan el subsistema SCSI.
