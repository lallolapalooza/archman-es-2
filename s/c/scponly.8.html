scponly(8) Manual del Administrador del Sistema scponly(8)

NOMBRE

scponly

SINOPSIS

scponly

— shell limitada para transferencias seguras de archivos

DESCRIPCIÓN

scponly es un "shell" alternativo (de algún tipo) para administradores de sistemas que desean proporcionar a los usuarios remotos acceso para leer y escribir archivos locales sin otorgar privilegios de ejecución remota. Funcionalmente, se describe mejor como un envoltorio para la suite de aplicaciones confiables de ssh.

Un uso típico de scponly es la creación de una cuenta semi-pública no muy diferente del concepto de inicio de sesión anónimo para ftp. Esto permite a un administrador compartir archivos de la misma manera que lo haría una configuración ftp anónima, solo que empleando toda la protección que proporciona ssh. Esto es especialmente significativo si considera que las autenticaciones ftp atraviesan redes públicas en formato de texto plano.

En lugar de un solo usuario anónimo, scponly soporta la configuración de potencialmente muchos usuarios, cada uno de los cuales podría configurarse para proporcionar acceso a árboles de directorios distintos. Aparte de los detalles de instalación, cada uno de estos usuarios tendría su shell predeterminado en /etc/passwd configurado como "/usr/local/bin/scponly" (o donde sea que elija instalarlo). Esto significaría que los usuarios con este shell no podrían iniciar sesión interactivamente ni ejecutar comandos de forma remota. Sin embargo, pueden copiar archivos hacia adentro y hacia afuera usando scp, regidos por los permisos de archivo habituales de estilo Unix.

CARACTERÍSTICAS

  • Registro: scponly registra la hora, la dirección IP del cliente, el nombre de usuario y la solicitud real en syslog.
  • chroot: scponly puede hacer chroot al directorio principal del usuario (o a cualquier otro directorio para el que el usuario tenga permisos), lo que impide el acceso al resto del sistema de archivos.
  • Compatibilidad con sftp: Mi prueba de sftp contra un usuario de scponly funcionó muy bien. Esta es probablemente la forma más limpia y utilizable para que un usuario de scponly acceda a los archivos.
  • Comprobaciones de seguridad: no se permite el inicio de sesión de root (aunque root nunca debería configurarse para usar scponly como shell predeterminado).
  • Compatibilidad con WinSCP 2.0: scponly puede compilarse en modo de compatibilidad con WinSCP que permitirá un shell "semi-interactivo" que WinSCP puede usar.
  • Compatibilidad con gftp: scponly es compatible con gftp si configura "use ssh2 sftp subsys" en sus opciones de gftp.

scponly no hace nada para gestionar los permisos de lectura/escritura. Las aplicaciones ssh ya lo hacen bastante bien. Si usa scponly, tenga en cuenta que los permisos de archivo de estilo Unix de toda la vida todavía hacen el trabajo de proteger sus archivos.

NOTAS

  • Tan reciente como el 26 de junio de 2002, se descubrieron vulnerabilidades en OpenSSH. También existe una vulnerabilidad en el protocolo SSH1. Si va a usar scponly, tenga en cuenta que no es más seguro que la instalación ssh sobre la que se ejecuta.
  • Desde entonces he descubierto que la oferta comercial de ssh de ssh.com soporta tanto "usuarios dummy" como funcionalidades paralelas a scponly. No he podido encontrar ninguna nota sobre estas características, pero leí que existen. Me aseguraré de incluir más información más adelante. Parece que OpenSSH aún no soporta estas características. En este momento, no tengo planes de retirar scponly, aunque en última instancia, reconozco que scponly eventualmente debería ser solo una característica de cualquiera que sea el sshd que pueda ejecutar.

ARCHIVOS

La ubicación predeterminada para el propio shell.
/usr/local/sbin/scponlyc
La ubicación predeterminada para la versión chrooted de scponly
/etc/shells
Para ser un shell adecuado, debe incluirse aquí.
