NOMBRE

sctp - Protocolo SCTP.

SINOPSIS

#include <sys/socket.h>
#include <netinet/in.h>
#include <netinet/sctp.h>

sctp_socket = socket(PF_INET, SOCK_STREAM, IPPROTO_SCTP);
sctp_socket = socket(PF_INET, SOCK_SEQPACKET, IPPROTO_SCTP);

DESCRIPCIÓN

Esta es una implementación del protocolo SCTP tal como se define en RFC4960. Es un protocolo de transporte fiable orientado a mensajes con soporte directo para multi-homing que se ejecuta sobre ip(7), y soporta tanto versiones v4 como v6.

Al igual que TCP, SCTP proporciona entrega de datos fiable y orientada a conexión con control de congestión. A diferencia de TCP, SCTP también proporciona preservación de límites de mensajes, entrega de mensajes ordenada y desordenada, multi-streaming y multi-homing. La detección de corrupción de datos, pérdida de datos y duplicación de datos se logra mediante el uso de sumas de verificación y números de secuencia. Se aplica un mecanismo de retransmisión selectiva para corregir la pérdida o corrupción de datos.

Esta implementación soporta un mapeo del protocolo SCTP a la API de sockets definida en RFC6458 (extensiones de la API de sockets para SCTP). Se admiten dos estilos de interfaz.

Una interfaz de estilo uno a muchos con una relación de 1 a MUCHOS entre el socket y las asociaciones, donde la configuración de la asociación de salida es implícita. La sintaxis de una llamada a socket() de estilo uno a muchos es

sd = socket(PF_INET, SOCK_SEQPACKET, IPPROTO_SCTP);

Un servidor típico en este estilo utiliza las siguientes llamadas a socket en secuencia para preparar un punto final para atender solicitudes.


1. socket()
2. bind()
3. listen()
4. recvmsg()
5. sendmsg()
6. close()

Un cliente típico utiliza las siguientes llamadas en secuencia para establecer una asociación con un servidor para solicitar servicios.


1. socket()
2. sendmsg()
3. recvmsg()
4. close()

Una interfaz de estilo uno a uno con una relación de 1 a 1 entre el socket y la asociación, lo que permite portar aplicaciones TCP existentes a SCTP con muy poco esfuerzo. La sintaxis de una llamada a socket() de estilo uno a uno es

sd = socket(PF_INET, SOCK_STREAM, IPPROTO_SCTP);

Un servidor típico en estilo uno a uno utiliza la siguiente secuencia de llamadas al sistema para preparar un punto final SCTP para atender solicitudes:


1. socket()
2. bind()
3. listen()
4. accept()

La llamada accept() se bloquea hasta que se establece una nueva asociación. Devuelve un nuevo descriptor de socket. Luego, el servidor utiliza el nuevo descriptor de socket para comunicarse con el cliente, utilizando las llamadas recv() y send() para obtener solicitudes y enviar respuestas. Luego llama a


5. close()

para terminar la asociación. Un cliente típico utiliza la siguiente secuencia de llamadas al sistema para establecer una asociación con un servidor para solicitar servicios:


1. socket()
2. connect()

Después de regresar de connect(), el cliente utiliza las llamadas send() y recv() para enviar solicitudes y recibir respuestas del servidor. El cliente llama a


3. close()

para terminar esta asociación cuando haya terminado.

FORMATOS DE DIRECCIÓN

SCTP se basa en IP (consulte ip(7)). Los formatos de dirección definidos por ip(7) se aplican a SCTP. SCTP solo soporta comunicación punto a punto; no se admiten la difusión y la multidifusión.

SYSCTLS

Estas variables se pueden acceder a través de los archivos ** /proc/sys/net/sctp/* ** o con la interfaz sysctl(2). Además, la mayoría de los sysctls de IP también se aplican a SCTP. Consulte ip(7).

Por favor, consulte la documentación del kernel para esto, en Documentation/networking/ip-sysctl.rst.

ESTADÍSTICAS

Estas variables se pueden acceder a través de los archivos ** /proc/net/sctp/* **.

assocs
Muestra la siguiente información sobre las asociaciones activas. Puntero de asociación, puntero de socket, estilo de socket, estado del socket, estado de la asociación, cubo hash, ID de asociación, bytes en cola de transmisión, bytes en cola de recepción, ID de usuario, inodo, puerto local, puerto remoto, direcciones locales, direcciones remotas, intervalo de latido, flujos de entrada, flujos de salida, retransmisiones máximas, reintentos de inicialización, reintentos de cierre, fragmentos retransmitidos, bytes comprometidos en la cola de transmisión del socket, bytes en la cola de transmisión del socket, y bytes del búfer de envío y recepción del socket.
eps
Muestra la siguiente información sobre los puntos finales activos. Puntero de punto final, puntero de socket, estilo de socket, estado del socket, cubo hash, puerto local, ID de usuario, inodo y direcciones locales.
snmp
Muestra las siguientes estadísticas relacionadas con los estados, paquetes y fragmentos de SCTP.
SctpCurrEstab
El número de asociaciones para las cuales el estado actual es ESTABLECIDA, SHUTDOWN-RECIBIDA o SHUTDOWN-PENDIENTE.
SctpActiveEstabs
El número de veces que las asociaciones han realizado una transición directa al estado ESTABLECIDA desde el estado ECHO-DE-COOKIE. La capa superior inició el intento de asociación.
SctpPassiveEstabs
El número de veces que las asociaciones han realizado una transición directa al estado ESTABLECIDA desde el estado CERRADO. El punto final remoto inició el intento de asociación.
SctpAborteds
El número de veces que las asociaciones han realizado una transición directa al estado CERRADO desde cualquier estado utilizando la primitiva 'ABORT'. Terminación abrupta de la asociación.
SctpShutdowns
El número de veces que las asociaciones han realizado una transición directa al estado CERRADO desde el estado SHUTDOWN-ENVIADO o el estado SHUTDOWN-ACK-ENVIADO. Terminación elegante de la asociación.
SctpOutOfBlues
El número de paquetes "fuera de lo azul" recibidos por el host. Un paquete "fuera de lo azul" es un paquete SCTP formado correctamente, incluida la suma de verificación correcta, pero para el cual el receptor no pudo identificar una asociación apropiada.
SctpChecksumErrors
El número de paquetes SCTP recibidos con una suma de verificación inválida.
SctpOutCtrlChunks
El número de fragmentos de control SCTP enviados (no se incluyen las retransmisiones). Los fragmentos de control son aquellos fragmentos diferentes de DATA.
SctpOutOrderChunks
El número de fragmentos de datos ordenados SCTP enviados (no se incluyen las retransmisiones).
SctpOutUnorderChunks
El número de fragmentos desordenados SCTP (fragmentos de datos en los que el bit U está establecido en 1) enviados (no se incluyen las retransmisiones).
SctpInCtrlChunks
El número de fragmentos de control SCTP recibidos (no se incluyen fragmentos duplicados).
SctpInOrderChunks
El número de fragmentos de datos ordenados SCTP recibidos (no se incluyen fragmentos duplicados).
SctpInUnorderChunks
El número de fragmentos desordenados SCTP (fragmentos de datos en los que el bit U está establecido en 1) recibidos (no se incluyen fragmentos duplicados).
SctpFragUsrMsgs
El número de mensajes de usuario que deben fragmentarse debido a la MTU.
SctpReasmUsrMsgs
El número de mensajes de usuario reensamblados, después de la conversión i

SCTP_RECONFIG_SUPPORTED
Enable the Stream Reconfiguration(RECONF) for the future associations. For different type of requests enabling, see SCTP_ENABLE_STREAM_RESET option.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, assoc_id is SCTP_FUTURE_ASSOC.

Default: sysctl_net.sctp.reconf_enable. RFC: RFC6525.

SCTP_ENABLE_STREAM_RESET
This option allows a user to control whether the kernel processes or denies incoming requests in RECONF chunks.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, assoc_id is a specified assoc_id or SCTP_{FUTURE|CURRENT|ALL}_ASSOC. assoc_value can be SCTP_ENABLE_{RESET_STREAM_REQ|RESET_ASSOC_REQ|CHANGE_ASSOC_REQ}.

Default: 0. Require: SCTP_RECONFIG_SUPPORTED.

SCTP_RESET_STREAMS
This option allows the user to request the reset of incoming and/or outgoing streams.

The parameter type is struct sctp_reset_streams, for writing only. srs_assoc_id is a specified assoc_id.

Require: SCTP_ENABLE_STREAM_RESET.

SCTP_RESET_ASSOC
This option allows a user to request the reset of the SSN/TSN.

The parameter type is sctp_assoc_t, for writing only. It is a specified assoc_id.

Require: SCTP_ENABLE_STREAM_RESET.

SCTP_ADD_STREAMS
This option allows a user to request the addition of a number of incoming and/or outgoing streams.

The parameter type is struct sctp_add_streams, for writing only. sas_assoc_id is a specified assoc_id.

Require: SCTP_ENABLE_STREAM_RESET.

SCTP_STREAM_SCHEDULER
This option is used to select a stream scheduler for data sending.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, assoc_id is a specified assoc_id or SCTP_{FUTURE|CURRENT|ALL}_ASSOC. assoc_value can be SCTP_SS_{FCFS|PRIO|RR|FC|WFQ}.

Default: SCTP_SS_FCFS. RFC: RFC8260.

SCTP_STREAM_SCHEDULER_VALUE
Some stream schedulers require additional information to be set for individual streams.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id. For writing, assoc_id is a specified assoc_id or SCTP_CURRENT_ASSOC.

Require: SCTP_STREAM_SCHEDULER.

SCTP_INTERLEAVING_SUPPORTED
This socket option allows the enabling or disabling of the negotiation of user message interleaving support for future associations.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, assoc_id is SCTP_FUTURE_ASSOC.

Default: sysctl_net.sctp.intl_enable. Require: SCTP_FRAGMENT_INTERLEAVE. RFC: RFC8260.

SCTP_ASCONF_SUPPORTED
Enable the Dynamic Address Reconfiguration(ASCONF) for the future associations.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, assoc_id is SCTP_FUTURE_ASSOC.

Default: sysctl_net.sctp.addip_enable. RFC: RFC5061.

SCTP_AUTO_ASCONF
This option will enable or disable the use of the automatic generation of ASCONF chunks to add and delete addresses to an existing association. Note that this option has two caveats, namely a) it only affects sockets that are bound to all addresses available to the SCTP stack, and b) the system administrator may have an overriding control that turns the ASCONF feature off no matter what setting the socket option may have.

The parameter type is int boolean, for reading and writing.

Default: sysctl_net.sctp.default_auto_asconf.

SCTP_AUTH_SUPPORTED
Enable AUTH for the future associations.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, ssoc_id is SCTP_FUTURE_ASSOC.

Default: sysctl_net.sctp.auth_enable. RFC: RFC4895.

SCTP_ECN_SUPPORTED
Enable ECN for the future associations.

The parameter type is struct sctp_assoc_value. For reading, assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC. For writing, assoc_id is SCTP_FUTURE_ASSOC.

Default: sysctl_net.sctp.ecn_enable.

SCTP_REMOTE_UDP_ENCAPS_PORT
This option is used to set the encapsulation port(a remote listening or dest port) for SCTP over UDP, which allows SCTP traffic to pass through legacy NATs that do not provide native SCTP support.

The parameter type is struct sctp_udpencaps, for reading and writing. sue_address is a specified transport address or 0, sue_assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC.

Default: sysctl_net.sctp.encap_port. RFC: RFC6951.

SCTP_PLPMTUD_PROBE_INTERVAL
This option is used to configure the PROBE_INTERVAL for the Packetization Layer Path MTU Discovery(PLPMTUD). It can be set to a value >= 5000 or 0(disabled).

The parameter type is struct sctp_probeinterval, for reading and writing. spi_address is a specified transport address or 0, spi_assoc_id is a specified assoc_id or SCTP_FUTURE_ASSOC.

Default: 0(disabled). RFC: RFC8899.
