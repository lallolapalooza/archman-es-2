sched_setaffinity(2) Manual de llamadas al sistema sched_setaffinity(2)

NOMBRE

sched_setaffinity, sched_getaffinity - establecer y obtener la máscara de afinidad de CPU de un hilo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE             /* Ver feature_test_macros(7) */
#include <sched.h>
int sched_setaffinity(pid_t pid, size_t cpusetsize,
                      const cpu_set_t *mask);
int sched_getaffinity(pid_t pid, size_t cpusetsize,
                      cpu_set_t *mask);

DESCRIPCIÓN

La máscara de afinidad de CPU de un hilo determina el conjunto de CPUs en las que es elegible para ejecutarse. En un sistema multiprocesador, establecer la máscara de afinidad de CPU puede usarse para obtener beneficios de rendimiento. Por ejemplo, al dedicar una CPU a un hilo particular (es decir, al establecer la máscara de afinidad de ese hilo para especificar una sola CPU, y al establecer la máscara de afinidad de todos los demás hilos para excluir esa CPU), es posible garantizar la máxima velocidad de ejecución para ese hilo. Restringir un hilo para que se ejecute en una sola CPU también evita el costo de rendimiento causado por la invalidación de caché que ocurre cuando un hilo deja de ejecutarse en una CPU y luego reanuda la ejecución en una CPU diferente.

Una máscara de afinidad de CPU se representa mediante la estructura cpu_set_t, un "conjunto de CPU", apuntado por mask. Un conjunto de macros para manipular conjuntos de CPU se describe en CPU_SET(3).

sched_setaffinity() establece la máscara de afinidad de CPU del hilo cuya ID es pid al valor especificado por mask. Si pid es cero, entonces se usa el hilo que llama.

El argumento cpusetsize es la longitud (en bytes) de los datos apuntados por mask. Normalmente, este argumento se especificaría como sizeof(cpu_set_t).

Si el hilo especificado por pid no se está ejecutando actualmente en una de las CPUs especificadas en mask, entonces ese hilo se migra a una de las CPUs especificadas en mask.

sched_getaffinity() escribe la máscara de afinidad del hilo cuya ID es pid en la estructura cpu_set_t apuntada por mask. El argumento cpusetsize especifica el tamaño (en bytes) de mask. Si pid es cero, entonces se devuelve la máscara del hilo que llama.

VALOR DE RETORNO

En caso de éxito, sched_setaffinity() y sched_getaffinity() devuelven 0 (pero ver "diferencias entre biblioteca C/kernel" a continuación, que señala que sched_getaffinity() subyacente difiere en su valor de retorno). En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EFAULT
Una dirección de memoria proporcionada era inválida.
EINVAL
La máscara de bits de afinidad mask contiene procesadores que no están actualmente físicamente en el sistema y permitidos para el hilo de acuerdo con cualquier restricción que puedan imponer los cgroups de cpuset o el mecanismo "cpuset" descrito en cpuset(7).
EINVAL
(sched_getaffinity() y, antes de Linux 2.6.9, sched_setaffinity()) cpusetsize es menor que el tamaño de la máscara de afinidad utilizada por el kernel.
EPERM
(sched_setaffinity()) El hilo que llama no tiene los privilegios apropiados. El llamador necesita un ID de usuario efectivo igual al ID de usuario real o al ID de usuario efectivo del hilo identificado por pid, o debe poseer la capacidad CAP_SYS_NICE en el espacio de nombres de usuario del hilo pid.
ESRCH
No se pudo encontrar el hilo cuya ID es pid.

ESTÁNDARES

Linux.

HISTORIA

Linux 2.5.8, glibc 2.3.

Inicialmente, las interfaces de glibc incluían un argumento cpusetsize, tipado como unsigned int. En glibc 2.3.3, se eliminó el argumento cpusetsize, pero luego se restauró en glibc 2.3.4, con el tipo size_t.

NOTAS

Después de una llamada a sched_setaffinity(), el conjunto de CPUs en las que realmente se ejecutará el hilo es la intersección del conjunto especificado en el argumento mask y el conjunto de CPUs realmente presentes en el sistema. El sistema puede restringir aún más el conjunto de CPUs en las que se ejecuta el hilo si se está utilizando el mecanismo "cpuset" descrito en cpuset(7). Estas restricciones sobre el conjunto real de CPUs en las que se ejecutará el hilo son impuestas silenciosamente por el kernel.

Existen varias formas de determinar el número de CPUs disponibles en el sistema, entre ellas: inspeccionar el contenido de /proc/cpuinfo; utilizar sysconf(3) para obtener los valores de los parámetros _SC_NPROCESSORS_CONF y _SC_NPROCESSORS_ONLN; e inspeccionar la lista de directorios de CPU bajo /sys/devices/system/cpu/.

sched(7) tiene una descripción del esquema de planificación de Linux.

La máscara de afinidad es un atributo por hilo que se puede ajustar independientemente para cada uno de los hilos en un grupo de hilos. El valor devuelto de una llamada a gettid(2) se puede pasar en el argumento pid. Especificar pid como 0 establecerá el atributo para el hilo que llama, y pasar el valor devuelto de una llamada a getpid(2) establecerá el atributo para el hilo principal del grupo de hilos. (Si está utilizando la API de hilos POSIX, use pthread_setaffinity_np(3) en lugar de sched_setaffinity().)

La opción de arranque isolcpus se puede utilizar para aislar una o más CPUs al arrancar, de modo que ningún proceso se planifique en esas CPUs. Después de usar esta opción de arranque, la única forma de planificar procesos en las CPUs aisladas es a través de sched_setaffinity() o el mecanismo de cpuset(7). Para más información, ver el archivo fuente del kernel Documentation/admin-guide/kernel-parameters.txt. Como se indica en ese archivo, isolcpus es el mecanismo preferido para aislar CPUs (en comparación con la alternativa de establecer manualmente la afinidad de CPU de todos los procesos en el sistema).

Un hijo creado a través de fork(2) hereda la máscara de afinidad de CPU de su padre. La máscara de afinidad se conserva a través de un execve(2).

Diferencias biblioteca C/kernel

Esta página del manual describe la interfaz de glibc para las llamadas de afinidad de CPU. La interfaz de llamada al sistema real es ligeramente diferente, con mask tipado como unsigned long *, lo que refleja el hecho de que la implementación subyacente de los conjuntos de CPU es una simple máscara de bits.

En caso de éxito, la llamada al sistema bruta sched_getaffinity() devuelve el número de bytes copiados en el buffer mask; este será el mínimo entre cpusetsize y el tamaño (en bytes) del tipo de datos cpumask_t que se utiliza internamente en el kernel para representar la máscara de bits del conjunto de CPU.

Manejo de sistemas con máscaras de afinidad de CPU grandes

Las llamadas al sistema subyacentes (que representan las máscaras de CPU como máscaras de bits de tipo unsigned long *) no imponen ninguna restricción en el tamaño de la máscara de CPU. Sin embargo, el tipo de datos cpu_set_t utilizado por glibc tiene un tamaño fijo de 128 bytes, lo que significa que el número de CPU máximo que se puede representar es 1023. Si la máscara de afinidad de CPU del kernel es mayor que 1024, entonces las llamadas de la forma:


sched_getaffinity(pid, sizeof(cpu_set_t), &mask);

sched_getaffinity(2) — Arch Linux man pages

NAME

sched_getaffinity, sched_setaffinity - get and set CPU affinity of a process

LIBRARY

Linux Thread Library (since Linux 2.6.0)

SYNOPSIS

#include <sched.h>
int sched_getaffinity(pid_t pid, size_t cpusetsize, cpu_set_t *mask);
int sched_setaffinity(pid_t pid, size_t cpusetsize, const cpu_set_t *mask);

DESCRIPTION

The CPU affinity of a process (or thread) is the set of CPUs on which it is allowed to run. By default, a process can run on any available CPU.

The Linux-specific functions sched_getaffinity() and sched_setaffinity() are used to get and set the CPU affinity mask of a process specified by pid. The affinity mask is represented by a cpu_set_t structure (referred to as a CPU set) which is a bitmask of CPUs. The mask argument points to such a structure. The cpusetsize argument specifies the size in bytes of the buffer pointed to by mask.

For the sched_getaffinity() and sched_setaffinity() system calls, the pid argument specifies the ID of the process whose affinity is to be retrieved or set. If pid is 0, then the calling thread is used.

The CPU set structure cpu_set_t is defined in <sched.h>. Its actual size depends on the system's CPU topology. The macros defined in <sched.h> (and also defined when using <numa.h>) can be used to manipulate CPU sets:

  • CPU_ZERO(setp) initializes the CPU set setp to the empty set.
  • CPU_SET(cpu, setp) adds the CPU numbered cpu to the CPU set setp.
  • CPU_CLR(cpu, setp) removes the CPU numbered cpu from the CPU set setp.
  • CPU_ISSET(cpu, setp) returns true (a non-zero value) if the CPU numbered cpu is present in the CPU set setp, and false (zero) otherwise.
  • CPU_COUNT(setp) returns the number of CPUs in the CPU set setp.
  • CPU_WEIGHT(setp) returns the number of set bits in the CPU set setp.

The CPU numbers are 0-based. The maximum CPU number that can be represented in a cpu_set_t depends on the system. You can determine the number of CPUs available on the system using get_nprocs(3) or sched_get_affinity(3) (by checking the size of the mask it returns).

The value of cpusetsize should be the size of the cpu_set_t structure. This can be determined dynamically using sizeof(cpu_set_t).

sched_setaffinity() sets the CPU affinity mask of the thread specified by pid to the CPU set specified by mask. If mask contains bits set for CPUs that are not available on the system, sched_setaffinity() will fail with the error EINVAL.

sched_getaffinity() retrieves the CPU affinity mask of the thread specified by pid and stores it in the buffer pointed to by mask. The size of this buffer is specified by cpusetsize.

RETURN VALUE

On success, both sched_getaffinity() and sched_setaffinity() return 0.

On error, they return -1, and errno is set appropriately.

ERRORS

  • EFAULT: The address specified by mask is not in a writable part of the user address space.
  • EINVAL: cpusetsize is invalid, or the mask argument contains bits set for CPUs that are not available on the system.
  • EPERM: The calling thread does not have permission to set the affinity of the specified thread. This occurs if the effective user ID of the calling thread is not the same as the real or effective user ID of the thread specified by pid, and the calling thread is not privileged (on older kernels, CAP_SYS_NICE was sufficient; on newer kernels, CAP_SYS_ADMIN is required).
  • ESRCH: No thread could be found with the specified pid.

STANDARDS

These functions are Linux-specific. They are described in POSIX.1-2001 as extensions, but are not mandated by POSIX.1-2008.

HISTORY

These functions first appeared in Linux kernel 2.5.8.

NOTES

Setting the CPU affinity of a thread does not affect the CPU affinity of any other threads in the same process. Only the affinity of the thread specified by pid is modified.

A process can only set the affinity of threads that belong to it. Setting the affinity of another process requires appropriate privileges (see capabilities(7)).

It is important to correctly handle the cpusetsize argument. If it is smaller than the actual size of the affinity mask used by the kernel, sched_setaffinity() might not be able to set the affinity to the desired CPUs, and sched_getaffinity() might not be able to return the full affinity mask. Specifically, the kernel affinity mask can be larger than the size of the cpu_set_t structure passed to the system call. This can happen if cpusetsize is smaller than the size of the affinity mask specified in cpusetsize is smaller than the size of the affinity mask used by the kernel. (Depending on the system CPU topology, the kernel affinity mask can be substantially larger than the number of active CPUs in the system.)

When working on systems with large kernel CPU affinity masks, one must dynamically allocate the mask argument (see CPU_ALLOC(3)). Currently, the only way to do this is by probing for the size of the required mask using sched_getaffinity() calls with increasing mask sizes (until the call does not fail with the error EINVAL).

Be aware that CPU_ALLOC(3) may allocate a slightly larger CPU set than requested (because CPU sets are implemented as bit masks allocated in units of sizeof(long)). Consequently, sched_getaffinity() can set bits beyond the requested allocation size, because the kernel sees a few additional bits. Therefore, the caller should iterate over the bits in the returned set, counting those which are set, and stop upon reaching the value returned by CPU_COUNT(3) (rather than iterating over the number of bits requested to be allocated).

EXAMPLES

The program below creates a child process. The parent and child then each assign themselves to a specified CPU and execute identical loops that consume some CPU time. Before terminating, the parent waits for the child to complete. The program takes three command-line arguments: the CPU number for the parent, the CPU number for the child, and the number of loop iterations that both processes should perform.

As the sample runs below demonstrate, the amount of real and CPU time consumed when running the program will depend on intra-core caching effects and whether the processes are using the same CPU.

We first employ lscpu(1) to determine that this (x86) system has two cores, each with two CPUs:


$ lscpu | egrep -i 'core.*:|socket';
Thread(s) per core:    2
Core(s) per socket:    2
Socket(s):             1

We then time the operation of the example program for three cases: both processes running on the same CPU; both processes running on different CPUs on the same core; and both processes running on different CPUs on different cores.


$ time -p ./a.out 0 0 100000000;
real 14.75
user 3.02
sys 11.73
$ time -p ./a.out 0 1 100000000;
real 11.52
user 3.98
sys 19.06
$ time -p ./a.out 0 3 100000000;
real 7.89
user 3.29
sys 12.07

Program source

#define _GNU_SOURCE
#include <err.h>
#include <sched.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int           parentCPU, childCPU;
    cpu_set_t     set;
    unsigned int  nloops;
    if (argc != 4) {
        fprintf(stderr, "Usage: %s parent-cpu child-cpu num-loops\n",
                argv[0]);
        exit(EXIT_FAILURE);
    }
    parentCPU = atoi(argv[1]);
    childCPU = atoi(argv[2]);
    nloops = atoi(argv[3]);
    CPU_ZERO(&set);
    switch (fork()) {
    case -1:            /* Error */
        err(EXIT_FAILURE, "fork");
    case 0:             /* Child */
        CPU_SET(childCPU, &set);
        if (sched_setaffinity(0, sizeof(set), &set) == -1)
            err(EXIT_FAILURE, "sched_setaffinity");
        for (unsigned int j = 0; j < nloops; j++)
            getppid();
        exit(EXIT_SUCCESS);
    default:            /* Parent */
        CPU_SET(parentCPU, &set);
        if (sched_setaffinity(0, sizeof(set), &set) == -1)
            err(EXIT_FAILURE, "sched_setaffinity");
        for (unsigned int j = 0; j < nloops; j++)
            getppid();
        wait(NULL);     /* Wait for child to terminate */
        exit(EXIT_SUCCESS);
    }
}
