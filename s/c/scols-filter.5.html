SCOLS-FILTER(5) Formatos y convenciones de archivos SCOLS-FILTER(5)

NOMBRE

scols-filter - sintaxis para expresiones de filtro de libsmartcols

SINTAXIS

expr: param
      | ( expr )
      | expr && expr | expr AND expr
      | expr || expr | expr OR expr
      | !expr        | NOT expr
      | expr == expr | expr EQ expr
      | expr != expr | expr NE expr
      | expr >= expr | expr GE expr
      | expr <= expr | expr LE expr
      | expr >  expr | expr GT expr
      | expr <  expr | expr LT expr
      | expr =~ string
      | expr !~ string
param: integer
      | float
      | string
      | boolean
      | holder
integer: [0-9]*
      | [0-9]*[KMGTPEZY]
      | [0-9]*[KMGTPEZY]iB
float: integer.integer
boolean: "true" | "false" | "TRUE" | "FALSE"
string: "[^\n\"]*" | '[^\n\']*'
holder: [a-zA-Z][a-zA-Z_.%:/\-0-9]*

DESCRIPCIÓN

La expresión de filtro puede ser utilizada por aplicaciones enlazadas con libsmartcols para filtrar datos de salida. La aplicación puede usar el filtro antes de recopilar todos los datos para la salida para reducir recursos y mejorar el rendimiento. Esto hace que el filtro scols sea más efectivo que grep(1) en la salida completa. Por ejemplo:

 lsblk --output NAME,LABEL,FSTYPE --filter 'NAME=="sda1"'

ayuda a lsblk(1) a no leer las ETIQUETAS de todos los dispositivos de bloque de udevd o libblkid, sino a leerlas solo para el dispositivo sda1.

El filtro también puede usarse para columnas que no se utilizan en la salida.

NOTAS DE SINTAXIS

Una expresión consta de marcadores (holders), parámetros (params) y operadores.

El tipo de holder actualmente soportado es solo el nombre de la columna. El nombre debe usarse sin comillas. Antes de la evaluación, la aplicación mapea los nombres de las columnas en la expresión dada a las columnas de la tabla de salida y asigna el tipo de dato de la columna al marcador. El tipo por defecto es "string".

El param es para representar un valor directamente. Los tipos de datos actualmente soportados son entero, flotante, cadena (string) y booleano.

Un operador funciona con uno o dos operandos. Un operador tiene una expectativa sobre el(los) tipo(s) de dato de sus operandos. Dar un tipo de dato inesperado a un operador causa un error de sintaxis. La biblioteca puede realizar conversiones entre tipos de datos, siendo preferido siempre el tipo especificado por param y, en caso de una expresión con números y flotantes, el preferido es el flotante.

Los operadores que toman dos operandos son and, or, eq, ne, le, lt, ge, gt, =~, !~. Los operadores con nombres alfabéticos tienen alias al estilo del lenguaje C: &&, ||, ==, !=, <, ⇐, >=, y >.

! es el único operador que toma un operando. Si no se especifica ningún operador, la expresión es verdadera si el parámetro o el marcador no están vacíos. Por ejemplo, --filter NAME devolverá líneas donde la columna NAME no esté vacía.

=~ y !~ son para coincidencia de expresiones regulares; si una cadena en el lado derecho coincide (o no coincide para !~) con una expresión regular en el lado izquierdo, el resultado es verdadero. El operando del lado derecho debe ser un literal de cadena.

La precedencia entre operadores es or, and, y eq, ne, le, gt, ge, =~, !~, not.

LIMITACIONES

Respecto a los valores de tipo float e integer, el motor de filtro solo admite números no negativos. El integer es un número sin signo de 64 bits, y el float es un double largo. El integer puede ir seguido de los sufijos multiplicadores KiB, GiB, TiB, PiB, EiB, ZiB y YiB (el "iB" es opcional, por ejemplo, "K" tiene el mismo significado que "KiB").
