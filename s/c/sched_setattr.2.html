sched_setattr(2) Manual de llamadas al sistema sched_setattr(2)

NOMBRE

sched_setattr, sched_getattr - establecer y obtener la política y los atributos de planificación

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sched.h> /* Definición de las constantes SCHED_* */
#include <sys/syscall.h> /* Definición de las constantes SYS_* */
#include <unistd.h>
int syscall(SYS_sched_setattr, pid_t pid, struct sched_attr *attr,
            unsigned int flags);
int syscall(SYS_sched_getattr, pid_t pid, struct sched_attr *attr,
            unsigned int size, unsigned int flags);

Nota: glibc no proporciona envoltorios para estas llamadas al sistema, lo que hace necesario el uso de syscall(2).

DESCRIPCIÓN

sched_setattr()

La llamada al sistema sched_setattr() establece la política de planificación y los atributos asociados para el hilo cuyo ID se especifica en pid. Si pid es igual a cero, se establecerán la política de planificación y los atributos del hilo que realiza la llamada.

Actualmente, Linux soporta las siguientes políticas de planificación "normales" (es decir, no en tiempo real) como valores que pueden especificarse en policy:

SCHED_OTHER
la política estándar de time-sharing round-robin;
SCHED_BATCH
para la ejecución de procesos de estilo "batch"; y
SCHED_IDLE
para ejecutar trabajos en segundo plano de prioridad *muy* baja.

También se soportan varias políticas de "tiempo real", para aplicaciones especiales críticas en el tiempo que necesitan un control preciso sobre la forma en que se seleccionan los hilos ejecutables para su ejecución. Para las reglas que rigen cuándo un proceso puede utilizar estas políticas, consulte sched(7). Las políticas de tiempo real que pueden especificarse en policy son:

SCHED_FIFO
una política first-in, first-out; y
SCHED_RR
una política round-robin.

Linux también proporciona la siguiente política:

SCHED_DEADLINE
una política de planificación por plazos; consulte sched(7) para más detalles.

El argumento attr es un puntero a una estructura que define la nueva política de planificación y los atributos para el hilo especificado. Esta estructura tiene la siguiente forma:


struct sched_attr {
    u32 size;              /* Tamaño de esta estructura */
    u32 sched_policy;      /* Política (SCHED_*) */
    u64 sched_flags;       /* Banderas */
    s32 sched_nice;        /* Valor nice (SCHED_OTHER,
                              SCHED_BATCH) */
    u32 sched_priority;    /* Prioridad estática (SCHED_FIFO,
                              SCHED_RR) */
    /* Para SCHED_DEADLINE */
    u64 sched_runtime;
    u64 sched_deadline;
    u64 sched_period;
    /* Pistas de utilización */
    u32 sched_util_min;
    u32 sched_util_max;
};

Los campos de la estructura sched_attr son los siguientes:

size
Este campo debe establecerse al tamaño de la estructura en bytes, como en sizeof(struct sched_attr). Si la estructura proporcionada es más pequeña que la estructura del kernel, se asume que cualquier campo adicional es '0'. Si la estructura proporcionada es más grande que la estructura del kernel, el kernel verifica que todos los campos adicionales sean 0; si no lo son, sched_setattr() falla con el error E2BIG y actualiza size para contener el tamaño de la estructura del kernel.
El comportamiento anterior cuando el tamaño de la estructura sched_attr del espacio de usuario no coincide con el tamaño de la estructura del kernel permite la extensibilidad futura de la interfaz. Las aplicaciones mal formadas que pasan estructuras sobredimensionadas no fallarán en el futuro si se aumenta el tamaño de la estructura sched_attr del kernel. En el futuro, también podría permitir a las aplicaciones que conocen una estructura sched_attr más grande del espacio de usuario determinar si se están ejecutando en un kernel más antiguo que no soporta la estructura más grande.
sched_policy
Este campo especifica la política de planificación, como uno de los valores SCHED_* mencionados anteriormente.
sched_flags
Este campo contiene cero o más de las siguientes banderas que se combinan mediante OR para controlar el comportamiento de la planificación:
SCHED_FLAG_RESET_ON_FORK
Los hijos creados por fork(2) no heredan políticas de planificación privilegiadas. Consulte sched(7) para más detalles.
SCHED_FLAG_RECLAIM (desde Linux 4.13)
Esta bandera permite a un hilo SCHED_DEADLINE recuperar el ancho de banda no utilizado por otros hilos en tiempo real.
SCHED_FLAG_DL_OVERRUN (desde Linux 4.16)
Esta bandera permite que una aplicación sea informada sobre excedentes de tiempo de ejecución en hilos SCHED_DEADLINE. Dichos excedentes pueden ser causados por (por ejemplo) una contabilidad de tiempo de ejecución imprecisa o una asignación incorrecta de parámetros. La notificación toma la forma de una señal SIGXCPU que se genera en cada excedente.
Esta señal SIGXCPU está dirigida al proceso (consulte signal(7)) en lugar de al hilo. Esto es probablemente un error. Por un lado, sched_setattr() se utiliza para establecer un atributo por hilo. Por otro lado, si la señal dirigida al proceso se entrega a un hilo del proceso distinto de aquel que tuvo un excedente de tiempo de ejecución, la aplicación no tiene forma de saber qué hilo excedió.
SCHED_FLAG_UTIL_CLAMP_MIN
SCHED_FLAG_UTIL_CLAMP_MAX (ambos desde Linux 5.3)
Estas banderas indican que los campos sched_util_min o sched_util_max, respectivamente, están presentes, representando la utilización mínima y máxima esperada del hilo.
Los atributos de utilización proporcionan al planificador los límites dentro de los cuales debe planificar el hilo, lo que podría informar sus decisiones sobre la colocación de tareas y la selección de frecuencia.
sched_nice
Este campo especifica el valor nice a establecer al especificar sched_policy como SCHED_OTHER o SCHED_BATCH. El valor nice es un número en el rango de -20 (alta prioridad) a +19 (baja prioridad); consulte sched(7).
sched_priority
Este campo especifica la prioridad estática a establecer al especificar sched_policy como SCHED_FIFO o SCHED_RR. El rango permitido de prioridades para estas políticas se puede determinar usando sched_get_priority_min(2) y sched_get_priority_max(2). Para otras políticas, este campo debe especificarse como 0.
sched_runtime
Este campo especifica el parámetro "Tiempo de ejecución" para la planificación por plazos. El valor se expresa en nanosegundos. Este campo, y los dos campos siguientes, solo se utilizan para la planificación SCHED_DEADLINE; para más detalles, consulte sched(7).

NAME

sched_setattr, sched_getattr - set and get scheduling attributes

LIBRARY

Real-time threading library (librt, though the system calls are part of the kernel interface, glibc does not provide wrappers for them).

SYNOPSIS

int sched_setattr(pid_t pid, const struct sched_attr *attr, unsigned int flags);
int sched_getattr(pid_t pid, struct sched_attr *attr, unsigned int flags, unsigned int size);

DESCRIPTION

The sched_setattr() system call sets the scheduling policy and attributes for the thread whose ID is specified in pid. If pid equals zero, the scheduling policy and attributes of the calling thread will be modified.

The attr argument points to a structure that specifies the scheduling policy and attributes to be set. The flags argument is provided to allow for future extensions to the interface; in the current implementation it must be specified as 0.

The sched_attr structure is defined in <sched.h> as follows:

struct sched_attr {
    __u32 size;

    __u32 sched_policy;

    __u64 sched_flags;

    /* SCHED_NORMAL, SCHED_FIFO, SCHED_RR */
    __s32 sched_priority;

    /* SCHED_DEADLINE */
    __u64 sched_runtime;
    __u64 sched_period;
    __u64 sched_deadline;

    /* SCHED_CORE */
    __u32 __pad[1];
};

The fields in sched_attr are:

sched_policy
This field specifies the scheduling policy. The supported values are SCHED_NORMAL (normal multi-
-process scheduling), SCHED_FIFO (first-in, first-out), SCHED_RR (round-robin), and SCHED_DEADLINE (deadline scheduling).
sched_priority
This field specifies the priority of the task. It is used for policies SCHED_NORMAL, SCHED_FIFO, and SCHED_RR. Valid values are in the range [0, sched_get_priority_max(sched_policy)]. A value of 0 means the lowest priority. Higher values mean higher priority.
sched_flags
This field specifies a bit mask of flags that modify the behavior of the scheduling policy. The following flags are supported:
SCHED_FLAG_RESET_ON_FORK
           If set, the scheduling attributes of a child process created
           using fork(2) are reset to
           default values (policy SCHED_NORMAL,
           priority 0).
SCHED_FLAG_UTIL_CLAMP_MIN (since Linux 5.3)
           If set, the task will be scheduled on a CPU with a capacity
           at least as large as specified by
           attr.sched_util_min.
SCHED_FLAG_UTIL_CLAMP_MAX (since Linux 5.3)
           If set, the task will be scheduled on a CPU with a capacity
           no larger than specified by
           attr.sched_util_max.
SCHED_FLAG_KEEP (since Linux 5.11)
           If set, this flag has no effect. The intention is to allow for
           future extensions.

The following fields are used only for SCHED_DEADLINE policy:

sched_runtime
This field specifies the "Runtime" parameter for deadline scheduling. The value is expressed in nanoseconds.
sched_period
This field specifies the "Period" parameter for deadline scheduling. The value is expressed in nanoseconds.
sched_deadline
This field specifies the "Deadline" parameter for deadline scheduling. The value is expressed in nanoseconds.
sched_util_min
sched_util_max (both since Linux 5.3)
These fields specify the expected minimum and maximum utilization, respectively. They are ignored unless their corresponding SCHED_FLAG_UTIL_CLAMP_MIN or SCHED_FLAG_UTIL_CLAMP_MAX is set in sched_flags.
Utilization is a value in the range [0, 1024], representing the percentage of CPU time used by a task when running at the maximum frequency on the highest capacity CPU of the system. This is a fixed point representation, where 1024 corresponds to 100%, and 0 corresponds to 0%. For example, a 20% utilization task is a task running for 2ms every 10ms at maximum frequency and is represented by a utilization value of 0.2 * 1024 = 205.
A task with a minimum utilization value larger than 0 is more likely scheduled on a CPU with a capacity big enough to fit the specified value. A task with a maximum utilization value smaller than 1024 is more likely scheduled on a CPU with no more capacity than the specified value.
A task utilization boundary can be reset by setting its field to UINT32_MAX (since Linux 5.11).

The flags argument is provided to allow for future extensions to the interface; in the current implementation it must be specified as 0.

sched_getattr()

The sched_getattr() system call fetches the scheduling policy and the associated attributes for the thread whose ID is specified in pid. If pid equals zero, the scheduling policy and attributes of the calling thread will be retrieved.

The size argument should be set to the size of the sched_attr structure as known to user space. The value must be at least as large as the size of the initially published sched_attr structure, or the call fails with the error EINVAL.

The retrieved scheduling attributes are placed in the fields of the sched_attr structure pointed to by attr. The kernel sets attr.size to the size of its sched_attr structure.

If the caller-provided attr buffer is larger than the kernel's sched_attr structure, the additional bytes in the user-space structure are not touched. If the caller-provided structure is smaller than the kernel sched_attr structure, the kernel will silently not return any values which would be stored outside the provided space. As with sched_setattr(), these semantics allow for future extensibility of the interface.

The flags argument is provided to allow for future extensions to the interface; in the current implementation it must be specified as 0.

RETURN VALUE

On success, sched_setattr() and sched_getattr() return 0. On error, -1 is returned, and errno is set to indicate the error.

ERRORS

sched_getattr() and sched_setattr() can both fail for the following reasons:

EINVAL
attr is NULL; or pid is negative; or flags is not zero.
ESRCH
The thread whose ID is pid could not be found.

In addition, sched_getattr() can fail for the following reasons:

E2BIG
The buffer specified by size and attr is too small.
EINVAL
size is invalid; that is, it is smaller than the initial version of the sched_attr structure (48 bytes) or larger than the system page size.

In addition, sched_setattr() can fail for the following reasons:

E2BIG
The buffer specified by size and attr is larger than the kernel structure, and one or more of the excess bytes is nonzero.
EBUSY
SCHED_DEADLINE admission control failure, see sched(7).
EINVAL
attr.sched_policy is not one of the recognized policies.
EINVAL
attr.sched_flags contains a flag other than SCHED_FLAG_RESET_ON_FORK.
EINVAL
attr.sched_priority is invalid.
EINVAL
attr.sched_policy is SCHED_DEADLINE, and the deadline scheduling parameters in attr are invalid.
EINVAL
attr.sched_flags contains SCHED_FLAG_UTIL_CLAMP_MIN or SCHED_FLAG_UTIL_CLAMP_MAX, and attr.sched_util_min or attr.sched_util_max are out of bounds.
EOPNOTSUPP
SCHED_FLAG_UTIL_CLAMP was provided, but the kernel was not built with CONFIG_UCLAMP_TASK support.
EPERM
The caller does not have appropriate privileges.
EPERM
The CPU affinity mask of the thread specified by pid does not include all CPUs in the system (see sched_setaffinity(2)).

STANDARDS

Linux.

HISTORY

Linux 3.14.

NOTES

glibc does not provide wrappers for these system calls; call them using syscall(2).

sched_setattr() provides a superset of the functionality of sched_setscheduler(2), sched_setparam(2), nice(2), and (other than the ability to set the priority of all processes belonging to a specified user or all processes in a specified group) setpriority(2). Analogously, sched_getattr() provides a superset of the functionality of sched_getscheduler(2), sched_getparam(2), and (partially) getpriority(2).

BUGS

In Linux versions up to 3.15, sched_setattr() failed with the error EFAULT instead of E2BIG for the case described in ERRORS.

Up to Linux 5.3, sched_getattr() failed with the error EFBIG if the in-kernel sched_attr structure was larger than the size passed by user space.

sched_setattr

establecer atributos de planificación de procesos

SYNOPSIS

#include <sched.h>

int sched_setattr(pid_t pid, const struct sched_attr *attr, unsigned int flags);
int sched_getattr(pid_t pid, const struct sched_attr *attr, unsigned int *flags, void *stack_size);

DESCRIPTION

La función sched_setattr() establece los atributos de planificación de procesos especificados por attr para el proceso cuyo ID se indica en pid. Si pid es 0, se aplican los atributos al hilo de llamada.

La estructura struct sched_attr se define en <sched.h> y contiene los siguientes campos:

struct sched_attr {
    uint32_t size;              /* Tamaño de la estructura */
    uint32_t sched_policy;      /* Política de planificación */
    uint64_t sched_flags;       /* Banderas adicionales */
    int32_t sched_nice;         /* Prioridad (solo SCHED_NORMAL, SCHED_BATCH, SCHED_IDLE) */
    uint32_t sched_priority;    /* Prioridad (para SCHED_FIFO, SCHED_RR) */
    uint64_t sched_runtime;     /* Tiempo de ejecución garantizado (en nanosegundos) */
    uint64_t sched_period;      /* Período de tiempo de ejecución (en nanosegundos) */
    uint64_t sched_deadline;    /* Plazo de tiempo de ejecución (en nanosegundos) */
};

Los campos sched_policy pueden ser:

  • SCHED_NORMAL : Planificación normal de la CPU (prioridad basada en nice).
  • SCHED_FIFO : Planificación FIFO.
  • SCHED_RR : Planificación Round-Robin.
  • SCHED_BATCH : Planificación por lotes (para trabajos que no requieren interacción).
  • SCHED_IDLE : Planificación inactiva (para trabajos de muy baja prioridad).

El campo flags puede contener las siguientes banderas:

  • SCHED_RESET_ON_FORK : El proceso hijo hereda los atributos de planificación del padre en la bifurcación.

La función sched_getattr() recupera los atributos de planificación actuales para el proceso especificado por pid. Los atributos se devuelven en la estructura attr.

VALOR DE RETORNO

En caso de éxito, sched_setattr() y sched_getattr() devuelven 0. En caso de error, devuelven -1 y establecen errno para indicar el error.

ERRORES

  • EPERM : El proceso que llama no tiene los permisos necesarios para cambiar la planificación.
  • ESRCH : No se encontró ningún proceso con el ID especificado.
  • EINVAL : Se proporcionaron parámetros no válidos (por ejemplo, atributos o políticas de planificación no válidos).

ESTÁNDARES

POSIX.1-2008.

HISTORIAL

Linux 2.6.37.

NOTAS

Para utilizar sched_setattr() y sched_getattr(), el proceso que llama debe tener los privilegios adecuados (por ejemplo, ser un proceso privilegiado o tener la capacidad CAP_SYS_NICE).

ERRORES COMUNES

Un error común es intentar cambiar la planificación sin los permisos adecuados, lo que resulta en EPERM.

VER TAMBIÉN

sched_get_priority_max(2), sched_get_priority_min(2), sched_setscheduler(2), sched_yield(2)
