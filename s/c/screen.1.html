SCREEN(1) Manual de Comandos Generales SCREEN(1)

NOMBRE

screen - gestor de pantalla con emulación de terminal VT100/ANSI

SINOPSIS

screen [ -opciones ] [ comando [ argumentos ] ]
screen -r [[pid.]tty[.host]]
screen -r propietario_sesion/[[pid.]tty[.host]]

DESCRIPCIÓN

Screen es un gestor de pantalla completa que multiplexa un terminal físico entre varios procesos (típicamente shells interactivos). Cada terminal virtual proporciona las funciones de un terminal DEC VT100 y, además, varias funciones de control de los estándares ISO 6429 (ECMA 48, ANSI X3.64) e ISO 2022 (por ejemplo, inserción/eliminación de línea y soporte para múltiples conjuntos de caracteres). Hay un búfer de historial de desplazamiento para cada terminal virtual y un mecanismo de copiar y pegar que permite mover regiones de texto entre ventanas.

Cuando se llama a screen, crea una única ventana con un shell (o el comando especificado) y luego se aparta para que puedas usar el programa como lo harías normalmente. Luego, en cualquier momento, puedes crear nuevas ventanas (de pantalla completa) con otros programas (incluyendo más shells), matar ventanas existentes, ver una lista de ventanas, activar/desactivar el registro de salida, copiar y pegar texto entre ventanas, ver el historial de desplazamiento, cambiar entre ventanas de la manera que desees, etc. Todas las ventanas ejecutan sus programas de forma completamente independiente entre sí. Los programas continúan ejecutándose cuando su ventana no es visible actualmente e incluso cuando toda la sesión de screen se desvincula del terminal del usuario. Cuando un programa termina, screen (por defecto) mata la ventana que lo contenía. Si esta ventana estaba en primer plano, la pantalla cambia a la ventana anterior; si no quedan ninguna, screen sale. Los shells suelen distinguir entre ejecutarse como shell de inicio de sesión o shell secundario. Screen los ejecuta como shells secundarios, a menos que se le indique lo contrario (Ver comando .screenrc del shell).

Todo lo que escribas se envía al programa que se ejecuta en la ventana actual. La única excepción es la pulsación de tecla que se utiliza para iniciar un comando para el gestor de ventanas. Por defecto, cada comando comienza con una control-a (abreviado C-a de ahora en adelante), y va seguido por otra pulsación de tecla. El carácter de comando y todas las asignaciones de teclas pueden personalizarse completamente para que sean lo que tú quieras, aunque siempre tienen dos caracteres de longitud.

Screen no entiende el prefijo C- para significar control, aunque esta notación se usa en este manual para facilitar la lectura. Por favor, usa la notación de intercalación (^A en lugar de C-a) como argumentos para, por ejemplo, el comando de escape o la opción de -e. Screen también imprimirá caracteres de control en notación de intercalación.

La forma estándar de crear una nueva ventana es escribir C-a c. Esto crea una nueva ventana ejecutando un shell y cambia a esa ventana inmediatamente, independientemente del estado del proceso que se ejecuta en la ventana actual. De manera similar, puedes crear una nueva ventana con un comando personalizado en ella, primero asignando el comando a una pulsación de tecla (en tu archivo .screenrc o en la línea de comandos C-a :) y luego usándolo igual que el comando C-a c. Además, se pueden crear nuevas ventanas ejecutando un comando como:

screen emacs prog.c

desde un prompt de shell dentro de una ventana creada previamente. Esto no ejecutará otra copia de screen, sino que proporcionará el nombre del comando y sus argumentos al gestor de ventanas (especificado en la variable de entorno $STY) que lo usará para crear la nueva ventana. El ejemplo anterior iniciaría el editor emacs (editando prog.c) y cambiaría a su ventana. - Ten en cuenta que no puedes transportar variables de entorno del shell llamador a la aplicación (emacs en este caso), porque se bifurca desde el proceso padre de screen, no desde el shell llamador.

Si /etc/utmp es escribible por screen, se escribirá un registro apropiado en este archivo para cada ventana, y se eliminará cuando la ventana termine. Esto es útil para trabajar con talk, script, shutdown, rsend, sccs y otros programas similares que usan el archivo utmp para determinar quién eres. Mientras screen esté activo en tu terminal, el propio registro del terminal se eliminará del archivo utmp. Ver también C-a L.

EMPEZANDO

Antes de empezar a usar screen, deberás asegurarte de haber seleccionado correctamente el tipo de terminal, igual que harías para cualquier otro programa termcap/terminfo. (Puedes hacerlo usando test por ejemplo).

Si eres impaciente y quieres empezar sin leer más, deberías recordar este comando: C-a ?. Escribir estos dos caracteres mostrará una lista de los comandos disponibles de screen y sus asignaciones. Cada pulsación de tecla se discute en la sección ASIGNACIONES DE TECLAS PREDETERMINADAS. La sección del manual PERSONALIZACIÓN trata sobre el contenido de tu .screenrc.

Si tu terminal es un terminal de margen automático verdadero (no permite que la última posición de la pantalla se actualice sin desplazar la pantalla) considera usar una versión del termcap de tu terminal con los márgenes automáticos desactivados. Esto asegurará una actualización precisa y óptima de la pantalla en todas las circunstancias. La mayoría de los terminales hoy en día tienen márgenes mágicos (márgenes automáticos más columna final utilizable). Este es el tipo estilo VT100 y es perfectamente adecuado para screen. Si solo tienes un terminal de margen automático verdadero, screen se contentará con usarlo, pero actualizar un carácter puesto en la última posición de la pantalla puede no ser posible hasta que la pantalla se desplace o el carácter se mueva a una posición segura de alguna otra manera. Este retraso puede acortarse usando un terminal con capacidad de inserción de caracteres.

OPCIONES DE LA LÍNEA DE COMANDOS

Screen tiene las siguientes opciones de línea de comandos:

-a
incluye *todas* las capacidades (con algunas excepciones menores) en el termcap de cada ventana, incluso si screen debe redibujar partes de la pantalla para implementar una función.
-A
Adapta los tamaños de todas las ventanas al tamaño del terminal actual. Por defecto, screen intenta restaurar sus tamaños de ventana antiguos al conectarse a terminales redimensionables (aquellos con WS en su descripción, por ejemplo, suncmd o algunos xterm).
-c archivo
anula el archivo de configuración predeterminado de $HOME/.screenrc a archivo.
-d|-D [pid.tty.host]
no inicia screen, sino que desconecta la sesión de screen que se ejecuta en otro lugar. Tiene el mismo efecto que escribir C-a d desde el terminal de control de screen. -D es el equivalente a la tecla de desconexión forzada. Si no se puede desconectar ninguna sesión, esta opción se ignora. En combinación con la opción -r/-R se pueden lograr efectos más potentes:
-d -r
Reconecta una sesión y, si es necesario, la desconecta primero.
-d -R
Reconecta una sesión y, si es necesario, la desconecta o incluso la crea primero.
-d -RR
Reconecta una sesión y, si es necesario, la desconecta o crea. Usa la primera sesión si hay más de una disponible.
-D -r
Reconecta una sesión. Si es necesario, la desconecta y cierra la sesión remota primero.
-D -R
Conecta aquí y ahora. En detalle esto significa: Si una sesión está en ejecución, entonces reconecta. Si es necesario, desconecta y cierra la sesión remota primero. Si no estaba en ejecución, créala y notifica al usuario. Este es el favorito del autor.
-D -RR
Conecta aquí y ahora. Lo que sea que eso signifique, hazlo.
Nota: Siempre es una buena idea verificar el estado de tus sesiones mediante screen -list.
-e xy
especifica que el carácter de comando sea x y el carácter que genera un carácter de comando literal sea y (cuando se escribe después del carácter de comando). El valor predeterminado es C-a y `a', que se puede especificar como -e^Aa. Al crear una sesión de screen, esta opción establece el carácter de comando predeterminado. En una sesión multiusuario, todos los usuarios añadidos comenzarán con este carácter de comando. Pero al conectarse a una sesión ya en ejecución, esta opción solo cambia el carácter de comando del usuario que se conecta. Esta opción es equivalente a los comandos defescape o escape respectivamente.
-f, -fn, y -fa
activa, desactiva o cambia al modo de conmutación automática del control de flujo. Esto también puede definirse a través del comando defflow .screenrc.
-h num
Especifica que el búfer de desplazamiento de historial tenga una altura de num líneas.
-i
hará que la tecla de interrupción (normalmente C-c) interrumpa la visualización inmediatamente cuando el control de flujo esté activado. Consulte el comando defscreen .screenrc para obtener más detalles. Se desaconseja el uso de esta opción.
-l y -ln
activa o desactiva el modo de inicio de sesión (para la actualización de /etc/utmp). Esto también puede definirse a través del comando deflogin .screenrc.
-ls [coincidencia]
-list [coincidencia]
no inicia screen, sino que imprime una lista de cadenas pid.tty.host que identifican tus sesiones de screen. Las sesiones marcadas como `detached` se pueden reanudar con screen -r. Las marcadas como `attached` se están ejecutando y tienen una terminal de control. Si la sesión se ejecuta en modo multiusuario, se marca como `multi`. Las sesiones marcadas como `unreachable` se encuentran en un host diferente o están `dead`. Una sesión inalcanzable se considera muerta cuando su nombre coincide con el nombre del host local o con el parámetro especificado, si lo hay. Consulte la bandera -r para obtener una descripción de cómo construir coincidencias. Las sesiones marcadas como `dead` deben ser revisadas y eliminadas a fondo. Consulte a su administrador del sistema si no está seguro. Elimine sesiones con la opción -wipe.
-L
indica a screen que active el registro automático de salida para las ventanas.
-Logfile archivo
Por defecto, el nombre del archivo de registro es screenlog.0. Puede establecer un nuevo nombre de archivo de registro con la opción -Logfile.
-m
hace que screen ignore la variable de entorno $STY. Con screen -m, se fuerza la creación de una nueva sesión, independientemente de si screen se llama desde dentro de otra sesión de screen o no. Esta bandera tiene un significado especial en conexión con la opción `-d':
-d -m
Inicia screen en modo desconectado. Esto crea una nueva sesión pero no se adjunta a ella. Esto es útil para scripts de inicio del sistema.
-D -m
Esto también inicia screen en modo desconectado, pero no crea un nuevo proceso. El comando sale si la sesión termina.
-O
selecciona un modo de salida óptimo para su terminal en lugar de la emulación VT100 real (solo afecta a terminales de margen automático sin `LP`). Esto también se puede configurar en su .screenrc especificando `OP` en un comando termcap.
-p número_o_nombre|-|=|+
Preselecciona una ventana. Esto es útil cuando desea volver a conectarse a una ventana específica o desea enviar un comando a través de la opción -X a una ventana específica. Al igual que con el comando select de screen, - selecciona la ventana en blanco. Como caso especial para reconexión, = muestra la lista de ventanas en la ventana en blanco, mientras que + creará una nueva ventana. El comando no se ejecutará si no se encuentra la ventana especificada.
-P
Activa la autenticación. Por defecto, screen permite la conexión sin introducir la contraseña del usuario. Esta opción cambia este comportamiento, es decir, habilita la autenticación. El mismo efecto se puede lograr utilizando el comando "auth on".
-q
Suprime la impresión de mensajes de error. En combinación con -ls, el valor de salida es el siguiente: 9 indica un directorio sin sesiones. 10 indica un directorio con sesiones en ejecución pero no adjuntables. 11 (o más) indica 1 (o más) sesiones utilizables. En combinación con -r, el valor de salida es el siguiente: 10 indica que no hay ninguna sesión para reanudar. 12 (o más) indica que hay 2 (o más) sesiones para reanudar y debe especificar cuál elegir. En todos los demás casos, -q no tiene ningún efecto.
-Q
Algunos comandos ahora pueden ser consultados desde una sesión remota usando esta bandera, por ejemplo, screen -Q windows. Los comandos enviarán la respuesta a la salida estándar del proceso de consulta. Si hubo un error en el comando, el proceso de consulta saldrá con un estado distinto de cero.

Los comandos que se pueden consultar ahora son:
echo
info
lastmsg
number
select
time
title
windows

-r [pid.tty.host]
-r propietario_sesion/[pid.tty.host]
reanuda una sesión de screen desconectada. No se pueden especificar otras opciones (excepto combinaciones con -d/-D), aunque puede ser necesario un prefijo opcional de [pid.]tty.host para distinguir entre múltiples sesiones de screen desconectadas. La segunda forma se utiliza para conectarse a la sesión de screen de otro usuario que se ejecuta en modo multiusuario. Esto indica que screen debe buscar sesiones en el directorio de otro usuario. Esto requiere privilegios de setuid-root.
-R
reanuda screen solo cuando es inequívoco cuál adjuntar, generalmente cuando solo un screen está desconectado. De lo contrario, lista las sesiones disponibles. -RR intenta reanudar la primera sesión de screen desconectada que encuentra. Si tiene éxito, se ignoran todas las demás opciones de línea de comandos. Si no existe ninguna sesión desconectada, inicia una nueva sesión utilizando las opciones especificadas, como si -R no se hubiera especificado. La opción se establece por defecto si screen se ejecuta como un shell de inicio de sesión (en realidad, screen usa -xRR en ese caso). Para combinaciones con la opción -d/-D, consulte allí.
-s programa
establece el shell predeterminado al programa especificado, en lugar del valor de la variable de entorno $SHELL (o /bin/sh si no está definida). Esto también se puede definir a través del comando shell .screenrc. Consulte también allí.
-S nombre_sesion
Al crear una nueva sesión, esta opción se puede utilizar para especificar un nombre significativo para la sesión. Este nombre identifica la sesión para las acciones screen -list y screen -r. Sustituye el sufijo predeterminado [tty.host]. Este nombre no debe tener más de 80 símbolos.
-t nombre
establece el título (alias) para el shell predeterminado o el programa especificado. Consulte también el comando shelltitle .screenrc.
-T term
Establece la variable de entorno $TERM utilizando el término especificado en lugar de la configuración predeterminada de screen.
-U
Ejecuta screen en modo UTF-8. Esta opción indica a screen que su terminal envía y comprende caracteres codificados en UTF-8. También establece la codificación predeterminada para las nuevas ventanas en `utf8'.
-v
Imprime el número de versión.
-wipe [coincidencia]
hace lo mismo que screen -ls, pero elimina las sesiones destruidas en lugar de marcarlas como `dead'. Una sesión inalcanzable se considera muerta cuando su nombre coincide con el nombre del host local o con el parámetro especificado explícitamente, si lo hay. Consulte la bandera -r para obtener una descripción de cómo construir coincidencias.
-x
Se adjunta a una sesión de screen no desconectada. (Modo multiventana). Screen se niega a adjuntarse desde dentro de sí mismo. Pero al anidar múltiples screens, los bucles no se detectan; tenga cuidado.
-X
Envía el comando especificado a una sesión de screen en ejecución. Puede usar la opción -S para especificar la sesión de screen si tiene varias sesiones de screen en ejecución. Puede usar la opción -d o -r para indicar a screen que busque solo sesiones de screen adjuntas o desconectadas. Tenga en cuenta que este comando no funciona si la sesión está protegida por contraseña.
-4
Resuelve nombres de host solo a direcciones IPv4.
-6
Resuelve nombres de host solo a direcciones IPv6.

CUSTOMIZATION

The socket directory defaults either to $HOME/.screen or simply to /tmp/screens or preferably to /usr/local/screens chosen at compile-time. If screen is installed setuid-root, then the administrator should compile screen with an adequate (not NFS mounted) socket directory. If screen is not running setuid-root, the user can specify any mode 700 directory in the environment variable $SCREENDIR.

When screen is invoked, it executes initialization commands from the files /usr/local/etc/screenrc and defaults that can be overridden in the following ways: for the global screenrc file screen searches for the environment variable $SYSSCREENRC (this override feature may be disabled at compile-time). The user specific screenrc file is searched in $SCREENRC, then $HOME/.screenrc. The command line option -c takes precedence over the above user screenrc files.

Commands in these files are used to set options, bind functions to keys, and to automatically establish one or more windows at the beginning of your screen session. Commands are listed one per line, with empty lines being ignored. A command's arguments are separated by tabs or spaces, and may be surrounded by single or double quotes. A `#' turns the rest of the line into a comment, except in quotes. Unintelligible lines are warned about and ignored. Commands may contain references to environment variables. The syntax is the shell-like "$VAR " or "${VAR}". Note that this causes incompatibility with previous screen versions, as now the '$'-character has to be protected with '\' if no variable substitution shall be performed. A string in single-quotes is also protected from variable substitution.

Two configuration files are shipped as examples with your screen distribution: etc/screenrc and etc/etcscreenrc. They contain a number of useful examples for various commands.

Customization can also be done 'on-line'. To enter the command mode type `C-a :'. Note that commands starting with def change default values, while others change current settings.

The following commands are available:

acladd usernames [crypted-pw]
addacl usernames

Enable users to fully access this screen session. Usernames can be one user or a comma separated list of users. This command enables to attach to the screen session and performs the equivalent of `aclchg usernames +rwx "#?"'. executed. To add a user with restricted access, use the `aclchg' command below. If an optional second parameter is supplied, it should be a crypted password for the named user(s). `Addacl' is a synonym to `acladd'. Multi user mode only.

aclchg usernames permbits list
chacl usernames permbits list

Change permissions for a comma separated list of users. Permission bits are represented as `r', `w' and `x'. Prefixing `+' grants the permission, `-' removes it. The third parameter is a comma separated list of commands and/or windows (specified either by number or title). The special list `#' refers to all windows, `?' to all commands. if usernames consists of a single `*', all known users are affected.

A command can be executed when the user has the `x' bit for it. The user can type input to a window when he has its `w' bit set and no other user obtains a writelock for this window. Other bits are currently ignored. To withdraw the writelock from another user in window 2: `aclchg username -w+w 2'. To allow read-only access to the session: `acl

chg nombredeusuario -w "#". Tan pronto como se conozca el nombre de un usuario en screen, este podrá adjuntarse a la sesión y (por defecto) tendrá todos los permisos para todos los comandos y ventanas. Deberían eliminarse también los permisos de ejecución para los comandos acl, `at' y otros, de lo contrario, el usuario podría recuperar el permiso de escritura. Los derechos del nombre de usuario especial nobody no pueden cambiarse (ver el comando su). `Chacl' es un sinónimo de `aclchg'. Solo modo multiusuario.

Crea grupos de usuarios que comparten derechos de acceso comunes. El nombre del grupo es el nombre de usuario del líder del grupo. Cada miembro del grupo hereda los permisos que se otorgan al líder del grupo. Esto significa que, si un usuario falla una comprobación de acceso, se realiza otra comprobación para el líder del grupo. Usuarios puede ser ninguno, uno o una lista separada por comas de nombres de usuario conocidos. Si no se especifican usuarios, se asume una lista de todos los usuarios conocidos actualmente. Bits es cualquier combinación de bits de control de acceso permitidos definidos con el comando aclchg. El nombre de usuario especial ? predefine el acceso que los usuarios aún no conocidos obtendrán inicialmente para cualquier ventana. El nombre de usuario especial ?? predefine el acceso que los usuarios aún no conocidos obtienen para cualquier comando. at [identificador][#|*|%] comando [argumentos ...]

Ejecuta un comando en otras pantallas o ventanas como si se hubiera introducido allí. At cambia el contexto (la configuración de `ventana actual' o `pantalla actual') del comando. Si el primer parámetro describe un contexto no único, el comando se ejecutará múltiples veces. Si el primer parámetro tiene la forma `identificador*' entonces el identificador se compara con nombres de usuario. El comando se ejecuta una vez por cada pantalla de los usuarios seleccionados. Si el primer parámetro tiene la forma `identificador%' el identificador se compara con las pantallas. Las pantallas se nombran según los ttys a los que se conectan. El prefijo `/dev/' o `/dev/tty' puede omitirse del identificador. Si identificador tiene un '#' o nada adjunto, se compara con números y títulos de ventana. Omitir un identificador delante del carácter '#', '*' o '%' selecciona todos los usuarios, pantallas o ventanas porque se realiza una coincidencia de prefijo. Tenga en cuenta que en las pantallas afectadas se mostrará un mensaje corto describiendo lo sucedido. El permiso se verifica para el iniciador del comando at, no para los propietarios de las pantallas afectadas. Tenga en cuenta que el carácter '#' funciona como introductor de comentarios cuando va precedido de espacio en blanco. Esto puede escaparse prefijando una '\'. El permiso se verifica para el iniciador del comando at, no para los propietarios de las pantallas afectadas.

Advertencia: Al comparar con ventanas, el comando se ejecuta al menos una vez por ventana. Los comandos que cambian la disposición interna de las ventanas (como otros) pueden ser llamados de nuevo. En ventanas compartidas, el comando se repetirá para cada pantalla conectada. Tenga cuidado al emitir comandos de alternancia como login. Algunos comandos (por ejemplo, process) requieren que una pantalla esté asociada a las ventanas de destino. Estos comandos pueden no funcionar correctamente bajo at al iterar sobre ventanas.

bind [clase] tecla [comando [argumentos]]

Vincula un comando a una tecla. Por defecto, la mayoría de los comandos proporcionan

d por pantalla están vinculados a una o más teclas, como se indica en la sección CLAVES PREDETERMINADAS, por ejemplo, el comando para crear una nueva ventana está vinculado a C-c y c. El comando bind se puede usar para redefinir las vinculaciones de teclas y definir nuevas vinculaciones. El argumento tecla es un solo carácter, una secuencia de dos caracteres de la forma ^x (que significa C-x), una barra invertida seguida de un número octal (que especifica el código ASCII del carácter) o una barra invertida seguida de un segundo carácter, como \^ o \\. El argumento también puede ser citado, si lo desea. Si no se proporciona ningún argumento adicional, se elimina cualquier vinculación previamente establecida para esta tecla. El argumento comando puede ser cualquier comando que figure en esta sección.

Si se especifica una clase de comando a través de la opción -c, la tecla se vincula para la clase especificada. Use el comando command para activar una clase. Las clases de comandos se pueden usar para crear claves de comandos múltiples o vinculaciones de varios caracteres.

Algunos ejemplos:

bind ' ' windows
bind ^k
bind k
bind K kill
bind ^f screen telnet foobar
bind \033 screen -ln -t root -h 1000 9 su

vincularía la tecla de espacio al comando que muestra una lista de ventanas (de modo que el comando que normalmente se invoca con C-a C-w también estaría disponible como C-a espacio). Las siguientes tres líneas eliminan la vinculación predeterminada de matar de C-a C-k y C-a k. Luego, C-a K se vincula al comando matar. Luego, vincula C-f al comando crear una ventana con una conexión TELNET a foobar, y vincula la tecla de escape al comando que crea una ventana sin inicio de sesión con el nombre de usuario root en la ranura n.º 9, con un shell de superusuario y un búfer de desplazamiento de 1000 líneas.

bind -c demo1 0 select 10
bind -c demo1 1 select 11
bind -c demo1 2 select 12
bindkey "^B" command -c demo1

hace que C-b 0 seleccione la ventana 10, C-b 1 la ventana 11, etc.

bind -c demo2 0 select 10
bind -c demo2 1 select 11
bind -c demo2 2 select 12
bind - command -c demo2

hace que C-a - 0 seleccione la ventana 10, C-a - 1 la ventana 11, etc.

bindkey [-d] [-m] [-a] [[-k|-t] cadena [argumentos_comando]]

Este comando administra las tablas de traducción de entrada de screen. Cada entrada en una de las tablas le dice a screen cómo reaccionar si se encuentra una secuencia de caracteres determinada. Hay tres tablas: una que debe contener las acciones programadas por el usuario, una para las acciones predeterminadas utilizadas para la emulación de terminal y otra para el modo de copia de screen para realizar movimientos del cursor. Consulte la sección TRADUCCIÓN DE ENTRADAS para obtener una lista de las vinculaciones de teclas predeterminadas.

Si se proporciona la opción -d, bindkey modifica la tabla predeterminada, -m cambia la tabla del modo de copia y, sin ninguna opción, se selecciona la tabla del usuario. El argumento cadena es la secuencia de caracteres a los que se vincula una acción. Puede ser una cadena fija o un nombre de capacidad de teclado de termcap (seleccionable con la opción -k).

Algunas teclas en un terminal VT100 pueden enviar una cadena diferente si el modo de aplicación está activado (por ejemplo, las teclas de cursor). Dichas teclas tienen dos entradas en la tabla de traducción. Puede seleccionar la entrada del modo de aplicación especificando la opción -a.

La opción -t indica a screen que no realice la temporización entre caracteres. No se puede desactivar la temporización si se utiliza una capacidad de termcap.

Cmd puede ser cualquiera de los comandos de screen con un número arbitrario de argumentos. Si se omite cmd, la vinculación de teclas se elimina de la tabla.

Aquí hay algunos ejemplos de vinculaciones de teclado:

        bindkey -d

Muestra todas las vinculaciones de teclas predeterminadas. Las entradas del modo de aplicación están marcadas con [A].

        bindkey -k k1 select 1

Hace que la tecla "F1" cambie a la ventana uno.

        bindkey -t foo stuff barfoo

Hace de "foo" una abreviatura de la palabra "barfoo". Se desactiva el tiempo de espera para que los usuarios puedan escribir lentamente.

        bindkey "\024" mapdefault

Esta vinculación de teclas hace que ^T sea un carácter de escape para las vinculaciones de teclas. Si realizó la vinculación anterior de stuff barfoo, puede escribir la palabra foo escribiendo ^Tfoo. Si desea insertar un ^T, debe presionar la tecla dos veces (es decir, escapar de la vinculación de escape).

        bindkey -k F1 command

Hace que la tecla F11 (¡no F1!) sea un escape de pantalla alternativo (además de ^A).

exec [[pat-fd]nuevocmd [args ...]]

Ejecuta un subproceso de Unix (especificado por una ruta de ejecutable nuevocmd y sus argumentos opcionales) en la ventana actual. El flujo de datos entre la stdin/stdout/stderr de nuevocmd, el proceso iniciado originalmente en la ventana (llamémoslo "proceso-aplicación") y screen (ventana) se controla mediante el patrón de descriptor de archivo pat-fd. Este patrón es básicamente una secuencia de tres caracteres que representa stdin, stdout y stderr de nuevocmd. Un punto (.) conecta el descriptor de archivo a screen. Un signo de exclamación (!) hace que el descriptor de archivo se conecte al proceso-aplicación. Dos puntos (:) combinan ambos. La entrada del usuario irá a nuevocmd a menos que nuevocmd reciba la salida del proceso-aplicación (el primer carácter de pat-fd sea `!' o `:') o se agregue un símbolo de tubería (|) (como cuarto carácter) al final de pat-fd.

Invocar `exec' sin argumentos muestra el nombre y los argumentos del subproceso que se está ejecutando actualmente en esta ventana. Solo puede ejecutarse un subproceso a la vez en cada ventana.

Cuando se ejecuta un subproceso, el comando `kill' lo afectará en lugar del proceso de las ventanas.

Consulte el archivo postscript `doc/fdpat.ps' para obtener una ilustracíón confusa de todas las 21 combinaciones posibles. Cada dibujo muestra los dígitos 2,1,0 representando los tres descriptores de archivo de nuevocmd. El cuadro marcado con `W' es el pty habitual que tiene el proceso-aplicación en su lado esclavo. El cuadro marcado con `P' es el pty secundario que ahora tiene screen en su lado maestro.

Abreviaturas: Se puede omitir el espacio en blanco entre la palabra `exec' y pat-fd y el comando. Se pueden omitir los puntos finales y un pat-fd que solo conste de puntos. Una simple `|' es sinónimo del patrón `!..|'; la palabra exec se puede omitir aquí y siempre se puede reemplazar por `!'.

Ejemplos:

exec ... /bin/sh
exec /bin/sh
!/bin/sh

Crea otro shell en la misma ventana, mientras el shell original sigue ejecutándose. La salida de ambos shells se muestra y la entrada del usuario se envía al nuevo /bin/sh.

exec !.. stty 19200
exec ! stty 19200
!!stty 19200

Establece la velocidad del tty de la ventana. Si su comando stty opera en stdout, agregue otro `!'.

exec !..| less
|less

Esto agrega un paginador a la salida de la ventana. El carácter especial `|' es necesario para dar al usuario control sobre el paginador, aunque recibe su entrada del proceso de la ventana. Esto funciona porque less escucha en stderr (un comportamiento que screen no esperaría sin el `|') cuando su stdin no es un tty. Las versiones de Less más nuevas que 177 fallan miserablemente aquí; el buen y viejo pg todavía funciona.

!:sed -n s/.*Error.*/\007/p

Envía la salida de la ventana tanto al usuario como al comando sed. El sed inserta un carácter de campana adicional (octal 007) en la salida de la ventana vista por screen. Esto causará mensajes de "Bell in window x" siempre que la cadena "Error" aparezca en la ventana.

focus [ next | prev | up | down | left | right | top | bottom ]

Mueve el foco de entrada a la siguiente región. Esto se hace de forma cíclica para que la región superior izquierda se seleccione después de la inferior derecha. Si no se proporciona ninguna opción, el valor predeterminado es `next'. La siguiente región a seleccionar se determina por cómo están dispuestas las regiones. Normalmente, se seleccionaría la siguiente región en la misma capa. Sin embargo, si esa siguiente región contiene una o más capas, se seleccionará primero la primera región en la capa más alta. Si se encuentra en la última región de la capa actual, `next' moverá el foco a la siguiente región en la capa inferior (si hay una capa inferior). `Prev' cicla en el orden opuesto. Consulte split para obtener más información sobre capas.

El resto de las opciones (`up', `down', `left', `right', `top' y `bottom') son más indiferentes a las capas. La opción `up' moverá el foco hacia arriba a la región que toca la esquina superior izquierda de la región actual. `Down' se moverá hacia abajo a la región que toca la esquina inferior izquierda de la región actual. La opción `left' moverá el foco hacia la izquierda a la región que toca la esquina superior izquierda de la región actual, mientras que `right' se moverá hacia la derecha a la región que toca la esquina superior derecha de la región actual. Moverse hacia la izquierda desde una región más a la izquierda o moverse hacia la derecha desde una región más a la derecha no tendrá ningún efecto.

La opción `top' moverá el foco a la primera región en la esquina superior izquierda de la pantalla, y `bottom' se moverá a la región en la esquina inferior derecha de la pantalla. Moverse hacia arriba desde una región superior o hacia abaj

n desde una región inferior resultará en ninguna acción.

Los enlaces útiles son (h, j, k, y l como en vi)

    bind h focus left
    bind j focus down
    bind k focus up
    bind l focus right
    bind t focus top
    bind b focus bottom
Tenga en cuenta que k está tradicionalmente enlazado al comando kill.

Esta restricción se aplica cada vez que se usa el comando focus. Este comando configura el uso y la emulación de la línea de estado hardware del terminal. La primera forma alterna si screen usará la línea de estado hardware para mostrar mensajes. resize
[-h|-v|-b|-l|-p] [[+|-] n[%] |=|max|min|_|0]

Redimensiona la región actual. El espacio se eliminará o se añadirá a las regiones circundantes dependiendo del orden de las divisiones. Las opciones disponibles para redimensionar son `-h' (horizontal), `-v' (vertical), `-b' (ambas), `-l' (local a la capa) y `-p' (perpendicular). Los redimensionamientos horizontales añadirán o quitarán ancho a una región, los verticales añadirán o quitarán altura, y ambos añadirán o quitarán tamaño a ambas dimensiones. Local y perpendicular son similares a horizontal y vertical, pero tienen en cuenta cómo se dividió una región. Si la última división de una región fue horizontal, un redimensionamiento local funcionará como un redimensionamiento vertical. Si la última división de una región fue vertical, un redimensionamiento local funcionará como un redimensionamiento horizontal. Los redimensionamientos perpendiculares funcionan en sentido opuesto a los redimensionamientos locales. Si no se especifica ninguna opción, local es el valor predeterminado.

La cantidad de líneas a añadir o quitar se puede expresar de un par de maneras. Al especificar un número n por sí solo se redimensionará la región por esa cantidad absoluta. Puedes especificar una cantidad relativa prefijando un signo más `+' o un signo menos `-' a la cantidad, como añadir +n líneas o quitar -n líneas. El redimensionamiento también se puede expresar como un porcentaje absoluto o relativo al añadir un signo de porcentaje '%' al final. Usar cero `0' es un sinónimo de `min' y usar un guion bajo `_' es un sinónimo de `max'.

Algunos ejemplos son:

resize +N
aumentar la región actual en N
resize -N
disminuir la región actual en N
resize N
establecer la región actual a N
resize 20%
establecer la región actual al 20% de su tamaño original
resize +20%
aumentar la región actual en un 20%
resize -b =
hacer todas las ventanas iguales
resize max
maximizar la región actual
resize min
minimizar la región actual

Sin argumentos, *screen* solicitará cómo deseas redimensionar la región actual.

Ver focusminsize si deseas restringir el tamaño mínimo que puede tener una región.

screen [-opts] [n] [cmd [args]|//group]

Establece una nueva ventana. Las opciones de control de flujo (-f, -fn y -fa), la opción de título (alias) (-t), las opciones de inicio de sesión (-l y -ln), la opción de tipo de terminal (-T <term>), la bandera de todas las capacidades (-a) y la opción de scrollback (-h <num>) pueden especificarse con cada comando. La opción (-M) activa la monitorización para esta ventana. La opción (-L) activa el registro de salida para esta ventana. Si se proporciona un número opcional n en el rango 0..MAXWIN-1, se asigna el número de ventana n a la ventana recién creada (o, si este número ya está en uso, el siguiente número disponible). Si se especifica un comando después de screen, este comando (con los argumentos dados) se inicia en la ventana; de lo contrario, se crea un shell. Si se suministra //group, se crea una ventana de tipo contenedor en la que se pueden crear otras ventanas dentro de ella.

Por lo tanto, si tu .screenrc contiene las líneas

# ejemplo para .screenrc:
screen 1
screen -fn -t foobar -L 2 telnet foobar

*screen* crea una ventana de shell (en la ventana #1) y una ventana con una conexión TELNET a la máquina foobar (sin control de flujo usando el título foobar en la ventana #2) y escribirá un archivo de registro (screenlog.2) de la sesión telnet. Ten en cuenta que, a diferencia de las versiones anteriores de *screen*, no se crea ninguna ventana predeterminada adicional cuando los comandos de screen se incluyen en tu archivo .screenrc. Cuando se completa la inicialización, *screen* cambia a la última ventana especificada en tu archivo .screenrc o, si no hay ninguna, abre una ventana predeterminada #0.

Screen tiene incorporada parte de la funcionalidad de cu y telnet. Ver también el capítulo TIPOS DE VENTANA.

Cambia a la ventana identificada por IDVentana. Puede ser un prefijo de un título de ventana (nombre de ventana alfanumérico) o un número de ventana. El parámetro es opcional y si se omite, se te pedirá un identificador. Cuando se establece una nueva ventana, se le asigna el primer número disponible. Por lo tanto, la primera ventana se puede activar con select 0. El número de ventanas se establece mediante el parámetro de configuración MAXWIN (que por defecto es 100). termcap term modificaciones_terminal[modificaciones_ventana]

Utilice este comando para modificar la entrada termcap de su terminal sin pasar por todas las molestias que implica crear una entrada termcap personalizada. Además, puede personalizar opcionalmente el termcap generado para las ventanas. Debe colocar estos comandos en uno de los archivos de inicio de screenrc, ya que no tienen sentido una vez que el emulador de terminal se inicia.

Si su sistema utiliza la base de datos terminfo en lugar de termcap, screen entenderá el comando `terminfo', que tiene los mismos efectos que el comando `termcap'. Se proporcionan dos comandos separados, ya que hay sutiles diferencias sintácticas, por ejemplo, cuando se requiere interpolación de parámetros (usando '%'). Tenga en cuenta que los nombres de capacidades de termcap deben usarse con el comando `terminfo'.

En muchos casos, donde los argumentos son válidos tanto en sintaxis terminfo como termcap, puede usar el comando `termcapinfo', que es simplemente un atajo para un par de comandos `termcap' y `terminfo' con argumentos idénticos.

El primer argumento especifica qué terminal(es) deben verse afectados por esta definición. Puede especificar varios nombres de terminal separándolos con '|'. Use `*' para coincidir con todos los terminales y `vt*' para coincidir con todos los terminales que comiencen con vt.

Cada argumento tweak contiene una o más definiciones de termcap (separadas por ':') que se insertarán al inicio de la entrada termcap apropiada, mejorándola o anulando los valores existentes. La primera modificación altera el termcap de su terminal y contiene definiciones que su terminal utiliza para realizar ciertas funciones. Especifique una cadena nula para dejar esto sin cambios (por ejemplo, ''). La segunda modificación (opcional) modifica todos los termcap de las ventanas y debe contener definiciones que screen entienda (ver la sección VIRTUAL TERMINAL). La segunda modificación (opcional) modifica todos los termcap de las ventanas, y debe contener definiciones que screen entienda (ver la sección VIRTUAL TERMINAL).

Algunos ejemplos:

termcap xterm* LP:hs@

Informa a screen que todos los terminales que comienzan con `xterm' tienen márgenes automáticos fijos que permiten actualizar la última posición en la pantalla (LP), pero que en realidad no tienen una línea de estado (no 'hs' - agregue '@' para desactivar las entradas). Tenga en cuenta que asumimos `LP' para todos los nombres de terminal que comienzan con vt, pero solo si no especifica un comando termcap para ese terminal.

termcap vt*  LP

termcap vt102|vt220 Z0=\E[?3h:Z1=\E[?3l

Especifica la capacidad `LP' de margen fijo para todos los terminales que comienzan con `vt', y la segunda línea también agregará las secuencias de escape para entrar (Z0) y salir (Z1) del modo de 132 caracteres por línea si se trata de un VT102 o VT220. (Debe especificar Z0 y Z1 en su termcap para usar los comandos de cambio de ancho).

termcap vt100 "" l0=PF1:l1=PF2:l2=PF3:l3=PF4

Esto deja su termcap vt100 intacto y agrega las etiquetas de las teclas de función a la entrada termcap de cada ventana.

termcap h19|z19 am@:im=\E@:ei=\EO dc=\E[P

Toma un termcap h19 o z19 y desactiva los márgenes automáticos (am@) y habilita las capacidades de modo de inserción (im) y fin de inserción (ei) (el '@' en la cadena 'im' está después del '=', por lo que es parte de la cadena). Al incluir las definiciones 'im' y 'ei' en el termcap de su terminal, screen anunciará automáticamente la capacidad de inserción de caracteres en el termcap de cada ventana. Cada ventana también recibirá la capacidad de eliminación de caracteres (dc) añadida a su termcap, que screen traducirá a una actualización de línea para el terminal (fingimos que no admite la eliminación de caracteres).

Si desea especificar completamente la entrada termcap de cada ventana, debería establecer la variable $SCREENCAP antes de ejecutar screen. Consulte la discusión sobre el VIRTUAL TERMINAL en este manual y la página man termcap(5)

page para más información sobre las definiciones de termcap.

LA LÍNEA DE MENSAJES

Screen muestra mensajes informativos y otros diagnósticos en una línea de mensajes. Si bien esta línea se distribuye para aparecer en la parte inferior de la pantalla, se puede definir para que aparezca en la parte superior de la pantalla durante la compilación. Si tu terminal tiene una línea de estado definida en su termcap, screen la usará para mostrar sus mensajes, de lo contrario, se sobrescribirá temporalmente una línea de la pantalla actual y la salida se interrumpirá momentáneamente. La línea de mensajes se elimina automáticamente después de unos segundos de retraso, pero también se puede eliminar antes (en terminales sin línea de estado) comenzando a escribir.

Una aplicación que se ejecuta en la ventana actual puede usar el sistema de línea de mensajes mediante la secuencia de control de mensaje de privacidad ANSI. Por ejemplo, desde el shell, intenta algo como:

echo '<esc>^Hello world from window '$WINDOW'<esc>\\'

donde '<esc>' es un escape, '^' es una flecha hacia arriba literal, y '\\' se convierte en una sola barra invertida.

TIPOS DE VENTANAS

Screen proporciona tres tipos diferentes de ventanas. Las nuevas ventanas se crean con el comando screen de screen (ver también la entrada en el capítulo PERSONALIZACIÓN). El primer parámetro del comando screen define qué tipo de ventana se crea. Los diferentes tipos de ventanas son todos casos especiales del tipo normal. Se han agregado para permitir que screen se utilice de manera eficiente como multiplexor de consola con 100 o más ventanas.

  • La ventana normal contiene un shell (por defecto, si no se proporciona ningún parámetro) o cualquier otro comando del sistema que se pueda ejecutar desde un shell (por ejemplo, slogin, etc.).
  • Si se especifica un nombre de tty (dispositivo de caracteres especiales) (por ejemplo, /dev/ttya) como primer parámetro, la ventana se conecta directamente a este dispositivo. Este tipo de ventana es similar a screen cu -l /dev/ttya. Se requiere acceso de lectura y escritura en el nodo del dispositivo, y se intenta una apertura exclusiva en el nodo para marcar la línea de conexión como ocupada. Se permite un parámetro opcional que consiste en una lista separada por comas de banderas en la notación utilizada por stty(1):
<baud_rate>
Generalmente 300, 1200, 9600 o 19200. Esto afecta la velocidad de transmisión y recepción.
cs8 o cs7
Especifica la transmisión de ocho (o siete) bits por byte.
cstopb o -cstopb
Especifica dos bits de parada por carácter (uno con '-')
parenb o -parenb
Genera bit de paridad en la salida y espera bit de paridad en la entrada
parodd o -parodd
Establece paridad impar (o paridad par con '-')
ixon o -ixon
Habilita (o deshabilita) el control de flujo por software (CTRL-S/CTRL-Q) para enviar datos.
ixoff o -ixoff
Habilita (o deshabilita) el control de flujo por software para recibir datos.
istrip o -istrip
Borra (o mantiene) el octavo bit en cada byte recibido.

Es posible que desees especificar tantas de estas opciones como sean aplicables. Las opciones no especificadas hacen que el controlador del terminal invente los valores de los parámetros de la conexión. Estos valores dependen del sistema y pueden ser predeterminados o valores guardados de una conexión anterior.

Para las ventanas tty, el comando info muestra algunas de las líneas de control del módem en la línea de estado. Estas pueden incluir 'RTS', 'CTS', 'DTR', 'DSR', 'CD' y más. Esto depende de los ioctl() disponibles y de los archivos de encabezado del sistema, así como de las capacidades físicas de la placa serie. Las señales que son lógicamente bajas (inactivas) tienen su nombre precedido por un signo de exclamación (!), de lo contrario, la señal es lógicamente alta (activa). Las señales no soportadas por el hardware pero disponibles para la interfaz ioctl() generalmente se muestran bajas.

Cuando el bit de estado CLOCAL es verdadero, todo el conjunto de señales del módem se coloca entre llaves ({ y }). Cuando se establece el bit CRTSCTS o TIOCSOFTCAR, las señales 'CTS' o 'CD' se muestran entre paréntesis, respectivamente.

Para las ventanas tty, el comando break hace que la línea de transmisión de datos (TxD) se ponga a nivel bajo durante un período de tiempo especificado. Se espera que esto se interprete como una señal de interrupción en el otro lado. No se envían datos ni se modifica ninguna línea de control del módem cuando se emite un break.

CONTROL DE FLUJO

Cada ventana tiene una configuración de control de flujo que determina cómo screen maneja los caracteres XON y XOFF (y posiblemente el carácter de interrupción). Cuando el control de flujo está desactivado, screen ignora los caracteres XON y XOFF, lo que permite al usuario enviarlos al programa actual simplemente escribiéndolos (útil para el editor emacs, por ejemplo). La desventaja es que tardará más en que la salida de un programa normal se detenga en respuesta a un XOFF. Con el control de flujo activado, los caracteres XON y XOFF se utilizan para pausar inmediatamente la salida de la ventana actual. Todavía puedes enviar estos caracteres al programa actual, pero debes usar los comandos de screen de dos caracteres apropiados (típicamente C-a q (xon) y C-a s (xoff)). Los comandos xon/xoff también son útiles para escribir C-s y C-q pasando un terminal que intercepta estos caracteres.

Cada ventana tiene un valor inicial de control de flujo establecido con la opción -f o el comando defflow .screenrc. Por defecto, las ventanas se establecen en cambio de flujo automático. Luego se puede alternar entre los tres estados 'fijo encendido', 'fijo apagado' y 'automático' interactivamente con el comando flow enlazado a "C-a f".

El modo de cambio de flujo automático maneja el control de flujo utilizando el modo TIOCPKT (como lo hace rlogin). Si el controlador tty no admite TIOCPKT, screen intenta averiguar el modo correcto según la configuración actual del teclado de aplicaciones: cuando está habilitado, el control de flujo se desactiva y viceversa. Por supuesto, todavía puedes manipular el control de flujo manualmente cuando sea necesario.

Si estás ejecutando con el control de flujo habilitado y descubres que presionar la tecla de interrupción (generalmente C-c) no interrumpe la visualización hasta que se desplazan 6-8 líneas más, intenta ejecutar screen con la opción de interrupción (agrega la bandera de interrupción al comando flow en tu .screenrc, o usa la opción de línea de comandos -i). Esto hace que se vacíe la salida que screen ha acumulado del programa interrumpido. Una desventaja es que la memoria del terminal virtual contiene la versión no vaciada de la salida, lo que en casos raros puede causar pequeñas imprecisiones en la salida. Por ejemplo, si cambias de pantalla y regresas, o actualizas la pantalla con C-a l, verás la versión de la salida que habrías obtenido sin interrupción. Además, es posible que necesites desactivar el control de flujo (o usar el modo automático para desactivarlo automáticamente) al ejecutar un programa que espera que ingreses el carácter de interrupción como entrada, ya que es posible interrumpir la salida del terminal virtual a tu terminal físico cuando el control de flujo está habilitado. Si esto sucede, un simple refresco de la pantalla con C-a l la restaurará. Prueba cada modo y usa el que te resulte más cómodo.

TÍTULOS (nombrar ventanas)

Puedes personalizar el nombre de cada ventana en la pantalla de ventanas (vista con el comando windows (C-a w)) estableciéndolo con uno de los comandos de título. Normalmente, el nombre que se muestra es el nombre real del comando del programa creado en la ventana. Sin embargo, a veces es útil distinguir varios programas del mismo nombre o cambiar el nombre sobre la marcha para reflejar el estado actual de la ventana.

El nombre predeterminado para todas las ventanas de shell se puede establecer con el comando shelltitle en el archivo .screenrc, mientras que todas las demás ventanas se crean con un comando screen y, por lo tanto, pueden tener su nombre establecido con la opción -t. De forma interactiva, existe la secuencia de escape título-cadena (<esc>knombre<esc>\) y el comando title (C-a A). La primera puede ser emitida por una aplicación para controlar el nombre de la ventana bajo control de software, y la segunda solicitará un nombre al ser escrita. También puedes enlazar nombres predefinidos a teclas con el comando title para establecer cosas rápidamente sin pedir confirmación. Cambiar el título mediante esta secuencia de escape puede ser controlado por los comandos defdynamictitle y dynamictitle.

HEURÍSTICA_ESPECÍFICA_DEL_SHELL

Finalmente, screen tiene una heurística específica del shell que se habilita estableciendo el nombre de la ventana a search|name y organizando la salida de una secuencia de escape de título nula como parte de su prompt. La porción search especifica una cadena de búsqueda de fin de prompt, mientras que la porción name especifica el nombre de shell predeterminado para la ventana. Si name termina en dos puntos (`:'), screen agregará lo que cree que es el comando actual que se ejecuta en la ventana al final del nombre de shell de la ventana (por ejemplo, name:cmd). De lo contrario, el nombre del comando actual reemplazará el nombre del shell mientras se esté ejecutando.

Así es como funciona: debe modificar su prompt de shell para que salga una secuencia de escape de título nula (<esc>k<esc>\) como parte de su prompt. La última parte de su prompt debe ser la misma que la cadena que especificó para la porción search del título. Una vez que esto esté configurado, screen usará la secuencia de escape de título para borrar el nombre del comando anterior y prepararse para el próximo comando. Luego, cuando se reciba un salto de línea del shell, se buscará el final del prompt. Si se encuentra, tomará la primera palabra después de la cadena coincidente y la usará como nombre del comando. Si el nombre del comando comienza con '!', '%' o '^', screen usará la primera palabra de la siguiente línea (si se encuentra) en lugar del nombre recién encontrado. Esto ayuda a los usuarios de csh a obtener mejores nombres de comando cuando usan control de trabajos o comandos de recuperación de historial.

Aquí hay algunos ejemplos de .screenrc:

screen -t top 2 nice top

Agregar esta línea a su .screenrc iniciaría una versión "nice" del comando top en la ventana 2 llamada top en lugar de nice.

shelltitle '> |csh'
screen 1

Estos comandos iniciarían un shell con el shelltitle dado. El título especificado es un título automático que esperaría que el prompt y el comando escrito se parezcan a lo siguiente:

/usr/joe/src/dir> trn

(busca después del '> ' el nombre del comando). El estado de la ventana mostraría el nombre trn mientras se ejecuta el comando, y volvería a csh al completarse.

bind R screen -t '% |root:' su

Tener este comando en su .screenrc vincularía la secuencia de teclas C-a R al comando su y le daría un nombre de título automático de root:. Para que este título automático funcione, la pantalla podría parecerse a esto:

% !em
emacs file.c

Aquí el usuario escribió el comando de historial de csh !em, que ejecutó el comando emacs ingresado previamente. El estado de la ventana mostraría root:emacs durante la ejecución del comando, y volvería a ser simplemente root: al completarse.

bind o title
bind E title ""
bind u title (unknown)

La primera vinculación no tiene argumentos, por lo que le pedirá un título cuando escriba C-a o. La segunda vinculación borrará la configuración actual de un título automático (C-a E). La tercera vinculación establecerá el título de la ventana actual en (unknown) (C-a u).

Una cosa a tener en cuenta al agregar una secuencia de escape de título nula a su prompt es que algunos shells (como csh) cuentan todos los caracteres no de control como parte de la longitud del prompt. Si estos caracteres invisibles no son un múltiplo de 8, retroceder sobre una tabulación resultará en una visualización incorrecta. Una forma de solucionar esto es usar un prompt como este:

set prompt='^[[0000m^[k^[\% '

La secuencia de escape <esc>[0000m no solo normaliza los atributos del carácter, sino que todos los ceros redondean la longitud de los caracteres invisibles a 8. Los usuarios de Bash probablemente querrán hacer "echo" de la secuencia de escape en PROMPT_COMMAND:

PROMPT_COMMAND='printf "\033k\033\134"'

(Usé \134 para generar una `\' debido a un error en bash v1.04).

LA_TERMINAL_VIRTUAL

Cada ventana en una sesión de screen emula una terminal VT100, con algunas funciones adicionales agregadas. El emulador VT100 está codificado, no se pueden emular otros tipos de terminales.
Por lo general, screen intenta emular la mayor parte posible del estándar VT100/ANSI. Pero si su terminal carece de ciertas capacidades, la emulación puede no ser completa. En estos casos, screen tiene que informar a las aplicaciones que faltan algunas de las funciones. Esto no es un problema en máquinas que usan termcap, porque screen puede usar la variable $TERMCAP para personalizar el termcap estándar de screen.

Pero si hace un rlogin en otra máquina o su máquina solo admite terminfo, este método falla. Debido a esto, screen ofrece una forma de lidiar con estos casos. Así es como funciona:

Cuando screen intenta determinar un nombre de terminal para sí mismo, primero busca una entrada llamada screen.<term>, donde <term> es el contenido de su variable $TERM. Si no existe tal entrada, screen intenta screen (o screen-w si la terminal es ancha (132 columnas o más)). Si incluso esta entrada no se puede encontrar, se usa vt100 como sustituto.

La idea es que si tiene una terminal que no admite una función importante (por ejemplo, eliminar carácter o limpiar hasta el final de la pantalla), puede crear una nueva entrada termcap/terminfo para screen (llamada screen.<dumbterm>) en la que se haya deshabilitado esta capacidad. Si esta entrada está instalada en sus máquinas, puede hacer un rlogin y aún mantener la entrada termcap/terminfo correcta. El nombre de la terminal se coloca en la variable $TERM de todas las ventanas nuevas. Screen también establece la variable $TERMCAP que refleja las capacidades de la terminal virtual emulada. Tenga en cuenta que, sin embargo, en máquinas que utilizan la base de datos terminfo, esta variable no tiene efecto. Además, la variable $WINDOW se establece en el número de ventana de cada ventana.

El conjunto real de capacidades admitidas por la terminal virtual depende de las capacidades admitidas por la terminal física. Si, por ejemplo, la terminal física no admite el modo de subrayado, screen no coloca las capacidades `us' y `ue' en la variable $TERMCAP de la ventana, correspondientemente. Sin embargo, se debe admitir un número mínimo de capacidades para ejecutar screen; a saber, desplazamiento, limpieza de pantalla y direccionamiento directo del cursor (además, screen no se ejecuta en terminales de impresión o en terminales que se sobrescriben).

Además, puede personalizar el valor de $TERMCAP utilizado por screen utilizando el comando .screenrc de termcap, o definiendo la variable $SCREENCAP antes del inicio. Cuando esta última está definida, su valor se copiará textualmente en la variable $TERMCAP de cada ventana. Esto puede ser la definición completa de la terminal, o un nombre de archivo donde se define la pantalla de la terminal (y/o screen-w).

Tenga en cuenta que screen respeta el comando .screenrc de terminfo si el sistema utiliza la base de datos terminfo en lugar de termcap.

Cuando la capacidad booleana `G0' está presente en la entrada termcap para la terminal en la que se ha llamado screen, la emulación de terminal de screen admite varios conjuntos de caracteres. Esto permite que una aplicación utilice, por ejemplo, el conjunto de caracteres gráficos VT100 o los conjuntos de caracteres nacionales. Se admiten las siguientes funciones de control de ISO 2022: lock shift G0 (SI), lock shift G1 (SO), lock shift G2, lock shift G3, single shift G2 y single shift G3. Cuando se crea o se restablece una terminal virtual, el conjunto de caracteres ASCII se designa como G0 a G3. Cuando está presente la capacidad `G0', screen evalúa las capacidades `S0', `E0' y `C0' si están presentes. `S0' es la secuencia que la terminal utiliza para habilitar e iniciar el conjunto de caracteres gráficos en lugar de SI. `E0' es el reemplazo correspondiente para SO. `C0' proporciona una cadena de traducción carácter por carácter que se utiliza durante el modo semigráfico. Esta cadena se construye como la capacidad terminfo `acsc'.

Cuando las capacidades `po' y `pf' están presentes en la entrada termcap de la terminal, las aplicaciones que se ejecutan en una ventana de screen pueden enviar salida al puerto de la impresora de la terminal. Esto permite que un usuario tenga una aplicación en una ventana enviando salida a una impresora conectada a la terminal, mientras que todas las demás ventanas siguen activas (el puerto de la impresora se habilita y deshabilita nuevamente para cada bloque de salida). Como efecto secundario, los programas que se ejecutan en diferentes ventanas pueden enviar salida a la impresora simultáneamente. Los datos enviados a la impresora no se muestran en la ventana. El comando info muestra una línea que comienza con `PRIN' mientras la impresora está activa.

Screen mantiene una línea de estado duro para cada ventana. Si se selecciona una ventana, el estado duro de la pantalla se actualizará para que coincida con la línea de estado duro de la ventana. Si la pantalla no tiene estado duro, la línea se mostrará como un mensaje estándar de screen. La línea de estado duro se puede cambiar con el Comando de Programa de Aplicación ANSI (APC): ESC_<cadena>ESC\. Como conveniencia para los usuarios de xterm, también se acepta la secuencia ESC]0..2;<cadena>^G.

Algunas capacidades solo se colocan en la variable $TERMCAP de la terminal virtual si se pueden implementar de manera eficiente en la terminal física. Por ejemplo, `dl' (eliminar línea) solo se coloca en la variable $TERMCAP si la terminal admite la eliminación de línea en sí misma o las regiones de desplazamiento. Tenga en cuenta que esto puede provocar confusión, cuando la sesión se reasocia en una terminal diferente, ya que el valor de $TERMCAP no puede ser modificado por procesos padres.

La capacidad de "pantalla alternativa" no está habilitada por defecto. Establezca el comando altscreen .screenrc para habilitarla.

TRADUCCION DE ENTRADA

Para lograr una emulación VT100 completa, screen tiene que detectar que una secuencia de caracteres en el flujo de entrada fue generada por una pulsación de tecla en el teclado del usuario e insertar la secuencia de escape estilo VT100. Screen tiene una forma muy flexible de hacer esto al permitir mapear comandos arbitrarios a secuencias de caracteres arbitrarias. Para la emulación VT100 estándar, el comando siempre insertará una cadena en el búfer de entrada de la ventana (ver también el comando stuff en la tabla de comandos). Debido a que las secuencias generadas por una pulsación de tecla pueden cambiar después de una reconexión desde un tipo de terminal diferente, es posible vincular comandos al nombre termcap de las teclas. Screen insertará la vinculación correcta después de cada reconexión. Ver el comando bindkey para más detalles sobre la sintaxis y ejemplos.

TRADUCCION DE CARACTERES

Screen tiene un potente mecanismo para traducir caracteres a cadenas arbitrarias dependiendo del tipo de terminal y fuente actual. Utilice esta función si desea trabajar con un conjunto de caracteres estándar común (por ejemplo, ISO8851-latin1) incluso en terminales que distribuyen los caracteres más inusuales en varias páginas de fuentes de idiomas nacionales.

Sintaxis:

    XC=<mapeo-juego-caracteres>{,,<mapeo-juego-caracteres>}
    <mapeo-juego-caracteres> := <designador><plantilla>{,<mapeo>}
    <mapeo> := <caracter-a-mapear><argumento-plantilla>

Los elementos entre llaves pueden repetirse cualquier número de veces.

Un <mapeo-juego-caracteres> le dice a screen cómo mapear caracteres de la fuente <designador> ('B': Ascii, 'A': Reino Unido, 'K': Alemán, etc.) a cadenas. Cada <mapeo> describe a qué cadena se traducirá un solo carácter. Se utiliza un mecanismo de plantilla, ya que la mayoría de las veces los códigos tienen mucho en común (por ejemplo, cadenas para cambiar a y desde otro juego de caracteres). Cada aparición de '%' en <plantilla> se sustituye por el <argumento-plantilla> especificado junto con el carácter. Si sus cadenas no son similares en absoluto, use '%' como plantilla y coloque la cadena completa en <argumento-plantilla>. Un mecanismo de escap

TERMCAP

anism was added to make it possible to use a real '%'. The '\' character quotes the special characters '\', '%', and ','.

Here is an example:


termcap hp700 'XC=B\E(K%\E(B,\304[,\326\\\\,\334]'

This tells screen how to translate ISOlatin1 (charset 'B') upper case umlaut characters on a hp700 terminal that has a German charset. '\304' gets translated to '\E(K[\E(B' and so on. Note that this line gets parsed *three* times before the internal lookup table is built, therefore a lot of quoting is needed to create a single '\'.

Another extension was added to allow more emulation: If a mapping translates the unquoted '%' char, it will be sent to the terminal whenever screen switches to the corresponding <designator>. In this special case the template is assumed to be just '%' because the charset switch sequence and the character mappings normally haven't much in common.

This example shows one use of the extension:


termcap xterm 'XC=K%,%\E(B,[\304,\\\\\326,]\334'

Here, a part of the German ('K') charset is emulated on an xterm. If screen has to change to the 'K' charset, '\E(B' will be sent to the terminal, i.e. the ASCII charset is used instead. The template is just '%', so the mapping is straightforward: '[' to '\304', '\' to '\326', and ']' to '\334'.

ERRORES

  • `dm' (modo de borrado) y `xs' no se manejan correctamente (se ignoran). `xn' se trata como un indicador de margen mágico.
  • Screen no tiene ni idea de caracteres de doble altura o doble anchura. Pero esta es la única área donde se permite que vttest falle.
  • No es posible cambiar la variable de entorno $TERMCAP al volver a adjuntarse con un tipo de terminal diferente.
  • El soporte de sistemas basados en terminfo es muy limitado. Añadir capacidades extra a $TERMCAP puede no tener ningún efecto.
  • Screen no utiliza tabulaciones de hardware.
  • Screen debe instalarse como set-uid con propietario root en la mayoría de los sistemas para poder cambiar correctamente el propietario del archivo de dispositivo tty para cada ventana. También pueden ser necesarios permisos especiales para escribir en el archivo /etc/utmp.
  • Las entradas en /etc/utmp no se eliminan cuando screen se mata con SIGKILL. Esto hará que algunos programas (como "w" o "rwho") anuncien que un usuario está conectado cuando realmente no lo está.
  • Screen puede dar una advertencia extraña cuando tu tty no tiene una entrada utmp.
  • Cuando se colgaba la línea del módem, screen puede no desadjuntarse (o salir) automáticamente a menos que el controlador del dispositivo esté configurado para enviar una señal HANGUP. Para desadjuntar una sesión de screen, utiliza la opción de línea de comandos -D o -d.
  • Tanto breaktype como defbreaktype cambian el método de generación de rupturas utilizado por todos los dispositivos de terminal. El primero debería cambiar una configuración específica de la ventana, mientras que el segundo debería cambiar solo el valor predeterminado para las nuevas ventanas.
  • Al adjuntarse a una sesión multiusuario, el archivo .screenrc del usuario no se procesa. La configuración personal de cada usuario debe incluirse en el archivo .screenrc desde el que se inicia la sesión, o debe cambiarse manualmente.
  • Se necesita una imaginación extraña para sacar el máximo provecho de todas las características.
