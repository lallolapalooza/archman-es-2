NOMBRE

schroot.conf - archivo de definición de chroot para schroot

DESCRIPCIÓN

schroot.conf es un archivo de texto plano en UTF-8, que describe los chroots disponibles para su uso con schroot.

Los comentarios se introducen después de un carácter ‘#’ (hash) al principio de una línea, o después de cualquier otro texto. Todo el texto a la derecha del ‘#’ se trata como un comentario.

El formato de configuración es un estilo INI, dividido en grupos de pares clave-valor separados por nombres de sección entre corchetes.

Opciones generales

Un chroot se define como un grupo de pares clave-valor, que comienza con un nombre entre corchetes en una línea aparte. El archivo puede contener múltiples grupos que, por lo tanto, definen múltiples chroots.

Una definición de chroot comienza con el nombre del chroot entre corchetes. Por ejemplo,

[sid]

El nombre está sujeto a ciertas restricciones de nomenclatura. Para más detalles, véase la sección “Nombres de Chroot” abajo.

Esto va seguido de varios pares clave-valor, uno por línea:

type=tipo
El tipo de chroot. Los tipos válidos son ‘plain’, ‘directory’, ‘file’, ‘loopback’, ‘block-device’, ‘btrfs-snapshot’, ‘zfs-snapshot’ y ‘lvm-snapshot’. Si está vacío u omitido, el tipo predeterminado es ‘plain’. Tenga en cuenta que los chroots ‘plain’ no ejecutan scripts de configuración ni montan sistemas de archivos; se recomienda ‘directory’ para uso normal (véase “Chroots plainly y directory”, abajo).
description=descripción
Una breve descripción del chroot. Esto puede estar localizado para diferentes idiomas; véase la sección “Localización” abajo.
priority=número
Establece la prioridad de un chroot. número es un entero positivo que indica si una distribución es más antigua que otra. Por ejemplo, “oldstable” y “oldstable-security” podrían ser ‘0’, mientras que “stable” y “stable-security” son ‘1’, “testing” es ‘2’ y “unstable” es ‘3’. Los valores no son importantes, pero la diferencia entre ellos sí lo es. Esta opción está obsoleta y ya no la utiliza schroot, pero todavía se permite su uso; se obviará y eliminará en una versión futura.
message-verbosity=verbosity
Establece la verbosidad de los mensajes impresos por schroot al configurar, ejecutar comandos y limpiar el chroot. Los ajustes válidos son ‘quiet’ (suprimir la mayoría de los mensajes), ‘normal’ (el predeterminado) y ‘verbose’ (mostrar todos los mensajes). Este ajuste se ve anulado por las opciones --quiet y --verbose.
users=usuario1,usuario2,...
Una lista separada por comas de usuarios que tienen permitido el acceso al chroot. Si está vacío u omitido, ningún usuario tendrá permitido el acceso (a menos que un grupo al que pertenezcan también se especifique en groups).
groups=grupo1,grupo2,...
Una lista separada por comas de grupos que tienen permitido el acceso al chroot. Si está vacío u omitido, ningún grupo de usuarios tendrá permitido el acceso.
root-users=usuario1,usuario2,...
Una lista separada por comas de usuarios que tienen permitido el acceso a root sin contraseña al chroot. Si está vacío u omitido, ningún usuario tendrá permitido el acceso root sin contraseña (pero si un usuario o un grupo al que pertenezca está en users o groups, respectivamente, pueden obtener acceso con contraseña). Véase la sección “Seguridad” abajo.
root-groups=grupo1,grupo2,...
Una lista separada por comas de grupos que tienen permitido el acceso a root sin contraseña al chroot. Si está vacío u omitido, ningún usuario tendrá permitido el acceso root sin contraseña (pero si un usuario o un grupo al que pertenezca está en users o groups, respectivamente, pueden obtener acceso con contraseña). Véase la sección “Seguridad” abajo.
aliases=alias1,alias2,...
Una lista separada por comas de alias (nombres alternativos) para este chroot. Por ejemplo, un chroot llamado “sid” podría tener un alias ‘unstable’ por conveniencia. Los alias están sujetos a las mismas restricciones de nomenclatura que el propio nombre del chroot.
profile=directorio
script-config=nombre_archivo
El comportamiento de los scripts de configuración del chroot puede ser personalizado por chroot estableciendo un perfil de configuración específico. El directorio es relativo a /etc/schroot. El predeterminado es ‘default’. Los archivos en este directorio son referenciados por los scripts de configuración, y por lo tanto su comportamiento puede ser personalizado seleccionando el perfil apropiado. Las alternativas son ‘minimal’ (configuración mínima), ‘desktop’ (para ejecutar aplicaciones de escritorio en el chroot, haciendo más funcionalidad del sistema anfitrión disponible en el chroot) y ‘sbuild’ (para usar el chroot para la compilación de paquetes Debian). Otros paquetes pueden proporcionar perfiles adicionales. Los valores predeterminados de las claves setup.config, setup.copyfiles, setup.fstab y setup.nssdatabases se basan en el ajuste de profile.
Tenga en cuenta que la clave profile reemplaza a la clave más antigua script-config. La clave script-config es exactamente la misma que profile, pero tiene “/config” añadido. El nombre de archivo predeterminado es ‘default/config’. Cualquiera de estas claves puede ser utilizada. Si ambas están presentes, entonces script-config tendrá precedencia (profile se anulará). script-config está obsoleto y se eliminará en una versión futura. Tenga en cuenta que profile es equivalente a script-config si el archivo referenciado por script-config solo contiene las variables estándar proporcionadas por schroot; si se han añadido variables o fragmentos de script shell adicionales, establezca también setup.config, que seguirá permitiendo que este archivo sea referenciado. Se recomienda reemplazar el uso del archivo referenciado con claves adicionales en schroot.conf siempre que sea posible, pero seguirá siendo posible referenciar un archivo de configuración adicional usando setup.config.
Los usuarios de escritorio deben tener en cuenta que el archivo fstab desktop/fstab deberá ser editado si se usa gdm3; por favor, consulte los comentarios en este archivo para obtener instrucciones adicionales. La clave preserve-environment también debe establecerse en ‘true’ para que el entorno se preserve dentro del chroot.
Si ninguno de los perfiles de configuración proporcionados anteriormente satisface sus necesidades, entonces pueden ser editados para personalizarlos aún más, y/o copiados y usados como plantilla para perfiles completamente nuevos.
Tenga en cuenta que los diferentes perfiles tienen implicaciones de seguridad diferentes; véase la sección “Seguridad” abajo para más detalles.
setup.config=nombre_archivo
Esta clave especifica un archivo que los scripts de configuración referenciarán cuando se ejecuten. Por defecto, tiene el mismo valor que el establecido por script-config. El archivo es un script de shell Bourne

SCHROOT_PROFILES

Schroot profile configuration files

Description

Schroot supports a number of different chroot types, each with its own specific configuration options. The type of chroot is specified using the type= option within the chroot definition in schroot.conf.

The following chroot types are supported:

  • ‘plain’
  • ‘directory’
  • ‘file’
  • ‘loopback’
  • ‘block-device’
  • ‘btrfs-snapshot’
  • ‘lvm-snapshot’
  • ‘directory-union’
  • ‘binary’

In addition to the type-specific options, all chroots support a common set of options that control various aspects of the chroot environment.

Common options

type=type
Specifies the type of chroot. This option is mandatory. See the following sections for a description of the supported chroot types.
description=text
A short descriptive text for the chroot. This is used in the output of the schroot -l command.
groups=group1,group2,...
A comma-separated list of supplementary groups that the chroot will be made a member of. The default is to be made a member of the user's primary group and any groups specified in the /etc/group file. This option is only applicable to non-root users.
root-groups=group1,group2,...
A comma-separated list of supplementary groups that the chroot will be made a member of when run as root. The default is to be made a member of the user's primary group and any groups specified in the /etc/group file.
root-users=user1,user2,...
A comma-separated list of users that are allowed to become root inside the chroot. If this option is not specified, then only the real root user is allowed to become root inside the chroot. This option is only applicable to non-root users.
users=user1,user2,...
A comma-separated list of users that are allowed to enter the chroot. If this option is not specified, then all users are allowed to enter the chroot. This option is only applicable to non-root users.
script-wrapper=script
A script that will be executed before any chroot command or login shell is executed. The script will be executed with root privileges. This allows for runtime configuration of the chroot, for example, by setting up filesystems or modifying configuration files. Note that the script will be sourced in the current shell, and in consequence may contain any valid shell code, in addition to simple variable assignments. This will, for example, allow behaviour to be customised according to the specific chroot type or name. Note that the script will be sourced once for each and every script invocation, and must be idempotent.
All the default settings in this file are now settable using configuration keys in schroot.conf, as detailed below. Existing configurations should be modified to use these keys in place of this file. See schroot-script-config(5) for further details. This type of setup script configuration file is no longer provided as part of the standard profiles, but will continue to be sourced if present and this key is set.
setup.copyfiles=filename
A file containing a list of files to copy into the chroot (one file per line). The file will have the same absolute location inside the chroot.
setup.fstab=filename
The filesystem table file to be used to mount filesystems within the chroot. The format of this file is the same as for /etc/fstab, documented in fstab(5). The only difference is that the mountpoint path fs_dir is relative to the chroot, rather than the root. Also note that mountpoints are canonicalised on the host, which will ensure that absolute symlinks point inside the chroot, but complex paths containing multiple symlinks may be resolved incorrectly; it is inadvisable to use nested symlinks as mountpoints.
setup.nssdatabases=filename
A file listing the system databases to copy into the chroot. The default databases are ‘passwd’, ‘shadow’, ‘group’ and ‘gshadow’. Other potential databases which could be added include ‘services’, ‘protocols’, ‘networks’, and ‘hosts’. The databases are copied using getent(1) so all database sources listed in /etc/nsswitch.conf will be used for each database.
setup.services=service1,service2,...
A comma-separated list of services to run in the chroot. These will be started when the session is started, and stopped when the session is ended.
command-prefix=command,option1,option2,...
A comma-separated list of a command and the options for the command. This command and its options will be prefixed to all commands run inside the chroot. This is useful for adding commands such as nice, ionice or eatmydata for all commands run inside the chroot. nice and ionice will affect CPU and I/O scheduling. eatmydata ignores filesystem fsync operations, and is useful for throwaway snapshot chroots where you don't care about dataloss, but do care about high speed.
personality=persona
Set the personality (process execution domain) to use. This option is useful when using a 32-bit chroot on 64-bit system, for example. Valid options on Linux are ‘bsd’, ‘hpux’, ‘irix32’, ‘irix64’, ‘irixn32’, ‘iscr4’, ‘linux’, ‘linux32’, ‘linux_32bit’, ‘osf4’, ‘osr5’, ‘riscos’, ‘scorvr3’, ‘solaris’, ‘sunos’, ‘svr4’, ‘uw7’, ‘wysev386’, and ‘xenix’. The default value is ‘linux’. There is also the special option ‘undefined’ (personality not set). For a 32-bit chroot on a 64-bit system, ‘linux32’ is the option required. The only valid option for non-Linux systems is ‘undefined’. The default value for non-Linux systems is ‘undefined’.
preserve-environment=true|false
By default, the environment will not be preserved inside the chroot, instead a minimal environment will be used. Set to true to always preserve the environment. This is useful for example when running X applications inside the chroot, which need the environment to function correctly. The environment may also be preserved using the --preserve-environment option.
shell=shell
When running a login shell a number of potential shells will be considered, in this order: the command in the SHELL environment variable (if --preserve-environment is used, or preserve-environment is enabled), the user's shell in the ‘passwd’ database, /bin/bash and finally /bin/sh. This setting overrides this list, and will use the shell specified. It may be overridden using the --shell option.
environment-filter=regex
The environment to be set in the chroot will be filtered in order to remove environment variables which may pose a security risk. Any environment variable matching the specified POSIX extended regular expression will be removed prior to executing any command in the chroot.
Potentially dangerous environment variables are removed for safety by default using the following regular expression: “^(BASH_ENV|CDPATH|ENV|HOSTALIASES|IFS|KRB5_CONFIG|KRBCONFDIR|KRBTKFILE|KRB_CONF|LD_.*|LOCALDOMAIN|NLSPATH|PATH_LOCALE|RES_OPTIONS|TERMINFO|TERMINFO_DIRS|TERMPATH)$”.

Plain and directory chroots

Chroots of type ‘plain’ or ‘directory’ are directories accessible in the filesystem. The two types are equivalent except for the fact that directory chroots run setup scripts, whereas plain chroots do not. In consequence, filesystems such as /proc are not mounted in plain chroots; it is the responsibility of the system administrator to configure such chroots by hand, whereas directory chroots are automatically configured. Additionally, directory chroots implement the filesystem union chroot options (see “Filesystem Union chroot options”, below).

These chroot types have an additional (mandatory) configuration option:

directory=directory
The directory containing the chroot environment. This is where the root will be changed to when executing a login shell or a command. The directory must exist and have read and execute permissions to allow users access to it. Note that on Linux systems it will be bind-mounted elsewhere for use as a chroot; the directory for ‘plain’ chroots is mounted with the --rbind option to mount(8), while for ‘directory’ chroots --bind is used instead so that sub-mounts are not preserved (they should be set in the fstab file just like in /etc/fstab on the host).

File chroots

Chroots of type ‘file’ are files on the current filesystem containing an archive of the chroot files. They implement the source chroot options (see “Source chroot options”, below). Note that a corresponding source chroot (of type ‘file’) will be created for each chroot of this type; this is for convenient access to the source archive, e.g. for the purpose of updating. These additional options are also implemented:

file=filename
The file containing the archived chroot environment (mandatory). This must be a tar (tape archive), optionally compressed with gzip, bzip2, xz, lzop or lz4. The file extensions used to determine the type are .tar, .tar.gz, .tar.bz2, .tar.xz, .tar.lzop, .tar.lz4, .tgz, .tbz, .txz, .tzo and .tlz4. This file must be owned by the root user, and not be writable by other. Note that zip archives are no longer supported; zip was not able to archive named pipes and device nodes, so was not suitable for archiving chroots.
location=path
This is the path to the chroot inside the archive. For example, if the archive contains a chroot in /squeeze, you would specify “/squeeze” here. If the chroot is the only thing in the archive, i.e. / is the root filesystem for the chroot, this option should be left blank, or omitted entirely.

Loopback chroots

Chroots of type ‘loopback’ are a filesystem available as a file on disk, accessed via a loopback mount. The file will be loopback mounted and unmounted on demand. Loopback chroots implement the mountable chroot and filesystem union chroot options (see “Mountable chroot options” and “Filesystem Union chroot options”, below), plus an additional option:

file=filename
This is the filename of the file containing the filesystem, including the absolute path. For example “/srv/chroot/sid”.

Block device chroots

Chroots of type ‘block-device’ are a filesystem available on an unmounted block device. The device will be mounted and unmounted on demand. Block device chroots implement the mountable chroot and filesystem union chroot options (see “Mountable chroot options” and “Filesystem Union chroot options”, below), plus an additional option:

device=device
This is the device name of the block device, including the absolute path. For example, “/dev/sda5”.

Btrfs snapshot chroots

Chroots of type ‘btrfs-snapshot’ are a Btrfs snapshot created from an existing Btrfs subvolume on a mounted Btrfs filesystem. A snapshot will be created from this sourc

chroot de subvolumen bajo demanda al inicio de una sesión, y luego la instantánea se montará. Al final de la sesión, la instantánea se desmontará y eliminará. Este tipo de chroot implementa las opciones de fuente chroot (ver "Opciones de chroot de origen", más abajo). Tenga en cuenta que se creará un chroot de origen correspondiente (de tipo 'directorio') para cada chroot de este tipo; esto es para un acceso conveniente al volumen de origen. También se implementan estas opciones adicionales:
btrfs-source-subvolume=directorio
El directorio que contiene el subvolumen de origen.
btrfs-snapshot-directory=directorio
El directorio en el que se almacenarán las instantáneas del subvolumen de origen anterior.

chroots de instantáneas ZFS

Los chroots de tipo 'zfs-snapshot' son una clonación ZFS creada a partir de un conjunto de datos ZFS existente. Se creará una instantánea y una clonación de este subvolumen de origen bajo demanda al inicio de una sesión, y luego la clonación se montará. Al final de la sesión, la clonación se desmontará y la clonación y la instantánea se eliminarán. Este tipo de chroot implementa las opciones de chroot de origen (ver "Opciones de chroot de origen", más abajo). Tenga en cuenta que se creará un chroot de origen correspondiente (de tipo 'directorio') para cada chroot de este tipo; esto es para un acceso conveniente al volumen de origen. También se implementan estas opciones adicionales:

zfs-dataset=nombre_dataset
Nombre del conjunto de datos ZFS de origen a utilizar.
zfs-snapshot-options=opciones_instantanea
Opciones de instantánea. Estas son opciones adicionales para pasar a zfs snapshot.

chroots de instantáneas LVM

Los chroots de tipo 'lvm-snapshot' son un sistema de archivos disponible en un volumen lógico (LV) de LVM. Se creará un LV de instantánea a partir de este LV bajo demanda, y luego la instantánea se montará. Al final de la sesión, el LV de instantánea se desmontará y eliminará.

Los chroots de instantáneas LVM implementan las opciones de chroot de origen (ver "Opciones de chroot de origen", más abajo), y todas las opciones para 'block-device'. Tenga en cuenta que se creará un chroot de origen correspondiente (de tipo 'block-device') para cada chroot de este tipo; esto es para un acceso conveniente al dispositivo de origen. También se implementa esta opción adicional:

lvm-snapshot-options=opciones_instantanea
Opciones de instantánea. Estas son opciones adicionales para pasar a lvcreate(8). Por ejemplo, "-L 2g" para crear una instantánea de 2 GiB de tamaño. Nota: el nombre del LV (-n), la opción de instantánea (-s) y la ruta del LV original no se pueden especificar aquí; son establecidos automáticamente por schroot.

chroots personalizados

Los chroots de tipo 'custom' son un tipo especial de chroot, utilizado para implementar nuevos tipos de chroot no soportados por ninguno de los tipos de chroot anteriores. Esto puede ser útil para implementar y probar un nuevo tipo de chroot sin necesidad de escribir código C++. Sin embargo, necesitará escribir su propio script de configuración para realizar el trabajo de configuración, ya que por sí mismo este tipo de chroot hace muy poco. También necesitará añadir claves personalizadas a su definición de chroot para usarlas en el script de configuración; a diferencia de la configuración para los tipos de chroot anteriores, no se realizará ninguna validación de las opciones a menos que la haga usted mismo en su script de configuración personalizado. También se implementan estas opciones adicionales:

custom-session-cloneable=true|false
Establece si las sesiones pueden clonarse o no utilizando este chroot (habilitado por defecto).
custom-session-purgeable=true|false
Establece si las sesiones pueden ser purgadas o no utilizando este chroot (deshabilitado por defecto).
custom-source-cloneable=true|false
Establece si los chroots de origen pueden clonarse o no utilizando este chroot (deshabilitado por defecto).

Opciones de chroot de origen

Los tipos de chroot 'btrfs-snapshot', 'file' y 'lvm-snapshot' implementan chroots de origen. Además, los tipos de chroot con soporte de unión habilitado implementan chroots de origen (ver "Opciones de chroot de unión de sistemas de archivos", más abajo). Estos son chroots que crean automáticamente una copia de sí mismos antes de su uso y generalmente se gestionan por sesión. Estos chroots proporcionan adicionalmente un chroot extra en el espacio de nombres source:, para permitir un acceso conveniente a los datos originales (no instantaneados) y para ayudar en el mantenimiento del chroot. Es decir, para un chroot llamado wheezy (chroot:wheezy), se creará un source:wheezy correspondiente. Para compatibilidad con versiones anteriores de schroot que no soportaban espacios de nombres, se creará además un chroot con el sufijo -source añadido al nombre del chroot (es decir, wheezy-source usando el ejemplo anterior). Tenga en cuenta que estos nombres de compatibilidad se eliminarán en schroot 1.5.0, por lo que se prefiere el uso del espacio de nombres source: sobre el uso del sufijo -source. Ver schroot(1) para más detalles.

Estos chroots proporcionan las siguientes opciones adicionales:

source-clone=true|false
Establece si el chroot de origen debe ser clonado (creado) automáticamente para este chroot. El valor predeterminado es true para clonar automáticamente, pero si se desea puede deshabilitarse estableciéndolo a false. Si se deshabilita, el chroot de origen será inaccesible.
source-users=usuario1,usuario2,...
Una lista separada por comas de usuarios a los que se les permite el acceso al chroot de origen. Si está vacía o se omite, ningún usuario tendrá acceso. Esto se convertirá en la opción users en el chroot de origen.
source-groups=grupo1,grupo2,...
Una lista separada por comas de grupos a los que se les permite el acceso al chroot de origen. Si está vacía o se omite, ningún usuario tendrá acceso. Esto se convertirá en la opción groups en el chroot de origen.
source-root-users=usuario1,usuario2,...
Una lista separada por comas de usuarios a los que se les permite el acceso root sin contraseña al chroot de origen. Si está vacía u omitida, ningún usuario tendrá acceso root sin contraseña (pero si un usuario está en users, puede obtener acceso con contraseña). Esto se convertirá en la opción root-users en el chroot de origen. Ver la sección "Seguridad" más abajo.
source-root-groups=grupo1,grupo2,...
Una lista separada por comas de grupos a los que se les permite el acceso root sin contraseña al chroot de origen. Si está vacía u omitida, ningún usuario tendrá acceso root sin contraseña (pero si el grupo de un usuario está en groups, puede obtener acceso con contraseña). Esto se convertirá en la opción root-groups en el chroot de origen. Ver la sección "Seguridad" más abajo.

Opciones de chroot montables

Los tipos de chroot 'block-device', 'loopback' y 'lvm-snapshot' implementan el montaje de dispositivos. Estos son chroots que requieren el montaje de un dispositivo para acceder al chroot. Estos chroots proporcionan las siguientes opciones adicionales:

mount-options=opciones
Opciones de montaje para el dispositivo de bloque. Estas son opciones adicionales para pasar a mount(8). Por ejemplo, "-o atime,sync,user_xattr".
location=ruta
Esta es la ruta al chroot *dentro* del sistema de archivos en el dispositivo. Por ejemplo, si el sistema de archivos contiene un chroot en "/chroot/sid", especificaría "/chroot/sid" aquí. Si el chroot es lo único en el sistema de archivos, es decir, "/" es el sistema de archivos raíz para el chroot, esta opción debe dejarse en blanco u omitirse por completo.

Opciones de chroot de unión de sistemas de archivos

Los tipos de chroot 'block-device', 'directory' y 'loopback' permiten la creación de una sesión utilizando uniones de sistemas de archivos para superponer el sistema de archivos original con un directorio escritura separado. El sistema de archivos original es de solo lectura, con cualquier modificación realizada en el sistema de archivos realizada en el directorio escritura superpuesto, dejando el sistema de archivos original sin cambios. Una unión permite que múltiples sesiones accedan y realicen cambios en un solo chroot simultáneamente, manteniendo los cambios privados para cada sesión. Para habilitar esta función, establezca union-type en cualquier valor compatible. Si se habilita, el chroot también será un chroot de origen, que proporcionará opciones adicionales (ver "Opciones de chroot de origen", arriba). Todas las entradas son opcionales.

union-type=tipo
Establece el tipo de sistema de archivos de unión. Los sistemas de archivos actualmente compatibles son 'aufs', 'overlayfs', 'overlay' (a partir de Linux 4.0+) y 'unionfs'. El valor predeterminado es 'none', que deshabilita esta función.
union-mount-options=opciones
Opciones de montaje del sistema de archivos de unión (configuración de rama), utilizadas para montar el sistema de archivos de unión especificado con union-type. Esto reemplaza la cadena completa "-o" para mount y permite la creación de uniones de sistemas de archivos complejas. Tenga en cuenta que 'aufs', 'overlayfs' y 'unionfs'

CONFIGURATION FILE

The schroot configuration file is located at /etc/schroot/schroot.conf. This file is split into a number of sections, each defining a specific chroot. Each section begins with a name in square brackets, e.g. [example], and is followed by a number of key-value pairs.

A number of configuration keys are recognised. Some are specific to certain types, but the following are recognised for all types:

allow-empty-chroot
A boolean value which, if true, will allow the chroot to be entered even if it is empty. By default, this is false.
aliases=list
A comma separated list of aliases for the chroot. These aliases may be used on the command line in place of the actual chroot name. The aliases are available to all users.
boot-session
A boolean value which, if true, will cause the chroot to be entered with its setup scripts run with the same user ID as the user that invoked schroot. By default this is false and the setup scripts run as root.
description=text
A short description of the chroot. This is used for display purposes only.
directory=directory
The directory containing the chroot. This is used for types plain and directory.
users=list
A comma separated list of users who are permitted to enter the chroot. If this is empty, all users are permitted. If it contains the special value root, then only the root user is permitted. If specified, then the user running schroot must also be listed.
root-users=list
A comma separated list of users who are permitted to enter the chroot as root. If this is empty, only the root user is permitted. If specified, then the user running schroot must also be listed.
groups=list
A comma separated list of groups who are permitted to enter the chroot. If this is empty, all groups are permitted. If specified, then the user running schroot must also be a member of one of the listed groups. The group root is special and means only the root user may enter.
root-groups=list
A comma separated list of groups who are permitted to enter the chroot as root. If this is empty, only the root user is permitted. If specified, then the user running schroot must also be a member of one of the listed groups. The group root is special and means only the root user may enter.
script-config=file
Specify the configuration file to be used by the setup scripts. The default is /etc/schroot/default/config.
script-chmod-template=template
Specify the template used for creating directories and files within the chroot. The default is 0755.
priority=number
A numerical value indicating the priority of the chroot. Higher values indicate higher priority. This is used when an alias is specified which matches multiple chroots. The chroot with the highest priority is chosen. The default is 0.
type=type
The type of chroot. The following types are recognised:

plain: A standard chroot located in a directory. This is the default type.

directory: A standard chroot located in a directory. This is identical to plain.

block-device: A chroot residing on a block device, e.g. a partition or logical volume. The device option must be specified.

lvm-snapshot: A chroot created from an LVM snapshot of an existing logical volume. The device option must be specified, and the lvm-snapshot-options option may be used to specify options to the lvcreate command.

file: A chroot contained within a file, typically a tarball or compressed tarball. The file option must be specified.

union: A chroot created from a union mount of a read-only lower directory and a read-write upper directory. See union-overlay-directory and union-underlay-directory.

device=device
The block device or logical volume containing the chroot. This is used for types block-device and lvm-snapshot.
file=file
The file containing the chroot. This is used for type file.
mount-options=options
A comma separated list of mount options to be used when mounting the chroot. These are passed directly to the mount command. For example, -o ro,nodev. If not specified, then the default mount options are used.
personality=arch
Specify the Linux personality to use for the chroot. This is used for running 32-bit applications on a 64-bit system, for example. Possible values include linux, linux32, linux64.
lvm-snapshot-options=options
A comma separated list of options to be passed to the lvcreate command when creating an LVM snapshot. For example, --size 1G. Note that this option is only used for type lvm-snapshot.
source-users=list
A comma separated list of users who are permitted to enter the chroot. These are only used for type lvm-snapshot and plain chroots which are snapshots.
source-root-users=list
A comma separated list of users who are permitted to enter the chroot as root. These are only used for type lvm-snapshot and plain chroots which are snapshots.
source-groups=list
A comma separated list of groups who are permitted to enter the chroot. These are only used for type lvm-snapshot and plain chroots which are snapshots.
source-root-groups=list
A comma separated list of groups who are permitted to enter the chroot as root. These are only used for type lvm-snapshot and plain chroots which are snapshots.

For union chroots, the following keys are also recognised:

union-overlay-directory=directory
Specify the directory where the writeable overlay session directories will be created. The default is ‘/var/lib/schroot/union/overlay’.
union-underlay-directory=directory
Specify the directory where the read-only underlying directories will be created. The default is ‘/var/lib/schroot/union/underlay’.

Note: One can use the variables “${CHROOT_UNION_OVERLAY_DIRECTORY}” and “${CHROOT_UNION_UNDERLAY_DIRECTORY}” to refer to the writable overlay session directory and read-only underlying directory which are to form the union. See schroot-setup(5) for a complete variable list.

Customisation

In addition to the configuration keys listed above, it is possible to add custom keys. These keys will be used to add additional environment variables to the setup script environment when setup scripts are run. The only restriction is that the key name consists only of alphanumeric characters and hyphens, begins with an alphabet character and contains at least one period. That is to say, that it matches the extended regular expression “^([a-z][a-z0-9]*\.)+[a-z][a-z0-9-]*$”.

For example:

debian.apt-update=true
debian.distribution=unstable

would set the following environment:

DEBIAN_APT_UPDATE=true
DEBIAN_DISTRIBUTION=unstable

Note that it is an error to use different key names which would set the same environment variable by mixing periods and hyphens.

Custom configuration keys may also be modified at runtime using the --option option. However, for security, only selected keys may be modified. These keys are specified using the following options:

user-modifiable-keys=key1,key2,..
Set the keys which users may modify using --option.
root-modifiable-keys=key1,key2,.. Set the keys which the
root user may modify using --option. Note that the root user may use the keys specified in user-modifiable-keys in addition to those specified here.

Localisation

Some keys may be localised in multiple languages. This is achieved by adding the locale name in square brackets after the key name. For example:

description[en_GB]=British English translation

This will localise the description key for the en_GB locale.

description[fr]=French translation

This will localise the description key for all French locales.

NOMBRES DE CHROOT

Un certain nombre de caractères ou de mots ne sont pas autorisés dans le nom d'un chroot, le nom d'une session ou le nom d'un fichier de configuration. Le nom doit commencer par une lettre minuscule ou majuscule, ou un chiffre. Les caractères restants peuvent être en plus un trait d'union (‘-’), un point (‘.’) ou un soulignement (‘_’).

La raison de ces restrictions est la suivante :

Générique
Malheureusement, tous les endroits qui traitent les noms de chroot ne peuvent pas gérer correctement les caractères non imprimables et autres, et il est difficile de les mettre à jour tous. Ceci concerne principalement les divers scripts shell où il est également déconseillé de supposer que les auteurs créent toujours du code sûr.
‘dpkg-old’
‘dpkg-dist’
‘dpkg-new’
‘dpkg-tmp’
Ces noms ne peuvent pas apparaître à la fin d'un nom. Ce sont des copies sauvegardées de fichiers de configuration utilisés par le gestionnaire de paquets dpkg, et ils seront ignorés.

SÉCURITÉ

Utilisateurs non fiables

Notez qu'accorder aux utilisateurs non fiables un accès root aux chroots est un risque de sécurité grave ! Bien que l'utilisateur non fiable n'ait qu'un accès root aux fichiers à l'intérieur du chroot, en pratique, il existe de nombreuses façons évidentes de s'échapper du chroot et de perturber les services sur le système hôte. Comme toujours, cela se résume à la confiance.

Ne donnez pas d'accès root aux chroots aux utilisateurs en qui vous n'auriez pas confiance pour un accès root au système hôte.

Profils

Selon le profil que vous avez configuré avec l'option script-config, différents systèmes de fichiers seront montés à l'intérieur du chroot, et différents fichiers seront copiés dans le chroot depuis l'hôte. Certains profils monteront le répertoire /dev de l'hôte, tandis que d'autres ne le feront pas. Certains profils montent également en bind des parties supplémentaires du système de fichiers hôte afin de permettre l'utilisation de certaines fonctionnalités, y compris les répertoires personnels des utilisateurs et des parties spécifiques de /var. Vérifiez le fichier fstab du profil pour être certain de ce qui sera monté, et les autres fichiers du profil pour voir quels fichiers et bases de données système seront copiés dans le chroot. Choisissez un profil différent ou modifiez les fichiers pour restreindre davantage ce qui est rendu disponible à l'intérieur du chroot.

Il y a un compromis entre la sécurité (maintenir le chroot aussi minimal que possible) et la convivialité (qui nécessite parfois l'accès à des parties du système de fichiers hôte). Les différents profils font des compromis différents, et il est important que vous évaluiez celui qui répond au compromis sécurité/convivialité dont vous avez besoin.

EXEMPLE

# Configuration d'exemple
[sid]
type=plain
description=Debian unstable
description[fr_FR]=Debian instable
directory=/srv/chroot/sid
priority=3
users=jim
groups=sbuild
root-users=rleigh
aliases=unstable,default
[etch]
type=block-device
description=Debian testing (32-bit)
priority=2
groups=users
#groups=sbuild-security
aliases=testing
device=/dev/hda_vg/etch_chroot
mount-options=-o atime
personality=linux32
[sid-file]
type=file
description=Debian sid chroot basé sur fichier
priority=3
groups=sbuild
file=/srv/chroots/sid.tar.gz
[sid-snapshot]
type=lvm-snapshot
description=Snapshot LVM de Debian unstable
priority=3
groups=sbuild
users=rleigh
source-root-users=rleigh
source-root-groups=admin
device=/dev/hda_vg/sid_chroot
mount-options=-o atime,sync,user_xattr
lvm-snapshot-options=--size 2G

FICHIERS

Définitions de chroot

/etc/schroot/schroot.conf
Le fichier de définition des chroots de tout le système. Ce fichier doit appartenir à l'utilisateur root et ne doit pas être accessible en écriture par d'autres.
/etc/schroot/chroot.d
Des définitions de chroots supplémentaires peuvent être placées dans des fichiers sous ce répertoire. Ils sont traités exactement de la même manière que /etc/schroot/schroot.conf. Chaque fichier peut contenir une ou plusieurs définitions de chroot.

Configuration des scripts de configuration

Le répertoire /etc/schroot/default contient les paramètres par défaut utilisés par les scripts de configuration.

config
Fichier de configuration principal lu par les scripts de configuration. Le format de ce fichier est décrit dans schroot-script-config(5). C'est la valeur par défaut pour la clé script-config. Notez que ce fichier était auparavant nommé /etc/schroot/script-defaults. Les fichiers suivants sont référencés par défaut :
copyfiles
Une liste de fichiers à copier dans le chroot depuis le système hôte. Notez que ce fichier était auparavant nommé /etc/schroot/copyfiles-defaults.
fstab
Un fichier au format décrit dans fstab(5), utilisé pour monter des systèmes de fichiers à l'intérieur du chroot. L'emplacement de montage est relatif à la racine du chroot. Notez que ce fichier était auparavant nommé /etc/schroot/mount-defaults.
nssdatabases
Bases de données système (telles que décrites dans /etc/nsswitch.conf sur les systèmes GNU/Linux) à copier dans le chroot depuis l'hôte. Notez que ce fichier était auparavant nommé /etc/schroot/nssdatabases-defaults.
