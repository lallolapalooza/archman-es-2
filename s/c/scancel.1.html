scancel(1) Comandos de Slurm scancel(1)

NOMBRE

scancel - Se utiliza para enviar señales a trabajos o pasos de trabajo que están bajo el control de Slurm.

SINOPSIS

scancel [OPCIONES...] [id_trabajo[_id_array][.id_paso]] [id_trabajo[_id_array][.id_paso]...]

DESCRIPCIÓN

scancel se utiliza para enviar señales o cancelar trabajos, arreglos de trabajos o pasos de trabajo. Se puede enviar una cantidad arbitraria de señales a trabajos o pasos de trabajo usando filtros de especificación de trabajo o una lista separada por espacios de IDs de trabajo y/o pasos de trabajo específicos. Si se especifica el ID del trabajo de un arreglo de trabajos con un valor de ID de arreglo y el trabajo asociado con ese valor de ID de arreglo se ha separado del arreglo, entonces solo se cancelará ese elemento del arreglo de trabajos. Si se especifica el ID del trabajo de un arreglo de trabajos sin un valor de ID de arreglo o si el valor de ID de arreglo corresponde a un trabajo que no se ha separado del arreglo, entonces se cancelarán todos los elementos del arreglo de trabajos. Mientras un trabajo heterogéneo está en estado PENDIENTE, solo se puede cancelar el trabajo completo en lugar de sus componentes individuales. Una solicitud para cancelar un componente individual de un trabajo heterogéneo mientras está en estado PENDIENTE devolverá un error. Después de que el trabajo haya comenzado la ejecución, se puede cancelar un componente individual, excepto el componente cero. Si se cancela el componente cero, se cancelará todo el trabajo heterogéneo. Un trabajo o paso de trabajo solo puede ser señalado por el propietario de ese trabajo o por el usuario root. Si un usuario no autorizado intenta enviar una señal a un trabajo o paso de trabajo, se imprimirá un mensaje de error y el trabajo no recibirá la señal.

OPCIONES

-A, --account=cuenta
Restringe la operación de scancel a trabajos bajo esta cuenta de cargo.
--admin-comment=comentario
Establece el AdminComment en el trabajo al cancelar trabajos. El usuario debe tener privilegios de Administrador en el sistema.
-b, --batch
Por defecto, las señales distintas de SIGKILL no se envían al paso de lote (el script de shell). Con esta opción, scancel solo envía señales al paso de lote, pero no a ningún otro paso. Esto es útil cuando el script de shell tiene que atrapar la señal y tomar alguna acción definida por la aplicación. La mayoría de los shells no pueden manejar señales mientras un comando se está ejecutando (es decir, es un proceso hijo del paso de lote), por lo que el shell necesita esperar hasta que el comando termine para manejar la señal. Los hijos del paso de lote no reciben señales con esta opción. Si esto es deseado, use -f, --full en su lugar. NOTA: Si se usa con -f, --full, esta opción se ignora. NOTA: Esta opción no es aplicable si se especifica id_paso. NOTA: El shell en sí puede salir al recibir muchas señales. Puede evitar esto atrapando explícitamente las señales dentro del script de shell (por ejemplo, "trap <arg> <señales>"). Consulte la documentación del shell para obtener detalles.
-M, --clusters=<cadena>
Cluster al que se enviarán los comandos. Implica --ctld. Tenga en cuenta que el slurmdbd debe estar activo para que esta opción funcione correctamente, a menos que se ejecute en una federación con FederationParameters=fed_display configurado.
--ctld
Si esta opción no se usa con --interactive, --sibling, IDs de trabajo federados o IDs de paso específicos, entonces emite una única solicitud al slurmctld para enviar señales a todos los trabajos que coincidan con los filtros especificados. Esto mejora en gran medida el rendimiento de slurmctld y scancel. De lo contrario, esta opción hace que scancel envíe cada solicitud de señal de trabajo al demonio slurmctld en lugar de directamente a los demonios slurmd, lo que aumenta la sobrecarga pero ofrece una mejor tolerancia a fallos. --ctld es el comportamiento predeterminado cuando se utiliza la opción --clusters.
-c, --cron
Confirma la solicitud de cancelar un trabajo enviado por scrontab. Esta opción solo tiene efecto cuando la opción "explicit_scancel" está configurada en ScronParameters.
-f, --full
Por defecto, las señales distintas de SIGKILL no se envían al paso de lote (el script de shell). Con esta opción, scancel también envía señales al script de lote y sus procesos hijos. La mayoría de los shells no pueden manejar señales mientras un comando se está ejecutando (es decir, es un proceso hijo del paso de lote), por lo que el shell necesita esperar hasta que el comando termine para manejar la señal. A diferencia de -b, --batch, los hijos del paso de lote también reciben señales con esta opción. NOTA: Los pasos srun también son hijos del paso de lote, por lo que los pasos también reciben señales con esta opción.
--help
Imprime un mensaje de ayuda que describe todas las opciones de scancel.
-H, --hurry
No extrae ningún dato de burst buffer.
-i, --interactive
Modo interactivo. Confirma cada job_id.step_id antes de realizar la operación de cancelación.
-n, --jobname=nombre_trabajo, --name=nombre_trabajo
Restringe la operación de scancel a trabajos con este nombre de trabajo.
--me
Restringe la operación de scancel a trabajos propiedad del usuario actual.
-w, --nodelist=host1,host2,...
Cancela cualquier trabajo que utilice alguno de los hosts dados. La lista puede especificarse como una lista de hosts separada por comas, un rango de hosts (por ejemplo, host[1-5,7,...]) o un nombre de archivo. La lista de hosts se asumirá como un nombre de archivo solo si contiene un carácter "/".
-p, --partition=nombre_particion
Restringe la operación de scancel a trabajos en esta partición.
-q, --qos=qos
Restringe la operación de scancel a trabajos con esta calidad de servicio.
-Q, --quiet
No informe un error si el trabajo especificado ya se completó. Esta opción es incompatible con la opción --verbose.
-R, --reservation=nombre_reserva
Restringe la operación de scancel a trabajos con este nombre de reserva.
--sibling=nombre_cluster
Elimina un trabajo hermano activo de un trabajo federado.
-s, --signal=nombre_señal
El nombre o número de la señal a enviar. Si esta opción no se utiliza, se terminará el trabajo o paso especificado.
-t, --state=nombre_estado_trabajo
Restringe la operación de scancel a trabajos en este estado. nombre_estado_trabajo puede tener el valor "PENDING", "RUNNING" o "SUSPENDED".
-v, --verbose
Informe el estado de cada trabajo cancelado. Esta opción es incompatible con la opción -Q, --quiet.
-u, --user=nombre_usuario
Restringe la operación de scancel a trabajos propiedad de este usuario.
--version
Imprime la información de la versión de scancel.
-W, --wait
Espera a que el trabajo se complete o se elimine.
-z, --exact
Si se especifica un ID de trabajo de arreglo, el ID de arreglo debe ser especificado. Si se especifican ambos, el ID de trabajo y el ID de arreglo, se eliminará solo ese arreglo específico.

EJEMPLOS

Cancela el trabajo con ID 12345:

scancel 12345

Cancela todos los trabajos propiedad del usuario "janedoe" que están en estado PENDING:

scancel -u janedoe -t PENDING

Cancela el arreglo de trabajos con ID 12345, específicamente el elemento con ID de arreglo 3:

scancel 12345_3

Cancela todos los elementos del arreglo de trabajos con ID 12345:

scancel -t PENDING 12345

Envía la señal SIGHUP al trabajo con ID 12345:

scancel -s HUP 12345

Confirma interactivamente la cancelación de todos los trabajos propiedad del usuario actual:

scancel -i --me

ESTADO DE SALIDA

Al completarse con éxito, 0 se devuelve. En caso de error, se devuelve un valor distinto de cero.

OPTIONS

-A, --account=account
Cancel jobs associated with the specified account.
-b, --batch
Signal the batch shell processes instead of the job's steps.
-c, --cron
Cancel all jobs in the specified partition that are not running and are not the most recently submitted.
--ctld
Send the cancel request to the slurmctld daemon. This is the default behavior.
-f, --full
Cancel all jobs, including running jobs.
-H, --hurry
Cancel jobs that are eligible to run, but have not yet started.
-i, --interactive
Cancel only interactive jobs.
-M, --clusters
Specify the clusters that the command should affect. See slurm.conf(5) for more information.
-n, --name=job_name
Cancel jobs matching the specified job name.
-p, --partition=partition_name
Cancel jobs within the specified partition.
-q, --qos=qos
Cancel jobs associated with the specified Quality of Service.
--quiet
Suppress informational messages. This option is incompatible with the --verbose option.
-s, --signal=signal
Send the specified signal to the job. Signals may be specified by name (e.g., HUP, INT, TERM, KILL, USR1, USR2) or by number. If no signal is specified, then SIGTERM is used. If the signal is KILL, the job is immediately terminated without cleanup.
--sibling
Cancel all sibling jobs and job steps.
-t, --state=job_state_name
Cancel jobs in the specified state. Permitted job states are PENDING, RUNNING, or SUSPENDED.
--usage
Muestra un breve mensaje de ayuda que lista las opciones de scancel.
-u, --user=user_name
Restringe la operación de scancel a los trabajos propiedad del usuario dado.
-v, --verbose
Imprime registros adicionales. Múltiples v aumentan el nivel de detalle de los registros. Esta opción es incompatible con la opción --quiet.
-V, --version
Imprime el número de versión del comando scancel.
--wckey=wckey
Restringe la operación de scancel a trabajos que utilizan esta clave de caracterización de carga de trabajo.

ARGUMENTOS

job_id
El ID del trabajo de Slurm que se va a señalar.
step_id
El ID del paso del trabajo que se va a señalar. Si no se especifica, la operación se realiza a nivel de trabajo.

Si no se utilizan ni --batch ni --signal, se terminará todo el trabajo.

Cuando se utiliza --batch, se enviarán señales a los procesos del shell de batch. Slurm no enviará señales a los procesos hijos del shell, pero el shell puede reenviar la señal.

Cuando no se utiliza --batch pero sí se utiliza --signal, se enviarán señales a todos los pasos del trabajo, pero no se enviará señal al script de batch en sí.

RENDIMIENTO

Al ejecutar scancel sin la opción --ctld; o con la opción --ctld y --interactive, --sibling, o IDs de paso específicos; se envía una llamada a procedimiento remoto a slurmctld para obtener todos los trabajos. scancel luego envía una llamada a procedimiento remoto de señal de trabajo para cada trabajo que coincide con los filtros solicitados.

Al ejecutar scancel con la opción --ctld y sin --interactive, --sibling, o IDs de paso específicos, se envía una única llamada a procedimiento remoto a slurmctld para señalar todos los trabajos que coinciden con los filtros solicitados. Por lo tanto, se recomienda utilizar la opción --ctld para reducir el número de llamadas a procedimiento remoto enviadas a slurmctld.

Si llegan suficientes llamadas de scancel u otros comandos cliente de Slurm que envían llamadas a procedimiento remoto al daemon slurmctld al mismo tiempo, esto puede resultar en una degradación del rendimiento del daemon slurmctld, posiblemente resultando en una denegación de servicio.

No ejecute scancel u otros comandos cliente de Slurm que envíen llamadas a procedimiento remoto a slurmctld desde bucles en scripts de shell u otros programas. Asegúrese de que los programas limiten las llamadas a scancel al mínimo necesario para la información que intenta recopilar.

NOTAS

Si se proporcionan varios filtros (por ejemplo, --partition y --name), solo se señalarán los trabajos que cumplan con todas las opciones de filtrado.

Cancelar un paso de trabajo no resultará en la terminación del trabajo. El trabajo debe ser cancelado para liberar una asignación de recursos.

Para cancelar un trabajo, invoque scancel sin la opción --signal. Esto enviará primero una señal SIGCONT a todos los pasos para despertarlos, luego una señal SIGTERM, luego esperará la duración KillWait definida en el archivo slurm.conf y finalmente, si no se han terminado, enviará una señal SIGKILL. Esto da tiempo a los trabajos/pasos en ejecución para que se limpien.

Si se envía un valor de señal de "KILL" a un trabajo completo, esto cancelará los pasos de trabajo activos pero no cancelará el trabajo en sí.

AUTORIZACIÓN

Al utilizar SlurmDBD, los usuarios que tienen un AdminLevel definido (Operador o Administrador) y los usuarios que son coordinadores de cuenta tienen la autoridad para invocar scancel en los trabajos de otros usuarios.

EJEMPLOS

Enviar SIGTERM a los pasos 1 y 3 del trabajo 1234:
$ scancel --signal=TERM 1234.1 1234.3
Cancelar el trabajo 1234 junto con todos sus pasos:
$ scancel 1234
Enviar SIGKILL a todos los pasos del trabajo 1235, pero sin cancelar el trabajo en sí:
$ scancel --signal=KILL 1235
Enviar SIGUSR1 a los procesos del shell de batch del trabajo 1236:
$ scancel --signal=USR1 --batch 1236
Cancelar todos los trabajos pendientes que pertenecen al usuario "bob" en la partición "debug":
$ scancel --state=PENDING --user=bob --partition=debug
Cancelar solo el ID de array 4 del array de trabajos 1237
$ scancel 1237_4
