SCDAEMON(1) GNU Privacy Guard 2.4 SCDAEMON(1)

NOMBRE

scdaemon - Demonio de tarjeta inteligente para el sistema GnuPG

SINOPSIS

scdaemon [--homedir dir] [--options file] [options] --server
scdaemon [--homedir dir] [--options file] [options] --daemon [command_line]

DESCRIPCIÓN

El scdaemon es un demonio para gestionar tarjetas inteligentes. Normalmente es invocado por gpg-agent y, en general, no se usa directamente.

COMANDOS

Los comandos no se distinguen de las opciones, excepto por el hecho de que solo se permite un comando.

--version
Imprime la versión del programa e información de licencia. Tenga en cuenta que no puede abreviar este comando.
--help, -h
Imprime un mensaje de uso resumiendo las opciones de línea de comandos más útiles. Tenga en cuenta que no puede abreviar este comando.
--dump-options
Imprime una lista de todas las opciones y comandos disponibles. Tenga en cuenta que no puede abreviar este comando.
--server
Ejecuta en modo servidor y espera comandos en la entrada estándar. El modo predeterminado es crear un socket y escuchar comandos allí.
--multi-server
Ejecuta en modo servidor y espera comandos en la entrada estándar así como en un socket de dominio Unix adicional. El comando del servidor GETINFO puede usarse para obtener el nombre de ese socket adicional.
--daemon
Ejecuta el programa en segundo plano. Esta opción es necesaria para evitar que se ejecute accidentalmente en segundo plano.

OPCIONES

--options file
Lee la configuración del archivo file en lugar del archivo de configuración predeterminado por usuario. El archivo de configuración predeterminado se llama ‘scdaemon.conf’ y se espera en el directorio ‘.gnupg’ directamente debajo del directorio de inicio del usuario.
--homedir dir
Establece el nombre del directorio de inicio a dir. Si no se usa esta opción, el directorio de inicio predeterminado es ‘~/.gnupg’. Solo se reconoce cuando se proporciona en la línea de comandos. También anula cualquier directorio de inicio indicado a través de la variable de entorno ‘GNUPGHOME’ o (en sistemas Windows) por medio de la entrada del Registro HKCU\Software\GNU\GnuPG:HomeDir.

En sistemas Windows es posible instalar GnuPG como una aplicación portátil. En este caso, solo se considera esta opción de línea de comandos, y se ignoran todas las demás formas de establecer un directorio de inicio.

-v
--verbose
Muestra información adicional mientras se ejecuta. Puede aumentar la verbosidad proporcionando varios comandos de verbosidad a gpgsm, como ‘-vv’.
--debug-level level
Selecciona el nivel de depuración para investigar problemas. level puede ser un valor numérico o una palabra clave:
none
Sin depuración en absoluto. Se puede usar un valor menor que 1 en lugar de la palabra clave.
basic
Algunos mensajes de depuración básicos. Se puede usar un valor entre 1 y 2 en lugar de la palabra clave.
advanced
Mensajes de depuración aún más detallados. Se puede usar un valor entre 3 y 5 en lugar de la palabra clave.
expert
Mensajes aún más detallados. Se puede usar un valor entre 6 y 8 en lugar de la palabra clave.
guru
Todos los mensajes de depuración que pueda obtener. Se puede usar un valor mayor que 8 en lugar de la palabra clave. La creación de archivos de trazado de hash solo se habilita si se usa la palabra clave.

Cómo se mapean estos mensajes a las banderas de depuración reales no está especificado y puede cambiar con versiones más recientes de este programa. Sin embargo, están cuidadosamente seleccionados para ayudar mejor en la depuración.

Todas las opciones de depuración están sujetas a cambios y, por lo tanto, no deben ser utilizadas por ninguna aplicación programática. Como su nombre indica, solo se utilizan como ayudas para depurar problemas.
--debug flags
Establece las banderas de depuración. Todas las banderas se combinan con OR y flags puede proporcionarse en sintaxis C (por ejemplo, 0x0042) o como una lista separada por comas de nombres de banderas. Para obtener una lista de todas las banderas compatibles, se puede usar la palabra única "help". Esta opción solo es útil para la depuración y su comportamiento puede cambiar en cualquier momento sin previo aviso.
--debug-all
Igual que --debug=0xffffffff
--debug-wait n
Al ejecutarse en modo servidor, espera n segundos antes de entrar en el bucle de procesamiento real e imprime el PID. Esto da tiempo para adjuntar un depurador.
--debug-ccid-driver
Habilita la salida de depuración del controlador CCID incluido para tarjetas inteligentes. Usar esta opción dos veces también habilitará un seguimiento del protocolo T=1. Tenga en cuenta que esta opción puede revelar datos confidenciales.
--debug-disable-ticker
Esta opción deshabilita todas las funciones de ticker, como la verificación de inserción de tarjetas.
--debug-allow-core-dump
Por razones de seguridad, no crearemos un volcado de núcleo cuando el proceso aborte. Para fines de depuración, a veces es mejor permitir el volcado de núcleo. Esta opción lo habilita y también cambia el directorio de trabajo a ‘/tmp’ cuando se ejecuta en modo --server.
--debug-log-tid
Esta opción añade un ID de hilo al PID en la salida del registro.
--debug-assuan-log-cats cats
Cambia las categorías de registro de Libassuan activas a cats. El valor de cats es un entero sin signo proporcionado en sintaxis C habitual. Un valor de 0 cambia a una categoría predeterminada. Si no se utiliza esta opción, las categorías se toman de la variable de entorno ASSUAN_DEBUG. Tenga en cuenta que esta opción solo tiene efecto si la bandera de depuración de Assuan también se ha configurado con la opción --debug. Para obtener una lista de categorías, consulte el manual de Libassuan.
--no-detach
No separar el proceso de la consola. Esto es principalmente útil para la depuración.
--listen-backlog n
Establece el tamaño de la cola para conexiones pendientes. El valor predeterminado es 64. Esta opción solo tiene efecto si también se usa --multi-server.
--log-file file
Añade toda la salida de registro al archivo file. Esto es muy útil para ver lo que hace realmente el agente. Use ‘socket://’ para registrar en un socket.
--pcsc-shared
Usa el modo compartido para acceder a la tarjeta a través de PC/SC. Esta es una opción algo peligrosa porque Scdaemon asume acceso exclusivo a la tarjeta y, por ejemplo, almacena en caché cierta información de la tarjeta. Use esta opción solo si sabe lo que está haciendo.

NAME

scdaemon — smart card daemon

SYNOPSIS

scdaemon [-a] [-c name] [-d] [-f] [-I] [-i] [-k] [-l] [-n] [-q] [-r] [-s] [-v] [-V] [-w] [-H home-dir] [-o options-file] [-p pin-cache-dir] [-P pid-file] [-R reader-direction] [file...]

DESCRIPTION

The smart card daemon scdaemon is a helper program used by GnuPG (and gpgsm) to access smart cards. It is typically run by gpg-agent(1).

You may need to install a support library for your card reader. For example, you may need to install the PC/SC driver libpcsclite.

The default PC/SC driver configuration may not be optimal. For example, the default file name for the shared library is ‘libpcsclite.so.1’. You might also want to install a symbolic link to the default file name (e.g. from ‘libpcsclite.so.1’). A Unicode file name may not be used on Windows.

COMMANDS

When scdaemon is running as a server, it accepts a list of commands from its standard input. The commands are parsed according to the APDU specification. scdaemon responds by writing a response APDU to its standard output. The commands are line-oriented and are either in plain ASCII or as hexadecimal encoded byte strings.

The following commands are supported:

PIN command
This command is used to interact with a card's PIN entry device. For a description of the available commands, see the PIN COMMANDS section.
SERIALNO
This command returns the serial number of the card. This is useful for debugging and for selecting a specific card when multiple cards are present.
GETINFO attribute
This command returns information about the card reader or card. The supported attributes are:
  • reader_list: Returns a list of available card readers.
  • app_list: Returns a list of supported applications on the card.
BYE
This command terminates the connection to the card and exits.

OPTIONS

-a
This option enables the automatic use of the card. If this option is given, scdaemon will automatically try to detect and use the card. This is useful for applications that need to access the card without user interaction.
-c name
This option specifies the name of the card to be used. If this option is given, scdaemon will only use the card with the specified name. This is useful when multiple cards are present and you need to select a specific card.
-d
This option enables debugging output. The debugging output is sent to standard error. This is useful for troubleshooting.
-f
If this option is given, scdaemon will run in the foreground and not fork into the background. This is useful for debugging.
-I
This option enables the use of the PC/SC interface. If this option is given, scdaemon will use the PC/SC interface to access the card reader. This is the default behavior.
-i
This option enables the use of the CCID interface. If this option is given, scdaemon will use the CCID interface to access the card reader. This is useful for readers that do not support PC/SC.
-k
This option kills an existing scdaemon process. This is useful for restarting the daemon.
-l
This option enables logging of all communication with the card reader. The log is written to a file named ‘scdaemon.log’ in the current directory. This is useful for debugging.
-n
This option disables the use of the built-in card drivers. If this option is given, scdaemon will only use external drivers for card access. This is useful for testing custom drivers.
-q
This option suppresses all output to standard error. This is useful for running scdaemon in the background.
-r
This option enables raw mode. In raw mode, scdaemon will not perform any command translation or filtering. This is useful for debugging low-level card communication.
-s
This option enables the use of the serial port interface. If this option is given, scdaemon will use the serial port to access the card reader. This is useful for older card readers that do not support PC/SC or CCID.
-v
This option enables verbose output. The verbose output is sent to standard error. This is useful for debugging.
-V
Print the version number and exit.
-w
This option enables watching for card reader status changes. If this option is given, scdaemon will continuously monitor the card readers for any changes, such as a card being inserted or removed. This is useful for applications that need to be notified of such changes.
-H home-dir
Use home-dir for the GnuPG home directory. The default is the first directory in the environment variable GPG_HOME, or ‘~/.gnupg’ if no value is set.
-o options-file
Use options-file as the configuration file. The default is ‘scdaemon.conf’ in the GnuPG home directory.
-p pin-cache-dir
Use pin-cache-dir as the directory for the PIN cache. The default is ‘~/.gnupg/private-keys-v1.d’.
-P pid-file
Write the process ID to pid-file. The default is ‘scdaemon.pid’ in the GnuPG home directory.
-R reader-direction
Set the direction for reading card readers. reader-direction can be one of the following:
  • no-card: Do not read cards.
  • only-new: Only read new cards.
  • always: Always read cards.
The default is always.
--disable-ccid
The integrated CCID driver for CCID compliant devices can be available when libusb was detected at build time, and it is used to access the smartcard reader. If access via PC/SC driver is needed, please configure this option to disable CCID driver support (if any). In GnuPG 2.2, there was a fallback mechanism from CCID driver to PC/SC driver. The fallback mechanism worked, because scdaemon in GnuPG 2.2 only supported a single token/reader. To support of multiple tokens/readers at the same time, fallback mechanism was removed.
--reader-port number_or_string
This option may be used to specify the port of the card terminal. A value of 0 refers to the first serial device; add 32768 to access USB devices. The default is 32768 (first USB device). PC/SC or CCID readers might need a string here; run the program in verbose mode to get a list of available readers. The default is then the first reader found.

To get a list of available CCID readers you may use this command:

  echo scd getinfo reader_list \
    | gpg-connect-agent --decode | awk '/^D/ {print $2}'
--card-timeout n
This option is deprecated. In GnuPG 2.0, it used to be used for DISCONNECT command to control timing issue. Since DISCONNECT command works synchronously, it has no effect.
--enable-pinpad-varlen
Please specify this option when the card reader supports variable length input for pinpad (default is no). For known readers (listed in ccid-driver.c and apdu.c), this option is not needed. Note that if your card reader doesn't supports variable length input but you want to use it, you need to specify your pinpad request on your card.
--disable-pinpad
Even if a card reader features a pinpad, do not try to use it.
--deny-admin
This option disables the use of admin class commands for card applications where this is supported. Currently we support it for the OpenPGP card. This option is useful to inhibit accidental access to admin class command which could ultimately lock the card through wrong PIN numbers. Note that GnuPG versions older than 2.0.11 featured an --allow-admin option which was required to use such admin commands. This option has no more effect today because the default is now to allow admin commands.
--disable-application name
This option disables the use of the card application named name. This is mainly useful for debugging or if a application with lower priority should be used by default.
--application-priority namelist
This option allows one to change the order in which applications of a card a tried if no specific application was requested. namelist is a space or comma delimited list of application names. Unknown names are simply skipped. Applications not mentioned in the list are put in the former order at the end of the new priority list.

To get the list of current active applications, use

    gpg-connect-agent 'scd getinfo app_list' /bye

All the long options may also be given in the configuration file after stripping off the two leading dashes.

CARD APPLICATIONS

scdaemon supports the card applications as described below.

The OpenPGP card application ``openpgp''

 

This application is currently only used by gpg but may in future also be useful with gpgsm. Version 1 and version 2 of the card is supported.

The specification for this card is available at
(https://gnupg.org/ftp/specs/) .

The Telesec NetKey card ``nks''

 

This is the main application of the Telesec cards as available in Germany. It is a superset of the German DINSIG card. The card is used by gpgsm.

The DINSIG card application ``dinsig''

 

This is an application as described in the German draft standard DIN V 66291-1. It is intended to be used by cards supporting the German signature law and its bylaws (SigG and SigV).

The PKCS#15 card application ``p15''

 

This is common framework for smart card applications. It is used by gpgsm.

The Geldkarte card application ``geldkarte''

 

This is a simple application to display information of a German Geldkarte. The Geldkarte is a small amount debit card application which comes with almost all German banking cards.

The SmartCard-HSM card application ``sc-hsm''

 

This application adds read-only support for keys and certificates stored on a (http://www.smartcard-hsm.com, SmartCard-HSM).

To generate keys and store certificates you may use (https://github.com/OpenSC/OpenSC/wiki/SmartCardHSM, OpenSC) or the tools from (http://www.openscdp.org, OpenSCDP).

The SmartCard-HSM cards requires a card reader that supports Extended Length APDUs.

The Undefined card application ``undefined''

 

This is a stub application to allow the use of the APDU command even if no supported application is found on the card. This application is not used automatically but must be explicitly requested using the SERIALNO command.

EXAMPLES

$ scdaemon --server -v

FILES

There are a few configuration files to control certain aspects of scdaemons's operation. Unless noted, they are expected in the current home directory (see: [option --homedir]).

scdaemon.conf
This is the standard configuration file read by scdaemon on startup. It may contain any valid long option; the leading two dashes may not be entered and the option may not be abbreviated. This default name may be changed on the command line (see: [option --options]).
scd-event
If this file is present and executable, it will be called on every card reader's status change. An example of this script is provided with the source code distribution. This option is deprecated in favor of the DEVINFO --watch.
reader_n.status
This file is created by scdaemon to let other applications now about reader status changes. Its use is now deprecated in favor of ‘scd-event’.
