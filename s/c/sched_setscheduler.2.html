sched_setscheduler(2) Manual de llamadas al sistema sched_setscheduler(2)

NOMBRE

sched_setscheduler, sched_getscheduler - establecer y obtener la política/parámetros de planificación

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sched.h>
int sched_setscheduler(pid_t pid, int policy,
                       const struct sched_param *param);
int sched_getscheduler(pid_t pid);

DESCRIPCIÓN

La llamada al sistema sched_setscheduler() establece tanto la política de planificación como los parámetros para el hilo especificado por pid. Si pid es cero, se establecerán la política de planificación y los parámetros del hilo que realiza la llamada.

Los parámetros de planificación se especifican en el argumento param, que es un puntero a una estructura del siguiente tipo:


struct sched_param {
    ...
    int sched_priority;
    ...
};

En la implementación actual, la estructura contiene solo un campo, sched_priority. La interpretación de param depende de la política seleccionada.

Actualmente, Linux soporta las siguientes políticas de planificación "normales" (es decir, no en tiempo real) como valores que pueden ser especificados en policy:

SCHED_OTHER
la política estándar de tiempo compartido round-robin;
SCHED_BATCH
para la ejecución de procesos estilo "batch"; y
SCHED_IDLE
para ejecutar trabajos en segundo plano de muy baja prioridad.

Para cada una de las políticas anteriores, param->sched_priority debe ser 0.

También se admiten varias políticas de "tiempo real", para aplicaciones críticas de tiempo que necesitan un control preciso sobre la forma en que se seleccionan los hilos ejecutables para su ejecución. Para las reglas que rigen cuándo un proceso puede utilizar estas políticas, consulte sched(7). Las políticas de tiempo real que pueden ser especificadas en policy son:

SCHED_FIFO
una política first-in, first-out (primero en entrar, primero en salir); y
SCHED_RR
una política round-robin.

Para cada una de las políticas anteriores, param->sched_priority especifica una prioridad de planificación para el hilo. Este es un número en el rango devuelto al llamar a sched_get_priority_min(2) y sched_get_priority_max(2) con la policy especificada. En Linux, estas llamadas al sistema devuelven, respectivamente, 1 y 99.

Desde Linux 2.6.32, la bandera SCHED_RESET_ON_FORK puede ser aplicada mediante OR bit a bit en policy al llamar a sched_setscheduler(). Como resultado de incluir esta bandera, los hijos creados por fork(2) no heredan políticas de planificación privilegiadas. Consulte sched(7) para obtener más detalles.

sched_getscheduler() devuelve la política de planificación actual del hilo identificado por pid. Si pid es cero, se recuperará la política del hilo que realiza la llamada.

VALOR DE RETORNO

En caso de éxito, sched_setscheduler() devuelve cero. En caso de éxito, sched_getscheduler() devuelve la política del hilo (un entero no negativo). En caso de error, ambas llamadas devuelven -1, y errno se establece para indicar el error.

ERRORES

EINVAL
Argumentos inválidos: pid es negativo o param es NULL.
EINVAL
(sched_setscheduler()) policy no es una de las políticas reconocidas.
EINVAL
(sched_setscheduler()) param no tiene sentido para la policy especificada.
EPERM
El hilo que realiza la llamada no tiene los privilegios apropiados.
ESRCH
No se pudo encontrar el hilo cuyo ID es pid.

VERSIONES

POSIX.1 no detalla los permisos que un hilo no privilegiado requiere para llamar a sched_setscheduler(), y los detalles varían entre sistemas. Por ejemplo, la página del manual de Solaris 7 dice que el ID de usuario real o efectivo del llamante debe coincidir con el ID de usuario real o el ID de usuario guardado del objetivo.

La política y los parámetros de planificación son en realidad atributos por hilo en Linux. El valor devuelto por una llamada a gettid(2) puede ser pasado en el argumento pid. Especificar pid como 0 operará sobre los atributos del hilo que realiza la llamada, y pasar el valor devuelto por una llamada a getpid(2) operará sobre los atributos del hilo principal del grupo de hilos. (Si está utilizando la API de hilos POSIX, utilice en su lugar pthread_setschedparam(3), pthread_getschedparam(3) y pthread_setschedprio(3), en lugar de las llamadas al sistema sched_*(2).)

ESTÁNDARES

POSIX.1-2024 (pero vea ERRORES abajo).

SCHED_BATCH y SCHED_IDLE son específicos de Linux.

HISTORIAL

POSIX.1-2001.

NOTAS

Se pueden encontrar más detalles sobre la semántica de todas las políticas de planificación "normales" y "de tiempo real" anteriores en la página del manual sched(7). Esa página también describe una política adicional, SCHED_DEADLINE, que solo se puede establecer a través de sched_setattr(2).

Los sistemas POSIX en los que están disponibles sched_setscheduler() y sched_getscheduler() definen _POSIX_PRIORITY_SCHEDULING en <unistd.h>.

ERRORES Y BUGS

POSIX.1 dice que en caso de éxito, sched_setscheduler() debería devolver la política de planificación anterior. El sched_setscheduler() de Linux no cumple este requisito, ya que siempre devuelve 0 en caso de éxito.

sched_setscheduler(2)

NAME

sched_setscheduler, sched_getscheduler, sched_set_param, sched_get_param, sched_getscheduler - set and get process scheduling policy and parameters

LIBRARY

Real-time extensions (librt), -lrt

SYNOPSIS


#include <sched.h>

int sched_setscheduler(pid_t pid, int policy,
                       const struct sched_param *param);
int sched_getscheduler(pid_t pid);
int sched_set_param(pid_t pid, const struct sched_param *param);
int sched_get_param(pid_t pid, struct sched_param *param);

DESCRIPTION

These functions are part of the POSIX real-time extensions, which provide a facility for real-time programming. The real-time extensions allow a process to select its scheduling policy and to set scheduling parameters that can affect its behavior.

The scheduling policy determines the order in which processes are scheduled. The scheduling parameters are used by the scheduler to fine-tune the scheduling of a process.

The following scheduling policies are defined:

SCHED_FIFO
First-In, First-Out (FIFO) scheduling. This is a preemptive policy in which processes run until they block, yield, or are preempted by a higher-priority process.
SCHED_RR
Round-Robin (RR) scheduling. This is a preemptive policy similar to SCHED_FIFO, but with the addition that processes at the same priority level are timeshared using a round-robin mechanism.
SCHED_BATCH
Scheduling suitable for batch processing. This policy is intended for processes that do not require real-time guarantees.
SCHED_IDLE
Scheduling suitable for processes that should run only when nothing else is running.

The sched_param structure contains the scheduling parameters for a process. It has at least one member, sched_priority, which specifies the priority of the process. The range of valid priorities depends on the scheduling policy and the system configuration.

sched_setscheduler() sets the scheduling policy and parameters for the process specified by pid. If pid is 0, the calling process is used. The policy argument specifies the new scheduling policy, and the param argument points to a sched_param structure containing the new scheduling parameters.

sched_getscheduler() retrieves the scheduling policy of the process specified by pid. If pid is 0, the calling process is used. It returns the current scheduling policy.

sched_set_param() sets the scheduling parameters for the process specified by pid. If pid is 0, the calling process is used. The param argument points to a sched_param structure containing the new scheduling parameters.

sched_get_param() retrieves the scheduling parameters of the process specified by pid. If pid is 0, the calling process is used. It returns the current scheduling parameters in the structure pointed to by param.

RETURN VALUE

On success, sched_setscheduler(), sched_set_param() return 0.

On success, sched_getscheduler() returns the current scheduling policy of the process.

On success, sched_get_param() returns 0.

On error, all functions return -1, and errno is set to indicate the error.

ERRORS

EINVAL: Invalid arguments.

EPERM: The calling process does not have the required privileges to change the scheduling policy or parameters.

ESRCH: The process specified by pid does not exist.

VERSIONS

These functions are available since glibc 2.3.

STANDARDS

POSIX.1-2001, POSIX.1-2008.

HISTORY

These functions first appeared in POSIX.1b.

NOTES

Changing the scheduling policy or parameters of a process requires appropriate privileges. On most systems, only the superuser can change the scheduling policy or parameters of other processes.

The SCHED_BATCH and SCHED_IDLE policies are not available on all systems.

BUGS

None known.
