SCALAR(1) Git Manual SCALAR(1)

NOMBRE

scalar - Una herramienta para gestionar repositorios Git grandes

SINOPSIS

scalar clone [--single-branch] [--branch <rama-principal>] [--full-clone]
        [--[no-]src] [--[no-]tags] [--[no-]maintenance] <url> [<enlistment>]
scalar list
scalar register [--[no-]maintenance] [<enlistment>]
scalar unregister [<enlistment>]
scalar run ( all | config | commit-graph | fetch | loose-objects | pack-files ) [<enlistment>]
scalar reconfigure [--maintenance=(enable|disable|keep)] [ --all | <enlistment> ]
scalar diagnose [<enlistment>]
scalar delete <enlistment>

DESCRIPCIÓN

Scalar es una herramienta de gestión de repositorios que optimiza Git para su uso en repositorios grandes. Scalar mejora el rendimiento configurando ajustes avanzados de Git, manteniendo los repositorios en segundo plano y ayudando a reducir los datos enviados a través de la red.

Un concepto importante de Scalar es el enlistamiento: este es el directorio de nivel superior del proyecto. Generalmente contiene el subdirectorio src/, que es un árbol de trabajo de Git. Esto fomenta la separación entre los archivos rastreados (dentro de src/) y los archivos no rastreados, como los artefactos de compilación (fuera de src/). Al registrar un árbol de trabajo de Git existente con Scalar cuyo nombre no es src, el enlistamiento será idéntico al árbol de trabajo.

El comando scalar implementa varios subcomandos y diferentes opciones según el subcomando. Con la excepción de clone, list y reconfigure --all, todos los subcomandos esperan ser ejecutados en un enlistamiento.

Las siguientes opciones se pueden especificar *antes* del subcomando:

-C <directorio>

Antes de ejecutar el subcomando, cambia el directorio de trabajo. Esta opción imita la misma opción de git(1).

-c <clave>=<valor>

Durante la ejecución del subcomando especificado, configura este ajuste. Esta opción imita la misma opción de git(1).

COMANDOS

Clonar

clone [<opciones>] <url> [<enlistment>]

Clona el repositorio especificado, similar a git-clone(1). Por defecto, solo se clonan los objetos de commit y árbol. Una vez finalizado, el árbol de trabajo se encuentra en <enlistment>/src.

La función sparse-checkout está habilitada (excepto cuando se ejecuta con --full-clone) y los únicos archivos presentes son los del directorio de nivel superior. Usa git sparse-checkout set para expandir el conjunto de directorios que deseas ver, o git sparse-checkout disable para expandir a todos los archivos (ver git-sparse-checkout(1) para más detalles). Puedes explorar los subdirectorios fuera de tu sparse-checkout usando git ls-tree HEAD[:<directorio>].

-b <nombre>, --branch <nombre>

En lugar de extraer la rama apuntada por el HEAD del repositorio clonado, extrae la rama <nombre> en su lugar.

--single-branch, --no-single-branch

Clona solo el historial que conduce a la punta de una sola rama, ya sea especificada por la opción --branch o por el HEAD de la rama principal del remoto.

Los fetches posteriores al repositorio resultante solo actualizarán la rama de seguimiento remoto para la rama con la que se usó esta opción para la clonación inicial. Si el HEAD en el remoto no apuntaba a ninguna rama cuando se realizó el clonado de --single-branch, no se creará ninguna rama de seguimiento remoto.

--src, --no-src

Por defecto, scalar clone coloca el repositorio clonado dentro de un directorio <enlistment>/src. Usa --no-src para colocar el repositorio clonado directamente en el directorio <enlistment>.

--tags, --no-tags

Por defecto, scalar clone obtendrá los objetos de etiqueta anunciados por el remoto y los futuros comandos git fetch harán lo mismo. Usa --no-tags para evitar obtener etiquetas en scalar clone y para configurar el repositorio para evitar obtener etiquetas en el futuro. Para obtener etiquetas después de clonar con --no-tags, ejecuta git fetch --tags.

--full-clone, --no-full-clone

Se inicializa un sparse-checkout por defecto. Este comportamiento se puede desactivar con --full-clone.

--maintenance, --no-maintenance

Por defecto, scalar clone configura el enlistamiento para usar la función de mantenimiento en segundo plano de Git. Usa --no-maintenance para omitir esta configuración.

Listar

list

Lista los enlistamientos que están actualmente registrados por Scalar. Este subcomando no necesita ser ejecutado dentro de un enlistamiento.

Registrar

register [<enlistment>]

Añade el repositorio del enlistamiento a la lista de repositorios registrados y comienza el mantenimiento en segundo plano. Si no se proporciona <enlistment>, se registra el enlistamiento asociado con el directorio de trabajo actual.

Nota: cuando se llama a este subcomando en un árbol de trabajo que se llama src/, su directorio padre se considera el enlistamiento de Scalar. Si el árbol de trabajo *no* se llama src/, se considerará a sí mismo como el enlistamiento de Scalar.

--maintenance, --no-maintenance

Por defecto, scalar register configura el enlistamiento para usar la función de mantenimiento en segundo plano de Git. Usa --no-maintenance para omitir esta configuración. Esto no deshabilita ningún mantenimiento que ya pueda estar habilitado de otras maneras.

Anular registro

unregister [<enlistment>]

Elimina el repositorio especificado de la lista de repositorios registrados con Scalar y detiene el mantenimiento en segundo plano programado.

Ejecutar

scalar run ( all | config | commit-graph | fetch | loose-objects | pack-files ) [<enlistment>]

Ejecuta la tarea de mantenimiento dada (o todas las tareas, si se especificó all). Excepto para all y config, este subcomando simplemente se delega a git-maintenance(1) (mapeando fetch a prefetch y pack-files a incremental-repack).

Estas tareas se ejecutan automáticamente como parte del mantenimiento programado, tan pronto como el repositorio se registra con Scalar. Por lo tanto, no debería ser necesario ejecutar este subcomando manualmente.

La tarea config es específica de Scalar y configura todas esas configuraciones predeterminadas de opinión que hacen que Git funcione de manera más eficiente con repositorios grandes. Dado que esta tarea se ejecuta automáticamente como parte de scalar clone, las invocaciones explícitas de esta tarea rara vez son necesarias.

Reconfigurar

Después de una actualización de Scalar, o cuando la configuración de un enlistamiento de Scalar se ha corrompido de alguna manera o se ha modificado por error, este subcomando permite reconfigurar el enlistamiento.

--all

Cuando se especifica --all, reconfigura todos los enlistamientos actualmente registrados con Scalar mediante la clave de configuración scalar.repo. Usa esta opción después de cada actualización para obtener las últimas funciones.

--maintenance=(enable|disable|keep)

Por defecto, Scalar configura el enlistamiento para usar la función de mantenimiento en segundo plano de Git; esto es lo mismo que usar el valor `enable` para esta opción. Usa el valor disable para eliminar cada enlistamiento considerado del mantenimiento en segundo plano. Usa `keep` para dejar la configuración de mantenimiento en segundo plano intacta para estos repositorios.

Diagnosticar

diagnose [<enlistment>]

Al informar sobre problemas con Scalar, a menudo es útil proporcionar la información recopilada por este comando, incluidos los registros y ciertas estadísticas que describen la forma de los datos del enlistamiento actual.

T

Eliminar

delete <enlistment>

Elimina el enlistamiento especificado del disco y de la lista de enlistamientos registrados.

scalar(1) - Arch Linux man pages

NAME

scalar

manage Git repositories

SYNOPSIS

scalar -h | -v

scalar command [options]

DESCRIPTION

Scalar is a tool to manage a large number of Git repositories on your local machine. It is designed for use cases with thousands of repositories, such as those found in large monorepos.

Scalar provides commands to:

  • Clone large monorepos efficiently.
  • Update local repositories with remote changes.
  • Manage the lifecycle of local repositories.

COMMANDS

Clone

clone <repository> [<options>]

This subcommand clones a Git repository, optimizing for large monorepos. It uses a sparse checkout mechanism to only download the necessary files and directories.

Update

update [<enlistment>]

This subcommand updates the specified enlistment (or all enlistments if none is specified) with the latest changes from the remote repository. It leverages Scalar's knowledge of the monorepo structure to perform updates efficiently.

Status

status [<enlistment>]

This subcommand shows the status of the specified enlistment (or all enlistments if none is specified). It indicates which enlistments have local changes, are behind the remote, or are up-to-date.

Unshallow

unshallow <enlistment>

This subcommand fetches the full history for the specified enlistment, converting it from a shallow clone to a full clone. This can be useful if you need to perform operations that require the complete Git history.

Log

log [<enlistment>]

This subcommand displays the Git log for the specified enlistment (or all enlistments if none is specified). It can be used to view the commit history of your repositories.

Gc

gc [<enlistment>]

This subcommand runs Git's garbage collection on the specified enlistment (or all enlistments if none is specified). This helps to optimize the repository by removing unnecessary objects and improving performance.

Ls-files

ls-files [<enlistment>]

This subcommand lists the files in the index of the specified enlistment (or all enlistments if none is specified). This is similar to `git ls-files`.

Cat-file

cat-file [<enlistment>] <object>

This subcommand gives access to Git's object database for the specified enlistment. It is similar to `git cat-file`.

Add-remote

add-remote <name> <url> [<enlistment>]

This subcommand adds a remote repository to the specified enlistment (or all enlistments if none is specified).

Remove-remote

remove-remote <name> [<enlistment>]

This subcommand removes a remote repository from the specified enlistment (or all enlistments if none is specified).

Config

config [<enlistment>]

This subcommand allows you to view and modify the Scalar configuration for the specified enlistment (or all enlistments if none is specified).

Hooks

hooks [<enlistment>]

This subcommand allows you to manage Git hooks for the specified enlistment (or all enlistments if none is specified).

Bundle

bundle <enlistment>

This subcommand creates a bundle of the specified Scalar enlistment. The output of this command is a .zip file that is written into a directory adjacent to the worktree in the src directory.

Delete

delete <enlistment>

This subcommand lets you delete an existing Scalar enlistment from your local file system, unregistering the repository.

SEE ALSO

git-clone(1), git-maintenance(1).
