SCHED_SETSCHEDULER(3P) Manual del programador POSIX SCHED_SETSCHEDULER(3P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

sched_setscheduler — establecer la política y los parámetros de planificación (REALTIME)

SINOPSIS

#include <sched.h>
int sched_setscheduler(pid_t pid, int policy,
    const struct sched_param *param);

DESCRIPCIÓN

La función sched_setscheduler() establecerá la política de planificación y los parámetros de planificación del proceso especificado por pid a policy y los parámetros especificados en la estructura sched_param apuntada por param, respectivamente. El valor del miembro sched_priority en la estructura sched_param será cualquier entero dentro del rango de prioridad inclusivo para la política de planificación especificada por policy. Si el valor de pid es negativo, el comportamiento de la función sched_setscheduler() no está especificado.

Los posibles valores para el parámetro policy se definen en la cabecera <sched.h>.

Si existe un proceso especificado por pid, y si el proceso llamante tiene permiso, la política de planificación y los parámetros de planificación se establecerán para el proceso cuyo ID de proceso sea igual a pid.

Si pid es cero, la política de planificación y los parámetros de planificación se establecerán para el proceso llamante.

Las condiciones bajo las cuales un proceso tiene privilegios apropiados para cambiar los parámetros de planificación de otro proceso son de definición dependiente de la implementación.

Las implementaciones pueden requerir que el proceso solicitante tenga permiso para establecer sus propios parámetros de planificación o los de otro proceso. Adicionalmente, pueden aplicarse restricciones de definición dependiente de la implementación en cuanto a los privilegios apropiados necesarios para establecer la política de planificación del proceso, o la política de planificación de otro proceso, a un valor particular.

La función sched_setscheduler() se considerará exitosa si logra establecer la política de planificación y los parámetros de planificación del proceso especificado por pid a los valores especificados por policy y la estructura apuntada por param, respectivamente.

Consulte Políticas de Planificación para una descripción de cómo esta función afecta la planificación de los hilos dentro del proceso de destino.

Si la política de planificación actual para el proceso de destino no es SCHED_FIFO, SCHED_RR o SCHED_SPORADIC, el resultado es de definición dependiente de la implementación; este caso incluye la política SCHED_OTHER.

El sched_ss_repl_period especificado debe ser mayor o igual al sched_ss_init_budget especificado para que la función tenga éxito; si no lo es, la función fallará. El valor de sched_ss_max_repl debe estar dentro del rango inclusivo [1,{SS_REPL_MAX}] para que la función tenga éxito; si no, la función fallará. No se especifica si los valores de sched_ss_repl_period y sched_ss_init_budget se almacenan tal como los proporciona esta función o si se redondean para alinearse con la resolución del reloj que se está utilizando.

Esta función no es atómica con respecto a otros hilos en el proceso. Los hilos pueden continuar ejecutándose mientras esta llamada a función está en el proceso de cambiar la política de planificación y los parámetros de planificación asociados para las entidades subyacentes planificadas por el kernel utilizadas por los hilos de ámbito de contención del proceso.

VALOR DE RETORNO

Al completarse con éxito, la función devolverá la política de planificación anterior del proceso especificado. Si la función sched_setscheduler() no se completa con éxito, la política y los parámetros de planificación permanecerán sin cambios, y la función devolverá un valor de -1 y establecerá errno para indicar el error.

ERRORES

La función sched_setscheduler() fallará si:

EINVAL
El valor del parámetro policy es inválido, o uno o más de los parámetros contenidos en param está fuera del rango válido para la política de planificación especificada.
EPERM
El proceso solicitante no tiene permiso para establecer uno o ambos de los parámetros de planificación o la política de planificación del proceso especificado.
ESRCH
No se puede encontrar ningún proceso que corresponda al especificado por pid.

sched_setscheduler(3p)

Set CPU scheduling parameters

NAME

sched_setscheduler - set CPU scheduling parameters

SYNOPSIS

#include <sched.h>

int sched_setscheduler(pid_t pid, int policy,
                       const struct sched_param *param);

DESCRIPTION

The sched_setscheduler() function sets the scheduling policy and parameters for the process or thread identified by pid. If pid is 0, the calling process or thread is configured.

The scheduling policy can be one of the following:

SCHED_FIFO
First-In, First-Out scheduling. Threads with SCHED_FIFO run until they voluntarily yield the CPU, block for I/O, or are preempted by a higher priority thread.
SCHED_RR
Round-Robin scheduling. Threads with SCHED_RR run until they voluntarily yield the CPU, block for I/O, are preempted by a higher priority thread, or their time slice expires. If their time slice expires, they are moved to the end of the queue for their priority level.
SCHED_BATCH
Batch scheduling. This policy is intended for processes that do not require real-time guarantees and wish to run when the system is otherwise idle. It provides a lower-priority execution to minimize impact on interactive processes.
SCHED_IDLE
Idle scheduling. This policy runs processes at the lowest possible priority, only when the system has no other tasks to run.

SCHED_OTHER is the default policy for all processes and threads. It is a standard timesharing policy similar to SCHED_BATCH but generally provides better interactive performance.

The param argument is a pointer to a struct sched_param, which contains the scheduling parameters. For SCHED_FIFO and SCHED_RR, this structure contains a single member, sched_priority, which specifies the priority of the thread. Priorities range from 1 (lowest) to 99 (highest).

Only the superuser can set a process to a real-time scheduling policy (SCHED_FIFO or SCHED_RR) with a priority higher than the default priority of existing real-time processes. Normal users can only change the priority of their own processes within the default priority range, or switch to SCHED_BATCH or SCHED_IDLE.

RETURN VALUE

On success, sched_setscheduler() returns 0. On failure, it returns -1 and sets errno to indicate the error.

ERRORS

EPERM
The calling process does not have permission to set the specified scheduling policy or priority for the target process.
EINVAL
The specified policy is invalid, or the param structure contains invalid values.
ESRCH
The process or thread specified by pid does not exist.

EXAMPLES

The following example sets the scheduling policy of the calling process to SCHED_FIFO with the highest priority:

#include <sched.h>
#include <stdio.h>
#include <stdlib.h>

int main() {
    struct sched_param sp;
    int policy;
    int ret;

    // Get current scheduling policy and parameters
    ret = sched_getscheduler(0);
    if (ret == -1) {
        perror("sched_getscheduler");
        exit(EXIT_FAILURE);
    }
    policy = ret;

    ret = sched_getparam(0, &sp);
    if (ret == -1) {
        perror("sched_getparam");
        exit(EXIT_FAILURE);
    }

    printf("Current policy: %d, Current priority: %d\n", policy, sp.sched_priority);

    // Set new scheduling policy and parameters
    sp.sched_priority = 99; // Highest priority
    ret = sched_setscheduler(0, SCHED_FIFO, &sp);
    if (ret == -1) {
        perror("sched_setscheduler");
        exit(EXIT_FAILURE);
    }

    // Get new scheduling policy and parameters to verify
    ret = sched_getscheduler(0);
    if (ret == -1) {
        perror("sched_getscheduler");
        exit(EXIT_FAILURE);
    }
    policy = ret;

    ret = sched_getparam(0, &sp);
    if (ret == -1) {
        perror("sched_getparam");
        exit(EXIT_FAILURE);
    }

    printf("New policy: %d, New priority: %d\n", policy, sp.sched_priority);

    return 0;
}

APPLICATION USAGE

Applications that require specific scheduling behavior, such as real-time responsiveness, may use sched_setscheduler(). However, misuse can lead to system instability or starvation of other processes. It is generally recommended to use this function only when absolutely necessary and with careful consideration of the system's overall performance.

RATIONALE

The POSIX real-time extensions provide functions like sched_setscheduler() to allow fine-grained control over process scheduling. This is crucial for applications with strict timing requirements, such as control systems, audio/video processing, and high-frequency trading platforms.

FUTURE DIRECTIONS

Future developments might involve more sophisticated scheduling policies or mechanisms for dynamically adjusting scheduling parameters based on system load or application behavior. Integration with power management features could also be explored to optimize energy consumption alongside performance.
