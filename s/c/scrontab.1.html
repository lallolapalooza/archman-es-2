NOMBRE

scrontab - gestionar archivos crontab de Slurm

SINOPSIS

scrontab [-u usuario] archivo
scrontab [-u usuario] [ -e | -l | -r ]

DESCRIPCIÓN

scrontab se utiliza para configurar, editar y eliminar el crontab de un usuario gestionado por Slurm. Este archivo puede definir un número de trabajos por lotes recurrentes para ejecutarse en un intervalo programado.

Las líneas deben ser comentarios que comiencen con '#', espacios en blanco, entradas crontab válidas o configuraciones de variables personalizadas.

Las líneas que comienzan con #SCRON permiten definir opciones para la única entrada crontab siguiente. Las opciones se reinician siempre entre cada entrada crontab. Las opciones incluyen la mayoría de las disponibles para el comando sbatch; los detalles están disponibles en la página del manual de sbatch(1).

Tenga en cuenta que no se garantiza que los trabajos se ejecuten a la hora preferida. Los trabajos se ejecutarán no con más frecuencia de la solicitada, sino que se gestionan estableciendo el campo BeginTime a la siguiente iteración válida, y luego están sujetos a retrasos en la cola. El comportamiento exacto dependerá de la configuración del sitio local. Debido a este método de implementación, el siguiente trabajo de la serie no se enviará hasta después de que el trabajo anterior haya completado. Por ejemplo, si tiene un trabajo de monitoreo programado para ejecutarse cada minuto en un sistema ocupado, si el trabajo programado para comenzar a las 08:20:00 no puede comenzar hasta las 08:20:30 y se ejecuta durante 35 segundos, entonces el trabajo a las 08:21:00 se omitirá y el siguiente trabajo se programará para las 08:22:00.

scrontab utiliza la misma sintaxis para los especificadores de fecha y hora que cron. Cada línea tiene cinco campos que tienen los siguientes significados:

campo valores permitidos
----- -----------------
minuto 0-59
hora 0-23
día del mes 1-31
mes 1-12 (o nombre)
día de la semana 0-7 (0 y 7 son domingo, o usar nombre)

Un campo puede contener un asterisco (*) que significa que es válido para todos los valores permitidos para el período de tiempo dado. Se permiten rangos donde un rango son dos números con un guion entre ellos. El segundo número debe ser mayor que el primero. Se permiten listas, con comas separando los números o rangos separados. Los valores de paso se pueden especificar ingresando una barra (/), seguida del valor de paso, haciendo que el trabajo se ejecute en el intervalo especificado apropiado para ese campo.

Las variables personalizadas se pueden definir como en un script de shell normal. El carácter $ introduce la expansión de variables. La expansión de parámetros simple es la única variante de expansión actualmente aceptada (es decir, ${parameter} o ${parameter:-word} no son compatibles). La expansión de variables solo ocurrirá dentro de los comandos de trabajo de scrontab. No es posible expandir variables en otros tipos de líneas (otras definiciones de variables, comentarios o entradas crontab). La expansión ocurrirá antes de enviar el trabajo, pero las definiciones de variables permanecerán en el script de scrontab. A diferencia de crontab, las variables de entorno del usuario se ignoran.

OPCIONES

La primera forma de este comando se utiliza para instalar un nuevo crontab desde un archivo con nombre o desde la entrada estándar si se proporciona el pseudonombre de archivo ``-''.

-e
Editar el crontab. Si aún no existe un crontab, se proporcionará un ejemplo predeterminado (sin ninguna entrada definida) en el editor.
-l
Listar el crontab. (Imprime directamente en stdout.)
-r
Eliminar el crontab. Cualquier trabajo actualmente en ejecución definido en crontab continuará ejecutándose pero ya no será recurrente. Todos los demás trabajos definidos en crontab serán cancelados.
-u <usuario>
Editar o ver el crontab de otro usuario. La listado está permitido para Operadores y Administradores. La edición/eliminación solo está permitida para root y la cuenta SlurmUser.

OPCIONES SCRONTAB

scrontab te permite usar atajos para especificar algunos intervalos de tiempo comunes para que se ejecute el script especificado. Estos incluyen lo siguiente:

@yearly | @annually
El trabajo será elegible a las 00:00 del 1 de enero cada año.
@monthly
El trabajo será elegible a las 00:00 el primer día de cada mes.
@weekly
El trabajo será elegible a las 00:00 del domingo de cada semana.
@daily | @midnight
El trabajo será elegible a las 00:00 cada día.
@hourly
El trabajo será elegible en el primer minuto de cada hora.
@elevenses
El trabajo será elegible a las 11:00 cada día. (Esta es una extensión no estándar.)
@fika
El trabajo será elegible a las 15:00 cada día. (Esta es una extensión no estándar.)
@teatime
El trabajo será elegible a las 16:00 cada día. (Esta es una extensión no estándar.)

VARIABLES DE ENTORNO

VISUAL
Se utiliza como editor interactivo si está configurado.
EDITOR
Se utiliza como editor interactivo si está configurado y VISUAL no está definido.
SLURM_CONF
La ubicación del archivo de configuración de Slurm.
SLURM_DEBUG_FLAGS
Especifica las banderas de depuración que utilizará scrontab. Consulte DebugFlags en la página del manual de slurm.conf(5) para obtener una lista completa de las banderas. La variable de entorno tiene prioridad sobre la configuración en slurm.conf.

NOTAS

scrontab solo está disponible si la opción ScronParameters=enable ha sido habilitada en slurm.conf.

scrontab creará un archivo temporal en el directorio establecido por la variable de entorno TMPDIR. Si la variable no está configurada, se utilizará /tmp.

Los trabajos creados con scrontab reciben un único ID de trabajo. Cuando se cancelen, todas las ejecuciones futuras del trabajo también se cancelarán. La definición del trabajo se comentará en el archivo scrontab del usuario.

El uso de "scontrol requeue <job_id>" omitirá la próxima ejecución del trabajo cron y lo reprogramará para la próxima hora disponible según la expresión cron.

EJEMPLOS

Para crear un trabajo que se ejecute al comienzo de cada hora, utilizando la partición 'high', la cuenta 'sub1' y tenga un tiempo de ejecución de 1 minuto, agregaría lo siguiente a scrontab:

DIR=/home/usuario1
#SCRON -p high
#SCRON -A sub1
#SCRON -t 1:00
@hourly $DIR/date.printer.job

Para que un trabajo se ejecute todos los miércoles, cada dos horas durante el horario laboral, durante los primeros cinco minutos de cada hora y nuevamente a los treinta minutos, agregaría lo siguiente a scrontab.

1-5,30 8-17/2 * * wed $DIR/ejemplo.job

LIMITACIONES

La zona horaria del controlador Slurm será la que se utilice para evaluar los intervalos de repetición de cada crontab. Las zonas horarias específicas del usuario no son compatibles.
