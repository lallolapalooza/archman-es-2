SCHEDTOOL(8) Manual del Administrador del Sistema SCHEDTOOL(8)

NOMBRE

schedtool - consultar y establecer parámetros de planificación de CPU

SINOPSIS

schedtool
[-0|-N] [-1|-F] [-2|-R] [-3|-B] [-4|-I] [-5|-D]
[-M política]
[-a afinidad] 
[-p prio]
[-n nivel_nice]
[-e comando [arg ...]]
[-r]
[-v]
[-h]
[LISTA DE PIDs]

DESCRIPCIÓN

schedtool puede establecer todos los parámetros de planificación de CPU de los que Linux es capaz o mostrar información para procesos dados.

Las tareas de larga duración y no interactivas pueden beneficiarse de SCHED_BATCH, ya que los intervalos de tiempo son más largos, se desperdicia menos tiempo de sistema al calcular el próximo proceso ejecutable y las cachés permanecen estables.

Las aplicaciones de audio/vídeo u otras aplicaciones casi en tiempo real pueden ejecutarse con menos saltos si se configuran en SCHED_RR. Utilice el cambio de prioridad estática -p para designar jerarquías interprocesos.

schedtool ahora admite el establecimiento de la afinidad de CPU introducida en linux 2.5.8.

OPCIONES

-N o -0
establecer todos los PIDs a SCHED_NORMAL/OTHER
-F o -1
a SCHED_FIFO se requieren credenciales de root
-R o -2
a SCHED_RR se requieren credenciales de root
-B o -3
a SCHED_BATCH
-I o -4
a SCHED_ISO
-D o -5
a SCHED_IDLEPRIO
-M política
para modo manual/crudo; la política es el número de la política de planificación (ver arriba para 0-4). Esta opción es principalmente para los ingenieros del kernel que desean probar sus nuevas implementaciones.
-p prio
especificar prioridad estática requerida para SCHED_FIFO y SCHED_RR. Generalmente oscila entre 1 y 99.
-a afinidad
establecer la afinidad del PID a esta máscara de bits (hexadecimal); alternativamente, se admite un modo de lista.
-n nivel_nice
establecer el nivel nice del PID; ver nice(2), nice(1).
-e comando [arg ...]
ejecutar comando con los parámetros de planificación dados (sobrescribe la imagen del proceso de schedtool). Ver EJEMPLOS.
-r
mostrar prioridad mínima y máxima para cada política.
-v
ser verboso.
-h
ayuda

EJEMPLOS

Para consultar las políticas del $SHELL:

    #> schedtool $$
Para consultar algunos PIDs, concretamente 1 2 y 3:
    #> schedtool 1 2 3
Para ejecutar mplayer en SCHED_RR con prioridad 20. El argumento de prioridad es necesario tanto para SCHED_RR como para SCHED_FIFO. 
    #> schedtool -R -p 20 -e mplayer -quiet some_file.avi
Para establecer el shell actual en SCHED_BATCH, que todos los programas que inicie el shell heredarán: 
    #> schedtool -3 $$
Para establecer todos los procesos con el nombre 'cpu_hog' en SCHED_BATCH: 
    #> schedtool -3 `pidof cpu_hog`
Para establecer la afinidad de un proceso solo en la primera CPU (CPU0): 
    #> schedtool -a 0x1 <PID>
Usando el modo de lista y afinidad de CPU0 y CPU3:
    #> schedtool -a 0,3 <PID>
Una combinación de un argumento de afinidad y una política es, por supuesto, siempre posible. 
   #> schedtool -B -a 0x1 <PID>

MASCARA DE AFINIDAD

El argumento afinidad determina en qué CPUs puede ejecutarse un proceso. Consiste en una simple máscara de bits representada en hexadecimal. La CPU0 se denota por el bit menos significativo, la CPU1 por el segundo bit menos significativo y así sucesivamente, lo que da:


0x1 -> solo ejecutar en CPU0


0x2 -> solo ejecutar en CPU1


0x4 -> solo ejecutar en CPU2


0x8 -> solo ejecutar en CPU3 ... y así sucesivamente.

Las CPUs múltiples pueden especificarse usando OR bit a bit de los valores:


0x7 -> ejecutar en CPUs 0, 1, 2 pero NO en 4


0x3 -> ejecutar solo en CPUs 0 y 1

El valor predeterminado es ejecutar un proceso en todas las CPUs, lo que da una máscara de


0xf para las 4 CPUs


0xff para las 8 CPUs

MASCARA DE AFINIDAD - MODO DE LISTA

Alternativamente, se admite un modo de lista en el que puede especificar las CPUs delimitadas por ",". Lo siguiente ejecuta <PID> en la CPU0 y CPU1 (equivalente a 0x3):

   #> schedtool -a 0,1 <PID>

RESUMEN DE POLÍTICAS

SCHED_NORMAL / SCHED_OTHER Esta es la política predeterminada y para el programa promedio con algo de interacción. Realiza la preemption de otros procesos.

SCHED_FIFO Planificador Primero-En-Entrar, Primero-En-Salir, utilizado solo para restricciones en tiempo real. Los procesos de esta clase generalmente no son preemptados por otros, necesitan liberarse de la CPU mediante sched_yield() y, por lo tanto, necesita aplicaciones especialmente diseñadas. Usar con extrema precaución. Se requieren credenciales de ROOT.

SCHED_RR Planificador Round-Robin, también utilizado para restricciones en tiempo real. El tiempo de CPU se asigna en un modo round-robin con un intervalo de tiempo mucho menor que con SCHED_NORMAL y los procesos de este grupo tienen prioridad sobre SCHED_NORMAL. Útil para aplicaciones de audio/vídeo cerca de la tasa máxima del sistema. Se requieren credenciales de ROOT.

SCHED_BATCH [ desde 2.6.16 en mainline ] SCHED_BATCH fue diseñado para aplicaciones no interactivas y limitadas por CPU. Utiliza intervalos de tiempo más largos (para explotar mejor la caché), pero puede ser interrumpido en cualquier momento por otros procesos en otras clases para garantizar la interacción del sistema. Los procesos de esta clase se seleccionan al final, pero pueden resultar en una aceleración considerable (hasta un 300%). No se realiza ningún impulso interactivo.

SCHED_ISO [ se necesita parche ] SCHED_ISO fue diseñado para ofrecer a los usuarios una clase similar a SCHED_RR. Citando a Con Kolivas: "Esta es una política de planificación que no expira, diseñada para garantizar un intervalo de tiempo dentro de una latencia razonable al tiempo que se evita la inanición. Bueno para juegos, vídeo en los límites del hardware, captura de vídeo, etc."

SCHED_IDLEPRIO [ se necesita parche ] SCHED_IDLEPRIO es similar a SCHED_BATCH, pero fue diseñado explícitamente para consumir solo el tiempo que la CPU está inactiva. No se realiza ningún impulso interactivo. Si utilizó SCHED_BATCH en los kernels -ck, esto es lo que quiere desde 2.6.16

SUGERENCIAS

PID 0 significa "proceso actual", en nuestro caso, schedtool. Puede ocurrir al usar el interruptor -e.

¡Tenga cuidado con SCHED_FIFO! Puede bloquear a otros procesos fuera de la CPU, incluido su shell.

Para SCHED_BATCH, necesita ciertamente un kernel 2.6 reciente.

Se ofrece una breve descripción general en SCHED_DESIGN y el archivo README contiene una discusión exhaustiva. El archivo INSTALL también enumera todos los prerrequisitos y dónde puede obtener parches.

La afinidad 0x0 nunca debe usarse.
