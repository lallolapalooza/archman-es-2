NOMBRE

scache - Servidor de caché de conexión compartida de Postfix

SINOPSIS

scache [opciones genéricas de demonio de Postfix]

DESCRIPCIÓN


El servidor scache(8) mantiene una caché compartida de múltiples conexiones. Esta información puede ser utilizada por, por ejemplo, clientes SMTP de Postfix u otros agentes de entrega de Postfix.

La caché de conexiones se organiza en nombres lógicos de destino, nombres de puntos finales físicos y conexiones.

Como ejemplo específico, los destinos SMTP lógicos especifican (transporte, dominio, puerto), y los puntos finales SMTP físicos especifican (transporte, dirección IP, puerto). Una conexión SMTP puede guardarse después de una transacción de correo exitosa.

En el caso general, un destino lógico puede referirse a cero o más puntos finales físicos, un punto final físico puede ser referenciado por cero o más destinos lógicos, y un punto final puede referirse a cero o más conexiones.

La sintaxis exacta de un nombre de destino lógico o de punto final depende de la aplicación; al servidor scache(8) no le importa. Una conexión se almacena como un descriptor de archivo junto con información dependiente de la aplicación que se necesita para reactivar un objeto de conexión. Nuevamente, el servidor scache(8) desconoce completamente los detalles de esa información.

Toda la información se almacena con un tiempo de vida finito (ttl). El demonio de caché de conexiones termina cuando no hay ningún cliente conectado durante max_idle unidades de tiempo.

Este servidor implementa las siguientes solicitudes:

guardar_punto_final ttl punto_final propiedades_punto_final descriptor_archivo
Guarda el descriptor de archivo y los datos de propiedades de conexión especificados bajo el nombre de punto final especificado. Las propiedades del punto final son utilizadas por el cliente para reactivar un objeto de conexión pasivado.
buscar_punto_final punto_final
Busca propiedades cacheadas y un descriptor de archivo cacheado para el punto final especificado.
guardar_destino ttl destino propiedades_destino punto_final
Guarda la vinculación entre un destino lógico y un punto final bajo el nombre de destino, junto con propiedades de conexión específicas del destino. Las propiedades del destino son utilizadas por el cliente para reactivar un objeto de conexión pasivado.
buscar_destino destino
Busca propiedades de destino cacheadas, propiedades de punto final cacheadas y un descriptor de archivo cacheado para el destino lógico especificado.

SEGURIDAD

El servidor scache(8) no es sensible a la seguridad. No se comunica con la red, ni con usuarios locales. El servidor scache(8) puede ejecutarse chrooted con privilegios bajos fijos.

El servidor scache(8) no es un proceso confiable. No debe usarse para almacenar información sensible a la seguridad.

DIAGNÓSTICO


Los problemas y transacciones se registran en syslogd(8) o postlogd(8).

ERRORES


La caché de sesiones no se puede compartir entre múltiples máquinas.

Cuando una conexión expira de la caché, se cierra sin el apretón de manos específico del protocolo apropiado.

PARÁMETROS DE CONFIGURACIÓN

Los cambios en main.cf se capturan automáticamente ya que los procesos de scache(8) se ejecutan solo por un tiempo limitado. Use el comando "postfix reload" para acelerar un cambio.

El texto a continuación solo proporciona un resumen de los parámetros. Consulte postconf(5) para obtener más detalles, incluidos ejemplos.

CONTROLES DE RECURSOS

limite_actualizacion_ttl_cache_conexion (2s)
El valor máximo de tiempo de vida que permite el servidor de caché de conexiones scache(8).
tiempo_actualizacion_estado_cache_conexion (600s)
Con qué frecuencia el servidor scache(8) registra estadísticas de uso con tasas de aciertos y fallos de caché de conexiones para destinos lógicos y puntos finales físicos.

CONTROLES VARIOS

directorio_config (ver salida de 'postconf -d')
La ubicación predeterminada de los archivos de configuración main.cf y master.cf de Postfix.
tiempo_espera_demonio (18000s)
Cuánto tiempo puede tardar un proceso de demonio de Postfix en manejar una solicitud antes de que sea terminado por un temporizador de vigilancia incorporado.
tiempo_espera_ipc (3600s)
El límite de tiempo para enviar o recibir información a través de un canal de comunicación interno.
max_idle (100s)
La cantidad máxima de tiempo que un proceso de demonio de Postfix inactivo espera una conexión entrante antes de terminar voluntariamente.
id_proceso (solo lectura)
El ID del proceso de un comando o proceso de demonio de Postfix.
nombre_proceso (solo lectura)
El nombre del proceso de un comando o proceso de demonio de Postfix.
facility_syslog (mail)
La instalación de syslog para el registro de Postfix.
nombre_syslog (ver salida de 'postconf -d')
Un prefijo que se antepone al nombre del proceso en los registros de syslog, de modo que, por ejemplo, "smtpd" se convierte en "prefijo/smtpd".

Disponible en Postfix 3.3 y posteriores:

nombre_servicio (solo lectura)
El nombre del servicio master.cf de un proceso de demonio de Postfix.
