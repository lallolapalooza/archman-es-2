SCTP_PEELOFF(3) Manual del Programador de Linux SCTP_PEELOFF(3)

NOMBRE

sctp_peeloff - Desvincular una asociación en un socket separado.

SINOPSIS

#include <sys/types.h>
#include <sys/socket.h>
#include <netinet/sctp.h>

int sctp_peeloff(int sd, sctp_assoc_t assoc_id);
int sctp_peeloff_flags(int sd, sctp_assoc_t assoc_id, unsigned flags);

DESCRIPCIÓN

sctp_peeloff desvincula una asociación existente assoc_id en un socket de estilo uno a muchos sd en un socket separado. El nuevo socket es un socket de estilo uno a uno.

Esto es particularmente deseable cuando, por ejemplo, la aplicación desea mantener un número de remitentes/receptores de mensajes esporádicos bajo el socket original de estilo uno a muchos, pero desvincular aquellas asociaciones que transportan tráfico de datos de alto volumen en sus propios descriptores de socket separados.

sctp_peeloff_flags es una variante de sctp_peeloff, en la que se pueden especificar banderas que describen el comportamiento del socket recién desvinculado. Actualmente, las banderas admitidas son:

SOCK_NONBLOCK
Especifica que el nuevo socket no debe bloquearse en operaciones de E/S.
SOCK_CLOEXEC
Especifica que el nuevo socket debe cerrarse cuando el proceso propietario llame a exec.

VALOR DE RETORNO

En caso de éxito, se devuelve el nuevo descriptor de socket que representa la asociación desvinculada. En caso de error, se devuelve -1 y se establece errno apropiadamente.

ERRORES

EBADF
sd no es un descriptor válido.
EINVAL
El ID de asociación pasado no es válido o si el socket es un socket de estilo uno a uno.
ENOTSOCK
El argumento es un descriptor de archivo, no de socket.

NOTAS

sctp_peeloff_flags es una variante específica de Linux de sctp_peeloff. Aunque compilará en otros sistemas, su uso resultará en un error de retorno. El código portable debe usar sctp_peeloff.
