Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

sccs — interfaz para el subsistema SCCS (DESARROLLO)

SINOPSIS

sccs [-r] [-d ruta] [-p ruta] comando [opciones...] [operandos...]

DESCRIPCIÓN

La utilidad sccs es una interfaz para los programas SCCS. También incluye la capacidad de ejecutarse con el ID de usuario establecido a otro usuario para proporcionar protección adicional.

La utilidad sccs invocará el comando especificado con las opciones y operandos especificados. Por defecto, cada uno de los operandos se modificará anteponiéndoles la cadena "SCCS/s.".

El comando puede ser el nombre de una de las utilidades SCCS de este volumen de POSIX.1‐2017 (admin, delta, get, prs, rmdel, sact, unget, val o what) o uno de los pseudo-utilidades listados en la sección EXTENDED DESCRIPTION.

OPCIONES

La utilidad sccs se ajustará al volumen Base Definitions de POSIX.1‐2017, Sección 12.2, Pautas de sintaxis de utilidad, excepto que los operandos de opciones son en realidad opciones que se pasarán a la utilidad nombrada por comando. Cuando se considera la porción del comando:

comando [opciones ... ] [operandos ... ]

todos los pseudo-utilidades utilizados como comando cumplirán con las Pautas de Sintaxis de Utilidad. Cualquiera de las otras utilidades SCCS que se puedan invocar de esta manera soportan las Pautas en la medida indicada por sus secciones OPTIONS individuales.

Las siguientes opciones se soportarán precediendo al operando comando:

-d ruta
Una ruta de un directorio que se utilizará como directorio raíz para los archivos SCCS. El valor por defecto será el directorio actual. La opción -d tendrá prioridad sobre la variable PROJECTDIR. Consulte -p.
-p ruta
Una ruta de un directorio en el que se encuentran los archivos SCCS. El valor por defecto será el directorio SCCS.

La opción -p difiere de la opción -d en que el argumento de la opción -d se antepondrá a la ruta completa y el argumento de la opción -p se insertará antes del componente final de la ruta. Por ejemplo:

sccs -d /x -p y get a/b

se convierte en:

get /x/a/y/s.b

Esto permite la creación de alias como:

alias syssccs="sccs -d /usr/src"

que se utiliza como:

syssccs get cmd/who.c
-r
Invoca comando con el ID de usuario real del proceso, no con ningún ID de usuario efectivo al que se establezca la utilidad sccs. Ciertos comandos (admin, check, clean, diffs, info, rmdel y tell) no pueden ejecutarse con el ID de usuario establecido por todos los usuarios, ya que esto permitiría a cualquiera cambiar las autorizaciones. Estos comandos siempre se ejecutan como el usuario real.

OPERANDOS

Se soportarán los siguientes operandos:

comando
Un nombre de utilidad SCCS o el nombre de uno de los pseudo-utilidades listados en la sección EXTENDED DESCRIPTION.
opciones
Una opción o argumento de opción que se pasará a comando.
operandos
Un operando que se pasará a comando.

Las siguientes variables de entorno afectarán la ejecución de sccs:

Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen Base Definitions de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de locale.)
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en argumentos y archivos de entrada).
LC_MESSAGES

Determina la configuración regional que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en el error estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.
PROJECTDIR

Proporciona un valor predeterminado para la opción -d ruta. Si el valor de PROJECTDIR comienza con una barra inclinada (<barra inclinada>), se considerará una ruta absoluta; de lo contrario, el valor de PROJECTDIR se tratará como un nombre de usuario y se examinará el directorio de trabajo inicial de ese usuario en busca de un subdirectorio src o source. Si se encuentra dicho directorio, se utilizará. De lo contrario, el valor se utilizará como una ruta relativa.

Los efectos adicionales de las variables de entorno pueden encontrarse en la descripción de la utilidad para el comando especificado.

NAME

sccs - front end for the Source Code Control System

SYNOPSIS

    sccs [options] [g-file...]

DESCRIPTION

The sccs utility is a front end for the Source Code Control System (SCCS). It allows a user to invoke various SCCS pseudo-utilities, such as admin, delta, get, etc. The exact set of pseudo-utilities supported by sccs is implementation-defined, but shall include those described in the following sections.

The pseudo-utilities are invoked by providing an option string to sccs which begins with a hyphen and the name of the pseudo-utility, followed by any options or operands required by the underlying SCCS utility.

For example, to invoke sccs delta to create a delta for the file s.file.c with the comment option -m, the command line would be:

sccs delta -m "comment" s.file.c

Note that the file operands for the SCCS utilities are typically prefixed with "s.". The sccs utility does not require the "s." prefix for file operands. It adds the prefix if necessary. If the files are specified without the "s." prefix, sccs appends the prefix and searches for the file in the current directory or in the SCCS file directory (see get (1)).

The standard SCCS utilities typically operate on files in the current directory. The sccs utility provides a mechanism to specify a different SCCS file directory. If the first operand to sccs is not a valid pseudo-utility option (i.e., it does not begin with a hyphen, or it is an unknown pseudo-utility), it is treated as an SCCS file directory pathname. Any subsequent pseudo-utility options and operands are then applied to SCCS files found in that directory.

For example:

sccs -r/usr/src/sccs get file.c

retrieves file.c from the SCCS directory `/usr/src/sccs/s.file.c.

If the -r directory option is given, it is passed as the -d option to the underlying SCCS utility.

The default SCCS file directory is the subdirectory named "sccs" in the current directory.

OPTIONS

The following options are supported by the sccs utility itself:

[-r directory]
Use the specified directory as the root of the SCCS directory tree. This option is passed as the -d option to the underlying SCCS utility.

Any other options are treated as operands for the underlying SCCS utility.

OPERANDS

The operands depend on the pseudo-utility being invoked. For example, the get pseudo-utility takes filenames as operands.

STDIN

Input from standard input is used only when the underlying SCCS utility requires it, typically for commands that operate on multiple files, like delta.

INPUT FILES

The input files depend on the pseudo-utility being invoked.

ENVIRONMENT VARIABLES

The following environment variables are used:

HOME
Used to determine the user's home directory when the SCCS file directory is not specified via the -r option.
SHELL
Used to invoke an editor.
TZ
Used to convert between local, standard, and Daylight Saving time. See get (1).

In addition, the following environment variables are used by the underlying SCCS utilities:

USER
See get (1).
EDITOR
See get (1).

ASYNCHRONOUS EVENTS

Default.

STDOUT

The standard output depends on the pseudo-utility being invoked. Typically, it is used for informational messages and the results of commands like get.

STDERR

Standard error is used for error messages.

OUTPUT FILES

The output files depend on the pseudo-utility being invoked. For example, get creates file copies.

EXTENDED DESCRIPTION

The following pseudo-utilities are supported:

admin
Create SCCS files or designate ignored files. Any options to the SCCS admin utility are accepted.
archelp
A help command for the SCCS archive file format. It is useful for debugging problems that might arise when manipulating SCCS files.
cdc
Change the description, comment, and author information of SCCS files. The -r and -m options to cdc are accepted.
check
Check that each file named by an operand is a checked-out file that has been modified. Write a list of files being edited to standard output. The options -b, -u, and -U are accepted.
cm4v
The cm4v utility is used to check the validity of SCCS files. It detects inconsistencies in the SCCS file, such as incorrect magic numbers, bad character counts, or incorrect delta table entries. It can also be used to check for potential problems, like missing delta tables or duplicate SIDs. The primary purpose of cm4v is to ensure the integrity of SCCS files and to prevent corruption that could lead to data loss or errors. It is often used in conjunction with other SCCS maintenance tools like admin and delta to maintain a healthy SCCS repository. The default behavior is to check all SCCS files in the current directory. The command supports options to specify target files, recursion into subdirectories, and different levels of checking. The output of cm4v provides detailed reports on any issues found, along with recommendations for remediation. This utility is crucial for SCCS administration and maintenance.
comb
Combine the SCCS deltas from the given files into a single delta. This command is useful for cleaning up the SCCS history by reducing the number of individual deltas. The options -s, -x, -y, and -p are accepted.
cpio
Archive file is extracted from or created for an SCCS file. The options -o, -i, -p, -r, -t, -c, -b, -d, -m, -s, -v, -K, and -H are accepted.
date
Write the date and time at which each SCCS file was last modified. Any options to the SCCS date utility are accepted.
delta
Create a delta (a new version) from an SCCS text file. Any options to the SCCS delta utility are accepted.
get
Retrieve SCCS files. Any options to the SCCS get utility are accepted.
help
Provide help information for SCCS commands. The -i and -x options are accepted.
prs
Print a specified file or the history of a specified file. Any options to the SCCS prs utility are accepted.
rcsdiff
Compare two versions of an SCCS file. The options -r, -c, -e, -i, -x, -t, -l, -s, -f, -h, and -b are accepted.
rmdelt
Remove a delta from an SCCS file. The options -s, -n, -f, and -z are accepted.
sact
Determine which files are being edited. The -u option is accepted.
scompare
Compare the differences between two SCCS files. The options -e, -l, -r, -s, -t, -x, and -C are accepted. The -C option is passed to diff as -c.
sedit
Apply a set of specified transformations to each SCCS file. The transformations are applied individually to each file. The options -e, -r, -s, -p, -f, -i, -x, and -l are accepted.
sf
Update SCCS files. The options -d, -u, -v, -r, -c, -p, -s, -i, -x, -f, -h, and -l are accepted.
sget
Retrieve SCCS files. This is equivalent to get. The options -r, -c, -e, -p, -k, -s, -t, -x, -i, -k, -l, -b, and -q are accepted.
shelp
Provide help information for SCCS commands. This is equivalent to help.
sinfo
Write information about files being edited. This is equivalent to info.
skey
Generate the keys (SIDs) for SCCS files. The options -h, -n, -s, -e, -a, -u, -b, -d, -f, -l, -p, -t, and -v are accepted.
sls
List the contents of an SCCS file. The options -a, -v, -l, -p, -f, -h, -r, -c, -d, -b, and -x are accepted.
smerge
Merge SCCS files. The options -e, -r, -s, -p, -f, -i, -x, -l, -b, and -v are accepted.
sremove
Remove SCCS files. This is equivalent to rmdel.
srev
Write the SCCS file ID (SID) for the specified file to standard output. The options -h, -n, -s, -e, -a, -u, -b, -d, -f, -l, -p, -t, and -v are accepted.
ssearch
Search for SCCS files matching specified criteria. The options -a, -v, -u, -s, -p, -f, -h, -r, -c, -d, -b, and -x are accepted.
sstat
Write various pieces of information about SCCS files. The options -a, -b, -c, -d, -f, -h, -i, -l, -p, -r, -s, -t, -u, -v, and -x are accepted.
stouch
Update the "each file was edited" flags for SCCS files. The options -a, -b, -c, -d, -f, -h, -i, -l, -p, -r, -s, -t, -u, -v, and -x are accepted.
sval
Validate SCCS files. This is equivalent to val. The options -a, -b, -c, -d, -f, -h, -i, -l, -p, -r, -s, -t, -u, -v, and -x are accepted.
swhat
Extract SCCS version information from source files. This is equivalent to what.
unget
Undo the effects of a get -e. This command is used to discard changes made to a file that was checked out for editing. If the file has been modified since it was retrieved with get -e, unget will report that the changes will be lost. The options -s and -k are accepted.
xargs
Build and execute command lines from standard input. The options -t, -n, -s, -l, -i, -f, -d, -p, -R, -s, -x, -P, and -R are accepted.

The following pseudo-utilities are also supported:

branch
Create a new branch delta for the named file. Any options to admin that create a new branch are accepted. If the branch creation is successful, the original file shall be renamed by prefixing the basename with a comma. These renamed files should be removed after it has been verified that the SCCS files have been created successfully.
create
Create an SCCS file, taking the initial contents from the file of the same name. Any options to admin are accepted. If the creation is successful, the original files shall be renamed by prefixing the basenames with a comma. These renamed files should be removed after it has been verified that the SCCS files have been created successfully.
delget
Perform a delta on the named files and then get new versions. The new versions shall have ID keywords expanded and shall not be editable. Any -m, -p, -r, -s, and -y options shall be passed to delta, and any -b, -c, -e, -i, -k, -l, -s, and -x options shall be passed to get.
deledit
Equivalent to delget, except that the get phase shall include the -e option. This option is useful for making a checkpoint of the current editing phase. The same options shall be passed to delta as described above, and all the options listed for get above except -e shall be passed to edit.
diffs
Write a difference listing between the current version of the files checked out for editing and the versions in SCCS format. Any -r, -c, -i, -x, and -t options shall be passed to get; any -l, -s, -e, -f, -h, and -b options shall be passed to diff. A -C option shall be passed to diff as -c.
edit
Equivalent to get -e.
fix
Remove the named delta, but leave a copy of the delta with the changes that were in it. It is useful for fixing small compiler bugs, and so on. The application shall ensure that it is followed by a -r SID option. Since fix does not leave audit trails, it should be used carefully.
info
Write a listing of all files being edited. If the -b option is given, branches (that is, SIDs with two or fewer components) shall be ignored. If a -u user option is given, then only files being edited by the named user shall be listed. A -U option shall be equivalent to -u<current user>.
print
Write out verbose information about the named files, equivalent to sccs prs.
tell
Write a <newline>-separated list of the files being edited to standard output. Takes the -b, -u, and -U options like info and check.
unedit
This is the opposite of an edit or a get -e. It should be used with caution, since any changes made since the get are lost.

EXIT STATUS

The following exit values shall be returned:

 0
Successful completion.
>0
An error occurred.

CONSEQUENCES OF ERRORS

Default.

The following sections are informative.

APPLICATION USAGE

Many of the SCCS utilities take directory names as operands as well as specific filenames. The pseudo-utilities supported by sccs are not described as having this capability, but are not prohibited from doing so.

EXAMPLES

1.
To get a file for editing, edit it and produce a new delta:
sccs get -e file.c
ex file.c
sccs delta file.c
2.
To get a file from another directory:
sccs -p /usr/src/sccs/sccs get cc.c

or:

sccs get /usr/src/sccs/s.cc.c
3.
To make a delta of a large number of files in the current directory:
sccs delta *.c
4.
To get a list of files being edited that are not on branches:
sccs info -b
5.
To delta everything being edited by the current user:
sccs delta $(sccs tell -U)
6.
In a makefile, to get source files from an SCCS file if it does not already exist:
SRCS = <list of source files>
$(SRCS):
    sccs get $(REL) $@

RATIONALE

sccs and its associated utilities are part of the XSI Development Utilities option within the XSI option.

SCCS is an abbreviation for Source Code Control System. It is a maintenance and enhancement tracking tool. When a file is put under SCCS, the source code control system maintains the file and, when changes are made, identifies and stores them in the file with the original source code and/or documentation. As other changes are made, they too are identified and retained in the file.

Retrieval of the original and any set of changes is possible. Any version of the file as it develops can be reconstructed for inspection or additional modification. History data can be stored with each version, documenting why the changes were made, who made them, and when they were made.

RESUMEN

sccs [ options ] [ files ]

DESCRIPCIÓN

El comando sccs es una utilidad de control de versiones que permite a los usuarios gestionar diferentes versiones de archivos. Permite rastrear cambios, recuperar versiones anteriores y colaborar en proyectos de desarrollo de software.

Las options son modificadores que cambian el comportamiento del comando. Los files son los archivos en los que opera el comando.

EJEMPLO

Para obtener la última versión de un archivo llamado miarchivo.c, usaría:

sccs get miarchivo.c

Para registrar un cambio en el archivo miarchivo.c, usaría:

sccs delta miarchivo.c
