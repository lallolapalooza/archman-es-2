Paquete: tcl

Licencias: TCL

scan(n) Tcl Built-In Commands scan(n)

NOMBRE

scan - Analiza una cadena usando especificadores de conversión al estilo de sscanf

SINOPSIS

scan cadena formato ?varName varName ...?

INTRODUCCIÓN

Este comando analiza subcadenas de una cadena de entrada de manera similar al procedimiento sscanf de C ANSI y devuelve el número de conversiones realizadas, o -1 si se alcanza el final de la cadena de entrada antes de que se haya realizado alguna conversión. Cadena proporciona la entrada a analizar y formato indica cómo analizarla, utilizando especificadores de conversión % como en sscanf. Cada varName da el nombre de una variable; cuando se escanea una subcadena de cadena que coincide con un especificador de conversión, la subcadena se asigna a la variable correspondiente. Si no se especifican variables varName, entonces scan funciona de manera en línea, devolviendo los datos que de otro modo se almacenarían en las variables como una lista. En el caso en línea, se devuelve una cadena vacía cuando se alcanza el final de la cadena de entrada antes de que se hayan realizado conversiones.

DETALLES SOBRE EL ANÁLISIS

Scan opera analizando cadena y formato juntos. Si el siguiente carácter en formato es un espacio en blanco o una tabulación, entonces coincide con cualquier número de caracteres de espacio en blanco en cadena (incluido cero). De lo contrario, si no es un carácter %, debe coincidir con el siguiente carácter de cadena. Cuando se encuentra un % en formato, indica el inicio de un especificador de conversión. Un especificador de conversión contiene hasta cuatro campos después del %: un especificador de posición XPG3 (o un * para indicar que el valor convertido se descartará en lugar de asignarse a cualquier variable); un número que indica un ancho de subcadena máximo; un modificador de tamaño; y un carácter de conversión. Todos estos campos son opcionales excepto el carácter de conversión. Los campos que están presentes deben aparecer en el orden dado anteriormente.

Cuando scan encuentra un especificador de conversión en formato, primero omite cualquier carácter de espacio en blanco en cadena (a menos que el carácter de conversión sea [ o c). Luego convierte los siguientes caracteres de entrada según el especificador de conversión y almacena el resultado en la variable proporcionada por el siguiente argumento a scan.

ESPECIFICADOR POSICIONAL OPCIONAL

Si el % va seguido de un número decimal y un $, como en "%2$d", entonces la variable a usar no se toma del siguiente argumento secuencial. En su lugar, se toma del argumento indicado por el número, donde 1 corresponde al primer varName. Si hay algún especificador posicional en formato, entonces todos los especificadores deben ser posicionales. Cada varName en la lista de argumentos debe corresponder a exactamente un especificador de conversión o se generará un error, o en el caso en línea, cualquier posición se puede especificar como máximo una vez y las posiciones vacías se llenarán con cadenas vacías.

MODIFICADOR DE TAMAÑO OPCIONAL

El campo del modificador de tamaño se utiliza solo al analizar una subcadena en uno de los valores enteros de Tcl. El campo del modificador de tamaño dicta el rango entero aceptable para almacenar en una variable o, en el caso en línea, en una posición de la lista de resultados. Los valores sintácticamente válidos para el modificador de tamaño son h, L, l y ll. El valor del modificador de tamaño h es equivalente a la ausencia de un modificador de tamaño en el especificador de conversión. Cualquiera de los dos indica que el rango entero a almacenar se limita al mismo rango producido por la función int() del comando expr. El modificador de tamaño L es equivalente al modificador de tamaño l. Cualquiera de los dos indica que el rango entero a almacenar se limita al mismo rango producido por la función wide() del comando expr. El modificador de tamaño ll indica que el rango entero a almacenar es ilimitado.

CARÁCTER DE CONVERSIÓN OBLIGATORIO

Se admiten los siguientes caracteres de conversión:

d
La subcadena de entrada debe ser un entero decimal. Se lee y el valor entero se almacena en la variable, truncado según lo requiera el valor del modificador de tamaño.
o
La subcadena de entrada debe ser un entero octal. Se lee y el valor entero se almacena en la variable, truncado según lo requiera el valor del modificador de tamaño.
x o X
La subcadena de entrada debe ser un entero hexadecimal. Se lee y el valor entero se almacena en la variable, truncado según lo requiera el valor del modificador de tamaño.
b
La subcadena de entrada debe ser un entero binario. Se lee y el valor entero se almacena en la variable, truncado según lo requiera el valor del modificador de tamaño.
u
La subcadena de entrada debe ser un entero decimal. El valor entero se trunca según lo requiera el modificador de tamaño, y se calcula el valor sin signo correspondiente para ese rango truncado y se almacena en la variable como una cadena decimal. La conversión no tiene sentido sin referencia a un rango de truncamiento, por lo que el modificador de tamaño ll no está permitido en combinación con el carácter de conversión u.
i
La subcadena de entrada debe ser un entero. La base (es decir, decimal, octal o hexadecimal) se determina por la convención C (0 inicial para octal; prefijo 0x para hexadecimal). El valor entero se almacena en la variable, truncado según lo requiera el valor del modificador de tamaño.
c
Se lee un solo carácter y su valor Unicode se almacena en la variable como un valor entero. Los espacios en blanco iniciales no se omiten en este caso, por lo que la subcadena de entrada puede ser un carácter de espacio en blanco.
s
La subcadena de entrada consta de todos los caracteres hasta el siguiente carácter de espacio en blanco; los caracteres se copian en la variable.
e o f o g o E o G
La subcadena de entrada debe ser un número de punto flotante que consta de un signo opcional, una cadena de dígitos decimales que posiblemente contenga un punto decimal y un exponente opcional que consta de una e o E seguida de un signo opcional y una cadena de dígitos decimales. Se lee y se almacena en la variable como un valor de punto flotante.
[chars]
La subcadena de entrada consta de uno o más caracteres de chars. La cadena coincidente se almacena en la variable. Si el primer carácter entre los corchetes es un ], se trata como parte de chars en lugar del corchete de cierre del conjunto. Si chars contiene una secuencia de la forma a-b, entonces cualquier carácter entre a y b (inclusive) coincidirá. Si el primer o el último carácter entre los corchetes es un -, se tratará como parte de chars en lugar de indicar un rango.
[^chars]
La subcadena de entrada consta de uno o más caracteres que no están en chars. La cadena coincidente se almacena en la variable. Si el carácter inmediatamente posterior al ^ es un ], se trata como parte del conjunto en lugar del corchete de cierre del conjunto. Si chars contiene una secuencia de la forma a-b, entonces cualquier carácter entre a y b (inclusive) se excluirá del conjunto. Si el primer o el último carácter entre los corchetes es un -, se tratará como parte de chars en lugar de indicar un valor de rango.
n
No se consume entrada de la cadena de entrada. En su lugar, el número total de caracteres escaneados de la cadena de entrada hasta ahora se almacena en la variable.

El número de caracteres leídos de la entrada para una conversión es el mayor número que tiene sentido para esa conversión particular (por ejemplo, tantos dígitos decimales como sea posible para %d, tantos dígitos octales como sea posible para %o, y así sucesivamente). La conversión termina cuando se encuentra un carácter de espacio en blanco o cuando se alcanza el ancho máximo de subcadena, lo que ocurra primero. Si hay un * en el especificador de conversión, no se asigna ninguna variable y no se consume el siguiente argumento de escaneo.

DIFERENCIAS CON ANSI SSCANF

El comportamiento del comando scan es el mismo que el comportamiento del procedimiento ANSI C sscanf, excepto por las siguientes diferencias:

[1]
No se admite el especificador de conversión %p.
[2]
Para las conversiones %c, un valor de un solo carácter se convierte en una cadena decimal, que luego se asigna a la varName correspondiente; no se puede especificar un ancho de subcadena para esta conversión.
[3]
El modificador h siempre se ignora y los modificadores l y L se ignoran al convertir valores reales (es decir, el tipo double se utiliza para la representación interna). El modificador ll no tiene contraparte en sscanf.
[4]
Si se llega al final de la cadena de entrada antes de que se haya realizado alguna conversión y no se proporcionan variables, se devuelve una cadena vacía.

EJEMPLOS

Convertir un carácter UNICODE a su valor numérico:

set char "x"
set value [scan $char %c]

Analizar una especificación de color simple de la forma #RRGGBB utilizando conversiones hexadecimales con tamaños de subcadena:

set string "#08D03F"
scan $string "#%2x%2x%2x" r g b

Analizar una cadena de tiempo HH:MM, señalando que esto evita problemas con números octales al forzar la interpretación como decimales (si no nos importara, usaríamos la conversión %i en su lugar):

set string "08:08"   ;# ¡*No* es octal!
if {[scan $string "%d:%d" hours minutes] != 2} {
    error "not a valid time string"
}
# Tenemos que entender los rangos numéricos nosotros mismos...
if {$minutes < 0 || $minutes > 59} {
    error "invalid number of minutes"
}

Dividir una cadena en secuencias de caracteres que no sean espacios en blanco (tenga en cuenta el uso de la conversión %n para que el salto de los espacios en blanco iniciales sea correcto):

set string " a string {con palabras entre llaves} + espacio inicial "
set words {}
while {[scan $string %s%n word length] == 2} {
    lappend words $word
    set string [string range $string $length end]
}

Analizar una cadena de coordenadas simple, comprobando que está completa buscando explícitamente el carácter de terminación:

set string "(5.2,-4e-2)"
# Tenga en cuenta que los espacios antes de las partes literales del
# patrón de escaneo son significativos, y que ")" es
# el carácter Unicode \u0029
if {
    [scan $string " (%f ,%f %c" x y last] != 3
    || $last != 0x0029
} then {
    error "invalid coordinate string"
}
puts "X=$x, Y=$y"

Una sesión interactiva que demuestra la truncación de valores enteros determinada por los modificadores de tamaño:

% set tcl_platform(wordSize)
4
% scan 20000000000000000000 %d
2147483647
% scan 20000000000000000000 %ld
9223372036854775807
% scan 20000000000000000000 %lld
20000000000000000000
