sched_setscheduler(2) Manual de Llamadas al Sistema sched_setscheduler(2)

NOMBRE

sched_setscheduler, sched_getscheduler - establecer y obtener la política/parámetros de planificación

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sched.h>
int sched_setscheduler(pid_t pid, int policy,
                       const struct sched_param *param);
int sched_getscheduler(pid_t pid);

DESCRIPCIÓN

La llamada al sistema sched_setscheduler() establece la política de planificación y los parámetros para el hilo cuyo ID se especifica en pid. Si pid es cero, se establecerán la política de planificación y los parámetros del hilo que realiza la llamada.

Los parámetros de planificación se especifican en el argumento param, que es un puntero a una estructura de la siguiente forma:


struct sched_param {
    ...
    int sched_priority;
    ...
};

En la implementación actual, la estructura contiene solo un campo, sched_priority. La interpretación de param depende de la política seleccionada.

Actualmente, Linux soporta las siguientes políticas de planificación "normales" (es decir, no en tiempo real) como valores que pueden especificarse en policy:

SCHED_OTHER
la política estándar de intercambio de tiempo round-robin;
SCHED_BATCH
para ejecución de procesos estilo "batch"; y
SCHED_IDLE
para ejecutar trabajos de fondo de muy baja prioridad.

Para cada una de las políticas anteriores, param->sched_priority debe ser 0.

También se soportan varias políticas de "tiempo real", para aplicaciones especiales críticas en tiempo que necesitan un control preciso sobre la forma en que se seleccionan los hilos ejecutables para su ejecución. Para las reglas que rigen cuándo un proceso puede usar estas políticas, consulte sched(7). Las políticas de tiempo real que se pueden especificar en policy son:

SCHED_FIFO
una política primero en entrar, primero en salir (FIFO); y
SCHED_RR
una política round-robin.

Para cada una de las políticas anteriores, param->sched_priority especifica una prioridad de planificación para el hilo. Este es un número en el rango devuelto al llamar a sched_get_priority_min(2) y sched_get_priority_max(2) con la política policy especificada. En Linux, estas llamadas al sistema devuelven, respectivamente, 1 y 99.

Desde Linux 2.6.32, se puede ORear el flag SCHED_RESET_ON_FORK en policy al llamar a sched_setscheduler(). Como resultado de incluir este flag, los hijos creados por fork(2) no heredan políticas de planificación privilegiadas. Consulte sched(7) para obtener más detalles.

sched_getscheduler() devuelve la política de planificación actual del hilo identificado por pid. Si pid es cero, se recuperará la política del hilo que realiza la llamada.

VALOR DE RETORNO

En caso de éxito, sched_setscheduler() devuelve cero. En caso de éxito, sched_getscheduler() devuelve la política del hilo (un entero no negativo). En caso de error, ambas llamadas devuelven -1 y errno se establece para indicar el error.

ERRORES

EINVAL
Argumentos inválidos: pid es negativo o param es NULL.
EINVAL
(sched_setscheduler()) policy no es una de las políticas reconocidas.
EINVAL
(sched_setscheduler()) param no tiene sentido para la policy especificada.
EPERM
El hilo que realiza la llamada no tiene los privilegios adecuados.
ESRCH
El hilo cuyo ID es pid no se pudo encontrar.

VERSIONES

POSIX.1 no detalla los permisos que un hilo no privilegiado requiere para llamar a sched_setscheduler(), y los detalles varían entre sistemas. Por ejemplo, la página del manual de Solaris 7 dice que el ID de usuario real o efectivo del llamador debe coincidir con el ID de usuario real o el ID de usuario guardado del destino.

La política y los parámetros de planificación son, de hecho, atributos por hilo en Linux. El valor devuelto por una llamada a gettid(2) puede pasarse en el argumento pid. Especificar pid como 0 operará sobre los atributos del hilo que realiza la llamada, y pasar el valor devuelto por una llamada a getpid(2) operará sobre los atributos del hilo principal del grupo de hilos. (Si está utilizando la API de hilos POSIX, utilice pthread_setschedparam(3), pthread_getschedparam(3) y pthread_setschedprio(3), en lugar de las llamadas al sistema sched_*(2).)

ESTáNDARES

POSIX.1-2024 (pero consulte BUGS a continuación).

SCHED_BATCH y SCHED_IDLE son específicos de Linux.

HISTORIA

POSIX.1-2001.

NOTAS

Se pueden encontrar más detalles sobre la semántica de todas las políticas de planificación "normales" y "de tiempo real" anteriores en la página del manual sched(7). Esa página también describe una política adicional, SCHED_DEADLINE, que solo se puede establecer a través de sched_setattr(2).

Los sistemas POSIX en los que sched_setscheduler() y sched_getscheduler() están disponibles definen _POSIX_PRIORITY_SCHEDULING en <unistd.h>.

ERRORES GRAVES

POSIX.1 dice que en caso de éxito, sched_setscheduler() debería devolver la política de planificación anterior. El Linux sched_setscheduler() no cumple este requisito, ya que siempre devuelve 0 en caso de éxito.
