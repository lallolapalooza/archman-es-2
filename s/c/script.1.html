SCRIPT(1) Comandos de usuario SCRIPT(1)

NOMBRE

script - crear una transcripción de la sesión del terminal

SINOPSIS

script [opciones] [archivo]

DESCRIPCIÓN

script crea una transcripción de todo lo que ocurre en la sesión de tu terminal. Los datos del terminal se almacenan en formato crudo en el archivo de registro y la información sobre el tiempo en otro archivo de registro estructurado (opcional). El archivo de registro de tiempo es necesario para reproducir la sesión más tarde con scriptreplay(1) y para almacenar información adicional sobre la sesión.

Desde la versión 2.35, script soporta múltiples flujos y permite el registro de entrada y salida a archivos separados o todo en un único archivo. Esta versión también soporta un nuevo archivo de tiempo que registra información adicional. El comando scriptreplay --summary entonces proporciona toda la información.

Si se proporciona el argumento archivo o la opción --log-out archivo, script guarda el diálogo en este archivo. Si no se proporciona nombre de archivo, el diálogo se guarda en el archivo typescript.

Ten en cuenta que el registro de entrada usando --log-in o --log-io puede registrar información sensible para la seguridad, ya que el archivo de registro contiene toda la entrada de la sesión del terminal (por ejemplo, contraseñas) independientemente de la configuración del eco del terminal.

OPCIONES

A continuación, el argumento tamaño puede ir seguido de los sufijos multiplicadores KiB (=1024), MiB (=1024*1024), y así sucesivamente para GiB, TiB, PiB, EiB, ZiB e YiB (la opción "iB" es opcional, por ejemplo, "K" tiene el mismo significado que "KiB"), o los sufijos KB (=1000), MB (=1000*1000), y así sucesivamente para GB, TB, PB, EB, ZB e YB.

-a, --append

Añade la salida al archivo o a typescript, conservando el contenido previo.

-c, --command comando

Ejecuta el comando en lugar de un shell interactivo. Esto facilita que un script capture la salida de un programa que se comporta de manera diferente cuando su salida estándar no es una tty.

-E, --echo cuándo

Esta opción controla el flag ECHO para el extremo esclavo del pseudoterminal de la sesión. Los modos soportados son always (siempre), never (nunca), o auto.

El valor predeterminado es auto; en este caso, ECHO está habilitado para el esclavo pseudoterminal; si la entrada estándar actual es un terminal, ECHO está deshabilitado para evitar el doble eco; si la entrada estándar actual no es un terminal (por ejemplo, una tubería: echo date | script) entonces mantener ECHO habilitado para el esclavo pseudoterminal permite que los datos de entrada estándar se vean en pantalla mientras se registran simultáneamente en el registro de sesión.

Ten en cuenta que el modo 'never' afecta al contenido del registro de salida de la sesión, ya que la entrada del usuario no se repite en la salida.

-e, --return

Devuelve el estado de salida del proceso hijo. Utiliza el mismo formato que la terminación de bash por señal (es decir, el estado de salida es 128 + el número de señal). El estado de salida del proceso hijo siempre se almacena también en el archivo de tipo script.

-f, --flush

Vacía la salida después de cada escritura. Esto es bueno para la telecooperación: una persona crea mkfifo foo; script -f foo, y otra puede supervisar en tiempo real lo que se está haciendo usando cat foo. Ten en cuenta que el vaciado afecta al rendimiento; es posible usar SIGUSR1 para vaciar los registros bajo demanda.

--force

Permite que el archivo de salida predeterminado typescript sea un enlace duro o simbólico. El comando seguirá un enlace simbólico.

-B, --log-io archivo

Registra la entrada y la salida en el mismo archivo. Ten en cuenta que esta opción solo tiene sentido si también se especifica --log-timing, de lo contrario, es imposible separar los flujos de entrada y salida del archivo de registro archivo.

-I, --log-in archivo

Registra la entrada en el archivo. El registro de salida se deshabilita si solo se especifica --log-in.

Utiliza esta funcionalidad de registro con cuidado, ya que registra toda la entrada, incluida la entrada cuando el terminal tiene el eco deshabilitado (por ejemplo, entradas de contraseñas).

-O, --log-out archivo

Registra la salida en el archivo. Por defecto, se registra la salida en el archivo llamado typescript si no se especifica la opción --log-out o --log-in. El registro de salida se deshabilita si solo se especifica --log-in.

-T, --log-timing archivo

Registra la información de tiempo en el archivo. Ahora se admiten dos formatos de archivo de tiempo. El formato clásico se usa cuando solo se habilita el registro de un flujo (entrada o salida). El formato multiflujo se usa en --log-io o cuando se usan juntos --log-in y --log-out. Ver también --logging-format.

-m, --logging-format formato

Forzar el uso del formato de registro de tiempo avanzado o clásico. El valor predeterminado es el formato clásico para registrar solo la salida y el formato avanzado cuando se solicita el registro tanto de entrada como de salida.

Formato clásico

El registro de tiempo contiene dos campos, separados por un espacio. El primer campo indica cuánto tiempo ha transcurrido desde la salida anterior. El segundo campo indica cuántos caracteres se emitieron en ese momento.

Formato avanzado (multiflujo)

El primer campo es un identificador de tipo de entrada ('I' de entrada, 'O' de salida, 'H' de cabecera, 'S' de señal). El segundo campo indica cuánto tiempo ha transcurrido desde la entrada anterior, y el resto de la entrada son datos específicos del tipo.

-o, --output-limit tamaño

Limita el tamaño de los archivos typescript y de tiempo a tamaño y detiene el proceso hijo después de superar este tamaño. El tamaño de archivo calculado no incluye los mensajes de inicio y fin que el comando script antepone y pospone a la salida del proceso hijo. Debido al almacenamiento en búfer, el archivo de salida resultante puede ser mayor que el valor especificado.

-q, --quiet

Silencioso (no escribe mensajes de inicio y fin en la salida estándar).

-t[archivo], --timing[=archivo]

Envía datos de tiempo a la salida de error estándar, o a archivo cuando se proporciona. Esta opción está obsoleta en favor de --log-timing donde el argumento archivo no es opcional.

-h, --help

Muestra el texto de ayuda y sale.

-V, --version

Muestra la versión y sale.

SEÑALES

Al recibir SIGUSR1, script vacía inmediatamente los archivos de salida.

ENTORNO

La siguiente variable de entorno es utilizada por script:

SHELL

Si la variable SHELL existe, el shell forkeado por script será ese shell. Si SHELL no está configurada, se asume el shell Bourne. (La mayoría de los shells configuran esta variable automáticamente).

NOTAS

El script termina cuando el shell forkeado sale (un control-D para el shell Bourne (sh(1p)), y exit, logout o control-d (si ignoreeof no está configurado) para el shell C, csh(1)).

Ciertos comandos interactivos, como vi(1), crean basura en el archivo typescript. script funciona mejor con comandos que no manipulan la pantalla; los resultados están destinados a emular una terminal de copia impresa.

No se recomienda ejecutar script en shells no interactivos. El shell interno de script es siempre interactivo, y esto podría llevar a resultados inesperados. Si usas script en el archivo de inicialización del shell, debes evitar entrar en un bucle infinito. Puedes usar, por ejemplo, el archivo .profile, que solo es leído por los shells de inicio de sesión:

if test -t 0 ; t

NOTES

The script utility is primarily designed for interactive terminal sessions. When stdin is not a terminal (e.g. echo foo | script), the session can hang, because the interactive shell within the script session misses EOF and script has no clue when to close the session. A common workaround is to use the -e option:

$ echo foo | script -e
$ exit
fi

También debe evitar el uso de script en pipes de comandos, ya que script puede leer más entrada de la que espera.

HISTORIA

El comando script apareció en 3.0BSD.

BUGS

script coloca *todo* en el archivo de registro, incluyendo saltos de línea y retrocesos. Esto no es lo que espera el usuario ingenuo.

script está diseñado principalmente para sesiones de terminal interactivas. Cuando stdin no es una terminal (por ejemplo: echo foo | script), la sesión puede colgarse, porque el shell interactivo dentro de la sesión de script pierde EOF y script no tiene ni idea de cuándo cerrar la sesión. Ver la sección de NOTAS para más información.
