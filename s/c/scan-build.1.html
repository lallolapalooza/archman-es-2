NOMBRE

scan-build — Analizador estático de Clang

SINOPSIS

scan-build [-ohkvV] [-analyze-headers] [-enable-checker [nombre_verificador]] [-disable-checker [nombre_verificador]] [--help] [--help-checkers] [--html-title [=título]] [--keep-going] [-plist] [-plist-html] [--status-bugs] [--use-c++ [ruta_compilador]] [--use-cc [ruta_compilador]] [--view] [-constraints [modelo]] [-maxloop N] [-no-failure-reports] [-stats] [-store [modelo]] comando_construccion [opciones_construccion]

DESCRIPCIÓN

scan-build es un script de Perl que invoca al analizador estático de Clang. Las opciones utilizadas por scan-build o por el analizador aparecen primero, seguidas por el comando_construccion y cualquier opciones_construccion que se usen normalmente para construir el sistema de destino.

El analizador estático emplea una larga lista de algoritmos de verificación, ver VERIFICADORES. La salida puede escribirse en formato .plist y/o HTML.

Las siguientes opciones son compatibles:

-analyze-headers
Analizar también funciones en archivos #include.
-enable-checker nombre_verificador, -disable-checker nombre_verificador
Habilitar/deshabilitar nombre_verificador. Ver VERIFICADORES.
-h, --help
Mostrar este mensaje.
--help-checkers
Listar verificadores por defecto, ver VERIFICADORES.
--html-title[=título]
Especificar el título utilizado en las páginas HTML generadas. Se genera un título por defecto si no se especifica título.
-k, --keep-going
Añadir una opción de "seguir adelante" a comando_construccion. Actualmente compatible con make y xcodebuild. Esta es una opción de conveniencia; se puede especificar este comportamiento directamente usando opciones de construcción.
-o
Directorio de destino para los archivos de informe HTML. Se crearán subdirectorios según sea necesario para representar invocaciones separadas del analizador. Si esta opción no se especifica, se crea un directorio en /tmp (TMPDIR en Mac OS X) para almacenar los informes.
-plist
Generar los resultados como un conjunto de archivos .plist. (Por defecto, la salida de scan-build es un conjunto de archivos HTML.)
-plist-html
Generar los resultados como un conjunto de archivos HTML y .plist
--status-bugs
Establecer el estado de salida a 1 si se encontraron posibles errores y 0 en caso contrario. Por defecto, el estado de salida de scan-build es el devuelto por comando_construccion.
--use-c++[=ruta_compilador]
Adivinar el compilador por defecto para tu código C++ y Objective-C++. Usa esta opción para especificar un compilador alternativo.
--use-cc[=ruta_compilador]
Adivinar el compilador por defecto para tu código C y Objective-C. Usa esta opción para especificar un compilador alternativo.
-v
Salida detallada de scan-build y del analizador. Una segunda y tercera v aumentan la verbosidad.
-V, --view
Ver los resultados del análisis en un navegador web cuando la compilación se complete.
-constraints [modelo]
Especificar el motor de restricciones utilizado por el analizador. Por defecto se utiliza el modelo de ‘range’. Especificar ‘basic’ utiliza un modelo de restricciones más simple y menos potente, usado por checker-0.160 y anteriores.
-maxloop N
Especificar el número de veces que se puede visitar un bloque antes de rendirse. Por defecto es 4. Aumentar para una cobertura más completa a costa de la velocidad.
-no-failure-reports
No crear un subdirectorio ‘failures’ que incluya informes de fallos del analizador y archivos fuente preprocesados.
-stats
Genera estadísticas de visita para el proyecto que se está analizando.
-store [modelo]
Especificar el modelo de almacenamiento utilizado por el analizador. Por defecto, se utiliza el modelo de almacenamiento ‘region’. ‘region’ especifica un modelo de almacenamiento sensible a campos. Los usuarios también pueden especificar ‘basic’ que es mucho menos preciso pero puede analizar código más rápidamente. ‘basic’ fue el modelo de almacenamiento por defecto para checker-0.221 y anteriores.

ESTADO DE SALIDA

scan-build devuelve el valor devuelto por comando_construccion a menos que se utilice --status-bugs o --keep-going.

VERIFICADORES

Los verificadores listados a continuación pueden ser habilitados/deshabilitados usando las opciones -enable-checker y -disable-checker. Un grupo por defecto de verificadores se ejecuta a menos que se deshabiliten explícitamente. Exactamente qué verificadores constituyen el grupo por defecto es una función del sistema operativo en uso; se listan con --help-checkers.

core.AdjustedReturnValue
Comprobar si el valor de retorno de una llamada a función es diferente de lo que espera el llamador (por ejemplo, desde llamadas a través de punteros a función).
core.AttributeNonNull
Comprobar punteros nulos pasados como argumentos a una función cuyos argumentos están marcados con el atributo ‘nonnull’.
core.CallAndMessage
Comprobar errores lógicos para llamadas a funciones y expresiones de mensaje de Objective-C (por ejemplo, argumentos no inicializados, punteros a función nulos).
core.DivideZero
Comprobar división por cero.
core.NullDereference
Comprobar desreferencias de punteros nulos.
core.StackAddressEscape
Comprobar que las direcciones a memoria de pila no escapen de la función.
core.UndefinedBinaryOperatorResult
Comprobar resultados indefinidos de operadores binarios.
core.VLASize
Comprobar declaraciones de VLA de tamaño indefinido o cero.
core.builtin.BuiltinFunctions
Evaluar funciones intrínsecas del compilador, por ejemplo alloca
