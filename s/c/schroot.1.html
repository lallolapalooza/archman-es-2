NOMBRE

schroot - entrar de forma segura en un entorno chroot

SINOPSIS

schroot [-h|--help | -V|--version | -l|--list | -i|--info | --config | --location | --automatic-session | -b|--begin-session | --recover-session | -r|--run-session | -e|--end-session] [-f|--force] [-n nombre-sesion|--session-name=nombre-sesion] [-d directorio|--directory=directorio] [-u usuario|--user=usuario] [-p|--preserve-environment] [-s shell|--shell=shell] [-q|--quiet | -v|--verbose] [-c chroot|--chroot=chroot | [--all | --all-chroots | --all-source-chroots | --all-sessions] [--exclude-aliases]] [-o|--option=clave=valor] [--] [COMANDO [ ARG1 [ ARG2 [ ARGN]]]]

DESCRIPCIÓN

schroot permite al usuario ejecutar un comando o un shell de inicio de sesión en un entorno chroot. Si no se especifica ningún comando, se iniciará un shell de inicio de sesión en el directorio de trabajo actual del usuario dentro del chroot.

El comando es un programa, más tantos argumentos opcionales como sean necesarios. Cada argumento puede ser citado por separado.

El directorio en el que se ejecuta el comando o el shell de inicio de sesión depende del contexto. Consulte la opción --directory a continuación para obtener una descripción completa.

Todo el uso de chroot se registrará en los logs del sistema. Bajo ciertas circunstancias, al usuario se le puede requerir que se autentique; vea la sección “Autenticación”, abajo.

Si no se especifica ningún chroot, se utilizará el nombre o alias de chroot ‘default’ como respaldo. Esto es equivalente a “--chroot=default”.

VISIÓN GENERAL

A menudo existe la necesidad de ejecutar programas en un entorno virtualizado en lugar de hacerlo directamente en el sistema anfitrión. A diferencia de otros sistemas de virtualización como kvm o Xen, schroot no virtualiza todo el sistema; solo virtualiza el sistema de archivos, y algunas partes del sistema de archivos aún pueden compartirse con el anfitrión. Por lo tanto, es rápido, ligero y flexible. Sin embargo, no virtualiza otros aspectos del sistema, como la memoria compartida, la red, los dispositivos, etc., y por lo tanto puede ser menos seguro que otros sistemas, dependiendo de su uso previsto. Algunos ejemplos de usos existentes para schroot incluyen:

•
Ejecutar un programa no confiable en un sandbox, para que no pueda interferir con los archivos del sistema anfitrión; esto también se puede usar para limitar el daño que un servicio comprometido puede infligir al anfitrión
•
Usar un entorno definido o limpio, para garantizar la reproducibilidad y la integridad de una tarea determinada
•
Usar diferentes versiones de un sistema operativo, o incluso diferentes sistemas operativos, por ejemplo, diferentes distribuciones GNU/Linux
•
Ejecutar programas de 32 bits usando un chroot de 32 bits en un sistema anfitrión de 64 bits
•
Construcción automática de paquetes Debian usando sbuild(1), que construye cada paquete en un snapshot de chroot prístino al usar snapshots LVM o uniones
•
Soporte de múltiples imágenes de sistema en una configuración de clúster, donde modificar la imagen base consume mucho tiempo y/o dar soporte a todas las configuraciones requeridas por los usuarios es difícil: diferentes chroots pueden soportar todas las configuraciones diferentes requeridas, y a los usuarios del clúster se les puede dar acceso a los chroots que necesitan (lo que puede incluir acceso root para usuarios confiables para mantener sus propias imágenes)

Se puede usar un chroot directamente como root ejecutando chroot(8), pero los usuarios normales no pueden usar este comando. schroot permite el acceso a chroots para usuarios normales utilizando el mismo mecanismo, pero con varias características adicionales. Si bien schroot utiliza un directorio como chroot al igual que chroot(8), no requiere que este sea un directorio regular en el sistema de archivos. Si bien este es el comportamiento predeterminado, el chroot también se puede crear a partir de un archivo, un sistema de archivos, incluidos snapshots LVM y Btrfs y montajes de loopback, o componerse de una superposición de unionfs. Al ser extensible por el usuario, el alcance para crear chroots de diferentes fuentes se limita solo a su imaginación. schroot realiza la verificación de permisos y permite la configuración automatizada adicional del entorno chroot, como el montaje de sistemas de archivos adicionales y otras tareas de configuración. Esta configuración automatizada se realiza a través de la acción de scripts de configuración que pueden personalizarse y extenderse para realizar cualquier acción requerida. Las acciones típicas incluyen el montaje del directorio personal del usuario, la configuración de redes y bases de datos del sistema, e incluso el inicio de servicios. Estos son nuevamente totalmente personalizables por el administrador. Los scripts de configuración se ejecutan para todo tipo de chroot, con la excepción del tipo ‘plain’, el tipo de chroot más simple, que no ofrece ninguna característica de configuración automatizada. La configuración de schroot se cubre con más detalle en schroot.conf(5).

OPCIONES

schroot acepta las siguientes opciones:

Acciones

-h, --help
Mostrar resumen de ayuda.
-V, --version
Imprimir información de la versión.
-l, --list
Listar todos los chroots disponibles.
-i, --info
Imprimir información detallada sobre los chroots especificados.
--config
Imprimir la configuración de los chroots especificados. Esto es útil para probar que la configuración en uso es la misma que la del archivo de configuración. Los comentarios del archivo original se omitirán.
--location
Imprimir la ubicación (ruta) de los chroots especificados. Tenga en cuenta que los tipos de chroot que solo se pueden usar dentro de una sesión no tendrán una ubicación hasta que estén activos.

Opciones generales

-q, --quiet
Imprimir solo mensajes esenciales.
-v, --verbose
Imprimir todos los mensajes.

Selección de chroot

-c, --chroot=chroot
Especificar un chroot o una sesión activa para usar. Esta opción se puede usar varias veces para especificar más de un chroot, en cuyo caso su efecto es similar a --all. El nombre del chroot puede ir precedido de un espacio de nombres; consulte la sección “Espacios de nombres de chroot”, abajo.
-a, --all
Seleccionar todos los chroots, chroots de origen y sesiones activas. Cuando se ha especificado un comando, el comando se ejecutará en todos los chroots, chroots de origen y sesiones activas. Si se ha utilizado --info, mostrar información sobre todos los chroots. Esta opción no tiene sentido usarla con un shell de inicio de sesión (ejecutado cuando no se ha especificado ningún comando). Esta opción es equivalente a “--all-chroots --all-source-chroots --all-sessions”.
--all-chroots
Seleccionar todos los chroots. Idéntico a --all, excepto que los chroots de origen y las sesiones activas no se consideran.
--all-sessions
Seleccionar todas las sesiones activas. Idéntico a --all, excepto que los chroots y los chroots de origen no se consideran.
--all-source-chroots
Seleccionar todos los chroots de origen. Idéntico a --all, excepto que los chroots y las sesiones activas no se consideran.

Opciones de ejecución

-b, --begin-session
Comenzar una nueva sesión y ejecutar el comando en ella. Si no se especifica un nombre de sesión, se generará uno automáticamente.
--recover-session
Intentar recuperar una sesión que ha terminado inesperadamente. Se utiliza para reparar una sesión que ha sido interrumpida.
-r, --run-session
Ejecutar el comando en la sesión activa especificada. Si no se especifica ninguna sesión, se utiliza la sesión por defecto.
-e, --end-session
Terminar la sesión activa especificada. Si no se especifica ninguna sesión, se utiliza la sesión por defecto.
-d, --directory=directorio
Establecer el directorio de trabajo dentro del chroot. Por defecto, el directorio de trabajo se establece en el directorio personal del usuario dentro del chroot. Si el usuario no tiene un directorio personal, se establece en la raíz del chroot. El argumento puede ser una ruta absoluta o una ruta relativa al directorio personal del usuario dentro del chroot.
-u, --user=usuario
Ejecutar el comando como el usuario especificado dentro del chroot. El usuario especificado debe existir dentro del chroot. Por defecto, el comando se ejecuta como el usuario que lo invocó en el sistema anfitrión. Si el usuario invocado no existe dentro del chroot, se utilizará la configuración por defecto del chroot.
--preserve-environment
Preservar todas las variables de entorno del sistema anfitrión. Por defecto, solo se preservan un número limitado de variables de entorno seguras.
-s, --shell=shell
Ejecutar el shell especificado en lugar del shell de inicio de sesión predeterminado. El shell debe ser un ejecutable válido dentro del chroot. Si el shell especificado no es válido, se utilizará el shell de inicio de sesión predeterminado.

Opciones avanzadas

-f, --force
Forzar la acción solicitada. Esto se utiliza para invalidar ciertas comprobaciones de seguridad o para forzar una operación que normalmente fallaría.
-n, --session-name=nombre-sesion
Especificar un nombre para la sesión. Si se utiliza con una acción que crea una sesión, se creará una nueva sesión con ese nombre. Si se utiliza con una acción que opera sobre una sesión existente, se utilizará la sesión con ese nombre.
-o, --option=clave=valor
Establecer una opción de configuración específica para el chroot. Las opciones disponibles dependen del tipo de chroot. Consulte la documentación de schroot.conf para obtener más detalles.
--exclude-aliases
Excluir todos los alias de chroot al seleccionar chroots. Solo se considerarán los nombres de chroot directos.

EJEMPLOS

Ejecutar un shell en el chroot 'debian':

 $ schroot -c debian

Ejecutar el comando 'ls -l /' en el chroot 'debian':

 $ schroot -c debian -- ls -l /

Iniciar una sesión en el chroot 'debian', cambiar el directorio de trabajo a '/home/user' y ejecutar un shell bash:

 $ schroot -c debian -d /home/user -s /bin/bash

Listar todos los chroots disponibles:

 $ schroot -l

Mostrar información detallada sobre el chroot 'debian':

 $ schroot -c debian -i

Ejecutar un comando en todos los chroots y sesiones disponibles:

 $ schroot --all -- whoami

Iniciar una nueva sesión con el nombre 'mi_sesion' en el chroot 'ubuntu':

 $ schroot -c ubuntu -n mi_sesion --begin-session

Ejecutar un comando en la sesión 'mi_sesion':

 $ schroot -c mi_sesion --run-session -- pwd

Terminar la sesión 'mi_sesion':

 $ schroot -c mi_sesion --end-session

VER TAMBIÉN

schroot.conf(5), chroot(8), sbuild(1).

AUTENTICACIÓN

El módulo de autenticación por defecto para schroot es pam. Este módulo se configura en el archivo /etc/schroot/schroot.conf. Puede que sea necesario instalar el paquete libpam-runtime para que funcione correctamente.

El archivo de configuración /etc/schroot/schroot.conf contiene una sección [auth] que permite especificar el módulo de autenticación a utilizar. Si no se especifica ningún módulo, se utilizará pam por defecto.

La configuración de pam se realiza en los archivos de configuración de PAM, normalmente en /etc/pam.d/schroot. En este archivo se definen los módulos y servicios de autenticación que se utilizarán para schroot.

Para obtener más información sobre la configuración de PAM, consulte la página del manual pam.conf(5).

REGISTROS

Schroot registra todas sus acciones en el sistema de registro de mensajes del sistema. Puede ver estos registros utilizando el comando dmesg o journalctl.

Por ejemplo, para ver todos los mensajes de schroot:

 $ journalctl -f -t schroot

O para ver los mensajes del último día:

 $ journalctl --since "1 day ago" -t schroot

SECCIONES DEL SISTEMA DE ARCHIVOS

Schroot puede montar varias secciones del sistema de archivos del anfitrión dentro del chroot. Esto se configura en el archivo /etc/schroot/schroot.conf. Las secciones comunes a montar incluyen:

/proc
Sistema de archivos de procesos.
/sys
Sistema de archivos del sistema.
/dev
Sistema de archivos de dispositivos.
/run
Sistema de archivos de tiempo de ejecución.
/home
Directorio personal del usuario.
/tmp
Directorio temporal.

También es posible montar cualquier otro directorio del sistema anfitrión dentro del chroot, así como montar directorios del chroot en el sistema anfitrión.

ESPACIOS DE NOMBRES DE CHROOT

Schroot soporta el uso de espacios de nombres para los chroots. Un espacio de nombres es una forma de agrupar chroots relacionados. Por ejemplo, se puede tener un espacio de nombres para cada distribución de Linux, como 'debian', 'ubuntu', 'fedora', etc.

Los chroots se especifican con el prefijo del espacio de nombres, por ejemplo: debian:nombre_chroot. Si no se especifica ningún espacio de nombres, se utilizará el espacio de nombres 'default'.

La configuración de los espacios de nombres se realiza en el archivo /etc/schroot/schroot.conf.

ESCRITOS DE CONFIGURACIÓN

Schroot utiliza scripts de configuración para configurar el entorno del chroot antes de ejecutar un comando o shell. Estos scripts se especifican en el archivo /etc/schroot/schroot.conf.

Los scripts de configuración se ejecutan en el siguiente orden:

  1. chroot: scripts de configuración específicos del chroot.
  2. session: scripts de configuración específicos de la sesión.
  3. user: scripts de configuración específicos del usuario.

Los scripts de configuración pueden ser utilizados para realizar una variedad de tareas, como montar sistemas de archivos, crear usuarios, establecer variables de entorno, etc.

CÓDIGO DE SALIDA

El código de salida de schroot es el código de salida del comando ejecutado dentro del chroot. Si no se ejecutó ningún comando, el código de salida es 0.

Si schroot falla al iniciar una sesión o ejecutar un comando, devolverá un código de salida distinto de cero.

OPCIONES NFS

Las siguientes opciones pueden ser especificadas en la sección [default] o [chroot] de schroot.conf(5) o como opciones de línea de comandos. Permiten que el chroot sea montado como un sistema de archivos NFS.

  • nfs-mount— La ruta del sistema de archivos NFS a montar. Por ejemplo: nfs.example.com:/export/sid. El valor por defecto es usar la ruta del chroot.

  • nfs-mount-options— Opciones a ser pasadas a mount(8) para el montaje NFS. El valor por defecto es usar la opción ro (solo lectura).

OPERACIÓN FSYNC

Por defecto, schroot realiza una llamada a fsync() después de cada operación de escritura para asegurar que los datos son escritos físicamente al disco. Si se desea deshabilitar esta operación, se puede usar la opción fsync-kernel-commits o la clave de configuración command-prefix, la cual deshabilita todas las operaciones fsync. Tenga en cuenta que esto solo debe hacerse en chroots de instantánea donde la pérdida de datos no sea un problema. Esto es útil cuando se usa un chroot para compilar paquetes, por ejemplo.

FALLOS DE DIRECTORIO

schroot seleccionará un directorio apropiado para usar dentro del chroot basándose en si se usará un shell de inicio de sesión interactivo o un comando invocado, y además si se usa la opción --directory. En el caso de ejecutar comandos directamente, o especificar explícitamente un directorio, solo se usará un directorio por seguridad y consistencia, mientras que para un shell de inicio de sesión se pueden probar varias posibilidades. Las siguientes subsecciones listan la secuencia de fallos para cada caso. CWD es el directorio de trabajo actual, DIR es el directorio especificado con --directory.

Shell de inicio de sesión

Transición
(Host → Chroot) Comentario
CWD → CWD Comportamiento normal (si no se usa --directory)
CWD → $HOME Si CWD no existe y se usa --preserve-environment
CWD → passwd pw_dir Si CWD no existe (o se usa --preserve-environment y no existe $HOME)
CWD → / Si ninguno de los anteriores existe
FALLO Si / no existe

Comando

Transición
(Host → Chroot) Comentario
CWD → CWD Comportamiento normal (si no se usa --directory)
FALLO Si CWD no existe

No deberían existir fallos bajo ninguna circunstancia.

--directory usado

Transición
(Host → Chroot) Comentario
CWD → DIR Comportamiento normal
FALLO Si DIR no existe

No deberían existir fallos bajo ninguna circunstancia.

Depuración

Tenga en cuenta que --debug=notice mostrará la lista interna de fallos calculada para la sesión.

TROUBLESHOOTING


Si algo no funciona, y no está claro por los mensajes de error qué está mal, intente usar la opción --debug=nivel para activar los mensajes de depuración. Esto proporciona mucha más información. Los niveles de depuración válidos son «none», «notice», «info», «warning» y «critical», en orden de gravedad creciente. Cuanto menor sea el nivel de gravedad, más salida se generará.

BUGS


En las arquitecturas mips y mipsel, los kernels de Linux hasta la versión 2.6.17 inclusive tienen un soporte defectuoso para personality(2), lo que resulta en un fallo al establecer la personalidad. Esto se verá como un error de «Operación no permitida» (EPERM). Para solucionar este problema, establezca personality en «undefined» o actualice a un kernel más reciente.


ENVIRONMENT


Por defecto, el entorno no se conserva y las siguientes variables de entorno se definen: HOME, LOGNAME, PATH, SHELL, TERM (conservada si ya está definida) y USER. Las variables de entorno SCHROOT_COMMAND, SCHROOT_USER, SCHROOT_GROUP, SCHROOT_UID y SCHROOT_GID se establecen dentro del chroot especificando el comando que se está ejecutando, el nombre de usuario, el nombre del grupo, el ID de usuario y el ID de grupo, respectivamente. Además, las variables de entorno SCHROOT_SESSION_ID, SCHROOT_CHROOT_NAME y SCHROOT_ALIAS_NAME especifican el ID de sesión, el nombre original del chroot antes de la creación de la sesión y el alias utilizado para identificar originalmente el chroot seleccionado, respectivamente.


Las siguientes variables de entorno, potencialmente peligrosas, se eliminan por seguridad por defecto: BASH_ENV, CDPATH, ENV, HOSTALIASES, IFS, KRB5_CONFIG, KRBCONFDIR, KRBTKFILE, KRB_CONF, LD_.*, LOCALDOMAIN, NLSPATH, PATH_LOCALE, RES_OPTIONS, TERMINFO, TERMINFO_DIRS y TERMPATH. Si se desea, la clave de configuración environment-filter permitirá modificar la lista de exclusión; consulte schroot.conf(5) para obtener más detalles.


FILES




Archivos de configuración




/etc/schroot/schroot.conf


El archivo de definición de chroot a nivel de sistema. Este archivo debe pertenecer al usuario root y no ser escribible por otros.


/etc/schroot/chroot.d


Se pueden colocar definiciones de chroot adicionales en archivos dentro de este directorio. Se tratan de la misma manera que /etc/schroot/schroot.conf. Cada archivo puede contener una o más definiciones de chroot. Tenga en cuenta que los archivos de este directorio siguen las mismas reglas de nomenclatura que run-parts(8) cuando se ejecuta con la opción --lsbsysinit.


/etc/schroot/setup.d


Los directorios de scripts de configuración de chroot a nivel de sistema. Consulte schroot-setup(5).


/etc/pam.d/schroot


Configuración de PAM.








Directorios del sistema




/usr/lib/schroot


Directorio que contiene programas auxiliares utilizados por los scripts de configuración.

Directorio utilizado para montar los sistemas de archivos utilizados por cada sesión activa.

Directorio utilizado para la fuente de la unión del sistema de archivos (underlay).

Directorio utilizado para desempaquetar chroots de archivos.
