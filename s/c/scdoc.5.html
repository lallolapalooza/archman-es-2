SCDOC(5) Manual de formatos de archivo SCDOC(5)

NOMBRE

scdoc - formato de documento para escribir páginas del manual

SINTAXIS

Los archivos de entrada deben usar la codificación UTF-8.

Preámbulo

Cada archivo scdoc debe comenzar con el siguiente preámbulo:

NOMBRE(sección) ["pie_izquierdo" ["encabezado_central"]]

NOMBRE es el nombre de la página del manual que estás escribiendo, y sección es la sección para la que estás escribiendo (ver man(1) para información sobre las secciones del manual).

pie_izquierdo y encabezado_central son argumentos opcionales que establecen el texto posicionado en esas ubicaciones en la página del manual generada, y **deben** estar rodeados por comillas dobles.

Encabezados de sección

Cada sección de tu página del manual debe comenzar con algo similar a lo siguiente:

# NOMBRE DEL ENCABEZADO

También se entienden los encabezados de subsección; usa dos hashes. Cada encabezado debe tener una línea vacía a cada lado.

Párrafos

Comienza un nuevo párrafo con una línea vacía.

Saltos de línea

Inserta un salto de línea terminando una línea con ++.

El resultado se ve
así.

Formato

El texto se puede poner en **negrita** o subrayado con asteriscos y guiones bajos: *negrita* o _subrayado_. Los guiones bajos en el_medio_de_las_palabras serán ignorados.

Indentación

Puedes indentar líneas con caracteres de tabulación (\t) para indentarlas 4 espacios en la salida. Las líneas indentadas no pueden contener encabezados.

El resultado se ve algo así.

Puedes usar múltiples líneas y la mayoría de formato.

Desindentar para volver a la normalidad, o indentar de nuevo para aumentar tu nivel de indentación.

Listas

Puedes comenzar listas con viñetas con guiones (-), así:

- Elemento 1
- Elemento 2
	- Subelemento 1
	- Subelemento 2
- Elemento 3

El resultado se ve así:

  • Elemento 1
  • Elemento 2
  • Subelemento 1
  • Subelemento 2
•
Elemento 3

También puedes extender entradas largas a otra línea dándole el mismo nivel de indentación, más dos espacios. Se renderizarán como una única entrada de lista.

- El elemento 1 es bastante largo, así que
  lo dividiremos en dos líneas
- El elemento 2 es más corto
	- Pero sus hijos pueden continuar
	  durante un tiempo
  • El elemento 1 es bastante largo, así que lo dividiremos en dos líneas
  • El elemento 2 es más corto
•
Pero sus hijos pueden continuar durante un tiempo

Listas numeradas

Las listas numeradas son similares a las listas normales, pero comienzan con puntos (.) en lugar de guiones (-), así:

. Elemento 1
. Elemento 2
. Elemento 3,
  con múltiples líneas
1.
Elemento 1
2.
Elemento 2
3.
Elemento 3, con múltiples líneas

Tablas

Para comenzar una tabla, agrega una línea vacía seguida de cualquier número de filas.

Cada línea de una tabla debe comenzar con | o : para iniciar una nueva fila o columna respectivamente (o un espacio para continuar la celda anterior en múltiples líneas), seguido de [ o - o ] para alinear el contenido a la izquierda, centro o derecha, seguido de un espacio y el contenido de esa celda. Puedes usar un espacio en lugar de un especificador de alineación para heredar la alineación de la misma columna en la fila anterior. Cada fila debe tener el mismo número de columnas; se permiten columnas vacías.

El primer carácter de la primera fila no se limita a | y tiene un significado especial. [ producirá una tabla con bordes alrededor de cada celda. | producirá una tabla sin bordes. ] producirá una tabla con un borde alrededor de toda la tabla.

Para concluir tu tabla, agrega una línea vacía después de la última fila.

[[ *Foo*
:- _Bar_
:-
|  *Fila 1*
:  Hola
:] mundo!
|  *Fila 2*
:  こんにちは
:  世界
   !
Foo Bar
Fila 1 Hola mundo!
Fila 2 こんにちは 世界 !

También puedes hacer que las columnas se expandan para llenar el espacio disponible con < (alinear a la izquierda), = (centrar) y > (alinear a la derecha), así:

[[ *Columna normal*
:< Columna expandida
|  *Foo*
:  Bar
Columna normal Columna expandida
Foo Bar

Texto literal

Puedes desactivar el formato de scdoc y mostrar texto literal con códigos de escape y bloques literales. Insertar una \ en tu fuente hará que el símbolo subsiguiente se trate como literal y se copie directamente a la salida. También puedes crear bloques de sintaxis literal así:

```
_Este formato_ no será interpretado por scdoc.
```

Estos bloques se indentarán un nivel. Ten en cuenta que el texto literal se muestra literalmente en el visor de manuales; es decir, no es un medio para insertar tus propios macros roff en la salida. Ten en cuenta que \ todavía se interpreta dentro de los bloques literales, lo que, por ejemplo, puede ser útil para mostrar ``` dentro de un bloque literal.

Comentarios

Las líneas que comienzan con ; y un espacio se ignoran.

; Este es un comentario

CONVENCIONES

Por convención, todos los documentos scdoc deben tener saltos de línea duros a las 80 columnas.
