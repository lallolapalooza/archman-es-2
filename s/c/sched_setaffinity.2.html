sched_setaffinity(2) Manual de llamadas al sistema sched_setaffinity(2)

NOMBRE

sched_setaffinity, sched_getaffinity - establecer y obtener la máscara de afinidad de CPU de un hilo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE             /* Ver feature_test_macros(7) */
#include <sched.h>
int sched_setaffinity(pid_t pid, size_t cpusetsize,
                      const cpu_set_t *mask);
int sched_getaffinity(pid_t pid, size_t cpusetsize,
                      cpu_set_t *mask);

DESCRIPCIÓN

La máscara de afinidad de CPU de un hilo determina el conjunto de CPUs en las que es elegible para ejecutarse. En un sistema multiprocesador, establecer la máscara de afinidad de CPU se puede utilizar para obtener beneficios de rendimiento. Por ejemplo, al dedicar una CPU a un hilo particular (es decir, establecer la máscara de afinidad de ese hilo para especificar una única CPU y establecer la máscara de afinidad de todos los demás hilos para excluir esa CPU), es posible garantizar la máxima velocidad de ejecución para ese hilo. Restringir un hilo a ejecutarse en una única CPU también evita el costo de rendimiento causado por la invalidación de la caché que ocurre cuando un hilo deja de ejecutarse en una CPU y luego recomienza la ejecución en una CPU diferente.

Una máscara de afinidad de CPU se representa mediante la estructura cpu_set_t, un "conjunto de CPU", apuntado por mask. Un conjunto de macros para manipular conjuntos de CPU se describe en CPU_SET(3).

sched_setaffinity() establece la máscara de afinidad de CPU del hilo cuyo ID es pid al valor especificado por mask. Si pid es cero, entonces se utiliza el hilo que realiza la llamada.

El argumento cpusetsize es la longitud (en bytes) de los datos apuntados por mask. Normalmente, este argumento se especificaría como sizeof(cpu_set_t).

Si el hilo especificado por pid no se está ejecutando actualmente en una de las CPUs especificadas en mask, entonces ese hilo se migra a una de las CPUs especificadas en mask.

sched_getaffinity() escribe la máscara de afinidad del hilo cuyo ID es pid en la estructura cpu_set_t apuntada por mask. El argumento cpusetsize especifica el tamaño (en bytes) de mask. Si pid es cero, entonces se devuelve la máscara del hilo que realiza la llamada.

VALOR DE RETORNO

En caso de éxito, sched_setaffinity() y sched_getaffinity() devuelven 0 (pero ver "Diferencias entre la biblioteca C/el kernel" a continuación, que señala que sched_getaffinity() subyacente difiere en su valor de retorno). En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EFAULT
Una dirección de memoria proporcionada era inválida.
EINVAL
La máscara de bits de afinidad mask no contiene procesadores que estén actualmente físicamente en el sistema y permitidos para el hilo de acuerdo con cualquier restricción que puedan imponer los cgroups cpuset o el mecanismo "cpuset" descrito en cpuset(7).
EINVAL
(sched_getaffinity() y, antes de Linux 2.6.9, sched_setaffinity()) cpusetsize es menor que el tamaño de la máscara de afinidad utilizada por el kernel.
EPERM
(sched_setaffinity()) El hilo que realiza la llamada no tiene los privilegios apropiados. El llamador necesita un ID de usuario efectivo igual al ID de usuario real o al ID de usuario efectivo del hilo identificado por pid, o debe poseer la capacidad CAP_SYS_NICE en el espacio de nombres de usuario del hilo pid.
ESRCH
No se pudo encontrar el hilo cuyo ID es pid.

ESTANDARES

Linux.

HISTORIA

Linux 2.5.8, glibc 2.3.

Inicialmente, las interfaces de glibc incluían un argumento cpusetsize, tipificado como unsigned int. En glibc 2.3.3, se eliminó el argumento cpusetsize, pero luego se restauró en glibc 2.3.4, con el tipo size_t.

NOTAS

Después de una llamada a sched_setaffinity(), el conjunto de CPUs en las que el hilo se ejecutará realmente es la intersección del conjunto especificado en el argumento mask y el conjunto de CPUs realmente presentes en el sistema. El sistema puede restringir aún más el conjunto de CPUs en las que se ejecutará el hilo si se está utilizando el mecanismo "cpuset" descrito en cpuset(7). Estas restricciones en el conjunto real de CPUs en las que se ejecutará el hilo son impuestas silenciosamente por el kernel.

Existen varias formas de determinar el número de CPUs disponibles en el sistema, entre ellas: inspeccionar el contenido de /proc/cpuinfo; utilizar sysconf(3) para obtener los valores de los parámetros _SC_NPROCESSORS_CONF y _SC_NPROCESSORS_ONLN; e inspeccionar la lista de directorios de CPU bajo /sys/devices/system/cpu/.

sched(7) tiene una descripción del esquema de planificación de Linux.

La máscara de afinidad es un atributo por hilo que se puede ajustar independientemente para cada uno de los hilos de un grupo de hilos. El valor devuelto por una llamada a gettid(2) se puede pasar en el argumento pid. Especificar pid como 0 establecerá el atributo para el hilo que realiza la llamada, y pasar el valor devuelto por una llamada a getpid(2) establecerá el atributo para el hilo principal del grupo de hilos. (Si está utilizando la API de hilos POSIX, use pthread_setaffinity_np(3) en lugar de sched_setaffinity().)

La opción de arranque isolcpus se puede utilizar para aislar una o más CPUs al arrancar, de modo que ningún proceso se programe en esas CPUs. Después de usar esta opción de arranque, la única forma de programar procesos en las CPUs aisladas es a través de sched_setaffinity() o el mecanismo de cpuset(7). Para más información, consulte el archivo fuente del kernel Documentation/admin-guide/kernel-parameters.txt. Como se señala en ese archivo, isolcpus es el mecanismo preferido para aislar CPUs (en comparación con la alternativa de establecer manualmente la afinidad de CPU de todos los procesos en el sistema).

Un hijo creado a través de fork(2) hereda la máscara de afinidad de CPU de su padre. La máscara de afinidad se conserva durante un execve(2).

Diferencias entre la biblioteca C/el kernel

Esta página del manual describe la interfaz de glibc para las llamadas de afinidad de CPU. La interfaz de llamada al sistema real es ligeramente diferente, con mask tipificado como unsigned long *, lo que refleja el hecho de que la implementación subyacente de los conjuntos de CPU es una simple máscara de bits.

En caso de éxito, la llamada al sistema bruta sched_getaffinity() devuelve el número de bytes copiados en el búfer mask; este será el mínimo entre cpusetsize y el tamaño (en bytes) del tipo de datos cpumask_t que se utiliza internamente en el kernel para representar la máscara de bits del conjunto de CPU.

Manejo de sistemas con máscaras de afinidad de CPU grandes

Las llamadas al sistema subyacentes (que representan máscaras de CPU como máscaras de bits de tipo unsigned long *) no imponen restricciones al tamaño de la máscara de CPU. Sin embargo, el tipo de datos cpu_set_t utilizado por glibc tiene un tamaño fijo de 128 bytes, lo que significa que el número máximo de CPU que se puede representar es 1023. Si la máscara de afinidad de CPU del kernel es mayor que 1024, entonces las llamadas de la forma:


  sched_getaffinity(0, sizeof(cpu_set_t), &my_set)

solo devolverá información para las primeras 1024 CPUs. Para manejar sistemas con más de 1024 CPUs, deberá asignar memoria dinámicamente para un búfer de tamaño apropiado y llamar a la llamada al sistema sched_getaffinity() (o sched_setaffinity()) directamente, pasando el tamaño de su búfer asignado.

    NOTES

    The implementation of CPU sets uses bitmasks allocated in units of long. If the size requested for the mask argument to sched_setaffinity() is smaller than the size of the affinity mask used by the kernel, the call will

    fail with the error EINVAL, the error produced by the
    underlying system call for the case where the mask size specified in
    cpusetsize is smaller than the size of the affinity mask used by the
    kernel. (Depending on the system CPU topology, the kernel affinity mask can
    be substantially larger than the number of active CPUs in the system.)

    When working on systems with large kernel CPU affinity masks, one must dynamically allocate the mask argument (see CPU_ALLOC(3)). Currently, the only way to do this is by probing for the size of the required mask using sched_getaffinity() calls with increasing mask sizes (until the call does not fail with the error EINVAL).

    Be aware that CPU_ALLOC(3) may allocate a slightly larger CPU set than requested (because CPU sets are implemented as bit masks allocated in units of sizeof(long)). Consequently, sched_getaffinity() can set bits beyond the requested allocation size, because the kernel sees a few additional bits. Therefore, the caller should iterate over the bits in the returned set, counting those which are set, and stop upon reaching the value returned by CPU_COUNT(3) (rather than iterating over the number of bits requested to be allocated).

    EXAMPLES

    The program below creates a child process. The parent and child then each assign themselves to a specified CPU and execute identical loops that consume some CPU time. Before terminating, the parent waits for the child to complete. The program takes three command-line arguments: the CPU number for the parent, the CPU number for the child, and the number of loop iterations that both processes should perform.

    As the sample runs below demonstrate, the amount of real and CPU time consumed when running the program will depend on intra-core caching effects and whether the processes are using the same CPU.

    We first employ lscpu(1) to determine that this (x86) system has two cores, each with two CPUs:


    $ lscpu | egrep -i 'core.*:|socket';
Thread(s) per core:    2
Core(s) per socket:    2
Socket(s):             1

    We then time the operation of the example program for three cases: both processes running on the same CPU; both processes running on different CPUs on the same core; and both processes running on different CPUs on different cores.


    $ time -p ./a.out 0 0 100000000;
real 14.75
user 3.02
sys 11.73
$ time -p ./a.out 0 1 100000000;
real 11.52
user 3.98
sys 19.06
$ time -p ./a.out 0 3 100000000;
real 7.89
user 3.29
sys 12.07

    Program source

    #define _GNU_SOURCE
#include <err.h>
#include <sched.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int           parentCPU, childCPU;
    cpu_set_t     set;
    unsigned int  nloops;
    if (argc != 4) {
        fprintf(stderr, "Usage: %s parent-cpu child-cpu num-loops\n",
                argv[0]);
        exit(EXIT_FAILURE);
    }
    parentCPU = atoi(argv[1]);
    childCPU = atoi(argv[2]);
    nloops = atoi(argv[3]);
    CPU_ZERO(&set);
    switch (fork()) {
    case -1:            /* Error */
        err(EXIT_FAILURE, "fork");
    case 0:             /* Child */
        CPU_SET(childCPU, &set);
        if (sched_setaffinity(0, sizeof(set), &set) == -1)
            err(EXIT_FAILURE, "sched_setaffinity");
        for (unsigned int j = 0; j < nloops; j++)
            getppid();
        exit(EXIT_SUCCESS);
    default:            /* Parent */
        CPU_SET(parentCPU, &set);
        if (sched_setaffinity(0, sizeof(set), &set) == -1)
            err(EXIT_FAILURE, "sched_setaffinity");
        for (unsigned int j = 0; j < nloops; j++)
            getppid();
        wait(NULL);     /* Wait for child to terminate */
        exit(EXIT_SUCCESS);
    }
}
