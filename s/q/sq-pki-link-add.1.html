NOMBRE

sq-pki-link-add - Vincula un certificado y un ID de usuario

SINOPSIS

sq pki link add [OPCIONES]

DESCRIPCIÓN

Vincula un certificado y un ID de usuario.

Esto hace que `sq` considere la vinculación del certificado y el ID de usuario como auténtica. Harías esto si estuvieras seguro de que un certificado en particular debe asociarse con Alice, por ejemplo. Nota: esto no considera que el certificado sea un introductor de confianza; solo considera que el vínculo es auténtico. Para autorizar que un certificado sea un introductor de confianza, utiliza `sq pki link authorize`.

Un vínculo puede ser revocado usando `sq pki link retract`.

Este comando es similar a `sq pki vouch add`, pero las certificaciones que realiza se hacen utilizando la raíz de confianza del directorio de certificados, no una clave arbitraria. Además, los certificados se marcan como no exportables. Lo primero facilita la gestión de las certificaciones, especialmente cuando la clave de certificación del usuario está sin conexión. Y lo segundo mejora la privacidad del usuario, al reducir la posibilidad de que partes del grafo social del usuario se filtren cuando se comparte un certificado.

Por defecto, un vínculo nunca expira. Esto se puede anular usando el argumento `--expiration`.

`sq pki link add` respeta la hora de referencia establecida por el argumento `--time` de nivel superior. Establece la hora de creación del vínculo a la hora de referencia.

OPCIONES

Opciones del subcomando

--add-email=EMAIL
Utiliza un ID de usuario con la dirección de correo electrónico especificada
El ID de usuario consiste solo en la dirección de correo electrónico. La dirección de correo electrónico no tiene que aparecer en un ID de usuario autofirmado.
--add-userid=USERID
Utiliza el ID de usuario especificado
El ID de usuario especificado no necesita ser autofirmado.
Dado que usar un ID de usuario que no está autofirmado a menudo es un error, necesitas usar esta opción para aceptarlo explícitamente.
--all
Utiliza todos los IDs de usuario autofirmados
--allow-non-canonical-userids
No rechaces nuevos IDs de usuario que no estén en forma canónica
Los IDs de usuario canónicos tienen el formato `Nombre (Comentario) <localpart@example.org>`.
--amount=AMOUNT
Establece el nivel de confianza
Los valores entre 1 y 120 son significativos. 120 significa totalmente confiable. Los valores inferiores a 120 indican el grado de confianza. 60 se usa generalmente para parcialmente confiable.
[predeterminado: full]
--cert=FINGERPRINT|KEYID
Utiliza certificados con la huella digital o ID de clave especificados
--cert-special=SPECIAL
Utiliza certificados identificados por el nombre especial
[posibles valores: public-directories, keys.openpgp.org, keys.mailvelope.com, proton.me, wkd, dane, autocrypt, web]
--email=EMAIL
Utiliza un ID de usuario que consiste solo en la dirección de correo electrónico, si la dirección de correo electrónico aparece en un ID de usuario autofirmado
--expiration=EXPIRATION
Establece la hora de expiración
EXPIRATION es una fecha en formato ISO 8601 con hora opcional o una duración personalizada. Una duración tiene el formato `N[ymwds]`, donde las letras representan años, meses, semanas, días y segundos, respectivamente. Alternativamente, la palabra clave `never` no establece una hora de expiración.
[predeterminado: never]
--recreate
Recrea la firma aunque los parámetros no hayan cambiado
Si los parámetros del vínculo no han cambiado, y por lo tanto no es necesario crear una firma, omitimos la operación. Se puede proporcionar esta bandera para forzar la recreación de la firma de todos modos.
--signature-notation NAME VALUE
Agrega una notación a la firma
El nombre de una notación definida por el usuario debe tener el formato `name@a.domain.you.control.org`. Si el nombre de la notación comienza con `!`, entonces la notación se marca como crítica. Si un consumidor de una firma no entiende una notación crítica, ignorará la firma. La notación se marca como legible por humanos.
--temporary
Acepta temporalmente la vinculación
Crea un vínculo totalmente confiable entre un certificado y uno o más IDs de usuario durante una semana. Después de eso, el vínculo se degrada automáticamente a un vínculo parcialmente confiable (confianza = 40).
--userid=USERID
Utiliza el ID de usuario autofirmado especificado
El ID de usuario especificado debe estar autofirmado.
--userid-by-email=EMAIL
Utiliza el ID de usuario autofirmado con la dirección de correo electrónico especificada

Opciones globales

Vea sq(1) para una descripción de las opciones globales.

EJEMPLOS

Vincula el certificado EB28F26E2739A4870ECC47726F0073F60FD0CBF0 con la dirección de correo electrónico alice@example.org.

sq pki link add \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--email=alice@example.org

Primero, examine el certificado EB28F26E2739A4870ECC47726F0073F60FD0CBF0.

sq inspect --cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0

Luego, acepte temporalmente el certificado EB28F26E2739A4870ECC47726F0073F60FD0CBF0 con todos sus IDs de usuario autofirmados durante una semana.

sq pki link add --expiration=1w \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

Una vez satisfecho, acepte permanentemente el certificado EB28F26E2739A4870ECC47726F0073F60FD0CBF0 con todos sus IDs de usuario autofirmados.

sq pki link add \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

NOMBRE

sq-pki-link-add - añade un enlace a una identidad de clave pública

SINOPSIS

sq-pki-link-add [--force] [--set=VALOR] [--unset=VALOR] [--set-by=VALOR] [--set-by-email=VALOR] [--set-by-keyid=VALOR] [--keyid=VALOR] [--owner=VALOR] [--owner-email=VALOR] [--owner-keyid=VALOR] [--to=VALOR] [--to-email=VALOR] [--to-keyid=VALOR] [--identity=VALOR] [--policy=VALOR] [--policy-keyid=VALOR] [--policy-email=VALOR] [--policy-owner=VALOR] [--policy-owner-keyid=VALOR] [--policy-owner-email=VALOR] [--from=VALOR] [--from-email=VALOR] [--from-keyid=VALOR] [--input-format=VALOR] [--output-format=VALOR] [--output=VALOR] [--print] [--no-tty] [--verbose] [--quiet] [--debug] [--no-user-interaction] [--version] [--help]

DESCRIPCIÓN

Este comando se utiliza para añadir un enlace a una identidad dentro de la infraestructura de claves públicas (PKI) de Sequoia. Un enlace representa una relación entre dos identidades, a menudo utilizada para certificar o vincular identidades dentro de un sistema de gestión de claves.

El comando permite especificar las identidades de origen y destino del enlace, así como varias opciones para configurar la naturaleza y las propiedades del enlace.

OPCIONES

--force
Forzar la operación, incluso si existen advertencias o conflictos.
--set=VALOR
Establecer un atributo arbitrario para el enlace.
--unset=VALOR
Eliminar un atributo arbitrario del enlace.
--set-by=VALOR
Especificar la identidad que establece el enlace (por nombre o ID).
--set-by-email=VALOR
Especificar la dirección de correo electrónico de la identidad que establece el enlace.
--set-by-keyid=VALOR
Especificar el ID de clave de la identidad que establece el enlace.
--keyid=VALOR
ID de clave de la clave principal para la operación.
--owner=VALOR
Nombre de la identidad propietaria.
--owner-email=VALOR
Dirección de correo electrónico del propietario de la identidad.
--owner-keyid=VALOR
ID de clave del propietario de la identidad.
--to=VALOR
Identidad de destino del enlace (por nombre o ID).
--to-email=VALOR
Dirección de correo electrónico de la identidad de destino.
--to-keyid=VALOR
ID de clave de la identidad de destino.
--identity=VALOR
Identidad específica para asociar con el enlace.
--policy=VALOR
Política que rige el enlace.
--policy-keyid=VALOR
ID de clave asociado a la política.
--policy-email=VALOR
Dirección de correo electrónico asociada a la política.
--policy-owner=VALOR
Propietario de la política.
--policy-owner-keyid=VALOR
ID de clave del propietario de la política.
--policy-owner-email=VALOR
Dirección de correo electrónico del propietario de la política.
--from=VALOR
Identidad de origen del enlace (por nombre o ID).
--from-email=VALOR
Dirección de correo electrónico de la identidad de origen.
--from-keyid=VALOR
ID de clave de la identidad de origen.
--input-format=VALOR
Formato de entrada (por ejemplo, `json`, `text`).
--output-format=VALOR
Formato de salida (por ejemplo, `json`, `text`).
--output=VALOR
Escribir la salida a un archivo especificado.
--print
Imprimir la salida estándar.
--no-tty
Desactivar la interacción de la terminal.
--verbose
Activar la salida detallada.
--quiet
Suprimir la salida.
--debug
Activar la salida de depuración.
--no-user-interaction
Desactivar la interacción con el usuario.
--version
Mostrar información sobre la versión.
--help
Mostrar mensaje de ayuda.

EJEMPLOS

Para añadir un enlace de la identidad 'Alice' a la identidad 'Bob' establecido por Alice: 

sq-pki-link-add --from "Alice" --to "Bob" --set-by "Alice"

Para añadir un enlace desde una dirección de correo electrónico a un ID de clave, especificando la política: 

sq-pki-link-add --from-email alice@example.com --to-keyid 0x12345678 --policy "certification"
