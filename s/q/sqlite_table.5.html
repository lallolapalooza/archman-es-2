NOMBRE

sqlite_table - Configuración SQLite de Postfix

SINOPSIS

postmap -q "cadena" sqlite:/etc/postfix/nombre_archivo
postmap -q - sqlite:/etc/postfix/nombre_archivo <archivo_entrada

DESCRIPCIÓN


El sistema de correo Postfix utiliza tablas opcionales para la reescritura de direcciones o el enrutamiento de correo. Estas tablas suelen estar en formato dbm o db.

Alternativamente, las tablas de consulta se pueden especificar como bases de datos SQLite. Para usar consultas SQLite, defina una fuente SQLite como una tabla de consulta en main.cf, por ejemplo:

    alias_maps = sqlite:/etc/postfix/sqlite-aliases.cf

El archivo /etc/postfix/sqlite-aliases.cf tiene el mismo formato que el archivo main.cf de Postfix y puede especificar los parámetros descritos a continuación.

MEMBRESÍA DE LISTA

Al usar SQL para almacenar listas como $mynetworks, $mydestination, $relay_domains, $local_recipient_maps, etc., es importante entender que la tabla debe almacenar cada miembro de la lista como una clave separada. La consulta de tabla verifica la *existencia* de la clave. Consulte "Listas frente a tablas de Postfix" en el documento DATABASE_README para una discusión.

NO cree tablas que devuelvan la lista completa de dominios en $mydestination o $relay_domains, etc., o direcciones IP en $mynetworks.

SÍ cree tablas con cada elemento coincidente como clave y con un valor arbitrario. Con bases de datos SQL, no es raro devolver la propia clave o un valor constante.

PARÁMETROS SQLITE

dbpath
La ubicación del archivo de la base de datos SQLite. Ejemplo: 
    dbpath = base_de_datos_cliente
query
La plantilla de consulta SQL utilizada para buscar en la base de datos, donde %s es un sustituto de la dirección que Postfix está intentando resolver, p. ej. 
    query = SELECT replacement FROM aliases WHERE mailbox = '%s'

Este parámetro admite las siguientes expansiones de '%':

%%
Esto se reemplaza por un carácter '%' literal.
%s
Esto se reemplaza por la clave de entrada. Se utilizan comillas SQL para asegurarse de que la clave de entrada no agregue metacaracteres inesperados.
%u
Cuando la clave de entrada es una dirección del tipo usuario@dominio, %u se reemplaza por la parte local de la dirección entre comillas SQL. De lo contrario, %u se reemplaza por la cadena de búsqueda completa. Si la parte local está vacía, se suprime la consulta y no se devuelven resultados.
%d
Cuando la clave de entrada es una dirección del tipo usuario@dominio, %d se reemplaza por la parte del dominio de la dirección entre comillas SQL. De lo contrario, se suprime la consulta y no se devuelven resultados.
%[SUD]
Los equivalentes en mayúsculas de las expansiones anteriores se comportan en el parámetro query de manera idéntica a sus contrapartes en minúsculas. Con el parámetro result_format (ver más abajo), expanden la clave de entrada en lugar del valor del resultado.
%[1-9]
Los patrones %1, %2, ... %9 se reemplazan por el componente más significativo correspondiente del dominio de la clave de entrada. Si la clave de entrada es usuario@mail.example.com, entonces %1 es com, %2 es example y %3 es mail. Si la clave de entrada no está cualificada o no tiene suficientes componentes de dominio para satisfacer todos los patrones especificados, la consulta se suprime y no devuelve resultados.
El parámetro domain descrito a continuación limita las claves de entrada a direcciones en dominios coincidentes. Cuando el parámetro domain no está vacío, las consultas SQL para direcciones no cualificadas o direcciones en dominios no coincidentes se suprimen y no devuelven resultados.

Este parámetro está disponible con Postfix 2.2. En versiones anteriores, la consulta SQL se construía a partir de los parámetros separados: select_field, table, where_field y additional_conditions. El mapeo de los parámetros antiguos a la consulta equivalente es:

    SELECT [select_field]
    FROM [table]
    WHERE [where_field] = '%s'
          [additional_conditions]

El '%s' en la cláusula WHERE se expande a la cadena de búsqueda escapada. Con Postfix 2.2, estos parámetros heredados se usan si no se especifica el parámetro query.

NOTA: NO ponga comillas alrededor del parámetro de consulta.

result_format (por defecto: %s)
Plantilla de formato aplicada a los atributos de resultado. Se usa comúnmente para agregar (o anteponer) texto al resultado. Este parámetro admite las siguientes expansiones de '%':
%%
Esto se reemplaza por un carácter '%' literal.
%s
Esto se reemplaza por el valor del atributo de resultado. Cuando el resultado está vacío, se omite.
%u
Cuando el valor del atributo de resultado es una dirección del tipo usuario@dominio, %u se reemplaza por la parte local de la dirección. Cuando el resultado tiene una parte local vacía, se omite.
%d
Cuando el valor de un atributo de resultado es una dirección del tipo usuario@dominio, %d se reemplaza por la parte del dominio del valor del atributo. Cuando el resultado no está cualificado, se omite.
%[SUD1-9]
Las expansiones en mayúsculas y con dígitos decimales interpolan las partes de la clave de entrada en lugar del resultado. Su comportamiento es idéntico al descrito con query, y de hecho, dado que la clave de entrada se conoce de antemano, las consultas cuya clave no contenga toda la información especificada en la plantilla de resultado se suprimen y no devuelven resultados.
Por ejemplo, usar "result_format = smtp:[%s]" permite usar un atributo mailHost como base de una tabla transport(5). Después de aplicar el formato de resultado, varios valores se concatenan como cadenas separadas por comas. El límite de expansión y el parámetro explicado a continuación permiten restringir el número de valores en el resultado, lo cual es especialmente útil para mapas que deben devolver como máximo un valor.

El valor predeterminado %s especifica que cada valor de resultado debe usarse tal cual.

Este parámetro está disponible a partir de Postfix 2.2.

NOTA: ¡NO ponga comillas alrededor del formato de resultado!

domain (por defecto: sin lista de dominios)
Esta es una lista de nombres de dominio, rutas a archivos o bases de datos de "tipo:tabla". Cuando se especifica, solo las claves de búsqueda completamente cualificadas con una parte local *no vacía* y un dominio coincidente son elegibles para la consulta: las búsquedas de 'usuario', búsquedas de dominio desnudo y búsquedas de "@dominio" no se realizan. Esto puede reducir significativamente la carga de consultas en el servidor SQLite. 
    domain = postfix.org, hash:/etc/postfix/dominios_busqueda

Es mejor no usar SQL para almacenar los dominios elegibles para consultas SQL.

Este parámetro está disponible a partir de Postfix 2.2.

NOTA: NO defina este parámetro para alias de local(8), porque las claves de entrada siempre no están cualificadas.

expansion_limit (por defecto: 0)
Un límite en el número total de elementos de resultado devueltos (como una lista separada por comas) por una consulta en el mapa. Una configuración de cero deshabilita el límite. Las consultas fallan con un error temporal si se supera el límite. Establecer el límite a 1 asegura que las consultas no devuelvan múltiples valores.

PARÁMETROS OBSOLETOS DE MAIN.CF

Para compatibilidad con otras tablas de consulta de Postfix, los parámetros SQLite también se pueden definir en main.cf. Para hacerlo, especifique como fuente SQLite un nombre que no comience con una barra o un punto. Los parámetros SQLite serán accesibles como el nombre que le ha dado a la fuente en su definición, un guion bajo y el nombre del parámetro. Por ejemplo, si el mapa se especifica como "sqlite:nombre_sqlite", el parámetro "query" se definirá en main.cf como "nombre_sqlite_query".

INTERFAZ DE CONSULTA OBSOLETA

INTERFAZ DE CONSULTA OBSOLETA

Esta sección describe una interfaz que está obsoleta desde Postfix 2.2. Ha sido reemplazada por la interfaz query más general descrita anteriormente. Si se define el parámetro query, los parámetros heredados descritos aquí se ignoran. Por favor, migre a la nueva interfaz, ya que la interfaz heredada puede ser eliminada en una futura versión.

Los siguientes parámetros se pueden utilizar para completar una declaración de plantilla SELECT de la forma:

    SELECT [select_field]
    FROM [table]
    WHERE [where_field] = '%s'
          [additional_conditions]

El especificador %s se reemplaza por la cadena de búsqueda y se escapa para que, si contiene comillas simples u otros caracteres inusuales, no cause un error de análisis o, peor aún, un problema de seguridad.

select_field
El parámetro SQL "select". Ejemplo: 
    select_field = forw_addr
table
El nombre de tabla SQL "select .. from". Ejemplo: 
    table = mxaliases
where_field
El parámetro SQL "select .. where". Ejemplo: 
    where_field = alias
additional_conditions
Condiciones adicionales para la consulta SQL. Ejemplo: 
    additional_conditions = AND status = 'paid'
