SQLITE3(1) Manual de comandos generales SQLITE3(1)

NOMBRE

sqlite3 - Una interfaz de línea de comandos para SQLite versión 3

SINOPSIS

sqlite3 [opciones] [archivo_base_de_datos] [SQL]

RESUMEN

sqlite3 es un front-end basado en terminal para la biblioteca SQLite que puede evaluar consultas de forma interactiva y mostrar los resultados en varios formatos. sqlite3 también se puede usar dentro de scripts de shell y otras aplicaciones para proporcionar funciones de procesamiento por lotes.

DESCRIPCIÓN

Para iniciar una sesión interactiva de sqlite3, invoca el comando sqlite3 y, opcionalmente, proporciona el nombre de un archivo de base de datos. Si el archivo de base de datos no existe, se creará. Si el archivo de base de datos existe, se abrirá.

Por ejemplo, para crear un nuevo archivo de base de datos llamado "mydata.db", crear una tabla llamada "memos" e insertar un par de registros en esa tabla:

$ sqlite3 mydata.db
Versión de SQLite 3.43.0 2023-08-11 17:45:23
Introduce ".help" para ver sugerencias de uso.
sqlite> create table memos(text, priority INTEGER);
sqlite> insert into memos values('deliver project description', 10);
sqlite> insert into memos values('lunch with Christine', 100);
sqlite> select * from memos;
deliver project description|10
lunch with Christine|100
sqlite>

Si no se proporciona ningún nombre de base de datos, se puede usar el comando SQL ATTACH para adjuntar a bases de datos existentes o crear nuevas. ATTACH también se puede usar para adjuntar a múltiples bases de datos dentro de la misma sesión interactiva. Esto es útil para migrar datos entre bases de datos, posiblemente cambiando el esquema en el proceso.

Opcionalmente, se puede proporcionar una sentencia SQL o un conjunto de sentencias SQL como un solo argumento. Múltiples sentencias deben separarse por punto y coma.

Por ejemplo:

$ sqlite3 -line mydata.db 'select * from memos where priority > 20;'
text = lunch with Christine
priority = 100

COMANDOS META SQLITE

El intérprete interactivo ofrece un conjunto de metacomandos que se pueden utilizar para controlar el formato de salida, examinar los archivos de base de datos adjuntos actualmente o realizar operaciones administrativas sobre las bases de datos adjuntas (como reconstruir índices). Los metacomandos siempre van precedidos de un punto (.).

Una lista de metacomandos disponibles se puede ver en cualquier momento emitiendo el comando '.help'. Por ejemplo:

sqlite> .help

Los comandos disponibles difieren según la versión y las opciones de compilación, por lo que no se enumeran aquí. Consulte su copia local para ver todas las opciones disponibles.

ARCHIVO DE INICIALIZACIÓN

sqlite3 lee un archivo de inicialización para configurar el entorno interactivo. Durante la inicialización, cualquier configuración previamente especificada puede ser anulada. La secuencia de inicialización es la siguiente:

o Se establece la configuración predeterminada de la siguiente manera:

mode            = LIST
separator       = "|"
main prompt     = "sqlite> "
continue prompt = "   ...> "

o Si la variable de entorno XDG_CONFIG_HOME está establecida, entonces se busca ${XDG_CONFIG_HOME}/sqlite3/sqliterc, de lo contrario, se busca ~/.config/sqlite3/sqliterc. Si el archivo seleccionado no existe, se utiliza el archivo de reserva ~/.sqliterc. Generalmente solo debe contener metacomandos.

o Si está presente la opción -init, se procesa el archivo especificado.

o Se procesan todas las demás opciones de la línea de comandos.

ARCHIVO DE HISTORIAL

sqlite3 puede configurarse para usar un archivo de historial para guardar sentencias SQL y metacomandos introducidos interactivamente. Estas sentencias y comandos se pueden recuperar, editar y reutilizar en los prompts principal y de continuación. Si la variable de entorno SQLITE_HISTORY está establecida, se usará como nombre del archivo de historial, exista o no previamente. Si no está establecida pero la variable de entorno XDG_STATE_HOME sí lo está, entonces se usa ${XDG_STATE_HOME}/sqlite_history. Si XDG_STATE_HOME no está establecida, entonces se usa ~/.local/state/sqlite_history. Si el archivo seleccionado no existe, se usará ~/.sqlite_history como archivo de historial. Si se encuentra algún archivo de historial, se escribirá si el shell sale del modo interactivo normalmente, independientemente de si existía previamente, aunque la escritura fallará silenciosamente si el directorio del archivo de historial no existe.
