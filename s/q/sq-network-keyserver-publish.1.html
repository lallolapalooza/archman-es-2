NOMBRE

sq-network-keyserver-publish - Publicar certificados en servidores de claves

SINOPSIS

sq network keyserver publish [OPCIONES]

DESCRIPCIÓN

Publicar certificados en servidores de claves.

Envía certificados a los servidores de claves configurados para su publicación. Por defecto, los certificados se envían a `hkps://keys.openpgp.org`, `hkps://mail-api.proton.me`, `hkps://keys.mailvelope.com`, `hkps://keyserver.ubuntu.com` y `hkps://sks.pod01.fleetstreetops.com`. Esto se puede modificar usando `--servers`.

OPCIONES

Opciones de subcomando

--cert=HUella_digital|ID_CLAVE
Usar certificados con la huella digital o ID de clave especificada
--cert-domain=DOMINIO
Usar certificados donde un ID de usuario incluya una dirección de correo electrónico para el dominio especificado
--cert-email=CORREO
Usar certificados donde un ID de usuario incluya la dirección de correo electrónico especificada
--cert-file=RUTA
Leer certificados de RUTA
--cert-userid=ID_USUARIO
Usar certificados con el ID de usuario especificado
--server=URI
Establecer un servidor de claves a usar (se puede dar varias veces)
El valor por defecto se puede cambiar en el archivo de configuración usando la configuración `network.keyserver.servers`.
[por defecto: hkps://keys.openpgp.org, hkps://mail-api.proton.me, hkps://keys.mailvelope.com, hkps://keyserver.ubuntu.com, hkps://sks.pod01.fleetstreetops.com]

Opciones globales

Ver sq(1) para una descripción de las opciones globales.

EJEMPLOS

Publicar el certificado de Alice en los servidores de claves por defecto.

sq network keyserver publish --cert-email=alice@example.org
