SQFSTAR(1) Comandos de usuario SQFSTAR(1)

NOMBRE

sqfstar - herramienta para crear un sistema de archivos squashfs a partir de un archivo tar

SINOPSIS


cat xxx.tar | sqfstar [OPCIONES] FILESYSTEM [archivos a excluir]
zcat xxx.tgz | sqfstar [OPCIONES] FILESYSTEM [archivos a excluir]
xzcat xxx.tar.xz | sqfstar [OPCIONES] FILESYSTEM [archivos a excluir]
zstdcat xxx.tar.zst | sqfstar [OPCIONES] FILESYSTEM [archivos a excluir]

DESCRIPCIÓN

Squashfs es un sistema de archivos de solo lectura altamente comprimido para Linux. Utiliza compresión gzip/xz/lzo/lz4/zstd para comprimir tanto archivos, inodos como directorios. Los inodos en el sistema son muy pequeños y todos los bloques se empaquetan para minimizar la sobrecarga de datos. Se admiten tamaños de bloque superiores a 4K hasta un máximo de 1 Mbyte (tamaño de bloque predeterminado de 128K).

Squashfs está diseñado para uso general de sistemas de archivos de solo lectura, para uso de archivo (es decir, en casos donde se puede usar un archivo .tar.gz), y en sistemas con restricciones de dispositivo de bloque/memoria (por ejemplo, sistemas integrados) donde se necesita baja sobrecarga.

OPCIONES

Opciones de compresión del sistema de archivos:

-b TAMAÑO-BLOQUE
establece el bloque de datos en TAMAÑO-BLOQUE. Predeterminado 128 Kbytes. Opcionalmente, se puede dar un sufijo de K, KB, Kbytes o M, MB, Mbytes para especificar Kbytes o Mbytes respectivamente.
-comp COMP
selecciona la compresión COMP. Ejecuta -help-comp COMP para obtener las opciones del compresor para COMP, o ALL para todos los compresores. Compresores disponibles: gzip (predeterminado), lzo, lz4, xz, zstd, lzma.
-noI
no comprime la tabla de inodos.
-noId
no comprime la tabla uid/gid (implícito por -noI).
-noD
no comprime los bloques de datos.
-noF
no comprime los bloques de fragmentos.
-noX
no comprime los atributos extendidos.
-no-compression
no comprime ninguno de los datos o metadatos. Esto es equivalente a especificar -noI -noD -noF y -noX.

Opciones de creación del sistema de archivos:

-exports
hace que el sistema de archivos sea exportable a través de NFS.
-no-sparse
no detecta archivos dispersos.
-no-fragments
no usa fragmentos.
-no-tailends
no empaqueta las colas en fragmentos.
-no-duplicates
no realiza la comprobación de duplicados.
-no-hardlinks
no crea enlaces duros de archivos, sino que almacena duplicados.
-regex
permite el uso de expresiones regulares POSIX en directorios/archivos a excluir.
-ignore-zeros
permite concatenar archivos tar y alimentarlos a Sqfstar. Normalmente, un archivo tar tiene dos bloques consecutivos de 512 bytes llenos de ceros que significan fin de archivo y Sqfstar dejará de leer después del primer archivo tar al encontrarlos. Esta opción hace que Sqfstar ignore los bloques llenos de ceros.
-ef ARCHIVO-EXCLUSION
lista de directorios/archivos a excluir. Uno por línea.

Opciones de tiempo del sistema de archivos:

-mkfs-time TIEMPO
establece la marca de tiempo de creación del sistema de archivos en TIEMPO. TIEMPO puede ser "inode", que significa usar la marca de tiempo de inodo más reciente, un entero sin signo de 32 bits que indica segundos desde la época (1970-01-01) o un valor de cadena que se pasa al comando "date" para su análisis. Se puede utilizar cualquier valor de cadena que el comando date reconozca, como "now", "last week" o "Wed Feb 15 21:02:39 GMT 2023".
-inode-time TIEMPO
establece las marcas de tiempo de todos los archivos y directorios en TIEMPO. TIEMPO puede ser "inode", que significa usar la marca de tiempo de inodo más reciente, un entero sin signo de 32 bits que indica segundos desde la época (1970-01-01) o un valor de cadena que se pasa al comando "date" para su análisis. Se puede utilizar cualquier valor de cadena que el comando date reconozca, como "now", "last week" o "Wed Feb 15 21:02:39 GMT 2025". Esta opción establece y anula la opción -root-time.
-root-time TIEMPO
establece la marca de tiempo del directorio raíz en TIEMPO. TIEMPO puede ser "inode", que significa usar la marca de tiempo de inodo más reciente, un entero sin signo de 32 bits que indica segundos desde la época (1970-01-01) o un valor de cadena que se pasa al comando "date" para su análisis. Se puede utilizar cualquier valor de cadena que el comando date reconozca, como "now", "last week" o "Wed Feb 15 21:02:39 GMT 2025".
-repro
construye una imagen de sistema de archivos reproducible. Esto es equivalente a -mkfs-time inode, que logra la reproducibilidad estableciendo el tiempo de construcción del sistema de archivos en la marca de tiempo de inodo más reciente. Obviamente, la imagen no será reproducible si cambian las marcas de tiempo o el contenido.
-repro-time TIEMPO
construye una imagen de sistema de archivos reproducible. Esto es equivalente a especificar -mkfs-time TIEMPO y -inode-time TIEMPO, lo que logra la reproducibilidad estableciendo todas las marcas de tiempo en TIEMPO. Esta opción se puede utilizar en casos donde las marcas de tiempo pueden cambiar, y donde -repro no se puede utilizar por este motivo.

Opciones de permisos del sistema de archivos:

-all-root
hace que todos los archivos y directorios sean propiedad de root.
-root-mode MODO
establece los permisos del directorio raíz en MODO. MODO puede ser simbólico u octal (ver sección Especificación de modo simbólico). El modo raíz predeterminado es ugo=rwx o 0777 octal.
-root-uid USUARIO
establece el propietario del directorio raíz en el USUARIO especificado, USUARIO puede ser un uid entero o un nombre de usuario.
-root-gid GRUPO
establece el grupo del directorio raíz en el GRUPO especificado, GRUPO puede ser un gid entero o un nombre de grupo.
-force-file-mode MODO
establece todos los permisos de archivo (no directorio) en MODO. MODO puede ser simbólico u octal (ver sección Especificación de modo simbólico).
-force-dir-mode MODO
establece todos los permisos de directorio en MODO. MODO puede ser simbólico u octal (ver sección Especificación de modo simbólico).
-force-uid USUARIO
establece todos los uid de archivos y directorios en el USUARIO especificado, USUARIO puede ser un uid entero o un nombre de usuario.
-force-gid GRUPO
establece todos los gid de archivos y directorios en el GRUPO especificado, GRUPO puede ser un gid entero o un nombre de grupo.
-uid-gid-offset VALOR
desplaza todos los uid y gid por el VALOR especificado. VALOR debe ser un entero positivo.
-default-mode MODO
los archivos tar a menudo no almacenan los permisos de los directorios intermedios. Esta opción establece los permisos predeterminados del directorio en MODO. MODO puede ser simbólico u octal (ver sección Especificación de modo simbólico). El modo predeterminado es u=rwx,go=rx o 0755 octal. Esto también establece el modo del directorio raíz.

OPTIONS

See sqfstar(1).

-comp COMPRESSOR
Specify the compression algorithm to use. The following compressors are available: gzip (default), lzo, lz4, xz, zstd, lzma (deprecated).
-b BLOCK_SIZE
Specify the block size for the filesystem. BLOCK_SIZE can be specified as a size in bytes (e.g. 1024) or as a power of 2 multiplier (e.g. 128k, 1M).
-noI
Do not add an index into the filesystem. This will save space, but will make filesystem lookups slower.
-noId
Do not add id table into the filesystem. This will save space, but will make filesystem lookups slower.
-noD
Do not add directory entries into the filesystem. This will save space, but will make filesystem lookups slower.
-noF
Do not add file entries into the filesystem. This will save space, but will make filesystem lookups slower.
-noX
Do not add extended attributes into the filesystem. This will save space, but will make filesystem lookups slower.
-all-time
Set all timestamps to the current time.
-no-duplicates
Do not remove duplicate file contents.
-root-uid UID
Set the UID of the root directory.
-root-gid GID
Set the GID of the root directory.
-root-mode MODE
Set the mode of the root directory.
-no-fragments
Do not use fragments. Fragments are small pieces of files that are smaller than the block size. Using fragments can save space, but may also slow down filesystem access.
-no-sparse
Do not use sparse files. Sparse files are files that contain a large number of null bytes. Using sparse files can save space, but may also slow down filesystem access.
-no-xattrs
Do not store extended attributes.
-p PSEUDO
Specify a pseudo file definition. See PSEUDO FILE DEFINITION FORMAT below.
-quiet
Do not print progress information.
-verbose
Print verbose debugging information.
-version
Print version information and exit.
-noIdTableCompression
alternative name for -noId.
-noDataCompression
alternative name for -noD.
-noFragmentCompression
alternative name for -noF.
-noXattrCompression
alternative name for -noX.

SYMBOLIC MODE SPECIFICATION

The symbolic mode is of the format [ugoa]*[[+-=]PERMS]+. PERMS = [rwxXst]+ or [ugo], and the sequence can be repeated separated with commas.

A combination of the letters ugoa specify which permission bits will be affected, u means user, g means group, o means other, and a means all or ugo.

The next letter is +, - or =. The letter + means add to the existing permission bits, - means remove the bits from the existing permission bits, and = means set the permission bits.

The permission bits (PERMS) are a combination of [rwxXst] which sets/adds/removes those bits for the specified ugoa combination, r means read, w means write and x means execute for files or search for directories. X has a special meaning, if the file is a directory it is equivalent to x or search, but if it is a non-directory, it only takes effect if execute is already set for user, group or other. The s flag sets user or group ID on execution, and the t flag on a directory sets restricted deletion, or historically made the file sticky if a non-directory.

The permission bits can also be u, g or o, which takes the permission bits from the user, group or other of the file respectively.

EXIT STATUS

0
Sqfstar successfully generated a filesystem.
1
Fatal errors occurred, Sqfstar aborted and did not generate a filesystem.

COMPRESSORS AVAILABLE AND COMPRESSOR SPECIFIC OPTIONS

gzip (default):

-Xcompression-level COMPRESSION-LEVEL
COMPRESSION-LEVEL should be 1 .. 9 (default 9).
-Xwindow-size WINDOW-SIZE
WINDOW-SIZE should be 8 .. 15 (default 15).
-Xstrategy strategy1,strategy2,...,strategyN
Compress using strategy1,strategy2,...,strategyN in turn and choose the best compression. Available strategies: default, filtered, huffman_only, run_length_encoded and fixed.

lzo:

-Xalgorithm ALGORITHM
Where ALGORITHM is one of: lzo1x_1, lzo1x_1_11, lzo1x_1_12, lzo1x_1_15, lzo1x_999 (default).
-Xcompression-level COMPRESSION-LEVEL
COMPRESSION-LEVEL should be 1 .. 9 (default 8). Only applies to lzo1x_999 algorithm.

lz4:

-Xhc
Compress using LZ4 High Compression.

xz:

-Xbcj filter1,filter2,...,filterN
Compress using filter1,filter2,...,filterN in turn (in addition to no filter), and choose the best compression. Available filters: x86, arm, armthumb, arm64, powerpc, sparc, ia64, riscv.
-Xdict-size DICT-SIZE
Use DICT-SIZE as the XZ dictionary size. The dictionary size can be specified as a percentage of the block size, or as an absolute value. The dictionary size must be less than or equal to the block size and 8192 bytes or larger. It must also be storable in the xz header as either 2^n or as 2^n+2^(n+1). Example dict-sizes are 75%, 50%, 37.5%, 25%, or 32K, 16K, 8K etc.

zstd:

-Xcompression-level COMPRESSION-LEVEL
COMPRESSION-LEVEL should be -131072 .. -1 or 1 .. 22 (default 15). Negative compression levels correspond to the zstd --fast option.

lzma:

(no options) (deprecated - no kernel support)

ENVIRONMENT

SQFS_CMDLINE
If set, this is used as the directory to write the file sqfs_cmdline which contains the command line arguments given to Sqfstar. Each command line argument is wrapped in quotes to ensure there is no ambiguity when arguments contain spaces. If the file already exists then the command line is appended to the file.
SOURCE_DATE_EPOCH
If set, this is used as the filesystem creation timestamp. Also any file timestamps which are after SOURCE_DATE_EPOCH will be clamped to SOURCE_DATE_EPOCH. See https://reproducible-builds.org/docs/source-date-epoch/ for more information.
PAGER
If set, this is used as the name of the program used to display the help text. The value can be a simple command or a pathname. The default is /usr/bin/pager.

EXAMPLES

sqfstar IMAGE.SQFS < archive.tar
Create a Squashfs filesystem from the uncompressed tar file "archive.tar". Sqfstar will use the default compressor (normally gzip), and block size of 128 Kbytes.
zcat archive.tgz | sqfstar IMAGE.SQFS
Create a Squashfs filesystem from the compressed tar file "archive.tgz". Sqfstar will use the default compressor (normally gzip), and block size of 128 Kbytes.
sqfstar -b 1M -comp zstd IMAGE.SQFS < archive.tar
Use a block size of 1 Mbyte and Zstandard compression to create the filesystem.
sqfstar -root-uid 0 -root-gid 0 IMAGE.SQFS < archive.tar
Tar files do not supply a definition for the root directory, and the default is to make the directory owned/group owned by the user running Sqfstar. The above command sets the ownership/group ownership to root.
sqfstar -root-mode 0755 IMAGE.SQFS < archive.tar
The default permissions for the root directory is 0777 (rwxrwxrwx). The above command sets the permissions to 0755 (rwxr-xr-x).
sqfstar -all-time n

EJEMPLOS

sqfstar IMAGE.SQFS < archive.tar
Crea una imagen Squashfs llamada IMAGE.SQFS a partir de la entrada estándar (archive.tar).
sqfstar -comp gzip IMAGE.SQFS < archive.tar
Crea una imagen Squashfs comprimida usando gzip.
sqfstar -le IMAGE.SQFS < archive.tar
Crea una imagen Squashfs con orden de bytes little-endian (predeterminado).
sqfstar -be IMAGE.SQFS < archive.tar
Crea una imagen Squashfs con orden de bytes big-endian.
sqfstar -no-duplicates IMAGE.SQFS < archive.tar
Desactiva la deduplicación de bloques.
sqfstar -set-time "now" IMAGE.SQFS < archive.tar
Establece todas las marcas de tiempo de archivos y directorios a "ahora" (hora actual) en el sistema de archivos.
sqfstar -force-uid phillip -force-gid phillip IMAGE.SQFS < archive.tar
Hace que todos los archivos y directorios en el sistema de archivos pertenezcan a "phillip".
sqfstar -force-file-mode ugo+r,go-w IMAGE.SQFS < archive.tar
Hace que todos los archivos sean legibles por todos, pero solo escribibles por el usuario; todos los demás bits de permiso no se ven afectados.
sqfstar IMAGE.SQFS file1 file2 < archive.tar
Excluye file1 y file2 del archivo tar al crear el sistema de archivos.
sqfstar IMAGE.SQFS "*.gz" < archive.tar
Excluye cualquier archivo en el directorio superior que coincida con el patrón comodín "*.gz".
sqfstar IMAGE.SQFS "... *.gz" < archive.tar
Excluye cualquier archivo que coincida con el patrón comodín "*.gz" en cualquier lugar dentro del archivo tar. El "..." inicial indica que el patrón comodín es "no anclado" y coincidirá en cualquier lugar.

Nota: al pasar nombres con comodines a Sqfstar, deben entrecomillarse (como en los ejemplos anteriores), para asegurar que no sean procesados por el shell.

Usando definiciones de pseudo archivos

sqfstar -p "build_dir d 0644 0 0" IMAGE.SQFS < archive.tar
Crea un directorio llamado "build_dir" en el sistema de archivos de salida.
sqfstar -p "version.txt l /tmp/build/version" IMAGE.SQFS < archive.tar
Crea una referencia llamada "version.txt" a un archivo que no está en el archivo tar, que actúa como si ese archivo estuviera en el archivo tar.
sqfstar -p "date.txt f 0644 0 0 date" IMAGE.SQFS < archive.tar
Crea un archivo llamado "date.txt" que contiene la salida (stdout) de la ejecución del comando "date".
sqfstar -p "\"hello world\" f 0644 0 0 date" IMAGE.SQFS < archive.tar
Como el anterior, pero mostrando que los nombres de archivo pueden tener espacios, si están entrecomillados. Las comillas deben escaparse con una barra invertida para protegerlas del shell.
sqfstar -p "input f 0644 root root dd if=/dev/sda1 bs=1024" IMAGE.SQFS < archive.tar
Crea un archivo que contiene el contenido de la partición "/dev/sda1". Lo anterior permite capturar la entrada de estos archivos especiales y colocarla en el sistema de archivos Squashfs.

Nota: las definiciones de pseudo archivos deben entrecomillarse (como en los ejemplos anteriores), para asegurar que se pasen a Mksquashfs como un único argumento, y para asegurar que no sean procesados por el shell.
