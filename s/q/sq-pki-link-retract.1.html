SQ(1) Comandos de usuario SQ(1)

NOMBRE

sq-pki-link-retract - Retirar enlaces

SINOPSIS

sq pki link retract [OPCIONES]

DESCRIPCIÓN

Retira enlaces.

Este comando retira enlaces que fueron creados previamente usando `sq pki link add` o `sq pki link authorize`. Ver la documentación de ese subcomando para más detalles. Nota: esto se llama `retract` (retirar) y no `remove` (eliminar), porque las certificaciones no se eliminan. En su lugar, se añade una nueva certificación que indica que la vinculación no ha sido autenticada.

`sq pki link retract` respeta el tiempo de referencia establecido por el argumento de nivel superior `--time`. Esto hace que un enlace se retire a partir de un momento determinado en lugar del momento actual.

OPCIONES

Opciones del subcomando

--all
Usar todos los IDs de usuario autofirmados.
--cert=HUELLA_DIGITAL|ID_CLAVE
Usar certificados con la huella digital o ID de clave especificado.
--cert-special=ESPECIAL
Usar certificados identificados por el nombre especial.
[posibles valores: public-directories, keys.openpgp.org, keys.mailvelope.com, proton.me, wkd, dane, autocrypt, web]
--email=CORREO
Usar un ID de usuario con la dirección de correo electrónico especificada.
El ID de usuario consiste solo en la dirección de correo electrónico. La dirección de correo electrónico no tiene que aparecer en un ID de usuario autofirmado.
--recreate
Recrear la firma incluso si los parámetros no cambiaron.
Si los parámetros del enlace no cambiaron, y por lo tanto no debería ser necesario crear una firma, omitimos la operación. Se puede dar esta bandera para forzar la recreación de la firma de todos modos.
--signature-notation NOMBRE VALOR
Añadir una notación a la firma.
El nombre de una notación definida por el usuario debe tener el formato `nombre@a.dominio.que.tu.controlas.org`. Si el nombre de la notación comienza con un `!`, entonces la notación se marca como crítica. Si un consumidor de una firma no entiende una notación crítica, entonces ignorará la firma. La notación se marca como legible por humanos.
--userid=ID_USUARIO
Usar el ID de usuario especificado.
El ID de usuario especificado no necesita ser autofirmado.
Debido a que usar un ID de usuario que no es autofirmado a menudo es un error, necesitas usar esta opción para aceptarlo explícitamente.
--userid-by-email=CORREO
Usar el ID de usuario autofirmado con la dirección de correo electrónico especificada.

Opciones globales

Ver sq(1) para una descripción de las opciones globales.

EJEMPLOS

Vincular el certificado EB28F26E2739A4870ECC47726F0073F60FD0CBF0 con la dirección de correo electrónico alice@example.org.

sq pki link add \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--add-email=alice@example.org

Retirar la aceptación del certificado EB28F26E2739A4870ECC47726F0073F60FD0CBF0 y la dirección de correo electrónico alice@example.org.

sq pki link retract \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--email=alice@example.org

Retirar la aceptación del certificado EB28F26E2739A4870ECC47726F0073F60FD0CBF0 y todos los IDs de usuario asociados. Esto invalida efectivamente todos los enlaces.

sq pki link retract \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all
