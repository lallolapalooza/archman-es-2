SQ(1) Comandos de usuario SQ(1)

NOMBRE

sq-pki - Autenticar certificados usando la Web de Confianza

SINOPSIS

sq pki authenticate [OPCIONES]
sq pki lookup [OPCIONES]
sq pki identify [OPCIONES]
sq pki vouch [OPCIONES] SUBCOMANDO
sq pki link [OPCIONES] SUBCOMANDO
sq pki path [OPCIONES] HASH|ID

DESCRIPCIÓN

Autenticar certificados usando la Web de Confianza.

La "Web de Confianza" es un modelo de confianza descentralizado popularizado por PGP. Es un superconjunto de X.509, que es un modelo de confianza jerárquico, y es el modelo de confianza más popular en internet pública hoy en día. Tal como se usa en internet pública, sin embargo, X.509 se basa en un puñado de autoridades de certificación (AC) globales que a menudo socavan su seguridad.

La Web de Confianza es más matizada que X.509. Usando la Web de Confianza, se requieren múltiples caminos independientes para autenticar una vinculación confiando solo parcialmente en las AC. Esto evita que un solo actor malintencionado comprometa su seguridad. Y aquellos que tienen requisitos de seguridad más estrictos pueden usar la Web de Confianza de manera completamente descentralizada donde solo los individuos que seleccionan – que no son necesariamente instituciones – actúan como introductories de confianza.

SUBCOMANDOS

sq pki authenticate

Autenticar una vinculación.

Autentica una vinculación (un certificado y un ID de usuario) buscando un camino desde las raíces de confianza hasta la vinculación especificada en la Web de Confianza. Dado que las certificaciones pueden expresar incertidumbre (es decir, las certificaciones pueden marcarse como que solo otorgan confianza parcial o marginal), pueden ser necesarios múltiples caminos.

Se devolverá un error si no se pudo autenticar ninguna vinculación con el nivel especificado (por defecto: autenticada completamente, es decir, una cantidad de confianza de 120).

Si se encuentran caminos válidos hacia la vinculación, se imprimirán en la salida estándar, ya sea que sean suficientes para autenticar la vinculación o no.

sq pki lookup

Buscar los certificados asociados con un ID de usuario.

Identifica vinculaciones autenticadas (pares de ID de usuario y certificado) donde el ID de usuario coincide con el ID de usuario especificado.

Se devolverá un error si no se pudo autenticar ninguna vinculación con el nivel especificado (por defecto: autenticada completamente, es decir, una cantidad de confianza de 120).

Si una vinculación pudo ser autenticada parcialmente (es decir, su cantidad de confianza es mayor que 0), entonces la vinculación se muestra, incluso si la confianza está por debajo del umbral especificado.

sq pki identify

Identificar un certificado.

Identifica un certificado encontrando vinculaciones autenticadas (pares de ID de usuario y certificado).

Se devolverá un error si no se pudo autenticar ninguna vinculación con el nivel especificado (por defecto: autenticada completamente, es decir, una cantidad de confianza de 120).

Si una vinculación pudo ser autenticada parcialmente (es decir, su cantidad de confianza es mayor que 0), entonces la vinculación se muestra, incluso si la confianza está por debajo del umbral especificado.

sq pki vouch

Gestionar certificaciones.

Un aval (vouch) es una declaración potencialmente pública de que algo es verdad. En OpenPGP hay dos tipos principales de declaraciones que puedes hacer: certificaciones y autorizaciones.

Puedes afirmar que un certificado pertenece a una entidad en particular. Esto no dice nada sobre la confiabilidad de una entidad. Por ejemplo, podrías certificar `bob@nsa.gov` para un certificado dado. Esto solo significa que crees que la persona detrás de la dirección de correo electrónico `bob@nsa.gov` realmente controla ese certificado. Esa es una declaración útil de hacer incluso si no confías en que esa persona actúe en tu interés.

Alternativamente, puedes decir que crees que un certificado es un introductor de confianza razonable. Un introductor de confianza es un tercero que autorizas para hacer introducciones. Por ejemplo, tu banco podría tener una autoridad de certificación (AC). Si verificas la huella digital de la AC, puedes autorizarla a hacer certificaciones. Eso significa que sq usará esas certificaciones casi como si tú las hubieras hecho. Esto es conveniente ya que ahora puedes autenticar a cualquiera de los empleados del banco.

Autorizar a un introductor de confianza le da mucho poder. Puedes limitar la cantidad de poder que le das diciendo que solo está autorizado a certificar IDs de usuario que tengan una dirección de correo electrónico en uno o más dominios, por ejemplo. De esta manera, puedes aprovechar los lugares donde tus intereses y los de una AC están alineados, y protegerte de acciones potencialmente maliciosas. Por ejemplo, podrías autorizar a la AC de tu banco a certificar IDs de usuario que tengan una dirección de correo electrónico en `bank.com`. sq entonces ignorará cualquier otra certificación hecha por la AC.

sq pki link

Gestionar enlaces de certificados y IDs de usuario autenticados.

Vincular un certificado y un ID de usuario es una forma de hacer que `sq` considere auténtica una vinculación. Otra forma es usar `sq pki vouch add` para certificar la vinculación con una raíz de confianza configurada explícitamente. La funcionalidad de vinculación suele ser más fácil de manejar y la información es privada por defecto.

Las vinculaciones autenticadas se pueden usar para designar un certificado usando un nombre simbólico. Por ejemplo, usando las opciones `--for-userid` y `--for-email` de `sq encrypt`, un usuario puede designar un certificado usando un ID de usuario o una dirección de correo electrónico que está autenticada para ese certificado.

`sq` también usa certificados autenticados para autenticar otros datos. Por ejemplo, `sq verify` considera que las firmas hechas por un certificado autenticado son válidas.

Los usuarios pueden crear un enlace usando `sq pki link add`. Ese enlace puede ser posteriormente retractado usando `sq pki link retract`. Un certificado también puede ser aceptado como introductor de confianza usando `sq pki link authorize`.

`sq` implementa la vinculación usando certificaciones no exportables y una raíz de confianza implícita. Un directorio de certificados OpenPGP, el almacén de certificados predeterminado utilizado por `sq`, incluye una raíz de confianza local, que se almacena bajo el nombre especial `trust-root`. Cuando el usuario instruye a `sq` a aceptar una vinculación, `sq` utiliza la raíz de confianza local para crear una certificación no exportable, que almacena en el directorio de certificados. De esta manera, las operaciones que utilizan la Web de Confianza para autenticar una vinculación utilizan automáticamente los enlaces.

Cuando un usuario retrae un enlace, `sq` crea una nueva certificación no exportable con confianza cero. Esta certificación suprime el enlace anterior.

sq pki path

Verificar el camino especificado.

Un camino es una secuencia de certificados que comienza en la raíz, y un ID de usuario. Esta función comprueba que cada segmento del camino tenga una certificación válida, que también satisfaga cualquier restricción (cantidad de confianza, profundidad de confianza, expresiones regulares).

Si no se encuentra un camino válido, entonces este subcomando también lintra el camino. En particular, informa si alguna certificación es insuficiente, por ejemplo, no tiene suficiente profundidad de confianza, o es inválida, por ejemplo, porque usa SHA-1, pero el uso de SHA-1 ha sido deshabilitado.

EJEMPLOS

sq pki authenticate

Autenticar una vinculación específica.

sq pki authenticate --cert \
EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --userid \
"Alice <alice@example.org>"

Comprobar si podemos autenticar cualquier ID de usuario con la dirección de correo electrónico especificada para el certificado dado.

sq pki authenticate --cert \
EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --email \
alice@example.org

sq pki lookup

Buscar certificados que puedan autenticarse para el ID de usuario dado.

sq pki lookup --userid "Alice <alice@example.org>"

Buscar certificados que tengan un ID de usuario con la dirección de correo electrónico especificada, y que dicho ID de usuario pueda ser autenticado.

sq pki lookup --email alice@example.org

sq pki identify

Identifica los identificadores de usuario que pueden ser autenticados para el certificado.

sq pki identify --cert \
EB28F26E2739A4870ECC47726F0073F60FD0CBF0

Lista todos los identificadores de usuario que han sido certificados por cualquier persona.

sq pki identify --gossip --cert \
511257EBBF077B7AEDAE5D093F68CB84CE537C9A

sq pki path

Verifica que Alice certificó un Identificador de Usuario particular para el certificado de Bob.

sq pki path EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
511257EBBF077B7AEDAE5D093F68CB84CE537C9A --userid \
"Bob <bob@example.org>"
