sqlsharp(1) Manual de comandos generales sqlsharp(1)

NOMBRE

sqlsharp - Herramienta de línea de comandos Mono SQL Query

SINOPSIS

sqlsharp [-f nombre_archivo] [-o nombre_archivo] [-s]

DESCRIPCIÓN

sqlsharp es una herramienta Mono SQL utilizada para introducir consultas SQL a una base de datos utilizando proveedores de datos Mono.

OPCIONES

Se soportan las siguientes opciones:

-f nombre_archivo
Archivo de salida para cargar comandos SQL.
-o nombre_archivo
Archivo de salida para enviar resultados.
-s
Modo silencioso.

CÓMO USAR

La herramienta SQL acepta comandos a través de su interfaz de línea de comandos. Los comandos comienzan con una barra invertida seguida del nombre del comando.

Ejemplo:

\open

Básicamente, hay cinco comandos que un usuario debe conocer: \provider, \connectionstring, \open, \quit, y \help

Para conectarse a una base de datos, necesita hacer lo siguiente:

1. Establecer el proveedor de datos con \provider

Ejemplo:
	SQL# \provider mysql

2. Establecer la cadena de conexión con \connectionstring

Ejemplo:
	SQL# \connectionstring Database=test

3. Abrir una conexión a la base de datos con \open

Ejemplo:
	SQL# \open

COMANDOS DE CONEXIÓN Y PROVEEDOR

Estos comandos se utilizan para configurar el proveedor, la cadena de conexión y abrir/cerrar la conexión a la base de datos.

ConnectionString
Establece la Cadena de Conexión 
Ejemplo:
	SQL# \ConnectionString Database=testdb
	o
	SQL# \cs Database=testdb
Para más ejemplos, ver la sección EJEMPLOS DE CADENA DE CONEXIÓN.
Provider
Establece el Proveedor de la Fuente de Datos. Para una lista de Proveedores, ver la sección PROVEEDORES. 
Ejemplo: para establecer el proveedor para MySQL:
	SQL# \provider mysql
           o
	SQL# \p mysql

Nota: si necesita cargar un proveedor externo en SQL#, 
      consulte el comando SQL# \loadextprovider
ListProviders
Lista los Proveedores ADO.NET 2.0 disponibles. 
Ejemplo:
	SQL# \ListProviders 
	   o
	SQL# \listp
BCS
Le pide la creación de cada parámetro de conexión y construye la cadena de conexión, además le permite introducir una contraseña que no se muestra. 
Ejemplo:
	SQL# \bcs
	Opción de Cadena de Conexión: Data Source [] SQL# blazer
	Opción de Cadena de Conexión: Persist Security Info [False] SQL# 
	Opción de Cadena de Conexión: Integrated Security [False] SQL# 
	Opción de Cadena de Conexión: User ID [] SQL# scott
	Contraseña: *****
	Opción de Cadena de Conexión: Enlist [False] SQL# 
	Opción de Cadena de Conexión: Pooling [True] SQL# 
	Opción de Cadena de Conexión: Min Pool Size [0] SQL# 
	Opción de Cadena de Conexión: Max Pool Size [100] SQL# 
	Opción de Cadena de Conexión: Unicode [False] SQL# 
	Opción de Cadena de Conexión: Load Balance Timeout [0] SQL# 
	Opción de Cadena de Conexión: Omit Oracle Connection Name [False] SQL# 
	Cadena de Conexión establecida.
LoadExtProvider
ENSAMBLADO CLASE para cargar un proveedor externo. Use el nombre completo de su ensamblado y su clase de Conexión. 
Ejemplo: para cargar el proveedor MySQL Mono.Data.MySql
	SQL# \loadextprovider Mono.Data.MySql Mono.Data.MySql.MySqlConnection
Open
Abre una conexión a la base de datos. 
Ejemplo:
	SQL# \open
Close
Cierra la conexión a la base de datos. 
Ejemplo:
	SQL# \close
Default
Muestra las variables predeterminadas, como Proveedor y Cadena de Conexión. 
Ejemplo:
	SQL# \defaults
Q
Salir. 
Ejemplo:
	SQL# \q

COMANDOS DE EJECUCIÓN SQL

Comandos para ejecutar sentencias SQL.

e ejecuta consulta SQL (SELECT)

Ejemplo: para ejecutar una consulta

	SQL# SELECT * FROM EMPLOYEE
	SQL# \e
Nota: para que \e funcione automáticamente después de introducir una consulta,
      añada un punto y coma ; al final de la consulta.

Ejemplo: para introducir y ejecutar una consulta al mismo tiempo
	SQL# SELECT * FROM EMPLOYEE;
exenonquery
ejecuta una consulta SQL que no es SELECT. 
Ejemplo: para insertar una fila en una tabla:

	SQL# INSERT INTO SOMETABLE (COL1, COL2) VALUES('ABC','DEF')
	SQL# \exenonquery

Nota: esto puede ser usado para aquellos proveedores nuevos que aún no tienen
      la capacidad de ejecutar consultas.
exescalar
ejecuta SQL para obtener una sola fila y una sola columna. 
Ejemplo: para ejecutar un agregado Maximo
		SQL# SELECT MAX(grade) FROM class
		SQL# \exescalar
exexml
NOMBRE_ARCHIVO para ejecutar SQL y guardar la salida en un archivo XML. 
Ejemplo: 
	SQL# SELECT fname, lname, hire_date FROM employee
	SQL# \exexml employee.xml

Nota: esto depende de que DataAdapter, DataTable y DataSet
      funcionen correctamente.

COMANDOS DE ARCHIVOS

Comandos para importar comandos desde un archivo a SQL# y viceversa.

f
NOMBRE_ARCHIVO para leer un lote de comandos SQL# desde un archivo. 
Ejemplo:
	SQL# \f batch.sql#

Nota: los comandos SQL# se interpretan a medida que se leen. Si hay
      alguna sentencia SQL, se ejecuta.
o
NOMBRE_ARCHIVO para escribir el resultado de los comandos ejecutados en un archivo. 
Ejemplo:
	SQL# \o result.txt
load
NOMBRE_ARCHIVO para cargar comandos SQL desde un archivo al buffer de SQL. 
Ejemplo:
	SQL# \load commands.sql
save
NOMBRE_ARCHIVO para guardar los comandos SQL del buffer de SQL a un archivo. 
Ejemplo:
	SQL# \save commands.sql

COMANDOS DE PROPÓSITO GENERAL

Comandos generales para usar.

h
Muestra la ayuda (todos los comandos). 
Ejemplo:
	SQL# \h
s
VERDADERO, FALSO para silenciar mensajes. 
Ejemplo 1:
	SQL# \s true

Ejemplo 2:
	SQL# \s false
r
Reinicia o borra el buffer de consulta. 
Ejemplo:
	SQL# \r
print
Muestra lo que hay actualmente en el buffer SQL. 
Ejemplo:
	SQL# \print
VARIABLES DE SHELL QUE PUEDEN SER USADAS COMO PARÁMETROS Comandos para establecer variables que pueden ser usadas como Parámetros en una sentencia SQL. Si el SQL contiene algún parámetro, y este no tiene una variable establecida, se le pedirá al usuario el valor para cada parámetro faltante.
set
NOMBRE VALOR para establecer una variable interna. 
Ejemplo:
	SQL# \set sFirstName John
unset
NOMBRE para eliminar una variable interna. 
Ejemplo:
	SQL# \unset sFirstName
variable
NOMBRE para mostrar el valor de una variable interna. 
Ejemplo:
	SQL# \variable sFirstName

OPCIONES DE SOPORTE DE PROVEEDOR

Habilita o deshabilita el soporte para una opción de proveedor particular.

UseParameters
VERDADERO, FALSO para usar parámetros.

PROVIDER SUPPORT OPTIONS

UseParameter
TRUE,FALSE enable/disable parameter substitution. If this option is TRUE, the SQL will be checked for parameters that do not have a value specified. If a parameter is found, the user will be prompted for a value.

This option is useful when you are executing SQL that contains parameters, and you want to be prompted for the value of these parameters. This option is not related to the parameters used to connect to the database, but rather to the parameters used in the SQL statements themselves.

When this option is set to TRUE, the tool will parse the SQL statements for parameters. Parameters are typically represented by a symbol such as '@' or '?' followed by a name or number. If any of these parameters do not have a corresponding SQL# variable set, the user will be prompted to enter a value for that parameter.

This feature allows for dynamic execution of SQL queries where certain values can be provided at runtime, making the tool more flexible for interactive use or when dealing with parameterized queries where variable values might not be predetermined.

Example:
	SQL# \useparameter true

If this option is true, the SQL contains parameters, and for each parameter which does not have a SQL# variable set, the user will be prompted to enter the value For that parameter.

Example:
	SQL# \useparameter true

Default: false

UseSimpleReader
TRUE,FALSE to use simple reader when displaying results. 
Example:
	SQL# \usesimplereader true

Default: false. Mostly, this is dependent on the provider. If the provider does not have enough of IDataReader implemented to have the normal reader working, then the simple reader can be used. Providers like SqlClient, MySQL, and PostgreSQL have this ption defaulting to true.
