NOMBRE

squid - Servidor proxy caché web HTTP

SINOPSIS

squid [-dhisrvzCFNRSVYX] [--foreground] [-l instalación ] [-f archivo-config ] [-[au] puerto ] [-k señal ] [-n nombre-servicio ] [-O línea-de-comandos ]

DESCRIPCIÓN

squid es un servidor proxy caché de alto rendimiento para clientes web, compatible con objetos de datos FTP, ICAP, ICP, HTCP y HTTP. A diferencia del software de caché tradicional, Squid maneja todas las solicitudes en un único proceso no bloqueante.

Squid mantiene metadatos y especialmente objetos populares en caché en RAM, almacena en caché las búsquedas DNS, admite búsquedas DNS no bloqueantes e implementa el almacenamiento en caché negativo de las solicitudes fallidas.

Squid admite SSL, controles de acceso extensos y registro completo de solicitudes. Al utilizar los protocolos ligeros de caché de Internet ICP, HTCP o CARP, las cachés de Squid se pueden organizar en una jerarquía o malla para obtener ahorros de ancho de banda adicionales.

Squid consta de un programa servidor principal squid, algunos programas opcionales para procesamiento personalizado y autenticación, y algunas herramientas de gestión y cliente. Cuando squid se inicia, genera un número configurable de procesos auxiliares, cada uno de los cuales puede realizar búsquedas paralelas. Esto reduce la cantidad de tiempo que la caché espera los resultados.

Squid se deriva del Proyecto Harvest financiado por ARPA.

Esta página del manual solo enumera los argumentos de la línea de comandos. Para obtener detalles sobre cómo configurar Squid, consulte el archivo /etc/squid/squid.conf.documented, la FAQ de la wiki de Squid y los ejemplos en https://wiki.squid-cache.org/ , o el manual de configuración en la página principal de Squid http://www.squid-cache.org/Doc/config/

OPCIONES

-a puerto
Especifica el número de puerto HTTP donde Squid debe escuchar las solicitudes, además de cualquier especificación de http_port en squid.conf
-C
No capturar señales fatales.
-d nivel
Escribir depuración también en stderr.
-f archivo
Utiliza el archivo-config proporcionado en lugar de /etc/squid/squid.conf. Si el nombre del archivo comienza con ! o |, se asume que es un comando externo o una línea de comandos. Por ejemplo, se puede usar para preprocesar la configuración antes de que sea leída por Squid. Para facilitar esto, Squid también entiende la noción común de #line para indicar el archivo fuente real.
-F
No servir ninguna solicitud hasta que se reconstruya el almacén.
-h
Imprimir mensaje de ayuda.
-i
Instalar como un servicio de Windows (ver opción -n).
-k reconfigurar | rotar | apagar | interrumpir | matar | depurar | comprobar | analizar
Analiza el archivo de configuración, luego envía una señal a la copia en ejecución (excepto -k parse) y sale.
-l instalación
Utiliza la instalación de syslog especificada. Implica -s
-n nombre
Especifica el nombre del servicio de Windows a usar para operaciones de servicio, por defecto es: Squid
-N
Modo no daemon.
--foreground
El proceso padre no sale hasta que sus hijos hayan terminado. No tiene efecto con -N que no crea/sale al inicio.
--kid rolID
Desempeña un rol de proceso hijo SMP dado, con un ID dado. No uses esta opción. Está pensada solo para uso del proceso maestro.
-O opciones
Establece las opciones de línea de comandos del servicio de Windows en el Registro.
-r
Elimina un servicio de Windows (ver opción -n).
-R
No establecer REUSEADDR en el puerto.
-s
Habilita el registro a syslog. También configurable en /etc/squid/squid.conf
-S
Verificar doblemente el swap durante la reconstrucción.
-u puerto
Especifica el número de puerto ICP (por defecto: 3130), desactiva con 0.
-v
Imprimir versión y detalles de compilación.
-X
Forzar depuración completa.
-Y
Solo devolver UDP_HIT o UDP_MISS_NOFETCH durante la recarga rápida.
-z
Crea directorios de swap faltantes y otras estructuras de cache_dir faltantes, luego sale. Todos los tipos de cache_dir crean el directorio de nivel superior configurado si falta. Otras acciones son específicas del tipo. Por ejemplo, los sistemas de almacenamiento basados en ufs crean directorios L1 y L2 faltantes, mientras que Rock crea el archivo de base de datos faltante.
Esta opción no habilita la validación de las estructuras de swap presentes. Su enfoque está en la creación de piezas faltantes. Si nada falta, squid -z simplemente sale. Si sospecha de corrupción en cache_dir, debe eliminar el directorio cache_dir de nivel superior antes de ejecutar squid -z.
Por defecto, squid -z se ejecuta en modo daemon (para que las macros de configuración y otras características SMP funcionen como se espera), devolviendo el control al llamador antes de que los cache_dirs se inicialicen completamente. Si se ejecuta desde scripts de inicio o administradores de demonios, el llamador a menudo necesita esperar a que la inicialización se complete antes de continuar. Use la opción --foreground para evitar salidas prematuras. Para deshabilitar el modo daemon, use la opción -N.

ARCHIVOS

Archivos de configuración de Squid ubicados en /etc/squid/:

squid.conf
El archivo de configuración principal. Debe realizar cambios iniciales en este archivo para que squid funcione. Por ejemplo, la configuración predeterminada solo permite el acceso desde redes LAN privadas de RFC. Algunas distribuciones de paquetes bloquean incluso eso.
squid.conf.default
Copia de referencia del archivo de configuración. Siempre actualizada con la versión de Squid que esté utilizando.
Úselo para buscar la configuración predeterminada y la sintaxis después de actualizar.
squid.conf.documented
Copia de referencia del archivo de configuración. Siempre actualizada con la versión de Squid que esté utilizando.
Úselo para leer la documentación de las opciones de configuración disponibles en su compilación de Squid. El manual de configuración en línea también está disponible para una referencia completa de las opciones. verhttp://www.squid-cache.org/Doc/config/
msntauth.conf
El archivo de configuración principal para el autenticador de ejemplo MSNT.
errorpage.css
Hoja de estilos CSS para controlar la visualización de las páginas de error generadas. Úselo para establecer cualquier marca corporativa que necesite, se aplicará a todos los idiomas para los que Squid proporciona páginas de error.

Algunos archivos también ubicados en otros lugares:

/etc/squid/mime.conf (mime_table)
Asignaciones de tipos MIME para la pasarela FTP
/usr/share/squid/errors
Ubicación de las páginas de error y plantillas de Squid.
