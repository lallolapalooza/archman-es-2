NOMBRE

sq-pki-lookup - Busca los certificados asociados con un ID de usuario

SINOPSIS

sq pki lookup [OPCIONES]

DESCRIPCIÓN

Busca los certificados asociados con un ID de usuario.

Identifica las vinculaciones autenticadas (pares de ID de usuario y certificado) donde el ID de usuario coincide con el ID de usuario especificado.

Se devuelve un error si no se pudo autenticar ninguna vinculación con el nivel especificado (por defecto: completamente autenticada, es decir, una cantidad de confianza de 120).

Si se pudo autenticar parcialmente una vinculación (es decir, su cantidad de confianza es mayor que 0), entonces se muestra la vinculación, incluso si la confianza está por debajo del umbral especificado.

OPCIONES

Opciones de subcomando

--amount=CANTIDAD
La cantidad requerida de confianza
120 indica autenticación completa; los valores inferiores a 120 indican autenticación parcial. Cuando se pasa `--certification-network`, esto se establece por defecto en 1200, es decir, este comando intenta encontrar 10 rutas.
--certification-network
Trata la red como una red de certificación
Normalmente, la maquinaria de autenticación trata la red Web of Trust como una red de autenticación donde una certificación solo significa que la vinculación es correcta, no que el objetivo debe ser tratado como un introductor de confianza. En una red de certificación, los objetivos de las certificaciones se tratan como introductores de confianza con profundidad infinita, y se ignoran las expresiones regulares. Nota: La cantidad de confianza no cambia. Así es como funcionan la mayoría de los llamados algoritmos de búsqueda de rutas PGP.
--email=CORREO
Busca certificados que puedan ser autenticados para la dirección de correo electrónico especificada
Se devuelve un certificado si un ID de usuario con la dirección de correo electrónico especificada puede ser autenticado para ese certificado.
Para buscar un certificado con un ID de usuario que contenga solo la dirección de correo electrónico especificada, use `--userid <CORREO>`.
--gossip
Trata todos los certificados como raíces de confianza poco fiables
Esta opción es útil para averiguar qué piensan los demás sobre un certificado (es decir, rumores o cotilleos). En otras palabras, esto encuentra rutas arbitrarias a un certificado particular.
Los rumores son útiles para ayudar a identificar formas alternativas de autenticar un certificado. Por ejemplo, imagina que Ed quiere autenticar el certificado de Laura, pero pedirle directamente es inconveniente. Ed descubre que Micah ha certificado el certificado de Laura, pero Ed aún no ha autenticado el certificado de Micah. Si Ed está dispuesto a confiar en Micah como introductor de confianza, y autenticar el certificado de Micah es más fácil que autenticar el certificado de Laura, entonces Ed ha aprendido una forma más fácil de autenticar el certificado de Laura.
Estable desde 1.1.0.
--show-paths
Muestra por qué se autentica una vinculación
Por defecto, solo se muestra el grado de autenticación de un ID de usuario y una vinculación de certificado (un valor entre 0 y 120). Esto cambia la salida para mostrar también cómo se calculó ese valor, mostrando las rutas desde las raíces de confianza hasta las vinculaciones.
--unusable
Muestra las vinculaciones que no son utilizables
Normalmente, no se muestran los certificados y vinculaciones no utilizables. Esta opción considera las vinculaciones, incluso si no son no utilizables, porque (o los certificados) no son válidas según la política, están revocadas o no están activas.
Esta opción solo tiene sentido con `--gossip`, porque las vinculaciones no utilizables todavía se consideran no autenticadas.
Estable desde 1.1.0.
--userid=USERID
Busca certificados que puedan ser autenticados para el ID de usuario especificado
El ID de usuario especificado no necesita ser autofirmado.

Opciones globales

Vea sq(1) para una descripción de las opciones globales.

EJEMPLOS

Busca certificados que puedan ser autenticados para el ID de usuario dado.

sq pki lookup --userid "Alice <alice@example.org>"

Busca certificados que tengan un ID de usuario con la dirección de correo electrónico especificada, y que ese ID de usuario pueda ser autenticado.

sq pki lookup --email alice@example.org
