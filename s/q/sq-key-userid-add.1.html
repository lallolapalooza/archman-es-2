SQ(1) Comandos de usuario SQ(1)

NOMBRE

sq-key-userid-add - Añadir un ID de usuario

SINOPSIS

sq key userid add [OPCIONES]

DESCRIPCIÓN

Añadir un ID de usuario.

Un ID de usuario puede contener un nombre, como `Juliet`, o una dirección de correo electrónico, como `<juliet@example.org>`. Históricamente, un nombre y una dirección de correo electrónico solían combinarse como un único ID de usuario, como `Juliet <juliet@example.org>`. Sin embargo, los ID de usuario que incluyen información diferente, como nombre y dirección de correo electrónico, son más difíciles de razonar, por lo que hoy en día se prefieren usar ID de usuario distintos para el nombre y la dirección de correo electrónico.

`sq key userid add` respeta la hora de referencia establecida por el argumento de nivel superior `--time`. Establece la hora de creación de la firma de enlace del ID de usuario a la hora especificada.

OPCIONES

Opciones de subcomando

--allow-non-canonical-userids
No rechazar ID de usuario que no estén en formato canónico
Los ID de usuario canónicos tienen el formato `Nombre (Comentario) <parte local@ejemplo.org>`.
--cert=HUellaDactilar|IDCLAVE
Añadir el ID de usuario a la clave con la huella dactilar o ID de clave especificado
--cert-email=CORREO
Añadir el ID de usuario a la clave donde un ID de usuario incluye la dirección de correo electrónico especificada
--cert-file=RUTA
Añadir el ID de usuario a la clave leída desde RUTA
--cert-userid=USERID
Añadir el ID de usuario a la clave con el ID de usuario especificado
--email=DIRECCIÓN
Añadir una dirección de correo electrónico como ID de usuario a la clave
--name=NOMBRE
Añadir un nombre como ID de usuario a la clave
--output=ARCHIVO
Escribir en el ARCHIVO especificado
Si no se especifica, y la clave se leyó de la tienda de claves, importa la clave modificada en la tienda de claves. Si no se especifica, y la clave se leyó de un archivo, escribe la clave modificada en la salida estándar.
--userid=USERID
Añadir un ID de usuario a la clave
Este ID de usuario puede combinar nombre y dirección de correo electrónico, puede contener opcionalmente un comentario, o incluso tener formato libre si se proporciona `--allow-non-canonical-userids`. Sin embargo, los ID de usuario que incluyen información diferente, como nombre y dirección de correo electrónico, son más difíciles de razonar, por lo que hoy en día se prefiere usar ID de usuario distintos para el nombre y la dirección de correo electrónico.
En caso de duda, prefiere `--name` y `--email`.

Opciones globales

Ver sq(1) para una descripción de las opciones globales.

EJEMPLOS

# Añadir un nuevo ID de usuario a la clave de Alice.

sq key userid add --cert \
EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --name Alice \
--email alice@work.example.com
