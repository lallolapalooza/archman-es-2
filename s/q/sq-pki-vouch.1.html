SQ(1) Comandos de usuario SQ(1)

NOMBRE

sq-pki-vouch - Gestionar certificaciones

SINOPSIS

sq pki vouch add [OPCIONES]
sq pki vouch authorize [OPCIONES]
sq pki vouch list [OPCIONES]
sq pki vouch replay [OPCIONES]

DESCRIPCIÓN

Gestionar certificaciones.

Un aval (vouch) es una declaración potencialmente pública de que algo es cierto. En OpenPGP existen dos tipos principales de declaraciones que puedes hacer: certificaciones y autorizaciones.

Puedes afirmar que un certificado pertenece a una entidad en particular. Esto no dice nada sobre la fiabilidad de una entidad. Por ejemplo, podrías certificar `bob@nsa.gov` para un certificado dado. Esto solo significa que crees que la persona detrás de la dirección de correo electrónico `bob@nsa.gov` realmente controla ese certificado. Esa es una declaración útil incluso si no confías en que esa persona actúe en tu interés.

Alternativamente, puedes decir que crees que un certificado es un introductor de confianza razonable. Un introductor de confianza es un tercero al que autorizas para hacer introducciones. Por ejemplo, tu banco podría tener una autoridad de certificación (CA). Si verificas la huella digital de la CA, puedes autorizarla para hacer certificaciones. Eso significa que sq usará esas certificaciones casi como si las hubieras hecho tú. Esto es conveniente ya que ahora puedes autenticar a cualquiera de los empleados del banco.

Autorizar a un introductor de confianza otorga a ese introductor mucho poder. Puedes limitar la cantidad de poder que le otorgas diciendo que solo está autorizado a certificar IDs de usuario que tengan una dirección de correo electrónico en uno o más dominios, por ejemplo. De esta manera, puedes aprovechar los lugares donde tus intereses y los de una CA coinciden, y protegerte de acciones potencialmente maliciosas. Por ejemplo, podrías autorizar a la CA de tu banco a certificar IDs de usuario que tengan una dirección de correo electrónico en `bank.com`. sq entonces ignorará cualquier otra certificación hecha por la CA.

SUBCOMANDOS

sq pki vouch add

Certifica un ID de usuario para un Certificado.

Usando una certificación, el poseedor de una clave puede avalar el hecho de que un certificado ajeno pertenece legítimamente a un ID de usuario. En el contexto de correos electrónicos, esto significa que la misma entidad controla la clave y la dirección de correo electrónico. Estos tipos de certificaciones forman la base de la Red de Confianza.

Este comando emite el certificado con la nueva certificación. El certificado actualizado debe ser distribuido, preferiblemente enviándolo al titular del certificado para su aprobación. Ver también `sq key approvals`.

Por defecto, una certificación expira después de 10 años. Usando el argumento `--expiration` se pueden definir períodos de validez específicos. Permite proporcionar un punto en el tiempo para el fin de la validez o una duración de validez.

`sq pki vouch add` respeta el tiempo de referencia establecido por el argumento de nivel superior `--time`. Establece la hora de creación de la certificación a la hora de referencia.

sq pki vouch authorize

Marca un certificado como introductor de confianza.

Crea una certificación que indica que el emisor considera al certificado como un introductor de confianza. Introductor de confianza es otra palabra para autoridad de certificación (CA). Cuando un usuario confía en un introductor de confianza, el usuario considera válidas las certificaciones hechas por el introductor de confianza. Un introductor de confianza también puede designar introductories adicionales.

Tal cual, un introductor de confianza tiene mucho poder. Este poder puede ser limitado de varias maneras.


- La capacidad de especificar introductories adicionales puede ser restringida usando el parámetro `--depth`.


- El grado en que se confía en un introductor puede ser modificado usando el parámetro `--amount`.


- Los IDs de usuario que un introductor puede certificar pueden ser restringidos por dominio usando el parámetro `--domain` o una expresión regular usando el parámetro `--regex`.

Estos mecanismos permiten a Alice decir que está dispuesta a confiar en la CA, por ejemplo, para example.org, pero solo para IDs de usuario que tengan una dirección de correo electrónico para example.org, por ejemplo.

Por defecto, una delegación expira después de 10 años. Usa el argumento `--expiration` para anular esto.

Este subcomando respeta el tiempo de referencia establecido por el argumento de nivel superior `--time`. Establece la hora de creación de la certificación a la hora de referencia.

sq pki vouch list

Lista las certificaciones.

Si se proporciona el argumento certificador, se muestran las certificaciones hechas por el certificado especificado. Si se proporciona el argumento certificado, se muestran las certificaciones del certificado especificado. Si se proporcionan ambos, se muestran las certificaciones del certificado especificado hechas por el certificador especificado.

Este comando lista todas las certificaciones, no solo la certificación activa.

Dado que las certificaciones están asociadas con el certificado certificable y no con el certificado del certificador, esta lista probablemente esté incompleta.

Estable desde 1.2.0.

sq pki vouch replay

Reproduce avales (vouches).

Este comando reproduce los avales hechos por un certificado usando otro certificado. Esto es principalmente útil cuando reemplazas un certificado y quieres que el nuevo certificado haya hecho las mismas certificaciones que hiciste con el certificado antiguo.

Dado que las certificaciones están asociadas con el certificado certificable y no con el certificado del certificador, esto puede no reproducir todas las certificaciones que la fuente haya hecho alguna vez.

Este comando solo copia la certificación activa para un ID de usuario y certificado dados. Esto incluye tanto certificaciones exportables (avales) como certificaciones no exportables (enlaces). Excluye las certificaciones expiradas. Tampoco reproduce certificaciones hechas en certificados inválidos, expirados o revocados, o IDs de usuario revocados.

Este comando reproduce todos los parámetros de certificación, incluido cualquier tiempo de expiración, pero la hora de creación se establece a la hora actual.

Estable desde 1.2.0.

EJEMPLOS

sq pki vouch add

Alice certifica que Bob controla 3F68CB84CE537C9A y bob@example.org.

sq pki vouch add \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=511257EBBF077B7AEDAE5D093F68CB84CE537C9A \
--email=bob@example.org

Alice certifica que Bob controla 3F68CB84CE537C9A y bob@bobs.lair.net, que no es un ID de usuario autocertificado.

sq pki vouch add \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=511257EBBF077B7AEDAE5D093F68CB84CE537C9A \
--add-email=bob@bobs.lair.net

sq pki vouch authorize

Certifica que E7FC51AD886BBB5C4F44C3D7A9DA14F3E740F63F es un introductor de confianza para example.org y example.com.

sq pki vouch authorize \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=E7FC51AD886BBB5C4F44C3D7A9DA14F3E740F63F \
--domain=example.org --domain=example.com --all

sq pki vouch list

Lista las certificaciones hechas por Alice.

sq pki vouch list \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0

Lista las certificaciones hechas por Alice para el certificado de Bob.

sq pki vouch list \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=511257EBBF077B7AEDAE5D093F68CB84CE537C9A

sq pki vouch replay

sq-pki-vouch(1) — Sequoia PGP

NAME

sq-pki-vouch

verifies a certificate by vouching for it

SYNOPSIS

sq pki vouch [OPTIONS] CERT [...]

DESCRIPTION

This command vouches for one or more certificates, thereby adding your signature to them. This is useful for two main purposes:

  • You can use it to certify that you know the owner of the key, and that the associated identity information is correct.
  • You can use it to make sure that your own certificates are verified by others.

To vouch for a certificate, you use the sq pki vouch command. It creates a new signature on the certificate, which includes your own public key. This signature is stored in your keyring.

When you use sq pki vouch, you are essentially saying: "I vouch for this certificate". The certificate is then signed with your private key.

The signature created is a certification signature, as defined by OpenPGP. This signature indicates that you have verified the identity of the certificate's owner and that you believe the information in the certificate to be accurate. The signature will be added to the certificate, and the updated certificate will be stored in your keyring.

SUBCOMMANDS

sq pki vouch replay

Replays certifications made with an old certificate using the new one.

sq pki vouch replay [OPTIONS] --source=SOURCE --target=TARGET

This subcommand is used to transfer certifications from one certificate to another. For example, if you have certified a certificate with an old key, and you have now created a new key, you can use this command to re-certify the certificate with your new key. This ensures that your certifications are still valid even after you have updated your key.

The --source option specifies the old certificate, and the --target option specifies the new certificate. The command will then replay all certifications made with the old certificate onto the new one.

EXAMPLES

Vouch for a certificate with the user ID "Alice <alice@example.com>":

sq pki vouch "Alice <alice@example.com>"

Vouch for a certificate using its fingerprint:

sq pki vouch 0xEB28F26E2739A487

Replay certifications from an old certificate to a new one. The old certificate is identified by the fingerprint EB28F26E2739A4870ECC47726F0073F60FD0CBF0 and the new certificate is identified by the fingerprint C5999E8191BF7B503653BE958B1F7910D01F86E5. This command effectively transfers the certifications made with the old certificate to the new one.

sq pki vouch replay \
--source=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--target=C5999E8191BF7B503653BE958B1F7910D01F86E5
