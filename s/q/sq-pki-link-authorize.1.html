NOMBRE

sq-pki-link-authorize - Hacer que un certificado sea un introductor de confianza

SINOPSIS

sq pki link authorize [OPCIONES]

DESCRIPCIÓN

Hacer que un certificado sea un introductor de confianza.

Esto hace que `sq` considere el certificado como un introductor de confianza. Introductor de confianza es otra forma de decir autoridad de certificación (CA). Cuando se vincula un introductor de confianza, se consideran válidas las certificaciones realizadas por el introductor de confianza. Un introductor de confianza también puede designar a otros introductor de confianza.

Tal como está, un introductor de confianza tiene mucho poder. Este poder puede limitarse de varias maneras.


- La capacidad de especificar introductor adicionales se puede restringir usando el parámetro `--depth`.


- El grado en que un introductor es de confianza se puede cambiar usando el parámetro `--amount`.


- Los identificadores de usuario (user IDs) que un introductor puede certificar pueden restringirse por dominio usando el parámetro `--domain` o por una expresión regular usando el parámetro `--regex`.

Estos mecanismos le permiten decir que está dispuesto a confiar en la CA de, por ejemplo, example.org, pero solo para identificadores de usuario que tengan una dirección de correo electrónico para example.org, por ejemplo.

Un enlace se puede revocar usando `sq pki link retract`.

Este comando es similar a `sq pki vouch authorize`, pero las certificaciones que realiza se hacen utilizando la raíz de confianza del directorio de certificados, no una clave arbitraria. Además, los certificados se marcan como no exportables. Lo primero facilita la gestión de certificaciones, especialmente cuando su clave de certificación está desconectada. Y lo segundo mejora su privacidad, al reducir la posibilidad de que partes de su grafo social se filtren cuando se comparte un certificado.

Por defecto, un enlace nunca expira. Usando el argumento `--expiration` se pueden definir períodos de validez específicos. Permite proporcionar un punto en el tiempo para el fin de la validez o una duración de validez.

`sq pki link authorize` respeta la hora de referencia establecida por el argumento de nivel superior `--time`. Establece la hora de creación del enlace a la hora de referencia.

OPCIONES

Opciones de subcomando

--add-email=CORREO
Usar un identificador de usuario con la dirección de correo electrónico especificada
El identificador de usuario consta solo de la dirección de correo electrónico. La dirección de correo electrónico no tiene que aparecer en un identificador de usuario autocertificado.
--add-userid=IDENTIFICADOR_USUARIO
Usar el identificador de usuario especificado
El identificador de usuario especificado no necesita ser autocertificado.
Dado que usar un identificador de usuario que no es autocertificado suele ser un error, necesita usar esta opción para aceptarlo explícitamente.
--all
Usar todos los identificadores de usuario autocertificados
--allow-non-canonical-userids
No rechazar nuevos identificadores de usuario que no estén en forma canónica
Los identificadores de usuario canónicos tienen el formato `Nombre (Comentario) <parte_local@ejemplo.org>`.
--amount=CANTIDAD
Establecer la cantidad de confianza
Los valores entre 1 y 120 son significativos. 120 significa totalmente de confianza. Los valores inferiores a 120 indican el grado de confianza. 60 se usa normalmente para confianza parcial.
[por defecto: completa]
--cert=HUELLA_DIGITAL|ID_CLAVE
Usar certificados con la huella digital o ID de clave especificados
--cert-special=ESPECIAL
Usar certificados identificados por el nombre especial
[valores posibles: directorios-publicos, keys.openpgp.org, keys.mailvelope.com, proton.me, wkd, dane, autocrypt, web]
--depth=PROFUNDIDAD_CONFIANZA
Establecer la profundidad de confianza
Esto a veces se denomina nivel de confianza. 1 significa que el CERTIFICADO es un introductor de confianza (por defecto), 2 significa que el CERTIFICADO es un meta-introductor de confianza y puede autorizar a otro introductor de confianza, etc.
[por defecto: 255]
--domain=DOMINIO
Añadir una restricción de dominio al introductor
Añadir un dominio para restringir qué certificaciones se respetan. Una certificación realizada por el certificado solo se respeta si es sobre un identificador de usuario con una dirección de correo electrónico en el dominio especificado. Se pueden especificar varios dominios. En ese caso, uno debe coincidir.
--email=CORREO
Usar un identificador de usuario que consiste solo en la dirección de correo electrónico, si la dirección de correo electrónico aparece en un identificador de usuario autocertificado
--expiration=EXPIRACIÓN
Establece la hora de expiración
EXPIRACIÓN es una fecha en formato ISO 8601 con una hora opcional o una duración personalizada. Una duración tiene el formato `N[ymwds]`, donde las letras representan años, meses, semanas, días y segundos, respectivamente. Alternativamente, la palabra clave `never` (nunca) no establece una hora de expiración.
[por defecto: nunca]
--recreate
Recrear la firma incluso si los parámetros no cambiaron
Si los parámetros del enlace no cambiaron, y por lo tanto no debería ser necesario crear una firma, omitimos la operación. Esta bandera se puede dar para forzar la recreación de la firma de todos modos.
--regex=REGEX
Añadir una expresión regular para restringir el introductor
Añadir una expresión regular para restringir qué certificaciones se respetan. Una certificación realizada por el certificado solo se respeta si es sobre un identificador de usuario que coincide con una de las expresiones regulares especificadas. Se pueden especificar varias expresiones regulares. En ese caso, al menos una debe coincidir.
--signature-notation NOMBRE VALOR
Añadir una notación a la firma
El nombre de una notación definida por el usuario debe tener el formato `nombre@dominio.que.controlas.org`. Si el nombre de la notación comienza con un `!`, entonces la notación se marca como crítica. Si un consumidor de una firma no entiende una notación crítica, ignorará la firma. La notación se marca como legible por humanos.
--unconstrained
No restringir el introductor
Normalmente un introductor está restringido para que solo se respeten ciertos identificadores de usuario, por ejemplo, aquellos que tienen una dirección de correo electrónico para un determinado nombre de dominio. Esta opción autoriza a un introductor sin restringirlo de esta manera. Dado que esto otorga al introductor un gran poder, debe aceptar explícitamente este comportamiento.
--userid=IDENTIFICADOR_USUARIO
Usar el identificador de usuario autocertificado especificado
El identificador de usuario especificado debe ser autocertificado.
--userid-by-email=CORREO
Usar el identificador de usuario autocertificado con la dirección de correo electrónico especificada

Opciones globales

Vea sq(1) para una descripción de las opciones globales.

EJEMPLOS

Añadir un introductor de confianza no restringido.

NAME


sq-pki-link-authorize, sq-pki-link-sign — authorize or reject a public key






SYNOPSIS


sq pki link authorize [options] [key-id ...]


sq pki link sign [options] [key-id ...]






DESCRIPTION


The sq pki link authorize command allows you to authorize a public key. This means that Sequoia will trust this key for future operations, such as signing messages or identifying the introducer of another key. You can either authorize a key without any constraints, or with a partial trust level, specified with the --amount option.


The sq pki link sign command is an alias for sq pki link authorize.


If --all is specified, the command will authorize all the keys currently present in the keyring.


If no key-id is given, the command will process all the keys specified by --all.






OPTIONS


The commands sq pki link authorize and sq pki link sign accept the following options:




--all


Authorize all the keys in the keyring.


--amount=amount


Set the trust amount for the introducer. The amount must be an integer between 0 and 100. Default is 100. This option is only valid when --unconstrained is given.


--cert=cert


Authorize the specified certificate. A certificate can be given as a hexadecimal string, or as a filename. If it's a filename, the certificate is read from the file.


--domain=domain


Authorize the specified domain. All keys belonging to the specified domain will be authorized.


--unconstrained


Authorize the key without any constraints. This means the key is fully trusted.








EXAMPLES


Authorize the key with fingerprint
    EB28F26E2739A4870ECC47726F0073F60FD0CBF0:




sq pki link authorize --cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0




Authorize all keys in the keyring:




sq pki link authorize --all




Authorize the key EB28F26E2739A4870ECC47726F0073F60FD0CBF0 without constraints:




sq pki link authorize --unconstrained \








--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all






Add a trusted introducer for example.org and example.com.




sq pki link authorize --domain=example.org \








--domain=example.com \










--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all






Add a partially trusted introducer.




sq pki link authorize --unconstrained --amount=60 \








--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all










SEE   ALSO


sq(1), sq-pki(1), sq-pki-link(1).


For the full documentation see
    https://book.sequoia-pgp.org/.

NOMBRE


sq-pki-link-authorize, sq-pki-link-sign — autoriza o rechaza una clave pública






SINOPSIS


sq pki link authorize [opciones] [id-clave ...]


sq pki link sign [opciones] [id-clave ...]






DESCRIPCIÓN


El comando sq pki link authorize te permite autorizar una clave pública. Esto significa que Sequoia confiará en esta clave para operaciones futuras, como firmar mensajes o identificar al presentador de otra clave. Puedes autorizar una clave sin restricciones, o con un nivel de confianza parcial, especificado con la opción --amount.


El comando sq pki link sign es un alias para sq pki link authorize.


Si se especifica --all, el comando autorizará todas las claves presentes actualmente en el llavero.


Si no se proporciona ningún id-clave, el comando procesará todas las claves especificadas por --all.






OPCIONES


Los comandos sq pki link authorize y sq pki link sign aceptan las siguientes opciones:




--all


Autoriza todas las claves en el llavero.


--amount=cantidad


Establece la cantidad de confianza para el presentador. La cantidad debe ser un número entero entre 0 y 100. El valor predeterminado es 100. Esta opción solo es válida cuando se proporciona --unconstrained.


--cert=cert


Autoriza el certificado especificado. Un certificado puede proporcionarse como una cadena hexadecimal o como un nombre de archivo. Si es un nombre de archivo, el certificado se lee del archivo.


--domain=dominio


Autoriza el dominio especificado. Todas las claves que pertenezcan al dominio especificado serán autorizadas.


--unconstrained


Autoriza la clave sin restricciones. Esto significa que la clave tiene plena confianza.








EJEMPLOS


Autoriza la clave con huella digital
    EB28F26E2739A4870ECC47726F0073F60FD0CBF0:




sq pki link authorize --cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0




Autoriza todas las claves en el llavero:




sq pki link authorize --all




Autoriza la clave EB28F26E2739A4870ECC47726F0073F60FD0CBF0 sin restricciones:




sq pki link authorize --unconstrained \








--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all






Añade un presentador de confianza para example.org y example.com.




sq pki link authorize --domain=example.org \








--domain=example.com \










--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all






Añade un presentador parcialmente confiable.




sq pki link authorize --unconstrained --amount=60 \








--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all
