NOMBRE

sq-pki-vouch-add - Certificar una Identificación de Usuario para un Certificado

SINOPSIS

sq pki vouch add [OPCIONES]

DESCRIPCIÓN

Certifica una Identificación de Usuario para un Certificado.

Usando una certificación, el poseedor de una clave puede dar fe de que otro certificado pertenece legítimamente a una identificación de usuario. En el contexto de correos electrónicos, esto significa que la misma entidad controla la clave y la dirección de correo electrónico. Estos tipos de certificaciones forman la base de la Red de Confianza.

Este comando emite el certificado con la nueva certificación. El certificado actualizado debe ser distribuido, preferiblemente enviándolo al poseedor del certificado para su aprobación. Ver también `sq key approvals`.

Por defecto, una certificación caduca después de 10 años. Usando el argumento `--expiration` se pueden definir períodos de validez específicos. Permite proporcionar un punto en el tiempo para que termine la validez o una duración de validez.

`sq pki vouch add` respeta la hora de referencia establecida por el argumento de nivel superior `--time`. Establece la hora de creación de la certificación a la hora de referencia.

OPCIONES

Opciones de subcomando

--add-email=EMAIL
Usar una identificación de usuario con la dirección de correo electrónico especificada
La identificación de usuario consiste solo en la dirección de correo electrónico. La dirección de correo electrónico no tiene que aparecer en una identificación de usuario autocertificada.
--add-userid=USERID
Usar la identificación de usuario especificada
La identificación de usuario especificada no necesita ser autocertificada.
Debido a que usar una identificación de usuario que no es autocertificada suele ser un error, necesitas usar esta opción para opt-in explícitamente.
--all
Usar todas las identificaciones de usuario autocertificadas
--allow-non-canonical-userids
No rechazar nuevas identificaciones de usuario que no estén en forma canónica
Las identificaciones de usuario canónicas tienen el formato `Nombre (Comentario) <localpart@example.org>`.
--amount=CANTIDAD
Establecer la cantidad de confianza
Los valores entre 1 y 120 son significativos. 120 significa completamente confiable. Los valores menores a 120 indican el grado de confianza. 60 se usa generalmente para parcialmente confiable.
[predeterminado: full]
--cert=HUellaDactilar|IDLLAVE
Usar certificados con la huella dactilar o ID de clave especificada
--cert-file=RUTA
Leer certificados desde RUTA
--certifier=HUellaDactilar|IDLLAVE
Crear la certificación usando la clave con la huella dactilar o ID de clave especificada
--certifier-email=EMAIL
Crear la certificación usando la clave donde una identificación de usuario incluye la dirección de correo electrónico especificada
--certifier-file=RUTA
Crear la certificación usando la clave leída desde RUTA
--certifier-self
Crear la certificación usando tu clave de certificación predeterminada
Esto usa los certificados establecidos en el archivo de configuración bajo `pki.vouch.certifier-self` como clave de certificación.
Actualmente, no hay una clave de certificación predeterminada.
--certifier-userid=USERID
Crear la certificación usando la clave con la identificación de usuario especificada
--email=EMAIL
Usar una identificación de usuario que consista solo en la dirección de correo electrónico, si la dirección de correo electrónico aparece en una identificación de usuario autocertificada
--expiration=EXPIRACION
Establece la hora de expiración
EXPIRACION es una fecha en formato ISO 8601 con hora opcional o una duración personalizada. Una duración tiene el formato `N[ymwds]`, donde las letras representan años, meses, semanas, días y segundos, respectivamente. Alternativamente, la palabra clave `never` no establece una hora de expiración.
El predeterminado se puede cambiar en el archivo de configuración usando la configuración `pki.vouch.expiration`.
[predeterminado: 10y]
--local
Hacer que la certificación sea una certificación local
Normalmente, las certificaciones locales no se exportan.
--non-revocable
Marcar la certificación como no revocable
Es decir, no podrás revocar esta certificación más tarde. Esto normalmente solo debe usarse con una expiración.
--output=ARCHIVO
Escribir en ARCHIVO o en la salida estándar si se omite
--signature-notation NOMBRE VALOR
Añadir una notación a la firma
El nombre de una notación definida por el usuario debe tener el formato `nombre@a.dominio.que.controlas.org`. Si el nombre de la notación comienza con un `!`, entonces la notación se marca como crítica. Si un consumidor de una firma no entiende una notación crítica, ignorará la firma. La notación se marca como legible por humanos.
--userid=USERID
Usar la identificación de usuario autocertificada especificada
La identificación de usuario especificada debe ser autocertificada.
--userid-by-email=EMAIL
Usar la identificación de usuario autocertificada con la dirección de correo electrónico especificada

Opciones globales

Ver sq(1) para una descripción de las opciones globales.

EJEMPLOS

Alice certifica que Bob controla 3F68CB84CE537C9A y bob@example.org.

sq pki vouch add \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=511257EBBF077B7AEDAE5D093F68CB84CE537C9A \
--email=bob@example.org

Alice certifica que Bob controla 3F68CB84CE537C9A y bob@bobs.lair.net, que no es una identificación de usuario autocertificada.

sq pki vouch add \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=511257EBBF077B7AEDAE5D093F68CB84CE537C9A \
--add-email=bob@bobs.lair.net

NAME

sq-pki-vouch-add - adds a vouch to a certificate

SYNOPSIS

sq pki vouch add --cert <CERT> --recipient <RECIPIENT> --signature <SIGNATURE>

DESCRIPTION

This subcommand is used to add a vouch to a certificate. A vouch is a signature from one certificate’s owner certifying that they trust another certificate. This is often used to sign keys in a web of trust.

The command takes the following arguments:

  • --cert <CERT>: The certificate to which the vouch will be added. This can be a path to a file, or a key ID.

  • --recipient <RECIPIENT>: The certificate of the recipient of the vouch. This should be the certificate of the person or entity that the current certificate is vouching for.

  • --signature <SIGNATURE>: The signature that vouches for the recipient. This signature should be created using the private key corresponding to the certificate being used to vouch.

OPTIONS

--cert <CERT>
The certificate to which the vouch will be added.
--recipient <RECIPIENT>
The certificate of the recipient of the vouch.
--signature <SIGNATURE>
The signature that vouches for the recipient.
-h, --help
Prints help information and exits.
-V, --version
Prints version information and exits.

EXAMPLES

Add a vouch to a certificate:

sq pki vouch add --cert mycert.pem --recipient theircert.pem --signature mysignature.sig

This command adds a vouch to `mycert.pem` that trusts `theircert.pem`, using the signature `mysignature.sig`.
