NOMBRE

sq-key-rotate - Rota un certificado

SINOPSIS

sq key rotate [OPCIONES]

DESCRIPCIÓN

Rota un certificado.

Genera un nuevo certificado para reemplazar uno existente.

El nuevo certificado tendrá las mismas capacidades que el certificado antiguo. Esto puede ser anulado usando los argumentos `--can-sign`, `--cannot-sign`, etc. Nota: el nuevo certificado puede tener una forma diferente al certificado antiguo. Por ejemplo, si la clave primaria del certificado antiguo está marcada como capaz de certificación y firma, la clave primaria del nuevo certificado será capaz de certificación, y tendrá una subclave de firma.

Por defecto, el certificado expira después de 3 años. Esto puede ser cambiado usando el argumento `--expiration`.

El nuevo certificado tendrá los mismos IDs de usuario auto-firmados que el certificado antiguo. Los IDs de usuario revocados son ignorados.

El nuevo certificado y el certificado antiguo se certificarán mutuamente como introductoras de confianza sin restricciones.

El nuevo certificado se enlazará de la misma manera que el certificado antiguo. Esto puede ser anulado usando el argumento `--own-key` o `--shared-key`.

El nuevo certificado certificará los mismos certificados que el certificado antiguo. Es decir, se reproducirán las certificaciones del certificado antiguo. Ver `sq pki vouch replay` para más información.

Se emitirá un certificado de revocación indicando que el certificado antiguo está retirado y que se debe usar el nuevo certificado en su lugar. Por defecto, entrará en vigor en 182 días. Esto puede ser cambiado o suprimido usando el argumento `--retire-in`.

Cuando se usa `--output`, el nuevo certificado, así como todos los demás certificados actualizados, se escriben en el archivo especificado.

Estable desde 1.2.0.

OPCIONES

Opciones de subcomando

--can-authenticate
Añade una subclave capaz de autenticación
--can-encrypt=PROPÓSITO
Añade una subclave capaz de cifrado
Las subclaves capaces de cifrado pueden ser marcadas como adecuadas para cifrado de transporte, cifrado de almacenamiento, o ambas, es decir, universal.
[posibles valores: transport, storage, universal]
--can-sign
Añade una subclave capaz de firma
--cannot-authenticate
No añadir una subclave capaz de autenticación
--cannot-encrypt
No añadir una subclave capaz de cifrado
--cannot-sign
No añadir una subclave capaz de firma
--cert=HUELLA DIGITAL|ID DE CLAVE
Usa certificados con la huella digital o ID de clave especificada
--cert-email=CORREO
Usa certificados donde un ID de usuario incluya la dirección de correo especificada
--cert-file=RUTA
Lee certificados desde RUTA
--cert-userid=ID DE USUARIO
Usa certificados con el ID de usuario especificado
--cipher-suite=SUITE DE CIFRADO
Selecciona los algoritmos criptográficos para la clave
El valor predeterminado puede ser cambiado en el archivo de configuración usando el ajuste `key.generate.cipher-suite`.
[predeterminado: cv25519]
[posibles valores: rsa2k, rsa3k, rsa4k, cv25519]
--expiration=EXPIRACIÓN
Establece la hora de expiración
EXPIRACIÓN es una fecha con formato ISO 8601 con hora opcional o una duración personalizada. Una duración tiene el formato `N[ymwds]`, donde las letras representan años, meses, semanas, días y segundos, respectivamente. Alternativamente, la palabra clave `never` no establece una hora de expiración.
[predeterminado: 3y]
--new-password-file=ARCHIVO DE CONTRASEÑA
Archivo que contiene la contraseña para cifrar el material de clave secreta
Ten en cuenta que todo el archivo de clave se usará como contraseña, incluyendo cualquier espacio en blanco circundante, como una nueva línea final.
--output=ARCHIVO
Escribe la clave en el archivo especificado
Cuando no se especifica, la clave se guarda en el almacén de claves.
--own-key
Marca la clave como clave propia
La clave recién generada con todos sus IDs de usuario será marcada como autenticada y como introductora totalmente confiable.
--profile=PERFIL
Selecciona el estándar OpenPGP para la clave
A medida que OpenPGP evoluciona, habrá nuevas versiones disponibles. Esta opción selecciona la versión de OpenPGP a usar para la clave recién generada.
Actualmente, sq solo soporta una versión: RFC4880. En consecuencia, este es el valor predeterminado. Sin embargo, ya existe una versión más nueva del estándar: RFC9580. Y, el valor predeterminado cambiará en una futura versión de sq.
El valor predeterminado puede ser cambiado en el archivo de configuración usando el ajuste `key.generate.profile`.
[predeterminado: rfc4880]
[posibles valores: rfc9580, rfc4880]
--retire-in=TIEMPO
Establece la hora en que el certificado debe ser retirado
TIEMPO es una fecha con formato ISO 8601 con hora opcional o una duración personalizada. Una duración tiene el formato `N[ymwds]`, donde las letras representan años, meses, semanas, días y segundos, respectivamente. Alternativamente, la palabra clave `never` omite la certificación de un certificado de revocación.
[predeterminado: 26w]
--rev-cert=ARCHIVO
Escribe el certificado de revocación de emergencia en ARCHIVO
Cuando la clave se almacena en el almacén de claves, el certificado de revocación se almacena por defecto en $HOME/.local/share/sequoia/revocation-certificates.
Cuando se especifica `--output`, el certificado de revocación se escribe en el archivo especificado por `--rev-cert`.
Si `--output` es `-`, entonces esta opción no debe ser también `-`.
--shared-key
Marca la clave como clave compartida
La clave recién generada con todos sus IDs de usuario será marcada como autenticada, pero no como introductora confiable. Además, los metadatos de la clave indicarán que esta es una clave compartida.
Usa esta opción si planeas compartir esta clave con otras personas. Normalmente, no deberías compartir material de claves. Un ejemplo de dónde podrías querer hacer esto es un buzón compartido.
--without-password
No proteger el material de clave secreta con una contraseña

Opciones globales

Ver sq(1) para una descripción de las opciones globales.

EJEMPLOS

Rota el certificado de Alice.

sq key rotate --cert EB28F26E2739A4870ECC47726F0073F60FD0CBF0

sq-key-rotate(1)

NAME

sq-key-rotate - rota la clave secreta del usuario

SYNOPSIS

sq key rotate

DESCRIPTION

Rota la clave secreta del usuario. Esto permite que un usuario cambie su clave privada sin tener que generar una nueva identidad. Es una operación costosa que requiere que se vuelvan a cifrar todos los mensajes cifrados anteriormente para la identidad del usuario.

Por defecto, esta operación realiza una rotación de clave de las claves secretas del usuario. Se pueden usar las opciones para modificar este comportamiento.

OPTIONS

Esta orden no soporta opciones.

EXAMPLES

Para rotar la clave secreta del usuario:

$ sq key rotate

SEE ALSO

sq(1), sq-key(1)

Para la documentación completa, véase https://book.sequoia-pgp.org/.
