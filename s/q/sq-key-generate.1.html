SQ(1) Comandos de Usuario SQ(1)

NOMBRE

sq-key-generate - Generar una nueva clave

SINOPSIS

sq key generate [OPCIONES]

DESCRIPCIÓN

Generar una nueva clave.

Generar una clave es el requisito previo para recibir mensajes cifrados y crear firmas. Hay algunos parámetros para este proceso, pero proporcionamos valores predeterminados razonables para la mayoría de los usuarios.

Al generar una clave, también generamos un certificado de revocación de emergencia. Esto se puede usar en caso de que la clave se pierda o se vea comprometida. Se guarda junto con la clave. Esto se puede cambiar usando el argumento `--rev-cert`.

Por defecto, una clave expira después de 3 años. Esto se puede cambiar usando el argumento `--expiration`.

`sq key generate` respeta la hora de referencia establecida por el argumento superior `--time`. Establece la hora de creación de la clave primaria, todas las subclaves y las firmas de enlace a la hora de referencia.

OPCIONES

Opciones del subcomando

--allow-non-canonical-userids
No rechazar identificadores de usuario que no estén en formato canónico
Los identificadores de usuario canónicos tienen el formato `Nombre (Comentario) <parte-local@ejemplo.org>`.
--can-authenticate
Añadir una subclave capaz de autenticación (predeterminado)
--can-encrypt=PROPÓSITO
Añadir una subclave capaz de cifrado [predeterminado: universal]
Las subclaves capaces de cifrado pueden marcarse como adecuadas para cifrado de transporte, cifrado de almacenamiento o ambas, es decir, universales.
[posibles valores: transport, storage, universal]
--can-sign
Añadir una subclave capaz de firma (predeterminado)
--cannot-authenticate
No añadir una subclave capaz de autenticación
--cannot-encrypt
No añadir una subclave capaz de cifrado
--cannot-sign
No añadir una subclave capaz de firma
--cipher-suite=CIPHER-SUITE
Selecciona los algoritmos criptográficos para la clave
El valor predeterminado se puede cambiar en el archivo de configuración usando la configuración `key.generate.cipher-suite`.
[predeterminado: cv25519]
[posibles valores: rsa2k, rsa3k, rsa4k, cv25519]
--email=DIRECCIÓN
Añade una dirección de correo electrónico como identificador de usuario a la clave
--expiration=EXPIRACIÓN
Establece la hora de expiración
EXPIRACIÓN es una fecha en formato ISO 8601 con una hora opcional o una duración personalizada. Una duración tiene el formato `N[ymwds]`, donde las letras representan años, meses, semanas, días y segundos, respectivamente. Alternativamente, la palabra clave `never` no establece una hora de expiración.
[predeterminado: 3y]
--name=NOMBRE
Añade un nombre como identificador de usuario a la clave
--new-password-file=ARCHIVO_CONTRASEÑA
Archivo que contiene la contraseña para cifrar el material de la clave secreta
Tenga en cuenta que todo el archivo de clave se utilizará como contraseña, incluido cualquier espacio en blanco circundante, como una nueva línea final.
--no-userids
Crea una clave sin ningún identificador de usuario
--output=ARCHIVO
Escribe la clave en el archivo especificado
Cuando no se especifica, la clave se guarda en el almacén de claves.
--own-key
Marca la clave como propia
La clave recién generada con todos sus identificadores de usuario se marcará como autenticada y como introductor completamente confiable.
--profile=PERFIL
Selecciona el estándar OpenPGP para la clave
A medida que OpenPGP evoluciona, estarán disponibles nuevas versiones. Esta opción selecciona la versión de OpenPGP a utilizar para la clave recién generada.
Actualmente, sq admite dos perfiles: RFC9580 y RFC4880. Actualmente, el predeterminado es RFC4880. Sin embargo, una vez que el soporte para RFC9580 se implemente más ampliamente, el valor predeterminado cambiará en una futura versión de sq.
El valor predeterminado se puede cambiar en el archivo de configuración usando la configuración `key.generate.profile`.
[predeterminado: rfc4880]
[posibles valores: rfc9580, rfc4880]
--rev-cert=ARCHIVO
Escribe el certificado de revocación de emergencia en ARCHIVO
Cuando la clave se almacena en el almacén de claves, el certificado de revocación se almacena en $HOME/.local/share/sequoia/revocation-certificates por defecto.
Cuando se especifica `--output`, el certificado de revocación se escribe en el archivo especificado por `--rev-cert`.
Si `--output` es `-`, entonces esta opción no debe ser `-`.
--shared-key
Marca la clave como una clave compartida
La clave recién generada con todos sus identificadores de usuario se marcará como autenticada, pero no como un introductor confiable. Además, los metadatos de la clave indicarán que se trata de una clave compartida.
Utilice esta opción si planea compartir esta clave con otras personas. Normalmente, no debe compartir material de claves. Un ejemplo de dónde podría querer hacer esto es un buzón compartido.
--userid=USERID
Añade un identificador de usuario a la clave
Este identificador de usuario puede combinar nombre y dirección de correo electrónico, puede contener opcionalmente un comentario, o incluso puede ser de formato libre si se proporciona `--allow-non-canonical-userids`. Sin embargo, los identificadores de usuario que incluyen información diferente, como nombre y dirección de correo electrónico, son más difíciles de razonar, por lo que hoy en día se prefieren identificadores de usuario distintos para el nombre y la dirección de correo electrónico.
En caso de duda, prefiera `--name` y `--email`.
--without-password
No proteja el material de la clave secreta con una contraseña

Opciones globales

Vea sq(1) para una descripción de las opciones globales.

EJEMPLOS

Genera una clave y la guarda en el almacén de claves.

sq key generate --own-key --name Alice --email \
alice@example.org

Genera una clave y la guarda en un archivo en lugar de en el almacén de claves.

sq key generate --own-key --name Alice --email \
alice@example.org --output alice-priv.pgp --rev-cert \
alice-priv.rev

VER TAMBIÉN

sq(1), sq-key(1).

Para la documentación completa, consulte https://book.sequoia-pgp.org/.

sq-key-generate(1) — Sequoia PGP

NAME

sq-key-generate - Generate a new OpenPGP key pair

SYNOPSIS

sq key generate [OPTIONS] [UserId]

DESCRIPTION

Generates a new OpenPGP key pair, consisting of a private and a public key. A User ID is required to identify the key owner. If no User ID is provided on the command line, you will be prompted for one.

The User ID is typically formatted as "Real Name <email@example.com>".

The generated keys will be stored in the current directory by default. You may want to use the sq-key-store(1) command to move them to a more permanent location.

OPTIONS

--output-private <file>
Write the generated private key to <file>.
--output-public <file>
Write the generated public key to <file>.
--cipher-algo <algorithm>
Use the specified symmetric cipher algorithm for the secret key. Supported algorithms are: aes128, aes192, aes256, tripledes. Defaults to aes256.
--digest-algo <algorithm>
Use the specified digest algorithm for signatures. Supported algorithms are: sha1, sha256, sha384, sha512, md5. Defaults to sha512.
--sign-algo <algorithm>
Use the specified public key algorithm for signing. Supported algorithms are: rsa, dsa, ecdsa, ed25519. Defaults to ed25519.
--key-length <bits>
Use a key of <bits> length. This option is only applicable for RSA keys, and defaults to 4096.
--curve <curve>
Use the specified elliptic curve for ECDSA keys. Supported curves are: nistp256, nistp384, nistp521, ed25519. Defaults to nistp256.
--not-before <date>
Set the validity period of the key to start at <date>. The date format is YYYY-MM-DD.
--not-after <date>
Set the validity period of the key to expire at <date>. The date format is YYYY-MM-DD.
--days <days>
Set the validity period of the key to <days> days.
--password-file <file>
Read the passphrase for encrypting the private key from <file>.
--no-protection
Do not encrypt the private key. This is strongly discouraged.
-h, --help
Print help information and exit.
-V, --version
Print version information and exit.

EXAMPLES

Generate a new key pair with the User ID "John Doe <john.doe@example.com>":

$ sq key generate "John Doe <john.doe@example.com>"

Generate a new key pair using Ed25519, valid for 30 days:

$ sq key generate --sign-algo ed25519 --days 30 "Jane Doe <jane.doe@example.com>"
