NOMBRE

sq-pki-vouch-authorize - Marca un certificado como introductor de confianza

SINOPSIS

sq pki vouch authorize [OPCIONES]

DESCRIPCIÓN

Marca un certificado como introductor de confianza.

Crea una certificación que indica que el emisor considera el certificado como un introductor de confianza. Un introductor de confianza es otra forma de llamar a una autoridad de certificación (CA). Cuando un usuario confía en un introductor de confianza, considera válidas las certificaciones hechas por ese introductor de confianza. Un introductor de confianza también puede designar a otros introducers de confianza.

Tal como está, un introductor de confianza tiene mucho poder. Este poder se puede limitar de varias maneras.


- La capacidad de especificar introducers adicionales se puede restringir usando el parámetro `--depth`.


- El grado en que se confía en un introducer se puede cambiar usando el parámetro `--amount`.


- Los IDs de usuario que un introducer puede certificar se pueden restringir por dominio usando el parámetro `--domain` o por una expresión regular usando el parámetro `--regex`.

Estos mecanismos permiten a Alice decir que está dispuesta a confiar en la CA de por ejemplo.org, pero solo para IDs de usuario que tengan una dirección de correo electrónico para por ejemplo.org, por ejemplo.

Por defecto, una delegación expira después de 10 años. Use el argumento `--expiration` para anular esto.

Este subcomando respeta el tiempo de referencia establecido por el argumento de nivel superior `--time`. Establece el tiempo de creación de la certificación al tiempo de referencia.

OPCIONES

Opciones del subcomando

--add-email=CORREO
Usar un ID de usuario con la dirección de correo electrónico especificada
El ID de usuario consiste solo en la dirección de correo electrónico. La dirección de correo electrónico no tiene que aparecer en un ID de usuario auto-firmado.
--add-userid=ID_USUARIO
Usar el ID de usuario especificado
El ID de usuario especificado no necesita estar auto-firmado.
Dado que usar un ID de usuario no auto-firmado suele ser un error, debe usar esta opción para opt-in explícitamente.
--all
Usar todos los IDs de usuario auto-firmados
--allow-non-canonical-userids
No rechazar nuevos IDs de usuario que no estén en formato canónico
Los IDs de usuario canónicos tienen el formato `Nombre (Comentario) <localpart@example.org>`.
--amount=CANTIDAD
Establecer la cantidad de confianza
Valores entre 1 y 120 son significativos. 120 significa confianza total. Valores menores a 120 indican el grado de confianza. 60 se usa usualmente para confianza parcial.
[predeterminado: total]
--cert=HUELLA|ID_CLAVE
Usar certificados con la huella o ID de clave especificados
--cert-file=RUTA
Leer certificados desde RUTA
--certifier=HUELLA|ID_CLAVE
Crear la certificación usando la clave con la huella o ID de clave especificados
--certifier-email=CORREO
Crear la certificación usando la clave donde un ID de usuario incluye la dirección de correo electrónico especificada
--certifier-file=RUTA
Crear la certificación usando la clave leída desde RUTA
--certifier-self
Crear la certificación usando su clave de certificación predeterminada
Esto usa los certificados establecidos en el archivo de configuración bajo `pki.vouch.certifier-self` como clave de certificación.
Actualmente, no hay clave de certificación predeterminada.
--certifier-userid=ID_USUARIO
Crear la certificación usando la clave con el ID de usuario especificado
--depth=PROFUNDIDAD_CONFIANZA
Establecer la profundidad de confianza
Esto a veces se conoce como nivel de confianza. 1 significa que el CERTIFICADO es un introductor de confianza (predeterminado), 2 significa que el CERTIFICADO es un meta-introductor de confianza y puede autorizar a otro introductor de confianza, etc.
[predeterminado: 1]
--domain=DOMINIO
Añadir una restricción de dominio al introducer
Añadir un dominio para restringir qué certificaciones son respetadas. Una certificación hecha por el certificado solo se respeta si es sobre un ID de usuario con una dirección de correo electrónico en el dominio especificado. Se pueden especificar múltiples dominios. En ese caso, uno debe coincidir.
--email=CORREO
Usar un ID de usuario que consiste solo en la dirección de correo electrónico, si la dirección de correo electrónico aparece en un ID de usuario auto-firmado
--expiration=EXPIRACION
Establece el tiempo de expiración
EXPIRACION es una fecha en formato ISO 8601 con hora opcional o una duración personalizada. Una duración tiene el formato `N[ymwds]`, donde las letras representan años, meses, semanas, días y segundos, respectivamente. Alternativamente, la palabra clave `never` no establece un tiempo de expiración.
El valor predeterminado se puede cambiar en el archivo de configuración usando la configuración `pki.vouch.expiration`.
[predeterminado: 10y]
--local
Hacer que la certificación sea local
Normalmente, las certificaciones locales no se exportan.
--non-revocable
Marcar la certificación como no revocable
Es decir, no puedes revocar esta certificación más tarde. Esto normalmente solo debe usarse con una expiración.
--output=ARCHIVO
Escribir en ARCHIVO o stdout si se omite
--regex=REGEX
Añadir una expresión regular para restringir el introducer
Añadir una expresión regular para restringir qué certificaciones son respetadas. Una certificación hecha por el certificado solo se respeta si es sobre un ID de usuario que coincide con una de las expresiones regulares especificadas. Se pueden especificar múltiples expresiones regulares. En ese caso, al menos una debe coincidir.
--signature-notation NOMBRE VALOR
Añadir una notación a la firma
El nombre de una notación definida por el usuario debe tener el formato `nombre@a.dominio.que.controlas.org`. Si el nombre de la notación comienza con un `!`, entonces la notación se marca como crítica. Si un consumidor de una firma no entiende una notación crítica, entonces ignorará la firma. La notación se marca como legible por humanos.
--unconstrained
No restringir el introducer
Normalmente un introducer está restringido de tal manera que solo se respetan ciertos IDs de usuario, p. ej., aquellos que tienen una dirección de correo electrónico para un cierto nombre de dominio. Esta opción autoriza a un introducer sin restringirlo de esta manera. Dado que esto otorga al introducer mucho poder, debe optar explícitamente por este comportamiento.
--userid=ID_USUARIO
Usar el ID de usuario auto-firmado especificado
dl>
El ID de usuario especificado debe ser autofirmado.
--userid-by-email=EMAIL
Utiliza el ID de usuario autofirmado con la dirección de correo electrónico especificada

Opciones globales

Ver sq(1) para una descripción de las opciones globales.

EJEMPLOS

Certifica que E7FC51AD886BBB5C4F44C3D7A9DA14F3E740F63F es un introductor de confianza para example.org y example.com.

sq pki vouch authorize \
--certifier=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--cert=E7FC51AD886BBB5C4F44C3D7A9DA14F3E740F63F \
--domain=example.org --domain=example.com --all
