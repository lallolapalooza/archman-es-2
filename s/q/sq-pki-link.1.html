NOMBRE

sq-pki-link - Gestionar enlaces de certificados y de ID de usuario autenticados

SINOPSIS

sq pki link add [OPCIONES]
sq pki link authorize [OPCIONES]
sq pki link retract [OPCIONES]
sq pki link list [OPCIONES] PATRÓN

DESCRIPCIÓN

Gestiona enlaces de certificados y de ID de usuario autenticados.

Vincular un certificado y un ID de usuario es una forma de hacer que `sq` considere auténtica una vinculación. Otra forma es usar `sq pki vouch add` para certificar la vinculación con una raíz de confianza configurada explícitamente. La funcionalidad de vinculación suele ser más fácil de usar y la información es privada por defecto.

Las vinculaciones autenticadas pueden usarse para designar un certificado mediante un nombre simbólico. Por ejemplo, usando las opciones `--for-userid` y `--for-email` de `sq encrypt`, un usuario puede designar un certificado usando un ID de usuario o una dirección de correo electrónico que esté autenticada para ese certificado.

`sq` también utiliza certificados autenticados para autenticar otros datos. Por ejemplo, `sq verify` considera auténticas las firmas realizadas por un certificado autenticado.

Los usuarios pueden crear un enlace usando `sq pki link add`. Ese enlace puede ser posteriormente revocado usando `sq pki link retract`. Un certificado también puede ser aceptado como un introductor de confianza usando `sq pki link authorize`.

`sq` implementa la vinculación utilizando certificaciones no exportables y una raíz de confianza implícita. Un directorio de certificados OpenPGP, el almacén de certificados predeterminado utilizado por `sq`, incluye una raíz de confianza local, que se almacena bajo el nombre especial `trust-root`. Cuando el usuario instruye a `sq` para aceptar una vinculación, `sq` utiliza la raíz de confianza local para crear una certificación no exportable, que almacena en el directorio de certificados. De esta manera, las operaciones que utilizan la Red de Confianza para autenticar una vinculación utilizan automáticamente los enlaces.

Cuando un usuario revoca un enlace, `sq` crea una nueva certificación no exportable con confianza cero. Esta certificación suprime el enlace anterior.

SUBCOMANDAS

sq pki link add

Enlaza un certificado y un ID de usuario.

Esto hace que `sq` considere auténtica la vinculación entre el certificado y el ID de usuario. Haría esto si estuviera seguro de que un certificado en particular debería asociarse con Alicia, por ejemplo. Nota: esto no considera que el certificado sea un introductor de confianza; solo considera que la vinculación es auténtica. Para autorizar un certificado como introductor de confianza, use `sq pki link authorize`.

Un enlace puede ser revocado usando `sq pki link retract`.

Este comando es similar a `sq pki vouch add`, pero las certificaciones que realiza se hacen utilizando la raíz de confianza del directorio de certificados, no una clave arbitraria. Además, los certificados se marcan como no exportables. Lo primero facilita la gestión de certificaciones, especialmente cuando la clave de certificación del usuario está fuera de línea. Y lo segundo mejora la privacidad del usuario, al reducir la posibilidad de que partes del grafo social del usuario se filtren cuando se comparte un certificado.

Por defecto, un enlace nunca expira. Esto se puede anular usando el argumento `--expiration`.

`sq pki link add` respeta el tiempo de referencia establecido por el argumento de nivel superior `--time`. Establece la hora de creación del enlace a la hora de referencia.

sq pki link authorize

Convierte un certificado en un introductor de confianza.

Esto hace que `sq` considere que el certificado es un introductor de confianza. Introductor de confianza es otra palabra para autoridad de certificación (CA). Cuando enlaza un introductor de confianza, considera que las certificaciones realizadas por el introductor de confianza son válidas. Un introductor de confianza también puede designar introductoras de confianza adicionales.

Tal como está, un introductor de confianza tiene mucho poder. Este poder puede limitarse de varias maneras.


- La capacidad de especificar introductoras adicionales puede restringirse usando el parámetro `--depth`.


- El grado en que se confía en un introductor puede cambiarse usando el parámetro `--amount`.


- Los ID de usuario que un introductor puede certificar pueden restringirse por dominio usando el parámetro `--domain` o por una expresión regular usando el parámetro `--regex`.

Estos mecanismos le permiten decir que está dispuesto a confiar en la CA de example.org, por ejemplo, pero solo para ID de usuario que tengan una dirección de correo electrónico para example.org, por ejemplo.

Un enlace puede ser revocado usando `sq pki link retract`.

Este comando es similar a `sq pki vouch authorize`, pero las certificaciones que realiza se hacen utilizando la raíz de confianza del directorio de certificados, no una clave arbitraria. Además, los certificados se marcan como no exportables. Lo primero facilita la gestión de certificaciones, especialmente cuando su clave de certificación está fuera de línea. Y lo segundo mejora su privacidad, al reducir la posibilidad de que partes de su grafo social se filtren cuando se comparte un certificado.

Por defecto, un enlace nunca expira. Usando el argumento `--expiration` se pueden definir períodos de validez específicos. Permite proporcionar un punto en el tiempo para el fin de la validez o una duración de validez.

`sq pki link authorize` respeta el tiempo de referencia establecido por el argumento de nivel superior `--time`. Establece la hora de creación del enlace a la hora de referencia.

sq pki link retract

Revoca enlaces.

Este comando revoca los enlaces que se crearon previamente usando `sq pki link add` o `sq pki link authorize`. Consulte la documentación de esa subcomando para obtener más detalles. Nota: esto se llama `retract` (revocar) y no `remove` (eliminar), porque las certificaciones no se eliminan. En su lugar, se agrega una nueva certificación que indica que la vinculación no ha sido autenticada.

`sq pki link retract` respeta el tiempo de referencia establecido por el argumento de nivel superior `--time`. Esto hace que un enlace se revoque a partir de una hora determinada en lugar de la hora actual.

sq pki link list

Lista enlaces.

Este comando lista todas las vinculaciones que están enlazadas o cuya vinculación ha sido revocada.

Devuelve un código de salida distinto de cero si un certificado designado explícitamente nunca fue enlazado.

EJEMPLOS

sq pki link add

Enlaza el certificado EB28F26E2739A4870ECC47726F0073F60FD0CBF0 con la dirección de correo electrónico alice@example.org.

sq pki link add \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--email=alice@example.org

Primero, examina el certificado EB28F26E2739A4870ECC47726F0073F60FD0CBF0.

sq inspect --cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0

Luego, acepta temporalmente el certificado EB28F26E2739A4870ECC47726F0073F60FD0CBF0 con todos sus ID de usuario autofirmados durante una semana.

sq pki link add --expiration=1w \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

Una vez satisfecho, acepta permanentemente el certificado EB28F26E2739A4870ECC47726F0073F60FD0CBF0 con todos sus ID de usuario autofirmados.

sq pki link add \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

sq pki link authorize

Agrega un introductor de confianza sin restricciones.

sq pki link authorize --unconstrained \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

Agrega un introductor de confianza para example.org y example.com.

sq pki link authorize --domain=example.org \
--domain=example.com \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

Agrega un introductor parcialmente confiable.

sq pki link authorize --unconstrained --amount=60 \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

sq pki link retract

sq-pki-link

Manage user IDs linked to a certificate.

SYNOPSIS

sq pki link add [options]
sq pki link authorize [options]
sq pki link retract [options]
sq pki link list [options]

DESCRIPTION

This command manages the user IDs that are linked to a certificate. It is useful for asserting that a particular user ID belongs to the owner of a certificate. This command is particularly useful in the context of identity management.

SUBCOMMANDS

add
Adds a link between a certificate and a user ID. The user ID must be provided with --email, --key-id, or --user-id.
authorize
Adds a link between a certificate and a user ID, and signs this link with the key that is used to sign the certificate. This is a way to assert that a user ID belongs to the owner of a certificate.
retract
Removes a link between a certificate and a user ID. If --all is given, all links for the given certificate are removed.
list
Lists all stored links.

EXAMPLES

Link the certificate EB28F26E2739A4870ECC47726F0073F60FD0CBF0 with the email address alice@example.org.

sq pki link add \
    --cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
    --email=alice@example.org

Retract the acceptance of certificate EB28F26E2739A4870ECC47726F0073F60FD0CBF0 and the email address alice@example.org.

sq pki link retract \
    --cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
    --email=alice@example.org

Retract the acceptance of certificate EB28F26E2739A4870ECC47726F0073F60FD0CBF0 and any associated user IDs. This effectively invalidates all links.

sq pki link retract \
    --cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --all

Link the certificate EB28F26E2739A4870ECC47726F0073F60FD0CBF0 with the email address alice@example.org.

sq pki link add \
    --cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
    --email=alice@example.org

List all links.

sq pki link list

List links to certificates with an authenticated user ID that contains an email address in the specified domain.

sq pki link list --cert-domain=example.org
