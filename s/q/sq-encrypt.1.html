SQ(1) Comandos de Usuario SQ(1)

NOMBRE

sq-encrypt - Cifra un mensaje

SINOPSIS

sq encrypt [OPCIONES] ARCHIVO

DESCRIPCIÓN

Cifra un mensaje.

Cifra un mensaje para cualquier número de destinatarios y con cualquier número de contraseñas, firmando opcionalmente el mensaje en el proceso.

La operación inversa es `sq decrypt`.

`sq encrypt` respeta el tiempo de referencia establecido por el argumento de nivel superior `--time`. Utiliza el tiempo de referencia al seleccionar las claves de cifrado y establece la hora de creación de la firma al tiempo de referencia.

OPCIONES

Opciones del subcomando

--binary
Emite datos binarios
--compression=TIPO
Selecciona el esquema de compresión a usar
[por defecto: pad]
[valores posibles: none, pad, zip, zlib, bzip2]
--encrypt-for=PROPÓSITO
Selecciona qué tipo de claves se consideran para el cifrado
[por defecto: universal]
[valores posibles: transport, storage, universal]
--for=HUELLA_DIGITAL|ID_CLAVE
Usa certificados con la huella digital o ID de clave especificada
--for-email=CORREO
Usa certificados donde un ID de usuario incluya la dirección de correo electrónico especificada
--for-file=RUTA
Lee certificados desde la RUTA
--for-self
Cifra el mensaje para ti mismo
Esto añade los certificados listados en el archivo de configuración bajo `encrypt.for-self` a la lista de destinatarios. Esto se puede usar para asegurarse de que tú mismo puedas descifrar el mensaje.
Actualmente, la lista de certificados a añadir está vacía.
--for-userid=ID_USUARIO
Usa certificados con el ID de usuario especificado
--output=ARCHIVO
Escribe en ARCHIVO o stdout si se omite
[por defecto: -]
--profile=PERFIL
Selecciona el estándar OpenPGP predeterminado para el contenedor de cifrado
Al cifrar para certificados, el contenedor de cifrado se selecciona basándose en las preferencias declaradas de los destinatarios. Sin embargo, si no hay orientación, por ejemplo, porque el mensaje está cifrado solo con contraseñas, sq recurre a este perfil.
A medida que OpenPGP evoluciona, habrá nuevas versiones disponibles. Esta opción selecciona la versión de OpenPGP a utilizar para cifrar mensajes si la versión no puede inferirse de otra manera.
Actualmente, sq admite dos perfiles: RFC9580 y RFC4880. Actualmente, el valor predeterminado es RFC4880. Sin embargo, una vez que el soporte para RFC9580 se implemente más ampliamente, el valor predeterminado cambiará en una versión futura de sq.
El valor predeterminado se puede cambiar en el archivo de configuración utilizando la configuración `key.generate.profile`.
[por defecto: rfc4880]
[valores posibles: rfc9580, rfc4880]
--set-metadata-filename=ESTABLECER_NOMBRE_ARCHIVO_METADATOS
Establece el nombre del archivo cifrado como metadato
Tenga en cuenta que este metadato no está firmado y, como tal, depender de él, ya sea en el lado del remitente o del receptor, generalmente se considera peligroso.
--signature-notation NOMBRE VALOR
Añade una notación a la firma
El nombre de una notación definida por el usuario debe tener el formato `nombre@un.dominio.que.controlas.org`. Si el nombre de la notación comienza con un `!`, entonces la notación se marca como crítica. Si un consumidor de una firma no entiende una notación crítica, ignorará la firma. La notación se marca como legible por humanos.
--signer=HUELLA_DIGITAL|ID_CLAVE
Firma el mensaje utilizando la clave con la huella digital o ID de clave especificado
--signer-email=CORREO
Firma el mensaje utilizando la clave donde un ID de usuario incluye la dirección de correo electrónico especificada
--signer-file=RUTA
Firma el mensaje utilizando la clave leída desde la RUTA
--signer-self
Firma utilizando tus claves de firmante predeterminadas
Esto añade los certificados listados en el archivo de configuración bajo `sign.signer-self` a la lista de claves de firmante.
Actualmente, la lista de claves a añadir está vacía.
--signer-userid=ID_USUARIO
Firma el mensaje utilizando la clave con el ID de usuario especificado
--use-expired-subkey
Recurre a subclaves de cifrado expiradas
Si un certificado solo tiene subclaves capaces de cifrado que han expirado, recurre a usar la que expiró más recientemente
--with-password
Pregunta para añadir una contraseña para cifrar
Al usar esta opción, se le pide al usuario que proporcione una contraseña, que se utiliza para cifrar el mensaje. Esta opción se puede proporcionar más de una vez para proporcionar más de una contraseña. Los datos cifrados se pueden descifrar posteriormente con cualquiera de las claves del destinatario o con una de las contraseñas proporcionadas.
--with-password-file=RUTA
Archivo que contiene la contraseña para cifrar el mensaje
Tenga en cuenta que todo el archivo clave se utilizará como contraseña, incluidos los espacios en blanco circundantes, como un salto de línea final.
Esta opción se puede proporcionar más de una vez para proporcionar más de una contraseña. Los datos cifrados se pueden descifrar posteriormente con cualquiera de las claves del destinatario o con una de las contraseñas proporcionadas.
--without-signature
No firmar el mensaje

ARCHIVO
Lee desde ARCHIVO o stdin si ARCHIVO es '-'
[por defecto: -]

Opciones globales

Vea sq(1) para una descripción de las opciones globales.

EJEMPLOS

Cifrar un archivo para un destinatario dado por su huella digital.

sq encrypt --for=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--signer-email=juliet@example.org documento.txt

Cifrar un archivo para un destinatario dado por correo electrónico.

sq encrypt --for-email=alice@example.org \
--signer-email=juliet@example.org documento.txt
