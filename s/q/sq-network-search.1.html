NOMBRE

sq-network-search - Recuperar certificados utilizando todos los servicios de red compatibles

SINOPSIS

sq network search [OPCIONES] CONSULTA

DESCRIPCIÓN

Recupera certificados utilizando todos los servicios de red compatibles.

Este comando intentará localizar certificados relevantes dada una consulta, que puede ser una huella digital, un ID de clave, una dirección de correo electrónico o una URL https. También puede descubrir e importar certificados relacionados con el consultado, como certificados alternativos, certificados caducados o certificados revocados.

Descubrir certificados relacionados es útil: los certificados alternativos admiten rotaciones de claves, los certificados caducados permiten la verificación de firmas realizadas en el pasado y el descubrimiento de certificados revocados es importante para obtener la información de revocación. El mecanismo PKI ayudará a seleccionar el certificado correcto, consulte `sq pki`.

Por defecto, cualquier certificado devuelto se almacena en el almacén de certificados local. Esto se puede anular utilizando la opción `--output`.

Cuando un certificado se recupera de un servidor de claves de verificación (actualmente, esto se limita a una lista de servidores conocidos: `hkps://keys.openpgp.org`, `hkps://keys.mailvelope.com` y `hkps://mail-api.proton.me`), WKD, DANE o a través de https, y se importa en el almacén de certificados local, los User IDs también se certifican con una clave local específica del servidor. Ese certificado proxy, a su vez, se certifica como una CA mínimamente confiable (nivel de confianza: 1 de 120) por la raíz de confianza local. La confianza en una CA de servidor de claves proxy se puede ajustar usando `sq pki link add` o `sq pki link retract` de la manera habitual.

OPCIONES

Opciones de subcomando

--all
Obtener actualizaciones para todos los certificados conocidos
--iterations=N
Iterar para encontrar actualizaciones y certificados relacionados
El valor predeterminado se puede cambiar en el archivo de configuración utilizando la configuración `network.search.iterations`.
[predeterminado: 3]
--output=ARCHIVO
Escribir en ARCHIVO (o stdout si se omite) en lugar de importar en el almacén de certificados
--server=URI
Establecer un servidor de claves a utilizar (se puede especificar varias veces)
El valor predeterminado se puede cambiar en el archivo de configuración utilizando la configuración `network.keyserver.servers`.
[predeterminado: hkps://keys.openpgp.org, hkps://mail-api.proton.me, hkps://keys.mailvelope.com, hkps://keyserver.ubuntu.com, hkps://sks.pod01.fleetstreetops.com]
--use-dane=HABILITAR
Usar DANE para buscar certificados
El valor predeterminado se puede cambiar en el archivo de configuración utilizando la configuración `network.search.use-dane`.
[predeterminado: true]
[valores posibles: true, false]
--use-wkd=HABILITAR
Usar WKD para buscar certificados
El valor predeterminado se puede cambiar en el archivo de configuración utilizando la configuración `network.search.use-wkd`.
[predeterminado: true]
[valores posibles: true, false]

CONSULTA
Recuperar certificado(s) utilizando CONSULTA
Puede ser una huella digital, un ID de clave, una dirección de correo electrónico o una URL https.

Opciones globales

Consulte sq(1) para obtener una descripción de las opciones globales.

EJEMPLOS

Buscar el certificado de firma maestro de Qubes.

sq network search 427F11FD0FAA4B080123F01CDDFA1A3E36879494

Buscar certificados asociados a una dirección de correo electrónico.

sq network search alice@example.org
