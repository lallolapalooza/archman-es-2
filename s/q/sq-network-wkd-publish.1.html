NOMBRE

sq-network-wkd-publish - Publicar certificados en un Directorio de Claves Web

SINOPSIS

sq network wkd publish [OPCIONES] DEST

DESCRIPCIÓN

Publicar certificados en un Directorio de Claves Web (Web Key Directory).

Publica certificados o actualizaciones de certificados en un Directorio de Claves Web (WKD). Puede crear o actualizar una jerarquía WKD en el sistema local especificando una ruta como destino.

Típicamente, un WKD se almacena en un servidor web. Si se proporciona `--rsync`, este comando gestiona jerarquías de directorios WKD remotos utilizando rsync(1).

Para insertar un nuevo certificado en el WKD, use `--cert`.

Cualquier actualización de certificados ya existentes en el WKD se publicará automáticamente.

Nota: Para actualizar una jerarquía WKD, primero se copia a una ubicación temporal en la máquina local, se insertan los nuevos certificados o las actualizaciones de certificados en la copia local, y la jerarquía se copia de nuevo a su ubicación original. Como esta no es una operación atómica, se debe tener cuidado para evitar actualizaciones concurrentes.

OPCIONES

Opciones de subcomando

--all
Publicar certificados autenticados con un ID de usuario que coincida con el dominio
Utilizar todos los certificados que tengan un ID de usuario que coincida con el dominio proporcionado al parámetro `--domain` y que puedan ser autenticados completamente.
--cert=HUellaDigital|IDClave
Utilizar certificados con la huella digital o ID de clave especificado
--cert-email=CORREO
Utilizar certificados donde un ID de usuario incluya la dirección de correo especificada
--cert-file=RUTA
Leer certificados desde RUTA
--cert-userid=IDUSUARIO
Utilizar certificados con el ID de usuario especificado
--create
Crear la jerarquía WKD si aún no existe
--domain=FQDN
Generar un WKD para un nombre de dominio completamente calificado para correo electrónico
--method=METODO
Seleccionar el tipo de jerarquía WKD a crear
El método avanzado, que es el predeterminado y debe preferirse, se aloja en un dominio separado (por ejemplo, openpgpkey.example.org).
El método directo se aloja en el mismo dominio (por ejemplo, example.org).
[posibles valores: advanced, direct]
--rsync
Utilizar rsync(1) para acceder a DEST
--rsync-path=RSYNC
Ruta al comando rsync local a utilizar, implica --rsync

DEST
Ubicación del WKD en la máquina local o remota
Si se proporciona --rsync, esto se pasa tal cual a rsync(1).

Opciones globales

Consulte sq(1) para una descripción de las opciones globales.

EJEMPLOS

Crear una nueva jerarquía WKD en el directorio local `public_html`, e insertar el certificado de Alice.

sq network wkd publish --create \
--cert=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--domain=example.org public_html

Añadir el certificado de Bob a la jerarquía WKD existente en el directorio local `public_html`.

sq network wkd publish \
--cert=511257EBBF077B7AEDAE5D093F68CB84CE537C9A \
--domain=example.org public_html

Añadir todos los certificados con un ID de usuario autenticado en example.org a la jerarquía WKD existente.

sq network wkd publish --domain=example.org --all public_html

Actualizar todos los certificados en la jerarquía WKD existente en el directorio local `public_html` desde el almacén de certificados.

sq network wkd publish --domain=example.org public_html
