SQ(1) Comandos de Usuario SQ(1)

NOMBRE

sq - Una interfaz de línea de comandos para Sequoia, una implementación de OpenPGP

SINOPSIS

sq encrypt [OPCIONES] ARCHIVO
sq decrypt [OPCIONES] ARCHIVO
sq sign [OPCIONES] ARCHIVO
sq verify [OPCIONES] ARCHIVO
sq download [OPCIONES]
sq inspect [OPCIONES] ARCHIVO
sq cert [OPCIONES] SUBCOMANDO
sq key [OPCIONES] SUBCOMANDO
sq pki [OPCIONES] SUBCOMANDO
sq network [OPCIONES] SUBCOMANDO
sq keyring [OPCIONES] SUBCOMANDO
sq packet [OPCIONES] SUBCOMANDO
sq config [OPCIONES] SUBCOMANDO
sq version [OPCIONES]

DESCRIPCIÓN

Una interfaz de línea de comandos para Sequoia, una implementación de OpenPGP.

La funcionalidad está agrupada y disponible mediante subcomandos. Esta interfaz no es completamente sin estado. En particular, se utiliza el almacén de certificados predeterminado del usuario. Esto se puede deshabilitar usando `--cert-store=none`. De manera similar, se utiliza un almacén de claves para gestionar y proteger el material de claves secretas. Esto se puede deshabilitar usando `--key-store=none`.

Los datos de OpenPGP pueden proporcionarse en formato binario o codificado en ASCII. Esto se manejará automáticamente. Los datos de OpenPGP emitidos están codificados en ASCII por defecto.

Usamos el término "certificado" (o "cert" para abreviar) para referirnos a las claves OpenPGP que no contienen secretos. Por el contrario, usamos el término "clave" para referirnos a las claves OpenPGP que sí contienen secretos.

OPCIONES

Opciones globales

--batch
Evita cualquier tipo de solicitud
Habilita el modo por lotes. En el modo por lotes, sq nunca solicitará información al usuario, como contraseñas.
--cert-store=RUTA
Especifica la ubicación del almacén de certificados
Por defecto, `sq` utiliza el directorio de certificados OpenPGP en el directorio de inicio de Sequoia (ver `--home`), $HOME/.local/share/pgp.cert.d. Esto se puede anular estableciendo la variable de entorno `PGP_CERT_D`.
Use 'default' para usar explícitamente el almacén de certificados predeterminado, use 'none' para no usar un almacén de certificados.
--cli-version=VERSIÓN_CLI
Selecciona una versión de CLI
La CLI de `sq` tiene versiones utilizando un esquema de versionado semántico. Establecer esta opción hace que `sq` falle si no implementa una interfaz compatible con la versión especificada. Por ejemplo, si establece esto a 1.1.0 y `sq` solo implementa la versión 1.0.0 de la interfaz, entonces `sq` fallará.
`sq` puede implementar múltiples interfaces (por ejemplo, 1.1.4 y 2.0.5). Por defecto, selecciona la versión más reciente. Como tal, si requiere una interfaz particular, debe establecer esta opción para cada llamada a `sq`.
Esta opción debe ser la primera opción en la línea de comandos.
Esta versión de `sq` implementa la versión 1.3.1 de la interfaz CLI.
Estable desde 1.2.0.
-h, --help
Imprime la ayuda (ver un resumen con '-h')
--home=RUTA
Establece el directorio de inicio
El directorio de inicio predeterminado de Sequoia es `$HOME`. Cuando se utiliza la ubicación predeterminada, los archivos se colocan de acuerdo con el estándar local, por ejemplo, la Especificación de Directorios Base XDG. Cuando se especifica una ubicación alternativa, los datos del usuario, los archivos de configuración y los datos de caché se colocan dentro de un único directorio unificado. Esta es una forma ligera de aislar parcialmente `sq`.
Use 'default' para usar explícitamente la ubicación predeterminada, use 'none' para no usar un directorio de inicio.
--key-store=RUTA
Anula el servidor de almacén de claves y sus datos
Un servidor de almacén de claves gestiona y protege el material de claves secretas. Por defecto, `sq` se conecta al servidor de almacén de claves del directorio de inicio predeterminado de Sequoia (ver `--home`), $HOME/.local/share/sequoia/keystore. Si no hay ningún servidor de almacén de claves en ejecución, se inicia uno.
Esta opción hace que `sq` utilice un servidor de almacén de claves alternativo. Si es necesario, se inicia un servidor de almacén de claves y se configura para buscar sus datos en la ubicación especificada.
Use 'default' para usar explícitamente el servidor predeterminado, use 'none' para no usar un almacén de claves.
--keyring=RUTA
Especifica la ubicación de un keyring a usar
Los keyrings se utilizan además de cualquier almacén de certificados. El contenido del keyring no se importa en el almacén de certificados. Cuando se busca un certificado, se busca en todos los keyrings y en cualquier almacén de certificados, y los resultados se fusionan.
--known-notation=NOTACIÓN
Añade NOTACIÓN a la lista de notaciones conocidas
Esto se utiliza al validar firmas. Las firmas que tienen notaciones desconocidas con el bit crítico establecido se consideran inválidas.
--overwrite
Sobrescribe archivos existentes
--password-file=ARCHIVO
Siembra la caché de contraseñas con la contraseña especificada
La contraseña se añade a la caché de contraseñas. Al descifrar material de clave secreta, la caché de contraseñas solo se utiliza si la clave no está protegida por un contador de reintentos, que bloquea automáticamente la clave si se introduce una contraseña incorrecta demasiadas veces.
Tenga en cuenta que se utilizará todo el archivo de clave como contraseña, incluyendo cualquier espacio en blanco circundante, como un salto de línea final.
--policy-as-of=TIEMPO
Selecciona la política criptográfica a partir del tiempo especificado
El tiempo se expresa como una marca de tiempo con formato ISO 8601. La política determina qué constructos criptográficos están permitidos.
Si está trabajando con un mensaje que `sq` rechaza, porque está protegido por constructos criptográficos que ahora se consideran rotos, puede usar esta opción para seleccionar una política criptográfica diferente. Si confía en la criptografía, es decir, si está verificando una firma, solo debe hacer esto si está seguro de que el mensaje no ha sido manipulado.
El TIEMPO se interpreta como una marca de tiempo ISO 8601. Para establecer la política de tiempo al 1 de enero de 2007 a medianoche UTC, puede hacer:
$ sq --policy-as-of 20070101 verify --message msg.pgp
Por defecto, usa el tiempo de referencia, que se puede establecer usando --time.
-q, --quiet
Sé más silencioso
El valor predeterminado se puede cambiar en el archivo de configuración usando la configuración `ui.quiet`.
--time=TIEMPO
Establece el tiempo de referencia como una marca de tiempo con formato ISO 8601
Normalmente, los comandos usan la hora actual como tiempo de referencia. Este argumento permite al usuario usar un tiempo de referencia diferente. Por ejemplo, al crear una clave usando `sq key generate`, la hora de creación se establece normalmente en la hora actual, pero se puede anular usando esta opción. De manera similar, al verificar un mensaje, el mensaje se verifica con respecto a la hora actual. Esta opción permite al usuario utilizar un tiempo diferente.

OPTIONS

-t DATETIME, --time=DATETIME
Use DATETIME instead of the current date and time.
The date and time are specified using the ISO 8601 format, e.g. "2013-07-21T16:40:30Z". This is useful for signing messages, or to verify messages that were signed in the past.
Supported formats: YYYYMMDD, YYYY-MM-DD, YYYYMMDDTHHMMSSZ, YYYY-MM-DDTHH:MM:SSZ, YYYYMMDDTHHMMSS+HHMM, YYYY-MM-DDTHH:MM:SS+HH:MM.
The following commands support this option:
sq encrypt, sq decrypt, sq sign, sq verify, sq inspect, sq cert, sq key, sq keyring, sq pki.
This option can be set in the configuration file using the `ui.time` setting.
To specify the time of signature creation, the argument to `--time` is parsed as a date and time. To verify a message as of a given date and time, the argument to `--time` is parsed as a date and time. Otherwise, the argument to `--time` is parsed as a date only.
To include a time, say 5:50 AM, add a T, the time and optionally the timezone (the default timezone is UTC):
$ sq --time 20130721T0550+0200 --message verify msg.pgp
--trust-root=FINGERPRINT|KEYID
Consider the specified certificate to be a trust root
Trust roots are used by trust models, e.g., the Web of Trust, to authenticate certificates and User IDs.
-v, --verbose
Be more verbose
The default can be changed in the configuration file using the setting `ui.verbose`.

SUBCOMANDOS

sq encrypt

Cifra un mensaje.

Cifra un mensaje para cualquier número de destinatarios y con cualquier número de contraseñas, firmando opcionalmente el mensaje en el proceso.

La operación inversa es `sq decrypt`.

`sq encrypt` respeta el tiempo de referencia establecido por el argumento de nivel superior `--time`. Utiliza el tiempo de referencia al seleccionar claves de cifrado y establece la hora de creación de la firma como el tiempo de referencia.

sq decrypt

Descifra un mensaje.

Descifra un mensaje utilizando claves proporcionadas o solicitando una contraseña. Si se detecta manipulación del mensaje, se devuelve un error. Consulte más abajo para obtener detalles.

Si se proporcionan certificados utilizando la opción `--signer-file`, se comprobarán las firmas encontradas utilizando estos certificados. La verificación solo tiene éxito si no hay firmas erróneas y el número de firmas verificadas con éxito alcanza el umbral configurado con el parámetro `--signatures`.

Si la verificación de la firma falla o si se detecta manipulación del mensaje, el programa termina con un estado de salida que indica fallo, y el archivo de salida se elimina. Si la salida se envió a stdout, se retienen los últimos 25 MiB del mensaje (en consecuencia, si el mensaje es menor a 25 MiB, no se produce ninguna salida).

La operación inversa es `sq encrypt`.

sq sign

Firma mensajes o archivos de datos.

Crea mensajes firmados o firmas separadas. Las firmas separadas se utilizan a menudo para firmar paquetes de software.

La operación inversa es `sq verify`.

`sq sign` respeta el tiempo de referencia establecido por el argumento de nivel superior `--time`. Cuando se establece, utiliza la hora especificada en lugar de la hora actual, al determinar qué claves son válidas, y establece la hora de creación de la firma como el tiempo de referencia en lugar de la hora actual.

sq verify

Verifica mensajes firmados o firmas separadas.

Al verificar mensajes firmados, el mensaje se escribe en stdout o en el archivo proporcionado a `--output`.

Al verificar un mensaje separado, no se produce ninguna salida. Las firmas separadas se utilizan a menudo para firmar paquetes de software.

La verificación solo tiene éxito si no hay firmas erróneas y el número de firmas verificadas con éxito alcanza el umbral configurado con el parámetro `--signatures`. Si la verificación falla, el programa termina con un estado de salida que indica fallo, y el archivo de salida se elimina. Si la salida se envió a stdout, se retienen los últimos 25 MiB del mensaje (en consecuencia, si el mensaje es menor a 25 MiB, no se produce ninguna salida).

Una firma se considera autenticada si el firmante puede ser autenticado. Si el firmante se proporciona a través de `--signer-file`, entonces se considera autenticado al firmante. De lo contrario, el firmante se busca y se autentica utilizando la Red de Confianza. Si al menos un ID de usuario puede ser autenticado completamente, entonces se considera que la firma ha sido autenticada. Si la firma incluye un subpaquete de ID de usuario del firmante, entonces solo se considera ese ID de usuario. Nota: el ID de usuario no necesita ser autofirmado.

La operación inversa es `sq sign`.

Si está buscando un programa independiente para verificar firmas separadas, considere usar sequoia-sqv.

`sq verify` respeta el tiempo de referencia establecido por el argumento de nivel superior `--time`. Cuando se establece, verifica el mensaje como en el tiempo de referencia en lugar del tiempo actual.

sq download

Descarga y autentica los datos.

Este comando descarga los datos de la URL especificada, comprueba la firma y luego autentica al firmante. Si el firmante no puede ser autenticado, los datos se eliminan, si es posible.

sq inspect

Inspecciona datos, como file(1).

A menudo es difícil saber por una inspección superficial con cat(1) o file(1) qué tipo de OpenPGP se está mirando. Este subcomando inspecciona los datos y proporciona una descripción significativa legible por humanos.

`sq inspect` respeta el tiempo de referencia establecido por el argumento de nivel superior `--time`. Utiliza el tiempo de referencia al determinar qué firmas vinculantes están activas.

sq cert

Gestiona certificados.

Usamos el término "certificado" o "cert" para abreviar, para referirnos a claves OpenPGP que no contienen secretos. Este subcomando proporciona primitivas para generar y manipular certificados.

Por el contrario, usamos el término "clave" para referirnos a claves OpenPGP que contienen secretos. Consulte `sq key` para operaciones sobre claves.

sq key

Gestiona claves.

Usamos el término "clave" para referirnos a claves OpenPGP que contienen secretos. Este subcomando proporciona primitivas para generar y manipular claves.

Por el contrario, usamos el término "certificado" o "cert" para abreviar, para referirnos a claves OpenPGP que no contienen secretos. Consulte `sq cert` para operaciones sobre certificados.

sq pki

Autentica certificados utilizando la Red de Confianza.

La "Red de Confianza" es un modelo de confianza descentralizado popularizado por PGP. Es un superconjunto de X.509, que es un modelo de confianza jerárquico y es el modelo de confianza más popular en Internet pública hoy en día. Tal como se usa en Internet pública, sin embargo, X.509 depende de un puñado de autoridades de certificación (CA) globales que a menudo socavan su seguridad.

La Red de Confianza es más matizada que X.509. Usando la Red de Confianza, requiere múltiples caminos independientes para autenticar una vinculación confiando parcialmente en las CA. Esto evita que un solo actor malintencionado comprometa su seguridad. Y aquellos con requisitos de seguridad más estrictos pueden usar la Red de Confianza de manera completamente descentralizada donde solo los individuos que seleccionan — que no son necesariamente instituciones — actúan como introductoras de confianza.

sq network

Recupera y publica certificados a través de la red.

Los certificados OpenPGP pueden descubrirse y actualizarse desde, y publicarse en servicios accesibles a través de la red. Esta es una colección de comandos para interactuar con estos servicios.

sq keyring

Gestiona colecciones de claves o certificados.

Las colecciones de claves o certificados (también conocidas como "keyrings" cuando contienen material de clave secreta, y "certrings" cuando no) son cualquier número de certificados concatenados. Este subcomando proporciona herramientas para listar, dividir, fusionar y filtrar keyrings.

Nota: En la documentación de este subcomando, a veces usamos los términos claves y certs de forma intercambiable.

sq packet

Manipulación de paquetes de bajo nivel.

Un flujo de datos OpenPGP consta de paquetes. Estas herramientas permiten trabajar con flujos de paquetes. Son principalmente de interés para los desarrolladores, pero `sq packet dump` puede ser útil para una audiencia más amplia, tanto para proporcionar información valiosa en informes de errores a software relacionado con OpenPGP, como para herramienta de aprendizaje.

sq config

Consulta, inspecciona y crea el archivo de configuración.

Este subcomando se puede usar para consultar e inspeccionar el archivo de configuración (ubicación predeterminada: $HOME/.config/sequoia/sq/config.toml), y para crear una plantilla que se pueda editar a su gusto.

Archivo de configuración: $HOME/.config/sequoia/sq/config.toml

sq version

Información detallada de versión y versión de salida.

Sin opciones adicionales, este comando enumera la versión de `sq`, la versión de la implementación OpenPGP subyacente `sequoia-openpgp`, y qué biblioteca criptográfica se utiliza.

EJEMPLOS

sq encrypt

Cifra un archivo para un destinatario dado por su huella digital.

sq encrypt --for=EB28F26E2739A4870ECC47726F0073F60FD0CBF0 \
--signer-email=juliet@example.org document.txt

Cifra un archivo para un destinatario dado por su correo electrónico.

sq encrypt --for-email=alice@example.org \
--signer-email=juliet@example.org document.txt

sq decrypt

Descifra un archivo usando una clave secreta.

sq decrypt --recipient-file juliet-secret.pgp ciphertext.pgp

Descifra un archivo verificando las firmas.

sq decrypt --recipient-file juliet-secret.pgp --signer-file \
romeo.pgp ciphertext.pgp

Descifra un archivo usando el almacén de claves.

sq decrypt ciphertext.pgp

sq sign

Crea un mensaje firmado.

sq sign --signer-file juliet-secret.pgp --message document.txt

Crea una firma separada.

sq sign --signer-file juliet-secret.pgp \
--signature-file=document.txt.sig document.txt

sq verify

Verifica un mensaje firmado.

sq verify --message document.pgp

Verifica una firma separada.

sq verify --signature-file=document.sig document.txt

Verifica un mensaje a partir del 19 de junio de 2024 a medianoche UTC.

sq verify --time 2024-06-19 --message document.pgp

sq download

Descarga y verifica el archivo de suma de verificación de Debian 12.

sq download --url=file://debian/SHA512SUMS \
--signature-url=file://debian/SHA512SUMS.sign \
--signer=DF9B9C49EAA9298432589D76DA87E80D6294BE9B \
--output=SHA512SUMS

sq inspect

Inspecciona un certificado.

sq inspect juliet.pgp

Muestra cómo se veía el certificado el 21 de julio de 2013.

sq inspect --time 20130721 juliet.pgp

Inspecciona un mensaje cifrado.

sq inspect message.pgp

Inspecciona una firma separada.

sq inspect document.sig
