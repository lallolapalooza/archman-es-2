SQUEAK(1) Sistema Squeak Smalltalk SQUEAK(1)

NOMBRE

squeak, inisqueak - máquina virtual y instalador de Squeak para Unix

SINOPSIS

inisqueak
squeak [ opción... ] [ imagen ] [ script [ argumento... ] ]

DESCRIPCIÓN

squeak es la máquina virtual para el sistema Squeak Smalltalk. Requiere tres archivos para operar correctamente: un archivo de imagen que contiene una 'instantánea' de una sesión Squeak activa, un archivo de cambios que contiene el código fuente de los métodos modificados en la imagen, y una copia de (o un enlace a) un archivo de fuentes del sistema compartido que contiene el código fuente de los métodos que no han sido modificados desde el último incremento de versión principal.

Los archivos de imagen y cambios contienen el estado de la sesión Squeak de un usuario, que es persistente entre sesiones consecutivas. Por lo tanto, normalmente se requieren copias privadas de estos archivos. El script inisqueak verifica que la instalación local de Squeak parezca correcta y luego copia los archivos necesarios al directorio de trabajo actual. Si inisqueak no encuentra ningún problema, finalizará ejecutando squeak para iniciar una sesión Squeak utilizando los archivos de imagen y cambios recién copiados.

inisqueak debe ejecutarse una vez, al usar Squeak por primera vez, para crear una nueva sesión Squeak 'personal'. Después, squeak debe ejecutarse cada vez que se desee reanudar esa sesión.

INVOCACIÓN

inisqueak no tiene opciones ni argumentos. Simplemente navegue ('cd') al directorio que contendrá las copias de trabajo de los archivos de imagen y cambios, y luego ejecútelo.

squeak acepta varias opciones (descritas a continuación), y luego un nombre de imagen opcional (que no debe comenzar con un guion '-'). Si se proporciona un nombre de imagen en la línea de comandos, entonces squeak intenta ejecutar esa imagen. De lo contrario, squeak verifica la variable de entorno SQUEAK_IMAGE y, si está establecida, utiliza su valor como el nombre de la imagen a ejecutar. De lo contrario, squeak busca una imagen llamada 'squeak.image' en el directorio actual. Si el archivo de imagen no existe, entonces squeak imprime un mensaje indicando qué archivo de imagen no pudo encontrar y luego sale. Si la extensión '.image' falta en el argumento imagen o en el valor de la variable SQUEAK_IMAGE, se agregará automáticamente.

Al argumento imagen se le puede seguir un nombre de script. Este es el nombre de un 'documento' que debe contener código Smalltalk a ser ejecutado al inicio. El documento puede ser el nombre de un archivo o una URL que comience con 'http:'. Cualquier argumento que aparezca después del nombre del script se ignora, pero está disponible para el script desde dentro de Squeak a través del método getSystemAttribute:. (Ver la sección SCRIPTS abajo).

Si imagen se proporciona como '--' entonces squeak detiene inmediatamente el procesamiento de argumentos (y se comporta como si imagen no se hubiera especificado). Esto es útil para especificar un script (posiblemente con argumentos de script) sin especificar una imagen explícita.

OPCIONES

Las opciones de línea de comandos se dividen en dos categorías: opciones 'comunes' que son reconocidas por la VM base y opciones 'específicas' que están ligadas a un controlador de pantalla o sonido particular. Las opciones comunes siempre serán reconocidas por squeak, mientras que una opción específica dada solo será reconocida después de que squeak haya cargado el controlador al que se relaciona. Consulte la opción '-vm' a continuación para obtener más detalles.

Las opciones comunes reconocidas por squeak son las siguientes:

-codificación cod
especifica la codificación de caracteres interna a ser utilizada por Squeak. Esto afecta la traducción que realiza la VM al importar texto (desde el teclado o mediante 'pegar' desde una selección externa) o al exportar texto (pegar texto desde Squeak a otra aplicación, o al generar nombres de archivo que contengan caracteres especiales). En otras palabras, afecta la correspondencia entre lo que Squeak muestra en la pantalla y lo que envía a (o recibe de) aplicaciones externas. El valor correcto depende de la forma en que están codificadas las fuentes internas de Squeak. Las imágenes actuales se entregan con fuentes tradicionales de Macintosh 'New York' que usan la codificación Mac Roman, y por lo tanto esta es la codificación interna predeterminada. Si otras fuentes (de X11 o de otro lugar) se importan a la imagen y se usan como fuentes del sistema, entonces esta traducción predeterminada dará resultados incorrectos para marcas diacríticas y caracteres especiales. En tales casos, la opción 
    -codificación ISO-8859-15

(también conocido como Latin9) que sería apropiado para muchas de las fuentes diseñadas para idiomas europeos.

-ayuda
imprime un breve resumen de la sintaxis de la línea de comandos, las opciones y los controladores disponibles, y luego sale.
-memoria tamaño[mk]
solicita que se asigne un montón (heap) fijo de tamaño bytes para la imagen Squeak. Si se da el sufijo `k' entonces el argumento se expresa en kilobytes. Si se da el sufijo `m' entonces el argumento se expresa en megabytes. Esta opción NO DEBE usarse, a menos que haya una buena razón para hacerlo, ya que impone un límite arbitrario al tamaño de la memoria de objetos de Squeak.
-mmap tamaño[mk]
solicita que se asigne un montón (heap) variable de como máximo tamaño bytes. (Los sufijos son como se describe para la opción '-memoria'.) squeak asignará inicialmente un montón que sea lo suficientemente grande para contener la imagen, con una pequeña cantidad de espacio adicional. Si en algún momento Squeak requiere más memoria para su imagen, se asignará espacio adicional dinámicamente. De manera similar, cuando la memoria ya no sea necesaria, se liberará y se devolverá al sistema. El argumento tamaño establece un límite superior sobre cuán grande puede crecer el montón de esta manera. squeak usa un montón dinámico por defecto con un tamaño máximo establecido al 75% de la memoria virtual disponible o 1 gigabyte, lo que sea menor.
-sin-eventos
deshabilita el nuevo mecanismo de entrada basado en eventos (imagen 2.8 y posteriores). Esta opción solo es útil para probar la compatibilidad con versiones anteriores de imágenes y no debe usarse.
-sin-temporizador
deshabilita el uso del temporizador de intervalo para el seguimiento del tiempo de baja resolución. (Si tiene problemas con la E/S de archivos, sonido o sockets que informan de `llamada al sistema interrumpida' entonces configurar esta bandera podría ayudar.)
-pathenc cod
especifica la codificación de caracteres externa a ser utilizada por Squeak al acceder al sistema de archivos (rutas de archivos y directorios). El valor correcto depende de las características de la plataforma local. Si no se debe realizar ninguna conversión de codificación, entonces esto debería establecerse en la misma codificación que Squeak usa internamente (ver la opción -codificación). De lo contrario, ISO-8859-15 (también conocido como Latin9) podría tener sentido en un sistema de archivos que soporte caracteres de 8 bits, y UTF-8 para sistemas de archivos que utilicen rutas basadas en Unicode. El valor predeterminado es UTF-8, que es correcto para Mac OS X y distribuciones GNU/Linux muy recientes, y que (en un mundo ideal) eventualmente será adoptado por todas las variantes de Unix.
-plugins ruta
especifica una ubicación alternativa para plugins externos (colecciones de primitivas nombradas) y controladores (para pantalla y sonido). El argumento ruta contiene un patrón en el que cualquier ocurrencia de `%n' será reemplazada por el nombre del plugin o controlador que se está cargando. La ruta puede nombrar un directorio o el plugin en sí y puede ser absoluta o relativa (al directorio en el que se ejecutó squeak). Si no se puede encontrar un plugin o controlador en la ubicación especificada por ruta, la búsqueda continúa en las ubicaciones predeterminadas.
-textenc cod
especifica la codificación de caracteres externa a ser utilizada por Squeak al intercambiar texto del portapapeles con otras aplicaciones. El valor predeterminado es UTF-8 en Mac OS X y ISO-8859-15 (también conocido como Latin9) en otros sistemas Unix. Tenga en cuenta que las aplicaciones X11 que solicitan la selec

Squeak reconoce un subconjunto de los nombres de codificación definidos por la IANA. (Si prefiere usar el símbolo de moneda internacional en lugar del símbolo Euro en texto externo, puede que desee configurar esto en ISO-8859-1, también conocido como Latin1).

-version
imprime tres o más líneas de información de versión, como sigue:
   •
la arquitectura configurada para la máquina virtual en el momento de la compilación, el `número de secuencia' de compilación, la hora y fecha de compilación, y el nombre (y versión, si se conoce) del compilador que se utilizó para compilar squeak;

la información completa de uname(1) para el host en el que se compiló la máquina virtual;
   •
la ubicación predeterminada instalada para plugins y drivers;

Después de imprimir lo anterior, la máquina virtual se cierra.

-vm driver
pide a squeak que cargue un driver de sonido/pantalla. Para cada dispositivo soportado, hay un driver correspondiente que squeak carga durante la inicialización. A menos que se indique lo contrario, squeak determinará drivers predeterminados sensatos para cargar. Esta elección puede ser anulada usando esta opción. El argumento driver es una lista de una o más 'asignaciones' de la forma

     clase=dispositivo

separadas por espacios o comas. Las combinaciones soportadas actualmente son:

   display=X11
para mostrar la ventana de Squeak en un servidor X Window System local o remoto.
   display=Quartz
para mostrar en el escritorio local de Mac OS X.
   display=none
para deshabilitar la pantalla (y el teclado/ratón) por completo. (Este driver es útil principalmente para ejecutar aplicaciones de 'servidor' en Squeak).
   sound=OSS
proporciona entrada y salida de audio a través del Open Sound System. (Si tiene un dispositivo llamado '/dev/dsp', es probable que sea este).
   sound=MacOSX
proporciona entrada/salida de audio a través de Core Audio en Mac OS X.
   sound=NAS
proporciona E/S de audio a través del Network Audio System.
   sound=Sun
proporciona sonido en hardware de Sun Microsystems.
   sound=none
deshabilita el sonido por completo. squeak no intentará reproducir ni grabar sonidos cuando este driver esté cargado.
Tenga en cuenta que solo estarán disponibles los drivers relevantes para la plataforma local. Intentar cargar un driver no soportado provocará que squeak termine con un mensaje de error. Una lista de los drivers disponibles se imprime con la opción '-help'. Si un driver particular no puede cargar las bibliotecas del sistema de las que depende, no se listará ni estará disponible para cargar en tiempo de ejecución.
Tenga en cuenta también que en Mac OS X, tanto los drivers de pantalla X11 como Quartz son soportados, aunque el primero se negará a cargar si las bibliotecas cliente X11 no están instaladas en la máquina local. El driver Quartz se cargará sin problemas (y Squeak se ejecutará como una aplicación completa) incluso cuando squeak se invoque desde la línea de comandos. Tenga cuidado al iniciar sesión en Mac OS X desde otra máquina: olvidar establecer DISPLAY antes de intentar ejecutar squeak en la pantalla remota podría causar vergüenza.

Las opciones específicas para el driver de pantalla X11 son las siguientes:

-browserWindow id
especifica el id de la ventana que squeak debe usar para su pantalla. Esta opción está destinada a usarse cuando Squeak se ejecuta como un plugin de navegador web.
-display server
especifica que Squeak debe conectarse al servidor de pantalla dado en lugar de buscar en la variable de entorno DISPLAY (el comportamiento predeterminado) para encontrar el nombre del servidor a usar.
-cmdmod N
indica a la VM que mapee la tecla modificadora N del teclado al código modificador que la imagen espera para la tecla Comando.
-optmod N
indica a la VM que mapee la tecla modificadora N del teclado al código modificador que la imagen espera para la tecla Opción.
-compositioninput
habilita el soporte para una ventana superpuesta en la que se componen caracteres individuales (por ejemplo, hiragana japonés) antes de ser interpretados como un solo carácter (por ejemplo, kanji japonés) por la imagen.
-xicfont font
indica a la VM que utilice la fuente con nombre dentro de la ventana superpuesta de composición.
-fullscreen
hace que la ventana de Squeak ocupe la mayor parte del área de la pantalla posible. Implica '-notitle'.
-headless
deshabilita la pantalla gráfica y la entrada del ratón/teclado. Este modo de operación es útil principalmente para servidores.
-iconic
pide al gestor de ventanas que minimice la ventana de Squeak al inicio.
-lazy
hace que Squeak `duerma' siempre que la ventana principal no esté mapeada. Esto se puede usar si Squeak parece estar consumiendo tiempo de CPU en reposo (lo que normalmente no debería ocurrir). Tenga en cuenta que si esta opción está activa, cuando la ventana de Squeak no esté mapeada, squeak no responderá a ningún estímulo externo (aparte de proporcionar la selección X a los solicitantes, cuando Squeak sea el propietario).
-mapdelbs
mapea la tecla Suprimir a Retroceso. Suprimir elimina el carácter a la izquierda del cursor y Suprimir normalmente elimina el carácter a la derecha del cursor. Con esta opción, Suprimir se comportará como Retroceso. El comportamiento de Retroceso no cambia.
-noxdnd
deshabilita el soporte para el protocolo X de arrastrar y soltar.
-nointl
deshabilita el manejo de teclas muertas en teclados internacionales. Sin esta opción, el manejo de teclas muertas está habilitado si LC_ALL o LC_CTYPE están configurados en el entorno.
-notitle
deshabilita la barra de título en la ventana de Squeak (si el gestor de ventanas lo soporta). Esta opción está implícita en '-fullscreen'.
-swapbtn
intercambia los botones amarillo y azul. (Tradicionalmente, el botón rojo está a la izquierda, el amarillo en el centro y el azul a la derecha. Los nombres coloridos provienen del Xerox Alto en el que se implementó por primera vez Smalltalk.) Squeak normalmente mapea los botones X 1, 2 y 3 a los botones rojo, amarillo y azul, en ese orden. Con esta opción, mapea los botones X 1, 2 y 3 a los botones rojo, azul y amarillo.)
-xasync
hace que Squeak utilice actualizaciones de pantalla asíncronas. La máquina virtual normalmente vacía y sincroniza la conexión de pantalla a intervalos regulares. Usar esta opción deshabilita la sincronización, que solo se realizará cuando la imagen la solicite explícitamente.
-xshm
habilita el uso de la extensión X Shared Memory en servidores que la soporten. Esto puede mejorar drásticamente el rendimiento de la pantalla, pero solo funciona cuando Squeak se ejecuta en el servidor.

Las opciones específicas para el driver de pantalla FBDev son las siguientes:

-fbdev device
Utiliza el dispositivo de framebuffer dado en lugar del predeterminado '/dev/fb0'.
-kbmap mapfile
Carga el mapa del teclado desde el mapfile dado en lugar de leerlo del kernel en ejecución. Tenga en cuenta que squeak no puede (actualmente) leer archivos de mapa comprimidos o de 'taquigrafía' (como los que se encuentran en /usr/share/keymaps o /lib/kbd/keymaps). Para generar un archivo de mapa de teclas utilizable por squeak, ejecute el siguiente programa desde la consola:

    dumpkeys -f -n --keys-only > key.map

Si squeak encuentra un problema al intentar cargar mapfile, imprimirá un mensaje de error y saldrá. Consulte keymaps(5) para obtener más información sobre el formato del archivo de mapa de teclas. Los programas dumpkeys(1), loadkeys(1), y showkey(1) se pueden usar para modificar el mapa del teclado antes de crear un archivo de mapa de teclas para squeak.

-msdev device
Utiliza el dispositivo de ratón dado en lugar del predeterminado. El predeterminado es intentar '/dev/psaux', '/dev/input/mice' y '/dev/adbmouse', en ese orden, y usar el primero que tenga un dispositivo físico conectado.
-msproto protocol
Utiliza el protocolo de ratón dado en lugar del predeterminado. Los protocolos soportados son 'ps2' y 'adb'. El predeterminado es 'ps2' para ratones conectados a '/dev/psaux' o '/dev/input/mice', y 'adb' para ratones conectados a '/dev/adbmouse'.
-vtlock
No permite el cambio de VT, independientemente de si la solicitud proviene del teclado o de otro programa como chvt(1).
-vtswitch
Habilita el cambio de VT por teclado. Tenga en cuenta que esta opción está efectivamente deshabilitada si la opción '-vtlock' también está habilitada.

OPTIONS

Options are specified on the command line with a leading hyphen and a following argument. Some options are flags and do not require an argument. The order of options is not important.

The arguments for the options are generally case-insensitive.

-vm vmname
Use the named virtual machine program to run Squeak. If this option is not specified then squeak will attempt to find a suitable virtual machine program automatically.
-xshm
Enable the use of XShm (Shared Memory) extension for X11 display servers. This can improve graphics performance. This is the default on systems where XShm is available.
-xsync
Enable synchronous mode for X11 display servers. This is useful for debugging as it causes X11 calls to return immediately. Slower than asynchronous mode.
-heap size[k|m]
Set the initial size of the Squeak heap. If the size is followed by 'k' or 'm' then it is interpreted in kilobytes or megabytes respectively. By default the heap size is 64 megabytes.
image
The name of the image file to load. If omitted then the system default image is loaded.
script
The name of a script file containing Smalltalk code to be executed when the image is loaded. See the section 'SCRIPTS' below.
argument
Any arguments following the image or script name are passed to the Squeak environment and can be retrieved by the running Squeak image. See the section 'SCRIPTS' below.

Options relating to the display system are as follows:

-display dpy
Use the named X server display. Default is $DISPLAY.
-fullscreen
Run Squeak in fullscreen mode.
-geometry WxH[+X[+Y]]
Set the initial size and position of the Squeak window. For example: -geometry 800x600+10+10
-iconic
Start Squeak in an iconic (minimized) state.
-headless
Run without a graphical display. This is useful for batch processing or server applications.
-maximizewindow
Start Squeak with the window maximized.
-title string
Set the window title string.

Options relating to sound are as follows:

-nomixer
Disable the mixer. This option is intended for use on systems where mixer controls are problematic or unavailable. In such cases, Squeak will operate without any sound capabilities.
-nosound
Disable all sound input and output. This option is useful if you do not intend to use Squeak's sound capabilities or if you are experiencing problems with sound support.
-sounddev device
Use the specified sound device for audio input and output. The format of the device name depends on the sound system being used (e.g., ALSA, OSS). If this option is omitted, Squeak will attempt to use the system's default sound device.

If you prefer to leave sound configuration to your operating system's mixer program or sound control panel (they are, after all, really the responsibility of whichever mixer program or sound control panel you use), then this option is for you.

Options specific to the ALSA sound driver are as follows:

-capture device
Uses the named input device for sound capture.
-playback device
Uses the named output device for sound playback.

Several common options are deprecated and are provided only for backward compatibility. These options should not be used and will be removed in a future release:

-display dpy
is equivalent to '-vm display=X11 -display dpy'.
-headless
is equivalent to '-vm display=X11 -headless'.
-nodisplay
is equivalent to '-vm display=none'.
-nosound
is equivalent to '-vm sound=none'.
-quartz
is equivalent to '-vm display=Quartz'.

If an environment variable and a command-line option conflict over a particular value then normally the value in the command line takes precedence. The exception to this rule is the '-vm' option. squeak also checks the environment for LC_ALL and LC_CTYPE. If either of these variables is set then support for international keyboards (including dead keys for diacritical marks) is enabled. To prevent this support being enabled even when one or both of these variables is set, use the '-nointl' option (or set SQUEAK_NOINTL in the environment). For example, to start squeak with support for dead keys on Spanish keyboards, with Latin-1 encoding of external characters and the default MacRoman internal font encoding, run squeak like this:

export LC_CTYPE=es_ES
export SQUEAK_TEXTENC=latin1
squeak

SCRIPTS

Squeak can load and execute a 'script' file containing Smalltalk code at startup. The name of the file should be given as the script argument to squeak. For example, assuming that the image 'foo.image' contains an open Transcript window, then the following represents the 'hello world' program for Squeak:

Transcript cr; show: 'Hello, world'.

If this script is in a file called 'hello.sq', then it could be run like this:

squeak foo.image hello.sq

It is also possible to make 'self interpreting' scripts by adding an 'interpreter line' to the start of the script. The 'hello.sq' file could be changed to

#!/usr/bin/squeak --
Transcript cr; show: 'Hello, world'.

and then made executable with

chmod +x hello.sq

and then invoked by running the script file directly:

SQUEAK_IMAGE="foo.image"
export SQUEAK_IMAGE
./hello.sq

If any arguments are present after the script name then they can be retrieved from within the script using the method

Smalltalk getSystemAttribute: 
n

where n is the index of the argument, starting at 3 for the first argument. (See the method comment for

SystemDictionary>>getSystemAttribute:

in the image for an explanation of the meanings of the indices.)

As an example of this, here is the 'echo' program written as a Squeak script:

#!/usr/bin/squeak --
"Echo arguments to the Transcript."
| i a |
i := 2.
[(a := Smalltalk getSystemAttribute: (i := i + 1))
    notNil]
  whileTrue: [Transcript space; show: a].

When run as

./echo.sq one two three

this would print 'one two three' in the Transcript window.

DESCRIPTION

Squeak is an implementation of Smalltalk-80, which is a high-level, object-oriented, dynamic language. It includes a graphical user interface, and is often used for educational purposes, and in the creation of games and interactive applications. This package provides the Unix port of Squeak.

The Squeak system consists of two main parts:

  • The virtual machine (VM): written in C, this is the program that interprets the Squeak bytecode, interacts with the operating system, and provides access to the underlying hardware.
  • The image: this is a file containing the Squeak virtual machine's memory, including the Squeak system code, applications, and any saved objects. By convention, this file has the extension .image.

When Squeak is run, the virtual machine loads an image file (or creates a default one if none is specified) and executes the code within it. Changes made to the system are saved in a separate .changes file.

The inisqueak script is a helper utility that simplifies the process of copying the bundled system sources and image files to the user's home directory, and prompts the user to make private copies of the image and changes files, which should always be made before running squeak for the first time. See inisqueak(1)).

INVOCATION

The squeak command executes the Squeak virtual machine. If an imagefile argument is provided, it will be loaded. If no argument is provided, the default image file (usually ~/.squeak/username.image) is loaded.

The inisqueak command is used to initialize a user's Squeak environment. It copies the default system files (sources, image, and changes) to the user's home directory and prompts the user to make private copies of the image and changes files. It is recommended that this script be run before the first invocation of squeak.

OPTIONS

Command line options are passed directly to the Squeak virtual machine. Consult the Squeak documentation for a complete list of options. Commonly used options include:

-memory size
Set the size of the Squeak memory heap.
-heap size
Synonym for -memory.
-nodisplay
Run Squeak without a graphical display (e.g., for server-side operations).
-headless
Synonym for -nodisplay.
-vmpath path
Specify the path to the virtual machine executable.
-plugins path
Specify a directory containing plugin libraries.

ENVIRONMENT

SQUEAK_VM
If set, this environment variable specifies the path to the Squeak virtual machine executable. This is overridden by the -vmpath command line option.
SQUEAK_PLUGINS
If set, this environment variable specifies a directory containing plugin libraries. This is overridden by the -plugins command line option.
SQUEAK_DISPLAY
Specifies the X display to use. Defaults to the value of the DISPLAY environment variable.
SQUEAK_SCREEN_NUMBER
Specifies the screen number to use. Defaults to 0.

SCRIPTS

The following scripts are installed:

~/.squeak/username.image
~/.squeak/username.changes

Default image and changes files for the user. The inisqueak(1) script will create these. Private copies should always be made before running squeak for the first time. See inisqueak(1)).

./SqueakV4.sources

A link to the system sources file.

./name.image
./name.changes

Private copies of image and changes files.

/usr/lib/squeak/4.10.2-2614/*.so
/usr/lib/squeak/4.10.2-2614/*.la

Virtual machine 'plugins' (containing primitives that are loaded on demand) and drivers (for different types of display and sound hardware).

/usr/bin/squeak
/usr/bin/inisqueak

The Squeak virtual machine and personal image installer script.

/usr/man/man1/squeak.1

This manual page.

/usr/share/doc/squeak-4.10.2-2614/*

Miscellaneous documentation.

NOTES

This manual page documents version 4.10.2-2614 of Unix Squeak. It may not be appropriate for any other version.

The image and changes files containing a saved Squeak session are intimately related. They should always be used together, never be separated, and under no circumstances should an image be run with a changes file that has been used with a different image. Failure to adhere to the above could cause the source code for the methods in the image to become garbled and impossible to retrieve.

The Unix Squeak virtual machine fully supports OpenGL in both the X11 and Quartz display drivers. Open Croquet will run just fine with either of these drivers (and many Mac OS X users will even have the choice of which driver to use :).

BUGS

If a 'binary' option is enabled by an environment variable, there is no way to disable it on the command line.

Similarly, drivers specified in the SQUEAK_VM environment variable cannot be overridden by passing options on the command line.

squeak should never crash. In the unlikely event that it does crash, or prints any kind of message that does not appear to be caused by incorrect arguments or illegal operations from within a Squeak program, please send a bug report to: <ian.piumarta@squeakland.org>. (Do not send bug reports to the general-purpose 'squeak-dev' mailing list. They will not be read. If you feel you must post a bug report to a mailing list, send it to the Squeak 'vm-dev' mailing list in addition to the above email address.)
