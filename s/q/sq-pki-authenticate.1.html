NOMBRE

sq-pki-authenticate - Autenticar una vinculación

SINOPSIS

sq pki authenticate [OPCIONES]

DESCRIPCIÓN

Autenticar una vinculación.

Autentica una vinculación (un certificado y un ID de usuario) buscando un camino desde las raíces de confianza hasta la vinculación especificada en la Red de Confianza. Debido a que las certificaciones pueden expresar incertidumbre (es decir, las certificaciones pueden marcarse como que solo transmiten confianza parcial o marginal), pueden ser necesarios múltiples caminos.

Se devuelve un error si no se pudo autenticar ninguna vinculación al nivel especificado (por defecto: autenticado completamente, es decir, una cantidad de confianza de 120).

Si se encuentran caminos válidos hacia la vinculación, se imprimen en la salida estándar, independientemente de si son suficientes para autenticar la vinculación o no.

OPCIONES

Opciones de subcomando

--amount=CANTIDAD
La cantidad de confianza requerida
120 indica autenticación completa; valores menores a 120 indican autenticación parcial. Cuando se pasa `--certification-network`, esto predetermina a 1200, es decir, este comando intenta encontrar 10 caminos.
--cert=HUELLA_DIGITAL|ID_CLAVE
Utilizar certificados con la huella digital o el ID de clave especificado
--certification-network
Trata la red como una red de certificación
Normalmente, la maquinaria de autenticación trata la red de la Red de Confianza como una red de autenticación donde una certificación solo significa que la vinculación es correcta, no que el objetivo debe ser tratado como un introductor de confianza. En una red de certificación, los objetivos de las certificaciones son tratados como introductores de confianza con profundidad infinita, y se ignoran las expresiones regulares. Nota: La cantidad de confianza permanece sin cambios. Así es como funcionan la mayoría de los algoritmos de búsqueda de caminos de PGP.
--email=CORREO_ELECTRONICO
Autenticar la dirección de correo electrónico especificada
Esto comprueba si es posible autenticar un ID de usuario con la dirección de correo electrónico especificada. Los IDs de usuario no necesitan ser autocertificados. Para autenticar un ID de usuario que contiene solo la dirección de correo electrónico especificada, use `--userid <CORREO_ELECTRONICO>`.
--gossip
Trata todos los certificados como raíces de confianza poco fiables
Esta opción es útil para averiguar qué piensan los demás sobre un certificado (es decir, chismes o rumores). En otras palabras, esto encuentra caminos arbitrarios hacia un certificado particular.
El chisme es útil para identificar formas alternativas de autenticar un certificado. Por ejemplo, imagina que Ed quiere autenticar el certificado de Laura, pero preguntarle directamente es inconveniente. Ed descubre que Micah ha certificado el certificado de Laura, pero Ed aún no ha autenticado el certificado de Micah. Si Ed está dispuesto a confiar en Micah como un introductor de confianza, y autenticar el certificado de Micah es más fácil que autenticar el certificado de Laura, entonces Ed ha aprendido una forma más fácil de autenticar el certificado de Laura.
Estable desde 1.1.0.
--show-paths
Mostrar por qué una vinculación está autenticada
Por defecto, solo se muestra el grado de autenticación de un ID de usuario y vinculación de certificado (un valor entre 0 y 120). Esto cambia la salida para mostrar también cómo se calculó ese valor, mostrando los caminos desde las raíces de confianza hasta las vinculaciones.
--unusable
Mostrar vinculaciones que no son utilizables
Normalmente, los certificados y vinculaciones no utilizables no se muestran. Esta opción considera vinculaciones, incluso si no son inutilizables, porque (o los certificados) no son válidos según la política, están revocados o no están activos.
Esta opción solo tiene sentido con `--gossip`, porque las vinculaciones inutilizables todavía se consideran no autenticadas.
Estable desde 1.1.0.
--userid=ID_USUARIO
Autenticar el ID de usuario especificado
El ID de usuario especificado no necesita ser autocertificado.

Opciones globales

Vea sq(1) para una descripción de las opciones globales.

EJEMPLOS

Autenticar una vinculación específica.

sq pki authenticate --cert \
EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --userid \
"Alice <alice@example.org>"

Comprobar si podemos autenticar cualquier ID de usuario con la dirección de correo electrónico especificada para el certificado dado.

sq pki authenticate --cert \
EB28F26E2739A4870ECC47726F0073F60FD0CBF0 --email \
alice@example.org
