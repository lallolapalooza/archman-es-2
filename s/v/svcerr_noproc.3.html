rpc(3) Manual de Funciones de Biblioteca rpc(3)

NOMBRE

rpc - rutinas de biblioteca para llamadas a procedimientos remotos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS Y DESCRIPCIÓN

Estas rutinas permiten a los programas C realizar llamadas a procedimientos en otras máquinas a través de la red. Primero, el cliente llama a un procedimiento para enviar un paquete de datos al servidor. Al recibir el paquete, el servidor llama a una rutina de distribución para realizar el servicio solicitado y luego envía una respuesta. Finalmente, la llamada al procedimiento retorna al cliente.

Para utilizar estas rutinas, incluya el archivo de cabecera <rpc/rpc.h>.

Los prototipos a continuación hacen uso de los siguientes tipos:

typedef int bool_t;
typedef typeof(bool_t (XDR *, void *, ...))  *xdrproc_t;
typedef typeof(bool_t (caddr_t resp, struct sockaddr_in *raddr)
    *resultproc_t;

Consulte los archivos de cabecera para ver las declaraciones de los tipos AUTH, CLIENT, SVCXPRT y XDR.

void auth_destroy(AUTH *auth);
Una macro que destruye la información de autenticación asociada con auth. La destrucción generalmente implica la desasignación de estructuras de datos privadas. El uso de auth no está definido después de llamar a auth_destroy().
AUTH *authnone_create(void);
Crea y devuelve un manejador de autenticación RPC que pasa información de autenticación no utilizable con cada llamada a procedimiento remoto. Esta es la autenticación predeterminada utilizada por RPC.
AUTH *authunix_create(char *host, uid_t uid, gid_t gid,
                      int n, gid_t aup_gids[n]);
Crea y devuelve un manejador de autenticación RPC que contiene información de autenticación. El parámetro host es el nombre de la máquina en la que se creó la información; uid es el ID de usuario del usuario; gid es el ID de grupo actual del usuario; n y aup_gids se refieren a una matriz contada de grupos a los que pertenece el usuario. Es fácil suplantar a un usuario.
AUTH *authunix_create_default(void);
Llama a authunix_create() con los parámetros apropiados.
int callrpc(char *host, unsigned long prognum,
            unsigned long versnum, unsigned long procnum,
            xdrproc_t inproc, const char *in,
            xdrproc_t outproc, char *out);
Llama al procedimiento remoto asociado con prognum, versnum y procnum en la máquina host. El parámetro in es la dirección del (los) argumento(s) del procedimiento, y out es la dirección donde colocar el (los) resultado(s); inproc se utiliza para codificar los parámetros del procedimiento, y outproc se utiliza para decodificar los resultados del procedimiento. Esta rutina devuelve cero si tiene éxito, o el valor de enum clnt_stat convertido a entero si falla. La rutina clnt_perrno() es útil para traducir estados de error a mensajes.
Advertencia: llamar a procedimientos remotos con esta rutina utiliza UDP/IP como transporte; consulte clntudp_create() para ver las restricciones. No tiene control sobre los tiempos de espera o la autenticación usando esta rutina.
enum clnt_stat clnt_broadcast(unsigned long prognum,
                     unsigned long versnum, unsigned long procnum,
                     xdrproc_t inproc, char *in,
                     xdrproc_t outproc, char *out,
                     resultproc_t eachresult);
Similar a callrpc(), excepto que el mensaje de llamada se difunde a todas las redes de difusión conectadas localmente. Cada vez que recibe una respuesta, esta rutina llama a eachresult(), cuya forma es:

eachresult(char *out, struct sockaddr_in *addr);

donde out es el mismo que out pasado a clnt_broadcast(), excepto que la salida del procedimiento remoto se decodifica allí; addr apunta a la dirección de la máquina que envió los resultados. Si eachresult() devuelve cero, clnt_broadcast() espera más respuestas; de lo contrario, retorna con el estado apropiado.
Advertencia: los sockets de difusión están limitados en tamaño a la unidad de transferencia máxima del enlace de datos. Para ethernet, este valor es de 1500 bytes.
enum clnt_stat clnt_call(CLIENT *clnt, unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout);
Una macro que llama al procedimiento remoto procnum asociado con el manejador del cliente, clnt, que se obtiene con una rutina de creación de cliente RPC como clnt_create(). El parámetro in es la dirección del (los) argumento(s) del procedimiento, y out es la dirección donde colocar el (los) resultado(s); inproc se utiliza para codificar los parámetros del procedimiento, y outproc se utiliza para decodificar los resultados del procedimiento; tout es el tiempo permitido para que regresen los resultados.
clnt_destroy(CLIENT *clnt);
Una macro que destruye el manejador RPC del cliente. La destrucción generalmente implica la desasignación de estructuras de datos privadas, incluyendo clnt en sí. El uso de clnt no está definido después de llamar a clnt_destroy(). Si la biblioteca RPC abrió el socket asociado, también lo cerrará. De lo contrario, el socket permanecerá abierto.
CLIENT *clnt_create(const char *host, unsigned long prog,
                    unsigned long vers, const char *proto);
Rutina genérica de creación de cliente. host identifica el nombre del host remoto donde se encuentra el servidor. proto indica qué tipo de protocolo de transporte usar. Los valores actualmente admitidos para este campo son “udp” y “tcp”. Se establecen tiempos de espera predeterminados, pero se pueden modificar usando clnt_control().
Advertencia: usar UDP tiene sus inconvenientes. Dado que los mensajes RPC basados en UDP solo pueden contener hasta 8 Kbytes de datos codificados, este transporte no se puede usar para procedimientos que toman argumentos grandes o devuelven resultados enormes.
bool_t clnt_control(CLIENT *cl, int req, char *info);
Una macro utilizada para cambiar o recuperar diversa información sobre un objeto cliente. req indica el tipo de operación y info es un puntero a la información. Tanto para UDP como para TCP, los valores admitidos de req y sus tipos de argumento y lo que hacen son:

CLSET_TIMEOUT  struct timeval // establecer tiempo de espera total
CLGET_TIMEOUT  struct timeval // obtener tiempo de espera total

Nota: si establece el tiempo de espera usando clnt_control(), el parámetro de tiempo de espera pasado a clnt_call() se ignorará en todas las llamadas futuras.

CLGET_SERVER_ADDR  struct sockaddr_in
                // obtener dirección del servidor

Las siguientes operaciones son válidas solo para UDP:

CLSET_RETRY_TIMEOUT  struct timeval // establecer tiempo de espera de reintento
CLGET_RETRY_TIMEOUT  struct timeval // obtener tiempo de espera de reintento

El tiempo de espera de reintento es el tiempo que "UDP RPC" espera la respuesta del servidor antes de retransmitir la solicitud.
clnt_freeres(CLIENT * clnt, xdrproc_t outproc, char *out);
Una macro que libera cualquier dato asignado por el sistema RPC/XDR al decodificar los resultados de una llamada RPC. El parámetro out es la dirección de los resultados y outproc es la rutina XDR que describe los resultados. Esta rutina devuelve uno si los resultados se liberaron correctamente y cero en caso contrario.

Client creation Several routines are provided for creating client handles. CLIENT * clnt_create(const char *host, unsigned long prognum, unsigned long versnum, const char *proto); This routine creates an RPC client handle for the remote program prognum, version versnum, by contacting the specified program on the specified host using the specified transport proto. The supported transport protocols are "udp" and "tcp". If the remote machine's portmapper cannot be contacted, or if the desired program and version cannot be found, then clnt_create returns NULL. In this case, the global variable rpc_createerr contains the RPC status. CLIENT * clnt_create_rdma(const char *host, unsigned long prognum, unsigned long versnum, const char *proto); This routine creates an RPC client handle for the remote program prognum, version versnum, by contacting the specified program on the specified host using the specified transport proto. The supported transport protocols are "udp" and "tcp". If the remote machine's portmapper cannot be contacted, or if the desired program and version cannot be found, then clnt_create returns NULL. In this case, the global variable rpc_createerr contains the RPC status.
Error reporting The following routines are provided for reporting RPC errors. void clnt_err(CLIENT *rpch); A macro that returns the error code for the last RPC error that occurred on the client handle rpch. void clnt_geterr(CLIENT *errp); A macro that copies the error structure out of the client handle to the structure at address errp. void clnt_pcreateerror(const char *s); Print a message to standard error indicating why a client RPC handle could not be created. The message is prepended with string s and a colon. Used when a clnt_create(), clntraw_create(), clnttcp_create(), or clntudp_create() call fails. void clnt_perrno(enum clnt_stat stat); Print a message to standard error corresponding to the condition indicated by stat. Used after callrpc(). clnt_perror(CLIENT *clnt, const char *s); Print a message to standard error indicating why an RPC call failed; clnt is the handle used to do the call. The message is prepended with string s and a colon. Used after clnt_call(). char * clnt_spcreateerror(const char *s); Like clnt_pcreateerror(), except that it returns a string instead of printing to the standard error. Bugs: returns pointer to static data that is overwritten on each call. char * clnt_sperrno(enum clnt_stat stat); Take the same arguments as clnt_perrno(), but instead of sending a message to the standard error indicating why an RPC call failed, return a pointer to a string which contains the message. The string ends with a NEWLINE. clnt_sperrno() is used instead of clnt_perrno() if the program does not have a standard error (as a program running as a server quite likely does not), or if the programmer does not want the message to be output with printf(3), or if a message format different than that supported by clnt_perrno() is to be used. Note: unlike clnt_sperror() and clnt_spcreateerror(), clnt_sperrno() returns pointer to static data, but the result will not get overwritten on each call. char * clnt_sperror(CLIENT *rpch, const char *s); Like clnt_perror(), except that (like clnt_sperrno()) it returns a string instead of printing to standard error. Bugs: returns pointer to static data that is overwritten on each call.
Transport-specific creation routines CLIENT * clntraw_create(unsigned long prognum, unsigned long versnum); This routine creates a toy RPC client for the remote program prognum, version versnum. The transport used to pass messages to the service is actually a buffer within the process's address space, so the corresponding RPC server should live in the same address space; see svcraw_create(). This allows simulation of RPC and acquisition of RPC overheads, such as round trip times, without any kernel interference. This routine returns NULL if it fails. CLIENT * clnttcp_create(struct sockaddr_in *addr, unsigned long prognum, unsigned long versnum, int *sockp, unsigned int sendsz, unsigned int recvsz); This routine creates an RPC client for the remote program prognum, version versnum; the client uses TCP/IP as a transport. The remote program is located at Internet address *addr. If addr->sin_port is zero, then it is set to the actual port that the remote program is listening on (the remote portmap service is consulted for this information). The parameter sockp is a socket; if it is RPC_ANYSOCK, then this routine opens a new one and sets sockp. Since TCP-based RPC uses buffered I/O, the user may specify the size of the send and receive buffers with the parameters sendsz and recvsz; values of zero choose suitable defaults. This routine returns NULL if it fails. CLIENT * clntudp_create(struct sockaddr_in *addr, unsigned long prognum, unsigned long versnum, struct timeval wait, int *sockp); This routine creates an RPC client for the remote program prognum, version versnum; the client uses use UDP/IP as a transport. The remote program is located at Internet address addr. If addr->sin_port is zero, then it is set to actual port that the remote program is listening on (the remote portmap service is consulted for this information). The parameter sockp is a socket; if it is RPC_ANYSOCK, then this routine opens a new one and sets sockp. The UDP transport resends the call message in intervals of wait time until a response is received or until the call times out. The total time for the call to time out is specified by clnt_call(). since UDP-based RPC messages can hold only up to 8 Kbytes of encoded data, this transport cannot be used for procedures that take large arguments or return huge results. CLIENT * clntudp_bufcreate(struct sockaddr_in *addr, unsigned long prognum, unsigned long versnum, struct timeval wait, int *sockp, unsigned int sendsize, unsigned int recosize); This routine creates an RPC client for the remote program prognum, on versnum; the client uses use UDP/IP as a transport. The remote program is located at Internet address addr. If addr->sin_port is zero, then it is set to actual port that the remote program is listening on (the remote portmap service is consulted for this information). The parameter sockp is a socket; if it is RPC_ANYSOCK, then this routine opens a new one and sets sockp. The UDP transport resends the call message in intervals of wait time until a response is received or until the call times out. The total time for the call to time out is specified by clnt_call(). This allows the user to specify the maximum packet size for sending and receiving UDP-based RPC messages.
Portmapper interface void get_myaddress(struct sockaddr_in *addr); Stuff the machine's IP address into *addr, without consulting the library routines that deal with /etc/hosts. The port number is always set to htons(PMAPPORT). struct pmaplist * pmap_getmaps(struct sockaddr_in *addr); A user interface to the portmap service, which returns a list of the current RPC program-to-port mappings on the host located at IP address *addr. This routine can return NULL. The command rpcinfo -p uses this routine. unsigned short pmap_getport(struct sockaddr_in *addr, unsigned long prognum, unsigned long versnum, unsigned int protocol); A user interface to the portmap service, which returns the port number on which waits a service that supports program number prognum, version versnum, and speaks the transport protocol associated with protocol. The value of protocol is most likely IPPROTO_UDP or IPPROTO_TCP. A return value of zero means that the mapping does not exist or that the RPC system failed to contact the remote portmap service. In the latter case, the global variable rpc_createerr contains the RPC status. enum clnt_stat pmap_rmtcall(struct sockaddr_in *addr, unsigned long prognum, unsigned long versnum, unsigned long procnum, xdrproc_t inproc, char *in, xdrproc_t outproc, char *out, struct timeval tout, unsigned long *portp); A user interface to the portmap service, which instructs portmap on the host at IP address *addr to make an RPC call on your behalf to a procedure on that host. The parameter *portp will be modified to the program's port number if the procedure succeeds. The definitions of other parameters are discussed in callrpc() and clnt_call(). This procedure should be used for a “ping” and nothing else. See also clnt_broadcast(). bool_t pmap_set(unsigned long prognum, unsigned long versnum, int protocol, unsigned short port); A user interface to the portmap service, which establishes a mapping between the triple [prognum,versnum,protocol] and port on the machine's portmap service. The value of protocol is most likely IPPROTO_UDP or IPPROTO_TCP. This routine returns one if it succeeds, zero otherwise. Automatically done by svc_register(). bool_t pmap_unset(unsigned long prognum, unsigned long versnum); A user interface to the portmap service, which destroys all mapping between the triple [prognum,versnum,*] and ports on the machine's portmap service. This routine returns one if it succeeds, zero otherwise.

If a request arrives for program prognum, version versnum, and procedure procnum, procname is called with a pointer to its parameter(s); procname should return a pointer to its static result(s); inproc is used to decode the parameters while outproc is used to encode the results. This routine returns zero if the registration succeeded, -1 otherwise. remote procedures registered in this form are accessed using the UDP/IP tra
nsport; véase svcudp_create() para restricciones. 
struct rpc_createerr rpc_createerr;
Una variable global cuyo valor es establecido por cualquier rutina de creación de cliente RPC que no tenga éxito. Utilice la rutina clnt_pcreateerror() para imprimir la razón.
void svc_destroy(SVCXPRT *xprt);
Una macro que destruye el manejador de transporte del servicio RPC, xprt. La destrucción generalmente implica la desasignación de estructuras de datos privadas, incluyendo xprt mismo. El uso de xprt no está definido después de llamar a esta rutina.
fd_set svc_fdset;
Una variable global que refleja la máscara de bits del descriptor de archivo de lectura del lado del servicio RPC; es adecuada como parámetro para la llamada al sistema select(2). Esto solo interesa si un implementador de servicio realiza su propio procesamiento de eventos asíncronos, en lugar de llamar a svc_run(). Esta variable es de solo lectura (¡no pase su dirección a select(2)!), sin embargo, puede cambiar después de las llamadas a svc_getreqset() o cualquier rutina de creación.
int svc_fds;
Similar a svc_fdset, pero limitado a 32 descriptores de archivo. Esta interfaz está obsoleta por svc_fdset.
svc_freeargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);
Una macro que libera cualquier dato asignado por el sistema RPC/XDR cuando decodificó los argumentos de un procedimiento de servicio usando svc_getargs(). Esta rutina devuelve 1 si los resultados se liberaron con éxito y cero en caso contrario.
svc_getargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);
Una macro que decodifica los argumentos de una solicitud RPC asociada con el manejador de transporte del servicio RPC, xprt. El parámetro in es la dirección donde se colocarán los argumentos; inproc es la rutina XDR utilizada para decodificar los argumentos. Esta rutina devuelve uno si la decodificación tiene éxito y cero en caso contrario.
struct sockaddr_in *svc_getcaller(SVCXPRT *xprt);
La forma aprobada de obtener la dirección de red del llamador de un procedimiento asociado con el manejador de transporte del servicio RPC, xprt.
void svc_getreqset(fd_set *rdfds);
Esta rutina solo interesa si un implementador de servicio no llama a svc_run(), sino que implementa procesamiento de eventos asíncronos personalizado. Se llama cuando la llamada al sistema select(2) ha determinado que ha llegado una solicitud RPC en algún(os) socket(s) RPC; rdfds es la máscara de bits resultante del descriptor de archivo de lectura. La rutina regresa cuando todos los sockets asociados con el valor de rdfds han sido atendidos.
void svc_getreq(int rdfds);
Similar a svc_getreqset(), pero limitado a 32 descriptores de archivo. Esta interfaz está obsoleta por svc_getreqset().
bool_t svc_register(SVCXPRT *xprt, unsigned long prognum,
                    unsigned long versnum,
                    typeof(void (struct svc_req *, SVCXPRT *)) *dispatch,
                    unsigned long protocol);
Asocia prognum y versnum con el procedimiento de despacho del servicio, dispatch. Si protocol es cero, el servicio no se registra con el servicio portmap. Si protocol no es cero, entonces se establece un mapeo del triple [prognum,versnum,protocol] a xprt->xp_port con el servicio portmap local (generalmente protocol es cero, IPPROTO_UDP o IPPROTO_TCP). El procedimiento dispatch tiene la siguiente forma:

dispatch(struct svc_req *request, SVCXPRT *xprt);

La rutina svc_register() devuelve uno si tiene éxito y cero en caso contrario.
void svc_run(void);
Esta rutina nunca regresa. Espera a que lleguen solicitudes RPC y llama al procedimiento de servicio apropiado usando svc_getreq() cuando llega una. Este procedimiento generalmente espera a que una llamada al sistema select(2) regrese.
bool_t svc_sendreply(SVCXPRT *xprt, xdrproc_t outproc, char *out);
Llamada por la rutina de despacho de un servicio RPC para enviar los resultados de una llamada a procedimiento remoto. El parámetro xprt es el manejador de transporte asociado con la solicitud; outproc es la rutina XDR que se utiliza para codificar los resultados; y out es la dirección de los resultados. Esta rutina devuelve uno si tiene éxito y cero en caso contrario.
void svc_unregister(unsigned long prognum, unsigned long versnum);
Elimina todos los mapeos del doble [prognum,versnum] a procedimientos de despacho, y del triple [prognum,versnum,*] a número de puerto.
void svcerr_auth(SVCXPRT *xprt, enum auth_stat why);
Llamada por una rutina de despacho de servicio que se niega a realizar una llamada a procedimiento remoto debido a un error de autenticación.
void svcerr_decode(SVCXPRT *xprt);
Llamada por una rutina de despacho de servicio que no puede decodificar sus parámetros con éxito. Ver también svc_getargs().
void svcerr_noproc(SVCXPRT *xprt);
Llamada por una rutina de despacho de servicio que no implementa el número de procedimiento que solicita el llamador.
void svcerr_noprog(SVCXPRT *xprt);
Se llama cuando el programa deseado no está registrado con el paquete RPC. Los implementadores de servicio generalmente no necesitan esta rutina.
void svcerr_progvers(SVCXPRT *xprt, unsigned long low_vers,
                     unsigned long high_vers);
Se llama cuando la versión deseada de un programa no está registrada con el paquete RPC. Los implementadores de servicio generalmente no necesitan esta rutina.
void svcerr_systemerr(SVCXPRT *xprt);
Llamada por una rutina de despacho de servicio cuando detecta un error del sistema no cubierto por ningún protocolo particular. Por ejemplo, si un servicio ya no puede asignar almacenamiento, puede llamar a esta rutina.
void svcerr_weakauth(SVCXPRT *xprt);
Llamada por una rutina de despacho de servicio que se niega a realizar una llamada a procedimiento remoto debido a parámetros de autenticación insuficientes. La rutina llama a svcerr_auth(xprt, AUTH_TOOWEAK).
SVCXPRT *svcfd_create(int fd, unsigned int sendsize,
                      unsigned int recvsize);
Crea un servicio sobre cualquier descriptor de archivo abierto. Típicamente, este descriptor de archivo es un socket conectado para un protocolo de flujo como TCP. sendsize y recvsize indican los tamaños para los búferes de envío y recepción. Si son cero, se elige un valor predeterminado razonable.
SVCXPRT *svcraw_create(void);
Esta rutina crea un transporte de servicio RPC de juguete, al que devuelve un puntero. El transporte es en realidad un búfer dentro del espacio de direcciones del proceso, por lo que el cliente RPC correspondiente debe residir en el mismo espacio de direcciones; ver clntraw_create(). Esta rutina permite simular RPC y adquirir sobrecargas RPC (como tiempos de ida y vuelta), sin ninguna interferencia del kernel. Esta rutina devuelve NULL si falla.
SVCXPRT *svctcp_create(int sock, unsigned int send_buf_size,
                       unsigned int recv_buf_size);
Esta rutina crea un transporte de servicio RPC basado en TCP/IP, al que devuelve un puntero. El transporte está asociado con el socket sock, que puede ser RPC_ANYSOCK, en cuyo caso se crea un nuevo socket. Si el socket no está enlazado a un puerto TCP local, esta rutina lo enlaza a un puerto arbitrario. Al completarse, xprt->xp_sock es el descriptor del socket del transporte, y xprt->xp_port es el número de puerto del transporte. Esta rutina devuelve NULL si falla. Dado que RPC basado en TCP utiliza E/S en búfer, los usuarios pueden especificar el tamaño de los búferes; los valores de cero eligen predeterminados adecuados.
SVCXPRT *svcudp_bufcreate(int sock, unsigned int sendsize,
                          unsigned int recosize);
Esta rutina crea un transporte de servicio RPC basado en UDP/IP, al que devuelve un puntero. El transporte está asociado con el socket sock, que puede ser RPC_ANYSOCK, en cuyo caso se crea un nuevo socket. Si el socket no está enlazado a un puerto UDP local, esta rutina lo enlaza a un puerto arbitrario. Al completarse, xprt->xp_sock es el descriptor del socket del transporte, y xprt->xp_port es el número de puerto del transporte. Esta rutina devuelve NULL si falla.
Esto permite al usuario especificar el tamaño máximo de paquete para enviar y recibir mensajes RPC basados en UDP.
SVCXPRT *svcudp_create(int sock);
Esta llamada es equivalente a svcudp_bufcreate(sock,SZ,SZ) para algún tamaño predeterminado SZ.
bool_t xdr_accepted_reply(XDR *xdrs, struct accepted_reply *ar);
Se utiliza para codificar mensajes de respuesta RPC. Esta rutina es útil para usuarios que desean generar mensajes de estilo RPC sin utilizar el paquete RPC.
bool_t xdr_authunix_parms(XDR *xdrs, struct authunix_parms *aupp);
Se utiliza para describir credenciales de UNIX. Esta rutina es útil para usuarios que desean generar estas credenciales sin utilizar el paquete de autenticación RPC.
void xdr_callhdr(XDR *xdrs, struct rpc_msg *chdr);
Se utiliza para describir mensajes de encabezado de llamada RPC. Esta rutina es útil para usuarios que desean generar mensajes de estilo RPC sin utilizar el paquete RPC.

Genera un mensaje de error de procedimiento no válido. El manejador de
      transporte RPC llama a esta rutina cuando se invoca un procedimiento que
      no está registrado para un programa RPC dado.




void svcerr_progvers(XDR *xdrs);



  

  
Genera un mensaje de error de versión de programa no válido. El manejador
      de transporte RPC llama a esta rutina cuando se invoca un procedimiento
      con una versión de programa no válida.




void svcerr_systemerr(XDR *xdrs);



  

  
Genera un mensaje de error del sistema. El manejador de transporte RPC
      llama a esta rutina cuando ocurre un error interno.




void svcerr_decode(XDR *xdrs);



  

  
Genera un mensaje de error de decodificación. El manejador de transporte
      RPC llama a esta rutina cuando no puede decodificar los argumentos de
      llamada.




void svcerr_auth(XDR *xdrs);



  

  
Genera un mensaje de error de autenticación. El manejador de transporte
      RPC llama a esta rutina cuando falla la autenticación de un cliente.




void svcerr_weakauth(XDR *xdrs);



  

  
Genera un mensaje de error de autenticación débil. El manejador de
      transporte RPC llama a esta rutina cuando un cliente intenta usar un tipo
      de autenticación débil.




void svcerr_noprog(XDR *xdrs);



  

  
Genera un mensaje de error de programa no válido. El manejador de
      transporte RPC llama a esta rutina cuando se invoca un programa RPC que no
      está registrado.




bool_t xdr_callmsg(XDR *xdrs, struct rpc_msg *cmsg);



  

  
Se utiliza para describir mensajes de llamada RPC. Esta rutina es útil para
      los usuarios que desean generar mensajes de estilo RPC sin utilizar el
      paquete RPC.




bool_t xdr_opaque_auth(XDR *xdrs, struct opaque_auth *ap);



  

  
Se utiliza para describir mensajes de información de autenticación RPC.
      Esta rutina es útil para los usuarios que desean generar mensajes de estilo
      RPC sin utilizar el paquete RPC.




bool_t xdr_pmap(XDR *xdrs, struct pmap *regs);



  

  
Se utiliza para describir los parámetros de varios procedimientos
      de portmap, externamente. Esta rutina es útil para los usuarios que
      desean generar estos parámetros sin utilizar la interfaz
      pmap.




bool_t xdr_pmaplist(XDR *xdrs, struct pmaplist **rp);



  

  
Se utiliza para describir una lista de mapeos de puertos, externamente.
      Esta rutina es útil para los usuarios que desean generar estos parámetros
      sin utilizar la interfaz pmap.




bool_t xdr_rejected_reply(XDR *xdrs, struct rejected_reply *rr);



  

  
Se utiliza para describir mensajes de respuesta RPC. Esta rutina es útil para
      los usuarios que desean generar mensajes de estilo RPC sin utilizar el
      paquete RPC.




bool_t xdr_replymsg(XDR *xdrs, struct rpc_msg *rmsg);



  

  
Se utiliza para describir mensajes de respuesta RPC. Esta rutina es útil para
      los usuarios que desean generar mensajes de estilo RPC sin utilizar el
      paquete RPC.




void xprt_register(SVCXPRT *xprt);



  

  
Después de crear los manejadores de transporte del servicio RPC, deben
      registrarse en el paquete del servicio RPC. Esta rutina modifica la
      variable global svc_fds. Los implementadores de servicios
      generalmente no necesitan esta rutina.




void xprt_unregister(SVCXPRT *xprt);



  

  
Antes de destruir un manejador de transporte del servicio RPC, debe
      darse de baja en el paquete del servicio RPC. Esta rutina modifica la
      variable global svc_fds. Los implementadores de servicios
      generalmente no necesitan esta rutina.
