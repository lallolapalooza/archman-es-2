svnserve(8) Manual del Administrador del Sistema svnserve(8)

NOMBRE

svnserve - Servidor para el método de acceso al repositorio 'svn'

SINOPSIS

svnserve [opciones]

DESCRIPCIÓN

svnserve permite el acceso a repositorios de Subversion utilizando el protocolo de red svn. Puede ejecutarse como un proceso servidor independiente o puede ejecutarse a través de inetd. Debe elegir un modo de operación al iniciar svnserve. Se reconocen las siguientes opciones:

-d, --daemon
Hace que svnserve se ejecute en modo daemon. svnserve se ejecuta en segundo plano y acepta y sirve conexiones TCP/IP en el puerto svn (3690, por defecto).
--listen-port=puerto
Hace que svnserve escuche en el puerto cuando se ejecuta en modo daemon.
--listen-host=host
Hace que svnserve escuche en la interfaz especificada por host, que puede ser un nombre de host o una dirección IP.
--foreground
Cuando se utiliza junto con -d, esta opción hace que svnserve permanezca en primer plano. Esta opción es útil principalmente para la depuración.
-i, --inetd
Hace que svnserve utilice los descriptores de archivo stdin/stdout, como corresponde a un daemon que se ejecuta a través de inetd.
-h, --help
Muestra un resumen de uso y sale.
--version
Imprime la versión de svnserve y el/los backend(s) del sistema de archivos del repositorio que soporta una determinada instancia de svnserve.
-r root, --root=root
Establece la raíz virtual para los repositorios servidos por svnserve. La ruta en las URLs proporcionadas por el cliente se interpretará relativa a esta raíz y no se permitirá que escape de ella.
-R --read-only
Fuerza que todas las operaciones de escritura a través de esta instancia de svnserve estén prohibidas, anulando toda otra configuración de política de acceso. No utilice esta opción para establecer una política general de acceso al repositorio; para eso está el archivo de configuración del repositorio conf/svnserve.conf. Esta opción solo debe utilizarse para restringir el acceso a través de un método específico de invocación de svnserve; por ejemplo, para permitir el acceso de escritura a través de SSH, pero no a través de un daemon svnserve, o para crear una clave SSH restringida que solo sea capaz de acceso de solo lectura.
-t, --tunnel
Hace que svnserve se ejecute en modo túnel, que es igual al modo de operación inetd (servir una conexión sobre stdin/stdout) excepto que la conexión se considera preautenticada con el nombre de usuario del uid actual. Esta bandera es seleccionada por el cliente cuando se ejecuta a través de un agente de túnel.
--tunnel-user=nombre de usuario
Cuando se combina con --tunnel, anula el nombre de usuario preautenticado con el nombre de usuario proporcionado. Esto es útil en combinación con la directiva "command" del archivo authorized_key de ssh para permitir que una única cuenta de sistema sea utilizada por múltiples committers, cada uno con una identidad ssh distinta.
-T, --threads
Al ejecutarse en modo daemon, hace que svnserve genere un hilo en lugar de un proceso para cada conexión. El proceso svnserve aún se ejecuta en segundo plano al inicio.
--config-file=nombre de archivo
Cuando se especifica, svnserve lee nombre de archivo una vez al inicio del programa y almacena en caché la configuración de svnserve. Las configuraciones de contraseña y autorización a las que se hace referencia desde nombre de archivo se cargarán en cada conexión. svnserve no leerá ningún archivo conf/svnserve.conf por repositorio cuando se utilice esta opción. Consulte la página del manual svnserve.conf(5) para obtener detalles sobre el formato de archivo para esta opción.
--pid-file=nombre de archivo
Cuando se especifica, svnserve escribirá su ID de proceso en nombre de archivo.
-X, --listen-once
Hace que svnserve acepte una conexión en el puerto svn, la sirva y salga. Esta opción es útil principalmente para la depuración.

A menos que se haya especificado la opción --config-file en la línea de comandos, una vez que el cliente ha seleccionado un repositorio transmitiendo su URL, svnserve lee un archivo llamado conf/svnserve.conf en el directorio del repositorio para determinar la configuración específica del repositorio, como qué base de datos de autenticación utilizar y qué políticas de autorización aplicar. Consulte la página del manual svnserve.conf(5) para obtener detalles sobre el formato de ese archivo.

VER TAMBIÉN
