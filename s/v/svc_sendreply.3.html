rpc(3) Manual de Funciones de Biblioteca rpc(3)

NOMBRE

rpc - rutinas de biblioteca para llamadas a procedimientos remotos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS Y DESCRIPCIÓN

Estas rutinas permiten a los programas C realizar llamadas a procedimientos en otras máquinas a través de la red. Primero, el cliente llama a un procedimiento para enviar un paquete de datos al servidor. Al recibir el paquete, el servidor llama a una rutina de despacho para realizar el servicio solicitado y luego envía una respuesta. Finalmente, la llamada al procedimiento retorna al cliente.

Para utilizar estas rutinas, incluya el archivo de cabecera <rpc/rpc.h>.

Los prototipos a continuación hacen uso de los siguientes tipos:

typedef int bool_t;
typedef typeof(bool_t (XDR *, void *, ...))  *xdrproc_t;
typedef typeof(bool_t (caddr_t resp, struct sockaddr_in *raddr)
    *resultproc_t;

Consulte los archivos de cabecera para ver las declaraciones de los tipos AUTH, CLIENT, SVCXPRT y XDR.

void auth_destroy(AUTH *auth);
Una macro que destruye la información de autenticación asociada con auth. La destrucción generalmente implica la desasignación de estructuras de datos privadas. El uso de auth no está definido después de llamar a auth_destroy().
AUTH *authnone_create(void);
Crea y devuelve un manejador de autenticación RPC que pasa información de autenticación no utilizable con cada llamada a procedimiento remoto. Esta es la autenticación predeterminada utilizada por RPC.
AUTH *authunix_create(char *host, uid_t uid, gid_t gid,
                      int n, gid_t aup_gids[n]);
Crea y devuelve un manejador de autenticación RPC que contiene información de autenticación. El parámetro host es el nombre de la máquina en la que se creó la información; uid es el ID de usuario del usuario; gid es el ID de grupo actual del usuario; n y aup_gids se refieren a una matriz contada de grupos a los que pertenece el usuario. Es fácil suplantar a un usuario.
AUTH *authunix_create_default(void);
Llama a authunix_create() con los parámetros apropiados.
int callrpc(char *host, unsigned long prognum,
            unsigned long versnum, unsigned long procnum,
            xdrproc_t inproc, const char *in,
            xdrproc_t outproc, char *out);
Llama al procedimiento remoto asociado con prognum, versnum y procnum en la máquina host. El parámetro in es la dirección de los argumentos del procedimiento, y out es la dirección donde colocar los resultados; inproc se utiliza para codificar los parámetros del procedimiento, y outproc se utiliza para decodificar los resultados del procedimiento. Esta rutina devuelve cero si tiene éxito, o el valor de enum clnt_stat convertido a un entero si falla. La rutina clnt_perrno() es útil para traducir los estados de error en mensajes.
Advertencia: llamar a procedimientos remotos con esta rutina utiliza UDP/IP como transporte; consulte clntudp_create() para conocer las restricciones. No tiene control sobre los tiempos de espera o la autenticación utilizando esta rutina.
enum clnt_stat clnt_broadcast(unsigned long prognum,
                     unsigned long versnum, unsigned long procnum,
                     xdrproc_t inproc, char *in,
                     xdrproc_t outproc, char *out,
                     resultproc_t eachresult);
Similar a callrpc(), excepto que el mensaje de llamada se difunde a todas las redes de difusión locales conectadas. Cada vez que recibe una respuesta, esta rutina llama a eachresult(), cuya forma es:

eachresult(char *out, struct sockaddr_in *addr);

donde out es el mismo que out pasado a clnt_broadcast(), excepto que la salida del procedimiento remoto se decodifica allí; addr apunta a la dirección de la máquina que envió los resultados. Si eachresult() devuelve cero, clnt_broadcast() espera más respuestas; de lo contrario, retorna con el estado apropiado.
Advertencia: los sockets de difusión están limitados en tamaño a la unidad de transferencia máxima del enlace de datos. Para ethernet, este valor es de 1500 bytes.
enum clnt_stat clnt_call(CLIENT *clnt, unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout);
Una macro que llama al procedimiento remoto procnum asociado con el manejador del cliente, clnt, que se obtiene con una rutina de creación de cliente RPC como clnt_create(). El parámetro in es la dirección de los argumentos del procedimiento, y out es la dirección donde colocar los resultados; inproc se utiliza para codificar los parámetros del procedimiento, y outproc se utiliza para decodificar los resultados del procedimiento; tout es el tiempo permitido para que regresen los resultados.
clnt_destroy(CLIENT *clnt);
Una macro que destruye el manejador RPC del cliente. La destrucción generalmente implica la desasignación de estructuras de datos privadas, incluido el propio clnt. El uso de clnt no está definido después de llamar a clnt_destroy(). Si la biblioteca RPC abrió el socket asociado, también lo cerrará. De lo contrario, el socket permanece abierto.
CLIENT *clnt_create(const char *host, unsigned long prog,
                    unsigned long vers, const char *proto);
Rutina genérica de creación de cliente. host identifica el nombre del host remoto donde se encuentra el servidor. proto indica qué tipo de protocolo de transporte usar. Los valores actualmente soportados para este campo son “udp” y “tcp”. Se establecen tiempos de espera predeterminados, pero se pueden modificar usando clnt_control().
Advertencia: usar UDP tiene sus inconvenientes. Dado que los mensajes RPC basados en UDP solo pueden contener hasta 8 Kbytes de datos codificados, este transporte no se puede utilizar para procedimientos que toman argumentos grandes o devuelven resultados enormes.
bool_t clnt_control(CLIENT *cl, int req, char *info);
Una macro utilizada para cambiar o recuperar diversa información sobre un objeto cliente. req indica el tipo de operación, y info es un puntero a la información. Tanto para UDP como para TCP, los valores soportados de req y sus tipos de argumento y lo que hacen son:

CLSET_TIMEOUT  struct timeval // establecer tiempo de espera total
CLGET_TIMEOUT  struct timeval // obtener tiempo de espera total

Nota: si establece el tiempo de espera usando clnt_control(), el parámetro de tiempo de espera pasado a clnt_call() será ignorado en todas las llamadas futuras.

CLGET_SERVER_ADDR  struct sockaddr_in
                // obtener la dirección del servidor

Las siguientes operaciones son válidas solo para UDP:

CLSET_RETRY_TIMEOUT  struct timeval // establecer el tiempo de espera de reintento
CLGET_RETRY_TIMEOUT  struct timeval // obtener el tiempo de espera de reintento

El tiempo de espera de reintento es el tiempo que la "RPC UDP" espera la respuesta del servidor antes de retransmitir la solicitud.
clnt_freeres(CLIENT * clnt, xdrproc_t outproc, char *out);
Una macro que libera cualquier dato asignado por el sistema RPC/XDR al decodificar los resultados de una llamada RPC. El parámetro out es la dirección de los resultados, y outproc es la rutina XDR que describe los resultados. Esta rutina devuelve uno si los resultados se liberaron correctamente y cero en caso contrario.
void clnt_geterr(CLIENT *clnt, struct rpc_er

ror *errp);

Una macro que obtiene la información del último error de la llamada RPC desde el manejador del cliente clnt y la coloca en la estructura apuntada por errp.
char *clnt_sperrno(enum clnt_stat stat);
Devuelve un puntero a una cadena de caracteres que describe el estado de error RPC especificado por stat.
char *clnt_sperror(CLIENT *clnt);
Devuelve un puntero a una cadena de caracteres que describe el último error de la llamada RPC asociada con el manejador del cliente clnt.
enum clnt_stat clntudp_create(const char *host, unsigned long prog,
                     unsigned long vers, struct timeval routines,
                     int *sockp, u_int sendsz, u_int recvsz);
Crea un manejador de cliente RPC y lo asocia con una conexión UDP en el servidor especificado por host, prog, y vers. El parámetro routines especifica el tiempo de espera de las rutinas de transporte. Si sockp es distinto de NULL, indica un socket ya existente que se utilizará para la comunicación. Si es NULL, el procedimiento creará un nuevo socket. sendsz y recvsz especifican los tamaños de los búferes de envío y recepción para el socket.
Advertencia: debido a las limitaciones de los datagramas UDP, este transporte no se puede utilizar para procedimientos que toman argumentos grandes o devuelven resultados enormes.
enum clnt_stat clnttcp_create(const char *host, unsigned long prog,
                    unsigned long vers, struct timeval routines,
                    int *sockp, u_int sendsz, u_int recvsz);
Crea un manejador de cliente RPC y lo asocia con una conexión TCP en el servidor especificado por host, prog, y vers. El parámetro routines especifica el tiempo de espera de las rutinas de transporte. Si sockp es distinto de NULL, indica un socket ya existente que se utilizará para la comunicación. Si es NULL, el procedimiento creará un nuevo socket. sendsz y recvsz especifican los tamaños de los búferes de envío y recepción para el socket.
int registerrpc(unsigned long prognum, unsigned long versnum,
                unsigned long procnum, char *procname,
                xdrproc_t inproc, char *in,
                xdrproc_t outproc, char *out);
Registra una rutina de servicio RPC con el sistema RPC. prognum, versnum y procnum identifican el servicio. procname es un nombre para el servicio. inproc y outproc son las rutinas XDR para codificar y decodificar los argumentos y resultados, respectivamente. in y out son punteros a las estructuras de argumentos y resultados.
void svc_run(void);
Entra en un bucle infinito, esperando y procesando llamadas a servicio RPC entrantes. Esta rutina nunca retorna.

int rpc_createerr;
This global variable is used to communicate RPC errors from the library routines to the calling program. It is set when most RPC library routines fail. The error codes are defined by the enumeration clnt_stat.
void clnt_err(CLIENT *errp);
Una macro que copia la estructura de error del manejador del cliente a la estructura en la dirección errp.
void clnt_pcreateerror(const char *s);
Imprime un mensaje en la salida de error estándar indicando por qué no se pudo crear un manejador RPC de cliente. El mensaje se antepone con la cadena s y dos puntos. Se utiliza cuando una llamada a clnt_create(), clntraw_create(), clnttcp_create() o clntudp_create() falla.
void clnt_perrno(enum clnt_stat stat);
Imprime un mensaje en la salida de error estándar correspondiente a la condición indicada por stat. Se utiliza después de callrpc().
clnt_perror(CLIENT *clnt, const char *s);
Imprime un mensaje en la salida de error estándar indicando por qué falló una llamada RPC; clnt es el manejador utilizado para realizar la llamada. El mensaje se antepone con la cadena s y dos puntos. Se utiliza después de clnt_call().
char *clnt_spcreateerror(const char *s);
Igual que clnt_pcreateerror(), pero devuelve una cadena en lugar de imprimir en la salida de error estándar.
Errores: devuelve un puntero a datos estáticos que se sobrescriben en cada llamada.
char *clnt_sperrno(enum clnt_stat stat);
Toma los mismos argumentos que clnt_perrno(), pero en lugar de enviar un mensaje a la salida de error estándar indicando por qué falló una llamada RPC, devuelve un puntero a una cadena que contiene el mensaje. La cadena termina con una nueva línea.
clnt_sperrno() se utiliza en lugar de clnt_perrno() si el programa no tiene una salida de error estándar (como es muy probable que no la tenga un programa que se ejecuta como servidor), o si el programador no desea que el mensaje se genere con printf(3), o si se va a utilizar un formato de mensaje diferente al soportado por clnt_perrno(). Nota: a diferencia de clnt_sperror() y clnt_spcreateerror(), clnt_sperrno() devuelve un puntero a datos estáticos, pero el resultado no se sobrescribirá en cada llamada.
char *clnt_sperror(CLIENT *rpch, const char *s);
Igual que clnt_perror(), pero (como clnt_sperrno()) devuelve una cadena en lugar de imprimir en la salida de error estándar.
Errores: devuelve un puntero a datos estáticos que se sobrescriben en cada llamada.
CLIENT *clntraw_create(unsigned long prognum, unsigned long versnum);
Esta rutina crea un cliente RPC de juguete para el programa remoto prognum, versión versnum. El transporte utilizado para pasar mensajes al servicio es en realidad un búfer dentro del espacio de direcciones del proceso, por lo que el servidor RPC correspondiente debería vivir en el mismo espacio de direcciones; ver svcraw_create(). Esto permite simular RPC y obtener sobrecargas RPC, como los tiempos de ida y vuelta, sin ninguna interferencia del kernel. Esta rutina devuelve NULL si falla.
CLIENT *clnttcp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                int *sockp, unsigned int sendsz, unsigned int recvsz);
Esta rutina crea un cliente RPC para el programa remoto prognum, versión versnum; el cliente utiliza TCP/IP como transporte. El programa remoto se encuentra en la dirección de Internet *addr. Si addr->sin_port es cero, se establece en el puerto real en el que el programa remoto está escuchando (se consulta el servicio portmap remoto para obtener esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, esta rutina abre uno nuevo y establece sockp. Dado que RPC basado en TCP utiliza E/S en búfer, el usuario puede especificar el tamaño de los búferes de envío y recepción con los parámetros sendsz y recvsz; valores cero eligen los valores predeterminados adecuados. Esta rutina devuelve NULL si falla.
CLIENT *clntudp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                struct timeval wait, int *sockp);
Esta rutina crea un cliente RPC para el programa remoto prognum, versión versnum; el cliente utiliza UDP/IP como transporte. El programa remoto se encuentra en la dirección de Internet addr. Si addr->sin_port es cero, se establece en el puerto real en el que el programa remoto está escuchando (se consulta el servicio portmap remoto para obtener esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, esta rutina abre uno nuevo y establece sockp. El transporte UDP reenvía el mensaje de llamada en intervalos de tiempo wait hasta que se reciba una respuesta o hasta que la llamada exceda el tiempo de espera. El tiempo total para que la llamada exceda el tiempo de espera se especifica en clnt_call().
Advertencia: dado que los mensajes RPC basados en UDP solo pueden contener hasta 8 Kbytes de datos codificados, este transporte no se puede utilizar para procedimientos que toman argumentos grandes o devuelven resultados enormes.
CLIENT *clntudp_bufcreate(struct sockaddr_in *addr,
            unsigned long prognum, unsigned long versnum,
            struct timeval wait, int *sockp,
            unsigned int sendsize, unsigned int recosize);
Esta rutina crea un cliente RPC para el programa remoto prognum, en versnum; el cliente utiliza UDP/IP como transporte. El programa remoto se encuentra en la dirección de Internet addr. Si addr->sin_port es cero, se establece en el puerto real en el que el programa remoto está escuchando (se consulta el servicio portmap remoto para obtener esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, esta rutina abre uno nuevo y establece sockp. El transporte UDP reenvía el mensaje de llamada en intervalos de tiempo wait hasta que se reciba una respuesta o hasta que la llamada exceda el tiempo de espera. El tiempo total para que la llamada exceda el tiempo de espera se especifica en clnt_call().
Esto permite al usuario especificar el tamaño máximo de paquete para enviar y recibir mensajes RPC basados en UDP.
void get_myaddress(struct sockaddr_in *addr);
Carga la dirección IP de la máquina en *addr, sin consultar las rutinas de la biblioteca que tratan con /etc/hosts. El número de puerto siempre se establece en htons(PMAPPORT).
struct pmaplist *pmap_getmaps(struct sockaddr_in *addr);
Una interfaz de usuario para el servicio portmap, que devuelve una lista de las asignaciones actuales de programas RPC a puertos en el host ubicado en la dirección IP *addr. Esta rutina puede devolver NULL. El comando rpcinfo -p utiliza esta rutina.
unsigned short pmap_getport(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned int protocol);
Una interfaz de usuario para el servicio portmap, que devuelve el número de puerto en el que espera un servicio que soporta el número de programa prognum, la versión versnum y habla el protocolo de transporte asociado con protocol. El valor de protocol es muy probablemente IPPROTO_UDP o IPPROTO_TCP. Un valor de retorno de cero significa que la asignación no existe o que el sistema RPC no pudo contactar el servicio portmap remoto. En este último caso, la variable global rpc_createerr contiene el estado RPC.
enum clnt_stat pmap_rmtcall(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout, unsigned long *portp);
Una interfaz de usuario para el servicio portmap, que instruye al portmap en el host en la dirección IP *addr para que realice una llamada RPC en su nombre a un procedimiento en ese host. El parámetro *portp se modificará al número de puerto del programa si el procedimiento tiene éxito. Las definiciones de otros parámetros se discuten en callrpc() y clnt_call(). Este procedimiento debe usarse para una “ping” y nada más. Ver también clnt_broadcast().
bool_t pmap_set(unsigned long prognum, unsigned long versnum,
                int protocol, unsigned short port);
Una interfaz de usuario para el servicio portmap, que establece una asignación entre el triple [prognum,versnum,protocol] y port en el servicio portmap de la máquina. El valor de protocol es muy probablemente IPPROTO_UDP o IPPROTO_TCP. Esta rutina devuelve uno si tiene éxito, cero en caso contrario. Se hace automáticamente por svc_register().
bool_t pmap_unset(unsigned long prognum, unsigned long versnum);
Una interfaz de usuario para el servicio portmap, que destruye todas las asignaciones entre el triple [prognum,versnum,*] y los puertos en el servicio portmap de la máquina. Esta rutina devuelve uno si tiene éxito, cero en caso contrario.
int registerrpc(unsigned long prognum, unsigned long versnum,
                unsigned long procnum, typeof(char *(char *)) *procname,
                xdrproc_t inproc, xdrproc_t outproc);
Registra el procedimiento procname con el paquete de servicios RPC. Si llega una solicitud para el programa prognum, versión versnum y procedimiento procnum, se llama a procname con un puntero a sus parámetros; procname debe devolver un puntero a sus resultados estáticos; inproc se utiliza para decodificar los parámetros, mientras que outproc se utiliza para codificar los resultados. Esta rutina devuelve cero si el registro tuvo éxito, -1 en caso contrario.
Advertencia: los procedimientos remotos registrados de esta forma se acceden utilizando la traza UDP/IP
nsport; ver svcudp_create() para restricciones. 
struct rpc_createerr rpc_createerr;
Una variable global cuyo valor se establece mediante cualquier rutina de creación de cliente RPC que no tenga éxito. Utilice la rutina clnt_pcreateerror() para imprimir el motivo.
void svc_destroy(SVCXPRT *xprt);
Una macro que destruye el manejador de transporte del servicio RPC, xprt. La destrucción generalmente implica la desasignación de estructuras de datos privadas, incluido xprt en sí. El uso de xprt no está definido después de llamar a esta rutina.
fd_set svc_fdset;
Una variable global que refleja la máscara de bits del descriptor de archivo de lectura del lado del servicio RPC; es adecuada como parámetro para la llamada al sistema select(2). Esto solo es de interés si un implementador de servicio realiza su propio procesamiento de eventos asíncronos, en lugar de llamar a svc_run(). Esta variable es de solo lectura (¡no pase su dirección a select(2)!), sin embargo, puede cambiar después de las llamadas a svc_getreqset() o a cualquier rutina de creación.
int svc_fds;
Similar a svc_fdset, pero limitado a 32 descriptores de archivo. Esta interfaz está obsoleta por svc_fdset.
svc_freeargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);
Una macro que libera cualquier dato asignado por el sistema RPC/XDR cuando decodificó los argumentos de un procedimiento de servicio utilizando svc_getargs(). Esta rutina devuelve 1 si los resultados se liberaron correctamente y cero en caso contrario.
svc_getargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);
Una macro que decodifica los argumentos de una solicitud RPC asociada con el manejador de transporte del servicio RPC, xprt. El parámetro in es la dirección donde se colocarán los argumentos; inproc es la rutina XDR utilizada para decodificar los argumentos. Esta rutina devuelve uno si la decodificación tiene éxito y cero en caso contrario.
struct sockaddr_in *svc_getcaller(SVCXPRT *xprt);
La forma aprobada de obtener la dirección de red del llamador de un procedimiento asociado con el manejador de transporte del servicio RPC, xprt.
void svc_getreqset(fd_set *rdfds);
Esta rutina solo es de interés si un implementador de servicio no llama a svc_run(), sino que implementa un procesamiento de eventos asíncronos personalizado. Se llama cuando la llamada al sistema select(2) ha determinado que ha llegado una solicitud RPC en alguno(s) socket(s) RPC; rdfds es la máscara de bits resultante del descriptor de archivo de lectura. La rutina devuelve cuando todos los sockets asociados con el valor de rdfds han sido atendidos.
void svc_getreq(int rdfds);
Similar a svc_getreqset(), pero limitado a 32 descriptores de archivo. Esta interfaz está obsoleta por svc_getreqset().
bool_t svc_register(SVCXPRT *xprt, unsigned long prognum,
                    unsigned long versnum,
                    typeof(void (struct svc_req *, SVCXPRT *)) *dispatch,
                    unsigned long protocol);
Asocia prognum y versnum con el procedimiento de despacho del servicio, dispatch. Si protocol es cero, el servicio no se registra con el servicio portmap. Si protocol es distinto de cero, se establece un mapeo del triple [prognum,versnum,protocol] a xprt->xp_port con el servicio portmap local (generalmente protocol es cero, IPPROTO_UDP o IPPROTO_TCP). El procedimiento dispatch tiene la siguiente forma:

dispatch(struct svc_req *request, SVCXPRT *xprt);

La rutina svc_register() devuelve uno si tiene éxito y cero en caso contrario.
void svc_run(void);
Esta rutina nunca devuelve. Espera a que lleguen las solicitudes RPC y llama al procedimiento de servicio apropiado utilizando svc_getreq() cuando llega una. Este procedimiento generalmente está esperando que la llamada al sistema select(2) devuelva.
bool_t svc_sendreply(SVCXPRT *xprt, xdrproc_t outproc, char *out);
Llamada por la rutina de despacho de un servicio RPC para enviar los resultados de una llamada a un procedimiento remoto. El parámetro xprt es el manejador de transporte asociado con la solicitud; outproc es la rutina XDR que se utiliza para codificar los resultados; y out es la dirección de los resultados. Esta rutina devuelve uno si tiene éxito, cero en caso contrario.
void svc_unregister(unsigned long prognum, unsigned long versnum);
Elimina todos los mapeos del doble [prognum,versnum] a los procedimientos de despacho y del triple [prognum,versnum,*] al número de puerto.
void svcerr_auth(SVCXPRT *xprt, enum auth_stat why);
Llamada por una rutina de despacho de servicio que se niega a realizar una llamada a un procedimiento remoto debido a un error de autenticación.
void svcerr_decode(SVCXPRT *xprt);
Llamada por una rutina de despacho de servicio que no puede decodificar sus parámetros correctamente. Ver también svc_getargs().
void svcerr_noproc(SVCXPRT *xprt);
Llamada por una rutina de despacho de servicio que no implementa el número de procedimiento que solicita el llamador.
void svcerr_noprog(SVCXPRT *xprt);
Se llama cuando el programa deseado no está registrado con el paquete RPC. Los implementadores de servicios generalmente no necesitan esta rutina.
void svcerr_progvers(SVCXPRT *xprt, unsigned long low_vers,
                     unsigned long high_vers);
Se llama cuando la versión deseada de un programa no está registrada con el paquete RPC. Los implementadores de servicios generalmente no necesitan esta rutina.
void svcerr_systemerr(SVCXPRT *xprt);
Llamada por una rutina de despacho de servicio cuando detecta un error del sistema que no está cubierto por ningún protocolo particular. Por ejemplo, si un servicio ya no puede asignar almacenamiento, puede llamar a esta rutina.
void svcerr_weakauth(SVCXPRT *xprt);
Llamada por una rutina de despacho de servicio que se niega a realizar una llamada a un procedimiento remoto debido a parámetros de autenticación insuficientes. La rutina llama a svcerr_auth(xprt, AUTH_TOOWEAK).
SVCXPRT *svcfd_create(int fd, unsigned int sendsize,
                      unsigned int recvsize);
Crea un servicio sobre cualquier descriptor de archivo abierto. Típicamente, este descriptor de archivo es un socket conectado para un protocolo de flujo como TCP. sendsize y recvsize indican los tamaños de los búferes de envío y recepción. Si son cero, se elige un valor predeterminado razonable.
SVCXPRT *svcraw_create(void);
Esta rutina crea un transporte de servicio RPC de juguete, al que devuelve un puntero. El transporte es en realidad un búfer dentro del espacio de direcciones del proceso, por lo que el cliente RPC correspondiente debería residir en el mismo espacio de direcciones; ver clntraw_create(). Esta rutina permite simular RPC y adquirir sobrecargas RPC (como tiempos de ida y vuelta), sin ninguna interferencia del kernel. Esta rutina devuelve NULL si falla.
SVCXPRT *svctcp_create(int sock, unsigned int send_buf_size,
                       unsigned int recv_buf_size);
Esta rutina crea un transporte de servicio RPC basado en TCP/IP, al que devuelve un puntero. El transporte está asociado con el socket sock, que puede ser RPC_ANYSOCK, en cuyo caso se crea un nuevo socket. Si el socket no está enlazado a un puerto TCP local, esta rutina lo enlaza a un puerto arbitrario. Al completarse, xprt->xp_sock es el descriptor del socket de transporte y xprt->xp_port es el número de puerto del transporte. Esta rutina devuelve NULL si falla. Dado que RPC basado en TCP utiliza E/S en búfer, los usuarios pueden especificar el tamaño de los búferes; los valores de cero eligen valores predeterminados adecuados.
SVCXPRT *svcudp_bufcreate(int sock, unsigned int sendsize,
                          unsigned int recosize);
Esta rutina crea un transporte de servicio RPC basado en UDP/IP, al que devuelve un puntero. El transporte está asociado con el socket sock, que puede ser RPC_ANYSOCK, en cuyo caso se crea un nuevo socket. Si el socket no está enlazado a un puerto UDP local, esta rutina lo enlaza a un puerto arbitrario. Al completarse, xprt->xp_sock es el descriptor del socket de transporte y xprt->xp_port es el número de puerto del transporte. Esta rutina devuelve NULL si falla.
Esto permite al usuario especificar el tamaño máximo del paquete para enviar y recibir mensajes RPC basados en UDP.
SVCXPRT *svcudp_create(int sock);
Esta llamada es equivalente a svcudp_bufcreate(sock,SZ,SZ) para algún tamaño predeterminado SZ.
bool_t xdr_accepted_reply(XDR *xdrs, struct accepted_reply *ar);
Se utiliza para codificar mensajes de respuesta RPC. Esta rutina es útil para usuarios que desean generar mensajes de estilo RPC sin utilizar el paquete RPC.
bool_t xdr_authunix_parms(XDR *xdrs, struct authunix_parms *aupp);
Se utiliza para describir credenciales UNIX. Esta rutina es útil para usuarios que desean generar estas credenciales sin utilizar el paquete de autenticación RPC.
void xdr_callhdr(XDR *xdrs, struct rpc_msg *chdr);
Se utiliza para describir mensajes de cabecera de llamada RPC. Esta rutina es útil para usuarios que desean generar mensajes de estilo RPC sin utilizar el paquete RPC.

SYNOPSIS AND DESCRIPTION


void svc_sendreply(SVCXPRT *xprt, xdrproc_t xdr_results, caddr_t xdr_location);






The svc_sendreply routine is called by a service procedure to send a reply to the client. The xprt argument is the transport handle that was given to the service routine. The xdr_results argument is the XDR routine used to encode the procedure's results. The xdr_location argument is the address of the results to be encoded.




bool_t xdr_accepted_reply(XDR *xdrs, struct rpc_msg *rmsg);






Used for describing RPC accepted reply messages. This routine is useful for users who wish to generate RPC-style messages without using the RPC package.




bool_t xdr_authunix_parms(XDR *xdrs, struct authunix_parms *uap);






Used for describing RPC Unix authentication parameters messages. This routine is useful for users who wish to generate RPC-style messages without using the RPC package.

bool_t xdr_pmap(XDR *xdrs, struct pmap *regs);






Used for describing parameters to various portmap procedures, externally. This routine is useful for users who wish to generate these parameters without using the pmap interface.

Used for describing RPC reply messages. This routine is useful for users who wish to generate RPC style messages without using the RPC package.




void xprt_register(SVCXPRT *xprt);






After RPC service transport handles are created, they should register themselves with the RPC service package. This routine modifies the global variable svc_fds. Service implementors usually do not need this routine.




void xprt_unregister(SVCXPRT *xprt);






Before an RPC service transport handle is destroyed, it should unregister itself with the RPC service package. This routine modifies the global variable svc_fds. Service implementors usually do not need this routine.
