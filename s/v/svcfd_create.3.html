rpc(3) Manual de Funciones de Biblioteca rpc(3)

NOMBRE

rpc - rutinas de biblioteca para llamadas a procedimientos remotos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

RESUMEN Y DESCRIPCIÓN

Estas rutinas permiten a programas C realizar llamadas a procedimientos en otras máquinas a través de la red. Primero, el cliente llama a un procedimiento para enviar un paquete de datos al servidor. Al recibir el paquete, el servidor llama a una rutina de distribución para realizar el servicio solicitado y luego envía una respuesta. Finalmente, la llamada al procedimiento retorna al cliente.

Para hacer uso de estas rutinas, incluya el archivo de cabecera <rpc/rpc.h>.

Los prototipos a continuación hacen uso de los siguientes tipos:

typedef int bool_t;
typedef typeof(bool_t (XDR *, void *, ...))  *xdrproc_t;
typedef typeof(bool_t (caddr_t resp, struct sockaddr_in *raddr)
    *resultproc_t;

Consulte los archivos de cabecera para las declaraciones de los tipos AUTH, CLIENT, SVCXPRT y XDR.

void auth_destroy(AUTH *auth);
Una macro que destruye la información de autenticación asociada con auth. La destrucción generalmente implica la desasignación de estructuras de datos privadas. El uso de auth no está definido después de llamar a auth_destroy().
AUTH *authnone_create(void);
Crea y devuelve un manejador de autenticación RPC que pasa información de autenticación no utilizable con cada llamada a procedimiento remoto. Esta es la autenticación predeterminada utilizada por RPC.
AUTH *authunix_create(char *host, uid_t uid, gid_t gid,
                      int n, gid_t aup_gids[n]);
Crea y devuelve un manejador de autenticación RPC que contiene información de autenticación. El parámetro host es el nombre de la máquina en la que se creó la información; uid es el ID de usuario del usuario; gid es el ID de grupo actual del usuario; n y aup_gids se refieren a una matriz contada de grupos a los que pertenece el usuario. Es fácil suplantar a un usuario.
AUTH *authunix_create_default(void);
Llama a authunix_create() con los parámetros apropiados.
int callrpc(char *host, unsigned long prognum,
            unsigned long versnum, unsigned long procnum,
            xdrproc_t inproc, const char *in,
            xdrproc_t outproc, char *out);
Llama al procedimiento remoto asociado con prognum, versnum y procnum en la máquina host. El parámetro in es la dirección de los argumentos del procedimiento, y out es la dirección donde colocar los resultados; inproc se utiliza para codificar los parámetros del procedimiento, y outproc se utiliza para decodificar los resultados del procedimiento. Esta rutina devuelve cero si tiene éxito, o el valor de enum clnt_stat convertido a entero si falla. La rutina clnt_perrno() es útil para traducir los estados de fallo en mensajes.
Advertencia: llamar a procedimientos remotos con esta rutina utiliza UDP/IP como transporte; consulte clntudp_create() para ver las restricciones. No tiene control sobre los tiempos de espera o la autenticación al usar esta rutina.
enum clnt_stat clnt_broadcast(unsigned long prognum,
                     unsigned long versnum, unsigned long procnum,
                     xdrproc_t inproc, char *in,
                     xdrproc_t outproc, char *out,
                     resultproc_t eachresult);
Similar a callrpc(), excepto que el mensaje de llamada se difunde a todas las redes de difusión conectadas localmente. Cada vez que recibe una respuesta, esta rutina llama a eachresult(), cuya forma es:

eachresult(char *out, struct sockaddr_in *addr);

donde out es el mismo que out pasado a clnt_broadcast(), excepto que la salida del procedimiento remoto se decodifica allí; addr apunta a la dirección de la máquina que envió los resultados. Si eachresult() devuelve cero, clnt_broadcast() espera más respuestas; de lo contrario, devuelve el estado apropiado.
Advertencia: los sockets de difusión están limitados en tamaño a la unidad máxima de transferencia del enlace de datos. Para ethernet, este valor es 1500 bytes.
enum clnt_stat clnt_call(CLIENT *clnt, unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout);
Una macro que llama al procedimiento remoto procnum asociado con el manejador del cliente, clnt, que se obtiene con una rutina de creación de cliente RPC como clnt_create(). El parámetro in es la dirección de los argumentos del procedimiento, y out es la dirección donde colocar los resultados; inproc se utiliza para codificar los parámetros del procedimiento, y outproc se utiliza para decodificar los resultados del procedimiento; tout es el tiempo permitido para que regresen los resultados.
clnt_destroy(CLIENT *clnt);
Una macro que destruye el manejador RPC del cliente. La destrucción generalmente implica la desasignación de estructuras de datos privadas, incluido el propio clnt. El uso de clnt no está definido después de llamar a clnt_destroy(). Si la biblioteca RPC abrió el socket asociado, también lo cerrará. De lo contrario, el socket permanece abierto.
CLIENT *clnt_create(const char *host, unsigned long prog,
                    unsigned long vers, const char *proto);
Rutina genérica de creación de cliente. host identifica el nombre del host remoto donde se encuentra el servidor. proto indica qué tipo de protocolo de transporte usar. Los valores actualmente admitidos para este campo son “udp” y “tcp”. Se establecen tiempos de espera predeterminados, pero se pueden modificar usando clnt_control().
Advertencia: usar UDP tiene sus inconvenientes. Dado que los mensajes RPC basados en UDP solo pueden contener hasta 8 Kbytes de datos codificados, este transporte no se puede usar para procedimientos que toman argumentos grandes o devuelven resultados enormes.
bool_t clnt_control(CLIENT *cl, int req, char *info);
Una macro utilizada para cambiar o recuperar diversa información sobre un objeto cliente. req indica el tipo de operación y info es un puntero a la información. Tanto para UDP como para TCP, los valores admitidos de req y sus tipos de argumento y lo que hacen son:

CLSET_TIMEOUT  struct timeval // establecer tiempo de espera total
CLGET_TIMEOUT  struct timeval // obtener tiempo de espera total

Nota: si establece el tiempo de espera usando clnt_control(), el parámetro de tiempo de espera pasado a clnt_call() se ignorará en todas las llamadas futuras.

CLGET_SERVER_ADDR  struct sockaddr_in
                // obtener dirección del servidor

Las siguientes operaciones son válidas solo para UDP:

CLSET_RETRY_TIMEOUT  struct timeval // establecer tiempo de espera de reintento
CLGET_RETRY_TIMEOUT  struct timeval // obtener tiempo de espera de reintento

El tiempo de espera de reintento es el tiempo que la "RPC UDP" espera la respuesta del servidor antes de retransmitir la solicitud.
clnt_freeres(CLIENT * clnt, xdrproc_t outproc, char *out);
Una macro que libera cualquier dato asignado por el sistema RPC/XDR al decodificar los resultados de una llamada RPC. El parámetro out es la dirección de los resultados y outproc es la rutina XDR que describe los resultados. Esta rutina devuelve uno si los resultados se liberaron correctamente y cero en caso contrario.
void clnt_geterr(CLIENT *clnt, struct rpc_err

DESCRIPCIÓN

La biblioteca RPC proporciona una forma de llamar a procedimientos en máquinas remotas. Los programas de cliente se crean utilizando una de las funciones de creación de clientes de nivel superior, como clnt_create().

Las funciones que terminan en perror imprimen un mensaje a stderr indicando por qué falló una llamada RPC. Las funciones que terminan en sperror devuelven un puntero a una cadena que contiene el mensaje.

La función clnt_freeres libera la memoria asociada con la estructura de resultados devuelta por una llamada RPC.

Las funciones de creación de clientes, como clnttcp_create() y clntudp_create(), se utilizan para crear un cliente RPC para un programa y versión específicos en una dirección remota determinada.

clntraw_create() crea un cliente RPC de juguete para su uso en la depuración y simulación.

get_myaddress() rellena la dirección IP de la máquina en *addr.

Las funciones que comienzan con pmap_ son interfaces para el servicio RPC portmap, que se utiliza para asignar números de programa RPC a números de puerto de red.

pmap_getport() devuelve el número de puerto en el que un servicio determinado está esperando. Si el servicio no se puede encontrar o no se puede contactar con el portmap remoto, devuelve 0.

pmap_getmaps() devuelve una lista de todos los mapeos de programa-a-puerto RPC actuales en un host remoto.

pmap_set() establece un mapeo entre un triple de programa/versión/protocolo y un puerto.

pmap_unset() destruye todos los mapeos para un triple de programa/versión/protocolo dado.

pmap_rmtcall() instruye al portmap en un host remoto para que realice una llamada RPC en su nombre. Se utiliza para "pingear" un host.

registerrpc() registra un procedimiento para que sea accesible a través de RPC.

Las funciones de creación de clientes devuelven un puntero a una estructura `CLIENT` si tienen éxito y NULL si fallan. Si falla una llamada de creación de cliente, el error se almacena en la variable global rpc_createerr.

CLNT_PERROR y CLNT_SPERROR

void
clnt_perror(CLIENT *clnt, const char *s);
char *
clnt_sperror(CLIENT *rpch, const char *s);

Estas funciones imprimen (o devuelven) un mensaje de error que indica por qué falló una llamada RPC. El mango clnt se utiliza para hacer la llamada. El mensaje se antepone con la cadena s y dos puntos. Se utilizan después de una llamada fallida a clnt_call().

Bugs: devuelven punteros a datos estáticos que se sobrescriben en cada llamada.

CLNT_PERRNO y CLNT_SPERRNO

void
clnt_perrno(enum clnt_stat stat);
char *
clnt_sperrno(enum clnt_stat stat);

Estas funciones imprimen (o devuelven) un mensaje de error que corresponde a la condición indicada por stat. Se utilizan después de que callrpc() falla.

clnt_sperrno() se utiliza en lugar de clnt_perrno() si el programa no tiene un error estándar (como probablemente no lo tiene un programa que se ejecuta como servidor), o si el programador no quiere que el mensaje se genere con printf(3), o si se va a utilizar un formato de mensaje diferente al admitido por clnt_perrno(). Tenga en cuenta que, a diferencia de clnt_sperror() y clnt_spcreateerror(), clnt_sperrno() devuelve un puntero a datos estáticos, pero el resultado no se sobrescribirá en cada llamada.

CLNT_PCREATEERROR y CLNT_SPCREATEERROR

void
clnt_pcreateerror(const char *s);
char *
clnt_spcreateerror(const char *s);

Estas funciones imprimen (o devuelven) un mensaje que indica por qué no se pudo crear un mango RPC de cliente. El mensaje se antepone con la cadena s y dos puntos. Se utilizan cuando una llamada a clnt_create(), clntraw_create(), clnttcp_create(), o clntudp_create() falla.

Bugs: devuelven punteros a datos estáticos que se sobrescriben en cada llamada.

CLNTRAW_CREATE

CLIENT *
clntraw_create(unsigned long prognum, unsigned long versnum);

Esta rutina crea un cliente RPC de juguete para el programa remoto prognum, versión versnum. El transporte utilizado para pasar mensajes al servicio es en realidad un búfer dentro del espacio de direcciones del proceso, por lo que el servidor RPC correspondiente debería vivir en el mismo espacio de direcciones; consulte svcraw_create(). Esto permite la simulación de RPC y la adquisición de sobrecargas RPC, como los tiempos de ida y vuelta, sin ninguna intervención del kernel. Esta rutina devuelve NULL si falla.

CLNTTCP_CREATE

CLIENT *
clnttcp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                int *sockp, unsigned int sendsz, unsigned int recvsz);

Esta rutina crea un cliente RPC para el programa remoto prognum, versión versnum; el cliente utiliza TCP/IP como transporte. El programa remoto se encuentra en la dirección de Internet *addr. Si addr->sin_port es cero, entonces se establece en el puerto real en el que el programa remoto está escuchando (se consulta el servicio portmap remoto para obtener esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, entonces esta rutina abre uno nuevo y establece sockp. Dado que RPC basado en TCP utiliza E/S con búfer, el usuario puede especificar el tamaño de los búferes de envío y recepción con los parámetros sendsz y recvsz; los valores de cero eligen valores predeterminados adecuados. Esta rutina devuelve NULL si falla.

CLNTUDP_CREATE

CLIENT *
clntudp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                struct timeval wait, int *sockp);

Esta rutina crea un cliente RPC para el programa remoto prognum, versión versnum; el cliente utiliza UDP/IP como transporte. El programa remoto se encuentra en la dirección de Internet addr. Si addr->sin_port es cero, entonces se establece en el puerto real en el que el programa remoto está escuchando (se consulta el servicio portmap remoto para obtener esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, entonces esta rutina abre uno nuevo y establece sockp. El transporte UDP reenviará el mensaje de llamada en intervalos de tiempo wait hasta que se reciba una respuesta o hasta que la llamada expire. El tiempo total para que la llamada expire se especifica mediante clnt_call().

Advertencia: dado que los mensajes RPC basados en UDP solo pueden contener hasta 8 Kbytes de datos codificados, este transporte no se puede utilizar para procedimientos que toman argumentos grandes o devuelven resultados muy grandes.

CLNTUDP_BUFCREATE

CLIENT *
clntudp_bufcreate(struct sockaddr_in *addr,
            unsigned long prognum, unsigned long versnum,
            struct timeval wait, int *sockp,
            unsigned int sendsize, unsigned int recosize);

Esta rutina crea un cliente RPC para el programa remoto prognum, en versnum; el cliente utiliza UDP/IP como transporte. El programa remoto se encuentra en la dirección de Internet addr. Si addr->sin_port es cero, entonces se establece en el puerto real en el que el programa remoto está escuchando (se consulta el servicio portmap remoto para obtener esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, entonces esta rutina abre uno nuevo y establece sockp. El transporte UDP reenviará el mensaje de llamada en intervalos de tiempo wait hasta que se reciba una respuesta o hasta que la llamada expire. El tiempo total para que la llamada expire se especifica mediante clnt_call().

Esto permite al usuario especificar el tamaño máximo del paquete para enviar y recibir mensajes RPC basados en UDP.

GET_MYADDRESS

void
get_myaddress(struct sockaddr_in *addr);

Rellena la dirección IP de la máquina en *addr, sin consultar las rutinas de la biblioteca que tratan con /etc/hosts. El número de puerto siempre se establece en htons(PMAPPORT).

PMAP_GETMAPS

struct pmaplist *
pmap_getmaps(struct sockaddr_in *addr);

Una interfaz de usuario para el servicio portmap, que devuelve una lista de los mapeos actuales de programas RPC a puertos en el host ubicado en la dirección IP *addr. Esta rutina puede devolver NULL. El comando rpcinfo -p utiliza esta rutina.

PMAP_GETPORT

unsigned short
pmap_getport(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned int protocol);

Una interfaz de usuario para el servicio portmap, que devuelve el número de puerto en el que espera un servicio que admita el número de programa prognum, versión versnum y hable el protocolo de transporte asociado con protocol. El valor de protocol es muy probablemente IPPROTO_UDP o IPPROTO_TCP. Un valor de retorno de cero significa que el mapeo no existe o que el sistema RPC no pudo contactar con el servicio portmap remoto. En este último caso, la variable global rpc_createerr contiene el estado RPC.

PMAP_RMTCALL

enum clnt_stat
pmap_rmtcall(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout, unsigned long *portp);

Una interfaz de usuario para el servicio portmap, que instruye al portmap en el host en la dirección IP *addr para que realice una llamada RPC en su nombre a un procedimiento en ese host. El parámetro *portp se modificará al número de puerto del programa si el procedimiento tiene éxito. Las definiciones de otros parámetros se discuten en callrpc() y clnt_call(). Este procedimiento debe utilizarse para un "ping" y nada más. Consulte también clnt_broadcast().

PMAP_SET

bool_t
pmap_set(unsigned long prognum, unsigned long versnum,
                int protocol, unsigned short port);

Una interfaz de usuario para el servicio portmap, que establece un mapeo entre el triple [prognum,versnum,protocol] y port en el servicio portmap de la máquina. El valor de protocol es muy probablemente IPPROTO_UDP o IPPROTO_TCP. Esta rutina devuelve uno si tiene éxito, cero en caso contrario. Realizado automáticamente por svc_register().

PMAP_UNSET

bool_t
pmap_unset(unsigned long prognum, unsigned long versnum);

Una interfaz de usuario para el servicio portmap, que destruye todos los mapeos entre el triple [prognum,versnum,*] y puertos en el servicio portmap de la máquina. Esta rutina devuelve uno si tiene éxito, cero en caso contrario.

REGISTERRPC

int
registerrpc(unsigned long prognum, unsigned long versnum,
                unsigned long procnum, typeof(char *(char *)) *procname,
                xdrproc_t inproc, xdrproc_t outproc);

Registra el procedimiento procname con el paquete de servicios RPC. Si llega una solicitud para el programa prognum, versión versnum y procedimiento procnum, se llama a procname con un puntero a sus parámetros; procname debe devolver un puntero a sus resultados estáticos; inproc se utiliza para decodificar los parámetros mientras que outproc se utiliza para codificar los resultados. Esta rutina devuelve cero si el registro tuvo éxito, -1 en caso contrario.

Advertencia: los procedimientos remotos registrados de esta forma se acceden utilizando el tran UDP/IP

These routines are the server-side interface to the RPC package. They are intended for use by RPC service implementors. 
SVCXPRT *svctcp_create(int sock, unsigned int send_buf_size, unsigned int recv_buf_size);
 This routine creates a TCP/IP-based RPC service transport, to which it returns a pointer. The transport is associated with the socket sock, which may be RPC_ANYSOCK, in which case a new socket is created. If the socket is not bound to a local TCP port, then this routine binds it to an arbitrary port. Upon completion, xprt->xp_sock is the transport's socket descriptor, and xprt->xp_port is the transport's port number. This routine returns NULL if it fails. Since TCP-based RPC uses buffered I/O, users may specify the size of buffers; values of zero choose suitable defaults. 
SVCXPRT *svcudp_bufcreate(int sock, unsigned int sendsize, unsigned int recosize);
 This routine creates a UDP/IP-based RPC service transport, to which it returns a pointer. The transport is associated with the socket sock, which may be RPC_ANYSOCK, in which case a new socket is created. If the socket is not bound to a local UDP port, then this routine binds it to an arbitrary port. Upon completion, xprt->xp_sock is the transport's socket descriptor, and xprt->xp_port is the transport's port number. This routine returns NULL if it fails. This allows the user to specify the maximum packet size for sending and receiving UDP-based RPC messages. 
SVCXPRT *svcudp_create(int sock);
 This call is equivalent to svcudp_bufcreate(sock,SZ,SZ) for some default size SZ. 
struct rpc_createerr rpc_createerr;
 A global variable whose value is set by any RPC client creation routine that does not succeed. Use the routine clnt_pcreateerror() to print the reason why. 
void svc_destroy(SVCXPRT *xprt);
 A macro that destroys the RPC service transport handle, xprt. Destruction usually involves deallocation of private data structures, including xprt itself. Use of xprt is undefined after calling this routine. 
fd_set svc_fdset;
 A global variable reflecting the RPC service side's read file descriptor bit mask; it is suitable as a parameter to the select(2) system call. This is of interest only if a service implementor does their own asynchronous event processing, instead of calling svc_run(). This variable is read-only (do not pass its address to select(2)!), yet it may change after calls to svc_getreqset() or any creation routines. 
int svc_fds;
 Similar to svc_fdset, but limited to 32 file descriptors. This interface is obsoleted by svc_fdset. 
svc_freeargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);
 A macro that frees any data allocated by the RPC/XDR system when it decoded the arguments to a service procedure using svc_getargs(). This routine returns 1 if the results were successfully freed, and zero otherwise. 
svc_getargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);
 A macro that decodes the arguments of an RPC request associated with the RPC service transport handle, xprt. The parameter in is the address where the arguments will be placed; inproc is the XDR routine used to decode the arguments. This routine returns one if decoding succeeds, and zero otherwise. 
struct sockaddr_in *svc_getcaller(SVCXPRT *xprt);
 The approved way of getting the network address of the caller of a procedure associated with the RPC service transport handle, xprt. 
void svc_getreqset(fd_set *rdfds);
 This routine is of interest only if a service implementor does not call svc_run(), but instead implements custom asynchronous event processing. It is called when the select(2) system call has determined that an RPC request has arrived on some RPC socket(s); rdfds is the resultant read file descriptor bit mask. The routine returns when all sockets associated with the value of rdfds have been serviced. 
void svc_getreq(int rdfds);
 Similar to svc_getreqset(), but limited to 32 file descriptors. This interface is obsoleted by svc_getreqset(). 
bool_t svc_register(SVCXPRT *xprt, unsigned long prognum, unsigned long versnum, typeof(void (struct svc_req *, SVCXPRT *)) *dispatch, unsigned long protocol);
 Associates prognum and versnum with the service dispatch procedure, dispatch. If protocol is zero, the service is not registered with the portmap service. If protocol is nonzero, then a mapping of the triple [prognum,versnum,protocol] to xprt->xp_port is established with the local portmap service (generally protocol is zero, IPPROTO_UDP or IPPROTO_TCP). The procedure dispatch has the following form: dispatch(struct svc_req *request, SVCXPRT *xprt); The svc_register() routine returns one if it succeeds, and zero otherwise. 
void svc_run(void);
 This routine never returns. It waits for RPC requests to arrive, and calls the appropriate service procedure using svc_getreq() when one arrives. This procedure is usually waiting for a select(2) system call to return. 
bool_t svc_sendreply(SVCXPRT *xprt, xdrproc_t outproc, char *out);
 Called by an RPC service's dispatch routine to send the results of a remote procedure call. The parameter xprt is the request's associated transport handle; outproc is the XDR routine which is used to encode the results; and out is the address of the results. This routine returns one if it succeeds, zero otherwise. 
void svc_unregister(unsigned long prognum, unsigned long versnum);
 Remove all mapping of the double [prognum,versnum] to dispatch routines, and of the triple [prognum,versnum,*] to port number. 
void svcerr_auth(SVCXPRT *xprt, enum auth_stat why);
 Called by a service dispatch routine that refuses to perform a remote procedure call due to an authentication error. 
void svcerr_decode(SVCXPRT *xprt);
 Called by a service dispatch routine that cannot successfully decode its parameters. See also svc_getargs(). 
void svcerr_noproc(SVCXPRT *xprt);

void svcerr_systemerr(SVCXPRT *xprt);
 Called by a service dispatch routine when it detects a system error not covered by any particular protocol. For example, if a service can no longer allocate storage, it may call this routine. 
void svcerr_weakauth(SVCXPRT *xprt);
 Called by a service dispatch routine that refuses to perform a remote procedure call due to insufficient authentication parameters. The routine calls svcerr_auth(xprt, AUTH_TOOWEAK). 
SVCXPRT *svcfd_create(int fd, unsigned int sendsize, unsigned int recvsize);
 Create a service on top of any open file descriptor. Typically, this file descriptor is a connected socket for a stream protocol such as TCP. sendsize and recvsize indicate sizes for the send and receive buffers. If they are zero, a reasonable default is chosen. 
SVCXPRT *svcraw_create(void);
 This routine creates a toy RPC service transport, to which it returns a pointer. The transport is really a buffer within the process's address space, so the corresponding RPC client should live in the same address space; see clntraw_create(). This routine allows simulation of RPC and acquisition of RPC overheads (such as round trip times), without any kernel interference. This routine returns NULL if it fails.
