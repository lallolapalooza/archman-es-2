rpc(3) Manual de funciones de biblioteca rpc(3)

NOMBRE

rpc - rutinas de biblioteca para llamadas a procedimientos remotos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS Y DESCRIPCIÓN

Estas rutinas permiten a los programas C realizar llamadas a procedimientos en otras máquinas a través de la red. Primero, el cliente llama a un procedimiento para enviar un paquete de datos al servidor. Al recibir el paquete, el servidor llama a una rutina de distribución para realizar el servicio solicitado y luego envía una respuesta. Finalmente, la llamada al procedimiento retorna al cliente.

Para utilizar estas rutinas, incluya el archivo de encabezado <rpc/rpc.h>.

Los prototipos a continuación hacen uso de los siguientes tipos:

typedef int bool_t;
typedef typeof(bool_t (XDR *, void *, ...))  *xdrproc_t;
typedef typeof(bool_t (caddr_t resp, struct sockaddr_in *raddr)
    *resultproc_t;

Consulte los archivos de encabezado para ver las declaraciones de los tipos AUTH, CLIENT, SVCXPRT y XDR.

void auth_destroy(AUTH *auth);
Una macro que destruye la información de autenticación asociada con auth. La destrucción generalmente implica la desasignación de estructuras de datos privadas. El uso de auth no está definido después de llamar a auth_destroy().
AUTH *authnone_create(void);
Crea y devuelve un identificador de autenticación RPC que pasa información de autenticación no utilizable con cada llamada a procedimiento remoto. Esta es la autenticación predeterminada utilizada por RPC.
AUTH *authunix_create(char *host, uid_t uid, gid_t gid,
                      int n, gid_t aup_gids[n]);
Crea y devuelve un identificador de autenticación RPC que contiene información de autenticación. El parámetro host es el nombre de la máquina en la que se creó la información; uid es el ID de usuario; gid es el ID de grupo actual del usuario; n y aup_gids se refieren a una matriz contada de grupos a los que pertenece el usuario. Es fácil suplantar a un usuario.
AUTH *authunix_create_default(void);
Llama a authunix_create() con los parámetros apropiados.
int callrpc(char *host, unsigned long prognum,
            unsigned long versnum, unsigned long procnum,
            xdrproc_t inproc, const char *in,
            xdrproc_t outproc, char *out);
Llama al procedimiento remoto asociado con prognum, versnum y procnum en la máquina host. El parámetro in es la dirección de los argumentos del procedimiento y out es la dirección donde colocar los resultados; inproc se utiliza para codificar los parámetros del procedimiento y outproc se utiliza para decodificar los resultados del procedimiento. Esta rutina devuelve cero si tiene éxito, o el valor de enum clnt_stat convertido a entero si falla. La rutina clnt_perrno() es útil para traducir estados de error en mensajes.
Advertencia: llamar a procedimientos remotos con esta rutina utiliza UDP/IP como transporte; consulte clntudp_create() para ver las restricciones. No tiene control sobre los tiempos de espera ni la autenticación utilizando esta rutina.
enum clnt_stat clnt_broadcast(unsigned long prognum,
                     unsigned long versnum, unsigned long procnum,
                     xdrproc_t inproc, char *in,
                     xdrproc_t outproc, char *out,
                     resultproc_t eachresult);
Similar a callrpc(), excepto que el mensaje de llamada se transmite a todas las redes de difusión conectadas localmente. Cada vez que recibe una respuesta, esta rutina llama a eachresult(), cuya forma es:

eachresult(char *out, struct sockaddr_in *addr);

donde out es el mismo que out pasado a clnt_broadcast(), excepto que la salida del procedimiento remoto se decodifica allí; addr apunta a la dirección de la máquina que envió los resultados. Si eachresult() devuelve cero, clnt_broadcast() espera más respuestas; de lo contrario, retorna con el estado apropiado.
Advertencia: los sockets de difusión están limitados en tamaño a la unidad de transferencia máxima del enlace de datos. Para ethernet, este valor es de 1500 bytes.
enum clnt_stat clnt_call(CLIENT *clnt, unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout);
Una macro que llama al procedimiento remoto procnum asociado con el identificador del cliente, clnt, que se obtiene con una rutina de creación de cliente RPC como clnt_create(). El parámetro in es la dirección de los argumentos del procedimiento y out es la dirección donde colocar los resultados; inproc se utiliza para codificar los parámetros del procedimiento y outproc se utiliza para decodificar los resultados del procedimiento; tout es el tiempo permitido para que regresen los resultados.
clnt_destroy(CLIENT *clnt);
Una macro que destruye el identificador RPC del cliente. La destrucción generalmente implica la desasignación de estructuras de datos privadas, incluido el propio clnt. El uso de clnt no está definido después de llamar a clnt_destroy(). Si la biblioteca RPC abrió el socket asociado, también lo cerrará. De lo contrario, el socket permanecerá abierto.
CLIENT *clnt_create(const char *host, unsigned long prog,
                    unsigned long vers, const char *proto);
Rutina genérica de creación de cliente. host identifica el nombre del host remoto donde se encuentra el servidor. proto indica qué tipo de protocolo de transporte utilizar. Los valores actualmente compatibles para este campo son “udp” y “tcp”. Se establecen tiempos de espera predeterminados, pero se pueden modificar utilizando clnt_control().
Advertencia: el uso de UDP tiene sus inconvenientes. Dado que los mensajes RPC basados en UDP solo pueden contener hasta 8 Kbytes de datos codificados, este transporte no se puede utilizar para procedimientos que aceptan argumentos grandes o devuelven resultados enormes.
bool_t clnt_control(CLIENT *cl, int req, char *info);
Una macro utilizada para cambiar o recuperar diversa información sobre un objeto de cliente. req indica el tipo de operación y info es un puntero a la información. Tanto para UDP como para TCP, los valores compatibles de req y los tipos de sus argumentos y lo que hacen son:

CLSET_TIMEOUT  struct timeval // establecer tiempo total de espera
CLGET_TIMEOUT  struct timeval // obtener tiempo total de espera

Nota: si establece el tiempo de espera utilizando clnt_control(), el parámetro de tiempo de espera pasado a clnt_call() se ignorará en todas las llamadas futuras.

CLGET_SERVER_ADDR  struct sockaddr_in
                // obtener dirección del servidor

Las siguientes operaciones son válidas solo para UDP:

CLSET_RETRY_TIMEOUT  struct timeval // establecer tiempo de espera de reintento
CLGET_RETRY_TIMEOUT  struct timeval // obtener tiempo de espera de reintento

El tiempo de espera de reintento es el tiempo que "RPC UDP" espera la respuesta del servidor antes de retransmitir la solicitud.
clnt_freeres(CLIENT * clnt, xdrproc_t outproc, char *out);
Una macro que libera cualquier dato asignado por el sistema RPC/XDR al decodificar los resultados de una llamada RPC. El parámetro out es la dirección de los resultados y outproc es la rutina XDR que describe los resultados. Esta rutina devuelve uno si los resultados se liberaron correctamente y cero en caso contrario.
void clnt_geterr(CLIENT *clnt, struct rpc_err
*errp);
Una macro que copia la estructura de error del manejador del cliente a la estructura en la dirección errp.
void clnt_pcreateerror(const char *s);
Imprime un mensaje en la salida de error estándar indicando por qué no se pudo crear un manejador RPC de cliente. El mensaje va precedido por la cadena s y dos puntos. Se usa cuando una llamada a clnt_create(), clntraw_create(), clnttcp_create() o clntudp_create() falla.
void clnt_perrno(enum clnt_stat stat);
Imprime un mensaje en la salida de error estándar correspondiente a la condición indicada por stat. Se usa después de callrpc().
clnt_perror(CLIENT *clnt, const char *s);
Imprime un mensaje en la salida de error estándar indicando por qué falló una llamada RPC; clnt es el manejador utilizado para realizar la llamada. El mensaje va precedido por la cadena s y dos puntos. Se usa después de clnt_call().
char *clnt_spcreateerror(const char *s);
Similar a clnt_pcreateerror(), excepto que devuelve una cadena en lugar de imprimir en la salida de error estándar.
Errores: devuelve un puntero a datos estáticos que se sobrescribe en cada llamada.
char *clnt_sperrno(enum clnt_stat stat);
Toma los mismos argumentos que clnt_perrno(), pero en lugar de enviar un mensaje a la salida de error estándar indicando por qué falló una llamada RPC, devuelve un puntero a una cadena que contiene el mensaje. La cadena termina con un salto de línea.
clnt_sperrno() se usa en lugar de clnt_perrno() si el programa no tiene una salida de error estándar (como es muy probable que no tenga un programa que se ejecute como servidor), o si el programador no desea que el mensaje se imprima con printf(3), o si se desea un formato de mensaje diferente al soportado por clnt_perrno(). Nota: a diferencia de clnt_sperror() y clnt_spcreateerror(), clnt_sperrno() devuelve un puntero a datos estáticos, pero el resultado no se sobrescribirá en cada llamada.
char *clnt_sperror(CLIENT *rpch, const char *s);
Similar a clnt_perror(), excepto que (como clnt_sperrno()) devuelve una cadena en lugar de imprimir en la salida de error estándar.
Errores: devuelve un puntero a datos estáticos que se sobrescribe en cada llamada.
CLIENT *clntraw_create(unsigned long prognum, unsigned long versnum);
Esta rutina crea un cliente RPC ficticio para el programa remoto prognum, versión versnum. El transporte utilizado para pasar mensajes al servicio es en realidad un búfer dentro del espacio de direcciones del proceso, por lo que el servidor RPC correspondiente debe residir en el mismo espacio de direcciones; consulte svcraw_create(). Esto permite simular RPC y adquirir sobrecargas de RPC, como tiempos de ida y vuelta, sin interferencia del kernel. Esta rutina devuelve NULL si falla.
CLIENT *clnttcp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                int *sockp, unsigned int sendsz, unsigned int recvsz);
Esta rutina crea un cliente RPC para el programa remoto prognum, versión versnum; el cliente utiliza TCP/IP como transporte. El programa remoto se encuentra en la dirección de Internet *addr. Si addr->sin_port es cero, se establece en el puerto real en el que el programa remoto está escuchando (se consulta el servicio portmap remoto para obtener esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, esta rutina abre uno nuevo y establece sockp. Dado que RPC basado en TCP utiliza E/S con búfer, el usuario puede especificar el tamaño de los búferes de envío y recepción con los parámetros sendsz y recvsz; los valores de cero eligen valores predeterminados adecuados. Esta rutina devuelve NULL si falla.
CLIENT *clntudp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                struct timeval wait, int *sockp);
Esta rutina crea un cliente RPC para el programa remoto prognum, versión versnum; el cliente utiliza UDP/IP como transporte. El programa remoto se encuentra en la dirección de Internet addr. Si addr->sin_port es cero, se establece en el puerto real en el que el programa remoto está escuchando (se consulta el servicio portmap remoto para obtener esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, esta rutina abre uno nuevo y establece sockp. El transporte UDP reenvía el mensaje de llamada en intervalos de tiempo wait hasta que se recibe una respuesta o hasta que la llamada expira. El tiempo total para que la llamada expire se especifica mediante clnt_call().
Advertencia: dado que los mensajes RPC basados en UDP solo pueden contener hasta 8 Kbytes de datos codificados, este transporte no se puede utilizar para procedimientos que aceptan argumentos grandes o devuelven resultados enormes.
CLIENT *clntudp_bufcreate(struct sockaddr_in *addr,
            unsigned long prognum, unsigned long versnum,
            struct timeval wait, int *sockp,
            unsigned int sendsize, unsigned int recosize);
Esta rutina crea un cliente RPC para el programa remoto prognum, en versnum; el cliente utiliza UDP/IP como transporte. El programa remoto se encuentra en la dirección de Internet addr. Si addr->sin_port es cero, se establece en el puerto real en el que el programa remoto está escuchando (se consulta el servicio portmap remoto para obtener esta información). El parámetro sockp es un socket; si es RPC_ANYSOCK, esta rutina abre uno nuevo y establece sockp. El transporte UDP reenvía el mensaje de llamada en intervalos de tiempo wait hasta que se recibe una respuesta o hasta que la llamada expira. El tiempo total para que la llamada expire se especifica mediante clnt_call().
Esto permite al usuario especificar el tamaño máximo del paquete para enviar y recibir mensajes RPC basados en UDP.
void get_myaddress(struct sockaddr_in *addr);
Introduce la dirección IP de la máquina en *addr, sin consultar las rutinas de la biblioteca que manejan /etc/hosts. El número de puerto siempre se establece en htons(PMAPPORT).
struct pmaplist *pmap_getmaps(struct sockaddr_in *addr);
Una interfaz de usuario para el servicio portmap, que devuelve una lista de las asignaciones actuales de programas RPC a puertos en el host ubicado en la dirección IP *addr. Esta rutina puede devolver NULL. El comando rpcinfo -p utiliza esta rutina.
unsigned short pmap_getport(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned int protocol);
Una interfaz de usuario para el servicio portmap, que devuelve el número de puerto en el que espera un servicio que soporta el número de programa prognum, versión versnum y habla el protocolo de transporte asociado con protocol. El valor de protocol es muy probablemente IPPROTO_UDP o IPPROTO_TCP. Un valor de retorno de cero significa que la asignación no existe o que el sistema RPC no pudo contactar al servicio remoto portmap. En este último caso, la variable global rpc_createerr contiene el estado RPC.
enum clnt_stat pmap_rmtcall(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout, unsigned long *portp);
Una interfaz de usuario para el servicio portmap, que instruye a portmap en el host en la dirección IP *addr para que realice una llamada RPC en tu nombre a un procedimiento en ese host. El parámetro *portp se modificará al número de puerto del programa si el procedimiento tiene éxito. Las definiciones de otros parámetros se discuten en callrpc() y clnt_call(). Este procedimiento debe usarse para una "ping" y nada más. Consulte también clnt_broadcast().
bool_t pmap_set(unsigned long prognum, unsigned long versnum,
                int protocol, unsigned short port);
Una interfaz de usuario para el servicio portmap, que establece una asignación entre el triple [prognum,versnum,protocol] y port en el servicio portmap de la máquina. El valor de protocol es muy probablemente IPPROTO_UDP o IPPROTO_TCP. Esta rutina devuelve uno si tiene éxito, cero en caso contrario. Automáticamente realizado por svc_register().
bool_t pmap_unset(unsigned long prognum, unsigned long versnum);
Una interfaz de usuario para el servicio portmap, que destruye todas las asignaciones entre el triple [prognum,versnum,*] y puertos en el servicio portmap de la máquina. Esta rutina devuelve uno si tiene éxito, cero en caso contrario.
int registerrpc(unsigned long prognum, unsigned long versnum,
                unsigned long procnum, typeof(char *(char *)) *procname,
                xdrproc_t inproc, xdrproc_t outproc);
Registra el procedimiento procname con el paquete de servicios RPC. Si llega una solicitud para el programa prognum, versión versnum y procedimiento procnum, se llama a procname con un puntero a sus parámetros; procname debe devolver un puntero a sus resultados estáticos; inproc se utiliza para decodificar los parámetros mientras que outproc se utiliza para codificar los resultados. Esta rutina devuelve cero si el registro tuvo éxito, -1 en caso contrario.
Advertencia: los procedimientos remotos registrados de esta forma se acceden utilizando el tran UDP/IP

SVCXPRT *svctcp_create(int sock, unsigned int send_buf_size,
                       unsigned int recv_buf_size);
 Esta rutina crea un transporte de servicio RPC basado en TCP/IP, al que devuelve un puntero. El transporte está asociado con el socket sock, que puede ser RPC_ANYSOCK, en cuyo caso se crea un nuevo socket. Si el socket no está enlazado a un puerto TCP local, esta rutina lo enlaza a un puerto arbitrario. Al finalizar, xprt->xp_sock es el descriptor del socket del transporte y xprt->xp_port es el número de puerto del transporte. Esta rutina devuelve NULL si falla. Dado que RPC basado en TCP utiliza E/S en búfer, los usuarios pueden especificar el tamaño de los búferes; los valores cero eligen valores predeterminados adecuados.

Asocia
prognum y
versnum con el procedimiento de despacho del servicio,
dispatch. Si
protocol es cero, el servicio no se registra con el servicio
portmap. Si
protocol es distinto de cero, entonces se establece un mapeo de la tripleta
[prognum,versnum,protocol] a
xprt->xp_port con el servicio
portmap local (generalmente
protocol es cero, IPPROTO_UDP o IPPROTO_TCP). El procedimiento
dispatch tiene el siguiente formato:






dispatch(struct svc_req *request, SVCXPRT *xprt);








La rutina
svc_register() devuelve uno si tiene éxito y cero en caso contrario.





void svc_run(void);


Esta rutina nunca devuelve. Espera a que lleguen las solicitudes RPC y llama al procedimiento de servicio apropiado utilizando
svc_getreq() cuando llega una. Este procedimiento generalmente espera a que devuelva una llamada al sistema
select(2).





bool_t svc_sendreply(SVCXPRT *xprt, xdrproc_t outproc, char *out);


Llamada por la rutina de despacho de un servicio RPC para enviar los resultados de una llamada a procedimiento remoto. El parámetro
xprt es el identificador de transporte asociado con la solicitud;
outproc es la rutina XDR que se utiliza para codificar los resultados; y
out es la dirección de los resultados. Esta rutina devuelve uno si tiene éxito, cero en caso contrario.





void svc_unregister(unsigned long prognum, unsigned long versnum);


Elimina todos los mapeos del doble [prognum,versnum] a rutinas de despacho, y de la tripleta
[prognum,versnum,*] a número de puerto.





void svcerr_auth(SVCXPRT *xprt, enum auth_stat why);


Llamada por una rutina de despacho de servicio que se niega a realizar una llamada a procedimiento remoto debido a un error de autenticación.





void svcerr_decode(SVCXPRT *xprt);


Llamada por una rutina de despacho de servicio que no puede decodificar sus parámetros correctamente. Consulte también
svc_getargs().





void svcerr_noproc(SVCXPRT *xprt);


Llamada por una rutina de despacho de servicio que no implementa el número de procedimiento que solicita el llamador.





void svcerr_noprog(SVCXPRT *xprt);


Se llama cuando el programa deseado no está registrado con el paquete RPC. Los implementadores de servicio generalmente no necesitan esta rutina.





void svcerr_progvers(SVCXPRT *xprt, unsigned long low_vers,

                     unsigned long high_vers);


Se llama cuando la versión deseada de un programa no está registrada con el paquete RPC. Los implementadores de servicio generalmente no necesitan esta rutina.





void svcerr_systemerr(SVCXPRT *xprt);


Llamada por una rutina de despacho de servicio cuando detecta un error del sistema no cubierto por ningún protocolo en particular. Por ejemplo, si un servicio ya no puede asignar almacenamiento, puede llamar a esta rutina.





void svcerr_weakauth(SVCXPRT *xprt);


Llamada por una rutina de despacho de servicio que se niega a realizar una llamada a procedimiento remoto debido a parámetros de autenticación insuficientes. La rutina llama a
svcerr_auth(xprt, AUTH_TOOWEAK).





SVCXPRT *svcfd_create(int fd, unsigned int sendsize,

                      unsigned int recvsize);


Crea un servicio sobre cualquier descriptor de archivo abierto. Típicamente, este descriptor de archivo es un socket conectado para un protocolo de flujo como TCP.
sendsize y
recvsize indican los tamaños de los búferes de envío y recepción. Si son cero, se elige un valor predeterminado razonable.





SVCXPRT *svcraw_create(void);


Esta rutina crea un transporte de servicio RPC de juguete, al que devuelve un puntero. El transporte es en realidad un búfer dentro del espacio de direcciones del proceso, por lo que el cliente RPC correspondiente debe residir en el mismo espacio de direcciones; consulte
clntraw_create(). Esta rutina permite simular RPC y adquirir sobrecargas RPC (como tiempos de ida y vuelta), sin ninguna interferencia del kernel. Esta rutina devuelve NULL si falla.

SYNOPSIS AND DESCRIPTION


#include <rpc/rpc.h>


void svc_register(SVCXPRT *xprt, const rpcprog_t prog,


    const rpcvers_t vers,


    xdrproc_t proc,


    const char *nettype);



  

  
The svc_register() function is used to register an RPC service
      program number prog, with version number vers, with the RPC
      service package. The function proc is the dispatch function for this
      program and version. This function is called by the RPC service package
      when a caller wishes to invoke an RPC routine. The nettype
      parameter is the network type to be used for this service. If
      nettype is NULL, the default network type is used.
      This routine modifies the global variable svc_fds. Service
      implementors usually do not need this routine.




void svc_unregister(const rpcprog_t prog,


    const rpcvers_t vers);



  

  
The svc_unregister() function is used to unregister an RPC service
      program number prog, with version number vers, with the RPC
      service package. This routine modifies the global variable
      svc_fds. Service implementors usually do not need this routine.




bool_t xdr_callmsg(XDR *xdrs, struct rpc_msg *cmsg);



  

  
Used for describing RPC call messages. This routine is useful for users
      who wish to generate RPC-style messages without using the RPC
      package.




bool_t xdr_opaque_auth(XDR *xdrs, struct opaque_auth *ap);



  

  
Used for describing RPC authentication information messages. This routine
      is useful for users who wish to generate RPC-style messages without using
      the RPC package.




bool_t xdr_pmap(XDR *xdrs, struct pmap *regs);



  

  
Used for describing parameters to various portmap procedures,
      externally. This routine is useful for users who wish to generate these
      parameters without using the pmap interface.




bool_t xdr_pmaplist(XDR *xdrs, struct pmaplist **rp);



  

  
Used for describing a list of port mappings, externally. This routine is
      useful for users who wish to generate these parameters without using the
      pmap interface.




bool_t xdr_rejected_reply(XDR *xdrs, struct rejected_reply *rr);



  

  
Used for describing RPC reply messages. This routine is useful for users
      who wish to generate RPC-style messages without using the RPC
      package.




bool_t xdr_replymsg(XDR *xdrs, struct rpc_msg *rmsg);



  

  
Used for describing RPC reply messages. This routine is useful for users
      who wish to generate RPC style messages without using the RPC
      package.




void xprt_register(SVCXPRT *xprt);



  

  
After RPC service transport handles are created, they should register
      themselves with the RPC service package. This routine modifies the global
      variable svc_fds. Service implementors usually do not need this
      routine.




void xprt_unregister(SVCXPRT *xprt);



  

  
Before an RPC service transport handle is destroyed, it should unregister
      itself with the RPC service package. This routine modifies the global
      variable svc_fds. Service implementors usually do not need this
      routine.
