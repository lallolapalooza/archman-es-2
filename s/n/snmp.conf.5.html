NOMBRE

snmp.conf - archivos de configuración para las aplicaciones Net-SNMP

DESCRIPCIÓN

Las aplicaciones creadas con las bibliotecas Net-SNMP suelen utilizar uno o más archivos de configuración para controlar diversos aspectos de su funcionamiento. Estos archivos (snmp.conf y snmp.local.conf) pueden encontrarse en varias ubicaciones, como se describe en la página del manual snmp_config(5).

En particular, /etc/snmp/snmp.conf es un archivo común que contiene la configuración compartida por todos los usuarios del sistema. ~/.snmp/snmp.conf es un archivo personal, con la configuración específica de un usuario determinado.

ARCHIVOS ESPECÍFICOS DEL HOST

También se pueden cargar archivos específicos del host y se buscarán si se especifica un nombre de transporte que coincida con un archivo PATH/hosts/HOST.conf. Por ejemplo, si quisiera que un host determinado utilizara SNMPv2c por defecto, podría crear un archivo ~/.snmp/hosts/NOMBRE.conf y en él poner:

defVersion 2c

Todas las conexiones configuradas para conectarse al nombre de host NOMBRE utilizarán SNMPv2c. Consulte también el token transport a continuación para ver ejemplos adicionales específicos del host.

Los archivos de configuración específicos del host se cargan en el momento en que se abre la conexión. Por lo tanto, generalmente se cargan después de todos los demás archivos de configuración y se pueden utilizar para anular la configuración de los archivos genéricos.

Para evitar la carga de cualquier archivo de configuración específico del host, establezca "dontLoadHostConfig true" en su archivo snmp.conf.

OPCIONES DE LÍNEA DE COMANDOS

Todos los tokens descritos en este archivo también se pueden usar en la línea de comandos de las aplicaciones Net-SNMP anteponiéndoles "--". Por ejemplo, especificar --dontLoadHostConfig=true en la línea de comandos desactivará la carga de los archivos de configuración específicos del host.

NOTA IMPORTANTE

Varias de estas directivas pueden contener información sensible (como frases de contraseña). Los archivos de configuración que incluyan dichos ajustes solo deben ser legibles por el usuario correspondiente.

Además de los tokens de configuración específicos de la aplicación, existen varias directivas que se relacionan con el comportamiento estándar de la biblioteca, relevantes para la mayoría de las aplicaciones Net-SNMP. Muchas de ellas corresponden a opciones de línea de comandos estándar, que se describen en la página del manual snmpcmd(1).

Estas directivas se pueden dividir en varios grupos distintos.

COMPORTAMIENTO DEL CLIENTE

defDomain dominio de aplicación
El dominio de transporte que debe utilizarse para un tipo de aplicación determinado, a menos que se especifique otra cosa.
defTarget objetivo de dominio de aplicación
El objetivo que debe utilizarse para las conexiones a una aplicación determinada si la conexión debe estar en un dominio específico.
defaultPort PUERTO
define el puerto UDP predeterminado al que intentarán conectarse las aplicaciones cliente SNMP. Esto puede ser anulado incluyendo explícitamente un número de puerto en la especificación del AGENT. Consulte la página del manual snmpcmd(1) para más detalles.
Si no se especifica, el valor predeterminado para este token es 161.
transport ESPECIFICADOR_HOST
Este token especial debe ir en un archivo de configuración específico del nombre de host en un subdirectorio de hosts. Por ejemplo, si el archivo hosts/foo.conf existe en la ruta de búsqueda, se cargará si se utiliza un nombre de transporte de foo. Dentro del archivo foo.conf puede incluir tanto configuraciones generales de snmp.conf como una cadena especial transport para especificar el destino al que conectarse. Por ejemplo, poner:
transport tcp:foo.example.com:9876
en el archivo hosts/foo.conf hará que las aplicaciones que hagan referencia al nombre de host foo (por ejemplo, snmpget) se conecten realmente a través de TCP a foo.exmaple.com en el puerto 9876.
defVersion (1|2c|3)
define la versión predeterminada de SNMP a utilizar. Esto puede ser anulado usando la opción -v.
defCommunity CADENA
define la comunidad predeterminada a utilizar para las solicitudes SNMPv1 y SNMPv2c. Esto puede ser anulado usando la opción -c.
alias NOMBRE DEFINICIÓN
Crea un alias vinculado a NOMBRE para una definición de transporte dada. El alias puede entonces ser referido usando un prefijo alias:. Por ejemplo, una línea de "alias here udp:127.0.0.1:6161" permitiría usar un host de destino de "alias:here" en lugar de "udp:127.0.0.1:6161". Esto se vuelve más útil con direcciones de transporte complejas que involucran direcciones IPv6, etc.
dumpPacket sí
define si se debe mostrar un volcado hexadecimal de las solicitudes SNMP sin procesar enviadas y recibidas por la aplicación. Esto es equivalente a la opción -d.
doDebugging (1|0)
activa la depuración para todas las aplicaciones ejecutadas si se establece en 1.
debugTokens TOKEN[,TOKEN...]
define los tokens de depuración que deben activarse cuando se establece doDebugging. Esto es equivalente a la opción -D.
debugLogLevel (emerg|alert|crit|err|warning|notice|info|debug)
Establece el nivel de prioridad para el registro de la salida de depuración. Por defecto es debug.
16bitIDs sí
restringe los requestIDs, etc., a valores de 16 bits.
Las especificaciones SNMP definen estos campos ID como cantidades de 32 bits, y la biblioteca Net-SNMP típicamente los inicializa a valores aleatorios por seguridad. Sin embargo, algunos agentes (defectuosos) no pueden manejar valores ID mayores que 2^16; esta opción permite la interoperabilidad con dichos agentes.
clientaddr [<especificador-de-transporte>:]<dirección-de-transporte>
especifica la dirección de origen que deben utilizar las aplicaciones de línea de comandos al enviar solicitudes SNMP. Consulte snmpcmd(1) para más información sobre el formato de las direcciones.
Este valor también es utilizado por snmpd al generar notificaciones.
clientaddrUsesPort no
especifica si la opción clientaddr contiene un número de puerto. Establezca esta opción a "yes" si clientaddr contiene un número de puerto y este puerto debe utilizarse para enviar solicitudes SNMP salientes. Esta opción solo afecta a las direcciones cliente IPv4 y se ignora para las direcciones cliente IPv6.
clientRecvBuf ENTERO
especifica el tamaño deseado del búfer que se utilizará al recibir respuestas a solicitudes SNMP. Si el límite máximo del sistema operativo es inferior al valor de clientRecvBuf, se utilizará este último en su lugar. Algunas plataformas pueden decidir aumentar el tamaño del búfer realmente utilizado para la gestión interna.
Esta directiva se ignorará si la plataforma no soporta setsockopt().
clientSendBuf ENTERO
es similar a clientRecvBuf, pero se aplica al tamaño del búfer que se utiliza al enviar solicitudes SNMP.
noRangeCheck sí
desactiva la validación de los valores de varbind frente a la definición de MIB para el OID correspondiente. Esto es equivalente a la opción -Ir.
Esta directiva es principalmente relevante para el comando snmpset, pero también se aplicará a cualquier aplicación que llame a snmp_add_var() con un valor no nulo.
noTokenWarnings
desactiva las advertencias sobre tokens de archivo de configuración desconocidos.
reverseEncodeBER (1|yes|true|0|no|false)
controla cómo
w el manejo de la codificación de las solicitudes SNMP.
El comportamiento predeterminado es codificar los paquetes comenzando desde el final de la PDU y trabajando hacia atrás. Esta directiva se puede utilizar para deshabilitar este comportamiento y construir la solicitud codificada en la dirección (más obvia) hacia adelante.
Normalmente no debería ser necesario cambiar esta configuración, ya que la codificación es básicamente la misma en ambos casos, pero trabajar hacia atrás generalmente produce una codificación ligeramente más eficiente y, por lo tanto, un datagrama de red más pequeño.
dontLoadHostConfig (1|sí|verdadero|0|no|falso)
Especifica si se cargan o no los archivos de configuración específicos del host. Establézcalo en "verdadero" para desactivar la carga de los archivos de configuración específicos del host.
retries ENTERO
Especifica el número de reintentos que se utilizarán en las solicitudes.
timeout ENTERO
Especifica el tiempo de espera en segundos entre reintentos.

CONFIGURACIÓN SNMPv1/SNMPv2c

disableSNMPv1 (1|sí|verdadero|0|no|falso)
disableSNMPv2c (1|sí|verdadero|0|no|falso)
Deshabilita las versiones del protocolo en tiempo de ejecución. Se descartarán los paquetes entrantes y salientes para el protocolo.

CONFIGURACIÓN SNMPv3

disableSNMPv3 (1|sí|verdadero|0|no|falso)
Deshabilita las versiones del protocolo en tiempo de ejecución. Se descartarán los paquetes entrantes y salientes para el protocolo.
defSecurityName CADENA
define el nombre de seguridad predeterminado a utilizar para las solicitudes SNMPv3. Esto puede ser anulado usando la opción -u.
defSecurityLevel noAuthNoPriv|authNoPriv|authPriv
define el nivel de seguridad predeterminado a utilizar para las solicitudes SNMPv3. Esto puede ser anulado usando la opción -l.
Si no se especifica, el valor predeterminado para este token es noAuthNoPriv.
Nota:
authPriv solo está disponible si el software se ha compilado para utilizar las bibliotecas OpenSSL.
defPassphrase CADENA
defAuthPassphrase CADENA
defPrivPassphrase CADENA
definen las frases de contraseña de autenticación y privacidad predeterminadas a utilizar para las solicitudes SNMPv3. Estas pueden ser anuladas usando las opciones -A y -X respectivamente.
El valor defPassphrase se utilizará para las frases de contraseña de autenticación y/o privacidad si alguna de las otras directivas no se especifica.
defAuthType MD5|SHA|SHA-512|SHA-384|SHA-256|SHA-224
defPrivType DES|AES
definen los protocolos de autenticación y privacidad predeterminados a utilizar para las solicitudes SNMPv3. Estos pueden ser anulados usando las opciones -a y -x respectivamente.
Si no se especifica, las solicitudes SNMPv3 usarán por defecto autenticación MD5 y cifrado DES.
Nota:
Si el software no se ha compilado para utilizar las bibliotecas OpenSSL, entonces solo se admite la autenticación MD5. Ni la autenticación SHA ni ninguna forma de cifrado estarán disponibles.
defContext CADENA
define el contexto predeterminado a utilizar para las solicitudes SNMPv3. Esto puede ser anulado usando la opción -n.
Si no se especifica, el valor predeterminado para este token es el contexto predeterminado (es decir, la cadena vacía "").
defSecurityModel CADENA
define el modelo de seguridad a utilizar para las solicitudes SNMPv3. El valor predeterminado es "usm", que es el único modelo de seguridad ampliamente utilizado para SNMPv3.
defAuthMasterKey 0xCADENAHEX
defPrivMasterKey 0xCADENAHEX
defAuthLocalizedKey 0xCADENAHEX
defPrivLocalizedKey 0xCADENAHEX
definen las claves (hexadecimales) que se utilizarán para las comunicaciones seguras SNMPv3. Las claves SNMPv3 a menudo se derivan de una frase de contraseña, como se discute en la sección defPassphrase anterior. Sin embargo, para mejorar la seguridad, se puede generar y utilizar una clave verdaderamente aleatoria en su lugar (que normalmente tendría una mejor entropía que una contraseña, a menos que sea increíblemente larga). Las directivas son equivalentes a las opciones de línea de comandos de formato corto -3m, -3M, -3k y -3K.
Las claves localizadas son claves maestras que se han convertido en una clave única que solo es adecuada para un motor (agente) SNMP en particular. La longitud de la clave debe ser apropiada para el tipo de autenticación o cifrado que se está utilizando (claves de autenticación: MD5=16 bytes, SHA1=20 bytes; claves de privacidad: DES=16 bytes (8 bytes de los cuales se utilizan como IV y no como clave), y AES=16 bytes).
sshtosnmpsocket RUTA
Establece la ruta del socket sshtosnmp creado por una aplicación (por ejemplo, snmpd) que escucha las conexiones ssh entrantes a través del socket unix sshtosnmp.
sshtosnmpsocketperms MODO [PROPIETARIO [GRUPO]]
Establece el modo, propietario y grupo del socket sshtosnmp creado por una aplicación (por ejemplo, snmpd) que escucha las conexiones ssh entrantes a través del socket unix sshtosnmp. El socket necesita tener permisos de lectura/escritura para los usuarios SSH que tienen permitido conectarse al servicio SNMP (el acceso VACM todavía debe concederse, muy probablemente a través del modelo de seguridad TSM).
sshusername NOMBRE
Establece el nombre de usuario SSH para iniciar sesión en el sistema remoto.
sshpubkey ARCHIVO
Establece el archivo de clave pública a utilizar al conectarse a un sistema remoto.
sshprivkey ARCHIVO
Establece el archivo de clave privada a utilizar al conectarse a un sistema remoto.

COMPORTAMIENTO DEL SERVIDOR

persistentDir DIRECTORIO
define el directorio donde snmpd y snmptrapd almacenan la configuración persistente.
Si no se especifica, el directorio persistente predeterminado es /var/net-snmp
noPersistentLoad sí
noPersistentSave sí
deshabilita la carga y el guardado de la información de configuración persistente.
Nota:
Esto interrumpirá las operaciones SNMPv3 (y otro comportamiento que depende de que los cambios persistan después de reiniciar la aplicación). Úselo con precaución.
tempFilePattern PATRÓN
define una plantilla de nombre de archivo para crear archivos temporales, para manejar la entrada y salida de comandos externos de shell. Utilizado por las funciones mkstemp() y mktemp().
Si no se especifica, el patrón predeterminado es "/tmp/snmpdXXXXXX".
serverRecvBuf ENTERO
especifica el tamaño deseado del búfer que se utilizará al recibir solicitudes SNMP entrantes. Si el límite máximo del SO es inferior al valor de serverRecvBuf, se utilizará este último en su lugar. Algunas plataformas pueden decidir aumentar el tamaño del búfer utilizado realmente para la gestión interna.
Esta directiva se ignorará si la plataforma no admite setsockopt().
serverSendBuf ENTERO
es similar a serverRecvBuf, pero se aplica al tamaño del búfer utilizado al enviar respuestas SNMP.
sourceFilterType ninguno|listaAceptacion|listBloqueo
especifica si las direcciones añadidas con sourceFilterAddress se aceptan o se bloquean. El valor predeterminado es ninguno, lo que indica que los paquetes entrantes no se comprobarán contra la lista de filtros.
sourceFilterAddress DIRECCION
especifica una dirección que se añadirá a la lista de filtros de direcciones de origen. La configuración de sourceFilterType determina si las direcciones se aceptan o se bloquean.

MANEJO DE MIB

mibdirs LISTADIR
especifica una lista de directorios donde buscar archivos MIB. Esto funciona de la misma manera que la opción -M (ver snmpcmd(1) para más detalles). Tenga en cuenta que este valor puede ser anulado por la variable de entorno MIBDIRS y la opción -M.
mibs LISTAMIB
especifica una lista de módulos MIB (no archivos) que deben cargarse. Esto funciona de la misma manera que la opción -m (ver snmpcmd(1) para más detalles). Tenga en cuenta que esta lista puede ser anulada por la variable de entorno MIBS y la opción -m.

MANEJO DE MIB

mibfile ARCHIVO
especifica un archivo MIB (único) para cargar, además de la lista leída del token mibs (o equivalente de configuración). Tenga en cuenta que este valor puede ser anulado por la variable de entorno MIBFILES.
showMibErrors (1|yes|true|0|no|false)
si se deben mostrar los errores de análisis de MIB.
commentToEOL (1|yes|true|0|no|false)
si el análisis de MIB debe ser estricto con la terminación de comentarios. Muchos escritores de MIB asumen que los comentarios ASN.1 se extienden hasta el final de la línea de texto, en lugar de ser terminados por el siguiente token "--". Este token se puede utilizar para aceptar tales MIBs (estrictamente incorrectas).
Tenga en cuenta que esta directiva se llamaba anteriormente (erróneamente) strictCommentTerm, pero con un comportamiento inverso al que implica el nombre. Este token anterior todavía se acepta por compatibilidad con versiones anteriores.
mibAllowUnderline (1|yes|true|0|no|false)
si se permiten caracteres de subrayado en los nombres de objetos MIB y valores de enumeración. Este token se puede utilizar para aceptar tales MIBs (estrictamente incorrectas).
mibWarningLevel INTEGER
el nivel mínimo de advertencia de las advertencias impresas por el analizador de MIB.

CONFIGURACIÓN DE SALIDA

logTimestamp (1|yes|true|0|no|false)
Si los comandos deben registrar marcas de tiempo con su registro de errores/mensajes o no. Tenga en cuenta que la salida no se verá tan bien con marcas de tiempo si el código fuente que realiza el registro realiza un registro incremental de mensajes que no se almacenan en búfer de línea antes de pasarlos a las rutinas de registro. Esta opción solo se utiliza cuando el registro de archivos está activo.
printNumericEnums (1|yes|true|0|no|false)
Equivalente a -Oe.
printNumericOids (1|yes|true|0|no|false)
Equivalente a -On.
dontBreakdownOids (1|yes|true|0|no|false)
Equivalente a -Ob.
escapeQuotes (1|yes|true|0|no|false)
Equivalente a -OE.
quickPrinting (1|yes|true|0|no|false)
Equivalente a -Oq.
printValueOnly (1|yes|true|0|no|false)
Equivalente a -Ov.
dontPrintUnits (1|yes|true|0|no|false)
Equivalente a -OU.
numericTimeticks (1|yes|true|0|no|false)
Equivalente a -Ot.
printHexText (1|yes|true|0|no|false)
Equivalente a -OT.
hexOutputLength entero
Especifica dónde dividir la salida de cadenas hexadecimales. Establecer en 0 para deshabilitar saltos de línea. Por defecto es 16.
suffixPrinting (0|1|2)
El valor 1 es equivalente a -Os y el valor 2 es equivalente a -OS.
oidOutputFormat (1|2|3|4|5|6)
Mapea las opciones -O de la siguiente manera: -Os=1, -OS=2, -Of=3, -On=4, -Ou=5. El valor 6 no tiene una opción -O correspondiente. Suprime la salida.
extendedIndex (1|yes|true|0|no|false)
Equivalente a -OX.
noDisplayHint (1|yes|true|0|no|false)
Deshabilita el uso de información DISPLAY-HINT al analizar índices y valores para establecer. Equivalente a -Ih.
outputPrecision PRECISION
Utiliza la cadena PRECISION para permitir la modificación del formato de salida de valores. Consulte snmpcmd(1) para obtener más detalles. Equivalente a -Op (que tiene prioridad sobre el archivo de configuración).

ARCHIVOS

Archivos de configuración a nivel de sistema:
/etc/snmp/snmp.conf
/etc/snmp/snmp.local.conf
Configuración específica del usuario:
$HOME/.snmp/snmp.conf
$HOME/.snmp/snmp.local.conf
Archivos específicos del host de destino:
/etc/snmp/hosts/HOSTNAME.conf
$HOME/.snmp/hosts/HOSTNAME.conf
