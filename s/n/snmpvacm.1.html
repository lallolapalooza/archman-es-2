NOMBRE

snmpvacm - crea y mantiene entradas de control de acceso basadas en vistas SNMPv3 en una entidad de red

SINOPSIS

snmpvacm [OPCIONES COMUNES] AGENTE createSec2Group MODEL NOMBRESEGURIDAD NOMBREGRUPO
snmpvacm [OPCIONES COMUNES] AGENT deleteSec2Group MODEL NOMBRESEGURIDAD
snmpvacm [OPCIONES COMUNES] AGENT createView [-Ce] NOMBRE SUBARBOL MASCARA
snmpvacm [OPCIONES COMUNES] AGENT deleteView NOMBRE SUBARBOL
snmpvacm [OPCIONES COMUNES] AGENT createAccess NOMBREGRUPO [PREFIJOCONTEXTO] MODEL NIVEL COINCIDENCIACONTEXTO VISTALEIDA VISTAESCRITURA VISTANOTIFICACION
snmpvacm [OPCIONES COMUNES] AGENT deleteAccess NOMBREGRUPO [PREFIJOCONTEXTO] MODEL NIVEL
snmpvacm [OPCIONES COMUNES] AGENT createAuth NOMBREGRUPO [PREFIJOCONTEXTO] MODEL NIVEL TIPOAUNT CONCIDENTE CONTEXTO VISTA
snmpvacm [OPCIONES COMUNES] AGENT deleteAuth NOMBREGRUPO [PREFIJOCONTEXTO] MODEL NIVEL TIPOAUNT

DESCRIPCIÓN

snmpvacm es una aplicación SNMP que puede utilizarse para realizar un mantenimiento sencillo de las tablas del Módulo de Control Basado en Vistas (VACM) de un agente SNMP. Las especificaciones de VACM de SNMPv3 (véase RFC2575) definen varias tablas para especificar grupos de usuarios, vistas MIB y configuraciones de acceso autorizadas. Estos comandos de snmpvacm crean o eliminan eficazmente filas en la tabla apropiada de estas tablas y coinciden con las directivas de configuración equivalentes que se documentan en la página del manual snmpd.conf(5).

Una explicación más completa de cómo funcionan estos comandos se puede encontrar en las FAQ del proyecto.

SUB-COMANDOS

createSec2Group MODEL NOMBRESEGURIDAD NOMBREGRUPO

Crea una entrada en la tabla de nombre de seguridad a grupo de SNMPv3. Esta tabla permite aplicar una única entrada de control de acceso a varios usuarios (o 'principales'), y se indexa mediante los valores del modelo de seguridad y el nombre de seguridad.

MODEL

Un entero que representa el modelo de seguridad, tomando uno de los siguientes valores:
1 - reservado para SNMPv1
2 - reservado para SNMPv2c
3 - Modelo de Seguridad Basado en Usuarios (USM)

NOMBRESEGURIDAD

Una cadena que representa el nombre de seguridad para un principal (representado en un formato independiente del modelo de seguridad). Para solicitudes basadas en USM, el nombre de seguridad es el mismo que el nombre de usuario.

NOMBREGRUPO

Una cadena que identifica el grupo al que debe pertenecer esta entrada (es decir, el par nombre de seguridad/modelo). Este nombre de grupo se referenciará luego en la tabla de acceso (véase createAccess más abajo).

deleteSec2Group MODEL NOMBRESEGURIDAD

Elimina una entrada de la tabla de nombre de seguridad a grupo de SNMPv3, eliminando así la configuración de control de acceso para el principal dado. La entrada a eliminar se indexa por los valores MODEL y NOMBRESEGURIDAD, que deben coincidir con los utilizados en el comando createSec2Group correspondiente (o su equivalente).

createView [-Ce] NOMBRE SUBARBOL MASCARA

Crea una entrada en la tabla de vistas MIB de SNMPv3. Una vista MIB consta de una familia de subárboles de vista que pueden incluirse individualmente (ocasionalmente) o excluirse de la vista. Cada subárbol de vista se define por una combinación de un subárbol OID junto con una máscara de cadena de bits. La tabla de vistas se indexa por el nombre de la vista y los valores OID del subárbol.

[-Ce]

Una bandera opcional para indicar que este subárbol de vista debe excluirse de la vista nombrada. Si no se especifica, el valor predeterminado es incluir el subárbol en la vista. Al construir una vista a partir de una mezcla de subárboles incluidos y excluidos, los subárboles excluidos deben definirse primero, especialmente si la vista nombrada ya se referencia en una o más entradas de acceso.

NOMBRE

Una cadena que identifica una vista MIB particular, de la cual este subárbol OID/máscara forma parte (posiblemente la única parte).

SUBARBOL

El OID que define la raíz del subárbol a añadir (o excluir de) la vista nombrada.

MASCARA

Una máscara de bits que indica qué sub-identificadores del OID del subárbol asociado deben considerarse significativos.

deleteView NOMBRE SUBARBOL

Elimina una entrada de la tabla de vistas SNMPv3, eliminando así el subárbol de la vista MIB dada. La eliminación del subárbol final (o único) resultará en la eliminación de la vista. La entrada a eliminar se indexa por los valores NOMBRE y SUBARBOL, que deben coincidir con los utilizados en el comando createView correspondiente (o su equivalente).

Al eliminar subárboles de una vista mixta (es decir, que contiene subárboles incluidos y excluidos), los subárboles incluidos deben eliminarse primero.

createAccess NOMBREGRUPO [PREFIJOCONTEXTO] MODEL NIVEL COINCIDENCIACONTEXTO VISTALEIDA VISTAESCRITURA VISTANOTIFICACION

Crea una entrada en la tabla de acceso de SNMPv3, permitiendo así un cierto nivel de acceso a vistas MIB particulares para los principales del grupo especificado (con los niveles y modelo de seguridad adecuados en la solicitud). La tabla de acceso se indexa por el nombre del grupo, el prefijo de contexto, el modelo de seguridad y los valores del nivel de seguridad.

NOMBREGRUPO

El nombre del grupo al que se aplica esta entrada de acceso (según lo configurado por un comando createSec2Group o equivalente)

PREFIJOCONTEXTO

Una cadena que representa un nombre de contexto (o colección de nombres de contexto) al que se aplica esta entrada de acceso. La interpretación de esta cadena depende del valor del campo COINCIDENCIACONTEXTO (véase más abajo).
Si se omite, esto será por defecto el contexto nulo "".

MODEL

Un entero que representa el modelo de seguridad, tomando uno de los siguientes valores:
1 - reservado para SNMPv1
2 - reservado para SNMPv2c
3 - Modelo de Seguridad Basado en Usuarios (USM)

NIVEL

Un entero que representa el nivel de seguridad mínimo, tomando uno de los siguientes valores:
1 - noAuthNoPriv
2 - authNoPriv
3 - authPriv
Esta entrada de acceso se aplicará a solicitudes de este nivel o superior (donde authPriv es superior a authNoPriv, que a su vez es superior a noAuthNoPriv).

COINCIDENCIACONTEXTO

Indica cómo interpretar el valor PREFIJOCONTEXTO. Si este campo tiene el valor '1' (que representa 'exacto'), entonces el nombre de contexto de una solicitud debe coincidir exactamente con el valor PREFIJOCONTEXTO para que esta entrada de acceso sea aplicable a esa solicitud.
Si este campo tiene el valor '2' (que representa 'prefijo'), entonces la subcadena inicial del nombre de contexto de una solicitud debe coincidir con el valor PREFIJOCONTEXTO para que esta entrada de acceso sea aplicable a esa solicitud. Esto proporciona una forma simple de comodín.

VISTALEIDA

El nombre de la vista MIB (configurada mediante createView o equivalente) que define los objetos MIB para los cuales esta solicitud puede solicitar los valores actuales.
Si no existe una vista con este nombre, no se concede acceso de lectura.

VISTAESCRITURA

El nombre de la vista MIB (configurada mediante createView o equivalente) que define los objetos MIB para los cuales esta solicitud puede potencialmente ESTABLECER nuevos valores.
Si no existe una vista con este nombre, no se concede acceso de escritura.

VISTANOTIFICACION

El nombre de la vista MIB (configurada mediante createView o equivalente) que define los objetos MIB que pueden incluirse en una solicitud de notificación.
Si no existe una vista con este nombre, no se conceden notificaciones.

deleteAccess NOMBREGRUPO [PREFIJOCONTEXTO] MODEL NIVEL

Elimina una entrada de la tabla de acceso de SNMPv3, eliminando así los privilegios de acceso para el grupo especificado. La entrada a eliminar se indexa por el NOMBREGRUPO, PREFIJOCONTEXTO, MODEL y NIVEL, que deben coincidir con los utilizados en el comando createAccess correspondiente (o su equivalente).

createAuth NOMBREGRUPO [PREFIJOCONTEXTO] MODEL NIVEL TIPOAUNT COINCIDENTE CONTEXTO VISTA

Crea una entrada en la tabla de autorización de SNMPv3. Esta tabla especifica las vistas MIB que se pueden utilizar para determinar si una solicitud puede ser autorizada para acceder a determinados objetos MIB (y qué nivel de acceso se permite).

NOMBREGRUPO

El nombre del grupo al que se aplica esta entrada de autorización.

PREFIJOCONTEXTO

El prefijo de contexto (o colección de prefijos de contexto) que se aplica a esta entrada.
Si se omite, se utilizará el contexto nulo.

MODEL

El modelo de seguridad (1, 2 o 3).

NIVEL

El nivel de seguridad mínimo (1, 2 o 3).

TIPOAUNT

El tipo de autorización. Actualmente, solo se admite 'any'.

COINCIDENTE CONTEXTO

El tipo de coincidencia de contexto ('exact' o 'prefix').

VISTA

El nombre de la vista MIB que se utilizará para la autorización.

deleteAuth NOMBREGRUPO [PREFIJOCONTEXTO] MODEL NIVEL TIPOAUNT

Elimina una entrada de la tabla de autorización de SNMPv3.

Los parámetros deben coincidir con los utilizados en el comando createAuth correspondiente (o su equivalente).

OPCIONES COMUNES

Las opciones comunes se enumeran en snmpcmd(5).

EJEMPLOS

Para permitir que el usuario 'fred' del grupo 'adminGroup' tenga acceso de lectura y escritura a la vista MIB llamada 'myView' a través de USM con el nivel de seguridad 'authPriv':

snmpvacm localhost createSec2Group usm fred adminGroup
snmpvacm localhost createAccess adminGroup '' usm 3 exact myView myView none

Para permitir que el usuario 'guest' del grupo 'users' tenga acceso de lectura a la vista MIB 'systemView' a través de SNMPv2c:

snmpvacm localhost createSec2Group v2c guest users
snmpvacm localhost createAccess users '' v2c 1 exact systemView systemView none

NAME

snmpvacm — interact with the SNMPv1/v2c Access Control (VACM) information base

SYNOPSIS

snmpvacm [-h localhost] [-c community] [-v1|-v2c] [-C configname] SUB-COMMAND ARGUMENTS...

snmpvacm [-h localhost] [-u user] [-n context] [-l level] [-a proto] [-x proto] [-v3] [-C configname] SUB-COMMAND ARGUMENTS...

DESCRIPTION

The snmpvacm command can be used to examine and modify the SNMPv1/v2c Access Control (VACM) information stored in the agent's configuration file (usually snmpd.conf(5)). This information is used to control access to the MIB tree.

The VACM model involves the following concepts:

Security Model
The protocol used for authentication and encryption (e.g. SNMPv1, SNMPv2c, SNMPv3).
Security Level
The level of security provided by the security model (noAuthNoPriv, authNoPriv, authPriv).
Security Name
A name that identifies the principal making the request. For SNMPv1 and SNMPv2c, this is the community string. For SNMPv3, this is the username.
Group Name
A name that groups together principals with similar access rights.
Context Name
The name of the MIB view that the request is intended for.
View Name
A name identifying a specific MIB view (a subset of the MIB tree).

The snmpvacm command manipulates the tables that define the relationships between these concepts.

SUB-COMMANDS

The following sub-commands are available:

createSec2Group MODEL SECURITYNAME GROUPNAME

Create a mapping between a security model, security name and a group name. For example, to map the SNMPv1 community string `public' to the group `mygroup', you would use:

snmpvacm localhost createSec2Group 1 public mygroup

The first argument specifies the security model: 0 for SNMPv1, 1 for SNMPv2c, and 2 for SNMPv3.

deleteSec2Group MODEL SECURITYNAME [GROUPNAME]

Delete a mapping between a security model, security name and group name. If GROUPNAME is omitted, all mappings for the given MODEL and SECURITYNAME will be deleted.

createView VIEWNAME TYPE OIDMASK

Create a MIB view. The view is identified by VIEWNAME. TYPE can be EXCLUDED or INCLUDED. OIDMASK specifies the MIB objects that are included or excluded. OIDMASK is specified as a dotted OID string, optionally followed by a mask length.

createView allTree        included  .1
createView systemView     included  .1.3.6.1.2.1.1
createView limitedView    excluded  .1.3.6.1.2.1.1.5.0/24

See snmpd.conf(5) for a detailed explanation of OID masks.

deleteView VIEWNAME TYPE OIDMASK

Delete a MIB view definition.

createAccess GROUPNAME [CONTEXTPREFIX] MODEL LEVEL VIEW

Create an entry in the standard SNMP VACM access table. This authorizes access to a MIB view for principals in a specified group, using a specific security model and level. The interpretation of GROUPNAME, MODEL, LEVEL and VIEW are the same as for the createView directive.

CONTEXTPREFIX

If specified, this restricts the access control entry to apply only to contexts with this prefix. If omitted, the entry applies to all contexts.

MODEL

The security model to which this access control entry applies. 0 = SNMPv1
1 = SNMPv2c
2 = SNMPv3

LEVEL

The security level to which this access control entry applies. 0 = noAuthNoPriv
1 = authNoPriv
2 = authPriv

VIEW

The name of the MIB view (as defined by createView) to which access is being granted.

Note that this aspect of access control is not currently supported.

deleteAccess GROUPNAME [CONTEXTPREFIX] MODEL LEVEL

Delete an entry from the SNMPv3 access table, thus removing the specified access control settings. The entry to be removed is indexed by the group name, context prefix, security model and security level values, which should match those used in the corresponding createAccess command (or equivalent).

createAuth GROUPNAME [CONTEXTPREFIX] MODEL LEVEL AUTHTYPE CONTEXTMATCH VIEW

Create an entry in the Net-SNMP extension to the standard access table, thus allowing a certain type of access to the MIB view for the principals in the specified group. The interpretation of GROUPNAME, CONTEXTPREFIX, MODEL, LEVEL and CONTEXTMATCH are the same as for the createAccess directive. The extension access table is indexed by the group name, context prefix, security model, security level and authtype values.

AUTHTYPE

The style of access that this entry should be applied to. See snmpd.conf(5) and snmptrapd.conf(5) for details of valid tokens.

VIEW

The name of the MIB view (as set up by createView or equivalent) defining the MIB objects for which this style of access is authorized.

deleteAuth GROUPNAME [CONTEXTPREFIX] MODEL LEVEL AUTHTYPE

Delete an entry from the extension access table, thus removing the specified access control settings. The entry to be removed is indexed by the group name, context prefix, security model, security level and authtype values, which should match those used in the corresponding createAuth command (or equivalent).

Note that snmpget REQUIRES an argument specifying the agent to query as described in the .I snmpcmd(1) manual page.

EXAMPLES

Given a pre-existing user dave (which could be set up using the snmpusm(1) command), we could configure full read-write access to the whole OID tree using the commands:

snmpvacm localhost createSec2Group 3 dave RWGroup
snmpvacm localhost createView all .1 80
snmpvacm localhost createAccess RWGroup 3 1 1 all all none

This creates a new security group named "RWGroup" containing the SNMPv3 user "dave", a new view "all" containing the full OID tree based on .iso(1) , and then allows those users in the group "RWGroup" (i.e. "dave") both read- and write-access to the view "all" (i.e. the full OID tree) when using authenticated SNMPv3 requests.

As a second example, we could set up read-only access to a portion of the OID tree using the commands:

snmpvacm localhost createSec2Group 3 wes ROGroup
snmpvacm localhost createView sysView system fe
snmpvacm localhost createAccess ROGroup 3 0 1 sysView none none

This creates a new security group named "ROGroup" containing the (pre-existing) user "wes", a new view "sysView" containing just the OID tree based on .iso(1).org(3).dod(6).inet(1).mgmt(2).mib-2(1).system(1) , and then allows those users in the group "ROGroup" (i.e. "wes") read-access, but not write-access to the view "sysView" (i.e. the system group).

EXIT STATUS

The following exit values are returned:

0 - Successful completion

1 - A usage syntax error (which displays a suitable usage message) or a request timeout.

2 - An error occurred while executing the command (which also displays a suitable error message).

LIMITATIONS

This utility does not support the configuration of new community strings, so is only of use for setting up new access control for SNMPv3 requests. It can be used to amend the access settings for existing community strings, but not to set up new ones.

The use of numeric parameters for secLevel and contextMatch parameters is less than intuitive. These commands do not provide the full flexibility of the equivalent config file directives.

There is (currently) no equivalent to the one-shot configure directives rouser and rwuser.
