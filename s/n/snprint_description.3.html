DESCRIPCIÓN

Las funciones que manejan los módulos MIB se agrupan en cuatro grupos: los que se encargan de la inicialización y el cierre, los de lectura y análisis de archivos MIB, los de búsqueda en el árbol MIB y las rutinas de salida.

Inicialización y Cierre

add_mibdir se utiliza para añadir el directorio especificado a la ruta de ubicaciones que se buscan para encontrar archivos que contienen módulos MIB. Tenga en cuenta que esto no carga realmente los módulos MIB ubicados en ese directorio, sino que es simplemente un paso de inicialización para hacerlos disponibles para netsnmp_read_module. Esta función devuelve el recuento de archivos encontrados en el directorio, o un -1 si hay un error. Debe llamarse *antes* de invocar netsnmp_init_mib.

netsnmp_init_mib configura la ruta de búsqueda de directorios MIB (utilizando add_mibdir), prepara el marco interno de MIB y luego carga los módulos MIB apropiados (utilizando netsnmp_read_module y read_mib). Consulte la sección VARIABLES DE ENTORNO para obtener detalles.
Debe llamarse antes que cualquier otra rutina que manipule o acceda al árbol MIB (pero después de cualquier llamada adicional a add_mibdir).

shutdown_mib borrará la información que fue recopilada por netsnmp_read_module, add_mibdir y add_module_replacement. Se recomienda encarecidamente no invocar shutdown_mib mientras haya sesiones SNMP activamente gestionadas.

Lectura y Análisis de MIBs

netsnmp_read_module toma el nombre de un módulo MIB (que no necesariamente tiene que ser el mismo que el nombre del archivo que contiene el módulo), lo localiza dentro de la lista configurada de directorios MIB y carga las definiciones del módulo en el árbol MIB activo. También carga cualquier módulo MIB listado en la cláusula IMPORTS de este módulo.

read_mib es similar, pero toma el nombre del archivo que contiene el módulo MIB. Tenga en cuenta que este archivo no necesita estar ubicado dentro de la lista de búsqueda de directorios MIB (aunque cualquier módulo listado en la cláusula IMPORTS sí lo está).

read_all_mibs leerá todos los módulos MIB encontrados en la lista de búsqueda de directorios MIB.

En general, el analizador es silencioso sobre las rarezas que ve en los archivos MIB. Para que se informen las advertencias, llame a snmp_set_mib_warnings con un nivel de 1 (o 2 para aún más advertencias).

add_module_replacement puede usarse para permitir que los nuevos módulos MIB obsoleten a los antiguos, sin necesidad de modificar las cláusulas IMPORTS de otros módulos. Toma los nombres de los módulos antiguos y nuevos, junto con una indicación de qué partes del módulo antiguo se ven afectadas.

tag len carga el nuevo módulo cuando:
NULL 0 siempre (el módulo antiguo es un subconjunto estricto del
nuevo)
nombre 0 solo para la etiqueta dada
nombre distinto de 0 para cualquier identificador con este prefijo
También puede utilizarse para manejar errores en los identificadores de módulo utilizados en las cláusulas IMPORTS de MIB (como referirse a *RFC1213* en lugar de *RFC1213-MIB*).

Búsqueda en el Árbol MIB

read_objid toma una cadena que contiene una versión textual de un identificador de objeto (en forma numérica o descriptiva) y la transforma en la lista correspondiente de subidentificadores. Esto se devuelve en el parámetro *output*, con el número de subidentificadores devuelto a través de *out_len*. Cuando se llama, *out_len* debe contener la longitud máxima de la matriz *output*. Si se están procesando varios identificadores de objeto, esta longitud debe restablecerse antes de cada llamada. Esta función devuelve un valor de 1 si tiene éxito en analizar la cadena y 0 en caso contrario.

snmp_parse_oid es similar, pero devuelve un puntero al buffer OID analizado (o NULL).

get_module_node toma un descriptor y el nombre de un módulo, y devuelve la lista OID correspondiente, de la misma manera que read_objid anteriormente.
Si el nombre del módulo se especifica como "ANY", esta rutina asumirá que el descriptor proporcionado es único dentro del árbol y devolverá la entrada que coincida. Si esta suposición no es válida, el comportamiento sobre qué variable se devuelve depende de la implementación.

Salida

print_mib imprimirá una representación del árbol MIB activo actual al puntero FILE especificado.

print_objid tomará un identificador de objeto (como el devuelto por read_objid, snmp_parse_oid o get_module_node) e imprimirá la forma textual de ese OID en la salida estándar.

fprint_objid hace lo mismo, pero imprime en el puntero FILE especificado por el parámetro inicial.

snprint_objid imprime la misma información en el buffer apuntado por *buf*, que tiene una longitud de *len*. Devuelve el número de caracteres impresos, o -1 si el buffer no era lo suficientemente grande. En este último caso, *buf* típicamente contendrá una versión truncada de la información (pero este comportamiento no está garantizado).

print_description, fprint_description y snprint_description toman un identificador de objeto similar e imprimen una versión de la definición MIB para ese objeto, junto con el OID completo. El argumento *width* controla cómo se distribuye el OID.

snprint_description(3)

NAME

snprint_description, fprint_description, snmp_set_save_descriptions, init_mib, read_mib, read_all_mibs, netsnmp_read_module ― parse and load MIB modules

SYNOPSIS

#include <net-snmp/mib_api.h>
#include <net-snmp/net-snmp-includes.h>

char *
snprint_description(oid *oidin, size_t oidInLen, char *buf, size_t bufLen);
char *
fprint_description(FILE *fp, oid *oidin, size_t oidInLen, char *buf, size_t bufLen);
void
snmp_set_save_descriptions(int setting);
int
init_mib(void);
int
read_mib(const char *filename);
int
read_all_mibs(void);
int
netsnmp_read_module(const char *modulename);

DESCRIPTION

The primary purpose of MIBs (Management Information Bases) is to describe the kinds of information that can be managed on a particular device. This information is organised in a tree-like structure, where each node has a unique identifier (an OID, Object Identifier).

The Net-SNMP library provides functionality to parse these MIBs, load them into memory and to retrieve textual information about specific OIDs, such as their textual description, name and syntax.

MIB files are typically stored in text files and are parsed and loaded into memory by calling init_mib(). This function initialises the MIB parsing code, and then attempts to load all MIB modules that are listed in the MIBS environment variable (see below). If the MIBS variable is not set, a default set of MIB modules are loaded. This includes modules defining basic SNMP information such as IP-MIB, IF-MIB, SNMPv2-MIB, RFC1213-MIB etc.

If you only want to load a specific MIB file, you can use read_mib(filename). This will parse and load the specified MIB file, and any modules that it imports from. It does not affect the MIBS environment variable setting.

To load all MIB modules found in the MIB search path (see MIBDIRS below), you can call read_all_mibs().

netsnmp_read_module(modulename) reads a single MIB module specified by modulename. It will also load any modules that it IMPORTS from.

By default, the Net-SNMP library caches the textual descriptions of MIB objects. This means that when an OID is encountered for the first time, its description is parsed from the loaded MIB modules and stored in memory. Subsequent calls for the same OID will retrieve the stored description directly from memory, making them much faster.

However, if you plan to *only* use the textual descriptions of OIDs (e.g. to display them to the user), and do not require the full MIB parsing capabilities, you can disable the caching and loading of MIB descriptions by calling snmp_set_save_descriptions(0) *before* calling init_mib() (or similar).

snprint_description() and fprint_description() are used to retrieve the textual description for a given OID. They take an OID value (oidin) and its length (oidInLen) as input, and will attempt to find the corresponding textual description from the loaded MIB modules. The output is written to the provided buffer (buf) of size bufLen. snprint_description() writes to a standard character buffer, while fprint_description() writes to a given FILE pointer. Both functions return a pointer to the beginning of the buffer (buf) on success, or NULL on failure.

If the textual description is not found, a string indicating this will be returned instead.

Note: If you are using snmp_set_save_descriptions(0), then these functions will not work, as no MIB descriptions will have been loaded.

It is recommended to call snmp_set_save_descriptions(1) to enable saving of descriptions, and then call init_mib() (or similar) to load the MIB modules. Then you can use snprint_description(3) (or similar).

ENVIRONMENT VARIABLES

The main use of environmental variables with respect to these API calls is to configure which MIB modules should be loaded, and where they are located.

MIBDIRS
A colon separated list of directories to search for MIB modules.
Default: /usr/share/snmp/mibs
Used by init_mib, netsnmp_read_module, read_all_mibs and (implicitly) by read_mib.
MIBS
A colon separated list of MIB modules to load.
The default list of modules will depend on how the Net-SNMP software was originally compiled, but is typically:
IP-MIB:IF-MIB:TCP-MIB:UDP-MIB:SNMPv2-MIB:RFC1213-MIB:UCD-SNMP-MIB:HOST-RESOURCES-MIB
If the value of the MIBS environmental variable starts with a '+' character, then these MIB modules will be added to the default list. Otherwise these modules (plus any that they IMPORT from) will be loaded instead of the default list.
If the MIBS environmental variable has the value ALL then read_all_mibs will be called to load the full collection of all available MIB modules.
Used by init_mib only.
MIBFILES
A colon separated list of files to load.
Default: (none)
Used by init_mib only.
