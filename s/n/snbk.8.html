SNBK(8) Gestión de instantáneas de sistemas de archivos SNBK(8)

NOMBRE

snbk - Programa de línea de comandos para copias de seguridad de instantáneas de snapper

SINOPSIS

snbk [opciones-globales] comando [argumentos-del-comando]

snbk {--help}

DESCRIPCIÓN

Snbk es un programa de línea de comandos para copias de seguridad de instantáneas de snapper. Puede transferir y eliminar instantáneas de copia de seguridad en sistemas de archivos btrfs locales y remotos.

CONCEPTOS

Configuraciones de copia de seguridad

Para cada configuración de snapper, puede haber varias configuraciones de copia de seguridad. Cada configuración de copia de seguridad define copias de seguridad de las instantáneas de snapper en una ubicación, ya sea local o remota, consulte snapper-backup-configs(5) para ver las opciones posibles.

Estados de instantánea

Cada instantánea tiene un estado en el origen y en el destino. Los valores posibles para el origen son:

(vacío)

La instantánea falta y, por lo tanto, se considera obsoleta en el destino. Se eliminará en el destino mediante el próximo comando de eliminación.

solo-lectura

La instantánea es de solo lectura.

lectura-escritura

La instantánea es de lectura-escritura y, por lo tanto, no se puede respaldar.

Los valores posibles para el destino son:

(vacío)

La instantánea falta. Si la instantánea de origen es de solo lectura, se transferirá al destino mediante el próximo comando de transferencia.

válida

La instantánea es válida. Eso implica que es de solo lectura.

inválida

La instantánea es inválida. O la UUID recibida es incorrecta o es de lectura-escritura. Eso puede ocurrir si la transferencia se interrumpió. El próximo comando de transferencia intentará transferir la instantánea nuevamente.

OPCIONES GLOBALES

-q, --quiet

Suprime la salida normal. Sin embargo, los mensajes de error seguirán mostrándose.

-v, --verbose

Aumenta la verbosidad.

--debug

Activa la depuración.

--utc

Muestra fechas y horas en UTC. Por defecto, se utiliza la hora local.

--iso

Muestra fechas y horas en formato ISO. El formato ISO se utiliza siempre para salidas legibles por máquina.

-t, --table-style estilo

Especifica el estilo de tabla. El estilo de tabla se identifica por un número entero.

--machine-readable formato

Especifica un formato de salida legible por máquina. Las opciones posibles son csv y json.

--csvout

Establece el formato de salida CSV. Para algunos comandos, la salida CSV contiene más información que la salida de tabla predeterminada. Consulte RFC 4180[1] para obtener detalles, excepto que las líneas terminan con LF, no CR+LF.

--jsonout

Establece el formato de salida JSON. Para algunos comandos, la salida JSON contiene más información que la salida de tabla predeterminada.

--separator carácter

Especifica el carácter separador para el formato de salida CSV.

--no-headers

Suprime las cabeceras para el formato de salida CSV.

-b, --backup-config nombre

Utiliza la configuración especificada en lugar de todas las configuraciones.

--no-dbus

Opera sin conexión DBus.

Úselo con precaución.

--target-mode nombre

Opera solo en configuraciones de copia de seguridad con el modo de destino especificado.

--automatic

Opera solo en configuraciones de copia de seguridad que tengan activada la bandera automática.

--version

Muestra la versión y sale.

COMANDOS

Snbk proporciona una serie de comandos. Cada comando acepta las opciones enumeradas en la sección OPCIONES GLOBALES. Estas opciones deben especificarse antes del nombre del comando. Además, muchos comandos tienen argumentos específicos, que se enumeran en esta sección. Estos argumentos específicos del comando deben especificarse después del nombre del comando.

help

Muestra un texto de ayuda corto.

list-configs

Lista las configuraciones disponibles.

list (ls)

Lista las instantáneas.

transfer [número]

Transfiere todas las instantáneas faltantes o la instantánea especificada al destino.

delete (remove|rm) [número]

Elimina todas las instantáneas obsoletas o la instantánea especificada del destino.

transfer-and-delete

Combina transferencia y eliminación.

RESTOREAR

Hasta ahora, una restauración debe hacerse manualmente. Hay varios métodos para hacer una restauración, por ejemplo, la copia de seguridad se puede montar y luego copiar, o se puede usar rsync. Aquí proporcionamos un ejemplo sobre cómo usar btrfs send y receive para restaurar una instantánea en el sistema de origen. En general, usar btrfs send y receive es un poco complicado.

Cuando se usa target-mode local:

# mkdir /.snapshots/42
# cp /backups/root/42/info.xml /.snapshots/42/
# btrfs send /backups/root/42/snapshot | btrfs receive /.snapshots/42

Cuando se usa target-mode ssh-push:

# mkdir /.snapshots/42
# scp backups.example.com:/backups/eberich/root/42/info.xml /.snapshots/42
# ssh backups.example.com btrfs send /backups/eberich/root/42/snapshot | btrfs receive /.snapshots/42

Si el sistema fue reinstalado, desafortunadamente, en general no es posible utilizar simplemente la instantánea restaurada como la nueva instantánea predeterminada, ya que algunos archivos, como /etc/fstab, probablemente necesiten modificaciones. Además, desafortunadamente, para subvolúmenes distintos de root, no se admite la reversión.

Si hay instantáneas en el origen, para acelerar la operación, también puede usar la opción -p para btrfs send.

NOTAS

El contenido de las instantáneas transferidas no debe modificarse en el sistema de origen. Normalmente, esto está garantizado ya que las instantáneas son de solo lectura. Pero es posible cambiar las instantáneas a lectura-escritura. Esto puede causar errores durante las transferencias en el futuro.

PERMISOS

Dado que el target-mode ssh-push necesita permisos de root en el destino, se recomienda usar una máquina dedicada o un contenedor como destino.

ARCHIVOS

/etc/snapper/backup-configs

Directorio que contiene los archivos de configuración.

ESTADO DE SALIDA

Normalmente, el estado de salida es 0. Si ocurrió un error, el estado de salida es 1.

snapper(8)

NAME

snapper — create and manage filesystem snapshots

SYNOPSIS

snapper [OPTIONS] COMMAND

DESCRIPTION

Snapper is a tool for managing filesystem snapshots. It uses the filesystem snapshot capabilities of Btrfs and ZFS. Snapper can be used to create, delete, compare and restore snapshots.

CONCEPTS

Snapper works with snapshot subvolumes on a Btrfs or ZFS filesystem. Each snapshot is a point-in-time copy of the filesystem. Snapper automates the creation of these snapshots. It can also be configured to automatically delete older snapshots based on predefined criteria. This allows you to keep a history of your filesystem, making it easy to revert changes.

GLOBAL OPTIONS

The following options are available for all snapper commands:

-c, --config <config>
Use the specified configuration. If not specified, the default configuration for the current filesystem is used.
-h, --help
Show help message and exit.
-v, --verbose
Increase verbosity.
-q, --quiet
Decrease verbosity.

COMMANDS

Snapper supports the following commands:

create-snapshot [OPTIONS] <TARGET>
Create a new snapshot of the specified target directory.
delete-snapshot [OPTIONS] <SNAPSHOT...>
Delete the specified snapshot(s).
list-snapshots [OPTIONS]
List available snapshots.
compare-snapshots <SNAPSHOT1> <SNAPSHOT2>
Compare two snapshots and show the differences.
restore-snapshot <SNAPSHOT>
Restore the specified snapshot. This will revert the filesystem to the state of the snapshot.
mountpoint [OPTIONS]
Show the mountpoint of the snapshot root.
status [OPTIONS]
Show the status of the snapshot configuration.
get-config [CONFIG]
Get configuration values.
set-config [CONFIG] <KEY>=<VALUE>...
Set configuration values.

RESTORE

The restore-snapshot command reverts the filesystem to the state of the specified snapshot. This operation is irreversible. Make sure you have backed up any important data before restoring.

NOTES

Snapper requires Btrfs or ZFS filesystems to be mounted with the snaps or compr mount options respectively. The snapshot subvolumes should be located in the .snapshots directory at the root of the filesystem.

PERMISSIONS

Snapper requires root privileges to create and delete snapshots, and to restore the filesystem. Regular users can list snapshots and compare them.

FILES

/etc/snapper/snapper.conf
Global configuration file for snapper.
/etc/snapper/configs/<config>
Configuration file for a specific snapshot configuration.

EXIT STATUS

Snapper returns 0 on success, and non-zero on failure.

HOMEPAGE

http://snapper.io

AUTHORS
