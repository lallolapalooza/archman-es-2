NOMBRE

snmptrapd - Recibe y registra mensajes SNMP trap.

SINOPSIS

snmptrapd [OPCIONES] [DIRECCIONES DE ESCUCHA]

DESCRIPCIÓN

snmptrapd es una aplicación SNMP que recibe y registra mensajes SNMP TRAP e INFORM.

Nota: el valor predeterminado es escuchar en el puerto UDP 162 en todas las interfaces IPv4. Dado que 162 es un puerto privilegiado, snmptrapd normalmente debe ejecutarse como root.

OPCIONES

-a
Ignorar traps de authenticationFailure.
-A
Añadir al archivo de registro en lugar de truncarlo.

Tenga en cuenta que esto debe venir antes de cualquier opción -Lf a la que deba aplicarse.

-c ARCHIVO
Leer ARCHIVO como un archivo de configuración (o una lista de archivos de configuración separados por comas).
-C
No leer ningún archivo de configuración excepto el especificado opcionalmente por la opción -c.
-d
Volcar (en hexadecimal) los paquetes SNMP enviados y recibidos.
-D[TOKEN[,...]]
Activar la salida de depuración para el/los TOKEN dado(s). Pruebe con ALL para obtener una salida extremadamente detallada.
-f
No hacer fork() desde la shell que lo llama.
-F FORMATO
Al registrar en la salida estándar, usar el formato de la cadena FORMATO. Ver la sección ESPECIFICACIONES DE FORMATO para más detalles.
-h, --help
Mostrar un breve mensaje de uso y luego salir.
-H
Mostrar una lista de directivas de archivos de configuración entendidas por el demonio de traps y luego salir.
-I [-]LISTAINICIALIZACIÓN
Especifica qué módulos deben (o no deben) inicializarse cuando se inicia snmptrapd. Si la LISTAINICIALIZACIÓN separada por comas va precedida por un '-', es la lista de módulos que no deben iniciarse. De lo contrario, esta es la lista de los únicos módulos que deben iniciarse.

Para obtener una lista de módulos compilados, ejecute snmptrapd con los argumentos -Dmib_init -H (suponiendo que se ha compilado soporte de depuración).

-L[efos]
Especifica a dónde debe dirigirse la salida de registro (salida estándar o error estándar, a un archivo o a través de syslog). Ver OPCIONES DE REGISTRO en snmpcmd(1) para más detalles.
-m LISTAMIB
Especifica una lista de módulos MIB separados por dos puntos para cargar para esta aplicación. Esto anula la variable de entorno MIBS. Ver snmpcmd(1) para más detalles.
-M LISTADIR
Especifica una lista de directorios separados por dos puntos para buscar MIBs. Esto anula la variable de entorno MIBDIRS. Ver snmpcmd(1) para más detalles.
-n
No intente traducir las direcciones de origen de los paquetes entrantes a nombres de host.
-p ARCHIVO
Guarda el ID del proceso del demonio de traps en ARCHIVO.
-O [abeEfnqQsStTuUvxX]
Especifica cómo se deben mostrar los objetos MIB y otra salida. Ver la sección OPCIONES DE SALIDA en la página del manual de snmpcmd(1) para más detalles.
-t
No registrar traps en syslog. Esto deshabilita el registro en syslog. Esto es útil si desea que la aplicación snmptrapd ejecute solo los hooks de traphandle y no registre ningún trap en ninguna ubicación.
-v, --version
Imprimir información de la versión del demonio de traps y luego salir.
-x DIRECCIÓN
Conectarse al agente maestro AgentX en la dirección especificada, en lugar de la predeterminada "/var/agentx/master". Ver snmpd(8) para más detalles sobre el formato de dichas direcciones.
-X
No conectarse a un agente maestro AgentX
--nombre="valor"
Permite especificar cualquier token ("nombre") soportado en el archivo snmptrapd.conf y establece su valor a "valor". Anula el token correspondiente en el archivo snmptrapd.conf. Ver snmptrapd.conf(5) para la lista completa de tokens.

ESPECIFICACIONES DE FORMATO

snmptrapd interpreta las cadenas de formato de manera similar a printf(3). Comprende las siguientes secuencias de formato:

%%
un literal %
%a
el contenido del campo agent-addr de la PDU (solo TRAPs v1)
%A
el nombre de host correspondiente al contenido del campo agent-addr de la PDU, si está disponible, de lo contrario el contenido del campo agent-addr de la PDU (solo TRAPs v1).
%b
dirección de transporte de la PDU (Nota: esta no es necesariamente una dirección IPv4).
Algo como "[UDP: [172.16.10.12]:23456->[10.150.0.8]]"
%B
nombre de host de origen de la PDU si está disponible, de lo contrario dirección de origen de la PDU (ver nota anterior)
%E
ID del motor de contexto SNMPv3
%h
hora actual en el sistema local
%H
el campo de hora del varbind sysUpTime.0
%j
minuto actual en el sistema local
%J
el campo de minuto del varbind sysUpTime.0
%k
segundo actual en el sistema local
%K
el campo de segundos del varbind sysUpTime.0
%l
día actual del mes en el sistema local
%L
el campo del día del mes del varbind sysUpTime.0
%m
mes actual (numérico) en el sistema local
%M
el campo del mes numérico del varbind sysUpTime.0
%N
cadena de empresa
%P
información de seguridad de la PDU (nombre de comunidad para v1/v2c, usuario y contexto para v3)
%q
subtipo de trap (numérico, en decimal)
%s
número de versión SNMP (0: v1, 1: v2c, 2: v3)
%S
número de versión del modelo de seguridad SNMPv3
%t
número decimal de segundos desde la época del sistema operativo (como lo devuelve time(2))
%T
el valor del varbind sysUpTime.0 en segundos
%u
nombre de seguridad SNMPv3, o nombre de comunidad v1/v2c
%v
lista de enlaces de variables de la carga útil de la notificación. Estos estarán separados por una tabulación, o por una coma y un espacio si se solicita la forma alternativa. Ver también %V
%V
especifica el separador de enlaces de variables. Toma una secuencia de caracteres, hasta el siguiente % (para incrustar un % en la cadena, use \%)
%w
tipo de trap (numérico, en decimal)
%W
descripción del trap
%y
año actual en el sistema local
%Y
el campo del año del varbind sysUpTime.0

Además de estos valores, también se pueden especificar un ancho de campo y una precisión opcionales, al igual que en printf(3), y un valor de bandera. Las siguientes banderas son compatibles:

-
justificar a la izquierda
0
usar ceros iniciales
#
usar forma alternativa

La bandera "usar forma alternativa" cambia el comportamiento de varias secuencias de cadenas de formato:

La información de la hora se mostrará basándose en GMT (en lugar de la zona horaria local)
Los enlaces de variables serán una lista separada por comas (en lugar de una separada por tabulaciones)

El tiempo de actividad del sistema se dividirá en un formato comprensible para el ser humano
en lugar de ser un simple entero)

Ejemplos:

Para obtener un mensaje como "14:03 TRAP3.1 de humpty.ucd.edu" podrías usar algo como esto:

snmptrapd -P -F "%02.2h:%02.2j TRAP%w.%q de %A\n"

Si quieres lo mismo pero en GMT en lugar de hora local, usa

snmptrapd -P -F "%#02.2h:%#02.2j TRAP%w.%q de %A\n"

DIRECCIONES DE ESCUCHA

Por defecto, snmptrapd escucha los paquetes SNMP TRAP e INFORM entrantes en el puerto UDP 162 en todas las interfaces IPv4. Sin embargo, es posible modificar este comportamiento especificando una o más direcciones de escucha como argumentos para snmptrapd. Consulta la página del manual de snmpd(8) para obtener más información sobre el formato de las direcciones de escucha.

SOPORTE NOTIFICATION-LOG-MIB

A partir de net-snmp 5.0, la aplicación snmptrapd soporta NOTIFICATION-LOG-MIB. Lo hace abriendo una conexión de subagente AgentX al agente maestro snmpd y registrando las tablas de registro de notificaciones. Mientras la aplicación snmpd se inicie primero, se conectará a ella y, por lo tanto, deberías poder ver las últimas notificaciones registradas a través de nlmLogTable y nlmLogVariableTable. Consulta el archivo snmptrapd.conf y el token "doNotRetainNotificationLogs" para desactivar este soporte. Consulta NOTIFICATION-LOG-MIB para más detalles sobre la propia MIB.
