snmpusm(1)

Paquete: net-snmp

Licencias: BSD

SNMPUSM(1) Net-SNMP SNMPUSM(1)

NOMBRE

snmpusm - crea y mantiene usuarios SNMPv3 en una entidad de red

SINOPSIS

snmpusm [OPCIONES COMUNES] [-Cw] AGENTE create USUARIO [CLONAR-DESDE-USUARIO]
snmpusm [OPCIONES COMUNES] AGENTE delete USUARIO
snmpusm [OPCIONES COMUNES] AGENTE cloneFrom USUARIO CLONAR-DESDE-USUARIO
snmpusm [OPCIONES COMUNES] [-Ca] [-Cx] AGENTE passwd FRASEPASOLD FRASEPASEANUEVA [USUARIO]
snmpusm [OPCIONES COMUNES] <-Ca | -Cx> -Ck AGENTE passwd CLAVE-O-FRASEPASOLDFRSECLAVE-O-FRASENUEVA [USUARIO]
snmpusm [OPCIONES COMUNES] [-Ca] [-Cx] AGENTE changekey [USUARIO]

DESCRIPCIÓN

snmpusm es una aplicación SNMP que puede usarse para realizar un mantenimiento simple de los usuarios conocidos por un agente SNMP, manipulando la tabla User-based Security Module (USM) del agente. El usuario necesita acceso de escritura a la tabla MIB usmUserTable. Esta herramienta puede usarse para crear, eliminar, clonar y cambiar la frase de paso de usuarios configurados en un agente SNMP en ejecución.

OPCIONES

Opciones comunes para todos los comandos snmpusm:

-CE ID-MOTOR
Establece usmUserEngineID que se usará como parte del índice de la usmUserTable. Por defecto, usa el contextEngineID (establecido vía -E o sondeado) como usmUserEngineID.
-Cp CADENA
Establece el valor usmUserPublic del (nuevo) usuario a la CADENA especificada.

Opciones para los comandos passwd y changekey:

-Ca
Cambia la clave de autenticación.
-Cx
Cambia la clave de privacidad.
-Ck
Permite usar una clave localizada (debe empezar con 0x) en lugar de una frase de paso. Cuando se usa esta opción, también se debe usar la opción -Ca o -Cx (pero no ambas).

CREACIÓN DE USUARIOS

Se puede crear un usuario SNMPv3 sin autenticación usando el comando

snmpusm [OPCIONES COMUNES] AGENTE create USUARIO

Esto construye una entrada (inactiva) en la usmUserTable, sin configuraciones de autenticación ni privacidad. En principio, este usuario debería ser utilizable para peticiones 'noAuthNoPriv', pero en la práctica, el agente Net-SNMP no permitirá que dicha entrada se active. El usuario puede crearse mediante la operación createAndWait en su lugar usando el indicador -Cw. Esto evitará que el usuario se marque como activo en cualquier agente hasta que se active explícitamente más tarde mediante el comando activate.

Para activar esta entrada, es necesario "clonar" un usuario existente, usando el comando

snmpusm [OPCIONES COMUNES] AGENTE cloneFrom USUARIO CLONAR-DESDE-USUARIO

La entrada USUARIO hereda entonces la misma configuración de autenticación y privacidad (incluyendo frases de paso) que el usuario CLONAR-DESDE-USUARIO.

Estos dos pasos se pueden combinar en uno, usando el comando

snmpusm [OPCIONES COMUNES] AGENTE create USUARIO CLONAR-DESDE-USUARIO

Las dos formas del subcomando create requieren que el usuario que se está creando no exista ya. El subcomando cloneFrom requiere que el usuario desde el que se clona sí exista.

Clonar es la única forma de especificar qué protocolos de autenticación y privacidad usar para un usuario dado, y solo es posible hacerlo una vez. Los intentos posteriores de volver a clonar sobre el mismo usuario parecerán tener éxito, pero serán ignorados silenciosamente. Este comportamiento (algo inesperado) está dictado por las especificaciones USM de SNMPv3 (RFC 3414). Para cambiar la configuración de autenticación y privacidad para un usuario dado, es necesario eliminar y recrear la entrada del usuario. Esto *no* es necesario para simplemente cambiar las frases de paso (ver abajo). Esto significa que el agente debe inicializarse con al menos un usuario para cada combinación de protocolos de autenticación y privacidad. Ver la página del manual de snmpd.conf(5) para detalles sobre la directiva de configuración createUser.

ELIMINACIÓN DE USUARIOS

Un usuario puede ser eliminado de la usmUserTable usando el comando

snmpusm [OPCIONES COMUNES] AGENTE delete USUARIO

CAMBIO DE FRASES DE PASO

Los perfiles de usuario contienen claves privadas que nunca se transmiten por la red en texto plano (independientemente de si las solicitudes de administración están cifradas o no). Para cambiar la clave secreta de un usuario, es necesario especificar la frase de paso antigua del usuario, así como la nueva. Esto utiliza el comando

snmpusm [OPCIONES COMUNES] [-Ca] [-Cx] AGENTE passwd FRASEPASOLD FRASEPASEANUEVA [USUARIO]

Después de clonar una nueva entrada de usuario desde la plantilla apropiada, deberías cambiar inmediatamente la frase de paso del nuevo usuario.

Si no se especifica USUARIO, este comando cambiará la frase de paso del usuario (SNMPv3) que emite el comando. Si se especifican las opciones -Ca o -Cx, solo se cambian las claves de autenticación o privacidad. Si estas opciones no se especifican, se cambian ambas claves, la de autenticación y la de privacidad.

snmpusm [OPCIONES COMUNES] [-Ca] [-Cx] AGENTE changekey [USUARIO]

Este comando cambia la clave de forma compatible con forward-secrecy a través de un intercambio diffie-helman. El agente remoto debe soportar el SNMP-USM-DH-OBJECTS-MIB para que este comando funcione. Las claves resultantes se imprimen en la consola y pueden ser establecidas en futuras invocaciones de comandos usando las opciones --defAuthLocalizedKey y --defPrivLocalizedKey o en tu archivo snmp.conf usando las palabras clave defAuthLocalizedKey y defPrivLocalizedKey.

Ten en cuenta que como estas claves se generan aleatoriamente basándose en un intercambio diffie-helman, ya no se derivan de una contraseña más fácil de escribir. Sin embargo, son mucho más seguras.

Para cambiar de una clave localizada de nuevo a una contraseña, se utiliza la siguiente variante del subcomando passwd:

snmpusm [OPCIONES COMUNES] <-Ca | -Cx> -Ck AGENTE passwd CLAVE-O-FRASEPASOLDFRSE CLAVE-O-FRASENUEVA [USUARIO]

Se debe especificar la opción -Ca o -Cx. Los argumentos CLAVE-O-FRASEPASOLDFRSE y/o CLAVE-O-FRASENUEVA pueden ser una frase de paso o una clave localizada que empiece por "0x", por ejemplo, como imprime el subcomando changekey.

Ten en cuenta que snmpusm REQUIERE un argumento que especifique el agente a consultar, como se describe en la página del manual de .I snmpcmd(1).

EJEMPLOS

Supongamos para nuestros ejemplos que las siguientes líneas de configuración VACM y USM estaban en el archivo snmpd.conf para un agente Net-SNMP. Estas líneas establecen un usuario por defecto llamado "initial" con la frase de paso de autenticación "setup_passphrase" para que podamos realizar la configuración inicial de un agente:

# Entradas de configuración VACM
rwuser initial
# Añadamos también el nuevo usuario que crearemos:
rwuser wes
# Entradas de configuración USM
createUser initial MD5 setup_passphrase DES

Nota: la configuración del usuario "initial" debería eliminarse después de crear un usuario real al que se le otorguen privilegios administrativos (como el usuario "wes" que crearemos en este ejemplo.

Nota: las frases de paso deben tener una longitud MÍNIMA de 8 caracteres.

Crear un nuevo usuario

snmpusm -v3 -u initial -n "" -l authNoPriv -a MD5 -A setup_passphrase localhost create wes initial

Crea un nuevo usuario, aquí llamado "wes", utilizando el usuario "initial" para hacerlo. "wes" se clona de "initial" en el proceso, por lo que hereda la frase de paso de ese usuario ("setup_passphrase").

Cambiar la frase de paso del usuario

snmpusm -v3 -u initial -n "" -l authNoPriv -a MD5 -A setup_passphrase localhost passwd setup_passphrase new_passphrase wes

Cambia la frase de paso del usuario "wes". Debes tener en cuenta que el usuario que emite el comando debe tener privilegios para hacerlo. Aquí estamos usando el usuario "initial" (que tiene permisos rwuser) para cambiar la frase de paso del nuevo usuario "wes".

Eliminar un usuario

snmpusm -v3 -u initial -n "" -l authNoPriv -a MD5 -A setup_passphrase localhost delete wes

Elimina el usuario "wes" de la tabla USM del agente.

Crear un usuario autenticado

snmpusm -v3 -u initial -n "" -l authPriv -a MD5 -A setup_passphrase localhost create wes auth_wes_pw

Esto fallará con un mensaje de error indicando que el usuario 'wes' ya existe. Este comando debería ser: snmpusm -v3 -u initial -n "" -l authNoPriv -a MD5 -A setup_passphrase localhost create wes initial
Creará un usuario 'wes' con la frase de paso 'auth_wes_pw' usando MD5 y DES.
Nota: El ejemplo está mal. Necesitas clonar de un usuario que ya tenga la configuración de seguridad deseada. Para crear un usuario con autenticación y privacidad, necesitarías un usuario existente con configuración `authPriv` y luego clonar `wes` de ese usuario.

Ejemplo corregido para crear un usuario con autenticación y privacidad:

# En snmpd.conf
createUser authPrivUser MD5 authPassPriv DES
rwuser authPrivUser

Y luego usar `snmpusm` para crear un nuevo usuario clonado de `authPrivUser`:

snmpusm -v3 -u authPrivUser -n "" -l authNoPriv -a MD5 -A authPassPriv
    localhost create newSecureUser authPrivUser

Luego cambia la frase de paso del nuevo usuario:

snmpusm -v3 -u authPrivUser -n "" -l authNoPriv -a MD5 -A authPassPriv
    localhost passwd authPassPriv newSecureUserPw newSecureUser

CAMBIAR LAS FRASES DE PASO

snmpusm -v 3 -u wes -n "" -l authNoPriv -a MD5 -A setup_passphrase localhost passwd setup_passphrase new_passphrase

Después de crear el usuario "wes" con la misma frase de paso que el usuario "initial", necesitamos cambiarle su frase de paso. El comando anterior la cambia de "setup_passphrase", que fue heredada del usuario inicial, a "new_passphrase".

Probar el nuevo usuario

snmpget -v 3 -u wes -n "" -l authNoPriv -a MD5 -A new_passphrase localhost sysUpTime.0

Si los comandos anteriores tuvieron éxito, este comando debería haber realizado correctamente una solicitud GET autenticada de SNMPv3 al agente.

Ahora, elimine la entrada de "group" de vacm en snmpd.conf para el usuario "initial" y tendrá un usuario válido 'wes' que puede usar para transacciones futuras en lugar de initial.

ADVERTENCIA

La manipulación de usmUserTable usando este comando sólo se puede hacer usando SNMPv3. Este comando no funcionará con las versiones basadas en comunidades, incluso si tienen acceso de escritura a la tabla.
