SNAPPER(8) Gestión de instantáneas del sistema de archivos SNAPPER(8)

NOMBRE

snapper - Programa de línea de comandos para la gestión de instantáneas del sistema de archivos

SINOPSIS

snapper [opciones-globales] comando [opciones-del-comando] [argumentos-del-comando]

snapper {--help}

DESCRIPCIÓN

Snapper es un programa de línea de comandos para la gestión de instantáneas del sistema de archivos. Puede crear, eliminar y comparar instantáneas y deshacer cambios realizados entre instantáneas.

Snapper nunca modifica el contenido de las instantáneas. Por lo tanto, snapper crea instantáneas de solo lectura si el kernel lo admite. Los sistemas de archivos admitidos son btrfs y ext4 (descontinuado), así como instantáneas de volúmenes lógicos de LVM con aprovisionamiento ligero. Algunos sistemas de archivos podrían no ser compatibles dependiendo de su instalación.

CONCEPTOS

Configuraciones

Para cada sistema de archivos o subvolumen que deba ser instantáneo por snapper, se requiere un archivo de configuración, consulte snapper-configs(5). La configuración se puede realizar con el comando create-config.

Instantáneas

Snapper distingue tres tipos de instantáneas.

pre

Las instantáneas pre siempre deben tener una instantánea post correspondiente. La intención de los pares de instantáneas pre/post es crear una instantánea del sistema de archivos antes y después de una modificación.

post

Ver tipo pre.

single

Estas instantáneas no tienen una relación especial con otras instantáneas.

Nota que a nivel de sistema de archivos, los tres tipos son idénticos.

Descripción e información del usuario de la instantánea

Con cada instantánea se puede asociar una descripción y cierta información del usuario. La descripción es una cadena de texto. La información del usuario es una lista de pares clave-valor, donde las claves y los valores son cadenas de texto.

No utilice caracteres no ASCII para la descripción de la instantánea, la información del usuario ni ninguna otra cadena, a menos que siempre utilice la codificación de caracteres UTF-8.

Creación automática de instantáneas

Además de la creación manual de instantáneas, estas también se crean automáticamente.

•Un cronjob o un temporizador systemd crea instantáneas horarias, si TIMELINE_CREATE está habilitado para una configuración.
•Ciertos programas como YaST y zypper crean pares de instantáneas pre/post al modificar el sistema.

Algoritmos de limpieza

Snapper proporciona varios algoritmos para limpiar instantáneas antiguas. Los algoritmos se ejecutan en un cronjob o temporizador systemd horario. Esto se puede configurar en los archivos de configuración correspondientes junto con los parámetros para cada algoritmo.

number

Elimina instantáneas antiguas cuando se alcanza un cierto número de instantáneas.

timeline

Elimina instantáneas antiguas pero conserva un número de instantáneas horarias, diarias, semanales, mensuales, trimestrales y anuales.

empty-pre-post

Elimina pares de instantáneas pre/post con diferencias vacías.

Los algoritmos de limpieza number y timeline también pueden intentar mantener el espacio utilizado por las instantáneas por debajo de un límite y el espacio libre del sistema de archivos por encima de un límite. Para la primera condición, se debe configurar una cuota, consulte el comando setup-quota. Además, las variables NUMBER_LIMIT y TIMELINE_LIMIT en el archivo de configuración deben tener rangos (valor mínimo y máximo). Los algoritmos realizarán entonces dos pasadas:

1.Eliminar instantáneas por encima del valor máximo, independientemente del espacio de la instantánea y del sistema de archivos.
2.Eliminar instantáneas por encima del valor mínimo hasta que se alcancen los límites para la instantánea y el sistema de archivos.

El límite para el espacio utilizado se puede configurar a través de la variable SPACE_LIMIT. Nota: Solo las instantáneas que tienen un algoritmo de limpieza establecido se tienen en cuenta al calcular el espacio utilizado por las instantáneas.

El límite para el espacio libre se puede configurar a través de la variable FREE_LIMIT.

Nota: Dado que la limpieza se realiza de forma asíncrona a la creación de instantáneas, las instantáneas observadas pueden diferir de las instantáneas esperadas según los límites. También pueden existir temporalmente qgroups obsoletos de btrfs.

Filtros

Algunos archivos conservan información de estado del sistema, por ejemplo, /etc/mtab. Dichos archivos nunca deben revertirse. Para ayudar a los usuarios, snapper permite ignorar estos archivos.

Los filtros se leen de los archivos /etc/snapper/filters/*.txt y /usr/share/snapper/filters/*.txt, donde para archivos con el mismo nombre, la primera ubicación tiene precedencia. Cada línea en estos archivos especifica un patrón. Cuando snapper calcula la diferencia entre dos instantáneas, ignora todos los archivos y directorios que coinciden con cualquiera de estos patrones utilizando fnmatch(3) con la bandera FNM_LEADING_DIR.

Tenga en cuenta que los filtros no excluyen archivos o directorios de ser instantáneos. Para eso, utilice subvolúmenes o puntos de montaje.

-q, --quiet

Suprime la salida normal. Sin embargo, los mensajes de error se seguirán mostrando.

-v, --verbose

Aumenta la verbosidad.

--utc

--iso

-t, --table-style estilo

Estas opciones específicas del comando deben especificarse después del nombre del comando y antes de cualquier argumento del comando.

Las columnas posibles son: config, subvolume.

Sin esta opción, snapper intenta detectar el sistema de archivos.

-t, --template nombre

Nombre de la plantilla para el nuevo archivo de configuración.

delete-config

Eliminar una configuración para un sistema de archivos o subvolumen. Para este comando probablemente necesitará la opción global --config, ver OPCIONES GLOBALES y CONCEPTOS.

--columnas columnas

Seleccionar columnas para mostrar separadas por comas.

Las columnas posibles son: key, value.

set-config configdata

Cambia la configuración. Los ajustes configdata son una lista de pares clave-valor separados por espacios y la clave y el valor deben estar separados por un signo igual, por ejemplo, "NUMBER_CLEANUP=yes NUMBER_LIMIT=10". El valor de SUBVOLUME y FSTYPE no se puede cambiar.

list (ls) [opciones]

Lista instantáneas.

-t, --type tipo

Selecciona el tipo de instantáneas a listar. Los valores posibles son all, single y pre-post.

--disable-used-space

Desactivar la visualización del espacio utilizado.

El cálculo del espacio utilizado lleva tiempo. Por lo tanto, esta opción puede acelerar la listado.

-a, --all-configs

Lista instantáneas de todas las configuraciones accesibles por el usuario.

--columnas columnas

Seleccionar columnas para mostrar separadas por comas.

Las columnas posibles son: config, subvolume, number, default, active, date, user, used-space, cleanup, description, userdata, pre-number, post-number, post-date, read-only.

Para cada instantánea, la salida consta de varias columnas. Algunas requieren explicación:

#, Pre # y Post #

El número de la instantánea.

Para btrfs, el número puede ir seguido de un signo. Un "-" indica que la instantánea es la que está montada actualmente y un "+" indica que la instantánea se montará la próxima vez (es el subvolumen predeterminado de btrfs). Si ambas condiciones se aplican, se muestra un "*".

Used Space

Para btrfs, el espacio exclusivo del grupo de cuotas de btrfs correspondiente a la instantánea.

La visualización del espacio utilizado se desactiva automáticamente si no está disponible, por ejemplo, si la cuota no está habilitada en btrfs.

-u, --userdata userdata

Establecer datos de usuario para la instantánea. Los pares clave-valor deben estar separados por comas y la clave y el valor deben estar separados por un signo igual, por ejemplo, requestid=42,user=arthur.

--read-only

Establecer la instantánea como de solo lectura.

--read-write

Establecer la instantánea como de lectura y escritura.

--default

delete (remove|rm) número | número1-número2

Eliminar una instantánea o un rango de instantáneas.

-s, --sync

Sincronizar el sistema de archivos después de eliminar las instantáneas. Los detalles dependen del tipo de sistema de archivos.

Btrfs normalmente libera espacio de forma asíncrona después de eliminar instantáneas. Con esta opción, snapper esperará hasta que el espacio utilizado una vez por las instantáneas eliminadas esté realmente disponible de nuevo.

La instantánea 0 no se puede eliminar. Para btrfs, la instantánea montada actualmente y la instantánea que se montará la próxima vez (el subvolumen predeterminado de btrfs) tampoco se pueden eliminar.

mount número

Montar una instantánea. No es necesario para todos los tipos de sistemas de archivos.

umount número

Desmontar una instantánea. No es necesario para todos los tipos de sistemas de archivos.

status [opciones] número1..número2

Compara las instantáneas número1 y número2. Esto mostrará una lista de archivos y directorios que se han creado, modificado o eliminado en el tiempo transcurrido entre la toma de ambas instantáneas.

-o, --output archivo

Escribir la salida al archivo archivo.

La salida consta de una cadena que codifica el estado seguida del nombre del archivo. Los caracteres de la cadena de estado son:

1.A "+" significa que el archivo se creó, un "-" significa que el archivo se eliminó. Una "c" significa que el contenido del archivo ha cambiado y una "t" significa que el tipo de archivo ha cambiado (por ejemplo, de archivo regular a directorio).
2.Una "p" significa que los permisos han cambiado.
3.Una "u" significa que la propiedad del usuario ha cambiado.
4.Una "g" significa que la propiedad del grupo ha cambiado.
5.Una "x" significa que la información de atributos extendidos ha cambiado.
6.Una "a" significa que la información ACL ha cambiado.

Si no hay ningún cambio, se muestra un ".".

diff [opciones] número1..número2 [archivos]

Compara las instantáneas número1 y número2. Esto mostrará un diff del contenido de los archivos y directorios que se han creado, modificado o eliminado en el tiempo transcurrido entre la toma de ambas instantáneas.

-i, --input archivo

Leer los archivos para comparar desde el archivo archivo.

--diff-cmd comando

Comando utilizado para comparar archivos. El valor predeterminado es /usr/bin/diff --new-file --unified. Los dos archivos a comparar se pasan como parámetros al comando.

-x, --extensions opciones

Opciones adicionales pasadas al comando diff.

undochange [opciones] número1..número2 [archivos]

Deshacer los cambios realizados entre la instantánea número1 y número2.

-i, --input archivo

Leer los archivos para los que se deben deshacer los cambios desde el archivo archivo.

rollback [opciones] [número]

Crea dos nuevas instantáneas y establece el subvolumen predeterminado. Por defecto, el sistema arranca desde el subvolumen predeterminado del sistema de archivos raíz. Las acciones exactas dependen de si se proporciona o no un número:
•Sin un número, se crea una primera instantánea de solo lectura del subvolumen predeterminado. Se crea una segunda instantánea de lectura y escritura del sistema actual. El sistema se configura para arrancar desde la segunda instantánea.
•Con un número, se crea una primera instantánea de solo lectura del sistema actual. Se crea una segunda instantánea de lectura y escritura de número. El sistema se configura para arrancar desde la segunda instantánea.

Rollback solo está soportado con btrfs y requiere un sistema configurado correctamente.

-p, --print-number

Imprimir el número de la segunda instantánea creada.

-d, --description descripción

Descripción para la instantánea.

-c, --cleanup-algorithm algoritmo-limpieza

Establecer el algoritmo de limpieza para la instantánea.

-u, --userdata userdata

Establecer datos de usuario para la instantánea. Los pares clave-valor deben estar separados por comas y la clave y el valor deben estar separados por un signo igual, por ejemplo, requestid=42,user=arthur.

El comando rollback también establece la descripción, el algoritmo de limpieza y algunos datos de usuario a menos que los valores se especifiquen en la línea de comandos. Esto automatizará la limpieza de las instantáneas creadas por los rollbacks.

En ámbitos distintos al clásico, el comando rollback hace lo que se requiere para realizar un rollback. De todos modos, se recomienda utilizar programas específicos en ese caso.

NAME

snapper - manage snapshots of btrfs and lvm filesystems

SYNOPSIS

snapper [-c config] [-d directory] [-y] [-q] command

snapper command [subcommand-options]

DESCRIPTION

Snapper is a tool to manage snapshots of btrfs and lvm filesystems. It is useful for automated snapshots, rollback operations and comparing snapshots.

Snapper uses configuration files to manage snapshots for specific subvolumes or logical volumes. The configuration files are stored in /etc/snapper/configs/ and contain options like filesystem type, target directory, snapshotting pre/post commands, etc.

The main purpose of snapper is to automate snapshot creation and management, especially for system rollback. It also supports detailed comparison between snapshots, making it useful for debugging and tracking changes.

CONCEPTS

Snapshots: Snapper works with snapshots of btrfs subvolumes or lvm logical volumes. These snapshots are read-only copies of the filesystem at a specific point in time.

Configurations: Snapper uses configuration files to manage snapshots for specific mountpoints or subvolumes. Each configuration defines how snapshots are created, how they are cleaned up, and what actions are performed before or after snapshot operations.

Cleanup Algorithms: Snapper provides algorithms to automatically delete old snapshots based on defined criteria (e.g., number of snapshots, timeline). This helps manage disk space.

Plugins: External scripts can be executed at various points in the snapper operation lifecycle (e.g., before creating a snapshot, after deleting a configuration).

Extended Attributes (xattrs): Snapper can compare extended attributes between snapshots, which is useful for tracking changes in file metadata.

GLOBAL OPTIONS

-c config, --config config

Use the specified configuration. If not specified, the default configuration is used. This is equivalent to using the configuration in the global options in snapper-configs(5).

-d directory, --directory directory

Use the specified directory for operations. This is equivalent to using the target directory in the global options in snapper-configs(5).

-y, --yes

Automatic yes to all prompts.

-q, --quiet

Suppress progress messages.

COMMANDS

snapper create-config [--template template] config

Create a new configuration named config. Currently implemented templates are btrfs and lvm. If no template is specified, the default template is used. See snapper-configs(5) for details.

snapper delete-config config

Delete the specified configuration. All snapshots associated with this configuration are also deleted.

snapper list [-t type] [-s snapshot] [-e snapshot] [-o] [-r] [-j json]

List snapshots. Valid types are: pre, post, single, all. Default is all. -s and -e specify a range of snapshots. -o shows only snapshot numbers. -r shows only the default snapshot. -j outputs in JSON format.

snapper create [-c config] [-p] [-d description] [-f fssize] [-s subvolume] [-w =|!|<|<=|>|>= size]

Create a new snapshot. -p creates a pre-snapshot. -d adds a description to the snapshot. -f specifies the size of the filesystem. -s specifies the subvolume to snapshot. -w sets a minimum free space size.

snapper delete [snapshot...]

Delete the specified snapshots.

snapper restore-snapshot [-r] snapshot

Restore the specified snapshot. This operation is destructive and cannot be undone easily. Use with caution. -r restores the snapshot read-write.

snapper rollback [-r] snapshot

Rollback to the specified snapshot. This operation replaces the current filesystem state with the state of the specified snapshot. Use with caution. -r creates a snapshot of the current filesystem before rolling back.

snapper mountpoint [-r] snapshot

Mount the specified snapshot. -r mounts the snapshot read-write.

snapper umount snapshot

Unmount the specified snapshot.

snapper mountlist [-t type]

List mounted snapshots. Valid types are: pre, post, single, all. Default is all.

snapper get-config [config]

Get configuration values for the specified configuration. If no configuration is specified, all configurations are listed.

snapper set-config [config] [option=value] ...

Set configuration values for the specified configuration. See snapper-configs(5) for available options.

snapper diff [-r] [-t type] snapshot1..snapshot2

Compare two snapshots. -r shows only changed files. -t specifies the type of diff (pre, post, single, all). Default is all.

snapper status [-c config] [-p] snapshot

Show the status of files within a snapshot. -p shows only changed files.

snapper xo [-c config] [-p] snapshot

Show extended object data for a snapshot. -p shows only changed entries.

snapper cleanup [-c config] [-a cleanup-algorithm] [-p path] [-f free-space]

Run the cleanup algorithm cleanup-algorithm. Currently implemented cleanup algorithms are number, timeline and empty-pre-post. To run all cleanup algorithms, all can be provided as cleanup-algorithm.

--path path

Cleanup all configs affecting path. Only useful for btrfs.

--free-space free-space

Try to make free-space available. Only useful for btrfs.

xadiff number1..number2 [files]

Compare the extended attributes between snapshot number1 and number2. See examples below:
•+:user.foo for created attributes
•-:user.bar for removed attributes
•-+:security.selinux for modified attributes

PERMISSIONS

Non-root users can be allowed to use a configuration by setting ALLOW_USERS or ALLOW_GROUPS in the config file. For all operations to work, the user must also be able to read and access the .snapshots directory inside the subvolume. The .snapshots directory must be owned by root and must not be writable by anybody else.

Here are some methods how to achieve that:

•Make the directory accessible for everyone:

chmod a+rx .snapshots

•Make the directory accessible for a group the user belongs to, e.g.:

chown :users .snapshots

•Make the directory accessible for the user using ACLs, e.g.:

setfacl -m u:tux:rx .snapshots

The last method can be performed by snapper, see the SYNC_ACL setting in snapper-configs(5).

PLUGINS

snapper can execute external scripts after certain actions. Scripts have to be placed in /usr/lib/snapper/plugins. The name has to start with a digit, execution order is alphabetical.

The first argument of a script is the action snapper executed. The following actions are defined:

create-config-pre subvolume fstype

Executed before a new config is created

create-config-post subvolume fstype

Executed after a new config was created

delete-config-pre subvolume fstype

Executed before a config is deleted

delete-config-post subvolume fstype

Executed after a config was deleted

create-snapshot-pre subvolume fstype snapshot-number

Executed before a new snapshot is created

create-snapshot-post subvolume fstype snapshot-number

Executed after a new snapshot was created

modify-snapshot-pre subvolume fstype snapshot-number

Executed before a snapshot is modified

modify-snapshot-post subvolume fstype snapshot-number

Executed after a snapshot was modified

delete-snapshot-pre subvolume fstype snapshot-number

Executed before a snapshot is removed

delete-snapshot-post subvolume fstype snapshot-number

Executed after a snapshot was removed

set-read-only-pre subvolume fstype snapshot-number

Executed before a snapshot is set read-only or read-write

set-read-only-post subvolume fstype snapshot-number

Executed after a snapshot is set read-only or read-write

set-default-snapshot-pre subvolume fstype snapshot-number

Executed before the default snapshot is changed

set-default-snapshot-post subvolume fstype snapshot-number

Executed after the default snapshot was changed

rollback-post subvolume fstype old-snapshot-number new-snapshot-number

Executed after a rollback was done

More actions and arguments can be added any time. Using snapper in the plugins is not allowed.

It is undefined whether the plugins are called from the client (snapper) or server (snapperd).

EXIT STATUS

Normally the exit status is 0. If an error occurred the exit status is 1. It is also an error if the exit status of a plugin is not 0.

NOTES

There is no mechanism to ensure consistency of the files while a snapshot it made. E.g. the files of a database can be inconsistent while the database is running.

Consistency after undochange is not guaranteed. E.g. when the creation of a user is undone, there might still exist files from that user.

Support for individual filesystems, rollback and extended attributes are compile-time options and may not be available.
