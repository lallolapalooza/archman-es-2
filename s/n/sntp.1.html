NAME

sntp - programa cliente estándar del Protocolo Simple de Network Time Protocol

SYNOPSIS

sntp [-flags] [-flag [value]] [--option-name[[=| ]value]] [ hostname-or-IP ...]

DESCRIPTION

sntp puede ser utilizado como un cliente SNTP para consultar un servidor NTP o SNTP y, o bien mostrar la hora, o bien ajustar la hora del sistema local (con el privilegio adecuado). Puede ejecutarse como un comando interactivo o desde un trabajo de cron. NTP (el Protocolo de Tiempo de Red) y SNTP (el Protocolo Simple de Tiempo de Red) se definen y describen en la RFC 5905.

El valor predeterminado es escribir la fecha y hora local estimada correcta (es decir, no UTC) en la salida estándar en un formato como: '1996-10-15 20:17:25.123 (+0800) +4.567 +/- 0.089 [host] IP sN' donde '(+0800)' significa que para obtener UTC a partir de la hora local reportada, se deben sumar 8 horas y 0 minutos, el '+4.567' indica que el reloj local está 4.567 segundos atrasado respecto a la hora correcta (por lo tanto, se deben sumar 4.567 segundos al reloj local para que sea correcto). Tenga en cuenta que el número de decimales impresos para este valor cambiará según la precisión reportada por el servidor. '+/- 0.089' es la distancia de sincronización reportada (en segundos), que representa el error máximo debido a todas las causas. Si el servidor no reporta datos válidos necesarios para calcular la distancia de sincronización, se reportará como '+/- ?'. Si el host es diferente de la IP, se mostrarán ambos. De lo contrario, solo se mostrará la IP. Finalmente, se reporta el stratum del host y se decodifica y muestra el indicador de salto.

OPTIONS

-4, --ipv4

Forzar la resolución de nombres DNS a IPv4. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: ipv6.

Forzar la resolución DNS de los siguientes nombres de host en la línea de comandos al espacio de nombres IPv4.

-6, --ipv6

Forzar la resolución de nombres DNS a IPv6. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: ipv4.

Forzar la resolución DNS de los siguientes nombres de host en la línea de comandos al espacio de nombres IPv6.

-a auth-keynumber, --authentication=auth-keynumber

Habilitar autenticación con la clave auth-keynumber. Esta opción toma un número entero como argumento.

Habilitar la autenticación usando la clave especificada en el argumento de esta opción. El argumento de esta opción es el keyid, un número especificado en el keyfile como identificador de esta clave. Ver la opción keyfile (-k) para más detalles.

-b broadcast-address, --broadcast=broadcast-address

Escuchar en la dirección especificada para sincronización de tiempo por difusión. Esta opción puede aparecer un número ilimitado de veces.

Si se especifica, sntp escuchará en la dirección especificada para transmisiones NTP. El tiempo máximo de espera predeterminado puede (y probablemente debería) modificarse con -t.

-c host-name, --concurrent=host-name

Consultar concurrentemente todas las IPs devueltas para host-name. Esta opción puede aparecer un número ilimitado de veces.

Las solicitudes de un cliente NTP a un servidor nunca deben enviarse más rápido que una cada 2 segundos. Por defecto, se asume que cualquier IP devuelta como parte de una búsqueda DNS es para una única instancia de ntpd, y por lo tanto, sntp enviará consultas a estas IPs una tras otra, con un lapso de 2 segundos entre cada consulta.

El flag -c o --concurrent indica que las IPs devueltas para la búsqueda DNS del nombre de host proporcionado están en máquinas diferentes, por lo que podemos enviar consultas concurrentes.

-d, --debug-level

Aumentar el nivel de verbosidad de depuración. Esta opción puede aparecer un número ilimitado de veces.
-D number, --set-debug-level=number

Establecer el nivel de verbosidad de depuración. Esta opción puede aparecer un número ilimitado de veces. Esta opción toma un número entero como argumento.
-g milliseconds, --gap=milliseconds

El lapso (en milisegundos) entre solicitudes de tiempo. Esta opción toma un número entero como argumento. El valor predeterminado de milliseconds para esta opción es:
50

Dado que solo usaremos la primera respuesta válida que obtengamos y hay beneficio en especificar un buen número de servidores a consultar, separe las consultas que enviamos por el número especificado de milisegundos.

-K file-name, --kod=file-name

Nombre del archivo de historial KoD. El nombre de archivo predeterminado file-name para esta opción es:
/var/db/ntp-kod

Especifica el nombre del archivo que se utilizará para el historial persistente de respuestas KoD recibidas de los servidores. Si el archivo no existe, se mostrará un mensaje de advertencia. El archivo no se creará.

-k file-name, --keyfile=file-name

Buscar en este archivo la clave especificada con -a. El nombre de archivo predeterminado file-name para esta opción es:
/etc/ntp.keys

Esta opción especifica el archivo de claves. sntp buscará la clave especificada con -a keyno en este archivo. Ver ntp.keys(5) para más información.

-l file-name, --logfile=file-name

Registrar en el archivo de registro especificado.

Esta opción hace que el cliente escriba mensajes de registro en el logfile especificado.

-M number, --steplimit=number

Los ajustes menores a steplimit milisegundos se deslizarán. Esta opción toma un número entero como argumento. El valor de number está restringido a ser: 
mayor o igual a 0

Si el ajuste de tiempo es menor a steplimit milisegundos, deslizar la cantidad usando adjtime(2). De lo contrario, avanzar el paso de la corrección usando settimeofday(2). El valor predeterminado es 0, lo que significa que todos los ajustes se avanzarán. Esta es una característica, ya que diferentes situaciones exigen diferentes valores.

-o number, --ntpversion=number

Enviar int como nuestra versión del protocolo NTP. Esta opción toma un número entero como argumento. El valor de number está restringido a ser: 
en el rango 0 a 7

El número predeterminado number para esta opción es:
4

Al enviar solicitudes a un servidor remoto, indicarle que estamos ejecutando la versión ntpversion del protocolo NTP.

-r, --usereservedport

Usar el Puerto Reservado NTP (puerto 123).

Usar el puerto 123, que está reservado para NTP, para nuestras comunicaciones de red.

-S, --step

Está bien 'avanzar' el tiempo con settimeofday(2).
-s, --slew

Está bien 'deslizar' el tiempo con adjtime(2).
-t seconds, --timeout=seconds

El número de segundos a esperar por las respuestas. Esta opción toma un número entero como argumento. El valor predeterminado de seconds para esta opción es:
5

Al esperar una respuesta, sntp esperará el número de segundos especificado antes de rendirse. El valor predeterminado debería ser más que suficiente para una respuesta unicast. Si sntp solo está esperando una respuesta de difusión, es probable que se necesite un tiempo de espera más largo.

--wait, --wait=seconds

Igual que -t.

EXIT STATUS

Returns 0 on success, and non-zero otherwise.

SEE ALSO

adjtime(2), ntp.conf(5), ntp.keys(5), ntpd(8), settimeofday(2), RFC 5905.

OPTIONS

--no-wait

Espera las respuestas pendientes (si no se establece la hora). La forma no-wait deshabilitará la opción. Esta opción está habilitada por defecto.

Si no estamos estableciendo la hora, espera todas las respuestas pendientes.

-?, --help

Muestra la información de uso y sale.
-!, --more-help

Pasa la información de uso extendida a través de un paginador.
-> [archivo-cfg], --save-opts [=archivo-cfg]

Guarda el estado de las opciones en archivo-cfg. El valor por defecto es el último archivo de configuración listado en la sección OPTION PRESETS, abajo. El comando saldrá después de actualizar el archivo de configuración.
-< archivo-cfg, --load-opts=archivo-cfg, --no-load-opts

Carga las opciones desde archivo-cfg. La forma no-load-opts deshabilitará la carga de archivos de configuración/rc/ini anteriores. --no-load-opts se maneja temprano, fuera de orden.
--version [{v|c|n}]

Muestra la versión del programa y sale. El modo por defecto es `v', una versión simple. El modo `c' mostrará información de copyright y `n' mostrará el aviso de copyright completo.

AJUSTES DE OPCIONES

Cualquier opción que no esté marcada como no ajustable puede ser preestablecida cargando valores desde archivos de configuración ("RC" o ".INI") y valores de variables de entorno llamadas:

  SNTP_<nombre-opción> o SNTP

Los preajustes ambientales tienen precedencia (se procesan más tarde que) los archivos de configuración. Los archivos homerc son "$HOME", y ".". Si alguno de estos es un directorio, entonces se busca el archivo .ntprc dentro de esos directorios.

USO

sntp ntpserver.somewhere

es el uso más simple de este programa y puede ejecutarse como un comando no privilegiado para verificar la hora actual y el error en el reloj local.
sntp -Ss -M 128 ntpserver.somewhere

Con privilegios adecuados, ejecute como un comando o desde un trabajo de cron(8), sntp -Ss -M 128 ntpserver.somewhere solicitará la hora al servidor, y si ese servidor informa que está sincronizado entonces si el ajuste de desplazamiento es menor a 128 milisegundos la corrección se deslizará, y si la corrección es mayor a 128 milisegundos la corrección se saltará.
sntp -S ntpserver.somewhere

Con privilegios adecuados, ejecute como un comando o desde un trabajo de cron(8), sntp -S ntpserver.somewhere establecerá (saltará) el reloj local desde un servidor especificado sincronizado, como los comandos (obsoletos) ntpdate(1), o rdate(8).
