DESCRIPCIÓN

Las funciones de la familia printf() producen salida de acuerdo con un formato como se describe a continuación. Las funciones printf() y vprintf() escriben la salida en stdout, el flujo de salida estándar; fprintf() y vfprintf() escriben la salida en el flujo de salida stream dado; sprintf(), snprintf(), vsprintf(), y vsnprintf() escriben en la cadena de caracteres str.

La función dprintf() es la misma que fprintf() excepto que produce salida a un descriptor de archivo, fd, en lugar de a un flujo stdio(3).

Las funciones snprintf() y vsnprintf() escriben como máximo size bytes (incluyendo el byte nulo terminador ('\0')) en str.

Las funciones vprintf(), vfprintf(), vdprintf(), vsprintf(), vsnprintf() son equivalentes a las funciones printf(), fprintf(), dprintf(), sprintf(), snprintf(), respectivamente, excepto que se llaman con una va_list en lugar de un número variable de argumentos. Estas funciones no llaman a la macro va_end. Como invocan la macro va_arg, el valor de ap no está definido después de la llamada. Ver stdarg(3).

Todas estas funciones escriben la salida bajo el control de una cadena de formato que especifica cómo los argumentos subsiguientes (o los argumentos accedidos a través de las facilidades de argumentos de longitud variable de stdarg(3)) se convierten para la salida.

C99 y POSIX.1-2001 especifican que los resultados no están definidos si una llamada a sprintf(), snprintf(), vsprintf(), o vsnprintf() causara una copia entre objetos que se superponen (por ejemplo, si la cadena de destino y uno de los argumentos de entrada se refieren al mismo búfer). Ver ADVERTENCIAS.

Formato de la cadena de formato

La cadena de formato es una cadena de caracteres, que comienza y termina en su estado de desplazamiento inicial, si existe. La cadena de formato se compone de cero o más directivas: caracteres ordinarios (no %), que se copian sin cambios al flujo de salida; y especificaciones de conversión, cada una de las cuales resulta en la obtención de cero o más argumentos subsiguientes. Cada especificación de conversión se introduce con el carácter %, y termina con un especificador de conversión. Entre ellos puede haber (en este orden) cero o más flags, un ancho de campo mínimo opcional, una precisión opcional y un modificador de longitud opcional.

La sintaxis general de una especificación de conversión es:


%[argumento$][flags][ancho][.precision][modificador de longitud]conversión

Los argumentos deben corresponderse adecuadamente (después de la promoción de tipo) con el especificador de conversión. Por defecto, los argumentos se utilizan en el orden dado, donde cada '*' (ver Ancho de campo y Precisión a continuación) y cada especificador de conversión solicitan el siguiente argumento (y es un error si se dan insuficientes argumentos). También se puede especificar explícitamente qué argumento se toma, en cada lugar donde se requiere un argumento, escribiendo "%m$" en lugar de '%' y "*m$" en lugar de '*', donde el entero decimal m denota la posición en la lista de argumentos del argumento deseado, indexado a partir de 1. Por lo tanto,


printf("%*d", ancho, num);

y


printf("%2$*1$d", ancho, num);

son equivalentes. El segundo estilo permite referencias repetidas al mismo argumento. El estándar C99 no incluye el estilo que utiliza '$', que proviene de la Single UNIX Specification. Si se utiliza el estilo con '$', debe usarse en todo momento para todas las conversiones que toman un argumento y todos los argumentos de ancho y precisión, pero se puede mezclar con formatos "%%", que no consumen un argumento. No debe haber huecos en los números de argumentos especificados usando '$'; por ejemplo, si se especifican los argumentos 1 y 3, el argumento 2 también debe especificarse en algún lugar de la cadena de formato.

Para algunas conversiones numéricas se utiliza un carácter de base ("punto decimal") o un carácter de agrupación de miles. El carácter real utilizado depende de la parte LC_NUMERIC de la localidad. (Ver setlocale(3).) La localidad POSIX utiliza '.' como carácter de base, y no tiene carácter de agrupación. Por lo tanto,


printf("%'.2f", 1234567.89);

resulta en "1234567.89" en la localidad POSIX, en "1234567,89" en la localidad nl_NL, y en "1.234.567,89" en la localidad da_DK.

Caracteres de flag

El carácter % va seguido de cero o más de los siguientes flags:

#
El valor debe convertirse a una "forma alternativa". Para conversiones o, el primer carácter de la cadena de salida se convierte en cero (prefijando un 0 si no era cero ya). Para conversiones x y X, a un resultado distinto de cero se le prefija la cadena "0x" (o "0X" para conversiones X). Para conversiones a, A, e, E, f, F, g y G, el resultado siempre contendrá un punto decimal, incluso si no le siguen dígitos (normalmente, un punto decimal aparece en los resultados de esas conversiones solo si un dígito le sigue). Para conversiones g y G, los ceros finales no se eliminan del resultado, como se haría de otra manera. Para m, si errno contiene un código de error válido, se imprime la salida de strerrorname_np(errno); de lo contrario, se imprime el valor almacenado en errno como un número decimal. Para otras conversiones, el resultado no está definido.
0
El valor debe rellenarse con ceros. Para conversiones d, i, o, u, x, X, a, A, e, E, f, F, g y G, el valor convertido se rellena por la izquierda con ceros en lugar de espacios. Si los flags 0 y - aparecen juntos, el flag 0 se ignora. Si se da una precisión con una conversión entera (d, i, o, u, x y X), el flag 0 se ignora. Para otras conversiones, el comportamiento no está definido.
-
El valor convertido debe ajustarse a la izquierda en el límite del campo. (El valor por defecto es la justificación a la derecha). El valor convertido

lue se rellena a la derecha con espacios, en lugar de a la izquierda con espacios o ceros. Un - anula un 0 si se dan ambos.
' '
(un espacio) Se dejará un espacio antes de un número positivo (o una cadena vacía) producido por una conversión con signo.
+
Siempre se colocará un signo (+ o -) antes de un número producido por una conversión con signo. Por defecto, el signo solo se usa para números negativos. Un + anula un espacio si se usan ambos.

Los cinco caracteres de bandera anteriores están definidos en el estándar C99. POSIX especifica un carácter de bandera adicional.

'
Para la conversión decimal (i, d, u, f, F, g, G) la salida se agrupará con caracteres de agrupación de miles como una cantidad *no monetaria*. Engañosamente, no son necesariamente cada mil: por ejemplo, Karbi ("mjw_IN") agrupa sus dígitos en 3 una vez, luego 2 repetidamente. Compare con locale(7) grouping y thousands_sep, contraste con mon_grouping/mon_thousands_sep y strfmon(3). Esto no tiene efecto en la configuración regional predeterminada "C".

glibc 2.2 añade un carácter de bandera adicional.

I
Para la conversión de enteros decimales (i, d, u) la salida utiliza los dígitos de salida alternativos de la configuración regional, si los hay. Por ejemplo, desde glibc 2.2.3 esto producirá dígitos arábigo-índigos en la configuración regional persa ("fa_IR").

Ancho de campo

Una cadena de dígitos decimales opcional (con primer dígito distinto de cero) que especifica un ancho de campo mínimo. Si el valor convertido tiene menos caracteres que el ancho de campo, se rellenará con espacios a la izquierda (o a la derecha, si se ha dado la bandera de ajuste a la izquierda). En lugar de una cadena de dígitos decimales se puede escribir "*" o "*m$" (para algún entero decimal *m*) para especificar que el ancho de campo se da en el siguiente argumento, o en el *m*-ésimo argumento, respectivamente, que debe ser de tipo *int*. Un ancho de campo negativo se toma como una bandera '-' seguida de un ancho de campo positivo. En ningún caso un ancho de campo inexistente o pequeño provocará la truncación de un campo; si el resultado de una conversión es más ancho que el ancho de campo, el campo se expandirá para contener el resultado de la conversión.

Precisión

Una precisión opcional, en forma de un punto ('.') seguido de una cadena de dígitos decimales opcional. En lugar de una cadena de dígitos decimales se puede escribir "*" o "*m$" (para algún entero decimal *m*) para especificar que la precisión se da en el siguiente argumento, o en el *m*-ésimo argumento, respectivamente, que debe ser de tipo *int*. Si la precisión se da solo como '.', la precisión se toma como cero. Una precisión negativa se toma como si la precisión se hubiera omitido. Esto da el número mínimo de dígitos que deben aparecer para las conversiones d, i, o, u, x y X, el número de dígitos que deben aparecer después del carácter de punto decimal para las conversiones a, A, e, E, f y F, el número máximo de dígitos significativos para las conversiones g y G, o el número máximo de caracteres que se imprimirán de una cadena para las conversiones s y S.

Modificador de longitud

Aquí, "conversión de enteros" significa conversión d, i, o, u, x o X.

hh
Una conversión de enteros posterior corresponde a un argumento *signed char* o *unsigned char*, o una conversión n posterior corresponde a un puntero a un argumento *signed char*.
h
Una conversión de enteros posterior corresponde a un argumento *short* o *unsigned short*, o una conversión n posterior corresponde a un puntero a un argumento *short*.
l
(ele) Una conversión de enteros posterior corresponde a un argumento *long* o *unsigned long*, o una conversión n posterior corresponde a un puntero a un argumento *long*, o una conversión c posterior corresponde a un argumento *wint_t*, o una conversión s posterior corresponde a un puntero a un argumento *wchar_t*. En una conversión a, A, e, E, f, F, g o G posterior, este modificador de longitud se ignora (C99; no en SUSv2).
ll
(ele-ele). Una conversión de enteros posterior corresponde a un argumento *long long* o *unsigned long long*, o una conversión n posterior corresponde a un puntero a un argumento *long long*.
q
Un sinónimo de ll. Esta es una extensión no estándar, derivada de BSD; evite su uso en código nuevo.
L
Una conversión a, A, e, E, f, F, g o G posterior corresponde a un argumento *long double*. (C99 permite %LF, pero SUSv2 no.)
j
Una conversión de enteros posterior corresponde a un argumento *intmax_t* o *uintmax_t*, o una conversión n posterior corresponde a un puntero a un argumento *intmax_t*.
z
Una conversión de enteros posterior corresponde a un argumento *size_t* o *ssize_t*, o una conversión n posterior corresponde a un puntero a un argumento *size_t*.
Z
Un sinónimo no estándar de z que precede a la aparición de z. No usar en código nuevo.
t
Una conversión de enteros posterior corresponde a un argumento *ptrdiff_t*, o una conversión n posterior corresponde a un puntero a un argumento *ptrdiff_t*.

SUSv3 especifica todos los anteriores, excepto aquellos modificadores explícitamente anotados como extensiones no estándar. SUSv2 especificó solo los modificadores de longitud h (en hd, hi, ho, hx, hX, hn) y l (en ld, li, lo, lx, lX, ln, lc, ls) y L (en Le, LE, Lf, Lg, LG).

Como extensión no estándar, las implementaciones de GNU tratan ll y L como sinónimos, de modo que se puede, por ejemplo, escribir llg (como sinónimo de Lg compatible con el estándar) y Ld (como sinónimo de lld compatible con el estándar). Dicho uso no es portable.

Especificadores de conversión

Un carácter que especifica el tipo de conversión a aplicar. Los especificadores de conversión y sus significados son:

d, i
El argumento *int* se convierte a notación decimal con signo. La precisión, si la hay, da el número mínimo de dígitos que deben aparecer; si el valor convertido requiere menos dígitos, se rellena a la izquierda con ceros. La precisión predeterminada es 1. Cuando se imprime 0 con una precisión explícita de 0, la salida está vacía.
o, u, x, X
El argumento *unsigned int* se convierte a notación octal sin signo (o), decimal sin signo (u) o hexadecimal sin signo (x y X). Las letras abcdef se utilizan para las conversiones x; las letras ABCDEF se utilizan para las conversiones X. La precisión, si la hay, da el número mínimo de dígitos que deben aparecer; si el valor convertido requiere menos dígitos, se rellena a la izquierda con ceros. La precisión predeterminada es 1. Cuando se imprime 0 con una precisión explícita de 0, la salida está vacía.
e, E
El argumento *double* se redondea y se convierte en el estilo [-]d.ddde±dd donde hay un dígito (que es distinto de cero si el argumento es distinto de cero) antes del carácter del punto decimal y el número de dígitos después de él es igual a la precisión; si falta la precisión, se toma como 6; si la precisión es cero, no aparece el carácter del punto decimal. La conversión E utiliza la letra E (en lugar de e) para introducir el exponente. El exponente siempre contiene al menos dos dígitos; si el valor es cero, el exponente es 00.
f, F
El argumento *double* se redondea y se convierte a notación decimal en el estilo [-]ddd.ddd, donde el número de dígitos después del carácter del punto decimal es igual a la especificación de precisión. Si falta la precisión, se toma como 6; si la precisión es explícitamente cero, no aparece el carácter del punto decimal. Si aparece un punto decimal, aparece al menos un dígito antes de él.
(SUSv2 no conoce F y dice que pueden estar disponibles representaciones de cadena de caracteres para infinito y NaN. SUSv3 añade una especificación para F. El estándar C99 especifica "[-]inf" o "[-]infinity" para infinito, y una cadena que comienza con "nan" para NaN, en el caso de la conversión f, y "[-]INF" o "[-]INFINITY" o "NAN" en el caso de la conversión F.)
g, G
El argumento *double* se convierte en el estilo f o e (o F o E para conversiones G). La precisión especifica el número de dígitos significativos. Si falta la precisión, se dan 6 dígitos; si la precisión es cero, se trata como 1. El estilo e se utiliza si el exponente de su conversión es menor que -4 o mayor o igual que la precisión. Los ceros finales se eliminan de la parte fraccionaria del resultado; un punto decimal aparece solo si va seguido de al menos un dígito.

EJEMPLOS

Para imprimir Pi con cinco decimales:


#include <math.h>
#include <stdio.h>
fprintf(stdout, "pi = %.5f\n", 4 * atan(1.0));

Para imprimir una fecha y hora en el formato "domingo, julio 3, 10:02", donde weekday y month son punteros a cadenas:


#include <stdio.h>
fprintf(stdout, "%s, %s %d, %.2d:%.2d\n",
        weekday, month, day, hour, min);

Muchos países usan el orden día-mes-año. Por lo tanto, una versión internacionalizada debe ser capaz de imprimir los argumentos en un orden especificado por el formato:


#include <stdio.h>
fprintf(stdout, format,
        weekday, month, day, hour, min);

donde format depende de la configuración regional y puede permutar los argumentos. Con el valor:


"%1$s, %3$d. %2$s, %4$d:%5$.2d\n"

se podría obtener "Sonntag, 3. Juli, 10:02".

Para asignar una cadena lo suficientemente grande e imprimir en ella (código correcto tanto para glibc 2.0 como para glibc 2.1):

#include <stdio.h>
#include <stdlib.h>
#include <stdarg.h>
char *
make_message(const char *fmt, ...)
{
    int n = 0;
    size_t size = 0;
    char *p = NULL;
    va_list ap;
    /* Determinar el tamaño requerido.  */
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0)
        return NULL;
    size = (size_t) n + 1;      /* Un byte extra para '\0' */
    p = malloc(size);
    if (p == NULL)
        return NULL;
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0) {
        free(p);
        return NULL;
    }
    return p;
}

Si se produce truncamiento en versiones de glibc anteriores a glibc 2.0.6, esto se trata como un error en lugar de manejarse de forma adecuada.
