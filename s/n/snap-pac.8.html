NOMBRE

snap-pac - Ganchos de Pacman que utilizan snapper para crear instantáneas btrfs pre/post como las de YaST de openSUSE

DESCRIPCIÓN

Dado que estos son ganchos de pacman, no importa cómo llames a pacman, ya sea directamente, a través de un ayudante de AUR o usando un alias, snapper creará las instantáneas cuando pacman instale, actualice o elimine un paquete. El comando pacman utilizado se registra en la descripción de snapper para las instantáneas. Además, los números de instantánea se muestran en la pantalla y en el registro de pacman para cada configuración de snapper durante la transacción de pacman, de modo que el usuario pueda encontrar fácilmente los cambios que podría querer revertir.

Cuando ejecutas pacman, las instantáneas pre/post de snapper se crean automáticamente. Para un ejemplo más completo, consulta Ejemplo.

Si tienes un problema grave (por ejemplo, si snapper desaparece por alguna razón y no puedes recuperarlo), tendrás que recurrir a métodos más extremos, como hacer una instantánea de la instantánea pre y convertirla en la subvolumen por defecto o montarla como /. Lo más probable es que necesites usar un USB en vivo para acceder a un entorno chroot y realizar alguna de estas acciones. Snapper tiene una función de snapper rollback, pero tu configuración debe estar configurada adecuadamente para usarla. El procedimiento exacto depende de tu configuración específica. Ten cuidado.

Ten en cuenta que los ganchos pre-transacción ocurren antes de la transacción de pacman pero después de que la base de datos de pacman se sincroniza, si aplica. En otras palabras, si ejecutas pacman -Syu y reviertes la actualización según las instrucciones anteriores, no habrás revertido la base de datos de pacman al estado anterior. Por lo tanto, si, después de actualizar y revertir la actualización, instalas un paquete, posiblemente sea una actualización parcial, lo cual no está soportado.

INSTALACIÓN

Instala el paquete snap-pac usando pacman:

gpg --verify snap-pac-<version>.tar.gz.sig

donde <version> es el número de versión que descargaste.

Finalmente, ejecuta:

make install

He firmado el archivo tarball de lanzamiento y los commits con mi clave PGP. A partir de la versión 2.2, los archivos tarball se firman con mi clave con la huella digital F7B28C61944FE30DABEEB0B01070BCC98C18BD66.

Para versiones anteriores, la huella digital de la clave era 8535CEF3F3C38EE69555BF67E4B5E45AA3B8C5C3.

Dependencias

Se requieren python, pacman y snapper.

Pruebas

Para realizar pruebas, se requiere pytest. Para ejecutar las pruebas, haz:

man 8 snap-pac

Para compilar la documentación, se requiere sphinx. Para compilar la documentación, puedes hacer:

make docs

La documentación html resultante se ubicará en docs/build/index.html. Además, esto genera la página del manual que se encontrará en man8.

CONFIGURACIÓN

La configuración se realiza a través de archivos de configuración ini de Python. Los valores predeterminados deberían ser adecuados para la mayoría de los usuarios, por lo que es posible que no necesites realizar ninguna configuración. Por defecto, solo se captura la configuración de `root` de snapper.

Un ejemplo comentado de archivo de configuración se encuentra en /etc/snap-pac.ini.

Edita con tu editor favorito. El archivo está comentado y debería ser autoexplicativo.

Cada sección corresponde a una configuración de snapper. Agrega secciones adicionales para incluir otras configuraciones de snapper que se capturarán. Por defecto, solo se captura la configuración de root. Además, puedes agregar una sección llamada DEFAULT con opciones que se aplican a todas las configuraciones de snapper a menos que se anulen en una sección posterior.

Cada sección puede tener las siguientes entradas:

  • desc_limit - entero; longitud máxima de la cadena de descripción antes de ser truncada. Por defecto: 72
  • important_packages - lista de cadenas; nombres de paquetes que, si están involucrados en una transacción de pacman, agregarán important=yes a los datos de usuario de snapper para el par de instantáneas. Por defecto: []
  • important_commands - lista de cadenas; comandos principales que agregarán important=yes a los datos de usuario de snapper para el par de instantáneas. Por defecto: []
  • pre_description - cadena; descripción para la instantánea pre. Por defecto: el comando principal que llamó al gancho de pacman.
  • post_description - cadena; descripción para la instantánea post. Por defecto: lista de paquetes separados por espacios que fueron instalados, actualizados o eliminados.
  • snapshot - booleano; si se debe capturar o no la configuración. Por defecto: True para la configuración root; False en caso contrario.
  • userdata - lista de cadenas; pares clave-valor que se agregarán a los datos de usuario para el par de instantáneas. Por defecto: []

Ejemplos

Desactivar las instantáneas para la configuración root y activarlas para la configuración home:

[root]
snapshot = False
[home]
snapshot = True

Establecer snapper para agregar los datos de usuario important=yes para cada instantánea en la configuración root cuando se realiza una actualización del sistema:

[root]
important_commands = ["pacman -Syu"]

Establecer snapper para agregar los datos de usuario important=yes para cada instantánea en la configuración root cuando una transacción de pacman maneja los paquetes linux y linux-lts:

[root]
important_packages = ["linux", "linux-lts"]

VARIABLES DE ENTORNO

Para evitar temporalmente que se realicen instantáneas para un único comando pacman, establece la variable de entorno SNAP_PAC_SKIP. Por ejemplo:

sudo SNAP_PAC_SKIP=y pacman -Syu

SOLUCIÓN DE PROBLEMAS

snap-pac solo está tomando instantáneas de la configuración root.

Ese es el comportamiento predeterminado. Consulta Configuración.

No se están tomando instantáneas cuando ejecuto pacman.

No hay configuraciones de snapper configuradas para los hooks de pacman de snap-pac. Por defecto, snap-pac tomará instantáneas para la configuración root y cualquier otra configuración que tenga SNAPSHOT establecido en yes en su archivo de configuración. Consulta Configuración.

Después de restaurar una instantánea de snap-pac, la base de datos de pacman está bloqueada.

PREGUNTAS FRECUENTES

¿snap-pac hace copias de seguridad de particiones /boot que no son btrfs?

No, pero puedes añadir un hook que lo haga por ti. Sería algo parecido a lo siguiente:

[Trigger]
Operation = Upgrade
Operation = Install
Operation = Remove
Type = Package
Target = linux
[Action]
Description = Haciendo copia de seguridad de /boot...
When = PreTransaction
Exec = /usr/bin/rsync -avzq --delete /boot /.bootbackup

Ten en cuenta que probablemente querrás nombrar el archivo con un prefijo numérico menor que 05 para que se ejecute antes de que se tome la instantánea pre-transacción de snap-pac. Esto asegurará que la instantánea tomada corresponda con la copia de seguridad de la partición de arranque y el estado del sistema. Por ejemplo, podrías nombrarlo 04-backupboot.hook.

¿Cómo vinculo automáticamente los módulos del kernel antiguos cuando se actualiza el kernel?

Este comportamiento ya no forma parte de este paquete. Utiliza un hook de pacman como el siguiente:

[Trigger]
Operation = Upgrade
Operation = Install
Operation = Remove
Type = Package
Target = linux
[Action]
Description = Vinculando símbolos a módulos del kernel antiguos...
When = PostTransaction
Exec = /usr/bin/bash -c "find /usr/lib/modules -xtype l -delete; ln -sv /.snapshots/$(snapper -c root list | awk 'END{print $1}')/snapshot/usr/lib/modules/$(uname -r) /usr/lib/modules/"
