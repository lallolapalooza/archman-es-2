#include <net-snmp/session_api.h>

void snmp_sess_init(struct snmp_session *session);

struct snmp_session *snmp_sess_session(void *handle);

int snmp_sess_async_send(void *handle,
struct snmp_pdu *pdu,
snmp_callback callback,

int snmp_sess_select_info(void *handle,
int *numfds, fd_set *fdset,
struct timeval *timeout,
int *block);

int snmp_sess_read(void *handle, fd_set *fdset);

void snmp_sess_timeout(void *handle);

int snmp_sess_synch_response ( void *handle,

netsnmp_pdu *pdu,
netsnmp_pdu **response);

int snmp_sess_close(void *handle);

void snmp_sess_error(void *handle, int *pcliberr,
int *psnmperr, char **pperrstring);

DESCRIPCIÓN

Estas funciones definen un subconjunto de la API que puede ser usado para gestionar sesiones SNMP individuales en una aplicación multihilo. Excepto por snmp_sess_session(), estas funciones son versiones de sesión única de la API tradicional de la biblioteca SNMP.

Note que estas funciones usan un puntero opaco (handle en los prototipos anteriores) para identificar una sesión individual en lugar de un puntero session (como en la API tradicional).

snmp_sess_init() prepara una estructura `struct snmp_session` que contiene las características de transporte e información común que se utilizará para un conjunto de transacciones SNMP. Después de que esta estructura sea pasada a snmp_sess_open() para crear una sesión SNMP, la estructura ya no se utiliza. En su lugar, el puntero opaco devuelto por snmp_sess_open() se utiliza para referirse a esa sesión en adelante.

Las sesiones SNMP que se crean con snmp_sess_open() no se ven afectadas por, y NO DEBEN SER USADAS CON, snmp_select_info(), snmp_read(), snmp_timeout() ni snmp_close(). Más bien, se deben utilizar las funciones equivalentes de sesión única descritas aquí.

snmp_sess_init() y snmp_sess_open() toman cada una como entrada un puntero a un objeto `struct snmp_session`. Esta estructura contiene información para un conjunto de transacciones que compartirán características de transporte similares. snmp_sess_session() toma el handle de sesión opaco y devuelve un puntero a su `struct snmp_session` asociada.

snmp_sess_send() y snmp_sess_async_send() toman cada una un parámetro pdu, que apunta a un objeto `struct snmp_pdu` que contiene información que describe una transacción que se realizará sobre una sesión abierta.

Consulte snmp_api.h para las definiciones de estas estructuras.

Con la llamada snmp_sess_async_send(), snmp_sess_read invocará la función de retorno especificada cuando se reciba la respuesta.

snmp_sess_select_info(), snmp_sess_read() y snmp_sess_timeout() proporcionan una interfaz para el uso de la llamada al sistema select(2) para que las transacciones SNMP de una sesión individual puedan ocurrir de forma asíncrona.

A snmp_sess_select_info() se le pasa la información que se habría pasado a select(2) en ausencia de SNMP. Por ejemplo, esto podría incluir descriptores de archivo asociados al bucle principal de una aplicación gráfica. Esta información se modifica para que SNMP obtenga el servicio que requiere de la llamada a select(2). En este caso, numfds, fdset y timeout corresponden a los argumentos nfds, readfds y timeout de select(2) respectivamente. La única excepción es que `timeout` SIEMPRE debe apuntar a una `struct timeval` asignada (pero quizás no inicializada) (no puede ser NULL como para select(2)). Si `timeout` se hubiera pasado como NULL, en su lugar se establece `block` a true, y `timeout` se trata como indefinido. Esta misma regla se aplica al regresar de snmp_select_info().

Después de llamar a snmp_sess_select_info(), se debe llamar a select(2) con los datos devueltos. Cuando regrese, se debe llamar a snmp_sess_read() con el fd_set devuelto por select(2). Esto leerá cualquier entrada del socket SNMP de esta sesión. Si select(2) expira (es decir, devuelve cero), se debe llamar a snmp_sess_timeout() para ver si ha ocurrido una expiración en la sesión SNMP.

snmp_sess_synch_response es una rutina de conveniencia que enviará la solicitud, esperará la respuesta y la procesará antes de regresar. Consulte las descripciones de snmp_sess_send , snmp_sess_read etc para más detalles.

DIAGNÓSTICOS

El estado de retorno de error de snmp_sess_open() se indica con la devolución de un puntero NULL. El estado de retorno de error de snmp_sess_close() y snmp_sess_send() se indica con un valor de retorno de 0. Un estado exitoso devolverá 1.

Se puede obtener más información utilizando snmp_sess_error() para ver qué tipo de error ha ocurrido. Esta función devuelve la variable SNMP snmp_errno, el valor de la variable del sistema errno y una interpretación en cadena de ambas variables. La cadena debe ser liberada después de su uso por el llamador.

Para los errores devueltos por snmp_sess_open(), utilice la función correspondiente snmp_error() en lugar de snmp_sess_error().

Consulte snmp_api.h para el conjunto completo de valores de error de la biblioteca SNMP. El valor de error de la biblioteca SNMP snmperr puede ser uno de los siguientes valores:

snmp_sess_async_send(3) — net-snmp

NAME

snmp_sess_async_send, snmp_sess_send, snmp_sess_reply, snmp_sess_real_send — asynchronous SNMP session send routines

SYNOPSIS

#include <net-snmp/session.h>

int
snmp_sess_async_send(
    struct snmp_session *session,
    struct snmp_pdu *pdu,
    snmp_callback callback,
    void *callback_data
);

int
snmp_sess_send(
    struct snmp_session *session,
    struct snmp_pdu *pdu
);

int
snmp_sess_reply(
    struct snmp_session *session,
    struct snmp_pdu *pdu
);

int
snmp_sess_real_send(
    struct snmp_session *session,
    struct snmp_pdu *pdu
);

DESCRIPTION

These routines are used to send SNMP Protocol Data Units (PDUs) asynchronously over an established SNMP session.

The snmp_sess_async_send() function is the primary interface for asynchronous operations. It takes a pointer to an open snmp_session structure, a pointer to the snmp_pdu to be sent, a callback function callback to be invoked when a response is received or an error occurs, and user-defined callback_data that will be passed to the callback function.

The snmp_sess_send(), snmp_sess_reply(), and snmp_sess_real_send() functions are synchronous interfaces. They send the PDU and block until a response is received or an error occurs. These functions are typically used for simple, synchronous operations, or when implementing custom retry logic.

snmp_sess_send() is a generic send function. snmp_sess_reply() is specifically for sending replies to requests. snmp_sess_real_send() is the lowest-level function and performs the actual socket transmission.

In all cases, the pdu structure is consumed by these functions. The caller should not attempt to reuse or free the pdu after calling any of these functions. The library will free the pdu once it has been processed.

The return value is the number of PDU's successfully sent. This will typically be 1, unless an error occurred during transmission.

For snmp_sess_async_send(), if a non-zero value is returned, the callback function will be invoked later with the result. If zero is returned, an immediate error occurred, and the callback will not be invoked.

DIAGNOSTICS

SNMPERR_BAD_SESSION
The provided session pointer is invalid.
SNMPERR_BAD_PDU
The provided PDU pointer is invalid.
SNMPERR_NOT_IN_PACKET
The PDU is not valid for sending.
SNMPERR_SENDERR
An error occurred while sending the PDU over the network.
SNMPERR_V3_AUTHONLY
An authentication-only SNMPv3 message could not be sent.
SNMPERR_V3_ENCRYPTED_PDU
An encrypted SNMPv3 PDU could not be sent.
SNMPERR_V3_ERROR
A general SNMPv3 error occurred during sending.
SNMPERR_UNKNOWN_PDU
The PDU type is unknown.
SNMPERR_TIMEOUT
The operation timed out while waiting for a response.

snmp_sess_async_send, snmp_sess_send, snmp_sess_reply, snmp_sess_real_send — rutinas de envío asíncrono de sesión SNMP

DESCRIPCIÓN

Estas rutinas se utilizan para enviar Unidades de Datos de Protocolo (PDUs) SNMP de forma asíncrona a través de una sesión SNMP establecida.

La función snmp_sess_async_send() es la interfaz principal para operaciones asíncronas. Toma un puntero a una estructura snmp_session abierta, un puntero a la snmp_pdu que se enviará, una función de devolución de llamada callback que se invocará cuando se reciba una respuesta o ocurra un error, y callback_data definida por el usuario que se pasará a la función de devolución de llamada.

Las funciones snmp_sess_send(), snmp_sess_reply() y snmp_sess_real_send() son interfaces síncronas. Envían la PDU y se bloquean hasta que se recibe una respuesta o ocurre un error. Estas funciones se utilizan típicamente para operaciones simples y síncronas, o al implementar lógica de reintento personalizada.

snmp_sess_send() es una función de envío genérica. snmp_sess_reply() es específicamente para enviar respuestas a solicitudes. snmp_sess_real_send() es la función de nivel más bajo y realiza la transmisión real del socket.

En todos los casos, la estructura pdu es consumida por estas funciones. El llamador no debe intentar reutilizar o liberar la pdu después de llamar a cualquiera de estas funciones. La biblioteca liberará la pdu una vez que haya sido procesada.

El valor de retorno es el número de PDUs enviadas exitosamente. Típicamente será 1, a menos que ocurra un error durante la transmisión.

Para snmp_sess_async_send(), si se devuelve un valor distinto de cero, la función de devolución de llamada se invocará más tarde con el resultado. Si se devuelve cero, ocurrió un error inmediato y la devolución de llamada no se invocará.

SNMPERR_SENDERR

SNMPERR_V3_AUTHONLY
No se pudo enviar un mensaje SNMPv3 solo de autenticación.
SNMPERR_V3_ENCRYPTED_PDU
No se pudo enviar una PDU SNMPv3 cifrada.
SNMPERR_V3_ERROR
Ocurrió un error general de SNMPv3 durante el envío.
SNMPERR_UNKNOWN_PDU
El tipo de PDU es desconocido.
SNMPERR_TIMEOUT
La operación expiró mientras se esperaba una respuesta.
