DESCRIPCIÓN

Snmp_sess_init prepara una netsnmp_session que proporciona características de transporte e información común que se utilizará para un conjunto de transacciones SNMP. Después de que esta estructura se pasa a snmp_open para crear una sesión SNMP, la estructura no se utiliza.

Snmp_open devuelve un puntero a un objeto netsnmp_session recién formado, que la aplicación debe usar para referenciar la sesión SNMP activa.

snmp_send y snmp_async_send() toman como entrada un puntero a un objeto netsnmp_pdu. Esta estructura contiene información que describe una transacción que se realizará en una sesión abierta.

Consulte snmp_api.h para ver las definiciones de estas estructuras.

Con la llamada a snmp_async_send(), snmp_read invocará la función de devolución de llamada especificada cuando se reciba la respuesta.

Snmp_read, snmp_select_info, y snmp_timeout proporcionan una interfaz para el uso de la llamada al sistema select(2) para que las transacciones SNMP puedan ocurrir de forma asíncrona.

Snmp_select_info recibe la información que se habría pasado a select en ausencia de SNMP. Por ejemplo, esto podría incluir información de actualización de ventana. Esta información se modifica para que SNMP obtenga el servicio que requiere de la llamada a select. En este caso, numfds, fdset, y timeout corresponden a los argumentos nfds, readfds, y timeout de select, respectivamente. La única excepción es que timeout siempre debe apuntar a una struct timeval asignada (pero quizás no inicializada). Si timeout se hubiera pasado como NULL, block se establecería en true, y timeout se trataría como indefinido. Esta misma regla se aplica al regresar de snmp_select_info.

Después de llamar a snmp_select_info, se llama a select con los datos devueltos. Cuando select regresa, se debe llamar a snmp_read con el fd_set devuelto por select para leer cada socket SNMP que tenga entrada. Si select se agota el tiempo de espera, se debe llamar a snmp_timeout para ver si el tiempo de espera estaba destinado a SNMP.

snmp_synch_response es una rutina de conveniencia que enviará la solicitud, esperará la respuesta y la procesará antes de regresar. Consulte las descripciones de snmp_send , snmp_read etc para obtener detalles.

DIAGNÓSTICOS

Versiones anteriores de la biblioteca utilizaban snmp_get_errno para leer la variable global snmp_errno que podría haber contenido el estado de error dentro de la biblioteca SNMP. El método existente snmp_perror debe usarse solo para registrar errores de codificación ASN.1.

El nuevo método snmp_sess_perror se proporciona para capturar errores que ocurren durante el procesamiento de una sesión SNMP particular. Snmp_sess_perror llama a la función snmp_error para obtener el error de la biblioteca "C" errno , el error de la biblioteca SNMP snmperr , y el mensaje de error detallado de la biblioteca SNMP que está asociado con un error que ocurrió durante una sesión dada.

Tenga en cuenta que en todos los casos excepto uno, snmp_sess_perror debe recibir el puntero netsnmp_session * devuelto por snmp_open. Si snmp_open devuelve un puntero nulo, pase el puntero netsnmp_session * de ENTRADA utilizado para llamar a snmp_open.

El estado de retorno de error de snmp_close y snmp_send se indica mediante el retorno de 0. Un estado exitoso devolverá un 1 para snmp_close y el ID de solicitud del paquete para snmp_send. Tras el retorno exitoso de snmp_send, la biblioteca liberará el pdu.

Consulte snmp_api.h para obtener el conjunto completo de valores de error de la biblioteca SNMP. El valor de error de la biblioteca SNMP snmperr puede ser uno de los siguientes valores:

SNMPERR_GENERR
Ocurrió un error genérico.
SNMPERR_BAD_LOCPORT
El puerto local era incorrecto porque ya se había asignado o se denegó el permiso.
SNMPERR_BAD_ADDRESS
El nombre o dirección del host proporcionado no era utilizable.
SNMPERR_BAD_SESSION
La sesión especificada no estaba abierta.
SNMPERR_TOO_LONG
SNMPERR_NO_SOCKET
SNMPERR_V2_IN_V1
SNMPERR_V1_IN_V2
SNMPERR_BAD_REPEATERS
SNMPERR_BAD_REPETITIONS
SNMPERR_BAD_ASN1_BUILD
SNMPERR_BAD_SENDTO
SNMPERR_BAD_PARSE
SNMPERR_BAD_VERSION
SNMPERR_NOAUTH_DESPRIV
SNMPERR_ABORT
SNMPERR_UNKNOWN_PDU
SNMPERR_TIMEOUT

Una representación en cadena del código de error se puede obtener con snmp_api_errstring, y un mensaje de error estándar puede ser impreso usando snmp_perror que funciona de manera similar a la rutina estándar perror.
