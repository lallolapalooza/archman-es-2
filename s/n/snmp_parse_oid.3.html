DESCRIPCIÓN

Las funciones que manejan módulos MIB se dividen en cuatro grupos: aquellas que se ocupan de la inicialización y el cierre, de la lectura y el análisis de archivos MIB, de la búsqueda en el árbol MIB y de las rutinas de salida.

Inicialización y Cierre

add_mibdir se utiliza para añadir el directorio especificado a la lista de ubicaciones que se buscan para encontrar archivos que contienen módulos MIB. Tenga en cuenta que esto no carga realmente los módulos MIB ubicados en ese directorio, sino que es simplemente un paso de inicialización para hacerlos disponibles para netsnmp_read_module. Esta función devuelve el recuento de archivos encontrados en el directorio, o -1 si hay un error. Debe llamarse *antes* de invocar netsnmp_init_mib.

netsnmp_init_mib configura la ruta de búsqueda del directorio MIB (utilizando add_mibdir), configura el marco MIB interno y luego carga los módulos MIB apropiados (utilizando netsnmp_read_module y read_mib). Consulte la sección VARIABLES DE ENTORNO para más detalles.
Debe llamarse antes que cualquier otra rutina que manipule o acceda al árbol MIB (pero después de cualquier llamada adicional a add_mibdir).

shutdown_mib borrará la información que fue recopilada por netsnmp_read_module, add_mibdir y add_module_replacement. Se recomienda encarecidamente no invocar shutdown_mib mientras haya sesiones SNMP activamente gestionadas.

Lectura y Análisis de MIBs

netsnmp_read_module toma el nombre de un módulo MIB (que no necesariamente es el mismo que el nombre del archivo que contiene el módulo), lo localiza dentro de la lista configurada de directorios MIB y carga las definiciones del módulo en el árbol MIB activo. También carga cualquier módulo MIB listado en la cláusula IMPORTS de este módulo.

read_mib es similar, pero toma el nombre del archivo que contiene el módulo MIB. Tenga en cuenta que este archivo no necesita estar ubicado dentro de la lista de búsqueda de directorios MIB (aunque cualquier módulo listado en la cláusula IMPORTS sí lo está).

read_all_mibs leerá todos los módulos MIB encontrados en la lista de búsqueda de directorios MIB.

En general, el analizador es silencioso sobre las rarezas que ve en los archivos MIB. Para que se informen de advertencias, llame a snmp_set_mib_warnings con un *nivel* de 1 (o 2 para aún más advertencias).

add_module_replacement se puede utilizar para permitir que los nuevos módulos MIB obsoleten otros más antiguos, sin necesidad de modificar las cláusulas IMPORTS de otros módulos. Toma los nombres de los módulos viejos y nuevos, junto con una indicación de qué porciones del módulo viejo se ven afectadas.

etiqueta len carga el nuevo módulo cuando:
NULL 0 siempre (el módulo viejo es un subconjunto estricto del
nuevo)
nombre 0 solo para la etiqueta dada
nombre distinto de 0 para cualquier identificador con este prefijo
También se puede utilizar para manejar errores en los identificadores de módulo utilizados en las cláusulas IMPORTS de MIB (como referirse a *RFC1213* en lugar de *RFC1213-MIB*).

Búsqueda en el Árbol MIB

read_objid toma una cadena que contiene una versión textual de un identificador de objeto (en formato numérico o descriptivo), y lo transforma en la lista correspondiente de sub-identificadores. Esto se devuelve en el parámetro *salida*, con el número de sub-identificadores devuelto a través de *out_len*. Cuando se llama, *out_len* debe contener la longitud máxima de la matriz *salida*. Si se están procesando múltiples identificadores de objeto, entonces esta longitud debe restablecerse antes de cada llamada. Esta función devuelve un valor de 1 si tiene éxito en el análisis de la cadena y 0 en caso contrario.

snmp_parse_oid es similar, pero devuelve un puntero al búfer OID analizado (o NULL).

get_module_node toma un descriptor y el nombre de un módulo, y devuelve la lista OID correspondiente, de la misma manera que read_objid anteriormente.
Si el nombre del módulo se especifica como "ANY", esta rutina asumirá que el descriptor dado es único dentro del árbol y devolverá la entrada que coincide. Si esta suposición no es válida, el comportamiento en cuanto a qué variable se devuelve depende de la implementación.

Salida

print_mib imprimirá una representación del árbol MIB activo actualmente en el puntero FILE especificado.

print_objid tomará un identificador de objeto (como el devuelto por read_objid, snmp_parse_oid o get_module_node), e imprimirá la forma textual de este OID en la salida estándar.

fprint_objid hace lo mismo, pero imprime en el puntero FILE especificado por el parámetro inicial.

snprint_objid imprime la misma información en el búfer apuntado por *buf*, que tiene una longitud *len*. Devuelve el número de caracteres impresos, o -1 si el búfer no era lo suficientemente grande. En este último caso, *buf* típicamente contendrá una versión truncada de la información (pero este comportamiento no está garantizado).

print_description, fprint_description y snprint_description toman un identificador de objeto similar e imprimen una versión de la definición MIB para ese objeto, junto con el OID completo. El argumento *width* controla cómo se distribuye el OID.

DESCRIPTION

These functions provide a more detailed interface to the MIB parsing and loading mechanisms within the Net-SNMP library.

snmp_parse_oid parses an SNMP Object Identifier (OID) string and returns it as an oid structure (an array of unsigned integers). The caller is responsible for freeing the returned memory using free().

snmp_smi_error returns a string describing the last SMI (Structure of Management Information) parsing error encountered.

snmp_get_mib_module and snmp_set_mib_module allow querying and setting the current MIB module context. When parsing MIBs, only those that belong to the specified module (and those that the module imports from) will be loaded.

snmp_get_utility_path and snmp_set_utility_path allow querying and setting the path used by the library to find utility MIB files (e.g. SNMPv2-SMI).

snmp_get_config_file and snmp_set_config_file allow querying and setting the path to the main Net-SNMP configuration file.

snmp_get_save_descriptions returns whether descriptions are saved when parsing MIBs. This is enabled by default.

snmp_set_save_descriptions enables or disables saving of descriptions. It is recommended to call snmp_set_save_descriptions(1)before calling init_mib (or similar).

ENVIRONMENT VARIABLES

The main use of environmental variables with respect to these API calls is to configure which MIB modules should be loaded, and where they are located.

MIBDIRS
A colon separated list of directories to search for MIB modules.
Default: /usr/share/snmp/mibs
Used by init_mib, netsnmp_read_module, read_all_mibs and (implicitly) by read_mib.
MIBS
A colon separated list of MIB modules to load.
The default list of modules will depend on how the Net-SNMP software was originally compiled, but is typically:
IP-MIB:IF-MIB:TCP-MIB:UDP-MIB:SNMPv2-MIB:RFC1213-MIB:UCD-SNMP-MIB:HOST-RESOURCES-MIB
If the value of the MIBS environmental variable starts with a '+' character, then these MIB modules will be added to the default list. Otherwise these modules (plus any that they IMPORT from) will be loaded instead of the default list.
If the MIBS environmental variable has the value ALL then read_all_mibs will be called to load the full collection of all available MIB modules.
Used by init_mib only.
MIBFILES
A colon separated list of files to load.
Default: (none)
Used by init_mib only.
