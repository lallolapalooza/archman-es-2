DESCRIPCIÓN

Estas funciones definen un subconjunto de la API que se puede usar para gestionar sesiones SNMP individuales en una aplicación multihilo. Excepto snmp_sess_session(), estas funciones son versiones de sesión única de la API tradicional de la biblioteca SNMP.

Tenga en cuenta que estas funciones utilizan un puntero opaco (handle en los prototipos anteriores) para identificar una sesión individual en lugar de un puntero session (como en la API tradicional).

snmp_sess_init() prepara una estructura snmp_session que contiene las características de transporte y la información común que se utilizará para un conjunto de transacciones SNMP. Después de que esta estructura se pasa a snmp_sess_open() para crear una sesión SNMP, la estructura ya no se utiliza. En su lugar, el puntero opaco devuelto por snmp_sess_open() se utiliza para referirse a esa sesión de ahora en adelante.

Las sesiones SNMP que se crean con snmp_sess_open() no se ven afectadas por snmp_select_info(), snmp_read(), snmp_timeout() ni snmp_close(), y NO DEBERÍAN USARSE CON ellas. En su lugar, se deben utilizar las funciones equivalentes de sesión única descritas aquí.

snmp_sess_init() y snmp_sess_open() toman cada una como entrada un puntero a un objeto de estructura snmp_session. Esta estructura contiene información para un conjunto de transacciones que compartirán características de transporte similares. snmp_sess_session() toma el manejador de sesión opaco y devuelve un puntero a su struct snmp_session asociado.

snmp_sess_send() y snmp_sess_async_send() toman cada una un parámetro pdu, que apunta a un objeto struct snmp_pdu que contiene información que describe una transacción que se realizará a través de una sesión abierta.

Consulte snmp_api.h para conocer las definiciones de estas estructuras.

Con la llamada snmp_sess_async_send(), snmp_sess_read invocará la función de devolución de llamada especificada cuando se reciba la respuesta.

snmp_sess_select_info(), snmp_sess_read() y snmp_sess_timeout() proporcionan una interfaz para el uso de la llamada al sistema select(2) para que las transacciones SNMP de una sesión individual puedan ocurrir de forma asíncrona.

A snmp_sess_select_info() se le pasa la información que se habría pasado a select(2) en ausencia de SNMP. Por ejemplo, esto podría incluir descriptores de archivo asociados con el bucle principal de una aplicación gráfica. Esta información se modifica para que SNMP obtenga el servicio que requiere de la llamada a select(2). En este caso, numfds, fdset y timeout corresponden a los argumentos nfds, readfds y timeout de select(2) respectivamente. La única excepción es que timeout DEBE apuntar SIEMPRE a una estructura struct timeval asignada (pero quizás no inicializada) (no puede ser NULL como para select(2)). Si timeout se hubiera pasado como NULL, block se establecerá en verdadero, y timeout se tratará como indefinido. La misma regla se aplica al regresar de snmp_select_info().

Después de llamar a snmp_sess_select_info(), se debe llamar a select(2) con los datos devueltos. Cuando regrese, se debe llamar a snmp_sess_read() con el fd_set devuelto por select(2). Esto leerá cualquier entrada del socket SNMP de esta sesión. Si select(2) se agota (es decir, devuelve cero), se debe llamar a snmp_sess_timeout() para ver si ha ocurrido un tiempo de espera en la sesión SNMP.

snmp_sess_synch_response es una rutina de conveniencia que enviará la solicitud, esperará la respuesta y la procesará antes de regresar. Consulte las descripciones de snmp_sess_send , snmp_sess_read etc. para obtener más detalles.

DIAGNÓSTICOS

El estado de retorno de error de snmp_sess_open() se indica mediante el retorno de un puntero NULL. El estado de retorno de error de snmp_sess_close() y snmp_sess_send() se indica mediante un valor de retorno de 0. Un estado exitoso devolverá 1.

Se puede obtener más información utilizando snmp_sess_error() para ver qué tipo de error ha ocurrido. Esta función devuelve la variable SNMP snmp_errno, el valor de la variable errno del sistema y una interpretación en cadena de ambas variables. La cadena debe ser liberada después de su uso por el llamador.

Para los errores devueltos por snmp_sess_open(), utilice la función correspondiente snmp_error() en lugar de snmp_sess_error().

Consulte snmp_api.h para ver el conjunto completo de valores de error de la biblioteca SNMP. El valor de error de la biblioteca SNMP snmperr puede ser uno de los siguientes valores:

SNMPERR_GENERR
Ocurrió un error genérico.
SNMPERR_BAD_LOCPORT
El puerto local era incorrecto porque ya se había asignado o se denegó el permiso.
SNMPERR_BAD_ADDRESS
El nombre de host o la dirección proporcionados no eran utilizables.
SNMPERR_BAD_SESSION

SNMPERR_TOO_LONG

DESCRIPTION

This manual page describes the netsnmp session routines.

The session routines provide a way to communicate with SNMP entities. They abstract the underlying transport mechanism (e.g. UDP/IP) and the SNMP message format, allowing applications to focus on SNMP management tasks.

The core structure used is netsnmp_session, which holds all the information needed to establish and maintain an SNMP session.

Initialization and Opening:

snmp_sess_init()
Initializes a netsnmp_session structure. This should be called before any other session routines, except perhaps snmp_sess_open() which implicitly calls snmp_sess_init() if the session is not initialized.
snmp_sess_open()
Opens an SNMP session based on the information in the netsnmp_session structure. It returns a pointer to the opened session or NULL on failure. If the session was not initialized, it will be initialized by this call.

Sending and Receiving:

snmp_sess_send()
Sends an SNMP PDU (Protocol Data Unit) over the established session. The PDU is represented by a netsnmp_pdu structure.
snmp_sess_read()
Waits for and reads an incoming SNMP PDU. This is a blocking call. It returns a pointer to the received PDU or NULL on error.
snmp_sess_select_info()
This function is used in conjunction with select(2) to monitor the session's file descriptor for incoming data. It updates the file descriptor set (fdsetp) and the maximum file descriptor number (numfds_p). It also sets the timeout value for the select call based on the session's retry parameters.

Closing and Error Handling:

snmp_sess_close()
Closes the SNMP session and frees associated resources.
snmp_sess_error()
Returns the last SNMP error code for the session. If optlenp is not NULL, it is used to return the length of the error message.
snmp_sess_perror()
Prints a human-readable error message corresponding to the last SNMP error for the session to standard error. calling_func is a string identifying the function that encountered the error.

Session Duplication and Configuration:

snmp_sess_duplicate()
Creates a duplicate of an existing session. This is useful for sending multiple requests concurrently or for maintaining separate contexts.
snmp_sess_config()
Configures session parameters using a token-value pair. This allows for dynamic setting of various session attributes.

Session Parameter Getters and Setters:

A comprehensive set of functions are provided to get and set various session parameters, including:

  • Timeouts (snmp_sess_set_timeout, snmp_sess_get_timeout, etc.)
  • Retry counts (snmp_sess_set_retry_count, snmp_sess_get_retry_count, etc.)
  • Buffer length (snmp_sess_set_buflen, snmp_sess_get_buflen)
  • Agent address (snmp_sess_set_agentaddr, snmp_sess_get_agentaddr)
  • SNMP version (snmp_sess_set_version, snmp_sess_get_version)
  • Community string (for SNMPv1/v2c) (snmp_sess_set_community, snmp_sess_get_community)
  • User-based security parameters (for SNMPv3) (snmp_sess_set_userbasedauth, snmp_sess_get_userbasedauth, snmp_sess_set_securityModel, snmp_sess_get_securityModel, snmp_sess_set_securityName, snmp_sess_get_securityName)
  • Context name (snmp_sess_set_contextName, snmp_sess_get_contextName)
  • SNMPv3 engine ID, boots, and time (snmp_sess_set_engineID, snmp_sess_get_engineID, etc.)
  • Local SNMPv3 engine ID, boots, and time (snmp_sess_set_localEngineID, snmp_sess_get_localEngineID, etc.)

Target Routines:

The target routines provide a higher-level interface for interacting with SNMP targets defined in configuration files (e.g. snmpd.conf or a dedicated target configuration file). They allow you to send and receive PDUs to named targets without explicitly managing the session details.

snmp_sess_target_init()
Initializes the target subsystem. It may load target definitions from configuration files.
snmp_sess_target_add()
Adds a new target definition. This can be used to dynamically add targets to the system.
snmp_sess_target_send()
Sends an SNMP PDU to a specified named target. This function handles the creation and management of the underlying session if needed.
snmp_sess_target_get()
Retrieves an SNMP PDU from a specified named target. This is typically used for asynchronous operations or when polling a target.
snmp_sess_target_close()
Closes the session associated with a named target.
snmp_sess_target_error()
Retrieves the last SNMP error code for a specific target's session.
snmp_sess_target_perror()
Prints a human-readable error message for a specific target's session.

DIAGNOSTICS

The return values of the session routines indicate success or failure. Specific error conditions are indicated by return values of 0 or NULL, and detailed error information can be retrieved using snmp_sess_error() and snmp_sess_perror().

Common errors include:

SNMPERR_UNKNOWN_PDU
An unknown or invalid PDU type was encountered.
SNMPERR_TIMEOUT
An SNMP request timed out waiting for a response.
