SNDIOD(8) Manual del administrador del sistema SNDIOD(8)

NOMBRE

sndiod — servidor de audio/MIDI

SINOPSIS

sndiod [-d] [-a flag] [-b nframes] [-C min:max] [-c min:max] [-e enc] [-F device] [-f device] [-j flag] [-L addr] [-m mode] [-Q port] [-q port] [-r rate] [-s name] [-t mode] [-U unit] [-v volume] [-w flag] [-z nframes]

DESCRIPCIÓN

El demonio sndiod es una capa intermedia entre los programas de audio o MIDI y el hardware. Realiza el procesamiento de audio necesario para permitir que cualquier programa funcione en cualquier hardware compatible. Por defecto, sndiod acepta conexiones de programas que se ejecutan solo en el mismo sistema; se inicializa solo cuando los programas utilizan sus servicios, lo que permite que sndiod consuma una cantidad insignificante de recursos del sistema el resto del tiempo. Los sistemas sin hardware de audio pueden usar sndiod para mantener los dispositivos conectables en caliente utilizables por defecto a un costo prácticamente nulo.

sndiod opera de la siguiente manera: expone al menos un sub-dispositivo al que cualquier número de programas de audio puede conectarse y usar como si fuera hardware de audio. Durante la reproducción, sndiod recibe datos de audio simultáneamente de todos los programas, los mezcla y envía el resultado al dispositivo de hardware. De manera similar, durante la grabación, duplica los datos de audio grabados desde el dispositivo y los envía a todos los programas. Dado que los datos de audio fluyen a través del proceso sndiod, este tiene la oportunidad de procesar los datos de audio sobre la marcha:

  • Cambiar la codificación de sonido para superar incompatibilidades entre software y hardware.
  • Enrutar el sonido de un canal a otro, unir estéreo o dividir mono.
  • Controlar el volumen de reproducción por aplicación, así como el volumen maestro.
  • Monitorizar el sonido que se está reproduciendo, permitiendo que un programa grabe lo que otros programas reproducen.

El procesamiento se configura por sub-dispositivo, lo que significa que el sonido de todos los programas conectados al mismo sub-dispositivo se procesará de acuerdo con la misma configuración. Se pueden definir múltiples sub-dispositivos, lo que permite que coexistan múltiples configuraciones. El usuario selecciona la configuración que utilizará un programa determinado seleccionando el sub-dispositivo que utiliza el programa.

sndiod expone cajas de paso (hubs) MIDI, permitiendo que los programas se envíen mensajes MIDI entre sí o a puertos MIDI de hardware de manera uniforme.

Finalmente, sndiod expone un puerto de control MIDI utilizable para:

  • Control de volumen.
  • Fuente de reloj común para programas de audio y MIDI.
  • Iniciar, detener y reubicar grupos de programas de audio.

Las opciones son las siguientes:

-a flag
Controla si sndiod abre el dispositivo de audio o el puerto MIDI solo cuando es necesario o lo mantiene abierto todo el tiempo. Si el indicador es on, entonces el dispositivo de audio o el puerto MIDI se mantienen abiertos todo el tiempo, asegurando que ningún otro programa pueda robarlo. Si el indicador es off, entonces se cierra automáticamente, permitiendo que otros programas tengan acceso directo al dispositivo de audio, o que el dispositivo se desconecte. El valor predeterminado es off.
-b nframes
El tamaño del búfer del dispositivo de audio en fotogramas. Un fotograma consiste en una muestra para cada canal en la secuencia. Este es el número de fotogramas que se almacenarán en búfer antes de reproducirse y, por lo tanto, controla la latencia de reproducción. El valor predeterminado es 7680 o el doble del tamaño del bloque (-z), si se ha establecido el tamaño del bloque.
-C min:max, -c min:max
El rango de números de canales para las direcciones de grabación y reproducción, respectivamente, que cualquier cliente tiene permitido utilizar. Este es un subconjunto de los canales del dispositivo de audio. El valor predeterminado es 0:1, es decir, estéreo.
-d
Habilita la depuración en la salida de error estándar y no se desvincula de la terminal controladora. Se puede especificar varias veces para aumentar aún más la verbosidad del registro.
-e enc
Intenta configurar el dispositivo para usar esta codificación. El valor predeterminado es s16. Los nombres de codificación usan el siguiente esquema: signo (s o u) seguido de la precisión en bits, el orden de los bytes (le o be), el número de bytes por muestra y la alineación (msb o lsb). Solo el signo y la precisión son obligatorios. Ejemplos: u8, s16le, s24le3, s24le4lsb.
-F device
Igual que -f, excepto que si el dispositivo se desconecta, se utilizará el proporcionado con la opción anterior -f o -F.
-f device
Agrega este dispositivo de audio sndio(7) a los dispositivos utilizados para reproducir y/o grabar. Las opciones precedentes por dispositivo (-aberwz) se aplican a este dispositivo. Los sub-dispositivos (-s) que se apliquen después se adjuntarán a este dispositivo. El modo y los parámetros del dispositivo se determinan a partir de los sub-dispositivos adjuntos a él. Si no se utiliza ninguna opción -f, sndiod utilizará rsnd/0, rsnd/1, ..., rsnd/3.
-j flag
Controla si los canales del programa se unen o expanden si el número de canales solicitados por un programa no es igual al número de canales del dispositivo. Si el indicador es off, entonces los canales del cliente se enrutan al canal del dispositivo correspondiente, posiblemente descartando canales no presentes en el dispositivo. Si el indicador es on, entonces un solo canal de cliente puede enviarse en múltiples canales de dispositivo, o múltiples canales de cliente pueden enviarse a un solo canal de dispositivo. Por ejemplo, esta característica podría usarse para conversiones de mono a estéreo. El valor predeterminado es on.
-L addr
Especifica una dirección de red local en la que sndiod debe escuchar; sndiod escuchará en el puerto TCP 11025+n, donde n es el número de unidad especificado con -U. Sin esta opción, sndiod escucha solo en el socket de dominio UNIX, y no es accesible desde ninguna red. Si el argumento de la opción es ‘-’, entonces sndiod aceptará conexiones desde cualquier dirección. Dado que la comunicación no es segura, esta opción solo es adecuada para redes locales.
-m mode
Establece el modo del dispositivo de audio para la dirección especificada por -F o -f. El modo puede ser play o rec.
-Q port
Especifica el número de puerto TCP para el servidor de control MIDI. El valor predeterminado es 11027.
-q port
Especifica el número de puerto TCP para el servidor de audio. El valor predeterminado es 11024.
-r rate
La frecuencia de muestreo del dispositivo de audio en Hz. El valor predeterminado es 44100.
-s name
Define un nuevo sub-dispositivo con el nombre especificado. La sintaxis para name es sub-device o sub-device:rate, sub-device:rate:enc, sub-device:rate:enc:channels. Por ejemplo, rec:44100:s16le:1 define un sub-dispositivo llamado rec que siempre grabará a 44100 Hz, s16le, y solo con un canal.
-t mode
Controla si sndiod opera en modo monitor o mix. El modo monitor permite grabar lo que otros programas reproducen. El modo mix (predeterminado) mezcla la salida de todos los programas en un solo flujo.
-U unit
Número de unidad del demonio sndiod. Esto se usa para determinar el nombre del socket UNIX-domain (si no se usa -L) y el número de puerto TCP para los servidores de audio y MIDI.
-v volume
Establece el volumen de reproducción maestro. El valor es un entero de 0 a 100. El valor predeterminado es 100.
-w flag
Controla si el dispositivo de audio se abre en modo de solo reproducción (play) o modo de solo grabación (rec). Si el indicador es play, el dispositivo se abre solo para reproducción. Si el indicador es rec, el dispositivo se abre solo para grabación. El valor predeterminado es abrirlo para ambos.
-z nframes
El tamaño del bloque de audio en fotogramas. El tamaño del bloque es el número de fotogramas que se envían al dispositivo de audio a la vez. Un fotograma consta de una muestra por canal. El valor predeterminado es 3840.

OPTIONS

The following options are available:

-a average
Set the size of the audio input and output buffers in frames. The default is 512 frames.
-b buffer
Set the audio buffer size in frames. The default is 1024 frames.
-c channels
Set the number of channels to use for playback and recording. The default is 2.
-C flags
Set flags for the sub-device. Valid flags are realtime and monitor.
-d device
Specify the audio device to use. If not specified, the default device is used.
-e encoding
Set the audio encoding. Valid encodings are pcm8, pcm16, pcm24, and pcm32. The default is pcm16.
-f device
Attach to the given audio device. This option can be used multiple times to attach to multiple devices. If no -f option is used, sndiod will use rsnd/0.
-F device
Same as -f, but the device is considered available only when it is plugged. This allows runtime detection of devices.
-H host
Set the remote host to connect to. If not specified, the local host is used. Use -H localhost for the local server, or -H none if all hosts and users are trusted.
-m mode
Set the sub-device mode. Valid modes are play, rec, and mon, corresponding to playback, recording and monitoring. A monitoring stream is a fake recording stream corresponding to the mix of all playback streams. Multiple modes can be specified, separated by commas, but the same sub-device cannot be used for both recording and monitoring. The default is play,rec (i.e. full-duplex).
-Q port
Specify an alternate MIDI port to use. If it doesn't work, the one given with the last -Q or -q options will be used. For instance, this allows a USB MIDI controller to be replaced without the need to restart programs using it.
-q port
Expose the given MIDI port. This allows multiple programs to share the port. If no -q option is used, sndiod will use rmidi/0, rmidi/1, ..., rmidi/7.
-r rate
Attempt to force the device to use this sample rate in Hertz. The default is 48000.
-s name
Add name to the list of sub-devices to expose. This allows clients to use sndiod instead of the physical audio device for audio input and output in order to share the physical device with other clients. Defining multiple sub-devices allows splitting a physical audio device into sub-devices having different properties (e.g. channel ranges). The given name corresponds to the “option” part of the sndio(7) device name string.
-t mode
Select the way clients are controlled by MIDI Machine Control (MMC) messages received by sndiod. If the mode is off (the default), then programs are not affected by MMC messages. If the mode is slave, then programs are started synchronously by MMC start messages; additionally, the server clock is exposed as MIDI Time Code (MTC) messages allowing MTC-capable software or hardware to be synchronized to audio programs.
-U unit
Unit number. Each sndiod server instance has a unique unit number, used in sndio(7) device names. The default is 0.
-v volume
Software volume attenuation of playback. The value must be between 1 and 127, corresponding to -42dB and -0dB attenuation in 1/3dB steps. Clients inherit this parameter. Reducing the volume in advance allows a client's volume to stay independent from the number of clients as long as their number is small enough. 18 volume units (i.e. -6dB attenuation) allows the number of playback programs to be doubled. The default is 127.
-w flag
Control sndiod behaviour when the maximum volume of the hardware is reached and a new program starts playing. This happens only when volumes are not properly set using the -v option. If the flag is on, then the master volume is automatically adjusted to avoid clipping. The default is off.
-z nframes
The audio device block size in frames. This is the number of frames between audio clock ticks, i.e. the clock resolution. If a sub-device is created with the -t option, and MTC is used for synchronization, the clock resolution must be 96, 100 or 120 ticks per second for maximum accuracy. For instance, 100 ticks per second at 48000Hz corresponds to a 480 frame block size. The default is 480 or half of the buffer size (-b), if the buffer size is set.

COMMAND LINE PARAMETERS

On the command line, per-device parameters (-aberwz) must precede the device definition (-f), and per-sub-device parameters (-Ccjmtvx) must precede the sub-device definition (-s). Sub-device definitions (-s) must follow the definition of the device (-f) to which they are attached.

If no audio devices (-f) are specified, settings are applied as if the default device is specified. If no sub-devices (-s) are specified for a device, a default sub-device is created attached to it. If a device (-f) is defined twice, both definitions are merged: parameters of the first one are used but sub-devices (-s) of both definitions are created. The default sndio(7) device used by sndiod is rsnd/0, and the default sub-device exposed by sndiod is snd/default.

If sndiod is sent SIGINT or SIGTERM, it terminates. If sndiod is sent SIGHUP, it reopens all audio devices and MIDI ports.

By default, when the program cannot accept recorded data fast enough or cannot provide data to play fast enough, the program is paused, i.e. samples that cannot be written are discarded and samples that cannot be read are replaced by silence. If a sub-device is created with the -t option, then recorded samples are discarded, but the same amount of silence will be written once the program is unblocked, in order to reach the right position in time. Similarly silence is played, but the same amount of samples will be discarded once the program is unblocked. This ensures proper synchronization between programs.

MIDI CONTROL

sndiod creates a MIDI port with the same name as the exposed audio sub-device to which MIDI programs can connect. sndiod exposes the audio device clock and allows audio device properties to be controlled through MIDI.

A MIDI channel is assigned to each stream, and the volume is changed using the standard volume controller (number 7). Similarly, when the audio client changes its volume, the same MIDI controller message is sent out; it can be used for instance for monitoring or as feedback for motorized faders.

The master volume can be changed using the standard master volume system exclusive message.

Streams created with the -t option are controlled by the following MMC messages:

relocate
This message is ignored by audio sndiod clients, but the given time position is sent to MIDI ports as an MTC “full frame” message forcing all MTC-slaves to relocate to the given position (see below).
start
Put all streams in starting mode. In this mode, sndiod waits for all streams to become ready to start, and then starts them synchronously. Once started, new streams can be created (sndiod) but they will be blocked until the next stop-to-start transition.
stop
Put all streams in stopped mode (the default). In this mode, any stream attempting to start playback or recording is paused. Client streams that are already started are not affected until they stop and try to start again.

Streams created with the -t option export the sndiod device clock using MTC, allowing non-audio software or hardware to be synchronized to the audio stream. Maximum accuracy is achieved when the number of blocks per second is equal to one of the standard MTC clock rates (96, 100 and 120Hz). The following sample rates (-r) and block sizes (-z) are recommended:

  • 44100Hz, 441 frames (MTC rate is 100Hz)
  • 48000Hz, 400 frames (MTC rate is 120Hz)
  • 48000Hz, 480 frames (MTC rate is 100Hz)
  • 48000Hz, 500 frames (MTC rate is 96Hz)

For instance, the following command will create two devices: the default snd/default and a MIDI-controlled snd/mmc:

$ sndiod -r 48000 -z 400 -s default -t slave -s mmc

Streams connected to snd/default behave normally, while streams connected to snd/mmc wait for the MMC start signal and start synchronously. Regardless of which device a stream is connected to, its playback volume knob is exposed.

HOT PLUGGING

If devices specified with -F are unavailable when needed or unplugged at runtime, sndiod will attempt to seamlessly fall back to the last device specified.

sndiod will not automatically switch to a specified device that is plugged at runtime. Instead, sndioctl(1) must be used to change the server.device control.

For instance, specifying a USB device with -F following a PCI device with -f allows sndiod to use the USB one preferably when it's connected and to fall back to the PCI one when it's disconnected.

EXAMPLES

Start server using default parameters, creating an additional sub-device for output to channels 2:3 only (rear speakers on most cards), exposing the snd/default and snd/rear devices:

$ sndiod -s default -s rear -f snd/rear:2,3

EJEMPLOS

Inicie el servidor creando el subdispositivo predeterminado con bajo volumen y un subdispositivo adicional para salida de alto volumen, exponiendo los dispositivos snd/default y snd/max:

$ sndiod -s default -v 65 -v 127 -s max

Inicie el servidor creando el subdispositivo predeterminado con bajo volumen y un subdispositivo adicional para salida de alto volumen, exponiendo los dispositivos snd/default y snd/max:

$ sndiod -s default -c 2:3 -s rear

Inicie el servidor configurando el dispositivo de audio para usar una frecuencia de muestreo de 48 kHz, un tamaño de bloque de 240 fotogramas y búferes de 2 bloques. La latencia correspondiente es de 10 ms, que es el tiempo que tarda el sonido en propagarse 3,5 metros.

$ sndiod -r 48000 -b 480 -z 240

ERRORES

El remuestreo es de baja calidad; especialmente se debe evitar la reducción de la frecuencia de muestreo al grabar.

Si se usa -a off, sndiod crea subdispositivos para exponerlos y luego abre el hardware de audio bajo demanda. Técnicamente, esto permite que sndiod intente usar uno de los subdispositivos que expone como dispositivo de audio, creando un punto muerto. No hay nada que impida al usuario autolesionarse creando dicho punto muerto.
