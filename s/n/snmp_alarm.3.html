snmp_alarm(3)

Paquete: net-snmp

Licencias: BSD

SNMP_ALARM(3) Net-SNMP SNMP_ALARM(3)

NOMBRE

snmp_alarm_register, snmp_alarm_register_hr, snmp_alarm_unregister - funciones de alarma

SINOPSIS

#include <net-snmp/utilities.h>

unsigned int
snmp_alarm_register(unsigned int segundos,
unsigned int flags,
SNMPAlarmCallback *f_callback,
void *clientarg);

unsigned int
snmp_alarm_register_hr(struct timeval t,
unsigned int flags,
SNMPAlarmCallback *f_callback,
void *clientarg);

void
snmp_alarm_unregister(unsigned int reg);

DESCRIPCIÓN

Estas funciones implementan soporte para un mecanismo genérico de manejo de temporizadores para que múltiples partes de una aplicación registren callbacks de funciones para que ocurran en un momento determinado en el futuro.

USO

El uso es bastante simple y directo: simplemente cree una función que desee que se llame de vuelta en algún momento en el futuro. La definición de la función debe ser similar a:

void mi_callback(unsigned int reg, void *clientarg);

Luego, llame a snmp_alarm_register() para registrar su callback para que se llame segundos a partir de ahora. El campo flags debe ser SA_REPEAT o NULL. Si flags se establece con SA_REPEAT, entonces la función de callback registrada se llamará cada segundos. Si flags es NULL, la función solo se llamará una vez y luego se eliminará del registro del sistema de alarmas.

El parámetro clientarg en la función de registro solo es utilizado por la función cliente y se almacena y se devuelve directamente a ellos en cada llamada al sistema.

La función snmp_alarm_register() devuelve un unsigned int único (que también se pasa como el primer argumento de cada callback), que luego se puede usar para eliminar el callback de la cola en un momento posterior utilizando la función snmp_alarm_unregister(). Si la llamada a snmp_alarm_register() falla, devuelve cero. En particular, tenga en cuenta que es totalmente permisible que una función de alarma se desregistre a sí misma.

La función snmp_alarm_register_hr() es idéntica en operación a la función snmp_alarm_register(), pero toma un struct timeval como primer parámetro y programa el callback después del período representado por t (las letras hr significan "alta resolución"). La operación de esta función depende de la disponibilidad de la llamada al sistema setitimer(2) por parte del sistema operativo. Si esta llamada al sistema no está disponible, la alarma se programará como si se hubiera llamado a snmp_alarm_register() con un primer argumento igual al valor del miembro tv_sec de t. Vea, sin embargo, las notas a continuación.

INICIALIZACIÓN

La función init_snmp() inicializa el subsistema snmp_alarm llamando a init_snmp_alarm() y luego a init_alarm_post_config() para configurar el primer temporizador para inicializar la función de callback. Estas dos funciones no deben ser utilizadas directamente por las aplicaciones.

NOTAS

El comportamiento predeterminado del subsistema snmp_alarm es solicitar señales SIGALRM del sistema operativo a través de las llamadas al sistema alarm(2) o setitimer(2). Sin embargo, esto tiene la desventaja de que ninguna otra parte de la aplicación puede usar la funcionalidad SIGALRM (o, si alguna otra parte de la aplicación *sí* usa la funcionalidad SIGALRM, el subsistema snmp_alarm no funcionará correctamente).

Sin embargo, si su aplicación ejecuta un bucle de eventos basado en select(2), no es necesario utilizar SIGALRM para el subsistema snmp_alarm, dejándolo disponible para otras partes de la aplicación. Esto se hace haciendo la siguiente llamada:

netsnmp_ds_set_boolean(NETSNMP_DS_LIBRARY_ID, 
                       NETSNMP_DS_LIB_ALARM_DONT_USE_SIG, 1);

antes de llamar a init_snmp(). Luego, snmp_select_info() tiene en cuenta las alarmas al calcular el valor de tiempo de espera que se utilizará para select(2). Todo lo que necesita hacer es llamar a run_alarms() cuando select(2) se agota el tiempo de espera (valor de retorno de cero). Este es el enfoque que se toma en el agente; vea snmpd.c. Además, al usar este método, las alarmas de alta resolución no dependen de la presencia de la llamada al sistema setitimer(2), aunque la precisión general, por supuesto, todavía está determinada por el sistema operativo subyacente. Recomendado.

VER TAMBIÉN
