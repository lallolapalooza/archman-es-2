DESCRIPCIÓN

Estas funciones definen un subconjunto de la API que se puede usar para gestionar sesiones SNMP individuales en una aplicación multihilo. Excepto snmp_sess_session(), estas funciones son versiones de sesión única de la API tradicional de la biblioteca Net-SNMP.

Tenga en cuenta que estas funciones utilizan un puntero opaco (handle en los prototipos anteriores) para identificar una sesión individual en lugar de un puntero session (como en la API tradicional).

snmp_sess_init() prepara una estructura `snmp_session` que contiene las características de transporte y la información común que se utilizará para un conjunto de transacciones SNMP. Después de que esta estructura se pasa a snmp_sess_open() para crear una sesión SNMP, la estructura ya no se utiliza. En su lugar, se utiliza el puntero opaco devuelto por snmp_sess_open() para referirse a esa sesión en lo sucesivo.

Las sesiones SNMP que se crean con snmp_sess_open() no se ven afectadas por, y NO DEBEN UTILIZARSE CON, snmp_select_info(), snmp_read(), snmp_timeout() ni snmp_close(). En su lugar, se deben utilizar las funciones equivalentes de sesión única descritas aquí.

snmp_sess_init() y snmp_sess_open() toman como entrada un puntero a un objeto de estructura `snmp_session`. Esta estructura contiene información para un conjunto de transacciones que compartirán características de transporte similares. snmp_sess_session() toma el identificador de sesión opaco y devuelve un puntero a su estructura `snmp_session` asociada.

snmp_sess_send() y snmp_sess_async_send() toman cada una un parámetro pdu, que apunta a un objeto de estructura `snmp_pdu` que contiene información que describe una transacción que se realizará sobre una sesión abierta.

Consulte `snmp_api.h` para ver las definiciones de estas estructuras.

Con la llamada snmp_sess_async_send(), snmp_sess_read invocará la función de devolución de llamada especificada cuando se reciba la respuesta.

snmp_sess_select_info(), snmp_sess_read() y snmp_sess_timeout() proporcionan una interfaz para el uso de la llamada al sistema select(2) para que las transacciones SNMP de una sesión individual puedan ocurrir de forma asíncrona.

A snmp_sess_select_info() se le pasa la información que se habría pasado a select(2) en ausencia de SNMP. Por ejemplo, esto podría incluir descriptores de archivo asociados con el bucle principal de una aplicación gráfica. Esta información se modifica para que SNMP obtenga el servicio que requiere de la llamada a select(2). En este caso, numfds, fdset y timeout corresponden a los argumentos nfds, readfds y timeout de select(2) respectivamente. La única excepción es que `timeout` debe apuntar SIEMPRE a un `struct timeval` asignado (pero quizás no inicializado) (no puede ser NULL como para select(2)). Si `timeout` se hubiera pasado como NULL, block se establece en verdadero y timeout se trata como indefinido. La misma regla se aplica al regresar de snmp_select_info().

Después de llamar a snmp_sess_select_info(), se debe llamar a select(2) con los datos devueltos. Cuando regrese, se debe llamar a snmp_sess_read() con el `fd_set` devuelto por select(2). Esto leerá cualquier entrada del socket SNMP de esta sesión. Si select(2) agota el tiempo de espera (es decir, devuelve cero), se debe llamar a snmp_sess_timeout() para ver si ha ocurrido un tiempo de espera en la sesión SNMP.

snmp_sess_synch_response es una rutina de conveniencia que enviará la solicitud, esperará la respuesta y la procesará antes de regresar. Consulte las descripciones de snmp_sess_send, snmp_sess_read, etc. para obtener detalles.

DIAGNÓSTICOS

El estado de retorno de error de snmp_sess_open() se indica mediante el retorno de un puntero NULL. El estado de retorno de error de snmp_sess_close() y snmp_sess_send() se indica mediante un valor de retorno de 0. Un estado exitoso devolverá 1.

Se puede obtener información adicional utilizando snmp_sess_error() para ver qué tipo de error ha ocurrido. Esta función devuelve la variable snmp_errno de SNMP, el valor de la variable errno del sistema y una interpretación en cadena de ambas variables. La cadena debe ser liberada después de su uso por el llamador.

Para los errores devueltos por snmp_sess_open(), utilice la función correspondiente snmp_error() en lugar de snmp_sess_error().

Consulte `snmp_api.h` para ver el conjunto completo de valores de error de la biblioteca SNMP. El valor de error de la biblioteca SNMP snmperr puede ser uno de los siguientes valores:

SNMPERR_GENERR
Ocurrió un error genérico.
SNMPERR_BAD_LOCPORT
El puerto local era incorrecto porque ya había sido asignado o se denegó el permiso.
SNMPERR_BAD_ADDRESS
El nombre o la dirección del host proporcionado no era utilizable.
SNMPERR_BAD_SESSION
La sesión especificada no estaba abierta.

snmp_sess_send(3)

NAME

snmp_sess_send - send an SNMP packet

SYNOPSIS

#include <net-snmp/session.h>

int
snmp_sess_send(struct snmp_session *session, struct snmp_pdu *pdu);

DESCRIPTION

The snmp_sess_send function sends the given pdu structure through the specified session. The function takes a pointer to an snmp_session structure and a pointer to an snmp_pdu structure. It returns the number of bytes sent, or -1 on error.

The pdu structure is consumed by this function. If you need to reuse the pdu, you should make a copy before calling snmp_sess_send.

DIAGNOSTICS

The return value is the number of bytes sent, or -1 on error. If an error occurs, the session->s_errno field will be set to indicate the error. Possible error codes are:

SNMPERR_BAD_SESSION
The session structure is invalid.
SNMPERR_BAD_PDU
The PDU structure is invalid.
SNMPERR_V3_ERROR
An error occurred during SNMPv3 processing.
SNMPERR_SERIALIZATION
An error occurred during PDU serialization.
SNMPERR_SEND_FAILED
The underlying send operation failed.
SNMPERR_UNKNOWN_PDU
SNMPERR_TIMEOUT
