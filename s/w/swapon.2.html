swapon(2) Manual de llamadas al sistema swapon(2)

NOMBRE

swapon, swapoff - iniciar/detener el intercambio en archivo/dispositivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/swap.h>
int swapon(const char *path, int swapflags);
int swapoff(const char *path);

DESCRIPCIÓN

swapon() establece el área de intercambio al archivo o dispositivo de bloques especificado por path. swapoff() detiene el intercambio al archivo o dispositivo de bloques especificado por path.

Si se especifica el indicador SWAP_FLAG_PREFER en el argumento swapflags de swapon(), la nueva área de intercambio tendrá una prioridad más alta que la predeterminada. La prioridad se codifica dentro de swapflags como:


(prio << SWAP_FLAG_PRIO_SHIFT) & SWAP_FLAG_PRIO_MASK

Si se especifica el indicador SWAP_FLAG_DISCARD en el argumento swapflags de swapon(), las páginas de intercambio liberadas se desecharán antes de ser reutilizadas, si el dispositivo de intercambio soporta la operación de descarte o recorte (trim). (Esto puede mejorar el rendimiento en algunos Dispositivos de Estado Sólido, pero a menudo no es así.) Ver también NOTAS.

Estas funciones solo pueden ser utilizadas por un proceso privilegiado (uno que tenga la capacidad CAP_SYS_ADMIN).

Prioridad

Cada área de intercambio tiene una prioridad, ya sea alta o baja. La prioridad predeterminada es baja. Dentro de las áreas de baja prioridad, las áreas más nuevas tienen una prioridad aún menor que las áreas más antiguas.

Todas las prioridades establecidas con swapflags son de alta prioridad, más altas que las predeterminadas. Pueden tener cualquier valor no negativo elegido por el llamante. Números más altos significan mayor prioridad.

Las páginas de intercambio se asignan desde las áreas en orden de prioridad, primero la prioridad más alta. Para áreas con diferentes prioridades, un área de mayor prioridad se agota antes de usar un área de menor prioridad. Si dos o más áreas tienen la misma prioridad, y es la prioridad más alta disponible, las páginas se asignan de forma round-robin entre ellas.

A partir de Linux 1.3.6, el kernel generalmente sigue estas reglas, pero hay excepciones.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1, y errno se establece para indicar el error.

ERRORES

EBUSY
(para swapon()) La path especificada ya se está utilizando como área de intercambio.
EINVAL
El archivo path existe, pero no se refiere a un archivo regular ni a un dispositivo de bloques;
EINVAL
(swapon()) La ruta indicada no contiene una firma de intercambio válida o reside en un sistema de archivos en memoria como tmpfs(5).
EINVAL (desde Linux 3.4)
(swapon()) Se especificó un valor de indicador inválido en swapflags.
EINVAL
(swapoff()) path actualmente no es un área de intercambio.
ENFILE
Se alcanzó el límite del sistema para el número total de archivos abiertos.
ENOENT
El archivo path no existe.
ENOMEM
El sistema tiene memoria insuficiente para iniciar el intercambio.
EPERM
El llamante no tiene la capacidad CAP_SYS_ADMIN. Alternativamente, ya se están utilizando el número máximo de archivos de intercambio; ver NOTAS más abajo.

ESTANDARES

Linux.

HISTORIA

El argumento swapflags se introdujo en Linux 1.3.2.

NOTAS

La partición o ruta debe prepararse con mkswap(8).

Existe un límite superior en el número de archivos de intercambio que pueden utilizarse, definido por la constante del kernel MAX_SWAPFILES. Antes de Linux 2.4.10, MAX_SWAPFILES tiene el valor 8; desde Linux 2.4.10, tiene el valor 32. Desde Linux 2.6.18, el límite se reduce en 2 (por lo tanto, 30), desde Linux 5.19, el límite se reduce en 3 (por lo tanto: 29) si el kernel se compila con la opción CONFIG_MIGRATION (que reserva dos entradas de tabla de intercambio para las características de migración de páginas de mbind(2) y migrate_pages(2)). Desde Linux 2.6.32, el límite se reduce adicionalmente en 1 si el kernel se compila con la opción CONFIG_MEMORY_FAILURE. Desde Linux 5.14, el límite se reduce adicionalmente en 4 si el kernel se compila con la opción CONFIG_DEVICE_PRIVATE. Desde Linux 5.19, el límite se reduce adicionalmente en 1 si el kernel se compila con la opción CONFIG_PTE_MARKER.

El descarte de páginas de intercambio se introdujo en Linux 2.6.29, luego se hizo condicional a la bandera SWAP_FLAG_DISCARD en Linux 2.6.36, que aún descarta el área de intercambio completa cuando se llama a swapon(), incluso si ese bit de bandera no está establecido.

VER TAMBIÉN

mkswap(8), swapoff(8), swapon(8)
