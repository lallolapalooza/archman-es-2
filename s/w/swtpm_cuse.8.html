NOMBRE

swtpm - Emulador de TPM para TPM 1.2 y 2.0

SINOPSIS

swtpm socket [OPCIONES]

swtpm chardev [OPCIONES]

swtpm cuse [OPCIONES]

DESCRIPCIÓN

swtpm implementa un emulador de software de TPM basado en libtpms. Proporciona acceso a la funcionalidad de TPM a través de una interfaz de socket TCP/IP o puede escuchar comandos en un dispositivo de caracteres, o crear una interfaz CUSE (dispositivo de caracteres en el espacio de usuario) para recibir comandos de TPM.

A menos que se utilicen los parámetros de línea de comandos correspondientes, la versión de socket de swtpm requiere que la variable de entorno TPM_PORT esté configurada en el puerto TCP/IP en el que el proceso debe escuchar los mensajes de solicitud de TPM.

De manera similar, la variable de entorno TPM_PATH puede estar configurada y contener el nombre de un directorio donde el TPM puede almacenar su estado persistente.

El proceso swtpm puede ser terminado de forma controlada enviándole una señal SIGTERM.

La versión cuse de swtpm requiere derechos de root para iniciar el TPM.

Opciones para la interfaz de socket

Las siguientes opciones se admiten si se elige la interfaz socket:

-p|--port <puerto>
Utilice el puerto dado en lugar de la variable de entorno TPM_PORT.
-t|--terminate
Termine el TPM después de que el cliente haya cerrado la conexión del canal de datos (solo TCP).
--server [type=tcp][,port=<puerto>[,bindaddr=<direccion> [,ifname=<nombre_interfaz>]]][,fd=<descriptor_archivo>][,disconnect]
Espere conexiones TCP en el puerto dado; si no se proporciona un puerto, se debe pasar un descriptor de archivo con el parámetro fd y los comandos se leerán de este descriptor de archivo. Si se proporciona un puerto, también se puede proporcionar la dirección de enlace en la que escuchar las conexiones TCP; la dirección de enlace predeterminada es 127.0.0.1. Si se proporciona una dirección IPv6 de enlace local, se debe proporcionar el nombre de la interfaz a la que enlazar con ifname.

Este parámetro habilita una conexión persistente por defecto a menos que se proporcione la opción disconnect. Este parámetro debe usarse en lugar de las opciones -p y --fd.

--server type=unixio[,path=<ruta>][,fd=<descriptor_archivo>] [,mode=<0...>][,uid=<uid>][,gid=<gid>]
Espere conexiones UnixIO en la ruta dada. Si no se proporciona una ruta, se debe pasar un descriptor de archivo en su lugar. El parámetro mode permite a un usuario establecer los bits de modo de archivo de la ruta UnixIO. El valor de los bits de modo debe darse como un número octal que comience con '0'. El valor predeterminado es 0770. uid y gid establecen la propiedad de la ruta del socket UnixIO. Esta operación requiere privilegios de root.

Opciones para la interfaz de dispositivo de caracteres

Las siguientes opciones se admiten si se elige la interfaz chardev:

-c|--chardev <ruta_del dispositivo>
Utilice el dispositivo dado para escuchar comandos de TPM y enviar respuestas.
--vtpm-proxy
Cree una instancia de dispositivo proxy vTPM de Linux y lea comandos de TPM de su dispositivo backend.

Opciones para la interfaz CUSE

Las siguientes opciones se admiten si se elige la interfaz cuse:

-n|--name <NOMBRE>
El TPM utilizará un dispositivo con el nombre dado. Se creará un dispositivo con el nombre dado en /dev. Esta es una opción obligatoria.
-M|--maj <MAYOR>
Cree el dispositivo con el número mayor dado.
-m|--min <MENOR>
Cree el dispositivo con el número menor dado.

Opciones para las interfaces de socket y dispositivo de caracteres:

Las siguientes opciones son compatibles con las interfaces de socket y dispositivo de caracteres:

-f|--fd <descriptor_archivo>
Utilice el descriptor de archivo de socket o el descriptor de archivo de dispositivo de caracteres dado para recibir comandos de TPM y enviar respuestas. Para la interfaz de socket, esta opción asume automáticamente -t.
-d|--daemon
Convierte el proceso en un demonio.
--ctrl type=[unixio|tcp][,path=<ruta>] [,port=<puerto>[,bindaddr=<direccion>[,ifname=<nombre_interfaz>]]] [,fd=<descriptor_archivo>|clientfd=<descriptor_archivo>] [,mode=<0...>][,uid=<uid>][,gid=<gid>][,terminate]
Esta opción agrega un canal de control al TPM. El canal de control puede utilizar un socket UnixIO con una ruta o descriptor de archivo dados, o puede utilizar un socket TCP en el puerto o descriptor de archivo dados. Si se proporciona un puerto, también se puede proporcionar la dirección de enlace en la que escuchar las conexiones TCP; la dirección de enlace predeterminada es 127.0.0.1. Si se proporciona una dirección IPv6 de enlace local, se debe proporcionar el nombre de la interfaz a la que enlazar con ifname.

El parámetro mode permite a un usuario establecer los bits de modo de archivo de la ruta UnixIO. El valor de los bits de modo debe darse como un número octal que comience con '0'. El valor predeterminado es 0770. uid y gid establecen la propiedad de la ruta del socket UnixIO. Esta operación requiere privilegios de root.

El parámetro terminate habilita la terminación automática de swtpm cuando se pierde la conexión del canal de control. Esto es útil en escenarios donde la conexión del canal de control se mantiene permanentemente, como por QEMU, y swtpm debe terminar al terminarse anormalmente el cliente que ya no pudo enviar un CMD_SHUTDOWN a través del canal de control.

El canal de control permite el control fuera de banda del TPM, como el reinicio del TPM.

Opciones para todas las interfaces

Las siguientes opciones son compatibles con todas las interfaces:

--tpmstate dir=<directorio>|backend-uri=<uri>[,mode=<0...>][,lock]
Utilice la ruta dada en lugar de la variable de entorno TPM_PATH.

Si se especifica dir, los archivos de estado del TPM se escribirán en el directorio con los bits de modo de archivo dados. Este valor debe proporcionarse como un número octal que comience con '0'. El valor predeterminado es 0640.

Si se especifica backend-uri, los datos de estado del TPM se almacenarán en la URI. Actualmente, backend-uri=dir://<ruta_al_directorio> y backend-uri=file://<ruta_al_directorio> están disponibles. Para 'dir://', la URI debe especificar la ruta al directorio donde se almacenan los archivos. Si ruta_al_directorio comienza con '/' entonces la ruta se interpreta como una ruta absoluta, de lo contrario es una ruta relativa al directorio actual. Para 'file://', la URI debe especificar un solo archivo o dispositivo de bloque donde se almacenará el estado del TPM. Un dispositivo de bloque debe existir ya y ser lo suficientemente grande para almacenar todo el estado. (desde v0.7)

Si se especifica lock, el backend de almacenamiento del TPM bloqueará el archivo de estado del TPM para evitar el acceso concurrente por otra instancia de swtpm. El valor predeterminado, si falta este parámetro de opción, depende del backend de almacenamiento. Para el backend de directorio, el valor predeterminado es que el bloqueo está siempre habilitado, y por lo tanto, este parámetro de opción no necesita ser proporcionado. Para el backend de archivo, es requerido ya que el valor predeterminado es que el bloqueo no está habilitado automáticamente. Para evitar el bloqueo, se puede usar lock=false.

--tpm2
Elija la funcionalidad TPM 2; por defecto se elige TPM 1.2.
--log [fd=<descriptor de archivo>|file=<ruta>][,level=<n>] [,prefix=<prefijo>][,truncate]
Habilita el registro en un archivo dado su descriptor de archivo o su ruta. Usa '-' para la ruta para suprimir el registro.

El parámetro level permite al usuario elegir el nivel de registro. A partir del nivel de registro 5, se activa el registro de depuración de libtpms.

Todas las líneas registradas irán precedidas por prefix. Por defecto no se antepone ningún prefijo.

Si se pasa truncate, el archivo de registro se truncará.

--locality reject-locality-4[,allow-set-locality]
El parámetro reject-locality-4 hará que se devuelvan mensajes de error de TPM para solicitudes de establecer el TPM en la localidad 4.

El parámetro allow-set-locality permite que swtpm reciba comandos TPM/TPM2_SetLocality. Este parámetro es útil si el controlador proxy VTPM de Linux está habilitado mediante el paso de descriptores de archivo. Esta opción está implícita por la opción --vtpm-proxy y, por lo tanto, no es necesario configurarla explícitamente si se pasa esta opción. En todos los demás casos, se debe tener cuidado con quién puede enviar el comando TPM/TPM2_SetLocality.

--key file=<archivo clave>|fd=<descriptor de archivo> [,format=<hex|binario>][,mode=aes-cbc|aes-256-cbc], [remove[=true|false]]
Habilita el cifrado de los archivos de estado del TPM. El archivo clave debe contener una clave AES de tamaño compatible; se admiten claves de 128 bits (16 bytes) y 256 bits (32 bytes).

La clave puede estar en formato binario, en cuyo caso el tamaño del archivo debe ser de 16 o 32 bytes. Si la clave está en formato hexadecimal (por defecto), la clave puede constar de 32 o 64 dígitos hexadecimales que comiencen con un '0x' opcional.

El parámetro mode indica qué modo de encadenamiento de bloques se va a utilizar. Actualmente se admiten aes-cbc (aes-128-cbc) y aes-256-cbc. Los datos cifrados están protegidos contra manipulaciones mediante encrypt-then-mac.

El parámetro remove intentará eliminar el archivo clave dado una vez que se haya leído la clave.

--key pwdfile=<archivo de contraseña>|pwdfd=<descriptor de archivo> [,mode=aes-cbc|aes-256-cbc][remove[=true|false]][,kdf=sha512|pbkdf2]
Esta variante del parámetro clave permite al usuario proporcionar una contraseña en un archivo. El archivo se lee y se deriva una clave de él utilizando un hash SHA512 o PBKDF2. Por defecto se utiliza PBKDF2.
--migration-key file=<archivo clave>|fd=<descriptor de archivo> [,format=<hex|binario>][,mode=aes-cbc|aes-256-cbc] [,remove[=true|false]]
La disponibilidad de una clave de migración garantiza que el estado del TPM no se revelará en forma no cifrada cuando los blobs de estado del TPM se recuperen a través de la interfaz ioctl. La clave de migración no se utiliza para cifrar el estado del TPM escrito en archivos, para eso se utiliza el parámetro --key.

La clave de migración y la clave utilizada para cifrar los archivos de estado del TPM pueden ser la misma.

Mientras que la clave para los archivos de estado del TPM debe permanecer con los archivos que cifra, la clave de migración debe permanecer con los blobs de estado del TPM. Si, por ejemplo, el estado del TPM se migra entre hosts en un centro de datos, la clave de migración del TPM debe estar disponible en todos los destinos, por lo que en efecto puede ser una clave compartida en todas las máquinas del centro de datos. En contraste, la clave utilizada para cifrar los archivos de estado del TPM puede ser diferente para cada TPM y solo necesita estar disponible en el host donde reside el estado del TPM.

La clave de migración habilita el cifrado de los blobs de estado del TPM. El archivo clave debe contener una clave AES de tamaño compatible; se admiten claves de 128 bits (16 bytes) y 256 bits (32 bytes).

La clave puede estar en formato binario, en cuyo caso el tamaño del archivo debe ser de 16 o 32 bytes. Si la clave está en formato hexadecimal (por defecto), la clave puede constar de 32 o 64 dígitos hexadecimales que comiencen con un '0x' opcional.

El parámetro mode indica qué modo de encadenamiento de bloques se va a utilizar. Actualmente se admiten aes-cbc (aes-128-cbc) y aes-256-cbc. Los datos cifrados están protegidos contra manipulaciones mediante encrypt-then-mac.

El parámetro remove intentará eliminar el archivo clave dado una vez que se haya leído la clave.

--migration-key pwdfile=<archivo de contraseña>|pwdfd=<descriptor de archivo> [,mode=aes-cbc|aes-256-cbc][,remove[=true|false]][,pdf=sha512|pbkdf2]
Esta variante del parámetro clave permite al usuario proporcionar una contraseña en un archivo. El archivo se lee y se deriva una clave de él utilizando un hash SHA512 o PBKDF2. Por defecto se utiliza PBKDF2.
--pid file=<archivo pid>|fd=<descriptor de archivo>
Esta opción permite al usuario establecer el nombre del archivo donde se escribirá el ID de proceso (pid) del TPM. También es posible pasar un descriptor de archivo a un archivo que se haya abierto para escritura.
-r|--runas <propietario>
Cambia al usuario dado. Esta opción solo se puede usar cuando swtpm se inicia como root.
-R|--chroot <ruta<gt>
Chroot al directorio dado al inicio. Esta opción solo se puede usar cuando swtpm se inicia como root.
--seccomp action=none|log|kill (desde v0.2)
Esta opción permite al usuario seleccionar la acción a tomar por el perfil seccomp cuando se ejecuta una llamada al sistema que no está permitida. El valor predeterminado es kill. Para deshabilitar el perfil seccomp, elija none. La acción log registra las llamadas al sistema infractoras. La acción log solo está disponible si libseccomp admite el registro.

Esta opción solo está disponible en Linux y solo si swtpm fue compilado con soporte libseccomp.

--flags [not-need-init][,startup-clear|startup-state|startup-deactivated|startup-none][,disable-auto-shutdown]
El flag not-need-init permite que el TPM acepte comandos del TPM justo después de iniciarse sin requerir que se le envíe un INIT a través del canal de comandos (ver la opción '-i' de swtpm_ioctl).

Las opciones startup hacen que se envíe automáticamente un comando TPM_Startup o TPM2_Startup. La opción startup-deactivated solo es válida para TPM 1.2. Estas opciones implican not-need-init, excepto la opción startup-none, que no envía ningún comando.

Si se utiliza --vtpm-proxy, se elige automáticamente startup-clear, pero esto se puede cambiar con esta opción.

El flag disable-auto-shutdown evita que swtpm envíe automáticamente un TPM2_Shutdown() antes del reinicio de un TPM 2 o antes de que se termine el proceso swtpm. Cuando este flag no se proporciona, swtpm enviará este comando para evitar aumentar el contador de bloqueo de ataques de diccionario (DA) y, en última instancia, un bloqueo de DA por parte del TPM 2 debido a la omisión del envío de un TPM2_Shutdown() requerido antes del reinicio del TPM 2 o la terminación del proceso swtpm.

--migration [incoming][,release-lock-outgoing]
Esta opción permite controlar el bloqueo del almacenamiento NVRAM con el propósito de soportar la migración entre hosts que tienen una configuración de almacenamiento compartido para el directorio de estado de swtpm y si el almacenamiento de backend soporta el bloqueo. El backend de almacenamiento de directorio, por ejemplo, soporta el bloqueo y por lo tanto requiere el uso de esta opción en caso de almacenamiento compartido. Al proporcionar el parámetro de opción incoming, swtpm difiere el bloqueo de la NVRAM hasta que se reciben los blobs de estado o hasta que se procesa el primer comando TPM si no se recibieron blobs de estado. El parámetro de opción release-lock-outgoing hace que swtpm libere cualquier bloqueo NVRAM una vez que el blob 'savestate' del TPM es recibido de swtpm. Para evitar liberar el bloqueo demasiado pronto, los blobs de estado 'permanent' y 'volatile' deben ser recibidos antes del blob 'savestate'.
--profile name=<profile-name>|profile=<json-profile>|file=<filename>|fd=<fd>[,remove-disabled=check|fips-host] (since v0.10)
Esta opción permite establecer un perfil para un TPM 2. Se puede seleccionar un perfil incorporado por su nombre usando el parámetro de opción name=. Con el parámetro de opción profile= se puede pasar un perfil con formato JSON directamente. Con el parámetro de opción file= se leerá un perfil con formato JSON desde un archivo. El parámetro de opción fd= permite leerlo desde un descriptor de archivo.

Los perfiles deben hacer referencia al nombre de un perfil incorporado. Tenga en cuenta que solo el perfil 'custom', o perfiles cuyo nombre empiece por 'custom:', pueden ser modificados y proporcionan una lista de algoritmos, comandos o atributos que controlan qué algoritmos criptográficos habilita un TPM 2. Si no se proporciona alguna de estas listas, se utiliza la lista correspondiente del perfil 'custom' incorporado.

La siguiente opción de línea de comandos selecciona el perfil 'custom' bajo el nuevo nombre 'custom:test' con el atributo 'fips-host' establecido:

[...] --profile '{"Name":"custom:test", "Attributes":"fips-host"}'

El perfil solo se puede establecer la primera vez que se inicia una instancia de TPM 2 y mientras no exista ningún archivo de estado. El perfil no se puede cambiar a partir de entonces y, si se vuelve a pasar usando esta opción, se producirá un error.

El parámetro de opción remove-disabled indica a swtpm que elimine aquellos algoritmos del perfil que están deshabilitados cuando FIPS está habilitado en un host (parámetro fips-host; referencia RHEL 9.4+ modo FIPS) y el acceso de OpenSSL a los algoritmos criptográficos está restringido. El parámetro check se puede usar para verificar que un algoritmo está de hecho deshabilitado antes de eliminarlo. Esta opción solo es compatible si se elige el perfil custom. En este caso, (actualmente) hará lo siguiente:

  • elimina camellia, tdes y rsaes (cifrado RSA con relleno PKCS#1 v1.5)
  • deshabilita el soporte de firma (RSA y EC) sobre SHA1
  • deshabilita el cifrado RSA sin relleno
  • establece el tamaño mínimo de las claves RSA a 2048 bits
  • establece el tamaño mínimo de las claves EC a 224 bits

Todos los demás algoritmos permanecen habilitados, incluidos aquellos que FIPS normalmente no permite, como ecdaa y ecschnorr y otros. La lista de algoritmos deshabilitados se ampliará en el futuro cuando el modo FIPS en el host deshabilite más algoritmos. Dado que en este caso swtpm puede agregar atributos al perfil que requieren un cierto StateFormatLevel, se recomienda omitir el campo StateFormatLevel del perfil.

El único perfil que un usuario puede modificar es el perfil 'custom'. Aquí un usuario puede optar por deshabilitar algoritmos, comandos y atributos que se permiten deshabilitar. Para evitar errores en aplicaciones TPM 2, se debe tener cuidado de que ninguna de ellas dependa de comandos o algoritmos deshabilitados.
--print-profiles (desde v0.10)
Muestra los perfiles compatibles con libtpms. Usar con la opción --tpm2.
--print-info (desde v0.10)
Muestra información sobre el TPM de la llamada TPMLIB_GetInfo de libtpms y sale. Use la opción --tpm2 para obtener información sobre TPM 2. Si también se proporciona la opción --tpmstate, la salida mostrará información sobre el perfil también. Tenga en cuenta que con esta opción se puede crear un estado de TPM si no existía antes.

Los siguientes valores pueden ser proporcionados. Todos los valores pueden ser combinados (o añadidos) para obtener información sobre todos ellos en una sola consulta.

  • 0x1: información sobre la especificación que siguió la implementación del TPM
  • 0x2: información sobre el fabricante, modelo y versión del TPM
  • 0x4: lista los tamaños de clave RSA y Camellia compatibles
  • 0x8: describe los algoritmos compatibles y habilitados
  • 0x10: describe los comandos compatibles y habilitados
  • 0x20: describe el perfil activo
  • 0x40: lista todos los perfiles integrados
  • 0x80: describe los atributos compatibles
-h|--help
Muestra la información de uso.

NOTAS

Si se utiliza un TPM 2, normalmente se requiere que el usuario envíe un comando TPM2_Shutdown() a un TPM 2 para evitar posiblemente aumentar el TPM_PT_LOCKOUT_COUNTER, lo que podría llevar a un bloqueo de ataque de diccionario (DA) después del próximo inicio (TPM2_Startup()) del TPM 2. Si el TPM_PT_LOCKOUT_COUNTER se incrementa depende de los comandos enviados previamente al TPM 2, así como del estado interno del TPM 2. Un ejemplo que activará el contador para aumentar es la omisión de una contraseña al intentar acceder a un objeto protegido por contraseña o a una ubicación NVRAM que tenga el atributo DA establecido, seguido de la terminación de swtpm sin enviar TPM2_Shutdown(). Para evitar un bloqueo DA, swtpm hará un mejor esfuerzo y enviará TPM2_Shutdown(SU_STATE) o TPM2_Shutdown(SU_CLEAR) si se considera necesario.
