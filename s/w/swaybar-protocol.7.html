NOMBRE

swaybar-protocol - protocolo de línea de estado JSON para swaybar

RESUMEN

swaybar define el siguiente protocolo JSON para especificar qué información se muestra en la línea de estado en el lado derecho de swaybar. El protocolo comprende una cabecera, que es un objeto JSON, seguido de una nueva línea (0x0A), seguido de un array JSON infinito que representa la información a mostrar. Toda la comunicación se realiza escribiendo la línea de estado en la salida estándar y leyendo eventos de la entrada estándar.

CABECERA

La cabecera es un objeto JSON con soporte para las siguientes propiedades (solo version es requerida):

PROPIEDAD TIPO DE DATO POR DEFECTO DESCRIPCIÓN
version entero - La versión del protocolo a usar. Actualmente, debe ser 1
click_events booleano false Si se deben recibir información de eventos de clic en la entrada estándar
cont_signal entero SIGCONT La señal que swaybar debe enviar para continuar el procesamiento
stop_signal entero SIGSTOP La señal que swaybar debe enviar para detener el procesamiento

CABECERA MÍNIMA

{
	"version": 1
}

CABECERA COMPLETA

{
	"version": 1,
	"click_events": true,
	"cont_signal": 18,
	"stop_signal": 19
}

CUERPO

El cuerpo es un array infinito, donde cada elemento del array es una representación de la línea de estado en el momento en que se escribió el elemento. Cada elemento del array es a su vez un array de objetos JSON, donde cada objeto representa un bloque en la línea de estado. Cada bloque puede tener las siguientes propiedades (solo full_text es requerida):

PROPIEDAD TIPO DE DATO DESCRIPCIÓN
full_text cadena El texto que se mostrará. Si falta, el bloque se omitirá.
short_text cadena Si se proporciona y el texto necesita ser acortado por falta de espacio, se mostrará esto en lugar de full_text
color cadena El color del texto a usar en notación #RRGGBBAA o #RRGGBB
background cadena El color de fondo para el bloque en notación #RRGGBBAA o #RRGGBB
border cadena El color del borde para el bloque en notación #RRGGBBAA o #RRGGBB
border_top entero La altura en píxeles del borde superior. El valor por defecto es 1
border_bottom entero La altura en píxeles del borde inferior. El valor por defecto es 1
border_left entero El ancho en píxeles del borde izquierdo. El valor por defecto es 1
border_right entero El ancho en píxeles del borde derecho. El valor por defecto es 1
min_width entero o cadena El ancho mínimo a usar para el bloque. Esto puede ser en píxeles o se puede dar una cadena para permitir que se calcule basándose en el ancho de la cadena.
align cadena Si el texto no abarca el ancho completo del bloque, esto especifica cómo se alineará el texto dentro del bloque. Puede ser left (izquierda, por defecto), right (derecha), o center (centro).
name cadena Un nombre para el bloque. Esto solo se usa para identificar el bloque para los eventos de clic. Si se establece, cada bloque debe tener un par name e instance único.
instance cadena La instancia del name para el bloque. Esto solo se usa para identificar el bloque para los eventos de clic. Si se establece, cada bloque debe tener un par name e instance único.
urgent booleano Si el bloque debe mostrarse como urgente. Actualmente swaybar utiliza los colores establecidos en la configuración de sway para los botones de espacios de trabajo urgentes. Consulte sway-bar(5) para más información sobre la configuración de color de la barra.
separator booleano Si el separador de la barra debe dibujarse después del bloque. Consulte sway-bar(5) para más información sobre cómo establecer el texto del separador.
separator_block_width entero La cantidad de píxeles a dejar en blanco después del bloque. El texto del separador se mostrará centrado en este espacio. El valor por defecto es 9 píxeles.
markup cadena El tipo de marcado a usar al analizar el texto para el bloque. Puede ser pango o none (por defecto).

Se pueden dar otras propiedades y swaybar ignorará cualquier propiedad que no conozca. Se recomienda prefijar cualquier propiedad personalizada con un guion bajo para que sea más fácil distinguirla de las propiedades del protocolo.

EJEMPLO DE CUERPO

[
	[
		{
			"full_text": "25%",
			"min_width": "100%",
			"urgent": false
		},
		{
			"full_text": "Jue 30 May 2019 02:15:15"
		}
	],
	[
		{
			"full_text": "20%",
			"min_width": "100%",
			"urgent": false
		},
		{
			"full_text": "Jue 30 May 2019 02:20:52"
		}
	],
	[
		{
			"full_text": "15%",
			"min_width": "100%",
			"urgent": true
		},
		{
			"full_text": "Jue 30 May 2019 02:25:41"
		}
	],
	...

EJEMPLO DE BLOQUE COMPLETO

EVENTOS DE CLIC

Si se solicitó en la cabecera, swaybar enviará

{ "name": "nombre_del_bloque", "instance": "instancia_del_bloque", "x": 0, "y": 0, "button": 0, "event": 0, "relative_x": 0, "relative_y": 0, "width": 0, "height": 0 } ```

Este objeto JSON representa un evento de clic en un bloque. Puede ser leído desde la entrada estándar cuando el usuario hace clic en un bloque. El objeto tiene las siguientes propiedades:

PROPIEDAD TIPO DE DATO DESCRIPCIÓN
name string El nombre del bloque, si está establecido
instance string La instancia del bloque, si está establecida
x integer La coordenada x donde ocurrió el clic
y integer La coordenada y donde ocurrió el clic
button integer El número de botón x11 para el clic. Si el botón no tiene una correspondencia de botón x11, será 0.
event integer El código de evento que corresponde al botón para el clic
relative_x integer La coordenada x del clic relativa a la esquina superior izquierda del bloque
relative_y integer La coordenada y del clic relativa a la esquina superior izquierda del bloque
width integer El ancho del bloque en píxeles
height integer La altura del bloque en píxeles

Diferencias con el protocolo de i3bar:

  • button puede ser 0 para botones que no tienen correspondencias de botón x11
  • Se ha introducido event para permitir la representación de botones que no son x11
  • La propiedad modifiers no es añadida actualmente por swaybar

EJEMPLO

{
	"name": "reloj",
	"instance": "edt",
	"x": 1900,
	"y": 10,
	"button": 1,
	"event": 274,
	"relative_x": 100,
	"relative_y": 8,
	"width": 120,
	"height": 18
}
