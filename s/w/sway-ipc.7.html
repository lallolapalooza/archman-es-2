NAME

sway-ipc - IPC protocol for sway

DESCRIPTION

This details the interprocess communication (IPC) protocol for sway(1). This IPC protocol can be used to control or obtain information from a sway process.

The IPC protocol uses a UNIX socket as the method of communication. The path to the socket is stored in the environment variable SWAYSOCK and, for backwards compatibility with i3, I3SOCK. You can also retrieve the socket path by calling sway --get-socketpath.

MESSAGE AND REPLY FORMAT

The format for messages and replies is:

<magic-string> <payload-length> <payload-type> <payload>
Where
<magic-string> is i3-ipc, for compatibility with i3
<payload-length> is a 32-bit integer in native byte order
<payload-type> is a 32-bit integer in native byte order

For example, sending the exit command would look like the following hexdump:

00000000 | 69 33 2d 69 70 63 04 00 00 00 00 00 00 00 65 78 |i3-ipc........ex|
00000010 | 69 74                                           |it              |

The payload for replies will be a valid serialized JSON data structure.

MESSAGES AND REPLIES

The following message types and their corresponding reply types are currently supported. For all replies, any properties not listed are subject to removal.

TYPE NUMBER MESSAGE NAME PURPOSE
0 RUN_COMMAND Runs the payload as sway commands
1 GET_WORKSPACES Get the list of current workspaces
2 SUBSCRIBE Subscribe the IPC connection to the events listed in the payload
3 GET_OUTPUTS Get the list of current outputs
4 GET_TREE Get the node layout tree
5 GET_MARKS Get the names of all the marks currently set
6 GET_BAR_CONFIG Get the specified bar config or a list of bar config names
7 GET_VERSION Get the version of sway that owns the IPC socket
8 GET_BINDING_MODES Get the list of binding mode names
9 GET_CONFIG Returns the config that was last loaded
10 SEND_TICK Sends a tick event with the specified payload
11 SYNC Replies failure object for i3 compatibility
12 GET_BINDING_STATE Request the current binding state, e.g. the currently active binding mode name.
100 GET_INPUTS Get the list of input devices
101 GET_SEATS Get the list of seats

0. RUN_COMMAND

MESSAGE
Parses and runs the payload as sway commands

REPLY
An array of objects corresponding to each command that was parsed. Each object has the property success, which is a boolean indicating whether the command was successful. The object may also contain the properties error and parse_error. The error property is a human readable error message while parse_error is a boolean indicating whether the reason the command failed was because the command was unknown or not able to be parsed.

Example Reply:

[
	{
		"success": true
	},
	{
		"success": false,
		"parse_error": true,
		"error": "Invalid/unknown command"
	}
]

1. GET_WORKSPACES

MESSAGE
Retrieves the list of workspaces.

REPLY
The reply is an array of objects corresponding to each workspace. Each object has the following properties:

PROPERTY DATA TYPE DESCRIPTION
num integer The workspace number or -1 for workspaces that do not start with a number
name string The name of the workspace
visible boolean Whether the workspace is currently visible on any output
focused boolean Whether the workspace is currently focused by the default seat (seat0)
urgent boolean Whether a window on the workspace has the urgent flag set
rect object The bounds of the workspace. It consists of x, y, width, and height
output string The name of the output that the workspace is on

Example Reply:

[
	{
		"num": 1,
		"name": "1",
		"visible": true,
		"focused": true,
		"rect": {
			"x": 0,
			"y": 23,
			"width": 1920,
			"height": 1057
		},
		"output": "eDP-1"
	},
]

2. SUBSCRIBE

MESSAGE
Subscribe this IPC connection to the event types specified in the message payload. The payload should be a valid JSON array of events. See the EVENTS section for the list of supported events.

REPLY
A single object that contains the property success, which is a boolean value indicating whether the subscription was successful or not.

Example Reply:

{
	"success": true
}

3. GET_OUTPUTS

MESSAGE
Retrieve the list of outputs

REPLY
An array of objects corresponding to each output. Each object has the following properties:

PROPERTY DATA TYPE DESCRIPTION
name string The name of the output. On DRM, this is the connector
make string The make of the output
model string El modelo de la salida
serial string El número de serie de la salida como una cadena hexadecimal
active boolean Si esta salida está activa/habilitada
dpms boolean (Obsoleto, usar power en su lugar) Si esta salida está encendida/apagada (vía DPMS)
power boolean Si esta salida está encendida/apagada
primary boolean Para compatibilidad con i3, esto será falso. No tiene sentido en Wayland
scale float La escala actualmente en uso en la salida o -1 para salidas deshabilitadas
subpixel_hinting string El subpíxel de hinting actualmente en uso en la salida. Puede ser rgb, bgr, vrgb, vbgr o none
transform string La transformación actualmente en uso para la salida. Puede ser normal, 90, 180, 270, flipped-90, flipped-180 o flipped-270
current_workspace string El espacio de trabajo actualmente visible en la salida o null para salidas deshabilitadas
modes array Un array de objetos de modo compatibles. Cada objeto contiene width, height y refresh
current_mode object Un objeto que representa el modo actual que contiene width, height y refresh
rect object Los límites para la salida que consisten en x, y, width y height

4. GET_TREE

MENSAJE
Recupera una representación JSON del árbol

RESPUESTA
Un array de objetos que representan el árbol actual. Cada objeto representa un nodo y tendrá las siguientes propiedades:

PROPIEDAD TIPO DE DATO DESCRIPCIÓN
id integer El ID interno único para este nodo
name string El nombre del nodo, como el nombre de la salida o el título de la ventana. Para el scratchpad, será __i3_scratch para compatibilidad con i3.
type string El tipo de nodo. Puede ser root, output, workspace, con o floating_con
border string El estilo del borde para el nodo. Puede ser normal, none, pixel o csd
current_border_width integer Número de píxeles utilizados para el ancho del borde
layout string El diseño del nodo. Puede ser splith, splitv, stacked, tabbed o output
orientation string La orientación del nodo. Puede ser vertical, horizontal o none
percent float El porcentaje del padre del nodo que ocupa o null para la raíz y otros nodos especiales como el scratchpad
rect object La geometría absoluta del nodo. Las decoraciones de la ventana están excluidas de esto, pero los bordes están incluidos.
window_rect object La geometría del contenido dentro del nodo. Estas coordenadas son relativas al propio nodo. Las decoraciones de ventana y los bordes están fuera de window_rect
deco_rect object La geometría de las decoraciones del nodo relativas al nodo padre
geometry object La geometría natural del contenido si se ajustara a sí mismo
urgent boolean Si el nodo o alguno de sus descendientes tiene la sugerencia de urgencia activada. Nota: Esto puede no existir cuando se compila sin soporte xwayland
sticky boolean Si el nodo es pegajoso (se muestra en todos los espacios de trabajo)
marks array Lista de marcas asignadas al nodo
focused boolean Si el nodo está actualmente enfocado por el asiento predeterminado (seat0)
focus array Array de IDs de nodos hijos en el orden de enfoque actual
nodes array Los nodos hijos de tiling para el nodo
floating_nodes array Los nodos hijos flotantes para el nodo
representation string (Solo espacios de trabajo) Una representación de cadena del diseño del espacio de trabajo que puede usarse como ayuda para enviar pasos de reproducción para informes de errores
fullscreen_mode integer (Solo contenedores y ventanas) El modo de pantalla completa del nodo. 0 significa ninguno, 1 significa espacio de trabajo completo y 2 significa pantalla completa global
floating string Estado flotante del contenedor. Puede ser "auto_off" o "user_on"
scratchpad_state string Si la ventana está en el scratchpad. Puede ser "none" o "fresh"
app_id string (Solo ventanas) Para una ventana xdg-shell, el nombre de la aplicación, si está establecido. De lo contrario, null
pid integer (Solo ventanas) El PID de la aplicación que posee la ventana
foreign_toplevel_identifier string (Solo ventanas) El identificador de toplevel de ext-foreign-toplevel-list-v1 de este nodo.
visible boolean (Solo ventanas) Si el nodo es visible
shell string (Solo ventanas) El shell de la ventana, como xdg_shell o xwayland
inhibit_idle boolean (Solo ventanas) Si la ventana está inhibiendo el estado de inactividad
idle_inhibitors object (Solo ventanas) Un objeto que contiene el estado de los inhibidores de inactividad de application y user. application puede ser enabled o none. user puede ser focus, fullscreen, open, visible o none.
sandbox_engine string (Solo ventanas) El motor de sandbox asociado (o null)
sandbox_app_id string (Solo ventanas) El ID de la aplicación proporcionado por el motor de sandbox asociado (o null)
sandbox_instance_id string (Solo ventanas) El ID de instancia proporcionado por el motor de sandbox asociado (o null)
window integer (Solo ventanas xwayland) El ID de ventana X11 para la ventana xwayland
ndow window_properties objeto (Solo ventanas xwayland) Un objeto que contiene el título, la clase, la instancia, el rol de ventana, el tipo de ventana y transient_for de la ventana

5. GET_MARKS

MENSAJE
Recuperar las marcas actualmente establecidas

RESPUESTA
Una matriz de marcas actualmente establecidas. Dado que cada marca solo se puede establecer para un contenedor, este es un conjunto para que cada valor sea único y el orden no esté definido.

Respuesta de Ejemplo:

[
	"one",
	"test"
]

6. GET_BAR_CONFIG (SIN CARGA ÚTIL)

MENSAJE
Al enviar sin carga útil, esto recupera la lista de IDs de barras configuradas

RESPUESTA
Una matriz de IDs de barras, que son cadenas

Respuesta de Ejemplo:

[
	"bar-0",
	"bar-1"
]

6. GET_BAR_CONFIG (CON CARGA ÚTIL)

MENSAJE
Cuando se envía con un ID de barra como carga útil, esto recupera la configuración asociada con el ID de barra especificado en la carga útil. Esto es utilizado por swaybar, pero también podría ser utilizado para barras de terceros.

RESPUESTA
Un objeto que representa la configuración de la barra con el ID de barra enviado como carga útil. Las siguientes propiedades existen y más información sobre lo que significan sus valores se puede encontrar en sway-bar(5):

6. GET_BAR_CONFIG

MESSAGE
Retrieve the configuration of the configured bars

REPLY
An array of objects, each representing a bar configuration. See below for more information

PROPERTY DATA TYPE DESCRIPTION
id string El ID de la barra
mode string El modo para la barra. Puede ser dock, hide, o invisible
position string La posición de la barra. Actualmente puede ser bottom o top
status_command string El comando que debe ejecutarse para generar la línea de estado
font string La fuente a usar para el texto en la barra
workspace_buttons boolean Si se deben mostrar los botones de espacio de trabajo en la barra
workspace_min_width integer Ancho mínimo en px para los botones de espacio de trabajo en la barra
binding_mode_indicator boolean Si se debe mostrar el modo de enlace actual en la barra
verbose boolean Para compatibilidad con i3, este será el valor booleano false.
colors object Un objeto que contiene los colores #RRGGBBAA a usar para la barra. Ver más abajo para más información
gaps object Un objeto que representa los huecos para la barra que consta de top, right, bottom, y left.
bar_height integer La altura absoluta a usar para la barra o 0 para ajustar automáticamente según la fuente
status_padding integer El relleno vertical a usar para la línea de estado
status_edge_padding integer El relleno horizontal a usar para la línea de estado cuando está al final de una salida

El objeto colors contiene las siguientes propiedades, que son todas cadenas que contienen la representación #RRGGBBAA del color:

PROPERTY DESCRIPTION
background El color a usar para el fondo de la barra en salidas no enfocadas

separator El color a usar para el texto del separador en salidas no enfocadas
focused_background El color a usar para el fondo de la barra en la salida enfocada
focused_statusline El color a usar para el texto de la línea de estado en la salida enfocada
focused_separator El color a usar para el texto del separador en la salida enfocada
focused_workspace_text El color a usar para el texto del botón de espacio de trabajo enfocado
focused_workspace_bg El color a usar para el fondo del botón de espacio de trabajo enfocado
focused_workspace_border El color a usar para el borde del botón de espacio de trabajo enfocado
active_workspace_text El color a usar para el texto de los botones de espacio de trabajo para los espacios de trabajo visibles en salidas no enfocadas
active_workspace_bg El color a usar para el fondo de los botones de espacio de trabajo para los espacios de trabajo visibles en salidas no enfocadas
active_workspace_border El color a usar para el borde de los botones de espacio de trabajo para los espacios de trabajo visibles en salidas no enfocadas
inactive_workspace_text El color a usar para el texto de los botones de espacio de trabajo para los espacios de trabajo que no son visibles
inactive_workspace_bg El color a usar para el fondo de los botones de espacio de trabajo para los espacios de trabajo que no son visibles
inactive_workspace_border El color a usar para el borde de los botones de espacio de trabajo para los espacios de trabajo que no son visibles

sway-ipc(7) — sway local

NAME

sway-ipc — Wayland compositor IPC interface

DESCRIPTION

The sway IPC interface allows clients to query information about the sway compositor and issue commands.

Sway exposes its IPC socket at /run/user/<uid>/sway-ipc.<pid>.sock. This socket can be accessed by clients via the Wayland protocol.

For more information on the protocol, see the sway wiki.

MESSAGE AND REPLY FORMAT

Messages and replies are formatted as JSON objects.

  • Messages sent to the compositor must contain a type field.
  • Replies from the compositor will contain a type field.
  • Events sent by the compositor will contain a type field.

MESSAGES AND REPLIES

The following messages can be sent to the compositor:

get_workspaces
Retrieves a list of workspaces.
get_outputs
Retrieves a list of outputs.
get_tree
Retrieves the node tree.
get_marks
Retrieves a list of marks.
get_bar_config
Retrieves the configuration of the status bar.
send_tick
Sends a tick to the client. The client should reply with the same tick.
get_version
Retrieves the IPC version.
get_config
Retrieves the current sway configuration.
run_command
Executes a sway command.
get_inputs
Retrieves a list of input devices.
get_seat_config
Retrieves the configuration of the input seats.

The following fields are present in replies:

type
The type of the reply (e.g., workspace, output, node, marks, bar_config, tick, version, config, command, inputs, seat_config).
success
A boolean indicating whether the command was successful.
payload
The data associated with the reply.

EVENTS

The compositor can send the following events:

workspace
A workspace has changed.
output
An output has changed.
mode
A mode has changed.
window
A window has changed.
input
An input device has changed.
bar_config
A status bar configuration has changed.
shutdown
The compositor is shutting down.
tick
A tick has been received.
config
The compositor configuration has changed.
binding
A binding has changed.

The structure of these events depends on the event type. For example, an input event might contain information about the device that changed, including its name, vendor, product, type, and any specific input device configuration changes.

Example Event:

{
	"change": "xkb_layout",
	"input": {
		"identifier": "1:1:AT_Translated_Set_2_keyboard",
		"name": "AT Translated Set 2 keyboard",
		"vendor": 1,
		"product": 1,
		"type": "keyboard",
		"xkb_layout_names": [
			"English (US)",
			"English (Dvorak)"
		],
		"xkb_active_layout_index": 1,
		"xkb_active_layout_name": "English (Dvorak)",
		"libinput": {
			"send_events": "enabled"
		}
	}
}
