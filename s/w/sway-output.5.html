NOMBRE

sway-output - comandos de configuración de salida para sway

DESCRIPCIÓN

Puede combinar comandos de salida en uno solo, de la siguiente manera:

output HDMI-A-1 mode 1920x1080 pos 1920 0 bg ~/wallpaper.png stretch

Puede obtener una lista de nombres de salida con swaymsg -t get_outputs. También puede coincidir con cualquier salida utilizando el nombre de salida "*". Además, se puede usar "-" para coincidir con la salida enfocada por nombre y "--" para coincidir con la salida enfocada por su identificador.

Algunas salidas pueden tener nombres diferentes al desconectarse y volver a conectarse. Para identificar estas, el nombre puede ser sustituido por una cadena que consta de la marca, modelo y serie que puede obtener de swaymsg -t get_outputs. Cada valor debe estar separado por un espacio. Por ejemplo:

output "Some Company ABC123 0x00000000" pos 1920 0

COMANDOS

output <nombre> mode|resolution|res [--custom] <ancho>x<alto>[@<tasa>Hz]

Configura la salida especificada para usar el modo dado. Los modos son una combinación de ancho y alto (en píxeles) y una frecuencia de actualización a la que su pantalla puede configurarse. Para obtener una lista de los modos disponibles para cada salida, use swaymsg -t get_outputs.

Para establecer un modo personalizado no listado en la lista de modos disponibles, use --custom. Probablemente solo debería usar esto si sabe lo que está haciendo.

Ejemplos:

output HDMI-A-1 mode 1920x1080

output HDMI-A-1 mode 1920x1080@60Hz

output <nombre> modeline <reloj> <hdisplay> <hsync_start> <hsync_end> <htotal> <vdisplay> <vsync_start> <vsync_end> <vtotal> <hsync> <vsync>

Configura la salida especificada para usar la modeline dada. Puede ser generada usando los comandos cvt(1) y gtf(1). Ver xorg.conf(5). Solo compatible con el backend DRM.

Ejemplo:

output HDMI-A-1 modeline 173.00 1920 2048 2248 2576 1080 1083 1088 1120 -hsync +vsync

output <nombre> position|pos <X> <Y>

Coloca la salida especificada en la posición específica en el espacio de coordenadas global. El cursor solo puede moverse entre salidas inmediatamente adyacentes. Si el escalado está activo, debe tenerse en cuenta al posicionar. Por ejemplo, si el factor de escala para la salida izquierda es 2, la posición relativa para la salida derecha debe dividirse por 2. El punto de referencia es la esquina superior izquierda, por lo que si desea que los fondos estén alineados, también debe considerarse esto.

Ejemplo:

output HDMI1 scale 2

output HDMI1 pos 0 1020 res 3200x1800

output eDP1 pos 1600 0 res 1920x1080

Tenga en cuenta que la posición x izquierda de eDP1 es 1600 = 3200/2 y la posición y inferior es 1020 + (1800 / 2) = 1920 = 0 + 1920

output <nombre> scale <factor>

Escala la salida especificada por el factor de escala especificado. Se recomienda un entero, pero también se admiten valores fraccionarios. Puede que le sea más útil establecer un factor de escala entero y ajustar el tamaño de fuente de sus aplicaciones a su gusto. HiDPI no es compatible con clientes Xwayland (las ventanas se verán borrosas). Un factor de escala fraccionario puede ajustarse ligeramente para cumplir con los requisitos del protocolo.

output <nombre> scale_filter linear|nearest|smart

Indica cómo escalar los búferes de aplicaciones que se renderizan a una escala inferior a la escala configurada de la salida, como aplicaciones de baja DPI en pantallas de alta DPI. Lineal es más suave y borroso, más cercano (también conocido como vecino más cercano) es más nítido y pixelado. Establecer "smart" aplicará el escalado más cercano cuando la salida tenga un factor de escala entero, de lo contrario lineal. El valor predeterminado es "smart".

output <nombre> subpixel rgb|bgr|vrgb|vbgr|none

Establece manualmente la subpíxel para la salida especificada. Este valor generalmente se detecta automáticamente, pero algunas pantallas pueden informar incorrectamente su geometría de subpíxeles. Usar la geometría de subpíxeles correcta permite un texto más nítido. Los valores incorrectos resultarán en un texto más borroso. Al cambiar esto a través de swaymsg, algunas aplicaciones pueden necesitar ser reiniciadas para usar el nuevo valor.

output <nombre> background|bg <archivo> <modo> [<color_de_respaldo>]

Establece el fondo de pantalla para la salida dada al archivo especificado, utilizando el modo de escalado dado (uno de "stretch", "fill", "fit", "center", "tile"). Si el archivo especificado no se puede acceder o si la imagen no llena toda la salida, se puede proporcionar un color de respaldo para cubrir el resto de la salida. color_de_respaldo debe especificarse como #RRGGBB. El alfa no es compatible.

output <nombre> background|bg <color> solid_color

Establece el fondo de la salida dada al color especificado. color debe especificarse como #RRGGBB. El alfa no es compatible.

output <nombre> transform <transformación> [clockwise|anticlockwise]

Establece la transformación de fondo al valor dado. Puede ser uno de "90", "180", "270" para rotación; o "flipped", "flipped-90", "flipped-180", "flipped-270" para aplicar una rotación y volteo, o "normal" para no aplicar ninguna transformación. La rotación se realiza en sentido horario. Si se elige una única salida y se especifica una dirección de rotación (clockwise o anticlockwise), la transformación se suma o resta de la transformación actual (esto no se puede usar directamente en el archivo de configuración).

output <nombre> disable|enable

Habilita o deshabilita la salida especificada (todas las salidas están habilitadas por defecto).

A diferencia del comando power, la salida perderá su espacio de trabajo y ventanas actuales.

output <nombre> toggle

Alterna la salida especificada.

output <nombre> power on|off|toggle

Enciende o apaga la salida especificada.

A diferencia de los comandos enable y disable, la salida conserva sus espacios de trabajo y ventanas actuales.

output <nombre> dpms on|off|toggle

Obsoleto. Alias de power.

output <nombre> max_render_time off|<msec>

Controla cuándo sway compone la salida, como un número positivo de milisegundos antes de la próxima actualización de pantalla. Un número menor produce fotogramas compuestos más frescos y menor latencia de entrada percibida, pero si se establece demasiado bajo, sway puede no terminar de componer a tiempo para la actualización de pantalla, lo que lleva a fotogramas retrasados.

Cuando se establece en off, sway compone inmediatamente después de la actualización de pantalla, maximizando el tiempo disponible para la composición.

Para ajustar cuándo se instruye a las aplicaciones para que se rendericen, consulte max_render_time en sway(5).

Para configurar esto para una latencia óptima:

1.
Inicie alguna aplicación de pantalla completa que se renderice continuamente, como glxgears.
2.
Comience con max_render_time 1. Incremente en 1 si ve caídas de fotogramas.

Esta configuración solo tiene efecto en los backends Wayland y DRM, ya que se requiere compatibilidad con marcas de tiempo de presentación y frecuencia de actualización de salida predicha.

output <nombre> adaptive_sync on|off|toggle

Habilita o deshabilita la sincronización adaptativa (comúnmente conocida como Tasa de Refresco Variable, o por los nombres específicos del proveedor FreeSync/G-Sync).

La sincronización adaptativa permite a los clientes enviar fotogramas un poco tarde sin tener que esperar un período de actualización completo para mostrarlo en pantalla. Habilitar la sincronización adaptativa puede mejorar la latencia, pero puede causar parpadeos en algunos hardware.

output <nombre> render_bit_depth 6|8|10

Controla la profundidad de bits máxima del canal de color en la que se renderizan los fotogramas; el valor predeterminado es actualmente 8 bits por canal.

Establecer valores más altos no tendrá efecto si el hardware y el software carecen de soporte para tales profundidades de bits. Incrementar con éxito la profundidad de bits de renderizado no necesariamente aumentará la profundidad de bits de los fotogramas enviados a una pantalla. Una mayor profundidad de bits de renderizado puede proporcionar una renderización más suave de los gradientes, y capturas de pantalla que pueden almacenar con mayor precisión los colores de programas que muestran colores de alta profundidad de bits.

SALIDA

Los comandos de esta sección se aplican a las salidas, también conocidas como monitores o pantallas.

COMANDOS

salida <nombre> scale <factor>

Establece la escala para una salida. El valor predeterminado es 1.0. Esto afecta al tamaño de las ventanas y a la resolución efectiva de la salida.

Por ejemplo, salida eDP-1 scale 2 duplicará el tamaño de todo en la salida eDP-1.

Este comando afecta a la forma en que las aplicaciones de captura de pantalla/grabación de pantalla que no se han actualizado para funcionar con diferentes profundidades de bits. Este comando es experimental y puede ser eliminado o modificado en el futuro.

salida <nombre> perfil_color srgb|[icc <archivo>]

Establece el perfil de color para una salida. El valor predeterminado es srgb. <archivo> debe ser una ruta a un perfil ICC de pantalla.

No todos los renderizadores soportan esta característica; actualmente solo funciona con el renderizador Vulkan. Incluso donde se soporta, la aplicación del perfil de color puede ser imprecisa.

Este comando es experimental y puede ser eliminado o modificado en el futuro. Puede no tener efecto o producir resultados inesperados cuando se usa junto con futuras características de soporte HDR.

salida <nombre> permitir_desgarro sí|no

Permite o prohíbe el desgarro de pantalla como resultado de los volteos de página inmediatos, y un modo de presentación inmediato desde un cliente. El valor predeterminado es que no se permite el desgarro de pantalla.

Con volteos de página inmediatos, los fotogramas del cliente se presentan tan pronto como sea posible en lugar de sincronizarse con el intervalo de borrado vertical (VSync) del monitor.

Se recomienda establecer max_render_time en off. En ese caso, un volteo de página ocurre tan pronto como un cliente se actualiza. De lo contrario, el desgarro solo ocurrirá si la renderización tarda más de los milisegundos configurados antes de la siguiente actualización de la pantalla.

Para ajustar si se permite el desgarro para aplicaciones específicas, consulta allow_tearing en sway(5). Ten en cuenta que el desgarro solo se habilitará cuando esté permitido tanto para la salida como para la aplicación.

Esta configuración solo tiene efecto cuando una ventana está en pantalla completa en la salida.
