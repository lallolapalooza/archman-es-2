makecontext(3) Manual de funciones de biblioteca makecontext(3)

NOMBRE

makecontext, swapcontext - manipula el contexto del usuario

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOSIS

#include <ucontext.h>
void makecontext(ucontext_t *ucp, typeof(void (int arg0, ...)) *func,
                 int argc, ...);
int swapcontext(ucontext_t *restrict oucp,
                 const ucontext_t *restrict ucp);

DESCRIPCIÓN

En un entorno similar a System V, existe el tipo ucontext_t (definido en <ucontext.h> y descrito en getcontext(3)) y las cuatro funciones getcontext(3), setcontext(3), makecontext() y swapcontext() que permiten el cambio de contexto a nivel de usuario entre múltiples hilos de control dentro de un proceso.

La función makecontext() modifica el contexto apuntado por ucp (obtenido de una llamada a getcontext(3)). Antes de invocar makecontext(), el llamador debe asignar una nueva pila para este contexto y asignar su dirección a ucp->uc_stack, y definir un contexto sucesor y asignar su dirección a ucp->uc_link.

Cuando este contexto se active posteriormente (usando setcontext(3) o swapcontext()), se llamará a la función func, pasándole la serie de argumentos enteros (int) que siguen a argc; el llamador debe especificar el número de estos argumentos en argc. Cuando esta función retorne, se activará el contexto sucesor. Si el puntero al contexto sucesor es NULL, el hilo termina.

La función swapcontext() guarda el contexto actual en la estructura apuntada por oucp, y luego activa el contexto apuntado por ucp.

VALOR DE RETORNO

Cuando tiene éxito, swapcontext() no retorna. (Pero puede retornar más tarde, en caso de que se active oucp, en cuyo caso parece que swapcontext() retorna 0). En caso de error, swapcontext() retorna -1 y establece errno para indicar el error.

ERRORES

ENOMEM
Espacio de pila insuficiente restante.

ATRIBUTOS

Para una explicación de los términos utilizados en esta sección, consulte attributes(7).

Interfaz Atributo Valor
makecontext () Seguridad de hilos MT-Safe race:ucp
swapcontext () Seguridad de hilos MT-Safe race:oucp race:ucp

ESTÁNDARES

Ninguno.

HISTORIA

glibc 2.1. SUSv2, POSIX.1-2001. Eliminado en POSIX.1-2008, citando problemas de portabilidad y recomendando que las aplicaciones se reescriban para usar hilos POSIX en su lugar.

NOTAS

La interpretación de ucp->uc_stack es igual que en sigaltstack(2), es decir, esta estructura contiene el inicio y la longitud de un área de memoria que se usará como pila, independientemente de la dirección de crecimiento de la pila. Por lo tanto, no es necesario que el programa de usuario se preocupe por esta dirección.

En arquitecturas donde los tipos int y puntero tienen el mismo tamaño (por ejemplo, x86-32, donde ambos tipos son de 32 bits), es posible que pueda salirse con la suya pasando punteros como argumentos a makecontext() después de argc. Sin embargo, hacer esto no está garantizado que sea portable, no está definido según los estándares y no funcionará en arquitecturas donde los punteros son más grandes que los enteros. No obstante, a partir de glibc 2.8, glibc realiza algunos cambios en makecontext() para permitir esto en algunas arquitecturas de 64 bits (por ejemplo, x86-64).

EJEMPLOS

El siguiente programa de ejemplo demuestra el uso de getcontext(3), makecontext() y swapcontext(). Ejecutar el programa produce la siguiente salida:


$ ./a.out
main: swapcontext(&uctx_main, &uctx_func2)
func2: started
func2: swapcontext(&uctx_func2, &uctx_func1)
func1: started
func1: swapcontext(&uctx_func1, &uctx_func2)
func2: returning
func1: returning
main: exiting

Fuente del programa

#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <ucontext.h>
static ucontext_t uctx_main, uctx_func1, uctx_func2;
static void
func1(void)
{
    printf("%s: started\n", __func__);
    printf("%s: swapcontext(&uctx_func1, &uctx_func2)\n", __func__);
    if (swapcontext(&uctx_func1, &uctx_func2) == -1)
        err(EXIT_FAILURE, "swapcontext");
    printf("%s: returning\n", __func__);
}
static void
func2(void)
{
    printf("%s: started\n", __func__);
    printf("%s: swapcontext(&uctx_func2, &uctx_func1)\n", __func__);
    if (swapcontext(&uctx_func2, &uctx_func1) == -1)
        err(EXIT_FAILURE, "swapcontext");
    printf("%s: returning\n", __func__);
}
int
main(int argc, char *argv[])
{
    char func1_stack[16384];
    char func2_stack[16384];
    if (getcontext(&uctx_func1) == -1)
        err(EXIT_FAILURE, "getcontext");
    uctx_func1.uc_stack.ss_sp = func1_stack;
    uctx_func1.uc_stack.ss_size = sizeof(func1_stack);
    uctx_func1.uc_link = &uctx_main;
    makecontext(&uctx_func1, func1, 0);
    if (getcontext(&uctx_func2) == -1)
        err(EXIT_FAILURE, "getcontext");
    uctx_func2.uc_stack.ss_sp = func2_stack;
    uctx_func2.uc_stack.ss_size = sizeof(func2_stack);
    /* Contexto sucesor es f1(), a menos que argc > 1 */
    uctx_func2.uc_link = (argc > 1) ? NULL : &uctx_func1;
    makecontext(&uctx_func2, func2, 0);
    printf("%s: swapcontext(&uctx_main, &uctx_func2)\n", __func__);
    if (swapcontext(&uctx_main, &uctx_func2) == -1)
        err(EXIT_FAILURE, "swapcontext");
    printf("%s: exiting\n", __func__);
    exit(EXIT_SUCCESS);
}

swapcontext(3) - Arch manual pages

NAME

swapcontext - manipulate user thread context

LIBRARY

Realtime extensions (librt), POSIX threads (libpthread)

SYNOPSIS

#include <ucontext.h>

int swapcontext(ucontext_t *restrict oldctx, const ucontext_t *restrict newctx);

DESCRIPTION

The swapcontext() function saves the current execution context of the calling thread in the object pointed to by oldctx and then makes the context specified by newctx active. A context is defined by the set of signals in the signal mask, the stack, the register values, and the instruction pointer.

The contexts are stored in ucontext_t structures. This structure is defined in <ucontext.h> and can hold information about the current execution context of a thread.

The context pointed to by newctx must have been previously initialized, for example, using makecontext() or getcontext().

The function getcontext() initializes the ucontext_t structure pointed to by its argument to the caller's current context. The call returns immediately, and the current context is saved. If getcontext() fails, it returns -1 and sets errno.

The function setcontext() makes the context pointed to by its argument the current context. If setcontext() succeeds, it does not return. The context pointed to by newctx must have been previously initialized, for example, using makecontext() or getcontext(). If setcontext() is called with a ucontext_t pointer that was not initialized or has been destroyed, the behavior is undefined.

The function makecontext() modifies the context pointed to by ucp so that it will call the function func with the arguments specified by .... The stack pointer is set to point to the stack region described by ucp->uc_stack. The context is set to be the context that will be returned to when func returns. This is specified by ucp->uc_link. If ucp->uc_link is NULL, then the thread terminates when func returns. The stack must be at least STACK_SIZE bytes large, where STACK_SIZE is a constant that must be greater than or equal to MINSIGSTKSZ.

RETURN VALUE

On success, swapcontext() returns 0. On failure, it returns -1 and sets errno.

ERRORS

ENOMEM
Not enough memory to allocate a new context.

ATTRIBUTES

For an explanation of the terms used in this section, see attributes(7).

Multithreaded Calls No
Thread Safety No

STANDARDS

POSIX.1-2008.

HISTORY

These functions first appeared in POSIX.1-2001.

NOTES

The functions getcontext(), setcontext(), and swapcontext() are used to manipulate user-level thread contexts. These contexts can be used to implement coroutines or user-level threads. They are not related to POSIX threads (pthreads), which are kernel-level threads.

The ucontext_t structure contains the following members:

  • uc_flags: Flags indicating which fields are valid.
  • uc_link: Pointer to the context to resume when the current context returns.
  • uc_stack: The stack used by the context.
  • uc_mcontext: Machine-specific context information.

The swapcontext() function is typically used in conjunction with getcontext() and setcontext() to switch between different execution contexts. For example, you might use getcontext() to save the current context, then use makecontext() to create a new context, and then use swapcontext() to switch to the new context. When the new context returns, swapcontext() will restore the old context.

EXAMPLES

The following example demonstrates how to use getcontext(), makecontext(), and swapcontext() to create and switch between two contexts:

#include <stdio.h>
#include <stdlib.h>
#include <ucontext.h>

#define STACK_SIZE 1024

ucontext_t ctx1, ctx2;
char stack1[STACK_SIZE];
char stack2[STACK_SIZE];

void func1() {
    printf("Entering func1\n");
    swapcontext(&ctx2, &ctx1);
    printf("Exiting func1\n");
}

void func2() {
    printf("Entering func2\n");
    swapcontext(&ctx1, &ctx2);
    printf("Exiting func2\n");
}

int main() {
    getcontext(&ctx1);
    ctx1.uc_stack.ss_sp = stack1;
    ctx1.uc_stack.ss_size = STACK_SIZE;
    ctx1.uc_link = NULL; // No context to return to
    makecontext(&ctx1, func1, 0);

    getcontext(&ctx2);
    ctx2.uc_stack.ss_sp = stack2;
    ctx2.uc_stack.ss_size = STACK_SIZE;
    ctx2.uc_link = &ctx1; // Return to ctx1 when func2 finishes
    makecontext(&ctx2, func2, 0);

    swapcontext(&ctx1, &ctx2); // Start with ctx2

    return 0;
}
