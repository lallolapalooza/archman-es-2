NOMBRE

swtpm-create-tpmca - Herramienta para crear una CA local para swtpm_localca

SINOPSIS

swtpm-create-tpmca [OPCIONES]

DESCRIPCIÓN

swtpm-create-tpmca es una herramienta para crear una CA basada en TPM 1.2 o TPM 2 que puede ser utilizada por swtpm_localca para firmar certificados EK y de plataforma. La CA utiliza una clave GnuTLS para firmar certificados. Si se utiliza un TPM 1.2, GnuTLS se comunicará con el TPM 1.2 utilizando el demonio tcsd (TrouSerS). Si se utiliza un TPM 2, también se requerirán el controlador pkcs11 de Intel y sus herramientas (tpm2_ptool).

Dado que el certificado de la CA del TPM debe ser firmado por una CA, también se creará una autoridad de certificación raíz que firmará este certificado. La clave privada y el certificado de la CA raíz estarán ubicados en el mismo directorio que la clave de firma y tendrán los nombres swtpm-localca-rootca-privkey.pem y swtpm-localca-rootca-cert.pem respectivamente. La variable de entorno SWTPM_ROOTCA_PASSWORD puede configurarse para la contraseña de la clave privada de la CA raíz.

Nota: Esta herramienta es experimental. Consulte la sección sobre problemas conocidos a continuación.

Se admiten las siguientes opciones:

--dir dir
El directorio donde se escribirán las claves. Se reutilizará una CA raíz existente con los archivos swtpm-localca-rootca-privkey.pem y swtpm-localca-rootca-cert.pem en este directorio. Si alguno de estos archivos no existe, se creará una nueva CA raíz.
--overwrite
Sobrescribe el contenido del directorio de salida.
--register
Registra la clave con TCSD. Para que la clave esté disponible para firmar, el mismo usuario que creó la CA del TPM debe ejecutar posteriormente la herramienta swtpm_localca. Si esta opción no se pasa, la clave privada se escribe en un archivo y otros usuarios también pueden usarla.
--key-password s
La nueva clave de firma tendrá esta contraseña.

Nota: Debido a un error en certtool de GnuTLS, puede ser necesario utilizar la misma contraseña para la clave de firma que para la SRK.

--srk-password s
La contraseña de la SRK del TPM.

Nota: Dado que GnuTLS tpmtool no admite la contraseña 'bien conocida' de 20 bytes cero, la contraseña de la SRK debe establecerse.

--outfile filename
El nombre de un archivo donde escribir la configuración swtpm-localca.conf.
--owner owner
El nombre o el número UID del propietario que poseerá el directorio y el archivo outfile. Esta opción solo tiene efecto si esta swtpm-create-tpmca es ejecutada por el usuario root.
--group group
El nombre o el número GID del grupo que poseerá el directorio y el archivo outfile. Esta opción solo tiene efecto si esta swtpm-create-tpmca es ejecutada por el usuario root.
--tss-tcsd-hostname
El nombre de host donde se está ejecutando tcsd. El nombre de host predeterminado es 'localhost'.
-tss-tcsd-port
El puerto TCP en el que tcsd está escuchando mensajes. El puerto predeterminado es 30003.
--tpm2
El TPM a utilizar para firmar los certificados es un TPM 2 y la pila TSS de Intel debe estar en ejecución (tpm2-abrmd) junto con su módulo PKCS11. El módulo PKCS11 del TPM 2 debe haber sido inicializado usando tpm2_ptool.

Las variables de entorno SWTPM_PKCS11_PIN y SWTPM_PKCS11_SO_PIN deben configurarse para contener los PIN. Si SWTPM_PKCS11_PIN no está configurado, se utilizará el PIN predeterminado 'swtpm-tpmca'. SWTPM_PKCS11_SO_PIN es necesario para crear el token y debe configurarse explícitamente como una variable de entorno.

--pid primary-object-id
El ID del objeto primario que tpm2_ptool devuelve tras 'init'.
-help, -h, -?
Muestra la pantalla de ayuda y sale.

EJEMPLO

El siguiente ejemplo crea una CA de TPM intermedia y escribe las claves en /var/lib/swtpm-localca y la configuración de swtpm_localca en /etc/swtpm-localca.conf. Posteriormente, puede ser utilizada para firmar certificados de nuevos swtpm TPMs creados.

Si el TPM del host es un TPM 1.2, necesitamos iniciar tcsd primero y luego podemos crear la clave del TPM y el certificado de la CA del TPM:

#> sudo systemctl start tcsd
#> sudo /usr/share/swtpm/swtpm-create-tpmca \
               --dir /var/lib/swtpm-localca \
               --overwrite \
               --outfile /etc/swtpm-localca.conf \
               --srk-password password \
               --key-password password \
               --group tss
statedir = /var/lib/swtpm-localca
signingkey = tpmkey:file=/var/lib/swtpm-localca/swtpm-localca-tpmca-privkey.pem
issuercert = /var/lib/swtpm-localca/swtpm-localca-tpmca-cert.pem
certserial = /var/lib/swtpm-localca/certserial
TSS_TCSD_HOSTNAME = localhost
TSS_TCSD_PORT = 30003
signingkey_password = password
parentkey_password = password

Alternativamente, si el TPM del host es un TPM 2 y la pila TPM 2 de Intel está instalada, necesitamos iniciar tpm2-abrmd primero y luego podemos crear la clave del TPM y el certificado de la CA del TPM:

#> sudo systemctl start tpm2-abrmd     # puede no ser necesario con las herramientas recientes de TPM 2 de Intel
#> sudo tpm2_ptool init
action: Created
id: 1                   # este es el parámetro --pid abajo
#> sudo SWTPM_PKCS11_PIN="mypin 123" SWTPM_PKCS11_SO_PIN=123 /usr/share/swtpm/swtpm-create-tpmca \
               --dir /var/lib/swtpm-localca \
               --overwrite \
               --outfile /etc/swtpm-localca.conf \
               --group tss \
               --tpm2 \
               --pid 1
statedir = /var/lib/swtpm-localca
signingkey = pkcs11:model=SW%20%20%20TPM\;manufacturer=IBM\;serial=0000000000000000\;token=swtpm-tpmca-1\;id=%31\;object=swtpm-tpmca-key\;type=private
issuercert = /var/lib/swtpm-localca/swtpm-localca-tpmca-cert.pem
certserial = /var/lib/swtpm-localca/certserial
SWTPM_PKCS11_PIN = mypin 123

Nota: Esto también funciona para usuarios no root adaptando los parámetros --dir y --outfile aquí y abajo cambiando el parámetro --dir y agregando un parámetro --config.

Para probar alguna de las CA de TPM anteriores, ejecute el siguiente comando:

#> swtpm_localca \
       --type ek --ek x=11,y=13 \
       --dir /tmp --vmid test --tpm2 \
       --tpm-spec-family 2.0 --tpm-spec-revision 146 --tpm-spec-level 00 \
       --tpm-model swtpm --tpm-version 20170101 --tpm-manufacturer IBM

El --tpm2 en este comando indica que el TPM para el cual se está creando el certificado es un TPM 2.

PROBLEMAS CONOCIDOS

La interacción de GnuTLS certtool con el demonio TCSD del TPM puede causar tantos fallos de autenticación del TPM (clave) que el TPM se niega a aceptar más comandos autenticados hasta que el propietario del TPM envíe el comando TPM_ORD_ResetLockValue. La razón de esto es que certtool primero intenta usar 20 bytes cero para la contraseña de la SRK y solo después solicita y utiliza la contraseña de la SRK requerida. GnuTLS tpmtool no admite 20 bytes cero para la contraseña de la SRK, por lo que fuerza el uso de una contraseña 'real'.

El efecto de los fallos de autenticación puede ser que la CA del TPM no pueda firmar certificados, ya que el TPM no acepta comandos autenticados.
