NOMBRE

swtpm_setup - Herramienta swtpm para simular la fabricación de un TPM 1.2 o 2.0

SINOPSIS

swtpm_setup [OPCIONES]

DESCRIPCIÓN

swtpm_setup es una herramienta que prepara el estado inicial para un TPM basado en libtpms.

Se admiten las siguientes opciones:

--runas <idusuario>
Utilice este id de usuario para ejecutar swtpm_setup como. Solo 'root' puede usar esta opción.
--config <archivo>
Ruta al archivo de configuración que contiene la herramienta a utilizar para crear certificados; véase también swtpm_setup.conf

Si no se proporciona este parámetro, se utilizará el archivo de configuración predeterminado. El orden de búsqueda del archivo de configuración predeterminado es el siguiente. Si la variable de entorno XDG_CONFIG_HOME está establecida, se usará ${XDG_CONFIG_HOME}/swtpm_setup.conf si está disponible, de lo contrario, si la variable de entorno HOME está establecida, se usará ${HOME}/.config/swtpm_setup.conf si está disponible. Si ninguno de los anteriores está disponible, se usará /etc/swtpm_setup.conf.

--tpm-state <dir> o --tpmstate <dir>
Ruta donde se escribirá el estado del TPM; este es un argumento obligatorio. Prefije con dir:// para usar el backend de directorio, o file:// para usar un archivo lineal.
--tpm <ruta al ejecutable>
Ruta al ejecutable del TPM; este es un argumento opcional y, por defecto, se usará el ejecutable swtpm que se encuentre en el PATH.
--tpm2
Realizar la configuración en un TPM 2; por defecto se configura un TPM 1.2.
--createek
Crear una clave de habilitación (EK).
--allow-signing
Crear una EK que pueda firmar. Esta opción requiere --tpm2.

Esta opción creará una EK no estándar. Al recrear la EK, las herramientas de TPM 2 tienen que usar la Plantilla de EK que se escribe en un índice NV correspondiente a la EK creada (por ejemplo, índice NV 0x01c00004 para EK RS 2048). De lo contrario, la EK creada por la herramienta no corresponderá a la clave real que se está utilizando ni al módulo que se muestra en el certificado de la EK.

Tenga en cuenta que la especificación TCG "EK Credential Profile For TPM Family 2.0; Level 0" sugiere en su sección sobre "EK Usage" que "la Endorsement Key puede crearse como una clave de descifrado o firma". Sin embargo, algunas plataformas no aceptarán una EK como clave de firma, o como clave de firma y cifrado, y por lo tanto, esta opción debe usarse con mucho cuidado.

--decryption
Crear una EK que se pueda usar para el cifrado de claves. Esta es la opción predeterminada a menos que se pase --allow-signing. Esta opción requiere --tpm2.
--ecc
Crear claves de criptografía de curva elíptica (ECC); por defecto se generan claves RSA.
--take-ownership
Tomar posesión; esta opción implica --createek. Esta opción solo está disponible para TPM 1.2.
--ownerpass <contraseña>
Proporcionar una contraseña de propietario personalizada; por defecto es 'ooo'. Esta opción solo está disponible para TPM 1.2.
--owner-well-known
Utilizar una contraseña de ceros (20 bytes de ceros) como contraseña de propietario. Esta opción solo está disponible para TPM 1.2.
--srkpass <contraseña>
Proporcionar una contraseña SRK personalizada; por defecto es 'sss'. Esta opción solo está disponible para TPM 1.2.
--srk-well-known
Utilizar una contraseña de ceros (20 bytes de ceros) como contraseña SRK. Esta opción solo está disponible para TPM 1.2.
--create-ek-cert
Crear un certificado de EK; esto implica --createek.
--create-platform-cert
Crear un certificado de plataforma; esto implica --create-ek-cert.
--lock-nvram
Bloquear el acceso NVRAM a todas las ubicaciones NVRAM que se han escrito.
--display
Al final, mostrar la mayor cantidad de información posible sobre la configuración del TPM.
--logfile <archivo>
El archivo de registro al que registrar. Por defecto, el registro va a stdout y stderr.
--keyfile <archivo>
El archivo de clave contiene una clave hexadecimal ASCII que consta de 32 dígitos hexadecimales con un prefijo opcional '0x'. Esta es la clave que utilizará el emulador de TPM para cifrar el estado del TPM.
--keyfile-fd <descriptor de archivo>
Similar a --keyfile pero la clave se leerá del descriptor de archivo.
--pwdfile <archivo de contraseña>
El archivo de contraseña contiene una frase de contraseña de la cual el emulador de TPM derivará la clave de cifrado y usará la clave para cifrar el estado del TPM.
--pwdfile-fd <descriptor de archivo>
Similar a --pwdfile pero la frase de contraseña se leerá del descriptor de archivo.
--ciper <cifrador>
El cifrador puede ser aes-cbc o aes-128-cbc para cifrado AES de 128 bits, o aes-256-cbc para cifrado AES de 256 bits. El mismo cifrador debe usarse más adelante en la línea de comandos de swtpm.
--overwrite
Sobrescribir el estado existente del TPM. Todo el estado anterior se borrará. Si no se proporciona esta opción y se encuentra un archivo de estado existente, se devolverá un código de error.
--not-overwrite
No sobrescribir el estado existente del TPM. Si se encuentra un estado de TPM existente, el programa finalizará sin error.
--vmid <ID de VM>
ID de VM opcional que se puede usar para realizar un seguimiento de los certificados emitidos para VMs (o contenedores). Este parámetro se pasará a la herramienta utilizada para crear los certificados y puede ser requerido por esa herramienta.
--pcr-banks <bancos PCR>
Lista opcional separada por comas de bancos PCR a activar. Proporcionar '-' permite al usuario omitir la selección y activa todos los bancos PCR. Si no se proporciona esta opción, se consultará el archivo de configuración swtpm_setup.conf para la entrada active_pcr_banks. Si no se encuentra dicha entrada, se activará el conjunto predeterminado de bancos PCR. El conjunto predeterminado de bancos PCR se puede determinar usando la opción --help.
--swtpm_ioctl <ejecutable>
Pase la ruta al ejecutable swtpm_ioctl. Por defecto, se utiliza el swtpm_ioctl en el PATH.
--tcsd-system-ps-file <archivo>
Esta opción está obsoleta y no tiene efecto (desde v0.4).
--rsa-keysize <tamaño de clave> (desde v0.4)
Esta opción permite pasar el tamaño de una clave EK RSA de TPM 2, como 2048 o 3072. Los tamaños de clave compatibles para un TPM 2 se pueden consultar usando la opción --print-capabilities. El tamaño predeterminado es de 2048 bits tanto para TPM 1.2 como para TPM 2. Si se pasa 'max', se utiliza el tamaño de clave más grande posible.
--reconfigure (desde v0.7)
Esta opción permite la reconfiguración de los bancos PCR activos de un TPM 2 utilizando la opción --pcr-banks.
--profile <perfil-json> (desde v0.10)
Configurar un TPM 2 con el perfil dado. Los perfiles de ejemplo se ven así: 
{"Name": "null"}
{"Name": "default-v1"}
{
 "Name": "custom",
 "Algorithms":"rsa,rsa-min-size=1024,tdes-min-size=128,hmac,aes,\
               aes-min-size=128,mgf1,keyed

El perfil JSON debe contener el campo 'name' con el nombre de un perfil compatible con libtpms. Solo el perfil 'custom', o los perfiles cuyo nombre comience con 'custom:', son modificables y pueden contener campos Algorithms, Commands o Attributes con selecciones del usuario. Los campos desconocidos en el perfil JSON serán ignorados. Para más información, consulta la página man de swtpm.

--profile-name <nombre del archivo de perfil| nombre del perfil incorporado (desde v0.10)
Configura un TPM 2 con un perfil cargado desde una de las siguientes ubicaciones en el orden mostrado, a menos que se califique con un prefijo:
  • directorio de perfiles locales especificado en swtpm_setup.conf como 'local_profiles_dir'; para forzar la carga del perfil desde este directorio, antepón 'local:' al nombre
  • directorio de perfiles de distribución, que típicamente es /usr/share/swtpm/profiles; para forzar la carga del perfil desde este directorio, antepón 'distro:' al nombre
  • instancia un perfil incorporado de libtpms; para forzar un perfil incorporado, antepón 'builtin:' al nombre

Todos los perfiles cargados desde los directorios mencionados anteriormente requieren que el archivo esté disponible bajo el nombre dado con '.json' añadido.

Utiliza las opciones --print-profiles y --tpm2 para mostrar todos los perfiles disponibles.

--profile-file <archivo> (desde v0.10)
Configura un TPM 2 con un perfil desde un archivo.
--profile-file-fd <fd> (desde v0.10)
Configura un TPM 2 con un perfil leído desde un descriptor de archivo.
--profile-remove-disabled check|fips-host (desde v0.10)
Cuando se pasa esta opción, swtpm eliminará del perfil dado los algoritmos que OpenSSL no pueda usar cuando el modo FIPS esté habilitado en el host. Si se da el parámetro check, se prueban los algoritmos antes de eliminarlos, mientras que el parámetro fips-host fuerza la eliminación de todos los algoritmos potencialmente deshabilitados sin probarlos.

Esta opción solo funciona si el perfil 'custom' se referencia pasando --profile '{"Name":"custom:test"}' por ejemplo.

Esta opción pasa el parámetro de opción remove-disable como parte de la opción --profile a swtpm. Para más información, consulta la página man de swtpm.

--print-profiles (desde v0.10)
Imprime todos los perfiles encontrados en los directorios de perfiles locales y de distribución y muestra los incorporados. Todos los perfiles almacenados en archivos deben tener la extensión .json. Los nombres en el JSON mostrado indicarán el nombre bajo el cual estos perfiles se pueden cargar con la opción --profile-name, es decir, mostrarán el nombre del archivo sin la extensión .json. Por lo tanto, un perfil con el nombre de archivo myprofile.json mostrará el Name 'myprofile'. El autor del perfil puede querer establecer el Name en el JSON del perfil como 'custom:myprofile'.
--print-capabilities (desde v0.2)
Imprime las capacidades que se añadieron a swtpm_setup después de la versión 0.1. La salida puede contener lo siguiente: 
{
  "type": "swtpm_setup",
  "features": [
    "tpm-1.2",
    "tpm-2.0",
    "cmdarg-keyfile-fd",
    "cmdarg-pwdfile-fd",
    "tpm12-not-need-root",
    "cmdarg-write-ek-cert-files",
    "cmdarg-create-config-files",
    "cmdarg-reconfigure-pcr-banks",
    "tpm2-rsa-keysize-2048",
    "tpm2-rsa-keysize-3072",
    "cmdarg-profile",
    "cmdarg-profile-remove-disabled"
  ],
  "version": "0.7.0"
}

El campo version está disponible desde v0.7.

El significado de los verbos de características es el siguiente:

cmdarg-key-fd (desde v0.2)
La opción --keyfile-fd es compatible.
cmdarg-pwd-fd (desde v0.2)
La opción --pwdfile-fd es compatible.
cmdarg-write-ek-cert-files (desde v0.7)
La opción --write-ek-cert-files es compatible.
cmdarg-create-config-files (desde v0.7)
La opción --create-config-files es compatible.
cmdarg-reconfigure-pcr-banks (desde v0.7)
La opción --reconfigure es compatible y permite la reconfiguración de los bancos de PCR activos.
tpm2-rsa-keysize-2048, ... (desde v0.4)
Los tamaños de clave RSA mostrados son compatibles para la clave EK de un TPM 2. Si no se muestra ninguno de los verbos tpm2-rsa-keysize, entonces solo son compatibles las claves RSA de 2048 bits.
tpm12-not-need-root (desde v0.4)
Esta opción implica que cualquier usuario puede configurar un TPM 1.2. Anteriormente, solo root o el usuario 'tss', dependiendo de la configuración y disponibilidad de esta cuenta, podían hacerlo.
tpm-1.2 (desde v0.7)
La configuración de TPM 1.2 es compatible (libtpms está compilado con soporte para TPM 1.2).
tpm-2.0 (desde v0.7)
La configuración de TPM 2 es compatible (libtpms está compilado con soporte para TPM 2).
cmdarg-profile (desde v0.10)
Las opciones --profile, profile-file y --profile-file-fd son compatibles.
cmdarg-profile-remove-disabled (desde v0.10)
La opción --profile-remove-disabled es compatible.
--write-ek-cert-files <directorio> (desde v0.7)
Esta opción hace que los archivos de la clave de respaldo (EK) se escriban en el directorio proporcionado. Los archivos contienen las EK en formato DER que se escribieron en las ubicaciones de memoria NVRAM del TPM 1.2 o TPM 2. Los archivos EK tienen el patrón de nombre de archivo ek-<tipo de clave>.crt. Ejemplos de nombres de archivo son ek-rsa2048.crt, ek-rsa3072.crt y ek-secp384r1.crt.

Las claves que se escriben para un TPM 2 pueden cambiar con el tiempo a medida que cambia la fuerza predeterminada de las claves EK. Esto significa que se deben buscar todos los archivos con el patrón de nombre de archivo anterior al buscar las EK.

--create-config-files [[overwrite][,root][,skip-if-exist]] (desde v0.7)
Esta opción permite a un usuario crear archivos de configuración para swtpm_setup y swtpm-localca bajo los directorios $XDG_CONFIG_HOME o $HOME/.config.

Los archivos de configuración no se crearán si alguno de ellos ya existe y en ese caso el programa informará el primer archivo que encuentre y saldrá con un código de error.

El significado de las opciones es el siguiente:

overwrite
Sobrescribir cualquier archivo de configuración existente.
root
Crear los archivos de configuración incluso bajo la cuenta root. Estos archivos de configuración pueden entonces ocultar cualquier otro archivo de configuración existente, como /etc/swtpm-localca.conf, por ejemplo.
skip-if-exist
No hacer nada si alguno de los archivos de configuración que se crearían ya existe. El programa saldrá sin código de error.

Nota: Actualmente no se maneja el caso en que un usuario sea parte del grupo que tiene permitido acceder a las rutas de los archivos de configuración predeterminados. En muchos sistemas, este puede ser el caso cuando un usuario es parte del grupo 'tss'. En este caso, se recomienda que el usuario reemplace el swtpm-localca.conf creado con este comando con un enlace simbólico a /etc/swtpm-localca.conf.

--help, -h
Mostrar la pantalla de ayuda

EJEMPLO DE USO

Para simular la fabricación de un TPM, normalmente se ejecutaría el siguiente comando:

#> sudo swtpm_setup --tpmstate /tmp/mytpm1/ \
    --create-ek-cert --create-platform-cert --lock-nvram

Nota: desde v0.4, la configuración de TPM 1.2 ya no requiere privilegios de root.

Cualquier usuario también puede simular la fabricación de un TPM utilizando la utilidad swtpm_localca. El siguiente ejemplo asume que el usuario ha establecido la variable de entorno XDG_CONFIG_HOME de la siguiente manera (usando bash, por ejemplo):

export XDG_CONFIG_HOME=~/.config

Nota: La variable XDG_CONFIG_HOME forma parte de la Especificación de Directorios Base XDG.

Los siguientes archivos de configuración deben crearse:

~/.config/swtpm_setup.conf:

# Programa invocado para crear certificados
create_certs_tool= /usr/share/swtpm/swtpm-localca
create_certs_tool_config = ${XDG_CONFIG_HOME}/swtpm-localca.conf
create_certs_tool_options = ${XDG_CONFIG_HOME}/swtpm-localca.options

~/.config/swtpm-localca.conf:

statedir = ${XDG_CONFIG_HOME}/var/lib/swtpm-localca
signingkey = ${XDG_CONFIG_HOME}/var/lib/swtpm-localca/signkey.pem
issuercert = ${XDG_CONFIG_HOME}/var/lib/swtpm-localca/issuercert.pem
certserial = ${XDG_CONFIG_HOME}/var/lib/swtpm-localca/certserial

~/.config/swtpm-localca.options:

--platform-manufacturer Fedora
--platform-version 2.12
--platform-model QEMU

Nota: La herramienta swtpm-create-user-config-files puede ser utilizada para crear dichos archivos (con contenido diferente):

#> /usr/share/swtpm/swtpm-create-user-config-files
Writing /home/stefanb/.config/swtpm_setup.conf.
Writing /home/stefanb/.config/swtpm-localca.conf.

NAME

swtpm_setup – set up a virtual TPM 2 device

SYNOPSIS

swtpm_setup [‑h] [‑V] [‑‑child name] [‑‑create-ek-cert] [‑‑create-platform-cert] [‑‑data-dir dir] [‑‑lock-nvram] [‑‑log opts] [‑‑machine qemu] [‑‑migration-parameters params] [‑‑module mod] [‑‑nodaemon] [‑‑pidfile pidfile] [‑‑platform type] [‑‑qemu-socket path] [‑‑qemu-version version] [‑‑resume] [‑‑server opts] [‑‑tpm2] [‑‑tpmstate dir] [‑‑transfer-parameters params] [‑‑transfer-state dir] [‑‑version] [‑‑vdo opts] [‑‑vdo-cert-dir dir]

DESCRIPTION

The swtpm_setup utility sets up a virtual TPM device. It can be used to initialize a TPM 1.2 or TPM 2 device and to create a primary seed and a primary seed key for the TPM. It can also be used to create an EK (Endorsement Key) certificate and a platform certificate.

The state of the TPM device is stored in a directory specified by the ‑‑tpmstate option.

The TPM device can be of type TPM 1.2 or TPM 2. The default is TPM 1.2. To set up a TPM 2 device, use the ‑‑tpm2 option.

The ‑‑create-ek-cert option creates a self-signed EK certificate. The certificate is stored in the TPM state directory.

The ‑‑create-platform-cert option creates a self-signed platform certificate. The certificate is stored in the TPM state directory.

The ‑‑lock-nvram option locks the TPM's NVRAM area after initialization. This prevents any further changes to the NVRAM contents.

The ‑‑data-dir option specifies the directory where TPM-related data, such as certificates and keys, are stored. If not specified, it defaults to ${XDG_DATA_HOME}/swtpm.

The ‑‑log option configures logging. It takes a comma-separated list of options, e.g., file=logfile, level=level.

The ‑‑server option configures the TPM event log server. It takes a comma-separated list of options, e.g., port=port, host=host.

EXAMPLE USAGE

The following command initializes a TPM 1.2 device and stores its state in /home/stefanb/.config/swtpm-localca.options.

#> swtpm_setup --tpmstate /home/stefanb/.config/swtpm-localca.options

The following commands now create a TPM 2 with an EK and platform certificate. The state of the TPM 2 will be stored in the directory ${XDG_CONFIG_HOME}/mytpm1.

#> mkdir -p ${XDG_CONFIG_HOME}/mytpm1
#> swtpm_setup --tpm2 --tpmstate ${XDG_CONFIG_HOME}/mytpm1 \
    --create-ek-cert --create-platform-cert --lock-nvram
