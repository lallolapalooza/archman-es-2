NOMBRE

swtpm_ioctls - Descripción de los ioctl del TPM CUSE (swtpm_cuse) y comandos de control utilizados por el canal de control sobre la interfaz de socket.

SINOPSIS

#include <tpm_ioctl.h>

DESCRIPCIÓN

El TPM CUSE implementa una interfaz ioctl en el dispositivo de carácter del TPM CUSE. Los ioctl se utilizan para el control fuera de banda de varias operaciones del TPM, como su inicialización, reinicio y migración de estado. El canal de control sobre sockets TCP o UnixIO utiliza comandos de control para estas operaciones.

La siguiente es una enumeración de los ioctl y comandos de control compatibles, junto con los nombres de los tipos de estructura de datos. Todos los ioctl y comandos de control devuelven un código de error del TPM en su respuesta. Los ioctl se prefijan con PTM y los comandos de control se prefijan con CMD.

En el caso de la interfaz ioctl, el puntero a la estructura de datos de un comando se pasa como segundo parámetro a la función ioctl(). Los campos de la estructura de datos del comando deben completarse en formato de orden de bytes del host.

En el caso de los comandos de control, el código del comando debe codificarse como un entero de 4 bytes que precede a la estructura de datos del comando. El código y los datos del comando deben escribirse en formato big-endian.

PTM_GET_CAPABILITY / CMD_GET_CAPABILITY, ptm_cap
Este ioctl permite al llamante verificar qué ioctl son implementados por el TPM CUSE. La siguiente es una lista de indicadores de capacidad que pueden establecerse al regresar:
PTM_CAP_INIT (desde v0.1)
Se admite el ioctl PTM_INIT o el comando CMD_INIT.
PTM_CAP_SHUTDOWN (desde v0.1)
Se admite el ioctl PTM_SHUTDOWN o el comando CMD_SHUTDOWN.
PTM_CAP_GET_TPMESTABLISHED (desde v0.1)
Se admite el ioctl PTM_GET_TPMESTABLISHED o el comando CMD_GET_TPMESTABLISHED.
PTM_CAP_SET_LOCALITY (desde v0.1)
Se admite el ioctl PTM_SET_LOCALITY o el comando CMD_SET_LOCALITY.
PTM_CAP_HASHING (desde v0.1)
Se admiten los ioctl PTM_HASH_START, PTM_HASH_DATA y PTM_HASH_END o los comandos CMD_HASH_START, CMD_HASH_DATA, CMD_HASH_END.
PTM_CAP_CANCEL_TPM_CMD (desde v0.1)
Se admite el ioctl PTM_CANCEL_TPM_CMD o el comando CMD_CANCEL_TPM_CMD.
PTM_CAP_STORE_VOLATILE (desde v0.1)
Se admite el ioctl PTM_STORE_VOLATILE o el comando CMD_STORE_VOLATILE.
PTM_CAP_RESET_TPMESTABLISHED (desde v0.1)
Se admite el ioctl PTM_RESET_TPMESTABLISHED o el comando CMD_RESET_TPMESTABLISHED.
PTM_CAP_GET_STATEBLOB (desde v0.1)
Se admite el ioctl PTM_GET_STATEBLOB o el comando CMD_GET_STATEBLOB.
PTM_CAP_SET_STATEBLOB (desde v0.1)
Se admite el ioctl PTM_SET_STATEBLOB o el comando CMD_SET_STATEBLOB.
PTM_CAP_STOP (desde v0.1)
Se admite el ioctl PTM_STOP o el comando CMD_STOP.
PTM_CAP_GET_CONFIG (desde v0.1)
Se admite el ioctl PTM_GET_CONFIG o el comando CMD_GET_CONFIG.
PTM_CAP_SET_DATAFD (desde v0.1)
Se admite el comando CMD_SET_DATAFD. Este comando solo se aplica a UnixIO y no hay soporte para PTM_SET_DATAFD.
PTM_CAP_SET_BUFFERSIZE (desde v0.1)
Se admite el ioctl PTM_SET_BUFFERSIZE o el comando CMD_SET_BUFFERSIZE.
PTM_CAP_LOCK_STORAGE (desde v0.8)
Se admite el ioctl PTM_LOCK_STORAGE o el comando CMD_LOCK_STORAGE.
PTM_GET_CAPABILITY / CMD_GET_CAPABILITY, ptm_cap_n
La estructura de datos ptm_cap_n se puede usar para swtpm que no sea CUSE y tiene el siguiente aspecto: 
struct ptm_cap_n {
   union {
      struct {
          ptm_res tpm_result; /* siempre será TPM_SUCCESS (0) */
          uint32_t caps;
      } resp; /* respuesta */
   } u;
};
PTM_INIT / CMD_INIT, ptm_init
Este ioctl debe usarse para inicializar el TPM. Debe enviarse al TPM antes de enviar cualquier comando del TPM.

La estructura de datos ptm_init tiene el siguiente aspecto:

struct ptm_init {
   union {
       struct {
           uint32_t init_flags; /* ver definiciones a continuación */
       } req; /* solicitud */
       struct {
           ptm_res tpm_result;
       } resp; /* respuesta */
   } u;
};

El campo init_flags en la solicitud se puede usar para que el TPM elimine el estado volátil al iniciar (PTM_INIT_FLAG_DELETE_VOLATILE).

Se devuelve un código de resultado del TPM en el campo tpm_result.

PTM_SHUTDOWN / CMD_SHUTDOWN, ptm_res
Este ioctl permite a un usuario apagar el TPM.

Se devuelve un código de resultado del TPM en ptm_res.

PTM_GET_TPMESTABLISHED / CMD_GET_TPMESTABLISHED, ptm_est
Este ioctl se utiliza para verificar si el bit establecido del TPM está activado.

La estructura de datos tpm_est tiene el siguiente aspecto:

struct ptm_est {
   union {
       struct {
           ptm_res tpm_result;
           unsigned char bit; /* bit establecido del TPM */
       } resp; /* respuesta */
   } u;
};

Se devuelve un código de resultado del TPM en el campo tpm_result.

El estado del bit establecido del TPM se devuelve en el campo bit.

PTM_SET_LOCALITY / CMD_SET_LOCALITY, ptm_loc
Este ioctl se utiliza para establecer la localidad actual. Todos los comandos posteriores se ejecutarán en esta localidad hasta que se cambie la localidad.

La estructura de datos ptm_loc tiene el siguiente aspecto:

struct ptm_loc {
   union {
       struct {
           uint8_t loc; /* localidad a establecer */
       } req; /* solicitud */
       struct {
           ptm_res tpm_result;
       } resp; /* respuesta */
   } u;
};

El número de localidad debe establecerse en el campo loc de la solicitud. Las localidades válidas están en el rango de 0 a 4.

Se devuelve un código de resultado del TPM en el campo tpm_result.

PTM_HASH_START / CMD_HASH_START, ptm_res
Este ioctl se utiliza para iniciar la operación de hash que normalmente se inicia escribiendo en ciertos registros de la localidad 4 de la Interfaz TPM (TPM TIS). Las operaciones de escritura posteriores para transferir datos deben realizarse con el ioctl PTM_HASH_DATA.

Se devuelve un código de resultado del TPM en ptm_res.

PTM_HASH_DATA / CMD_HASH_DATA, ptm_hdata
Este comando se utiliza para transferir los datos de la operación de hash.

La estructura ptm_hdata tiene el siguiente aspecto:

struct ptm_hdata {
   union {
       struct {
           uint32_t length;
           uint8_t data[4096];
       } req; /* solicitud */
       struct {
           ptm_res tpm_result;
       } resp; /* respuesta */
   } u;
};

La longitud de los datos se indica en el campo length con los datos en el campo data. Se pueden transferir hasta 4096 bytes en una sola llamada.

Se devuelve un código de resultado del TPM en el campo tpm_result.
