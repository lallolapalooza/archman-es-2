NOMBRE

swipl-ld - Crear un ejecutable incrustado de SWI-Prolog

SINOPSIS

swipl-ld opciones archivos-c archivos-o archivos-pl

DESCRIPCIÓN

La utilidad swipl-ld es un front-end para el compilador C y el enlazador para crear un ejecutable independiente a partir de una serie de archivos de entrada C/C++ y Prolog. Extrae información del ejecutable de SWI-Prolog swipl, después de lo cual escanea los argumentos y los divide en varias categorías. Luego llama al compilador C para crear un ejecutable que contiene el código C del usuario y el kernel de SWI-Prolog. Después de esto, llamará al entorno de desarrollo para crear un estado guardado de Prolog a partir de los archivos de Prolog y finalmente creará el ejecutable de destino concatenando el estado al emulador. Ver también qsave_program/2 del manual de SWI-Prolog.

Opciones

-pl prolog
Especifica la versión de prolog a usar. El valor predeterminado es swipl. Esta bandera puede usarse para elegir entre diferentes versiones instaladas en su sistema, o para especificar una versión modificada. Una versión modificada debe entender las banderas -dump-runtime-variables -f archivo -F archivo -g meta -t toplevel.
-help
Muestra las opciones brevemente
-nostate
Simplemente vuelve a enlazar el kernel. El kernel recién enlazado solo puede funcionar en presencia del sistema de desarrollo. Los archivos fuente de prolog proporcionados son ignorados, al igual que las opciones -goal -toplevel -initfile. -class Esta es la forma preferida de adjuntar módulos externos a Prolog si la carga dinámica no es compatible con su sistema.
-c
Compila archivos fuente C o C++ en archivos objeto. Esto convierte swipl-ld en un reemplazo para el compilador C o C++ donde las opciones adecuadas, como la ubicación del directorio de inclusión, se pasan automáticamente al compilador.
-E
Invoca el preprocesador C. Se utiliza para hacer de swipl-ld un reemplazo para el compilador C o C++.
-shared
Enlaza archivos C, C++ o objeto en un objeto compartido (DLL) que puede ser cargado por el predicado load_foreign_library/1. Si se usa con -c establece las opciones adecuadas para compilar un archivo C o C++ listo para ser enlazado en un objeto compartido.
-embed-shared
Incrusta SWI-Prolog en una DLL/Objeto compartido en lugar de un ejecutable. Ver el manual de referencia para detalles.
-dll
Solo Windows Igual que -embed-shared Compatibilidad hacia atrás.
-F base
Por defecto, se pasa none al comando swipl para crear el estado guardado. Usando -F xpce puedes especificar la carga de xpce.rc, haciendo que XPCE esté disponible para el estado guardado.
-goal meta
La meta que se ejecuta inicialmente cuando se inicia el intérprete usando PL_toplevel(). Es decir, el valor predeterminado. Bandera -g para el nuevo ejecutable.
-toplevel meta
La meta que se ejecuta como meta principal del intérprete. Es decir, el valor predeterminado. Bandera -t para el nuevo ejecutable.
-initfile archivo
El archivo que carga el intérprete. Es decir, el valor predeterminado. Bandera -f para el nuevo ejecutable.
-class {runtime,kernel,development}
Establece la clase de guardado del estado guardado de Prolog que se crea. Si es runtime (predeterminado), el sistema resultante deja la interpretación de todos los argumentos a la aplicación. Si es kernel todos los predicados estarán bloqueados para el depurador. Finalmente, si es development el estado se guarda "tal cual" y el sistema resultante procesa las opciones al igual que el ejecutable básico de SWI-Prolog. Ver también qsave_program/2 en el manual de referencia de SWI-Prolog.
-v
Operación detallada. Muestra los comandos antes de ejecutarlos. Tenga en cuenta que algunos comandos se imprimen como comandos de shell, pero en realidad son ejecutados por el propio swipl-ld para compatibilidad con las plataformas Win32.
-f
Operación simulada. Junto con -v imprime los comandos que deben ejecutarse sin hacer nada.
-Eargumento-cpp ...
Si la primera opción es -E, todas las opciones subsiguientes se añaden y se pasan al programa seleccionado por la configuración de SWI-Prolog para ejecutar cpp.
-o archivo
Especifica el nombre del ejecutable final. El valor predeterminado es a.out.
-cc compilador-C
Especifica el compilador a usar para archivos *.c. El valor predeterminado es el compilador utilizado para compilar SWI-Prolog, tal como se lee de la característica c_cc.
-c++ compilador-C++
Especifica el compilador a usar para archivos de entrada C++. Si el compilador C es gcc, este será g++, de lo contrario se asume c++.
-ld enlazador
Especifica el enlazador a usar. El valor predeterminado es el compilador C. En plataformas Win32, el valor predeterminado es link.exe.
-lbiblioteca
Especifica una biblioteca C para enlazar la aplicación. Por defecto, -lswipl así como las bibliotecas requeridas por el kernel de SWI-Prolog se pasarán al compilador C.
-Ldirectorio-biblioteca
Especifica un directorio de bibliotecas adicional para el compilador C. Por defecto, se pasa el directorio de tiempo de ejecución para la arquitectura actual.
-g|-I*|-D*|-U*|-O*|-W*
Se pasan al compilador como flags C. Por defecto, el directorio de inclusión de SWI-Prolog se pasa como directorio de inclusión adicional. Las siguientes flags -D son añadidas por swipl-ld: -D__SWI_PROLOG__ y -D__SWI_EMBEDDED__.
-pl-options*
Especifica opciones adicionales para swipl. El primer carácter que sigue a -pl-options determina el separador de opciones. El resto del argumento se divide usando este separador y las partes se añaden a la lista de opciones para Prolog. Ver también -cc-options y -ld-options
-ld-options*
Opciones adicionales pasadas al enlazador. Por ejemplo: -ld-options,-Bstatic
-cc-options*
Opciones adicionales pasadas tanto al compilador C como al C++.
*.o
Se pasan como archivos de entrada al enlazador.
*.c
Se compila usando el compilador C, después de lo cual el archivo objeto se pasa al enlazador. El archivo objeto se elimina al finalizar.
*.cc|*.C|*.cxx|*.cpp
Se compila usando el compilador C++, después de lo cual el archivo objeto se pasa al enlazador. El archivo objeto se elimina al finalizar.
*.pl|*.qlf
Se pasan como archivos de entrada de Prolog

ERRORES

El análisis de las opciones y su distribución entre los diversos programas es probablemente incompleto. Siéntase libre de modificarlo y por favor envíe modificaciones de utilidad general a bugs@swi-prolog.org.

Hay que tener cuidado de que el estado creado con qsave_program/2 sea autocontenido (es decir, que no contenga referencias a las bibliotecas de Prolog). Además, dado que el estado se crea utilizando el entorno de desarrollo en lugar del emulador del usuario, el código Prolog no puede usar directivas que dependan del código C añadido por el usuario.
