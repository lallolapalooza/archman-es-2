NOMBRE

swtpm_ioctl - Utilidad para enviar comandos de control a swtpm

SINOPSIS

swtpm_ioctl [COMANDO] [<dispositivo>]

DESCRIPCIÓN

swtpm_ioctl implementa una herramienta cliente para controlar los emuladores de software de TPM swtpm_cuse y swtpm, como por ejemplo su inicialización y apagado. Una vez inicializado, se le pueden enviar comandos de TPM.

Nota: La variable de entorno SWTPM_IOCTL_BUFFERSIZE se puede establecer al tamaño del búfer para la transferencia de blob de estado. Si no se establece, se utiliza la interfaz ioctl() para transferir el estado. Esta variable de entorno se utiliza principalmente con fines de prueba.

Los siguientes comandos son compatibles:

--tpm-device <dispositivo>
Utiliza el dispositivo dado. Se debe proporcionar la ruta completa al dispositivo de caracteres, como por ejemplo /dev/vtpm-200.

Esta opción se puede usar en lugar de proporcionar el dispositivo como último parámetro.

--tcp <servidor>:<puerto>
Conéctate al servidor y puerto dados; si no se proporciona servidor, se usa 127.0.0.1; si no se proporciona puerto, se usa el puerto predeterminado 6545.
--unix <ruta>
Conéctate a la ruta UnixIO dada.
-c
Obtener las banderas de capacidad que indican qué comandos son compatibles.
-i
Enviar una señal de inicialización de hardware a swtpm_cuse/swtpm. El estado volátil escrito previamente por el TPM se leerá y el archivo se eliminará automáticamente.
-s
Iniciar un apagado ordenado.
--stop
Detener swtpm_cuse/swtpm. Esto no lo apaga. El comando -i se puede enviar de nuevo. Después de una detención, también es posible cargar blobs de estado de TPM en el TPM usando el comando --load.
-e
Obtener el bit tpmEstablished.
-r <localidad>
Restablecer el bit tpmEstablished utilizando la localidad dada. Solo las localidades 3 y 4 funcionan. Esta operación no cambiará permanentemente la localidad que se estableció previamente usando la opción -l.
-l <localidad>
Establecer la localidad para los comandos de TPM subsiguientes.
-v
Hacer que el TPM escriba el estado volátil en un archivo. Tras un TPM_Init (-i), se leerá el estado del TPM y este podrá reanudar la operación sin necesidad de inicialización adicional.
-C
Cancelar un comando de TPM en curso.
-h <datos>
Restablecer y extender el PCR 17 con el hash de los datos dados. Si los datos son el carácter único '-', entonces se leerán todos los datos de stdin.
--save <nombre del blob de estado del TPM> <nombre del archivo>
Guardar el blob de estado del TPM en el archivo dado. Los nombres válidos de blob de estado del TPM son 'permanent', 'volatile' y 'savestate'.

Tenga en cuenta que este comando se puede ejecutar en cualquier momento. Sin embargo, para recuperar el estado volátil más reciente, el comando -v se debería haber ejecutado inmediatamente antes de ejecutar este comando. El blob savestate solo se devolverá si se ejecutó un comando TPM_SaveState en el TPM (TPM 1.2).

--load <nombre del blob de estado del TPM> <nombre del archivo>
Cargar el blob de estado del TPM dado desde el archivo dado. Los nombres válidos de blob de estado del TPM son 'permanent', 'volatile' y 'savestate'.

Tenga en cuenta que este comando solo se puede ejecutar en un TPM que esté apagado. Para iniciar el TPM con el estado cargado, se debe emitir el comando -i.

-g
Obtener las banderas de configuración que, por ejemplo, indican qué claves (cifrado de archivo o clave de migración) están en uso por el TPM.
--info <banderas>
Obtener información sobre la implementación del TPM y su configuración en formato JSON. Los siguientes valores se pueden proporcionar. Todos los valores se pueden combinar (o sumar) para obtener información sobre todos ellos en una sola consulta.
  • 0x1: información sobre la especificación que siguió la implementación del TPM
  • 0x2: información sobre el fabricante, modelo y versión del TPM
  • 0x4: enumera los tamaños de clave RSA y Camellia compatibles
  • 0x8: describe los algoritmos compatibles y habilitados
  • 0x10: describe los comandos compatibles y habilitados
  • 0x20: describe el perfil activo
  • 0x40: enumera todos los perfiles integrados
  • 0x80: describe los atributos compatibles
--lock-storage <reintentos>
Bloquear el almacenamiento y reintentar un número de veces dado con un intervalo de 10 ms. Bloquear el almacenamiento puede ser necesario hacerlo después de que el estado del TPM haya sido migrado y el bloqueo del almacenamiento se haya liberado cuando se recibió el blob 'savestate' y ahora el almacenamiento debería bloquearse nuevamente.

EJEMPLO

Iniciar swtpm en el puerto 10000 para el puerto de control y emular un TPM 1.2:

#> swtpm socket --tpmstate dir=/tmp/myvtpm1 --log level=4 --ctrl type=tcp,port=10000 --server type=tcp,port=10001 --flags not-need-init

Obtener información sobre la implementación del TPM en JSON:

#> swtpm_ioctl --tcp :10000 --info 1
{"TPMSpecification":{"family":"1.2","level":2,"revision":116}}
#> swtpm_ioctl --tcp :10000 --info 2
{"TPMAttributes":{"manufacturer":"id:00001014","version":"id:00740001","model":"swtpm"}}

Apagar el swtpm

#> swtpm_ioctl --tcp :10000 -s
