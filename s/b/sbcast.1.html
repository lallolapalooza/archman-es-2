NOMBRE

sbcast - transmitir un archivo a los nodos asignados a un trabajo de Slurm.

SINOPSIS

sbcast [-CfFjpstvV] SOURCE DEST

DESCRIPCIÓN

sbcast se utiliza para transmitir un archivo a todos los nodos asignados al trabajo de Slurm actualmente activo. Este comando solo debe ser ejecutado desde dentro de un trabajo por lotes de Slurm o dentro del shell generado después de la asignación de recursos de un trabajo de Slurm. SOURCE es el nombre de un archivo en el nodo actual. DEST debe ser la ruta completa del archivo que se creará en cada nodo. Si no se proporciona una ruta completa, el archivo se creará en el directorio especificado en el parámetro BcastParameters en el archivo slurm.conf (si está disponible), de lo contrario, se creará en el directorio de trabajo actual desde el que se invoca el comando sbcast. DEST debe estar en un sistema de archivos local a ese nodo. Tenga en cuenta que los sistemas de archivos paralelos *pueden* ofrecer un mejor rendimiento que el que sbcast puede proporcionar, aunque el rendimiento variará según el tamaño del archivo, el grado de paralelismo y el tipo de red.

OPCIONES

-C, --compress[=library]
Comprimir el archivo que se está transmitiendo. El argumento opcional especifica la biblioteca de compresión de datos a utilizar. Los valores admitidos son "lz4" (por defecto) y "none". Algunas bibliotecas de compresión pueden no estar disponibles en algunos sistemas. La biblioteca de compresión predeterminada (y la habilitación de la compresión) se puede establecer en el archivo slurm.conf utilizando la opción BcastParameters.
--exclude=<NONE|path1,...,pathN>
Lista separada por comas de rutas de directorio absolutas que se excluirán al autodetectar y transmitir dependencias de objetos compartidos ejecutables. Si la palabra clave "*NONE*" está configurada, no se excluirán rutas de directorio. El valor predeterminado es el de BcastExclude de slurm.conf y esta opción lo anula. Ver también --send-libs.
-f, --force
Si el archivo de destino (y el directorio de bibliotecas de destino al usar --send-libs) ya existe, reemplázalo.
-j, --jobid=<jobID[+hetjobOffset].[stepID]>
Especifique el ID del trabajo a utilizar con un desplazamiento de trabajo heterogéneo y/o un ID de paso opcional. Si se ejecuta dentro de una asignación, esto no es necesario ya que el ID del trabajo se leerá del entorno.
-Z, --no-allocation
Transmitir archivos a una lista de nodos independientemente de los trabajos que puedan estar ejecutando. Esto solo puede ser realizado por SlurmUser/root.

--nodelist debe usarse con esta opción.

-w, --nodelist=<node_name_list>
Lista de hosts a los que transmitir archivos. Estos nodos deben ser un subconjunto del trabajo de destino, o se debe usar la opción --no-allocation.
-p, --preserve
Preserva los tiempos de modificación, tiempos de acceso y modos del archivo original.
--send-libs[=yes|no]
Si se establece en *yes* (o sin argumento), autodetecta y transmite las dependencias de objetos compartidos del ejecutable a los nodos de cálculo asignados. Los archivos se colocan en un directorio junto al ejecutable. Esto anula el comportamiento predeterminado configurado en SbcastParameters send_libs de slurm.conf. Ver también --exclude.
-s, --size=<size>
Especifique el tamaño del bloque utilizado para la transmisión del archivo. El tamaño puede tener un sufijo de *k* o *m* para kilobytes o megabytes respectivamente (predeterminado en bytes). Este tamaño está sujeto a redondeo y límites de rango para mantener un buen rendimiento. El valor predeterminado es el tamaño del archivo o 8 MB, lo que sea menor. Este valor puede necesitar ser configurado en sistemas con memoria muy limitada.
-t, --timeout=<seconds>
Especifique el tiempo de espera del mensaje en segundos. El valor predeterminado es *MessageTimeout* tal como lo informa "scontrol show config". Establecer un valor más alto puede ser necesario debido a un rendimiento de E/S relativamente lento en los discos de los nodos de cálculo.
-F, --treewidth=<number>
Especifique el ancho del árbol de mensajes utilizado para la transferencia de archivos. El valor máximo es actualmente 64. Un valor de "off" deshabilita el abanico.
-v, --verbose
Proporcionar registro detallado de eventos durante la ejecución del programa.
-V, --version
Imprimir información de la versión y salir.

RENDIMIENTO

Ejecutar sbcast envía una llamada a procedimiento remoto a slurmctld. Si suficientes llamadas de sbcast u otros comandos cliente de Slurm que envían llamadas a procedimientos remotos al demonio slurmctld llegan a la vez, puede resultar en una degradación del rendimiento del demonio slurmctld, posiblemente resultando en una denegación de servicio.

No ejecute sbcast u otros comandos cliente de Slurm que envíen llamadas a procedimientos remotos a slurmctld desde bucles en scripts de shell u otros programas. Asegúrese de que los programas limiten las llamadas a sbcast al mínimo necesario para la información que intenta recopilar.

VARIABLES DE ENTORNO

Algunas opciones de sbcast se pueden establecer a través de variables de entorno. Estas variables de entorno, junto con sus opciones correspondientes, se enumeran a continuación. (Nota: las opciones de línea de comandos siempre anularán estas configuraciones).

SBCAST_COMPRESS
-C, --compress
SBCAST_EXCLUDE
--exclude=<NONE|path1,...,pathN>
SBCAST_FANOUT
-F number, --fanout=number
SBCAST_FORCE
-f, --force
SBCAST_SEND_LIBS
--send-libs[=yes|no]
SBCAST_PRESERVE
-p, --preserve
SBCAST_SIZE
-s size, --size=size
SBCAST_TIMEOUT
-t segundos, --timeout=segundos
SLURM_CONF
La ubicación del archivo de configuración de Slurm.
SLURM_DEBUG_FLAGS
Especifica las banderas de depuración que debe usar sbcast. Consulte DebugFlags en la página man de slurm.conf(5) para obtener una lista completa de banderas. La variable de entorno tiene precedencia sobre la configuración en slurm.conf.

AUTORIZACIÓN

Cuando se utiliza SlurmDBD, a los usuarios que tienen definido un Nivel de Administración (Operador o Administrador) se les otorga la autoridad para invocar sbcast en trabajos de otros usuarios.

EJEMPLOS

Usando un script de lote, transmita el archivo local my.prog a /tmp/my.proc en los nodos locales y luego ejecútelo.

$ cat my.job
#!/bin/bash
sbcast my.prog /tmp/my.prog
srun /tmp/my.prog
$ sbatch --nodes=8 my.job
srun: jobid 12345 submitted
