NOMBRE

sbctl - Gestor de Arranque Seguro

SINOPSIS

sbctl <comando>

DESCRIPCIÓN

sbctl es una herramienta que permite crear claves para el arranque seguro, inscribirlas de forma segura y llevar un registro de los archivos a firmar.

COMANDOS DE FIRMA EFI

status

Muestra el estado actual del arranque seguro del sistema. Comprueba si estás arrancando actualmente en UEFI con Arranque Seguro y si el Modo de Configuración ha sido habilitado.

create-keys

Crea un conjunto de claves de firma utilizadas para firmar binarios de EFI. Actualmente, creará las siguientes claves:
•Clave de Plataforma
•Clave de Intercambio de Claves
•Clave de Base de Datos de Firmas

-e, --export

El directorio donde persistirán las claves exportadas.

-d, --database-path

Ruta para guardar el archivo GUID al generar claves.

enroll-keys

Inscribe la clave creada en las variables EFI. 
Ten en cuenta que algunos dispositivos tienen firmware de hardware que está firmado y validado cuando el Arranque Seguro está habilitado. No validar este firmware podría dañar los dispositivos. Se recomienda inscribir tus propias claves con certificados de Microsoft.

-m, --microsoft

Inscribe certificados de proveedor UEFI de Microsoft en la base de datos de firmas.

Ver ROM de Opciones*.

-t, --tpm-eventlog

Inscribe sumas de verificación del Registro de Eventos de TPM en la base de datos de firmas.

Ver ROM de Opciones*.

Esta característica es experimental

-c, --custom

Inscribe certificados personalizados de KEK y db desde "/var/lib/sbctl/keys/custom/KEK/", "/var/lib/sbctl/keys/custom/db/", respectivamente.

-f, --firmware-builtin

Inscribe firmas de dbDefault, KEKDefault o PKDefault. Esto es útil si sbctl no gestiona tus certificados OEM, o no incluye todos ellos.

Los valores válidos son "db", "KEK" o "PK" pasados como una cadena separada por comas.

Por defecto: "db,KEK"

--yes-this-might-brick-my-machine, --yolo

Ignora el error de ROM de Opciones y continúa inscribiendo claves en el firmware UEFI.

Ver ROM de Opciones*.

-i, --ignore-immutable

Ignora la comprobación de archivos inmutables en /sys/firmware/efi/efivars/ y desactiva el atributo de inmutabilidad antes de inscribir certificados.

--export

Exporta las claves que pretendemos inscribir como Listas de Firmas EFI (esl), o Variables Autenticadas EFI (auth) al directorio de trabajo actual.

Los valores válidos son: esl, auth.

-p, --partial

Inscribe claves solo para la jerarquía especificada.

Los valores válidos son: db, KEK, PK.

--custom-bytes

Inscribe un archivo de bytes personalizado proporcionado por su ruta al efivar especificado por partial.

-a, --append

En lugar de reemplazar las claves actualmente inscritas, añade la proporcionada.

--keytype

Establece el tipo de clave para todas las claves de firma utilizadas por sbctl. Esto incluye las claves PK, KEK y db.

Por defecto: file

Los valores válidos son: file, tpm

--pk-keytype

Establece el tipo de clave PK.

Por defecto: file

Los valores válidos son: file, tpm

--kek-keytype

Establece el tipo de clave KEK.

Por defecto: file

Los valores válidos son: file, tpm

--db-keytype

Establece el tipo de clave db.

Por defecto: file

Los valores válidos son: file, tpm

sign <ARCHIVO>...

Firma un binario EFI con la clave creada. El archivo se verificará en busca de firmas válidas para evitar duplicados.

-o RUTA, --output RUTA

Nombre del archivo de salida. Por defecto, reemplaza el archivo.

-s, --save

Guarda el archivo en la base de datos.

sign-all

Firma todos los binarios EFI inscritos.

-g, --generate

Genera todos los paquetes antes de firmar.

import-keys

Importa claves existentes en sbctl.

--db-cert RUTA

Ruta a un certificado de Base de Datos (db) válido.

--db-key RUTA

Ruta a una clave privada de Base de Datos (db) válida.

--kek-cert RUTA

Ruta a un certificado de Clave de Intercambio de Claves (KEK) válido.

--kek-key RUTA

Ruta a una clave privada de Clave de Intercambio de Claves (KEK) válida.

--pk-cert RUTA

Ruta a un certificado de Clave de Plataforma (PK) válido.

--pk-key RUTA

Ruta a una clave privada de Clave de Plataforma (PK) válida.

--directory RUTA

Ruta a un directorio de claves. Las ubicaciones de archivo esperadas dentro de este directorio son:
•PK/PK.key
•PK/PK.pem
•KEK/KEK.key
•KEK/KEK.pem
•db/db.key
•db/db.pem

--force

Sobrescribe el directorio de claves existente utilizado por sbctl.

list-files, ls-files, ls

Lista todos los binarios EFI inscritos.

remove-file <ARCHIVO>, rm-file <ARCHIVO>, rm <ARCHIVO>

Elimina el archivo de la base de datos de firma.

list-enrolled-keys, ls-enrolled-keys

Lista todas las claves inscritas en el sistema.

verify [ARCHIVO...]

Busca binarios EFI con el tipo MIME application/x-dosexec en la partición ESP y consulta la base de datos de archivos. Comprueba si han sido firmados con la Clave de Base de Datos de Firmas. Acepta un argumento de archivo opcional para comprobar archivos específicos.

reset

Reinicia la Clave de Plataforma. Esto saca la máquina del modo de Arranque Seguro y permite la rotación de claves.

-p, --partial

Reinicia claves solo para la jerarquía especificada.

Los valores válidos son: db, KEK, PK.

rotate-keys

Rota las claves de arranque seguro y las reemplaza con claves recién generadas. Guarda las claves antiguas en un directorio en /var/tmp y vuelve a firmar cualquier archivo de la base de datos de archivos.

--backup-dir RUTA

Elige el directorio de copia de seguridad para las claves antiguas.

-p, --partial

Rota claves solo para la jerarquía especificada.

Los valores válidos son: db, KEK, PK.

-k, --key-file

Archivo de clave que se añadirá para la jerarquía especificada.

-c, --cert-file

Archivo de certificado que se añadirá para la jerarquía especificada.

--keytype

Establece el tipo de clave para todas las claves de firma utilizadas por sbctl. Esto incluye las claves PK, KEK y db.

Por defecto: file

Los valores válidos son: file, tpm

--pk-keytype

Establece el tipo de clave PK.

Por defecto: file

Los valores válidos son: file, tpm

--kek-keytype

Establece el tipo de clave KEK.

Por defecto: file

Los valores válidos son: file, tpm

--db-keytype

Establece el tipo de clave db.

Por defecto: file

Los valores válidos son: file, tpm

export-enrolled-keys

Exporta las claves ya inscritas desde el sistema.

--dir RUTA

Directorio de salida para las claves exportadas.

--format TIPO

Formato de
las claves exportadas.

Por defecto: der valores válidos: esl, auth.

setup

Configura una instalación de sbctl. 
Este comando habilita la configuración declarativa de sbctl a través del
archivo de configuración. También puede imprimir la configuración actual y el
estado actual de la instalación.

--setup

Configura una instalación de sbctl basada en el archivo de configuración proporcionado, o la configuración de lectura por defecto de /etc/sbctl/sbctl.conf.

Esto ejecutará automáticamente los comandos create-keys y enroll-keys y también configurará la base de datos de archivos para la firma.

Ver sbctl.conf(5) para más detalles.

--migrate

Migra la configuración y la configuración de sbctl a una nueva iteración.

Actualmente, la única migración para sbctl es mover de /usr/share/secureboot a /var/lib/sbctl.

--print-config

Imprime una versión serializada de la configuración actual de sbctl.

Ver sbctl.conf(5) para más detalles.

--print-state

Imprime el estado de la instalación de sbctl. Actualmente solo imprime si sbctl ha sido instalado en el sistema o no.

Nota: Esta opción requiere pasar --json.

help

Muestra un mensaje de ayuda.

PAQUETES

Nota: Esto está siendo obsoleto. Por favor, migra a dracut/mkinitcpio/ukify.

Normalmente, solo el kernel se firma con tus claves de arranque seguro. Esto significa que la línea de comandos del kernel y el initramfs pueden ser cambiados sin posibilidad de verificación.

Los paquetes son ejecutables EFI que empaquetan los tres (initramfs, kernel y línea de comandos) en un solo archivo que es fácil de firmar. Evitar archivos sin firmar durante el arranque hace que todo el proceso sea más resistente a manipulaciones.

Cuando se genera un paquete, su configuración se almacena en la base de datos de paquetes (ver ARCHIVOS). Ejecuciones posteriores de sbctl generate-bundles reconstruirán estos paquetes, por lo que no necesitas volver a especificar todos los parámetros después de cada actualización del sistema.

Consejo: systemd-boot mostrará automáticamente entradas para cualquier paquete encontrado en esp/EFI/Linux/*.efi.

TIPOS DE CLAVE SOPORTADOS

sbctl soporta actualmente el almacenamiento de claves como archivos simples sin cifrar, o como claves protegidas por TPM.

Los archivos simples sin cifrar (file) solo deben usarse cuando la partición raíz esté cifrada. Este es el tipo de clave por defecto por razones históricas. Las claves de archivo están codificadas para RSA 4096.

Las claves protegidas por TPM (tpm) están protegidas dentro del TPM y disponibles si hay un TPM accesible en el sistema. Las políticas de TPM no son soportadas, lo que significa que no podemos sellar claves hacia el estado del sistema. Ten en cuenta que las claves de TPM están codificadas para RSA 2048, que suele ser la mayor fuerza de bits soportada por los TPMs.

Al crear una jerarquía de claves para Secure Boot, el usuario puede decidir qué tipo de clave tendrá cada una de las claves de la jerarquía. Dado que los TPMs pueden ser lentos para firmar, generalmente se aconseja mantener PK y KEK en el TPM, mientras que la clave db puede ser una clave file estándar.

Ten en cuenta que la protección por contraseña no está soportada actualmente.

LANDLOCK

sbctl soporta landlock e intentará restringir el acceso a las rutas de archivo a donde sea necesario durante la ejecución. Cualquier intento de establecer acceso a la red también está restringido.

Esta función puede ser deshabilitada estableciendo landlock: false en el archivo de configuración, o pasando --disable-landlock a sbctl.

USO

Nota: Para usar claves de arranque seguro personalizadas, es importante reiniciar en la configuración del firmware (systemctl reboot --firmware-setup) y navegar al menú de Secure Boot para entrar en Setup Mode. Esto se logra normalmente eliminando/borrando las claves de arranque seguro (o como mínimo la Clave de Plataforma) mientras se deja habilitado el modo de arranque seguro. Algunos firmwares tienen un Custom Mode que solo deshabilita la verificación de firmas y por lo tanto no debe ser habilitado a menos que no haya otra forma de acceder a la gestión de claves. Si este paso no se completa, el firmware rechazará la inscripción de claves personalizadas.

Lo siguiente es crear las claves para el arranque seguro. create-keys crea la jerarquía de claves necesaria para el arranque seguro en "/var/lib/sbctl/keys".

# sbctl create-keys
Created Owner UUID a9fbbdb7-a05f-48d5-b63a-08c5df45ee70
Creating secure boot keys...✔
Secure boot keys created!

A continuación, se inscriben las claves en el firmware EFI. sbctl soporta hacer esto en un sistema en vivo en lugar de tener que arrancar o ejecutar una herramienta de gestión de claves desde la shell UEFI.

Nota: Esto puede fallar debido a problemas de firmware y opciones únicas en el menú BIOS de la máquina. Además, algunos dispositivos tienen firmware de hardware que está firmado y validado cuando Secure Boot está habilitado. No validar este firmware podría inutilizar dispositivos. Se recomienda inscribir tus propias claves con certificados de Microsoft usando la opción -m. Ver Opción ROM* arriba.

# sbctl enroll-keys
Enrolling keys to EFI variables...✔
Enrolled keys to the EFI variables!

Después de haber inscrito las claves con éxito, necesitamos firmar nuestra cadena de arranque actual. Tradicionalmente en sistemas UEFI, se puede tener una Partición del Sistema EFI (ESP) en /efi, /boot o /boot/efi. Normalmente se puede encontrar la correcta mirando los puntos de montaje o encontrando el directorio EFI en el ESP.

El archivo más importante para firmar es el kernel. Esta ubicación difiere entre distribuciones, pero normalmente se puede encontrar en el ESP o en /boot. Usamos --save para almacenar la ruta del archivo, para no tener que firmarlo manualmente más tarde.

Ten en cuenta que sbctl solo puede rastrear rutas de archivo. En kernels versionados, esto puede resultar complicado.

# sbctl sign --save /efi/vmlinuz-linux
✔ Signed /efi/vmlinuz-linux

Lo siguiente es firmar el gestor de arranque. Este normalmente se puede encontrar en la ruta estándar de abajo, pero podría diferir entre instalaciones.

# sbctl sign --save /efi/EFI/BOOT/BOOTX64.EFI
✔ Signed /efi/EFI/BOOT/BOOTX64.EFI

sbctl es capaz de encontrar y verificar la ESP, junto con cualquier archivo guardado para verificar que hemos firmado los archivos que necesitamos.

# sbctl verify
Verifying file database and EFI images in /efi...
✔ /efi/EFI/BOOT/BOOTX64.EFI is signed
✔ /efi/vmlinuz-linux is signed

Una vez confirmado que todo funciona, podemos reiniciar. Una vez que hayamos iniciado sesión de nuevo, podemos verificar el estado del sistema. No debería ser necesario volver a habilitar Secure Boot ni entrar en User Mode en el firmware.

$ sbctl status
Installed:  ✓ sbctl is installed
Owner GUID: a7b893cc-949d-408c-b5cc-6e7d0370fdb6
Setup Mode: ✓ Disabled
Secure Boot:    ✓ Enabled

Cuando hagamos una actualización del sistema, podemos ejecutar sign-all para volver a firmar todos los archivos guardados de antes.

# sbctl sign-all
File has already been signed /boot/vmlinuz-linux
✓ Signed /efi/EFI/BOOT/BOOTX64.EFI

sbctl soporta

BUNDLES

Las imágenes de kernel unificadas (UKI) son ejecutables UEFI que agrupan el initramfs, el kernel y la línea de comandos en un solo ejecutable que se puede firmar para arranque seguro. Esto le permite autenticar partes más grandes de la cadena de arranque en lugar de solo firmar el kernel.

# sbctl bundle -i /boot/intel-ucode.img
               -l /usr/share/systemd/bootctl/splash-arch.bmp
               -k /boot/vmlinuz-linux
               -f /boot/initramfs-linux-lts.img
               -c /etc/kernel/cmdline
               /efi/EFI/Linux/linux-linux.efi

Tenga en cuenta que dracut(8) y mkinitcpio(8) admiten funcionalidades de kernel unificadas y deberían preferirse sobre la implementación de sbctl. Se proporciona principalmente en los casos en que esta funcionalidad no está soportada por el generador de initramfs de la distribución.

NOTAS

Todos los comandos que toman argumentos de ruta los convierten en rutas absolutas al guardarlos en la base de datos.

ESTADO DE SALIDA

En caso de éxito, se devuelve 0, de lo contrario, un código de error distinto de cero.

VARIABLES DE ENTORNO

SYSTEMD_ESP_PATH, ESP_PATH

Define la ubicación de la partición del sistema EFI (ESP). Esto anula el comportamiento de sbctl donde consultamos la partición correcta con lsblk. No se realizan comprobaciones en esta ruta y puede ser útil para fines de prueba.

SBCTL_UNICODE

Si este valor es "0", sbctl reemplazará los símbolos unicode por equivalentes ascii. El valor predeterminado se asume que es 1.

ARCHIVOS

/var/lib/sbctl

Directorio de almacenamiento predeterminado.

Identificación del propietario. Este es un UUID generado aleatoriamente.
