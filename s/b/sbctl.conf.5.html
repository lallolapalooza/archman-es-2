NOMBRE

sbctl.conf - el archivo de configuración de sbctl

SINOPSIS

/etc/sbctl/sbctl.conf

DESCRIPCIÓN

El archivo de configuración de sbctl es un archivo YAML. Se lee al arrancar si está presente.

El archivo puede usarse para la configuración inicial de una instalación de sbctl.

DIRECTORIOS DE CONFIGURACIÓN Y PRECEDENCIA

Actualmente, el archivo de configuración solo se lee de /etc/sbctl. Esto podría cambiar en el futuro.

OPCIONES

keydir: /ruta/al/directorio/de/claves

Define el directorio donde sbctl buscará las claves.

Por defecto: /var/lib/sbctl/keys

guid: /ruta/al/archivo/guid

La ubicación del archivo que define el GUID creado por el usuario.

El GUID se utiliza para identificar de forma única la lista de certificados almacenados en las variables EFI.

Por defecto: /var/lib/sbctl/GUID

files_db: /ruta/al/archivo/json/de/archivos

La ubicación del archivo json que almacena los archivos que sbctl firmará.

Por defecto: /var/lib/sbctl/files.json

bundles_db: /ruta/al/archivo/json/de/paquetes

La ubicación del archivo json que almacena los paquetes que sbctl firmará.

Por defecto: /var/lib/sbctl/bundles.json

landlock: booleano

Habilita o deshabilita el sandboxing de sbctl con Landlock.

Por defecto: true

db_additions: [ opciones... ] Incluye claves o sumas de verificación adicionales en la base de datos de autorización para Secure Boot. Estos valores son sinónimos de las banderas pasadas a sbctl enroll-keys. Valores válidos: microsoft, tpm-eventlog, firmware-builtin, custom

files: [ [path: /ruta/al/archivo output: /ruta/al/salida ], ... ]

Una lista de archivos que sbctl firmará al configurarse. Se utilizará para sembrar el files_db durante la configuración inicial.

path

Ruta absoluta a un archivo que sbctl debe firmar.

output

Una ruta de salida absoluta opcional para el archivo firmado.

keys: {pk: {...}, kek: {...}, db: {...}}

Un par clave-valor para todas las claves en la jerarquía de claves utilizada para Secure Boot. Se utiliza para el arranque inicial durante la configuración.
•pk
•kek
•db
Cada una de las jerarquías puede especificar el tipo de clave y la ubicación de la clave privada y el archivo del certificado independientemente uno del otro. Esto permite a los usuarios mantener algunas claves en diferentes soportes de almacenamiento según sus necesidades. Un ejemplo sería mantener la clave db como un archivo sin cifrar fácilmente accesible para firmar y la PK en un enclave respaldado por hardware para asegurar mejor el material de la clave.

privkey: /ruta/al/archivo/clave/privada

Ruta a la clave privada.

Por defecto:

•pk: /var/lib/sbctl/keys/PK/PK.key
•kek: /var/lib/sbctl/keys/KEK/KEK.key
•db: /var/lib/sbctl/keys/db/db.key

pubkey: /ruta/al/archivo/certificado

Ruta a la clave pública.

Por defecto:

•pk: /var/lib/sbctl/keys/PK/PK.pem
•kek: /var/lib/sbctl/keys/KEK/KEK.pem
•db: /var/lib/sbctl/keys/db/db.pem

type: file

El tipo de clave utilizada para esta clave de firma.

Actualmente, sbctl solo admite el tipo de clave file.

Por defecto: file

EJEMPLO

Un ejemplo de un archivo /etc/sbctl/sbctl.conf con los valores por defecto.

---
keydir: /var/lib/sbctl/keys
guid: /var/lib/sbctl/GUID
files_db: /var/lib/sbctl/files.json
bundles_db: /var/lib/sbctl/bundles.json
landlock: true
db_additions:
- microsoft
files:
- path: /boot/vmlinuz-linux
  output: /boot/vmlinuz-linux
- path: /efi/EFI/Linux/arch-linux.efi
  output: /efi/EFI/Linux/arch-linux.efi
keys:
  pk:
    privkey: /var/lib/sbctl/keys/PK/PK.key
    pubkey: /var/lib/sbctl/keys/PK/PK.pem
    type: file
  kek:
    privkey: /var/lib/sbctl/keys/KEK/KEK.key
    pubkey: /var/lib/sbctl/keys/KEK/KEK.pem
    type: file
  db:
    privkey: /var/lib/sbctl/keys/db/db.key
    pubkey: /var/lib/sbctl/keys/db/db.pem
    type: file
