SRP_DAEMON(8) COMANDOS DE USUARIO SRP_DAEMON(8)

NOMBRE

srp_daemon - Descubre objetivos SRP en una Fabric InfiniBand

SINOPSIS

srp_daemon [-vVcaeon] [-d dispositivo-umad | -i dispositivo-infiniband [-p numero-puerto] | -j dev:puerto] [-t tiempo-espera(ms)] [-r reintentos] [-R tiempo-re-escaneo] [-f archivo-reglas]

DESCRIPCIÓN

Descubre y se conecta a objetivos de SCSI RDMA Protocol (SRP) de InfiniBand en una fabric IB.

Cada instancia de srp_daemon opera en un puerto local. Al arrancar, realiza un reescaneo completo de la fabric y luego espera un evento de srp_daemon. Un evento de srp_daemon puede ser la unión de una nueva máquina a la fabric, un cambio en las capacidades de una máquina, un cambio de SA o la expiración de un tiempo de espera predefinido.

Cuando una nueva máquina se une a la fabric, srp_daemon comprueba si es un objetivo SRP. Cuando hay un cambio de capacidades, srp_daemon comprueba si la máquina se ha convertido en un objetivo SRP. Cuando hay un cambio de SA o una expiración de tiempo de espera, srp_daemon realiza un reescaneo completo de la fabric.

Para cada objetivo que srp_daemon encuentra, comprueba si debe conectarse a él según sus reglas (el archivo de reglas predeterminado es /etc/srp_daemon.conf) y si ya está conectado al puerto local. Si debe conectarse a este objetivo y aún no está conectado, srp_daemon puede imprimir los detalles del objetivo o conectarse a él.

OPCIONES

-v
Imprime salida más detallada
-V
Imprime salida aún más detallada (modo depuración)
-i dispositivo-infiniband
Trabaja en dispositivo-infiniband. Esta opción no debe usarse con -d ni con -j.
-p numero-puerto
Trabaja en el puerto numero-puerto (predeterminado 1). Esta opción debe usarse con -i y no debe usarse con -d ni con -j.
-j dev:puerto
Trabaja en el número de puerto puerto del dispositivo InfiniBand dev. Esta opción no debe usarse con -d, -i ni con -p.
-d dispositivo-umad
Usa el archivo de dispositivo dispositivo-umad (predeterminado /dev/infiniband/umad0). Esta opción no debe usarse con -i, -p ni con -j.
-c
Genera salida adecuada para enviarla directamente a un archivo /sys/class/infiniband_srp/srp-<dispositivo>-<puerto>/add_target.
-a
Imprime todos los objetivos en la fabric, no solo los objetivos que no están conectados a través del puerto local. Este es el mismo comportamiento que el de ibsrpdm.
-e
Ejecuta el comando de conexión, es decir, establece la conexión con el objetivo.
-o
Realiza solo un reescaneo y sale, al igual que ibsrpdm.
-R tiempo-re-escaneo
Fuerza un reescaneo completo cada tiempo-re-escaneo segundos. Si no se especifica -R, no se realizarán reescaneos por tiempo de espera.
-T tiempo-espera-reintento
Reintenta conectarse a un objetivo existente después de tiempo-espera-reintento segundos. Si -R no se especifica, usa un tiempo de espera de 5 segundos. Si tiempo-espera-reintento es 0, no intentará reconectarse. La razón por la que srp_daemon reintenta conectarse al objetivo es porque puede haber un escenario raro en el que srp_daemon intente conectarse para añadir un objetivo cuando el objetivo está a punto de ser eliminado, pero aún no lo ha sido.
-f archivo-reglas
Decide a qué objetivos conectarse según las reglas en archivo-reglas. Si no se especifica -f, usa el archivo de reglas predeterminado /etc/srp_daemon.conf. Cada línea en el archivo-reglas es una regla que puede ser permitir la conexión o denegar la conexión según el primer carácter de la línea (a o d respectivamente). El resto de la línea son valores para id_ext, ioc_guid, dgid, service_id. Por favor, consulta la sección de ejemplos para ver un ejemplo del archivo. srp_daemon decide si permitir o denegar cada objetivo según la primera regla que coincida con el objetivo. Si ninguna regla coincide con el objetivo, el objetivo se permite y se conectará. En una regla de permitir, es posible establecer atributos para la conexión al objetivo. Los atributos admitidos son max_cmd_per_lun y max_sect.
-t tiempo-espera
Usa un tiempo de espera de tiempo-espera msec para las respuestas MAD (predeterminado: 5 segundos).
-r reintentos
Realiza reintentos reintentos en cada envío a MAD (predeterminado: 3 reintentos).
-n
Nuevo formato - también usa initiator_ext en el comando de conexión.
--systemd
Habilita la integración con systemd.

ARCHIVOS

/etc/srp_daemon.conf - Archivo de configuración de reglas predeterminado que indica a qué objetivos conectarse. Puede ser anulado usando la opción -f archivo-reglas. Cada línea en este archivo es una regla que puede ser permitir la conexión o denegar la conexión según el primer carácter de la línea (a o d respectivamente). El resto de la línea son valores para id_ext, ioc_guid, dgid, service_id. Por favor, consulta la sección de ejemplos para ver un ejemplo del archivo. srp_daemon decide si permitir o denegar cada objetivo según la primera regla que coincida con el objetivo. Si ninguna regla coincide con el objetivo, el objetivo se permite y se conectará. En una regla de permitir, es posible establecer atributos para la conexión al objetivo. Los atributos admitidos son max_cmd_per_lun y max_sect.

EJEMPLOS

srp_daemon -e -i mthca0 -p 1 -R 60 (Se conecta a los objetivos accesibles a través del puerto 1 de mthca0. Realiza un reescaneo completo cada minuto)

srp_daemon -o -c -a (Imprime los comandos de conexión para los objetivos en la fabric y sale - similar a ibsrpdm)

srp_daemon -e -f rules.txt (Se conecta a los objetivos permitidos en el archivo de reglas rules.txt)

Un ejemplo de archivo de configuración de reglas (como /etc/srp_daemon.conf)
------------------------------------------------------------------------
# Archivo de reglas ejemplo
# Esto es un comentario
# denegar el siguiente dgid
d       dgid=fe800000000000000002c90200402bd5
# permitir objetivo con el siguiente ioc_guid
a       ioc_guid=00a0b80200402bd7
# permitir objetivo con el siguiente id_ext y ioc_guid. Y estableciendo max_cmd_per_lun a 31.
a       id_ext=200500A0B81146A1,ioc_guid=00a0b80200402bef,max_cmd_per_lun=31
# denegar el resto
d
