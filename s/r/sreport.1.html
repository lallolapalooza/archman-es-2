NOMBRE

sreport - Genera informes de uso de trabajos y utilización del clúster para trabajos de Slurm guardados en la Base de Datos de Slurm, slurmdbd.

SINOPSIS

sreport [OPCIONES...] [COMANDO...]

DESCRIPCIÓN

sreport se utiliza para generar informes de uso de trabajos y utilización del clúster para trabajos de Slurm guardados en la Base de Datos de Slurm, slurmdbd. Los datos del informe provienen de resúmenes horarios, diarios y mensuales de los datos de contabilidad que ocurren automáticamente en segundo plano. Los datos se extraerán de la tabla de resumen con el intervalo más largo que pueda satisfacer el período del informe solicitado. Por ejemplo, un informe sobre el rango de tiempo "Start=01/01 End=03/01" podrá extraer de la tabla de resumen mensual, mientras que un informe con "Start=01/01-03:00 End=03/01" necesitará usar la tabla de resumen horaria.

OPCIONES

-a, --all_clusters
Utiliza todos los clústeres en lugar de solo el clúster desde el cual se ejecutó el comando.
-M, --cluster
Los clúster(es) para los cuales generar informes. Por defecto es el clúster local, a menos que el clúster local sea actualmente parte de una federación y en ese caso generar un informe para todos los clústeres en la federación actual. Si los clústeres incluidos en una federación varían con el tiempo, usa esta opción para identificar los clústeres a incluir en el informe. Implica --local.
--federation
Genera un informe para la federación si es miembro de una.
-h, --help
Imprime un mensaje de ayuda que describe el uso de sreport.
--local
Genera un informe para el clúster local, incluso si es parte de una federación. Anula --federation.
-n, --noheader
No muestra la cabecera al listar los resultados.
-p, --parsable
La salida estará delimitada por '|' con un '|' al final.
-P, --parsable2
La salida estará delimitada por '|' sin un '|' al final.
-Q, --quiet
No imprime mensajes de advertencia o informativos, solo mensajes de error.
-t <formato_tiempo>
Especifica el formato de tiempo de salida. Las opciones de formato de tiempo no distinguen entre mayúsculas y minúsculas y pueden abreviarse. El formato predeterminado es Minutos. Las opciones de formato de tiempo admitidas se enumeran en la sección de comando time a continuación.
-T, --tres=<nombres_tres>
Recurso rastreable (TRES) para el cual informar los valores. Por defecto, se informa el uso del recurso de CPU (excepto para informes de reserva. Todos los tipos de TRES reservados por una reserva se mostrarán por defecto a menos que se anulen con esta opción). Múltiples nombres de TRES pueden separarse con una lista separada por comas para todos los informes excepto los informes de trabajos, que solo pueden admitir un solo nombre de TRES, o "ALL" para todos los TRES.

El TRES de Facturación "Reportado" se calcula a partir del TRES de Facturación más grande de cada nodo multiplicado por el marco de tiempo. Por ejemplo, si un nodo forma parte de múltiples particiones y cada una tiene diferentes TRESBillingWeights definidos, el TRES de Facturación para el nodo será el más alto de las particiones. Si TRESBillingWeights no está definido en ninguna partición para un nodo, entonces el TRES de Facturación será igual al número de CPUs en el nodo.

El uso de nodos TRES ya no se informa en formato de porcentaje ni en Utilización del Clúster. Por favor, use TRES CPU en su lugar. El principal problema con el uso de nodos es que en la mayoría de las configuraciones múltiples trabajos pueden ejecutarse en el mismo nodo. Esto hace que la contabilidad de nodos TRES cuente el mismo nodo varias veces en el mismo período. En configuraciones de nodos exclusivos, la contabilidad de CPU devuelve el mismo uso que la contabilidad de nodos.

-v, --verbose
Imprime registro detallado de eventos.
-V , --version
Imprime la información de la versión y sale.

TIPOS DE REPORTE

Los tipos de reporte válidos son:

cluster <REPORTE> <OPCIONES>
job <REPORTE> <OPCIONES>
reservation <REPORTE> <OPCIONES>
user <REPORTE> <OPCIONES>

<REPORTE> las opciones para cada tipo incluyen:

cluster
AccountUtilizationByUser, AccountUtilizationByQOS, UserUtilizationByAccount, UserUtilizationByWckey, Utilization, WCKeyUtilizationByUser
job
SizesByAccount, SizesByAccountAndWcKey, SizesByWckey
reservation
Utilization
user
TopUsage

NOTA: Si OverSubscribe está configurado como FORCE o YES en tu slurm.conf y el sistema no está configurado para usar la preemption (PreemptMode=OFF), la contabilidad puede crecer fácilmente a valores mayores que la utilización real. Puede ser común en tales sistemas recibir mensajes de error en el log de slurmdbd que dicen: "Tenemos más tiempo asignado del que es posible."

DESCRIPCIÓN DE REPORTES

cluster AccountUtilizationByUser
Este reporte mostrará la utilización de cuentas tal como aparece en el árbol jerárquico. Comenzando con la cuenta especificada o la cuenta raíz por defecto, este reporte listará el uso subyacente con una suma en cada nivel. Usa la opción 'tree' para expandir el árbol para una mejor visibilidad.

NOTA: El tiempo de reserva inactivo se dividirá equitativamente entre las cuentas/usuarios a los que se les da acceso. Cuando una reserva se asigna a cuentas completas, el tiempo se contará en la asociación de las cuentas, no en las asociaciones de usuarios en las cuentas. En este caso, el uso de una cuenta padre puede ser mayor que la suma de sus hijos.

cluster AccountUtilizationByQOS
Este reporte mostrará la utilización de cuentas tal como aparece en el árbol jerárquico. Comenzando con la cuenta raíz por defecto, o con la cuenta especificada, este reporte listará el uso subyacente en cada cuenta, con una suma en cada nivel. Usa la opción 'tree' para expandir el árbol para una mejor visibilidad. Los usuarios no se muestran aquí, solo las cuentas padre.

NOTA: El tiempo de reserva inactivo se dividirá equitativamente entre las cuentas que tengan acceso a él. Como no hay un QOS directamente conectado con el tiempo inactivo, el tiempo se cuenta contra el QOS predeterminado de la cuenta, o 'normal' cuando no hay predeterminado.

NOTA: Si reorganizas los datos en la base de datos y has cambiado el QOS predeterminado en una asociación a algo diferente de lo que estaba allí en el momento del resumen original, puedes obtener datos diferentes.

cluster UserUtilizationByAccount
Este reporte mostrará los usuarios por cuenta en orden de utilización sin agrupar múltiples cuentas por usuario en una sola, sino mostrándolas en líneas separadas.
cluster UserUtilizationByWCKey
Este reporte mostrará los usuarios por wckey en orden de utilización sin agrupar múltiples wckeys por usuario en uno solo, sino mostrándolas en líneas separadas.
cluster Utilization
Este reporte mostrará el uso total dividido entre tiempo Asignado, Caído, Caído Planificado, Inactivo y Planificado para los clústeres seleccionados.

Consulte la sección posterior para obtener descripciones de estos campos.

Nota: Las reservas creadas con el flag IGNORE_JOBS no se rastrean en el reporte de Utilización de Clúster debido a que permitir que los trabajos actuales/activos continúen ejecutándose en la reserva introduce la posibilidad de que se contabilicen incorrectamente. Los trabajos en estas reservas se rastrearán normalmente en lugar de agruparse en el tiempo de reserva, como ocurre con las reservas que no tienen el flag IGNORE_JOBS.

Nota: La vista predeterminada para el reporte "Utilización de Clúster" incluye los siguientes campos: Cluster, Asignado, Caído, CaídoPlanificado, Inactivo, Planificado, Reportado. Puedes incluir campos adicionales como OverCommitted y campos TresCount con la opción Format. El TresName también se incluirá si se utiliza la opción -T, --tres <tres_names>.


cluster WCKeyUtilizationByUser
Este reporte mostrará la utilización de wckey ordenada por nombre de WCKey para cada usuario en cada clúster.
job SizesByAccount
Este reporte mostrará la cantidad de tiempo utilizado para rangos de trabajos especificados por la opción 'grouping='. Solo se muestra un nivel en el árbol por defecto al directorio raíz. Si especificas otras cuentas con la opción 'account=', sreport usará esas cuentas como cuenta raíz y recibirás los totales agregados de cada cuenta listada más sus subcuentas.
job SizesByAccountAndWckey
Este reporte es muy similar a SizesByAccount, con la diferencia de que cada cuenta se empareja con wckeys, por lo que el identificador es cuenta:wckey en lugar de solo cuenta, por lo que lo más probable es que se listan varias cuentas dependiendo del número de wckeys utilizadas.
job SizesByWckey
Este reporte mostrará la cantidad de tiempo para cada wckey para rangos de trabajos especificados por la opción 'grouping='.
reservation Utilization
Este reporte mostrará el uso total para las reservas en los sistemas. Nota: Las solicitudes de tiempo en este reporte no truncarán el tiempo que utilizó la reserva, solo las reservas que se ejecutaron en algún momento durante el período solicitado.
user TopUsage
Muestra los principales usuarios en un clúster, es decir, los usuarios con mayor uso. Por defecto, los usuarios se ordenan por CPUTime, pero la opción -T, --tres ordenará los usuarios por el primer TRES especificado.

Usa la opción group para agrupar cuentas. El valor por defecto es tener una línea diferente para cada combinación de cuenta de usuario.

Cada tipo de reporte tiene varias opciones...

OPCIONES ESPECÍFICAS PARA INFORMES DE CLUSTER

Cuentas=<OPT>
Cuando se usa con UserUtilizationByAccount o AccountUtilizationBy[User|QOS], lista de cuentas a incluir en el informe. El valor predeterminado es todas.
Árbol
Cuando se usa con el informe AccountUtilizationBy[User|QOS], abarcará las cuentas tal como están en la jerarquía.
Usuarios=<OPT>
Cuando se usa con cualquier informe que no sea Utilization, lista de usuarios a incluir en el informe. El valor predeterminado es todos.
Wckeys=<OPT>

OPCIONES ESPECÍFICAS PARA INFORMES DE TRABAJOS

Cuentas=<OPT>
Lista de cuentas a utilizar para el informe. El valor predeterminado es todas, que mostrará solo una línea correspondiente a los totales de todas las cuentas en la jerarquía. Esta explicación no se aplica cuando se ejecuta con las opciones FlatView o AcctAsParent.
AcctAsParent
Cuando se usa con SizesbyAccount(*) tomará las cuentas especificadas como padres y se mostrará la siguiente capa de cuentas debajo de las especificadas. El valor predeterminado es root si no se solicitan cuentas específicas. Cuando se usa FlatView, esta opción se ignora.
FlatView
Cuando se usa con SizesbyAccount(*), no agrupará las cuentas en un nivel jerárquico, sino que imprimirá cada cuenta donde se ejecutaron trabajos en una línea separada sin ninguna jerarquía.
GID=<OPT>
Lista de IDs de grupo a incluir en el informe. El valor predeterminado es todos.
Agrupación=<OPT>
Lista separada por comas de agrupaciones de tamaño. (por ejemplo, 50,100,150 agruparía el conteo de CPU de trabajos 1-49, 50-99, 100-149, > 150). grouping=individual dará como resultado una sola columna para cada tamaño de trabajo encontrado.
Trabajos=<OPT>
Lista de trabajos/pasos a incluir en el informe. El valor predeterminado es todos.
Nodos=<OPT>
Solo mostrar trabajos que se ejecutaron en estos nodos. El valor predeterminado es todos.
Particiones=<OPT>
Lista de particiones en las que se ejecutaron trabajos para incluirlas en el informe. El valor predeterminado es todas.
PrintJobCount
Cuando se usa con el informe Sizes, imprimirá el número de trabajos ejecutados en lugar del tiempo utilizado.
Usuarios=<OPT>
Lista de usuarios cuyos trabajos incluir en el informe. El valor predeterminado es todos.
Wckeys=<OPT>
Lista de wckeys a utilizar para el informe. El valor predeterminado es todos. El informe SizesbyWckey suma todos los usuarios. Si solo desea usuarios específicos, especifíquelos con la opción Users=.

OPCIONES ESPECÍFICAS PARA INFORMES DE RESERVAS

Nombres=<OPT>
Lista de reservas a utilizar para el informe. El valor predeterminado es todas.
Nodos=<OPT>
Solo mostrar reservas que utilizaron estos nodos. El valor predeterminado es todos.

OPCIONES ESPECÍFICAS PARA INFORMES DE USUARIOS

Lista de cuentas a utilizar para el informe. El valor predeterminado es todas.

Usuarios=<OPT>
Lista de usuarios cuyos trabajos incluir en el informe. El valor predeterminado es todos.

DESCRIPCIÓN

El comando sreport genera informes sobre el uso de recursos del clúster. Los informes pueden generarse para el clúster completo o para reservas específicas. El comando se comunica con el demonio slurmdbd para recuperar datos del informe.

Esto contiene cualquier desbordamiento del tiempo planificado que de otra manera excedería el tiempo reportado. Típicamente es útil para determinar si su sistema está sobrecargado y en qué medida.
Planned
Informe de utilización del clúster solamente: Tiempo que los nodos no estuvieron asignados, caídos o planificados para caída con trabajos elegibles en la cola que no pudieron iniciarse debido a restricciones de tiempo o tamaño. Si el tiempo asignado más el planificado excede el tiempo reportado, el exceso se informará como sobrecomisionado. Si este valor no es de importancia para usted, entonces el número puede agruparse con el tiempo inactivo.
PlannedDown
Informe de utilización del clúster solamente: Tiempo que los nodos estuvieron en uso por una reserva creada con la marca MAINT pero no con la marca IGNORE_JOBS. Además, tiempo que los nodos estuvieron en estado FUTURO o APAGADO.
Proper Name
Nombre propio/real del usuario.
Reported
Informe de utilización del clúster solamente: Tiempo total para el que hay datos disponibles. Los nodos que se agregaron o eliminaron del clúster durante el período del informe solo contribuirán con datos de uso durante el tiempo que estuvieron presentes en el clúster y causarán que los cálculos porcentuales se desvíen del 100%.
ReservationId
Informe de reserva solamente: ID de la reserva.
Start
Informe de reserva solamente: Hora de inicio.
TotalTime
Informe de reserva solamente: Cantidad de tiempo que la reserva fue válida.
TresCount
Número de TRES presentes.
TresName
Nombre del TRES reportado.
TresTime
Informe de reserva solamente: Tiempo total de TRES en la reserva.
Used
Minutos de TRES utilizados.
Wckey
Clave de caracterización de carga de trabajo.

RENDIMIENTO

Ejecutar sreport envía una llamada de procedimiento remoto a slurmdbd. Si llegan suficientes llamadas de sreport u otros comandos cliente de Slurm que envían llamadas de procedimiento remoto al demonio slurmdbd a la vez, esto puede resultar en una degradación del rendimiento del demonio slurmdbd, posiblemente resultando en una denegación de servicio.

No ejecute sreport u otros comandos cliente de Slurm que envían llamadas de procedimiento remoto a slurmdbd desde bucles en scripts de shell u otros programas. Asegúrese de que los programas limiten las llamadas a sreport al mínimo necesario para la información que está tratando de recopilar.

VARIABLES DE ENTORNO

Algunas opciones de sreport pueden establecerse a través de variables de entorno. Estas variables de entorno, junto con sus opciones correspondientes, se enumeran a continuación. (Nota: Las opciones de línea de comandos siempre anularán estas configuraciones.)

SREPORT_CLUSTER
Igual que -M, --cluster
SREPORT_FEDERATION
Igual que --federation
SREPORT_LOCAL
Igual que --local
SREPORT_TRES
Igual que -t, --tres
SLURM_CONF
La ubicación del archivo de configuración de Slurm.
