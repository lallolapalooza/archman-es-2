NOMBRE

systemd-keyutil - Realizar varias operaciones con claves privadas y certificados X.509

SINOPSIS

systemd-keyutil [OPCIONES...] {COMANDO}

DESCRIPCIÓN

systemd-keyutil se puede utilizar para realizar varias operaciones con claves privadas y certificados X.509.

COMANDOS

validate

Comprueba que podemos cargar la clave privada y el certificado especificados con --private-key= y --certificate= respectivamente.

Como efecto secundario, si la clave privada se carga desde un token de hardware protegido con PIN, este comando se puede utilizar para almacenar en caché el PIN en el keyring del kernel. Las variables de entorno $SYSTEMD_ASK_PASSWORD_KEYRING_TIMEOUT_SEC y $SYSTEMD_ASK_PASSWORD_KEYRING_TYPE se pueden utilizar para controlar cuánto tiempo y en qué keyring del kernel se almacena en caché el PIN.

Añadido en la versión 257.

public

Este comando imprime la clave pública en formato PEM extraída del certificado proporcionado con --certificate= o de la clave privada proporcionada con --private-key=.

Añadido en la versión 257.

pkcs7

Este comando incrusta la firma PKCS#1 (RSA) proporcionada con --signature= en una firma PKCS#7 utilizando el certificado proporcionado con --certificate= y lo escribe en el archivo especificado con --output= en formato PKCS#7 (p7s). Si se proporciona --content=, se incluye en el p7s; de lo contrario, se crea una firma "separada". La opción --hash-algorithm=, que por defecto es "SHA256", especifica qué algoritmo de hash se utilizó para generar la firma.

Añadido en la versión 258.

OPCIONES

Se admiten las siguientes opciones:

--private-key=RUTA/URI, --private-key-source=TIPO[:NOMBRE], --certificate=RUTA, --certificate-source=TIPO[:NOMBRE]

Establece la clave privada y el certificado a utilizar. La opción --certificate= toma una ruta a un certificado X.509 codificado en PEM o una URI que se pasa al proveedor OpenSSL configurado con --certificate-source. --certificate-source toma uno de "file" o "provider", y este último va seguido de un identificador de proveedor específico, separado por dos puntos, por ejemplo, "provider:pkcs11". La opción --private-key= puede tomar una ruta o una URI que se pasará al motor o proveedor OpenSSL, según lo especificado por --private-key-source= como una tupla "tipo:nombre", como "engine:pkcs11".

Añadido en la versión 257.

--signature=RUTA

Firma PKCS#1 de entrada para el comando pkcs7.

Añadido en la versión 258.

--content=RUTA

Datos de entrada que corresponden a la firma PKCS#1 para el comando pkcs7, utilizados para generar firmas PKCS#7 en línea (es decir, no "separadas").

Añadido en la versión 258.

--hash-algorithm=ALGORITMO

Algoritmo de hash utilizado para generar la firma PKCS#1 para el comando pkcs7. Debe ser un algoritmo de digestos de openssl válido; use ""openssl list -digest-algorithms"" para ver una lista de algoritmos válidos en su sistema. Por defecto es "SHA256".

Añadido en la versión 258.

--output=RUTA

Firma PKCS#7 de salida para el comando pkcs7.

Añadido en la versión 258.

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.
