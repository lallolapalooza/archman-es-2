NOMBRE

systemd.device - Configuración de unidades de dispositivo

SINOPSIS

dispositivo.device

DESCRIPCIÓN

Un archivo de configuración de unidad cuyo nombre termina en ".device" codifica información sobre una unidad de dispositivo tal como se expone en el árbol de dispositivos de sysfs/udev(7). Esto puede usarse para definir dependencias entre dispositivos y otras unidades.

Este tipo de unidad no tiene opciones específicas. Vea systemd.unit(5) para las opciones comunes de todos los archivos de configuración de unidades. Los elementos de configuración comunes se configuran en las secciones genéricas [Unit] y [Install]. No existe una sección [Device] separada, ya que no se pueden configurar opciones específicas del dispositivo.

systemd creará dinámicamente unidades de dispositivo para todos los dispositivos del kernel que estén etiquetados con la etiqueta udev "systemd" (por defecto, todos los dispositivos de bloque y de red, y algunos otros). Tenga en cuenta que *si systemd-udevd.service no se está ejecutando, no habrá unidades de dispositivo disponibles (por ejemplo, en un contenedor típico)*.

Las unidades de dispositivo se nombran según las rutas /sys/ y /dev/ que controlan. Ejemplo: el dispositivo /dev/sda5 se expone en systemd como dev-sda5.device. Para obtener detalles sobre la lógica de escapado utilizada para convertir una ruta del sistema de archivos en un nombre de unidad, consulte systemd.unit(5).

Para etiquetar un dispositivo udev, use "TAG+="systemd"" en el archivo de reglas udev, consulte udev(7) para obtener más detalles.

systemd recargará las unidades de dispositivo cada vez que el dispositivo correspondiente genere un evento de "cambio". Otras unidades pueden usar ReloadPropagatedFrom= para reaccionar a ese evento.

DEPENDENCIAS AUTOMÁTICAS

Dependencias implícitas

Muchos tipos de unidades adquieren automáticamente dependencias de unidades de dispositivo de los dispositivos que requieren. Por ejemplo, las unidades .socket adquieren dependencias de las unidades de dispositivo de la interfaz de red especificada en BindToDevice=. De manera similar, las unidades swap y mount adquieren dependencias de las unidades que encapsulan sus dispositivos de bloque de respaldo.

Dependencias predeterminadas

No hay dependencias predeterminadas para las unidades de dispositivo.

LA BASE DE DATOS UDEV

La configuración de unidades de las unidades de dispositivo puede configurarse a través de archivos de unidad o directamente desde la base de datos udev. El gestor de servicios entiende las siguientes propiedades del dispositivo udev:

SYSTEMD_WANTS=, SYSTEMD_USER_WANTS=

Añade dependencias de tipo Wants= desde la unidad de dispositivo a las unidades especificadas. SYSTEMD_WANTS= es leído por el gestor de servicios del sistema, SYSTEMD_USER_WANTS= por las instancias del gestor de servicios de usuario. Estas propiedades pueden usarse para activar unidades arbitrarias cuando un dispositivo específico esté disponible.

Tenga en cuenta que estas y otras propiedades de dispositivo udev no se tienen en cuenta a menos que el dispositivo esté etiquetado con la etiqueta "systemd" en la base de datos udev, ya que de lo contrario el dispositivo no se expone como una unidad systemd (ver arriba).

Tenga en cuenta que systemd solo actuará sobre las dependencias Wants= cuando un dispositivo se active por primera vez. No actuará sobre ellas si se añaden a dispositivos que ya están activos. Use SYSTEMD_READY= (ver abajo) para configurar cuándo se considerará activo un dispositivo udev y, por lo tanto, cuándo se activarán las dependencias.

El valor de la propiedad especificado debe ser una lista separada por espacios de nombres de unidades válidos. Si se especifica un nombre de plantilla de unidad (es decir, un nombre de unidad que contiene un carácter "@" que indica un nombre de unidad a usar para la instanciación múltiple, pero con un nombre de instancia vacío después del "@"), se instanciará automáticamente por la ruta "sysfs" del dispositivo (es decir: la ruta se escapa y se inserta como nombre de instancia en el nombre de la plantilla de unidad). Esto es útil para instanciar una plantilla de unidad específica una vez por cada dispositivo que aparece y que coincide con propiedades específicas.

SYSTEMD_ALIAS=

Añade un alias adicional a la unidad de dispositivo. Debe ser una ruta absoluta que se transforma automáticamente en un nombre de unidad. (Ver arriba).

SYSTEMD_READY=

Si se establece en 0, systemd considerará este dispositivo desconectado incluso si aparece en el árbol udev. Si esta propiedad no está establecida o está establecida en 1, el dispositivo se considerará conectado si es visible en el árbol udev.

Esta opción es útil para dispositivos que inicialmente aparecen en un estado no inicializado en el árbol, y para los cuales se genera un evento de "cambio" en el momento en que están completamente configurados. Tenga en cuenta que SYSTEMD_WANTS= (ver arriba) no se activa mientras SYSTEMD_READY=0 esté establecido para un dispositivo.

ID_MODEL_FROM_DATABASE=, ID_MODEL=

Si se establece, esta propiedad se utiliza como cadena de descripción para la unidad de dispositivo.

OPCIONES

Los archivos de unidad de dispositivo pueden incluir las secciones [Unit] y [Install], que se describen en systemd.unit(5). No se admiten opciones específicas para este tipo de archivo.
