NOMBRE

systemd-getty-generator - Generador para habilitar instancias de getty en la consola

SINOPSIS

/usr/lib/systemd/system-generators/systemd-getty-generator

DESCRIPCIÓN

systemd-getty-generator es un generador que instancia automáticamente serial-getty@.service en las consolas del kernel, si estas pueden funcionar como ttys y no son proporcionadas por el subsistema de consola virtual. También instanciará instancias de serial-getty@.service para consolas de virtualizador, si se detecta ejecución en un entorno virtualizado. Si se detecta ejecución en un entorno de contenedor, habilitará en su lugar console-getty.service para /dev/console, e instancias de container-getty@.service para ttys de contenedor adicionales según lo solicitado por el administrador del contenedor (ver Interfaz de Contenedor[1]). Esto debería asegurar que al usuario se le muestre un prompt de inicio de sesión en el lugar correcto, independientemente del entorno en el que se inicie el sistema. Por ejemplo, es suficiente redirigir la consola del kernel con un argumento de línea de comandos del kernel como console= para obtener tanto mensajes del kernel como un prompt de getty en un TTY serial. Ver Los parámetros de línea de comandos del kernel[2] para más información sobre el parámetro del kernel console=.

systemd-getty-generator implementa systemd.generator(7).

Se puede encontrar más información sobre la configuración de gettys en systemd para Administradores, Parte XVI: Gettys en Consolas Seriales (y en otros lugares)[3].

LÍNEA DE COMANDOS DEL KERNEL

systemd-getty-generator entiende los siguientes parámetros de kernel-command-line(7):

systemd.getty_auto=

Esta opción de línea de comandos del kernel puede usarse para controlar el modo de ejecución del generador. Acepta un argumento booleano opcional. Desde la v258, también acepta una lista separada por comas de valores especiales: "credential", "container", "console", y "builtin".

Cuando se especifica "credential", se analizarán las dos credenciales getty.ttys.serial y getty.ttys.container. Ver la sección Credenciales del Sistema a continuación para más detalles.

Cuando se especifica "container", se habilitarán console-getty.service y container-getty@.service cuando el sistema se esté ejecutando en un contenedor. Esta opción se ignorará cuando el sistema no esté en un contenedor.

Cuando se especifica "console", se habilitarán serial-getty@.service para las consolas del kernel activas. Esta opción se ignorará cuando el sistema se esté ejecutando en un contenedor.

Cuando se especifica "builtins", se habilitarán serial-getty@.service para las consolas de virtualizador disponibles. Esta opción se ignorará cuando el sistema se esté ejecutando en un contenedor.

Cuando es sí, las cuatro opciones anteriores se habilitarán. Cuando es no, todas las opciones se deshabilitarán y no se habilitará ningún servicio. Cuando la opción de línea de comandos del kernel se especifica sin argumento, por defecto es sí. El generador está habilitado por defecto, y se puede usar un valor falso para deshabilitarlo.

Añadido en la versión 250.

ENTORNO

$SYSTEMD_GETTY_AUTO

Esta variable de entorno puede usarse para controlar el modo de ejecución del generador. Acepta el mismo valor que la opción de línea de comandos del kernel systemd.getty_auto=.

Añadido en la versión 250.

CREDENCIALES DEL SISTEMA

getty.auto

La credencial del sistema puede usarse para controlar el modo de ejecución del generador. Acepta el mismo valor que la opción de línea de comandos del kernel systemd.getty_auto=.

Añadido en la versión 258.

getty.ttys.serial, getty.ttys.container

Estas credenciales del sistema pueden usarse para iniciar prompts de inicio de sesión adicionales en TTYs seleccionados. Las dos credenciales deben contener una lista separada por saltos de línea de nombres de TTY para iniciar instancias de serial-getty@.service (en el caso de getty.ttys.serial) y container-getty@.service (en el caso de getty.ttys.container). Cualquier línea que empiece con "#" será ignorada.

Añadido en la versión 254.
