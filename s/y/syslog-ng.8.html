NOMBRE

syslog-ng - aplicación de registro del sistema syslog-ng

SINOPSIS

syslog-ng [opciones]

DESCRIPCIÓN

Esta página del manual es solo un resumen.

La aplicación syslog-ng OSE es una aplicación de registro del sistema flexible y altamente escalable. Típicamente, syslog-ng OSE se utiliza para gestionar mensajes de registro e implementar un registro centralizado, donde el objetivo es recopilar los mensajes de registro de varios dispositivos en un único servidor de registro central. Los diferentes dispositivos - llamados clientes syslog-ng OSE - ejecutan todos syslog-ng OSE y recopilan los mensajes de registro de las diversas aplicaciones, archivos y otras fuentes. Los clientes envían todos los mensajes de registro importantes al servidor remoto syslog-ng OSE, donde el servidor los clasifica y almacena.

OPCIONES

--caps
Ejecuta el proceso syslog-ng OSE con los indicadores de capacidades POSIX especificados.

  • Si la opción --no-caps no está activada, syslog-ng OSE ha sido compilado con la opción de compilación --enable-linux-caps, y el host soporta CAPSYSLOG, syslog-ng OSE utiliza las siguientes capacidades: "capnetbindservice, capnetbroadcast, capnetraw, capdacreadsearch, capdacoverride, capchown, capfowner=p capsyslog=ep"
  • Si la opción --no-caps no está activada, y el host no soporta CAPSYSLOG, syslog-ng OSE utiliza las siguientes capacidades: "capnetbindservice, apnetbroadcast, capnetraw, capdacreadsearch, capdacoverride, capchown, capfowner=p capsys_admin=ep"

Por ejemplo:

    /usr/sbin/syslog-ng -Fv --caps cap_sys_admin,cap_chown,cap_dac_override,cap_net_bind_service,cap_fowner=pi

NOTA: Las capacidades no distinguen mayúsculas de minúsculas, el siguiente comando también es válido:

    /usr/sbin/syslog-ng -Fv --caps CAP_SYS_ADMIN,CAP_CHOWN,CAP_DAC_OVERRIDE,CAP_NET_BIND_SERVICE,CAP_FOWNER=pi

Para obtener detalles sobre los indicadores de capacidad, consulte las siguientes páginas del manual: cap_from_text(3) y capabilities(7)

--cfgfile <archivo> o -f <archivo>
Utiliza el archivo de configuración especificado.

--chroot <directorio> o -C <directorio>
Cambia la raíz al directorio especificado. El archivo de configuración se lee después de chrootear, por lo que el archivo de configuración debe estar disponible dentro del chroot. De esta manera, también es posible recargar la configuración de syslog-ng OSE después de chrootear. Sin embargo, tenga en cuenta que las opciones --user y --group se resuelven antes de chrootear.

--check-startup
Disponible en las versiones 4.5 y posteriores de syslog-ng OSE.
Esta opción se puede utilizar para realizar una inicialización completa de la configuración con syslog-ng OSE, y luego salir con el código de salida que indica el resultado. Esta opción también se puede utilizar para comprobar si la configuración es semánticamente válida y si syslog-ng OSE puede iniciarse realmente. (La opción --syntax-only solo detecta errores sintácticos.)
Además, --check-startup también se puede utilizar en un entorno de Kubernetes, para ejecutarlo como un contenedor dedicado de verificación de configuración.

NOTA: Es muy probable que esta opción falle si otra instancia de syslog-ng OSE se está ejecutando en segundo plano, ya que inicializa varios procesos, como los oyentes de red. En tal caso, la dirección de red ya estaría en uso.

--control <archivo> o -c <archivo>
Establece la ubicación del socket de control de syslog-ng OSE. Valor por defecto: /var/run/syslog-ng.ctl

--debug o -d
Inicia syslog-ng OSE en modo de depuración.

--default-modules
Una lista separada por comas de los módulos que se cargan automáticamente. Los módulos que no se cargan automáticamente se pueden cargar incluyendo la declaración @module <nombre_del_módulo> en el archivo de configuración de syslog-ng OSE. Disponible solo en la versión 4.1 y posteriores de syslog-ng OSE.

--enable-core
Permite a syslog-ng OSE escribir archivos core en caso de fallo para ayudar con el soporte y la depuración.

--fd-limit <número>
Establece el número mínimo de descriptores de archivo (fd) requeridos. Esto define cuántos archivos puede mantener abiertos simultáneamente syslog-ng OSE.
Valor por defecto: 4096.

NOTA: Esto no anula la configuración ulimit global del host.

--foreground o -F
No demonizar, ejecutar en primer plano. Al ejecutarse en primer plano, syslog-ng OSE se inicia desde el directorio actual (${CWD}) para que pueda crear archivos core (normalmente, syslog-ng OSE se inicia desde ${PREFIX}/var).

--group <grupo> o -g <grupo>
Cambia al grupo especificado después de inicializar el archivo de configuración.

--help o -h
Muestra un breve mensaje de ayuda.

--module-registry
Muestra la lista y descripción de los módulos disponibles.

NOTA: No todos estos módulos se cargan automáticamente, solo los especificados en la opción --default-modules. Disponible solo en syslog-ng OSE 4.0 y posteriores.

--no-caps
Ejecuta syslog-ng OSE como root, sin soporte de capacidades. Este es el comportamiento por defecto. En Linux, es posible ejecutar syslog-ng OSE como no-root con soporte de capacidades si syslog-ng OSE fue compilado con la opción --enable-linux-caps habilitada. (Ejecute syslog-ng --version para mostrar la lista de parámetros de compilación habilitados.)
Para ejecutar syslog-ng OSE con capacidades específicas, use la opción --caps.

--persist-file <archivo-persistencia> o -R <archivo-persistencia>
Establece la ruta y el nombre del archivo syslog-ng.persist donde se almacenan las opciones y los datos persistentes.

--pidfile <archivo-pid> o -p <archivo-pid>
Establece la ruta al archivo PID donde se almacena el pid del proceso principal.

--preprocess-into <archivo-salida>
Después de procesar el archivo de configuración y resolver los archivos incluidos y las variables, escribe la configuración resultante en el archivo de salida especificado. Disponible solo en syslog-ng OSE 4.0 y posteriores.

--process-mode <modo>
Establece cómo ejecutar syslog-ng OSE: en primer plano (principalmente para depuración), en segundo plano como demonio, o en modo de segundo plano seguro. Por defecto, syslog-ng OSE se ejecuta en modo de segundo plano seguro. Este modo crea un proceso supervisor llamado syslog-ng OSE supervisor, que reinicia syslog-ng OSE si falla.

--stderr o -e
Registra los mensajes internos de syslog-ng OSE en stderr. Principalmente para fines de depuración en conjunción con la opción --foreground. Si no se especifica, syslog-ng OSE registrará dichos mensajes en su fuente interna.

--syntax-only o -s
Verifica que el archivo de configuración sea sintácticamente correcto y sale.

--user <usuario> o -u <usuario>
Cambia al usuario especificado después de inicializar el archivo de configuración (y opcionalmente chrootear).

NOTA: No es posible recargar la configuración de syslog-ng OSE si el usuario especificado no tiene privilegios para crear el archivo /dev/log.

--verbose o -v
Habilita el registro detallado utilizado para solucionar problemas de syslog-ng OSE.

--version o -V
Muestra el número de versión y la información de compilación, así como la lista y una breve descripción de los módulos disponibles. Para obtener una descripción detallada de los módulos disponibles, consulte la opción --module-registry.

NOTA: No todos estos módulos se cargan automáticamente, solo los especificados en la opción --default-modules.

--worker-threads
Establece el número de hilos de trabajo que syslog-ng OSE puede utilizar, incluyendo el hilo principal de syslog-ng OSE.
Consulte la Guía del administrador de syslog-ng OSE[1] para obtener detalles.

NOTA: Ciertas operaciones en syslog-ng OSE pueden usar hilos que no están limitados por esta opción. Esta configuración solo tiene efecto cuando syslog-ng OSE se ejecuta en modo multihilo. Disponible solo en syslog-ng OSE 4.0 y posteriores.
