SYD(1) Manual de Comandos Generales SYD(1)

NOMBRE

syd - Kernel de aplicación robusto

SINOPSIS

syd [-acefhlmpqxEPV] [--] {comando [argumento...]}

syd [-acefhlmpqxEPV] [--] {biblioteca.so}

syd --api

syd --check

syd --el

syd --sh

DESCRIPCIÓN

Syd es una utilidad que aprovecha la llamada al sistema seccomp(2) para aislar procesos en sistemas Linux versión 5.19 o posterior. Permite un control detallado sobre el acceso al sistema de archivos y a la red de un proceso sin requerir privilegios de root. Syd está diseñado para ser fácil de usar en una amplia gama de arquitecturas, incluyendo x86, x86_64, x32, armv7, aarch64, loongarch64, mips, mips64, mips64el, ppc, ppc64, ppc64le, riscv64 y s390x, encarnando el principio de proporcionar un control de acceso simple, flexible y robusto a los usuarios de Linux.

La funcionalidad principal de Syd gira en torno a la restricción del acceso a recursos de un proceso a través de varios mecanismos:

  • Montajes de unión (Bind Mounts): Utilizados dentro de un espacio de nombres de montaje para imponer restricciones a nivel del Sistema de Archivos Virtual (VFS), como solo lectura, nodev, noexec, nosuid y nosymfollow.
  • Landlock: Emplea restricciones de ruta de solo lectura y lectura/escritura a nivel del kernel.
  • seccomp-bpf: Aplica filtros de usuario Secure Computing para el aislamiento en el espacio del kernel.
  • seccomp-notify: Permite el aislamiento en el espacio del kernel con un fallback al espacio de usuario para desreferenciar argumentos de puntero en llamadas al sistema, incluyendo nombres de ruta y direcciones de red. Las comprobaciones de acceso utilizan patrones de estilo de shell de UNIX y notación CIDR, negando por defecto las llamadas al sistema con EACCES mientras se intenta emular llamadas exitosas para mitigar vectores de ataque Tiempo de Verificación a Tiempo de Uso (TOCTOU).

Los prerrequisitos para Syd incluyen un kernel Linux que soporte las llamadas al sistema pidfd_getfd(2) y pidfd_send_signal(2), la operación SECCOMP_USER_NOTIF_FLAG_CONTINUE en la instalación de Secure Computing, y preferiblemente la opción del kernel CONFIG_CROSS_MEMORY_ATTACH. Para la emulación de llamadas al sistema, Syd utiliza la operación seccomp SECCOMP_IOCTL_NOTIF_ADDFD. Además, Syd establece el flag SECCOMP_FILTER_FLAG_WAIT_KILLABLE_RECV para manejar correctamente las interrupciones durante el rastreo. Si bien se requiere Linux versión 5.19 o posterior, para el soporte de Landlock Syd requiere un kernel configurado con la opción CONFIG_LSM_LANDLOCK que soporte la versión 3 de la ABI de Landlock, con syd-lock(1) disponible como programa auxiliar para verificar el soporte del kernel. Se recomiendan las opciones del kernel Linux CONFIG_KCMP y CONFIG_UNIX_DIAG.

Syd está comprometido a mantener rigurosos estándares de seguridad al delimitar estrictamente el espacio de recursos accesible a los procesos aislados. En la sección SEGURIDAD de la página del manual syd(7), se proporciona una enumeración detallada de las medidas de endurecimiento de seguridad implementadas por Syd, junto con configuraciones opcionales para relajar ciertas restricciones. Esta flexibilidad permite acomodar una diversa gama de procesos dentro del entorno del sandbox.

El enfoque de la seguridad dentro de Syd está diseñado metódicamente para equilibrar una protección robusta con la flexibilidad operativa, asegurando que los usuarios tengan la capacidad de ajustar los mecanismos de aislamiento para cumplir con requisitos específicos. Al ofrecer información sobre las técnicas de endurecimiento y las opciones de personalización, Syd capacita a los usuarios para navegar eficazmente el equilibrio entre seguridad y funcionalidad.

OPCIONES

Se entienden las siguientes opciones:

-h, --help Muestra el uso y sale.
-V, --version Muestra la versión y sale.
-C, --check Imprime información de soporte de aislamiento sobre el sistema actual y sale.
-v, --verbose Sea verboso, equivalente a log/verbose:true comando.
-c Compatibilidad con shell de inicio de sesión
Hace que el comando se ejecute bajo un shell con el perfil del usuario.
El shell a ejecutar es /bin/sh por defecto.
Utilice la variable de entorno SYD_SHELL para anular.
-f Compatibilidad con shell de inicio de sesión.
Hace que Syd analice el perfil del usuario al inicio.
-l, --login Compatibilidad con shell de inicio de sesión
Hace que Syd analice el perfil del usuario al inicio.
-q Habilita el modo de arranque rápido para tiempos de inicio más rápidos.
Esto debe pasarse como la primera opción o será ignorado.
Consulte la explicación de la variable de entorno SYD_QUICK_BOOT para la seguridad de esta opción.
-x Habilita el modo trace o "dry run".
En este modo, Syd permitirá llamadas al sistema incluso si generan violaciones de acceso.
Este modo con registro extendido puede usarse para construir perfiles de aislamiento de forma automatizada.
Consulte pandora(1), que es una herramienta que utiliza el modo de rastreo de Syd para generar perfiles de sandbox automáticamente.
-m config Configura el sandbox durante la inicialización, puede repetirse.
-p nombre Utiliza un perfil de sandbox durante la inicialización, puede repetirse.
-P ruta Ejecuta un archivo de configuración durante la inicialización, puede repetirse.
-a alias Establece un alias del comando. Se pasa como argv[0] al programa.
-e Use -e var=val para poner var=val en el entorno para el comando, puede repetirse.
Use -e var para eliminar var del entorno para el comando, puede repetirse.
Use -e var= para pasar una variable de entorno insegura, puede repetirse.
-E modo Exporta reglas de computación segura con el formato dado a la salida estándar y sale.
El modo debe ser uno de bpf o pfc:
bpf, también conocido como Berkeley Packet Filter, es un formato binario legible por máquina, mientras que
pfc, también conocido como Pseudo Filter Code, es un formato textual legible por humanos.
--api Salida de la especificación de la API de syd(2) en formato JSON.
Esta especificación está destinada a facilitar la generación de enlaces de lenguaje.
Esta especificación también está disponible a través de la ruta mágica /dev/syd.
--el Salida syd.el, que es la implementación en Emacs Lisp de la interfaz stat(2) de Syd.
Este archivo también está disponible a través de la ruta mágica /dev/syd.el.
--sh Salida de un script de shell que define la función auxiliar esyd.
Este archivo también está disponible a través de la ruta mágica /dev/syd.sh.
Funciona con POSIX sh, bash y zsh.
Puede usar eval "$(syd --sh)" en su archivo de inicialización del shell.

INVOCCIÓN

Syd puede ejecutar un comando con los argumentos especificados o cargar una biblioteca dinámica y ejecutar la función syd_main() de ella. En caso de que el primer argumento que no sea una opción termine con el sufijo .so, se espera que sea la ruta de una biblioteca dinámica a cargar. La biblioteca dinámica se carga al inicio del proceso Syd de forma temprana, de modo que incluso su sistema de archivos propietario pueda montarse como noexec, utilizando por ejemplo bind+/:/:noexec. Esto permite crear un entorno muy restringido

Entorno para que la función de biblioteca se ejecute en su interior. La función syd_main() no debe tener argumentos y debe devolver un entero. Este entero será el valor de salida del proceso Syd. Tenga en cuenta que cargar una biblioteca requiere cuidado, ya que sus constructores se ejecutarán sin aislamiento.

AMBIENTE

SYD_ID Especificar el ID del sandbox como 128 caracteres hexadecimales en minúsculas.
Los primeros 32 caracteres no pueden ser todos ceros.
Si esta variable no la establece el usuario al inicio,
Syd la genera hasheando bytes de AT_RANDOM con SHA3-512.
Syd entra en pánico si el usuario pasa el valor en formato incorrecto.
SYD_IPC Especificar la dirección del socket UNIX para la configuración en tiempo de ejecución.
Equivalente al comando ipc, consulte la página del manual de syd(2).
El comando ipc tiene precedencia sobre esta variable de entorno.
SYD_LOG Establecer el nivel de registro a emerg, alert, crit, error, warn, notice, info o debug.
SYD_LOG_BUF_LEN Establecer la capacidad del búfer de anillo de syslog(2).
Por defecto, el búfer de anillo se asigna en la pila con un tamaño dependiente de la arquitectura.
Establecer esta variable hace que Syd asigne el búfer de anillo en el heap con el tamaño especificado por el usuario.
Tenga en cuenta que el valor se analiza utilizando el crate parse-size.
Consulte su documentación para obtener información sobre el formato.
SYD_LOG_FD Establecer el descriptor de archivo de registro, por defecto es stderr(3).
Se permiten valores negativos como atajo para deshabilitar el registro.
Los valores positivos deben ser FDs válidos o Syd saldrá con EBADF.
SYD_PDS Establecer la señal de muerte del padre usando el nombre o número de señal.
SYD_PID_FN Establecer el nombre del archivo de PID, hace que Syd escriba su ID de proceso en este archivo al inicio.
El archivo no debe existir y se creará con permisos de lectura solo para el usuario.
SYD_NPROC Establecer el número de hilos del manejador de llamadas al sistema principales, por defecto es el número de CPUs.
El número debe ser al menos 1.
SYD_NPROC_MAX Establecer el número máximo de hilos del manejador de llamadas al sistema, por defecto es usize::MAX.
El número debe ser mayor que SYD_NPROC.
SYD_SHELL Elegir el shell a iniciar cuando se invoca como shell de inicio de sesión, por defecto es /bin/sh.
SYD_DUMP_SCMP Exportar las reglas de computación segura con el formato dado, equivalente a la opción -E.
SYD_SKIP_SCMP Omitir el aislamiento de seccomp(2) de los hilos por Syd.
Esto es inseguro y solo debe usarse para perfilado.
SYD_FORCE_NO_SYMLINKS Forzar el flag de resolución RESOLVE_NO_SYMLINKS en el límite de open(2).
Equivalente a trace/force_no_symlinks:1.
SYD_FORCE_NO_MAGICLINKS Forzar el flag de resolución RESOLVE_NO_MAGICLINKS en el límite de open(2).
Equivalente a trace/force_no_magiclinks:1.
SYD_FORCE_NO_XDEV Forzar el flag de resolución RESOLVE_NO_XDEV en el límite de open(2).
Equivalente a trace/force_no_xdev:1.
SYD_FORCE_CLOEXEC Forzar el cierre al ejecutar para descriptores de archivo.
Equivalente a trace/force_cloexec:1.
SYD_FORCE_RAND_FD Usar descriptores de archivo aleatorios para endurecer contra la reutilización de FD.
Equivalente a trace/force_rand_fd:1.
SYD_FORCE_RO_OPEN Rechazar la creación y escritura de llamadas a open(2).
Equivalente a trace/force_ro_open:1.
SYD_FORCE_TTY Forzar salida TTY que es JSON con formato bonito.
SYD_QUIET_TTY Forzar salida TTY silenciosa que es JSON orientado a líneas.
SYD_PROXY_HOST Anular el valor por defecto de proxy/ext/host,
Si el valor es un nombre de host y no una dirección IP,
Syd resuelve este nombre de host al inicio y selecciona una IP de respuesta al azar.
SYD_PROXY_PORT Anular el valor por defecto de proxy/ext/port.
SYD_PROXY_UNIX Establecer el valor por defecto para proxy/ext/unix que anula proxy/ext/host.
SYD_QUICK_BOOT Habilitar el modo de arranque rápido, esto hace que Syd arranque notablemente más rápido:
Sin embargo, el arranque rápido elimina una capa de defensa contra algunas rupturas de contenedores.
Use esto si ejecuta frecuentemente syd(1) o syd-oci(1),
como hace Exherbo Linux durante cave-generate-metadata(1).
SYD_NO_CROSS_MEMORY_ATTACH Deshabilitar la adjunción de memoria cruzada y usar proc_pid_mem(5) incondicionalmente.
SYD_PROC_PID_MEM_FALLBACK Por defecto, Syd utiliza la adjunción de memoria cruzada incondicionalmente.
Establecer esta variable hace que Syd recurra a proc_pid_mem(5) automáticamente,
si process_vm_readv(2) o process_vm_writev(2) falla con ENOSYS,
lo que indica que falta soporte del kernel para estas llamadas al sistema.
La variable SYD_NO_CROSS_MEMORY_ATTACH tiene precedencia sobre esta variable.
SYD_ASSUME_KERNEL Anular uname(2) para obtener la versión del kernel de Linux del host utilizada para la detección de características.
Syd informa la versión mayor y menor del kernel en el límite de uname(2) dentro del sandbox.
La versión micro se aleatoriza por ejecución de Syd para prevenir fugas de información.
SYD_PALUDIS_LPATH Anular la opción sandbox/lpath para el perfil paludis, por defecto está desactivada.
SYD_PALUDIS_IOCTL Anular la opción sandbox/ioctl para el perfil paludis, por defecto está desactivada.
SYD_USER_LPATH Anular la opción sandbox/lpath para el perfil user, por defecto está activada.
CARGO_BIN_EXE_syd-pty Ruta a la utilidad syd-pty(1). Por defecto es buscar en PATH.
CARGO_BIN_EXE_syd-tor Ruta a la utilidad syd-tor(1). Por defecto es buscar en PATH.

REGISTRO

Existen ocho niveles de registro: emerg, alert, crit, error, warn, notice, info y debug. El nivel de registro se puede establecer con la variable de entorno SYD_LOG. Los registros van a la salida de error estándar a menos que se especifique un descriptor de archivo con la variable de entorno SYD_LOG_FD. Los mensajes de severidad warn y superior también se envían a syslog(3) a menos que se establezca la variable de entorno SYD_NO_SYSLOG.

Syd registra en líneas JSON. A continuación se muestra una lista de algunas de las claves utilizadas comúnmente y sus significados:

CLAVE DESCRIPCIÓN
ctx Contexto de la entrada de registro, por ejemplo, access, safesetid, segvguard, etc.
cap Capacidad del sandbox
act Acción del sandbox: Allow, Warn, Deny, Panic, Stop, Abort, Kill o Exit
pid ID del proceso
path Argumento de ruta de la llamada al sistema
addr Argumento de dirección de red de la llamada al sistema, por ejemplo, 127.0.0.1!22
unix Argumento de dirección de socket UNIX de la llamada al sistema
ipv Versión IP de la dirección de red en el campo addr (4 o 6)
abs Verdadero si la dirección del socket en el campo unix es un socket UNIX abstracto
sys Nombre de la llamada al sistema
arch Arquitectura de la llamada al sistema
args Argumentos de la llamada al sistema
src Origen de la llamada al sistema en formato path+offset
Use, por ejemplo, objdump -D path | grep offset para mostrar la instrucción de la llamada al sistema
cmd Nombre del proceso o línea de comandos si la salida del registro es una TTY o si la característica log está habilitada
cwd Directorio de trabajo actual del proceso
uid ID de usuario
time Marca de tiempo en formato compatible con ISO8601, actualmente YYYYMMDDThhmmssZ
El formato de hora puede cambiar pero siempre será compatible con ISO8601.
Los errores de formato recurren a imprimir la marca de tiempo como un entero.
err Error syd(1) - Arch manual pages

LOGGING

Syd has logging capabilities. The following log levels are supported:

error Errors encountered while running the sandbox.
warn Warnings which may be of interest but don't prevent the sandbox from running.
info General information about the sandbox execution.
debug Debug messages, useful for diagnosing problems.
trace Trace messages, even more detailed than debug. Useful for understanding the sandbox flow.
msg Miscellaneous informational messages, mostly used with the info log level
tip Informational messages on how to configure the sandbox

EXIT CODES

Syd exits with the same exit code as the sandbox process itself. If the sandbox process exits with a signal, Syd exits with 128 plus the value of the signal. In case there was an error in spawning or waiting for the sandbox process, Syd exits with errno indicating the error condition. E.g. syd true returns 0, syd false returns 1, and syd -- syd true returns 16 which stands for EBUSY which means Device or resource busy indicating there is already a secure computing filter loaded.
