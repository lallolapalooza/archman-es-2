NOMBRE

systemd-mount, systemd-umount - Establecer y destruir puntos de montaje o montaje automático transitorios

SINOPSIS

systemd-mount [OPCIONES...] QUÉ [DÓNDE]

systemd-mount [OPCIONES...] --tmpfs [NOMBRE] DÓNDE

systemd-mount [OPCIONES...] --list

systemd-mount [OPCIONES...] --umount QUÉ|DÓNDE...

DESCRIPCIÓN

systemd-mount puede usarse para crear e iniciar una unidad .mount o .automount transitoria del sistema de archivos QUÉ en el punto de montaje DÓNDE.

En muchos aspectos, systemd-mount es similar al comando de bajo nivel mount(8), sin embargo, en lugar de ejecutar la operación de montaje directa e inmediatamente, systemd-mount la programa a través de la cola de trabajos del gestor de servicios, de modo que pueda invocar dependencias adicionales (como montajes padre, o un verificador de sistemas de archivos para ejecutar a priori), y pueda hacer uso de la lógica de montaje automático.

El comando toma uno o dos argumentos. Si solo se especifica un argumento, este debe referirse a un dispositivo de bloque o a un archivo regular que contenga un sistema de archivos (por ejemplo, "/dev/sdb1" o "/ruta/a/disco.img"). El dispositivo de bloque o el archivo de imagen se examinan para obtener una etiqueta de sistema de archivos y metadatos adicionales, y se montan en un directorio debajo de /run/media/system/ cuyo nombre se genera a partir de la etiqueta del sistema de archivos. En este modo, el dispositivo de bloque o el archivo de imagen deben existir en el momento de la invocación del comando, para que pueda ser examinado. Si se detecta que el dispositivo es un dispositivo de bloque extraíble (por ejemplo, una unidad USB), se crea un punto de montaje automático en lugar de un punto de montaje regular (es decir, la opción --automount= está implícita, ver más abajo). Si se especifica la opción --tmpfs, entonces el argumento se interpreta como la ruta donde se montará el nuevo sistema de archivos temporal.

Si se especifican dos argumentos, el primero indica el origen del montaje (el QUÉ) y el segundo indica la ruta donde montarlo (el DÓNDE). En este modo no se intenta examinar el origen, y un nodo de dispositivo de respaldo no tiene que existir. Sin embargo, si este modo se combina con --discover, se habilita el examen del nodo del dispositivo para metadatos adicionales y – de manera muy similar al caso de un solo argumento discutido anteriormente – el dispositivo especificado debe existir en el momento de la invocación del comando.

Use el comando --list para mostrar una tabla concisa de todos los dispositivos de bloque locales conocidos con sistemas de archivos que pueden montarse con este comando.

systemd-umount se puede usar para desmontar un punto de montaje o montaje automático. Es lo mismo que systemd-mount --umount.

OPCIONES

Se entienden las siguientes opciones:

--no-block

No espere de forma síncrona a que la operación solicitada finalice. Si esto no se especifica, la tarea se verificará, se pondrá en cola y systemd-mount esperará hasta que se complete el inicio de la unidad de montaje o montaje automático. Al pasar este argumento, solo se verifica y se pone en cola.

Añadido en la versión 232.

-l, --full

No truncar la salida cuando se especifica --list.

Añadido en la versión 245.

--no-pager

No canalizar la salida a un paginador.

--no-legend

No imprimir la leyenda, es decir, las cabeceras de las columnas y el pie de página con sugerencias.

--no-ask-password

No consultar al usuario para autenticación en operaciones privilegiadas.

--json=MODO

Muestra la salida formateada como JSON. Espera uno de "short" (para la salida más corta posible sin espacios en blanco redundantes ni saltos de línea), "pretty" (para una versión bonita de la misma, con sangría y saltos de línea) o "off" (para desactivar la salida JSON, el valor predeterminado).

--quiet, -q

Suprime la salida informativa adicional mientras se ejecuta.

Añadido en la versión 232.

--discover

Habilita el examen del origen del montaje. Este interruptor está implícito si se especifica un solo argumento en la línea de comandos. Si se pasa, se leen metadatos adicionales del dispositivo para mejorar la unidad a crear. Por ejemplo, una cadena descriptiva para las unidades transitorias se genera a partir de la etiqueta del sistema de archivos y el modelo del dispositivo. Además, si se detecta un dispositivo de bloque extraíble (por ejemplo, una unidad USB), se crea una unidad de montaje automático en lugar de una unidad de montaje regular, con un tiempo de inactividad corto, para garantizar que el sistema de archivos se coloque en un estado limpio rápidamente después de cada acceso.

Añadido en la versión 232.

--type=, -t

Especifica el tipo de sistema de archivos a montar (por ejemplo, "vfat" o "ext4"). Si se omite o se establece en "auto", el tipo de sistema de archivos se determina automáticamente.

Añadido en la versión 232.

--options=, -o

Opciones de montaje adicionales para el punto de montaje.

Añadido en la versión 232.

--owner=USUARIO

Permite que el usuario especificado USUARIO sea el propietario del sistema de archivos montado. Esto se hace añadiendo las opciones uid= y gid= a la lista de opciones de montaje. Solo ciertos sistemas de archivos soportan esta opción.

Añadido en la versión 237.

--fsck=

Toma un argumento booleano, por defecto está activado. Controla si se debe realizar una verificación del sistema de archivos inmediatamente antes de la operación de montaje. En el caso de montaje automático (ver --automount= abajo) la verificación se realizará en el momento del primer acceso al dispositivo, lo que podría retrasar ligeramente el acceso.

Añadido en la versión 232.

--description=

Proporciona una descripción para la unidad de montaje o montaje automático. Ver Description= en systemd.unit(5).

Añadido en la versión 232.

--property=, -p

Establece una propiedad de unidad para la unidad de montaje que se crea. Esto toma una asignación en el mismo formato que el comando set-property de systemctl(1).

Añadido en la versión 232.

--automount=

Toma un argumento booleano. Controla si se crea un punto de montaje automático o un punto de montaje regular. Si es verdadero, se crea un punto de montaje automático que está respaldado por el sistema de archivos real en el momento del primer acceso. Si es falso, se crea un punto de montaje simple que está respaldado por el sistema de archivos real inmediatamente. Los puntos de montaje automático tienen el beneficio de que el sistema de archivos permanece desmontado y, por lo tanto, en un estado limpio hasta que se accede a él por primera vez. En el modo de montaje automático, el interruptor --timeout-idle-sec= (ver más abajo) puede usarse para asegurar que el punto de montaje se desmonte automáticamente después del último acceso y de que haya transcurrido un período de inactividad.

Si este interruptor no se especifica, el valor predeterminado es falso. Si no se especifica y se usa --discover (o solo se pasa un argumento, que implica --discover, ver más arriba), y se detecta que el dispositivo de bloque del sistema de archivos es extraíble, se establece en verdadero, para aumentar la probabilidad de que el sistema de archivos esté en un estado completamente limpio si el dispositivo se desconecta abruptamente.

Añadido en la versión 232.

-A

Equivalente a --automount=yes.

Añadido en la versión 232.

--timeout-idle-sec=

Toma un valor de tiempo que controla el tiempo de espera inactivo en el modo de montaje automático. Si se establece en "infinity" (el valor predeterminado), no se realizan desmontajes automáticos. De lo contrario, el sistema de archivos que respalda el punto de montaje automático se desconecta después del último acceso y de que haya transcurrido el tiempo de espera inactivo. Consulte systemd.time(7) para obtener detalles sobre la sintaxis de tiempo admitida. Esta opción no tiene efecto si solo se establece un montaje regular y no se utiliza el montaje automático.

Tenga en cuenta que si se utiliza --discover (o solo se pasa un argumento, que implica --discover, ver más arriba), y se detecta que el dispositivo de bloque del sistema de archivos es extraíble, se implica --timeout-idle-sec=1s.

Añadido en la versión 232.

--automount-property=

Similar a --property=, pero aplica propiedades adicionales a la unidad de montaje automático creada, en lugar de a la unidad de montaje.

Añadido en la versión 232.

--bind-device

systemd-mount(1) - Arch Linux Manual Pages

Controla si la unidad de montaje/montaje automático generada será vinculada a la vida útil del dispositivo de respaldo. Esta configuración es especialmente útil en modo de montaje automático. Si se establece, las unidades se detendrán automáticamente cuando desaparezca el dispositivo de respaldo. Por defecto, la unidad de montaje automático permanece, y los accesos subsiguientes se bloquearán hasta que se vuelva a conectar el dispositivo de respaldo. Esta opción no tiene efecto en el caso de montajes que no sean de dispositivos, como montajes de red o sistemas de archivos virtuales.

Si se utiliza --discover (o solo se pasa un argumento, lo que implica --discover, véase más arriba), y se detecta que el dispositivo de bloque del sistema de archivos es extraíble, esta opción se asume.

Tenga en cuenta que las unidades de montaje por defecto obtienen una dependencia Requires= del dispositivo de respaldo. Este comportamiento se puede controlar mediante la opción de montaje x-systemd.device-bound=, véase systemd.mount(5) para más detalles. En particular, x-systemd.device-bound=no tiene precedencia sobre esta opción, lo que suprime las dependencias de dispositivo tanto en las unidades de montaje generadas como en lo que implica el gestor de servicios.

Añadido en la versión 232.

--list

En lugar de establecer un punto de montaje o montaje automático, imprime una lista concisa de dispositivos de bloque que contienen sistemas de archivos que pueden ser montados con "systemd-mount", junto con metadatos útiles como etiquetas, etc.

Añadido en la versión 232.

-u, --umount

Detiene las unidades de montaje y montaje automático correspondientes a los puntos de montaje especificados WHERE o a los dispositivos WHAT. systemd-mount con esta opción o systemd-umount puede aceptar múltiples argumentos que pueden ser puntos de montaje, dispositivos, nombres de nodo al estilo /etc/fstab, o archivos de respaldo correspondientes a dispositivos loop, como systemd-mount --umount /ruta/a/desmontar /dev/sda1 UUID=xxxxxx-xxxx LABEL=xxxxx /ruta/a/disco.img. Tenga en cuenta que cuando se especifica -H o -M, solo se admiten rutas absolutas a los puntos de montaje.

Añadido en la versión 233.

-G, --collect

Descarga la unidad transitoria después de que se complete, incluso si falló. Normalmente, sin esta opción, todas las unidades de montaje que montaron y fallaron se mantienen en memoria hasta que el usuario restablece explícitamente su estado de fallo con systemctl reset-failed o un comando equivalente. Por otro lado, las unidades que se detuvieron exitosamente se descargan inmediatamente. Si esta opción se activa, la "recolección de basura" de unidades es más agresiva, y descarga unidades independientemente de si salieron exitosamente o fallaron. Esta opción es un atajo para --property=CollectMode=inactive-or-failed, véase la explicación de CollectMode= en systemd.unit(5) para más información.

Añadido en la versión 236.

-T, --tmpfs

Crea y monta un nuevo sistema de archivos tmpfs en WHERE, con un NAME opcional que por defecto es "tmpfs".

El sistema de archivos se monta con el modo del directorio de nivel superior determinado por la configuración de umask(2) del llamador, es decir, rwxrwxrwx enmascarado por la umask del llamador. Esto coincide con lo que hace mkdir(1), pero es diferente del valor por defecto del kernel de "rwxrwxrwxt", es decir, un directorio escribible por todos con el bit sticky activado.

Añadido en la versión 255.

--canonicalize=

Controla si la ruta especificada debe ser canonicalizada en el lado del cliente antes de solicitar la operación o no. Toma un parámetro booleano, por defecto es true. Tenga en cuenta que para operaciones no locales (es decir, cuando se utilizan --machine= o ----host=) la canonicalización se desactiva implícitamente.

La canonicalización de la ruta implica la resolución de enlaces simbólicos, elementos de ruta ".." y la expansión de nodos de dispositivo estilo LABEL=/UUID=. Si la canonicalización está desactivada y la ruta contiene un elemento de enlace simbólico, "..", o una expansión LABEL=/UUID=/... la operación fallará.

Añadido en la versión 258.

--user

Habla con el gestor de servicios del usuario que llama, en lugar del gestor de servicios del sistema.

--system

Habla con el gestor de servicios del sistema. Esta es la opción por defecto.

-H, --host=

Ejecuta la operación de forma remota. Especifique un nombre de host, o un nombre de usuario y un nombre de host separados por "@", para conectarse. Opcionalmente, el nombre de host puede ir seguido de un puerto en el que SSH esté escuchando, separado por ":", y luego un nombre de contenedor, separado por "/", lo que conecta directamente a un contenedor específico en la máquina remota. Esto utilizará SSH para hablar con la instancia remota del gestor de máquinas. Los nombres de contenedores se pueden enumerar con machinectl -H HOST. Ponga las direcciones IPv6 entre corchetes.

-M, --machine=

Ejecuta la operación en un contenedor local. Especifique un nombre de contenedor para conectarse, opcionalmente prefijado por un nombre de usuario para conectarse y un carácter separador "@". Si se utiliza la cadena especial ".host" en lugar del nombre del contenedor, se establece una conexión con el sistema local (lo que es útil para conectarse al bus de un usuario específico: "--user --machine=lennart@.host"). Si no se utiliza la sintaxis "@", la conexión se realiza como usuario root. Si se utiliza la sintaxis "@", se puede omitir el lado izquierdo o el derecho (pero no ambos) en cuyo caso se implican el nombre de usuario local y ".host".

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.

ESTADO DE SALIDA

En caso de éxito, se devuelve 0, un código de error distinto de cero en caso contrario.

LA BASE DE DATOS DE UDEV

Si se utiliza --discover, systemd-mount respeta un par de propiedades adicionales de udev de los dispositivos de bloque:

SYSTEMD_MOUNT_OPTIONS=

Las opciones de montaje a utilizar, si no se usa --options=.

Añadido en la versión 232.

SYSTEMD_MOUNT_WHERE=

La ruta del sistema de archivos donde colocar el punto de montaje, en lugar del generado automáticamente.

Añadido en la versión 232.

EJEMPLO

Utilice una regla de udev como la siguiente para montar automáticamente todo el almacenamiento USB conectado:

ACTION=="add", SUBSYSTEMS=="usb", SUBSYSTEM=="block", ENV{ID_FS_USAGE}=="filesystem", \
        RUN{program}+="/usr/bin/systemd-mount --no-block --automount=yes --collect $devnode"
