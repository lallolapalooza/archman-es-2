SYD-SEC(1) Manual de comandos generales SYD-SEC(1)

NOMBRE

syd-sec - Imprimir bits seguros o ejecutar comando con bits seguros establecidos

SINOPSIS

syd-sec [-ahikprsxAIKPRSX] {comando [argumentos...]}

DESCRIPCIÓN

Sin argumentos, imprime información sobre los bits seguros del proceso en formato JSON compacto.

Sin comando, se pueden proporcionar una o más de las opciones de bits seguros [-aikprsx] para probar los bits seguros. Utilice las opciones en mayúsculas, [-AIKPRSX], para probar las versiones bloqueadas de los bits seguros correspondientes.

Dado un comando y argumentos, con al menos una de las opciones de bits seguros [-aikprsxAIKRSX] establecidas, los bits seguros especificados, ejecuta el comando y sale con el mismo estado.

OPCIONES

-h Muestra la ayuda y sale.
-p, -P Establece/prueba el atributo no_new_privs del proceso.
-r, -R Establece/prueba el bit seguro SECBIT_NOROOT.
-s, -S Establece/prueba el bit seguro SECBIT_NO_SETUID_FIXUP.
-k, -K Establece/prueba el bit seguro SECBIT_KEEP_CAPS.
-a, -A Establece/prueba el bit seguro SECBIT_NO_CAP_AMBIENT_RAISE.
-x, -X Establece/prueba el bit seguro SECBIT_EXEC_RESTRICT_FILE.
-i, -I Establece/prueba el bit seguro SECBIT_EXEC_DENY_INTERACTIVE.

BITS SEGUROS

Bit Seguro Descripción ¿Se requiere CAP_SETPCAP?
NO_NEW_PRIVS Cuando se establece, execve(2) no otorgará nuevos privilegios (por ejemplo, se ignorarán los bits de modo de usuario/grupo establecido y las capacidades de archivo). Se hereda a través de fork(2), clone(2) y execve(2); una vez establecido, no se puede deshacer. No
NOROOT Deshabilita el manejo especial del UID 0 para obtener capacidades en la ejecución/setuid. NOROOT_LOCKED es el bloqueo para NOROOT (impide cambios adicionales; irreversible). Sí
NO_SETUID_FIXUP Detiene los ajustes del kernel en los conjuntos de capacidades permitidas/efectivas/ambientales cuando los UID efectivos/del sistema de archivos cambian entre 0 y un valor distinto de cero. NO_SETUID_FIXUP_LOCKED es el bloqueo para NO_SETUID_FIXUP (impide cambios adicionales; irreversible). Sí
KEEP_CAPS Permite retener las capacidades permitidas al cambiar todos los UID de 0 a un valor distinto de cero; siempre se borra en execve(2). KEEP_CAPS_LOCKED es el bloqueo para KEEP_CAPS (impide cambios adicionales; irreversible). Sí
NO_CAP_AMBIENT_RAISE Prohíbe aumentar las capacidades ambientales a través de prctl(PR_CAP_AMBIENT_RAISE). NO_CAP_AMBIENT_RAISE_LOCKED es el bloqueo para NO_CAP_AMBIENT_RAISE (impide cambios adicionales; irreversible). Sí
EXEC_RESTRICT_FILE El intérprete/enlazador dinámico solo debe ejecutar un archivo si execveat(2) con AT_EXECVE_CHECK en el descriptor de archivo relacionado tiene éxito. EXEC_RESTRICT_FILE_LOCKED es el bloqueo para EXEC_RESTRICT_FILE (impide cambios adicionales; irreversible). No
EXEC_DENY_INTERACTIVE El intérprete no debe aceptar comandos interactivos del usuario; el contenido a través de un descriptor de archivo solo se permite si execveat(2) con AT_EXECVE_CHECK tiene éxito. EXEC_DENY_INTERACTIVE_LOCKED es el bloqueo para EXEC_DENY_INTERACTIVE (impide cambios adicionales; irreversible). No

ESTADO DE SALIDA

Al consultar bits seguros, syd-sec sale con éxito si todos los bits seguros especificados están establecidos en los bits seguros del proceso. Al ejecutar un comando, syd-sec sale con el mismo código que el proceso hijo. Si la operación PR_SET_SECUREBITS(2const) prctl(2) falla antes de la ejecución del comando, syd-sec sale con errno(3).
