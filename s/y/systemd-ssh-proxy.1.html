NOMBRE

systemd-ssh-proxy - Plugin cliente SSH para conectarse a sockets AF_VSOCK y AF_UNIX

SINOPSIS

Host unix/* unix%* vsock/* vsock%* vsock-mux/* vsock-mux%*
    ProxyCommand /usr/lib/systemd/systemd-ssh-proxy %h %p
    ProxyUseFdpass yes

/usr/lib/systemd/systemd-ssh-proxy [DIRECCIÓN] [PUERTO]

DESCRIPCIÓN

systemd-ssh-proxy es un pequeño plugin "proxy" para la herramienta ssh(1) que permite conectarse a sockets AF_UNIX y AF_VSOCK. Implementa la interfaz definida por la opción de configuración ProxyCommand de ssh. Está pensado para utilizarse con un fragmento de configuración de ssh_config(5) como el siguiente:

Host unix/* unix%* vsock/* vsock%* vsock-mux/* vsock-mux%*
    ProxyCommand /usr/lib/systemd/systemd-ssh-proxy %h %p
    ProxyUseFdpass yes
    CheckHostIP no
Host .host
    ProxyCommand /usr/lib/systemd/systemd-ssh-proxy unix/run/ssh-unix-local/socket %p
    ProxyUseFdpass yes
    CheckHostIP no

Un fragmento de configuración similar a este se instala por defecto en /etc/ssh/ssh_config.d/20-systemd-ssh-proxy.conf.

Con esto configurado, las conexiones SSH a la cadena de host "unix/" seguida de una ruta absoluta del sistema de archivos AF_UNIX a un socket se dirigirán al socket especificado, que debe ser de tipo SOCK_STREAM. De forma similar, las conexiones SSH a "vsock/" seguida de un CID de AF_VSOCK resultarán en una conexión SSH realizada a ese CID. "vsock-mux/" seguida de una ruta absoluta del sistema de archivos AF_UNIX a un socket es similar pero para cloud-hypervisor/firecracker que no permiten comunicación directa AF_VSOCK entre el host y los invitados, y proporcionan su propio multiplexor sobre sockets AF_UNIX. Véase soporte VSOCK de cloud-hypervisor[1] y Uso del dispositivo Virtio-vsock de Firecracker[2]. Tenga en cuenta que "%" puede usarse como separador en lugar de "/" para ser compatible con herramientas como "scp" y "rsync".

Además, conectarse a ".host" conectará al host local a través de ssh, sin involucrar redes.

Esta herramienta está pensada para ser utilizada junto con systemd-ssh-generator(8), que cuando se ejecuta dentro de una VM o contenedor vinculará SSH a direcciones adecuadas. Se supone que systemd-ssh-generator se ejecuta en el contenedor o invitado de la VM, y systemd-ssh-proxy se ejecuta en el host, para conectarse al contenedor o invitado de la VM.

ESTADO DE SALIDA

En caso de éxito, se devuelve 0, en caso contrario, un código de error distinto de cero.

EJEMPLOS

Ejemplo 1. Hablar con una VM local con CID 4711

ssh vsock/4711

Ejemplo 2. Hablar con un invitado de VM alojado con cloud-hypervisor/firecracker

ssh vsock-mux/run/vm-1234.sock

Ejemplo 3. Hablar con el host local a través de ssh

ssh .host

o el equivalente:

ssh unix/run/ssh-unix-local/socket

Ejemplo 4. Copiar el archivo local 'foo' a una VM local con CID 1348

scp foo vsock%1348:
