NOMBRE

systemd-tmpfiles, systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service, systemd-tmpfiles-clean.timer - Crear, eliminar y limpiar archivos y directorios

SINOPSIS

systemd-tmpfiles [OPCIONES...] [ARCHIVO_CONFIG...]

Unidades del sistema:

systemd-tmpfiles-setup.service
systemd-tmpfiles-setup-dev-early.service
systemd-tmpfiles-setup-dev.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

Unidades de usuario:

systemd-tmpfiles-setup.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

DESCRIPCIÓN

systemd-tmpfiles crea, elimina y limpia archivos y directorios, utilizando el formato y la ubicación de archivo de configuración especificados en tmpfiles.d(5). Históricamente, fue diseñado para gestionar archivos volátiles y temporales, como sugiere el nombre, pero proporciona funcionalidad genérica de gestión de archivos y puede ser utilizado para gestionar cualquier tipo de archivos. Debe invocarse con uno o más comandos --create, --remove y --clean, para seleccionar el subconjunto respectivo de operaciones.

Si se invoca sin argumentos, se ejecutan las directivas de los archivos de configuración encontrados en los directorios especificados por tmpfiles.d(5). Cuando se invoca con argumentos posicionales, si se especifica la opción --replace=RUTA, se utilizan los argumentos especificados en la línea de comandos en lugar de la RUTA del archivo de configuración. De lo contrario, solo se ejecuta la configuración especificada por los argumentos de la línea de comandos. Si se especifica la cadena "-" en lugar de un nombre de archivo, la configuración se lee de la entrada estándar. Si el argumento es un nombre de archivo (sin barras), se buscan en todos los directorios de configuración un archivo coincidente y se ejecuta el archivo encontrado que tenga la mayor prioridad. Si el argumento es una ruta, se utiliza ese archivo directamente sin buscar en los directorios de configuración ningún otro archivo coincidente.

Los servicios del sistema (systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service) invocan a systemd-tmpfiles para crear archivos del sistema y realizar la limpieza a nivel de sistema. Estos servicios leen archivos de configuración controlados por el administrador en los directorios tmpfiles.d/. Los servicios de usuario (systemd-tmpfiles-setup.service, systemd-tmpfiles-clean.service) también invocan a systemd-tmpfiles, pero leen un conjunto diferente de archivos, que incluye archivos controlados por el usuario en ~/.config/user-tmpfiles.d/ y ~/.local/share/user-tmpfiles.d/, y archivos controlados por el administrador en /usr/share/user-tmpfiles.d/. Los usuarios pueden usar esto para crear y limpiar archivos bajo su control, pero la instancia del sistema realiza la limpieza global y no se ve influenciada por la configuración del usuario. Tenga en cuenta que esto significa que una limpieza basada en el tiempo configurada en la instancia del sistema, como la que normalmente se configura para /tmp/, afectará también a los archivos creados por la instancia del usuario si se colocan en /tmp/, incluso si la limpieza basada en el tiempo de la instancia del usuario está desactivada.

Para volver a aplicar la configuración después de haberla modificado, simplemente reinicie systemd-tmpfiles-clean.service, lo que aplicará cualquier configuración que se pueda ejecutar de forma segura en tiempo de ejecución. Para depurar systemd-tmpfiles, puede ser útil invocarlo directamente desde la línea de comandos con un nivel de registro aumentado (ver $SYSTEMD_LOG_LEVEL a continuación).

COMANDOS Y OPCIONES

Se entienden los siguientes comandos:

--create

Si se pasa este comando, se crearán o escribirán todos los archivos y directorios marcados con f, F, w, d, D, v, p, L, c, b, m en los archivos de configuración. Los archivos y directorios marcados con z, Z, t, T, a y A tendrán establecida su propiedad, modo de acceso y etiquetas de seguridad.

--clean

Si se pasa este comando, se limpiarán todos los archivos y directorios con un parámetro de antigüedad configurado.

--remove

Si se pasa este comando, se eliminarán los contenidos de los directorios marcados con D o R, y los propios archivos o directorios marcados con r o R a menos que se tome un bloqueo exclusivo o compartido de BSD sobre ellos (ver flock(2)).

--purge

Si se pasa esta opción, se eliminarán todos los archivos y directorios declarados para creación y marcados con el carácter "$" por los archivos tmpfiles.d/ especificados en la línea de comandos. Específicamente, esto actúa sobre todos los archivos y directorios marcados con f, F, d, D, v, q, Q, p, L, c, b, C, w, e. Si se usa este interruptor, se debe especificar al menos un archivo tmpfiles.d/ (o - para la entrada estándar) en la línea de comandos o se denegará la invocación, por motivos de seguridad (ya que de lo contrario se podrían eliminar muchos archivos del sistema instalados).

El caso de uso principal para esta opción es eliminar automáticamente archivos y directorios que originalmente se crearon en nombre de un paquete instalado en el momento de la desinstalación del paquete.

Se recomienda ejecutar primero este comando en combinación con --dry-run (ver más abajo) para verificar qué archivos y directorios se eliminarán.

¡Advertencia! ¡Este generalmente no es el comando que quiere! En la mayoría de los casos, --remove es lo que está buscando.

Añadido en la versión 256.

--user

Ejecutar la configuración de "usuario", es decir, archivos tmpfiles.d/ en los directorios de configuración de usuario.

Añadido en la versión 236.

--boot

Ejecutar también las líneas con un signo de exclamación. Las líneas que no son seguras de ejecutar en un sistema en ejecución pueden marcarse de esta manera. systemd-tmpfiles se ejecuta al inicio temprano con --boot especificado y ejecutará esas líneas. Cuando se invoque de nuevo más tarde, debería llamarse sin --boot.

Añadido en la versión 209.

--graceful

Ignorar las líneas de configuración relativas a usuarios o grupos desconocidos. Esta opción está destinada a ser utilizada al inicio temprano, antes de que todos los usuarios o grupos hayan sido creados.

Añadido en la versión 254.

--dry-run

Procesar la configuración e imprimir qué operaciones se realizarían, pero sin cambiar realmente nada en el sistema de archivos.

Añadido en la versión 256.

--prefix=ruta

Aplicar solo reglas con rutas que comiencen con el prefijo especificado. Esta opción se puede especificar varias veces.

Añadido en la versión 212.

--exclude-prefix=ruta

Ignorar reglas con rutas que comiencen con el prefijo especificado. Esta opción se puede especificar varias veces.

Añadido en la versión 207.

-E

Un atajo para "--exclude-prefix=/dev --exclude-prefix=/proc --exclude-prefix=/run --exclude-prefix=/sys", es decir, excluir las jerarquías típicamente respaldadas por sistemas de archivos virtuales o de memoria. Esto es útil en combinación con --root=, si el árbol de directorios especificado contiene un árbol de SO sin estos sistemas de archivos virtuales/de memoria montados, ya que típicamente no es deseable crear ningún archivo y directorio debajo de estos subdirectorios si se supone que deben ser sobremontados durante la ejecución.

Añadido en la versión 247.

--root=raiz

Toma una ruta de directorio como argumento. Todas las rutas serán prefijadas con la ruta alternativa raiz dada, incluyendo las rutas de búsqueda de configuración.

Cuando se utiliza esta opción, se omite el sistema de conmutación de nombres (NSS) de libc para resolver usuarios y grupos. En su lugar, se leen directamente los archivos /etc/passwd y /etc/group dentro de la raíz alternativa. Esto significa que los usuarios/grupos no listados en estos archivos no serán resueltos, es decir, no se considerarán bases de datos complejas como LDAP, NIS, etc.

Considere combinar esto con -E para asegurar que la invocación no cree archivos o directorios debajo de los puntos de montaje en la imagen del SO operada que típicamente se sobremontan durante la ejecución.

OPTIONS

--image=image

Toma una ruta a un archivo de imagen de disco o nodo de dispositivo de bloque. Si se especifica, todas las operaciones se aplican al sistema de archivos en la imagen de disco indicada. Esto es similar a --root= pero opera en sistemas de archivos almacenados en imágenes de disco o dispositivos de bloque. La imagen de disco debe contener solo un sistema de archivos o un conjunto de sistemas de archivos dentro de una tabla de particiones GPT, siguiendo la Especificación de Particiones Descubribles[1]. Para obtener más información sobre imágenes de disco compatibles, consulte el conmutador del mismo nombre en systemd-nspawn(1).

Implica -E.

Añadido en la versión 247.

--image-policy=policy

Toma una cadena de política de imagen como argumento, según systemd.image-policy(7). La política se aplica al operar en la imagen de disco especificada a través de --image=, ver arriba. Si no se especifica, por defecto es la política "*", es decir, se utilizan todos los sistemas de archivos reconocidos en la imagen.

--replace=PATH

Cuando se proporciona esta opción, se debe especificar uno o más argumentos posicionales. Todos los archivos de configuración que se encuentren en los directorios listados en tmpfiles.d(5) se leerán, y la configuración proporcionada en la línea de comandos se manejará en lugar de y con la misma prioridad que el archivo de configuración PATH.

Esta opción está pensada para ser utilizada cuando se ejecutan scripts de instalación de paquetes y los archivos que pertenecen a ese paquete aún no están disponibles en el disco, por lo que su contenido debe proporcionarse en la línea de comandos, pero la configuración del administrador ya podría existir y debería tener mayor prioridad.

Añadido en la versión 238.

--cat-config

Copia el contenido de los archivos de configuración a la salida estándar. Antes de cada archivo, se imprime el nombre del archivo como un comentario.

--tldr

Copia el contenido de los archivos de configuración a la salida estándar. Solo se imprimen las partes "interesantes" de los archivos de configuración, se omiten los comentarios y las líneas vacías. Antes de cada archivo, se imprime el nombre del archivo como un comentario.

--no-pager

No canaliza la salida a un paginador.

-h, --help

Imprime un texto de ayuda corto y sale.

--version

Imprime una cadena de versión corta y sale.

Es posible combinar --create, --clean y --remove en una sola invocación (en cuyo caso la eliminación y la limpieza se ejecutan antes de la creación de nuevos archivos). Por ejemplo, durante el arranque, se ejecuta la siguiente línea de comandos para asegurar que todos los directorios temporales y volátiles se eliminen y creen de acuerdo con el archivo de configuración:

systemd-tmpfiles --remove --create

CREDENTIALS

systemd-tmpfiles soporta la lógica de credenciales de servicio tal como la implementa ImportCredential=/LoadCredential=/SetCredential= (ver systemd.exec(5) para detalles). Las siguientes credenciales se utilizan cuando se pasan:

tmpfiles.extra

El contenido de esta credencial puede contener líneas adicionales para operar. El contenido de la credencial debe seguir el mismo formato que cualquier otro archivo de configuración de drop-in de tmpfiles.d/. Si se pasa esta credencial, se procesa después de todos los archivos de drop-in leídos del sistema de archivos. Por lo tanto, las líneas en la credencial pueden aumentar las líneas existentes del sistema operativo, pero no anularlas.

Añadido en la versión 252.

Tenga en cuenta que, por defecto, el archivo de unidad systemd-tmpfiles-setup.service (y los archivos de unidad relacionados) está configurado para heredar la credencial "tmpfiles.extra" del gestor de servicios.

ENVIRONMENT

$SYSTEMD_LOG_LEVEL

El nivel máximo de registro de los mensajes emitidos (los mensajes con un nivel de registro superior, es decir, menos importantes, se suprimirán). Toma una lista de valores separados por comas. Un valor puede ser uno de (en orden de importancia decreciente) emerg, alert, crit, err, warning, notice, info, debug, o un entero en el rango 0...7. Consulte syslog(3) para obtener más información. Cada valor puede ir opcionalmente precedido por uno de console, syslog, kmsg o journal seguido de dos puntos para establecer el nivel máximo de registro para ese objetivo de registro específico (por ejemplo, SYSTEMD_LOG_LEVEL=debug,console:info especifica registrar en nivel debug excepto cuando se registra en la consola, que debe ser en nivel info). Tenga en cuenta que el nivel máximo de registro global tiene prioridad sobre cualquier nivel máximo de registro por objetivo.

$SYSTEMD_LOG_COLOR

Un booleano. Si es verdadero, los mensajes escritos en la tty se colorearán según la prioridad.

Esta configuración solo es útil cuando los mensajes se escriben directamente en la terminal, ya que journalctl(1) y otras herramientas que muestran los registros colorearán los mensajes según el nivel de registro por sí mismas.

$SYSTEMD_LOG_TIME

Un booleano. Si es verdadero, los mensajes de registro de la consola se prefijarán con una marca de tiempo.

Esta configuración solo es útil cuando los mensajes se escriben directamente en la terminal o en un archivo, ya que journalctl(1) y otras herramientas que muestran los registros adjuntarán marcas de tiempo según los metadatos de la entrada por sí mismas.

$SYSTEMD_LOG_LOCATION

Un booleano. Si es verdadero, los mensajes se prefijarán con un nombre de archivo y número de línea en el código fuente donde se origina el mensaje.

Tenga en cuenta que la ubicación del registro a menudo se adjunta como metadatos a las entradas del journal de todos modos. Incluirlo directamente en el texto del mensaje puede ser conveniente al depurar programas.

$SYSTEMD_LOG_TARGET

El destino de los mensajes de registro. Uno de console (registrar en la tty adjunta), console-prefixed (registrar en la tty adjunta pero con prefijos que codifican el nivel de registro y la "instalación", ver syslog(3), kmsg (registrar en el búfer de registro circular del kernel), journal (registrar en el journal), journal-or-kmsg (registrar en el journal si está disponible, y en kmsg en caso contrario), auto (determinar automáticamente el objetivo de registro apropiado, el valor por defecto), null (deshabilitar la salida de registro).

$SYSTEMD_PAGER, $PAGER

Paginador a utilizar cuando no se especifica --no-pager. Se utiliza $SYSTEMD_PAGER si está establecido; de lo contrario, se utiliza $PAGER. Si no se establecen ni $SYSTEMD_PAGER ni $PAGER, se prueban una serie de implementaciones de paginadores conocidas en orden, incluyendo less(1) y more(1), hasta que se encuentra una. Si no se descubre ninguna implementación de paginador, no se invoca ningún paginador. Establecer estas variables de entorno a una cadena vacía o al valor "cat" es equivalente a pasar --no-pager.

Nota: si $SYSTEMD_PAGERSECURE no está establecido, $SYSTEMD_PAGER y $PAGER solo se pueden usar para deshabilitar el paginador (con "cat" o ""), y de lo contrario se ignoran.

$SYSTEMD_LESS

Anula las opciones pasadas a less (por defecto "FRSXMK").

Los usuarios podrían querer cambiar dos opciones en particular:

K

Esta opción instruye al paginador a salir inmediatamente cuando se presiona Ctrl+C. Para permitir que less maneje Ctrl+C por sí mismo para volver al prompt de comandos del paginador, anule esta opción.

Si el valor de $SYSTEMD_LESS no incluye "K", y el paginador que se invoca es less, Ctrl+C será ignorado por el ejecutable y deberá ser manejado por el paginador.

X

Esta opción instruye al paginador a no enviar cadenas de inicialización y desinicialización de termcap a la terminal. Se establece por defecto para permitir que la salida del comando permanezca visible en la terminal incluso después de que salga el paginador. Sin embargo, esto impide que funcione cierta funcionalidad del paginador, en particular, la salida paginada no se puede desplazar con el ratón.

Tenga en cuenta que establecer la variable de entorno $LESS regular no tiene ningún efecto para las invocaciones de less por parte de las herramientas de systemd.

Consulte less(1) para más discusión.

$SYSTEMD_LESSCHARSET

Anula el conjunto de caracteres pasado a less (por defecto "utf-8", si se determina que la terminal que invoca es compatible con UTF-8).

Tenga en cuenta que establecer la variable de entorno $LESSCHARSET regular no tiene ningún efecto para las invocaciones de less por parte de las herramientas de systemd.

$SYSTEMD_PAGERSECURE

Los comandos de paginador comunes como less(1), además de la "paginación", es decir, desplazarse por la salida, admiten la apertura o escritura de otros archivos y la ejecución de comandos arbitrarios del shell. Cuando se invocan comandos con privilegios elevados, por ejemplo, bajo sudo(8) o pkexec(1), el paginador se convierte en un límite de seguridad. Se debe tener cuidado de que solo se utilicen como paginadores programas con funcionalidad estrictamente limitada, y no se permitan funciones interactivas no deseadas como la apertura o creación de nuevos archivos o el inicio de subprocesos. El "modo seguro" para el paginador puede habilitarse como se describe a continuación, si el paginador lo soporta (la mayoría de los paginadores no están escritos de manera que tengan esto en cuenta). Se recomienda habilitar explícitamente el "modo seguro" o deshabilitar completamente el paginador usando --no-pager o PAGER=cat al permitir que usuarios no confiables ejecuten comandos con privilegios elevados.

Esta opción toma un argumento booleano. Cuando se establece en verdadero, se habilita el "modo seguro" del paginador. En "modo seguro", se establecerá LESSSECURE=1 al invocar el paginador, lo que instruye al paginador a deshabilitar comandos que abren o crean nuevos archivos o inician nuevos subprocesos. Actualmente, solo less(1) entiende esta variable e implementa el "modo seguro".

Cuando se establece en falso, no se impone ninguna limitación al paginador. Establecer SYSTEMD_PAGERSECURE=0 o no eliminarlo del entorno heredado puede permitir al usuario invocar comandos arbitrarios.

Cuando $SYSTEMD_PAGERSECURE no está establecido, las herramientas de systemd intentan determinar automáticamente si se debe habilitar el "modo seguro" y si el paginador lo soporta. El "modo seguro" se habilita si el UID efectivo no es el mismo que el propietario de la sesión de inicio de sesión, ver geteuid(2) y sd_pid_get_owne

NAME

systemd-tmpfiles - create, delete, clean and remove volatile and temporary files and directories

SYNOPSIS

systemd-tmpfiles [--root=ROOT] [--runtime=RUNTIME] [--state=STATE] [--user=USER] [--prefix=PREFIX]... [--all] [--purge] [--create] [--remove] [--clean] [--validate] [--force] [--directory] [--quiet] [--remove-tmpfiles-only] [--no-pager] [--now]

DESCRIPTION

systemd-tmpfiles is used to manage temporary and volatile files and directories. It is primarily configured through the /usr/lib/tmpfiles.d/*.conf and /etc/tmpfiles.d/*.conf configuration files.

The main goal of systemd-tmpfiles is to ensure that specified temporary directories are cleaned up, that volatile files and directories are created and initialized, and that temporary files are removed.

For a detailed description of the configuration file syntax, see tmpfiles.d(5).

COMMANDS AND OPTIONS

The following options are understood:

--root=ROOT
Operate on a directory tree, specified by ROOT, instead of the actual root directory. This is useful for system imaging and testing.
--runtime=RUNTIME
Operate on a directory tree, specified by RUNTIME, instead of /run. This is useful for testing.
--state=STATE
Operate on a directory tree, specified by STATE, instead of /var/lib. This is useful for testing.
--user=USER
Operate on a directory tree, specified by USER, instead of the user's home directory. This is useful for testing.
--prefix=PREFIX
Only consider configuration files and directories below PREFIX. May be specified multiple times. If not specified, defaults to /usr and /etc.
--all
Consider all configuration files and directories from all known paths. This is the default if no other action-modifying option is given.
--purge
Remove files and directories that are listed in the configuration files but are not marked with the + flag and have not been modified recently. See tmpfiles.d(5) for details.
--create
Create files and directories that are listed in the configuration files and do not exist. See tmpfiles.d(5) for details.
--remove
Remove files and directories that are listed in the configuration files and exist, unless they have been modified recently. See tmpfiles.d(5) for details.
--clean
Remove old files and directories from temporary directories. See tmpfiles.d(5) for details.
--validate
Check the current state of the filesystem against the configuration files. Print warnings for any deviations. This is intended for testing and debugging.
--force
Also act on files and directories that have been modified. This option is mostly used with --purge and --remove.
--directory
When creating directories, ensure that parent directories exist and are created if necessary. This is usually implied by default unless --no-directory is used.
--quiet
Suppress informative output. Only print error messages.
--remove-tmpfiles-only
Only remove temporary files. Do not create or clean other files or directories.
--no-pager
Do not use a pager for displaying output. This is the default when running as root or when output is redirected.
--now
When used with --create, ensure that files and directories are created immediately. Otherwise, they might be created on the next boot.

CREDENTIALS

When run by the root user, systemd-tmpfiles may change file ownership, permissions, and extended attributes. Some operations, like creating new files or directories, or changing ownership, might require specific capabilities like CAP_DAC_OVERRIDE, CAP_DAC_READ_SEARCH, CAP_FOWNER, CAP_SETFCAP, CAP_CHOWN, CAP_SETUID, CAP_SETGID, CAP_MAC_OVERRIDE, CAP_MAC_ADMIN, CAP_SELINUX, CAP_AUDIT_WRITE, CAP_CHDIR, CAP_LINK_DIR, CAP_SYS_CHROOT, CAP_SYS_TTY_CONFIG, CAP_KILL, CAP_SETFCAP, CAP_SETUID, CAP_SETGID.

When run by a regular user, systemd-tmpfiles only operates on files and directories owned by that user. It will not attempt to change ownership or permissions of files it does not own. It will also not create files or directories outside of the user's home directory.

ENVIRONMENT

The behavior of systemd-tmpfiles is affected by the following environment variables:

$SYSTEMD_PAGERSECURE
This variable controls whether external pagers are used. If it is set to any non-empty value, external pagers are used only if the user is the real root user or if the $USER environment variable is set to root. If it is set to 0, external pagers are always used. If it is set to 1, external pagers are never used. By default, external pagers are used only if the user is the real root user or if $USER is set to root. This is a safety mechanism to prevent arbitrary code execution when running under privileges. Specifically, when running as root (or under $SUDO_UID), external pagers are disallowed unless this variable is set to 0. If running as non-root, pagers are allowed by default, but disallowed if $SUDO_UID is set. This autodetection also covers cases like running under sudo(8). If $SYSTEMD_PAGERSECURE is set to 1, pagers that are not known to implement "secure mode" will not be used at all. Note that this autodetection only covers the most common mechanisms to elevate privileges and is intended as a convenience. It is recommended to explicitly set $SYSTEMD_PAGERSECURE or disable the pager.
$SYSTEMD_PAGER
This variable specifies the pager program to use. If set, it overrides the default pager determined by other mechanisms. If set to an empty string, no pager is used. If honor of $SYSTEMD_PAGER or $PAGER is desired, other than to disable the pager, $SYSTEMD_PAGERSECURE must also be set.
$SYSTEMD_COLORS
Takes a boolean argument. When true, systemd and related utilities will use colors in their output, otherwise the output will be monochrome. Additionally, the variable can take one of the following special values: "16", "256" to restrict the use of colors to the base 16 or 256 ANSI colors, respectively. This can be specified to override the automatic decision based on $TERM and what the console is connected to.
$SYSTEMD_URLIFY
The value must be a boolean. Controls whether clickable links should be generated in the output for terminal emulators supporting this. This can be specified to override the decision that systemd makes based on $TERM and other conditions.

Note that if the $SYSTEMD_PAGER or $PAGER variables are to be honoured, other than to disable the pager, $SYSTEMD_PAGERSECURE must be set too.

UNPRIVILEGED --CLEANUP OPERATION

systemd-tmpfiles tries to avoid changing the access and modification times on the directories it accesses, which requires CAP_FOWNER privileges. When running as non-root, directories which are checked for files to clean up will have their access time bumped, which might prevent their cleanup.

EXIT STATUS

On success, 0 is returned. If the configuration was syntactically invalid (syntax errors, missing arguments, ...), so some lines had to be ignored, but no other errors occurred, 65 is returned (EX_DATAERR from /usr/include/sysexits.h). If the configuration was syntactically valid, but could not be executed (lack of permissions, creation of files in missing directories, invalid contents when writing to /sys/ values, ...), 73 is returned (EX_CANTCREAT from /usr/include/sysexits.h). Otherwise, 1 is returned (EXIT_FAILURE from /usr/include/stdlib.h).

Note: when creating items, if the target already exists, but is of the wrong type or otherwise does not match the requested state, and forced operation has not been requested with "+", a message is emitted, but the failure is otherwise ignored.
