NOMBRE

systemd-sysusers, systemd-sysusers.service - Asignar usuarios y grupos del sistema

SINOPSIS

systemd-sysusers [OPCIONES...] [ARCHIVO_CONFIG...]

systemd-sysusers.service

DESCRIPCIÓN

systemd-sysusers crea usuarios y grupos del sistema, basándose en archivos con el formato descrito en sysusers.d(5).

Si se invoca sin argumentos, se ejecutan las directivas de los archivos de configuración encontrados en los directorios especificados por sysusers.d(5). Cuando se invoca con argumentos posicionales, si se especifica la opción --replace=RUTA, los argumentos especificados en la línea de comandos se usarán en lugar del archivo de configuración RUTA. De lo contrario, solo se ejecutará la configuración especificada por los argumentos de la línea de comandos. Si la cadena de texto "-" se especifica en lugar de un nombre de archivo, la configuración se leerá de la entrada estándar. Si el argumento es un nombre de archivo (sin barras), se buscarán todos los directorios de configuración que contengan un archivo coincidente y se ejecutará el archivo encontrado que tenga la mayor prioridad. Si el argumento es una ruta, se usará ese archivo directamente sin buscar en los directorios de configuración ningún otro archivo coincidente.

OPCIONES

Se entienden las siguientes opciones:

--root=raíz

Toma una ruta de directorio como argumento. Todas las rutas serán prefijadas con la ruta alternativa de raíz dada, incluyendo las rutas de búsqueda de configuración.

Añadido en la versión 215.

--image=imagen

Toma una ruta a un archivo de imagen de disco o nodo de dispositivo de bloque. Si se especifica, todas las operaciones se aplicarán al sistema de archivos en la imagen de disco indicada. Esto es similar a --root= pero opera en sistemas de archivos almacenados en imágenes de disco o dispositivos de bloque. La imagen de disco debe contener solo un sistema de archivos o un conjunto de sistemas de archivos dentro de una tabla de particiones GPT, siguiendo la Especificación de Particiones Reconocibles[1]. Para más información sobre imágenes de disco compatibles, véase el interruptor del mismo nombre en systemd-nspawn(1).

Añadido en la versión 247.

--image-policy=política

Toma una cadena de política de imagen como argumento, según systemd.image-policy(7). La política se aplica al operar en la imagen de disco especificada mediante --image=, véase arriba. Si no se especifica, por defecto es la política "*", es decir, se utilizan todos los sistemas de archivos reconocidos en la imagen.

--replace=RUTA

Cuando se da esta opción, debe especificarse uno o más argumentos posicionales. Se leerán todos los archivos de configuración encontrados en los directorios listados en sysusers.d(5), y la configuración dada en la línea de comandos se manejará en lugar de y con la misma prioridad que el archivo de configuración RUTA.

Esta opción está pensada para ser utilizada cuando se ejecutan scripts de instalación de paquetes y los archivos que pertenecen a ese paquete aún no están disponibles en disco, por lo que su contenido debe proporcionarse en la línea de comandos, pero la configuración del administrador puede existir ya y debe tener mayor prioridad.

Ejemplo 1. Script de instalación RPM para radvd

echo 'u radvd - "daemon radvd"' | \
          systemd-sysusers --replace=/usr/lib/sysusers.d/radvd.conf -

Esto creará el usuario radvd como si /usr/lib/sysusers.d/radvd.conf ya estuviera en disco. Un administrador podría anular la configuración especificada en la línea de comandos colocando /etc/sysusers.d/radvd.conf o incluso /etc/sysusers.d/00-overrides.conf.

Tenga en cuenta que esta es la forma expandida, y cuando se usa en un paquete, esto se escribiría usando una macro con "radvd" y un archivo que contiene la línea de configuración como argumentos.

Añadido en la versión 238.

--dry-run

Procesa la configuración y determina qué entradas se crearían, pero no escribe nada en realidad.

Añadido en la versión 250.

--inline

Trata cada argumento posicional como una línea de configuración separada en lugar de un nombre de archivo.

Añadido en la versión 238.

--cat-config

Copia el contenido de los archivos de configuración a la salida estándar. Antes de cada archivo, se imprime el nombre del archivo como un comentario.

--tldr

Copia el contenido de los archivos de configuración a la salida estándar. Solo se imprimen las partes "interesantes" de los archivos de configuración, se omiten los comentarios y las líneas vacías. Antes de cada archivo, se imprime el nombre del archivo como un comentario.

--no-pager

No canaliza la salida a un paginador.

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una cadena de versión corta y sale.

CREDENCIALES

systemd-sysusers soporta la lógica de credenciales de servicio implementada por ImportCredential=/LoadCredential=/SetCredential= (ver systemd.exec(5) para más detalles). Las siguientes credenciales se usan cuando se pasan:

passwd.hashed-password.usuario

Una cadena de contraseña hasheada de UNIX para usar con el usuario especificado, al crear una entrada para él. Esto es particularmente útil para el usuario "root" ya que permite aprovisionar la contraseña de root predeterminada a utilizar a través de un drop-in de archivo de unidad o desde un gestor de contenedores que pasa esta credencial. Tenga en cuenta que establecer esta credencial no tiene ningún efecto si la cuenta de usuario especificada ya existe. Por lo tanto, esta credencial es principalmente útil en escenarios de primer arranque o en sistemas que son completamente sin estado y arrancan con un /etc/ vacío en cada arranque.

Añadido en la versión 249.

passwd.plaintext-password.usuario

Similar a "passwd.hashed-password.usuario" pero espera una contraseña literal, sin cifrar, que luego se hashea automáticamente antes de usarse para la cuenta de usuario. Si se especifican tanto la credencial hasheada como la sin cifrar para el mismo usuario, la primera tiene prioridad. Generalmente se recomienda especificar la versión hasheada; sin embargo, en entornos de prueba con requisitos de seguridad más débiles, puede ser más fácil pasar contraseñas sin cifrar.

Añadido en la versión 249.

passwd.shell.usuario

Especifica el binario del shell a usar para la cuenta especificada al crearla.

Añadido en la versión 249.

sysusers.extra

El contenido de esta credencial puede contener líneas adicionales para operar. El contenido de la credencial debe seguir el mismo formato que cualquier otro drop-in de sysusers.d/. Si se pasa esta credencial, se procesará después de todos los archivos drop-in leídos del sistema de archivos.

Añadido en la versión 252.

Tenga en cuenta que, por defecto, el archivo de unidad systemd-sysusers.service está configurado para heredar las credenciales "passwd.hashed-password.root", "passwd.plaintext-password.root", "passwd.shell.root" y "sysusers.extra" del gestor de servicios. Por lo tanto, al invocar un contenedor con un /etc/ no poblado por primera vez, es posible configurar la contraseña del usuario root a "systemd" de la siguiente manera:

# systemd-nspawn --image=... --set-credential=passwd.hashed-password.root:'$y$j9T$yAuRJu1o5HioZAGDYPU5d.$F64ni6J2y2nNQve90M/p0ZP0ECP/qqzipNyaY9fjGpC' ...

Tenga en cuenta nuevamente que los datos especificados en esta credencial solo se consultan al crear una cuenta por primera vez, no pueden utilizarse para cambiar la contraseña o el shell de una cuenta que ya existe.

Use mkpasswd(1) para generar hashes de contraseña UNIX desde la línea de comandos.

ESTADO DE SALIDA

En caso de éxito, se devuelve 0, de lo contrario, un código de error distinto de cero.

VER TAMBIÉN

systemd(1), sysusers.d(5), Usuarios, Grupos, UID y GID en sistemas systemd[2], systemd.exec(5), mkpasswd(1)

mkpasswd(1) — Arch manual pages

NAME

mkpasswd — generate a password hash

SYNOPSIS

mkpasswd [OPTION]... [PASSWORD]

DESCRIPTION

mkpasswd generates a crypt(3) password hash from the given PASSWORD. If PASSWORD is not given, it is read from standard input.

The hash algorithm used is determined by the crypt(3) library call and the system configuration, which usually means that SHA-512 (hash format $6$) is used for new passwords, unless explicitly overridden by options or configuration.

This utility is primarily intended for generating password hashes for use in configuration files like shadow(5). It is generally not recommended to use this tool for interactive password generation.

OPTIONS

-m, --method=METHOD
Generate the hash using the specified METHOD. Supported methods include:
sha-512
SHA-512 crypt, uses $6$ prefix.
sha-256
SHA-256 crypt, uses $5$ prefix.
md5
MD5 crypt, uses $1$ prefix. Note that MD5 is considered insecure.
blowfish
Blowfish crypt, uses $2$ or $2a$ prefix. Often associated with the bcrypt algorithm. The exact prefix depends on the implementation. This is generally considered secure.
yescrypt
yescrypt crypt, uses $y$ prefix. A more modern and robust algorithm.
sha-512-crypt
Same as sha-512.
sha-256-crypt
Same as sha-256.
md5-crypt
Same as md5.
blowfish-crypt
Same as blowfish.
yescrypt-crypt
Same as yescrypt.
-S, --salt=SALT
Use the given SALT string to generate the hash. The salt string must be exactly 16 characters long for SHA-512 and SHA-256. For MD5, it must be exactly 8 characters long. If the salt is too short or too long, mkpasswd will exit with an error. If this option is used, the salt is not randomly generated.
-s, --sha1
Use the SHA1 hashing algorithm. This is generally not recommended due to known weaknesses.
-5, --sha256
Use the SHA256 hashing algorithm.
-6, --sha512
Use the SHA512 hashing algorithm. This is the default for new password hashes on most systems.
-H, --hook=METHOD
Use the specified crypt(3) hashing backend. This is useful for testing or selecting a specific implementation. Common values include 'glibc', 'openssl'.
-n, --rounds=COUNT
Set the number of rounds for the hashing algorithm. Higher rounds mean slower hashing, making it more resistant to brute-force attacks. The default value varies depending on the algorithm and system configuration.
-h, --help
Display a help message and exit.
-V, --version
Display version information and exit.

CREDENTIALS

When mkpasswd is used to generate passwords for system accounts, it is recommended to use a strong hashing algorithm like SHA-512 or yescrypt, and to ensure that the salt is randomly generated. Avoid using weak algorithms like MD5 or SHA1.

EXIT STATUS

Returns success unless an error occurs.

Errors include invalid options, invalid salt length, or failure to generate the hash.

SEE ALSO

crypt(3), login.defs(5), shadow(5), passwd(1), useradd(8), mkpasswd(1)
