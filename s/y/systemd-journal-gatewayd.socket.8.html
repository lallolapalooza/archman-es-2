SYSTEMD-JOURNAL-GATEWAYD.SERVICE(8) systemd-journal-gatewayd.service SYSTEMD-JOURNAL-GATEWAYD.SERVICE(8)

NOMBRE

systemd-journal-gatewayd.service, systemd-journal-gatewayd.socket, systemd-journal-gatewayd - Servidor HTTP para eventos del journal

SINOPSIS

systemd-journal-gatewayd.service

systemd-journal-gatewayd.socket

/usr/lib/systemd/systemd-journal-gatewayd [OPCIONES...]

DESCRIPCIÓN

systemd-journal-gatewayd sirve eventos del journal a través de la red. Los clientes deben conectarse usando HTTP. El servidor escucha en el puerto 19531 por defecto. Si se especifica --cert=, el servidor espera conexiones HTTPS.

El programa es iniciado por systemd(1) y espera recibir un único socket. Utilice systemctl start systemd-journal-gatewayd.socket para iniciar el servicio y systemctl enable systemd-journal-gatewayd.socket para que se inicie al arrancar.

OPCIONES

Se reconocen las siguientes opciones:

--cert=

Especifique la ruta a un archivo o socket de stream AF_UNIX para leer el certificado del servidor. El certificado debe estar en formato PEM. Esta opción cambia systemd-journal-gatewayd al modo HTTPS y debe usarse junto con --key=.

Añadido en la versión 198.

--key=

Especifique la ruta a un archivo o socket de stream AF_UNIX para leer la clave secreta del servidor correspondiente al certificado especificado con --cert=. La clave debe estar en formato PEM.

Añadido en la versión 198.

--trust=

Especifique la ruta a un archivo o socket de stream AF_UNIX para leer un certificado CA. El certificado debe estar en formato PEM.

Añadido en la versión 236.

--system, --user

Limitar las entradas servidas a las entradas de servicios del sistema y del kernel, o a las entradas de los servicios del usuario actual. Esto tiene el mismo significado que las opciones --system y --user para journalctl(1). Si no se especifica ninguna, se sirven todas las entradas accesibles.

Añadido en la versión 249.

-m, --merge

Servir entradas intercaladas de todos los journals disponibles, incluyendo otras máquinas. Esto tiene el mismo significado que la opción --merge para journalctl(1).

Añadido en la versión 249.

-D DIR, --directory=DIR

Toma como argumento una ruta de directorio. Si se especifica, systemd-journal-gatewayd servirá el directorio del journal especificado DIR en lugar de las rutas predeterminadas del journal de ejecución y del sistema.

Añadido en la versión 232.

--file=GLOB

Toma como argumento un patrón de archivo. Sirve entradas de los archivos de journal especificados que coincidan con GLOB en lugar de las rutas predeterminadas del journal de ejecución y del sistema. Puede especificarse varias veces, en cuyo caso los archivos se intercalarán adecuadamente. Esto tiene el mismo significado que la opción --file= para journalctl(1).

Añadido en la versión 249.

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.

URLS SOPORTADAS

Se reconocen las siguientes URLs:

/boots

Devuelve una respuesta json-seq (RFC 7464) que contiene objetos JSON, cada uno con el número de arranque, su ID y las marcas de tiempo del primer y último mensaje. Los arranques se devuelven comenzando por el arranque más reciente y utilizan el mismo esquema que journalctl --list-boots --output json.

Añadido en la versión 258.

/browse

Navegación interactiva.

Añadido en la versión 197.

/entries[?opcion1&opcion2=valor...]

Recuperación de eventos en varios formatos.

La parte Accept: de la cabecera HTTP determina el formato. Los valores compatibles se describen a continuación.

La parte Range: de la cabecera HTTP determina el rango de eventos devueltos. Los valores compatibles se describen a continuación.

Los parámetros GET se pueden usar para modificar qué eventos se devuelven. Los parámetros compatibles se describen a continuación.

Añadido en la versión 197.

/machine

Devuelve una estructura JSON que describe la máquina.

Ejemplo:

{ "machine_id" : "8cf7ed9d451ea194b77a9f118f3dc446",
  "boot_id" : "3d3c9efaf556496a9b04259ee35df7f7",
  "hostname" : "fedora",
  "os_pretty_name" : "Fedora 19 (Rawhide)",
  "virtualization" : "kvm",
  ...}

Añadido en la versión 197.

/fields/NOMBRE_CAMPO

Devuelve una lista de valores de este campo presentes en los logs.

Añadido en la versión 197.

CABECERA ACCEPT

Accept: formato

Formatos reconocidos:

text/plain

El predeterminado. Salida de texto similar a syslog, una línea por entrada del journal (como journalctl --output short).

Añadido en la versión 197.

application/json

Las entradas se formatean como estructuras de datos JSON, una por línea (como journalctl --output json). Consulte Formato JSON del Journal[1] para más información.

Añadido en la versión 197.

text/event-stream

Las entradas se formatean como estructuras de datos JSON, envueltas en un formato adecuado para Server-Sent Events[2] (como journalctl --output json-sse).

Añadido en la versión 229.

application/vnd.fdo.journal

Las entradas se serializan en un stream binario (pero en su mayoría basado en texto) adecuado para copias de seguridad y transferencia de red (como journalctl --output export). Consulte Formato de Exportación del Journal[3] para más información.

Añadido en la versión 197.

CABECERA RANGE

Range: entries=[cursor][[:num_skip]:[num_entries]]

Range: realtime=[desde]:[hasta][[:num_skip]:num_entries]

donde cursor es una cadena de cursor, por defecto la primera entrada, desde y hasta son marcas de tiempo (segundos desde 1970-01-01 00:00:00 UTC), num_skip es un entero, num_entries es un entero sin signo.

Range por defecto son todos los eventos disponibles.

Si num_skip es negativo y no se proporciona cursor, la última entrada será el punto de referencia.

PARAMETROS GET URL

Los siguientes parámetros se pueden usar como parte de la URL:

follow

espera nuevos eventos (como journalctl --follow, el número de eventos devueltos no está limitado, a menos que se especifique num_entries en la cabecera Range).

Añadido en la versión 197.

discrete

Comprueba que el cursor especificado se refiere a una entrada en el journal. Devuelve solo esta entrada.

Añadido en la versión 197.

boot

Limita los eventos al arranque actual del sistema (como journalctl -b).

Añadido en la versión 197.

CLAVE=coincidencia

Coincide con los campos del journal. Consulte systemd.journal-fields(7).

Añadido en la versión 197.

EJEMPLOS

Recupera eventos de este arranque del journal local en Formato de Exportación del Journal[3]:

curl --silent -H'Accept: application/vnd.fdo.journal' \
       'http://localhost:19531/entries?boot'

Escucha volcados del núcleo:

curl 'http://localhost:19531/entries?follow&MESSAGE_ID=fc2e22bc6ee6

También se puede enviar un evento POST con el cuerpo del mensaje:

curl -X POST --data-binary @/dev/log \
       'http://localhost:19531/entries'

Más información:

curl http://localhost:19531/browse

Obtener un par de claves y certificados de ejemplo:

mkdir -p /tmp/gateway
openssl req -x509 -newkey rsa:2048 -nodes -keyout /tmp/gateway/server.key \
          -out /tmp/gateway/server.crt -days 365 \
          -subj '/CN=localhost'
systemctl start systemd-journal-gatewayd.socket
systemctl edit systemd-journal-gatewayd.service
# Add the following lines:
# [Service]
# ExecStart=
# ExecStart=/usr/lib/systemd/systemd-journal-gatewayd --cert=/tmp/gateway/server.crt --key=/tmp/gateway/server.key
# Save and exit
systemctl daemon-reload
systemctl restart systemd-journal-gatewayd.service
curl --cacert /tmp/gateway/server.crt \
     https://localhost:19531/entries

VERSIÓN

El comando systemd-journal-gatewayd está disponible en systemd versión 197 y posteriores.

Las opciones --cert=, --key= y las URLs /boots, /machine, /fields/, application/json, application/vnd.fdo.journal y text/plain están disponibles en systemd versión 197 y posteriores.

La opción --trust= está disponible en systemd versión 236 y posteriores.

Las opciones -D, --directory= está disponible en systemd versión 232 y posteriores.

La opción text/event-stream está disponible en systemd versión 229 y posteriores.

Las opciones --system, --user, -m, --merge y --file= están disponibles en systemd versión 249 y posteriores.
