SYSTEMD-JOURNAL-UPLOAD.SERVICE(8) systemd-journal-upload.service SYSTEMD-JOURNAL-UPLOAD.SERVICE(8)

NOMBRE

systemd-journal-upload.service, systemd-journal-upload - Enviar mensajes del journal a través de la red

SINOPSIS

systemd-journal-upload.service

/usr/lib/systemd/systemd-journal-upload [OPCIONES...] [-u/--url=URL] [FUENTES...]

DESCRIPCIÓN

systemd-journal-upload cargará entradas del journal en la URL especificada con --url=. Este programa lee entradas del journal de uno o más archivos del journal, de forma similar a journalctl(1). A menos que se limite por una de las opciones especificadas a continuación, se cargarán todas las entradas del journal accesibles para el usuario con el que se ejecuta el programa, y luego el programa esperará y enviará nuevas entradas a medida que estén disponibles.

systemd-journal-upload transfiere el contenido bruto del archivo del journal y utiliza HTTP como protocolo de transporte.

systemd-journal-upload.service es un servicio del sistema que utiliza systemd-journal-upload para cargar entradas del journal a un servidor. Utiliza la configuración en journal-upload.conf(5). Debe especificarse al menos la opción URL=.

OPCIONES

-u, --url=[https://]URL[:PUERTO], --url=[http://]URL[:PUERTO]

Carga a la dirección especificada. URL puede especificar solo el nombre de host o tanto el protocolo como el nombre de host. https es el valor predeterminado. El número de puerto se puede especificar después de dos puntos (":"), de lo contrario, se utilizará 19532 por defecto.

Añadido en la versión 239.

--system, --user

Limita las entradas cargadas a las entradas de servicios del sistema y del kernel, o a las entradas de los servicios del usuario actual. Esto tiene el mismo significado que las opciones --system y --user para journalctl(1). Si no se especifica ninguna, se cargan todas las entradas accesibles.

Añadido en la versión 239.

-m, --merge

Carga entradas intercaladas de todos los journals disponibles, incluyendo otras máquinas. Esto tiene el mismo significado que la opción --merge para journalctl(1).

Añadido en la versión 239.

--namespace=NAMESPACE

Toma un identificador de namespace del journal como argumento. Carga entradas del namespace del journal especificado NAMESPACE en lugar del namespace predeterminado. Esto tiene el mismo significado que la opción --namespace= para journalctl(1).

Añadido en la versión 254.

-D, --directory=DIR

Toma una ruta de directorio como argumento. Carga entradas del directorio del journal especificado DIR en lugar de las rutas del journal del sistema y en tiempo de ejecución predeterminadas. Esto tiene el mismo significado que la opción --directory= para journalctl(1).

Añadido en la versión 239.

--file=GLOB

Toma un patrón de archivo como argumento. Carga entradas de los archivos del journal especificados que coincidan con GLOB en lugar de las rutas del journal del sistema y en tiempo de ejecución predeterminadas. Se puede especificar varias veces, en cuyo caso los archivos se intercalarán adecuadamente. Esto tiene el mismo significado que la opción --file= para journalctl(1).

Añadido en la versión 239.

--cursor=

Carga entradas desde la ubicación en el journal especificada por el cursor pasado. Esto tiene el mismo significado que la opción --cursor= para journalctl(1).

Añadido en la versión 239.

--after-cursor=

Carga entradas desde la ubicación en el journal después de la ubicación especificada por este cursor. Esto tiene el mismo significado que la opción --after-cursor= para journalctl(1).

Añadido en la versión 239.

--save-state[=PATH]

Carga entradas desde la ubicación en el journal después de la ubicación especificada por el cursor guardado en el archivo en PATH (/var/lib/systemd/journal-upload/state por defecto). Después de que una entrada se carga con éxito, actualiza este archivo con el cursor de esa entrada.

Añadido en la versión 239.

--follow[=BOOL]

Si se establece en sí, entonces systemd-journal-upload espera entrada.

Añadido en la versión 239.

--key=

Toma una ruta a un archivo de clave SSL en formato PEM, o -. Si se establece -, la verificación de autenticación del certificado del cliente se deshabilitará. Predeterminado a /etc/ssl/private/journal-upload.pem.

Añadido en la versión 239.

--cert=

Toma una ruta a un archivo de certificado SSL en formato PEM, o -. Si se establece -, la verificación de autenticación del certificado del cliente se deshabilitará. Predeterminado a /etc/ssl/certs/journal-upload.pem.

Añadido en la versión 239.

--trust=

Toma una ruta a un archivo de certificado CA SSL en formato PEM, o -/all. Si se establece -/all, la verificación del certificado se deshabilitará. Predeterminado a /etc/ssl/ca/trusted.pem.

Añadido en la versión 239.

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.

CÓDIGO DE SALIDA

En caso de éxito, se devuelve 0; de lo contrario, se devuelve un código de error distinto de cero.

EJEMPLOS

Ejemplo 1. Configuración de certificados para autenticación

Se utilizan certificados firmados por una autoridad confiable para verificar que el servidor al que se cargan los mensajes es legítimo y, a la inversa, que el cliente es confiable.

Un conjunto adecuado de certificados se puede generar con openssl. Tenga en cuenta que se recomienda una longitud de clave de 2048 bits como mínimo por razones de seguridad:

openssl req -newkey rsa:2048 -days 3650 -x509 -nodes \
      -out ca.pem -keyout ca.key -subj '/CN=Autoridad de Certificado/'
cat >ca.conf <<EOF
[ ca ]
default_ca = this
[ this ]
new_certs_dir = .
certificate = ca.pem
database = ./index
private_key = ca.key
serial = ./serial
default_days = 3650
default_md = default
policy = policy_anything
[ policy_anything ]
countryName             = optional
stateOrProvinceName     = optional
localityName            = optional
organizationName        = optional
organizationalUnitName  = optional
commonName              = supplied
emailAddress            = optional
EOF
touch index
echo 0001 >serial
SERVER=servidor
CLIENT=cliente
openssl req -newkey rsa:2048 -nodes -out $SERVER.csr -keyout $SERVER.key -subj "/CN=$SERVER/"
openssl ca -batch -config ca.conf -notext -in $SERVER.csr -out $SERVER.pem
openssl req -newkey rsa:2048 -nodes -out $CLIENT.csr -keyout $CLIENT.key -subj "/CN=$CLIENT/"
openssl ca -batch -config ca.conf -notext -in $CLIENT.csr -out $CLIENT.pem

Los archivos generados ca.pem, server.pem y server.key deben instalarse en el servidor, y ca.pem, client.pem y client.key en el cliente. La ubicación de esos archivos se puede especificar usando TrustedCertificateFile=, ServerCertificateFile= y ServerKeyFile= en /etc/systemd/journal-remote.conf y /etc/systemd/journal-upload.conf, respectivamente. Las ubicaciones predeterminadas se pueden consultar utilizando systemd-journal-remote --help y systemd-journal-upload --help.
