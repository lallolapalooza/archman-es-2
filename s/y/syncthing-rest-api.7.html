NOMBRE

syncthing-rest-api - API REST

Syncthing expone una interfaz REST sobre HTTP en el puerto de la GUI. Esta es utilizada por la GUI (desde Javascript) y puede ser utilizada por otros procesos que deseen controlar Syncthing. En la mayoría de los casos, tanto los datos de entrada como los de salida están en formato JSON. La interfaz está sujeta a cambios.

CLAVE API

Para usar la API REST, se debe configurar y usar una clave API. La clave API se puede generar en la GUI, o establecer en el elemento configuration/gui/apikey en el archivo de configuración. Para usar una clave API, establezca la cabecera de la solicitud X-API-Key con el valor de la clave API, o establécela como un token Bearer en la cabecera Authorization. Por ejemplo, curl -X POST -H "X-API-Key: abc123" http://localhost:8384/rest/... o curl -X POST -H "Authorization: Bearer abc123" http://localhost:8384/rest/... se pueden usar para invocar con curl (añada el indicador -k al usar HTTPS con un certificado autogenerado o autofirmado por Syncthing).

Una excepción a este requisito es /rest/noauth, no necesita una clave API para usar esos puntos finales. De esta manera, dispositivos y servicios de terceros pueden realizar llamadas simples que no exponen información sensible sin tener que exponer su clave API.

PAGINACIÓN DE RESULTADOS

Algunos puntos finales de GET aceptan argumentos opcionales page y perpage para la paginación. No se devuelven más de perpage (por defecto 65536 si no se proporciona) entradas de resultado en una matriz. Para acceder a entradas adicionales, pasar el parámetro page avanzará en los resultados por ese número de páginas. Los parámetros realmente utilizados siempre se devuelven como atributos en el objeto de respuesta.

POST   /rest/system/config (OBSOLETO)


Obsoleto desde la versión v1.12.0: este endpoint todavía funciona como antes pero está obsoleto. Usa Endpoints de Configuración en su lugar.


Publica el contenido completo de la configuración, en el mismo formato que devuelve la solicitud GET correspondiente. Cuando la publicación de la configuración tiene éxito, la configuración publicada se aplica inmediatamente, excepto los cambios que requieren un reinicio. Consulta /rest/config/restart-required para verificar si se requiere un reinicio.


Este endpoint es el punto principal para controlar Syncthing, incluso si el cambio solo se refiere a una parte muy pequeña de la configuración: el flujo de trabajo habitual es obtener la configuración, modificar las partes necesarias y volver a publicarla.

POST   /rest/system/pause


Pausa el dispositivo dado o todos los dispositivos.


Toma el parámetro opcional device (ID del dispositivo). Cuando
    se omite, pausa todos los dispositivos. Devuelve el estado 200 y sin contenido al éxito,
    o el estado 500 y un error en texto plano al fallar.

POST   /rest/system/reset


Publica con cuerpo vacío para borrar la base de datos de índice actual y
    reiniciar Syncthing. Sin parámetros de consulta, se borra toda la base de datos
    del disco. Especificando el parámetro folder con un ID de carpeta válido,
    solo se borrará la información de esa carpeta:






curl -X POST -H "X-API-Key: abc123" http://localhost:8384/rest/system/reset?folder=ab1c2-def3g






Precaución: Ver --reset-database para el efecto secundario de
    creación de .stfolder y precauciones relativas a los puntos de montaje.






POST   /rest/system/restart


Publica con cuerpo vacío para reiniciar Syncthing inmediatamente.






POST   /rest/system/resume


Reanuda el dispositivo dado o todos los dispositivos.


Toma el parámetro opcional device (ID del dispositivo). Cuando
    se omite, reanuda todos los dispositivos. Devuelve el estado 200 y sin contenido al éxito,
    o el estado 500 y un error en texto plano al fallar.






POST   /rest/system/shutdown


Publica con cuerpo vacío para que Syncthing salga y no se reinicie.

CONFIG ENDPOINTS

Config Endpoints

Added in version 1.12.0.

These endpoints facilitate access and modification of the configuration in a granular way. Config sent to the endpoints must be in the same format as returned by the corresponding GET request. When posting the configuration succeeds, the posted configuration is immediately applied, except for changes that require a restart. Query /rest/config/restart-required to check if a restart is required.

For all endpoints supporting PATCH, it takes the existing config and unmarshals the given JSON object on top of it. This means all child objects will replace the existing objects, not extend them. For example for RawListenAddresses in options, which is an array of strings, sending {RawListenAddresses: ["tcp://10.0.0.2"]} will replace all existing listen addresses.

/rest/config

GET returns the entire config and PUT replaces it.

/rest/config/restart-required

GET returns whether a restart of Syncthing is required for the current config to take effect.

/rest/config/folders, /rest/config/devices

GET returns all folders respectively devices as an array. PUT takes an array and POST a single object. In both cases if a given folder/device already exists, it’s replaced, otherwise a new one is added.

/rest/config/folders/*id*, /rest/config/devices/*id*

Put the desired folder- respectively device-ID in place of *id*. GET returns the folder/device for the given ID, PUT replaces the entire config, PATCH replaces only the given child objects and DELETE removes the folder/device.

/rest/config/defaults/folder, /rest/config/defaults/device

GET returns a template folder / device configuration object with all default values, which only needs a unique ID to be applied. PUT replaces the default config (omitted values are reset to the hard-coded defaults), PATCH replaces only the given child objects.

/rest/config/defaults/ignores

Added in version 1.19.0.

GET returns an object with a single lines attribute listing ignore patterns to be used by default on folders, as an array of single-line strings. PUT replaces the default ignore patterns from an object of the same format.

/rest/config/options, /rest/config/ldap, /rest/config/gui

GET returns the respective object, PUT replaces the entire object and PATCH replaces only the given child objects.

NOTE:

The gui.password configuration option has special handling to accept already hashed passwords. Any valid bcrypt hash is stored verbatim, while a plaintext password is first hashed.

GET /rest/db/ignores

Toma un parámetro, folder, y devuelve el contenido del como el campo ignore. Un segundo campo, expanded, proporciona una lista de cadenas que representan patrones de globbing descritos por gobwas/glob (basados en comodines estándar) que coinciden con los patrones en .stignore y todas las inclusiones. EVENT ENDPOINTS

GET /rest/events

To receive events, perform a HTTP GET of /rest/events.

To filter the event list, in effect creating a specific subscription for only the desired event types, add a parameter events=EventTypeA,EventTypeB,... where the event types are any of the Event Types. If no filter is specified, all events except LocalChangeDetected and RemoteChangeDetected are included.

The optional parameter since=<lastSeenID> sets the ID of the last event you’ve already seen. Syncthing returns a JSON encoded array of event objects, starting at the event just after the one with this last seen ID. The default value is 0, which returns all events. There is a limit to the number of events buffered, so if the rate of events is high or the time between polling calls is long some events might be missed. This can be detected by noting a discontinuity in the event IDs.

If no new events are produced since <lastSeenID>, the HTTP call blocks and waits for new events to happen before returning. If <lastSeenID> is a future ID, the HTTP call blocks until such ID is reached or timeouts. By default it times out after 60 seconds returning an empty array. The time out duration can be customized with the optional parameter timeout=<seconds>.

To receive only a limited number of events, add the limit=<n> parameter with a suitable value for n and only the last n events will be returned. This can be used to catch up with the latest event ID after a disconnection for example: /rest/events?since=0&limit=1.

GET /rest/events/disk

This convenience endpoint provides the same event stream, but pre-filtered to show only LocalChangeDetected and RemoteChangeDetected event types. The events parameter is not used.
