NAME

syscalls - Llamadas al sistema de Linux

SYNOPSIS

Llamadas al sistema de Linux.

DESCRIPTION

La llamada al sistema es la interfaz fundamental entre una aplicación y el kernel de Linux.

Llamadas al sistema y funciones envoltorio de la biblioteca

Las llamadas al sistema generalmente no se invocan directamente, sino a través de funciones envoltorio en glibc (o quizás alguna otra biblioteca). Para detalles sobre la invocación directa de una llamada al sistema, ver intro(2). A menudo, pero no siempre, el nombre de la función envoltorio es el mismo que el nombre de la llamada al sistema que invoca. Por ejemplo, glibc contiene una función chdir() que invoca la llamada al sistema subyacente "chdir".

A menudo, la función envoltorio de glibc es bastante delgada, haciendo poco trabajo más allá de copiar los argumentos a los registros correctos antes de invocar la llamada al sistema, y luego configurar errno adecuadamente después de que la llamada al sistema ha retornado. (Estos son los mismos pasos que realiza syscall(2), que se puede usar para invocar llamadas al sistema para las cuales no se proporciona una función envoltorio.) Nota: las llamadas al sistema indican un fallo devolviendo un número de error negativo al llamador en arquitecturas sin un registro/bandera de error separado, como se indica en syscall(2); cuando esto sucede, la función envoltorio niega el número de error devuelto (para hacerlo positivo), lo copia a errno y devuelve -1 al llamador de la función envoltorio.

Sin embargo, a veces la función envoltorio realiza algún trabajo adicional antes de invocar la llamada al sistema. Por ejemplo, hoy en día existen (por razones descritas a continuación) dos llamadas al sistema relacionadas, truncate(2) y truncate64(2), y la función envoltorio truncate() de glibc verifica qué llamadas al sistema son proporcionadas por el kernel y determina cuál debe ser empleada.

Lista de llamadas al sistema

A continuación se presenta una lista de las llamadas al sistema de Linux. En la lista, la columna Kernel indica la versión del kernel para aquellas llamadas al sistema que eran nuevas en Linux 2.2, o han aparecido desde esa versión del kernel. Tenga en cuenta los siguientes puntos:

•
Donde no se indica ninguna versión del kernel, la llamada al sistema apareció en Linux 1.0 o anterior.
•
Donde una llamada al sistema está marcada como "1.2" esto significa que la llamada al sistema probablemente apareció en una versión del kernel Linux 1.1.x, y apareció por primera vez en un kernel estable con 1.2. (El desarrollo del kernel Linux 1.2 se inició desde una rama de Linux 1.0.6 a través de la serie de kernels inestables Linux 1.1.x.)
•
Donde una llamada al sistema está marcada como "2.0" esto significa que la llamada al sistema probablemente apareció en una versión Linux 1.3.x, y apareció por primera vez en un kernel estable con Linux 2.0. (El desarrollo del kernel Linux 2.0 se inició desde una rama de Linux 1.2.x, alrededor de Linux 1.2.10, a través de la serie de kernels inestables Linux 1.3.x.)
•
Donde una llamada al sistema está marcada como "2.2" esto significa que la llamada al sistema probablemente apareció en una versión Linux 2.1.x, y apareció por primera vez en un kernel estable con Linux 2.2.0. (El desarrollo del kernel Linux 2.2 se inició desde una rama de Linux 2.0.21 a través de la serie de kernels inestables Linux 2.1.x.)
•
Donde una llamada al sistema está marcada como "2.4" esto significa que la llamada al sistema probablemente apareció en una versión Linux 2.3.x, y apareció por primera vez en un kernel estable con Linux 2.4.0. (El desarrollo del kernel Linux 2.4 se inició desde una rama de Linux 2.2.8 a través de la serie de kernels inestables Linux 2.3.x.)
•
Donde una llamada al sistema está marcada como "2.6" esto significa que la llamada al sistema probablemente apareció en una versión Linux 2.5.x, y apareció por primera vez en un kernel estable con Linux 2.6.0. (El desarrollo de Linux 2.6 se inició desde una rama de Linux 2.4.15 a través de la serie de kernels inestables Linux 2.5.x.)
•
A partir de Linux 2.6.0, el modelo de desarrollo cambió, y nuevas llamadas al sistema pueden aparecer en cada lanzamiento de Linux 2.6.x. En este caso, se muestra el número exacto de versión en el que apareció la llamada al sistema. Esta convención continúa con la serie de kernels Linux 3.x, que siguió a Linux 2.6.39; y la serie de kernels Linux 4.x, que siguió a Linux 3.19; y la serie de kernels Linux 5.x, que siguió a Linux 4.20; y la serie de kernels Linux 6.x, que siguió a Linux 5.19.
•
En algunos casos, una llamada al sistema se añadió a una serie de kernel estable después de que se ramificara desde la serie de kernel estable anterior, y luego se retroportó a la serie de kernel estable anterior. Por ejemplo, algunas llamadas al sistema que aparecieron en Linux 2.6.x también se retroportaron a un lanzamiento de Linux 2.4.x después de Linux 2.4.15. Cuando esto sucede, se enumera la versión en la que apareció la llamada al sistema en ambas series principales de kernel.

La lista de llamadas al sistema que están disponibles a partir de Linux 5.14 (o en unos pocos casos solo en kernels más antiguos) es la siguiente:

DESCRIPTION

System calls are the interfaces between user programs and the Linux kernel. They are implemented as kernel routines that are named sys_xxx(). There are many exceptions, however, mostly because older system calls were superseded by newer ones, and this has been treated somewhat unsystematically. On platforms with proprietary operating-system emulation, such as sparc, sparc64, and alpha, there are many additional system calls; mips64 also contains a full set of 32-bit system calls.

Over time, changes to the interfaces of some system calls have been necessary. One reason for such changes was the need to increase the size of structures or scalar values passed to the system call. Because of these changes, certain architectures (notably, longstanding 32-bit architectures such as i386) now have various groups of related system calls (e.g., truncate(2) and truncate64(2)) which perform similar tasks, but which vary in details such as the size of their arguments. (As noted earlier, applications are generally unaware of this: the glibc wrapper functions do some work to ensure that the right system call is invoked, and that ABI compatibility is preserved for old binaries.) Examples of system calls that exist in multiple versions are the following:

•
By now there are three different versions of stat(2): sys_stat() (slot __NR_oldstat), sys_newstat() (slot __NR_stat), and sys_stat64() (slot __NR_stat64), with the last being the most current. A similar story applies for lstat(2) and fstat(2).
•
Similarly, the defines __NR_oldolduname, __NR_olduname, and __NR_uname refer to the routines sys_olduname(), sys_uname(), and sys_newuname().
•
In Linux 2.0, a new version of vm86(2) appeared, with the old and the new kernel routines being named sys_vm86old() and sys_vm86().
•
In Linux 2.4, a new version of getrlimit(2) appeared, with the old and the new kernel routines being named sys_old_getrlimit() (slot __NR_getrlimit) and sys_getrlimit() (slot __NR_ugetrlimit).
•
Linux 2.4 increased the size of user and group IDs from 16 to 32 bits. To support this change, a range of system calls were added (e.g., chown32(2), getuid32(2), getgroups32(2), setresuid32(2)), superseding earlier calls of the same name without the "32" suffix.
•
Linux 2.4 added support for applications on 32-bit architectures to access large files (i.e., files for which the sizes and file offsets can't be represented in 32 bits.) To support this change, replacements were required for system calls that deal with file offsets and sizes. Thus the following system calls were added: fcntl64(2), getdents64(2), stat64(2), statfs64(2), truncate64(2), and their analogs that work with file descriptors or symbolic links. These system calls supersede the older system calls which, except in the case of the "stat" calls, have the same name without the "64" suffix.
On newer platforms that only have 64-bit file access and 32-bit UIDs/GIDs (e.g., alpha, ia64, s390x, x86-64), there is just a single version of the UID/GID and file access system calls. On platforms (typically, 32-bit platforms) where the *64 and *32 calls exist, the other versions are obsolete.
•
The rt_sig* calls were added in Linux 2.2 to support the addition of real-time signals (see signal(7)). These system calls supersede the older system calls of the same name without the "rt_" prefix.
•
The select(2) and mmap(2) system calls use five or more arguments, which caused problems in the way argument passing on the i386 used to be set up. Thus, while other architectures have sys_select() and sys_mmap() corresponding to __NR_select and __NR_mmap, on i386 one finds old_select() and old_mmap() (routines that use a pointer to an argument block) instead. These days passing five arguments is not a problem any more, and there is a __NR__newselect that corresponds directly to sys_select() and similarly __NR_mmap2. s390x is the only 64-bit architecture that has old_mmap().
