SYSTEMD-MOUNT(1) systemd-mount SYSTEMD-MOUNT(1)

NOMBRE

systemd-mount, systemd-umount - Establecer y destruir puntos de montaje o puntos de montaje automático transitorios

SINOPSIS

systemd-mount [OPCIONES...] QUÉ [DÓNDE]

systemd-mount [OPCIONES...] --tmpfs [NOMBRE] DÓNDE

systemd-mount [OPCIONES...] --list

systemd-mount [OPCIONES...] --umount QUÉ|DÓNDE...

DESCRIPCIÓN

systemd-mount puede ser utilizado para crear e iniciar una unidad .mount o .automount transitoria del sistema de archivos QUÉ en el punto de montaje DÓNDE.

En muchos sentidos, systemd-mount es similar al comando de bajo nivel mount(8), sin embargo, en lugar de ejecutar la operación de montaje directamente e inmediatamente, systemd-mount la programa a través de la cola de trabajos del gestor de servicios, de modo que pueda incluir dependencias adicionales (como montajes padres, o un verificador de sistemas de archivos para ejecutar a priori), y pueda hacer uso de la lógica de montaje automático.

El comando toma uno o dos argumentos. Si solo se especifica un argumento, debe referirse a un dispositivo de bloque o archivo regular que contenga un sistema de archivos (por ejemplo, "/dev/sdb1" o "/ruta/a/disco.img"). El dispositivo de bloque o el archivo de imagen se sondean para obtener una etiqueta del sistema de archivos y otros metadatos, y se montan en un directorio debajo de /run/media/system/ cuyo nombre se genera a partir de la etiqueta del sistema de archivos. En este modo, el dispositivo de bloque o el archivo de imagen debe existir en el momento de la invocación del comando, para que pueda ser sondeado. Si se encuentra que el dispositivo es un dispositivo de bloque extraíble (por ejemplo, una memoria USB), se crea un punto de montaje automático en lugar de un punto de montaje regular (es decir, se implica la opción --automount=, ver más abajo). Si se especifica la opción --tmpfs, el argumento se interpreta como la ruta donde se montará el nuevo sistema de archivos temporal.

Si se especifican dos argumentos, el primero indica la fuente del montaje (el QUÉ) y el segundo indica la ruta donde montarlo (el DÓNDE). En este modo no se intenta sondear la fuente, y no es necesario que exista un nodo de dispositivo subyacente. Sin embargo, si este modo se combina con --discover, se habilita el sondeo del nodo del dispositivo para metadatos adicionales y —de manera muy similar al caso de un solo argumento discutido anteriormente— el dispositivo especificado debe existir en el momento de la invocación del comando.

Use el comando --list para mostrar una tabla concisa de todos los dispositivos de bloque locales conocidos con sistemas de archivos que se pueden montar con este comando.

systemd-umount puede usarse para desmontar un punto de montaje o punto de montaje automático. Es lo mismo que systemd-mount --umount.

OPCIONES

Se entienden las siguientes opciones:

--no-block

No espere de forma síncrona a que la operación solicitada finalice. Si no se especifica, el trabajo se verificará, se pondrá en cola y systemd-mount esperará hasta que se complete el inicio de la unidad de montaje o montaje automático. Al pasar este argumento, solo se verifica y se pone en cola.

Añadido en la versión 232.

-l, --full

No elimine el contenido de la salida cuando se especifique --list.

Añadido en la versión 245.

--no-pager

No envíe la salida a un paginador.

--no-legend

No imprima la leyenda, es decir, los encabezados de columna y el pie de página con sugerencias.

--no-ask-password

No consulte al usuario para autenticación en operaciones privilegiadas.

--json=MODO

Muestra la salida formateada como JSON. Espera uno de "short" (para la salida más corta posible sin espacios en blanco redundantes ni saltos de línea), "pretty" (para una versión bonita de lo mismo, con indentación y saltos de línea) o "off" (para desactivar la salida JSON, el valor predeterminado).

--quiet, -q

Suprime la salida informativa adicional mientras se ejecuta.

Añadido en la versión 232.

--discover

Habilita el sondeo de la fuente de montaje. Este interruptor se implica si se especifica un solo argumento en la línea de comandos. Si se pasa, se leen metadatos adicionales del dispositivo para mejorar la unidad a crear. Por ejemplo, se genera una cadena descriptiva para las unidades transitorias a partir de la etiqueta del sistema de archivos y el modelo del dispositivo. Además, si se detecta un dispositivo de bloque extraíble (por ejemplo, una memoria USB), se crea una unidad de montaje automático en lugar de una unidad de montaje regular, con un tiempo de espera corto, para garantizar que el sistema de archivos se coloque en un estado limpio rápidamente después de cada acceso.

Añadido en la versión 232.

--type=, -t

Especifica el tipo de sistema de archivos a montar (por ejemplo, "vfat" o "ext4"). Si se omite o se establece en "auto", el tipo de sistema de archivos se determina automáticamente.

Añadido en la versión 232.

--options=, -o

Opciones de montaje adicionales para el punto de montaje.

Añadido en la versión 232.

--owner=USUARIO

Permite que el usuario especificado USUARIO sea el propietario del sistema de archivos montado. Esto se hace añadiendo opciones uid= y gid= a la lista de opciones de montaje. Solo ciertos sistemas de archivos admiten esta opción.

Añadido en la versión 237.

--fsck=

Toma un argumento booleano, por defecto activado. Controla si se ejecuta una verificación del sistema de archivos inmediatamente antes de la operación de montaje. En el caso de montaje automático (ver --automount= abajo) la verificación se ejecutará en el momento en que se realice el primer acceso al dispositivo, lo que podría retrasar ligeramente el acceso.

Añadido en la versión 232.

--description=

Proporciona una descripción para la unidad de montaje o montaje automático. Consulte Description= en systemd.unit(5).

Añadido en la versión 232.

--property=, -p

Establece una propiedad de unidad para la unidad de montaje que se crea. Esto toma una asignación en el mismo formato que el comando set-property de systemctl(1).

Añadido en la versión 232.

--automount=

Toma un argumento booleano. Controla si se crea un punto de montaje automático o un punto de montaje regular. Si es verdadero, se crea un punto de montaje automático que está respaldado por el sistema de archivos real en el momento del primer acceso. Si es falso, se crea un punto de montaje simple que está respaldado por el sistema de archivos real inmediatamente. Los puntos de montaje automático tienen el beneficio de que el sistema de archivos permanece desmontado y, por lo tanto, en estado limpio hasta que se accede a él por primera vez. En el modo de montaje automático, el interruptor --timeout-idle-sec= (ver más abajo) puede usarse para asegurar que el punto de montaje se desmonte automáticamente después del último acceso y que haya pasado un período de inactividad.

Si este interruptor no se especifica, por defecto es falso. Si no se especifica y se utiliza --discover (o solo se pasa un argumento, lo que implica --discover, ver arriba), y se detecta que el dispositivo de bloque del sistema de archivos es extraíble, se establece en verdadero, para aumentar la posibilidad de que el sistema de archivos esté en un estado completamente limpio si el dispositivo se desconecta abruptamente.

Añadido en la versión 232.

-A

Equivalente a --automount=yes.

Añadido en la versión 232.

--timeout-idle-sec=

Toma un valor de tiempo que controla el tiempo de espera de inactividad en modo de montaje automático. Si se establece en "infinity" (el valor predeterminado), no se realizan desmontajes automáticos. De lo contrario, el sistema de archivos que respalda el punto de montaje automático se desconecta después del último acceso y de que haya pasado el tiempo de espera de inactividad. Consulte systemd.time(7) para obtener detalles sobre la sintaxis de tiempo admitida. Esta opción no tiene ningún efecto si solo se establece un montaje regular y no se utiliza el montaje automático.

Tenga en cuenta que si se utiliza --discover (o solo se pasa un argumento, lo que implica --discover, ver arriba), y se detecta que el dispositivo de bloque del sistema de archivos es extraíble, se implica --timeout-idle-sec=1s.

Añadido en la versión 232.

--automount-property=

Similar a --property=, pero aplica propiedades adicionales a la unidad de montaje automático creada, en lugar de a la unidad de montaje.

Añadido en la versión 232.

Si se establece, las unidades se detendrán automáticamente cuando el dispositivo de respaldo desaparezca. Por defecto, la unidad de montaje automático permanece, y los accesos posteriores se bloquearán hasta que el dispositivo de respaldo se vuelva a conectar. Añadido en la versión 232.

--list

En lugar de establecer un punto de montaje o montaje automático, imprime una lista concisa de dispositivos de bloques que contienen sistemas de archivos que pueden montarse con "systemd-mount", junto con metadatos útiles como etiquetas, etc.

Añadido en la versión 232.

-u, --umount

Detiene las unidades de montaje y montaje automático correspondientes a los puntos de montaje especificados WHERE o a los dispositivos WHAT. systemd-mount con esta opción o systemd-umount puede aceptar varios argumentos que pueden ser puntos de montaje, dispositivos, nombres de nodos al estilo /etc/fstab o archivos de respaldo correspondientes a dispositivos loop, como systemd-mount --umount /ruta/para/desmontar /dev/sda1 UUID=xxxxxx-xxxx LABEL=xxxxx /ruta/al/disco.img. Tenga en cuenta que cuando se especifica -H o -M, solo se admiten rutas absolutas a los puntos de montaje.

Añadido en la versión 233.

-G, --collect

Descarga la unidad transitoria después de que se complete, incluso si falló. Normalmente, sin esta opción, todas las unidades de montaje que montaron y fallaron permanecen en memoria hasta que el usuario restablece explícitamente su estado de error con systemctl reset-failed o un comando equivalente. Por otro lado, las unidades que se detuvieron correctamente se descargan inmediatamente. Si esta opción está activada, la "recolección de basura" de unidades es más agresiva, y descarga unidades independientemente de si salieron con éxito o fallaron. Esta opción es un atajo para --property=CollectMode=inactive-or-failed, véase la explicación de CollectMode= en systemd.unit(5) para más información.

Añadido en la versión 236.

-T, --tmpfs

Crea y monta un nuevo sistema de archivos tmpfs en WHERE, con un NAME opcional que por defecto es "tmpfs".

El sistema de archivos se monta con el modo del directorio de nivel superior determinado por la configuración de umask(2) del llamante, es decir, rwxrwxrwx enmascarado por la umask del llamante. Esto coincide con lo que hace mkdir(1), pero es diferente del valor por defecto del kernel de "rwxrwxrwxt", es decir, un directorio de escritura universal con el bit sticky activado.

Añadido en la versión 255.

--canonicalize=

Controla si la ruta especificada debe ser canonicaizada en el lado del cliente antes de solicitar la operación o no. Acepta un parámetro booleano, por defecto es true. Tenga en cuenta que para operaciones no locales (es decir, cuando se utilizan --machine= o ----host=), la canonicaización se desactiva implícitamente.

La canonicaización de la ruta implica la resolución de enlaces simbólicos, elementos de ruta ".." y la expansión de nodos de dispositivo de estilo LABEL=/UUID=. Si la canonicaización está desactivada y la ruta contiene un elemento de enlace simbólico, "..", o una expansión LABEL=/UUID=/..., la operación fallará.

Añadido en la versión 258.

--user

Habla con el gestor de servicios del usuario que llama, en lugar del gestor de servicios del sistema.

--system

Habla con el gestor de servicios del sistema. Este es el valor por defecto implicado.

-H, --host=

Ejecuta la operación de forma remota. Especifica un nombre de host, o un nombre de usuario y un nombre de host separados por "@", al que conectarse. El nombre de host puede ir opcionalmente seguido de un puerto en el que SSH esté escuchando, separado por ":", y luego un nombre de contenedor, separado por "/", que se conecta directamente a un contenedor específico en el host especificado. Esto utilizará SSH para hablar con la instancia remota del gestor de máquinas. Los nombres de contenedores se pueden enumerar con machinectl -H HOST. Ponga las direcciones IPv6 entre corchetes.

-M, --machine=

Ejecuta la operación en un contenedor local. Especifica un nombre de contenedor al que conectarse, opcionalmente prefijado por un nombre de usuario para conectarse y un carácter separador "@". Si se utiliza la cadena especial ".host" en lugar del nombre del contenedor, se establece una conexión con el sistema local (lo que es útil para conectarse al bus de usuario de un usuario específico: "--user --machine=lennart@.host"). Si no se utiliza la sintaxis "@", la conexión se realiza como usuario root. Si se utiliza la sintaxis "@", cualquiera de los lados, izquierdo o derecho, puede omitirse (pero no ambos) en cuyo caso se implican el nombre de usuario local y ".host".

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.

ESTADO DE SALIDA

En caso de éxito, se devuelve 0, y en caso de error, un código de fallo distinto de cero.

LA BASE DE DATOS UDEV

Si se utiliza --discover, systemd-mount respeta algunas propiedades adicionales de udev de los dispositivos de bloques:

SYSTEMD_MOUNT_OPTIONS=

Las opciones de montaje a utilizar, si no se usa --options=.

Añadido en la versión 232.

SYSTEMD_MOUNT_WHERE=

La ruta del sistema de archivos donde colocar el punto de montaje, en lugar de la generada automáticamente.

Añadido en la versión 232.

EJEMPLO

Utilice una regla de udev como la siguiente para montar automáticamente todo el almacenamiento USB enchufado:

ACTION=="add", SUBSYSTEMS=="usb", SUBSYSTEM=="block", ENV{ID_FS_USAGE}=="filesystem", \
        RUN{program}+="/usr/bin/systemd-mount --no-block --automount=yes --collect $devnode"
