NOMBRE

systemd.environment-generator - generadores de archivos de entorno de systemd

SINOPSIS

/usr/lib/systemd/system-environment-generators/algun-generador

/usr/lib/systemd/user-environment-generators/algun-generador

/run/systemd/system-environment-generators/*
/etc/systemd/system-environment-generators/*
/usr/local/lib/systemd/system-environment-generators/*
/usr/lib/systemd/system-environment-generators/*
/run/systemd/user-environment-generators/*
/etc/systemd/user-environment-generators/*
/usr/local/lib/systemd/user-environment-generators/*
/usr/lib/systemd/user-environment-generators/*

DESCRIPCIÓN

Los generadores son pequeños ejecutables que residen en /usr/lib/systemd/system-environment-generators/ y otros directorios listados arriba. systemd(1) ejecutará estos binarios muy temprano al inicio de cada gestor y al momento de recargar la configuración, antes de ejecutar los generadores descritos en systemd.generator(7) y antes de iniciar cualquier unidad. Los generadores de entorno pueden sobrescribir el entorno que el gestor exporta a servicios y otros procesos.

Los generadores se cargan desde un conjunto de rutas determinadas durante la compilación, tal como se indica arriba. Los generadores de entorno del sistema y del usuario se cargan desde directorios cuyos nombres terminan en system-environment-generators/ y user-environment-generators/, respectivamente. Los generadores encontrados en directorios listados anteriormente anulan a los del mismo nombre en directorios más abajo en la lista [1]. Se puede usar un enlace simbólico a /dev/null o un archivo vacío para enmascarar un generador, evitando así su ejecución. Tenga en cuenta que el orden de los dos directorios con la mayor prioridad está invertido con respecto a la ruta de carga de unidades, y los generadores en /run/ sobrescriben a los de /etc/.

Después de instalar nuevos generadores o actualizar la configuración, se puede ejecutar systemctl daemon-reload. Esto volverá a ejecutar todos los generadores, actualizando la configuración del entorno. Se utilizará para cualquier servicio que se inicie posteriormente.

Los generadores de archivos de entorno se ejecutan de manera similar a los generadores de archivos de unidad descritos en systemd.generator(7), con las siguientes diferencias:

•Los generadores se ejecutan secuencialmente en el orden alfanumérico del componente final de su nombre. La salida de cada generador se analiza inmediatamente y se utiliza para actualizar el entorno de los generadores que se ejecutan después. Por lo tanto, los generadores posteriores pueden usar y/o modificar la salida de los generadores anteriores.
•Los generadores son ejecutados por cada instancia del gestor, su salida puede ser diferente para cada usuario.

Se recomienda usar prefijos numéricos para los nombres de los generadores para simplificar el ordenamiento.

EJEMPLOS

Ejemplo 1. Un generador simple que extiende una variable de entorno si existe un directorio en el sistema de archivos

#!/bin/sh
# SPDX-License-Identifier: MIT-0
# establece el valor predeterminado
XDG_DATA_DIRS="${XDG_DATA_DIRS:-/usr/local/share/:/usr/share}"
# añade un directorio si existe
if [ -d /opt/foo/share ]; then
    XDG_DATA_DIRS="/opt/foo/share:${XDG_DATA_DIRS}"
fi
# escribe nuestra salida
echo "XDG_DATA_DIRS=${XDG_DATA_DIRS}"

Ejemplo 2. Un generador más complicado que lee la configuración existente y muta una variable

#!/usr/bin/python
# SPDX-License-Identifier: MIT-0
"""
Generador de entorno systemd prueba de concepto que se asegura de que los
directorios bin siempre estén después de los directorios sbin correspondientes
en la ruta.
(Cambia /sbin:/bin:/foo/bar a /bin:/sbin:/foo/bar.)
Este generador muestra cómo anular la configuración posiblemente creada por
generadores anteriores. Sería más fácil escribirlo en bash, pero lo tenemos
en Python solo para demostrar que podemos, y para servir como plantilla para
generadores más interesantes.
"""
import os
import pathlib
def rearrange_bin_sbin(path):
    """Asegura que cualquier par de directorios .../bin, .../sbin esté en este orden
    >>> rearrange_bin_sbin('/bin:/sbin:/usr/sbin:/usr/bin')
    '/bin:/sbin:/usr/bin:/usr/sbin'
    """
    items = [pathlib.Path(p) for p in path.split(':')]
    for i in range(len(items)):
        if 'sbin' in items[i].parts:
            ind = items[i].parts.index('sbin')
            bin = pathlib.Path(*items[i].parts[:ind], 'bin', *items[i].parts[ind+1:])
            if bin in items[i+1:]:
                j = i + 1 + items[i+1:].index(bin)
                items[i], items[j] = items[j], items[i]
    return ':'.join(p.as_posix() for p in items)
if __name__ == '__main__':
    path = os.environ['PATH'] # Esto siempre debe estar establecido.
                              # Si no lo está, simplemente fallaremos, lo cual también está bien.
    new = rearrange_bin_sbin(path)
    if new != path:
        print('PATH={}'.format(new))
