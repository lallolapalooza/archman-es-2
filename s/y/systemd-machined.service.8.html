NOMBRE

systemd-machined.service, systemd-machined - Gestor de registro de máquinas virtuales y contenedores

SINOPSIS

systemd-machined.service

/usr/lib/systemd/systemd-machined

DESCRIPCIÓN

systemd-machined es un servicio del sistema que realiza un seguimiento de las máquinas virtuales y contenedores que se ejecutan localmente.

systemd-machined es útil para registrar y hacer un seguimiento tanto de contenedores de SO (contenedores que comparten el kernel del host pero ejecutan un sistema de init completo propio y se comportan en la mayoría de los aspectos como un sistema operativo virtual completo en lugar de solo una aplicación virtualizada) como de máquinas virtuales completas (hardware virtualizado que ejecuta sistemas operativos normales y posiblemente kernels diferentes).

systemd-machined no debe usarse para registrar/hacer un seguimiento de contenedores de sandbox de aplicaciones. Una máquina en el contexto de systemd-machined debe ser un término abstracto que cubra tanto los contenedores de SO como las máquinas virtuales completas, pero no los sandboxes de aplicaciones.

Las máquinas registradas con machined se exponen de varias maneras en el sistema. Por ejemplo:

•Herramientas como ps(1) mostrarán a qué máquina pertenece un proceso específico en una columna propia, al igual que lo harán gnome-system-monitor[1] o systemd-cgls(1).
•Las diversas herramientas de systemd (systemctl(1), journalctl(1), loginctl(1), hostnamectl(1), timedatectl(1), localectl(1), machinectl(1), ...) admiten el modificador -M para operar en contenedores locales en lugar del sistema host.
•systemctl list-machines mostrará el estado del sistema de todos los contenedores locales, conectándose al init system del contenedor para ello.
•El modificador --recursive de systemctl tiene el efecto de no solo mostrar los servicios que se ejecutan localmente, sino de mostrar recursivamente los servicios de todos los contenedores registrados.
•El comando machinectl proporciona acceso a un número de operaciones útiles en contenedores registrados, como introspeccionarlos, reiniciarlos, apagarlos y obtener un prompt de inicio de sesión en ellos.
•La biblioteca sd-bus(3) expone la llamada sd_bus_open_system_machine(3) para conectarse al bus del sistema de cualquier contenedor registrado.
•El módulo nss-mymachines(8) se asegura de que todos los contenedores registrados puedan resolverse a través de llamadas normales de glibc gethostbyname(3) o getaddrinfo(3).

Consulte systemd-nspawn(1) para ver algunos ejemplos sobre cómo ejecutar contenedores con herramientas del sistema.

Si está interesado en escribir un gestor de VM o contenedores que utilice machined, por favor, eche un vistazo a Escritura de Gestores de Máquinas Virtuales o Contenedores[2]. Consulte también las Nuevas Interfaces de Grupos de Control[3].

El demonio proporciona tanto una interfaz de biblioteca C (que se comparte con systemd-logind.service(8)) como una interfaz D-Bus y una interfaz Varlink. La interfaz de biblioteca puede usarse para introspeccionar y observar el estado de las máquinas virtuales/contenedores. La interfaz de bus proporciona lo mismo pero además puede usarse para registrar o terminar máquinas. La interfaz Varlink puede usarse para registrar máquinas con extensiones opcionales, por ejemplo, con una clave/dirección SSH; se puede consultar con varlinkctl introspect /run/systemd/machine/io.systemd.Machine io.systemd.Machine. Para más información, consulte sd-login(3) y org.freedesktop.machine1(5) y org.freedesktop.LogControl1(5).

Un pequeño demonio compañero systemd-importd.service(8) también está disponible, que implementa la importación, exportación y descarga de imágenes de contenedores y VM.

Para cada contenedor registrado con systemd-machined.service que utiliza el espacio de nombres de usuario, los usuarios/grupos se sintetizan para los UID/GID utilizados. Estos se ponen a disposición del sistema utilizando la API de búsqueda de registros de usuario/grupo a través de Varlink[4], y por lo tanto pueden resolverse con userdbctl(1) o las llamadas habituales de glibc NSS.
