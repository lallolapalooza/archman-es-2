NOMBRE

systemd.path - Configuración de unidades de ruta

SINOPSIS

ruta.path

DESCRIPCIÓN

Un archivo de configuración de unidad cuyo nombre termina en ".path" codifica información sobre una ruta monitorizada por systemd, para la activación basada en rutas.

Esta página del manual lista las opciones de configuración específicas para este tipo de unidad. Consulte systemd.unit(5) para las opciones comunes de todos los archivos de configuración de unidades. Los elementos de configuración comunes se configuran en las secciones genéricas [Unit] e [Install]. Las opciones de configuración específicas de la ruta se configuran en la sección [Path].

Para cada archivo de ruta, debe existir una unidad coincidente, que describa la unidad a activar cuando la ruta cambie. Por defecto, se activa un servicio con el mismo nombre que la ruta (excepto el sufijo). Ejemplo: un archivo de ruta foo.path activa un servicio coincidente foo.service. La unidad a activar puede ser controlada por Unit= (ver más abajo).

Internamente, las unidades de ruta utilizan la API de inotify(7) para monitorizar sistemas de archivos. Debido a eso, sufre las mismas limitaciones que inotify y, por ejemplo, no puede usarse para monitorizar archivos o directorios modificados por otras máquinas en sistemas de archivos NFS remotos.

Cuando una unidad de servicio activada por una unidad de ruta termina (independientemente de si salió con éxito o falló), las rutas monitorizadas se vuelven a comprobar inmediatamente y el servicio se reinicia instantáneamente. Como protección contra bucles intensivos en este ciclo de activación/inicio, se aplica un límite de velocidad de inicio a la unidad de servicio, consulte StartLimitIntervalSec= y StartLimitBurst= en systemd.unit(5). A diferencia de otros fallos de servicio, la condición de error de que se alcance el límite de velocidad de inicio se propaga de la unidad de servicio a la unidad de ruta y provoca que la unidad de ruta también falle, terminando así el bucle.

DEPENDENCIAS AUTOMÁTICAS

Dependencias Implícitas

Las siguientes dependencias se añaden implícitamente:

•Si una unidad de ruta está debajo de otra unidad de montaje en la jerarquía del sistema de archivos, se crea automáticamente una dependencia de requisito y de ordenación entre ambas unidades.
•Se añade una dependencia implícita de Before= entre una unidad de ruta y la unidad que se supone que debe activar.

Dependencias Predeterminadas

Las siguientes dependencias se añaden a menos que se establezca DefaultDependencies=no:

•Las unidades de ruta tendrán automáticamente dependencias de tipo Before= en paths.target, dependencias de tipo After= y Requires= en sysinit.target, y tendrán dependencias de tipo Conflicts= y Before= en shutdown.target. Esto asegura que las unidades de ruta se terminen limpiamente antes del apagado del sistema. Solo las unidades de ruta involucradas en el arranque temprano o el apagado tardío del sistema deben deshabilitar la opción DefaultDependencies=.

OPCIONES

Los archivos de unidad de ruta pueden incluir las secciones [Unit] e [Install], que se describen en systemd.unit(5).

Los archivos de unidad de ruta deben incluir una sección [Path], que contiene información sobre la ruta o rutas que monitoriza. Las opciones específicas de la sección [Path] de las unidades de ruta son las siguientes:

PathExists=, PathExistsGlob=, PathChanged=, PathModified=, DirectoryNotEmpty=

Define las rutas a monitorizar para ciertos cambios: PathExists= se puede usar para vigilar la mera existencia de un archivo o directorio. Si el archivo especificado existe, se activa la unidad configurada. PathExistsGlob= funciona de manera similar, pero comprueba la existencia de al menos un archivo que coincida con el patrón de globbing especificado. PathChanged= se puede usar para vigilar un archivo o directorio y activar la unidad configurada cada vez que cambie. No se activa en cada escritura al archivo vigilado, pero se activa si el archivo que estaba abierto para escritura se cierra. PathModified= es similar, pero además también se activa en escrituras simples al archivo vigilado. DirectoryNotEmpty= se puede usar para vigilar un directorio y activar la unidad configurada cada vez que contenga al menos un archivo.

Los argumentos de estas directivas deben ser rutas absolutas del sistema de archivos.

Se pueden combinar varias directivas, del mismo tipo y de tipos diferentes, para vigilar múltiples rutas. Si se asigna la cadena vacía a cualquiera de estas opciones, se restablece la lista de rutas a vigilar y cualquier asignación previa de estas opciones no tendrá ningún efecto.

Si la ruta en sí o cualquiera de los directorios que la contienen no son accesibles, systemd vigilará los cambios de permisos y notará que las condiciones se cumplen cuando los permisos lo permitan.

Tenga en cuenta que los archivos cuyo nombre comienza con un punto (es decir, archivos ocultos) generalmente se ignoran al monitorizar estas rutas.

Unit=

La unidad a activar cuando cualquiera de las rutas configuradas cambie. El argumento es un nombre de unidad, cuyo sufijo no es ".path". Si no se especifica, este valor por defecto es un servicio que tiene el mismo nombre que la unidad de ruta, excepto el sufijo. (Ver arriba.) Se recomienda que la unidad activada y la unidad de ruta tengan nombres idénticos, excepto el sufijo.

MakeDirectory=

Toma un argumento booleano. Si es verdadero, los directorios a vigilar se crean antes de la vigilancia. Esta opción se ignora para las configuraciones de PathExists=. Por defecto es false.

DirectoryMode=

Si MakeDirectory= está habilitado, use el modo especificado aquí para crear los directorios en cuestión. Toma un modo de acceso en notación octal. Por defecto es 0755.

TriggerLimitIntervalSec=, TriggerLimitBurst=

Configura un límite de cuántas veces esta unidad de ruta puede ser activada dentro de un intervalo de tiempo específico. TriggerLimitIntervalSec= se puede usar para configurar la longitud del intervalo de tiempo en las unidades de tiempo habituales "us", "ms", "s", "min", "h", ... y por defecto es 2s. Consulte systemd.time(7) para obtener detalles sobre las diversas unidades de tiempo que comprende. La configuración TriggerLimitBurst= toma un valor entero positivo y especifica el número de activaciones permitidas por intervalo de tiempo, y por defecto es 200. Establezca cualquiera de ellas a 0 para deshabilitar cualquier forma de limitación de velocidad de activación. Si se alcanza el límite, la unidad se pone en modo de fallo y ya no vigilará las rutas hasta que se reinicie. Tenga en cuenta que este límite se aplica antes de que se enfile la activación del servicio.

Añadido en la versión 250.

Consulte systemd.unit(5), systemd.exec(5) y systemd.kill(5) para más configuraciones.

VER TAMBIÉN

Las variables de entorno con detalles sobre el activador se establecerán para las unidades activadas. Consulte la sección "Variables de entorno establecidas o propagadas por el gestor de servicios" en systemd.exec(5) para obtener más detalles.
