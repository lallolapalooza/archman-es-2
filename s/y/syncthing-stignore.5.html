SYNCTHING-STIGNORE(5) Syncthing SYNCTHING-STIGNORE(5)

NOMBRE

syncthing-stignore - Evitar que los archivos se sincronicen con otros nodos

SINOPSIS

.stignore

DESCRIPCIÓN

Si algunos archivos no deben ser sincronizados (hacia o desde) otros dispositivos, se puede crear un archivo llamado .stignore que contenga patrones de archivos a ignorar. El archivo .stignore debe colocarse en la raíz de la carpeta sincronizada (los archivos en otras ubicaciones no se aplican). El archivo .stignore en sí nunca se sincronizará con otros dispositivos, aunque puede #include archivos que sí se sincronizan entre dispositivos. Todos los patrones son relativos a la raíz de la carpeta sincronizada. El contenido del archivo .stignore debe estar codificado en UTF-8.

NOTA:

Tenga en cuenta que los archivos ignorados pueden impedir la eliminación de un directorio que de otro modo estaría vacío. Consulte más abajo el prefijo (?d) para permitir la eliminación de archivos ignorados.

PATRONES

El archivo .stignore contiene una lista de patrones de archivos o rutas. El primer patrón que coincida determinará el destino de un archivo determinado.

  • Los nombres de archivo regulares coinciden consigo mismos, es decir, el patrón foo coincide con los archivos foo, subdir/foo así como con cualquier directorio llamado foo. Los espacios se tratan como caracteres regulares, excepto los espacios iniciales y finales, que se recortan automáticamente.
  • El asterisco (*) coincide con cero o más caracteres en un nombre de archivo, pero no coincide con el separador de directorios. te*ne coincide con telephone, subdir/telephone pero no con tele/phone.
  • El doble asterisco (**) coincide como se indica anteriormente, pero también con los separadores de directorios. te**ne coincide con telephone, subdir/telephone y tele/sub/dir/phone.
  • El signo de interrogación (?) coincide con un solo carácter que no sea el separador de directorios. te??st coincide con tebest pero no con teb/st o test.
  • Los corchetes ([]) denotan un rango de caracteres: [a-z] coincide con cualquier carácter en minúscula.
  • Las llaves ({}) denotan un conjunto de alternativas separadas por comas: {banana,piña} coincide con banana o piña.
  • La barra invertida (\) "escapa" un carácter especial para que pierda su significado especial. Por ejemplo, \{banana\} coincide exactamente con {banana} y no denota un conjunto de alternativas como se indica anteriormente.

    NOTA:

En Windows, \ es el separador de rutas, así que use | para escapar caracteres especiales. Por ejemplo, |{banana|} coincide con {banana}.

Para usar \ para escapar caracteres especiales (y usar / como separador de rutas), inserte un #escape=\ al principio del archivo. Aquí hay un breve ejemplo:

#escape=\
/foo
/path/bar/\{banana\}
/path/baz\[2\]/ex\[3\].txt

#escape=\ debe colocarse al principio del archivo, antes de cualquier patrón, pero los comentarios iniciales y las líneas en blanco están permitidos.

Cualquier archivo incluido usando #include (ver más abajo) necesitará su propio #escape=\.

Usar #escape=\ permite que el mismo archivo se sincronice y se use en cualquier sistema operativo.

  • Un patrón que comienza con / coincide solo en la raíz de la carpeta sincronizada. /foo coincide con foo pero no con subdir/foo.
  • Un patrón que comienza con #include resulta en la carga de patrones desde el archivo nombrado. Es un error si un archivo no existe o se incluye más de una vez. Tenga en cuenta que aunque esto se puede usar para incluir patrones de un archivo en un subdirectorio, los patrones en sí siguen siendo relativos a la raíz de la carpeta sincronizada. Ejemplo: #include more-patterns.txt.

    Cualquier directiva #include dentro de un archivo cargado por #include requiere que las rutas se especifiquen relativas al directorio que contiene el archivo cargado, en lugar del directorio raíz sincronizado.

  • Un patrón que comienza con un prefijo ! niega el patrón: los archivos coincidentes se incluyen (es decir, no se ignoran). Esto se puede usar para anular patrones más generales que siguen.

    NOTA:

Los patrones negados que pueden coincidir con elementos debajo de la raíz de la carpeta harán que Syncthing recorra directorios ignorados de otro modo. Si el observador está habilitado, esos directorios también serán observados. Sin embargo, los directorios ignorados antes del primer patrón negado pueden omitirse de forma segura, ya que el primer patrón coincidente gana. Por ejemplo: 
/foo
/bar
!baz
*

Los directorios foo y bar se ignorarán por completo. Sin embargo, todos los demás directorios presentes deben escanearse por completo para encontrar cualquier elemento llamado baz, a pesar de que serán ignorados debido al *. Como caso especial, los patrones con raíz de nivel superior (por ejemplo, !/foo) no causan este comportamiento:

!/baz
*

En este caso, solo se escaneará el directorio baz, ya que todo lo demás es ignorado por el patrón *.

  • Un patrón que comienza con un prefijo (?i) habilita la coincidencia de patrones sin distinción entre mayúsculas y minúsculas. (?i)test coincide con test, TEST y tEsT. El prefijo (?i) se puede combinar con otros patrones, por ejemplo, el patrón (?i)!picture*.png indica que Picture1.PNG debe sincronizarse. En Mac OS y Windows, los patrones no distinguen entre mayúsculas y minúsculas.
  • Un patrón que comienza con un prefijo (?d) habilita la eliminación de estos archivos si impiden la eliminación del directorio. Este prefijo debe ser utilizado por cualquier archivo generado por el sistema operativo que esté de acuerdo en que se elimine.

    NOTA:

Los prefijos se pueden especificar en cualquier orden (por ejemplo, (?d)(?i)), pero no se pueden combinar en un solo par de paréntesis como (?di).
•
Una línea que comienza con // es un comentario y no tiene efecto. Los mismos dobles barriles en cualquier otro lugar se interpretan literalmente, por ejemplo, intentar hacer archivo // comentario hará que Syncthing busque un archivo llamado archivo // comentario.

EJEMPLO

Dado un diseño de directorio que comienza en la raíz de la carpeta sincronizada:

.DS_Store
.stignore
foo
foofoo
bar/
    baz
    quux
    quuz
bar2/
    baz
    frobble
Mis Fotos/
    Img15.PNG

y un archivo .stignore con el contenido:

(?d).DS_Store
!frobble
!quuz
foo
*2
qu*
(?i)mis fotos

todos los archivos y directorios llamados "foo", que terminan en "2" o comienzan con "qu" serán ignorados. El resultado final es:

.DS_Store     # ignorado, se eliminará si interfiere con la eliminación del directorio padre
foo           # ignorado, coincide con "foo"
foofoo        # sincronizado, no coincide con "foo" pero coincidiría con "foo*" o "*foo"
bar/          # sincronizado
    baz       # sincronizado
    quux      # ignorado, coincide con "qu*"
    quuz      # sincronizado, coincide con "qu*" pero se excluye por el "!quuz" anterior
bar2/         # sincronizado, a pesar de coincidir con "*2" debido al hijo frobble
    baz       # ignorado, debido a que el padre está ignorado
    frobble   # sincronizado, debido a "!frobble"
Mis Fotos/  # ignorado, coincide de forma insensible a mayúsculas y minúsculas con el patrón "(?i)mis fotos"
    Img15.PNG # ignorado, debido a que el padre está ignorado

NOTA:

Tenga en cuenta que los patrones de directorio que terminan en una barra algún/directorio/ coinciden con el contenido del directorio, pero no con el directorio en sí. Si desea que el patrón coincida con el directorio y su contenido, asegúrese de que no tenga una barra / al final del patrón.

syncthing-stignore(5)

NAME

syncthing-stignore — pattern file format for syncthing(1)

SYNOPSIS

~/.config/syncthing/config.xml

.stignore

DESCRIPTION

This file format specifies which files and directories Syncthing should ignore. The file should contain one pattern per line. A pattern is used to exclude files or directories from synchronization.

A pattern can be a glob pattern or a regular expression. If a pattern contains any of the characters !, \, *, ?, [, ], {, }, (, ), ^, $, ., |, or +, it is treated as a glob pattern. Otherwise, it is treated as a regular expression.

By default, patterns are matched against the whole path. This can be controlled with the following directives:

dir:
Matches directories only.
file:
Matches files only.
root:
Matches the root directory.

PATTERNS

  • A pattern starting with ! ignores the file.
  • A pattern starting with ^ anchors the pattern to the beginning of the path.
  • A pattern ending with $ anchors the pattern to the end of the path.
  • A pattern ending with / ignores directories.

Patterns are matched against the whole path, relative to the root of the folder. For example, a pattern *.tmp will ignore all files ending with .tmp in the current directory and all subdirectories.

Patterns are processed in order. The first matching pattern determines whether a file is ignored or not. If a file is ignored, it can later be unignored by a subsequent pattern. For example:

*.tmp
!important.tmp

This will ignore all files ending with .tmp, except for important.tmp.

EXAMPLE

This example ignores all files and directories starting with a dot (.), except for .git directory. It also ignores all files ending with .bak and all files named node_modules.

# Ignore all dot-files and dot-directories, except .git
# Use a glob pattern to match everything starting with a dot
.*

# Exception for the .git directory
# Use a glob pattern to match the .git directory specifically
!.git/

# Ignore all files ending with .bak
*.bak

# Ignore all node_modules directories
node_modules/

Added in version 2.0.0: Windows users can now use the pipe character (|) to escape metacharacters in the .stignore file. Additionally, adding #escape=X to the top of the file, allows users to define X as the escape character for that particular file.
