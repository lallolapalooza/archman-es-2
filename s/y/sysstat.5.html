SYSSTAT(5) Manual de Usuario de Linux SYSSTAT(5)

NOMBRE

sysstat - archivo de configuración de sysstat.

DESCRIPCIÓN

Este archivo es leído por los scripts de shell sa1(8) y sa2(8) del conjunto de herramientas de sysstat. Consiste en una secuencia de asignaciones de variables de shell utilizadas para configurar el registro de sysstat. Las variables y sus significados son:

COMPRESSAFTER
Número de días después de los cuales se comprimirán los archivos de datos diarios. El programa de compresión se indica en la variable ZIP.
DELAY_RANGE
Indica al script sa2 que espere un retraso aleatorio en el rango indicado antes de ejecutarse. Este retraso se expresa en segundos y tiene como objetivo evitar un pico masivo de E/S al mismo tiempo en máquinas virtuales que comparten la misma área de almacenamiento. Un valor de 0 significa que el script sa2 generará sus archivos de informe inmediatamente.
HISTORY
El número de días durante los cuales se conservará un archivo de datos diario o un informe. Los archivos de datos o informes más antiguos que este número de días serán eliminados por el script de shell sa2(8). Los archivos de datos e informes se guardan normalmente en el directorio /var/log/sa, bajo el nombre saDD (para archivos de datos) o sarDD (para informes), donde el parámetro DD indica el día actual.

El número de archivos que se conservan realmente en el directorio /var/log/sa puede ser ligeramente superior al valor de HISTORY debido a la forma en que el script sa2 determina qué archivos se eliminarán (ver más abajo "Cómo el script sa2(8) aplica el valor de HISTORY"). Usar un valor de 28 conserva datos de un mes completo. Si establece HISTORY a un valor mayor que 28, debería considerar usar la opción -D de sadc para evitar que se sobrescriban archivos de datos más antiguos (ver la página del manual de sadc(8)). En este último caso, los archivos de datos se nombran saYYYYMMDD y los informes sarYYYYMMDD, donde YYYY representa el año actual, MM el mes actual y DD el día actual.

Cómo el script sa2(8) aplica el valor de HISTORY

El script sa2 utiliza el comando find con la opción -mtime para determinar qué archivos se eliminarán. El comando find interpreta este valor como "N períodos de 24 horas", ignorando cualquier parte fraccionaria. Esto significa que el tiempo de última modificación de un archivo de datos o informe sa[r]DD dado, usando un HISTORY de 1, tiene que haber sido modificado al menos hace dos días antes de que se elimine. Y para un HISTORY de 28, eso significaría hace 29 días.

Para determinar cómo se aplica un HISTORY de 28 en la práctica, debemos considerar que el script sa2 que emite el comando find para eliminar los archivos antiguos generalmente se ejecuta justo antes de la medianoche en un sistema dado, y dado que el primer registro de sadc también puede escribirse en el archivo de datos del día anterior (moviendo así su tiempo de modificación un poco), el script sa2 dejará 30 archivos intactos. Por lo tanto, para una configuración de 28, y contando el archivo de datos del día actual, siempre habrá 31 archivos (o 30 archivos, dependiendo del número de días en un mes) en el directorio /var/log/sa durante la mayor parte de un día determinado. Por ejemplo:

30 de abril: 31 archivos (30 de abril - 1 de abril, 31 de marzo)
1 de mayo: 30 archivos (1 de mayo, 30 de abril - 2 de abril)

Sin embargo, podemos notar las siguientes excepciones (según se inspeccionó al mediodía del día dado):

28 de febrero: 31 archivos (28 de febrero - 1 de febrero, 31 de enero, 30 y 29 de enero)
1 de marzo: 30 archivos (1 de marzo, 28 de febrero - 2 de febrero, 31 de enero y 30 de enero)
2 de marzo: 29 archivos (1 y 2 de marzo, 28 de febrero - 3 de febrero, 31 de enero)
3 de marzo: 28 archivos (1-3 de marzo, 28 de febrero - 4 de febrero)
28 de marzo - 4 de marzo: 28 archivos
29 de marzo: 29 archivos
30 de marzo: 30 archivos
31 de marzo: 31 archivos

(Determinar el número de archivos en marzo en un año bisiesto se deja como ejercicio para el lector).

Las cosas son más sencillas si usas el formato de nombre sa[r]YYYYMMDD. Aplica la misma lógica que la anterior en este caso y encontrarás que siempre hay HISTORY + 3 archivos en el directorio /var/log/sa durante la mayor parte de un día determinado.

REPEAT_HEADER
Número máximo de líneas después del cual se insertará una cabecera en el informe generado por el script sa2. Por defecto, solo hay una cabecera al principio de cada informe y no se repite después.
REPORTS
Establezca esta variable en false para evitar que el script sa2 genere informes (los archivos sarDD).
SA_DIR
Directorio donde se guardan los archivos de datos diarios y de informes de actividad del sistema. Su valor predeterminado es /var/log/sa.
SADC_OPTIONS
Opciones que se deben pasar a sadc(8). Con estas opciones (ver la página del manual de sadc(8)), puede seleccionar datos adicionales que se guardarán en los archivos de datos diarios. Estas opciones solo se utilizan cuando se crea un nuevo archivo de datos. Se ignorarán con uno ya existente.
UMASK
Los scripts sa1 y sa2 generan archivos de datos de actividad del sistema e informes en el directorio /var/log/sa. Por defecto, los archivos se crean con umask 0022 y, por lo tanto, son legibles para todos los usuarios. Cambie esta variable para restringir los permisos de los archivos (por ejemplo, use 0027 para cumplir con estándares de seguridad más estrictos).
YESTERDAY
Por defecto, el script sa2 genera el resumen de ayer, ya que el trabajo cron generalmente se ejecuta justo después de la medianoche. Si desea que sa2 genere el resumen del mismo día (por ejemplo, cuando el trabajo cron se ejecuta a las 23:53), establezca esta variable en no.
ZIP
Programa utilizado para comprimir archivos de datos e informes.
