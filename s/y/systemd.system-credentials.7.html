NOMBRE

systemd.system-credentials - Credenciales del Sistema

DESCRIPCIÓN

Las Credenciales del Sistema y de Servicio[1] son objetos de datos que pueden pasarse a los sistemas arrancados o a los servicios del sistema cuando se invocan. Pueden obtenerse de varias fuentes externas y propagarse al sistema y, desde allí, a los servicios del sistema. Las credenciales pueden opcionalmente cifrarse con una clave específica de la máquina y/o bloquearse al dispositivo TPM2 local, y solo se descifran cuando se invoca el servicio consumidor.

Las credenciales del sistema pueden usarse para aprovisionar y configurar varios aspectos del sistema. Dependiendo del componente consumidor, las credenciales solo se utilizan en las invocaciones iniciales o son necesarias para todas las invocaciones.

Las credenciales pueden usarse para cualquier tipo de datos, binarios o de texto, y pueden contener contraseñas, secretos, certificados, material de claves criptográficas, información de identidad, configuración y más.

CREDENCIALES DEL SISTEMA BIEN CONOCIDAS

firstboot.keymap

La asignación de teclas de la consola a establecer (p. ej. "de"). Leído por systemd-firstboot(1), y solo se tiene en cuenta si no se ha configurado previamente ninguna asignación de teclas de la consola.

Añadido en la versión 252.

firstboot.locale, firstboot.locale-messages

La configuración regional del sistema a establecer (p. ej. "de_DE.UTF-8"). Leído por systemd-firstboot(1), y solo se tiene en cuenta si no se ha configurado previamente ninguna configuración regional. firstboot.locale establece "LANG", mientras que firstboot.locale-message establece "LC_MESSAGES".

Añadido en la versión 252.

firstboot.timezone

La zona horaria del sistema a establecer (p. ej. "Europe/Berlin"). Leído por systemd-firstboot(1), y solo se tiene en cuenta si no se ha configurado previamente ninguna zona horaria del sistema.

Añadido en la versión 252.

login.issue

Los datos de esta credencial se escriben en /etc/issue.d/50-provision.conf, si el archivo aún no existe. agetty(8) lee este archivo y muestra su contenido en el aviso de inicio de sesión de las terminales. Consulte issue(5) para más detalles.

Consumido por /usr/lib/tmpfiles.d/provision.conf, consulte tmpfiles.d(5).

Añadido en la versión 252.

login.motd

Los datos de esta credencial se escriben en /etc/motd.d/50-provision.conf, si el archivo aún no existe. pam_motd(8) lee este archivo y muestra su contenido como "mensaje del día" durante los inicios de sesión en terminal. Consulte motd(5) para más detalles.

Consumido por /usr/lib/tmpfiles.d/provision.conf, consulte tmpfiles.d(5).

Añadido en la versión 252.

network.hosts

Los datos de esta credencial se escriben en /etc/hosts, si el archivo aún no existe. Consulte hosts(5) para más detalles.

Consumido por /usr/lib/tmpfiles.d/provision.conf, consulte tmpfiles.d(5).

Añadido en la versión 252.

network.dns, network.search_domains

Información del servidor DNS y dominios de búsqueda. Leído por systemd-resolved.service(8).

Añadido en la versión 253.

network.conf.*, network.link.*, network.netdev.*, network.network.*

Configura dispositivos de red. Leído por systemd-network-generator.service(8). Estas credenciales deben contener datos de configuración válidos de networkd.conf(5), systemd.link(5), systemd.netdev(5), systemd.network(5). De cada credencial coincidente se crea un archivo separado. Por ejemplo: el contenido de una credencial network.link.50-foobar se copiará en un archivo 50-foobar.link.

Tenga en cuenta que los archivos resultantes se crean legibles para todos los usuarios, por lo que se recomienda no incluir secretos en estas credenciales, sino proporcionarlos a través de credenciales separadas directamente a systemd-networkd.service, p. ej. network.wireguard.* como se describe a continuación.

Añadido en la versión 256.

network.wireguard.*

Configura secretos para netdevs de WireGuard. Leído por systemd-networkd.service(8). Para más información, consulte la sección [WireGuard] de systemd.netdev(5).

Añadido en la versión 256.

passwd.hashed-password.root, passwd.plaintext-password.root

Puede contener la contraseña (ya sea en formato hash de UNIX o en texto plano) para el usuario root. Leído tanto por systemd-firstboot(1) como por systemd-sysusers(8), y solo se tiene en cuenta si no se ha configurado previamente ninguna contraseña de root.

Añadido en la versión 252.

passwd.shell.root

La ruta al programa de shell (p. ej. "/bin/bash") para el usuario root. Leído tanto por systemd-firstboot(1) como por systemd-sysusers(8), y solo se tiene en cuenta si no se ha configurado previamente ningún shell de root.

Añadido en la versión 252.

ssh.ephemeral-authorized_keys-all

Proporciona claves públicas adicionales, dadas en el formato habitual de authorized_keys, para todos los usuarios, para conexiones entrantes a través de las unidades de socket AF_VSOCK y AF_UNIX generadas.

El uso previsto de esto es para que un sistema host (en configuraciones de VM o contenedor) genere un par de claves e inyecte la clave pública en el invitado, utilizando la clave privada para conectarse a cualquier cuenta de usuario en el invitado a través de ssh, sin autenticación adicional.

Consumido por systemd-ssh-generator(8).

Añadido en la versión 256.

ssh.authorized_keys.root

Los datos de esta credencial se escriben en /root/.ssh/authorized_keys, si el archivo aún no existe. Esto permite aprovisionar el acceso SSH para el usuario root del sistema.

Consumido por /usr/lib/tmpfiles.d/provision.conf, consulte tmpfiles.d(5).

Añadido en la versión 252.

ssh.listen

Puede usarse para configurar sockets SSH en los que el sistema deba ser alcanzable. Consulte systemd-ssh-generator(8) para más detalles.

Montajes adicionales a establecer al arrancar. Para más detalles, consulte systemd-fstab-generator(8).

vconsole.keymap, vconsole.keymap_toggle, vconsole.font, vconsole.font_map, vconsole.font_unimap

Configuración de la consola a aplicar, consulte systemd-vconsole-setup.service(8) para más detalles.

systemd.system-credentials(7) — systemd manual

NAME

systemd.system-credentials — system credentials

DESCRIPTION

System credentials are a mechanism to securely pass secrets and configuration to system services at boot. They are loaded into the system using systemd-cryptenroll(1) and systemd-kmod-unlock(8) and are made available to services via environment variables or by being written to files.

This man page lists the well-known system credentials that are interpreted by various systemd components.

Credential Types

The name of a credential consists of a type prefix and a suffix, separated by a dot. The type prefix indicates which component interprets the credential. The suffix is usually arbitrary, but may be used by the interpreting component to differentiate multiple credentials of the same type.

WELL KNOWN SYSTEM CREDENTIALS

journal.forward.*

Used by systemd-journald(8) to determine where to forward log messages for socket forwarding, see journald.conf(5) for details.

Added in version 256.

journal.storage

Used by systemd-journald(8) to determine where to store journal files, see journald.conf(5) for details.

Added in version 256.

vmm.notify_socket

Configures an sd_notify(3) compatible AF_VSOCK socket the service manager will report status information, ready notification and exit status on. For details see systemd(1).

Added in version 253.

shell.prompt.prefix, shell.prompt.suffix

Defines strings to prefix and suffix any interactive UNIX shell prompt with. For details see pam_systemd(8).

Added in version 257.

shell.welcome

Define a string to print when an interactive UNIX shell initializes. For details see pam_systemd(8).

Added in version 257.

system.machine_id

Takes a 128bit ID to initialize the machine ID from (if it is not set yet). Interpreted by the service manager (PID 1). For details see systemd(1).

Added in version 254.

system.hostname

Accepts a (transient) hostname to configure during early boot. The static hostname specified in /etc/hostname, if configured, takes precedence over this setting. Interpreted by the service manager (PID 1). For details see systemd(1).

Added in version 254.

home.add-signing-key.*

Adds a new signing key for user records to the system. The credential contents should contain a user signing key, for example as reported by homectl get-signing-key. Multiple keys may be specified, and they will be put in place under the name of the credential name suffix (which must itself carry the .public suffix). For details see homectl(1).

Added in version 258.

home.create.*

Creates a new home area for the specified user with the user record data passed in. For details see homectl(1).

Added in version 256.

home.register.*

Registers an existing home area for the specified user with the user record data passed in. For details see homectl(1).

Added in version 258.

cryptsetup.passphrase, cryptsetup.tpm2-pin, cryptsetup.fido2-pin, cryptsetup.pkcs11-pin, cryptsetup.luks2-pin

Specifies the passphrase/PINs to use for unlock encrypted storage volumes. For details see systemd-cryptsetup(8).

Added in version 256.

systemd.extra-unit.*, systemd.unit-dropin.*

These credentials specify extra units and drop-ins to add to the system. For details see systemd-debug-generator(8).

Added in version 256.

udev.conf.*, udev.rules.*

Configures udev configuration file and udev rules. Read by systemd-udev-load-credentials.service, which invokes udevadm control --load-credentials. These credentials directly translate to a matching udev.conf(5) or udev(7) rules file. Example: the contents of a credential udev.conf.50-foobar will be copied into a file /run/udev/udev.conf.d/50-foobar.conf, and udev.rules.50-foobar will be copied into a file /run/udev/rules.d/50-foobar.rules. See udev(7), udev.conf(5), and udevadm(8) for details.

Added in version 256.

import.pull

Specified disk images (tarballs and DDIs) to automatically download and install at boot. For details see systemd-import-generator(8).

Added in version 257.

userdb.user.*, userdb.group.*, userdb.transient.user.*, userdb.transient.group.*

Configure JSON user and group records. Read by systemd-userdb-load-credentials.service, which invokes userdbctl load-credentials. These credentials directly translate to matching JSON User[2] and JSON Group[3] records. Example: the contents of a credential userdb.user.foobar will be copied into a file /etc/userdb/foobar.user, and userdb.group.foobar will be copied into a file /etc/userdb/foobar.group. Symlinks for the uid/gid will also be created in /etc/userdb/, as well as the corresponding.membership files. See systemd-userdbd.service(7), nss-systemd(8), and userdbctl(1) for details.

Any passed user records must contain uid and gid fields. Any passed group records must contain a gid field. For both user and group records, the credential suffix (for "userdb.user.foobar" the suffix is "foobar") must match the user or group name field from the user or group record.

Note that the records created for userdb.user.* and userdb.group.* credentials are created in /etc/userdb/ and the records created for userdb.transient.user.* and userdb.transient.group.* are created in /run/userdb/ (/etc/passwd and /etc/group are not modified).

Added in version 258.

fsck.*

Read by systemd-fsck@.service, systemd-fsck-root.service, and systemd-fsck-usr.service. See systemd-fsck@.service(8) for more details.

Added in version 258.

quotacheck.*

Read by systemd-quotacheck@.service and systemd-quotacheck-root.service. See systemd-quotacheck(8) for more details.

Added in version 258.
