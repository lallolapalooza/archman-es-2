SYD-OCI(1) Manual de comandos generales SYD-OCI(1)

NOMBRE

syd-oci - tiempo de ejecución de contenedores OCI

SINOPSIS

syd-oci [OPCIONES] [COMANDO]

DESCRIPCIÓN

syd-oci es una implementación de tiempo de ejecución de contenedores OCI para syd(1).

Todos los subcomandos comunes son compatibles: create, start, state, kill, delete, pause, resume, exec, run, list, ps, spec, events, features, update. Se planea soporte para checkpoint/restore en un futuro cercano. Consulte el problema de youki correspondiente, https://github.com/youki-dev/youki/issues/142, para más información.

INTEGRACIÓN

syd-oci es una envoltura delgada alrededor de youki(1) que integra el sandbox de syd(1) en los contenedores. Es compatible con docker(1) y podman(1). Para obtener syd-oci, debe compilar syd(1) con la característica oci. Para usar syd-oci con docker(1) tiene dos opciones: O bien inicie dockerd(8) manualmente con la opción --add-runtime=syd-oci=/bin/syd-oci, y ejecute por ejemplo docker run -it --runtime=syd-oci alpine al iniciar contenedores, o añada el siguiente fragmento a su archivo /etc/docker/daemon.json:

{
"runtimes": { "syd-oci": { "path": "/bin/syd-oci" } },
"default-runtime": "syd-oci"
}

Puede que necesite adaptar la ruta a syd-oci dependiendo de su instalación. Para usar con podman(1) es similar, solo pase --runtime=/bin/syd-oci como opción a podman run.

CONFIGURACIÓN

El directorio de configuración de syd-oci es uno de los siguientes:

  • Para contenedores a nivel de sistema: /etc/syd/oci
  • Para contenedores sin root, uno de los siguientes:
    - ${XDG_CONFIG_HOME}/syd/oci donde XDG_CONFIG_HOME es usualmente ~/.config.
    - ${HOME}/.syd/oci si XDG_CONFIG_HOME no está definido.

syd-oci intenta configurar el sandbox de syd(1) en el siguiente orden, y analiza el primer archivo o perfil que localiza y detiene el procesamiento. La variable de entorno SYD_OCI_NO_CONFIG puede ser establecida para saltar al paso final:

  • Si el nombre de host y el nombre de dominio están definidos para el contenedor, intente cargar ${SYD_CONFIG_DIR}/${hostname}.${domainname}.syd-3.
  • Si el nombre de dominio está definido para el contenedor, intente cargar ${SYD_CONFIG_DIR}/${domainname}.syd-3.
  • Si el nombre de host está definido para el contenedor, intente cargar ${SYD_CONFIG_DIR}/${hostname}.syd-3.
  • Intente cargar ${SYD_CONFIG_DIR}/default.syd-3
  • Cargue el perfil incorporado oci. Este perfil está diseñado para ser combinado con pandora(1) y el modo de aprendizaje. Consulte syd-cat -p oci para la lista de reglas.

SYD_CONFIG_DIR en los elementos anteriores se refiere al directorio de configuración. Consulte syd(5) para la sintaxis de los archivos de configuración de syd(1) y syd(2) para una lista de elementos de configuración que syd(1) entiende. También se proporciona un archivo de resaltado de sintaxis para vim(1) para editar fácilmente los archivos de configuración de syd(1). Use syd-cat file.syd-3 para verificar un archivo de configuración de syd(1) en busca de errores de sintaxis.

Finalmente, tenga en cuenta que las directivas include en los archivos de configuración se buscan dentro de la imagen del contenedor. Esto le permite proporcionar configuración adicional del sandbox basada en imágenes. Un uso posible podría ser almacenar sumas de verificación criptográficas de todos los ejecutables y sus bibliotecas dinámicas dependientes en un archivo de inclusión en la imagen y luego usar esto con Sandboxing Forzado para la verificación de binarios, consulte syd(7) para más información sobre Sandboxing Forzado.
