DNSSEC-TRUST-ANCHORS.D(5) dnssec-trust-anchors.d DNSSEC-TRUST-ANCHORS.D(5)

NOMBRE

dnssec-trust-anchors.d, systemd.positive, systemd.negative - archivos de configuración de anclas de confianza DNSSEC

SINOPSIS

/etc/dnssec-trust-anchors.d/*.positive
/run/dnssec-trust-anchors.d/*.positive
/usr/local/lib/dnssec-trust-anchors.d/*.positive
/usr/lib/dnssec-trust-anchors.d/*.positive
/etc/dnssec-trust-anchors.d/*.negative
/run/dnssec-trust-anchors.d/*.negative
/usr/local/lib/dnssec-trust-anchors.d/*.negative
/usr/lib/dnssec-trust-anchors.d/*.negative

DESCRIPCIÓN

Los archivos de configuración de anclas de confianza definen las anclas de confianza positivas y negativas en las que systemd-resolved.service(8) basa las pruebas de integridad DNSSEC.

ANCLAS DE CONFIANZA POSITIVAS

Los archivos de configuración de anclas de confianza positivas contienen definiciones de registros de recursos DNSKEY y DS que se utilizan como base para las pruebas de integridad DNSSEC. Vea RFC 4035, Sección 4.4[1] para más información sobre las anclas de confianza DNSSEC.

Las anclas de confianza positivas se leen de archivos con la extensión .positive ubicados en /etc/dnssec-trust-anchors.d/, /run/dnssec-trust-anchors.d/ y /usr/lib/dnssec-trust-anchors.d/. Estos directorios se buscan en el orden especificado, y un archivo de ancla de confianza del mismo nombre en una ruta anterior anula los archivos de ancla de confianza en una ruta posterior. Para deshabilitar un archivo de ancla de confianza proporcionado en /usr/lib/dnssec-trust-anchors.d/, es suficiente proporcionar un archivo con nombre idéntico en /etc/dnssec-trust-anchors.d/ o /run/dnssec-trust-anchors.d/ que esté vacío o sea un enlace simbólico a /dev/null ("enmascarado").

Los archivos de anclas de confianza positivas son archivos de texto simples que se asemejan a los archivos de zona DNS, tal como se documenta en RFC 1035, Sección 5[2]. Se puede listar un registro de recursos DS o DNSKEY por línea. Las líneas vacías y las líneas que comienzan con "#" o ";" se ignoran, lo que puede usarse para comentarios. Un registro de recursos DS se especifica como en el siguiente ejemplo:

. IN DS 19036 8 2 49aac11d7b6f6446702e54a1607371607a1a41855200fd2ce1cdde32f24e8fb5

La primera palabra especifica el dominio, use "." para el dominio raíz. El dominio puede especificarse con o sin punto final, lo que se considera equivalente. La segunda palabra debe ser "IN", la tercera palabra "DS". Las siguientes palabras especifican la etiqueta de la clave, el algoritmo de firma, el algoritmo de resumen, seguido de la huella digital de la clave codificada en hexadecimal. Consulte RFC 4034, Sección 5[3] para obtener detalles sobre la sintaxis precisa y el significado de estos campos.

Alternativamente, se pueden usar registros de recursos DNSKEY para definir anclas de confianza, como en el siguiente ejemplo:

. IN DNSKEY 257 3 8 AwEAAagAIKlVZrpC6Ia7gEzahOR+9W29euxhJhVVLOyQbSEW0O8gcCjFFVQUTf6v58fLjwBd0YI0EzrAcQqBGCzh/RStIoO8g0NfnfL2MTJRkxoXbfDaUeVPQuYEhg37NZWAJQ9VnMVDxP/VHL496M/QZxkjf5/Efucp2gaDX6RS6CXpoY68LsvPVjR0ZSwzz1apAzvN9dlzEheX7ICJBBtuA6G3LQpzW5hOA2hzCTMjJPJ8LbqF6dsV6DoBQzgul0sGIcGOYl7OyQdXfZ57relSQageu+ipAdTTJ25AsRTAoub8ONGcLmqrAmRLKBP1dfwhYB4N7knNnulqQxA+Uk1ihz0=

La primera palabra especifica nuevamente el dominio, la segunda palabra debe ser "IN", seguida de "DNSKEY". Las siguientes palabras codifican los campos de banderas, protocolo y algoritmo de DNSKEY, seguidos de los datos de la clave codificados en Base64. Consulte RFC 4034, Sección 2[4] para obtener detalles sobre la sintaxis precisa y el significado de estos campos.

Si se definen varios registros DS o DNSKEY para el mismo dominio (posiblemente incluso en diferentes archivos de ancla de confianza), se utilizan todas las claves y se consideran equivalentes como base para las pruebas DNSSEC.

Tenga en cuenta que systemd-resolved utilizará automáticamente una clave de ancla de confianza incorporada para el dominio raíz de Internet si no se definen anclas de confianza positivas para el dominio raíz. En la mayoría de los casos, por lo tanto, no es necesario definir una clave explícita con archivos de ancla de confianza. La clave incorporada se deshabilita tan pronto como se define al menos una clave de ancla de confianza para el dominio raíz en los archivos de ancla de confianza.

En general, se recomienda codificar las anclas de confianza en registros de recursos DS, en lugar de registros DNSKEY.

Si se encuentra revocada un ancla de confianza especificada a través de un registro DS, se elimina automáticamente de la base de datos de anclas de confianza para la ejecución. Consulte RFC 5011[5] para obtener detalles sobre las anclas de confianza revocadas. Tenga en cuenta que systemd-resolved no actualizará automáticamente su base de datos de anclas de confianza a partir de servidores DNS. En su lugar, se recomienda actualizar el software del resolvedor o actualizar la nueva ancla de confianza agregando nuevos archivos de ancla de confianza.

El ancla de confianza DNSSEC actual para el dominio raíz de Internet está disponible en la página IANA Trust Anchor and Keys[6].

ANCLAS DE CONFIANZA NEGATIVAS

Las anclas de confianza negativas definen dominios en los que la validación DNSSEC se desactivará. Los archivos de ancla de confianza negativa se encuentran en la misma ubicación que los archivos de ancla de confianza positiva y siguen las mismas reglas de anulación. Son archivos de texto con la extensión .negative. Se ignoran las líneas vacías y las líneas cuyo primer carácter es ";". Cada línea especifica un nombre de dominio que es la raíz de un subárbol DNS donde se deshabilitará la validación. Por ejemplo:

# Mapeos inversos de IPv4
10.in-addr.arpa
16.172.in-addr.arpa
168.192.in-addr.arpa
...
# Algunos dominios personalizados
prod
stag

Las anclas de confianza negativas son útiles para admitir subárboles DNS privados que no están referenciados desde la jerarquía DNS de Internet y no están firmados.

RFC 7646[7] para obtener detalles sobre las anclas de confianza negativas.

Si no se configuran archivos de ancla de confianza negativa, se utiliza un conjunto incorporado de dominios de zona DNS privados conocidos como anclas de confianza negativa.

También es posible definir anclas de confianza negativa por interfaz utilizando la configuración DNSSECNegativeTrustAnchors= en los archivos de systemd.network(5).
