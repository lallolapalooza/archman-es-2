NOMBRE

systemd-ask-password - Consultar al usuario una contraseña del sistema

SINOPSIS

systemd-ask-password [OPCIONES...] [MENSAJE]

DESCRIPCIÓN

systemd-ask-password puede utilizarse para consultar interactivamente una contraseña o frase de contraseña al usuario, utilizando un mensaje de consulta especificado en la línea de comandos. Cuando se ejecuta desde una TTY, consultará una contraseña en la TTY y la imprimirá en la salida estándar. Cuando se ejecuta sin TTY o con --no-tty, utilizará un mecanismo de consulta basado en agentes, a nivel de sistema o por usuario, que permite a los usuarios activos responder a través de varios agentes, listados a continuación.

El propósito de esta herramienta es consultar contraseñas del sistema o por usuario — las primeras incluyen contraseñas que posiblemente no estén asociadas a una cuenta de usuario específica. Ejemplos: desbloquear discos duros cifrados cuando se conectan o al arrancar, introducir una frase de contraseña de certificado SSL para servidores web y VPN.

Los agentes del sistema existentes son:

•Un agente de contraseña de arranque que pregunta al usuario contraseñas usando plymouth(8),
•Un agente de contraseña de arranque que consulta al usuario directamente en la consola — systemd-ask-password-console.service(8),
•Un agente que solicita la entrada de contraseña a través de un mensaje de wall(1) — systemd-ask-password-wall.service(8),
•Un agente TTY que se inicia temporalmente durante las invocaciones de systemctl(1),
•Un agente de línea de comandos que puede iniciarse temporalmente para procesar solicitudes de contraseña en cola — systemd-tty-ask-password-agent --query.

Responder a las consultas de contraseñas del sistema es una operación privilegiada, por lo tanto, todos los agentes mencionados anteriormente (excepto el último) se ejecutan como servicios del sistema privilegiados. El último también necesita privilegios elevados, por lo que debe ejecutarse a través de run0(1) o similar.

Pueden implementarse agentes de contraseña adicionales según la **Especificación de Agente de Contraseña de systemd**[1].

Si se consulta una contraseña en una TTY, el usuario puede presionar TAB para ocultar los asteriscos que normalmente se muestran por cada carácter escrito. Presionar Retroceso como primera tecla logra el mismo efecto.

OPCIONES

Se entienden las siguientes opciones:

--icon=

Especificar un nombre de icono junto con la consulta de contraseña, que puede ser utilizado en todos los agentes que admitan pantalla gráfica. El nombre del icono debe seguir la **Especificación de Nomenclatura de Iconos XDG**[2].

--id=

Especificar un identificador para esta consulta de contraseña. Este identificador es de libre elección y permite el reconocimiento de consultas por los agentes involucrados. Debe incluir el subsistema que realiza la consulta y el objeto específico para el que se realiza la consulta. Ejemplo: "--id=cryptsetup:/dev/sda5".

Añadido en la versión 227.

--keyname=

Configurar un nombre de clave del keyring del kernel para usarlo como caché para la contraseña. Si se establece, la herramienta intentará introducir cualquier contraseña recopilada en el keyring del kernel del usuario root, como una clave del nombre especificado. Si se combina con --accept-cached, también intentará recuperar contraseñas cacheadas de la clave en el keyring del kernel en lugar de consultar al usuario de inmediato. Al usar esta opción, el keyring del kernel puede usarse como caché efectiva para evitar pedir contraseñas repetidamente, si hay varios objetos que pueden desbloquearse con la misma contraseña. La clave cacheadará tendrá un tiempo de expiración de 2.5 minutos, después del cual se purgará del keyring del kernel. Tenga en cuenta que es posible cachear varias contraseñas bajo el mismo keyname, en cuyo caso se almacenarán como una lista de contraseñas separadas por NUL. Use keyctl(1) para acceder a la clave cacheada directamente a través del keyring del kernel. Ejemplo: "--keyname=cryptsetup"

Añadido en la versión 227.

--credential=

Configurar una credencial de la cual leer la contraseña — si existe. Esto puede usarse junto con las configuraciones ImportCredential=, LoadCredential= y SetCredential= en archivos de unidad. Consulte systemd.exec(5) para más detalles. Si no se especifica, el valor predeterminado es "password". Esta opción no tiene efecto si no se pasa ningún directorio de credenciales al programa (es decir, si $CREDENTIALS_DIRECTORY no está configurado) o si no existe ninguna credencial del nombre especificado.

Añadido en la versión 249.

--timeout=

Especificar el tiempo de espera de la consulta en segundos. El valor predeterminado es 90s. Un tiempo de espera de 0 espera indefinidamente.

--echo=yes|no|masked

Controla si se debe mostrar la entrada del usuario. Acepta un valor booleano o la cadena especial "masked", siendo el valor predeterminado este último. Si está habilitado, los caracteres escritos se muestran literalmente, lo cual es útil para solicitar nombres de usuario y otros datos no protegidos. Si está deshabilitado, los caracteres escritos no se muestran de ninguna forma, el usuario no recibirá retroalimentación sobre su entrada. Si se establece en "masked", se muestra un asterisco ("*") por cada carácter escrito. En este modo, si el usuario presiona la tecla de tabulación ("↹"), la visualización se desactiva. (Alternativamente, si el usuario presiona la tecla de retroceso ("⌫") sin haber introducido ningún dato de otra manera, la visualización también se desactiva).

Añadido en la versión 249.

--echo, -e

Equivalente a --echo=yes, ver arriba.

Añadido en la versión 217.

--emoji=yes|no|auto

Controla si se debe anteponer un emoji de candado y llave (🔐) a la consulta, si la configuración de la TTY lo permite. El valor predeterminado es "auto", que por defecto es "yes", a menos que se especifique --echo=yes.

Añadido en la versión 249.

--no-tty

Nunca pregunte por la contraseña en la TTY actual aunque haya una disponible. Siempre utilice el sistema de agentes.

--accept-cached

Si se pasa, acepta contraseñas cacheadas, es decir, contraseñas introducidas previamente.

--multiple

Cuando se usa junto con --accept-cached, acepta múltiples contraseñas. Esto imprimirá una contraseña por línea.

--no-output

No imprima contraseñas en la salida estándar. Esto es útil si desea almacenar una contraseña en el keyring del kernel con --keyname= pero no desea que aparezca en pantalla o en los registros.

Añadido en la versión 230.

-n

Por defecto, cuando la contraseña adquirida se escribe en la salida estándar, se le añade un carácter de nueva línea. Esto puede desactivarse con el modificador -n, de forma similar al modificador del mismo nombre del comando echo(1).

Añadido en la versión 249.

--user, --system

Controla si se consultan los agentes de contraseñas del sistema o los agentes de contraseñas por usuario. Por defecto, si se invoca con privilegios, se consultan los agentes del sistema, de lo contrario, los agentes por usuario. Estas opciones permiten anular este comportamiento automático.

Añadido en la versión 257.

-h, --help

Imprime un breve texto de ayuda y sale.

ESTADO DE SALIDA

En caso de éxito, se devuelve 0, de lo contrario, un código de error distinto de cero.
