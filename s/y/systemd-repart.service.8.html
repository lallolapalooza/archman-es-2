NOMBRE

systemd-repart, systemd-repart.service - Crece y añade particiones automáticamente, y genera imágenes de disco (DDI)

SINOPSIS

systemd-repart [OPCIONES...] [[DISPOSITIVOBLOQUE]...]

systemd-repart.service

DESCRIPCIÓN

systemd-repart crea tablas de particiones, y añade o crece particiones, basándose en los archivos de configuración descritos en repart.d(5).

systemd-repart se utiliza al *construir* imágenes de SO, y también al *desplegar* imágenes para ajustarlas automáticamente, durante el arranque, al sistema en el que se están ejecutando. De esta manera la imagen puede ser mínima en tamaño y puede ser aumentada automáticamente al arrancar, apoderándose del espacio en disco disponible.

Si se invoca sin argumentos, systemd-repart opera sobre el dispositivo de bloque que respalda la partición de sistema de archivos raíz del SO en ejecución, aumentando así las particiones del propio SO arrancado. Cuando se llama en el initrd, opera sobre el dispositivo de bloque que respalda /sysroot/, es decir, sobre el dispositivo de bloque al que el sistema transicionará pronto. Si se usa --image=, operará sobre el dispositivo o archivo de imagen especificado. El servicio systemd-repart.service se ejecuta generalmente al arrancar en el initrd, para aumentar la tabla de particiones del SO antes de que sus particiones sean montadas.

Las operaciones de systemd-repart son mayormente incrementales: crece particiones existentes o añade nuevas, pero no reduce, elimina o mueve particiones existentes. El servicio está destinado a ejecutarse en cada arranque, pero cuando detecta que la tabla de particiones ya coincide con los archivos de configuración repart.d/*.conf instalados, no ejecuta ninguna operación.

Los siguientes casos de uso se encuentran entre los cubiertos:

•La partición raíz puede crecer para cubrir todo el espacio de disco disponible.
•Se puede añadir una partición /home/, swap, o /srv/.
•Se puede añadir una segunda (o tercera, ...) partición raíz, para cubrir configuraciones estilo A/B donde una segunda versión del sistema de archivos raíz se utiliza alternativamente para implementar esquemas de actualización. La imagen desplegada solo tendría una única partición ("A") pero en el primer arranque se crearía automáticamente una segunda partición ("B") para este propósito.

El algoritmo ejecutado por systemd-repart es aproximadamente el siguiente:

1.Los archivos de configuración repart.d/*.conf se cargan y parsean, y se ordenan por nombre de archivo (sin el prefijo del directorio). Para cada archivo de configuración, se cargan archivos complementarios de directorios con el mismo nombre que el archivo de configuración al que se añade el sufijo ".d".
2.La tabla de particiones en el dispositivo de bloque se carga y parsea, si está presente.
3.Las particiones existentes en la tabla de particiones se corresponden con los archivos repart.d/*.conf por UUID de tipo de partición GPT. La primera partición existente de un tipo específico se asigna al primer archivo de configuración que declara el mismo tipo. La segunda partición existente de un tipo específico se asigna entonces al segundo archivo de configuración que declara el mismo tipo, y así sucesivamente. Después de que esta asignación iterativa se completa, cualquier partición existente que no tenga un archivo de configuración coincidente se considera "externa" y se deja como está. Y cualquier archivo de configuración para el cual no se correspondió ninguna partición se trata como una solicitud para crear una partición.
4.Las particiones que se van a crear se asignan ahora en el disco, teniendo en cuenta las restricciones de tamaño y los pesos declarados en los archivos de configuración. Se utiliza espacio libre dentro de los límites establecidos por las solicitudes de tamaño y relleno. Además, las particiones existentes que deban crecer, crecen. Las nuevas particiones siempre se añaden al final de la tabla de particiones, ocupando la primera ranura de tabla de particiones cuyo índice sea mayor que los índices de todas las particiones existentes. Las particiones nunca se reordenan y, por lo tanto, los números de partición permanecen estables. Cuando se crean particiones, se colocan en el área de espacio libre más pequeña que sea lo suficientemente grande como para satisfacer los límites de tamaño y relleno. Esto significa que las particiones pueden tener un orden diferente en el disco que en la tabla de particiones. Tenga en cuenta que esta asignación ocurre solo en memoria, la tabla de particiones en disco aún no se actualiza.
5.A todas las particiones existentes para las cuales existen archivos de configuración y que actualmente no tienen ninguna etiqueta de partición GPT establecida, se les asignará una etiqueta, ya sea explícitamente configurada en la configuración o — si eso falta — derivada automáticamente del tipo de partición. Lo mismo se hace para todas las particiones que se crean de nuevo. Estas asignaciones se hacen solo en memoria, también, el disco aún no se actualiza.
6.De manera similar, a todas las particiones existentes para las cuales existen archivos de configuración y que actualmente tienen un UUID identificador de ceros, se les asignará un nuevo UUID. Este UUID se obtiene mediante hash criptográfico a partir de un valor de semilla común junto con el UUID del tipo de partición (y un contador en caso de que se definan múltiples particiones del mismo tipo), véase más abajo. Lo mismo se hace para todas las particiones que se crean de nuevo. Estas asignaciones se hacen solo en memoria, también, el disco aún no se actualiza.
7.De manera similar, si el UUID del volumen del disco es todo ceros, también se inicializa, también mediante hash criptográfico a partir de la misma semilla común. Esto también se hace solo en memoria.
8.El espacio en disco asignado a nuevas particiones (es decir, lo que antes era espacio libre) se borra ahora. Específicamente, se eliminan todas las firmas de sistemas de archivos y, si el dispositivo lo soporta, se emite el comando de control I/O BLKDISCARD para informar al hardware de que el espacio está ahora vacío. Además, cualquier "relleno" entre particiones y al final del dispositivo se borra de manera similar.
9.Finalmente, la nueva tabla de particiones se escribe en el disco. Se le pide al kernel que relea la tabla de particiones.

Como excepción a la operación incremental normal, cuando se llama en un modo especial de "restablecimiento de fábrica", systemd-repart puede usarse para borrar particiones existentes y restablecer una instalación a los valores predeterminados del proveedor. Este modo de operación se usa cuando se pasa el modificador --factory-reset=yes en la línea de comandos de la herramienta, o la opción systemd.factory_reset=yes se especifica en la línea de comandos del kernel, o la variable EFI FactoryResetRequest (UUID del proveedor 8cf2644b-4b0b-428f-9387-6d876050dc67) se establece en "yes". Altera ligeramente el algoritmo anterior: entre el tercer y el cuarto paso anterior, cualquier partición marcada explícitamente a través del booleano FactoryReset= se elimina, y el algoritmo se reinicia, recreando así inmediatamente estas particiones vacías.

Tenga en cuenta que systemd-repart por defecto solo cambia las tablas de particiones, no crea ni redimensiona sistemas de archivos dentro de estas particiones, a menos que se especifique la opción de configuración Format=. Tenga en cuenta también que existen mecanismos separados para este propósito, por ejemplo systemd-growfs(8) y systemd-makefs.

Los UUID que identifican las nuevas particiones creadas (o asignadas a particiones existentes que no tienen UUID aún), así como el disco en su conjunto, se obtienen mediante hash criptográfico a partir de un valor de semilla común. Este valor de semilla suele ser el machine-id(5) del sistema, de modo que el ID de máquina determina reproduciblemente los UUID asignados a todas las particiones. Si el ID de máquina no se puede leer (o el usuario pasa --seed=random, véase más abajo) la semilla se genera aleatoriamente en su lugar, de modo que los UUID de las particiones también son efectivamente aleatorios. El valor de semilla también puede establecerse explícitamente, formateado como UUID a través de la opción --seed=. Al obtener estos UUID mediante hash a partir de una semilla común, las imágenes preparadas con esta herramienta se vuelven reproducibles y el resultado del algoritmo anterior determinista.

El argumento posicional debe especificar el dispositivo de bloque o un archivo regular sobre el cual operar. Si se especifica --empty=create, la ruta especificada se crea como un archivo regular, lo cual es útil para generar imágenes de disco desde cero.

Se entienden las siguientes opciones:

Acepta un valor booleano. Si esta opción no se especifica, --dry-run=yes es el valor predeterminado implícito. Controla si systemd-repart ejecuta las operaciones de re-partición solicitadas o si solo debe mostrar lo que haría. A menos que se especifique --dry-run=no, systemd-repart no tocará realmente la tabla de particiones del dispositivo.

Si "refusar", **systemd-repart** requiere que el dispositivo de bloque en el que debe operar ya tenga una tabla de particiones y rechaza la operación si no se encuentra ninguna. **--discard=**

Toma un valor booleano. Si este interruptor no se especifica, **--discard=yes** es el valor predeterminado implícito. Controla si se emite el comando de control de E/S **BLKDISCARD** en el espacio ocupado por cualquier partición añadida o en el espacio entre ellas. Normalmente, es una buena idea emitir esta solicitud ya que le dice al hardware subyacente que los bloques cubiertos deben considerarse vacíos, mejorando el rendimiento. Si opera en un archivo regular en lugar de un nodo de dispositivo de bloque, se genera un archivo disperso.

Añadido en la versión 245.

**--size=**

Toma un tamaño en bytes, utilizando los sufijos habituales K, M, G, T, o el valor especial "auto". Si se utiliza, la ruta del nodo del dispositivo especificada debe referirse a un archivo regular, que luego se amplía al tamaño especificado si es menor, antes de realizar cualquier cambio en la tabla de particiones. Si se especifica como "auto", se determina automáticamente el tamaño mínimo de la imagen del disco (es decir, se suman los tamaños mínimos de todas las particiones, teniendo en cuenta espacio para metadatos adicionales). Este interruptor no es compatible si el nodo especificado es un dispositivo de bloque. Este interruptor no tiene ningún efecto si el archivo ya tiene el tamaño especificado o es mayor. El tamaño especificado se redondea implícitamente a múltiplos de 4096. Cuando se utiliza con **--empty=create**, especifica el tamaño inicial del archivo de loopback a crear.

La opción **--size=auto** tiene en cuenta los tamaños de las particiones preexistentes. Sin embargo, no tiene en cuenta las tablas de particiones que no están compactadas: las particiones configuradas podrían no caber en el dispositivo de respaldo si existe espacio vacío entre particiones preexistentes (o antes de la primera partición) que no pueda ser completamente ocupado por particiones a ampliar o crear.

Tenga en cuenta también que la determinación automática del tamaño no tiene en cuenta los archivos o directorios especificados con **CopyFiles=**: la operación podría fallar si los archivos o directorios especificados requieren más espacio en disco que el límite mínimo de tamaño por partición configurado.

Añadido en la versión 246.

**--factory-reset=**

Toma un valor booleano. Si este interruptor no se especifica, **--factory-reset=no** es el valor predeterminado implícito. Controla si se opera en modo "restablecimiento de fábrica", ver arriba. Si se establece en verdadero, eliminará todas las particiones existentes marcadas con FactoryReset= establecido en sí temprano al ejecutar el algoritmo de re-particionado. Úselo con cuidado, esta es una excelente manera de perder todos sus datos. Tenga en cuenta que los archivos de partición deben activar explícitamente FactoryReset=, ya que la opción está desactivada por defecto. Si no se marcan particiones para restablecimiento de fábrica, este interruptor no tiene ningún efecto. Tenga en cuenta que existen otros dos métodos para solicitar la operación de restablecimiento de fábrica: a través de la línea de comandos del kernel y a través de una variable EFI, ver arriba.

Añadido en la versión 245.

**--can-factory-reset**

Si se especifica este interruptor, el disco no se vuelve a particionar. En su lugar, se determina si alguna de las particiones existentes está marcada con FactoryReset=. Si las hay, la herramienta saldrá con el estado de salida cero, de lo contrario, saldrá con un estado de salida distinto de cero. Este interruptor se puede utilizar para determinar rápidamente si el sistema en ejecución admite un mecanismo de restablecimiento de fábrica basado en **systemd-repart**.

Añadido en la versión 245.

**--root=**

Toma una ruta a un directorio para usarlo como sistema de archivos raíz al buscar archivos repart.d/*.conf, para el archivo de ID de máquina a usar como semilla y para los archivos y directorios de origen de CopyFiles= y CopyBlocks=. Por defecto, cuando se invoca en el sistema normal, esto por defecto es el sistema de archivos raíz del host /. Si se invoca desde el initrd, esto por defecto es /sysroot/, de modo que la herramienta opera en la configuración y el ID de máquina almacenados en el sistema de archivos raíz que posteriormente se transfiere a sí mismo.

Consulte **--copy-source=** para una opción más restringida que solo afecta a CopyFiles=.

Añadido en la versión 245.

**--image=**

Toma una ruta a un archivo de imagen de disco o dispositivo para montarlo y usarlo de manera similar a **--root=**, ver arriba.

Añadido en la versión 249.

**--image-policy=**policy

Toma una cadena de política de imagen como argumento, según systemd.image-policy(7). La política se aplica al operar en la imagen de disco especificada a través de **--image=**, ver arriba. Si no se especifica, por defecto es la política "*", es decir, se utilizan todos los sistemas de archivos reconocidos en la imagen.

**--seed=**

Toma una UUID como argumento o el valor especial **random**. Si se especifica una UUID, las UUID que se asignarán a las particiones y a la propia tabla de particiones se derivan mediante hash criptográfico de ella. Si no se especifica, se intenta leer el ID de máquina del host (o más precisamente, el directorio raíz configurado a través de **--root=**) y usarlo como semilla en su lugar, recurriendo a una semilla aleatoria en caso contrario. Use **--seed=random** para forzar una semilla aleatoria. La especificación explícita de la semilla puede usarse para generar tablas de particiones estrictamente reproducibles.

Añadido en la versión 245.

**--pretty=**

Toma un argumento booleano. Si este interruptor no se especifica, por defecto está activado cuando se llama desde una terminal interactiva y desactivado en caso contrario. Controla si se muestra una tabla amigable para el usuario y un gráfico que ilustra los cambios aplicados.

OPTIONS

The following options are understood:

--definitions=FILE

Processes the partition definitions from FILE. This option may be used multiple times. The definitions are processed in order. If the file is a directory, all files within the directory are read in lexicographical order. Partition definition files are searched in /usr/lib/repart.d/*.conf, /etc/repart.d/*.conf, and the paths passed via --definitions=.

Added in version 252.

--root=PATH

Specifies the root directory to operate on. This is the directory that will be copied to the target image. If this option is not specified, the current host's file system is used. This is primarily useful for creating images that are bootable on other hosts.

Added in version 252.

--empty=MODE

Initializes the output image file. Takes one of "skip", "create", or "wipe". If "skip" (the default), an existing file is used as-is. If "create", an empty file of the specified size is created. If "wipe", an existing file is truncated to zero size.

Added in version 252.

--size=SIZE

Sets the size of the output image file. If the image file already exists and is smaller than this, it is grown. If it is larger, it is truncated. If not specified, the size is determined from the partition table, or defaults to 1 GiB if no partitions are defined.

Added in version 252.

--seed=STRING

Seeds the random number generator used for generating partition UUIDs. If not specified, the generator is seeded from `/dev/urandom`. This is useful for creating reproducible images.

Added in version 252.

--dry-run=BOOL

If enabled, no changes are made to the output image file. Only the actions that would be taken are printed.

Added in version 252.

--allow-empty=BOOL

If enabled, an empty image file is generated even if no partition definitions are found.

Added in version 252.

--force-partition-type=TYPE

Forces the specified partition type for all generated partitions. This overrides the partition type specified in the partition definition files. Supported types are "gpt" and "mbr".

Added in version 252.

--gpt-disk-guid=GUID

Sets the GPT disk GUID. If not specified, a random GUID is generated.

Added in version 252.

--fstab-path=PATH

Specifies the path to the fstab file to use when generating the partition table. If not specified, /etc/fstab is used.

Added in version 252.

--kernel-cmdline-path=PATH

Specifies the path to the kernel command line file to use when generating the partition table. If not specified, /proc/cmdline is used.

Added in version 252.

--journal-path=PATH

Specifies the path to the journal file to use when generating the partition table. If not specified, /etc/systemd/journald.conf is used.

Added in version 252.

--mkfs-options=OPTIONS

Specifies the options to pass to the mkfs utility when creating file systems.

Added in version 252.

--no-create-mountpoints

Do not create mount point directories.

Added in version 252.

--overwrite-config=KEY=VALUE

Overrides a specific partition definition key for all partitions. This option can be specified multiple times.

Added in version 252.

--state-path=PATH

Specifies the path to the state file to use when generating the partition table. If not specified, /var/lib/systemd/repart/state is used.

Added in version 252.

--wipe-partitions=BOOL

If enabled, all existing partitions on the output image are wiped before creating new ones.

Added in version 252.

--split=BOOL

Enables generation of split artifacts from partitions configured with SplitName=. If enabled, for each partition with SplitName= set, a separate output file containing just the contents of that partition is generated. The output filename consists of the loopback filename suffixed with the name configured with SplitName=. If the loopback filename ends with ".raw", the suffix is inserted before the ".raw" extension instead.

Note that --split is independent from --dry-run. Even if --dry-run is enabled, split artifacts will still be generated from an existing image if --split is enabled.

Added in version 252.

--include-partitions=PARTITIONS, --exclude-partitions=PARTITIONS

These options specify which partition types systemd-repart should operate on. If --include-partitions= is used, all partitions that are not specified are excluded. If --exclude-partitions= is used, all partitions that are specified are excluded. Both options take a comma separated list of GPT partition type UUIDs or identifiers (see Type= in repart.d(5)).

Added in version 253.

--defer-partitions=PARTITIONS

This option specifies for which partition types systemd-repart should defer. All partitions that are deferred using this option are still taken into account when calculating the sizes and offsets of other partitions, but are not actually written to the disk image. The net effect of this option is that if you run systemd-repart again without this option, the missing partitions will be added as if they had not been deferred the first time systemd-repart was executed.

Added in version 253.

--sector-size=BYTES

This option allows configuring the sector size of the image produced by systemd-repart. It takes a value that is a power of "2" between "512" and "4096". This option is useful when building images for disks that use a different sector size as the disk on which the image is produced.

Added in version 253.

--architecture=ARCH

This option allows overriding the architecture used for architecture specific partition types. For example, if set to "arm64" a partition type of "root-x86-64" referenced in repart.d/ drop-ins will be patched dynamically to refer to "root-arm64" instead. Takes one of "alpha", "arc", "arm", "arm64", "ia64", "loongarch64", "mips-le", "mips64-le", "parisc", "ppc", "ppc64", "ppc64-le", "riscv32", "riscv64", "s390", "s390x", "tilegx", "x86" or "x86-64".

Added in version 254.

--offline=BOOL

Instructs systemd-repart to build the image offline. Takes a boolean or "auto". Defaults to "auto". If enabled, the image is built without using loop devices. This is useful to build images unprivileged or when loop devices are not available. If disabled, the image is always built using loop devices. If "auto", systemd-repart will build the image online if possible and fall back to building the image offline if loop devices are not available or cannot be accessed due to missing permissions.

Added in version 254.

--copy-from=PATH

Instructs systemd-repart to synthesize partition definitions from the partition table in the given image or device. This option can be specified multiple times to synthesize definitions from each of the given images or devices. The generated definitions will copy the partitions into the destination partition table. The copied partitions will have the same size, metadata and contents but might have a different partition number and might be located at a different offset in the destination partition table. These definitions can be combined with partition definitions read from regular partition definition files. The synthesized definitions take precedence over the definitions read from partition definition files.

Added in version 255.

--copy-source=PATH, -s PATH

Specifies a source directory all CopyFiles= source paths shall be considered relative to. This is similar to --root=, but exclusively applies to the CopyFiles= setting. If --root= and --copy-source= are used in combination the former applies as usual, except for CopyFiles= where the latter takes precedence.

Added in version 255.

--make-ddi=TYPE

Takes one of "sysext", "confext" or "portable". Generates a Discoverable Disk Image (DDI) for a system extension (sysext, see systemd-sysext(8) for details), configuration extension (confext) or Portable Services[1]. The generated image will consist of a signed Verity "erofs" file system as root partition. In this mode of operation the partition definitions in /usr/lib/repart.d/*.conf and related directories are not read, and --definitions= is not supported, as appropriate definitions for the selected DDI class will be chosen automatically.

Must be used in conjunction with --copy-source= to specify the file hierarchy to populate the DDI with. The specified directory should contain an etc/ subdirectory if "confext" is selected. If "sysext" is selected it should contain either a usr/ or opt/ directory, or both. If "portable" is used a full OS file hierarchy can be provided.

This option implies --empty=create, --size=auto and --seed=random (the latter two can be overridden).

The private key and certificate for signing the DDI must be specified via the --private-key= and --certificate= switches.

Added in version 255.

-S, -C, -P

Shortcuts for --make-ddi=sysext, --make-ddi=confext, --make-ddi=portable, respectively.

Added in version 255.

--append-fstab=

Takes one of "no", "auto" or "replace". Controls how the generated fstab(5) file by --generate-fstab= will behave in case that there is a previously existing file.

If "no" systemd-repart will complain and abort in case that there is a file. This is the default behaviour. If "replace" the file will be silently replaced with the new generated one.

If "auto" systemd-repart will search in the pre-existing file the section that belong to the automatically generated content and will replace it with the newer generated content, and keep the user provided section if there is one. The generated section is identified looking for the automatic content surrounded by "# Start section ↓ of automatically generated fstab by systemd-repart" and "# End section ↑ of automatically generated fstab by systemd-repart". The content that is before and after those comments are considered user provided, and kept in the new file.

Added in version 258.

--generate-fstab=PATH

Specifies a path where to write fstab(5) entries for the mountpoints configured with MountPoint= in the root directory specified with --copy-source= or --root= or in the host's root directory if neither is specified. Disabled by default.

Added in version 256.

--generate-crypttab=PATH

Specifies a path where to write crypttab entries for the encrypted volumes configured with EncryptedVolume= in the root directory specified with --copy-source= or --root= or in the host's root directory if neither is specified. Disabled by default.

Added in version 256.

--list-devices

Show a list of candidate block devices this command may operate on. Specifically, this enumerates block devices currently present that support partition tables, and shows their device node paths along with any of their symlinks.

Added in version 257.

EXAMPLE

Example 1. Generate a configuration extension image

The following creates a configuration extension DDI (confext) for an /etc/motd update:

mkdir -p tree/etc/extension-release.d
echo "Hello World" >tree/etc/motd
cat >tree/etc/extension-release.d/extension-release.my-motd <<EOF
ID=fedora
VERSION_ID=38
IMAGE_ID=my-motd
IMAGE_VERSION=7
EOF
systemd-repart -C \
  --private-key=verity-private-key.pem \
  --certificate=verity-certificate.pem \
  -s tree/ \
  /var/lib/confexts/my-motd.confext.raw
systemd-confext refresh

The DDI generated that way may be applied to the system with systemd-confext(1).

Example 2. Generate a system extension image and sign it via PKCS11

The following creates a system extension DDI (sysext) for an /usr/foo update and signs it with a hardware token via PKCS11:

mkdir -p tree/usr/lib/extension-release.d
echo "Hello World" >tree/usr/foo
cat >tree/usr/lib/extension-release.d/extension-release.my-foo <<
EOF ID=fedora VERSION_ID=38 IMAGE_ID=my-foo IMAGE_VERSION=7 EOF systemd-repart --make-ddi=sysext \ --private-key-source=engine:pkcs11 \ --private-key="pkcs11:model=PKCS%2315%20emulated;manufacturer=piv_II;serial=0123456789abcdef;token=Some%20Cert" \ --certificate=verity-certificate.pem \ -s tree/ \ /var/lib/extensions/my-foo.sysext.raw systemd-sysext refresh

El DDI generado de esta manera puede aplicarse al sistema con systemd-sysext(8).

Ejemplo 3. Generar una firma dm-verity sin conexión y adjuntarla a una imagen preconstruida

Lo siguiente crea una imagen con metadatos dm-verity, la firma por separado para simular un sistema de firma sin conexión y luego adjunta la firma a la imagen:

mkdir -p repart.d/ /tmp/tree/usr/lib/
cat >/tmp/tree/usr/lib/os-release <<EOF
ID=debian
VERSION_ID=13
EOF
cat >repart.d/10-root.conf <<EOF
[Partition]
Type=root
Format=erofs
SizeMinBytes=100M
SizeMaxBytes=100M
Verity=data
VerityMatchKey=root
EOF
cat >repart.d/11-root-verity.conf <<EOF
[Partition]
Type=root-verity
Label=%o_%w_verity
Verity=hash
VerityMatchKey=root
SizeMinBytes=400M
SizeMaxBytes=400M
EOF
cat >repart.d/12-root-verity-sig.conf <<EOF
[Partition]
Type=root-verity-sig
Label=%o_%w_verity_sig
Verity=signature
VerityMatchKey=root
EOF
systemd-repart --definitions repart.d \
  --defer-partitions=root-verity-sig \
  --copy-source=/tmp/tree/ \
  --empty=create --size=600M \
  --json=short \
  /tmp/img.raw | | jq --raw-output0 .[-1].roothash > /tmp/img.roothash
openssl smime -sign -in /tmp/img.roothash \
  -inkey verity-private-key.pem \
  -signer verity-certificate.pem \
  -noattr -binary -outform der \
  -out /tmp/img.roothash.p7s
systemd-repart --definitions repart.d \
  --dry-run=no --root=/tmp/tree/ \
  --join-signature="$(cat /tmp/img.roothash):/tmp/img.roothash.p7s" \
  --certificate=verity-certificate.pem \
  /tmp/img.raw
