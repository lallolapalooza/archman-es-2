syslog(3) Manual de Funciones de Biblioteca syslog(3)

NOMBRE

closelog, openlog, syslog, vsyslog - enviar mensajes al registrador del sistema

BIBLIOTECA

Biblioteca estándar C (libc, -lc)

SINOPSIS

#include <syslog.h>
void openlog(const char *ident, int option, int facility);
void syslog(int priority, const char *format, ...);
void closelog(void);
void vsyslog(int priority, const char *format, va_list ap);
Requisitos de Macro de Prueba de Funciones para glibc (ver feature_test_macros(7)):

vsyslog():

    Desde glibc 2.19:
        _DEFAULT_SOURCE
    glibc 2.19 y anteriores:
        _BSD_SOURCE

DESCRIPCIÓN

openlog()

openlog() abre una conexión al registrador del sistema para un programa.

La cadena apuntada por ident se antepone a cada mensaje y típicamente se establece al nombre del programa. Si ident es NULL, se utiliza el nombre del programa. (POSIX.1-2008 no especifica el comportamiento cuando ident es NULL).

El argumento option especifica banderas que controlan el funcionamiento de openlog() y las llamadas posteriores a syslog(). El argumento facility establece un valor predeterminado a utilizar si no se especifica ninguno en las llamadas posteriores a syslog(). Los valores que se pueden especificar para option y facility se describen a continuación.

El uso de openlog() es opcional; será llamado automáticamente por syslog() si es necesario, en cuyo caso ident se establecerá a NULL por defecto.

syslog() y vsyslog()

syslog() genera un mensaje de registro, que será distribuido por syslogd(8).

El argumento priority se forma mediante la operación OR entre un valor de facility y un valor de level (descritos a continuación). Si no se aplica ningún valor de facility a priority mediante la operación OR, se utiliza el valor predeterminado establecido por openlog() o, si no hubo una llamada previa a openlog(), se emplea un valor predeterminado de LOG_USER.

Los argumentos restantes son un format, como en printf(3), y cualquier argumento requerido por el format, excepto que la secuencia de dos caracteres %m se reemplazará por la cadena de mensaje de error strerror(errno). La cadena de formato no necesita incluir un carácter de nueva línea de terminación.

La función vsyslog() realiza la misma tarea que syslog() con la diferencia de que toma un conjunto de argumentos que se han obtenido utilizando las macros de lista de argumentos variables de stdarg(3).

closelog()

closelog() cierra el descriptor de archivo que se está utilizando para escribir en el registrador del sistema. El uso de closelog() es opcional.

Valores para option

El argumento option para openlog() es una máscara de bits construida mediante la operación OR de cualquiera de los siguientes valores:

LOG_CONS
Escribir directamente en la consola del sistema si hay un error al enviar al registrador del sistema.
LOG_NDELAY
Abrir la conexión inmediatamente (normalmente, la conexión se abre cuando se registra el primer mensaje). Esto puede ser útil, por ejemplo, si un posterior chroot(2) hiciera que la ruta utilizada internamente por la facilidad de registro fuera inaccesible.
LOG_NOWAIT
No esperar a los procesos hijos que puedan haberse creado al registrar el mensaje. (La biblioteca C de GNU no crea un proceso hijo, por lo que esta opción no tiene efecto en Linux).
LOG_ODELAY
Lo opuesto a LOG_NDELAY; la apertura de la conexión se retrasa hasta que se llame a syslog(). (Este es el valor predeterminado y no necesita especificarse).
LOG_PERROR
(¡No está en POSIX.1-2001 ni POSIX.1-2008!) Registrar también el mensaje en stderr.
LOG_PID
Incluir el PID del llamante con cada mensaje.

Valores para facility

El argumento facility se utiliza para especificar qué tipo de programa está registrando el mensaje. Esto permite que el archivo de configuración especifique que los mensajes de diferentes instalaciones se manejen de manera diferente.

LOG_AUTH
mensajes de seguridad/autorización
LOG_AUTHPRIV
mensajes de seguridad/autorización (privados)
LOG_CRON
demonio del reloj (cron y at)
LOG_DAEMON
demonios del sistema sin valor de instalación separado
LOG_FTP
demonio ftp
LOG_KERN
mensajes del kernel (estos no se pueden generar desde procesos de usuario)
LOG_LOCAL0 a LOG_LOCAL7
reservados para uso local
LOG_LPR
sub sistema de impresora de línea
LOG_MAIL
sub sistema de correo
LOG_NEWS
sub sistema de noticias USENET
LOG_SYSLOG
mensajes generados internamente por syslogd(8)
LOG_USER (predeterminado)
mensajes genéricos a nivel de usuario
LOG_UUCP
sub sistema UUCP

Valores para level

Esto determina la importancia del mensaje. Los niveles son, en orden de importancia decreciente:

LOG_EMERG
el sistema es inutilizable
LOG_ALERT
se debe tomar una acción inmediatamente
LOG_CRIT
condiciones críticas
LOG_ERR
condiciones de error
LOG_WARNING
condiciones de advertencia
LOG_NOTICE
condición normal pero significativa
LOG_INFO
mensaje informativo
LOG_DEBUG
mensaje a nivel de depuración

La función setlogmask(3) se puede utilizar para restringir el registro solo a los niveles especificados.

HISTORIA

syslog()
4.2BSD, SUSv2, POSIX.1-2001.
openlog()
closelog()
4.3BSD, SUSv2, POSIX.1-2001.
vsyslog()
4.3BSD-Reno.

POSIX.1-2001 especifica solo los valores LOG_USER y LOG_LOCAL* para facility. Sin embargo, con la excepción de LOG_AUTHPRIV y LOG_FTP, los otros valores de facility aparecen en la mayoría de los sistemas UNIX.

El valor LOG_PERROR para option no está especificado por POSIX.1-2001 o POSIX.1-2008, pero está disponible en la mayoría de las versiones de UNIX.

NOTAS

El argumento ident en la llamada a openlog() probablemente se almacena tal cual. Por lo tanto, si la cadena a la que apunta se modifica, syslog() puede empezar a anteponer la cadena modificada, y si la cadena a la que apunta deja de existir, los resultados son indefinidos. Lo más portable es usar una cadena constante.

Nunca pase una cadena con datos proporcionados por el usuario como formato, use lo siguiente en su lugar:


syslog(priority, "%s", string);
