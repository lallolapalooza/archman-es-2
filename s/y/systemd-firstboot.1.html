NOMBRE

systemd-firstboot, systemd-firstboot.service - Inicializar ajustes básicos del sistema en o antes del primer arranque del sistema

SINOPSIS

systemd-firstboot [OPCIONES...]

systemd-firstboot.service

DESCRIPCIÓN

La unidad systemd-firstboot.service es una de las unidades que se utilizan para inicializar la configuración de la máquina durante el "Primer Arranque", es decir, cuando el sistema se ha instalado recientemente o después de un restablecimiento de fábrica. El gestor systemd(1) inicializará el machine-id(5) y preconfigurará todas las unidades, habilitándolas o deshabilitándolas según los ajustes de systemd.preset(5). systemd-firstboot.service se inicia más tarde para inicializar interactivamente la configuración básica del sistema. Solo se inicia si se cumple ConditionFirstBoot=yes, lo que esencialmente significa que /etc/ no está poblado, ver systemd.unit(5) para más detalles. Las credenciales del sistema pueden usarse para inyectar configuración; esas configuraciones no se consultan interactivamente.

El comando systemd-firstboot también puede usarse para inicializar de forma no interactiva una imagen de sistema sin conexión.

Los siguientes ajustes pueden configurarse:

• El ID de máquina del sistema
• La configuración regional del sistema, más específicamente las dos variables de configuración regional LANG= y LC_MESSAGES
• El mapa del teclado del sistema
• La zona horaria del sistema
• El nombre de host del sistema
• La línea de comandos del kernel utilizada al instalar imágenes del kernel
• La contraseña y el shell del usuario root

Cada uno de los campos puede ser consultado interactivamente por los usuarios, establecido de forma no interactiva en la línea de comandos de la herramienta, o copiado de un sistema host que se utiliza para configurar la imagen del sistema.

Si un ajuste ya está inicializado, no se sobrescribirá y no se le preguntará al usuario por ese ajuste.

Tenga en cuenta que esta herramienta opera directamente en el sistema de archivos y no involucra ningún servicio del sistema en ejecución, a diferencia de localectl(1), timedatectl(1) o hostnamectl(1). Esto permite que systemd-firstboot opere en imágenes de disco montadas pero no arrancadas y en el inicio temprano. No se recomienda usar systemd-firstboot en el sistema en ejecución después de que se haya configurado.

OPCIONES

Se admiten las siguientes opciones:

--root=ROOT

Toma una ruta de directorio como argumento. Todas las rutas se prefijarán con la ruta root alternativa dada, incluidas las rutas de búsqueda de configuración. Esto es útil para operar en una imagen de sistema montada en el directorio especificado en lugar del propio sistema host.

Añadido en la versión 216.

--image=PATH

Toma una ruta a un archivo de imagen de disco o nodo de dispositivo de bloque. Si se especifica, todas las operaciones se aplicarán al sistema de archivos en la imagen de disco indicada. Esto es similar a --root= pero opera en sistemas de archivos almacenados en imágenes de disco o dispositivos de bloque. La imagen de disco debe contener solo un sistema de archivos o un conjunto de sistemas de archivos dentro de una tabla de particiones GPT, siguiendo la Especificación de Particiones Descubribles[1]. Para más información sobre imágenes de disco compatibles, consulte el argumento del mismo nombre en systemd-nspawn(1).

Añadido en la versión 246.

--locale=LOCALE, --locale-messages=LOCALE

Establece la configuración regional del sistema, más específicamente los ajustes LANG= y LC_MESSAGES. El argumento debe ser un identificador de configuración regional válido, como "de_DE.UTF-8". Esto controla el archivo de configuración locale.conf(5).

Añadido en la versión 216.

--keymap=KEYMAP

Establece el diseño del teclado del sistema. El argumento debe ser un mapa de teclado válido, como "de-latin1". Esto controla la entrada "KEYMAP" en el archivo de configuración vconsole.conf(5).

Añadido en la versión 236.

--timezone=TIMEZONE

Establece la zona horaria del sistema. El argumento debe ser un identificador de zona horaria válido, como "Europe/Berlin". Esto controla el enlace simbólico localtime(5).

Añadido en la versión 216.

--hostname=HOSTNAME

Establece el nombre de host del sistema. El argumento debe ser un nombre de host, compatible con DNS. Esto controla el archivo de configuración hostname(5).

Añadido en la versión 216.

--setup-machine-id

Inicializa el ID de máquina del sistema a un ID aleatorio. Esto controla el archivo machine-id(5).

Esta opción solo funciona en combinación con --root= o --image=. En un sistema en ejecución, el ID de máquina se escribe por el gestor con la ayuda de systemd-machine-id-commit.service(8).

Añadido en la versión 216.

--machine-id=ID

Establece el ID de máquina del sistema al valor especificado. Se aplican las mismas restricciones que a --setup-machine-id.

Añadido en la versión 216.

--root-password=PASSWORD, --root-password-file=PATH, --root-password-hashed=HASHED_PASSWORD

Establece la contraseña del usuario root del sistema. Esto crea/modifica los archivos passwd(5) y shadow(5). Este ajuste existe en tres formas: --root-password= acepta la contraseña a establecer directamente en la línea de comandos, --root-password-file= la lee de un archivo y --root-password-hashed= acepta una contraseña ya cifrada en la línea de comandos. Consulte shadow(5) para más información sobre el formato de la contraseña cifrada. Tenga en cuenta que no se recomienda especificar contraseñas en texto plano en la línea de comandos, ya que otros usuarios podrían verlas simplemente invocando ps(1).

Añadido en la versión 216.

--root-shell=SHELL

Establece el shell del usuario root del sistema. Esto crea/modifica el archivo passwd(5).

Añadido en la versión 246.

--kernel-command-line=CMDLINE

Establece la línea de comandos del kernel del sistema. Esto controla el archivo /etc/kernel/cmdline que es utilizado por kernel-install(8).

Añadido en la versión 246.

--prompt-locale, --prompt-keymap, --prompt-timezone, --prompt-hostname, --prompt-root-password, --prompt-root-shell

Pregunta interactivamente al usuario por un ajuste básico específico. Tenga en cuenta que cualquier configuración explícita especificada en la línea de comandos tiene prioridad, y no se le preguntará al usuario por ella.

Añadido en la versión 216.

--prompt

Pregunta al usuario por la configuración regional, el mapa del teclado, la zona horaria, el nombre de host, la contraseña del root y el shell del root. Esto es equivalente a especificar --prompt-locale, --prompt-keymap, --prompt-timezone, --prompt-hostname, --prompt-root-password, --prompt-root-shell en combinación.

Añadido en la versión 216.

--copy-locale, --copy-keymap, --copy-timezone, --copy-root-password, --copy-root-shell

Copia un ajuste básico específico del host. Esto solo funciona en combinación con --root= o --image=.

Añadido en la versión 216.

--copy

Copia la configuración regional, el mapa del teclado, la zona horaria, la contraseña del root y el shell del host. Esto es equivalente a especificar --copy-locale, --copy-keymap, --copy-timezone, --copy-root-password, --copy-root-shell en combinación.

Añadido en la versión 216.

--for

Escribir la configuración incluso si los archivos relevantes ya existen. Sin esta opción, systemd-firstboot no modifica ni reemplaza archivos existentes. Tenga en cuenta que al configurar la cuenta root, incluso con esta opción, systemd-firstboot solo modifica la entrada del usuario "root", dejando intactas otras entradas en /etc/passwd y /etc/shadow.

Añadido en la versión 246.

--reset

Si se especifica, todos los archivos existentes que son configurados por systemd-firstboot se eliminan. Tenga en cuenta que los archivos se eliminan independientemente de si se configurarán con un nuevo valor o no. Esta operación asegura que el próximo arranque de la imagen se considere un primer arranque, y systemd-firstboot volverá a preguntar para configurar cada uno de los archivos eliminados.

Añadido en la versión 254.

--delete-root-password

Elimina la contraseña del usuario root del sistema, permitiendo el inicio de sesión como root sin contraseña a menos que la cuenta root esté bloqueada. Tenga en cuenta que esto es extremadamente inseguro y, por lo tanto, esta opción no debe usarse a la ligera.

Añadido en la versión 246.

--welcome=

Toma un argumento booleano. Por defecto, al solicitar al usuario opciones de configuración, se muestra un breve texto de bienvenida antes de que se haga la primera pregunta. Pase falso a esta opción para desactivar el texto de bienvenida.

Añadido en la versión 246.

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una cadena de versión corta y sale.

CREDENTIALS

systemd-firstboot soporta la lógica de credenciales del servicio tal como es implementada por ImportCredential=/LoadCredential=/SetCredential= (ver systemd.exec(5) para detalles). Las siguientes credenciales se utilizan cuando se pasan:

passwd.hashed-password.root, passwd.plaintext-password.root

Una versión cifrada o en texto plano de la contraseña de root a utilizar, en lugar de solicitarla al usuario. Estas credenciales son equivalentes a las mismas definidas para el servicio systemd-sysusers.service(8).

Añadido en la versión 249.

passwd.shell.root

Especifica el binario del shell a utilizar para la cuenta especificada. Equivalente a la credencial del mismo nombre definida para el servicio systemd-sysusers.service(8).

Añadido en la versión 249.

firstboot.locale, firstboot.locale-messages

Estas credenciales especifican la configuración regional a establecer durante el primer arranque, en lugar de solicitarla al usuario.

Añadido en la versión 249.

firstboot.keymap

Esta credencial especifica la configuración del teclado a establecer durante el primer arranque, en lugar de solicitarla al usuario.

Tenga en cuenta la relación con la credencial vconsole.keymap entendida por systemd-vconsole-setup.service(8): ambas afectan en última instancia la misma configuración, pero firstboot.keymap se escribe en /etc/vconsole.conf en el primer arranque (si no está ya configurada), y luego es leída desde allí por systemd-vconsole-setup, mientras que vconsole.keymap se lee en cada arranque y no se persiste en el disco (pero cualquier configuración en vconsole.conf tendrá precedencia si está presente).

Añadido en la versión 249.

firstboot.timezone

Esta credencial especifica la configuración de la zona horaria del sistema a establecer durante el primer arranque, en lugar de solicitarla al usuario.

Añadido en la versión 249.

Tenga en cuenta que, por defecto, el archivo de unidad systemd-firstboot.service está configurado para heredar las credenciales enumeradas del gestor de servicios. Por lo tanto, al invocar un contenedor con un /etc/ no poblado por primera vez, es posible configurar la contraseña del usuario root como "systemd" de esta manera:

# systemd-nspawn --image=... --set-credential=firstboot.locale:de_DE.UTF-8 ...

Tenga en cuenta que estas credenciales solo se leen y aplican durante el primer arranque. Una vez aplicadas, permanecen aplicadas para arranques posteriores y las credenciales ya no se consideran.

ESTADO DE SALIDA

En caso de éxito, se devuelve 0, de lo contrario, un código de error distinto de cero.

LÍNEA DE COMANDOS DEL KERNEL

systemd.firstboot=

Toma un argumento booleano, por defecto está activado. Si está desactivado, systemd-firstboot.service no consultará interactivamente al usuario sobre configuraciones básicas en el primer arranque, incluso si esas configuraciones aún no están inicializadas.

Añadido en la versión 233.
