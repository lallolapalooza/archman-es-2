NOMBRE

systemd-sysupdate, systemd-sysupdate.service, systemd-sysupdate.timer, systemd-sysupdate-reboot.service, systemd-sysupdate-reboot.timer - Actualiza automáticamente el SO u otros recursos

SINOPSIS

systemd-sysupdate [OPCIONES...]

systemd-sysupdate.service

DESCRIPCIÓN

systemd-sysupdate actualiza atómicamente el SO anfitrión, imágenes de contenedor, imágenes de servicio portátiles u otras fuentes, basándose en los archivos de configuración de transferencia descritos en sysupdate.d(5).

Esta herramienta implementa esquemas de actualización basados en particiones, directorios o archivos, admitiendo múltiples versiones instaladas en paralelo de recursos específicos en un estilo A/B (o incluso: A/B/C, A/B/C/D/, ...). La actualización A/B significa que cuando una versión de un recurso se está utilizando actualmente, la siguiente versión puede descargarse, descomprimirse y prepararse en una ubicación completamente separada, independientemente de la primera y, una vez completada, activarse, intercambiando los roles para que se convierta en la utilizada y la previamente utilizada se reemplace por la siguiente actualización, y así sucesivamente. Los recursos a actualizar se definen en archivos de transferencia, uno para cada recurso a actualizar. Por ejemplo, los recursos que pueden actualizarse con esta herramienta podrían ser: una partición del sistema de archivos raíz, una partición Verity coincidente más una imagen de kernel. La combinación de los tres se consideraría una actualización completa del SO.

La herramienta actualiza particiones, archivos o árboles de directorios siempre en su totalidad, y opera con al menos dos versiones de cada uno de estos recursos: la versión *actual*, más la versión *siguiente*: aquella a la que se está actualizando, y que inicialmente está incompleta ya que los datos descargados se escriben en ella; además de opcionalmente más versiones. Una vez completada la descarga de una versión más nueva, esta se convierte en la versión actual, liberando la versión previamente considerada actual para su eliminación/reemplazo/actualización.

Al instalar nuevas versiones, la herramienta descargará, descomprimirá, desempaquetará y escribirá directamente la nueva versión en el destino. Esto se hace de forma robusta para que una descarga incompleta pueda ser reconocida en la siguiente invocación, y se limpie antes de iniciar un nuevo intento.

Tenga en cuenta que al escribir actualizaciones en una partición, la partición ya debe existir, ya que systemd-sysupdate no creará automáticamente nuevas particiones. Utilice una herramienta como systemd-repart(8) para crear automáticamente particiones adicionales que se utilizarán con systemd-sysupdate al arrancar.

La herramienta puede usarse tanto en el SO en ejecución, para actualizar el SO en estado "en línea" desde sí mismo, como en imágenes de disco "fuera de línea", para actualizarlas desde el exterior basándose en archivos de transferencia incrustados en las imágenes de disco. Para esto último, consulte --image= más abajo. Esto último es particularmente interesante para actualizar imágenes de contenedor o imágenes de servicio portátiles.

El servicio del sistema systemd-sysupdate.service actualizará automáticamente el SO anfitrión basándose en los archivos de transferencia instalados. Se activa a intervalos regulares a través de systemd-sysupdate.timer. El systemd-sysupdate-reboot.service reiniciará automáticamente el sistema después de que se instale una nueva versión. Se activa a través de systemd-sysupdate-reboot.timer. Los dos servicios son independientes entre sí, ya que normalmente es aconsejable descargar actualizaciones regularmente mientras el sistema está en funcionamiento, pero retrasar los reinicios hasta el momento apropiado (es decir, típicamente por la noche). Los dos conjuntos de unidades de servicio/temporizador se pueden habilitar por separado.

Para obtener detalles sobre los archivos de transferencia y ejemplos, consulte sysupdate.d(5).

COMANDO

Se entienden los siguientes comandos:

list [VERSIÓN]

Si se invoca sin argumento, enumera las versiones descargables e instaladas, y muestra una tabla resumen con las versiones descubiertas y sus propiedades, incluyendo si hay una versión candidata más nueva para actualizar. Si se especifica un argumento de versión, muestra detalles sobre la versión específica, incluyendo los archivos individuales que deben transferirse para adquirir la versión.

Si no se especifica explícitamente ningún comando, este comando se implica.

Añadido en la versión 251.

features [FEATURE]

Si se invoca sin argumento, enumera las características opcionales y muestra una tabla resumen, incluyendo qué características están habilitadas o deshabilitadas. Si se especifica un argumento de característica, muestra detalles sobre la característica específica, incluyendo las transferencias que están controladas por la característica.

Añadido en la versión 257.

check-new

Comprueba si hay una nueva versión disponible. Esto enumera internamente las versiones descargables e instaladas y devuelve el estado de salida 0 si hay una nueva versión para actualizar, o un valor distinto de cero en caso contrario. Si hay una nueva versión para actualizar, su identificador de versión se escribe en la salida estándar.

Añadido en la versión 251.

update [VERSIÓN]

Instala (actualiza a) la versión especificada, o si no se especifica ninguna, a la versión más reciente disponible. Si la versión ya está instalada o no hay una versión más reciente disponible, no se ejecuta ninguna operación.

Si se encuentra una nueva versión para instalar/actualizar, las versiones instaladas antiguas se eliminan hasta que al menos una nueva versión pueda ser instalada, según lo configurado por InstanceMax= en sysupdate.d(5), o a través de las ranuras de partición disponibles del tipo correcto. Esta operación implícita también puede invocarse explícitamente a través del comando vacuum descrito más abajo.

Añadido en la versión 251.

vacuum

Elimina las versiones instaladas antiguas hasta que se vuelvan a cumplir los límites configurados por InstanceMax= en sysupdate.d(5). Normalmente, no debería ser necesario invocar este comando explícitamente, ya que se invoca implícitamente cada vez que se inicia una nueva actualización.

Añadido en la versión 251.

pending

Comprueba si se ha instalado una versión más reciente del SO que la que se está ejecutando actualmente. Devuelve cero si es así, y un valor distinto de cero en caso contrario. Esto compara el identificador de la versión instalada más reciente con la versión de la imagen del SO según lo informado por el campo IMAGE_VERSION= en /etc/os-release. Si el primero es más reciente que el último, aparentemente se completó una actualización pero aún no se ha activado (es decir, reiniciado).

Añadido en la versión 251.

reboot

Similar al comando pending, pero reinicia inmediatamente si se ha instalado una versión más reciente del SO que la que se está ejecutando actualmente. Esta operación se puede realizar implícitamente junto con el comando update, después de una actualización completada a través del interruptor --reboot, ver más abajo. Este comando no ejecutará ninguna operación (y devolverá éxito) si no se ha instalado ninguna actualización, y por lo tanto, el sistema no se reinició.

Añadido en la versión 251.

components

Enumera los componentes que se pueden actualizar. Esto enumera los directorios /etc/sysupdate.*.d/, /run/sysupdate.*.d/ y /usr/lib/sysupdate.*.d/ que contienen archivos de transferencia. Este comando es útil para enumerar posibles parámetros para --component= (ver más abajo).

Añadido en la versión 251.

-h, --help

Imprime un texto de ayuda corto y sale.

--version

Imprime una cadena de versión corta y sale.

OPCIONES

Se entienden las siguientes opciones:

--component=, -C

Selecciona el componente a actualizar. Acepta un nombre de componente como argumento. Esto tiene el efecto de alterar ligeramente la lógica de búsqueda de archivos de transferencia. Si no se utiliza este interruptor, los archivos de transferencia se cargan desde /etc/sysupdate.d/*.conf, /run/sysupdate.d/*.conf y /usr/lib/sysupdate.d/*.conf. Si se utiliza este interruptor, el nombre de componente especificado se utiliza para alterar los directorios en los que buscar, que serán /etc/sysupdate.componente.d/*.conf, /run/sysupdate.componente.d/*.conf y /usr/lib/sysupdate.componente.d/*.conf, cada vez con la cadena componente reemplazada por el nombre de componente especificado.

Utilice el comando components para enumerar los componentes disponibles para actualizar. Esto enumera los directorios que coinciden con esta regla de nomenclatura.

Los componentes pueden usarse para definir un conjunto separado de archivos de transferencia para diferentes componentes del SO que se deben actualizar por separado. No utilice este concepto para recursos que deban actualizarse siempre juntos.

Añadido en la versión 251.

--image=

Actualiza el archivo de imagen de disco especificado con el nombre de archivo o directorio, en lugar del sistema de archivos raíz en ejecución. Esto se puede usar para actualizar imágenes de contenedor o imágenes de servicio portátiles. El archivo de imagen de disco debe ser un sistema de archivos de solo lectura y montado temporalmente en una ubicación de montaje temporal, o debe ser un sistema de archivos de lectura/escritura o un archivo de imagen sin montar. En cualquier caso, se utiliza la ruta de la imagen como sistema de archivos de destino. Al actualizar un archivo de imagen sin montar, se puede proporcionar una imagen de disco sin montar, o una imagen de disco que contenga un sistema de archivos de solo lectura montado en un directorio o en una ubicación de montaje temporal.

Añadido en la versión 251.

--root=

Especifica un directorio de montaje alternativo para el directorio raíz del sistema de archivos (/). Por ejemplo, si el sistema de archivos raíz está montado en /mnt, use --root=/mnt. Esto es útil si se ejecuta systemd-sysupdate desde un entorno diferente, como durante el arranque desde un medio de rescate.

Añadido en la versión 251.

--no-clean

Por defecto, los archivos de transferencia no válidos se eliminarán en la siguiente ejecución. Con esta opción, los archivos no válidos se conservarán. Esto puede ser útil para fines de depuración o si la limpieza automática no es deseada.

Añadido en la versión 251.

--force, -f

Obliga a la actualización, incluso si no se encuentra una versión más nueva. Esto puede ser útil para forzar la reinstalación de una versión existente o para iniciar una actualización parcial.

Añadido en la versión 251.

--wait-reboot

Después de completar la actualización, en lugar de reiniciar inmediatamente, espera a que se reinicie el sistema. Esto se usa a menudo junto con el comando `update`.

Añadido en la versión 255.

--no-reboot

Evita que se reinicie el sistema después de la actualización. Esto es útil si se desea controlar manualmente el reinicio.

Añadido en la versión 251.

--reboot

Reinicia el sistema inmediatamente después de completar la actualización. Esto es útil si se desea que la actualización tenga efecto lo antes posible.

Añadido en la versión 251.

EJEMPLO

Para actualizar el sistema operativo a la última versión disponible, ejecute:

# systemd-sysupdate update

Para actualizar el sistema operativo a una versión específica, ejecute:

# systemd-sysupdate update 1.2.3

Para actualizar una imagen de contenedor específica, ejecute:

# systemd-sysupdate --image=/var/lib/containers/my-container.img update

systemd-sysupdate-reboot.timer(8)

NAME

systemd-sysupdate-reboot.timer, systemd-sysupdate.service - systemd system update timer and service

SYNOPSIS

systemd-sysupdate-reboot.timer

systemd-sysupdate.service

DESCRIPTION

The systemd-sysupdate.service system service is used to update system components, services, and other resources installed via sysupdate.d(5). The systemd-sysupdate-reboot.timer timer unit triggers the service on a daily basis.

The service executes the systemd-sysupdate command (see systemd-sysupdate(8) for details). The timer is configured to trigger the update at a random time each day. The service is masked by default and needs to be unmasked and enabled to run automatically.

Configuration files for sysupdate are located in /etc/sysupdate.d/. For detailed information on how to configure system updates, please refer to sysupdate.d(5).

COMMAND

systemd-sysupdate

OPTIONS

The following options are understood by the systemd-sysupdate command:

--root=
Takes a path to a directory to use as root file system when searching for sysupdate.d/*.conf files.
Added in version 251.
--image=
Takes a path to a disk image file or device to mount and use in a similar fashion to --root=, see above. If this is used and partition resources are updated this is done inside the specified disk image.
Added in version 251.
--image-policy=policy
Takes an image policy string as argument, as per systemd.image-policy(7). The policy is enforced when operating on the disk image specified via --image=, see above. If not specified, defaults to the "*" policy, i.e. all recognized file systems in the image are used.
--component=
Takes a component name as argument. If specified, only update definitions for this component are processed. This option may not be combined with --definitions=.
Added in version 251.
--definitions=
A path to a directory. If specified, the transfer *.conf files are read from this directory instead of /usr/lib/sysupdate.d/*.conf, /etc/sysupdate.d/*.conf, and /run/sysupdate.d/*.conf. This option may not be combined with --component=.
Added in version 251.
--instances-max=, -m
Takes a decimal integer greater than or equal to 2 while updating or 1 while vacuuming. Controls how many versions to keep at any time. This option may also be configured inside the transfer files, via the InstancesMax= setting, see sysupdate.d(5) for details.
Added in version 251.
--sync=
Takes a boolean argument, defaults to yes. This may be used to specify whether the newly updated resource versions shall be synchronized to disk when appropriate (i.e. after the download is complete, before it is finalized, and again after finalization). This should not be turned off, except to improve runtime performance in testing environments.
Added in version 251.
--verify=
Takes a boolean argument, defaults to yes. Controls whether to cryptographically verify downloads. Do not turn this off, except in testing environments.
Added in version 251.
--reboot
When used in combination with the update command and a new version is installed, automatically reboots the system immediately afterwards.
Added in version 251.
--offline
Prevents fetching metadata from the network (i.e. SHA256SUMS). This is most useful when used in combination with the list command, to query locally installed versions.
Added in version 257.
--transfer-source=
Takes a path as its argument. When specified, all transfer sources configured with PathRelativeTo=explicit will be interpreted relative to the specified path.
Added in version 257.
--no-pager
Do not pipe output into a pager.
--no-legend
Do not print the legend, i.e. column headers and the footer with hints.
--json=MODE
Shows output formatted as JSON. Expects one of "short" (for the shortest possible output without any redundant whitespace or line breaks), "pretty" (for a pretty version of the same, with indentation and line breaks) or "off" (to turn off JSON output, the default).

EXIT STATUS

On success, 0 is returned, a non-zero failure code otherwise.
