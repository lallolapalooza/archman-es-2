NAME

st discosrv - Syncthing Discovery Server

SYNOPSIS

st discosrv [--debug] [--http] [--compression] [--version]
           [--cert=<file>] [--key=<string>]
           [--listen=<address>] [--metrics-listen=<address>]
           [--db-dir=<string>] [--db-flush-interval=<string>]

DESCRIPTION

Syncthing relies on a discovery server to find peers on the internet. Anyone can run a discovery server and point Syncthing installations to it. The Syncthing project also maintains a global cluster for public use.

OPTIONS

--debug
Enable debug output.
--http
Listen on HTTP (behind an HTTPS proxy).
--version
Print the current version number and exit.
--compression
Enable GZIP compression of HTTP responses.
--cert=<file>
Certificate file (default “./cert.pem”). Unused in –http mode.
--key=<file>
Key file (default “./key.pem”). Unused in –http mode.
--listen=<address>
Listen address (default “:8443”).
--metrics-listen=<address>
Prometheus compatible metrics endpoint listen address (default disabled).
--db-dir=<string>
Database directory, where data is stored (default “.”).
--db-flush-interval=<string>
Interval at which the in-memory database is flushed to disk (default “5m”).

POINTING SYNCTHING AT YOUR DISCOVERY SERVER

By default, Syncthing uses a number of global discovery servers, signified by the entry default in the list of discovery servers. To make Syncthing use your own instance of st discosrv, open up Syncthing’s web GUI. Go to settings, Global Discovery Server and add st discosrv’s host address to the comma-separated list, e.g. https://disco.example.com:8443/. Note that st discosrv uses port 8443 by default. For st discosrv to be available over the internet with a dynamic IP address, you will need a dynamic DNS service.

Deprecated since version v0.14.44: Prior versions need /v2/ appended to the discovery server address, e.g. https://disco.example.com:8443/v2/.

If you wish to use only your own discovery server, remove the default entry from the list.

SETTING UP

Description

This guide assumes that you have already set up Syncthing. If you haven’t yet, head over to Getting Started first.

Installing

Configuring

NOTE:

If you are running an instance of Syncthing on the discovery server, you must either add that instance to other devices using a static address or bind the discovery server and Syncthing instances to different IP addresses.

Certificates

The discovery server provides service over HTTPS. To ensure secure connections from clients there are three options:

  • Use a CA-signed certificate pair for the domain name you will use for the discovery server. This is like any other HTTPS website; clients will authenticate the server based on its certificate and domain name.
  • Use any certificate pair and let clients authenticate the server based on its “device ID” (similar to Syncthing-to-Syncthing authentication). This option can be used with the certificate automatically generated by the discovery server.
  • Pass the --http flag if the discovery server is behind an SSL-secured reverse proxy. See below for configuration.

For the first two options, the discovery server must be given the paths to the certificate and key at startup. This isn’t necessary with the http flag:

$ st discosrv --cert=/path/to/cert.pem --key=/path/to/key.pem
Server device ID is 7DDRT7J-UICR4PM-PBIZYL3-MZOJ7X7-EX56JP6-IK6HHMW-S7EK32W-G3EUPQA

The discovery server prints its device ID at startup. In case you are using a non CA signed certificate, this device ID (fingerprint) must be given to the clients in the discovery server URL:

https://disco.example.com:8443/?id=7DDRT7J-UICR4PM-PBIZYL3-MZOJ7X7-EX56JP6-IK6HHMW-S7EK32W-G3EUPQA

Otherwise, the URL will be:

https://disco.example.com:8443/

Reverse Proxy Setup

Added in version 1.8.0: A new “X-Client-Port” HTTP header was added.

The discovery server can be run behind an SSL-secured reverse proxy. This allows:

  • Use of a subdomain name without requiring a port number added to the URL
  • Sharing an SSL certificate with multiple services on the same server

Note that after this configuration, if the proxy uses a valid HTTPS certificate, clients should omit the ?id=... parameter from the discovery server URL on their configuration. Client-side validation will be done by checking the visible proxy server’s HTTPS certificate. If, however, the proxy uses a self-signed or somehow invalid certificate, clients must still set the ?id=... parameter with the computed hash of the proxy’s certificate. Using such setup is discouraged and is not covered in this page. Always favour using valid and widely recognised certificates.

Requirements

The reverse proxy must be configured to pass the following headers through to the discovery server:

  • X-Forwarded-For
  • X-Real-IP
  • X-Forwarded-Proto
  • X-Client-Port

And pass the following via HTTP:

  • Host

It must also handle SSL termination itself.

server {
    listen 80;
    server_name disco.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name disco.example.com;

    ssl_certificate /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Client-Port $remote_port; # Added in nginx 1.13.10
    proxy_set_header Host $host;

    location / {
        proxy_pass http://127.0.0.1:8443; # Discovery server is listening on port 8443
    }
}

After setting up the reverse proxy, you can configure Syncthing to use the discovery server by appending the following to the URL in the Syncthing GUI:

https://disco.example.com/

Note that you are no longer required to add the discovery server’s device ID to the URL, nor are you required to append /v2/.

NAME

syncthing-discosrv - Syncthing discovery server

SYNOPSIS

syncthing discosrv [options]

DESCRIPTION

syncthing-discosrv is a server that accepts incoming connections from Syncthing instances and stores them. It is used to discover other Syncthing instances on the network, thus allowing Syncthing to discover nodes that are not directly reachable via its configured discovery servers.

Syncthing connects to a discovery server when a new device is added or when it is not possible to connect to any of its peers.

The discovery server is a simple HTTP server that accepts POST requests. These requests contain information about the client, such as its ID, its IP address, and its port. The server then stores this information and makes it available to other Syncthing instances that query it.

OPTIONS

The following options are available:

-http
Listen on an HTTP port instead of HTTPS. This is insecure and should only be used for testing or internal networks where security is not a concern.
-listen-address <address>
Listen on the specified address and port. Defaults to 0.0.0.0:8443 for HTTPS and 0.0.0.0:8080 for HTTP.
-keys <path>
Path to the TLS private key file. Defaults to /etc/syncthing/discosrv.pem.
-cert <path>
Path to the TLS certificate file. Defaults to /etc/syncthing/discosrv.crt.
-gui-api-key <key>
API key for the GUI. If not set, the GUI is disabled.
-gui-api-key-file <path>
Path to a file containing the GUI API key.
-gui-address <address>
Listen address for the GUI. Defaults to 127.0.0.1:8385.

POINTING SYNCTHING AT YOUR DISCOVERY SERVER

To point Syncthing at your own discovery server, you need to specify the URL in the Syncthing settings. You can do this in two ways:

  • Globally, by setting the discovery.client.servers configuration option to a comma-separated list of discovery server URLs.
  • Per-device, by setting the discovery.servers option for a specific device.

For example, if your discovery server is running at https://discovery.example.com, you would set the option to https://discovery.example.com.

SETTING UP

The discovery server requires a reverse proxy to be set up correctly in order for it to work. This is because the discovery server uses TLS client authentication to verify the identity of clients. The reverse proxy is responsible for handling the TLS handshake and passing the client certificate information to the discovery server.

The following are the requirements for setting up a reverse proxy for the discovery server:

Requirements

  • Run the discovery server using the -http flag: st discosrv -http.
  • SSL certificate/key configured for the reverse proxy.
  • The “X-Forwarded-For” HTTP header must be passed through with the client’s real IP address.
  • The “X-Client-Port” HTTP header should be passed through, containing the client’s real connection port.
  • The “X-SSL-Cert” HTTP header must be passed through with the PEM-encoded client SSL certificate. This will be present in POST requests and may be empty in GET requests from clients. If you see syncthing-discosrv outputting no certificates when receiving POST requests, that’s because the proxy is not passing this header through.
  • The proxy must request the client SSL certificate but not require it to be signed by a trusted CA.

Nginx

These lines in the configuration take care of the last four requirements listed above:

Apache

The following lines must be added to the configuration:

SSLProxyEngine On
SSLVerifyClient optional_no_ca
RequestHeader set X-SSL-Cert "%{SSL_CLIENT_CERT}s"
