syslog-ng-ctl(1) Página de manual de la herramienta de control de syslog-ng OSE syslog-ng-ctl(1)

NOMBRE

syslog-ng-ctl --- Muestra estadísticas de mensajes y habilita los modos verboso, depuración y rastreo en {{ site.product.short_name }}

SINOPSIS

syslog-ng-ctl [comando] [opciones]

DESCRIPCIÓN

NOTA: La aplicación syslog-ng-ctl se distribuye con la aplicación de registro del sistema syslog-ng OSE, y generalmente forma parte del paquete syslog-ng OSE. La última versión de la aplicación syslog-ng OSE está disponible en la página de syslog-ng OSE.

Esta página de manual es solo un resumen.

La aplicación syslog-ng-ctl es una utilidad que se puede utilizar para:

  • habilitar/deshabilitar varios mensajes de syslog-ng OSE para la resolución de problemas
  • mostrar estadísticas sobre los mensajes procesados
  • gestionar claves privadas protegidas con contraseña
  • mostrar la configuración actual en ejecución de syslog-ng OSE
  • recargar la configuración de syslog-ng OSE.

HABILITAR MENSAJES DE RESOLUCIÓN DE PROBLEMAS

comando [opciones]

Utilice el comando syslog-ng-ctl <comando> --set=on para mostrar mensajes verbosos, de rastreo o de depuración. Si está intentando resolver problemas de configuración, los mensajes verbosos (y ocasionalmente de rastreo) suelen ser suficientes. Los mensajes de depuración son necesarios principalmente para encontrar errores de software. Después de resolver el problema, no olvide desactivar estos mensajes utilizando el comando syslog-ng-ctl <comando> --set=off. Tenga en cuenta que habilitar los mensajes de depuración no habilita los mensajes verbosos y de rastreo.

Utilice syslog-ng-ctl <comando> sin ningún parámetro para mostrar si el tipo de mensaje particular está habilitado o no.

Si necesita utilizar un socket de control no estándar para acceder a syslog-ng OSE, utilice el comando syslog-ng-ctl <comando> --set=on --control=<socket> para especificar el socket a utilizar.

•
verbose

Imprime mensajes verbosos. Si syslog-ng OSE se inició con la opción --stderr o -e, los mensajes se enviarán a stderr. Si no se especifica, syslog-ng OSE registrará dichos mensajes en su fuente interna.

•
trace

Imprime mensajes de rastreo de cómo se procesan los mensajes. Si syslog-ng OSE se inició con la opción --stderr o -e, los mensajes se enviarán a stderr. Si no se especifica, syslog-ng OSE registrará dichos mensajes en su fuente interna.

•
debug

Imprime mensajes de depuración. Si syslog-ng OSE se inició con la opción --stderr o -e, los mensajes se enviarán a stderr. Si no se especifica, syslog-ng OSE registrará dichos mensajes en su fuente interna.

Ejemplo

syslog-ng-ctl verbose --set=on

syslog-ng-ctl query

La aplicación syslog-ng OSE almacena varios datos, métricas y estadísticas en una tabla hash. Cada propiedad tiene un nombre y un valor. Por ejemplo:

[syslog-ng]
|
|_[destinations]-[network]-[tcp]->[stats]->{received=12;dropped=2}
|
|_[sources]-[sql]-[stats]->{received=501;dropped=0}

Puede consultar los nodos de este árbol y también usar filtros para seleccionar la información que necesita. Una consulta es en realidad una ruta en el árbol. También puede usar los comodines ? y *. Por ejemplo:

  • Seleccionar cada propiedad: *
  • Seleccionar todos los valores de dropped de cada nodo stats: *.stats.dropped

Los nodos y propiedades disponibles en el árbol dependen de su configuración de syslog-ng OSE (es decir, las fuentes, destinos y otros objetos que haya configurado), y también de sus ajustes de stats-level().

El comando list

syslog-ng-ctl query list

Utilice el comando syslog-ng-ctl query list para mostrar la lista de métricas que syslog-ng OSE recopila sobre los mensajes procesados.

MOSTRAR MÉTRICAS Y ESTADÍSTICAS

syslog-ng-ctl query get [opciones]

El comando syslog-ng-ctl query get <consulta> lista los nodos que coinciden con la consulta y sus valores.

Por ejemplo, la consulta destination lista los destinos configurados y las métricas relacionadas con cada destino. Un ejemplo de salida:

destination.d_elastic.stats.processed=0

El comando syslog-ng-ctl query get tiene las siguientes opciones:

•
--sum

Suma el resultado de cada nodo coincidente y devuelve solo un número.

Por ejemplo, el comando syslog-ng-ctl query get --sum "destination*.dropped" muestra el número de mensajes descartados por la instancia de syslog-ng OSE.

•
--reset

Utilice --reset para establecer los contadores seleccionados en 0 después de ejecutar la consulta.

El comando stats

stats [opciones]

Utilice el comando stats para mostrar estadísticas sobre los mensajes procesados. Para obtener detalles sobre las estadísticas mostradas, consulte la Guía de administración de syslog-ng OSE. El comando stats tiene las siguientes opciones:

•
--control=<socket> o -c

Especifica el socket a utilizar para acceder a syslog-ng PE. Solo es necesario cuando se utiliza un socket no estándar.

•
--reset=<socket> o -r

Reinicia todas las estadísticas a cero, excepto los contadores en cola. (Los contadores en cola muestran el número de mensajes en la cola de mensajes del controlador de destino, esperando ser enviados al destino).

•
--remove-orphans

Elimina de forma segura todos los contadores que no están referenciados por ningún objeto productor de estadísticas de syslog-ng.

La bandera se puede utilizar para podar contadores dinámicos y estáticos manualmente. Esto es útil, por ejemplo, cuando un destino de archivo plantillado produce muchas estadísticas:

dst.file;#anon-destination0#0;/tmp/2021-08-16.log;o;processed;253592 dst.file;#anon-destination0#0;/tmp/2021-08-17.log;o;processed;156 dst.file;#anon-destination0#0;/tmp/2021-08-18.log;a;processed;961

NOTA: stats(lifetime()) se puede utilizar para hacer lo mismo automáticamente y periódicamente, pero actualmente stats(lifetime()) solo elimina contadores dinámicos que

This section provides details on how to obtain the timestamp of a specific message.

Gestión de claves privadas protegidas con contraseña

syslog-ng-ctl credentials [opciones]

El comando syslog-ng-ctl credentials status permite consultar el estado de las claves privadas que syslog-ng OSE utiliza en los controladores network() y syslog(). También puede proporcionar la frase de contraseña para las claves privadas protegidas con contraseña utilizando el comando syslog-ng-ctl credentials add. Para obtener detalles sobre el uso de claves protegidas con contraseña, consulte la Guía de Administración de syslog-ng OSE.

Visualización del estado de las claves privadas

syslog-ng-ctl credentials status [opciones]

El comando syslog-ng-ctl credentials status permite consultar el estado de las claves privadas que syslog-ng OSE utiliza en los controladores network() y syslog(). El comando devuelve la lista de claves privadas utilizadas y su estado. Por ejemplo:

syslog-ng-ctl credentials status
Estado del almacén secreto: /home/user/ssl_test/client-1/client-encrypted.key ÉXITO

Si el estado de una clave es PENDIENTE, debe proporcionar la frase de contraseña para la clave, de lo contrario, syslog-ng OSE no podrá utilizarla. Las fuentes y destinos que utilizan estas claves no funcionarán hasta que proporcione las contraseñas. Otras partes de la configuración de syslog-ng OSE no se verán afectadas. Debe proporcionar la frase de contraseña de las claves protegidas con contraseña cada vez que se reinicie syslog-ng OSE.

El siguiente mensaje de registro también le notifica sobre contraseñas PENDIENTES:

Esperando contraseña; keyfile='private.key'
•
--control=<socket> o -c

Especifica el socket a utilizar para acceder a syslog-ng OSE. Solo necesario cuando se utiliza un socket no estándar.

Apertura de claves privadas protegidas con contraseña

syslog-ng-ctl credentials add [opciones]

Puede añadir la frase de contraseña a un archivo de clave privada protegido con contraseña utilizando el siguiente comando. syslog-ng OSE mostrará una solicitud para que introduzca la frase de contraseña. Recomendamos que utilice este método.

syslog-ng-ctl credentials add --id=<ruta-a-la-clave>

Alternativamente, puede incluir la frase de contraseña en el parámetro --secret:

syslog-ng-ctl credentials add --id=<ruta-a-la-clave> --secret=<frase-de-contraseña-de-la-clave>

O puede canalizar la frase de contraseña al comando syslog-ng-ctl, por ejemplo:

echo "<frase-de-contraseña-de-la-clave>" | syslog-ng-ctl credentials add --id=<ruta-a-la-clave>
•
--control=<socket> o -c

Especifica el socket a utilizar para acceder a syslog-ng PE. Solo necesario cuando se utiliza un socket no estándar.

•
--id=<ruta-a-la-clave> o -i

La ruta al archivo de clave privada protegido con contraseña. Esta es la misma ruta que utiliza en la opción key-file() del archivo de configuración de syslog-ng OSE.

•
--secret=<frase-de-contraseña-de-la-clave> o -s

La contraseña o frase de contraseña de la clave privada.

Visualización de la configuración

syslog-ng-ctl config [opciones]

Utilice el comando syslog-ng-ctl config para mostrar la configuración que syslog-ng OSE está ejecutando actualmente. Tenga en cuenta que, por defecto, solo se muestra el contenido del archivo de configuración principal, los archivos incluidos no se resuelven. Para resolver los archivos incluidos y mostrar la configuración completa, utilice el comando syslog-ng-ctl config --preprocessed.

Recarga de la configuración

syslog-ng-ctl reload [opciones]

Utilice el comando syslog-ng-ctl reload para recargar el archivo de configuración de syslog-ng OSE sin tener que reiniciar la aplicación syslog-ng OSE. El comando syslog-ng-ctl reload funciona como un SIGHUP.

El comando syslog-ng-ctl reload devuelve 0 si la operación fue exitosa, 1 en caso contrario.
