SYSTEMD-HOMED.SERVICE(8) systemd-homed.service SYSTEMD-HOMED.SERVICE(8)

NOMBRE

systemd-homed.service, systemd-homed - Gestor de áreas de inicio/cuentas de usuario

SINOPSIS

systemd-homed.service

/usr/lib/systemd/systemd-homed

DESCRIPCIÓN

systemd-homed es un servicio del sistema que puede utilizarse para crear, eliminar, cambiar o inspeccionar áreas de inicio (directorios y montajes de red y dispositivos de bloque reales o de bucle invertido con un sistema de archivos, opcionalmente cifrados).

La mayor parte de la funcionalidad de systemd-homed es accesible a través del comando homectl(1).

Consulte la documentación de Directorios de Inicio[1] para obtener detalles sobre el formato y el diseño de las áreas de inicio gestionadas por systemd-homed.service.

Cada directorio de inicio gestionado por systemd-homed.service sintetiza un usuario y grupo local. Estos se ponen a disposición del sistema utilizando la API de Búsqueda de Registros de Usuario/Grupo a través de Varlink[2], y por lo tanto pueden ser explorados con userdbctl(1).

systemd-homed.service también gestiona directorios de "blob" (datos binarios) para cada directorio de inicio que gestiona. Consulte Directorios de Blob de Registros de Usuario[3] para obtener más detalles.

GESTIÓN DE CLAVES

Los registros de usuario se firman criptográficamente con un par de claves pública/privada (la firma es parte del propio registro JSON). Para que un usuario pueda iniciar sesión localmente, debe estar instalada la clave pública que coincida con la firma de su registro de usuario. Para que un registro de usuario se pueda modificar localmente, la clave privada que coincida con la firma también debe estar instalada localmente. Las claves se almacenan en el directorio /var/lib/systemd/home/:

/var/lib/systemd/home/local.private

La clave privada del par de claves pública/privada utilizado para registros locales. Actualmente, solo se puede instalar una clave de este tipo.

Añadido en la versión 246.

/var/lib/systemd/home/local.public

La clave pública del par de claves pública/privada utilizado para registros locales. Actualmente, solo se puede instalar una clave de este tipo.

Añadido en la versión 246.

/var/lib/systemd/home/*.public

Claves públicas adicionales. Cualquier usuario cuyos registros de usuario estén firmados con cualquiera de estas claves puede iniciar sesión localmente. Se puede instalar un número arbitrario de claves de esta manera.

Añadido en la versión 246.

Todos los archivos de clave mencionados anteriormente están en formato PEM.

Para migrar un directorio de inicio desde un host "foobar" a otro host "quux", es suficiente copiar /var/lib/systemd/home/local.public del host "foobar" a "quux", quizás llamando al archivo en el destino /var/lib/systemd/home/foobar.public, reflejando el origen de la clave. Si el registro de usuario debe ser modificable en "quux", el par /var/lib/systemd/home/local.public y /var/lib/systemd/home/local.private deben copiarse de "foobar" a "quux", y colocarse bajo los mismos caminos allí, ya que actualmente solo se admite una clave privada por host. Tenga en cuenta, por supuesto, que esto último significa que los registros de usuario generados/firmados antes de que se copien el par de claves pierden su validez.

SEÑALES

SIGUSR1

Al recibir la señal de proceso SIGUSR1, systemd-homed restablecerá sus vigilancias de archivos en /home/ y escaneará el directorio en busca de directorios de inicio.

Añadido en la versión 258.
