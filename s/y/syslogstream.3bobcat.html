FBB::SyslogStream(3bobcat) Flujo de salida para Syslog FBB::SyslogStream(3bobcat)

NOMBRE

FBB::SyslogStream - Un flujo de salida que inserta mensajes syslog

SINOPSIS

#include <bobcat/syslogstream>
Opción de enlace: -lbobcat

DESCRIPCIÓN

Los objetos FBB::SyslogStream se pueden utilizar como un std::ostream para escribir mensajes syslog utilizando las facilidades de flujo.

Se pueden usar múltiples inserciones separadas para crear un único mensaje syslog: el mensaje solo se envía al demonio syslog después de recibir un comando de flush (por ejemplo, después de insertar std::flush o std::endl). Los caracteres no imprimibles (como ’\n’) aparecen en el mensaje syslog como valores octales, precedidos por # (por ejemplo, #012 para ’\n’). El salto de línea normalmente insertado por std::endl se ignora: los objetos SyslogStream interpretan std::endl como std::flush.

Una serie de inserciones puede contener múltiples manipuladores std::endl o std::flush. En cada uno de estos manipuladores se envía un nuevo mensaje al demonio syslog, que contiene toda la información que se ha almacenado en el búfer hasta el momento. Después de enviar un mensaje al demonio syslog, el búfer interno de SyslogStream se limpia.

ESPACIO DE NOMBRES

FBB
Todos los constructores, miembros, operadores y manipuladores mencionados en esta página de manual están definidos en el espacio de nombres FBB.

ENUMERACIONES

Las siguientes enumeraciones están definidas en el espacio de nombres FBB:

Priority:

Los valores de esta enumeración coinciden con los valores de prioridad LOG_xxx correspondientes utilizados con syslog(3):

o
EMERG:
el sistema es inutilizable;
o
ALERT:
se debe tomar una acción inmediatamente;
o
CRIT:
condiciones críticas;
o
ERR:
condiciones de error;
o
WARNING:
condiciones de advertencia;
o
NOTICE:
condición normal, pero significativa;
o
INFO:
mensaje informativo;
o
DEBUG:
mensaje a nivel de depuración; El miembro setMask (ver más abajo) se puede utilizar para seleccionar qué tipo de mensajes serán procesados realmente por el demonio syslog.

PriorityType:

Esta enumeración tiene dos valores que ajustan el tipo de mensajes que son realmente procesados por el demonio syslog:

o
SINGLE:
Solo los mensajes de la prioridad especificada en la llamada a setMask son procesados por el demonio syslog;
o
UPTO:
Los mensajes de prioridad EMERG hasta la prioridad especificada en la llamada a setMask son procesados por el demonio syslog; Por defecto, el demonio syslog procesa todos los mensajes que recibe.

Facility:

Los valores de esta enumeración coinciden con los valores de facilidad LOG_xxx correspondientes utilizados con syslog(3):

o
AUTHPRIV:
mensajes de seguridad/autorización (privados)
o
CRON:
demonio del reloj (cron y at)
o
DAEMON:
otros demonios del sistema
o
KERN:
mensajes del kernel
o
LOCAL0:
reservado para uso local. LOCAL1 a LOCAL7 también están disponibles.
o
LPR:
subsistema de impresión de línea
o
MAIL:
subsistema de correo
o
NEWS:
subsistema de noticias de USENET
o
SYSLOGBUF:
mensajes generados internamente por syslogbufd
o
USER:
mensajes genéricos a nivel de usuario
o
UUCP:
subsistema UUCP

CONSTRUCTORES

o
SyslogStream(string const &ident = "", FBB::Priority priority = FBB::NOTICE, FBB::Facility facility = FBB::USER, int option = 0):
Este constructor inicializa un objeto SyslogStream. El parámetro ident suele ser el nombre del programa. Su contenido se antepone a los mensajes syslog.
El parámetro priority determina la importancia predeterminada del mensaje enviado al demonio syslog. Por defecto, los mensajes se envían al demonio syslog con prioridad FBB::NOTICE. Los mensajes syslog pueden tener una prioridad diferente insertando un manipulador de SyslogStream (ver más abajo). La prioridad establecida en el momento de la construcción también se puede modificar utilizando los miembros setPriority y setDefaultPriority.
Qué mensajes aparecen realmente en las facilidades de registro no se determina por las prioridades de los mensajes, sino por la máscara de registro de syslog. La máscara de registro se puede establecer mediante el miembro estático setMask (ver más abajo).
El parámetro facility determina el tipo de programa que realiza el registro. Por defecto se utiliza FBB::USER.
El parámetro option se puede utilizar para especificar varias opciones (use el operador binario `bitor` (`|`) para combinar opciones):
LOG_CONS: escribir directamente en la consola del sistema si hay un error al enviar al registrador del sistema
LOG_NDELAY: abrir la conexión inmediatamente (normalmente, la conexión se abre cuando se registra el primer mensaje)
LOG_PERROR: imprimir también en stderr
LOG__PID: incluir el PID con cada mensaje
Por defecto no se utilizan opciones.

Los constructores de copia y movimiento (y los operadores de asignación) no están disponibles.

FUNCIONES MIEMBRO

Todos los miembros de std::ostream están disponibles, ya que FBB::SyslogStream hereda de esta clase.

o
void close():
Si el búfer interno de SyslogStream no está vacío, se envía al demonio syslog. Después de eso, se llama a closelog(3).
o
Priority defaultPriority() const:
Devuelve la prioridad predeterminada actual. Es decir, la prioridad que se utilizará para los mensajes después de insertar endl o flush.
o
void open(string const &ident, FBB::Priority priority = FBB::NOTICE, FBB::Facility facility = FBB::USER, int option = 0):
Redefine el identificador, la prioridad, la facilidad y las opciones actuales que se utilizan al enviar mensajes al demonio syslog. Si el búfer interno de SyslogStream no está vacío, primero se envía al demonio syslog utilizando el identificador, la prioridad y las opciones que estaban activos justo antes de llamar a open.
o
Priority priority() co

MEMBER FUNCTIONS

o
Priority nextPriority():
Retorna la siguiente prioridad. Es decir, la prioridad que se utilizará para el próximo mensaje que se envíe al demonio syslog.
o
Priority setDefaultPriority(Priority priority):
Cambia la prioridad predeterminada del próximo mensaje que se enviará al demonio syslog después de insertar std::eoln o std::flush. Se devuelve la prioridad predeterminada activa anteriormente.
o
Priority setPriority(Priority priority):
Cambia la prioridad para el próximo mensaje que se enviará al demonio syslog después de insertar std::eoln o std::flush. Los mensajes subsiguientes volverán a usar la prioridad predeterminada. Se devuelve la configuración de prioridad activa anteriormente.

FUNCIONES MIEMBRO ESTÁTICAS

o
Priority setMask(Priority priority, PriorityMask upTo):
Los mensajes syslog de (si upTo es igual a SINGLE) o hasta (si upTo es igual a UPTO) la prioridad indicada son procesados por el demonio syslog.
o
Priority setMask(Priority priority, Priority ...priorities):
Los mensajes syslog de las prioridades pasadas a setMask son procesados por el demonio syslog. Se debe especificar al menos una prioridad.
o
Facility stoF(std::string const &name, Facility facility = USER):
Devuelve la instalación que coincide con el nombre de la instalación proporcionada por name. La coincidencia de instalaciones se realiza sin distinguir mayúsculas de minúsculas. Por ejemplo, si name contiene daemon, se devuelve la instalación FBB::DAEMON. Si name no coincide con ningún nombre de instalación, se devuelve el valor del segundo argumento de esta función. El nombre de la función (stoF) se utilizó en analogía con las diversas funciones de conversión sto... que fueron puestas a disposición por el estándar C++11.
o
Priority stoP(std::string const &name, Priority priority = NOTICE):
Devuelve la prioridad que coincide con el nombre de la prioridad proporcionada por name. La coincidencia de prioridades se realiza sin distinguir mayúsculas de minúsculas. Por ejemplo, si name contiene emerg, se devuelve la prioridad FBB::EMERG. Si name no coincide con ningún nombre de prioridad, se devuelve el valor del segundo argumento de esta función. El nombre de la función (stoP) se utilizó en analogía con las diversas funciones de conversión sto... que fueron puestas a disposición por el estándar C++11.

MANIPULADORES

El siguiente conjunto de manipuladores se definen como miembros (estáticos). Se pueden insertar en un objeto FBB::SyslogStream. Excepto el último manipulador (strerrno), tienen las siguientes características en común:

o
Cambian la prioridad de los mensajes que se insertan posteriormente por el objeto FBB::SyslogStream, actuando así como una llamada setPriority separada.
o
Al insertar varios manipuladores antes de que el mensaje insertado se vacíe (por ejemplo, usando los manipuladores std::flush o std::endl), se utilizará el último manipulador de FBB::SyslogStream insertado.
o
Si los manipuladores no se insertan en un objeto FBB::SyslogStream (sino en otro objeto de tipo std::ostream), entonces no realizan ninguna acción.

Aquí están los manipuladores disponibles:

o
SyslogStream::alert:
Los mensajes se insertan con prioridad FBB::ALERT.
o
SyslogStream::crit:
Los mensajes se insertan con prioridad FBB::CRIT.
o
SyslogStream::debug:
Los mensajes se insertan con prioridad FBB::DEBUG.
o
SyslogStream::emerg:
Los mensajes se insertan con prioridad FBB::EMERG.
o
SyslogStream::err:
Los mensajes se insertan con prioridad FBB::ERR.
o
SyslogStream::info:
Los mensajes se insertan con prioridad FBB::INFO.
o
SyslogStream::notice:
Los mensajes se insertan con prioridad FBB::NOTICE.
o
SyslogStream::strerrno:
Este manipulador inserta la interpretación textual del valor actual de std::errno en un std::ostream. Tenga en cuenta que, a diferencia de los demás manipuladores, el objeto en el que se inserta este manipulador no tiene por qué ser un objeto FBB::SyslogStream.
o
SyslogStream::warning:
Los mensajes se insertan con prioridad FBB::WARNING.

EJEMPLO

#include <bobcat/syslogstream>
using namespace std;
using namespace FBB;
int main(int argc, char **argv)
{
    SyslogStream sls(argv[0]);
    sls << SyslogStream::debug << "Hello world" << flush <<
           SyslogStream::strerrno << endl;
}
