NOMBRE

syslog.h — definiciones para el registro de errores del sistema

SINOPSIS

#include <syslog.h>

DESCRIPCION

El encabezado <syslog.h> definirá las siguientes constantes simbólicas, de las cuales se pueden OR-ear cero o más para formar la opción logopt de openlog():

LOG_PID
Registrar el ID del proceso con cada mensaje.
LOG_CONS
Registrar en la consola del sistema en caso de error.
LOG_NDELAY
Conectar inmediatamente al demonio syslog.
LOG_ODELAY
Retrasar la apertura hasta que se llame a syslog().
LOG_NOWAIT
No esperar a los procesos hijos.

El encabezado <syslog.h> definirá las siguientes constantes simbólicas para usarlas como argumento facility de openlog():

LOG_KERN
Reservado para mensajes generados por el sistema.
LOG_USER
Mensaje generado por un proceso.
LOG_MAIL
Reservado para mensajes generados por el sistema de correo.
LOG_NEWS
Reservado para mensajes generados por el sistema de noticias.
LOG_UUCP
Reservado para mensajes generados por el sistema UUCP.
LOG_DAEMON
Reservado para mensajes generados por demonios del sistema.
LOG_AUTH
Reservado para mensajes generados por el demonio de autorización.
LOG_CRON
Reservado para mensajes generados por el demonio de reloj.
LOG_LPR
Reservado para mensajes generados por el sistema de impresión.
LOG_LOCAL0
Reservado para uso local.
LOG_LOCAL1
Reservado para uso local.
LOG_LOCAL2
Reservado para uso local.
LOG_LOCAL3
Reservado para uso local.
LOG_LOCAL4
Reservado para uso local.
LOG_LOCAL5
Reservado para uso local.
LOG_LOCAL6
Reservado para uso local.
LOG_LOCAL7
Reservado para uso local.

El encabezado <syslog.h> definirá las siguientes macros para construir el argumento maskpri de setlogmask(). Las siguientes macros se expanden a una expresión de tipo int cuando el argumento pri es una expresión de tipo int:

LOG_MASK(pri)
Una máscara para la prioridad pri.

El encabezado <syslog.h> definirá las siguientes constantes simbólicas para usarlas como argumento priority de syslog():

LOG_EMERG
Se informó una condición de pánico a todos los procesos.
LOG_ALERT
Una condición que debería corregirse inmediatamente.
LOG_CRIT
Una condición crítica.
LOG_ERR
Un mensaje de error.
LOG_WARNING
Un mensaje de advertencia.
LOG_NOTICE
Una condición que requiere manejo especial.
LOG_INFO
Un mensaje de información general.
LOG_DEBUG
Un mensaje útil para depurar programas.

Las siguientes se declararán como funciones y también pueden definirse como macros. Se proporcionarán prototipos de función.

void  closelog(void);
void  openlog(const char *, int, int);
int   setlogmask(int);
void  syslog(int, const char *, ...);

syslog.h

Esta página describe la página del manual de syslog.h. La información puede ser diferente en otras distribuciones de Linux o sistemas operativos.

DESCRIPCIÓN

La cabecera <syslog.h> define un conjunto de macros y tipos utilizados para la recepción de mensajes del sistema. El servicio de registro del sistema syslog es un subsistema de software que permite a las aplicaciones enviar mensajes de registro a un demonio centralizado, que luego los procesa.

Las funciones principales definidas en <syslog.h> son:

  • openlog(): Abre una conexión con el registrador del sistema.
  • syslog(): Envía un mensaje de registro al sistema.
  • closelog(): Cierra la conexión con el registrador del sistema.

Estas funciones permiten a los desarrolladores registrar eventos importantes, errores o información de depuración de sus aplicaciones de manera estandarizada.

SINÓPSIS

La cabecera <syslog.h> contiene las siguientes definiciones: 

#include <syslog.h>

void openlog(const char *ident, int option, int facility);
void syslog(int priority, const char *message, ...);
void closelog(void);

También define una serie de macros para prioridades y facilidades, por ejemplo:

  • LOG_EMERG, LOG_ALERT, LOG_CRIT, LOG_ERR, LOG_WARNING, LOG_NOTICE, LOG_INFO, LOG_DEBUG
  • LOG_KERN, LOG_USER, LOG_MAIL, LOG_DAEMON, LOG_AUTH, LOG_SYSLOG, LOG_LPR, LOG_NEWS, LOG_UUCP, LOG_CRON, LOG_AUTHPRIV, LOG_FTP, etc.
  • LOG_CONS, LOG_NDELAY, LOG_PERROR, LOG_PID

NOTAS

La correcta configuración del demonio syslog (como rsyslog o syslog-ng) es crucial para determinar cómo se almacenan y gestionan los mensajes de registro.

Es una buena práctica cerrar la conexión con el registrador del sistema cuando ya no sea necesaria, utilizando closelog().
