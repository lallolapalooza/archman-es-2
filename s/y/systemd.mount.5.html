NOMBRE

systemd.mount - Configuración de la unidad de montaje

SINOPSIS

mount.mount

DESCRIPCIÓN

Un archivo de configuración de unidad cuyo nombre termina en ".mount" codifica información sobre un punto de montaje de sistema de archivos controlado y supervisado por systemd.

Esta página del manual enumera las opciones de configuración específicas de este tipo de unidad. Consulte systemd.unit(5) para ver las opciones comunes de todos los archivos de configuración de unidades. Los elementos de configuración comunes se configuran en las secciones genéricas [Unit] e [Install]. Las opciones de configuración específicas de montaje se configuran en la sección [Mount].

Se incluyen opciones adicionales en systemd.exec(5), que definen el entorno de ejecución en el que se ejecuta el programa mount(8), y en systemd.kill(5), que definen la forma en que se terminan los procesos, y en systemd.resource-control(5), que configuran los ajustes de control de recursos para los procesos del servicio.

Tenga en cuenta que las opciones User= y Group= no son útiles para las unidades de montaje. systemd pasa dos parámetros a mount(8); los valores de What= y Where=. Cuando se invoca de esta manera, mount(8) no lee ninguna opción de /etc/fstab y debe ejecutarse como UID 0.

Las unidades de montaje deben nombrarse según los directorios de punto de montaje que controlan. Ejemplo: el punto de montaje /home/lennart debe configurarse en un archivo de unidad home-lennart.mount. Para obtener más detalles sobre la lógica de escape utilizada para convertir una ruta de sistema de archivos a un nombre de unidad, consulte systemd.unit(5). Tenga en cuenta que las unidades de montaje no pueden ser plantillas, ni es posible añadir múltiples nombres a una unidad de montaje creando enlaces simbólicos a su archivo de unidad.

Opcionalmente, una unidad de montaje puede ir acompañada de una unidad de automontaje, para permitir el montaje bajo demanda o paralelizado. Consulte systemd.automount(5).

Los puntos de montaje creados en tiempo de ejecución (independientemente de los archivos de unidad o /etc/fstab) serán monitorizados por systemd y aparecerán como cualquier otra unidad de montaje en systemd. Consulte la descripción de /proc/self/mountinfo en proc(5).

Algunos sistemas de archivos tienen semánticas especiales como sistemas de archivos API para la interfaz del kernel al espacio de usuario y entre espacios de usuario. Algunos de ellos no pueden modificarse mediante unidades de montaje y no pueden deshabilitarse. Para una discusión más detallada, consulte Sistemas de Archivos API[1].

El comando systemd-mount(1) permite crear unidades .mount y .automount de forma dinámica y transitoria desde la línea de comandos.

DEPENDENCIAS AUTOMÁTICAS

Dependencias Implícitas

Las siguientes dependencias se añaden implícitamente:

•Si una unidad de montaje está debajo de otra unidad de montaje en la jerarquía del sistema de archivos, se crea automáticamente una dependencia de requisito y una dependencia de ordenación entre ambas unidades.
•Los sistemas de archivos respaldados por dispositivos de bloque obtienen automáticamente dependencias de tipo Requires=, StopPropagatedFrom= y After= en la unidad del dispositivo que encapsula el dispositivo de bloque (consulte x-systemd.device-bound= para más detalles).
•Si la cuota tradicional del sistema de archivos está habilitada para una unidad de montaje, se añaden dependencias automáticas de tipo Wants= y Before= para systemd-quotacheck@.service y quotaon@.service.
•Pueden añadirse dependencias implícitas adicionales como resultado de los parámetros de ejecución y control de recursos, tal como se documenta en systemd.exec(5) y systemd.resource-control(5).

Dependencias Predeterminadas

Las siguientes dependencias se añaden a menos que se establezca DefaultDependencies=no:

•Todas las unidades de montaje adquieren Before= y Conflicts= automáticas con umount.target para ser detenidas durante el apagado.
•Las unidades de montaje que se refieren a sistemas de archivos locales obtienen automáticamente una dependencia After= de local-fs-pre.target, y una dependencia Before= de local-fs.target, a menos que se establezca una o más opciones de montaje entre nofail, x-systemd.wanted-by= y x-systemd.required-by=. Consulte más abajo para obtener información detallada.

Además, se añade una dependencia After= de swap.target cuando el tipo de sistema de archivos es "tmpfs".

•Las unidades de montaje de red adquieren automáticamente dependencias After= de remote-fs-pre.target, network.target, más dependencias After= y Wants= de network-online.target, y una dependencia Before= de remote-fs.target, a menos que se establezca una o más opciones de montaje entre nofail, x-systemd.wanted-by= y x-systemd.required-by=.

Las unidades de montaje que se refieren a sistemas de archivos locales y de red se distinguen por la especificación de su tipo de sistema de archivos. En algunos casos, esto no es suficiente (por ejemplo, montajes basados en dispositivos de bloque de red, como iSCSI), en cuyo caso _netdev puede añadirse a la cadena de opciones de montaje de la unidad, lo que fuerza a systemd a considerar la unidad de montaje como una unidad de red.

FSTAB

Las unidades de montaje pueden configurarse a través de archivos de unidad o a través de /etc/fstab (consulte fstab(5) para obtener detalles). Los montajes listados en /etc/fstab se convertirán en unidades nativas dinámicamente al arrancar y cuando se recargue la configuración del gestor del sistema. En general, configurar puntos de montaje a través de /etc/fstab es el enfoque preferido para gestionar montajes para humanos. Para herramientas, se prefiere escribir unidades de montaje en lugar de editar /etc/fstab. Consulte systemd-fstab-generator(8) para obtener detalles sobre la conversión de /etc/fstab a unidades de montaje.

La opción de montaje NFS bg para montajes NFS en segundo plano, tal como se documenta en nfs(5), es detectada por systemd-fstab-generator y las opciones se transforman para que systemd cumpla las implicaciones de control de trabajos de esa opción. Específicamente, systemd-fstab-generator actúa como si "x-systemd.mount-timeout=infinity,retry=10000" se prefijara a la lista de opciones, y "fg,nofail" se añadiera al final. Dependiendo de los requisitos específicos, puede ser apropiado proporcionar explícitamente algunas de estas opciones, o utilizar la opción "x-systemd.automount" descrita a continuación en lugar de usar "bg".

Al leer /etc/fstab, systemd comprende algunas opciones de montaje especiales que influyen en cómo se crean las dependencias para los puntos de montaje. systemd creará una dependencia de tipo Wants= o Requires= (consulte la opción nofail a continuación), desde local-fs.target o remote-fs.target, dependiendo de si el sistema de archivos es local o remoto.

x-systemd.requires=

Configura una dependencia de tipo Requires= y una de tipo After= entre la unidad de montaje creada y otra unidad de systemd, como una unidad de dispositivo o de montaje. El argumento debe ser un nombre de unidad o una ruta absoluta a un nodo de dispositivo o punto de montaje. Esta opción se puede especificar varias veces. Esta opción es particularmente útil para declaraciones de puntos de montaje que necesitan un dispositivo adicional (como un diario externo para sistemas de archivos de diario) o un montaje adicional (como un sistema de archivos superpuesto que fusiona múltiples puntos de montaje). Consulte After= y Requires= en systemd.unit(5) para obtener detalles.

Tenga en cuenta que esta opción siempre se aplica solo a la unidad de montaje creada, independientemente de si se ha especificado x-systemd.automount.

Añadido en la versión 220.

x-systemd.wants=

Configura una dependencia de tipo Wants= y una de tipo After= entre la unidad de montaje creada y otra unidad de systemd, similar a la opción x-systemd.requires=.

Añadido en la versión 257.

x-systemd.before=, x-systemd.after=

En la unidad de montaje creada, configura una dependencia de tipo Before= o After= en otra unidad de systemd, como una unidad de montaje. El argumento debe ser un nombre de unidad o una ruta absoluta a un punto de montaje.

Este opción se puede especificar más de una vez. Esta opción es particularmente útil para declaraciones de puntos de montaje con la opción nofail que se montan asíncronamente pero necesitan montarse antes o después del inicio de alguna unidad, por ejemplo, antes de la unidad local-fs.target. Ver Before= y After= en systemd.unit(5) para más detalles.

Tenga en cuenta que estas opciones siempre se aplican solo a la unidad de montaje creada, independientemente de si se ha especificado x-systemd.automount.

x-systemd.wanted-by=, x-systemd.required-by=

En la unidad de montaje creada, configura una dependencia WantedBy= o RequiredBy= en otra unidad. Esta opción se puede especificar más de una vez. Si se especifica, las dependencias predeterminadas (ver arriba) distintas de umount.target en la unidad de montaje creada, por ejemplo, local-fs.target, no se crean automáticamente. Por lo tanto, es probable que algunas dependencias de ordenación deban configurarse manualmente a través de x-systemd.before= y x-systemd.after=. Ver WantedBy= y RequiredBy= en systemd.unit(5) para más detalles.

Configura una dependencia RequiresMountsFor= o WantsMountsFor= entre la unidad de montaje creada y otras unidades de montaje. El argumento debe ser una ruta absoluta. Esta opción se puede especificar más de una vez. Ver RequiresMountsFor= o WantsMountsFor= en systemd.unit(5) para más detalles.

Añadido en la versión 220.

x-systemd.graceful-option=

Opción de montaje adicional que se añadirá si es compatible con el kernel. Esto puede utilizarse para configurar opciones de montaje que son opcionales y solo se habilitan en los kernels que las soportan. Tenga en cuenta que esto solo se admite para opciones de montaje nativas del kernel (es decir, explícitamente no para opciones de montaje implementadas en el espacio de usuario, como las procesadas por /usr/bin/mount mismo, por FUSE o por ayudantes de montaje como mount.nfs). Esta opción se puede especificar más de una vez.

Añadido en la versión 258.

x-systemd.device-bound=

Toma un argumento booleano. Si es verdadero o no hay argumento, se establece una dependencia BindsTo= en el dispositivo subyacente. Si es falso, la unidad de montaje no se detiene, independientemente de si el dispositivo subyacente todavía está presente. Esto es útil cuando el sistema de archivos está respaldado por administradores de volúmenes. Si no se establece y el montaje proviene de fragmentos de unidad, es decir, generado desde /etc/fstab por systemd-fstab-generator(8) o cargado desde una unidad de montaje configurada manualmente, se establece una combinación de dependencias Requires= y StopPropagatedFrom= en el dispositivo subyacente; de lo contrario, solo se utiliza Requires=.

Añadido en la versión 233.

x-systemd.automount

Se creará una unidad de montaje automático para el sistema de archivos. Ver systemd.automount(5) para más detalles.

Añadido en la versión 215.

x-systemd.idle-timeout=

Configura el tiempo de espera inactivo de la unidad de montaje automático. Ver TimeoutIdleSec= en systemd.automount(5) para más detalles.

x-systemd.device-timeout=

Configura cuánto tiempo esperará systemd a que aparezca un dispositivo antes de renunciar a una entrada de /etc/fstab. Especifica un tiempo en segundos o añade explícitamente una unidad como "s", "min", "h", "ms".

Tenga en cuenta que esta opción solo se puede utilizar en /etc/fstab y se ignorará cuando forme parte de la configuración Options= en un archivo de unidad.

Añadido en la versión 215.

x-systemd.mount-timeout=

Configura cuánto tiempo esperará systemd a que el comando mount finalice antes de renunciar a una entrada de /etc/fstab. Especifica un tiempo en segundos o añade explícitamente una unidad como "s", "min", "h", "ms".

Tenga en cuenta que esta opción solo se puede utilizar en /etc/fstab y se ignorará cuando forme parte de la configuración Options= en un archivo de unidad.

Ver TimeoutSec= a continuación para más detalles.

x-systemd.makefs

El sistema de archivos se inicializará en el dispositivo. Si el dispositivo no está "vacío", es decir, contiene alguna firma, la operación se omitirá. Por lo tanto, se espera que esta opción permanezca establecida incluso después de que el dispositivo se haya inicializado.

Tenga en cuenta que esta opción solo se puede utilizar en /etc/fstab y se ignorará cuando forme parte de la configuración Options= en un archivo de unidad.

Ver systemd-makefs@.service(8).

wipefs(8) puede utilizarse para eliminar cualquier firma de un dispositivo de bloques para forzar a x-systemd.makefs a reinicializar el dispositivo.

x-systemd.growfs

El sistema de archivos se ampliará para ocupar todo el dispositivo de bloques. Si el sistema de archivos ya está en su tamaño máximo, no se realizará ninguna acción. Por lo tanto, se espera que esta opción permanezca establecida incluso después de que el sistema de archivos se haya ampliado. Solo se admiten ciertos tipos de sistemas de archivos, ver systemd-makefs@.service(8) para más detalles.

Tenga en cuenta que esta opción solo se puede utilizar en /etc/fstab y se ignorará cuando forme parte de la configuración Options= en un archivo de unidad.

Añadido en la versión 236.

Mide información de identidad del sistema de archivos (punto de montaje, tipo, etiqueta, UUID, etiqueta de partición, UUID de partición) en el PCR 15 después de que el sistema de archivos se haya montado. Esto asegura que los servicios systemd-pcrfs@.service(8) o systemd-pcrfs-root.service sean incluidos por la unidad de montaje.

Tenga en cuenta que esta opción solo se puede utilizar en /etc/fstab y se ignorará cuando forme parte de la configuración Options= en un archivo de unidad. También se implica para las particiones raíz y /usr/ descubiertas por systemd-gpt-auto-generator(8).

Añadido en la versión 253.

x-systemd.validatefs

Valida los metadatos de restricciones de montaje del sistema de archivos montado después de montarlo. Esto asegura que el servicio systemd-validatefs@.service(8) sea incluido por la unidad de montaje.

Tenga en cuenta que esta opción solo se puede utilizar en /etc/fstab y se ignorará cuando forme parte de la configuración Options= en un archivo de unidad. También se implica para todas las particiones descubiertas por systemd-gpt-auto-generator(8).

Añadido en la versión 258.

x-systemd.rw-only

Si una operación de montaje falla al montar el sistema de archivos de lectura y escritura, normalmente intenta montar el sistema de archivos de solo lectura en su lugar. Esta opción deshabilita ese comportamiento y hace que el montaje falle inmediatamente. Esta opción se traduce a la configuración ReadWriteOnly= en un archivo de unidad.

Añadido en la versión 246.

_netdev

Normalmente, el tipo de sistema de archivos se utiliza para determinar si un montaje es un "montaje de red", es decir, si solo debe iniciarse después de que la red esté disponible. El uso de esta opción anula esta detección y especifica que el montaje requiere red.

Las unidades de montaje de red se ordenan entre remote-fs-pre.target y remote-fs.target, en lugar de local-fs-pre.target y local-fs.target. También incluyen network-online.target y se ordenan después de él y de network.target.

Añadido en la versión 235.

noauto, auto

Con noauto, la unidad de montaje no se añadirá como dependencia de local-fs.target o remote-fs.target. Esto significa que no se montará automáticamente durante el arranque, a menos que sea invocada por alguna otra unidad. La opción auto tiene el significado opuesto y es la predeterminada.

Tenga en cuenta que si se utiliza x-systemd.automount (ver arriba), ni auto ni noauto tienen ningún efecto. La unidad de montaje automático correspondiente se añadirá como dependencia al objetivo apropiado.

Añadido en la versión 215.

nofail

Con nofail, este montaje solo será deseado, no requerido, por local-fs.target o remote-fs.target. Además, la unidad de montaje no se ordena antes de estas unidades de destino. Esto significa que el arranque continuará sin esperar a la unidad de montaje y sin importar si el punto de montaje se puede montar correctamente.

Añadido en la versión 215.

x-initrd.mount

Un sistema de archivos adicional que se montará en el initrd. Ver la descripción de initrd-fs.target en systemd.special(7). Esto es tanto un indicador para el initrd de montar esta partición temprano como un indicador para el host de dejar la partición montada hasta el apagado final. O en otras palabras, si esta bandera está establecida, se asume que el montaje debe estar activo durante toda la ejecución regular del sistema, es decir, establecido antes de que el initrd transicione al host, hasta que el host transicione a la fase de apagado final.

Añadido en la versión 215.

Si un punto de montaje está configurado tanto en /etc/fstab como en un archivo de unidad almacenado en /usr/, el primero tendrá prioridad. Si el archivo de unidad está almacenado en /etc/, tendrá prioridad. Esto significa: los archivos de unidad nativos tienen prioridad sobre los archivos de configuración tradicionales, pero esto es reemplazado por la regla de que la configuración en /etc/ siempre tendrá prioridad sobre la configuración en /usr/.

NAME

systemd.mount - Mount point configuration file

SYNOPSIS

/etc/systemd/system/*.mount, /run/systemd/system/*.mount, /usr/lib/systemd/system/*.mount, /etc/fstab

DESCRIPTION

A `*.mount` unit file configures a mount point. This unit type is used to manage the mounting and unmounting of file systems. It is an alternative to the traditional fstab(5) file, and may be used in conjunction with it. systemd will automatically generate mount units for every entry in fstab(5) on boot or on demand.

These units may be enabled to start automatically on boot, and may be started and stopped like any other systemd unit.

The mount units are named after the file system's mount point path. For example, a mount unit for `/home/user` would be named `home-user.mount`.

Mount units should not be confused with automount units (see systemd.automount(5)), which are used to manage automount points.

AUTOMATIC DEPENDENCIES

A mount unit implicitly requires the mount point directory to exist. If the mount point does not exist, systemd will attempt to create it.

A mount unit implicitly depends on and is ordered with respect to the corresponding automount unit, if one exists. If a mount unit for `/home` is started, and an automount unit `home.automount` exists, the mount unit will be started only after the automount unit has been started.

A mount unit implicitly requires the file system to be ready. For local file systems, this means the block device must be available. For network file systems, this means the network must be available and the remote host reachable. These requirements are usually met by dependencies on devices and network units. systemd automatically creates appropriate dependencies based on the fstab(5) entry and the mount options used.

FSTAB

Entries in fstab(5) are automatically converted into mount units by the systemd-fstab-generator(8) daemon. The generator creates mount units in `/run/systemd/system` during boot. These units are named according to the mount point path. For example, an fstab entry for `/srv` would result in a `srv.mount` unit.

Users can override fstab entries by creating corresponding mount units in `/etc/systemd/system`. For example, to override the fstab entry for `/srv`, create `srv.mount` in `/etc/systemd/system`.

It is also possible to completely disable an fstab entry by creating a symlink with the same name in `/etc/systemd/system` that points to `/dev/null`.

OPTIONS

The mount unit file describes mount points and their properties. It is structured like other systemd unit files, with sections like `[Unit]` and `[Mount]`. The `[Mount]` section is specific to mount units.

The following options are available:

What=

Takes a string which is the path to be mounted. This may be a device node (e.g., `/dev/sda1`), a LABEL= or UUID= identifier, or a network path (e.g., `server:/share`). This option is mandatory. Note that the usual specifier expansion is applied to this setting, literal percent characters should hence be written as "%%". If this mount is a bind mount and the specified path does not exist yet it is created as directory.

Where=

Takes an absolute path of a file or directory for the mount point; in particular, the destination cannot be a symbolic link. If the mount point does not exist at the time of mounting, it is created as either a directory or a file. The former is the usual case; the latter is done only if this mount is a bind mount and the source (What=) is not a directory. This string must be reflected in the unit filename. (See above.) This option is mandatory.

Type=

Takes a string for the file system type. See mount(8) for details. This setting is optional.

If the type is "overlay", and "upperdir=" or "workdir=" are specified as options and the directories do not exist, they will be created.

Options=

Mount options to use when mounting. This takes a comma-separated list of options. This setting is optional. Note that the usual specifier expansion is applied to this setting, literal percent characters should hence be written as "%%".

SloppyOptions=

Takes a boolean argument. If true, parsing of the options specified in Options= is relaxed, and unknown mount options are tolerated. This corresponds with mount(8)'s -s switch. Defaults to off.

Added in version 215.

LazyUnmount=

Takes a boolean argument. If true, detach the filesystem from the filesystem hierarchy at time of the unmount operation, and clean up all references to the filesystem as soon as they are not busy anymore. This corresponds with umount(8)'s -l switch. Defaults to off.

Added in version 232.

ReadWriteOnly=

Takes a boolean argument. If false, a mount point that shall be mounted read-write but cannot be mounted so is retried to be mounted read-only. If true the operation will fail immediately after the read-write mount attempt did not succeed. This corresponds with mount(8)'s -w switch. Defaults to off.

Added in version 246.

ForceUnmount=

Takes a boolean argument. If true, force an unmount (in case of an unreachable NFS system). This corresponds with umount(8)'s -f switch. Defaults to off.

Added in version 232.

DirectoryMode=

Directories of mount points (and any parent directories) are automatically created if needed. This option specifies the file system access mode used when creating these directories. Takes an access mode in octal notation. Defaults to 0755.

TimeoutSec=

Configures the time to wait for the mount command to finish. If a command does not exit within the configured time, the mount will be considered failed and be shut down again. All commands still running will be terminated forcibly via SIGTERM, and after another delay of this time with SIGKILL. (See KillMode= in systemd.kill(5).) Takes a unit-less value in seconds, or a time span value such as "5min 20s". Pass 0 to disable the timeout logic. The default value is set from DefaultTimeoutStartSec= option in systemd-system.conf(5).

Check systemd.unit(5), systemd.exec(5), and systemd.kill(5) for more settings.
