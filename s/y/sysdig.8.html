NOMBRE

sysdig - la herramienta definitiva para la resolución de problemas del sistema y procesos

SINOPSIS

sysdig [opción]... [filtro]

DESCRIPCIÓN

Nota: si está interesado en una interfaz más fácil de usar para la funcionalidad de sysdig, use la utilidad de línea de comandos csysdig.

sysdig es una herramienta para la resolución de problemas, análisis y exploración de sistemas. Se puede utilizar para capturar, filtrar y decodificar llamadas al sistema y otros eventos del SO. sysdig se puede usar tanto para inspeccionar sistemas en vivo como para generar archivos de traza que se pueden analizar en una etapa posterior.

sysdig incluye un potente lenguaje de filtrado, tiene salida personalizable y se puede extender a través de scripts Lua, llamados "chisels".

Formato de salida

Por defecto, sysdig imprime la información de cada evento capturado en una sola línea, con el siguiente formato:

*%evt.num %evt.time %evt.cpu %proc.name (%thread.tid) %evt.dir %evt.type %evt.info

donde:

•
evt.num es el número incremental del evento
•
evt.time es la marca de tiempo del evento
•
evt.cpu es el número de CPU donde se capturó el evento
•
proc.name es el nombre del proceso que generó el evento
•
thread.tid es el ID del hilo que generó el evento, que corresponde al PID para procesos de un solo hilo
•
evt.dir es la dirección del evento, > para eventos de entrada y < para eventos de salida
•
evt.type es el nombre del evento, por ejemplo, 'open' o 'read'
•
evt.args es la lista de argumentos del evento.

El formato de salida se puede personalizar con la opción -p, utilizando cualquiera de los campos listados por 'sysdig -l'.

Usando -pc o -pcontainer, el formato predeterminado cambiará a uno amigable para contenedores:

*%evt.num %evt.time %evt.cpu %container.name (%container.id) %proc.name (%thread.tid:%thread.vtid) %evt.dir %evt.type %evt.info

Archivos de traza

Se puede crear un archivo de traza usando la opción -w:

$ sysdig -w trace.scap

La opción -s se puede usar para especificar cuántos bytes de cada búfer de datos se deben guardar en disco. Y se pueden usar filtros para guardar solo eventos específicos en disco:

$ sysdig -s 2000 -w trace.scap proc.name=cat

Los archivos de traza se pueden leer usando la opción -r:

$ sysdig -r trace.scap

Filtrado

Los filtros de sysdig se especifican al final de la línea de comandos. El filtro más simple es una verificación básica de campo-valor:

$ sysdig proc.name=cat

La lista de campos disponibles se puede obtener con 'sysdig -l'. Las expresiones de filtro pueden usar uno de estos operadores de comparación: =, !=, <, <=, >, >=, contains, icontains, in y exists. ej.

$ sysdig fd.name contains /etc $ sysdig "evt.type in ( 'select', 'poll' )" $ sysdig proc.name exists

Se pueden combinar varias comprobaciones a través de corchetes y los siguientes operadores booleanos: and, or, not. ej.

$ sysdig "not (fd.name contains /proc or fd.name contains /dev)"

Chisels

Los chisels de sysdig son pequeños scripts que analizan la corriente de eventos de sysdig para realizar acciones útiles. Para obtener la lista de chisels disponibles, escriba

$ sysdig -cl

Para obtener detalles sobre un chisel específico, escriba

$ sysdig -i spy_ip

Para ejecutar uno de los chisels, use la bandera -c, ej.

$ sysdig -c topfiles_bytes

Si un chisel necesita argumentos, especifíquelos después del nombre del chisel:

$ sysdig -c spy_ip 192.168.1.157

Si un chisel tiene más de un argumento, especifíquelos después del nombre del chisel, entre comillas:

$ sysdig -c chisel_name "arg1 arg2 arg3"

Los chisels se pueden combinar con filtros:

$ sysdig -c topfiles_bytes "not fd.name contains /dev"

OPCIONES

-A, --print-ascii Solo imprime la porción de texto de los búferes de datos, y hace eco de los saltos de línea. Esto es útil para mostrar solo datos legibles por humanos.

-b, --print-base64 Imprime los búferes de datos en base64. Esto es útil para codificar datos binarios que necesitan ser utilizados en medios diseñados para manejar datos textuales (es decir, terminal o json).

-c nombre_chisel argumentos_chisel, --chisel=nombre_chisel argumentos_chisel ejecuta el chisel especificado. Si el chisel requiere argumentos, deben especificarse en la línea de comandos después del nombre.

-C tamaño_archivo Divide una captura en archivos separados, y limita el tamaño de cada archivo según el número especificado de megabytes. Las unidades de tamaño_archivo son millones de bytes (10^6, no 2^20). Usar junto con -W para habilitar la rotación automática de archivos. De lo contrario, se seguirán creando nuevos archivos hasta que la captura se detenga manualmente.

Los archivos tendrán el nombre especificado por -w con un contador añadido comenzando en 0.

-cl, --list-chisels lista los chisels disponibles. Sysdig busca chisels en los siguientes directorios: ./chisels, ~/.chisels y /usr/share/sysdig/chisels.

-d, --displayflt Hace que el filtro dado sea un filtro de visualización. Establecer esta opción hace que los eventos se filtren después de ser analizados por el sistema de estado. Los eventos normalmente se filtran antes de ser analizados, lo que es más eficiente, pero puede causar la pérdida de estado (por ejemplo, nombres de FD).

-D, --debug Captura eventos sobre sysdig mismo, muestra eventos internos además de eventos del sistema, e imprime registro adicional en el error estándar.

-E, --exclude-users No crea las tablas de usuarios/grupos consultando al SO cuando sysdig se inicia. Esto también significa que no se escribirá información de usuario o grupo en el archivo de traza con la bandera -w. Las tablas de usuarios/grupos son necesarias para usar campos de filtro como user.name o group.name. Sin embargo, crearlas puede aumentar el tiempo de inicio de sysdig. Además, contienen información que podría ser sensible a la privacidad.

-e numeventos Divide una captura en archivos separados, y limita el tamaño de cada archivo según el número especificado de eventos. Usar junto con -W para habilitar la rotación automática de archivos. De lo contrario, se seguirán creando nuevos archivos hasta que la captura se detenga manualmente.

Los archivos tendrán el nombre especificado por -w con un contador añadido comenzando en 0.

-F, --fatfile Habilita el modo fatfile. Al escribir en modo fatfile, el archivo de salida contendrá eventos que serán invisibles al leer el archivo, pero que son necesarios para reconstruir completamente el estado. El modo fatfile es útil al guardar eventos en disco con un filtro agresivo. El filtro podría descartar eventos que harían que el estado se actualizara (por ejemplo, clone() u open()). Con el modo fatfile, esos eventos todavía se guardan en el archivo, pero se 'ocultan' para que no aparezcan al leer el archivo. Tenga en cuenta que usar esta bandera puede generar archivos de traza sustancialmente más grandes.

--filter-proclist aplica el filtro a la tabla de procesos. Normalmente se incluye una volcada completa de /proc en cualquier archivo de traza para asegurarse de que todo el estado necesario para decodificar los eventos esté en el archivo. Esto podría hacer que el archivo contenga información no deseada o sensible. Usar esta bandera hace que el filtro de la línea de comandos se aplique también a la volcada de /proc.

-G numsegundos Divide una captura en archivos separados, y limita el tamaño de cada archivo según el número especificado de segundos. Usar junto con -W para habilitar la rotación automática de archivos. De lo contrario, se seguirán creando nuevos archivos hasta que la captura se detenga manualmente.

Los archivos tendrán el nombre especificado por -w, el cual debería incluir un formato de tiempo según lo definido por strftime(3). Si no se especifica ningún formato de tiempo, se utilizará un contador.

SYSCHISEL

sysdig

sysdig es una herramienta de código abierto para la inspección y el análisis de sistemas, que le permite capturar y analizar datos de rendimiento y actividad del sistema.

SYNOPSIS

sysdig [-C, --cfgfile file] [-c, --chisel name] [-cl, --list-chisels] [-d, --debug] [-f, --config file] [-F, --force-drivers] [-g, --group group] [-h, --help] [-H, --initconf conf] [-I, --input plugin] [-Il, --list-inputs] [--plugin-config-file file] [-i, --chisel-info name] [-j, --json] [-k, --k8s-api url] [-K, --k8s-api-cert certs] [-L, --list-events] [-l, --list] [--list-markdown] [-m, --mesos-api urls] [-M seconds] [-n, --numevents num] [--page-faults] [-P, --progress] [-p, --print format] [-q, --quiet] [-r, --read file] [-R, --resolve-ports] [-S, --summary] [-s, --snaplen len] [-t, --timetype type] [-T, --force-tracers-capture] [--unbuffered] [-v, --verbose] [--version] [-w, --write file] [-W num] [-x, --print-hex] [-X, --print-hex-ascii] [-z, --compress] [filter]

DESCRIPTION

sysdig es una herramienta de código abierto para la inspección y el análisis de sistemas, que le permite capturar y analizar datos de rendimiento y actividad del sistema. Está diseñado para ser potente y flexible, y se puede utilizar para una variedad de tareas, como la depuración de aplicaciones, la monitorización de la seguridad y la optimización del rendimiento.

OPTIONS

-C file, --cfgfile=file Load the configuration from the specified file.

-c name, --chisel=name Run the chisel named name. Chisels are Lua scripts that provide higher-level abstractions on top of the captured events. Use -cl to list the available chisels.

-cl, --list-chisels List the available chisels. Sysdig looks for chisels in the following directories: /usr/share/sysdig/chisels, ~/.chisels.

-d, --debug Enable debug output.

-f file, --config=file Load the configuration from the specified file. The configuration file is used to specify default values for various sysdig options, such as the output format and the filters to be applied. The configuration file is written in Lua.

-F, --force-drivers Force loading of kernel drivers. This option is useful when sysdig is unable to load the drivers automatically.

-g group, --group=group Run sysdig as the specified group.

-h, --help Print a help message and exit.

-H initconf, --initconf=initconf Initialize the driver with the specified configuration. The format of initconf is controlled by the plugin, refer to each plugin's documentation to learn about it.

-I pluginname[:openparams], --input pluginname[:openparams] Capture events using the plugin with name pluginname, passing to the plugin the openparams string as parameters. The format of inputargs is controller by the plugin, refer to each plugin's documentation to learn about it. The event sources available for capture vary depending on which plugins have been installed. You can list the plugins that have been loaded by using the -Il flag.

-Il, --list-inputs List the loaded plugins. Sysdig looks for plugins in the following directories: ./plugins, ~/.plugins, /usr/share/sysdig/plugins.

--plugin-config-file Load the plugin configuration from a Falco-compatible yaml config file. Mixing this option with '-H' or '-I' is unsupported. See the plugin section in https://falco.org/docs/configuration/ for additional informations.

-i chiselname, --chisel-info=chiselname Get a longer description and the arguments associated with a chisel found in the -cl option list.

-j, --json Emit output as json, data buffer encoding will depend from the print format selected.

-k, --k8s-api Enable Kubernetes support by connecting to the API server specified as argument. E.g. "http://admin:password@127.0.0.1:8080". The API server can also be specified via the environment variable SYSDIG_K8S_API.

-K btfile | certfile:keyfile[#password][:cacertfile], --k8s-api-cert=btfile | certfile:keyfile[#password][:cacertfile] Use the provided files names to authenticate user and (optionally) verify the K8S API server identity. Each entry must specify full (absolute, or relative to the current directory) path to the respective file. Private key password is optional (needed only if key is password protected). CA certificate is optional. For all files, only PEM file format is supported. Specifying CA certificate only is obsoleted - when single entry is provided for this option, it will be interpreted as the name of a file containing bearer token. Note that the format of this command-line option prohibits use of files whose names contain ':' or '#' characters in the file name. Option can also be provided via the environment variable SYSDIG_K8S_API_CERT.

-L, --list-events List the events that the engine supports

-l, --list List the fields that can be used for filtering and output formatting. Use -lv to get additional information for each field.

--list-markdown Like -l, but produces markdown output

-m url[,marathon-url], --mesos-api=url[,marathon-url] Enable Mesos support by connecting to the API server specified as argument (e.g. http://admin:password@127.0.0.1:5050). Mesos url is required. Marathon url is optional, defaulting to auto-follow - if Marathon API server is not provided, sysdig will attempt to retrieve (and subsequently follow, if it migrates) the location of Marathon API server from the Mesos master. Note that, with auto-follow, sysdig will likely receive a cluster internal IP address for Marathon API server, so running sysdig with Marathon auto-follow from a node that is not part of Mesos cluster may not work. Additionally, running sysdig with Mesos support on a node that has no containers managed by Mesos is of limited use because, although cluster metadata will be collected, there will be no Mesos/Marathon filtering capability. The API servers can also be specified via the environment variable SYSDIG_MESOS_API.

-M num_seconds Stop collecting after reaching

-n num, --numevents=num

Stop capturing after num events

--page-faults Capture user/kernel major/minor page faults

-P, --progress

Print progress on stderr while processing trace files.

-p outputformat, --print=outputformat

Specify the format to be used when printing the events. With -pc or -pcontainer will use a container-friendly format. With -pk or -pkubernetes will use a kubernetes-friendly format. With -pm or -pmesos will use a mesos-friendly format. Specifying -pp on the command line will cause sysdig to print the default command line format and exit.

-q, --quiet

Don't print events on the screen. Useful when dumping to disk.

-r readfile, --read=readfile

Read the events from readfile.

-R, --resolve-ports Resolve port numbers to names.

-S, --summary

print the event summary (i.e. the list of the top events) when the capture ends.

-s len, --snaplen=len

Capture the first len bytes of each I/O buffer. By default, the first 80 bytes are captured. Use this option with caution, it can generate huge trace files.

-t timetype, --timetype=timetype

Change the way event time is displayed. Accepted values are h for human-readable string, a for absolute timestamp from epoch, r for relative time from the first displayed event, d for delta between event enter and exit, and D for delta from the previous event.

-T, --force-tracers-capture

Tell the driver to make sure full buffers are captured from /dev/null, to make sure that tracers are completely captured. Note that sysdig will enable extended /dev/null capture by itself after detecting that tracers are written there, but that could result in the truncation of some tracers at the beginning of the capture. This option allows preventing that.

--unbuffered

Turn off output buffering. This causes every single line emitted by sysdig to be flushed, which generates higher CPU usage but is useful when piping sysdig's output into another process or into a script.

-v, --verbose

Verbose output. This flag will cause the full content of text and binary buffers to be printed on screen, instead of being truncated to 40 characters. Note that data buffers length is still limited by the snaplen (refer to the -s flag documentation) -v will also make sysdig print some summary information at the end of the capture.

--version

Print version number.

-w writefile, --write=writefile

Write the captured events to writefile.

-W num

Turn on file rotation for continuous capture, and limit the number of files created to the specified number. Once the cap is reached, older files will be overwritten (ring buffer). Use in conjunction with the -C / -G / -e options to limit the size of each file based on number of megabytes, seconds, and/or events (respectively).

-x, --print-hex

Print data buffers in hex.

-X, --print-hex-ascii

Print data buffers in hex and ASCII.

-z, --compress

Used with -w, enables compression for tracefiles.

EXAMPLES

Capture all the events from the live system and print them to screen

$ sysdig

Capture all the events from the live system and save them to disk

$ sysdig -w dumpfile.scap

Capture all the events in the latest 24 hours and save them to disk organized in files containing 1 hour of system activity each

$ sysdig -G 3600 -W 24 -w dumpfile.scap

Read events from a file and print them to screen

$ sysdig -r dumpfile.scap

Prepare a sanitized version of a system capture

$ sysdig -r dumpfile.scap 'not evt.buffer contains foo' -w cleandump.scap

Print all the open system calls invoked by cat

$ sysdig proc.name=cat and evt.type=open

Print the name of the files opened by cat

$ sysdig -p"%evt.arg.name" proc.name=cat and evt.type=open

List the available chisels

$ sysdig -cl

Use the spy_ip chisel to look at the data exchanged with 192.168.1.157:

$ sysdig -c spy_ip 192.168.1.157

FILES

/usr/share/sysdig/chisels

The global chisels directory.

~/.chisels

The personal chisels directory.

BUGS

•
sysdig and its chisels are designed to be used with LuaJIT in Lua 5.1 mode. While it is possible to use sysdig with LuaJIT in Lua 5.2 mode or regular Lua, some chisels may not work as expected.
