NOMBRE

syncthing-networking - Configuración del cortafuegos

CONFIGURACIÓN DEL ENRUTADOR

Reenvío de puertos

Si tiene un enrutador NAT que admite UPnP, la forma más sencilla de obtener un reenvío de puerto funcional es asegurarse de que la configuración UPnP esté habilitada tanto en Syncthing como en el enrutador; Syncthing intentará encargarse del resto. Si tiene éxito, verá un mensaje en la consola que dice:

Se ha creado un mapeo de puerto UPnP para el puerto externo XXXXX en el dispositivo UPnP YYYYY.

Si esto no es posible o deseable, debe configurar un reenvío de puertos para los puertos 22000/TCP y 22000/UDP (o el puerto que se establezca en la configuración Dirección de escucha del protocolo Sync). Los puertos externos reenviados y los puertos de destino internos deben ser los mismos (por ejemplo, 22000/TCP).

La comunicación en Syncthing funciona en ambos sentidos. Por lo tanto, si configura reenvíos de puertos para un dispositivo, otros dispositivos podrán conectarse a él incluso cuando estén detrás de una red NAT o un cortafuegos.

En ausencia de reenvío de puertos, el relevo puede funcionar lo suficientemente bien como para conectar y sincronizar dispositivos, pero tendrá un rendimiento deficiente en comparación con una conexión directa.

Descubrimiento local

El enrutador debe permitir/reenviar multidifusiones para que el descubrimiento local funcione. Normalmente, estos están permitidos por defecto en una única subred local, pero pueden bloquearse entre diferentes subredes o incluso entre una Wi-Fi y una LAN puenteadas.

Si no puede configurar su enrutador de esta manera o su cortafuegos como se muestra a continuación, y sus dispositivos tienen direcciones IP estáticas, puede especificarlas directamente cambiando la configuración dinámica por defecto de Direcciones a algo como: tcp://192.168.1.xxx:22000, dinámico.

CORTAFUEGOS LOCAL

Si su PC tiene un cortafuegos local, deberá abrir los siguientes puertos para el tráfico entrante y saliente:

  • Puerto 22000/TCP: Tráfico del protocolo de sincronización basado en TCP
  • Puerto 22000/UDP: Tráfico del protocolo de sincronización basado en QUIC
  • Puerto 21027/UDP: para transmisiones de descubrimiento en IPv4 y multidifusiones en IPv6

Si configuró un puerto personalizado en la configuración Dirección de escucha del protocolo Sync, deberá adaptar las reglas del cortafuegos en consecuencia.

Cortafuegos sin complicaciones (ufw)

sudo ufw allow syncthing

Si también desea permitir el acceso externo a la GUI web de Syncthing, ejecute:

sudo ufw allow syncthing-gui

Permitir el acceso externo **no** es necesario para una instalación típica.

Luego puede verificar que los puertos mencionados anteriormente estén permitidos:

Firewalld

sudo firewall-cmd --zone=public --add-service=syncthing --permanent
sudo firewall-cmd --reload

Del mismo modo, también existe un servicio syncthing-gui.

GUI WEB REMOTA

Para poder acceder a la GUI web desde otros ordenadores, necesita cambiar la configuración Dirección de escucha de la GUI de la configuración predeterminada 127.0.0.1:8384 a 0.0.0.0:8384. También necesita abrir el puerto en su cortafuegos local si tiene uno.

Tunelización a través de SSH

Si tiene acceso SSH a la máquina que ejecuta Syncthing pero prefiere no abrir el puerto de la GUI web al mundo exterior, puede acceder a él a través de un túnel SSH. Puede iniciar un túnel con un comando como el siguiente:

ssh -L 9999:localhost:8384 máquina

Esto se vinculará a su puerto local 9999 y reenviará todas las conexiones desde allí al puerto 8384 en la máquina de destino. Esto sigue funcionando incluso si Syncthing está configurado para escuchar solo en localhost.

A TRAVÉS DE UN PROXY

Syncthing puede utilizar un proxy SOCKS5 para conexiones salientes. Consulte Uso de Proxies.
