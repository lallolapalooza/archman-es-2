NOMBRE

systemd-socket-proxyd - Proxy bidireccional de sockets locales a otro socket (posiblemente remoto)

SINOPSIS

systemd-socket-proxyd [OPCIONES...] HOST:PUERTO

systemd-socket-proxyd [OPCIONES...] RUTA-SOCKET-UNIX

DESCRIPCIÓN

systemd-socket-proxyd es un reenviador proxy genérico activado por socket para sockets de red para IPv4, IPv6 y sockets de flujo UNIX. Puede utilizarse para reenviar bidireccionalmente el tráfico de un socket de escucha local a un socket de destino local o remoto.

Un uso de esta herramienta es proporcionar soporte de activación de socket para servicios que no admiten la activación de socket de forma nativa. En nombre del servicio a activar, el proxy hereda el socket de systemd, acepta cada conexión de cliente, abre una conexión a un servidor configurado para cada cliente y luego reenvía bidireccionalmente los datos entre ambos.

El comportamiento de esta utilidad es similar a socat(1). Las principales diferencias para systemd-socket-proxyd son el soporte para la activación de socket con "Accept=no" y un diseño impulsado por eventos que escala mejor con el número de conexiones.

Tenga en cuenta que systemd-socket-proxyd no reenviará información del canal lateral del socket, es decir, no reenviará SCM_RIGHTS, SCM_CREDENTIALS, SCM_SECURITY, SO_PEERCRED, SO_PEERPIDFD, SO_PEERSEC, SO_PEERGROUPS y similares.

OPCIONES

Se admiten las siguientes opciones:

-h, --help

Muestra un texto de ayuda breve y sale.

--version

Muestra una cadena de versión breve y sale.

--connections-max=, -c

Establece el número máximo de conexiones simultáneas, predeterminado a 256. Si se alcanza el límite de conexiones concurrentes, se rechazarán las conexiones adicionales.

Añadido en la versión 233.

--exit-idle-time=

Establece el tiempo antes de salir cuando no hay conexiones, predeterminado a infinito. Acepta un valor sin unidades en segundos, o un valor de período de tiempo como "5min 20s".

Añadido en la versión 246.

ESTADO DE SALIDA

En caso de éxito, se devuelve 0, de lo contrario, un código de error distinto de cero.

EJEMPLOS

Ejemplo Simple

Utiliza dos servicios con una dependencia y sin aislamiento de espacio de nombres.

Ejemplo 1. proxy-to-nginx.socket

[Socket]
ListenStream=80
[Install]
WantedBy=sockets.target

Ejemplo 2. proxy-to-nginx.service

[Unit]
Requires=nginx.service
After=nginx.service
Requires=proxy-to-nginx.socket
After=proxy-to-nginx.socket
[Service]
Type=notify
ExecStart=/usr/lib/systemd/systemd-socket-proxyd /run/nginx/socket
PrivateTmp=yes
PrivateNetwork=yes

Ejemplo 3. nginx.conf

[...]
server {
    listen       unix:/run/nginx/socket;
    [...]

Ejemplo 4. Habilitación del proxy

# systemctl enable --now proxy-to-nginx.socket
$ curl http://localhost:80/

Si nginx.service tiene StopWhenUnneeded= configurado, entonces pasar --exit-idle-time= a systemd-socket-proxyd permite que ambos servicios se detengan durante los períodos de inactividad.

Ejemplo de Espacio de Nombres

Similar a lo anterior, pero ejecuta el proxy de socket y el servicio principal en el mismo espacio de nombres privado, asumiendo que nginx.service también tiene configurados PrivateTmp= y PrivateNetwork=.

Ejemplo 5. proxy-to-nginx.socket

[Socket]
ListenStream=80
[Install]
WantedBy=sockets.target

Ejemplo 6. proxy-to-nginx.service

[Unit]
Requires=nginx.service
After=nginx.service
Requires=proxy-to-nginx.socket
After=proxy-to-nginx.socket
JoinsNamespaceOf=nginx.service
[Service]
Type=notify
ExecStart=/usr/lib/systemd/systemd-socket-proxyd 127.0.0.1:8080
PrivateTmp=yes
PrivateNetwork=yes

Ejemplo 7. nginx.conf

[...]
server {
    listen       8080;
    [...]

Ejemplo 8. Habilitación del proxy

# systemctl enable --now proxy-to-nginx.socket
$ curl http://localhost:80/
