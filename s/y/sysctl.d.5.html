SYSCTL.D(5) sysctl.d SYSCTL.D(5)

NOMBRE

sysctl.d - Configurar parámetros del kernel al arrancar

SINOPSIS

/etc/sysctl.d/*.conf
/run/sysctl.d/*.conf
/usr/local/lib/sysctl.d/*.conf
/usr/lib/sysctl.d/*.conf
clave.nombre.en.proc.sys = algún valor
clave/nombre/en/proc/sys = algún valor
clave/parte.intermedia.con.puntos/foo = 123
clave.parte.intermedia/con/puntos.foo = 123
-clave.que.no.fallará = valor
clave.patron.*.con.glob = cualquier cosa
-clave.patron.excluida.con.glob
clave.patron.sobrescrita.con.glob = personalizada

DESCRIPCIÓN

Al arrancar, systemd-sysctl.service(8) lee archivos de configuración de los directorios anteriores para configurar los parámetros del kernel de sysctl(8).

FORMATO DE CONFIGURACIÓN

Los archivos de configuración contienen una lista de asignaciones de variables, separadas por saltos de línea. Las líneas vacías y las líneas cuyo primer carácter que no sea espacio en blanco sea '#' o ';' se ignoran.

Tenga en cuenta que tanto '/' como '.' pueden usarse como separadores dentro de los nombres de variables de sysctl. Si el primer separador es una barra, las barras y puntos restantes se dejan intactos. Si el primer separador es un punto, los puntos y las barras se intercambian. "kernel.domainname=foo" y "kernel/domainname=foo" son equivalentes y provocarán que "foo" se escriba en /proc/sys/kernel/domainname. Se puede usar tanto "net.ipv4.conf.enp3s0/200.forwarding" como "net/ipv4/conf/enp3s0.200/forwarding" para referirse a /proc/sys/net/ipv4/conf/enp3s0.200/forwarding. Se puede utilizar un patrón de glob(7) para escribir el mismo valor en todas las claves coincidentes. Las claves para las que existe un patrón explícito se excluirán de cualquier coincidencia de glob. Además, una clave puede excluirse explícitamente de ser establecida por cualquier patrón de glob coincidente especificando el nombre de la clave precedido por un carácter '-' y no seguido por '=', véase SINOPSIS.

Cualquier error de permiso de acceso e intentos de escribir variables no presentes en el sistema local se registran a nivel de depuración y no provocan que el servicio falle. Otros tipos de errores al establecer variables se registran con mayor prioridad y hacen que el servicio devuelva un fallo al final (después de procesar otras variables). Como excepción, si una asignación de variable está precedida por un solo carácter '-', el fallo al establecer la variable por cualquier motivo se registrará a nivel de depuración y no provocará que el servicio falle.

La configuración establecida con los archivos sysctl.d se aplicará al principio del arranque. Las opciones específicas de la interfaz de red también se aplicarán individualmente para cada interfaz de red a medida que aparezca en el sistema. (Más específicamente, net.ipv4.conf.*, net.ipv6.conf.*, net.ipv4.neigh.* y net.ipv6.neigh.*).

Muchos parámetros de sysctl solo estarán disponibles cuando se carguen ciertos módulos del kernel. Los módulos generalmente se cargan bajo demanda, por ejemplo, cuando se conecta hardware específico o se activa la red. Esto significa que systemd-sysctl.service(8), que se ejecuta durante el arranque temprano, no configurará tales parámetros si se vuelven disponibles después de su ejecución. Para establecer dichos parámetros, se recomienda agregar una regla de udev(7) para establecer esos parámetros cuando estén disponibles. Alternativamente, una opción ligeramente más simple y menos eficiente es agregar el módulo a modules-load.d(5), lo que provocará que se cargue estáticamente antes de que se apliquen la configuración de sysctl (ver ejemplo a continuación).

DIRECTORIOS DE CONFIGURACIÓN Y PREFERENCIA

Los archivos de configuración se leen de los directorios /etc/, /run/, /usr/local/lib/ y /usr/lib/, en orden de preferencia, como se indica en la sección SINOPSIS anterior. Los archivos deben tener la extensión ".conf". Los archivos en /etc/ anulan a los archivos con el mismo nombre en /run/, /usr/local/lib/ y /usr/lib/. Los archivos en /run/ anulan a los archivos con el mismo nombre en /usr/.

Todos los archivos de configuración se ordenan por su nombre de archivo en orden lexicográfico, independientemente del directorio en el que residan. Si varios archivos especifican la misma opción, prevalecerá la entrada en el archivo con el nombre lexicográficamente posterior. Por lo tanto, la configuración en un archivo determinado puede ser reemplazada por completo (colocando un archivo con el mismo nombre en un directorio de mayor prioridad), o las configuraciones individuales pueden modificarse (especificando configuraciones adicionales en un archivo con un nombre diferente que se ordene más tarde).

Los paquetes deben instalar sus archivos de configuración en /usr/lib/ (paquetes de distribución) o /usr/local/lib/ (instalaciones locales) [1]. Los archivos en /etc/ están reservados para el administrador local, quien puede usar esta lógica para anular los archivos de configuración instalados por los paquetes del proveedor.

Se recomienda prefijar todos los nombres de archivo con un número de dos dígitos y un guion para simplificar el ordenamiento. Se recomienda utilizar el rango 10-40 para los archivos de configuración en /usr/ y el rango 60-90 para los archivos de configuración en /etc/ y /run/, para asegurar que los archivos de configuración locales y transitorios siempre tengan prioridad sobre los archivos de configuración proporcionados por el proveedor del sistema operativo.

Si el administrador desea deshabilitar un archivo de configuración proporcionado por el proveedor, la forma recomendada es colocar un enlace simbólico a /dev/null en el directorio de configuración en /etc/, con el mismo nombre de archivo que el archivo de configuración del proveedor. Si el archivo de configuración del proveedor está incluido en la imagen initrd, la imagen debe regenerarse.

EJEMPLOS

Ejemplo 1. Establecer el nombre de dominio YP del kernel

/etc/sysctl.d/domain-name.conf:

kernel.domainname=example.com

Ejemplo 2. Aplicar configuraciones disponibles solo cuando se carga un módulo específico (método uno)

/etc/udev/rules.d/99-bridge.rules:

ACTION=="add", SUBSYSTEM=="module", KERNEL=="br_netfilter", \
      RUN+="/usr/lib/systemd/systemd-sysctl --prefix=/net/bridge"

/etc/sysctl.d/bridge.conf:

net.bridge.bridge-nf-call-ip6tables = 0
net.bridge.bridge-nf-call-iptables = 0
net.bridge.bridge-nf-call-arptables = 0

Este método aplica la configuración cuando se carga el módulo. Tenga en cuenta que, a menos que se cargue el módulo br_netfilter, los paquetes en puentes no serán filtrados por Netfilter (a partir del kernel 3.18), por lo que simplemente no cargar el módulo es suficiente para evitar el filtrado.

Ejemplo 3. Aplicar configuraciones disponibles solo cuando se carga un módulo específico (método dos)

/etc/modules-load.d/bridge.conf:

br_netfilter

/etc/sysctl.d/bridge.conf:

net.bridge.bridge-nf-call-ip6tables = 0
net.bridge.bridge-nf-call-iptables = 0
net.bridge.bridge-nf-call-arptables = 0

Este método fuerza la carga del módulo siempre. Tenga en cuenta que, a menos que se cargue el módulo br_netfilter, los paquetes en puentes no serán filtrados por Netfilter (a partir del kernel 3.18), por lo que simplemente no cargar el módulo es suficiente para evitar el filtrado.

Ejemplo 4. Establecer propiedades de enrutamiento de red para todas las interfaces

/etc/sysctl.d/20-rp_filter.conf:

net.ipv4.conf.default.rp_filter = 2
net.ipv4.conf.*.rp_filter = 2
-net.ipv4.conf.all.rp_filter
net.ipv4.conf.hub0.rp_filter = 1

El parámetro rp_filter se establecerá en "2" para todas las interfaces, excepto "hub0". Establecemos net.ipv4.conf.default.rp_filter primero, para que cualquier interfaz que se agregue *después* obtenga este valor (esto también cubre cualquier interfaz detectada mientras estamos en ejecución). El glob coincide con cualquier interfaz que se detectó *antes*. El glob también coincidirá con net.ipv4.conf.all.rp_filter, que no queremos establecer en absoluto, por lo que se excluye explícitamente. Y "hub0" se excluye del glob porque tiene una configuración explícita.
