SYSTEMD-JOURNAL-REMOTE.SERVICE(8) systemd-journal-remote.service SYSTEMD-JOURNAL-REMOTE.SERVICE(8)

NOMBRE

systemd-journal-remote.service, systemd-journal-remote.socket, systemd-journal-remote - Recibir mensajes del journal a través de la red

SINOPSIS

systemd-journal-remote.service

systemd-journal-remote.socket

/usr/lib/systemd/systemd-journal-remote [OPCIONES...] [-o/--output=DIR|ARCHIVO] [FUENTES...]

DESCRIPCIÓN

systemd-journal-remote es un comando para recibir eventos del journal serializados y almacenarlos en archivos del journal. Los flujos de entrada están en el Formato de Exportación del Journal[1], es decir, como la salida de journalctl --output=export. Para el transporte a través de la red, este flujo serializado generalmente se transporta a través de una conexión HTTPS.

systemd-journal-remote.service es un servicio del sistema que utiliza systemd-journal-remote para escuchar conexiones. systemd-journal-remote.socket configura la dirección de red en la que systemd-journal-remote.service escucha. Por defecto, es el puerto 19532. Qué conexiones se aceptan y cómo se almacenan los datos recibidos se pueden configurar a través del archivo de configuración journal-remote.conf(5).

FUENTES

Las fuentes pueden ser "activas" ( systemd-journal-remote solicita y extrae los datos) o "pasivas" (systemd-journal-remote espera una conexión y luego recibe eventos enviados por el otro lado).

systemd-journal-remote puede leer más de un flujo de eventos a la vez. Se intercalarán en el archivo de salida. En el caso de conexiones "activas", cada "fuente" es un flujo, y en el caso de conexiones "pasivas", cada conexión puede resultar en un flujo separado. Los sockets se pueden configurar en modo "accept" (es decir, solo una conexión) o en modo "listen" (es decir, múltiples conexiones, cada una resultando en un flujo).

Cuando no hay más conexiones y no se pueden crear más (no hay sockets de escucha), systemd-journal-remote saldrá.

Las fuentes activas se pueden especificar de las siguientes maneras:

[FUENTES]

Cuando se da - como argumento posicional, los eventos se leerán de la entrada estándar. Otros argumentos posicionales se tratarán como nombres de archivo para abrir y leer.

Añadido en la versión 239.

--url=DIRECCIÓN

Con la opción --url=DIRECCIÓN, los eventos se recuperarán mediante HTTP de DIRECCIÓN. Esta URL debe referirse a la raíz de una instancia remota de systemd-journal-gatewayd(8), por ejemplo, http://algún.host:19531/ o https://algún.host:19531/.

Añadido en la versión 239.

--getter='PROG [OPCIONES]'

Programa a invocar para recuperar datos. El flujo de eventos del journal debe generarse en la salida estándar.

Ejemplos:

--getter='curl "-HAccept: application/vnd.fdo.journal" https://algún.host:19531/'
--getter='wget --header="Accept: application/vnd.fdo.journal" -O- https://algún.host:19531/'

Añadido en la versión 239.

Las fuentes pasivas se pueden especificar de las siguientes maneras:

--listen-raw=DIRECCIÓN

DIRECCIÓN debe ser una dirección adecuada para ListenStream= (ver systemd.socket(5)). systemd-journal-remote escuchará en este socket las conexiones. Se espera que cada conexión sea un flujo de eventos del journal.

Añadido en la versión 239.

--listen-http=DIRECCIÓN, --listen-https=DIRECCIÓN

DIRECCIÓN debe ser un entero negativo, en cuyo caso se interpretará como el número de descriptor de archivo (negado), o una dirección adecuada para ListenStream= (ver systemd.socket(5)). En el primer caso, el servidor escucha en el puerto 19532 por defecto, y el descriptor de archivo coincidente debe heredarse a través de $LISTEN_FDS/$LISTEN_PID. En el segundo caso, se iniciará un servidor HTTP o HTTPS en este puerto, respectivamente para --listen-http= y --listen-https=. Actualmente, solo se admiten solicitudes POST a /upload con "Content-Type: application/vnd.fdo.journal".

Añadido en la versión 239.

$LISTEN_FDS

systemd-journal-remote admite el protocolo $LISTEN_FDS/$LISTEN_PID. Los sockets abiertos heredados a través de la activación por socket se comportan como los abiertos con --listen-raw= descrito anteriormente, a menos que se especifiquen como argumento en --listen-http=-n o --listen-https=-n anteriormente. En este último caso, se iniciará un servidor HTTP o HTTPS utilizando este descriptor y las conexiones deben realizarse a través del protocolo HTTP.

Añadido en la versión 239.

--key=

Toma la ruta a un archivo de clave secreta SSL en formato PEM. Por defecto es /etc/ssl/private/journal-remote.pem. Esta opción se puede usar con --listen-https=. Si la ruta se refiere a un socket de flujo AF_UNIX en el sistema de archivos, se establece una conexión a él y la clave se lee de él.

Añadido en la versión 239.

--cert=

Toma la ruta a un archivo de certificado SSL en formato PEM. Por defecto es /etc/ssl/certs/journal-remote.pem. Esta opción se puede usar con --listen-https=. Si la ruta se refiere a un socket de flujo AF_UNIX en el sistema de archivos, se establece una conexión a él y el certificado se lee de él.

Añadido en la versión 239.

--trust=

Toma la ruta a un archivo de certificado CA SSL en formato PEM, o all. Si se establece all, la verificación del certificado se deshabilitará. Por defecto es /etc/ssl/ca/trusted.pem. Esta opción se puede usar con --listen-https=. Si la ruta se refiere a un socket de flujo AF_UNIX en el sistema de archivos, se establece una conexión a él y el certificado se lee de él.

Añadido en la versión 239.

--gnutls-log=

Toma una lista separada por comas de categorías de registro de gnutls. Esta opción se puede usar con --listen-http= o --listen-https=.

Añadido en la versión 239.

SUMIDEROS

La ubicación del journal de salida se puede especificar con -o o --output=.

-o ARCHIVO, --output=ARCHIVO

Escribirá en este archivo del journal. El nombre del archivo debe terminar en .journal. El archivo se creará si no existe. Si es necesario (archivo del journal lleno o corrupto), el archivo se renombrará siguiendo las reglas normales de journald y se creará un nuevo archivo del journal en su lugar.

Añadido en la versión 239.

-o DIR, --output=DIR

Creará archivos del journal dentro del directorio DIR. El directorio debe existir. Si es necesario (archivos del journal con tamaño excedido o corruptos), los archivos del journal se rotarán siguiendo las reglas normales de journald. Los nombres de los archivos dentro de DIR se generarán utilizando las reglas descritas a continuación.

Añadido en la versión 239.

Si no se utiliza --output=, se utilizará el directorio de salida /var/log/journal/remote/. En caso de que no se especifique el archivo de salida, se crearán archivos del journal dentro del directorio seleccionado. Los archivos se llamarán remote-nombrehost.journal, donde la parte nombrehost es el nombre de host escapado del punto final de origen de la conexión, o la dirección numérica si no se puede determinar el nombre de host.

En el caso de que las fuentes "activas" se proporcionen mediante los argumentos posicionales o la opción --getter=, el nombre del archivo de salida siempre debe especificarse explícitamente.

OPCIONES

Se entienden las siguientes opciones:

--split-mode

Uno de none u host. Para el primero, solo se utiliza un archivo de journal de salida. Para el segundo, se utiliza un archivo de salida separado, basado en el nombre de host del otro punto final de una conexión.

En el caso de que las fuentes "activas" se proporcionen mediante los argumentos posicionales o la opción --getter=, el nombre del archivo de salida debe especificarse siempre

systemd-journal-remote.service(8) — systemd journal-remote.service man pages

NAME

systemd-journal-remote.service, systemd-journal-remote — Receive remote journal data

SYNOPSIS

systemd-journal-remote [OPTION...] [--url URL]...

DESCRIPTION

systemd-journal-remote is a system service that listens for journal exports from other hosts and writes them to the local journal. It supports the journal export format (https://systemd.io/JOURNAL_EXPORT_FORMATS) and accepts data via HTTP/HTTPS POST requests.

The service may be configured via the systemd-journal-remote.service(8) unit snippet and the journal-remote.conf(5) configuration file. It is often used in conjunction with systemd-journal-gatewayd.service(8), which may be used to expose the local journal to remote hosts.

By default, the service listens on the SystemJournalExport D-Bus method and on TCP port 19532. It may also be configured to connect to one or more remote journal exports endpoints via the --url command line switch or the URL= setting in journal-remote.conf(5).

If the remote directory in journal-remote.conf(5) is set, journal data from remote hosts is stored in /var/log/journal/remote/. A subdirectory is created for each host, named after the host's identifier (e.g. remote-some.host.journal). If this directory is not set, all received data is appended to the main system journal.

The systemd-journal-remote.service unit accepts the following options:

SOURCES

By default, systemd-journal-remote accepts journal data from any source, as long as it is properly authenticated. This behaviour may be changed with the --listen-audit, --listen-kmsg, --listen-null, --listen-stdin, --listen-syslog, and --listen-stdout options.

SINKS

By default, systemd-journal-remote writes received data to the local journal. This behaviour may be changed with the --output= option.

OPTIONS

systemd-journal-remote supports the following options in addition to the global systemd(1) options:

The following options control which data sources are enabled:

--listen-audit

Listen for audit events on the NETLINK_AUDIT socket.

--listen-kmsg

Listen for kernel messages on /dev/kmsg.

--listen-null

Listen for journal exports on the NULL socket.

--listen-stdin

Listen for journal exports on standard input.

--listen-syslog [=port]

Listen for syslog data on TCP and UDP port port. If port is not specified, the default is 514. The IP_PKT_INFO socket option is enabled on the UDP socket for receiving packet information.

--listen-stdout

Listen for journal exports on standard output.

The following options control where the received data is written:

-o, --output=FILE

Write received journal data to the specified FILE instead of the main journal. The file must be in the journal export format. Standard output is implied if FILE is -. This option may be specified multiple times. If no --output= option is given, and the RemoteStorage= setting in journal-remote.conf(5) is not set to none, the data is written to /var/log/journal/remote/remote-HOST.journal, where HOST is the identifier of the remote host.

The following options control the behaviour of the service:

--url=URL

Connect to the specified URL and receive journal data from there. This option may be specified multiple times. If this option is used, systemd-journal-remote acts as a client, not a server. This is useful for fetching journal data from systemd-journal-gatewayd.service(8) instances.

--compress [BOOL]

If this is set to "yes" then compress the data in the journal using XZ. The default is "yes".

Added in version 239.

--seal [BOOL]

If this is set to "yes" then periodically sign the data in the journal using Forward Secure Sealing. The default is "no".

Added in version 239.

-h, --help

Print a short help text and exit.

--version

Print a short version string and exit.

EXAMPLES

Copy local journal events to a different journal directory:

journalctl -o export | systemd-journal-remote -o /tmp/dir/foo.journal -

Retrieve all available events from a remote systemd-journal-gatewayd(8) instance and store them in /var/log/journal/remote/remote-some.host.journal:

systemd-journal-remote --url http://some.host:19531/

Retrieve current boot events and wait for new events from a remote systemd-journal-gatewayd(8) instance, and store them in /var/log/journal/remote/remote-some.host.journal:

systemd-journal-remote --url http://some.host:19531/entries?boot&follow
