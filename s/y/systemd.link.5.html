NOMBRE

systemd.link - Configuración de red de dispositivos

SINOPSIS

link.link

DESCRIPCIÓN

Un archivo de texto plano estilo ini que codifica la configuración para la coincidencia de dispositivos de red, utilizado por systemd-udevd(8) y en particular su función incorporada net_setup_link. Consulte systemd.syntax(7) para una descripción general de la sintaxis.

Tenga en cuenta que algunas distribuciones pueden incorporar archivos .link en sus instalaciones de arranque temprano (por ejemplo, incluyendo copias de los archivos .link en el initramfs). Como tal, puede ser necesario tomar medidas manuales para garantizar que los cambios locales sean consistentes con las instalaciones de almacenamiento de arranque temprano. Se debe consultar la documentación específica de la distribución relevante.

Los archivos .link se leen de los archivos ubicados en el directorio de red del sistema /usr/lib/systemd/network y /usr/local/lib/systemd/network [1], el directorio de red de tiempo de ejecución volátil /run/systemd/network y el directorio de red de administración local /etc/systemd/network. Todos los archivos de configuración se ordenan y procesan colectivamente en orden alfanumérico, independientemente de los directorios en los que se encuentren. Sin embargo, los archivos con nombres idénticos se reemplazan entre sí. Se recomienda que cada nombre de archivo comience con un número menor que "70" (por ejemplo, 10-eth0.link). De lo contrario, los archivos .link predeterminados o los generados por systemd-network-generator.service(8) pueden tener precedencia sobre los archivos configurados por el usuario. Los archivos en /etc/ tienen la mayor prioridad, los archivos en /run/ tienen precedencia sobre los archivos con el mismo nombre en /usr/lib/. Esto se puede usar para anular un archivo de enlace proporcionado por el sistema con un archivo local si es necesario. Como caso especial, un archivo vacío (tamaño de archivo 0) o un enlace simbólico con el mismo nombre que apunta a /dev/null deshabilita el archivo de configuración por completo (está "enmascarado").

Además del archivo link foo.link, puede existir un directorio "drop-in" foo.link.d/. Todos los archivos con el sufijo ".conf" de este directorio se fusionarán en orden alfanumérico y se analizarán después de que se haya analizado el archivo principal en sí. Esto es útil para alterar o agregar configuraciones, sin tener que modificar el archivo de configuración principal. Cada archivo drop-in debe tener encabezados de sección apropiados.

Además de /etc/systemd/network, se pueden colocar directorios "drop-in" ".d" en los directorios /usr/lib/systemd/network o /run/systemd/network. Los archivos drop-in en /etc/ tienen precedencia sobre los de /run/, que a su vez tienen precedencia sobre los de /usr/lib/. Los archivos drop-in en cualquiera de estos directorios tienen precedencia sobre el archivo link principal, dondequiera que se encuentre.

El archivo link contiene una sección [Match], que determina si un archivo link dado puede aplicarse a un dispositivo dado, así como una sección [Link] que especifica cómo se debe configurar el dispositivo. Se aplica el primer archivo link (en orden léxico) que coincide con un dispositivo dado. Tenga en cuenta que el sistema proporciona un archivo predeterminado 99-default.link. Cualquier .link proporcionado por el usuario debe tener un nombre léxico anterior para ser considerado en absoluto.

Consulte udevadm(8) para diagnosticar problemas con los archivos .link.

OPCIONES DE SECCIÓN [MATCH]

Se dice que un archivo link coincide con una interfaz si todas las coincidencias especificadas por la sección [Match] se satisfacen. Cuando un archivo link no contiene configuraciones válidas en la sección [Match], el archivo coincidirá con todas las interfaces y systemd-udevd advertirá sobre ello. Pista: para evitar la advertencia y dejar claro que todas las interfaces deben coincidir, agregue lo siguiente:

OriginalName=*

Se aplica el primer archivo link (en orden alfanumérico) que coincide con una interfaz dada, todos los archivos posteriores se ignoran, incluso si también coinciden. Se aceptan las siguientes claves:

MACAddress=

Una lista separada por espacios en blanco de direcciones de hardware. Los formatos aceptables son:

Hexadecimal delimitado por dos puntos

Cada campo debe ser un byte. Por ejemplo, "12:34:56:78:90:ab" o "AA:BB:CC:DD:EE:FF".

Añadido en la versión 250.

Hexadecimal delimitado por guiones

Cada campo debe ser un byte. Por ejemplo, "12-34-56-78-90-ab" o "AA-BB-CC-DD-EE-FF".

Añadido en la versión 250.

Hexadecimal delimitado por puntos

Cada campo debe ser dos bytes. Por ejemplo, "1234.5678.90ab" o "AABB.CCDD.EEFF".

Añadido en la versión 250.

Formato de dirección IPv4

Por ejemplo, "127.0.0.1" o "192.168.0.1".

Añadido en la versión 250.

Formato de dirección IPv6

Por ejemplo, "2001:0db8:85a3::8a2e:0370:7334" o "::1".

Añadido en la versión 250.

La longitud total de cada dirección MAC debe ser 4 (para túnel IPv4), 6 (para Ethernet), 16 (para túnel IPv6) o 20 (para InfiniBand). Esta opción puede aparecer más de una vez, en cuyo caso las listas se fusionan. Si se asigna la cadena vacía a esta opción, se restablece la lista de direcciones de hardware definidas previamente. Por defecto está sin definir.

Añadido en la versión 211.

PermanentMACAddress=

Una lista separada por espacios en blanco de las direcciones permanentes del hardware. Mientras que MACAddress= coincide con la dirección MAC actual del dispositivo, esta coincide con la dirección MAC permanente del dispositivo, que puede ser diferente de la actual. Utilice formato hexadecimal completo delimitado por dos puntos, guiones o puntos, o formato de dirección IPv4 o IPv6. Esta opción puede aparecer más de una vez, en cuyo caso las listas se fusionan. Si se asigna la cadena vacía a esta opción, se restablece la lista de direcciones de hardware definidas previamente. Por defecto está sin definir.

Añadido en la versión 245.

Path=

Una lista separada por espacios en blanco de patrones de estilo shell que coinciden con la ruta persistente, expuesta por la propiedad udev ID_PATH.

Añadido en la versión 211.

Driver=

Una lista separada por espacios en blanco de patrones de estilo shell que coinciden con el controlador actualmente enlazado al dispositivo, expuesto por la propiedad udev ID_NET_DRIVER de su dispositivo padre, o si no está establecido, el controlador expuesto por ethtool -i del propio dispositivo. Si la lista está prefijada con un "!", la prueba se invierte.

Añadido en la versión 211.

Type=

Una lista separada por espacios en blanco de patrones de estilo shell que coinciden con el tipo de dispositivo, expuesto por networkctl list. Si la lista está prefijada con un "!", la prueba se invierte. Algunos valores válidos son "ether", "loopback", "wlan", "wwan". Los tipos válidos se nombran a partir del atributo "DEVTYPE" de udev, o de las macros "ARPHRD_" en linux/if_arp.h, por lo que esto no es exhaustivo.

Añadido en la versión 211.

Kind=

Una lista separada por espacios en blanco de patrones de estilo shell que coinciden con el tipo de dispositivo, expuesto por networkctl status INTERFACE o ip -d link show INTERFACE. Si la lista está prefijada con un "!", la prueba se invierte. Algunos valores válidos son "bond", "bridge", "gre", "tun", "veth". Los tipos válidos se dan por el atributo "IFLA_INFO_KIND" de netlink, por lo que esto no es exhaustivo.

Añadido en la versión 251.

Property=

Una lista separada por espacios en blanco de nombres de propiedades udev con sus valores después del signo igual ("="). Si se especifican varias propiedades, los resultados de la prueba se combinan con AND. Si la lista está prefijada con un "!", la prueba se invierte. Si un valor contiene espacios en blanco, entonces debe entrecomillar todo el par clave-valor. Si un valor contiene comillas, entonces debe escapar la comilla con "\".

Ejemplo: si un archivo .link tiene lo siguiente:

Property=ID_MODEL_ID=9999 "ID_VENDOR_FROM_DATABASE=vendor name" "KEY=with \"quotation\""

entonces, el archivo .link solo coincide cuando una interfaz tiene todas las tres propiedades anteriores.

Añadido en la versión 243.

Una lista separada por espacios en blanco de patrones de estilo shell que coinciden con el nombre del dispositivo, expuesto por la propiedad udev "INTERFACE". Esto no se puede utilizar para hacer coincidir nombres que ya han sido cambiados desde el espacio de usuario. Precaución
en se advierte al igualar nombres asignados por el kernel, ya que se sabe que son inestables entre reinicios.

[LINK] OPCIONES DE SECCIÓN

La sección [Link] acepta las siguientes claves:

Description=

Una descripción del dispositivo.

Añadido en la versión 211.

Property=

Establece propiedades de udev especificadas. Esto toma una lista separada por espacios de pares clave-valor concatenados con un signo de igual ("="). Ejemplo: 
Property=HOGE=foo BAR=baz

Esta opción admite la expansión de especificadores simples, consulte la sección de Especificadores a continuación. Esta opción se puede especificar varias veces. Si se asigna una cadena vacía, se borran todas las asignaciones anteriores.

Esta configuración es útil para configurar la propiedad "ID_NET_MANAGED_BY=" que declara qué servicio de gestión de red debe gestionar la interfaz, lo cual es respetado por systemd-networkd(8) y otros. Use

Property=ID_NET_MANAGED_BY=io.systemd.Network

para declarar explícitamente que systemd-networkd debe gestionar la interfaz, o establezca la propiedad en algo más para declarar explícitamente que no debe hacerlo. Consulte systemd.network(5) para obtener detalles sobre cómo se utiliza esta propiedad para hacer coincidir nombres de interfaz.

Añadido en la versión 256.

ImportProperty=

Importa propiedades de udev especificadas de la base de datos guardada. Esto toma una lista separada por espacios de nombres de propiedades. Ejemplo: 
ImportProperty=HOGE BAR

Esta opción admite la expansión de especificadores simples, consulte la sección de Especificadores a continuación. Esta opción se puede especificar varias veces. Si se asigna una cadena vacía, se borran todas las asignaciones anteriores.

Si la misma propiedad también se establece en Property= en el anterior, el valor de la propiedad importada se sobrescribirá con el valor especificado en Property=.

Añadido en la versión 256.

UnsetProperty=

Anula el establecimiento de propiedades de udev especificadas. Esto toma una lista separada por espacios de nombres de propiedades. Ejemplo: 
UnsetProperty=HOGE BAR

Esta opción admite la expansión de especificadores simples, consulte la sección de Especificadores a continuación. Esta opción se puede especificar varias veces. Si se asigna una cadena vacía, se borran todas las asignaciones anteriores.

Esta configuración se aplica después de que se aplican ImportProperty= y Property=. Por lo tanto, si la misma propiedad se especifica en ImportProperty= o Property=, el valor de la propiedad importada o especificada se ignorará y la propiedad se anulará.

Añadido en la versión 256.

Alias=

La propiedad de interfaz ifalias se establece en este valor.

Añadido en la versión 211.

MACAddressPolicy=

La política según la cual se debe establecer la dirección MAC. Las políticas disponibles son:

persistent

Si el hardware tiene una dirección MAC persistente, como debería tener la mayoría del hardware, y si está siendo utilizada por el kernel, no se hace nada. De lo contrario, se genera una nueva dirección MAC que se garantiza que será la misma en cada reinicio para la máquina dada y el dispositivo dado, pero que por lo demás es aleatoria. Esta función depende de que existan las propiedades ID_NET_NAME_* para el enlace. En hardware donde estas propiedades no están establecidas, la generación de una dirección MAC persistente fallará.

Añadido en la versión 211.

random

Si el kernel está utilizando una dirección MAC aleatoria, no se hace nada. De lo contrario, se genera una nueva dirección aleatoriamente cada vez que aparece el dispositivo, típicamente al arrancar. En cualquier caso, la dirección aleatoria tendrá los bits "unicast" y "administrada localmente" establecidos.

Añadido en la versión 211.

none

Mantiene la dirección MAC asignada por el kernel. O utiliza la dirección MAC especificada en MACAddress=.

Añadido en la versión 227.

Una asignación de cadena vacía es equivalente a establecer "none".

Añadido en la versión 211.

MACAddress=

La dirección MAC de la interfaz a utilizar. Para que esta configuración tenga efecto, MACAddressPolicy= debe no estar configurada, estar vacía o ser "none".

Añadido en la versión 211.

NamePolicy=

Una lista ordenada y separada por espacios de políticas según las cuales se debe establecer el nombre de la interfaz. NamePolicy= puede ser deshabilitada especificando net.ifnames=0 en la línea de comandos del kernel. Cada una de las políticas puede fallar, y se utilizará la primera que tenga éxito. El nombre no se establece directamente, sino que se exporta a udev como la propiedad ID_NET_NAME, que, por defecto, es utilizada por una regla de udev(7) para establecer NAME. Las políticas disponibles son:

kernel

Si el kernel afirma que el nombre que ha establecido para un dispositivo es predecible, no se realiza ningún cambio de nombre.

Añadido en la versión 216.

database

El nombre se establece basándose en entradas en la Base de Datos de Hardware de udev con la clave ID_NET_NAME_FROM_DATABASE.

Añadido en la versión 211.

onboard

El nombre se establece basándose en la información proporcionada por el firmware para dispositivos integrados, según lo exporta la propiedad de udev ID_NET_NAME_ONBOARD. Consulte systemd.net-naming-scheme(7).

Añadido en la versión 211.

slot

El nombre se establece basándose en la información proporcionada por el firmware para dispositivos conectables en caliente, según lo exporta la propiedad de udev ID_NET_NAME_SLOT. Consulte systemd.net-naming-scheme(7).

Añadido en la versión 211.

path

El nombre se establece basándose en la ubicación física del dispositivo, según lo exporta la propiedad de udev ID_NET_NAME_PATH. Consulte systemd.net-naming-scheme(7).

Añadido en la versión 211.

mac

El nombre se establece basándose en la dirección MAC persistente del dispositivo, según lo exporta la propiedad de udev ID_NET_NAME_MAC. Consulte systemd.net-naming-scheme(7).

Añadido en la versión 211.

keep

Si el dispositivo ya tenía un nombre asignado por el espacio de usuario (como parte de la creación del dispositivo o de un cambio de nombre), manténgalo.

Añadido en la versión 241.

Añadido en la versión 211.

Name=

El nombre de la interfaz a utilizar. Esta opción tiene menor precedencia que NamePolicy=, por lo que para que esta configuración tenga efecto, NamePolicy= debe no estar configurada, estar vacía, deshabilitada, o todas las políticas configuradas allí deben fallar. Consulte también el ejemplo a continuación con "Name=dmz0".

Tenga en cuenta que especificar un nombre que el kernel podría utilizar para otra interfaz (por ejemplo, "eth0") es peligroso porque la asignación de nombre realizada por udev competirá con la asignación realizada por el kernel, y solo una interfaz puede usar el nombre. Dependiendo del orden de las operaciones, udev o el kernel ganarán, haciendo que la asignación de nombres sea impredecible. Es mejor utilizar un prefijo diferente, por ejemplo, "internal0"/"external0" o "lan0"/"lan1"/"lan3".

Los nombres de interfaz deben tener una longitud mínima de 1 carácter y una longitud máxima de 15 caracteres, y pueden contener cualquier carácter ASCII de 7 bits, con la excepción de caracteres de control, ":", "/" y "%". Si bien "." es un carácter permitido, se recomienda evitarlo al nombrar interfaces, ya que varias herramientas (como resolvconf(1)) lo utilizan como carácter separador. Además, los nombres de interfaz completamente numéricos no están permitidos (para evitar ambigüedades con la especificación de interfaz por índices numéricos), ni tampoco las cadenas especiales ".", "..", "all" y "default".

Añadido en la versión 211.

AlternativeNamesPolicy=

Una lista separada por espacios de políticas según las cuales se deben establecer los nombres alternativos de la interfaz. Cada una de las políticas puede fallar, y se utilizan todas las políticas exitosas. Las políticas disponibles son "database", "onboard", "slot", "path" y "mac". Si el kernel no admite los nombres alternativos, esta configuración se ignorará.

Añadido en la versión 245.

AlternativeName=

El nombre alternativo de interfaz a utilizar. Esta opción se puede especificar varias veces. Si se asigna la cadena vacía a esta opción, la lista se restablece y todas las asignaciones previas no tienen efecto. Si el kernel no admite los nombres alternativos, esta configuración se ignorará.

Los nombres alternativos de interfaz se pueden utilizar para identificar interfaces en diversas herramientas. A diferencia del nombre primario (como se configura con Name= arriba), puede haber múltiples nombres alternativos que se refieren a la misma interfaz. Los nombres alternativos pueden tener una longitud máxima de 127 caracteres, en contraste con los 15 permitidos para el nombre de interfaz primario, pero por lo demás están sujetos a las mismas restricciones de nomenclatura.

Añadido en la versión 245.

Especifica el número de colas de transmisión del dispositivo. Un entero en el rango 1...4096. Cuando no se establece, se utilizará el valor predeterminado del kernel.

Añadido en la versión 248.

ReceiveQueues=

Especifica el número de colas de recepción del dispositivo. Un entero en el rango 1...4096. Cuando no se establece, se utilizará el valor predeterminado del kernel.

Añadido en la versión 248.

TransmitQueueLength=

Especifica la longitud de la cola de transmisión del dispositivo en número de paquetes. Un entero sin signo en el rango 0...4294967294. Cuando no se establece, se utilizará el valor predeterminado del kernel.

Añadido en la versión 248.

MTUBytes=

La unidad de transmisión máxima en bytes a establecer para el dispositivo. Los sufijos habituales K, M, G son compatibles y se entienden en base 1024.

Añadido en la versión 211.

BitsPerSecond=

La velocidad a establecer para el dispositivo, el valor se redondea a la baja al Mbps más cercano. Los sufijos habituales K, M, G son compatibles y se entienden en base 1000.

Añadido en la versión 211.

Duplex=

El modo dúplex a establecer para el dispositivo. Los valores aceptados son half (medio) y full (completo).

Añadido en la versión 211.

AutoNegotiation=

Acepta un valor booleano. Si se establece en sí, la negociación automática de parámetros de transmisión está habilitada. La autonegociación es un procedimiento mediante el cual dos dispositivos Ethernet conectados eligen parámetros de transmisión comunes, como la velocidad, el modo dúplex y el control de flujo. Cuando no se establece, se utilizará el valor predeterminado del kernel.

Tenga en cuenta que si la autonegociación está habilitada, la velocidad y la configuración dúplex son de solo lectura. Si la autonegociación está deshabilitada, la velocidad y la configuración dúplex son escribibles si el controlador admite varios modos de enlace.

secureon

Habilita la contraseña SecureOn para MagicPacket. Implicado cuando se especifica WakeOnLanPassword=. Si se especifica sin la opción WakeOnLanPassword=, entonces la contraseña se lee de la credencial "LINK.link.wol.password" (por ejemplo, "60-foo.link.wol.password"), y si la credencial no se encuentra, se lee de "wol.password". Consulte ImportCredential=/LoadCredential=/SetCredential= en systemd.exec(5) para obtener más detalles. La contraseña en la credencial debe tener 6 bytes en formato hexadecimal con cada byte separado por dos puntos (":") como una dirección MAC Ethernet, por ejemplo, "aa:bb:cc:dd:ee:ff".

Añadido en la versión 235.

Por defecto no se establece, y se utilizará el valor predeterminado del dispositivo. Esta configuración se puede especificar varias veces. Si se asigna una cadena vacía, se borran todas las asignaciones anteriores.

Añadido en la versión 211.

WakeOnLanPassword=

Especifica la contraseña SecureOn para MagicPacket. Acepta una ruta absoluta a un archivo regular o un socket de transmisión AF_UNIX, o la contraseña simple. Cuando se especifica una ruta a un archivo regular, la contraseña se lee de él. Cuando se especifica un socket de transmisión AF_UNIX, se establece una conexión a él y se lee la contraseña. La contraseña debe tener 6 bytes en formato hexadecimal con cada byte separado por dos puntos (":") como una dirección MAC Ethernet, por ejemplo, "aa:bb:cc:dd:ee:ff". Esto implica WakeOnLan=secureon. Por defecto no se establece, y el valor actual no se modificará.

[SR-IOV] OPCIONES DE SECCIÓN

SR-IOV proporciona la capacidad de particionar un único recurso PCI físico en funciones PCI virtuales que luego pueden ser, por ejemplo, inyectadas en una VM. En el caso de las VF de red, SR-IOV reduce la latencia y la utilización de la CPU para el tráfico de red norte-sur (es decir, el tráfico con puntos finales fuera de la máquina host), al permitir que el tráfico omita la pila de red de la máquina host.

La presencia de una sección [SR-IOV] en un archivo .link provocará la creación y configuración de la función virtual especificada. Dentro de un archivo .network, se configurará la función virtual especificada, pero esta debe existir previamente. Especifique varias secciones [SR-IOV] para configurar varias SR-IOV.

La sección [SR-IOV] acepta las siguientes claves.

EJEMPLOS

Ejemplo 1. /usr/lib/systemd/network/99-default.link

El archivo de enlace 99-default.link que se distribuye con systemd define las políticas predeterminadas para el nombre de la interfaz, los nombres alternativos y la dirección MAC de los enlaces.

[Match]
OriginalName=*
[Link]
NamePolicy=keep kernel database onboard slot path
AlternativeNamesPolicy=database onboard slot path
MACAddressPolicy=persistent

Ejemplo 2. /etc/systemd/network/10-dmz.link

Este ejemplo asigna el nombre fijo "dmz0" a la interfaz con la dirección MAC 00:a0:de:63:7a:e6:

[Match]
MACAddress=00:a0:de:63:7a:e6
[Link]
Name=dmz0

NamePolicy= no está configurado, por lo que Name= entra en vigor. Usamos el prefijo "10-" para ordenar este archivo al principio de la lista. Tenga en cuenta que necesita estar antes de 99-default.link, es decir, necesita un prefijo numérico, para tener algún efecto.

Ejemplo 3. (Re)aplicar un archivo .link a una interfaz

Después de crear un nuevo archivo .link o modificar uno existente, la nueva configuración se puede aplicar a la interfaz correspondiente con los siguientes comandos:

$ sudo udevadm control --reload
$ sudo ip link set eth0 down
$ sudo udevadm trigger --verbose --settle --action add /sys/class/net/eth0

También puede que necesite detener el servicio que gestiona la interfaz de red, por ejemplo, systemd-networkd.service(8) o NetworkManager.service antes de la operación anterior, y luego reiniciar el servicio después de eso. Para más detalles sobre el comando udevadm, consulte udevadm(8).

$ sudo SYSTEMD_LOG_LEVEL=debug udevadm test-builtin net_setup_link /sys/class/net/hub0
...
Parsed configuration file /usr/lib/systemd/network/99-default.link

ID_NET_DRIVER=cdc_ether

La configuración explícita Name= gana en este caso.

sudo SYSTEMD_LOG_LEVEL=debug udevadm test-builtin net_setup_link /sys/class/net/enp0s31f6
...
Parsed configuration file /usr/lib/systemd/network/99-default.link
Parsed configuration file /etc/systemd/network/10-eth0.link
Created link configuration context.
ID_NET_DRIVER=e1000e
Config file /usr/lib/systemd/network/99-default.link applies to device enp0s31f6
link_config: autonegotiation is unset or enabled, the speed and duplex are not writable.
enp0s31f6: Device has name_assign_type=4
Using default interface naming scheme 'v240'.
enp0s31f6: Policy *keep*: keeping existing userspace name
enp0s31f6: Device has addr_assign_type=0
enp0s31f6: MAC on the device already matches policy *persistent*
ID_NET_LINK_FILE=/usr/lib/systemd/network/99-default.link
...

En este caso, la interfaz ya había sido renombrada, por lo que la política keep especificada como la primera opción en 99-default.link significa que se conserva el nombre existente. Si keep se eliminara, o si estuviéramos en el arranque antes de que ocurriera el cambio de nombre, podríamos obtener lo siguiente en su lugar:

enp0s31f6: Policy *path* yields "enp0s31f6".
enp0s31f6: Device has addr_assign_type=0
enp0s31f6: MAC on the device already matches policy *persistent*
ID_NET_LINK_FILE=/usr/lib/systemd/network/99-default.link
ID_NET_NAME=enp0s31f6
...

Tenga en cuenta que los detalles de la salida están sujetos a cambios.

Ejemplo 5. /etc/systemd/network/10-internet.link

Este ejemplo asigna el nombre fijo "internet0" a la interfaz con la ruta del dispositivo "pci-0000:00:1a.0-*":

[Match]
Path=pci-0000:00:1a.0-*
[Link]
Name=internet0

Ejemplo 6. /etc/systemd/network/25-wireless.link

Aquí hay un ejemplo excesivamente complejo que muestra el uso de un gran número de configuraciones [Match] y [Link].

[Match]
MACAddress=12:34:56:78:9a:bc
Driver=brcmsmac
Path=pci-0000:02:00.0-*
Type=wlan
Virtualization=no
Host=my-laptop
Architecture=x86-64
[Link]
Name=wireless0
MTUBytes=1450
BitsPerSecond=10M
WakeOnLan=magic
MACAddress=cb:a9:87:65:43:21
