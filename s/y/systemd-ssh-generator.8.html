SYSTEMD-SSH-GENERATOR(8) systemd-ssh-generator SYSTEMD-SSH-GENERATOR(8)

NOMBRE

systemd-ssh-generator - Generador para enlazar un servidor SSH activado por socket a sockets locales AF_VSOCK y AF_UNIX

SINOPSIS

/usr/lib/systemd/system-generators/systemd-ssh-generator

DESCRIPCIÓN

systemd-ssh-generator enlaza un servidor SSH activado por socket a sockets locales AF_VSOCK y AF_UNIX bajo ciertas condiciones. Solo tiene efecto si el binario sshd(8) está instalado. Específicamente, hace lo siguiente:

•Si se invoca en una VM con soporte AF_VSOCK, un servicio SSH por conexión activado por socket se enlaza al puerto AF_VSOCK 22.
•Si se invoca en un entorno de contenedor con un directorio escribible /run/host/unix-export/ pre-montado, enlaza SSH a un socket AF_UNIX /run/host/unix-export/ssh. La suposición es que este directorio también se monta en el lado del host mediante bind mount y puede ser utilizado para conectar al contenedor desde allí. Ver Interfaz de Contenedor[1] para más información sobre esta interfaz.
•Un socket local AF_UNIX /run/ssh-unix-local/socket también se enlaza, incondicionalmente. Esto puede ser utilizado para la comunicación SSH del host consigo mismo, sin involucrar redes, por ejemplo, para atravesar límites de seguridad de forma segura y con autenticación segura.
•Opcionalmente, se enlazarán sockets AF_UNIX y AF_VSOCK adicionales, basados en la opción de línea de comandos del kernel systemd.ssh_listen= o el credential del sistema ssh.listen (ver más abajo).

Ver systemd-ssh-proxy(1) para detalles sobre cómo conectar a estos sockets a través del cliente ssh.

El credential ssh.authorized_keys.root puede ser utilizado para permitir que claves públicas específicas inicien sesión a través de SSH. Ver systemd.system-credentials(7) para más información.

El generador usará un archivo de plantilla de servicio empaquetado sshd@.service si existe, y de lo contrario generará un archivo de plantilla de servicio adecuado.

systemd-ssh-generator implementa systemd.generator(7).

LÍNEA DE COMANDOS DEL KERNEL

systemd-ssh-generator entiende los siguientes parámetros de kernel-command-line(7):

systemd.ssh_auto=

Esta opción toma un argumento booleano opcional y por defecto es sí. Si se habilita, se realiza el enlace automático a los sockets AF_VSOCK y AF_UNIX mencionados anteriormente. Si se deshabilita, esto no se hace, excepto para aquellos solicitados explícitamente a través de systemd.ssh_listen= en la línea de comandos del kernel o a través del credential del sistema ssh.listen.

Añadido en la versión 256.

systemd.ssh_listen=

Esta opción configura un socket adicional para enlazar SSH. Puede ser utilizada múltiples veces para enlazar múltiples sockets. La sintaxis debe seguir la de ListenStream=, ver systemd.socket(5) para detalles. Esta funcionalidad soporta todas las familias de sockets que systemd(1) soporta, incluyendo AF_INET y AF_INET6.

Añadido en la versión 256.

CREDENCIALES

systemd-ssh-generator soporta la lógica de credenciales del sistema. Los siguientes credenciales se utilizan cuando se pasan:

ssh.listen

Este credential debe ser un archivo de texto, con cada línea haciendo referencia a un socket adicional para enlazar SSH. La sintaxis debe seguir la de ListenStream=, ver systemd.socket(5) para detalles. Esta funcionalidad soporta todas las familias de sockets que systemd soporta, incluyendo AF_INET y AF_INET6.

Añadido en la versión 256.

ssh.ephemeral-authorized_keys-all

Proporciona claves públicas adicionales, dadas en el formato habitual de authorized_keys, para todos los usuarios, para las conexiones entrantes a través de las unidades de socket AF_VSOCK y AF_UNIX generadas.

El uso previsto de esto es para que un sistema host (en configuraciones de VM o contenedor) genere un par de claves e inyecte la clave pública en el invitado, utilizando la clave privada para conectarse a cualquier cuenta de usuario en el invitado a través de ssh, sin autenticación adicional.

Añadido en la versión 256.
