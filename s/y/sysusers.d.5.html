SYSUSERS.D(5) sysusers.d SYSUSERS.D(5)

NOMBRE

sysusers.d - Asignación declarativa de usuarios y grupos del sistema

SINOPSIS

/etc/sysusers.d/*.conf
/run/sysusers.d/*.conf
/usr/local/lib/sysusers.d/*.conf
/usr/lib/sysusers.d/*.conf
#Tipo Nombre       ID                  GECOS              Directorio de inicio Shell
u     nombre_usuario  uid                 "Descripción del Usuario" /home/dir      /ruta/a/shell
u     nombre_usuario  uid:gid             "Descripción del Usuario" /home/dir      /ruta/a/shell
u     nombre_usuario  /archivo/propiedad/del/usuario "Descripción del Usuario" /home/dir      /ruta/a/shell
g     nombre_grupo  gid
g     nombre_grupo  /archivo/propiedad/del/grupo
m     nombre_usuario  nombre_grupo
r     -          mas_bajo-mas_alto

DESCRIPCIÓN

systemd-sysusers utiliza los archivos del directorio sysusers.d para crear usuarios y grupos del sistema y para añadir usuarios a grupos, en el momento de la instalación del paquete o al arrancar. Esta herramienta puede ser utilizada solo para asignar usuarios y grupos del sistema; no es útil para crear usuarios y grupos no sistémicos (es decir, regulares, "humanos"), ya que accede directamente a /etc/passwd y /etc/group, omitiendo cualquier base de datos de usuarios más compleja, por ejemplo, cualquier base de datos que involucre NIS o LDAP.

DIRECTORIOS DE CONFIGURACIÓN Y PRECEDENCIA

Cada archivo de configuración debe nombrarse con el estilo de paquete.conf o paquete-parte.conf. La segunda variante debe usarse cuando se desea facilitar la anulación de solo esa parte de la configuración.

Los archivos en /etc/sysusers.d anulan a los archivos con el mismo nombre en /usr/lib/sysusers.d y /run/sysusers.d. Los archivos en /run/sysusers.d anulan a los archivos con el mismo nombre en /usr/lib/sysusers.d. Los paquetes deben instalar sus archivos de configuración en /usr/lib/sysusers.d. Los archivos en /etc/sysusers.d están reservados para el administrador local, quien puede usar esta lógica para anular los archivos de configuración instalados por los paquetes del proveedor. Todos los archivos de configuración se ordenan por su nombre de archivo en orden lexicográfico, independientemente de en qué directorio residan. Si varios archivos especifican la misma ruta, se aplicará la entrada en el archivo con el nombre lexicográficamente anterior. Todas las entradas posteriores para los mismos nombres de usuario y grupo se registrarán como advertencias.

Si el administrador desea deshabilitar un archivo de configuración proporcionado por el proveedor, la forma recomendada es colocar un enlace simbólico a /dev/null en /etc/sysusers.d/ con el mismo nombre de archivo.

FORMATO DEL ARCHIVO DE CONFIGURACIÓN

El formato del archivo es una línea por usuario o grupo que contiene el nombre, ID, descripción del campo GECOS, directorio de inicio y shell de inicio de sesión:

#Tipo Nombre     ID             GECOS                 Directorio de inicio Shell
u!    httpd    404            "Usuario HTTP"
u!    _authd   /usr/bin/authd "Usuario de Autorización"
u!    postgres -              "Base de datos de PostgreSql" /var/lib/pgsql /usr/libexec/postgresdb
g     input    -              -
m     _authd   input
u     root     0              "Superusuario"           /root          /bin/zsh
r     -        500-900

Las líneas vacías y las líneas que comienzan con el carácter "#" se ignoran y pueden usarse para comentarios.

Tipo

El tipo consta de una sola letra. Se entienden los siguientes tipos de línea:

u

Crea un usuario y un grupo del sistema con el nombre especificado si aún no existen. El grupo principal del usuario se establecerá al grupo que lleva el mismo nombre, a menos que el campo ID lo especifique. La cuenta se creará deshabilitada, por lo que los inicios de sesión no están permitidos.

El tipo u puede ir seguido de un signo de exclamación ("u!") para crear una cuenta completamente bloqueada. Esto se recomienda, ya que los inicios de sesión normalmente no deben permitirse para los usuarios del sistema. Con o sin el signo de exclamación, se establece una contraseña inválida. Para "u!", la cuenta también está bloqueada, lo que marca una diferencia para las formas de autenticación que no son de contraseña, como SSH o similar.

Añadido en la versión 215.

g

Crea un grupo del sistema con el nombre especificado si aún no existe. Tenga en cuenta que u implícitamente crea un grupo correspondiente. El grupo se creará sin contraseña establecida.

Añadido en la versión 215.

m

Añade un usuario a un grupo. Si el usuario o el grupo aún no existen, se crearán implícitamente.

Añadido en la versión 215.

r

Añade un rango de UID/GID numéricos al pool para asignar nuevos UID y GID. Si no se especifica ninguna línea de este tipo, el rango de UID/GID se establece a un valor predeterminado compilado. Tenga en cuenta que tanto los UID como los GID se asignan del mismo pool, para asegurar que los usuarios y grupos del mismo nombre lleven probablemente el mismo UID y GID numéricos.

Añadido en la versión 216.

Nombre

El campo nombre especifica el nombre del usuario o grupo. El nombre especificado debe consistir solo en los caracteres a-z, A-Z, 0-9, "_" y "-", excepto el primer carácter que debe ser uno de a-z, A-Z o "_" (es decir, los números y "-" no están permitidos como primer carácter). El nombre de usuario/grupo debe tener al menos un carácter y como máximo 31.

Para más detalles sobre la sintaxis de los nombres de usuario/grupo, consulte Sintaxis de Nombres de Usuario/Grupo[1].

Se recomienda encarecidamente elegir nombres de usuario y grupo que sea poco probable que entren en conflicto con los usuarios normales creados por el administrador. Un buen esquema para garantizar esto es prefijar todos los nombres de sistema y grupo con un guion bajo, y evitar nombres demasiado genéricos.

Para las líneas m, este campo debe contener el nombre de usuario a añadir a un grupo.

Para las líneas de tipo r, este campo debe establecerse en "-".

ID

Para u y g, el UID o GID numérico de 32 bits del usuario/grupo. No utilice los ID 65535 ni 4294967295, ya que tienen significados especiales de marcador de posición. Especifique "-" para la asignación automática de UID/GID para el usuario o grupo (esto se recomienda encarecidamente, a menos que sea estrictamente necesario usar un UID o GID específico). Alternativamente, especifique una ruta absoluta en el sistema de archivos. En este caso, el UID/GID se lee del propietario/grupo de la ruta. Esto es útil para crear usuarios cuyos UID/GID coincidan con los propietarios de archivos preexistentes (como binarios SUID o SGID). Se admiten las sintaxis "uid:gid" y "uid:nombre_grupo" para permitir la creación de usuarios con grupos primarios específicos. El grupo dado debe crearse explícitamente o ya debe existir. También se admite la especificación de "-" para el UID en estas sintaxis.

Para las líneas m, este campo debe contener el nombre del grupo al que añadir un usuario.

Para las líneas de tipo r, este campo debe establecerse en un rango de UID/GID en el formato "DESDE-HASTA", donde ambos valores se formatean como números ASCII decimales. Alternativamente, se puede especificar un solo UID/GID formateado como números ASCII decimales.

GECOS

Una cadena corta y descriptiva para los usuarios a crear, entre comillas. Tenga en cuenta que este campo no puede contener dos puntos.

Solo se aplica a las líneas de tipo u y, de lo contrario, debe dejarse sin establecer (o como "-").

Directorio de inicio

El directorio de inicio para un nuevo usuario del sistema. Si se omite, por defecto es el directorio raíz.

Solo se aplica a las líneas de tipo u y, de lo contrario, debe dejarse sin establecer (o como "-"). Se recomienda omitirlo, a menos que el software requiera estrictamente que se establezca un directorio de inicio.

systemd-sysusers solo establece el registro del directorio de inicio en la base de datos de usuarios. Para crear realmente el directorio, considere añadir un fragmento de tmpfiles.d(5) correspondiente.

ESPECIFICADORES

Se pueden usar especificadores en los campos "Nombre", "ID", "GECOS", "Directorio personal" y "Shell". Un especificador desconocido o irresoluble se trata como una configuración inválida. Se entienden las siguientes expansiones:

Tabla 1. Especificadores disponibles

Especificador Significado Detalles
"%a" Arquitectura Una cadena corta que identifica la arquitectura del sistema local. Una cadena como x86, x86-64 o arm64. Consulte las arquitecturas definidas para ConditionArchitecture= en systemd.unit(5) para obtener una lista completa.
"%A" Versión de la imagen del sistema operativo El identificador de la versión de la imagen del sistema operativo del sistema en ejecución, leído del campo IMAGE_VERSION= de /etc/os-release. Si no está establecido, se resuelve a una cadena vacía. Consulte os-release(5) para más información.
"%b" ID de arranque El ID de arranque del sistema en ejecución, formateado como cadena. Consulte random(4) para más información.
"%B" ID de compilación del sistema operativo El identificador de compilación del sistema operativo del sistema en ejecución, leído del campo BUILD_ID= de /etc/os-release. Si no está establecido, se resuelve a una cadena vacía. Consulte os-release(5) para más información.
"%H" Nombre de host El nombre de host del sistema en ejecución.
"%l" Nombre de host corto El nombre de host del sistema en ejecución, truncado en el primer punto para eliminar cualquier componente de dominio.
"%m" ID de máquina El ID de máquina del sistema en ejecución, formateado como cadena. Consulte machine-id(5) para más información.
"%M" Identificador de imagen del sistema operativo El identificador de imagen del sistema operativo del sistema en ejecución, leído del campo IMAGE_ID= de /etc/os-release. Si no está establecido, se resuelve a una cadena vacía. Consulte os-release(5) para más información.
"%o" ID del sistema operativo El identificador del sistema operativo del sistema en ejecución, leído del campo ID= de /etc/os-release. Consulte os-release(5) para más información.
"%q" Nombre de host bonito El nombre de host bonito del sistema en ejecución, leído del campo PRETTY_HOSTNAME= de /etc/machine-info. Si no está establecido, se resuelve al nombre de host corto. Consulte machine-info(5) para más información.
"%T" Directorio para archivos temporales Es /tmp o la ruta a la que se establecen "$TMPDIR", "$TEMP" o "$TMP". (Tenga en cuenta que el directorio puede especificarse sin una barra final).
"%v" Versión del kernel Idéntico a la salida de uname -r.
"%V" Directorio para archivos temporales más grandes y persistentes Es /var/tmp o la ruta a la que se establecen "$TMPDIR", "$TEMP" o "$TMP". (Tenga en cuenta que el directorio puede especificarse sin una barra final).
"%w" ID de versión del sistema operativo El identificador de versión del sistema operativo del sistema en ejecución, leído del campo VERSION_ID= de /etc/os-release. Si no está establecido, se resuelve a una cadena vacía. Consulte os-release(5) para más información.
"%W" ID de variante del sistema operativo El identificador de variante del sistema operativo del sistema en ejecución, leído del campo VARIANT_ID= de /etc/os-release. Si no está establecido, se resuelve a una cadena vacía. Consulte os-release(5) para más información.
"%%" Signo de porcentaje único Use "%%" en lugar de "%" para especificar un signo de porcentaje único.

IDEMPOTENCIA

Tenga en cuenta que
systemd-sysusers no hará nada si los usuarios o grupos especificados ya existen o si los usuarios son miembros de los grupos especificados, por lo que normalmente no hay razón para anular la configuración del proveedor de sysusers.d, excepto para bloquear la creación de ciertos usuarios o grupos.
