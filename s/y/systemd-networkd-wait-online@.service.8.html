NOMBRE

systemd-networkd-wait-online.service, systemd-networkd-wait-online@.service, systemd-networkd-wait-online - Esperar a que la red se conecte

SINOPSIS

systemd-networkd-wait-online.service

systemd-networkd-wait-online@.service

/usr/lib/systemd/systemd-networkd-wait-online

DESCRIPCIÓN

systemd-networkd-wait-online es un servicio de sistema "oneshot" (ver systemd.service(5)) que espera a que la red esté configurada. Por defecto, esperará a que todos los enlaces que conoce y que son gestionados por systemd-networkd.service(8) estén completamente configurados o fallidos, y a que al menos un enlace esté en línea. Aquí, "en línea" significa que el estado operacional del enlace es igual o superior a "degradado". El umbral se puede configurar con la opción --operational-state=.

El servicio systemd-networkd-wait-online.service invoca systemd-networkd-wait-online sin opciones. Por lo tanto, espera a que todas las interfaces gestionadas estén configuradas o fallidas, y a que al menos una esté en línea.

El servicio systemd-networkd-wait-online@.service toma un nombre de interfaz e invoca systemd-networkd-wait-online con -i y el nombre de interfaz especificado. Por lo tanto, espera a que la interfaz especificada esté configurada y en línea. Por ejemplo, systemd-networkd-wait-online@eth0.service espera a que eth0 sea configurada por systemd-networkd y esté en línea.

OPCIONES

Se entienden las siguientes opciones:

-i INTERFAZ[:MIN_OPERSTATE[:MAX_OPERSTATE]], --interface=INTERFAZ[:MIN_OPERSTATE[:MAX_OPERSTATE]]

Interfaz de red a esperar antes de decidir si el sistema está en línea. Esto es útil cuando un sistema tiene varias interfaces que serán configuradas, pero una en particular es necesaria para acceder a algunos recursos de red. Cuando se usa, todas las demás interfaces se ignoran. Esta opción puede usarse varias veces para esperar a múltiples interfaces de red. Cuando esta opción se especifica varias veces, entonces systemd-networkd-wait-online espera a que todas las interfaces especificadas estén en línea. Opcionalmente, se pueden especificar los estados operacionales mínimos y máximos requeridos después de dos puntos ":". Consulte networkctl(1) para conocer los posibles estados operacionales. Si el estado operacional no se especifica aquí, entonces se utiliza el valor de RequiredForOnline= en el archivo .network correspondiente si está presente, y "degradado" en caso contrario.

Añadido en la versión 213.

--ignore=INTERFAZ

Interfaces de red a ignorar al decidir si el sistema está en línea. Por defecto, solo se ignora la interfaz de loopback. Esta opción puede usarse varias veces para ignorar múltiples interfaces de red.

Añadido en la versión 219.

-o MIN_OPERSTATE[:MAX_OPERSTATE], --operational-state=MIN_OPERSTATE[:MAX_OPERSTATE]

Toma un estado operacional mínimo y un estado operacional máximo opcional. Consulte networkctl(1) para conocer los posibles estados operacionales. Si se establece, el valor especificado anula la configuración de RequiredForOnline= en los archivos .network. Pero esto no anula los estados operacionales especificados en la opción --interface=.

Añadido en la versión 242.

-4, --ipv4

Espera a que se configure una dirección IPv4 de cada interfaz de red. Si esta opción se especifica con --any, entonces systemd-networkd-wait-online sale con éxito cuando al menos una interfaz se pone en línea y tiene una dirección IPv4. Si el estado operacional mínimo requerido es inferior a "enrutable", entonces cada enlace (o al menos un enlace con --any) debe tener una dirección IPv4 enrutable o de enlace local. Si el estado operacional mínimo requerido es "enrutable", entonces cada enlace debe tener una dirección IPv4 enrutable.

Si no se especifica ni --ipv4 ni --ipv6, entonces se utiliza el valor de RequiredFamilyForOnline= en el archivo .network correspondiente si está presente.

Añadido en la versión 249.

-6, --ipv6

Espera a que se configure una dirección IPv6 de cada interfaz de red. Si esta opción se especifica con --any, entonces systemd-networkd-wait-online sale con éxito cuando al menos una interfaz se pone en línea y tiene una dirección IPv6. Si el estado operacional mínimo requerido es inferior a "enrutable", entonces cada enlace (o al menos un enlace con --any) debe tener una dirección IPv6 enrutable o de enlace local. Si el estado operacional mínimo requerido es "enrutable", entonces cada enlace debe tener una dirección IPv6 enrutable.

Si no se especifica ni --ipv4 ni --ipv6, entonces se utiliza el valor de RequiredFamilyForOnline= en el archivo .network correspondiente si está presente.

Añadido en la versión 249.

--dns

Espera a que los servidores DNS sean accesibles en cada interfaz. Si esta opción se especifica con --any, entonces systemd-networkd-wait-online sale con éxito cuando al menos una interfaz se pone en línea y tiene un servidor DNS accesible.

Si un enlace tiene la propiedad DefaultRoute=yes (ya sea porque la propiedad de red DNSDefaultRoute= está configurada explícitamente, o porque el enlace no tiene dominios "solo enrutamiento"), o si se configura el dominio de búsqueda ".", entonces espera a que los servidores DNS específicos del enlace sean accesibles. De lo contrario, permite que los servidores DNS globales satisfagan la condición.

Añadido en la versión 258.

--any

Incluso si varias interfaces están en estado de configuración, systemd-networkd-wait-online sale con éxito cuando al menos una interfaz se pone en línea. Cuando esta opción se especifica con --interface=, entonces systemd-networkd-wait-online espera a que una de las interfaces especificadas esté en línea. Esta opción es útil cuando algunas interfaces pueden no tener portadora al arrancar.

Añadido en la versión 242.

--timeout=SECS

Falla el servicio si la red no está en línea antes de que expire el tiempo de espera. Un tiempo de espera de 0 deshabilita el tiempo de espera. Por defecto son 120 segundos.

Añadido en la versión 219.

-q, --quiet

Suprime mensajes de registro.

Añadido en la versión 242.

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.
