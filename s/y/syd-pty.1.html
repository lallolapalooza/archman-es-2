SYD-PTY(1) Manual de comandos generales SYD-PTY(1)

NOMBRE

syd-pty - Reenviador bidireccional de PTY a STDIO

SINOPSIS

syd-pty [-dh] [-x <tamaño-x>] [-y <tamaño-y>] -p <pid-fd> -i <pty-fd>

DESCRIPCIÓN

Reenvía datos entre el descriptor de archivo principal de pty(7) proporcionado y stdio(3).

El descriptor de archivo PID se utiliza para rastrear la salida del proceso Syd.

OPCIONES

-h Muestra la ayuda.
-d Ejecutar en modo de depuración sin confinamiento.
-p pid-fd Descriptor de archivo PID del proceso Syd.
-i pty-fd Descriptor de archivo principal de PTY.
-x tamaño-x Especifica el tamaño de fila de la ventana (por defecto: heredar).
-y tamaño-y Especifica el tamaño de columna de la ventana (por defecto: heredar).

USO

syd-pty(1) no está diseñado para ser utilizado como una herramienta independiente. Syd invoca a syd-pty(1) al inicio cuando el sandboxing de PTY está activado con sandbox/pty:on. Consulte la sección PTY SANDBOXING de la página del manual de syd(7) para obtener más información. Si desea utilizar syd-pty(1) en su propio proyecto, lo primero que debe hacer es pasarle un descriptor de archivo PID no bloqueante de su propio proceso con el argumento -p <pid-fd> para que syd-pty(1) pueda salir simultáneamente con él. Se debe tener cuidado en esta etapa, ya que los descriptores de archivo PID son O_CLOEXEC por defecto. A continuación, cree un nuevo pseudoterminal con posix_openpt(3) o openpty(3) y pase el extremo principal del par de descriptores de archivo a syd-pty(1) con el argumento -i <pty-fd>.

IMPLEMENTACIÓN

syd-pty(1) está diseñado pensando en el rendimiento, la seguridad y la privacidad, utilizando técnicas avanzadas como epoll(7) disparado por flancos para una notificación de eventos eficiente y operaciones completamente asíncronas para manejar actividades de pseudoterminal sin bloqueo. Emplea transferencia de datos de cero copias utilizando la llamada al sistema splice(2) para mover datos directamente entre descriptores de archivo dentro del kernel, garantizando un alto rendimiento y privacidad de los datos. Para facilitar la comunicación bidireccional, syd-pty(1) utiliza dos pares de tuberías, lo que permite un flujo de datos sin problemas entre pty(7) y stdio(3). Además, syd-pty(1) confina su entorno de ejecución utilizando seccomp y Landlock, restringiendo las llamadas al sistema y los accesos a archivos para minimizar la superficie de ataque.

SEGURIDAD

syd-pty(1) implementa medidas de seguridad integrales para mitigar los riesgos asociados con la ejecución fuera del sandbox de Syd, previniendo así posibles ataques de Man-in-the-Middle (MITM) contra contenedores. Los filtros Seccomp están meticulosamente configurados para permitir solo las syscalls necesarias. Además, la memoria ejecutable no está permitida para prevenir ataques de inyección de código. Landlock y los espacios de nombres, si están disponibles, imponen restricciones adicionales al prohibir todo acceso al sistema de archivos y a la red, proporcionando una capa adicional de seguridad. Además, el descriptor de archivo PTY principal se pone en modo exclusivo mediante la solicitud ioctl(2) TIOCEXCL. Esto evita cualquier apertura adicional del dispositivo PTY secundario (salvo para procesos con la capacidad CAP_SYS_ADMIN), reduciendo así la superficie de ataque para la escucha no autorizada o la inyección de entrada en la capa del dispositivo como parte de una estrategia de defensa en profundidad. Estas técnicas combinadas garantizan que, incluso si syd-pty(1) se ve comprometido, el alcance de las acciones maliciosas se limita significativamente, manteniendo la integridad y seguridad del sistema en general.

ENTORNO

SYD_PTY_DEBUG Ejecutar en modo de depuración sin confinamiento, equivalente a la opción -d
SYD_PTY_RULES Imprime las reglas de seccomp en formato legible por humanos en la salida estándar de error al inicio

ERRORES

El soporte de splice(2) para ttys fue eliminado en el commit 36e2c7421f02a22f71c9283e55fdb672a9eb58e7 (fusionado para Linux 6.5) y posteriormente restaurado en el commit 9bb48c82aced07698a2d08ee0f1475a6c4f6b266 (fusionado para Linux 6.6). Al ejecutarse bajo un kernel de Linux problemático, syd-pty(1) saldrá con 22, es decir, EINVAL o Argumento inválido. Consulte los siguientes enlaces para obtener más información:

  • https://git.kernel.org/linus/36e2c7421f02a22f71c9283e55fdb672a9eb58e7
  • https://git.kernel.org/linus/9bb48c82aced07698a2d08ee0f1475a6c4f6b266
