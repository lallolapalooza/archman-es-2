NOMBRE

systemd-sysusers, systemd-sysusers.service - Asignar usuarios y grupos del sistema

SINOPSIS

systemd-sysusers [OPCIONES...] [ARCHIVO_CONFIG...]

systemd-sysusers.service

DESCRIPCIÓN

systemd-sysusers crea usuarios y grupos del sistema, basándose en archivos con el formato descrito en sysusers.d(5).

Si se invoca sin argumentos, se ejecutan las directivas de los archivos de configuración encontrados en los directorios especificados por sysusers.d(5). Cuando se invoca con argumentos posicionales, si se especifica la opción --replace=RUTA, se utilizan los argumentos especificados en la línea de comandos en lugar del archivo de configuración RUTA. De lo contrario, solo se ejecuta la configuración especificada por los argumentos de la línea de comandos. Si se especifica la cadena "-" en lugar de un nombre de archivo, la configuración se lee de la entrada estándar. Si el argumento es un nombre de archivo (sin barras), se buscan todos los directorios de configuración para encontrar un archivo coincidente y se ejecuta el archivo encontrado que tenga la mayor prioridad. Si el argumento es una ruta, se utiliza ese archivo directamente sin buscar en los directorios de configuración ningún otro archivo coincidente.

OPCIONES

Se entienden las siguientes opciones:

--root=root

Toma una ruta de directorio como argumento. Todas las rutas se prefijarán con la ruta raíz alternativa dada root, incluidas las rutas de búsqueda de configuración.

Añadido en la versión 215.

--image=imagen

Toma una ruta a un archivo de imagen de disco o nodo de dispositivo de bloque. Si se especifica, todas las operaciones se aplicarán al sistema de archivos en la imagen de disco indicada. Esto es similar a --root= pero opera en sistemas de archivos almacenados en imágenes de disco o dispositivos de bloque. La imagen de disco debería contener solo un sistema de archivos o un conjunto de sistemas de archivos dentro de una tabla de particiones GPT, siguiendo la Especificación de Particiones Reconocibles[1]. Para más información sobre imágenes de disco compatibles, véase el modificador del mismo nombre en systemd-nspawn(1).

Añadido en la versión 247.

--image-policy=política

Toma una cadena de política de imagen como argumento, según systemd.image-policy(7). La política se aplica al operar en la imagen de disco especificada mediante --image=, véase más arriba. Si no se especifica, por defecto es la política "*", es decir, se utilizan todos los sistemas de archivos reconocidos en la imagen.

--replace=RUTA

Cuando se da esta opción, debe especificarse uno o más argumentos posicionales. Se leerán todos los archivos de configuración encontrados en los directorios listados en sysusers.d(5), y la configuración dada en la línea de comandos se manejará en lugar de y con la misma prioridad que el archivo de configuración RUTA.

Esta opción está pensada para ser utilizada cuando se ejecutan scripts de instalación de paquetes y los archivos pertenecientes a ese paquete aún no están disponibles en disco, por lo que su contenido debe proporcionarse en la línea de comandos, pero la configuración del administrador puede existir y debe tener mayor prioridad.

Ejemplo 1. Script de instalación RPM para radvd

echo 'u radvd - "radvd daemon"' | \
          systemd-sysusers --replace=/usr/lib/sysusers.d/radvd.conf -

Esto creará el usuario radvd como si /usr/lib/sysusers.d/radvd.conf ya estuviera en el disco. Un administrador podría anular la configuración especificada en la línea de comandos colocando /etc/sysusers.d/radvd.conf o incluso /etc/sysusers.d/00-overrides.conf.

Tenga en cuenta que esta es la forma expandida, y cuando se utiliza en un paquete, esto se escribiría utilizando una macro con "radvd" y un archivo que contiene la línea de configuración como argumentos.

Añadido en la versión 238.

--dry-run

Procesa la configuración y determina qué entradas se crearían, pero no escribe nada realmente.

Añadido en la versión 250.

--inline

Trata cada argumento posicional como una línea de configuración separada en lugar de un nombre de archivo.

Añadido en la versión 238.

--cat-config

Copia el contenido de los archivos de configuración a la salida estándar. Antes de cada archivo, se imprime el nombre del archivo como un comentario.

--tldr

Copia el contenido de los archivos de configuración a la salida estándar. Solo se imprime la parte "interesante" de los archivos de configuración; se omiten los comentarios y las líneas vacías. Antes de cada archivo, se imprime el nombre del archivo como un comentario.

--no-pager

No canaliza la salida a un paginador.

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.

CREDENCIALES

systemd-sysusers soporta la lógica de credenciales de servicio implementada por ImportCredential=/LoadCredential=/SetCredential= (ver systemd.exec(5) para más detalles). Las siguientes credenciales se utilizan cuando se pasan:

passwd.hashed-password.usuario

Una cadena de contraseña cifrada de UNIX para usarla para el usuario especificado, al crear una entrada para él. Esto es particularmente útil para el usuario "root", ya que permite aprovisionar la contraseña predeterminada de root a usar a través de un drop-in del archivo de unidad o desde un gestor de contenedores que pase esta credencial. Tenga en cuenta que establecer esta credencial no tiene efecto si la cuenta de usuario especificada ya existe. Por lo tanto, esta credencial es principalmente útil en escenarios de primer arranque o en sistemas que son completamente sin estado y arrancan con un /etc/ vacío en cada arranque.

Añadido en la versión 249.

passwd.plaintext-password.usuario

Similar a "passwd.hashed-password.usuario" pero espera una contraseña literal en texto plano, que luego se cifra automáticamente antes de usarla para la cuenta de usuario. Si se especifican tanto la credencial cifrada como la de texto plano para el mismo usuario, la primera tiene prioridad. Generalmente se recomienda especificar la versión cifrada; sin embargo, en entornos de prueba con requisitos de seguridad más débiles, puede ser más fácil pasar contraseñas en texto plano.

Añadido en la versión 249.

passwd.shell.usuario

Especifica el binario del shell a usar para la cuenta especificada al crearla.

Añadido en la versión 249.

sysusers.extra

El contenido de esta credencial puede contener líneas adicionales para operar. El contenido de la credencial debe seguir el mismo formato que cualquier otro drop-in de sysusers.d/. Si se pasa esta credencial, se procesará después de todos los archivos drop-in leídos del sistema de archivos.

Añadido en la versión 252.

Tenga en cuenta que, por defecto, el archivo de unidad systemd-sysusers.service está configurado para heredar las credenciales "passwd.hashed-password.root", "passwd.plaintext-password.root", "passwd.shell.root" y "sysusers.extra" del gestor de servicios. Por lo tanto, al invocar un contenedor con un /etc/ no poblado por primera vez, es posible configurar la contraseña del usuario root a "systemd" de la siguiente manera:

# systemd-nspawn --image=... --set-credential=passwd.hashed-password.root:'$y$j9T$yAuRJu1o5HioZAGDYPU5d.$F64ni6J2y2nNQve90M/p0ZP0ECP/qqzipNyaY9fjGpC' ...

Tenga en cuenta nuevamente que los datos especificados en esta credencial se consultan solo al crear una cuenta por primera vez; no se pueden usar para cambiar la contraseña o el shell de una cuenta que ya existe.

Use mkpasswd(1) para generar hashes de contraseña de UNIX desde la línea de comandos.

ESTADO DE SALIDA

Al éxito, se devuelve 0; de lo contrario, se devuelve un código de error distinto de cero.

systemd-sysusers.8.en

NAME

systemd-sysusers - manage static user and group accounts

SYNOPSIS

systemd-sysusers [-h --help] [-V --version]

DESCRIPTION

systemd-sysusers is a tool to generate and manage static user and group accounts.

It operates based on configuration files found in /usr/lib/sysusers.d/*.conf, /etc/sysusers.d/*.conf and /run/sysusers.d/*.conf. These files describe the desired state of user and group accounts, including their names, UIDs, GIDs, home directories, shell, and whether they should be created or removed.

When run, systemd-sysusers reads these configuration files, determines the differences between the described state and the current system state, and performs the necessary actions (creating or deleting users/groups) to match the desired state.

This tool is typically run automatically during the system boot process or when package installations/removals modify the sysusers configuration files.

OPTIONS

The following options are available:

-h, --help
Print a short help text and exit.
-V, --version
Print a short version string and exit.

CREDENTIALS

systemd-sysusers may need to create users and groups, which requires appropriate privileges. It should typically be run as root or using elevated privileges (e.g., via sudo).

EXIT STATUS

Returns 0 if the operation was successful, and a non-zero value otherwise.
