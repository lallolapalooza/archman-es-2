GENERAL

¿Qué es Syncthing?

Syncthing es una aplicación que te permite sincronizar tus archivos entre múltiples dispositivos. Esto significa que la creación, modificación o eliminación de archivos en una máquina se replicará automáticamente en tus otros dispositivos. Creemos que tus datos son solo tuyos y mereces elegir dónde se almacenan. Por lo tanto, Syncthing no sube tus datos a la nube, sino que intercambia tus datos entre tus máquinas tan pronto como están en línea al mismo tiempo.

¿Es “syncthing”, “Syncthing” o “SyncThing”?

Es Syncthing, aunque el comando y el repositorio de código fuente están escritos en minúsculas syncthing, por lo que también se puede referir de esa manera. Definitivamente no es SyncThing, aunque la abreviatura st se use en algunas circunstancias y nombres de archivo.

¿Qué cosas se sincronizan?

Las siguientes cosas se sincronizan siempre:

  • Contenido de los archivos
  • Tiempos de modificación de archivos

Las siguientes cosas pueden sincronizarse o no, dependiendo:

  • Permisos de archivos (cuando el sistema de archivos lo soporta; en Windows solo se sincroniza el bit de solo lectura)
  • Enlaces simbólicos (se sincronizan, excepto en Windows, pero nunca se siguen)
  • Propietarios y grupos de archivos o directorios (cuando está habilitado)
  • Atributos extendidos (cuando está habilitado)
  • ACLs POSIX o NFS (como parte de los atributos extendidos)

NOTA:

Tenga en cuenta que lo que se puede sincronizar a menudo depende del sistema operativo, el sistema de archivos y posiblemente otros factores. Por ejemplo, aunque Syncthing intente sincronizar enlaces simbólicos en Android, esto no tendrá éxito, ya que el SO no los soporta en el almacenamiento del usuario.

Lo siguiente no se sincroniza:

  • Tiempos de modificación de directorios (no se conservan)
  • Enlaces duros (se siguen, no se conservan)
  • Uniones de Windows (se sincronizan como directorios ordinarios; requieren ser habilitados en la configuración por carpeta)
  • Forks de recursos (no se conservan)
  • ACLs de Windows (no se conservan)
  • Dispositivos, FIFOs y otros especiales (ignorados)
  • Espacios de archivos dispersos (se volverán dispersos, cuando sea soportado por el SO y el sistema de archivos)
  • Archivos y directorios internos de Syncthing (por ejemplo, .stfolder, .stignore, .stversions, archivos temporales, etc.)

¿La sincronización es rápida?

Syncthing segmenta los archivos en piezas, llamadas bloques, para transferir datos de un dispositivo a otro. Por lo tanto, múltiples dispositivos pueden compartir la carga de sincronización, de manera similar al protocolo torrent. Cuantos más dispositivos tenga en línea, más rápido recibirá un dispositivo adicional los datos, ya que pequeños bloques se obtendrán de todos los dispositivos en paralelo.

Syncthing maneja el cambio de nombre de archivos y la actualización de sus metadatos de manera eficiente. Esto significa que renombrar un archivo no provocará una retransmisión de ese archivo. Además, la adición de datos a archivos existentes también debería manejarse de manera eficiente.

Se utilizan archivos temporales para almacenar datos parciales descargados de otros dispositivos. Se eliminan automáticamente cada vez que se completa una transferencia de archivo o después de la cantidad de tiempo configurada, que se establece en el archivo de configuración (24 horas por defecto).

¿Cómo se diferencia Syncthing de BitTorrent/Resilio Sync?

Son diferentes y no están relacionados. Syncthing y BitTorrent/Resilio Sync logran algunas de las mismas cosas, a saber, sincronizar archivos entre dos o más computadoras.

BitTorrent Sync, ahora llamado Resilio Sync, es una herramienta propietaria de sincronización de archivos peer-to-peer disponible para Windows, Mac, Linux, Android, iOS, Windows Phone, Amazon Kindle Fire y BSD. [1] Syncthing es una herramienta de sincronización de archivos de código abierto.

Syncthing utiliza un protocolo abierto y documentado, y de manera similar, los mecanismos de seguridad en uso están bien definidos y son visibles en el código fuente. Resilio Sync utiliza un protocolo cerrado y no documentado con propiedades de seguridad desconocidas.

¿Hay un cliente para iOS?

El equipo actual de Syncthing no tiene planes para soportar oficialmente iOS en el futuro previsible.

iOS tiene restricciones significativas en el procesamiento en segundo plano que hacen que sea muy difícil ejecutar Syncthing de manera confiable e integrarlo en el sistema.

Sin embargo, existe una aplicación de código abierto para iOS, que incorpora Syncthing, que intenta funcionar dentro de estas limitaciones. Proporciona una interfaz de usuario nativa y funciones para sincronización selectiva, así como acceso bajo demanda a archivos. La mayoría de las funciones de Syncthing están disponibles, pero la interfaz de usuario nativa está simplificada en comparación con el cliente oficial. [2]

También existe un paquete comercial de Syncthing. Proporciona acceso a todas las funcionalidades de Syncthing a través de la interfaz de usuario original. [3]

¿Debo mantener secretos mis IDs de dispositivo?

No. Los IDs de dispositivo de Syncthing son públicos y se utilizan para la identificación y el descubrimiento de pares. Pueden ser compartidos abiertamente.

La seguridad de la comunicación se basa en la criptografía de clave pública de la conexión TLS y la autenticación de los pares mediante certificados mutuos, que son generados por Syncthing en cada dispositivo y no se comparten. Tu ID de dispositivo Syncthing es la clave pública autenticada para esa conexión.

SOLUCIÓN DE PROBLEMAS

¿Dónde están los registros de Syncthing?

Los registros se pueden encontrar en las siguientes ubicaciones:

  • Linux: /var/log/syncthing/syncthing.log o donde sea que el servicio lo haya configurado.
  • Windows: %LOCALAPPDATA%\Syncthing\syncthing.log.
  • macOS: ~/Library/Logs/Syncthing/syncthing.log.
  • Android: En la aplicación Syncthing bajo "Configuración" > "Avanzado" > "Ver registro".

También se puede acceder a ellos a través de la API de Syncthing.

¿Por qué la sincronización es tan lenta?

Hay muchas razones por las que la sincronización puede ser lenta. Estas son algunas de las causas más comunes y cómo solucionarlas:

  • Conexión a Internet lenta o concurrida: Si tu conexión a Internet está lenta o si otros dispositivos están usando mucho ancho de banda, Syncthing puede ser lento. Intenta ejecutar una prueba de velocidad de Internet para verificar la velocidad de carga y descarga.

  • Muchos dispositivos: Si tienes muchos dispositivos sincronizando el mismo directorio, la velocidad puede verse afectada. Considere usar "Envío exclusivo" para los dispositivos que no necesitan la sincronización activa.

  • Configuración de red: Los firewalls o los problemas de red pueden interferir con las conexiones directas. Asegúrate de que los puertos necesarios (TCP 22000 y UDP 21027) estén abiertos y accesibles.

  • Hardware o disco duro lento: Si tu disco duro es lento o está fragmentado, puede afectar el rendimiento de la sincronización. Las unidades de estado sólido (SSD) generalmente ofrecen un mejor rendimiento.

  • Muchos archivos pequeños: Sincronizar una gran cantidad de archivos pequeños puede ser más lento que sincronizar un solo archivo grande del mismo tamaño total, debido a la sobrecarga de procesamiento por archivo.

  • Reindexación: Si Syncthing acaba de iniciarse o si se realizaron muchos cambios en los archivos, puede estar reindexando los archivos, lo que puede ralentizar temporalmente la sincronización.

  • Limitaciones de CPU/RAM: Si tu dispositivo tiene recursos limitados, Syncthing puede tener dificultades para mantenerse al día.

  • Relays: Si los dispositivos se conectan a través de relays, la velocidad puede ser significativamente más lenta que las conexiones directas. Verifique el estado de la conexión en la GUI de Syncthing.

¿Por qué consume tanta CPU?

Syncthing puede consumir una cantidad significativa de CPU durante ciertas operaciones, como la indexación inicial de carpetas, la reindexación después de cambios importantes, la verificación de cambios de archivos o la transferencia de datos. Si notas un uso alto de CPU continuo y no deseado, considera lo siguiente:

  • Muchos archivos o cambios frecuentes: El escaneo de una gran cantidad de archivos o la gestión de cambios constantes en los archivos requiere recursos de CPU.
  • Configuración de `inotify/watch` inadecuada: En Linux, si el límite de `inotify` es demasiado bajo, Syncthing podría recurrir a verificaciones periódicas más intensivas en CPU. Asegúrate de que el límite de `inotify` sea lo suficientemente alto.
  • Base de datos corrupta: Una base de datos de Syncthing corrupta puede causar un uso elevado de CPU mientras intenta repararla. Reconstruir la base de datos puede ayudar.
  • Problemas de hardware o del sistema de archivos: Problemas con el disco duro o el sistema de archivos subyacente pueden causar un rendimiento lento y, en consecuencia, un uso elevado de CPU.
  • Análisis de Virus en tiempo real: El software antivirus que escanea constantemente los archivos que Syncthing está modificando puede causar una sobrecarga de CPU. Intenta excluir los directorios de Syncthing del análisis en tiempo real.

¿Por qué la configuración es más complicada que con BitTorrent/Resilio Sync?

Syncthing está diseñado priorizando la seguridad y la privacidad. A diferencia de Resilio Sync (anteriormente BitTorrent Sync), Syncthing no requiere una cuenta centralizada ni envía metadatos a un servidor externo. Cada dispositivo debe ser añadido explícitamente, y el intercambio de claves (IDs de dispositivo) es un paso necesario para garantizar que solo los dispositivos autorizados puedan conectarse y compartir datos.

Este enfoque garantiza que solo tú controlas tus datos y con quién los compartes. Si bien puede parecer más complejo al principio, proporciona un nivel de seguridad y control que no está disponible en otras soluciones.

¿Por qué recibo un error de "Host check error" en la GUI/API?

Este error ocurre cuando la dirección IP o el nombre de host que Syncthing está intentando usar para la API o la GUI web no coincide con la dirección que espera o ha configurado.

Las causas comunes incluyen:

  • Múltiples interfaces de red: Si tu máquina tiene varias interfaces de red (por ejemplo, Ethernet y Wi-Fi, o múltiples direcciones IP), Syncthing podría estar intentando escuchar o conectarse a través de una que no es la correcta o la esperada.
  • Configuración de `hosts` incorrecta: La configuración en tu archivo `hosts` del sistema operativo podría estar apuntando a la IP incorrecta.
  • Problemas de DNS dinámico: Si estás usando un servicio de DNS dinámico, puede haber demoras en la propagación de las actualizaciones de IP.
  • VPNs o proxies: El uso de VPNs o proxies puede enrutar el tráfico de manera diferente y causar conflictos con la configuración de la red de Syncthing.

Solución:

  • Verifica la configuración de la GUI web y la API en el archivo de configuración de Syncthing (gui.host_whitelist, gui.address, api.address). Asegúrate de que estén configurados para escuchar en las interfaces de red correctas (por ejemplo, 127.0.0.1:8384 para acceso local, o la IP de tu máquina para acceso de red).
  • Si usas un nombre de host, asegúrate de que se resuelva correctamente a la IP de tu máquina.
  • Considera deshabilitar temporalmente las VPNs o proxies para ver si eso resuelve el problema.

Mi base de datos de Syncthing está corrupta

Si experimentas problemas con la base de datos de Syncthing (por ejemplo, errores de corrupción, uso elevado de CPU sin razón aparente, archivos que no se sincronizan), puedes intentar reconstruirla.

Advertencia: Reconstruir la base de datos provocará que Syncthing vuelva a escanear todos tus archivos. Esto puede llevar tiempo y consumir recursos de CPU. Si tienes versiones de archivos habilitadas, perderás las versiones anteriores que se hayan guardado en la base de datos corrupta.

Para reconstruir la base de datos:

  • Detén Syncthing.
  • Navega al directorio de datos de Syncthing. La ubicación varía según el sistema operativo:
    • Linux: ~/.config/syncthing/index/
    • Windows: %LOCALAPPDATA%\Syncthing\index\
    • macOS: ~/Library/Application Support/Syncthing/index/
  • Elimina o renombra el directorio index.
  • Inicia Syncthing de nuevo. Reconstruirá la base de datos a medida que escaneará tus carpetas.

Si el problema persiste, puede ser necesario reconstruir la base de datos de cada carpeta compartida individualmente. Esto se puede hacer desde la GUI web de Syncthing, yendo a la configuración de la carpeta y haciendo clic en "Reconstruir".

¿Por veo Syncthing dos veces en el administrador de tareas?

Esto generalmente ocurre cuando ejecutas Syncthing manualmente desde la línea de comandos y también tienes un servicio o demonio de Syncthing ejecutándose en segundo plano. El proceso que iniciaste manualmente y el proceso del servicio están ambos activos, lo que resulta en dos instancias visibles en el administrador de tareas.

Solución:

  • Si deseas que Syncthing se ejecute como un servicio o demonio, asegúrate de iniciarlo de esa manera (por ejemplo, usando `systemctl` en Linux o configurando el servicio de Windows) y evita iniciarlo manualmente desde la línea de comandos al mismo tiempo.
  • Si prefieres ejecutarlo manualmente, asegúrate de que no haya un servicio o demonio de Syncthing ejecutándose en segundo plano.

¿Cómo puedo ver el historial de cambios?

Syncthing tiene una función de "Versionado de archivos" que te permite mantener copias de versiones anteriores de los archivos. Si está habilitada para una carpeta, puedes acceder al historial de cambios a través de la GUI web.

Para habilitar el versionado de archivos:

  • Ve a la configuración de la carpeta en la GUI web de Syncthing.
  • Haz clic en "Editar".
  • En la sección "Versionado de archivos", selecciona una estrategia (por ejemplo, "Copia simple" o "Balanceado").
  • Haz clic en "Guardar".

Una vez habilitado, puedes ver las versiones anteriores de un archivo haciendo clic derecho sobre él en la GUI web y seleccionando "Ver versiones".

¿El registro de auditoría contiene todos los cambios?

El registro de auditoría registra los eventos relacionados con la seguridad y la configuración, como cambios en la configuración, inicios y cierres de sesión, y adición o eliminación de dispositivos. Sin embargo, no registra cada cambio de archivo individual realizado dentro de una carpeta sincronizada. Para rastrear cambios en archivos específicos, deberías habilitar la función de "Versionado de archivos" de Syncthing.

¿Por qué Syncthing se conecta a esta dirección desconocida/sospechosa?

Syncthing puede conectarse a direcciones que no esperas por varias razones:

  • Descubrimiento Global de Pares (Global Peer Discovery): Syncthing utiliza un servicio de descubrimiento global para encontrar otros dispositivos Syncthing en Internet. Las conexiones a estos servidores de descubrimiento pueden parecer sospechosas.
  • Relays (Servidores de Relevo): Si Syncthing no puede establecer una conexión directa entre dos dispositivos (debido a firewalls o NAT), puede utilizar un servidor de relevo para facilitar la comunicación. Las conexiones a estos relays pueden parecer desconocidas. Puedes ver si se está usando un relay en la GUI de Syncthing, junto al estado de conexión de cada dispositivo.
  • Servidores de Sincronización de Tiempo (NTP): Syncthing puede sincronizar la hora de tu sistema con servidores de tiempo para asegurar que las marcas de tiempo de los archivos sean precisas entre dispositivos.
  • Servidores DNS: Si tu dispositivo necesita resolver nombres de dominio para conectarse a otros dispositivos o servicios, se conectará a servidores DNS.

Para verificar si una conexión es legítima:

  • En la GUI web de Syncthing, ve a la vista "Dispositivos". Busca el dispositivo específico al que se está conectando. El estado de la conexión (por ejemplo, "Directo", "Relay", "Desconocido") te dará pistas.
  • Si te preocupa una conexión específica, puedes intentar deshabilitar el descubrimiento global de pares o los relays temporalmente en la configuración de Syncthing para ver si el problema desaparece.
  • Investiga la dirección IP a la que se conecta Syncthing. Puedes usar herramientas de búsqueda de IP o bases de datos WHOIS para obtener más información sobre el propietario del rango de IP.

Veo el mensaje de error "folder marker missing". ¿Qué hago?

Este error indica que Syncthing no puede encontrar el archivo marcador (`.stfolder`) dentro de un directorio compartido. Este archivo es utilizado por Syncthing para identificar directorios que están bajo su control.

Las causas comunes y soluciones incluyen:

  • El archivo marcador fue eliminado accidentalmente: Si el archivo `.stfolder` fue eliminado manualmente o por otro proceso, Syncthing no reconocerá la carpeta como sincronizada.
    • Solución: Recrea el archivo marcador manualmente en el directorio raíz de la carpeta compartida. Puedes hacerlo ejecutando en la terminal (dentro del directorio de la carpeta): touch .stfolder. Luego, fuerza una resincronización de la carpeta desde la GUI de Syncthing.
  • La carpeta fue movida o renombrada fuera de Syncthing: Si moviste o renombraste la carpeta sincronizada sin notificar a Syncthing, el archivo marcador podría haber sido movido con ella, o Syncthing podría estar buscándola en la ubicación antigua.
    • Solución: Asegúrate de que la carpeta esté en la ubicación correcta esperada por Syncthing. Si la moviste, es posible que necesites detener Syncthing, mover la carpeta de nuevo a la ubicación original (o actualizar la ruta en la configuración de Syncthing), y luego volver a crear el archivo marcador si fue eliminado.
  • Permisos de archivo incorrectos: Si los permisos del directorio o del archivo marcador son incorrectos, Syncthing podría no poder leerlos.
    • Solución: Verifica que el usuario que ejecuta Syncthing tenga permisos de lectura y escritura para el directorio de la carpeta y su contenido.
  • Disco casi lleno o errores del sistema de archivos: En casos raros, problemas con el disco duro o el sistema de archivos pueden impedir la creación o el acceso al archivo marcador.
    • Solución: Verifica el espacio en disco y ejecuta herramientas de diagnóstico del sistema de archivos si sospechas de problemas subyacentes.

Después de aplicar una solución, es posible que debas forzar una "Resincronización" de la carpeta afectada en la GUI de Syncthing para que los cambios se reflejen.

¿Por qué mis computadoras con Windows siempre se conectan a través de un relay?

Esto suele ser un problema relacionado con la configuración de red en Windows, específicamente con el "Registro de autenticación de red" (Network Authentication Enrollment).

Causa:

Windows puede tener problemas para descubrir otros dispositivos en la red local cuando el registro de autenticación de red no está configurado correctamente. Esto impide que Syncthing establezca conexiones directas y lo obliga a usar relays para la comunicación.

Solución:

Puedes intentar solucionar este problema habilitando el registro de autenticación de red para tu adaptador de red:

  • Abre el "Centro de redes y recursos compartidos" (Network and Sharing Center).
  • Haz clic en "Cambiar configuración del adaptador" (Change adapter settings).
  • Haz clic derecho en tu adaptador de red principal (Ethernet o Wi-Fi) y selecciona "Propiedades" (Properties).
  • Busca "Registro de autenticación de red" (Network Authentication Enrollment) en la lista y asegúrate de que esté marcado. Si no está, selecciónalo y haz clic en "Aceptar" (OK).
  • Reinicia Syncthing y tu computadora.

Si esto no resuelve el problema, también puedes intentar reiniciar tu router o cambiar la configuración del firewall de Windows para permitir explícitamente las conexiones de Syncthing en la red local.

USO

¿Qué pasa si hay un conflicto?

Un conflicto ocurre cuando un archivo se modifica en dos dispositivos diferentes al mismo tiempo, o cuando un archivo se modifica en un dispositivo mientras se elimina en otro. Syncthing maneja los conflictos de la siguiente manera:

  • Archivo modificado en ambos: Syncthing conservará una versión del archivo y creará una nueva versión con un sufijo de conflicto (por ejemplo, `nombre_archivo.conflict-20230101-123456`). Puedes decidir cuál mantener manualmente.
  • Archivo modificado y eliminado: La modificación se conservará, y la eliminación se ignorará. Esto se debe a que la preservación de la versión modificada se considera más segura que eliminarla.

Para evitar conflictos, es recomendable minimizar las modificaciones simultáneas en el mismo archivo en diferentes dispositivos. Si es posible, deja que una sincronización se complete antes de realizar cambios en otro dispositivo.

¿Cómo sirvo una carpeta desde un sistema de archivos de solo lectura?

Syncthing puede servir carpetas desde sistemas de archivos de solo lectura, pero con limitaciones. Si una carpeta está marcada como "Solo envío" (Send Only), Syncthing no intentará escribir en ella.

Para configurar una carpeta como "Solo envío":

  • Edita la configuración de la carpeta en la GUI web de Syncthing.
  • En la sección "Modo de carpeta" (Folder Type), selecciona "Solo envío" (Send Only).
  • Guarda los cambios.

Con esta configuración, Syncthing leerá los archivos de la carpeta de solo lectura y los enviará a otros dispositivos, pero no intentará modificar o eliminar los archivos en esa carpeta.

Nota: Si necesitas que Syncthing también maneje la eliminación de archivos (por ejemplo, para que los archivos eliminados en otros dispositivos también se eliminen de la carpeta de solo lectura), entonces no podrás usar un sistema de archivos verdaderamente de solo lectura para esa carpeta. Necesitarás permisos de escritura, al menos para la eliminación.

Realmente odio el directorio .stfolder, ¿puedo eliminarlo?

No, el directorio `.stfolder` no se puede eliminar si quieres que Syncthing continúe gestionando la carpeta. Este directorio es esencial para que Syncthing identifique las carpetas que están bajo su control y para almacenar metadatos internos, como los archivos `.stignore` (para exclusiones de archivos) y `.stversions` (para versiones de archivos).

Si eliminas `.stfolder`, Syncthing perderá el rastro de la carpeta y podría intentar volver a sincronizarla desde cero o marcarla como desconectada.

Si el directorio te molesta visualmente, puedes ocultarlo en tu explorador de archivos. La mayoría de los sistemas operativos tienen una opción para mostrar u ocultar archivos y carpetas ocultos (que a menudo comienzan con un punto `.` en sistemas tipo Unix).

¿Puedo anidar carpetas compartidas en Syncthing?

Sí, puedes anidar carpetas compartidas en Syncthing. Sin embargo, hay algunas consideraciones importantes:

  • Compartir la carpeta externa: Si anidas una carpeta compartida (Carpeta B) dentro de otra carpeta compartida (Carpeta A), y ambas están configuradas en Syncthing, deberás asegurarte de que la Carpeta A esté también configurada y compartida. Syncthing gestionará ambas carpetas de forma independiente.
  • Evitar conflictos: Ten cuidado de no crear bucles de sincronización o conflictos. Por ejemplo, si compartes `/home/user/data` (Carpeta A) y también compartes `/home/user/data/projects` (Carpeta B), Syncthing podría tener problemas si un archivo en `projects` también está siendo gestionado por la sincronización de `data`. Generalmente, es mejor tener carpetas de sincronización separadas y no anidadas dentro de otras carpetas de sincronización, a menos que estés seguro de lo que estás haciendo.
  • Recomendación: Para una gestión más limpia, se recomienda no anidar carpetas compartidas de Syncthing dentro de otras carpetas compartidas de Syncthing. Es más sencillo tener carpetas de nivel superior para la sincronización.

¿Cómo renombro/muevo una carpeta sincronizada?

Renombrar o mover una carpeta sincronizada requiere un poco de cuidado para asegurar que Syncthing reconozca el cambio sin perder datos o causar conflictos.

Método recomendado:

  1. Detén Syncthing.
  2. Renombra o mueve la carpeta física en tu sistema de archivos a la nueva ubicación o con el nuevo nombre.
  3. Edita la configuración de Syncthing: Abre la GUI web de Syncthing y ve a la configuración de la carpeta que acabas de renombrar/mover. Haz clic en "Editar" y actualiza la ruta del "Directorio" a la nueva ubicación o el nuevo nombre de la carpeta. Guarda los cambios.
  4. Inicia Syncthing de nuevo.

Syncthing debería detectar el cambio de ruta y comenzar a sincronizar la carpeta en su nueva ubicación. Puede que necesite volver a escanear la carpeta para verificar la integridad de los archivos.

Alternativa (si el método anterior falla):

  1. Detén Syncthing.
  2. Elimina la carpeta de la lista en la GUI web de Syncthing (esto no borra los archivos físicos).
  3. Renombra o mueve la carpeta física.
  4. Agrega la carpeta de nuevo en la GUI web, apuntando a la nueva ubicación. Asegúrate de que el ID de la carpeta sea el mismo si deseas que se mantenga la configuración existente.
  5. Inicia Syncthing.

Precaución: Evita renombrar/mover archivos *dentro* de una carpeta sincronizada mientras Syncthing está ejecutándose si se van a realizar cambios significativos en otros dispositivos al mismo tiempo, ya que esto podría generar conflictos.

¿Cómo configuro varios usuarios en una sola máquina?

Syncthing está diseñado para ejecutarse una vez por usuario. Cada usuario que necesite usar Syncthing en la misma máquina debe tener su propia instancia de Syncthing ejecutándose.

Esto significa que cada usuario debe:

  • Instalar Syncthing (o tener acceso al ejecutable).
  • Ejecutar Syncthing desde su propia cuenta de usuario.
  • Tener su propia configuración y datos de Syncthing (generalmente en directorios como `~/.config/syncthing` en Linux/macOS o `%LOCALAPPDATA%\Syncthing` en Windows).
  • Compartir carpetas y dispositivos con otros usuarios de Syncthing según sea necesario.

Las carpetas sincronizadas por diferentes usuarios deben estar en ubicaciones distintas para evitar conflictos, a menos que se configure cuidadosamente la propiedad de los archivos y permisos.

En Linux, puedes usar `systemd --user` para gestionar instancias de Syncthing para cada usuario.

¿Syncthing soporta la sincronización entre carpetas en el mismo sistema?

Sí, Syncthing puede sincronizar carpetas dentro del mismo sistema. Para hacer esto, necesitarás dos instancias de Syncthing ejecutándose en el mismo sistema, cada una con su propia configuración y directorio de datos. Estas dos instancias se tratarán como dos dispositivos diferentes.

Pasos básicos:

  1. Configura la primera instancia de Syncthing (con su propia config y datos). Obtén su ID de dispositivo.
  2. Configura la segunda instancia de Syncthing (con su propia config y datos). Obtén su ID de dispositivo.
  3. Agrega el ID de dispositivo de la primera instancia a la segunda, y viceversa. Configura los pares para que se descubran mutuamente.
  4. Comparte la misma carpeta en ambas instancias. Por ejemplo, si quieres sincronizar `/ruta/carpeta1` y `/ruta/carpeta2`, comparte la misma carpeta (por ejemplo, `/ruta/carpeta1`) con ambas instancias. Ellas se sincronizarán entre sí.

Consideraciones:

  • **Evita la auto-sincronización:** No intentes sincronizar una carpeta consigo misma. Las dos instancias deben apuntar a carpetas diferentes que contienen los mismos datos que deseas sincronizar.
  • **Permisos y propiedad:** Asegúrate de que ambas instancias de Syncthing tengan los permisos necesarios para leer y escribir en ambas carpetas.
  • **Proceso de ejecución:** Necesitarás ejecutar dos instancias de Syncthing simultáneamente. Esto se puede hacer iniciando la segunda instancia desde la línea de comandos o configurando un segundo servicio/demonio si tu sistema lo soporta.

Cuando tengo dos carpetas distintas gestionadas por Syncthing en dos hosts, ¿cómo maneja Syncthing la acción de mover archivos entre ellas?

Syncthing no maneja directamente las operaciones de "mover" archivos entre carpetas diferentes (ni siquiera en el mismo host). Si mueves un archivo de la Carpeta A a la Carpeta B dentro de un mismo host, Syncthing lo interpretaría como:

  • Una eliminación en la Carpeta A.
  • Una adición (un nuevo archivo) en la Carpeta B.

Esto significa que el archivo se copiaría a la Carpeta B, y la versión original en la Carpeta A se eliminaría (si se configura así). Si la ovaná se mueve a otra máquina, el proceso sería similar entre las máquinas.

¿Cómo manejar esto de manera eficiente?

  • Recomendación: Si es posible, realiza la operación de mover directamente en uno de los dispositivos. Syncthing detectará la eliminación en la ubicación original y la adición en la nueva, y sincronizará el cambio. El algoritmo de Syncthing está diseñado para ser eficiente con estas operaciones (detecta que es un movimiento si las marcas de tiempo y tamaños son similares) y no debería requerir una resincronización completa del contenido del archivo.
  • Múltiples dispositivos: Si tienes que mover un archivo entre carpetas compartidas en diferentes dispositivos, el proceso sigue siendo el mismo. Realiza la operación de mover en uno de los dispositivos y Syncthing se encargará de replicarla en los demás.

Limitación: Syncthing no tiene una comprensión global de "mover" entre carpetas separadas. Simplemente observa los cambios en cada carpeta y los propaga. La eficiencia de la detección de movimientos depende de que los metadatos del archivo (tamaño, marca de tiempo) sean consistentes entre la eliminación y la adición.

¿Puedo ayudar en la sincronización inicial copiando archivos manualmente?

Sí, puedes pre-sembrar tus carpetas con archivos manualmente para acelerar la sincronización inicial. Este proceso se conoce comúnmente como "folder seeding" o "pre-seeding".

Pasos generales:

  1. Configura ambas carpetas en Syncthing (en diferentes dispositivos o instancias).
  2. Detén Syncthing en ambos dispositivos (o en el dispositivo de destino si solo copias manualmente).
  3. Copia manualmente todos los archivos y directorios de la carpeta fuente a la carpeta de destino. Asegúrate de copiar también los archivos ocultos (como `.stignore`).
  4. Asegúrate de que los permisos de archivo y las marcas de tiempo se conserven lo más posible durante la copia (herramientas como `rsync -a` son ideales para esto).
  5. Inicia Syncthing en ambos dispositivos.

Syncthing detectará que los archivos ya existen en el destino y comparará sus hashes. Solo necesitará descargar los bloques de archivo que faltan o son diferentes, lo que acelerará drásticamente el proceso de sincronización inicial.

Importante:

  • Si copias manualmente, es crucial que los archivos en el destino sean exactamente iguales (o al menos tengan los mismos metadatos) que en el origen para que Syncthing los reconozca como idénticos.
  • Para la primera sincronización, es una buena práctica configurar una de las carpetas como "Solo envío" (Send Only) hasta que la sincronización inicial se haya completado correctamente en el destino. Esto evita que Syncthing elimine archivos en el destino si detecta que faltan en el origen debido a errores de copia manual.

¿Es Syncthing mi aplicación de copia de seguridad ideal?

Syncthing no es una aplicación de copia de seguridad en el sentido tradicional. Su propósito principal es la **sincronización**: mantener los archivos idénticos en múltiples ubicaciones.

Si bien Syncthing tiene una función de "Versionado de archivos" que puede ayudar a recuperar versiones anteriores de archivos modificados o eliminados, no ofrece las características completas de una solución de copia de seguridad:

  • Copia de seguridad incremental/diferencial: Syncthing no realiza copias de seguridad incrementales o diferenciales eficientes del sistema completo.
  • Copia de seguridad fuera del sitio: Aunque puedes sincronizar con un dispositivo externo o en la nube, Syncthing no está diseñado inherentemente para copias de seguridad externas seguras y encriptadas.
  • Restauración granular del sistema: No puedes usar Syncthing para restaurar un sistema operativo completo o realizar una recuperación ante desastres a nivel de sistema.
  • Detección de corrupción: Si un archivo se corrompe en todos los dispositivos sincronizados, Syncthing propagará esa corrupción. Una copia de seguridad dedicada puede tener mecanismos para detectar y prevenir esto.

¿Cuándo usar Syncthing?

  • Para mantener tus archivos actualizados entre tus dispositivos (portátil, escritorio, teléfono).
  • Para compartir carpetas de forma segura con otros usuarios sin depender de servicios en la nube.
  • Como una capa de protección contra la pérdida accidental de archivos a nivel de dispositivo (gracias al versionado).

Recomendación:

Para una copia de seguridad robusta, considera usar herramientas dedicadas de copia de seguridad (como `borgbackup`, `restic`, `duplicity`, o soluciones comerciales) además de Syncthing. Usa Syncthing para la sincronización y las copias de seguridad para la protección de datos a largo plazo y recuperación ante desastres.

¿Cómo puedo excluir archivos con corchetes ([]) en el nombre?

Las reglas de exclusión de Syncthing usan el patrón de globos (globbing), que es similar a las expresiones regulares pero más simple. Los corchetes `[]` se usan para definir rangos de caracteres.

Si deseas excluir un archivo o directorio que contiene corchetes en su nombre, necesitas "escapar" los corchetes para que se interpreten literalmente y no como parte de un rango de caracteres.

Para excluir un archivo llamado `mi[archivo].txt`:

  • En tu archivo `.stignore` (o en la configuración de exclusión de la carpeta), usa el siguiente patrón: mi\[archivo].txt

El carácter de barra invertida `\` antes del corchete `[` le dice a Syncthing que trate el corchete como un carácter literal y no como el comienzo de una clase de caracteres.

Ejemplo:

Para excluir un archivo llamado `mi[archivo]con[varios]corchetes.doc` y un directorio llamado `[mi_directorio]`: 
mi\[archivo]con\[varios]corchetes.doc
\[mi_directorio]

¿Cómo accedo a la GUI web desde otra computadora?

Por defecto, la GUI web de Syncthing solo escucha en `127.0.0.1` (localhost), lo que significa que solo es accesible desde la misma máquina donde se está ejecutando Syncthing.

Para acceder a la GUI web desde otra computadora en tu red local:

  1. Edita la configuración de Syncthing:
    • Ve a la configuración de Syncthing (haz clic en el botón de engranaje en la GUI web).
    • En la sección "Interfaz de usuario web" (Web GUI), cambia la dirección de la GUI web (Address).
    • Para que sea accesible desde cualquier IP en tu red local, puedes establecerla en `0.0.0.0:8384` (o el puerto que estés usando). Si solo quieres permitir acceso desde IPs específicas, puedes listarlas.
    • También es importante configurar el campo "Lista blanca de hosts" (Host Whitelist) para incluir la(s) dirección(es) IP de las computadoras desde las que deseas acceder a la GUI. Por ejemplo, si quieres acceder desde `192.168.1.100`, agrega esa IP a la lista blanca.
  2. Guarda los cambios. Es posible que necesites reiniciar Syncthing para que los cambios surtan efecto.
  3. Accede desde otra computadora: Abre un navegador web en la otra computadora y navega a `http://:8384`, reemplazando `` con la dirección IP real de la máquina donde se está ejecutando Syncthing.

Seguridad:

Exponer la GUI web a la red puede ser un riesgo de seguridad si tu red no es confiable. Asegúrate de proteger tu GUI web con una contraseña fuerte y considera usar un túnel seguro (como SSH) si accedes a ella desde fuera de tu red local.

No me gusta la GUI ni el tema. ¿Se puede cambiar?

La interfaz gráfica de usuario (GUI) de Syncthing es principalmente una aplicación web. Si bien no hay opciones integradas para cambiar radicalmente la apariencia o el tema de la GUI principal, hay algunas maneras de personalizarla o utilizar interfaces alternativas:

  • Temas personalizados (limitado): En algunas versiones o con ciertos ajustes, podrías ser capaz de inyectar CSS personalizado para modificar la apariencia. Sin embargo, esto no es una característica oficial y puede romperse con las actualizaciones.
  • Alternativas de GUI: Existen interfaces de usuario de terceros diseñadas para interactuar con la API de Syncthing. Algunas pueden ofrecer diferentes enfoques de diseño o características adicionales. Busca "Syncthing GUI alternatives" en línea para encontrar opciones.
  • Interfaz de Línea de Comandos (CLI): Si prefieres una interfaz sin GUI, puedes controlar Syncthing completamente a través de su API y herramientas de línea de comandos.
  • Aplicaciones Móviles: Si bien no es la GUI web principal, las aplicaciones móviles de Syncthing (como las mencionadas en la sección de iOS) tienen sus propias interfaces de usuario.

En general, la GUI web está diseñada para ser funcional y directa. Si buscas una personalización visual profunda, es posible que debas explorar interfaces de terceros o herramientas de línea de comandos.

¿Cómo ejecuto Syncthing como un proceso demonio en Linux?

La forma recomendada de ejecutar Syncthing como un demonio en Linux es utilizando `systemd`. La mayoría de las distribuciones modernas de Linux vienen con `systemd` instalado.

Para el usuario actual (recomendado):

  1. Crea un archivo de unidad `systemd` para el usuario: mkdir -p ~/.config/systemd/user nano ~/.config/systemd/user/syncthing.service
  2. Pega el siguiente contenido en el archivo `syncthing.service` (ajusta `User` y `Group` si es necesario, aunque para el servicio de usuario normalmente no es necesario): 
    [Unit]
Description=Syncthing - Open security and privacy-focused file synchronization
Documentation=man:syncthing(1)
After=network.target

[Service]
ExecStart=/usr/bin/syncthing -no-browser -home="~/.config/syncthing"
Restart=on-failure
RestartSec=10

# If you want to enable the GUI to be accessible from the network, uncomment these lines:
# Environment="STGUIADDRESS=0.0.0.0:8384"
# Environment="STGUIHOSTWHITELIST=127.0.0.1, TU_IP_DE_RED"

[Install]
Gettext-package = syncthing
  3. Habilita y inicia el servicio: systemctl --user enable syncthing.service systemctl --user start syncthing.service
  4. Verifica el estado: systemctl --user status syncthing.service
  5. Para ver los registros: journalctl --user -u syncthing.service -f

Para ejecutar como root (menos recomendado):

Si necesitas ejecutar Syncthing como root (por ejemplo, para acceder a carpetas del sistema), puedes crear un archivo de unidad `systemd` en `/etc/systemd/system/` y habilitarlo globalmente. Sin embargo, es mucho más seguro ejecutar Syncthing como un usuario no privilegiado.

Nota: Asegúrate de que la ruta a `syncthing` (`/usr/bin/syncthing` en el ejemplo) sea correcta para tu sistema.

¿Cómo aumento el límite de inotify para que mi vigilante del sistema de archivos funcione?

En Linux, Syncthing utiliza el subsistema `inotify` del kernel para detectar cambios en los archivos y directorios en tiempo real. El kernel de Linux tiene un límite en la cantidad de eventos `inotify` que se pueden monitorear simultáneamente. Si trabajas con muchos archivos o directorios, es posible que alcances este límite, lo que puede hacer que el vigilante de archivos de Syncthing no funcione correctamente (es decir, los cambios no se sincronizan de inmediato).

Para aumentar el límite de `inotify`, necesitas modificar los parámetros del kernel. Esto generalmente requiere privilegios de administrador (`root`).

Pasos para aumentar el límite de `inotify` (temporalmente):

  • Ejecuta el siguiente comando como root: sudo sysctl fs.inotify.max_user_watches=1048576 (Este valor `1048576` es un ejemplo; puedes ajustarlo según sea necesario. Un valor común es `524288` o `1048576`).

Pasos para aumentar el límite de `inotify` (permanentemente):

  • Edita el archivo de configuración de `sysctl`. Crea o edita `/etc/sysctl.d/99-syncthing.conf` (el nombre del archivo puede variar, pero debe terminar en `.conf`).
  • Agrega la siguiente línea al archivo: fs.inotify.max_user_watches=1048576
  • Para aplicar los cambios sin reiniciar, ejecuta: sudo sysctl --system

Verificar el límite actual:

  • Ejecuta: sysctl fs.inotify.max_user_watches

Después de aumentar el límite, reinicia Syncthing para que utilice la nueva configuración.

¿Cómo restablezco la contraseña de la GUI?

Si olvidaste la contraseña de la GUI web de Syncthing o necesitas restablecerla, puedes hacerlo modificando el archivo de configuración de Syncthing.

Advertencia: Esto requiere detener Syncthing y editar su archivo de configuración.

Pasos:

  1. Detén Syncthing. Asegúrate de que el proceso no esté en ejecución.
  2. Localiza el archivo de configuración de Syncthing. La ubicación varía según el sistema operativo:
    • Linux: ~/.config/syncthing/config.xml
    • Windows: %LOCALAPPDATA%\Syncthing\config.xml
    • macOS: ~/Library/Application Support/Syncthing/config.xml
  3. Edita el archivo `config.xml` con un editor de texto.
  4. Busca la sección ``. Dentro de ella, encontrarás una línea similar a: <password>hash_de_tu_contraseña</password>
  5. Para restablecer la contraseña, simplemente elimina la línea completa: <password>hash_de_tu_contraseña</password>
  6. Guarda el archivo `config.xml`.
  7. Inicia Syncthing de nuevo.

Después de reiniciar Syncthing, podrás acceder a la GUI web sin necesidad de contraseña. Se te pedirá que establezcas una nueva contraseña la próxima vez que intentes acceder a la GUI, o puedes configurarla manualmente en la configuración de la GUI.

El directorio .stfolder

Syncthing usa un pequeño archivo/directorio llamado .stfolder para indicar que una carpeta compartida está presente y saludable en el disco. Esto es para asegurar que su carpeta sea legible y esté presente en el disco. Por ejemplo, si usted remueve una unidad USB de su computadora o desmonta un sistema de archivos, entonces Syncthing debe saber si usted realmente ha eliminado todos sus archivos. Por lo tanto, Syncthing siempre verifica que .stfolder esté presente.

Cuando aparece este error, Syncthing asume que la carpeta ha encontrado algún tipo de error y dejará de sincronizarla hasta que .stfolder reaparezca. Una vez que esto suceda, todos los cambios realizados en la carpeta localmente serán sincronizados (es decir, los archivos faltantes serán considerados eliminaciones).

  • Si recibe este mensaje de error, verifique la carpeta en cuestión en su almacenamiento. Si ha desmontado la carpeta (o una de sus superordinadas), debe volver a montarla para que Syncthing reanude la sincronización de esta carpeta.
  • Si ha movido la carpeta, debe moverla de regreso a su ubicación original, o eliminar la carpeta desde la interfaz de usuario de Syncthing y volver a agregarla en su nueva ubicación.
  • Si la carpeta está presente en el disco, con todos sus archivos y directorios hijos, pero .stfolder todavía falta:

    Es posible que un software de limpieza de archivos haya eliminado .stfolder. Algunos programas eliminan carpetas vacías, y .stfolder a menudo está vacío. Esto sucede con particular frecuencia en Android. Para remediarlo, recree .stfolder y agregue un archivo ficticio en él, o agregue una excepción a su software de limpieza.

Si aún no está seguro de lo que ha sucedido, puede eliminar la carpeta desde la interfaz de usuario de Syncthing y volver a agregarla en la misma ubicación. Esto hace que Syncthing intente una recreación automática de .stfolder. Luego, también restablecerá el estado de la base de datos de esta carpeta. Será considerada una carpeta “nueva”, lo que significa que sus archivos se fusionarán con los archivos de los dispositivos remotos.

Consulte también el FAQ de marcadores para obtener más información sobre el marcador de carpeta.

¿Por qué mis computadoras con Windows siempre se conectan a través de un relé?

Al conectarse a una red nueva, Windows establece por defecto su perfil en “Pública”. Si bien es más seguro, esta configuración generalmente impide que aplicaciones como Syncthing puedan establecer conexiones directas con el dispositivo en cuestión, obligándolo a conectarse a través de un relé. Si prefiere conectar sus dispositivos directamente, siga las instrucciones oficiales de Microsoft sobre cómo cambiar el perfil de red a “Privada” https://support.microsoft.com/windows/essential-network-settings-and-tasks-in-windows-f21a9bbc-c582-55cd-35e0-73431160a1b9#bkmk_network_profile.

Cambios en conflicto

¿Cómo comparto una carpeta desde un sistema de archivos de solo lectura?

Syncthing requiere un “marcador de carpeta” para indicar que la carpeta está presente y es saludable. Por defecto, es un directorio llamado .stfolder que Syncthing crea cuando se agrega la carpeta. Si esta carpeta no se puede crear (está compartiendo archivos desde un CD o algo similar), puede establecer la opción avanzada de configuración Nombre del marcador al nombre de algún archivo o carpeta que sepa que siempre existirá en la carpeta.

Realmente odio el directorio .stfolder, ¿puedo eliminarlo?

Consulte la pregunta anterior.

¿Puedo anidar carpetas compartidas en Syncthing?

Compartir una carpeta que está dentro de una carpeta ya compartida es posible, pero tiene sus advertencias. Lo que debe evitar absolutamente son las carpetas circulares. Este es solo un ejemplo, puede haber otros efectos indeseados. Anidar carpetas compartidas no está soportado, recomendado ni programado para ello, pero se puede hacer con éxito si sabe lo que está haciendo; se le ha advertido.

¿Cómo renombro/muevo una carpeta sincronizada?

Syncthing no tiene una forma directa de hacer esto, ya que puede ser peligroso hacerlo si no se tiene cuidado; puede resultar en pérdida de datos si algo sale mal durante la mudanza y se sincroniza con sus otros dispositivos.

La forma sencilla de renombrar o mover una carpeta sincronizada en el sistema local es eliminar la carpeta en la interfaz de usuario de Syncthing, moverla en el disco, y luego volver a agregarla usando la nueva ruta.

Es importante hacer esto cuando la carpeta ya está sincronizada entre sus dispositivos, ya que de lo contrario es impredecible qué cambios “ganarán” después de la mudanza. Los cambios realizados en otros dispositivos pueden sobrescribirse, o los cambios realizados localmente pueden ser sobrescritos por los de otros dispositivos.

Una forma alternativa es detener Syncthing, mover la carpeta en el disco (incluyendo el marcador .stfolder), editar la ruta directamente en config.xml en la carpeta de configuración (ver Configuración de Syncthing) y luego reiniciar Syncthing.

¿Cómo configuro múltiples usuarios en una sola máquina?

Cada usuario debe ejecutar su propia instancia de Syncthing. Tenga en cuenta que es posible que necesite configurar los puertos de escucha para que no se superpongan (ver Configuración de Syncthing).

¿Syncthing soporta la sincronización entre carpetas en el mismo sistema?

Cuando tengo dos carpetas distintas gestionadas por Syncthing en dos hosts, ¿cómo maneja Syncthing la mudanza de archivos entre ellas?

Syncthing no maneja especialmente este caso, y lo más probable es que la mayoría de los archivos se vuelvan a descargar.

En detalle, el comportamiento depende del orden de escaneo. Si tiene las carpetas A y B, y mueve archivos de A a B, si A se escanea primero, anunciará la eliminación de los archivos a otros, quienes luego eliminarán los archivos. Al volver a escanear B, B anunciará la adición de nuevos archivos, y los pares remotos no tendrán de dónde obtenerlos aparte de volver a descargarlos.

Si B se escanea primero, B anunciará primero las adiciones, y los pares remotos reconstruirán los archivos (no renombrarán, más bien copiarán bloque por bloque) desde A, y luego, al escanearse A nuevamente, eliminará los archivos de A.

Una solución sería copiar primero de A a B, escanear B, esperar a que B copie los archivos en el lado remoto, y luego eliminar de A.

¿Puedo ayudar a la sincronización inicial copiando archivos manualmente?

Si tiene una carpeta grande que desea mantener sincronizada a través de una red no tan rápida, y tiene la posibilidad de mover todos los archivos al dispositivo remoto de manera más rápida, aquí hay un procedimiento a seguir:

  • Cree la carpeta en el dispositivo local, pero aún no la comparta con el dispositivo remoto.
  • Copie los archivos del dispositivo local al dispositivo remoto usando copia de archivos normal. Si esto toma mucho tiempo (quizás requiera viajar físicamente), puede ser una buena idea asegurarse de que los archivos en el dispositivo local no se actualicen mientras hace esto.
  • Cree la carpeta en el dispositivo remoto y copie el ID de Carpeta de la carpeta en el dispositivo local, ya que queremos que las carpetas se consideren las mismas. Luego espere hasta que el escaneo de la carpeta se complete.
  • Ahora comparta la carpeta con el otro dispositivo, en ambos lados. Syncthing intercambiará información de archivos, actualizando la base de datos, pero los archivos existentes no se transferirán. Esto aún puede tomar un tiempo inicialmente, tenga paciencia y espere hasta que se asiente.

¿Es Syncthing mi aplicación de respaldo ideal?

No. Syncthing no es una gran aplicación de respaldo porque todos los cambios en sus archivos (modificaciones, eliminaciones, etc.) se propagarán a todos sus dispositivos. Puede habilitar el versionado, pero le animamos a utilizar otras herramientas para mantener sus datos a salvo de nuestros (o sus) errores.

¿Cómo puedo excluir archivos con corchetes ([]) en el nombre?

Los patrones en .stignore son patrones glob, donde los corchetes se usan para denotar rangos de caracteres. Es decir, el patrón q[abc]x coincidirá con los archivos qax, qbx y qcx.

Para coincidir con un archivo real llamado q[abc]x, el patrón necesita “escapar” los corchetes, de esta manera: q\[abc\]x.

En Windows, use el carácter | para escapar los corchetes (q|[abc|]x), ya que el carácter \ se usa como separador de ruta

How do I access the web GUI from another computer?

The default listening address is 127.0.0.1:8384, so you can only access the GUI from the same machine. This is for security reasons. To access it from another computer, change the GUI listen address option in the web GUI from 127.0.0.1:8384 to 0.0.0.0:8384, or change the config.xml:

<gui enabled="true" tls="false">
  <address>127.0.0.1:8384</address>

to

<gui enabled="true" tls="true">
  <address>0.0.0.0:8384</address>

Then the GUI is accessible from everywhere. There is no filtering based on e.g. source address (use a firewall for that). You should set a password and enable HTTPS with this configuration. You can do this from inside the GUI.

If both your computers are Unix-like (Linux, Mac, etc.) you can also leave the GUI settings at default and use an SSH port forward to access it. For example,

$ ssh -L 9090:127.0.0.1:8384 user@othercomputer.example.com

will log you into othercomputer.example.com, and present the remote Syncthing GUI on http://localhost:9090 on your local computer.

If you only want to access the remote GUI and don’t want the terminal session, use this example:

$ ssh -N -L 9090:127.0.0.1:8384 user@othercomputer.example.com

If only your remote computer is Unix-like, you can still access it with SSH from Windows. Under Windows 10 or later you can use the same ssh command if you install the OpenSSH Client <https://learn.microsoft.com/windows-server/administration/openssh/openssh_install_firstuse>.

I don’t like the GUI or the theme. Can it be changed?

You can change the theme in the settings. Syncthing ships with other themes than the default.

If you want a custom theme or a completely different GUI, you can add your own. By default, Syncthing will look for a directory gui inside the Syncthing home folder. To change the directory to look for themes, you need to set the STGUIASSETS environment variable. To get the concrete directory, run syncthing with the --paths parameter. It will print all the relevant paths, including the “GUI override directory”.

To add e.g. a red theme, you can create the file red/assets/css/theme.css inside the GUI override directory to override the default CSS styles.

To create a whole new GUI, you should checkout the files at https://github.com/syncthing/syncthing/tree/main/gui/default to get an idea how to do that.

How do I upgrade Syncthing?

If you use a package manager such as Debian’s apt-get, you should upgrade using the package manager. If you use the binary packages linked from Syncthing.net, you can use Syncthing’s built-in automatic upgrade functionality.

  • If automatic upgrades is enabled (which is the default), Syncthing will upgrade itself automatically within 24 hours of a new release.
  • The upgrade button appears in the web GUI when a new version has been released. Pressing it will perform an upgrade.
  • To force an upgrade from the command line, run syncthing --upgrade.

Note that your system should have CA certificates installed which allows a secure connection to GitHub (e.g. FreeBSD requires sudo pkg install ca_root_nss). If curl or wget works with normal HTTPS sites, then so should Syncthing.

Where do I find the latest release?

We release new versions through GitHub. The latest release is always found on the release page <https://github.com/syncthing/syncthing/releases/latest>. Unfortunately GitHub does not provide a single URL to automatically download the latest version. We suggest to use the GitHub API <https://api.github.com/repos/syncthing/syncthing/releases/latest> and parsing the JSON response.

How do I run Syncthing as a daemon process on Linux?

If you’re using systemd, runit, or upstart, we ship example configurations <https://github.com/syncthing/syncthing/tree/main/etc>.

If however you’re not using one of these tools, you have a couple of options. If your system has a tool called start-stop-daemon installed (that’s the name of the command, not the package), look into the local documentation for that, it will almost certainly cover 100% of what you want to do. If you don’t have start-stop-daemon, there are a bunch of other software packages you could use to do this. The most well known is called daemontools, and can be found in the standard package repositories for almost every modern Linux distribution. Other popular tools with similar functionality include S6 and the aforementioned runit.

How do I increase the inotify limit to get my filesystem watcher to work?

You are probably reading this because you encountered the following error with the filesystem watcher on linux:

Failed to start filesystem watcher for folder yourLabel (yourID): failed to set up inotify handler. Please increase inotify limits, see https://docs.syncthing.net/users/faq.html#inotify-limits

Linux typically restricts the number of watches per user (usually 8192). If you have many directories, you will need to adjust that number.

On many Linux distributions you can run the following to fix it:

echo "fs.inotify.max_user_watches=204800" | sudo tee -a /etc/sysctl.conf

On Arch Linux and potentially others it is preferred to write this line into a separate file, i.e. you should run:

echo "fs.inotify.max_user_watches=204800" | sudo tee -a /etc/sysctl.d/90-override.conf

This only takes effect after a reboot. To adjust the limit immediately, run:

echo 204800 | sudo tee /proc/sys/fs/inotify/max_user_watches

How do I reset the GUI password?

If you’ve forgotten / lost the GUI password, you can reset it using the --gui-password (and possibly --gui-user) options to the syncthing generate subcommand. This should be done while Syncthing is not running.

1.
Stop Syncthing: syncthing cli operations shutdown
2.
syncthing generate --gui-password=myNewPassword --gui-user=newUserName
3.
Restart Syncthing as usual.

Alternatively, in step 2, you can manually delete the <user> and <password> XML tags from the <gui> block in file config.xml. The location of the file depends on the OS and is described in the configuration documentation.
