NOMBRE

systemd-bless-boot.service, systemd-bless-boot - Marcar el proceso de arranque actual como exitoso

SINOPSIS

systemd-bless-boot.service

/usr/lib/systemd/systemd-bless-boot

DESCRIPCIÓN

systemd-bless-boot.service es un servicio del sistema que marca el proceso de arranque actual como exitoso. Se integra automáticamente en la transacción inicial cuando systemd-bless-boot-generator(8) detecta que se está utilizando el conteo de arranque estilo systemd-boot(7).

Internamente, el servicio opera basándose en la variable EFI LoaderBootCountPath (del UUID de proveedor 4a67b082-0a4c-41cf-b6c7-440b29bb8c4f), que se pasa desde el gestor de arranque al SO. Contiene una ruta de sistema de archivos (relativa a la partición del sistema EFI) del archivo de entrada del gestor de arranque compatible con la Especificación del Gestor de Arranque[1] o del archivo de imagen del kernel unificado que se utilizó para arrancar el sistema. systemd-bless-boot.service elimina los dos contadores numéricos de arranque "intentos realizados" y "intentos restantes" del nombre del archivo, lo que indica a futuras invocaciones del gestor de arranque que la entrada ha completado el arranque con éxito al menos una vez. (Este servicio, por lo tanto, cambiará el nombre del archivo de entrada del gestor de arranque o la imagen del kernel unificado en el primer arranque exitoso).

OPCIONES

El ejecutable /usr/lib/systemd/systemd-bless-boot también puede ser invocado desde la línea de comandos, tomando uno de los siguientes argumentos:

status

Se muestra el estado actual del archivo de entrada del gestor de arranque o de la imagen del kernel unificado. Esto produce una de las siguientes salidas: "good", "bad", "indeterminate", "clean", "dirty", dependiendo del estado e invocaciones previas del comando. La cadena "indeterminate" se muestra inicialmente después del arranque, antes de que se marque como "good" o "bad". La cadena "good" se muestra después de que el arranque se marcó como "good" con el comando good a continuación, y "bad" inversamente después de que se invocó el comando bad. La cadena "clean" se devuelve cuando el conteo de arranque no está activo en ese momento (lo que incluye el caso en que la entrada actual ya se marcó como persistentemente buena). La cadena "dirty" se devuelve cuando el sistema se arranca con un kernel conocido como defectuoso (es decir, uno en el que el contador de intentos restantes ya ha llegado a cero anteriormente).

Añadido en la versión 240.

good

Cuando se invoca, el archivo de entrada del gestor de arranque actual o la imagen del kernel unificado se marcará como "good" (bueno), ejecutando la operación de cambio de nombre de archivo descrita anteriormente. Este comando está diseñado para ser invocado al final de un arranque exitoso. La unidad systemd-bless-boot.service invoca este comando.

Añadido en la versión 240.

bad

Cuando se llama, el contador de "intentos restantes" en el nombre del archivo de entrada del gestor de arranque o en el nombre del archivo de imagen del kernel unificado se establece en cero, marcando la entrada del gestor de arranque o la imagen del kernel como "bad" (mala), para que el gestor de arranque no la tenga en cuenta en arranques futuros (al menos mientras haya otras entradas disponibles que aún no estén marcadas como "bad"). Este comando normalmente no se ejecuta, pero puede usarse para poner fin instantáneamente a la lógica de conteo de arranques si se detecta un problema y marcar de forma persistente la entrada de arranque como mala.

Añadido en la versión 240.

indeterminate

Este comando deshace cualquier marcado de la entrada actual del gestor de arranque o de la imagen del kernel unificado como buena o mala. Esto se implementa cambiando el nombre del archivo de entrada del gestor de arranque o de la imagen del kernel unificado de vuelta a la ruta codificada en la variable EFI LoaderBootCountPath. Tenga en cuenta que la operación fallará si el kernel actual no se arranca con el conteo de arranque habilitado (es decir, si la variable EFI no está configurada). Si el contador de intentos restantes ya alcanzó cero en un arranque anterior, esta operación también fallará: una vez que una entrada se marca como bad, solo se puede restablecer a good (bueno), pero no a indeterminate (indeterminado).

Añadido en la versión 240.
