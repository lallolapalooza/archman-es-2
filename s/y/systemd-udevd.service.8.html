NOMBRE

systemd-udevd.service, systemd-udevd-control.socket, systemd-udevd-kernel.socket, systemd-udevd-varlink.socket, systemd-udevd - Daemon de gestión de eventos de dispositivos

SINOPSIS

systemd-udevd.service

systemd-udevd-control.socket

systemd-udevd-kernel.socket

systemd-udevd-varlink.socket

/usr/lib/systemd/systemd-udevd [--daemon] [--debug] [--children-max=] [--exec-delay=] [--event-timeout=] [--resolve-names=early|late|never] [--version] [--help]

DESCRIPCIÓN

systemd-udevd escucha los uevents del kernel. Para cada evento, systemd-udevd ejecuta las instrucciones coincidentes especificadas en las reglas de udev. Véase udev(7).

El comportamiento del daemon se puede configurar usando udev.conf(5), sus opciones de línea de comandos, variables de entorno, y en la línea de comandos del kernel, o se puede cambiar dinámicamente con udevadm control.

OPCIONES

-d, --daemon

Se desprende y se ejecuta en segundo plano.

Añadido en la versión 186.

-D, --debug

Imprime mensajes de depuración en la salida estándar de errores.

Añadido en la versión 186.

-c, --children-max=

Limita el número de eventos ejecutados en paralelo.

Añadido en la versión 186.

-e, --exec-delay=

Retrasa la ejecución de cada parámetro RUN{programa} por el número dado de segundos. Esta opción puede ser útil al depurar bloqueos del sistema durante el arranque en frío causados por la carga de módulos del kernel que no funcionan.

Añadido en la versión 186.

-t, --event-timeout=

Establece el número de segundos a esperar a que finalicen los eventos. Después de este tiempo, el evento se terminará. El valor por defecto es 180 segundos.

Añadido en la versión 216.

-s, --timeout-signal=

Establece la señal que systemd-udevd enviará a los procesos derivados después de alcanzar el tiempo de espera del evento. La configuración puede ser anulada en el arranque con la opción de línea de comandos del kernel udev.timeout_signal=. Configurar a SIGABRT puede ser útil para depurar tiempos de espera de los trabajadores. Por defecto es SIGKILL. Tenga en cuenta que establecer la opción en la línea de comandos anula la configuración del archivo de configuración.

Añadido en la versión 246.

-N, --resolve-names=

Especifica cuándo systemd-udevd debe resolver los nombres de usuarios y grupos. Cuando se establece en early (el valor por defecto), los nombres se resolverán al analizar las reglas. Cuando se establece en late, los nombres se resolverán para cada evento. Cuando se establece en never, los nombres nunca se resolverán y todos los dispositivos serán propiedad de root.

Añadido en la versión 186.

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.

Añadido en la versión 246.

udev.blockdev_read_only, rd.udev.blockdev_read_only

Si se especifica, marca todos los dispositivos de bloque físicos como de solo lectura a medida que aparecen. Los dispositivos de bloque sintéticos (como los dispositivos de bucle o los dispositivos de mapeo de dispositivos) se dejan como están. Esto es útil para garantizar que el contenido de los dispositivos de bloque físicos permanezca sin modificaciones durante el tiempo de ejecución, por ejemplo, para implementar sistemas completamente sin estado, para pruebas o para situaciones de recuperación en las que los sistemas de archivos dañados no se dañen más por modificaciones accidentales.

Un dispositivo de bloque puede ser marcado de nuevo como escribible emitiendo el comando blockdev --setrw, véase blockdev(8) para más detalles.

net.ifnames=

Las interfaces de red se renombra para darles nombres predecibles cuando sea posible. Está habilitado por defecto; especificar 0 lo deshabilita.

Añadido en la versión 199.

net.naming_scheme=

Las interfaces de red se renombra para darles nombres predecibles cuando sea posible (a menos que se especifique net.ifnames=0, ver arriba). Con esta opción de línea de comandos del kernel, es posible elegir una versión específica de este algoritmo y anular la predeterminada elegida en tiempo de compilación. Espera uno de los identificadores de esquema de nombres listados en systemd.net-naming-scheme(7), o "latest" para seleccionar el esquema más reciente conocido (para esta versión particular de systemd-udevd.service).

Tenga en cuenta que seleccionar un esquema específico no es suficiente para estabilizar completamente el nombramiento de interfaces: el nombramiento se deriva generalmente de atributos del controlador expuestos por el kernel. A medida que el kernel se actualiza, los atributos previamente faltantes que systemd-udevd.service está comprobando podrían aparecer, lo que también afecta a los algoritmos de derivación de nombres más antiguos.

Añadido en la versión 240.

net.ifname_policy=policy1[,policy2,...][,MAC]

Especifica las políticas de nomenclatura aplicadas al renombrar interfaces de red. Toma una lista de políticas y una dirección MAC opcional separada por comas. Cada valor de política debe ser una de las políticas entendidas por la configuración NamePolicy= en los archivos .link, por ejemplo, "onboard" o "path". Véase systemd.link(5) para más detalles. Cuando se especifica la dirección MAC, las políticas se aplican a la interfaz que tiene la dirección. Cuando no se especifica ninguna dirección MAC, las políticas se aplican a todas las interfaces. Este argumento de línea de comandos del kernel se puede especificar varias veces.

Este argumento no es leído directamente por systemd-udevd, sino que es convertido a un archivo .link por systemd-network-generator.service(8). Para que este argumento tenga efecto, systemd-network-generator.service debe estar habilitado.

[Link]

NAME

systemd-udevd.service, systemd-udevd — event driven device initialization

SYNOPSIS

                        systemd-udevd.service
                        systemd-udevd()

DESCRIPTION

systemd-udevd is the event driven device initialization system. It receives device events from the kernel, processes them according to rules specified in udev.conf(5) and udev.rules(7), and dispatches events to other daemons and clients.

The systemd-udevd.service unit activates the systemd-udevd daemon.

systemd-udevd is responsible for managing the device nodes in /dev/, setting device-specific environment variables, and running configured programs when devices are added, removed, or change state.

It multiplexes access to the kernel's device event mechanism via netlink(7) sockets. It receives events, parses the device attributes, matches them against a set of rules, and then performs actions based on the matching rules.

The rules are processed in the order they are defined in the rule files. The rule files are:

  • /etc/udev/rules.d/, /run/udev/rules.d/, /usr/lib/udev/rules.d/

All files are sorted by their filename lexicographically. Directories have a higher priority than symbolic links, and files have a higher priority than directories. If two files have the same name, the one in the directory with the higher priority wins.

Rule files typically end with the suffix .rules.
