FBB::SyslogBuf(3bobcat) Buffer de flujo para Syslog FBB::SyslogBuf(3bobcat)

NOMBRE

FBB::SyslogBuf - Un objeto streambuf que inserta mensajes syslog

SINOPSIS

#include <bobcat/syslogbuf>
Opción de enlace: -lbobcat

DESCRIPCIÓN

Las direcciones de los objetos FBB::SyslogBuf se pueden pasar como direcciones std::streambuf a objetos std::ostream para escribir mensajes al demonio syslog utilizando las facilidades de flujo.

Se pueden usar múltiples inserciones separadas para crear un solo mensaje syslog: el mensaje solo se envía al demonio syslog después de recibir un comando de flush (por ejemplo, después de insertar std::flush o std::endl). Los caracteres no imprimibles (como ’\n’) aparecen en el mensaje syslog como valores octales, precedidos por # (por ejemplo, #012 para ’\n’). El salto de línea normalmente insertado por std::endl se ignora: los objetos SyslogStream interpretan std::endl como std::flush.

Una serie de inserciones puede contener múltiples manipuladores std::endl o std::flush. En cada uno de estos manipuladores se envía un nuevo mensaje al demonio syslog, que contiene toda la información que se ha almacenado en el búfer hasta el momento. Después de enviar un mensaje al demonio syslog, el búfer interno de SyslogStream se limpia.

PriorityType:

Esta enumeración tiene dos valores que ajustan el tipo de mensajes que son realmente procesados por el demonio syslog:

CONSTRUCTOR

o
SyslogBuf(string const &ident = "", FBB::Priority priority = FBB::NOTICE, FBB::Facility facility = FBB::USER, int option = 0):
El parámetro ident es usualmente el nombre del programa. Su contenido se antepone a los mensajes syslog.
El parámetro priority determina la importancia por defecto del mensaje enviado al demonio syslog. Por defecto, los mensajes se envían al demonio syslog con prioridad FBB::NOTICE. Los mensajes syslog pueden tener una prioridad diferente al insertar un manipulador SyslogStream(3bobcat). La prioridad establecida en el momento de la construcción también puede modificarse utilizando los miembros setPriority y setDefaultPriority.
Qué mensajes aparecen realmente en las instalaciones de registro no lo determinan las prioridades de los mensajes, sino la máscara de registro de syslog. La máscara de registro se puede establecer mediante el miembro estático setMask (ver abajo).
El parámetro facility determina el tipo de programa que realiza el registro. Por defecto se utiliza FBB::USER.
El parámetro option se puede usar para especificar varias opciones (use el operador binario `bitor` (`|`) para combinar opciones):
LOG_CONS: escribir directamente en la consola del sistema si hay un error al enviar al registrador del sistema
LOG_NDELAY: abrir la conexión inmediatamente (normalmente, la conexión se abre cuando se registra el primer mensaje)
LOG_PERROR: imprimir también en stderr
LOG__PID: incluir el PID con cada mensaje
Por defecto no se utilizan opciones.

Los constructores de copia y movimiento (y operadores de asignación) no están disponibles.

SyslogBuf():

Priority priority() const:
Returns the current message priority. This is the priority that will be used for the next message sent to the syslog daemon unless modified by setPriority or setDefaultPriority.
o
void open(char const *ident, int option, int facility):
Opens a connection to the syslog daemon. The ident, option, and facility arguments specify how messages are to be logged. The ident argument is a string that is prepended to every message. If the ident is NULL, the program name is used. The option argument is an integer formed by ORing together the available options. The facility argument specifies the default facility code if none is explicitly provided by the message itself.
o
void open(char const *ident, int option):
Opens a connection to the syslog daemon using the default facility (LOG_USER).
o
void open(char const *ident):
Opens a connection to the syslog daemon using the default facility (LOG_USER) and options (LOG_PID).
o
void open():
Opens a connection to the syslog daemon using the default facility (LOG_USER), options (LOG_PID), and ident (the program name).
o
int close():
Closes the connection to the syslog daemon. Returns 0 on success, or -1 if openlog(3) had not been called.
o
int flush():
Sends any buffered message to the syslog daemon. Returns 0 on success, or -1 if openlog(3) had not been called.
o
void end():
Flushes any buffered message to the syslog daemon, and then closes the connection. It is called implicitly when the SyslogBuf object is destroyed.
o
Priority setDefaultPriority(Priority priority):
Changes the default priority of the next message that is sent to the syslog daemon after inserting std::eoln or std::flush. The previously active default priority is returned.
o
Priority setPriority(Priority priority):
Changes the priority for the next message that is sent to the syslog daemon after inserting std::eoln or std::flush. Subsequent messages will again use the default priority. The previously active priority setting is returned.

MANIPULATOR

o
FBB::eoi:
The eoi manipulator can be inserted into the ostream instead of calling the SyslogBuf::end member. It performs the same actions as the eoi member. If inserted into a plain std::ostream nothing happens.

EXAMPLE

See also syslogstream(3bobcat)

#include <iostream>
#include <bobcat/syslogstream>
using namespace std;
using namespace FBB;
int main(int argc, char **argv)
{
    ostream sls(new SyslogBuf(argv[0]));
    sls << SyslogStream::debug << "Hello world" << flush <<
           SyslogStream::strerrno << endl;
}

BUGS

The constructor’s option parameter is an int. Because of this, int values rather than enumeration values are passed to the constructor. It is the responsibility of the programmer to pass defined option values only.
