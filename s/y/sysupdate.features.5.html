SYSUPDATE.FEATURES(5) sysupdate.features SYSUPDATE.FEATURES(5)

NOMBRE

sysupdate.features - Archivos de definición para características opcionales

SINOPSIS

/etc/sysupdate.d/*.feature
/run/sysupdate.d/*.feature
/usr/local/lib/sysupdate.d/*.feature
/usr/lib/sysupdate.d/*.feature

DESCRIPCIÓN

"Características opcionales" son funcionalidades proporcionadas por systemd-sysupdate(8), que permiten a una distribución definir conjuntos de definiciones de transferencia de sysupdate.d(5) que están destinadas a ser habilitadas o deshabilitadas por el administrador del sistema.

Cuando una característica está habilitada, las transferencias que le pertenecen serán consideradas al verificar y descargar actualizaciones, al hacer limpieza (vacuuming), y en todas las demás situaciones. En efecto, las transferencias que pertenecen a una característica se actualizarán al mismo ritmo que el resto de su objetivo. Esta es la principal diferencia entre una característica opcional y un componente de systemd-sysupdate(8). Cuando una característica está deshabilitada, sus transferencias no serán consideradas al verificar y descargar actualizaciones, pero systemd-sysupdate aún las considerará al hacer limpieza y en otras situaciones donde necesite determinar la propiedad de recursos del sistema descargados previamente. systemd-sysupdate limpiará todas las instancias de las transferencias de la característica cada vez que se deshabilite, desinstalándola efectivamente.

Las características opcionales se describen mediante archivos sysupdate.d/*.feature, que se definen a continuación. Las transferencias pueden declarar que pertenecen a una característica a través de la configuración Features=. Las definiciones de características admiten archivos de anulación (drop-in), que se utilizan más comúnmente para anular la configuración Enabled=. También se pueden enmascarar para ocultar completamente la disponibilidad de la característica.

Cada archivo *.feature contiene una sección: [Feature].

OPCIONES DE SECCIÓN [CARACTERÍSTICA]

Esta sección define las propiedades generales de esta característica.

Description=

Una breve descripción legible por humanos de esta característica. Esta cadena puede usarse como etiqueta para esta característica, por lo que la cadena debe identificar significativamente la característica entre las disponibles en sysupdate.d/.

Añadido en la versión 257.

Documentation=

Una URL presentable al usuario para la documentación sobre esta característica. Esta configuración admite la expansión de especificadores; consulte más abajo para obtener detalles sobre los especificadores admitidos.

Añadido en la versión 257.

AppStream=

Una URL a un archivo XML de **catálogo AppStream**[1]. Esto puede ser utilizado por centros de software (como GNOME Software o KDE Discover) para presentar metadatos enriquecidos sobre esta característica. Esto incluye nombres de visualización, registros de cambios, iconos y más. Esta configuración admite la expansión de especificadores; consulte más abajo para obtener detalles sobre los especificadores admitidos.

Añadido en la versión 257.

Enabled=

Si esta característica está habilitada o no. Si no se especifica, la característica está deshabilitada por defecto.

Añadido en la versión 257.

ESPECIFICADORES

Los especificadores pueden usarse en las configuraciones Documentation= y AppStream=. Las siguientes expansiones se entienden:

"%H" Nombre del host El nombre del host del sistema en ejecución.

"%o" ID del sistema operativo El identificador del sistema operativo del sistema en ejecución, tal como se lee del campo ID= de /etc/os-release. Consulte os-release(5) para más información.
"%v" Versión del kernel Idéntico a la salida de uname -r.
"%w" ID de versión del sistema operativo El identificador de versión del sistema operativo del sistema en ejecución, tal como se lee del campo VERSION_ID= de /etc/os-release. Si no está establecido, se resuelve a una cadena vacía. Consulte os-release(5) para más información.

"%%" Signo de porcentaje único Use "%%" en lugar de "%" para especificar un solo signo de porcentaje.

EJEMPLOS

Ejemplo 1. Herramientas de desarrollo para SO basado en imágenes

Usaremos el hipotético "foobarOS" descrito en sysupdate.d(5) como nuestro SO base de ejemplo. La gran mayoría de los usuarios de foobarOS no necesitan que un compilador, sistema de compilación, depurador y otras herramientas de desarrollo similares formen parte de su SO. Sin embargo, los desarrolladores del propio foobarOS necesitan que estas herramientas de compilación estén disponibles. Por lo tanto, foobarOS necesita proporcionar una imagen de extensión del sistema (ver systemd-sysext(8)) que contenga estas herramientas de desarrollo, y esta imagen debe actualizarse al mismo ritmo que el SO base subyacente. Este es un gran caso de uso para una característica opcional del SO, así que definamos una:

# /usr/lib/sysupdate.d/devel.feature
[Feature]
Description=Herramientas de Desarrollo
Documentation=https://developer.example.com/foobarOS/getting-started
Enabled=false

Lo anterior define la característica "devel" y la deshabilita por defecto. Ahora definamos una transferencia asociada a esta característica:

# /usr/lib/sysupdate.d/50-devel.transfer
[Transfer]
Features=devel
ProtectVersion=

sysupdate.features(5) – System Update Feature Definitions

NAME

sysupdate.features(5) – System Update Feature Definitions

SYNOPSIS

Files in /usr/lib/sysupdate.d/*.feature, /etc/sysupdate.d/*.feature.

DESCRIPTION

System update systemd-sysupdate(8) supports an extensible mechanism for defining optional features that may be installed or updated alongside the core operating system. These features are defined in *.feature files, which are INI-style files with a single [Feature] section.

The primary purpose of features is to group related system update transfers. Each feature may be enabled or disabled independently, and system update will ensure that all transfers associated with enabled features are downloaded and installed.

[FEATURE] SECTION OPTIONS

Enabled
A boolean value. If set to true, the feature is enabled by default. This is useful for features that are essential for the system's basic operation, but can be overridden by user configuration. Defaults to false.
Description
A short, human-readable description of the feature. This may be used by user interfaces to display information about the feature.
Documentation
A URL pointing to documentation for the feature. This may be used by user interfaces to link to more detailed information.
AppStream
A URL pointing to an AppStream metadata file for the feature. This allows software centers to discover and present the feature to end-users.

SPECIFIERS

The following specifiers may be used within the MatchPattern fields of *.transfer files:

%A
This specifier is replaced by the system's current OS version string. This ensures that only versions of features matching the core OS version are installed.
%v
This specifier is replaced by the OS version string specified in the feature's *.feature file (or the core OS version if not specified). This allows features to track specific OS versions.

EXAMPLES

Example 1. Development Tools

Suppose that the foobarOS distribution provides a set of development tools as an optional feature. This feature is enabled by default.

# /usr/lib/sysupdate.d/devel.feature
[Feature]
Enabled=true
Description=Development Tools
Documentation=https://docs.foobaros.org/devel.html
AppStream=https://metadata.example.com/devel.xml.gz

To make these tools available, a corresponding transfer is defined:

# /usr/lib/sysupdate.d/devel.transfer
[Transfer]
Features=devel
ProtectVersion=%A
[Source]
Type=url-file
Path=https://download.example.com/
MatchPattern=foobarOS_@v_devel.raw.xz
[Target]
Type=regular-file
Path=/var/lib/extensions
MatchPattern=foobarOS_@v_devel.raw
Mode=0444
InstancesMax=2

With these two files, we have created a feature called "devel" that, when enabled, will download and decompress the appropriate version of "https://download.example.com/foobarOS_@v_devel.raw.xz" into "/var/lib/extensions/foobarOS_@v_devel.raw" during each OS update.

The developers of foobarOS can enable the "devel" feature on their workstations by creating the following drop-in:

# /etc/sysupdate.d/devel.feature.d/enable.conf
[Feature]
Enabled=true

Example 2. Proprietary Drivers

Suppose that many of foobarOS's users have a GPU manufactured by the MVISUAL corporation. Due to lack of documentation and difficulty in reverse-engineering the hardware, the open-source drivers for MVISUAL GPUs are unable to make proper use of available graphics and compute performance. MVISUAL provides a redistributable proprietary driver for their cards, and foobarOS's developers distribute them to address their users' needs.

MVISUAL's driver has a couple different parts that must be installed for it to function: a UKI addon to configure the kernel command-line, an initrd system extension image to add the MVISUAL kernel module into the initrd, and a regular system extension image to add the proprietary OpenGL and Vulkan userspace drivers. All of these should be version-locked to the core OS.

Let's start by defining an optional feature named "mvisual-driver":

# /usr/lib/sysupdate.d/mvisual-driver.feature
[Feature]
Description=MVISUAL Proprietary GPU Driver
Documentation=https://support.example.com/foobarOS/mvisual
AppStream=https://metadata.example.com/mvisual-driver-%A.xml.gz

Note that we define AppStream metadata for this feature, because we want software centers to present it to end-users. Next, let's define the corresponding transfers:

# /usr/lib/sysupdate.d/50-mvisual-userspace.transfer
[Transfer]
Features=mvisual-driver
ProtectVersion=%A
[Source]
Type=url-file
Path=https://download.example.com/
MatchPattern=foobarOS_@v_mvisual_userspace.raw.xz
[Target]
Type=regular-file
Path=/var/lib/extensions
MatchPattern=foobarOS_@v_mvisual.raw
Mode=0444
InstancesMax=2
# /usr/lib/sysupdate.d/70-mvisual-initrd.transfer
[Transfer]
Features=mvisual-driver
ProtectVersion=%A
[Source]
Type=url-file
Path=https://download.example.com/
MatchPattern=foobarOS_@v_mvisual_initrd.raw.xz
[Target]
Type=regular-file
Path=/EFI/Linux
PathRelativeTo=boot
MatchPattern=foobarOS_@v.efi.extra.d/foobarOS_mvisual.raw
Mode=0444
InstancesMax=2
# /usr/lib/sysupdate.d/90-mvisual-addon.transfer
[Transfer]
Features=mvisual-driver
ProtectVersion=%A
[Source]
Type=url-file
Path=https://download.example.com/
MatchPattern=foobarOS_@v_mvisual_addon.efi.xz
[Target]
Type=regular-file
Path=/EFI/Linux
PathRelativeTo=boot
MatchPattern=foobarOS_@v.efi.extra.d/foobarOS_mvisual.addon.efi
Mode=0444
InstancesMax=2

Example 3. Intersecting Features

Suppose that MVISUAL releases special tooling to help a distribution developer troubleshoot crashes in their proprietary driver. Let's define a transfer:

# /usr/lib/sysupdate.d/50-mvisual-debugger.transfer
[Transfer]
RequisiteFeatures=devel mvisual-driver
ProtectVersion=%A
[Source]
Type=url-file
Path=https://download.example.com/
MatchPattern=foobarOS_@v_devel.raw.xz
[Target]
Type=regular-file
Path=/var/lib/extensions
MatchPattern=foobarOS_@v_devel.raw
Mode=0444
InstancesMax=2

This transfer will be used only if both the "devel" and "mvisual-driver" features are enabled.
