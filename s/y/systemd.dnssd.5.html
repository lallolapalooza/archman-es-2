NOMBRE

systemd.dnssd - configuración de DNS-SD

SINOPSIS

servicio_red.dnssd

DESCRIPCIÓN

La configuración de DNS-SD es realizada por systemd-resolved(8).

El archivo principal del servicio de red debe tener la extensión .dnssd; otras extensiones se ignoran.

Los archivos .dnssd se leen de los archivos ubicados en los directorios de red del sistema /usr/lib/systemd/dnssd y /usr/local/lib/systemd/dnssd, el directorio de red de tiempo de ejecución volátil /run/systemd/dnssd y el directorio de red de administración local /etc/systemd/dnssd. Todos los archivos de configuración se ordenan y procesan colectivamente en orden léxico, independientemente de los directorios en los que residan. Sin embargo, los archivos con nombres idénticos se reemplazan entre sí. Los archivos en /etc/ tienen la prioridad más alta, los archivos en /run/ prevalecen sobre los archivos con el mismo nombre en /usr/lib/. Esto se puede usar para anular un archivo de configuración proporcionado por el sistema con un archivo local si es necesario.

Junto con el archivo del servicio de red foo.dnssd, puede existir un directorio "drop-in" foo.dnssd.d/. Todos los archivos con el sufijo ".conf" de este directorio se analizarán después de que se analice el archivo en sí. Esto es útil para modificar o agregar configuraciones, sin tener que modificar el archivo de configuración principal. Cada archivo drop-in debe tener encabezados de sección apropiados.

Además de /etc/systemd/dnssd, los directorios drop-in ".d" pueden ubicarse en los directorios /usr/lib/systemd/dnssd o /run/systemd/dnssd. Los archivos drop-in en /etc/ prevalecen sobre los de /run/ que a su vez prevalecen sobre los de /usr/lib/ o /usr/local/lib. Los archivos drop-in en cualquiera de estos directorios prevalecen sobre el archivo principal del servicio de red dondequiera que esté ubicado.

[SERVICIO] SECCIÓN OPCIONES

El archivo del servicio de red contiene una sección [Service], que especifica un servicio de red detectable anunciado en una red local con transmisiones Multicast DNS.

Name=

Un nombre de instancia del servicio de red según se define en la sección 4.1.1 de RFC 6763[1], por ejemplo, "servidor web".

La opción admite la expansión de especificadores simples. Se entienden las siguientes expansiones:

Type=

Un tipo de servicio de red según se define en la sección 4.1.2 de RFC 6763[1], por ejemplo, "_http._tcp".

SubType=

Un subtipo del servicio de red según se define en la sección 7.1 de RFC 6763[1], por ejemplo, "_printer".

Añadido en la versión 256.

Port=

Un número de puerto IP del servicio de red.

Añadido en la versión 236.

Priority=

Un número de prioridad establecido en los registros de recurso SRV correspondientes al servicio de red.

Añadido en la versión 236.

Weight=

Un número de peso establecido en los registros de recurso SRV correspondientes al servicio de red.

Añadido en la versión 236.

TxtText=

Una lista separada por espacios de pares clave/valor arbitrarios que transmiten información adicional sobre el servicio nombrado en el registro de recursos TXT correspondiente, por ejemplo, "path=/portal/index.html". Las claves y los valores pueden contener secuencias de escape de estilo C que se traducen al leer los archivos de configuración.

Esta opción junto con TxtData= puede especificarse más de una vez, en cuyo caso se crearán varios registros de recursos TXT para el servicio. Si se asigna la cadena vacía a esta opción, la lista se restablece y todas las asignaciones anteriores no tendrán efecto.

Añadido en la versión 236.

TxtData=

Una lista separada por espacios de pares clave/valor arbitrarios que transmiten información adicional sobre el servicio nombrado en el registro de recursos TXT correspondiente, donde los valores son cadenas codificadas en base64 que representan cualquier dato binario, por ejemplo, "data=YW55IGJpbmFyeSBkYXRhCg==". Las claves pueden contener secuencias de escape de estilo C que se traducen al leer los archivos de configuración.

Esta opción junto con TxtText= puede especificarse más de una vez, en cuyo caso se crearán varios registros de recursos TXT para el servicio. Si se asigna la cadena vacía a esta opción, la lista se restablece y todas las asignaciones anteriores no tendrán efecto.

Añadido en la versión 236.

EJEMPLOS

Ejemplo 1. Servicio HTTP

# /etc/systemd/dnssd/http.dnssd
[Service]
Name=%H
Type=_http._tcp
Port=80
TxtText=path=/stats/index.html t=temperature_sensor

Esto hace que el servidor http que se ejecuta en el host sea detectable en la red local dado que MulticastDNS está habilitado en la interfaz de red.

Ahora la utilidad "resolvectl" debería poder resolver el servicio al nombre del host:

$ resolvectl service meteo._http._tcp.local
meteo._http._tcp.local: meteo.local:80 [priority=0, weight=0]
                        169.254.208.106%senp0s21f0u2u4
                        fe80::213:3bff:fe49:8aa%senp0s21f0u2u4

NAME

systemd.dnssd - Registering and publishing services with the network.

SYNOPSIS

 [DNSSD]
Path=
Service=
...
Ttl=
...
Port=
...
Host=
...
...

DESCRIPTION

This document describes the configuration options for registering and publishing services with the network using DNS-SD (DNS-based Service Discovery) as defined by RFC 6763. DNS-SD is a method for discovering services offered by hosts on a local network.

Services are registered using the systemd.service(5) unit files, but using the specific DNS-SD options described here. The options are grouped under the `[DNSSD]` section.

The service registration is performed by systemd-dnssd.service(8), which is enabled by default on systemd-based systems. This service reads the configuration files and registers the specified services with the DNS resolver.

DNSSD OPTIONS

Path=
Specifies the path component of the service URL. This is typically used to point to a specific resource or endpoint on the service. For example, Path=/stats/index.html.
Service=
Specifies the service name. This is a string that identifies the type of service being offered. It follows the convention of service type, domain, and protocol, such as _http._tcp.local. The .local suffix is recommended for local network services.
Ttl=
Sets the Time-To-Live (TTL) for the DNS records published for this service. A longer TTL means the records will be cached by clients for a longer period, reducing the load on the publishing host. The default TTL is usually sufficient.
Port=
Specifies the port number on which the service is listening. This is required for clients to connect to the service.
Host=
Specifies the hostname of the machine offering the service. If not specified, the system's hostname will be used.

[SERVICE] SECTION OPTIONS

In addition to the `[DNSSD]` options, the following options from the `[Service]` section are relevant when publishing a service:

Type=
Should be set to notify for services that are published via DNS-SD. This indicates that the service is intended to be discovered by other network hosts.

EXAMPLES

Here is an example of a service unit file that publishes a simple web server running on port 80:

[Unit]
Description=My Web Server

[Service]
Type=notify
ExecStart=/usr/local/bin/my-web-server
Restart=on-failure

[DNSSD]
Service=_http._tcp.local
Path=/stats/index.html
Port=80
Ttl=3600
Host=meteo.local

When this service is running, systemd-dnssd will publish the service information using DNS-SD. Other devices on the same network that are running mDNS/DNS-SD compatible software (like Avahi) will be able to discover this service. For instance, using resolvectl on a systemd-resolved client, you might see something like this:

$ resolvectl dnssec-probe meteo.local
meteo.local: 
          ... (A record for meteo.local) ...
          ... (AAAA record for meteo.local) ...

-- Information acquired via protocol mDNS/IPv6 in 4.0ms.
-- Data is authenticated: yes

"Avahi" running on a different host in the same local network should see the service as well:

$ avahi-browse -a -r
+ enp3s0 IPv6 meteo                                         Web Site             local
+ enp3s0 IPv4 meteo                                         Web Site             local
= enp3s0 IPv6 meteo                                         Web Site             local
   hostname = [meteo.local]
   address = [fe80::213:3bff:fe49:8aa]
   port = [80]
   txt = ["path=/stats/index.html" "t=temperature_sensor"]
= enp3s0 IPv4 meteo                                         Web Site             local
   hostname = [meteo.local]
   address = [169.254.208.106]
   port = [80]
   txt = ["path=/stats/index.html" "t=temperature_sensor"]
