NOMBRE

systemd-userdbd.service, systemd-userdbd - Multiplexor de Consulta de Registros de Usuario/Grupo JSON/Compatibilidad NSS

SINOPSIS

systemd-userdbd.service

/usr/lib/systemd/systemd-userdbd

DESCRIPCIÓN

systemd-userdbd es un servicio del sistema que multiplexa las consultas de usuarios/grupos a todos los servicios locales que proporcionan definiciones de registros de usuarios/grupos JSON al sistema. Además, sintetiza registros de usuarios/grupos JSON a partir de registros de usuarios/grupos clásicos UNIX/glibc NSS para proporcionar una compatibilidad completa hacia atrás. También puede recopilar registros de usuarios/grupos JSON definidos estáticamente de archivos en /etc/userdb/, /run/userdb/, /run/host/userdb/ y /usr/lib/userdb/ con la extensión ".user" o ".group". Para más detalles sobre las extensiones, lea la página del manual de nss-systemd(8).

La mayor parte de la funcionalidad de systemd-userdbd es accesible a través del comando userdbctl(1).

Los registros de usuarios y grupos a los que este servicio proporciona acceso siguen las definiciones de Registros de Usuarios JSON[1] y Registro de Grupos JSON[2]. Este servicio implementa la API de Consulta de Registros de Usuarios/Grupos vía Varlink[3], y también multiplexa el acceso a otros servicios que implementan esta API. Por lo tanto, es tanto un servidor como un cliente de esta API.

Este servicio proporciona tres servicios distintos de Varlink[4]: io.systemd.Multiplexer proporciona una API única y unificada para consultar registros de usuarios y grupos JSON. Internamente, se comunica con todos los demás servicios de registros de usuarios/grupos que se ejecutan en el sistema en paralelo y reenvía cualquier información descubierta. Esto simplifica sustancialmente a los clientes, ya que solo necesitan hablar con un único servicio en lugar de con todos ellos en paralelo. io.systemd.NameServiceSwitch proporciona compatibilidad con los registros de usuarios NSS clásicos de UNIX/glibc, es decir, convierte los registros de struct passwd y struct group obtenidos con APIs como getpwnam(1) en registros de usuarios/grupos JSON, ocultando así las diferencias entre los servicios tanto como sea posible. io.systemd.DropIn pone a disposición registros de usuarios/grupos JSON de los directorios de inclusión mencionados anteriormente.
