sys_mman.h(0p) Manual del programador POSIX sys_mman.h(0p)

PROLOGO

Esta página del manual es parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

sys/mman.h — declaraciones de gestión de memoria

SINOPSIS

#include <sys/mman.h>

DESCRIPCIÓN

El archivo de cabecera <sys/mman.h> definirá las siguientes constantes simbólicas para su uso como opciones de protección:

PROT_EXEC
La página puede ser ejecutada.
PROT_NONE
La página no puede ser accedida.
PROT_READ
La página puede ser leída.
PROT_WRITE
La página puede ser escrita.

El archivo de cabecera <sys/mman.h> definirá las siguientes constantes simbólicas para su uso como opciones de bandera:

MAP_FIXED
Interpretar addr exactamente.
MAP_PRIVATE
Los cambios son privados.
MAP_SHARED
Compartir cambios.

El archivo de cabecera <sys/mman.h> definirá las siguientes constantes simbólicas para la función msync():

MS_ASYNC
Realizar escrituras asíncronas.
MS_INVALIDATE
Invalidar mapeos.
MS_SYNC
Realizar escrituras síncronas.

El archivo de cabecera <sys/mman.h> definirá las siguientes constantes simbólicas para la función mlockall():

MCL_CURRENT
Bloquear páginas actualmente mapeadas.
MCL_FUTURE
Bloquear páginas que se mapeen en el futuro.

El archivo de cabecera <sys/mman.h> definirá la constante simbólica MAP_FAILED que tendrá tipo void * y se usará para indicar un error de la función mmap().

Si se soporta la opción de Información Asesora, el archivo de cabecera <sys/mman.h> definirá constantes simbólicas para el argumento advice de la función posix_madvise() como sigue:

POSIX_MADV_DONTNEED

La aplicación espera no acceder al rango especificado en un futuro cercano.
POSIX_MADV_NORMAL

La aplicación no tiene ninguna recomendación sobre su comportamiento con respecto al rango especificado. Es la característica por defecto si no se dan recomendaciones para un rango de memoria.
POSIX_MADV_RANDOM

La aplicación espera acceder al rango especificado en orden aleatorio.
POSIX_MADV_SEQUENTIAL

La aplicación espera acceder al rango especificado secuencialmente, de direcciones más bajas a más altas.
POSIX_MADV_WILLNEED

La aplicación espera acceder al rango especificado en un futuro cercano.

El archivo de cabecera <sys/mman.h> definirá las siguientes constantes simbólicas para su uso como banderas para la función posix_typed_mem_open():

POSIX_TYPED_MEM_ALLOCATE

Asignar en mmap().
POSIX_TYPED_MEM_ALLOCATE_CONTIG

Asignar de forma contigua en mmap().
POSIX_TYPED_MEM_MAP_ALLOCATABLE

Mapear en mmap(), sin afectar la asignabilidad.

El archivo de cabecera <sys/mman.h> definirá los tipos mode_t, off_t y size_t como se describe en <sys_types.h>.

El archivo de cabecera <sys/mman.h> definirá la estructura posix_typed_mem_info, que incluirá al menos el siguiente miembro:

size_t  posix_tmi_length  Longitud máxima que puede ser asignada
                          desde un objeto de memoria tipificada.

Se declararán las siguientes funciones y también podrán definirse como macros. Se proporcionarán prototipos de función.

int    mlock(const void *, size_t);
int    mlockall(int);
void  *mmap(void *, size_t, int, int, int, off_t);
int    mprotect(void *, size_t, int);
int    msync(void *, size_t, int);
int    munlock(const void *, size_t);
int    munlockall(void);
int    munmap(void *, size_t);
int    posix_madvise(void *, size_t, int);
int    posix_mem_offset(const void *restrict, size_t, off_t *restrict,
           size_t *restrict, int *restrict);
int    posix_typed_mem_get_info(int, struct posix_typed_mem_info *);
int    posix_typed_mem_open(const char *, int, int);
int    shm_open(const char *, int, mode_t);
int    shm_unlink(const char *);

PROLOG

Este manual describe los conceptos y el funcionamiento de las llamadas al sistema y las funciones de biblioteca del núcleo Linux.

NOMBRE

mman.h - interfaz para mapeo de memoria

SINOPSIS

#include <sys/mman.h>

DESCRIPCIÓN

El archivo de cabecera <sys/mman.h> declara las funciones y constantes relacionadas con el mapeo de memoria:

Las funciones principales son:

  • mmap(): Mapea archivos u otros dispositivos en la memoria.
  • munmap(): Desmapea regiones de memoria previamente mapeadas.
  • mprotect(): Cambia las protecciones de acceso de una región de memoria mapeada.
  • msync(): Sincroniza un mapa de memoria con su almacenamiento subyacente.
  • mlock(), munlock(), mlockall(), munlockall(): Bloquean o desbloquean páginas en memoria.
  • shm_open(), shm_unlink(): Utilidades para crear y destruir objetos de memoria compartida POSIX.

Las constantes importantes incluyen:

  • Flags para mmap():
    • MAP_SHARED: Comparte las escrituras entre procesos.
    • MAP_PRIVATE: Crea un mapeo privado (copia en escritura).
    • MAP_FIXED: Mapea en una dirección específica.
    • MAP_ANONYMOUS: Crea un mapeo anónimo (no asociado a un archivo).
    • MAP_POPULATE: Pre-carga las páginas.
    • MAP_NONBLOCK: No bloquea al pre-cargar.
  • Flags para mprotect():
    • PROT_READ: Permite la lectura.
    • PROT_WRITE: Permite la escritura.
    • PROT_EXEC: Permite la ejecución.
    • PROT_NONE: Sin permisos.
  • Flags para msync():
    • MS_SYNC: Escritura síncrona.
    • MS_ASYNC: Escritura asíncrona.
    • MS_INVALIDATE: Invalida cachés.
  • Flags para mlockall():
    • MCL_CURRENT: Bloquea páginas actualmente mapeadas.
    • MCL_FUTURE: Bloquea páginas mapeadas en el futuro.
  • Flags para shm_open():
    • O_CREAT, O_EXCL, O_RDWR, etc. (flags estándar de open()).

USO DE LA APLICACIÓN

Los programadores utilizan estas funciones para mapear regiones de memoria directamente en su espacio de direcciones, lo que permite un acceso eficiente a archivos o memoria compartida entre procesos.

FUNDAMENTO

El mapeo de memoria proporciona una alternativa de alto rendimiento a las operaciones de E/S tradicionales (como read() y write()) al permitir que los datos residan directamente en la memoria virtual del proceso.

DIRECCIONES FUTURAS

Las extensiones futuras pueden incluir un mejor soporte para arquitecturas heterogéneas y optimizaciones para sistemas con gran cantidad de memoria.

VER TAMBIÉN

open(2), read(2), write(2), close(2), fork(2), execve(2), exit(2).
