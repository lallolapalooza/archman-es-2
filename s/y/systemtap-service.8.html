SYSTEMTAP(8) Manual del Administrador del Sistema SYSTEMTAP(8)

NOMBRE

systemtap-service - Script de inicio y servicio systemd de SystemTap

SINOPSIS

systemtap-service COMANDO [OPCIONES] [SCRIPT...]

service systemtap COMANDO [OPCIONES] [SCRIPT...]

DESCRIPCIÓN

El script de inicio de SystemTap tiene como objetivo proporcionar una forma de ejecutar scripts como un servicio y controlarlos fácilmente de forma individual. Los scripts se pueden configurar para iniciarse mediante una solicitud manual o durante el arranque del sistema. En sistemas basados en dracut, también es posible integrar scripts en el initramfs y hacer que se inicien durante el arranque temprano.

El script de inicio de SystemTap se puede invocar manualmente usando el comando systemtap-service. En sistemas basados en systemd, el script de inicio se controla con systemctl utilizando el archivo de servicio systemtap.service.

Hay varios parámetros y opciones disponibles para modificar el comportamiento global, así como el comportamiento de los scripts. Se pueden establecer dependencias entre scripts para que al iniciar uno se inicien otros.

El archivo de configuración del script de inicio se encuentra en /etc/systemtap/config. Los parámetros aceptables se detallan en la sección PARÁMETROS GLOBALES.

Los scripts deben colocarse en el directorio /etc/systemtap/script.d y deben tener la extensión .stp. Sin embargo, al referirse a ellos en la línea de comandos, no es necesario incluir la extensión .stp. Los nombres de los scripts solo pueden contener caracteres alfanuméricos (y '_') y no deben comenzar con un número. El directorio de scripts puede modificarse estableciendo el parámetro SCRIPT_PATH en el archivo de configuración.

COMANDOS

Se debe especificar uno de los siguientes comandos:

iniciar
Inicia los SCRIPTs. Si no se especifican scripts, inicia los scripts especificados por la configuración DEFAULT_START. Si DEFAULT_START no está establecida, inicia todos los scripts en el directorio de scripts. Para los scripts que ya se iniciaron, el comando se ignora. El comando fallará si los scripts no se inician correctamente (ver también la configuración PASSALL).

Si la configuración AUTOCOMPILE está activada, el comando intentará compilar o actualizar los scripts especificados cuando una de las siguientes condiciones sea verdadera:

-
El archivo de caché compilado no existe.
-
La marca de tiempo de modificación (mtime) del archivo de script original es más reciente que la del caché del script compilado.
-
Las opciones de stap especificadas utilizadas para compilar el script han cambiado (ver también la sección PARÁMETROS DE SCRIPT).
-
El resultado de `uname -a` ha cambiado.
detener
Detiene los SCRIPTs. Si no se especifican scripts, detiene todos los scripts en ejecución. Para los scripts que ya están detenidos, el comando se ignora. El comando fallará si los scripts no se detienen correctamente (ver también la configuración PASSALL).
reiniciar
Detiene e inicia los SCRIPTs.
estado
Muestra el estado de los SCRIPTs y sus dependencias.
compilar
Compila los SCRIPTs pero no los inicia. Si los scripts ya se han compilado, solicita confirmación antes de sobrescribir la caché. Compila para el kernel actual, o para la versión del kernel especificada por la opción -r.
enboot
Hace que los SCRIPTs formen parte del initramfs para que se inicien más temprano durante el proceso de arranque. Este comando solo está disponible en sistemas basados en dracut. Si no se especifican scripts, crea un initramfs normal sin archivos de SystemTap.

El initramfs se crea para el kernel actual, o para la versión del kernel especificada por la opción -r. La ruta del initramfs creado por defecto es /boot/initramfs-KVER.img, donde KVER es la salida de `uname -r`. El gestor de arranque también se actualiza (usando new-kernel-pkg(8)) para que la entrada del kernel utilice el nuevo archivo initramfs. Utilice la opción -o para especificar una ruta diferente (el gestor de arranque no se actualizará).

Si el archivo de salida ya existe, se sobrescribe, a menos que se proporcione el modificador -b, en cuyo caso el archivo se respalda con la extensión .bak en lugar de sobrescribirse. Sin embargo, si ya existe una versión .bak del archivo, la copia de seguridad no se sobrescribirá.

ADVERTENCIA: no utilice la opción -o de stap(1) con scripts enboot, ya que el script se inicia antes de que el sistema de archivos raíz esté montado. Aumente el tamaño del búfer si se necesita más espacio.

limpiar
Elimina los SCRIPTs compilados de la caché. Si no se especifican scripts, se eliminan todos los scripts compilados. Solo se elimina la caché para el kernel actual, o para la versión del kernel especificada por la opción -r. Solicita confirmación antes de eliminar.

OPCIONES

Muchos de los comandos también pueden aceptar opciones. Sin embargo, dado que los usuarios no pueden pasar estas opciones al arrancar, solo están destinadas a la gestión de scripts después del arranque y para pruebas. Las opciones disponibles son:

-c ARCHIVO_CONFIG
Especifica un archivo de configuración diferente en lugar del predeterminado.
-R
Al usar los comandos iniciar y detener, incluye también las dependencias de los scripts (recursivamente).
-r VERSION_KERNEL
Al usar los comandos compilar, enboot y limpiar, especifica la versión del kernel de destino en lugar de usar la actual. Debe estar en el mismo formato que `uname -r`.
-s
Responde sí a todas las solicitudes.
-o RUTA.IMG
Al usar el comando enboot, especifica la ruta de salida del initramfs creado. Cuando se especifica, la configuración del gestor de arranque no se actualiza.
-b
Al usar el comando enboot, crea una copia de seguridad de una imagen initramfs existente añadiendo una extensión .bak en lugar de sobrescribirla. Sin esta opción, el initramfs se sobrescribe.

PARÁMETROS GLOBALES

Estos parámetros afectan el comportamiento general del servicio del script de inicio de SystemTap. Se pueden especificar en el archivo de configuración.

RUTA_SCRIPTS
Especifica la ruta absoluta del directorio de scripts. Estos son los scripts sobre los que el script de inicio puede operar. Los scripts deben tener la extensión .stp. La ruta predeterminada es /etc/systemtap/script.d.
RUTA_CONFIG
Especifica la ruta absoluta del directorio de configuración de scripts. Estos archivos de configuración contienen opciones para scripts específicos. Deben tener la extensión .conf. La ruta predeterminada es /etc/systemtap/conf.d.
RUTA_CACHE
Especifica la ruta absoluta del directorio de caché. La ruta predeterminada es /var/cache/systemtap.
RUTA_TEMP
Especifica la ruta absoluta del directorio temporal en el que SystemTap crea directorios temporales para compilar scripts. La ruta predeterminada es /tmp.
RUTA_STAT
Especifica la ruta absoluta del directorio que contiene los archivos PID utilizados para rastrear el estado de los scripts de SystemTap. La ruta predeterminada es /var/run/systemtap.
ARCHIVO_LOG
Especifica la ruta absoluta del archivo de registro. Todos los mensajes se envían a este archivo, incluidos los errores de compilación y ejecución. La ruta predeterminada es /var/log/sy

ARCHIVO DE CONFIGURACIÓN GLOBAL

Estos parámetros afectan al comportamiento general de los scripts de SystemTap. Deben colocarse en el archivo de configuración global, que es /etc/systemtap/systemtap.conf por defecto. El directorio donde se buscan los scripts de SystemTap se puede cambiar mediante el parámetro SCRIPT_PATH. El directorio donde se encuentran los archivos de configuración de los scripts se puede cambiar mediante el parámetro CONFIG_PATH. El registro de salida de SystemTap puede hacerse en el archivo de registro, que por defecto es /var/log/stemtap.log.

PASSALL
Si se establece en yes, los comandos del script de inicialización que operan sobre múltiples scripts informarán como fallidos cuando la acción no se pueda realizar en al menos un script. Si se establece en no, solo se emitirá una advertencia. El valor por defecto es yes.
RECURSIVE
Si se establece en yes, el script de inicialización seguirá siempre las dependencias de los scripts de forma recursiva. Esto significa que no es necesario especificar la opción -R. Este indicador solo es efectivo si se especifican scripts desde la línea de comandos. El valor por defecto es no.
AUTOCOMPILE
Si se establece en yes, el script de inicialización intentará automáticamente compilar los scripts especificados cuando sea necesario si no hay una caché válida. De lo contrario, el comando relacionado simplemente fallará. El valor por defecto es yes.
DEFAULT_START
Especifica los scripts que se iniciarán por defecto. Si se omite (o está vacío), se iniciarán todos los scripts del directorio de scripts. El valor por defecto es "".
ALLOW_CACHEONLY
Si se establece en yes, el script de inicialización también permitirá operar sobre scripts que se encuentran en el directorio de caché, pero no en el directorio de scripts. El valor por defecto es no.

ADVERTENCIA: el script de inicialización puede cargar cachés obsoletos inesperados con esta opción. El directorio de caché debe ser verificado antes de habilitar esta opción.

LOG_BOOT_ERR
Dado que los scripts de tiempo de arranque se ejecutan antes de montar el sistema de archivos raíz, la salida de error estándar de staprun no se puede registrar en LOG_FILE como de costumbre. Sin embargo, el registro puede ser emitido en su lugar a /run/systemtap/$script.log estableciendo LOG_BOOT_ERR en yes. Si STAT_PATH es diferente del valor por defecto, los archivos de registro se moverán allí al ejecutar cualquiera de los comandos del script de inicialización. El valor por defecto es no.

Aquí hay un ejemplo de archivo de configuración global:

SCRIPT_PATH=/var/systemtap/script.d/
PASSALL=yes
RECURSIVE=no

PARÁMETROS DE SCRIPT

Estos parámetros afectan a la compilación o al comportamiento en tiempo de ejecución de scripts específicos de SystemTap. Deben colocarse en archivos de configuración ubicados en el directorio CONFIG_PATH.

<SCRIPT>_OPT
Especifica las opciones que se pasan al comando stap(1) para el SCRIPT. Aquí, SCRIPT es el nombre del archivo del script sin la extensión .stp. Tenga en cuenta que la opción -F siempre se añade.

Las siguientes opciones se ignoran al compilar scripts: -p, -m, -r, -c, -x, -e, -s, -o, -h, -V, -k.

Las siguientes opciones se ignoran al ejecutar scripts de inicio: -h, -V, -v, -t, -p, -I, -e, -R, -r, -m, -k, -g, -P, -D, -b, -u, -q, -w, -l, -d, -L, -F, y todas las opciones largas.

<SCRIPT>_REQ
Especifica las dependencias del script (es decir, qué script requiere este script). Por ejemplo, si foo.stp requiere (o necesita ejecutarse después de) bar.stp, establezca 
foo_REQ="bar"

Especifique múltiples scripts separando sus nombres por espacios.

Aquí hay un ejemplo de archivo de configuración de script:

script1_OPT="-o /var/log/script1.out"
script2_OPT="-o /var/log/script2.out"
script2_REQ="script1"

EJEMPLOS

INSTALACIÓN DE SCRIPTS
Primero copiamos un script de SystemTap (por ejemplo, "script1.stp") al directorio de scripts: 
# cp script1.stp /etc/systemtap/script.d/

Luego podemos establecer cualquier opción de script, por ejemplo:

# vi /etc/systemtap/conf.d/group1.conf
script1_OPT="-o /var/log/group1.out"

Luego instalamos un script (por ejemplo, "script2.stp") que necesita ejecutarse después de script1. En este caso, podemos hacer lo siguiente:

# cp script2.stp /etc/systemtap/script.d/
# vi /etc/systemtap/conf.d/group1.conf
script2_OPT="-o /var/log/script2.out"
script2_REQ="script1"

De esta manera, si stap(1) falla al ejecutar script1, el script de inicialización ni siquiera intentará ejecutar script2.

PRUEBAS
Después de instalar los scripts, podemos probar que funcionan simplemente haciendo: 
# systemtap-service start
# systemtap-service stop

También podríamos ser más específicos, por ejemplo:

# systemtap-service start script1
# systemtap-service stop script1

Si no hubo errores, estamos listos para usarlo.

HABILITACIÓN DEL SERVICIO
Una vez que estemos satisfechos con los scripts y sus pruebas, podemos habilitar el servicio de script de inicialización de SystemTap: 
# chkconfig systemtap on
ELIMINACIÓN DE SCRIPTS
Los scripts se eliminan simplemente quitándolos del directorio de scripts y eliminando las líneas de configuración específicas de ellos: 
# rm /etc/systemtap/script.d/script2.stp
# vi /etc/systemtap/conf.d/group1.conf

Si el script todavía se está ejecutando, también debemos detenerlo:

# systemtap-service stop script2

También podemos eliminar la caché asociada con el script:

# systemtap-service cleanup script2
PREPARACIÓN PARA ACTUALIZACIONES DEL NÚCLEO
Por lo general, no hay nada que hacer al arrancar con un nuevo núcleo. El script de inicialización verá que la versión del núcleo es diferente y compilará los scripts. La compilación también se puede hacer de antemano para evitar tener que compilar durante el arranque utilizando la opción -r: 
# systemtap-service compile myscript -r <NUEVA_VERSIÓN_DEL_NÚCLEO>
IMPORTACIÓN DE SCRIPTS COMPILADOS
Para entornos que carecen de infraestructura de compilación (por ejemplo, sin compiladores ni información de depuración), como un sistema de producción, los scripts se pueden compilar en otra máquina (de desarrollo) y luego transferirse a la máquina de producción: 
# systemtap-service compile myscript -r \
>   <VERSIÓN_DEL_NÚCLEO_DE_LA_MÁQUINA_DE_DESTINO>
# tar czf stap-scripts-<versión-núcleo>.tar.gz \
>   /var/cache/systemtap/<versión-núcleo> \
>   /etc/systemtap/conf.d/<archivo-configuración>

Y luego copiar este paquete a la máquina de destino y extraerlo.

INICIO DE SCRIPTS DURANTE EL ARRANQUE TEMPRANO
El script de inicialización también nos permite iniciar scripts antes durante el proceso de arranque creando un initramfs que contenga el módulo del script. El sistema debe basarse en dracut para que esto funcione. Iniciar un script en esta etapa da acceso a información que de otro modo sería muy difícil de obtener.

Primero instalamos el script copiándolo al directorio de scripts como de costumbre y estableciendo las opciones que deseemos:

# cp myscript.stp /etc/systemtap/script.d
# vi /etc/systemtap/conf.d/myscript.conf

Para añadir el script al initramfs, usamos el comando onboot:

# systemtap-service onboot myscript

Si el script aún no está compilado y en caché, se hará en este punto. Luego se creará un nuevo initramfs en la ubicación por defecto. Podemos usar la opción -b para asegurarnos de que el initramfs existente se respalda. Luego podemos reiniciar el sistema.

USO DE UN INITRAMFS DIFERENTE
Si preferiríamos iniciar el script solo para un arranque y no para otros, podría ser más fácil usar la opción -o para especificar un archivo de salida de initramfs diferente: 
# systemtap-service onboot myscript \
>   -o /boot/special_initramfs.img

Una vez creado el initramfs, simplemente se trata de cambiar las opciones de línea de comandos en el arranque para que se utilice la nueva imagen en lugar de la habitual.

CREACIÓN DE UN INITRAMFS PARA UN NÚCLEO DIFERENTE
Al igual que el comando compile, podemos usar la opción -r para especificar el núcleo para el cual queremos crear el initramfs. Esto es útil cuando estamos a punto de actualizar y nos gustaría prepararnos con antelación. Por ejemplo: 
# systemtap-service onboot myscript \
>   -r 3.12.6-200.fc19.x86_64
ELIMINACIÓN DE SCRIPTS DEL INITRAMFS
Finalmente, para eliminar todos los scripts del initramfs, simplemente ejecutamos el comando onboot sin especificar ningún script: 
# systemtap-service onboot

Esto simplemente creará un initramfs estándar sin ningún módulo de SystemTap insertado.

RESOLUCIÓN DE PROBLEMAS DE ARRANQUE TEMPRANO
Puede haber muchas razones por las que el módulo no se insertó o no funcionó como se esperaba. Puede ser útil activar la depuración de dracut añadiendo 'rdinitdebug' a la línea de comandos del núcleo y comprobando dmesg/journalctl -ae. Además, la salida de error estándar de staprun se puede capturar estableciendo la opción LOG_BOOT_ERR en yes.
