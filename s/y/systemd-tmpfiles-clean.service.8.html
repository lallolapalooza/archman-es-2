NOMBRE

systemd-tmpfiles, systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service, systemd-tmpfiles-clean.timer - Crear, eliminar y limpiar archivos y directorios

SINOPSIS

systemd-tmpfiles [OPCIONES...] [ARCHIVO DE CONFIGURACIÓN...]

Unidades del sistema:

systemd-tmpfiles-setup.service
systemd-tmpfiles-setup-dev-early.service
systemd-tmpfiles-setup-dev.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

Unidades de usuario:

systemd-tmpfiles-setup.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

DESCRIPCIÓN

systemd-tmpfiles crea, elimina y limpia archivos y directorios, utilizando el formato y la ubicación del archivo de configuración especificados en tmpfiles.d(5). Históricamente, fue diseñado para gestionar archivos volátiles y temporales, como sugiere el nombre, pero proporciona funcionalidad genérica de gestión de archivos y puede ser utilizado para gestionar cualquier tipo de archivo. Debe invocarse con uno o más comandos --create, --remove y --clean, para seleccionar el subconjunto de operaciones respectivo.

Si se invoca sin argumentos, se ejecutan las directivas de los archivos de configuración encontrados en los directorios especificados por tmpfiles.d(5). Cuando se invoca con argumentos posicionales, si se especifica la opción --replace=RUTA, los argumentos especificados en la línea de comandos se utilizan en lugar del RUTA del archivo de configuración. De lo contrario, solo se ejecuta la configuración especificada por los argumentos de la línea de comandos. Si se especifica la cadena "-" en lugar de un nombre de archivo, la configuración se lee de la entrada estándar. Si el argumento es un nombre de archivo (sin barras), se buscan todos los directorios de configuración y se ejecuta el archivo encontrado que tenga la mayor prioridad. Si el argumento es una ruta, se utiliza directamente ese archivo sin buscar en los directorios de configuración ningún otro archivo coincidente.

Los servicios del sistema (systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service) invocan systemd-tmpfiles para crear archivos del sistema y realizar limpieza a nivel de sistema. Esos servicios leen archivos de configuración controlados por el administrador en directorios tmpfiles.d/. Los servicios de usuario (systemd-tmpfiles-setup.service, systemd-tmpfiles-clean.service) también invocan systemd-tmpfiles, pero leen un conjunto separado de archivos, que incluye archivos controlados por el usuario en ~/.config/user-tmpfiles.d/ y ~/.local/share/user-tmpfiles.d/, y archivos controlados por el administrador en /usr/share/user-tmpfiles.d/. Los usuarios pueden utilizar esto para crear y limpiar archivos bajo su control, pero la instancia del sistema realiza la limpieza global y no se ve influenciada por la configuración del usuario. Tenga en cuenta que esto significa que una limpieza basada en el tiempo configurada en la instancia del sistema, como la que normalmente se configura para /tmp/, afectará también a los archivos creados por la instancia del usuario si se colocan en /tmp/, aunque la limpieza basada en el tiempo de la instancia del usuario esté desactivada.

Para volver a aplicar la configuración después de haberla modificado, simplemente reinicie systemd-tmpfiles-clean.service, lo que aplicará cualquier configuración que pueda ejecutarse de forma segura en tiempo de ejecución. Para depurar systemd-tmpfiles, puede ser útil invocarlo directamente desde la línea de comandos con un nivel de registro aumentado (ver $SYSTEMD_LOG_LEVEL a continuación).

COMANDOS Y OPCIONES

Se entienden los siguientes comandos:

--create

Si se pasa este comando, se crean o escriben todos los archivos y directorios marcados con f, F, w, d, D, v, p, L, c, b, m en los archivos de configuración. Los archivos y directorios marcados con z, Z, t, T, a y A tendrán su propiedad, modo de acceso y etiquetas de seguridad establecidos.

--clean

Si se pasa este comando, se limpiarán todos los archivos y directorios con un parámetro de antigüedad configurado.

--remove

Si se pasa este comando, se elimina el contenido de los directorios marcados con D o R, y los propios archivos o directorios marcados con r o R, a menos que se tome un bloqueo exclusivo o compartido de BSD sobre ellos (ver flock(2)).

--purge

Si se pasa esta opción, se eliminarán todos los archivos y directorios declarados para su creación y marcados con el carácter "$" por los archivos tmpfiles.d/ especificados en la línea de comandos. Específicamente, esto actúa sobre todos los archivos y directorios marcados con f, F, d, D, v, q, Q, p, L, c, b, C, w, e. Si se utiliza este modificador, se debe especificar al menos un archivo tmpfiles.d/ (o - para la entrada estándar) en la línea de comandos, o se rechazará la invocación, por razones de seguridad (ya que de lo contrario, muchos de los archivos del sistema instalados podrían ser eliminados).

El caso de uso principal para esta opción es eliminar automáticamente los archivos y directorios que originalmente se crearon en nombre de un paquete instalado en el momento de la desinstalación del paquete.

Se recomienda ejecutar primero este comando en combinación con --dry-run (ver más abajo) para verificar qué archivos y directorios se eliminarán.

¡Advertencia! ¡Este no es el comando que normalmente quieres! En la mayoría de los casos, --remove es lo que estás buscando.

Añadido en la versión 256.

--user

Ejecuta la configuración de "usuario", es decir, archivos tmpfiles.d/ en los directorios de configuración del usuario.

Añadido en la versión 236.

--boot

Ejecuta también las líneas con un signo de exclamación. Las líneas que no son seguras para ser ejecutadas en un sistema en funcionamiento pueden marcarse de esta manera. systemd-tmpfiles se ejecuta al inicio temprano con --boot especificado y ejecutará esas líneas. Cuando se invoca de nuevo más tarde, debería llamarse sin --boot.

Añadido en la versión 209.

--graceful

Ignora las líneas de configuración relativas a usuarios o grupos desconocidos. Esta opción está pensada para usarse al inicio temprano, antes de que se hayan creado todos los usuarios o grupos.

Añadido en la versión 254.

--dry-run

Procesa la configuración e imprime qué operaciones se realizarían, pero sin cambiar nada en el sistema de archivos.

Añadido en la versión 256.

--prefix=ruta

Aplica solo reglas con rutas que comiencen con el prefijo especificado. Esta opción se puede especificar varias veces.

Añadido en la versión 212.

--exclude-prefix=ruta

Ignora las reglas con rutas que comiencen con el prefijo especificado. Esta opción se puede especificar varias veces.

Añadido en la versión 207.

-E

Un atajo para "--exclude-prefix=/dev --exclude-prefix=/proc --exclude-prefix=/run --exclude-prefix=/sys", es decir, excluye las jerarquías típicamente respaldadas por sistemas de archivos virtuales o en memoria. Esto es útil en combinación con --root=, si el árbol de directorios especificado contiene un árbol de sistema operativo sin estos sistemas de archivos virtuales/en memoria montados, ya que normalmente no es deseable crear ningún archivo o directorio debajo de estos subdirectorios si se supone que se montarán por encima durante la ejecución.

Añadido en la versión 247.

--root=raíz

Toma una ruta de directorio como argumento. Todas las rutas se prefijarán con la ruta alternativa de raíz dada, incluidas las rutas de búsqueda de configuración.

Cuando se utiliza esta opción, se omite el Switch de Nombre de Servicio (NSS) de libc para resolver usuarios y grupos. En su lugar, se leen directamente los archivos /etc/passwd y /etc/group dentro de la raíz alternativa. Esto significa que los usuarios/grupos no listados en estos archivos no se resolverán, es decir, no se considerarán bases de datos complejas como LDAP NIS y otras.

Considere combinar esto con -E para asegurar que la invocación no cree archivos o directorios debajo de los puntos de montaje en la imagen del sistema operativo operada que normalmente se montan por encima durante la ejecución.

Añadido en la versión 212.

--image=

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

--image=image

Toma una ruta a un archivo de imagen de disco o nodo de dispositivo de bloque. Si se especifica, todas las operaciones se aplican al sistema de archivos en la imagen de disco indicada. Esto es similar a --root= pero opera en sistemas de archivos almacenados en imágenes de disco o dispositivos de bloque. La imagen de disco debe contener solo un sistema de archivos o un conjunto de sistemas de archivos dentro de una tabla de particiones GPT, siguiendo la Especificación de Particiones Descubribles[1]. Para más información sobre imágenes de disco compatibles, consulta el modificador del mismo nombre en systemd-nspawn(1).

Implica -E.

Añadido en la versión 247.

--image-policy=policy

Toma una cadena de política de imagen como argumento, según systemd.image-policy(7). La política se aplica al operar en la imagen de disco especificada a través de --image=, ver arriba. Si no se especifica, por defecto es la política "*", es decir, se utilizan todos los sistemas de archivos reconocidos en la imagen.

--replace=RUTA

Cuando se proporciona esta opción, se debe especificar uno o más argumentos posicionales. Se leerán todos los archivos de configuración encontrados en los directorios listados en tmpfiles.d(5), y la configuración dada en la línea de comandos se manejará en lugar de y con la misma prioridad que el archivo de configuración RUTA.

Esta opción está pensada para ser utilizada cuando se ejecutan scripts de instalación de paquetes y los archivos pertenecientes a ese paquete aún no están disponibles en disco, por lo que su contenido debe proporcionarse en la línea de comandos, pero la configuración del administrador ya podría existir y debería tener mayor prioridad.

Añadido en la versión 238.

--cat-config

Copia el contenido de los archivos de configuración a la salida estándar. Antes de cada archivo, el nombre del archivo se imprime como un comentario.

--tldr

Copia el contenido de los archivos de configuración a la salida estándar. Solo se imprimen las partes "interesantes" de los archivos de configuración, se omiten los comentarios y las líneas vacías. Antes de cada archivo, el nombre del archivo se imprime como un comentario.

--no-pager

No canaliza la salida a un paginador.

-h, --help

Imprime un texto de ayuda corto y sale.

--version

Imprime una cadena de versión corta y sale.

Es posible combinar --create, --clean y --remove en una sola invocación (en cuyo caso la eliminación y la limpieza se ejecutan antes de la creación de nuevos archivos). Por ejemplo, durante el arranque se ejecuta la siguiente línea de comandos para garantizar que todos los directorios temporales y volátiles se eliminen y creen de acuerdo con el archivo de configuración:

systemd-tmpfiles --remove --create

CREDENTIALS

systemd-tmpfiles soporta la lógica de credenciales de servicio implementada por ImportCredential=/LoadCredential=/SetCredential= (ver systemd.exec(5) para detalles). Las siguientes credenciales se utilizan cuando se pasan:

tmpfiles.extra

El contenido de esta credencial puede contener líneas adicionales para operar. El contenido de la credencial debe seguir el mismo formato que cualquier otro archivo de configuración drop-in de tmpfiles.d/. Si se pasa esta credencial, se procesa después de todos los archivos drop-in leídos del sistema de archivos. Las líneas en la credencial pueden, por lo tanto, aumentar las líneas existentes del SO, pero no anularlas.

Añadido en la versión 252.

Tenga en cuenta que, por defecto, el archivo de unidad systemd-tmpfiles-setup.service (y archivos de unidad relacionados) está configurado para heredar la credencial "tmpfiles.extra" del gestor de servicios.

ENVIRONMENT

$SYSTEMD_LOG_LEVEL

El nivel máximo de registro de los mensajes emitidos (los mensajes con un nivel de registro más alto, es decir, menos importantes, serán suprimidos). Toma una lista separada por comas de valores. Un valor puede ser uno de (en orden de importancia decreciente) emerg, alert, crit, err, warning, notice, info, debug, o un entero en el rango 0...7. Ver syslog(3) para más información. Cada valor puede ir opcionalmente prefijado por uno de console, syslog, kmsg o journal seguido de dos puntos para establecer el nivel máximo de registro para ese destino de registro específico (por ejemplo, SYSTEMD_LOG_LEVEL=debug,console:info especifica registrar en nivel debug excepto cuando se registra en la consola, que debe estar en nivel info). Tenga en cuenta que el nivel máximo de registro global tiene prioridad sobre cualquier nivel máximo de registro por destino.

$SYSTEMD_LOG_COLOR

Un booleano. Si es verdadero, los mensajes escritos en la tty se colorearán según la prioridad.

Esta configuración solo es útil cuando los mensajes se escriben directamente en la terminal, porque journalctl(1) y otras herramientas que muestran los registros colorearán los mensajes basándose en el nivel de registro por sí mismas.

$SYSTEMD_LOG_TIME

Un booleano. Si es verdadero, los mensajes de registro de la consola se prefijarán con una marca de tiempo.

Esta configuración solo es útil cuando los mensajes se escriben directamente en la terminal o en un archivo, porque journalctl(1) y otras herramientas que muestran los registros adjuntarán marcas de tiempo basándose en los metadatos de la entrada por sí mismas.

$SYSTEMD_LOG_LOCATION

Un booleano. Si es verdadero, los mensajes se prefijarán con un nombre de archivo y número de línea en el código fuente donde se origina el mensaje.

Tenga en cuenta que la ubicación del registro a menudo se adjunta como metadatos a las entradas del journal de todos modos. Incluirlo directamente en el texto del mensaje puede ser conveniente al depurar programas.

$SYSTEMD_LOG_TARGET

El destino de los mensajes de registro. Uno de console (registrar en la tty conectada), console-prefixed (registrar en la tty conectada pero con prefijos que codifican el nivel de registro y la "instalación", ver syslog(3), kmsg (registrar en el búfer de registro circular del kernel), journal (registrar en el journal), journal-or-kmsg (registrar en el journal si está disponible, y en kmsg en caso contrario), auto (determinar el destino de registro apropiado automáticamente, por defecto), null (deshabilitar la salida de registro).

$SYSTEMD_PAGER, $PAGER

Paginador a utilizar cuando no se especifica --no-pager. Se utiliza $SYSTEMD_PAGER si está configurado; de lo contrario, se utiliza $PAGER. Si ni $SYSTEMD_PAGER ni $PAGER están configurados, se prueban una serie de implementaciones de paginadores conocidas en orden, incluyendo less(1) y more(1), hasta que se encuentre una. Si no se descubre ninguna implementación de paginador, no se invoca ningún paginador. Establecer estas variables de entorno a una cadena vacía o al valor "cat" es equivalente a pasar --no-pager.

Nota: si $SYSTEMD_PAGERSECURE no está configurado, $SYSTEMD_PAGER y $PAGER solo se pueden usar para deshabilitar el paginador (con "cat" o "" ), y de lo contrario se ignoran.

$SYSTEMD_LESS

Sobrescribe las opciones pasadas a less (por defecto "FRSXMK").

Los usuarios podrían querer cambiar dos opciones en particular:

K

Esta opción instruye al paginador a salir inmediatamente cuando se presiona Ctrl+C. Para permitir que less maneje Ctrl+C por sí mismo para volver al prompt de comandos del paginador, desactive esta opción.

Si el valor de $SYSTEMD_LESS no incluye "K", y el paginador que se invoca es less, Ctrl+C será ignorado por el ejecutable y deberá ser manejado por el paginador.

X

Esta opción instruye al paginador a no enviar cadenas de inicialización y desinicialización de termcap al terminal. Se establece por defecto para permitir que la salida del comando permanezca visible en el terminal incluso después de que el paginador salga. Sin embargo, esto impide que funcione cierta funcionalidad del paginador, en particular, la salida paginada no se puede desplazar con el ratón.

Tenga en cuenta que el establecimiento de la variable de entorno regular $LESS no tiene efecto para las invocaciones de less por las herramientas de systemd.

Ver less(1) para más discusión.

$SYSTEMD_LESSCHARSET

Sobrescribe el conjunto de caracteres pasado a less (por defecto "utf-8", si se determina que la terminal que invoca es compatible con UTF-8).

Tenga en cuenta que el establecimiento de la variable de entorno regular $LESSCHARSET no tiene efecto para las invocaciones de less por las herramientas de systemd.

$SYSTEMD_PAGERSECURE

Comandos de paginador comunes como less(1), además de la "paginación", es decir, desplazarse por la salida, admiten la apertura o escritura de otros archivos y la ejecución de comandos arbitrarios de shell. Cuando se invocan comandos con privilegios elevados, por ejemplo, bajo sudo(8) o pkexec(1), el paginador se convierte en un límite de seguridad. Se debe tener cuidado de que solo se utilicen programas con funcionalidad estrictamente limitada como paginadores, y no se permitan características interactivas no deseadas como la apertura o creación de nuevos archivos o el inicio de subprocesos. El "modo seguro" para el paginador puede habilitarse como se describe a continuación, si el paginador lo soporta (la mayoría de los paginadores no están escritos de manera que tengan esto en cuenta). Se recomienda habilitar explícitamente el "modo seguro" o deshabilitar completamente el paginador usando --no-pager o PAGER=cat al permitir que usuarios no confiables ejecuten comandos con privilegios elevados.

Esta opción toma un argumento booleano. Cuando se establece en verdadero, se habilita el "modo seguro" del paginador. En "modo seguro", se establecerá LESSSECURE=1 al invocar el paginador, lo que instruye al paginador a deshabilitar comandos que abren o crean nuevos archivos o inician nuevos subprocesos. Actualmente, solo se sabe que less(1) entiende esta variable e implementa el "modo seguro".

Cuando se establece en falso, no se aplica ninguna limitación al paginador. Establecer SYSTEMD_PAGERSECURE=0 o no eliminarlo del entorno heredado puede permitir al usuario invocar comandos arbitrarios.

Cuando $SYSTEMD_PAGERSECURE no está configurado, las herramientas de systemd intentan determinar automáticamente si se debe habilitar el "modo seguro" y si el paginador lo soporta. El "modo seguro" se habilita si el UID efectivo no es el mismo que el propietario de la sesión de inicio de sesión, ver geteuid(2) y sd_pid_get_owner_uid(3), o cuando se ejecuta bajo systemd-tmpfiles-clean.service(8) — systemd.258.2

SYNOPSIS

systemd-tmpfiles-clean.service, systemd-tmpfiles-clean.timer

DESCRIPTION

The systemd-tmpfiles-clean.service unit is used to clean up temporary directories. It is typically triggered by the systemd-tmpfiles-clean.timer unit, which is configured via systemd.timer(5) to run periodically.

The cleanup is controlled by configuration files in /etc/tmpfiles.d/*.conf, /usr/lib/tmpfiles.d/*.conf, and /usr/local/lib/tmpfiles.d/*.conf. Each configuration file contains a list of lines, possibly empty or starting with free-form white space. Lines starting with the character ‘#’ are commented out and ignored. An empty line or a line with only white space is ignored.

The format of the lines is:

TYPE PATH MODE UID GID AGE [ARGUMENT...]

The fields are interpreted as follows:

TYPE
A single character specifying the type of operation. Valid types are: b, c, d, f, l, r, s.
PATH
The path for the operation. This path must be absolute. If the path contains globbing characters (e.g. ‘*’, ‘?’, ‘[’), it is expanded using fnmatch(). If the path does not start with a slash, it is made absolute using the current working directory. This is usually not intended and might lead to unexpected results.
MODE
The file mode/permissions for f, l, d, s, c, and b types. This is an octal representation of the mode. If the string starts with a character other than a digit, the mode is not set. For r and D types, this field is ignored.
UID
The user name or UID for f, l, d, s, c, and b types. If this is empty, the file is not own. If the string starts with a character other than a digit, the UID is not set.
GID
The group name or GID for f, l, d, s, c, and b types. If this is empty, the file is not own. If the string starts with a character other than a digit, the GID is not set.
AGE
An age specification for f, r, D, and d types. The age is specified in days. The file or directory is only affected if its last access time (for files) or metadata change time (for directories) is older than the specified age. If the field is empty, the file is not removed. The special value never may be used to disable removal.
ARGUMENT
Additional arguments for certain types. For f, r, D, and d types, this field is the maximum size specification. If the file or directory exceeds this size, it is truncated or removed. The size is specified in bytes, or with k, M, G, T, P, E, Z, Y suffixes for KiB, MiB, GiB, etc.

The valid types are:

b c d f l s
Create a file or directory. The type character specifies the type of the file to create: b for block devices, c for character devices, d for directories, f for regular files, l for symbolic links, and s for sockets. If the file already exists, it is not modified (unless the path is prefixed with +).
r
Remove a file or directory. If the path is a symbolic link, the link itself is removed. If it is a directory, it must be empty. If the path does not exist, it is ignored. If the path is prefixed with +, directories are removed recursively.
D
Remove a directory and its contents recursively. This is a shortcut for +r. If the path does not exist, it is ignored.
z
Set the SELinux security context of the file or directory. This is mostly useful for files that are created by systemd-tmpfiles itself. The z command requires the PATH, MODE, UID, and GID fields.
Z
Set the SELinux security context of the file or directory and reset all other attributes (ownership, permissions, timestamps) to the defaults. This is mostly useful for files that are created by systemd-tmpfiles itself. The Z command requires the PATH, MODE, UID, and GID fields.

Paths may be prefixed with + to indicate that the operation should be performed even if the path already exists. This is useful for creating files or directories that might already exist.

The systemd-tmpfiles-clean.timer unit is enabled by default and runs daily. The timer can be controlled like any other systemd timer unit (e.g. using systemctl(1)).

COMMANDS AND OPTIONS

The systemd-tmpfiles command itself is used to perform the cleanup operations. It is typically run via the systemd-tmpfiles-clean.service unit. The command accepts the following options:

--clean
Clean up temporary directories. This is the default operation.
--create
Create temporary files and directories.
--remove
Remove temporary files and directories.
--verify
Verify the state of temporary files and directories.
--appliance-mode
Run in appliance mode, where only essential cleanup is performed.
--exclude=PATTERN
Exclude paths matching PATTERN from cleanup.
--preservable=PATTERN
Mark paths matching PATTERN as preservable. These paths will not be cleaned up.
--root=ROOT
Operate on a different directory tree ROOT.
--chroot=CHROOT
Chroot to CHROOT before operating.

CREDENTIALS

When running as root, systemd-tmpfiles does not drop any privileges. It is recommended to run it in a restricted environment or with minimal privileges.

ENVIRONMENT

$SYSTEMD_PAGER, $PAGER: Controls the pager used for output. If unset, a default pager is used. If set to an empty string or cat, no pager is used.

$SYSTEMD_PAGERSECURE: Controls whether the pager is allowed to be used. If set to 1, the pager will not be used if the user is not the owner of the terminal or if the terminal is not configured to allow access. This is intended to prevent security issues when running commands as root using tools like sudo(8) or similar tools ($SUDO_UID is set [2]). In those cases, SYSTEMD_PAGERSECURE=1 will be set and pagers which are not known to implement "secure mode" will not be used at all. Note that this autodetection only covers the most common mechanisms to elevate privileges and is intended as convenience. It is recommended to explicitly set $SYSTEMD_PAGERSECURE or disable the pager.

Note that if the $SYSTEMD_PAGER or $PAGER variables are to be honoured, other than to disable the pager, $SYSTEMD_PAGERSECURE must be set too.

$SYSTEMD_COLORS: Takes a boolean argument. When true, systemd and related utilities will use colors in their output, otherwise the output will be monochrome. Additionally, the variable can take one of the following special values: "16", "256" to restrict the use of colors to the base 16 or 256 ANSI colors, respectively. This can be specified to override the automatic decision based on $TERM and what the console is connected to.

$SYSTEMD_URLIFY: The value must be a boolean. Controls whether clickable links should be generated in the output for terminal emulators supporting this. This can be specified to override the decision that systemd makes based on $TERM and other conditions.

UNPRIVILEGED --CLEANUP OPERATION

systemd-tmpfiles tries to avoid changing the access and modification times on the directories it accesses, which requires CAP_FOWNER privileges. When running as non-root, directories which are checked for files to clean up will have their access time bumped, which might prevent their cleanup.

EXIT STATUS

On success, 0 is returned. If the configuration was syntactically invalid (syntax errors, missing arguments, ...), so some lines had to be ignored, but no other errors occurred, 65 is returned (EX_DATAERR from /usr/include/sysexits.h). If the configuration was syntactically valid, but could not be executed (lack of permissions, creation of files in missing directories, invalid contents when writing to /sys/ values, ...), 73 is returned (EX_CANTCREAT from /usr/include/sysexits.h). Otherwise, 1 is returned (EXIT_FAILURE from /usr/include/stdlib.h).

Note: when creating items, if the target already exists, but is of the wrong type or otherwise does not match the requested state, and forced operation has not been requested with "+", a message is emitted, but the failure is otherwise ignored.
