NOMBRE

systemd-sysupdate, systemd-sysupdate.service, systemd-sysupdate.timer, systemd-sysupdate-reboot.service, systemd-sysupdate-reboot.timer - Actualiza automáticamente el SO u otros recursos

SINOPSIS

systemd-sysupdate [OPCIONES...]

systemd-sysupdate.service

DESCRIPCIÓN

systemd-sysupdate actualiza atómicamente el SO del host, imágenes de contenedor, imágenes de servicio portátiles u otras fuentes, basándose en los archivos de configuración de transferencia descritos en sysupdate.d(5).

Esta herramienta implementa esquemas de actualización basados en archivos, directorios o particiones, admitiendo múltiples versiones instaladas en paralelo de recursos específicos al estilo A/B (o incluso: A/B/C, A/B/C/D/...). La actualización A/B significa que cuando una versión de un recurso se está utilizando actualmente, la siguiente versión puede descargarse, desempaquetarse y prepararse en una ubicación completamente separada, independientemente de la primera y — una vez completada — se puede activar, intercambiando los roles para que se convierta en la utilizada y la previamente utilizada se reemplace por la siguiente actualización, y así sucesivamente. Los recursos a actualizar se definen en archivos de transferencia, uno para cada recurso a actualizar. Por ejemplo, los recursos que se pueden actualizar con esta herramienta podrían ser: una partición del sistema de archivos raíz, una partición Verity correspondiente más una imagen del kernel. La combinación de los tres se consideraría una actualización completa del SO.

La herramienta actualiza particiones, archivos o árboles de directorios siempre en su totalidad, y opera con al menos dos versiones de cada uno de estos recursos: la versión actual, más la versión siguiente: la que se está actualizando, y que inicialmente está incompleta ya que los datos descargados se escriben en ella; más versiones adicionales opcionalmente. Una vez completada la descarga de una versión más nueva, se convierte en la versión actual, liberando la versión previamente considerada actual para su eliminación/reemplazo/actualización.

Al instalar nuevas versiones, la herramienta descargará, descomprimirá, desempaquetará y escribirá directamente la nueva versión en el destino. Esto se hace de manera robusta para que una descarga incompleta se pueda reconocer en la siguiente invocación, y se elimine antes de que se inicie un nuevo intento.

Tenga en cuenta que al escribir actualizaciones en una partición, la partición debe existir previamente, ya que systemd-sysupdate no creará automáticamente nuevas particiones. Utilice una herramienta como systemd-repart(8) para crear automáticamente particiones adicionales para usarlas con systemd-sysupdate al arrancar.

La herramienta puede usarse tanto en el SO en ejecución, para actualizar el SO en estado "en línea" desde sí mismo, como en imágenes de disco "fuera de línea", para actualizarlas desde el exterior basándose en archivos de transferencia incrustados en las imágenes de disco. Para esto último, consulte --image= a continuación. Esto último es particularmente interesante para actualizar imágenes de contenedor o imágenes de servicio portátiles.

El servicio del sistema systemd-sysupdate.service actualizará automáticamente el SO del host basándose en los archivos de transferencia instalados. Se activa en intervalos regulares a través de systemd-sysupdate.timer. El systemd-sysupdate-reboot.service reiniciará automáticamente el sistema después de instalar una nueva versión. Se activa a través de systemd-sysupdate-reboot.timer. Los dos servicios son independientes entre sí, ya que generalmente es aconsejable descargar actualizaciones regularmente mientras el sistema está activo, pero retrasar los reinicios hasta el momento adecuado (es decir, típicamente durante la noche). Los dos conjuntos de unidades de servicio/temporizador pueden habilitarse por separado.

Para obtener detalles sobre los archivos de transferencia y ejemplos, consulte sysupdate.d(5).

COMANDO

Se entienden los siguientes comandos:

list [VERSIÓN]

Si se invoca sin argumento, enumera las versiones descargables e instaladas, y muestra una tabla resumen con las versiones descubiertas y sus propiedades, incluido si hay una versión candidata más nueva a la que actualizar. Si se especifica un argumento de versión, muestra detalles sobre la versión específica, incluidos los archivos individuales que necesitan transferirse para adquirir la versión.

Si no se especifica explícitamente ningún comando, este comando se asume.

Añadido en la versión 251.

features [FEATURE]

Si se invoca sin argumento, enumera las características opcionales y muestra una tabla resumen, incluyendo qué características están activadas o desactivadas. Si se especifica un argumento de característica, muestra detalles sobre la característica específica, incluyendo las transferencias que son controladas por la característica.

Añadido en la versión 257.

check-new

Comprueba si hay una nueva versión disponible. Esto enumera internamente las versiones descargables e instaladas y devuelve el estado de salida 0 si hay una nueva versión a la que actualizar, de lo contrario no cero. Si hay una nueva versión a la que actualizar, su identificador de versión se escribirá en la salida estándar.

Añadido en la versión 251.

update [VERSIÓN]

Instala (actualiza a) la versión especificada, o si no se especifica ninguna, a la versión más nueva disponible. Si la versión ya está instalada o no hay una versión más nueva disponible, no se realiza ninguna operación.

Si se encuentra una nueva versión para instalar/actualizar, las versiones antiguas instaladas se eliminarán hasta que se pueda instalar al menos una nueva versión, según lo configurado a través de InstanceMax= en sysupdate.d(5), o a través de las ranuras de partición disponibles del tipo correcto. Esta operación implícita también se puede invocar explícitamente a través del comando vacuum descrito a continuación.

Añadido en la versión 251.

vacuum

Elimina versiones instaladas antiguas hasta que se cumplan nuevamente los límites configurados a través de InstanceMax= en sysupdate.d(5). Normalmente, no debería ser necesario invocar este comando explícitamente, ya que se invoca implícitamente cada vez que se inicia una nueva actualización.

Añadido en la versión 251.

pending

Comprueba si se ha instalado una versión más nueva del SO que la que se está ejecutando actualmente. Devuelve cero si es así, de lo contrario no cero. Esto compara el identificador de la versión más nueva instalada con la versión de la imagen del SO según lo informado por el campo IMAGE_VERSION= en /etc/os-release. Si el primero es más nuevo que el segundo, aparentemente se completó una actualización pero aún no se activó (es decir, se reinició).

Añadido en la versión 251.

reboot

Similar al comando pending pero reinicia inmediatamente en caso de que se haya instalado una versión más nueva del SO que la que se está ejecutando actualmente. Esta operación se puede hacer implícitamente junto con el comando update, después de una actualización completada a través del interruptor --reboot, ver más abajo. Este comando no ejecutará ninguna operación (y devolverá éxito) si no se ha instalado ninguna actualización, y por lo tanto el sistema no se ha reiniciado.

Añadido en la versión 251.

components

Enumera los componentes que se pueden actualizar. Esto enumera los directorios /etc/sysupdate.*.d/, /run/sysupdate.*.d/ y /usr/lib/sysupdate.*.d/ que contienen archivos de transferencia. Este comando es útil para enumerar posibles parámetros para --component= (ver más abajo).

Añadido en la versión 251.

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.

OPCIONES

Se entienden las siguientes opciones:

--component=, -C

Selecciona el componente a actualizar. Toma un nombre de componente como argumento. Esto tiene el efecto de alterar ligeramente la lógica de búsqueda de archivos de transferencia. Si no se usa este interruptor, los archivos de transferencia se cargan de /etc/sysupdate.d/*.conf, /run/sysupdate.d/*.conf y /usr/lib/sysupdate.d/*.conf. Si se usa este interruptor, el nombre de componente especificado se utiliza para alterar los directorios a buscar, siendo /etc/sysupdate.componente.d/*.conf, /run/sysupdate.componente.d/*.conf y /usr/lib/sysupdate.componente.d/*.conf, cada vez con la cadena componente reemplazada por el nombre de componente especificado.

Utilice el comando components para enumerar los componentes disponibles para actualizar. Esto enumera los directorios que coinciden con esta regla de nomenclatura.

NAME

systemd-sysupdate.timer, systemd-sysupdate.service - update resources

SYNOPSIS

systemd-sysupdate.service

systemd-sysupdate.timer

DESCRIPTION

The systemd-sysupdate service is a general-purpose utility to update system resources. It is designed to fetch, verify, and install updates for various parts of the operating system, such as the kernel, boot loader, or firmware. It may be triggered by the systemd-sysupdate.timer unit, or invoked manually. The configuration for updates is managed through files in /usr/lib/sysupdate.d/*.conf, /etc/sysupdate.d/*.conf, and /run/sysupdate.d/*.conf.

The service operates by processing a set of resource definitions, each specifying how to obtain and verify a particular resource. These definitions can be provided via configuration files or command-line options.

COMMAND

The primary command used with systemd-sysupdate is systemd-sysupdate itself. It accepts various options and commands to control its behavior.

OPTIONS

COMMAND

The following commands are available:

update
Fetches and installs updates for the configured resources.
list
Lists the available and installed versions of the configured resources.
cleanup
Removes old versions of resources, keeping only the number specified by --instances-max=.
verify
Verifies the integrity of the installed resources.

Additional options:

--component=
Limit operations to the specified component. This option may be used multiple times to specify multiple components. If this option is specified, only definitions for these components are loaded. This option may not be combined with --definitions=.
Added in version 251.
--definitions=
A path to a directory. If specified, the transfer *.conf files are read from this directory instead of /usr/lib/sysupdate.d/*.conf, /etc/sysupdate.d/*.conf, and /run/sysupdate.d/*.conf. This option may not be combined with --component=.
Added in version 251.
--root=
Takes a path to a directory to use as root file system when searching for sysupdate.d/*.conf files. Added in version 251.
--image=
Takes a path to a disk image file or device to mount and use in a similar fashion to --root=, see above. If this is used and partition resources are updated this is done inside the specified disk image. Added in version 251.
--image-policy=policy
Takes an image policy string as argument, as per systemd.image-policy(7). The policy is enforced when operating on the disk image specified via --image=, see above. If not specified, defaults to the "*" policy, i.e. all recognized file systems in the image are used.
--instances-max=, -m
Takes a decimal integer greater than or equal to 2 while updating or 1 while vacuuming. Controls how many versions to keep at any time. This option may also be configured inside the transfer files, via the InstancesMax= setting, see sysupdate.d(5) for details. Added in version 251.
--sync=
Takes a boolean argument, defaults to yes. This may be used to specify whether the newly updated resource versions shall be synchronized to disk when appropriate (i.e. after the download is complete, before it is finalized, and again after finalization). This should not be turned off, except to improve runtime performance in testing environments. Added in version 251.
--verify=
Takes a boolean argument, defaults to yes. Controls whether to cryptographically verify downloads. Do not turn this off, except in testing environments. Added in version 251.
--reboot
When used in combination with the update command and a new version is installed, automatically reboots the system immediately afterwards. Added in version 251.
--offline
Prevents fetching metadata from the network (i.e. SHA256SUMS). This is most useful when used in combination with the list command, to query locally installed versions. Added in version 257.
--transfer-source=
Takes a path as its argument. When specified, all transfer sources configured with PathRelativeTo=explicit will be interpreted relative to the specified path. Added in version 257.
--no-pager
Do not pipe output into a pager.
--no-legend
Do not print the legend, i.e. column headers and the footer with hints.
--json=MODE
Shows output formatted as JSON. Expects one of "short" (for the shortest possible output without any redundant whitespace or line breaks), "pretty" (for a pretty version of the same, with indentation and line breaks) or "off" (to turn off JSON output, the default).

EXIT STATUS

On success, 0 is returned, a non-zero failure code otherwise.
