NOMBRE

syncthing-event-api - API de eventos

DESCRIPCIÓN

Syncthing proporciona una interfaz simple de sondeo largo para exponer eventos desde la utilidad principal hacia una GUI. Para recibir eventos, consulta GET /rest/events.

ESTRUCTURA DE EVENTOS

Cada evento se representa mediante un objeto similar al siguiente:

{
    "id": 2,
    "globalID": 3,
    "type": "DeviceConnected",
    "time": "2014-07-13T21:04:33.687836696+02:00",
    "data": {
        "addr": "172.16.32.25:22000",
        "id": "NFGKEKE-7Z6RTH7-I3PRZXS-DEJF3UJ-FRWJBFO-VBBTDND-4SGNGVZ-QUQHJAG"
    }
}

Las claves de nivel superior id, globalID, time, type y data siempre están presentes, aunque data puede ser null.

id
Un ID único para este evento en la API de eventos. Siempre aumenta en 1: el primer evento generado tiene el ID 1, el siguiente tiene el ID 2, etc. Si esto aumenta en más de 1, significa que uno o más eventos han sido omitidos por la API de eventos.
globalID
Un ID global para este evento, a través de la API de eventos, el registro de auditoría y cualquier otra fuente. Puede aumentar en más de 1, pero siempre será mayor o igual al id.
time
La hora en que se generó el evento.
type
Indica el tipo de (es decir, la razón de) el evento y es uno de los tipos de evento a continuación.
data
Un objeto que contiene información adicional opcional; la estructura exacta está determinada por el tipo de evento.

TIPOS DE EVENTOS

ClusterConfigReceived

Añadido en la versión 1.20.0.

El evento ClusterConfigReceived se emite después de procesar dicho mensaje de protocolo recibido de un dispositivo remoto. Se utiliza principalmente para fines internos.

{
    "id": 84,
    "globalID": 84,
    "type": "ClusterConfigReceived",
    "time": "2022-04-27T14:14:27.043576583+09:00",
    "data": {
        "device": "I6KAH76-66SLLLB-5PFXSOA-UFJCDZC-YAOMLEK-CP2GB32-BV5RQST-3PSROAU"
    }
}

DeviceDisconnected

Generado cada vez que se ha terminado una conexión con un dispositivo.

{
    "id": 48,
    "globalID": 48,
    "type": "DeviceDisconnected",
    "time": "2014-07-13T21:18:52.859929215+02:00",
    "data": {
        "error": "EOF inesperado",
        "id": "NFGKEKE-7Z6RTH7-I3PRZXS-DEJF3UJ-FRWJBFO-VBBTDND-4SGNGVZ-QUQHJAG"
    }
}

NOTA:

La clave error contiene la causa de la desconexión, que podría no ser necesariamente un error como tal. Específicamente, “EOF” y “EOF inesperado” significan terminación de la conexión TCP, ya sea porque el otro dispositivo se reinició, se desconectó o debido a un cambio en la red.

DownloadProgress

Emitido durante las descargas de archivos para cada carpeta, para cada archivo. Por defecto, solo se maneja un archivo en una carpeta a la vez, pero una configuración personalizada puede hacer que se muestren varios archivos.

{
    "id": 221,
    "globalID": 221,
    "type": "DownloadProgress",
    "time": "2014-12-13T00:26:12.9876937Z",
    "data": {
        "folder1": {
            "file1": {
                "total": 800,
                "pulling": 2,
                "copiedFromOrigin": 0,
                "reuse": 0,
                "need": 800,
                "inLagSupported": false,
                "inLag": 0,
                "outLagSupported": false,
                "outLag": 0,
                "globalName": "/file1",
                "localName": "/file1"
            }
        }
    }
}

The keys total, pulling, copiedFromOrigin, reuse, need, inLagSupported, inLag, outLagSupported and outLag are all optional and only present if the value is known.

FolderCompleted

Emitido cuando la sincronización de una carpeta se ha completado. Esto ocurre cuando no quedan archivos por descargar.

{

    "globalID": 51,
    "type": "FolderCompleted",
    "time": "2014-12-13T00:09:13.5166486Z",
    "data": {
        "folder": "my-folder-id",
        "totalChange": 7
    }
}

FolderErrors

Emitido cuando hay un error en una carpeta. Todos los detalles necesarios para la depuración se incluyen en el objeto data.

{
    "id": 54,
    "globalID": 54,
    "type": "FolderErrors",
    "time": "2014-12-13T00:26:13.000012345Z",
    "data": {
        "folder": "my-folder-id",
        "file": "/a/bad/file",
        "error": "Permission denied",
        "fatal": false
    }
}

If fatal is true, then the folder has been ignored. Any subsequent changes to the file will be ignored.

{
    "id": 55,
    "globalID": 55,
    "type": "FolderErrors",
    "time": "2014-12-13T00:26:13.000012345Z",
    "data": {
        "folder": "my-folder-id",
        "file": "/another/bad/file",
        "error": "No such file or directory",
        "fatal": true
    }
}

VER TAMBIÉN

syncthing(1)

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

{ "id": 83, "globalID": 83, "type": "FileProgress", "time": "2022-04-27T14:14:27.043576583+09:00", "data": { "folder": "default", "file": "folder1/file1", "progress": { "total": 800, "pulling": 2, "copiedFromOrigin": 0, "reused": 633, "copiedFromElsewhere": 0, "pulled": 38, "bytesTotal": 104792064, "bytesDone": 87883776 } } }, { "id": 83, "globalID": 83, "type": "FileProgress", "time": "2022-04-27T14:14:27.043576583+09:00", "data": { "folder": "default", "file": "folder1/dir\\file2", "progress": { "total": 80, "pulling": 2, "copiedFromOrigin": 0, "reused": 0, "copiedFromElsewhere": 0, "pulled": 32, "bytesTotal": 10420224, "bytesDone": 4128768 } } }, { "id": 83, "globalID": 83, "type": "FileProgress", "time": "2022-04-27T14:14:27.043576583+09:00", "data": { "folder": "default", "file": "folder2/file3", "progress": { "total": 800, "pulling": 2, "copiedFromOrigin": 0, "reused": 633, "copiedFromElsewhere": 0, "pulled": 38, "bytesTotal": 104792064, "bytesDone": 87883776 } } }, { "id": 83, "globalID": 83, "type": "FileProgress", "time": "2022-04-27T14:14:27.043576583+09:00", "data": { "folder": "default", "file": "folder2/dir\\file4", "progress": { "total": 80, "pulling": 2, "copiedFromOrigin": 0, "reused": 0, "copiedFromElsewhere": 0, "pulled": 32, "bytesTotal": 10420224, "bytesDone": 4128768 } } } ```
  • total - número total de bloques del archivo
  • pulling - número de bloques que se están descargando actualmente
  • copiedFromOrigin - número de bloques copiados del archivo que vamos a reemplazar
  • reused - número de bloques reutilizados de un archivo temporal anterior
  • copiedFromElsewhere - número de bloques copiados de otros archivos o posiblemente de otras carpetas
  • pulled - número de bloques realmente descargados hasta ahora
  • bytesTotal - tamaño total aproximado del archivo
  • bytesDone - número aproximado de bytes ya manejados (reutilizados, copiados o descargados)

Donde el tamaño del bloque es 128KB.

Los archivos/carpetas que aparecen en los datos del evento implican que la descarga se ha iniciado para ese archivo/carpeta, mientras que su desaparición implica que las descargas han finalizado o fallado para ese archivo/carpeta. Siempre se emite un último evento sin datos, lo que implica que todas las descargas han finalizado/fallado.

Fallo

Generado para errores específicos que también se enviarán al servidor de informes de uso, si está habilitado en la configuración. Estos suelen ser de especial interés para los desarrolladores para solucionar errores complejos. El campo data contiene un mensaje de error textual.

{
  "id": 93,
  "globalID": 93,
  "type": "Failure",
  "time": "2021-06-07T21:22:03.414609034+02:00",
  "data": "el manejador de índice se puso en pausa mientras ya estaba en pausa"
}

CompletadoDeCarpeta

El evento FolderCompletion se emite cuando el contenido local o remoto de una carpeta cambia. Contiene el porcentaje de finalización para un dispositivo remoto dado y se emite una vez por cada dispositivo remoto conectado actualmente.

Añadido en la versión 1.20.0: Indicación de si el dispositivo remoto ha aceptado la carpeta (la comparte con nosotros) y si está en pausa. El campo remoteState es unknown cuando el dispositivo remoto no está conectado. De lo contrario, puede ser paused, notSharing, o valid si el remoto está compartiendo de vuelta.

{
    "id": 84,
    "globalID": 84,
    "type": "FolderCompletion",
    "time": "2022-04-27T14:14:27.043576583+09:00",
    "data": {
        "completion": 100,
        "device": "I6KAH76-66SLLLB-5PFXSOA-UFJCDZC-YAOMLEK-CP2GB32-BV5RQST-3PSROAU",
        "folder": "default",
        "globalBytes": 17,
        "globalItems": 4,
        "needBytes": 0,
        "needDeletes": 0,
        "needItems": 0,
        "remoteState": "valid",
        "sequence": 12
    }
}

ErroresDeCarpeta

El evento FolderErrors se emite cuando una carpeta no puede sincronizarse correctamente. El evento contiene el ID de la carpeta afectada y una lista de errores para archivos o directorios dentro de ella. Esta lista de errores queda obsoleta una vez que la carpeta cambia su estado a syncing; si los errores persisten después del próximo intento de sincronización, se emite un nuevo evento FolderErrors.

{
    "id": 132,
    "type": "FolderErrors",
    "time": "2015-06-26T13:39:24.697401384+02:00",
    "data": {
        "errors": [
            {
                "error": "abrir /Users/jb/src/github.com/syncthing/syncthing/test/s2/h2j/.syncthing.aslkjd.tmp: permiso denegado",
                "path": "h2j/aslkjd"
            }
        ],
        "folder": "default"
    }
}

Añadido en la versión 0.11.12.

LocalChangeDetected

Generado en cada escaneo cuando el disco local ha descubierto un archivo actualizado desde el escaneo anterior. Esto *no* incluye eventos descubiertos y copiados de otros dispositivos (RemoteChangeDetected), solo archivos que fueron cambiados en el sistema de archivos local.

LoginAttempt

Cuando la autenticación está habilitada para la GUI, este evento se emite en cada intento de inicio de sesión. Si el nombre de usuario o la contraseña son incorrectos, success es falso y en cualquier caso se devuelve el nombre de usuario proporcionado.

{
   "id" : 187,
   "time" : "2017-03-07T00:19:24.420386143+01:00",
   "data" : {
      "remoteAddress" : "127.0.0.1",
      "username" : "somename",
      "success" : false
   },
   "type" : "LoginAttempt",
   "globalID" : 195
}

Si la cabecera X-Forwared-For está presente y el host conectado está en localhost o en la misma LAN, se tratará como un proxy inverso. En este caso, el campo remoteAddress se rellena con la dirección IP más a la izquierda de la cabecera, y el campo adicional proxy conserva la IP original del host conectado.

{
   "id" : 187,
   "time" : "2017-03-07T00:19:24.420386143+01:00",
   "data" : {
      "proxy" : "127.0.0.1",
      "remoteAddress" : "192.168.178.10",
      "username" : "somename",
      "success" : false
   },
   "type" : "LoginAttempt",
   "globalID" : 195
}
