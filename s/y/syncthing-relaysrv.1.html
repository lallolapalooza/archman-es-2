STRELAYSRV(1) Syncthing STRELAYSRV(1)

NOMBRE

strelaysrv - Servidor de retransmisión Syncthing

SINOPSIS

OPCIONES

-debug
Habilita la salida de depuración.
-ext-address=<dirección>
Una dirección opcional para anunciar como disponible. Permite escuchar en un puerto no privilegiado con reenvío de puertos desde, por ejemplo, el puerto 443, y ser conectado en el puerto 443.
-global-rate=<bytes/s>
Límite de velocidad global, en bytes/s.
-keys=<dir>
Directorio donde se almacenan cert.pem y key.pem (por defecto “.”).
-listen=<dirección de escucha>
Dirección de escucha del protocolo (por defecto “:22067”).
-message-timeout=<duración>
Tiempo máximo que esperamos a que lleguen mensajes relevantes (por defecto 1m0s).
-nat
Usa UPnP/NAT-PMP para obtener mapeo de puertos externo
-nat-lease=<duración>
Duración del lease NAT en minutos (por defecto 60)
-nat-renewal=<duración>
Frecuencia de renovación NAT en minutos (por defecto 30)
-nat-timeout=<duración>
Tiempo de espera del descubrimiento NAT en segundos (por defecto 10)
-network-timeout=<duración>
Tiempo de espera para operaciones de red entre el cliente y el relé. Si no se reciben datos entre el cliente y el relé en este período de tiempo, la conexión se termina. Además, si no se envían datos entre ninguno de los clientes retransmitidos dentro de este período de tiempo, la sesión también se termina. (por defecto 2m0s)
-per-session-rate=<bytes/s>
Límite de velocidad por sesión, en bytes/s.
-ping-interval=<duración>
Con qué frecuencia se envían los pings (por defecto 1m0s).
-pools=<direcciones de pools>
Lista separada por comas de direcciones de pools de retransmisión a unirse (por defecto “https://relays.syncthing.net/endpoint”). En blanco para deshabilitar el anuncio a un pool, permaneciendo así como una retransmisión privada.
-pprof
Habilita el perfilado integrado en el servidor de estado
-protocol=<cadena>
Protocolo utilizado para escuchar. ‘tcp’ para IPv4 e IPv6, ‘tcp4’ para IPv4, ‘tcp6’ para IPv6 (por defecto “tcp”).
-provided-by=<cadena>
Una descripción opcional sobre quién proporciona la retransmisión.
-status-srv=<dirección de escucha>
Dirección de escucha para el servicio de estado (en blanco para deshabilitar) (por defecto “:22070”). El servicio de estado es utilizado por la interfaz del servidor del pool de retransmisiones para mostrar estadísticas (datos transferidos, número de clientes, etc.)
-token=<cadena>
Token para restringir el acceso a la retransmisión (opcional). Deshabilita la unión a cualquier pool.
-version
Mostrar versión

Instalación

CONFIGURACIÓN

Principalmente, necesitas decidir un directorio para almacenar la clave y el certificado TLS, y un puerto de escucha. El puerto de escucha predeterminado de 22067 funciona, pero para una compatibilidad óptima se recomienda un puerto conocido para tráfico cifrado como el 443. Esto puede requerir una configuración adicional para funcionar sin ejecutar como root o un usuario privilegiado, consulta Ejecución en el puerto 443 como un usuario no privilegiado a continuación. En principio, algo similar a esto debería funcionar en un sistema Linux/Unix:

$ sudo useradd strelaysrv
$ sudo mkdir /etc/strelaysrv
$ sudo chown strelaysrv /etc/strelaysrv
$ sudo -u strelaysrv /usr/local/bin/strelaysrv -keys /etc/strelaysrv

Esto crea un usuario strelaysrv y un directorio /etc/strelaysrv para almacenar las claves. Las claves se generan en el primer inicio. El relé se unirá al pool global de retransmisiones, a menos que se proporcione un argumento -pools="".

Para que el servidor de retransmisión se inicie automáticamente al arrancar, utiliza el procedimiento recomendado para tu sistema operativo.

Configuración del cliente

Syncthing se puede configurar para utilizar servidores de retransmisión específicos (exclusivamente del pool público) añadiendo los servidores requeridos al campo Dirección de Escucha de Protocolo Sync, en Acciones y Configuración. El formato es el siguiente:

relay://<nombre de host|IP>[:puerto]/?id=<ID del dispositivo de retransmisión>

Por ejemplo:

relay://private-relay-1.exam

syncthing-relaysrv(1) — Syncthing Relay Server

NAME

strelaysrv

Syncthing relay server

SYNOPSIS

strelaysrv [-h] [-url URL] [-listen address] [-ext-address address] [-status-srv address] [-logfile path] [-version] [-gui] [-gui-address address]

DESCRIPTION

The Syncthing relay server allows devices to connect to each other when direct connection is not possible. This is often the case when one or both devices are behind NAT or a firewall. The relay server does not inspect or modify traffic, it simply forwards packets between devices.

The relay server needs to be reachable from the internet. The Syncthing discovery server (a globally distributed set of servers) will tell devices to connect to your relay if direct connection fails.

The relay server is identified by its device ID, which is printed on start-up. This ID is used by devices to refer to the relay.

OPTIONS

-h
Show help message.
-url URL
The URL of the Syncthing discovery server. Defaults to https://discovery.syncthing.net/.
-listen address
Address and port to listen on for incoming connections. Defaults to :22067.
-ext-address address
The external address and port of the relay server. This is the address that other Syncthing devices will use to connect to the relay. Defaults to the value of -listen.
-status-srv address
Address and port to listen on for providing public statistics. Defaults to :22070. If set to empty string ("") statistics service is disabled.
-logfile path
File to log to. If empty, logging is sent to stderr.
-version
Show version.
-gui
Enable the built-in web GUI. Not enabled by default.
-gui-address address
Address and port for the web GUI. Defaults to 127.0.0.1:8443. Requires -gui to be set.

SETTING UP

To set up a relay server, you typically run the command with default options:

$ strelaysrv

This will start the relay server listening on port 22067 for data connections and port 22070 for status updates. The relay's device ID will be output on start-up.

Relay device ID: 8G24KUI-CSGQM6Z-46J6R43-74B7Q5M-6XAQB3S-VQRQ7K4-M64S74B-P5472XF

You can then configure your Syncthing devices to use this relay by adding the following to your Syncthing configuration:

relay://8G24KUI-CSGQM6Z-46J6R43-74B7Q5M-6XAQB3S-VQRQ7K4-M64S74B-P5472XF@ple.com:443/?id=ITZRNXE-YNROGBZ-HXTH5P7-VK5NYE5-QHRQGE2-7JQ6VNJ-KZUEDIU-5PPR5AM

The relay's device ID is output on start-up.

Running on port 443 as an unprivileged user

It is recommended that you run the relay on port 443 (or another port which is commonly allowed through corporate firewalls), in order to maximise the chances that people are able to connect. However, binding to ports below 1024 requires root privileges, and running a relay as root is not recommended. Thankfully there are a couple of approaches available to you.

One option is to run the relay on port 22067, and use an iptables rule to forward traffic from port 443 to port 22067, for example:

iptables -t nat -A PREROUTING -p tcp --dport 443 -j REDIRECT --to-port 22067

Or, if you’re using ufw, add the following to /etc/ufw/before.rules:

*nat
:PREROUTING ACCEPT [0:0]
:POSTROUTING ACCEPT [0:0]
-A PREROUTING -p tcp --dport 443 -j REDIRECT --to-port 22067
COMMIT

You will need to start strelaysrv with -ext-address ":443". This tells strelaysrv that it can be contacted on port 443, even though it is listening on port 22067. You will also need to let both port 443 and 22067 through your firewall.

FIREWALL CONSIDERATIONS

  • Data port: 22067/tcp overridden with -listen and advertised with -ext-address
  • Status port: 22070/tcp overridden with -status-srv

Runtime iptables rules to allow access to the default ports:

iptables -I INPUT -p tcp --dport 22067 -j ACCEPT
iptables -I INPUT -p tcp --dport 22070 -j ACCEPT

Please consult Linux distribution documentation to persist firewall rules.

ACCESS CONTROL FOR PRIVATE RELAYS

Added in version 1.22.1.

Private relays can be configured to only accept connections from peers in possession of a shared secret. To configure this use the -token option:

$ strelaysrv -token=mySecretToken

Then configure your Syncthing devices to send the token when joining the relay:

relay://<host name|IP>[:port]/?id=<relay device ID>&token=mySecretToken
