NOMBRE

systemd-dissect, mount.ddi - Analizar imágenes de disco descubribles (DDIs)

SINOPSIS

systemd-dissect [OPCIONES...] IMAGEN

systemd-dissect [OPCIONES...] [--mount] IMAGEN RUTA

systemd-dissect [OPCIONES...] [--umount] RUTA

systemd-dissect [OPCIONES...] [--attach] IMAGEN

systemd-dissect [OPCIONES...] [--detach] RUTA

systemd-dissect [OPCIONES...] [--list] IMAGEN

systemd-dissect [OPCIONES...] [--mtree] IMAGEN

systemd-dissect [OPCIONES...] [--with] IMAGEN [COMANDO...]

systemd-dissect [OPCIONES...] [--copy-from] IMAGEN RUTA [DESTINO]

systemd-dissect [OPCIONES...] [--copy-to] IMAGEN [ORIGEN] RUTA

systemd-dissect [OPCIONES...] [--make-archive] IMAGEN [DESTINO]

systemd-dissect [OPCIONES...] [--discover]

systemd-dissect [OPCIONES...] [--validate] IMAGEN

systemd-dissect [OPCIONES...] [--shift] IMAGEN UIDBASE

DESCRIPCIÓN

systemd-dissect es una herramienta para inspeccionar e interactuar con imágenes de disco de sistemas operativos, específicamente Imágenes de Disco Descubribles (DDIs). Soporta cuatro operaciones diferentes:

1. Mostrar información general de la imagen del SO, incluyendo los datos de os-release(5) de la imagen, el ID de la máquina, información de particiones y más.
2. Montar una imagen de SO en un directorio local. En este modo, analizará la imagen del SO y montará las particiones incluidas según su designación en un directorio y, posiblemente, en subdirectorios.
3. Desmontar una imagen de SO de un directorio local. En este modo, desmontará recursivamente las particiones montadas y eliminará el dispositivo de bucle subyacente, incluyendo todos los dispositivos de subparticiones.
4. Copiar archivos y directorios dentro y fuera de una imagen de SO.

La herramienta puede operar sobre tres tipos de imágenes de SO:

1. Imágenes de disco de SO que contienen un envoltorio de tabla de particiones GPT, con particiones marcadas según la Especificación de Particiones Descubribles[1].
2. Imágenes de disco de SO que contienen solo un sistema de archivos plano sin una tabla de particiones envolvente. (Se asume que este sistema de archivos es el sistema de archivos raíz del SO).
3. Imágenes de disco de SO que contienen una tabla de particiones GPT o MBR, con una sola partición. (Se asume que esta partición contiene el sistema de archivos raíz del SO).

Las imágenes de SO pueden usar cualquier tipo de sistema de archivos compatible con Linux. Además, pueden utilizar cifrado de disco LUKS y contener información de integridad Verity. Tenga en cuenta que las imágenes de SO compatibles pueden iniciarse con el modificador --image= de systemd-nspawn(1), y utilizarse como sistema de archivos raíz para servicios del sistema usando la configuración del archivo de unidad RootImage=, consulte systemd.exec(5).

Tenga en cuenta que la tabla de particiones que se muestra al invocar sin un modificador de comando (como se enumera a continuación) no muestra necesariamente todas las particiones incluidas en la imagen, sino solo las particiones que se entienden y se consideran parte de una imagen de disco de SO. Específicamente, las particiones de tipos desconocidos se ignoran, al igual que las particiones duplicadas (es decir, más de una por tipo de partición), y las particiones raíz y /usr/ de arquitecturas no compatibles con el sistema local. En otras palabras: esta herramienta mostrará con qué opera al montar la imagen. Para mostrar la lista completa de particiones, use una herramienta como fdisk(8).

El comando systemd-dissect puede invocarse como mount.ddi, en cuyo caso implementa la interfaz de "helper externo" de mount(8). Esto asegura que las imágenes de disco compatibles con systemd-dissect puedan ser montadas directamente por mount y fstab(5). Para más detalles, consulte abajo.

En lugar de la ruta de la imagen, se puede especificar un directorio versionado de tipo ".v/", consulte systemd.v(7) para más detalles.

COMANDOS

Si no se pasan ninguno de los modificadores de comando listados a continuación, se abre la imagen de disco especificada y se muestra información general sobre la imagen y las particiones contenidas y su uso.

--mount, -m

Monta la imagen de SO especificada en el directorio especificado. Esto analizará la imagen, determinará el sistema de archivos raíz del SO —así como posiblemente otras particiones— y las montará en el directorio especificado. Si la imagen del SO contiene múltiples particiones marcadas con la Especificación de Particiones Descubribles[1], se establecerán múltiples montajes anidados. Este comando espera dos argumentos: una ruta a un archivo de imagen y una ruta a un directorio donde montar la imagen.

Para desmontar una imagen de SO montada de esta manera, use la operación --umount.

Cuando la imagen del SO contiene sistemas de archivos cifrados con LUKS o protegidos con integridad Verity, se configuran volúmenes apropiados y se marcan para su desmontaje automático cuando se desmonta la imagen.

La imagen del SO puede especificarse como una ruta a una imagen de SO almacenada en un archivo regular o puede referirse a un nodo de dispositivo de bloque (en este último caso, el dispositivo de bloque debe ser el dispositivo "completo", es decir, no un dispositivo de partición). (Los otros comandos compatibles descritos aquí también admiten esto).

Todos los sistemas de archivos montados se verifican con la implementación apropiada de fsck(8) en modo de reparación automática, a menos que se desactive explícitamente (--fsck=no) o se solicite operación de solo lectura (--read-only).

Tenga en cuenta que esta funcionalidad también está disponible en mount(8) a través de un comando como mount -t ddi myimage.raw targetdir/, así como en fstab(5). Para más detalles, consulte abajo.

--umount, -u

Desmonta una imagen de SO del directorio especificado. Este comando espera un argumento: un directorio donde se montó una imagen de SO.

Todas las particiones montadas se desmontarán recursivamente y el dispositivo de bucle subyacente se eliminará, junto con todos sus dispositivos de subparticiones.

Añadido en la versión 252.

-U

Este es un atajo para --umount --rmdir.

Añadido en la versión 252.

--attach

Adjunta la imagen de disco especificada a un dispositivo de bloque de loopback asignado automáticamente, e imprime la ruta al dispositivo de bloque de loopback en la salida estándar. Esto es similar a una invocación de losetup --find --show --partscan, pero validará la imagen como DDI antes de adjuntarla, y derivará automáticamente el tamaño de sector correcto a usar. Además, asegura que se creen los dispositivos de bloque por partición antes de devolver y intenta habilitar el modo de E/S directa, si es posible. Toma una ruta a un archivo de imagen de disco.

Si se combina con --quiet, se suprime la salida del nombre del dispositivo de bloque.

Añadido en la versión 254.

--detach

Desvincula la imagen de disco especificada de un dispositivo de bloque de loopback. Esto deshace el efecto de --attach anterior. Espera una ruta a un dispositivo de bloque de loopback como argumento, o la ruta al archivo de imagen de respaldo. En este último caso, determinará automáticamente el dispositivo correcto a desvincular.

Añadido en la versión 254.

--list, -l

Imprime las rutas de todos los archivos y directorios en la imagen de SO o directorio especificado a la salida estándar.

Añadido en la versión 253.

COMMANDS

The following commands are understood:

--mount

Mounts the specified OS image (or specified partition within it) into a temporary directory. The temporary directory is created under /run/user/$(id -u)/systemd-dissect/, mounted read-write, and then removed again when the OS image is unmounted. If a command line is passed, it is executed in the new directory with the image mounted. If no command line is passed, an interactive shell is invoked. The image is mounted read-write. Use --read-only to switch to read-only operation. The invoked process will have the $SYSTEMD_DISSECT_ROOT environment variable set, containing the absolute path name of the temporary mount point, i.e. the same directory that is set as the current working directory. It will also have the $SYSTEMD_DISSECT_DEVICE environment variable set, containing the absolute path name of the loop device the image was attached to.

The following options may be used in conjunction with --mount:

--offset=, --fs-type=, --image-policy=

See below.

--image-policy=

Selects the image policy to use. The image policy determines how the OS image's partition table and file systems are interpreted and accessed. The default policy is determined by the image content itself (e.g. GPT partition table, EFI System Partition, regular partition). Explicitly setting a policy may be necessary if the image format is unusual, or if specific partition types need to be prioritized. Supported policies:
default: Use the default policy, based on partition table and partition type heuristics.
gpt: Assume a GPT partition table and access partitions by their GPT IDs.
mbr: Assume an MBR partition table and access partitions by their MBR IDs.
esp: Primarily access the EFI System Partition (ESP).
root: Primarily access the root partition.
usr: Primarily access the /usr partition.
home: Primarily access the /home partition.
var: Primarily access the /var partition.
tmp: Primarily access the /tmp partition.
srv: Primarily access the /srv partition.
srv-data: Primarily access the /srv/data partition.
srv-config: Primarily access the /srv/config partition.
boot: Primarily access the /boot partition.
local-usr: Primarily access the /usr/local partition.
raid: Primarily access RAID metadata.
luks: Primarily access LUKS encrypted partitions.
verity: Primarily access Verity protected partitions.
raw: Access the image as a raw block device.

Added in version 256.

--offset=, --size=, --fs-type=

Specify the offset, size, and file system type of the partition to mount. These options are useful when the image contains multiple partitions or when the partition table is missing or unreadable. The offset and size are specified in bytes, but may be suffixed with K, M, G, T, P, or E for powers of 1024. The file system type may be specified explicitly, or it may be detected automatically.

Added in version 247.

--hash=

Computes a cryptographic hash of the contents of the OS image and prints it to standard output. Supports SHA1, SHA256, SHA512, MD5, and other hash algorithms. This may be used to verify the integrity of the image. The output is formatted as a hex string. Additional fields might be added in future. Note that inode information such as link counts, inode numbers and timestamps is excluded from the output on purpose, as it typically complicates reproducibility.

Added in version 253.

--with

Runs the specified command with the specified OS image mounted. This will mount the image to a temporary directory, switch the current working directory to it, and invoke the specified command line as child process. Once the process ends it will unmount the image again, and remove the temporary directory. If no command is specified a shell is invoked. The image is mounted writable, use --read-only to switch to read-only operation. The invoked process will have the $SYSTEMD_DISSECT_ROOT environment variable set, containing the absolute path name of the temporary mount point, i.e. the same directory that is set as the current working directory. It will also have the $SYSTEMD_DISSECT_DEVICE environment variable set, containing the absolute path name of the loop device the image was attached to.

Added in version 253.

--copy-from, -x

Copies a file or directory from the specified OS image or directory into the specified location on the host file system. Expects three arguments: a path to an image file or directory, a source path (relative to the image's root directory) and a destination path (relative to the current working directory, or an absolute path, both outside of the image). If the destination path is omitted or specified as dash ("-"), the specified file is written to standard output. If the source path in the image file system refers to a regular file it is copied to the destination path. In this case, access mode, extended attributes and timestamps are copied as well, but file ownership is not. If the source path in the image refers to a directory, it is copied to the destination path, recursively with all containing files and directories, merging into existing directories and updating already existing files. In this case, the file ownership is copied too.

Added in version 247.

--copy-to, -a

Copies a file or directory from the specified location in the host file system into the specified OS image or directory. Expects three arguments: a path to an image file or directory, a source path (relative to the current working directory, or an absolute path, both outside of the image) and a destination path (relative to the image's root directory). If the source path is omitted or specified as dash ("-"), the data to write is read from standard input. If the source path in the host file system refers to a regular file, it is copied to the destination path. In this case, access mode, extended attributes and timestamps are copied as well, but file ownership is not. If the source path in the host file system refers to a directory it is copied to the destination path, recursively with all containing files and directories, merging into existing directories and updating already existing files.. In this case, the file ownership is copied too.

As with --mount file system checks are implicitly run before the copy operation begins.

Added in version 247.

--make-archive

Generates an archive file from the specified disk image. Expects two arguments: the path to the disk image and optionally the output archive file path. If the latter is omitted the archive is written to standard output. The archive file format is determined automatically from the specified output archive file name, e.g. any path suffixed with ".tar.xz" will result in an xz compressed UNIX tarball (if the path is omitted an uncompressed UNIX tarball is created). See libarchive(3) for a list of supported archive formats and compression schemes.

Added in version 256.

--discover

Show a list of DDIs in well-known directories. This will show machine, portable service and system/configuration extension disk images in the usual directories /usr/lib/machines/, /usr/lib/portables/, /usr/lib/confexts/, /var/lib/machines/, /var/lib/portables/, /var/lib/extensions/ and so on.

Added in version 253.

--validate

Validates the partition arrangement of a disk image (DDI), and ensures it matches the image policy specified via --image-policy=, if one is specified. This parses the partition table and probes the file systems in the image, but does not attempt to mount them (nor to set up disk encryption/authentication via LUKS/Verity). It does this taking the configured image dissection policy into account. Since this operation does not mount file systems, this command – unlike all other commands implemented by this tool – requires no privileges other than the ability to access the specified file. Prints "OK" and returns zero if the image appears to be in order and matches the specified image dissection policy. Otherwise, prints an error message and returns non-zero.

Added in version 254.

--shift

Recursively iterates through all inodes of the specified image and shifts the UIDs and GIDs the inodes are owned by into the specified UID range. Takes an image path and a UID base as parameter. The UID base can be specified numerically (in which case it must be a multiple of 65536, and either 0 or within the container or foreign UID range, as per Users, Groups, UIDs and GIDs on systemd Systems[2]), or as the symbolic identifier "foreign" which is shorthand to the foreign UID base. This command is useful for preparing directory container images for unprivileged use. Note that this command is intended for images that use the 16bit UIDs/GIDs range only, and it always ignores the upper 16bit of the current UID/GID ownership, combining the lower 16 bit with the target UID base.

Use systemd-dissect --shift /some/container/tree foreign to shift a container image into the foreign UID range, or systemd-dissect --shift /some/container/tree 0 to shift it to host UID range.

Added in version 258.

-h, --help

Print a short help text and exit.

--version

Print a short version string and exit.

OPTIONS

The following options are understood:

--read-only, -r

Operate in read-only mode. By default, --mount will establish writable mount points. If this option is specified they are established in read-only mode instead.

Added in version 247.

--fsck=no

Turn off automatic file system checking. By default, when an image is accessed for writing (by --mount or --copy-to) the file systems contained in the OS image are automatically checked using the appropriate fsck(8) command, in automatic fixing mode. This behavior may be switched off using --fsck=no.

Added in version 247.

--growfs=no

Turn off automatic growing of accessed file systems to their partition size, if marked for that in the GPT partition table. By default, when an image is accessed for writing (by --mount or --copy-to) the file systems contained in the OS image are automatically grown to their partition sizes, if bit 59 in the GPT partition flags is set for partition types that are defined by the Discoverable Partitions Specification[1]. This behavior may be switched off using --growfs=no. File systems are grown automatically on access if all of the following conditions are met:
1.The file system is mounted writable
2.The file system currently is smaller than the partition it is contained in (and thus can be grown)
3.The image contains a GPT partition table
4.The file system is stored on a partition defined by the Discoverable Partitions Specification
5.Bit 59 of the GPT partition flags for this partition is set, as per specification
6.The --growfs=no option is not passed.

Added in version 249.

--mkdir

If combined with --mount the directory to mount the OS image to is created if it is missing. Note that the directory is not automatically removed when the disk image is unmounted again.

Added in version 247.

--rmdir

If combined with --umount the specified directory where the OS image is mounted is removed after unmounting the OS image.

Added in version 252.

--discard=

Takes one of "disabled", "loop", "all", "crypto". If "disabled" the image is accessed with empty block discarding turned off. If "loop" discarding is enabled if operating on a regular file. If "crypt" discarding is enabled even on encrypted file systems. If "all" discarding is unconditionally enabled.

Added in version 247.

--in-memory

If specified an in-memory copy of the specified disk image is used. This may be used to operate with write-access on a (possibly read-only) image, without actually modifying the original file. This may also be used in order to operate on a disk image without keeping the originating file system busy, in order to allow it to be unmounted.

Added in version 253.

--root-hash=, --root-hash-sig=, --verity-data=

Configure various aspects of Verity data integrity for the OS image. Option --root-hash= specifies a hex-encoded top-level Verity hash to use for setting up the Verity integrity protection. Option --root-hash-sig= specifies the path to a file containing a PKCS#7 signature for the hash. This signature is passed to the kernel during activation, which will match it against signature keys available in the kernel keyring. Option --verity-data= specifies a path to a file with the Verity data to use for the OS image, in case it is stored in a detached file. It is recommended to embed the Verity data directly in the image, using the Verity mechanisms in the Discoverable Partitions Specification[1].

Added in version 247.

--usr-hash=, --usr-hash-sig=

Similar to --root-hash= and --root-hash-sig=, but specifies hash and signature for the /usr/ partition. Note that either the options for the root partition may be used or the ones for the /usr/, but not both in combination.

Added in version 258.

NOMBRE

systemd-dissect - analizar, extraer, montar y empaquetar sistemas de archivos de disco de arranque

SINOPSIS

systemd-dissect [OPCIONES...] {COMANDO}

DESCRIPCIÓN

systemd-dissect es una utilidad para analizar y operar en imágenes de disco o dispositivos de bloque que contienen un sistema de archivos de arranque, como los utilizados por los sistemas Linux y otros sistemas operativos.

Puede extraer archivos, montarlos, crear enlaces simbólicos, empaquetarlos y generar información sobre el contenido del disco.

COMANDOS

Los siguientes comandos están disponibles:

--print-machine-id
Imprime el ID de la máquina del sistema operativo encontrado en la imagen, si existe. Esto es útil para identificar la imagen sin montarla.
--discover
Enumera los sistemas de archivos reconocidos dentro de la imagen de disco. Esto mostrará las particiones de arranque si la imagen se adhiere a la especificación de particiones de arranque.
--mount=path
Monta el sistema de archivos de arranque encontrado en path. Esto espera que la imagen contenga un único sistema de archivos raíz. Si hay varios sistemas de archivos, como una partición de arranque separada y una partición raíz, se montará solo el sistema de archivos raíz.
--mount-vfat, --mount-ext4, --mount-btrfs, --mount-xfs
Similar a --mount=, pero monta específicamente el primer sistema de archivos del tipo especificado.
--mount-root
Monta el sistema de archivos raíz encontrado en la imagen. Esto puede fallar si la imagen no contiene un sistema de archivos raíz claramente identificable.
--with=cmd
Ejecuta el comando cmd después de montar el sistema de archivos de arranque. El comando se ejecuta en el directorio raíz del sistema de archivos montado. Esto es útil para realizar operaciones dentro del sistema de archivos de la imagen, como crear archivos tar.
--make-archive=path
Crea un archivo tar del contenido del sistema de archivos de arranque y lo guarda en path. Si la imagen tiene varios sistemas de archivos, esto solo archivará el sistema de archivos raíz.
--extract=path
Extrae el contenido del sistema de archivos de arranque en el directorio especificado por path. Si la imagen tiene varios sistemas de archivos, esto solo extraerá el sistema de archivos raíz.
--attach
Adjunta la imagen como un dispositivo de bloque de loopback. Esto es útil para hacer que la imagen sea accesible como un dispositivo de bloque normal. Se creará un nuevo dispositivo de loopback y se imprimirá su ruta.
--detach
Desconecta un dispositivo de loopback previamente adjuntado.
--copy-to=path
Copia la imagen de disco a la ubicación especificada. Esto es útil para tener una copia de trabajo de la imagen que se pueda modificar.
--copy-from=path
Copia el contenido de un dispositivo de loopback adjuntado a la imagen de disco original. Esto es útil para guardar cambios realizados en la imagen montada.
--wipe-new-partitions
Si se usa con --attach, borra todas las particiones nuevas creadas en la imagen.
--loop-ref=name
Establece un nombre de referencia para el dispositivo de loopback adjunto. Este nombre se puede usar para referenciar el dispositivo más tarde a través de enlaces simbólicos en /dev/disk/by-loop-ref/. El nombre puede ser cualquier cadena hasta 63 caracteres de longitud.
--loop-ref-auto
Similar a --loop-ref=, pero deriva automáticamente el nombre de referencia del nombre del archivo de respaldo especificado, truncándolo si es necesario.
--mtree
Genera una salida en formato mtree del contenido del sistema de archivos. Esto es útil para verificar la integridad del sistema de archivos.
--mtree-hash=no
Si se combina con --mtree, desactiva la inclusión de hashes de archivos en la salida mtree. Esto acelera la operación --mtree en imágenes grandes.
--system, --user
Cuando se usa junto con --discover, controla si se deben buscar imágenes instaladas en todo el sistema o en los directorios del usuario en $HOME. Si no se especifica ninguno de los dos, se buscarán en ambos ámbitos.
--all
Si se combina con --discover, también muestra imágenes que comienzan con un punto, es decir, imágenes ocultas.
--quiet, -q
Si se combina con --attach, suprime la salida de la ruta del dispositivo de bloque de loopback utilizado.
--image-policy=policy
Toma una cadena de política de imagen como argumento, según systemd.image-policy(7). La política se aplica al operar en la imagen de disco especificada a través de --image=, ver arriba. Si no se especifica, el valor predeterminado es la política "\*", es decir, se utilizan todos los sistemas de archivos reconocidos en la imagen.
--image-filter=filter
Toma una cadena de filtro de imagen como argumento, según systemd.image-filter(7). El filtro se tiene en cuenta al operar en la imagen de disco especificada a través de --image=, ver arriba. Si no se especifica, no se aplica ningún filtrado.
--no-pager
No canaliza la salida a un paginador.
--no-legend
No imprime la leyenda, es decir, los encabezados de columna y el pie de página con sugerencias.
--json=MODE
Muestra la salida formateada como JSON. Espera una de las opciones: "short" (para la salida más corta posible sin espacios en blanco o saltos de línea redundantes), "pretty" (para una versión bonita de la misma, con sangría y saltos de línea) o "off" (para desactivar la salida JSON, el valor predeterminado).

ESTADO DE SALIDA

Al éxito, se devuelve 0, de lo contrario, un código de error distinto de cero. Si se utiliza el comando --with, se propaga el estado de salida del comando invocado.

INVOCACIÓN COMO /SBIN/MOUNT.DDI

El ejecutable systemd-dissect puede ser enlazado simbólicamente a /sbin/mount.ddi. Si se invoca a través de él, implementa la interfaz de "ayudante externo" de mount(8) para el tipo de sistema de archivos (pseudo) "ddi". Esto significa que las imágenes de disco conformes pueden montarse directamente a través de

# mount -t ddi myimage.raw targetdir/

de una manera mayormente equivalente a:

# systemd-dissect --mount myimage.raw targetdir/

Tenga en cuenta que, dado que un solo DDI puede contener varios sistemas de archivos, más tarde debería desmontarse con umount -R targetdir/, para operación recursiva.

Esta funcionalidad es particularmente útil para montar DDIs automáticamente al arrancar a través de entradas /etc/fstab simples. Por ejemplo:

/path/to/myimage.raw /images/myimage/ ddi defaults 0 0

Cuando se invoca de esta manera, las opciones de montaje "ro", "rw", "discard", "nodiscard" se mapean a las opciones correspondientes enumeradas anteriormente (es decir, --read-only, --discard=all, --discard=disabled). Las opciones de montaje *no* se pasan genéricamente a los sistemas de archivos dentro de las imágenes.

Ejemplo 1. Generar un tarball a partir de una imagen de disco de SO (--with)

# systemd-dissect --with foo.raw tar cz . >foo.tar.gz

o alternativamente:

Ejemplo 2. Generar un tarball a partir de una imagen de disco de SO (--make-archive)
