NOMBRE

systemd.netdev - Configuración de dispositivos de red virtuales

SINOPSIS

netdev.netdev

DESCRIPCIÓN

Un archivo de texto plano de estilo ini que codifica la configuración sobre un dispositivo de red virtual, utilizado por systemd-networkd(8). Vea systemd.syntax(7) para una descripción general de la sintaxis.

El archivo principal del Dispositivo de Red Virtual debe tener la extensión .netdev; otras extensiones se ignoran. Los dispositivos de red virtuales se crean tan pronto como systemd-networkd se inicia si es posible. Si ya existe un netdev con el nombre especificado, systemd-networkd intentará actualizar la configuración si el tipo del netdev existente es equivalente al solicitado, de lo contrario (por ejemplo, cuando existe un dispositivo puente foo pero un dispositivo de agrupación con el mismo nombre está configurado en un archivo .netdev) se utilizará el netdev existente tal cual en lugar de reemplazarlo con el netdev solicitado. Tenga en cuenta que varias configuraciones (por ejemplo, ID de VLAN) no se pueden cambiar una vez que el netdev se ha creado. Para cambiar dichas configuraciones, es necesario primero eliminar el netdev existente y luego ejecutar el comando networkctl reload o reiniciar systemd-networkd. Vea también networkctl(1).

Los archivos .netdev se leen de los archivos ubicados en el directorio de red del sistema /usr/lib/systemd/network y /usr/local/lib/systemd/network, el directorio de red temporal en tiempo de ejecución /run/systemd/network y el directorio de red de administración local /etc/systemd/network. Todos los archivos de configuración se ordenan y procesan colectivamente en orden alfanumérico, independientemente de los directorios en los que se encuentren. Sin embargo, los archivos con nombres idénticos se reemplazan mutuamente. Se recomienda que cada nombre de archivo comience con un número menor que "70" (por ejemplo, 10-vlan.netdev). De lo contrario, los archivos .netdev generados por systemd-network-generator.service(8) pueden tener prioridad sobre los archivos configurados por el usuario. Los archivos en /etc/ tienen la prioridad más alta, los archivos en /run/ tienen prioridad sobre los archivos con el mismo nombre en /usr/lib/. Esto se puede usar para anular un archivo de configuración proporcionado por el sistema con un archivo local si es necesario. Como caso especial, un archivo vacío (tamaño de archivo 0) o un enlace simbólico con el mismo nombre que apunta a /dev/null deshabilita completamente el archivo de configuración (se "enmascara").

Junto con el archivo netdev foo.netdev, puede existir un directorio de "drop-in" foo.netdev.d/. Todos los archivos con el sufijo ".conf" de este directorio se fusionarán en orden alfanumérico y se analizarán después de que el archivo principal en sí mismo haya sido analizado. Esto es útil para alterar o agregar configuraciones, sin tener que modificar el archivo de configuración principal. Cada archivo drop-in debe tener encabezados de sección apropiados.

Además de /etc/systemd/network, se pueden colocar directorios de drop-in ".d" en los directorios /usr/lib/systemd/network o /run/systemd/network. Los archivos drop-in en /etc/ tienen prioridad sobre los de /run/, que a su vez tienen prioridad sobre los de /usr/lib/. Los archivos drop-in en cualquiera de estos directorios tienen prioridad sobre el archivo netdev principal dondequiera que se encuentre. (Por supuesto, dado que /run/ es temporal y /usr/lib/ es para proveedores, es poco probable que se utilicen drop-ins en ninguno de esos lugares.)

bond Un dispositivo bond es una agregación de todos sus dispositivos esclavos. Vea Linux Ethernet Bonding Driver HOWTO[1] para más detalles.
bridge Un dispositivo bridge es un switch de software, y cada uno de sus dispositivos esclavos y el propio bridge son puertos del switch.

erspan ERSPAN espeja el tráfico en uno o más puertos de origen y entrega el tráfico espejado a uno o más puertos de destino en otro switch. [VLAN] OPCIONES DE SECCIÓN

La sección [VLAN] solo se aplica a los dispositivos de red de tipo "vlan" y acepta la siguiente clave:

Id=

El ID de VLAN a utilizar. Un entero en el rango 0...4094. Esta configuración es obligatoria.

Añadido en la versión 211.

Protocol=

Permite establecer el protocolo utilizado para la interfaz VLAN. Acepta "802.1q" o "802.1ad", y por defecto no se establece y se utiliza el valor predeterminado del kernel.

Añadido en la versión 248.

GVRP=

Acepta un valor booleano. El Protocolo de Registro de VLAN Genérico (GVRP) es un protocolo que permite el aprendizaje automático de VLAN en una red. Si no se establece, se utilizará el valor predeterminado del kernel.

Añadido en la versión 234.

MVRP=

Acepta un valor booleano. El Protocolo de Registro de VLAN Múltiple (MVRP), anteriormente conocido como Protocolo de Registro de VLAN GARP (GVRP), es un protocolo de red de Capa 2 basado en estándares, para la configuración automática de información de VLAN en switches. Fue definido en la enmienda 802.1ak a 802.1Q-2005. Si no se establece, se utilizará el valor predeterminado del kernel.

Añadido en la versión 234.

LooseBinding=

Acepta un valor booleano. El modo de enlace suelto de VLAN, en el que solo el estado operativo se pasa del padre a las VLAN asociadas, pero el estado del dispositivo VLAN no cambia. Si no se establece, se utilizará el valor predeterminado del kernel.

Añadido en la versión 234.

ReorderHeader=

Acepta un valor booleano. Cuando está habilitado, se utiliza la cabecera de reordenamiento de VLAN y las interfaces VLAN se comportan como interfaces físicas. Si no se establece, se utilizará el valor predeterminado del kernel.

Añadido en la versión 234.

EgressQOSMaps=, IngressQOSMaps=

Define un mapeo de la prioridad interna de paquetes de Linux (SO_PRIORITY) al campo PCP de la cabecera VLAN para tramas salientes y entrantes, respectivamente. Acepta una lista separada por espacios de pares de enteros, donde cada entero debe estar en el rango 1...4294967294, en el formato "de"-"a", por ejemplo, "21-7 45-5". Tenga en cuenta que "de" debe ser mayor o igual que "a". Si no se establece, se utilizará el valor predeterminado del kernel.

Añadido en la versión 248.

[MACVLAN] OPCIONES DE SECCIÓN

La sección [MACVLAN] solo se aplica a los dispositivos de red de tipo "macvlan" y acepta la siguiente clave:

Mode=

El modo MACVLAN a utilizar. Las opciones admitidas son "private", "vepa", "bridge", "passthru" y "source".

Añadido en la versión 211.

SourceMACAddress=

Una lista separada por espacios de direcciones de hardware remotas permitidas en el MACVLAN. Esta opción solo tiene efecto en el modo "source". Utilice direcciones hexadecimales completas separadas por dos puntos, guiones o puntos. Esta opción puede aparecer más de una vez, en cuyo caso las listas se fusionan. Si se asigna una cadena vacía a esta opción, la lista de direcciones de hardware definidas previamente se reinicia. Por defecto, no se establece.

Añadido en la versión 246.

BroadcastMulticastQueueLength=

Especifica la longitud de la cola de recepción para paquetes de broadcast/multicast. Un entero sin signo en el rango 0...4294967294. Por defecto, no se establece.

Añadido en la versión 248.

BroadcastQueueThreshold=

Controla el umbral de puesta en cola de broadcast del dispositivo macvlan. Acepta el valor especial "no" o un entero en el rango 0...2147483647. Cuando se especifica "no", la puesta en cola de broadcast se deshabilita por completo. Cuando se especifica un entero, una dirección multicast se pondrá en cola como broadcast si el número de dispositivos que utilizan el macvlan es mayor que el valor dado. Por defecto, no se establece y se utilizará el valor predeterminado del kernel.

Añadido en la versión 256.

[HSR] SECTION OPTIONS

The [HSR] section only applies for netdevs of kind "hsr", and accepts the following keys:

Ports=

Specifies the underlying interfaces. This field is mandatory and must contain exactly two interface names separated by space. This option can be specified multiples times, hence the two cases below have the same result: 
Ports=eth1 eth2
Ports=eth1
Ports=eth2

All the previous assignments are cleared when an empty string is specified.

Added in version 258.

Protocol=

Specifies the protocol used by the interface. Takes one of "hsr" or "prp". Defaults to "hsr".

Both protocols work by sending two copies of every outgoing frame, one for each of the two ports. The destination node receives the two frames and and keeps only the first one. If a link fails, only one of the two frames is received. HSR uses a ring topology where the two outgoing frames are sent in opposite directions in the ring. PRP doesn't need a specific topology, but it requires two completely redundant networks attached to the two ports.

Added in version 258.

Specifies the last byte of the destination MAC address of supervision frames. Takes a number between 0 and 255. Defaults to 0. Supervision frames are used by the HSR and the PRP protocols to monitor the integrity of the network and the presence of nodes. The first 5 bytes of the destination MAC are always 01:15:4E:00:01 while the last byte is configurable.

NAME

SYNOPSIS

/etc/systemd/network/​*.netdev

/run/systemd/network/​*.netdev

/usr/lib/systemd/network/​*.netdev

DESCRIPTION

A unit file that configures network devices. It may be used to create, configure, and manage network devices of various kinds.

The configuration file format is an INI-style text file. It is split into sections, marked by a string in square brackets, and then followed by string keys and values.

The configuration files are processed in the order listed in the FILES section. Devices are created when the configuration file is parsed.

Each configuration file must have at least one section. The first section is the [NetDev] section, which is mandatory. Additional sections are used to configure specific device types and are optional.

Valid device kinds include:

  • ether (Ethernet device)
  • bridge (Ethernet bridge device)
  • bond (Bonding device)

Core options

The following options are available in the [NetDev] section:

Name=
Sets the name of the network device. This option is mandatory for all device kinds.
Kind=
Sets the type of the network device. This option is mandatory for all device kinds.
MTUBytes=
Sets the Maximum Transmission Unit (MTU) of the device in bytes. If not set, the MTU is chosen automatically.
MACAddress=
Sets the MAC address of the device. The address must be specified in hexadecimal notation, separated by colons (e.g. "12:34:56:78:9a:bc"). If not specified, the device will obtain a MAC address automatically.

ETHER_SECTION

The [Ether] section is used to configure basic Ethernet devices. No options are currently available.

BRIDGE_SECTION

The [Bridge] section configures Ethernet bridge devices. It accepts the following keys:

AgeingTime=
Sets the bridge ageing time. This is the time that MAC addresses are kept in the bridge table. The value is in seconds. Defaults to 300 seconds.
ForwardDelay=
Sets the bridge forward delay. This is the time that ports are kept in the listening and learning state. The value is in seconds. Defaults to 15 seconds.
HelloTime=
Sets the bridge hello time. This is the time between periodic transmission of the bridge hello packets. The value is in seconds. Defaults to 2 seconds.
MaxAge=
Sets the bridge max age. This is the maximum time that the bridge information is considered valid. The value is in seconds. Defaults to 20 seconds.
Priority=
Sets the bridge priority. This value is used in the Spanning Tree Protocol (STP) to determine the root bridge. The value is an integer between 0 and 65535. Defaults to 32768.
STP=
Enables or disables Spanning Tree Protocol (STP) on the bridge. Takes a boolean value. Defaults to false.

BOND_SECTION

The [Bond] section configures bonding devices. It accepts the following keys:

Mode=
Sets the bonding mode. Takes one of "balance-rr", "active-backup", "balance-xor", "broadcast", "802.3ad", "balance-tlb", "balance-alb". Defaults to "active-backup".
MIIMonitorSec=
Sets the MII link monitoring interval. The value is in seconds. Defaults to 1 second.
LACPTransmitRate=
Sets the LACPDU transmission rate for the bond. Takes either "fast" or "slow". Defaults to "slow".
LACPDUPeriod=
Sets the LACPDU transmission period. The value is in seconds. Defaults to 30 seconds.
TransmitHashPolicy=
Sets the transmit hash policy for the bond. Takes one of "layer2", "layer3+4", "encap2+4", "encap3+4", "layer2+encap2", "layer2+encap3", "layer3+4" or "active". Defaults to "layer2".
GBP=
Enabled Group Address Filtering for the bond. Takes a boolean value. Defaults to false.
TGR=
Enabled Transparent Group Reassembly for the bond. Takes a boolean value. Defaults to false.

See also Linux Ethernet Bonding Driver HOWTO.

VLAN_SECTION

The [VLAN] section configures VLAN devices. It accepts the following keys:

Id=
Sets the VLAN ID. This option is mandatory.
EgressVLANID=
Sets the VLAN ID used for egress frames. If not specified, the value of Id= is used.

TUN_SECTION

The [TUN] section configures TUN/TAP devices. It accepts the following keys:

OwnerUID=
Sets the user ID of the device owner. Defaults to the user ID of the process creating the device.
OwnerGID=
Sets the group ID of the device owner. Defaults to the group ID of the process creating the device.
Mode=
Sets the mode of the device. Takes either tap or tun. Defaults to tun.
Persist=
Takes a boolean value. If true, the device is not destroyed when the last process closes it. Defaults to false.
MultiQueue=
Takes a boolean value. If true, the device has multiple queues. Defaults to false.
PacketInfo=
Takes a boolean value. If true, the device passes packet information to userspace. Defaults to false.

TAP_SECTION

The [Tap] section configures TAP devices. It accepts the following keys:

BusyPoll=
Takes a boolean value. If true, the device uses busy polling to receive packets. Defaults to false.
Offload=
Takes a boolean value. If true, the device uses offloading to transmit packets. Defaults to false.

TUNNEL_SECTION

The [Tunnel] section configures IP tunnel devices. It accepts the following keys:

Independent=
Takes a boolean value. If true, the tunnel is independent of the link layer. Defaults to false.
Local=
Sets the local IP address of the tunnel endpoint. This option is mandatory for IP-based tunnels.
Remote=
Sets the remote IP address of the tunnel endpoint. This option is mandatory for IP-based tunnels.
TTL=
Sets the Time-To-Live (TTL) of the tunnel packets. Defaults to the system default.
TOS=
Sets the Type-Of-Service (TOS) of the tunnel packets. Defaults to the system default.
Dev=
Sets the underlying network device to use for the tunnel. If not specified, the system chooses the device automatically.
Key=
Sets the key for the tunnel. This is used for GRE tunnels.
Flags=
Sets the flags for the tunnel. This is used for GRE tunnels.
Checksum=
Takes a boolean value. If true, the tunnel computes and checks the checksum. Defaults to true.
PMTU=
Takes a boolean value. If true, the tunnel respects Path MTU Discovery. Defaults to true.
Window=
Sets the window size for the tunnel. This is used for GRE tunnels.
Ipip6=
Takes a boolean value. If true, the tunnel is an IPv6-in-IPv4 tunnel (SIT). Defaults to false.
IPv6RapidDeploymentPrefix=
Sets the IPv6 Rapid Deployment (6rd) prefix for the tunnel. This is used for SIT tunnels.
Encapsulation=
Sets the encapsulation mode for the tunnel. Takes one of "ip", "ipv6", or "vxlan". Defaults to "ip".
FooOverUDP=
Takes a boolean value. If true, the tunnel encapsulates traffic in UDP. Defaults to false.
FOUDestinationPort=
Sets the destination UDP port for Foo over UDP encapsulation. This option is only valid if FooOverUDP=true.

VXLAN_SECTION

The [VXLAN] section configures VXLAN tunnel devices. It accepts the following keys:

Local=
Sets the local IP address of the VXLAN tunnel endpoint. If not specified, the system chooses the device automatically.
Remote=
Sets the remote IP address of the VXLAN tunnel endpoint. This option is mandatory.
Group=
Sets the multicast group address for the VXLAN tunnel. This option is used for multicast VXLAN.
AgeingTime=
Sets the VXLAN ageing time. This is the time that MAC addresses are kept in the VXLAN table. The value is in seconds. Defaults to 300 seconds.
GBP=
Takes a boolean value. If true, the VXLAN tunnel uses Group Policy Backend. Defaults to false.
UDPChecksum=
Takes a boolean value. If true, the VXLAN tunnel uses UDP checksums. Defaults to true.
UDPFragment=
Takes a boolean value. If true, the VXLAN tunnel allows UDP fragmentation. Defaults to true.
L2Miss=
Takes a boolean value. If true, the VXLAN tunnel sends unknown unicast and multicast frames to the VTEP. Defaults to true.
L3Miss=
Takes a boolean value. If true, the VXLAN tunnel sends unknown unicast frames to the VTEP. Defaults to true.

VTI_SECTION

The [VTI] section configures Virtual Tunnel Interface devices. It accepts the following keys:

Mode=
Sets the VTI mode. Takes one of clear or xform. Defaults to clear.
Key=
Sets the VTI key. This is used for IPsec.

SIT_SECTION

The [SIT] section configures SIT tunnel devices. It accepts the following keys:

Local=
Sets the local IP address of the tunnel endpoint. This option is mandatory.
Remote=
Sets the remote IP address of the tunnel endpoint. This option is mandatory.
IPv6RapidDeploymentPrefix=
Sets the IPv6 Rapid Deployment (6rd) prefix for the tunnel.

WIREGUARD_SECTION

The [WireGuard] section configures WireGuard tunnel devices. It accepts the following keys:

PrivateKey=
Sets the private key for the WireGuard interface. This option is mandatory.
ListenPort=
Sets the UDP port to listen on for incoming WireGuard connections. If not specified, a random port is chosen.
FirewallMark=
Sets the firewall mark for the WireGuard interface. This is used for policy-based routing.
SaveConfig=
Takes a boolean value. If true, the current WireGuard configuration is saved to disk. Defaults to false.

The [WireGuardPeer] section configures WireGuard peers. It accepts the following keys:

PublicKey=
Sets the public key of the WireGuard peer. This option is mandatory.
PresharedKey=
Sets the preshared key for the WireGuard peer. This is an optional security enhancement.
Endpoint=
Sets the endpoint address (IP address and port) of the WireGuard peer. This option is mandatory.
AllowedIPs=
Sets the list of IP addresses that are allowed to be routed to this peer. This option is mandatory.
PersistentKeepalive=
Sets the interval in seconds for sending keepalive packets to the peer. This is used to keep connections alive through NAT.

XFRM_SECTION

The [XFRM] section configures XFRM interfaces. It accepts the following keys:

Independent=
Takes a boolean value. If true, the XFRM interface is independent of the link layer. Defaults to false.

IFB_SECTION

The [IFB] section configures IFB devices. No options are currently available.

VETH_SECTION

The [Veth] section configures VETH devices. It accepts the following keys:

Peer=
Configures the peer end of the VETH device. This option is mandatory.

The [Peer] section configures the peer end of a VETH device. It accepts the following keys:

Name=
Sets the name of the peer device. This option is mandatory.
Master=
Sets the master device for the peer device. This is used for bridging.

MACVTAP_SECTION

The [MacVTap] section configures MacVTap devices. It accepts the following keys:

Mode=
Sets the mode of the MacVTap device. Takes one of bridge, private, vepa, passthru. Defaults to bridge.
MACAddress=
Sets the MAC address of the device. The address must be specified in hexadecimal notation, separated by colons (e.g. "12:34:56:78:9a:bc"). If not specified, the device will obtain a MAC address automatically.

HSR_SECTION

The [HSR] section configures HSR devices. It accepts the following keys:

Protocol=
Sets the HSR protocol. Takes one of HSR or PTP. Defaults to HSR.
SubInterface=
Sets the sub-interface name. This option is mandatory.
Ring1=
Sets the name of the first ring interface. This option is mandatory.
Ring2=
Sets the name of the second ring interface. This option is mandatory.

PRP_SECTION

The [PRP] section configures PRP devices. It accepts the following keys:

SubInterface=
Sets the sub-interface name. This option is mandatory.
Port1=
Sets the name of the first port interface. This option is mandatory.
Port2=
Sets the name of the second port interface. This option is mandatory.

DUMMY_SECTION

The [Dummy] section configures dummy network devices. It accepts the following keys:

MACAddress=
Sets the MAC address of the device. The address must be specified in hexadecimal notation, separated by colons (e.g. "12:34:56:78:9a:bc"). If not specified, the device will obtain a MAC address automatically.

VRF_SECTION

The [VRF] section configures VRF (Virtual Routing and Forwarding) instances. It accepts the following keys:

Table=
Sets the routing table ID for the VRF instance. This option is mandatory.

IB_SECTION

The [IB] section configures InfiniBand devices. It accepts the following keys:

IgnoreUserspaceMulticastGroups=
Takes a boolean value. When true, the kernel ignores multicast groups handled by userspace. Defaults to unset, and the kernel's default is used.

Added in version 250.

[WLAN] SECTION OPTIONS

The [WLAN] section only applies to WLAN interfaces, and accepts the following keys:

PhysicalDevice=
Specifies the name or index of the physical WLAN device (e.g. "0" or "phy0"). The list of the physical WLAN devices that exist on the host can be obtained by iw phy command. This option is mandatory.

Added in version 251.

Type=
Specifies the type of the interface. Takes one of the "ad-hoc", "station", "ap", "ap-vlan", "wds", "monitor", "mesh-point", "p2p-client", "p2p-go", "p2p-device", "ocb", and "nan". This option is mandatory.

Added in version 251.

WDS=
Enables the Wireless Distribution System (WDS) mode on the interface. The mode is also known as the "4 address mode". Takes a boolean value. Defaults to unset, and the kernel's default will be used.

Added in version 251.

DESCRIPCIÓN

systemd maneja la configuración de dispositivos de red a través de archivos de unidad .netdev. Estos archivos definen dispositivos de red que systemd debe crear y configurar al arrancar o bajo demanda.

SINTAXIS

Los archivos .netdev se organizan en secciones, cada una definida por un encabezado entre corchetes, como [Match] o [NetDev]. Las opciones se especifican como pares clave=valor dentro de cada sección.

OPCIONES

OPCIONES GENERALES

Las opciones generales se aplican a todo el archivo .netdev y se definen en la sección [Match].

  • Name=: Especifica el nombre del dispositivo de red.
  • Kind=: Especifica el tipo de dispositivo de red (por ejemplo, bridge, vlan, tun).
  • MACAddress=: Especifica la dirección MAC del dispositivo.
  • Parent=: Especifica el dispositivo padre para tipos de dispositivos anidados.
  • Driver=: Especifica el controlador del kernel.
  • Type=: Especifica el tipo de dispositivo (por ejemplo, Ethernet, WiFi).
  • Path=: Especifica la ruta del dispositivo.
  • Subsystem=: Especifica el subsistema del dispositivo.

TIPOS DE NETDEV ADMITIDOS

systemd soporta una amplia gama de tipos de dispositivos de red, incluyendo:

  • bridge
  • vlan
  • macvlan
  • macvtap
  • ipvlan
  • ipvtap
  • vxlan
  • geneve
  • hsr
  • bareudp
  • l2tp
  • l2tsession
  • macsec
  • macsecreceivechannel
  • macsectransmitassociation
  • macsecreceiveassociation
  • tunnel
  • foooverudp
  • peer
  • vxcan
  • tun
  • tap
  • wireguard
  • wireguardpeer
  • bond
  • xfrm
  • vrf
  • batman-adv
  • ipoib
  • wlan

[MATCH] SECTION OPTIONS

La sección [Match] se utiliza para identificar el dispositivo de red al que se aplicarán las opciones de la sección [NetDev]. Las opciones comunes incluyen:

  • Name=: Coincide con el nombre del dispositivo.
  • Driver=: Coincide con el nombre del controlador del kernel.
  • Path=: Coincide con la ruta del dispositivo.
  • Subsystem=: Coincide con el subsistema del dispositivo.
  • Type=: Coincide con el tipo de dispositivo.
  • Property=: Coincide con una propiedad arbitraria del dispositivo.

[NETDEV] SECTION OPTIONS

La sección [NetDev] define las propiedades del dispositivo de red que se creará. Las opciones dependen del tipo de dispositivo especificado en la sección [Match] o en la opción Kind=.

Opciones comunes:

  • Name=: El nombre del dispositivo que se creará.
  • Kind=: El tipo de dispositivo de red a crear (por ejemplo, bridge, vlan).
  • MACAddress=: La dirección MAC deseada para el dispositivo.
  • MTUBytes=: La Unidad de Transmisión Máxima del dispositivo en bytes.
  • VLANProtocol=: El protocolo VLAN a utilizar (por ejemplo, 802.1Q, 802.1ad).

[BRIDGE] SECTION OPTIONS

Opciones específicas para crear dispositivos bridge:

  • STP=: Habilita o deshabilita el Spanning Tree Protocol.
  • Priority=: Prioridad del bridge.
  • ForwardDelay=: Retardo de reenvío.
  • HelloTime=: Tiempo de saludo.
  • MaxAge=: Tiempo máximo.
  • AgingTime=: Tiempo de envejecimiento de la tabla MAC.

[VLAN] SECTION OPTIONS

Opciones específicas para crear dispositivos VLAN:

  • Id=: El ID de la VLAN.
  • Protocol=: El protocolo VLAN a utilizar (por ejemplo, 802.1Q).

[MACVLAN] SECTION OPTIONS

Opciones específicas para crear dispositivos macvlan:

  • Mode=: El modo macvlan (por ejemplo, private, vepa, bridge, passthru).

[MACVTAP] SECTION OPTIONS

Opciones específicas para crear dispositivos macvtap:

  • Mode=: El modo macvtap (similar a macvlan).
