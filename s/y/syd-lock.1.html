SYD-LOCK(1) Manual de Comandos Generales SYD-LOCK(1)

NOMBRE

syd-lock - Ejecutar un programa bajo landlock(7)

SINOPSIS

syd-lock [-bchrvwASUV] [-C nivel] [-E errata] [-F flag]... [-l categoría[,categoría...]{+|-}ruta|puerto[-puerto]]... {comando [argumentos...]}

DESCRIPCIÓN

La utilidad syd-lock ejecuta un programa bajo landlock(7). El programa está confinado por las categorías de landlock(7) dadas. Las categorías soportadas son read, write, exec, ioctl, create, delete, rename, symlink, truncate, readdir, mkdir, rmdir, mkbdev, mkcdev, mkfifo, bind y connect. Las categorías distintas de bind y connect deben especificar rutas a confinar. Se permiten tanto rutas absolutas como relativas. Las categorías bind y connect deben especificar un puerto de red o un rango de puertos cerrados separados por un guion. Cero es un número de puerto válido para confinar binds y connects a puertos efímeros. La categoría bind también soporta rutas de sockets de dominio UNIX absolutas para confinar su creación vía mknod(2). Para detalles completos y comportamiento específico de cada categoría de landlock(7), consulte las secciones Sandboxing y Lock Sandboxing de la página del manual de syd(7).

OPCIONES

-h Muestra la ayuda.
-v Sea verboso. Imprime el estado de landlock(7) en stderr(3) antes de ejecutar el programa.
-V Imprime la versión ABI de landlock(7) en stdout(3).
-A Imprime la versión ABI de landlock(7) en stdout(3) y sale con ella como código de salida. Útil para scripting.
-l cat[,cat...]{+|-}ruta|puerto[-puerto] Añade o elimina una regla de landlock(7) con categorías y un recurso asociado (ruta o puerto), puede repetirse.
Une las categorías y el recurso con un "+" (más) para añadir o un "-" (menos) para eliminar.
El recurso debe ser una ruta para todas las categorías excepto bind y connect.
El recurso debe ser un puerto o un rango de puertos cerrado delimitado por guiones para bind y connect.
El recurso también puede ser una ruta de socket de dominio UNIX para bind para confinar mknod(2) con S_IFSOCK.
Se permiten rutas absolutas y relativas para todas las categorías excepto bind, que requiere una ruta absoluta.
Las rutas se almacenan como conjuntos hash y los puertos como conjuntos de bits fijos para permitir la concatenación de opciones de forma sencilla y predecible.
-C nivel Establece el nivel de compatibilidad de landlock(7). Debe ser uno de hard-requirement, soft-requirement y best-effort.
El valor predeterminado es hard-requirement para adherirse al principio de valores predeterminados seguros.
El nivel puede especificarse de forma abreviada como hard (o h), soft (o s) y best (o b).
-E errata Consulta las correcciones de erratas de landlock(7) soportadas. Usa -E list para imprimir una lista de erratas conocidas.
El argumento puede ser un nombre o un número. Usa un número para consultar erratas no definidas.
Se pueden especificar múltiples erratas separadas por comas.
-F flags Establece las banderas de landlock_restrict_self(2). Usa -F list para imprimir una lista de banderas.
Consulta la sección FLAGS para obtener información sobre las banderas y su funcionalidad.
-S Habilita señales acotadas introducidas con landlock(7) ABI 6.
-U Habilita sockets abstractos UNIX acotados introducidos con landlock(7) ABI 6.
-r ruta Especifica una ruta de solo lectura, puede repetirse. Equivalente a -l read,readdir,exec,ioctl+ruta.
-w ruta Especifica una ruta de lectura-escritura, puede repetirse. Equivalente a -l all+ruta.
-b puerto[-puerto] Especifica un puerto para bind(2), puede repetirse. Equivalente a -l bind+puerto.
-c puerto[-puerto] Especifica un puerto para connect(2), puede repetirse. Equivalente a -l connect+puerto.

CONFIGURACIÓN

landlock(7) las categorías y sus recursos asociados (rutas o puertos) se proporcionan con la opción -l. Esta opción acepta una lista de categorías separadas por comas, seguida de un símbolo "+" (más) o "-" (menos) que indica añadir o eliminar la regla dada. Los conjuntos de reglas almacenan rutas como conjuntos hash y puertos como conjuntos de bits fijos para permitir la concatenación sencilla y predecible de múltiples opciones -l. Usa la opción -V para comprobar el soporte de landlock(7) en el kernel de Linux. El nivel de soporte específico puede determinarse por el código de salida. Usa la opción -A para comprobar la versión ABI de landlock(7).

ABI

landlock(7) el versionado ABI permite ajustar la política de seguridad según las capacidades del kernel. syd-lock tiene soporte para landlock(7) ABI 7, que es nuevo en Linux-6.15. Consulta la sección HISTORIA para obtener información sobre cuándo se introdujo cada ABI de landlock(7) en el kernel de Linux.

CONJUNTOS

A partir de la versión 3.38.0, se pueden especificar múltiples categorías separadas por comas y se definen los siguientes conjuntos para agilizar la composición de perfiles de sandbox. Los nombres se eligen intencionalmente para ser consistentes con pledge(2) de OpenBSD:

all Todos los derechos de acceso al sistema de archivos
rpath read, readdir
wpath write, truncate
cpath create, delete, rename
dpath mkbdev, mkcdev
spath mkfifo, symlink
tpath mkdir, rmdir
inet bind, connect

NIVELES DE COMPATIBILIDAD

A partir de la versión 3.35.0, el nivel de compatibilidad de landlock(7) puede establecerse usando la opción -C a uno de los siguientes niveles: hard-requirement, o simplemente hard o h, soft-requirement, o simplemente short o s, y best-effort, o simplemente best o b. El valor predeterminado es hard-requirement para adherirse al principio de valores predeterminados seguros. En este nivel, las restricciones de landlock(7) solicitadas solo se tienen en cuenta si son compatibles con el sistema en ejecución; si alguna característica solicitada no es compatible, la operación devuelve un error de compatibilidad y el sandbox no se activa. Los errores de open(2) de archivos durante la configuración del sandbox, incluido el errno(3) ENOENT ("No such file or directory"), devuelven un error fatal en este nivel. En el nivel soft-requirement, las restricciones solicitadas se tienen en cuenta si son compatibles con el sistema en ejecución, o la solicitud de sandboxing completa se ignora silenciosamente sin error de compatibilidad.

SYNOPSIS

syd-lock [-h | --help] [-V | --version] [-A | --list-abiversions] [-E | --check-errata] [-F FLAGS | --flags=FLAGS] [-l RULE | --rule=RULE]... [-p PATH | --path=PATH] [-s STRING | --string=STRING] [-t INTEGER | --timeout=INTEGER] [-u UID | --uid=UID] [-v | --verbose] [--] [COMMAND] [ARG]...

DESCRIPTION

The syd-lock(1) command allows you to execute a COMMAND with landlock(7) security restrictions applied on it. It takes a list of access rules and applies them to the specified command.

The restrictions are applied using the landlock(7) Linux Security Module. If the kernel does not support landlock(7), syd-lock(1) will exit with status 127.

There are several compatibility levels which can be specified:

hard-requirement
The requested restrictions are enforced. Any unsupported restriction results in a compatibility error and the command is not executed.
best-effort
The requested restrictions are taken into account if they are supported by the running system, and any unsupported restrictions are silently ignored; no compatibility error is returned.
soft-requirement
Similar to hard-requirement, but file open(2) errors with the ENOENT ("No such file or directory") errno(3) are silently ignored. Other file open(2) errors are fatal.

In soft-requirement and best-effort levels file open(2) errors with the ENOENT ("No such file or directory") errno(3) are silently ignored. Other file open(2) errors are fatal.

FLAGS

As of version 3.38.0, landlock(7) flags may be set using the -F option. Flags may be specified using their names or numerical values. Multiple flags may be set at once by specifying them as a comma-separated list. Flags are supported beginning with landlock(7) ABI 7 which is new in Linux-6.15. List of supported flags are given below. Setting a flag on an unsupported ABI is a NO-OP unless otherwise noted.

log_same_exec_off 1: Disables logging of denied accesses originating from the thread creating the landlock(7) domain, as well as its children, as long as they continue running the same executable code (i.e., without an intervening execve(2) call). This is intended for programs that execute unknown code without invoking execve(2), such as script interpreters. Programs that only sandbox themselves should not set this flag, so users can be notified of unauthorized access attempts via system logs. This flag requires landlock(7) ABI 7 support which is new in Linux-6.15.
log_new_exec_on 2: Enables logging of denied accesses after an execve(2) call, providing visibility into unauthorized access attempts by newly executed programs within the created landlock(7) domain. This flag is recommended only when all potential executables in the domain are expected to comply with the access restrictions, as excessive audit log entries could make it more difficult to identify critical events. This flag requires landlock(7) ABI 7 support which is new in Linux-6.15.
log_subdomains_off 4: Disables logging of denied accesses originating from nested landlock(7) domains created by the caller or its descendants. This flag should be set according to runtime configuration, not hardcoded, to avoid suppressing important security events. It is useful for container runtimes or sandboxing tools that may launch programs which themselves create landlock(7) domains and could otherwise generate excessive logs. Unlike log_same_exec_off, this flag only affects future nested domains, not the one being created. This flag requires landlock(7) ABI 7 support which is new in Linux-6.15.

SECURITY

As of version 3.35.0, the default landlock(7) compatibility level has been changed from best-effort to hard-requirement, and ENOENT (No such file or directory) errors are made fatal unless level is set to best-effort. This adheres to the principle of secure defaults and above all avoids the silent and dangerous trap where a non-existing file or directory which had been denied access (and skipped) at startup is created after and landlock(7) ends up allowing access to the newly created file or directory. For more information, see: https://landlock.io/rust-landlock/landlock/trait.Compatible.html

Consider combining syd-lock(1) use with syd-mdwe(1) to get W^X memory protections. See syd-mdwe(1) manual page for more information.

EXIT STATUS

syd-lock exits with the same code as the child process on clean exit. On unclean termination, exit code is set to 128 plus signal number. In case executing the child process fails syd-lock(1) exits with the errno(3) number. syd-lock -A exits with the landlock(7) ABI version as exit code.

syd-lock -E exits with one of the following exit codes:

0 All erratas are available.
1 Some erratas are not available.
2 No erratas are available.

syd-lock -V exits with one of the following exit codes based on support for the latest landlock(7) ABI:

0 Fully enforced
1 Partially enforced
2 Not enforced
127 Not supported

syd-lock exits with 22 (EINVAL) for invalid CLI arguments.
