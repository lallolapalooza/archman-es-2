NOMBRE

syncthing-versioning - Conserva copias de seguridad automáticas de archivos eliminados por otros nodos

Syncthing soporta el archivado de la versión antigua de un archivo cuando este es eliminado o reemplazado por una versión más reciente del clúster. Esto se llama "versionado de archivos" y utiliza una de las estrategias de versionado disponibles descritas a continuación. El versionado de archivos se configura por carpeta, por dispositivo, y por defecto es "sin versionado de archivos", es decir, no se conservan copias antiguas de los archivos.

NOTA:

El versionado se aplica a los cambios recibidos *de otros dispositivos*. Es decir, si Alice tiene el versionado activado y Bob cambia un archivo, la versión antigua se archivará en el ordenador de Alice cuando ese cambio se sincronice desde Bob. Si Alice cambia un archivo localmente en su propio ordenador, Syncthing no archivará la versión antigua y no puede hacerlo.

Las opciones de configuración aplicables para cada estrategia de versionado se describen a continuación. Para la mayoría de ellas es posible especificar dónde se almacenan las versiones, siendo la opción por defecto la carpeta .stversions dentro de la ruta de la carpeta compartida. Si establece una ruta de versión personalizada, asegúrese de que está en la misma partición o sistema de archivos que la ruta de la carpeta regular, ya que mover archivos allí podría fallar de otro modo.

VERSIONADO DE ARCHIVOS CON PAPELERA

Esta estrategia de versionado emula el enfoque común de "papelera". Cuando un archivo es eliminado o reemplazado debido a un cambio en un dispositivo remoto, se mueve a la papelera en la carpeta .stversions. Si un archivo con el mismo nombre ya estaba en la papelera, se reemplaza.

Hay disponible una opción de configuración para limpiar la papelera de archivos más antiguos que un número especificado de días. Si esto se establece en un número positivo de días, los archivos se eliminarán cuando hayan estado en la papelera durante ese tiempo. Establecer esto en cero impide que los archivos se eliminen automáticamente de la papelera.

VERSIONADO SIMPLE DE ARCHIVOS

Con el "Versionado Simple de Archivos", los archivos se mueven a la carpeta .stversions cuando son reemplazados o eliminados en un dispositivo remoto. Además de la opción cleanoutDays, esta estrategia también toma un valor en un campo de entrada titulado "Conservar Versiones" que indica a Syncthing cuántas versiones antiguas del archivo debe *conservar*. Por ejemplo, si establece este valor en 5, si un archivo se reemplaza 5 veces en un dispositivo remoto, verá 5 versiones con marca de tiempo de ese archivo en la carpeta .stversions en los otros dispositivos que comparten la misma carpeta.

VERSIONADO ESCALONADO DE ARCHIVOS

Con el "Versionado Escalonado de Archivos", los archivos también se mueven a la carpeta .stversions cuando son reemplazados o eliminados en un dispositivo remoto (al igual que con el "Versionado Simple de Archivos"), sin embargo, las versiones se eliminan automáticamente si son más antiguas que la edad máxima o si superan el número de archivos permitidos en un intervalo.

Los siguientes intervalos se utilizan y cada uno tiene un número máximo de archivos que se conservarán para cada uno.

1 Hora
Durante la primera hora, se conserva la versión más antigua de cada intervalo de 30 segundos.
1 Día
Durante el primer día, se conserva la versión más antigua de cada hora.
30 Días
Durante los primeros 30 días, se conserva la versión más antigua de cada día.
Hasta Edad Máxima
Hasta la edad máxima, se conserva la versión más antigua de cada semana.
Edad Máxima
El tiempo máximo para conservar una versión en días. Por ejemplo, para conservar archivos reemplazados o eliminados en la carpeta .stversions durante un año completo, use 365. Si solo durante 10 días, use 10. Corresponde a la opción maxAge. Nota: Establézcalo en 0 para conservar versiones para siempre.

Esto significa que solo hay una versión en cada intervalo y, a medida que los archivos envejecen, se eliminarán a menos que el intervalo al que están entrando esté vacío. Al conservar las versiones más antiguas, este esquema de versionado preserva el archivo si se sobrescribe.

VERSIONADO EXTERNO DE ARCHIVOS

Esta estrategia de versionado delega la decisión sobre qué hacer a un *comando externo* (por ejemplo, un programa o un script de línea de comandos). Justo antes de que un archivo sea reemplazado, se ejecutará el comando. El archivo debe ser eliminado de la carpeta en el proceso, o Syncthing informará de un error. El comando puede utilizar los siguientes argumentos con plantillas:

%FOLDER_PATH%
Ruta a la carpeta
%FILE_PATH%
Ruta al archivo dentro de la carpeta

Tenga en cuenta que el primero se expande a la ruta de la carpeta real de Syncthing, y el segundo a la ruta dentro de esa carpeta. Por ejemplo, si utiliza la carpeta predeterminada Sync en Windows y la ruta completa al archivo es C:\Users\Usuario\Sync\Fotos familiares\IMG_2021-03-01.jpg, entonces %FOLDER_PATH% será C:\Users\Usuario\Sync y %FILE_PATH% será Fotos familiares\IMG_2021-03-01.jpg.

Ejemplo para Unixes

Supongamos que quiero conservar la última versión de cada archivo a medida que se reemplazan o eliminan; esencialmente quiero un comportamiento similar a una "papelera". Para ello, creo el siguiente script y lo guardo como /Users/jb/bin/onlylatest.sh (es decir, el directorio bin en mi directorio personal):

#!/bin/sh
set -eu
# Dónde quiero almacenar mis versiones
versionspath=~/.trashcan
# Los parámetros que obtenemos de Syncthing
folderpath="$1"
filepath="$2"
# Primero, asegúrese de que exista el directorio donde necesitamos almacenar el archivo
outpath=$(dirname "$versionspath/$filepath")
mkdir -p "$outpath"
# Luego, mueva el archivo allí
mv -f "$folderpath/$filepath" "$versionspath/$filepath"

Debo asegurarme de que el script tenga permisos de ejecución (chmod 755 onlylatest.sh), luego configurar Syncthing con el comando /Users/jb/bin/onlylatest.sh %FOLDER_PATH% %FILE_PATH%

Supongamos que tengo una carpeta "predeterminada" en ~/Sync, y que dentro de esa carpeta hay un archivo docs/carta.txt que está siendo reemplazado o eliminado. El script se llamará como si lo ejecutara desde la línea de comandos:

$ /Users/jb/bin/onlylatest.sh /Users/jb/Sync docs/carta.txt

El script moverá el archivo en cuestión a ~/.trashcan/docs/carta.txt, reemplazando cualquier versión anterior de esa carta que pudiera haber estado allí.

Ejemplos para Windows

Mover a una carpeta dada usando el símbolo del sistema (CMD)

En Windows podemos usar un script de lotes para realizar el mismo comportamiento similar a una "papelera" que se mencionó anteriormente. Creé el siguiente script y lo guardé como C:\Users\mfrnd\Scripts\onlylatest.bat.

@echo off
rem Habilitar codificación UTF-8 para manejar nombres de carpetas y archivos multilingües
chcp 65001
rem Necesitamos extensiones de comando para md para crear carpetas intermedias de una vez
setlocal enableextensions
rem Dónde quiero almacenar mis versiones
set "versions_path=%USERPROFILE%\.trashcan"
rem Los parámetros que obtenemos de Syncthing, '~' elimina las comillas si las hay
set "folder_path=%~1"
set "file_path=%~2"
rem Primero, asegúrese de que exista el directorio donde necesitamos almacenar el archivo
for %%f in ("%versions_path%\%file_path%") do set "output_path=%%~dpf"
if not exist "%output_path%" md "%output_path%" || exit /b
rem Finalmente, mueva el archivo, sobrescribiendo el archivo existente si lo hay
move /y "%folder_path%\%file_path%" "%versions_path%\%file_

Ahora, si un archivo docs\letter.txt en la carpeta C:\Users\mfrnd\Sync es reemplazado o eliminado, será movido a C:\Users\mfrnd\.trashcan\docs\letter.txt, reemplazando la versión anterior si ya existía.

Para utilizar este script, debe configurar Syncthing para que ejecute el siguiente comando:

C:\Users\mfrnd\Scripts\onlylatest.bat %FOLDER_PATH% %FILE_PATH%

Tenga en cuenta que el comando move con el parámetro `/y` sobrescribirá el archivo existente en el destino sin pedir confirmación. El comando md creará las carpetas necesarias en la ruta de destino si no existen. El comando chcp 65001 habilita la codificación UTF-8, que es importante para nombres de archivos y carpetas que contienen caracteres especiales o no ingleses.

path%"

Finalmente, establecí "C:\Users\mfrnd\Scripts\onlylatest.bat" "%FOLDER_PATH%" "%FILE_PATH%" como el nombre del comando en Syncthing.

Mover a la Papelera de Reciclaje usando PowerShell

Podemos usar PowerShell para enviar archivos directamente a la Papelera de Reciclaje, lo que imita el comportamiento de eliminarlos usando el Explorador de Windows. Primero, cree el siguiente script y guárdelo en su ubicación preferida, por ejemplo, C:\Users\User\Scripts\SendToRecycleBin.ps1.

# PowerShell no tiene un método nativo para reciclar archivos, así que usamos Visual
# Basic para realizar la operación. Si tiene éxito, también incluimos el
# archivo reciclado en la salida DEBUG de Syncthing.
Add-Type -AssemblyName Microsoft.VisualBasic
[Microsoft.VisualBasic.FileIO.FileSystem]::DeleteFile($args,'OnlyErrorDialogs','SendToRecycleBin')
if ($?) {
  Write-Output ("Recycled " + $args + ".")
}

Alternativamente, el script puede ser ampliado para enviar solo los archivos eliminados a la Papelera de Reciclaje, y eliminar permanentemente los modificados, lo que lo hace más coherente con la forma en que funciona el Explorador.

# PowerShell no tiene un método nativo para reciclar archivos, así que usamos Visual
# Basic para realizar la operación.
Add-Type -AssemblyName Microsoft.VisualBasic
# Necesitamos probar si existe un archivo .tmp de Syncthing. Si existe, asumimos
# una modificación y eliminamos el archivo existente. Si no existe, asumimos
# una eliminación y reciclamos el archivo actual. Si tiene éxito, también incluimos
# el archivo eliminado/reciclado en la salida DEBUG de Syncthing.
if (Test-Path -LiteralPath ((Split-Path -Path $args) + "\~syncthing~" + (Split-Path -Path $args -Leaf) + ".tmp")) {
  [Microsoft.VisualBasic.FileIO.FileSystem]::DeleteFile($args,'OnlyErrorDialogs','DeletePermanently')
  if ($?) {
    Write-Output ("Deleted " + $args + ".")
  }
} else {
  [Microsoft.VisualBasic.FileIO.FileSystem]::DeleteFile($args,'OnlyErrorDialogs','SendToRecycleBin')
  if ($?) {
    Write-Output ("Recycled " + $args + ".")
  }
}

Finalmente, establecemos el nombre del comando en Syncthing a powershell.exe -ExecutionPolicy Bypass -File "C:\Users\User\Scripts\SendToRecycleBin.ps1" "%FOLDER_PATH%\%FILE_PATH%".

La única advertencia de la que debe ser consciente es que si su carpeta de Syncthing se encuentra en un almacenamiento portátil, como una memoria USB, o si tiene deshabilitada la Papelera de Reciclaje, entonces el script terminará eliminando todos los archivos permanentemente.

REFERENCIA DE PARÁMETROS DE CONFIGURACIÓN

La configuración de versionado se agrupa en su propia sección de cada carpeta en el archivo de configuración. Lo siguiente muestra un ejemplo de dicha sección en XML:

<folder id="...">
    <versioning type="simple">
        <cleanupIntervalS>3600</cleanupIntervalS>
        <fsPath></fsPath>
        <fsType>basic</fsType>
        <param key="cleanoutDays" val="0"></param>
        <param key="keep" val="5"></param>
    </versioning>
</folder>
versioning.type
Selecciona una de las estrategias de versionado: trashcan, simple, staggered, external o déjelo vacío para deshabilitar el versionado completamente.
versioning.fsPath
Anula la ruta donde se almacenan las versiones antiguas de los archivos y por defecto es .stversions si se deja vacío. Se puede especificar una ruta absoluta o relativa. Esta última se interpreta en relación con la ruta de la carpeta compartida, si el fsType está configurado como basic. Ignorado para la estrategia de versionado external.

Esta opción solía almacenarse bajo las claves fsPath o versionsPath en el elemento params.

versioning.fsType
La implementación del sistema de archivos interno utilizada para acceder a esta carpeta de versiones. Solo se aplica si fsPath también está configurado como no vacío, de lo contrario, se utiliza el filesystemType del elemento de carpeta. Consulte la descripción de esa opción para ver los valores posibles. Ignorado para la estrategia de versionado external.

Esta opción solía almacenarse bajo la clave fsType en el elemento params.

versioning.cleanupIntervalS
El intervalo, en segundos, para ejecutar la limpieza en la carpeta de versiones. Cero para deshabilitar la limpieza periódica. Limitado a un año (31536000 segundos). Ignorado para la estrategia de versionado external.

Esta opción solía almacenarse bajo la clave cleanInterval en el elemento params.

versioning.params
Cada estrategia de versionado puede tener parámetros de configuración específicos para su implementación bajo este elemento.
versioning.params.cleanoutDays
El número de días para mantener los archivos en la carpeta de versiones. Cero significa mantener para siempre. Se eliminan los elementos más antiguos encontrados durante la limpieza.
versioning.params.keep
El número de versiones antiguas a mantener, por archivo.
versioning.params.maxAge
El tiempo máximo para mantener una versión, en segundos. Cero significa mantener para siempre.
versioning.params.command
Comando externo a ejecutar para almacenar una versión de archivo que está a punto de ser reemplazada o eliminada. Si la ruta de la aplicación contiene espacios, debe ir entre comillas.
