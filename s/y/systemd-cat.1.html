NOMBRE

systemd-cat - Conecta una tubería o la salida de un programa con el journal

SINOPSIS

systemd-cat [OPCIONES...] [COMANDO] [ARGUMENTOS...]

systemd-cat [OPCIONES...]

DESCRIPCIÓN

systemd-cat puede usarse para conectar la entrada y salida estándar de un proceso al journal, o como una herramienta de filtrado en una tubería de shell para pasar la salida que el elemento anterior de la tubería genera al journal.

Si no se pasa ningún parámetro, systemd-cat escribirá todo lo que lea de la entrada estándar (stdin) en el journal.

Si se pasan parámetros, se ejecutan como línea de comandos con la salida estándar (stdout) y la salida de error estándar (stderr) conectadas al journal, de modo que todo lo que escriba se almacene en el journal.

OPCIONES

Se entienden las siguientes opciones:

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.

-t, --identifier=

Especifica una cadena corta que se utiliza para identificar la herramienta de registro. Si no se especifica, no se establece ninguna cadena de identificación para la entrada del journal, y el nombre del ejecutable (o "cat" si la entrada se lee de una tubería) se utilizará para describir la fuente del registro en su lugar.

-p, --priority=

Especifica el nivel de prioridad predeterminado para los mensajes registrados. Pasa uno de "emerg", "alert", "crit", "err", "warning", "notice", "info", "debug", o un valor entre 0 y 7 (correspondiente a los mismos niveles con nombre). Estos valores de prioridad son los mismos que los definidos por syslog(3). Por defecto es "info". Tenga en cuenta que esto solo controla el valor predeterminado, las líneas individuales pueden registrarse con diferentes niveles si se anteponen adecuadamente. Para más detalles, vea --level-prefix= a continuación.

--stderr-priority=

Especifica el nivel de prioridad predeterminado para los mensajes de la salida de error estándar (stderr) del proceso. El uso de esta opción es el mismo que la opción --priority=, y ambas se pueden usar a la vez. Cuando ambas se usan, --priority= especificará la prioridad predeterminada para la salida estándar (stdout).

Si no se especifica --stderr-priority=, los mensajes de stderr aún se registrarán, con el mismo nivel de prioridad predeterminado que stdout.

Además, tenga en cuenta que cuando stdout y stderr utilizan la misma prioridad predeterminada, los mensajes se ordenarán estrictamente, ya que se utiliza un canal para ambos. Cuando la prioridad predeterminada difiere, se utilizan dos canales, y los mensajes de stdout no se ordenarán estrictamente con respecto a los mensajes de stderr, aunque tenderán a estar aproximadamente ordenados.

Añadido en la versión 241.

--level-prefix=

Controla si las líneas leídas se analizan para obtener prefijos de nivel de prioridad de syslog. Si está habilitado (el valor predeterminado), una línea precedida por un prefijo de prioridad como "<5>" se registrará con prioridad 5 ("notice"), y de manera similar para los otros niveles de prioridad. Toma un argumento booleano.

--namespace=

Especifica el espacio de nombres del journal al que se deberían conectar las E/S estándar. Para más detalles sobre los espacios de nombres del journal, vea systemd-journald.service(8).

Añadido en la versión 256.

CÓDIGO DE SALIDA

En caso de éxito, se devuelve 0, de lo contrario un código de error distinto de cero.

EJEMPLOS

Ejemplo 1. Invocar un programa

Esto llama a /bin/ls con la salida estándar y el error conectados al journal:

# systemd-cat ls

Ejemplo 2. Uso en una tubería de shell

Esto construye una tubería de shell invocando también /bin/ls y escribe la salida que genera en el journal:

# ls | systemd-cat

Aunque los dos ejemplos tienen efectos muy similares, el primero es preferible, ya que solo se ejecuta un proceso a la vez y se capturan tanto stdout como stderr, mientras que en el segundo ejemplo, solo se captura stdout.
