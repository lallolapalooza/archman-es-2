NOMBRE

systemd-creds - Lista, muestra, cifra y descifra credenciales de servicio

SINOPSIS

systemd-creds [OPCIONES...] COMANDO [ARGUMENTOS...]

DESCRIPCIÓN

systemd-creds es una herramienta para listar, mostrar, cifrar y descifrar credenciales de unidades. Las credenciales son objetos binarios o textuales de tamaño limitado que pueden pasarse a los procesos de las unidades. Se utilizan principalmente para pasar claves criptográficas (tanto públicas como privadas) o certificados, información de cuentas de usuario o información de identidad del host a los servicios.

Las credenciales se configuran en archivos de unidad a través de los ajustes ImportCredential=, LoadCredential=, SetCredential=, LoadCredentialEncrypted= y SetCredentialEncrypted=. Consulte systemd.exec(5) para más detalles.

Para más información, consulte la documentación de System and Service Credentials[1].

COMANDOS

Se entienden los siguientes comandos:

list

Muestra una lista de las credenciales pasadas al contexto de ejecución actual. Este comando muestra los archivos en el directorio al que hace referencia la variable de entorno $CREDENTIALS_DIRECTORY y está pensado para ejecutarse desde el contexto del servicio.

Junto con cada nombre de credencial, se muestra el tamaño y el estado de seguridad. Este último es uno de "secure" (en caso de que la credencial esté respaldada por memoria no paginable, es decir, "ramfs"), "weak" (en caso de que esté respaldada por cualquier otro tipo de memoria) o "insecure" (si tiene algún modo de acceso que no sea 0400, es decir, si es legible por cualquiera excepto el propietario).

Añadido en la versión 250.

cat credencial...

Muestra el contenido de las credenciales especificadas pasadas al contexto de ejecución actual. Toma uno o más nombres de credenciales, cuyo contenido se escribirá en la salida estándar.

Cuando se combina con --json= o --transcode=, la salida se transcodifica de forma sencilla antes de mostrarse.

Añadido en la versión 250.

setup

Genera una clave de cifrado de host para las credenciales, si no se ha generado ya una. Esto asegura que el archivo /var/lib/systemd/credential.secret se inicializa con una clave secreta aleatoria si no existe. Esta clave secreta se utiliza al cifrar/descifrar credenciales con encrypt o decrypt, y solo es accesible para el usuario root. Tenga en cuenta que normalmente no es necesario invocar este comando explícitamente, ya que se llama implícitamente cuando se invoca encrypt y se selecciona el cifrado de clave de host de credenciales.

Añadido en la versión 250.

encrypt entrada|- salida|-

Carga el archivo de credencial (texto plano no cifrado) especificado, lo cifra y escribe el (texto cifrado cifrado) resultante en el archivo de credencial de destino especificado. El archivo resultante puede hacer referencia en el ajuste LoadCredentialEncrypted= en los archivos de unidad, o su contenido puede usarse literalmente en los ajustes SetCredentialEncrypted=.

Toma dos rutas de archivo. La parte del nombre de archivo de la ruta de salida se incrusta como nombre en la credencial cifrada, para asegurar que las credenciales cifradas no puedan ser renombradas y reutilizadas para propósitos diferentes sin que esto se note. El nombre de la credencial a incrustar puede ser anulado con el ajuste --name=. Las rutas de entrada o salida pueden especificarse como "-" (guion), en cuyo caso los datos de la credencial se leen de/escriben en la entrada estándar y la salida estándar. Si la ruta de salida se especifica como "-", el nombre de la credencial no puede derivarse de la ruta del archivo y, por lo tanto, debe especificarse explícitamente con el interruptor --name=.

Los datos de la credencial se cifran y autentican simétricamente con una de las siguientes claves de cifrado:

1.Una clave secreta derivada automáticamente del chip TPM2 del sistema. Esta clave de cifrado no se almacena en el sistema host y, por lo tanto, el descifrado solo es posible con acceso al chip TPM2 original. O en otras palabras, la credencial asegurada de esta manera solo se puede descifrar de nuevo por la máquina local.
2.Una clave secreta almacenada en el archivo /var/lib/systemd/credential.secret, que solo es accesible para el usuario root. Esta clave de cifrado de "host" se almacena en el sistema de archivos host y, por lo tanto, el descifrado es posible con acceso al sistema de archivos host y privilegios suficientes. La clave se genera automáticamente cuando es necesario, pero también se puede crear explícitamente con el comando setup, véase arriba.
3.Una combinación de las anteriores: una clave de cifrado derivada tanto del chip TPM2 como del sistema de archivos host. Esto significa que el descifrado requiere tanto acceso al chip TPM2 original como a la instalación del SO. Este es el modo de operación predeterminado si está disponible un chip TPM2 y /var/lib/systemd/ reside en medios persistentes.

Cuál de las tres claves se debe utilizar para el cifrado puede configurarse con el interruptor --with-key=. Dependiendo del caso de uso de la credencial cifrada, la clave a utilizar puede variar. Por ejemplo, para credenciales que deban ser accesibles desde el initrd, el cifrado con la clave del host no es apropiado, ya que el acceso a la clave del host normalmente no está disponible desde el initrd. Por lo tanto, para tales credenciales, solo se debe usar la clave TPM2.

Las credenciales cifradas siempre están codificadas en Base64.

Utilice decrypt (ver abajo) para deshacer la operación de cifrado y obtener la credencial de texto plano descifrada a partir del texto cifrado cifrado.

Los datos de la credencial se cifran utilizando AES256-GCM, es decir, proporcionando tanto confidencialidad como integridad, con clave derivada de un hash SHA256 de una o ambas claves secretas descritas anteriormente.

Añadido en la versión 250.

decrypt entrada|- [salida|-]

Deshace el efecto de la operación encrypt: carga el archivo de credencial de entrada (texto cifrado cifrado) especificado, lo descifra y autentica, y escribe la salida (texto plano descifrado) en el archivo de credencial de destino especificado.

Toma una o dos rutas de archivo. La parte del nombre de archivo de la ruta de entrada se compara con el nombre de credencial incrustado en el archivo cifrado. Si no coincide, el descifrado falla. Esto se hace para garantizar que las credenciales cifradas no se reutilicen sin que esto se detecte. El nombre de la credencial a comparar con el nombre de credencial incrustado también puede ser anulado con el interruptor --name=. Si la ruta de entrada se especifica como "-", la credencial cifrada se lee de la entrada estándar. Si solo se especifica una ruta o la ruta de salida se especifica como "-", la credencial descifrada se escribe en la salida estándar. En este modo, el nombre esperado incrustado en la credencial no puede derivarse de la ruta y debe especificarse explícitamente con --name=.

El descifrado de credenciales requiere acceso al chip TPM2 original y/o a las credenciales de clave de host, véase arriba. La información sobre qué claves se requieren está incrustada en los datos de la credencial cifrada y, por lo tanto, el descifrado es completamente automático.

Añadido en la versión 250.

--no-ask-password

No solicitar al usuario autenticación para operaciones privilegiadas.

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una cadena corta de versión y sale.

OPCIONES

--system

Cuando se especifica con los comandos list y cat, opera en las credenciales pasadas al sistema en su conjunto en lugar de en las pasadas al contexto de ejecución actual. Esto es útil en entornos de contenedores donde las credenciales pueden ser pasadas por el gestor de contenedores.

Añadido en la versión 250.

--user

Cuando se especifica con los comandos encrypt y decrypt, cifra una credencial de ámbito de usuario (en lugar de ámbito de sistema). Use --uid= para seleccionar de qué usuario es la credencial. Dichas credenciales solo pueden ser descifradas desde el contexto del usuario especificado, excepto si se pueden adquirir privilegios. En general, cuando una credencial cifrada se va a utilizar en el gestor de servicios por usuario, debe cifrarse con esta opción activada; cuando se va a utilizar en el gestor de servicios del sistema, debe cifrarse sin ella.

Internamente, esto asegura que la UID numérica y el nombre de usuario del usuario seleccionado, así como el machine-id(5) del sistema, se incorporan

OPTIONS

The following options are understood:

--key=PATH

Specifies the encryption key to use. Takes a path to a file containing the key. If omitted, the key is read from standard input. This option is only effective when encrypting. When decrypting, the key is retrieved from the encrypted credential itself.

Added in version 256.

--uid=

Especifica el usuario para el que se cifra la credencial. Acepta un nombre de usuario o UID numérico. Si se establece, implica --user. Si se establece en la cadena especial "self", establece el usuario al usuario del proceso que llama. Si se usa --user sin --uid=, se implica --uid=self, es decir, la credencial se cifra para el usuario que llama.

Añadido en la versión 256.

--transcode=

Cuando se especifica con los comandos cat o decrypt, transcodifica la salida antes de mostrarla. Acepta como argumento "base64", "unbase64", "hex" o "unhex", para codificar/decodificar los datos de la credencial con Base64 o como una serie de valores hexadecimales. El valor especial "help" puede ser utilizado para listar los tipos de transcodificación compatibles.

Tenga en cuenta que esto no tiene ningún efecto en el comando encrypt, ya que las credenciales cifradas se codifican incondicionalmente en Base64.

Añadido en la versión 250.

--newline=

Cuando se especifica con cat o decrypt, controla si se añade un carácter de nueva línea al final de la salida si esta no termina ya en uno. Acepta "auto", "yes" o "no". El modo por defecto "auto" añadirá un solo carácter de nueva línea solo cuando la salida de los datos de la credencial se dirija a una TTY.

Añadido en la versión 250.

--pretty, -p

Cuando se especifica con encrypt, controla si se muestra la credencial cifrada como una configuración SetCredentialEncrypted= que puede ser pegada directamente en un archivo de unidad. Solo tiene efecto cuando se usa junto con --name= y "-" como archivo de salida.

Añadido en la versión 250.

--name=name

Cuando se especifica con el comando encrypt, controla el nombre de la credencial a incrustar en los datos de la credencial cifrada. Si no se especifica, el nombre se elige automáticamente del componente del nombre de archivo de la ruta de salida especificada. Si se especifica como una cadena vacía, no se incrusta ningún nombre de credencial en la credencial cifrada, y no se realiza ninguna verificación del nombre de la credencial al descifrarla.

Cuando se especifica con el comando decrypt, controla el nombre de la credencial con el que validar el nombre de credencial incrustado en la credencial cifrada. Si no se especifica, el nombre se elige automáticamente del componente del nombre de archivo de la ruta de entrada especificada. Si no se incrusta ningún nombre de credencial en el archivo de credencial cifrada (es decir, se utilizó --name= con una cadena vacía al cifrarla), el nombre especificado no tiene ningún efecto ya que no se realiza ninguna validación del nombre de la credencial.

Incrustar el nombre de la credencial en la credencial cifrada se hace para proteger contra la reutilización de credenciales para fines para los que no fueron concebidas originalmente, asumiendo que el nombre de la credencial se elige cuidadosamente para codificar su propósito previsto.

Añadido en la versión 250.

--timestamp=timestamp

Cuando se especifica con el comando encrypt, controla la marca de tiempo a incrustar en la credencial cifrada. Por defecto, usa la hora actual. Acepta una especificación de marca de tiempo en el formato descrito en systemd.time(7).

Cuando se especifica con el comando decrypt, controla la marca de tiempo a usar para validar la marca de tiempo "no-después" que se configuró con --not-after= durante el cifrado. Si no se especifica, por defecto usa la hora actual del sistema.

Añadido en la versión 250.

--not-after=timestamp

Cuando se especifica con el comando encrypt, controla la hora a partir de la cual la credencial ya no debe ser utilizada. Esto incrusta la marca de tiempo especificada en la credencial cifrada. Durante el descifrado, la marca de tiempo se compara con el reloj actual del sistema y, si la marca de tiempo está en el pasado, el descifrado fallará. Por defecto, no se establece ninguna marca de tiempo de este tipo. Acepta una especificación de marca de tiempo en el formato descrito en systemd.time(7).

Añadido en la versión 250.

--with-key=, -H, -T

Cuando se especifica con el comando encrypt, controla la clave de cifrado/firma a usar. Acepta "host", "tpm2", "host+tpm2", "null", "auto", "auto-initrd". Vea arriba los detalles sobre los tres tipos de clave. Si se establece en "auto" (que es el valor por defecto) se utiliza la clave TPM2 si se encuentra un dispositivo TPM2 y no se está ejecutando en un contenedor. La clave del host se utiliza si /var/lib/systemd/ está en medios persistentes. Esto significa que en sistemas típicos, el cifrado está por defecto vinculado tanto al chip TPM2 como a la instalación del SO, y ambos deben estar disponibles para descifrar la credencial de nuevo. Si se selecciona "auto" pero no está disponible TPM2 (o se ejecuta en un contenedor) ni /var/lib/systemd/ está en medios persistentes, el cifrado fallará. Si se establece en "null" se utiliza una clave de longitud cero fija (¡así, en este modo no se proporciona ni confidencialidad ni autenticidad!). Esta lógica es útil para cubrir sistemas que carecen de un chip TPM2 pero donde se deben generar credenciales. Tenga en cuenta que el descifrado de tales credenciales se rechaza en sistemas que tienen un chip TPM2 y donde UEFI SecureBoot está habilitado (esto se hace para que un sistema tan bloqueado no pueda ser engañado para cargar una credencial generada de esta manera que carezca de información de autenticación). Si se establece en "auto-initrd", se utiliza una clave TPM2 si se encuentra un TPM2. Si no, se utiliza una clave fija de longitud cero, equivalente al modo "null". Esta opción es particularmente útil para generar archivos de credenciales que se cifran/autentican contra TPM2 donde esté disponible pero que aún funcionen en sistemas que carezcan de soporte para ello. El valor especial "help" puede ser utilizado para listar los tipos de clave compatibles.

El interruptor -H es un atajo para --with-key=host. De manera similar, -T es un atajo para --with-key=tpm2.

Al cifrar credenciales que se utilizarán en el initrd (donde /var/lib/systemd/ normalmente no está disponible), asegúrese de usar el modo --with-key=auto-initrd, para deshabilitar el enlace con el secreto del host.

Este interruptor no tiene efecto en el comando decrypt, ya que la información sobre qué clave usar para el descifrado ya está incluida en la credencial cifrada.

Añadido en la versión 250.

--tpm2-device=PATH

Controla el dispositivo TPM2 a utilizar. Espera una ruta de nodo de dispositivo que haga referencia al chip TPM2 (por ejemplo, /dev/tpmrm0). Alternativamente, se puede especificar el valor especial "auto", para determinar automáticamente el nodo del dispositivo de un dispositivo TPM2 adecuado (del cual debe haber exactamente uno). El valor especial "list" puede ser utilizado para enumerar todos los dispositivos TPM2 adecuados actualmente descubiertos.

Añadido en la versión 250.

--tpm2-pcrs=PCR[+PCR...]

Configura los PCR (Registros de Configuración de Plataforma) TPM2 a los que vincular la clave de cifrado. Acepta una lista separada por "+" de índices de PCR numéricos en el rango 0...23. Si se especifica una cadena vacía, vincula la clave de cifrado a ningún PCR (este es también el valor por defecto si no se usa esta opción). Para más detalles sobre los PCR disponibles, consulte la documentación del interruptor del mismo nombre para systemd-cryptenroll(1).

Añadido en la versión 250.

--tpm2-public-key=PATH, --tpm2-public-key-pcrs=PCR[+PCR...]

Configura una política de PCR firmada por TPM2 para vincular el cifrado, para su uso con el comando encrypt. La opción --tpm2-public-key= acepta una ruta a una clave pública RSA codificada en PEM, para vincular el cifrado. Si no se especifica explícitamente, pero existe un archivo tpm2-pcr-public-key.pem en uno de los directorios /etc/systemd/, /run/systemd/, /usr/lib/systemd/ (buscados en este orden), se utiliza automáticamente. La opción --tpm2-public-key-pcrs= acepta una lista de índices de PCR TPM2 a los que vincular (misma sintaxis que --tpm2-pcrs= descrita anteriormente). Si no se especifica, por defecto es 11 (es decir, esto vincula la política a cualquier imagen de kernel unificada para la que se pueda proporcionar una firma PCR).

Tenga en cuenta la diferencia entre --tpm2-pcrs= y --tpm2-public-key-pcrs=: el primero vincula el descifrado a los valores actuales y específicos de los PCR; el segundo vincula el descifrado a cualquier conjunto de valores de PCR para los que se pueda proporcionar una firma de la clave pública especificada. Este último es, por lo tanto, más útil en escenarios donde las actualizaciones de software deben ser posibles sin perder el acceso a todos los secretos cifrados previamente.

Añadido en la versión 252.

--tpm2-signature=PATH

Acepta una ruta a un archivo de firma PCR TPM2, tal como lo genera la herramienta systemd-measure(1), y que puede ser utilizado para permitir que el comando decrypt descifre credenciales que están vinculadas a valores PCR firmados específicos. Si no se especifica explícitamente, y se intenta descifrar una credencial con una política PCR firmada, se busca un archivo de firma adecuado tpm2-pcr-signature.json en /etc/systemd/, /run/systemd/, /usr/lib/systemd/ (en este orden) y se utiliza.

Añadido en la versión 252.

--allow-null

Permite descifrar credenciales que utilizan una clave vacía.

Añadido en la versión 256.

--quiet, -q

Suprime la salida adicional.

Añadido en la versión 251.

--no-pager

No redirige la salida a un paginador.

--no-legend

No imprime la leyenda, es decir, las cabeceras de columna y el pie de página con sugerencias.

--json=MODE

Muestra la salida formateada como JSON. Espera "short" (para la salida más corta posible sin espacios en blanco redundantes ni saltos de línea), "pretty" (para una versión bonita de la misma, con indentación y saltos de línea) o "off" (para desactivar la salida JSON, que es el valor por defecto).

ESTADO DE SALIDA

En caso de éxito, se devuelve 0.

EJEMPLOS

Ejemplo 1. Cifrar una contraseña para usarla como credencial

La siguiente línea de comandos cifra la contraseña especificada "hunter2", escribiendo el resultado en el archivo password.cred.

# echo -n hunter2 | systemd-creds encrypt - password.cred

Esto descifra el archivo password.cred nuevamente, revelando la contraseña literal:

# systemd-creds decrypt password.cred
hunter2

systemd-creds(1) — systemd manual

NAME

systemd-creds — manage credentials for systemd services

SYNOPSIS

systemd-creds -h | --help

systemd-creds --list [-p | --user]

systemd-creds --create [-p | --user] [--name=NAME] [--lifetime=TIME] [--group=GROUP] [--owner=USER] [--mode=OCTAL]

systemd-creds --update [-p | --user] --name=NAME [--lifetime=TIME] [--group=GROUP] [--owner=USER] [--mode=OCTAL]

systemd-creds --delete [-p | --user] --name=NAME

systemd-creds --export [-p | --user] [--name=NAME] [--output=FILE] [--format=FMT]

systemd-creds --import [-p | --user] [--input=FILE] [--format=FMT]

systemd-creds --encrypt [-p | --user] [--name=NAME] [--lifetime=TIME] [--group=GROUP] [--owner=USER] [--mode=OCTAL] [-t | --template=TEMPLATE] [-d | --directory=DIR] [FILE...]

systemd-creds --decrypt [-p | --user] --name=NAME [-d | --directory=DIR] [FILE...]

DESCRIPTION

systemd-creds is a utility to manage credentials for systemd services. Credentials are sensitive values, such as passwords, API keys, or certificates, that are needed by services to authenticate and operate. They are stored encrypted and are only decrypted when a service explicitly requests them and is authorized to do so.

The primary goal is to allow system administrators to securely store and manage sensitive information needed by services, without embedding them directly in configuration files or service unit files. Credentials are stored in separate files, and access is controlled based on the service's identity and authorization.

Credentials can be managed for the system globally (default) or for a specific user. System credentials are typically stored in /etc/systemd/creds/ and user credentials in ~/.config/systemd/creds/.

This utility allows for the creation, deletion, updating, listing, exporting, importing, encryption, and decryption of credentials. It integrates with systemd-ask-password(1) to securely obtain sensitive values like passwords from the user.

COMMANDS

systemd-creds supports the following commands:

--list
List all available credentials. By default, lists system credentials. Use --user to list user credentials.
--create
Create a new credential. You will be prompted to enter the sensitive value unless it is piped via standard input. The credential will be stored encrypted. Use --name=NAME to specify the credential name (e.g., "database-password"). Other options control lifetime, group ownership, owner, and file permissions. Use --user to create a user credential.
--update
Update an existing credential. You will be prompted for the new value unless it is piped via standard input. Use --name=NAME to specify which credential to update. Other options control lifetime, group ownership, owner, and file permissions. Use --user to update a user credential.
--delete
Delete a credential. Use --name=NAME to specify the credential to delete. Use --user to delete a user credential.
--export
Export a credential in a specified format. Use --name=NAME to specify the credential. The output can be directed to a file using --output=FILE or to standard output. The default format is json. Use --user to export a user credential.
--import
Import credentials from a file. The format is inferred from the file content or can be specified with --format=FMT. Use --input=FILE to specify the input file, or pipe the data via standard input. Use --user to import user credentials.
--encrypt
Encrypt sensitive data, typically a password or key, and generate a SetCredentialEncrypted= line suitable for inclusion in a systemd unit file. The sensitive data should be provided via standard input or as arguments to -t / --template. If --name=NAME is specified, the credential will be stored in the system's or user's credential store. If FILE... arguments are provided, the encrypted data will be written to these files. Use --user to encrypt for user credentials.
--decrypt
Decrypt sensitive data that was previously encrypted with --encrypt. The encrypted data is read from standard input or from the specified FILE.... If a credential name is specified with --name=NAME, systemd-creds will look up the credential in the system's or user's credential store to obtain the decryption key. Use --user to decrypt for user credentials.

OPTIONS

The following options are available:

-h, --help
Show help text and exit.
-p, --user
Operate on user credentials instead of system credentials.
--name=NAME
Specify the name of the credential. This is required for --update, --delete, --export, --decrypt, and optional for --create and --encrypt.
--lifetime=TIME
Set the maximum lifetime for a credential. See systemd.time(7) for format.
--group=GROUP
Set the group owner of the credential file. Defaults to root for system credentials and the user's primary group for user credentials.
--owner=USER
Set the user owner of the credential file. Defaults to root for system credentials and the current user for user credentials.
--mode=OCTAL
Set the file permissions of the credential file in octal notation.
--output=FILE
Write the exported credential data to the specified FILE. If omitted, writes to standard output.
--format=FMT
Specify the format for export/import. Supported formats include json and key-value. Defaults to json.
--input=FILE
Read credential data to import from the specified FILE. If omitted, reads from standard input.
-t, --template=TEMPLATE
Use the provided TEMPLATE string as the data to encrypt. This is useful for encrypting specific values without needing to enter them interactively or pipe them.
-d, --directory=DIR
Use the specified DIR as the credential directory instead of the default (/etc/systemd/creds/ or ~/.config/systemd/creds/).
-p, --prompt
Prompt the user for the sensitive value using the system's password prompt mechanism. This is the default behavior when the value is not provided via standard input or --template.

EXIT STATUS

systemd-creds returns 0 on success, and a non-zero value on failure.

EXAMPLES

Create a system database password credential:

# systemd-creds --create --name=database-password
Password: [enter password here]

This will prompt for a password and store it encrypted under /etc/systemd/creds/database-password.

Create a user-specific API key:

$ systemd-creds --user --create --name=my-api-key
API Key: [enter API key here]

This stores the key encrypted in ~/.config/systemd/creds/my-api-key.

List all system credentials:

# systemd-creds --list

Delete a system credential:

# systemd-creds --delete --name=old-password

Encrypting a password and including it in a

unit file

The following command line prompts the user for a password and generates a SetCredentialEncrypted= line from it for a credential named "mysql-password", suitable for inclusion in a unit file.

# systemd-ask-password -n | systemd-creds encrypt --name=mysql-password -p - -

The generated line can be pasted 1:1 into a unit file, and will ensure the acquired password will be made available in the $CREDENTIALS_DIRECTORY/mysql-password credential file for the started service.

Utilizing the unit file drop-in logic this can be used to securely pass a password credential to a unit. A similar, more comprehensive set of commands to insert a password into a service xyz.service:

# mkdir -p /etc/systemd/system/xyz.service.d
# systemd-ask-password -n | ( echo "[Service]" && systemd-creds encrypt --name=mysql-password -p - - ) >/etc/systemd/system/xyz.service.d/50-password.conf
# systemctl daemon-reload
# systemctl restart xyz.service
