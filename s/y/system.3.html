system(3) Manual de funciones de la biblioteca system(3)

NOMBRE

system - ejecutar un comando de shell

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <stdlib.h>
int system(const char *comando);

DESCRIPCIÓN

La función de biblioteca system() se comporta como si utilizara fork(2) para crear un proceso hijo que ejecutara el comando de shell especificado en comando utilizando execl(3) de la siguiente manera:


execl("/bin/sh", "sh", "-c", command, (char *) NULL);

system() devuelve el control después de que el comando se haya completado.

Durante la ejecución del comando, SIGCHLD estará bloqueado y SIGINT y SIGQUIT serán ignorados, en el proceso que llama a system(). (Estas señales se manejarán de acuerdo con sus valores predeterminados dentro del proceso hijo que ejecuta comando).

Si comando es NULL, entonces system() devuelve un estado que indica si hay un shell disponible en el sistema.

VALOR DE RETORNO

El valor de retorno de system() es uno de los siguientes:

•
Si comando es NULL, entonces un valor distinto de cero si hay un shell disponible, o 0 si no hay un shell disponible.
•
Si no se pudo crear un proceso hijo, o no se pudo recuperar su estado, el valor de retorno es -1 y errno se establece para indicar el error.
•
Si no se pudo ejecutar un shell en el proceso hijo, entonces el valor de retorno es como si el shell hijo hubiera terminado llamando a _exit(2) con el estado 127.
•
Si todas las llamadas al sistema tienen éxito, entonces el valor de retorno es el estado de terminación del shell hijo utilizado para ejecutar comando. (El estado de terminación de un shell es el estado de terminación del último comando que ejecuta).

En los dos últimos casos, el valor de retorno es un estado de "espera" que se puede examinar utilizando las macros descritas en waitpid(2). (es decir, WIFEXITED(), WEXITSTATUS(), y así sucesivamente).

system() no afecta al estado de espera de ningún otro hijo.

ERRORES

system() puede fallar con cualquiera de los mismos errores que fork(2).

ATRIBUTOS

Para una explicación de los términos utilizados en esta sección, consulte attributes(7).

Interfaz Atributo Valor
system () Seguridad de hilos MT-Safe

ESTÁNDARES

C11, POSIX.1-2008.

HISTORIA

POSIX.1-2001, C89.

NOTAS

system() proporciona simplicidad y conveniencia: maneja todos los detalles de llamar a fork(2), execl(3) y waitpid(2), así como las manipulaciones necesarias de señales; además, el shell realiza las sustituciones e redireccionamientos de E/S habituales para comando. El principal coste de system() es la ineficiencia: se requieren llamadas al sistema adicionales para crear el proceso que ejecuta el shell y para ejecutar el shell.

Si se define el macro de prueba de características _XOPEN_SOURCE (antes de incluir cualquier archivo de cabecera), entonces las macros descritas en waitpid(2) (WEXITSTATUS(), etc.) se ponen a disposición al incluir <stdlib.h>.

Como se mencionó, system() ignora SIGINT y SIGQUIT. Esto puede hacer que los programas que lo llaman desde un bucle sean irrompibles, a menos que ellos mismos se cuiden de comprobar el estado de salida del hijo. Por ejemplo:


while (algo) {
    int ret = system("foo");
    if (WIFSIGNALED(ret) &&
        (WTERMSIG(ret) == SIGINT || WTERMSIG(ret) == SIGQUIT))
            break;
}

Según POSIX.1, no se especifica si los manejadores registrados usando pthread_atfork(3) se llaman durante la ejecución de system(). En la implementación de glibc, dichos manejadores no se llaman.

Antes de glibc 2.1.3, la comprobación de la disponibilidad de /bin/sh no se realizaba realmente si comando era NULL; en cambio, siempre se asumía que estaba disponible, y system() siempre devolvía 1 en este caso. Desde glibc 2.1.3, esta comprobación se realiza porque, aunque POSIX.1-2001 requiere que una implementación conforme proporcione un shell, es posible que ese shell no esté disponible o no sea ejecutable si el programa que llama ha llamado previamente a chroot(2) (que no está especificado por POSIX.1-2001).

Es posible que el comando del shell termine con un estado de 127, lo que genera un valor de retorno de system() indistinguible del caso en que no se pudo ejecutar un shell en el proceso hijo.

Advertencias

No utilice system() desde un programa privilegiado (un programa con ID de usuario o ID de grupo establecido, o un programa con capacidades) porque valores extraños para algunas variables de entorno podrían usarse para socavar la integridad del sistema. Por ejemplo, PATH podría manipularse para que se ejecute un programa arbitrario con privilegios. Utilice en su lugar la familia de funciones exec(3), pero no execlp(3) o execvp(3) (que también utilizan la variable de entorno PATH para buscar un ejecutable).

system() no funcionará correctamente desde programas con privilegios de ID de usuario o ID de grupo establecidos en sistemas en los que /bin/sh sea bash versión 2: como medida de seguridad, bash 2 elimina privilegios al iniciarse. (Debian utiliza un shell diferente, dash(1), que no hace esto cuando se invoca como sh).

Cualquier entrada del usuario que se emplee como parte de comando debe ser sanitizada *cuidadosamente*, para asegurar que no se ejecuten comandos o opciones de comando inesperados. Dichos riesgos son especialmente graves cuando se utiliza system() desde un programa privilegiado.

ERRORES COMUNES

Si el nombre del comando comienza con un guion, sh(1) interpreta el nombre del comando como una opción, y el comportamiento no está definido. (Consulte la opción -c de sh(1).) Para solucionar este problema, anteponga un espacio al comando como en la siguiente llamada:


    system(" -nombre-comando-desafortunado");

VER TAMBIÉN

sh(1), execve(2), fork(2), sigaction(2), sigprocmask(2), wait(2), exec(3), signal(7)

system(3)

NOMBRE

system - ejecutar un comando del shell

LIBRERÍA

Standard C library (libc, -lc)

SINOPSIS

#include <stdlib.h>

int system(const char *command);

DESCRIPCIÓN

La función system() ejecuta un comando pasándole una cadena de caracteres al shell del sistema. El comando se ejecuta en un subproceso creado mediante la llamada al sistema fork(2).

Si command es NULL, system() devuelve un valor distinto de cero si el shell está disponible, y cero en caso contrario. Esto se puede usar para comprobar si existe un shell.

Si command no es NULL, system() llama a /bin/sh para ejecutar el comando.

La llamada a system() es bloqueante hasta que el comando termina su ejecución.

Cuando el comando termina, system() devuelve el estado de salida del comando. Este estado de salida se codifica de la siguiente manera:

  • El byte de orden bajo del valor de retorno es el estado de salida del comando.
  • El byte de orden alto del valor de retorno es el número de señal que terminó el proceso.

En la práctica, los programas de usuario raramente necesitan saber si el comando terminó por una señal o por un estado de salida. En su lugar, normalmente usan las macros WEXITSTATUS(status), WTERMSIG(status) y WIFEXITED(status), WIFSIGNALED(status) definidas en <sys/wait.h> para analizar el valor de retorno.

Si system() no puede crear un subproceso, o si el subproceso no puede ejecutar el comando, system() devuelve -1 y errno se establece apropiadamente.

VALOR DE RETORNO

Si el comando se ejecutó correctamente, system() devuelve el estado de salida del comando, codificado como se describe arriba. Si se produjo un error (por ejemplo, no se pudo crear un subproceso o no se pudo ejecutar el comando), system() devuelve -1 y establece errno apropiadamente.

Si command es NULL, system() devuelve un valor distinto de cero si el shell está disponible, y cero en caso contrario.

ERRORES

ECHILD
No se pudo crear un subproceso. La llamada a fork(2) falló.
EINVAL
El valor de command era NULL y no se pudo encontrar el shell.
ENOENT
El shell (normalmente /bin/sh) no se pudo encontrar.
ENOMEM
No hay suficiente memoria para crear un subproceso.

ATRIBUTOS

Para obtener una explicación de los siguientes términos, consulte attributes(7).

InterfazAtributo
system()Thread safety levels: Async-signal safety (if command is NULL), Cancellation: Cancellation point, External interrupt: Cancellation point

ESTÁNDARES

C99, POSIX.1-2001, POSIX.1-2008.

HISTORIAL

C POSIX.1-2001.

NOTAS

La llamada a system() es un método conveniente para ejecutar un comando, pero tiene algunas limitaciones y riesgos de seguridad:

  • Seguridad: Si command contiene caracteres especiales de shell (como ;, &, |, >, <, $(), etc.), el shell puede interpretarlos de forma inesperada, lo que podría llevar a vulnerabilidades de seguridad. Si es posible, se recomienda usar la llamada al sistema execve(2) o funciones relacionadas para ejecutar programas directamente.

  • Bloqueo: system() es bloqueante. Mientras el comando se está ejecutando, el proceso que llamó a system() no puede hacer nada más.

  • Dependencia del shell: La ejecución de un comando a través de system() depende de la disponibilidad y el comportamiento del shell del sistema (normalmente /bin/sh). El comportamiento puede variar entre sistemas operativos y configuraciones.

  • Evasión de señales: La función system() ignora las señales SIGINT, SIGQUIT y SIGTSTP. El comando ejecutado por system() las recibe, pero no las maneja explícitamente. Si el comando se interrumpe por una señal, system() devuelve un valor que indica la señal.

Para un control más fino sobre la ejecución de comandos, considere usar fork(2) seguido de execve(2) o la familia de funciones posix_spawn().

ERRORES

Actualmente no se conocen errores.

execve(2), fork(2), wait(2), popen(3), sh(1), system.c (archivo de origen de glibc, que contiene más información sobre la implementación)
