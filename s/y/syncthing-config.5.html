NOMBRE

syncthing-config - Configuración de Syncthing

DESCRIPCIÓN GENERAL

Esta página cubre cómo configurar Syncthing para la sincronización de archivos, incluyendo la configuración de dispositivos, configuración de carpetas, ajustes de conexión y varios métodos de configuración a través de la GUI web, línea de comandos o edición directa de archivos.

UBICACIONES DEL ARCHIVO DE CONFIGURACIÓN

Las ubicaciones predeterminadas del directorio de configuración y base de datos son:

$XDG_STATE_HOME/syncthing
$HOME/.local/state/syncthing
$HOME/Library/Application Support/Syncthing
%LOCALAPPDATA%\Syncthing

DESCRIPCIÓN

Cambiado en la versión 1.27.0: La ubicación predeterminada del directorio de configuración y base de datos en sistemas tipo Unix cambió a $XDG_STATE_HOME/syncthing o $HOME/.local/state/syncthing. Anteriormente, la ubicación de configuración predeterminada era $XDG_CONFIG_HOME/syncthing o $HOME/.config/syncthing. El directorio de la base de datos era anteriormente $HOME/.config/syncthing o, si la variable de entorno estaba configurada, $XDG_DATA_HOME/syncthing. Las instalaciones existentes aún pueden usar estos directorios en lugar de los valores predeterminados más nuevos.

Añadido en la versión 1.5.0: Ahora la base de datos y la configuración se pueden establecer por separado. Anteriormente, la base de datos siempre se encontraba en el mismo directorio que la configuración.

Syncthing utiliza un único directorio para almacenar la configuración y las claves criptográficas. Syncthing también mantiene una base de datos de índice con metadatos de archivos que, por defecto, se almacena en el mismo directorio, aunque esto se puede sobrescribir.

La ubicación predeterminada es $XDG_STATE_HOME/syncthing o $HOME/.local/state/syncthing (tipo Unix), $HOME/Library/Application Support/Syncthing (Mac), o %LOCALAPPDATA%\Syncthing (Windows). Se puede cambiar en tiempo de ejecución utilizando las opciones --config o --home o las variables de entorno correspondientes ($STCONFDIR o STHOMEDIR). Los siguientes archivos se encuentran en este directorio:

config.xml
El archivo de configuración, en formato XML.
cert.pem, key.pem
La clave pública y privada ECDSA del dispositivo. Estas forman la base de la ID del dispositivo. La clave debe mantenerse privada.
https-cert.pem, https-key.pem
El certificado y la clave para las conexiones HTTPS de la GUI. Estos pueden ser reemplazados por un certificado personalizado para HTTPS según se desee.

La base de datos se almacena por defecto en el mismo directorio que la configuración, pero la ubicación puede ser sobrescrita por las opciones --data o --home o las variables de entorno correspondientes ($STDATADIR o STHOMEDIR).

El directorio de la base de datos contiene los siguientes archivos, entre otros:

index-*
La base de datos con metadatos y hashes de los archivos actualmente en disco y disponibles de los pares.
syncthing.log
Salida del registro, en algunos sistemas.
audit-*.log
Datos del registro de auditoría, cuando está habilitado.
panic-*.log
Datos del registro de fallos, cuando es necesario.

Se deben presentar uno o más elementos folder en el archivo. Cada elemento describe una carpeta. Se pueden establecer los siguientes atributos en el elemento folder:

id (obligatorio)
El ID de la carpeta, que debe ser único.
label
La etiqueta de una carpeta es un nombre local descriptivo y legible por humanos. Puede ser diferente en cada dispositivo, vacío y/o idéntico a otras etiquetas de carpeta. (opcional)
filesystemType
La implementación interna del sistema de archivos utilizada para acceder a esta carpeta, detallada en un capítulo aparte.
path (obligatorio)
La ruta al directorio donde se almacena la carpeta en este dispositivo; no se envía a otros dispositivos.
type
Controla cómo Syncthing maneja la carpeta. Los valores posibles son:
sendreceive
La carpeta está en modo predeterminado. Envía cambios locales y acepta cambios remotos. Tenga en cuenta que este tipo se llamaba anteriormente "readwrite", que está obsoleto pero todavía se acepta en configuraciones entrantes.
sendonly
La carpeta está en modo "solo envío": Syncthing no la modificará en este dispositivo. Tenga en cuenta que este tipo se llamaba anteriormente "readonly", que está obsoleto pero todavía se acepta en configuraciones entrantes.
receiveonly
La carpeta está en modo "solo recepción": no propagará cambios a otros dispositivos.
receiveencrypted
Debe usarse en dispositivos no confiables, donde los datos no se pueden descifrar porque no se ingresó ninguna contraseña de carpeta. Ver Dispositivos no confiables (cifrados).
rescanIntervalS
El intervalo de escaneo, en segundos. Se puede establecer en 0 para deshabilitarlo cuando se utilizan plugins externos para activar escaneos.
fsWatcherEnabled
Si se establece en true, esto detecta cambios en los archivos de la carpeta y los escanea.
fsWatcherDelayS
La duración durante la cual se acumulan los cambios detectados, antes de programar un escaneo (solo tiene efecto si fsWatcherEnabled está establecido en true).
fsWatcherTimeoutS
El retraso máximo antes de que se active un escaneo cuando un archivo cambia continuamente. Si no se establece o es cero, se calcula un valor predeterminado basado en fsWatcherDelayS.
ignorePerms
Si es true, los archivos originarios de esta carpeta se anunciarán a los dispositivos remotos con la bandera "sin bits de permisos". Los dispositivos remotos usarán la configuración de permisos predeterminada que tengan al crear los archivos. El caso de uso principal es para sistemas de archivos que no admiten permisos, como FAT, o entornos donde cambiar los permisos es imposible.
autoNormalize
Corrige automáticamente los errores de normalización UTF-8 encontrados en los nombres de archivo. El mecanismo y cómo configurarlo se describe en un capítulo aparte.

Los siguientes elementos hijos pueden existir:

device
Estos deben tener el atributo id y pueden tener un atributo introducedBy, que identifica el dispositivo que nos introdujo para compartir esta carpeta con el dispositivo dado. Si el introductor original deja de compartir esta carpeta con este dispositivo, nuestro dispositivo seguirá y dejará de compartir la carpeta (sujeto a que skipIntroductionRemovals sea false en el dispositivo introductor).

Todos los dispositivos mencionados son aquellos que compartirán la carpeta en cuestión. Cada dispositivo mencionado debe tener un elemento device separado más adelante en el archivo. Es costumbre que el ID del dispositivo local se incluya en todas las carpetas. Syncthing lo agregará automáticamente si no está presente en el archivo de configuración.

El subelemento encryptionPassword contiene el secreto necesario para descifrar los datos de esta carpeta en el dispositivo remoto. Si se deja vacío, los datos son de acceso libre (pero aún protegidos por el cifrado de transporte). El mecanismo y cómo configurarlo se describe en un capítulo aparte.

minDiskFree
El espacio libre mínimo requerido que debe estar disponible en el disco donde reside esta carpeta. La carpeta se detendrá cuando el valor caiga por debajo del umbral. El contenido del elemento se interpreta según el atributo unit dado. Los valores de unit aceptados son % (porcentaje del tamaño del disco/volumen), kB, MB, GB y TB. Establecer a cero para deshabilitar.
versioning
Especifica una configuración de versionado.

VER TAMBIÉN:

Versionado de archivos
copiers
hashers
El número de rutinas de copia y hash a utilizar, o 0 para las óptimas determinadas por el sistema. Estas son opciones de rendimiento de bajo nivel solo para usuarios avanzados; no las cambie a menos que se le haya solicitado o haya leído y entendido el código usted mismo. :)
pullerMaxPendingKiB
Controla cuándo dejamos de enviar solicitudes a otros dispositivos una vez que tenemos esta cantidad de solicitudes no atendidas. El número de pullers se ajusta automáticamente en función de esta cantidad deseada de datos de solicitudes pendientes.
order
El orden en que se deben descargar los archivos necesarios del clúster. No tiene ningún efecto cuando el tipo de carpeta es "solo envío". Los valores posibles son:
random (predeterminado)
Descarga archivos en orden aleatorio. Esto optimiza el equilibrio de recursos entre los dispositivos de un clúster.
alphabetic
Descarga archivos ordenados por nombre de archivo alfabéticamente.
smallestFirst, largestFirst
Descarga archivos ordenados por tamaño de archivo; primero los más pequeños y luego los más grandes respectivamente.
oldestFirst, newestFirst
Descarga archivos ordenados por fecha de modificación; primero los más antiguos y luego los más recientes respectivamente.

Tenga en cuenta que los archivos escaneados se envían en lotes y la ordenación solo se aplica a los archivos ya descubiertos. Esto significa que la sincronización podría comenzar con un archivo de 1 GB, incluso si hay un archivo de 1 KB disponible en el dispositivo de origen, hasta que el dispositivo que descarga conozca el de 1 KB.

ignoreDelete
ADVERTENCIA:
Se desaconseja encarecidamente habilitar esto; úselo bajo su propio riesgo. Ha sido advertido.

Cuando se establece en true, este dispositivo fingirá no ver las instrucciones para eliminar archivos de otros dispositivos. El mecanismo se describe en un capítulo aparte.

scanProgressIntervalS
El intervalo en segundos con el que se envía la información de progreso del escaneo a la GUI. Establecer en 0 hará que Syncthing use el valor predeterminado de dos. Si no necesita ver el progreso del escaneo, establézcalo en -1 para deshabilitarlo.
pullerPauseS
Ajuste para limitar la velocidad del puller cuando reintenta descargar archivos. No cambie esto a menos que sepa lo que está haciendo.
maxConflicts
El número máximo de copias de conflicto que se conservarán para cualquier archivo dado. El valor predeterminado es 10. -1 significa un número ilimitado. Establecer en 0 deshabilita las copias de conflicto por completo.
disableSparseFiles
Por defecto, los bloques que contienen todos ceros no se escriben, lo que hace que los archivos sean dispersos en los sistemas de archivos que admiten esta función. Cuando se establece en true, no se crearán archivos dispersos.
paused
Verdadero si esta carpeta está (temporalmente) suspendida.
markerName
Nombre de un directorio o archivo en la raíz de la carpeta que se utilizará como marcador; consulte las preguntas frecuentes sobre marcadores para conocer su propósito. Syncthing solo crea un directorio marcador para el valor predeterminado .stfolder, no de otra manera.
copyOwnershipFromParent
En sistemas Unix, intenta copiar la propiedad del archivo/carpeta del directorio padre (el directorio en el que se encuentra). Requiere ejecutar Syncthing como un usuario privilegiado o otorgarle capacidades adicionales (por ejemplo, CAP_CHOWN en Linux).
modTimeWindowS
Diferencia permitida en la marca de tiempo de modificación al comparar archivos para determinar su equivalencia. Para usarse en sistemas de archivos que tienen marcas de tiempo de modificación inestables que pueden cambiar después de ser registradas durante la última operación de escritura. El valor predeterminado es 2 en Android cuando la carpeta se encuentra en una partición FAT, y 0 en caso contrario.
maxConcurrentWrites
Número máximo de operaciones de escritura concurrentes durante la sincronización. Aumentar esto puede mejorar o disminuir el rendimiento del disco, dependiendo del almacenamiento subyacente. El valor predeterminado es 16.
disableFsync
ADVERTENCIA:
Esta es una opción insegura conocida; úsela bajo su propio riesgo.

Deshabilita la confirmación de las operaciones de archivo en el disco antes de registrarlas en la base de datos. Deshabilitar fsync puede provocar la corrupción de datos. El mecanismo se describe en un capítulo aparte.

blockPullOrder
Orden en el que se descargan los bloques de un archivo. Esta opción controla la rapidez con la que diferentes partes del archivo se distribuyen entre los dispositivos conectados, a costa de ejercer presión sobre el almacenamiento.

Opciones disponibles:

standard (predeterminado)
Los bloques de un archivo se dividen en N secuencias continuas iguales, donde N es el número de dispositivos conectados. Cada dispositivo comienza a descargar su propia secuencia, después de lo cual elige secuencias de otros dispositivos al azar. Proporciona una distribución de datos aceptable y una mínima presión sobre los discos duros giratorios.
random
Los bloques de un archivo se descargan en orden aleatorio. Proporciona una gran distribución de datos, pero es muy exigente para los discos duros giratorios.
inOrder
Los bloques de un archivo se descargan secuencialmente, de principio a fin. Amigable con los discos duros giratorios, pero no proporciona mejoras en la distribución de datos.
copyRangeMethod
Proporciona una opción de método para copiar datos entre archivos. Esto se puede utilizar para optimizar copias en sistemas de archivos de red, mejorar la velocidad de copias grandes o clonar datos utilizando la funcionalidad de copia en escritura si el
el sistema de archivos subyacente lo admite. El mecanismo se describe en un capítulo separado.
caseSensitiveFS
Afecta el rendimiento al deshabilitar las comprobaciones de seguridad adicionales para sistemas de archivos que no distinguen entre mayúsculas y minúsculas. El mecanismo y cómo configurarlo se describe en un capítulo separado.
junctionsAsDirs
Las uniones de directorios NTFS se tratan como directorios ordinarios, si esto está establecido en true.
syncOwnership
La propiedad de archivos y directorios se sincroniza cuando esto está establecido en true. Consulte syncOwnership para obtener más información.
sendOwnership
La información de propiedad de archivos y directorios se escanea cuando esto está establecido en true. Consulte sendOwnership para obtener más información.
syncXattrs
Los atributos extendidos de archivos y directorios se sincronizan cuando esto está establecido en true. Consulte syncXattrs para obtener más información.
sendXattrs
Los atributos extendidos de archivos y directorios se escanean y envían a otros dispositivos cuando esto está establecido en true. Consulte sendXattrs para obtener más información.

Uno o más elementos device deben estar presentes en el archivo. Cada elemento describe un dispositivo que participa en el clúster. Es habitual incluir un elemento device para el dispositivo local; Syncthing añadirá uno actualmente si no está presente. Los siguientes atributos se pueden establecer en el elemento device:

id (obligatorio)
El ID del dispositivo.
name
Un nombre amigable para el dispositivo. (opcional)
compression
Si se debe usar compresión de protocolo al enviar mensajes a este dispositivo. Los valores posibles son:
metadata
Comprime paquetes de metadatos, como información de índice. Los metadatos suelen ser muy amigables para la compresión, por lo que este es un buen valor predeterminado.
always
Comprime todos los paquetes, incluidos los datos de archivos. Se recomienda si el contenido de las carpetas son principalmente datos comprimibles como documentos o archivos de texto.
never
Deshabilita toda la compresión.
introducer
Se establece en true si este dispositivo debe ser considerado un introductor, es decir, debemos copiar su lista de dispositivos por carpeta al conectarnos.

VER TAMBIÉN:

Configuración de Introductor
skipIntroductionRemovals
Se establece en true si desea seguir solo las introducciones y no las desintroducciones. Por ejemplo, si esto está configurado, no eliminaríamos un dispositivo al que se nos presentó, incluso si el introductor original ya no enumera el dispositivo remoto como conocido.
introducedBy
Define qué dispositivo nos presentó a este dispositivo. Se utiliza solo para seguir las desintroducciones.
certName
El nombre común del certificado del dispositivo, si no es el valor predeterminado “syncthing”.

De los siguientes elementos hijos, al menos un hijo address debe existir.

address (obligatorio: Debe haber al menos uno.)
Contiene una dirección o nombre de host a utilizar al intentar conectarse a este dispositivo. Las entradas que no sean dynamic necesitan un prefijo específico del protocolo. Para el protocolo TCP, se pueden usar los prefijos tcp:// (doble pila), tcp4:// (solo IPv4) o tcp6:// (solo IPv6). Los prefijos para el protocolo QUIC son análogos: quic://, quic4:// y quic6:// Tenga en cuenta que las direcciones IP no necesitan usar prefijos IPv4 o IPv6; estos son opcionales. Los formatos aceptados son:
dirección IPv4 (tcp://192.0.2.42)
Se utiliza el puerto predeterminado (22000).
dirección IPv4 y puerto (tcp://192.0.2.42:12345)
Se utiliza la dirección y el puerto tal como se proporcionan.
dirección IPv6 (tcp://[2001:db8::23:42])
Se utiliza el puerto predeterminado (22000). La dirección debe estar entre corchetes.
dirección IPv6 y puerto (tcp://[2001:db8::23:42]:12345)
Se utiliza la dirección y el puerto tal como se proporcionan. La dirección debe estar entre corchetes.

Nombre de host y puerto (tcp://fileserver:12345)
Se utilizará el nombre de host en el puerto proporcionado y las conexiones se intentarán a través de IPv4 e IPv6, dependiendo de la resolución del nombre.

La palabra dynamic (sin ningún prefijo) significa usar descubrimiento local y global para encontrar el dispositivo.

Comodín TCP y puerto (tcp://0.0.0.0:22000, tcp://:22000)
Estos son equivalentes y resultarán en que Syncthing escuche en todas las interfaces, IPv4 e IPv6, en el puerto especificado.
Comodín TCP IPv4 y puerto (tcp4://0.0.0.0:22000, tcp4://:22000)
Estos son equivalentes y resultarán en que Syncthing escuche en todas las interfaces solo a través de IPv4.
Dirección y puerto TCP IPv4 (tcp4://192.0.2.1:22000)
Esto resulta en que Syncthing escuche en la dirección y puerto especificados, solo IPv4.
Comodín TCP IPv6 y puerto (tcp6://[::]:22000, tcp6://:22000)
Estos son equivalentes y resultarán en que Syncthing escuche en todas las interfaces solo a través de IPv6.
Dirección y puerto TCP IPv6 (tcp6://[2001:db8::42]:22000)
Esto resulta en que Syncthing escuche en la dirección y puerto especificados, solo IPv6.
Dirección y puerto QUIC (ej. quic://0.0.0.0:22000)
La sintaxis es la misma que para TCP, también se pueden usar quic4 y quic6.
Dirección de relé estática (relay://192.0.2.42:22067?id=abcd123...)
Syncthing se conectará y escuchará conexiones entrantes a través de la dirección de relé especificada.

SINCRONIZACIÓN DE ARCHIVOS DE CONFIGURACIÓN

Sincronizar archivos de configuración entre dispositivos (de modo que múltiples dispositivos utilicen los mismos archivos de configuración) puede causar problemas. Esto es fácil de hacer accidentalmente si sincroniza su carpeta personal entre dispositivos. Un síntoma común de la sincronización de archivos de configuración es que dos dispositivos terminen con el mismo ID de Dispositivo.

Si desea utilizar Syncthing para hacer una copia de seguridad de sus archivos de configuración, se recomienda que los archivos que está respaldando estén en una Carpeta Solo Envío para evitar que otros dispositivos sobrescriban la configuración específica del dispositivo. La carpeta en el(los) dispositivo(s) remoto(s) no debe utilizarse como configuración para los dispositivos remotos.

Si desea sincronizar su carpeta personal en modo no solo de envío, puede agregar la carpeta que almacena los archivos de configuración a la lista de exclusión. Si también desea hacer una copia de seguridad de sus archivos de configuración, agregue otra carpeta en modo solo de envío solo para la carpeta de configuración.
