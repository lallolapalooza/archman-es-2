SYSTEMD-JOURNAL-GATEWAYD.SERVICE(8) systemd-journal-gatewayd.service SYSTEMD-JOURNAL-GATEWAYD.SERVICE(8)

NOMBRE

systemd-journal-gatewayd.service, systemd-journal-gatewayd.socket, systemd-journal-gatewayd - Servidor HTTP para eventos del journal

SINOPSIS

systemd-journal-gatewayd.service

systemd-journal-gatewayd.socket

/usr/lib/systemd/systemd-journal-gatewayd [OPCIONES...]

DESCRIPCIÓN

systemd-journal-gatewayd sirve eventos del journal a través de la red. Los clientes deben conectarse usando HTTP. El servidor escucha en el puerto 19531 por defecto. Si se especifica --cert=, el servidor espera conexiones HTTPS.

El programa es iniciado por systemd(1) y espera recibir un único socket. Utilice systemctl start systemd-journal-gatewayd.socket para iniciar el servicio, y systemctl enable systemd-journal-gatewayd.socket para que se inicie al arrancar.

OPCIONES

Se entienden las siguientes opciones:

--cert=

Especifica la ruta a un archivo o socket de flujo AF_UNIX desde el que leer el certificado del servidor. El certificado debe estar en formato PEM. Esta opción cambia systemd-journal-gatewayd al modo HTTPS y debe usarse junto con --key=.

Añadido en la versión 198.

--key=

Especifica la ruta a un archivo o socket de flujo AF_UNIX desde el que leer la clave secreta del servidor correspondiente al certificado especificado con --cert=. La clave debe estar en formato PEM.

Añadido en la versión 198.

--trust=

Especifica la ruta a un archivo o socket de flujo AF_UNIX desde el que leer un certificado CA. El certificado debe estar en formato PEM.

Añadido en la versión 236.

--system, --user

Limita las entradas servidas a las entradas de servicios del sistema y del kernel, o a las entradas de los servicios del usuario actual. Esto tiene el mismo significado que las opciones --system y --user para journalctl(1). Si no se especifica ninguna, se sirven todas las entradas accesibles.

Añadido en la versión 249.

-m, --merge

Sirve entradas intercaladas de todos los journals disponibles, incluidas las de otras máquinas. Esto tiene el mismo significado que la opción --merge de journalctl(1).

Añadido en la versión 249.

-D DIR, --directory=DIR

Toma una ruta de directorio como argumento. Si se especifica, systemd-journal-gatewayd servirá el directorio de journal especificado DIR en lugar de las rutas predeterminadas del journal en tiempo de ejecución y del sistema.

Añadido en la versión 232.

--file=GLOB

Toma un comodín de archivo como argumento. Sirve entradas de los archivos de journal especificados que coincidan con GLOB en lugar de las rutas predeterminadas del journal en tiempo de ejecución y del sistema. Puede especificarse varias veces, en cuyo caso los archivos se intercalarán adecuadamente. Esto tiene el mismo significado que la opción --file= de journalctl(1).

Añadido en la versión 249.

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.

URLS SOPORTADAS

Se reconocen las siguientes URLs:

/boots

Devuelve una respuesta json-seq (RFC 7464) que contiene objetos JSON, cada uno de ellos con el número de arranque, su ID y las marcas de tiempo del primer y último mensaje. Los arranques se devuelven empezando por el más reciente y utilizan el mismo esquema que journalctl --list-boots --output json.

Añadido en la versión 258.

/browse

Navegación interactiva.

Añadido en la versión 197.

/entries[?opcion1&opcion2=valor...]

Recuperación de eventos en varios formatos.

La parte Accept: de la cabecera HTTP determina el formato. Los valores compatibles se describen a continuación.

La parte Range: de la cabecera HTTP determina el rango de eventos devueltos. Los valores compatibles se describen a continuación.

Los parámetros GET se pueden utilizar para modificar qué eventos se devuelven. Los parámetros compatibles se describen a continuación.

Añadido en la versión 197.

/machine

Devuelve una estructura JSON que describe la máquina.

Ejemplo:

{ "machine_id" : "8cf7ed9d451ea194b77a9f118f3dc446",
  "boot_id" : "3d3c9efaf556496a9b04259ee35df7f7",
  "hostname" : "fedora",
  "os_pretty_name" : "Fedora 19 (Rawhide)",
  "virtualization" : "kvm",
  ...}

Añadido en la versión 197.

/fields/NOMBRE_CAMPO

Devuelve una lista de valores de este campo presentes en los logs.

Añadido en la versión 197.

CABECERA ACCEPT

Accept: formato

Formatos reconocidos:

text/plain

El predeterminado. Salida de texto similar a syslog, una línea por entrada del journal (como journalctl --output short).

Añadido en la versión 197.

application/json

Las entradas se formatean como estructuras de datos JSON, una por línea (como journalctl --output json). Consulte Formato JSON del Journal[1] para más información.

Añadido en la versión 197.

text/event-stream

Las entradas se formatean como estructuras de datos JSON, envueltas en un formato adecuado para Server-Sent Events[2] (como journalctl --output json-sse).

Añadido en la versión 229.

application/vnd.fdo.journal

Las entradas se serializan en un flujo binario (pero mayormente basado en texto) adecuado para copias de seguridad y transferencia de red (como journalctl --output export). Consulte Formato de Exportación del Journal[3] para más información.

Añadido en la versión 197.

CABECERA RANGE

Range: entries=[cursor][[:num_skip]:[num_entries]]

Range: realtime=[since]:[until][[:num_skip]:num_entries]

donde cursor es una cadena de cursor, por defecto la primera entrada, since y until son marcas de tiempo (segundos desde 1970-01-01 00:00:00 UTC), num_skip es un entero, num_entries es un entero sin signo.

El rango por defecto son todos los eventos disponibles.

Si num_skip es negativo y no se proporciona cursor, la última entrada será el punto de referencia.

PARÁMETROS GET DE URL

Los siguientes parámetros se pueden utilizar como parte de la URL:

follow

esperar nuevos eventos (como journalctl --follow, el número de eventos devueltos no está limitado, a menos que se especifique num_entries en la cabecera Range).

Añadido en la versión 197.

discrete

Comprueba que el cursor especificado se refiere a una entrada en el journal. Devuelve solo esta entrada.

Añadido en la versión 197.

boot

Limita los eventos al arranque actual del sistema (como journalctl -b).

Añadido en la versión 197.

CLAVE=coincidencia

Coincide con los campos del journal. Consulte systemd.journal-fields(7).

Añadido en la versión 197.

EJEMPLOS

Recuperar eventos de este arranque del journal local en el Formato de Exportación del Journal[3]:

curl --silent -H'Accept: application/vnd.fdo.journal' \
       'http://localhost:19531/entries?boot'

Escuchar volcados de memoria (core dumps):

curl 'http://localhost:19531/entries?follow&MESSAGE_ID=fc2e22bc6ee647b6b90

See also journalctl(1), systemd.journal-fields(7), systemd.unit(8), systemd.service(8), systemd.socket(8).

systemd-journal-gatewayd.8.en

NAME

systemd-journal-gatewayd.service, systemd-journal-gatewayd - systemd journal gateway service

SYNOPSIS

systemd-journal-gatewayd.service

systemd-journal-gatewayd [OPTIONS...]

DESCRIPTION

systemd-journal-gatewayd is a systemd service that exposes the system journal over the network. It listens for journal export requests, fetches the appropriate log messages from the local journal, and sends them back to the client. It supports various export formats and protocols.

This service is typically used to provide remote access to system logs for monitoring or debugging purposes.

OPTIONS

--user
Run in user mode. This is intended for user service units.
--journal=path
Use the specified journal file or directory instead of the default.
--listen-address=address
Listen on the specified network address. Can be specified multiple times.
--port=port
Listen on the specified TCP port. Defaults to 19531.
--bind-address=address
Bind to the specified local address for outgoing connections. Defaults to the address of the first non-loopback interface.
--num-threads=n
Set the number of worker threads. Defaults to 12.
--http-port=port
Listen on the specified HTTP port for HTTP requests. Defaults to 19532.
--http-root=path
Set the HTTP root directory for serving static files.

SUPPORTED URLS

The gateway supports the following URL paths:

/journal/export
Exports the journal in the journal export format. See systemd.io.
/journal/json
Exports the journal in JSON format. See systemd.io.
/journal/sse
Exports the journal using Server-Sent Events (SSE). See MDN.

ACCEPT HEADER

The gateway understands the `Accept:` header to determine the desired output format. Supported media types are:

application/vnd.fdo.journal-export
Journal export format.
application/json
JSON format.
text/event-stream
Server-Sent Events.

If no `Accept:` header is provided, the gateway defaults to the journal export format.

RANGE HEADER

The gateway supports the `Range:` header for fetching specific parts of the journal. The header value should be in the format `items=start-end` or `bytes=start-end`.

URL GET PARAMETERS

The following GET parameters can be used to filter and control the journal export:

since=, until=
Filter entries by time.
boot=
Filter entries by boot ID.
unit=
Filter entries by unit name.
priority=
Filter entries by priority.
cursor=
Start reading from a specific cursor.
follow=true
Keep the connection open and stream new entries as they arrive (for SSE).

EXAMPLES

Fetch the last 100 log entries in JSON format:

$ curl -H "Accept: application/json" http://localhost:19532/journal/json?limit=100

Stream new log entries using Server-Sent Events:

$ curl http://localhost:19532/journal/sse?follow=true

Fetch log entries from a specific boot ID in journal export format:

$ curl http://localhost:19532/journal/export?boot=some-boot-id

Fetch entries starting from a specific cursor:

$ curl http://localhost:19532/journal/export?cursor=s=...

Using the native protocol on the default port:

$ journalctl --remote=localhost:19531

Using the native protocol with specific options:

$ journalctl --remote=localhost:19531 --since "2023-10-27 10:00:00" --until "2023-10-27 11:00:00"

Configure systemd-journal-gatewayd to listen on multiple addresses:

ListenStream=19531
ListenStream=192.168.1.100:19531

Configure systemd-journal-gatewayd to use a specific journal file:

ExecStart=/usr/lib/systemd/systemd-journal-gatewayd --journal=/var/log/journal/remote/remote-123.journal

Configure systemd-journal-gatewayd to use multiple threads:

ExecStart=/usr/lib/systemd/systemd-journal-gatewayd --num-threads=20

Disable the HTTP interface:

ExecStart=/usr/lib/systemd/systemd-journal-gatewayd --no-http

Start the gateway in user mode:

$ systemd-journal-gatewayd --user

Access the journal through a remote gateway:

$ journalctl --remote=gateway.example.com

Access the journal through a remote gateway using HTTP:

$ curl http://gateway.example.com:19532/journal/json

Access the journal through a remote gateway using the native protocol and specifying the remote address explicitly:

$ journalctl --remote=192.0.2.100:19531

Fetch entries from a remote gateway and filter by unit:

$ curl http://gateway.example.com:19532/journal/json?unit=sshd.service

Fetch entries from a remote gateway using HTTP Range header:

$ curl -H "Range: items=100-199" http://gateway.example.com:19532/journal/json

Fetch entries from a remote gateway using native Range header:

$ journalctl --remote=gateway.example.com --lines=100 --skip-lines=100

The following string is the journal cursor for the current state of the journal: 729ab34a250b1'
