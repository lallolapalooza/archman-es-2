syncthing - Syncthing

DESCRIPCIÓN

Syncthing te permite sincronizar tus archivos bidireccionalmente entre múltiples dispositivos. Esto significa que la creación, modificación o eliminación de archivos en una máquina se replicará automáticamente en tus otros dispositivos. Creemos que tus datos son solo tuyos y mereces elegir dónde se almacenan. Por lo tanto, Syncthing no carga tus datos a la nube, sino que los intercambia entre tus máquinas tan pronto como están en línea al mismo tiempo.

La aplicación principal syncthing es un programa de línea de comandos que normalmente se ejecuta en segundo plano y maneja la sincronización. Proporciona una interfaz de usuario integrada basada en HTML y JavaScript para ser controlada desde un navegador web. Este frontend comunica con la aplicación principal a través de algunas APIs HTTP, que otras aplicaciones como ayudantes de integración gráfica del sistema también pueden utilizar, para mayor flexibilidad. Un enlace para acceder a la GUI y a la API se imprime entre los primeros mensajes de registro.

OPCIONES COMUNES

--home=<dir>, -H <dir> ($STHOMEDIR)
Establece el directorio común de configuración y datos. El directorio de configuración predeterminado es $XDG_STATE_HOME/syncthing o $HOME/.local/state/syncthing (en sistemas tipo Unix), $HOME/Library/Application Support/Syncthing (Mac) y %LOCALAPPDATA%\Syncthing (Windows).
--config=<dir>, -C <dir> ($STCONFDIR)
Establece el directorio de configuración. Alternativa a --home y debe usarse junto con --data.
--data=<dir>, -D <dir> ($STDATADIR)
Establece el directorio de datos (por ejemplo, la base de datos). Alternativa a --home y debe usarse junto con --config.
--help, -h
Muestra el texto de ayuda sobre el uso de la línea de comandos. Sensible al contexto dependiendo del subcomando proporcionado.

OPCIONES DE SERVE

--allow-newer-config ($STALLOWNEWERCONFIG)
Intenta cargar un archivo de configuración escrito por una versión más nueva del programa, en lugar de fallar inmediatamente.
--audit ($STAUDIT)
Escribe eventos en el archivo con marca de tiempo audit-YYYYMMDD-HHMMSS.log.
--auditfile=<file|-|--> ($STAUDITFILE)
Utiliza el archivo o flujo especificado ("-" para stdout, "--" para stderr) para los eventos de auditoría, en lugar del nombre de archivo predeterminado con marca de tiempo.
--db-maintenance-interval=<interval> ($STDBMAINTENANCEINTERVAL)
Intervalo de mantenimiento de la base de datos - las rutinas de mantenimiento internas de la base de datos se ejecutan con esta frecuencia. El formato es el de una cadena de duración de Go (ver https://pkg.go.dev/time#ParseDuration).
--db-delete-retention-interval=<interval> ($STDBDELETERETENTIONINTERVAL)
Intervalo de retención de elementos eliminados en la base de datos - los elementos eliminados se olvidan de la base de datos después de este intervalo. El formato es el de una cadena de duración de Go (ver https://pkg.go.dev/time#ParseDuration).
--gui-address=<address> ($STGUIADDRESS)
Anula la dirección de escucha de la GUI. Establécela en una dirección (0.0.0.0:8384) o una URL (http://0.0.0.0:8384). Los esquemas admitidos son http para HTTP plano, https para HTTP sobre TLS, unix para sockets Unix planos o unixs para TLS sobre sockets Unix. Un socket Unix podría verse así: unix:///run/syncthing/syncthing.socket (nota las tres barras: dos como parte de la estructura URL, una para especificar una ruta absoluta).
--gui-apikey=<string> ($STGUIAPIKEY)
Anula la clave API necesaria para acceder a la GUI / API REST.
--log-file=<filename> ($STLOGFILE)
Establece el nombre del archivo de destino para el registro (usa "-" para stdout, que es la opción predeterminada).
--log-level=<level> ($STLOGLEVEL)
Establece el nivel de registro para todos los paquetes. Los niveles válidos son DEBUG, INFO, WARN y ERROR.
--log-max-old-files=<num> ($STLOGMAXOLDFILES)
Número de archivos antiguos a mantener (cero para mantener solo el actual). Se aplica solo cuando la rotación de registros está habilitada a través de --log-max-size.
--log-max-size=<num> ($STLOGMAXSIZE)
Tamaño máximo en bytes de cualquier archivo de registro (cero para deshabilitar la rotación de registros).
--log-format-timestamp=<format> ($STLOGFORMATTIMESTAMP)
Formato para la marca de tiempo, establecido a vacío para deshabilitar las marcas de tiempo. El formato es el del formateador de tiempo de Go (ver https://pkg.go.dev/time#Layout).
--[no-]log-format-level-string ($STLOGFORMATLEVELSTRING
(--log-format-level)
Si incluir la cadena de nivel (p. ej. "INF") en la línea de registro.
--[no-]log-format-level-syslog ($STLOGFORMATLEVELSYSLOG)
Si incluir el nivel como prefijo syslog (p. ej. "<6>") en la línea de registro.
--no-browser ($STNOBROWSER)
No iniciar un navegador.
--no-console ($STNOCONSOLE)
Ocultar la ventana de la consola. (Solo en Windows)
--no-port-probing ($STNOPORTPROBING)
No intentar encontrar puertos aleatorios no utilizados para la GUI y la dirección de escucha al generar una configuración inicial / al iniciar por primera vez.
--no-restart ($STNORESTART)
No reiniciar Syncthing cuando se cierre. El proceso monitor seguirá ejecutándose para manejar fallos y escribir en archivos de registro (si está configurado).
--no-upgrade ($STNOUPGRADE)
Deshabilitar las actualizaciones automáticas.
--paused ($STPAUSED)
Iniciar con todos los dispositivos y carpetas en pausa.
--unpaused ($STUNPAUSED)
Iniciar con todos los dispositivos y carpetas sin pausa.
--version
Mostrar la información de la versión actual y salir.
--debug-*
Existen varias opciones de depuración. Consulte syncthing serve --help para ver las opciones que se aplican a su versión.

OPCIONES DE DESENCRIPTACIÓN

--to=<directorio>
Directorio de destino donde se almacenarán los archivos después de la desencriptación.
--verify-only
No escribir archivos desencriptados en disco (pero verificar hashes de texto plano).
--password=<contraseña> ($FOLDER_PASSWORD)
Contraseña de la carpeta para desencriptación/verificación. Se puede pasar a través de la variable de entorno FOLDER_PASSWORD en su lugar para evitar que se grabe en el historial del shell o que se espíe desde la lista de procesos en ejecución.
--folder-id=<id>
ID de la carpeta cifrada, si no se puede determinar automáticamente.
--token-path=<archivo>
Ruta al archivo de token dentro de la carpeta (utilizado para determinar la ID de la carpeta).
--continue
Continuar procesando el siguiente archivo en caso de error, en lugar de abortar.

OPCIONES DE GENERACIÓN

--gui-password=<contraseña|->
Especificar una nueva contraseña de autenticación de la GUI, para actualizar el archivo de configuración. Se lee del flujo de entrada estándar si solo se proporciona un guion (-). Una contraseña en texto plano se hashea antes de escribirla en el archivo de configuración, pero una entrada ya hasheada con bcrypt se almacena literalmente. Como caso especial, proporcionar el hash de contraseña existente como contraseña lo dejará intacto.
--gui-user=<nombredeusuario>
Especificar un nuevo nombre de usuario de autenticación de la GUI, para actualizar el archivo de configuración.

OPCIONES DE ACTUALIZACIÓN

--check-only
No actualizar, solo indicar si hay una actualización disponible.
--from=<url>
Actualizar a la versión de Syncthing disponible desde la carga del paquete en la URL dada.

CÓDIGOS DE SALIDA

0
Éxito / Apagado
1
Error
2
Actualización no disponible
3
Reiniciando
4
Actualizando

Los códigos de salida superiores a 125 suelen ser devueltos por el shell/cargador binario/manejador de señales predeterminado. Los códigos de salida superiores a 128+N en Unix suelen representar la señal que provocó la salida del proceso. Por ejemplo, 128 + 9 (SIGKILL) = 137.

SUBCOMANDOS

La sintaxis de la línea de comandos admite diferentes modos de operación a través de varios subcomandos, especificados como el primer argumento. Si se omite, se asume el valor predeterminado serve.

La configuración inicial de un ID de dispositivo y la configuración predeterminada se pueden llamar explícitamente con el subcomando generate. También puede actualizar las credenciales de autenticación de la GUI configuradas, sin pasar por la API REST. Un certificado de dispositivo existente no se modifica. Si el archivo de configuración ya existe, se valida y se actualiza al último esquema de configuración, incluyendo la adición de valores predeterminados para cualquier opción nueva.

El subcomando decrypt se utiliza junto con dispositivos no confiables (cifrados), consulte la sección correspondiente sobre desencriptación para obtener detalles. No depende de que Syncthing esté en ejecución, sino que funciona con datos fuera de línea.

Para trabajar con la API REST para depuración o automatización de tareas en Syncthing, el subcomando cli proporciona un acceso fácil a funciones individuales. Básicamente, ahorra la molestia de manejar conexiones HTTP y autenticación de API.

Los subcomandos disponibles se agrupan en varias jerarquías anidadas y algunas partes se generan dinámicamente a partir de la instancia de Syncthing en ejecución. En cada nivel, la opción --help enumera las propiedades, acciones y comandos disponibles para que el usuario los descubra interactivamente. Los grupos de nivel superior son:

config
Accede a la configuración en vivo en una instancia en ejecución a través de la API REST para recuperar (get) o actualizar (set) valores de forma detallada. La jerarquía se basa en la misma estructura que se utiliza en las representaciones JSON / XML.
show
Muestra las propiedades del sistema y el estado de una instancia en ejecución. La salida se pasa directamente desde la respuesta de la API REST y, por lo tanto, requiere el análisis del formato JSON.
operations
Controla la operación general del programa, como reiniciar o gestionar actualizaciones, así como activar algunas acciones por carpeta. También puede configurar los patrones de ignorados predeterminados desde un archivo de ignorados de texto plano.
errors
Examina las condiciones de error pendientes que requieren la atención del usuario, o las reconoce (borra).
debug
Varias herramientas para ayudar en el diagnóstico de problemas o la recopilación de información para informes de errores. Algunos de estos comandos acceden directamente a la base de datos y, por lo tanto, solo pueden funcionar cuando Syncthing no está en ejecución.
- (un solo guion)
Lee comandos subsiguientes de la entrada estándar, sin necesidad de llamar al comando syncthing cli repetidamente. Sale ante cualquier comando inválido o cuando se recibe EOF (fin de archivo).

PROXIES

Syncthing puede usar un proxy SOCKS, HTTP o HTTPS para comunicarse con el mundo exterior. El proxy se utiliza solo para conexiones salientes; no es posible aceptar conexiones entrantes a través del proxy. El proxy se configura a través de la variable de entorno all_proxy. De forma un tanto inusual, esta variable debe llamarse en minúsculas; no es “ALL_PROXY”. Por ejemplo:

$ export all_proxy=socks://192.0.2.42:8081

CONFIGURACIÓN DE DESARROLLO

Las siguientes variables de entorno modifican el comportamiento de Syncthing de maneras que son principalmente útiles para los desarrolladores. Úselas con precaución. Si inicia Syncthing desde dentro de administradores de servicios como systemd o supervisor, la expansión de rutas puede no ser soportada.

STTRACE
Se utiliza para aumentar la verbosidad de la depuración en instalaciones específicas, generalmente mapeando a un paquete de Go. Introduzca una cadena separada por comas de instalaciones a rastrear: api,beacon. Opcionalmente, se puede proporcionar un nivel de registro por instalación para especificar algo diferente a DEBUG: api:WARN,beacon:ERROR, lo que podría anular un ajuste global de --log-level.

Las cadenas de instalaciones válidas se enumeran a continuación; además, syncthing serve --help siempre muestra la lista más actualizada.

Manejo de conexiones

Base de datos SQLite

Descubrimiento de dispositivos remotos

Generación y registro de eventos

Acceso al sistema de archivos

STLOCKTHRESHOLD
Se utiliza para depurar interbloqueos internos; establece la sensibilidad de depuración. Úselo solo bajo la dirección de un desarrollador.
STVERSIONEXTRA
Agrega información adicional a la cadena de versión en los registros y a la línea de versión en la GUI. Se puede establecer en el nombre de un wrapper o herramienta que controle syncthing para comunicar esto al usuario final.
GOMAXPROCS
Establece el número máximo de núcleos de CPU a utilizar. Por defecto, todos los núcleos de CPU disponibles.
GOGC
Porcentaje de crecimiento del heap en el que activar el GC. El valor predeterminado es 100. Números más bajos mantienen bajo el uso máximo de memoria, a costa del uso de CPU (es decir, rendimiento).
LOGGER_DISCARD
Hack para deshabilitar completamente el registro, por ejemplo, al ejecutar pruebas de rendimiento. Establezca en cualquier valor no vacío para usarlo.
