NOMBRE

systemd-bless-boot.service, systemd-bless-boot - Marcar el proceso de arranque actual como exitoso

SINOPSIS

systemd-bless-boot.service

/usr/lib/systemd/systemd-bless-boot

DESCRIPCIÓN

systemd-bless-boot.service es un servicio del sistema que marca el proceso de arranque actual como exitoso. Se incorpora automáticamente a la transacción inicial cuando systemd-bless-boot-generator(8) detecta que se está utilizando el conteo de arranque al estilo de systemd-boot(7).

Internamente, el servicio opera basándose en la variable EFI LoaderBootCountPath (del UUID del proveedor 4a67b082-0a4c-41cf-b6c7-440b29bb8c4f), que se pasa desde el gestor de arranque al SO. Contiene una ruta de sistema de archivos (relativa a la partición del sistema EFI) del archivo de entrada del gestor de arranque o imagen de kernel unificada compatible con la Especificación del Gestor de Arranque[1], que se utilizó para iniciar el sistema. systemd-bless-boot.service elimina los dos contadores numéricos de arranque "intentos realizados" y "intentos restantes" del nombre del archivo, lo que indica a futuras invocaciones del gestor de arranque que la entrada ha completado el arranque con éxito al menos una vez. (Por lo tanto, este servicio renombrará el archivo de entrada del gestor de arranque o la imagen de kernel unificada en el primer arranque exitoso).

OPCIONES

El ejecutable /usr/lib/systemd/systemd-bless-boot también puede ser invocado desde la línea de comandos, aceptando uno de los siguientes argumentos de comando:

status

Se muestra el estado actual del archivo de entrada del gestor de arranque o la imagen de kernel unificada. Esto produce una de las siguientes salidas: "good", "bad", "indeterminate", "clean", "dirty", dependiendo del estado e invocaciones previas del comando. La cadena "indeterminate" se muestra inicialmente después del arranque, antes de que se haya marcado como "good" o "bad". La cadena "good" se muestra después de que el arranque se marcó como "good" con el comando good a continuación, y "bad" respectivamente después de que se invocó el comando bad. La cadena "clean" se devuelve cuando el conteo de arranque no está activo actualmente (lo que incluye el caso en que la entrada actual ya se marcó como persistentemente buena). La cadena "dirty" se devuelve cuando el sistema se inicia con un kernel que se sabe que es defectuoso (es decir, uno en el que el contador de intentos restantes ya ha llegado a cero).

Este comando se implica si no se especifica ningún argumento de comando.

Añadido en la versión 240.

good

Cuando se invoca, el archivo de entrada del gestor de arranque actual o la imagen de kernel unificada se marcarán como "good", ejecutando la operación de renombrar el archivo descrita anteriormente. Este comando está destinado a ser invocado al final de un arranque exitoso. La unidad systemd-bless-boot.service invoca este comando.

Añadido en la versión 240.

bad

Cuando se llama, el contador de "intentos restantes" en el nombre del archivo de entrada del gestor de arranque o el nombre del archivo de imagen de kernel unificada se establece en cero, marcando la entrada del gestor de arranque o la imagen del kernel como "bad", de modo que el gestor de arranque no la considere en arranques futuros (al menos mientras haya otras entradas disponibles que aún no estén marcadas como "bad"). Este comando normalmente no se ejecuta, pero se puede utilizar para poner fin instantáneamente a la lógica de conteo de arranque si se detecta un problema y marcar persistentemente la entrada de arranque como defectuosa.

Añadido en la versión 240.

indeterminate

Este comando deshace cualquier marcado de la entrada del gestor de arranque actual o imagen de kernel unificada como buena o mala. Esto se implementa renombrando el archivo de entrada del gestor de arranque o la imagen de kernel unificada de vuelta a la ruta codificada en la variable EFI LoaderBootCountPath. Tenga en cuenta que la operación fallará si el kernel actual no se inicia con el conteo de arranque habilitado (es decir, si la variable EFI no está configurada). Si el contador de arranque ya alcanzó cero intentos restantes en un arranque anterior, esta operación también fallará: una vez que una entrada se marca como bad, solo se puede restablecer a good, pero no a indeterminate.

Añadido en la versión 240.

Imprime un breve texto de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.
