SYSTEM.ROOTDAEMONRC(1) Manual de Comandos Generales SYSTEM.ROOTDAEMONRC(1)

NOTA BENE

El uso de este archivo está obsoleto y se eliminará en futuras versiones de ROOT.

Póngase en contacto con el equipo de ROOT en http://root.cern en el improbable caso de que este cambio sea perjudicial para su flujo de trabajo.

NOMBRE

system.rootdaemonrc, .rootdaemonrc - directivas de control de acceso para demonios de ROOT

UBICACIONES

ROOTDAEMORC, $HOME/.rootdaemonrc
/etc/root/system.rootdaemonrc, $ROOTSYS/etc/system.rootdaemonrc

DESCRIPCIÓN

Esta página del manual documenta el formato de las directivas que especifican las directivas de control de acceso para los demonios de ROOT. Estas directivas se leen de un archivo de texto cuya ruta completa se obtiene de la variable de entorno ROOTDAEMONRC. Si dicha variable no está definida, el demonio busca un archivo llamado .rootdaemonrc en el directorio $HOME del usuario que inicia el demonio; si este archivo tampoco existe, se utiliza el archivo system.rootdaemonrc, ubicado en ** /etc/root** o ** $ROOTSYS/etc**. Si ninguno de estos archivos existe (o es legible), el demonio utiliza una directiva predeterminada incorporada, derivada de las opciones de configuración de la instalación.

FORMATO

*
las líneas que comienzan con '#' son líneas de comentario.
*
los hosts se pueden especificar ya sea con su nombre (por ejemplo, pcepsft43), su FQDN (por ejemplo, pcepsft43.cern.ch) o su dirección IP (por ejemplo, 137.138.99.73).
*
las directivas que se aplican a todos los hosts se pueden especificar con 'default' o '*'.
*
el carácter '*' se puede utilizar en cualquier campo del nombre para indicar un conjunto de máquinas o dominios, por ejemplo, pcepsft*.cern.ch se aplica a todas las máquinas 'pcepsft' en el dominio 'cern.ch'. (para indicar todas las máquinas 'lxplus' deberías usar 'lxplus*.cern.ch' porque internamente la máquina genérica lxplus tiene un nombre real del tipo lxplusnnn.cern.ch; también puedes usar 'lxplus' si no te importa la comprobación del nombre de dominio).
*
se puede indicar un dominio completo por su nombre, por ejemplo, 'cern.ch', 'cnaf.infn.it' o '.ch'.
*
las direcciones IP truncadas también se pueden usar para indicar un conjunto de máquinas; se interpretan como la primera o la última parte de la dirección; por ejemplo, para seleccionar 137.138.99.73, cualquiera de las siguientes es válida: '137.138.99', '137.138', '137`, '99.73'; o con comodines: '137.13*' o '*.99.73`; sin embargo, '138.99' no es válido porque es ambiguo.
*
la información que sigue al nombre o a la dirección IP indica, en orden de preferencia, los nombres cortos o los códigos internos de los métodos de autenticación aceptados para las solicitudes provenientes de los hosts especificados; los implementados hasta ahora son:


Nombre del método código


UsrPwd usrpwd 0

Los métodos no especificados explícitamente no son aceptados.

*
Las líneas que terminan con '´ son seguidas por información adicional para el host en la siguiente línea; el nombre del host no debe repetirse.

EJEMPLOS

Ejemplos válidos:

default none
Todas las solicitudes se deniegan a menos que se especifiquen mediante directivas dedicadas.
default 0
Los mecanismos de autenticación permitidos por defecto son 'usrpwd' (código 0)
137.138. 0
Los mecanismos de autenticación permitidos desde el host en el dominio 137.138. (cern.ch) son 'usrpwd' (código 0)
lxplus*.cern.ch 0:qwerty:uytre
Las solicitudes del clúster lxplus de los usuarios 'qwerty' y 'uytre' pueden autenticarse usando 'usrpwd'.
pcep*.cern.ch 0:-qwerty
Las solicitudes de los nodos pcep*.cern.ch pueden autenticarse usando 'usrpwd' al acceder al demonio 'rootd'; el usuario 'qwerty' no puede usar 'usrpwd'.

Para más información sobre el sistema ROOT, consulte http://root.cern/ .
