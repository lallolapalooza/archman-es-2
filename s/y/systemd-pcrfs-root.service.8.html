NOMBRE

systemd-pcrphase.service, systemd-pcrphase-sysinit.service, systemd-pcrphase-initrd.service, systemd-pcrmachine.service, systemd-pcrfs-root.service, systemd-pcrfs@.service, systemd-pcrextend - Medir la fase de arranque en el PCR 11 de TPM2, el ID de máquina y la identidad del sistema de archivos en el PCR 15

SINOPSIS

systemd-pcrphase.service

systemd-pcrphase-sysinit.service

systemd-pcrphase-initrd.service

systemd-pcrmachine.service

systemd-pcrfs-root.service

systemd-pcrfs@.service

/usr/lib/systemd/systemd-pcrextend [CADENA]

DESCRIPCIÓN

systemd-pcrphase.service, systemd-pcrphase-sysinit.service, y systemd-pcrphase-initrd.service son servicios del sistema que miden cadenas específicas en el PCR 11 de TPM2 durante el arranque en varios puntos de control del proceso de arranque.

systemd-pcrmachine.service es un servicio del sistema que mide el ID de máquina (ver machine-id(5)) en el PCR 15.

systemd-pcrfs-root.service y systemd-pcrfs@.service son servicios que miden información de identidad del sistema de archivos (es decir, punto de montaje, tipo de sistema de archivos, etiqueta y UUID, etiqueta y UUID de la partición) en el PCR 15. systemd-pcrfs-root.service lo hace para el sistema de archivos raíz, systemd-pcrfs@.service es una unidad plantilla que mide el sistema de archivos indicado por su identificador de instancia en su lugar.

Estos servicios requieren que systemd-stub(7) se utilice en una imagen de kernel unificada (UKI). No ejecutan ninguna operación cuando el stub no se ha utilizado para invocar el kernel. El stub medirá el kernel invocado y los recursos del proveedor asociados en el PCR 11 antes de ceder el control a él; una vez que se invoca el espacio de usuario, estos servicios extenderán el PCR 11 de TPM2 con ciertas cadenas literales que indican las fases del proceso de arranque. Durante un proceso de arranque normal, el PCR 11 se extiende con las siguientes cadenas:

1."enter-initrd" — temprano cuando el initrd se inicializa, antes de activar las imágenes de extensión del sistema para el initrd. Actúa como una barrera entre el momento en que el kernel se inicializa y el momento en que el initrd comienza a operar y habilita las imágenes de extensión del sistema, es decir, código enviado fuera de la UKI. (Esta extensión ocurre cuando se inicia el servicio systemd-pcrphase-initrd.service(8).)
2."leave-initrd" — cuando el initrd está a punto de transicionar al sistema de archivos del host. Actúa como una barrera entre el código del initrd y el código del sistema operativo host. (Esta extensión ocurre cuando se detiene el servicio systemd-pcrphase-sysinit.service(8).)
3."sysinit" — cuando la inicialización básica del sistema está completa (lo que incluye que los sistemas de archivos locales se hayan montado), y el sistema comienza a iniciar los servicios regulares del sistema. (Esta extensión ocurre cuando se inicia el servicio systemd-pcrphase-sysinit.service(8).)
4."ready" — durante una fase posterior del arranque, después de que los sistemas de archivos remotos se hayan activado (es decir, después de remote-fs.target), pero antes de que se permita el inicio de sesión a los usuarios (es decir, antes de systemd-user-sessions.service). Actúa como una barrera entre el momento en que a los usuarios regulares no privilegiados todavía se les prohíbe iniciar sesión y el momento en que se les permite hacerlo. (Esta extensión ocurre cuando se inicia el servicio systemd-pcrphase-sysinit.service(8).)
5."shutdown" — cuando comienza el apagado del sistema. Actúa como una barrera entre el momento en que el sistema está completamente en funcionamiento y el momento en que está a punto de apagarse. (Esta extensión ocurre cuando se detiene el servicio systemd-pcrphase.service.)
6."final" — al final del apagado del sistema. Actúa como una barrera entre el momento en que el gestor de servicios todavía se ejecuta y cuando transiciona a la fase final de apagado donde la gestión de servicios ya no está disponible. (Esta extensión ocurre cuando se detiene el servicio systemd-pcrphase-sysinit.service(8).)

Durante un ciclo de vida del sistema normal, el PCR 11 se extiende con las cadenas "enter-initrd", "leave-initrd", "sysinit", "ready", "shutdown" y "final".

Las fases específicas del proceso de arranque pueden ser referenciadas a través de la serie de cadenas medidas, separadas por dos puntos (la "ruta de la fase"). Por ejemplo, la ruta de la fase para el tiempo de ejecución normal del sistema es "enter-initrd:leave-initrd:sysinit:ready", mientras que la del initrd es solo "enter-initrd". La ruta de la fase para la fase de arranque anterior al initrd es una cadena vacía; dado que es difícil de pasar, se puede usar un solo dos puntos (":") en su lugar. Tenga en cuenta que las seis cadenas mencionadas anteriormente son solo las cadenas predeterminadas y los sistemas individuales pueden medir otras cadenas en otros momentos, implementando así fases de arranque diferentes y más detalladas para vincular políticas.

Al vincular políticas de objetos TPM2 a una ruta de fase específica, es posible restringir su acceso a fases específicas del proceso de arranque, por ejemplo, haciendo imposible acceder a la clave de cifrado del sistema de archivos raíz después de que el sistema haya transitado del initrd al sistema de archivos raíz del host.

Use systemd-measure(1) para precalcular los valores esperados del PCR 11 para fases de arranque específicas (a través del interruptor --phase=).

systemd-pcrfs-root.service y systemd-pcrfs@.service son incorporados automáticamente a la transacción inicial por systemd-gpt-auto-generator(8) para los sistemas de archivos raíz y /var/. systemd-fstab-generator(8) hará esto para todos los montajes con la opción de montaje x-systemd.pcrfs en /etc/fstab.

OPCIONES

El ejecutable /usr/lib/systemd/system-pcrextend también puede ser invocado desde la línea de comandos, donde espera la palabra a extender en el PCR 11, así como los siguientes interruptores:

--bank=

Toma los bancos PCR en los que extender la palabra especificada. Si no se especifica, la herramienta determina automáticamente todos los bancos PCR habilitados y mide la palabra en todos ellos.

Añadido en la versión 252.

--pcr=

Toma el índice del PCR a extender. Si se especifican --machine-id o --file-system=, el valor predeterminado es 15, de lo contrario, el valor predeterminado es 11.

Añadido en la versión 255.

--tpm2-device=RUTA

Controla qué dispositivo TPM2 se utilizará. Espera una ruta de nodo de dispositivo que se refiera al chip TPM2 (por ejemplo, /dev/tpmrm0). Alternativamente, se puede especificar el valor especial "auto", para determinar automáticamente el nodo de dispositivo de un dispositivo TPM2 adecuado (del cual debe haber exactamente uno). El valor especial "list" puede usarse para enumerar todos los dispositivos TPM2 adecuados descubiertos actualmente.

Añadido en la versión 252.

--graceful

Si no se encuentra soporte para firmware TPM2, subsistema del kernel, controlador del kernel o dispositivo, salga con el estado de salida 0 (es decir, indique éxito). Si esto no se especifica, cualquier intento de medir sin un dispositivo TPM2 hará que la invocación falle.

Añadido en la versión 253.

--machine-id

En lugar de medir una palabra especificada en la línea de comandos en el PCR 11, mide el ID de máquina del host en el PCR 15.

Añadido en la versión 253.

--file-system=

En lugar de medir una palabra especificada en la línea de comandos en el PCR 11, mide información de identidad del sistema de archivos especificado en el PCR 15. El parámetro debe ser la ruta al punto de montaje establecido del sistema de archivos a medir.

Añadido en la versión 253.

-h, --help

Imprime un breve mensaje de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.

systemd-pcrfs-root.service(8) — Arch Linux man pages

NAME

systemd-pcrfs-root.service, systemd-pcrfs-root — measure the contents of the root filesystem into TPM PCRs

SYNOPSIS

systemd-pcrfs-root.service

DESCRIPTION

The systemd-pcrfs-root.service is a systemd(1) service that measures the contents of the root filesystem into specific Trust Platform Module (TPM) Platform Configuration Registers (PCRs). This service is typically used early in the boot process to ensure the integrity of the operating system files.

When the system boots, systemd-pcrfs-root.service uses the systemd-measure(1) utility to calculate cryptographic hashes of the files that are considered essential for the system's integrity. These hashes are then "extended" into the TPM PCRs. Extending a PCR means combining the current value of the PCR with the new data (the hash) to produce a new value. This process is one-way, meaning it's computationally infeasible to determine the original PCR value from the extended value.

By measuring the root filesystem into TPM PCRs, the system can later verify if the files have been tampered with. If the contents of the root filesystem change after the initial measurement, the PCR values will differ from the expected values, indicating a potential security breach.

The specific files and directories to be measured are configured in the unit file itself or through related configuration mechanisms.

This service typically runs before other services that rely on the integrity of the root filesystem, such as those involved in secure boot or disk decryption.

OPTIONS

This service does not accept any command-line options directly. Its behavior is determined by the systemd unit file configuration and the systemd-measure(1) utility.

FILES

/usr/lib/systemd/system/systemd-pcrfs-root.service
The systemd unit file for the service.
/usr/lib/systemd/systemd-measure
The utility used for measuring files into TPM PCRs.

The service performs the actual measurement of the root filesystem. It acquires a LOCK_SH lock (shared lock) on the log file (see systemd-measure(8)) on the log file is acquired while the measurement is made and the file is updated. Thus, applications that intend to acquire a consistent quote from the TPM with the associated snapshot of the event log should acquire a LOCK_SH lock while doing so.

Added in version 252.
