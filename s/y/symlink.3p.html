SYMLINK(3P) Manual de Programador de POSIX SYMLINK(3P)

PROLOG

Esta página del manual forma parte del Manual de Programador de POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

symlink, symlinkat — crear un enlace simbólico

SINOPSIS

#include <unistd.h>
int symlink(const char *path1, const char *path2);
#include <fcntl.h>
int symlinkat(const char *path1, int fd, const char *path2);

DESCRIPCIÓN

La función symlink() crea un enlace simbólico llamado path2 que contiene la cadena apuntada por path1 (path2 es el nombre del enlace simbólico creado, path1 es la cadena contenida en el enlace simbólico).

La cadena apuntada por path1 se tratará únicamente como una cadena y no se validará como un nombre de ruta.

Si la función symlink() falla por cualquier motivo que no sea [EIO], cualquier archivo nombrado por path2 no se verá afectado.

Si path2 nombra un enlace simbólico, symlink() fallará y establecerá errno a [EEXIST].

El ID de usuario del enlace simbólico se establecerá en el ID de usuario efectivo del proceso. El ID de grupo del enlace simbólico se establecerá en el ID de grupo del directorio padre o en el ID de grupo efectivo del proceso. Las implementaciones proporcionarán una forma de inicializar el ID de grupo del enlace simbólico al ID de grupo del directorio padre. Las implementaciones pueden, pero no tienen que, proporcionar una forma definida por la implementación para inicializar el ID de grupo del enlace simbólico al ID de grupo efectivo del proceso que llama.

Los valores de los bits del modo de archivo para el enlace simbólico creado no están especificados. Todas las interfaces especificadas por POSIX.1‐2008 se comportarán como si el contenido de los enlaces simbólicos siempre pudiera leerse, excepto que el valor de los bits del modo de archivo devuelto en el campo st_mode de la estructura stat no está especificado.

Al completarse con éxito, symlink() marcará para actualización los tiempos de acceso, modificación de datos y cambio de estado del último acceso del enlace simbólico. Además, los tiempos de modificación de datos y cambio de estado del último archivo del directorio que contiene la nueva entrada se marcarán para actualización.

La función symlinkat() será equivalente a la función symlink() excepto en el caso en que path2 especifique una ruta relativa. En este caso, el enlace simbólico se crea relativo al directorio asociado con el descriptor de archivo fd en lugar del directorio de trabajo actual. Si el modo de acceso de la descripción del archivo abierto asociado con el descriptor de archivo no es O_SEARCH, la función verificará si se permiten las búsquedas de directorios utilizando los permisos actuales del directorio subyacente al descriptor de archivo. Si el modo de acceso es O_SEARCH, la función no realizará la verificación.

Si se pasa a symlinkat() el valor especial AT_FDCWD en el parámetro fd, se utilizará el directorio de trabajo actual y el comportamiento será idéntico al de una llamada a symlink().

VALOR DE RETORNO

Al completarse con éxito, estas funciones devolverán 0. De lo contrario, estas funciones devolverán -1 y establecerán errno para indicar el error.

ERRORES

Estas funciones fallarán si:

EACCES
Se deniega el permiso de escritura en el directorio donde se está creando el enlace simbólico, o se deniega el permiso de búsqueda para un componente del prefijo de ruta de path2.
EEXIST
El argumento path2 nombra un archivo existente.
EIO
Se produce un error de E/S al leer o escribir en el sistema de archivos.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path2.
ENAMETOOLONG

La longitud de un componente del nombre de ruta especificado por el argumento path2 es mayor que {NAME_MAX} o la longitud del argumento path1 es mayor que {SYMLINK_MAX}.
ENOENT
Un componente del prefijo de ruta de path2 no nombra un archivo existente o path2 es una cadena vacía.
ENOENT o ENOTDIR

El argumento path2 contiene al menos un carácter que no es <barra> y termina con uno o más caracteres <barra> siguientes. Si path2 sin los caracteres <barra> siguientes nombrara un archivo existente, no se producirá un error [ENOENT].
ENOSPC
El directorio en el que se está colocando la entrada para el nuevo enlace simbólico no puede ampliarse porque no queda espacio en el sistema de archivos que contiene el directorio, o no se puede crear el nuevo enlace simbólico porque no queda espacio en el sistema de archivos que contendrá el enlace, o el sistema de archivos carece de recursos de asignación de archivos.
ENOTDIR
Un componente del prefijo de ruta de path2 nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio.
EROFS
El nuevo enlace simbólico residiría en un sistema de archivos de solo lectura.

La función symlinkat() fallará si:

EACCES
El modo de acceso de la descripción del archivo abierto asociado con fd no es O_SEARCH y los permisos del directorio subyacente a fd no permiten búsquedas de directorios.
EBADF
El argumento path2 no especifica una ruta absoluta y el argumento fd no es AT_FDCWD ni un descriptor de archivo válido abierto para lectura o búsqueda.
ENOTDIR
El argumento path2 no es una ruta absoluta y fd es un descriptor de archivo asociado con un archivo que no es un directorio.

Estas funciones pueden fallar si:

ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path2.
ENAMETOOLONG

La longitud del argumento path2 excede {PATH_MAX} o la resolución del nombre de ruta de un enlace simbólico en el argumento path2 produjo un resultado intermedio con una longitud que excede {PATH_MAX}.

EJEMPLOS

Ninguno.

USO DE LA APLICACIÓN

Al igual que un enlace duro, un enlace simbólico permite que un archivo tenga múltiples nombres lógicos. La presencia de un enlace duro garantiza la existencia de un archivo, incluso después de que se haya eliminado el nombre original. Un enlace simbólico no proporciona tal garantía; de hecho, el archivo nombrado por el argumento path1 no necesita existir cuando se crea el enlace. Un enlace simbólico puede cruzar los límites del sistema de archivos.

Se realizan comprobaciones de permisos normales en cada componente del nombre de ruta del enlace simbólico durante su resolución.

FUNDAMENTO

El propósito de la función symlinkat() es crear enlaces simbólicos en directorios distintos al directorio de trabajo actual sin exposición a condiciones de carrera. Cualquier parte de la ruta de un archivo podría modificarse en paralelo a una llamada a symlink(), lo que resultaría en un comportamiento no especificado. Al abrir un descriptor de archivo para el directorio de destino y utilizar la función symlinkat(), se puede garantizar que el enlace simbólico creado se ubica en relación con el directorio deseado.
