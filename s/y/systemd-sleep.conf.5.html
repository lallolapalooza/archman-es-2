NOMBRE

systemd-sleep.conf, sleep.conf.d - Archivo de configuración para suspensión e hibernación

SINOPSIS

/etc/systemd/sleep.conf
/run/systemd/sleep.conf
/usr/lib/systemd/sleep.conf
/etc/systemd/sleep.conf.d/*.conf
/run/systemd/sleep.conf.d/*.conf
/usr/lib/systemd/sleep.conf.d/*.conf

DESCRIPCIÓN

systemd soporta cuatro modos generales de ahorro de energía:

suspend

un estado de bajo consumo donde la ejecución del SO se pausa, y una pérdida total de energía podría resultar en pérdida de datos, y que es rápido de entrar y salir. Esto corresponde a los estados de suspensión, espera o congelación como los entiende el kernel.

Añadido en la versión 203.

hibernate

un estado de bajo consumo donde la ejecución del SO se pausa, y una pérdida total de energía no resulta en pérdida de datos, y que puede ser lento de entrar y salir. Esto corresponde a la hibernación como la entiende el kernel.

Añadido en la versión 203.

hybrid-sleep

un estado de bajo consumo donde la ejecución del SO se pausa, que puede ser lento de entrar, y ante una pérdida total de energía no resulta en pérdida de datos pero puede ser más lento de salir en ese caso. Este modo se llama suspend-to-both (suspender a ambos) por el kernel.

Añadido en la versión 203.

suspend-then-hibernate

Un estado de bajo consumo donde el sistema se suspende inicialmente (el estado se almacena en RAM). Cuando el nivel de batería es demasiado bajo (menos del 5%) o ha pasado un cierto período de tiempo, lo que ocurra primero, el sistema se activa automáticamente y luego hiberna. Esto establece un equilibrio entre velocidad y seguridad.

Si el sistema no tiene batería, hibernará después de que transcurra HibernateDelaySec=. Si no se establece, el valor por defecto es "2h".

Si el sistema tiene batería y HibernateDelaySec= no está establecido, primero se intentan las alarmas de batería baja (ACPI _BTP) para detectar el porcentaje de batería y despertar el sistema para hibernar. Si no están disponibles, o si HibernateDelaySec= está establecido, el sistema se despertará regularmente para comprobar la hora y detectar el porcentaje de batería/tasa de descarga. La tasa se utiliza para programar la próxima detección. Si tampoco está disponible, SuspendEstimationSec= se utiliza como último recurso.

Añadido en la versión 239.

Los ajustes en estos archivos determinan qué cadenas se escribirán en /sys/power/disk y /sys/power/state por systemd-sleep(8) cuando systemd(1) intente suspender o hibernar la máquina. Véase systemd.syntax(7) para una descripción general de la sintaxis.

DIRECTORIOS DE CONFIGURACIÓN Y PRECEDENCIA

La configuración por defecto se establece durante la compilación, por lo que la configuración solo es necesaria cuando es necesario desviarse de esos valores por defecto. El archivo de configuración principal se carga desde uno de los directorios listados en orden de prioridad, solo se utiliza el primer archivo encontrado: /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La versión del proveedor del archivo contiene entradas comentadas que muestran los valores por defecto como guía para el administrador. Las anulaciones locales también se pueden crear creando "drop-ins", como se describe a continuación. El archivo de configuración principal también se puede editar para este propósito (o una copia en /etc/ si se distribuye bajo /usr/), sin embargo, se recomienda usar drop-ins para la configuración local en lugar de modificar el archivo de configuración principal.

Además del archivo de configuración principal, se leen fragmentos de configuración drop-in de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, y /etc/systemd/*.conf.d/. Estos drop-ins tienen mayor precedencia y anulan el archivo de configuración principal. Los archivos en los subdirectorios de configuración *.conf.d/ se ordenan por su nombre de archivo en orden lexicográfico, independientemente de en qué subdirectorios residan. Cuando varios archivos especifican la misma opción, para las opciones que aceptan solo un valor, la entrada en el archivo que se ordena al final tiene precedencia, y para las opciones que aceptan una lista de valores, las entradas se recopilan a medida que ocurren en los archivos ordenados.

Cuando los paquetes necesitan personalizar la configuración, pueden instalar drop-ins bajo /usr/. Los archivos en /etc/ están reservados para el administrador local, quien puede usar esta lógica para anular los archivos de configuración instalados por los paquetes del proveedor. Los drop-ins deben usarse para anular los drop-ins de los paquetes, ya que el archivo de configuración principal tiene menor precedencia. Se recomienda prefijar todos los nombres de archivo en estos subdirectorios con un número de dos dígitos y un guion, para simplificar el orden. Esto también define un concepto de prioridades de drop-in para permitir a los proveedores de SO distribuir drop-ins dentro de un rango específico inferior al rango utilizado por los usuarios. Esto debería reducir el riesgo de que los drop-ins de los paquetes anulen accidentalmente los drop-ins definidos por los usuarios. Se recomienda usar el rango 10-40 para drop-ins en /usr/ y el rango 60-90 para drop-ins en /etc/ y /run/, para asegurar que los drop-ins locales y transitorios tengan prioridad sobre los drop-ins distribuidos por el proveedor del sistema operativo.

Para deshabilitar un archivo de configuración proporcionado por el proveedor, la forma recomendada es colocar un enlace simbólico a /dev/null en el directorio de configuración en /etc/, con el mismo nombre de archivo que el archivo de configuración del proveedor.

OPCIONES

Las siguientes opciones se pueden configurar en la sección [Sleep] de /etc/systemd/sleep.conf o un archivo de sleep.conf.d:

AllowSuspend=, AllowHibernation=, AllowHybridSleep=, AllowSuspendThenHibernate=

Por defecto, se anuncia cualquier modo de ahorro de energía si es posible (es decir, si el kernel soporta ese modo, los recursos necesarios están disponibles). Estos interruptores se pueden usar para deshabilitar modos específicos.

Si se usa AllowHibernation=no o AllowSuspend=no, esto implica AllowSuspendThenHibernate=no y AllowHybridSleep=no, ya que estos métodos usan tanto la suspensión como la hibernación internamente. AllowSuspendThenHibernate=yes y AllowHybridSleep=yes se pueden usar para anular y habilitar esos modos específicos.

Añadido en la versión 240.

SuspendState=

La cadena que se escribirá en /sys/power/state por systemd-suspend.service(8). Se pueden especificar varios valores separando múltiples valores con espacios en blanco. Se intentarán uno por uno, hasta que uno se escriba sin error. Si ninguna de las escrituras tiene éxito, la operación se abortará.

El conjunto de valores permitidos está determinado por el kernel y se muestra en el propio archivo (use cat /sys/power/state para mostrar). Véase Basic sysfs Interfaces for System Suspend and Hibernation[2] para más detalles.

systemd-suspend-then-hibernate.service(8) usa este valor al suspender.

Añadido en la versión 203.

HibernateMode=

La cadena que se escribirá en /sys/power/disk por systemd-hibernate.service(8). Se pueden especificar varios valores separando múltiples valores con espacios en blanco. Se intentarán uno por uno, hasta que uno se escriba sin error. Si ninguna de las escrituras tiene éxito, la operación se abortará.

El conjunto de valores permitidos está determinado por el kernel y se muestra en el propio archivo (use cat /sys/power/disk para mostrar). Véase la página de documentación del kernel Basic sysfs Interfaces for System Suspend and Hibernation[2] para más detalles.

systemd-suspend-then-hibernate.service(8) usa el valor de HibernateMode= al hibernar.

Añadido en la versión 203.

MemorySleepMode=

La cadena que se escribirá en /sys/power/mem_sleep cuando SuspendState=mem o hybrid-sleep se usa. Se pueden especificar varios valores separando múltiples valores con espacios en blanco. Se intentarán uno por uno, hasta que uno se escriba sin error. Si ninguna de las escrituras tiene éxito, la operación se abortará. Por defecto está vacío, es decir, se respeta el valor por defecto del kernel o la opción de línea de comandos del kernel mem_sleep_default=.

Añadido en la versión 256.

HibernateDelaySec=

La cantidad de tiempo que el sistema permanece en modo de suspensión antes de que se ponga automáticamente en modo de hibernación. Solo lo usa systemd-suspend-then-hibernate.service(8). Consulte suspend-then-hibernate para detalles sobre cómo esta opción interactúa con otras opciones/el estado de la batería del sistema.

Añadido en la versión 239.

HibernateOnACPower=

Si se permite la hibernación cuando el sistema tiene alimentación de CA. Solo lo usa systemd-suspend-then-hibernate.service(8) cuando HibernateDelaySec= está configurado.

Si esta opción está deshabilitada, la cuenta regresiva de HibernateDelaySec= solo comienza después de desconectar la alimentación de CA, manteniendo el sistema en el estado de suspensión de lo contrario.

Esta opción solo es efectiva en sistemas con batería.

Añadido en la versión 257.

SuspendEstimationSec=

La alarma RTC despertará al sistema después del intervalo de tiempo especificado para medir el nivel de capacidad de la batería del sistema y estimar la tasa de descarga de la batería. Solo lo usa systemd-suspend-then-hibernate.service(8). Consulte suspend-then-hibernate para detalles sobre cómo esta opción interactúa con otras opciones/el estado de la batería del sistema.

Añadido en la versión 253.

EJEMPLO: FREEZE

Ejemplo: para explotar el modo “freeze” añadido en Linux 3.9, se puede usar systemctl suspend con

[Sleep]
SuspendState=freeze
