SYSTEMD-GPT-AUTO-GENERATOR(8) systemd-gpt-auto-generator SYSTEMD-GPT-AUTO-GENERATOR(8)

NOMBRE

systemd-gpt-auto-generator - Generador para el descubrimiento y montaje automáticos de particiones raíz, /home/, /srv/, /var/ y /var/tmp/, así como el descubrimiento y habilitación de particiones de intercambio, basados en GUIDs de tipo de partición GPT

SINOPSIS

/usr/lib/systemd/system-generators/systemd-gpt-auto-generator

DESCRIPCIÓN

systemd-gpt-auto-generator es un generador de unidades que descubre automáticamente la partición raíz, /home/, /srv/, /var/, /var/tmp/, la Partición del Sistema EFI (ESP), la Partición de Arranque Extendida (XBOOTLDR) y las particiones de intercambio, y crea unidades de montaje y de intercambio para ellas, basándose en los GUIDs de tipo de partición de las tablas de particiones GUID (GPT). Consulte la Especificación UEFI[1], capítulo 5 para más detalles. Implementa la Especificación de Particiones Descubribles[2].

Tenga en cuenta que este generador no tiene efecto en sistemas que no sean GPT. Tampoco creará puntos de montaje para directorios que ya contengan archivos o si el punto de montaje está configurado explícitamente en fstab(5). Además, no se creará ninguna unidad para la ESP o la partición XBOOTLDR si se encuentran entradas de montaje en las jerarquías /boot/ o /efi/ en fstab(5).

Si las unidades que este generador crea se ven sobrescritas, por ejemplo, por unidades en directorios con mayor precedencia, las caídas y las dependencias adicionales creadas por este generador aún pueden ser utilizadas.

Cuando se ejecuta en el disco RAM inicial (initrd), este generador puede buscar automáticamente el sistema de archivos raíz. Específicamente:

•Buscará la partición raíz en el mismo disco físico donde se encuentra la Partición del Sistema EFI (ESP). Tenga en cuenta que se requiere soporte del cargador de arranque para que esto funcione: la variable EFI LoaderDevicePartUUID del UUID del proveedor 4a67b082-0a4c-41cf-b6c7-440b29bb8c4f se utiliza para determinar desde qué partición (y por lo tanto disco) se arrancó el sistema. Si el cargador de arranque no establece esta variable, este generador no podrá detectar la partición raíz. Consulte la Interfaz del Cargador de Arranque[3] para obtener detalles.
•Alternativamente, buscará el sistema de archivos raíz en un dispositivo de bloque de loopback cuyo campo ".lo_name" esté establecido en una de las cadenas literales "rootdisk" o "rootdisk.raw". Este campo se puede establecer usando la cadena --loop-ref= de losetup. Para imágenes descargadas a través de systemd-import-generator(8), asegúrese de establecer la opción "blockdev" y establecer la cadena de nombre local a "rootdisk" para lograr este efecto. Tenga en cuenta que el descubrimiento del sistema de archivos raíz en dispositivos de bloque de loopback como este solo se realiza si se especifica explícitamente "root=gpt-auto" o "root=dissect" en la línea de comandos del kernel, a diferencia del descubrimiento basado en la ESP reportada por el cargador de arranque que también se habilita si no se especifica ningún parámetro "root=". (Este último se basa en la generación de enlaces simbólicos de dispositivo de bloque /dev/gpt-auto-root de systemd-udevd.service).

Cuando se ejecuta en el sistema host (es decir, después de haber transicionado con éxito fuera del initrd al sistema de archivos raíz), este generador buscará todas las demás particiones en el mismo disco físico que la partición raíz. Para este descubrimiento, no se requiere el soporte del cargador de arranque. Además, no es necesario que la partición raíz haya sido descubierta automáticamente por el initrd (como se describe arriba) para que tenga lugar el descubrimiento de las particiones de archivos no raíz. O en otras palabras: el descubrimiento automático del sistema de archivos raíz y de los sistemas de archivos no raíz son operaciones independientes, que no dependen una de la otra, y se realizan durante dos fases distintas del proceso de arranque (una en el initrd, la otra después). Estas particiones no se buscarán en sistemas donde el sistema de archivos raíz esté distribuido en múltiples discos, por ejemplo, a través de RAID btrfs.

La partición raíz se puede configurar explícitamente enlazando simbólicamente /run/systemd/volatile-root a /dev/block/$major:$minor. Esto es especialmente útil si el montaje raíz ha sido reemplazado por alguna forma de sistema de archivos volátil (overlayfs).

systemd-gpt-auto-generator es útil para centralizar la configuración del sistema de archivos en la tabla de particiones y hacer innecesaria la configuración en /etc/fstab o en la línea de comandos del kernel.

Este generador busca las particiones basándose en sus GUIDs de tipo de partición. Se identifican los siguientes GUIDs de tipo de partición:

systemd-gpt-auto-generator

The systemd-gpt-auto-generator is a systemd generator that may be plugged into systemd-fstab-generator(8) to install mount units for certain GPT partition types.

It understands the following GPT partition types:

Discoverable Partitions [2]:

  • AF2E3E70-7E38-40E4-9500-060143957210: Root partition ( /)
  • D3BFE2DE-A050-4D9A-A050-125B0357F0AF: Usr partition ( /usr)
  • 20911374-357A-4725-8E5F-905B854467BB: Home partition ( /home)
  • 5A4B50E0-6491-41B1-A9F9-A48E1544635D: Var partition ( /var)
  • 3F883C5B-1A4C-44A3-8827-5E0B8E756B6C: Var TMP partition ( /var/tmp)
  • 84619124-747C-4852-83A7-A34B5AE37C9B: Srv partition ( /srv)
  • E3B28F0A-E081-4D2E-BF0A-13D6D949F85A: Host partition ( /host)
  • 79A07A4A-226C-4525-B56D-6E7E98363276: Export partition ( /export)
  • 30C9D695-DB2C-46A5-9C6D-3B7C31736A53: Swap partition ( swap)
  • 4484F43C-3171-4256-94A0-B3B4A301C221: ESP partition ( /efi)
  • 00000000-0000-0000-0000-000000000001: ESP partition ( /boot)

EFI Disk Partition [1]:

  • C12A7328-F81F-11D2-BA4B-00A0C93EC93B: EFI System Partition (ESP)

The generator may be disabled by kernel command line parameter systemd.gpt_auto=0. This is the default.

Mount and swap units are generated for partitions with these UUIDs. In addition, a device mapper name is set up for swap partitions, see systemd-swap(5). The corresponding mount points are created if they do not exist.

The generator recognizes partition type 00000000-0000-0000-0000-000000000001 for the purpose of identifying a partition to be mounted at /boot/ from the EFI System Partition UUID, see above.

The first partition with this type UUID located on the same disk as the root partition is mounted to /boot/, see below.

This generator understands the following attribute flags for partitions:

Table 2. Partition Attribute Flags

Flag Value Applicable to Explanation
SD_GPT_FLAG_READ_ONLY 0x1000000000000000 /, /home/, /srv/, /var/, /var/tmp/, Extended Boot Loader Partition Partition is mounted read-only
SD_GPT_FLAG_NO_AUTO 0x8000000000000000 /, /home/, /srv/, /var/, /var/tmp/, Extended Boot Loader Partition Partition is not mounted automatically
SD_GPT_FLAG_NO_BLOCK_IO_PROTOCOL 0x0000000000000002 EFI System Partition (ESP) Partition is not mounted automatically

The
/home/, /srv/, /var/, /var/tmp/ and swap partitions may be encrypted in LUKS format. In this case, a device mapper device is set up under the names /dev/mapper/home, /dev/mapper/srv, /dev/mapper/var, /dev/mapper/tmp or /dev/mapper/swap. Note that this might create conflicts if the same partition is listed in /etc/crypttab with a different device mapper device name.

When systemd is running in the initrd the / partition may be encrypted with LUKS as well. In this case, a device mapper device is set up under the name /dev/mapper/root, and a sysroot.mount is set up that mounts the device under /sysroot. For more information, see bootup(7).

Mount and automount units for the EFI System Partition (ESP) and Extended Boot Loader Partition (XBOOTLDR) are generated on EFI systems. If the disk contains an XBOOTLDR partition, as defined in the Boot Loader Specification[4], it is made available at /boot/. This generator creates an automount unit; the mount will only be activated on-demand when accessed. The mount point will be created if necessary.

The ESP is mounted to /boot/ if that directory exists and is not used for XBOOTLDR, and otherwise to /efi/. Same as for /boot/, an automount unit is used. The mount point will be created if necessary.

No configuration is created for mount points that are configured in fstab(5) or when the target directory contains files.

When using this generator in conjunction with btrfs file systems, make sure to set the correct default subvolumes on them, using btrfs subvolume set-default.

If the system was booted via systemd-stub(7) and the stub reported to userspace that the kernel image was measured to a TPM2 PCR, then any discovered root and /var/ volume identifiers (and volume encryption key in case it is encrypted) will be automatically measured into PCR 15 on activation, via systemd-pcrfs@.service(8).

Mount constraint metadata contained in the file systems is validated by pulling in systemd-validatefs@.service(8) for generated mounts.

systemd-gpt-auto-generator implements systemd.generator(7).

KERNEL COMMAND LINE

systemd-gpt-auto-generator understands the following kernel command line parameters:

systemd.gpt_auto, rd.systemd.gpt_auto

Those options take an optional boolean argument, and default to yes. The generator is enabled by default, and a false value may be used to disable it (e.g. "systemd.gpt_auto=0").

Added in version 242.

systemd.image_policy=

Takes an image dissection policy string as argument (as per systemd.image-policy(7)), and allows enforcing a policy on dissection and use of the automatically discovered GPT partition table entries.

Note that the specified image policy is not taken into account for automatic root or /usr/ file system discovery unless root=dissect/mount.usr=dissect (or root=dissect-force) are specified. (The policy will always be applied to the other auto-discoverable partition types.)

Added in version 254.

systemd.image_filter=

Takes an image dissection filter string as argument (as per systemd.image-filter(7)), and allows enforcing a set of globbing patterns on the partition matching of the automatically discovered GPT partition table entries.

Note that the specified image filter is not taken into account for automatic root or /usr/ file system discovery unless root=dissect/mount.usr=dissect (or root=dissect-force) are specified. (The filter will always be applied to the other auto-discoverable partition types.)

Added in version 258.

root=, rootfstype=, rootflags=

When root= is used with the special value "gpt-auto", basic automatic discovery of the root partition based on the GPT partition type is enabled. Use of the root partition is delayed until factory reset mode is left, in case it is enabled during the current boot. See Factory Reset[5] for more information on that. If "gpt-auto-force" is specified automatic discovery of the root partition is enabled, ignoring any factory reset mode.

If root= is set to the special value "dissect" full automatic discovery of the root partition based on GPT partition information is enabled. This is a superset of root=gpt-auto, as it automatically configures Verity partitions (including signature-based setup) following the logic defined for that in the Discoverable Partitions Specification[6]. Moreover it takes the configured image policy and image filter into account for all partition types, including the root file system. "root=dissect" will wait for the factory reset phase to be completed if it is in effect before activating the root file system. Use "root=dissect-force" to ignore the factory reset phase and activate the root file system immediately.

Any other value (i.e. besides "gpt-auto", "gpt-auto-force", "dissect", "dissect-force") disables automatic root file system discovery.

If root= is not specified at all on the kernel command line automatic discovery of the root partition via the ESP reported by the boot loader is also enabled (taking factory reset state into account, i.e. equivalent to "root=gpt-auto"), however in this case discovery based on the loopback block device ".lo_name" field is not enabled.

The rootfstype= and rootflags= options are used to select the file system type and options when the root file system is automatically discovered.

Added in version 242.

mount.usr=, mount.usrfstype=, mount.usrflags=

Similar to root=, rootfstype=, rootflags= (see above), but applies to the /usr/ partition instead. Note that the "gpt-auto", "gpt-auto-force", "dissect-force" settings that root= understands are not supported by mount.usr= (however "dissect" is).

Also note that automatic partition discovery for /usr/ must be enabled explicitly, unlike the discovery for the root file system, which is enabled if no root= parameter is passed at all.

Added in version 258.

rw, ro

Mount the root partition read-write or read-only initially.

Note that unlike most kernel command line options these settings do not override configuration in the file system, and the file system may be remounted later. See systemd-remount-fs.service(8).

Added in version 242.

systemd.swap=

Takes a boolean argument or enables the option if specified without an argument. If disabled, automatic discovery of swap partition(s) based on GPT partition type is disabled. Defaults to enabled.

Added in version 254.

NAME

systemd-gpt-auto-generator - Automatically mount partitions based on GPT partition type UUIDs

SYNOPSIS

systemd-gpt-auto-generator

DESCRIPTION

The systemd-gpt-auto-generator utility is a systemd-generator that activates early in the boot process. It scans the available block devices for partitions marked with specific GPT partition type UUIDs, and creates corresponding .mount units for them.

This mechanism allows for automatic mounting of partitions that are designated for specific purposes, such as the root file system, home directories, or temporary storage, without requiring manual configuration in fstab(5).

The generator recognizes the following GPT partition type UUIDs:

  • 7233f551-1c4f-4004-9c41-0880513671f2 (Linux filesystem): Used for general Linux file systems.

  • 0605a307-e723-40e7-8c5a-8c0113a18a34 (Linux swap): Used for Linux swap partitions.

  • 521e8472-7559-4927-bf2d-113870257647 (Linux LVM): Used for Linux Logical Volume Manager (LVM) physical volumes.

  • b921402a-1c73-4399-892d-773165900c16 (Linux RAID): Used for Linux software RAID partitions.

  • a19d880f-05fc-4d3b-a006-743f0f84911e (Linux LUKS): Used for Linux Unified Key Setup (LUKS) encrypted partitions.

  • 4449e684-0513-4721-9c3c-2896b4e6b402 (EFI System Partition): Used for EFI System Partitions (ESPs).

When a partition with one of these UUIDs is detected, systemd-gpt-auto-generator creates a systemd unit file in memory (e.g., .mount, .swap) that describes how to mount or activate the partition. These units are then processed by systemd during the boot process.

For example, a partition with the GPT type UUID 7233f551-1c4f-4004-9c41-0880513671f2 and the label "ROOT" would result in a systemd-root.mount unit being created, which systemd would then use to mount the partition as the root file system.

KERNEL COMMAND LINE

The behavior of systemd-gpt-auto-generator can be influenced by kernel command line parameters. For instance, the root= parameter can be used to specify the root file system, which may override or complement the automatic GPT partition discovery.

SEE ALSO

systemd(1), fstab(5), systemd.unit(5), systemd.mount(5), gdisk(8)

NOTES

This generator is typically enabled by default. If it is disabled, partitions with the recognized GPT partition type UUIDs will not be automatically mounted or activated.

The specific GPT partition type UUIDs recognized by this generator might be extended in future versions of systemd.
