SYSTEMD-JOURNAL-REMOTE.SERVICE(8) systemd-journal-remote.service SYSTEMD-JOURNAL-REMOTE.SERVICE(8)

NOMBRE

systemd-journal-remote.service, systemd-journal-remote.socket, systemd-journal-remote - Recibir mensajes del journal a través de la red

SINOPSIS

systemd-journal-remote.service

systemd-journal-remote.socket

/usr/lib/systemd/systemd-journal-remote [OPCIONES...] [-o/--output=DIR|ARCHIVO] [FUENTES...]

DESCRIPCIÓN

systemd-journal-remote es un comando para recibir eventos del journal serializados y almacenarlos en archivos del journal. Las corrientes de entrada están en el Formato de Exportación del Journal[1], es decir, similar a la salida de journalctl --output=export. Para el transporte a través de la red, esta corriente serializada generalmente se transporta a través de una conexión HTTPS.

systemd-journal-remote.service es un servicio del sistema que utiliza systemd-journal-remote para escuchar conexiones. systemd-journal-remote.socket configura la dirección de red en la que escucha systemd-journal-remote.service. Por defecto, es el puerto 19532. Qué conexiones se aceptan y cómo se almacenan los datos recibidos se puede configurar a través del archivo de configuración journal-remote.conf(5).

FUENTES

Las fuentes pueden ser "activas" (systemd-journal-remote solicita y extrae los datos), o "pasivas" (systemd-journal-remote espera una conexión y luego recibe eventos enviados por el otro lado).

systemd-journal-remote puede leer más de una corriente de eventos a la vez. Se intercalarán en el archivo de salida. En el caso de conexiones "activas", cada "fuente" es una corriente, y en el caso de conexiones "pasivas", cada conexión puede resultar en una corriente separada. Los sockets se pueden configurar en modo "accept" (es decir, solo una conexión), o modo "listen" (es decir, múltiples conexiones, cada una resultando en una corriente).

Cuando no quedan más conexiones y no se pueden crear más (no hay sockets de escucha), entonces systemd-journal-remote saldrá.

Las fuentes activas se pueden especificar de las siguientes maneras:

[FUENTES]

Cuando se da - como argumento posicional, los eventos se leerán de la entrada estándar. Otros argumentos posicionales se tratarán como nombres de archivo para abrir y leer.

Añadido en la versión 239.

--url=DIRECCIÓN

Con la opción --url=DIRECCIÓN, los eventos se recuperarán usando HTTP desde DIRECCIÓN. Esta URL debe referirse a la raíz de una instancia remota de systemd-journal-gatewayd(8), por ejemplo, http://some.host:19531/ o https://some.host:19531/.

Añadido en la versión 239.

--getter='PROG [OPCIONES]'

Programa a invocar para recuperar datos. La corriente de eventos del journal debe generarse en la salida estándar.

Ejemplos:

--getter='curl "-HAccept: application/vnd.fdo.journal" https://some.host:19531/'
--getter='wget --header="Accept: application/vnd.fdo.journal" -O- https://some.host:19531/'

Añadido en la versión 239.

Las fuentes pasivas se pueden especificar de las siguientes maneras:

--listen-raw=DIRECCIÓN

DIRECCIÓN debe ser una dirección adecuada para ListenStream= (ver systemd.socket(5)). systemd-journal-remote escuchará en este socket las conexiones. Se espera que cada conexión sea una corriente de eventos del journal.

Añadido en la versión 239.

--listen-http=DIRECCIÓN, --listen-https=DIRECCIÓN

DIRECCIÓN debe ser un entero negativo, en cuyo caso se interpretará como el número de descriptor de archivo (negado), o una dirección adecuada para ListenStream= (ver systemd.socket(5)). En el primer caso, el servidor escucha en el puerto 19532 por defecto, y el descriptor de archivo coincidente debe ser heredado a través de $LISTEN_FDS/$LISTEN_PID. En el segundo caso, se iniciará un servidor HTTP o HTTPS en este puerto, respectivamente para --listen-http= y --listen-https=. Actualmente, solo se admiten solicitudes POST a /upload con "Content-Type: application/vnd.fdo.journal".

Añadido en la versión 239.

$LISTEN_FDS

systemd-journal-remote admite el protocolo $LISTEN_FDS/$LISTEN_PID. Los sockets abiertos heredados a través de la activación de sockets se comportan como los abiertos con --listen-raw= descritos anteriormente, a menos que se especifiquen como argumento en --listen-http=-n o --listen-https=-n anteriormente. En este último caso, se iniciará un servidor HTTP o HTTPS utilizando este descriptor y las conexiones deben realizarse a través del protocolo HTTP.

Añadido en la versión 239.

--key=

Toma una ruta a un archivo de clave secreta SSL en formato PEM. Por defecto es /etc/ssl/private/journal-remote.pem. Esta opción se puede utilizar con --listen-https=. Si la ruta se refiere a un socket de corriente AF_UNIX en el sistema de archivos, se establece una conexión a él y se lee la clave desde él.

Añadido en la versión 239.

--cert=

Toma una ruta a un archivo de certificado SSL en formato PEM. Por defecto es /etc/ssl/certs/journal-remote.pem. Esta opción se puede utilizar con --listen-https=. Si la ruta se refiere a un socket de corriente AF_UNIX en el sistema de archivos, se establece una conexión a él y se lee el certificado desde él.

Añadido en la versión 239.

--trust=

Toma una ruta a un archivo de certificado CA SSL en formato PEM, o all. Si se establece all, la comprobación del certificado se deshabilitará. Por defecto es /etc/ssl/ca/trusted.pem. Esta opción se puede utilizar con --listen-https=. Si la ruta se refiere a un socket de corriente AF_UNIX en el sistema de archivos, se establece una conexión a él y se lee el certificado desde él.

Añadido en la versión 239.

--gnutls-log=

Toma una lista separada por comas de categorías de registro de gnutls. Esta opción se puede utilizar con --listen-http= o --listen-https=.

Añadido en la versión 239.

SUMIDEROS

La ubicación del journal de salida se puede especificar con -o o --output=.

-o ARCHIVO, --output=ARCHIVO

Escribirá en este archivo del journal. El nombre del archivo debe terminar en .journal. El archivo se creará si no existe. Si es necesario (el archivo del journal está lleno o dañado), el archivo se renombrará siguiendo las reglas normales de journald y se creará un nuevo archivo del journal en su lugar.

Añadido en la versión 239.

-o DIR, --output=DIR

Creará archivos del journal dentro del directorio DIR. El directorio debe existir. Si es necesario (los archivos del journal superan el tamaño o están dañados), los archivos del journal se rotarán siguiendo las reglas normales de journald. Los nombres de los archivos dentro de DIR se generarán utilizando las reglas descritas a continuación.

Añadido en la versión 239.

Si no se utiliza --output=, se utilizará el directorio de salida /var/log/journal/remote/. En caso de que no se especifique el archivo de salida, se crearán archivos del journal dentro del directorio seleccionado. Los archivos se llamarán remote-hostname.journal, donde la parte hostname es el nombre de host escapado del punto final de la conexión, o la dirección numérica si no se puede determinar el nombre de host.

En el caso de que las fuentes "activas" se proporcionen mediante argumentos posicionales o la opción --getter=, el nombre del archivo de salida debe proporcionarse siempre explícitamente.

OPCIONES

Se admiten las siguientes opciones:

--split-mode

Una de none o host. Para la primera, solo se utiliza un archivo de journal de salida. Para la segunda, se utiliza un archivo de salida separado, basado en el nombre de host del otro punto final de una conexión.

systemd-journal-remote.service(8)

NAME

systemd-journal-remote.service, systemd-journal-remote - Forward journal messages to a remote system

SYNOPSIS

systemd-journal-remote [-n | --log-limit=BOOL] [-f | --follow-journal=BOOL] [-o | --output=FILE] [-c | --compress=BOOL] [-s | --seal=BOOL] [-h | --help] [--version]

systemd-journal-remote --url=URL [-n | --log-limit=BOOL] [-f | --follow-journal=BOOL] [-o | --output=FILE] [-c | --compress=BOOL] [-s | --seal=BOOL] [-h | --help] [--version]

DESCRIPTION

systemd-journal-remote is a service that listens for journal messages from remote hosts (via the systemd-journal-gatewayd.service(8) service) or reads journal messages from local journal files and forwards them to a local journal file or to a remote system via HTTP/S.

It understands two main operating modes:

  • Receiving mode: In this mode, systemd-journal-remote is configured to listen on a specific URL. It fetches journal entries from a systemd-journal-gatewayd.service(8) instance. See SOURCES.
  • Sending mode: In this mode, systemd-journal-remote reads journal entries from standard input (in journal export format) and writes them to a local journal file. See SINKS.

The service may be configured via the systemd-journal-remote.conf(5) man page.

The service is typically started by systemd-journal-gatewayd.service(8) if it is configured to relay journal messages to a remote server.

SOURCES

When operating in receiving mode, the source for journal entries is specified using the --url= option. The URL should point to a systemd-journal-gatewayd.service(8) instance. The following URL parameters are supported:

boot
Only include entries from the current boot.
follow
Continuously listen for new entries.
since=TIMESTAMP
Only include entries since the specified timestamp. The timestamp should be in the format accepted by journalctl(1).
until=TIMESTAMP
Only include entries until the specified timestamp. The timestamp should be in the format accepted by journalctl(1).
field=FIELD=VALUE
Filter entries by a specific field and value.

Multiple parameters can be combined by separating them with ampersands (&).

SINKS

When operating in sending mode, the sink for journal entries is specified using the --output= option. The output file must be in the journal export format. The special value none can be used to discard the output.

OPTIONS

The following options are understood:

-n, --log-limit=[BOOL]

If this is set to "yes" then the journal entries will be limited by size. The default is "yes".

-f, --follow-journal=[BOOL]

If this is set to "yes" then the journal entries will be appended. The default is "yes".

-o, --output=FILE

Write the journal entries to the specified file. If this is set to none then all journal entries are discarded. When using the --url= option, the output file name must always be given explicitly and only none is allowed.

Added in version 239.

--compress [BOOL]

If this is set to "yes" then compress the data in the journal using XZ. The default is "yes".

Added in version 239.

--seal [BOOL]

If this is set to "yes" then periodically sign the data in the journal using Forward Secure Sealing. The default is "no".

Added in version 239.

-h, --help

Print a short help text and exit.

--version

Print a short version string and exit.

EXAMPLES

Copy local journal events to a different journal directory:

journalctl -o export | systemd-journal-remote -o /tmp/dir/foo.journal -

Retrieve all available events from a remote systemd-journal-gatewayd(8) instance and store them in /var/log/journal/remote/remote-some.host.journal:

systemd-journal-remote --url http://some.host:19531/

Retrieve current boot events and wait for new events from a remote systemd-journal-gatewayd(8) instance, and store them in /var/log/journal/remote/remote-some.host.journal:

systemd-journal-remote --url http://some.host:19531/entries?boot&follow

SEE ALSO

journal-remote.conf(5), journalctl(1), systemd-journal-gatewayd.service(8), systemd-journal-upload.service(8), systemd-journald.service(8)
