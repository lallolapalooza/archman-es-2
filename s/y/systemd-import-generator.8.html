SYSTEMD-IMPORT-GENERATOR(8) systemd-import-generator SYSTEMD-IMPORT-GENERATOR(8)

NOMBRE

systemd-import-generator - Generador para descargar automáticamente imágenes de disco al arrancar

SINOPSIS

/usr/lib/systemd/system-generators/systemd-import-generator

DESCRIPCIÓN

systemd-import-generator se puede utilizar para descargar automáticamente imágenes de disco (tarballs o DDIs) a través de systemd-importd.service(8) al arrancar, basándose en parámetros de la línea de comandos del kernel o a través de credenciales del sistema. Esto es útil para desplegar automáticamente una systemd-confext(8), systemd-sysext(8), systemd-nspawn(1)/ systemd-vmspawn(1) o systemd-portabled.service(8) imagen al arrancar. Esto proporciona funcionalidad equivalente a importctl(1), pero accesible a través de la línea de comandos del kernel y las credenciales del sistema.

systemd-import-generator implementa systemd.generator(7).

LÍNEA DE COMANDOS DEL KERNEL

systemd-import-generator entiende los siguientes parámetros de kernel-command-line(7):

systemd.pull=

Esta opción toma un triplete separado por dos puntos de una cadena de opciones, nombre de imagen de destino local y URL remota. El nombre de imagen de destino local puede especificarse como una cadena vacía, en cuyo caso el nombre se deriva de la URL remota especificada. La URL remota debe usar los esquemas "http://", "https://", "file://". La cadena de opciones en sí misma es una lista de opciones separadas por comas:

rw, ro

Controla si la imagen local se marca como de solo lectura. Si no se especifica, la opción de solo lectura está desactivada por defecto.

Añadido en la versión 257.

verify=

Controla si se valida criptográficamente la descarga antes de instalarla. Toma uno de los valores "no", "checksum" o "signature" (por defecto si no se especifica). Para más detalles, consulte el argumento --verify= de importctl(1).

Añadido en la versión 257.

sysext, confext, machine, portable

Controla la clase de imagen a descargar, y por lo tanto, en última instancia, el directorio de destino para la imagen, dependiendo de esta elección se selecciona el directorio de destino /var/lib/extensions/, /var/lib/confexts/, /var/lib/machines/ o /var/lib/portables/.

La especificación de exactamente una de estas opciones es obligatoria.

Añadido en la versión 257.

tar, raw

Controla el tipo de recurso a descargar, es decir, un tarball (posiblemente comprimido) que necesita ser desempaquetado en un árbol de sistema de archivos, o una imagen de disco cruda (DDI) (posiblemente comprimida).

La especificación de exactamente una de estas opciones es obligatoria.

Añadido en la versión 257.

blockdev

Si se especifica esta opción, la imagen descargada se adjunta a un dispositivo de bloque de loopback (a través de systemd-loop@.service) después de su finalización. Esto permite arrancar desde imágenes de disco descargadas. Esto solo se admite para imágenes de disco "raw".

Tenga en cuenta que cuando se utiliza esta opción con el propósito de montar una imagen de disco que cumpla con la Discoverable Disk Image Specification[1], y la lógica automática de descubrimiento de particiones GPT implementada por systemd-gpt-auto-generator(8) debe procesarla, es esencial especificar "rootdisk" como el nombre local para la importación. Además, se debe especificar explícitamente "root=gpt-auto" en la línea de comandos del kernel. Además, prefije la opción de línea de comandos "systemd.pull=" con "rd." para asegurar que se ejecute en el disco RAM inicial (initrd) ya, véase también más abajo.

Añadido en la versión 258.

bootorigin

Si se especifica esta opción, en lugar de la URL se puede especificar un simple nombre de archivo. Si el sistema arranca a través del arranque de red HTTP de UEFI, el último componente de la URL de origen de arranque de red se reemplaza por este nombre de archivo y se utiliza como fuente de descarga. Esto permite, por lo tanto, juntar automáticamente las URL de las imágenes de disco a partir de la URL de arranque original utilizada para invocar el kernel o el cargador de arranque.

Si se utiliza esta opción y el sistema no está arrancando realmente a través del arranque de red HTTP de UEFI, la descarga se omite de forma elegante. O en otras palabras, sin otras modificaciones, es posible armar una imagen initrd que arranque desde un disco local si está disponible, o desde una imagen de disco descargada si se utiliza a través del arranque de red.

Añadido en la versión 258.

runtime=

Toma un argumento booleano. Si se establece en true, la imagen se descarga debajo de la jerarquía /run/, si se establece en false debajo de la jerarquía /var/lib/. Si no se especifica, por defecto es true en el disco RAM inicial (initrd) y false en el sistema anfitrión.

Añadido en la versión 258.

Añadido en la versión 257.

systemd.pull.success_action=, systemd.pull.failure_action=

Controla si se ejecuta una acción como reinicio, apagado y similares después de completar la descarga con éxito o sin éxito. Consulte SuccessAction=/FailureAction= en systemd.unit(5) para obtener detalles sobre las acciones disponibles. Si no se especifica, no se realiza ninguna acción y el sistema continuará arrancando normalmente.

Añadido en la versión 257.

Estas opciones de línea de comandos del kernel son interpretadas solo por el sistema anfitrión. Si estas opciones se prefijan con "rd.", son interpretadas por el disco RAM inicial (initrd) en su lugar.

CREDENCIALES

systemd-import-generator soporta la lógica de credenciales del sistema. Las siguientes credenciales se utilizan cuando se pasan:

import.pull

Esta credencial debe ser un archivo de texto, con cada línea haciendo referencia a una operación de descarga. Cada línea debe seguir el mismo formato que el valor de la opción de línea de comandos del kernel systemd.pull= descrita anteriormente.

Añadido en la versión 257.

EJEMPLOS

Ejemplo 1. Descargar Extensión de Configuración 

systemd.pull=raw,confext::https://example.com/myconfext.raw.gz

Con una opción de línea de comandos del kernel como la anterior, se descarga automáticamente una DDI de extensión de configuración al arrancar desde la URL especificada, se valida criptográficamente, se descomprime y se instala.

Ejemplo 2. Descargar Extensión del Sistema (Sin Validación)

systemd.pull=tar,sysext,verify=no::https://example.com/mysysext.tar.gz

Con una opción de línea de comandos del kernel como la anterior, se descarga automáticamente un tarball de extensión del sistema al arrancar desde la URL especificada, se descomprime y se instala – sin ninguna validación criptográfica. Esto es útil para fines de desarrollo en máquinas virtuales y contenedores. ¡Advertencia: no implemente un sistema con validación deshabilitada de esta manera!

Ejemplo 3. Descargar imagen de disco raíz (raw) en memoria, para arrancar desde ella

rd.systemd.pull=raw,machine,verify=no,blockdev:image:https://example.com/image.raw.xz root=/dev/disk/by-loop-ref/image.raw-part2

Esto descarga la imagen de disco especificada, la guarda localmente con el nombre "image", y la adjunta a un dispositivo de bloque de loopback al finalizar. Luego arranca desde la partición 2 de la imagen.

Ejemplo 4. Arrancar desde imagen de disco (raw), con URL derivada del arranque de red HTTP de UEFI

rd.systemd.pull=raw,machine,verify=no,blockdev,bootorigin:rootdisk:image.raw.xz root=gpt-auto

Esto es similar al ejemplo anterior, pero esta vez la URL de origen se deriva automáticamente de la URL de arranque de red HTTP de UEFI. Por ejemplo, si se arranca una UKI desde una URL "http://example.com/image.efi", esto resultaría en una descarga de disco raíz desde "http://example.com/image.raw.xz". Además, esto utiliza el systemd-gpt-auto-gen

systemd-import-generator(8) — systemd manual

NAME

systemd-import-generator — Disk image import generator

SYNOPSIS

systemd-import-generator [‑directory=path] [‑type=type]

DESCRIPTION

systemd-import generator for importing disk images.

This generator is triggered by kernel command line parameters starting with root= or root=bind. It is used to mount the root file system from a disk image. The disk image can be a raw disk image (block device) or a tarball. The location of the disk image can be specified via kernel command line parameters, or it can be discovered via Discoverable Disk Image Specification.

When root=bind:/run/machines/root is used, systemd-import-generator will attempt to mount an imported disk image located at /run/machines/root. This is commonly used when booting an OS from a disk image. The disk image itself must be imported prior to booting, for example, using systemd-importd.service or importctl.

KERNEL COMMAND LINE

The generator uses the following kernel command line parameters:

‘root=’
Specifies the root device or image.
‘root=LABEL=...’
Mounts the specified label.
‘root=/dev/...’
Mounts the specified block device.
‘root=bind:/path/to/image’
Mounts the specified path as the root. This can be a raw disk image file or a tarball. If it is a tarball, it will be unpacked into a temporary directory and then mounted.
‘rootfstype=’
Specifies the filesystem type of the root device. If not specified, it will be inferred.
‘rootflags=’
Specifies mount options for the root filesystem.
‘root.mount=’
Specifies an alternative mount point for the root filesystem. Defaults to /.
‘root.system-credentials=’
Specifies a path to a system credentials file to be used for unlocking encrypted root filesystems. See systemd.system-credentials(7).
‘systemd.importd.mount=’
Specifies the mount point for imported disk images. Defaults to /run/machines.
‘systemd.gpt-auto-generator.realm=’
Specifies the realm for GPT disk image discovery. Defaults to machine. See systemd-gpt-auto-generator(8).

CREDENTIALS

If the root filesystem is encrypted, the necessary credentials can be provided via the root.system-credentials= kernel command line parameter, pointing to a file that follows the format described in systemd.system-credentials(7).

EXAMPLES

Example 1. Boot into a raw disk image from a block device

rd.systemd.pull=raw,bootorigin:root:/dev/sda1 root=bind:/run/machines/root

This example boots the system from a raw disk image located on /dev/sda1. The rd.systemd.pull=raw parameter tells the generator to expect a raw disk image. bootorigin:root:/dev/sda1 specifies the source of the image. The image will be mounted at /run/machines/root, and this directory will become the new root filesystem.

Example 2. Boot into a tarball from a URL

rd.systemd.pull=tar,machine,verify=no,bootorigin:root:http://example.com/root.tar.xz root=bind:/run/machines/root

This example boots the system from a tarball downloaded from a URL. rd.systemd.pull=tar indicates a tarball image. bootorigin:root:http://example.com/root.tar.xz specifies the URL of the tarball. verify=no disables signature verification. The tarball will be unpacked into a temporary directory and mounted as the root filesystem at /run/machines/root.

Example 3. Boot using GPT disk image discovery

root=bind:/run/machines/root systemd.gpt-auto-generator.realm=machine

This example relies on the systemd-gpt-auto-generator(8) to discover and mount a disk image based on GPT partition labels. The disk image is expected to be mounted at /run/machines/root and then used as the root filesystem.

Example 4. Boot into a disk image with system credentials

rd.systemd.pull=raw,bootorigin:root:/dev/sda1 root=bind:/run/machines/root root.system-credentials=/etc/cryptsetup-keys.d/root.key

This is similar to Example 1, but includes the root.system-credentials parameter. This is useful if the disk image on /dev/sda1 is encrypted and requires a key file located at /etc/cryptsetup-keys.d/root.key to be unlocked. The generator uses the systemd-gpt-auto-generator(8) logic to mount the root file system from the disk image.

Example 5. Boot into disk image (tar), with URL derived from UEFI HTTP network booting

rd.systemd.pull=tar,machine,verify=no,bootorigin:root:image.tar.xz root=bind:/run/machines/root

This is similar to the previous example, but instead of a raw (i.e. block device based) disk image the system boots into a tarball that is downloaded from the originating UEFI network server.
