NOMBRE

systemd-tmpfiles, systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service, systemd-tmpfiles-clean.timer - Crear, eliminar y limpiar archivos y directorios

SINOPSIS

systemd-tmpfiles [OPCIONES...] [ARCHIVO_CONFIG...]

Unidades del sistema:

systemd-tmpfiles-setup.service
systemd-tmpfiles-setup-dev-early.service
systemd-tmpfiles-setup-dev.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

Unidades de usuario:

systemd-tmpfiles-setup.service
systemd-tmpfiles-clean.service
systemd-tmpfiles-clean.timer

DESCRIPCIÓN

systemd-tmpfiles crea, elimina y limpia archivos y directorios, utilizando el formato de archivo de configuración y la ubicación especificados en tmpfiles.d(5). Históricamente, fue diseñado para administrar archivos volátiles y temporales, como sugiere el nombre, pero proporciona funcionalidad genérica de gestión de archivos y puede usarse para administrar cualquier tipo de archivo. Debe invocarse con uno o más comandos --create, --remove y --clean, para seleccionar el subconjunto respectivo de operaciones.

Si se invoca sin argumentos, se ejecutan las directivas de los archivos de configuración encontrados en los directorios especificados por tmpfiles.d(5). Cuando se invoca con argumentos posicionales, si se especifica la opción --replace=RUTA, se utilizan los argumentos especificados en la línea de comandos en lugar de la RUTA del archivo de configuración. De lo contrario, solo se ejecuta la configuración especificada por los argumentos de la línea de comandos. Si se especifica la cadena "-" en lugar de un nombre de archivo, la configuración se lee de la entrada estándar. Si el argumento es un nombre de archivo (sin barras), se buscan en todos los directorios de configuración un archivo coincidente y se ejecuta el archivo encontrado que tenga la mayor prioridad. Si el argumento es una ruta, se utiliza ese archivo directamente sin buscar en los directorios de configuración ningún otro archivo coincidente.

Los servicios del sistema (systemd-tmpfiles-setup.service, systemd-tmpfiles-setup-dev-early.service, systemd-tmpfiles-setup-dev.service, systemd-tmpfiles-clean.service) invocan a systemd-tmpfiles para crear archivos del sistema y realizar limpieza a nivel de sistema. Esos servicios leen archivos de configuración controlados por el administrador en los directorios tmpfiles.d/. Los servicios de usuario (systemd-tmpfiles-setup.service, systemd-tmpfiles-clean.service) también invocan a systemd-tmpfiles, pero leen un conjunto separado de archivos, que incluye archivos controlados por el usuario en ~/.config/user-tmpfiles.d/ y ~/.local/share/user-tmpfiles.d/, y archivos controlados por el administrador en /usr/share/user-tmpfiles.d/. Los usuarios pueden usar esto para crear y limpiar archivos bajo su control, pero la instancia del sistema realiza la limpieza global y no se ve influenciada por la configuración del usuario. Tenga en cuenta que esto significa que una limpieza basada en tiempo configurada en la instancia del sistema, como la que generalmente se configura para /tmp/, afectará también a los archivos creados por la instancia del usuario si se colocan en /tmp/, incluso si la limpieza basada en tiempo de la instancia del usuario está desactivada.

Para volver a aplicar la configuración después de haberla modificado, simplemente reinicie systemd-tmpfiles-clean.service, lo que aplicará cualquier configuración que pueda ejecutarse de forma segura en tiempo de ejecución. Para depurar systemd-tmpfiles, puede ser útil invocarlo directamente desde la línea de comandos con un nivel de registro aumentado (consulte $SYSTEMD_LOG_LEVEL a continuación).

COMANDOS Y OPCIONES

Se entienden los siguientes comandos:

--create

Si se pasa este comando, se crean o escriben todos los archivos y directorios marcados con f, F, w, d, D, v, p, L, c, b, m en los archivos de configuración. Los archivos y directorios marcados con z, Z, t, T, a y A tienen configurada su propiedad, modo de acceso y etiquetas de seguridad.

--clean

Si se pasa este comando, se limpian todos los archivos y directorios con un parámetro de antigüedad configurado.

--remove

Si se pasa este comando, se elimina el contenido de los directorios marcados con D o R, y los propios archivos o directorios marcados con r o R, a menos que se tome un bloqueo exclusivo o compartido de BSD sobre ellos (consulte flock(2)).

--purge

Si se pasa esta opción, se *eliminarán* todos los archivos y directorios declarados para su creación y marcados con el carácter "$" por los archivos tmpfiles.d/ especificados en la línea de comandos. Específicamente, esto actúa sobre todos los archivos y directorios marcados con f, F, d, D, v, q, Q, p, L, c, b, C, w, e. Si se utiliza este interruptor, debe especificarse al menos un archivo tmpfiles.d/ (o - para la entrada estándar) en la línea de comandos, o se rechazará la invocación, por motivos de seguridad (ya que de lo contrario se podrían eliminar muchos archivos del sistema instalados).

El caso de uso principal para esta opción es eliminar automáticamente archivos y directorios que originalmente se crearon en nombre de un paquete instalado en el momento de la eliminación del paquete.

Se recomienda ejecutar primero este comando en combinación con --dry-run (ver más abajo) para verificar qué archivos y directorios serán eliminados.

¡Advertencia! ¡Este no es el comando que suele querer! En la mayoría de los casos, --remove es lo que busca.

Añadido en la versión 256.

--user

Ejecuta la configuración de "usuario", es decir, archivos tmpfiles.d/ en directorios de configuración de usuario.

Añadido en la versión 236.

--boot

Ejecuta también las líneas con un signo de exclamación. Las líneas que no son seguras de ejecutar en un sistema en funcionamiento pueden marcarse de esta manera. systemd-tmpfiles se ejecuta en el arranque temprano con --boot especificado y ejecutará esas líneas. Cuando se invoca de nuevo más tarde, debería llamarse sin --boot.

Añadido en la versión 209.

--graceful

Ignora las líneas de configuración relativas a usuarios o grupos desconocidos. Esta opción está destinada a ser utilizada al inicio del arranque, antes de que se hayan creado todos los usuarios o grupos.

Añadido en la versión 254.

--dry-run

Procesa la configuración e imprime qué operaciones se realizarían, pero sin cambiar nada en el sistema de archivos.

Añadido en la versión 256.

--prefix=ruta

Aplica solo reglas con rutas que comiencen con el prefijo especificado. Esta opción se puede especificar varias veces.

Añadido en la versión 212.

--exclude-prefix=ruta

Ignora reglas con rutas que comiencen con el prefijo especificado. Esta opción se puede especificar varias veces.

Añadido en la versión 207.

-E

Un atajo para "--exclude-prefix=/dev --exclude-prefix=/proc --exclude-prefix=/run --exclude-prefix=/sys", es decir, excluye las jerarquías típicamente respaldadas por sistemas de archivos virtuales o de memoria. Esto es útil en combinación con --root=, si el árbol de directorios especificado contiene un árbol del sistema operativo sin estos sistemas de archivos virtuales/de memoria montados, ya que generalmente no es deseable crear archivos y directorios debajo de estos subdirectorios si se supone que serán sobremontados durante la ejecución.

Añadido en la versión 247.

--root=raíz

Toma una ruta de directorio como argumento. Todas las rutas se antepondrán con la ruta alternativa raíz dada, incluidas las rutas de búsqueda de configuración.

Cuando se utiliza esta opción, se omite el Switch de Nombre de Servicio (NSS) de libc para resolver usuarios y grupos. En su lugar, se leen directamente los archivos /etc/passwd y /etc/group dentro de la raíz alternativa. Esto significa que los usuarios/grupos no listados en estos archivos no se resolverán, es decir, no se considerarán bases de datos complejas como LDAP, NIS, etc.

Considere combinar esto con -E para asegurar que la invocación no cree archivos o directorios debajo de los puntos de montaje en la imagen del sistema operativo operado que típicamente se sobremontan durante la ejecución.

Añadido en la versión 212.

--imag

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

OPTIONS

--image=image

Toma una ruta a un archivo de imagen de disco o a un nodo de dispositivo de bloque. Si se especifica, todas las operaciones se aplicarán al sistema de archivos en la imagen de disco indicada. Esto es similar a --root= pero opera en sistemas de archivos almacenados en imágenes de disco o dispositivos de bloque. La imagen de disco debe contener solo un sistema de archivos o un conjunto de sistemas de archivos dentro de una tabla de particiones GPT, siguiendo la Especificación de Particiones Descubribles[1]. Para más información sobre imágenes de disco compatibles, consulta el modificador del mismo nombre en systemd-nspawn(1).

Implica -E.

Añadido en la versión 247.

--image-policy=policy

Toma una cadena de política de imagen como argumento, según systemd.image-policy(7). La política se aplica al operar en la imagen de disco especificada mediante --image=, ver arriba. Si no se especifica, el valor por defecto es la política "*", es decir, se utilizan todos los sistemas de archivos reconocidos en la imagen.

--replace=PATH

Cuando se proporciona esta opción, se deben especificar uno o más argumentos posicionales. Se leerán todos los archivos de configuración encontrados en los directorios listados en tmpfiles.d(5), y la configuración dada en la línea de comandos se manejará en lugar de y con la misma prioridad que el archivo de configuración PATH.

Esta opción está destinada a ser utilizada cuando se ejecutan scripts de instalación de paquetes y los archivos pertenecientes a ese paquete aún no están disponibles en disco, por lo que su contenido debe proporcionarse en la línea de comandos, pero la configuración del administrador puede existir y debe tener mayor prioridad.

Añadido en la versión 238.

--cat-config

Copia el contenido de los archivos de configuración a la salida estándar. Antes de cada archivo, el nombre del archivo se imprime como un comentario.

--tldr

Copia el contenido de los archivos de configuración a la salida estándar. Solo se imprimen las partes "interesantes" de los archivos de configuración, se omiten los comentarios y las líneas vacías. Antes de cada archivo, el nombre del archivo se imprime como un comentario.

--no-pager

No canalizar la salida a un paginador.

-h, --help

Imprime un texto de ayuda corto y sale.

--version

Imprime una cadena de versión corta y sale.

Es posible combinar --create, --clean y --remove en una sola invocación (en cuyo caso la eliminación y la limpieza se ejecutan antes de la creación de nuevos archivos). Por ejemplo, durante el arranque, la siguiente línea de comandos se ejecuta para asegurar que todos los directorios temporales y volátiles se eliminen y creen según el archivo de configuración:

systemd-tmpfiles --remove --create

CREDENTIALS

systemd-tmpfiles soporta la lógica de credenciales de servicio implementada por ImportCredential=/LoadCredential=/SetCredential= (ver systemd.exec(5) para detalles). Las siguientes credenciales se utilizan cuando se pasan:

tmpfiles.extra

El contenido de esta credencial puede contener líneas adicionales para operar. El contenido de la credencial debe seguir el mismo formato que cualquier otro archivo de configuración de tipo drop-in de tmpfiles.d/. Si se pasa esta credencial, se procesa después de todos los archivos drop-in leídos del sistema de archivos. Por lo tanto, las líneas de la credencial pueden aumentar las líneas existentes del sistema operativo, pero no anularlas.

Añadido en la versión 252.

Tenga en cuenta que, por defecto, el archivo de unidad systemd-tmpfiles-setup.service (y archivos de unidad relacionados) está configurado para heredar la credencial "tmpfiles.extra" del gestor de servicios.

ENVIRONMENT

$SYSTEMD_LOG_LEVEL

El nivel máximo de registro de los mensajes emitidos (los mensajes con un nivel de registro más alto, es decir, menos importantes, se suprimirán). Toma una lista de valores separados por comas. Un valor puede ser uno de (en orden de importancia decreciente) emerg, alert, crit, err, warning, notice, info, debug, o un entero en el rango 0...7. Ver syslog(3) para más información. Cada valor puede ir opcionalmente prefijado con uno de console, syslog, kmsg o journal seguido de dos puntos para establecer el nivel máximo de registro para ese destino de registro específico (por ejemplo, SYSTEMD_LOG_LEVEL=debug,console:info especifica registrar a nivel de depuración excepto cuando se registra en la consola, que debe estar a nivel de información). Tenga en cuenta que el nivel máximo de registro global tiene prioridad sobre cualquier nivel máximo de registro por destino.

$SYSTEMD_LOG_COLOR

Un booleano. Si es verdadero, los mensajes escritos en la tty se colorearán según la prioridad.

Esta configuración solo es útil cuando los mensajes se escriben directamente en la terminal, ya que journalctl(1) y otras herramientas que muestran registros colorearán los mensajes basándose en el nivel de registro por sí mismas.

$SYSTEMD_LOG_TIME

Un booleano. Si es verdadero, los mensajes de registro de la consola se prefijarán con una marca de tiempo.

Esta configuración solo es útil cuando los mensajes se escriben directamente en la terminal o en un archivo, ya que journalctl(1) y otras herramientas que muestran registros adjuntarán marcas de tiempo basándose en los metadatos de la entrada por sí mismas.

$SYSTEMD_LOG_LOCATION

Un booleano. Si es verdadero, los mensajes se prefijarán con un nombre de archivo y número de línea en el código fuente donde se origina el mensaje.

Tenga en cuenta que la ubicación del registro a menudo se adjunta como metadatos a las entradas del journal de todos modos. Incluirlo directamente en el texto del mensaje puede ser conveniente al depurar programas.

$SYSTEMD_LOG_TARGET

El destino para los mensajes de registro. Uno de console (registrar en la tty conectada), console-prefixed (registrar en la tty conectada pero con prefijos que codifican el nivel de registro y la "instalación", ver syslog(3), kmsg (registrar en el buffer de registro circular del kernel), journal (registrar en el journal), journal-or-kmsg (registrar en el journal si está disponible, y en kmsg en caso contrario), auto (determinar automáticamente el destino de registro apropiado, el predeterminado), null (desactivar la salida de registro).

$SYSTEMD_PAGER, $PAGER

Paginador a usar cuando no se especifica --no-pager. Se usa $SYSTEMD_PAGER si está configurado; de lo contrario, se usa $PAGER. Si ni $SYSTEMD_PAGER ni $PAGER están configurados, se intenta una serie de implementaciones de paginadores conocidos en orden, incluyendo less(1) y more(1), hasta que se encuentre uno. Si no se descubre ninguna implementación de paginador, no se invoca ningún paginador. Configurar estas variables de entorno a una cadena vacía o al valor "cat" es equivalente a pasar --no-pager.

Nota: si $SYSTEMD_PAGERSECURE no está configurado, $SYSTEMD_PAGER y $PAGER solo pueden usarse para deshabilitar el paginador (con "cat" o "" en cuyo caso se ignoran).

$SYSTEMD_LESS

Anula las opciones pasadas a less (por defecto "FRSXMK").

Los usuarios pueden querer cambiar dos opciones en particular:

K

Esta opción instruye al paginador a salir inmediatamente cuando se presiona Ctrl+C. Para permitir que less maneje Ctrl+C para volver al prompt del comando del paginador, desactive esta opción.

Si el valor de $SYSTEMD_LESS no incluye "K", y el paginador invocado es less, el ejecutable ignorará Ctrl+C y deberá ser manejado por el paginador.

X

Esta opción instruye al paginador a no enviar cadenas de inicialización y desinicialización de termcap a la terminal. Está configurado por defecto para permitir que la salida del comando permanezca visible en la terminal incluso después de que el paginador salga. Sin embargo, esto evita que funcione cierta funcionalidad del paginador, en particular la salida paginada no se puede desplazar con el ratón.

Tenga en cuenta que configurar la variable de entorno $LESS regular no tiene ningún efecto para las invocaciones de less por parte de las herramientas de systemd.

Ver less(1) para más discusión.

$SYSTEMD_LESSCHARSET

Anula el conjunto de caracteres pasado a less (por defecto "utf-8", si la terminal invocadora se determina compatible con UTF-8).

Tenga en cuenta que configurar la variable de entorno $LESSCHARSET regular no tiene ningún efecto para las invocaciones de less por parte de las herramientas de systemd.

$SYSTEMD_PAGERSECURE

Los comandos de paginador comunes como less(1), además de "paginar", es decir, desplazarse por la salida, soportan la apertura o escritura de otros archivos y la ejecución de comandos de shell arbitrarios. Cuando se invocan comandos con privilegios elevados, por ejemplo bajo sudo(8) o pkexec(1), el paginador se convierte en un límite de seguridad. Se debe tener cuidado de que solo se utilicen como paginadores programas con funcionalidad estrictamente limitada, y no se permitan características interactivas no deseadas como la apertura o creación de nuevos archivos o el inicio de subprocesos. El modo "seguro" para el paginador puede habilitarse como se describe a continuación, si el paginador lo soporta (la mayoría de los paginadores no están escritos de manera que tengan esto en cuenta). Se recomienda habilitar explícitamente el modo "seguro" o deshabilitar completamente el paginador usando --no-pager o PAGER=cat al permitir que usuarios no confiables ejecuten comandos con privilegios elevados.

Esta opción toma un argumento booleano. Cuando se establece en verdadero, se habilita el modo "seguro" del paginador. En modo "seguro", se establecerá LESSSECURE=1 al invocar el paginador, lo que instruye al paginador a deshabilitar comandos que abran o creen nuevos archivos o inicien nuevos subprocesos. Actualmente, solo se sabe que less(1) entiende esta variable e implementa el modo "seguro".

Cuando se establece en falso, no se impone ninguna limitación al paginador. Establecer SYSTEMD_PAGERSECURE=0 o no eliminarlo del entorno heredado puede permitir al usuario invocar comandos arbitrarios.

systemd-tmpfiles(8) — systemd manual

NAME

systemd-tmpfiles — manages temporary files and directories

SYNOPSIS

systemd-tmpfiles [--dry-run] [--remove] [--create] [--clean] [--prefix=PATH] [--exclude=PATH] [--all]

DESCRIPTION

systemd-tmpfiles is used to manage temporary files and directories. It reads configuration files from /usr/lib/tmpfiles.d/*.conf, /run/tmpfiles.d/*.conf, and /etc/tmpfiles.d/*.conf. The configuration files must be named after the package that installs them, using the .conf suffix. The files are processed in alphanumerical order. If several files specify settings for the same path, the settings from the file that comes later in this order take precedence.

Each configuration file consists of lines, and each line describes an action to be taken.

Empty lines and lines starting with # or ; are ignored.

The format of the configuration lines is:

TYPE PATH MODE UID GID AGE ARGUMENT

  • TYPE: The action to perform. One of the following:
    • w: Write the file. If the file or directory does not exist, it is created. If it exists and is a directory, the action fails. If it exists and is a file, its content is overwritten. The specified argument is written to the file. Only the first line starting with w for a specific file is honoured.
    • W: Like w, but fails if the file exists.
    • d: Create a directory. If the directory already exists, its metadata (mode, owner, group) is updated. The directory is only created if it doesn't exist.
    • D: Like d, but fails if the directory already exists.
    • r: Remove a file or directory, including its contents. Fails if the path does not exist.
    • R: Like r, but does not fail if the path does not exist.
    • l: Create a symbolic link named PATH pointing to ARGUMENT. Fails if PATH already exists.
    • L: Like l, but overwrites an existing symlink.
    • a: Remove file or directory contents. This is a non-recursive removal. For directories, only the immediate contents are removed. For files, the file is truncated to zero size. Fails if the path does not exist.
    • A: Like a, but does not fail if the path does not exist.
    • z: Set the mode, owner, and group. This action is also performed by d, D, r, R, l, L, a and A.
    • Z: Like z, but only updates the metadata if the path exists.
    The AGE column is only used for r, R, a and A types. It specifies the maximum age of files/directories to remove. The age is specified in days. If a file/directory is older than the specified age, it is removed. + may be prepended to the number to specify the minimum age. If the AGE column is empty, all files/directories are removed.
  • PATH: The path to operate on. May contain globbing patterns.
  • MODE: The file mode (permissions) in octal. If empty, the default is used.
  • UID: The user name or ID. If empty, the default is used.
  • GID: The group name or ID. If empty, the default is used.
  • AGE: The age in days. See above.
  • ARGUMENT: The argument for the action. See above.

Special file modes, owners, and groups can be specified using a leading +. For example, +i sets the immutable flag. For a full list, see man chattr.

The user and group may be specified as - to indicate that the corresponding value should not be set.

The PATH may contain specifiers like %t, %T, %m, %M, %h, %H, %v, %V, %u, %U, %g, %G, %l, %L, %k, %K, %o, %O, %p, %P, %s, %S, %n, %N, %i, %I, %e, %E, %d, %D, %r, %R, %a, %A, %z, %Z, %c, %C, %x, %X, %y, %Y, %f, %F, %b, %B, %j, %J, %q, %Q, %w, %W, %1, %2, %3, %4, %5, %6, %7, %8, %9, %0, %%. These specifiers are expanded based on the current date and time. See systemd.time(7) for a list of all supported specifiers.

COMMANDS AND OPTIONS

The following options are available:

‐‐dry-run
Only print what would be done, do not make any changes.
‐‐remove
Remove files and directories that are older than specified in the configuration. This is the default action.
‐‐create
Create files and directories that do not exist. This is the default action.
‐‐clean
Remove files and directories that are not mentioned in any of the configuration files. This is a dangerous operation and should be used with caution.
‐‐prefix=PATH
Only consider paths under PATH. This option can be given multiple times.
‐‐exclude=PATH
Do not consider paths matching PATH. This option can be given multiple times.
‐‐all
Process all configuration files, even those not marked with !systemd-tmpfiles. This is the default action.

CREDENTIALS

When running with elevated privileges, the systemd-tmpfiles utility might change file ownership and permissions. To limit the attack surface, it might be necessary to drop privileges. This is achieved by checking the $SUDO_UID environment variable set by sudo(8) or similar tools.

In those cases, $SYSTEMD_PAGERSECURE will be set to 1 and pagers which are not known to implement "secure mode" will not be used at all. Note that this autodetection only covers the most common mechanisms to elevate privileges and is intended as convenience. It is recommended to explicitly set $SYSTEMD_PAGERSECURE or disable the pager.

Note that if the $SYSTEMD_PAGER or $PAGER variables are to be honoured, other than to disable the pager, $SYSTEMD_PAGERSECURE must be set too.

ENVIRONMENT

$SYSTEMD_COLORS
Takes a boolean argument. When true, systemd and related utilities will use colors in their output, otherwise the output will be monochrome. Additionally, the variable can take one of the following special values: "16", "256" to restrict the use of colors to the base 16 or 256 ANSI colors, respectively. This can be specified to override the automatic decision based on $TERM and what the console is connected to.
$SYSTEMD_URLIFY
The value must be a boolean. Controls whether clickable links should be generated in the output for terminal emulators supporting this. This can be specified to override the decision that systemd makes based on $TERM and other conditions.

UNPRIVILEGED --CLEANUP OPERATION

systemd-tmpfiles tries to avoid changing the access and modification times on the directories it accesses, which requires CAP_FOWNER privileges. When running as non-root, directories which are checked for files to clean up will have their access time bumped, which might prevent their cleanup.

EXIT STATUS

On success, 0 is returned. If the configuration was syntactically invalid (syntax errors, missing arguments, ...), so some lines had to be ignored, but no other errors occurred, 65 is returned (EX_DATAERR from /usr/include/sysexits.h). If the configuration was syntactically valid, but could not be executed (lack of permissions, creation of files in missing directories, invalid contents when writing to /sys/ values, ...), 73 is returned (EX_CANTCREAT from /usr/include/sysexits.h). Otherwise, 1 is returned (EXIT_FAILURE from /usr/include/stdlib.h).

Note: when creating items, if the target already exists, but is of the wrong type or otherwise does not match the requested state, and forced operation has not been requested with "+", a message is emitted, but the failure is otherwise ignored.
