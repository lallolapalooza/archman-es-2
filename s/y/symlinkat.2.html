symlink(2) Manual de llamadas al sistema symlink(2)

NOMBRE

symlink, symlinkat - crear un nuevo nombre para un archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int symlink(const char *target, const char *linkpath);
#include <fcntl.h>           /* Definición de constantes AT_* */
#include <unistd.h>
int symlinkat(const char *target, int newdirfd, const char *linkpath);
Requisitos de macro de prueba de características para glibc (ver feature_test_macros(7)):

symlink():

    _XOPEN_SOURCE >= 500 || _POSIX_C_SOURCE >= 200112L
        || /* glibc <= 2.19: */ _BSD_SOURCE

symlinkat():

    Desde glibc 2.10:
        _POSIX_C_SOURCE >= 200809L
    Antes de glibc 2.10:
        _ATFILE_SOURCE

DESCRIPCIÓN

symlink() crea un enlace simbólico llamado linkpath que contiene la cadena target.

Los enlaces simbólicos se interpretan en tiempo de ejecución como si el contenido del enlace hubiera sido sustituido en la ruta que se está siguiendo para encontrar un archivo o directorio.

Los enlaces simbólicos pueden contener componentes de ruta .., los cuales (si se usan al principio del enlace) se refieren a los directorios padre del directorio donde reside el enlace.

Un enlace simbólico (también conocido como enlace suave) puede apuntar a un archivo existente o a uno inexistente; este último caso se denomina enlace colgante.

Los permisos de un enlace simbólico son irrelevantes; la propiedad se ignora al seguir el enlace (excepto cuando la característica protected_symlinks está habilitada, como se explica en proc(5)), pero se verifica al eliminar o renombrar el enlace y el enlace se encuentra en un directorio con el bit pegajoso (S_ISVTX) establecido.

Si linkpath existe, no se sobrescribirá.

symlinkat()

La llamada al sistema symlinkat() opera exactamente de la misma manera que symlink(), excepto por las diferencias descritas aquí.

Si la ruta de acceso dada en linkpath es relativa, se interpreta en relación con el directorio al que se refiere el descriptor de archivo newdirfd (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como hace symlink() para una ruta de acceso relativa).

Si linkpath es relativa y newdirfd es el valor especial AT_FDCWD, entonces linkpath se interpreta en relación con el directorio de trabajo actual del proceso que llama (como symlink()).

Si linkpath es absoluta, entonces se ignora newdirfd.

Ver openat(2) para una explicación de la necesidad de symlinkat().

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1, y errno se establece para indicar el error.

ERRORES

EACCES
Se deniega el acceso de escritura al directorio que contiene linkpath, o uno de los directorios en el prefijo de ruta de linkpath no permitió permisos de búsqueda. (Ver también path_resolution(7)).
EBADF
(symlinkat()) linkpath es relativa pero newdirfd no es ni AT_FDCWD ni un descriptor de archivo válido.
EDQUOT
La cuota del usuario de recursos en el sistema de archivos se ha agotado. Los recursos podrían ser inodos o bloques de disco, dependiendo de la implementación del sistema de archivos.
EEXIST
linkpath ya existe.
EFAULT
target o linkpath apunta fuera de su espacio de direcciones accesible.
EIO
Ocurrió un error de E/S.
ELOOP
Se encontraron demasiados enlaces simbólicos al resolver linkpath.
ENAMETOOLONG
target o linkpath era demasiado largo.
ENOENT
Un componente de directorio en linkpath no existe o es un enlace simbólico colgante, o target o linkpath es una cadena vacía.
ENOENT
(symlinkat()) linkpath es una ruta relativa y newdirfd se refiere a un directorio que ha sido eliminado.
ENOMEM
No había suficiente memoria del kernel disponible.
ENOSPC
El dispositivo que contiene el archivo no tiene espacio para la nueva entrada de directorio.
ENOTDIR
Un componente utilizado como directorio en linkpath no es, de hecho, un directorio.
ENOTDIR
(symlinkat()) linkpath es relativa y newdirfd es un descriptor de archivo que se refiere a un archivo que no sea un directorio.
EPERM
El sistema de archivos que contiene linkpath no admite la creación de enlaces simbólicos.
EROFS
linkpath está en un sistema de archivos de solo lectura.

ESTANDARES

POSIX.1-2024.

HISTORIA

symlink()
SVr4, 4.3BSD, POSIX.1-2001.
symlinkat()
POSIX.1-2008. Linux 2.6.16, glibc 2.4.

Notas de glibc

En kernels más antiguos donde symlinkat() no está disponible, la función de envoltura de glibc recurre al uso de symlink(). Cuando linkpath es una ruta relativa, glibc construye una ruta basada en el enlace simbólico en /proc/self/fd que corresponde al argumento newdirfd.

NOTAS

No se realiza ninguna comprobación de target.

Eliminar el nombre al que se refiere un enlace simbólico eliminará realmente el archivo (a menos que también tenga otros enlaces duros). Si este comportamiento no es deseado, use link(2).
