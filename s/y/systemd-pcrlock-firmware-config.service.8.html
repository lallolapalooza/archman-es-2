SYSTEMD-PCRLOCK(8) systemd-pcrlock SYSTEMD-PCRLOCK(8)

NOMBRE

systemd-pcrlock, systemd-pcrlock-file-system.service, systemd-pcrlock-firmware-code.service, systemd-pcrlock-firmware-config.service, systemd-pcrlock-machine-id.service, systemd-pcrlock-make-policy.service, systemd-pcrlock-secureboot-authority.service, systemd-pcrlock-secureboot-policy.service - Analiza y predice estados de PCR de TPM2 y genera una política de acceso a partir de la predicción

SINOPSIS

/usr/lib/systemd/systemd-pcrlock [OPCIONES...]

DESCRIPCIÓN

Nota: este comando es experimental por ahora. Si bien es probable que se convierta en un componente habitual de systemd, aún podría cambiar en su comportamiento e interfaz.

systemd-pcrlock es una herramienta que puede ser utilizada para analizar y predecir mediciones de PCR de TPM2, y generar políticas de acceso de TPM2 a partir de la predicción, la cual almacena en un índice NV de TPM2 (es decir, en la memoria no volátil de TPM2). Esto puede ser utilizado para restringir el acceso a objetos de TPM2 (como claves de cifrado de disco) a arranque de sistemas en los que solo se utilizan componentes específicos y confiables.

systemd-pcrlock utiliza como entrada para su análisis y predicción:

•El registro de eventos TPM2 del firmware UEFI (es decir, /sys/kernel/security/tpm0/binary_bios_measurements) del arranque actual.
•El registro de eventos TPM2 del espacio de usuario (es decir, /run/log/systemd/tpm2-measure.log) del arranque actual.
•El estado actual de los PCR del chip TPM2.
•Archivos de definición de componentes de arranque (*.pcrlock y *.pcrlock.d/*.pcrlock, ver systemd.pcrlock(5)) que definen mediciones esperadas para cada componente del proceso de arranque, permitiendo variantes alternativas para cada uno. (Las variantes pueden ser utilizadas para bendecir múltiples versiones de kernel o de gestor de arranque al mismo tiempo.)

Utiliza estas entradas para generar un registro de eventos combinado, validándolo contra los estados de los PCR. Luego intenta reconocer los registros del log de eventos y los compara con los componentes definidos. Para cada PCR donde esto se pueda hacer de manera exhaustiva (es decir, donde todos los registros listados y todos los componentes definidos hayan sido emparejados) se podrá predecir mediciones futuras de PCR, teniendo en cuenta las variantes alternativas definidas para cada componente. Esta predicción podrá ser convertida en una política de acceso de TPM2 (que consiste en elementos PolicyPCR y PolicyOR de TPM2), que luego se almacena en un índice NV en el TPM2. Esto podrá ser utilizado para bloquear secretos (como claves de cifrado de disco) a estas políticas (a través de una política PolicyAuthorizeNV de TPM2).

Utilice herramientas como systemd-cryptenroll(1) o systemd-repart(8) para vincular el cifrado de disco a una política de TPM2 de systemd-pcrlock de este tipo. Específicamente, vea los interruptores --tpm2-pcrlock= de estas herramientas.

La lógica de la política de acceso requiere un dispositivo TPM2 que implemente el comando "PolicyAuthorizeNV", es decir, que implemente TPM 2.0 versión 1.38 o posterior.

COMANDOS

Se entienden los siguientes comandos:

log

Lee el registro de eventos TPM2 combinado, lo valida, lo compara con los valores actuales de los PCR y muestra ambos en formato tabular. Combine con --json= para generar salida en formato JSON.

Añadido en la versión 255.

cel

Lee el registro de eventos TPM2 combinado y lo escribe a STDOUT en el Formato de Registro de Eventos Canónico de TCG (CEL-JSON)[1].

Añadido en la versión 255.

list-components

Muestra una lista de definiciones de componentes y sus variantes, es decir, los archivos *.pcrlock descubiertos en /var/lib/pcrlock.d/, /usr/lib/pcrlock.d/, y los otros directorios soportados. Ver systemd.pcrlock(5) para detalles sobre estos archivos y la lista completa de directorios buscados.

Añadido en la versión 255.

predict

Predice el estado de los PCR en arranques futuros. Analizará el registro de eventos TPM2 como se describe anteriormente, reconocerá los componentes y luego generará todos los valores de PCR resultantes posibles para todas las combinaciones de variantes de componentes. Tenga en cuenta que no se realiza ninguna predicción para los PCR cuyo valor no coincida con los registros del log de eventos, para los que se descubren mediciones no reconocidas o para los que se definen componentes que no se pueden encontrar en el log de eventos. Esto es una medida de seguridad para garantizar que cualquier política de acceso generada pueda cumplirse correctamente en arranques actuales y futuros.

Añadido en la versión 255.

make-policy

Predice el estado de los PCR para arranques futuros, de forma muy similar al comando predict anterior. Luego utiliza estos datos para generar una política de acceso de TPM2 que almacena en un índice NV de TPM2. La predicción y la información sobre el TPM2 utilizado y su índice NV se escriben en /var/lib/systemd/pcrlock.json.

El índice NV se asigna en la primera invocación y se actualiza en invocaciones posteriores.

El contenido del índice NV puede ser cambiado (y por lo tanto la política almacenada en él actualizada) proporcionando un PIN de acceso. Este PIN normalmente se genera automáticamente y se almacena en forma cifrada (con una política de acceso que lo vincula al propio índice NV) en el archivo JSON de política mencionado. Este PIN puede ser elegido por el usuario, a través del interruptor --recovery-pin=. Si se especifica, puede ser utilizado como vía alternativa de acceso para actualizar la política.

Si la nueva predicción coincide con la antigua, este comando termina rápidamente y no realiza ninguna operación adicional. (A menos que se especifique --force, ver más abajo.)

A partir de la versión 256, se codifica una copia del archivo de política /var/lib/systemd/pcrlock.json en una credencial (ver systemd-creds(1) para detalles) y se escribe en la partición EFI System Partition o XBOOTLDR, en el subdirectorio /loader/credentials/. Allí es recogida al arrancar por systemd-stub(7) y pasada al initrd invocado, donde puede ser utilizada para desbloquear el sistema de archivos raíz (que típicamente contiene /var/, que es donde se encuentra la copia principal de la política, la cual por lo tanto no puede ser utilizada para desbloquear el sistema de archivos raíz). El archivo de credencial se nombra según el token de entrada de arranque de la instalación (ver bootctl(1)), que es configurable a través del interruptor --entry-token=, ver más abajo.

Añadido en la versión 255.

remove-policy

Elimina una política generada previamente. Borra el archivo /var/lib/systemd/pcrlock.json y desasigna el índice NV.

Añadido en la versión 255.

is-supported

Comprueba si el TPM2 local soporta toda la funcionalidad para que systemd-pcrlock funcione correctamente. Realiza pruebas similares a systemd-analyze has-tpm2, pero también verifica el soporte de las operaciones de TPM2 requeridas por systemd-pcrlock. Muestra uno de "no", "partial" (en caso de que algunas partes del soporte de TPM2 estén disponibles en hardware, firmware, SO, pero no completas), "obsolete" (si el soporte de TPM2 está disponible en hardware, firmware y SO, pero faltan las operaciones requeridas para systemd-pcrlock), "yes". Devuelve un estado de salida de cero si el soporte completo está disponible, de lo contrario un valor distinto de cero.

Si se combina con --quiet, suprime la salida de la cadena.

Actualmente, esto comprueba el soporte para el comando TPM2 PolicyAuthorizeNV, así como el soporte del algoritmo de hash SHA-256.

Añadido en la versión 258.

lock-firmware-code, unlock-firmware-code

Genera/elimina archivos .pcrlock basados en el registro de eventos TPM2 del arranque actual que cubren todos los registros para los PCR 0 ("platform-code") y 2 ("external-code").

Esta operación permite bloquear el proceso de arranque a la versión actual del firmware del sistema y sus tarjetas de extensión. Esta operación solo debe usarse si el proveedor del sistema no proporciona datos pcrlock adecuados con antelación.

Tenga en cuenta que estos datos solo coinciden con la versión actual del firmware. Si se aplica una actualización de firmware, estos datos quedarán obsoletos y cualquier política de acceso generada a partir de ellos ya no será válida. Por lo tanto, se recomienda invocar unlock-firmware-code antes de realizar una actualización de firmware, seguido de make-policy para actualizar la política.

systemd-pcrlock lock-firmware-code se invoca automáticamente al arrancar a través de la unidad systemd-pcrlock-firmware-code.service, si está habilitada. COMMANDS

The following commands are understood:

lock-firmware-code, unlock-firmware-code

Genera/elimina un archivo .pcrlock basándose en el firmware de arranque actual. Esto es útil para predecir las mediciones que el firmware realiza en PCR 4 ("código de arranque") y PCR 5 ("configuración del cargador de arranque").

Este comando puede fallar y se puede omitir temporalmente para cubrir las actualizaciones de firmware, como se describe anteriormente.

Los archivos solo se generan a partir del registro de eventos si el registro de eventos coincide con el estado actual de PCR del TPM2.

Esto escribe/elimina los archivos /var/lib/pcrlock.d/250-firmware-code-early.pcrlock.d/generated.pcrlock y /var/lib/pcrlock.d/550-firmware-code-late.pcrlock.d/generated.pcrlock.

Añadido en la versión 255.

lock-firmware-config, unlock-firmware-config

Esto es similar a lock-firmware-code/unlock-firmware-code pero bloquea la configuración del firmware, es decir, PCRs 1 ("configuración de plataforma") y 3 ("configuración externa").

Esta funcionalidad debe usarse con cuidado, ya que en la mayoría de los escenarios un cambio menor en la configuración del firmware no debería invalidar las políticas de acceso a objetos TPM2. También tenga en cuenta que algunos sistemas miden información inestable e impredecible (por ejemplo, voltajes de CPU actuales, temperaturas, como parte de los datos SMBIOS) en estas PCRs, lo que significa que esta forma de bloqueo no se puede usar de forma fiable en tales sistemas. Utilice esta funcionalidad solo si el sistema y el hardware son bien conocidos y no sufren estas limitaciones, por ejemplo, en entornos virtualizados.

Utilice unlock-firmware-config antes de realizar cambios en la configuración del firmware. Si la unidad systemd-pcrlock-firmware-config.service está habilitada, generará automáticamente un archivo pcrlock a partir de las nuevas mediciones.

Esto escribe/elimina los archivos /var/lib/pcrlock.d/250-firmware-config-early.pcrlock.d/generated.pcrlock y /var/lib/pcrlock.d/550-firmware-config-late.pcrlock.d/generated.pcrlock.

Añadido en la versión 255.

lock-secureboot-policy, unlock-secureboot-policy

Genera/elimina un archivo .pcrlock basándose en la política SecureBoot aplicada actualmente. Esto examina las variables EFI de SecureBoot, PK, KEK, db, dbx, dbt, dbr y predice sus mediciones en la PCR 7 ("política de arranque seguro") en el próximo arranque.

Utilice unlock-firmware-config antes de aplicar actualizaciones de la política SecureBoot. Si la unidad systemd-pcrlock-secureboot-policy.service está habilitada, generará automáticamente un archivo pcrlock a partir de la política detectada.

Esto escribe/elimina el archivo /var/lib/pcrlock.d/230-secureboot-policy.pcrlock.d/generated.pcrlock.

Añadido en la versión 255.

lock-secureboot-authority, unlock-secureboot-authority

Genera/elimina un archivo .pcrlock basándose en las autoridades de arranque seguro utilizadas para validar la ruta de arranque. Las autoridades de arranque seguro son las entradas específicas de la base de datos de arranque seguro que se utilizaron para validar los binarios PE de UEFI ejecutados al arrancar. Esto examina el registro de eventos del arranque actual y utiliza mediciones relevantes en la PCR 7 ("política de arranque seguro").

Esto escribe/elimina el archivo /var/lib/pcrlock.d/620-secureboot-authority.pcrlock.d/generated.pcrlock.

Añadido en la versión 255.

lock-gpt [DISPOSITIVO], unlock-gpt

Genera/elimina un archivo .pcrlock basándose en la tabla de particiones GPT del disco especificado. Si no se especifica ningún disco, determina automáticamente el dispositivo de bloque que respalda el sistema de archivos raíz. Esto bloquea el estado de la partición del disco de arranque, que el firmware mide en la PCR 5 ("configuración del cargador de arranque").

Esto escribe/elimina el archivo /var/lib/pcrlock.d/600-gpt.pcrlock.d/generated.pcrlock.

Añadido en la versión 255.

lock-pe [BINARIO], unlock-pe

Genera/elimina un archivo .pcrlock basándose en el binario PE especificado. Esto es útil para predecir las mediciones que el firmware realiza en la PCR 4 ("código de arranque") si el binario especificado forma parte del proceso de arranque UEFI. Úselo en binarios del cargador de arranque y similares. Utilice lock-uki (ver más abajo) para binarios PE que son imágenes de kernel unificadas (UKI).

Espera una ruta al binario PE como argumento. Si no se especifica, lee el binario desde STDIN en su lugar.

El archivo pcrlock a escribir debe especificarse mediante el interruptor --pcrlock=.

Añadido en la versión 255.

lock-uki [UKI], unlock-uki

Genera/elimina un archivo .pcrlock basándose en el binario PE UKI especificado. Esto es útil para predecir las mediciones que el firmware realiza en la PCR 4 ("código de arranque"), y que systemd-stub(7) realiza en la PCR 11 ("arranque del kernel"), si se arranca la UKI especificada. Esto es un superconjunto de lock-pe.

Espera una ruta al binario PE UKI como argumento. Si no se especifica, lee el binario desde STDIN en su lugar.

El archivo pcrlock a escribir debe especificarse mediante el interruptor --pcrlock=.

Añadido en la versión 255.

lock-machine-id, unlock-machine-id

Genera/elimina un archivo .pcrlock basándose en /etc/machine-id. Esto es útil para predecir las mediciones que systemd-pcrmachine.service(8) realiza en la PCR 15 ("identidad del sistema").

Esto escribe/elimina el archivo /var/lib/pcrlock.d/820-machine-id.pcrlock.

Añadido en la versión 255.

lock-file-system [RUTA], unlock-file-system [RUTA]

Genera/elimina un archivo .pcrlock basándose en la identidad del sistema de archivos. Esto es útil para predecir las mediciones que systemd-pcrfs@.service(8) realiza en la PCR 15 ("identidad del sistema") para los sistemas de archivos raíz y /var/.

Esto escribe/elimina los archivos /var/lib/pcrlock.d/830-root-file-system.pcrlock y /var/lib/pcrlock.d/840-file-system-ruta.pcrlock.

Añadido en la versión 255.

lock-kernel-cmdline [ARCHIVO], unlock-kernel-cmdline

Genera/elimina un archivo .pcrlock basándose en /proc/cmdline (o el archivo especificado si se proporciona). Esto es útil para predecir las mediciones que el kernel de Linux realiza en la PCR 9 ("initrd del kernel").

Esto escribe/elimina el archivo /var/lib/pcrlock.d/710-kernel-cmdline.pcrlock/generated.pcrlock.

Añadido en la versión 255.

lock-kernel-initrd ARCHIVO, unlock-kernel-initrd

Genera/elimina un archivo .pcrlock basándose en un archivo cpio de initrd del kernel. Esto es útil para predecir las mediciones que el kernel de Linux realiza en la PCR 9 ("initrd del kernel"). No lo use para UKIs de systemd-stub(7), ya que el initrd se combina dinámicamente de varias fuentes y, por lo tanto, no toma una entrada única, como este comando.

Esto escribe/elimina el archivo /var/lib/pcrlock.d/720-kernel-initrd.pcrlock/generated.pcrlock.

Añadido en la versión 255.

lock-raw [ARCHIVO], unlock-raw

Genera/elimina un archivo .pcrlock basándose en datos binarios en bruto. Los datos se leen del archivo especificado o de STDIN (si no se especifica ninguno). Esto requiere que se especifique --pcrs=. El archivo .pcrlock generado se escribe en el archivo especificado mediante --pcrlock= o en STDOUT (si no se especifica ninguno).

Añadido en la versión 255.

OPTIONS

Las siguientes opciones se entienden:

--raw-description

Al mostrar el registro de eventos TPM2, no intente decodificar los registros para proporcionar una cadena de descripción amigable del registro de eventos. En su lugar, muestre los datos de carga útil binaria en forma escapada.

Añadido en la versión 255.

--pcr=

Especifica el número de PCR a utilizar. Puede especificarse más de una vez para seleccionar varias PCRs.

Esto es utilizado por lock-raw y lock-pe para seleccionar la PCR a bloquear.

Si se utiliza con predict y make-policy, esto anulará qué PCRs incluir en la predicción y la política. Si no se especifica, por defecto se usarán las PCRs 0-5, 7, 11-15. Tenga en cuenta que estos comandos no incluirán ninguna PCR en la predicción/política (incluso si se especifican explícitamente) si hay mediciones en el registro de eventos que no coinciden con el valor actual de la PCR, o hay mediciones no reconocidas en el registro de eventos, o los componentes definen mediciones no vistas en el registro de eventos.

Añadido en la versión 255.

--nv-index=

Especifica el índice NV donde almacenar la política. Honrado por make-policy. Si no se especifica, el comando elegirá automáticamente un índice NV libre.

Añadido en la versión 255.

--components=

Toma una ruta para leer archivos *.pcrlock y *.pcrlock.d/*.pcrlock. Puede usarse más de una vez para especificar varios de estos directorios. Si no se especifica, por defecto es /etc/pcrlock.d/, /run/pcrlock.d/, /var/lib/pcrlock.d/, /usr/local/lib/pcrlock.d/, /usr/lib/pcrlock.d/.

Añadido en la versión 255.

--location=

Toma una cadena o un par de cadenas separadas por dos puntos. Configura hasta qué punto en la lista ordenada de componentes definidos para analizar/predecir PCRs. Típicamente, la herramienta systemd-pcrlock se invoca desde un sistema completamente arrancado después del arranque y antes del apagado. Esto significa que varios componentes que se definen para el apagado aún no se han medido y no deben buscarse. Esta opción permite restringir qué componentes se consideran para el análisis (tomando solo los componentes anteriores a algún punto, ignorando los posteriores). La cadena esperada se ordena contra los nombres de archivo de los componentes definidos. Se ignoran todos los componentes con un nombre lexicográficamente posterior. Esta lógica se aplica a los verbos log, predict y make-policy. Si se especifica un par de cadenas separadas por dos puntos, seleccionan qué fases del arranque incluir en la predicción/política. La primera cadena define dónde se realizará la primera predicción, y la segunda cadena define dónde se realizará la última predicción. Todas estas predicciones se combinan en un solo conjunto.

Si se usa con list-components, el rango de ubicación seleccionado se resaltará en la lista de componentes.

Por defecto es "760-:940-", lo que significa que las políticas generadas por defecto cubrirán básicamente todo el tiempo de ejecución del espacio de usuario del sistema operativo, desde el initrd (ya que "760-" sigue de cerca a 750-enter-initrd.pcrlock) hasta (e incluyendo) el tiempo de ejecución principal del sistema (ya que "940-" es seguido de cerca por 950-shutdown.pcrlock). Consulte systemd.pcrlock(5) para obtener una lista completa de componentes conocidos, que ilustran dónde se coloca este rango por defecto.

Añadido en la versión 255.

NAME

systemd-pcrlock-firmware-config.service, systemd-pcrlock-firmware-config - Configure systemd-pcrlock firmware settings

SYNOPSIS

systemd-pcrlock-firmware-config [OPTIONS...]

DESCRIPTION

The systemd-pcrlock-firmware-config tool is used to manage the configuration of the TPM2 NV index used by systemd-pcrlock.service and systemd-pcrlockd.service. It allows users to create, display, and manage the policies that protect NV index access.

The TPM2 NV index is used to store boot measurement data (PCR values) which can be used to verify the integrity of the boot process. Access to this index is protected by a policy that is defined and managed using this tool.

COMMANDS

The following commands are supported:

is-supported
Checks if the system has the necessary hardware and software support for TPM2 NV index operations.
make-policy
Generates a new policy for the TPM2 NV index. This command should be run after the initial setup of the system or after changing the boot configuration. It reads the current PCR values and stores them in the policy. If the NV index is already initialized, it will prompt for the recovery PIN to unlock write access.
show-policy
Displays the current policy associated with the TPM2 NV index. This includes information about the policy flags and the recovery PIN if available.
unlock
Unlocks the TPM2 NV index using the provided recovery PIN. This command is useful if the access policy has expired or become invalid, allowing write access to be regained.
lock
Locks the TPM2 NV index, preventing any further modifications until it is unlocked with the recovery PIN.
hide
Hides the policy associated with the TPM2 NV index. This will generate a new recovery PIN automatically and store it securely. This is useful for enhancing security when the policy is no longer needed for regular access.
--force
When used with make-policy, this option forces the policy to be written to the NV index even if it is detected to be the same as the previously stored one.

OPTIONS

The following options are supported:

--recovery-pin=

Takes a file system path as argument. This path is used to store the recovery PIN. If the path does not exist, it will be created. If a PIN is provided, it is used to unlock the TPM2 NV index. If no policy was created before, this PIN is used to protect the newly allocated NV index. If a policy has been created before, the PIN is used to unlock write access to the NV index. If either "hide" or "show" is used, a PIN is automatically generated, and — only in case of "show" — displayed on screen. Regardless if user supplied or automatically generated, it is stored in encrypted form in the policy metadata file. The recovery PIN may be used to regain write access to an NV index in case the access policy became out of date.

Added in version 255.

--pcrlock=

Takes a file system path as argument. If specified, configures where to write the generated pcrlock data to. Honoured by the various lock-* commands. If not specified, a default path is generally used, as documented above.

Added in version 255.

--policy=

Takes a file system path as argument. If specified, configures where to write pcrlock policy metadata to. If not specified, defaults to /var/lib/systemd/pcrlock.json.

Added in version 255.

--force

If specified with make-policy, the predicted policy will be written to the NV index even if it is detected to be the same as the previously stored one.

Added in version 255.

--entry-token=

Sets the boot entry token to use for the file name for the pcrlock policy credential in the EFI System Partition or XBOOTLDR partition. See the bootctl(1) option of the same regarding expected values. This switch has an effect on the make-policy command only.

Added in version 256.

--quiet

If specified suppresses output when invoked for is-supported.

Added in version 258.

--json=MODE

Shows output formatted as JSON. Expects one of "short" (for the shortest possible output without any redundant whitespace or line breaks), "pretty" (for a pretty version of the same, with indentation and line breaks) or "off" (to turn off JSON output, the default).

--no-pager

Do not pipe output into a pager.

-h, --help

Print a short help text and exit.

--version

Print a short version string and exit.

EXIT STATUS

On success, 0 is returned, a non-zero failure code otherwise.
