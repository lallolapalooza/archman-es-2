perror(3) Manual de funciones de biblioteca perror(3)

NOMBRE

perror - imprimir un mensaje de error del sistema

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <stdio.h>
void perror(const char *s);
#include <errno.h>
int errno;  /* En realidad no se declara así; ver errno(3) */
[[deprecated]] const char *const sys_errlist[];
[[deprecated]] int sys_nerr;
Requisitos de Macro de Prueba de Funcionalidades para glibc (ver feature_test_macros(7)):

sys_errlist, sys_nerr:

    Desde glibc 2.19 hasta glibc 2.31:
        _DEFAULT_SOURCE
    glibc 2.19 y anteriores:
        _BSD_SOURCE

DESCRIPCIÓN

La función perror() produce un mensaje en la salida de error estándar describiendo el último error encontrado durante una llamada a una función del sistema o de la biblioteca.

Primero (si s no es NULL y *s no es un byte nulo ('\0')), se imprime la cadena de argumento s, seguida de dos puntos y un espacio. Luego, un mensaje de error correspondiente al valor actual de errno y un salto de línea.

Para ser de mayor utilidad, el argumento de cadena debe incluir el nombre de la función que incurrió en el error.

La lista global de errores sys_errlist[], que puede ser indexada por errno, puede ser utilizada para obtener el mensaje de error sin el salto de línea. El número de mensaje más grande proporcionado en la tabla es sys_nerr-1. Tenga cuidado al acceder directamente a esta lista, ya que puede que no se hayan añadido nuevos valores de error a sys_errlist[]. El uso de sys_errlist[] está obsoleto hoy en día; use strerror(3) en su lugar.

Cuando una llamada al sistema falla, generalmente devuelve -1 y establece la variable errno a un valor que describe qué salió mal. (Estos valores se pueden encontrar en <errno.h>). Muchas funciones de biblioteca hacen lo mismo. La función perror() sirve para traducir este código de error a un formato legible por humanos. Tenga en cuenta que errno no está definido después de una llamada exitosa al sistema o a una función de biblioteca: esta llamada podría cambiar esta variable, aunque tenga éxito, por ejemplo, porque internamente usó alguna otra función de biblioteca que falló. Por lo tanto, si una llamada fallida no es seguida inmediatamente por una llamada a perror(), el valor de errno debe guardarse.
