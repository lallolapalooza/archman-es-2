sysexits.h(3head) sysexits.h(3head)

NOMBRE

sysexits.h - códigos de salida para programas

BIBLIOTECA

Biblioteca estándar de C (libc)

SINOPSIS

#include <sysexits.h>
#define EX_OK 0 /* terminación exitosa */
#define EX__BASE 64 /* valor base para mensajes de error */
#define EX_USAGE 64 /* error de uso de la línea de comandos */
#define EX_DATAERR 65 /* error de formato de datos */
#define EX_NOINPUT 66 /* no se puede abrir la entrada */
#define EX_NOUSER 67 /* destinatario desconocido */
#define EX_NOHOST 68 /* nombre de host desconocido */
#define EX_UNAVAILABLE 69 /* servicio no disponible */
#define EX_SOFTWARE 70 /* error interno de software */
#define EX_OSERR 71 /* error del sistema (ej. no se puede hacer fork) */
#define EX_OSFILE 72 /* falta archivo crítico del SO */
#define EX_CANTCREAT 73 /* no se puede crear archivo de salida (del usuario) */
#define EX_IOERR 74 /* error de entrada/salida */
#define EX_TEMPFAIL 75 /* fallo temporal; se invita al usuario a reintentar */
#define EX_PROTOCOL 76 /* error remoto en el protocolo */
#define EX_NOPERM 77 /* permiso denegado */
#define EX_CONFIG 78 /* error de configuración */
#define EX__MAX ... /* valor máximo listado */

DESCRIPCIÓN

Algunos programas salen con los siguientes códigos de error.

La salida exitosa siempre se indica con un estado de 0, o EX_OK (equivalente a EXIT_SUCCESS de <stdlib.h>). Los números de error comienzan en EX__BASE para reducir la posibilidad de colisión con otros estados de salida que programas aleatorios puedan retornar. El significado del código es aproximadamente el siguiente:

EX_USAGE
El comando se usó incorrectamente, p. ej., con un número incorrecto de argumentos, una opción inválida, sintaxis incorrecta en un parámetro, o cualquiera de ellos.
EX_DATAERR
Los datos de entrada fueron incorrectos de alguna manera. Esto solo debe usarse para datos del usuario y no para archivos del sistema.
EX_NOINPUT
Un archivo de entrada (no un archivo del sistema) no existía o no era legible. Esto también podría incluir errores como "Sin mensaje" para un programa de correo (si éste se molestara en capturarlo).
EX_NOUSER
El usuario especificado no existía. Esto podría usarse para direcciones de correo o inicios de sesión remotos.
EX_NOHOST
El host especificado no existía. Esto se usa en direcciones de correo o solicitudes de red.
EX_UNAVAILABLE
Un servicio no está disponible. Esto puede ocurrir si un programa o archivo de soporte no existe. También puede usarse como un mensaje de captura general cuando algo que querías hacer no funciona, pero no sabes por qué.
EX_SOFTWARE
Se ha detectado un error interno de software. Esto debe limitarse a errores no relacionados con el sistema operativo si es posible.
EX_OSERR
Se ha detectado un error del sistema operativo. Está destinado a usarse para cosas como "no se puede hacer fork", "no se puede crear tubería" o similares. Incluye cosas como que getuid(2) devuelva un usuario que no existe en el archivo passwd(5).
EX_OSFILE
Algún archivo del sistema (p. ej., /etc/passwd, /etc/utmp, etc.) no existe, no se puede abrir, o tiene algún tipo de error (p. ej., error de sintaxis).
EX_CANTCREAT
No se puede crear un archivo de salida (especificado por el usuario).
EX_IOERR
Ocurrió un error al realizar E/S en algún archivo.
EX_TEMPFAIL
Fallo temporal, indicando algo que en realidad no es un error. Por ejemplo, que un programa de correo no pudo establecer una conexión, y la solicitud debería reintentarse más tarde.
EX_PROTOCOL
El sistema remoto devolvió algo que "no era posible" durante un intercambio de protocolo.
EX_OSFILE
No tenías suficiente permiso para realizar la operación. Esto no está destinado a problemas del sistema de archivos, que deberían usar EX_NOINPUT o EX_CANTCREAT, sino a permisos de nivel superior.
EX_CONFIG
Se encontró algo en un estado no configurado o mal configurado.

Los valores numéricos correspondientes a los simbólicos se dan entre paréntesis para facilitar la referencia.

ESTÁNDARES

BSD.

HISTORIA

El archivo <sysexits.h> apareció en 4.0BSD para ser utilizado por la utilidad deliverymail, renombrada posteriormente a sendmail(8).

ADVERTENCIAS

La elección de un valor de salida apropiado es a menudo ambigua.

VER TAMBIÉN

err(3), error(3), exit(3)
