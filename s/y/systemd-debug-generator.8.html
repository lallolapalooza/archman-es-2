NOMBRE

systemd-debug-generator - Generador para habilitar un shell de depuración en tiempo de ejecución y enmascarar unidades específicas al arrancar

SINOPSIS

/usr/lib/systemd/system-generators/systemd-debug-generator

DESCRIPCIÓN

systemd-debug-generator es un generador que proporciona algunas funcionalidades de depuración.

systemd-debug-generator implementa systemd.generator(7).

LÍNEA DE COMANDOS DEL NÚCLEO

systemd-debug-generator entiende los siguientes parámetros de línea de comandos del núcleo:

systemd.mask=, rd.systemd.mask=

Estas opciones toman un nombre de unidad como argumento. La unidad especificada se enmascara para el tiempo de ejecución (es decir, para esta sesión — desde el arranque hasta el apagado), de manera similar al efecto del comando mask de systemctl(1). Esto es útil para arrancar con ciertas unidades eliminadas de la transacción de arranque inicial para depurar el inicio del sistema. Se puede especificar más de una vez. La opción prefijada con "rd." solo se tiene en cuenta en el initrd, mientras que la que no tiene prefijo solo se tiene en cuenta en el host.

Añadido en la versión 215.

systemd.wants=, rd.systemd.wants=

Estas opciones toman un nombre de unidad como argumento. Se añade un trabajo de inicio para esta unidad a la transacción inicial. Esto es útil para iniciar una o más unidades adicionales al arrancar. Se puede especificar más de una vez. La opción prefijada con "rd." solo se tiene en cuenta en el initrd, mientras que la que no tiene prefijo solo se tiene en cuenta en el host.

Añadido en la versión 215.

systemd.debug_shell, rd.systemd.debug_shell, systemd.default_debug_tty=, rd.systemd.default_debug_tty=

Si se especifica la opción systemd.debug_shell o rd.systemd.debug_shell, el servicio de shell de depuración "debug-shell.service" se incluirá en la transacción de arranque y se iniciará un shell de depuración durante el arranque temprano. Por defecto, se utiliza /dev/tty9, pero también se puede especificar una tty específica, con o sin el prefijo /dev/. Para establecer la tty a utilizar sin habilitar el shell de depuración, se puede usar la opción systemd.default_debug_tty=, que también acepta una tty con o sin el prefijo /dev/. Tenga en cuenta que el shell también se puede activar de forma persistente habilitándolo con el comando enable de systemctl(1). Las opciones prefijadas con "rd." solo se tienen en cuenta en el initrd, mientras que las que no tienen prefijo solo se tienen en cuenta en el host.

Añadido en la versión 215.

systemd.break=, rd.systemd.break=

Toma uno de pre-udev, pre-basic, pre-mount, o pre-switch-root (el valor predeterminado para la opción "rd."). También acepta múltiples valores separados por coma (","). Estas opciones permiten pausar el proceso de arranque en un punto determinado e iniciar un shell de depuración. Después de salir de este shell, el sistema reanudará el arranque. La opción prefijada con "rd." solo se tiene en cuenta en el initrd, mientras que la que no tiene prefijo solo se tiene en cuenta en el host.

Tabla 1. Puntos de interrupción disponibles

Puntos de interrupción Descripción Se puede usar en el initrd Se puede usar en el host
pre-udev Antes de empezar a procesar eventos u eventos del núcleo, es decir, antes de que se inicie systemd-udevd.service. ✓ ✓
pre-basic Antes de salir del arranque temprano y que comiencen los servicios regulares, es decir, antes de alcanzar basic.target. ✓ ✓
pre-mount Antes de montar el sistema de archivos raíz, es decir, antes de que comience sysroot.mount. ✓ ✗
pre-switch-root Antes de cambiar del initrd al sistema de archivos raíz real. ✓ ✗

Añadido en la versión 258.

CREDENCIALES DEL SISTEMA

systemd.extra-unit.*

Las credenciales prefijadas con "systemd.extra-unit." especifican unidades adicionales a añadir al sistema final. Tenga en cuenta que estas unidades adicionales se añaden tanto al initrd como al sistema final. ConditionPathExists=!/etc/initrd-release se puede usar para asegurarse de que la unidad se condicione fuera en el initrd. Tenga en cuenta que esto también se puede usar para enmascarar unidades, simplemente especificando un valor vacío.

Añadido en la versión 256.

systemd.unit-dropin.*

Las credenciales prefijadas con "systemd.unit-dropin." añaden drop-ins para las unidades correspondientes en el sistema final. Cada credencial debe ir seguida del nombre completo de la unidad, incluida la extensión de la unidad. Su contenido debe ser un archivo drop-in de unidad válido. Opcionalmente, el nombre de la unidad puede ir seguido de "~", seguido del nombre del drop-in sin el sufijo ".conf". Si no se especifica, el nombre del drop-in generado será "50-credential.conf". Tenga en cuenta que estos drop-ins adicionales se añaden tanto al initrd como al sistema final.

Añadido en la versión 256.
