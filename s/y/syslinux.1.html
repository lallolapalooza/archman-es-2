SYSLINUX(1) Manual de Comandos Generales SYSLINUX(1)

NOMBRE

syslinux - instala el cargador de arranque SYSLINUX en un sistema de archivos FAT

SINOPSIS

syslinux [OPCIONES] dispositivo

DESCRIPCIÓN

Syslinux es un cargador de arranque para el sistema operativo Linux que opera desde un sistema de archivos MS-DOS/Windows FAT. Está diseñado para simplificar la instalación inicial de Linux y para crear discos de arranque de rescate y otros de propósito especial.

Para crear un disquete de arranque de Linux usando Syslinux, prepara un disquete formateado normal de MS-DOS. Copia uno o más archivos de kernel de Linux en él, luego ejecuta el comando:

syslinux --install /dev/fd0

Esto alterará el sector de arranque en el disco y copiará un archivo llamado ldlinux.sys en su directorio raíz.

En tiempo de arranque, por defecto, el kernel se cargará desde la imagen llamada LINUX en el disquete de arranque. Este valor predeterminado se puede cambiar, consulta la sección sobre el archivo de configuración de syslinux.

Si las teclas Shift o Alt se mantienen presionadas durante el arranque, o los bloqueos Caps o Scroll están activados, syslinux mostrará un prompt de "boot:" estilo lilo(8). El usuario puede entonces escribir el nombre de un archivo de kernel seguido de cualquier parámetro del kernel. El cargador de arranque SYSLINUX no necesita conocer el archivo del kernel de antemano; todo lo que se requiere es que sea un archivo ubicado en el directorio raíz del disco.

Syslinux soporta la carga de ramdisks iniciales (initrd) y el formato de kernel bzImage.

OPCIONES

-i, --install
Instala SYSLINUX en un nuevo medio, sobrescribiendo cualquier cargador de arranque instalado previamente.
-U, --update
Instala SYSLINUX en un nuevo medio si y solo si una versión de SYSLINUX ya está instalada.
-s, --stupid
Instala una versión "segura, lenta y estúpida" de SYSLINUX. Esta versión puede funcionar en algunas BIOS muy defectuosas en las que SYSLINUX de lo contrario fallaría. Si encuentras una máquina en la que se requiere la opción -s para que arranque de manera confiable, por favor envía tanta información sobre tu máquina como sea posible, e incluye el modo de fallo.
-f, --force
Fuerza la instalación incluso si parece inseguro.
-r, --raid
Modo RAID. Si falla el arranque, dile a la BIOS que arranque el siguiente dispositivo en la secuencia de arranque (generalmente el siguiente disco duro) en lugar de detenerse con un mensaje de error. Esto es útil para el arranque RAID-1.
-d, --directory subdirectorio
Instala los archivos de control de SYSLINUX en un subdirectorio con el nombre especificado (relativo al directorio raíz en el dispositivo).
-t, --offset offset
Indica que el sistema de archivos está en un offset desde la base del dispositivo o archivo.
--once comando
Declara un comando de arranque para ser probado solo en el primer arranque.
-O, --clear-once
Borra el comando de arranque único.
-H, --heads conteo-de-cabezales
Sobrescribe el número detectado de cabezales para la geometría.
-S, --sectors conteo-de-sectores
Sobrescribe el número detectado de sectores para la geometría.
-z, --zipdrive
Asume geometría de unidad zip (--heads 64 --sectors 32).

ARCHIVOS

Archivo de configuración

Todos los valores predeterminados configurables en SYSLINUX se pueden cambiar colocando un archivo llamado syslinux.cfg en el directorio de instalación del disco de arranque. Este es un archivo de texto en formato UNIX o DOS, que contiene uno o más de los siguientes elementos (las mayúsculas y minúsculas no distinguen para las palabras clave).

Esta lista está desactualizada.

En el archivo de configuración, las líneas en blanco y las líneas de comentario que comienzan con un signo de almohadilla (#) se ignoran.

default kernel [ opciones ... ]
Establece la línea de comandos predeterminada. Si syslinux arranca automáticamente, actuará como si las entradas después de "default" se hubieran escrito en el prompt "boot:".
Si no se encuentra ninguna declaración DEFAULT o UI, o si el archivo de configuración no existe, SYSLINUX cae al prompt de boot: con un mensaje de error (si NOESCAPE está configurado, se detiene con un mensaje de "fallo de arranque"; este también es el caso para PXELINUX si el archivo de configuración no se encuentra.)
NOTA: Hasta SYSLINUX 3.85, si no hay archivo de configuración presente, o no
hay una entrada "default" presente en el archivo de configuración, el valor predeterminado es "linux auto".
Incluso versiones anteriores de SYSLINUX solían
añadir automáticamente la cadena "auto" a lo que el usuario especificaba usando el comando DEFAULT. A partir de la versión 1.54, esto ya no es cierto, ya que causaba problemas al usar un shell como sustituto de "init". Es posible que desees incluir esta opción manualmente.
append opciones ...
Agrega una o más opciones a la línea de comandos del kernel. Estas se agregan tanto para arranques automáticos como manuales. Las opciones se agregan al principio de la línea de comandos del kernel, permitiendo que las opciones del kernel especificadas explícitamente las invaliden. Esto es el equivalente a la opción lilo(8)
"append".
label etiqueta
kernel imagen
append opciones ...
Indica que si etiqueta se ingresa como el kernel a arrancar, syslinux arrancará en su lugar imagen, y las opciones "append" especificadas se usarán en lugar de las especificadas en la sección global del archivo (antes del primer comando "label".) El valor predeterminado para imagen es el mismo que etiqueta, y si no se proporciona "append", el valor predeterminado es usar la entrada global (si existe). Usa "append -" para no usar ninguna opción. Se permiten hasta 128 entradas de "label".
La "imagen" no tiene que ser un kernel de Linux; puede ser un sector de arranque (ver abajo.)
implicit valor_bandera
Si valor_bandera es 0, no cargues una imagen de kernel a menos que haya sido nombrada explícitamente en una declaración de "label". El valor predeterminado es 1.
timeout tiempo_de_espera
Indica cuánto tiempo esperar en el prompt "boot:" antes de arrancar automáticamente, en unidades de 1/10 s. El tiempo de espera se cancela tan pronto como el usuario escribe algo en el teclado, asumiendo que el usuario completará la línea de comandos ya iniciada. Un tiempo de espera de cero deshabilitará completamente el tiempo de espera, este es también el valor predeterminado. El valor máximo de tiempo de espera posible es 35996; correspondiente a poco menos de una hora.
serial puerto [ velocidad_en_baudios ]
Habilita un puerto serie para actuar como consola. "puerto" es un número (0 = /dev/ttyS0 = COM1, etc.); si "velocidad_en_baudios" se omite, la velocidad en baudios por defecto es 9600 bps. Los parámetros serie están codificados como 8 bits, sin paridad, 1 bit de parada.
Para que esta directiva funcione correctamente garantizado, debe ser la primera directiva en el archivo de configuración.
font nombre_archivo
Carga una fuente en formato .psf antes de mostrar cualquier salida (excepto la línea de copyright, que se muestra cuando se carga ldlinux.sys.) syslinux solo carga la fuente en la tarjeta de video; si el archivo .psf contiene
s una tabla Unicode se ignora. Esto solo funciona en tarjetas EGA y VGA; esperemos que no haga nada en otras.
kbdmap mapadeteclado
Instala un mapa de teclado simple. El remapeador de teclado utilizado es *muy* simplista (simplemente reasigna los códigos de tecla recibidos de la BIOS, lo que significa que solo las combinaciones de teclas relevantes en la disposición predeterminada - generalmente inglés de EE. UU. - pueden ser mapeadas) pero al menos debería ayudar a las personas con diseños de teclado AZERTY y las ubicaciones de = y , (dos caracteres especiales utilizados intensamente en la línea de comandos del kernel de Linux).
El programa incluido keytab-lilo.pl(8) de la distribución lilo(8) se puede usar para crear dichos mapas de teclado.
display nombrearchivo
Muestra el archivo indicado en la pantalla en el momento del arranque (antes del aviso de inicio, si se muestra). Consulte la sección a continuación sobre los archivos DISPLAY. Si el archivo no se encuentra, esta opción simplemente se ignora.
prompt valorbandera
Si valorbandera es 0, muestra el aviso "boot:" solo si se presiona la tecla Shift o Alt, o si Caps Lock o Scroll Lock están activados (este es el valor predeterminado). Si valorbandera es 1, siempre muestra el aviso "boot:".
f1 nombrearchivo
f2 nombrearchivo
...
f9 nombrearchivo
f10 nombrearchivo
f11 nombrearchivo
f12 nombrearchivo
Muestra el archivo indicado en la pantalla cuando se presiona una tecla de función en el aviso "boot:". Esto se puede usar para implementar ayuda en línea previa al arranque (presumiblemente para las opciones de línea de comandos del kernel).
Al usar la consola serie, presione <Ctrl-F><dígito> para acceder a las pantallas de ayuda, por ejemplo, <Ctrl-F>2 para acceder a la pantalla f2. Para f10-f12, presione <Ctrl-F>A, <Ctrl-F>B, <Ctrl-F>C. Para compatibilidad con versiones anteriores, f10 también se puede ingresar como <Ctrl-F>0.

Formato de archivo Display

Los archivos de ayuda de DISPLAY y teclas de función son archivos de texto en formato DOS o UNIX (con o sin <CR>). Además, se interpretan los siguientes códigos especiales:

<FF> = <Ctrl-L> = ASCII 12
Borra la pantalla, mueve el cursor al inicio. Tenga en cuenta que la pantalla se rellena con el color de pantalla actual.
<SI><fondo><primerplano>, <SI> = <Ctrl-O> = ASCII 15
Establece los colores de pantalla a los colores de fondo y primer plano especificados, donde <fondo> y <primerplano> son dígitos hexadecimales, correspondientes a los atributos de pantalla estándar de PC:
0 = negro	8 = gris oscuro
1 = azul oscuro	9 = azul brillante
2 = verde oscuro	a = verde brillante
3 = cian oscuro	b = cian brillante
4 = rojo oscuro	c = rojo brillante
5 = púrpura oscuro	d = púrpura brillante
6 = marrón	e = amarillo
7 = gris claro	f = blanco
Elegir un color brillante (8-f) para el fondo da como resultado el color oscuro correspondiente (0-7), con el primer plano parpadeando.
los colores no son visibles en la consola serie.
<CAN>nombrearchivo<nueva línea>, <CAN> = <Ctrl-X> = ASCII 24
Si hay una pantalla VGA, entra en modo gráfico y muestra los gráficos incluidos en el archivo especificado. El formato del archivo es un formato ad hoc llamado LSS16; el programa Perl incluido "ppmtolss16" puede usarse para producir estas imágenes. Este programa Perl también incluye la especificación del formato del archivo.
La imagen se muestra en modo 640x480 de 16 colores. Una vez en modo gráfico, los atributos de pantalla (establecidos por secuencias de código <SI>) funcionan de manera ligeramente diferente: el color de fondo se ignora y los colores de primer plano son los 16 colores especificados en el archivo de imagen. Por esa razón, ppmtolss16 le permite especificar que ciertos colores deben asignarse a índices de color específicos.
Los índices de color 0 y 7, en particular, deben elegirse con cuidado: 0 es el color de fondo y 7 es el color utilizado para el texto impreso por SYSLINUX.
<EM>, <EM> = <Ctrl-U> = ASCII 25
Si actualmente estamos en modo gráfico, volvemos a modo de texto.
<DLE>..<ETB>, <Ctrl-P>..<Ctrl-W> = ASCII 16-23
Estos códigos se pueden usar para seleccionar en qué modos se imprimirá cierta parte del archivo de mensajes. Cada uno de estos caracteres de control selecciona un conjunto específico de modos (pantalla de texto, pantalla gráfica, puerto serie) para los cuales la salida se muestra realmente:
Carácter                       Texto    Gráf.   Serie
------------------------------------------------------
<DLE> = <Ctrl-P> = ASCII 16     No      No      No
<DC1> = <Ctrl-Q> = ASCII 17     Sí      No      No
<DC2> = <Ctrl-R> = ASCII 18     No      Sí      No
<DC3> = <Ctrl-S> = ASCII 19     Sí      Sí      No
<DC4> = <Ctrl-T> = ASCII 20     No      No      Sí
<NAK> = <Ctrl-U> = ASCII 21     Sí      No      Sí
<SYN> = <Ctrl-V> = ASCII 22     No      Sí      Sí
<ETB> = <Ctrl-W> = ASCII 23     Sí      Sí      Sí
Por ejemplo: 
<DC1>Modo texto<DC2>Modo gráfico<DC4>Puerto serie<ETB>

... ¡imprimirá realmente en qué modo está la consola!
<SUB> = <Ctrl-Z> = ASCII 26
Fin de archivo (convención DOS).

Otros sistemas operativos

Esta versión de syslinux soporta la carga en cadena de otros sistemas operativos (como MS-DOS y sus derivados, incluido Windows 95/98).

La carga en cadena requiere que el sector de arranque del sistema operativo externo se almacene en un archivo en el directorio raíz del sistema de archivos. Dado que ni los kernels de Linux ni las imágenes de sectores de arranque tienen números mágicos confiables, syslinux mirará la extensión del archivo. Se reconocen las siguientes extensiones:

ninguna u otra	Imagen del kernel de Linux
BSS	Sector de arranque (se parcheará el superbloque de DOS)
BS	Sector de arranque

Para los nombres de archivo dados en la línea de comandos, syslinux buscará el archivo agregando extensiones en el orden que se enumera arriba si no se encuentra el nombre de archivo simple. Los nombres de archivo en las sentencias KERNEL deben estar completamente calificados.

Protección para principiantes

Syslinux intentará detectar si el usuario está intentando arrancar en una máquina de clase 286 o inferior, o una máquina con menos de 608K de RAM baja ("DOS") (lo que significa que la secuencia de arranque de Linux no puede completarse). Si es así, se muestra un mensaje y se aborta la secuencia de arranque. Mantener presionada la tecla Ctrl al arrancar desactiva esta función.

La hora y fecha de compilación de una versión específica de syslinux se pueden obtener con el comando DOS "type ldlinux.sys". Esto también se usa como la firma del archivo LDLINUX.SYS, que debe coincidir con el sector de arranque.

Cualquier archivo que syslinux utilice puede ser marcado como oculto, sistema o de solo lectura si así lo desea; syslinux ignora todos los atributos de archivo. SYSLINUX instalado establece automáticamente el atributo de solo lectura en LDLINUX.SYS.

CD-ROMs arrancables

SYSLINUX se puede usar para crear imágenes de disquete de arranque para CD-ROMs arrancables compatibles con El Torito. Sin embargo, parece que muchas BIOS tienen errores al arrancar desde CD-ROMs. Algunos usuarios han informado que los siguientes pasos son útiles para crear un CD-ROM que sea arrancable en la mayor cantidad posible de máquinas:

  • Use la opción -s (seguro, lento y estúpido) para SYSLINUX
  • Coloque la imagen de arranque lo más cerca posible del principio del sistema de archivos ISO 9660.

Un CD-ROM es mucho más rápido que un disquete, por lo que la opción -s no debería importar desde la perspectiva de la velocidad.

Por supuesto, probablemente querrá usar ISOLINUX. Consulte el archivo de documentación isolinux.doc.

Arrancar desde una partición FAT en un disco duro

SYSLINUX puede arrancar desde una partición con sistema de archivos FAT en un disco duro (incluido FAT32). El procedimiento de instalación es idéntico al procedimiento para instalarlo en un disquete, y debería funcionar tanto bajo DOS como bajo Linux. Para arrancar desde una partición, SYSLINUX necesita ser lanzado desde un Master Boot Record u otro cargador de arranque, al igual que lo haría DOS. Se incluye un sector de arranque maestro de ejemplo (mbr.bin) con SYSLINUX.

ERRORES

Agradecería saber de cualquier problema que tenga con SYSLINUX. También me gustaría saber si ha utilizado SYSLINUX con éxito, especialmente si lo está utilizando para una distribución.

Si está informando problemas, incluya toda la información posible sobre su sistema y su BIOS; la gran mayoría de todos los problemas informados resultan ser errores de BIOS o de hardware, y necesito tanta información como sea posible para diagnosticar los problemas.

Hay una lista de correo para discutir entre los usuarios de SYSLINUX y para anunciar versiones nuevas y de prueba. Para unirse, envíe un mensaje a majordomo@linux.kernel.org con la línea:

subscribe syslinux

en el cuerpo del mensaje. La dirección de envío es syslinux@linux.kernel.org.
