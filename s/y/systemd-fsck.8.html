NOMBRE

systemd-fsck@.service, systemd-fsck-root.service, systemd-fsck-usr.service, systemd-fsck - Lógica del comprobador de sistemas de archivos

SINOPSIS

systemd-fsck@.service
systemd-fsck-root.service
systemd-fsck-usr.service
/usr/lib/systemd/systemd-fsck

DESCRIPCIÓN

systemd-fsck@.service, systemd-fsck-root.service y systemd-fsck-usr.service son servicios responsables de las comprobaciones de los sistemas de archivos. Se instancian para cada dispositivo configurado para la comprobación del sistema de archivos. systemd-fsck-root.service y systemd-fsck-usr.service son responsables de las comprobaciones de los sistemas de archivos en el sistema de archivos raíz y /usr, respectivamente, pero solo si el sistema de archivos raíz no fue comprobado en el initrd. systemd-fsck@.service se utiliza para todos los demás sistemas de archivos y para el sistema de archivos raíz en el initrd.

Estos servicios se inician al arrancar si passno en /etc/fstab para el sistema de archivos tiene un valor mayor que cero, pero solo si también está configurado para ser montado al arrancar (es decir, sin la opción "noauto"). La comprobación del sistema de archivos para la raíz se realiza antes que los demás sistemas de archivos. Otros sistemas de archivos pueden ser comprobados en paralelo, excepto cuando están en el mismo disco rotativo.

systemd-fsck no conoce ningún detalle sobre sistemas de archivos específicos y simplemente ejecuta comprobadores de sistemas de archivos específicos para cada tipo de sistema de archivos (fsck.type). Estos comprobadores decidirán si el sistema de archivos debe ser comprobado en realidad basándose en el tiempo transcurrido desde la última comprobación, el número de montajes, desmontaje no limpio, etc.

systemd-fsck-root.service y systemd-fsck-usr.service activarán reboot.target si fsck(8) devuelve la condición "El sistema debe reiniciarse", o emergency.target si fsck devuelve la condición "Errores de sistema de archivos no corregidos".

systemd-fsck@.service fallará si fsck(8) devuelve tanto la condición "El sistema debe reiniciarse" como la condición "Errores de sistema de archivos no corregidos". Para los sistemas de archivos listados en /etc/fstab sin las opciones "nofail" o "noauto", local-fs.target activará entonces emergency.target.

LÍNEA DE COMANDOS DEL NÚCLEO

systemd-fsck entiende los siguientes parámetros de la línea de comandos del núcleo:

fsck.mode=

Una de "auto", "force", "skip". Controla el modo de operación. El valor predeterminado es "auto" y asegura que se realicen comprobaciones de los sistemas de archivos cuando el comprobador de sistemas de archivos las considere necesarias. "force" resulta incondicionalmente en comprobaciones completas de los sistemas de archivos. "skip" omite cualquier comprobación de los sistemas de archivos.

Añadido en la versión 186.

fsck.repair=

Una de "preen", "yes", "no". Controla el modo de operación. El valor predeterminado es "preen" y reparará automáticamente los problemas que puedan ser corregidos de forma segura. "yes" responderá sí a todas las preguntas de fsck y "no" responderá no a todas las preguntas.

Añadido en la versión 213.

CREDENCIALES

systemd-fsck soporta la lógica de credenciales del servicio tal como la implementa ImportCredential=/LoadCredential=/SetCredential= (ver systemd.exec(5) para más detalles). Las siguientes credenciales se utilizan cuando se pasan:

fsck.mode, fsck.repair

El contenido de las credenciales se analiza igual que las opciones de la línea de comandos del núcleo con el mismo nombre. Ver arriba para más detalles.

Añadido en la versión 258.

Tenga en cuenta que, por defecto, los archivos de unidad systemd-fsck@.service, systemd-fsck-root.service y systemd-fsck-usr.service se configuran para heredar las credenciales fsck.mode y fsck.repair del gestor de servicios.
