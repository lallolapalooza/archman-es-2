NOMBRE

systemd-bootchart - Herramienta de graficación del rendimiento de arranque

DESCRIPCIÓN

systemd-bootchart es una herramienta, que normalmente se ejecuta al inicio del sistema, que recopila la carga de la CPU, la carga del disco, el uso de memoria, así como información por proceso de un sistema en ejecución. Los resultados recopilados se presentan como un gráfico SVG. Normalmente, systemd-bootchart es invocado por el kernel pasando init=/usr/lib/systemd/systemd-bootchart en la línea de comandos del kernel, añadiendo initcall_debug para recopilar datos sobre los hilos de inicialización del kernel. systemd-bootchart luego bifurcará el init real para reanudar el inicio normal del sistema, mientras monitoriza y registra la información de inicio en segundo plano.

Después de recopilar una cierta cantidad de datos (normalmente 15-30 segundos, por defecto 20 s) el registro se detiene y se genera un gráfico a partir de la información registrada. Este gráfico contiene pistas vitales sobre qué recursos se están utilizando, en qué orden y dónde pueden existir problemas en la secuencia de inicio del sistema. Es esencialmente una versión más detallada de la función systemd-analyze plot.

Por supuesto, bootchart también puede utilizarse en cualquier momento para recopilar y graficar datos durante un período de tiempo. Se recomienda usar la opción --rel en este caso.

Bootchart no requiere privilegios de root y funcionará sin problemas como un usuario normal.

Los gráficos de Bootchart se escriben por defecto con marca de tiempo en /run/log y se guardan en el journal con MESSAGE_ID=9f26aa562cf440c2b16c773d0479b518. El campo del journal BOOTCHART= contiene el bootchart en formato SVG.

INVOCACIÓN

systemd-bootchart puede ser invocado de varias maneras diferentes:

Invocación por el kernel

El kernel puede invocar systemd-bootchart en lugar del proceso init. A su vez, systemd-bootchart invocará /usr/lib/systemd/systemd. Se recopilarán datos sobre los hilos de inicialización del kernel y también sobre los procesos, incluyendo los servicios iniciados por systemd.

Unidad systemd

Se proporciona un archivo de unidad, systemd-bootchart.service. Si se habilita al inicio del sistema, recopilará datos sobre los procesos, incluyendo los servicios iniciados por systemd.

Iniciado como programa independiente

Se puede ejecutar systemd-bootchart como una aplicación normal desde la línea de comandos. En este modo, se recomienda encarecidamente pasar la opción -r para no graficar el tiempo transcurrido desde el arranque y antes de que se iniciara systemd-bootchart, ya que puede resultar en gráficos extremadamente grandes. El tiempo transcurrido desde el arranque también puede incluir cualquier tiempo en que el sistema estuvo suspendido.

OPCIONES

Estas opciones también pueden configurarse en el archivo /etc/systemd/bootchart.conf. Consulte bootchart.conf(5).

-h, --help

Imprime un breve texto de ayuda y sale.

-n, --sample N

Especifica el número de muestras, N, a registrar. Las muestras se registrarán en intervalos definidos con --freq.

-f, --freq f

Especifica la frecuencia de registro de muestras, un número real positivo f, en Hz. La mayoría de los sistemas pueden soportar valores de hasta 25-50 sin crear demasiada sobrecarga.

-r, --rel

Utiliza tiempos relativos en lugar de tiempos absolutos. Esto es útil para usar bootchart después del arranque para perfilar un sistema ya arrancado. Sin esta opción, el gráfico se volvería extremadamente grande. Si se establece, el eje horizontal comienza en la primera muestra registrada en lugar de en el tiempo 0.0.

-F, --no-filter

Deshabilita el filtrado de tareas que no contribuyeron significativamente al arranque. Los procesos de vida demasiado corta (solo vistos en una muestra) o que no consumen tiempo de CPU significativo (menos de 0.001 s) no se mostrarán en el gráfico de salida.

-C, --cmdline

Muestra la línea de comandos completa con argumentos de los procesos, en lugar de solo el nombre del proceso.

-g, --control-group

Muestra el grupo de control del proceso.

-o, --output ruta

Especifica el directorio de salida para los gráficos. Por defecto, bootchart escribe los gráficos en /run/log.

-i, --init ruta

Utiliza este binario init. Por defecto es /usr/lib/systemd/systemd.

-p, --pss

Habilita el registro y la graficación del consumo de memoria PSS (Proportional Set Size) de los procesos. Consulte filesystems/proc.txt en la documentación del kernel para una explicación de este campo.

-e, --entropy

Habilita el registro y la graficación del tamaño del pool de entropía aleatoria del kernel.

-x, --scale-x N

Factor de escalado horizontal para todos los componentes variables del gráfico.

-y, --scale-y N

Factor de escalado vertical para todos los componentes variables del gráfico.

SALIDA

systemd-bootchart genera gráficos SVG. Para renderizar estos en una pantalla gráfica, se puede usar cualquier visor compatible con SVG. Cabe señalar que los motores de renderizado SVG en la mayoría de los navegadores (incluyendo Chrome y Firefox) son muchas veces más rápidos que aplicaciones gráficas dedicadas como Gimp e Inkscape. ¡Simplemente apunte su navegador a file:///run/log/!

HISTORIA

Esta versión de bootchart se implementó desde cero, pero está inspirada en versiones anteriores de bootchart:

Bash original

El código original de bash/shell implementó bootchart. Esta versión creaba un tarball comprimido para procesarlo con aplicaciones externas. Esta versión no graficaba nada, solo generaba datos.

Implementación C de Ubuntu

Esta versión reemplazó la versión de shell con un registrador de datos rápido y eficiente, pero tampoco graficaba los datos.

Bootchart de Java

Esta fue la aplicación de graficación original para trazar los datos, escrita en Java.

pybootchartgui.py

pybootchart creaba un gráfico a partir de los datos recopilados por la versión de bash o C.

La versión de bootchart que está utilizando ahora combina la recopilación de datos y la graficación en una sola aplicación, lo que la hace más eficiente y simple. Ya no hay problemas de temporización con el recolector de datos y el graficador, ya que la graficación no se puede ejecutar hasta que se hayan recopilado los datos. Además, los datos que se mantienen en memoria se reducen al mínimo absoluto necesario.

VER TAMBIÉN

bootchart.conf(5)

ERRORES

systemd-bootchart no obtiene la información del modelo del disco duro a menos que el dispositivo raíz se especifique con root=/dev/sdxY. Usar UUIDs o PARTUUIDs arrancará bien, pero el modelo del disco duro no se añadirá al gráfico.
