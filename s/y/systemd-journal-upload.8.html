NOMBRE

systemd-journal-upload.service, systemd-journal-upload - Envía mensajes del journal a través de la red

SINOPSIS

systemd-journal-upload.service

/usr/lib/systemd/systemd-journal-upload [OPCIONES...] [-u/--url=URL] [FUENTES...]

DESCRIPCIÓN

systemd-journal-upload subirá las entradas del journal a la URL especificada con --url=. Este programa lee las entradas del journal de uno o más archivos de journal, de forma similar a journalctl(1). A menos que se limite por una de las opciones especificadas a continuación, se subirán todas las entradas del journal accesibles para el usuario con el que se ejecuta el programa, y luego el programa esperará y enviará nuevas entradas a medida que estén disponibles.

systemd-journal-upload transfiere el contenido bruto del archivo del journal y utiliza HTTP como protocolo de transporte.

systemd-journal-upload.service es un servicio del sistema que utiliza systemd-journal-upload para subir entradas del journal a un servidor. Utiliza la configuración en journal-upload.conf(5). Como mínimo, se debe especificar la opción URL=.

OPCIONES

-u, --url=[https://]URL[:PUERTO], --url=[http://]URL[:PUERTO]

Sube a la dirección especificada. URL puede especificar solo el nombre de host o tanto el protocolo como el nombre de host. https es el valor predeterminado. El número de puerto se puede especificar después de dos puntos (":"), de lo contrario, se usará 19532 por defecto.

Añadido en la versión 239.

--system, --user

Limita las entradas subidas a entradas de servicios del sistema y del kernel, o a entradas de servicios del usuario actual. Esto tiene el mismo significado que las opciones --system y --user para journalctl(1). Si no se especifica ninguna de las dos, se subirán todas las entradas accesibles.

Añadido en la versión 239.

-m, --merge

Sube entradas intercaladas de todos los journals disponibles, incluidas otras máquinas. Esto tiene el mismo significado que la opción --merge para journalctl(1).

Añadido en la versión 239.

--namespace=NAMESPACE

Toma un identificador de espacio de nombres del journal como argumento. Sube las entradas del espacio de nombres del journal especificado NAMESPACE en lugar del espacio de nombres predeterminado. Esto tiene el mismo significado que la opción --namespace= para journalctl(1).

Añadido en la versión 254.

-D, --directory=DIR

Toma una ruta de directorio como argumento. Sube entradas del directorio del journal especificado DIR en lugar de las rutas predeterminadas del journal del sistema y en tiempo de ejecución. Esto tiene el mismo significado que la opción --directory= para journalctl(1).

Añadido en la versión 239.

--file=GLOB

Toma un patrón de archivo como argumento. Sube entradas de los archivos del journal especificados que coincidan con GLOB en lugar de las rutas predeterminadas del journal del sistema y en tiempo de ejecución. Se puede especificar varias veces, en cuyo caso los archivos se intercalarán adecuadamente. Esto tiene el mismo significado que la opción --file= para journalctl(1).

Añadido en la versión 239.

--cursor=

Sube entradas desde la ubicación en el journal especificada por el cursor proporcionado. Esto tiene el mismo significado que la opción --cursor= para journalctl(1).

Añadido en la versión 239.

--after-cursor=

Sube entradas desde la ubicación en el journal después de la ubicación especificada por este cursor. Esto tiene el mismo significado que la opción --after-cursor= para journalctl(1).

Añadido en la versión 239.

--save-state[=PATH]

Sube entradas desde la ubicación en el journal después de la ubicación especificada por el cursor guardado en el archivo en PATH (/var/lib/systemd/journal-upload/state por defecto). Después de que una entrada se suba con éxito, actualiza este archivo con el cursor de esa entrada.

Añadido en la versión 239.

--follow[=BOOL]

Si se establece en sí, systemd-journal-upload espera entrada.

Añadido en la versión 239.

--key=

Toma una ruta a un archivo de clave SSL en formato PEM, o -. Si se establece -, se deshabilitará la verificación de autenticación del certificado del cliente. Por defecto es /etc/ssl/private/journal-upload.pem.

Añadido en la versión 239.

--cert=

Toma una ruta a un archivo de certificado SSL en formato PEM, o -. Si se establece -, se deshabilitará la verificación de autenticación del certificado del cliente. Por defecto es /etc/ssl/certs/journal-upload.pem.

Añadido en la versión 239.

--trust=

Toma una ruta a un archivo de certificado CA SSL en formato PEM, o -/all. Si se establece -/all, se deshabilitará la verificación del certificado. Por defecto es /etc/ssl/ca/trusted.pem.

Añadido en la versión 239.

-h, --help

Imprime un texto de ayuda corto y sale.

--version

Imprime una cadena de versión corta y sale.

ESTADO DE SALIDA

Al éxito, se devuelve 0; de lo contrario, se devuelve un código de error distinto de cero.

EJEMPLOS

Ejemplo 1. Configuración de certificados para autenticación

Se utilizan certificados firmados por una autoridad de confianza para verificar que el servidor al que se suben los mensajes es legítimo y viceversa, que el cliente es de confianza.

Un conjunto adecuado de certificados se puede generar con openssl. Nota, se recomiendan como mínimo 2048 bits de longitud de clave por motivos de seguridad:

openssl req -newkey rsa:2048 -days 3650 -x509 -nodes \
      -out ca.pem -keyout ca.key -subj '/CN=Certificate authority/'
cat >ca.conf <<EOF
[ ca ]
default_ca = this
[ this ]
new_certs_dir = .
certificate = ca.pem
database = ./index
private_key = ca.key
serial = ./serial
default_days = 3650
default_md = default
policy = policy_anything
[ policy_anything ]
countryName             = optional
stateOrProvinceName     = optional
localityName            = optional
organizationName        = optional
organizationalUnitName  = optional
commonName              = supplied
emailAddress            = optional
EOF
touch index
echo 0001 >serial
SERVER=server
CLIENT=client
openssl req -newkey rsa:2048 -nodes -out $SERVER.csr -keyout $SERVER.key -subj "/CN=$SERVER/"
openssl ca -batch -config ca.conf -notext -in $SERVER.csr -out $SERVER.pem
openssl req -newkey rsa:2048 -nodes -out $CLIENT.csr -keyout $CLIENT.key -subj "/CN=$CLIENT/"
openssl ca -batch -config ca.conf -notext -in $CLIENT.csr -out $CLIENT.pem

Los archivos generados ca.pem, server.pem y server.key deben instalarse en el servidor, y ca.pem, client.pem y client.key en el cliente. La ubicación de esos archivos se puede especificar mediante TrustedCertificateFile=, ServerCertificateFile= y ServerKeyFile= en /etc/systemd/journal-remote.conf y /etc/systemd/journal-upload.conf, respectivamente. Las ubicaciones predeterminadas se pueden consultar utilizando systemd-journal-remote --help y systemd-journal-upload --help.

NAME

systemd-journal-upload - Uploads journal entries to a remote syslog server

SYNOPSIS

systemd-journal-upload [OPTIONS...] [FILE...]

DESCRIPTION

systemd-journal-upload is a service that collects journal entries from the local system and uploads them to a remote syslog server. It is typically used to centralize logging for multiple systems.

The service reads journal entries from the specified files or from the current system journal if no files are given. It then sends these entries to a remote server configured via journal-upload.conf(5).

systemd-journal-upload supports various transmission protocols, including UDP, TCP, and TLS. The specific protocol and server address are configured in journal-upload.conf(5).

OPTIONS

--force
Forces the upload of all buffered journal entries, even if they have already been uploaded. This option is useful for re-uploading lost or corrupted entries.
--listen-address=ADDRESS
Specifies the network address to listen on for incoming journal entries. This is typically used in conjunction with systemd-journal-gatewayd.service(8).
--output=FILE
Writes the journal entries to the specified file instead of uploading them to a remote server. This option is useful for debugging and testing.
--rotate
Rotates the journal files before uploading. This is useful for preventing excessively large journal files.
--version
Prints the version of systemd-journal-upload and exits.
-h, --help
Prints a short help message and exits.

EXIT STATUS

Returns 0 if the operation was successful, and a non-zero value otherwise.

EXAMPLES

# Upload all journal entries to the configured remote server
systemd-journal-upload

# Force re-upload of all journal entries
systemd-journal-upload --force

# Write journal entries to a file instead of uploading
systemd-journal-upload --output=journal.log
