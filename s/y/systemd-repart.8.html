NOMBRE

systemd-repart, systemd-repart.service - Crece y añade particiones automáticamente, y genera imágenes de disco (DDI)

SINOPSIS

systemd-repart [OPCIONES...] [[DISPOSITIVOBLOQUE]...]

systemd-repart.service

DESCRIPCIÓN

systemd-repart crea tablas de particiones, y añade o crece particiones, basándose en los archivos de configuración descritos en repart.d(5).

systemd-repart se utiliza al *construir* imágenes del SO, y también al *desplegar* imágenes para ajustarlas automáticamente, durante el arranque, al sistema en el que se están ejecutando. De esta manera, la imagen puede ser mínima en tamaño y puede ser aumentada automáticamente al arrancar, apoderándose del espacio en disco disponible.

Si se invoca sin argumentos, systemd-repart opera sobre el dispositivo de bloque que soporta la partición del sistema de archivos raíz del SO en ejecución, aumentando así las particiones del propio SO arrancado. Cuando se llama en el initrd, opera sobre el dispositivo de bloque que soporta /sysroot/, es decir, sobre el dispositivo de bloque al que el sistema hará la transición pronto. Si se utiliza --image=, operará sobre el dispositivo o archivo de imagen especificado. El servicio systemd-repart.service se ejecuta generalmente al arrancar en el initrd, con el fin de aumentar la tabla de particiones del SO antes de que sus particiones sean montadas.

Las operaciones de systemd-repart son mayormente incrementales: crece particiones existentes o añade nuevas, pero no reduce, elimina ni mueve particiones existentes. El servicio está diseñado para ejecutarse en cada arranque, pero cuando detecta que la tabla de particiones ya coincide con los archivos de configuración de repart.d/*.conf instalados, no ejecuta ninguna operación.

Los siguientes casos de uso se encuentran entre los cubiertos:

•La partición raíz puede crecer para cubrir todo el espacio de disco disponible.
•Se puede añadir una partición /home/, swap, o /srv/.
•Se puede añadir una segunda (o tercera, ...) partición raíz, para cubrir configuraciones de estilo A/B donde se utiliza alternativamente una segunda versión del sistema de archivos raíz para implementar esquemas de actualización. La imagen desplegada solo llevaría una única partición ("A") pero en el primer arranque se crearía automáticamente una segunda partición ("B") para este propósito.

El algoritmo ejecutado por systemd-repart es aproximadamente el siguiente:

1.Los archivos de configuración repart.d/*.conf se cargan y analizan, y se ordenan por nombre de archivo (sin el prefijo del directorio). Para cada archivo de configuración, se cargan archivos de tipo "drop-in" de directorios con el mismo nombre que el archivo de configuración al que se le añade el sufijo ".d".
2.La tabla de particiones en el dispositivo de bloque se carga y analiza, si está presente.
3.Las particiones existentes en la tabla de particiones se asocian con los archivos repart.d/*.conf por el UUID del tipo de partición GPT. La primera partición existente de un tipo específico se asigna al primer archivo de configuración que declara el mismo tipo. La segunda partición existente de un tipo específico se asigna entonces al segundo archivo de configuración que declara el mismo tipo, y así sucesivamente. Después de que esta asignación iterativa se completa, cualquier partición existente que no tenga un archivo de configuración coincidente se considera "ajena" y se deja tal cual. Y cualquier archivo de configuración para el que no se haya asociado ninguna partición se trata como una solicitud para crear una partición.
4.Las particiones que se crearán ahora se asignan en el disco, teniendo en cuenta las restricciones de tamaño y los pesos declarados en los archivos de configuración. Se utiliza el espacio libre dentro de los límites establecidos por las solicitudes de tamaño y relleno. Además, se aumentan las particiones existentes que deben crecer. Las nuevas particiones siempre se añaden al final de la tabla de particiones, ocupando la primera ranura de tabla de particiones cuyo índice sea mayor que los índices de todas las particiones existentes. Las particiones nunca se reordenan y, por lo tanto, los números de partición permanecen estables. Cuando se crean particiones, se colocan en el área de espacio libre más pequeña que sea lo suficientemente grande como para satisfacer los límites de tamaño y relleno. Esto significa que las particiones pueden tener un orden diferente en el disco que en la tabla de particiones. Tenga en cuenta que esta asignación se realiza solo en memoria, la tabla de particiones en el disco aún no se ha actualizado.
5.Todas las particiones existentes para las que existen archivos de configuración y que actualmente no tienen una etiqueta de partición GPT establecida recibirán una etiqueta, ya sea explícitamente configurada en la configuración o —si falta— derivada automáticamente del tipo de partición. Lo mismo se hace para todas las particiones que se crean nuevas. Estas asignaciones se realizan solo en memoria, tampoco, el disco aún no se ha actualizado.
6.De manera similar, todas las particiones existentes para las que existen archivos de configuración y que actualmente tienen un UUID identificador de ceros se les asignará un nuevo UUID. Este UUID se hashea criptográficamente a partir de un valor de semilla común junto con el UUID del tipo de partición (y un contador en caso de que se definan múltiples particiones del mismo tipo), ver más abajo. Lo mismo se hace para todas las particiones que se crean de nuevo. Estas asignaciones se realizan solo en memoria, tampoco, el disco aún no se ha actualizado.
7.De manera similar, si el UUID del volumen del disco son todos ceros, también se inicializa, hasheado criptográficamente a partir del mismo valor de semilla común. Esto también se realiza solo en memoria.
8.El espacio en disco asignado a nuevas particiones (es decir, lo que antes era espacio libre) ahora se borra. Específicamente, se eliminan todas las firmas de sistema de archivos y, si el dispositivo lo soporta, se emite el comando de control de E/S BLKDISCARD para informar al hardware de que el espacio está ahora vacío. Además, cualquier "relleno" entre particiones y al final del dispositivo se borra de manera similar.
9.Finalmente, la nueva tabla de particiones se escribe en el disco. Se le pide al kernel que relea la tabla de particiones.

Como excepción a la operación incremental normal, cuando se llama en un modo especial de "restablecimiento de fábrica", systemd-repart puede utilizarse para borrar particiones existentes y restablecer una instalación a los valores predeterminados del fabricante. Este modo de operación se utiliza cuando se pasa el interruptor --factory-reset=yes en la línea de comandos de la herramienta, o se especifica la opción systemd.factory_reset=yes en la línea de comandos del kernel, o la variable EFI FactoryResetRequest (UUID del proveedor 8cf2644b-4b0b-428f-9387-6d876050dc67) se establece en "yes". Altera ligeramente el algoritmo anterior: entre el tercer y el cuarto paso anterior, cualquier partición marcada explícitamente a través del booleano FactoryReset= se elimina y el algoritmo se reinicia, recreando así inmediatamente estas particiones vacías.

Tenga en cuenta que systemd-repart por defecto solo cambia las tablas de particiones, no crea ni redimensiona ningún sistema de archivos dentro de estas particiones, a menos que se especifique la opción de configuración Format=. Tenga en cuenta también que existen mecanismos separados para este propósito, por ejemplo systemd-growfs(8) y systemd-makefs.

Los UUID que identifican las nuevas particiones creadas (o asignadas a particiones existentes que aún no tienen UUID), así como el disco en su conjunto, se hashean criptográficamente a partir de un valor de semilla común. Este valor de semilla suele ser el machine-id(5) del sistema, por lo que el ID de la máquina determina de forma reproducible los UUID asignados a todas las particiones. Si el ID de la máquina no se puede leer (o el usuario pasa --seed=random, véase más abajo) la semilla se genera aleatoriamente en su lugar, de modo que los UUID de las particiones también son efectivamente aleatorios. El valor de la semilla también se puede establecer explícitamente, formateado como UUID mediante la opción --seed=. Al hashear estos UUID a partir de una semilla común, las imágenes preparadas con esta herramienta se vuelven reproducibles y el resultado del algoritmo anterior es determinista.

El argumento posicional debe especificar el dispositivo de bloque o un archivo regular sobre el que operar. Si se especifica --empty=create, la ruta especificada se crea como un archivo regular, lo cual es útil para generar imágenes de disco desde cero.

OPCIONES

Se entienden las siguientes opciones:

--dry-run=

Toma un valor booleano. Si este interruptor no se especifica, se asume --dry-run=yes por defecto. Controla si systemd-repart ejecuta las operaciones de re-particionado solicitadas o si solo debe mostrar lo que haría. A menos que se especifique --dry-run=no, systemd-repart no tocará realmente la tabla de particiones del dispositivo.

Añadido en la versión 245.

--empty=

Toma uno de "refuse", "allow", "req
uire", "force" o "create". Controla cómo operar en dispositivos de bloque que están completamente vacíos, es decir, que aún no contienen una tabla de particiones/etiqueta de disco. Si no se especifica esta opción, el valor predeterminado implícito es "refuse".

Si se establece en "refuse", systemd-repart requiere que el dispositivo de bloque sobre el que operará ya contenga una tabla de particiones y se niega a operar si no encuentra ninguna. Si se establece en "allow", el comando extenderá una tabla de particiones existente o creará una nueva si no existe. Si se establece en "require", el comando creará una nueva tabla de particiones si no existe hasta el momento y se negará a operar si ya existe una. Si se establece en "force", creará una nueva tabla de particiones incondicionalmente, borrando completamente el disco en efecto. Si se establece en "force", no se tendrán en cuenta ni sobrevivirán las particiones existentes. Por lo tanto, úselo con cuidado, es una excelente manera de perder todos sus datos. Si se establece en "create", se creará un nuevo archivo de loopback en la ruta pasada a través del parámetro del nodo del dispositivo, del tamaño indicado con --size=, véase más abajo.

Añadido en la versión 245.

--discard=

Toma un valor booleano. Si no se especifica esta opción, el valor predeterminado implícito es --discard=yes. Controla si se emite el comando de control de E/S BLKDISCARD sobre el espacio ocupado por las particiones añadidas o sobre el espacio entre ellas. Normalmente, es una buena idea emitir esta solicitud, ya que le dice al hardware subyacente que los bloques cubiertos deben considerarse vacíos, mejorando el rendimiento. Si opera sobre un archivo regular en lugar de un nodo de dispositivo de bloque, se genera un archivo disperso.

Añadido en la versión 245.

--size=

Toma un tamaño en bytes, utilizando los sufijos habituales K, M, G, T, o el valor especial "auto". Si se utiliza, la ruta del nodo de dispositivo especificada debe referirse a un archivo regular, que luego se ampliará al tamaño especificado si es menor, antes de realizar cualquier cambio en la tabla de particiones. Si se especifica como "auto", el tamaño mínimo de la imagen del disco se determinará automáticamente (es decir, se sumarán los tamaños mínimos de todas las particiones, teniendo en cuenta el espacio para metadatos adicionales). Esta opción no es compatible si el nodo especificado es un dispositivo de bloque. Esta opción no tiene ningún efecto si el archivo ya tiene el tamaño especificado o es más grande. El tamaño especificado se redondea implícitamente a múltiplos de 4096. Cuando se utiliza con --empty=create, especifica el tamaño inicial del archivo de loopback a crear.

La opción --size=auto tiene en cuenta los tamaños de las particiones preexistentes. Sin embargo, no tiene en cuenta las tablas de particiones que no están densamente empaquetadas: las particiones configuradas podrían no caber en el dispositivo subyacente si existe espacio vacío entre particiones preexistentes (o antes de la primera partición) que no puede ser completamente llenado por las particiones a ampliar o crear.

Tenga en cuenta también que la determinación automática del tamaño no tiene en cuenta los archivos o directorios especificados con CopyFiles=: la operación podría fallar si los archivos o directorios especificados requieren más espacio en disco que el límite mínimo de tamaño por partición configurado.

Añadido en la versión 246.

--factory-reset=

Toma un valor booleano. Si no se especifica esta opción, el valor predeterminado implícito es --factory-reset=no. Controla si se opera en modo "restablecimiento de fábrica", véase más arriba. Si se establece en true, se eliminarán todas las particiones existentes marcadas con FactoryReset= establecido en sí temprano mientras se ejecuta el algoritmo de re-particionado. Úselo con cuidado, es una excelente manera de perder todos sus datos. Tenga en cuenta que los archivos de partición deben activar explícitamente FactoryReset=, ya que la opción tiene como valor predeterminado apagado. Si ninguna partición está marcada para restablecimiento de fábrica, esta opción no tendrá ningún efecto. Tenga en cuenta que existen otros dos métodos para solicitar la operación de restablecimiento de fábrica: a través de la línea de comandos del kernel y a través de una variable EFI, véase más arriba.

Añadido en la versión 245.

--can-factory-reset

Si se especifica esta opción, el disco no se vuelve a particionar. En su lugar, se determina si alguna de las particiones existentes está marcada con FactoryReset=. Si las hay, la herramienta saldrá con el estado de salida cero, de lo contrario, con un estado de salida distinto de cero. Esta opción se puede utilizar para determinar rápidamente si el sistema en ejecución admite un mecanismo de restablecimiento de fábrica basado en systemd-repart.

Añadido en la versión 245.

--root=

Toma una ruta a un directorio para usar como sistema de archivos raíz al buscar archivos repart.d/*.conf, para el archivo de ID de máquina a utilizar como semilla y para los archivos y directorios de origen CopyFiles= y CopyBlocks=. Por defecto, cuando se invoca en el sistema normal, este valor por defecto es el sistema de archivos raíz de host /. Si se invoca desde initrd, este valor por defecto es /sysroot/, de modo que la herramienta opere sobre la configuración y el ID de máquina almacenados en el sistema de archivos raíz que luego se transiciona a sí mismo.

Consulte --copy-source= para una opción más restringida que solo afecta a CopyFiles=.

Añadido en la versión 245.

--image=

Toma una ruta a un archivo de imagen de disco o dispositivo para montarlo y usarlo de manera similar a --root=, véase más arriba.

Añadido en la versión 249.

--image-policy=policy

Toma una cadena de política de imagen como argumento, según systemd.image-policy(7). La política se aplica al operar en la imagen de disco especificada a través de --image=, véase más arriba. Si no se especifica, el valor predeterminado es la política "*", es decir, se utilizan todos los sistemas de archivos reconocidos en la imagen.

--seed=

Toma un UUID como argumento o el valor especial random. Si se especifica un UUID, los UUID que se asignarán a las particiones y a la propia tabla de particiones se derivan mediante hash criptográfico de él. Si no se especifica, se intenta leer el ID de máquina del host (o más precisamente, el directorio raíz configurado a través de --root=) y usarlo como semilla en su lugar, recurriendo a una semilla aleatoria en caso contrario. Use --seed=random para forzar una semilla aleatoria. Especificar explícitamente la semilla puede usarse para generar tablas de particiones estrictamente reproducibles.

Añadido en la versión 245.

--pretty=

Toma un argumento booleano. Si no se especifica esta opción, por defecto está activada cuando se llama desde una terminal interactiva y desactivada en caso contrario. Controla si se muestra una tabla y gráfica amigables para el usuario que ilustren los cambios aplicados.

Añadido en la versión 245.

--definitions=

Toma una ruta de sistema de archivos. Si se especifica, los archivos *.conf se leen del directorio especificado en lugar de buscar en /usr/lib/repart.d/*.conf, /etc/repart.d/*.conf, /run/repart.d/*.conf.

Este parámetro se puede especificar varias veces.

Añadido en la versión 245.

--key-file=

Toma una ruta de sistema de archivos. Configura la clave de cifrado a utilizar al configurar volúmenes LUKS2 configurados con la opción Encrypt=key-file en los archivos de partición. Debe referirse a un archivo regular que contenga la clave, o a un socket de transmisión AF_UNIX en el sistema de archivos. En este último caso, se establece una conexión a él y se lee la clave de él. Si no se especifica esta opción, se utiliza la clave vacía (es decir, clave de longitud cero). Este comportamiento es útil para configurar particiones cifradas durante el primer arranque, que solo reciben su contraseña proporcionada por el usuario en un paso de configuración posterior.

Añadido en la versión 247.

--private-key=

Toma una ruta de sistema de archivos o una designación específica del motor o proveedor. Configura la clave de firma a utilizar al crear particiones de firma de veracidad con la opción Verity=signature en los archivos de partición.

Añadido en la versión 252.

--private-key-source=

Toma una de las opciones "file", "engine" o "provider". En los dos últimos casos, va seguida del nombre de un proveedor o motor, separado por dos puntos, que se pasará a la lógica de "engine" o "provider" de OpenSSL. Configura cómo cargar la clave privada a utilizar al crear particiones de firma de veracidad con la opción Verity=signature en los archivos de partición.

Añadido en la versión 256.

--certificate=

Toma una ruta de sistema de archivos o una designación específica del proveedor. Configura el certificado X.509 codificado en PEM a utilizar al crear particiones de firma de veracidad con la opción Verity=signature en los archivos de partición.

Añadido en la versión 252.

--certificate-source=

Toma una de las opciones "file", o "provider". En este último caso, va seguida del nombre de un proveedor, separado por dos puntos, que se pasará a la lógica de "provider" de OpenSSL. Configura cómo cargar el certificado X.509 a utilizar al crear particiones de firma de veracidad con la opción Verity=signature en los archivos de partición.

Añadido en la versión 257.

--join-signature=

Especifica una tupla separada por dos puntos con un hash de veracidad de nivel superior codificado en hexadecimal de una partición Verity=hash como primer elemento, y una firma PKCS7 del roothash como ruta a un archivo de firma codificado en DER, o como una cadena de codificación base64 ASCII de una firma codificada en DER prefijada con "base64:". Se utilizará en una imagen preexistente creada con un parámetro como --defer-partitions=root-verity-sig, para permitir la firma sin conexión de la partición de firma de veracidad.

Esta es una alternativa a la firma en línea utilizando parámetros como --private-key=, para sistemas de compilación donde la clave privada para la firma de producción no está disponible en el mismo contexto donde se crea el contenido.

Añadido en la versión 258.

--tpm2-pcrlock=PATH

Configura una política TPM2 pcrlock para vincular esystemd-repart -r /run/image/disk.raw --dry-run --no-write-clone --directory=/usr/lib/kernel-install/ \ --definitions=/usr/lib/kernel-install/50-repart.conf ```

--apply-image=PATH

Aplica las definiciones de partición en el archivo de imagen dado. Esta opción se puede especificar varias veces para aplicar definiciones de cada una de las imágenes dadas. Las particiones copiadas tendrán el mismo tamaño, metadatos y contenido, pero pueden tener un número de partición diferente y pueden estar ubicadas en un desplazamiento diferente en la tabla de particiones de destino. Estas definiciones se pueden combinar con las definiciones de partición leídas de los archivos de definición de partición normales. Las definiciones sintetizadas tienen precedencia sobre las definiciones leídas de los archivos de definición de partición.

--tpm-key-usage=USAGE

Especifica el uso de la clave de TPM. Solo se aplica cuando se utiliza systemd-cryptenroll.

Se añadió en la versión 255.

--tpm-key-flags=FLAGS

Especifica las banderas de la clave de TPM. Solo se aplica cuando se utiliza systemd-cryptenroll.

Se añadió en la versión 255.

--tpm-key-blob=BLOB

Especifica el blob de clave de TPM. Solo se aplica cuando se utiliza systemd-cryptenroll.

Se añadió en la versión 255.

--tpm-key-auth=AUTH

Especifica la autenticación de la clave de TPM. Solo se aplica cuando se utiliza systemd-cryptenroll.

Se añadió en la versión 255.

--tpm-key-scheme=SCHEME

Especifica el esquema de clave de TPM. Solo se aplica cuando se utiliza systemd-cryptenroll.

Se añadió en la versión 255.

--tpm-key-protected=BOOL

Especifica si la clave de TPM está protegida. Solo se aplica cuando se utiliza systemd-cryptenroll.

Se añadió en la versión 255.

--tpm-key-pin=PIN

Especifica el PIN de la clave de TPM. Solo se aplica cuando se utiliza systemd-cryptenroll.

Se añadió en la versión 255.

--tpm-key-puk=PUK

Especifica el PUK de la clave de TPM. Solo se aplica cuando se utiliza systemd-cryptenroll.

Se añadió en la versión 255.

--tpm-key-auth-data=DATA

Especifica los datos de autenticación de la clave de TPM. Solo se aplica cuando se utiliza systemd-cryptenroll.

Se añadió en la versión 255.

--split=BOOL

Habilita la generación de artefactos divididos a partir de particiones configuradas con SplitName=. Si está habilitado, para cada partición con SplitName= establecido, se genera un archivo de salida separado que contiene solo el contenido de esa partición. El nombre del archivo de salida consiste en el nombre del archivo de bucle invertido con el sufijo del nombre configurado con SplitName=. Si el nombre del archivo de bucle invertido termina en ".raw", el sufijo se inserta antes de la extensión ".raw".

Tenga en cuenta que --split es independiente de --dry-run. Incluso si --dry-run está habilitado, los artefactos divididos se generarán a partir de una imagen existente si --split está habilitado.

Se añadió en la versión 252.

--include-partitions=PARTICIONES, --exclude-partitions=PARTICIONES

Estas opciones especifican en qué tipos de partición operará systemd-repart. Si se utiliza --include-partitions=, todas las particiones que no se especifican quedan excluidas. Si se utiliza --exclude-partitions=, todas las particiones que se especifican quedan excluidas. Ambas opciones toman una lista separada por comas de UUIDs de tipo de partición GPT o identificadores (ver Type= en repart.d(5)).

Se añadió en la versión 253.

--defer-partitions=PARTICIONES

Esta opción especifica para qué tipos de partición debe diferir systemd-repart. Todas las particiones que se difieren usando esta opción todavía se tienen en cuenta al calcular los tamaños y desplazamientos de otras particiones, pero no se escriben realmente en la imagen del disco. El efecto neto de esta opción es que si ejecuta systemd-repart nuevamente sin esta opción, las particiones faltantes se agregarán como si no hubieran sido diferidas la primera vez que se ejecutó systemd-repart.

Se añadió en la versión 253.

--sector-size=BYTES

Esta opción permite configurar el tamaño del sector de la imagen producida por systemd-repart. Toma un valor que es una potencia de "2" entre "512" y "4096". Esta opción es útil al construir imágenes para discos que usan un tamaño de sector diferente al disco en el que se produce la imagen.

Se añadió en la versión 253.

--architecture=ARCH

Esta opción permite anular la arquitectura utilizada para tipos de partición específicos de la arquitectura. Por ejemplo, si se establece en "arm64", un tipo de partición "root-x86-64" referenciado en los drop-in de repart.d/ se parcheará dinámicamente para referirse a "root-arm64" en su lugar. Toma uno de "alpha", "arc", "arm", "arm64", "ia64", "loongarch64", "mips-le", "mips64-le", "parisc", "ppc", "ppc64", "ppc64-le", "riscv32", "riscv64", "s390", "s390x", "tilegx", "x86" o "x86-64".

Se añadió en la versión 254.

--offline=BOOL

Instruye a systemd-repart para construir la imagen sin conexión. Toma un booleano o "auto". Por defecto es "auto". Si está habilitado, la imagen se construye sin usar dispositivos de bucle. Esto es útil para construir imágenes sin privilegios o cuando los dispositivos de bucle no están disponibles. Si está deshabilitado, la imagen se construye siempre utilizando dispositivos de bucle. Si es "auto", systemd-repart construirá la imagen en línea si es posible y recurrirá a construir la imagen sin conexión si los dispositivos de bucle no están disponibles o no se puede acceder a ellos debido a permisos faltantes.

Se añadió en la versión 254.

--copy-from=PATH

Instruye a systemd-repart para sintetizar definiciones de partición de la tabla de particiones en la imagen o dispositivo dado. Esta opción se puede especificar varias veces para sintetizar definiciones de cada una de las imágenes o dispositivos dados. Las definiciones generadas copiarán las particiones en la tabla de particiones de destino. Las particiones copiadas tendrán el mismo tamaño, metadatos y contenido, pero pueden tener un número de partición diferente y pueden estar ubicadas en un desplazamiento diferente en la tabla de particiones de destino. Estas definiciones se pueden combinar con definiciones de partición leídas de archivos de definición de partición normales. Las definiciones sintetizadas tienen precedencia sobre las definiciones leídas de los archivos de definición de partición.

Se añadió en la versión 255.

--copy-source=PATH, -s PATH

Especifica un directorio de origen del cual se considerarán todas las rutas de origen de CopyFiles=. Esto es similar a --root=, pero se aplica exclusivamente a la configuración CopyFiles=. Si se usan --root= y --copy-source= en combinación, el primero se aplica como de costumbre, excepto para CopyFiles=, donde el segundo tiene precedencia.

Se añadió en la versión 255.

--make-ddi=TYPE

Toma uno de "sysext", "confext" o "portable". Genera una Imagen de Disco Descubrible (DDI) para una extensión de sistema (sysext, ver systemd-sysext(8) para detalles), extensión de configuración (confext) o Servicios Portátiles[1]. La imagen generada consistirá en un sistema de archivos "erofs" firmado Verity como partición raíz. En este modo de operación, las definiciones de partición en /usr/lib/repart.d/*.conf y directorios relacionados no se leen, y --definitions= no es compatible, ya que se elegirán automáticamente las definiciones apropiadas para la clase DDI seleccionada.

Debe usarse junto con --copy-source= para especificar la jerarquía de archivos para poblar la DDI. El directorio especificado debe contener un subdirectorio etc/ si se selecciona "confext". Si se selecciona "sysext", debe contener un directorio usr/ o opt/, o ambos. Si se usa "portable", se puede proporcionar una jerarquía completa de archivos del sistema operativo.

Esta opción implica --empty=create, --size=auto y --seed=random (los dos últimos se pueden anular).

La clave privada y el certificado para firmar la DDI deben especificarse mediante los modificadores --private-key= y --certificate=.

Se añadió en la versión 255.

-S, -C, -P

Atajos para --make-ddi=sysext, --make-ddi=confext, --make-ddi=portable, respectivamente.

Se añadió en la versión 255.

--append-fstab=

Toma uno de "no", "auto" o "replace". Controla cómo el archivo fstab(5) generado por --generate-fstab= se comportará en caso de que exista un archivo preexistente.

Si es "no", systemd-repart se quejará y abortará en caso de que exista un archivo. Este es el comportamiento predeterminado. Si es "replace", el archivo será reemplazado silenciosamente por el nuevo generado.

Si es "auto", systemd-repart buscará en el archivo preexistente la sección que pertenece al contenido generado automáticamente y la reemplazará con el contenido generado más reciente, y conservará la sección proporcionada por el usuario si existe una. La sección generada se identifica buscando el contenido automático rodeado por "# Start section ↓ of automatically generated fstab by systemd-repart" y "# End section ↑ of automatically generated fstab by systemd-repart". El contenido que está antes y después de esos comentarios se considera proporcionado por el usuario y se conserva en el nuevo archivo.

Se añadió en la versión 258.

--generate-fstab=PATH

Especifica una ruta donde escribir las entradas de fstab(5) para los puntos de montaje configurados con MountPoint= en el directorio raíz especificado con --copy-source= o --root= o en el directorio raíz del host si no se especifica ninguno. Deshabilitado por defecto.

Se añadió en la versión 256.

--generate-crypttab=PATH

Especifica una ruta donde escribir las entradas de crypttab para los volúmenes cifrados configurados con EncryptedVolume= en el directorio raíz especificado con --copy-source= o --root= o en el directorio raíz del host si no se especifica ninguno. Deshabilitado por defecto.

Se añadió en la versión 256.

--list-devices

Muestra una lista de dispositivos de bloque candidatos sobre los que este comando puede operar. Específicamente, enumera los dispositivos de bloque actualmente presentes que admiten tablas de particiones, y muestra sus rutas de nodos de dispositivo junto con cualquiera de sus enlaces simbólicos.

Se añadió en la versión 257.

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.

--no-pager

No canaliza la salida a un paginador.

--no-legend

No imprime la leyenda, es decir, las cabeceras de las columnas y el pie de página con pistas.

--json=MODE

Muestra la salida formateada como JSON. Espera uno de "short" (para la salida más corta posible sin espacios en blanco redundantes o saltos de línea), "pretty" (para una versión bonita de la misma, con indentación y saltos de línea) o "off" (para desactivar la salida JSON, el valor predeterminado).

En caso de éxito, se devuelve 0, y un código de error distinto de cero en caso contrario.

Ejemplo 1. Generar una imagen de extensión de configuración

Lo siguiente crea una DDI de extensión de configuración (confext) para una actualización de /etc/motd:

mkdir -p tree/etc/extension-release.d

ID=fedora

  --private-key=verity-private-key.pem \

mkdir -p tree/usr/lib/extension-release.d
echo "Hola Mundo" >tree/usr/foo

NAME

                    
systemd-repart — Tool for automatically partitioning block devices

                

                
                

                    
SYNOPSIS

                    
systemd-repart [OPTIONS...] [DEVICE]

                

                
                

                    
DESCRIPTION

                    
systemd-repart is a tool that partitions a block device
                        (like a USB stick, SD card, or a disk image file) based on a set of
                        partitioning definitions. It is primarily used to create OS images for
                        portable systems, such as those based on systemd's
                        portable service images feature.

                    
The partitioning definitions are read from a directory specified
                        using the --definitions= option, or
                        from /etc/repart.d/, /usr/lib/repart.d/,
                        and /run/repart.d/ by default. These definitions
                        reside in .conf files and describe the desired
                        partitions, their types, file systems, and size constraints.

                    
By default, systemd-repart operates on the
                        block device specified by the DEVICE argument. If
                        omitted, it attempts to partition the root device of the system,
                        usually /dev/mmcblk0 or /dev/sda,
                        if it is a removable device.

                    
The tool supports creating various partition types and file systems,
                        including ext4, erofs, f2fs,
                        btrfs, xfs, and FAT variants. It
                        also has built-in support for dm-verity, allowing the creation
                        of read-only, verifiable file systems.

                    
When creating dm-verity partitions,
                        systemd-repart can generate the necessary metadata
                        (hash tree and signature) directly or use pre-generated files. It can
                        also integrate with cryptographic hardware modules (PKCS#11) for signing.

                    
The --json= option can be used to
                        output detailed information about the generated partitions, which can be
                        useful for scripting and integration with other tools.

                

                
                

                    
OPTIONS

                    
The following options are understood:

                    

                        
-d, --definitions=

                        
Load partitioning definitions from the specified directory instead of the
                            default locations.

                        
-A, --allow-empty

                        
Allow partitioning an empty or unformatted block device.

                        
--empty=

                        
Control behavior when partitioning an empty device. Accepts
                            create (create partitions as defined),
                            no (do not create any partitions), or
                            auto (default; create partitions if definitions
                            are found).

                        
--json=

                        
Generate output in JSON format. Accepts short,
                            pretty, or off.

                        
-s, --copy-source=

                        
Copy files from the specified source directory into the generated file
                            system(s).

                        
--defer-partitions=

                        
A comma-separated list of partition types that should be created after
                            all other partitions. This is useful for partitions that depend on
                            data from other partitions, like signatures.

                        
--join-signature=

                        
When creating a partition of type ...-sig, this
                            option allows joining the data from a prior partition (e.g., a hash
                            tree) with a separate signature file. The format is
                            HASH_DATA:SIGNATURE_FILE.

                        
--root-hash=

                        
Specify the hash of the root file system. This is used when generating
                            dm-verity signatures.

                        
--private-key-source=

                        
Specify the source for the private key used for signing dm-verity
                            data. Accepts engine:pkcs11 for PKCS#11 tokens.

                        
--private-key=

                        
Path to the private key file or PKCS#11 URI for signing.

                        
--certificate=

                        
Path to the certificate file used for signing.

                        
--remove-digits

                        
Remove leading digits from partition labels.

                        
--dry-run=

                        
Perform a trial run with the given options without making any changes.
                            Accepts yes, no, or
                            metadata.

                        
--size=

                        
Set the total size of the block device to be created. Useful when
                            working with image files.

                        
-h, --help

                        
Print a help message and exit.

                        
-V, --version

                        
Print version information and exit.

                    

                

                
                

                    
EXIT STATUS

                    
systemd-repart exits with status 0 on success, and
                        non-zero otherwise.

                

                
                

                    
EXAMPLE

                    
Example 1. Create a bootable USB drive with
                        multiple partitions

                    

                        
# Create a directory for the portable image content
mkdir -p /tmp/my-portable-image/usr/lib/extension-release.d/
# Define the image metadata
cat >/tmp/my-portable-image/usr/lib/extension-release.d/extension-release.my-foo <<EOF
ID=fedora
VERSION_ID=38
IMAGE_ID=my-foo
IMAGE_VERSION=7
EOF
# Create the image file and partition it
systemd-repart --copy-source=/tmp/my-portable-image/ --size=10G --empty=create my-portable-image.img

                    

                    
This command creates a 10GB image file named
                        my-portable-image.img and partitions it according to
                        the definitions found in /etc/repart.d/,
                        /usr/lib/repart.d/, and /run/repart.d/.
                        It also copies the contents of /tmp/my-portable-image/
                        into the generated file system(s).

                    
Example 2. Generate a dm-verity protected portable
                        extension image

                    
This example demonstrates creating a portable extension image with
                        dm-verity protection, signing it using a PKCS#11
                        token.

                    

                        
# Prepare the extension content
mkdir -p tree/usr/lib/extension-release.d/
cat >tree/usr/lib/extension-release.d/extension-release.my-foo <<EOF
ID=fedora
VERSION_ID=38
IMAGE_ID=my-foo
IMAGE_VERSION=7
EOF
# Create the dm-verity protected extension image
systemd-repart --make-ddi=sysext \
  --private-key-source=engine:pkcs11 \
  --private-key="pkcs11:model=PKCS%2315%20emulated;manufacturer=piv_II;serial=0123456789abcdef;token=Some%20Cert" \
  --certificate=verity-certificate.pem \
  -s tree/ \
  /var/lib/extensions/my-foo.sysext.raw
# Refresh systemd-sysext to recognize the new extension
systemd-sysext refresh

                    

                    
The DDI generated this way may be applied to the system with
                        systemd-sysext(8).

                    
Example 3. Generate a dm-verity signature offline
                        and append it to a pre-built image

                    
The following creates an image with dm-verity metadata, signs it
                        separately to simulate an offline signing system, and then appends the
                        signature to the image:

                    

                        
mkdir -p repart.d/ /tmp/tree/usr/lib/
cat >/tmp/tree/usr/lib/os-release <<EOF
ID=debian
VERSION_ID=13
EOF
cat >repart.d/10-root.conf <<EOF
[Partition]
Type=root
Format=erofs
SizeMinBytes=100M
SizeMaxBytes=100M
Verity=data
VerityMatchKey=root
EOF
cat >repart.d/11-root-verity.conf <<EOF
[Partition]
Type=root-verity
Label=%o_%w_verity
Verity=hash
VerityMatchKey=root
SizeMinBytes=400M
SizeMaxBytes=400M
EOF
cat >repart.d/12-root-verity-sig.conf <<EOF
[Partition]
Type=root-verity-sig
Label=%o_%w_verity_sig
Verity=signature
VerityMatchKey=root
EOF
systemd-repart --definitions repart.d \
  --defer-partitions=root-verity-sig \
  --copy-source=/tmp/tree/ \
  --empty=create --size=600M \
  --json=short \
  /tmp/img.raw | | jq --raw-output0 .[-1].roothash > /tmp/img.roothash
openssl smime -sign -in /tmp/img.roothash \
  -inkey verity-private-key.pem \
  -signer verity-certificate.pem \
  -noattr -binary -outform der \
  -out /tmp/img.roothash.p7s
systemd-repart --definitions repart.d \
  --dry-run=no --root=/tmp/tree/ \
  --join-signature="$(cat /tmp/img.roothash):/tmp/img.roothash.p7s" \
  --certificate=verity-certificate.pem \
  /tmp/img.raw
