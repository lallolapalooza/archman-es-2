sync_file_range(2) Manual de llamadas al sistema sync_file_range(2)

NOMBRE

sync_file_range - sincroniza un segmento de archivo con el disco

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE         /* Ver feature_test_macros(7) */
#define _FILE_OFFSET_BITS 64
#include <fcntl.h>
int sync_file_range(int fd, off_t offset, off_t nbytes,
                    unsigned int flags);

DESCRIPCIÓN

sync_file_range() permite un control fino al sincronizar el archivo abierto al que se refiere el descriptor de archivo fd con el disco.

offset es el byte de inicio del rango de archivo a sincronizar. nbytes especifica la longitud del rango a sincronizar, en bytes; si nbytes es cero, entonces se sincronizan todos los bytes desde offset hasta el final del archivo. La sincronización se realiza en unidades del tamaño de página del sistema: offset se redondea hacia abajo al límite de página; (offset+nbytes-1) se redondea hacia arriba al límite de página.

El argumento de máscara de bits flags puede incluir cualquiera de los siguientes valores:

SYNC_FILE_RANGE_WAIT_BEFORE
Espera la escritura de todas las páginas en el rango especificado que ya han sido enviadas al controlador del dispositivo para su escritura antes de realizar cualquier escritura.
SYNC_FILE_RANGE_WRITE
Inicia la escritura de todas las páginas sucias en el rango especificado que no están actualmente enviadas para escritura. Ten en cuenta que incluso esto puede bloquearse si intentas escribir más que el tamaño de la cola de solicitudes.
SYNC_FILE_RANGE_WAIT_AFTER
Espera la escritura de todas las páginas en el rango después de realizar cualquier escritura.

Se permite especificar flags como 0, como una operación nula.

Advertencia

Esta llamada al sistema es extremadamente peligrosa y no debe usarse en programas portátiles. Ninguna de estas operaciones escribe los metadatos del archivo. Por lo tanto, a menos que la aplicación esté estrictamente sobrescribiendo bloques de disco ya existentes, no hay garantía de que los datos estarán disponibles después de un bloqueo. No hay interfaz de usuario para saber si una escritura es puramente una sobrescritura. En sistemas de archivos que utilizan semántica de copia en escritura (por ejemplo, btrfs), la sobrescritura de bloques asignados existentes es imposible. Al escribir en espacio preasignado, muchos sistemas de archivos también requieren llamadas al asignador de bloques, que esta llamada al sistema no sincroniza en el disco. Esta llamada al sistema no vacía las cachés de escritura del disco y, por lo tanto, no proporciona ninguna integridad de datos en sistemas con cachés de escritura de disco volátiles.

Algunos detalles

SYNC_FILE_RANGE_WAIT_BEFORE y SYNC_FILE_RANGE_WAIT_AFTER detectarán cualquier error de I/O o condición ENOSPC y los devolverán al llamador.

Las combinaciones útiles de los bits de flags son:

SYNC_FILE_RANGE_WAIT_BEFORE | SYNC_FILE_RANGE_WRITE
Asegura que todas las páginas en el rango especificado que estaban sucias cuando se llamó a sync_file_range() se envíen para escritura. Esta es una operación de inicio de escritura para la integridad de datos.
SYNC_FILE_RANGE_WRITE
Inicia la escritura de todas las páginas sucias en el rango especificado que no están actualmente en proceso de escritura. Esta es una operación de vaciado asíncrono al disco. No es adecuada para operaciones de integridad de datos.
SYNC_FILE_RANGE_WAIT_BEFORE (o SYNC_FILE_RANGE_WAIT_AFTER)
Espera la finalización de la escritura de todas las páginas en el rango especificado. Esto se puede usar después de una operación anterior de SYNC_FILE_RANGE_WAIT_BEFORE | SYNC_FILE_RANGE_WRITE para esperar la finalización de esa operación y obtener su resultado.
SYNC_FILE_RANGE_WAIT_BEFORE | SYNC_FILE_RANGE_WRITE | SYNC_FILE_RANGE_WAIT_AFTER
Esta es una operación de escritura para la integridad de datos que asegurará que todas las páginas en el rango especificado que estaban sucias cuando se llamó a sync_file_range() se confirmen en el disco.

VALOR DE RETORNO

En caso de éxito, sync_file_range() devuelve 0; en caso de error, devuelve -1 y errno se establece para indicar el error.

ERRORES

EBADF
fd no es un descriptor de archivo válido.
EINVAL
flags especifica un bit inválido; o offset o nbytes son inválidos.
EIO
Error de I/O.
ENOMEM
Sin memoria.
ENOSPC
Sin espacio en disco.
ESPIPE
fd se refiere a algo que no sea un archivo regular, un dispositivo de bloques o un directorio.

VERSIÓNES

sync_file_range2()

Algunas arquitecturas (por ejemplo, PowerPC, ARM) necesitan que los argumentos de 64 bits se alineen en un par adecuado de registros. En dichas arquitecturas, la firma de llamada de sync_file_range() que se muestra en la SINOPSIS forzaría un registro a desperdiciarse como relleno entre los argumentos fd y offset. (Ver syscall(2) para más detalles.) Por lo tanto, estas arquitecturas definen una llamada al sistema diferente que ordena los argumentos adecuadamente:


int sync_file_range2(int fd, unsigned int flags,
                     off_t offset, off_t nbytes);

El comportamiento de esta llamada al sistema es, por lo demás, exactamente el mismo que sync_file_range().

ESTÁNDARES

Linux.

HISTORIA

Linux 2.6.17.

sync_file_range2()

Una llamada al sistema con esta firma apareció por primera vez en la arquitectura ARM en Linux 2.6.20, con el nombre arm_sync_file_range(). Fue renombrada en Linux 2.6.22, cuando se añadió la llamada al sistema análoga para PowerPC. En arquitecturas donde se proporciona soporte para glibc, glibc envuelve transparentemente sync_file_range2() bajo el nombre sync_file_range().

NOTAS

_FILE_OFFSET_BITS debe definirse como 64 en el código que toma la dirección de sync_file_range, si el código está destinado a ser portátil a plataformas x86 y ARM de 32 bits tradicionales donde el ancho de off_t es de 32 bits por defecto.
