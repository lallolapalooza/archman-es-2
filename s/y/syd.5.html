SYD(5) Manual de formatos de archivo SYD(5)

NOMBRE

syd - Formato de documento para escribir perfiles de Syd

API

La versión actual de la API de comandos de Syd es la **3**. Esta versión es **estable**.

CONFIGURACIÓN

Syd se configura a través de comandos de sandbox. Para múltiples reglas coincidentes (por ejemplo, dos reglas que coinciden con la misma ruta), la última regla coincidente es la que prevalece. Hay dos formas de proporcionar comandos de sandbox. Primero, Syd puede configurarse utilizando un archivo de configuración. La ruta al archivo de configuración se especifica usando el modificador de línea de comandos **-P**. Se pueden especificar varios archivos de configuración de esta manera. Los comandos individuales también se pueden pasar a través del modificador de línea de comandos **-m**. Los perfiles de configuración se pueden aplicar usando el modificador de línea de comandos **-p**. Consulte la sección PERFILES para obtener más información. Segundo, Syd puede configurarse utilizando llamadas mágicas al sistema stat(2) durante el tiempo de ejecución. Esto se logra llamando a la llamada al sistema stat(2) en la ruta especial /dev/syd seguida del comando de sandbox. La configuración en tiempo de ejecución solo es posible si el bloqueo del sandbox está **desactivado**. Se eligió la llamada al sistema stat(2) porque es práctico invocarla utilizando comandos integrados del shell como:

; test -c /dev/syd/sandbox/read:on

lo que habilita el **Sandbox de lectura** para un shell que se ejecuta bajo Syd. También es posible consultar ciertos valores utilizando el valor de retorno de la llamada stat(2):

test -c /dev/syd/sandbox/read? && echo sandboxing de lectura activado || echo sandboxing de lectura desactivado

Algunos de estos comandos integrados del shell pueden llamar a otras llamadas al sistema como fstat(2), lstat(2), newfstatat(2), o statx(2). Syd soporta la misma interfaz a través de todas estas llamadas al sistema de forma transparente. Consulte la página del manual syd(2) para obtener una descripción de la interfaz stat(2).

NOMBRADO

La denominación de los archivos de configuración de Syd sigue un esquema que permite extraer la versión de la API de comandos del nombre del archivo. Un archivo de configuración de Syd debe tener la extensión **syd-** seguida de la versión de la API (por ejemplo, **"syd-3"** para la versión de API **3**).

SINTAXIS

Los archivos de entrada deben usar la codificación UTF-8. El formato de configuración está orientado a líneas. Los comentarios comienzan con "#". Los comentarios en línea *no* son compatibles. Las líneas en blanco se ignoran. Todas las demás líneas se tratan como si se hubieran proporcionado a Syd a través del modificador de línea de comandos **-m**. Para obtener una lista de los comandos de sandbox disponibles, consulte syd(2). Para un archivo de sintaxis VIM para perfiles de Syd, consulte aquí: https://gitlab.exherbo.org/sydbox/sydbox/-/tree/main/vim

A partir de la versión 3.15.1, Syd agrega dos características adicionales al análisis de archivos de configuración:

  • Se realiza la expansión de variables de entorno en los argumentos. Por defecto, se utiliza el crate shellexpand para realizar la expansión y se puede establecer un tiempo de espera usando config/expand para realizar la expansión usando wordexp(3) en su lugar. Notablemente, las variables de entorno no establecidas no se expanden a cadenas vacías. En caso de errores de búsqueda de variables de entorno y errores de decodificación UTF-8, Syd deja de analizar y sale con un error. Esto se hace por seguridad, ya que una expansión no intencionada a cadena vacía podría hacer que la regla de sandbox resultante permita inadvertidamente rutas no deseadas sin que el usuario se dé cuenta fácilmente. Se recomienda al usuario que establezca valores predeterminados para las variables de entorno utilizando la notación familiar ${HOME:-/var/empty}. Si realmente desea una expansión a cadena vacía en variables de entorno no establecidas, puede obtener este efecto utilizando la notación ${HOME:-}, pero no se recomienda y debe usarse con cuidado.
  • Se pueden usar directivas include para solicitar la inclusión de otro archivo de configuración. Al leer una línea de inclusión, Syd deja de analizar el archivo actual, valida la ruta de inclusión dada y comienza a analizar el nuevo archivo de configuración. El archivo no debe ser escribible por el grupo ni por otros por seguridad. Para los archivos de inclusión con rutas relativas, Syd busca el archivo en el directorio del archivo de configuración anterior en lugar del directorio de trabajo actual por seguridad y facilidad de configuración. Los bucles en las directivas de inclusión se detectan almacenando en caché el ID del dispositivo y el inodo de los archivos de configuración. Tenga en cuenta que esta directiva no está permitida cuando se carga la configuración desde un descriptor de archivo usando el comando load.

A partir de la versión 3.17.6, Syd agrega la directiva include_profile que se puede usar para incluir un perfil de Syd. Consulte syd-cat -plist para obtener la lista de perfiles.

PERFILES

Syd tiene una serie de perfiles predefinidos para facilitar la configuración. Estos perfiles se pueden usar de forma independiente o apilados con otros perfiles y configuraciones personalizadas para crear varios niveles de aislamiento y confinamiento. Para ver la lista completa de perfiles, use syd-cat -plist. Para enumerar las reglas de un perfil, use syd-cat -p<nombre-perfil>. A continuación, puede encontrar una breve lista de perfiles comunes y su funcionalidad:

syd(5) — Manual page

NAME

syd — Syd configuration file syntax

SYNOPSIS

syd [ options ]

Configuration files are loaded with the -p option.

DESCRIPTION

Syd can be configured using a profile system. Profiles are loaded in order, and the last matching rule wins. Profiles can be defined in files or passed as command-line arguments. This man page describes the syntax of the configuration files and the available profiles.

CONFIGURATION

Syd configuration files consist of a list of rules, separated by newlines. Each rule is either a profile definition or a command-line argument.

Rules can be commented out using a leading hash symbol #.

NAMING

A Syd profile is a collection of rules that define a specific sandboxing environment. Profiles can be named and referred to by name. Some profiles are built-in and can be invoked using a short name or a character shortcut.

SYNTAX

The syntax for rules is as follows:

type/rule
Applies a specific rule of a given type. For example, sandbox/read:on enables read restrictions.
type/rule:argument
Applies a rule with a specific argument. For example, bind+/home:/home:ro binds the host directory /home to the guest directory /home with read-only permissions.
type/rule:argument1+argument2
Applies a rule with multiple arguments. For example, unshare/mount+uts+pid:1 enables mount, UTS, and PID namespacing.
type/rule+argument
Applies a rule with an argument that is a path. For example, allow/exec+/usr/bin/bash allows the execution of /usr/bin/bash.
lock:on
Enforces system-wide settings.
lock:off
Disables system-wide settings.

PROFILES

Syd provides several built-in profiles that can be used to quickly configure common sandboxing scenarios. These profiles can be stacked to create more complex configurations.

The order in which profiles are stacked matters, as the last matching rule wins.

container Habilita los namespaces de Linux.
Puede referirse a este perfil brevemente como solo c.
immutable Habilita los namespaces de Linux y remonta los siguientes directorios en modo de solo lectura en el nuevo namespace de montaje:
/etc, /home, /media, /mnt, /opt, /srv y /usr.
Además, se aplican otras opciones de montaje como nodev, noexec, nosuid y noatime según sea necesario.
Adicionalmente, /dev/shm y /tmp se montan de forma privada y los sistemas de archivos del kernel se enmascaran.
Consulte syd-cat -p immutable para ver la lista completa de opciones de montaje.
Puede referirse a este perfil brevemente como solo i.
privileged No elimina las capacidades de Linux al inicio. Se utiliza para construir contenedores privilegiados.
Puede referirse a este perfil brevemente como solo p.
readonly Niega todas las capacidades de sandbox de escritura a todo el sistema de archivos raíz.
Puede referirse a este perfil brevemente como solo ro.
landlock Habilita LandLock y permite directorios del sistema para el Sandbox de Bloqueo.
Puede referirse a este perfil brevemente como solo l.
linux Perfil común del sistema Linux, utilizado por los perfiles oci, paludis y user.
oci Utilizado por syd-oci(1) como perfil de contenedor predeterminado.
paludis Utilizado por el gestor de paquetes Paludis.
noipv4 Deshabilita la conectividad IPv4.
Puede referirse a este perfil brevemente como solo 6.
noipv6 Deshabilita la conectividad IPv6.
Puede referirse a este perfil brevemente como solo 4.
core Permite la generación de coredumps.
Puede referirse a este perfil brevemente como solo C.
debug Permite depuradores dentro del sandbox.
Syd no utiliza ptrace(1) con este perfil, por lo que los rastreadores pueden adjuntarse.
Puede referirse a este perfil brevemente como solo D.
nomem Permite memoria insegura (sin W^X, sin Memory-Deny-Write-Execute, permite por ejemplo JITs).
Puede referirse a este perfil brevemente como solo M.
nopie Relaja la restricción de PIE (ejecutable independiente de posición).
Puede referirse a este perfil brevemente como solo P.
quiet Silences all access violations.
You may refer to this profile shortly as just q.
rand Enables randomized file descriptors.
See Force Randomized File Descriptors section of the syd(7) manual page for more information.
You may refer to this profile shortly as just r.
off Turns all sandboxing off.
lib libsyd helper profile. Turns all sandboxing off and sets sandbox lock to exec.
Useful to configure Syd in the application using libsyd.
user Allows user-specific directories, and connections, and parses the files
/etc/user.syd-3, and ~/.user.syd-3 if they exist.
Syd sets the environment variables SYD_UID, SYD_GID, SYD_USER, SYD_HOME before parsing this profile.
To enforce system-wide settings, set lock:on at the end of /etc/user.syd-3.
You may refer to this profile shortly as just u.
kvm Profile to allowlist KVM ioctl(2) requests without path check.
Read: https://www.kernel.org/doc/Documentation/virtual/kvm/api.txt
tty Profile to allow TTY access, used by oci, paludis, and user profiles.
Syd sets the environment variable SYD_TTY before parsing this profile.
If the process has no controlling terminal, SYD_TTY variable is set to /dev/null.
firefox Profile to relax restrictions to enable running Firefox family browsers.
You may refer to this profile shortly as just ff.

Stacking Profiles

It is possible to stack multiple profiles to configure a more restricted sandbox. Remember the order you stack the profiles matter, the last matching rule wins. Below are some examples:

  • syd -puser -pimmutable -mroot:/mnt/gnu ...
  • syd -ppaludis -plandlock -mallow/lock/write+/var/tmp ...

It is also possible to combine the one character shortcuts of helper profiles, in order to stack them together. Below are some examples:

  • syd -pMPX ... # Disable MDWE, PIE and exec restrictions.
  • syd -puiq ... # Parse user profile, create an immutable container, and silence access violations.

Login shell and the User Profile

When invoked without arguments, /bin/sh is executed under Syd with the user profile as a login shell, use SYD_SH environment variable to override the shell to execute.

SECURITY

As of version 3.30.0, Syd aborts with error if path to a specified configuration file has a symbolic link in any of its path components.

Therefore, the user must supply canonicalized paths as configuration file arguments.

EXAMPLE 

# Syd profile for OpenNTPD
# Seccomp sandbox
sandbox/read,stat,write,exec,net:on
# Landlock
sandbox/lock:on
# Provide isolation using namespaces.
unshare/mount,uts,pid,ipc,cgroup:1
# Allow adjtimex and keep CAP_SYS_TIME.
trace/allow_unsafe_time:1
# Mount everything ro except /var
bind+tmpfs:/dev/shm:nodev,nosuid,noexec
bind+tmpfs:/tmp:nodev,nosuid
bind+/etc:/etc:ro,nodev,noexec,nosuid,noatime
bind+/home:/home:ro,nodev,noexec,nosuid,noatime
bind+/media:/media:ro,nodev,noexec,nosuid,noatime
bind+/mnt:/mnt:ro,nodev,noexec,nosuid,noatime
bind+/opt:/opt:ro,nodev,nosuid,noatime
bind+/srv:/srv:ro,nodev,noexec,nosuid,noatime
bind+/usr:/usr:ro,nodev,noatime
# Hide Syd
deny/read,stat,write+/proc/1/***
# Allow listen to the ntp port on loopback.
allow/net/bind+loopback!123
# Allow connections to NTP servers.
allow/net/connect+any!53
allow/net/connect+any!123
allow/net/connect+any!65535
# Allow logging to syslog.
allow/net/connect+/dev/log
# Allow `listen wildcard`
allow/net/bind+0.0.0.0!0
allow/net/connect+0.0.0.0!0
# Allow listen to the ntpd socket.
allow/net/bind+/run/ntpd.sock
allow/net/bind+/var/run/ntpd.sock
allow/write+/run/ntpd.sock
allow/write+/var/run/ntpd.sock
# Allow access to system paths
allow/read,stat+/dev/urandom
allow/lock/read+/dev/urandom
allow/read,stat+/etc/hosts
allow/lock/read+/etc/hosts
allow/read,stat+/etc/ntpd.conf
allow/lock/read+/etc/ntpd.conf
allow/read,stat+/etc/passwd
allow/lock/read+/etc/passwd
allow/read,stat+/etc/resolv.conf
allow/lock/read+/etc/resolv.conf
allow/read,stat+/etc/services
allow/lock/read+/etc/services
allow/read,stat+/usr/share/zoneinfo-posix/UTC
# chroot /var/empty && cd /
allow/stat+/
allow/stat+/var/empty
allow/write+/dev/null
allow/lock/write+/dev/null
# Allow executing the ntp binary.
allow/lock/read+/proc
allow/lock/read+/usr
allow/lock/write+/run
allow/lock/write+/var/run
allow/exec+/usr/**/bin/openntpd*
# Allow writing the drift file.
allow/write+/var/db/ntpd.drift
allow/lock/write+/var/db/ntpd.drift
# Lock configuration
lock:on
