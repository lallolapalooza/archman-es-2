NOMBRE

streamlink - extrae transmisiones de varios servicios y las canaliza a un reproductor de video de elección

SINOPSIS

streamlink [OPCIONES] <URL> [STREAM]

EJEMPLOS

streamlink --loglevel debug youtu.be/VIDEO-ID best
streamlink --player mpv --player-args '--no-border --no-keepaspect-window' twitch.tv/CHANNEL 1080p60
streamlink --player-external-http --player-external-http-port 8888 URL STREAM
streamlink --output /path/to/file --http-timeout 60 URL STREAM
streamlink --stdout URL STREAM | ffmpeg -i pipe:0 ...
streamlink --http-header 'Authorization=OAuth TOKEN' --http-header 'Referer=URL' URL STREAM
streamlink --hls-live-edge 5 --stream-segment-threads 5 'hls://https://host/playlist.m3u8' best
streamlink --twitch-low-latency -p mpv -a '--cache=yes --demuxer-max-back-bytes=2G' twitch.tv/CHANNEL best

OPCIONES

Argumentos posicionales

URL
Una URL para intentar extraer transmisiones.

Por lo general, el protocolo de las URL http(s) se puede omitir (https://), dependiendo de la implementación del plugin que se esté utilizando.

Alternativamente, la URL también se puede especificar usando la opción --url.

STREAM
Transmisión a reproducir.

Use best o worst para seleccionar la calidad más alta o más baja disponible.

Las transmisiones de respaldo se pueden especificar usando una lista separada por comas:

"720p,480p,best"

Si no se especifica ninguna transmisión y no se usa --default-stream, se imprimirá una lista de las transmisiones disponibles.

Opciones del reproductor

-p RUTA

Establece el ejecutable del reproductor que se lanzará (a menos que se elija un método de salida diferente).

Establece una ruta absoluta o relativa al ejecutable del reproductor, o simplemente el nombre del ejecutable si se puede resolver desde las rutas de la variable de entorno PATH del sistema.

Además de establecer la ruta del ejecutable del reproductor, se pueden establecer argumentos personalizados del reproductor a través de --player-args.

NOTA:

En el pasado, --player permitía definir argumentos adicionales del reproductor, lo que como consecuencia requería envolver rutas de reproductor que contenían espacios entre comillas. Esto no se admite desde la versión 6.0.0.

-a ARGUMENTOS
--player-args ARGUMENTOS
Establece una cadena de argumentos personalizados de lanzamiento de --player que se analizarán y tokenizarán.

El valor puede contener variables de formato rodeadas por llaves, { y }. Los caracteres de llave se pueden escapar duplicándolos, por ejemplo, {{ y }}.

Variables de formato disponibles:

{playerinput}
Este es el argumento de entrada que recibirá el --player. Para la entrada estándar (stdin), es - (guion), pero también puede ser una ruta de archivo o una URL, dependiendo de las opciones utilizadas. Si no se establece, el argumento de entrada del reproductor se añadirá a la lista de argumentos del reproductor analizados.
{playertitleargs}
Los argumentos de título del reproductor generados automáticamente, si se encontró un --player compatible. Consulte --title para más información. Si no se establece, los argumentos de título del reproductor generados automáticamente se antepondrán a la lista de argumentos del reproductor analizados.

Ejemplo:

streamlink -p vlc -a "--play-and-exit --no-one-instance" <url> [stream]

El valor predeterminado es: "".

--player-env CLAVE=VALOR
Agrega una variable de entorno adicional al proceso --player generado, además de las heredadas del proceso padre de Streamlink/Python. Esto permite establecer variables de entorno del reproductor en archivos de configuración.

Se puede repetir para agregar múltiples variables de entorno.

-v
--player-verbose
Escribe la salida stdout/stderr del --player en la salida stdout/stderr de Streamlink.
--verbose-player
Obsoleto en favor de --player-verbose.
-n
--player-fifo
Hace que el --player lea el stream a través de una tubería con nombre en lugar de la tubería stdin.
--fifo
Obsoleto en favor de --player-fifo.
--player-http
Hace que el --player lea el stream a través de HTTP en lugar de la tubería stdin.
--player-continuous-http
Hace que el --player lea el stream a través de HTTP, pero a diferencia de --player-http, intentará abrir continuamente el stream si el reproductor lo solicita.

Esto habilita el manejo de desconexiones del stream si el reproductor es capaz de reconectarse a un stream HTTP. Esto se hace generalmente estableciendo el reproductor en un modo de "repetición".

--player-external-http
Sirve datos de stream a través de HTTP sin abrir el --player. Esto es útil para permitir que dispositivos externos como teléfonos inteligentes o cajas de transmisión vean streams que de otro modo no podrían.

El comportamiento predeterminado es similar a la opción --player-continuous-http, pero no se iniciará ningún programa reproductor, y el servidor escuchará en todas las conexiones disponibles en lugar de solo en la interfaz local (de bucle invertido).

Consulte --player-external-http-interface para elegir una interfaz de red específica, y consulte --player-external-http-port para elegir un puerto no aleatorio.

Opcionalmente, la opción --player-external-http-continuous permite deshabilitar el modo de ejecución continua, de modo que Streamlink se detendrá cuando finalice el stream.

Las URLs que se pueden usar para acceder al stream se imprimirán en la consola, y el servidor se puede interrumpir usando CTRL-C.

--player-external-http-continuous {sí,verdadero,1,activado,no,falso,0,desactivado}
Establece el modo de ejecución de --player-external-http a continuo o no continuo.

En el modo de ejecución continua, Streamlink seguirá en ejecución después de que finalice el stream y esperará a que se realice la siguiente solicitud HTTP, a menos que se apague con CTRL-C.

Si se establece en no continuo, Streamlink se detendrá una vez que finalice el stream.

El valor predeterminado es: true.

--player-external-http-interface INTERFAZ
Establece la interfaz de red en la que escuchará el servidor HTTP. Si no se establece o se establece en 0.0.0.0, se vincularán todas las interfaces disponibles.
--player-external-http-port PUERTO
Establece el puerto del servidor HTTP externo si ese modo está habilitado. Omita o establezca en 0 para usar un puerto aleatorio alto (>1024).
--player-passthrough TIPOS
Una lista separada por comas de tipos de stream para pasar al --player como una URL para que maneje el transporte del stream en lugar de Streamlink.

Los tipos de stream que se pueden convertir en una URL reproducible son:

hls, http

Asegúrese de que el reproductor pueda manejar el tipo de stream al usar esta opción.

--player-no-close
Por defecto, Streamlink cerrará el --player cuando finalice el stream. Esto es para evitar reproductores GUI "muertos" que queden abiertos después de que Streamlink haya salido.

Sin embargo, tiene el efecto secundario de cerrar a veces un reproductor antes de que haya reproducido todos sus datos cacheados.

Esta opción permitirá que el reproductor decida cuándo salir en su lugar.

-t TÍTULO
--title TÍTULO
Cambia el título de la ventana del --player.

Consulte la sección de "Variables de metadatos" de la documentación CLI de Streamlink para conocer todas las variables de metadatos disponibles, así como la sección "Plugins" para la lista de variables de metadatos definidas en cada plugin.

Solo se admiten los siguientes reproductores:

  • mpv
  • PotPlayer
  • VLC

Ejemplo:

Opciones de transmisión

--url URL
Una URL de la que intentar extraer transmisiones.

Normalmente, el protocolo de las URL http(s) se puede omitir (https://), dependiendo de la implementación del plugin que se esté utilizando.

Esta es una alternativa a establecer la URL usando un argumento posicional y puede ser útil si se establece en un archivo de configuración.

--default-stream STREAM
Transmisión a reproducir.

Utiliza best o worst para seleccionar la calidad más alta o más baja disponible.

Se pueden especificar transmisiones de respaldo usando una lista separada por comas:

"720p,480p,best"

Esta es una alternativa a establecer la transmisión usando un argumento posicional y puede ser útil si se establece en un archivo de configuración.

--stream-url
Si es posible, traduce la transmisión resuelta a una URL y la imprime.
--retry-streams RETRASO
Reintenta obtener la lista de transmisiones disponibles hasta que se encuentren transmisiones, esperando RETRASO segundo(s) entre cada intento.

El número de intentos de reintento se puede limitar con --retry-max. Se implica un valor predeterminado de 1 para valores distintos de cero de --retry-max.

Si tanto --retry-streams como --retry-max se establecen en 0, solo se hará un intento para obtener la lista de transmisiones disponibles. Este es el comportamiento predeterminado.

--retry-max CUENTA
Deja de obtener la lista de transmisiones disponibles después de CUENTA intento(s) de reintento.

Un valor de 0 hace que Streamlink obtenga transmisiones indefinidamente si --retry-streams se establece en un valor distinto de cero. Si --retry-streams no está establecido, el retraso predeterminado entre la obtención de transmisiones disponibles es de 1 segundo.

--retry-open INTENTOS
Después de una obtención exitosa, intenta abrir la transmisión INTENTOS vez(ces) hasta rendirse.

El valor predeterminado es: 1.

--stream-types TIPOS
--stream-priority TIPOS
Una lista de tipos de transmisión separados por comas para permitir.

El orden se utilizará para separar las transmisiones cuando haya múltiples transmisiones con el mismo nombre pero diferentes tipos de transmisión. Cualquier tipo de transmisión no listado se omitirá de la lista de transmisiones disponibles. Un * (asterisco) se puede usar como comodín para coincidir con cualquier otro tipo de transmisión, por ejemplo, dash.

El valor predeterminado es: "hls,http,*".

--stream-sorting-excludes STREAMS
Ajusta los sinónimos de nombres de transmisión best y worst excluyendo transmisiones no deseadas.

Si se excluyen todas las transmisiones disponibles, best y worst se volverán inaccesibles y se pueden usar nuevos sinónimos de transmisión especiales best-unfiltered y worst-unfiltered como método de selección de respaldo.

El formato de la expresión de filtro es:

[operador]<valor>

Los operadores válidos son >, >=, < y <=. Si no se especifica ningún operador, se prueba la igualdad.

Por ejemplo, esto excluirá las transmisiones de mayor calidad que "480p":

--stream-sorting-excludes ">480p"

Se pueden usar varios filtros separando cada expresión con una coma.

Por ejemplo, esto excluirá transmisiones de dos tipos de calidad:

--stream-sorting-excludes ">480p,>medium"

Opciones de transporte de transmisión

--ringbuffer-size TAMAÑO
El tamaño máximo del búfer de anillo.

Se pueden especificar Mebibytes o Kibibytes (base 2) mediante el sufijo M o K respectivamente.

El búfer de anillo se utiliza como almacenamiento temporal entre la transmisión y el reproductor. Esto permite que Streamlink descargue la transmisión más rápido de lo que el reproductor lee los datos del búfer de anillo.

Cuanto menor sea el tamaño del búfer de anillo, mayor será la probabilidad de que el reproductor tenga búfer si la velocidad de descarga disminuye, y cuanto mayor sea el tamaño, más datos se podrán utilizar como almacenamiento para recuperarse de velocidades de descarga volátiles.

La mayoría de los reproductores tienen su propia caché adicional y leerán el contenido del búfer de anillo tan pronto como los datos estén disponibles. Si el reproductor deja de leer datos mientras la reproducción está en pausa, Streamlink seguirá descargando la transmisión en segundo plano siempre que el búfer de anillo no se llene.

El valor predeterminado es:

"16M".

--stream-segment-attempts INTENTOS
El número de intentos de descarga de cada segmento de transmisión antes de rendirse.

Esto se aplica a todos los diferentes tipos de transmisiones segmentadas, como DASH, HLS, etc.

El valor predeterminado es: 3.

--stream-segment-threads HILOS
El tamaño del grupo de hilos utilizado para descargar segmentos. El valor mínimo es 1 y el máximo es 10.

Esto se aplica a todos los diferentes tipos de transmisiones segmentadas, como DASH, HLS, etc.

El valor predeterminado es: 1.

--stream-segment-timeout TIEMPO_DE_ESPERA
El tiempo máximo de espera para que comience la descarga de cada segmento.

Esto se aplica a todos los diferentes tipos de transmisiones segmentadas, como DASH, HLS, etc.

El valor predeterminado es: 10.0.

--stream-segmented-duration [[HH:]HH:]HH[.HH] | [HHh][MMm][SS[.SS]s]
Limita la duración de salida de las transmisiones segmentadas, como HLS y DASH. La duración real puede ser ligeramente mayor, ya que se redondea al segmento más cercano.

Establecer en 0 para deshabilitar.

El valor predeterminado es: 0.

--stream-timeout TIEMPO_DE_ESPERA
El tiempo máximo de espera para que una transmisión sin filtrar continúe produciendo datos.

Esto se aplica a todos los diferentes tipos de transmisiones, como DASH, HLS, HTTP, etc.

El valor predeterminado es: 60.0.

--mux-subtitles
Incluye automáticamente los subtítulos disponibles en la transmisión de salida.

Debe ser compatible con el plugin utilizado.

Opciones HLS

--hls-live-edge SEGMENTOS
Número de segmentos desde la posición actual en vivo de la transmisión para comenzar a transmitir. El tamaño o la duración de cada segmento está determinado por el proveedor de la transmisión.

Valores más bajos disminuirán la latencia, pero también aumentarán la probabilidad de buffering, ya que hay menos tiempo para que Streamlink descargue segmentos y escriba sus datos en el búfer de salida. El número de descargas paralelas de segmentos se puede establecer con --stream-segment-threads y el tiempo de recarga de la lista de reproducción HLS para obtener y poner en cola nuevos segmentos se puede anular con --hls-playlist-reload-time.

El valor predeterminado es: 3.

NOTA:

Durante la reproducción en vivo, la configuración de caché/buffering del reproductor utilizado agregará latencia adicional. Para ajustar esto, consulte la documentación del propio reproductor para la configuración requerida. Los parámetros del reproductor se pueden establecer a través de --player-args.
--hls-segment-stream-data
Escribe inmediatamente los datos del segmento en el búfer de salida mientras se descargan.
--hls-playlist-reload-attempts INTENTOS
El número máximo de intentos al recargar la lista de reproducción HLS antes de rendirse.

El valor predeterminado es: 3.

--hls-playlist-reload-time TIEMPO
Establece un valor de tiempo de recarga de lista de reproducción HLS personalizado, ya sea en segundos o utilizando una de las siguientes palabras clave:
  • segmento: La duración del último segmento en la lista de reproducción actual
  • live-edge: La suma de las duraciones de los segmentos del valor live-edge menos uno
  • predeterminado: Los metadatos de duración objetivo de la lista de reproducción

El valor predeterminado es: predeterminado.

--hls-segment-queue-threshold FACTOR
El factor de multiplicación de la duración objetivo de la lista de reproducción HLS después del cual la transmisión se detendrá tempranamente si no se han puesto en cola nuevos segmentos después de actualizar la lista de reproducción (múltiples veces). La duración objetivo define la duración máxima que puede tener un solo segmento, lo que significa que deben estar disponibles nuevos segmentos durante este período de tiempo, de lo contrario, pueden ocurrir problemas de reproducción.

La intención de este umbral de cola es poder detenerse tempranamente cuando el final de una transmisión no es anunciado por el servidor, para que Streamlink no tenga que esperar hasta que ocurra un time-out de lectura. Ver --stream-timeout.

Establecer en 0 para deshabilitar.

El valor predeterminado es: 3.

--hls-segment-ignore-names NOMBRES
Una lista separada por comas de nombres de segmentos que se filtrarán.

Ejemplo: --hls-segment-ignore-names 000,001,002

Esto ignorará todos los segmentos que terminen con 000.ts, 001.ts y 002.ts

El valor predeterminado es: Ninguno.

--hls-segment-key-uri URI
Anula las URI de las claves de cifrado de segmentos para transmisiones cifradas.

El valor puede ser parametrizado utilizando las siguientes variables, que se reemplazarán con su parte respectiva de la URI del segmento de origen:

{url} {scheme} {netloc} {path} {query}

Ejemplos:

--hls-segment-key-uri "https://example.com/hls/encryption_key"
--hls-segment-key-uri "{scheme}://1.2.3.4{path}{query}"
--hls-segment-key-uri "{scheme}://{netloc}/custom/path/to/key"

Opciones del navegador web

--webbrowser {yes,true,1,on,no,false,0,off}
Habilita o deshabilita el soporte para la API del navegador web de Streamlink.

La API del navegador web de Streamlink permite a los plugins que la implementan lanzar un navegador web y extraer datos de sitios web que de otra manera no podrían hacerlo a través de la sesión HTTP normal en Python debido a restricciones específicas de JavaScript.

El navegador web se ejecuta aislado y en un entorno limpio sin acceso a los datos del usuario normal.

Streamlink actualmente solo admite navegadores web basados en Chromium que utilizan el Protocolo de herramientas para desarrolladores de Chrome (CDP). Esto incluye Chromium en sí, Google Chrome, Microsoft Edge, Brave, Vivaldi y otros, pero no se garantiza el soporte completo para bifurcaciones de Chromium de terceros. Intente Chromium o Google Chrome cuando encuentre algún problema.

Por defecto es: true.
