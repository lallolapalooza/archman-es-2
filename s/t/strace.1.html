NOMBRE

strace - rastrea llamadas al sistema y señales

SINOPSIS

strace [-ACdffhikqqrtttTvVwxxyyYzZ] [-a columna] [-b execve] [-e expresión]... [-I n] [-o archivo] [-O overhead] [-p pid]... [-P ruta]... [-s tamañocadena] [-S ordenadopor] [-U columnas] [-X formato] [--seccomp-bpf] [--stack-trace-frame-limit=límite] [--syscall-limit=límite] [--tips[=formato]] { -p pid | [-DDD] [-E var[=val]]... [-u nombreusuario] comando [argumentos] }
strace -c [-dfwzZ] [-b execve] [-e expresión]... [-I n] [-O overhead] [-p pid]... [-P ruta]... [-S ordenadopor] [-U columnas] [--seccomp-bpf] [--syscall-limit=límite] [--tips[=formato]] { -p pid | [-DDD] [-E var[=val]]... [-u nombreusuario] comando [argumentos] }
strace --tips[=formato]

DESCRIPCIÓN

En su uso más simple, strace ejecuta el comando especificado hasta que este termina. Intercepta y registra las llamadas al sistema realizadas por un proceso y las señales que recibe un proceso. El nombre de cada llamada al sistema, sus argumentos y su valor de retorno se imprimen en la salida estándar de error o en el archivo especificado con la opción -o.

strace es una herramienta útil de diagnóstico, enseñanza y depuración. Los administradores de sistemas, diagnosticadores y solucionadores de problemas la encontrarán invaluable para resolver problemas con programas para los que no se dispone fácilmente del código fuente, ya que no se requiere recompilación para el rastreo. Los estudiantes, hackers y los excesivamente curiosos descubrirán que se puede aprender mucho sobre un sistema y sus llamadas al sistema rastreando incluso programas ordinarios. Los programadores encontrarán que, dado que las llamadas al sistema y las señales ocurren en la interfaz usuario/kernel, un examen detallado de esta frontera es muy útil para el aislamiento de errores, la verificación de cordura e intentar capturar condiciones de carrera.

Cada línea en el rastreo contiene el nombre de la llamada al sistema, seguido de sus argumentos entre paréntesis y su valor de retorno. Un ejemplo de rastreo del comando "cat /dev/null" es:


open("/dev/null", O_RDONLY) = 3

Los errores, típicamente indicados por un valor de retorno de -1, tienen el símbolo errno y la cadena de error adjunta.


open("/foo/bar", O_RDONLY) = -1 ENOENT (No such file or directory)

Las señales se imprimen como un símbolo de señal y una estructura siginfo decodificada. Un extracto del rastreo e interrupción del comando "sleep 666" es:


sigsuspend([] <unfinished ...>
--- SIGINT {si_signo=SIGINT, si_code=SI_USER, si_pid=...} ---
+++ killed by SIGINT +++

Si una llamada al sistema se está ejecutando mientras se llama a otra desde un hilo o proceso diferente, strace intentará preservar el orden de estos eventos y marcar la llamada en curso como unfinished (sin terminar). Cuando la llamada retorne, se marcará como resumed (reanudada).


[pid 28772] select(4, [3], NULL, NULL, NULL <unfinished ...>
[pid 28779] clock_gettime(CLOCK_REALTIME, {tv_sec=1130322148, tv_nsec=3977000}) = 0
[pid 28772] <... select resumed> )      = 1 (in [3])

La interrupción de una llamada al sistema (reiniciable) por la entrega de una señal se maneja de manera diferente, ya que el kernel termina la llamada al sistema y organiza su reejecución inmediata después de que el manejador de señales se complete.


read(0, 0x7ffff72cf5cf, 1)              = ? ERESTARTSYS (To be restarted)
--- SIGALRM {si_signo=SIGALRM, si_code=SI_KERNEL} ---
rt_sigreturn({mask=[]})                 = 0
read(0, "", 1)                          = 0

Los argumentos se imprimen en formato simbólico con pasión. Este ejemplo muestra cómo el shell realiza la redirección de salida ">>xyzzy":


open("xyzzy", O_WRONLY|O_APPEND|O_CREAT, 0666) = 3

Aquí, el segundo y tercer argumento de open(2) se decodifican desglosando el argumento de banderas en sus tres constituyentes de OR bit a bit e imprimiendo el valor del modo en octal, siguiendo la tradición. Donde el uso tradicional o nativo difiere del ANSI o POSIX, se prefieren las últimas formas. En algunos casos, la salida de strace ha demostrado ser más legible que el propio código fuente.

Los punteros a estructuras se desreferencian y sus miembros se muestran según corresponda. En la mayoría de los casos, los argumentos se formatean de la manera más parecida a C posible. Por ejemplo, la esencia del comando "ls -l /dev/null" se captura como:


lstat("/dev/null", {st_mode=S_IFCHR|0666, st_rdev=makedev(0x1, 0x3), ...}) = 0

Observe cómo se desreferencia el argumento struct stat y cómo se muestra cada miembro simbólicamente. En particular, observe cómo el miembro st_mode se decodifica cuidadosamente en un OR bit a bit de valores simbólicos y numéricos. Además, tenga en cuenta que en este ejemplo, el primer argumento para lstat(2) es una entrada para la llamada al sistema, y el segundo argumento es una salida. Dado que los argumentos de salida no se modifican si la llamada al sistema falla, los argumentos pueden no ser desreferenciados siempre. Por ejemplo, al reintentar el ejemplo "ls -l" con un archivo inexistente se produce la siguiente línea:


lstat("/foo/bar", 0xb004) = -1 ENOENT (No such file or directory)

En este caso, la luz del porche está encendida pero no hay nadie en casa. Se muestra el valor del puntero porque la estructura a la que apunta no se pobló debido al error.

Las llamadas al sistema desconocidas para strace se imprimen en un formato crudo, con el número hexadecimal de la llamada al sistema precedido por "syscall_":


syscall_0xbad(0x1, 0x2, 0x3, 0x4, 0x5, 0x6) = -1 ENOSYS (Function not implemented)

Los punteros de caracteres se desreferencian y se imprimen como cadenas C. Los caracteres que no se imprimen en las cadenas normalmente se representan mediante códigos de escape estándar de C. Solo se imprimen los primeros tamañocadena (32 por defecto) bytes de las cadenas; las cadenas más largas tienen puntos suspensivos adjuntos después de la comilla de cierre. Aquí hay una línea de "ls -l" donde la rutina de la biblioteca getpwuid(3) está leyendo el archivo de contraseñas:


read(3, "root::0:0:System Administrator:/"..., 1024) = 422

Mientras que las estructuras se anotan usando llaves, los punteros a tipos básicos y arreglos se imprimen usando corchetes con comas separando los elementos. Aquí hay un ejemplo del comando id(1) en un sistema con IDs de grupo suplementarios:


getgroups(32, [100, 0]) = 2

Por otro lado, los conjuntos de bits también se muestran usando corchetes, pero los elementos del conjunto solo están separados por un espacio. Aquí está el shell, preparándose para ejecutar un comando externo:


sigprocmask(SIG_BLOCK, [CHLD TTOU], []) = 0

Aquí, el segundo argumento es un conjunto de bits de dos señales

s, SIGCHLD y SIGTTOU. En algunos casos, el conjunto de bits está tan completo que es más valioso imprimir los elementos no establecidos. En ese caso, el conjunto de bits va precedido de una tilde, así:


sigprocmask(SIG_UNBLOCK, ~[], NULL) = 0

Aquí, el segundo argumento representa el conjunto completo de todas las señales.

OPCIONES

General

-e expresión
Modifica qué eventos rastrear o cómo rastrearlos especificando una expresión calificadora. El formato de la expresión es:
[calificador=][!]valor[,valor]...
donde calificador es uno de trace (o t), trace-fds (o trace-fd o fd o fds), abbrev (o a), verbose (o v), raw (o x), signal (o signals o s), read (o reads o r), write (o writes o w), fault, inject, status, quiet (o silent o silence o q), decode-fds (o decode-fd), decode-pids (o decode-pid), o kvm, y valor es un símbolo o número dependiente del calificador. El calificador por defecto es trace. Usar un signo de exclamación niega el conjunto de valores. Por ejemplo, -e open es equivalente a -e trace=open, que a su vez significa rastrear solo la llamada al sistema open. Por el contrario, -e trace=!open significa rastrear todas las llamadas al sistema excepto open. Además, los valores especiales all y none pueden usarse para rastrear todos los eventos o ningún evento, respectivamente.
Tenga en cuenta que algunos shells usan el signo de exclamación para la expansión del historial incluso dentro de argumentos entre comillas. En ese caso, el signo de exclamación debe escaparse con una barra invertida.

Arranque

-E var=val
--env=var=val
Ejecuta el comando con la variable de entorno var=val establecida para la ejecución.
-E var
--env=var
Elimina var de las variables de entorno heredadas antes de ejecutar el comando.
-p pid
--attach=pid
Se adjunta al proceso con el ID de proceso pid y comienza el rastreo. El rastreo puede terminarse en cualquier momento por una interrupción de teclado (CTRL-C). strace responderá desvinculándose de los procesos rastreados, dejándolos continuar su ejecución.
Se pueden usar múltiples opciones -p para adjuntarse a varios procesos además del comando, lo cual es opcional si se proporciona al menos una opción -p.
Una única opción -p puede aceptar múltiples IDs de proceso separados por una coma (“,”), espacio (“ ”), tabulación o nueva línea. Por consiguiente, se admiten sintaxis como -p "$(pidof PROG)" y -p "$(pgrep PROG)".
-u nombreusuario
--user=nombreusuario
Ejecuta el comando con el ID de usuario, ID de grupo y grupos suplementarios de nombreusuario. Esta opción solo es útil cuando se ejecuta como root, ya que permite la ejecución correcta de binarios setuid y/o setgid. A menos que se use esta opción, los programas setuid y setgid se ejecutan sin sus privilegios efectivos.
-u UID:GID
--user=UID:GID
Sintaxis alternativa donde el programa se inicia con exactamente los IDs de usuario y grupo dados, y una lista vacía de grupos suplementarios. En este caso, no se realizan búsquedas de nombres de usuario y grupo.
--argv0=nombre
Establece argv[0] del comando ejecutado a nombre. Esto es útil para rastrear ejecutables multi-llamada que interpretan argv[0], como busybox o kmod.

Rastreo

-b llamada_sistema
--detach-on=llamada_sistema
Se desvincula del proceso rastreado si se alcanza la llamada al sistema especificada. Actualmente, solo se admite la palabra clave execve, que incluye las llamadas al sistema execve(2) y execveat(2). Esta opción es útil para rastrear un proceso multihilo con -f sin rastrear también sus procesos hijos (potencialmente muy complejos).
-D
--daemonize
--daemonize=nieto
Ejecuta el proceso de rastreo como un nieto del rastreado, no como su padre. Esto reduce el efecto visible de strace al mantener al rastreado como hijo directo del proceso llamante.
-DD
--daemonize=pgroup
--daemonize=pgrp
Ejecuta el proceso de rastreo como nieto del rastreado en un grupo de procesos separado. Además de reducir el efecto visible de strace, esto también evita que strace sea terminado por una señal kill(2) enviada a todo el grupo de procesos.
-DDD
--daemonize=session
Ejecuta el proceso de rastreo como el nieto del rastreado en una sesión separada (conocida como "daemonización real"). Además de reducir el efecto visible de strace, esto también evita que strace sea terminado al terminar la sesión.
-f
--follow-forks
Rastrea los procesos hijos a medida que son creados por los procesos actualmente rastreados como resultado de las llamadas al sistema fork(2), vfork(2) y clone(2). Tenga en cuenta que si el proceso PID es multihilo, usar -f -p PID se adjunta a todos sus hilos, no solo al que tiene thread_id = PID.
--output-separately
Si la opción --output=nombrearchivo está activa, el rastreo de cada proceso se escribe en un archivo separado nombrearchivo.pid, donde pid es el ID del proceso.
-ff
--follow-forks --output-separately
Combina los efectos de las opciones --follow-forks y --output-separately. Esto es incompatible con -c, ya que no se mantienen recuentos por proceso.
Utilice strace-log-merge(1) para obtener una vista combinada de los archivos de registro.
-I interrumpible
--interruptible=interrumpible
Controla cuándo strace puede ser interrumpido por señales (como al presionar CTRL-C).
1, anywhere
no se bloquean señales;
2, waiting
se bloquean señales fatales mientras se decodifica la llamada al sistema (por defecto);
3, never
se bloquean siempre las señales fatales (por defecto si -o ARCHIVO PROG);
4, never_tstp
se bloquean siempre las señales fatales y SIGTSTP (CTRL-Z) (útil para evitar que strace -o ARCHIVO PROG se detenga con CTRL-Z, por defecto si -D).
--syscall-limit=límite
Se desvincula de todos los rastreados después de capturar límite llamadas al sistema. Las llamadas al sistema filtradas a través de las opciones --trace, --trace-path o --status no se consideran al hacer el seguimiento del número de llamadas al sistema capturadas.
--kill-on-exit
Aplica la opción ptrace PTRACE_O_EXITKILL a todos los rastreados, la cual envía una señal SIGKILL a un rastreado si el rastreador sale. Esto evita que los rastreados queden en ejecución después de que el rastreador salga, ya que no se desvincularán al limpiar. --kill-on-exit no es compatible con las opciones -p/--attach.

Filtrado

-e trace=conjunto_llamadas_sistema
-e t=conjunto_llamadas_sistema
--trace=conjunto_llamadas_sistema
Rastrea solo el conjunto especificado de llamadas al sistema. conjunto_llamadas_sistema se define como [!]valor[,valor], y valor puede ser uno de los siguientes:
llamada_sistema
Rastrea una llamada al sistema específica, especificada por su nombre (ver syscalls(2) para una referencia, pero también ver NOTAS).
?valor
Un signo de interrogación que precede a la calificación suprime los errores si no se encuentran llamadas al sistema coincidentes.

System call filtering

value@64
Limita la especificación de llamadas al sistema descrita por value a la personalidad de 64 bits.
value@32
Limita la especificación de llamadas al sistema descrita por value a la personalidad de 32 bits.
value@x32
Limita la especificación de llamadas al sistema descrita por value a la personalidad x32.
all
Rastrea todas las llamadas al sistema.
/regex
Rastrea solo aquellas llamadas al sistema que coinciden con la regex. Puede usar la sintaxis de Expresiones Regulares Extendidas POSIX (ver regex(7)).
%file
file
Rastrea todas las llamadas al sistema que toman un nombre de archivo como argumento. Puede pensar en esto como una abreviatura de --trace=open,stat,chmod,unlink,... lo cual es útil para ver a qué archivos hace referencia el proceso. Además, usar la abreviatura asegurará que usted no olvide accidentalmente incluir una llamada como newfstatat(2) en la lista. La sintaxis sin un signo de porcentaje previo ("--trace=file") está obsoleta.
%process
process
Rastrea llamadas al sistema asociadas con el ciclo de vida del proceso (creación, ejecución, terminación). La sintaxis sin un signo de porcentaje previo ("--trace=process") está obsoleta.
%net
%network
network
Rastrea todas las llamadas al sistema relacionadas con la red. La sintaxis sin un signo de porcentaje previo ("--trace=network") está obsoleta.
%signal
signal
Rastrea todas las llamadas al sistema relacionadas con señales. La sintaxis sin un signo de porcentaje previo ("--trace=signal") está obsoleta.
%ipc
ipc
Rastrea todas las llamadas al sistema relacionadas con IPC. La sintaxis sin un signo de porcentaje previo ("--trace=ipc") está obsoleta.
%desc
desc
Rastrea todas las llamadas al sistema relacionadas con descriptores de archivo. La sintaxis sin un signo de porcentaje previo ("--trace=desc") está obsoleta.
%memory
memory
Rastrea todas las llamadas al sistema relacionadas con mapeo de memoria. La sintaxis sin un signo de porcentaje previo ("--trace=memory") está obsoleta.
%creds
Rastrea llamadas al sistema que leen o modifican identificadores de usuario y grupo o conjuntos de capacidades.
%stat
Rastrea variantes de la llamada al sistema stat.
%lstat
Rastrea variantes de la llamada al sistema lstat.
%fstat
Rastrea variantes de las llamadas al sistema fstat, fstatat y statx.
%%stat
Rastrea llamadas al sistema utilizadas para solicitar el estado del archivo (stat, lstat, fstat, fstatat, statx y sus variantes).
%statfs
Rastrea las llamadas al sistema statfs, statfs64, statvfs, osf_statfs y osf_statfs64. El mismo efecto se puede lograr con la expresión regular --trace=/^(.*_)?statv?fs.
%fstatfs
Rastrea las llamadas al sistema fstatfs, fstatfs64, fstatvfs, osf_fstatfs y osf_fstatfs64. El mismo efecto se puede lograr con la expresión regular --trace=/fstatv?fs.
%%statfs
Rastrea llamadas al sistema relacionadas con estadísticas del sistema de archivos (similares a statfs, similares a fstatfs y ustat). El mismo efecto se puede lograr con la expresión regular --trace=/statv?fs|fsstat|ustat.
%clock
Rastrea llamadas al sistema que leen o modifican los relojes del sistema.
%pure
Rastrea llamadas al sistema que siempre tienen éxito y no tienen argumentos. Actualmente, esta lista incluye arc_gettls(2), getdtablesize(2), getegid(2), getegid32(2), geteuid(2), geteuid32(2), getgid(2), getgid32(2), getpagesize(2), getpgrp(2), getpid(2), getppid(2), get_thread_area(2) (en arquitecturas distintas a x86), gettid(2), get_tls(2), getuid(2), getuid32(2), getxgid(2), getxpid(2), getxuid(2), kern_features(2), y metag_get_tls(2) llamadas al sistema.
La opción -c es útil para determinar qué llamadas al sistema pueden ser útiles de rastrear. Por ejemplo, --trace=open,close,read,write significa rastrear solo esas cuatro llamadas al sistema. Tenga cuidado al hacer inferencias sobre el límite usuario/kernel si solo se está monitoreando un subconjunto de llamadas al sistema. El valor predeterminado es --trace=all.
-e trace-fd=set
-e trace-fds=set
-e fd=set
-e fds=set
--trace-fds=set
Rastrea solo las llamadas al sistema que operan sobre el subconjunto especificado de descriptores de archivo (no negativos). Tenga en cuenta que el uso de esta opción también filtra todas las llamadas al sistema que no operan en descriptores de archivo en absoluto.
Este filtro se combina con el filtro --trace-path; una llamada al sistema se rastrea si coincide con alguna de ellas.
-e signal=set
-e signals=set
-e s=set
--signal=set
Rastrea solo el subconjunto especificado de señales. El valor predeterminado es --signal=all. Por ejemplo, --signal=!SIGIO (o --signal=!io) hace que las señales SIGIO no se rastreen.
-e status=set
--status=set
Imprime solo llamadas al sistema con el estado de retorno especificado. El valor predeterminado es --status=all. Al usar el calificador status, el orden cronológico de los eventos puede no conservarse. Esto se debe a que strace debe esperar a que una llamada al sistema se complete antes de decidir si imprimirla. Si dos llamadas al sistema son ejecutadas por hilos concurrentes, strace imprimirá primero la entrada y salida de la primera llamada al sistema en salir, independientemente de su hora de entrada respectiva. La entrada y salida de la segunda llamada al sistema en salir se imprimirán después. Aquí hay un ejemplo cuando se llama a select(2), pero un hilo diferente llama a clock_gettime(2) antes de que select(2) finalice: 


[pid 28779] 1130322148.939977 clock_gettime(CLOCK_REALTIME, {1130322148, 939977000}) = 0
[pid 28772] 1130322148.438139 select(4, [3], NULL, NULL, NULL) = 1 (en [3])

set puede incluir los siguientes elementos:

successful
Rastrea llamadas al sistema que regresaron sin un código de error. La opción -z tiene el efecto de --status=successful.
failed
Rastrea llamadas al sistema que regresaron con un código de error. La opción -Z tiene el efecto de --status=failed.
unfinished
Rastrea llamadas al sistema que no regresaron. Esto podría suceder, por ejemplo, debido a una llamada execve en un hilo diferente del mismo grupo de hilos.
unavailable
Rastrea llamadas al sistema que regresaron pero strace no pudo obtener el estado de error.
detached
Rastrea llamadas al sistema de las cuales strace se desconectó antes del retorno.
-P path
--trace-path=path
Rastrea solo llamadas al sistema que acceden a path. Se pueden usar múltiples opciones -P para especificar varias rutas. Este filtro se combina con el filtro --trace-fds; una llamada al sistema se rastrea si coincide con alguna de las opciones.
-z
--successful-only
Imprime solo llamadas al sistema que regresaron sin un código de error.
-Z
--failed-only
Imprime solo llamadas al sistema que regresaron con un código de error.

Formato de salida

-a column
--columns=column
Alinea los valores de retorno en una columna específica (columna predeterminada 40).
-e abbrev=syscall_set
-e a=syscall_set
--abbrev=syscall_set
Abreviatura la salida al imprimir cada miembro de estructuras grandes. La sintaxis de la especificación de syscall_set es la misma que en la opción -
-trace. El valor predeterminado es --abbrev=all. La opción -v tiene el efecto de --abbrev=none.
-e verbose=syscall_set
-e v=syscall_set
--verbose=syscall_set
Desreferencia estructuras para el conjunto especificado de llamadas al sistema. La sintaxis de la especificación syscall_set es la misma que en la opción --trace. El valor predeterminado es --verbose=all.
-e raw=syscall_set
-e x=syscall_set
--raw=syscall_set
Imprime argumentos sin procesar y sin decodificar para el conjunto especificado de llamadas al sistema. La sintaxis de la especificación syscall_set es la misma que en la opción --trace. Esta opción tiene el efecto de hacer que todos los argumentos se impriman en hexadecimal. Esta opción es útil si la decodificación no es confiable, o si se necesita el valor numérico real de un argumento. Ver también la opción -X raw.
-e read=set
-e reads=set
-e r=set
--read=set
Realiza un volcado completo en hexadecimal y ASCII de todos los datos leídos de los descriptores de archivo listados en el conjunto especificado. Por ejemplo, para ver toda la actividad de entrada en los descriptores de archivo 3 y 5, usa --read=3,5. Ten en cuenta que esto es independiente del rastreo normal de la llamada al sistema read(2) que se controla mediante la opción --trace=read.
-e write=set
-e writes=set
-e w=set
--write=set
Realiza un volcado completo en hexadecimal y ASCII de todos los datos escritos en los descriptores de archivo listados en el conjunto especificado. Por ejemplo, para ver toda la actividad de salida en los descriptores de archivo 3 y 5, usa --write=3,5. Ten en cuenta que esto es independiente del rastreo normal de la llamada al sistema write(2) que se controla mediante la opción --trace=write.
-e quiet=set
-e silent=set
-e silence=set
-e q=set
--quiet=set
--silent=set
--silence=set
Suprime varios mensajes informativos. El valor predeterminado es --quiet=none. set puede incluir los siguientes elementos:
attach
Suprime mensajes sobre adjuntar y desadjuntar ("[ Proceso NNNN adjunto ]", "[ Proceso NNNN desadjunto ]").
exit
Suprime mensajes sobre la salida de procesos ("+++ salió con SSS +++").
path-resolution
Suprime mensajes sobre la resolución de rutas proporcionadas a través de la opción -P ("Ruta solicitada "..." resuelta en "..."").
personality
Suprime mensajes sobre cambios de personalidad del proceso ("[ Proceso PID=NNNN se ejecuta en modo PPP. ]").
thread-execve
superseded
Suprime mensajes sobre procesos siendo reemplazados por execve(2) en otro hilo ("+++ reemplazado por execve en pid NNNN +++").
-e decode-fds=set
--decode-fds=set
Decodifica diversa información asociada con descriptores de archivo. El valor predeterminado es --decode-fds=none. set puede incluir los siguientes elementos:
path
Imprime rutas de archivo. También habilita la impresión del directorio de trabajo actual del rastreado cuando se usa la constante AT_FDCWD.
socket
Imprime información específica del protocolo de socket.
dev
Imprime números de dispositivo de carácter/bloque.
eventfd
Imprime detalles del objeto eventfd asociados con descriptores de archivo eventfd.

Los valores de tiempo se especifican como un número decimal de punto flotante (en un formato aceptado por strtod(3)), opcionalmente seguido de un sufijo para indicar la unidad de tiempo: s (segundos), ms (milisegundos), us (microsegundos) o ns (nanosegundos). El formato descrito se utiliza para las opciones -O, --inject=delay_enter y --inject=delay_exit.

DIAGNÓSTICOS

Cuando comando sale, strace sale con el mismo estado de salida. Si comando es terminado por una señal, strace se termina a sí mismo con la misma señal, de modo que strace puede ser utilizado como un proceso envoltorio transparente para el proceso padre que lo invoca. Tenga en cuenta que la relación padre-hijo (notificaciones de parada por señal, el valor de getppid(2), etc.) entre el proceso trazado y su padre no se conserva a menos que se utilice -D.

Al usar -p sin un comando, el estado de salida de strace es cero a menos que no se haya adjuntado ningún proceso o se haya producido un error inesperado durante el trazado.

INSTALACIÓN SETUID

Si strace está instalado como setuid root, entonces el usuario invocador podrá adjuntarse y trazar procesos propiedad de cualquier usuario. Además, los programas setuid y setgid se ejecutarán y trazarán con los privilegios efectivos correctos. Dado que estas capacidades solo deben concederse a usuarios con privilegios de root completos, instalar strace como setuid root solo es apropiado cuando su uso se restringe a usuarios de confianza. Por ejemplo, una versión especial de strace podría instalarse con el modo 'rwsr-x---', usuario root, y grupo trace. En esta configuración, solo los usuarios de confianza que sean miembros del grupo trace podrían ejecutarlo. Si usa esta característica, recuerde también instalar una versión regular, no setuid, de strace para usuarios ordinarios.

NOTAS

Los sistemas que utilizan bibliotecas compartidas a menudo producen una gran cantidad de salida de trazado al cargarlas.

Es instructivo pensar en las entradas y salidas de las llamadas al sistema como flujo de datos a través del límite usuario/kernel. Dado que el espacio de usuario y el espacio del kernel están separados y protegidos por direcciones, a veces es posible hacer inferencias deductivas sobre el comportamiento del proceso utilizando las entradas y salidas como proposiciones.

En algunos casos, una llamada al sistema diferirá del comportamiento documentado o tendrá un nombre diferente. Por ejemplo, la llamada subyacente al sistema faccessat(2) no tiene un argumento flags, y la función de biblioteca setrlimit(2) se implementa utilizando la llamada al sistema prlimit64(2) en los kernels modernos (2.6.38+). Estas discrepancias son características normales de la interfaz de llamadas al sistema y son manejadas por funciones envoltorio de la biblioteca C.

Algunas llamadas al sistema tienen nombres diferentes en diferentes arquitecturas y personalidades. En estos casos, el filtrado y la impresión de llamadas al sistema utilizan los nombres que coinciden con las macros del kernel __NR_* correspondientes de la arquitectura y personalidad del tracee. Hay dos excepciones a esta regla general: la llamada al sistema ARM arm_fadvise64_64(2) y la llamada al sistema Xtensa xtensa_fadvise64_64(2) se filtran y se imprimen como fadvise64_64(2).

En la ABI x32, algunas llamadas al sistema están destinadas a procesos de 64 bits pero pueden invocarse desde x32 estableciendo el indicador __X32_SYSCALL_BIT. Cuando esto ocurre, strace designa estas llamadas con un sufijo #64. Un ejemplo es readv(2), que es el número de llamada al sistema 19 en x86_64, mientras que su contraparte distinta en x32 es el número de llamada al sistema 515.

En algunas plataformas, un proceso adjunto con la opción -p puede recibir un error espurio EINTR de una llamada al sistema no reiniciable. Esto puede tener un efecto impredecible en el proceso si no intenta reiniciar la llamada. Idealmente, todas las llamadas al sistema deberían reiniciarse al adjuntarse strace, haciendo que la adjunción sea invisible para el proceso trazado, pero unas pocas llamadas al sistema no lo son. Podría argumentarse que cada instancia de tal comportamiento es un error del kernel.

Dado que strace ejecuta el comando especificado directamente sin un shell, los scripts que carecen de una línea shebang (por ejemplo, #!/bin/sh) fallarán con un error ENOEXEC, incluso si un shell pudiera ejecutarlos correctamente. Se recomienda proporcionar manualmente un shell como comando con el script como su argumento.

ERRORES

Los programas que utilizan el bit setuid no tienen privilegios de ID de usuario efectivo mientras están siendo trazados.

Un proceso trazado se ejecuta más lentamente que uno no trazado. El impacto en el rendimiento se puede mitigar utilizando la opción --seccomp-bpf.

Al trazar un comando, sus procesos descendientes pueden quedar ejecutándose después de que strace sea terminado por una señal de interrupción (como CTRL-C). Esto se puede prevenir utilizando la opción --kill-on-exit, o utilizando la opción --seccomp-bpf de una manera que implique --kill-on-exit.

Un proceso trazado puede usar la bandera CLONE_UNTRACED con la llamada al sistema clone para crear un proceso hijo que no sea trazado por strace. Esto rompe una garantía de la opción --seccomp-bpf, ya que este hijo no trazado puede quedarse con un filtro seccomp activo después de que strace termine.

HISTORIA

El strace original fue escrito por Paul Kranenburg para SunOS y se inspiró en su utilidad trace. La versión de SunOS de strace fue portada a Linux y mejorada por Branko Lankester, quien también escribió el soporte para el kernel de Linux. A pesar de que Paul lanzó strace 2.5 en 1992, el trabajo de Branko se basó en la versión 1.5 de strace de Paul de 1991.

En 1993, Rick Sladkey asumió el proyecto. Fusionó strace 2.5 para SunOS con la segunda versión de strace para Linux, agregó muchas características de truss(1) de SVR4, y produjo una versión de strace que funcionaba en ambas plataformas. En 1994, Rick portó strace a SVR4 y Solaris y escribió el soporte de configuración automática. En 1995 portó strace a Irix (y se cansó de escribir sobre sí mismo en tercera persona).

A partir de 1996, strace fue mantenido por Wichert Akkerman. Durante su mandato, el desarrollo de strace migró a CVS; se introdujeron ports a FreeBSD y muchas arquitecturas en Linux (incluyendo ARM, IA-64, MIPS, PA-RISC, PowerPC, s390, SPARC).

En 2002, la responsabilidad del mantenimiento de strace fue transferida a Roland McGrath. Desde entonces, strace ha ganado

HISTORY

strace was originally written by Torsten Duwe. In the early days, strace had support for Linux/i386 and Linux/alpha. Later, it gained support for Linux/ARM, Linux/MIPS, Linux/x86_64, Linux/PPC64, and Linux/IA64. In the meantime, it has gained support for many other architectures and operating systems. For example, strace gained support for the SPARC architecture in 2001.

In 2004, strace had received support for several new Linux architectures (AMD64, s390x, SuperH), bi-architecture support for some of them, and received numerous additions and improvements in system calls decoders on Linux; strace development migrated to Git during that period.

Since 2009, strace has been actively maintained by Dmitry Levin. During this period, strace has gained support for the AArch64, ARC, AVR32, Blackfin, C-SKY, LoongArch, Meta, Nios II, OpenRISC 1000, RISC-V, Tile/TileGx, and Xtensa architectures. In 2012, unmaintained and apparently broken support for non-Linux operating systems was removed. Also, in 2012 strace gained support for path tracing and file descriptor path decoding. In 2014, support for stack trace printing was added. In 2016, system call tampering was implemented.

For the additional information, please refer to the NEWS file and strace repository commit log.
