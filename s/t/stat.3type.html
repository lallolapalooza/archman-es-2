stat(3type) stat(3type)

NOMBRE

stat - estado del archivo

BIBLIOTECA

Biblioteca C estándar (libc)

SINOPSIS

#include <sys/stat.h>
struct stat {
    dev_t      st_dev;      /* ID del dispositivo que contiene el archivo */
    ino_t      st_ino;      /* Número de inodo */
    mode_t     st_mode;     /* Tipo y modo del archivo */
    nlink_t    st_nlink;    /* Número de enlaces duros */
    uid_t      st_uid;      /* ID de usuario del propietario */
    gid_t      st_gid;      /* ID del grupo del propietario */
    dev_t      st_rdev;     /* ID del dispositivo (si es un archivo especial) */
    off_t      st_size;     /* Tamaño total, en bytes */
    blksize_t  st_blksize;  /* Tamaño de bloque para I/O del sistema de archivos */
    blkcnt_t   st_blocks;   /* Número de bloques de 512 B asignados */
    /* Desde POSIX.1-2008, esta estructura admite precisión de nanosegundos
       para los siguientes campos de marca de tiempo.
       Para los detalles anteriores a POSIX.1-2008, véase VERSIONS.  */
    struct timespec  st_atim;  /* Tiempo del último acceso */
    struct timespec  st_mtim;  /* Tiempo de la última modificación */
    struct timespec  st_ctim;  /* Tiempo del último cambio de estado */
#define st_atime  st_atim.tv_sec  /* Compatibilidad hacia atrás */
#define st_mtime  st_mtim.tv_sec
#define st_ctime  st_ctim.tv_sec
};
Requisitos de Macro de Prueba de Características para glibc (ver feature_test_macros(7)):

st_atim, st_mtim, st_ctim:

    Desde glibc 2.12:
        _POSIX_C_SOURCE >= 200809L || _XOPEN_SOURCE >= 700
    glibc 2.19 y anteriores:
        _BSD_SOURCE || _SVID_SOURCE

DESCRIPCIÓN

Describe información sobre un archivo.

Los campos son los siguientes:

st_dev
Este campo describe el dispositivo en el que reside este archivo. (Las macros major(3) y minor(3) pueden ser útiles para descomponer el ID del dispositivo en este campo.)
st_ino
Este campo contiene el número de inodo del archivo.
st_mode
Este campo contiene el tipo y modo del archivo. Consulte inode(7) para más información.
st_nlink
Este campo contiene el número de enlaces duros al archivo.
st_uid
Este campo contiene el ID de usuario del propietario del archivo.
st_gid
Este campo contiene el ID del grupo propietario del archivo.
st_rdev
Este campo describe el dispositivo que representa este archivo (inodo).
st_size
Este campo proporciona el tamaño del archivo (si es un archivo regular o un enlace simbólico) en bytes. El tamaño de un enlace simbólico es la longitud del nombre de ruta que contiene, sin un byte nulo de terminación.
st_blksize
Este campo proporciona el tamaño de bloque "preferido" para una E/S eficiente del sistema de archivos.
st_blocks
Este campo indica el número de bloques asignados al archivo, en unidades de 512 bytes. (Esto puede ser menor que st_size/512 cuando el archivo tiene agujeros.)
st_atime
Este es el momento del último acceso a los datos del archivo.
st_mtime
Este es el momento de la última modificación de los datos del archivo.
st_ctime
Esta es la marca de tiempo del último cambio de estado del archivo (momento del último cambio en el inodo).

Para más información sobre los campos anteriores, consulte inode(7).

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001.

Los kernels antiguos y los estándares antiguos no admitían campos de marca de tiempo de nanosegundos. En su lugar, había tres campos de marca de tiempo —st_atime, st_mtime y st_ctime— de tipo time_t que registraban marcas de tiempo con precisión de un segundo.

Desde Linux 2.5.48, la estructura stat admite resolución de nanosegundos para los tres campos de marca de tiempo del archivo. Los componentes de nanosegundos de cada marca de tiempo están disponibles a través de nombres de la forma st_atim.tv_nsec, si se definen macros de prueba adecuadas. Las marcas de tiempo de nanosegundos se estandarizaron en POSIX.1-2008 y, a partir de glibc 2.12, glibc expone los nombres de los componentes de nanosegundos si _POSIX_C_SOURCE se define con el valor 200809L o superior, o _XOPEN_SOURCE se define con el valor 700 o superior. Hasta glibc 2.19 inclusive, las definiciones de los componentes de nanosegundos también se definen si se definen _BSD_SOURCE o _SVID_SOURCE. Si ninguna de las macros mencionadas anteriormente se define, entonces los valores de nanosegundos se exponen con nombres de la forma st_atimensec.

NOTAS

La siguiente cabecera también proporciona este tipo: <ftw.h>.
