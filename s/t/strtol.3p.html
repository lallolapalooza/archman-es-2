STRTOL(3P) Manual de Programador POSIX STRTOL(3P)

PROLOGO

Esta página del manual forma parte del Manual de Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

strtol, strtoll — convertir una cadena a un entero largo

SINOPSIS

#include <stdlib.h>
long strtol(const char *restrict nptr, char **restrict endptr, int base);
long long strtoll(const char *restrict nptr, char **restrict endptr,
    int base)

DESCRIPCION

La funcionalidad descrita en esta página de referencia está alineada con el estándar ISO C. Cualquier conflicto entre los requisitos descritos aquí y el estándar ISO C es involuntario. Este volumen de POSIX.1‐2017 se remite al estándar ISO C.

Estas funciones convertirán la porción inicial de la cadena apuntada por nptr a una representación de tipo long y long long, respectivamente. Primero, descomponen la cadena de entrada en tres partes:

1.
Una secuencia inicial, posiblemente vacía, de caracteres de espacio en blanco (según lo especificado por isspace())
2.
Una secuencia de sujeto interpretada como un entero representado en una base determinada por el valor de base
3.
Una cadena final de uno o más caracteres no reconocidos, incluido el carácter NUL de terminación de la cadena de entrada.

Luego, intentarán convertir la secuencia de sujeto a un entero y devolverán el resultado.

Si el valor de base es 0, la forma esperada de la secuencia de sujeto es la de una constante decimal, una constante octal o una constante hexadecimal, cualquiera de las cuales puede ir precedida por un signo '+' o '-'. Una constante decimal comienza con un dígito distinto de cero y consta de una secuencia de dígitos decimales. Una constante octal consta del prefijo '0' seguido opcionalmente por una secuencia de los dígitos '0' a '7' solamente. Una constante hexadecimal consta del prefijo 0x o 0X seguido por una secuencia de dígitos decimales y letras 'a' (o 'A') a 'f' (o 'F') con valores de 10 a 15 respectivamente.

Si el valor de base está entre 2 y 36, la forma esperada de la secuencia de sujeto es una secuencia de letras y dígitos que representan un entero con la base especificada por base, opcionalmente precedida por un signo '+' o '-'. Las letras de 'a' (o 'A') a 'z' (o 'Z') inclusive se les atribuyen los valores de 10 a 35; solo se permiten letras cuyos valores atribuidos sean menores que los de base. Si el valor de base es 16, los caracteres 0x o 0X pueden opcionalmente preceder la secuencia de letras y dígitos, siguiendo al signo si está presente.

La secuencia de sujeto se define como la sub-secuencia inicial más larga de la cadena de entrada, comenzando con el primer carácter que no sea espacio en blanco que tenga la forma esperada. La secuencia de sujeto no contendrá caracteres si la cadena de entrada está vacía o consta enteramente de caracteres de espacio en blanco, o si el primer carácter que no sea espacio en blanco es diferente de un signo o de una letra o dígito permitido.

Si la secuencia de sujeto tiene la forma esperada y el valor de base es 0, la secuencia de caracteres que comienza con el primer dígito se interpretará como una constante entera. Si la secuencia de sujeto tiene la forma esperada y el valor de base está entre 2 y 36, se utilizará como base para la conversión, atribuyendo a cada letra su valor como se indica arriba. Si la secuencia de sujeto comienza con un <signo menos>, el valor resultante de la conversión se negará. Se almacenará un puntero a la cadena final en el objeto al que apunta endptr, siempre que endptr no sea un puntero nulo.

En localidades distintas de la C o POSIX, se pueden aceptar formas de secuencia de sujeto adicionales específicas de la localidad.

Si la secuencia de sujeto está vacía o no tiene la forma esperada, no se realiza ninguna conversión; el valor de nptr se almacenará en el objeto al que apunta endptr, siempre que endptr no sea un puntero nulo.

Estas funciones no cambiarán la configuración de errno si se realizan con éxito.

Dado que 0, {LONG_MIN} o {LLONG_MIN}, y {LONG_MAX} o {LLONG_MAX} se devuelven en caso de error y también son devoluciones válidas en caso de éxito, una aplicación que desee comprobar situaciones de error debe establecer errno a 0, luego llamar a strtol() o strtoll(), y luego comprobar errno.

VALOR DE RETORNO

Tras una finalización exitosa, estas funciones devolverán el valor convertido, si lo hay. Si no se pudo realizar ninguna conversión, se devolverá 0 y errno puede establecerse en [EINVAL].

Si el valor de base no es compatible, se devolverá 0 y errno se establecerá en [EINVAL].

Si el valor correcto está fuera del rango de valores representables, se devolverá {LONG_MIN}, {LONG_MAX}, {LLONG_MIN} o {LLONG_MAX} (según el signo del valor), y errno se establecerá en [ERANGE].

ERRORES

Estas funciones fallarán si:

EINVAL
El valor de base no es compatible.
ERANGE
El valor a devolver no es representable.

Estas funciones pueden fallar si:

EINVAL
No se pudo realizar ninguna conversión.

USO DE APLICACIONES

Dado que el valor de *endptr no se especifica si el valor de base no es compatible, las aplicaciones deben asegurarse de que base tenga un valor compatible (0 o entre 2 y 36) antes de la llamada, o comprobar si hay un error [EINVAL] antes de examinar *endptr.
