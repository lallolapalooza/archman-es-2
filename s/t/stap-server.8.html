STAP-SERVER(8) Manual del Administrador del Sistema STAP-SERVER(8)

NOMBRE

stap-server - gestión del servidor de compilación systemtap

SINOPSIS

[ service ] stap-server { start | stop | restart | condrestart | try-restart | force-reload | status } [ options ]

DESCRIPCIÓN

Un servidor de compilación de systemtap escucha conexiones de clientes stap en un puerto seguro de red SSL y acepta solicitudes para ejecutar el frontend de stap. Cada servidor anuncia su presencia y configuración en la red local usando mDNS (avahi), permitiendo la detección automática por parte de los clientes.

El script stap-server tiene como objetivo proporcionar:

  • gestión de servidores de compilación de systemtap como un servicio.
  • control conveniente sobre servidores configurados y servidores individuales (ad-hoc).

ARGUMENTOS

Se debe especificar una de las siguientes acciones:

start
Inicia servidores. Se inician los servidores especificados. Si no se especifica ningún servidor, se inician los servidores configurados. Si no hay servidores configurados, se inicia un servidor para la versión del kernel y la arquitectura del host. Si un servidor especificado ya está en ejecución, esta acción se ignorará para ese servidor. Si un servidor falla al iniciarse, esta acción falla.
stop
Detiene servidor(es). Se detienen los servidores especificados. Si no se especifica ningún servidor, se detienen todos los servidores en ejecución. Si un servidor especificado no está en ejecución, esta acción será exitosa para ese servidor. Si un servidor falla al detenerse, esta acción falla.
restart
Detiene y reinicia servidores. Se detienen y reinician los servidores especificados. Si no se especifica ningún servidor, se detienen y reinician todos los servidores en ejecución. Si no hay servidores en ejecución, esta acción se comporta como start.
condrestart
Detiene y reinicia servidores. Se detienen y reinician los servidores especificados. Si un servidor especificado no está en ejecución, no se inicia. Si no se especifica ningún servidor, se detienen y reinician todos los servidores en ejecución. Si no hay servidores en ejecución, no se iniciará ninguno.
try-restart
Esta acción es idéntica a condrestart.
force-reload
Detiene todos los servidores en ejecución, recarga los archivos de configuración y reinicia el servicio como si se hubiera especificado start.
status
Imprime información sobre los servidores en ejecución. Se imprimirá información sobre el(los) servidor(es) especificado(s). Si no se especifica ningún servidor, se imprimirá información sobre todos los servidores en ejecución.

OPCIONES

Las siguientes opciones se utilizan para proporcionar configuración adicional y para especificar los servidores que se gestionarán:

-c archivo-configuración
Esta opción especifica un archivo de configuración global además del archivo de configuración global predeterminado descrito a continuación. Este archivo se procesará después del archivo de configuración global predeterminado. Si la opción -c se especifica más de una vez, se utilizará el último archivo de configuración especificado.
-a arquitectura
Esta opción especifica la arquitectura de destino del servidor y es análoga a la opción -a de stap. Consulte la página del manual de stap(1) para más detalles. La arquitectura predeterminada es la arquitectura del host.
-r versión-kernel
Esta opción especifica una versión de kernel de destino para el servidor y es análoga a la opción -r de stap. Consulte la página del manual de stap(1) para más detalles. La versión predeterminada es la del kernel actualmente en ejecución. Un servidor puede manejar múltiples versiones especificando múltiples flags -r.
-I ruta
Esta opción especifica una ruta adicional que será buscada por el(los) servidor(es) para obtener tapsets y es análoga a la opción -I de stap. Consulte la página del manual de stap(1) para más detalles.
-R ruta
Esta opción especifica la ubicación del runtime de systemtap que será utilizado por el(los) servidor(es) y es análoga a la opción -R de stap. Consulte la página del manual de stap(1) para más detalles.
-B opciones
Esta opción especifica opciones que se pasarán a make al compilar módulos de systemtap y es análoga a la opción -B de stap. Consulte la página del manual de stap(1) para más detalles.
-i
Esta opción es un atajo que especifica un servidor que maneja cada versión instalada en /lib/modules/.
-n apodo
Esta opción permite la especificación de una configuración de servidor por apodo. Cuando se especifica -n, se buscará un servidor en ejecución con el apodo dado. Si no se encuentra ningún servidor en ejecución con el apodo dado, se buscará una configuración de servidor con el apodo dado en los archivos de configuración para servidores predeterminados, o en la ruta configurada en el archivo de configuración global o en el archivo de configuración especificado por la opción -c. Si se encuentra una configuración de servidor para el apodo dado, las opciones -a, -r, -I, -R, -B y -u para ese servidor se utilizarán como si se hubieran especificado en la línea de comandos. Si no se encuentra ninguna configuración con el apodo dado, y la acción es start (o una acción que se comporta como start (ver ARGUMENTOS), el servidor se iniciará con el apodo dado. Si no se encuentra ninguna configuración con el apodo dado, y la acción no es start (o una acción que se comporta como start), se producirá un error. Si no se especifica un apodo para un servidor que se está iniciando, su apodo será su ID de proceso.
-p pid
Esta opción permite la especificación de una configuración de servidor por ID de proceso. Cuando se especifica -p, se buscará un servidor en ejecución con el ID de proceso dado. Si no se encuentra dicho servidor, se producirá un error. Si se encuentra un servidor con el ID de proceso dado, las opciones -a, -r, -I, -R, -B y -u para ese servidor se utilizarán como si se hubieran especificado en la línea de comandos.
-u nombre-usuario
Cada servidor de compilación de systemtap se ejecuta normalmente bajo el nombre de usuario stap-server (para el script de inicio) o como el usuario que invoca a stap-server, a menos que se configure lo contrario (ver ARCHIVOS). Esta opción especifica el nombre de usuario utilizado para ejecutar el(los) servidor(es). El nombre de usuario especificado debe ser miembro del grupo stap-server.
--log archivo-registro
Esta opción permite la especificación de un archivo de registro separado para cada servidor. Cada opción --log se agrega a una lista que se aplicará, por turno, a cada servidor especificado. Si se especifican más servidores que opciones --log, se utilizará el archivo de registro predeterminado (ver ARCHIVOS) para los servidores subsiguientes.
--port número-puerto
Esta opción permite la especificación de un puerto de red específico para cada servidor. Cada opción --port se agrega a una lista que se aplicará, por turno, a cada servidor especificado. Si se especifican más servidores que opciones --port, se utilizará un puerto seleccionado aleatoriamente para los servidores subsiguientes.
--ssl ruta-db-certificados
Esta opción permite la especificación de una base de datos de certificados NSS separada para cada servidor. Cada opción --ssl se agrega a una lista que se aplicará, por turno, a cada servidor especificado. Si se especifican más

--max-threads hilos
Esta opción permite especificar el número máximo de hilos de trabajo para manejar solicitudes concurrentes. Si hilos == 0, cada solicitud se manejará en el hilo principal, secuencialmente. El valor predeterminado es el número de núcleos de procesador disponibles.
--max-request-size tamaño
Esta opción permite especificar el tamaño máximo de una solicitud de cliente sin comprimir. El argumento tamaño se especifica en bytes. El valor predeterminado es 50000 bytes.
--max-compressed-request tamaño
Esta opción permite especificar el tamaño máximo de una solicitud de cliente comprimida. El argumento tamaño se especifica en bytes. El valor predeterminado es 5000 bytes.

CONFIGURACIÓN

Los archivos de configuración nos permiten:

  • especificar la configuración global de registro, archivos de configuración del servidor, archivos de estado y otros parámetros globales.
  • especificar qué servidores se iniciarán por defecto.

Configuración Global

El archivo de Configuración Global contiene asignaciones de variables utilizadas para configurar la operación general del servicio. Cada línea que comienza con el carácter '#' se ignora. Todas las demás líneas deben tener el formato VARIABLE=VALOR. Esto no es un script de shell. El contenido completo de la línea después del = se asignará tal cual a la variable.

Las siguientes variables pueden ser asignadas:

CONFIG_PATH
Especifica la ruta absoluta del directorio que contiene las configuraciones predeterminadas del servidor.
STAT_PATH
Especifica la ruta absoluta del directorio de estado del servidor en ejecución.
LOG_FILE
Especifica la ruta absoluta del archivo de registro.
STAP_USER
Especifica el ID de usuario que se utilizará para ejecutar el(los) servidor(es) (predeterminado: para el script de inicio stap-server, de lo contrario, el usuario que ejecuta stap-server).

Aquí hay un ejemplo de un archivo de Configuración Global:

CONFIG_PATH=~<usuario>/my-stap-server-configs
LOG_FILE=/tmp/stap-server/log

Configuración Individual del Servidor

Cada archivo de configuración del servidor configura un servidor para que se inicie cuando no se especifica ningún servidor para la acción start, o una acción que se comporta como la acción start (ver ARGUMENTOS). Cada archivo de configuración contiene asignaciones de variables utilizadas para configurar un servidor individual.

Cada línea que comienza con el carácter '#' se ignora. Todas las demás líneas deben tener el formato VARIABLE=VALOR. Esto no es un script de shell. El contenido completo de la línea después del = se asignará tal cual a la variable.

Cada archivo de configuración debe tener una extensión de nombre de archivo de .conf. Ver stappaths(7) para la ubicación predeterminada de estos archivos. Esta ubicación predeterminada puede ser anulada en el archivo de configuración global usando la opción -c (ver OPCIONES).

Las siguientes variables pueden ser asignadas:

ARCH
Especifica la arquitectura de destino para este servidor y corresponde a la opción -a (ver OPCIONES). Si ARCH no está configurado, se utilizará la arquitectura del host.
RELEASE
Especifica una versión del kernel para este servidor y corresponde a la opción -r (ver OPCIONES). Si RELEASE no está configurado, se utilizará la versión del kernel que se está ejecutando en el host.
BUILD
Especifica las opciones que se pasarán al proceso make utilizado por systemtap para compilar módulos del kernel. Esta es una variable de matriz con cada elemento correspondiente a una opción -B (ver OPCIONES). Usar la forma BUILD=CADENA borra la matriz y establece el primer elemento en CADENA. Usar la forma BUILD+=CADENA agrega CADENA como un elemento adicional a la matriz.
INCLUDE
Especifica una lista de directorios que el servidor buscará para obtener tapsets. Esta es una variable de matriz con cada elemento correspondiente a una opción -I (ver OPCIONES). Usar la forma INCLUDE=RUTA borra la matriz y establece el primer elemento en RUTA. Usar la forma INCLUDE+=RUTA agrega RUTA como un elemento adicional a la matriz.
RUNTIME
Especifica el directorio que contiene el código de tiempo de ejecución de systemtap que será utilizado por este servidor y corresponde a la opción -R (ver OPCIONES).
USER
Especifica el nombre de usuario que se utilizará para ejecutar este servidor y corresponde a la opción -u (ver OPCIONES).
NICKNAME
Especifica el apodo que se utilizará para referirse a este servidor y corresponde a la opción -n (ver OPCIONES).
LOG
Especifica la ubicación del archivo de registro que utilizará este servidor y corresponde a la opción --log (ver OPCIONES).
PORT
Especifica el puerto de red que utilizará este servidor y corresponde a la opción --port (ver OPCIONES).
SSL
Especifica la ubicación de la base de datos de certificados NSS que utilizará este servidor y corresponde a la opción --ssl (ver OPCIONES).
MAXTHREADS
Especifica el número máximo de hilos de trabajo para manejar solicitudes concurrentes que utilizará este servidor y corresponde a la opción --max-threads (ver OPCIONES).
MAXREQSIZE
Especifica el tamaño máximo de una solicitud de cliente sin comprimir, que utilizará este servidor y corresponde a la opción --max-request-size (ver OPCIONES).
MAXCOMPRESSEDREQ
Especifica el tamaño máximo de una solicitud de cliente comprimida, que utilizará este servidor y corresponde a la opción --max-compressed-request (ver OPCIONES).

Aquí hay un ejemplo de un archivo de configuración de servidor:

ARCH=
USER=
RELEASE=
NICKNAME=native

Al mantener los campos ARCH, USER y RELEASE en blanco, se usarán los valores predeterminados de la arquitectura y versión actuales y se utilizará el usuario predeterminado.

Un ejemplo más específico:

ARCH=i386
RELEASE=2.6.18-128.el5
PORT=5001
LOG=/path/to/log/file

Y aquí hay un ejemplo más complicado:

USER=serveruser
RELEASE=/kernels/2.6.18-92.1.18.el5/build
INCLUDE=/mytapsets
INCLUDE+=/yourtapsets
BUILD='VARIABLE1=VALUE1 VARIABLE2=VALUE2'
DEFINE=STP_MAXMEMORY=1024
DEFINE+=DEBUG_TRANS
RUNTIME=/myruntime
NICKNAME=my-server
SSL=/path/to/NSS/certificate/database

AUTENTICACIÓN DEL SERVIDOR

La seguridad de la conexión de red SSL entre el cliente y el servidor depende de la gestión adecuada de los certificados del servidor.

La confiabilidad de un servidor de compilación de systemtap dado no puede determinarse automáticamente sin una autoridad de certificación de confianza que emita certificados de servidor de compilación de systemtap. Esto no es práctico en el uso diario y, por lo tanto, los clientes deben autenticar los servidores contra su propia base de datos de certificados de servidores confiables. En este contexto, establecer un servidor dado como confiable por un cliente dado significa agregar el certificado de ese servidor a la base de datos de servidores confiables del cliente.

Para el script de inicio stap-server, en el host local, esto se maneja automáticamente. Cuando se instala el paquete systemtap-server, el certificado del servidor para el usuario predeterminado (stap-server) se genera e instala automáticamente. Esto significa que los servidores iniciados por el script de inicio stap-server, con el usuario predeterminado, son automáticamente confiables por los clientes en el host local, tanto como un par SSL como un firmante de módulos de systemtap.

Además, cuando stap es invocado por un usuario no privilegiado (no root, no miembro del grupo stapdev, sino miembro del grupo stapusr y posiblemente del grupo stapsys), las opciones --use-server y --privilege se agregan automáticamente a las opciones especificadas. Esto significa que los usuarios no privilegiados en el host local pueden usar un servidor en el host local en modo no privilegiado sin configuración ni opciones adicionales requeridas. Los usuarios normales (aquellos que no están en ningún grupo de SystemTap) también pueden usar servidores de compilación a través de las opciones --use-server y --privilege. Pero, por supuesto, no podrán cargar el módulo (la opción -p4 se puede usar para detenerse antes de cargar).

Para usar un servidor que se ejecuta en otro host, el certificado de ese servidor debe estar instalado en el host del cliente. Consulte la opción --trust-servers en la página del manual de stap(1) para más detalles y README.unprivileged en las fuentes de systemtap para más detalles.

EJEMPLOS

Consulte la página del manual de stapex(3stap) para ver una colección de scripts de ejemplo de systemtap.

Para iniciar los servidores configurados, o el servidor predeterminado, si no hay ninguno configurado:

$ [ servicio ] stap-server start

Para iniciar un servidor que maneja todas las versiones del kernel instaladas en /lib/modules:

$ [ servicio ] stap-server start -i

Para obtener información sobre el(los) servidor(es) en ejecución:

$ [ servicio ] stap-server status

EXAMPLES

Para iniciar un servidor como otro, pero apuntando a una arquitectura diferente, haciendo referencia al alias del primer servidor:

$ [ service ] stap-server start -n ALIAS -a ARQUITECTURA

Para iniciar un servidor para una versión de kernel no instalada (compilación cruzada)

$ [ service ] stap-server start -a ARQUITECTURA -r /DIRECTORIO_DE_COMPILACION

Para detener uno de los servidores haciendo referencia a su ID de proceso (obtenido ejecutando stap-server status):

$ [ service ] stap-server stop -p PID

Para ejecutar un script utilizando un servidor de compilación:

$ stap SCRIPT --use-server

Para ejecutar un script como un usuario no privilegiado utilizando un servidor de compilación:

$ stap SCRIPT

Para detener todos los servidores en ejecución:

$ [ service ] stap-server stop

Para reiniciar los servidores después de un cambio de configuración global y/o cuando se han agregado, cambiado o eliminado servidores predeterminados:

$ [ service ] stap-server force-reload

SEGURIDAD Y PROTECCIÓN

Systemtap es una herramienta administrativa. Expone las estructuras de datos internas del kernel y potencialmente información privada del usuario. Consulte la página del manual de stap(1) para obtener información adicional sobre seguridad y protección.

Como servidor de red, stap-server debe activarse con cuidado para limitar los efectos potenciales de errores o usuarios maliciosos. Considere las siguientes medidas profilácticas.

1
Ejecute stap-server como un usuario no privilegiado, nunca como root.

Cuando se invoca como un servicio (es decir, service stap-server ...), cada servidor se ejecuta, por defecto, como el usuario stap-server. Cuando se invoca directamente (es decir, stap-server ...), cada servidor se ejecuta, por defecto, como el usuario que lo invoca. En cada caso, se puede seleccionar otro usuario utilizando la opción -u al invocarlo, especificando STAP_USER=nombredeusuario en el archivo de configuración global o especificando USER=nombredeusuario en un archivo de configuración individual del servidor. El usuario que lo invoca debe tener autoridad para ejecutar procesos como otro usuario. Consulte CONFIGURACIÓN.

El usuario seleccionado debe tener acceso de escritura al archivo de registro del servidor. La ubicación del archivo de registro del servidor se puede cambiar estableciendo LOG_FILE=ruta en el archivo de configuración global. Consulte CONFIGURACIÓN.

El usuario seleccionado debe tener acceso de lectura/escritura al directorio que contiene los archivos de estado del servidor. La ubicación de los archivos de estado del servidor se puede cambiar estableciendo STAT_PATH=ruta en el archivo de configuración global. Consulte CONFIGURACIÓN.

El usuario seleccionado debe tener acceso de lectura/escritura al directorio de compilación de uprobes.ko y sus archivos.

Ninguna forma de stap-server se ejecutará si el usuario seleccionado es root.

2
Ejecute las solicitudes de stap-server con límites de recursos que impongan un tiempo máximo de CPU, tamaño de archivo y consumo de memoria, para limitar los efectos del procesamiento de entradas excesivamente grandes o falsas.

Cuando el usuario que ejecuta el servidor es stap-server, cada solicitud del servidor se ejecuta con los límites especificados en ~stap-server/.systemtap/rc, de lo contrario, no se imponen límites.

3
Ejecute stap-server con una variable de entorno TMPDIR que apunte a un directorio separado y/o con cuotas, para evitar llenar sistemas de archivos importantes.

El TMPDIR predeterminado es /tmp/.

4
Active firewalls de red para limitar las conexiones de clientes de stap a redes relativamente confiables.

Para la selección automática de servidores por parte de los clientes, avahi debe estar instalado tanto en los hosts del servidor como en los del cliente y los mensajes mDNS deben permitirse a través del firewall.

El servidor de compilación de systemtap y sus utilidades relacionadas utilizan Secure Socket Layer (SSL) implementado por Network Security Services (NSS) para la seguridad de la red. NSS también se utiliza para la generación y gestión de certificados. Las bases de datos de certificados relacionadas deben protegerse para mantener la seguridad del sistema. El uso de las utilidades proporcionadas ayudará a garantizar que se mantenga la protección adecuada. El cliente de systemtap verificará los permisos de acceso adecuados antes de utilizar cualquier base de datos de certificados.
