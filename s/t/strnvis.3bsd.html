DESCRIPCIÓN

La función vis() copia en dst una cadena que representa el carácter c. Si c no necesita codificación, se copia sin modificar. La cadena se termina con nulo y se devuelve un puntero al final de la cadena. La longitud máxima de cualquier codificación es de cuatro bytes (sin incluir el nulo final); por lo tanto, al codificar un conjunto de caracteres en un búfer, el tamaño del búfer debe ser cuatro veces el número de bytes codificados, más uno para el nulo final. El parámetro flag se utiliza para alterar el rango por defecto de caracteres considerados para la codificación y para alterar la representación visual. El carácter adicional, nextc, solo se utiliza al seleccionar el formato de codificación VIS_CSTYLE (explicado a continuación).

Las funciones strvis(), stravis(), strnvis(), strvisx() y strnvisx() copian en dst una representación visual de la cadena src. Las funciones strvis() y strnvis() codifican caracteres de src hasta el primer nulo. Las funciones strvisx() y strnvisx() codifican exactamente len caracteres de src (esto es útil para codificar un bloque de datos que puede contener nulos). Ambas formas terminan con nulo dst. El tamaño de dst debe ser cuatro veces el número de bytes codificados de src (más uno para el nulo). Ambas formas devuelven el número de caracteres en dst (sin incluir el nulo final). Las funciones svis(), snvis(), strsvis(), strsnvis(), strsvisx(), strsnvisx(), y strsenvisx() corresponden a vis(), nvis(), strvis(), strnvis(), strvisx(), strnvisx(), y strenvisx() pero tienen un argumento adicional extra, apuntando a una lista de caracteres terminada en NUL. Estos caracteres se copiarán codificados o con escape de barra invertida en dst. Estas funciones son útiles, por ejemplo, para eliminar el significado especial de ciertos caracteres para los shells.

La codificación es una representación única e invertible compuesta enteramente de caracteres gráficos; se puede decodificar a su forma original utilizando las funciones unvis(3bsd), strunvis(3bsd) o strnunvis(3bsd).

Hay dos parámetros que se pueden controlar: el rango de caracteres que se codifican (se aplica solo a vis(), nvis(), strvis(), strnvis(), strvisx(), y strnvisx()), y el tipo de representación utilizado. Por defecto, todos los caracteres no gráficos, excepto el espacio, el tabulador y la nueva línea se codifican (ver isgraph(3)). Las siguientes banderas alteran esto:

VIS_DQ
También codifica las comillas dobles.
VIS_GLOB
También codifica los caracteres mágicos (‘*’, ‘?’, ‘[’, y ‘#’) reconocidos por glob(3).
VIS_SHELL
También codifica los meta-caracteres utilizados por los shells (además de los caracteres de globbing): (‘'’, ‘`’, ‘"’, ‘;’, ‘&’, ‘<’, ‘>’, ‘(’, ‘)’, ‘|’, ‘]’, ‘\’, ‘$’, ‘!’, ‘^’, y ‘~’).
VIS_SP
También codifica el espacio.
VIS_TAB
También codifica el tabulador.
VIS_NL
También codifica la nueva línea.
VIS_WHITE
Sinónimo de VIS_SP | VIS_TAB | VIS_NL.
VIS_META
Sinónimo de VIS_WHITE | VIS_GLOB | VIS_SHELL.
VIS_SAFE
Solo codifica caracteres "inseguros". Inseguro significa caracteres de control que pueden hacer que terminales comunes realicen funciones inesperadas. Actualmente, esta forma permite que el espacio, el tabulador, la nueva línea, el retroceso, la campana y el retorno de carro —además de todos los caracteres gráficos— no se codifiquen.

(Las banderas anteriores no tienen efecto para svis(), snvis(), strsvis(), strsnvis(), strsvisx(), y strsnvisx(). Al usar estas funciones, coloque todos los caracteres gráficos a codificar en un array apuntado por extra. En general, el carácter de barra invertida debe incluirse en este array, vea la advertencia sobre el uso de la bandera VIS_NOSLASH a continuación).

Hay seis formas de codificación. Todas las formas usan el carácter de barra invertida ‘\’ para introducir una secuencia especial; se usan dos barras invertidas para representar una barra invertida real, excepto VIS_HTTPSTYLE que usa ‘%’, o VIS_MIMESTYLE que usa ‘=’. Estos son los formatos visuales:

(predeterminado)
Usa una ‘M’ para representar meta-caracteres (caracteres con el 8vo bit establecido), y usa el circunflejo ‘^’ para representar caracteres de control (ver iscntrl(3)). Se utilizan los siguientes formatos:
\^C
Representa el carácter de control ‘C’. Cubre los caracteres ‘\000’ hasta ‘\037’, y ‘\177’ (como ‘\^?’).
\M-C
Representa el carácter ‘C’ con el 8vo bit establecido. Cubre los caracteres ‘\241’ hasta ‘\376’.
\M^C
Representa el carácter de control ‘C’ con el 8vo bit establecido. Cubre los caracteres ‘\200’ hasta ‘\237’, y ‘\377’ (como ‘\M^?’).
\040
Representa el espacio ASCII.
\240
Representa el meta-espacio.
VIS_CSTYLE
Utiliza secuencias de barra invertida estilo C para representar caracteres no imprimibles estándar. Las siguientes secuencias se utilizan para representar los caracteres indicados: 
\a — BEL (007)
\b — BS (010)
\f — NP (014)
\n — NL (012)
\r — CR (015)
\s — SP (040)
\t — HT (011)
\v — VT (013)
\0 — NUL (000)

Al usar este formato, se examina el parámetro nextc para determinar si un carácter NUL puede ser codificado como ‘\0’ en lugar de ‘\000’. Si nextc es un dígito octal, se utiliza la última representación para evitar ambigüedades.

Los caracteres no imprimibles sin secuencias de barra invertida estilo C utilizan la representación predeterminada.

VIS_OCTAL
Utiliza una secuencia octal de tres dígitos. El formato es ‘\ddd’ donde d representa un dígito octal.

Igual que VIS_CSTYLE excepto que los caracteres no imprimibles sin secuencias de barra invertida estilo C utilizan una secuencia octal de tres dígitos.

DESCRIPTION

The nvis() and snvis() functions create a human-readable representation of binary data. The nvis() function writes the representation to the buffer pointed to by dst, which is assumed to be large enough to hold the result. The snvis() function writes the result into a buffer of size dlen. The strnvis(), strnvisx(), strsnvis(), and strsnvisx() functions are similar, but return the length of the resulting string, or -1 on error.

The vis() and svis() functions are similar to nvis() and snvis() respectively, but write to standard output.

The visx() and strvisx() functions are similar to vis() and strvis() respectively, but also encode the characters specified by the argument localemask.

The strvisx() and strsnvisx() functions are similar to strvis() and strsnvis() respectively, but also encode the characters specified by the argument localemask.

The encoding is done as follows:

  • A literal character is represented by itself.

  • A control character is represented by a caret (`^') followed by the character.

    For example, the control-M character is represented as `^M'.

  • The characters for which the localemask argument has the corresponding bit set are represented by a meta character (`M-') followed by the character.

    For example, if localemask has the bit for `a' set, then `a' will be represented as `M-a'.

    If the character is a control character and the meta bit is set, the meta character representation takes precedence.

  • The characters `\', `^', `M', and the character represented by `=' are escaped by a backslash (`\').

    For example, `\' is represented as `\\'.

There are several flags that can be passed in the flag argument:

VIS_DQ
Quote the result using backslashes and double quotes. This is useful for producing strings that can be re-parsed by the shell.
VIS_CSTYLE
Escape tabs, newlines, and carriage returns using C-style backslash notation (`\t', `\n', `\r').
VIS_SP
Represent spaces as `^' followed by a space character. This is useful for making spaces visible.
VIS_NL
Represent newlines as `^' followed by a newline character. This is useful for making newlines visible.
VIS_MB
Encode non-ASCII characters using MIME Quoted-Printable encoding. This is described in RFC 2045. The form is ‘=XX’ where x represents a lower case hexadecimal digit.
VIS_MV
Encode non-ASCII characters using MIME Quoted-Printable encoding. This is described in RFC 2045. The form is ‘=XX’ where X represents an upper case hexadecimal digit.
VIS_MIMESTYLE
Use MIME Quoted-Printable encoding as described in RFC 2045, only don't break lines and don't handle CRLF. The form is ‘=XX’ where X represents an upper case hexadecimal digit.

There is one additional flag, VIS_NOSLASH, which inhibits the doubling of backslashes and the backslash before the default format (that is, control characters are represented by ‘^C’ and meta characters as ‘M-C’). With this flag set, the encoding is ambiguous and non-invertible.

MULTIBYTE CHARACTER SUPPORT

These functions support multibyte character input. The encoding conversion is influenced by the setting of the LC_CTYPE environment variable which defines the set of characters that can be copied without encoding.

If VIS_NOLOCALE is set, processing is done assuming the C locale and overriding any other environment settings.

When 8-bit data is present in the input, LC_CTYPE must be set to the correct locale or to the C locale. If the locales of the data and the conversion are mismatched, multibyte character recognition may fail and encoding will be performed byte-by-byte instead.

As noted above, dst must be four times the number of bytes processed from src. But note that each multibyte character can be up to MB_LEN_MAX bytes so in terms of multibyte characters, dst must be four times MB_LEN_MAX times the number of characters processed from src.

ENVIRONMENT

LC_CTYPE
Specify the locale of the input data. Set to C if the input data locale is unknown.

ERRORS

The functions nvis() and snvis() will return NULL and the functions strnvis(), strnvisx(), strsnvis(), and strsnvisx(), will return -1 when the dlen destination buffer size is not enough to perform the conversion while setting errno to:

[ENOSPC]
The destination buffer size is not large enough to perform the conversion.

HISTORY

The vis(), strvis(), and strvisx() functions first appeared in 4.4BSD. The svis(), strsvis(), and strsvisx() functions appeared in NetBSD 1.5. The buffer size limited versions of the functions (nvis(), strnvis(), strnvisx(), snvis(), strsnvis(), and strsnvisx()) appeared in NetBSD 6.0 and FreeBSD 9.2. Multibyte character support was added in NetBSD 7.0 and FreeBSD 9.2.
