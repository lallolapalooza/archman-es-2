stat(2) Manual de Llamadas al Sistema stat(2)

NOMBRE

stat, fstat, lstat, fstatat - obtener estado del archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/stat.h>
int stat(const char *restrict path,
         struct stat *restrict statbuf);
int fstat(int fd, struct stat *statbuf);
int lstat(const char *restrict path,
         struct stat *restrict statbuf);
#include <fcntl.h>           /* Definición de constantes AT_* */
#include <sys/stat.h>
int fstatat(int dirfd, const char *restrict path,
         struct stat *restrict statbuf, int flags);

DESCRIPCIÓN

Estas funciones devuelven información sobre un archivo, en el búfer apuntado por statbuf. No se requieren permisos sobre el archivo en sí, pero —en el caso de stat(), fstatat(), y lstat()— se requiere permiso de ejecución (búsqueda) en todos los directorios en path que conducen al archivo.

stat() y fstatat() recuperan información sobre el archivo apuntado por path; las diferencias para fstatat() se describen a continuación.

lstat() es idéntico a stat(), excepto que si path es un enlace simbólico, entonces devuelve información sobre el enlace en sí, no sobre el archivo al que se refiere el enlace.

fstat() es idéntico a stat(), excepto que el archivo sobre el cual se debe recuperar información se especifica mediante el descriptor de archivo fd.

La estructura stat

Todas estas llamadas al sistema devuelven una estructura stat (ver stat(3type)).

Nota: por razones de rendimiento y simplicidad, diferentes campos en la estructura stat pueden contener información de estado de diferentes momentos durante la ejecución de la llamada al sistema. Por ejemplo, si st_mode o st_uid son cambiados por otro proceso llamando a chmod(2) o chown(2), stat() podría devolver el st_mode antiguo junto con el nuevo st_uid, o el st_uid antiguo junto con el nuevo st_mode.

fstatat()

La llamada al sistema fstatat() es una interfaz más general para acceder a la información del archivo que aún puede proporcionar exactamente el comportamiento de cada una de stat(), lstat(), y fstat().

Si path es relativo, entonces se interpreta en relación con el directorio al que se refiere el descriptor de archivo dirfd (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como hacen stat() y lstat() para un nombre de ruta relativo).

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta en relación con el directorio de trabajo actual del proceso que llama (como stat() y lstat()).

Si path es absoluto, entonces dirfd se ignora.

flags puede ser 0, o incluir una o más de las siguientes banderas ORed:

AT_EMPTY_PATH (desde Linux 2.6.39)
Si path es una cadena vacía (o NULL, desde Linux 6.11) opera sobre el archivo al que se refiere dirfd (que podría haber sido obtenido usando la bandera open(2) O_PATH). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo un directorio, y el comportamiento de fstatat() es similar al de fstat(). Si dirfd es AT_FDCWD, la llamada opera sobre el directorio de trabajo actual. Esta bandera es específica de Linux; define _GNU_SOURCE para obtener su definición.
AT_NO_AUTOMOUNT (desde Linux 2.6.38)
No montar automáticamente el componente terminal ("basename") de path. Desde Linux 3.1 esta bandera se ignora. Desde Linux 4.11 esta bandera está implícita.
AT_SYMLINK_NOFOLLOW
Si path es un enlace simbólico, no lo desreferencies: en su lugar, devuelve información sobre el enlace en sí, como lstat(). (Por defecto, fstatat() desreferencia enlaces simbólicos, como stat().)

Ver openat(2) para una explicación de la necesidad de fstatat().

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EACCES
Se deniega el permiso de búsqueda en uno de los directorios en el prefijo de ruta de path. (Ver también path_resolution(7).)
EBADF
fd no es un descriptor de archivo abierto válido.
EBADF
(fstatat()) path es relativo pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
Dirección incorrecta.
EINVAL
(fstatat()) Bandera inválida especificada en flags.
ELOOP
Se encontraron demasiados enlaces simbólicos al recorrer la ruta.
ENAMETOOLONG
path es demasiado largo.
ENOENT
Un componente de path no existe o es un enlace simbólico colgante.
ENOENT
path es una cadena vacía y AT_EMPTY_PATH no fue especificado en flags.
ENOMEM
Sin memoria (es decir, memoria del kernel).
ENOTDIR
Un componente del prefijo de ruta de path no es un directorio.
ENOTDIR
(fstatat()) path es relativo y dirfd es un descriptor de archivo que se refiere a un archivo distinto de un directorio.
EOVERFLOW
path o fd se refieren a un archivo cuyo tamaño, número de inodo o número de bloques no pueden ser representados en los tipos respectivamente off_t, ino_t o blkcnt_t. Este error puede ocurrir cuando, por ejemplo, una aplicación compilada en una plataforma de 32 bits sin -D_FILE_OFFSET_BITS=64 llama a stat() en un archivo cuyo tamaño excede los (1<<31)-1 bytes.

NAME

stat, fstat, lstat, fstatat - obtener información de un archivo

LIBRARY

libc, - POSIX.1-2001, POSIX.1-2008

SYNOPSIS

#include <sys/stat.h>

int stat(const char *pathname, struct stat *statbuf);
int fstat(intfd, struct stat *statbuf);
int lstat(const char *pathname, struct stat *statbuf);
int fstatat(intdirfd, const char *pathname, struct stat *statbuf, intflags);

DESCRIPTION

Estas funciones devuelven información sobre el archivo especificado por pathname (para stat() y lstat()) o por el descriptor de archivo fd (para fstat()). La información se almacena en la estructura cuyos miembros se describen en la página de manual stat(5), en la ubicación a la que apunta statbuf.

Las diferencias entre stat(), fstat() y lstat() son:

stat()
Se opera sobre un archivo especificado por un nombre de ruta. Si el archivo es un enlace simbólico, stat() sigue el enlace y devuelve información sobre el archivo al que apunta el enlace.
fstat()
Se opera sobre un archivo especificado por un descriptor de archivo.
lstat()
Se opera sobre un archivo especificado por un nombre de ruta. Si el archivo es un enlace simbólico, lstat() devuelve información sobre el propio enlace simbólico, en lugar del archivo al que apunta.

fstatat() es similar a fstat() en que opera sobre un descriptor de archivo fd (el descriptor de archivo para un directorio, o el descriptor especial AT_FDCWD). Sin embargo, el nombre de ruta pathname se interpreta relativo a ese descriptor de archivo.

El argumento flags es un OR bit a bit de cero o más de las siguientes banderas:

AT_SYMLINK_NOFOLLOW
Si el archivo especificado por pathname es un enlace simbólico, devuelve información sobre el enlace simbólico en lugar de seguirlo. Esto hace que fstatat() con esta bandera sea similar a lstat().
AT_NO_AUTOMOUNT
(No implementado en Linux.) No seguir un punto de montaje automático si la ruta lo atraviesa.
AT_RECURSIVE
(No implementado en Linux.)

Si pathname es una ruta absoluta, entonces dirfd se ignora.

Si pathname es relativo, entonces se resuelve respecto al directorio especificado por dirfd. Si dirfd es AT_FDCWD, entonces pathname se resuelve respecto al directorio de trabajo actual, como lo harían stat() y lstat().

Si pathname es relativo y dirfd es un descriptor de archivo válido para un directorio, entonces pathname se resuelve respecto a ese directorio.

fstatat() con la bandera AT_SYMLINK_NOFOLLOW también tiene un comportamiento especial si pathname es relativo y dirfd especifica un descriptor de archivo para un directorio que ha sido abierto con la bandera O_NOFOLLOW. En este caso, si el nombre de ruta especifica un enlace simbólico, se devuelve información sobre el enlace simbólico.

El estándar POSIX.1-2001 y posteriores especifica que lstat() solo necesita devolver información válida en el campo st_size y el tipo de archivo en el campo st_mode de la estructura stat cuando se opera sobre un enlace simbólico. POSIX.1-2008 aprieta la especificación, requiriendo que lstat() devuelva información válida en todos los campos excepto en los bits de modo de st_mode.

El uso de los campos st_blocks y st_blksize puede ser menos portable. (Se introdujeron en BSD. La interpretación difiere entre sistemas, y posiblemente en un solo sistema cuando hay montajes NFS involucrados).

Diferencias entre la biblioteca C/kernel

Con el tiempo, los aumentos en el tamaño de la estructura stat han llevado a tres versiones sucesivas de stat(): sys_stat() (ranura __NR_oldstat), sys_newstat() (ranura __NR_stat), y sys_stat64() (ranura __NR_stat64) en plataformas de 32 bits como i386. Las dos primeras versiones ya estaban presentes en Linux 1.0 (aunque con nombres diferentes); la última se añadió en Linux 2.4. Observaciones similares se aplican a fstat() y lstat().

Las versiones internas del kernel de la estructura stat manejadas por las diferentes versiones son, respectivamente:

__old_kernel_stat
La estructura original, con campos bastante estrechos y sin relleno.
stat
Campo st_ino más grande y relleno añadido a varias partes de la estructura para permitir una futura expansión.
stat64
Campo st_ino aún más grande, campos st_uid y st_gid más grandes para acomodar la expansión de UIDs y GIDs a 32 bits en Linux-2.4, y varios otros campos ampliados y relleno adicional en la estructura. (Varios bytes de relleno finalmente se consumieron en Linux 2.6, con la llegada de IDs de dispositivo de 32 bits y componentes de nanosegundos para los campos de marca de tiempo.)

La función de envoltura stat() de glibc oculta estos detalles de las aplicaciones, invocando la versión más reciente de la llamada al sistema proporcionada por el kernel y reempaquetando la información devuelta si es necesario para binarios antiguos.

En sistemas modernos de 64 bits, la vida es más simple: hay una única llamada al sistema stat() y el kernel maneja una estructura stat que contiene campos de tamaño suficiente.

La llamada subyacente al sistema empleada por la función de envoltura fstatat() de glibc se llama en realidad fstatat64() o, en algunas arquitecturas, newfstatat().

EJEMPLOS

El siguiente programa llama a lstat() y muestra campos seleccionados en la estructura stat devuelta.

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/sysmacros.h>
#include <time.h>
int
main(int argc, char *argv[])
{
    struct stat sb;
    if (argc != 2) {
        fprintf(stderr, "Uso: %s <ruta>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (lstat(argv[1], &sb) == -1) {
        perror("lstat");
        exit(EXIT_FAILURE);
    }
    printf("ID del dispositivo contenedor:  [%x,%x]\n",
           major(sb.st_dev),
           minor(sb.st_dev));
    printf("Tipo de archivo:                ");
    switch (sb.st_mode & S_IFMT) {
    case S_IFBLK:  printf("dispositivo de bloques\n");            break;
    case S_IFCHR:  printf("dispositivo de caracteres\n");        break;
    case S_IFDIR:  printf("directorio\n");               break;
    case S_IFIFO:  printf("FIFO/pipe\n");               break;
    case S_IFLNK:  printf("enlace simbólico\n");                 break;
    case S_IFREG:  printf("archivo regular\n");            break;
    case S_IFSOCK: printf("socket\n");                  break;
    default:       printf("¿desconocido?\n");                break;
    }
    printf("Número de I-nodo:            %ju\n", (uintmax_t) sb.st_ino);
    printf("Modo:                     %jo (octal)\n",
           (uintmax_t) sb.st_mode);
    printf("Número de enlaces:               %ju\n", (uintmax_t) sb.st_nlink);
    printf("Propiedad:                UID=%ju   GID=%ju\n",
           (uintmax_t) sb.st_uid, (uintmax_t) sb.st_gid);
    printf("Tamaño de E/S preferido: %jd bytes\n",
           (intmax_t) sb.st_blksize);
    printf("Tamaño del archivo:                %jd bytes\n",
           (intmax_t) sb.st_size);
    printf("Bloques asignados:         %jd\n",
           (intmax_t) sb.st_blocks);
    printf("Último cambio de estado:       %s", ctime(&sb.st_ctime));
    printf("Último acceso al archivo:         %s", ctime(&sb.st_atime));
    printf("Última modificación del archivo:   %s", ctime(&sb.st_mtime));
    exit(EXIT_SUCCESS);
}
