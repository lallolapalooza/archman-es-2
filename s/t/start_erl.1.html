NOMBRE

start_erl - Inicia Erlang para sistemas embebidos en sistemas Windows

DESCRIPCIÓN

El programa start_erl es específico para Windows NT/2000/XP (y versiones posteriores de Windows). Aunque existen programas con el mismo nombre en otras plataformas, su funcionalidad es diferente.

Este programa se distribuye tanto en forma compilada (en <Erlang root>\erts-<version>\bin) como en forma de código fuente (en <Erlang root>\erts-<version>\src). El propósito del código fuente es facilitar la personalización del programa para necesidades locales, como la detección de reinicios cíclicos. También hay un archivo "make", escrito para el programa nmake distribuido con Microsoft Visual C++. Sin embargo, este programa puede compilarse con cualquier compilador C de Win32 (posiblemente con modificaciones menores).

Este programa ayuda en el manejo de versiones en sistemas Windows. El programa es llamado por el programa erlsrv, lee el archivo de datos de versión start_erl.data e inicia Erlang. Algunas opciones para start_erl son añadidas y eliminadas por el gestor de versiones durante la actualización con reinicio del emulador (más específicamente la opción -data).

start_erl [<opciones_erl>] ++ [<opciones_start_erl>]

El programa start_erl en su forma original reconoce las siguientes opciones:

++

Obligatorio. Delimita las opciones de start_erl de las opciones normales de Erlang. Todo en la línea de comandos antes de ++ se interpreta como opciones que se enviarán al programa erl. Todo después de ++ se interpreta como opciones para el propio start_erl.

-reldir <directorio raíz de la versión>

Obligatorio si la variable de entorno RELDIR no está especificada y no se especifica la opción -rootdir. Indica a start_erl dónde se encuentra la raíz del árbol de la versión en el sistema de archivos (típicamente <Erlang root>\releases). Se espera que el archivo start_erl.data se encuentre en este directorio (a menos que se especifique lo contrario). Si solo se especifica la opción -rootdir, el directorio se asume como <Erlang root>\releases.

-rootdir <directorio raíz de Erlang>

Obligatorio si -reldir no está especificado y no existe RELDIR en el entorno. Esto especifica el directorio raíz de la instalación de Erlang (bajo el cual se encuentran los directorios lib, releases y erts-<Version>). Si solo se especifica -reldir (o la variable de entorno RELDIR), se asume que el directorio raíz de Erlang es el directorio exactamente un nivel por encima del directorio de la versión.

-data <nombre del archivo de datos>

Opcional. Especifica un archivo de datos diferente a start_erl.data en el <directorio raíz de la versión>. Se especifica en relación con el <directorio raíz de la versión> o de forma absoluta (incluyendo la letra de la unidad, etc.). Esta opción es utilizada por el gestor de versiones durante la actualización y no debe usarse durante la operación normal. Normalmente, el archivo de datos de la versión no debe tener un nombre diferente.

-bootflags <nombre del archivo de flags de arranque>

Opcional. Especifica un nombre de archivo relativo al directorio de la versión (es decir, el subdirectorio de <directorio raíz de la versión> donde se encuentran el archivo .boot y otros). El contenido de este archivo se añade a la línea de comandos al iniciar Erlang. Esto facilita el inicio del emulador con diferentes opciones para diferentes versiones.

Notas

•Dado que el código fuente se distribuye, puede modificarse fácilmente para aceptar otras opciones. El programa aún debe aceptar la opción -data con la semántica descrita anteriormente para que el gestor de versiones funcione correctamente.
•El emulador de Erlang se encuentra examinando las claves del registro para la versión del emulador especificada en el archivo de datos de la versión. El nuevo emulador debe estar correctamente instalado antes de la actualización para que esto funcione.
•Aunque el programa se encuentra junto con archivos específicos de la versión del emulador, no se espera que sea específico de la versión del emulador. El gestor de versiones no cambia la opción -machine a erlsrv durante el reinicio del emulador. Ubique el programa start_erl (posiblemente personalizado) de manera que no sea sobrescrito durante la actualización.
•Las opciones predeterminadas del programa erlsrv no son suficientes para el manejo de versiones. La máquina iniciada por erlsrv debe especificarse como el programa start_erl y los argumentos deben contener ++ seguido de las opciones deseadas.
