DESCRIPCIÓN

La función vis() copia en dst una cadena que representa el carácter c. Si c no necesita codificación, se copia sin alterar. La cadena se termina con nulo y se devuelve un puntero al final de la cadena. La longitud máxima de cualquier codificación es de cuatro bytes (sin incluir el NUL final); por lo tanto, al codificar un conjunto de caracteres en un búfer, el tamaño del búfer debe ser cuatro veces el número de bytes codificados, más uno para el NUL final. El parámetro flag se utiliza para alterar el rango predeterminado de caracteres considerados para la codificación y para alterar la representación visual. El carácter adicional, nextc, solo se utiliza al seleccionar el formato de codificación VIS_CSTYLE (explicado a continuación).

Las funciones strvis(), stravis(), strnvis(), strvisx(), y strnvisx() copian en dst una representación visual de la cadena src. Las funciones strvis() y strnvis() codifican caracteres de src hasta el primer NUL. Las funciones strvisx() y strnvisx() codifican exactamente len caracteres de src (esto es útil para codificar un bloque de datos que puede contener NULs). Ambas formas terminan en NUL a dst. El tamaño de dst debe ser cuatro veces el número de bytes codificados desde src (más uno para el NUL). Ambas formas devuelven el número de caracteres en dst (sin incluir el NUL final). Las funciones svis(), snvis(), strsvis(), strsnvis(), strsvisx(), strsnvisx(), y strsenvisx() corresponden a vis(), nvis(), strvis(), strnvis(), strvisx(), strnvisx(), y strenvisx() pero tienen un argumento adicional extra, apuntando a una lista de caracteres terminada en NUL. Estos caracteres se copiarán codificados o escapados con barra invertida en dst. Estas funciones son útiles, por ejemplo, para eliminar el significado especial de ciertos caracteres para los shells.

La codificación es una representación única e invertible compuesta enteramente por caracteres gráficos; puede ser decodificada de nuevo a su forma original utilizando las funciones unvis(3bsd), strunvis(3bsd) o strnunvis(3bsd).

Hay dos parámetros que se pueden controlar: el rango de caracteres que se codifican (se aplica solo a vis(), nvis(), strvis(), strnvis(), strvisx(), y strnvisx()), y el tipo de representación utilizada. Por defecto, todos los caracteres no gráficos, excepto el espacio, la tabulación y el salto de línea se codifican (ver isgraph(3)). Las siguientes banderas alteran esto:

VIS_DQ
Codifica también las comillas dobles.
VIS_GLOB
Codifica también los caracteres mágicos ("*" , "?" , "[" , y "#") reconocidos por glob(3).
VIS_SHELL
Codifica también los metacaracteres utilizados por los shells (además de los caracteres de globbing): ("'" , "`" , "\"" , ";" , "&" , "<" , ">" , "(" , ")" , "|" , "]" , "\" , "$" , "!" , "^" , y "~").
VIS_SP
Codifica también el espacio.
VIS_TAB
Codifica también la tabulación.
VIS_NL
Codifica también el salto de línea.
VIS_WHITE
Sinónimo de VIS_SP | VIS_TAB | VIS_NL.
VIS_META
Sinónimo de VIS_WHITE | VIS_GLOB | VIS_SHELL.
VIS_SAFE
Codifica solo caracteres "inseguros". Inseguro significa caracteres de control que pueden causar que terminales comunes realicen funciones inesperadas. Actualmente, esta forma permite codificar sin codificar el espacio, la tabulación, el salto de línea, el retroceso, el timbre y el retorno de carro, además de todos los caracteres gráficos.

(Las banderas anteriores no tienen efecto para svis(), snvis(), strsvis(), strsnvis(), strsvisx(), y strsnvisx(). Al usar estas funciones, coloque todos los caracteres gráficos a codificar en un arreglo apuntado por extra. En general, el carácter de barra invertida debe incluirse en este arreglo, consulte la advertencia sobre el uso de la bandera VIS_NOSLASH a continuación).

Hay seis formas de codificación. Todas las formas usan el carácter de barra invertida "\" para introducir una secuencia especial; se usan dos barras invertidas para representar una barra invertida real, excepto VIS_HTTPSTYLE que usa "%" , o VIS_MIMESTYLE que usa "=" . Estos son los formatos visuales:

(predeterminado)
Usa una "M" para representar caracteres meta (caracteres con el octavo bit establecido), y usa un acento circunflejo "^" para representar caracteres de control (ver iscntrl(3)). Se utilizan los siguientes formatos:
\^C
Representa el carácter de control "C". Abarca los caracteres "\000" hasta "\037", y "\177" (como "\^?").
\M-C
Representa el carácter "C" con el octavo bit establecido. Abarca los caracteres "\241" hasta "\376".
\M^C
Representa el carácter de control "C" con el octavo bit establecido. Abarca los caracteres "\200" hasta "\237", y "\377" (como "\M^?").
\040
Representa el espacio ASCII.
\240
Representa el meta-espacio.
VIS_CSTYLE
Utiliza secuencias de barra invertida estilo C para representar caracteres no imprimibles estándar. Se utilizan las siguientes secuencias para representar los caracteres indicados: 
\a — BEL (007)
\b — BS (010)
\f — NP (014)
\n — NL (012)
\r — CR (015)
\s — SP (040)
\t — HT (011)
\v — VT (013)
\0 — NUL (000)

Al usar este formato, se examina el parámetro nextc para determinar si un carácter NUL se puede codificar como "\0" en lugar de "\000". Si nextc es un dígito octal, se utiliza la última representación para evitar ambigüedades.

Los caracteres no imprimibles sin secuencias de barra invertida estilo C utilizan la representación predeterminada.

VIS_OCTAL
Utiliza una secuencia octal de tres dígitos. El formato es "\ddd" donde d representa un dígito octal.
VIS_CSTYLE | VIS_OCTAL
Igual que VIS_CSTYLE excepto que los caracteres no imprimibles sin secuencias de barra invertida estilo C utilizan una secuencia octal de tres dígitos.

strvisx(3bsd) — Arch manual pages

NAME

strvisx, strnvisx, snvisx, nvisx ― produce a string with non-graphic characters replaced by printable characters

LIBRARY

libbsd

SYNOPSIS

#include <vis.h>

int
strvisx(dst, src, dlen, visex);

int
strnvisx(dst, src, dlen, visex);

int
snvisx(dst, dlen, src, visex);

int
nvisx(dst, src, visex);

DESCRIPTION

The vis() family of functions converts non-graphic characters in the input string src into sequences of printable characters in the output string dst. The conversion is controlled by the bitwise OR of flags in the integer visex.

The strvisx() and strnvisx() functions write the converted output to the buffer pointed to by dst. The buffer must be large enough to hold the result. The maximum length of the result is 4 times the length of the source string, plus one byte for a terminating null character. The strnvisx() function will write at most dlen bytes into the buffer dst. The return value is the number of characters written into dst, not including the terminating null character. If the destination buffer is too small, an error will be returned and errno will be set to ENOSPC.

The snvisx() function behaves like strnvisx(), but the number of characters to convert from src is determined by the first null byte encountered in src. The return value is the number of characters written into dst, not including the terminating null character.

The nvisx() function converts the null-terminated string src into the buffer dst. The size of the buffer dst must be at least 4 times the size of the src string plus one byte for the terminating null character. The return value is a pointer to the terminating null character in dst.

The following flags are available:

VIS_DQ
If set, strings are double-quoted, and backslashes are used to escape double quotes and backslashes. Tabs are escaped with a preceding backslash.
VIS_CSTYLE
If set, C-style backslash escapes are used for the characters that have them. The character representations are:
\a
Alert (bell)
\b
Backspace
\e
Escape
\f
Form feed
\n
Newline
\r
Carriage return
\t
Tab
\v
Vertical tab
Otherwise, non-graphic characters are represented by a caret followed by the character, e.g., ^A for SOH.
VIS_SP
If set, spaces are escaped with a preceding backslash.
VIS_TAB
If set, tabs are escaped with a preceding backslash.
VIS_NL
If set, newlines are escaped with a preceding backslash.
VIS_LDISP
If set, lowercase alphabetic characters are escaped with a preceding backslash.
VIS_UPPER
If set, uppercase alphabetic characters are escaped with a preceding backslash.
VIS_ALPHA
If set, all alphabetic characters are escaped with a preceding backslash.
VIS_DIGIT
If set, all digits are escaped with a preceding backslash.
VIS_SAFE
If set, all characters that are not alphanumeric are escaped.
VIS_WHITE
If set, all whitespace characters (space, tab, newline, carriage return, form feed, vertical tab) are escaped.
VIS_OCTAL
If set, octal characters are represented by a backslash followed by three octal digits.
VIS_HEXASCII
If set, all characters are escaped using the form ‘=XX’ where X represents a hexadecimal digit. This encoding is similar to the MIME Quoted-Printable encoding, but uses uppercase hexadecimal digits.
VIS_MB_ASCII
If set, non-ASCII characters are represented by a backslash followed by three octal digits. This is essentially the same as VIS_OCTAL, but it is intended for use with multibyte character sets.
VIS_NOESCAPE
If set, backslashes are not used for escaping. Control characters are represented by a caret followed by the character (e.g., ^C), and meta characters are represented by M- followed by the character (e.g., M-C). This flag makes the encoding ambiguous and non-invertible.
VIS_MIMESTYLE
Use MIME Quoted-Printable encoding as described in RFC 2045, but do not break lines and do not handle CRLF. The form is ‘=XX’ where X represents an upper case hexadecimal digit.

There is one additional flag, VIS_NOSLASH, which inhibits the doubling of backslashes and the backslash before the default format (that is, control characters are represented by ‘^C’ and meta characters as ‘M-C’). With this flag set, the encoding is ambiguous and non-invertible.

MULTIBYTE CHARACTER SUPPORT

These functions support multibyte character input. The encoding conversion is influenced by the setting of the LC_CTYPE environment variable which defines the set of characters that can be copied without encoding.

If VIS_NOLOCALE is set, processing is done assuming the C locale and overriding any other environment settings.

When 8-bit data is present in the input, LC_CTYPE must be set to the correct locale or to the C locale. If the locales of the data and the conversion are mismatched, multibyte character recognition may fail and encoding will be performed byte-by-byte instead.

As noted above, dst must be four times the number of bytes processed from src. But note that each multibyte character can be up to MB_LEN_MAX bytes so in terms of multibyte characters, dst must be four times MB_LEN_MAX times the number of characters processed from src.

ENVIRONMENT

LC_CTYPE
Specify the locale of the input data. Set to C if the input data locale is unknown.

ERRORS

The functions nvis() and snvis() will return NULL and the functions strnvis(), strnvisx(), strsnvis(), and strsnvisx(), will return -1 when the dlen destination buffer size is not enough to perform the conversion while setting errno to:

[ENOSPC]
The destination buffer size is not large enough to perform the conversion.

HISTORY

The vis(), strvis(), and strvisx() functions first appeared in 4.4BSD. The svis(), strsvis(), and strsvisx() functions appeared in NetBSD 1.5. The buffer size limited versions of the functions (nvis(), strnvis(), strnvisx(), snvis(), strsnvis(), and strsnvisx()) appeared in NetBSD 6.0 and FreeBSD 9.2. Multibyte character support was added in NetBSD 7.0 and FreeBSD 9.2.
