Descripción Detallada

template<typename_CharT,_typename_Traits>

El propósito de la clase basic_streambuf es actuar como una interfaz común para el control de entrada y salida de datos. La mayoría de las operaciones de E/S realizadas por los objetos de flujo (como basic_istream y basic_ostream) se delegan a un objeto basic_streambuf asociado. Las clases de flujo proporcionan una interfaz de nivel superior más conveniente, mientras que el basic_streambuf maneja los detalles de bajo nivel de la obtención y colocación de caracteres.

El nombre de la clase proviene de "buffer de stream".

Aunque la clase basic_streambuf proporciona una interfaz general, la mayoría de las aplicaciones no la utilizan directamente. En su lugar, utilizan clases de flujo (istream, ostream, fstream, etc.) que tienen objetos basic_streambuf incorporados o asociados. Las clases derivadas (como basic_filebuf y basic_stringbuf) se utilizan para implementar el comportamiento específico de las diferentes fuentes y destinos de E/S.

La clase basic_streambuf es una clase base abstracta. Para usarla, debe crear una clase derivada que implemente los métodos virtuales que manejan la obtención y colocación de datos (como underflow, overflow, seekoff y seekpos).

Los objetos basic_streambuf mantienen punteros para gestionar las áreas de lectura y escritura de datos. Estas áreas se conocen como "get area" y "put area", respectivamente.

  • El "get area" se utiliza para los datos de entrada. Está definido por tres punteros:
    • eback(): Puntero al principio del área de lectura.
    • gptr(): Puntero al carácter de lectura actual.
    • egptr(): Puntero al final del área de lectura.
  • El "put area" se utiliza para los datos de salida. Está definido por tres punteros:
    • pbase(): Puntero al principio del área de escritura.
    • pptr(): Puntero al carácter de escritura actual.
    • epptr(): Puntero al final del área de escritura.

Las funciones miembro protegidas (como setg, setp, gbump y pbump) se utilizan para manipular estos punteros y gestionar las áreas de lectura y escritura.

Las funciones miembro públicas (como sgetc, sbumpc, sputc, sputbackc, sungetc, xsgetn y xsputn) proporcionan una interfaz para interactuar con el buffer desde fuera de la clase derivada. Estas funciones llaman a las funciones virtuales protegidas correspondientes (como underflow, overflow, pbackfail, seekoff y seekpos) cuando es necesario.

La función pubimbue y el método virtual imbue se utilizan para gestionar la configuración regional del buffer, que puede afectar a la traducción de caracteres.

La función pubsync y el método virtual sync se utilizan para sincronizar el buffer con la secuencia subyacente. Esto asegura que todos los datos en el buffer se escriban o lean según sea necesario.

Las funciones pubseekoff y pubseekpos, junto con los métodos virtuales seekoff y seekpos, se utilizan para cambiar la posición actual dentro del stream.

El método virtual showmanyc se puede implementar para indicar cuántos caracteres se pueden obtener del buffer sin bloquear. Esto puede ser útil para optimizar operaciones de lectura.

Los métodos uflow y underflow se utilizan para obtener el siguiente carácter de la secuencia de entrada. La diferencia es que uflow consume el carácter del buffer si está disponible, mientras que underflow solo lo pone a disposición sin consumirlo (aunque esto puede implicar la obtención de datos del dispositivo de entrada).

El método virtual pbackfail se utiliza para intentar "devolver" un carácter al stream de entrada. Esto es necesario cuando una operación de lectura retrocede más allá del inicio del buffer actual.

El método virtual overflow se utiliza para escribir datos en el stream de salida. Se llama cuando el buffer de escritura está lleno y se necesita espacio para más datos.

La función pubsetbuf y el método virtual setbuf se utilizan para establecer o cambiar el buffer asociado con el objeto basic_streambuf.

El constructor y destructor protegidos gestionan la vida útil del objeto basic_streambuf.

Los métodos __safe_gbump y __safe_pbump son implementaciones internas para mover los punteros de lectura y escritura, asegurando que se mantengan dentro de los límites del buffer.

Se proporcionan constructores de copia y operadores de asignación (que generalmente son eliminados o no funcionales para las clases de buffer de stream) para prevenir la copia de objetos de buffer, ya que la copia de buffers de E/S normalmente no tiene sentido.

Los amigos incluyen varias clases y funciones relacionadas con los streams y los iteradores de streams, lo que les permite acceder a los miembros protegidos del buffer cuando es necesario.

El atributo _M_buf_locale almacena la configuración regional utilizada por el buffer.

Los atributos _M_in_beg, _M_in_cur, _M_in_end, _M_out_beg, _M_out_cur y _M_out_end son los punteros que definen las áreas de lectura y escritura, tal como se describe anteriormente.

Parámetros de plantilla

_CharT Tipo de flujo de caracteres.
_Traits Rasgos para el tipo de carácter, por defecto es char_traits<_CharT>.

Esta es una clase base. Los buffers de flujo derivados controlan cada uno un par de secuencias de caracteres: una para entrada y otra para salida.

La sección [27.5.1] del estándar describe los requisitos y el comportamiento de las clases de buffer de flujo. Esa sección (tres párrafos) se reproduce aquí, por simplicidad y precisión.

1.
Los buffers de flujo pueden imponer varias restricciones en las secuencias que controlan. Algunas restricciones son:
•
La secuencia de entrada controlada puede no ser legible.
•
La secuencia de salida controlada puede no ser escribible.
•
Las secuencias controladas pueden asociarse con el contenido de otras representaciones de secuencias de caracteres, como archivos externos.
•
Las secuencias controladas pueden admitir operaciones directamente hacia o desde secuencias asociadas.
•
Las secuencias controladas pueden imponer limitaciones sobre cómo el programa puede leer caracteres de una secuencia, escribir caracteres en una secuencia, devolver caracteres a una secuencia de entrada o alterar la posición del flujo.
2.
Cada secuencia se caracteriza por tres punteros que, si no son nulos, apuntan todos al mismo objeto de array charT. El objeto de array representa, en cualquier momento, una (sub)secuencia de caracteres de la secuencia. Las operaciones realizadas en una secuencia alteran los valores almacenados en estos punteros, realizan lecturas y escrituras directamente hacia o desde secuencias asociadas, y alteran la posición del flujo y el estado de conversión según sea necesario para mantener esta relación de subsecuencia. Los tres punteros son:
•
el puntero de inicio, o la dirección del elemento más bajo en el array (llamado xbeg aquí);
•
el puntero siguiente, o la dirección del siguiente elemento que es un candidato actual para leer o escribir (llamado xnext aquí);
•
el puntero de fin, o la dirección del primer elemento más allá del final del array (llamado xend aquí).
3.
Las siguientes restricciones semánticas siempre se aplicarán para cualquier conjunto de tres punteros para una secuencia, utilizando los nombres de puntero dados inmediatamente arriba:
•
Si xnext no es un puntero nulo, entonces xbeg y xend también serán punteros no nulos dentro del mismo objeto de array charT, como se describe anteriormente; de lo contrario, xbeg y xend también serán nulos.
•
Si xnext no es un puntero nulo y xnext < xend para una secuencia de salida, entonces hay disponible una posición de escritura. En este caso, *xnext será asignable como el siguiente elemento a escribir (para colocar, o almacenar un valor de carácter, en la secuencia).
•
Si xnext no es un puntero nulo y xbeg < xnext para una secuencia de entrada, entonces hay disponible una posición de devolución. En este caso, xnext[-1] tendrá un valor definido y es el siguiente elemento (precedente) donde almacenar un carácter que se devuelve a la secuencia de entrada.
•
Si xnext no es un puntero nulo y xnext< xend para una secuencia de entrada, entonces hay disponible una posición de lectura. En este caso, *xnext tendrá un valor definido y es el siguiente elemento a leer (para obtener, o obtener un valor de carácter, de la secuencia).

NAME

std::basic_streambuf — buffer classes

SYNOPSIS

#include <streambuf>

template<typename _CharT, typename _Traits>
class std::basic_streambuf< _CharT, _Traits >

Detailed Description

The C++ standard library provides support for input and output streams through a set of classes defined in the <iostream> and <streambuf> headers. The basic_streambuf class is the base class for all stream buffer classes.

A stream buffer object manages a sequence of characters. This sequence is often referred to as a "buffer". The stream buffer provides an interface to the underlying character device (e.g., a file, a console, or an in-memory character array).

The basic_streambuf class template has two template parameters:

_CharT
The character type. This can be char, wchar_t, or any other character type.
_Traits
The character traits class. This class provides information about the character type, such as how to compare characters or check for the end-of-file marker. The default is std::char_traits<_CharT>.

The basic_streambuf class provides a generic interface for managing character sequences. It defines several virtual functions that are intended to be overridden by derived classes to provide specific implementations for different types of character devices. Some of the key virtual functions include:

  • xsgetn(): Extracts characters from the input sequence.
  • xsputn(): Inserts characters into the output sequence.
  • uflow(): Extracts and returns the next character from the input sequence.
  • overflow(): Inserts the next character into the output sequence.
  • pbackget(): Pushes a character back into the input sequence.
  • sync(): Synchronizes the buffer with the underlying character device.

The standard library provides several derived classes for basic_streambuf, including:

  • std::basic_filebuf: For file I/O.
  • std::basic_stringstream: For in-memory string I/O.
  • std::basic_stringbuf: For simpler in-memory string I/O.
