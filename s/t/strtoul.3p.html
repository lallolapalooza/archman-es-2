STRTOUL(3P) Manual de Programador POSIX STRTOUL(3P)

PRÓLOGO

Esta página del manual forma parte del Manual de Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

strtoul, strtoull — convertir una cadena a un unsigned long

SINOPSIS

#include <stdlib.h>
unsigned long strtoul(const char *restrict str,
    char **restrict endptr, int base);
unsigned long long strtoull(const char *restrict str,
    char **restrict endptr, int base);

DESCRIPCIÓN

La funcionalidad descrita en esta página de referencia está alineada con el estándar ISO C. Cualquier conflicto entre los requisitos descritos aquí y el estándar ISO C es no intencional. Este volumen de POSIX.1‐2017 remite al estándar ISO C.

Estas funciones convertirán la porción inicial de la cadena apuntada por str a una representación de tipo unsigned long y unsigned long long, respectivamente. Primero, descomponen la cadena de entrada en tres partes:

1.
Una secuencia inicial, posiblemente vacía, de caracteres de espacio en blanco (según lo especificado por isspace())
2.
Una secuencia sujeto interpretada como un entero representado en una radix determinada por el valor de base
3.
Una cadena final de uno o más caracteres no reconocidos, incluyendo el carácter NUL terminador de la cadena de entrada

Luego, intentarán convertir la secuencia sujeto a un entero sin signo y devolverán el resultado.

Si el valor de base es 0, la forma esperada de la secuencia sujeto es la de una constante decimal, una constante octal o una constante hexadecimal, cualquiera de ellas puede ir precedida por un signo '+' o '-'. Una constante decimal comienza con un dígito distinto de cero y consiste en una secuencia de dígitos decimales. Una constante octal consiste en el prefijo '0' seguido opcionalmente por una secuencia de los dígitos '0' a '7' únicamente. Una constante hexadecimal consiste en el prefijo 0x o 0X seguido por una secuencia de los dígitos decimales y letras 'a' (o 'A') a 'f' (o 'F') con valores de 10 a 15 respectivamente.

Si el valor de base está entre 2 y 36, la forma esperada de la secuencia sujeto es una secuencia de letras y dígitos que representan un entero con la radix especificada por base, opcionalmente precedida por un signo '+' o '-'. Las letras de 'a' (o 'A') a 'z' (o 'Z') inclusive se les atribuyen los valores de 10 a 35; solo se permiten letras cuyos valores atribuidos sean menores que el de base. Si el valor de base es 16, los caracteres 0x o 0X pueden opcionalmente preceder a la secuencia de letras y dígitos, siguiendo el signo si está presente.

La secuencia sujeto se define como la sub-secuencia inicial más larga de la cadena de entrada, comenzando con el primer carácter que no sea espacio en blanco que tenga la forma esperada. La secuencia sujeto no contendrá caracteres si la cadena de entrada está vacía o consiste enteramente en caracteres de espacio en blanco, o si el primer carácter que no sea espacio en blanco es distinto de un signo o de una letra o dígito permitidos.

Si la secuencia sujeto tiene la forma esperada y el valor de base es 0, la secuencia de caracteres que comienza con el primer dígito se interpretará como una constante entera. Si la secuencia sujeto tiene la forma esperada y el valor de base está entre 2 y 36, se usará como base para la conversión, atribuyendo a cada letra su valor como se indica arriba. Si la secuencia sujeto comienza con un <guion menos>, el valor resultante de la conversión se negará. Se almacenará un puntero a la cadena final en el objeto apuntado por endptr, siempre que endptr no sea un puntero nulo.

En configuraciones distintas de la localización C o POSIX, se pueden aceptar formas adicionales de secuencia sujeto específicas de la localización.

Si la secuencia sujeto está vacía o no tiene la forma esperada, no se realizará ninguna conversión; el valor de str se almacenará en el objeto apuntado por endptr, siempre que endptr no sea un puntero nulo.

Estas funciones no cambiarán la configuración de errno si tienen éxito.

Dado que se devuelven 0, {ULONG_MAX} y {ULLONG_MAX} en caso de error y también son retornos válidos en caso de éxito, una aplicación que desee verificar situaciones de error debe establecer errno a 0, luego llamar a strtoul() o strtoull(), luego verificar errno.

VALOR DE RETORNO

Al completarse con éxito, estas funciones devolverán el valor convertido, si lo hubiera. Si no se pudo realizar ninguna conversión, se devolverá 0 y errno puede establecerse en [EINVAL].

Si el valor de base no es compatible, se devolverá 0 y errno se establecerá en [EINVAL].

Si el valor correcto está fuera del rango de valores representables, se devolverá {ULONG_MAX} o {ULLONG_MAX} y se establecerá errno en [ERANGE].

ERRORES

Estas funciones fallarán si:

EINVAL
El valor de base no es compatible.
ERANGE
El valor a devolver no es representable.

Estas funciones pueden fallar si:

EINVAL
No se pudo realizar ninguna conversión.

USO DE APLICACIONES

Dado que el valor de *endptr no está especificado si el valor de base no es compatible, las aplicaciones deben asegurarse de que base tenga un valor compatible (0 o entre 2 y 36) antes de la llamada, o verificar si hay un error [EINVAL] antes de examinar *endptr.
