Descripción Detallada

template<typename _CharT, typename _Traits>

Este es el corazón de todas las clases de flujo C++ STL. Proporciona una interfaz para que las clases de flujo accedan a los búferes de entrada y salida.

Debe crear una subclase de basic_streambuf si desea implementar un nuevo tipo de dispositivo de flujo o si desea manipular la forma en que los flujos existentes acceden a sus búferes. La clase más comúnmente derivada es std::filebuf (para archivos), std::stringstream (para cadenas) y std::sync_filebuf (para sincronizar un búfer con un archivo C FILE *).

Aquí, los 'traits' se refieren a un objeto traits de la clase definida por el usuario que se puede utilizar para acceder a los caracteres individuales en el búfer. Por defecto, este es el `char_traits` de carácter.

Aquí, los 'CharT' se refieren al tipo de carácter que está utilizando (por ejemplo, `char`, `wchar_t`, etc.).

Parámetros de plantilla

_CharT Tipo de flujo de caracteres.
_Traits Rasgos para el tipo de carácter, por defecto es char_traits<_CharT>.

Esta es una clase base. Los búferes de flujo derivados controlan cada uno un par de secuencias de caracteres: uno para entrada y otro para salida.

La sección [27.5.1] del estándar describe los requisitos y el comportamiento de las clases de búfer de flujo. Esa sección (tres párrafos) se reproduce aquí, por simplicidad y precisión.

1.
Los búferes de flujo pueden imponer varias restricciones en las secuencias que controlan. Algunas restricciones son:
•
La secuencia de entrada controlada puede no ser legible.
•
La secuencia de salida controlada puede no ser escribible.
•
Las secuencias controladas pueden estar asociadas con el contenido de otras representaciones de secuencias de caracteres, como archivos externos.
•
Las secuencias controladas pueden imponer limitaciones sobre cómo el programa puede leer caracteres de una secuencia, escribir caracteres en una secuencia, devolver caracteres a una secuencia de entrada o alterar la posición del flujo.
2.
Cada secuencia se caracteriza por tres punteros que, si no son nulos, apuntan todos al mismo objeto de matriz charT. El objeto de matriz representa, en cualquier momento, una (sub)secuencia de caracteres de la secuencia. Las operaciones realizadas en una secuencia alteran los valores almacenados en estos punteros, realizan lecturas y escrituras directa o indirectamente desde secuencias asociadas, y alteran la posición del flujo y el estado de conversión según sea necesario para mantener esta relación de subsecuencia. Los tres punteros son:
•
el puntero de inicio, o dirección del elemento más bajo en la matriz (llamado xbeg aquí);
•
el puntero siguiente, o dirección del siguiente elemento que es un candidato actual para lectura o escritura (llamado xnext aquí);
•
el puntero final, o dirección del primer elemento más allá del final de la matriz (llamado xend aquí).
3.
Las siguientes restricciones semánticas siempre se aplicarán para cualquier conjunto de tres punteros para una secuencia, utilizando los nombres de puntero dados inmediatamente arriba:
•
Si xnext no es un puntero nulo, entonces xbeg y xend también serán punteros no nulos en la misma matriz charT, como se describe anteriormente; de lo contrario, xbeg y xend también serán nulos.
•
Si xnext no es un puntero nulo y xnext < xend para una secuencia de salida, entonces hay una posición de escritura disponible. En este caso, *xnext será asignable como el siguiente elemento a escribir (para poner, o almacenar un valor de carácter, en la secuencia).
•
Si xnext no es un puntero nulo y xbeg < xnext para una secuencia de entrada, entonces hay una posición de devolución de carácter disponible. En este caso, xnext[-1] tendrá un valor definido y es el elemento siguiente (anterior) para almacenar un carácter que se devuelve a la secuencia de entrada.
•
Si xnext no es un puntero nulo y xnext < xend para una secuencia de entrada, entonces hay una posición de lectura disponible. En este caso, *xnext tendrá un valor definido y es el siguiente elemento a leer (para obtener, o obtener un valor de carácter, de la secuencia).

template<typename _CharT, typename _Traits> virtual int_type std::basic_streambuf< _CharT, _Traits >::overflow (int_type __c = traits_type::eof()) [inline], [protected], [virtual]

Consume datos del búfer; escribe en la secuencia controlada.

Parámetros

__c Un carácter adicional para consumir.

Devoluciones

eof() para indicar fallo, algún otro valor (generalmente __c, o not_eof())

Informalmente, esta función se llama cuando el búfer de salida está lleno (o no existe, ya que el almacenamiento en búfer no necesita realizarse realmente). Si existe un búfer, se consume, con algún efecto en la secuencia controlada. (Típicamente, el búfer se escribe en la secuencia tal cual). En cualquier caso, el carácter c también se escribe, si __c no es eof().

Para una definición formal de esta función, consulte un buen texto como Langer & Kreft, o [27.5.2.4.5]/3-7.

Se puede crear un streambuf de salida funcional sobrescribiendo solo esta función (no se utilizará área de búfer).

Nota

La versión de la clase base no hace nada, devuelve eof().

template<typename _CharT, typename _Traits> char_type * std::basic_streambuf< _CharT, _Traits >::pbase () const [inline], [protected]

Access to the put area. These functions are only available to other protected functions, including derived classes.

  • pbase() returns the beginning pointer for the output sequence

NAME

std::basic_streambuf — stream buffer class template

SYNOPSIS

template<typename _CharT, typename _Traits>
class std::basic_streambuf< _CharT, _Traits >

Detailed Description

The class std::basic_streambuf is the base class for stream buffer classes. Stream buffers are used by stream classes to handle the actual input and output of characters.

The template parameters are:

_CharT
The type of character stored in the stream buffer.
_Traits
The character traits class, which provides character manipulation and comparison functions.

The std::basic_streambuf class provides an abstract interface for stream buffers. Derived classes must implement virtual functions to provide specific input and output operations.
