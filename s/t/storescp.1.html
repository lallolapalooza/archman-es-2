NOMBRE

storescp - Almacén de DICOM (C-STORE) SCP

SINOPSIS

storescp [opciones] [puerto]

DESCRIPCIÓN

La aplicación storescp implementa un Proveedor de Clase de Servicio (SCP) para la Clase de Servicio de Almacenamiento. Escucha en un puerto TCP/IP específico las solicitudes de asociación entrantes de un Usuario de Clase de Servicio (SCU) y puede recibir tanto imágenes DICOM como otros objetos compuestos DICOM. La aplicación storescp también soporta la Clase de Servicio de Verificación como SCP.

PARÁMETROS

puerto  número de puerto tcp/ip en el que escuchar
      (este parámetro es obligatorio a menos que se especifique la opción --inetd)

NAME


storescp


DICOM storage SCP






SYNOPSIS


storescp [OPTION
    ...] [--help | --version]


storescp
    [OPTION ...] --config-file
    FILE






DESCRIPTION


The storescp application implements a DICOM
    Storage Service Class Provider (SCP). It listens for incoming DICOM network
    connections on a specified port, accepts DICOM associations and stores
    incoming DICOM dataset objects into a specified directory. If no directory is
    specified, incoming DICOM objects are stored in the current working
    directory.


The storescp application accepts DICOM
    network associations by default on the port defined by the ACR-NEMA service
    name in the /etc/services file. This is typically port 104.


A number of command line options are available to configure the
    behavior of storescp:




--accept-all


Accept DICOM associations regardless of the peer's IP address. By default,
        storescp only accepts associations from known
        (trusted) peers. This option can be used to open up the SCP to any
        incoming associations. It implicitly enables the --all-peers
        option and may be a security risk if not used carefully.


--all-peers


Accept DICOM associations from any IP address. This option is useful when
        storescp is running behind a firewall or when
        the IP address of the peer is not known in advance. This option may be
        a security risk if not used carefully.


--config-file FILE


Read association negotiation profiles and other configuration settings from
        the specified FILE. The format of the
        configuration file is described in Association Negotiation Profiles and Configuration Files.


--output-directory DIR


Store incoming DICOM objects in the directory specified by DIR.
        If not specified, incoming DICOM objects are stored in the current
        working directory.


--inetd


Run in inetd mode. This means that storescp
        is started by inetd and inherits the network
        connection from it. The DICOM association is then established over the
        standard input and output streams.


--listen-port PORT


Listen for incoming DICOM associations on the specified PORT.
        The default port is 104 (ACR-NEMA).


--log-config FILE


Use the specified FILE for logging configuration.
        The format of the logging configuration file is described in
        dcm4che.conf(5).


--prefer SYNTAX


Prefer the specified SYNTAX for the transfer
        syntax during association negotiation. This option can be specified
        multiple times to define a list of preferred transfer syntaxes in order
        of preference. If not specified, storescp prefers
        explicit transfer syntaxes over implicit ones and big-endian over
        little-endian transfer syntaxes.


--peer IP_ADDRESS[:PORT]


Only accept DICOM associations from the specified IP_ADDRESS
        and optional PORT. This option can be specified
        multiple times to define a list of trusted peers. If no --peer
        option is specified, storescp accepts associations
        from any IP address (see --all-peers).


--timeout SECONDS


Set the network connection timeout to SECONDS. If no
        data is received from the peer within this timeout, the connection is
        closed. The default timeout is 60 seconds.


--verbose


Enable verbose logging. This option can be specified multiple times to
        increase the verbosity level.


--warning


Enable warning logging. This option can be specified multiple times to
        increase the warning level.


--access-control


Enable host-based access control using TCP wrappers. This option requires
        that storescp be compiled with TCP wrapper
        support.

Access   Control


When compiled on Unix platforms with TCP wrapper support,
    host-based access control can be enabled with the --access-control
    command line option. In this case the access control rules defined in the
    system's host access control tables for storescp are
    enforced. The default locations of the host access control tables are
    /etc/hosts.allow and /etc/hosts.deny. Further details are
    described in hosts_access(5).






Running   storescp from inetd


On Posix platforms, storescp can be initiated
    through the inetd(8) super server. This requires
    that storescp be configured in the
    /etc/inetd.conf configuration file. A typical configuration line
    could look like this:


acr-nema stream tcp nowait root /usr/sbin/storescp -id +ac -od /tmp/storescp


where -id (--inetd)
    activates the inetd mode in which the DICOM association is actually accepted
    by inetd and passed to storescp, +ac
    (--access-control) activates the TCP wrapper based
    access control described above and -od
    (--output-directory) defines the directory in which
    storescp stores incoming DICOM objects. Note that the
    service name ("acr-nema" in this example) determines the port number
    on which DICOM associations are accepted and must be defined in
    /etc/services. When running from inetd, the stdout and stderr
    streams are discarded. However, you can still configure logging via the
    --log-config option (see below).


Please note that when run through inetd, storescp
    is executed with root privileges, which may be a security risk.






Association   Negotiation Profiles and Configuration Files


storescp supports a flexible mechanism for
    specifying the DICOM network association negotiation behavior, based on
    so-called "association negotiation profiles" which may be read
    from a configuration file. The format and semantics of this configuration
    file are documented in asconfig.txt.

LOGGING

The level of logging output of the various command line tools and underlying libraries can be specified by the user. By default, only errors and warnings are written to the standard error stream. Using option --verbose also informational messages li

se detallan. La opción --debug puede usarse para obtener más detalles sobre la actividad interna, p. ej., para fines de depuración. Se pueden seleccionar otros niveles de registro mediante la opción --log-level. En el modo --quiet solo se informan los errores fatales. En tales eventos de error muy graves, la aplicación generalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida de registro deba escribirse en un archivo (opcionalmente con rotación de archivos de registro), en syslog (Unix) o en el registro de eventos (Windows), se puede usar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes según el módulo o la aplicación donde se generan. Se proporciona un archivo de configuración de ejemplo en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos utilizan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos al final indican que se permiten múltiples valores (1-n), una combinación de ambos significa de 0 a n valores.

Las opciones de línea de comandos se distinguen de los parámetros por un signo '+' o '-' inicial, respectivamente. Por lo general, el orden y la posición de las opciones de línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se utiliza la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells de Unix comunes.

Además, se puede especificar uno o más archivos de comandos utilizando un signo '@' como prefijo del nombre del archivo (p. ej., @comando.txt). Dicho argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier evaluación adicional. Tenga en cuenta que un archivo de comandos no puede contener otro archivo de comandos. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (se proporciona un ejemplo en el archivo <datadir>/dumppat.txt).

ENTORNO

La utilidad storescp intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está configurada, se cargará el archivo <datadir>/dicom.dic a menos que el diccionario esté integrado en la aplicación (predeterminado para Windows).

Se debe preferir el comportamiento predeterminado y usar la variable de entorno DCMDICTPATH solo cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell de Unix, en que un dos puntos (":") separa las entradas. En los sistemas Windows, se utiliza un punto y coma (";") como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se puede cargar ningún diccionario de datos.
