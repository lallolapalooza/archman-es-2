STAP-EXPORTER(8) Manual del Administrador del Sistema STAP-EXPORTER(8)

NOMBRE

stap-exporter - mecanismo de interconexión systemtap-prometheus

SINOPSIS

stap-exporter [ OPCIONES ]

DESCRIPCIÓN

stap-exporter ejecuta un conjunto de scripts systemtap y retransmite sus salidas de procfs a clientes HTTP remotos bajo demanda. Esto hace que los scripts de systemtap sean directamente utilizables como exportadores individuales de prometheus. Esto se ve asistido por un conjunto de macros proporcionadas en el archivo tapset prometheus.stpm.

OPCIONES

El programa stap-exporter admite las siguientes opciones.

-p --puerto PUERTO
Escucha en el puerto TCP especificado para solicitudes HTTP. Se utiliza el puerto 9900 por defecto.
-k --keepalive KEEPALIVE
Los scripts que se ejecutan durante más de KEEPALIVE segundos después de la última solicitud se cierran. No hay tiempo de espera por defecto, por lo que una vez iniciados, los scripts permanecen en ejecución.
-s --scripts SCRIPTS
Busca en el directorio SCRIPTS archivos *.stp para ser expuestos. El valor por defecto se da en la página del manual stappaths.7.
-h --ayuda
Imprime el mensaje de ayuda.

FUNCIONAMIENTO

Al iniciarse, stap-exporter busca en el directorio especificado por el directorio -s los archivos con nombre *.stp. El nombre de cada archivo estará disponible como un componente de URL para las solicitudes HTTP GET posteriores. Por ejemplo, cuando un cliente HTTP solicita /foo.stp, y el script foo.stp (ejecutable / script de shell) era conocido, entonces se inicia con opciones stap adicionales para establecer un nombre de módulo. Este nombre de módulo predecible hace posible que stap-exporter transcriba un archivo procfs de ese script en ejecución a clientes HTTP.

Después de un período configurable de inactividad (opción -k o --keepalive), se termina un script systemtap. Se reiniciará de nuevo si un cliente lo solicita.

Todos los archivos cuyo nombre incluye la subcadena autostart se inician inmediatamente (y se reinician si se detienen), en lugar de hacerlo bajo demanda. Estos se excluyen de las consideraciones de keepalive. Los scripts que pueden ser demasiado lentos para iniciarse o que desean informar estadísticas a largo plazo son candidatos para este tratamiento.

EJEMPLO

Supongamos que example.stp contiene el siguiente script. Cuenta las llamadas al sistema de lectura por hilo y por CPU.

global arr%
probe syscall.read {
    arr[tid(), cpu()]++
}
probe prometheus {
    @prometheus_dump_array2(arr, "count", "tid", "cpu")
}

Las macros prometheus_dump_array se utilizan para producir métricas a partir de un array. Systemtap proporciona una macro prometheus_dump_arrayN para todos los N de 1 a 8. El primer argumento de las macros representa un array con claves de N elementos. El segundo argumento representa el nombre de la métrica. Los N argumentos restantes representan los nombres de las etiquetas de la métrica.

Se puede ejecutar stap-exporter como root, o con privilegios equivalentes de stapdev, luego de una breve demora, usar cualquier cliente web para obtener datos:

# stap-exporter -p 9999 -k 60 -c . &
$ curl http://localhost:9999/example.stp
Refresh page to access metrics.  [...]
$ curl http://localhost:9999/example.stp
count{tid="12614",cpu="0"} 9
count{tid="12170",cpu="3"} 107
count{tid="1802",cpu="0"} 33687
count{tid="12617",cpu="1"} 99
[...]

La misma URL puede ser añadida a la sección scrape_config de un servidor Prometheus, o a un directorio Performance Co-Pilot pmdaprometheus config.d, para recopilar estos datos en un sistema de monitorización.

SEGURIDAD Y PROTECCIÓN

El servidor stap-exporter no aplica ningún mecanismo de seguridad particular. Por lo tanto, la implementación en un entorno no confiable debe considerar:

selección de scripts
Dado que los scripts systemtap se ejecutan bajo los privilegios del proceso stap-exporter (probablemente root), el administrador del sistema debe seleccionar solo scripts seguros y robustos. Verifique los scripts instalados por defecto antes de activar el servicio. Los scripts no pueden recibir entrada de los clientes web.
cortafuegos TCP/IP
Dado que stap-exporter expone el puerto TCP/HTTP seleccionado a todas las interfaces del host, puede ser necesario añadir un cortafuegos. Es poco probable que sea apropiado exponer dicho servicio a una red no confiable.
filtrado HTTP
Dado que stap-exporter expone los scripts systemtap configurados a todos los clientes HTTP sin autenticación, puede ser necesario protegerlo contra abusos incluso en redes mayoritariamente confiables. Se puede utilizar un proxy HTTP para imponer filtros basados en URL, clientes, uso o autenticación.
HTTPS
Dado que stap-exporter solo habla HTTP plano, se puede utilizar un proxy HTTP para soportar protocolos seguros HTTPS.
