stow(8) Documentación de Perl aportada por el usuario stow(8)

NOMBRE

stow - gestionar granjas de enlaces simbólicos

SINOPSIS

stow [ opciones ] paquete ...

DESCRIPCIÓN

Esta página del manual describe GNU Stow 2.4.1. Esta no es la documentación definitiva para Stow; para ello, consulte el manual de info adjunto, por ejemplo, escribiendo "info stow".

Stow es un gestor de enlaces simbólicos que toma conjuntos distintos de software y/o datos ubicados en directorios separados en el sistema de archivos, y hace que todos ellos parezcan estar instalados en un único árbol de directorios.

Originalmente Stow nació para abordar la necesidad de administrar, actualizar, instalar y eliminar archivos en paquetes de software independientes sin confundirlos con otros archivos que comparten el mismo espacio del sistema de archivos. Por ejemplo, hace muchos años era común compilar programas como Perl y Emacs desde la fuente. Usando Stow, /usr/local/bin podría contener enlaces simbólicos a archivos dentro de /usr/local/stow/emacs/bin, /usr/local/stow/perl/bin, etc., y de manera similar recursivamente para cualquier otro subdirectorio como .../share, .../man, y así sucesivamente.

Si bien esto es útil para llevar un registro de las instalaciones de software compilado desde la fuente, tanto a nivel de sistema como por usuario, en tiempos más recientes los paquetes de software a menudo son gestionados por software de gestión de paquetes más sofisticado como rpm, dpkg, y Nix / GNU Guix, o gestores de paquetes nativos de lenguajes como gem de Ruby, pip de Python, npm de Javascript, y similares.

Sin embargo, Stow todavía se utiliza no solo para la gestión de paquetes de software, sino también para otros propósitos, como facilitar un enfoque más controlado para la gestión de archivos de configuración en el directorio de inicio del usuario, especialmente cuando se combina con sistemas de control de versiones.

Stow se inspiró en el programa Depot de Carnegie Mellon, pero es sustancialmente más simple y seguro. Mientras que Depot requería archivos de base de datos para mantener las cosas sincronizadas, Stow no almacena ningún estado adicional entre ejecuciones, por lo que no hay peligro (como lo hubo en Depot) de dañar directorios cuando las jerarquías de archivos no coinciden con la base de datos. Tampoco, a diferencia de Depot, Stow eliminará nunca archivos, directorios o enlaces que aparezcan en un directorio de Stow (p. ej., /usr/local/stow/emacs), por lo que siempre es posible reconstruir el árbol de destino (p. ej., /usr/local).

Stow está implementado como una combinación de un script de Perl que proporciona una interfaz CLI, y un módulo de Perl de backend que hace la mayor parte del trabajo.

TERMINOLOGÍA

Un "paquete" es una colección relacionada de archivos y directorios que desea administrar como una unidad — p. ej., Perl o Emacs — y que necesita ser instalado en una estructura de directorios particular — p. ej., con subdirectorios bin, lib y man.

Un "directorio de destino" es la raíz de un árbol en el cual uno o más paquetes desean **aparecer** como instalados. Una ubicación común, pero de ninguna manera la única, es /usr/local. Los ejemplos en esta página del manual usarán /usr/local como el directorio de destino.

Un "directorio de stow" es la raíz de un árbol que contiene paquetes separados en subárboles privados. Cuando Stow se ejecuta, utiliza el directorio actual como el directorio de stow predeterminado. Los ejemplos en esta página del manual usarán /usr/local/stow como el directorio de stow, de modo que los paquetes individuales serán, por ejemplo, /usr/local/stow/perl y /usr/local/stow/emacs.

Una "imagen de instalación" es la disposición de archivos y directorios requerida por un paquete, relativa al directorio de destino. Por lo tanto, la imagen de instalación para Perl incluye: un directorio bin que contiene perl y a2p (entre otros); un directorio info que contiene documentación Texinfo; un directorio lib/perl que contiene bibliotecas de Perl; y un directorio man/man1 que contiene páginas del manual.

Un "directorio de paquete" es la raíz de un árbol que contiene la imagen de instalación para un paquete particular. Cada directorio de paquete debe residir en un directorio de stow — p. ej., el directorio de paquete /usr/local/stow/perl debe residir en el directorio de stow /usr/local/stow. El "nombre" de un paquete es el nombre de su directorio dentro del directorio de stow — p. ej., perl.

Por lo tanto, el ejecutable de Perl podría residir en /usr/local/stow/perl/bin/perl, donde /usr/local es el directorio de destino, /usr/local/stow es el directorio de stow, /usr/local/stow/perl es el directorio de paquete, y bin/perl dentro es parte de la imagen de instalación.

Un "enlace simbólico" es un enlace simbólico. Un enlace simbólico puede ser "relativo" o "absoluto". Un enlace simbólico absoluto nombra una ruta completa; es decir, una que comienza desde /. Un enlace simbólico relativo nombra una ruta relativa; es decir, una que no comienza desde /. El objetivo de un enlace simbólico relativo se calcula a partir del propio directorio del enlace simbólico. Stow solo crea enlaces simbólicos relativos.

OPCIONES

El directorio de stow se asume que es el valor de la variable de entorno "STOW_DIR" o, si no está definida, el directorio actual, y el directorio de destino se asume que es el padre del directorio actual (por lo que es típico ejecutar stow desde el directorio /usr/local/stow). Cada paquete dado en la línea de comandos es el nombre de un paquete en el directorio de stow (p. ej., perl). Por defecto, se instalan en el directorio de destino (pero pueden eliminarse en su lugar usando "-D").

-n
--no
--simular
No realizar ninguna operación que modifique el sistema de archivos; simplemente mostrar lo que sucedería.
-d DIRECTORIO
--directorio=DIRECTORIO
Establecer el directorio de stow a "DIRECTORIO" en lugar del directorio actual. Esto también tiene el efecto de hacer que el directorio de destino predeterminado sea el padre de "DIRECTORIO".
-t DIRECTORIO
--destino=DIRECTORIO
Establecer el directorio de destino a "DIRECTORIO" en lugar del padre del directorio de stow.
-v
--verboso[=N]
Enviar salida detallada al error estándar describiendo lo que está haciendo Stow. Los niveles de verbosidad son de 0 a 5; 0 es el valor predeterminado. Usar "-v" o "--verboso" aumenta la verbosidad en uno; usar `--verboso=N'` lo establece a N.
-S
--stow
Instalar los paquetes que siguen esta opción en el directorio de destino. Esta es la acción predeterminada, por lo que se puede omitir si solo se están instalando paquetes en lugar de realizar una mezcla de acciones de instalación/eliminación/reinstalación.
-D
--eliminar
Desinstalar los paquetes que siguen esta opción del directorio de destino en lugar de instalarlos.
-R
--restow
Reinstalar paquetes (primero desinstalar, luego reinstalar). Esto es útil para eliminar enlaces simbólicos obsoletos del árbol de destino después de actualizar el software en un paquete.
--adoptar
¡Advertencia! Este comportamiento está específicamente destinado a alterar el contenido de tu directorio de stow. Si no deseas eso, esta opción no es para ti.

Al instalar, si se encuentra un destino que ya existe pero es un archivo plano (y por lo tanto no es propiedad de ningún paquete de stow existente), normalmente Stow registrará esto como un conflicto y se negará a proceder. Esta opción cambia ese comportamiento para que el archivo se mueva a la misma ubicación relativa dentro de la imagen de instalación del paquete dentro del directorio de stow, y luego la instalación procede como antes. Así que, efectivamente, el archivo es adoptado por el paquete de stow, sin que cambie su contenido.

--no-folding
Desactivar el plegado de directorios recién instalados al instalar, y el repliegue de directorios recién plegables al desinstalar.

OPTIONS

--ignore=REGEX
Ignorar archivos que terminen con esta expresión regular de Perl.
--defer=REGEX
No instalar archivos que comiencen con esta expresión regular de Perl si el archivo ya está instalado en otro paquete.
--override=REGEX
Forzar la instalación de archivos que comiencen con esta expresión regular de Perl si el archivo ya está instalado en otro paquete.
--dotfiles
Habilitar manejo especial para "dotfiles" (archivos o carpetas cuyo nombre comienza con un punto) en el directorio del paquete. Si esta opción está habilitada, Stow agregará un paso de preprocesamiento para cada archivo o carpeta cuyo nombre comience con "dot-", y reemplazará el prefijo "dot-" en el nombre por un punto (.). Esto es útil cuando Stow se usa para gestionar colecciones de dotfiles, para evitar tener un directorio de paquetes lleno de archivos ocultos.

Por ejemplo, supongamos que tenemos un paquete que contiene dos archivos, stow/dot-bashrc y stow/dot-emacs.d/init.el. Con esta opción, Stow creará enlaces simbólicos de .bashrc a stow/dot-bashrc y de .emacs.d/init.el a stow/dot-emacs.d/init.el. Cualquier otro archivo, cuyo nombre no comience con "dot-", se procesará como de costumbre.

-V
--version
Mostrar el número de versión de Stow y salir.
-h
--help
Mostrar la sintaxis de comandos de Stow y salir.

INSTALACIÓN DE PAQUETES

La acción predeterminada de Stow es instalar un paquete. Esto significa crear enlaces simbólicos en el árbol de destino que apunten al árbol del paquete. Stow intenta hacer esto con la menor cantidad de enlaces simbólicos posible; en otras palabras, si Stow puede crear un único enlace simbólico que apunte a un subárbol completo dentro del árbol del paquete, elegirá hacer eso en lugar de crear un directorio en el árbol de destino y poblarlo con enlaces simbólicos.

Por ejemplo, supongamos que ningún paquete se ha instalado aún en /usr/local; está completamente vacío (excepto por el subdirectorio stow, por supuesto). Ahora supongamos que se instala el paquete Perl. Recordemos que incluye los siguientes directorios en su imagen de instalación: bin; info; lib/perl; man/man1. En lugar de crear el directorio /usr/local/bin y poblarlo con enlaces simbólicos a ../stow/perl/bin/perl y ../stow/perl/bin/a2p (etc.), Stow creará un único enlace simbólico, /usr/local/bin, que apunta a stow/perl/bin. De esta manera, todavía funciona referirse a /usr/local/bin/perl y /usr/local/bin/a2p, y se han creado menos enlaces simbólicos. Esto se llama "plegado de árbol", ya que un subárbol completo se "pliega" en un único enlace simbólico.

Para completar este ejemplo, Stow también creará el enlace simbólico /usr/local/info apuntando a stow/perl/info; el enlace simbólico /usr/local/lib apuntando a stow/perl/lib; y el enlace simbólico /usr/local/man apuntando a stow/perl/man.

Ahora supongamos que en lugar de instalar el paquete Perl en un árbol de destino vacío, el árbol de destino no está vacío desde el principio. En cambio, contiene varios archivos y directorios instalados bajo una filosofía de administración de sistemas diferente. En particular, /usr/local/bin ya existe y es un directorio, al igual que /usr/local/lib y /usr/local/man/man1. En este caso, Stow descenderá en /usr/local/bin y creará enlaces simbólicos a ../stow/perl/bin/perl y ../stow/perl/bin/a2p (etc.), y descenderá en /usr/local/lib y creará el enlace simbólico de plegado de árbol perl apuntando a ../stow/perl/lib/perl, y así sucesivamente. Como regla general, Stow solo desciende tanto como sea necesario en el árbol de destino cuando puede crear un enlace simbólico de plegado de árbol.

Llega el momento en que un enlace simbólico de plegado de árbol tiene que ser deshecho porque otro paquete utiliza uno o más de los directorios plegados en su imagen de instalación. Esta operación se llama "desplegar" un árbol plegado. Implica eliminar el enlace simbólico original del árbol de destino, crear un directorio real en su lugar y luego poblar el nuevo directorio con enlaces simbólicos al paquete recién instalado y al paquete antiguo que utilizaba el enlace simbólico antiguo. Por ejemplo, supongamos que después de instalar Perl en un /usr/local vacío, deseamos instalar Emacs. La imagen de instalación de Emacs incluye un directorio bin que contiene los ejecutables emacs y etags, entre otros. Stow debe hacer que estos archivos parezcan estar instalados en /usr/local/bin, pero actualmente /usr/local/bin es un enlace simbólico a stow/perl/bin. Por lo tanto, Stow realiza los siguientes pasos: se elimina el enlace simbólico /usr/local/bin; se crea el directorio /usr/local/bin; se crean enlaces desde /usr/local/bin a ../stow/emacs/bin/emacs y ../stow/emacs/bin/etags; y se crean enlaces desde /usr/local/bin a ../stow/perl/bin/perl y ../stow/perl/bin/a2p.

Al desplegar un árbol plegado, Stow se asegura de que el enlace simbólico que está a punto de eliminar apunte dentro de un paquete válido en el directorio de stow actual.

Stow nunca eliminará nada que no posea.

Stow "posee" todo lo que se encuentra en el árbol de destino y que apunta a un paquete en el directorio de stow. Cualquier cosa que Stow posea, puede recalcularla si se pierde. Tenga en cuenta que por esta definición, Stow no "posee" nada en el directorio de stow o en ninguno de los paquetes.

Si Stow necesita crear un directorio o un enlace simbólico en el árbol de destino y no puede porque ese nombre ya está en uso y no es propiedad de Stow, entonces ha surgido un conflicto. Consulte la sección "Conflicts" en el manual de información.

ELIMINACIÓN DE PAQUETES

Cuando se proporciona la opción "-D", la acción de Stow es eliminar un paquete del árbol de destino. Tenga en cuenta que Stow no eliminará nada que no "posea". Eliminar un paquete no significa eliminarlo del directorio de stow ni descartar el árbol del paquete.

Para eliminar un paquete, Stow escanea recursivamente el árbol de destino, omitiendo el directorio de stow (ya que suele ser un subdirectorio del árbol de destino) y cualquier otro directorio de stow que encuentre (ver "Multiple stow directories" en el manual de información). Se elimina cualquier enlace simbólico que encuentre y que apunte al paquete que se está eliminando. Se elimina cualquier directorio que contuviera solo enlaces simbólicos al paquete que se está eliminando. Cualquier directorio que, después de eliminar enlaces simbólicos y subdirectorios vacíos, contenga solo enlaces simbólicos a un único otro paquete, se considera un árbol previamente "plegado" que fue "desplegado". Stow volverá a plegar el árbol eliminando los enlaces simbólicos al paquete que sobrevive, eliminando el directorio y luego enlazando el directorio de vuelta al paquete que sobrevive.

ARCHIVOS DE RECURSOS

Stow busca opciones de línea de comandos predeterminadas en .stowrc (directorio actual) y ~/.stowrc (directorio de inicio) en ese orden. Si ambas ubicaciones están presentes, los archivos se adjuntan efectivamente.

El efecto de las opciones en el archivo de recursos es similar a simplemente anteponer las opciones a la línea de comandos. Para las opciones que proporcionan un único valor, como --target o --dir, la opción de línea de comandos sobrescribirá cualquier opción en el archivo de recursos. Para las opciones que se pueden proporcionar varias veces, como --ignore, por ejemplo, las opciones de línea de comandos y las opciones de recursos se adjuntan.

Las variables de entorno y el carácter de tilde (~) se expandirán para las opciones que toman una ruta de archivo.

Se ignoran las opciones -D, -R, -S y los paquetes listados en el archivo de recursos.

Consulte el manual de información para obtener más detalles sobre cómo Stow maneja los archivos de recursos.

VER TAMBIÉN

La documentación completa de stow se mantiene como un manual de Texinfo. Si los programas info y stow están instalados correctamente en su sitio, el comando

info stow

debería darle acceso al manual completo.

ERRORES

Por favor, informe de los errores en Stow utilizando el sistema de seguimiento de errores de Debian.

Los errores conocidos actualmente incluyen:

  • El problema del directorio vacío.

    Si el paquete foo incluye un directorio vacío, por ejemplo, foo/bar, entonces si ningún otro paquete tiene un subdirectorio bar, todo está bien. Si otro paquete instalado, quux, tiene un subdirectorio bar, entonces al instalar, targetdir/bar será "desplegado" y el contenido de quux/bar se instalará individualmente. Hasta aquí, todo bien. Pero al desinstalar quux, se eliminará targetdir/bar, aunque foo/bar lo necesite. Una solución provisional para este problema es crear un archivo en foo/bar como marcador de posición. Si nombra ese archivo .placeholder, será fácil encontrar y eliminar dichos archivos cuando este error se corrija.

  • Al utilizar múltiples directorios de stow (ver "Multiple stow directories" en el manual de información), Stow no logra "desplegar" enlaces simbólicos de plegado de árbol (ver "Installing packages" en el manual de información) que apuntan a un directorio de stow que no es el que está utilizando el comando Stow actual. Antes de fallar, debería buscar el destino del enlace para ver si algún elemento de la ruta contiene un archivo .stow. Si encuentra uno, puede "aprender" sobre el directorio de stow cooperante para acortar la búsqueda de .stow la próxima vez que encuentre un enlace simbólico de plegado de árbol.
