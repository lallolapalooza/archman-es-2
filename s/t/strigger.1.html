NOMBRE

strigger - Se utiliza para establecer, obtener o borrar información de disparadores de Slurm.

SINOPSIS

strigger --set [OPCIONES...]
strigger --get [OPCIONES...]
strigger --clear [OPCIONES...]

DESCRIPCIÓN

strigger se utiliza para establecer, obtener o borrar información de disparadores de Slurm. Los disparadores incluyen eventos como un nodo que falla, un trabajo que alcanza su límite de tiempo o un trabajo que termina. Estos eventos pueden provocar acciones como la ejecución de un script arbitrario. Los usos típicos incluyen notificar a los administradores del sistema sobre fallos de nodos y terminar un trabajo de forma controlada cuando se acerca su límite de tiempo. Una expresión de lista de hosts para la lista de nodos o el ID del trabajo se pasa como argumento al programa.

Los eventos de disparador no se procesan de forma instantánea, sino que se realiza una comprobación de eventos de disparador de forma periódica (actualmente cada 15 segundos). Cualquier evento de disparador que ocurra dentro de ese intervalo se comparará con los programas de disparador establecidos al final del intervalo de tiempo. El programa de disparador se ejecutará una vez por cada evento que ocurra en ese intervalo. El registro de esos eventos (por ejemplo, los nodos que pasaron a estado DOWN en los 15 segundos anteriores) se borrará. El programa de disparador debe establecer un nuevo disparador antes del final del siguiente intervalo para garantizar que no se pierdan eventos de disparador O el disparador debe crearse con el argumento "--flags=PERM". Si se desea, se pueden establecer múltiples programas de disparador para el mismo evento.

NOTA: Este comando solo puede establecer disparadores si lo ejecuta el usuario SlurmUser, a menos que SlurmUser esté configurado como usuario root. Esto es necesario para que el demonio slurmctld establezca los identificadores de usuario y grupo apropiados para el programa ejecutado. Tenga en cuenta también que el programa de disparador se ejecuta en el mismo nodo que utiliza el demonio slurmctld en lugar de algún nodo de cómputo asignado. Para verificar el valor de SlurmUser, ejecute el comando:

scontrol show config | grep SlurmUser

ARGUMENTOS

-C, --backup_slurmctld_assumed_control
Evento de disparador cuando el slurmctld de respaldo asume el control.
-B, --backup_slurmctld_failure
Dispara un evento cuando el slurmctld de respaldo falla.
-c, --backup_slurmctld_resumed_operation
Dispara un evento cuando el slurmctld de respaldo reanuda la operación después de un fallo.
--burst_buffer
Evento de disparador cuando ocurre un error en el buffer de ráfaga.
--clear
Borra o elimina un disparador de eventos previamente definido. Se debe especificar la opción --id, --jobid o --user para identificar el(los) disparador(es) a borrar. Solo el usuario root o el creador del disparador pueden eliminar un disparador.
-M, --clusters=<cadena>
Clusters a los que emitir comandos. Tenga en cuenta que el slurmdbd debe estar activo para que esta opción funcione correctamente, a menos que se ejecute en una federación con FederationParameters=fed_display configurado.
-d, --down
Dispara un evento si el nodo especificado pasa al estado DOWN.
-D, --drained
Dispara un evento si el nodo especificado pasa al estado DRAINED.
--draining
Dispara un evento si el nodo especificado pasa al estado DRAINING, antes de que esté DRAINED.
-F, --fail
Dispara un evento si el nodo especificado pasa al estado FAILING.
-f, --fini
Dispara un evento cuando el trabajo especificado completa su ejecución.
--flags=<bandera>
Asocia banderas con la reserva. Múltiples banderas deben estar separadas por comas. Las banderas válidas incluyen:
PERM
Hace que el disparador sea permanente. No lo elimina después de que ocurra el evento.
--get
Muestra los disparadores de eventos registrados. Las opciones se pueden utilizar con fines de filtrado.
-i, --id=<id>
Número de ID del disparador.
-I, --idle
Dispara un evento si el nodo especificado permanece en estado IDLE durante al menos el período de tiempo especificado por la opción --offset. Esto puede ser útil para hibernar un nodo que permanece inactivo, reduciendo así el consumo de energía.
-j, --jobid=<id>
ID del trabajo de interés. NOTA: La opción --jobid no se puede usar junto con la opción --node. Cuando la opción --jobid se usa junto con la opción --up o --down, todos los nodos asignados a ese trabajo se considerarán los nodos utilizados como evento de disparador.
-n, --node[=host]
Nombre(s) de host de interés. Por defecto, todos los nodos asociados con el trabajo (si se especifica --jobid) o en el sistema se consideran para eventos de disparador. NOTA: La opción --node no se puede usar junto con la opción --jobid. Cuando la opción --jobid se usa junto con las opciones --up, --down o --drained, todos los nodos asignados a ese trabajo se considerarán los nodos utilizados como evento de disparador. Dado que el argumento de esta opción es opcional, para un análisis correcto, la opción de una sola letra debe ir seguida inmediatamente por el valor y no incluir un espacio entre ellos. Por ejemplo, "-ntux" y no "-n tux".
-N, --noheader
No imprimir la cabecera al mostrar una lista de disparadores.
-o, --offset=<segundos>
La acción especificada debe seguir al evento por este intervalo de tiempo. Especifique un valor negativo si la acción debe preceder al evento. El valor predeterminado es cero si no se especifica la opción --offset. La resolución de este tiempo es de aproximadamente 20 segundos, por lo que para ejecutar un script no menos de cinco minutos antes de que un trabajo alcance su límite de tiempo, especifique --offset=320 (5 minutos más 20 segundos).
-h, --primary_database_failure
Dispara un evento cuando falla la base de datos primaria. Este evento se dispara cuando el plugin de contabilidad intenta abrir una conexión con mysql y falla, y slurmctld necesita la base de datos para algunas operaciones.

DESCRIPTION

The strigger command is used to set, clear, get, or delete event triggers for Slurm. Event triggers are events that are logged by Slurm and can be used to initiate actions such as executing a command.

For a list of events that can be logged, see the Event Types section below.

OPTIONS

-C, --clear
Clear event triggers. If no specific trigger is identified by other options, then all event triggers are cleared. If a user is specified with the --user option, then all event triggers for that user are cleared.
-d, --down
Trigger an event if the specified node is marked as DOWN.
-D, --drained
Trigger an event if the specified node is marked as DRAINED.
-f, --fini
Trigger an event when a job finishes. This can be used in conjunction with the --jobid option to trigger on a specific job's finish.
--get
Get a list of existing event triggers. If no specific trigger is identified by other options, then all event triggers are listed.
-i, --idle
Trigger an event if the specified node is marked as IDLE.
-J, --jobid=<job_id>
Trigger on a specific job ID. This option is only valid for job-related events (e.g., fini, time).
-m, --message=<message>
Add a message to the trigger event. The message will be logged along with the event. The message can be up to 1024 characters long.
-n, --node
Trigger an event based on a node state change. This option is used in conjunction with other node-related event options such as --down, --drained, --idle, --resume, and --up.
-o, --offset=<time_offset>
Trigger an event at a specified time offset from the event. The offset can be specified in seconds (default), minutes (m), hours (h), or days (d). For example, -o 10m will trigger the event 10 minutes before the event occurs. Negative offsets are allowed and indicate that the action should occur before the event. This is only applicable to job-related events.
-H, --primary_database_resumed_operation
Trigger an event when the primary database resumes operation after failure. It happens when the connection to mysql from the accounting plugin is restored.
-g, --primary_slurmdbd_failure
Trigger an event when the primary slurmdbd fails. The trigger is launched by slurmctld in the occasions it tries to connect to slurmdbd, but receives no response on the socket.
-G, --primary_slurmdbd_resumed_operation
Trigger an event when the primary slurmdbd resumes operation after failure. This event is triggered when opening the connection from slurmctld to slurmdbd results in a response. It can happen also in different situations, periodically every 15 seconds when checking the connection status, when saving state, when agent queue is filling, and so on.
-e, --primary_slurmctld_acct_buffer_full
Trigger an event when primary slurmctld accounting buffer is full.
-a, --primary_slurmctld_failure
Trigger an event when the primary slurmctld fails.
-b, --primary_slurmctld_resumed_control
Trigger an event when primary slurmctld resumes control.
-A, --primary_slurmctld_resumed_operation
Trigger an event when the primary slurmctld resuming operation after failure.
-p, --program=<path>
Execute the program at the specified fully qualified pathname when the event occurs. You may quote the path and include extra program arguments if desired. The program will be executed as the user who sets the trigger. If the program fails to terminate within 5 minutes, it will be killed along with any spawned processes.
-Q, --quiet
Do not report non-fatal errors. This can be useful to clear triggers which may have already been purged.
-r, --reconfig
Trigger an event when the system configuration changes. This is triggered when the slurmctld daemon reads its configuration file or when a node state changes.
-R, --resume
Trigger an event if the specified node is set to the RESUME state.
--set
Register an event trigger based upon the supplied options. NOTE: An event is only triggered once. A new event trigger must be set established for future events of the same type to be processed. Triggers can only be set if the command is run by the user SlurmUser unless SlurmUser is configured as user root.
-t, --time
Trigger an event when the specified job's time limit is reached. This must be used in conjunction with the --jobid option.
-u, --up
Trigger an event if the specified node is returned to service from a DOWN state.
--user=<user_name_or_id>
Clear or get triggers created by the specified user. For example, a trigger created by user root for a job created by user adam could be cleared with an option --user=root. Specify either a user name or user ID.
-v, --verbose
Print detailed event logging. This includes time-stamps on data structures, record counts, etc.
-V , --version
Print version information and exit.

OUTPUT FIELD DESCRIPTIONS

TRIG_ID
Trigger ID number.
RES_TYPE
Resource type: job or node
RES_ID
Resource ID: job ID or host names or "*" for any host
TYPE
Trigger type: time or fini (for jobs only), down or up (for jobs or nodes), or drained, idle or reconfig (for nodes only)
OFFSET
Time offset in seconds. Negative numbers indicated the action should occur before the event (if possible)
USER
Name of the user requesting the action
PROGRAM
Pathname of the program to execute when the event occurs

PERFORMANCE

Executing strigger sends a remote procedure call to slurmctld. If enough calls from strigger or other Slurm client commands that send remote procedure calls to the slurmctld daemon come in at once, it can result in a degradation of performance of the slurmctld daemon, possibly resulting in a denial of service.

Do not run strigger or other Slurm client commands that send remote procedure calls to slurmctld from loops in shell scripts or other programs. Ensure that programs limit calls to strigger to the minimum necessary for the information you are trying to gather.

ENVIRONMENT VARIABLES

Some strigger options may be set via environment variables. These environment variables, along with their corresponding options, are listed below. (Note: Command line options will always override these settings.)

SLURM_CONF
The location of the Slurm configuration file.
SLURM_DEBUG_FLAGS
Specify debug flags for strigger to use. See DebugFlags in the slurm.conf(5) man page for a full list of flags. The environment variable takes precedence over the setting in the slurm.conf.

EXAMPLES

Execute the program "/usr/sbin/primary_slurmctld_failure" whenever the primary slurmctld fails.
$ cat /usr/sbin/primary_slurmctld_failure
#!/bin/bash
# Submit trigger for next primary slurmctld failure event
strigger --set --primary_slurmctld_failure \
         --program=/usr/sbin/primary_slurmctld_failure
# Notify the administrator of the failure using e-mail
/bin/mail slurm_admin@site.com -s Primary_SLURMCTLD_FAILURE
$ strigger --set --primary_slurmctld_failure \
           --program=/usr/sbin/primary_slurmctld_failure
Execute the program "/usr/sbin/slurm_admin_notify" whenever any node in the cluster goes down. The subject line will include the node names which have entered the down state (passed as an argument to the script by Slurm).
$ cat /usr/sbin/slurm_admin_notify
#!/bin/bash
# Submit trigger for next event
strigger --set --node --down \
         --program=/usr/sbin/slurm_admin_notify
# Notify administrator using by e-mail
/bin/mail slurm_admin@site.com -s NodesDown:$*
$ strigger --set --node --down \
           --program=/usr/sbin/slurm_admin_notify
Execute the program "/usr/sbin/slurm_suspend_node" whenever any node in the cluster remains in the idle state for at least 600 seconds.
$ strigger --set --node --idle --offset=600 \
           --program=/usr/sbin/slurm_suspend_node
Execute the program "/home/joe/clean_up" when job 1234 is within 10 minutes of reaching its time limit.

EJEMPLOS

Ejecutar el programa "/home/joe/clean_up" 600 segundos antes de que el trabajo 1234 finalice.
$ strigger --set --jobid=1234 --time --offset=-600 \
           --program=/home/joe/clean_up
Ejecutar el programa "/home/joe/node_died" cuando cualquier nodo asignado al trabajo 1234 entre en el estado DOWN.
$ strigger --set --jobid=1234 --down \
           --program=/home/joe/node_died
Mostrar todos los disparadores asociados con el trabajo 1235.
$ strigger --get --jobid=1235
TRIG_ID RES_TYPE RES_ID TYPE OFFSET USER PROGRAM
    123      job   1235 time   -600  joe /home/bob/clean_up
    125      job   1235 down      0  joe /home/bob/node_died
Eliminar el disparador de evento 125.
$ strigger --clear --id=125
Ejecutar /home/joe/job_fini al finalizar el trabajo 1237.
$ strigger --set --jobid=1237 --fini --program=/home/joe/job_fini
