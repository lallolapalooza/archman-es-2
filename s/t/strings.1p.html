STRINGS(1P) Manual pages del programador de POSIX STRINGS(1P)

PROLOG

Esta página del manual forma parte del Manual del Programador de POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

strings — buscar cadenas imprimibles en archivos

SINOPSIS

strings [-a] [-t formato] [-n numero] [archivo...]

DESCRIPCIÓN

La utilidad strings buscará cadenas imprimibles en archivos regulares y escribirá dichas cadenas en la salida estándar. Una cadena imprimible es cualquier secuencia de cuatro (por defecto) o más caracteres imprimibles terminada por un carácter de nueva línea o NUL. Se pueden escribir cadenas adicionales definidas por la implementación; consulte localedef.

Si el primer argumento es '-', los resultados no están definidos.

OPCIONES

La utilidad strings cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis de Utilidades, excepto por el uso no definido de '-'.

Se admitirán las siguientes opciones:

-a
Escanear archivos en su totalidad. Si no se especifica -a, se definirá por la implementación qué porción de cada archivo se escanea en busca de cadenas.
-n numero
Especificar la longitud mínima de la cadena, donde el argumento numero es un entero decimal positivo. El valor predeterminado será 4.
-t formato
Escribir cada cadena precedida por su desplazamiento de bytes desde el inicio del archivo. El formato dependerá del único carácter utilizado como argumento de opción formato:
d
El desplazamiento se escribirá en decimal.
o
El desplazamiento se escribirá en octal.
x
El desplazamiento se escribirá en hexadecimal.

OPERANDOS

Se admitirá el siguiente operando:

archivo
Una ruta de acceso a un archivo regular que se utilizará como entrada. Si no se especifica ningún operando archivo, la utilidad strings leerá desde la entrada estándar.

STDIN

Consulte la sección ARCHIVOS DE ENTRADA.

ARCHIVOS DE ENTRADA

Los archivos de entrada especificados por los argumentos de la utilidad o la entrada estándar serán archivos regulares de cualquier formato.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de strings:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no estén establecidas o estén vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en argumentos y archivos de entrada) y para identificar cadenas imprimibles.
LC_MESSAGES

Determinar la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

STDOUT

Las cadenas encontradas se escribirán en la salida estándar, una por línea.

Cuando no se especifica la opción -t, el formato de la salida será:

"%s", <cadena>

Con la opción -t o, el formato de la salida será:

"%o %s", <desplazamiento de bytes>, <cadena>

Con la opción -t x, el formato de la salida será:

"%x %s", <desplazamiento de bytes>, <cadena>

Con la opción -t d, el formato de la salida será:

"%d %s", <desplazamiento de bytes>, <cadena>

STDERR

La salida de error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0
Ocurrió un error.

CONSECUENCIAS DE ERRORES

Predeterminado.

Las siguientes secciones son informativas.

USO DE LA APLICACIÓN

Por defecto, se escanea el área de datos (en contraposición a las áreas de texto, ``bss'' o cabecera) de un archivo ejecutable binario. Las implementaciones documentan qué áreas se escanean.

Algunas implementaciones históricas no requieren terminadores NUL o de nueva línea para las cadenas, lo que permite que se escriban las cadenas de aquellos idiomas que no utilizan NUL como terminador de cadena.

EJEMPLOS

Ninguno.

RACIOCINIO

Aparte de racionalizar la sintaxis de las opciones y las ligeras dificultades con los archivos binarios objeto y ejecutables, strings está especificado para coincidir de cerca con la práctica histórica. Las opciones -a y -n se introdujeron para reemplazar las opciones no conformes - y -número. Estas opciones ya no están especificadas por POSIX.1‐2008, pero pueden estar presentes en algunas implementaciones.

La opción -o históricamente significa cosas diferentes en diferentes implementaciones. Algunas la utilizan para significar ``desplazamiento en decimal'', mientras que otras la utilizan como ``desplazamiento en octal''. En lugar de intentar decidir qué forma sería la menos objetable, se añadió la opción -t. Originalmente se llamó -O para significar ``offset'', pero se cambió a -t para ser consistente con od.

La función isprint() del estándar ISO C está restringida a un dominio de unsigned char. Este volumen de POSIX.1‐2017 requiere que las implementaciones escriban cadenas según lo definido por la localización actual.
