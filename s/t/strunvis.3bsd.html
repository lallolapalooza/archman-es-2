NOMBRE

unvis, strunvis, strnunvis, strunvisx, strnunvisx — decodificar una representación visual de caracteres

DESCRIPCIÓN

Las funciones unvis(), strunvis() y strunvisx() se utilizan para decodificar una representación visual de caracteres, tal como la produce la función vis(3bsd), de vuelta a su forma original.

La función unvis() se llama con caracteres sucesivos en c hasta que se reconoce una secuencia válida, momento en el cual el carácter decodificado está disponible en el carácter apuntado por cp.

La función strunvis() decodifica los caracteres apuntados por src en el búfer apuntado por dst. La función strunvis() simplemente copia src a dst, decodificando cualquier secuencia de escape en el camino, y devuelve el número de caracteres colocados en dst, o -1 si se detectó una secuencia de escape inválida. El tamaño de dst debe ser igual al tamaño de src (es decir, no se produce expansión durante la decodificación).

La función strunvisx() hace lo mismo que la función strunvis(), pero permite agregar un indicador que especifica el estilo con el que está codificada la cadena src. Actualmente, los indicadores soportados son: VIS_HTTPSTYLE y VIS_MIMESTYLE.

La función unvis() implementa una máquina de estados que puede usarse para decodificar un flujo arbitrario de bytes. Todo el estado asociado con los bytes que se están decodificando se almacena fuera de la función unvis() (es decir, se pasa un puntero al estado), por lo que las llamadas que decodifican diferentes flujos pueden mezclarse libremente. Para comenzar a decodificar un flujo de bytes, primero inicialice un entero a cero. Llame a unvis() con cada byte sucesivo, junto con un puntero a este entero y un puntero a un carácter de destino. La función unvis() tiene varios códigos de retorno que deben manejarse correctamente. Estos son:

0 (cero)
Se necesita otro carácter; aún no se ha reconocido nada.
UNVIS_VALID
Se ha reconocido un carácter válido y está disponible en la ubicación apuntada por cp.
UNVIS_VALIDPUSH
Se ha reconocido un carácter válido y está disponible en la ubicación apuntada por cp; sin embargo, el carácter pasado actualmente debería pasarse de nuevo.
UNVIS_NOCHAR
Se detectó una secuencia válida, pero no se produjo ningún carácter. Este código de retorno es necesario para indicar una pausa lógica entre caracteres.
UNVIS_SYNBAD
Se detectó una secuencia de escape inválida o el decodificador está en un estado desconocido. El decodificador se coloca en el estado inicial.

Cuando todos los bytes del flujo se han procesado, llame a unvis() una vez más con el indicador establecido en UNVIS_END para extraer cualquier carácter restante (el carácter pasado se ignora).

El argumento flag también se usa para especificar el estilo de codificación de la fuente. Si se establece en VIS_HTTPSTYLE o VIS_HTTP1808, unvis() decodificará cadenas URI según lo especificado en RFC 1808. Si se establece en VIS_HTTP1866, unvis() decodificará referencias de entidad y referencias de caracteres numéricos según lo especificado en RFC 1866. Si se establece en VIS_MIMESTYLE, unvis() decodificará cadenas MIME Quoted-Printable según lo especificado en RFC 2045. Si se establece en VIS_NOESCAPE, unvis() no decodificará caracteres citados con «\».

El siguiente fragmento de código ilustra un uso adecuado de unvis().

int state = 0;
char out;

while ((ch = getchar()) != EOF) {
again:
	switch(unvis(&out, ch, &state, 0)) {
	case 0:
	case UNVIS_NOCHAR:
		break;
	case UNVIS_VALID:
		(void)putchar(out);
		break;
	case UNVIS_VALIDPUSH:
		(void)putchar(out);
		goto again;
	case UNVIS_SYNBAD:
		errx(EXIT_FAILURE, "Secuencia de caracteres incorrecta!");
	}
}
if (unvis(&out, '\0', &state, UNVIS_END) == UNVIS_VALID)
	(void)putchar(out);

ERRORES

Las funciones strunvis(), strnunvis(), strunvisx(), y strnunvisx() devolverán -1 en caso de error y establecerán errno a:

[EINVAL]
Se detectó una secuencia de escape inválida o el decodificador está en un estado desconocido.

Adicionalmente, las funciones strnunvis() y strnunvisx() también pueden establecer errno en caso de error a:

[ENOSPC]
No hay suficiente espacio para realizar la conversión.

BUGS

Los nombres VIS_HTTP1808 y VIS_HTTP1866 son incorrectos. La codificación de porcentaje se definió en el RFC 1738, el RFC original para las URL. El RFC 1866 define HTML 2.0, una aplicación de SGML, de la cual hereda conceptos de referencias de caracteres numéricos y referencias de entidades.
