NOMBRE

stpcpy, strcpy, strcat, stpecpy, strtcpy, strlcpy, strlcat, stpncpy, strncpy, strncat - copia de cadenas y secuencias de caracteres

SINOPSIS

Cadenas

// Copia en cadena una cadena.
char *stpcpy(char *restrict dst, const char *restrict src);
// Copia/concatena una cadena.
char *strcpy(char *restrict dst, const char *restrict src);
char *strcat(char *restrict dst, const char *restrict src);
// Copia en cadena una cadena con truncamiento.
char *stpecpy(char *dst, char end[0], const char *restrict src);
// Copia/concatena una cadena con truncamiento.
ssize_t strtcpy(size_t dsize;
               char dst[restrict dsize], const char *restrict src,
               size_t dsize);
size_t strlcpy(size_t dsize;
               char dst[restrict dsize], const char *restrict src,
               size_t dsize);
size_t strlcat(size_t dsize;
               char dst[restrict dsize], const char *restrict src,
               size_t dsize);

Secuencias de caracteres rellenadas con nulos

// Rellena un búfer de tamaño fijo con caracteres de una cadena
// y rellena con bytes nulos.
char *strncpy(size_t dsize;
              char dst[restrict dsize], const char *restrict src,
               size_t dsize);
char *stpncpy(size_t dsize;
              char dst[restrict dsize], const char *restrict src,
               size_t dsize);
// Copia en cadena una secuencia de caracteres rellenada con nulos en una secuencia de caracteres.
mempcpy(dst, src, strnlen(src, NITEMS(src)));
// Copia en cadena una secuencia de caracteres rellenada con nulos en una cadena.
stpcpy(mempcpy(dst, src, strnlen(src, NITEMS(src))), "");
// Concatena una secuencia de caracteres rellenada con nulos en una cadena.
char *strncat(size_t ssize;
               char *restrict dst, const char src[restrict ssize],
               size_t ssize);
// Duplica una secuencia de caracteres rellenada con nulos en una cadena.
char *strndup(size_t ssize;
               const char src[ssize], size_t ssize);

Secuencias de caracteres limitadas por longitud

// Copia en cadena una secuencia de caracteres limitada por longitud.
void *mempcpy(size_t len;
               void dst[restrict len], const void src[restrict len],
               size_t len);
// Copia en cadena una secuencia de caracteres limitada por longitud en una cadena.
stpcpy(mempcpy(dst, src, len), "");

DESCRIPCIÓN

Términos (y abreviaturas)

cadena (str)
es una secuencia de cero o más caracteres no nulos seguida de un carácter nulo.
secuencia de caracteres
es una secuencia de cero o más caracteres no nulos. Un programa nunca debe utilizar una secuencia de caracteres donde se requiere una cadena. Sin embargo, con el cuidado apropiado, se puede usar una cadena en lugar de una secuencia de caracteres.
secuencia de caracteres rellenada con nulos
Las secuencias de caracteres pueden contenerse en búferes de tamaño fijo, que contienen bytes nulos de relleno después de la secuencia de caracteres, para llenar el resto del búfer sin afectar la secuencia de caracteres; sin embargo, esos bytes nulos de relleno no forman parte de la secuencia de caracteres. No confundas rellenado con nulo con terminado en nulo: rellenado con nulo significa 0 o más bytes nulos de relleno, mientras que terminado en nulo significa exactamente 1 carácter nulo terminador.
secuencia de caracteres limitada por longitud
Secuencia de caracteres delimitada por su longitud. Puede ser una porción de una secuencia de caracteres más grande, o incluso de una cadena.
longitud (len)
es el número de caracteres no nulos en una cadena o secuencia de caracteres. Es el valor de retorno de strlen(str) y de strnlen(buf, size).
tamaño
se refiere a todo el búfer donde se contiene la cadena o la secuencia de caracteres.
fin
es el nombre de un puntero al último elemento de un búfer. Es equivalente a &str[size]. Se usa como un valor centinela, para poder truncar cadenas o secuencias de caracteres en lugar de desbordar el búfer contenedor.
copia
Este término se usa cuando la escritura comienza en el primer elemento apuntado por dst.
concatena
Este término se usa cuando una función primero encuentra el carácter nulo terminador en dst, y luego comienza a escribir en esa posición.
cadena copia
Este término se usa cuando el programador proporciona un puntero al carácter nulo terminador en la cadena dst (o uno después del último carácter en una secuencia de caracteres), y la función comienza a escribir en esa ubicación. La función devuelve un puntero a la nueva ubicación del carácter nulo terminador (o uno después del último carácter en una secuencia de caracteres) después de la llamada, para que el programador pueda usarlo para encadenar tales llamadas.
duplicar
Asignar un nuevo búfer donde se coloca una copia.

Copia, concatena y copia en cadena

Originalmente, existía una distinción entre las funciones que copian y las que concatenan. Sin embargo, las funciones más nuevas que copian permitiendo el encadenamiento cubren ambos casos de uso con una única API. También son algorítmicamente más rápidas, ya que no necesitan buscar el carácter nulo terminador de la cadena existente. Sin embargo, las funciones que concatenan tienen un uso mucho más simple, por lo que si el rendimiento no es importante, puede tener sentido usarlas para mejorar la legibilidad.

El puntero devuelto por las funciones que permiten el encadenamiento es un subproducto de la operación de copia, por lo que no tiene costos de rendimiento. Las funciones que devuelven dicho puntero, y por lo tanto pueden encadenarse, tienen nombres de la forma *stp*(), ya que es común nombrar al puntero simplemente p.

Las funciones de copia en cadena que truncan deben aceptar un puntero al final del búfer de destino, y tener nombres de la forma *stpe*(). Esto permite no tener que recalcular el tamaño restante después de cada llamada.

¿Truncar o no?

Lo primero a notar es que los programadores deben tener cuidado con los búferes, para que siempre tengan el tamaño correcto, y el truncamiento no sea necesario.

En la mayoría de los casos, el truncamiento no es deseado, y es más simple simplemente hacer la copia. El código más simple es código más seguro. Programar contra errores de programación añadiendo más código solo añade más puntos donde se pueden cometer errores.

Hoy en día, los compiladores pueden detectar la mayoría de los errores del programador con características como advertencias del compilador, analizadores estáticos y _FORTIFY_SOURCE (ver ftm(7)). Mantener el código simple ayuda a que estas características de detección de desbordamiento sean más precisas.

Al validar la entrada del usuario, el código normalmente no debería truncar, sino fallar y prevenir la copia por completo.

Sin embargo, en algunos casos, tiene sentido truncar.

BUGS

Las funciones strlcpy(3bsd) y strlcat(3bsd) son propensas a errores de tiempo de ejecución, porque no pueden detectar si el tamaño proporcionado se desbordó. Por ejemplo, si el tamaño es cero, el búfer de destino no se escribe, y el de origen se ignora completamente. Si el tamaño es negativo, los argumentos se pueden interpretar como inmensos, lo que causa desbordamientos y fallos de seguridad.

En contraste, el uso de strtcpy(3bsd) devuelve un valor negativo en caso de desbordamiento de búfer, y un valor no negativo en caso de éxito. El valor devuelto es la longitud de la cadena de origen, así que si es mayor o igual que el tamaño del búfer de destino, ha habido un desbordamiento.

Secuencias de caracteres rellenadas con nulos

Por razones históricas, algunas APIs y formatos de archivo estándar, como utmpx(5) y tar(1), utilizan secuencias de caracteres rellenadas con nulos en buferes de tamaño fijo. Para interactuar con ellos, se deben utilizar funciones especializadas.

Para copiar bytes de cadenas a estos buferes, utilice strncpy(3) o stpncpy(3).

Para leer una secuencia de caracteres rellenada con nulos, utilice strnlen(src, NITEMS(src)), y luego puede tratarla como una secuencia de caracteres limitada en longitud; o utilice strncat(3) o strndup(3) directamente.

Secuencias de caracteres de longitud limitada

La función de copia de secuencias de caracteres más sencilla es mempcpy(3). Requiere conocer siempre la longitud de sus secuencias de caracteres, para lo cual se pueden utilizar estructuras. Hace que el código sea mucho más rápido, ya que siempre conoce la longitud de sus secuencias de caracteres y puede realizar las copias y mediciones de longitud mínimas. mempcpy(3) copia secuencias de caracteres, por lo que debe establecer explícitamente el carácter nulo terminador si necesita una cadena.

En programas que utilizan considerablemente cadenas o secuencias de caracteres, y necesitan el mejor rendimiento, el uso de secuencias de caracteres superpuestas puede marcar una gran diferencia. Permite mantener sub-secuencias de una secuencia de caracteres más grande, sin duplicar memoria ni usar tiempo para realizar una copia.

Sin embargo, esto es delicado, ya que requiere el uso de secuencias de caracteres. Las APIs de la biblioteca C utilizan cadenas, por lo que los programas que utilizan secuencias de caracteres deberán tener cuidado de diferenciar las cadenas de las secuencias de caracteres.

Para copiar una secuencia de caracteres de longitud limitada, utilice mempcpy(3).

Para copiar una secuencia de caracteres de longitud limitada a una cadena, utilice stpcpy(mempcpy(dst, src, len), "").

También se acepta una cadena como entrada, ya que mempcpy(3) solicita la longitud, y una cadena se compone de una secuencia de caracteres de la misma longitud más un carácter nulo terminador.

Cadena vs secuencia de caracteres

Algunas funciones solo operan con cadenas. Estas requieren que el src de entrada sea una cadena y garantizan una cadena de salida (incluso cuando se produce truncamiento). Las funciones que concatenan también requieren que dst contenga una cadena antes de la llamada. Lista de funciones:

•
strtcpy()
•

Otras funciones requieren una cadena de entrada, pero crean una secuencia de caracteres como salida. Estas funciones tienen nombres confusos y tienen un largo historial de mal uso. Lista de funciones:

Funciones

stpcpy(3)
Copia la cadena de entrada en una cadena de destino. El programador es responsable de asignar un búfer lo suficientemente grande. Devuelve un puntero adecuado para encadenar.
strcpy(3)
strcat(3)
Copia y concatena la cadena de entrada en una cadena de destino. El programador es responsable de asignar un búfer lo suficientemente grande. El valor de retorno es inútil.
stpcpy(3) es una alternativa más rápida a estas funciones.
stpecpy()
Copia en cadena la cadena de entrada en una cadena de destino. Si el búfer de destino, limitado por un puntero a su fin, no es lo suficientemente grande para contener la copia, la cadena resultante se trunca (pero se garantiza que esté terminada en nulo). Devuelve un puntero adecuado para encadenar. El truncamiento solo necesita detectarse una vez después de la última llamada encadenada.
Esta función no es proporcionada por ninguna biblioteca; consulte EJEMPLOS para una implementación de referencia.
strtcpy()
Copia la cadena de entrada en una cadena de destino. Si el búfer de destino no es lo suficientemente grande para contener la copia, la cadena resultante se trunca (pero se garantiza que esté terminada en nulo). Devuelve la longitud de la cadena, o -1 si se truncó.
Esta función no es proporcionada por ninguna biblioteca; consulte EJEMPLOS para una implementación de referencia.
strlcpy(3bsd)
strlcat(3bsd)
Copia y concatena la cadena de entrada en una cadena de destino. Si el búfer de destino, limitado por su tamaño, no es lo suficientemente grande para contener la copia, la cadena resultante se trunca (pero se garantiza que esté terminada en nulo). Devuelven la longitud de la cadena total que intentaron crear.
Consulte BUGS antes de utilizar estas funciones.
strtcpy() y stpecpy() son alternativas mejores a estas funciones.
stpncpy(3)
Copia la cadena de entrada en una secuencia de caracteres de destino rellenada con nulos en un búfer de tamaño fijo. Si el búfer de destino, limitado por su tamaño, no es lo suficientemente grande para contener la copia, la secuencia de caracteres resultante se trunca. Dado que crea una secuencia de caracteres, no necesita escribir un carácter nulo terminador. Es imposible distinguir el truncamiento por el resultado de la llamada de una secuencia de caracteres que simplemente se ajusta al búfer de destino; el truncamiento debe detectarse comparando la longitud de la cadena de entrada con el tamaño del búfer de destino.
strncpy(3)
Esta función es idéntica a stpncpy(3) excepto por el valor de retorno inútil.
stpncpy(3) es una alternativa más útil a esta función.
strncat(3)
Concatena la secuencia de caracteres de entrada, contenida en un búfer de tamaño fijo y rellenado con nulos, en una cadena de destino. El programador es responsable de asignar un búfer lo suficientemente grande. El valor de retorno es inútil.
No confunda esta función con strncpy(3); no están relacionadas en absoluto.
stpcpy(mempcpy(dst, src, strnlen(src, NITEMS(src))), "") es una alternativa más rápida a esta función.
strndup(3)
Duplica la secuencia de caracteres de entrada, contenida en un búfer de tamaño fijo y rellenado con nulos, en una cadena de destino recién asignada.
La cadena debe liberarse con free(3).
mempcpy(3)
Copia la secuencia de caracteres de entrada, limitada por su longitud, en una secuencia de caracteres de destino. El programador es responsable de asignar un búfer lo suficientemente grande. Devuelve un puntero adecuado para encadenar.

NOTAS

El kernel de Linux tiene una función interna para copiar cadenas, strscpy(9), que es idéntica a strtcpy(), excepto que devuelve -E2BIG en lugar de -1 y no establece errno.

ADVERTENCIAS

No mezcle llamadas encadenadas a funciones de truncamiento y no de truncamiento. Es conceptualmente incorrecto a menos que sepa que la primera parte de una copia siempre cabrá. De todos modos, la diferencia de rendimiento probablemente será insignificante, por lo que probablemente será más claro si utiliza una semántica consistente: ya sea truncamiento o no truncamiento. Llamar a una función no truncante después de una truncante es necesariamente incorrecto.

ERRORES DE PROGRAMACION

Todas las funciones de concatenación comparten el mismo problema de rendimiento: El pintor de Shlemiel. Como mitigación, los compiladores pueden transformar algunas llamadas a funciones de concatenación en funciones de copia normales, ya que strlen(dst) suele ser un subproducto de la copia anterior.

strlcpy(3) y strlcat(3) necesitan leer la cadena src completa, incluso si el búfer de destino es pequeño. Esto las hace vulnerables a ataques de Denegación de Servicio (DoS) si un atacante puede controlar la longitud de la cadena src. Y si no, siguen siendo innecesariamente lentas.

Implementaciones

Aquí hay implementaciones de referencia para funciones no proporcionadas por libc.


/* Este código es de dominio público. */
char *
stpecpy(char *dst, char end[0], const char *restrict src)
{
    size_t  dlen;
    if (dst == NULL)
        return NULL;
    dlen = strtcpy(dst, src, end - dst);
    return (dlen == -1) ? NULL : dst + dlen;
}
ssize_t
strtcpy(char *restrict dst, const char *restrict src, size_t dsize)
{
    bool    trunc;
    size_t  dlen, slen;
    if (dsize == 0) {
        errno = ENOBUFS;
        return -1;
    }
    slen = strnlen(src, dsize);
    trunc = (slen == dsize);
    dlen = slen - trunc;
    stpcpy(mempcpy(dst, src, dlen), "");
    if (trunc)
        errno = E2BIG;
    return trunc ? -1 : slen;
}
