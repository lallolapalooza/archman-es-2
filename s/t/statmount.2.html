statmount(2) Manual de llamadas al sistema statmount(2)

NOMBRE

statmount - obtener el estado de un montaje

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/mount.h>  /* Definición de las constantes STATMOUNT_* */
#include <unistd.h>
int syscall(SYS_statmount, struct mnt_id_req *req,
            struct statmount *smbuf, size_t bufsize,
            unsigned long flags);
#include <linux/mount.h>
struct mnt_id_req {
    __u32  size;    /* sizeof(struct mnt_id_req) */
    __u64  mnt_id;  /* El mnt_id que se consulta */
    __u64  param;   /* Una combinación OR de las constantes STATMOUNT_* */
};
struct statmount {
    __u32  size;
    __u64  mask;
    __u32  sb_dev_major;
    __u32  sb_dev_minor;
    __u64  sb_magic;
    __u32  sb_flags;
    __u32  fs_type;
    __u64  mnt_id;
    __u64  mnt_parent_id;
    __u32  mnt_id_old;
    __u32  mnt_parent_id_old;
    __u64  mnt_attr;
    __u64  mnt_propagation;
    __u64  mnt_peer_group;
    __u64  mnt_master;
    __u64  propagate_from;
    __u32  mnt_root;
    __u32  mnt_point;
    char   str[];
};

Nota: glibc no proporciona un envoltorio para statmount(), lo que hace necesario el uso de syscall(2).

DESCRIPCIÓN

Para acceder al estado de un montaje, el llamador debe tener CAP_SYS_ADMIN en el espacio de nombres del usuario.

Esta función devuelve información sobre un montaje, almacenándola en el búfer apuntado por smbuf. El búfer devuelto es una struct statmount de tamaño bufsize con los campos rellenados como se describe a continuación.

(Nota: se omiten el espacio reservado y el relleno.)

La estructura mnt_id_req

req.size es utilizada por el kernel para determinar qué struct mnt_id_req se está pasando; siempre debe establecerse en sizeof(struct mnt_id_req).

req.mnt_id se puede obtener de statx(2) usando STATX_MNT_ID_UNIQUE o de listmount(2) y se utiliza como identificador para consultar el estado del punto de montaje deseado.

req.param se utiliza para indicar al kernel qué campos interesan al llamador. Es una combinación OR de las siguientes constantes


STATMOUNT_SB_BASIC /* Querer/obtener sb_* */
STATMOUNT_MNT_BASIC /* Querer/obtener mnt_* */
STATMOUNT_PROPAGATE_FROM /* Querer/obtener propagate_from */
STATMOUNT_MNT_ROOT /* Querer/obtener mnt_root */
STATMOUNT_MNT_POINT /* Querer/obtener mnt_point */
STATMOUNT_FS_TYPE /* Querer/obtener fs_type */

En general, el kernel *no* rechaza valores en req.param distintos de los anteriores. (Para una excepción, véase EINVAL en errores.) En su lugar, simplemente informa al llamador qué valores son compatibles con este kernel y sistema de archivos a través del campo statmount.mask. Por lo tanto, *no* establezca simplemente req.param en UINT_MAX (todos los bits establecidos), ya que uno o más bits pueden, en el futuro, utilizarse para especificar una extensión del búfer.

La información devuelta

La información de estado para el montaje de destino se devuelve en la estructura statmount apuntada por smbuf.

Los campos de la estructura statmount son:

smbuf.size
El tamaño de la estructura smbuf devuelta, incluidas las cadenas de los campos que se rellenaron.
smbuf.mask
La combinación OR de las banderas STATMOUNT_* que indica qué campos se rellenaron y, por lo tanto, son válidos. El kernel puede devolver campos que no se solicitaron y puede no devolver campos que se solicitaron, dependiendo de lo que admita el sistema de archivos subyacente y el kernel. En cualquier caso, req.param no será igual a mask.
smbuf.sb_dev_major
smbuf.sb_dev_minor
El dispositivo que está montado en este punto de montaje.
smbuf.sb_magic
La magia de superbloque específica del sistema de archivos.
smbuf.sb_flags
Las banderas establecidas en el superbloque, una combinación OR de SB_RDONLY, SB_SYNCHRONOUS, SB_DIRSYNC, SB_LAZYTIME.
smbuf.fs_type
El desplazamiento a la ubicación en el búfer smbuf.str que contiene la representación en cadena del sistema de archivos montado. Es una cadena terminada en nulo.
smbuf.mnt_id
El ID único de montaje del montaje.
smbuf.mnt_parent_id
El ID único de montaje del punto de montaje padre de este montaje. Si este es el punto de montaje raíz, entonces smbuf.mnt_id == smbuf.parent_mount_id.
smbuf.mnt_id_old
Esto corresponde al ID de montaje que se exporta desde /proc/pid/mountinfo.
smbuf.mnt_parent_id_old
Esto corresponde al ID de montaje padre que se exporta desde /proc/pid/mountinfo.
smbuf.mnt_attr
Las banderas MOUNT_ATTR_* establecidas en este punto de montaje.
smbuf.mnt_propagation
Las banderas de propagación de montaje, que pueden ser una de MS_SHARED, MS_SLAVE, MS_PRIVATE, MS_UNBINDABLE.
smbuf.mnt_peer_group
El ID del grupo de pares compartido.
smbuf.mnt_master
El punto de montaje recibe su propagación de este ID de montaje.
smbuf.propagate_from
El ID del espacio de nombres desde el que propagamos.
smbuf.mnt_root
El desplazamiento a la ubicación en el búfer smbuf.str que contiene la representación en cadena del montaje relativo a la raíz del sistema de archivos. Es una cadena terminada en nulo.
smbuf.mnt_point
El desplazamiento a la ubicación en el búfer smbuf.str que contiene la representación en cadena del montaje relativo a la raíz actual (es decir, si estás en un chroot). Es una cadena terminada en nulo.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EPERM
Se deniega el permiso para acceder a este montaje.
EFAULT
req o smbuf apuntan a una ubicación fuera del espacio de direcciones accesible del proceso.
EINVAL
Se especificó una bandera no válida en flags.
EINVAL
req es de tamaño insuficiente para ser utilizado.
E2BIG
req es demasiado grande.
EOVERFLOW
El tamaño de smbuf es demasiado pequeño para contener ni smbuf.fs_type, smbuf.mnt_root, o smbuf.mnt_point. Asigna un búfer más grande e intenta la llamada de nuevo.
ENOENT
mnt_id de req especificado no existe.
ENOMEM
Memoria agotada (es decir, memoria del kernel).

ESTÁNDARES

Linux.

VER TAMBIÉN

listmount(2), statx(2)
