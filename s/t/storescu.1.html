NOMBRE

storescu - SCU de almacenamiento DICOM (C-STORE)

SINOPSIS

storescu [opciones] peer puerto archivo-dcm...

DESCRIPCIÓN

La aplicación storescu implementa un Usuario de Clase de Servicio (SCU) para la Clase de Servicio de Almacenamiento. Para cada archivo DICOM en la línea de comandos, envía un mensaje C-STORE a un Proveedor de Clase de Servicio de Almacenamiento (SCP) y espera una respuesta. La aplicación puede ser utilizada para transmitir imágenes DICOM y otros objetos compuestos DICOM.

PARÁMETROS

peer        nombre de host del peer DICOM
puerto        número de puerto tcp/ip del peer
archivo-dcm  archivo o directorio DICOM a transmitir

NOTES

Scanning Directories

Adding directories as a parameter to the command line only makes sense if option --scan-directories is also given. If the files in the provided directories should be selected according to a specific name pattern (e.g. using wildcard matching), option --scan-pattern has to be used. Please note that this file pattern only applies to the files within the scanned directories, and, if any other patterns are specified on the command line outside the --scan-pattern option (e.g. in order to select further files), these do not apply to the specified directories.

The default behavior of storescu is to propose two presentation contexts for each supported SOP class (abstract syntax) - one with the preferred transfer syntax and one with all other uncompressed transfer syntaxes. The default preferred transfer syntax is explicit VR with byte ordering corresponding to the local byte ordering of the machine on which storescu is running. This behavior can be changed with the --propose, --combine and --required options, see above. Depending on these options, the following transfer syntaxes are supported:

Additional Storage SOP Classes and transfer syntaxes can be used with the so-called "association negotiation profiles" (see below).

The storescu application does not support extended negotiation by default. However, using an appropriate association negotiation profile (see below) the optional support for extended negotiation can be added to particular SOP classes.

Association Negotiation Profiles and Configuration Files

storescu supports a flexible mechanism for specifying the DICOM network association negotiation behavior, based on so-called "association negotiation profiles" which may be read from a configuration file. The format and semantics of this configuration file are documented in asconfig.txt.

User Identity Negotiation

The storescu application supports user identity negotiation according to the DICOM standard PS3.8, Annex K. This feature can be enabled by the --username and --password options.

NEGOTIAZIONE IDENTITÀ UTENTE

Quando si specifica il nome utente e/o la password usando le opzioni --user e -e --password, il valore deve essere fornito in codifica UTF-8.

Se viene usata l'opzione --pos-response, a SCP viene chiesto di rispondere esplicitamente, cioè confermare, le credenziali utente fornite nella richiesta storescu. Altrimenti, se non viene inviata alcuna risposta, storescu non continuerà ma interromperà la connessione. Poiché la Negoziazione dell'Identità Utente è una funzionalità opzionale introdotta successivamente nello standard, molti SCP non controlleranno l'identità utente fornita e quindi non forniranno alcuna risposta sull'identità utente.

LOGGING

Il livello di output del logging degli vari strumenti a riga di comando e librerie sottostanti può essere specificato dall'utente. Per impostazione predefinita, solo errori e avvisi vengono scritti sullo stream di errore standard. Usando l'opzione --verbose vengono riportati anche messaggi informativi come i dettagli di elaborazione. L'opzione --debug può essere usata per ottenere maggiori dettagli sull'attività interna, ad es. per scopi di debug. Altri livelli di logging possono essere selezionati usando l'opzione --log-level. In modalità --quiet vengono riportati solo errori fatali. In eventi di errore così gravi, l'applicazione terminerà di solito. Per maggiori dettagli sui diversi livelli di logging, vedere la documentazione del modulo "oflog".

Nel caso in cui l'output del logging debba essere scritto su file (opzionalmente con rotazione del file di log), su syslog (Unix) o sul log eventi (Windows), si può usare l'opzione --log-config. Questo file di configurazione permette anche di dirigere solo alcuni messaggi a un particolare stream di output e di filtrare alcuni messaggi in base al modulo o all'applicazione da cui sono generati. Un file di configurazione di esempio è fornito in <etcdir>/logger.cfg.

RIGA DI COMANDO

Tutti gli strumenti a riga di comando usano la seguente notazione per i parametri: le parentesi quadre racchiudono valori opzionali (0-1), tre puntini finali indicano che sono ammessi valori multipli (1-n), una combinazione di entrambi significa 0 a n valori.

Le opzioni a riga di comando si distinguono dai parametri con un segno '+' o '-' rispettivamente. Di solito, l'ordine e la posizione delle opzioni a riga di comando sono arbitrari (cioè possono apparire ovunque). Tuttavia, se le opzioni sono mutuamente esclusive, viene utilizzata l'apparizione più a destra. Questo comportamento è conforme alle regole di valutazione standard delle comuni shell Unix.

In aggiunta, uno o più file di comando possono essere specificati usando un segno '@' come prefisso al nome del file (ad es. @command.txt). Un tale argomento di comando viene sostituito dal contenuto del file di testo corrispondente (spazi multipli vengono trattati come un unico separatore a meno che non appaiano tra due virgolette) prima di qualsiasi ulteriore valutazione. Si noti che un file di comando non può contenere un altro file di comando. Questo approccio semplice ma efficace permette di riassumere combinazioni comuni di opzioni/parametri ed evita righe di comando troppo lunghe e confuse (un esempio è fornito nel file <datadir>/dumppat.txt).

AMBIENTE

L'utility storescu tenterà di caricare i dizionari dati DICOM specificati nella variabile d'ambiente DCMDICTPATH. Per impostazione predefinita, cioè se la variabile d'ambiente DCMDICTPATH non è impostata, verrà caricato il file <datadir>/dicom.dic a meno che il dizionario non sia integrato nell'applicazione (predefinito per Windows).

Il comportamento predefinito dovrebbe essere preferito e la variabile d'ambiente DCMDICTPATH usata solo quando sono richiesti dizionari dati alternativi. La variabile d'ambiente DCMDICTPATH ha lo stesso formato della variabile PATH della shell Unix, in quanto un due punti (":") separa le voci. Sui sistemi Windows, un punto e virgola (";") viene usato come separatore. Il codice del dizionario dati tenterà di caricare ogni file specificato nella variabile d'ambiente DCMDICTPATH. È un errore se nessun dizionario dati può essere caricato.
