str_to_gensio, str_to_gensio_child, gensio_acc_str_to_gensio - Crear un gensio a partir de una cadena

DESCRIPCIÓN

str_to_gensio asigna una nueva pila gensio basándose en la cadena dada str.

str_to_gensio_child asigna una pila gensio parcial y la apila encima del child dado. Tenga en cuenta que si el hijo ya está abierto, debe usar gesnio_open_nochild() para abrir solo este gensio. Esto solo se puede usar para asignar gensios de filtro.

gensio_acc_str_to_gensio asigna un gensio basándose en el aceptador dado. La disponibilidad y el uso de esto varía de gensio a gensio, pero se puede usar en UDP para crear un gensio que utilice los puertos UDP que posee el aceptador. Esto provendrá de la primera dirección/puerto en el que se encuentre el aceptador para TCP y UDP. Se enlazará a todas las direcciones/puertos para SCTP. Para usar esto, debe especificar una cadena que coincida exactamente con las capas del aceptador. Por ejemplo, si el aceptador es "telnet,ssl(CA=x1,key=x2,cert=x3),sctp,3095", entonces la cadena debe tener el formato "telnet,ssl(CA=x2),sctp,otherserver,3820". Las capas son exactamente las mismas, pero puede variar las opciones de las capas.

Para asignar directamente gensios, puede usar gensio_terminal_alloc y gensio_filter_alloc. Un gensio terminal es uno en la parte inferior de la pila. El parámetro gdata depende del gensio particular. Por ejemplo, para serialdev es una cadena que especifica el dispositivo y los parámetros seriales. Para stdio es una matriz argv. Consulte gensio.5 bajo "Asignación Directa" para el gensio particular para ver qué es gdata.

Un gensio de filtro es uno que tiene un hijo. Puede usar estas dos funciones para asignar una pila gensio directamente, sin usar un formato de cadena.

Los parámetros cb y user_data establecen una función que se llamará cuando lleguen eventos al gensio. user_data no es utilizado por la pila gensio en sí, está ahí para el usuario y puede ser cualquier cosa que el usuario desee. cb puede ser NULL antes de que el gensio se abra, pero debe establecerse antes de que se abra. En particular, no es necesario establecer cb si se apilarán otros gensios encima de él en el futuro, ya que los gensios apilados encima establecerán los valores de cb y user_data.

El nuevo gensio se devuelve en io. Estará en estado cerrado.

VALORES DE RETORNO

Se devuelve cero en caso de éxito, o un error de gensio en caso de fallo.
