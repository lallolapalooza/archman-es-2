strerror(3) Manual de funciones de biblioteca strerror(3)

NOMBRE

strerror, strerrorname_np, strerrordesc_np, strerror_r, strerror_l - devuelve una cadena que describe un número de error

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <string.h>
char *strerror(int errnum);
const char *strerrorname_np(int errnum);
const char *strerrordesc_np(int errnum);
int strerror_r(size_t size;
               int errnum, char buf[size], size_t size);
               /* Conforme a XSI */
char *strerror_r(size_t size;
               int errnum, char buf[size], size_t size);
               /* Específico de GNU */
char *strerror_l(int errnum, locale_t locale);
Requisitos de macro de prueba de características para glibc (ver feature_test_macros(7)):

strerrorname_np(), strerrordesc_np():

    _GNU_SOURCE

strerror_r():

    La versión conforme a XSI se proporciona si:
        (_POSIX_C_SOURCE >= 200112L) && ! _GNU_SOURCE
    De lo contrario, se proporciona la versión específica de GNU.

DESCRIPCIÓN

La función strerror() devuelve un puntero a una cadena que describe el código de error pasado en el argumento errnum, posiblemente utilizando la parte LC_MESSAGES de la configuración regional actual para seleccionar el idioma apropiado. (Por ejemplo, si errnum es EINVAL, la descripción devuelta será "Argumento inválido".) Esta cadena no debe ser modificada por la aplicación, y el puntero devuelto se invalidará en una llamada posterior a strerror() o strerror_l(), o si el hilo que obtuvo la cadena termina. Ninguna otra función de biblioteca, incluida perror(3), modificará esta cadena.

Al igual que strerror(), la función strerrordesc_np() devuelve un puntero a una cadena que describe el código de error pasado en el argumento errnum, con la diferencia de que la cadena devuelta no está traducida según la configuración regional actual.

La función strerrorname_np() devuelve un puntero a una cadena que contiene el nombre del código de error pasado en el argumento errnum. Por ejemplo, dado EPERM como argumento, esta función devuelve un puntero a la cadena "EPERM". Dado 0 como argumento, esta función devuelve un puntero a la cadena "0".

strerror_r()

strerror_r() es como strerror(), pero puede usar el búfer suministrado buf en lugar de asignarlo internamente. Esta función está disponible en dos versiones: una versión conforme a XSI especificada en POSIX.1-2001 (disponible desde glibc 2.3.4, pero no conforme a POSIX hasta glibc 2.13), y una versión específica de GNU (disponible desde glibc 2.0). La versión conforme a XSI se proporciona con la configuración de macros de prueba de características que se muestra en la SINOPSIS; de lo contrario, se proporciona la versión específica de GNU. Si no se definen macros de prueba de características explícitamente, entonces (desde glibc 2.4) _POSIX_C_SOURCE se define por defecto con el valor 200112L, de modo que la versión conforme a XSI de strerror_r() se proporciona por defecto.

La versión conforme a XSI de strerror_r() es preferible para aplicaciones portátiles. Devuelve la cadena de error en el búfer proporcionado por el usuario buf de tamaño size.

La versión específica de GNU de strerror_r() devuelve un puntero a una cadena que contiene el mensaje de error. Puede ser un puntero a una cadena que la función almacena en buf, o un puntero a una cadena estática (inmutable) (en cuyo caso buf no se utiliza). Si la función almacena una cadena en buf, entonces se almacenan como máximo size bytes (la cadena puede truncarse si size es demasiado pequeño y errnum es desconocido). La cadena siempre incluye un byte nulo terminador ('\0').

strerror_l()

strerror_l() es como strerror(), pero mapea errnum a un mensaje de error dependiente de la configuración regional en la configuración regional especificada por locale. El comportamiento de strerror_l() no está definido si locale es el objeto especial de configuración regional LC_GLOBAL_LOCALE o no es un manejador de objetos de configuración regional válido.

VALOR DE RETORNO

Las funciones strerror(), strerror_l() y la versión específica de GNU de strerror_r() devuelven la cadena de descripción de error apropiada, o un mensaje "Error desconocido nnn" si el número de error es desconocido.

En caso de éxito, strerrorname_np() y strerrordesc_np() devuelven la cadena de descripción de error apropiada. Si errnum es un número de error no válido, estas funciones devuelven NULL.

En caso de éxito, la versión conforme a XSI de strerror_r() devuelve 0. En caso de error, se devuelve un número de error (positivo) (desde glibc 2.13), o se devuelve -1 y se establece errno para indicar el error (antes de glibc 2.13).

POSIX.1-2001 y POSIX.1-2008 requieren que una llamada exitosa a strerror() o strerror_l() deje errno sin cambios, y señalan que, dado que no hay ningún valor de retorno reservado para indicar un error, una aplicación que desee comprobar errores debe inicializar errno a cero antes de la llamada y luego comprobar errno después de la llamada.

ERRORES

EINVAL
El valor de errnum no es un número de error válido.
ERANGE
No se proporcionó suficiente espacio para contener la cadena de descripción del error.

POSIX.1-2001 permite que strerror() establezca errno si la llamada encuentra un error, pero no especifica qué valor se debe devolver como resultado de la función en caso de error. En algunos sistemas, strerror() devuelve NULL si el número de error es desconocido. En otros sistemas, strerror() devuelve una cadena como "Error nnn ocurrido" y establece errno a EINVAL si el número de error es desconocido. C99 y POSIX.1-2008 requieren que el valor de retorno no sea NULL.

NOTAS

strerrorname_np() y strerrordesc_np() son seguras para hilos (thread-safe) y seguras para señales asíncronas (async-signal-safe).
