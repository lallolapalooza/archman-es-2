strftime(3) Manual de funciones de biblioteca strftime(3)

NOMBRE

strftime - formatear fecha y hora

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <time.h>
size_t strftime(size_t max;
                char s[restrict max], size_t max,
                const char *restrict format,
                const struct tm *restrict tm);
size_t strftime_l(size_t max;
                char s[restrict max], size_t max,
                const char *restrict format,
                const struct tm *restrict tm,
                locale_t locale);

DESCRIPCIÓN

La función strftime() formatea la hora desglosada tm según la especificación de formato format y coloca el resultado en el array de caracteres s de tamaño max. La estructura de hora desglosada tm se define en <time.h>. Ver también ctime(3).

La especificación de formato es una cadena terminada en nulo y puede contener secuencias de caracteres especiales llamadas especificaciones de conversión, cada una de las cuales está introducida por un carácter '%' y terminada por algún otro carácter conocido como carácter especificador de conversión. Todas las demás secuencias de caracteres son secuencias de caracteres ordinarios.

Los caracteres de las secuencias de caracteres ordinarios (incluido el byte nulo) se copian textualmente de format a s. Sin embargo, los caracteres de las especificaciones de conversión se reemplazan como se muestra en la lista a continuación. En esta lista, también se muestran los campos utilizados de la estructura tm.

%a
El nombre abreviado del día de la semana según la configuración regional actual. (Calculado a partir de tm_wday.) (Los nombres específicos utilizados en la configuración regional actual se pueden obtener llamando a nl_langinfo(3) con ABDAY_{1–7} como argumento.)
%A
El nombre completo del día de la semana según la configuración regional actual. (Calculado a partir de tm_wday.) (Los nombres específicos utilizados en la configuración regional actual se pueden obtener llamando a nl_langinfo(3) con DAY_{1–7} como argumento.)
%b
El nombre abreviado del mes según la configuración regional actual. (Calculado a partir de tm_mon.) (Los nombres específicos utilizados en la configuración regional actual se pueden obtener llamando a nl_langinfo(3) con ABMON_{1–12} como argumento.)
%B
El nombre completo del mes según la configuración regional actual. (Calculado a partir de tm_mon.) (Los nombres específicos utilizados en la configuración regional actual se pueden obtener llamando a nl_langinfo(3) con MON_{1–12} como argumento.)
%c
La representación preferida de fecha y hora para la configuración regional actual. (El formato específico utilizado en la configuración regional actual se puede obtener llamando a nl_langinfo(3) con D_T_FMT como argumento para la especificación de conversión %c, y con ERA_D_T_FMT para la especificación de conversión %Ec.) (En la configuración regional POSIX, esto es equivalente a %a %b %e %H:%M:%S %Y.)
%C
El número de siglo (año/100) como un entero de 2 dígitos. (SU) (La especificación de conversión %EC corresponde al nombre de la era.) (Calculado a partir de tm_year.)
%d
El día del mes como un número decimal (rango 01 a 31). (Calculado a partir de tm_mday.)
%D
Equivalente a %m/%d/%y. (Puaj, solo para americanos. Los americanos deben tener en cuenta que en otros países %d/%m/%y es bastante común. Esto significa que en un contexto internacional este formato es ambiguo y no debe usarse.) (SU)
%e
Como %d, el día del mes como un número decimal, pero un cero inicial se reemplaza por un espacio. (SU) (Calculado a partir de tm_mday.)
%E
Modificador: usar formato alternativo ("basado en era"); ver abajo. (SU)
%F
Equivalente a %Y-%m-%d (el formato de fecha ISO 8601). (C99)
%G
El año basado en semanas ISO 8601 (ver NOTAS) con el siglo como un número decimal. El año de 4 dígitos correspondiente al número de semana ISO (ver %V). Esto tiene el mismo formato y valor que %Y, excepto que si el número de semana ISO pertenece al año anterior o siguiente, se usa ese año en su lugar. (TZ) (Calculado a partir de tm_year, tm_yday y tm_wday.)
%g
Como %G, pero sin el siglo, es decir, con un año de 2 dígitos (00–99). (TZ) (Calculado a partir de tm_year, tm_yday y tm_wday.)
%h
Equivalente a %b. (SU)
%H
La hora como un número decimal usando un reloj de 24 horas (rango 00 a 23). (Calculado a partir de tm_hour.)
%I
La hora como un número decimal usando un reloj de 12 horas (rango 01 a 12). (Calculado a partir de tm_hour.)
%j
El día del año como un número decimal (rango 001 a 366). (Calculado a partir de tm_yday.)
%k
La hora (reloj de 24 horas) como un número decimal (rango 0 a 23); los dígitos individuales van precedidos por un espacio. (Ver también %H.) (Calculado a partir de tm_hour.) (TZ)
%l
La hora (reloj de 12 horas) como un número decimal (rango 1 a 12); los dígitos individuales van precedidos por un espacio. (Ver también %I.) (Calculado a partir de tm_hour.) (TZ)
%m
El mes como un número decimal (rango 01 a 12). (Calculado a partir de tm_mon.)
%M
El minuto como un número decimal (rango 00 a 59). (Calculado a partir de tm_min.)
%n
Un carácter de nueva línea. (SU)
%O
Modificador: usar símbolos numéricos alternativos; ver abajo. (SU)
%p
Ya sea "AM" o "PM" según el valor de hora dado, o las cadenas correspondientes a la configuración regional actual. Las doce del mediodía se tratan como "PM" y la medianoche como "AM". (Calculado a partir de tm_hour.) (Las representaciones de cadena específicas utilizadas para "AM" y "PM" en la configuración regional actual se pueden obtener llamando a nl_langinfo(3) con AM_STR y PM_STR, respectivamente.)
%P
Como %p pero en minúsculas: "am" o "pm" o una cadena correspondiente a la configuración regional actual. (Calculado a partir de tm_hour.) (GNU)
%r
La hora en notación a.m. o p.m. (SU) (El formato específico utilizado en la configuración regional actual se puede obtener llamando a nl_langinfo(3) con T_FMT_AMPM como argumento.) (En la configuración regional POSIX, esto es equivalente a %I:%M:%S %p.)
%R
La hora en notación de 24 horas (%H:%M). (SU) Para una versión que incluya los segundos, ver %T abajo.
%s
El número de segundos transcurridos desde la Época, 1970-01-01 00:00:00 +0000 (UTC). (TZ) (Calculado a partir de mktime(tm).)
%S
El segundo como un número decimal (rango 00 a 60). (El rango es hasta 60 para permitir segundos intercalares ocasionales.) (Calculado a partir de tm_sec.)
%t
Un carácter de tabulación. (SU)
%T
La hora en notación de 24 horas (%H:%M:%S). (SU)
%u
El día de la semana como un decimal, rango 1 a 7, siendo el lunes 1. Ver también %w. (Calculado a partir de tm_wday.) (SU)
%U
El número de semana del año actual como un número decimal, rango 00 a 53, comenzando con el primer domingo como el primer día de la semana 01. Ver también %V y %W. (Calculado a partir de tm_yday y tm_wday.)
%V
El número de semana ISO 8601 (ver NOTAS) del año actual como un número decimal, rango 01 a 53, donde la semana 1 es la primera semana que tiene al menos 4 días en el año nuevo. Ver también %U y %W. (Calculado a partir de tm_year, tm_yday y tm_wday.) (SU)
%w
El día de la semana como un decimal, rango 0 a 6, siendo el domingo 0. Ver también %u. (Calculado a partir de tm_wday.)
%W

Algunas especificaciones de conversión pueden modificarse anteponiendo al carácter especificador de conversión el modificador E u O para indicar que se debe usar un formato alternativo. Si el formato o la especificación alternativa no existen para la configuración regional actual, el comportamiento será como si se hubiera utilizado la especificación de conversión no modificada. (SU) La Especificación Única de Unix menciona %Ec, %EC, %Ex, %EX, %Ey, %EY, %Od, %Oe, %OH, %OI, %Om, %OM, %OS, %Ou, %OU, %OV, %Ow, %OW, %Oy, donde el efecto del modificador O es usar símbolos numéricos alternativos (por ejemplo, números romanos), y el del modificador E es usar una representación alternativa dependiente de la configuración regional. Las reglas que rigen la representación de fechas con el modificador E se pueden obtener proporcionando ERA como argumento a nl_langinfo(3). Un ejemplo de tales formas alternativas es el esquema de calendario de era japonesa en la configuración regional glibc ja_JP.

strftime_l() es equivalente a strftime(), excepto que utiliza la locale especificada en lugar de la configuración regional actual. El comportamiento no está definido si locale es inválida o LC_GLOBAL_LOCALE.

VALOR DE RETORNO

Siempre que la cadena resultante, incluyendo el byte nulo terminador, no supere los max bytes, strftime() devuelve el número de bytes (excluyendo el byte nulo terminador) colocados en la matriz s. Si la longitud de la cadena resultante (incluyendo el byte nulo terminador) superara los max bytes, entonces strftime() devuelve 0 y el contenido de la matriz no está definido.

Tenga en cuenta que el valor de retorno 0 no indica necesariamente un error. Por ejemplo, en muchas configuraciones regionales, %p produce una cadena vacía. Una cadena format vacía también producirá una cadena vacía.

ENTORNO

Se utilizan las variables de entorno TZ y LC_TIME.

Existen inclusiones estrictas entre el conjunto de conversiones dado en ANSI C (sin marcar), los dados en la Especificación Única de Unix (marcados SU), los dados en el paquete de zonas horarias de Olson (marcados TZ) y los dados en glibc (marcados GNU), excepto que %+ no está soportado en glibc2. Por otro lado, glibc2 tiene varias extensiones más. POSIX.1 solo se refiere a ANSI C; POSIX.2 describe bajo date(1) varias extensiones que también podrían aplicarse a strftime(). La conversión %F está en C99 y POSIX.1-2001.

En SUSv2, el especificador %S permitía un rango de 00 a 61, para permitir la posibilidad teórica de un minuto que incluyera un segundo intercalar doble (nunca ha existido tal minuto).

NOTAS

Fechas de semana ISO 8601

%G, %g y %V producen valores calculados a partir del año basado en semanas definido por el estándar ISO 8601. En este sistema, las semanas comienzan los lunes y se numeran a partir de 01, para la primera semana, hasta 52 o 53, para la última semana. La semana 1 es la primera semana en la que cuatro o más días caen dentro del nuevo año (o, de manera equivalente, la semana 01 es: la primera semana del año que contiene un jueves; o, la semana que tiene el 4 de enero en ella). Cuando tres o menos días de la primera semana calendario del año caen dentro de ese año, el sistema basado en semanas ISO 8601 cuenta esos días como parte de la semana 52 o 53 del año anterior. Por ejemplo, el 1 de enero de 2010 es viernes, lo que significa que solo tres días de esa semana calendario caen en 2010. Por lo tanto, el sistema basado en semanas ISO 8601 considera que estos días forman parte de la semana 53 (%V) del año 2009 (%G); la semana 01 del año ISO 8601 2010 comienza el lunes 4 de enero de 2010. Del mismo modo, los dos primeros días de enero de 2011 se consideran parte de la semana 52 del año 2010.

Notas de glibc

glibc proporciona algunas extensiones para las especificaciones de conversión. (Estas extensiones no están especificadas en POSIX.1-2001, pero algunos otros sistemas proporcionan características similares). Entre el carácter '%' y el carácter especificador de conversión, se puede especificar una bandera y un ancho de campo opcionales. (Estos preceden a los modificadores E u O, si están presentes.)

Los siguientes caracteres de bandera están permitidos:

_
(guion bajo) Rellena una cadena numérica resultante con espacios.
-
(guion) No rellenes una cadena numérica resultante.
0
Rellena una cadena numérica resultante con ceros incluso si el carácter especificador de conversión utiliza relleno con espacios por defecto.
^
Convierte los caracteres alfabéticos en la cadena resultante a mayúsculas.
#
Intercambia la capitalización de la cadena resultante. (Esta bandera solo funciona con ciertos caracteres especificadores de conversión, y de estos, solo es realmente útil con %Z.)

Un especificador de ancho decimal opcional puede seguir a la (posiblemente ausente) bandera. Si el tamaño natural del campo es menor que este ancho, la cadena resultante se rellena (a la izquierda) hasta el ancho especificado.

ERRORES

Si la cadena de salida superara los max bytes, errno no se establece. Esto hace imposible distinguir este caso de error de los casos en los que la cadena format produce legítimamente una cadena de salida de longitud cero. POSIX.1-2001 no especifica ninguna configuración de errno para strftime().

Algunas versiones defectuosas de gcc(1) se quejan del uso de %c: warning: `%c' yields only last 2 digits of year in some locales. Por supuesto, se anima a los programadores a usar %c, ya que proporciona la representación de fecha y hora preferida. Uno se encuentra con todo tipo de extrañas ofuscaciones para eludir este problema de gcc(1). Una relativamente limpia es añadir una función intermedia


size_t
my_strftime(char *s, size_t max, const char *fmt,
            const struct tm *tm)
{
    return strftime(s, max, fmt, tm);
}

Hoy en día, gcc(1) proporciona la opción -Wno-format-y2k para evitar la advertencia, por lo que la solución alternativa anterior ya no es necesaria.
