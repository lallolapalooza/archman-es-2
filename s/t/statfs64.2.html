statfs(2) Manual de llamadas al sistema statfs(2)

NOMBRE

statfs, fstatfs - obtener estadísticas del sistema de archivos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/vfs.h>    /* o <sys/statfs.h> */
int statfs(const char *path, struct statfs *buf);
int fstatfs(int fd, struct statfs *buf);

A menos que necesite el campo f_type, debería usar la interfaz estándar statvfs(3) en su lugar.

DESCRIPCIÓN

La llamada al sistema statfs() devuelve información sobre un sistema de archivos montado. path es la ruta de cualquier archivo dentro del sistema de archivos montado. buf es un puntero a una estructura statfs definida aproximadamente de la siguiente manera:


struct statfs {
    __fsword_t f_type;    /* Tipo de sistema de archivos (ver abajo) */
    __fsword_t f_bsize;   /* Tamaño de bloque de transferencia óptimo */
    fsblkcnt_t f_blocks;  /* Bloques de datos totales en el sistema de archivos */
    fsblkcnt_t f_bfree;   /* Bloques libres en el sistema de archivos */
    fsblkcnt_t f_bavail;  /* Bloques libres disponibles para
                             usuario no privilegiado */
    fsfilcnt_t f_files;   /* Inodos totales en el sistema de archivos */
    fsfilcnt_t f_ffree;   /* Inodos libres en el sistema de archivos */
    fsid_t     f_fsid;    /* ID del sistema de archivos */
    __fsword_t f_namelen; /* Longitud máxima de nombres de archivo */
    __fsword_t f_frsize;  /* Tamaño de fragmento (desde Linux 2.6) */
    __fsword_t f_flags;   /* Opciones de montaje del sistema de archivos
                             (desde Linux 2.6.36) */
    __fsword_t f_spare[xxx];
                    /* Bytes de relleno reservados para uso futuro */
};

La mayoría de estas constantes MAGIC están definidas en /usr/include/linux/magic.h y algunas están codificadas en fuentes del kernel.

El campo f_flags es una máscara de bits que indica las opciones de montaje para el sistema de archivos. Contiene cero o más de los siguientes bits:

ST_MANDLOCK
El bloqueo obligatorio está permitido en el sistema de archivos (ver fcntl(2)).
ST_NOATIME
No actualizar tiempos de acceso; ver mount(2).
ST_NODEV
Denegar el acceso a archivos especiales de dispositivo en este sistema de archivos.
ST_NODIRATIME
No actualizar tiempos de acceso de directorios; ver mount(2).
ST_NOEXEC
La ejecución de programas está prohibida en este sistema de archivos.
ST_NOSUID
Los bits set-user-ID y set-group-ID son ignorados por exec(3) para archivos ejecutables en este sistema de archivos.
ST_RDONLY
Este sistema de archivos está montado como solo lectura.
ST_RELATIME
Actualizar atime relativo a mtime/ctime; ver mount(2).
ST_SYNCHRONOUS
Las escrituras se sincronizan con el sistema de archivos inmediatamente (ver la descripción de O_SYNC en open(2)).
ST_NOSYMFOLLOW (desde Linux 5.10)
Los enlaces simbólicos no se siguen al resolver rutas; ver mount(2).

Nadie sabe qué se supone que contiene f_fsid (pero ver abajo).

Los campos que no están definidos para un sistema de archivos particular se establecen a 0.

fstatfs() devuelve la misma información sobre un archivo abierto referenciado por el descriptor fd.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EACCES
(statfs()) Se niega el permiso de búsqueda para un componente del prefijo de ruta de path. (Ver también path_resolution(7).)
EBADF
(fstatfs()) fd no es un descriptor de archivo válido y abierto.
EFAULT
buf o path apuntan a una dirección inválida.
EINTR
La llamada fue interrumpida por una señal; ver signal(7).
EIO
Ocurrió un error de E/S al leer del sistema de archivos.
ELOOP
(statfs()) Se encontraron demasiados enlaces simbólicos al traducir path.
ENAMETOOLONG
(statfs()) path es demasiado largo.
ENOENT
(statfs()) El archivo al que se refiere path no existe.
ENOMEM
No había suficiente memoria del kernel disponible.

ERRORES

ENOSYS
El sistema de archivos no soporta esta llamada.
ENOTDIR
(statfs()) Un componente del prefijo de la ruta de path no es un directorio.
EOVERFLOW
Algunos valores eran demasiado grandes para ser representados en la estructura devuelta.

VERSIONES

El campo f_fsid

Solaris, Irix y POSIX tienen una llamada al sistema statvfs(2) que devuelve una struct statvfs (definida en <sys/statvfs.h>) que contiene un unsigned long f_fsid. Linux, SunOS, HP-UX, 4.4BSD tienen una llamada al sistema statfs() que devuelve una struct statfs (definida en <sys/vfs.h>) que contiene un fsid_t f_fsid, donde fsid_t se define como struct { int val[2]; }. Lo mismo ocurre con FreeBSD, excepto que utiliza el archivo de inclusión <sys/mount.h>.

La idea general es que f_fsid contiene información aleatoria tal que el par (f_fsid,ino) determina de forma única un archivo. Algunos sistemas operativos utilizan (una variación de) el número de dispositivo, o el número de dispositivo combinado con el tipo de sistema de archivos. Varios sistemas operativos restringen la entrega del campo f_fsid solo al superusuario (y lo ponen a cero para usuarios no privilegiados), porque este campo se utiliza en el manejador de archivos del sistema de archivos cuando se exporta por NFS, y su entrega es un problema de seguridad.

En algunos sistemas operativos, el fsid puede utilizarse como segundo argumento para la llamada al sistema sysfs(2).

ESTANDARES

Linux.

HISTORIA

El statfs() de Linux se inspiró en el de 4.4BSD (pero no utilizan la misma estructura).

Las llamadas originales al sistema statfs() y fstatfs() de Linux no fueron diseñadas teniendo en cuenta tamaños de archivo extremadamente grandes. Posteriormente, Linux 2.6 añadió nuevas llamadas al sistema statfs64() y fstatfs64() que emplean una nueva estructura, statfs64. La nueva estructura contiene los mismos campos que la estructura statfs original, pero los tamaños de varios campos se incrementan para acomodar tamaños de archivo grandes. Las funciones de envoltorio statfs() y fstatfs() de glibc manejan transparentemente las diferencias del kernel.

LSB ha desaprobado las llamadas a la biblioteca statfs() y fstatfs() y nos indica que usemos statvfs(3) y fstatvfs(3) en su lugar.

NOTAS

El tipo __fsword_t utilizado para varios campos en la definición de la estructura statfs es un tipo interno de glibc, no destinado al uso público. Esto deja al programador en una especie de dilema al intentar copiar o comparar estos campos con variables locales en un programa. El uso de unsigned int para tales variables es suficiente en la mayoría de los sistemas.

Algunos sistemas solo tienen <sys/vfs.h>, otros sistemas también tienen <sys/statfs.h>, donde el primero incluye el segundo. Por lo tanto, parece que incluir el primero es la mejor opción.

ERRORES GRAVES

Desde Linux 2.6.38 hasta Linux 3.1 inclusive, fstatfs() fallaba con el error ENOSYS para descriptores de archivo creados por pipe(2).

VER TAMBIÉN

stat(2), statvfs(3), path_resolution(7)
