strict(3perl) Guía de referencia del programador de Perl strict(3perl)

NOMBRE

strict - Pragma de Perl para restringir construcciones inseguras

SINOPSIS

use strict;
use strict "vars";
use strict "refs";
use strict "subs";
use strict;
no strict "vars";

DESCRIPCIÓN

El pragma "strict" deshabilita ciertas expresiones de Perl que podrían comportarse de forma inesperada o ser difíciles de depurar, convirtiéndolas en errores. El efecto de este pragma se limita al archivo actual o al bloque de alcance.

Si no se proporciona una lista de importación, se asumen todas las restricciones posibles. (Este es el modo más seguro para operar, pero a veces es demasiado estricto para la programación casual.) Actualmente, hay tres cosas posibles sobre las que ser estricto: "subs", "vars" y "refs".

"strict refs"
Esto genera un error en tiempo de ejecución si usas referencias simbólicas (ver perlref). 
use strict 'refs';
$ref = \$foo;
print $$ref;        # ok
$ref = "foo";
print $$ref;        # error en tiempo de ejecución; normalmente ok
$file = "STDOUT";
print $file "Hi!";  # error; nota: sin coma después de $file

Hay una excepción a esta regla:

$bar = \&{'foo'};
&$bar;

está permitido para que "goto &$AUTOLOAD" no falle bajo la rigurosidad.

"strict vars"
Esto genera un error en tiempo de compilación si accedes a una variable que no fue declarada explícitamente (usando cualquiera de "my", "our", "state", o "use vars") ni está completamente calificada. (Como esto es para evitar problemas de suicidio de variables y problemas sutiles de alcance dinámico, una variable meramente "local" no es suficiente.) Ver "my" en perlfunc, "our" en perlfunc, "state" en perlfunc, "local" en perlfunc, y vars. 
use strict 'vars';
$X::foo = 1;         # ok, completamente calificada
my $foo = 10;        # ok, variable my()
local $baz = 9;      # falla, $baz no declarado antes
package Cinna;
our $bar;                   # Declara $bar en el paquete actual
$bar = 'HgS';               # ok, global declarado vía pragma

El local() generó un error en tiempo de compilación porque simplemente tocaste un nombre global sin calificarlo completamente.

Debido a su uso especial por parte de sort(), las variables $a y $b están exentas de esta verificación.

"strict subs"
Esto deshabilita la optimización de poesía, generando un error en tiempo de compilación si intentas usar un identificador de palabra desnuda que no sea una subrutina, a menos que sea un identificador simple (sin dos puntos) y que aparezca entre llaves, en el lado izquierdo del símbolo "=>", o tenga aplicado el operador unario menos. 
use strict 'subs';
$SIG{PIPE} = Plumber;   # falla
$SIG{PIPE} = "Plumber"; # bien: la cadena entre comillas siempre es ok
$SIG{PIPE} = \&Plumber; # forma preferida

Ver "Pragmatic Modules" en perlmodlib.

HISTORIA

"strict 'subs'", con Perl 5.6.1, permitía erróneamente usar un identificador compuesto sin comillas (por ejemplo, "Foo::Bar") como clave de hash (antes de "=>" o dentro de llaves), pero sin forzarlo siempre a una cadena literal.

A partir de Perl 5.8.1, strict es estricto con sus restricciones: si se usan restricciones desconocidas, el pragma strict abortará con

Unknown 'strict' tag(s) '...'

A partir de la versión 1.04 (Perl 5.10), strict verifica que se use como "strict" para evitar la temida trampa de Strict en sistemas de archivos no sensibles a mayúsculas y minúsculas.

A partir de Perl 5.12, el uso de "use VERSION" (donde VERSION >= 5.11.0) ahora habilita léxicamente las rigurosidades al igual que "use strict" (además de los efectos y características normales de "use VERSION"). En otras palabras, "use v5.011" o superior ahora implica "use strict" automáticamente, como se señala en "Implicit strictures" en perl5120delta y "use VERSION".
