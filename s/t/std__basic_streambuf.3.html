Descripción Detallada

template<typename_CharT,_typename_Traits>

La clase std::basic_streambuf proporciona una interfaz de nivel inferior para la E/S de flujos en C++. Las clases de flujo de C++ (como std::cin, std::cout, etc.) se basan en esta clase para realizar el trabajo real de E/S. La clase basic_streambuf en sí misma no maneja ningún dispositivo de E/S; en su lugar, proporciona una interfaz común para las clases de búfer derivadas que sí lo hacen.

La clase basic_streambuf mantiene dos búferes: un búfer de entrada (get area) y un búfer de salida (put area). Cada búfer tiene tres punteros: un puntero al inicio del búfer, un puntero al final del búfer y un puntero al siguiente carácter a leer o escribir.

Las funciones virtuales protegidas son las que realizan el trabajo real de E/S. Las funciones miembro públicas llaman a estas funciones virtuales para realizar las operaciones de E/S.

Las funciones miembro públicas principales son:

xsgetn
Lee hasta n caracteres del búfer de entrada en el arreglo s.
xsputn
Escribe n caracteres del arreglo s en el búfer de salida.
seekoff
Cambia la posición del flujo. Se usa para la búsqueda.
seekpos
Cambia la posición del flujo a una posición específica. Se usa para la búsqueda.
setbuf
Establece un nuevo búfer para el flujo.
sync
Sincroniza el búfer con el dispositivo de E/S subyacente.

Las funciones virtuales protegidas principales son:

underflow
Lee el siguiente carácter del búfer de entrada. Si el búfer está vacío, intenta rellenarlo a partir del dispositivo de E/S subyacente.
overflow
Escribe un carácter en el búfer de salida. Si el búfer está lleno, intenta escribir el contenido del búfer en el dispositivo de E/S subyacente.
pbackfail
Intenta devolver un carácter al búfer de entrada. Esto se usa para la funcionalidad "ungetc".
showmanyc
Devuelve el número de caracteres que se pueden leer del búfer de entrada sin bloquear.
uflow
Lee el siguiente carácter del búfer de entrada y avanza el puntero de lectura. Si el búfer está vacío, intenta rellenarlo.

El constructor y el destructor de basic_streambuf se encargan de inicializar y limpiar los punteros del búfer y la localización.

Parámetros de Plantilla

_CharT Tipo de flujo de caracteres.
_Traits Rasgos para el tipo de carácter, por defecto es char_traits<_CharT>.

Esta es una clase base. Los buffers de flujo derivados controlan cada uno un par de secuencias de caracteres: una para entrada y otra para salida.

La sección [27.5.1] del estándar describe los requisitos y el comportamiento de las clases de buffer de flujo. Esa sección (tres párrafos) se reproduce aquí, por simplicidad y precisión.

1.
Los buffers de flujo pueden imponer varias restricciones a las secuencias que controlan. Algunas restricciones son:
•
La secuencia de entrada controlada puede no ser legible.
•
La secuencia de salida controlada puede no ser escribible.
•
Las secuencias controladas pueden asociarse con el contenido de otras representaciones de secuencias de caracteres, como archivos externos.
•
Las secuencias controladas pueden admitir operaciones *directamente* desde o hacia secuencias asociadas.
•
Las secuencias controladas pueden imponer limitaciones sobre cómo el programa puede leer caracteres de una secuencia, escribir caracteres en una secuencia, devolver caracteres a una secuencia de entrada o alterar la posición del flujo.
2.
Cada secuencia se caracteriza por tres punteros que, si no son nulos, apuntan todos al mismo objeto de array charT. El objeto de array representa, en cualquier momento, una (sub)secuencia de caracteres de la secuencia. Las operaciones realizadas en una secuencia alteran los valores almacenados en estos punteros, realizan lecturas y escrituras directamente desde o hacia secuencias asociadas, y alteran la *posición del flujo* y el estado de conversión según sea necesario para mantener esta relación de subsecuencia. Los tres punteros son:
•
el *puntero de inicio*, o la dirección del elemento más bajo en el array (llamado *xbeg* aquí);
•
el *puntero siguiente*, o la dirección del siguiente elemento que es un candidato actual para lectura o escritura (llamado *xnext* aquí);
•
el *puntero final*, o la dirección del primer elemento más allá del final del array (llamado *xend* aquí).
3.
Las siguientes restricciones semánticas se aplicarán siempre para cualquier conjunto de tres punteros para una secuencia, utilizando los nombres de puntero dados inmediatamente arriba:
•
Si *xnext* no es un puntero nulo, entonces *xbeg* y *xend* también serán punteros no nulos en el mismo objeto de array charT, como se describió anteriormente; de lo contrario, *xbeg* y *xend* también serán nulos.
•
Si *xnext* no es un puntero nulo y *xnext* < *xend* para una secuencia de salida, entonces hay una *posición de escritura* disponible. En este caso, *xnext* será asignable como el siguiente elemento a escribir (para poner, o para almacenar un valor de carácter, en la secuencia).
•
Si *xnext* no es un puntero nulo y *xbeg* < *xnext* para una secuencia de entrada, entonces hay una *posición de devolución* disponible. En este caso, xnext[-1] tendrá un valor definido y es el siguiente elemento (anterior) para almacenar un carácter que se devuelve a la secuencia de entrada.
•
Si *xnext* no es un puntero nulo y *xnext*< *xend* para una secuencia de entrada, entonces hay una *posición de lectura* disponible. En este caso, *xnext* tendrá un valor definido y es el siguiente elemento a leer (para obtener, o para obtener un valor de carácter, de la secuencia).

template<typename _CharT, typename _Traits> virtual int_type std::basic_streambuf< _CharT, _Traits >::overflow (int_type __c = traits_type::eof()) [inline], [protected], [virtual]

Consume datos del búfer; escribe en la secuencia controlada.

Parámetros

__c Un carácter adicional para consumir.

Devuelve

eof() para indicar fallo, algún otro valor (normalmente __c, o not_eof())

Informalmente, esta función se llama cuando el búfer de salida está lleno (o no existe, ya que el almacenamiento en búfer no tiene por qué realizarse). Si existe un búfer, se *consume*, con *algún efecto* en la secuencia controlada. (Típicamente, el búfer se escribe en la secuencia tal cual). En cualquier caso, el carácter *c* también se escribe, si *__c* no es eof().

Para una definición formal de esta función, consulte un buen texto como Langer & Kreft, o [27.5.2.4.5]/3-7.

Se puede crear un streambuf de salida funcional anulando solo esta función (no se utilizará área de búfer).

Nota

La versión de la clase base no hace nada, devuelve eof().

Parámetros

Informalmente, esta función se llama cuando el búfer de entrada está agotado (o no existe, ya que no es necesario realizar el almacenamiento en búfer). Si existe un búfer, se recarga.
