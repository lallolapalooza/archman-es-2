Unformatted Input Functions
All the unformatted input functions have some common behavior. Each starts by constructing a temporary object of type std::basic_istream::sentry with the second argument (noskipws) set to true. This has several effects, concluding with the setting of a status flag; see the sentry documentation for more.

If the sentry status is good, the function tries to extract whatever data is appropriate for the type of the argument.

The number of characters extracted is stored for later retrieval by gcount().

If an exception is thrown during extraction, ios_base::badbit will be turned on in the stream's error state (without causing an ios_base::failure to be thrown) and the original exception will be rethrown if badbit is set in the exceptions mask.

Funciones Miembro Básicas


Estos operadores sobrecargados se encargan de extraer datos de tipo flotante desde el flujo de entrada y almacenarlos en la variable proporcionada. Cada uno de estos operadores comienza procesando el `sentry` del flujo. Si la extracción tiene éxito, el valor extraído se almacena en el argumento de referencia, y el flujo de entrada se devuelve.

Extracción de punto flotante. Extrae un valor de punto flotante del flujo de entrada. El valor se almacena en el objeto `__f` y el flujo se devuelve.


Funciones de Entrada No Formateada


Todas las funciones de entrada no formateada comparten un comportamiento común. Cada una comienza construyendo un objeto temporal de tipo `std::basic_istream::sentry` con el segundo argumento (`noskipws`) establecido en `true`. Esto tiene varios efectos, que concluyen con el establecimiento de una bandera de estado; consulta la documentación de `sentry` para más detalles.

Si el estado de `sentry` es bueno, la función intenta extraer los datos apropiados para el tipo del argumento.

El número de caracteres extraídos se almacena para su posterior recuperación mediante `gcount()`.

Si se lanza una excepción durante la extracción, `ios_base::badbit` se activará en el estado de error del flujo (sin causar que se lance una `ios_base::failure`) y la excepción original se volverá a lanzar si `badbit` está activado en la máscara de excepciones.
