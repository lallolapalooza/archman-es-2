Descripción Detallada

Interfaz abstracta para proporcionar soporte para archivos definidos por el usuario.

Advertencia

Esto es para usuarios avanzados, de nivel experto. No lo necesitarás a menos que sepas realmente lo que estás haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionaba un medio para montar varios formatos de archivo y directorios físicos en el sistema de archivos nativo. Sin embargo, las aplicaciones se han limitado a los formatos de archivo proporcionados por la biblioteca. Esta interfaz permite a una aplicación proporcionar sus propios tipos de archivo.

Conceptualmente, un PHYSFS_Archiver proporciona entradas de directorio, mientras que PHYSFS_Io proporciona flujos de datos para esas entradas de directorio. El uso más obvio de PHYSFS_Archiver es proporcionar soporte para un tipo de archivo que no proporciona PhysicsFS directamente: quizás algún formato propietario que solo tu aplicación necesite entender.

Internamente, todo el soporte de archivo integrado utiliza esta interfaz, por lo que los mejores ejemplos para construir un PHYSFS_Archiver es el código fuente de PhysicsFS.

Un archivador se añade al sistema con PHYSFS_registerArchiver(), y luego estará disponible para su uso automáticamente con PHYSFS_mount(); si un archivo dado puede ser manejado por tu archivador, se le dará el control según corresponda.

Estos métodos tratan con identificadores de directorio. Tienes una instancia de tu archivador, y esta genera un identificador único y opaco para cada archivo abierto en su método openArchive(). Dado que la vida útil de un Archivador (no de un archivo) es generalmente la vida útil completa del proceso, y se asume que es un singleton, no proporcionamos ningún dato de instancia para el archivador en sí; la aplicación puede usar variables estáticas si es necesario.

Los enlaces simbólicos siempre deben seguirse (excepto en stat()); PhysicsFS utilizará el método stat() para comprobar los enlaces simbólicos y tomar una decisión sobre si continuar llamando a otros métodos basándose en eso.

Los archivadores, cuando sea necesario, deben establecer el estado de error de PhysicsFS con PHYSFS_setErrorCode() antes de devolver. PhysicsFS pasará estos errores a la aplicación sin modificarlos en la mayoría de los casos.

Seguridad de hilos: No se garantiza que las implementaciones de PHYSFS_Archiver sean seguras para hilos por sí mismas. PhysicsFS proporciona seguridad de hilos cuando llama a un archivador dado dentro de la biblioteca, pero no promete que usar el mismo PHYSFS_File desde dos hilos a la vez sea seguro para hilos; como tal, tu PHYSFS_Archiver puede asumir que el bloqueo se maneja por ti siempre que el PHYSFS_Io que devuelves de PHYSFS_open* no cambie ningún estado de tu Archivador, ya que el PHYSFS_Io no estará tan agresivamente protegido.

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Destruye un archivo previamente abierto. Cierra este archivo y libera cualquier memoria asociada, incluido el PHYSFS_Io original y (opaco) en sí mismo, si procede. La implementación puede asumir que no se llamará si todavía hay archivos abiertos de este archivo.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Lista todos los archivos en (dirname). Cada archivo se pasa a (cb), donde se hace una copia si es apropiado, para que puedas desecharla al regresar de la llamada de retorno. (dirname) está en notación independiente de plataforma. Si tienes un error, llama a PHYSFS_SetErrorCode() con el código que parezca apropiado y regresa PHYSFS_ENUM_ERROR. Si la llamada de retorno regresa PHYSFS_ENUM_ERROR, por favor llama a PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) y luego regresa PHYSFS_ENUM_ERROR también. No llames a la llamada de retorno de nuevo bajo ninguna circunstancia. Si la llamada de retorno regresa PHYSFS_ENUM_STOP, deja de enumerar y regresa PHYSFS_ENUM_STOP también. No llames a la llamada de retorno de nuevo bajo ninguna circunstancia. No establezcas un código de error en este caso. Las llamadas de retorno solo deben regresar un valor de PHYSFS_EnumerateCallbackResult. Cualquier otro resultado tiene un comportamiento indefinido. Mientras la llamada de retorno haya regresado PHYSFS_ENUM_OK y tú no hayas experimentado ningún error propio, continúa enumerando hasta que hayas terminado y luego regresa PHYSFS_ENUM_OK sin establecer un código de error.

Advertencia

PHYSFS_enumerate regresa cero o no cero (éxito o fracaso), así que ¡ten en cuenta que este puntero de función regresa valores diferentes!

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Información básica sobre este archivador. Esto se utiliza para identificar tu archivo y se regresa en PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crea un directorio en el archivo. Si la aplicación intenta crear múltiples directorios, PhysicsFS los dividirá en múltiples llamadas antes de pasarlos a tu controlador. Si el archivo es de solo lectura, esta operación debería fallar. Regresa un valor distinto de cero en caso de éxito, cero en caso de fracaso. Este nombre de archivo está en notación independiente de plataforma. En caso de fracaso, llama a PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Abre un archivo en este archivo para añadir. Si el archivo no existe, debe crearse. El offset de escritura debe ser el final del archivo. Si el archivo es de solo lectura, esta operación debería fallar. Este nombre de archivo está en notación independiente de plataforma. Regresa NULL en caso de fracaso y llama a PHYSFS_setErrorCode(). Regresa no NULL en caso de éxito. El puntero devuelto se pasará como parámetro "opaco" para llamadas posteriores al archivo.

void *(* PHYSFS_Archiver::openArchive) (PHYSFS_Io *io, const char *name, int forWrite, int *claimed)

Abre un archivo proporcionado por (io). Aquí es donde se asignan recursos y se analizan los datos al montar un archivo. (name) es un nombre de archivo asociado con (io), pero no necesariamente se mapea a nada, y mucho menos a un nombre de archivo real. Este nombre, posiblemente sin sentido, está en notación dependiente de plataforma. (forWrite) es distinto de cero si se va a usar para el directorio de escritura, y cero si se va a usar para un elemento del sistema de búsqueda.

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque, const char *filename)

Abre un archivo en este archivo para lectura. El archivo debe existir. Este nombre de archivo está en notación independiente de plataforma. Regresa NULL en caso de fracaso y llama a PHYSFS_setErrorCode(). Regresa no NULL en caso de éxito. El puntero devuelto se pasará como parámetro "opaco" para llamadas posteriores al archivo.

PHYSFS_Io *(* PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Abre un archivo en este archivo para escritura. Si el archivo no existe, debe crearse. Si el archivo existe, su contenido debe truncarse. Si el archivo es de solo lectura, esta operación debería fallar. Este nombre de archivo está en notación independiente de plataforma. Regresa NULL en caso de fracaso y llama a PHYSFS_setErrorCode(). Regresa no NULL en caso de éxito. El puntero devuelto se pasará como parámetro "opaco" para llamadas posteriores al archivo.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Elimina un archivo o directorio en el archivo. Si el archivo es un directorio, este solo puede ser eliminado si está vacío. Si el archivo es de solo lectura, esta operación debería fallar. Este nombre de archivo está en notación independiente de plataforma. Regresa un valor distinto de cero en caso de éxito, cero en caso de fracaso. En caso de fracaso, llama a PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtiene metadatos básicos del archivo. El archivo especificado por (fn) se pasa a través de (stat). El nombre del archivo está en notación independiente de plataforma. Regresa un valor distinto de cero en caso de éxito, cero en caso de fracaso. En caso de fracaso, llama a PHYSFS_setErrorCode(). Si el archivo especificado es un enlace simbólico, el indicador PHYSFS_STAT_SYMLINK será establecido en el campo flags. PhysicsFS no sigue enlaces simbólicos en el sistema de archivos subyacente cuando se accede a un archivo.

PHYSFS_uint32 PHYSFS_Archiver::version

Información de compatibilidad binaria. Este campo indica la versión del formato de estructura de datos.

Detailed Description

This structure defines an archive implementation. It's a virtual table of functions that Physicals will call to interact with a specific archive type (like a ZIP file, a tarball, etc.).

int(* PHYSFS_Archiver::claim) (const char *filename, const unsigned char *data, unsigned len, int *claimed)

Called by PHYSFS_mount to see if this archive implementation can handle a given file. The `filename` is the path to the potential archive file. `data` and `len` are the first `len` bytes of the file. `claimed` is an output parameter: if your archiver can handle this file, set `*claimed` to 1. Even if opening the archive fails, if you recognise it, you should still set `*claimed` to 1. This is used to decide whether to stop trying other archivers if you fail to open it. For example, the .zip archiver will set `*claimed` to 1 for something with a .zip file signature, even if it failed because the file was truncated. There's no point trying other archivers in this case, as we've already tried to handle it with the appropriate implementation!

Return NULL on failure and set `*claimed` appropriately. If no archiver opened the archive or set `*claimed`, PHYSFS_mount() will report PHYSFS_ERR_UNSUPPORTED. Otherwise, it will report the error from the archiver that claimed the data through `*claimed`. Return non-NULL on success. The pointer returned will be passed as the "opaque" parameter for later calls.

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque, const char *fnm)

Open a file in this archive for reading. This filename, `fnm`, is in platform-independent notation. Fail if the file does not exist. Returns NULL on failure, and calls PHYSFS_setErrorCode(). Returns non-NULL on success. The pointer returned will be passed as the "opaque" parameter for later file calls.

PHYSFS_Io *(* PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Open a file in this archive for writing. If the file does not exist, it should be created. If it exists, it should be truncated to zero bytes. The writing offset should be the start of the file. If the archive is read-only, this operation should fail. This filename is in platform-independent notation. Returns NULL on failure, and calls PHYSFS_setErrorCode(). Returns non-NULL on success. The pointer returned will be passed as the "opaque" parameter for later file calls.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Delete a file or directory in the archive. This same call is used for both files and directories; there is not a separate rmdir() call. Directories are only meant to be removed if they are empty. If the archive is read-only, this operation should fail.

Return non-zero on success, zero on failure. This filename is in platform-independent notation. On failure, call PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtain basic file metadata. On success, fill in all the fields in (stat), using reasonable defaults for fields that apply to your archive.

Returns non-zero on success, zero on failure. This filename is in platform-independent notation. On failure, call PHYSFS_setErrorCode().

PHYSFS_uint32 PHYSFS_Archiver::version

Binary compatibility information. This must be set to zero at this time. Future versions of this struct will increment this field, so we know what a given implementation supports. We'll presumably keep supporting older versions as we offer new features, though.
