STRERROR(3P) Manual del programador POSIX STRERROR(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

strerror, strerror_l, strerror_r — obtener cadena de mensaje de error

SINOPSIS

#include <string.h>
char *strerror(int errnum);
char *strerror_l(int errnum, locale_t locale);
int strerror_r(int errnum, char *strerrbuf, size_t buflen);

DESCRIPCIÓN

Para strerror(): La funcionalidad descrita en esta página de referencia está alineada con el estándar ISO C. Cualquier conflicto entre los requisitos descritos aquí y el estándar ISO C es no intencional. Este volumen de POSIX.1‐2017 remite al estándar ISO C.

La función strerror() mapeará el número de error en errnum a una cadena de mensaje de error dependiente de la configuración regional y devolverá un puntero a ella. Típicamente, los valores para errnum provienen de errno, pero strerror() mapeará cualquier valor de tipo int a un mensaje.

La aplicación no debe modificar la cadena devuelta. El puntero de cadena devuelto puede invalidarse o el contenido de la cadena puede sobrescribirse por una llamada posterior a strerror(), o por una llamada posterior a strerror_l() en el mismo hilo. El puntero devuelto y el contenido de la cadena también pueden invalidarse si el hilo que llama termina.

La cadena puede sobrescribirse por una llamada posterior a strerror_l() en el mismo hilo.

El contenido de las cadenas de mensajes de error devueltas por strerror() debe determinarse por la configuración de la categoría LC_MESSAGES en la configuración regional actual.

La implementación se comportará como si ninguna función definida en este volumen de POSIX.1‐2017 llamara a strerror().

Las funciones strerror() y strerror_l() no modificarán la configuración de errno si tienen éxito.

Dado que no hay un valor de retorno reservado para indicar un error de strerror(), una aplicación que desee comprobar situaciones de error debe establecer errno a 0, luego llamar a strerror(), luego comprobar errno. De manera similar, dado que se requiere que strerror_l() devuelva una cadena para algunos errores, una aplicación que desee comprobar todas las situaciones de error debe establecer errno a 0, luego llamar a strerror_l(), luego comprobar errno.

La función strerror() no necesita ser segura para hilos.

La función strerror_l() mapeará el número de error en errnum a una cadena de mensaje de error dependiente de la configuración regional en la configuración regional representada por locale y devolverá un puntero a ella.

La función strerror_r() mapeará el número de error en errnum a una cadena de mensaje de error dependiente de la configuración regional y devolverá la cadena en el búfer apuntado por strerrbuf, con longitud buflen.

Si el valor de errnum es un número de error válido, la cadena del mensaje indicará qué error ocurrió; si el valor de errnum es cero, la cadena del mensaje será una cadena vacía o indicará que no ocurrió ningún error; de lo contrario, si estas funciones se completan con éxito, la cadena del mensaje indicará que ocurrió un error desconocido.

El comportamiento no está definido si el argumento locale para strerror_l() es el objeto de configuración regional especial LC_GLOBAL_LOCALE o no es un manejador de objeto de configuración regional válido.

VALOR DE RETORNO

Al completarse, ya sea con éxito o no, strerror() devolverá un puntero a la cadena de mensaje generada. En caso de error, errno puede establecerse, pero no se reserva ningún valor de retorno para indicar un error.

Al completarse con éxito, strerror_l() devolverá un puntero a la cadena de mensaje generada. Si errnum no es un número de error válido, errno puede establecerse en [EINVAL], pero aun así se devolverá un puntero a una cadena de mensaje. Si ocurre cualquier otro error, errno se establecerá para indicar el error y se devolverá un puntero nulo.

Al completarse con éxito, strerror_r() devolverá 0. De lo contrario, se devolverá un número de error para indicar el error.

ERRORES

Estas funciones pueden fallar si:

EINVAL
El valor de errnum no es un número de error válido ni cero.

La función strerror_r() puede fallar si:

ERANGE
Se proporcionó almacenamiento insuficiente a través de strerrbuf y buflen para contener la cadena de mensaje generada.

USO DE LA APLICACIÓN

Históricamente, en algunas implementaciones, las llamadas a perror() sobrescribían la cadena a la que apuntaba el puntero devuelto por strerror(). Dichas implementaciones no se ajustaban al estándar ISO C; sin embargo, los desarrolladores de aplicaciones deben ser conscientes de este comportamiento si desean que sus aplicaciones sean portables a dichas implementaciones.

FUNDAMENTO

La función strerror_l() debe ser segura para hilos, eliminando así la necesidad de un equivalente a la función strerror_r().

Versiones anteriores de este estándar no requerían explícitamente que las cadenas de mensajes de error devueltas por strerror() y strerror_r() proporcionaran información sobre el error. Esta versión del estándar requiere un mensaje significativo para cualquier finalización exitosa.

Dado que no hay un valor de retorno reservado para indicar un error de strerror(), pero todas las llamadas (exitosas o no) deben devolver un puntero a una cadena de mensaje, en caso de error strerror() puede devolver un puntero a una cadena vacía o un puntero a una cadena significativa que pueda imprimirse.

Tenga en cuenta que la condición de error [EINVAL] es un error que puede fallar. Si se suministra un número de error no válido como valor de errnum, las aplicaciones deben estar preparadas para manejar cualquiera de los siguientes:

1.
Error (sin mensaje significativo): errno se establece en [EINVAL], el valor de retorno es un puntero a una cadena vacía.
2.
Finalización exitosa: errno no cambia y el valor de retorno apunta a una cadena como "unknownerror" o "errornumberxxx" (donde xxx es el valor de errnum).
3.
Combinación de #1 y #2: errno se establece en [EINVAL] y el valor de retorno apunta a una cadena como "unknownerror" o "errornumberxxx" (donde xxx es el valor de errnum). Dado que las aplicaciones utilizan frecuentemente el valor de retorno de strerror() como argumento para funciones como fprintf() (sin comprobar el valor de retorno) y dado que las aplicaciones no tienen forma de analizar una cadena de mensaje de error para determinar si errnum representa un número de error válido, se anima a las implementaciones a implementar el #3. Del mismo modo, se anima a las implementaciones a que strerror_r() devuelva [EINVAL] y coloque una cadena como "unknownerror" o "errornumberxxx" en el búfer apuntado por strerrbuf cuando el valor de errnum no es un número de error válido.

Algunas aplicaciones dependen de poder establecer errno a 0 antes de llamar a una función sin valor reservado para indicar un error, y luego llamar a strerror(errno) después para detectar si ocurrió un error (porque errno cambió) o para indicar éxito (porque errno permaneció cero). Este patrón de uso requiere que strerror(0) tenga éxito con resultados útiles. Versiones anteriores del estándar no especificaban el comportamiento cuando errnum es cero.
