NAME

std::allocator_traits - Traits for allocators

SYNOPSIS

template<typename _Alloc>
struct std::allocator_traits
{
  typedef typename _Alloc::allocator_type            allocator_type;
  typedef typename _Alloc::value_type                   value_type;
  typedef typename _Alloc::size_type                    size_type;
  typedef typename _Alloc::difference_type              difference_type;
  typedef typename _Alloc::pointer                      pointer;
  typedef typename _Alloc::const_pointer                const_pointer;
  typedef typename _Alloc::reference                  reference;
  typedef typename _Alloc::const_reference              const_reference;
  typedef typename _Alloc::rebind_allocator
    typename _Alloc::template rebind<U>::other>::other allocator_type;
  typedef typename _Alloc::template rebind<U>::other other;

  static constexpr void allocate (_Alloc& __a, size_type __n);
  static constexpr pointer allocate (_Alloc& __a, size_type __n, const_void_pointer __hint);
  template<typename _Tp, typename... _Args>
    static constexpr void construct (_Alloc& __a, _Tp * __p, _Args &&... __args);
  template<typename _Tp>
    static constexpr void destroy (_Alloc& __a, _Tp * __p);
  static constexpr void deallocate (_Alloc& __a, pointer __p, size_type __n);
  static constexpr size_type max_size (const _Alloc& __a) noexcept;
  static constexpr _Alloc select_on_container_copy_construction (const _Alloc& __rhs);
};

Detailed Description

The std::allocator_traits class template provides a uniform interface to the properties and functionalities of allocator types. It is used by standard library containers to interact with allocators in a way that is independent of the specific allocator type. This allows for custom allocators to be used with standard containers as long as they adhere to the allocator requirements.

The primary purpose of allocator_traits is to provide default implementations for certain allocator operations, such as construction and destruction of objects, even if the allocator itself does not explicitly define them. It also provides access to allocator-specific properties like value_type, size_type, and max_size.

For a custom allocator to be fully compatible with std::allocator_traits, it should provide the following members (some of which have defaults provided by std::allocator_traits):

  • value_type: The type of the objects to be allocated.
  • size_type: An unsigned integral type that can represent the size of the largest object in the allocation model.
  • difference_type: A signed integral type that can represent the difference between any two pointers in the allocation model.
  • pointer: A pointer type to an object of value_type.
  • const_pointer: A pointer type to a constant object of value_type.
  • reference: A reference type to an object of value_type.
  • const_reference: A reference type to a constant object of value_type.
  • rebind<U>::other: A type that is the allocator type for objects of type U. This is used by containers to obtain allocators for internal types.
  • allocate(size_type n): Allocates storage for n objects of value_type.
  • deallocate(pointer p, size_type n): Deallocates storage pointed to by p, which was previously allocated for n objects.
  • construct(pointer p, Args... args): Constructs an object of value_type at the location pointed to by p using the provided arguments.
  • destroy(pointer p): Destroys the object of value_type at the location pointed to by p.
  • max_size(): Returns the maximum number of objects that can be allocated.
  • select_on_container_copy_construction(): Returns an allocator instance to be used by a container when it is copied.
