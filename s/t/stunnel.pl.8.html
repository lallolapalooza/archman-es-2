NOMBRE

stunnel - túnel universal de protocolo TLS

SINTAXIS

Unix:
stunnel [ARCHIVO] | -fd N | -help | -version | -sockets | -options
WIN32:
stunnel [ [ -install | -uninstall | -start | -stop |
-reload | -reopen | -exit ] [-quiet] [ARCHIVO] ] |
-help | -version | -sockets | -options

DESCRIPCIÓN

stunnel está diseñado para envolver conexiones de protocolo TLS entre clientes remotos y servidores locales o remotos. Un servidor local es una aplicación diseñada para ser ejecutada con inetd. Stunnel permite establecer fácilmente la comunicación de servidores que no poseen funcionalidad TLS a través de canales TLS seguros.

stunnel permite añadir funcionalidad TLS a demonios inetd comunes, como pop3 o imap, a demonios autónomos, como nntp, smtp o http, e incluso tunelizar ppp a través de sockets de red sin modificaciones en el código fuente.

OPCIONES

ARCHIVO
usa el archivo de configuración especificado
-fd N (solo Unix)
carga la configuración desde el descriptor de archivo especificado
-help
imprime la lista de opciones soportadas
-version
imprime la versión del programa y los valores predeterminados de los parámetros
-sockets
imprime las opciones predeterminadas de los sockets
-options
imprime las opciones TLS soportadas
-install (solo Windows NT o superior)
instala el servicio NT
-uninstall (solo Windows NT o superior)
desinstala el servicio NT
-start (solo Windows NT o superior)
inicia el servicio NT
-stop (solo Windows NT o superior)
detiene el servicio NT
-reload (solo Windows NT o superior)
recarga el archivo de configuración del servicio NT en ejecución
-reopen (solo Windows NT o superior)
vuelve a abrir el log del servicio NT en ejecución
-exit (solo Win32)
detiene el programa en ejecución
-quiet (solo Win32)
no muestra ventanas de mensajes

ARCHIVO DE CONFIGURACIÓN

Una línea en el archivo de configuración puede ser:

  • vacía (ignorada)
  • un comentario que empiece con el carácter ';' (ignorado)
  • un par de 'nombre_opción = valor_opción'
  • un texto '[nombre_servicio]' que indica el inicio de una definición de servicio

El parámetro de dirección puede ser:

  • un número de puerto
  • un par de dirección (IPv4, IPv6 o nombre de dominio) y número de puerto, separados por dos puntos
  • una ruta a un socket de Unix (solo Unix)

OPCIONES GLOBALES

chroot = DIRECTORIO (solo Unix)
directorio raíz del sistema de archivos

La opción especifica el directorio en el que el proceso stunnel será "encerrado" inmediatamente después de su inicialización, y antes de que comience a aceptar conexiones. Las rutas especificadas en las opciones CApath, CRLpath, pid y exec deben estar ubicadas dentro del directorio especificado en la opción chroot y especificadas con respecto a dicho directorio.

Algunas funciones del sistema operativo pueden requerir archivos adicionales ubicados en el directorio especificado por chroot:

  • la resolución diferida de nombres DNS típicamente requiere /etc/nsswitch.conf y /etc/resolv.conf
  • la ubicación de la zona horaria en los logs requiere el archivo /etc/timezone
  • algunos otros archivos pueden requerir archivos de dispositivo, como /dev/zero o /dev/null
compression = deflate | zlib
selección del algoritmo de compresión de datos transmitidos

predeterminado: sin compresión

El algoritmo deflate es el método de compresión estándar según RFC 1951.

debug = [SUBSISTEMA].NIVEL
nivel de detalle del registro (logging)

El nivel de registro se puede especificar usando uno de los nombres o números: emerg (0), alert (1), crit (2), err (3), warning (4), notice (5), info (6) o debug (7). Se registran los mensajes con un nivel numéricamente menor o igual al especificado. El nivel predeterminado es notice (5).

Aunque usar debug = debug o debug = 7 proporciona los logs más detallados, su contenido solo es útil para los desarrolladores de stunnel. Utilice este nivel de registro solo si es un desarrollador de stunnel, o si está recopilando información detallada para enviarla al soporte técnico. De lo contrario, intentar analizar el contenido de los logs **será** solo una fuente de confusión adicional.

A menos que se especifique un subsistema, se utilizará el predeterminado: daemon. Los subsistemas no son compatibles con la plataforma Win32.

Se ignora el uso de mayúsculas tanto para el nivel como para el subsistema.

EGD = RUTA_A_EGD (solo Unix)
ruta al socket del demonio Entropy Gathering Daemon

La opción permite especificar la ruta al socket del demonio Entropy Gathering Daemon utilizado para inicializar el generador de números pseudoaleatorios de la biblioteca OpenSSL.

engine = auto | ID_DEL_MOTOR
selección del motor criptográfico

predeterminado: sin uso de motores criptográficos

La sección EJEMPLOS contiene configuraciones de ejemplo que utilizan motores criptográficos.

engineCtrl = COMANDO[:PARÁMETRO]
configuración del motor criptográfico
engineDefault = LISTA_DE_OPERACIONES
lista de operaciones de OpenSSL delegadas al motor actual

El parámetro es una lista de operaciones de OpenSSL separadas por comas que deben ser delegadas al motor criptográfico actual.

Dependiendo del motor específico, las siguientes operaciones pueden estar disponibles: ALL, RSA, DSA, ECDH, ECDSA, DH, RAND, CIPHERS, DIGESTS, PKEY, PKEY_CRYPTO, PKEY_ASN1.

fips = yes | no
modo FIPS 140-2

La opción permite desactivar la entrada en modo FIPS si stunnel fue compilado con soporte para FIPS 140-2.

por defecto: no (desde la versión 5.00)

foreground = yes | quiet | no (solo Unix)
modo principal

El uso de esta opción hace que stunnel no pase a segundo plano.

El parámetro yes adicionalmente hace que los mensajes de diagnóstico se registren en el flujo de error estándar (stderr) además de las salidas definidas mediante las opciones syslog y output.

iconActive = ARCHIVO_CON_ICONO (solo GUI)
icono que se muestra cuando hay conexiones activas al servicio

En Windows, el icono es un archivo .ico que contiene una imagen de 16x16 píxeles.

iconError = ARCHIVO_CON_ICONO (solo GUI)
icono que se muestra si no se cargó correctamente el archivo de configuración

En Windows, el icono es un archivo .ico que contiene una imagen de 16x16 píxeles.

iconIdle = ARCHIVO_CON_ICONO (solo GUI)
icono que se muestra cuando no hay conexiones activas al servicio

En Windows, el icono es un archivo .ico que contiene una imagen de 16x16 píxeles.

log = append | overwrite
manejo de registros

Esta opción permite especificar si los nuevos registros en el archivo (definido en la opción output) se añadirán o se sobrescribirán.

por defecto: append

output = ARCHIVO
archivo al que se añadirán los registros

El uso de esta opción añade los registros al archivo proporcionado.

Para dirigir los mensajes a la salida estándar (por ejemplo, para registrarlos con el programa splogger del paquete daemontools) se puede especificar el dispositivo /dev/stdout como parámetro.

pid = ARCHIVO (solo Unix)
ubicación del archivo con el número de proceso

Si el argumento está vacío, el archivo no se creará.

Si se ha definido un directorio chroot, la ruta a pid se especifica en relación con ese directorio.

provider = PROVIDER_ID
Especifica el identificador del proveedor que se va a utilizar. PROVIDER_ID es un identificador único que apunta a un proveedor de servicios criptográficos específico.

Esta opción requiere la biblioteca OpenSSL en su versión 3.0 o posterior.

providerParameter = PROVIDER_ID:PARAMETER=VALUE
Establece un parámetro específico para el proveedor indicado. PROVIDER_ID identifica al proveedor, PARAMETER es el nombre del parámetro y VALUE es su valor. Esta opción permite adaptar la configuración del proveedor de servicios criptográficos seleccionado.

Esta opción requiere la biblioteca OpenSSL en su versión 3.5 o posterior.

RNDbytes = NUMERO_DE_BYTES
número de bytes para inicializar el generador pseudoaleatorio
RNDfile = ARCHIVO
ruta al archivo que contiene datos aleatorios

La biblioteca OpenSSL utilizará los datos de este archivo para inicializar el generador pseudoaleatorio.

RNDoverwrite = yes | no
sobrescribir el archivo con nuevos valores pseudoaleatorios

por defecto: yes (sobrescribir)

service = SERVICIO (solo Unix)
nombre del servicio

El nombre del servicio proporcionado se utilizará como nombre del servicio para la inicialización de sysloga y para la biblioteca TCP Wrapper en modo inetd. Aunque técnicamente se puede usar esta opción en modo en la sección de servicios, solo es útil en las opciones globales.

por defecto: stunnel

setEnv = VAR_NAME=VALUE
Cambia o añade una variable de entorno para los procesos hijos. Si VAR_NAME ya existe, su valor se actualizará; de lo contrario, se creará una nueva variable. La modificación solo afecta a los procesos hijos iniciados y no influye en el entorno actual.
syslog = yes | no (solo Unix)
activar el registro a través del mecanismo syslog

por defecto: yes (activar)

taskbar = yes | no (solo WIN32)
activar el icono en la esquina inferior derecha de la pantalla

por defecto: yes (activar)

OPCIONES DE SERVICIO

Cada sección de configuración de servicio comienza con su nombre entre corchetes. El nombre del servicio se utiliza para el control de acceso por la biblioteca libwrap (TCP wrappers) y permite distinguir los servicios individuales en los registros.

Si stunnel se va a utilizar en modo inetd, donde un programa separado (generalmente inetd, xinetd o tcpserver) es responsable de aceptar la conexión, lea la sección MODO INETD a continuación.

accept = [HOST:]PORT
escucha conexiones en la dirección y puerto especificados

Si no se ha especificado una dirección, stunnel por defecto escucha en todas las direcciones IPv4 de las interfaces locales.

Para escuchar en todas las direcciones IPv6 use:

accept = :::port
CAengine = ID_CA_EN_ENGINE
carga certificados de Autoridad de Certificación de confianza desde el motor

La opción permite especificar la ubicación del archivo que contiene los certificados utilizados por la opción verifyChain o verifyPeer.

La opción puede ser utilizada múltiples veces en una única sección.

Motores actualmente soportados: pkcs11, cng.

CApath = DIRECTORIO_CA
carga certificados de Autoridad de Certificación de confianza desde un directorio

La opción especifica el directorio donde stunnel buscará los certificados si se ha utilizado la opción verifyChain o verifyPeer. Los archivos de certificados deben tener nombres especiales XXXXXXXX.0, donde XXXXXXXX es un hash criptográfico de la representación DER del nombre del sujeto del certificado.

Esta opción también puede ser utilizada para proporcionar el certificado raíz de CA, que es necesario para la verificación correcta de OCSP stapling en modo servidor.

La función de hash se cambió en OpenSSL 1.0.0. Es necesario ejecutar c_rehash al cambiar de OpenSSL 0.x.x a 1.x.x.

Si se ha definido un directorio chroot, la ruta a CApath se especifica en relación con ese directorio.

CAfile = ARCHIVO_CA
carga certificados de Autoridad de Certificación de confianza desde un archivo

La opción permite especificar la ubicación del archivo que contiene los certificados utilizados por la opción verifyChain o verifyPeer.

Esta opción también puede ser utilizada para proporcionar el certificado raíz de CA, que es necesario para la verificación correcta de OCSP stapling en modo servidor.

CAstore = URI_CA
carga certificados de Autoridad de Certificación de confianza desde un recurso indicado por URI

La opción permite cargar certificados de CA desde un almacén externo compatible con el mecanismo OSSL_STORE, como un módulo PKCS#11 (por ejemplo, un token de hardware), un almacén de certificados del sistema o un recurso de red.

La opción se puede utilizar independientemente de CAfile y CAdir, sirve de manera análoga para la validación de la cadena de certificados utilizando las opciones verifyChain o verifyPeer, así como para la verificación de OCSP stapling en el lado del servidor.

Esta opción requiere la biblioteca OpenSSL en su versión 3.0 o posterior.

cert = ARCHIVO_CERT | URI
archivo con la cadena de certificados

La opción especifica la ubicación del archivo que contiene los certificados utilizados por el programa stunnel para autenticarse ante la otra parte de la conexión. El archivo debe contener la cadena completa de certificados comenzando desde el certificado del cliente/servidor y terminando

Opcje Konfiguracyjne Plik konfiguracyjny programu stunnel zawiera sekcje, z których każda definiuje jedną usługę. Każda sekcja zaczyna si&emac; od słowa kluczowego service, po którym nast&emac;puje nazwa usługi, np. service MyService. Nazwa usługi jest używana do wyświetlania komunikatów w logach. Dostępne są również opcje globalne, które nie należą do żadnej konkretnej sekcji usługi. Opcje Konfiguracji Usługi
accept = [HOST:]PORT
połącz si&emac; z lokalnym portem nasłuchującym Opcja ta jest używana do określenia lokalnego adresu i portu, na którym usługa będzie nasłuchiwać na przychodzące połączenia. Jeśli nie zostanie podany adres hosta, usługa będzie nasłuchiwać na wszystkich dostępnych interfejsach sieciowych. Opcja ta może być użyta wielokrotnie w jednej sekcji, aby usługa nasłuchiwała na wielu adresach i portach. Przykład: accept = 127.0.0.1:8080 accept = 443
CAfile = PLIK
plik z certyfikatami CA Opcja ta określa plik zawierający certyfikaty głównego urzędu certyfikacji (CA) lub samopodpisany certyfikat głównego CA. Plik ten jest używany do weryfikacji certyfikatu serwera lub klienta. Obsługiwane formaty to PEM i P12.
CApath = KATALOG
katalog z certyfikatami CA Opcja ta określa katalog zawierający certyfikaty głównego urzędu certyfikacji (CA) lub samopodpisany certyfikat głównego CA. Katalog ten jest używany do weryfikacji certyfikatu serwera lub klienta. Pliki w tym katalogu powinny być odpowiednio zaindeksowane. Obsługiwane formaty to PEM i P12.
cert = PLIK
plik certyfikatu Opcja ta określa plik zawierający certyfikat SSL/TLS. Plik ten może zawierać klucz prywatny lub być używany w połączeniu z opcją key. Certyfikat jest konieczny do użycia programu w trybie serwera. W trybie klienta jest opcjonalny. Pliki w formacie PEM lub P12 są obsługiwane. Opcja cert może być podana wielokrotnie. Pierwszy napotkany certyfikat zostanie użyty jako certyfikat serwera lub klienta, kolejne będą traktowane jako certyfikaty pośrednie łańcucha. Ta funkcjonalność wymaga biblioteki OpenSSL w wersji 1.0.2 lub nowszej. Jeśli używany jest silnik kryptograficzny lub provider, opcja cert pozwala wybrać identyfikator (PKCS#11 URI) używanego certyfikatu. Uwaga: provider wymaga OpenSSL 3.0 lub nowszego.
checkEmail = EMAIL
adres email podmiotu przedstawionego certyfikatu Pojedyncza sekcja może zawierać wiele wystąpień opcji checkEmail. Certyfikaty są akceptowane, jeśli sekcja nie weryfikuje podmiotu certyfikatu, albo adres email przedstawionego certyfikatu pasuje do jednego z adresów email określonych za pomocą checkEmail. Opcja ta wymaga biblioteki OpenSSL w wersji 1.0.2 lub nowszej.
checkHost = NAZWA_SERWERA
nazwa serwera podmiotu przedstawionego certyfikatu Pojedyncza sekcja może zawierać wiele wystąpień opcji checkHost. Certyfikaty są akceptowane, jeśli sekcja nie weryfikuje podmiotu certyfikatu, albo nazwa serwera przedstawionego certyfikatu pasuje do jednej z nazw określonych za pomocą checkHost. Opcja ta wymaga biblioteki OpenSSL w wersji 1.0.2 lub nowszej.
checkIP = IP
adres IP podmiotu przedstawionego certyfikatu Pojedyncza sekcja może zawierać wiele wystąpień opcji checkIP. Certyfikaty są akceptowane, jeśli sekcja nie weryfikuje podmiotu certyfikatu, albo adres IP przedstawionego certyfikatu pasuje do jednego z adresów IP określonych za pomocą checkIP. Opcja ta wymaga biblioteki OpenSSL w wersji 1.0.2 lub nowszej.
ciphers = LISTA_SZYFRóW
lista dozwolonych szyfrów dla protokołów SSLv2, SSLv3, TLSv1, TLSv1.1, TLSv1.2 Ta opcja nie wpł&emac;ywa na listę parametrów kryptograficznych dla protokołu TLSv1.3. Parametrem tej opcji jest lista szyfrów, które będą użyte przy otwieraniu nowych połączeń TLS, np.: DES-CBC3-SHA:IDEA-CBC-MD5.
ciphersuites = LISTA_PARAMETRóW_KRYPTOGRAFICZNYCH
lista dozwolonych parametrów kryptograficznych dla protokołu TLSv1.3 Parametrem tej opcji są listy parametrów kryptograficznych w kolejności ich preferowania. Poczynając od OpenSSL 3.0, opcja ciphersuites ignoruje nieznane szyfry. Opcja ciphersuites jest dostępna poczynając od OpenSSL 1.1.1. domyślnie: TLS_CHACHA20_POLY1305_SHA256: TLS_AES_256_GCM_SHA384: TLS_AES_128_GCM_SHA256
client = yes | no
tryb kliencki (zdalna usługa używa TLS) domyślnie: no (tryb serwerowy)
config = KOMENDA[:PARAMETR]
komenda konfiguracyjna OpenSSL Komenda konfiguracyjna OpenSSL zostaje wykonana z podanym parametrem. Pozwala to na wydawanie komend konfiguracyjnych OpenSSL z pliku konfiguracyjnego stunnel. Dostępne komendy opisane są w podręczniku SSL_CONF_cmd(3ssl). Możliwe jest wyspecyfikowanie wielu opcji OpenSSL przez wielokrotne użycie komendy config. Zamiast wyłączyć config = Curves:list_curves użyj opcji curves w celu ustawienia krzywych eliptycznych. Opcja ta wymaga biblioteki OpenSSL w wersji 1.0.2 lub nowszej.
connect = [HOST:]PORT
połącz si&emac; ze zdalnym serwerem na podany port Jeśli nie został podany adres, stunnel domyślnie łączy si&emac; z lokalnym serwerem. Komenda może być użyta wielokrotnie w pojedynczej sekcji celem zapewnienia wysokiej niezawodności lub rozłożenia ruchu pomiędzy wiele serwerów.
CRLpath = KATALOG_CRL
katalog List Odwołań Certyfikatów (CRL) Opcja określa katalog, w którym stunnel będzie szukał list CRL używanych przez opcje verifyChain i verifyPeer. Pliki z listami CRL muszą posiadać specjalne nazwy XXXXXXXX.r0, gdzie XXXXXXXX jest skrótem listy CRL. Funkcja skrótu została zmieniona OpenSSL 1.0.0. Należy wykonać c_rehash przy zmianie OpenSSL 0.x.x na 1.x.x. Jeśli zdefiniowano katalog chroot, to ścieżka do CRLpath jest określona względem tego katalogu.
CRLfile = PLIK_CRL
plik List Odwołań Certyfikatów (CRL) Opcja pozwala określić położenie pliku zawierającego listy CRL używane przez opcje verifyChain i verifyPeer.
curves = lista
krzywe ECDH oddzielone ':' Wersje OpenSSL starsze niż 1.1.1 pozwalają na użycie tylko jednej krzywej. Listę dostępnych krzywych można uzyskać poleceniem: 
openssl ecparam -list_curves
domyślnie: 
X25519:P-256:X448:P-521:P-384 (poczynając od OpenSSL 1.1.1)
prime256v1 (OpenSSL starszy niż 1.1.1)
logId = TYP
typ identyfikatora połączenia klienta Identyfikator ten pozwala rozróżnić wpisy w logu wygenerowane dla poszczególnych połączeń. Aktualnie wspierane typy:
sequential
Kolejny numer połączenia jest unikalny jedynie w obrębie pojedynczej instancji programu stunnel, ale bardzo krótki. Jest on szczególnie użyteczny przy ręcznej analizie logów.
unique
Ten rodzaj identyfikatora jest globalnie unikalny, ale znacznie dłuższy, niż kolejny numer połączenia. Jest on szczególnie użyteczny przy zautomatyzowanej analizie logów.
thread
Identyfikator wątku systemu operacyjnego nie jest ani unikalny (nawet w obrębie pojedynczej instancji programu stunnel), ani krótki. Jest on szczególnie użyteczny przy diagnozowaniu problemów z oprogramowaniem lub konfiguracją.
process
Identyfikator procesu (PID) może być użyteczny w trybie inetd.

domyślnie: sequential

debug = POZIOM
szczegółowość logowania Poziom logowania można określić przy pomocy jednej z nazw lub liczb: emerg (0), alert (1), crit (2), err (3), warning (4), notice (5), info (6) lub debug (7). Zapisywane są komunikaty o poziomie niższym (numerycznie) lub równym podanemu. Do uzyskania najwyższego poziomu szczegółowości można użyć opcji debug = debug lub debug = 7. Domyślnym poziomem jest notice (5).
delay = yes | no
opóźnij rozwinięcie adresu DNS podanego w opcji connect Opcja jest przydatna przy dynamicznym DNS, albo gdy usługa DNS nie jest dostępna przy starcie programu stunnel (klient VPN, połączenie wdzwaniane). Opóźnione rozwijanie adresu DNS jest włączane automatycznie, jeśli nie powiedzie si&emac; rozwinięcie któregokolwiek z adresów connect dla danej usługi. Opóźnione rozwijanie adresu automatycznie aktywuje failover = prio. domyślnie: no
engineId = NUMER_URZĄDZENIA
wybierz silnik kryptograficzny dla usługi
engineNum = NUMER_URZĄDZENIA
wybierz silnik kryptograficzny dla usługi Urządzenia są numerowane od 1 w górę.

VALOR DE RETORNO

stunnel devuelve cero en caso de éxito, o un valor distinto de cero en caso de error.

SEÑALES

Las siguientes señales pueden utilizarse para controlar el programa en sistemas Unix:

SIGHUP
Recarga el archivo de configuración.

Algunas opciones globales no se recargarán:

  • chroot
  • foreground
  • pid
  • setgid
  • setuid

Si se utiliza la opción 'setuid', stunnel no podrá recargar una configuración que utilice puertos privilegiados (<1024).

Si se utiliza la opción 'chroot', stunnel buscará todos los archivos necesarios (incluyendo el archivo de configuración, certificados, log y archivo pid) dentro del directorio indicado por 'chroot'.

SIGUSR1
Cierra y vuelve a abrir el log. Esta función puede ser utilizada en un script de rotación de logs del programa stunnel.
SIGUSR2
Escribe en el log la lista de conexiones activas.
SIGTERM, SIGQUIT, SIGINT
Termina la ejecución del programa.

El efecto de enviar otras señales no está definido.

EJEMPLOS

Se puede utilizar el cifrado de conexiones a un servidor local imapd:

[imapd]
accept = 993
exec = /usr/sbin/imapd
execArgs = imapd

o en modo remoto:

[imapd]
accept = 993
connect = 143

Para permitir que un cliente de correo electrónico local utilice el servidor imapd a través de TLS, configure la recepción de correo desde localhost y el puerto 119, y utilice la siguiente configuración:

[imap]
client = yes
accept = 143
connect = server:993

En combinación con el programa pppd, stunnel permite establecer una VPN simple. En el lado del servidor, escuchando en el puerto 2020, su configuración puede ser la siguiente:

[vpn]
accept = 2020
exec = /usr/sbin/pppd
execArgs = pppd local
pty = yes

El siguiente archivo de configuración puede ser utilizado para ejecutar el programa stunnel en modo inetd. Cabe señalar que no hay una sección [nombre_servicio] en el archivo de configuración.

exec = /usr/sbin/imapd
execArgs = imapd

Para configurar una VPN, se puede utilizar la siguiente configuración del cliente:

[socks_client]
client = yes
accept = 127.0.0.1:1080
connect = vpn_server:9080
verifyPeer = yes
CAfile = stunnel.pem

La configuración correspondiente del servidor vpn_server:

[socks_server]
protocol = socks
accept = 9080
cert = stunnel.pem
key = stunnel.key

Para probar la configuración, se puede ejecutar el siguiente comando en la máquina cliente:

curl --socks4a localhost http://www.example.com/
