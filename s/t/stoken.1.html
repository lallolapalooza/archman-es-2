stoken(1) General Commands Manual stoken(1)

NOMBRE

stoken - token de software para autenticación criptográfica

SINOPSIS

stoken [tokencode] [--stdin] [--force] [--next] [opts]

stoken import {--file=archivo | --token=cadena_token} [--force] [opts]

stoken setpin [opts]

stoken setpass [opts]

stoken show [--seed] [opts]

stoken export [{--blocks | --iphone | --android | --v3 | --sdtid | --qr=archivo.png | --show-qr}] [opts]

stoken issue [--template=archivo]

stoken help

stoken version

DESCRIPCIÓN

stoken es un token de software compatible con tokens RSA SecurID de 128 bits (AES). La interfaz de línea de comandos proporciona facilidades para importar nuevos tokens, mostrar el tokencode actual, cifrar la semilla con una contraseña especificada por el usuario, almacenar el PIN del usuario junto con el token, y ver o exportar los datos del token.

USO BÁSICO

Use stoken import para decodificar una cadena de token y escribirla en ~/.stokenrc. Esto puede solicitar un ID de dispositivo y/o una contraseña, dependiendo de las opciones que su administrador haya utilizado para crear el token. La cadena de token se puede proporcionar en la línea de comandos o leer de un archivo de texto.

stoken autodetectará los siguientes tipos de cadenas de token:

286510182209303756117707012447003320623006...
29658-21098-45467-64675-65731-01441-11337...
Cadenas "ctf" (formato de token comprimido) puramente numéricas (de 81 dígitos), con o sin guiones. Estas podrían haber sido proporcionadas tal cual, o podrían haber sido derivadas de un archivo sdtid por el programa TokenConverter de RSA.
com.rsa.securid.iphone://ctf?ctfData=229639330774927764401...
Cadenas de token compatibles con iPhone.
http://127.0.0.1/securid/ctf?ctfData=250494932146245277466...
http://127.0.0.1/securid/ctf?ctfData=AwAAfBc3QSopPxxjLGnxf...
Cadenas de token compatibles con Android.
<?xml version=...
Archivos XML con formato sdtid de RSA. Estos deben importarse desde un archivo: stoken import --file=ARCHIVO.SDTID.

Los tokens proporcionados como códigos QR se pueden convertir de nuevo a URIs estándar ejecutando zbarimg(1) sobre el archivo de imagen.

El ID del dispositivo, si se usa, se puede ver en el menú "acerca de" de la aplicación de token de software RSA en el teléfono. Las cadenas ctf numéricas y los tokens de smartphone vinculados a un ID de dispositivo contienen una semilla que se cifra utilizando el ID del dispositivo, por lo que se debe proporcionar el ID antes de que stoken pueda importar el token con éxito. Los archivos sdtid se pueden importar sin conocer el ID del dispositivo, siempre que se conozca la contraseña (si la hay).

Por defecto, stoken import se negará a sobrescribir un token existente en ~/.stokenrc. El modificador --force anula esta comprobación.

stoken import normalmente solicitará una nueva contraseña, que se utiliza para cifrar la semilla antes de almacenarla en ~/.stokenrc. Esto se puede omitir introduciendo una contraseña vacía o especificando --new-password='' en la línea de comandos. Se recomienda elegir una frase de contraseña más larga y difícil de adivinar para este propósito.

Después de importar un token, ejecutar stoken sin argumentos pedirá la contraseña o PIN requerido, y luego mostrará el tokencode actual.

Los tokencodes se calculan a partir de los datos de la semilla cruda (descifrada), la hora actual del día y el PIN. Si la misma semilla está instalada en varios dispositivos, todos deberían producir tokencodes idénticos. Si no es así, compruebe la configuración de la zona horaria y considere usar NTP para sincronizar la hora del sistema con una fuente confiable.

stoken setpin se puede utilizar para guardar el PIN en ~/.stokenrc. No todos los tokens requerirán un PIN; esto puede ser configurado por el administrador de SecurID al generar nuevos tokens. Establecer un PIN vacío eliminará el PIN de ~/.stokenrc para que se le solicite al usuario cada vez que sea necesario. Consulte la sección CONSIDERACIONES DE SEGURIDAD más abajo para obtener detalles adicionales.

stoken setpass cifra la semilla y el PIN (si está presente) en ~/.stokenrc con una contraseña o frase de contraseña seleccionable por el usuario. Si se introduce una contraseña vacía, se eliminará la contraseña. Consulte la sección CONSIDERACIONES DE SEGURIDAD más abajo para obtener detalles adicionales.

VISUALIZACIÓN DE TOKENS

stoken show muestra información sobre el token actual, leído típicamente de ~/.stokenrc. La opción --seed muestra los bytes de la semilla cifrados y descifrados (que deben tratarse como datos sensibles, ya que se pueden utilizar para derivar tokencodes).

stoken export traduce el token actual a un formato adecuado para su importación a otro dispositivo.

stoken issue genera un nuevo token de software en formato XML sdtid. Se puede proporcionar un archivo de plantilla, en sí mismo en formato sdtid, para anular algunos o todos los campos legibles por humanos. Esto permitiría especificar números de serie, fechas de caducidad, nombres de usuario, etc., apropiados. Si los campos Secret, Seed o MAC están presentes en el archivo de plantilla, se ignorarán.

OPCIONES GLOBALES

--rcfile=archivo
Utilizar un archivo de configuración .stokenrc alternativo. Esto se usa típicamente para soportar múltiples tokens en la cuenta de usuario de UNIX. Tenga en cuenta que el archivo .stokenrc almacena datos adicionales (como el PIN), por lo que no puede ser analizado como una cadena de token "cruda" por stoken --file.
--password=contraseña, -p contraseña
Usar una contraseña proporcionada desde la línea de comandos, en lugar de pedirla al usuario. Ver notas en CONSIDERACIONES DE SEGURIDAD más abajo.
--pin=pin, -n pin
Usar un PIN proporcionado desde la línea de comandos, en lugar de pedirlo al usuario. Ver notas en CONSIDERACIONES DE SEGURIDAD más abajo. Si guarda su PIN en ~/.stokenrc, tenga en cuenta que a menudo se requiere --pin=0000 al activar un nuevo token de software por primera vez.
--devid=devid
Usar un ID de dispositivo proporcionado desde la línea de comandos para descifrar el token. Un token puede estar vinculado a un ID de dispositivo de clase GUID (es decir, un cierto tipo de dispositivo, como "iPhone" o "Android"), un ID de dispositivo único (una unidad específica), o nada. stoken intentará autodetectar coincidencias con un GUID de clase, pero en raras ocasiones esto resulta en falsos positivos debido a colisiones de hash. En estos casos, se debe especificar el ID del dispositivo vinculado en la línea de comandos para anular la autodetección.

OPCIONES DE EXPORTACIÓN

--new-password=contraseña
Proporcionar la contraseña de cifrado desde la línea de comandos para operaciones que escriben una cadena de token o archivo .stokenrc: import, export, setpass, y issue. Ver notas en CONSIDERACIONES DE SEGURIDAD más abajo.
--keep-password
Si el token en el archivo .stokenrc está protegido con contraseña, conserva la misma contraseña al exportar el token. Por defecto, la operación export no cifrará el token con una contraseña.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

d; note que puede que no sea posible introducir todas las contraseñas posibles en dispositivos con capacidades de entrada de texto limitadas (como teléfonos básicos).
--new-pin=pin
Proporciona un nuevo PIN desde la línea de comandos para la operación setpin. Consulta las notas en CONSIDERACIONES DE SEGURIDAD más abajo.
--new-devid=devid
Se utiliza con el comando export o issue para cifrar el nuevo token con un ID de dispositivo específico. Esto solo se usa para fines de prueba.
--blocks, --iphone, --android, --v3
Se utiliza con el comando export para seleccionar el formato de salida. Consulta los ejemplos en USO BÁSICO. Por defecto, el comando export imprimirá una cadena de 81 dígitos sin formato a la salida estándar.
--sdtid, --xml
Estas opciones son sinónimos. Ambas exportan un token a la salida estándar en formato XML sdtid de RSA.
--qr=archivo.png
Codifica el token como un código QR y lo escribe en archivo.png. Esto requiere que el programa qrencode esté instalado.
--show-qr
Codifica el token como un código QR y lo muestra inmediatamente en la pantalla. Esto requiere que el programa qrencode esté instalado. Si la variable de entorno QR_VIEWER está configurada, stoken utilizará ese programa como visor preferido. De lo contrario, intentará ejecutar algunos visores de imágenes comunes de Linux y se rendirá si ninguno de ellos existe.
--template=archivo
Se utiliza con los comandos export o issue para anular campos en la salida XML. El archivo de plantilla debe tener el aspecto de cualquier archivo sdtid estándar, pero todos los campos son opcionales y tendrán valores predeterminados razonablemente sensatos si se omiten. Esto se puede usar para forzar que la salida XML utilice un número de serie, nombre de usuario, fecha de caducidad, etc. específicos. Las sumas de verificación MAC correctas se (re)calcularán sobre los valores proporcionados. Consulta el directorio examples en la distribución fuente para obtener más información.

OTRAS OPCIONES

--use-time={unix_time|+offset|-offset}
En lugar de generar un tokencode basado en la hora actual del día, fuerza una hora específica o ajusta la hora actual basándose en un desplazamiento positivo o negativo (especificado en segundos). Esto solo se usa para fines de prueba.
--next
Genera el siguiente tokencode en lugar del tokencode actual. Para un token de 60 segundos, esto es equivalente a --use-time=+60.
--stdin, -s
Cuando se genera un tokencode que requiere una contraseña o un PIN, lee la contraseña o el PIN como una sola línea de la entrada estándar. Esto está destinado a permitir que programas externos llamen a stoken para generar contraseñas de un solo uso sin intervención del usuario; consulta USO NO INTERACTIVO más abajo.
--force, -f
Anula las comprobaciones de fecha de caducidad del token (para tokencode) o las comprobaciones de sobrescritura del token (para import).
--batch, -b
Aborta con un código de salida de error si se requiere alguna entrada del usuario. Previsto para operación automatizada y pruebas.
--file=archivo
Lee una cadena ctf, una URI de Android/iPhone o un token XML sdtid del archivo en lugar de la configuración de .stokenrc. La mayoría de los comandos de stoken aceptan esta marca, pero se espera que el usuario típico guarde su token en ~/.stokenrc en lugar de proporcionarlo manualmente en cada invocación. Típicamente --file y --token solo se utilizan para el comando import.
--token=cadena_token
Utiliza un token de la línea de comandos en lugar del archivo .stokenrc. Consulta las notas anteriores sobre --file.
--random
Genera un token aleatorio sobre la marcha. Utilizado solo para pruebas o demostraciones. Estos tokens no deben usarse para autenticación real.
--help, -h
Muestra información básica de uso.
--version, -v
Muestra información de la versión.

CONSIDERACIONES DE SEGURIDAD

Los tokens de software, a diferencia de los tokens de hardware, son relativamente fáciles de replicar. Los sistemas que almacenan las semillas de tokens blandos deben ser protegidos cuidadosamente para evitar la divulgación no autorizada. Se recomienda encarecidamente el uso de cifrado de disco completo, como TrueCrypt, para ordenadores portátiles y otros dispositivos portátiles que se pierden o se roban fácilmente.

stoken permite a los usuarios almacenar su PIN en ~/.stokenrc para permitir la generación automatizada (scriptable) de tokencodes, pero los riesgos de este enfoque deben sopesarse cuidadosamente frente a los beneficios.

Utilizar el comando setpass para cifrar la semilla y el PIN en ~/.stokenrc proporciona cierto grado de protección contra el acceso no autorizado, pero no cubre necesariamente todos los posibles vectores de ataque. Un host que ya esté comprometido (por ejemplo, ejecutando un registrador de teclas) no proporcionará una protección adecuada para ninguna semilla almacenada en él.

Las contraseñas de cifrado de stoken pueden tener hasta 40 caracteres de longitud. Una frase de contraseña más larga, construida a partir de varias palabras aleatorias, puede proporcionar más protección contra ataques de fuerza bruta que una contraseña más corta.

Introducir una contraseña o PIN en la línea de comandos es generalmente inseguro en sistemas multiusuario, ya que otros usuarios pueden ser capaces de ver los argumentos de la línea de comandos en ps o utilidades similares. La línea de comandos también podría almacenarse en caché en archivos de historial del shell.

La codificación de tokens QR puede exponer los datos de la semilla a través de ps, y la opción --show-qr escribe archivos PNG temporales en /tmp.

stoken intenta bloquear páginas para evitar el intercambio en disco, pero no borra los secretos de la memoria del proceso.

USO NO INTERACTIVO

Otras aplicaciones, como clientes VPN, pueden querer invocar stoken de forma no interactiva para generar contraseñas de un solo uso. Se admiten tres modos de uso, dependiendo del nivel de seguridad (y/o conveniencia) que se requiera:

Sin contraseña o PIN

El usuario configura stoken para que imprima un tokencode inmediatamente al invocarlo, sin indicaciones, utilizando setpin para almacenar el PIN en ~/.stokenrc y utilizando setpass para establecer una contraseña vacía. La otra aplicación puede entonces invocar stoken --batch y leer el tokencode a través de una tubería desde la salida estándar.

Esto no proporciona ninguna seguridad para la semilla, pero puede ser útil en aplicaciones donde la (re)autenticación es frecuente o se requiere operación desatendida.

Guardar el PIN y establecer una contraseña

El usuario configura stoken para cifrar los secretos de ~/.stokenrc con una contraseña usando setpass, luego guarda el PIN con setpin. El PIN y la semilla se cifrarán con la contraseña. La otra aplicación solicitará la contraseña al usuario, luego llamará a stoken --stdin, escribirá la contraseña en la entrada estándar de stoken a través de una tubería y leerá un tokencode de la salida estándar de stoken.

Sin contraseña; solicitar el PIN

Similar a lo anterior, pero establece una contraseña vacía usando setpass, no guarda el PIN en ~/.stokenrc y pasa el PIN a stoken --stdin a través de la entrada estándar.

ERRORES/TODO

El soporte para sdtid todavía es nuevo y puede fallar con entradas inesperadas. Como solución temporal a corto plazo, puedes intentar comentar las comprobaciones de sanidad en sdtid_decrypt() para ver si el problema desaparece.

Las características en desarrollo incluyen: semillas de tokens de hardware (y el comando stoken split necesario para trabajar con ellas), y soporte para hosts no Linux.

Los parches son siempre bienvenidos.

STOKEN(1)

stoken - Herramienta de línea de comandos para manejar tokens de software

USO BÁSICO

El uso básico de stoken es para generar un token de software dado un tipo de token, un nombre de usuario y un nombre de host.

stoken --token=HOTP --username=user --hostname=example.com

Este comando generará un token HOTP para el usuario `user` en el host `example.com`. Si se especifica la opción `--create`, también se le pedirá al usuario que cree un nuevo token para este par usuario/host.

VISUALIZACIÓN DE TOKENS

Puede ver la lista de tokens de software configurados utilizando la opción `--list`:

stoken --list

Esto mostrará una lista de todos los tokens de software creados, junto con su tipo, nombre de usuario y nombre de host.

OPCIONES GLOBALES

Las siguientes opciones son globales y pueden usarse con cualquier subcomando:

  • --config=FILE: Especifica un archivo de configuración alternativo.
  • --debug: Habilita la salida de depuración.
  • --help: Muestra el mensaje de ayuda y sale.
  • --version: Muestra la información de la versión y sale.

OPCIONES DE EXPORTACIÓN

Se pueden exportar tokens de software a diferentes formatos:

  • --export=TOKEN_ID: Exporta el token especificado.
  • --export-format=FORMAT: Especifica el formato de exportación (ej. `json`, `xml`).

OTRAS OPCIONES

Otras opciones útiles incluyen:

  • --create: Crea un nuevo token.
  • --delete=TOKEN_ID: Elimina el token especificado.
  • --update=TOKEN_ID: Actualiza el token especificado.
  • --type=TYPE: Especifica el tipo de token (ej. `HOTP`, `TOTP`).

CONSIDERACIONES DE SEGURIDAD

Los tokens de software almacenan información sensible. Asegúrese de proteger su archivo de configuración de stoken con permisos de archivo apropiados.

Evite almacenar tokens en sistemas inseguros o en la nube sin cifrado adicional.

USO NO INTERACTIVO

Para uso no interactivo, como en scripts, puede especificar credenciales y opciones directamente en la línea de comandos. Tenga cuidado al hacerlo, ya que exponer información sensible en la línea de comandos puede ser un riesgo de seguridad.

stoken --token=TOTP --username=admin --hostname=server.local --secret=BASE32_SECRET --digits=6 --period=30

ERRORES/TODO

Reportar errores y sugerencias a la lista de correo o al sistema de seguimiento de errores del proyecto.
