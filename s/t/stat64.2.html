stat(2) Manual de llamadas al sistema stat(2)

NOMBRE

stat, fstat, lstat, fstatat - obtener estado del archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/stat.h>
int stat(const char *restrict ruta,
         struct stat *restrict buf_estat);
int fstat(int fd, struct stat *buf_estat);
int lstat(const char *restrict ruta,
         struct stat *restrict buf_estat);
#include <fcntl.h>           /* Definición de constantes AT_* */
#include <sys/stat.h>
int fstatat(int dirfd, const char *restrict ruta,
         struct stat *restrict buf_estat, int flags);

DESCRIPCIÓN

Estas funciones devuelven información sobre un archivo, en el búfer apuntado por buf_estat. No se requieren permisos sobre el archivo en sí, pero —en el caso de stat(), fstatat() y lstat()— se requiere permiso de ejecución (búsqueda) en todos los directorios en ruta que conducen al archivo.

stat() y fstatat() obtienen información sobre el archivo apuntado por ruta; las diferencias para fstatat() se describen a continuación.

lstat() es idéntica a stat(), excepto que si ruta es un enlace simbólico, entonces devuelve información sobre el enlace en sí, no sobre el archivo al que se refiere el enlace.

fstat() es idéntica a stat(), excepto que el archivo sobre el cual se debe obtener información se especifica mediante el descriptor de archivo fd.

La estructura stat

Todas estas llamadas al sistema devuelven una estructura stat (ver stat(3type)).

Nota: por razones de rendimiento y simplicidad, diferentes campos en la estructura stat pueden contener información de estado de diferentes momentos durante la ejecución de la llamada al sistema. Por ejemplo, si st_modo o st_uid son cambiados por otro proceso llamando a chmod(2) o chown(2), stat() podría devolver el st_modo antiguo junto con el nuevo st_uid, o el st_uid antiguo junto con el nuevo st_modo.

fstatat()

La llamada al sistema fstatat() es una interfaz más general para acceder a la información del archivo que aún puede proporcionar exactamente el comportamiento de cada una de stat(), lstat(), y fstat().

Si ruta es relativa, entonces se interpreta en relación con el directorio al que se refiere el descriptor de archivo dirfd (en lugar de en relación con el directorio de trabajo actual del proceso llamador, como se hace con stat() y lstat() para un nombre de ruta relativo).

Si ruta es relativa y dirfd es el valor especial AT_FDCWD, entonces ruta se interpreta en relación con el directorio de trabajo actual del proceso llamador (como stat() y lstat()).

Si ruta es absoluta, entonces dirfd se ignora.

flags puede ser 0, o incluir una o más de las siguientes banderas ORed:

AT_EMPTY_PATH (desde Linux 2.6.39)
Si ruta es una cadena vacía (o NULL, desde Linux 6.11) opera sobre el archivo al que se refiere dirfd (que podría haberse obtenido usando la bandera open(2) O_PATH). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio, y el comportamiento de fstatat() es similar al de fstat(). Si dirfd es AT_FDCWD, la llamada opera sobre el directorio de trabajo actual. Esta bandera es específica de Linux; defina _GNU_SOURCE para obtener su definición.
AT_NO_AUTOMOUNT (desde Linux 2.6.38)
No automontar el componente terminal ("nombre base") de ruta. Desde Linux 3.1 esta bandera se ignora. Desde Linux 4.11 esta bandera está implícita.
AT_SYMLINK_NOFOLLOW
Si ruta es un enlace simbólico, no lo desreferencie: en su lugar, devuelva información sobre el enlace en sí, como lstat(). (Por defecto, fstatat() desreferencia los enlaces simbólicos, como stat().)

Ver openat(2) para una explicación de la necesidad de fstatat().

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EACCES
Se niega el permiso de búsqueda en uno de los directorios en el prefijo de ruta de ruta. (Ver también path_resolution(7)).
EBADF
fd no es un descriptor de archivo abierto válido.
EBADF
(fstatat()) ruta es relativa pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
Dirección inválida.
EINVAL
(fstatat()) Bandera inválida especificada en flags.
ELOOP
Se encontraron demasiados enlaces simbólicos al recorrer la ruta.
ENAMETOOLONG
ruta es demasiado larga.
ENOENT
Un componente de ruta no existe o es un enlace simbólico colgante.
ENOENT
ruta es una cadena vacía y no se especificó AT_EMPTY_PATH en flags.
ENOMEM
Sin memoria (es decir, memoria del kernel).
ENOTDIR
Un componente del prefijo de ruta de ruta no es un directorio.
ENOTDIR
(fstatat()) ruta es relativa y dirfd es un descriptor de archivo que se refiere a un archivo que no es un directorio.
EOVERFLOW
ruta o fd se refieren a un archivo cuyo tamaño, número de inodo o número de bloques no se pueden representar en, respectivamente, los tipos off_t, ino_t o blkcnt_t. Este error puede ocurrir cuando, por ejemplo, una aplicación compilada en una plataforma de 32 bits sin -D_FILE_OFFSET_BITS=64 llama a stat() en un archivo cuyo tamaño excede los (1<<31)-1 bytes.

NAME

stat64, fstat64, lstat64 - get file status (64-bit)

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <sys/stat.h>

int stat64(const char *restrict pathname, struct stat64 *restrict buf);
int fstat64(int fd, struct stat64 *buf);
int lstat64(const char *restrict pathname, struct stat64 *restrict buf);

Feature Test Macro requirements for glibc (see feature_test_macros(7)):

stat64(), fstat64(), lstat64():
_FILE_OFFSET_BITS && _GNU_SOURCE

DESCRIPTION

The functions stat64(), fstat64(), and lstat64() are versions of stat(2), fstat(2), and lstat(2), respectively, that operate on a 64-bit structure.

These functions are provided for compatibility with older systems or applications that require the use of the 64-bit structure. On modern systems, the standard stat(2), fstat(2), and lstat(2) functions already use a 64-bit structure, provided that the macro _FILE_OFFSET_BITS is defined with the value 64. When _FILE_OFFSET_BITS is defined as 64, the standard stat(), fstat(), and lstat() functions will actually call the 64-bit versions internally.

The struct stat64 structure contains the following fields:

st_dev
ID of the device containing the file.
st_ino
I-node number of the file.
st_mode
Protection (and type) of the file.
st_nlink
Number of hard links to the file.
st_uid
User ID of the owner of the file.
st_gid
Group ID of the owner of the file.
st_rdev
Device ID (if special file).
st_size
Total size, in bytes, of the file. This is a 64-bit value.
st_atime
Time of last access.
st_mtime
Time of last modification.
st_ctime
Time of last status change.
st_blksize
Preferred block size for file I/O. This is a 64-bit value.
st_blocks
Number of 512-byte blocks allocated for this file. This is a 64-bit value. Note that st_blocks is not a count of how many blocks are used by the file, nor is it a measure of the file size in 512-byte units. It is the number of filesystem blocks allocated to the file.

The fields st_atime, st_mtime, and st_ctime are structures containing members tv_sec (seconds) and tv_nsec (nanoseconds).

The macros major(3), minor(3), and makedev(3) are available for manipulating device numbers.

stat64(): Gets the status of the file referred to by pathname. If pathname refers to a symbolic link, then the information returned is for the link itself, not for the file the link points to. (This is the behavior of lstat(2)). If you want the behavior of stat(2) (follow symbolic links), use stat(2) (or stat with _FILE_OFFSET_BITS=64 defined).

fstat64(): Gets the status of the file referred to by the open file description identified by fd. fd must be an open file descriptor.

lstat64(): Gets the status of the file referred to by pathname. If pathname refers to a symbolic link, then the information returned is for the link itself, not for the file the link points to.

The st_mode field contains file type and mode bits. The file type is encoded in the least significant bits, and can be extracted using macros of the form S_IF*. The mode bits represent file permissions. The macro S_IMODE can be used to extract the mode bits. The file type bits are:

S_IFMT
Mask to extract file type.
S_IFBLK
Block special file.
S_IFCHR
Character special file.
S_IFDIR
Directory.
S_IFIFO
FIFO (named pipe).
S_IFLNK
Symbolic link.
S_IFREG
Regular file.
S_IFSOCK
Socket.

RETURN VALUE

On success, zero is returned. On error, -1 is returned, and errno is set to indicate the error.

ERRORS

The stat64() and lstat64() functions will fail if:

EACCES
Search permission denied for any component of the pathname prefix of pathname.
EBADF
fd is not a valid file descriptor.
EFAULT
buf points outside the accessible address space.
ELOOP
Too many symbolic links were encountered in translating pathname.
ENAMETOOLONG
pathname is too long.
ENOENT
A component of pathname does not exist or is a dangling symbolic link (for stat64() and fstat64() only).
ENOMEM
Out of kernel memory.
ENOTDIR
A component of pathname is not a directory.
EOVERFLOW
The file or a component of the pathname cannot be represented in a stat64 structure (e.g., a file size is too large for st_size).
EROFS
A read-only filesystem was mounted.
ETXTBSY
The file is a regular file that is opened for writing, and that the system is executing it.
EACCES
Access to the file was denied.
EFAULT
buf is not a valid address.
ELOOP
Too many symbolic links encountered.
ENAMETOOLONG
pathname is too long.
ENOENT
pathname does not exist.
ENOTDIR
pathname is not a directory.
ENXIO
A block or character device does not exist or is invalid.
EOVERFLOW
The file or a component of the pathname cannot be represented in a stat64 structure.
EROFS
A read-only filesystem was mounted.

The fstat64() function may also fail if:

EBADF
fd is not a valid file descriptor.

See also the errors for stat(2), fstat(2), and lstat(2).

STANDARDS

These functions are specific to Linux and are not part of any standard. The standard POSIX functions stat(2), fstat(2), and lstat(2) are available and typically use 64-bit structures when _FILE_OFFSET_BITS is defined as 64.

The POSIX.1-2008 standard specifies that the standard stat(), fstat(), and lstat() functions should return valid information in all fields of the st_mode field of the stat structure. POSIX.1-2008 tightens the specification, requiring lstat() to return valid information in all fields except the mode bits in st_mode.

Use of the st_blocks and st_blksize fields may be less portable. (They were introduced in BSD. The interpretation differs between systems, and possibly on a single system when NFS mounts are involved.)

C library/kernel differences

Over time, increases in the size of the stat structure have led to three successive versions of stat(): sys_stat() (slot __NR_oldstat), sys_newstat() (slot __NR_stat), and sys_stat64() (slot __NR_stat64) on 32-bit platforms such as i386. The first two versions were already present in Linux 1.0 (albeit with different names); the last was added in Linux 2.4. Similar remarks apply for fstat() and lstat().

The kernel-internal versions of the stat structure dealt with by the different versions are, respectively:

__old_kernel_stat
The original structure, with rather narrow fields, and no padding.
stat
Larger st_ino field and padding added to various parts of the structure to allow for future expansion.
stat64
Even larger st_ino field, larger st_uid and st_gid fields to accommodate the Linux-2.4 expansion of UIDs and GIDs to 32 bits, and various other enlarged fields and further padding in the structure. (Various padding bytes were eventually consumed in Linux 2.6, with the advent of 32-bit device IDs and nanosecond components for the timestamp fields.)

The glibc stat() wrapper function hides these details from applications, invoking the most recent version of the system call provided by the kernel, and repacking the returned information if required for old binaries.

On modern 64-bit systems, life is simpler: there is a single stat() system call and the kernel deals with a stat structure that contains fields of a sufficient size.

The underlying system call employed by the glibc fstatat() wrapper function is actually called fstatat64() or, on some architectures, newfstatat().

EXAMPLES

The following program calls lstat() and displays selected fields in the returned stat structure.

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/sysmacros.h>
#include <time.h>
int
main(int argc, char *argv[])
{
    struct stat sb;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <path>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (lstat(argv[1], &sb) == -1) {
        perror("lstat");
        exit(EXIT_FAILURE);
    }
    printf("ID of containing device:  [%x,%x]\n",
           major(sb.st_dev),
           minor(sb.st_dev));
    printf("File type:                ");
    switch (sb.st_mode & S_IFMT) {
    case S_IFBLK:  printf("block device\n");            break;
    case S_IFCHR:  printf("character device\n");        break;
    case S_IFDIR:  printf("directory\n");               break;
    case S_IFIFO:  printf("FIFO/pipe\n");               break;
    case S_IFLNK:  printf("symlink\n");                 break;
    case S_IFREG:  printf("regular file\n");            break;
    case S_IFSOCK: printf("socket\n");                  break;
    default:       printf("unknown?\n");                break;
    }
    printf("I-node number:            %ju\n", (uintmax_t) sb.st_ino);
    printf("Mode:                     %jo (octal)\n",
           (uintmax_t) sb.st_mode);
    printf("Link count:               %ju\n", (uintmax_t) sb.st_nlink);
    printf("Ownership:                UID=%ju   GID=%ju\n",
           (uintmax_t) sb.st_uid, (uintmax_t) sb.st_gid);
    printf("Preferred I/O block size: %jd bytes\n",
           (intmax_t) sb.st_blksize);
    printf("File size:                %jd bytes\n",
           (intmax_t) sb.st_size);
    printf("Blocks allocated:         %jd\n",
           (intmax_t) sb.st_blocks);
    printf("Last status change:       %s", ctime(&sb.st_ctime));
    printf("Last file access:         %s", ctime(&sb.st_atime));
    printf("Last file modification:   %s", ctime(&sb.st_mtime));
    exit(EXIT_SUCCESS);
}
