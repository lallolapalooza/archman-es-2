stdin(3) Manual de funciones de biblioteca stdin(3)

NOMBRE

stdin, stdout, stderr - flujos de E/S estándar

BIBLIOTECA

Biblioteca estándar C (libc, -lc)

SINOPSIS

#include <stdio.h>
extern FILE  *stdin;
extern FILE  *stdout;
extern FILE  *stderr;

DESCRIPCIÓN

En circunstancias normales, cada programa UNIX tiene tres flujos abiertos para él cuando se inicia, uno para entrada, uno para salida y uno para imprimir mensajes de diagnóstico o error. Estos suelen estar conectados al terminal del usuario (ver tty(4)) pero podrían hacer referencia a archivos u otros dispositivos, dependiendo de lo que el proceso padre eligiera configurar. (Ver también la sección "Redirecciones" de sh(1).)

El flujo de entrada se denomina "entrada estándar"; el flujo de salida se denomina "salida estándar"; y el flujo de error se denomina "error estándar". Estos términos se abrevian para formar los símbolos que se utilizan para referirse a estos archivos, a saber, stdin, stdout y stderr.

Cada uno de estos símbolos es una macro de stdio(3) de tipo puntero a FILE, y puede usarse con funciones como fprintf(3) o fread(3).

Dado que los FILE son un envoltorio de búfer alrededor de los descriptores de archivo de UNIX, los mismos archivos subyacentes también pueden accederse utilizando la interfaz de archivo sin procesar de UNIX, es decir, las funciones como read(2) y lseek(2).

Al inicio del programa, los descriptores de archivo enteros asociados con los flujos stdin, stdout y stderr son 0, 1 y 2, respectivamente. Los símbolos preprocesador STDIN_FILENO, STDOUT_FILENO y STDERR_FILENO están definidos con estos valores en <unistd.h>. (Aplicar freopen(3) a uno de estos flujos puede cambiar el número del descriptor de archivo asociado con el flujo).

Tenga en cuenta que la mezcla del uso de FILEs y descriptores de archivo sin procesar puede producir resultados inesperados y generalmente debe evitarse. (Para los masoquistas entre ustedes: POSIX.1, sección 8.2.3, describe en detalle cómo se supone que funciona esta interacción.) Una regla general es que los descriptores de archivo se manejan en el kernel, mientras que stdio es solo una biblioteca. Esto significa, por ejemplo, que después de un exec(3), el hijo hereda todos los descriptores de archivo abiertos, pero todos los flujos antiguos se han vuelto inaccesibles.

Dado que los símbolos stdin, stdout y stderr se especifican como macros, la asignación a ellos no es portable. Los flujos estándar pueden configurarse para que hagan referencia a diferentes archivos con la ayuda de la función de biblioteca freopen(3), introducida especialmente para hacer posible la reasignación de stdin, stdout y stderr. Los flujos estándar se cierran mediante una llamada a exit(3) y por la terminación normal del programa.

ESTANDARES

C11, POSIX.1-2008.

Los estándares también estipulan que estos tres flujos deben estar abiertos al inicio del programa.

HISTORIA

C89, POSIX.1-2001.

NOTAS

El flujo stderr no tiene búfer. El flujo stdout tiene búfer de línea cuando apunta a un terminal. Las líneas parciales no aparecerán hasta que se llame a fflush(3) o exit(3), o se imprima un salto de línea. Esto puede producir resultados inesperados, especialmente con la salida de depuración. El modo de almacenamiento en búfer de los flujos estándar (o de cualquier otro flujo) se puede cambiar utilizando la llamada setbuf(3) o setvbuf(3). Tenga en cuenta que en caso de que stdin esté asociado con un terminal, también puede haber almacenamiento en búfer de entrada en el controlador del terminal, completamente independiente del almacenamiento en búfer de stdio. (De hecho, normalmente la entrada del terminal tiene búfer de línea en el kernel.) Este manejo de entrada del kernel se puede modificar mediante llamadas como tcsetattr(3); ver también stty(1) y termios(3).

VER TAMBIÉN

csh(1), sh(1), open(2), fopen(3), stdio(3)
