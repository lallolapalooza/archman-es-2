statx(2) Manual de llamadas al sistema statx(2)

NOMBRE

statx - obtener estado de archivo (extendido)

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE          /* Ver feature_test_macros(7) */
#include <fcntl.h>           /* Definición de constantes AT_* */
#include <sys/stat.h>
int statx(int dirfd, const char *_Nullable restrict path,
          int flags, unsigned int mask,
          struct statx *restrict statxbuf);

DESCRIPCIÓN

Esta función devuelve información sobre un archivo, almacenándola en el buffer apuntado por statxbuf. El buffer devuelto es una estructura del siguiente tipo:


struct statx {
    __u32 stx_mask;        /* Máscara de bits que indica
                              campos completados */
    __u32 stx_blksize;     /* Tamaño de bloque para E/S del sistema de archivos */
    __u64 stx_attributes;  /* Indicadores de atributos adicionales del archivo */
    __u32 stx_nlink;       /* Número de enlaces duros */
    __u32 stx_uid;         /* ID de usuario del propietario */
    __u32 stx_gid;         /* ID de grupo del propietario */
    __u16 stx_mode;        /* Tipo y permisos del archivo */
    __u64 stx_ino;         /* Número de inodo */
    __u64 stx_size;        /* Tamaño total en bytes */
    __u64 stx_blocks;      /* Número de bloques de 512B asignados */
    __u64 stx_attributes_mask;
                           /* Máscara para mostrar qué es compatible
                              en stx_attributes */
    /* Los siguientes campos son las marcas de tiempo del archivo */
    struct statx_timestamp stx_atime;  /* Último acceso */
    struct statx_timestamp stx_btime;  /* Creación */
    struct statx_timestamp stx_ctime;  /* Último cambio de estado */
    struct statx_timestamp stx_mtime;  /* Última modificación */
    /* Si este archivo representa un dispositivo, entonces los siguientes dos
       campos contienen el ID del dispositivo */
    __u32 stx_rdev_major;  /* ID principal */
    __u32 stx_rdev_minor;  /* ID secundario */
    /* Los siguientes dos campos contienen el ID del dispositivo
       que contiene el sistema de archivos donde reside el archivo */
    __u32 stx_dev_major;   /* ID principal */
    __u32 stx_dev_minor;   /* ID secundario */
    __u64 stx_mnt_id;      /* ID de montaje */
    /* Restricciones de alineación de E/S directa */
    __u32 stx_dio_mem_align;
    __u32 stx_dio_offset_align;
    __u64 stx_subvol;      /* Identificador de subvolumen */
    /* Límites atómicos de escritura de E/S directa */
    __u32 stx_atomic_write_unit_min;
    __u32 stx_atomic_write_unit_max;
    __u32 stx_atomic_write_segments_max;
    /* Alineación del desplazamiento del archivo para lecturas de E/S directa */
    __u32 stx_dio_read_offset_align;
    /* Límite máximo de escritura atómica de E/S directa */
    __u32 stx_atomic_write_unit_max_opt;
};

Las marcas de tiempo del archivo son estructuras del siguiente tipo:


struct statx_timestamp {
    __s64 tv_sec;    /* Segundos desde la Época (tiempo UNIX) */
    __u32 tv_nsec;   /* Nanosegundos desde tv_sec */
};

(Se omiten el espacio reservado y el relleno.)

Invocando statx():

Para acceder al estado de un archivo, no se requieren permisos sobre el archivo en sí, pero en el caso de statx() con una ruta de nombre de archivo, se requiere permiso de ejecución (búsqueda) en todos los directorios de path que conducen al archivo.

statx() usa path, dirfd y flags para identificar el archivo de destino de una de las siguientes maneras:

Una ruta absoluta
Si path comienza con una barra, entonces es una ruta absoluta que identifica el archivo de destino. En este caso, dirfd se ignora.
Una ruta relativa
Si path es una cadena que comienza con un carácter que no es una barra y dirfd es AT_FDCWD, entonces path es una ruta relativa que se interpreta en relación con el directorio de trabajo actual del proceso.
Una ruta relativa al directorio
Si path es una cadena que comienza con un carácter que no es una barra y dirfd es un descriptor de archivo que se refiere a un directorio, entonces path es una ruta relativa que se interpreta en relación con el directorio al que se refiere dirfd. (Ver openat(2) para una explicación de por qué esto es útil.)
Por descriptor de archivo
Si path es una cadena vacía (o NULL desde Linux 6.11) y la bandera AT_EMPTY_PATH se especifica en flags (ver abajo), entonces el archivo de destino es el al que se refiere el descriptor de archivo dirfd.

flags se puede usar para influir en la búsqueda basada en la ruta de nombre de archivo. Un valor para flags se construye ORando cero o más de las siguientes constantes:

AT_EMPTY_PATH
Si path es una cadena vacía (o NULL desde Linux 6.11), opera sobre el archivo al que se refiere dirfd (que puede haber sido obtenido usando la bandera open(2) O_PATH). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio.
Si dirfd es AT_FDCWD, la llamada opera sobre el directorio de trabajo actual.
AT_NO_AUTOMOUNT
No montar automáticamente el componente terminal ("basename") de path si es un directorio que es un punto de montaje automático. Esto permite al llamante recopilar atributos de un punto de montaje automático (en lugar de la ubicación que montaría). Esta bandera no tiene efecto si el punto de montaje ya ha sido sobreescrito.
La bandera AT_NO_AUTOMOUNT puede usarse en herramientas que escanean directorios para evitar el montaje automático masivo de un directorio de puntos de montaje automático.
Todas las llamadas stat(2), lstat(2), y fstatat(2) actúan como si AT_NO_AUTOMOUNT estuviera configurada.
AT_SYMLINK_NOFOLLOW
Si path es un enlace simbólico, no lo desreferencies: en su lugar, devuelve información sobre el propio enlace, como lstat(2).

flags también se puede usar para controlar qué tipo de sincronización realizará el kernel al consultar un archivo en un sistema de archivos remoto. Esto se hace ORando uno de los siguientes valores:

AT_STATX_SYNC_AS_STAT
Hace lo que hace stat(2). Este es el valor predeterminado y depende mucho del sistema de archivos.
AT_STATX_FORCE_SYNC
Fuerza la sincronización de los atributos con el servidor. Esto puede requerir que un sistema de archivos de red realice una escritura para que las marcas de tiempo sean correctas.
AT_STATX_DONT_SYNC
No sincronizar nada, sino simplemente tomar lo que el sistema tenga en caché si es posible. Esto puede significar que la información devuelta es aproximada, pero, en un sistema de archivos de red, puede que no implique un viaje de ida y vuelta al servidor, incluso si no se tiene una concesión.

El argumento mask de statx() se utiliza para indicar al kernel qué campos le interesan al llamante. mask es una combinación ORada de las siguientes constantes:


STATX_TYPE Quiere stx_mode & S_IFMT
STATX_MODE Quiere stx_mode & ~S_IFMT
STATX_NLINK Quiere stx_nlink
STATX_UID Quiere stx_uid
STATX_GID Quiere stx_gid
STATX_ATIME Quiere stx_atime
STATX_MTIME Quiere stx_mtime
STATX_CTIME Quiere stx_ctime
STATX_INO Quiere stx_ino
STATX_SIZE Quiere stx_size
STATX_BLOCKS Quiere stx_blocks
STATX_BASIC_STATS [Todos los anteriores]
STATX_BTIME Quiere stx_btime

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

STATX_ALL Lo mismo que STATX_BASIC_STATS | STATX_BTIME. Está obsoleto y no debe usarse. STATX_MNT_ID Solicita stx_mnt_id (desde Linux 5.8) STATX_DIOALIGN Solicita stx_dio_mem_align y stx_dio_offset_align. (desde Linux 6.1; el soporte varía según el sistema de archivos) STATX_MNT_ID_UNIQUE Solicita un stx_mnt_id único (desde Linux 6.8) STATX_SUBVOL Solicita stx_subvol (desde Linux 6.10; el soporte varía según el sistema de archivos) STATX_WRITE_ATOMIC Solicita stx_atomic_write_unit_min, stx_atomic_write_unit_max, stx_atomic_write_segments_max, y stx_atomic_write_unit_max_opt. (desde Linux 6.11; el soporte varía según el sistema de archivos) STATX_DIO_READ_ALIGN Solicita stx_dio_read_offset_align. (desde Linux 6.14; el soporte varía según el sistema de archivos)

Tenga en cuenta que, en general, el kernel no rechaza los valores en mask que no sean los anteriores. (Para una excepción, vea EINVAL en errores.) En cambio, simplemente informa al llamador qué valores son soportados por este kernel y sistema de archivos a través del campo statx.stx_mask. Por lo tanto, no establezca simplemente mask a UINT_MAX (todos los bits establecidos), ya que uno o más bits pueden, en el futuro, usarse para especificar una extensión del búfer.

La información devuelta

La información de estado del archivo objetivo se devuelve en la estructura statx apuntada por statxbuf. Incluido en esto está stx_mask, que indica qué otra información se ha devuelto. stx_mask tiene el mismo formato que el argumento mask y se establecen bits en él para indicar qué campos se han completado.

Cabe señalar que el kernel puede devolver campos que no se solicitaron y puede no devolver campos que se solicitaron, dependiendo de lo que admita el sistema de archivos subyacente. (Los campos que reciben valores a pesar de no haber sido solicitados pueden simplemente ser ignorados). En cualquier caso, stx_mask no será igual a mask.

Si un sistema de archivos no admite un campo o si tiene un valor no representable (por ejemplo, un archivo con un tipo exótico), el bit de máscara correspondiente a ese campo se borrará en stx_mask incluso si el usuario lo solicitó y se completará un valor ficticio para compatibilidad si está disponible (por ejemplo, un UID y GID ficticios pueden especificarse en el montaje bajo algunas circunstancias).

Un sistema de archivos también puede completar campos que el llamador no solicitó si tiene valores disponibles y la información está disponible sin costo adicional. Si esto sucede, los bits correspondientes se establecerán en stx_mask.

Nota: por razones de rendimiento y simplicidad, diferentes campos en la estructura statx pueden contener información de estado de diferentes momentos durante la ejecución de la llamada al sistema. Por ejemplo, si stx_mode o stx_uid es modificado por otro proceso llamando a chmod(2) o chown(2), stat() podría devolver el antiguo stx_mode junto con el nuevo stx_uid, o el antiguo stx_uid junto con el nuevo stx_mode.

Aparte de stx_mask (que se describe anteriormente), los campos en la estructura statx son:

stx_blksize
El tamaño de bloque "preferido" para E/S eficiente del sistema de archivos. (Escribir en un archivo en fragmentos más pequeños puede causar una lectura-modificación-reescritura ineficiente).
stx_attributes
Información de estado adicional sobre el archivo (ver más abajo para más información).
stx_nlink
El número de enlaces duros en un archivo.
stx_uid
Este campo contiene el ID de usuario del propietario del archivo.
stx_gid
Este campo contiene el ID del propietario del grupo del archivo.
stx_mode
El tipo y modo del archivo. Ver inode(7) para detalles.
stx_ino
El número de inodo del archivo.
stx_size
El tamaño del archivo (si es un archivo regular o un enlace simbólico) en bytes. El tamaño de un enlace simbólico es la longitud del nombre de ruta que contiene, sin un byte nulo de terminación.
stx_blocks
El número de bloques asignados al archivo en el medio, en unidades de 512 bytes. (Esto puede ser menor que stx_size/512 cuando el archivo tiene agujeros).
stx_attributes_mask
Una máscara que indica qué bits en stx_attributes son compatibles con el VFS y el sistema de archivos.
stx_atime
La marca de tiempo del último acceso al archivo.
stx_btime
La marca de tiempo de creación del archivo.
stx_ctime
La marca de tiempo del último cambio de estado del archivo.
stx_mtime
La marca de tiempo de la última modificación del archivo.
stx_dev_major
stx_dev_minor
El dispositivo en el que reside este archivo (inodo).
stx_rdev_major
stx_rdev_minor
El dispositivo que representa este archivo (inodo) si el archivo es de tipo dispositivo de bloque o carácter.
stx_mnt_id
Si se usa STATX_MNT_ID, este es el ID del montaje del montaje que contiene el archivo. Este es el mismo número que se informa en name_to_handle_at(2) y corresponde al número en el primer campo de uno de los registros de /proc/self/mountinfo.
Si se usa STATX_MNT_ID_UNIQUE, este es el ID único del montaje que contiene el archivo. Este es el número informado por listmount(2) y es el ID utilizado para consultar el montaje con statmount(2). Está garantizado que no se reutilizará mientras el sistema esté en ejecución.
stx_dio_mem_align
La alineación (en bytes) requerida para los búferes de memoria de usuario para E/S directa (O_DIRECT) en este archivo, o 0 si la E/S directa no es compatible con este archivo.
STATX_DIOALIGN (stx_dio_mem_align y stx_dio_offset_align) es compatible con dispositivos de bloque desde Linux 6.1. El soporte en archivos regulares varía según el sistema de archivos; es compatible con ext4, f2fs y xfs desde Linux 6.1.
stx_dio_offset_align
La alineación (en bytes) requerida para los offsets de archivo y las longitudes de segmento de E/S para E/S directa (O_DIRECT) en este archivo, o 0 si la E/S directa no es compatible con este archivo. Esto solo será distinto de cero si stx_dio_mem_align es distinto de cero, y viceversa.
stx_dio_read_offset_align
La alineación (en bytes) requerida para los offsets de archivo y las longitudes de segmento de E/S para lecturas de E/S directa (O_DIRECT) en este archivo. Si es cero, el límite en stx_dio_offset_align se aplica también a las lecturas. Si es distinto de cero, este valor debe ser menor o igual a stx_dio_offset_align, que debe ser proporcionado por el sistema de archivos si es solicitado por la aplicación. La alineación de memoria en stx_dio_mem_align no se ve afectada por este valor.
STATX_DIO_READ_ALIGN (stx_dio_offset_align) es compatible con xfs en archivos regulares desde Linux 6.14.
stx_subvol
Número de subvolumen del archivo actual.
Los subvolúmenes son directorios especiales, es decir, forman una estructura de árbol que puede recorrerse recursivamente. El soporte varía según el sistema de archivos; es compatible con bcachefs y btrfs desde Linux 6.10.
stx_atomic_write_unit_min
stx_atomic_write_unit_max
Los tamaños mínimo y máximo (en bytes) compatibles para E/S directa (O_DIRECT) en el archivo para ser escrito con protección contra escrituras fragmentadas. Cada uno de estos valores es garantizado que sea una potencia de 2.
STATX_WRITE_ATOMIC (stx_atomic_write_unit_min, stx_atomic_write_unit_max y stx_atomic_write_segments_max) es compatible con dispositivos de bloque desde Linux 6.11. El soporte en archivos regulares varía según el sistema de archivos; es compatible con xfs y ext4 desde Linux 6.13.
stx_atomic_write_unit_max_opt
El tamaño máximo (en bytes) que está optimizado para escrituras emitidas con protección contra escrituras fragmentadas. Si es distinto de cero, este valor no excederá el valor en stx_atomic_write_unit_max y no será menor que el valor en stx_atomic_write_unit_min. Un valor de cero indica que stx_atomic_write_unit_max es el límite optimizado. Pueden experimentarse escrituras más lentas cuando el tamaño de la escritura excede stx_atomic_write_unit_max_opt (cuando es distinto de cero).
stx_atomic_write_segments_max

NAME

statx - obtener información sobre un archivo

LIBRARY

Librería C estándar (libc), desde la versión 2.28.

SYNOPSIS

#include <fcntl.h>
#include <sys/stat.h>

ssize_t statx(int dirfd,
                            const char *pathname,
                            const unsigned int *flags,
                            const unsigned int *mask,
                            struct statx *statxbuf);

DESCRIPTION

La llamada al sistema statx recupera información sobre un archivo especificado por pathname. El argumento dirfd es un descriptor de archivo que especifica un directorio en el que se resolverá pathname si este es relativo. Si pathname es una ruta absoluta, dirfd se ignora. Si dirfd es AT_FDCWD, entonces pathname se resuelve con respecto al directorio de trabajo actual.

Los argumentos flags y mask se utilizan para controlar el comportamiento de la llamada al sistema y los campos de la estructura statx que se rellenarán. flags y mask son punteros a enteros sin signo de 32 bits. Solo se utilizan los 16 bits inferiores de flags.

El argumento mask especifica qué campos de la estructura statx se deben rellenar. Solo se rellenarán los campos cuyos bits correspondientes estén establecidos en mask. El valor STATX_ALL (0xFFFFFFFF) rellena todos los campos disponibles.

La estructura statx se define como sigue:

struct statx {
    unsigned int     stx_mask;    /* Máscara de los campos presentes */
    unsigned int     stx_blksize; /* Tamaño preferido para I/O de bloque */
    unsigned long long stx_attributes; /* Atributos del archivo */
    unsigned int     stx_nlink;   /* Número de enlaces duros */
    unsigned int     stx_uid;     /* ID de usuario */
    unsigned int     stx_gid;     /* ID de grupo */
    unsigned int     stx_mode;    /* Permisos y tipo de archivo */
    unsigned long long stx_size;    /* Tamaño del archivo en bytes */
    unsigned int     stx_હો;     /* Contar bloques de disco */
    unsigned int     stx_atime_nsecs; /* Nanosegundos de tiempo de acceso */
    unsigned int     stx_mtime_nsecs; /* Nanosegundos de tiempo de modificación */
    unsigned int     stx_ctime_nsecs; /* Nanosegundos de tiempo de cambio */
    unsigned long long stx_btime_sec;  /* Segundos de tiempo de creación */
    unsigned int     stx_btime_nsecs; /* Nanosegundos de tiempo de creación */
    unsigned int     stx_dev_major; /* ID principal del dispositivo */
    unsigned int     stx_dev_minor; /* ID menor del dispositivo */
    unsigned int     stx_ino;     /* Número de inodo */
    unsigned int     stx_atime_status; /* Estado de tiempo de acceso */
    unsigned int     stx_mtime_status; /* Estado de tiempo de modificación */
    unsigned int     stx_ctime_status; /* Estado de tiempo de cambio */
    unsigned int     stx_btime_status; /* Estado de tiempo de creación */
    unsigned int     stx_rdev_major; /* ID principal del dispositivo de caracteres */
    unsigned int     stx_rdev_minor; /* ID menor del dispositivo de caracteres */
    unsigned long long stx_parent_ino; /* Inodo del directorio padre */
    unsigned int     stx_attributes_mask; /* Máscara de atributos válidos */
    unsigned int     stx_projid_major; /* ID principal del proyecto */
    unsigned int     stx_projid_minor; /* ID menor del proyecto */
};

El campo stx_mask se establece con los bits de máscara de los campos válidos en la estructura statxbuf.

El campo stx_attributes contiene un conjunto de indicadores ORed que indican atributos adicionales del archivo. Tenga en cuenta que cualquier atributo que no se indique como compatible en stx_attributes_mask no tiene un valor utilizable aquí. Los bits en stx_attributes_mask se corresponden bit a bit con stx_attributes.

Los indicadores son los siguientes:

STATX_TYPE
El tipo de archivo está presente.
STATX_MODE
Los permisos del archivo están presentes.
STATX_NLINK
El número de enlaces duros está presente.
STATX_UID
El ID de usuario está presente.
STATX_GID
El ID de grupo está presente.
STATX_SIZE
El tamaño del archivo está presente.
STATX_BLOCKS
El número de bloques asignados al archivo está presente.
STATX_BTIME
El tiempo de creación del archivo está presente.
STATX_ATIME
El tiempo de último acceso al archivo está presente.
STATX_MTIME
El tiempo de última modificación del archivo está presente.
STATX_CTIME
El tiempo de último cambio del archivo está presente.
STATX_MNT_ID
El ID del montaje está presente.
STATX_DIOALIGN
El alineamiento de E/S directa está presente.
STATX_INODE
El número de inodo está presente.
STATX_GROUP_ведущий
El ID de grupo principal está presente.
STATX_USER_ведущий
El ID de usuario principal está presente.
STATX_ALL
Todos los campos disponibles.
STATX_BASIC_BLOCK
Equivalente a STATX_TYPE|STATX_MODE|STATX_NLINK|STATX_SIZE|STATX_BTIME|STATX_ATIME|STATX_MTIME|STATX_CTIME|STATX_INO|STATX_DEV.
STATX_DONT_SYNC
No sincronizar el archivo. Esto puede ser útil para obtener información de forma más rápida, pero los datos pueden no estar completamente actualizados.
STATX_FORCE_SYNC
Forzar la sincronización del archivo. Esto garantiza que todos los datos y metadatos se escriban en el almacenamiento antes de devolver el control. Tenga en cuenta que esto puede ser lento.

Los indicadores de flags son los siguientes:

AT_EMPTY_PATH
Si pathname es una cadena vacía, se obtendrá la información del archivo especificado por dirfd. Si dirfd es AT_FDCWD, se obtendrá la información del directorio de trabajo actual.
AT_NO_AUTOMOUNT
No montar automáticamente el sistema de archivos si pathname requiere uno.
AT_REMOUNT
Este indicador está reservado para uso futuro.
AT_SYMLINK_NOFOLLOW
Si pathname apunta a un enlace simbólico, devuelva información sobre el enlace simbólico en sí, en lugar de seguir el enlace para obtener información sobre el archivo al que apunta.

Para obtener más información sobre los campos anteriores, consulte inode(7).

Atributos del archivo

El campo stx_attributes contiene un conjunto de indicadores ORed que indican atributos adicionales del archivo. Tenga en cuenta que cualquier atributo que no se indique como compatible en stx_attributes_mask no tiene un valor utilizable aquí. Los bits en stx_attributes_mask corresponden bit por bit a stx_attributes.

Los indicadores son los siguientes:

STATX_ATTR_COMPRESSED
El archivo está comprimido por el sistema de archivos y puede requerir recursos adicionales para acceder a él.
STATX_ATTR_IMMUTABLE
El archivo no se puede modificar: no se puede eliminar ni renombrar, no se pueden crear enlaces duros a este archivo y no se pueden escribir datos en él. Consulte chattr(1).
STATX_ATTR_APPEND
El archivo solo se puede abrir en modo de adición para escritura. No se permite la escritura de acceso aleatorio. Consulte chattr(1).
STATX_ATTR_NODUMP
El archivo no es candidato para copia de seguridad cuando se ejecuta un programa de copia de seguridad como dump(8). Consulte chattr(1).
STATX_ATTR_ENCRYPTED
Se requiere una clave para que el archivo sea cifrado por el sistema de archivos.
STATX_ATTR_VERITY (desde Linux 5.5)
El archivo tiene fs-verity habilitado. No se puede escribir en él y todas las lecturas del mismo se verificarán con un hash criptográfico que cubre todo el archivo (por ejemplo, a través de un árbol de Merkle).
STATX_ATTR_WRITE_ATOMIC (desde Linux 6.11)
El archivo admite la protección contra escrituras rasgadas.
STATX_ATTR_DAX (desde Linux 5.8)
El archivo está en estado DAX (acceso directo de CPU). El estado DAX intenta minimizar los efectos de la caché de software tanto para las E/S como para los mapeos de memoria de este archivo. Requiere un sistema de archivos que se haya configurado para admitir DAX.
DAX generalmente asume que todos los accesos se realizan a través de instrucciones de carga/almacenamiento de CPU, lo que puede minimizar la sobrecarga para accesos pequeños, pero puede afectar negativamente la utilización de la CPU para transferencias grandes.
Las E/S de archivos se realizan directamente desde/hacia búferes de espacio de usuario y los E/S de memoria mapeada pueden realizarse con mapeos de memoria directos que omiten la caché de páginas del kernel.
Si bien la propiedad DAX tiende a resultar en que los datos se transfieran sincrónicamente, no proporciona las mismas garantías que el indicador O_SYNC (consulte open(2)), donde los datos y los metadatos necesarios se transfieren juntos.
Un archivo DAX puede admitir el mapeo con el indicador MAP_SYNC, que permite a un programa utilizar instrucciones de vaciado de caché de CPU para persistir las operaciones de almacenamiento de CPU sin un fsync(2) explícito. Consulte mmap(2) para obtener más información.
STATX_ATTR_MOUNT_ROOT (desde Linux 5.8)
El archivo es la raíz de un montaje.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EACCES
Se deniega el permiso de búsqueda para uno de los directorios en el prefijo de ruta de pathname. (Consulte también path_resolution(7)).
EBADF
pathname es relativo pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
pathname o statxbuf apuntan a una ubicación fuera del espacio de direcciones accesible del proceso o son NULL (excepto desde Linux 6.11 si se especifica AT_EMPTY_PATH en flags, se permite que pathname sea NULL).
EINVAL
Se especificó un indicador no válido en flags.
EINVAL
Se especificó un indicador reservado en mask. (Actualmente, existe un indicador de este tipo, designado por la constante STATX__RESERVED, con el valor 0x80000000U).
ELOOP
Se encontraron demasiados enlaces simbólicos al recorrer el nombre de la ruta.
ENAMETOOLONG
pathname es demasiado largo.
ENOENT
Un componente de pathname no existe, o pathname es una cadena vacía y no se especificó AT_EMPTY_PATH en flags.
ENOMEM
Memoria insuficiente (es decir, memoria del kernel).
ENOTDIR
Un componente del prefijo de ruta de pathname no es un directorio o pathname es relativo y dirfd es un descriptor de archivo que se refiere a un archivo que no es un directorio.
