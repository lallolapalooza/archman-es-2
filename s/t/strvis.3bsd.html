DESCRIPCIÓN

La función vis() copia en dst una cadena que representa el carácter c. Si c no necesita codificación, se copia sin alterar. La cadena se termina con nulo y se devuelve un puntero al final de la cadena. La longitud máxima de cualquier codificación es de cuatro bytes (sin incluir el NUL final); por lo tanto, al codificar un conjunto de caracteres en un búfer, el tamaño del búfer debe ser cuatro veces el número de bytes codificados, más uno para el NUL final. El parámetro flag se utiliza para alterar el rango por defecto de caracteres considerados para la codificación y para alterar la representación visual. El carácter adicional, nextc, solo se utiliza al seleccionar el formato de codificación VIS_CSTYLE (explicado a continuación).

Las funciones strvis(), stravis(), strnvis(), strvisx(), y strnvisx() copian en dst una representación visual de la cadena src. Las funciones strvis() y strnvis() codifican caracteres de src hasta el primer NUL. Las funciones strvisx() y strnvisx() codifican exactamente len caracteres de src (esto es útil para codificar un bloque de datos que puede contener NUL). Ambas formas terminan dst con NUL. El tamaño de dst debe ser cuatro veces el número de bytes codificados de src (más uno para el NUL). Ambas formas devuelven el número de caracteres en dst (sin incluir el NUL final). Las funciones svis(), snvis(), strsvis(), strsnvis(), strsvisx(), strsnvisx(), y strsenvisx() corresponden a vis(), nvis(), strvis(), strnvis(), strvisx(), strnvisx(), y strenvisx() pero tienen un argumento adicional extra, apuntando a una lista de caracteres terminada en NUL. Estos caracteres se copiarán codificados o con barra invertida escapada en dst. Estas funciones son útiles, por ejemplo, para eliminar el significado especial de ciertos caracteres para los shells.

La codificación es una representación única e invertible compuesta enteramente de caracteres gráficos; puede ser decodificada a su forma original utilizando las funciones unvis(3bsd), strunvis(3bsd) o strnunvis(3bsd).

Hay dos parámetros que se pueden controlar: el rango de caracteres que se codifican (solo se aplica a vis(), nvis(), strvis(), strnvis(), strvisx(), y strnvisx()), y el tipo de representación utilizada. Por defecto, todos los caracteres no gráficos, excepto el espacio, el tabulador y el salto de línea, se codifican (ver isgraph(3)). Las siguientes banderas alteran esto:

VIS_DQ
También codifica las comillas dobles.
VIS_GLOB
También codifica los caracteres mágicos (‘*’, ‘?’, ‘[’, y ‘#’) reconocidos por glob(3).
VIS_SHELL
También codifica los meta-caracteres utilizados por los shells (además de los caracteres glob): (‘'’, ‘`’, ‘"’, ‘;’, ‘&’, ‘<’, ‘>’, ‘(’, ‘)’, ‘|’, ‘]’, ‘\’, ‘$’, ‘!’, ‘^’, y ‘~’).
VIS_SP
También codifica el espacio.
VIS_TAB
También codifica el tabulador.
VIS_NL
También codifica el salto de línea.
VIS_WHITE
Sinónimo de VIS_SP | VIS_TAB | VIS_NL.
VIS_META
Sinónimo de VIS_WHITE | VIS_GLOB | VIS_SHELL.
VIS_SAFE
Solo codifica caracteres “inseguros”. Inseguro significa caracteres de control que pueden hacer que los terminales comunes realicen funciones inesperadas. Actualmente, esta forma permite que el espacio, el tabulador, el salto de línea, el retroceso, la campana y el retorno de carro —además de todos los caracteres gráficos— no se codifiquen.

(Las banderas anteriores no tienen efecto para svis(), snvis(), strsvis(), strsnvis(), strsvisx(), y strsnvisx(). Al usar estas funciones, coloque todos los caracteres gráficos que se van a codificar en una matriz apuntada por extra. En general, el carácter de barra invertida debe incluirse en esta matriz, consulte la advertencia sobre el uso de la bandera VIS_NOSLASH a continuación).

Hay seis formas de codificación. Todas las formas utilizan el carácter de barra invertida ‘\’ para introducir una secuencia especial; se utilizan dos barras invertidas para representar una barra invertida real, excepto VIS_HTTPSTYLE que usa ‘%’, o VIS_MIMESTYLE que usa ‘=’. Estos son los formatos visuales:

(predeterminado)
Usa una ‘M’ para representar meta-caracteres (caracteres con el 8vo bit establecido), y usa un acento circunflejo ‘^’ para representar caracteres de control (ver iscntrl(3)). Los siguientes formatos se utilizan:
\^C
Representa el carácter de control ‘C’. Cubre los caracteres ‘\000’ hasta ‘\037’, y ‘\177’ (como ‘\^?’).
\M-C
Representa el carácter ‘C’ con el 8vo bit establecido. Cubre los caracteres ‘\241’ hasta ‘\376’.
\M^C
Representa el carácter de control ‘C’ con el 8vo bit establecido. Cubre los caracteres ‘\200’ hasta ‘\237’, y ‘\377’ (como ‘\M^?’).
\040
Representa el espacio ASCII.
\240
Representa el meta-espacio.
VIS_CSTYLE
Utiliza secuencias de barra invertida al estilo C para representar caracteres no imprimibles estándar. Las siguientes secuencias se usan para representar los caracteres indicados: 
\a — BEL (007)
\b — BS (010)
\f — NP (014)
\n — NL (012)
\r — CR (015)
\s — SP (040)
\t — HT (011)
\v — VT (013)
\0 — NUL (000)

Al usar este formato, se examina el parámetro nextc para determinar si un carácter NUL puede codificarse como ‘\0’ en lugar de ‘\000’. Si nextc es un dígito octal, se utiliza la última representación para evitar ambigüedades.

Los caracteres no imprimibles sin secuencias de barra invertida al estilo C utilizan la representación predeterminada.

VIS_OCTAL
Usa una secuencia octal de tres dígitos. El formato es ‘\ddd’ donde d representa un dígito octal.
VIS_CSTYLE | VIS_OCTAL
Igual que VIS_CSTYLE excepto que los caracteres no imprimibles sin secuencias de barra invertida al estilo C utilizan una secuencia octal de tres dígitos.
VIS_HTTPSTYLE

FLAGS

The following flags are available:

VIS_DQ
If the character is a double quote, it is represented as \". If the character is a backslash, it is represented as \\. If the character is a newline, it is represented as \n. If the character is a tab, it is represented as \t. Otherwise, if the character is a standard ASCII character, it is represented as itself. Otherwise, the character is represented in the form ‘%xx’ where x represents a lower case hexadecimal digit.
VIS_MIMESTYLE
Use MIME Quoted-Printable encoding as described in RFC 2045, only don't break lines and don't handle CRLF. The form is ‘=XX’ where X represents an upper case hexadecimal digit.

There is one additional flag, VIS_NOSLASH, which inhibits the doubling of backslashes and the backslash before the default format (that is, control characters are represented by ‘^C’ and meta characters as ‘M-C’). With this flag set, the encoding is ambiguous and non-invertible.

SOPORTE DE CARACTERES MULTIBYTE

Estas funciones soportan entrada de caracteres multibyte. La conversión de codificación está influenciada por la configuración de la variable de entorno LC_CTYPE, que define el conjunto de caracteres que pueden copiarse sin codificación.

Si se establece VIS_NOLOCALE, el procesamiento se realiza asumiendo la configuración regional C y anulando cualquier otra configuración del entorno.

Cuando hay datos de 8 bits en la entrada, LC_CTYPE debe establecerse en la configuración regional correcta o en la configuración regional C. Si las configuraciones regionales de los datos y la conversión no coinciden, el reconocimiento de caracteres multibyte puede fallar y la codificación se realizará byte a byte en su lugar.

Como se indicó anteriormente, dst debe ser cuatro veces el número de bytes procesados de src. Pero tenga en cuenta que cada carácter multibyte puede tener hasta MB_LEN_MAX bytes, por lo que en términos de caracteres multibyte, dst debe ser cuatro veces MB_LEN_MAX veces el número de caracteres procesados de src.

ENTORNO

LC_CTYPE
Especifica la configuración regional de los datos de entrada. Establézcalo en C si la configuración regional de los datos de entrada es desconocida.

ERRORES

Las funciones nvis() y snvis() devolverán NULL y las funciones strnvis(), strnvisx(), strsnvis(), y strsnvisx(), devolverán -1 cuando el tamaño del búfer de destino dlen no sea suficiente para realizar la conversión, estableciendo errno en:

[ENOSPC]
El tamaño del búfer de destino no es lo suficientemente grande para realizar la conversión.

HISTORIA

Las funciones vis(), strvis(), y strvisx() aparecieron por primera vez en 4.4BSD. Las funciones svis(), strsvis(), y strsvisx() aparecieron en NetBSD 1.5. Las versiones con tamaño de búfer limitado de las funciones (nvis(), strnvis(), strnvisx(), snvis(), strsnvis(), y strsnvisx()) aparecieron en NetBSD 6.0 y FreeBSD 9.2. El soporte de caracteres multibyte se añadió en NetBSD 7.0 y FreeBSD 9.2.
