st(4) Manual de controladores de dispositivos st(4)

NOMBRE

st - dispositivo de cinta SCSI

SINOPSIS

#include <sys/mtio.h>
int ioctl(int fd, int request [, (void *)arg3]);
int ioctl(int fd, MTIOCTOP, (struct mtop *)mt_cmd);
int ioctl(int fd, MTIOCGET, (struct mtget *)mt_status);
int ioctl(int fd, MTIOCPOS, (struct mtpos *)mt_pos);

DESCRIPCIÓN

El controlador st proporciona la interfaz a una variedad de dispositivos de cinta SCSI. Actualmente, el controlador toma el control de todos los dispositivos detectados de tipo "sequential-access". El controlador st utiliza el número de dispositivo principal 9.

Cada dispositivo utiliza ocho números de dispositivo menores. Los cinco bits inferiores de los números menores se asignan secuencialmente en el orden de detección. En el kernel 2.6, los bits superiores a los ocho bits inferiores se concatenan a los cinco bits inferiores para formar el número de cinta. Los números menores se pueden agrupar en dos conjuntos de cuatro números: los números de dispositivo principales (rebobinado automático), n, y los números de dispositivo "sin rebobinado", (n + 128). Los dispositivos abiertos utilizando el número de dispositivo principal enviarán un comando REWIND al cerrarse. Los dispositivos abiertos utilizando el número de dispositivo "sin rebobinado" no lo harán. (Tenga en cuenta que usar un dispositivo de rebobinado automático para posicionar la cinta con, por ejemplo, mt no conduce al resultado deseado: la cinta se rebobina después del comando mt y el siguiente comando comienza desde el principio de la cinta).

Dentro de cada grupo, hay cuatro números menores disponibles para definir dispositivos con diferentes características (tamaño de bloque, compresión, densidad, etc.). Cuando el sistema se inicia, solo el primer dispositivo está disponible. Los otros tres se activan cuando se definen las características predeterminadas (ver más abajo). (Cambiando constantes en tiempo de compilación, es posible cambiar el número máximo de unidades de cinta y el número de números menores para cada unidad. La asignación predeterminada permite controlar 32 unidades de cinta. Por ejemplo, es posible controlar hasta 64 unidades de cinta con dos números menores para diferentes opciones).

Los dispositivos se crean típicamente mediante:


mknod -m 666 /dev/st0 c 9 0
mknod -m 666 /dev/st0l c 9 32
mknod -m 666 /dev/st0m c 9 64
mknod -m 666 /dev/st0a c 9 96
mknod -m 666 /dev/nst0 c 9 128
mknod -m 666 /dev/nst0l c 9 160
mknod -m 666 /dev/nst0m c 9 192
mknod -m 666 /dev/nst0a c 9 224

No existe un dispositivo de bloque correspondiente.

El controlador utiliza un búfer interno que debe ser lo suficientemente grande como para contener al menos un bloque de cinta. Antes de Linux 2.1.121, el búfer se asignaba como un bloque contiguo. Esto limita el tamaño del bloque al bloque contiguo de memoria más grande que el asignador del kernel puede proporcionar. El límite es actualmente 128 KiB para arquitecturas de 32 bits y 256 KiB para arquitecturas de 64 bits. En kernels más recientes, el controlador asigna el búfer en varias partes si es necesario. Por defecto, el número máximo de partes es 16. Esto significa que el tamaño máximo del bloque es muy grande (2 MiB si la asignación de 16 bloques de 128 KiB tiene éxito).

El tamaño del búfer interno del controlador está determinado por una constante en tiempo de compilación que se puede anular con una opción de arranque del kernel. Además de esto, el controlador intenta asignar un búfer temporal más grande en tiempo de ejecución si es necesario. Sin embargo, la asignación en tiempo de ejecución de grandes bloques contiguos de memoria puede fallar y es aconsejable no depender demasiado de la asignación dinámica de búferes antes de Linux 2.1.121 (esto también se aplica a la carga a demanda del controlador con kerneld o kmod).

El controlador no soporta específicamente ninguna marca o modelo de unidad de cinta. Después del inicio del sistema, las opciones del dispositivo de cinta se definen por el firmware de la unidad. Por ejemplo, si el firmware de la unidad selecciona el modo de bloque fijo, el dispositivo de cinta usa el modo de bloque fijo. Las opciones se pueden cambiar con llamadas explícitas a ioctl(2) y permanecen en vigor cuando el dispositivo se cierra y reabre. La configuración de las opciones afecta tanto al dispositivo de rebobinado automático como al de no rebobinado.

Se pueden especificar diferentes opciones para los diferentes dispositivos dentro del subgrupo de cuatro. Las opciones entran en vigor cuando se abre el dispositivo. Por ejemplo, el administrador del sistema puede definir un dispositivo que escriba en modo de bloque fijo con un determinado tamaño de bloque, y otro que escriba en modo de bloque variable (si la unidad soporta ambos modos).

El controlador soporta particiones de cinta si son soportadas por la unidad. (Tenga en cuenta que las particiones de cinta no tienen nada que ver con las particiones de disco. Una cinta particionada puede verse como varias cintas lógicas dentro de un mismo medio.) El soporte de particiones debe habilitarse con una llamada a ioctl(2). La ubicación de la cinta se conserva dentro de cada partición al cambiar de partición. La partición utilizada para operaciones posteriores de cinta se selecciona con una llamada a ioctl(2). El cambio de partición se ejecuta junto con la siguiente operación de cinta para evitar movimientos innecesarios de la cinta. El número máximo de particiones en una cinta se define por una constante en tiempo de compilación (originalmente cuatro). El controlador contiene una llamada a ioctl(2) que puede formatear una cinta con una o dos particiones.

El dispositivo /dev/tape suele crearse como un enlace duro o simbólico al dispositivo de cinta predeterminado en el sistema.

A partir de Linux 2.6.2, el controlador exporta en el directorio sysfs /sys/class/scsi_tape los dispositivos conectados y algunos parámetros asignados a los dispositivos.

Transferencia de datos

El controlador soporta la operación tanto en modo de bloque fijo como en modo de bloque variable (si es soportado por la unidad). En modo de bloque fijo, la unidad escribe bloques del tamaño especificado y el tamaño del bloque no depende de los recuentos de bytes de las llamadas de escritura. En modo de bloque variable, se escribe un bloque de cinta por cada llamada de escritura y el recuento de bytes determina el tamaño del bloque de cinta correspondiente. Tenga en cuenta que los bloques de la cinta no contienen ninguna información sobre el modo de escritura: al leer, lo único importante es usar comandos que acepten los tamaños de bloque de la cinta.

En modo de bloque variable, el recuento de bytes de lectura no tiene que coincidir exactamente con el tamaño del bloque de cinta. Si el recuento de bytes es mayor que el siguiente bloque en la cinta, el controlador devuelve los datos y la función devuelve el tamaño real del bloque. Si el tamaño del bloque es mayor que el recuento de bytes, se devuelve un error.

En modo de bloque fijo, los recuentos de bytes de lectura pueden ser arbitrarios si la memorización en búfer está habilitada, o un múltiplo del tamaño del bloque de cinta si la memorización en búfer está deshabilitada. Antes de Linux 2.1.121, las escrituras con recuento de bytes arbitrario están permitidas si la memorización en búfer está habilitada. En todos los demás casos (antes de Linux 2.1.121 con memorización en búfer deshabilitada o kernel más nuevo), el recuento de bytes de escritura debe ser un múltiplo del tamaño del bloque de cinta.

En Linux 2.6, el controlador intenta utilizar transferencias directas entre el búfer del usuario y el dispositivo. Si esto no es posible, se utiliza el búfer interno del controlador. Las razones para no utilizar transferencias directas incluyen la alineación incorrecta del búfer del usuario (el valor predeterminado es de 512 bytes, pero esto puede ser modificado por el controlador HBA), una o más páginas del búfer del usuario no alcanzables por el adaptador SCSI, etc.

Se escribe una marca de archivo automáticamente en la cinta si la última operación de cinta antes de cerrar fue una escritura.

Cuando se encuentra una marca de archivo al leer, ocurre lo siguiente. Si quedan datos en el búfer cuando se encuentra la marca de archivo, se devuelven los datos almacenados en el búfer. La siguiente lectura devuelve cero bytes. La siguiente lectura devuelve datos del siguiente archivo. El final de los datos grabados se señala devolviendo cero bytes en dos llamadas de lectura consecutivas. La tercera lectura devuelve un error.

Ioctls

El controlador soporta tres solicitudes ioctl(2). Las solicitudes no reconocidas por el controlador st se pasan al controlador SCSI. Las definiciones a continuación son de /usr/include/linux/mtio.h:

MTIOCTOP — realizar una operación de cinta

Esta solicitud toma un argumento de tipo (struct mtop *)

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

> . No todas las unidades admiten todas las operaciones. El controlador devuelve un error EIO si la unidad rechaza una operación.


/* Estructura para MTIOCTOP - comando de operación de cinta magnética: */
struct mtop {
    short   mt_op;       /* operaciones definidas a continuación */
    int     mt_count;    /* cuántas de ellas */
};

Operaciones de cinta magnética para uso normal de cinta:

MTBSF
Retrocede mt_count marcas de archivo.
MTBSFM
Retrocede mt_count marcas de archivo. Reposiciona la cinta al lado EOT de la última marca de archivo.
MTBSR
Retrocede mt_count registros (bloques de cinta).
MTBSS
Retrocede mt_count marcas de conjunto.
MTCOMPRESSION
Habilita la compresión de datos de cinta dentro de la unidad si mt_count no es cero y deshabilita la compresión si mt_count es cero. Este comando utiliza la página de modo 15 compatible con la mayoría de las DAT.
MTEOM
Ve al final del medio grabado (para añadir archivos).
MTERASE
Borra la cinta. Con Linux 2.6, se realiza un borrado corto (marca la cinta como vacía) si el argumento es cero. De lo contrario, se realiza un borrado largo (borra todo).
MTFSF
Avanza mt_count marcas de archivo.
MTFSFM
Avanza mt_count marcas de archivo. Reposiciona la cinta al lado BOT de la última marca de archivo.
MTFSR
Avanza mt_count registros (bloques de cinta).
MTFSS
Avanza mt_count marcas de conjunto.
MTLOAD
Ejecuta el comando de carga SCSI. Hay un caso especial disponible para algunos cargadores automáticos HP. Si mt_count es la constante MT_ST_HPLOADER_OFFSET más un número, el número se envía a la unidad para controlar el cargador automático.
MTLOCK
Bloquea la puerta de la unidad de cinta.
MTMKPART
Formatea la cinta en una o dos particiones. Si mt_count es positivo, indica el tamaño de la partición 1 y la partición 0 contiene el resto de la cinta. Si mt_count es cero, la cinta se formatea en una partición. Desde Linux 4.6, un mt_count negativo especifica el tamaño de la partición 0 y el resto de la cinta contiene la partición 1. El orden físico de las particiones depende de la unidad. Este comando no está permitido para una unidad a menos que el soporte de particiones esté habilitado para la unidad (ver MT_ST_CAN_PARTITIONS abajo).
MTNOP
Sin operación (no-op) — vacía el búfer del controlador como efecto secundario. Debe usarse antes de leer el estado con MTIOCGET.
MTOFFL
Retrocede y pone la unidad fuera de línea.
MTRESET
Restablece la unidad.
MTRETEN
Re-tensar la cinta.
MTREW
Retrocede.
MTSEEK
Busca el número de bloque de cinta especificado en mt_count. Esta operación requiere una unidad SCSI-2 que admita el comando LOCATE (dirección específica del dispositivo) o una unidad SCSI-1 compatible con Tandberg (Tandberg, Archive Viper, Wangtek, ...). El número de bloque debe ser uno que fue devuelto previamente por MTIOCPOS si se utilizan direcciones específicas del dispositivo.
MTSETBLK
Establece la longitud del bloque de la unidad al valor especificado en mt_count. Una longitud de bloque de cero establece la unidad en modo de tamaño de bloque variable.
MTSETDENSITY
Establece la densidad de la cinta al código en mt_count. Los códigos de densidad compatibles con una unidad se pueden encontrar en la documentación de la unidad.
MTSETPART
La partición activa se cambia a mt_count. Las particiones se numeran a partir de cero. Este comando no está permitido para una unidad a menos que el soporte de particiones esté habilitado para la unidad (ver MT_ST_CAN_PARTITIONS abajo).
MTUNLOAD
Ejecuta el comando de descarga SCSI (no expulsa la cinta).
MTUNLOCK
Desbloquea la puerta de la unidad de cinta.
MTWEOF
Escribe mt_count marcas de archivo.
MTWSM
Escribe mt_count marcas de conjunto.

Operaciones de cinta magnética para la configuración de opciones del dispositivo (por el superusuario):

MTSETDRVBUFFER
Establece varias opciones de unidad y controlador según los bits codificados en mt_count. Estos consisten en el modo de búfer de la unidad, un conjunto de opciones booleanas del controlador, el umbral de escritura del búfer, los valores predeterminados para el tamaño del bloque y la densidad, y los tiempos de espera (solo desde Linux 2.1). Una sola operación puede afectar solo a un elemento de la siguiente lista (los booleanos cuentan como un elemento).
Se utilizará un valor que tenga ceros en los 4 bits de orden superior para establecer el modo de búfer de la unidad. Los modos de búfer son:
0
La unidad no informará estado GOOD en los comandos de escritura hasta que los bloques de datos se escriban realmente en el medio.
1
La unidad puede informar estado GOOD en los comandos de escritura tan pronto como todos los datos se hayan transferido al búfer interno de la unidad.
2
La unidad puede informar estado GOOD en los comandos de escritura tan pronto como (a) todos los datos se hayan transferido al búfer interno de la unidad y (b) todos los datos almacenados en búfer de diferentes iniciadores se hayan escrito correctamente en el medio.
Para controlar el umbral de escritura, el valor en mt_count debe incluir la constante MT_ST_WRITE_THRESHOLD combinada con OR a nivel de bits con un recuento de bloques en los 28 bits inferiores. El recuento de bloques se refiere a bloques de 1024 bytes, no al tamaño físico del bloque en la cinta. El umbral no puede exceder el tamaño del búfer interno del controlador (ver DESCRIPCIÓN, arriba).
Para establecer y borrar las opciones booleanas, el valor en mt_count debe incluir una de las constantes MT_ST_BOOLEANS, MT_ST_SETBOOLEANS, MT_ST_CLEARBOOLEANS o MT_ST_DEFBOOLEANS combinada con OR a nivel de bits con la combinación deseada de las siguientes opciones. Usando MT_ST_BOOLEANS las opciones se pueden establecer a los valores definidos en los bits correspondientes. Con MT_ST_SETBOOLEANS las opciones se pueden establecer selectivamente y con MT_ST_DEFBOOLEANS se pueden borrar selectivamente.
Las opciones predeterminadas para un dispositivo de cinta se establecen con MT_ST_DEFBOOLEANS. Un dispositivo de cinta inactivo (por ejemplo, dispositivo con menor 32 o 160) se activa cuando se definen por primera vez las opciones predeterminadas para él. Un dispositivo activado hereda del dispositivo activado al inicio las opciones no establecidas explícitamente.
Las opciones booleanas son:
MT_ST_BUFFER_WRITES (Predeterminado: verdadero)
Almacena en búfer todas las operaciones de escritura en modo de bloque fijo. Si esta opción es falsa y la unidad utiliza un tamaño de bloque fijo, entonces todas las operaciones de escritura deben ser múltiplos del tamaño del bloque. Esta opción debe establecerse en falso para escribir archivos multivolumen fiables.
MT_ST_ASYNC_WRITES (Predeterminado: verdadero)
Cuando esta opción es verdadera, las operaciones de escritura se devuelven inmediatamente sin esperar a que los datos se transfieran a la unidad si los datos caben en el búfer del controlador. El umbral de escritura determina cuán lleno debe estar el búfer antes de emitir un nuevo comando de escritura SCSI. Cualquier error informado por la unidad se retendrá hasta la próxima operación. Esta opción debe establecerse en falso para escribir archivos multivolumen fiables.
MT_ST_READ_AHEAD (Predeterminado: verdadero)
Esta opción hace que el controlador proporcione búfer de lectura y avance de lectura en modo de bloque fijo. Si esta opción es falsa y la unidad utiliza un tamaño de bloque fijo, entonces todas las operaciones de lectura deben ser un múltiplo del tamaño del bloque.
MT_ST_TWO_FM (Predeterminado: falso)
Esta opción modifica el comportamiento del controlador cuando se cierra un archivo. La acción normal es escribir una sola marca de archivo. Si la opción es verdadera, el controlador escribirá dos marcas de archivo y retrocederá sobre la segunda.
Nota: Esta opción no debe establecerse en verdadero para las unidades de cinta QIC, ya que no pueden sobrescribir una marca de archivo. Estas unidades detectan el final de los datos grabados probando cinta en blanco en lugar de dos marcas de archivo consecutivas. La mayoría de las otras unidades actuales también detectan el final de los datos grabados y el uso de dos marcas de archivo generalmente solo es necesario al intercambiar cintas con otros sistemas.
MT_ST_DEBUGGING (Predeterminado: falso)
Esta opción activa varios mensajes de depuración del controlador (efectiva solo si el controlador se compiló con DEBUG definido como distinto de cero).
MT_ST_FAST_EOM (Predeterminado: falso)
Esta opción hace que la operación MTEOM se envíe directamente a la unidad, lo que podría acelerar la operación pero hacer que el controlador pierda la pista del número de archivo actual devuelto normalmente por la solicitud MTIOCGET. Si MT_ST_FAST_EOM es falso, el controlador responderá a una solicitud MTEOM avanzando sobre los archivos.
MT_ST_AUTO_LOCK (Predeterminado: falso)
Cuando esta opción es verdadera, la puerta de la unidad se bloquea cuando se abre el archivo del dispositivo y se desbloquea cuando se cierra.

IOCTLS

The magnetic tape device driver supports the following ioctls:

MTIOCTOP — tape operations

This request takes an argument of type (struct mtop *).


/* structure for MTIOCTOP - mag tape operation command */
struct mtop {
    int   mt_op;    /* operation */
    int   mt_count; /* how many times to repeat the operation */
};
mt_op
The operation to perform. The header file defines the following tape operations:
MTNOP
No operation (a valid no-op).
MTREW
Rewind the tape file.
MTOFFL
Rewind the tape and put it in a state on which it can be unloaded.
MTREWEN
Rewind the tape, then space over the End Of Medium. If the tape is already at EOD, the tape is rewound and put in a state on which it can be unloaded.
MTBSF
Space backward over the next mt_count files.
MTFSR
Space forward over the next mt_count files.
MTFSF
Space forward over the next mt_count files.
MTBSS
Space backward over the next mt_count records.
MTFSD
Space forward over the next mt_count records.
MTFSE
Space forward to the next End-Of-File mark. If EOM is encountered before an EOF, the operation fails.
MTFSM
Space forward over the next mt_count filemarks.
MTSEEK
Seek to the mt_count-th file on the tape. File numbers are zero based. This implies that to find the first file, the count must be zero. This operation is only supported on drives that support the READ POSITION command.
MTSETDRVBUFFER
Set drive buffering options. The value for mt_count is a bitmask composed of the following flags:
MT_ST_BOOLEANS
This is a mask for all boolean options. The driver will not allow any boolean options to be set that are not defined.
MT_ST_BUFFER_WRITES
(Default: true) If this option is set, the driver will buffer writes to the tape. This means that the driver will return from a write request when the data has been copied into the driver's buffer, and not when the data has been physically written to the tape. This option is ignored if MT_ST_ASYNC_WRITES is set.
MT_ST_ASYNC_WRITES
(Default: false) If this option is set, writes to the tape are asynchronous. This means that the driver will return from a write request when the data has been copied into the driver's buffer, and not when the data has been physically written to the tape. This option causes the driver to return the buffer full error if the buffer is full, even if the device is not ready. It also means that the driver will not automatically flush the buffer on closing the device, so the device may be closed before all data has been written.
MT_ST_READ_AHEAD
(Default: true) If this option is set, the driver will perform read-ahead operations. This means that when a read request has been satisfied, the driver will read the next block from the tape into the driver's buffer in anticipation of the next read request.
MT_ST_COLLISION_EVNP
(Default: false) If this option is set, the driver will try to detect buffer collisions. This feature is intended for drivers that can support both buffered and unbuffered writes. The default driver behaviour is to assume that it is always dealing with buffered writes.
MT_ST_NO_BLKLIM
(Default: false) Some drives do not accept the READ BLOCK LIMITS SCSI command. If this is used, the driver does not use the command. The drawback is that the driver cannot check before sending commands if the selected block size is acceptable to the drive.
MT_ST_CAN_PARTITIONS
(Default: false) This option enables support for several partitions within a tape. The option applies to all devices linked to a drive.
MT_ST_SCSI2LOGICAL
(Default: false) This option instructs the driver to use the logical block addresses defined in the SCSI-2 standard when performing the seek and tell operations (both with MTSEEK and MTIOCPOS commands and when changing tape partition). Otherwise, the device-specific addresses are used. It is highly advisable to set this option if the drive supports the logical addresses because they count also filemarks. There are some drives that support only the logical block addresses.
MT_ST_SYSV
(Default: false) When this option is enabled, the tape devices use the System V semantics. Otherwise, the BSD semantics are used. The most important difference between the semantics is what happens when a device used for reading is closed: in System V semantics the tape is spaced forward past the next filemark if this has not happened while using the device. In BSD semantics the tape position is not changed.
MT_ST_CAN_BSR
(Default: false) When read-ahead is used, the tape must sometimes be spaced backward to the correct position when the device is closed and the SCSI command to space backward over records is used for this purpose. Some older drives can't process this command reliably and this option can be used to instruct the driver not to use the command. The end result is that, with read-ahead and fixed-block mode, the tape may not be correctly positioned within a file when the device is closed. With Linux 2.6, the default is true for drives supporting SCSI-3.
MT_ST_NO_WAIT
(Default: false) Enables immediate mode (i.e., don't wait for the command to finish) for some commands (e.g., rewind).
MT_ST_DEF_WRITES
(Default: false) The tape options (block size, mode, compression, etc.) may change when changing from one device linked to a drive to another device linked to the same drive depending on how the devices are defined. This option defines when the changes are enforced by the driver using SCSI-commands and when the drives auto-detection capabilities are relied upon. If this option is false, the driver sends the SCSI-commands immediately when the device is changed. If the option is true, the SCSI-commands are not sent until a write is requested. In this case, the drive firmware is allowed to detect the tape structure when reading and the SCSI-commands are used only to make sure that a tape is written according to the correct specification.
MT_ST_DEF_BLKSIZE
The default block size for a device can be set with this option. The value is ORed with the operation code.
MT_ST_DEFDENSITY
The default density code can be set with this option. The value is ORed with the operation code.
MT_ST_SET_TIMEOUT
The timeout value in seconds can be set with this option. The value is ORed with the operation code. This command can be used to set more practical values for a specific drive. The timeouts set for one device apply for all devices linked to the same drive.
MT_ST_SET_LONG_TIMEOUT
The long timeout value in seconds can be set with this option. The value is ORed with the operation code. This command can be used to set more practical values for a specific drive. The timeouts set for one device apply for all devices linked to the same drive.
MT_ST_SEL_CLN
This subcommand sets the method used by the drive to return cleaning information. The value is ORed with the operation code. If the value is zero, the cleaning bit is always zero. If the value is one, the TapeAlert data defined in the SCSI-3 standard is used (not yet implemented). Values 2–17 are reserved. If the lowest eight bits are >= 18, bits from the extended sense data are used. The bits 9–16 specify a mask to select the bits to look at and the bits 17–23 specify the bit pattern to look for. If the bit pattern is zero, one or more bits under the mask indicate the cleaning request. If the pattern is nonzero, the pattern must match the masked sense data byte.

See the example below.

Example:


struct mtop mt_cmd;
mt_cmd.mt_op = MTSETDRVBUFFER;
mt_cmd.mt_count = MT_ST_BOOLEANS |
        MT_ST_BUFFER_WRITES | MT_ST_ASYNC_WRITES;
ioctl(fd, MTIOCTOP, mt_cmd);

The default block size for a device can be set with MT_ST_DEF_BLKSIZE and the default density code can be set with MT_ST_DEFDENSITY. The values for the parameters are or'ed with the operation code.

With Linux 2.1.x and later, the timeout values can be set with the subcommand MT_ST_SET_TIMEOUT ORed with the timeout in seconds. The long timeout (used for rewinds and other commands that may take a long time) can be set with MT_ST_SET_LONG_TIMEOUT. The kernel defaults are very long to make sure that a successful command is not timed out with any drive. Because of this, the driver may seem stuck even if it is only waiting for the timeout. These commands can be used to set more practical values for a specific drive. The timeouts set for one device apply for all devices linked to the same drive.

Starting from Linux 2.4.19 and Linux 2.5.43, the driver supports a status bit which indicates whether the drive requests cleaning. The method used by the drive to return cleaning information is set using the MT_ST_SEL_CLN subcommand. If the value is zero, the cleaning bit is always zero. If the value is one, the TapeAlert data defined in the SCSI-3 standard is used (not yet implemented). Values 2–17 are reserved. If the lowest eight bits are >= 18, bits from the extended sense data are used. The bits 9–16 specify a mask to select the bits to look at and the bits 17–23 specify the bit pattern to look for. If the bit pattern is zero, one or more bits under the mask indicate the cleaning request. If the pattern is nonzero, the pattern must match the masked sense data byte.

MTIOCGET — get status

This request takes an argument of type (struct mtget *).


/* structure for MTIOCGET - mag tape get status command */
struct mtget {
    long     mt_type;
    long     mt_resid;
    /* the following registers are device dependent */
    long     mt_dsreg;
    long     mt_gstat;
    long     mt_erreg;
    /* The next two fields are not always used */
    daddr_t  mt_fileno;
    daddr_t  mt_blkno;
};
mt_type
The header file defines many values for mt_type, but the current driver reports only the generic types MT_ISSCSI1 (Generic SCSI-1 tape) and MT_ISSCSI2 (Generic SCSI-2 tape).
mt_resid
contains the current tape partition number.
mt_dsreg
reports the drive's current settings for block size (in the low 24 bits) and density (in the high 8 bits). These fields are defined by MT_ST_BLKSIZE_SHIFT, MT_ST_BLKSIZE_MASK, MT_ST_DENSITY_SHIFT, and MT_ST_DENSITY_MASK.
mt_gstat
reports generic (device independent) status information. The header file defines macros for testing these status bits:
GMT_EOF(x)
The tape is positioned just after a filemark (always false after an MTSEEK operation).
GMT_BOT(x)
The tape is positioned at the beginning of the first file (always false after an MTSEEK operation).
GMT_EOT(x)
A tape operation has reached the physical End Of Tape.
GMT_SM(x)
The tape is currently positioned at a setmark (always false after an MTSEEK operation).
GMT_EOD(x)
The tape is positioned at the end of recorded data.
GMT_WR_PROT(x)
The drive is write-protected. For some drives this can also mean that the drive does not support writing on the current medium type.
GMT_ONLINE(x)
The last open(2) found the drive with a tape in place and ready for operation.
GMT_D_6250(x)
GMT_D_1600(x)
GMT_D_800(x)
This “generic” status information reports the current density setting for 9-track ½" tape drives only.
GMT_DR_OPEN(x)
The drive does not have a tape in place.
GMT_IM_REP_EN(x)
Immediate report mode. This bit is set if there are no guarantees that the data has been physically written to the tape when the write call returns. It is set zero only when the driver does not buffer data and the drive is set not to buffer data.
GMT_CLN(x)
The drive has requested cleaning. Implemented since Linux 2.4.19 and Linux 2.5.43.
mt_erreg
The only field defined in mt_erreg is the recovered error count in the low 16 bits (as defined by MT_ST_SOFTERR_SHIFT and MT_ST_SOFTERR_MASK). Due to inconsistencies in the way drives report recovered errors, this count is often not maintained (most drives do not by default report soft errors but this can be changed with a SCSI MODE SELECT command).
mt_fileno
reports the current file number (zero-based). This value is set to -1 when the file number is unknown (e.g., after MTBSS or MTSEEK).
mt_blkno
reports the block number (zero-based) within the current file. This value is set to -1 when the block number is unknown (e.g., after MTBSF, MTBSS, or MTSEEK).

MTIOCPOS — get tape position

This request takes an argument of type (struct mtpos *) and reports the drive's notion of the current tape block number, which is not the same as mt_blkno returned by MTIOCGET. This drive must be a SCSI-2 drive that supports the READ POSITION command (device-specific address) or a Tandberg-compatible SCSI-1 drive (Tandberg, Archive Viper, Wangtek, ...).


/* structure for MTIOCPOS - mag tape get position command */
struct mtpos {
    long mt_blkno;    /* current block number */
};

RETURN VALUE

On success, the ioctl() function returns 0. On error, it returns -1, and errno is set to indicate the error.

ERRORS

The return value errno is set to one of the following values:

EINVAL
An invalid operation was requested.
EIO
An I/O error occurred on the tape device.
ENFILE
The device is write-protected.
ENXIO
The device does not exist.
ENODEV
The device does not exist.
ENOMEDIUM
There is no tape in the drive.
ENOSPC
No space left on device.
EFAULT
Arg points to memory that cannot be accessed.
EBUSY
The device or resource is busy.

STANDARDS

The mt utility supports the operations described here. The ioctl calls are specific to the Linux kernel's SCSI tape driver.

HISTORY

The magnetic tape ioctl interface was introduced in Linux 1.0.18. The SCSI tape driver was added in Linux 1.2.x.

NOTAS

•
Al intercambiar datos entre sistemas, ambos sistemas deben acordar el tamaño físico del bloque de cinta. Los parámetros de una unidad después del inicio a menudo no son los que la mayoría de los sistemas operativos utilizan con estos dispositivos. La mayoría de los sistemas utilizan unidades en modo de bloque variable si la unidad admite ese modo. Esto se aplica a la mayoría de las unidades modernas, incluidas las DAT, unidades de escaneo helicoidal de 8 mm, DLT, etc. Puede ser aconsejable utilizar estas unidades en modo de bloque variable también en Linux (es decir, usar MTSETBLK o MTSETDEFBLK al inicio del sistema para establecer el modo), al menos al intercambiar datos con un sistema externo. La desventaja de esto es que se debe usar un tamaño de bloque de cinta bastante grande para obtener tasas de transferencia de datos aceptables en el bus SCSI.
•
Muchos programas (por ejemplo, tar(1)) permiten al usuario especificar el factor de bloque en la línea de comandos. Tenga en cuenta que esto determina el tamaño físico del bloque en la cinta solo en modo de bloque variable.
•
Para utilizar unidades de cinta SCSI, el controlador SCSI básico, un controlador de adaptador SCSI y el controlador de cinta SCSI deben estar configurados en el kernel o cargados como módulos. Si el controlador de cinta SCSI no está presente, la unidad se reconoce pero el soporte de cinta descrito en esta página no está disponible.
•
El controlador escribe mensajes de error en la consola/registro. Los códigos SENSE escritos en algunos mensajes se traducen automáticamente a texto si los mensajes SCSI detallados están habilitados en la configuración del kernel.
•
El búfer interno del controlador permite un buen rendimiento en modo de bloque fijo, incluso con recuentos de bytes pequeños en read(2) y write(2). Con transferencias directas, esto no es posible y puede causar sorpresas al pasar al kernel 2.6. La solución es indicar al software que utilice transferencias más grandes (a menudo indicándole que utilice bloques más grandes). Si esto no es posible, las transferencias directas se pueden deshabilitar.
