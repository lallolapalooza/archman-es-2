NOMBRE

stl2dcm - Encapsular archivo STL en formato de archivo DICOM

SINOPSIS

stl2dcm [opciones] stlfile-in dcmfile-out

DESCRIPCIÓN

La utilidad stl2dcm lee un archivo STL (stlfile-in), lo convierte a una instancia SOP de Almacenamiento STL Encapsulado DICOM y almacena los datos convertidos en un archivo de salida (dcmfile-out).

PARÁMETROS

stlfile-in   Nombre del archivo de entrada STL a encapsular
dcmfile-out  Nombre del archivo de salida DICOM ("-" para stdout)

OPCIONES

opciones generales

  -h   --help
         imprimir este texto de ayuda y salir
       --version
         imprimir información de versión y salir
       --arguments
         imprimir argumentos de línea de comandos expandidos
  -q   --quiet
         modo silencioso, no imprimir advertencias ni errores
  -v   --verbose
         modo detallado, imprimir detalles del procesamiento
  -d   --debug
         modo de depuración, imprimir información de depuración
  -ll  --log-level  [l]evel: cadena de texto
         (fatal, error, warn, info, debug, trace)
         usar nivel l para el registrador
  -lc  --log-config  [f]ilename: cadena de texto
         usar archivo de configuración f para el registrador

opciones del documento DICOM

título del documento:
  +t   --title  [t]ítulo: cadena de texto (por defecto: vacío)
         título del documento
  +cn  --concept-name  [CSD] [CV] [CM]: cadena de texto (por defecto: vacío)
         representación codificada del título del documento definida por el
         designador del esquema de codificación CSD, valor del código CV y
         significado del código CM
datos del paciente:
  +pn  --patient-name  [n]ombre: cadena de texto
         nombre del paciente en sintaxis PN de DICOM
  +pi  --patient-id  [i]d: cadena de texto
         identificador del paciente
  +pb  --patient-birthdate  [f]echa: cadena de texto (YYYYMMDD)
         fecha de nacimiento del paciente
  +ps  --patient-sex  [s]exo: cadena de texto (M, F u O)
         sexo del paciente
estudio y serie:
  +sg  --generate
         generar nuevas UID de estudio y serie (por defecto)
  +st  --study-from  [f]ilename: cadena de texto
         leer datos de paciente/estudio desde archivo DICOM
  +se  --series-from  [f]ilename: cadena de texto
         leer datos de paciente/estudio/serie desde archivo DICOM
número de instancia:
  +i1  --instance-one
         usar número de instancia 1 (por defecto, no con +se)
  +ii  --instance-inc
         incrementar número de instancia (solo con +se)
  +is  --instance-set [i]nstance number: entero
         usar número de instancia i
anotación grabada:
  +an  --annotation-yes
         el documento contiene datos de identificación del paciente (por defecto)
  -an  --annotation-no
         el documento no contiene datos de identificación del paciente
equipo general mejorado:
  +mn  --manufacturer  [n]ombre: cadena de texto
         nombre del fabricante
  +mm  --manufacturer-model  [n]ombre: cadena de texto
         modelo del fabricante
  +ds  --device-serial  [n]úmero: cadena de texto
         número de serie del dispositivo
  +sv  --software-versions  [v]ersiones: cadena de texto
         versiones del software
unidades de medida del modelo 3d:
  +mu  --measurement-units  [CSD] [CV] [CM]: cadena de texto
         unidades de medida con designador de esquema de codificación CSD,
         valor de código CV y significado de código CM (por defecto: UCUM, um, um)

opciones de procesamiento

otras opciones de procesamiento:
  -k   --key  [k]ey: gggg,eeee="str", ruta o nombre de diccionario="str"
         añadir atributo adicional

opciones de salida

formato del archivo de salida:
  +F   --write-file
         escribir formato de archivo (por defecto)
  -F   --write-dataset
         escribir conjunto de datos sin información meta del archivo
codificación de longitud de grupo:
  +g=  --group-length-recalc
         recalcular longitudes de grupo si están presentes (por defecto)
  +g   --group-length-create
         escribir siempre con elementos de longitud de grupo
  -g   --group-length-remove
         escribir siempre sin elementos de longitud de grupo
codificación de longitud en secuencias y elementos:
  +e   --length-explicit
         escribir con longitudes explícitas (por defecto)
  -e   --length-undefined
         escribir con longitudes indefinidas
relleno final del conjunto de datos (no con --write-dataset):
  -p   --padding-off
         sin relleno (implícito si --write-dataset)
  +p   --padding-create  [f]ile-pad [i]tem-pad: entero
         alinear archivo en un múltiplo de f bytes
         y elementos en un múltiplo de i bytes

NOTAS

Fuentes de atributos

La aplicación puede ser alimentada con información adicional para completar atributos obligatorios (y opcionales) en el nuevo archivo DICOM, como información del paciente, estudio y serie:

  • La opción --key puede usarse para añadir atributos adicionales al archivo de salida DICOM.
  • También es posible especificar secuencias, elementos y atributos anidados utilizando la opción --key. En estos casos, se debe usar una notación especial de "ruta". Los detalles sobre esta notación de ruta se pueden encontrar en la documentación de dcmodify.
  • La opción --key puede aparecer más de una vez.
  • La parte del valor (después del '=') puede estar ausente, haciendo que el atributo se establezca con longitud cero.
  • Tenga en cuenta que la opción --key se aplica al final, justo antes de guardar el archivo DICOM, por lo que no hay ninguna verificación de valor.

REGISTRO

El nivel de salida del registro de las diversas herramientas de línea de comandos y bibliotecas subyacentes puede ser especificado por el usuario. Por defecto, solo los errores y advertencias se escriben en el flujo de error estándar. Usando la opción --verbose también se informan mensajes informativos como detalles del procesamiento. La opción --debug puede usarse para obtener más detalles sobre la actividad interna, por ejemplo, para fines de depuración. Otros niveles de registro se pueden seleccionar usando la opción --log-level. En el modo --quiet solo se informan errores fatales. En tales eventos de error muy graves, la aplicación generalmente terminará. Para más detalles sobre los diferentes niveles de registro, consulte la documentación del módulo "oflog".

En caso de que la salida del registro deba escribirse en un archivo (opcionalmente con rotación de archivo de registro), a syslog (Unix) o al registro de eventos (Windows), se puede usar la opción --log-config. Este archivo de configuración también permite dirigir solo ciertos mensajes a un flujo de salida particular y filtrar ciertos mensajes basándose en el módulo o la aplicación donde se generan. Un archivo de configuración de ejemplo se proporciona en <etcdir>/logger.cfg.

LÍNEA DE COMANDOS

Todas las herramientas de línea de comandos utilizan la siguiente notación para los parámetros: los corchetes encierran valores opcionales (0-1), tres puntos seguidos indican que se permiten múltiples valores (1-n), una combinación de ambos significa 0 a n valores.

Las opciones de línea de comandos se distinguen de los parámetros por un signo '+' o '-' respectivamente. Normalmente, el orden y la posición de las opciones de línea de comandos son arbitrarios (es decir, pueden aparecer en cualquier lugar). Sin embargo, si las opciones son mutuamente excluyentes, se utiliza la aparición más a la derecha. Este comportamiento se ajusta a las reglas de evaluación estándar de los shells de Unix comunes.

Además, se puede especificar uno o más archivos de comandos usando el signo '@' como prefijo del nombre del archivo (por ejemplo, @command.txt). Dicho argumento de comando se reemplaza por el contenido del archivo de texto correspondiente (múltiples espacios en blanco se tratan como un solo separador a menos que aparezcan entre dos comillas) antes de cualquier otra evaluación. Tenga en cuenta que un archivo de comandos no puede contener otro archivo de comandos. Este enfoque simple pero efectivo permite resumir combinaciones comunes de opciones/parámetros y evita líneas de comandos largas y confusas (un ejemplo se proporciona en el archivo <datadir>/dumppat.txt).

ENTORNO

La utilidad stl2dcm intentará cargar los diccionarios de datos DICOM especificados en la variable de entorno DCMDICTPATH. Por defecto, es decir, si la variable de entorno DCMDICTPATH no está establecida, se cargará el archivo <datadir>/dicom.dic, a menos que el diccionario esté incorporado en la aplicación (por defecto en Windows).

Se debe preferir el comportamiento por defecto y utilizar la variable de entorno DCMDICTPATH solo cuando se necesiten diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell Unix, en el sentido de que dos puntos (":") separan las entradas. En sistemas Windows, un punto y coma (";") se utiliza como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se puede cargar ningún diccionario de datos.
