NOMBRE

smenc - Programa para codificar un archivo wav en un modelo SpectMorph

SINOPSIS

smenc [OPCIONES] Archivo-WAV [Archivo-SM]

DESCRIPCIÓN

smenc es una herramienta de línea de comandos para crear modelos SpectMorph a partir de archivos de audio. Por lo general, el archivo de entrada debe contener una sola nota de algún instrumento, como una sola nota Do4. Dado que las notas bajas requieren parámetros de análisis diferentes a las notas altas, es una buena idea usar la opción -m para que el algoritmo de codificación sepa qué nota se está codificando.

También existe una compensación entre calidad y tiempo, lo que significa que puedes usar la opción -O0, -O1 u -O2 para especificar cuán preciso debe ser el análisis, con números más altos que indican mejor calidad, pero mayor tiempo de análisis.

Para entradas multicanal, cada canal se codifica por separado. Si no especificas el nombre del archivo de salida, el codificador creará, por ejemplo, piano-ch0.sm y piano-ch1.sm a partir del archivo estéreo piano.wav. Si especificas un nombre de archivo de salida, debes incluir un %c en el nombre, como piano-ch%c.sm, que será sustituido por el número de canal.

OPCIONES

smenc sigue la sintaxis habitual de línea de comandos de GNU, con opciones largas que comienzan con dos guiones ('-').

-h, --help
Muestra un breve mensaje de ayuda.
-v, --version
Imprime la versión de smenc.
-f <frecuencia>
Especifica la frecuencia fundamental en Hz; esta información es opcional, pero debe proporcionarse cuando se conoce, para aumentar la precisión del modelo. Es equivalente a especificar la nota MIDI; solo se debe usar -m o -f.
-m <nota-midi>
Especifica la nota MIDI de la entrada; esto se utilizará para establecer la frecuencia fundamental en Hz. Esta información no es obligatoria, pero aumenta la precisión del algoritmo de análisis. Solo se debe usar -m o -f.
-O <nivel>
Para todos los fotogramas del archivo de entrada, una vez que smenc ha descubierto qué ondas sinusoidales se pueden usar para describir el fotograma, necesita estimar la magnitud y la fase de cada onda sinusoidal para este fotograma. El nivel de optimización elige el algoritmo utilizado para encontrar la magnitud y la fase; cuanto mayor sea el nivel, más preciso será el resultado. Sin embargo, por defecto es -O0, ya que es el algoritmo más rápido: estimar la magnitud/fase a partir del resultado de la FFT. Una buena opción es -O1, que es algo más lento, pero también algo mejor.
-s
Actualmente, smenc incluye por defecto mucha información en la salida que reproduce el archivo. Por lo tanto, los archivos creados por smenc son muy grandes por defecto. Para limitar el tamaño del archivo, usar la opción -s indica a smenc que cree un modelo "despojado" (stripped), que contiene solo la información necesaria para reproducirlo. Estos modelos despojados suelen ser mucho más pequeños que los modelos no despojados.
--no-attack
Por defecto, smenc intenta encontrar una envolvente de ataque al principio de la entrada, que describe en qué punto temporal ocurre el ataque y qué tan rápido es el ataque. Esta opción deshabilita ese paso (que consume bastante tiempo de CPU).
--no-sines
Omite el análisis de la parte sinusoidal de la señal (seguimiento de armónicos).
--loop-start
Establece el punto de inicio del bucle (en muestras) - el tipo de bucle se establece en timeloop.
--loop-end
Establece el punto final del bucle (en muestras) - el tipo de bucle se establece en timeloop.
