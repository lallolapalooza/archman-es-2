SMBD(8) Herramientas de administración del sistema SMBD(8)

NOMBRE

smbd - servidor para proporcionar servicios SMB/CIFS a clientes

SINOPSIS

smbd [-D|--daemon] [-i|--interactive] [-F|--foreground] [--no-process-group] [-b|--build-options] [-p <número(s)> de puerto] [-P <nivel> de profiling] [-d <nivel> de depuración] [--debug-stdout] [--configfile=<archivo> de configuración] [--option=<nombre>=<valor>] [-l|--log-basename <directorio> de registros] [--leak-report] [--leak-report-full] [-V|--version]

DESCRIPCIÓN

Este programa forma parte del conjunto samba(7).

smbd es el demonio servidor que proporciona servicios de intercambio de archivos e impresión a clientes de Windows. El servidor proporciona servicios de espacio de archivos e impresoras a clientes que utilizan el protocolo SMB (o CIFS). Esto es compatible con el protocolo LanManager y puede atender a clientes LanManager. Estos incluyen MSCLIENT 3.0 para DOS, Windows para Workgroups, Windows 95/98/ME, Windows NT, Windows 2000, OS/2, DAVE para Macintosh y smbfs para Linux.

Una descripción exhaustiva de los servicios que puede proporcionar el servidor se encuentra en la página del manual del archivo de configuración que controla los atributos de dichos servicios (consulte smb.conf(5). Esta página del manual no describirá los servicios, sino que se centrará en los aspectos administrativos de la ejecución del servidor.

Tenga en cuenta que ejecutar este servidor tiene importantes implicaciones de seguridad, y la página del manual de smb.conf(5) debe considerarse de lectura obligatoria antes de proceder con la instalación.

Se crea una sesión cada vez que un cliente solicita una. Cada cliente recibe una copia del servidor por cada sesión. Esta copia se encarga de atender todas las conexiones realizadas por el cliente durante esa sesión. Cuando se cierran todas las conexiones de su cliente, la copia del servidor para ese cliente termina.

El archivo de configuración, y cualquier archivo que incluya, se recargan automáticamente cada tres minutos si cambian. Se puede forzar una recarga enviando una señal SIGHUP al servidor. La recarga del archivo de configuración no afectará a las conexiones a ningún servicio que ya esté establecido. El usuario tendrá que desconectarse del servicio, o bien matar y reiniciar smbd.

En lugar de enviar una señal SIGHUP, se puede enviar una solicitud para recargar el archivo de configuración utilizando el programa smbcontrol(1).

OPCIONES

-D|--daemon

Si se especifica, este parámetro hace que el servidor opere como un demonio. Es decir, se desvincula y se ejecuta en segundo plano, atendiendo solicitudes en el puerto apropiado. Operar el servidor como un demonio es la forma recomendada de ejecutar smbd para servidores que proporcionan servicios de archivos e impresión de uso más allá de lo ocasional. Este conmutador se asume si smbd se ejecuta en la línea de comandos de una shell.

-i|--interactive

Si se especifica este parámetro, hace que el servidor se ejecute "interactivamente", no como un demonio, incluso si el servidor se ejecuta en la línea de comandos de una shell. Establecer este parámetro niega el modo demonio implícito cuando se ejecuta desde la línea de comandos. smbd solo aceptará una conexión y terminará. También registrará en la salida estándar, como si se hubiera dado el parámetro -S.

-F|--foreground

Si se especifica, este parámetro hace que el proceso principal de smbd no se desvincule (es decir, no haga doble fork ni se desasocie de la terminal). Los procesos hijos se crean de forma normal para atender cada solicitud de conexión, pero el proceso principal no sale. Este modo de operación es adecuado para ejecutar smbd bajo supervisores de procesos como supervise y svscan del paquete daemontools de Daniel J. Bernstein, o el monitor de procesos de AIX.

--no-process-group

No crear un nuevo grupo de procesos para smbd.

-b|--build-options

Imprime información sobre cómo se compiló Samba.

-p|--port<número(s) de puerto>

número(s) de puerto es una lista separada por espacios o comas de puertos TCP en los que smbd debe escuchar. El valor predeterminado se toma del parámetro ports en /etc/samba/smb.conf

Los puertos predeterminados son 139 (utilizado para SMB sobre NetBIOS sobre TCP) y el puerto 445 (utilizado para SMB plano sobre TCP).

-P|--profiling-level<nivel de profiling>

nivel de profiling es un número que especifica el nivel de datos de profiling que se recopilarán. 0 desactiva el profiling, 1 activa solo el profiling de contadores, 2 activa el profiling completo y 3 restablece todos los datos de profiling.

-d|--debuglevel=nivel

nivel es un entero de 0 a 10. El valor predeterminado si no se especifica este parámetro es 0.

Cuanto mayor sea este valor, más detalle se registrará en los archivos de registro sobre las actividades del servidor. En el nivel 0, solo se registrarán errores críticos y advertencias graves. El nivel 1 es un nivel razonable para el uso diario: genera una pequeña cantidad de información sobre las operaciones realizadas.

Los niveles superiores a 1 generarán una cantidad considerable de datos de registro y solo deben utilizarse al investigar un problema. Los niveles superiores a 3 están diseñados para uso exclusivo de desarrolladores y generan ENORMES cantidades de datos de registro, la mayoría de los cuales son extremadamente crípticos.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro log level en el archivo /etc/samba/smb.conf.

--debug-stdout

Esto redirigirá la salida de depuración a STDOUT. Por defecto, los demonios del servidor registran en un archivo de registro.

--configfile=ARCHIVO_CONFIGURACION

El archivo especificado contiene los detalles de configuración requeridos por el servidor. La información de este archivo incluye detalles específicos del servidor, como qué archivo printcap usar, así como descripciones de todos los servicios que el servidor debe proporcionar. Consulte /etc/samba/smb.conf para obtener más información. El nombre predeterminado del archivo de configuración se determina en el momento de la compilación.

--option=<nombre>=<valor>

Establece la opción smb.conf(5) "<nombre>" al valor "<valor>" desde la línea de comandos. Esto anula los valores predeterminados compilados y las opciones leídas del archivo de configuración. Si un nombre o un valor incluyen un espacio, encierre toda la opción --option=nombre=valor entre comillas.

-l|--log-basename=directorio_de_registros

Nombre base del directorio para los archivos de registro/depuración. Se añadirá la extensión ".progname" (por ejemplo, log.smbclient, log.smbd, etc...). El archivo de registro nunca es eliminado por el cliente.

--leak-report

Habilita la notificación de fugas de talloc al salir.

--leak-report-full

Habilita la notificación completa de fugas de talloc al salir.

-V|--version

Imprime el número de versión del programa.

-?|--help

Imprime un resumen de las opciones de la línea de comandos.

--usage

Muestra un breve mensaje de uso.

ARCHIVOS

/etc/inetd.conf

Si el servidor va a ser ejecutado por el metademonio inetd, este archivo debe contener información de inicio adecuada para el metademonio.

/etc/rc

o el script de inicialización que utilice su sistema).

Si se ejecuta el servidor como demonio al inicio, este archivo necesitará contener una secuencia de inicio adecuada para el servidor.

/etc/services

Si se ejecuta el servidor a través del metademonio inetd, este archivo debe contener un mapeo del nombre del servicio (por ejemplo, netbios-ssn) al puerto del servicio (por ejemplo, 139) y al tipo de protocolo (por ejemplo, tcp).

/usr/local/samba/lib/smb.conf

Esta es la ubicación predeterminada del archivo de configuración del servidor smb.conf(5). Otros lugares comunes donde los sistemas instalan este archivo son /usr/samba/lib/smb.conf y /etc/samba/smb.conf.

Este archivo describe todos los servicios que el servidor pondrá a disposición de los clientes. Consulte smb.conf(5) para obtener más información.

LIMITACIONES

En algunos sistemas, smbd no puede volver a cambiar el UID a root después de una llamada setuid(). Dichos sistemas se denominan sistemas de UID con puerta trampa. Si tiene uno de esos sistemas, no podrá conectarse desde un cliente (como un PC) como dos usuarios diferentes.

SMBD(8)

System Administration Commands

NAME

smbd — a Samba daemon that implements the SMB/CIFS server.

SYNOPSIS

smbd [-D] [-F] [-S] [-i] [-d debuglevel] [-l log directory] [-p port]

DESCRIPTION

smbd is the Samba daemon that implements the SMB/CIFS network protocol. It provides file and printer sharing services to clients running Windows, Linux, macOS, and other operating systems.

It acts as a file server, a print server, and handles user authentication and authorization.

OPTIONS

The following options are available:

-D
Daemonize the process. This is the default behavior when run from the command line.
-F
Foreground execution. The server will not daemonize, and will run in the foreground. This is useful for debugging.
-S
Log to standard output. This is typically used in conjunction with -F.
-i
Run interactively. When -i is specified, smbd will not fork itself into the background. The server will run in the foreground and all output will be sent to standard output. This is useful for debugging.
-d debuglevel
Set the debug level. Higher levels provide more verbose logging.
-l log directory
Set the directory where log files are written. Defaults to /var/log/samba/.
-p port
Bind to a specific network port instead of the default SMB port (445).

LIMITATIONS

The smbd daemon is designed to allow only one user to connect to the server at a time. Attempts to connect a second user will result in access denied or similar.

ENVIRONMENT VARIABLES

PRINTER

If no printer name is specified to printable services, most systems will use the value of this variable (or lp if this variable is not defined) as the name of the printer to use. This is not specific to the server, however.

PAM INTERACTION

Samba uses PAM for authentication (when presented with a plaintext password), for account checking (is this account disabled?) and for session management. The degree to which Samba supports PAM is restricted by the limitations of the SMB protocol and the obey pam restrictions parameter in smb.conf(5). When this is set, the following restrictions apply:

•Account Validation: All accesses to a Samba server are checked against PAM to see if the account is valid, not disabled, and is permitted to login at this time. This also applies to encrypted logins.
•Session Management: When not using share level security, users must pass PAM's session checks before access is granted. Note, however, that this is bypassed in share level security. Note also that some older PAM configuration files may need a line added for session support.

DIAGNOSTICS

Most diagnostics issued by the server are logged in a specified log file. The log file name is specified at compile time, but may be overridden on the command line.

The number and nature of diagnostics available depends on the debug level used by the server. If you have problems, set the debug level to 3 and peruse the log files.

Most messages are reasonably self-explanatory. Unfortunately, at the time this man page was created, there are too many diagnostics available in the source code to warrant describing each and every diagnostic. At this stage, your best bet is still to grep the source code and inspect the conditions that gave rise to the diagnostics you are seeing.

SIGNALS

Sending the smbd a SIGHUP will cause it to reload its smb.conf configuration file within a short period of time.

To shut down a user's smbd process, it is recommended that SIGKILL (-9) *NOT* be used, except as a last resort, as this may leave the shared memory area in an inconsistent state. The safe way to terminate an smbd is to send it a SIGTERM (-15) signal and wait for it to die on its own.

The debug log level of smbd may be raised or lowered using the smbcontrol(1) program (SIGUSR[1|2] signals are no longer used since Samba 2.2). This is to allow transient problems to be diagnosed, whilst still running at a normally low log level.

Note that as the signal handlers send a debug write, they are not re-entrant in smbd. Thus, you should wait until smbd is in a state of waiting for an incoming SMB before issuing them. It is possible to make the signal handlers safe by un-blocking the signals before the select call and re-blocking them after, however this would affect performance.
