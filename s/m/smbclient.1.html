SMBCLIENT(1) Comandos de usuario SMBCLIENT(1)

NOMBRE

smbclient - cliente tipo ftp para acceder a recursos SMB/CIFS en servidores

SINOPSIS

smbclient [-M|--message=HOST] [-I|--ip-address=IP] [-E|--stderr] [-L|--list=HOST] [-T|--tar=<c|x>IXFvgbNan] [-D|--directory=DIR] [-b|--send-buffer=BYTES] [-t|--timeout=SECONDS] [-p|--port=PORT] [-g|--grepable] [-q|--quiet] [-B|--browse] [-?|--help] [--usage] [-d|--debuglevel=DEBUGLEVEL] [--debug-stdout] [-s|--configfile=CONFIGFILE] [--option=name=value] [-l|--log-basename=LOGFILEBASE] [--leak-report] [--leak-report-full] [-R|--name-resolve=NAME-RESOLVE-ORDER] [-O|--socket-options=SOCKETOPTIONS] [-m|--max-protocol=MAXPROTOCOL] [-n|--netbiosname=NETBIOSNAME] [--netbios-scope=SCOPE] [-W|--workgroup=WORKGROUP] [--realm=REALM] [-U|--user=[DOMAIN/]USERNAME%[PASSWORD]] [-N|--no-pass] [--password=STRING] [--pw-nt-hash] [-A|--authentication-file=FILE] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=desired|required|off] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=sign|encrypt|off] [-V|--version] [-c|--command=STRING]

DESCRIPCIÓN

Esta herramienta forma parte del conjunto de utilidades de samba(7).

smbclient es un cliente que puede 'hablar' con un servidor SMB/CIFS. Ofrece una interfaz similar a la del programa ftp (ver ftp(1)). Las operaciones incluyen cosas como obtener archivos del servidor a la máquina local, subir archivos de la máquina local al servidor, obtener información de directorios del servidor, etc.

OPCIONES

nombre_servicio

nombre_servicio es el nombre del servicio que desea utilizar en el servidor. Un nombre de servicio tiene el formato //servidor/servicio donde servidor es el nombre NetBIOS del servidor SMB/CIFS que ofrece el servicio deseado y servicio es el nombre del servicio ofrecido. Por lo tanto, para conectarse al servicio "printer" en el servidor SMB/CIFS "smbserver", usaría el nombre_servicio //smbserver/printer

Tenga en cuenta que el nombre de servidor requerido NO es necesariamente el nombre de host IP (DNS) del servidor. El nombre requerido es un nombre de servidor NetBIOS, que puede o no ser el mismo que el nombre de host IP de la máquina que ejecuta el servidor.

El nombre del servidor se busca de acuerdo con el parámetro -R|--name-resolve de smbclient o utilizando el orden de resolución de nombres en el archivo smb.conf(5), permitiendo a un administrador cambiar el orden y los métodos por los que se buscan los nombres de servidor.

contraseña

La contraseña requerida para acceder al servicio especificado en el servidor especificado. Si se proporciona este parámetro, se asume la opción -N (suprimir solicitud de contraseña).

No hay contraseña por defecto. Si no se proporciona ninguna contraseña en la línea de comandos (ya sea usando este parámetro o agregando una contraseña a la opción -U (ver abajo)) y la opción -N no se especifica, el cliente solicitará una contraseña, incluso si el servicio deseado no la requiere. (Si no se requiere contraseña, simplemente presione ENTER para proporcionar una contraseña nula).

Nota: Algunos servidores (incluyendo OS/2 y Windows for Workgroups) insisten en una contraseña en mayúsculas. Las contraseñas en minúsculas o mixtas pueden ser rechazadas por estos servidores.

Tenga cuidado al incluir contraseñas en scripts.

-M|--message nombre_NetBIOS

Esta opción le permite enviar mensajes, utilizando el protocolo "WinPopup", a otro ordenador. Una vez establecida la conexión, escriba su mensaje, presionando ^D (control-D) para finalizar.

Si el ordenador receptor está ejecutando WinPopup, el usuario recibirá el mensaje y probablemente un pitido. Si no están ejecutando WinPopup, el mensaje se perderá y no se producirá ningún mensaje de error.

El mensaje también se trunca automáticamente si tiene más de 1600 bytes, ya que ese es el límite del protocolo.

Un truco útil es canalizar el mensaje a través de smbclient. Por ejemplo: smbclient -M FRED < mymessage.txt enviará el mensaje del archivo mymessage.txt a la máquina FRED.

También puede encontrar útiles las opciones -U y -I, ya que le permiten controlar las partes DE y PARA del mensaje.

Consulte el parámetro message command en smb.conf(5) para obtener una descripción de cómo manejar los mensajes WinPopup entrantes en Samba.

Nota: Copie WinPopup en el grupo de inicio en sus PCs WfWg si desea que siempre puedan recibir mensajes.

-p|--port puerto

Este número es el número de puerto TCP que se utilizará al establecer conexiones con el servidor. El número de puerto TCP estándar (bien conocido) para un servidor SMB/CIFS es 139, que es el valor por defecto.

-g|--grepable

Este parámetro, combinado con -L, proporciona una salida fácil de analizar que permite el procesamiento con utilidades como grep y cut.

-m|--max-protocol protocolo

Esto permite al usuario seleccionar el nivel de protocolo SMB más alto que smbclient utilizará para conectarse al servidor. Por defecto, este valor se establece en la versión más alta del protocolo SMB3 disponible. Para conectarse usando el protocolo SMB2 o SMB1, use las cadenas SMB2 o NT1 respectivamente. Tenga en cuenta que para conectarse a un servidor Windows 2012 con transporte cifrado, se requiere seleccionar un max-protocol de SMB3.

-P|--machine-pass

Realiza consultas al servidor externo utilizando la cuenta de la máquina del servidor local.

-I|--ip-address IP-address

IP address es la dirección del servidor al que conectarse. Debe especificarse en notación estándar "a.b.c.d".

Normalmente, el cliente intentaría localizar un servidor SMB/CIFS con nombre buscándolo a través del mecanismo de resolución de nombres NetBIOS descrito anteriormente en el parámetro orden de resolución de nombres. El uso de este parámetro forzará al cliente a asumir que el servidor está en la máquina con la dirección IP especificada y que se ignorará el componente del nombre NetBIOS del recurso al que se conecta.

No hay valor por defecto para este parámetro. Si no se proporciona, será determinado automáticamente por el cliente como se describe anteriormente.

-E|--stderr

Este parámetro hace que el cliente escriba los mensajes en el flujo de error estándar (stderr) en lugar de en el flujo de salida estándar.

Por defecto, el cliente escribe los mensajes en la salida estándar, típicamente el tty del usuario.

-L|--list

Esta opción le permite ver qué servicios están disponibles en un servidor. Se usa como smbclient -L host y debería aparecer una lista. La opción -I puede ser útil si sus nombres NetBIOS no coinciden con sus nombres de host DNS TCP/IP o si está intentando llegar a un host en otra red.

-b|--send-buffer buffersize

Al enviar o recibir archivos, smbclient utiliza un búfer interno cuyo tamaño está determinado por el número máximo de solicitudes permitidas al servidor conectado. Este comando permite que este tamaño se establezca en cualquier rango entre 0 (que significa usar el tamaño por defecto controlado por el servidor) bytes y 16776960 (0xFFFF00) bytes. Usar el tamaño controlado por el servidor es lo más eficiente, ya que smbclient canalizará tantas lecturas o escrituras simultáneas como sean necesarias para mantener el servidor lo más ocupado posible. Establecer esto a cualquier otro tamaño ralentizará la transferencia. Esto también se puede configurar usando el comando iosize dentro de smbclient.

-B|--browse

Explora servidores SMB usando DNS.

-t|--timeout <tiempo_de_espera_segundos>

Esto permite al usuario ajustar el tiempo de espera por defecto utilizado para cada solicitud SMB. El valor por defecto es de 20 segundos. Auméntelo si las solicitudes al servidor a veces fallan por tiempo de espera agotado. Esto puede ocurrir cuando se selecciona el cifrado SMB3 y smbclient está abrumando al servidor con solicitudes. Esto también se puede configurar usando el comando timeout dentro de smbclient.

-T|--tar opciones_tar

smbclient puede usarse para crear copias de seguridad compatibles con tar(1) de todos los archivos en un recurso compartido SMB/CIFS. Las opciones secundarias de tar que se pueden pasar a esta opción son:
•c - Crea un archivo de copia de seguridad tar en el sistema local. Debe ir seguido del nombre de un archivo tar, un dispositivo de cinta o "-" para la salida estándar. Si usa la salida estándar, debe establecer el nivel de registro al valor más bajo -d0 para evitar corromper su archivo tar. Esta bandera es mutuamente excluyente con la bandera x.
•n - En combinación con la bandera c, no
Aquí tienes la traducción del contenido proporcionado, manteniendo la estructura del archivo: ```text realiza una simulación en seco que intenta todo lo involucrado en la creación, excepto la escritura del archivo.
•x - Extraer (restaurar) un archivo tar local de vuelta a un recurso compartido. A menos que se proporcione la opción -D, los archivos tar se restaurarán desde el nivel superior del recurso compartido. Debe ir seguido del nombre del archivo tar, dispositivo o "-" para la entrada estándar. Mutuamente excluyente con la bandera c. Los archivos restaurados tendrán sus tiempos de creación (mtime) establecidos en la fecha guardada en el archivo tar. Los directorios actualmente no restauran sus fechas de creación correctamente.
•I - Incluir archivos y directorios. Es el comportamiento predeterminado cuando se especifican nombres de archivo arriba. Hace que los archivos se incluyan en una extracción o creación (y por lo tanto, que todo lo demás se excluya). Ver ejemplo a continuación. La expansión de nombres de archivo funciona de una de dos maneras. Ver r abajo.
•X - Excluir archivos y directorios. Hace que los archivos se excluyan de una extracción o creación. Ver ejemplo a continuación. La expansión de nombres de archivo funciona de una de dos maneras. Ver r abajo.
•F - Archivo que contiene una lista de archivos y directorios. El F hace que el nombre que sigue al archivo tar a crear se lea como un nombre de archivo que contiene una lista de archivos y directorios a incluir en una extracción o creación (y por lo tanto, que todo lo demás se excluya). Ver ejemplo a continuación. La expansión de nombres de archivo funciona de una de dos maneras. Ver r abajo.
•b - Tamaño de bloque. Debe ir seguido de un tamaño de bloque válido (mayor que cero). Hace que el archivo tar se escriba en bloques de tamaño de bloque * TBLOCK (512 bytes).
•g - Incremental. Copia de seguridad solo de los archivos que tienen el bit de archivo establecido. Útil solo con la bandera c.
•v - Verboso. Hace que tar imprima los archivos que se están procesando. Por defecto, tar no es verboso. Esto es lo mismo que el modo tar verboso.
•r - Usar coincidencia de comodines para incluir o excluir. Obsoleto.
•N - Más nuevo que. Debe ir seguido del nombre de un archivo cuya fecha se compara con los archivos encontrados en el recurso compartido durante una creación. Solo se copian de seguridad los archivos más nuevos que el archivo especificado en el archivo tar. Útil solo con la bandera c.
•a - Establecer bit de archivo. Hace que el bit de archivo se restablezca cuando se copia de seguridad un archivo. Útil con las banderas g y c.
Nombres de archivo largos de Tar

La opción tar de smbclient ahora admite nombres de archivo largos tanto en copias de seguridad como en restauraciones. Sin embargo, la ruta completa del archivo debe tener menos de 1024 bytes. Además, cuando se crea un archivo tar, la opción tar de smbclient coloca todos los archivos en el archivo con nombres relativos, no nombres absolutos.

Nombres de archivo Tar

Todos los nombres de archivo se pueden proporcionar como nombres de ruta DOS (con '\' como separador de componentes) o como nombres de ruta UNIX (con '/' como separador de componentes).

Ejemplos

Restaurar desde la copia de seguridad del archivo tar backup.tar en myshare en mypc (sin contraseña en el recurso compartido).

smbclient //mypc/myshare "" -N -Tx backup.tar

Restaurar todo excepto users/docs

smbclient //mypc/myshare "" -N -TXx backup.tar users/docs

Crear un archivo tar de los archivos debajo de users/docs.

smbclient //mypc/myshare "" -N -Tc backup.tar users/docs

Crear el mismo archivo tar que el anterior, pero ahora usar un nombre de ruta DOS.

smbclient //mypc/myshare "" -N -Tc backup.tar users\edocs

Crear un archivo tar de los archivos listados en el archivo tarlist.

smbclient //mypc/myshare "" -N -TcF backup.tar tarlist

Crear un archivo tar de todos los archivos y directorios en el recurso compartido.

smbclient //mypc/myshare "" -N -Tc backup.tar *

-D|--directory directorio inicial

Cambiar al directorio inicial antes de comenzar. Probablemente solo tenga utilidad con la opción tar -T.

-c|--command cadena de comandos

La cadena de comandos es una lista separada por punto y coma de comandos que se ejecutarán en lugar de solicitar desde stdin. -N se implica por -c.

Esto es particularmente útil en scripts y para imprimir stdin al servidor, por ejemplo, -c 'print -'.

-?|--help

Imprimir un resumen de las opciones de línea de comandos.

--usage

Mostrar un mensaje de uso breve.

-d|--debuglevel=nivel

nivel es un entero de 0 a 10. El valor predeterminado si este parámetro no se especifica es 1 para aplicaciones cliente.

Cuanto mayor sea este valor, más detalles se registrarán en los archivos de registro sobre las actividades del servidor. En el nivel 0, solo se registrarán errores críticos y advertencias serias. El nivel 1 es un nivel razonable para el uso diario: genera una pequeña cantidad de información sobre las operaciones realizadas.

Los niveles superiores a 1 generarán una cantidad considerable de datos de registro, y solo deben usarse al investigar un problema. Los niveles superiores a 3 están diseñados para ser utilizados solo por desarrolladores y generan ENORMES cantidades de datos de registro, la mayoría de los cuales son extremadamente crípticos.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro nivel de registro en el archivo /etc/samba/smb.conf.

--debug-stdout

Esto redirigirá la salida de depuración a STDOUT. Por defecto, todos los clientes registran en STDERR.

--configfile=<archivo de configuración>

El archivo especificado contiene los detalles de configuración requeridos por el cliente. La información en este archivo puede ser general para cliente y servidor o solo proporcionar opciones específicas del cliente como client smb encrypt. Consulte /etc/samba/smb.conf para obtener más información. El nombre del archivo de configuración predeterminado se determina en tiempo de compilación.

--option=<nombre>=<valor>

Establece la opción smb.conf(5) "<nombre>" al valor "<valor>" desde la línea de comandos. Esto anula los valores predeterminados compilados y las opciones leídas del archivo de configuración. Si un nombre o un valor incluye un espacio, envuelva todo --option=nombre=valor entre comillas.

-l|--log-basename=directorio de registro

Nombre base del directorio para los archivos de registro/depuración. Se agregará la extensión ".nombre_programa" (por ejemplo, log.smbclient, log.smbd, etc.). El cliente nunca elimina el archivo de registro.

--leak-report

Habilita el informe de fugas de talloc al salir.

--leak-report-full

Habilita el informe completo de fugas de talloc al salir.

-V|--version

Imprime el número de versión del programa.

-R|--name-resolve=ORDEN-RESOLUCION-NOMBRES

Esta opción se utiliza para determinar qué servicios de nombres y en qué orden resolver nombres de host a direcciones IP. La opción toma una cadena separada por espacios de diferentes opciones de resolución de nombres. Lo mejor es envolver todo --name-resolve=ORDEN-RESOLUCION-NOMBRES entre comillas.

Las opciones son: "lmhosts", "host", "wins" y "bcast". Hacen que los nombres se resuelvan de la siguiente manera:

•lmhosts: Busca una dirección IP en el archivo lmhosts de Samba. Si la línea en lmhosts no tiene un tipo de nombre adjunto al nombre NetBIOS (consulte lmhosts(5) para obtener detalles), entonces cualquier tipo de nombre coincide para la búsqueda.
•host: Realiza una resolución estándar de nombre de host a dirección IP, utilizando los archivos /etc/hosts del sistema, NIS o búsquedas DNS. Este método de resolución de nombres depende del sistema operativo; por ejemplo, en IRIX o Solaris, esto puede controlarse mediante el archivo /etc/nsswitch.conf). Tenga en cuenta que este método solo se utiliza si el tipo de nombre NetBIOS que se consulta es el tipo de nombre 0x20 (servidor), de lo contrario, se ignora.
•wins: Consulta un nombre con la dirección IP que aparece en el parámetro wins server. Si no se ha especificado ningún servidor WINS, este método se ignorará.
•bcast: Realiza una difusión en cada una de las interfaces locales conocidas que aparecen en el parámetro interfaces. Este es el menos confiable de los métodos de resolución de nombres, ya que depende de que el host de destino esté en una subred conectada localmente.
Si este parámetro no está establecido, se utilizará el orden de resolución de nombres definido en el parámetro de archivo /etc/samba/smb.conf (orden de resolución de nombres).

El orden predeterminado es lmhosts, host, wins, bcast. Sin este parámetro o cualquier entrada en el parámetro orden de resolución de nombres del archivo /etc/samba/smb.conf, los métodos de resolución de nombres se intentarán en este orden.

-O|--socket-options=OPCIONES DE SOCKET

Opciones de socket TCP para establecer en el socket del cliente. Consulte el parámetro de opciones de socket en la página del manual /etc/samba/smb.conf para ver la lista de opciones válidas.

-m|--max-protocol=MAXPROTOCOL

El valor del parámetro (una cadena) es el nivel de protocolo más alto que será compatible con el cliente.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro client max protocol en el archivo /etc/samba/smb.conf.

-n|--netbiosname=NOMBRE NETBIOS

Esta opción permite anular el nombre NetBIOS que Samba utiliza para sí mismo. Esto es idéntico a establecer el parámetro netbios name en el archivo /etc/samba/smb.conf. Sin embargo, una configuración de línea de comandos tendrá prioridad sobre la configuración en /etc/samba/smb.conf.

--netbios-scope=SCOPE

Esto especifica un ámbito NetBIOS con el que nmblookup se comunicará al generar nombres NetBIOS. Para obtener detalles sobre el uso de ámbitos NetBIOS, consulte rfc1001.txt y rfc1002.txt. Los ámbitos NetBIOS se utilizan *muy* raramente, solo establezca este parámetro si usted es el administrador del sistema a cargo de todos los sistemas NetBIOS con los que se comunica.

-W|--workgroup=GRUPO DE TRABAJO

Establece el dominio SMB del nombre de usuario. Esto anula el dominio predeterminado, que es el dominio definido en smb.conf. Si el dominio especificado es el mismo que el nombre NetBIOS del servidor, hace que el cliente inicie sesión utilizando el SAM local del servidor (en lugar del SAM del Dominio).

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro workgroup en el archivo /etc/samba/smb.conf.

-r|--realm=REALM

Establece el reino para el dominio.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro realm en el archivo /etc/samba/smb.conf.

-U|--user=[DOMINIO\]NOMBRE DE USUARIO[%CONTRASEÑA]

Establece el nombre de usuario SMB o el nombre de usuario y la contraseña.

Si no se especifica %CONTRASEÑA, se le pedirá al usuario. El cliente primero verificará la variable de entorno USER (que también puede contener la contraseña separada por un %) y luego la variable LOGNAME (que no está permitida por separado.

smbclient

11/07/2025 Samba 4.23.3

SYNOPSIS

smbclient //server/share [/path] [-d debuglevel] [-L] [-M machine] [-N] [-n] [-O options] [-m max_protocol] [-A filename] [-U username[%password]] [-E] [-W workgroup] [-P password] [-S] [-e] [-x] [-k] [-c "command string"] [-I <ip address>] [-p <port>] [-B <bind ip>] [-R <port range>] [-T] [-d debuglevel] [-l log_file] [-s smb.conf] [-Y] [-Z] [-K] [-F] [-V] [-h]

DESCRIPTION

smbclient is an utility program that allows you to connect to an SMB/CIFS server and perform operations on it. It is particularly useful for administrating Windows file servers and other SMB/CIFS resources.

The primary features of smbclient are:

  • Interactive command-line interface for browsing and manipulating files and directories on the server.

  • Ability to perform various operations such as copying, moving, deleting, and listing files and directories.

  • Support for various SMB/CIFS protocols and features.

  • Integration with Samba server administration tools.

OPTIONS

-d debuglevel
Sets the debug level for the client. Higher levels produce more detailed logging.
-L
Lists available shares on the server.
-M machine
Sends a message to the specified machine.
-N
No password prompt. Use this if you don't want to be prompted for a password.
-n
No login. This option is used when connecting to servers that do not require authentication.
-O options
Sets SMB protocol options.
-m max_protocol
Sets the maximum SMB protocol version to use.
-A filename
Specifies a file containing authentication credentials (username, password, domain).
-U username[%password]
Specifies the username and optional password for authentication.
-E
Prints extended information about files and directories.
-W workgroup
Specifies the workgroup or domain to connect to.
-P password
Specifies the password for authentication.
-S
Lists server names that are providing services.
-e
Enables extended security.
-x
Disables extended security.
-k
Enables null session support.
-c "command string"
Executes a single command string and exits.
-I ip address
Specifies the IP address of the server.
-p port
Specifies the port number to use for the connection.
-B bind ip
Specifies the IP address to bind to on the client.
-R port range
Specifies the range of ports to use for passive FTP connections.
-T
Enables tar mode for file transfers.
-l log file
Specifies the log file for client messages.
-s smb.conf
Specifies the smb.conf file to use.
-Y

-Z

-K

-F

-V

-h

OPERATIONS

The following operations can be performed within the smbclient interactive shell:

get [remote-file [local-file]]

Downloads a file from the server. If local-file is not specified, the filename is used.

put [local-file [remote-file]]

Uploads a file to the server. If remote-file is not specified, the filename is used.

mget wildcards

Downloads multiple files matching the given wildcards.

mput wildcards

Uploads multiple files matching the given wildcards.

ls [wildcards]

Lists files and directories on the server. Wildcards can be used to filter the listing.

cd directory

Changes the current working directory on the server.

mkdir directory

Creates a new directory on the server.

rmdir directory

Removes an empty directory on the server.

rm file

Removes a file on the server.

mv oldname newname

Renames a file or directory on the server.

help

Displays a list of available commands.

quit

Exits smbclient.

! command

Executes a command on the local system.

reget [remote-file [local-file]]

Resumes a download of a file.

reput [local-file [remote-file]]

Resumes an upload of a file.

link <target> <linkname>

Creates a symbolic link.

symlink <target> <linkname>

Creates a symbolic link.

rename <oldname> <newname>

Renames a file or directory.

stat [file]

Displays information about a file, including file size, modification time, and permissions. If no file is specified, prints information about the current directory. This command requires the server to support the stat command. On CIFS servers that support UNIX extensions this will print the file's mode, owner, group, file size, inode number, number of links and finally the three timestamps (access, modify and change). If the file is a special file (symlink, character or block device, fifo or socket) then extra information may also be printed.

symlink target linkname

This command depends on the server supporting the CIFS UNIX extensions and will fail if the server does not. The client requests that the server create a symbolic hard link between the target and linkname files. The linkname file must not exist. Note that the server will not create a link to any path that lies outside the currently connected share. This is enforced by the Samba server.

tar <c|x>[IXbgNa]

Performs a tar operation - see the -T command line option above. Behavior may be affected by the tarmode command (see below). Using g (incremental) and N (newer) will affect tarmode settings. Note that using the "-" option with tar x may not work - use the command line option instead.

blocksize <blocksize>

Blocksize. Must be followed by a valid (greater than zero) blocksize. Causes tar file to be written out in blocksize*TBLOCK (512 byte) blocks.

tarmode <full|inc|reset|noreset|system|nosystem|hidden|nohidden|verbose|noverbose>

Changes tar's behavior with regard to DOS attributes. There are 4 modes which can be turned on or off.

Incremental mode (default off). When off (using full) tar will back up everything regardless of the archive bit setting. When on (using inc), tar will only back up files with the archive bit set.

Reset mode (default off). When on (using reset), tar will remove the archive bit on all files it backs up (implies read/write share). Use noreset to turn off.

System mode (default on). When off, tar will not backup system files. Use nosystem to turn off.

Hidden mode (default on). When off, tar will not backup hidden files. Use nohidden to turn off.

timeout <per-operation timeout in seconds>

This allows the user to tune the default timeout used for each SMB request. The default setting is 20 seconds. Increase it if requests to the server sometimes time out. This can happen when SMB3 encryption is selected and smbclient is overwhelming the server with requests.

unlock <filenum> <hex-start> <hex-len>

This command depends on the server supporting the CIFS UNIX extensions and will fail if the server does not. Tries to unlock a POSIX fcntl lock on the given range. Used for internal Samba testing purposes.

volume

Prints the current volume name of the share.

vuid <number>

Changes the currently used vuid in the protocol to the given arbitrary number. Without an argument prints out the current vuid being used. Used for internal Samba testing purposes.

tcon <sharename>

Establishes a new tree connect (connection to a share). Replaces the current tree connect. Prints the new tid (tree id). Used for internal Samba testing purposes.

tdis

Close the current share connection (tree disconnect). Used for internal Samba testing purposes.

tid <number>

Changes the current tree id (tid) in the protocol to a new arbitrary number. Without an argument, it prints out the tid currently used. Used for internal Samba testing purposes.

utimes <filename> <create time> <access time> <write time> < change time>

Changes the timestamps on a file by name. Times should be specified in the format [YY]YY:MM:DD-HH:MM:SS or -1 for no change.

NOTES

Some servers are fussy about the case of supplied usernames, passwords, share names (AKA service names) and machine names. If you fail to connect try giving all parameters in uppercase.

It is often necessary to use the -n option when connecting to some types of servers. For example OS/2 LanManager insists on a valid NetBIOS name being used, so you need to supply a valid name that would be known to the server.

smbclient supports long file names where the server supports the LANMAN2 protocol or above.

ENVIRONMENT VARIABLES

See the --user and --password options for details on ways to specify a username and password via an environment variable.

INSTALLATION

The location of the client program is a matter for individual system administrators. The following are thus suggestions only.

It is recommended that the smbclient software be installed in the /usr/local/samba/bin/ or /usr/samba/bin/ directory, this directory readable by all, writeable only by root. The client program itself should be executable by all. The client should NOT be setuid or setgid!

The client log files should be put in a directory readable and writeable only by the user.

To test the client, you will need to know the name of a running SMB/CIFS server. It is possible to run smbd(8) as an ordinary user - running that server as a daemon on a user-accessible port (typically any port number over 1024) would provide a suitable test server.

DIAGNOSTICS

Most diagnostics issued by the client are logged in a specified log file. The log file name is specified at compile time, but may be overridden on the command line.

The number and nature of diagnostics available depends on the debug level used by the client. If you have problems, set the debug level to 3 and peruse the log files.
