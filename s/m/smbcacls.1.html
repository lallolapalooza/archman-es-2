SMBCACLS(1) Comandos de usuario SMBCACLS(1)

NOMBRE

smbcacls - Establecer u obtener ACLs en nombres de archivos o directorios NT

SINOPSIS

smbcacls {//servidor/recurso_compartido} {/nombre_archivo} [-D|--delete=ACL] [-M|--modify=ACL] [-a|--add=ACL] [-S|--set=ACLS] [-C|--chown=NOMBRE_USUARIO] [-G|--chgrp=NOMBRE_GRUPO] [-I|--inherit=CADENA] [--recurse] [--propagate-inheritance] [--save=archivo_guardado] [--restore=archivo_restauracion] [--numeric] [--sddl] [--query-security-info=INT] [--set-security-info=INT] [-t|--test-args] [--domain-sid=SID] [-x|--maximum-access] [-?|--help] [--usage] [-d|--debuglevel=NIVEL_DEBUG] [--debug-stdout] [--configfile=ARCHIVO_CONFIG] [--option=nombre=valor] [-l|--log-basename=NOMBRE_ARCHIVO_LOG] [--leak-report] [--leak-report-full] [-R|--name-resolve=ORDEN_RESOLUCION_NOMBRES] [-O|--socket-options=OPCIONES_SOCKET] [-m|--max-protocol=PROTOCOLO_MAXIMO] [-n|--netbiosname=NOMBRE_NETBIOS] [--netbios-scope=AMBITO] [-W|--workgroup=GRUPO_TRABAJO] [--realm=REALM] [-U|--user=[DOMINIO/]NOMBRE_USUARIO[%CONTRASEÑA]] [-N|--no-pass] [--password=CADENA] [--pw-nt-hash] [-A|--authentication-file=ARCHIVO] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=desired|required|off] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=sign|encrypt|off] [-V|--version]

DESCRIPCIÓN

Esta herramienta forma parte del conjunto de utilidades de samba(7).

El programa smbcacls manipula Listas de Control de Acceso (ACLs) de NT en recursos compartidos de archivos SMB. Una ACL consta de cero o más Entradas de Control de Acceso (ACEs), que definen restricciones de acceso para un usuario o grupo específico.

OPCIONES

Las siguientes opciones están disponibles para el programa smbcacls. El formato de las ACLs se describe en la sección FORMATO DE ACL.

-a|--add acl

Añade las entradas especificadas a la ACL. Las entradas de control de acceso existentes no se modifican.

-M|--modify acl

Modifica el valor de la máscara (permisos) para las ACEs especificadas en la línea de comandos. Se imprimirá un error por cada ACE especificada que no estuviera ya presente en la ACL del objeto.

-D|--delete acl

Elimina cualquier ACE especificada en la línea de comandos. Se imprimirá un error por cada ACE especificada que no estuviera ya presente en la ACL del objeto.

-S|--set acl

Este comando establece la ACL en el objeto solo con lo especificado en la línea de comandos. Cualquier ACL existente se borra. Tenga en cuenta que la ACL especificada debe contener al menos una revisión, tipo, propietario y grupo para que la llamada tenga éxito.

-C|--chown nombre

El propietario de un archivo o directorio puede cambiarse al nombre dado usando la opción -C. El nombre puede ser un SID en formato S-1-x-y-z o un nombre resuelto contra el servidor especificado en el primer argumento.

Este comando es un atajo para -M PROPIETARIO:nombre.

-G|--chgrp nombre

El propietario del grupo de un archivo o directorio puede cambiarse al nombre dado usando la opción -G. El nombre puede ser un SID en formato S-1-x-y-z o un nombre resuelto contra el servidor especificado en el primer argumento.

Este comando es un atajo para -M GRUPO:nombre.

-I|--inherit permitir|eliminar|copiar

Establece o anula la casilla de verificación de Windows "Permitir permisos heredables" usando la opción -I. Para establecer la casilla, pase allow. Para anular la casilla, pase remove o copy. Remove eliminará todas las ACEs heredadas. Copy copiará todas las ACEs heredadas.

--propagate-inheritance

Añade, modifica, elimina o establece ACEs en un árbol de directorios completo según las banderas de herencia. Consulte la sección HERENCIA para obtener más detalles.

--save archivo_guardado

almacena las DACLs en formato sddl del archivo o carpeta especificada para su uso posterior con restore. Las SACLs, el propietario o las etiquetas de integridad no se almacenan.

--restore archivo_restauracion

aplica las DACLs almacenadas a archivos en el directorio.

--recurse

indica que la operación se realiza en el directorio y todos los archivos/directorios inferiores. (solo se aplica a la opción guardar)

--numeric

Esta opción muestra toda la información de la ACL en formato numérico. El valor predeterminado es convertir los SIDs a nombres y los tipos de ACE y las máscaras a un formato de cadena legible.

-m|--max-protocol PROTOCOLO

Esto permite al usuario seleccionar el nivel más alto de protocolo SMB que smbcacls utilizará para conectarse al servidor. Por defecto, esto está establecido en NT1, que es el protocolo SMB1 más alto disponible. Para conectarse utilizando el protocolo SMB2 o SMB3, utilice las cadenas SMB2 o SMB3 respectivamente. Tenga en cuenta que para conectarse a un servidor Windows 2012 con transporte cifrado, se requiere seleccionar un max-protocol de SMB3.

-t|--test-args

No haga nada realmente, solo valide la corrección de los argumentos.

--query-security-info FLAGS

Las banderas de información de seguridad para consultas.

--set-security-info FLAGS

Las banderas de información de seguridad para consultas.

--sddl

Salida y entrada de ACLs en formato sddl.

--domain-sid SID

SID utilizado para el procesamiento sddl.

-x|--maximum-access

Al mostrar una ACL, consulte además al servidor los permisos máximos efectivos. Tenga en cuenta que esto solo es compatible con el protocolo SMB versión 2 o superior.

-?|--help

Imprime un resumen de las opciones de la línea de comandos.

--usage

Muestra un breve mensaje de uso.

-d|--debuglevel=nivel

nivel es un entero de 0 a 10. El valor predeterminado si no se especifica este parámetro es 1 para aplicaciones cliente.

Cuanto más alto sea este valor, más detalle se registrará en los archivos de registro sobre las actividades del servidor. En el nivel 0, solo se registrarán errores críticos y advertencias serias. El nivel 1 es un nivel razonable para el uso diario: genera una pequeña cantidad de información sobre las operaciones realizadas.

Los niveles superiores a 1 generarán una cantidad considerable de datos de registro, y solo deben utilizarse cuando se investigue un problema. Los niveles superiores a 3 están diseñados solo para uso de desarrolladores y generan una ENORME cantidad de datos de registro, la mayor parte de los cuales es extremadamente críptica.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro de nivel de registro en el archivo /etc/samba/smb.conf.

--debug-stdout

Esto redirigirá la salida de depuración a STDOUT. Por defecto, todos los clientes registran en STDERR.

--configfile=<archivo de configuración>

El archivo especificado contiene los detalles de configuración requeridos por el cliente. La información de este archivo puede ser general para cliente y servidor o solo proporcionar opciones específicas del cliente como client smb encrypt. Consulte /etc/samba/smb.conf para obtener más información. El nombre del archivo de configuración predeterminado se determina en tiempo de compilación.

--option=<nombre>=<valor>

Establece la opción smb.conf(5) "<nombre>" al valor "<valor>" desde la línea de comandos. Esto anula los valores predeterminados compilados y las opciones leídas del archivo de configuración. Si un nombre o valor incluye un espacio, envuelva todo --option=nombre=valor entre comillas.

-l|--log-basename=directorio_log

Directorio base para los archivos de registro/depuración. La extensión ".progname" se añadirá (por ejemplo, log.smbclient, log.smbd, etc.). El cliente nunca elimina el archivo de registro.

--leak-report

Habilita el informe de fugas de talloc al salir.

--leak-report-full

Habilita el informe completo de fugas de talloc al salir.

-V|--version

Imprime el número de versión del programa.

-R|--name-resolve=ORDEN_RESOLUCION_NOMBRES

Esta opción se utiliza para determinar qué servicios de nombres y en qué orden resolver nombres de host a direcciones IP. La opción toma una cadena separada por espacios de diferentes opciones de resolución de nombres. Lo mejor es envolver todo --name-resolve=ORDEN_RESOLUCION_NOMBRES entre comillas.

Las opciones son: "lmhosts", "host", "wins" y "bcast". Hacen que los nombres se resuelvan de la siguiente manera:

•lmhosts: Busca una dirección IP en el archivo lmhosts de Samba. Si la línea en lmhosts no tiene un tipo de nombre adjunto al nombre NetBIOS (consulte lmhosts(5) para obtener detalles), entonces cualquier tipo de nombre coincide para la búsqueda.
•host: Realiza una resolución estándar de nombre de host a dirección IP, utilizando el archivo /etc/

-R|--resolve-order=ORDER

Este parámetro especifica el orden en el que se utilizarán los métodos de resolución de nombres. Los métodos de resolución de nombres disponibles son:
•lmhosts: Consulta el archivo lmhosts para la resolución de nombres.
•host: Consulta el archivo hosts, NIS o DNS. Este método de resolución de nombres depende del sistema operativo, por ejemplo, en IRIX o Solaris esto puede ser controlado por el archivo /etc/nsswitch.conf). Tenga en cuenta que este método solo se utiliza si el tipo de nombre NetBIOS que se consulta es el tipo de nombre 0x20 (servidor), de lo contrario se ignora.
•wins: Consulta un nombre con la dirección IP listada en el parámetro wins server. Si no se ha especificado ningún servidor WINS, este método será ignorado.
•bcast: Realiza una difusión en cada una de las interfaces locales conocidas listadas en el parámetro interfaces. Este es el método de resolución de nombres menos fiable, ya que depende de que el host de destino esté en una subred conectada localmente.
Si este parámetro no está establecido, se utilizará el orden de resolución de nombres definido en el parámetro (name resolve order) del archivo /etc/samba/smb.conf.

El orden por defecto es lmhosts, host, wins, bcast. Sin este parámetro o cualquier entrada en el parámetro name resolve order del archivo /etc/samba/smb.conf, los métodos de resolución de nombres se intentarán en este orden.

-O|--socket-options=SOCKETOPTIONS

Opciones de socket TCP que se establecerán en el socket del cliente. Consulte el parámetro de opciones de socket en la página del manual de /etc/samba/smb.conf para ver la lista de opciones válidas.

-m|--max-protocol=MAXPROTOCOL

El valor del parámetro (una cadena) es el nivel de protocolo más alto que será soportado por el cliente.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro client max protocol en el archivo /etc/samba/smb.conf.

-n|--netbiosname=NETBIOSNAME

Esta opción le permite anular el nombre NetBIOS que Samba usa para sí mismo. Esto es idéntico a establecer el parámetro netbios name en el archivo /etc/samba/smb.conf. Sin embargo, una configuración de línea de comandos tendrá precedencia sobre las configuraciones en /etc/samba/smb.conf.

--netbios-scope=SCOPE

Esto especifica un ámbito NetBIOS con el que nmblookup se comunicará al generar nombres NetBIOS. Para obtener detalles sobre el uso de ámbitos NetBIOS, consulte rfc1001.txt y rfc1002.txt. Los ámbitos NetBIOS se usan muy raramente, solo establezca este parámetro si usted es el administrador del sistema a cargo de todos los sistemas NetBIOS con los que se comunica.

-W|--workgroup=WORKGROUP

Establece el dominio SMB del nombre de usuario. Esto anula el dominio por defecto, que es el dominio definido en smb.conf. Si el dominio especificado es el mismo que el nombre NetBIOS del servidor, hace que el cliente inicie sesión utilizando el SAM local del servidor (en contraposición al SAM del Dominio).

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro workgroup en el archivo /etc/samba/smb.conf.

-r|--realm=REALM

Establece el realm para el dominio.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro realm en el archivo /etc/samba/smb.conf.

-U|--user=[DOMAIN\]USERNAME[%PASSWORD]

Establece el nombre de usuario SMB o el nombre de usuario y contraseña.

Si no se especifica %PASSWORD, se le pedirá al usuario. El cliente primero comprobará la variable de entorno USER (que también tiene permiso para contener la contraseña separada por un %), luego la variable LOGNAME (que no tiene permiso para contener una contraseña) y si alguna de ellas existe, se utilizará el valor. Si estas variables de entorno no se encuentran, se puede utilizar el nombre de usuario encontrado en una caché de credenciales de Kerberos.

Una tercera opción es utilizar un archivo de credenciales que contenga la contraseña sin cifrar del nombre de usuario y la contraseña. Esta opción se proporciona principalmente para scripts en los que el administrador no desea pasar las credenciales en la línea de comandos o a través de variables de entorno. Si se utiliza este método, asegúrese de que los permisos del archivo restrinjan el acceso a usuarios no deseados. Consulte la opción -A para más detalles.

Tenga cuidado al incluir contraseñas en scripts o al pasar valores proporcionados por el usuario en la línea de comandos. Por motivos de seguridad, es mejor dejar que la herramienta cliente de Samba solicite la contraseña si es necesario, u obtener la contraseña una vez con kinit.

Aunque Samba intentará limpiar la contraseña del título del proceso (como se ve en ps), esto ocurre después del inicio y, por lo tanto, está sujeto a una condición de carrera.

-N|--no-pass

Si se especifica, este parámetro suprime el mensaje de contraseña normal del cliente al usuario. Esto es útil cuando se accede a un servicio que no requiere contraseña.

A menos que se especifique una contraseña en la línea de comandos o se especifique este parámetro, el cliente solicitará una contraseña.

Si se especifica una contraseña en la línea de comandos y también se define esta opción, la contraseña en la línea de comandos será ignorada silenciosamente y no se utilizará ninguna contraseña.

--password

Especifica la contraseña en la línea de comandos.

Tenga cuidado al incluir contraseñas en scripts o al pasar valores proporcionados por el usuario en la línea de comandos. Por motivos de seguridad, es mejor dejar que la herramienta cliente de Samba solicite la contraseña si es necesario, u obtener la contraseña una vez con kinit.

Si no se especifica --password, la herramienta comprobará la variable de entorno PASSWD, seguida de PASSWD_FD que se espera que contenga un número de descriptor de archivo (FD) abierto.

Finalmente comprobará PASSWD_FILE (que contiene una ruta de archivo a abrir). El archivo solo debe contener la contraseña. ¡Asegúrese de que los permisos del archivo restrinjan el acceso a usuarios no deseados!

Aunque Samba intentará limpiar la contraseña del título del proceso (como se ve en ps), esto ocurre después del inicio y, por lo tanto, está sujeto a una condición de carrera.

--pw-nt-hash

La contraseña proporcionada es el hash NT.

-A|--authentication-file=filename

Esta opción le permite especificar un archivo del que leer el nombre de usuario y la contraseña utilizados en la conexión. El formato del archivo es: 
username = <valor>
password = <valor>
domain   = <valor>

¡Asegúrese de que los permisos del archivo restrinjan el acceso a usuarios no deseados!

-P|--machine-pass

Utiliza la contraseña de cuenta de máquina almacenada.

--simple-bind-dn=DN

DN a utilizar para una vinculación simple.

--use-kerberos=desired|required|off

Este parámetro determina si las herramientas cliente de Samba intentarán autenticarse utilizando Kerberos. Para la autenticación Kerberos, debe utilizar nombres DNS en lugar de direcciones IP al conectarse a un servicio. Por defecto, las herramientas cliente de Samba intentarán utilizar la caché de credenciales Kerberos (ccache) por defecto. En caso de que la ccache no exista o se haya especificado la opción -U|--user, los clientes pedirán introducir una contraseña y obtendrán un ticket Kerberos (kinit) para usted. Si desea utilizar una caché de credenciales Kerberos alternativa, utilice la opción --use-krb5-ccache.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro client use kerberos en el archivo /etc/samba/smb.conf.

--use-krb5-ccache=CCACHE

Especifica la ubicación de la caché de credenciales para la autenticación Kerberos.

Esto forzará --use-kerberos=required.

--use-winbind-ccache

Intenta utilizar la caché de credenciales de winbind.

--client-protection=sign|encrypt|off

Establece la protección de conexión que debe usar la herramienta cliente.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro client protection en el archivo /etc/samba/smb.conf.

En caso de que necesite un control más detallado, puede usar: --option=clientsmbencrypt=OPTION, --option=clientipcsigning=OPTION, --option=clientsigning=OPTION.

FORMATO DE ACL

El formato de una ACL es una o más entradas separadas por comas o saltos de línea. Una entrada ACL es una de las siguientes:

REVISION:<número de revisión>
OWNER:<sid o nombre>
GROUP:<sid o nombre>
ACL:<sid o nombre>:<tipo>/<flags>/<máscara>

Bits de control relacionados con la herencia automática

•OD - "Owner Defaulted" - Indica que el SID del propietario del descriptor de seguridad se proporcionó mediante un mecanismo por defecto.
•GD - "Group Defaulted" - Indica que el SID del grupo del descriptor de seguridad se proporcionó mediante un mecanismo por defecto.
•DP - "DACL Present" - Indica un descriptor de seguridad que tiene una lista de control de acceso discrecional (DACL).
•DD - "DACL Defaulted" - Indica un descriptor de seguridad con una DACL por defecto.
•SP - "SACL Present" - Indica un descriptor de seguridad que tiene una lista de control de acceso del sistema (SACL).
•SD - "SACL Defaulted" - Un mecanismo por defecto, en lugar del proveedor original del descriptor de seguridad, proporcionó la SACL.
•DT - "DACL Trusted"
•SS - "Server Security"
•DR - "DACL Inheritance Required" - Indica un descriptor de seguridad requerido en el que la DACL está configurada para soportar la propagación automática de entradas de control de acceso (ACE) heredables a los objetos hijos existentes.
•SR - "SACL Inheritance Required" - Indica un descriptor de seguridad requerido en el que la SACL está configurada para soportar la propagación automática de ACE heredables a los objetos hijos existentes.
•DI - "DACL Auto Inherited" - Indica un descriptor de seguridad en el que la DACL está configurada para soportar la propagación automática de entradas de control de acceso (ACE) heredables a los objetos hijos existentes.
•SI - "SACL Auto Inherited" - Indica un descriptor de seguridad en el que la SACL está configurada para soportar la propagación automática de ACE heredables a los objetos hijos existentes.
•PD - "DACL Protected" - Evita que la DACL del descriptor de seguridad sea modificada por ACEs heredables.
•PS - "SACL Protected" - Evita que la SACL del descriptor de seguridad sea modificada por ACEs heredables.
•RM - "RM Control Valid" - Indica que el control del gestor de recursos es válido.
•SR - "Self Relative" - Indica un descriptor de seguridad autorreferencial.

La revisión de la ACL especifica la revisión interna de la ACL de Windows NT para el descriptor de seguridad. Si no se especifica, por defecto es 1. Usar valores diferentes a t

han 1 puede causar un comportamiento extraño.

El propietario y el grupo especifican los SID del propietario y del grupo para el objeto. Si se especifica un SID en formato S-1-x-y-z, este se utiliza; de lo contrario, el nombre especificado se resuelve utilizando el servidor en el que reside el archivo o directorio.

Las ACE se especifican con el prefijo "ACL:", y definen los permisos concedidos a un SID. El SID puede especificarse de nuevo en formato S-1-x-y-z o como un nombre, en cuyo caso se resuelve contra el servidor en el que reside el archivo o directorio. Los valores de tipo, indicadores y máscara determinan el tipo de acceso concedido al SID.

El tipo puede ser ALLOWED o DENIED para permitir/denegar el acceso al SID.

El campo de indicadores define cómo se debe considerar la ACE al realizar la herencia. smbcacls utiliza estos indicadores cuando se ejecuta con --propagate-inheritance.

Los indicadores se pueden especificar como valores decimales o hexadecimales, o con los alias (XX) respectivos, separados por una barra vertical "|".

•(OI) Herencia de objeto 0x1
•(CI) Herencia de contenedor 0x2
•(NP) No propagar herencia 0x4
•(IO) Solo herencia 0x8
•(I) La ACE fue heredada 0x10

La máscara es un valor que expresa el derecho de acceso concedido al SID. Se puede proporcionar como valor decimal o hexadecimal, o utilizando una de las siguientes cadenas de texto que se mapean a los permisos de archivo de NT del mismo nombre.

•R - Permitir acceso de lectura
•W - Permitir acceso de escritura
•X - Permiso de ejecución sobre el objeto
•D - Eliminar el objeto
•P - Cambiar permisos
•O - Tomar propiedad

Se pueden especificar los siguientes permisos combinados:

•READ - Equivalente a los permisos 'RX'
•CHANGE - Equivalente a los permisos 'RXWD'
•FULL - Equivalente a los permisos 'RWXDPO'

HERENCIA

Los indicadores de herencia por ACE se pueden establecer en el campo de indicadores de la ACE. Por defecto, las ACE heredables, por ejemplo, las marcadas para herencia de objeto (OI) o herencia de contenedor (CI), no se propagan a subarchivos o subcarpetas. Sin embargo, con el argumento --propagate-inheritance especificado, dichas ACE se propagan automáticamente según algunas reglas de herencia.

•Los indicadores de ACE heredables (OI)(OI) solo se pueden aplicar a carpetas.
•Cualquier ACE heredable aplicada a subarchivos o subcarpetas se marca con el indicador heredado (I). Las ACE heredables se aplican a las carpetas a menos que se establezca el indicador de no propagación (NP).
•Cuando una ACE con solo el indicador (OI) establecido se propaga a una subcarpeta, también se aplica el indicador de solo herencia (IO). Esto indica que los permisos asociados con la ACE no se aplican a la propia carpeta (solo a sus archivos hijos). Al aplicar la ACE a un archivo hijo, la ACE se hereda normalmente.
•Cuando una ACE con solo el indicador (CI) establecido se propaga a un archivo hijo, no tiene ningún efecto; cuando se propaga a una carpeta hija, se hereda normalmente.
•Cuando una ACE que tiene ambos indicadores (OI) y (CI) establecidos, la ACE se hereda normalmente tanto por carpetas como por archivos.

(OI)(READ) añadido a la carpeta padre

+-parent/        (OI)(READ)
| +-file.1       (I)(READ)
| +-nested/      (OI)(IO)(I)(READ)
  |   +-file.2   (I)(READ)

(CI)(READ) añadido a la carpeta padre

+-parent/        (CI)(READ)
| +-file.1
| +-nested/      (CI)(I)(READ)
  |   +-file.2

(OI)(CI)(READ) añadido a la carpeta padre

+-parent/        (OI)(CI)(READ)
| +-file.1       (I)(READ)
| +-nested/      (OI)(CI)(I)(READ)
  |   +-file.2   (I)(READ)

(OI)(NP)(READ) añadido a la carpeta padre

+-oi_dir/        (OI)(NP)(READ)
| +-file.1       (I)(READ)
| +-nested/
|   +-file.2

(CI)(NP)(READ) añadido a la carpeta padre

+-oi_dir/        (CI)(NP)(READ)
| +-file.1
| +-nested/      (I)(READ)
|   +-file.2

(OI)(CI)(NP)(READ) añadido a la carpeta padre

+-parent/        (CI)(OI)(NP)(READ)
| +-file.1       (I)(READ)
| +-nested/      (I)(READ)
|   +-file.2

Los archivos y carpetas con ACL protegidas no permiten permisos heredables (establecidos con -I). Dichos objetos no recibirán ACE marcadas para herencia con (CI) o (OI).

ESTADO DE SALIDA

El programa smbcacls establece el estado de salida dependiendo del éxito o no de las operaciones realizadas. El estado de salida puede ser uno de los siguientes valores.

Si la operación tuvo éxito, smbcacls devuelve un estado de salida de 0. Si smbcacls no pudo conectarse al servidor especificado, o hubo un error al obtener o establecer las ACL, se devuelve un estado de salida de 1. Si hubo un error al analizar algún argumento de la línea de comandos, se devuelve un estado de salida de 2.
