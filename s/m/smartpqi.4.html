smartpqi(4) Device Drivers Manual smartpqi(4)

NOMBRE

smartpqi - Controlador SCSI de Microchip Smart Storage

SINOPSIS

modprobe smartpqi [disable_device_id_wildcards={0|1}] [disable_heartbeat={0|1}] [disable_ctrl_shutdown={0|1}] [lockup_action={none|reboot|panic}] [expose_ld_first={0|1}] [hide_vsep={0|1}] [disable_managed_interrupts={0|1}] [ctrl_ready_timeout={0|[30,1800]}]

DESCRIPCIÓN

smartpqi es un controlador SCSI para controladores Microchip Smart Storage.

Operaciones ioctl() Soportadas

Para compatibilidad con aplicaciones escritas para los controladores cciss(4) y hpsa(4), muchas, pero no todas las operaciones ioctl(2) soportadas por el controlador hpsa también son soportadas por el controlador smartpqi. Las estructuras de datos utilizadas por estas operaciones se describen en el archivo fuente del kernel de Linux include/linux/cciss_ioctl.h.

CCISS_DEREGDISK
CCISS_REGNEWDISK
CCISS_REGNEWD
Estas operaciones hacen exactamente lo mismo, que es hacer que el controlador busque de nuevo dispositivos. Esto hace exactamente lo mismo que escribir en el atributo rescan específico del host de smartpqi.
CCISS_GETPCIINFO
Esta operación devuelve el dominio PCI, bus, dispositivo y función, y "ID de placa" (ID de subsistema PCI).
CCISS_GETDRIVVER
Esta operación devuelve la versión del controlador en cuatro bytes, codificada como:

(major_version << 28) | (minor_version << 24) |
        (release << 16) | revision

CCISS_PASSTHRU
Permite pasar comandos BMIC y CISS al controlador.

Opciones de Arranque

disable_device_id_wildcards={0|1}
Deshabilita el soporte para comodines de ID de dispositivo. El valor predeterminado es 0 (los comodines están habilitados).
disable_heartbeat={0|1}
Deshabilita el soporte para la verificación del latido del controlador. Este parámetro se utiliza para fines de depuración. El valor predeterminado es 0 (la verificación del latido del controlador está habilitada).
disable_ctrl_shutdown={0|1}
Deshabilita el soporte para apagar el controlador en caso de un bloqueo del controlador. El valor predeterminado es 0 (el controlador se apagará).
lockup_action={none|reboot|panic}
Especifica la acción que toma el controlador cuando se detecta un bloqueo del controlador. La acción predeterminada es none.
parámetro acción
none poner el controlador fuera de línea solamente
reboot reiniciar el sistema
panic provocar un pánico del sistema
expose_ld_first={0|1}
Esta opción expone los dispositivos lógicos al SO antes que los dispositivos físicos. El valor predeterminado es 0 (los dispositivos físicos se exponen primero).
hide_vsep={0|1}
Esta opción deshabilita la exposición del SEP virtual al SO. El valor predeterminado es 0 (el SEP virtual se expone).
disable_managed_interrupts={0|1}
Deshabilita la utilización por parte del controlador de las interrupciones gestionadas del kernel de Linux para los controladores. La función de interrupciones gestionadas distribuye automáticamente las interrupciones a todas las CPUs disponibles y asigna afinidad SMP. El valor predeterminado es 0 (interrupciones gestionadas habilitadas).
ctrl_ready_timeout={0|[30,1800]}
Esta opción especifica el tiempo de espera en segundos para que el controlador espere a que el controlador esté listo. El rango válido es 0 o [30, 1800]. El valor predeterminado es 0, lo que hace que el controlador utilice un tiempo de espera de 180 segundos.

ARCHIVOS

Nodos de Dispositivo

Las unidades de disco se acceden a través del controlador de disco SCSI (sd), las unidades de cinta a través del controlador de cinta SCSI (st), y el controlador RAID a través del controlador genérico SCSI (sg), con nodos de dispositivo nombrados /dev/sd*, /dev/st*, y /dev/sg*, respectivamente.

Archivos de atributos específicos del host SmartPQI en /sys

/sys/class/scsi_host/host*/rescan
El atributo rescan del host es un atributo de solo escritura. Escribir en este atributo hará que el controlador busque dispositivos nuevos, cambiados o eliminados (por ejemplo, unidades de cinta conectadas en caliente, o volúmenes lógicos recién configurados o eliminados) y notifique a la capa media de SCSI cualquier cambio detectado. Normalmente esta acción se activa automáticamente por cambios de configuración, por lo que el usuario normalmente no debería tener que escribir en este archivo. Hacerlo puede ser útil al conectar en caliente dispositivos como unidades de cinta o cajas de almacenamiento completas que contienen volúmenes lógicos preconfigurados.
/sys/class/scsi_host/host*/lockup_action
El atributo lockup_action del host es un atributo de lectura/escritura. Este atributo hará que el controlador realice una acción específica en el improbable caso de que se haya detectado un bloqueo del controlador. Consulte OPCIONES arriba para una explicación de los valores de lockup_action.
/sys/class/scsi_host/host*/driver_version
El atributo driver_version es de solo lectura. Este atributo contiene la versión del controlador smartpqi.
Por ejemplo:

$ 
cat /sys/class/scsi_host/host1/driver_version
1.1.2-126

/sys/class/scsi_host/host*/firmware_version
El atributo firmware_version es de solo lectura. Este atributo contiene la versión del firmware del controlador.
Por ejemplo:

$ 
cat /sys/class/scsi_host/host1/firmware_version
1.29-112

/sys/class/scsi_host/host*/model
El atributo model es de solo lectura. Este atributo contiene la cadena de identificación del producto del controlador.
Por ejemplo:

$ 
cat /sys/class/scsi_host/host1/model
1100-16i

/sys/class/scsi_host/host*/serial_number
El atributo serial_number es de solo lectura. Este atributo contiene el número de identificación único del controlador.
Por ejemplo:

$ 
cat
/sys/class/scsi_host/host1/serial_number
6A316373777

/sys/class/scsi_host/host*/vendor
El atributo vendor es de solo lectura. Este atributo contiene la cadena de identificación del proveedor del controlador.
Por ejemplo:

$ 
cat /sys/class/scsi_host/host1/vendor
Adaptec

/sys/class/scsi_host/host*/enable_stream_detection
El atributo enable_stream_detection es de lectura/escritura. Este atributo habilita/deshabilita la detección de flujo en el controlador. Habilitar la detección de flujo puede mejorar el rendimiento de escritura secuencial para volúmenes habilitados para ioaccel. Consulte la sección del atributo de disco ssd_smart_path_enabled para obtener detalles sobre los volúmenes habilitados para ioaccel. El valor predeterminado es 1 (detección de flujo habilitada).
Ejemplo de habilitación:

$ 
echo 1 > /sys/class/scsi_host/host1/enable_stream_detection

/sys/class/scsi_host/host*/enable_r5_writes
El atributo enable_r5_writes es de lectura/escritura. Este atributo habilita/deshabilita las operaciones de escritura RAID 5 para volúmenes habilitados para ioaccel. Habilitarlas puede mejorar el rendimiento de escritura secuencial. Consulte la sección del atributo de disco ssd_smart_path_enabled para obtener detalles sobre los volúmenes habilitados para ioaccel. El valor predeterminado es 1 (escrituras RAID 5 habilitadas).
Ejemplo de habilitación:

$ 
echo 1 > /sys/class/scsi_host/host1/enable_r5_writes

/sys/class/scsi_host/host*/enable_r6_writes
El atributo enable_r6_writes es de lectura/escritura. Este atributo habilita/deshabilita las operaciones de escritura RAID 6 para volúmenes habilitados para ioaccel. Habilitarlas puede mejorar el rendimiento de escritura secuencial. Consulte la sección del atributo de disco ssd_smart_path_enabled para obtener detalles sobre los volúmenes habilitados para ioaccel. El valor predeterminado es 1 (escrituras RAID 6 habilitadas).
Ejemplo de habilitación:

$ 
echo 1 > /sys/class/scsi_host/host1/enable_r6_writes

Archivos de atributos de disco específicos de SmartPQI en /sys

En las siguientes especificaciones de archivo, c representa el número del controlador SCSI apropiado, b es el número del bus, t el número del destino y l es el número de unidad lógica (LUN).

/sys/class/scsi_disk/c:b:t:l/device/raid_level
El atributo raid_level es de solo lectura. Este atributo contiene el nivel RAID del volumen lógico.
Por ejemplo:

$ 
cat /sys/class/scsi_disk/4:0:0:0/device/raid_level
RAID 0

/sys/class/scsi_disk/c:b:t:l/device/sas_address
El atributo sas_address es de solo lectura. Este atributo contiene la dirección SAS del dispositivo.
Por ejemplo:

$ 
cat /sys/class/scsi_disk/1:0:3:0/device/sas_address
0x5001173d028543a2

/sys/class/scsi_disk/c:b:t:l/device/ssd_smart_path_enabled
El atributo ssd_smart_path_enabled es de solo lectura. Este atributo es para volúmenes habilitados para ioaccel. (Ioaccel es una ruta de envío de controlador alternativa que permite al controlador enviar solicitudes de E/S directamente a los dispositivos SCSI de backend, omitiendo el firmware del controlador. Esto resulta en un aumento del rendimiento. Este método se utiliza para discos HBA y para volúmenes lógicos compuestos por SSD). Contiene 1 si ioaccel está habilitado para el volumen y 0 en caso contrario.
Por ejemplo:

$ 
cat /sys/class/scsi_disk/1:0:3:0/device/ssd_smart_path_enabled
0

/sys/class/scsi_disk/c:b:t:l/device/lunid
El atributo lunid es de solo lectura. Este atributo contiene el ID LUN SCSI para el dispositivo.
Por ejemplo:

$ 
cat /sys/class/scsi_disk/13:1:0:3/device/lunid
0x0300004000000000

/sys/class/scsi_disk/c:b:t:l/device/unique_id
El atributo unique_id es de solo lectura. Este atributo contiene un ID de 16 bytes que identifica de forma única el dispositivo dentro del controlador.
Por ejemplo:

$ 
cat /sys/class/scsi_disk/13:1:0:3/device/unique_id
600508B1001C6D4723A8E98D704FDB94

/sys/class/scsi_disk/c:b:t:l/device/path_info
El atributo path_info es de solo lectura. Este atributo contiene el c:b:t:l del dispositivo junto con el tipo de dispositivo y si el dispositivo está Activo o Inactivo. Si el dispositivo es un dispositivo HBA, path_info también mostrará el PUERTO, CAJA y BAHÍA en los que está conectado el dispositivo.
Por ejemplo:

$ 
cat /sys/class/scsi_disk/13:1:0:3/device/path_info
[13:1:0:3]    Acceso directo    Activo
$ 
cat /sys/class/scsi_disk/12:0:9:0/device/path_info
[12:0:9:0]  Acceso directo  PUERTO: C1 CAJA: 1 BAHÍA: 14 Inactivo
[12:0:9:0]  Acceso directo  PUERTO: C0 CAJA: 1 BAHÍA: 14 Activo

/sys/class/scsi_disk/c:b:t:l/device/raid_bypass_cnt
El atributo raid_bypass_cnt es de solo lectura. Este atributo contiene el número de solicitudes de E/S que han pasado por la ruta ioaccel para volúmenes habilitados para ioaccel. Consulte la sección del atributo de disco ssd_smart_path_enabled para obtener detalles sobre los volúmenes habilitados para ioaccel.
Por ejemplo:

$ 
cat /sys/class/scsi_disk/13:1:0:3/device/raid_bypass_cnt
0x300

/sys/class/scsi_disk/c:b:t:l/device/sas_ncq_prio_enable
El atributo sas_ncq_prio_enable es de lectura/escritura. Este atributo habilita el soporte de prioridad NCQ de SATA. Este atributo solo funciona cuando el dispositivo tiene soporte NCQ y el firmware del controlador puede manejar E/S con el atributo de prioridad NCQ.
Por ejemplo:

$ 
echo 1 > /sys/class/scsi_disk/13:1:0:3/device/sas_ncq_prio_enable

VERSIONES

El controlador smartpqi se añadió en Linux 4.9.

NOTAS

Configuración

Para configurar un controlador Microchip Smart Storage, consulte la Guía del usuario del controlador, que se puede encontrar buscando el controlador específico en https://www.microchip.com/design-centers/storage.

HISTORIAL

/sys/class/scsi_host/host*/version fue reemplazado por dos entradas sysfs:

/sys/class/scsi_host/host*/driver_version
/sys/class/scsi_host/host*/firmware_version
