NOMBRE

smokeping_config - Referencia para el archivo de configuración de SmokePing

RESUMEN

SmokePing toma su configuración de un único archivo central. Su ubicación debe estar codificada en el script de smokeping y en smokeping.cgi.

El contenido de este manual se genera directamente desde el analizador del archivo de configuración.

El analizador del archivo de configuración está escrito utilizando el módulo Config::Grammar de David Schweikert. Lee todo sobre él en Config::Grammar.

El archivo de configuración tiene una estructura similar a un árbol con encabezados de sección en varios niveles. También contiene asignaciones de variables y tablas.

Advertencia: este manual es bastante largo. Consulta smokeping_examples para ver ejemplos de configuración sencillos.

REFERENCIA

SINTAXIS GENERAL

El texto a continuación describe la sintaxis general del archivo de configuración de SmokePing. Se copió de la documentación de Config::Grammar.

Un '#' denota un comentario hasta el final de la línea, se permiten líneas vacías y se recorta el espacio al principio y al final de las líneas.

Un '\' al final de la línea marca una línea continuada en la siguiente línea. Se insertará un solo espacio entre las líneas concatenadas.

'@include filename' se utiliza para incluir otro archivo.

'@define a some value' reemplazará todas las ocurrencias de 'a' en el texto siguiente con 'some value'.

Los campos en tablas que contienen espacios en blanco pueden estar entre comillas simples "'" o triples """. Los espacios en blanco también se pueden escapar con "\". Las comillas dentro de comillas están permitidas, pero también deben escaparse con una barra inversa.

SINTAXIS ESPECÍFICA

El texto a continuación describe la sintaxis específica del archivo de configuración de SmokePing.

*** General *** (sección obligatoria)

Valores de configuración generales válidos para toda la configuración de SmokePing.

Las siguientes variables se pueden establecer en esta sección:

owner (configuración obligatoria)
Nombre de la persona responsable de esta instalación de smokeping.
imgcache (configuración obligatoria)
Un directorio visible en tu servidor web donde SmokePing puede almacenar en caché los gráficos.
imgurl (configuración obligatoria)
Una URL absoluta al directorio imgcache o una relativa al directorio donde guardas el CGI de SmokePing.
datadir (configuración obligatoria)
El directorio donde SmokePing puede guardar sus archivos rrd.
dyndir
El directorio base donde SmokePing guarda los archivos relacionados con la función DYNAMIC. Este directorio debe ser escribible por el servidor WWW. También se utiliza para el almacenamiento temporal de resultados de sondeo de esclavos por parte del maestro en el modo maestro/esclavo.

Si esta variable no se especifica, se utilizará el valor de "datadir" en su lugar.

pagedir
Directorio para almacenar representaciones estáticas de páginas.
piddir (configuración obligatoria)
El directorio donde SmokePing guarda su pid cuando está demonizado.
sendmail
Ruta a tu binario de sendmail. Se utilizará para enviar correos electrónicos en conexión con el soporte de direcciones DYNAMIC.
offset
Si ejecutas muchas instancias de smokeping, es posible que desees evitar que impacten tu red al mismo tiempo. Usando el parámetro offset, puedes cambiar el punto en el tiempo cuando se ejecutan las sondas. El offset se especifica en % del intervalo total, o alternativamente como 'random'. Recomiendo usar 'random'. Ten en cuenta que esto NO influye en los rrd en sí, es solo una cuestión de cuándo se inicia la adquisición de datos. El offset predeterminado es 'random'.
smokemail (configuración obligatoria)
Ruta a la plantilla de correo DYNAMIC para hosts. Esta plantilla de correo debe contener palabras clave del tipo <##keyword##>. Hay una plantilla de ejemplo incluida con SmokePing.
cgiurl (configuración obligatoria)
Ruta completa de la URL del SmokePing.cgi
mailhost
En lugar de usar sendmail, puedes especificar el nombre de un servidor smtp y usar el módulo Net::SMTP de perl para enviar correo (para alertas y script del cliente DYNAMIC). Se pueden especificar varios mailhosts separados por comas. SmokePing intentará uno tras otro si uno no responde durante 5 segundos.
mailuser
nombre de usuario en mailhost, SmokePing usará este usuario para enviar correo (Net::SMTP).
mailpass
contraseña de username en mailhost, SmokePing usará esta contraseña para enviar correo (Net::SMTP).
snpphost
Si tienes un servidor SNPP (Simple Network Pager Protocol) a mano, también puedes enviar alertas allí. Usa la sintaxis snpp:someaddress para usar una dirección snpp en cualquier lugar donde puedas usar una dirección de correo electrónico.
contact (configuración obligatoria)
Dirección de correo electrónico de la persona responsable de esta instalación de smokeping.
display_name
Cómo debe llamarse el host maestro cuando trabaja en modo maestro/esclavo. Esto se usa en el gráfico de resumen, por ejemplo.
syslogfacility
La instalación de syslog a utilizar, por ejemplo, local0...local7. Nota: el registro de syslog solo se utiliza si especificas esto.
syslogpriority
La prioridad de syslog a utilizar, por ejemplo, debug, notice o info. El valor predeterminado es info.
concurrentprobes
Si usas múltiples sondas o múltiples instancias de la misma sonda y deseas que se ejecuten simultáneamente en procesos separados, configúralo en 'yes'. Esto te da la posibilidad de especificar parámetros step y offset específicos de la sonda (ver la sección 'Probes') para cada sonda y hace que las sondas no puedan bloquearse mutuamente en casos de interrupción de servicios. El valor predeterminado es 'yes', pero si por alguna razón deseas el comportamiento anterior, puedes configurarlo en 'no'.
changeprocessnames
Cuando se usa 'concurrentprobes' (ver arriba), esto controla si los subprocesos de la sonda deben cambiar su cadena argv para indicar su sonda en el nombre del proceso. Si se configura en 'yes' (el valor predeterminado), el nombre de la sonda se agregará al nombre del proceso como '[probe]', por ejemplo, '/usr/bin/smokeping [FPing]'. Si no te gusta este comportamiento, configura esta variable en 'no'. Si 'concurrentprobes' no está configurado en 'yes', esta variable no tiene efecto.

Valor predeterminado: changeprocessnames = yes

tmail
Ruta a tu archivo de plantilla de correo HTML tSmoke. Consulta la documentación de tSmoke para más detalles.
changecgiprogramname
Por lo general, el CGI de Smokeping intenta registrar cualquier posible error con un nombre de programa extendido que incluye la dirección IP del cliente remoto para facilitar la depuración. Si esta variable se configura en 'no', el nombre del programa no se modificará. La única razón por la que querrías esto es si tienes una versión muy antigua del módulo CGI::Carp. Consulta el documento de instalación para más detalles.

Valor predeterminado: changecgiprogramname = yes

linkstyle
Cómo se el CGI
explicar los valores de `linkstyle`. Los valores posibles son:
absoluto
Nombre de host completo y ruta derivados de la variable 'cgiurl'.

<a href="http://hostname/path/smokeping.cgi?foo=bar">

relativo
Solo se especifica la parte del parámetro.

<a href="?foo=bar">

original
La forma en que se generaron los enlaces antes de la versión 2.0.4 de Smokeping: sin nombre de host, solo la ruta.

<a href="/path/smokeping.cgi?foo=bar">

El valor predeterminado es "relativo", lo que, con suerte, funciona para todos.

Valor predeterminado: linkstyle = relative

precreateperms
Si esta variable está configurada, el demonio Smokeping creará su jerarquía de directorios debajo de 'dyndir' (el árbol escribible por CGI) al inicio con los bits de permisos de directorio especificados. El valor se interpreta como un valor octal, por ejemplo, 775 para rwxrwxr-x, etc.

Si no está configurado, los directorios se crearán dinámicamente con umask 022.

Ejemplo: precreateperms = 2755

*** Base de datos *** (sección obligatoria)

Describe las propiedades de la base de datos de series temporales circulares (round robin database) para almacenar los datos de SmokePing. Tenga en cuenta que no es posible editar RRD existentes cambiando las entradas en el archivo cfg.

Las siguientes variables se pueden configurar en esta sección:

step (configuración obligatoria)
Duración del intervalo de operación base de SmokePing en segundos. SmokePing saldrá cada step segundos para hacer ping a sus hosts de destino. Si 'concurrentprobes' está configurado como 'yes' (ver arriba), esta variable puede ser anulada por cada sondeo. Tenga en cuenta que el paso en los archivos RRD es fijo cuando se generan originalmente, y si cambia el parámetro de paso después, tendrá que eliminar los archivos RRD antiguos o convertirlos de alguna manera.
pings (configuración obligatoria)
¿Cuántos pings se deben enviar a cada destino? Sugerido: 20 pings. Valor mínimo: 3 pings. Esto puede ser anulado por cada sondeo. Algunos sondeos (los derivados de basefork.pm, es decir, la mayoría excepto las variantes de FPing) permitirán que esto sea anulado específicamente por destino. Tenga en cuenta que el número de pings en los archivos RRD es fijo cuando se generan originalmente, y si cambia este parámetro después, tendrá que eliminar los archivos RRD antiguos o convertirlos de alguna manera.

*** Presentación *** (sección obligatoria)

Define cómo se deben presentar los datos de SmokePing.

Las siguientes variables se pueden configurar en esta sección:

template (configuración obligatoria)
La plantilla de la página web debe contener palabras clave del formulario <##palabra clave##>. Hay una plantilla de ejemplo incluida con SmokePing; úsela como base para sus experimentos. La plantilla predeterminada contiene un puntero al contador y a la página de inicio de SmokePing. Me alegraría si no la eliminara, ya que me da una indicación de cuán ampliamente se utiliza la herramienta.

Por defecto, SmokePing asume el conjunto de caracteres 'utf-8'. Si utiliza algo diferente, este es el lugar para indicarlo.
htmltitle
Por defecto, SmokePing mostrará el título del gráfico en la imagen, cuando se establece en 'yes', el título se inserta en la página html.
graphborders
Por defecto, SmokePing mostrará un borde gris sobre un fondo gris claro, si se establece en 'no', los bordes se ocultarán y el fondo y el lienzo serán transparentes.
literalsearch
Por defecto, SmokePing procesará las consultas del menú de filtro como expresiones regulares, si se establece en 'yes', las búsquedas se tratarán como cadenas literales en su lugar.
colortext
colorbackground
Por defecto, SmokePing mostrará el fondo gris claro, lo que puede ser anulado aquí con su propio valor RGB.
colorborder
Por defecto, SmokePing mostrará el borde gris, lo que puede ser anulado aquí con su propio valor RGB.

Nombre

echoping_ldap - comprueba la conectividad de red

Sinopsis

echoping [-d debug] [-f logfile] [-L logfacility] [-p facility] [-t facility] [-V]

echoping [-h]

Descripción

echoping se utiliza para comprobar la conectividad de red a un host determinado. Puede realizar comprobaciones de ping (ICMP) y comprobaciones de apertura de sockets (TCP).

La herramienta puede ampliarse mediante plugins. Los plugins se cargan mediante la variable de configuración plugin. Los plugins pueden tener sus propios argumentos, definidos en la variable pluginargs.

Para obtener más información, véase el sitio web del proyecto: http://www.echoping.org/

El archivo de configuración se encuentra en /etc/echoping.conf.

Archivo de configuración

El archivo de configuración se divide en secciones. Las secciones están delimitadas por [section_name]. La primera sección siempre se denomina global y contiene valores predeterminados para todas las demás secciones.

Las secciones se pueden anidar. Si se utiliza una sección anidada con un nombre de host, todos los hosts de esa sección se vincularán a la sección principal. Esto permite definir grupos de hosts.

Las secciones pueden ser:

global
Valores predeterminados para todas las demás secciones.
ldap
Valores predeterminados para todas las comprobaciones LDAP.

Ejemplos

Comprobar la conectividad de red a un host específico:

echoping host.example.com

Comprobar la conectividad de red a varios hosts:

echoping host1.example.com host2.example.com

Comprobar la conectividad de red a hosts de un archivo:

echoping -f hosts.txt

Comprobar la conectividad de red utilizando un archivo de configuración personalizado:

echoping -c /etc/echoping/myconfig.conf host.example.com

Realizar una comprobación de puerto TCP en un host específico:

echoping -t 80 host.example.com

Realizar una comprobación de puerto UDP en un host específico:

echoping -p 53 host.example.com

Realizar una comprobación LDAP en un host específico:

echoping -L cn=$,ou=Users,dc=example,dc=com host.example.com

Archivos

/etc/echoping.conf: archivo de configuración principal.

~/.echoping.conf: archivo de configuración del usuario.

parents
After setting up a hierarchy in the Presentation section of the configuration file you can use this property to assign an entry to alternate hierarchies. The format for parent entries is. 
hierarchyA:/Node1/Node2 hierarchyB:/Node3

The entries from all parent properties together will build a new tree for each hierarchy. With this method it is possible to make a single target show up multiple times in a tree. If you think this is a good thing, go ahead, nothing is stopping you. Since you do not only define the parent but the full path of the parent node, circular dependencies are not possible.

hide
Set the hide property to 'yes' to hide this host from the navigation menu and from search results. Note that if you set the hide property on a non leaf entry all subordinate entries will also disappear in the menu structure. If you know a direct link to a page it is still accessible. Pages which are hidden from the menu due to a parent being hidden will still show up in search results and in alternate hierarchies where they are below a non hidden parent.

Default value: hide = no

nomasterpoll
Use this in a master/slave setup where the master must not poll a particular target. The master will now skip this entry in its polling cycle. Note that if you set the hide property on a non leaf entry all subordinate entries will also disappear in the menu structure. You can still access them via direct link or via an alternate hierarchy.

If you have no master/slave setup this will have a similar effect to the hide property, except that the menu entry will still show up, but will not contain any graphs.

This variable inherits its value from the parent section if nothing is specified here.

Default value: nomasterpoll = no

*** Alertas ***

La sección Alertas le permite configurar detectores de pérdida y RTT. Después de cada ronda de sondeo, SmokePing examinará sus datos y determinará qué detectores coinciden. Los detectores se habilitan por destino y son heredados por los hijos del destino.

Los detectores no son solo umbrales simples que se activan a la primera señal de un problema. Son configurables para detectar patrones especiales de pérdida o RTT. Le permiten mirar un número de lecturas pasadas para tomar una decisión más informada sobre qué tipo de alerta se debe enviar, o si se debe enviar una alerta en absoluto.

Los patrones son números precedidos por un operador que indica el tipo de comparación requerida para una coincidencia.

El siguiente patrón de RTT detecta si el RTT de un destino pasa de estar constantemente por debajo de 10 ms a estar constantemente por encima de 100 ms:

antiguo ------------------------------> nuevo
<10,<10,<10,<10,<10,>10,>100,>100,>100

Los patrones de pérdida funcionan de manera similar, excepto que la pérdida se define como el porcentaje que el número total de paquetes recibidos representa del número total de paquetes enviados.

antiguo ------------------------------> nuevo
==0%,==0%,==0%,==0%,>20%,>20%,>=20%

Además de los números normales, los patrones también pueden contener los valores * que es verdadero para todos los valores independientemente del operador. Y U que es verdadero para datos desconocidos junto con los operadores == y =!.

Los detectores normalmente actúan sobre cambios de estado. Esto tiene la desventaja de que fallarán al encontrar condiciones que ya estaban presentes al iniciar smokeping. Para esto, es posible escribir detectores que comiencen con el valor especial ==S que se inserta siempre que se inicia smokeping.

Puedes escribir

==S,>20%,>20%

para detectar líneas que han estado perdiendo más del 20% de los paquetes durante dos períodos después del inicio.

Si quieres asegurarte de que un valor está dentro de un cierto rango, puedes usar dos condiciones en un solo elemento

>45%<=55%

A veces puede ocurrir que las condiciones ocurran a intervalos irregulares. Pero aún así solo quieres lanzar una alerta si ocurren varias veces dentro de un período de tiempo determinado. El operador *X* ignorará hasta X valores y aún así permitirá que el patrón coincida:

>10%,*10*,>10%

se activará si se ha perdido más del 10% de los paquetes al menos dos veces en las últimas 10 muestras.

Un ejemplo completo

*** Alertas ***
a = admin@company.xy,peter@home.xy
de = smokealert@company.xy
+lossdetect
tipo = loss
# en por ciento
patrón = ==0%,==0%,==0%,==0%,>20%,>20%,>20%
comentario = de repente hay pérdida de paquetes
+miniloss
tipo = loss
# en por ciento
patrón = >0%,*12*,>0%,*12*,>0%
comentario = pérdida de paquetes detectada 3 veces en las últimas dos horas
+rttdetect
tipo = rtt
# en milisegundos
patrón = <10,<10,<10,<10,<10,<100,>100,>100,>100
comentario = ¿se volvió a estropear el enrutamiento?
+rttbadstart
tipo = rtt
# en milisegundos
patrón = ==S,==U
comentario = desconectado al inicio

Las siguientes variables se pueden configurar en esta sección:

a (configuración obligatoria)
Una dirección de correo electrónico para enviar alertas, o el nombre de un programa a ejecutar cuando una alerta coincida. Para llamar a un programa, el primer carácter del valor de a debe ser un símbolo de tubería ""|"". El programa se llamará cada vez que una alerta coincida, utilizando los siguientes 5 argumentos (excepto si edgetrigger es 'yes'; ver abajo): nombre-de-alerta, destino, patrón-de-pérdida, patrón-de-rtt, nombre-de-host. También puede proporcionar una lista de direcciones y programas separada por comas.
de (configuración obligatoria)
¿de quién deben parecer provenir las alertas?
edgetrigger
Las notificaciones de alerta y/o los programas ejecutados se activan normalmente cada vez que la alerta coincide. Si esta variable se establece en 'yes', solo se activarán cuando el estado de la alerta cambie, es decir, cuando se eleve y cuando se borre. Las coincidencias posteriores de la misma alerta no activarán una notificación.

Cuando esta variable se establece en 'yes', un programa de notificación (ver la documentación de la variable a arriba) recibirá un sexto argumento, raise, que tendrá el valor 1 si la alerta acaba de ser elevada y 0 si fue borrada.

Valor por defecto: edgetrigger = no

mailtemplate
Al enviar correos electrónicos para alertas, smokeping normalmente utiliza un mensaje generado internamente. Con mailtemplate puede especificar un nombre de archivo para una plantilla personalizada. El archivo debe contener una línea 'Subject: ...'. El resto del archivo debe contener texto. Todas las cadenas de tipo <##palabra clave##> se reemplazarán en la plantilla antes de enviarla. Las siguientes palabras clave son compatibles: 
<##ALERT##>    - nombre del destino
<##WHAT##>     - estado (está activo, fue elevado, fue borrado)
<##LINE##>     - ruta en el árbol de configuración
<##URL##>      - página web para el gráfico
<##STAMP##>    - fecha y hora
<##PAT##>      - patrón que coincidió con la alerta
<##LOSS##>     - historial de pérdida
<##RTT##>      - historial de rtt
<##COMMENT##>  - comentario

This is a list of configuration variables recognized by smokeping. The configuration file is parsed top-down with sections delimited by *** Section ***. The names of the sections are used to decide which part of the configuration applies to which target. Configuration variables are set using the syntax name = value. Comments start with # and end at the end of the line.

Variables starting with + or * indicate that the variable is a template. + indicates that it is a template that can be inherited from, and * indicates that it is a template that cannot be inherited from.

Sections can be nested. A section name may contain any character except whitespace. It is recommended to use only alphanumeric characters and periods (.) for section names.

Variables can be set to inherit their value from the parent section by setting them to (inherit). It is also possible to set the configuration to no to disable it. If a variable is not specified it is assumed to be set to (inherit).

u2d
Path to the u2d executable. Default is /usr/bin/u2d.
webserver
This is the URL of the webserver where smokeping is running. Default is http://localhost/smokeping.

*** Targets ***

This section defines the targets to be monitored. Targets can be arranged in a hierarchical structure.

The following variables can be set in this section:

alerts
A comma-separated list of alert names to be applied to this target. If not specified, the alerts from the parent section are inherited.
bitmap
This variable is used for setting the bitmap probe. Please see smokeping_probes_base(3) for more details.
browse
If set to no, this target will not be displayed in the web interface. Default is yes.
children
This variable is used to define child targets. For example: 
children = r1 r2 r3

This means that targets r1, r2, and r3 are children of the current target.

color
This variable is used to set the color of the target in the graphs. If not specified, a default color is used.
data-goodping
This variable is used by the goodping probe. It specifies the data source for the probe.
data-source
This variable is used for setting the data source for the probe. For example, for the Curl probe, this could be the URL to fetch.
data-url
This variable is used for setting the data URL for the probe. For example, for the Curl probe, this could be the URL to fetch. This is used in conjunction with data-source.
description
A description of the target. This is displayed in the web interface.
disklog
If set to yes, the target data will be logged to disk. Default is no.
edgetrigger
This variable inherits its value from the parent section if nothing is specified here.

Default value: edgetrigger = no

group
This variable is used to group targets together in the web interface. For example, group = Europe.
host-ripciones
This variable is used to specify the host. For example: 
host-ripciones = host1 host2

This means that the target is monitored on host1 and host2.

host-ripciones-expr
This variable is used to specify a regular expression to match hosts. For example: 
host-ripciones-expr = host.*

This means that the target is monitored on all hosts that match the regular expression host.*.

host-ripciones-group
This variable is used to specify a group of hosts. For example: 
host-ripciones-group = production

This means that the target is monitored on all hosts in the production group.

interval
This variable is used to set the interval for the probe. For example, interval = 10 means that the probe will be run every 10 seconds. This overrides the global collection-interval.
location
This variable is used to specify the location of the target. For example: 
location = New York

This means that the target is located in New York.

logurl
This variable is used to specify the URL for the log file. This is used in conjunction with disklog.
mailinterval
This variable is used to set the interval for sending email alerts. If not specified, the default interval is used.
mailtemplate
This variable inherits its value from the parent section if nothing is specified here.
max-intargets
This variable is used to set the maximum number of targets in a group. If not specified, there is no limit.
menu
This variable is used to set the menu item for the target in the web interface. For example: 
menu = Datacenters/New York

This means that the target will be displayed under the Datacenters/New York menu item.

noerr
If set to yes, no error messages will be generated for this target. Default is no.
pagelength
The number of targets to display per page in the web interface. Default is 50.
probe
This variable is used to specify the probe to be used for this target. For example: 
probe = FPing

This means that the FPing probe will be used for this target.

probechoice
This variable is used to specify a list of probes to choose from. The first probe in the list that is available on the system will be used.
priority
if multiple alerts 'match' only the one with the highest priority (lowest number) will cause and alert to be sent. Alerts without priority will be sent in any case.
regex
This variable is used to specify a regular expression to match targets. For example: 
regex = .*

This means that all targets will match this configuration.

shortname
This variable is used to specify a short name for the target. This is used in the web interface.
slavename
This variable is used to specify the name of the slave that monitors this target. If not specified, the target is monitored by the master.
sorter
This variable is used to specify the sorter to be used for this target. For example: 
sorter = Median

This means that the Median sorter will be used for this target.

template
This variable is used to specify a template to be used for this target. For example: 
template = default

This means that the default template will be used for this target.

title
This variable is used to specify the title of the target. This is displayed in the web interface.
to
Similar to the "to" parameter on the top-level except that it will only be used IN ADDITION to the value of the toplevel parameter. Same rules apply.

*** Slaves ***

Your smokeping can remote control other smokeping instances running in slave mode on different hosts. Use this section to tell your master smokeping about the slaves you are going to use.

The following variables can be set in this section:

secrets (mandatory setting)
The slave secrets file contains one line per slave with the name of the slave followed by a colon and the secret: 
slave1:secret1
slave2:secret2
...

Note that these secrets combined with a man-in-the-middle attack effectively give shell access to the corresponding slaves (see smokeping_master_slave), so the file should be appropriately protected and the secrets should not be easily crackable.
