SMARTD(8) Herramientas de Monitorización SMART SMARTD(8)

NOMBRE

smartd - Demonio de Monitorización de Discos SMART

SINOPSIS

smartd [opciones]

DESCRIPCIÓN

[Esta página del manual está generada para la versión Linux de smartmontools. No contiene información específica para otras plataformas.]

smartd es un demonio que monitoriza el sistema S.M.A.R.T. (Self-Monitoring, Analysis and Reporting Technology) integrado en la mayoría de los discos duros y unidades de estado sólido ATA/SATA y SCSI/SAS. El propósito de SMART es monitorizar la fiabilidad del disco duro y predecir fallos del mismo, y llevar a cabo diferentes tipos de autocomprobaciones del disco. Esta versión de smartd es compatible con los estándares ACS-3, ACS-2, ATA8-ACS, ATA/ATAPI-7 y anteriores (ver REFERENCIAS más abajo).

smartd intentará habilitar la monitorización SMART en dispositivos ATA (equivalente a smartctl -s on) y sondea estos y los dispositivos SCSI cada 30 minutos (configurable), registrando los errores SMART y los cambios en los Atributos SMART a través de la interfaz SYSLOG. La ubicación predeterminada para estas notificaciones y advertencias de SYSLOG depende del sistema (típicamente /var/log/messages o /var/log/syslog). Para cambiar esta ubicación predeterminada, consulte la opción de línea de comandos '-l' descrita más abajo.

Además de registrar en un archivo, smartd también puede configurarse para enviar advertencias por correo electrónico si se detectan problemas. Dependiendo del tipo de problema, es posible que desee ejecutar autocomprobaciones en el disco, hacer una copia de seguridad del disco, reemplazar el disco o utilizar una utilidad del fabricante para forzar la reubicación de sectores del disco defectuosos o ilegibles. Si se detectan problemas en el disco, consulte la página del manual de smartctl y la página web/FAQ de smartmontools para obtener más información.

Si envía una señal USR1 a smartd, comprobará inmediatamente el estado de los discos y luego volverá a sondear los discos cada 30 minutos. Consulte la opción '-i' más abajo para obtener detalles adicionales.

smartd puede configurarse al inicio utilizando el archivo de configuración /etc/smartd.conf (Windows: EXEDIR/smartd.conf). Si el archivo de configuración se modifica posteriormente, se puede indicar a smartd que vuelva a leer el archivo de configuración enviándole una señal HUP, por ejemplo con el comando:
killall -HUP smartd.

Al inicio, si smartd encuentra un error de sintaxis en el archivo de configuración, imprimirá un mensaje de error y luego saldrá. Sin embargo, si smartd ya está en ejecución, y se le indica con una señal HUP que relea el archivo de configuración, y luego encuentra un error de sintaxis en este archivo, imprimirá un mensaje de error y luego continuará, ignorando el contenido del archivo de configuración (defectuoso), como si la señal HUP nunca hubiera sido recibida.

Cuando smartd se está ejecutando en modo de depuración, la señal INT (normalmente generada desde una terminal con CTRL-C) se trata de la misma manera que una señal HUP: hace que smartd recargue su archivo de configuración. Para salir de smartd use CTRL-\.

[Solo Linux] Si smartd se inicia como un servicio de systemd(1) y se especifica 'Type=Notify' en el archivo del servicio, el gestor de servicios es notificado después de un inicio exitoso. Otros cambios de estado se informan a través de mensajes de estado de notificación de systemd. No se admite la notificación de recargas exitosas (después de la señal HUP). Para detectar este tipo de inicio de proceso, smartd comprueba si la variable de entorno 'NOTIFY_SOCKET' está establecida. Tenga en cuenta que es necesario establecer la opción '-n' ('--nofork') en el comando 'ExecStart=/usr/bin/smartd' si se utiliza 'Type=Notify'.

Al inicio, en ausencia del archivo de configuración /etc/smartd.conf, el demonio smartd primero escanea todos los dispositivos que admiten SMART. El escaneo se realiza de la siguiente manera:

LINUX:
Examine todas las entradas "/dev/hd[a-t]" para dispositivos IDE/ATA y "/dev/sd[a-z]", "/dev/sd[a-z][a-z]" para dispositivos ATA/SATA o SCSI/SAS. Los discos detrás de controladores RAID no están incluidos.

Si la directiva '-d nvme' o ninguna directiva '-d' es especificada, examine todas las entradas "/dev/nvme[0-99]" para dispositivos NVMe.

smartd luego monitoriza todos los posibles errores SMART (correspondientes a la directiva '-a' en el archivo de configuración; ver la página del manual de smartd.conf(5)).

OPCIONES

-A PREFIJO, --attributelog=PREFIJO
Escribe la información de atributos del disco en archivos
'PREFIJO''MODELO-SERIAL[-NSID].PRT.csv'.
PREFIJO especifica el directorio de destino si incluye una barra inclinada final. De lo contrario, su último componente de ruta especifica el prefijo del nombre del archivo. La ruta debe ser absoluta, excepto si el modo de depuración está habilitado. MODELO y SERIAL se construyen a partir de información de identificación del disco, los caracteres inválidos se reemplazan por guiones bajos. NSID es el ID del espacio de nombres NVMe si se aborda un espacio de nombres individual. PRT es uno de 'ata', 'scsi' o 'nvme'.

En cada ciclo de comprobación, los atributos se registran como una línea de tuplas separadas por tabulaciones que consiste en nombres o valores separados por punto y coma. Cada línea va precedida de una cadena de fecha con el formato "aaaa-mm-dd HH:MM:SS" (en hora local). La parte restante es específica del protocolo:
[ATA] Escribe los atributos SMART ATA como "id;valor-normalizado;valor-crudo;".
[SCSI] Escribe los contadores de errores SCSI y la temperatura como "nombre;valor;".
[NVMe: NUEVA CARACTERÍSTICA EXPERIMENTAL SMARTD 7.5] Escribe la información SMART/Salud NVMe como "nombre;valor;".

-B [+]ARCHIVO, --drivedb=[+]ARCHIVO
[Solo ATA] Lee la base de datos de discos de ARCHIVO. La nueva base de datos reemplaza la base de datos incorporada por defecto. Si se especifica '+', entonces las nuevas entradas preceden a las entradas incorporadas. Por favor, consulte la página del manual de smartctl(8) para más detalles.
-c ARCHIVO, --configfile=ARCHIVO
Lee las Directivas de configuración de smartd desde ARCHIVO, en lugar de la ubicación predeterminada /etc/smartd.conf (Windows: EXEDIR/smartd.conf). Si ARCHIVO NO existe, entonces smartd imprimirá un mensaje de error y saldrá con estado distinto de cero. Por lo tanto, '-c /etc/smartd.conf' se puede usar para verificar la existencia del archivo de configuración predeterminado.

Usando '-' para ARCHIVO, la configuración se lee desde la entrada estándar. Esto es útil para comandos como:
echo /dev/sdb -m usuario@casa -M test | smartd -c - -q onecheck
para realizar comprobaciones rápidas y sencillas sin archivo de configuración.

-C, --capabilities[=mail]
[Solo Linux] Utiliza libcap-ng para soltar las capabilities(7) innecesarias del proceso Linux. Las siguientes capabilities se mantienen en los conjuntos efectivos y permisivos: CAP_SYS_ADMIN, CAP_SYS_RAWIO, CAP_MKNOD. Si la opción '-u, --warn_as_user' (ver más abajo) se utiliza con un usuario o grupo no privilegiado, también se mantienen las siguientes capabilities: CAP_SETGID, CAP_SETUID. El conjunto de límites de capabilities se borra. Depende del MTA local si el correo puede ser enviado desde un proceso raíz con todas las capabilities eliminadas. Funciona con el MTA postfix.

Si se especifica '--capabilities=mail', las siguientes capabilities se añaden al conjunto de límites: CAP_SETGID, CAP_SETUID, CAP_CHOWN, CAP_FOWNER, CAP_DAC_OVERRIDE. Esto permite enviar correo con el MTA exim.

-d, --debug
Ejecuta smartd en modo de "depuración". En este modo, muestra información de estado a STDOUT en lugar de registrarla en SYSLOG y no hace fork(2) al segundo plano ni se desconecta de la terminal de control. En este modo, smartd también muestra información más detallada sobre lo que está haciendo que cuando opera en modo "demonio". En este modo, la señal INT (normalmente generada desde una terminal con CTRL-C) hace que smartd recargue su archivo de configuración. Por favor, use CTRL-\ para salir.
-D, --showdirectives
Imprime una lista (en STDOUT) de todas las Directivas posibles que pueden aparecer en el archivo de configuración /etc/smartd.conf, y luego sale. Estas Directivas se describen en la página del manual de smartd.conf(5). Pueden aparecer en el archivo de configuración siguiendo el nombre del dispositivo.

OPTIONS

-h, --help, --usage
Muestra el mensaje de uso en STDOUT y sale.
-i N, --interval=N
Establece el intervalo entre verificaciones del disco a N segundos, donde N es un entero decimal. El valor mínimo permitido es diez y el máximo es el entero positivo más grande que se puede representar en su sistema (a menudo 2^31-1). El valor predeterminado es 1800 segundos. El intervalo podría ser anulado con la directiva '-c i=N', ver la página man de smartd.conf(5).

Tenga en cuenta que el superusuario puede hacer que smartd verifique el estado de los discos en cualquier momento enviándole la señal SIGUSR1, por ejemplo, con el comando:
kill -SIGUSR1 <pid>
donde <pid> es el número de identificación del proceso de smartd. También se puede usar:
killall -USR1 smartd
para el mismo propósito.

-l FACILITY, --logfacility=FACILITY
Utiliza la instalación de syslog FACILITY para registrar los mensajes de smartd. Aquí FACILITY es una de local0, local1, ..., local7, o daemon [predeterminado]. Si no se utiliza esta opción de línea de comandos, por defecto los mensajes de smartd se registran en la instalación daemon.

Si desea que los mensajes de smartd se registren en un lugar distinto de la ubicación predeterminada, incluya (por ejemplo) '-l local3' en su lista de argumentos de inicio. Indique al demonio syslog que registre todos los mensajes de la instalación local3 en (por ejemplo) '/var/log/smartd.log'.

Para obtener información más detallada, consulte las páginas man del demonio syslog local, típicamente syslogd(8), syslog-ng(8) o rsyslogd(8).

-n, --no-fork
No se bifurca en segundo plano; esto es útil cuando se ejecuta desde métodos de inicialización modernos como initng, minit, supervise o systemd.
-p NAME, --pidfile=NAME
Escribe el archivo pidfile NAME que contiene el número de identificación del proceso (PID) de smartd. Para evitar ataques de enlaces simbólicos, asegúrese de que el directorio al que se escribe el pidfile solo sea escribible por root. Sin esta opción, o si se da la opción --debug, no se escribe ningún archivo PID al inicio. Si smartd se termina con una señal enmascarable, el pidfile se elimina.
-q WHEN, --quit=WHEN
Especifica cuándo, si es que alguna vez, smartd debe salir. Los argumentos válidos para esta opción son:

nodev - Sale si no hay dispositivos que monitorear, o si se encuentran errores al inicio en el archivo de configuración. Este es el valor predeterminado.

errors - Sale si no hay dispositivos que monitorear, o si se encuentran errores en el archivo de configuración /etc/smartd.conf al inicio o cada vez que se recarga.

nodevstartup - Sale si no hay dispositivos que monitorear al inicio. Pero continúa ejecutándose si no se encuentran dispositivos cada vez que se recarga el archivo de configuración.

never - Solo sale si ocurre un error fatal (no hay memoria del sistema restante, argumentos de línea de comandos inválidos). En este modo, incluso si no hay dispositivos que monitorear, o si el archivo de configuración /etc/smartd.conf tiene errores, smartd continuará ejecutándose, esperando cargar un archivo de configuración que liste dispositivos válidos.

nodev0 - Igual que 'nodev', excepto que el estado de salida es 0 si no hay dispositivos que monitorear.

nodev0startup - Igual que 'nodevstartup', excepto que el estado de salida es 0 si no hay dispositivos que monitorear.

errors,nodev0 - Igual que 'errors', excepto que el estado de salida es 0 si no hay dispositivos que monitorear.

onecheck - Inicia smartd en modo de depuración, luego registra los dispositivos, luego verifica el estado SMART del dispositivo una vez y luego sale con un estado de salida cero si todos estos pasos se realizaron correctamente.

Esta última opción está destinada a los "distribuidores" que desean crear scripts automatizados para determinar si deben iniciar smartd automáticamente después de instalar smartmontools. Después de iniciar smartd con esta opción de línea de comandos, los scripts de instalación de la distribución deben esperar un tiempo razonable (por ejemplo, diez segundos). Si smartd no ha salido con estado cero en ese momento, el script debe enviarle a smartd una SIGTERM o SIGKILL y asumir que smartd no funcionará correctamente en el host. Por el contrario, si smartd sale con estado cero, entonces es seguro ejecutar smartd en modo demonio normal. Si smartd no puede monitorear ningún dispositivo o encuentra otros problemas, devolverá un estado de salida distinto de cero.

showtests - Inicia smartd en modo de depuración, luego registra los dispositivos, luego escribe una lista de las próximas pruebas programadas en la salida estándar y luego sale con un estado de salida cero si todos estos pasos se realizaron correctamente. El estado SMART del dispositivo no se verifica.

Esta opción está destinada a probar si las directivas '-s REGEX' en smartd.conf tendrán el efecto deseado. La salida enumera los próximos programas de pruebas, limitados a 5 pruebas por tipo y dispositivo. A esto le sigue un resumen de todas las pruebas de cada dispositivo en los próximos 90 días.

-r TYPE, --report=TYPE
Diseñado principalmente para ayudar a los desarrolladores de smartmontools a comprender el comportamiento de smartmontools en hardware no conforme o mal conforme. Esta opción informa detalles de las transacciones de smartd con el dispositivo. La opción se puede usar varias veces. Cuando se usa solo una vez, muestra un registro de las transacciones ioctl() con el dispositivo. Cuando se usa más de una vez, el detalle de estas transacciones ioctl() se informa con mayor detalle. Los argumentos válidos para esta opción son:

ioctl - informa todas las transacciones ioctl().

ataioctl - informa solo las transacciones ioctl() con dispositivos ATA.

scsiioctl - informa solo las transacciones ioctl() con dispositivos SCSI.

nvmeioctl - informa solo las transacciones ioctl() con dispositivos NVMe.

Cualquier argumento puede incluir un entero positivo para especificar el nivel de detalle que se debe informar. El argumento debe ir seguido de una coma y luego el entero sin espacios. Por ejemplo, ataioctl,2 El nivel predeterminado es 1, por lo que '-r ataioctl,1' y '-r ataioctl' son equivalentes.

-s PREFIX, --savestates=PREFIX
Lee/escribe información de estado de smartd desde/hacia archivos
'PREFIX''MODEL-SERIAL[-NSID].PRT.state'.
Para PREFIX, MODEL, SERIAL, NSID y PRT, ver la opción '-A' anterior.

Los archivos de información de estado conservan diversa información a través de reinicios de smartd, por ejemplo: atributos SMART, temperaturas mínima y máxima del disco (directiva '-W'), información sobre el último correo electrónico de advertencia enviado (directiva '-m'), la hora de la próxima verificación de la expresión regular de auto-prueba ('-s' directive), e información sobre las últimas entradas del registro de errores reportadas (directivas '-l [x]error').

Los archivos de información de estado se leen al inicio de smartd. Los archivos siempre se (re)escriben después de leer el archivo de configuración, antes de volver a leer el archivo de configuración (SIGHUP), antes de apagar smartd y después de una verificación forzada por SIGUSR1. Después de un ciclo de verificación normal, un archivo solo se reescribe si ocurrió un cambio importante (que generalmente resulta en una salida SYSLOG).

-w PATH, --warnexec=PATH
Ejecuta el ejecutable PATH en lugar del script predeterminado cuando smartd necesita enviar mensajes de advertencia. PATH debe apuntar a un archivo binario ejecutable o a un script. El script predeterminado es /usr/share/smartmontools/smartd_warning.sh.
-u USER[:GROUP], --warn-as-user=USER[:GROUP]
Ejecuta el script de advertencia como un usuario no privilegiado en lugar de root. USER y GROUP opcional pueden especificarse como IDs numéricos o nombres. Si no se especifica GROUP, se utiliza el grupo predeterminado de USER.

Si ocurre una advertencia, se crea un proceso hijo con fork(2). Este proceso cierra todos los descriptores de archivo heredados, conecta stdio a /dev/null, cambia los IDs de usuario y grupo, elimina cualquier ID de grupo suplementario y luego llama a la función popen(3) de la biblioteca estándar.

Si se especifica '0:0', el usuario y el grupo no se cambian, pero las acciones restantes siguen aplicándose.

Si se especifica '-', se llama directamente a popen(3). Este es el valor predeterminado.

-V, --version, --license, --copyright
Muestra la versión, derechos de autor, licencia, página de inicio e información de revisión SVN de su copia de smartd en STDOUT y luego sale.

EJEMPLOS

smartd
Ejecuta el demonio en modo bifurcado. Esta es la forma normal de ejecutar smartd. Las entradas se registran en SYSLOG.

smartd -d -i 30
Ejecuta en modo de primer plano (depuración), verificando el estado del disco cada 30 segundos.

smartd -q onecheck
Registra los dispositivos y verifica el estado de los dispositivos una sola vez. El estado de salida (la variable $? del shell) será cero si todo fue bien, y distinto de cero si no se detectaron dispositivos o se encontró algún otro problema.

CONFIGURACIÓN

La sintaxis del archivo smartd.conf(5) se discute por separado.

NOTAS

smartd realizará entradas de registro en el nivel de registro LOG_INFO si los valores normalizados de los atributos SMART han cambiado, tal como se informa utilizando las directivas '-t', '-p', o '-u'. Por ejemplo:
'Device: /dev/sda, SMART Attribute: 194 Temperature_Celsius changed from 94 to 93'
Tenga en cuenta que en este mensaje, el valor dado es el valor 'Normalizado' y no el valor 'Crudo' del Atributo (la temperatura del disco en este caso es de aproximadamente 22 Celsius). Las directivas '-R' y '-r' modifican este comportamiento, de modo que la información se imprime también con los valores Crudos, por ejemplo:
'Device: /dev/sda, SMART Attribute: 194 Temperature_Celsius changed from 94 [Raw 22] to 93 [Raw 23]'
Aquí th

VALORES_BRUTOS

Los valores Raw son las temperaturas reales del disco en Celsius. La forma en que se imprimen los valores Raw, y los nombres bajo los cuales se informan los Attributes, se rigen por las diversas Directivas '-v Num,Description' descritas anteriormente.

Por favor, consulte la página del manual de smartctl para obtener más explicaciones sobre las diferencias entre los valores Normalizados y los valores Raw de los atributos.

smartd creará entradas de registro en el nivel de registro LOG_CRIT si un atributo SMART ha fallado, por ejemplo:

Device: /dev/sdc, Failed SMART Attribute: 5 Reallocated_Sector_Ct

Este nivel de registro se utiliza para las notificaciones habilitadas por las Directivas '-H', '-f', '-l selftest' y '-l error'. Las entradas que informan sobre fallos de los atributos SMART de Prefallo no deben ser ignoradas: significan que el disco está fallando. Utilice la utilidad smartctl para investigar.

ZONA HORARIA DE LA MARCA DE TIEMPO DEL REGISTRO

Cuando smartd crea entradas de registro, estas llevan una marca de tiempo. Las marcas de tiempo están en la zona horaria local del ordenador, que generalmente se establece utilizando la variable de entorno 'TZ' o un archivo de zona horaria como /etc/localtime. Es posible que desee cambiar la zona horaria mientras smartd se está ejecutando (por ejemplo, si lleva un portátil a una nueva zona horaria y no lo reinicia). Debido a un error en la función tzset(3) de muchas bibliotecas C estándar de Unix, las marcas de tiempo de zona horaria de smartd podrían no cambiar. Para algunos sistemas, smartd evitará este problema *si* la zona horaria se establece usando /etc/localtime. La solución alternativa *falla* si la zona horaria se establece usando la variable 'TZ' (o un archivo al que apunta).

ESTADO DE SALIDA

El estado de salida (valor de retorno) de smartd puede tener los siguientes valores:

0:
Inicio del demonio exitoso, o smartd fue terminado por una SIGTERM (o en modo de depuración, una SIGQUIT).
1:
La línea de comandos no se analizó.
2:
Hubo un error de sintaxis en el archivo de configuración.
3:
Fallo al crear el demonio.
4:
No se pudo crear el archivo PID.
5:
El archivo de configuración no existe (solo se devuelve junto con la opción '-c').
6:
El archivo de configuración existe, pero no se puede leer.
8:
smartd se quedó sin memoria durante el inicio.
10:
Se encontró una inconsistencia en las estructuras de datos internas de smartd. Esto nunca debería suceder. Debe deberse a un error de código o compilador. *Por favor*, informe de tales fallos a los desarrolladores de smartmontools, vea REPORTAR ERRORES a continuación.
16:
Un dispositivo listado explícitamente en /etc/smartd.conf no puede ser monitoreado.
17:
smartd no encontró ningún dispositivo para monitorear. Esto podría cambiarse a 0 (éxito) con una de las opciones '-q *nodev0*', ver arriba.
254:
Cuando está en modo demonio, smartd recibió una SIGINT o SIGQUIT. (Tenga en cuenta que en modo de depuración, SIGINT tiene el mismo efecto que SIGHUP, y hace que smartd recargue su archivo de configuración. SIGQUIT tiene el mismo efecto que SIGTERM y hace que smartd salga con un estado de salida cero).
132 y superior
smartd fue terminado por una señal que no se enumera explícitamente anteriormente. El estado de salida es entonces 128 más el número de señal. Por ejemplo, si smartd es terminado por SIGKILL (señal 9) entonces el estado de salida es 137.
