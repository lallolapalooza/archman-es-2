SMBPASSWD(8) Herramientas de administración del sistema SMBPASSWD(8)

NOMBRE

smbpasswd - cambiar la contraseña SMB de un usuario

SINOPSIS

smbpasswd [-a] [-c <archivo de configuración>] [-x] [-d] [-e] [-D <nivel de depuración>] [-n] [-r <máquina remota>] [-R <orden de resolución de nombres>] [-m] [-U nombredeusuario[%contraseña]] [-h] [-s] [-w contraseña] [-W] [-i] [-L] [nombredeusuario]

DESCRIPCIÓN

Esta herramienta forma parte del conjunto de utilidades samba(7).

El programa smbpasswd tiene varias funciones diferentes, dependiendo de si es ejecutado por el usuario root o no. Cuando se ejecuta como un usuario normal, permite al usuario cambiar la contraseña utilizada para sus sesiones SMB en cualquier máquina que almacene contraseñas SMB.

Por defecto (cuando se ejecuta sin argumentos) intentará cambiar la contraseña SMB del usuario actual en la máquina local. Esto es similar a cómo funciona el programa passwd(1). Sin embargo, smbpasswd difiere de cómo funciona el programa passwd en que no es setuid root, sino que opera en modo cliente-servidor y se comunica con un smbd(8) que se ejecuta localmente. Como consecuencia, para que esto tenga éxito, el demonio smbd debe estar ejecutándose en la máquina local. En una máquina UNIX, las contraseñas SMB cifradas se almacenan normalmente en el backend de la base de datos de contraseñas predeterminado.

Cuando se ejecuta por un usuario ordinario sin opciones, smbpasswd le pedirá su antigua contraseña SMB y luego le pedirá su nueva contraseña dos veces, para asegurar que la nueva contraseña se escribió correctamente. No se mostrarán contraseñas en la pantalla mientras se escriben. Si tiene una contraseña SMB en blanco (especificada por la cadena "NO PASSWORD" en el archivo smbpasswd) simplemente presione la tecla <Enter> cuando se le solicite su antigua contraseña.

smbpasswd también puede ser utilizado por un usuario normal para cambiar su contraseña SMB en máquinas remotas, como los Controladores de Dominio Principales de Windows NT. Consulte las opciones (-r) y -U más abajo.

Cuando lo ejecuta root, smbpasswd permite añadir y eliminar usuarios en el archivo smbpasswd, así como realizar cambios en los atributos del usuario en este archivo. Cuando lo ejecuta root, smbpasswd accede directamente al archivo smbpasswd local, permitiendo así realizar cambios incluso si smbd no se está ejecutando.

OPCIONES

-a

Esta opción especifica que el nombre de usuario siguiente debe añadirse al archivo smbpasswd local, con la nueva contraseña que se introduzca (escriba <Enter> para la contraseña antigua). Esta opción se ignora si el nombre de usuario siguiente ya existe en el archivo smbpasswd y se trata como un comando normal de cambio de contraseña. Tenga en cuenta que los backends de base de datos de contraseñas predeterminados requieren que el usuario ya exista en el archivo de contraseñas del sistema (normalmente /etc/passwd), de lo contrario, la solicitud para añadir el usuario fallará.

Esta opción solo está disponible cuando se ejecuta smbpasswd como root.

-c

Esta opción se puede utilizar para especificar la ruta y el nombre del archivo de configuración /etc/samba/smb.conf cuando sea importante utilizar un archivo y/o ubicación distintos de los predeterminados.

-x

Esta opción especifica que el nombre de usuario siguiente debe eliminarse del archivo smbpasswd local.

Esta opción solo está disponible cuando se ejecuta smbpasswd como root.

-d

Esta opción especifica que el nombre de usuario siguiente debe ser deshabilitado en el archivo smbpasswd local. Esto se hace escribiendo un indicador 'D' en el espacio de control de la cuenta en el archivo smbpasswd. Una vez hecho esto, todos los intentos de autenticación a través de SMB utilizando este nombre de usuario fallarán.

Si el archivo smbpasswd está en formato 'antiguo' (formato anterior a Samba 2.0), no hay espacio en la entrada de contraseña del usuario para escribir esta información y el comando FALLARÁ. Consulte smbpasswd(5) para obtener detalles sobre los formatos de archivo de contraseñas 'antiguo' y nuevo.

Esta opción solo está disponible cuando se ejecuta smbpasswd como root.

-e

Esta opción especifica que el nombre de usuario siguiente debe ser habilitado en el archivo smbpasswd local, si la cuenta fue previamente deshabilitada. Si la cuenta no estaba deshabilitada, esta opción no tiene ningún efecto. Una vez que la cuenta está habilitada, el usuario podrá autenticarse a través de SMB una vez más.

Si el archivo smbpasswd está en formato 'antiguo', smbpasswd FALLARÁ al habilitar la cuenta. Consulte smbpasswd(5) para obtener detalles sobre los formatos de archivo de contraseñas 'antiguo' y nuevo.

Esta opción solo está disponible cuando se ejecuta smbpasswd como root.

-D nivel de depuración

nivel de depuración es un número entero de 0 a 10. El valor predeterminado si este parámetro no se especifica es cero.

Cuanto mayor sea este valor, más detalles se registrarán en los archivos de registro sobre las actividades de smbpasswd. En el nivel 0, solo se registrarán errores críticos y advertencias graves.

Los niveles superiores a 1 generarán una cantidad considerable de datos de registro y solo deben usarse al investigar un problema. Los niveles superiores a 3 están diseñados solo para uso de desarrolladores y generan ENORMES cantidades de datos de registro, la mayoría de los cuales son extremadamente crípticos.

-n

Esta opción especifica que la contraseña del nombre de usuario siguiente debe establecerse a nulo (es decir, una contraseña en blanco) en el archivo smbpasswd local. Esto se hace escribiendo la cadena "NO PASSWORD" como la primera parte de la primera contraseña almacenada en el archivo smbpasswd.

Tenga en cuenta que para permitir que los usuarios inicien sesión en un servidor Samba una vez que la contraseña se haya establecido en "NO PASSWORD" en el archivo smbpasswd, el administrador debe establecer el siguiente parámetro en la sección [global] del archivo smb.conf:

contraseñas nulas = sí

Esta opción solo está disponible cuando se ejecuta smbpasswd como root.

-r nombre de máquina remota

Esta opción permite a un usuario especificar en qué máquina desea cambiar su contraseña. Sin este parámetro, smbpasswd se establece por defecto en el host local. El nombre de máquina remota es el nombre NetBIOS del servidor SMB/CIFS al que contactar para intentar el cambio de contraseña. Este nombre se resuelve en una dirección IP utilizando el mecanismo de resolución de nombres estándar en todos los programas del conjunto Samba. Consulte el parámetro -R orden de resolución de nombres para obtener detalles sobre cómo cambiar este mecanismo de resolución.

El nombre de usuario cuya contraseña se cambia es el del usuario actualmente conectado en UNIX. Consulte el parámetro -U nombredeusuario para obtener detalles sobre cómo cambiar la contraseña para un nombre de usuario diferente.

Tenga en cuenta que si está cambiando una contraseña de Dominio de Windows NT, la máquina remota especificada debe ser el Controlador de Dominio Principal para el dominio (los Controladores de Dominio de Respaldo solo tienen una copia de solo lectura de la base de datos de cuentas de usuario y no permitirán el cambio de contraseña).

Tenga en cuenta que Windows 95/98 no tiene una base de datos de contraseñas real, por lo que no es posible cambiar contraseñas especificando una máquina Win95/98 como destino de máquina remota.

-R orden de resolución de nombres

Esta opción permite al usuario de smbpasswd determinar qué servicios de resolución de nombres utilizar al buscar el nombre NetBIOS del host al que se está conectando.

Las opciones son: "lmhosts", "host", "wins" y "bcast". Hacen que los nombres se resuelvan de la siguiente manera:

•lmhosts: Busca una dirección IP en el archivo lmhosts de Samba. Si la línea en lmhosts no tiene un tipo de nombre adjunto al nombre NetBIOS (consulte lmhosts(5) para obtener detalles), entonces cualquier tipo de nombre coincide para la búsqueda.
•host: Realiza una resolución estándar de nombre de host a dirección IP, utilizando las búsquedas de DNS, NIS o /etc/hosts del sistema. Este método de resolución de nombres depende del sistema operativo, por ejemplo, en IRIX o Solaris esto puede controlarse mediante el archivo /etc/nsswitch.conf). Tenga en cuenta que este método solo se utiliza si el tipo de nombre NetBIOS que se consulta es el tipo de nombre 0x20 (servidor), de lo contrario se ignora.
•wins: Consulta un nombre con la dirección IP listada en el parámetro servidor wins. Si no se ha especificado ningún servidor WINS, este método se ignorará.
•bcast: Realiza una transmisión en cada una de las interfaces locales conocidas listadas en el parámetro interfaces. Este es el método menos fiable de resolución de nombres, ya que depende de que el host de destino esté en una subred conectada localmente.

OPTIONS

These are the options that can be given to smbpasswd. Resolution methods will be attempted in this order.

-m

This option tells smbpasswd that the account being changed is a MACHINE account. Currently this is used when Samba is being used as an NT Primary Domain Controller.

This option is only available when running smbpasswd as root.

-U username

This option may only be used in conjunction with the -r option. When changing a password on a remote machine it allows the user to specify the user name on that machine whose password will be changed. It is present to allow users who have different user names on different systems to change these passwords.

-h

This option prints the help string for smbpasswd, selecting the correct one for running as root or as an ordinary user.

-s

This option causes smbpasswd to be silent (i.e. not issue prompts) and to read its old and new passwords from standard input, rather than from /dev/tty (like the passwd(1) program does). This option is to aid people writing scripts to drive smbpasswd

-w password

This parameter is only available if Samba has been compiled with LDAP support. The -w switch is used to specify the password to be used with the ldap admin dn. Note that the password is stored in the secrets.tdb and is keyed off of the admin's DN. This means that if the value of ldap admin dn ever changes, the password will need to be manually updated as well.

-W

NOTE: This option is same as "-w" except that the password should be entered using stdin.

This parameter is only available if Samba has been compiled with LDAP support. The -W switch is used to specify the password to be used with the ldap admin dn. Note that the password is stored in the secrets.tdb and is keyed off of the admin's DN. This means that if the value of ldap admin dn ever changes, the password will need to be manually updated as well.

-i

This option tells smbpasswd that the account being changed is an interdomain trust account. Currently this is used when Samba is being used as an NT Primary Domain Controller. The account contains the info about another trusted domain.

This option is only available when running smbpasswd as root.

-L

Run in local mode.

username

This specifies the username for all of the root only options to operate on. Only root can specify this parameter as only root has the permission needed to modify attributes directly in the local smbpasswd file.

NOTES

Since smbpasswd works in client-server mode communicating with a local smbd for a non-root user then the smbd daemon must be running for this to work. A common problem is to add a restriction to the hosts that may access the smbd running on the local machine by specifying either allow hosts or deny hosts entry in the smb.conf(5) file and neglecting to allow "localhost" access to the smbd.

In addition, the smbpasswd command is only useful if Samba has been set up to use encrypted passwords.
