SMTP(8) Manual del Administrador del Sistema SMTP(8)

NOMBRE

smtp, lmtp - Cliente Postfix SMTP+LMTP

SINOPSIS

smtp [opciones genéricas del demonio Postfix] [flags=DORX]
lmtp [opciones genéricas del demonio Postfix] [flags=DORX]

DESCRIPCIÓN


El cliente Postfix SMTP+LMTP implementa los protocolos de entrega de correo SMTP y LMTP. Procesa solicitudes de entrega de mensajes del gestor de colas. Cada solicitud especifica un archivo de cola, una dirección de remitente, un dominio o host al que entregar, e información del destinatario. Este programa espera ser ejecutado por el gestor de procesos master(8). El nombre del proceso, smtp o lmtp, controla el protocolo y los nombres de los parámetros de configuración que se utilizarán.

El cliente SMTP+LMTP actualiza el archivo de cola y marca a los destinatarios como finalizados, o informa al gestor de colas que la entrega debe intentarse de nuevo más tarde. Los informes de estado de entrega se envían al demonio bounce(8), defer(8) o trace(8), según corresponda.

La estrategia de búsqueda de servidores es diferente para SMTP y LMTP, como se describe en las secciones "BÚSQUEDA DE SERVIDOR SMTP" y "BÚSQUEDA DE SERVIDOR LMTP".

Después de una transacción de correo exitosa, una conexión puede ser guardada en el servidor de caché de conexiones scache(8), para que pueda ser utilizada por cualquier cliente SMTP+LMTP para una transacción subsiguiente.

Por defecto, la caché de conexiones está habilitada temporalmente para destinos que tienen un alto volumen de correo en la cola activa. La caché de conexiones se puede habilitar permanentemente para destinos específicos.

BÚSQUEDA DE SERVIDOR SMTP

El cliente SMTP de Postfix soporta múltiples destinos separados por coma o espacio en blanco (Postfix 3.5 y posteriores). Cada destino se prueba en el orden especificado.

Los destinos SMTP tienen el siguiente formato:

nombre-dominio
nombre-dominio:servicio
Busca los intercambiadores de correo para el dominio especificado y se conecta al servicio especificado (por defecto: smtp). Opcionalmente, los intercambiadores de correo se pueden buscar con consultas SRV en lugar de MX; esto requiere que se proporcione servicio en formato simbólico.
[nombre-host]
[nombre-host]:servicio
Busca las direcciones para el host especificado y se conecta al servicio especificado (por defecto: smtp).
[direccion]
[direccion]:servicio
Se conecta al host en la dirección especificada y al servicio especificado (por defecto: smtp). Una dirección IPv6 debe formatearse como [ipv6:direccion].

BÚSQUEDA DE SERVIDOR LMTP

El cliente LMTP de Postfix soporta múltiples destinos separados por coma o espacio en blanco (Postfix 3.5 y posteriores). Cada destino se prueba en el orden especificado.

Los destinos LMTP tienen el siguiente formato:

unix:ruta-archivo
Se conecta al servidor local de dominio UNIX enlazado a la ruta-archivo especificada. Si el proceso se ejecuta en modo chroot, una ruta de archivo absoluta se interpreta en relación con el directorio de cola de Postfix.
inet:nombre-dominio
inet:nombre-dominio:servicio
Busca los servidores LMTP para el dominio y servicio especificados (por defecto: lmtp). Esta forma se soporta cuando las búsquedas SRV están habilitadas y requiere que servicio esté en formato simbólico.
inet:nombre-host
inet:nombre-host:servicio
Busca las direcciones para el host especificado y se conecta al servicio especificado (por defecto: lmtp). Cuando las búsquedas SRV están habilitadas, usa la forma [nombre-host] para forzar búsquedas de direcciones.
inet:[direccion]
inet:[direccion]:servicio
Se conecta al host y servicio local o remoto especificado (por defecto: lmtp). Una dirección IPv6 debe formatearse como [ipv6:direccion].

ENTREGA DE UN SOLO DESTINATARIO

Por defecto, el cliente Postfix SMTP+LMTP entrega el correo a múltiples destinatarios por solicitud de entrega. Esto es indeseable cuando se antepone una cabecera de mensaje Delivered-to: o X-Original-To:. Para evitar que Postfix envíe múltiples destinatarios por solicitud de entrega, especifica

    transporte_destination_recipient_limit = 1

en el archivo main.cf de Postfix, donde transporte es el nombre en la primera columna de la entrada de master.cf de Postfix para este servicio de entrega de correo.

SINTAXIS DE ATRIBUTO COMANDO

flags=DORX (opcional)
Banderas opcionales de procesamiento de mensajes.
D
Antepone una cabecera de mensaje "Delivered-To: destinatario" con la dirección del destinatario del sobre. Nota: para que esto funcione, el transporte_destination_recipient_limit debe ser 1 (ver ENTREGA DE UN SOLO DESTINATARIO arriba para más detalles).

La bandera D también fuerza la detección de bucles: si un mensaje ya contiene una cabecera Delivered-To: con la misma dirección de destinatario, entonces el mensaje se devuelve como indistribuible. La comparación de direcciones no distingue entre mayúsculas y minúsculas.

Esta característica está disponible a partir de Postfix 3.5.

O
Antepone una cabecera de mensaje "X-Original-To: destinatario" con la dirección del destinatario tal como se le proporcionó a Postfix. Nota: para que esto funcione, el transporte_destination_recipient_limit debe ser 1 (ver ENTREGA DE UN SOLO DESTINATARIO arriba para más detalles).

Esta característica está disponible a partir de Postfix 3.5.

R
Antepone una cabecera de mensaje "Return-Path: <remitente>" con la dirección del remitente del sobre.

Esta característica está disponible a partir de Postfix 3.5.

X
Indica que la entrega es final. Esta bandera afecta al estado informado en mensajes DSN (notificación de estado de entrega) de "éxito", y lo cambia de "retransmitido" a "entregado".

Esta característica está disponible a partir de Postfix 3.5.

SEGURIDAD

El cliente SMTP+LMTP es moderadamente sensible a la seguridad. Habla con servidores SMTP o LMTP y con servidores DNS en la red. El cliente SMTP+LMTP puede ejecutarse en modo chroot con privilegios bajos fijos.

BUGS


La reutilización de conexiones SMTP y LMTP para TLS (sin cerrar la conexión SMTP o LMTP) no está soportada antes de Postfix 3.4.

La reutilización de conexiones SMTP y LMTP asume que las credenciales SASL son válidas para todos los destinos que mapean a la misma dirección IP y puerto TCP.

PARÁMETROS DE CONFIGURACIÓN

Las versiones de Postfix 2.3 y posteriores implementan el cliente SMTP y LMTP con el mismo programa, y eligen el protocolo y los parámetros de configuración basándose en el nombre del proceso, smtp o lmtp.

La mayoría de los parámetros de configuración smtp_xxx tienen un parámetro "espejo" lmtp_xxx para la característica LMTP equivalente. Este documento describe solo aquellos parámetros relacionados con LMTP que no son simplemente parámetros "espejo".

Los cambios en main.cf se detectan automáticamente, ya que los procesos de smtp(8) se ejecutan solo durante un tiempo limitado. Utilice el comando "postfix reload" para acelerar un cambio.

El texto a continuación proporciona solo un resumen de parámetros. Consulte postconf(5) para obtener más detalles, incluidos ejemplos.

El programa SMTP cliente de Postfix

NOMBRE

smtp — El programa SMTP cliente de Postfix

SINOPSIS

smtp [aplicación] [dirección ...]

DESCRIPCIÓN

El programa smtp es la implementación cliente SMTP del MTA (Mail Transport Agent) de Postfix. Se utiliza para enviar correo a otros servidores de correo vía SMTP, o a través de un proxy de relé SMTP.

Normalmente, smtp no se invoca directamente. Lo invoca el proceso principal de Postfix (master.cf) para entregar correo a servidores de destino remotos.

La aplicación y las direcciones pueden especificarse para enviar correo de forma interactiva, o para alimentar la salida de otro programa al cliente SMTP.

Los parámetros de configuración de Postfix que controlan el comportamiento del cliente SMTP se encuentran en el archivo main.cf.

BUSQUEDA DE SERVIDOR SMTP

El cliente SMTP busca un servidor de destino utilizando el nombre de host del destinatario para la consulta de registros DNS MX (Mail eXchanger). Si no se encuentra ningún registro MX, se utilizará el nombre de host para una consulta de registro A (dirección).

La búsqueda de DNS puede ser controlada por los parámetros:

smtp_dns_resolver_options
Opciones de resolución DNS. Ver smtp.conf(5).
smtp_dns_lookup_domain
Si se buscan registros MX o A para el dominio de destino.
smtp_dns_lookup_helo
Si se buscan registros MX o A para el nombre de host HELO/EHLO del servidor remoto.
smtp_dns_map_defer
Mapea nombres de dominio a un resultado de aplazamiento.
smtp_dns_map_reject
Mapea nombres de dominio a un resultado de rechazo.

BUSQUEDA DE SERVIDOR LMTP

El cliente LMTP busca un servidor de destino utilizando el nombre de host del destinatario para la consulta de registros DNS MX (Mail eXchanger). Si no se encuentra ningún registro MX, se utilizará el nombre de host para una consulta de registro A (dirección).

La búsqueda de DNS puede ser controlada por los parámetros:

lmtp_dns_resolver_options
Opciones de resolución DNS. Ver smtp.conf(5).
lmtp_dns_lookup_domain
Si se buscan registros MX o A para el dominio de destino.
lmtp_dns_lookup_helo
Si se buscan registros MX o A para el nombre de host HELO/EHLO del servidor remoto.
lmtp_dns_map_defer
Mapea nombres de dominio a un resultado de aplazamiento.
lmtp_dns_map_reject
Mapea nombres de dominio a un resultado de rechazo.

ENTREGA DE UN SOLO DESTINATARIO

El cliente SMTP puede entregar un mensaje a cada destinatario individualmente, en lugar de enviarlo una vez a todos los destinatarios. Esto puede ser útil para realizar una entrega más granular o para eludir ciertos filtros de spam.

El control sobre este comportamiento se encuentra en el archivo main.cf:

smtp_delivery_mode
Establece el modo de entrega. Los valores posibles son multiple (predeterminado), single o recipient.

SINTAXIS DEL ATRIBUTO DE COMANDO

La sintaxis general de los atributos de comando es:

nombre = valor
Asigna un valor a un atributo. Si el valor contiene espacios, debe estar entre comillas.
nombre + = valor
Añade un valor a una lista existente de atributos. Esto es útil para añadir direcciones IP a una lista de mynetworks, por ejemplo.
nombre - = valor
Elimina un valor de una lista existente de atributos.

SEGURIDAD

El cliente SMTP puede configurarse para utilizar SASL (Simple Authentication and Security Layer) para la autenticación con servidores remotos. Esto está controlado por los siguientes parámetros en main.cf:

smtp_sasl_auth_enable
Habilita o deshabilita la autenticación SASL.
smtp_sasl_password_maps
Especifica la tabla de contraseñas SASL.
smtp_sasl_security_options
Define las opciones de seguridad SASL.

Además, el cliente SMTP puede utilizar TLS/SSL para cifrar la comunicación con servidores remotos. Esto está controlado por los siguientes parámetros en main.cf:

smtp_use_tls
Habilita o deshabilita el uso de TLS.
smtp_tls_security_level
Establece el nivel de seguridad TLS.
smtp_tls_wrappermode
Indica si se debe utilizar el modo wrapper TLS (SSL).
smtp_tls_CAfile
Especifica el archivo que contiene los certificados de las autoridades de certificación (CA).
smtp_tls_CApath
Especifica el directorio que contiene los certificados de las autoridades de certificación (CA).
smtp_tls_cert_file
Especifica el archivo del certificado del cliente.
smtp_tls_key_file
Especifica el archivo de la clave privada del cliente.

4xx
Errores temporales que requieren un reintento posterior.
5xx
Errores permanentes que requieren una acción correctiva.
