SMBCQUOTAS(1) Comandos de usuario SMBCQUOTAS(1)

NOMBRE

smbcquotas - Establecer u obtener las CUOTAS de recursos compartidos NTFS 5

SINOPSIS

smbcquotas {//servidor/recurso} [-u|--cuota-usuario=USUARIO] [-L|--listar] [-F|--fs] [-S|--establecer=CADENACOMANDO] [-n|--numérico] [-v|--verboso] [-t|--probar-args] [-?|--ayuda] [--uso] [-d|--nivel-debug=NIVEL] [--debug-stdout] [--configfile=ARCHIVO] [--option=nombre=valor] [-l|--log-basename=ARCHIVO] [--leak-report] [--leak-report-full] [-R|--name-resolve=ORDEN] [-O|--socket-options=OPCIONES] [-m|--max-protocol=PROTOCOLO] [-n|--netbiosname=NOMBRE] [--netbios-scope=ALCANCE] [-W|--workgroup=GRUPO] [--realm=REINO] [-U|--user=[DOMINIO/]USUARIO[%CONTRASEÑA]] [-N|--no-pass] [--password=CADENA] [--pw-nt-hash] [-A|--authentication-file=ARCHIVO] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=deseado|requerido|off] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=sign|encrypt|off] [-V|--version]

DESCRIPCIÓN

Esta herramienta forma parte del conjunto de samba(7).

El programa smbcquotas manipula las cuotas NT en recursos compartidos de archivos SMB.

OPCIONES

Las siguientes opciones están disponibles para el programa smbcquotas.

-u|--cuota-usuario usuario

Especifica el usuario cuyas cuotas se obtienen o establecen. Por defecto, se usará el nombre de usuario del usuario actual.

-L|--listar

Lista todos los registros de cuotas del recurso compartido.

-F|--fs

Muestra el estado de la cuota del recurso compartido y los límites predeterminados.

-S|--establecer CADENACOMANDO

Este comando establece/modifica las cuotas para un usuario o en el recurso compartido, dependiendo del parámetro CADENACOMANDO que se describe más adelante.

-n|--numérico

Esta opción muestra toda la información de CUOTA en formato numérico. El valor predeterminado es convertir los SID a nombres y los límites de CUOTA a un formato de cadena legible.

-t|--probar-args

No haga nada en realidad, solo valide la corrección de los argumentos.

-v|--verboso

Sea verboso.

-?|--ayuda

Imprima un resumen de las opciones de la línea de comandos.

--uso

Muestre un breve mensaje de uso.

-d|--nivel-debug=nivel

nivel es un entero de 0 a 10. El valor predeterminado si este parámetro no se especifica es 1 para las aplicaciones cliente.

Cuanto mayor sea este valor, más detalles se registrarán en los archivos de registro sobre las actividades del servidor. En el nivel 0, solo se registrarán errores críticos y advertencias graves. El nivel 1 es un nivel razonable para el uso diario: genera una pequeña cantidad de información sobre las operaciones realizadas.

Los niveles superiores a 1 generarán una cantidad considerable de datos de registro y solo deben usarse al investigar un problema. Los niveles superiores a 3 están diseñados solo para que los utilicen los desarrolladores y generan ENORMES cantidades de datos de registro, la mayor parte de los cuales son extremadamente crípticos.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro de nivel de registro en el archivo /etc/samba/smb.conf.

--debug-stdout

Esto redirigirá la salida de depuración a STDOUT. Por defecto, todos los clientes registran en STDERR.

--configfile=<archivo de configuración>

El archivo especificado contiene los detalles de configuración requeridos por el cliente. La información en este archivo puede ser general para cliente y servidor o solo proporcionar opciones específicas del cliente como client smb encrypt. Consulte /etc/samba/smb.conf para obtener más información. El nombre del archivo de configuración predeterminado se determina en el momento de la compilación.

--option=<nombre>=<valor>

Establezca la opción smb.conf(5) "<nombre>" con el valor "<valor>" desde la línea de comandos. Esto anula los valores predeterminados compilados y las opciones leídas del archivo de configuración. Si un nombre o un valor incluyen un espacio, envuelva todo --option=nombre=valor entre comillas.

-l|--log-basename=directorio

Nombre base del directorio para los archivos de registro/depuración. Se añadirá la extensión ".progname" (por ejemplo, log.smbclient, log.smbd, etc.). El cliente nunca elimina el archivo de registro.

--leak-report

Habilita la generación de informes de fugas de talloc al salir.

--leak-report-full

Habilita la generación de informes completos de fugas de talloc al salir.

-V|--version

Imprime el número de versión del programa.

-R|--name-resolve=ORDEN

Esta opción se utiliza para determinar qué servicios de nombres y en qué orden resolver nombres de host a direcciones IP. La opción toma una cadena separada por espacios de diferentes opciones de resolución de nombres. Lo mejor es encerrar todo --name-resolve=ORDEN entre comillas.

Las opciones son: "lmhosts", "host", "wins" y "bcast". Provocan que los nombres se resuelvan de la siguiente manera:

•lmhosts: Busca una dirección IP en el archivo lmhosts de Samba. Si la línea en lmhosts no tiene un tipo de nombre adjunto al nombre NetBIOS (ver lmhosts(5) para más detalles) entonces cualquier tipo de nombre coincide para la búsqueda.
•host: Realiza una resolución estándar de nombre de host a dirección IP, utilizando las búsquedas del sistema /etc/hosts, NIS o DNS. Este método de resolución de nombres depende del sistema operativo; por ejemplo, en IRIX o Solaris, esto puede ser controlado por el archivo /etc/nsswitch.conf). Tenga en cuenta que este método solo se utiliza si el tipo de nombre NetBIOS que se consulta es el tipo de nombre 0x20 (servidor), de lo contrario se ignora.
•wins: Consulta un nombre con la dirección IP listada en el parámetro wins server. Si no se ha especificado ningún servidor WINS, este método se ignorará.
•bcast: Realiza una transmisión en cada una de las interfaces locales conocidas listadas en el parámetro interfaces. Este es el menos fiable de los métodos de resolución de nombres, ya que depende de que el host de destino esté en una subred conectada localmente.
Si este parámetro no está configurado, se utilizará el orden de resolución de nombres definido en el parámetro (name resolve order) del archivo /etc/samba/smb.conf.

El orden predeterminado es lmhosts, host, wins, bcast. Sin este parámetro o cualquier entrada en el parámetro name resolve order del archivo /etc/samba/smb.conf, los métodos de resolución de nombres se intentarán en este orden.

-O|--socket-options=OPCIONES

Opciones de socket TCP que se establecerán en el socket del cliente. Consulte el parámetro de opciones de socket en la página del manual de /etc/samba/smb.conf para obtener la lista de opciones válidas.

-m|--max-protocol=PROTOCOLO

El valor del parámetro (una cadena) es el nivel de protocolo más alto que será compatible con el cliente.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro client max protocol en el archivo /etc/samba/smb.conf.

-n|--netbiosname=NOMBRE

Esta opción permite anular el nombre NetBIOS que Samba utiliza para sí mismo. Esto es idéntico a establecer el parámetro netbios name en el archivo /etc/samba/smb.conf. Sin embargo, una configuración en línea de comandos tendrá prioridad sobre las configuraciones en /etc/samba/smb.conf.

--netbios-scope=ALCANCE

Esto especifica un alcance NetBIOS que nmblookup utilizará para comunicarse al generar nombres NetBIOS. Para obtener detalles sobre el uso de alcances NetBIOS, consulte rfc1001.txt y rfc1002.txt. Los alcances NetBIOS se utilizan *muy* raramente; solo configure este parámetro si usted es el administrador del sistema a cargo de todos los sistemas NetBIOS con los que se comunica.

-W|--workgroup=GRUPO

Establezca el dominio SMB del nombre de usuario. Esto anula el dominio predeterminado, que es el dominio definido en smb.conf. Si el dominio especificado es el mismo que el nombre NetBIOS del servidor, hace que el cliente inicie sesión utilizando el SAM local del servidor (en lugar del SAM de Dominio).

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro workgroup en el archivo /etc/samba/smb.conf.

-r|--realm=REINO

Establezca el reino para el dominio.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro realm en el archivo /etc/samba/smb.conf.

-U|--user=[DOMINIO\]USUARIO[%CONTRASEÑA]

Establece el nombre de usuario SMB o el nombre de usuario y la contraseña.

Si no se especifica %CONTRASEÑA, se le pedirá al usuario. El cliente primero comprobará la variable de entorno USER (que también tiene permitido también

OPTIONS

The options are explained below.

-U|--user=

Specify the username to use for connecting to the server.

If the username is not specified, the username found in a Kerberos Credentials cache may be used. If neither exists, the username found in the LOGNAME environment variable is used. If this is not set, the UID of the current user is used to look up the name with the getlogin(3) and getpwuid(3) calls.

If the username contains a semicolon, the part after the semicolon is treated as the password. The password will be prompted for if not found and if the LOGNAME variable is not set. If the password is not available via either of these methods, the client will ask the user for a password.

For example: -U user%password, or -U user%password%domain

If the specified username contains a password and the LOGNAME environment variable is set, then the value of the username will be used and the password will be ignored. This is to ensure that you do not accidentally send a password on the command line that you did not intend to. You should be very careful with passwords on the command line!

Be cautious about including passwords in scripts or passing user-supplied values onto the command line. For security it is better to let the Samba client tool ask for the password if needed, or obtain the password once with kinit.

-O|--option==

Emulate command line options. This is useful to specify options that are not available as command line arguments.

-A|--authentication-file=

The file specified by filename contains the username and password. The format of the file is: 
username = <value>
password = <value>
domain   = <value>

Make certain that the permissions on the file restrict access from unwanted users!

-l|--long

Produce long, detailed listing.

-p|--show-all

Show all quotas, even if they are zero.

-q|--quiet

Do not print error messages.

-S|--super

Use the super user quotas.

-P|--machine-pass

Use stored machine account password.

-N|--no-pass

If specified, this parameter suppresses the normal password prompt from the client to the user. This is useful when accessing a service that does not require a password.

Unless a password is specified on the command line or this parameter is specified, the client will request a password.

If a password is specified on the command line and this option is also defined the password on the command line will be silently ignored and no password will be used.

--password=

Specify the password on the commandline.

Be cautious about including passwords in scripts or passing user-supplied values onto the command line. For security it is better to let the Samba client tool ask for the password if needed, or obtain the password once with kinit.

If --password is not specified, the tool will check the PASSWD environment variable, followed by PASSWD_FD which is expected to contain an open file descriptor (FD) number.

Finally it will check PASSWD_FILE (containing a file path to be opened). The file should only contain the password. Make certain that the permissions on the file restrict access from unwanted users!

While Samba will attempt to scrub the password from the process title (as seen in ps), this is after startup and so is subject to a race.

--pw-nt-hash

The supplied password is the NT hash.

--use-kerberos=

This parameter determines whether Samba client tools will try to authenticate using Kerberos. For Kerberos authentication you should use DNS names instead of IP addresses when connecting to a service. By default Samba client tools will try to use the default Kerberos credential cache (ccache). In case the ccache does not exist or -U|--user option was specified, clients will ask to enter a password and will obtain a Kerberos ticket (kinit) for you. If you want to use an alternative Kerberos credentical cache, use the --use-krb5-ccache option.

Note that specifying this parameter here will override the client use kerberos parameter in the /etc/samba/smb.conf file.

--use-krb5-ccache=

Specifies the credential cache location for Kerberos authentication.

This will enforce --use-kerberos=required.

--use-winbind-ccache

Try to use the credential cache by winbind.

--client-protection=

Sets the connection protection the client tool should use.

Note that specifying this parameter here will override the client protection parameter in the /etc/samba/smb.conf file.

In case you need more fine grained control you can use: --option=clientsmbencrypt=OPTION, --option=clientipcsigning=OPTION, --option=clientsigning=OPTION.

--simple-bind-dn=

DN to use for a simple bind.

--option==

Emulate command line options. This is useful to specify options that are not available as command line arguments.

The format of an the QUOTA_SET_COMMAND is an operation name followed by a set of parameters specific to that operation.

To set user quotas for the user specified by -u or for the current username:

UQLIM:<username>:<softlimit>/<hardlimit>

To set the default quotas for a share:

FSQLIM:<softlimit>/<hardlimit>

To change the share quota settings:

FSQFLAGS:QUOTA_ENABLED/DENY_DISK/LOG_SOFTLIMIT/LOG_HARD_LIMIT

All limits are specified as a number of bytes.

QUOTA_SET_COMMAND

The format of an the QUOTA_SET_COMMAND is an operation name followed by a set of parameters specific to that operation.

To set user quotas for the user specified by -u or for the current username:

UQLIM:<username>:<softlimit>/<hardlimit>

To set the default quotas for a share:

FSQLIM:<softlimit>/<hardlimit>

To change the share quota settings:

FSQFLAGS:QUOTA_ENABLED/DENY_DISK/LOG_SOFTLIMIT/LOG_HARD_LIMIT

All limits are specified as a number of bytes.

EXIT STATUS

The smbcquotas program sets the exit status depending on the success or otherwise of the operations performed. The exit status may be one of the following values.

If the operation succeeded, smbcquotas returns an exit status of 0. If smbcquotas couldn't connect to the specified server, or when there was an error getting or setting the quota(s), an exit status of 1 is returned. If there was an error parsing any command line arguments, an exit status of 2 is returned.
