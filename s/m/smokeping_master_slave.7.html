NOMBRE

smokeping_master_slave - Cómo ejecutar múltiples instancias distribuidas de SmokePing

DESCRIPCIÓN GENERAL

Normalmente, las sondas de smokeping ejecutan sus pruebas desde el host donde se ejecuta smokeping hacia algún host de destino y monitorizan la latencia de la conexión entre ambos.

El concepto Maestro/Esclavo permite que todas las sondas de smokeping se ejecuten de forma remota. El caso de uso para esto es medir la conectividad general en una red. Si está interesado en verificar que su servidor DNS central o su servidor de archivos funcione para todos, podría configurar varias instancias de smokeping verificando los dos servidores desde múltiples ubicaciones dentro de su red. Con la configuración maestro/esclavo de smokeping, este proceso se vuelve mucho más simple, ya que un servidor maestro de smokeping puede controlar múltiples esclavos.

Todos los datos de monitorización se almacenan y presentan en el servidor, pero son recopilados por los esclavos. Los esclavos también obtendrán su información de configuración del maestro, por lo que solo tendrá que mantener el archivo de configuración del servidor maestro y el resto se manejará automáticamente.

DESCRIPCIÓN

Arquitectura

Los esclavos se comunican con el servidor maestro de smokeping a través de la interfaz web normal de smokeping. Al inicio, cada esclavo se conecta al servidor maestro y solicita sus asignaciones. Cuando el esclavo ha completado una ronda de sondeos, se conecta nuevamente al maestro para entregar los resultados.

Si la asignación para un esclavo cambia, el maestro se lo indicará al esclavo después de que este haya entregado sus resultados.

El maestro y los esclavos firman sus mensajes proporcionando un código HMAC-MD5 (RFC 2104) del mensaje y un secreto compartido. Opcionalmente, toda la comunicación puede ejecutarse a través de ssl.

[esclavo 1]     [esclavo 2]      [esclavo 3]
    |             |              |
    +-------+     |     +--------+
            |     |     |
            v     v     v
          +---------------+
          |     maestro     |
          +---------------+

El esclavo es una configuración normal de smokeping donde la configuración proviene del maestro en lugar de un archivo de configuración local. El esclavo intenta contactar al servidor maestro después de cada ronda de sondeo, proporcionando sus resultados. Si no se puede contactar al servidor maestro, los resultados se enviarán al servidor junto con la siguiente ronda de resultados. Los resultados se almacenarán en un archivo en formato Perl storable para que sobrevivan a un reinicio de la instancia de smokeping.

Configuración del Maestro

Para configurar una configuración maestro/esclavo, agregue una sección de esclavos a su archivo de configuración de smokeping. Cada esclavo tiene una sección en la parte de esclavos del archivo de configuración del maestro. El nombre de la sección debe coincidir con el nombre de host del esclavo. Si algún parámetro de configuración debe establecerse en un valor especial para el esclavo, use una sección de anulación para configurarlo.

Los nombres de los esclavos deben ser los nombres que los hosts creen tener, no sus nombres de host externos o direcciones IP o cualquier otra cosa. Cuando el esclavo llama al maestro para obtener su configuración o informar sus mediciones, le dirá al maestro su 'nombre de host'. Esto, junto con el secreto compartido, se utiliza para autenticar e identificar quién es quién.

*** Slaves ***
secrets=/etc/smokeping/slavesecrets.conf 
+slave1
display_name=erul22
location=India
color=ff0000
++override
Probes.FPing.binary = /usr/bin/fping
...

Luego, en la sección de objetivos, puede definir esclavos en cualquier nivel. Nuevamente, la configuración se hereda de los objetivos de orden inferior y se puede anular en cualquier lugar del árbol.

Un esclavo recibirá la configuración apropiada asignada por el servidor.

*** Targets ***
slaves = slave1 slave2
...
+dest1
slaves =
...
+dest2
slaves = slave1
...
+dest3
...

Los datos de los esclavos se almacenarán en NombreObjetivo~NombreEsclavo.rrd. Por lo tanto, el ejemplo anterior crearía los siguientes archivos:

dest1.rrd
dest2.rrd
dest2~slave1.rrd
dest3.rrd
dest3~slave1.rrd
dest3~slave2.rrd

El archivo slavesecrets.conf contiene una lista separada por dos puntos de nombres de host y secretos.

host1:secret1
host2:secret2

Configuración del Esclavo

Una configuración de esclavo de smokeping no tiene archivo de configuración. Simplemente necesita saber que se ejecuta en modo esclavo y su secreto. El secreto se almacena en un archivo para una protección óptima. Por defecto, la caché de datos persistente se ubicará en /tmp/smokeping.$USER.cache.

./smokeping --master-url=http://smokeping/smokeping.cgi \
            --cache-dir=/var/smokeping/ \
            --shared-secret=/var/smokeping/secret.txt

El archivo secret.txt contiene una sola palabra, el secreto de este esclavo. NO es lo mismo que el archivo slavesecrets.conf que utiliza el maestro.

CONSIDERACIONES DE SEGURIDAD

El maestro tiene efectivamente acceso total a los hosts esclavos como el usuario que ejecuta la instancia esclava de smokeping. La configuración se transfiere como código Perl que se evalúa en el esclavo. Si bien esto se hace dentro de un compartimento restringido "Safe", existen varias formas en que un maestro malicioso podría incrustar comandos arbitrarios en la configuración y hacer que se ejecuten cuando el esclavo sondea sus objetivos.

La fortaleza del secreto compartido es, por lo tanto, de suma importancia. Forzar el secreto permitiría a un atacante intermediario inyectar una nueva configuración maliciosa y comprometer al esclavo.
