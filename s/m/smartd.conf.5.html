NOMBRE

smartd.conf - Archivo de Configuración del Demonio de Monitoreo SMART

DESCRIPCIÓN

[Esta página del manual está generada para la versión de Linux de smartmontools. No contiene información específica para otras plataformas.]

/etc/smartd.conf es el archivo de configuración para el demonio smartd.

Si el archivo de configuración /etc/smartd.conf está presente, smartd lo lee al inicio. Si smartd recibe posteriormente una señal HUP, volverá a leer el archivo de configuración. Si smartd se está ejecutando en modo de depuración, entonces una señal INT también hará que vuelva a leer el archivo de configuración. Esta señal se puede generar escribiendo <CONTROL-C> en la ventana de terminal donde se está ejecutando smartd.

En ausencia de un archivo de configuración, smartd intentará abrir todos los dispositivos disponibles (ver la página del manual de smartd(8)). Un archivo de configuración con una sola línea 'DEVICESCAN -a' tendría el mismo efecto.

Esto puede ser molesto si tienes un dispositivo ATA o SCSI que se bloquea o se comporta mal al recibir comandos SMART. Incluso si esto no causa problemas, puedes verte molesto por la cadena de mensajes de error sobre dispositivos que no se pueden abrir.

Puedes evitar este problema y obtener un mayor control sobre los tipos de eventos monitoreados por smartd, utilizando el archivo de configuración /etc/smartd.conf. Este archivo contiene una lista de dispositivos para monitorear, con un dispositivo por línea. Un archivo de ejemplo se incluye con la distribución de smartmontools. Encontrarás este archivo de configuración de ejemplo en /usr/share/doc/smartmontools/. Por seguridad, el archivo de configuración no debería ser escribible por nadie que no sea root. La sintaxis del archivo es la siguiente:

  • Debe haber un dispositivo listado por línea, aunque puedes tener líneas que sean completamente comentarios o espacios en blanco.
  • Cualquier texto que siga a un signo de almohadilla '#' y hasta el final de la línea se considera un comentario y se ignora.
  • Las líneas se pueden continuar utilizando una barra invertida '\' como el último elemento no-espacio en blanco o no-comentario en una línea.
  • Nota: una línea cuyo primer carácter es un signo de almohadilla '#' se trata como una línea en blanco de espacio en blanco, no como una línea inexistente, y finalizará una línea de continuación.

Aquí hay un archivo de configuración de ejemplo. Es solo para fines ilustrativos; ¡no lo copies en tu sistema sin leer hasta el final de la Sección de DIRECTIVAS a continuación!

################################################
# Este es un archivo de configuración de inicio de smartd de ejemplo
# /etc/smartd.conf
#
# En el segundo disco, inicia una auto-prueba larga todos
# los domingos entre las 3 y las 4 am.
#
/dev/sda -a -m admin@example.com,root@localhost
/dev/sdb -a -I 194 -I 5 -i 12 -s L/../../7/03
#
# Envía un correo electrónico de advertencia de PRUEBA a admin al inicio.
#
/dev/sdc -m admin@example.com -M test
#
# Un disco ATA puede aparecer como un dispositivo SCSI para el
# sistema operativo. Si hay una capa de Traducción SCSI a ATA (SAT)
# entre el sistema operativo y el dispositivo, esto se puede indicar
# con la opción '-d sat'.
/dev/sda -a -d sat
#
# Discos conectados a un controlador MegaRAID
# Inicia auto-pruebas cortas diariamente entre las 1-2, 2-3 y
# 3-4 am.
# Linux:
/dev/sda -d megaraid,0 -a -s S/../.././01
/dev/sda -d megaraid,1 -a -s S/../.././02
/dev/sda -d megaraid,2 -a -s S/../.././03
/dev/bus/0 -d megaraid,2 -a -s S/../.././03
#
# Tres discos conectados a un controlador AacRaid
# Inicia auto-pruebas cortas diariamente entre las 1-2, 2-3 y
# 3-4 am.
/dev/sda -d aacraid,0,0,66 -a -s S/../.././01
/dev/sda -d aacraid,0,0,67 -a -s S/../.././02
/dev/sda -d aacraid,0,0,68 -a -s S/../.././03
#
# Dos discos SATA (no SAS) en un controlador 3ware 9750.
# Inicia auto-pruebas largas los domingos entre la medianoche y
# la 1 am y las 2-3 am
# bajo Linux
/dev/twl0 -d 3ware,0 -a -s L/../../7/00
/dev/twl0 -d 3ware,1 -a -s L/../../7/02
#
# Dos discos conectados al primer controlador HP SmartArray
# que utiliza el controlador cciss de Linux. Inicia auto-pruebas largas
# las noches de domingo y auto-pruebas cortas todas las noches y envía
# errores a root.
/dev/sda -d cciss,0 -a -s (L/../../7/02|S/../.././02) -m root
/dev/sda -d cciss,1 -a -s (L/../../7/03|S/../.././03) -m root
#
# Tres discos SATA en un controlador HighPoint RocketRAID.
# Inicia auto-pruebas cortas diariamente entre las 1-2, 2-3 y
# 3-4 am.
# bajo Linux
/dev/sde -d hpt,1/1 -a -s S/../.././01
/dev/sde -d hpt,1/2 -a -s S/../.././02
/dev/sde -d hpt,1/3 -a -s S/../.././03
#
# Dos discos SATA conectados a un HighPoint RocketRAID
# a través de un dispositivo pmport. Inicia auto-pruebas largas los domingos
# entre la medianoche y la 1 am y las 2-3 am.
# bajo Linux
/dev/sde -d hpt,1/4/1 -a -s L/../../7/00
/dev/sde -d hpt,1/4/2 -a -s L/../../7/02
#
# Tres discos SATA conectados a un controlador RAID Areca.
# Inicia auto-pruebas largas los domingos
# entre la medianoche y las 3 am.
# bajo Linux
/dev/sg2 -d areca,1 -a -s L/../../7/00
/dev/sg2 -d areca,2 -a -s L/../../7/01
/dev/sg2 -d areca,3 -a -s L/../../7/02
#
# La siguiente línea habilita el monitoreo del
# Log de Errores ATA y el Log de Errores de Auto-Prueba.
# También rastrea cambios en los Atributos de Prefallos
# y Uso, aparte de los Atributos
# 9, 194 y 231, y muestra líneas continuadas:
#
/dev/sdd -l error \
     -l selftest \
     -t \         # Atributos no rastreados:
     -I 194 \     # temperatura
     -I 231 \     # también temperatura
     -I 9         # horas de encendido
#

DEVICESCAN

Si una entrada que no es un comentario en el archivo de configuración es la cadena de texto DEVICESCAN en mayúsculas, entonces smartd ignorará cualquier línea restante en el archivo de configuración y escaneará en busca de dispositivos. Si DEVICESCAN no va seguido de ninguna Directiva, entonces '-a' se aplicará a todos los dispositivos.

DEVICESCAN puede ir opcionalmente seguido de Directivas que se aplicarán a todos los dispositivos que se encuentren en el escaneo. Por ejemplo

  DEVICESCAN -m root@example.com

escaneará todos los dispositivos y luego los monitoreará. Enviará una advertencia por correo electrónico por cada dispositivo por cualquier problema que se encuentre.

  DEVICESCAN -H -m root@example.com

hará lo mismo, pero solo monitoreará el estado de salud SMART de los dispositivos, en lugar del '-a' predeterminado.

Se pueden especificar múltiples opciones '-d TYPE' con DEVICESCAN para combinar los resultados del escaneo de más de un TIPO.

Las entradas de configuración para dispositivos específicos pueden preceder a la entrada DEVICESCAN. Por ejemplo

  DEFAULT -m root@example.com
  /dev/sda -s S/../.././02
  /dev/sdc -d ignore
  DEVICESCAN -s L/../.././02

escaneará todos los dispositivos excepto /dev/sda y /dev/sdc, los monitoreará y ejecutará una prueba larga entre las 2 y las 3 am cada mañana. El dispositivo /dev/sda también será monitoreado, pero solo se ejecutará una prueba corta. El dispositivo /dev/sdc será ignorado. Se enviarán correos electrónicos de advertencia para todos los dispositivos monitoreados.

Un dispositivo es ignorado por DEVICESCAN si existe una línea de configuración con el mismo nombre de dispositivo. Los enlaces simbólicos se resuelven antes de realizar esta comprobación. Un nombre de dispositivo también se ignora si ya existe otro dispositivo con la misma información de identificación (proveedor, modelo, versión de firmware, número de serie, WWN).

[NVMe: NUEVA CARACTERÍSTICA EXPERIMENTAL DE SMARTD 7.5] Si un dispositivo solo admite un único espacio de nombres y ya existe una línea de configuración que aborda su ID de espacio de nombres, un resultado de DEVICESCAN que no aborda un espacio de nombres también se ignora (y viceversa).

AJUSTES PREDETERMINADOS

Si una entrada en el archivo de configuración comienza con DEFAULT en lugar de un nombre de dispositivo, entonces todas las directivas en esta entrada se establecen como valores predeterminados para las siguientes entradas de dispositivo.

Esta configuración:

  DEFAULT -a -R5! -W 2,40,45 -I 194 -s L/../../7/00 -m admin@example.com
  /dev/sda
  /dev/sdb
  /dev/sdc
  DEFAULT -H -m admin@example.com
  /dev/sdd
  /dev/sde -d removable

tiene el mismo efecto que:

  /dev/sda -a -R5! -W 2,40,45 -I 194 -s L/../../7/00 -m admin@example.com
  /dev/sdb -a -R5! -W 2,40,45 -I 194 -s L/../../7/00 -m admin@example.com
  /dev/sdc -a -R5! -W 2,40,45 -I 194 -s L/../../7/00 -m admin@example.com
  /dev/sdd -H -m admin@example.com
  /dev/sde -d removable -H -m admin@example.com

DIRECTIVAS DEL ARCHIVO DE CONFIGURACIÓN

Las siguientes son las Directivas que pueden aparecer después del nombre del dispositivo o DEVICESCAN o DEFAULT en cualquier línea del archivo de configuración /etc/smartd.conf. Tenga en cuenta que estas NO son opciones de línea de comandos para smartd. Las Directivas a continuación pueden aparecer en cualquier orden, después del nombre del dispositivo.

Si no aparecen Directivas, el dispositivo se supervisará como si se hubiera dado la Directiva '-a'.

-d TIPO
Especifica el tipo de dispositivo. Los argumentos válidos para esta directiva son:

auto: intenta adivinar el tipo de dispositivo a partir del nombre del dispositivo o de la información del tipo de controlador proporcionada por el sistema operativo o de una entrada de ID USB coincidente en la base de datos de discos. Esta es la opción predeterminada.

ata: el tipo de dispositivo es ATA. Esto evita que smartd emita comandos SCSI a un dispositivo ATA.

scsi: el tipo de dispositivo es SCSI. Esto evita que smartd emita comandos ATA a un dispositivo SCSI.

nvme[,NSID]: el tipo de dispositivo es NVM Express (NVMe). El parámetro opcional NSID especifica el ID del namespace (en hexadecimal) que se pasa al controlador. Utilice 0xffffffff para el ID del namespace de difusión. El valor predeterminado para NSID es el ID del namespace al que se dirige el nombre del dispositivo.

sat[,auto][,N]: el tipo de dispositivo es SCSI a ATA Translation (SAT). Esto es para discos ATA que tienen una capa de traducción SCSI a ATA (SATL) entre el disco y el sistema operativo. SAT define dos comandos SCSI de pase directo ATA, uno de 12 bytes de longitud y el otro de 16 bytes de longitud. El valor predeterminado es la variante de 16 bytes, que se puede anular con '-d sat,12' o '-d sat,16'.

Si se especifica '-d sat,auto', el tipo de dispositivo SAT (para discos ATA/SATA) solo se utiliza si los datos SCSI INQUIRY informan de un SATL (VENDOR: "ATA "). De lo contrario, se utiliza el tipo de dispositivo SCSI (para discos SCSI/SAS).

usbasm1352r,PUERTO: [NUEVA CARACTERÍSTICA EXPERIMENTAL DE SMARTD 7.4] este tipo de dispositivo es para uno o dos discos SATA que se encuentran detrás de un puente USB a SATA (RAID) ASMedia ASM1352R. El parámetro PUERTO (0 o 1) selecciona el disco a supervisar.
Nota: Este puente USB también admite '-d sat'. Esto supervisa el primer disco o el segundo disco si no hay ningún disco conectado al primer puerto.

usbcypress: este tipo de dispositivo es para discos ATA que se encuentran detrás de un puente USB a PATA Cypress. Utilizará el comando propietario de pase directo SCSI ATACB. El código de operación SCSI predeterminado es 0x24, pero aunque se puede anular con '-d usbcypress,0xN', donde N es el código de operación SCSI, corre el riesgo de dañar el dispositivo o los sistemas de archivos en él.

usbjmicron[,p][,x][,PUERTO]: este tipo de dispositivo es para discos SATA que se encuentran detrás de un puente USB a PATA/SATA JMicron. Los comandos ATA de 48 bits (requeridos p. ej. para '-l xerror', véase más abajo) no funcionan con todos estos puentes y, por lo tanto, están deshabilitados por defecto. Estos comandos se pueden habilitar con '-d usbjmicron,x'. Si dos discos están conectados a un puente con dos puertos, se imprime un mensaje de error si no se especifica PUERTO (0 o 1).
El parámetro PUERTO no es necesario si el dispositivo utiliza un multiplicador de puertos para conectar varios discos a un solo puerto. Los discos aparecen entonces bajo nombres de /dev/ice separados.
PRECAUCIÓN: Especificar ',x' para un dispositivo que no lo soporta provoca errores de E/S y puede desconectar la unidad. Lo mismo se aplica si el PUERTO especificado no existe o no está conectado a un disco.

Los puentes USB Prolific PL2507/3507 con firmware antiguo admiten un comando de pase directo similar a JMicron y funcionan con '-d usbjmicron,0'. Los firmwares Prolific más recientes requieren un comando modificado que se puede seleccionar con '-d usbjmicron,p'. Tenga en cuenta que esto todavía no admite el comando de estado SMART.

usbprolific: este tipo de dispositivo es para discos SATA que se encuentran detrás de un puente USB a SATA Prolific PL2571/2771/2773/2775.

usbsunplus: este tipo de dispositivo es para discos SATA que se encuentran detrás de un puente USB a SATA SunplusIT.

sntasmedia[/sat]: este tipo de dispositivo es para discos NVMe que se encuentran detrás de un puente USB a NVMe ASMedia.
[NUEVA CARACTERÍSTICA EXPERIMENTAL DE SMARTD 7.5] Si se especifica el sufijo '/sat' y falla el comando NVMe Identify Controller, el tipo de dispositivo se cambia a '-d sat'. Esto es útil para adaptadores M.2 USB que admiten dispositivos NVMe y SATA.

sntjmicron[,NSID][/sat]: este tipo de dispositivo es para discos NVMe que se encuentran detrás de un puente USB a NVMe JMicron. El parámetro opcional NSID especifica el ID del namespace (en hexadecimal) que se pasa al controlador. El ID del namespace predeterminado es el ID del namespace de difusión (0xffffffff). Véase también '-d sntasmedia' para el sufijo '/sat'.

sntrealtek[/sat]: este tipo de dispositivo es para discos NVMe que se encuentran detrás de un puente USB a NVMe Realtek. Véase también '-d sntasmedia' para el sufijo '/sat'.

marvell: [solo Linux] (obsoleto y sujeto a eliminación).

megaraid,N: [solo FreeBSD y Linux] el dispositivo consta de uno o más discos SCSI/SAS conectados a un controlador MegaRAID. El entero no negativo N (en el rango de 0 a 127 inclusive) denota qué disco en el controlador se supervisa. Esta interfaz también funcionará para los controladores Dell PERC. En los archivos de registro y mensajes de correo electrónico, este disco se identificará como megaraid_disk_XXX con XXX en el rango de 000 a 127 inclusive. Consulte la página del manual de smartctl(8) para obtener más detalles.

aacraid,H,L,ID: [solo Linux, Windows y Cygwin] el dispositivo consta de uno o más discos SCSI/SAS o SATA conectados a un controlador AacRaid. Los enteros no negativos H, L, ID (número de host, Lun, ID) denotan qué disco en el controlador se supervisa. En los archivos de registro y mensajes de correo electrónico, este disco se identificará como aacraid_disk_HH_LL_ID. Consulte la página del manual de smartctl(8) para obtener más detalles.

3ware,N: [solo FreeBSD y Linux] el dispositivo consta de uno o más discos ATA conectados a un controlador RAID 3ware. El entero no negativo N (en el rango de 0 a 127 inclusive) denota qué disco en el controlador se supervisa. En los archivos de registro y mensajes de correo electrónico, este disco se identificará como 3ware_disk_XXX con XXX en el rango de 000 a 127 inclusive.

Tenga en cuenta que si bien puede usar cualquiera de los dispositivos lógicos SCSI de 3ware /dev/tw* para direccionar cualquiera de los discos físicos (puertos 3ware), los mensajes de error y registro tendrán más sentido si siempre lista el dispositivo lógico SCSI de 3ware correspondiente a los discos físicos particulares. Consulte la página del manual de smartctl(8) para obtener más detalles.

areca,N: [solo FreeBSD, Linux, Windows y Cygwin] el dispositivo consta de uno o más discos SATA conectados a un controlador RAID SATA Areca. El entero positivo N (en el rango de 1 a 24 inclusive) denota qué disco en el controlador se supervisa. En los archivos de registro y mensajes de correo electrónico, este disco se identificará como areca_disk_XX con XX en el rango de 01 a 24 inclusive. Consulte la página del manual de smartctl(8) para obtener más detalles.

areca,N/E: [solo FreeBSD, Linux, Windows y Cygwin] el dispositivo consta de uno o más discos SATA o SAS conectados a un controlador RAID SAS Areca. El entero N (rango 1 a 128) denota el canal (ranura) y E (rango 1 a 8) denota la carcasa. Importante: esto requiere la versión 1.51 o posterior del firmware del controlador SAS Areca.

cciss,N: [solo FreeBSD y Linux] el dispositivo consta de uno o más discos SCSI/SAS o SATA conectados a un controlador RAID cciss. El entero no negativo N (en el rango de 0 a 127 inclusive) denota qué disco en el controlador se supervisa. En los archivos de registro y mensajes de correo electrónico, este disco se identificará como cciss_disk_XX con XX en el rango de 00 a 127 inclusive. Consulte la página del manual de smartctl(8) para obtener más detalles.

hpt,L/M/N: [solo FreeBSD y Linux] el dispositivo consta de uno o más discos ATA conectados a un controlador HighPoint RocketRAID. El entero L es el ID del controlador, el entero M es el número de canal y el entero N es el número de PMPort si está disponible. Los valores permitidos de L son de 1 a 4 inclusive, M de 1 a 128 inclusive y N de 1 a 4 si hay PMPort disponible. Y también estos valores están limitados por el modelo del controlador HighPoint RocketRAID. En los archivos de registro y mensajes de correo electrónico, este disco se identificará como hpt_X/X/X y X/X/X es lo mismo que L/M/N, tenga en cuenta que si no se indica N, N se establece en el valor predeterminado 1. Consulte la página del manual de smartctl(8) para obtener más detalles.

sssraid,E,S: [solo Linux: NUEVA CARACTERÍSTICA EXPERIMENTAL DE SMARTD 7.4] el dispositivo consta de uno o más discos SCSI/SAS o SATA conectados a un controlador SSSRAID. El entero no negativo E (en el rango de 0 a 8) denota la carcasa y S (rango 0 a 128) denota la ranura. Consulte la página del manual de smartctl(8) para obtener más detalles.

intelliprop,N[+TIPO]: (obsoleto y sujeto a eliminación).

jmb39x[-q[2]],N[,sLBA][,force][+TIPO]: el dispositivo consta de varios discos SATA conectados a un multiplicador de puertos RAID JMicron JMB39x. El sufijo '-q' selecciona una variante de comando ligeramente diferente utilizada por los dispositivos NAS QNAP TR-004. El entero N es el número de puerto de 0 a 4.
[NUEVA CARACTERÍSTICA EXPERIMENTAL DE SMARTD 7.5] El sufijo '-q2' selecciona otra variante de comando utilizada por los dispositivos NAS QNAP TR-002. Consulte la página del manual de smartctl(8) para obtener más detalles.

jms56x,N[,sLBA][,force][+TIPO]: el dispositivo consta de varios discos SATA conectados a un puente USB a SATA RAID JMicron JMS56x. Consulte 'jmb39x...' más arriba para ver los argumentos válidos.

ignore: el dispositivo especificado por esta entrada de configuración debe ser ignorado. Esto permite ignorar dispositivos específicos que son detectados por una siguiente línea de configuración DEVICESCAN. También puede usarse para deshabilitar temporalmente entradas de configuración multilínea más largas. Esta Directiva puede usarse en conjunción con las otras Directivas '-d'.

removable: el dispositivo o sus medios son extraíbles. Esto indica a smartd que continúe (en lugar de salir, que es el comportamiento predeterminado) si el dispositivo no parece estar presente cuando se inicia smartd. Esta directiva también s

supprime los correos electrónicos de advertencia y los mensajes de registro repetidos si el dispositivo se elimina después del inicio. Esta Directiva puede usarse junto con las otras Directivas '-d'.
ADVERTENCIA: Quitar un dispositivo y conectar uno diferente en la misma interfaz no está soportado y puede resultar en advertencias falsas hasta que smartd se reinicie.

-n MODOALIMENTACION[,N][,q]
[Solo ATA] Esta Directiva 'nocheck' se utiliza para evitar que un disco sea desactivado (spin-up) cuando es consultado periódicamente por smartd.

Los discos ATA tienen cinco estados de energía diferentes. En orden de consumo de energía creciente son: 'OFF', 'SLEEP', 'STANDBY', 'IDLE' y 'ACTIVE'. Típicamente en los modos OFF, SLEEP y STANDBY los platos del disco no giran. Pero usualmente, en respuesta a los comandos SMART emitidos por smartd, los platos del disco giran. Así que si esta opción no se usa, un disco que está en un modo de bajo consumo puede ser desactivado y puesto en un modo de mayor consumo cuando es consultado periódicamente por smartd.

Ten en cuenta que si el disco está en modo SLEEP cuando smartd se inicia, no responderá a los comandos de smartd, y por lo tanto el disco no será registrado como un dispositivo para que smartd lo supervise. Si un disco está en cualquier otro modo de bajo consumo, los comandos emitidos por smartd para registrar el disco probablemente causarán que gire.

La Directiva '-n' (nocheck) especifica si las comprobaciones periódicas de smartd deben realizarse cuando el dispositivo está en un modo de bajo consumo. Puede usarse para evitar que un disco sea activado por las consultas periódicas de smartd. Los valores permitidos de MODOALIMENTACION son:

never - smartd consultará (comprobará) el dispositivo sin importar su modo de energía. Esto puede causar que un disco que está detenido sea activado cuando smartd lo comprueba. Este es el comportamiento por defecto si la Directiva '-n' no se proporciona.

sleep - comprueba el dispositivo a menos que esté en modo SLEEP .

standby - comprueba el dispositivo a menos que esté en modo SLEEP o STANDBY. En estos modos la mayoría de los discos no giran, así que si quieres evitar que un disco de portátil gire cada vez que smartd consulta, probablemente esto es lo que quieres.

idle - comprueba el dispositivo a menos que esté en modo SLEEP, STANDBY o IDLE. En el estado IDLE, la mayoría de los discos todavía giran, así que esto probablemente no es lo que quieres.

El número máximo de comprobaciones omitidas (seguidas) puede especificarse añadiendo un número positivo ',N' a MODOALIMENTACION (como '-n standby,15'). Después de que N comprobaciones sean omitidas seguidas, el modo de energía se ignora y la comprobación se realiza de todos modos.

Cuando se omite una prueba periódica, smartd normalmente escribe un mensaje de registro informal. El mensaje puede suprimirse añadiendo la opción ',q' a MODOALIMENTACION (como '-n standby,q'). Esto evita que un disco de portátil gire debido a este mensaje.

Tanto ',N' como ',q' pueden especificarse juntos.

-T TIPO
Especifica cuán tolerante debe ser smartd a los fallos de comandos SMART. Los argumentos válidos para esta Directiva son:

normal - no intentes supervisar el disco si un comando SMART obligatorio falla, pero continúa si un comando SMART opcional falla. Este es el valor por defecto.

permissive - intenta supervisar el disco incluso si parece carecer de capacidades SMART. Esto puede ser necesario para algunos discos antiguos (anteriores a ATA-3 revisión 4) que implementaron SMART antes de que los estándares SMART se incorporaran a las Especificaciones ATA/ATAPI. -t
Equivalente a activar las dos banderas anteriores '-p' y '-u'.
-i ID
[Solo ATA] Ignorar el Atributo número ID del dispositivo al comprobar fallos de los Atributos de Uso. ID debe ser un número entero decimal en el rango de 1 a 255. Esta Directiva modifica el comportamiento de la Directiva '-f' y no tiene efecto sin ella.

Esto es útil, por ejemplo, si tiene un disco muy antiguo y no desea seguir recibiendo mensajes sobre el fallo del Atributo de horas de funcionamiento de por vida (normalmente el Atributo 9). Esta Directiva puede aparecer varias veces para un mismo dispositivo, si desea ignorar múltiples Atributos.

-I ID
[Solo ATA] Ignorar el Atributo ID del dispositivo al rastrear cambios en los valores del Atributo. ID debe ser un número entero decimal en el rango de 1 a 255. Esta Directiva modifica el comportamiento de las Directivas de rastreo '-p', '-u' y '-t' y no tiene efecto sin una de ellas.

Esto es útil, por ejemplo, si uno de los Atributos del dispositivo es la temperatura del disco (normalmente el Atributo 194 o 231). Es molesto recibir informes cada vez que cambia la temperatura. Esta Directiva puede aparecer varias veces para un mismo dispositivo, si desea ignorar múltiples Atributos.

-r ID[!]
[Solo ATA] Al rastrear, informar el valor *Raw* del Atributo ID junto con su valor *Normalizado* (normalmente informado). ID debe ser un número entero decimal en el rango de 1 a 255. Esta Directiva modifica el comportamiento de las Directivas de rastreo '-p', '-u' y '-t' y no tiene efecto sin una de ellas. Esta Directiva puede darse varias veces.

Un uso común de esta Directiva es rastrear la Temperatura del dispositivo (a menudo ID=194 o 231).

Si se añade la bandera opcional '!', un cambio del valor Normalizado se considera crítico. El informe se registrará como LOG_CRIT y se enviará un correo electrónico de advertencia si se especifica '-m'.

-R ID[!]
[Solo ATA] Al rastrear, informar siempre que el valor *Raw* del Atributo ID cambie. (Normalmente smartd solo rastrea/informa cambios de los valores de Atributo *Normalizados*.) ID debe ser un número entero decimal en el rango de 1 a 255. Esta Directiva modifica el comportamiento de las Directivas de rastreo '-p', '-u' y '-t' y no tiene efecto sin una de ellas. Esta Directiva puede darse varias veces.

Si se da esta Directiva, implica automáticamente la Directiva '-r' para el mismo Atributo, de modo que se informe el valor Raw del Atributo.

Un uso común de esta Directiva es rastrear la Temperatura del dispositivo (a menudo ID=194 o 231). También es útil para comprender cómo los diferentes tipos de comportamiento del sistema afectan los valores de ciertos Atributos.

Si se añade la bandera opcional '!', un cambio del valor Raw se considera crítico. El informe se registrará como LOG_CRIT y se enviará un correo electrónico de advertencia si se especifica '-m'. Un ejemplo es '-R 5!' para advertir cuando se reasignan nuevos sectores.

[Solo ATA] Informar si el número actual de sectores pendientes es distinto de cero. Aquí ID es el número de id del Atributo cuyo valor Raw es el recuento de sectores pendientes actuales. El rango permitido de ID es de 0 a 255 inclusive. Para desactivar esta notificación, utilice ID = 0. Si no se proporciona la opción -C ID, por defecto será -C 197 (ya que el Atributo 197 se utiliza generalmente para monitorizar sectores pendientes). Si el nombre de este Atributo se cambia por una directiva '-v 197,FORMAT,NAME', el valor por defecto se cambia a -C 0.

Si se especifica '+', solo se imprime un informe si el número de sectores ha aumentado entre dos ciclos de comprobación. Algunos discos no restablecen este atributo cuando se reasigna un sector defectuoso. Véase también '-v 197,increasing' más abajo.

El contador de correos electrónicos de advertencia se restablece si el número de sectores pendientes cae a 0. Esto suele ocurrir cuando todos los sectores pendientes han sido reasignados o podrían ser leídos de nuevo.

Un sector pendiente es un sector del disco (que contiene 512 bytes de sus datos) que el dispositivo gustaría marcar como "defectuoso" y reasignar. Normalmente esto se debe a que su ordenador intentó leer ese sector, y la lectura falló porque los datos en él se han corrompido y tienen códigos de Error Checking and Correction (ECC) inconsistentes. Esto es importante saberlo, porque significa que hay algunos datos no legibles en el disco. El problema de averiguar a qué archivo pertenecen estos datos es específico del sistema operativo y del sistema de archivos. Normalmente puede forzar la reasignación del sector escribiendo en él (traducción: hacer que el dispositivo sustituya un sector bueno de reserva por el defectuoso), pero a costa de perder los 512 bytes de datos almacenados allí.

[Solo ATA] Informar si el número de sectores no corregibles sin conexión es distinto de cero. Aquí ID es el número de id del Atributo cuyo valor Raw es el recuento de sectores no corregibles sin conexión. El rango permitido de ID es de 0 a 255 inclusive. Para desactivar esta notificación, utilice ID = 0. Si no se proporciona la opción -U ID, por defecto será -U 198 (ya que el Atributo 198 se utiliza generalmente para monitorizar sectores no corregibles sin conexión). Si el nombre de este Atributo se cambia por una directiva '-v 198,FORMAT,NAME' (excepto '-v 198,FORMAT,Offline_Scan_UNC_SectCt'), el valor por defecto se cambia a -U 0.

Si se especifica '+', solo se imprime un informe si el número de sectores ha aumentado desde el último ciclo de comprobación. Algunos discos no restablecen este atributo cuando se reasigna un sector defectuoso. Véase también '-v 198,increasing' más abajo.

El contador de correos electrónicos de advertencia se restablece si el número de sectores no corregibles sin conexión cae a 0. Esto suele ocurrir cuando todos los sectores no corregibles sin conexión han sido reasignados o podrían ser leídos de nuevo.

Un sector no corregible sin conexión es un sector del disco que no se pudo leer durante un escaneo sin conexión o una autoprueba. Esto es importante saberlo, porque si tiene datos almacenados en este sector del disco y necesita leerlos, la lectura fallará. Consulte la opción '-C' anterior para más detalles.

-W DIFF[,INFO[,CRIT]]
Informar si la temperatura actual ha cambiado en al menos DIFF grados desde el último informe, o si se detecta una nueva temperatura mínima o máxima. Informar o advertir si la temperatura es mayor o igual a uno de los grados INFO o CRIT Celsius. Si se alcanza el límite CRIT, se registrará un mensaje con nivel de registro LOG_CRIT en syslog y se enviará un correo electrónico de advertencia si se especifica '-m'. Si solo se alcanza el límite INFO, se registrará un mensaje con nivel de registro LOG_INFO.

El contador de correos electrónicos de advertencia se restablece si la temperatura cae por debajo de INFO o CRIT-5 si INFO no se especifica.

-W 2
Para registrar mensajes informales sobre temperaturas de al menos 40 grados, use:
-W 0,40
Para mensajes/correos electrónicos de advertencia sobre temperaturas de al menos 45 grados, use:
-W 0,0,45
Para combinar todos los informes anteriores, use:
-W 2,40,45

NAME

smartd.conf — configuration file for the ATA daemon

DESCRIPTION

The file /etc/smartd.conf is the configuration file for the smartd daemon. This file is used to control the behavior of smartd, including which devices to monitor and how often to check them.

The configuration file consists of Directives, which are recognized by keywords starting with a hyphen (-) or by Device-specific keywords. Directives apply to all devices unless overridden by a Device-specific configuration.

Device-specific configurations start with the name of the device, followed by a colon (:). All directives following this line apply only to the specified device, until the next device-specific configuration or the end of the file.

Comments begin with a hash sign (#) and continue to the end of the line.

Blank lines are ignored.

DEVICESCAN

If the keyword DEVICESCAN is present, then smartd will scan for all ATA devices on all SCSI/SATA/IDE/USB interfaces and will apply the default settings to them, unless overridden by device-specific settings.

It is recommended to use DEVICESCAN whenever possible, as it simplifies the configuration file.

DEFAULT SETTINGS

If the keyword DEFAULT is present, then all directives following this line apply to all devices, unless overridden by device-specific settings.

CONFIGURATION FILE DIRECTIVES

The following directives can be used in the configuration file:

-H
[ATA/SCSI only] Enable drive self-health (-H) monitoring. This directive is enabled by default.
-o
Enables disk status monitoring. This directive is enabled by default.
-s TYPE
[ATA/SCSI only] Enable scheduled self-tests of TYPE. The valid arguments to this Directive are:
short
Perform a short self-test once a week.
long
Perform a long self-test once a month.
conveyance
Perform a conveyance self-test once a month.
short -d DATETIME
Perform a short self-test on DATETIME.
long -d DATETIME
Perform a long self-test on DATETIME.
conveyance -d DATETIME
Perform a conveyance self-test on DATETIME.

DATETIME is of the form DAYofWEEK,TIMEofDAY, where DAYofWEEK is a number from 0 (Sunday) to 6 (Saturday), and TIMEofDAY is the hour of the day (00-23).

If multiple -s directives are given for the same device, they are all enabled. If no -s directive is given, then no self-tests are performed.

-t
[ATA/SCSI only] Enable vendor-specific self-tests. This directive is enabled by default.
-l TYPE
Enable logging of TYPE. The valid arguments to this Directive are:
error
Log ATA error information. This directive is enabled by default.
selftest
Log the results of self-tests. This directive is enabled by default.
selfteststs

all
Log all available information.

EXAMPLES OF SHELL SCRIPTS FOR '-M exec'
These are two examples of shell scripts that can be used with the '-M exec PATH' Directive described previously. The paths to these scripts and similar executables is the PATH argument to the '-M exec PATH' Directive.

Example 1: This script is for use with '-m ADDRESS -M exec PATH'. It appends the output of smartctl -a to the output of the smartd email warning message and sends it to ADDRESS.

#! /bin/sh
# Save the email message (STDIN) to a file:
cat > /root/msg
# Append the output of smartctl -a to the message:
/usr/bin/smartctl -a -d $SMART_DEVICETYPE \
  $SMARTD_DEVICE >> /root/msg
# Now email the message to the user at address ADD:
/usr/bin/mail -s "$SMARTD_SUBJECT" $SMARTD_ADDRESS \
  < /root/msg

Example 2: This script is for use with '-m <nomailer> -M exec PATH'. It warns all users about a disk problem, waits 30 seconds, and then powers down the machine.

#! /bin/sh
# Warn all users of a problem
wall <<EOF
Problem detected with disk: $SMARTD_DEVICESTRING
Warning message from smartd is: $SMARTD_MESSAGE
Shutting down machine in 30 seconds...
EOF
# Wait half a minute
sleep 30
# Power down the machine
/sbin/shutdown -hf now

Some example scripts are distributed with the smartmontools package, in /usr/share/doc/smartmontools/examplescripts/.

Please note that these scripts typically run as root, so any files that they read/write should not be writable by ordinary users or reside in directories like /tmp that are writable by ordinary users and may expose your system to symlink attacks.

As previously described, if the scripts write to STDOUT or STDERR, this is interpreted as indicating that there was an internal error within the script, and a snippet of STDOUT/STDERR is logged to SYSLOG. The remainder is flushed.
