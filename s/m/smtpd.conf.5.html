NAME

smtpd.conf — Archivo de configuración del demonio SMTP

DESCRIPTION

smtpd.conf es el archivo de configuración para el demonio de correo smtpd(8).

Cuando llega correo, cada comando “RCPT TO:” genera un sobre de correo. Si un sobre coincide con alguno de un conjunto de criterios predefinidos (usando la directiva match), el mensaje se acepta para su entrega. Una copia del mensaje, así como sus sobres asociados, se guarda en la cola de correo y posteriormente se envía según un conjunto de acciones asociadas (usando la directiva action). Si un sobre no coincide con ninguna opción, se rechaza. Las reglas de coincidencia se evalúan secuencialmente, y la primera coincidencia es la que prevalece.

El formato del archivo de configuración es bastante flexible. La línea actual se puede extender en varias líneas usando una barra invertida (‘\’). Los comentarios se pueden colocar en cualquier lugar del archivo usando un signo de almohadilla (‘#’) y se extienden hasta el final de la línea actual. Se debe tener cuidado al comentar texto multilínea: el comentario es efectivo hasta el final de todo el bloque. Los nombres de argumentos que no comienzan con una letra, dígito o guion bajo, así como las palabras reservadas (como listen, match y port), deben ir entre comillas. Los argumentos que contienen espacios en blanco deben ir entre comillas dobles (").

Se define una macro con un comando de la forma nombre=valor. El nombre de la macro puede contener letras, dígitos y guiones bajos y no puede ser una palabra reservada. Dentro de los argumentos sin comillas, la cadena $nombre se expande posteriormente a valor.

Por ejemplo:

lan_addr = "192.168.0.1"
listen on $lan_addr
listen on $lan_addr tls auth

La sintaxis de smtpd.conf se describe a continuación.

action nombre método [opciones]
Cuando el procesador de colas procesa un sobre de la cola de correo, lleva a cabo la action nombre, seleccionada por la directiva match … action cuando se recibió el mensaje. La directiva action proporciona datos de configuración para los intentos de entrega. Las búsquedas requeridas se realizan en el momento de cada intento de entrega. En consecuencia, cambiar una directiva action o los archivos que referencia y reiniciar el demonio smtpd(8) hace que los cambios tengan efecto para los intentos de entrega posteriores del despachador correspondiente nombre, incluso para los mensajes que ya estaban atascados en la cola antes de los cambios de configuración.

El parámetro método de entrega puede ser uno de los siguientes:

expand-only
Solo acepte el mensaje si se especificó un método de entrega en un archivo de alias o .forward.
forward-only
Solo acepte el mensaje si el destinatario resulta en una dirección remota después del procesamiento de alias o archivo forward.
lmtp destino [rcpt-to]
Entregue el mensaje a un servidor LMTP en destino. La ubicación puede expresarse como host:puerto o como un socket UNIX.

Opcionalmente, se puede especificar rcpt-to para usar la dirección de correo electrónico del destinatario (después de la expansión) en lugar del usuario local en la sesión LMTP como RCPT TO.

maildir [ruta] [junk]
Entregue el mensaje al maildir en ruta si se especifica, o por defecto a ~/Maildir.

La ruta puede contener especificadores de formato que se expanden antes de usarse (ver ESPECIFICADORES DE FORMATO).

Si se proporciona el argumento junk, el mensaje se moverá a la carpeta ‘Junk’ si contiene una cabecera ‘X-Spam’ positiva. Esta carpeta se creará debajo de ruta si aún no existe.

mbox
Entregue el mensaje al mbox del usuario con mail.local(8).
mda comando
Delegue la entrega a un comando que recibe el mensaje en su entrada estándar (ver COMANDOS MDA).

El comando puede contener especificadores de formato que se expanden antes de usarse (ver ESPECIFICADORES DE FORMATO).

relay
Reenvíe el mensaje a otro servidor SMTP.

Los métodos de entrega local admiten opciones adicionales:

alias <tabla>
Use la asignación tabla para la expansión de aliases(5).
ttl n{s|m|h|d}
Especifique cuánto tiempo puede permanecer un mensaje en la cola.
user nombreusuario
Especifique el nombreusuario para realizar la entrega, para ser buscado con getpwnam(3).

Esto se utiliza para alojamiento virtual donde un solo nombre de usuario es responsable de manejar la entrega para todos los usuarios virtuales.

Esta opción no es utilizable con el método de entrega mbox.

Solo se procesará el archivo .forward del usuario de entrega.

userbase <tabla>
Use la asignación tabla para búsquedas de usuario en lugar de la función getpwnam(3).

El userbase no se aplica a la opción user.

virtual <tabla>
Use la asignación tabla para la expansión virtual. El formato de la tabla de alias se describe en table(5).
wrapper nombre
Use el envoltorio especificado en mda wrapper.

Los métodos de entrega de reenvío también admiten opciones adicionales:

backup
Opere como un intercambiador de correo de respaldo que entrega mensajes a cualquier intercambiador de correo con mayor prioridad.
backup mx nombre
Opere como un intercambiador de correo de respaldo que entrega mensajes a cualquier intercambiador de correo con mayor prioridad que el intercambiador identificado como nombre.

helo heloname
Anuncie heloname como el nombre del host a otros intercambiadores de correo durante la fase HELO.
helo-src <tabla>
Use el mapeo tabla para buscar un nombre de host que coincida con la dirección de origen, para anunciarlo durante la fase HELO.
domain <dominios>
No realice búsquedas MX, sino busque el dominio de destino en dominios y utilice la URL de retransmisión coincidente como host de retransmisión.
host url-retransmision
No realice búsquedas MX, sino retransmita los mensajes al host de retransmisión descrito por url-retransmision. El formato para url-retransmision es [proto://[etiqueta@]]host[:puerto]. Los siguientes protocolos están disponibles:
smtp
Sesión SMTP normal con STARTTLS oportunista (el predeterminado).
smtp+tls
Sesión SMTP normal con STARTTLS obligatorio.
smtp+notls
Sesión SMTP de texto plano sin TLS.
lmtp
Sesión LMTP. Se requiere puerto.
smtps
Sesión SMTP con TLS forzado en la conexión. El puerto predeterminado es 465.

A menos que se indique lo contrario, puerto es 25 por defecto.

La etiqueta corresponde a una entrada en una tabla de credenciales, como se documenta en table(5). Se utiliza con los protocolos “smtp+tls” y “smtps” para la autenticación. Los certificados del servidor para esos protocolos se verifican por defecto.

pki nombrepki
Para conexiones seguras, use el certificado asociado con nombrepki (declarado en una directiva pki) para probar la identidad del cliente al servidor de correo remoto.
srs
Al retransmitir un correo resultante de un reenvío, use el Esquema de Reescritura del Remitente (Sender Rewriting Scheme) para reescribir la dirección del remitente.
tls [no-verify]
Requerir el uso de TLS al retransmitir, usando STARTTLS obligatorio por defecto. Cuando se usa con un smarthost, el protocolo no debe ser “smtp+notls://”. Si se especifica no-verify, no se requerirá un certificado válido.
protocols cadena-protocolos
Defina las versiones de protocolo que se utilizarán para las sesiones TLS. Consulte la página del manual tls_config_parse_protocols(3) para conocer el formato de cadena-protocolos.
ciphers cadena-cifrado
Defina la lista de cifrados que pueden utilizarse para las sesiones TLS. Consulte la página del manual tls_config_set_ciphers(3) para conocer el formato de cadena-cifrado.
auth <tabla>
Use el mapeo tabla para conectarse a url-retransmision usando credenciales. Esta opción solo es utilizable con la opción host. El formato de la tabla de credenciales se describe en table(5).
mail-from direccion-correo
Use direccion-correo como la dirección MAIL FROM dentro de la transacción SMTP.
src direccion-origen | <direccion-origen>
Use la cadena o tabla de listas direccion-origen para la dirección IP de origen, lo cual es útil en máquinas con múltiples interfaces. Si la lista contiene más de una dirección, todas ellas se utilizan de tal manera que el tráfico se enruta de la forma más eficiente posible.
admd id-servicio-autenticacion
El Dominio de Gestión Administrativa al que pertenece este servidor de correo. El id-servicio-autenticacion se reenviará a los filtros usándolo para identificar o marcar las cabeceras de results-autenticacion. Si se omite, por defecto será el nombre del servidor.
bounce warn-interval retraso [, retraso ...]
Envía mensajes de advertencia al remitente del sobre cuando fallos temporales de entrega causan que un mensaje permanezca en la cola durante más tiempo del especificado en retraso. Cada parámetro retraso consiste en un entero decimal positivo y una unidad s, m, h o d. Se pueden especificar como máximo cuatro parámetros retraso. El valor predeterminado es "bounce warn-interval 4h", que envía una única advertencia después de cuatro horas.
ca caname cert archivo-ca
Asocia el archivo de certificado de la Autoridad de Certificación (CA) archivo-ca con la entrada de CA caname. La entrada de CA puede ser referenciada en las reglas de listen on y action ... relay.
filter nombre-cadena chain {nombre-filtro [, ...]}
Registra una cadena de filtros nombre-cadena, que consiste en los filtros listados en nombre-filtro. Los filtros en una cadena de filtros se ejecutan en orden de declaración para cada fase para la que están registrados. Una cadena de filtros puede ser usada en lugar de un filtro para cualquier directiva excepto para las cadenas de filtros mismas.
filter nombre-filtro phase nombre-fase match condiciones decisión
Registra un filtro nombre-filtro. Una decisión sobre qué hacer con el correo se toma en la fase nombre-fase al coincidir con las condiciones. Las fases, las condiciones de coincidencia y las decisiones se describen en MAIL FILTERING, más abajo.
filter nombre-filtro proc nombre-proceso
Registra el filtro de "proc" nombre-filtro respaldado por el proceso nombre-proceso.
filter nombre-filtro proc-exec comando
Registra y ejecuta el filtro de "proc" nombre-filtro desde el comando, de acuerdo con la API de smtpd-filters(7). Si comando comienza con una barra, se ejecuta con una ruta absoluta, de lo contrario se ejecutará desde “/usr/lib/smtpd/opensmtpd”.
include "ruta-archivo"
Reemplaza esta directiva con el contenido del archivo de configuración adicional en la ruta-archivo absoluta.
listen on interfaz [familia] [opciones]
Escucha en la interfaz para conexiones entrantes, usando la misma sintaxis que ifconfig(8). El parámetro interfaz también puede ser un grupo de interfaces, una dirección IP o un nombre de dominio. La escucha puede ser restringida opcionalmente a una familia de direcciones específica, que puede ser inet4 o inet6.

Las opciones son las siguientes:

auth [<tabla-autenticacion>]
Soporta SMTPAUTH: los clientes solo pueden iniciar transacciones SMTP después de una autenticación exitosa. Los usuarios se autentican contra sus propias credenciales de inicio de sesión normales o contra una tabla de credenciales tabla-autenticacion, cuyo formato se describe en table(5).
auth-optional [<tabla-autenticacion>]
Soporta SMTPAUTH opcionalmente: los clientes no necesitan autenticarse, pero pueden hacerlo. Esto permite que una directiva listen on acepte tanto correo entrante de remitentes no confiables como permita correo saliente de usuarios autenticados (usando match auth). Puede ser utilizada en situaciones donde no es posible escuchar en un puerto separado (generalmente el puerto de envío, 587) para que los usuarios se autentiquen.
ca caname

ca caname
Para conexiones seguras, utiliza el certificado CA asociado con caname (declarado en una directiva ca) como certificado CA al verificar certificados de cliente.
filter name
Aplica el filtro name en las conexiones manejadas por este listener.
hostname hostname
Utiliza hostname en el banner de saludo en lugar del nombre de servidor predeterminado.
hostnames <names>
Anula el nombre del servidor para direcciones específicas. La tabla names contiene un mapeo de direcciones IP a nombres de host. Si la dirección en la que llega la conexión aparece en el mapeo, se utiliza el nombre de host asociado.
mask-src
Omite la parte from al anteponer las cabeceras "Received".
no-dsn
Deshabilita la extensión DSN (Delivery Status Notification).
pki pkiname
Para conexiones seguras, utiliza el certificado asociado con pkiname (declarado en una directiva pki) para probar la identidad de un servidor de correo. Esta opción puede usarse varias veces para proporcionar certificados alternativos para SNI.
port [port]
Escucha en el puerto port dado en lugar del puerto predeterminado 25.
proxy-v2
Soporta el protocolo PROXYv2, reescribiendo apropiadamente la dirección de origen recibida del proxy.
received-auth
En las cabeceras "Received", informa si la sesión fue autenticada y por qué usuario local.
senders <users> [masquerade]
Busca el usuario autenticado en la tabla de mapeo users para encontrar las direcciones de correo electrónico que ese usuario tiene permitido enviar. Además, si se proporciona la opción masquerade, la cabecera From se reescribe para que coincida con el remitente proporcionado en la sesión SMTP.
smtps [verify]
Soporta SMTPS, por defecto en el puerto 465. Mutuamente excluyente con tls. Con la opción verify, los clientes también deben proporcionar un certificado válido para establecer una sesión SMTP.
tag tag
Los clientes que se conectan al listener son etiquetados con la etiqueta dada tag.
tls
Soporta STARTTLS, por defecto en el puerto 25. Mutuamente excluyente con smtps.
tls-require [verify]
Similar a tls, pero fuerza a los clientes a establecer una conexión segura antes de permitirles iniciar una transacción SMTP. Con la opción verify, los clientes también deben proporcionar un certificado válido para establecer una sesión SMTP.
protocols protostr
Define las versiones de protocolo a utilizar para las sesiones TLS. Consulte la página del manual tls_config_parse_protocols(3) para conocer el formato de protostr.
ciphers cipherstr
Define la lista de cifradores que pueden utilizarse para las sesiones TLS. Consulte la página del manual tls_config_set_ciphers(3) para conocer el formato de cipherstr.
listen on socket [options]
Escucha las conexiones SMTP entrantes en el socket de dominio Unix /run/smtpd.sock. Esto se hace por defecto, incluso si la directiva está ausente.

Las options son las siguientes:

filter name
Aplica el filtro name en las conexiones manejadas por este listener.
mask-src
Omite la parte from al anteponer las cabeceras "Received".
no-dsn
Deshabilita la extensión DSN (Delivery Status Notification).
tag tag
Los clientes que se conectan al listener son etiquetados con la etiqueta dada tag.
match options action name
Si al menos un sobre de correo coincide con las options de una directiva match action, recibe el mensaje entrante, pone una copia en cada sobre coincidente y guarda atómicamente los sobres en el spool de correo para su posterior procesamiento por el dispatcher name respectivo, que debe declararse de antemano con la directiva action.

Las siguientes opciones de coincidencia son compatibles y todas pueden ser negadas:

[!] for any
Especifica que la sesión puede dirigir cualquier destino.
[!] for local
Especifica que la sesión puede dirigir cualquier dominio local. Este es el valor predeterminado y puede omitirse.
[!] for domain [regex] domain | <domain>
Especifica que la sesión puede dirigir la cadena o tabla de listas domain. La palabra clave regex es requerida si domain es una expresión regular o tabla de expresiones regulares.
[!] for rcpt-to [regex] recipient | <recipient>
Especifica que la sesión puede dirigir la cadena o tabla de listas recipient. La palabra clave regex es requerida si recipient es una expresión regular o tabla de expresiones regulares.
[!] from any
Especifica que la sesión puede originarse desde cualquier fuente.
[!] from auth
Especifica que la sesión puede originarse desde cualquier usuario autenticado, sin importar la dirección IP de origen.
[!] from auth [regex] user | <user>
Especifica que la sesión puede originarse desde el usuario autenticado o lista de usuarios user, sin importar la dirección IP de origen. La palabra clave regex es requerida si user es una expresión regular o tabla de expresiones regulares.
[!] from local
Especifica que la sesión solo puede originarse desde una dirección IP local, o desde el encolador local. Este es el valor predeterminado y puede omitirse.
[!] from mail-from [regex] sender | <sender>
Especifica que la sesión puede originarse desde el remitente o lista de remitentes sender, sin importar la dirección IP de origen. La palabra clave regex es requerida si sender es una expresión regular o tabla de expresiones regulares.
[!] from rdns
Especifica que la sesión solo puede originarse desde una dirección IP que resuelva a un DNS inverso.
[!] from rdns [regex] hostname | <hostname>
Especifica que la sesión solo puede originarse desde una dirección IP que resuelva a un DNS inverso que coincida con la cadena o tabla de listas hostname. La palabra clave regex es requerida si hostname es una expresión regular o tabla de expresiones regulares.
[!] from socket
Especifica que la sesión solo puede originarse desde el encolador local.
[!] from src [regex] address | <address>
Especifica que la sesión solo puede originarse desde la cadena o tabla de listas address, que puede ser una dirección específica o una subred expresada en notación CIDR. La palabra clave regex es requerida si address es una expresión regular o tabla de expresiones regulares.

Adicionalmente, las siguientes opciones de transacción pueden ser coincidentes:

[!] auth
Especifica que la sesión debe estar autenticada.
Coincide con transacciones que han sido autenticadas.
[!] auth [regex] username | <username>
Coincide con transacciones que han sido autenticadas para el usuario o lista de usuarios username. La palabra clave regex es requerida si username es una expresión regular o una tabla de expresiones regulares.
[!] helo [regex] helo-name | <helo-name>
Especifica que el HELO / EHLO de la sesión debe coincidir con la cadena o tabla de listas helo-name. La palabra clave regex es requerida si helo-name es una expresión regular o una tabla de expresiones regulares.
[!] mail-from [regex] sender | <sender>
Especifica que el MAIL FROM de la transacción debe coincidir con la cadena o tabla de listas sender. La palabra clave regex es requerida si sender es una expresión regular o una tabla de expresiones regulares.
[!] rcpt-to [regex] recipient | <recipient>
Especifica que el RCPT TO de la transacción debe coincidir con la cadena o tabla de listas recipient. La palabra clave regex es requerida si recipient es una expresión regular o una tabla de expresiones regulares.
[!] tag [regex] tag
Coincide con transacciones etiquetadas con el tag dado. La palabra clave regex es requerida si tag es una expresión regular.
[!] tls
Especifica que la transacción debe tener lugar en un canal TLS.
match options reject
Rechaza el mensaje entrante durante el diálogo SMTP. Se admiten las mismas options que para la directiva match action.
mda wrapper name command
Asocia command con el envoltorio del agente de entrega de correo llamado name. Cuando una entrega local especifica un envoltorio, se ejecutará el command asociado con el envoltorio. El comando puede contener especificadores de formato (ver FORMAT SPECIFIERS).
mta max-deferred number
Cuando la entrega a un host dado se suspende debido a fallos temporales, almacena en caché como máximo number sobres para ese host, de modo que puedan ser entregados tan pronto como otra entrega tenga éxito a ese host. El valor predeterminado es 100.
pki pkiname cert certfile
Asocia el archivo de certificado certfile con la entrada pki pkiname. La entrada pki define una configuración de par de claves que puede ser referenciada en las reglas de escucha y acciones de retransmisión.

Se puede crear una cadena de certificados añadiendo uno o varios certificados, incluido un certificado de Autoridad Certificadora, a certfile. La creación de certificados se documenta en starttls(8).

pki pkiname key keyfile
Asocia la clave ubicada en keyfile con la entrada pki pkiname.
pki pkiname dhe params
Especifica los parámetros DHE a usar para los conjuntos de cifrado DHE con la entrada pki pkiname. Los valores de parámetros válidos son none, legacy y auto. Para legacy, se usa una longitud de clave fija de 1024 bits, mientras que para auto, la longitud de clave se determina automáticamente. El valor predeterminado es none, que deshabilita los conjuntos de cifrado DHE.
proc proc-name command
Registra un proceso externo llamado proc-name desde command, conforme a la API de smtpd-filters(7). Dichos procesos pueden usarse para compartir la misma instancia entre múltiples filtros. Si command comienza con una barra, se ejecuta con una ruta absoluta; de lo contrario, se ejecutará desde “/usr/lib/smtpd/opensmtpd”.
queue compression
Almacena los archivos de cola en formato comprimido. Esto puede ser útil para ahorrar espacio en disco.
queue encryption [key]
Cifra los archivos de cola con EVP_aes_256_gcm(3). Si no se especifica key, se lee con getpass(3). Si se proporciona la cadena stdin o un solo guion (‘-’) en lugar de una key, la clave se lee de la entrada estándar.
queue ttl delay
Establece el tiempo de expiración predeterminado para los mensajes temporalmente no entregables, dado como un entero decimal positivo seguido de una unidad s, m, h o d. El valor predeterminado es cuatro días (4d).
smtp ciphers control
Establece la cadena de control para SSL_CTX_set_cipher_list(3). El valor predeterminado es "HIGH:!aNULL:!MD5".
smtp limit max-mails count
Limita el número de mensajes a count para cada sesión. El valor predeterminado es 100.
smtp limit max-rcpt count
Limita el número de destinatarios a count para cada transacción. El valor predeterminado es 1000.
smtp max-message-size size
Rechaza mensajes más grandes que size, dado como un número positivo de bytes o como una cadena para ser analizada con scan_scaled(3). El valor predeterminado es "35M".
smtp sub-addr-delim character
Al resolver la parte local de una dirección de correo electrónico local, ignora el carácter ASCII character y todos los caracteres posteriores. El valor predeterminado es ‘+’.
srs key [backup] secret
Establece la clave secreta a utilizar para SRS, el Esquema de Reesritura de Remitentes. La opción backup puede ser especificada para establecer una clave secreta a usar como respaldo para SRS; esto se puede usar para implementar la rotación de claves SRS.
srs ttl delay
Establece el retraso de tiempo de vida (time-to-live) para los sobres SRS. Después de este retraso, se descartará una respuesta de rebote a la dirección SRS para limitar los riesgos de direcciones falsificadas. El valor predeterminado es cuatro días (4d).
table name [type:]pathname
Las tablas proporcionan información de configuración adicional para smtpd(8) en forma de listas o mapeos de clave-valor. El formato de las entradas depende de para qué se utiliza la tabla. Consulte table(5) para la documentación exhaustiva.

Cada tabla se identifica por un name arbitrario y único.

Si el type es db, la información se almacena en un archivo creado con makemap(8); si es file o se omite, la información se almacena en un archivo de texto plano utilizando el formato descrito en table(5). La pathname del archivo debe ser absoluta.

table name {value [, ...]}
En lugar de usar un archivo separado, declare una tabla de lista que contenga los values estáticos dados. La tabla debe contener al menos un valor y puede declarar múltiples valores como una lista separada por comas (con espacios opcionales).
table name {key=value [, ...]}
En lugar de usar un archivo separado, declare una tabla de mapeo que contenga los pares key-value estáticos dados. La tabla debe contener al menos un par clave-valor y puede declarar múltiples pares como una lista separada por comas (con espacios opcionales).

FILTRADO DE CORREO

En un flujo de trabajo regular, smtpd(8) puede aceptar o rechazar un mensaje basándose únicamente en el contenido de los sobres. Sus decisiones se refieren al manejo del mensaje, no al manejo de una sesión activa.

El filtrado amplía el proceso de toma de decisiones al permitir que smtpd(8) se detenga en cada fase de una sesión SMTP, verifique que se cumplan las condiciones y luego decida si se permite que la sesión avance.

Con el filtrado, una sesión puede interrumpirse en cualquier fase antes de que se complete un sobre. Un mensaje también puede ser rechazado después de ser enviado, independientemente de si el sobre fue aceptado o no.

Las siguientes fases son compatibles actualmente:

connect al conectarse, antes de que se muestre un banner
helo después de enviar el comando HELO
ehlo después de enviar el comando EHLO
mail-from después de enviar el comando MAIL FROM
rcpt-to después de enviar el comando RCPT TO
data después de enviar el comando DATA
commit después de que el mensaje se ha enviado por completo

En cada fase, se pueden hacer coincidir varias condiciones. Los datos fcrdns, rdns y src están disponibles en todas las fases, pero otros datos deben haberse enviado previamente para que estén disponibles.

fcrdns DNS inverso confirmado hacia adelante es válido
rdns la sesión tiene un DNS inverso
rdns <tabla> la sesión tiene un DNS inverso en la tabla
src <tabla> la dirección de origen está en la tabla
helo <tabla> el nombre helo está en la tabla
auth la sesión está autenticada
auth <tabla> el nombre de usuario de la sesión está en la tabla
mail-from <tabla> la dirección del remitente está en la tabla
rcpt-to <tabla> la dirección del destinatario está en la tabla

Todas estas condiciones pueden ser negadas prefijándolas con un signo de exclamación:

!fcrdns DNS inverso confirmado hacia adelante es inválido

Cualquier condición que utilice una tabla puede indicar que la tabla contiene expresiones regulares prefijando el nombre de la tabla con la palabra clave regex.

helo regex <tabla> el nombre helo coincide con una regex en la tabla

Finalmente, se pueden tomar varias decisiones:

bypass la sesión o transacción omite los filtros
disconnect mensaje la sesión se desconecta con el mensaje
junk la sesión o transacción se marca como basura, es decir, se añade una cabecera ‘X-Spam: yes’ a cualquier mensaje
reject mensaje el comando se rechaza con el mensaje
rewrite valor el parámetro del comando se reescribe con el valor

Las decisiones que involucran un mensaje requieren que el mensaje sea válido según RFC, lo que significa que deben comenzar con un código de estado 4xx o 5xx. Las decisiones se pueden tomar en cualquier fase, aunque la marca de basura solo puede ocurrir antes de que se confirme un mensaje.

ESPECIFICADORES DE FORMATO

Algunas directivas de configuración admiten la expansión de sus parámetros en tiempo de ejecución. Dichas directivas (por ejemplo action maildir, action mda) pueden usar especificadores de formato que se expanden antes de la entrega o el reenvío. Los siguientes formatos son compatibles actualmente:

%{sender} dirección de correo electrónico del remitente, puede ser una cadena vacía
%{sender.user} parte del usuario de la dirección de correo electrónico del remitente, puede estar vacía
%{sender.domain} parte del dominio de la dirección de correo electrónico del remitente, puede estar vacía
%{rcpt} dirección de correo electrónico del destinatario
%{rcpt.user} parte del usuario de la dirección de correo electrónico del destinatario
%{rcpt.domain} parte del dominio de la dirección de correo electrónico del destinatario
%{dest} dirección de correo electrónico del destinatario después de la expansión
%{dest.user} parte del usuario después de la expansión
%{dest.domain} parte del dominio después de la expansión
%{user.username} usuario local
%{user.directory} directorio de inicio del usuario local
%{mbox.from} nombre utilizado en las líneas separadoras de mbox From
%{mda} comando mda, solo disponible para envolturas mda

Los formatos de expansión también admiten expansión parcial utilizando las notaciones de corchetes opcionales con desplazamiento de subcadena. Por ejemplo, con el dominio del destinatario “example.org”:

%{rcpt.domain[0]} se expande a “e”
%{rcpt.domain[1]} se expande a “x”
%{rcpt.domain[8:]} se expande a “org”
%{rcpt.domain[-3:]} se expande a “org”
%{rcpt.domain[0:6]} se expande a “example”
%{rcpt.domain[0:-4]} se expande a “example”

Además, se pueden aplicar modificadores al token. Por ejemplo, con el destinatario “User+Tag@Example.org”:

%{rcpt:lowercase} se expande a “user+tag@example.org”
%{rcpt:uppercase} se expande a “USER+TAG@EXAMPLE.ORG”
%{rcpt:strip} se expande a “User@Example.org”
%{rcpt:lowercase|strip} se expande a “user@example.org”

Por motivos de seguridad, los valores expandidos se sanitizan y los caracteres potencialmente peligrosos se reemplazan por ‘:’. En situaciones en las que sean deseables, se puede aplicar el modificador “raw”. Por ejemplo, con el destinatario “user+t?g@example.org”:

%{rcpt} se expande a “user+t:g@example.org”
%{rcpt:raw} se expande a “user+t?g@example.org”

COMANDOS MDA

Cuando un método de entrega de acción es mda, smtpd(8) ejecuta el comando asociado para la entrega con el contenido del correo proporcionado a través de la entrada estándar. Se espera que el comando lea todo el contenido del correo.

El código de salida del comando informa el resultado de la entrega: el estado 0 (EX_OK) es una entrega exitosa; los estados 71 (EX_OSERR) y 75 (EX_TEMPFAIL) son fallos temporales; y todos los demás estados de salida se consideran fallos permanentes.

Las siguientes variables de entorno se establecen:

DOMAIN
El dominio del destinatario.
EXTENSION
La subdirección del destinatario (puede no estar definida).
HOME
El directorio de inicio del usuario de entrega.
LOCAL
La parte local de la dirección del usuario destinatario.
LOGNAME
El nombre de inicio de sesión del usuario.
ORIGINAL_RECIPIENT
La dirección del destinatario original.
PATH
Establecido a _PATH_DEFPATH. Tradicionalmente /usr/bin:/bin, pero expandido para incluir /usr/sbin, /sbin, /usr/X11R6/bin, /usr/local/bin, y /usr/local/sbin en OpenBSD.
RECIPIENT
La dirección del destinatario final.
SENDER
La dirección del remitente (puede estar vacía).
SHELL
Establecido a /bin/sh.
USER
Sinónimo de LOGNAME por compatibilidad hacia atrás.

ARCHIVOS

/etc/smtpd/smtpd.conf
Archivo de configuración predeterminado de smtpd(8).
/etc/smtpd/mailname
Si este archivo existe, la primera línea se utiliza como nombre del servidor. De lo contrario, el nombre del servidor se deriva del nombre de host local devuelto por gethostname(3), ya sea directamente si es un nombre de dominio completamente calificado, o recuperando el nombre canónico asociado a través de getaddrinfo(3).
/run/smtpd.sock
Socket de dominio Unix para conexiones SMTP entrantes.
/var/spool/smtpd/
Directorios de cola para el correo durante el procesamiento.

EJEMPLOS

El archivo smtpd.conf predeterminado que se incluye con OpenBSD escucha en la interfaz de red de bucle local (lo0) y permite el correo de usuarios y daemons en la máquina local, además de permitir el correo a servidores remotos. A continuación, se muestran algunas configuraciones más complejas.

Este primer ejemplo es similar a la configuración predeterminada, pero todo el correo saliente se reenvía a un servidor SMTP remoto. Se necesita un archivo de secretos para especificar un nombre de usuario y una contraseña:

# touch /etc/smtpd/secrets
# chmod 640 /etc/smtpd/secrets
# chown root:smtpd /etc/smtpd/secrets
# echo "bob nombredeusuario:contraseña" > /etc/smtpd/secrets

smtpd.conf se vería así:

table aliases file:/etc/smtpd/aliases
table secrets file:/etc/smtpd/secrets

listen on lo0

action "local_mail" mbox alias <aliases>
action "outbound" relay host smtp+tls://bob@smtp.example.com \
	auth <secrets>

match from local for local action "local_mail"
match from local for any action "outbound"

En este segundo ejemplo, el objetivo es permitir la entrega de correo y el reenvío solo para usuarios que puedan autenticarse (utilizando sus credenciales de inicio de sesión normales). Se debe proporcionar un certificado RSA para demostrar la identidad del servidor. El servidor de correo escucha en todas las interfaces a las que apuntan las rutas predeterminadas. El correo con destino local se envía a un MDA externo. Primero, se crea el certificado RSA:

# openssl genrsa -out /etc/ssl/private/mail.example.com.key 4096
# openssl req -new -x509 -key /etc/ssl/private/mail.example.com.key \
	-out /etc/ssl/mail.example.com.crt -days 365
# chmod 600 /etc/ssl/mail.example.com.crt
# chmod 600 /etc/ssl/private/mail.example.com.key

En el ejemplo anterior, se creó un certificado válido por un año. El archivo de configuración se vería así:

pki mail.example.com cert "/etc/ssl/mail.example.com.crt"
pki mail.example.com key "/etc/ssl/private/mail.example.com.key"

table aliases file:/etc/smtpd/aliases

listen on lo0
listen on egress tls pki mail.example.com auth

action mda_with_aliases mda "/path/to/mda -f -" alias <aliases>
action mda_without_aliases mda "/path/to/mda -f -"
action "outbound" relay

match for local action mda_with_aliases
match from any for domain example.com action mda_without_aliases
match for any action "outbound"
match auth from any for any action "outbound"

Para los sitios que desean firmar mensajes usando DKIM, el siguiente ejemplo utiliza opensmtpd-filter-dkimsign para la firma DKIM:

table aliases file:/etc/smtpd/aliases

filter "dkimsign" proc-exec "filter-dkimsign -d <dominio> -s <selector> \
	-k /etc/smtpd/dkim/private.key" user _dkimsign group _dkimsign

listen on socket filter "dkimsign"
listen on lo0 filter "dkimsign"

action "local_mail" mbox alias <aliases>
action "outbound" relay

match for local action "local_mail"
match for any action "outbound"

Alternativamente, se puede usar el paquete opensmtpd-filter-rspamd para proporcionar integración con rspamd, un demonio de terceros que proporciona múltiples funciones antispam, así como firma DKIM. Además de configurar el propio rspamd, requiere el uso de la palabra clave proc-exec:

filter "rspamd" proc-exec "filter-rspamd"

Los sitios que aceptan mensajes no locales pueden reducir el volumen de spam recibido rechazando mensajes falsificados que afirman ser del dominio local. El siguiente ejemplo utiliza una tabla de listas other-relays para especificar las direcciones IP de los retransmisores que pueden originar legítimamente correo con el dominio del propietario como remitente.

table aliases file:/etc/smtpd/aliases
table other-relays file:/etc/smtpd/other-relays

listen on lo0
listen on egress

action "local_mail" mbox alias <aliases>
action "outbound" relay

match for local action "local_mail"
match for any action "outbound"
match !from src <other-relays> mail-from "@example.com" for any \
      reject
match from any for domain example.com action "local_mail"
