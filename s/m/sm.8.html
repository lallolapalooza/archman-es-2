SM(8) Documentación de InterNetNews SM(8)

NOMBRE

sm - Interfaz de línea de comandos para el gestor de almacenamiento de INN

SINOPSIS

sm [-cdHiqRrSs] [token ...]

DESCRIPCIÓN

El gestor de almacenamiento de INN es el subsistema que almacena y rastrea todos los artículos y el backend de almacenamiento en el que se encuentran. A todos los artículos almacenados se les asigna un token de la API de almacenamiento. sm es una interfaz de línea de comandos para ese gestor de almacenamiento, utilizada principalmente para recuperar artículos por esos tokens, pero también para realizar otras operaciones en el subsistema de almacenamiento.

token es el token de un artículo (lo mismo que devuelve grephistory o que se almacena en el archivo history). Tiene un aspecto similar a:

@0502000005A4000000010000000000000000@

Se puede proporcionar cualquier número de tokens en la línea de comandos para cualquier función que no sea -s. Si no hay ninguno, sm normalmente lee tokens de la entrada estándar, uno por línea. La operación predeterminada es recuperar y escribir en la salida estándar el artículo correspondiente para cada token proporcionado.

Si se proporciona -s, sm en su lugar almacena el artículo proporcionado en la entrada estándar (en formato nativo, a menos que se proporcione -R, en cuyo caso se espera formato de cable) usando las reglas estándar del subsistema de almacenamiento. Si el artículo se almacena con éxito, el token del artículo se imprime en la salida estándar. Tenga en cuenta que esto no intenta escribir una entrada de historial ni ningún dato de resumen, y por lo tanto, solo es útil en circunstancias muy específicas.

OPCIONES

-c
Muestra una forma clara y decodificada del token de la API de almacenamiento. Cada parte del token se explica en una cadena legible por humanos. Entre otros elementos, este comando proporciona la ruta a donde se supone que se almacenará el artículo correspondiente.
-d, -r
En lugar de recuperar el artículo especificado, elimina el artículo. Esto eliminará el artículo del news spool y no podrá recuperarse posteriormente por ninguna parte de INN. Es equivalente a "ctlinnd cancel", excepto que toma un token de la API de almacenamiento en lugar de un ID de mensaje.
-H
Recupera solo las cabeceras del artículo en lugar del artículo completo. Esta opción no se puede usar con -d, -r, -i o -S.
-i
Muestra el nombre del grupo de noticias y el número de artículo asociados con el token en lugar del artículo en sí. Tenga en cuenta que para los artículos cruzados, solo se devolverá el primer grupo de noticias y número de artículo con el que se asocia el artículo.
-q
Suprime todos los mensajes de error, excepto los de error de uso.
-R
Muestra el artículo sin procesar. Esto significa que los finales de línea no se convertirán a los finales de línea nativos y se dejarán como secuencias CRLF; los puntos iniciales seguirán siendo escapados para enviarlos a través de NNTP, y el artículo terminará en una secuencia CRLF.CRLF.

Cuando se usa con -s, lee artículos en formato de cable.

-S
Escribe el artículo en la salida estándar en el formato utilizado por los archivos de spool de rnews. Se pueden escribir varios artículos en este formato, y la salida resultante se puede alimentar a rnews (en otro sistema, por ejemplo) para inyectar esos artículos en INN. Esta opción no se puede usar con -d, -r, -H, -i o -R.
-s
Almacena el artículo proporcionado en la entrada estándar usando las reglas de almacenamiento normales para artículos, según lo configurado en storage.conf(5). Imprime el nuevo token para el mensaje en la salida estándar si se almacena con éxito. Si se proporciona esta opción, no se deben proporcionar otras opciones excepto -R y posiblemente -q. Cuando se proporciona -R, se leen y almacenan cualquier número de artículos en formato de cable en la entrada estándar.

ESTADO DE SALIDA

Si todas las operaciones fueron exitosas, sm sale con estado 0. Si una operación en cualquiera de los tokens proporcionados falla, sm saldrá con estado 1, incluso si las operaciones en otros tokens fueron exitosas. En otras palabras, si veinte tokens se alimentan a "sm -r" en stdin, 19 artículos fueron eliminados con éxito, pero el sexto artículo no pudo ser encontrado, sm aún así saldrá con estado 1.

Esto significa que si necesita estar seguro de si una operación particular tuvo éxito, debe ejecutar sm en un token a la vez.
