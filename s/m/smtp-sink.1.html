SMTP-SINK(1) Manual de Comandos Generales SMTP-SINK(1)

NOMBRE

smtp-sink - servidor de prueba SMTP/LMTP paralelizado

SINOPSIS

smtp-sink [opciones] [inet:][host]:puerto cola

smtp-sink [opciones] unix:ruta_acceso cola

DESCRIPCIÓN


smtp-sink escucha en el host (o dirección) y puerto especificados. Recibe mensajes SMTP de la red y los descarta. El propósito es medir el rendimiento del cliente, no el cumplimiento del protocolo.

smtp-sink también puede configurarse para capturar cada transacción de entrega de correo en un archivo. Dado que la latencia del disco es grande en comparación con los retrasos de red, este modo de operación puede reducir el rendimiento máximo en varios órdenes de magnitud.

Las conexiones pueden ser aceptadas en puntos finales IPv4 o IPv6, o en sockets de dominio UNIX. IPv4 e IPv6 son los predeterminados. Este programa es el complemento del programa smtp-source(1).

Nota: este es un programa de prueba no soportado. No se hace ningún intento por mantener la compatibilidad entre versiones sucesivas.

Argumentos:

-4
Soporte solo para IPv4. Esta opción no tiene efecto cuando Postfix está compilado sin soporte IPv6.
-6
Soporte solo para IPv6. Esta opción no está disponible cuando Postfix está compilado sin soporte IPv6.
-8
No anunciar soporte 8BITMIME.
-a
No anunciar soporte de autenticación SASL.
-A retraso
Esperar retraso segundos después de responder a DATA, luego abortar prematuramente con un estado de respuesta 550. No leer más entrada del cliente; este es un intento de bloquear al cliente antes de que envíe ".". Especificar un valor de retraso cero para abortar inmediatamente.
-b respuesta-rebote-suave
Usar respuesta-rebote-suave para respuestas de rechazo suave. La respuesta predeterminada es "450 4.3.0 Error: comando fallido".
-B respuesta-rebote-duro
Usar respuesta-rebote-duro para respuestas de rechazo duro. La respuesta predeterminada es "500 5.3.0 Error: comando fallido".
-c
Mostrar contadores en ejecución que se actualizan cada vez que finaliza una sesión SMTP, se ejecuta un comando QUIT, o cuando se recibe ".".
-C
Deshabilitar soporte XCLIENT.
-d plantilla-volcado
Volcar cada transacción de correo a un archivo de mensaje único cuyo nombre se crea expandiendo la plantilla-volcado a través de strftime(3) y añadiendo un número hexadecimal pseudoaleatorio (ejemplo: "%Y%m%d%H/%M." se expande a "2006081203/05.809a62e3"). Si la plantilla contiene caracteres "/", se crean directorios faltantes automáticamente. El formato del volcado del mensaje se describe a continuación.

Nota: esta opción mantiene un archivo de captura abierto por cada transacción de correo en progreso.

-D plantilla-volcado
Añadir transacciones de correo a un archivo de volcado de múltiples mensajes cuyo nombre se crea expandiendo la plantilla-volcado a través de strftime(3). Si la plantilla contiene caracteres "/", se crean directorios faltantes automáticamente. El formato del volcado del mensaje se describe a continuación.

Nota: esta opción mantiene un archivo de captura abierto por cada transacción de correo en progreso.

-e
No anunciar soporte ESMTP.
-E
No anunciar soporte ENHANCEDSTATUSCODES.
-f comando,comando,...
Rechazar los comandos especificados con un código de error duro (5xx). Esta opción implica -p.

Ejemplos de comandos son CONNECT, HELO, EHLO, LHLO, MAIL, RCPT, VRFY, DATA, ., RSET, NOOP, y QUIT. Separe los nombres de comando por espacios en blanco o comas, y use comillas para proteger los espacios en blanco del shell. Los nombres de comando no distinguen entre mayúsculas y minúsculas.

-F
Deshabilitar soporte XFORWARD.
-h nombre-host
Usar nombre-host en el saludo SMTP, en la respuesta HELO y en la respuesta EHLO. El nombre-host predeterminado es "smtp-sink".
-H retraso
Retrasar la primera operación de lectura después de recibir DATA (tiempo en segundos). Combinar con un mensaje de prueba grande y un tamaño de ventana TCP pequeño (ver la opción -T) para probar la implementación write_wait() del cliente Postfix.
-L
Habilitar LMTP en lugar de SMTP.
-m cantidad (predeterminado: 256)
Un límite superior en la cantidad máxima de conexiones simultáneas que smtp-sink manejará. Esto evita que el proceso se quede sin descriptores de archivo. Las conexiones excedentes permanecerán en cola en la pila TCP/IP.
-M cantidad
Terminar después de recibir cantidad mensajes.
-n cantidad
Terminar después de cantidad sesiones.
-N
No anunciar soporte para DSN.
-p
No anunciar soporte para el pipelining de comandos ESMTP.
-P
Cambiar el saludo del servidor para que parezca que proviene de un sistema CISCO PIX. Implica -e.
-q comando,comando,...
Desconectar (sin responder) después de recibir uno de los comandos especificados.

Ejemplos de comandos son CONNECT, HELO, EHLO, LHLO, MAIL, RCPT, VRFY, DATA, ., RSET, NOOP, y QUIT. Separe los nombres de comando por espacios en blanco o comas, y use comillas para proteger los espacios en blanco del shell. Los nombres de comando no distinguen entre mayúsculas y minúsculas.

-Q comando,comando,...
Enviar una respuesta 421 y desconectar después de recibir uno de los comandos especificados.

Ejemplos de comandos son CONNECT, HELO, EHLO, LHLO, MAIL, RCPT, VRFY, DATA, ., RSET, NOOP, y QUIT. Separe los nombres de comando por espacios en blanco o comas, y use comillas para proteger los espacios en blanco del shell. Los nombres de comando no distinguen entre mayúsculas y minúsculas.

-r comando,comando,...
Rechazar los comandos especificados con un código de error suave (4xx). Esta opción implica -p.

Ejemplos de comandos son CONNECT, HELO, EHLO, LHLO, MAIL, RCPT, VRFY, DATA, ., RSET, NOOP, y QUIT. Separe los nombres de comando por espacios en blanco o comas, y use comillas para proteger los espacios en blanco del shell. Los nombres de comando no distinguen entre mayúsculas y minúsculas.

-R directorio-raiz
Cambiar el directorio raíz del proceso a la ubicación especificada. Esta opción requiere privilegios de superusuario. Ver también la opción -u.
-s comando,comando,...
Registrar los comandos nombrados en syslogd.

Ejemplos de comandos son CONNECT, HELO, EHLO, LHLO, MAIL, RCPT, VRFY, DATA, ., RSET, NOOP, y QUIT. Separe los nombres de comando por espacios en blanco o comas, y use comillas para proteger los espacios en blanco del shell. Los nombres de comando no distinguen entre mayúsculas y minúsculas.

-S cadena-inicio
Una cadena opcional que se antepone a cada mensaje escrito en un archivo de volcado (ver la descripción del formato del archivo de volcado a continuación). Se soportan las siguientes secuencias de escape C: \a (campana), \b (retroceso), \f (avance de página), \n (nueva línea), \r (retorno de carro), \t (tabulación horizontal), \v (tabulación vertical), \ddd (hasta tres dígitos octales) y \\ (el carácter de barra invertida).
-t tiempo-espera (predeterminado: 100)
Limitar el tiempo para recibir un comando o enviar una respuesta. El límite de tiempo se especifica en segundos.
-T tamaño-ventana
Anular el tamaño de ventana TCP predeterminado. Para solucionar problemas con implementaciones de escalado de ventana TCP defectuosas, especifique un valor > 0 y < 65536.

NAME

smtp-sink — SMTP/LMTP message sink

SYNOPSIS

smtp-sink [generic_options] [-A inet_address] [-l log_level] [-R username] [-S text] [-v] [-w delay] [-W command:delay[:odds]] [inet:host:port | unix:pathname] [backlog]

DESCRIPTION

The smtp-sink command is a low-level SMTP/LMTP server. It implements the SMTP protocol and writes received messages to files. This is useful for testing SMTP clients or for capturing mail content.

The program accepts mail via the network, or via a UNIX domain socket. It logs activity and stores received messages in a directory specified by the MAILROOT environment variable (defaulting to $HOME/Maildir).

The following command-line options are available:

-A inet_address
Bind to a specific network interface address. This option is only useful when the server is started with super-user privileges and needs to bind to an address other than the default (any interface).
-l log_level
Set the logging level. Higher values mean more verbose logging. The default is 0.
-R username
Switch to the specified user privileges after opening the network socket and optionally changing the process root directory. This option is required when the process runs with super-user privileges. See also the -u option.
-S text
Prepend the specified text to the content of each dumped message. This is useful for adding arbitrary information or headers.
-u username
Switch to the specified user privileges after opening the network socket and optionally changing the process root directory. This option is required when the process runs with super-user privileges. See also the -R option.
-v
Show the SMTP conversations.
-w delay
Wait delay seconds before responding to a DATA command.
-W command:delay[:odds]
Wait delay seconds before responding to command. If odds is also specified (a number between 1-99 inclusive), wait for a random multiple of delay. The random multiplier is equal to the number of times the program needs to roll a dice with a range of 0..99 inclusive, before the dice produces a result greater than or equal to odds.
[inet:][host]:port
Listen on network interface host (default: any interface) TCP port port. Both host and port may be specified in numeric or symbolic form.
unix:pathname
Listen on the UNIX-domain socket at pathname.
backlog
The maximum length of the queue of pending connections, as defined by the listen(2) system call.

DUMP FILE FORMAT

Each dumped message contains a sequence of text lines, terminated with the newline character. The sequence of information is as follows:

  • The optional string specified with the -S option.
  • The smtp-sink generated headers as documented below.
  • The message header and body as received from the SMTP client.
  • An empty line.

The format of the smtp-sink generated headers is as follows:

X-Client-Addr: text
The client IP address without enclosing []. An IPv6 address is prefixed with "ipv6:". This record is always present.
X-Client-Proto: text
The client protocol: SMTP, ESMTP or LMTP. This record is always present.
X-Helo-Args: text
The arguments of the last HELO or EHLO command before this mail delivery transaction. This record is present only if the client sent a recognizable HELO or EHLO command before the DATA command.
X-Mail-Args: text
The arguments of the MAIL command that started this mail delivery transaction. This record is present exactly once.
X-Rcpt-Args: text
The arguments of an RCPT command within this mail delivery transaction. There is one record for each RCPT command, and they are in the order as sent by the client.
Received: text
A message header for compatibility with mail processing software. This three-line header marks the end of the headers provided by smtp-sink, and is formatted as follows:
from helo ([addr])
The HELO or EHLO command argument and client IP address. If the client did not send HELO or EHLO, the client IP address is used instead.
by host (smtp-sink) with proto id random;
The hostname specified with the -h option, the client protocol (see X-Client-Proto above), and the pseudo-random portion of the per-message capture file name.
time-stamp
A time stamp as defined in RFC 2822.
