NOMBRE

smokeping_examples - Ejemplos de configuración de Smokeping

DESCRIPCIÓN GENERAL

Este documento proporciona algunos ejemplos de archivos de configuración de Smokeping. Todos los ejemplos se encuentran en el directorio "examples" de la documentación de Smokeping. Tenga en cuenta que los nombres DNS en los ejemplos no son funcionales.

Los detalles de la sintaxis y todas las variables se encuentran en smokeping_config y en la documentación de la sonda correspondiente, si corresponde.

Este manual se genera automáticamente a partir del código fuente de Smokeping, específicamente del módulo Smokeping::Examples.

DESCRIPCIÓN

Actualmente, los ejemplos difieren solo en las secciones "Probes" y "Targets". Las otras secciones se toman de la plantilla de configuración "etc/config.dist" en la distribución de Smokeping para que los archivos de ejemplo estén completos.

Si desea proporcionar más ejemplos, documentar las otras secciones o mejorar los ejemplos existentes, hágalo, preferiblemente enviando los cambios propuestos a la lista de correo de usuarios de smokeping.

Ejemplo 1: config.simple

Configuración de la sonda
*** Probes ***
+FPing
binary = /usr/bin/fping
Explicación de la sonda
Aquí tenemos solo una sonda, fping, haciendo ping a cuatro hosts.

La sonda fping está utilizando los parámetros predeterminados, algunos de ellos suministrados desde la sección Base de Datos ("step" y "pings"), y algunos de ellos por el módulo de sonda.

Configuración del objetivo
*** Targets ***
probe = FPing

menu = Top
title = Network Latency Grapher
remark = Welcome to this SmokePing website.

+ mysite1
menu = Site 1
title = Hosts in Site 1

++ myhost1
host = myhost1.mysite1.example
++ myhost2
host = myhost2.mysite1.example

+ mysite2
menu = Site 2
title = Hosts in Site 2

++ myhost3
host = myhost3.mysite2.example
++ myhost4
host = myhost4.mysite2.example
Explicación del objetivo
Los hosts están ubicados en dos sitios de dos hosts cada uno, y la configuración se ha dividido en secciones de sitio ('+') y subsecciones de host ('++') en consecuencia.

Ejemplo 2: config.multiple-probes

Configuración de la sonda
*** Probes ***
+ FPing
binary = /usr/bin/fping
packetsize = 1000

+ DNS
binary = /usr/bin/dig
lookup = name.example
pings = 5
step = 180

+ EchoPingHttp
pings = 5
url = /test-url
Explicación de la sonda
Aquí tenemos tres sondas: FPing para los pings ICMP regulares, DNS para la medición de latencia del servidor de nombres y EchoPingHttp para servidores web.

La sonda FPing se ejecuta con los parámetros predeterminados, excepto que el tamaño del paquete ICMP es de 1000 bytes en lugar de los 56 bytes predeterminados.

Las sondas DNS y EchoPingHttp se han configurado para ser un poco más amables con los servidores, ya que solo realizan 5 consultas (pings) en lugar de las 20 predeterminadas (o lo que se especifique en la sección Base de Datos). Sin embargo, las consultas DNS se realizan con más frecuencia: 5 consultas cada 3 minutos en lugar de cada 5 minutos.

Configuración del objetivo
*** Targets ***
probe = FPing
menu = Top
title = Network Latency Grapher
remark = Welcome to this SmokePing website.

+ network
menu = Net latency
title = Network latency (ICMP pings)

++ myhost1
host = myhost1.example
++ myhost2
host = myhost2.example

+ services
menu = Service latency
title = Service latency (DNS, HTTP)

++ DNS
probe = DNS
menu = DNS latency
title = Service latency (DNS)

+++ dns1
host = dns1.example

+++ dns2
host = dns2.example

++ HTTP
menu = HTTP latency
title = Service latency (HTTP)

+++ www1
host = www1.example

+++ www2
host = www2.example
Explicación del objetivo
El árbol de objetivos se ha dividido según la sonda utilizada. Esto no tiene por qué ser así: cada sección de objetivo (sub) puede utilizar una sonda diferente, y la misma sonda puede utilizarse en diferentes partes del árbol de configuración.

Ejemplo 3: config.fping-instances

Configuración de la sonda
*** Probes ***
+ FPing
binary = /usr/bin/fping

++ FPingNormal
offset = 0%

++ FPingLarge
packetsize = 5000
offset = 50%
Explicación de la sonda
Este ejemplo demuestra el concepto de instancias de sonda. Las sondas FPingLarge y FPingNormal son independientes entre sí, solo utilizan el mismo módulo, FPing. FPingNormal utiliza los parámetros predeterminados, al igual que FPingLarge, excepto por el tamaño del paquete de 5000 bytes. Ambas utilizan la misma binario de fping, y su ruta está configurada en la sección principal de FPing.

Los parámetros 'offset' aseguran que las sondas no se ejecuten al mismo tiempo: FPingNormal se ejecuta cada 5 minutos 'completos' (es decir, 8:00, 8:05, 8:10 y así sucesivamente, en hora del reloj) mientras que FPingLarge se ejecuta a mitad de estos intervalos (es decir, 8:02:30, 8:07:30, etc.)

La sección principal FPing no define una sonda en sí misma porque tiene subsecciones. Si realmente quisiéramos tener una sonda llamada "FPing", podríamos hacerlo creando una subsección con ese nombre.

Configuración del objetivo
*** Targets ***
probe = FPingNormal
menu = Top
title = Network Latency Grapher
remark = Welcome to this SmokePing website.

+ network
menu = Net latency
title = Network latency (ICMP pings)

++ myhost1
menu = myhost1
title = ICMP latency for myhost1

+++ normal
title = Normal packetsize (56 bytes)
probe = FPingNormal
host = myhost1.example

+++ large
title = Large packetsize (5000 bytes)
probe = FPingLarge
host = myhost1.example

++ myhost2
menu = myhost2
title = ICMP latency for myhost2

+++ normal
title = Normal packetsize (56 bytes)
probe = FPingNormal
host = myhost2.example

+++ large
title = Large packetsize (5000 bytes)
probe = FPingLarge
host = myhost2.example
Explicación del objetivo
La sección de objetivos muestra dos hosts, myhost1.example y myhost2.example, a los que se les hace ping con dos paquetes ICMP de diferente tamaño. Esta vez, el árbol se divide por el host objetivo en lugar de por la sonda.

Ejemplo 4: config.targetvars-with-Curl

Configuración de la sonda
*** Probes ***
+ Curl
# probe-specific variables
binary = /usr/bin/curl
step = 60

# a default for this target-specific variable
urlformat = http://%host%/
Explicación de la sonda
Este ejemplo explica la diferencia entre variables específicas de sonda y específicas de objetivo. Usamos la sonda Curl para esto.

Cada sonda admite al menos algunas variables específicas de sonda. Los valores de estas variables son comunes a todos los objetivos de la sonda y solo se pueden configurar en la sección Probes. En este caso, las variables específicas de sonda son "binary" y "step".

La mayoría de las sondas admiten variables específicas de objetivo, siendo la excepción más notable la sonda FPing y sus derivados. Las variables específicas de objetivo pueden tener diferentes valores para diferentes objetivos. Se pueden configurar tanto en las secciones Probes como en Targets. Los valores asignados en la sección Probes se convierten en valores predeterminados que se pueden anular en la sección Targets.

La documentación de cada sonda indica cuáles de sus variables son específicas de sonda y cuáles son específicas de objetivo.

Ejemplo 4: config.http

Configuración de la sonda
*** Sondas ***
+ Curl
binary = /usr/bin/curl
options = --user-agent SmokePing/1.0
# default url is http://%host%/
Explicación de la sonda
Esto utiliza la sonda Curl para sondear la latencia HTTP. El valor por defecto para la URL es http://%host%/. Se puede especificar una URL personalizada para cada objetivo si es necesario.
Configuración del objetivo
*** Objetivos ***
probe = Curl
menu = Principal
title = Gráfica de Latencia de Red
remark = Bienvenido a este sitio web de SmokePing.

+ HTTP
menu = http
title = Latencia HTTP

++ myhost1
menu = myhost1
title = Latencia HTTP para myhost1
host = myhost1.example

++ myhost2
menu = myhost2
title = Latencia HTTP para myhost2
host = myhost2.example

++ myhost3
menu = myhost3
title = Latencia HTTP para myhost3 (¡puerto 8080!)
host = myhost3.example
urlformat = http://%host%:8080/
Explicación del objetivo
Esto define tres objetivos para sondear con la sonda Curl. Todos los objetivos usan la sonda Curl por defecto, pero el último, "myhost3.example", especifica un puerto diferente (8080) y usa la variable %host% en la cadena urlformat para construir la URL completa. La variable %host% es un marcador de posición para el nombre de host especificado para el objetivo. La variable urlformat se aplica a todos los objetivos que heredan de ella, a menos que se anule explícitamente en un objetivo hijo.

Nota: En el ejemplo anterior, el objetivo myhost3 define urlformat = http://%host%:8080/. Esto significa que la URL que se utilizará para sondear este objetivo será http://myhost3.example:8080/. La variable %host% se reemplaza por el valor de la variable host del objetivo, que en este caso es myhost3.example.

También es posible especificar una URL completa directamente, sin utilizar el marcador de posición %host%. Por ejemplo, se podría haber escrito: urlformat = http://myhost3.example:8080/. Sin embargo, incluso en ese caso, la variable host seguiría siendo necesaria, aunque no se utilizara para construir la URL. Esto se debe a que la variable host es fundamental para la estructura de los objetivos en SmokePing y se utiliza para otros fines, como la identificación y el agrupamiento de objetivos.

El uso de %host% en la variable urlformat es un caso especial y no una característica general para todas las variables de objetivo. Su uso está limitado a la variable urlformat y al código de escape %host%. La razón por la que la sonda FPing no admite variables específicas del objetivo es que el programa fping mide todos sus objetivos a la vez, por lo que todos tienen los mismos parámetros. Las otras sondas hacen ping a sus objetivos uno por uno.

Configuración del objetivo
*** Objetivos ***
probe = Curl
menu = Principal
title = Gráfica de Latencia de Red
remark = Bienvenido a este sitio web de SmokePing.

+ HTTP
menu = http
title = Latencia HTTP

++ myhost1
menu = myhost1
title = Latencia HTTP para myhost1
host = myhost1.example

++ myhost2
menu = myhost2
title = Latencia HTTP para myhost2
host = myhost2.example

++ myhost3
menu = myhost3
title = Latencia HTTP para myhost3 (¡puerto 8080!)
host = myhost3.example
urlformat = http://%host%:8080/

+ FTP
menu = ftp
title = Latencia FTP
urlformat = ftp://%host%/

++ myhost1
menu = myhost1
title = Latencia FTP para myhost1
host = myhost1.example

++ myhost2
menu = myhost2
title = Latencia FTP para myhost2
host = myhost2.example
Explicación del objetivo
El árbol de objetivos se divide en una rama HTTP y una rama FTP. Los servidores "myhost1.example" y "myhost2.example" se sondean en ambas. El tercer servidor, "myhost3.example", solo tiene un servidor HTTP y está en un puerto no estándar (8080).

La variable "urlformat" se especifica para toda la rama FTP como "ftp://%host%/". Para la rama HTTP, se utiliza el valor por defecto de la sección Sondas, excepto para myhost3, que lo anula para añadir el número de puerto a la URL.

La asignación de myhost3 podría haber incluido el nombre de host literalmente (es decir, urlformat = http://myhost3.example:8080/) en lugar de utilizar el marcador de posición %host%, pero la variable host seguiría siendo necesaria (aunque no se utilizara para nada).

Ejemplo 5: config.echoping

Configuración de la sonda
*** Sondas ***
+ FPing
binary = /usr/bin/fping

# estos esperan encontrar echoping en /usr/bin
# si no, tendrás que especificar la ubicación por separado para cada sonda
# + EchoPing         # usa echo TCP o UDP (puerto 7)
# + EchoPingDiscard  # usa discard TCP o UDP (puerto 9)
# + EchoPingChargen  # usa chargen TCP (puerto 19)
+ EchoPingSmtp       # SMTP (25/tcp) para servidores de correo
+ EchoPingHttps      # HTTPS (443/tcp) para servidores web
+ EchoPingHttp       # HTTP (80/tcp) para servidores web y cachés
+ EchoPingIcp        # ICP (3130/udp) para cachés
# estos necesitan al menos echoping 6 con los plugins correspondientes
+ EchoPingDNS        # servidores DNS (53/udp o tcp)
+ EchoPingLDAP       # servidores LDAP (389/tcp)
+ EchoPingWhois      # servidores Whois (43/tcp)
Explicación de la sonda
Este ejemplo muestra la mayoría de las sondas derivadas de echoping en acción.
Configuración del objetivo
*** Objetivos ***
# sonda por defecto
probe = FPing

menu = Principal
title = Gráfica de Latencia de Red
remark = Bienvenido a este sitio web de SmokePing.

+ MisServidores

menu = Mis Servidores
title = Mis Servidores

++ www-server
menu = www-server
title = Servidor Web (www-server) / ICMP
# probe = FPing propagado desde arriba
host = www-server.example

+++ http
menu = http
title = Servidor Web (www-server) / HTTP
probe = EchoPingHttp
host = www-server.example
# url por defecto es /

+++ https
menu = https
title = Servidor Web (www-server) / HTTPS
probe = EchoPingHttps
host = www-server.example

++ cache
menu = www-cache
title = Caché Web (www-cache) / ICMP
host = www-cache.example

+++ http
menu = http
title = www-cache / HTTP
probe = EchoPingHttp
host = www-cache.example
port = 8080 # usa el puerto de squid
url = http://www.somehost.example/

+++ icp
menu = icp
title = www-cache / ICP
probe = EchoPingIcp
host = www-cache.example
url = http://www.somehost.example/

++ mail
menu = mail-server
title = Servidor de Correo (mail-server) / ICMP
host = mail-server.example

+++ smtp
menu = mail-server / SMTP
title = Servidor de Correo (mail-server) / SMTP
probe = EchoPingSmtp
host = mail-server.example

++ ldap-server
menu = ldap-server
title = ldap-server / ICMP
host = ldap-server.example

+++ ldap
menu = ldap-server / LDAP
title = Servidor LDAP (ldap-server) / LDAP
probe = EchoPingLDAP
ldap_request = (objectclass=*)
host = ldap-server.example

++ name-server
menu = name-server
title = name-server / ICMP
host = name-server.example

+++ DNS
menu = name-server / DNS
title = Servidor DNS (name-server) / DNS
probe = EchoPingDNS
dns_request = name.example
host = name-server.example

++ whois-server
menu = whois-server
title = whois-server / ICMP
host = whois-server.example

+++ Whois
menu = whois-server / Whois
title = Servidor Whois (whois-server) / Whois
probe = EchoPingWhois
whois_request = domain.example
host = whois-server.example
Explicación del objetivo
Todos los servidores reciben ping tanto con ICMP (la sonda FPing) como con su respectiva sonda echoping. El servidor proxy, www-cache, recibe ping tanto con solicitudes HTTP como con solicitudes ICP para la misma URL.
