NOMBRE

skopeo -- Utilidad de línea de comandos utilizada para interactuar con imágenes de contenedores locales y remotas y registros de imágenes de contenedores

SINOPSIS

skopeo [opciones globales] comando [opciones del comando]

DESCRIPCIÓN

skopeo es una utilidad de línea de comandos que proporciona varias operaciones con imágenes de contenedores y registros de imágenes de contenedores.

skopeo puede copiar imágenes de contenedores entre varias tiendas de imágenes de contenedores, convirtiéndolas según sea necesario. Por ejemplo, puede usar skopeo para copiar imágenes de contenedores de un registro de contenedores a otro.

skopeo puede convertir una imagen de contenedor de Docker schema 2 o schema 1 a una imagen OCI.

skopeo puede inspeccionar un repositorio en un registro de contenedores sin descargar innecesariamente la imagen. Descargar una imagen de un repositorio, especialmente uno remoto, es una operación costosa en red y almacenamiento. Skopeo obtiene el manifiesto del repositorio y muestra una salida JSON similar a docker inspect sobre el repositorio o una etiqueta. skopeo, en contraste con docker inspect, le ayuda a recopilar información útil sobre un repositorio o una etiqueta sin requerir que ejecute docker pull, por ejemplo: ¿Qué etiquetas están disponibles para el repositorio dado? ¿Qué etiquetas tiene la imagen?

skopeo puede firmar y verificar imágenes de contenedores.

skopeo puede eliminar imágenes de contenedores de un registro de contenedores remoto.

Nota: skopeo no requiere ningún tiempo de ejecución de contenedores activo para realizar la mayor parte de su funcionalidad. Tampoco requiere ser root, a menos que esté copiando imágenes a un backend de almacenamiento de tiempo de ejecución de contenedor, como el demonio de docker o github.com/containers/storage.

NOMBRES DE IMAGEN

La mayoría de los comandos se refieren a imágenes de contenedores, utilizando el formato transporte:detalles. Se admiten los siguientes formatos:

containers-storage:referencia-docker
Una imagen ubicada en una tienda de imágenes local de containers/storage. Tanto la ubicación como la tienda de imágenes se especifican en /etc/containers/storage.conf. (Backend para Podman, CRI-O, Buildah y similares)

dir:ruta
Un directorio local existente ruta que almacena el manifiesto, los archivos tar de capas y las firmas como archivos individuales. Este es un formato no estandarizado, principalmente útil para depuración o inspección no invasiva de contenedores.

docker://referencia-docker
Una imagen en un registro que implementa la "Docker Registry HTTP API V2".
Las credenciales se gestionan típicamente usando (skopeo login);
consulte containers-auth.json(5) para más detalles sobre el mecanismo de búsqueda de credenciales.

docker-archive:ruta[:referencia-docker]
Una imagen se almacena en el archivo con formato docker save. referencia-docker solo se utiliza al crear dicho archivo y no debe contener un digest.

docker-daemon:referencia-docker
Una imagen referencia-docker almacenada en el almacenamiento interno del demonio de docker. referencia-docker debe contener una etiqueta o un digest. Alternativamente, al leer imágenes, el formato puede ser docker-daemon:algo:digest (un ID de imagen).

oci:ruta:etiqueta
Una etiqueta de imagen en un directorio compatible con la "Open Container Image Layout Specification" en ruta.

oci-archive:ruta:etiqueta
Una etiqueta de imagen en un archivo tar compatible con la "Open Container Image Layout Specification" en ruta.

Consulte containers-transports(5) ⟨https://github.com/containers/image/blob/main/docs/containers-transports.5.md⟩ para más detalles.

OPCIONES

Estas opciones deben colocarse antes del nombre del subcomando. Cada subcomando tiene sus propias opciones.

--command-timeout duración

Tiempo de espera para la ejecución del comando.

--debug

habilitar salida de depuración

--help, -h

Mostrar ayuda

--insecure-policy

Adoptar una política insegura y permisiva que permite cualquier cosa. Esto elimina la necesidad de un archivo de política.

--override-arch arch

Utilizar arch en lugar de la arquitectura de la máquina para seleccionar imágenes.

--override-os os

Utilizar OS en lugar del sistema operativo en ejecución para seleccionar imágenes.

--override-variant variante

Utilizar variante en lugar de la variante de arquitectura en ejecución para seleccionar imágenes.

--policy ruta-a-política

Ruta a un archivo policy.json para usar al verificar firmas y decidir si una imagen es confiable, reemplazando el archivo de política de confianza predeterminado.

--registries.d dir

Usar archivos de configuración de registro en dir (por ejemplo, para el almacenamiento de firmas de contenedores), reemplazando la ruta predeterminada.

--tmpdir dir

Directorio utilizado para almacenar archivos temporales. Por defecto es /var/tmp.

--user-agent-prefix prefijo

Prefijo a añadir a la cadena del agente de usuario. El agente de usuario resultante tendrá el formato "prefijo skopeo/versión".

--version, -v

Imprimir el número de versión

COMANDOS

Comando Descripción
skopeo-copy(1) Copia una imagen (manifiesto, capas de sistema de archivos, firmas) de una ubicación a otra.
skopeo-delete(1) Marca el nombre-de-imagen para su posterior eliminación por el recolector de basura del registro.
skopeo-generate-sigstore-key(1) Genera un par de claves pública/privada de sigstore.
skopeo-inspect(1) Devuelve información de bajo nivel sobre nombre-de-imagen en un registro.
skopeo-list-tags(1) Lista los nombres de imagen en una colección de imágenes específica del transporte.
skopeo-login(1) Inicia sesión en un registro de contenedores.
skopeo-logout(1) Cierra sesión en un registro de contenedores.
skopeo-manifest-digest(1) Calcula un digest de manifiesto para un archivo-manifiesto y lo escribe en la salida estándar.
skopeo-standalone-sign(1) Herramienta de depuración: firma una imagen localmente sin subirla.
skopeo-standalone-verify(1) Herramienta de depuración: verifica una firma de imagen desde archivos locales.
skopeo-sync(1) Sincroniza imágenes entre repositorios de registro y directorios locales.

ESTADO DE SALIDA

skopeo sale con estado 0 en caso de éxito, y no cero en caso de error.

Detalles sobre los estados de salida:

1 Error genérico, los detalles se pueden encontrar en el mensaje de error.

2 No se puede encontrar la imagen de entrada. Tenga en cuenta que esto es un esfuerzo del mejor de los casos y para registros remotos el estado a menudo no se puede informar de manera confiable.

ARCHIVOS

/etc/containers/policy.json
Archivo de política de confianza predeterminado, si no se especifica --policy.
El formato de la política se documenta en containers-policy.json(5) ⟨https://github.com/containers/image/blob/main/docs/containers-policy.json.5.md⟩ .

/etc/containers/registries.d
Directorio predeterminado que contiene la configuración del registro, si no se especifica --registries.d.
El contenido de este directorio se documenta en containers-registries.d(5) ⟨https://github.com/containers/image/blob/main/docs/containers-registries.d.5.md⟩.
