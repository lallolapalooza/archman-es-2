NOMBRE

skopeo-delete - Marca el nombre-imagen para su posterior eliminación por el recolector de basura del registro.

SINOPSIS

skopeo delete [opciones] nombre-imagen

DESCRIPCIÓN

Marca nombre-imagen para su eliminación. El efecto de esto es específico del registro; muchos registros no admiten esta operación, o no la permiten en algunas circunstancias/configuraciones.

ADVERTENCIA: Si nombre-imagen contiene un digest, esto afecta al manifiesto referenciado y puede eliminar todas las etiquetas (¿dentro del repositorio actual?) que apunten a ese manifiesto.

ADVERTENCIA: Si nombre-imagen contiene una etiqueta (pero no un digest), en la versión actual de Skopeo esto resuelve la etiqueta en un digest y luego elimina el manifiesto por digest, como se describe anteriormente (posiblemente eliminando todas las etiquetas que apuntan a ese manifiesto, no solo la etiqueta proporcionada). Este comportamiento puede cambiar en el futuro.

Al utilizar el servidor de registro github.com/distribution/distribution: para liberar el espacio en disco asignado, debe iniciar sesión en el servidor de registro de contenedores y ejecutar el recolector de basura del registro de contenedores. Por ejemplo,

/usr/bin/registry garbage-collect /etc/docker-distribution/registry/config.yml

Nota: a veces el config.yml se almacena en /etc/docker/registry/config.yml

Si está ejecutando el registro de contenedores dentro de un contenedor, ejecutaría algo como:

$ docker exec -it registry /usr/bin/registry garbage-collect /etc/docker-distribution/registry/config.yml

OPCIONES

Ver también skopeo(1) para opciones que se colocan antes del nombre del subcomando.

--authfile ruta

Ruta del archivo principal de credenciales del registro. En Linux, el valor predeterminado es ${XDG_RUNTIME_DIR}/containers/auth.json. Consulte containers-auth.json(5) para obtener más detalles sobre el mecanismo de búsqueda de credenciales y los valores predeterminados en otras plataformas.

Utilice skopeo login para administrar las credenciales.

El valor predeterminado de esta opción se lee de la variable de entorno REGISTRY\_AUTH\_FILE.

--creds usuario[:contraseña]

Credenciales para acceder al registro.

--cert-dir ruta

Utilice los certificados en ruta (*.crt, *.cert, *.key) para conectarse al registro.

--daemon-host host

Utilice el host del demonio de Docker en host (solo transporte docker-daemon:)

--help, -h

Imprimir el enunciado de uso

--no-creds

Acceder al registro de forma anónima.

Además, el registro debe permitir eliminaciones estableciendo REGISTRY\_STORAGE\_DELETE\_ENABLED=true para el demonio del registro.

--registry-token token

Token de portador para acceder al registro.

--retry-times

Número de veces que se reintentará.

--retry-delay

Retardo fijo entre reintentos. Si no se establece (o se establece en 0s), el tiempo de espera de reintento aumentará exponencialmente según el número de intentos fallidos.

--shared-blob-dir directorio

Directorio a utilizar para compartir blobs entre repositorios OCI.

--tls-verify=bool

Requerir HTTPS y verificar certificados al comunicarse con el registro o demonio de contenedores. El valor predeterminado se lee de la configuración de registry.conf.

--username

El nombre de usuario para acceder al registro.

--password

La contraseña para acceder al registro.

EJEMPLOS

Marcar la imagen example/pause para su eliminación del registro registry.example.com:

$ skopeo delete docker://registry.example.com/example/pause:latest

Ver arriba para obtener detalles adicionales sobre el uso del comando delete.
