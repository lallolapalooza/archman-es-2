sk98lin(4) Manual de Controladores de Dispositivos sk98lin(4)

NOMBRE

sk98lin - Controlador de Ethernet Gigabit Marvell/SysKonnect v6.21

SINOPSIS

insmod sk98lin.o [Speed_A=i,j,...] [Speed_B=i,j,...] [AutoNeg_A=i,j,...] [AutoNeg_B=i,j,...] [DupCap_A=i,j,...] [DupCap_B=i,j,...] [FlowCtrl_A=i,j,...] [FlowCtrl_B=i,j,...] [Role_A=i,j,...] [Role_B=i,j,...] [ConType=i,j,...] [Moderation=i,j,...] [IntsPerSec=i,j,...] [PrefPort=i,j,...] [RlmtMode=i,j,...]

DESCRIPCIÓN

Nota: Este controlador obsoleto fue eliminado en Linux 2.6.26.

sk98lin es el controlador de Ethernet Gigabit para tarjetas adaptadoras de red Marvell y SysKonnect. Soporta adaptadores Ethernet Gigabit compatibles con SysKonnect SK-98xx/SK-95xx y cualquier chipset compatible con Yukon.

Al cargar el controlador usando insmod, los parámetros para las tarjetas de red pueden especificarse como una secuencia de comandos separados por comas. Si, por ejemplo, se instalan dos adaptadores de red y la negociación automática en el Puerto A del primer adaptador debe estar ACTIVADA, pero en el Puerto A del segundo adaptador desactivada, se debe ingresar:


insmod sk98lin.o AutoNeg_A=On,Off

Después de que sk98lin se vincule a uno o más adaptadores y el sistema de archivos /proc esté montado en su sistema, se creará un archivo de estadísticas dedicado en la carpeta /proc/net/sk98lin para todos los puertos de las tarjetas adaptadoras de red instaladas. Estos archivos se nombran eth[x], donde x es el número de la interfaz que ha sido asignada a un puerto dedicado por el sistema.

Si la carga finaliza, se puede asignar cualquier dirección IP deseada a la interfaz eth[x] respectiva usando el comando ifconfig(8). Esto hace que el adaptador se conecte a Ethernet y muestre un mensaje de estado en la consola diciendo "ethx: conexión de red activa usando puerto y" seguido de los parámetros de conexión configurados o detectados.

sk98lin también soporta tramas grandes (también llamadas tramas jumbo). El uso de tramas grandes puede mejorar enormemente el rendimiento al transferir grandes cantidades de datos. Para habilitar tramas grandes, el tamaño de la MTU (unidad de transmisión máxima) para una interfaz debe establecerse en un valor alto. El tamaño de MTU predeterminado es 1500 y se puede cambiar hasta 9000 (bytes). La configuración del tamaño de la MTU se puede hacer al asignar la dirección IP a la interfaz o más tarde usando el comando ifconfig(8) con el parámetro mtu. Si, por ejemplo, eth0 necesita una dirección IP y un tamaño de MTU de trama grande, se pueden usar los siguientes dos comandos:


ifconfig eth0 10.1.1.1
ifconfig eth0 mtu 9000

Estos dos comandos incluso pueden combinarse en uno:


ifconfig eth0 10.1.1.1 mtu 9000

Tenga en cuenta que las tramas grandes solo se pueden usar si su infraestructura de red lo permite. Esto significa que cualquier switch utilizado en su Ethernet también debe admitir tramas grandes. Bastantes switches admiten tramas grandes, pero necesitan ser configurados para hacerlo. La mayoría de las veces, su configuración predeterminada es admitir solo tramas estándar con un tamaño de MTU de 1500 (bytes). Además de los switches dentro de la red, todos los adaptadores de red que se vayan a utilizar también deben estar habilitados con respecto a las tramas jumbo. Si un adaptador no está configurado para recibir tramas grandes, simplemente las descartará.

Volver al tamaño de trama Ethernet estándar se puede hacer usando el comando ifconfig(8) nuevamente:


ifconfig eth0 mtu 1500

El controlador Marvell/SysKonnect Gigabit Ethernet para Linux es capaz de soportar VLAN y Agregación de Enlaces de acuerdo con los estándares IEEE 802.1, 802.1q y 802.3ad. Estas características solo están disponibles después de la instalación de módulos de código abierto que se pueden encontrar en Internet:

VLAN: http://www.candelatech.com/~greear/vlan.html
Agregación de Enlaces: http://www.st.rim.or.jp/~yumo

Tenga en cuenta que Marvell/SysKonnect no ofrece ningún soporte para estos módulos de código abierto y no asume ninguna responsabilidad por ningún tipo de fallo o problema que surja al usar estos módulos.

Parámetros

Speed_A=i,j,...
Este parámetro se utiliza para establecer las capacidades de velocidad del puerto A de una tarjeta adaptadora. Solo es válido para adaptadores de cobre Yukon. Los valores posibles son: 10, 100, 1000 o Auto; Auto es el valor predeterminado. Por lo general, la velocidad se negocia entre los dos puertos durante el establecimiento del enlace. Si esto falla, un puerto puede forzarse a una configuración específica con este parámetro.
Speed_B=i,j,...
Este parámetro se utiliza para establecer las capacidades de velocidad del puerto B de una tarjeta adaptadora. Solo es válido para adaptadores de cobre Yukon. Los valores posibles son: 10, 100, 1000 o Auto; Auto es el valor predeterminado. Por lo general, la velocidad se negocia entre los dos puertos durante el establecimiento del enlace. Si esto falla, un puerto puede forzarse a una configuración específica con este parámetro.
AutoNeg_A=i,j,...
Habilita o deshabilita el uso de la negociación automática del puerto A de una tarjeta adaptadora. Los valores posibles son: On, Off o Sense; On es el valor predeterminado. El modo Sense detecta automáticamente si el socio de enlace soporta la negociación automática o no.
AutoNeg_B=i,j,...
Habilita o deshabilita el uso de la negociación automática del puerto B de una tarjeta adaptadora. Los valores posibles son: On, Off o Sense; On es el valor predeterminado. El modo Sense detecta automáticamente si el socio de enlace soporta la negociación automática o no.
DupCap_A=i,j,...
Este parámetro indica el modo dúplex que se utilizará para el puerto A de una tarjeta adaptadora. Los valores posibles son: Half, Full o Both; Both es el valor predeterminado. Este parámetro solo es relevante si AutoNeg_A del puerto A no está configurado como Sense. Si AutoNeg_A está configurado como On, se pueden especificar los tres valores de DupCap_A (Half, Full o Both). Si AutoNeg_A está configurado como Off, solo se permiten los valores Full y Half de DupCap_A. Este parámetro DupCap_A es útil si su socio de enlace no admite todas las combinaciones dúplex posibles.
DupCap_B=i,j,...
Este parámetro indica el modo dúplex que se utilizará para el puerto B de una tarjeta adaptadora. Los valores posibles son: Half, Full o Both; Both es el valor predeterminado. Este parámetro solo es relevante si AutoNeg_B del puerto B no está configurado como Sense. Si AutoNeg_B está configurado como On, se pueden especificar los tres valores de DupCap_B (Half, Full o Both). Si AutoNeg_B está configurado como Off, solo se permiten los valores Full y Half de DupCap_B. Este parámetro DupCap_B es útil si su socio de enlace no admite todas las combinaciones dúplex posibles.
FlowCtrl_A=i,j,...
Este parámetro se puede utilizar para establecer las capacidades de control de flujo que el puerto informa durante la negociación automática. Los valores posibles son: Sym, SymOrRem, LocSend o None; SymOrRem es el valor predeterminado. Los diferentes modos tienen el siguiente significado:
Sym = Simétrico
Se permite que ambos socios de enlace envíen tramas PAUSE.
SymOrRem = Simétrico o Remoto
Se permite que ambos socios de enlace o solo el socio remoto envíen tramas PAUSE.
LocSend = Envío Local
Solo se permite que el socio de enlace local envíe tramas PAUSE.
None = Ninguno
No se permite que ningún socio de enlace envíe tramas PAUSE.
Tenga en cuenta que este parámetro se ignora
rojo si AutoNeg_A está configurado como Off.
FlowCtrl_B=i,j,...
Este parámetro se puede usar para configurar las capacidades de control de flujo que el puerto informa durante la negociación automática. Los valores posibles son: Sym, SymOrRem, LocSend o None; SymOrRem es el valor predeterminado. Los diferentes modos tienen el siguiente significado:
Sym = Symmetric
Ambos socios de enlace pueden enviar tramas PAUSE.
SymOrRem = SymmetricOrRemote
Ambos socios o solo el socio remoto pueden enviar tramas PAUSE.
LocSend = LocalSend
Solo el socio de enlace local puede enviar tramas PAUSE.
None = None
Ningún socio de enlace puede enviar tramas PAUSE.
Tenga en cuenta que este parámetro se ignora si AutoNeg_B está configurado como Off.
Role_A=i,j,...
Este parámetro solo es válido para tarjetas adaptadoras 1000Base-T. Para que dos puertos 1000Base-T se comuniquen, uno debe asumir el rol de maestro (proporcionando información de temporización), mientras que el otro debe ser el esclavo. Los valores posibles son: Auto, Master o Slave; Auto es el valor predeterminado. Normalmente, el rol de un puerto se negocia entre dos puertos durante el establecimiento del enlace, pero si falla, el puerto A de una tarjeta adaptadora se puede forzar a una configuración específica con este parámetro.
Role_B=i,j,...
Este parámetro solo es válido para tarjetas adaptadoras 1000Base-T. Para que dos puertos 1000Base-T se comuniquen, uno debe asumir el rol de maestro (proporcionando información de temporización), mientras que el otro debe ser el esclavo. Los valores posibles son: Auto, Master o Slave; Auto es el valor predeterminado. Normalmente, el rol de un puerto se negocia entre dos puertos durante el establecimiento del enlace, pero si falla, el puerto B de una tarjeta adaptadora se puede forzar a una configuración específica con este parámetro.
ConType=i,j,...
Este parámetro es una combinación de los cinco parámetros por puerto dentro de un único parámetro. Esto simplifica la configuración de ambos puertos de una tarjeta adaptadora. Los diferentes valores de esta variable reflejan las combinaciones más significativas de parámetros de puerto. Valores posibles y su combinación correspondiente de parámetros por puerto:
ConType DupCap AutoNeg FlowCtrl Role Speed
Auto Both On SymOrRem Auto Auto
100FD Full Off None Auto 100
100HD Half Off None Auto 100
10FD Full Off None Auto 10
10HD Half Off None Auto 10
Especificar cualquier otro parámetro de puerto junto con este parámetro ConType resultará en una configuración combinada de esas configuraciones. Esto se debe al hecho de que los parámetros por puerto (por ejemplo, Speed_A) tienen una prioridad más alta que la variable combinada ConType.
Moderation=i,j,...
La moderación de interrupciones se emplea para limitar el número máximo de interrupciones que el controlador debe atender. Es decir, una o más interrupciones (que indican cualquier paquete transmitido o recibido para ser procesado) se ponen en cola hasta que el controlador las procesa. Cuándo se deben atender las interrupciones en cola lo determina el parámetro IntsPerSec, que se explica más adelante. Los posibles modos de moderación son: None, Static o Dynamic; None es el valor predeterminado. Los diferentes modos tienen el siguiente significado:
None No se aplica moderación de interrupciones en la tarjeta adaptadora. Por lo tanto, cada interrupción de transmisión o recepción se atiende inmediatamente tan pronto como aparece en la línea de interrupción de la tarjeta adaptadora.
Static Se aplica moderación de interrupciones en la tarjeta adaptadora. Todas las interrupciones de transmisión y recepción se ponen en cola hasta que finaliza un intervalo de moderación completo. Si finaliza dicho intervalo de moderación, todas las interrupciones en cola se procesan en un solo grupo sin ningún retraso. El término Static refleja el hecho de que la moderación de interrupciones siempre está habilitada, independientemente de la carga de red que esté pasando actualmente por una interfaz particular. Además, la duración del intervalo de moderación tiene una longitud fija que nunca cambia mientras el controlador está operativo.
Dynamic La moderación de interrupciones podría aplicarse en la tarjeta adaptadora, dependiendo de la carga del sistema. Si el controlador detecta que la carga del sistema es demasiado alta, el controlador intenta proteger el sistema contra demasiada carga de red habilitando la moderación de interrupciones. Si, en un momento posterior, la utilización de la CPU disminuye nuevamente (o si la carga de red es insignificante), la moderación de interrupciones se deshabilitará automáticamente.
La moderación de interrupciones debe usarse cuando el controlador tiene que manejar una o más interfaces con una alta carga de red, lo que, como consecuencia, también conduce a una alta utilización de la CPU. Cuando se aplica moderación en tales situaciones de alta carga de red, la carga de la CPU podría reducirse entre un 20 y un 30 % en ordenadores lentos.
Tenga en cuenta que el inconveniente de usar la moderación de interrupciones es un aumento del tiempo de ida y vuelta (RTT), debido a la puesta en cola y atención de interrupciones en momentos de moderación dedicados.
IntsPerSec=i,j,...
Este parámetro determina la duración de cualquier intervalo de moderación de interrupciones. Suponiendo que se va a utilizar moderación de interrupciones estática, un valor del parámetro IntsPerSec de 2000 dará lugar a un intervalo de moderación de interrupciones de 500 microsegundos. Los valores posibles para este parámetro están en el rango de 30...40000 (interrupciones por segundo). El valor predeterminado es 2000.
Este parámetro solo se utiliza si la moderación de interrupciones estática o dinámica está habilitada en una tarjeta de red adaptadora. Este parámetro se ignora si no se aplica moderación.
Tenga en cuenta que la duración del intervalo de moderación debe elegirse con cuidado. A primera vista, seleccionar una duración muy larga (por ejemplo, solo 100 interrupciones por segundo) parece significativo, pero el aumento del retraso en el procesamiento de paquetes es tremendo. Por otro lado, seleccionar un tiempo de moderación muy corto podría compensar el uso de cualquier moderación que se esté aplicando.
PrefPort=i,j,...
Este parámetro se utiliza para forzar el puerto preferido a A o B (en adaptadores de red de doble puerto). El puerto preferido es el que se utiliza si ambos puertos A y B se detectan como completamente funcionales. Los valores posibles son: A o B; A es el valor predeterminado.
RlmtMode=i,j,...
RLMT monitoriza el estado del puerto. Si falla el enlace del puerto activo, RLMT cambia inmediatamente al enlace de espera. El enlace virtual se mantiene mientras al menos un enlace "físico" esté activo. Este parámetro indica cómo RLMT debe monitorizar ambos puertos. Los valores posibles son: CheckLinkState, CheckLocalPort, CheckSeg o DualNet; CheckLinkState es el valor predeterminado. Los diferentes modos tienen el siguiente significado:
CheckLinkState Solo comprueba el estado del enlace: RLMT utiliza el estado del enlace informado por el hardware del adaptador para cada puerto individual para determinar si un puerto se puede utilizar para todo el tráfico de red o no.
CheckLocalPort En este modo, RLMT monitoriza la ruta de red entre los dos puertos de un adaptador intercambiando paquetes regularmente entre ellos. Este modo requiere una configuración de red en la que los dos puertos puedan "verse" entre sí (es decir, no debe haber ningún enrutador entre los puertos).
CheckSeg Comprueba el puerto local y la segmentación: Este modo admite las mismas funciones que el modo CheckLocalPort y, además, comprueba la segmentación de red entre los puertos. Por lo tanto, este modo solo debe utilizarse si se instalan switches Gigabit Ethernet en la red que se hayan configurado para utilizar el protocolo Spanning Tree.
DualNet En este modo, los puertos A y B se utilizan como dispositivos separados. Si tiene un adaptador de doble puerto, el puerto A se configurará como eth[x] y el puerto B como eth[x+1]. Ambos puertos se pueden utilizar de forma independiente con direcciones IP distintas. La configuración del puerto preferido no se utiliza. RLMT está desactivado.
Tenga en cuenta que los modos RLMT CheckLocalPort y CheckLinkState están diseñados para funcionar en configuraciones donde existe una ruta de red entre los puertos de un adaptador. Además, no están diseñados para funcionar donde los adaptadores están conectados directamente.

ARCHIVOS

/proc/net/sk98lin/eth[x]
El archivo de estadísticas de una interfaz particular de una tarjeta adaptadora. Contiene información genérica sobre la tarjeta adaptadora, además de un resumen detallado de todos los contadores de transmisión y recepción.

Este es el archivo README del controlador sk98lin. Contiene un HOWTO de instalación detallado y describe todos los parámetros del controlador. También describe problemas comunes y proporciona soluciones para ellos.
