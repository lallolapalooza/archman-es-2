NOMBRE

skopeo list-tags - Enumera los nombres de las imágenes en una colección de imágenes específica del transporte.

SINOPSIS

skopeo list-tags [opciones] imagen-origen

Devuelve una lista de etiquetas de imagen-origen en un registro o un archivo de archivo docker local.

imagen-origen nombre del repositorio del cual recuperar una lista de etiquetas o un archivo de archivo docker local.

OPCIONES

Ver también skopeo(1) para las opciones colocadas antes del nombre del subcomando.

--authfile ruta

Ruta del archivo de credenciales del registro actualizado. En Linux, el valor predeterminado es ${XDG_RUNTIME_DIR}/containers/auth.json. Consulte containers-auth.json(5) para obtener más detalles sobre el mecanismo de búsqueda de credenciales y los valores predeterminados en otras plataformas.

Use skopeo login para administrar las credenciales.

El valor predeterminado de esta opción se lee de la variable de entorno REGISTRY\_AUTH\_FILE.

--creds usuario[:contraseña] para acceder al registro.

--cert-dir ruta

Use certificados en ruta (*.crt, *.cert, *.key) para conectarse al registro.

--help, -h

Imprime la declaración de uso

--no-creds

Accede al registro de forma anónima.

--registry-token Token Bearer

Token Bearer para acceder al registro.

--retry-times

El número de veces que se reintentará.

--retry-delay

Retraso fijo entre reintentos. Si no se establece (o se establece en 0s), el tiempo de espera del reintento aumentará exponencialmente en función del número de intentos fallidos.

--tls-verify=booleano

Requiere HTTPS y verifica los certificados al hablar con el registro o demonio de contenedores. El valor predeterminado es la configuración de registry.conf.

--username

El nombre de usuario para acceder al registro.

--password

La contraseña para acceder al registro.

NOMBRES DE REPOSITORIO

Los nombres de los repositorios son referencias específicas del transporte, ya que cada transporte puede tener su propio concepto de un "repositorio" y "etiquetas".

Este comando se refiere a los repositorios utilizando el formato transporte:detalles. Se admiten los siguientes formatos:

docker://referencia-repositorio-docker
Un repositorio en un registro que implementa la "API HTTP de Registro Docker V2".
Una referencia-repositorio-docker tiene la forma: host-registro:puerto/nombre-repositorio que es similar a una referencia-imagen pero sin etiqueta o digest permitidos como último componente (por ejemplo, sin :latest o @sha256:xyz)

  Ejemplos de referencias-repositorio-docker válidas:
    "docker.io/myuser/myrepo"
    "docker.io/nginx"
    "docker.io/library/fedora"
    "localhost:5000/myrepository"
  Ejemplos de referencias inválidas:
    "docker.io/nginx:latest"
    "docker.io/myuser/myimage:v1.0"
    "docker.io/myuser/myimage@sha256:f48c4cc192f4c3c6a069cb5cca6d0a9e34d6076ba7c214fd0cc3ca60e0af76bb"

**docker-archive:ruta[:referencia-docker]
se almacenaron más de una imagen en un archivo con formato de guardado de docker.

EJEMPLOS

Transporte Docker

Para obtener la lista de etiquetas en el repositorio "fedora" del registro docker.io (el nombre del repositorio se expande a "library/fedora" según la forma canónica del transporte docker):

$ skopeo list-tags docker://docker.io/fedora
{
    "Repository": "docker.io/library/fedora",
    "Tags": [
        "20",
        "21",
        "22",
        "23",
        "24",
        "25",
        "26-modular",
        "26",
        "27",
        "28",
        "29",
        "30",
        "31",
        "32",
        "branched",
        "heisenbug",
        "latest",
        "modular",
        "rawhide"
    ]
}

Para listar las etiquetas en un registro local de docker/distribution en el puerto 5000, en este caso para el repositorio "fedora":

$ skopeo list-tags docker://localhost:5000/fedora
{
    "Repository": "localhost:5000/fedora",
    "Tags": [
        "latest",
        "30",
        "31"
    ]
}

Transporte Docker-archive

Para listar las etiquetas en un archivo docker-archive local:

$ skopeo list-tags docker-archive:/tmp/busybox.tar.gz
{
    "Tags": [
        "busybox:1.28.3"
    ]
}

También admite más de una etiqueta en un archivo:

$ skopeo list-tags docker-archive:/tmp/docker-two-images.tar.gz
{
    "Tags": [
        "example.com/empty:latest",
        "example.com/empty/but:different"
    ]
}

Incluirá una entrada source-index por cada imagen sin etiqueta:

$ skopeo list-tags docker-archive:/tmp/four-tags-with-an-untag.tar
{
    "Tags": [
        "image1:tag1",
        "image2:tag2",
        "@2",
        "image4:tag4"
    ]
}
