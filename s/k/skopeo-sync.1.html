NOMBRE

skopeo-sync - Sincroniza imágenes entre repositorios de registros y directorios locales.

SINOPSIS

skopeo sync [opciones] --src transporte --dest transporte fuente destino

DESCRIPCIÓN

Sincroniza imágenes entre repositorios de registros y directorios locales. La sincronización se logra copiando todas las imágenes encontradas en fuente a destino, lo cual es útil al sincronizar un espejo local de un registro de contenedores o para poblar registros que se ejecutan dentro de entornos air-gapped (aislados).

A diferencia de otros comandos de skopeo, skopeo sync requiere que los transportes de origen y destino se especifiquen por separado de fuente y destino. Uno de los problemas de prefijar un destino con su transporte es que el registro docker://hostname:port sería interpretado erróneamente como una referencia de imagen en un registro no totalmente calificado, con hostname y port como el nombre y etiqueta de la imagen.

Transportes fuente disponibles:
- docker (es decir, --src docker): fuente es un repositorio alojado en un registro de contenedores (ej: registry.example.com/busybox).
Si no se especifica ninguna etiqueta de imagen, skopeo sync copia todas las etiquetas encontradas en ese repositorio.
- dir (es decir, --src dir): fuente es una ruta de directorio local (ej: /media/usb/). Consulte skopeo(1) dir:ruta para el formato de imagen local.
- yaml (es decir, --src yaml): fuente es una ruta de archivo YAML local.
El archivo YAML debe especificar la lista de imágenes copiadas desde diferentes registros de contenedores (los directorios locales no son soportados). Consulte EJEMPLOS para el formato del archivo.

Transportes destino disponibles:
- docker (es decir, --dest docker): destino es un registro de contenedores (ej: my-registry.local.lan).
- dir (es decir, --dest dir): destino es una ruta de directorio local (ej: /media/usb/).
Se crea un directorio por cada 'imagen:etiqueta' de origen para cada imagen copiada.

Cuando se especifica la opción --scoped, las imágenes se prefijan con la ruta de la imagen de origen para que se puedan almacenar múltiples imágenes con el mismo nombre en destino.

OPCIONES

Consulte también skopeo(1) para ver las opciones que se colocan antes del nombre del subcomando.

--all, -a Si una de las imágenes en src se refiere a una lista de imágenes, en lugar de copiar solo la imagen que coincide con el sistema operativo y la arquitectura actuales (sujeto al uso de las opciones globales --override-os, --override-arch y --override-variant), intente copiar todas las imágenes de la lista, y la propia lista.

--authfile ruta

Ruta del archivo de credenciales del registro principal. En Linux, el valor predeterminado es ${XDG_RUNTIME_DIR}/containers/auth.json. Consulte containers-auth.json(5) para más detalles sobre el mecanismo de búsqueda de credenciales y los valores predeterminados en otras plataformas.

Utilice skopeo login para gestionar las credenciales.

El valor predeterminado de esta opción se lee de la variable de entorno REGISTRY\_AUTH\_FILE.

--src-authfile ruta

Ruta del archivo de credenciales del registro principal para el registro de origen. Utiliza la ruta proporcionada por --authfile si no se especifica.

--dest-authfile ruta

Ruta del archivo de credenciales del registro principal para el registro de destino. Utiliza la ruta proporcionada por --authfile si no se especifica.

--dry-run

Ejecuta la sincronización sin copiar realmente los datos al destino.

--src, -s transporte Transporte para el repositorio de origen.

--dest, -d transporte Transporte de destino.

--format, -f tipo-manifiesto Tipo de manifiesto (oci, v2s1 o v2s2) a utilizar al sincronizar imagen(es) a un destino (el valor predeterminado es el tipo de manifiesto de origen, con alternativas).

--help, -h

Imprime el enunciado de uso.

--scoped Prefija las imágenes con la ruta de la imagen de origen, para que se puedan almacenar múltiples imágenes con el mismo nombre en destino.

--append-suffix sufijo-etiqueta Cadena a añadir a las etiquetas de destino.

--digestfile ruta

Después de copiar las imágenes del origen, escribe el digest de las imágenes resultantes junto con la Referencia de Imagen.

sha256:bf91f90823248017a4f920fb541727fa8368dc6cf377a7debbd271cf6a31c8a7 docker://myhost.com/alpine:edge
sha256:31603596830fc7e56753139f9c2c6bd3759e48a850659506ebfb885d1cf3aef5 docker://myhost.com/postgres:14.3

--preserve-digests

Preserva los digests durante la copia. Falla si el digest no puede ser preservado.

Esta opción no cambia lo que se copiará; considere usar --all al mismo tiempo.

--remove-signatures No copies las firmas, si las hay, de imagen-origen. Esto es necesario al copiar una imagen firmada a un destino que no soporta firmas.

--sign-by id-clave

Añade una firma de “firma simple” usando ese id de clave para un nombre de imagen correspondiente a imagen-destino

--sign-by-sigstore archivo-parametros

Añade una firma sigstore basada en las opciones del archivo de parámetros de firma sigstore de contenedores especificado, archivo-parametros. Consulte containers-sigstore-signing-params.yaml(5) para detalles sobre el formato del archivo.

--sign-by-sigstore-private-key ruta

Añade una firma sigstore usando una clave privada en ruta para un nombre de imagen correspondiente a imagen-destino

--sign-by-sq-fingerprint huella-digital

Añade una firma de “firma simple” usando una clave Sequoia-PGP con la huella-digital especificada.

--sign-passphrase-file ruta

La contraseña a utilizar al firmar con --sign-by, --sign-by-sigstore-private-key o --sign-by-sq-fingerprint. Solo se leerá la primera línea. Una contraseña almacenada en un archivo es de seguridad cuestionable si otros usuarios pueden leer ese archivo. No utilice esta opción si es evitable.

--src-creds usuario[:contraseña] para acceder al registro de origen.

--dest-creds usuario[:contraseña] para acceder al registro de destino.

--src-cert-dir ruta Usa certificados (*.crt, *.cert, *.key) en ruta para conectarse al registro o demonio de origen.

--src-no-creds Accede al registro de forma anónima.

--src-tls-verify=booleano Requiere HTTPS y verifica los certificados al hablar con un registro o demonio de origen de contenedores. El valor predeterminado es la entrada del registro de origen en la configuración de registry.conf.

--dest-cert-dir ruta Usa certificados (*.crt, *.cert, *.key) en ruta para conectarse al registro o demonio de destino.

--dest-no-creds Accede al registro de forma anónima.

--dest-tls-verify=booleano Requiere HTTPS y verifica los certificados al hablar con un registro o demonio de destino de contenedores. El valor predeterminado es la entrada del registro de destino en la configuración de registry.conf.

--src-registry-token Token Bearer para acceder al registro de origen.

--dest-registry-token Token Bearer para acceder al registro de destino.

--retry-times

El número de veces que se reintentará.

--retry-delay

Retraso fijo entre reintentos. Si no se establece (o se establece en 0s), el tiempo de espera de reintento se incrementará exponencialmente en función del número de intentos fallidos.

--keep-going Si ocurren errores durante la copia de imágenes, estos errores se registrarán y el proceso continuará sincronizando el resto de las imágenes, fallando finalmente al final.

--src-username

El nombre de usuario para acceder al registro de origen.

--src-password

La contraseña para acceder al registro de origen.

--dest-username

El nombre de usuario para acceder al registro de destino.

--dest-password

La contraseña para acceder al registro de destino.

EJEMPLOS

Sincronizando a un directorio local

NAME


skopeo-sync(1)


copia de imágenes de contenedores entre almacenes






SYNOPSIS



  skopeo sync [options] --src <source_transport> <source_location> --dest <destination_transport> <destination_location>







DESCRIPTION


skopeo sync es una utilidad para copiar imágenes de contenedores
  entre diferentes almacenes (registries de contenedores, directorios locales, etc.).
  Soporta una variedad de almacenes a través de diferentes transportes.






OPTIONS


Las opciones comunes incluyen:



  
[--src-dir-permissions=mode]

  
Permisos para los directorios creados en el destino. Por defecto es
    0755.

  
[--src-xattrs-to-copy=REGEX]

  
Expresión regular que especifica las atributos extendidas que se copiarán
    desde el origen al destino.

  
[--dest-dir-permissions=mode]

  
Permisos para los directorios creados en el destino. Por defecto es
    0755.

  
[--dest-xattrs-to-copy=REGEX]

  
Expresión regular que especifica las atributos extendidas que se copiarán
    desde el origen al destino.

  
[--all]

  
Copia todas las imágenes/etiquetas del origen al destino.

  
[--scoped]

  
Si el destino es un directorio, copia la imagen dentro de un subdirectorio
    que coincide con la ruta de transporte del origen.

  
[--src-daemon]

  
Lee las imágenes del socket del demonio Docker especificado por
    DOCKER_HOST.

  
[--dest-daemon]

  
Escribe las imágenes en el socket del demonio Docker especificado por
    DOCKER_HOST.

  
[--src-creds=USER:PASSWORD]

  
Credenciales para el origen.

  
[--dest-creds=USER:PASSWORD]

  
Credenciales para el destino.

  
[--src-identity=STRING]

  
Identidad para el origen.

  
[--dest-identity=STRING]

  
Identidad para el destino.

  
[--src-no-TLS-verify]

  
No verifica el certificado TLS del origen.

  
[--dest-no-TLS-verify]

  
No verifica el certificado TLS del destino.

  
[--src-cert-dir=PATH]

  
Directorio que contiene los certificados de CA para verificar el servidor
    de origen.

  
[--dest-cert-dir=PATH]

  
Directorio que contiene los certificados de CA para verificar el servidor
    de destino.

  
[--src-authfile=PATH]

  
Ruta al archivo de autenticación para el origen.

  
[--dest-authfile=PATH]

  
Ruta al archivo de autenticación para el destino.

  
[--src-storage-driver=DRIVER]

  
Controlador de almacenamiento para usar con el origen (si aplica).

  
[--dest-storage-driver=DRIVER]

  
Controlador de almacenamiento para usar con el destino (si aplica).

  
[--src-storage-opt=OPTION=VALUE]

  
Opciones de configuración para el controlador de almacenamiento de origen.

  
[--dest-storage-opt=OPTION=VALUE]

  
Opciones de configuración para el controlador de almacenamiento de
    destino.

  
[--retry-delay=DELAY]

  
Retraso entre reintentos (ej., 5s).

  
[--retry-times=NUMBER]

  
Número de reintentos.

  
[--timeout=DURATION]

  
Tiempo de espera para la operación.

  
[--policy=POLICY]

  
Archivo de política de imagen para verificar la imagen de origen.

  
[--quiet]

  
Suprime la salida detallada.

  
[--logging-driver=DRIVER]

  
Controlador de logging para usar.

  
[--logging-opt=OPTION=VALUE]

  
Opciones de configuración para el controlador de logging.

  
[--help]

  
Muestra la ayuda y sale.

  
[--version]

  
Muestra la información de versión y sale.

  
[--signature-policy=POLICY]

  
Archivo de política de firma para la verificación de imágenes.

  
[--sign-by=KEYNAME]

  
Firma la imagen copiada con la clave especificada.




Transportes disponibles:



  
docker

  
Registries de contenedores compatibles con la API de Docker V2 (docker.io,
    quay.io, GCR, etc.).

  
dir

  
Un directorio local que contiene una imagen de contenedor descomprimida,
    generalmente en formato de capas de Docker.

  
oci

  
Un directorio local que contiene una imagen de contenedor en formato OCI
    Image Layout Specification.

  
ostree

  
Un repositorio ostree.

  
atomic

  
Un registro de imágenes atómicas.

  
docker-archive

  
Un archivo tar que contiene una imagen de contenedor, como la generada por
    docker save.

  
docker-daemon

  
Una imagen almacenada localmente en el demonio de Docker.

  
oci-archive

  
Un archivo tar que contiene una imagen en formato OCI Image Layout
    Specification.

  
tar

  
Un archivo tar que contiene una imagen de contenedor descomprimida.

  
yaml

  
Un archivo YAML que describe múltiples imágenes y sus etiquetas para
    copiar.








EXAMPLES




Synchronizing   to a local directory


$ skopeo sync --src docker --dest dir registry.example.com/busybox /media/usb


Las imágenes se encuentran en:


/media/usb/busybox:1-glibc
/media/usb/busybox:1-musl
/media/usb/busybox:1-ubuntu
...
/media/usb/busybox:latest






Synchronizing   to a container registry from local


Las imágenes se encuentran en:


/media/usb/busybox:1-glibc


Ejecución de sync:


$ skopeo sync --src dir --dest docker /media/usb/busybox:1-glibc my-registry.local.lan/test/


Contenido del registro de destino:


REPO                                 TAGS
my-registry.local.lan/test/busybox   1-glibc






Synchronizing   to a local directory, scoped


$ skopeo sync --src docker --dest dir --scoped registry.example.com/busybox /media/usb


Las imágenes se encuentran en:


/media/usb/registry.example.com/busybox:1-glibc
/media/usb/registry.example.com/busybox:1-musl
/media/usb/registry.example.com/busybox:1-ubuntu
...
/media/usb/registry.example.com/busybox:latest






Synchronizing   to a container registry


$ skopeo sync --src docker --dest docker registry.example.com/busybox my-registry.local.lan


Contenido del registro de destino:


REPO                         TAGS
registry.local.lan/busybox   1-glibc, 1-musl, 1-ubuntu, ..., latest






Synchronizing   to a container registry keeping the repository


$ skopeo sync --src docker --dest docker registry.example.com/repo/busybox my-registry.local.lan/repo


Contenido del registro de destino:


REPO                              TAGS
registry.local.lan/repo/busybox   1-glibc, 1-musl, 1-ubuntu, ..., latest






Synchronizing   to a container registry with tag suffix


$ skopeo sync --src docker --dest docker --append-suffix '-mirror' registry.example.com/busybox my-registry.local.lan


Contenido del registro de destino:


REPO                         TAGS
registry.local.lan/busybox   1-glibc-mirror, 1-musl-mirror, 1-ubuntu-mirror, ..., latest-mirror






YAML   file content (used source for **--src yaml**)


registry.example.com:
    images:
        busybox: []
        redis:
            - "1.0"
            - "2.0"
            - "sha256:0000000000000000000000000000000011111111111111111111111111111111"
    images-by-tag-regex:
        nginx: ^1\.13\.[12]-alpine-perl$
    images-by-semver:
        alpine: ">= 3.12.0"
    credentials:
        username: john
        password: this is a secret
    tls-verify: true
    cert-dir: /home/john/certs
quay.io:
    tls-verify: false
    images:
        coreos/etcd:
            - latest


Si el nombre del archivo yaml es sync.yml, ejecución de
  sync:


$ skopeo sync --src yaml --dest docker sync.yml my-registry.local.lan/repo/


Esto copiará las siguientes imágenes: - Repositorio
  registry.example.com/busybox: todas las imágenes, ya que no se especifican
  etiquetas. - Repositorio registry.example.com/redis: imágenes etiquetadas
  "1.0" y "2.0" junto con la imagen con digest
  "sha256:0000000000000000000000000000000011111111111111111111111111111111".
  - Repositorio registry.example.com/nginx: imágenes etiquetadas
  "1.13.1-alpine-perl" y "1.13.2-alpine-perl". -
  Repositorio quay.io/coreos/etcd: imágenes etiquetadas "latest". -
  Repositorio registry.example.com/alpine: todas las imágenes con etiquetas
  que coinciden con la restricción de versión semántica ">= 3.12.0"
  ("3.12.0", "3.12.1", ..., "4.0.0", ...)


La lista completa de comparaciones posibles de versiones
  semánticas se puede encontrar en la documentación de la biblioteca upstream:
  https://github.com/Masterminds/semver/tree/v3.2.0#basic-comparisons.


El orden de versiones y la precedencia se entienden según se definen
  aquí: https://semver.org/#spec-item-11.


Para el registro registry.example.com, se utilizan las
  credenciales "john"/"this is a secret", con los certificados
  TLS del servidor ubicados en /home/john/certs.


La verificación TLS está habilitada normalmente y se puede deshabilitar
  estableciendo tls-verify en false. En el ejemplo anterior, la
  verificación TLS está habilitada para registry.example.com, mientras que
  está deshabilitada para quay.io.
