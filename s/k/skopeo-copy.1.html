NOMBRE

skopeo-copy - Copia una imagen (manifiesto, capas del sistema de archivos, firmas) de una ubicación a otra.

SINOPSIS

skopeo copy [opciones] imagen-origen imagen-destino

DESCRIPCION

Copia una imagen (manifiesto, capas del sistema de archivos, firmas) de una ubicación a otra.

Utiliza la política de confianza del sistema para validar imágenes, rechaza imágenes no confiables según la política.

imagen-origen usa el formato de "nombre de imagen" descrito anteriormente

imagen-destino usa el formato de "nombre de imagen" descrito anteriormente

imagen-origen e imagen-destino se interpretan de forma completamente independiente; por ejemplo, el nombre del destino no hereda automáticamente ninguna parte del nombre del origen.

OPCIONES

Ver también skopeo(1) para las opciones que se colocan antes del nombre del subcomando.

--additional-tag=cadenas

Etiquetas adicionales (soporta docker-archive).

--all, -a

Si imagen-origen se refiere a una lista de imágenes, en lugar de copiar solo la imagen que coincide con el sistema operativo y la arquitectura actuales (sujeto al uso de las opciones globales --override-os, --override-arch y --override-variant), intente copiar todas las imágenes de la lista, y la lista misma.

--authfile ruta

Ruta del archivo de credenciales del registro principal. En Linux, el valor predeterminado es ${XDG_RUNTIME_DIR}/containers/auth.json. Ver containers-auth.json(5) para más detalles sobre el mecanismo de búsqueda de credenciales y los valores predeterminados en otras plataformas.

Use skopeo login para administrar las credenciales.

El valor predeterminado de esta opción se lee de la variable de entorno REGISTRY\_AUTH\_FILE.

--src-authfile ruta

Ruta del archivo de credenciales del registro principal para el registro de origen. Usa la ruta dada por --authfile si no se proporciona.

--dest-authfile ruta

Ruta del archivo de credenciales del registro principal para el registro de destino. Usa la ruta dada por --authfile si no se proporciona.

--dest-shared-blob-dir directorio

Directorio a utilizar para compartir blobs entre repositorios OCI.

--digestfile ruta

Después de copiar la imagen, escriba el digest de la imagen resultante en el archivo.

--preserve-digests

Preserva los digests durante la copia. Falla si el digest no puede ser preservado.

Esta opción no cambia lo que se copiará; considere usar --all al mismo tiempo.

--encrypt-layer enteros

Experimental los índices de capas indexados en 0, con soporte para indexación negativa (por ejemplo, 0 es la primera capa, -1 es la última capa)

--format, -f tipo-manifiesto

TIPO DE MANIFIESTO (oci, v2s1, o v2s2) a utilizar en el destino (el valor predeterminado es el tipo de manifiesto del origen, con reservas)

--help, -h

Imprime la declaración de uso

--multi-arch opción

Controla qué se copia si imagen-origen se refiere a una imagen multi-arquitectura. El valor predeterminado es system.

Opciones: - system: Copia solo la imagen que coincide con la arquitectura del sistema - all: Copia la imagen completa multi-arquitectura - index-only: Copia solo el índice

La opción index-only generalmente falla a menos que las imágenes referenciadas por arquitectura ya estén presentes en el destino, o el registro de destino soporte índices dispersos.

--quiet, -q

Suprime la información de salida al copiar imágenes.

--remove-signatures

No copie firmas, si las hay, de imagen-origen. Necesario al copiar una imagen firmada a un destino que no soporta firmas.

--sign-by id-clave

Agrega una firma de “firma simple” usando ese id de clave para un nombre de imagen correspondiente a imagen-destino

--sign-by-sigstore archivo-parámetros

Agrega una firma sigstore basada en las opciones del archivo de parámetros de firma sigstore de contenedores especificado, archivo-parámetros. Ver containers-sigstore-signing-params.yaml(5) para detalles sobre el formato del archivo.

--sign-by-sigstore-private-key ruta

Agrega una firma sigstore usando una clave privada en ruta para un nombre de imagen correspondiente a imagen-destino

--sign-by-sq-fingerprint huella-digital

Agrega una firma de “firma simple” usando una clave Sequoia-PGP con la huella-digital especificada.

--sign-passphrase-file ruta

La frase de contraseña a utilizar al firmar con --sign-by, --sign-by-sigstore-private-key o --sign-by-sq-fingerprint. Solo se leerá la primera línea. Una frase de contraseña almacenada en un archivo es de dudosa seguridad si otros usuarios pueden leer este archivo. No use esta opción si se puede evitar.

--sign-identity referencia

La identidad a usar al firmar la imagen. La identidad debe ser una referencia docker completamente especificada. Si la identidad no se especifica, se usará la referencia docker de destino.

--src-shared-blob-dir directorio

Directorio a utilizar para compartir blobs entre repositorios OCI.

--encryption-key protocolo:archivo-clave

Especifica el protocolo de cifrado, que puede ser JWE (RFC7516), PGP (RFC4880) y PKCS7 (RFC2315) y el material clave requerido para el cifrado de la imagen. Por ejemplo, jwe:/ruta/a/clave.pem o pgp:admin@ejemplo.com o pkcs7:/ruta/a/archivo-x509.

--decryption-key clave[:frase-contraseña]

Clave a utilizar para el descifrado de imágenes. La clave puede apuntar a claves y/o certificados. El descifrado se intentará con todas las claves. Si la clave está protegida por una frase de contraseña, se debe proporcionar en el argumento y omitirla de lo contrario.

--src-creds usuario[:contraseña]

Credenciales para acceder al registro de origen.

--dest-compress

Comprime las capas de la imagen tarball al guardarlas en un directorio usando el transporte 'dir'. (el valor predeterminado es el mismo tipo de compresión que el origen).

--dest-decompress

Descomprime las capas de la imagen tarball al guardarlas en un directorio usando el transporte 'dir'. (el valor predeterminado es el mismo tipo de compresión que el origen).

--dest-oci-accept-uncompressed-layers

Permite capas de imagen sin comprimir al guardarlas en una imagen OCI usando el transporte 'oci'. (el valor predeterminado es comprimir aquello que no está comprimido).

--dest-creds usuario[:contraseña]

Credenciales para acceder al registro de destino.

--src-cert-dir ruta

Utiliza certificados en ruta (*.crt, *.cert, *.key) para conectarse al registro o demonio de origen.

--src-no-creds

Accede al registro de forma anónima.

--src-tls-verify=booleano

Requiere HTTPS y verifica los certificados al hablar con el registro o demonio de origen del contenedor. Por defecto, usa la configuración del registro de origen.

--dest-cert-dir ruta

Utiliza certificados en ruta (*.crt, *.cert, *.key) para conectarse al registro o demonio de destino.

--dest-no-creds

Accede al registro de forma anónima.

--dest-tls-verify=booleano

Requiere HTTPS y verifica los certificados al hablar con el registro o demonio de destino del contenedor. Por defecto, usa la configuración del registro de destino.

--src-daemon-host host

Copia desde el demonio de docker en host. Si host comienza con tcp://, HTTPS está habilitado por defecto. Para usar HTTP plano, usa el formato http:// (el valor predeterminado es unix:///var/run/docker.sock).

--dest-daemon-host host

Copia al demonio de docker en host. Si host comienza con tcp://, HTTPS está habilitado por defecto. Para usar HTTP plano, usa el formato http:// (el valor predeterminado es unix:///var/run/docker.sock).

Las firmas existentes, si las hay, también se conservan.

--dest-compress-format formato

NAME

skopeo-copy(1)

copy images between different storage mechanisms

SYNOPSIS

skopeo copy [OPTIONS] SOURCE DESTINATION

DESCRIPTION

Copy an image from a source to a destination. The source and destination are specified in the format transport:address, where transport is the storage mechanism (e.g. docker, docker-archive, oci, oci-archive, dir, containers-storage).

See containers-transports(5) for a list of supported transports and their syntax.

OPTIONS

The long and short options are identical and available at any time.

-a, --all
Copy all tags and versions of the specified image.
-A, --src-all
Copy all tags and versions of the specified image.
-b, --dest-auth-file FILE
Use FILE for authentication for the destination. The default is ~/.docker/config.json.
-c, --src-auth-file FILE
Use FILE for authentication for the source. The default is ~/.docker/config.json.
-C, --dest-cert-dir DIR
Use certificates and keys found in DIR for the destination.
-d, --src-cert-dir DIR
Use certificates and keys found in DIR for the source.
-D, --dest-tls-verify BOOL
Whether to verify the destination TLS certificate. Default: true.
-e, --src-tls-verify BOOL
Whether to verify the source TLS certificate. Default: true.
-f, --dest-insecure
Allow insecure transport for the destination registry.
-F, --src-insecure
Allow insecure transport for the source registry.
-g, --dest-skip-digests
Do not compare digests for layers. This will upload layers even if they already exist in the destination.
-G, --src-skip-digests
Do not compare digests for layers. This will upload layers even if they already exist in the source.
-h, --dest-signature-policy POLICY
Use POLICY for verifying the source image's signature. See containers-policy.json(5) for syntax.
-i, --dest-image-name NAME
Set the destination image name. Useful when copying to a directory or an archive.
-j, --dest-blob-copy OBJECT_PATH
Copy a blob from OBJECT_PATH to the destination. Used when copying partial images.
-k, --dest-tls-verify BOOL
Whether to verify the destination TLS certificate. Default: true.
-l, --src-tls-verify BOOL
Whether to verify the source TLS certificate. Default: true.
-m, --dest-auth-file FILE
Use FILE for authentication for the destination. The default is ~/.docker/config.json.
-n, --src-auth-file FILE
Use FILE for authentication for the source. The default is ~/.docker/config.json.
-O, --dest-auth-file FILE
Use FILE for authentication for the destination. The default is ~/.docker/config.json.
-P, --src-auth-file FILE
Use FILE for authentication for the source. The default is ~/.docker/config.json.
-q, --dest-signature-policy POLICY
Use POLICY for verifying the source image's signature. See containers-policy.json(5) for syntax.
-r, --src-signature-policy POLICY
Use POLICY for verifying the source image's signature. See containers-policy.json(5) for syntax.
-s, --dest-tls-verify BOOL
Whether to verify the destination TLS certificate. Default: true.
-S, --src-tls-verify BOOL
Whether to verify the source TLS certificate. Default: true.
-t, --dest-insecure
Allow insecure transport for the destination registry.
-T, --src-insecure
Allow insecure transport for the source registry.
-u, --dest-username USERNAME
Username for destination registry authentication.
-v, --src-username USERNAME
Username for source registry authentication.
-w, --dest-password PASSWORD
Password for destination registry authentication.
-x, --src-password PASSWORD
Password for source registry authentication.
-z, --dest-compress COMPRESSOR
Compress layers using the specified COMPRESSOR. Supported values are zstd, gzip.
--dest-compress-level level
Specifies the compression level to use. The value is specific to the compression algorithm used, e.g. for zstd the accepted values are in the range 1-20 (inclusive), while for gzip it is 1-9 (inclusive).
--dest-force-compress-format
Ensures that the compression algorithm set in --dest-compress-format is used exclusively.
--src-registry-token token
Bearer token for accessing the source registry.
--dest-registry-token token
Bearer token for accessing the destination registry.
--dest-precompute-digests
Precompute digests to ensure layers are not uploaded that already exist on the destination registry. Layers with initially unknown digests (ex. compressing "on the fly") will be temporarily streamed to disk.
--retry-times N
The number of times to retry.
--retry-delay DELAY
Fixed delay between retries. If not set (or set to 0s), retry wait time will be exponentially increased based on the number of failed attempts.
--src-username USERNAME
The username to access the source registry.
--src-password PASSWORD
The password to access the source registry.
--dest-username USERNAME
The username to access the destination registry.
--dest-password PASSWORD
The password to access the destination registry.
--image-parallel-copies n
Maximum number of image layers to be copied (pulled/pushed) simultaneously. Not setting this field will fall back to containers/image defaults.

EXAMPLES

To just copy an image from one registry to another:

$ skopeo copy docker://quay.io/skopeo/stable:latest docker://registry.example.com/skopeo:latest

To copy the layers of the docker.io busybox image to a local directory:

$ mkdir -p /var/lib/images/busybox
$ skopeo copy docker://busybox:latest dir:/var/lib/images/busybox
$ ls /var/lib/images/busybox/*
  /tmp/busybox/2b8fd9751c4c0f5dd266fcae00707e67a2545ef34f9a29354585f93dac906749.tar
  /tmp/busybox/manifest.json
  /tmp/busybox/8ddc19f16526912237dd8af81971d5e4dd0587907234be2b83e249518d5b673f.tar

To create an archive consumable by docker load (but note that using a registry is almost always more efficient):

$ skopeo copy docker://busybox:latest docker-archive:archive-file.tar:busybox:latest

To copy and sign an image:

$ skopeo copy --sign-by dev@example.com containers-storage:example/busybox:streaming docker://example/busybox:gold

To encrypt an image:

$ skopeo copy docker://docker.io/library/nginx:1.17.8 oci:local_nginx:1.17.8
$ openssl genrsa -out private.key 1024
$ openssl rsa -in private.key -pubout > public.key
$ skopeo copy --encryption-key jwe:./public.key oci:local_nginx:1.17.8 oci:try-encrypt:encrypted

To decrypt an image:

$ skopeo copy --decryption-key ./private.key oci:try-encrypt:encrypted oci:try-decrypt:decrypted

To copy encrypted image without decryption:

$ skopeo copy oci:try-encrypt:encrypted oci:try-encrypt-copy:encrypted

To decrypt an image that requires more than one key:

$ skopeo copy --decryption-key ./private1.key --decryption-key ./private2.key --decryption-key ./private3.key oci:try-encrypt:encrypted oci:try-decrypt:decrypted

Container images can also be partially encrypted by specifying the index of the layer. Layers are 0-indexed indices, with support for negative indexing. i.e. 0 is the first layer, -1 is the last layer.

Let's say out of 3 layers that the image docker.io/library/nginx:1.17.8 is made up of, we only want to encrypt the 2nd layer,

$ skopeo copy --encryption-key jwe:./public.key --encrypt-layer 1 oci:local_nginx:1.17.8 oci:try-encrypt:encrypted
