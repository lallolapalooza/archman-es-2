NOMBRE

yadm - Otro Gestor de Archivos de Configuración

SINOPSIS

yadm comando [opciones]

yadm comando-git-o-alias [opciones]

yadm init [-f] [-w dir]

yadm clone url [-f] [-w dir] [-b rama] [--bootstrap] [--no-bootstrap]

yadm config nombre [valor]

yadm config [-e]

yadm list [-a]

yadm bootstrap

yadm encrypt

yadm decrypt [-l]

yadm alt

yadm perms

yadm enter [comando]

yadm git-crypt [opciones]

yadm transcrypt [opciones]

yadm upgrade [-f]

yadm introspect categoria

DESCRIPCIÓN

yadm es una herramienta para gestionar una colección de archivos en múltiples ordenadores, utilizando un repositorio Git compartido. Además, yadm proporciona una característica para seleccionar versiones alternativas de archivos para sistemas particulares. Por último, yadm ofrece la capacidad de gestionar un subconjunto de archivos seguros, que se cifran antes de ser incluidos en el repositorio.

COMANDOS

comando-git o alias-git
Cualquier comando no manejado internamente por yadm se pasa a git(1). Los comandos o alias de Git se invocan con el repositorio gestionado por yadm. El directorio de trabajo para los comandos de Git será el árbol-de-trabajo configurado (normalmente $HOME).

Los archivos de configuración se gestionan utilizando comandos estándar de git; add, commit, push, pull, etc.

El comando config no se pasa directamente. En su lugar, utilice el comando gitconfig (ver más abajo).

alt
Crea enlaces simbólicos y procesa plantillas para cualquier archivo gestionado que coincida con las reglas de nomenclatura descritas en las secciones ALTERNATES y TEMPLATES. Normalmente no es necesario ejecutar este comando, ya que yadm procesa automáticamente las alternativas por defecto. Este comportamiento automático se puede deshabilitar estableciendo la configuración yadm.auto-alt a "false".
bootstrap
Ejecuta $HOME/.config/yadm/bootstrap si existe.
clone url
Clona un repositorio remoto para rastrear archivos de configuración. Después de descargar el contenido del repositorio remoto, se intenta realizar un "checkout" de la rama HEAD remota. Si ya existen archivos conflictivos en el árbol-de-trabajo, la versión local no se modificará y tendrás que revisar y resolver la diferencia.

El repositorio se almacena en $HOME/.local/share/yadm/repo.git. Por defecto, $HOME se utilizará como árbol-de-trabajo, pero esto se puede anular con la opción -w. yadm puede forzarse a sobrescribir un repositorio existente proporcionando la opción -f. Si deseas utilizar una rama distinta de la rama HEAD remota, puedes especificarla usando la opción -b. Por defecto, yadm preguntará al usuario si se debe ejecutar el programa bootstrap (si existe). Las opciones --bootstrap o --no-bootstrap forzarán la ejecución del bootstrap o evitarán que se ejecute, sin preguntar al usuario.

config
Este comando gestiona las configuraciones de yadm. Funciona exactamente como git-config(1). Consulte la sección CONFIGURACIÓN para más detalles.
decrypt
Descifra todos los archivos almacenados en $HOME/.local/share/yadm/archive. Los archivos descifrados serán relativos al árbol-de-trabajo configurado (normalmente $HOME). Usar la opción -l listará los archivos almacenados sin extraerlos.
encrypt
Cifra todos los archivos que coincidan con los patrones encontrados en $HOME/.config/yadm/encrypt. Consulte la sección CIFRADO para más detalles.
enter
Ejecuta un subshell con todas las variables de Git configuradas. Sal del subshell de la misma manera que sales de tu shell normal (normalmente con el comando "exit"). Este subshell se puede usar para interactuar fácilmente con tu repositorio yadm usando comandos "git". Esto podría ser útil si estás utilizando una herramienta que usa Git directamente, como tig, vim-fugitive, git-cola, etc.

Opcionalmente, puedes proporcionar un comando después de "enter", y en lugar de invocar tu shell, ese comando se ejecutará con todas las variables de Git expuestas al entorno del comando.

Emacs Tramp y Magit pueden gestionar archivos usando esta configuración:


(add-to-list 'tramp-methods
'("yadm"
(tramp-login-program "yadm")
(tramp-login-args (("enter")))
(tramp-login-env (("SHELL") ("/bin/sh")))
(tramp-remote-shell "/bin/sh")
(tramp-remote-shell-args ("-c"))))
Con esta configuración, usa (magit-status "/yadm::").
git-crypt opciones
Si git-crypt está instalado, este comando te permite pasar opciones directamente a git-crypt, con el entorno configurado para usar el repositorio yadm.

git-crypt permite el cifrado y descifrado transparente de archivos en un repositorio git. Puedes leer https://github.com/AGWA/git-crypt para obtener detalles.

gitconfig
Pasa opciones al comando git config. Dado que yadm ya utiliza el comando config para gestionar sus propias configuraciones, este comando se proporciona como una forma de cambiar las configuraciones del repositorio gestionado por yadm. Un caso útil podría ser configurar el repositorio para que los archivos no rastreados se muestren en los comandos de estado. yadm inicialmente configura su repositorio para que los archivos no rastreados no se muestren. Si deseas utilizar el comportamiento predeterminado de Git (para mostrar archivos y directorios no rastreados), puedes eliminar esta configuración.
yadm gitconfig --unset status.showUntrackedFiles
help
Imprime un resumen de los comandos de yadm.
init
Inicializa un repositorio nuevo y vacío para rastrear archivos de configuración. El repositorio se almacena en $HOME/.local/share/yadm/repo.git. Por defecto, $HOME se utilizará como árbol-de-trabajo, pero esto se puede anular con la opción -w. yadm puede forzarse a sobrescribir un repositorio existente proporcionando la opción -f.
list
Imprime una lista de archivos gestionados por yadm. La opción -a hará que se listen todos los archivos gestionados. De lo contrario, la lista solo incluirá archivos del directorio actual o inferiores.
introspect categoria
Reporta datos internos de yadm. Las categorías admitidas son commands, configs, repo y switches. El propósito de la introspección es soportar la finalización en la línea de comandos.
perms
Actualiza los permisos como se describe en la sección PERMISOS. Normalmente no es necesario ejecutar este comando, ya que yadm procesa automáticamente los permisos por defecto. Este comportamiento automático se puede deshabilitar estableciendo la configuración yadm.auto-perms a "false".

Si transcrypt está instalado, este comando te permite pasar opciones directamente a transcrypt, con el entorno configurado para usar el repositorio yadm.

transcrypt permite el cifrado y descifrado transparente de archivos en un reposi

user, u
Válido si el valor coincide con el nombre de usuario del sistema actual. El usuario se calcula ejecutando id -u -n.
hostname, h
Válido si el valor coincide con el nombre de host corto. El nombre de host se calcula ejecutando uname -n y eliminando cualquier dominio.
class, c
Válido si el valor coincide con la configuración local.class. La clase debe establecerse manualmente usando yadm config local.class <clase>. Consulte la sección CONFIGURACIÓN para obtener más detalles sobre cómo establecer local.class.
distro_family, f
Válido si el valor coincide con la familia de la distribución. La familia de la distribución se calcula inspeccionando la línea ID_LIKE de /etc/os-release (o ID si no se encuentra ninguna línea ID_LIKE).
distro, d
Válido si el valor coincide con la distribución. La distribución se calcula ejecutando lsb_release -si o inspeccionando el ID de /etc/os-release.
os, o
Válido si el valor coincide con el SO. El SO se calcula ejecutando uname -s.
arch, a
Válido si el valor coincide con la arquitectura. La arquitectura se calcula ejecutando uname -m.
default
Válido cuando ninguna otra alternativa es válida.
extension, e
Una "condición" especial que no afecta el proceso de selección. Su propósito es permitir que el archivo alternativo termine con una determinada extensión, por ejemplo, para que los editores resalten el contenido correctamente.

NOTA: El SO para "Subsistema de Windows para Linux" se informa como "WSL", aunque uname se identifica como "Linux".

Puede usar cualquier número de condiciones, en cualquier orden. Una alternativa solo se usará si TODAS las condiciones son válidas. Para todos los archivos administrados por el repositorio de yadm o listados en $HOME/.config/yadm/encrypt, si coinciden con esta convención de nomenclatura, se crearán enlaces simbólicos para la versión más apropiada.

La versión "más apropiada" se determina calculando una puntuación para cada versión de un archivo. Una plantilla siempre tiene una puntuación más alta que cualquier condición de enlace simbólico. El número de condiciones es el siguiente factor más importante en la puntuación; los archivos con más condiciones siempre serán favorecidos. Las condiciones negativas (precedidas por "~") solo se puntúan en relación con el número de condiciones no negadas. Cualquier condición inválida descalificará completamente ese archivo.

Si no le importa tener todas las versiones de alternativas almacenadas en el mismo directorio que el enlace simbólico generado, puede colocarlas en el directorio $HOME/.config/yadm/alt. El enlace simbólico generado o la plantilla procesada se crearán utilizando la misma ruta relativa.

La vinculación de alternativas se demuestra mejor con un ejemplo. Supongamos que los siguientes archivos son administrados por el repositorio de yadm:


- $HOME/path/example.txt##default
- $HOME/path/example.txt##class.Work
- $HOME/path/example.txt##class.Work,~os.Darwin
- $HOME/path/example.txt##os.Darwin
- $HOME/path/example.txt##os.Darwin,hostname.host1
- $HOME/path/example.txt##os.Darwin,hostname.host2
- $HOME/path/example.txt##os.Linux
- $HOME/path/example.txt##os.Linux,hostname.host1
- $HOME/path/example.txt##os.Linux,hostname.host2

Si se ejecuta en un Macbook llamado "host2", yadm creará un enlace simbólico que se ve así:

$HOME/path/example.txt -> $HOME/path/example.txt##os.Darwin,hostname.host2

Sin embargo, en otro Macbook llamado "host3", yadm creará un enlace simbólico que se ve así:

$HOME/path/example.txt -> $HOME/path/example.txt##os.Darwin

Dado que el nombre de host no coincide con ninguno de los archivos administrados, se elige la versión más genérica.

Si se ejecuta en un servidor Linux llamado "host4", el enlace será:

$HOME/path/example.txt -> $HOME/path/example.txt##os.Linux

Si se ejecuta en un servidor Solaris, el enlace utilizará la versión predeterminada:

$HOME/path/example.txt -> $HOME/path/example.txt##default

Si se ejecuta en un Macbook con la clase establecida en "Work", el enlace será:

$HOME/path/example.txt -> $HOME/path/example.txt##class.Work

Dado que la clase tiene una precedencia mayor que el SO, se elige esta versión.

Si se ejecuta en un sistema con la clase establecida en "Work", pero dentro del Subsistema de Windows para Linux, donde el SO se informa como WSL, el enlace será:

$HOME/path/example.txt -> $HOME/path/example.txt##class.Work,~os.Darwin

Si no existe una versión "##default" y ningún archivo tiene condiciones válidas, no se creará ningún enlace.

Los enlaces también se crean para directorios nombrados de esta manera, siempre que tengan al menos un archivo administrado por yadm dentro de ellos.

yadm creará automáticamente estos enlaces por defecto. Esto se puede desactivar usando la configuración yadm.auto-alt. Incluso si está desactivado, los enlaces se pueden crear manualmente ejecutando yadm alt.

Los enlaces creados se añaden automáticamente al archivo info/exclude del repositorio. Esto se puede desactivar usando la configuración yadm.auto-exclude.

La clase es un valor especial que se almacena localmente en cada host (dentro del repositorio local). Para usar enlaces simbólicos alternativos que utilicen la clase, debe establecer el valor de la clase usando la configuración local.class. Esto se establece como cualquier otra configuración de yadm con el comando yadm config. Lo siguiente establece la clase en "Work".


yadm config local.class Work

De manera similar, los valores de arquitectura, SO, nombre de host, usuario, distribución y familia de distribución se pueden anular manualmente utilizando las opciones de configuración local.arch, local.os, local.hostname, local.user, local.distro y local.distro-family.

PLANTILLAS

Si se define una condición de plantilla en el sufijo "##" de un archivo alternativo, y las dependencias necesarias para la plantilla están disponibles, el archivo se procesará para crear o sobrescribir archivos.

Procesadores de plantillas compatibles:

default
Este es el procesador de plantillas integrado de yadm. Este procesador es muy básico, con una sintaxis similar a Jinja. La ventaja de este procesador es que solo depende de awk, que está disponible en la mayoría de los sistemas *nix. Para usar este procesador, especifique el valor de "default" o simplemente omita el valor (por ejemplo, "##template").

NOTA: Este procesador de plantillas realiza comparaciones insensibles a mayúsculas y minúsculas en las sentencias if.

ESH
ESH es un procesador de plantillas escrito en shell compatible con POSIX. Permite ejecutar comandos de shell dentro de las plantillas. Esto se puede utilizar para hacer referencia a sus propias configuraciones dentro de las plantillas, por ejemplo:


<% yadm config mysection.myconfig %>

Para usar el procesador de plantillas ESH, especifique el valor de "esh"

j2cli
Para usar el procesador de plantillas Jinja j2cli, especifique el valor de "j2" o "j2cli".
envtpl
Para usar el procesador de plantillas Jinja envtpl, especifique el valor de "j2" o "envtpl".

NOTA: Especificar "j2" como procesador intentará usar j2cli o envtpl, el que esté disponible.

Si el procesador de plantillas especificado está disponible, las plantillas se procesarán para crear o sobrescribir archivos.

Durante el procesamiento, las siguientes variables están disponibles en la plantilla:


Por defecto Jinja o ESH Descripción
------------- ------------- ----------------------------
yadm.arch YADM_ARCH uname -m
yadm.class YADM_CLASS Última clase definida localmente
yadm.classes YADM_CLASSES Todas las clases
yadm.distro YADM_DISTRO lsb_release -si
yadm.distro_family YADM_DISTRO_FAMILY ID_LIKE de /etc/os-release
yadm.filename Nombre de archivo del archivo actual
yadm.hostname YADM_HOSTNAME uname -n (sin dominio)
yadm.os YADM_OS uname -s
yadm.source YADM_SOURCE Nombre de archivo de la plantilla
yadm.user YADM_USER id -u -n
env.VAR Variable de entorno VAR

NOTA: El SO para "Subsistema de Windows para Linux" se informa como "WSL", aunque uname se identifica como "Linux".

NOTA: Si lsb_release no está disponible, DISTRO será el ID especificado en /etc/os-release.

Ejemplos:

whatever##template con el siguiente contenido


{% if yadm.user == "harvey" %}
config={{yadm.class}}-{{yadm.os}}
{% else %}
config=dev-whatever
{% include "whatever.extra" %}
{% endif %}

generaría un archivo llamado whatever con el siguiente contenido si el usuario es "harvey":


config=work-Linux

y el siguiente en caso contrario (si whatever.extra contiene admin=false):


config=dev-whatever
admin=false

Una plantilla Jinja equivalente llamada whatever##template.j2 se vería así:


{% if YADM_USER == 'harvey' -%}
config={{YADM_CLASS}}-{{YADM_OS}}
{% else -%}
config=dev-whatever
{% include 'whatever.extra' %}
{% endif -%}

NAME

yadm - manage dotfiles using git

SYNOPSIS

yadm [options] command [arguments]

DESCRIPTION

yadm is a command line utility to manage your dotfiles using git. It is an alternative to storing dotfiles in a bare git repository, or using symlinks.

The yadm repository is stored in $HOME/.local/share/yadm/repo.git, and your work-tree is simply your home directory ($HOME). This means you can run yadm commands from anywhere in your home directory.

Note that yadm is a wrapper around git. Any valid git command can be run using yadm by prefixing the command with yadm. For example, to add a file to the index, you would run yadm add instead of git add.

yadm offers some enhancements over plain git:

ENCRYPTION
yadm can encrypt sensitive files such as SSH or GPG keys, across multiple systems. However, doing so would put plain text data into a Git repository, which often resides on a public system. yadm can make it easy to encrypt and decrypt a set of files so the encrypted version can be maintained in the Git repository. This feature will only work if a supported tool is available. Both gpg(1) and openssl(1) are supported. gpg is used by default, but openssl can be configured with the yadm.cipher configuration.

To use this feature, a list of patterns (one per line) must be created and saved as $HOME/.config/yadm/encrypt. This list of patterns should be relative to the configured work-tree (usually $HOME). For example:


.ssh/*.key
.gnupg/*.gpg

Standard filename expansions (*, ?, [) are supported. Two consecutive asterisks "**" can be used to match all subdirectories. Other shell expansions like brace and tilde are not supported. Spaces in paths are supported, and should not be quoted. If a directory is specified, its contents will be included. Paths beginning with a "!" will be excluded.

The yadm encrypt command will find all files matching the patterns, and prompt for a password. Once a password has confirmed, the matching files will be encrypted and saved as $HOME/.local/share/yadm/archive. The "encrypt" and "archive" files should be added to the yadm repository so they are available across multiple systems.

To decrypt these files later, or on another system run yadm decrypt and provide the correct password. After files are decrypted, permissions are automatically updated as described in the PERMISSIONS section.

Symmetric encryption is used by default, but asymmetric encryption may be enabled using the yadm.gpg-recipient configuration.

NOTE: It is recommended that you use a private repository when keeping confidential files, even though they are encrypted.

Patterns found in $HOME/.config/yadm/encrypt are automatically added to the repository's info/exclude file every time yadm encrypt is run. This is to prevent accidentally committing sensitive data to the repository. This can be disabled using the yadm.auto-exclude configuration.

Using transcrypt or git-crypt

A completely separate option for encrypting data is to install and use transcrypt or git-crypt. Once installed, you can use these tools by running yadm transcrypt or yadm git-crypt. These tools enables transparent encryption and decryption of files in a git repository. See the following web sites for more information:

- https://github.com/elasticdog/transcrypt

- https://github.com/AGWA/git-crypt

PERMISSIONS
When files are checked out of a Git repository, their initial permissions are dependent upon the user's umask. Because of this, yadm will automatically update the permissions of some file paths. The "group" and "others" permissions will be removed from the following files:

- $HOME/.local/share/yadm/archive

- All files matching patterns in $HOME/.config/yadm/encrypt

- The SSH directory and files, .ssh/*

- The GPG directory and files, .gnupg/*

yadm will automatically update permissions by default. This can be disabled using the yadm.auto-perms configuration. Even if disabled, permissions can be manually updated by running yadm perms. The .ssh directory processing can be disabled using the yadm.ssh-perms configuration. The .gnupg directory processing can be disabled using the yadm.gpg-perms configuration.

When cloning a repo which includes data in a .ssh or .gnupg directory, if those directories do not exist at the time of cloning, yadm will create the directories with mask 0700 prior to merging the fetched data into the work-tree.

When running a Git command and .ssh or .gnupg directories do not exist, yadm will create those directories with mask 0700 prior to running the Git command. This can be disabled using the yadm.auto-private-dirs configuration.

HOOKS
For every command yadm supports, a program can be provided to run before or after that command. These are referred to as "hooks". yadm looks for hooks in the directory $HOME/.config/yadm/hooks. Each hook is named using a prefix of pre_ or post_, followed by the command which should trigger the hook. For example, to create a hook which is run after every yadm pull command, create a hook named post_pull. Hooks must have the executable file permission set.

If a pre_ hook is defined, and the hook terminates with a non-zero exit status, yadm will refuse to run the yadm command. For example, if a pre_commit hook is defined, but that command ends with a non-zero exit status, the yadm commit will never be run. This allows one to "short-circuit" any operation using a pre_ hook.

Hooks have the following environment variables available to them at runtime:

YADM_HOOK_COMMAND
The command which triggered the hook
YADM_HOOK_DATA
The path to the yadm data directory
YADM_HOOK_DIR
The path to the yadm directory
YADM_HOOK_EXIT
The exit status of the yadm command
YADM_HOOK_FULL_COMMAND
The yadm command with all command line arguments (parameters are space delimited, and any space, tab or backslash will be escaped with a backslash)
YADM_HOOK_REPO
The path to the yadm repository
YADM_HOOK_WORK
The path to the work-tree

FILES

All of yadm's configurations are relative to the "yadm directory". yadm uses the "XDG Base Directory Specification" to determine this directory. If the environment variable $XDG_CONFIG_HOME is defined as a fully qualified path, this directory will be $XDG_CONFIG_HOME/yadm. Otherwise it will be $HOME/.config/yadm.

Similarly, yadm's data files are relative to the "yadm data directory". yadm uses the "XDG Base Directory Specification" to determine this directory. If the environment variable $XDG_DATA_HOME is defined as a fully qualified path, this directory will be $XDG_DATA_HOME/yadm. Otherwise it will be $HOME/.local/share/yadm.

The following are the default paths yadm uses for its own data. Most of these paths can be altered using universal options. See the OPTIONS section for details.

$HOME/.config/yadm
The yadm directory. By default, all configs yadm stores is relative to this directory.
$HOME/.local/share/yadm
The yadm data directory. By default, all data yadm stores is relative to this directory.
$YADM_DIR/config
Configuration file for yadm.
$YADM_DIR/alt
This is a directory to keep "alternate files" without having them side-by-side with the resulting symlink or processed template. Alternate files placed in this directory will be created relative to $HOME instead.
$YADM_DATA/repo.git
Git repository used by yadm.
$YADM_DIR/encrypt
List of globs used for encrypt/decrypt
$YADM_DATA/archive
All files encrypted with yadm encrypt are stored in this file.

EXAMPLES

yadm init
Create an empty repo for managing files
yadm add .bash_profile ; yadm commit
Add .bash_profile to the Git index and create a new commit
yadm remote add origin <url>
Add a remote origin to an existing repository
yadm push -u origin master
Initial push of master to origin
echo .ssh/*.key >> $HOME/.config/yadm/encrypt
Add a new pattern to the list of encrypted files
yadm encrypt ; yadm add ~/.local/share/yadm/archive ; yadm commit
Commit a new set of encrypted files
