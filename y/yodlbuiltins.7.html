NOMBRE

yodlbuiltins - Funciones incorporadas para los conversores de Yodl

SINOPSIS

Esta página del manual enumera las funciones incorporadas estándar del paquete Yodl.

DESCRIPCIÓN

La siguiente lista muestra las funciones incorporadas definidas por los conversores de Yodl y que pueden ser utilizadas en documentos Yodl. Consulte la guía del usuario de Yodl, distribuida con el paquete Yodl, para obtener una descripción completa.

La siguiente lista muestra todas las funciones incorporadas del paquete en orden alfabético.

`Comandos incorporados de Yodl’
Como se mencionó anteriormente, la entrada de YODL consiste en texto y comandos. YODL soporta una serie de comandos incorporados que pueden ser utilizados en un documento YODL, o que pueden ser usados para crear un paquete de macros.
No se desespere si encuentra que la descripción de esta sección es demasiado técnica. Exactamente por esta razón, YODL soporta los paquetes de macros para facilitar la vida a un escritor de documentación. Por ejemplo, vea el capítulo `[MACROPACKAGE]’ que describe un paquete de macros para YODL.
La mayoría de las funciones y macros incorporadas expanden la información que reciben de la manera en que la reciben. Es decir, la información en sí solo se evalúa cuando finalmente se inserta en un medio de salida (generalmente un archivo). Sin embargo, algunas funciones incorporadas *evalúan* su(s) argumento(s) una vez que el argumento es procesado. Estas son:
o
La función incorporada `ERROR’ (ver sección `[ERROR]’);
o
La función incorporada `EVAL’ (ver sección `[EVAL]’);
o
La función incorporada `FPUTS’ (ver sección `[FPUTS]’);
o
La función incorporada `INTERNALINDEX’ (ver sección `[INTERNALINDEX]’);
o
La función incorporada `PUSHSUBST’ (ver sección `[PUSHSUBST]’);
o
La función incorporada `TYPEOUT’ (ver sección `[TYPEOUT]’);
o
La función incorporada `UPPERCASE’ (ver sección `[UPPERCASE]’);
o
La función incorporada `WARNING’ (ver sección `[WARNING]’);
o
La función incorporada `XXSUBST’ para uso interno solamente; Todas las demás funciones incorporadas *no* evaluarán sus argumentos. Vea las funciones mencionadas para más detalles, y en particular `EVAL()’ para una descripción de este proceso de evaluación.
`ADDTOCOUNTER’
La función `ADDTOCOUNTER’ suma un valor dado a un contador. Espera dos argumentos: el nombre del contador y una expresión aditiva que define el valor a sumar. El contador debe haber sido creado previamente con `DEFINECOUNTER’.
La expresión aditiva no puede contener espacios en blanco y puede usar los operadores + y -, sus operandos pueden ser valores numéricos enteros o nombres de contadores (definidos). El valor resultante puede ser negativo; en ese caso, se resta un valor del contador de destino.
Por ejemplo, si `one’ y `two’ son contadores, entonces 
    ADDTOCOUNTER(one)(-two)\//    resta el valor de two de one
    ADDTOCOUNTER(one)(two+two)\// suma 2 veces el valor de two a one
Ver más adelante la sección `[COUNTERS]’.
`ADDTOSYMBOL’
Desde la versión 2.00 de Yodl, los símbolos pueden ser manipulados. Para añadir texto a un símbolo existente, está disponible la función incorporada `ADDTOSYMBOL’. Espera dos listas de parámetros: el nombre del símbolo y el texto a añadir al símbolo. El símbolo debe haber sido creado anteriormente usando DEFINECOUNTER (ver sección `[DEFINECOUNTER]’). El segundo argumento de la macro no se evalúa mientras se procesa `ADDTOSYMBOL’. Por lo tanto, es fácil añadir el texto de otro símbolo o la expansión de una macro al valor de un símbolo. Por ejemplo, 
    ADDTOSYMBOL(one)(SYMBOLVALUE(two)XXnl())
Esto añade el texto del símbolo `two’, seguido de una nueva línea, al contenido del símbolo `one’ solo cuando se evalúa el símbolo `one’, no cuando se evalúa `ADDTOSYMBOL’.
Ejemplo: 
    ADDTOSYMBOL(LOCATION)(este texto se añade a LOCATION)
`ATEXIT’
`ATEXIT’ espera un argumento. El argumento se añade al archivo de salida. Tenga en cuenta que este texto está sujeto a traducciones de la tabla de caracteres, etc..
Un ejemplo que utiliza esta función es el siguiente. Un documento en el lenguaje de maquetación LaTeX requiere que `\end{document}’ aparezca al final del documento. Para añadir automáticamente esta cadena al archivo de salida, se puede usar la siguiente especificación: 
    ATEXIT(NOEXPAND(\end{document}))
Se pueden definir varias listas de `ATEXIT’. Estas se añaden al archivo de salida en el orden **inverso** de especificación; es decir, la primera lista de `ATEXIT’ se añade al archivo de salida en último lugar. Esto significa que, en general, el texto de `ATEXIT’ debe especificarse cuando se envía un comando de inicio "emparejado" al archivo de salida; como en: 
    COMMENT(Inicia el documento LaTeX.)
    NOEXPAND(\begin{document})
    COMMENT(Asegura su correcta finalización.)
    ATEXIT(NOEXPAND(\end{document}))
`CHAR’
El comando `CHAR’ toma un argumento, un número o un carácter, y produce su carácter ASCII correspondiente en el archivo de salida final. Este comando está hecho para "situaciones de emergencia", donde necesita imprimir un carácter a pesar de que pueda estar redefinido en la tabla de caracteres actual (para una discusión sobre tablas de caracteres, vea `[CHARTABLES]’). Además, la función `CHAR’ puede usarse para evitar el requisito de Yodl de que los paréntesis de apertura y cierre deban coincidir.
Los siguientes argumentos pueden especificarse con `CHAR’ (intentados en este orden):
o
Un número decimal que indica el número del carácter en la tabla ASCII (por ejemplo `CHAR’`(41)’);
o
Un carácter simple y plano (por ejemplo `CHAR’`(#)’).
Por lo tanto, cuando esté seguro de que quiere enviar un carácter imprimible que no sea un paréntesis de cierre al archivo de salida, puede usar la forma `CHAR’`(c)’, siendo `c’ el carácter (como en, `CHAR’`(;)’). Para enviar un carácter no imprimible o un paréntesis de cierre al archivo de salida, busque el número ASCII del carácter y proporciónelo como argumento al comando `CHAR’.
Ejemplo: Las siguientes dos sentencias envían una `A’ al archivo de salida. 
    CHAR(65)
    CHAR(A)
La siguiente sentencia envía un paréntesis de cierre: 
    CHAR(41)
Otra forma de enviar una cadena al archivo de salida sin expansión por tablas de caracteres o por interpretación de macros, es usando la función `NOTRANS’ (ver sección `[NOTRANS]’). Si desea enviar una cadena al archivo de salida *sin* interpretación de macros, pero *con* traducción de tabla de caracteres, use `NOEXPAND’ (ver sección `[NOEXPAND]’).
`CHDIR’
El comando `CHDIR’ toma un argumento, un directorio al que cambiarse. Este comando está implementado para simplificar el trabajo con `includefile’ (ver `includefile’ en `yodlmacros(7)’). Como demostración, considere el siguiente fragmento: 
    includefile(subdir/onefile)
    includefile(subdir/anotherfile)
    includefile(subdir/yetanotherfile)
Este fragmento puede cambiarse a: 
    CHDIR(subdir)
    includefile(onefile)
    includefile(anotherfile)
    includefile(yetanotherfile)
    CHDIR(..)
El directorio actual, tal como se pasa a `CHDIR’, solo afecta a cómo `includefile’ busca sus archivos.
Tenga en cuenta que este ejemplo asume que el directorio de trabajo actual es un miembro de la especificación de ruta de inclusión de Yodl (ver opción `--include’ de Yodl).
`COMMENT’
La función `COMMENT’ define una lista de parámetros. El texto que se pasa como argumento se trata como un comentario. Es decir, se ignora; no se copia al archivo de salida final.

`DEFINESYMBOL’
`DEFINESYMBOL` espera dos argumentos. Un identificador, que es el nombre del símbolo a definir, y el valor textual del símbolo. Si el segundo argumento está vacío, el símbolo se define, pero tiene un valor vacío.
La interpretación anterior de un símbolo de Yodl como una bandera lógica aún se puede usar, pero permitirle obtener valores textuales simplifica enormemente varias macros de Yodl.
Ejemplo: 
    DEFINESYMBOL(Yodl)(Your own document language)
    DEFINESYMBOL(Options)()
`DELETECHARTABLE’
`DELETECHARTABLE` elimina la definición de una tabla de caracteres que fue definida por `DEFINECHARTABLE`. Esta función espera un argumento: el nombre de la tabla de caracteres a eliminar.
Es un error intentar eliminar una tabla de caracteres que está actualmente en uso o intentar eliminar una tabla de caracteres inexistente.
Ejemplo: 
    DELETECHARTABLE(mytable)
`DELETECOUNTER’
`DELETECOUNTER` elimina la definición de un contador que fue definido por `DEFINECOUNTER`. Esta función espera un argumento: el nombre del contador a eliminar.
Si el contador no existe, se emite una advertencia. No se considera un error intentar eliminar un contador que no se haya definido previamente.
Ejemplo: 
    DELETECOUNTER(mycounter)
`DELETEMACRO’
`DELETEMACRO` elimina la definición de una macro que fue definida por `DEFINEMACRO`. Esta función toma un argumento: el nombre de la macro a eliminar.
No hay condición de error (excepto errores de sintaxis): cuando no se definió previamente ninguna macro con un nombre coincidente, no se realiza ninguna acción.
Por ejemplo, la forma segura de definir una macro es desdefiniéndola primero. Esto asegura que las posibles definiciones previas se eliminen primero:
Ejemplo: 
DELETEMACRO(mymacro)
`DELETENOUSERMACRO’
`DELETENOUSERMACRO` elimina una definición de `nousermacro`. La función espera un argumento: el nombre del identificador de `nousermacro` a eliminar del conjunto de nousermacros.
No hay condición de error (excepto errores de sintaxis): cuando el identificador no estaba almacenado como `nousermacro`, no se toma ninguna acción.
Ejemplo: 
DELETENOUSERMACRO(mymacro)
`DELETESYMBOL’
`DELETESYMBOL` elimina la definición de una variable de símbolo. Espera un argumento, que contiene el nombre de la variable a eliminar.
Esta macro no tiene condición de error (excepto errores de sintaxis): el símbolo en cuestión puede estar previamente definido, pero eso no es necesario.
Ejemplo: 
    DELETESYMBOL(Options)
`ERROR’
La función `ERROR` toma un argumento: texto para mostrar en el flujo de error estándar. También se muestran el archivo de entrada actual y el número de línea. Después de mostrar el texto, el programa `yodl` se aborta con un estado de salida de 1.
El texto pasado a la función se expande primero. Ver el ejemplo.
La función `ERROR` es un ejemplo de una función que evalúa su propio argumento.
Este comando se puede usar, por ejemplo, en un paquete de macros cuando se expande una macro incorrecta. En mi paquete de macros (ver capítulo `[MACROPACKAGE]`) la función `ERROR` se usa cuando el comando de sección `chapter()` se utiliza en un documento `article` (en el paquete, los `chapter` solo están disponibles en `book` o `report`).
Una función incorporada análoga es `WARNING`, que también imprime un mensaje pero no sale (ver sección `[WARNING]`).
Ejemplo: En la siguiente llamada, `COUNTERVALUE(NTRIES)` se reemplaza por su valor real: 
    ERROR(Stopping after COUNTERVALUE(NTRIES) attempts)
`EVAL’
La función `EVAL` toma un argumento: el texto que se va a evaluar. Esta función te permite realizar una evaluación indirecta de comandos de Yodl. Supongamos que hay un símbolo `varnam` que contiene el nombre de una variable de contador, entonces lo siguiente muestra el valor del contador, después de haberlo incrementado: 
    EVAL(NOTRANS(USECOUNTER)(SYMBOLVALUE(varnam)))
Aquí, `EVAL` realiza los siguientes pasos:
o
Primero, se evalúa `NOTRANS(USECOUNTER)`, produciendo `USECOUNTER`.
o
A continuación, se procesa el paréntesis de apertura, produciendo el paréntesis de apertura mismo.
o
Luego, `SYMBOLVALUE(varnam)` se evalúa, produciendo el nombre de un contador, por ejemplo, ``counter``.
o
Se procesa el paréntesis de cierre, produciendo el paréntesis de cierre mismo.
o
Todo esto da como resultado el *texto* 
    USECOUNTER(counter)
o
Este texto se presenta al escáner léxico de Yodl, lo que resulta en el incremento del contador y la visualización de su valor incrementado.
b(Advertencia): los argumentos de las macros generalmente no se evalúan. Por lo tanto, una construcción como 
    USECOUNTER(EVAL(SYMBOLVALUE(varnam)))
falla, ya que ``EVAL(SYMBOLVALUE(varnam))`` no es un nombre legal para un contador. Aquí se usa la llamada `EVAL()` como argumento y, por lo tanto, no se expande.
La distinción es sutil y es una consecuencia del hecho de que las funciones incorporadas reciben argumentos sin procesar. Las funciones incorporadas pueden imponer ciertos requisitos a sus argumentos (como `USECOUNTER` que requiere el nombre de un contador) y estos requisitos se verifican en los argumentos tal como se reciben.
En resumen: `EVAL` actúa de la siguiente manera:
o
Su argumento se presenta al escáner léxico de Yodl.
o
La salida producida por el procesamiento del argumento se inserta luego en el flujo de entrada *en lugar de* la llamada `EVAL` original.
La mayoría de las funciones incorporadas *no* evalúan sus argumentos. De hecho, solo `ERROR, EVAL, FPUTS, INTERNALINDEX, PUSHSUBST, TYPEOUT, UPPERCASE, WARNING` y las funciones `XXSUBST` utilizadas internamente evalúan sus argumentos.
Posponer las evaluaciones te permite escribir: 
    DEFINESYMBOL(later)(SYMBOLVALUE(earlier))
Eventualmente, y no cuando se define `later`, una sentencia como 
    SYMBOLVALUE(later)
produce el valor de `earlier` en el momento en que se procesa `SYMBOLVALUE(later)`. Esto es, en todas sus complejas consecuencias, lo que se esperaría en la mayoría de los casos. Nos permite
macros generales que producen salida que solo se evalúa cuando el texto de los símbolos y los valores de los argumentos se vuelven disponibles, en lugar de cuando se define la macro.
Decisiones como estas invariablemente resultan en preguntas como "¿qué pasa si tengo que definir variables usando los valores de otras variables?". En esos casos, se debe usar `EVAL()`. El siguiente ejemplo muestra la definición de tres símbolos: `one` recibe un valor inicial, `two` devuelve el valor real de `one` cuando se muestra el valor de `two`, `three`, usando `EVAL()`, almacena el valor inicial de `one`.
El ejemplo también muestra otra forma de suprimir llamadas a macros, utilizando la macro `nop()` que se define en todos los tipos de conversión estándar: 
    DEFINESYMBOL(one)(Primer valor de One)
    DEFINESYMBOL(two)(SYMBOLVALUE(one))
    EVAL(DEFINESYMBOL+nop()(three)(SYMBOLVALUE(one)))
    SETSYMBOL(one)(Segundo valor de One)
    "SYMBOLVALUE(two)"      COMMENT(muestra "Segundo valor de One")
    "SYMBOLVALUE(three)"    COMMENT(muestra "Primer valor de One")

`INTERNALINDEX`
`INTERNALINDEX` espera una lista de argumentos. La lista de argumentos se evalúa y se escribe en el archivo de índice.
El archivo de índice se define desde la versión 2.00 de Yodl, y contiene la información de corrección que anteriormente se escribía en la salida de Yodl como la secuencia `.YODLTAGSTART. ... .YODLTAGEND.`.
El archivo de índice permite una mayor velocidad de procesamiento, a costa de un archivo adicional. El programa de postprocesamiento asociado `yodlpost` lee y procesa el archivo de índice, y modifica la salida de yodl correspondiente en consecuencia.
El archivo de índice no se crea cuando la salida se escribe en el nombre de salida estándar, ya que Yodl no puede solicitar al sistema la posición actual del archivo.
Las entradas del archivo de índice siempre caben en una línea. `INTERNALINDEX` cambia los caracteres de nueva línea en su argumento por espacios en blanco simples. Cada línea comienza con la posición actual del archivo de salida de Yodl, indicando así la ubicación exacta donde se solicita una corrección.     3004 ref PAQUETEMACRO
indicando que en la posición 3004 del archivo de salida producido se solicita una referencia a la etiqueta `PAQUETEMACRO`. Suponiendo una conversión html, el postprocesador escribe algo como

o
Primero, se inicia Yodl mismo, produciendo, por ejemplo, `out.idx` (el archivo índice) y `out.yodl` (la salida bruta de Yodl).
o
Luego, el postprocesador de Yodl procesa `out.idx` y `out.yodl`, produciendo uno o más archivos de salida finales, en los que los elementos del archivo índice han sido manejados adecuadamente. El argumento para `NOEXPANDINCLUDE` se evalúa parcialmente:
o
Si el argumento es el nombre de un símbolo, el valor del símbolo es el valor del argumento.
o
De lo contrario, se utiliza el argumento mismo. El nombre de archivo obtenido de esta manera no se evalúa más: en particular, no se ve afectado por las traducciones de caracteres disponibles.
El contenido del archivo se incluye literalmente, no sujeto a expansión de macros. Sin embargo, se realizan traducciones de caracteres. Si las traducciones de caracteres no son apropiadas, PUSHCHARTABLE se puede usar para suprimir temporalmente las traducciones de tablas de caracteres.
El propósito de NOEXPANDINCLUDE es incluir código fuente literalmente en el documento, como en: 
    NOEXPANDINCLUDE(literal.c)
La función NOEXPANDPATHINCLUDE se puede usar para insertar un archivo que *sí* se encuentra en uno de los directorios especificados en la ruta de inclusión de Yodl.
`NOEXPANDPATHINCLUDE`
`NOEXPANDPATHINCLUDE` toma un argumento, un nombre de archivo. El archivo se incluye. El archivo se busca en los directorios especificados en la ruta de inclusión de Yodl.
El argumento para `NOEXPANDPATHINCLUDE` se evalúa parcialmente:
o
Si el argumento es el nombre de un símbolo, el valor del símbolo es el valor del argumento.
o
De lo contrario, se utiliza el argumento mismo. El nombre de archivo obtenido de esta manera no se evalúa más: en particular, no se ve afectado por las traducciones de caracteres disponibles.
Al igual que la función `NOEXPANDINCLUDE`, el contenido del archivo se incluye literalmente, no sujeto a expansión de macros. Sin embargo, se realizan traducciones de caracteres. Si las traducciones de caracteres no son apropiadas, se puede usar `PUSHCHARTABLE` `[PUSHCHARTABLE]` para suprimir temporalmente las traducciones de tablas de caracteres.
El propósito de NOEXPANDPATHINCLUDE es incluir código fuente tal como se define en un paquete de macros literalmente en el documento, como en: 
    NOEXPANDPATHINCLUDE(rug-menubegin.xml)
`NOTRANS`
`NOTRANS` copia su único argumento literalmente al archivo de salida, sin expandir macros en él ni traducir los caracteres con la tabla de traducción actual. La función `NOTRANS` se utiliza típicamente para enviar comandos para el formato de salida al archivo de salida.
Por ejemplo, considere el siguiente fragmento de código: 
    COMMENT(--- Definir traducciones de caracteres para \, { y } en LaTeX. ---)
    DEFINECHARTABLE(standard)(
        '\\'    =    "$\\backslash$"
        '{'     =    "\\verb+{+"
        '}'     =    "\\verb+}+"
    )
    COMMENT(--- Activar la tabla de traducción. ---)
    USECHARTABLE(standard)
    COMMENT(--- Ahora dos pruebas: ---)
    NOEXPAND(\input{epsf.tex})
    NOTRANS(\input{epsf.tex})
`NOEXPAND` envía 
    $\backslash$input\verb+{+epsf.tex\verb+}+
ya que los caracteres de su argumento se traducen con la tabla de traducción `standard`. En contraste, `NOTRANS` envía `\input{epsf.tex}`.
El argumento de `NOTRANS` *debe* estar balanceado con respecto a sus paréntesis. Al usar un conjunto de paréntesis desbalanceados, use `CHAR(40)` para enviar un literal (, o `CHAR(41)` para enviar un ).
Al convertir documentos Yodl a tipos de documentos de destino, Yodl utiliza frecuentemente la función incorporada (no documentada) `XXSUBST`. En el improbable caso de que el texto `XXSUBST(...)` deba escribirse en un documento, la secuencia 
    XXSUBST+CHAR(40)...CHAR(41)
puede ser utilizada.
La descripción de NOEXPAND resume todas las combinaciones de traducciones de caracteres y/o expansión de macros, y cómo son manejadas y realizadas por Yodl.
`NOUSERMACRO`
`NOUSERMACRO` controla las advertencias de `yodl` de la siguiente manera: Cuando se inicia Yodl con la opción `-w` en la línea de comandos, se generan advertencias cuando Yodl encuentra un posible nombre de macro, es decir, un nombre seguido de un argumento entre paréntesis, mientras que no se ha definido ninguna macro con ese nombre. Yodl entonces imprime algo como `no se puede expandir posible macro de usuario`.
Ejemplos de tales secuencias son `Los archivos necesarios están en /usr/local/lib/yodl`, o `ver la página del manual para sed(1)`. Las macros candidatas son `file` y `sed`; estos nombres podrían ser fácilmente macros de usuario `válidas` seguidas de sus argumentos.
Cuando una declaración `NOUSERMACRO` correspondiente aparece *antes* de que `yodl` encuentre las macros candidatas, no se genera ninguna advertencia. Un fragmento podría, por lo tanto, ser: 
    NOUSERMACRO(file sed)
    Los archivos necesarios están en ...
    Ver la página del manual para sed(1).
`NOUSERMACRO` acepta uno o más nombres en su argumento, separados por espacios en blanco, comas, dos puntos o punto y coma.
`OUTBASE`

Si el archivo de salida es el archivo de salida estándar, se inserta `-`.
`OUTDIR`

El nombre de ruta es un designador, no necesariamente absoluto, del directorio en el que se encuentra el archivo de salida. Si el archivo de salida se indica como, por ejemplo, `-o out`, entonces `OUTDIR` simplemente inserta un punto.
Si el archivo de salida es el archivo de salida estándar, también se inserta un punto.

`PARAGRAPH`
`PARAGRAPH` no es realmente una función incorporada, pero como Yodl maneja los párrafos de una manera especial, es probable que sea útil describir el manejo de párrafos de todos modos. A partir de Yodl 2.00 `PARAGRAPH` opera de la siguiente manera:
Si la macro no está definida, los párrafos nuevos, definidos como series de líneas vacías consecutivas escritas en el flujo de salida, no se manejan de manera diferente a cualquier otra serie de caracteres enviados al flujo de salida. Es decir, se insertan en ese flujo.
Sin embargo, si la macro ha sido definida, Yodl la llama cada vez que un nuevo párrafo (definido como una serie de al menos dos líneas en blanco en) ha sido reconocido.
Las líneas en blanco que fueron realmente reconocidas se pueden obtener dentro de la macro `PARAGRAPH’ a partir del símbolo `XXparagraph’, *si* este símbolo se ha definido para entonces. Si se define, contiene el espacio en blanco que hizo que Yodl llamara a la macro `PARAGRAPH’.
Tenga en cuenta que, para inspeccionar `XXparagraph’, primero debe haber sido definido. Yodl mismo *no* define este símbolo.
La macro `PARAGRAPH’ debe definirse como una macro que no espera argumentos. Por lo tanto, se le da a la macro la oportunidad de procesar el párrafo de una manera que sea adecuada para el tipo de conversión particular. Si la macro `PARAGRAPH’ produce series de líneas en blanco por sí misma, entonces esas líneas en blanco *no* hacen que Yodl active `PARAGRAPH’. Por lo tanto, Yodl en sí mismo no llamará recursivamente a `PARAGRAPH’, aunque la macro podría llamarse a sí misma recursivamente. Por supuesto, tal activación recursiva de `PARAGRAPH’ es entonces responsabilidad exclusiva del autor de la macro, y no de Yodl.
Algunos lenguajes de documentos no necesitan inicios de párrafo; por ejemplo, LaTeX maneja sus propios párrafos. Otros lenguajes de documentos sí lo necesitan: típicamente, `PARAGRAPH’ se define entonces en un archivo de macros para activar alguna acción especial. Por ejemplo, un conversor HTML podría definir un párrafo como: 
    DEFINEMACRO(PARAGRAPH)(0)(
        XXnl()
        NOTRANS(<p>)
    )
Un sistema como `xml’ tiene requisitos más estrictos. Aquí los párrafos deben abrirse y cerrarse utilizando pares de etiquetas `<p>’ y `</p>’. En esos casos, se puede usar un contador auxiliar para indicar si hay un párrafo abierto o no. La macro `PARAGRAPH’ podría verificar esto de la siguiente manera, asumiendo la disponibilidad de un contador `XXp’: 
    DEFINEMACRO(PARAGRAPH)(0)(
        XXnl()
        IFZERO(XXp)(
        )(
            NOTRANS(</p>)
        )
        NOTRANS(<p>)
        SETCOUNTER(XXp)(1)
    )
Tenga en cuenta que el fragmento anterior ejemplifica un enfoque, no necesariamente *la* implementación de la macro `PARAGRAPH’ para un conversor xml.
`PIPETHROUGH’
La función incorporada `PIPETHROUGH’ es, además de `SYSTEM’, la segunda función con la que un documento Yodl puede afectar su entorno. `PIPETHROUGH’ puede ser muy útil. Utiliza un programa externo para lograr características especiales. La idea es que se inicie un comando externo, al que se le envía un bloque de texto desde dentro de un documento Yodl. La salida de ese programa hijo se redirige de nuevo al documento Yodl; por lo tanto, un bloque de texto se `redirige a través’ de un programa externo. Lo que se recibe nuevamente en la ejecución de Yodl, se procesa adicionalmente.
La función `PIPETHROUGH’ toma dos argumentos:
o
el comando a ejecutar y
o
el texto a enviar a ese comando.
Funcionalmente, la ocurrencia de la función `PIPETHROUGH’ y de sus dos argumentos es reemplazada por lo que el programa hijo produce en su salida estándar.
Un ejemplo podría ser la inclusión de la fecha actual, como en:
La fecha actual es:
PIPETHROUGH(date)()
En este ejemplo, el comando es `date’ y el texto a enviar a ese programa es vacío.
El propósito principal de esta función es proporcionar una forma mediante la cual los programas externos puedan usarse para crear, por ejemplo, tablas o figuras para un formato de salida dado. Lanzamientos futuros de Yodl pueden contener tales programas dedicados para los formatos de salida.
`POPCHARTABLE’
Las tablas de caracteres que se insertan en la pila de tablas usando `PUSHCHARTABLE()’ se restauran (se extraen) usando `POPCHARTABLE()’. Para una descripción de este mecanismo, consulte la sección `[PUSHINGTABLES]’.
`POPCOUNTER’
`POPCOUNTER’ se utiliza para eliminar el contador superior de la pila de contadores. Los valores de los contadores se pueden insertar en una pila usando PUSHCOUNTER `[PUSHCOUNTER]’. Para eliminar el elemento superior de la pila de un contador, está disponible `POPCOUNTER’. `POPCOUNTER’ espera un argumento: el nombre del contador a extraer. El valor previamente insertado se convierte entonces en el nuevo valor del contador. El valor de un contador puede extraerse después de definirlo, después de lo cual la pila está vacía, pero el contador seguirá estando definido. En ese caso, usar el valor del contador se considera un error.
Ejemplos: 
    DEFINECOUNTER(YEAR)(1950)
    POPCOUNTER(YEAR)
    COMMENT(YEAR ahora tiene un valor indefinido)
Ver también la sección `[COUNTERS]’.
`POPMACRO’
`POPMACRO’ se utiliza para eliminar la definición de macro actual, restaurando una definición previamente insertada. Los valores de las macros se pueden insertar en una pila usando PUSHMACRO.
Para eliminar el elemento superior de la pila de una macro, está disponible `POPMACRO’. `POPMACRO’ espera un argumento: el nombre de la macro a extraer. El valor previamente insertado se convierte entonces en el nuevo valor de la macro.
El valor de una macro puede extraerse después de definirla, después de lo cual su pila está vacía. En ese caso, usar la macro (aunque el nombre de la macro todavía esté definido) se considera un error.
Ejemplo: 
    DEFINEMACRO(Hello)(1)(Hello, ARG1, esto es una definición de macro)
    Hello(Karel)
    PUSHMACRO(Hello)(1)(Hello, ARG1, esta es la nueva definición)
    Hello(Karel)
    POPMACRO(Hello)
    Hello(Karel)
    COMMENT(La tercera activación de Hello() produce la misma salida
            que la primera activación)
`POPSUBST’
`POPSUBST’ se utiliza para volver a un nivel anterior de interpretación de las definiciones de `SUBST’. Consulte las descripciones de los comandos incorporados `PUSHSUBST’ y `SUBST’ a continuación para obtener detalles.
No hay límite al número de veces que se puede llamar a `POPSUBST’. Una vez que la "pila PUSHSUBST" está vacía, las definiciones de `SUBST’ se interpretan automáticamente (por lo que nunca se produce un error de desbordamiento de pila inferior).
`POPSYMBOL’
`POPSYMBOL’ se utiliza para eliminar el símbolo superior de la pila de símbolos. Los valores de los símbolos se pueden insertar en una pila usando PUSHSYMBOL `[PUSHSYMBOL]’. Para eliminar el elemento superior de la pila de un símbolo, está disponible `POPSYMBOL’.
`POPSYMBOL’ espera un argumento: el nombre del símbolo a extraer. El valor previamente insertado se convierte entonces en el nuevo valor del símbolo.
El valor de un símbolo puede extraerse después de definirlo, después de lo cual su pila está vacía. En ese caso, usar el símbolo (aunque el nombre del símbolo todavía esté definido) se considera un error.
Ejemplo: 
    DEFINESYMBOL(YEAR)(Esto sucedió en 1950)
    POPSYMBOL(YEAR)
    COMMENT(YEAR ahora tiene un valor indefinido)
`POPWSLEVEL’
`POPWSLEVEL’ se utiliza para eliminar el nivel de espacio en blanco superior de la pila de niveles de espacio en blanco. Los valores de los niveles de espacio en blanco se pueden insertar en una pila usando PUSHWSLEVEL `[PUSHWSLEVEL]’. Ver también la sección DECWSLEVEL `[DECWSLEVEL]’
Para eliminar el elemento superior de la pila de un nivel de espacio en blanco, está disponible `POPWSLEVEL’. `POPWSLEVEL’ espera un argumento: el nombre del nivel de espacio en blanco a extraer. El valor previamente insertado se convierte entonces en el nuevo valor del nivel de espacio en blanco. El valor de un nivel de espacio en blanco puede extraerse después de definirlo, vaciando la pila, pero el nivel de espacio en blanco seguirá estando definido. En ese caso, usar el valor del nivel de espacio en blanco se considera un error.
Ejemplo: 
    COMMENT(Asumir que el nivel de WS es cero)
    PUSHWSLEVEL(1)
    COMMENT(El nivel de WS ahora es 1)
    POPWSLEVEL()
    COMMENT(El nivel de WS ahora es 0 de nuevo)
`PUSHCHARTABLE’
Una vez que se ha definido una tabla de caracteres, se puede *insertar* en una pila usando `PUSHCHARTABLE’. La tabla de caracteres insertada puede ser *extraída* más tarde. `PUSHCHARTABLE’ se describe con más detalle en la sección `[PUSHINGTABLES]’.
`PUSHCOUNTER’
`PUSHCOUNTER’ se utiliza para iniciar otra vida útil para un contador, insertando su valor actual en una pila. Hay una pila disponible para cada contador individual.
`PUSHCOUNTER’ espera dos argumentos: el nombre del contador a insertar y una expresión aditiva cuyo valor se convierte en el nuevo valor del contador (después de insertar el valor actual).
La expresión aditiva no puede contener espacios en blanco y puede usar operadores + y -, sus operandos pueden ser valores numéricos enteros o nombres de contadores (definidos). El valor resultante puede ser negativo; en ese caso, se resta un valor del contador de destino.
Cuando el segundo argumento está vacío, el nuevo valor será cero. Especifique el nombre del contador dos veces para simplemente insertar su valor, sin modificar su valor actual.
Ejemplos: 
    DEFINECOUNTER(YEAR)(1950)
    PUSHCOUNTER(YEAR)(1962)
    COMMENT(YEAR ahora tiene el valor 1962, y un valor insertado de 1950)
Ver también la sección `[COUNTERS]’.
`PUSHMACRO’
`PUSHMACRO’ se utiliza para iniciar otra vida útil para una macro, insertando su definición actual en una pila. Hay una pila disponible para cada macro individual.
`PUSHMACRO’ espera tres argumentos: el nombre de la macro a insertar, el número de sus argumentos después de insertar (que puede ser diferente del número de argumentos interpretados por la macro insertada) y su nueva definición.
Por lo tanto, `PUSHMACRO’ se utiliza exactamente como DEFINEMACRO, pero redefine una macro actual (o define una nueva macro si no se definió ninguna macro con el nombre especificado como su primer argumento.
Ejemplo: 
    DEFINEMACRO(Hello)(1)(Hello, ARG1, esto es una definición de macro)
    Hello(Karel)
    PUSHMACRO(Hello)(1)(Hello, ARG1, esta es la nueva definición)
    Hello(Karel)
    POPMACRO(Hello)
    Hello(Karel)
    COMMENT(La tercera activación de Hello() produce la misma salida
            que la primera activación)
`PUSHSUBST’
`PUSHSUBST’ se puede usar para (temporalmente) suprimir la interpretación de las definiciones de `SUBST’ (el comando incorporado `SUBST’ se cubre a continuación, consulte su descripción para ver un ejemplo).
`PUSHSUBST’ espera un argumento: un número entero que es 0 o distinto de cero (comúnmente: 1). Después de llamar a `PUSHSUBST’(0)’, las definiciones de `SUBST’ ya no se interpretan; use `POPSUBST’`()’ para volver al tipo anterior de interpretación. Alternativamente, `PUSHSUBST’`(0)’ se puede usar para apilar otro nivel de interpretaciones de `SUBST’ encima de la
El más usado recientemente.
En un ordenador de 64 bits, la pila `PUSHSUBST’ puede contener algo más de 60 niveles de interpretación de `SUBST’. Cuando se introducen más niveles, los niveles más antiguos se olvidan silenciosamente. Llamar a `POPSUBST’ una vez que la pila `PUSHSUBST’ está vacía resulta en la activación de las interpretaciones de `SUBST’ (y por lo tanto, no se encontrará un error de desbordamiento de pila).
`PUSHSYMBOL’
`PUSHSYMBOL’ se utiliza para iniciar otra vida útil para un símbolo, introduciendo su valor actual en una pila. Hay una pila disponible para cada símbolo individual.
`PUSHSYMBOL’ espera dos argumentos: el nombre del símbolo a introducir y su nuevo texto después de introducirlo. Cuando el segundo argumento es un argumento vacío, el nuevo texto será vacío. El nuevo texto puede especificarse como un texto literal, o como el nombre de un símbolo existente. Especifique el nombre del símbolo dos veces para simplemente introducir su valor, sin modificar su valor actual.
Ejemplos: 
    DEFINESYMBOL(YEAR)(Esto ocurrió en 1950)
    PUSHSYMBOL(YEAR)(Esto ocurrió en 1962)

`PUSHWSLEVEL’
`PUSHWSLEVEL’ se utiliza para iniciar otra vida útil del nivel de espacios en blanco introduciendo el valor actual del nivel en una pila. Véase también la sección INCWSLEVEL `[INCWSLEVEL]’
`PUSHWSLEVEL’ espera un argumento, el nuevo valor del nivel de espacios en blanco. Este valor puede especificarse como un valor numérico o como el nombre de un contador. El argumento puede estar vacío, en cuyo caso el nuevo valor será cero.

`RENAMEMACRO’ toma dos argumentos: el nombre de una macro incorporada (como `INCLUDEFILE’) y su nuevo nombre.
Por ejemplo, después de 
    RENAMEMACRO(INCLUDEFILE)(include)
un archivo *debe* incluirse con `include(archivo)’. `INCLUDEFILE’ ya no puede usarse para esto: después de la acción `RENAMEMACRO’, el nombre antiguo ya no puede usarse; se convierte en un símbolo indefinido.

tanto `INCLUDEFILE’ como `include’ pueden usarse para incluir un archivo.
`SETCOUNTER’
`SETCOUNTER’ espera dos argumentos: el nombre de un contador y una expresión aditiva que define el valor a asignar. El contador debe haber sido creado previamente con `DEFINECOUNTER’.
La expresión aditiva no puede contener espacios en blanco y puede usar los operadores + y -, sus operandos pueden ser valores numéricos enteros o nombres de contadores (definidos). El valor resultante puede ser negativo; en ese caso, se asigna un valor negativo al contador de destino.
Por ejemplo, si `one’ y `two’ son contadores, entonces 
    SETTOCOUNTER(one)(-two)\//    asigna el valor de -two a one
    SETTOCOUNTER(one)(two+two)\// asigna el valor de 2 x two a one
Véase también la sección `[COUNTERS]’.
`SETSYMBOL’
`SETSYMBOL’ espera dos argumentos: el nombre de un símbolo y el texto a asignar al símbolo nombrado. El símbolo debe haber sido previamente definido por `DEFINESYMBOL’.
`SUBST’
`SUBST’ es un mecanismo de sustitución de propósito general para cadenas que aparecen en la entrada. `SUBST’ toma dos argumentos: una cadena de búsqueda y una cadena de sustitución. Por ejemplo, después de 
    SUBST(VERSION)(1.00)
YODL transforma todas las ocurrencias de `VERSION’ en su entrada en `1.00’.
`SUBST’ también es útil en situaciones donde secuencias de varios caracteres deben convertirse a caracteres acentuados. Por ejemplo, un convertidor de LaTeX podría definir: 
    SUBST(’e)(+NOTRANS(\’{e}))
Cada `’e’ en la entrada se convertirá posteriormente en `e’.
`SUBST’ puede usarse en combinación con la bandera de la línea de comandos `-P’, como en una invocación 
    yodl2html -P’SUBST(VERSION)(1.00)’ myfile.yo
Otra sustitución útil podría ser: 
    SUBST(_OP_)(CHAR(40))
    SUBST(_CP_)(CHAR(41))
que define un paréntesis de apertura (`_OP_’) y un paréntesis de cierre (`_CP_’) como mapeados a la función `CHAR’. Las cadenas `_OP_’ y `_CP_’ podrían usarse entonces para producir argumentos desequilibrados.
Tenga en cuenta que:
o
El primer argumento del comando `SUBST’, la cadena de búsqueda, se toma literalmente. Yodl no lo expande; la cadena debe coincidir literalmente en la entrada.
o
El segundo argumento, el reemplazo, es procesado adicionalmente por Yodl. Proteja este texto con `NOTRANS’ o `NOEXPAND’ donde sea apropiado.
Las sustituciones ocurren muy temprano mientras YODL procesa sus archivos de entrada. Para procesar sus archivos de entrada, YODL sigue estos pasos:
1.
Solicita entrada a su analizador léxico (los llamados *tokens*)
2.
Su analizador procesa los tokens producidos por el analizador léxico
3.
Su analizador puede enviar texto a un `objeto’ de salida, que eventualmente aparece en el archivo de salida generado por YODL. YODL realiza todas las sustituciones de macro en el paso 2, y todas las conversiones de tabla de caracteres en el paso 3. Sin embargo, el analizador léxico tiene acceso a las definiciones de `SUBST’: tan pronto como su analizador léxico detecta una serie de caracteres que coinciden con la secuencia definitoria de una definición de `SUBST’, reemplaza esa secuencia definitoria por su definición. Esa definición es entonces leída nuevamente por el analizador léxico. Por supuesto, esta definición puede, a su vez, contener secuencias definitorias de otras definiciones de `SUBST’: estas se reemplazan por sus definiciones también. Esto implica:
o
Definiciones circulares pueden hacer que el analizador léxico se quede atascado en un bucle de reemplazo. Es responsabilidad del autor que define las definiciones de `SUBST’ asegurarse de que esto no suceda.
o
Ni el analizador, ni el objeto de salida ven nunca las secuencias de caracteres definitorias de `SUBST’: solo ven sus definiciones.
En algunos casos, las sustituciones deben suprimirse. Considere las cadenas de texto entre comillas dobles que se usan frecuentemente en lenguajes de programación. Por ejemplo, `"hola mundo"’. El texto dentro de la cadena no debe ser convertido por Yodl, pero a menos que las sustituciones puedan suprimirse, la cadena 
"\"código malicioso"
aparece como 
"código malicioso"
Para suprimir la interpretación de las definiciones de `SUBST’, se puede usar `PUSHSUBST’, introducido anteriormente. La macro predefinida `verb’ suprime la interpretación de las definiciones de `SUBST’ comenzando con `PUSHSUBST’(0)’ y terminando con `POPSUBST’`()’.

`SYSTEM’ puede ser útil de muchas maneras. Por ejemplo, podrías querer registrar cuándo alguien procesa tu documento, como en: 
    SYSTEM(echo Documento procesado! | mail yo@mi.host)
Tenga en cuenta que `SYSTEM’ simplemente realiza una tarea relacionada con el sistema. Es un proceso que está separado del proceso YODL en sí. Una de las consecuencias de esto es que cualquier salida generada por `SYSTEM’ normalmente no aparece en el archivo de salida de YODL. Si la salida de un subproceso debe insertarse en el archivo de salida de YODL, use PIPETHROUGH `[PIPETHROUGH]’, o inserte un archivo temporal como se muestra en el siguiente ejemplo: 
    SYSTEM(date > datefile)
    La fecha actual es:
    INCLUDEFILE(datefile)
    SYSTEM(rm datefile)
`TYPEOUT’
`TYPEOUT’ requiere un argumento. El texto de la lista se envía al flujo de error estándar, seguido de una nueva línea. Esta característica puede ser útil para mostrar, por ejemplo, mensajes como números de versión en archivos de paquetes de macros.
Ejemplo: La siguiente macro incluye un archivo y escribe en la pantalla que este archivo se está procesando actualmente. 
    DEFINEMACRO(includefile)(1)(
        TYPEOUT(Procesando el documento: ARG1)
        INCLUDEFILE(ARG1)
    )
`UPPERCASE’
`UPPERCASE’ convierte una cadena o una parte de ella a mayúsculas. Tiene dos argumentos:
o
La cadena a convertir;
o
Una longitud, que indica cuántos caracteres (a partir del principio de la cadena) deben convertirse. El indicador de longitud puede ser menor que uno o mayor que la longitud de la cadena; en ese caso, se convierte toda la cadena.
Ejemplo: 
    UPPERCASE(hola mundo)(1)
    UPPERCASE(hola mundo)(5)
    UPPERCASE(hola mundo)(0)
Esta muestra de código se expande a: 
    Hola mundo
    HOLA mundo
    HOLA MUNDO
`USECHARTABLE’
`USECHARTABLE’ toma un argumento: el nombre de una tabla de traducción a activar. La tabla debe haber sido definida previamente usando `DEFINECHARTABLE’. Véase la sección `[CHARTABLES]’ para una descripción de las tablas de traducción de caracteres.
Alternativamente, el nombre puede estar vacío en cuyo caso se restaura el mapeo de caracteres predeterminado.
`USECOUNTER’
`USECOUNTER’ es una combinación de `ADDTOCOUNTER’ y `COUNTERVALUE’. Espera un argumento: el nombre de un contador definido (ver DEFINECOUNTER `[DEFINECOUNTER]’).
El contador se incrementa primero en 1. Luego la función se expande al valor del contador.
Véase también la sección `[COUNTERS]’.

VERBOSITY

The `VERBOSITY' macro controls the verbosity of Yodl's output.

VERBOSITY(action, levels)
The `VERBOSITY' macro is useful to set or change the verbosity of Yodl to debug the expansion of a macro or the processing of a YODL input file.
The first argument indicates the processing mode of the second argument, and it may be:
o
Empty, in which case the message-level is set to the value specified in the second argument;
o
+’, in which case the value specified in the second argument augments the current message level;
o
-’, in which case the value specified in the second argument augments is removed from the current message level
The second argument specifies one or more, separated by blanks, message level names or it may be set to a hexadecimal value (starting with 0x’), using hexadecimal values to represent message levels. Also, `NONE’ may be used, to specify no message level, or `ALL’ can be used to specify all message levels.
The following message levels are defined:
o
ALERT (0x40). When an alert-error occurs, Yodl terminates. Here Yodl requests something of the system (like a `get_cwd()’), but the system fails.
o
CRITICAL (0x20). When a critical error occurs, Yodl terminates. The message itself can be suppressed, but exiting can’t. A critical condition is, e.g., the omission of an open parenthesis at a location where a parenthesized argument should appear, or a non-existing file in an `INCLUDEFILE’ specification (as this file should be parsed). A non-existing file with a `NOEXPANDINCLUDE’ specification is a plain (non-critical) error.
o
DEBUG (0x01). Probably too much info, like getting information about each character that was read by Yodl.
o
ERROR (0x10). An error (like doubly defined symbols). Error messages will not stop the parsing of the input (up to a maximum number of errors), but no output is generated.
o
INFO (0x02). Not as detailed as `debug’, but still very much info, like information about media switches.
o
NOTICE (0x04). Information about, e.g., calls to the builtin function calls.
o
WARNING (0x08). Something you should know about, but probably not affecting Yodl’s proper functioning
There also exists a level EMERG (0x80) which cannot be suppressed.
The value `0x00’ represents `NONE’, the value `0xff’ represents `ALL’.
When specifying multiple message levels using the hexadecimal form, their hexadecimal values should be binary-or-ed: adding them is ok, as long as you don’t specify `ALL’: 
    VERBOSITY()(0x06)
    COMMENT(this specifies `INFO’ and `NOTICE’)
When specifying message levels by their names, the names may be truncated at a unique point. However, the message level names are interpreted case sensitively, so `INF’ for `INFO’ is recognized as such, but `info’ for `INFO’ isn’t. The following examples all specify verbosity levels INFO and NOTICE: 
    VERBOSITY()(I N)
    VERBOSITY()(N I)
    VERBOSITY()(NOT IN)
    VERBOSITY()(INFO NOTICE)
`WARNING’
`WARNING’ takes one argument: text to display as a warning. The `yodl’ program makes sure that before showing the text, the current file and line number are printed. Other than this, `WARNING’ works just as `TYPEOUT’ (see section `[TYPEOUT]’).
Note that an analogous function `ERROR’ exists, which prints a message and then terminates the program (see section `[ERROR]’).
