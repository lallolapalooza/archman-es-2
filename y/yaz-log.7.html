YAZ-LOG(7) Convenciones y varios YAZ-LOG(7)

NOMBRE

yaz-log - Manejo de registros en todos los programas basados en yaz

SINOPSIS

yaz-XXXX [-v nivel_registro,...] [-l archivo_registro]

DESCRIPCIÓN

Todos los programas basados en YAZ utilizan un subsistema de registro común y deberían soportar opciones de línea de comandos comunes para controlarlo. Esta página del manual documenta esas opciones.

OPCIONES

-l archivo_registro

Especifica el archivo donde se escribirá el registro. Si no se especifica ninguno, se utiliza stderr. El registro se añade a este archivo. Si el archivo crece demasiado, se rota silenciosamente: se renombra a archivo_registro.1, archivo_registro.2, .., 9 (el archivo antiguo se elimina) y se abre un nuevo archivo. El límite por defecto es 1 GB, pero puede ser establecido por el programa. El límite de rotación se puede especificar con la opción -r para el servidor frontal YAZ (yaz-ztest).

La rotación también puede habilitarse implícitamente utilizando un nombre de archivo que se cambia para una fecha dada, debido a sustituciones según lo dado por la función strftime(3).

-v nivel_registro

Especifica el nivel de registro. El argumento es un conjunto de nombres de niveles de registro, separados por comas (¡sin espacios!), opcionalmente precedidos por un '-' para negar ese nivel. La mayoría de los programas tienen su propio valor por defecto, que a menudo contiene fatal, warn, log, y algunos valores específicos de la aplicación. La lista por defecto puede ser borrada con la palabra none, o los bits individuales pueden ser eliminados prefijándolos con un guion '-'.

NIVELES DE REGISTRO PARA CONTROLAR EL REGISTRO

Algunos de los niveles de registro controlan la forma en que se escribe el registro.

flush hace que el registro se vacíe después de cada escritura. Esto puede tener serias implicaciones en el rendimiento y no debe usarse en producción. Por otro lado, al depurar un bloqueo del programa, esto puede ser extremadamente útil. La opción debug también implica flush.

notime evita la escritura de marcas de tiempo. Esto está destinado a scripts de prueba automáticos, que deben producir archivos de registro predecibles y fáciles de comparar.

NIVELES DE REGISTRO GENERALES EN YAZ MISMO

YAZ utiliza los siguientes niveles de registro:

fatal para errores fatales, que impiden la ejecución posterior del programa.

warn para advertencias sobre cosas que deberían corregirse.

debug para depuración. Este indicador puede usarse temporalmente al desarrollar o depurar yaz, o un programa que utiliza yaz. Está prácticamente obsoleto, deberías definir y usar tus propios niveles de registro (ver abajo).

all activa casi todos los niveles de registro codificados.

loglevel registra información sobre los niveles de registro utilizados por el programa. Cada vez que se cambia el nivel de registro, se lista todos los bits que están activados. Cada vez que un módulo solicita sus bits de registro, se registra. Esto se puede usar para tener una idea de qué niveles de registro están disponibles en cualquier programa que use yaz-log. Inicia el programa con -v none,loglevel, y realiza algunas operaciones comunes con él. Otra forma es buscar yaz_log_module_level en el código fuente, como en

      find . -name '*.[ch]' -print |
         xargs grep yaz_log_module_level |
         grep '"' |
         cut -d'"' -f2 |
         sort -u

eventl, malloc, nmem, odr se utilizan internamente para depurar yaz.

NIVELES DE REGISTRO PARA CLIENTES

zoom registra las llamadas a la API de zoom, lo que puede ser útil para depurar aplicaciones cliente.

NIVELES DE REGISTRO PARA SERVIDORES

server registra las funciones del servidor a un alto nivel, inicio, escucha en un puerto, etc.

session registra sesiones individuales (conexiones).

request registra una línea por cada solicitud (init, search, etc.).

requestdetail registra los detalles de cada solicitud, antes de que se pase al backend, y los resultados recibidos del mismo.

Se supone que cada programa servidor (zebra, etc.) define sus propios niveles de registro además de estos. Como dependen del servidor en cuestión, no se pueden describir aquí. Ver arriba cómo averiguarlos.

EJEMPLOS DE NOMBRE DE ARCHIVO DE REGISTRO

Un archivo con formato my_YYYYMMDD.log (donde Y, M, D son los dígitos del año, mes y día) se da de la siguiente manera: -l my_%Y%m%d.log . Y dado que el nombre del archivo depende del día, la rotación ocurrirá a medianoche.

Un registro semanal podría especificarse como -l my_%Y%U.log.
