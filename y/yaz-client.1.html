NOMBRE

yaz-client - Cliente Z39.50/SRU para implementadores

SINOPSIS

yaz-client [-a apdulog] [-b berdump] [-c cclfile] [-d dump] [-f cmdfile] [-k size] [-m marclog] [-p proxy-addr] [-q cqlfile] [-t dispcharset] [-u auth] [-v loglevel] [-V] [-x] [server-addr]

DESCRIPCIÓN

yaz-client es un cliente Z39.50[1]/SRU[2] (origen) con una interfaz de línea de comandos simple que te permite probar el comportamiento y el rendimiento de los objetivos Z39.50 y los servidores SRU.

Desde la versión 4.1.0 de YAZ, yaz-client también puede funcionar como cliente de servicio web Solr[3].

Si se especifica server-addr, el cliente crea una conexión con el objetivo Z39.50/SRU en la dirección dada.

Cuando se inicia yaz-client, intenta leer comandos de uno de los siguientes archivos:

•Archivo de comandos si se proporciona con la opción -f.
•.yazclientrc en el directorio de trabajo actual.
•.yazclientrc en el directorio de inicio del usuario. El valor de la variable de entorno $HOME se utiliza para determinar el directorio de inicio. Normalmente, $HOME solo se establece en sistemas POSIX como Linux, FreeBSD, Solaris.

OPCIONES

-a filename

Si se especifica, el registro de paquetes de protocolo se añadirá al archivo dado. Si filename se especifica como -, la salida se escribe en stdout.

-b filename

Si se especifica, YAZ volcará los datos BER en notación legible en el archivo especificado. Si filename se especifica como - la salida se escribe en stdout.

-c filename

Si se especifica, la configuración CCL se leerá del archivo dado.

-d dump

Si se especifica, YAZ volcará los datos BER de todas las PDUs enviadas y recibidas en archivos individuales, nombrados dump.DDD.raw, donde DDD es 001, 002, 003, ...

-f cmdfile

Lee comandos de cmdfile. Cuando se utiliza esta opción, el cliente YAZ no lee .yazclientrc del directorio actual o del directorio de inicio.

-k size

Establece el tamaño preferido de mensajes y el tamaño máximo de registro para la Solicitud de Inicialización en kilobytes. El valor predeterminado es 65536 (64 MB).

-m filename

Si se especifica, los registros recuperados se añadirán al archivo dado.

-p proxy-addr

Si se especifica, el cliente utilizará el proxy en la dirección dada. El cliente YAZ se conectará a un proxy en la dirección y puerto dados. El objetivo real se especificará como parte de la InitRequest para informar al proxy sobre el objetivo real.

-q filename

Si se especifica, la configuración CQL se leerá del archivo dado.

-t displaycharset

Si se proporciona displaycharset, especifica el nombre del juego de caracteres de la salida (en la terminal en la que se está ejecutando YAZ client).

-u auth

Si se especifica, la cadena auth se utilizará para la autenticación.

-v level

Establece el nivel de LOG a level. El nivel es una secuencia de tokens separados por comas. Cada token es un entero o un elemento de LOG con nombre: fatal, debug, warn, log, malloc, all, none.

-V

Imprime la versión de YAZ.

-x

Hace que el cliente YAZ imprima volcados hexadecimales de los paquetes enviados y recibidos en la salida estándar.

COMANDOS

El cliente YAZ acepta los siguientes comandos.

open zurl

Abre una conexión a un servidor. La sintaxis de zurl es la misma que se describe anteriormente para conectarse desde la línea de comandos.

Sintaxis:

[(tcp|ssl|unix|http)':']host [:port][/base]

quit

Sale del cliente YAZ

find query

Envía una Solicitud de Búsqueda utilizando la query dada. Por defecto, se asume que la consulta es PQF. Consulte el comando querytype para más información.

delete setname

Elimina el conjunto de resultados con el nombre setname en el servidor.

base base1 base2 ...

Establece los nombres de las bases de datos a buscar. Se pueden especificar una o más bases de datos, separadas por espacios. Este comando anula la base de datos dada en zurl.

show [start[+number [+resultset]]]

Recupera registros enviando una Solicitud Presentar desde la posición de inicio dada por start y un número de registros dado por number, desde el conjunto de resultados resultset. Si start no se da, el cliente recuperará desde la posición del último registro recuperado más 1. Si number no se da, se recuperará un registro a la vez. Si resultset no se da, se utiliza el conjunto de resultados recuperado más recientemente.

scan term

Busca en el índice de la base de datos un término. La sintaxis se asemeja a la sintaxis de find. Si quieres buscar la palabra "water", puedes escribir 
      scan water

pero si quieres buscar solo en, por ejemplo, el campo de título, escribirías

      scan @attr 1=4 water

setscan set term

Busca en el índice de la base de datos un término dentro de un conjunto de resultados. Esto es similar al comando scan pero tiene un conjunto de resultados como su primer argumento.

scanpos pos

Establece la posición preferida para el escaneo. Este valor se utiliza en el próximo escaneo. Por defecto, la posición es 1.

scansize size

Establece el número de entradas a devolver por el escaneo. El número predeterminado de entradas es 20.

scanstep step

Establece el tamaño del paso para el escaneo. Este valor se utiliza en el próximo escaneo enviado al objetivo. Por defecto, el tamaño del paso es 0.

sort sortspecs

Ordena un conjunto de resultados. El comando sort toma una secuencia de especificaciones de ordenación separadas por espacios, y cada especificación de ordenación consta de dos palabras separadas por espacios (por lo que la lista de especificaciones completa consta de un número par de palabras). La primera palabra de cada especificación contiene un campo (criterio de ordenación) y la segunda contiene indicadores. Si el criterio de ordenación incluye =, se asume que la Clave de Ordenación es de tipo sortAttributes utilizando Bib-1: en este caso, el entero antes de = es el tipo de atributo y el entero que sigue a = es el valor del atributo. Si no hay un carácter = en el criterio, se trata como un campo de ordenación de tipo InternationalString. La palabra de indicadores de cada especificación de ordenación debe constar de s para sensible a mayúsculas/minúsculas o i para insensible a mayúsculas/minúsculas, y < para orden ascendente o > para orden descendente.

Ejemplo usando criterio de ordenación con atributos use=local-number y structure=numeric y un indicador ascendente: 1=12,4=109 <

Otro ejemplo con el campo de ordenación "Title" e indicador descendente: Title >

sort+

Igual que sort pero almacena el conjunto de resultados ordenado en un nuevo conjunto de resultados.

authentication [auth1 [auth2 [auth3]]]

Configura las cadenas de autenticación que se enviarán al servidor. Pueden seguir cero, una, dos o tres argumentos al comando auth.

Si no se dan argumentos (0), no se envía ninguna cadena de autenticación.

Si se da un argumento, se utiliza la autenticación de estilo de apertura Z39.50 v2. Una convención común para la cadena auth1 es que el nombre de usuario y la contraseña estén separados por una barra, por ejemplo, nombredeusuario/contraseñasecreta.

Si se dan dos o más argumentos, se utiliza la autenticación Z39.50 v3, en cuyo caso el primer argumento se utiliza como nombre de usuario, el segundo argumento como grupo y el tercer argumento como contraseña. Si solo se dan dos argumentos, se asume que el grupo está vacío.

Al igual que con otros comandos en yaz-client, los argumentos se separan por espacios. Se puede utilizar un carácter de barra invertida para incluir un carácter literalmente. Por ejemplo, auth miusuario a\ b es un comando auth de dos argumentos donde el usuario es miusuario y la contraseña es a b.

AUTHENTICATION

La cadena de autenticación se envía primero al servidor cuando se emite el comando open y se envía la Solicitud de Inicialización Z39.50, por lo que este comando debe usarse antes de open para que sea efectivo.

SRU

sru method version

Selecciona el método y la versión del Servicio Web. Debe ser uno de post, get, soap (por defecto) o solr. La versión debe ser 1.1, 1.2 o 2.0 para SRU. Se permiten otras versiones para fines de prueba (negociación de versión con el servidor SRU). La versión no se utiliza actualmente para los Servicios Web de Solr.

list_all

Este comando muestra el estado y los valores de muchas configuraciones.

lslb

lslb n

Establece el límite para cuando no se deben devolver registros junto con el resultado de la búsqueda. Consulte el estándar Z39.50 sobre límites de conjuntos[4] para obtener más detalles.

ssub

ssub n

Establece el límite para cuando se deben devolver todos los registros con el resultado de la búsqueda. Consulte el estándar Z39.50 sobre límites de conjuntos[4] para obtener más detalles.

mspn

mspn n

Establece el número de registros que deben devolverse si el número de registros en el conjunto de resultados está entre los valores de lslb y ssub. Consulte el estándar Z39.50 sobre límites de conjuntos[4] para obtener más detalles.

status

Muestra los valores de lslb, ssub y mspn.

setname

Activa y desactiva los conjuntos de resultados con nombre. Por defecto está activado.

cancel

Envía una Solicitud de Control de Recursos Disparador al destino.

facets

facets spec

Especifica las facetas solicitadas que se utilizarán en la búsqueda. La notación se especifica en ???.

format

format oid

Establece la sintaxis de transferencia preferida para los registros recuperados. yaz-client admite todas las sintaxis de registro que están actualmente registradas. Consulte los Identificadores de Sintaxis de Registro Z39.50[5] para obtener más detalles. Las sintaxis de registro utilizadas comúnmente incluyen usmarc, sutrs y xml.

elements

elements e

Establece el nombre del conjunto de elementos para los registros. Muchos destinos admiten los conjuntos de elementos B (para breve) y F (para completo).

close

Envía un APDU de Cierre Z39.50 y cierra la conexión con el par.

querytype

querytype type

Establece el tipo de consulta tal como lo utiliza el comando find. Se admite lo siguiente: prefix para Notación de Consulta de Prefijo (Consulta de Tipo 1); ccl para búsqueda CCL (Consulta de Tipo 2), cql para CQL (búsqueda de Tipo 104 con OID CQL), ccl2rpn para conversión de CCL a RPN (Consulta de Tipo 1), cql2rpn para conversión de CQL a RPN (Consulta de Tipo 1).

attributeset

attributeset set

Establece el OID del conjunto de atributos para consultas de prefijo (RPN, Tipo 1).

refid

refid id

Establece el ID de referencia para la(s) Solicitud(es) Z39.50.

itemorder

itemorder type no

Envía una Solicitud de Orden de Artículo utilizando el ILL Externo. type es 1 o 2, que corresponden a ILL-Profile 1 y 2 respectivamente. El no es la posición en el conjunto de resultados del registro que se va a solicitar.

update

update action recid doc

Envía una Solicitud de Actualización de Artículo. El argumento action debe ser el tipo de acción: una de insert, replace, delete y update. El segundo argumento, recid, es el identificador del registro (cualquier cadena). El tercer argumento, que es opcional, es el documento del registro para la solicitud. Si doc va precedido por "<", entonces los caracteres siguientes se tratarán como un nombre de archivo con los registros que se van a actualizar. De lo contrario, doc se tratará como un documento en sí. doc también puede ir entre comillas dobles. Si se omite doc, se utilizará el último registro recibido (como parte de la respuesta present o la respuesta de búsqueda piggybacked) para la actualización.

source

source filename

Ejecuta la lista de comandos del archivo filename, igual que 'source' en la mayoría de los shells de UNIX. Se puede utilizar un solo punto (.) como alternativa.

!

! args

Ejecuta el comando args en un subshell usando la llamada al sistema.

push_command

push_command command

push_command toma otro comando como su argumento. Ese comando se agrega a la información del historial (para que pueda recuperarlo más tarde). El comando en sí no se ejecuta. Este comando solo funciona si tiene habilitado GNU readline/history.

set_apdufile

set_apdufile filename

Establece que el APDU se registrará en el archivo filename. Otra forma de lograr el registro APDU es usando la opción de línea de comandos -a.

set_auto_reconnect

set_auto_reconnect flag

Especifica si el cliente YAZ se reconecta automáticamente si el destino cierra la conexión (solo Z39.50).

flag debe ser on u off.

set_auto_wait

set_auto_wait flag

Especifica si el cliente YAZ debe esperar paquetes de protocolo de respuesta después de una solicitud. Por defecto, el cliente YAZ espera (on) los paquetes de respuesta inmediatamente después de emitir un comando (find, show). Si se usa off, el cliente YAZ no intenta recibir paquetes automáticamente. Estos tendrán que ser recibidos manualmente cuando se use el comando wait_response.

flag debe ser on u off.

set_marcdump

set_marcdump filename

Especifica que todos los registros recuperados se agregarán al archivo filename. Este comando hace lo mismo que la opción -m.

schema

schema schemaid

Especifica el esquema para la recuperación. El esquema puede ser especificado como un OID para Z39.50. Para SRU, el esquema es una simple URI de cadena.

charset

charset negotiationcharset [displaycharset] [[marccharset]]

Especifica el conjunto de caracteres (codificación) para la negociación Z39.50 / codificación SRU y/o el conjunto de caracteres para la salida (terminal).

negotiationcharset es el nombre del conjunto de caracteres que será negociado por el servidor. El nombre especial - para negotiationcharset especifica ningún conjunto de caracteres que se negociará.

Si se proporciona displaycharset, especifica el nombre del conjunto de caracteres de la salida (en la terminal en la que se ejecuta el cliente YAZ). Para deshabilitar la conversión de caracteres a la codificación de salida, se puede usar el nombre especial - (guion). Si se da el nombre especial auto, el cliente YAZ convertirá las cadenas a la codificación de la terminal tal como la devuelve la llamada nl_langinfo.

Si se proporciona marccharset, especifica el nombre del conjunto de caracteres de los registros MARC recuperados del servidor. Consulte también el comando marccharset.


Nota
Dado que la negociación del conjunto de caracteres entra en vigor en la Solicitud de Inicialización Z39.50, debe emitir este comando antes de usar el comando open.

Nota
Los registros MARC no están cubiertos por la negociación del conjunto de caracteres Z39.50, por lo que hay un carácter separado que debe conocerse para realizar conversiones significativas.

negcharset

negcharset charset

Especifica el conjunto de caracteres para la negociación (Z39.50). El argumento es el mismo que el segundo argumento para el comando charset.

displaycharset

displaycharset charset

Especifica el conjunto de caracteres para la salida (visualización). El argumento es el mismo que el segundo argumento para el comando charset.

marccharset

marccharset charset

Especifica el conjunto de caracteres para los registros MARC recuperados para que el cliente YAZ pueda mostrarlos en un carácter adecuado para su pantalla. Consulte el comando charset. Si se indica auto, YAZ asumirá que MARC21/USMARC utiliza MARC8/UTF8 e ISO-8859-1 para todas las demás variantes de MARC. El argumento charset es el mismo que el tercer argumento para el comando charset.

querycharset

querycharset charset

Especifica el conjunto de caracteres para los términos de consulta para las consultas RPN Z39.50 y las Solicitudes de Escaneo Z39.50 (termListAndStartPoint). Esta es una conversión puramente del lado del cliente que convierte desde displayCharset a queryCharset.

set_cclfile

set_cclfile filename

Especifica que los campos CCL se leerán del archivo filename. Este comando hace lo mismo que la opción -c.

set_cqlfile

set_cqlfile filename

Especifica que los campos CQL se leerán del archivo filename. Este comando hace lo mismo que la opción -q.

register_oid

register_oid name class OID

Este comando le permite registrar su propio identificador de objeto, de modo que en lugar de introducir una notación de puntos larga, puede utilizar un nombre corto. El name es su nombre para el OID, class es la clase y OID es el OID crudo en notación de puntos. La clase es una de: appctx, absyn, attet, transyn, diagset, recsyn, resform, accform, extserv, userinfo, elemspec, varset, schema, tagset, general. Si tiene dudas, use la clase general.

register_tab

register_tab command string

Este comando registra una cadena de completado TAB para el comando dado.

sleep

sleep seconds

Este comando hace que el cliente YAZ duerma (esté inactivo) durante el número de segundos dado.

wait_response

wait_response [ number]

Este comando hace que el cliente YAZ espere un número de paquetes de respuesta del destino. Si se omite number, se asume 1.

Este comando rara vez se usa y solo es útil si el comando set_auto_wait está configurado en off.

xmles

xmles OID doc

Envía una solicitud de Servicios Extendidos XML utilizando el OID y el doc dados.

zversion

zversion ver

Este comando establece la versión Z39.50 para la negociación. Debe usarse antes de open. Por defecto se utiliza 3 (versión 3).

options

options op1 op2..

Este comando establece las opciones Z39.50 para la negociación. Debe usarse antes de open.

Se admiten las siguientes opciones: search, present, delSet, resourceReport, triggerResourceCtrl, resourceCtrl, accessCtrl, scan, sort, extendedServices, level_1Segmentation, level_2Segmentation, concurrentOperations, namedResultSets, encapsulation, resultCount, negotiationModel, duplicationDetection, queryType104, pQESCorrection, stringSchema.

EXAMPLE

El ejemplo más simple de una Consulta de Prefijo sería algo como

    f knuth

o

    f "donald knuth"

En esas consultas, no se especificaron atributos. Esto deja que el servidor decida en qué campos buscar, pero la mayoría de los servidores buscarán en todos los campos. Sin embargo, algunos servidores no admiten esta función y requieren que se definan algunos atributos. Para agregar un atributo, podría hacer:

    f @attr 1=4 computer

donde buscamos en el campo título, ya que el uso (1) es título (4). Si queremos buscar en el campo autor y en el campo título, y en el campo título usando truncamiento a la derecha, podría verse algo así

Finalmente, usando una combinación de atributos Bib-1 y GILS podría verse algo así:

    f @attrset Bib-1 @and @attr GILS 1=2008 Washington @attr 1=21 weather
