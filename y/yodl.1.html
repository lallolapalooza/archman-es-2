yodl(1) Tu Propio Lenguaje de Documentos yodl(1)

NOMBRE

yodl - convertidor principal de Yodl

SINOPSIS

yodl [OPCIÓN]... [ARCHIVO]...

DESCRIPCIÓN

Yodl es un paquete que implementa un pre-lenguaje de documentos y herramientas para procesarlo. La idea de Yodl es que escribas un documento en un pre-lenguaje, luego uses las herramientas (por ejemplo, yodl2html(1)) para convertirlo a algún lenguaje de documento final. Los convertidores actuales son para HTML, man, LaTeX, texto y un conversor experimental de xml. Los tipos de documentos principales son "article", "report", "book" "manpage" y "letter". El lenguaje de documento Yodl está diseñado para ser fácil de usar y extensible.

OPCIONES

o
`-D, --define=NOMBRE[=VALOR]’: Define nombre como un símbolo. Esta opción actúa como `DEFINESYMBOL(NOMBRE)()’. Si se añade `=VALOR’, `NOMBRE’ se inicializa a `VALOR’ (idénticamente a `DEFINESYMBOL(NOMBRE)(VALOR)’).
o
`-d, --definemacro=NOMBRE=EXPANSION’: Define `NOMBRE’ como un macro que se expande a `EXPANSION’
o
`-h, --help’: la información de uso se escribe en el flujo de salida estándar, describiendo todas las opciones de Yodl.
o
`-i, --index[=archivo]’: `archivo’ es el nombre del archivo de índice. Por defecto se utiliza `<salida_base>.idx’. No hay valor por defecto cuando la salida se escribe a stdout. El archivo de índice es procesado por el post-procesador de Yodl, `yodlpost’.
o
`-I, --include=DIR’: Define el directorio de inclusión del sistema donde YODL busca sus archivos de entrada. Por ejemplo, una declaración para incluir un archivo dado, como: 
INCLUDEFILE(latex)
Yodl busca ahora el archivo `latex’ en el directorio actual y, cuando falla, en el directorio de inclusión del sistema. El directorio de inclusión del sistema es típicamente el lugar donde el mantenedor de un sistema almacena los archivos macro para Yodl. Este proceso de búsqueda se aplica a los archivos que se incluyen dentro de un documento, pero también se aplica a los nombres de archivo en la línea de comandos al invocar el programa YODL.
El nombre del archivo incluido (`latex’ en el ejemplo anterior) es el nombre base, YODL proporciona una extensión por defecto (`.yo’), si es necesario.
La opción `-I’ anula el nombre predeterminado del sistema para el directorio de inclusión del sistema. El nombre predeterminado se define al compilar Yodl, y es, por ejemplo, `/usr/share/yodl’. Además, la definición puede contener $HOME, que se reemplaza por el directorio personal del usuario si la variable de entorno `home’ o `HOME’ está definida. También puede contener $STD_INCLUDE, que se reemplaza por la ruta de inclusión estándar definida en la compilación. La ruta de inclusión estándar puede ser anulada por (en ese orden) el interruptor de línea de comandos `-I’ o la variable de entorno `YODL_INCLUDE_PATH’. Por defecto, el directorio actual se añade a la ruta de inclusión estándar. Sin embargo, cuando se utiliza `-I’ o `YODL_INCLUDE_PATH’, el directorio actual debe mencionarse explícitamente. Los directorios individuales no necesitan terminar con un carácter de barra inclinada /. En los archivos `.deb’ distribuidos, el directorio estándar se define como `/usr/share/yodl’ (precedido por el directorio de trabajo actual).
o
`-k, --keep-ws’: Desde la versión 2.00 de YODL, los espacios al principio y al final de las líneas se ignoran, incluso sin una barra invertida al final, cuando el `nivel de espacios en blanco’ es distinto de cero. Las versiones anteriores conservaban estos espacios. El manejo legado de espacios en blanco al final de las líneas se puede obtener usando la bandera `-k’. Nótese que los espacios en blanco siempre se conservan cuando se utiliza la copia literal, y cuando el nivel de espacios en blanco es cero.
o
`-m, --messages=SET’: Establece el llamado `nivel de mensajes’ a una combinación de los CONJUNTOS `acdeinw’. Las letras de este conjunto tienen los siguientes significados:
o
`a’: alerta. Cuando ocurre un error de alerta, Yodl termina. Aquí Yodl solicita algo al sistema (como `get_cwd()’), pero el sistema falla.
o
`c’: crítico. Cuando ocurre un error crítico, Yodl termina. El mensaje en sí puede suprimirse, pero la salida no. Una condición crítica es, por ejemplo, la omisión de un paréntesis de apertura en una ubicación donde debería aparecer un argumento entre paréntesis, o un archivo no existente en una especificación `INCLUDEFILE’ (ya que este archivo debería ser analizado). Un archivo no existente con una especificación `NOEXPANDINCLUDE’ es un error simple (no crítico).
o
`d’: depuración. Probablemente demasiada información, como obtener información sobre cada carácter que fue leído por Yodl.
o
`e’: error. Un error (como símbolos definidos doblemente). Una vez que se ha encontrado un error, el resto de la entrada todavía se analiza (hasta un número máximo de errores), pero no se genera ninguna salida.
o
`i’: información. No tan detallado como `debug’, pero todavía mucha información, como información sobre cambios de medios.
o
`n’: aviso. Información sobre, por ejemplo, llamadas a las funciones integradas.
o
`w’: advertencia. Algo de lo que deberías estar al tanto, pero que probablemente no afecta el funcionamiento correcto de Yodl. No configurable es el manejo de un mensaje de emergencia. Estos mensajes no se pueden suprimir, pero no deberían ocurrir, ya que apuntan a algún error interno. Se agradecería recibir información sobre estos mensajes si alguna vez ocurren.
o
`-n, --max-nested-files=NR’: Esta opción hace que Yodl aborte cuando el número de archivos de entrada anidados excede `NR’, que es 20 por defecto. Exceder este número generalmente significa una definición circular en algún lugar del documento. Este es el caso cuando un archivo `a.yo’ incluye `b.yo’, mientras que `b.yo’ incluye `a.yo’, etc. No previene reemplazos recursivos de macros o subst. Para eso está disponible la opción `-r’ (`--max-replacements’).
o
`-o, --output=ARCHIVO’: Esta opción hace que Yodl escriba su salida en `ARCHIVO’. Por defecto, la salida va al flujo de salida estándar. Por ejemplo, puedes usar YODL para leer un archivo `entrada’ y escribir en `salida’ con los siguientes dos comandos: 
        yodl entrada > salida
        yodl -osalida entrada
La diferencia es que en el último caso se genera un archivo de índice, pero no en el primer caso. Nótese que la escritura de un archivo de índice puede ser forzada cuando se especifica la opción `--index’.
o
`-p, --preload=CMD’: Esta opción `pre-carga’ la cadena `cmd’. Actúa como si `cmd’ fuera el primer comando en el primer archivo de entrada que es procesado por YODL.
Puede haber más de una opción `--preload=CMD’ en la línea de comandos. Cada uno de los comandos se procesa en orden, antes de leer cualquier archivo.
o
`-r, --max-replacements=NR’: Esta opción hace que Yodl aborte cuando el número de llamadas a macros o reemplazos de subst excede `NR * 10,000’. Por defecto, `NR’ es igual a 1. Establecer `--max-replacements=0’ implica que no se realizan comprobaciones de reemplazo de macros o subst.
o
`-t, --trace’: Esta opción habilita el rastreo: mientras analiza, Yodl escribe su salida en el flujo de error estándar. Al igual que con la opción `-k’, esta opción está definida solo para fines de depuración.
o
`-V, --version’. Esta opción muestra la versión actual de YODL.
o
`-v, --verbose’: Esta opción aumenta el `nivel de verbosidad’ de Yodl y puede aparecer más de una vez. Por defecto, yodl muestra alertas, errores críticos, emer

OPCIONES

o
`-v, --verbose’. Esta opción controla la cantidad de mensajes que se muestran. Cada opción `--verbose’ añade un nivel de mensaje siguiente. En orden, se añaden mensajes de advertencia, aviso, información y depuración a este conjunto. También es posible suprimir mensajes. El builtin `VERBOSITY’ se puede usar para eso.
o
`-W, --warranty’. Esta opción muestra un descargo de responsabilidad de garantía y un aviso de copyright.
o
`-w, --warn’: La presencia de esta opción hace que Yodl advierta cuando, por ejemplo, se redefinen símbolos.

ARCHIVOS

El programa yodl no requiere archivos, pero el uso "normal" del paquete Yodl requiere archivos de macros, instalados por defecto en `tmp/wip/macros’. Los archivos en este directorio son incluidos por los convertidores yodl2txt(1) etc..
