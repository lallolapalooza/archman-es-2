NOMBRE

yaz-asncomp - Compilador ASN.1 de YAZ

SINOPSIS

yaz-asncomp [-v] [-c archivo_c] [-h archivo_h] [-p archivo_p] [-d config] [-I salida_incluir] [-i directorio_incluir] [-m modulo] [nombre_archivo]

DESCRIPCIÓN

yaz-asncomp es un compilador ASN.1 que lee una especificación ASN.1 en nombre_archivo y produce definiciones C/C++ y codificadores/decodificadores BER para ella.

El código C/C++ y los archivos de cabecera producidos utilizan el módulo ODR de YAZ, que es una biblioteca que codifica/decodifica/imprime paquetes BER. yaz-asncomp permite especificar el nombre del código fuente resultante a través de opciones. Alternativamente, puede especificar un archivo DEFINITIONS, que proporciona salida personalizada a muchos archivos de salida, si el archivo de especificación ASN.1 consta de muchos módulos.

Esta utilidad está escrita en Tcl. Cualquier versión de Tcl debería funcionar.

OPCIONES

-v

Hace que el compilador ASN.1 imprima más información sobre las diversas etapas de las operaciones.

-c archivo_c

Especifica el nombre del archivo C/C++ con codificadores/decodificadores.

-h archivo_h

Especifica el nombre del archivo de cabecera con definiciones.

-p archivo_p

Especifica el nombre de un archivo de cabecera privado con definiciones. Por defecto, todas las definiciones se colocan en el archivo de cabecera (opción -h).

-d archivo_d

Especifica el nombre de un archivo de definiciones.

-I salida_incluir

Especifica la primera parte del directorio en el que se escriben los archivos de cabecera.

-i directorio_incluir

Especifica la segunda parte del directorio en el que se escriben los archivos de cabecera.

-m modulo

Especifica que el compilador ASN.1 solo debe procesar el módulo dado. Si no se especifica esta opción, se procesan todos los módulos del archivo ASN.1.

ARCHIVO DE DEFINICIONES

El archivo de definiciones es en realidad un script Tcl, pero sigue las reglas tradicionales para archivos de configuración tipo Shell. Es decir, # denota el comienzo de un comentario. Las definiciones están orientadas a línea. Los archivos de definiciones suelen consistir en una serie de asignaciones de variables de la forma:

set nombre valor

Las variables disponibles son:

default-prefix

Establece el prefijo para los nombres en la salida producida. El valor consta de tres tokens: prefijo de función C, prefijo de tipos `typedef` C y prefijo de preprocesador, respectivamente.

prefix(modulo)

Este valor establece los valores de prefijo para el módulo modulo. El valor tiene la misma forma que default-prefix.

filename(modulo)

Especifica el nombre de archivo para el archivo C/cabecera del módulo modulo.

init(modulo,h)

Fragmento de código que se incluirá en la primera parte de la cabecera pública para el módulo modulo.

body(modulo,h)

Fragmento de código que se incluirá en la última parte de la cabecera pública para el módulo modulo (remate).

init(modulo,c)

Fragmento de código que se incluirá en la primera parte del codificador/decodificador basado en C para el módulo modulo.

body(modulo,c)

Fragmento de código que se incluirá en la última parte del codificador/decodificador basado en C para el módulo modulo (remate).

map(modulo,nombre)

Mapea el tipo ASN.1 en el módulo modulo de nombre a un valor.

membermap(modulo,nombre,miembro)

Mapea el miembro miembro en SEQUENCE/CHOICE de nombre en el módulo modulo a un valor. El valor consta de uno o dos tokens. El primer token es el nombre de la parte del preprocesador C. El segundo token es el nombre del miembro C resultante. Si se omite el segundo token, el valor (un token) es tanto la parte del preprocesador como la estructura/unión C.

unionmap(modulo,nombre,miembro)

Mapea el miembro miembro en CHOICE de nombre en el módulo modulo a un valor. El valor consta de dos o tres tokens. El primer token es el nombre del entero en la unión que se utiliza como selector para la propia unión. El segundo token es el nombre de la unión. El tercer token anula el nombre del miembro de CHOICE; si se omite, se utiliza el nombre del miembro.
