YASM(1) El Ensamblador Modular Yasm YASM(1)

NOMBRE

yasm - El Ensamblador Modular Yasm

SINOPSIS

yasm [-f formato] [-o archivo_salida] [otras opciones...] {archivo_entrada}

yasm -h

DESCRIPCIÓN

El Ensamblador Modular Yasm es un ensamblador portátil y retargetable escrito bajo la licencia BSD "nueva" (de 2 o 3 cláusulas). Yasm actualmente soporta los conjuntos de instrucciones x86 y AMD64, acepta sintaxis de los ensambladores NASM y GAS, genera formatos de objeto binario, ELF32, ELF64, COFF, Win32 y Win64, y genera información de depuración de origen en formatos STABS, DWARF 2 y CodeView 8.

YASM consiste en el comando yasm, libyasm, la biblioteca backend central y un gran número de módulos. Actualmente, libyasm y los módulos cargables se compilan estáticamente en el ejecutable yasm.

El comando yasm ensambla el archivo de entrada y dirige la salida al archivo archivo_salida si se especifica. Si no se especifica archivo_salida, yasm derivará un nombre de archivo de salida predeterminado del nombre de su archivo de entrada, generalmente añadiendo .o o .obj, o eliminando todas las extensiones para un archivo binario plano. Si no, el nombre del archivo de salida será yasm.out.

Si se llama con un archivo_entrada de “-”, yasm ensambla la entrada estándar y dirige la salida al archivo archivo_salida, o a yasm.out si no se especifica ningún archivo_salida.

OPCIONES

Muchas opciones pueden darse en una de dos formas: ya sea un guion seguido de una sola letra, o dos guiones seguidos de un nombre de opción larga. Las opciones se enumeran en orden alfabético.

Opciones Generales

-a arquitectura o --arch=arquitectura: Seleccionar arquitectura de destino

Selecciona la arquitectura de destino. La arquitectura predeterminada es “x86”, que soporta tanto los conjuntos de instrucciones IA-32 y derivados como AMD64. Para imprimir una lista de arquitecturas disponibles en la salida estándar, use “help” como arquitectura. Consulte yasm_arch(7) para una lista de arquitecturas soportadas.

-f formato o --oformat=formato: Seleccionar formato de objeto

Selecciona el formato de objeto de salida. El formato de objeto predeterminado es “bin”, que es un binario de formato plano sin reubicación. Para imprimir una lista de formatos de objeto disponibles en la salida estándar, use “help” como formato. Consulte yasm_objfmts(7) para una lista de formatos de objeto soportados.

-g depuracion o --dformat=depuracion: Seleccionar formato de depuración

Selecciona el formato de depuración para la información de depuración. La información de depuración puede ser utilizada por un depurador para asociar el código ejecutable de vuelta al archivo fuente u obtener información de estructuras de datos y tipos. Los formatos de depuración disponibles varían entre diferentes formatos de objeto; yasm generará un error cuando se seleccione una combinación inválida. El formato de objeto predeterminado es seleccionado por el formato de objeto. Para imprimir una lista de formatos de depuración disponibles en la salida estándar, use “help” como depuracion. Consulte yasm_dbgfmts(7) para una lista de formatos de depuración soportados.

-L lista o --lformat=lista: Seleccionar formato de archivo de lista

Selecciona el formato/estilo del archivo de lista de salida. Los archivos de lista típicamente intercalan el código fuente original con el código máquina generado por el ensamblador. El formato de lista predeterminado es “nasm”, que imita el formato de archivo de lista de NASM. Para imprimir una lista de formatos de archivo de lista disponibles en la salida estándar, use “help” como lista.

-l archivo_lista o --list=archivo_lista: Especificar nombre de archivo de lista

Especifica el nombre del archivo de lista de salida. Si no se utiliza esta opción, no se genera ningún archivo de lista.

-m maquina o --machine=maquina: Seleccionar arquitectura de máquina de destino

Selecciona la arquitectura de máquina de destino. Esencialmente un subtipo de la arquitectura seleccionada, el tipo de máquina selecciona entre subconjuntos importantes de una arquitectura. Por ejemplo, para la arquitectura “x86”, las dos máquinas disponibles son “x86”, que se usa para el conjunto de instrucciones de 32 bits IA-32 y derivados, y “amd64”, que se usa para el conjunto de instrucciones de 64 bits. Esta diferenciación es necesaria para generar el archivo de objeto correcto para formatos de objeto reubicables como COFF y ELF. Para imprimir una lista de máquinas disponibles para una arquitectura dada en la salida estándar, use “help” como maquina y la arquitectura dada usando -a arquitectura. Consulte yasm_arch(7) para más detalles.

-o nombre_archivo o --objfile=nombre_archivo: Especificar nombre de archivo de objeto

Especifica el nombre del archivo de salida, anulando cualquier nombre predeterminado generado por Yasm.

-p parser o --parser=parser: Seleccionar parser

Selecciona el parser (la sintaxis del ensamblador). El parser predeterminado es “nasm”, que emula la sintaxis de NASM, el Ensamblador Netwide. Otro parser disponible es “gas”, que emula la sintaxis de GNU AS. Para imprimir una lista de parsers disponibles en la salida estándar, use “help” como parser. Consulte yasm_parsers(7) para una lista de parsers soportados.

-r preproc o --preproc=preproc: Seleccionar preprocesador

Selecciona el preprocesador a utilizar en el archivo de entrada antes de pasarlo al parser. Los preprocesadores a menudo proporcionan funcionalidad de macros que no está incluida en el parser principal. El preprocesador predeterminado es “nasm”, que es una versión importada del preprocesador real de NASM. También está disponible un preprocesador “raw”, que simplemente omite el paso de preprocesamiento, pasando el archivo de entrada directamente al parser. Para imprimir una lista de preprocesadores disponibles en la salida estándar, use “help” como preproc.

-h o --help: Imprimir un resumen de opciones

Imprime un resumen de las opciones de invocación. Todas las demás opciones se ignoran y no se genera ningún archivo de salida.

--version: Obtener la versión de Yasm

Esta opción hace que Yasm imprima el número de versión de Yasm, así como un resumen de la licencia en la salida estándar. Todas las demás opciones se ignoran y no se genera ningún archivo de salida.

Opciones de Advertencia

Las opciones -W tienen dos formas contrarias: -Wnombre y -Wno-nombre. Solo se muestran aquí las formas no predeterminadas.

Las opciones de advertencia se manejan en el orden en que se dan en la línea de comandos, por lo que si -w va seguido de -Worphan-labels, todas las advertencias se desactivan *excepto* las de orphan-labels.

-w: Inhibir todos los mensajes de advertencia

Esta opción hace que Yasm inhiba todos los mensajes de advertencia. Como se discutió anteriormente, esta opción puede ir seguida de otras opciones para volver a habilitar advertencias específicas.

-Werror: Tratar las advertencias como errores

Esta opción hace que Yasm trate todas las advertencias como errores. Normalmente, las advertencias no impiden que se genere un archivo de objeto y no resultan en un estado de salida de error de yasm, mientras que los errores sí lo hacen. Esta opción hace que las advertencias sean equivalentes a los errores en términos de este comportamiento.

-Wno-unrecognized-char: No advertir sobre caracteres de entrada no reconocidos

Hace que Yasm no advierta sobre caracteres no reconocidos encontrados en la entrada. Normalmente, Yasm generará una advertencia para cualquier carácter no ASCII encontrado en el archivo de entrada.

-Worphan-labels: Advertir sobre etiquetas sin una opción final

Al usar el parser compatible con NASM, hace que Yasm advierta sobre etiquetas que se encuentran solas en una línea sin dos puntos finales. Aunque estas son etiquetas legales en la sintaxis de NASM, pueden ser involuntarias, debido a errores tipográficos o al orden de definición de macros.

-X estilo: Cambiar el estilo de reporte de errores/advertencias

Selecciona un estilo de salida específico para los mensajes de error y advertencia. El predeterminado es el estilo “gnu”, que imita la salida de gcc. También está disponible el estilo “vc”, que imita la salida de Microsoft&#x

Opciones del preprocesador

Aunque estas opciones del preprocesador teóricamente afectarán a cualquier preprocesador, el único preprocesador actualmente en Yasm es el preprocesador "nasm".

-D macro[=valor]: Predefinir una macro

Predefine una macro de una sola línea. El valor es opcional (si no se proporciona valor, la macro sigue definida, pero a un valor vacío).

-e o --preproc-only: Solo preprocesar

Detiene el ensamblado después de la etapa de preprocesamiento; la salida preprocesada se envía al nombre de salida especificado o, si no se especifica nombre de salida, a la salida estándar. No se produce ningún archivo objeto.

-I ruta: Añadir ruta de archivo de inclusión

Añade el directorio ruta a la ruta de búsqueda de archivos de inclusión. La ruta de búsqueda, por defecto, solo incluye el directorio en el que reside el archivo fuente.

-P nombrearchivo: Pre-incluir un archivo

Pre-incluye el archivo nombrearchivo, haciendo que parezca que nombrearchivo fue antepuesto a la entrada. Puede ser útil para anteponer macros de varias líneas que la opción -D no puede soportar.

-U macro: Anular la definición de una macro

Anula la definición de una macro de una sola línea (puede ser una macro incorporada o una definida anteriormente en la línea de comandos con -D.

EJEMPLOS

Para ensamblar código fuente de sintaxis NASM, x86 de 32 bits, source.asm en un archivo ELF source.o, advirtiendo sobre etiquetas huérfanas:

yasm -f elf32 -Worphan-labels source.asm

Para ensamblar código fuente de sintaxis NASM AMD64, x.asm en un archivo Win64 object.obj:

yasm -f win64 -o object.obj x.asm

Para ensamblar código fuente de sintaxis NASM x86 ya preprocesado, y.asm en un archivo binario plano y.com:

yasm -f bin -r raw -o y.com y.asm

DIAGNÓSTICOS

El comando yasm sale con 0 en caso de éxito y con un valor distinto de cero si ocurre un error.

COMPATIBILIDAD

El analizador y preprocesador NASM de Yasm, aunque se esfuerzan por ser lo más compatibles posible con NASM, tienen algunas incompatibilidades debido a la diferente estructura interna de YASM.

Al analizador y preprocesador GAS de Yasm les faltan varias características presentes en GNU AS.

RESTRICCIONES

Dado que los archivos objeto suelen depender de la arquitectura y la máquina, no todas las combinaciones de formatos de objeto, arquitecturas y máquinas son legales; intentar usar una combinación inválida resultará en un error.

No hay soporte para mapas de símbolos.

VER TAMBIÉN

ERRORES

Al usar la arquitectura "x86", es demasiado fácil generar código AMD64 (usando la directiva BITS 64) y generar un archivo objeto de 32 bits (al no especificar -m amd64 o seleccionar un formato de objeto de 64 bits como ELF64 en la línea de comandos).
