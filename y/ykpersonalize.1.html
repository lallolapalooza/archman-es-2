ykpersonalize(1)

Paquete: yubikey-personalization

YKPERSONALIZE(1) Herramienta de Personalización YubiKey M YKPERSONALIZE(1)

NOMBRE

ykpersonalize - personaliza tokens OTP de YubiKey

SINOPSIS

ykpersonalize [-Nkey] [-1 | -2] [-sarchivo] [-iarchivo] [-mformato] [-axx] [-cxxx] [-oopción] [-y] [-v] [-d] [-h] [-n] [-t] [-u] [-x] [-z] [-m] [-S] [-V] [-Dxxx_]

DESCRIPCIÓN

Configura la clave AES, el ID de usuario y otras configuraciones en un YubiKey. Para la explicación completa del significado de todos los parámetros, consulta el manual de referencia: Manual de YubiKey (https://www.yubico.com/wp-content/uploads/2015/03/YubiKeyManual_v3.4.pdf)

OPCIONES

-Nkey

usa el enésimo YubiKey encontrado.

-1

cambia la primera configuración. Este es el valor predeterminado y normalmente se usa para la generación de OTP real. En esta configuración, la bandera de opción -oappend-cr está establecida por defecto.

-2

cambia la segunda configuración. Esto es solo para YubiKey II y normalmente se usa para la generación de claves estáticas. En esta configuración, las banderas de opción -oappend-cr, -ostatic-ticket, -ostrong-pw1, -ostrong-pw2 y -oman-update están establecidas por defecto.

-z

elimina la configuración en la ranura seleccionada.

-sarchivo

guarda la configuración en un archivo en lugar de la clave (si el archivo es -, envíalo a la salida estándar).

-iarchivo

lee la configuración de un archivo (si el archivo es -, lee de la entrada estándar). La importación de configuración solo es válida para el formato ycfg.

-fformato

formato a usar con -s e -i. Las opciones válidas son ycfg y legacy.

-a[xxx]

la clave secreta AES como un valor hexadecimal de 32 (o 40 para OATH-HOTP/HMAC CHAL-RESP) caracteres (no modhex) (nada para solicitar la clave en la entrada estándar). Si -a no se usa, se generará una clave aleatoria.

-c[xxx]

un valor hexadecimal de 12 caracteres (no modhex) para usar como código de acceso para la programación. NOTA: esto NO CONFIGURA el código de acceso. Eso se hace con -oaccess=. Si no se proporciona argumento, se solicitará el código en la entrada estándar.

-oopción

cambia la opción de configuración. Los argumentos de opción posibles son:

fixed=fffffffffff

La identidad pública en modhex del YubiKey, de 0 a 32 caracteres de longitud (codificando hasta 16 bytes). También es posible proporcionar la identidad en hexadecimal, simplemente prefija el valor con 'h:'. La parte fija se emite antes del OTP cuando se presiona el botón del YubiKey. Se puede usar como identificador para el usuario, por ejemplo.

uid[=uuuuuu]

La parte uid del OTP generado, también llamada identidad privada, en hexadecimal. Debe tener 12 caracteres de longitud. El uid es un dato estático de 6 bytes que se incluye (cifrado) en cada OTP y se usa para validar que un OTP fue efectivamente cifrado con la clave AES compartida entre el YubiKey y el servicio de validación. No se puede usar para identificar el YubiKey, ya que solo es legible para quienes conocen la clave AES. Si no se proporciona argumento, se solicitará el uid en la entrada estándar.

access[=fffffffffff]

Nuevo código de acceso hexadecimal para configurar. Debe tener 12 caracteres de longitud. Si se establece un código de acceso, se requerirá para la reprogramación posterior del YubiKey. Si no se proporciona argumento, se solicitará el código en la entrada estándar.

oath-imf=xxx

Establece el Factor de Movimiento Inicial de OATH. Este es el valor inicial del contador para el YubiKey. Debe ser un valor entre 0 y 1048560, divisible uniformemente por 16.

bandera-ticket

Establece/borra la bandera de ticket, consulta la sección Banderas de Ticket.

bandera-configuración

Establece/borra la bandera de configuración, consulta la sección Banderas de Configuración.

-y

confirma siempre sin preguntar.

-d

ejecución de prueba, ejecuta sin escribir en un YubiKey.

-v

sea más verboso.

-h

muestra la ayuda.

-V

muestra la versión.

Solo YubiKey Neo

-n URI

programa URI NDEF NFC.

-t texto

programa texto NDEF NFC.

Solo YubiKey 3 y 4

-m modo

establece la configuración del dispositivo para el YubiKey. Se analiza en el formato modo:timeout_cr:timeout_autoeject donde modo es:

0

solo dispositivo OTP.

1

solo dispositivo CCID.

2

dispositivo compuesto OTP/CCID.

3

solo dispositivo U2F.

4

dispositivo compuesto OTP/U2F.

5

dispositivo compuesto U2F/CCID.

6

dispositivo compuesto OTP/U2F/CCID. Añade 80 para establecer MODE_FLAG_EJECT, por ejemplo: 81

timeout_cr es el tiempo de espera en segundos para que el YubiKey espere la pulsación del botón para respuesta a desafío (el valor predeterminado es 15)

timeout_autoeject es el tiempo de espera en segundos antes de que la tarjeta se expulse automáticamente en el modo 81

La eliminación del modo OTP también deshabilita la comunicación entre ykpersonalize y el YubiKey. Los cambios de modo posteriores deberán realizarse con ykneomgr (para el modo CCID) o u2f-host (para el modo U2F).

YubiKey 3 y superiores

-S0605...

establece el scanmap a usar con el YubiKey. Debe ser 45 bytes únicos como 90 caracteres. Deja el argumento vacío para restablecer al valor predeterminado del YubiKey. El scanmap debe enviarse en el orden: 
cbdefghijklnrtuvCBDEFGHIJKLNRTUV0123456789!\t\r

El scanmap predeterminado en el YubiKey es:

06050708090a0b0c0d0e0f111517181986858788898a8b8c8d8e8f9195979899271e1f202122232425269e2b28

Un ejemplo para Dvorak simplificado de EE. UU. sería:

0c110b071c180d0a0619130f120e09378c918b879c988d8a8699938f928e89b7271e1f202122232425269e2b28

O para un teclado francés azerty (los dígitos están desplazados):

06050708090a0b0c0d0e0f111517181986858788898a8b8c8d8e8f9195979899a79e9fa0a1a2a3a4a5a6382b28

O para un teclado francés BÉPO (Dvorak francés):

0b140c0938363707130512330f0d16188b948c89b8b6b787938592b38f8d9698a79e9fa0a1a2a3a4a5a69c2b28

Y un ejemplo turco (tiene una i sin punto en lugar de la i normal):

06050708090a0b340d0e0f111517181986858788898a8b8c8d8e8f9195979899271e1f202122232425269e2b28

Tenga en cuenta que debe eliminar cualquier espacio en blanco presente en estos ejemplos antes de usar los valores.

YubiKey 5 y superiores

-D0403...

establece la información del dispositivo a usar con este YubiKey.

YubiKey 2.3 y superiores

-u

actualiza la configuración existente, en lugar de sobrescribirla. Solo es posible si la ranura está configurada como actualizable.

-x

intercambia la ranura de configuración 1 y 2 dentro del YubiKey. Solo es posible si ambas ranuras están configuradas como actualizables.

BANDERAS DE TICKET

tab-first

envía un carácter de tabulación como primer carácter. Esto se usa normalmente para pasar al siguiente campo de entrada.

append-tab1

envía un carácter de tabulación entre la parte fija y la parte de contraseña de un solo uso. Esto es útil si tienes la parte fija igual a t

FLAGS DE CONFIGURACIÓN

send-ref

Envía una cadena de referencia de los 16 caracteres modhex antes de la parte fija. Cuando se combina con -ostrong-pw2, envía un ! antes del resto de la cadena.

pacing-10ms

Agrega un retraso de 10 ms entre pulsaciones de teclas.

pacing-20ms

Agrega un retraso de 20 ms entre pulsaciones de teclas.

static-ticket

Genera una cadena fija en lugar de una contraseña de un solo uso. La contraseña todavía se basa en la clave AES y debería ser difícil de adivinar e imposible de recordar.

firmware YubiKey 1.x únicamente

ticket-first

Envía la contraseña de un solo uso en lugar de la parte fija primero.

allow-hidtrig

Permite la activación a través de HID/teclado presionando Bloq Mayús, Bloq Num o Bloq Despl dos veces. No se recomienda por razones de seguridad.

Firmware YubiKey 2.0 y superior

short-ticket

Limita la longitud de la cadena estática a un máximo de 16 dígitos. Esta bandera solo tiene sentido con la opción -ostatic-ticket. Cuando se usa -oshort-ticket sin -ostatic-ticket, programará el YubiKey en modo "scan-code", en este modo la clave envía el contenido de fijo, uid y clave como códigos de escaneo de teclado sin procesar. Por ejemplo, al usar la cadena fija h:8b080f0f122c9a12150f079e en este modo, enviará Hello World! en un teclado qwerty. Este modo envía códigos de escaneo sin procesar, por lo que la salida diferirá entre las distribuciones del teclado.

strong-pw1

Convierte en mayúsculas las dos primeras letras de la cadena de salida. Esto es para compatibilidad con sistemas heredados que exigen caracteres en mayúsculas y minúsculas en una contraseña y no agrega seguridad.

strong-pw2

Reemplaza los primeros ocho caracteres del alfabeto modhex con los números del 0 al 7. Al igual que -ostrong-pw1, esto está destinado a admitir sistemas heredados.

man-update

Habilita la actualización iniciada por el usuario de la contraseña estática. Solo tiene sentido con la opción -ostatic-ticket. Esto solo es válido para el firmware 2.x.

Firmware YubiKey 2.1 y superior

oath-hotp8

Genera un HOTP de 8 dígitos en lugar de uno de 6 dígitos.

oath-fixed-modhex1

Envía el primer byte de la parte fija como modhex.

oath-fixed-modhex2

Envía los dos primeros bytes de la parte fija como modhex.

oath-fixed-modhex

Envía la parte fija como modhex.

oath-id=m:OOTTUUUUUUUU

Configura el id del token OATH con un valor proporcionado. Consulte la descripción de esta opción en la sección 2.2 para obtener detalles, pero tenga en cuenta que una clave YubiKey 2.1 no puede informar su número de serie y, por lo tanto, se debe especificar un valor de identificador de token.

Firmware YubiKey 2.2 y superior

chal-yubico

Modo de respuesta a desafío Yubico OTP.

chal-hmac

Genera respuestas a desafíos HMAC-SHA1.

hmac-lt64

Calcula HMAC en menos de 64 bytes de entrada. Cualquier cosa en el último byte del desafío se usa como marcador de fin de entrada (retrocediendo desde el final de la carga útil).

chal-btn-trig

El YubiKey esperará a que el usuario presione la tecla (en 15 segundos) antes de responder al desafío.

serial-btn-visible

El YubiKey emitirá su número de serie si se presiona el botón durante el encendido. Esta opción solo es válida para la línea de firmware 2.x.

serial-usb-visible

El YubiKey indicará su número de serie en el campo iSerial del USB. Esta opción no está disponible en los firmwares 3.0 y 3.1.

serial-api-visible

El YubiKey permitirá leer su número de serie mediante una llamada a la API.

oath-id[=m:OOTTUUUUUUUU]

Configura el id del token OATH con un valor proporcionado, o si se usa sin valor, utiliza el identificador de token estándar de YubiKey.

El id de token OATH estándar para un Yubico YubiKey es (modhex) OO=ub, TT=he, (decimal) UUUUUUUU=número de serie.

La razón del número de serie decimal es facilitar que los humanos correlacionen el número de serie en la parte posterior del YubiKey con una entrada en una lista de tokens asociados, por ejemplo. Otras codificaciones se pueden lograr utilizando las opciones oath-fixed-modhex apropiadas.

Tenga en cuenta que el YubiKey debe estar programado para permitir la lectura de su número de serie, de lo contrario, la creación automática del id del token no es posible.

Consulte la sección "5.3.4 - OATH-HOTP Token Identifier" del manual de YubiKey http://yubico.com/files/YubiKey_manual-2.0.pdf para obtener más detalles.

Firmware YubiKey 2.3 y superior

use-numeric-keypad

Envía códigos de escaneo para las pulsaciones de teclas del teclado numérico al enviar dígitos; ayuda con algunas distribuciones de teclado. Esta opción solo es válida para la línea de firmware 2.x.

fast-trig

Activación más rápida cuando solo la configuración 1 está disponible. Esta opción está siempre activa en las versiones de firmware 3.0 y superiores.

allow-update

Permite actualizar (o intercambiar) ciertos parámetros en una configuración en un momento posterior.

dormant

Oculta/muestra una configuración almacenada en un YubiKey.

Firmware YubiKey 2.4/3.1 y superior

led-inv

Invierte el comportamiento del LED en el YubiKey.

Modo OATH-HOTP

Al usar el modo OATH-HOTP, se puede proporcionar una clave HMAC de 160 bits (20 bytes, 40 caracteres hexadecimales) con -a.

Modo Respuesta a Desafío

En el modo CHAL-RESP, el token NO generará ninguna pulsación de tecla cuando se presione el botón (aunque es perfectamente posible tener una ranura con configuración de generación de pulsaciones de teclas y la otra en modo de respuesta a desafío). En su lugar, se debe utilizar un programa capaz de enviar informes de características HID USB al token para enviarle un desafío y leer la respuesta.

Modhex

Modhex es una forma de escribir dígitos hexadecimales donde los "dígitos" se eligen por estar en la misma posición en la mayoría de las distribuciones de teclado. Para convertir de hexadecimal a modhex, puede usar:

tr "[0123456789abcdef]" "[cbdefghijklnrtuv]"

Para convertir en el otro sentido, use:

tr "[cbdefghijklnrtuv]" "[0123456789abcdef]"

EJEMPLOS

Programación para YubiCloud:

ouid=$(dd if=/dev/urandom 2>/dev/null | tr -d '[:upper:]' | tr -cd '[:xdigit:]' | fold -w12 | head -1)
ofixed=ff$(dd if=/dev/urandom 2>/dev/null | tr -d '[:upper:]' | tr -cd '[:xdigit:]' | fold -w10 | head -1)
ykpersonalize -1 -ouid=h:$ouid -ofixed=h:$ofixed

Esto programará una clave con un uid aleatorio de 6 bytes y una cadena fija de 12 caracteres que comienza con vv. Esto es adecuado para subir a YubiCloud en https://upload.yubico.com/
