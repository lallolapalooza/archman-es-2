NOMBRE

yum2dnf - Cambios en DNF comparado con YUM

--SKIP-BROKEN

Para el comando de instalación:

La opción --skip-broken es un alias para --setopt=strict=0. Ambas opciones pueden ser usadas con DNF para omitir todos los paquetes no disponibles o paquetes con dependencias rotas que se le dan a DNF sin generar un error que cause que toda la operación falle. Este comportamiento puede ser configurado por defecto en el archivo dnf.conf. Ver la opción de configuración strict <#strict-label>.

Para el comando de actualización:

La semántica que se suponía que debía activarse en YUM con --skip-broken ahora está configurada por defecto para el simple dnf update. No hay necesidad de usar --skip-broken con el comando dnf upgrade. Para usar solo las últimas versiones de paquetes en transacciones, existe el modificador de línea de comandos --best.

LOS COMANDOS UPDATE Y UPGRADE SON LO MISMO

Invocar dnf update o dnf upgrade, en todas sus formas, tiene el mismo efecto en DNF, prefiriéndose este último. En YUM, yum upgrade era exactamente igual a yum --obsoletes update.

LIMPIAR_REQUISITOS_AL_ELIMINAR ACTIVADO POR DEFECTO

El modificador clean_requirements_on_remove <#clean-requirements-on-remove-label> está activado por defecto en DNF. Por lo tanto, puede ser confuso comparar los resultados de la operación de "eliminar" entre DNF y YUM, ya que por defecto DNF a menudo eliminará más paquetes.

NO HAY COMANDO RESOLVEDEP

La versión de YUM de este comando se mantiene solo por razones de legado. El usuario puede simplemente usar dnf provides para averiguar qué paquete proporciona un archivo particular.

NO HAY COMANDO DEPLIST

Una alternativa al comando deplist de YUM para averiguar las dependencias de un paquete es dnf repoquery --deplist usando el comando repoquery <#repoquery-command-label>.

Nota:

Alternativamente, existe soporte de compatibilidad con YUM donde yum deplist es un alias para el comando dnf repoquery --deplist

EXCLUDE Y REPO EXCLUDE SE APLICAN A TODAS LAS OPERACIONES

YUM solo respeta los excludes durante las instalaciones y actualizaciones. DNF extiende esto a todas las operaciones, entre otras, borrar y listar. Si, por ejemplo, deseas ver una lista de todos los paquetes instalados de python-f* pero no ninguno de los paquetes Flask, lo siguiente funcionará:

dnf -x '*flask*' list installed 'python-f*'

LA OPCIÓN INCLUDE HA SIDO ELIMINADA

Ya no se admite la inclusión de otros archivos de configuración en el archivo de configuración principal.

DNF PROVIDES /BIN/<ARCHIVO> NO ESTÁ TOTALMENTE SOPORTADO

Después de UsrMove https://fedoraproject.org/wiki/Features/UsrMove, no hay un directorio /bin en los sistemas Fedora y no se instalan archivos allí; /bin es solo un enlace simbólico creado por el paquete filesystem para apuntar a /usr/bin. Resolver los enlaces simbólicos a su ruta real solo daría al usuario una falsa sensación de que esto funciona, mientras que de hecho las solicitudes de 'provides' que usan comodines como:

dnf provides /b*/<file>

seguirán fallando (como fallan ahora en YUM). Para averiguar qué proporciona un binario en particular, usa la ruta real para los binarios en Fedora:

dnf provides /usr/bin/<file>

Ver también los errores relacionados en el bugzilla de Fedora 982947 https://bugzilla.redhat.com/show_bug.cgi?id=982947 y 982664 https://bugzilla.redhat.com/show_bug.cgi?id=982664.

SKIP_IF_UNAVAILABLE PODRÍA HABER SIDO ACTIVADO POR DEFECTO

En algunas distribuciones, DNF se distribuye con skip_if_unavailable=True en el archivo de configuración de DNF <#conf-ref-label>. La razón del cambio es que los repositorios de terceros a menudo pueden no estar disponibles. Sin esta configuración en el archivo de configuración del repositorio relevante, YUM se detiene inmediatamente ante un error de sincronización del repositorio, confundiendo y molestando al usuario.

Ver el error relacionado en el bugzilla de Fedora 984483 https://bugzilla.redhat.com/show_bug.cgi?id=984483.

OVERWRITE_GROUPS ELIMINADO, FUNCIONES COMPS ACTUANDO COMO SI SIEMPRE ESTUVIERAN DESACTIVADAS

Esta opción de configuración ha sido eliminada. Cuando DNF ve varios grupos con el mismo ID de grupo, fusiona los contenidos de los grupos.

MIRRORLIST_EXPIRE ELIMINADO

Para simplificar las cosas para el usuario, DNF usa metadata_expire tanto para expirar metadatos como para el archivo mirrorlist (que es un tipo de metadato en sí mismo).

METALINK NO RECONOCIDO EN LA OPCIÓN REPO MIRRORLIST

La siguiente parte de yum.conf(5) ya no se aplica para la opción mirrorlist:

Como un truco especial si la URL de mirrorlist contiene la palabra "metalink", entonces el valor de mirrorlist se copia a metalink (si metalink no está configurado).

Los archivos de configuración de repositorios relevantes han sido corregidos para respetar esto, ver el error relacionado en el bugzilla de Fedora 948788 https://bugzilla.redhat.com/show_bug.cgi?id=948788.

ALWAYSPROMPT ELIMINADO

No soportado para simplificar la configuración.

UPGRADE_REQUIREMENTS_ON_INSTALL ELIMINADO

Eliminar esta opción de configuración con semántica poco clara simplifica la configuración. DNF se comporta como si estuviera desactivada. Si el usuario quisiera actualizar todo a la última versión, simplemente usaría dnf upgrade.

DNF HISTORY ROLLBACK CHECK ELIMINADO

Dado que DNF tolera el uso de otros gestores de paquetes, es posible que no todos los cambios en la RPMDB se almacenen en el historial de transacciones. Por lo tanto, DNF no falla si se encuentra tal situación y, por lo tanto, la opción force ya no es necesaria.

REEMPLAZO DE PAQUETES SIN YUM SWAP

De vez en cuando, es necesario eliminar un paquete instalado y reemplazarlo por uno diferente que proporcione las mismas capacidades mientras que otros paquetes que dependen de estas capacidades permanecen instalados. Sin romper (transitoriamente) la consistencia de la base de datos de paquetes, esto se puede hacer realizando la eliminación y la instalación en una sola transacción. La forma común de configurar una transacción de este tipo en DNF es usar dnf shell o usar el modificador --allowerasing.

Por ejemplo, digamos que quieres reemplazar A (que proporciona P) con B (que también proporciona P, y entra en conflicto con A) sin

t eliminando C (que requiere P) en el proceso. Utiliza:

dnf --allowerasing install B

Este comando es igual a yum swap A B.

DNF proporciona el comando swap, pero solo se admite la sintaxis dnf swap A B

DETALLES DEL PROCESAMIENTO DE DEPENDENCIAS NO SE MUESTRAN EN LA CLI

Durante su fase de resolución de dependencias, YUM genera líneas similares a:

---> Package rubygem-rhc.noarch 0:1.16.9-1.fc19 will be an update
--> Processing Dependency: rubygem-net-ssh-multi >= 1.2.0 for package: rubygem-rhc-1.16.9-1.fc19.noarch

DNF no genera información como esta. La razón técnica es que el resolutor de dependencias debajo de DNF siempre considera todas las dependencias para los candidatos de actualización y la salida sería muy larga. En segundo lugar, incluso en YUM, esta salida se vuelve confusa muy rápidamente, especialmente para transacciones grandes, y por lo tanto hace más daño que bien.

Ver el error relacionado de Fedora 1044999 https://bugzilla.redhat.com/show_bug.cgi?id=1044999.

DNF PROPORCIONA CUMPLE CON LA DOCUMENTACIÓN DE YUM DEL COMANDO

Cuando uno ejecuta:

yum provides sandbox

YUM aplica heurísticas adicionales para determinar qué quiso decir el usuario con sandbox, por ejemplo, antepone secuencialmente entradas de la variable de entorno PATH para ver si coincide con un archivo proporcionado por algún paquete. Este es un comportamiento no documentado que DNF no emula. Simplemente use típicamente:

dnf provides /usr/bin/sandbox

o incluso:

dnf provides '*/sandbox'

para obtener resultados similares.

LIMITACIÓN DE ANCHO DE BANDA

DNF admite las opciones throttle y bandwidth familiares de YUM. A diferencia de YUM, cuando varias descargas se ejecutan simultáneamente, se limita la velocidad total de descarga. Esto no fue posible en YUM ya que los descargadores se ejecutaban en procesos diferentes.

OPCIÓN DE CONFIGURACIÓN INSTALLONLYPKGS

En comparación con YUM, DNF agrega los valores de lista de la opción de configuración installonlypkgs a los valores predeterminados de DNF, mientras que YUM sobrescribe los valores predeterminados con los valores de la opción.

EL USO DE ARCHIVOS DELTA RPM

La opción booleana deltarpm controla si se utilizan archivos delta RPM. En comparación con YUM, DNF no admite deltarpm_percentage y, en su lugar, elige un valor óptimo de la relación DRPM/RPM para decidir si usar deltarpm tiene sentido en el caso dado.

MANEJO DE ARCHIVOS .SRPM Y PAQUETES INEXISTENTES

DNF terminará temprano con un error si se ejecuta un comando que solicita una operación de instalación en un archivo local .srpm:

$ dnf install fdn-0.4.17-1.fc20.src.rpm tour-4-6.noarch.rpm
Error: Will not install a source rpm package (fdn-0.4.17-1.fc20.src).

Lo mismo se aplica a las especificaciones de paquetes que no coinciden con ningún paquete disponible.

YUM solo emitirá una advertencia en este caso y continuará instalando el paquete "tour". La lógica detrás del resultado en DNF es que un programa debe terminar con un error si no puede cumplir el comando CLI en su totalidad.

PROMOCIÓN DE PAQUETE A INSTALAR A UN PAQUETE QUE LO OBSOLETA

DNF no reemplazará mágicamente una solicitud de instalación del paquete X por la instalación del paquete Y si Y obsoleto a X. YUM hace esto si su opción de configuración obsoletes está habilitada, pero el comportamiento no está documentado adecuadamente y puede ser perjudicial.

Ver el error relacionado de Fedora 1096506 https://bugzilla.redhat.com/show_bug.cgi?id=1096506 y las pautas para renombrar y obsolecer paquetes en Fedora http://fedoraproject.org/wiki/Upgrade_paths_%E2%80%94_renaming_or_splitting_packages.

COMPORTAMIENTO DE LA OPCIÓN --INSTALLROOT

DNF ofrece un comportamiento más predecible de installroot. DNF maneja la ruta de manera diferente a la opción de línea de comandos --config, donde esta ruta siempre está relacionada con el sistema host (YUM combina esta ruta con installroot). Reposdir también se maneja ligeramente diferente, si una ruta de los reposdirs existe dentro de installroot, entonces los repos se toman estrictamente de installroot (YUM prueba cada ruta de reposdir por separado y usa la ruta de installroot si existía). Ver la descripción detallada de la opción --installroot <#installroot-label>.

PROMPT DIFERENTE DESPUÉS DE LA TABLA DE TRANSACCIÓN

DNF no proporciona funcionalidad de descarga después de mostrar la tabla de transacciones. Solo pregunta al usuario si desea continuar con la transacción o no. Si uno quiere descargar paquetes, puede usar el comando 'download'.

EL COMANDO LIST MUESTRA TODAS LAS ALTERNATIVAS DE REPOSITORIO

DNF lista todos los paquetes de todos los repositorios, lo que significa que puede haber nombres de paquetes duplicados (con nombres de repositorio diferentes). Esto se debe a que se brinda a los usuarios la posibilidad de elegir el repositorio preferido.

SE HAN ELIMINADO LOS SUBCOMANDOS DE YUM-LANGPACKS

Las traducciones se convirtieron en parte del núcleo de DNF y ya no es necesario administrar paquetes de idioma individuales.

Se eliminaron los siguientes subcomandos:

  • langavailable
  • langinstall
  • langremove
  • langlist
  • langinfo

LOS SUBCOMANDOS DNF HISTORY LIST E INFO RETORNAN 0 CUANDO NO SE ENCUENTRAN TRANSACCIONES

DNF dnf history list y dnf history info devuelven un estado de salida cero cuando no encuentran transacciones para un paquete especificado.

Esto es diferente de los correspondientes YUM yum history package-list y yum history list, que devuelven un estado de salida no cero cuando no encuentran

transacciones para un paquete especificado.

YUM-UPDATEONBOOT AND YUM-CRON

DNF does not have a direct replacement of yum-updateonboot and yum-cron commands. However, the similar result can be achieved by dnf automatic command (see DNF Automatic <>).

You can either use the shortcut:

$ systemctl enable --now dnf-automatic-install.timer

Or set apply_updates option of /etc/dnf/automatic.conf to True and use generic timer unit:

$ systemctl enable --now dnf-automatic.timer

The timer in both cases is activated 1 hour after the system was booted up and then repetitively once every 24 hours. There is also a random delay on these timers set to 5 minutes. These values can be tweaked via dnf-automatic*.timer config files located in the /usr/lib/systemd/system/ directory.

Take a look at the FAQ https://dnf.readthedocs.io/en/latest/user_faq.html about YUM to DNF migration. Feel free to file an RFE https://github.com/rpm-software-management/dnf/wiki/Bug-Reporting#new-feature-request for missing functionality if you need it.

NAME

yum2dnf — Convert yum configuration to dnf configuration

--SKIP-BROKEN

This option is passed to the dnf(8) command, and it will skip packages that have unmet dependencies. This behavior is enabled by default for dnf, unlike yum.

UPDATE AND UPGRADE COMMANDS ARE THE SAME

The update and upgrade commands are now the same. dnf will upgrade all packages that have updates available.

CLEAN_REQUIREMENTS_ON_REMOVE ON BY DEFAULT

dnf removes packages that were automatically installed as dependencies and are no longer needed. This behavior is enabled by default.

NO RESOLVEDEP COMMAND

dnf does not have the resolvedep command. Instead, you should use dnf repoquery --requires.

NO DEPLIST COMMAND

dnf does not have the deplist command. Instead, you should use dnf repoquery --requires.

EXCLUDES AND REPO EXCLUDES APPLY TO ALL OPERATIONS

In yum, the exclude and repo_exclude options in yum.conf(5) only applied to the install, update, and remove commands. In dnf, these options apply to all operations, including group installs.

THE INCLUDE OPTION HAS BEEN REMOVED

The include option in yum.conf(5) has been removed. Instead, you should use the --enable-repo and --disable-repo options on the command line, or use the enabled=0 option in the repository file.

DNF PROVIDES /BIN/<FILE> IS NOT FULLY SUPPORTED

dnf does not fully support dnf provides /bin/<file>. Instead, you should use dnf provides <file>, or dnf repoquery --provides <file>.

SKIP_IF_UNAVAILABLE COULD BE ENABLED BY DEFAULT

The skip_if_unavailable option in yum.conf(5) is now enabled by default in dnf. This means that if a repository is unavailable, dnf will not error out, but will instead continue without that repository.

OVERWRITE_GROUPS DROPPED, COMPS FUNCTIONS ACTING AS IF ALWAYS DISABLED

The overwrite_groups option in yum.conf(5) has been removed. The comps functions that were previously controlled by this option are now acting as if they were always disabled.

MIRRORLIST_EXPIRE DROPPED

The mirrorlist_expire option in yum.conf(5) has been removed. Dnf now uses a more efficient method for checking mirror lists.

METALINK NOT RECOGNIZED IN THE MIRRORLIST REPO OPTION

The metalink option in yum.conf(5) is no longer recognized in the mirrorlist repository option. If you need to use metalink, you should use the metalink option directly in the repository file.

ALWAYSPROMPT DROPPED

The alwaysprompt option in yum.conf(5) has been removed. Dnf will now always prompt for confirmation before installing, updating, or removing packages.

UPGRADE_REQUIREMENTS_ON_INSTALL DROPPED

The upgrade_requirements_on_install option in yum.conf(5) has been removed. Dnf will now always try to upgrade dependencies when installing a package.

DNF HISTORY ROLLBACK CHECK DROPPED

The dnf history rollback check command has been removed. Dnf will now always perform a rollback if the command is given.

PACKAGES REPLACEMENT WITHOUT YUM SWAP

In yum, when a package was replaced by another package, yum would automatically swap them out. Dnf now requires you to explicitly remove the old package before installing the new one.

DEPENDENCY PROCESSING DETAILS ARE NOT SHOWN IN THE CLI

Dnf does not show the detailed dependency processing information in the command-line interface. This information is still available in the debug logs.

DNF PROVIDES COMPLIES WITH THE YUM DOCUMENTATION OF THE COMMAND

The behavior of dnf provides is now consistent with the documentation for the yum provides command.

BANDWIDTH LIMITING

Dnf does not support bandwidth limiting. You can use external tools like trickles or pv to limit bandwidth.

INSTALLONLYPKGS CONFIG OPTION

The installonlypkgs configuration option in yum.conf(5) is now handled differently. Dnf will only keep a limited number of versions of packages listed in installonlypkgs. You can configure the number of versions to keep using the installonly_limit option in dnf.conf(5).

THE USAGE OF DELTA RPM FILES

Dnf uses delta RPM files by default. If you want to disable the usage of delta RPM files, you can set the deltarpm option to 0 in dnf.conf(5).

HANDLING .SRPM FILES AND NON-EXISTENT PACKAGES

Dnf does not support installing .src.rpm files. Also, dnf will now error out if you try to install a package that does not exist in any of the enabled repositories.

PROMOTING PACKAGE TO INSTALL TO A PACKAGE THAT OBSOLETES IT

In yum, if you tried to install a package that was obsoleted by another package, yum would automatically install the obsoleting package. Dnf will now prompt you to confirm the installation of the obsoleting package.

BEHAVIOR OF --INSTALLROOT OPTION

The --installroot option in dnf now behaves differently than in yum. In dnf, --installroot will create a new root directory and install packages into it. In yum, it would install packages into the specified directory, but still use the system's configuration files.

DIFFERENT PROMPT AFTER TRANSACTION TABLE

The prompt after the transaction summary table is now different. It will show you the packages to be installed, updated, or removed, and ask for confirmation.

LIST COMMAND SHOWS ALL REPO ALTERNATIVES

The dnf list command now shows all available repository alternatives for packages. This means that if a package is available in multiple repositories, dnf list will show all of them.

YUM-LANGPACKS SUBCOMMANDS HAVE BEEN REMOVED

The yum-langpacks subcommands have been removed. You can now use dnf langpacks instead.

DNF HISTORY SUBCOMMANDS LIST AND INFO RETURN 0 WHEN TRANSACTIONS NOT FOUND

The dnf history list and dnf history info subcommands now return 0 even if no transactions are found. This is different from yum, which would return a non-zero exit code.

YUM-UPDATEONBOOT AND YUM-CRON

The yum-updateonboot and yum-cron packages have been replaced by dnf-automatic. You can configure automatic updates using dnf-automatic.

UTILITIES THAT HAVE NOT BEEN PORTED YET

Some yum utilities have not yet been ported to dnf. These include:

  • yumdownloader
  • yum-builddep
  • yum-complete-transaction
  • yum-config-manager
  • yum-debug-dump
  • yum-debug-restore
  • yum-export-data
  • yum-groups-manager
  • yum-merge-conf
  • yum-mirror
  • yum-plugin-fastestmirror
  • yum-plugin-filter-data
  • yum-plugin-keys
  • yum-plugin-merge-conf
  • yum-plugin-ovl
  • yum-plugin-protect-packages
  • yum-plugin-ps
  • yum-plugin-remove-with-leaves
  • yum-plugin-security
  • yum-plugin-versionlock
  • yum-utils

You can use yum to run these utilities until they are ported to dnf.
