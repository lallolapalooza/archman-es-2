NOMBRE

yt-dlp - Descargador de audio/vídeo de línea de comandos con ricas funciones

SINOPSIS

yt-dlp [OPCIONES] URL [URL...]

DESCRIPCIÓN

yt-dlp es un descargador de audio/vídeo de línea de comandos con ricas funciones y soporte para miles de sitios. El proyecto es un fork de youtube-dl (https://github.com/ytdl-org/youtube-dl) basado en el ahora inactivo youtube-dlc (https://github.com/blackjack4494/yt-dlc).

Opciones Generales:

Muestra descripciones de todos los extractores soportados y sale
--use-extractors NOMBRES

Antepone un "-" al nombre para excluirlo, por ejemplo, --ies default,-generic. Usa --list-extractors para una lista de nombres de extractores. (Alias: --ies)
--default-search PREFIJO

No cargues ningún archivo de configuración personalizado (predeterminado). Cuando se usa dentro de un archivo de configuración, ignora todos los --config-locations definidos previamente en el archivo actual
--config-locations RUTA

--plugin-dirs DIR

Borra los directorios de plugins a buscar, incluyendo los predeterminados y los proporcionados por --plugin-dirs anteriores

Solo "deno" está habilitado por defecto. Se usará el runtime de mayor prioridad que esté tanto habilitado como disponible. Para usar un runtime de menor prioridad cuando "deno" está disponible, se debe pasar --no-js-runtimes antes de habilitar otros runtimes
--no-js-runtimes
Borra los runtimes de JavaScript a habilitar, incluyendo los predeterminados y los proporcionados por --js-runtimes anteriores
--remote-components COMPONENT

Esta opción actualmente no es necesaria si estás usando un ejecutable oficial o tienes instalada la versión requerida del paquete yt-dlp-ejs. --no-remote-components
Niega la obtención de todos los componentes remotos, incluyendo aquellos previamente permitidos por --remote-components o por defecto.
--flat-playlist
No extraer las entradas de resultado de una lista de reproducción; es posible que falte metadato de algunas entradas y se pueda omitir la descarga
--no-flat-playlist
Extraer completamente los vídeos de una lista de reproducción (predeterminado)
--live-from-start
Descarga transmisiones en vivo desde el principio. Actualmente experimental y solo soportado para YouTube y Twitch
--no-live-from-start
Descarga transmisiones en vivo desde el momento actual (predeterminado)
--wait-for-video MIN-MAX
Espera a que las transmisiones programadas estén disponibles. Pasa el número mínimo de segundos (o rango) para esperar entre reintentos
--no-wait-for-video
No esperar transmisiones programadas (predeterminado)
--mark-watched

--no-mark-watched

Selección de Vídeo:

-I, --playlist-items ITEM_SPEC
Índices de lista de reproducción separados por comas de los elementos a descargar. Puedes especificar un rango usando `"[INICIO]:[FIN][:PASO]"`. Para compatibilidad con versiones anteriores, también se admite `INICIO-FIN`. Usa índices negativos para contar desde el final y un `PASO` negativo para descargar en orden inverso. Por ejemplo, `"-I 1:3,7,-5::2"` en una lista de reproducción de tamaño 15 descargará los elementos en los índices 1, 2, 3, 7, 11, 13, 15.
--min-filesize TAMAÑO
Aborta la descarga si el tamaño del archivo es menor que `TAMAÑO`, por ejemplo, `50k` o `44.6M`.
--max-filesize TAMAÑO
Aborta la descarga si el tamaño del archivo es mayor que `TAMAÑO`, por ejemplo, `50k` o `44.6M`.
--date FECHA
Descarga solo vídeos subidos en esta fecha. La fecha puede ser `"YYYYMMDD"` o en el formato `[now|today|yesterday][-N[day|week|month|year]]`. Por ejemplo, `"--date today-2weeks"` descarga solo vídeos subidos el mismo día hace dos semanas.
--datebefore FECHA
Descarga solo vídeos subidos en o antes de esta fecha. Los formatos de fecha aceptados son los mismos que los de `--date`.
--dateafter FECHA
Descarga solo vídeos subidos en o después de esta fecha. Los formatos de fecha aceptados son los mismos que los de `--date`.
--match-filters FILTRO
Filtro genérico de vídeo. Cualquier campo de `"FORMATO DE SALIDA"` se puede comparar con un número o una cadena utilizando los operadores definidos en `"Filtering Formats"`. También puedes simplemente especificar un campo para que coincida si el campo está presente, usa `"!campo"` para comprobar si el campo no está presente, y `"\&"` para comprobar múltiples condiciones. Usa `""` para escapar `"\&"` o comillas si es necesario. Si se usa varias veces, el filtro coincide si al menos una de las condiciones se cumple. Por ejemplo, `--match-filters !is_live --match-filters "like_count>?100 & description~='(?i)& dogs'"` coincide solo con vídeos que no están en vivo O aquellos que tienen un recuento de "me gusta" superior a 100 (o el campo "me gusta" no está disponible) y además tienen una descripción que contiene la frase `"gatos & perros"` (sin distinguir mayúsculas y minúsculas). Usa `"--match-filters -"` para preguntar interactivamente si se debe descargar cada vídeo.
--no-match-filters
No usar ningún `--match-filters` (predeterminado).
--break-match-filters FILTRO
Igual que `"--match-filters"`, pero detiene el proceso de descarga cuando un vídeo es rechazado.
--no-break-match-filters
No usar ningún `--break-match-filters` (predeterminado).
--no-playlist
Descarga solo el vídeo, si la URL se refiere a un vídeo y una lista de reproducción.
--yes-playlist
Descarga la lista de reproducción, si la URL se refiere a un vídeo y una lista de reproducción.
--age-limit AÑOS
Descarga solo vídeos adecuados para la edad dada.
--download-archive ARCHIVO
Descarga solo vídeos no listados en el archivo. Registra los IDs de todos los vídeos descargados en él.
--no-download-archive
No usar archivo (predeterminado).
--max-downloads NÚMERO
Aborta después de descargar `NÚMERO` archivos.
--break-on-existing
Detiene el proceso de descarga al encontrar un archivo que está en el archivo proporcionado con la opción `--download-archive`.
--no-break-on-existing
No detiene el proceso de descarga al encontrar un archivo que está en el archivo (predeterminado).
--break-per-input
Modifica `--max-downloads`, `--break-on-existing`, `--break-match-filters` y la numeración automática para que se reinicien por cada URL de entrada.
--no-break-per-input
Las opciones `--break-on-existing` y similares terminan toda la cola de descarga.
--skip-playlist-after-errors N
Número de fallos permitidos hasta que se omita el resto de la lista de reproducción.

Opciones de Descarga:

-N, --concurrent-fragments N
Número de fragmentos de un vídeo dash/hlsnative que deben descargarse concurrentemente (predeterminado es 1).
-r, --limit-rate TASA
Tasa máxima de descarga en bytes por segundo, por ejemplo, `50K` o `4.2M`.
--throttled-rate TASA
Tasa mínima de descarga en bytes por segundo por debajo de la cual se asume estrangulamiento y se vuelven a extraer los datos del vídeo, por ejemplo, `100K`.
-R, --retries REINTENTOS
Número de reintentos (predeterminado es 10), o `"infinite"`.
--file-access-retries REINTENTOS
Número de veces que se reintenta un error de acceso al archivo (predeterminado es 3), o `"infinite"`.
--fragment-retries REINTENTOS
Número de reintentos para un fragmento (predeterminado es 10), o `"infinite"` (DASH, hlsnative e ISM).
--retry-sleep [TIPO:]EXPR
Tiempo de espera entre reintentos en segundos (opcionalmente) prefijado por el tipo de reintento (http (predeterminado), fragment, file_access, extractor) para aplicar el tiempo de espera. EXPR puede ser un número, `linear=INICIO[:FIN[:PASO=1]]` o `exp=INICIO[:FIN[:BASE=2]]`. Esta opción se puede usar varias veces para establecer el tiempo de espera para los diferentes tipos de reintento, por ejemplo, `--retry-sleep linear=1::2` `--retry-sleep fragment:exp=1:20`.
--skip-unavailable-fragments
Omitir fragmentos no disponibles para descargas DASH, hlsnative e ISM (predeterminado) (Alias: `--no-abort-on-unavailable-fragments`).
--abort-on-unavailable-fragments
Abortar la descarga si un fragmento no está disponible (Alias: `--no-skip-unavailable-fragments`).
--keep-fragments
Mantener los fragmentos descargados en el disco después de que la descarga haya finalizado.
--no-keep-fragments
Eliminar los fragmentos descargados después de que la descarga haya finalizado (predeterminado).

Network Options:

--buffer-size SIZE
Tamaño del búfer de descarga, por ejemplo, 1024 o 16K (el valor predeterminado es 1024)
--resize-buffer
El tamaño del búfer se ajusta automáticamente a partir de un valor inicial de --buffer-size (predeterminado)
--no-resize-buffer
No ajustar automáticamente el tamaño del búfer
--http-chunk-size SIZE
Tamaño de un fragmento para la descarga HTTP basada en fragmentos, por ejemplo, 10485760 o 10M (predeterminado está deshabilitado). Puede ser útil para evitar la limitación de ancho de banda impuesta por un servidor web (experimental)
--playlist-random
Descargar videos de la lista de reproducción en orden aleatorio
--lazy-playlist
Procesar entradas en la lista de reproducción a medida que se reciben. Esto deshabilita n_entries, --playlist-random y --playlist-reverse
--no-lazy-playlist
Procesar videos en la lista de reproducción solo después de que se haya analizado toda la lista de reproducción (predeterminado)
--hls-use-mpegts
Usar el contenedor mpegts para videos HLS; permitiendo que algunos reproductores reproduzcan el video mientras se descarga y reduciendo la posibilidad de corrupción de archivos si la descarga se interrumpe. Esto está habilitado por defecto para transmisiones en vivo
--no-hls-use-mpegts
No usar el contenedor mpegts para videos HLS. Este es el valor predeterminado cuando no se descargan transmisiones en vivo
--download-sections REGEX
Descargar solo capítulos que coincidan con la expresión regular. Un prefijo "*" denota un rango de tiempo en lugar de un capítulo. Las marcas de tiempo negativas se calculan desde el final. "*desde-url" se puede usar para descargar entre el "tiempo_inicio" y el "tiempo_fin" extraídos de la URL. Requiere ffmpeg. Esta opción se puede usar varias veces para descargar varias secciones, por ejemplo, --download-sections "*10:15-inf" --download-sections "intro".
--downloader [PROTO:]NOMBRE
Nombre o ruta del descargador externo a utilizar (opcionalmente) precedido por los protocolos (http, ftp, m3u8, dash, rstp, rtmp, mms) para utilizarlo. Actualmente soporta native, aria2c, axel, curl, ffmpeg, httpie, wget. Puedes usar esta opción varias veces para configurar diferentes descargadores para diferentes protocolos. Por ejemplo, --downloader aria2c --downloader "dash,m3u8:native" utilizará aria2c para descargas http/ftp, y el descargador nativo para descargas dash/m3u8 (Alias: --external-downloader).
--downloader-args NOMBRE:ARGUMENTOS
Dar estos argumentos al descargador externo. Especifica el nombre del descargador y los argumentos separados por dos puntos ":". Para ffmpeg, los argumentos se pueden pasar a diferentes posiciones utilizando la misma sintaxis que --postprocessor-args. Puedes usar esta opción varias veces para dar diferentes argumentos a diferentes descargadores (Alias: --external-downloader-args).

Opciones del sistema de archivos:

-a, --batch-file ARCHIVO
Archivo que contiene las URLs a descargar ("-" para stdin), una URL por línea. Las líneas que comienzan con "#", ";" o "]" se consideran comentarios y se ignoran.
--no-batch-file
No leer URLs del archivo por lotes (predeterminado)
-P, --paths [TIPOS:]RUTA
Las rutas donde se descargarán los archivos. Especifica el tipo de archivo y la ruta separadas por dos puntos ":". Se admiten todos los TIPOS iguales a --output. Adicionalmente, también puedes proporcionar rutas "home" (predeterminada) y "temp". Todos los archivos intermedios se descargan primero en la ruta temporal y luego los archivos finales se mueven a la ruta home después de que la descarga haya finalizado. Esta opción se ignora si --output es una ruta absoluta.
-o, --output [TIPOS:]PLANTILLA
Plantilla de nombre de archivo de salida; consulta "PLANTILLA DE SALIDA" para obtener detalles.
--output-na-placeholder TEXTO
Marcador de posición para campos no disponibles en --output (predeterminado: "NA")
--restrict-filenames
Restringir los nombres de archivo a solo caracteres ASCII, y evitar "&" y espacios en los nombres de archivo.
--no-restrict-filenames
Permitir caracteres Unicode, "&" y espacios en los nombres de archivo (predeterminado)
--windows-filenames
Forzar que los nombres de archivo sean compatibles con Windows.
--no-windows-filenames
Sanitizar nombres de archivo solo mínimamente.
--trim-filenames LONGITUD
Limitar la longitud del nombre de archivo (excluyendo la extensión) al número especificado de caracteres.
-w, --no-overwrites
No sobrescribir ningún archivo.
--force-overwrites
Sobrescribir todos los archivos de video y metadatos. Esta opción incluye --no-continue.
--no-force-overwrites
No sobrescribir el video, pero sí sobrescribir archivos relacionados (predeterminado)
-c, --continue
Reanudar archivos/fragmentos parcialmente descargados (predeterminado)
--no-continue
No reanudar fragmentos parcialmente descargados. Si el archivo no está fragmentado, reiniciar la descarga de todo el archivo.
--part
Usar archivos .part en lugar de escribir directamente en el archivo de salida (predeterminado)
--no-part
No usar archivos .part - escribir directamente en el archivo de salida
--mtime
Usar la cabecera Last-modified para establecer la hora de modificación del archivo.
--no-mtime
No usar la cabecera Last-modified para establecer la hora de modificación del archivo (predeterminado)
--write-description
Escribir la descripción del video en un archivo .description.
--no-write-description
No escribir la descripción del video (predeterminado)
--write-info-json
Escribir metadatos del video en un archivo .info.json (esto puede contener información personal).
--no-write-info-json
No escribir metadatos del video (predeterminado)
--write-playlist-metafiles
Escribir metadatos de la lista de reproducción además de los metadatos del video al usar --write-info-json, --write-description, etc. (predeterminado)
--no-write-playlist-metafiles
No escribir metadatos de la lista de reproducción al usar --write-info-json, --write-description, etc.
--clean-info-json
Eliminar algunos metadatos internos como nombres de archivo del infojson (predeterminado)
--no-clean-info-json
Escribir todos los campos en el infojson
--write-comments
Obtener comentarios del video para colocarlos en el infojson. Los comentarios se obtienen incluso sin esta opción si se sabe que la extracción es rápida (Alias: --get-comments)
--no-write-comments
No obtener comentarios del video a menos que se sepa que la extracción es rápida (Alias: --no-get-comments)
--load-info-json ARCHIVO
Archivo JSON que contiene la información del video (creado con la opción "--write-info-json")
--cookies ARCHIVO
Archivo en formato Netscape para leer cookies desde y volcar el tarro de cookies en.
--no-cookies
No leer/volcar cookies desde/hacia el archivo (predeterminado)
--cookies-from-browser NAVEGADOR[+KEYRING][:PERFIL][::CONTENEDOR]
Nombre del navegador desde el cual cargar las cookies. Los navegadores compatibles actualmente son: brave, chrome, chromium, edge, firefox, opera, safari, vivaldi, whale. Opcionalmente, se puede proporcionar el KEYRING utilizado para descifrar las cookies de Chromium en Linux, el nombre/ruta del PERFIL desde el cual cargar las cookies, y el nombre del CONTENEDOR (si es Firefox) ("none" para ningún contenedor) con sus respectivos separadores. Por defecto, se utilizan todos los contenedores del perfil accedido más recientemente. Los keyrings compatibles actualmente son: basictext, gnomekeyring, kwallet, kwallet5, kwallet6.
--no-cookies-from-browser
No cargar cookies desde el navegador (predeterminado)
--cache-dir DIR
Ubicación en el sistema de archivos donde yt-dlp puede almacenar de forma permanente cierta información descargada (como identificadores de cliente y firmas). Por defecto ${XDG_CACHE_HOME}/yt-dlp
--no-cache-dir
Deshabilitar el caché del sistema de archivos
--rm-cache-dir
Eliminar todos los archivos de caché del sistema de archivos

Si deseas que tu archivo se decodifique de manera diferente, agrega # coding: CODIFICACIÓN al principio del archivo (por ejemplo, # coding: shift-jis). No debe haber caracteres antes de eso, ni siquiera espacios o BOM.

Autenticación con netrc

También es posible que desees configurar el almacenamiento automático de credenciales para extractores que admiten autenticación (proporcionando inicio de sesión y contraseña con --username y --password) para no pasar las credenciales como argumentos de línea de comandos en cada ejecución de yt-dlp y evitar el seguimiento de contraseñas en texto plano en el historial de comandos del shell. Puedes lograr esto usando un archivo .netrc (https://stackoverflow.com/tags/.netrc/info) por extractor. Para ello, deberás crear un archivo .netrc en --netrc-location y restringir los permisos de lectura/escritura solo a ti:

touch ${HOME}/.netrc
chmod a-rwx,u+rw ${HOME}/.netrc

Después de eso, puedes agregar credenciales para un extractor en el siguiente formato, donde *extractor* es el nombre del extractor en minúsculas:

machine <extractor> login <username> password <password>

Por ejemplo:

machine youtube login myaccount@gmail.com password my_youtube_password
machine twitch login my_twitch_account_name password my_twitch_password

Para activar la autenticación con el archivo .netrc, debes pasar --netrc a yt-dlp o colocarlo en el archivo de configuración.

La ubicación predeterminada del archivo .netrc es ~ (ver más abajo).

Como alternativa al uso del archivo .netrc, que tiene la desventaja de mantener tus contraseñas en un archivo de texto plano, puedes configurar un comando de shell personalizado para proporcionar las credenciales de un extractor. Esto se hace proporcionando el parámetro --netrc-cmd, que debe generar las credenciales en formato netrc y devolver 0 en caso de éxito; otros valores se tratarán como un error. {} en el comando se reemplazará por el nombre del extractor para que sea posible seleccionar las credenciales del extractor correcto.

Por ejemplo, para usar un archivo .netrc cifrado almacenado como .authinfo.gpg

yt-dlp --netrc-cmd 'gpg --decrypt ~/.authinfo.gpg' 'https://www.youtube.com/watch?v=BaW_jenozKc'

Las variables de entorno normalmente se especifican como ${VARIABLE}/$VARIABLE en UNIX y %VARIABLE% en Windows; pero siempre se muestran como ${VARIABLE} en esta documentación
•
yt-dlp también permite usar variables estilo UNIX en Windows para opciones tipo ruta; por ejemplo, --output, --config-locations
•
Si no está configurado, ${XDG_CONFIG_HOME} tiene como valor predeterminado ~/.config y ${XDG_CACHE_HOME} a ~/.cache
•
En Windows, ~ apunta a ${HOME} si está presente; o, ${USERPROFILE} o ${HOMEDRIVE}${HOMEPATH} en caso contrario
•
En Windows, ${USERPROFILE} generalmente apunta a C:\Users\<nombre de usuario> y ${APPDATA} a ${USERPROFILE}\AppData\Roaming

PLANTILLA DE SALIDA

La opción -o se usa para indicar una plantilla para los nombres de los archivos de salida, mientras que la opción -P se usa para especificar la ruta donde se debe guardar cada tipo de archivo.

El uso más simple de -o es no establecer ningún argumento de plantilla al descargar un solo archivo, como en yt-dlp -o funny_video.flv "https://some/video" (codificar la extensión del archivo de esta manera *no* se recomienda y podría romper algunos post-procesamientos).

Sin embargo, también puede contener secuencias especiales que se reemplazarán al descargar cada video. Las secuencias especiales pueden formatearse según las operaciones de formato de cadena de Python (https://docs.python.org/3/library/stdtypes.html#printf-style-string-formatting), por ejemplo, %(NOMBRE)s o %(NOMBRE)05d. Para aclarar, eso es un símbolo de porcentaje seguido de un nombre entre paréntesis, seguido de operaciones de formato.

Los nombres de los campos en sí (la parte dentro de los paréntesis) también pueden tener un formato especial:

1.
Recorrido de objetos: Los diccionarios y listas disponibles en los metadatos se pueden recorrer usando un separador de punto .; por ejemplo, %(tags.0)s, %(subtitles.en.-1.ext)s. Puedes usar slicing de Python con dos puntos :; por ejemplo, %(id.3:7)s, %(id.6:2:-1)s, %(formats.:.format_id)s. Las llaves {} se pueden usar para construir diccionarios con claves específicas; por ejemplo, %(formats.:.{format_id,height})#j. Un nombre de campo vacío %()s se refiere a todo el infodict; por ejemplo, %(.{id,title})s. Ten en cuenta que todos los campos que se vuelven disponibles usando este método no se enumeran a continuación. Usa -j para ver dichos campos
2.
Aritmética: Se pueden realizar operaciones aritméticas simples en campos numéricos usando +, - y *. Por ejemplo, %(playlist_index+10)03d, %(n_entries+1-playlist_index)d
3.
Formato de fecha/hora: Los campos de fecha/hora se pueden formatear según el formato strftime (https://docs.python.org/3/library/datetime.html#strftime-and-strptime-format-codes) especificándolo separado del nombre del campo usando un >. Por ejemplo, %(duration>%H-%M-%S)s, %(upload_date>%Y-%m-%d)s, %(epoch-3600>%H-%M-%S)s
4.
Alternativas: Se pueden especificar campos alternativos separados por una ,. Por ejemplo, %(release_date>%Y,upload_date>%Y|Unknown)s
5.
Reemplazo: Se puede especificar un valor de reemplazo usando un separador & según el minilenguaje de formato de str.format (https://docs.python.org/3/library/string.html#format-specification-mini-language). Si el campo *no* está vacío, se usará este valor de reemplazo en lugar del contenido real del campo. Esto se hace después de considerar los campos alternativos; por lo tanto, el reemplazo se usa si *cualquiera* de los campos alternativos *no* está vacío. Por ejemplo, %(chapters&has chapters|no chapters)s, %(title&TITLE={:>20}|NO TITLE)s
6.
Predeterminado: Se puede especificar un valor predeterminado literal para cuando el campo esté vacío usando un separador |. Esto anula --output-na-placeholder. Por ejemplo, %(uploader|Unknown)s
7.
Más conversiones: Además de los tipos de formato normales diouxXeEfFgGcrs, yt-dlp admite adicionalmente conversiones a B = **B**ytes, j = **j**son (bandera # para impresión elegante, + para Unicode), h = escape HTML, l = una **l**ista separada por comas (bandera # para \n separada por saltos de línea), q = una cadena **q**ue cotiza para la terminal (bandera # para dividir una lista en diferentes argumentos), D = agregar sufijos **D**ecimales (por ejemplo, 10M) (bandera # para usar 1024 como factor), y S = **S**anitizar como nombre de archivo (bandera # para restringido)
8.
Normalización Unicode: El tipo de formato U se puede usar para la normalización Unicode NFC (https://docs.python.org/3/library/unicodedata.html#unicodedata.normalize). La bandera de forma alternativa (#) cambia la normalización a NFD y la bandera de conversión + se puede usar para la normalización de equivalencia de compatibilidad NFKC/NFKD. Por ejemplo, %(title)+.100U es NFKC

Para resumir, la sintaxis general para un campo es:

%(name[.keys][addition][>strf][,alternate][&replacement][|default])[flags][width][.precision][length]type

Además, puedes establecer diferentes plantillas de salida para los diversos archivos de metadatos por separado de la plantilla de salida general especificando el tipo de archivo seguido de la plantilla separada por dos puntos :. Los diferentes tipos de archivo admitidos son subtitle, thumbnail, description, annotation (obsoleto), infojson, link, pl_thumbnail, pl_description, pl_infojson, chapter, pl_video. Por ejemplo, -o "%(title)s.%(ext)s" -o "thumbnail:%(title)s\%(title)s.%(ext)s" colocará las miniaturas en una carpeta con el mismo nombre que el video. Si alguna de las plantillas está vacía, ese tipo de archivo no se escribirá. Por ejemplo, --write-thumbnail -o "thumbnail:" escribirá miniaturas solo para listas de reproducción y no para videos.

Nota: Debido al post-procesamiento (es decir, fusión, etc.), el nombre de archivo de salida real podría diferir. Usa --print after_move:filepath para obtener el nombre después de que todo el post-procesamiento haya finalizado.

Para secuencias numéricas, puedes usar formato numérico relacionado ( https://docs.python.org/3/library/stdtypes.html#printf-style-string-formatting ); por ejemplo, %(view_count)05d dará como resultado una cadena con el contador de vistas rellenado con ceros hasta 5 caracteres, como en 00042.

Las plantillas de salida también pueden contener rutas jerárquicas arbitrarias, por ejemplo, -o "%(playlist)s/%(playlist_index)s - %(title)s.%(ext)s" lo que resultará en la descarga de cada video en un directorio que corresponda a esta plantilla de ruta. Cualquier directorio faltante se creará automáticamente para ti.

Para usar literales de porcentaje en una plantilla de salida, usa %%. Para enviar la salida a stdout, usa -o -.

La plantilla predeterminada actual es %(title)s [%(id)s].%(ext)s.

En algunos casos, no querrás caracteres especiales como 中, espacios o &, como cuando transfieres el nombre de archivo descargado a un sistema Windows o el nombre de archivo a través de un canal inseguro de 8 bits. En estos casos, agrega la bandera --restrict-filenames para obtener un título más corto.

SELECCIÓN DE FORMATO

Por defecto, yt-dlp intenta descargar la mejor calidad disponible si **no** pasas ninguna opción. Esto es generalmente equivalente a usar -f bestvideo*+bestaudio/best. Sin embargo, si se habilitan múltiples flujos de audio (--audio-multistreams), el formato predeterminado cambia a -f bestvideo+bestaudio/best. De manera similar, si ffmpeg no está disponible, o si usas yt-dlp para transmitir a stdout (-o -), el predeterminado se convierte en -f best/bestvideo+bestaudio.

Advertencia de deprecación: Las últimas versiones de yt-dlp pueden transmitir múltiples formatos a stdout simultáneamente usando ffmpeg. Por lo tanto, en versiones futuras, el valor predeterminado para esto se establecerá en -f bv*+ba/b, similar a las descargas normales. Si deseas preservar la configuración -f b/bv+ba, se recomienda especificarla explícitamente en las opciones de configuración.

La sintaxis general para la selección de formato es -f FORMAT (o --format FORMAT) donde FORMAT es una **expresión selectora**, es decir, una expresión que describe el formato o los formatos que te gustaría descargar.

El caso más simple es solicitar un formato específico; por ejemplo, con -f 22 puedes descargar el formato con código de formato igual a 22. Puedes obtener la lista de códigos de formato disponibles para un video particular usando --list-formats o -F. Ten en cuenta que estos códigos de formato son específicos del extractor.

También puedes usar una extensión de archivo (actualmente se admiten 3gp, aac, flv, m4a, mp3, mp4, ogg, wav, webm) para descargar el formato de mejor calidad de una extensión de archivo particular servida como un solo archivo, por ejemplo, -f webm descargará el formato de mejor calidad con extensión webm servido como un solo archivo.

Puedes usar -f - para proporcionar interactivamente el selector de formato **para cada video**

También puedes usar nombres especiales para seleccionar formatos de casos límite particulares:

•
all: Selecciona **todos los formatos** por separado
•
mergeall: Selecciona y **fusiona todos los formatos** (Debe usarse con --audio-multistreams, --video-multistreams o ambos)
•
b*, best*: Selecciona el formato de mejor calidad que **contiene** un video o un audio o ambos (es decir, vcodec!=none o acodec!=none)
•
b, best: Selecciona el formato de mejor calidad que **contiene tanto** video como audio. Equivalente a best*[vcodec!=none][acodec!=none]
•
bv, bestvideo: Selecciona el formato **solo de video** de mejor calidad. Equivalente a best*[acodec=none]
•
bv*, bestvideo*: Selecciona el formato de mejor calidad que **contiene video**. Puede contener también audio. Equivalente a best*[vcodec!=none]
•
ba, bestaudio: Selecciona el formato **solo de audio** de mejor calidad. Equivalente a best*[vcodec=none]
•
ba*, bestaudio*: Selecciona el formato de mejor calidad que **contiene audio**. Puede contener también video. Equivalente a best*[acodec!=none] (¡No usar! (https://github.com/yt-dlp/yt-dlp/issues/979#issuecomment-919629354))
•
w*, worst*: Selecciona el formato de peor calidad que contiene un video o un audio
•
w, worst: Selecciona el formato de peor calidad que contiene tanto video como audio. Equivalente a worst*[vcodec!=none][acodec!=none]
•
wv, worstvideo: Selecciona el formato solo de video de peor calidad. Equivalente a worst*[acodec=none]
•
wv*, worstvideo*: Selecciona el formato de peor calidad que contiene video. Puede contener también audio. Equivalente a worst*[vcodec!=none]
•
wa, worstaudio: Selecciona el formato solo de audio de peor calidad. Equivalente a worst*[vcodec=none]
•
wa*, worstaudio*: Selecciona el formato de peor calidad que contiene audio. Puede contener también video. Equivalente a worst*[acodec!=none]

Por ejemplo, para descargar el formato solo de video de peor calidad, puedes usar -f worstvideo. Sin embargo, se recomienda no usar worst y opciones relacionadas. Cuando tu selector de formato es worst, se selecciona el formato que es peor en todos los aspectos. La mayoría de las veces, lo que realmente quieres es el video con el menor tamaño de archivo. Por lo tanto, generalmente es mejor usar -S +size o, de manera más rigurosa, -S +size,+br,+res,+fps en lugar de -f worst. Ver Ordenando Formatos para más detalles.

Puedes seleccionar el n-ésimo mejor formato de un tipo usando best<tipo>.<n>. Por ejemplo, best.2 seleccionará el segundo mejor formato combinado. De manera similar, bv*.3 seleccionará el tercer mejor formato que contenga un flujo de video.

Si quieres descargar varios videos, y no tienen los mismos formatos disponibles, puedes especificar el orden de preferencia usando barras diagonales. Ten en cuenta que los formatos en el lado izquierdo son preferidos; por ejemplo, -f 22/17/18 descargará el formato 22 si está disponible, de lo contrario descargará el formato 17 si está disponible, de lo contrario descargará el formato 18 si está disponible, de lo contrario se quejará de que no hay formatos adecuados disponibles para descargar.

Si quieres descargar varios formatos del mismo video, usa una coma como separador, por ejemplo, -f 22,17,18 descargará los tres formatos, por supuesto, si están disponibles. O un ejemplo más sofisticado combinado con la característica de precedencia: -f 136/137/mp4/bestvideo,140/m4a/bestaudio.

Puedes fusionar el video y el audio de múltiples formatos en un solo archivo usando -f <formato1>+<formato2>+... (requiere que ffmpeg esté instalado); por ejemplo, -f bestvideo+bestaudio descargará el mejor formato solo de video, el mejor formato solo de audio y los unirá con ffmpeg.

Advertencia de deprecación: Dado que el comportamiento descrito *a continuación* es complejo y contraintuitivo, se eliminará y los múltiples flujos se habilitarán por defecto en el futuro. En su lugar, se agregará un nuevo operador para limitar los formatos a un solo audio/video

A menos que se use --video-multistreams, todos los formatos con un flujo de video excepto el primero se ignoran. De manera similar, a menos que se use --audio-multistreams, todos los formatos con un flujo de audio excepto el primero se ignoran. Por ejemplo, -f bestvideo+best+bestaudio --video-multistreams --audio-multistreams descargará y fusionará los 3 formatos dados. El archivo resultante tendrá 2 flujos de video y 2 flujos de audio. Pero -f bestvideo+best+bestaudio --no-video-multistreams descargará y fusionará solo bestvideo y bestaudio. best se ignora ya que otro formato que contiene un flujo de video (bestvideo) ya ha sido seleccionado. El orden de los formatos es, por lo tanto, importante. -f best+bestaudio --no-audio-multistreams descargará solo best, mientras que -f bestaudio+best --no-audio-multistreams ignorará best y descargará solo bestaudio.

Filtrado de Formatos

También puedes filtrar los formatos de video poniendo una condición entre corchetes, como en -f "best[heig

ht=720]" (o -f "[filesize>10M]" ya que los filtros sin selector se interpretan como "mejor").

•

•

•

•

•

•

•

•

•

El filtrado también funciona para comparaciones = (igual), ^= (comienza con), $= (termina con), *= (contiene), ~= (coincide con regex) y los siguientes metacampos de cadena:

•

•

•

•

•

•

También puede usar los filtros con all para descargar todos los formatos que cumplan con el filtro, por ejemplo, -f "all[vcodec=none]" selecciona todos los formatos solo de audio.

Los selectores de formato también se pueden agrupar usando paréntesis; por ejemplo, -f "(mp4,webm)[height<480]" descargará los mejores formatos pre-unidos de mp4 y webm con una altura inferior a 480.

Ordenar Formatos

Puede cambiar los criterios para ser considerado el mejor usando -S (--format-sort). El formato general para esto es --format-sort campo1,campo2....

Los campos disponibles son:

•
hasvid: Da prioridad a los formatos que tienen una transmisión de video
•
hasaud: Da prioridad a los formatos que tienen una transmisión de audio
•
ie_pref: La preferencia de formato
•
lang: La preferencia de idioma según lo determinado por el extractor (por ejemplo, idioma original preferido sobre descripción de audio)
•
quality: La calidad del formato
•
source: La preferencia de la fuente
•
proto: Protocolo utilizado para la descarga (https/ftps > http/ftp > m3u8_native/m3u8 > http_dash_segments> websocket_frag > mms/rtsp > f4f/f4m)
•
vcodec: Códec de Video (av01 > vp9.2 > vp9 > h265 > h264 > vp8 > h263 > theora > other)
•
acodec: Códec de Audio (flac/alac > wav/aiff > opus > vorbis > aac > mp4a > mp3 > ac4 > eac3 > ac3 > dts > other)
•
codec: Equivalente a vcodec,acodec
•
vext: Extensión de Video (mp4 > mov > webm > flv > other). Si se usa --prefer-free-formats, se prefiere webm.
•
aext: Extensión de Audio (m4a > aac > mp3 > ogg > opus > webm > other). Si se usa --prefer-free-formats, el orden cambia a ogg > opus > webm > mp3 > m4a > aac
•
ext: Equivalente a vext,aext
•
filesize: Tamaño de archivo exacto, si se conoce de antemano
•
fs_approx: Tamaño de archivo aproximado
•
size: Tamaño de archivo exacto si está disponible, de lo contrario, tamaño de archivo aproximado
•
height: Altura del video
•
width: Ancho del video
•
res: Resolución del video, calculada como la dimensión más pequeña.
•
fps: Tasa de fotogramas del video
•
hdr: El rango dinámico del video (DV > HDR12 > HDR10+ > HDR10 > HLG > SDR)
•
channels: El número de canales de audio
•
tbr: Tasa de bits promedio total en kbps
•
vbr: Tasa de bits de video promedio en kbps
•
abr: Tasa de bits de audio promedio en kbps
•
br: Tasa de bits promedio en kbps, tbr/vbr/abr
•
asr: Frecuencia de muestreo de audio en Hz

Advertencia de deprecación: Muchos de estos campos tienen alias (actualmente indocumentados), que pueden eliminarse en una versión futura. Se recomienda usar solo los nombres de campo documentados.

Todos los campos, a menos que se especifique lo contrario, se ordenan en orden descendente. Para invertir esto, prefije el campo con un +. Por ejemplo, +res prefiere el formato con la resolución más pequeña. Adicionalmente, puede añadir un valor preferido para los campos, separado por dos puntos (:). Por ejemplo, res:720 prefiere videos más grandes, pero no más grandes que 720p, y el video más pequeño si no hay videos de menos de 720p. Para codec y ext, puede proporcionar dos valores preferidos, el primero para video y el segundo para audio. Por ejemplo, +codec:avc:m4a (equivalente a +vcodec:avc,+acodec:m4a) establece la preferencia de códec de video a h264 > h265 > vp9 > vp9.2 > av01 > vp8 > h263 > theora y la preferencia de códec de audio a mp4a > aac > vorbis > opus > mp3 > ac3 > dts. También puede hacer que el ordenamiento prefiera los valores más cercanos a los proporcionados usando ~ como delimitador. Por ejemplo, filesize~1G prefiere el formato con un tamaño de archivo más cercano a 1 GiB.

Los campos hasvid y ie_pref siempre tienen la máxima prioridad en el ordenamiento, independientemente del orden definido por el usuario. Este comportamiento se puede cambiar usando --format-sort-force. Aparte de estos, el orden predeterminado utilizado es: lang,quality,res,fps,hdr:12,vcodec,channels,acodec,size,br,asr,proto,ext,hasaud,source,id. Los extractores pueden anular este orden predeterminado, pero no pueden anular el orden proporcionado por el usuario.

Tenga en cuenta que el valor predeterminado para hdr es hdr:12; es decir, Dolby Vision no es preferido. Esta elección se hizo ya que los formatos DV aún no son totalmente compatibles con la mayoría de los dispositivos. Esto puede cambiar en el futuro.

Si su selector de formato es worst, el último elemento se selecciona después de ordenar. Esto significa que seleccionará el formato que sea el peor en todos los aspectos. La mayoría de las veces, lo que realmente quieres es el video con el tamaño de archivo más pequeño. Por lo tanto, generalmente es mejor usar -f best -S +size,+br,+res,+fps.

Consejo: Puede usar -v -F para ver cómo se han ordenado los formatos (de peor a mejor).

MODIFICAR METADATOS

Los metadatos obtenidos por los extractores pueden modificarse utilizando --parse-metadata y --replace-in-metadata

--replace-in-metadata CAMPOS REGEX REEMPLAZO se utiliza para reemplazar texto en cualquier campo de metadatos utilizando expresiones regulares de Python (https://docs.python.org/3/library/re.html#regular-expression-syntax). Se pueden utilizar referencias posteriores (https://docs.python.org/3/library/re.html?highlight=backreferences#re.sub) en la cadena de reemplazo para uso avanzado.

La sintaxis general de --parse-metadata DESDE:HASTA es dar el nombre de un campo o una plantilla de salida de la que extraer datos, y el formato para interpretarlo, separados por dos puntos :. Se puede utilizar una expresión regular de Python (https://docs.python.org/3/library/re.html#regular-expression-syntax) con grupos de captura con nombre, un solo nombre de campo o una sintaxis similar a la plantilla de salida (solo se admite el formato %(field)s) para HASTA. La opción se puede utilizar varias veces para analizar y modificar varios campos.

Tenga en cuenta que estas opciones conservan su orden relativo, lo que permite realizar reemplazos en campos analizados y viceversa. Además, cualquier campo creado de esta manera se puede usar en la plantilla de salida y también afectará a los metadatos del archivo multimedia agregados cuando se utiliza --embed-metadata.

Esta opción también tiene algunos usos especiales:

•
Puede descargar una URL adicional basada en los metadatos del video que se está descargando actualmente. Para ello, establezca el campo additional_urls en la URL que desea descargar. Por ejemplo, --parse-metadata "description:(?P<additional_urls>https?://www .vimeo.com/\d+)" descargará el primer video de vimeo que se encuentre en la descripción
•
Puede utilizar esto para cambiar los metadatos que se incrustan en el archivo multimedia. Para ello, establezca el valor del campo correspondiente con un prefijo meta_. Por ejemplo, cualquier valor que establezca en el campo meta_description se agregará al campo description en el archivo; puede usar esto para establecer una "description" y una "synopsis" diferentes. Para modificar los metadatos de flujos individuales, utilice el prefijo meta<n>_ (por ejemplo, meta1_language). Cualquier valor establecido en el campo meta_ sobrescribirá todos los valores predeterminados.

Nota: La modificación de metadatos ocurre antes de la selección de formato, post-extracción y otras operaciones de post-procesamiento. Algunos campos pueden agregarse o cambiarse durante estos pasos, invalidando sus cambios.

Como referencia, estos son los campos que yt-dlp agrega por defecto a los metadatos del archivo:

UPDATE

You can use yt-dlp -U to update if you are using the release binaries

If you installed with pip (https://github.com/yt-dlp/yt-dlp/wiki/Installation#with-pip), simply re-run the same command that was used to install the program

For other third-party package managers, see the wiki (https://github.com/yt-dlp/yt-dlp/wiki/Installation#third-party-package-managers) or refer to their documentation

There are currently three release channels for binaries: stable, nightly and master.

•
stable is the default channel, and many of its changes have been tested by users of the nightly and master channels.
•
The nightly channel has releases scheduled to build every day around midnight UTC, for a snapshot of the project's new patches and changes. This is the recommended channel for regular users of yt-dlp. The nightly releases are available from yt-dlp/yt-dlp-nightly-builds (https://github.com/yt-dlp/yt-dlp-nightly-builds/releases) or as development releases of the yt-dlp PyPI package (which can be installed with pip's --pre flag).
•
The master channel features releases that are built after each push to the master branch, and these will have the very latest fixes and additions, but may also be more prone to regressions. They are available from yt-dlp/yt-dlp-master-builds (https://github.com/yt-dlp/yt-dlp-master-builds/releases).

When using --update/-U, a release binary will only update to its current channel. --update-to CHANNEL can be used to switch to a different channel when a newer version is available. --update-to [CHANNEL@]TAG can also be used to upgrade or downgrade to specific tags from a channel.

You may also use --update-to <repository> (<owner>/<repository>) to update to a channel on a completely different repository. Be careful with what repository you are updating to though, there is no verification done for binaries from different repositories.

Example usage:

•
yt-dlp --update-to master switch to the master channel and update to its latest release
•
yt-dlp --update-to stable@2023.07.06 upgrade/downgrade to release to stable channel tag 2023.07.06
•
yt-dlp --update-to 2023.10.07 upgrade/downgrade to tag 2023.10.07 if it exists on the current channel
•
yt-dlp --update-to example/yt-dlp@2023.09.24 upgrade/downgrade to the release from the example/yt-dlp repository, tag 2023.09.24

Important: Any user experiencing an issue with the stable release should install or update to the nightly release before submitting a bug report:

# To update to nightly from stable executable/binary:
yt-dlp --update-to nightly
# To install nightly with pip:
python -m pip install -U --pre "yt-dlp[default]"

When running a yt-dlp version that is older than 90 days, you will see a warning message suggesting to update to the latest version. You can suppress this warning by adding --no-update to your command or configuration file.

PLUGINS

Ten en cuenta que **todos** los plugins se importan incluso si no se invocan, y que **no se realizan comprobaciones** sobre el código del plugin. **¡Usa los plugins bajo tu propio riesgo y solo si confías en el código!**

Los plugins pueden ser de tipo extractor o postprocesador. Los plugins extractores no necesitan ser habilitados desde la línea de comandos y se invocan automáticamente cuando la URL de entrada es adecuada para ello. Los plugins extractores tienen prioridad sobre los extractores integrados. Los plugins postprocesadores se pueden invocar usando --use-postprocessor NOMBRE.

Los plugins se cargan desde los paquetes de espacio de nombres yt_dlp_plugins.extractor y yt_dlp_plugins.postprocessor.

En otras palabras, la estructura de archivos en el disco se ve algo así:

            myplugin.py
        postprocessor/
            myplugin.py

yt-dlp busca estas carpetas de espacio de nombres yt_dlp_plugins en muchas ubicaciones (ver más abajo) y carga plugins de **todas** ellas. Establece la variable de entorno YTDLP_NO_PLUGINS a algo no vacío para deshabilitar la carga de plugins por completo.

INCRUSTAR YT-DLP

yt-dlp hace todo lo posible para ser un buen programa de línea de comandos, y por lo tanto debería ser invocable desde cualquier lenguaje de programación.

Tu programa debe evitar analizar la salida estándar normal, ya que puede cambiar en versiones futuras. En su lugar, debe usar opciones como -J, --print, --progress-template, --exec, etc. para crear una salida de consola que puedas reproducir y analizar de manera confiable.

Desde un programa Python, puedes incrustar yt-dlp de una manera más potente, de la siguiente manera:

from yt_dlp import YoutubeDL
URLS = ['https://www.youtube.com/watch?v=BaW_jenozKc']
with YoutubeDL() as ydl:
    ydl.download(URLS)

Lo más probable es que quieras usar varias opciones. Para ver una lista de opciones disponibles, echa un vistazo a yt_dlp/YoutubeDL.py o ayuda(yt_dlp.YoutubeDL) en un shell de Python. Si ya estás familiarizado con la línea de comandos, puedes usar devscripts/cli_to_api.py (https://github.com/yt-dlp/yt-dlp/blob/master/devscripts/cli_to_api.py) para traducir cualquier opción de línea de comandos a parámetros de YoutubeDL.

Consejo: Si estás migrando tu código de youtube-dl a yt-dlp, un punto importante a tener en cuenta es que no garantizamos que el valor de retorno de YoutubeDL.extract_info sea serializable en JSON, o incluso que sea un diccionario. Será similar a un diccionario, pero si quieres asegurarte de que sea un diccionario serializable, pásalo por YoutubeDL.sanitize_info como se muestra en el siguiente ejemplo.

PERSONALIZACIÓN

Este programa puede ser personalizado para realizar diferentes acciones. Algunas de las personalizaciones más comunes son:

Añadir un registrador personalizado

import yt_dlp
URLS = ['https://www.youtube.com/watch?v=BaW_jenozKc']
class MyLogger:
    def debug(self, msg):
        # Don't do anything with debug messages
        pass
    def warning(self, msg):
        pass
    def error(self, msg):
        print(msg)
# ℹ️ Ver "progress_hooks" en help(yt_dlp.YoutubeDL)
def my_hook(d):
    if d['status'] == 'finished':
        print('Descarga completada, ahora post-procesando...')
ydl_opts = {
    'logger': MyLogger(),
    'progress_hooks': [my_hook],
}
with yt_dlp.YoutubeDL(ydl_opts) as ydl:
    ydl.download(URLS)

Añadir un PostProcessor personalizado

import yt_dlp
URLS = ['https://www.youtube.com/watch?v=BaW_jenozKc']
# ℹ️ Ver help(yt_dlp.postprocessor.PostProcessor)
class MyCustomPP(yt_dlp.postprocessor.PostProcessor):
    def run(self, info):
        self.to_screen('Haciendo cosas')
        return [], info
with yt_dlp.YoutubeDL() as ydl:
    # ℹ️ "when" puede tomar cualquier valor en yt_dlp.utils.POSTPROCESS_WHEN
    ydl.add_post_processor(MyCustomPP(), when='pre_process')
    ydl.download(URLS)

Usar un selector de formato personalizado

import yt_dlp
URLS = ['https://www.youtube.com/watch?v=BaW_jenozKc']
def format_selector(ctx):
    """ Selecciona el mejor video y el mejor audio que no resulte en un mkv.
    NOTA: Este es solo un ejemplo y no maneja todos los casos """
    # los formatos ya están ordenados de peor a mejor
    formats = ctx.get('formats')[::-1]
    # acodec='none' significa que no hay audio
    best_video = next(f for f in formats
                      if f['vcodec'] != 'none' and f['acodec'] == 'none')
    # encuentra la extensión de audio compatible
    audio_ext = {'mp4': 'm4a', 'webm': 'webm'}[best_video['ext']]
    # vcodec='none' significa que no hay video
    best_audio = next(f for f in formats if (
        f['acodec'] != 'none' and f['vcodec'] == 'none' and f['ext'] == audio_ext))
    # Estos son los campos mínimos requeridos para un formato fusionado
    yield {
        'format_id': f'{best_video["format_id"]}+{best_audio["format_id"]}',
        'ext': best_video['ext'],
        'requested_formats': [best_video, best_audio],
        # Debe ser una lista de protocolos separada por +
        'protocol': f'{best_video["protocol"]}+{best_audio["protocol"]}'
    }
ydl_opts = {
    'format': format_selector,
}
with yt_dlp.YoutubeDL(ydl_opts) as ydl:
    ydl.download(URLS)

Diferencias en el comportamiento por defecto

Algunas de las opciones por defecto de yt-dlp son diferentes a las de youtube-dl y youtube-dlc:

•
yt-dlp solo soporta Python 3.10+ y eliminará el soporte para más versiones a medida que lleguen a su fin de vida (EOL) (https://devguide.python.org/versions/#python-release-cycle); mientras que youtube-dl todavía soporta Python 2.6+ y 3.2+ (https://github.com/ytdl-org/youtube-dl/issues/30568#issue-1118238743)
•
Las opciones --auto-number (-A), --title (-t) y --literal (-l) ya no funcionan. Ver opciones eliminadas para más detalles
•
avconv no es compatible como alternativa a ffmpeg
•
yt-dlp almacena los archivos de configuración en ubicaciones ligeramente diferentes a youtube-dl. Ver CONFIGURACIÓN para una lista de las ubicaciones correctas
•
La plantilla de salida por defecto es %(title)s [%(id)s].%(ext)s. No hay una razón real para este cambio. Se cambió antes de que yt-dlp se hiciera público y ahora no hay planes de revertirlo a %(title)s-%(id)s.%(ext)s. En su lugar, puedes usar --compat-options filename
•
La ordenación de formatos por defecto es diferente a youtube-dl y prefiere resoluciones más altas y mejores códecs en lugar de bitrates más altos. Puedes usar la opción --format-sort para cambiarla a cualquier orden que prefieras, o usar --compat-options format-sort para usar el orden de ordenación de youtube-dl. Versiones anteriores de yt-dlp preferían VP9 debido a su mayor compatibilidad; puedes usar --compat-options prefer-vp9-sort para volver a esa preferencia de ordenación de formatos. Estas dos opciones de compatibilidad no se pueden usar juntas
•
El selector de formato por defecto es bv*+ba/b. Esto significa que si se encuentra un formato combinado de video + audio que es mejor que el mejor formato solo de video, se preferirá el primero. Usa -f bv+ba/b o --compat-options format-spec para revertir esto
•
A diferencia de youtube-dlc, yt-dlp no permite fusionar múltiples flujos de audio/video en un solo archivo por defecto (ya que esto entra en conflicto con el uso de -f bv*+ba). Si es necesario, esta característica debe habilitarse

Opciones de compatibilidad

--compat-options multistreams: Use --audio-multistreams y --video-multistreams. También puede usar --compat-options multistreams para habilitar ambos
--no-abort-on-error está habilitado por defecto. Use --abort-on-error o --compat-options abort-on-error para abortar en caso de error
Al escribir archivos de metadatos como miniaturas, descripción o infojson, la misma información (si está disponible) también se escribe para las listas de reproducción. Use --no-write-playlist-metafiles o --compat-options no-playlist-metafiles para no escribir estos archivos
--add-metadata adjunta el infojson a los archivos mkv además de escribir los metadatos cuando se usa con --write-info-json. Use --no-embed-info-json o --compat-options no-attach-info-json para revertir esto
Algunos metadatos se incrustan en diferentes campos cuando se usa --add-metadata en comparación con youtube-dl. Notablemente, el campo comentario contiene la webpage_url y la sinopsis contiene la descripción. Puede usar --parse-metadata para modificar esto a su gusto o usar --compat-options embed-metadata para revertir esto
playlist_index se comporta de manera diferente cuando se usa con opciones como --playlist-reverse y --playlist-items. Consulte #302 (https://github.com/yt-dlp/yt-dlp/issues/302) para obtener detalles. Puede usar --compat-options playlist-index si desea mantener el comportamiento anterior
La salida de -F se enumera en un nuevo formato. Use --compat-options list-formats para revertir esto
Los chats en vivo (si están disponibles) se consideran subtítulos. Use --sub-langs all,-live_chat para descargar todos los subtítulos excepto los chats en vivo. También puede usar --compat-options no-live-chat para evitar la descarga de cualquier chat en vivo/danmaku
Las URL de canales de YouTube descargan todas las cargas del canal. Para descargar solo los videos en una pestaña específica, pase la URL de la pestaña. Si el canal no muestra la pestaña solicitada, se generará un error. Además, las URL /live generan un error si no hay videos en vivo en lugar de descargar silenciosamente todo el canal. Puede usar --compat-options no-youtube-channel-redirect para revertir todas estas redirecciones
Los videos no disponibles también se enumeran para las listas de reproducción de YouTube. Use --compat-options no-youtube-unavailable-videos para eliminar esto
Las fechas de carga extraídas de YouTube están en UTC.
Si ffmpeg se usa como descargador, la descarga y fusión de formatos ocurren en un solo paso cuando sea posible. Use --compat-options no-direct-merge para revertir esto
La incrustación de miniaturas en mp4 se realiza con mutagen si es posible. Use --compat-options embed-thumbnail-atomicparsley para forzar el uso de AtomicParsley en su lugar
Se eliminan algunos metadatos internos, como los nombres de archivo, de infojson por defecto. Use --no-clean-infojson o --compat-options no-clean-infojson para revertir esto
Cuando se usan --embed-subs y --write-subs juntos, los subtítulos se escriben en el disco y también se incrustan en el archivo multimedia. Puede usar solo --embed-subs para incrustar los subtítulos y eliminar automáticamente el archivo separado. Consulte #630 (comment) (https://github.com/yt-dlp/yt-dlp/issues/630#issuecomment-893659460) para más información. --compat-options no-keep-subs puede usarse para revertir esto
certifi se usará para los certificados raíz SSL, si está instalado. Si desea usar certificados del sistema (por ejemplo, autofirmados), use --compat-options no-certifi
La sanitización de caracteres inválidos en nombres de archivo de yt-dlp es diferente/más inteligente que en youtube-dl. Puede usar --compat-options filename-sanitization para revertir al comportamiento de youtube-dl
[STRIKEOUT:yt-dlp intenta analizar las salidas del descargador externo en la salida de progreso estándar si es posible (Implementado actualmente: aria2c (https://github.com/yt-dlp/yt-dlp/issues/5931)). Puede usar --compat-options no-external-downloader-progress para obtener la salida del descargador tal cual]
Las versiones de yt-dlp entre 2021.09.01 y 2023.01.02 aplican --match-filters a listas de reproducción anidadas. Este fue un efecto secundario no intencional de 8f18ac (https://github.com/yt-dlp/yt-dlp/commit/8f18aca8717bb0dd49054555af8d386e5eda3a88) y se corrigió en d7b460 (https://github.com/yt-dlp/yt-dlp/commit/d7b460d0e5fc710950582baed2e3fc616ed98a80). Use --compat-options playlist-match-filter para revertir esto
Las versiones de yt-dlp entre 2021.11.10 y 2023.06.21 estimaron valores filesize_approx para formatos fragmentados/manifiesto. Esto se agregó para conveniencia en f2fe69 (https://github.com/yt-dlp/yt-dlp/commit/f2fe69c7b0d208bdb1f6292b4ae92bc1e1a7444a), pero se revirtió en 0dff8e (https://github.com/yt-dlp/yt-dlp/commit/0dff8e4d1e6e9fb938f4256ea9af7d81f42fd54f) debido a la imprecisión potencialmente extrema de los valores estimados. Use --compat-options manifest-filesize-approx para seguir extrayendo los valores estimados
yt-dlp utiliza backends de clientes http modernos como requests. Use --compat-options prefer-legacy-http-handler para preferir el manejador http heredado (urllib) para solicitudes http estándar.
Los submódulos swfinterp, casefold se eliminan.
Pasar --simulate (o llamar a extract_info con download=False) ya no altera la selección de formato por defecto. Consulte #9843 (https://github.com/yt-dlp/yt-dlp/issues/9843) para obtener detalles.
yt-dlp ya no aplica la hora modificada por el servidor a los archivos descargados por defecto. Use --mtime o --compat-options mtime-by-default para revertir esto.
