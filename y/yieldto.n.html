yieldto(n)

Paquete: tcl

Licencias: TCL

coroutine(n) Comandos integrados de Tcl coroutine(n)

NOMBRE

coroutine, yield, yieldto - Crear y producir valores desde corrutinas

SINOPSIS

coroutine nombre comando ?arg...?
yield ?valor?
yieldto comando ?arg...?
nombre ?valor...?

DESCRIPCIÓN

El comando coroutine crea un nuevo contexto de corrutina (con el comando asociado) llamado nombre y ejecuta ese contexto llamando a comando, pasando los argumentos restantes sin más interpretación. Una vez que comando retorna normalmente o con una excepción (por ejemplo, un error), el contexto de corrutina nombre se elimina.

Dentro del contexto, se pueden generar valores como resultados usando el comando yield; si no se proporciona ningún valor, se usa la cadena vacía. Cuando se llama a eso, el contexto suspenderá la ejecución y el comando coroutine devolverá el argumento a yield. La ejecución del contexto puede reanudarse llamando al comando de contexto, pasando opcionalmente el único valor para usarlo como resultado de la llamada yield que provocó la suspensión del contexto. Si el contexto de corrutina nunca produce un valor y en su lugar retorna convencionalmente, el resultado del comando coroutine será el resultado de la evaluación del contexto.

La corrutina también puede suspender su ejecución mediante el uso del comando yieldto, que en lugar de retornar, cede la ejecución a algún comando llamado comando (resuelto en el contexto de la corrutina) y al cual se le puede pasar cualquier número de argumentos. Dado que cada corrutina tiene un comando de contexto, yieldto puede usarse para transferir el control directamente de una corrutina a otra (esto solo es aconsejable si las dos corrutinas esperan que esto suceda) pero cualquier comando puede ser el objetivo. Si una corrutina se suspende por este mecanismo, el procesamiento de la corrutina puede reanudarse llamando al comando de contexto, pasando opcionalmente un número arbitrario de argumentos. El valor de retorno de la llamada yieldto será la lista de argumentos pasados al comando de contexto; depende del llamador decidir qué hacer con esos valores.

La forma recomendada de escribir una versión de yield que permita la reanudación con múltiples argumentos es usar yieldto y el comando return, de esta manera:

proc yieldm {valor} {
    yieldto return -level 0 $valor
}

La corrutina también puede ser eliminada destruyendo el comando nombre, y el nombre de la corrutina actual puede obtenerse usando info coroutine. Si hay trazas de eliminación en las variables de la implementación de la corrutina, se activarán en el momento en que la corrutina sea eliminada explícitamente (o, naturalmente, si el comando retorna convencionalmente).

En el momento en que se llama a comando, el namespace actual será el namespace global y no habrá ningún frame de pila encima (en el sentido de upvar y uplevel). Sin embargo, qué comando se llamará se determinará en el namespace desde el cual se llamó al comando coroutine.

EJEMPLOS

Este ejemplo muestra una corrutina que producirá una secuencia infinita de valores pares, y un bucle que consume los primeros diez de ellos.

proc allNumbers {} {
    yield
    set i 0
    while 1 {
        yield $i
        incr i 2
    }
}
coroutine nextNumber allNumbers
for {set i 0} {$i < 10} {incr i} {
    puts "recibido [nextNumber]"
}
rename nextNumber {}

En este ejemplo, la corrutina actúa para sumar los argumentos que se le pasan.

coroutine accumulator apply {{} {
    set x 0
    while 1 {
        incr x [yield $x]
    }
}}
for {set i 0} {$i < 10} {incr i} {
    puts "$i -> [accumulator $i]"
}

Este ejemplo demuestra el uso de corrutinas para implementar el clásico algoritmo de la Criba de Eratóstenes para encontrar números primos. Observe la creación de corrutinas dentro de una corrutina.

proc filterByFactor {source n} {
    yield [info coroutine]
    while 1 {
        set x [$source]
        if {$x % $n} {
            yield $x
        }
    }
}
coroutine allNumbers apply {{} {while 1 {yield [incr x]}}}
coroutine eratosthenes apply {c {
    yield
    while 1 {
        set n [$c]
        yield $n
        set c [coroutine prime$n filterByFactor $c $n]
    }
}} allNumbers
for {set i 1} {$i <= 20} {incr i} {
    puts "primo#$i = [eratosthenes]"
}

Este ejemplo muestra cómo un valor puede pasarse entre un grupo de tres corrutinas que se ceden mutuamente la palabra:

proc juggler {nombre objetivo {valor ""}} {
    si {$valor eq ""} {
        set valor [yield [info coroutine]]
    }
    mientras {$valor ne ""} {
        puts "$nombre : $valor"
        set valor [string range $valor 0 end-1]
        lassign [yieldto $objetivo $valor] valor
    }
}
coroutine j1 juggler Larry [
    coroutine j2 juggler Curly [
        coroutine j3 juggler Moe j1]] "Nyuck!Nyuck!Nyuck!"

SEMÁNTICA DETALLADA

Este ejemplo demuestra que las corrutinas comienzan desde el namespace global, y que la resolución de comando ocurre antes de que se cree la pila de corrutina.

proc report {donde nivel} {
    # ¿Desde dónde se llamó al llamador?
    set ns [uplevel 2 {namespace current}]
    yield "creado $donde $nivel contexto=$ns nombre=[info coroutine]"
}
proc example {} {
    report outer [info level]
}
namespace eval demo {
    proc example {} {
        report inner [info level]
    }
    proc makeExample {} {
        puts "haciendo desde [info level]"
        puts [coroutine coroEg example]
    }
    makeExample
}

En particular, podemos ver que se ha producido manipulación de pila (comparando los niveles de la primera y segunda línea) y que el nivel padre en la corrutina es el namespace global. También podemos ver que los nombres de corrutina son locales al namespace actual si no están calificados, y que las corrutinas pueden ceder en profundidad (por ejemplo, en procedimientos llamados).
