YASM_ARCH(7) Arquitecturas soportadas por Yasm YASM_ARCH(7)

NOMBRE

yasm_arch - Arquitecturas objetivo soportadas por Yasm

SINOPSIS

yasm -a arquitectura [-m máquina] ...

DESCRIPCIÓN

La distribución estándar de Yasm incluye una serie de módulos para diferentes arquitecturas objetivo. Cada arquitectura objetivo puede soportar una o más arquitecturas de máquina.

La arquitectura y la máquina se seleccionan en la línea de comandos de yasm(1) mediante las opciones de línea de comandos -a arquitectura y -m máquina, respectivamente.

La arquitectura de máquina también puede ser seleccionada automáticamente por ciertos formatos de objeto. Por ejemplo, el formato de objeto 'elf32' selecciona la arquitectura de máquina 'x86' por defecto, mientras que el formato de objeto 'elf64' selecciona la arquitectura de máquina 'amd64' por defecto.

ARQUITECTURA X86

La arquitectura 'x86' soporta el conjunto de instrucciones IA-32 y sus derivados, así como el conjunto de instrucciones AMD64. Consiste en dos máquinas: 'x86' (para IA-32 y derivados) y 'amd64' (para AMD64 y derivados). La máquina por defecto para la arquitectura 'x86' es la máquina 'x86'.

Configuración BITS

La configuración BITS de la arquitectura x86 especifica a Yasm el modo del procesador en el que se pretende ejecutar el código generado. Los procesadores x86 pueden ejecutarse en tres modos de ejecución principales: 16 bits, 32 bits y, en procesadores que soportan AMD64, 64 bits. Dado que el conjunto de instrucciones x86 contiene partes cuya función depende del modo de ejecución (como los prefijos de anulación de tamaño de operando y tamaño de dirección), Yasm no puede ensamblar instrucciones x86 correctamente a menos que el usuario le indique en qué modo de procesador se ejecutará el código.

La configuración BITS se puede cambiar de diversas maneras. Al usar el analizador compatible con NASM, la configuración BITS se puede cambiar directamente mediante el uso de la directiva del ensamblador BITS xx. La configuración BITS por defecto viene determinada por el formato de objeto en uso.

Extensiones BITS 64

La arquitectura AMD64 es una nueva arquitectura de 64 bits desarrollada por AMD, basada en la arquitectura x86 de 32 bits. Extiende la arquitectura x86 original duplicando el número de registros de propósito general y SIMD, extendiendo las operaciones aritméticas y el espacio de direcciones a 64 bits, además de otras características.

Recientemente, Intel ha introducido una versión esencialmente idéntica de AMD64 llamada EM64T.

Cuando un procesador compatible con AMD64 se ejecuta en modo de 64 bits, hay disponibles una serie de extensiones adicionales, incluyendo registros de propósito general adicionales, registros SSE2 adicionales y direcciones relativas a RIP.

Yasm extiende la sintaxis base de NASM para soportar AMD64 de la siguiente manera. Para habilitar el ensamblaje de instrucciones para el modo de 64 bits de los procesadores AMD64, use la directiva BITS 64. Al igual que con la directiva BITS de NASM, esto no cambia el formato del archivo de objeto de salida a 64 bits; solo cambia el modo del ensamblador para asumir que las instrucciones que se están ensamblando se ejecutarán en modo de 64 bits. Para especificar un archivo de objeto AMD64, use -m amd64 en la línea de comandos de Yasm, o apunte explícitamente a un formato de objeto de 64 bits como -f win64 o -f elf64. Se puede usar -f elfx32 para seleccionar el formato de objeto ELF de 32 bits para procesadores AMD64.

Cambios en los Registros

Los registros adicionales de propósito general de 64 bits se denominan r8-r15. También existen subregistros de 8 bits (rXb), 16 bits (rXw) y 32 bits (rXd) que se mapean a los 8, 16 o 32 bits menos significativos del registro de 64 bits. Los registros originales de propósito general de 8 bits también se han extendido a 64 bits: eax, edx, ecx, ebx, esi, edi, esp y ebp tienen nuevas versiones de 64 bits llamadas rax, rdx, rcx, rbx, rsi, rdi, rsp y rbp respectivamente. Los antiguos registros de 32 bits se mapean a los bits menos significativos de los nuevos registros de 64 bits.

También están disponibles nuevos registros de 8 bits que se mapean a los 8 bits menos significativos de rsi, rdi, rsp y rbp. Estos se llaman sil, dil, spl y bpl respectivamente. Desafortunadamente, debido a la forma en que se codifican las instrucciones, estos nuevos registros de 8 bits se codifican de la misma manera que los antiguos registros de 8 bits ah, dh, ch y bh. El procesador indica cuál se está utilizando mediante la presencia del nuevo prefijo REX que se utiliza para especificar los otros registros extendidos. Esto significa que es ilegal mezclar el uso de ah, dh, ch y bh con una instrucción que requiere el prefijo REX por otras razones. Por ejemplo:

add ah, [r10]

(sintaxis NASM) no es una instrucción válida porque el uso de r10 requiere un prefijo REX, lo que hace imposible usar ah.

En modo de 64 bits, también hay disponibles 8 registros SSE2 adicionales. Estos se denominan xmm8-xmm15.

Instrucciones de 64 bits

Por defecto, la mayoría de las operaciones en modo de 64 bits siguen siendo de 32 bits; las operaciones que son de 64 bits generalmente requieren un prefijo REX (un bit en el prefijo REX determina si una operación es de 64 bits o de 32 bits). Por lo tanto, esencialmente todas las instrucciones de 32 bits tienen una versión de 64 bits, y las versiones de 64 bits de las instrucciones pueden usar registros extendidos "gratis" (ya que el prefijo REX ya está presente). Ejemplos en sintaxis NASM:

mov eax, 1  ; instrucción de 32 bits
mov rcx, 1  ; instrucción de 64 bits

Las instrucciones que modifican la pila (push, pop, call, ret, enter y leave) son implícitamente de 64 bits. Sus contrapartes de 32 bits no están disponibles, pero sus contrapartes de 16 bits sí lo están. Ejemplos en sintaxis NASM:

push eax  ; instrucción ilegal
push rbx  ; instrucción de 1 byte
push r11  ; instrucción de 2 bytes con prefijo REX

Extensión Implícita de Cero

Los resultados de las operaciones de 32 bits se extienden implícitamente a cero a los 32 bits superiores del registro de 64 bits correspondiente. Las operaciones de 16 y 8 bits, por otro lado, no afectan a los bits superiores del registro (al igual que en los modos de 32 y 16 bits). Esto se puede utilizar para generar código más pequeño en algunos casos. Ejemplos en sintaxis NASM:

mov ecx, 1  ; 1 byte más corto que mov rcx, 1
and edx, 3  ; equivalente a and rdx, 3

Inmediatos

Para la mayoría de las instrucciones en modo de 64 bits, los valores inmediatos siguen siendo de 32 bits; su valor se extiende con signo a los 32 bits superiores del registro de destino antes de ser utilizado. La excepción es la instrucción mov, que puede tomar un inmediato de 64 bits cuando el destino es un registro de 64 bits. Ejemplos en sintaxis NASM:

add rax, 1           ; optimizado a 8 bits con signo
add rax, dword 1     ; forzar tamaño a 32 bits
add rax, 0xffffffff  ; extensión con signo de 32 bits
add rax, -1          ; igual que el anterior
add rax, 0xffffffffffffffff ; truncado a 32 bits (advertencia)
mov eax, 1           ; 5 bytes
mov rax, 1           ; 5 bytes (optimizado a 32 bits con signo)
mov rax, qword 1     ; 10 bytes (forzado a 64 bits)
mov rbx, 0x1234567890abcdef ; 10 bytes
mov rcx, 0xffffffff  ; 10 bytes (no cabe en 32 bits con signo)
mov ecx, -1          ; 5 bytes, equivalente al anterior
mov rcx, sym         ; 5 bytes, tamaño por defecto de 32 bits para símbolos
mov rcx, qword sym   ; 10 bytes, anular el tamaño por defecto

El manejo de mov reg64, inmediato sin tamaño es diferente entre YASM y NASM 2.x; YASM sigue el comportamiento anterior, mientras que NASM 2.x hace lo siguiente:

add rax, 0xffffffff  ; inmediato de 32 bits con extensión de signo
add rax, -1          ; igual que el anterior
add rax, 0xffffffffffffffff ; inmediato de 32 bits truncado (advertencia)
add rax, sym         ; inmediato de 32 bits con extensión de signo

yasm_arch(7)

NAME

yasm_arch - yasm architecture-specific syntax and directives

SYNOPSIS

yasm -a arch [ -f format ] ...

The following architectures are supported:

x86
32-bit and 64-bit x86 instruction sets.
lc3b
LC-3b ISA.

DESCRIPTION

The yasm assembler supports multiple architectures. This man page describes architecture-specific syntax and directives. Use the -a flag to specify the architecture, or the arch directive within the source file.

X86 ARCHITECTURE

The x86 architecture supports both 32-bit (i386) and 64-bit (amd64) modes. The default mode is 32-bit. To assemble for 64-bit mode, use the BITS 64 directive in your source file, or the -m amd64 flag on the command line.

Immediates 

mov eax, 1           ; 5 bytes (inmediato de 32 bits)
mov rax, 1           ; 10 bytes (inmediato de 64 bits)
mov rbx, 0x1234567890abcdef ; instrucción de 10 bytes
mov rcx, 0xffffffff  ; instrucción de 10 bytes
mov ecx, -1          ; 5 bytes, equivalente al anterior
mov ecx, sym         ; 5 bytes (inmediato de 32 bits)
mov rcx, sym         ; instrucción de 10 bytes
mov rcx, qword sym   ; 10 bytes (inmediato de 64 bits)

Displacements

Al igual que los inmediatos, los desplazamientos, en su mayor parte, permanecen de 32 bits y se extienden con signo antes de su uso. Nuevamente, la excepción es una forma restringida de la instrucción mov: entre el registro al/ax/eax/rax y una dirección absoluta de 64 bits (no se permiten registros en la dirección efectiva). En la sintaxis NASM, el uso de la forma absoluta de 64 bits requiere [qword]. Ejemplos en sintaxis NASM:

mov eax, [1]    ; 32 bits, con extensión de signo
mov al, [rax-1] ; 32 bits, con extensión de signo
mov al, [qword 0x1122334455667788] ; absoluto de 64 bits
mov al, [0x1122334455667788] ; truncado a 32 bits (advertencia)

RIP Relative Addressing

En modo de 64 bits, hay una nueva forma de direccionamiento efectivo disponible para facilitar la escritura de código independiente de la posición. Cualquier referencia de memoria puede hacerse relativa a RIP (RIP es el registro del puntero de instrucción, que contiene la dirección de la ubicación inmediatamente posterior a la instrucción actual).

En la sintaxis NASM, hay dos formas de especificar el direccionamiento relativo a RIP:

mov dword [rip+10], 1

almacena el valor 1 diez bytes después del final de la instrucción. 10 también puede ser una constante simbólica y se tratará de la misma manera. Por otro lado,

mov dword [symb wrt rip], 1

almacena el valor 1 en la dirección del símbolo symb. Esto es claramente diferente del comportamiento de:

mov dword [symb+rip], 1

que toma la dirección del final de la instrucción, le suma la dirección de symb, y luego almacena el valor 1 allí. Si symb es una variable, ¡esto *no* almacenará el valor 1 en la variable symb!

Yasm también soporta la siguiente sintaxis para el direccionamiento relativo a RIP:

mov [rel sym], rax  ; relativo a RIP
mov [abs sym], rax  ; no relativo a RIP

El comportamiento de:

mov [sym], rax

Depende de un modo establecido por la directiva DEFAULT, como sigue. El modo predeterminado es siempre "abs", y en modo "rel", el uso de registros, una anulación de segmento fs o gs, o una anulación explícita "abs" resultará en una dirección efectiva no relativa a RIP.

default rel
mov [sym], rbx      ; relativo a RIP
mov [abs sym], rbx  ; no relativo a RIP (anulación explícita)
mov [rbx+1], rbx    ; no relativo a RIP (uso de registro)
mov [fs:sym], rbx   ; no relativo a RIP (uso de fs o gs)
mov [ds:sym], rbx   ; relativo a RIP (segmento, pero no fs o gs)
mov [rel sym], rbx  ; relativo a RIP (anulación redundante)
default abs
mov [sym], rbx      ; no relativo a RIP
mov [abs sym], rbx  ; no relativo a RIP
mov [rbx+1], rbx    ; no relativo a RIP
mov [fs:sym], rbx   ; no relativo a RIP
mov [ds:sym], rbx   ; no relativo a RIP
mov [rel sym], rbx  ; relativo a RIP (anulación explícita)

Memory references

Por lo general, el tamaño de una referencia de memoria se puede deducir por los registros que se están moviendo. Por ejemplo, "mov [rax],ecx" es un movimiento de 32 bits, porque ecx es de 32 bits. YASM actualmente genera el error no obvio "combinación inválida de opcode y operandos" si no puede averiguar cuánta memoria estás moviendo. La solución en este caso es agregar un especificador de tamaño de memoria: qword, dword, word o byte.

Aquí hay un movimiento de memoria de 64 bits, que establece 8 bytes comenzando en rax:

mov qword [rax], 1

Aquí hay un movimiento de memoria de 32 bits, que establece 4 bytes:

mov dword [rax], 1

Aquí hay un movimiento de memoria de 16 bits, que establece 2 bytes:

mov word [rax], 1

Aquí hay un movimiento de memoria de 8 bits, que establece 1 byte:

mov byte [rax], 1

LC3B ARCHITECTURE

La arquitectura "lc3b" soporta el ISA LC-3b tal como se utiliza en el curso ECE 312 (ahora ECE 411) en la Universidad de Illinois, Urbana-Champaign, así como en otros cursos universitarios. Vea http://courses.ece.uiuc.edu/ece411/ para más detalles y código de ejemplo. La arquitectura "lc3b" consiste en una sola máquina: "lc3b".

BUGS

Al usar la arquitectura "x86", es demasiado fácil generar código AMD64 (usando la directiva BITS 64) y generar un archivo objeto de 32 bits (al no especificar -m amd64 en la línea de comandos o al seleccionar un formato de objeto de 64 bits). Del mismo modo, especificar -m amd64 no establece BITS a 64 por defecto. Una forma fácil de evitar esto es especificar directamente un formato de objeto de 64 bits como -f elf64.
