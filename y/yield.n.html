coroutine(n) Comandos integrados de Tcl coroutine(n)

NOMBRE

coroutine, yield, yieldto - Crear y producir valores desde coroutines

SINOPSIS

coroutine nombre comando ?arg...?
yield ?valor?
yieldto comando ?arg...?
nombre ?valor...?

DESCRIPCIÓN

El comando coroutine crea un nuevo contexto de coroutine (con un comando asociado) llamado nombre y ejecuta ese contexto llamando a comando, pasando los demás argumentos restantes sin más interpretación. Una vez que comando retorna normalmente o con una excepción (p.ej., un error), el contexto de coroutine nombre se elimina.

Dentro del contexto, se pueden generar valores como resultados usando el comando yield; si no se proporciona ningún valor, se usa la cadena vacía. Cuando se llama a esto, el contexto suspenderá la ejecución y el comando coroutine devolverá el argumento de yield. La ejecución del contexto se puede reanudar llamando al comando de contexto, pasando opcionalmente el único valor a usar como resultado de la llamada yield que provocó la suspensión del contexto. Si el contexto de coroutine nunca cede y en su lugar retorna convencionalmente, el resultado del comando coroutine será el resultado de la evaluación del contexto.

La coroutine también puede suspender su ejecución mediante el uso del comando yieldto, que en lugar de retornar, cede la ejecución a algún comando llamado comando (resuelto en el contexto de la coroutine) y al cual se le puede pasar *cualquier* *número* de argumentos. Dado que cada coroutine tiene un comando de contexto, yieldto puede usarse para transferir el control directamente de una coroutine a otra (esto solo es aconsejable si las dos coroutines esperan que esto suceda) pero *cualquier* comando puede ser el objetivo. Si una coroutine se suspende por este mecanismo, el procesamiento de la coroutine puede reanudarse llamando al comando de contexto, pasando opcionalmente un número arbitrario de argumentos. El valor de retorno de la llamada yieldto será la lista de argumentos pasados al comando de contexto; depende del llamador decidir qué hacer con esos valores.

La forma recomendada de escribir una versión de yield que permita la reanudación con múltiples argumentos es usando yieldto y el comando return, así:

proc yieldm {valor} {
    yieldto return -level 0 $valor
}

La coroutine también puede ser eliminada destruyendo el comando nombre, y el nombre de la coroutine actual se puede obtener usando info coroutine. Si hay trazas de eliminación en las variables de la implementación de la coroutine, se activarán en el momento en que la coroutine sea eliminada explícitamente (o, naturalmente, si el comando retorna convencionalmente).

En el momento en que se llama a comando, el namespace actual será el namespace global y no habrá frames de pila por encima de él (en el sentido de upvar y uplevel). Sin embargo, qué comando se llamará se determinará en el namespace desde el cual se llamó al comando coroutine.

EJEMPLOS

Este ejemplo muestra una coroutine que producirá una secuencia infinita de valores pares, y un bucle que consume los diez primeros.

proc todosLosNumeros {} {
    yield
    set i 0
    while 1 {
        yield $i
        incr i 2
    }
}
coroutine siguienteNumero todosLosNumeros
for {set i 0} {$i < 10} {incr i} {
    puts "recibido [siguienteNumero]"
}
rename siguienteNumero {}

En este ejemplo, la coroutine actúa para sumar los argumentos que se le pasan.

coroutine acumulador apply {{} {
    set x 0
    while 1 {
        incr x [yield $x]
    }
}}
for {set i 0} {$i < 10} {incr i} {
    puts "$i -> [acumulador $i]"
}

Este ejemplo demuestra el uso de coroutines para implementar el clásico algoritmo de la Criba de Eratóstenes para encontrar números primos. Tenga en cuenta la creación de coroutines dentro de una coroutine.

proc filtrarPorFactor {fuente n} {
    yield [info coroutine]
    while 1 {
        set x [$fuente]
        if {$x % $n} {
            yield $x
        }
    }
}
coroutine todosLosNumeros apply {{} {while 1 {yield [incr x]}}}
coroutine criba apply {c {
    yield
    while 1 {
        set n [$c]
        yield $n
        set c [coroutine primo$n filtrarPorFactor $c $n]
    }
}} todosLosNumeros
for {set i 1} {$i <= 20} {incr i} {
    puts "primo#$i = [criba]"
}

Este ejemplo muestra cómo un valor puede ser pasado entre un grupo de tres coroutines que se ceden mutuamente:

proc malabarista {nombre objetivo {valor ""}} {
    if {$valor eq ""} {
        set valor [yield [info coroutine]]
    }
    while {$valor ne ""} {
        puts "$nombre : $valor"
        set valor [string range $valor 0 end-1]
        lassign [yieldto $objetivo $valor] valor
    }
}
coroutine j1 malabarista Larry [
    coroutine j2 malabarista Curly [
        coroutine j3 malabarista Moe j1]] "Nyuck!Nyuck!Nyuck!"

SEMÁNTICA DETALLADA

Este ejemplo demuestra que las coroutines comienzan desde el namespace global y que la resolución del comando ocurre antes de que se cree la pila de coroutines.

proc reportar {donde nivel} {
    # ¿De dónde fue llamado el llamador?
    set ns [uplevel 2 {namespace current}]
    yield "creado contexto $donde $nivel contexto=$ns nombre=[info coroutine]"
}
proc ejemplo {} {
    reportar exterior [info level]
}
namespace eval demo {
    proc ejemplo {} {
        reportar interior [info level]
    }
    proc hacerEjemplo {} {
        puts "haciendo desde [info level]"
        puts [coroutine coroEj ejemplo]
    }
    hacerEjemplo
}

También podemos ver que los nombres de las coroutines son locales al namespace actual si no están calificados, y que las coroutines pueden ceder a profundidad (p.ej., en procedimientos llamados).
