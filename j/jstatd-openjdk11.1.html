jstatd(1) Herramientas de monitorización jstatd(1)

NOMBRE

jstatd - Monitoriza Máquinas Virtuales Java (JVM) y permite a las herramientas de monitorización remota conectarse a las JVM. Este comando es experimental y no está soportado.

SINOPSIS

jstatd [ opciones ]
opciones
Las opciones de línea de comandos. Véase Opciones.

DESCRIPCIÓN

El comando jstatd es una aplicación de servidor RMI que monitoriza la creación y terminación de HotSpot VMs instrumentadas y proporciona una interfaz para que las herramientas de monitorización remota se conecten a las JVM que se están ejecutando en el host local.

El servidor jstatd requiere un registro RMI en el host local. El servidor jstatd intenta conectarse al registro RMI en el puerto predeterminado, o en el puerto que especifique con la opción -ppuerto. Si no se encuentra un registro RMI, se crea uno dentro de la aplicación jstatd que está enlazado al puerto indicado por la opción -ppuerto o al puerto de registro RMI predeterminado cuando se omite la opción -ppuerto. Puede detener la creación de un registro RMI interno especificando la opción -nr.

OPCIONES

-nr

No intenta crear un registro RMI interno dentro del proceso jstatd cuando no se encuentra un registro RMI existente.
-p puerto

El número de puerto donde se espera encontrar el registro RMI, o cuando no se encuentra, se crea si la opción -nr no se especifica.
-n nombrermiregistro

Nombre al que se enlaza el objeto RMI remoto en el registro RMI. El nombre predeterminado es JStatRemoteHost. Si se inician varios servidores jstatd en el mismo host, el nombre del objeto RMI exportado para cada servidor puede hacerse único especificando esta opción. Sin embargo, hacerlo requiere que el nombre de servidor único se incluya en las cadenas hostid y vmid del cliente de monitorización.
-Jopción

Pasa opción a la JVM, donde opción es una de las opciones descritas en la página de referencia del lanzador de aplicaciones Java. Por ejemplo, -J-Xms48m establece la memoria de inicio en 48 MB. Véase java(1).

SEGURIDAD

El servidor jstatd solo puede monitorizar JVM para las que tiene los permisos de acceso nativos apropiados. Por lo tanto, el proceso jstatd debe ejecutarse con las mismas credenciales de usuario que las JVM de destino. Algunas credenciales de usuario, como el usuario root en sistemas basados en UNIX, tienen permiso para acceder a la instrumentación exportada por cualquier JVM en el sistema. Un proceso jstatd que se ejecuta con dichas credenciales puede monitorizar cualquier JVM en el sistema, pero introduce preocupaciones de seguridad adicionales.

El servidor jstatd no proporciona ninguna autenticación de clientes remotos. Por lo tanto, ejecutar un proceso servidor jstatd expone la instrumentación exportada por todas las JVM a las que el proceso jstatd tiene permisos de acceso a cualquier usuario en la red. Esta exposición podría ser indeseable en su entorno y, por lo tanto, se deben considerar las políticas de seguridad locales antes de iniciar el proceso jstatd, particularmente en entornos de producción o en redes que no son seguras.

El servidor jstatd instala una instancia de RMISecurityPolicy cuando no hay ningún otro gestor de seguridad instalado y, por lo tanto, requiere que se especifique un archivo de política de seguridad. El archivo de política debe ajustarse a la Implementación Predeterminada de Políticas y a la Sintaxis de Archivos de Política en http://docs.oracle.com/javase/8/docs/technotes/guides/security/PolicyFiles.html

El siguiente archivo de política permite que el servidor jstatd se ejecute sin ninguna excepción de seguridad. Esta política es menos liberal que conceder todos los permisos a todas las bases de código, pero es más liberal que una política que concede los permisos mínimos para ejecutar el servidor jstatd.

grant codebase "file:${java.home}/../lib/tools.jar" {   
    permission java.security.AllPermission;
};

Para usar esta configuración de política, copie el texto en un archivo llamado jstatd.all.policy y ejecute el servidor jstatd de la siguiente manera:

jstatd -J-Djava.security.policy=jstatd.all.policy

Para sitios con prácticas de seguridad más restrictivas, es posible utilizar un archivo de política personalizado para limitar el acceso a hosts o redes específicas de confianza, aunque tales técnicas están sujetas a ataques de suplantación de identidad (spoofing) de direcciones IP. Si sus preocupaciones de seguridad no pueden abordarse con un archivo de política personalizado, entonces la acción más segura es no ejecutar el servidor jstatd y utilizar las herramientas jstat y jps de forma local.

INTERFAZ&#x00A0;REMOTA

La interfaz exportada por el proceso jstatd es propietaria y está garantizado que cambiará. Se desaconseja a los usuarios y desarrolladores escribir en esta interfaz.

EJEMPLOS

Los siguientes son ejemplos del comando jstatd. Los scripts jstatd inician automáticamente el servidor en segundo plano.

REGISTRO&#x00A0;RMI&#x00A0;INTERNO

Este ejemplo muestra cómo iniciar una sesión jstatd con un registro RMI interno. Este ejemplo asume que ningún otro servidor está enlazado al puerto de registro RMI predeterminado (puerto 1099).

jstatd -J-Djava.security.policy=all.policy

REGISTRO&#x00A0;RMI&#x00A0;EXTERNO

Este ejemplo inicia una sesión jstatd con un registro RMI externo.

rmiregistry&
jstatd -J-Djava.security.policy=all.policy

Este ejemplo inicia una sesión jstatd con un servidor de registro RMI externo en el puerto 2020.

rmiregistry 2020&
jstatd -J-Djava.security.policy=all.policy -p 2020

Este ejemplo inicia una sesión jstatd con un registro RMI externo en el puerto 2020 que está enlazado a AlternateJstatdServerName.

rmiregistry 2020&
jstatd -J-Djava.security.policy=all.policy -p 2020
    -n AlternateJstatdServerName

DETENER&#x00A0;LA&#x00A0;CREACIÓN&#x00A0;DE&#x00A0;UN&#x00A0;REGISTRO&#x00A0;RMI&#x00A0;EN&#x00A0;PROCESO

Este ejemplo inicia una sesión jstatd que no crea un registro RMI cuando no se encuentra uno. Este ejemplo asume que ya se está ejecutando un registro RMI. Si no se está ejecutando un registro RMI, se mostrará un mensaje de error.

jstatd -J-Djava.security.policy=all.policy -nr

HABILITAR&#x00A0;REGISTRO&#x00A0;RMI

Este ejemplo inicia una sesión jstatd con capacidades de registro RMI habilitadas. Esta técnica es útil como ayuda para la resolución de problemas o para monitorizar las actividades del servidor.

jstatd -J-Djava.security.policy=all.policy
    -J-Djava.rmi.server.logCalls=true
