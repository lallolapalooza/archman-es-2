jstat(1) Herramientas de Monitorización jstat(1)

NOMBRE

jstat - Monitoriza estadísticas de la Máquina Virtual Java (JVM). Este comando es experimental y no está soportado.

SINOPSIS

jstat [ opciónGeneral | opcionesSalida vmid [ intervalo[s|ms] [ contador ] ]

opciónGeneral

Una única opción de línea de comandos general -help o -options. Ver Opciones Generales.

opcionesSalida

Una o más opciones de salida que consisten en una única statOption, más cualquiera de las opciones -t, -h, y -J. Ver Opciones de Salida.

vmid

Identificador de la máquina virtual, que es una cadena que indica la JVM de destino. La sintaxis general es la siguiente: 
[protocolo:][//]lvmid[@hostname[:puerto]/nombreServidor]
La sintaxis de la cadena vmid corresponde a la sintaxis de una URI. La cadena vmid puede variar desde un simple entero que representa una JVM local hasta una construcción más compleja que especifica un protocolo de comunicaciones, un número de puerto y otros valores específicos de la implementación. Ver Identificador de Máquina Virtual.

intervalo [s|ms]

Intervalo de muestreo en las unidades especificadas, segundos (s) o milisegundos (ms). Las unidades por defecto son milisegundos. Debe ser un entero positivo. Cuando se especifica, el comando jstat produce su salida en cada intervalo.

contador

Número de muestras a mostrar. El valor por defecto es infinito, lo que provoca que el comando jstat muestre estadísticas hasta que la JVM de destino termine o el comando jstat sea terminado. Este valor debe ser un entero positivo.

DESCRIPCIÓN

El comando jstat muestra estadísticas de rendimiento para una VM HotSpot Java instrumentada. La JVM de destino se identifica por su identificador de máquina virtual, o la opción vmid.

IDENTIFICADOR DE MÁQUINA VIRTUAL

La sintaxis de la cadena vmid corresponde a la sintaxis de una URI:

[protocolo:][//]lvmid[@hostname[:puerto]/nombreServidor]

protocolo

El protocolo de comunicaciones. Si se omite el valor protocolo y no se especifica un nombre de host, el protocolo por defecto es un protocolo local optimizado específico de la plataforma. Si se omite el valor protocolo y se especifica un nombre de host, el protocolo por defecto es rmi.

lvmid

El identificador local de la máquina virtual para la JVM de destino. El lvmid es un valor específico de la plataforma que identifica de forma única una JVM en un sistema. El lvmid es el único componente requerido de un identificador de máquina virtual. El lvmid es típicamente, pero no necesariamente, el identificador de proceso del sistema operativo para el proceso de la JVM de destino. Puedes usar el comando jps para determinar el lvmid. Además, puedes determinar el lvmid en plataformas Solaris, Linux y OS X con el comando ps, y en Windows con el Administrador de Tareas de Windows.

hostname

Un nombre de host o dirección IP que indica el host de destino. Si se omite el valor hostname, el host de destino es el host local.

puerto

El puerto por defecto para comunicarse con el servidor remoto. Si se omite el valor hostname o el valor protocolo especifica un protocolo local optimizado, el valor puerto se ignora. De lo contrario, el tratamiento del parámetro puerto depende de la implementación. Para el protocolo rmi por defecto, el valor del puerto indica el número de puerto para el rmiregistry en el host remoto. Si se omite el valor puerto y el valor protocolo especifica rmi, se utiliza el puerto por defecto del rmiregistry (1099).

nombreServidor

El tratamiento del parámetro nombreServidor depende de la implementación. Para el protocolo local optimizado, este campo se ignora. Para el protocolo rmi, representa el nombre del objeto remoto RMI en el host remoto.

OPCIONES

El comando jstat soporta dos tipos de opciones, opciones generales y opciones de salida. Las opciones generales hacen que el comando jstat muestre información simple de uso y versión. Las opciones de salida determinan el contenido y formato de la salida estadística.

Todas las opciones y su funcionalidad están sujetas a cambios o eliminación en futuras versiones.

Opciones Generales

Si especificas una de las opciones generales, no podrás especificar ninguna otra opción o parámetro.

-help

Muestra un mensaje de ayuda.

-options

Muestra una lista de opciones estáticas. Ver Opciones de Salida.

Opciones de Salida

Si no especificas una opción general, puedes especificar opciones de salida. Las opciones de salida determinan el contenido y formato de la salida del comando jstat, y consisten en una única statOption, más cualquiera de las otras opciones de salida (-h, -t, y -J). La statOption debe ir primero.

La salida se formatea como una tabla, con columnas separadas por espacios. Una fila de encabezado con títulos describe las columnas. Usa la opción -h para establecer la frecuencia con la que se muestra el encabezado. Los nombres de las cabeceras de columna son consistentes entre las diferentes opciones. En general, si dos opciones proporcionan una columna con el mismo nombre, entonces la fuente de datos para las dos columnas es la misma.

Usa la opción -t para mostrar una columna de marca de tiempo, etiquetada como Timestamp, como la primera columna de la salida. La columna Timestamp contiene el tiempo transcurrido, en segundos, desde que la JVM de destino se inició. La resolución de la marca de tiempo depende de varios factores y está sujeta a variaciones debido a la programación de hilos retrasada en sistemas muy cargados.

Usa los parámetros de intervalo y contador para determinar con qué frecuencia y cuántas veces, respectivamente, el comando jstat muestra su salida.

Nota: No escribas scripts para analizar la salida del comando jstat porque el formato podría cambiar en futuras versiones. Si escribes scripts que analizan la salida del comando jstat, prepárate para modificarlos para futuras versiones de esta herramienta.

-statOption

Determina la información de estadísticas que muestra el comando jstat. La siguiente lista las opciones disponibles. Usa la opción general -options para mostrar la lista de opciones para una instalación de plataforma particular. Ver Opciones de Estadísticas y Salida.

class: Muestra estadísticas sobre el comportamiento del cargador de clases.

compiler: Muestra estadísticas sobre el comportamiento del compilador Just-in-Time de la VM HotSpot de Java.

gc: Muestra estadísticas sobre el comportamiento del montón recolectado por el recolector de basura.

gccapacity: Muestra estadísticas sobre las capacidades de las generaciones y sus espacios correspondientes.

gccause: Muestra un resumen sobre estadísticas de recolección de basura (igual que -gcutil), con la causa de los últimos y actuales eventos de recolección de basura (cuando sea aplicable).

gcnew: Muestra estadísticas del comportamiento de la generación nueva.

gcnewcapacity: Muestra estadísticas sobre los tamaños de las generaciones nuevas y sus espacios correspondientes.

gcold: Muestra estadísticas sobre el comportamiento de la generación antigua y estadísticas del metaspace.

gcoldcapacity: Muestra estadísticas sobre los tamaños de la generación antigua.

gcmetacapacity: Muestra estadísticas sobre los tamaños del metaspace.

gcutil: Muestra un resumen sobre estadísticas de recolección de basura.

printcompilation: Muestra estadísticas de métodos de compilación de la VM HotSpot de Java.

-h n

Muestra una cabecera de columna cada n muestras (filas de salida), donde n es un entero positivo. El valor por defecto es 0, que muestra la cabecera de columna en la primera fila de datos.

-t

Muestra una columna de marca de tiempo como la primera columna de la salida. La marca de tiempo es el tiempo transcurrido desde la hora de inicio de la JVM de destino.

-JopciónJava

Pasa opciónJava al lanzador de aplicaciones Java. Por ejemplo, -J-Xms48
m establece la memoria de inicio en 48 MB. Para obtener una lista completa de opciones, consulte java(1).

Esta sección presenta algunos ejemplos de monitoreo de una JVM local con un lvmid de 21891.

La opción gcutil

Este ejemplo se conecta a lvmid 21891, toma 7 muestras en intervalos de 250 milisegundos y muestra la salida especificada por la opción -gcutil.

La salida de este ejemplo muestra que ocurrió una recolección de la generación joven entre la tercera y cuarta muestra. La recolección tomó 0.078 segundos y promovió objetos del espacio Eden (E) al espacio antiguo (O), lo que resultó en un aumento de la utilización del espacio antiguo del 66.80% al 68.19%. Antes de la recolección, el espacio de supervivencia tenía una utilización del 97.02%, pero después de esta recolección tiene una utilización del 91.03%.

EXAMPLES

Using the -gcnew Option to Display New Generation Statistics

This example uses the -gcnew option to output the statistics for the new generation of the garbage collector. It also uses the -h3 option to output the column header after every 3 lines of data.

In addition to showing the repeating header string, this example shows that between the second and third samples, a young GC occurred. Its duration was 0.001 seconds. The collection found enough active data that the survivor space 0 utilization (S0U) would have exceeded the desired survivor Size (DSS). As a result, objects were promoted to the old generation (not visible in this output), and the tenuring threshold (TT) was lowered from 31 to 2.

Another collection occurs between the fifth and sixth samples. This collection found very few survivors and returned the tenuring threshold to 31.

Include a Time Stamp for Each Sample

This example attaches to lvmid 21891 and takes 3 samples at 250 millisecond intervals. The -t option is used to generate a time stamp for each sample in the first column.

The Timestamp column reports the elapsed time in seconds since the start of the target JVM. In addition, the -gcoldcapacity output shows the old generation capacity (OGC) and the old space capacity (OC) increasing as the heap expands to meet allocation or promotion demands. The old generation capacity (OGC) has grown from 11,696 kB to 13,820 kB after the eighty-first full garbage collection (FGC). The maximum capacity of the generation (and space) is 60,544 kB (OGCMX), so it still has room to expand.

Monitor Instrumentation for a Remote JVM

This example attaches to lvmid 40496 on the system named remote.domain using the -gcutil option, with samples taken every second indefinitely.

The lvmid is combined with the name of the remote host to construct a vmid of 40496@remote.domain. This vmid results in the use of the rmi protocol to communicate to the default jstatd server on the remote host. The jstatd server is located using the rmiregistry command on remote.domain that is bound to the default port of the rmiregistry command (port 1099).

jstat -gcutil 40496@remote.domain 1000
