NOMBRE

jj-config - Gestionar opciones de configuración

SINOPSIS

jj config [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <subcomandos>

DESCRIPCIÓN

Gestionar opciones de configuración

Opera sobre la configuración de jj, que proviene del archivo de configuración y de las variables de entorno.

Consulte [`jj help -k config`] para saber más sobre la ubicación de los archivos, las opciones de configuración soportadas y otros detalles sobre `jj config`.

[`jj help -k config`]: https://docs.jj-vcs.dev/latest/config/

OPCIONES

-h, --help
Imprimir ayuda (ver un resumen con '-h')

OPCIONES GENERALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio más cercano `.jj/` en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No guardar una instantánea de la copia de trabajo y no actualizarla

Por defecto, Jujutsu guarda una instantánea de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si desea evitar guardar una instantánea de la copia de trabajo y ver en su lugar un commit de la copia de trabajo posiblemente desactualizado, puede usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en un prompt de comando, especialmente si tiene otro proceso que confirma la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu impide reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y le permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta a la verificación. No afecta al revset `immutable_heads()` ni a la palabra clave de plantilla `immutable`.

--at-operation <OPERACIÓN_EN>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puede usar `--at-op=<ID de operación>` para ver cómo era el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` le mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor por defecto, excepto que las operaciones divergentes nunca se fusionarán.

Use `jj op log` para encontrar el ID de operación que desea. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignorará la copia de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilitar registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[posibles valores: always, never, debug, auto]

--quiet
Silenciar la salida no principal del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no le dirá si se guardó una instantánea de la copia de trabajo o si se reorganizaron los descendientes.

Las advertencias y los errores seguirán imprimiéndose.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (pueden repetirse)

El nombre debe especificarse como claves separadas por puntos en TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado por ninguna construcción TOML (como la notación de matriz), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (pueden repetirse)
