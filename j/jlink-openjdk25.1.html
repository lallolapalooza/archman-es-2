JLINK(1) Comandos JDK JLINK(1)

NOMBRE

jlink - ensambla y optimiza un conjunto de módulos y sus dependencias en una imagen de tiempo de ejecución personalizada

SINOPSIS

jlink [opciones] --module-path rutamodulos --add-modules modulo[,modulo...]

opciones
Opciones de línea de comandos separadas por espacios. Ver Opciones de jlink.
rutamodulos
La ruta donde la herramienta jlink descubre módulos observables. Estos módulos pueden ser archivos JAR modulares, archivos JMOD o módulos desempaquetados.
modulo
Los nombres de los módulos a añadir a la imagen de tiempo de ejecución. La herramienta jlink añade estos módulos y sus dependencias transitivas.

DESCRIPCIÓN

La herramienta jlink enlaza un conjunto de módulos, junto con sus dependencias transitivas, para crear una imagen de tiempo de ejecución personalizada.

Nota:

Los desarrolladores son responsables de actualizar sus imágenes de tiempo de ejecución personalizadas.

OPCIONES DE JLINK

--add-modules mod[,mod...]
Añade los módulos nombrados, mod, al conjunto predeterminado de módulos raíz. El conjunto predeterminado de módulos raíz está vacío.
--bind-services
Enlaza módulos de proveedores de servicios y sus dependencias.
-c ={0|1|2} o --compress={0|1|2}
Habilita la compresión de recursos:
•
0: Sin compresión
•
1: Compartición de cadenas constantes
•
2: ZIP
--disable-plugin nombreplugin
Inhabilita el plug-in especificado. Ver Plug-ins de jlink para la lista de plug-ins compatibles.
--endian {little|big}
Especifica el orden de bytes de la imagen generada. El valor predeterminado es el formato de la arquitectura de tu sistema.
-h o --help
Imprime el mensaje de ayuda.
--ignore-signing-information
Suprime un error fatal cuando se enlazan archivos JAR modulares firmados en la imagen de tiempo de ejecución. Los archivos relacionados con la firma de los archivos JAR modulares firmados no se copian a la imagen de tiempo de ejecución.
--launcher comando=modulo o --launcher comando=modulo/clase principal
Especifica el nombre del comando lanzador para el módulo o el nombre del comando para el módulo y la clase principal (los nombres del módulo y la clase principal están separados por una barra (/)).
--limit-modules mod[,mod...]
Limita el universo de módulos observables a aquellos en el cierre transitivo de los módulos nombrados, mod, más el módulo principal, si lo hay, más cualquier módulo adicional especificado en la opción --add-modules.
--list-plugins
Lista los plug-ins disponibles, a los que puedes acceder a través de opciones de línea de comandos; ver Plug-ins de jlink.
-p o --module-path rutamodulos
Especifica la ruta de los módulos.

Si esta opción no se especifica, la ruta de módulos predeterminada es $JAVA_HOME/jmods. Este directorio contiene el módulo java.base y los otros módulos estándar y del JDK. Si se especifica esta opción pero el módulo java.base no puede resolverse a partir de ella, el comando jlink añade $JAVA_HOME/jmods a la ruta de módulos.

--no-header-files
Excluye archivos de cabecera.
--no-man-pages
Excluye páginas de manual.
--output ruta
Especifica la ubicación de la imagen de tiempo de ejecución generada.
--save-opts nombrearchivo
Guarda las opciones de jlink en el archivo especificado.
--suggest-providers [nombre, ...]
Sugiere proveedores que implementan los tipos de servicio dados desde la ruta de módulos.
--version
Imprime información de la versión.
@nombrearchivo
Lee las opciones desde el archivo especificado.

Un archivo de opciones es un archivo de texto que contiene las opciones y los valores que normalmente introducirías en una línea de comandos. Las opciones pueden aparecer en una línea o en varias. No puedes especificar variables de entorno para nombres de ruta. Puedes comentar líneas anteponiendo un símbolo de almohadilla (#) al principio de la línea.

El siguiente es un ejemplo de un archivo de opciones para el comando jlink:

#Wed Dec 07 00:40:19 EST 2016
--module-path mlib
--add-modules com.greetings
--output greetingsapp

PLUGINS DE JLINK

Nota:

Los plug-ins no listados en esta sección no son compatibles y están sujetos a cambios.

Para las opciones de plug-in que requieren una lista de patrones, el valor es una lista separada por comas de elementos, y cada elemento utiliza una de las siguientes formas:

•
patrón glob
•
glob:patrón glob
•
regex:patrón regex
•
@nombrearchivo
•
nombrearchivo es el nombre de un archivo que contiene patrones a utilizar, un patrón por línea.

Para obtener una lista completa de todos los plug-ins disponibles, ejecuta el comando jlink --list-plugins.

Plug-in compress

Opciones
--compress={0|1|2}[:filter=lista de patrones]
Descripción
Comprime todos los recursos en la imagen de salida.
•
Nivel 0: Sin compresión
•
Nivel 1: Compartición de cadenas constantes
•
Nivel 2: ZIP

Se puede especificar un filtro de lista de patrones opcional para listar el patrón de archivos a incluir.

Plug-in include-locales

Opciones
--include-locales=etiqueta de idioma[,etiqueta de idioma]*
Descripción
Incluye la lista de locales donde etiqueta de idioma es una etiqueta de idioma BCP 47. Esta opción soporta la coincidencia de locales según se define en RFC 4647.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Asegúrate de agregar el módulo `jdk.localedata` cuando uses esta opción.

Ejemplo:

--add-modules jdk.localedata --include-locales=en,ja,*-IN

Plugin order-resources

Opciones
--order-resources=lista-de-patrones
Descripción
Ordena las rutas especificadas en orden de prioridad. Si se especifica @nombre-archivo, entonces cada línea en lista-de-patrones debe ser una coincidencia exacta para las rutas que se van a ordenar.

Ejemplo:

--order-resources=/module-info.class,@classlist,/java.base/java/lang/

Plugin strip-debug

Opciones
--strip-debug
Descripción
Elimina la información de depuración de la imagen de salida.

Plugin generate-cds-archive

Opciones
--generate-cds-archive
Descripción
Genera el archivo CDS si la imagen en tiempo de ejecución admite la característica CDS.

EJEMPLOS DE JLINK

El siguiente comando crea una imagen en tiempo de ejecución en el directorio greetingsapp. Este comando enlaza el módulo com.greetings, cuya definición de módulo se encuentra en el directorio mlib.

jlink --module-path mlib --add-modules com.greetings --output greetingsapp

El siguiente comando lista los módulos en la imagen en tiempo de ejecución greetingsapp:

greetingsapp/bin/java --list-modules
com.greetings
java.base@11
java.logging@11
org.astro@1.0

El siguiente comando crea una imagen en tiempo de ejecución en el directorio compressedrt que está despojada de símbolos de depuración, utiliza compresión para reducir el espacio e incluye información de localización en francés:

jlink --add-modules jdk.localedata --strip-debug --compress=2 --include-locales=fr --output compressedrt

El siguiente ejemplo compara el tamaño de la imagen en tiempo de ejecución compressedrt con fr_rt, que no está despojada de símbolos de depuración y no utiliza compresión:

jlink --add-modules jdk.localedata --include-locales=fr --output fr_rt
du -sh ./compressedrt ./fr_rt
23M     ./compressedrt
36M     ./fr_rt

El siguiente ejemplo lista los proveedores que implementan java.security.Provider:

jlink --suggest-providers java.security.Provider
Suggested providers:
  java.naming provides java.security.Provider used by java.base
  java.security.jgss provides java.security.Provider used by java.base
  java.security.sasl provides java.security.Provider used by java.base
  java.smartcardio provides java.security.Provider used by java.base
  java.xml.crypto provides java.security.Provider used by java.base
  jdk.crypto.cryptoki provides java.security.Provider used by java.base
  jdk.crypto.ec provides java.security.Provider used by java.base
  jdk.crypto.mscapi provides java.security.Provider used by java.base
  jdk.security.jgss provides java.security.Provider used by java.base

El siguiente ejemplo crea una imagen en tiempo de ejecución personalizada llamada mybuild que incluye solo java.naming y jdk.crypto.cryptoki y sus dependencias, pero ningún otro proveedor. Tenga en cuenta que estas dependencias deben existir en la ruta del módulo:

jlink --add-modules java.naming,jdk.crypto.cryptoki --output mybuild

El siguiente comando es similar al que crea una imagen en tiempo de ejecución llamada greetingsapp, excepto que enlazará los módulos resueltos desde módulos raíz con enlace de servicios; consulte el método Configuration.resolveAndBind.

jlink --module-path mlib --add-modules com.greetings --output greetingsapp --bind-services
