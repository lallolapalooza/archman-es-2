DESCRIPCIÓN

El jw script de shell permite convertir un archivo DocBook (u otro formato basado en SGML) a otros formatos (incluyendo HTML, RTF, PS y PDF) con una sintaxis fácil de entender. Oculta la mayor parte de la complejidad de Jade u OpenJade y añade características cómodas.

Otros scripts como docbook2html, docbook2rtf o docbook2ps proporcionan diferentes formas de llamar a jw que pueden ser más fáciles de recordar.

Por el momento, jw no maneja XML, sino solo SGML.

Esta utilidad asume que varios otros componentes están instalados. La lista incluye:

•
las entidades de caracteres ISO para SGML
•
el motor DSSSL de James Clark, jade, o un analizador equivalente como OpenJade
•
el DTD de DocBook del consorcio OASIS
•
las hojas de estilo modulares de DocBook de Norman Walsh (u otro conjunto de hojas de estilo DSSSL)
•
el conjunto de macros TeX jadetex de Sebastian Rahtz para jade (para backends destinados a formatos de "impresión" como PDF, RTF o PostScript)
•
Un intérprete de perl (para backends que usan perl)
•
SGMLSpm de CPAN (para backends que usan sgmls)
•
El navegador HTML Lynx (para el txt backend)

El script jw se llama básicamente así:

jw mydoc.sgml

donde mydoc.sgml es un archivo SGML.

La línea de comandos anterior usa opciones predeterminadas: convierte de DocBook (el frontend predeterminado) a HTML (el backend predeterminado), no coloca el resultado en un subdirectorio (a menos que se especifique lo contrario en las hojas de estilo), etc.

En este ejemplo, el nombre de archivo "mydoc" así como la extensión ".sgml" pueden ser reemplazados por cualquier otra cosa. Las extensiones actuales para archivos DocBook SGML incluyen ".sgml", ".sgm", ".docbook" y ".db". El archivo procesado mydoc.sgml puede estar en cualquier otro directorio que no sea el actual.

Aquí hemos elegido generar salida HTML. De hecho, podemos usar cualquiera de los backends almacenados en el backends/ subdirectorio del directorio de distribución de DocBook-utils (usualmente /usr/share/sgml/docbook/utils-0.6.14). De manera similar, puedes usar cualquier frontend definido en el frontends/ subdirectorio para convertir desde otro formato de entrada.

Este comando de ejemplo crea uno o varios archivos HTML con nombres de archivo arbitrarios en el directorio actual. Este comportamiento predeterminado se puede cambiar a través de opciones de línea de comandos y/o hojas de estilo de personalización.

OPCIONES

Las siguientes opciones se aplican al script de conversión:

-f frontend | --frontend frontend
Permite especificar otro frontend diferente al predeterminado docbook. La lista de frontends actualmente disponibles es:
docbook
Convierte docbook con las hojas de estilo de Norman Walsh. Este frontend busca en los subdirectorios del directorio base SGML un archivo llamado html/docbook.dsl o print/docbook.dsl (dependiendo del tipo de backend: html o print).
-b backend | --backend backend
Permite especificar otro backend diferente al predeterminado HTML. La lista de backends actualmente disponibles es:
dvi
Convierte a DVI (archivos DeVice Independant) llamando a Jade o OpenJade.
html
Convierte a HTML (HyperText Markup Language) llamando a Jade o OpenJade.
man
Convierte un refentry a una página de manual de Unix llamando a docbook2man. No funciona con otros tipos de documentos SGML que no sean DocBook.
pdf
Convierte a PDF (Portable Document Format) llamando a Jade o OpenJade.
ps
Convierte a PostScript llamando a Jade o OpenJade.
rtf
Convierte a RTF (Rich Text Format) llamando a Jade o OpenJade. El archivo resultante puede ser importado en MS Word o uno de sus programas de reemplazo en Linux.
tex
Convierte a TeX llamando a Jade o OpenJade.
texi
Convierte a páginas GNU TeXinfo llamando a docbook2texi. No funciona con otros tipos de documentos SGML que no sean DocBook.
txt
Convierte a un archivo de texto sin formato llamando a Jade o OpenJade, luego Lynx.
-c file | --cat file
Permite usar un SGML Open Catalogo extra que listará otros archivos como hojas de estilo de personalización, adaptaciones a la Definición de Tipo de Documento de DocBook, entidades de caracteres especiales, etc. Este catálogo se añade a la lista de catálogos determinada por el script (ver la opción --nostd más abajo)
-n | --nostd
No usar los SGML Open Catalogs estándar. Normalmente, la lista de catálogos estándar se determina así:
•
si el catálogo centralizado existe, úsalo. El catálogo centralizado es una lista de todos los catálogos que puedan ser necesarios que usualmente reside en /etc/sgml. Su nombre lo proporciona el frontend, por ejemplo el docbook frontend devuelve /etc/sgml/sgml-docbook.cat.
•
De lo contrario, toma todos los archivos llamados catalog de los subdirectorios del directorio base SGML (usualmente /usr/share/sgml).
Esta opción es útil en conjunto con la --cat opción para usar solo los catálogos que se especifican en la línea de comandos.
-d file|default|none | --dsl file|default|none
Permite usar una hoja de estilo personalizada en lugar de la predeterminada
