NOMBRE

jj-git - Comandos para trabajar con repositorios remotos Git y el repositorio Git subyacente

SINOPSIS

jj git [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <subcomandos>

DESCRIPCIÓN

Comandos para trabajar con repositorios remotos Git y el repositorio Git subyacente.

Consulta esta [comparación], incluyendo una [tabla de comandos].

[comparación]: https://docs.jj-vcs.dev/latest/git-comparison/.

[tabla de comandos]: https://docs.jj-vcs.dev/latest/git-command-table

OPCIONES

-h, --help
Imprime la ayuda (ver un resumen con '-h')

OPCIONES GENERALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar.

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No captura la copia de trabajo y no la actualiza.

Por defecto, Jujutsu captura la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si quieres evitar capturar la copia de trabajo y ver en su lugar un commit de copia de trabajo posiblemente obsoleto, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en un prompt de comando, especialmente si tienes otro proceso que confirma la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables.

Por defecto, Jujutsu evita reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa comprobación y te permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la comprobación. No afecta al revset `immutable_heads()` ni a la palabra clave `immutable` de la plantilla.

--at-operation <OPERACION_EN>
Operación en la que cargar el repositorio.

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puedes usar `--at-op=<ID de operación>` para ver cómo era el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` te mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente igual que el valor por defecto, excepto que las operaciones divergentes nunca se fusionarán.

Usa `jj op log` para encontrar el ID de operación que quieres. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignorará la copia de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacer eso, pero es posible.

--debug
Habilita el registro de depuración.
--color <CUANDO>
Cuándo colorear la salida.

[posibles valores: siempre, nunca, debug, auto]

--quiet
Silencia la salida no principal del comando.

Por ejemplo, `jj file list` seguirá listando archivos, pero no te dirá si la copia de trabajo fue capturada o si los descendientes fueron rebasados.

Las advertencias y errores seguirán imprimiéndose.

--no-pager
Deshabilita el paginador.
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir).

El nombre debe especificarse como claves punteadas TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está delimitado por ninguna construcción TOML (como notación de matriz), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir).

SUBCOMANDOS

jj-git-clone(1)
Crea un nuevo repositorio respaldado por un clon de un repositorio Git.
jj-git-colocation(1)
Gestiona la colocación del repositorio Jujutsu con Git.
jj-git-export(1)
Actualiza el repositorio Git subyacente con los cambios realizados en el repositorio.
jj-git-fetch(1)
Descarga desde un remoto Git.
jj-git-import(1)
Actualiza el repositorio con los cambios realizados en el repositorio Git subyacente.
jj-git-init(1)
Crea un nuevo repositorio con respaldo Git.
jj-git-push(1)
Envía a un remoto Git.
jj-git-remote(1)
Gestiona los remotos Git.
jj-git-root(1)
Muestra el directorio Git subyacente de un repositorio que utiliza el backend Git.
