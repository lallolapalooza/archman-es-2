DESCRIPCIÓ

N

El comando java inicia una aplicación Java. Lo hace iniciando el Entorno de Ejecución Java (JRE), cargando la clase especificada, y llamando al método main() de esa clase. El método debe ser declarado public y static, no debe devolver ningún valor, y debe aceptar un arreglo de String como parámetro. La declaración del método tiene la siguiente

forma: 
public static void
main(Stri
ng[] args)

El comando java puede usarse para lanzar una aplicación JavaFX cargando una clase que tenga un método main() o que extienda a javafx.application.Application. En el último caso, el lanzador construye una instancia de la clase Application, llama a su método init(), y luego llama al método start(javafx.stage.Stage)

.

Por defecto, el primer argumento que no es una opción del comando java es el nombre completamente calificado de la clase a ser invocada. Si se especifica la opción -jar, su argumento es el nombre del archivo JAR que contiene los archivos de clase y recursos de la aplicación. La clase de inicio debe ser indicada por la cabecera del manifiesto Main-Class en su código

fuente.

El JRE busca la clase de inicio (y otras clases usadas por la aplicación) en tres conjuntos de ubicaciones: la ruta de clases de arranque (bootstrap class path), las extensiones instaladas, y la ruta de clases del

usuario.

Los argumentos después del nombre del archivo de clase o del nombre del archivo JAR son pasados al método

-Xnoclassgc

Deshabilita la recolección de basura (GC) de clases. Esto puede ahorrar algo de tiempo de GC, lo que acorta las interrupciones durante la ejecución de la aplicación.

Cuando especifica -Xnoclassgc al inicio, los objetos de clase en la aplicación permanecerán intactos durante la GC y siempre se considerarán vivos. Esto puede resultar en que se ocupe más memoria de forma permanente, lo que, si no se usa con cuidado, provocará una excepción de falta de memoria.

-Xrs

Reduce el uso de señales del sistema operativo por parte de la JVM.

Los "shutdown hooks" (ganchos de apagado) permiten un apagado ordenado de una aplicación Java ejecutando código de limpieza del usuario (como cerrar conexiones de bases de datos) al apagar, incluso si la JVM termina abruptamente.

La JVM captura señales para implementar los ganchos de apagado en caso de terminación inesperada. La JVM utiliza SIGHUP, SIGINT y SIGTERM para iniciar la ejecución de los ganchos de apagado.

La JVM utiliza un mecanismo similar para implementar la función de volcado de pilas de hilos con fines de depuración. La JVM utiliza SIGQUIT para realizar volcados de hilos.

Las aplicaciones que incrustan la JVM a menudo necesitan interceptar señales como SIGINT o SIGTERM, lo que puede interferir con los manejadores de señales de la JVM. La opción -Xrs está disponible para abordar este problema. Cuando se utiliza -Xrs, las máscaras de señales para SIGINT, SIGTERM, SIGHUP y SIGQUIT no son modificadas por la JVM, y no se instalan manejadores de señales para estas señales.

•Los volcados de hilos SIGQUIT no están disponibles.

Opciones Avanzadas del Compilador JIT

Estas opciones controlan la compilación dinámica just-in-time (JIT) realizada por la Java HotSpot VM.

-XX:+AggressiveOpts

Habilita el uso de funciones de optimización de rendimiento agresivas, que se espera que se conviertan en predeterminadas en futuras versiones. Por defecto, esta opción está deshabilitada y no se utilizan funciones de rendimiento experimentales.

-XX:AllocateInstancePrefetchLines=líneas

Establece el número de líneas a prefijar antes del puntero de asignación de instancias. Por defecto, el número de líneas a prefijar se establece en 1: 
-XX:AllocateInstancePrefetchLines=1
Solo la Java HotSpot Server VM admite esta opción.

-XX:AllocatePrefetchDistance=tamaño

Establece el tamaño (en bytes) de la distancia de prefetch para la asignación de objetos. La memoria que se va a escribir con el valor de nuevos objetos se prefija hasta esta distancia a partir de la dirección del último objeto asignado. Cada hilo de Java tiene su propio punto de asignación.

Los valores negativos indican que la distancia de prefetch se elige según la plataforma. Los valores positivos son bytes a prefijar. Añada la letra k o K para indicar kilobytes, m o M para indicar megabytes, g o G para indicar gigabytes. El valor predeterminado se establece en -1.

El siguiente ejemplo muestra cómo establecer la distancia de prefetch en 1024 bytes:

-XX:AllocatePrefetchDistance=1024
Solo la Java HotSpot Server VM admite esta opción.

-XX:AllocatePrefetchInstr=instrucción

Establece la instrucción de prefetch para prefijar antes del puntero de asignación. Solo la Java HotSpot Server VM admite esta opción. Los valores posibles son de 0 a 3. Las instrucciones reales detrás de los valores dependen de la plataforma. Por defecto, la instrucción de prefetch se establece en 0: 
-XX:AllocatePrefetchInstr=0
Solo la Java HotSpot Server VM admite esta opción.

-XX:AllocatePrefetchLines=líneas

Establece el número de líneas de caché a cargar después de la última asignación de objetos utilizando las instrucciones de prefetch generadas en el código compilado. El valor predeterminado es 1 si el último objeto asignado fue una instancia, y 3 si fue un array.

El siguiente ejemplo muestra cómo establecer el número de líneas de caché cargadas en 5:

-XX:AllocatePrefetchLines=5
Solo la Java HotSpot Server VM admite esta opción.

-XX:AllocatePrefetchStepSize=tamaño

Establece el tamaño del paso (en bytes) para las instrucciones de prefetch secuenciales. Añada la letra k o K para indicar kilobytes, m o M para indicar megabytes, g o G para indicar gigabytes. Por defecto, el tamaño del paso se establece en 16 bytes: 
-XX:AllocatePrefetchStepSize=16
Solo la Java HotSpot Server VM admite esta opción.

-XX:AllocatePrefetchStyle=estilo

Establece el estilo de código generado para las instrucciones de prefetch. El argumento estilo es un entero de 0 a 3:

0

No genere instrucciones de prefetch.

1

Ejecute instrucciones de prefetch después de cada asignación. Este es el parámetro predeterminado.

2

Utilice el puntero de marca del bloque de asignación local del hilo (TLAB) para determinar cuándo se ejecutan las instrucciones de prefetch.

3

Utilice la instrucción BIS en SPARC para prefetch de asignación.

Solo la Java HotSpot Server VM admite esta opción.

-XX:+BackgroundCompilation

Habilita la compilación en segundo plano. Esta opción está habilitada por defecto. Para deshabilitar la compilación en segundo plano, especifique -XX:-BackgroundCompilation (esto es equivalente a especificar -Xbatch).

-XX:CICompilerCount=hilos

Establece el número de hilos del compilador a utilizar para la compilación. Por defecto, el número de hilos se establece en 2 para la JVM del servidor, en 1 para la JVM del cliente, y escala al número de núcleos si se utiliza compilación por niveles. El siguiente ejemplo muestra cómo establecer el número de hilos en 2: 
-XX:CICompilerCount=2

-XX:CodeCacheMinimumFreeSpace=tamaño

Establece el espacio libre mínimo (en bytes) requerido para la compilación. Añada la letra k o K para indicar kilobytes, m o M para indicar megabytes, g o G para indicar gigabytes. Cuando queda menos del espacio libre mínimo, la compilación se detiene. Por defecto, esta opción se establece en 500 KB. El siguiente ejemplo muestra cómo establecer el espacio libre mínimo en 1024 MB: 
-XX:CodeCacheMinimumFreeSpace=1024m

-XX:CompileCommand=comando,método[,opción]

Especifica un comando a realizar sobre un método. Por ejemplo, para excluir el método indexOf() de la clase String de la compilación, utilice lo siguiente: 
-XX:CompileCommand=exclude,java/lang/String.indexOf
Tenga en cuenta que se especifica el nombre completo de la clase, incluyendo todos los paquetes y subpaquetes separados por una barra (/). Para facilitar las operaciones de copiar y pegar, también es posible utilizar el formato del nombre del método producido por las opciones -XX:+PrintCompilation y -XX:+LogCompilation: 
-XX:CompileCommand=exclude,java.lang.String::indexOf
Si el método se especifica sin la firma, el comando se aplicará a todos los métodos con el nombre especificado. Sin embargo, también puede especificar la firma del método en el formato de archivo de clase. En este caso, debe encerrar los argumentos entre comillas, ya que de lo contrario el shell trata el punto y coma como el fin del comando. Por ejemplo, si desea excluir solo el método indexOf(String) de la clase String de la compilación, utilice lo siguiente: 
-XX:CompileCommand="exclude,java/lang/String.indexOf,(Ljava/lang/String;)I"
También puede utilizar el asterisco (*) como comodín para nombres de clases y métodos. Por ejemplo, para excluir todos los métodos indexOf() en todas las clases de la compilación, utilice lo siguiente: 
-XX:CompileCommand=exclude,*.indexOf
Las comas y los puntos son alias de espacios, lo que facilita el paso de comandos del compilador a través de un shell. Puede pasar argumentos a -XX:CompileCommand utilizando espacios como separadores encerrando el argumento entre comillas: 
-XX:CompileCommand="exclude java/lang/String indexOf"
Tenga en cuenta que después de analizar los comandos pasados en la línea de comandos utilizando las opciones -XX:CompileCommand, el compilador JIT lee los comandos del archivo .hotspot_compiler. Puede añadir comandos a este archivo o especificar un archivo diferente utilizando la opción -XX:CompileCommandFile.

Para añadir varios comandos, especifique la opción -XX:CompileCommand varias veces o separe cada argumento con el separador de nueva línea (\n). Los siguientes comandos están disponibles:

break

Establece un punto de interrupción al depurar la JVM para detenerse al principio de la compilación del método especificado.

compileonly

Excluye todos los métodos de la compilación excepto el método especificado. Como alternativa, puede utilizar la opción -XX:CompileOnly, que permite especificar varios métodos.

dontinline

Impide la inserción (inlining) del método especificado.

exclude

Excluye el método especificado de la compilación.

help

Imprime un mensaje de ayuda para la opción -XX:CompileCommand.

inline

Intenta insertar (inline) el método especificado.

log

Excluye el registro de compilación (con la opción -XX:+LogCompilation) para todos los métodos excepto el método especificado. Por defecto, se realiza el registro de todos los métodos compilados.

option

Este comando se puede utilizar para pasar una opción de compilación JIT al método especificado en lugar del último argumento (opción). La opción de compilación se establece al final, después del nombre del método. Por ejemplo, para habilitar la opción BlockLayoutByFrequency para el método append() de la clase StringBuffer, utilice lo siguiente: 
-XX:CompileCommand=option,java/lang/StringBuffer.append,BlockLayoutByFrequency
Puede especificar varias opciones de compilación, separadas por comas o espacios.

print

Imprime el código ensamblador generado después de la compilación del método especificado.

quiet

No imprima los comandos de compilación. Por defecto, se imprimen los comandos que especifique con la opción -XX:CompileCommand; por ejemplo, si excluye de la compilación el método indexOf() de la clase String, se imprimirá lo siguiente en la salida estándar: 
CompilerOracle: exclude java/lang/String.indexOf
Puede suprimir esto especificando la opción -XX:CompileCommand=quiet antes de otras opciones -XX:CompileCommand.

-XX:CompileCommandFile=nombre_archivo

Establece el archivo desde el que se leen los comandos del compilador JIT. Por defecto, el archivo .hotspot_compiler se utiliza para almacenar los comandos realizados por el compilador JIT.

Cada línea en el archivo de comandos representa un comando, un nombre de clase y un nombre de método para los cuales se utiliza el comando. Por ejemplo, esta línea imprime el código ensamblador para el método toString() de la clase String:

print java/lang/String toString
Para obtener más información sobre cómo especificar los comandos para que el compilador JIT los realice en los métodos, consulte la opción -XX:CompileCommand.

-XX:CompileOnly=métodos

Establece la lista de métodos (separados por comas) a los que se debe restringir la compilación. Solo se compilarán los métodos especificados. Especifique cada método con el nombre completo de la clase (incluyendo los paquetes y subpaquetes). Por ejemplo, para compilar solo el método length()
método de la clase String y el método size() de la clase List, utilice lo siguiente:

PÁGINAS

GRANDES

También conocidas como páginas enormes, las páginas grandes son páginas de memoria que son significativamente más grandes que el tamaño de página de memoria estándar (que varía según el procesador y el sistema operativo). Las páginas grandes optimizan los búfers de traducción de direcciones (TLB) del

procesador.

Un búfer de traducción de direcciones (TLB) es una caché de traducción de páginas que contiene las traducciones de direcciones virtuales a físicas usadas más recientemente. El TLB es un recurso escaso del sistema. Un fallo en el TLB puede ser costoso, ya que el procesador debe entonces leer de la tabla de páginas jerárquica, lo que puede requerir múltiples accesos a memoria. Al usar un tamaño de página de memoria más grande, una sola entrada del TLB puede representar un rango de memoria más grande. Habrá menos presión en el TLB, y las aplicaciones intensivas en memoria pueden tener un mejor

rendimiento.

Sin embargo, el uso de páginas grandes puede afectar negativamente el rendimiento del sistema. Por ejemplo, cuando una gran cantidad de memoria es fijada por una aplicación, puede crear una escasez de memoria regular y causar un paginado excesivo en otras aplicaciones y ralentizar todo el sistema. Además, un sistema que ha estado encendido durante mucho tiempo podría producir una fragmentación excesiva, lo que podría hacer imposible reservar suficiente memoria de páginas grandes. Cuando esto sucede, ya sea el SO o la JVM regresan al uso de páginas

regulares.
