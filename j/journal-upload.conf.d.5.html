DESCRIPCIÓ

N

Estos archivos configuran varios parámetros de systemd-journal-upload.service(8). Consulte systemd.syntax(7) para una de

scripción general
de la sintaxis.

DIRECTORIOS DE CONFIGURACIÓN Y

PRECEDENCIA

La configuración predeterminada se establece durante la compilación, por lo que solo es necesario configurar cuando es necesario desviarse de esos valores predeterminados. El archivo de configuración principal se carga desde uno de los directorios enumerados en orden de prioridad, solo se usa el primer archivo encontrado: /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La versión del proveedor del archivo contiene entradas comentadas que muestran los valores predeterminados como guía para el administrador. Las anulaciones locales también se pueden crear mediante drop-ins, como se describe a continuación. El archivo de configuración principal también se puede editar para este propósito (o una copia en /etc/ si se distribuye en /usr/), sin embargo, se recomienda usar drop-ins para la configuración local en lugar de modificar el archivo de configuración

principal.

Además del archivo de configuración principal, se leen fragmentos de configuración drop-in de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/ y /etc/systemd/*.conf.d/. Esos drop-ins tienen mayor precedencia y anulan el archivo de configuración principal. Los archivos en los subdirectorios de configuración *.conf.d/ se ordenan por su nombre de archivo en orden lexicográfico, independientemente de en cuál de los subdirectorios se encuentren. Cuando varios archivos especifican la misma opción, para opciones que aceptan un solo valor, la entrada en el archivo ordenado al final toma precedencia, y para opciones que aceptan una lista de valores, las entradas se recopilan a medida que aparecen en los archivos

ordenados.

Cuando los paquetes necesitan personalizar la configuración, pueden instalar drop-ins en /usr/. Los archivos en /etc/ están reservados para el administrador local, quien puede usar esta lógica para anular los archivos de configuración instalados por los paquetes del proveedor. Se deben usar drop-ins para anular los drop-ins de paquetes, ya que el archivo de configuración principal tiene menor precedencia. Se recomienda prefijar todos los nombres de archivo en esos subdirectorios con un número de dos dígitos y un guion, para simplificar el ordenamiento. Esto también define un concepto de prioridades de drop-in para permitir a los proveedores del SO distribuir drop-ins dentro de un rango específico inferior al rango utilizado por los usuarios. Esto debería reducir el riesgo de que los drop-ins de paquetes anulen accidentalmente los drop-ins definidos por los usuarios. Se recomienda usar el rango 10-40 para drop-ins en /usr/ y el rango 60-90 para drop-ins en /etc/ y /run/, para asegurar que los drop-ins locales y transitorios tengan prioridad sobre los drop-ins distribuidos por el proveedor del

SO.

Para deshabilitar un archivo de configuración suministrado por el proveedor, la forma r

ecomendada es colocar un enlace simbólico a /dev/null en el directorio de configuració
n en /etc/, con el mismo nombre de archivo que el archivo de configuración del proveedor.

S

URL

=
La URL a la que subir las entradas del diario. Consulte la descripción de la opción --url= en systemd-journal-upload(8) para la descripción de los valores posibles. No hay un valor predeterminado, por lo que esta opción o la opción de línea de comandos debe estar siempre presente para realizar una subida.

NetworkTimeoutSec

=
Cuando se pierde la conectividad de red con el servidor, esta opción configura el tiempo de espera para que se restablezca la conectividad. Si el servidor no es accesible por la red durante el tiempo configurado, systemd-journal-upload sale. Acepta un valor en segundos (o en otras unidades de tiempo si se le añade el sufijo "ms", "min", "h", etc). Para más detalles, consulte systemd.time(7).

n la ver

Compression

=
Configura el algoritmo de compresión a aplicar a los datos de los registros antes de enviarlos. Acepta una lista de algoritmos de compresión separados por espacios, o "no". Los algoritmos soportados son "zstd", "xz" o "lz4". Opcionalmente, cada algoritmo seguido de dos puntos (":") y su nivel de compresión, por ejemplo "zstd:4". El nivel de compresión debe ser un entero positivo. Cuando se especifica "no", no se aplicará ningún algoritmo de compresión a los datos a enviar. Esta opción se puede especificar varias veces. Si se asigna una cadena vacía, entonces se limpian todas las asignaciones anteriores. Por defecto no está definida, y se listan todos los algoritmos de compresión soportados con sus niveles de compresión predeterminados.

Ejemplo

: 
Compress
ion=zstd
:4 lz4:2

Incluso cuando la compresión está habilitada, las solicitudes iniciales se envían sin compresión. Se vuelve efectiva si "ForceCompression=" está habilitada, o si la respuesta del servidor contiene cabeceras "Accept-Encoding" con una lista de algoritmos de compresión que contiene uno de los algoritmos especificados en esta

opción.

ForceCompression

=
Acepta un valor booleano, fuerza el uso de compresión sin negociación de codificación de contenido. Por defecto es "false".

Header

=
Especifica una cabecera HTTP adicional a añadir a cada solicitud a una URL. Acepta un par de nombre de cabecera y valor separados por dos puntos(":"), p. ej. "Nombre:Valor". El nombre de la cabecera puede contener valores alfanuméricos, y los símbolos "_" y "-" adicionalmente. Esta opción se puede especificar más de una vez, en cuyo caso se establecerán todas las cabeceras listadas. Si el mismo nombre de cabecera se lista más de una vez, todas sus valores únicos se concatenarán con comas. Establecer Header= a cadena vacía limpia todas las asignaciones anteriores.

Ejemplo

: 
Header=HeaderName: HeaderValue
Header=HeaderName: NewValue
Header=HeaderName: HeaderValue

añade la cabecera "HeaderName" con "HeaderValue, NewValue" a cada solicitud

HTTP.
