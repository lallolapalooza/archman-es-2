NOMBRE

jj-git-remote-list - Listar remotos de Git

SINOPSIS

jj git remote list [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help]

DESCRIPCIÓN

Listar remotos de Git

OPCIONES

-h, --help
Imprimir ayuda (ver un resumen con '-h')

OPCIONES GLOBALES

-R, --repository <REPOSITORY>
Ruta al repositorio en el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No hacer snapshot de la copia de trabajo y no actualizarla

Por defecto, Jujutsu hace un snapshot de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si desea evitar hacer snapshot de la copia de trabajo y ver en su lugar un commit de copia de trabajo posiblemente desactualizado, puede usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tiene otro proceso que hace commit de la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu evita reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y le permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puede usar `--at-op=<ID de operación>` para ver cómo era el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` le mostrará lo que `jj st` habría mostrado cuando la operación dada hubiera finalizado. `--at-op=@` es prácticamente lo mismo que el valor predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Use `jj op log` para encontrar el ID de operación que desea. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignorará la copia de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilitar registro de depuración
--color <WHEN>
Cuándo colorear la salida

[valores posibles: always, never, debug, auto]

--quiet
Silenciar la salida de comandos no primarios

Por ejemplo, `jj file list` seguirá listando archivos, pero no le dirá si se hizo un snapshot de la copia de trabajo o si los descendientes se rebasaron.

Las advertencias y errores seguirán imprimiéndose.

--no-pager
Deshabilitar el paginador
--config <NAME=VALUE>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves puntuales de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado en ninguna construcción TOML (como la notación de matriz), las comillas se pueden omitir.

--config-file <PATH>
Archivos de configuración adicionales (se pueden repetir)
lista
