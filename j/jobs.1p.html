JOBS(1P) Manual de Programador POSIX JOBS(1P)

PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

jobs — muestra el estado de los trabajos en la sesión actual

SINOPSIS

jobs [-l|-p] [id_trabajo...]

DESCRIPCIÓN

La utilidad jobs mostrará el estado de los trabajos que se iniciaron en el entorno del shell actual; consulte la Sección 2.12, Entorno de Ejecución del Shell.

Cuando jobs informe el estado de terminación de un trabajo, el shell eliminará su ID de proceso de la lista de aquellos ``conocidos en el entorno de ejecución del shell actual''; consulte la Sección 2.9.3.1, Ejemplos.

OPCIONES

La utilidad jobs se conformará con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Pautas de Sintaxis de Utilidades.

Se soportarán las siguientes opciones:

-l
(La letra ele). Proporciona más información sobre cada trabajo listado. Esta información incluirá el número del trabajo, el trabajo actual, el ID del grupo de procesos, el estado y el comando que formó el trabajo.
-p
Muestra solo los IDs de proceso de los líderes de grupo de procesos de los trabajos seleccionados.

Por defecto, la utilidad jobs mostrará el estado de todos los trabajos detenidos, los trabajos en segundo plano en ejecución y todos los trabajos cuyo estado ha cambiado y no han sido informados por el shell.

OPERANDOS

Se soportará el siguiente operando:

id_trabajo
Especifica los trabajos para los cuales se va a mostrar el estado. Si no se proporciona ningún id_trabajo, se mostrará la información de estado de todos los trabajos. El formato de id_trabajo se describe en el volumen de Definiciones Base de POSIX.1‐2017, Sección 3.204, ID de Trabajo de Control de Trabajos.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de jobs:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en los argumentos).
LC_MESSAGES

Determina la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida estándar de error y los mensajes informativos escritos en la salida estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

SALIDA ESTÁNDAR

Si se especifica la opción -p, la salida consistirá en una línea por cada ID de proceso:

"%d\n", <ID de proceso>

De lo contrario, si no se especifica la opción -l, la salida será una serie de líneas con el formato:

"[%d] %c %s %s\n", <número de trabajo>, <actual>, <estado>, <comando>

donde los campos serán los siguientes:

<actual>
El carácter '+' identifica el trabajo que se utilizaría como predeterminado para las utilidades fg o bg; este trabajo también puede especificarse usando el id_trabajo %+ o "%%". El carácter '-' identifica el trabajo que se convertiría en el predeterminado si el trabajo predeterminado actual saliera; este trabajo también puede especificarse usando el id_trabajo %-. Para otros trabajos, este campo es un <espacio>. Como máximo, un trabajo puede identificarse con '+' y como máximo un trabajo puede identificarse con '-'. Si hay algún trabajo suspendido, entonces el trabajo actual será un trabajo suspendido. Si hay al menos dos trabajos suspendidos, entonces el trabajo anterior también será un trabajo suspendido.
<número de trabajo>
Un número que se puede usar para identificar el grupo de procesos con las utilidades wait, fg, bg y kill. Usando estas utilidades, el trabajo se puede identificar anteponiendo el número del trabajo con '%'.
<estado>
Una de las siguientes cadenas (en la localización POSIX):
Running
Indica que el trabajo no ha sido suspendido por una señal y no ha salido.
Done
Indica que el trabajo se completó y devolvió un estado de salida cero.
Done(código)
Indica que el trabajo se completó normalmente y que salió con el estado de salida no cero especificado, código, expresado como un número decimal.
Stopped
Indica que el trabajo fue suspendido por la señal SIGTSTP.
Stopped (SIGTSTP)

Indica que el trabajo fue suspendido por la señal SIGTSTP.
Stopped (SIGSTOP)

Indica que el trabajo fue suspendido por la señal SIGSTOP.
Stopped (SIGTTIN)

Indica que el trabajo fue suspendido por la señal SIGTTIN.
Stopped (SIGTTOU)

Indica que el trabajo fue suspendido por la señal SIGTTOU.

La implementación puede sustituir la cadena Suspended en lugar de Stopped. Si el trabajo fue terminado por una señal, el formato de <estado> no está especificado, pero será visiblemente distinto de todos los demás formatos de <estado> que se muestran aquí e indicará el nombre o la descripción de la señal que causó la terminación.

<comando>
El comando asociado que se le dio al shell.

Si se especifica la opción -l, se insertará un campo que contiene el ID del grupo de procesos antes del campo <estado>. Además, se pueden mostrar más procesos de un grupo de procesos en líneas separadas, utilizando solo los campos de ID de proceso y <comando>.

RAZONAMIENTO

La utilidad jobs se utiliza para mostrar el estado de los trabajos que el usuario ha puesto en segundo plano. El sistema de control de trabajos del shell es responsable de realizar un seguimiento de los trabajos que se ejecutan en segundo plano. La definición de trabajo gestionado por el shell en la Sección 2.12, Entorno de Ejecución del Shell, es la base de esta utilidad.

La capacidad de especificar un ID de trabajo para consultar el estado de un trabajo específico es una característica importante. La definición del formato del ID de trabajo en la Sección 3.204, ID de Trabajo de Control de Trabajos, proporciona un mecanismo estándar para hacer esto.

Los símbolos '+' y '-' para los trabajos actual y anterior, respectivamente, son una forma estándar de identificar los trabajos de forma relativa al contexto del shell. Se proporciona un mecanismo para que el usuario pueda interactuar con los trabajos de forma sencilla.

El estándar POSIX requiere que se definan los estados de los trabajos. Los estados definidos son Running, Done, y las diversas variaciones de Stopped. La norma también permite que los estados que implican una salida de señal tengan un formato no especificado, pero distintivo.

La inclusión de los IDs de grupo de procesos cuando se utiliza la opción -l es importante para la administración de trabajos y para que el usuario pueda utilizar la utilidad kill de forma eficaz. La capacidad de listar procesos individuales dentro de un grupo de procesos también proporciona información adicional útil.

Se espera que las implementaciones de shell soporten esta utilidad de acuerdo con las especificaciones.

USO DE LA

APLICACIÓN

La opción -p es la única forma portátil de averiguar el grupo de procesos de un trabajo, ya que las diferentes implementaciones tienen diferentes estrategias para definir el grupo de procesos del trabajo. Un uso como $(jobs -p) proporciona una forma de referirse al grupo de procesos del trabajo de una manera independiente de la

implementación.

La utilidad jobs no funciona como se espera cuando se está ejecutando en su propio entorno de ejecución de utilidades, ya que ese entorno no tiene trabajos aplicables que manipular. Véase la sección USO DE LA APLICACIÓN de bg. Por esta razón, jobs generalmente se implementa como un

comando intern
o regular del shell.

JUSTIFICACIÓ

N

Tanto "%%" como "%+" se utilizan para referirse al trabajo actual. Ambas formas son igualmente válidas: la forma "%%" refleja "$$" y la forma "%+" refleja la salida de jobs. Ambas formas reflejan la práctica histórica del KornShell y el C shell con control de

trabajos.

Las características de control de trabajos proporcionadas por bg, fg y jobs se basan en el KornShell. Los desarrolladores de estándares examinaron las características de las versiones del C shell de estas utilidades y encontraron que existen diferencias. A pesar del uso generalizado del C shell, se seleccionaron las versiones del KornShell para este volumen de POSIX.1‐2017 para mantener un grado de uniformidad con el resto de las características del KornShell seleccionadas (como las muy populares características de edición de línea de comandos)

.

La utilidad jobs no depende de la opción de control de trabajos, como lo hacen las utilidades aparentemente relacionadas bg y fg, porque jobs es útil para examinar trabajos en segundo plano, independientemente de la condición del control de trabajos. Cuando el usuario ha invocado un comando set +m y el control de trabajos ha sido desactivado, jobs todavía puede usarse para examinar los trabajos en segundo plano asociados con esa sesión actual. De manera similar, kill puede usarse entonces para terminar trabajos en segundo plano con kill %<número de trabajo en segundo plano>

.

La salida para trabajos terminados se deja sin especificar para acomodar varios sistemas históricos. Se han observado los siguientes

formatos:
