DESCRIPCIÓ

N

jackd es el demonio del servidor de audio JACK que permite a los programas cliente de JACK procesar y enrutar datos de audio y MIDI de manera sincrónica, con precisión de muestra y baja latencia. Escrito originalmente para el sistema operativo GNU/Linux, también se ejecuta en varias plataformas Unix, Mac OS X y MS Windows. JACK puede conectar una serie de diferentes aplicaciones cliente a un dispositivo de audio y también entre sí. La mayoría de los clientes son externos, ejecutándose en sus propios procesos como aplicaciones normales. JACK también admite clientes internos, que se ejecutan dentro del proceso jackd utilizando una interfaz de "plugin"

cargable.

JACK difiere de otros servidores de audio en que está diseñado desde cero para el trabajo de audio profesional. Se centra en dos áreas clave: la ejecución sincrónica de todos los clientes y la operación de baja

latencia.

El nombre JACK hace referencia a la forma clásica de conectar conexiones de audio con cables de jack de audio físicos. JACK es también un acrónimo recursivo, es decir, una abreviatura que es parte de sí misma. JACK Audio Connection Kit

.

Para la información más reciente de JACK, consulte el sitio web: http://www.ja

ckaudio
.org/.

-H,

Habilitar monitoreo por hardware de los puertos de captura. Este es un método para obtener monitoreo de la entrada de audio con "cero latencia". Requiere soporte en el hardware y del controlador de dispositivo ALSA subyacente.

Cuando está habilitado, las solicitudes de monitoreo de puertos de captura se satisfarán creando una ruta de señal directa entre los conectores de entrada y salida de la interfaz de audio, sin ningún procesamiento por parte del ordenador anfitrión. Esto ofrece la menor latencia posible para la señal

monitoreada.

Actualmente (marzo de 2003), solo la serie RME Hammerfall y las tarjetas basadas en el chipset ICE1712 (serie M-Audio Delta, Terratec y otras) admiten --hwmon. En el futuro, algunas tarjetas de consumo también pueden ser compatibles modificando sus ajustes de mezclador.

Sin --hwmon, la monitorización de puertos requiere que JACK lea audio en la memoria del sistema y luego lo copie de nuevo al hardware, imponiendo la latencia básica del sistema JACK determinada por los parámetros --period y --nperiods.

-i, --inchannels int

Número de canales de captura. (por defecto: máximo admitido por el hardware)
-I, --input-latency
Latencia de entrada adicional (fotogramas). (por defecto: 0)
-n, --nperiods int

Número de períodos de latencia de reproducción. En segundos, esto corresponde a --nperiods por --period dividido por --rate. El valor por defecto es 2, el mínimo permitido. Para la mayoría de los dispositivos, no es necesario ningún otro valor con la opción --realtime. Sin privilegios de tiempo real o con placas que proporcionan interrupciones poco fiables (como ymfpci), un valor mayor puede producir menos xruns. Esto también puede ayudar si el sistema no está optimizado para la planificación en tiempo real fiable.

Para la mayoría de los dispositivos ALSA, el búfer de hardware tiene exactamente --period por --nperiods fotogramas. Algunos dispositivos exigen un búfer mayor. En ese caso, JACK utilizará el búfer más pequeño posible que contenga al menos --nperiods, pero la latencia de reproducción no aumenta.

Para los dispositivos de audio USB se recomienda usar -n 3. Los dispositivos Firewire compatibles con FFADO (anteriormente FreeBoB) se configuran con -n 3 por defecto.

-o, --outchannels int

Número de canales de reproducción. (por defecto: máximo admitido por el hardware)
-O, --output-latency
Latencia de salida adicional (fotogramas). (por defecto: 0)
-P, --playback [ name ]
Proporcionar solo puertos de reproducción, a menos que se combine con -D o -C. Opcionalmente, establecer el nombre del dispositivo de reproducción.
-p, --period int

Número de fotogramas entre las llamadas a process() de JACK. Este valor debe ser una potencia de 2. Si necesita baja latencia, establezca -p lo más bajo posible sin ver xruns. Un tamaño de período mayor produce una latencia mayor, pero hace que los xruns sean menos probables. La latencia de captura de JACK en segundos es --period dividido por --rate. (por defecto: 1024)
-r, --rate int
Frecuencia de muestreo. (por defecto: 48000)
-S, --shorts

Intentar configurar la tarjeta para muestras de 16 bits primero, solo probando 32 bits si no se tiene éxito. (por defecto: muestras de 32 bits)
-s, --softmode

Ignorar los xruns reportados por el controlador ALSA. Esto hace que JACK sea menos propenso a desconectar puertos que no responden cuando se ejecuta sin --realtime.
-X, --midi [seq|raw]

A qué sistema MIDI de ALSA proporcionar acceso. Usar raw proporcionará un conjunto de puertos MIDI de JACK que corresponden a cada dispositivo ALSA "raw" en la máquina. Usar seq proporcionará un conjunto de puertos MIDI de JACK que corresponden a cada cliente "sequencer" de ALSA (que incluye cada puerto MIDI de hardware en la máquina). raw proporciona un rendimiento ligeramente mejor pero no permite la comunicación MIDI de JACK con software escrito para usar la API "sequencer" de ALSA.

DESCRIPTION

The JACK Connection Kit is a low-latency audio server that can be used to connect together multiple audio applications. It supports features such as sample accurate, real-time audio processing. This manual page describes the command line options available for the JACK audio server daemon, jackd.

The jackd daemon should be started by the jackstart script, which performs some system initializations and then starts jackd itself.

GENERAL OPTIONS

-a, --audio-fallback
Use the audio driver backend if the specified backend fails. This is the default behaviour.
-d, --driver driver
Use the specified audio driver backend. If not specified, the driver is determined by the system. Drivers include alsa, coreaudio, freebob, firewire, net, oss, portaudio, sndio, sun, and dummy.
-h, --help
Print a usage message summarizing the options for the specified driver.
-L, --log logfilename
Log messages to the specified file instead of stderr.
-m, --midi midi_driver
Use the specified midi driver backend. If not specified, the driver is determined by the system. Drivers include alsa, coreaudio, oss, sndio, net, dummy, and portaudio.
-R, --realtime
Attempt to use realtime scheduling priority. This is the default behaviour.
-r, --rate rate
Set the sample rate. (default: 48000)
-s, --sync
Use synchronous mode. This synchronizes the JACK server to the system clock. This is useful for network audio.
-t, --temporary
Run in temporary mode. This causes jackd to exit immediately after printing its configuration information.
-v, --verbose
Increase verbosity of output.
-w, --version
Print the version of the JACK server and exit.
--realtime-priority=priority
Set the realtime priority to use. (default: depends on system)

The Firewire device name to use. If none is specified, JACK will try to use "hw:0". To get a list of available Firewire devices, see ffado-test. It's recommended to use the GUID of a Firewire device to rule out any ambiguities. Once the GUID of the device is known ("ffado-test ListDevices"), it can be used like -dguid:0xff2584e39b078a2e to tell JACK which interface to use. Sometimes resetting the Firewire bus can help ("ffado-test BusReset") if there is any problem. (default: hw:0)
-p, --period int

Number of frames between JACK process() calls. This value must be a power of 2. If you need low latency, set -p as low as you can go without seeing xruns. A larger period size yields higher latency, but makes xruns less likely. The JACK capture latency in seconds is --period divided by --rate. (default: 1024)
-n, --nperiods int

Number of periods of playback latency. Value must be greater or equal 2. In seconds, this corresponds to --nperiods times --period divided by --rate. (default: 3)
-r, --rate int
Sample rate. (default: 48000)
-C, --capture [ name ]
Provide only capture ports, unless combined with -D or -P. Optionally set capture device name.
-P, --playback [ name ]
Provide only playback ports, unless combined with -D or -C. Optionally set playback device name.
-D, --duplex
Provide both capture and playback ports. This option is the default behaviour and can normally be omitted. -D can not be combined with -P or -C.
-I, --input-latency
Extra input latency (frames). (default: 0)
-O, --output-latency
Extra output latency (frames). (default: 0)
-v, --verbose

libffado verbose level. (default: 3)
-X, --snoop

Snoop Firewire traffic. (default: false)
-h, --help Print a brief usage message describing only the
firewire backend parameters.

EXAMPLES

Print usage message for the parameters specific to each backend.

jackd -d alsa --help
jackd -d coreaudio --help
jackd -d net --help
jackd -d dummy --help
jackd -d firewire --help
jackd -d oss --help
jackd -d sun --help
jackd -d portaudio --help

Run the JACK daemon with realtime priority using the first ALSA hardware card defined in /etc/modules.conf.

jackstart --realtime --driver=alsa

Run the JACK daemon with low latency giving verbose output, which can be helpful for trouble-shooting system latency problems. A reasonably well-tuned system with a good sound card and a low-latency kernel can handle these values reliably. Some can do better. If you get xrun messages, try a larger buffer. Tuning a system for low latency can be challenging. Please consult the JACK FAQ for more suggestions.

jackstart -Rv -d alsa -p 128 -n 2 -r 44100

Run jackd with realtime priority using the "sblive" ALSA device defined in ~/.asoundrc. Apply shaped dithering to playback audio.

jackd -R -d alsa -d sblive --dither=shaped

Run jackd with no special privileges using the second ALSA hardware card defined in /etc/modules.conf. Any xruns reported by the ALSA backend will be ignored. The larger buffer helps reduce data loss. Rectangular dithering will be used for playback.

jackd -d alsa -d hw:1 --ignorehwbuf=true --dither=rectangular
jackd -d alsa -d hw:1 -p2048 -n3 --softmode -zr

Ejecuta jackd en modo full-duplex utilizando el dispositivo ALSA hw:0,0 para reproducción y el dispositivo hw:0,2 para captura.

jackd -d alsa -P hw:0,0 -C hw:0,2

Ejecuta jackd en modo solo reproducción utilizando el dispositivo ALSA hw:0,0.

jackd -d alsa -P hw:0,0

AMBIENTE

JACK está evolucionando un mecanismo para iniciar automáticamente el servidor cuando sea necesario. Cualquier cliente iniciado sin un servidor JACK en ejecución intentará iniciar uno utilizando la línea de comandos que se encuentra en la primera línea de $HOME/.jackdrc si existe, o /etc/jackdrc si no existe. Si ninguno de los archivos existe, se utilizará un comando predeterminado incorporado, incluido el indicador -T, que hace que el servidor se apague cuando todos los clientes han salido.

Como transición, esto solo ocurre cuando se define $JACK_START_SERVER en el entorno del proceso que llama. En el futuro, este será el comportamiento normal. En cualquier caso, definir $JACK_NO_START_SERVER deshabilita esta función.

Para cambiar dónde busca JACK los controladores backend, establezca $JACK_DRIVER_DIR.

$JACK_DEFAULT_SERVER especifica el nombre del servidor predeterminado. Si no se define, se utiliza la cadena "default". Si se establece en sus respectivos entornos, esto afecta a jackd a menos que se establezca su parámetro --name, y a todos los clientes JACK a menos que pasen un nombre explícito a jack_client_open().

Definir $JACK_NO_AUDIO_RESERVATION omitirá la reserva del dispositivo de audio a través del bus de sesión (DBus). Esto puede ser útil si JACK se compiló con soporte DBus pero debe ejecutarse en un sistema sin interfaz gráfica.

$JACK_PROMISCUOUS_SERVER habilita una forma alternativa de manejar los diversos recursos compartidos (sockets Unix, semáforos, ...). En este modo, los nombres generados no contendrán el ID de usuario, y los permisos de esos recursos se relajarán, permitiendo que los clientes de diferentes usuarios hablen con el mismo servidor. Además, en las plataformas que lo admiten (todas las variantes POSIX), si se establece en un nombre de grupo Unix válido o un ID, los permisos se restringirán a ese grupo, por lo que solo los miembros de ese grupo podrán iniciar clientes que hablen con este servidor. Nota importante: debe establecerse con el mismo valor para que el servidor y los clientes funcionen como se espera.
