DESCRIPCIÓ

N

El Depurador de Java (JDB) es un depurador de línea de comandos sencillo para clases de Java. El comando jdb y sus opciones invocan al JDB. El comando jdb demuestra la Arquitectura de Depuración de la Plataforma

Java y proporciona inspección y depur
ación de una JVM local o remota.

INICIAR UNA SESIÓN DE

JDB

Hay muchas formas de iniciar una sesión de JDB. La forma más utilizada es que el JDB lance una nueva JVM con la clase principal de la aplicación a depurar. Hazlo sustituyendo el comando jdb por el comando java en la línea de comandos. Por ejemplo, si la clase principal de tu aplicación es MyClass, entonces usa el siguiente comando para depurarla bajo el

JDB:

jdb

MyC
lass

Cuando se inicia de esta manera, el comando jdb invoca una segunda JVM con los parámetros especificados, carga la clase especificada y detiene la JVM antes de ejecutar la primera instrucción de esa

clase.

Otra forma de usar el comando jdb es adjuntándolo a una JVM que ya está en ejecución. La sintaxis para iniciar una JVM a la que el comando jdb se adjunta cuando la JVM está en ejecución es la siguiente. Esto carga las bibliotecas de depuración en el proceso y especifica el tipo de conexión a

realizar.

java -agentlib:jdwp=tr

ansport=dt_socket,serv
er=y,suspend=n MyClass

Luego puedes adjuntar el comando jdb a la JVM con el siguiente

comando:

8000 es la dirección de la JVM en

El argumento MyClass no se especifica en la línea de comandos de jdb en este caso porque el comando jdb se está conectando a una JVM existente en lugar de lanzar una nueva

JVM.

Hay muchas otras formas de conectar el depurador a una JVM, y todas ellas son compatibles con el comando jdb. La Arquitectura de Depuración de la Plataforma Java

tiene documentación adicional sob

INTERRUPCIÓN

En el JDB se pueden establecer puntos de interrupción en números de línea o en la primera instrucción de un método, por

ejemplo:
•
El comando stop at MyClass:22 establece un punto de interrupción en la primera instrucción para la línea 22 del archivo fuente que contiene MyClas
s.
•
El comando stop in java.lang.String.length establece un punto de interrupción al comienzo del método java.lang.String
.length.
•
El comando stop in MyClass.<clinit> usa <clinit> para identificar el código de inicialización estática de MyCl
as
s.

Cuando un método está sobrecargado, también debes especificar sus tipos de argumentos para que se pueda seleccionar el método adecuado para el punto de interrupción. Por ejemplo, MyClass.myMethod(int,java.lang.String) o MyClass.myMet

hod().

El comando clear elimina puntos de interrupción usando la siguiente sintaxis: clear MyClass:45. Usar el comando clear o stop sin argumentos muestra una lista de todos los puntos de interrupción establecidos actualmente. El comando cont conti

EXCEPCIONE

S

Cuando ocurre una excepción para la que no hay una instrucción catch en ninguna parte de la pila de llamadas del hilo que la lanza, la JVM normalmente imprime un rastro de la excepción y termina. Sin embargo, cuando se ejecuta bajo el JDB, el control regresa al JDB en el lanzamiento ofensivo. Luego puedes usar el comando jdb para diagnosticar la causa de la

excepción.

Usa el comando catch para hacer que la aplicación depurada se detenga en otras excepciones lanzadas, por ejemplo: catch java.io.FileNotFoundException o catch mypackage.BigTroubleException. Cualquier excepción que sea una instancia de la clase especificada o de una subclase detiene la aplicación en el punto donde se lanza la

excepción.

El comando ignore anula el efecto de un comando catch anterior. El comando ignore no hace que la JVM depurada ignore ex

cepciones específicas, sino q
ue solo ignora al depurador.
