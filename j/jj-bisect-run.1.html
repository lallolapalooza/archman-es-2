DESCRIPCIÓ

N

Ejecuta un comando dado para encontrar la primera revisión

defectuosa.

Utiliza búsqueda binaria para encontrar la primera revisión defectuosa. Las revisiones se evalúan ejecutando un comando dado (consulta la documentación de `--command` para más detalles)

.

Se asume que si una revisión dada es defectuosa, entonces todos sus descendientes en el rango de entrada también son

defectuosos.

El objetivo de la bisectión se puede invertir para buscar la primera revisión correcta pasando

`--find-good`.

Consejo: Puedes pasar tu shell como comando de evaluación. Puedes entonces ejecutar pruebas manuales en el shell y asegurarte de salir del shell con el código de error apropiado dependiendo del resultado (p. ej. `exit 0` para marcar la revisión como correcta en Bash o Fish)

.

Ejemplo: Para ejecutar `cargo test` con los cambios de la revisión `xyz`

aplicados:

`jj bisect --range v1.0..main

-- bash -c "jj duplicate -r
xyz -B @ && cargo test"`

--ignore-working-c
opy
No hacer instantánea de la copia de trabajo, y no actualizarla

Por defecto, Jujutsu hace una instantánea de la copia de trabajo al comienzo de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si quieres evitar hacer una instantánea de la copia de trabajo y en su lugar ver un commit de la copia de trabajo posiblemente obsoleto, puedes usar `--ignore-working-copy`. Esto puede ser útil, p. ej., en un prompt de comando, especialmente si tienes otro proceso que hace commit de la copia de

trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-

cop
y`.
--ignore-immuta
ble
Permitir reescribir commits inmutables

Por defecto, Jujutsu impide reescribir commits en el conjunto configurado de commits inmutables. Esta opción desactiva esa comprobación y te permite reescribir cualquier commit excepto el commit

raíz.

Esta opción solo afecta a la comprobación. No

afecta al revset `immutable_heads()` n
i a la palabra clave de plantilla `immutable`.
--at-operation <AT_OPERATIO
N>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las

hay.

Puedes usar `--at-op=<operation ID>` para ver cómo era el repositorio en una operación anterior. Por ejemplo `jj --at-op=<operation ID> st` te mostrará lo que `jj st` te habría mostrado cuando la operación dada hubiera terminado. `--at-op=@` es prácticamente lo mismo que el defecto excepto que las operaciones divergentes nunca se

fusionarán.

Usa `jj op log` para encontrar el ID de operación que quieres. Cualquier prefijo no ambiguo del ID de operación es

suficiente.

Al cargar el repositorio en una operación anterior, la copia de trabajo se ignorará, como si se hubiera especificado `--ignore-working-c

opy`.

Es posible ejecutar comandos mutantes al cargar el repositorio en una operación an

terior. Hacer eso es equivalente a haber ejecutado comandos concurrentes comenzando
en la operación anterior. Rara vez hay una razón para hacer eso, pero es posible.
