JPEGOPTIM(1) Manual de Comandos Generales JPEGOPTIM(1)

NOMBRE

jpegoptim - utilidad para optimizar/comprimir archivos JPEG/JFIF.

SINOPSIS

jpegoptim [ opciones ] [ nombres_de_archivo ]

DESCRIPCIÓN

jpegoptim se utiliza para optimizar/comprimir archivos jpeg. El programa soporta optimización sin pérdida, que se basa en la optimización de las tablas de Huffman. Y la llamada optimización "con pérdida" donde, además de optimizar las tablas de Huffman, el usuario puede especificar un límite superior para la calidad de la imagen.

¡NOTA! Por defecto, jpegoptim modifica los archivos de entrada (si se optimizan); para conservar los archivos originales, utiliza la opción -d para especificar un directorio alternativo para guardar los archivos optimizados.

Solo se optimizan los archivos normales (se omiten los enlaces simbólicos y los archivos especiales). Además, cualquier otro enlace físico al archivo que se está optimizando (como los creados usando link(2)) no se ve afectado.

OPCIONES

Las opciones pueden ser las opciones tradicionales de una letra de POSIX o las opciones largas de estilo GNU. Las opciones de estilo POSIX comienzan con un único ``-'', mientras que las opciones largas de GNU comienzan con ``--''.

Las opciones que ofrece jpegoptim son las siguientes:

-d<ruta>, --dest=<ruta>
Establece un directorio de destino alternativo donde guardar los archivos optimizados (por defecto, se sobrescriben los originales). Tenga en cuenta que los archivos sin cambios no se añadirán al directorio de destino. Esto significa que si el archivo de origen no se puede comprimir, no se creará ningún archivo en la ruta de destino.
-f, --force
Forzar la optimización, incluso si el resultado fuera más grande que el archivo original.
-h, --help
Muestra información de uso breve y sale.
-m<calidad>, --max=<calidad>
Establece el factor de calidad máxima de la imagen (deshabilita el modo de optimización sin pérdida, que está habilitado por defecto). Esta opción reducirá la calidad de aquellos archivos fuente que se guardaron usando una configuración de calidad superior. Mientras que los archivos que ya tienen una configuración de calidad inferior se comprimirán utilizando el método de optimización sin pérdida.

Los valores válidos para el parámetro de calidad son: 0 - 100

-n, --noaction
No optimizar realmente los archivos, solo mostrar los resultados.
-S<tamaño>, --size=<tamaño>
Intentar optimizar el archivo a un tamaño dado (deshabilita el modo de optimización sin pérdida). El tamaño objetivo se especifica en kilobytes (1 - n) o como porcentaje (1% - 99%) del tamaño del archivo original.
-T<umbral>, --threshold=<umbral>
Mantener el archivo sin cambios si la ganancia de compresión es menor que el umbral (%).

Los valores válidos para el umbral son: 0 - 100

-w<máx>, --workers=<máx>
Establece el número máximo de procesos paralelos a lanzar. (Por defecto es 1)
-b, --csv
Mostrar información de progreso en formato CSV.
-o, --overwrite
Sobrescribir el archivo de destino incluso si existe (cuando se usa la opción -d).
-p, --preserve
Preservar las fechas de modificación del archivo.
-P, --preserve-perms
Preservar los permisos del archivo (propietario/grupo) sobrescribiendo el archivo original. Esto es ligeramente menos seguro que el modo de operación por defecto (donde el nuevo archivo se guarda primero como un archivo temporal y luego se renombra sobre el archivo original). En este modo, se crea una copia de seguridad del archivo original con la extensión .jpegoptim.bak, y este archivo se elimina después de que el archivo original haya sido reemplazado con éxito. NOTA: si se ejecuta jpegoptim como root, generalmente no hay necesidad de usar esta opción, ya que jpegoptim puede preservar los permisos de archivo cuando se ejecuta como root en modo por defecto.
-q, --quiet
Modo silencioso.
-r, --retry
Reintentar la compresión recursivamente hasta que el tamaño del archivo de salida ya no disminuya. Esto puede resultar en un archivo de salida unos pocos bytes más pequeño, pero a costa de mucho más tiempo de cálculo utilizado.

NOTA: Esta opción solo es efectiva cuando se usa en combinación con la opción -m (--max) o -S (--size).

-t, --totals
Mostrar totales después de procesar todos los archivos.
-v, --verbose
Habilita el modo detallado (muy hablador).
--auto-mode
Seleccionar el modo progresivo vs. no progresivo basándose en cuál produce un archivo de salida más pequeño. Por defecto, se preserva el modo (progresivo vs. no progresivo).
--all-normal
Forzar que todos los archivos de salida sean no progresivos. Se puede usar para convertir todos los archivos de entrada a JPEGs no progresivos cuando se usa con la opción --force.
--all-progressive
Forzar que todos los archivos de salida sean progresivos. Se puede usar para convertir todos los archivos de entrada JPEG normales (no progresivos) a progresivos cuando se usa con la opción --force.
--all-arith
Forzar que todos los archivos de salida usen Codificación Aritmética. Esta opción es experimental y solo está disponible si jpegoptim fue compilado con soporte de Codificación Aritmética habilitado.
--all-huffman
Forzar que todos los archivos de salida usen codificación Huffman (tradicional). Esta opción es experimental y solo está disponible si jpegoptim fue compilado con soporte de Codificación Aritmética habilitado.
--nofix
Omitir el procesamiento de cualquier archivo de entrada que tenga errores/advertencias durante la descompresión. Por defecto, jpegoptim intentará optimizar cualquier archivo que pueda descomprimir, incluso si la descompresión genera advertencias. Esto "corregirá" algunas imágenes JPEG (corruptas) automáticamente. Si este comportamiento no es deseado, se puede usar esta opción para hacer que jpegoptim omita cualquier archivo de entrada que contenga errores.
--save-extra
Guardar datos extraños después del final de la imagen JPEG en el archivo de entrada (por defecto, se descartan todos los datos extraños después del final de la imagen que puedan estar presentes). Esto puede ser útil si la imagen JPEG contiene extensiones no estándar que no forman parte del formato de imagen JPEG. NOTA: Esta opción no funciona si la imagen JPEG de entrada se lee desde la entrada estándar (stdin).
--stdout
Enviar la imagen de salida a la salida estándar. Tenga en cuenta que si la optimización no crea un archivo más pequeño que el archivo de entrada, entonces la imagen original de salida no se pasa sin modificar (excepto que se desecharán los datos adicionales después de la imagen JPEG).
--stdin
Leer la imagen de entrada desde la entrada estándar y enviar la salida a la salida estándar (--stdout se asume cuando se usa esta opción). Cuando se usa esta opción, solo se lee una imagen de la entrada estándar. Se ignoran los (otros) archivos de entrada especificados en la línea de comandos. Tenga en cuenta que si se ve el archivo de entrada '-' en la línea de comandos, también se asume la entrada estándar.
--files-stdin
Leer los nombres de los archivos a procesar desde la entrada estándar. Un nombre de archivo por línea.
--files-from=<nombre_de_archivo>
Leer los nombres de los archivos a procesar desde un archivo. Un nombre de archivo por línea.

OPCIONES DE METADATOS

Por defecto, jpegoptim conservará metadatos comunes (marcadores JPEG) y descartará cualquier otro (desconocido).

Los siguientes marcadores se conservan por defecto:
- EXIF
- IPTC
- ICC
- XMP
- COM (Marcadores de Comentarios JPEG)

El marcador JFIF será regenerado (por libjpeg) durante el proceso

METADATA OPTIONS

(Esto no se puede cambiar). Sin embargo, el marcador de Adobe también se genera (o se omite) por libjpeg en función del espacio de color de la imagen, etc. Este comportamiento depende de la versión de la biblioteca libjpeg que se esté utilizando. Para asegurar que el marcador de Adobe se conserve, se puede usar la opción --keep-adobe.

Para eliminar marcadores adicionales, se pueden usar una o más de las opciones --strip-*.

Por ejemplo: --strip-icc --strip-xmp --strip-com

Alternativamente, es posible especificar --strip-all y luego una o más de las opciones --keep-* para listar explícitamente qué marcadores conservar.

Por ejemplo: --strip-all --keep-exif --keep-iptc

Opciones para controlar los metadatos (marcadores) en los archivos de salida:

-s, --strip-all
Elimina todos los marcadores del archivo de salida. (¡NOTA! por defecto solo se conservan los marcadores de Comentario y Exif/IPTC/PhotoShop/ICC/XMP, todo lo demás se descarta). El JPEG de salida probablemente seguirá conteniendo uno o dos marcadores (JFIF y Adobe APP14) dependiendo del espacio de color utilizado en la imagen, ya que estos marcadores son generados automáticamente por el codificador libjpeg.
--strip-none, --keep-all
Conserva "todos" los marcadores de la imagen. Esto dejará todos los marcadores intactos en la imagen, excepto los marcadores JFIF (APP0) y Adobe (APP14), ya que estos son regenerados por la biblioteca libjpeg.

¡NOTA! Si se especifica esta opción, se ignorarán todas las demás opciones --strip-* o --keep-*.

--strip-com
Elimina los marcadores de Comentario (COM) del archivo de salida.
--strip-exif
Elimina los marcadores EXIF del archivo de salida.
--strip-iptc
Elimina los marcadores IPTC / Adobe Photoshop (APP13) del archivo de salida.
--strip-icc
Elimina los perfiles ICC del archivo de salida.
--strip-xmp
Elimina los perfiles XMP del archivo de salida.
--strip-jfif
Elimina los marcadores JFIF del archivo de salida.
--strip-jfxx
Elimina los marcadores JFXX (Extensiones JFIF) del archivo de salida.
--strip-adobe
Elimina los marcadores de Adobe del archivo de salida.
--keep-com
No elimina ningún marcador de Comentario (COM) del archivo de salida.
--keep-exif
No elimina ningún marcador EXIF del archivo de salida.
--keep-iptc
No elimina ningún marcador IPTC / Adobe Photoshop (APP13) del archivo de salida.
--keep-icc
No elimina ningún perfil ICC del archivo de salida.
--keep-xmp
No elimina ningún perfil XMP del archivo de salida.
--keep-jfif
No elimina ningún marcador JFIF del archivo de salida.
--keep-jfxx
No elimina ningún marcador JFXX (Extensiones JFIF) del archivo de salida.
--keep-adobe
No elimina los marcadores de Adobe del archivo de salida.

BUGS

Al usar la opción --size, el archivo resultante no siempre tiene exactamente el tamaño solicitado. Una solución es volver a ejecutar jpegoptim en el mismo archivo, lo que a menudo resultará en un archivo más cercano al tamaño objetivo.
