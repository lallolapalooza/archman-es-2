JMOD(1) Comandos JDK JMOD(1)

NOMBRE

jmod - crea archivos JMOD y lista el contenido de archivos JMOD existentes

SINOPSIS

jmod (create|extract|list|describe|hash) [opciones] archivo-jmod

Incluye lo siguiente:

Modos de operación principales

create
Crea un nuevo archivo de archivo JMOD.
extract
Extrae todos los archivos del archivo JMOD.
list
Imprime los nombres de todas las entradas.
describe
Imprime los detalles del módulo.
hash
Determina los módulos hoja y registra los hashes de las dependencias que los requieren directa e indirectamente.

Opciones

opciones
Consulte Opciones para jmod.

Requerido

archivo-jmod
Especifica el nombre del archivo JMOD a crear o del cual recuperar información.

DESCRIPCIÓN

Nota: Para la mayoría de las tareas de desarrollo, incluida la implementación de módulos en la ruta de módulos o su publicación en un repositorio Maven, continúe empaquetando módulos en archivos JAR modulares. La herramienta jmod está destinada a módulos que tienen bibliotecas nativas u otros archivos de configuración, o para módulos que pretende enlazar, con la herramienta jlink, a una imagen en tiempo de ejecución.

El formato de archivo JMOD permite agregar archivos que no sean archivos .class, metadatos y recursos. Este formato es transportable pero no ejecutable, lo que significa que puede usarlo durante el tiempo de compilación o enlace, pero no en tiempo de ejecución.

Muchas opciones de jmod implican especificar una ruta cuyos contenidos se copian en los archivos JMOD resultantes. Estas opciones copian todo el contenido de la ruta especificada, incluyendo subdirectorios y sus contenidos, pero excluyendo archivos cuyos nombres coincidan con el patrón especificado por la opción --exclude.

Con la opción --hash-modules o el comando jmod hash, puede, en el descriptor de cada módulo, registrar hashes del contenido de los módulos que tienen permitido depender de él, así "uniendo" estos módulos. Esto permite que un paquete se exporte a uno o más módulos específicamente nombrados y a ninguno más a través de exportaciones calificadas. El tiempo de ejecución verifica si el hash registrado de un módulo coincide con el resuelto en tiempo de ejecución; si no, el tiempo de ejecución devuelve un error.

OPCIONES PARA JMOD

--class-path ruta
Especifica la ubicación de los archivos JAR de la aplicación o un directorio que contiene clases para copiar en el archivo JMOD resultante.
--cmds ruta
Especifica la ubicación de los comandos nativos para copiar en el archivo JMOD resultante.
--compress compresion
Especifica la compresión a usar al crear el archivo JMOD. Los valores aceptados son zip-[0-9], donde zip-0 no proporciona compresión y zip-9 proporciona la mejor compresión. El valor predeterminado es zip-6.
--config ruta
Especifica la ubicación de los archivos de configuración editables por el usuario para copiar en el archivo JMOD resultante.
--dateMARCA_DE_TIEMPO
La marca de tiempo en formato de fecha y hora extendida ISO-8601 con zona horaria opcional, para usar como marca de tiempo de las entradas, p. ej., "2022-02-12T12:30:00-05:00".
--dir ruta
Especifica la ubicación donde jmod coloca los archivos extraídos del archivo JMOD especificado.
--dry-run
Realiza una ejecución de prueba del modo hash. Identifica los módulos hoja y sus módulos requeridos sin registrar ningún valor de hash.
--exclude lista-patrones
Excluye archivos que coincidan con la lista de patrones proporcionada y separada por comas, cada elemento utilizando una de las siguientes formas:
•
patron-glob
•
glob:patron-glob
•
regex:patron-regex

Consulte el método FileSystem.getPathMatcher para conocer la sintaxis de patron-glob. Consulte la clase Pattern para conocer la sintaxis de patron-regex, que representa una expresión regular.

--hash-modules patron-regex
Determina los módulos hoja y registra los hashes de las dependencias que los requieren directa e indirectamente, basándose en el grafo de módulos de los módulos que coinciden con el patron-regex dado. Los hashes se registran en el archivo JMOD que se está creando, o en un archivo JMOD o JAR modular en la ruta de módulos especificada por el comando jmod hash.
--header-files ruta
Especifica la ubicación de los archivos de cabecera para copiar en el archivo JMOD resultante.
--help o -h
Imprime un mensaje de uso.
--help-extra
Imprime ayuda para opciones adicionales.
--legal-notices ruta
Especifica la ubicación de los avisos legales para copiar en el archivo JMOD resultante.
--libs ruta
Especifica la ubicación de las bibliotecas nativas para copiar en el archivo JMOD resultante.
--main-class nombre-clase
Especifica la clase principal a registrar en el archivo module-info.class.
--man-pages ruta
Especifica la ubicación de las páginas man para copiar en el archivo JMOD resultante.
--module-version version-modulo
Especifica la versión del módulo a registrar en el archivo module-info.class.
--module-path ruta o -p ruta
Especifica la ruta del módulo. Esta opción es requerida si también especifica --hash-modules.
--target-platform plataforma
Especifica la plataforma de destino.
--version
Imprime información de la versión de la herramienta jmod.
@nombre-archivo
Lee las opciones del archivo especificado.

Un archivo de opciones es un archivo de texto que contiene las opciones y valores que normalmente escribiría en una línea de comandos. Las opciones pueden aparecer en una línea o en varias. No puede especificar variables de entorno para los nombres de ruta. Puede comentar líneas anteponiendo un símbolo de almohadilla (#) al principio de la línea.

< jmod(1) - Arch Linux man pages

NAME

jmod

manipulate Java module archives

SYNOPSIS

jmod create [OPTION]... <module-archive>
jmod extract [OPTION]... <module-archive>
jmod list [OPTION]... <module-archive>
jmod describe [OPTION]... <module-archive>
jmod hash [OPTION]... <module-archive>
jmod remove [OPTION]... <module-archive>
jmod help [COMMAND]

DESCRIPTION

The jmod command manipulates Java module archives. A Java module archive, or JMOD file, is a portable archive file that contains a module's code, resources, and other necessary files. JMOD files are used by the jlink tool to create custom runtime images.

OPTIONS FOR JMOD

The following options are available for the jmod command:

create
Create a new module archive.
extract
Extract the contents of a module archive.
list
List the contents of a module archive.
describe
Describe the contents of a module archive.
hash
Compute and record hash values for a module archive.
remove
Remove files from a module archive.
help
Display help information for a specific command.

EXTRA OPTIONS FOR JMOD

In addition to the options described in Options for jmod, the following are extra options that can be used with the command.

--do-not-resolve-by-default
Exclude from the default root set of modules
--warn-if-resolved
Hint for a tool to issue a warning if the module is resolved. One of deprecated, deprecated-for-removal, or incubating.

JMOD CREATE EXAMPLE

The following is an example of creating a JMOD file:

jmod create --class-path mods/com.greetings --cmds commands --config configfiles --header-files src/h --libs lib --main-class com.greetings.Main --man-pages man --module-version 1.0 --os-arch "x86_x64" --os-name "macOS" --os-version "10.10.5" greetingsmod

Create a JMOD file specifying the date for the entries as 2022 March 15 00:00:00:

jmod create --class-path build/foo/classes --date 2022-03-15T00:00:00Z
   jmods/foo1.jmod

JMOD HASH EXAMPLE

The following example demonstrates what happens when you try to link a leaf module (in this example, ma) with a required module (mb), and the hash value recorded in the required module doesn't match that of the leaf module.

1.
Create and compile the following .java files:
•
jmodhashex/src/ma/module-info.java
module ma {
  requires mb;
}
•
jmodhashex/src/mb/module-info.java
module mb {
}
•
jmodhashex2/src/ma/module-info.java
module ma {
  requires mb;
}
•
jmodhashex2/src/mb/module-info.java
module mb {
}
2.
Create a JMOD archive for each module. Create the directories jmodhashex/jmods and jmodhashex2/jmods, and then run the following commands from the jmodhashex directory, then from the jmodhashex2 directory:
•
jmod create --class-path mods/ma jmods/ma.jmod
•
jmod create --class-path mods/mb jmods/mb.jmod
3.
Optionally preview the jmod hash command. Run the following command from the jmodhashex directory:

jmod hash --dry-run -module-path jmods --hash-modules .*

The command prints the following:

Dry run:
mb
  hashes ma SHA-256 07667d5032004b37b42ec2bb81b46df380cf29e66962a16481ace2e71e74073a

This indicates that the jmod hash command (without the --dry-run option) will record the hash value of the leaf module ma in the module mb.

4.
Record hash values in the JMOD archive files contained in the jmodhashex directory. Run the following command from the jmodhashex directory:

jmod hash --module-path jmods --hash-modules .*

The command prints the following:

Hashes are recorded in module mb

5.
Print information about each JMOD archive contained in the jmodhashex directory. Run the highlighted commands from the jmodhashex directory:
jmod describe jmods/ma.jmod
ma
  requires mandated java.base
  requires mb
jmod describe jmods/mb.jmod
mb
  requires mandated java.base
  hashes ma SHA-256 07667d5032004b37b42ec2bb81b46df380cf29e66962a16481ace2e71e74073a
6.
Attempt to create a runtime image that contains the module ma from the directory jmodhashex2 but the module mb from the directory jmodhashex. Run the following command from the jmodhashex2 directory:
•
Linux and macOS:

jlink --module-path $JAVA_HOME/jmods:jmods/ma.jmod:../jmodhashex/jmods/mb.jmod --add-modules ma --output ma-app

•
Windows:

jlink --module-path %JAVA_HOME%/jmods;jmods/ma.jmod;../jmodhashex/jmods/mb.jmod --add-modules ma --output ma-app

The command prints an error message similar to the following:

Error: Hash of ma (a2d77889b0cb067df02a3abc39b01ac1151966157a68dc4241562c60499150d2) differs to
expected hash (07667d5032004b37b42ec2bb81b46df380cf29e66962a16481ace2e71e74073a) recorded in mb
