--coloca
te
Coloca el repositorio Jujutsu junto con el repositorio git

Especifica que el repositorio `jj` también debe ser un repositorio `git` válido, permitiendo el uso de los comandos `jj` y `git` en el mismo

directorio.

El repositorio contendrá un directorio `.git` en el nivel superior. Las herramientas Git habituales podrán operar sobre el

repositorio.

**Esta es la opción predeterminada**, y esta opción no tiene efecto, a menos que la [configuración git.colocate] esté establecida en

`false`.

Esta opción es mutuamente excluyente con

`--git-repo`.

[configuración git.colocate]: https://docs.jj-vcs.dev/latest/config/#default-coloc

--no-coloca
te
Desactiva la colocación del repositorio Jujutsu con el repositorio git

Impide que las herramientas Git que no conocen `jj` y los comandos Git habituales operen sobre el repositorio. El repositorio Git que almacena la mayor parte de los datos del repositorio se ocultará dentro de un subdirectorio del directorio

`.jj`.

Consulta [documentación de colocación] para algunas pequeñas ventajas de los espacios de trabajo no

colocados.

[documentación de colocación]: https://docs.jj-vcs.dev/latest/git-compatibility/#colocated-jujutsugit

--ignore-working-c
opy
No tomar instantánea de la copia de trabajo, y no actualizarla

Por defecto, Jujutsu toma una instantánea de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó la confirmación de la copia de trabajo (`@`). Si deseas evitar tomar una instantánea de la copia de trabajo y en su lugar ver una confirmación de la copia de trabajo posiblemente obsoleta, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en un prompt de comandos, especialmente si tienes otro proceso que confirma la copia de

trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-

cop
y`.
--ignore-immuta
ble
Permitir reescribir confirmaciones inmutables

Por defecto, Jujutsu impide reescribir confirmaciones en el conjunto configurado de confirmaciones inmutables. Esta opción desactiva esa comprobación y te permite reescribir cualquier confirmación excepto la de la

raíz.

Esta opción solo afecta a la comprobación. No

afecta al revset `immutable_heads()` n
i a la palabra clave de plantilla `immutable`.
--at-operation <AT_OPERATIO
N>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las

hay.

Puedes usar `--at-op=<operation ID>` para ver cómo era el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<operation ID> st` te mostraría lo que `jj st` habría mostrado cuando la operación indicada hubiera terminado. `--at-op=@` es prácticamente lo mismo que la predeterminada, excepto que las operaciones divergentes nunca se

fusionarán.

Usa `jj op log` para encontrar el ID de operación que deseas. Cualquier prefijo no ambiguo del ID de operación es

suficiente.

Al cargar el repositorio en una operación anterior, la copia de trabajo se ignorará, como si se hubiera especificado `--ignore-working-c

opy`.

Es posible ejecutar comandos mutadores al cargar el repositorio en una operación a

nterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes que comienz
an en la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.
