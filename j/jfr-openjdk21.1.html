DESCRIPCIÓ

N

El comando jfr proporciona una herramienta para interactuar con archivos de grabación de vuelo (.jfr). Su función principal es filtrar, resumir y generar la salida de archivos de grabación de vuelo en un formato legible para humanos. También admite la eliminación, fusión y división de archivos de grabación.Los archivos de grabación de vuelo se crean y se guardan como archivos con formato binario. Contar con una herramienta que pueda extraer el contenido de una grabación de vuelo, manipular el contenido y traducirlo a un formato legible para humanos ayuda a los desarrolladores a depurar problemas de rendimiento en aplicaciones Java. NAME

jfr

- Java Flight Recorder command-line tool

SYNOPSIS

jfr print [--help] [--version] [--path <path>] [--type type] [--filter filter] [--count count] [--stack-depth depth] [--lines] [--verbose] [--pretty-print] [file]

DESCRIPTION

The jfr tool is used to control and inspect flight recordings.

A flight recording is a low-overhead data collection that captures event information from a Java Virtual Machine (JVM). This information can be used to diagnose performance problems, analyze application behavior, and understand resource consumption.

The jfr tool can be used to perform a variety of operations on flight recordings, including:

  • Printing event data
  • Viewing event data
  • Configuring flight recorders
  • Retrieving metadata
  • Generating summaries
  • Scrubbing sensitive data
  • Assembling and disassembling recording files

jfr print subcommand

Use jfr print to print event data from a flight recording file.

The syntax is:

jfr print [--help] [--version] [--path <path>] [--type type] [--filter filter] [--count count] [--stack-depth depth] [--lines] [--verbose] [--pretty-print] [file]

--path <path>
Specifies the path to the JVM process to record from. If not specified, jfr will attempt to find a running JVM.
--type type
Filters the output to only include events of the specified type. Can be a fully qualified name (e.g., jdk.compiler.Inlining) or a simple name (e.g., GarbageCollection).
--filter filter
Filters the output based on a flexible filter expression. See Filter Syntax section below.
--count count
Prints only the specified number of events.
--stack-depth depth
Sets the maximum depth of stack traces to print.
--lines
Includes line numbers in the output where applicable.
--verbose
Prints additional details about the events.
--pretty-print
Formats the output in a more human-readable way.
file
Location of the flight recording file (.jfr). If omitted, events are read from a running JVM.

jfr view subcommand

Use jfr view to view event data from a flight recording file. This is similar to jfr print but optimized for interactive viewing.

The syntax is:

jfr view [--help] [--version] [--path <path>] [--type type] [--filter filter] [--lines] [--verbose] [file]

--path <path>
Specifies the path to the JVM process to record from. If not specified, jfr will attempt to find a running JVM.
--type type
Filters the output to only include events of the specified type.
--filter filter
Filters the output based on a flexible filter expression. See Filter Syntax section below.
--lines
Includes line numbers in the output where applicable.
--verbose
Prints additional details about the events.
file
Location of the flight recording file (.jfr). If omitted, events are read from a running JVM.

jfr configure subcommand

Use jfr configure to configure flight recorders.

The syntax is:

jfr configure [--help] [--version] [--all] [--name name] [--settings <file>] [--reset] [--path <path>] [--default] [--dump-settings <file>] [--track-metadata] [--track-initial-values] [--track-active-setting] [file]

--all
Configures all running JVMs.
--name name
Specifies the name of the recording to configure.
--settings <file>
Applies settings from the specified file.
--reset
Resets the configuration to default values.
--path <path>
Specifies the path to the JVM process to configure.
--default
Applies default settings.
--dump-settings <file>
Dumps the current settings to the specified file.
--track-metadata
Enables tracking of metadata.
--track-initial-values
Enables tracking of initial values.
--track-active-setting
Enables tracking of active settings.
file
Location of the flight recording file (.jfr). If omitted, configuration is applied to a running JVM.

jfr metadata subcommand

Use jfr metadata to retrieve metadata from a flight recording file.

The syntax is:

jfr metadata [--help] [--version] [file]

file
Location of the flight recording file (.jfr).

jfr summary subcommand

Use jfr summary to print statistics for a recording. For example, a summary can illustrate the number of recorded events and how much disk space they used. This is useful for troubleshooting and understanding the impact of event settings.

The syntax is:

jfr summary <file>

<file>
Location of the flight recording file (.jfr)

jfr scrub subcommand

Use jfr scrub to remove sensitive contents from a file or to reduce its size.

The syntax is:

jfr scrub [--include-events filter] [--exclude-events filter] [--include-categories filter] [--exclude-categories filter] [--include-threads filter] [--exclude-threads filter] <input-file> [<output-file>]

--include-events filter
Select events matching an event name.
--exclude-events filter
Exclude events matching an event name.
--include-categories filter
Select events matching a category name.
--exclude-categories filter
Exclude events matching a category name.
--include-threads filter
Select events matching a thread name.
--exclude-threads filter
Exclude events matching a thread name.
<input-file>
The input file to read events from.
<output-file>
The output file to write filter events to. If no file is specified, it will be written to the same path as the input file, but with "-scrubbed" appended to the filename.

The filter is a comma-separated list of names, simple and/or qualified, and/or quoted glob patterns. If multiple filters are used, they are applied in the specified order.

jfr assemble subcommand

Use jfr assemble to assemble chunk files into a recording file.

The syntax is:

jfr assemble <repository> <file>

where:

<repository>
Directory where the repository containing chunk files is located.
<file>
Location of the flight recording file (.jfr).

Flight recording information is written in chunks. A chunk contains all of the information necessary for parsing. A chunk typically contains events useful for troubleshooting. If a JVM should crash, these chunks can be recovered and used to create a flight recording file using this jfr assemble command. These chunk files are concatenated in chronological order and chunk files that are not finished (.part) are excluded.

jfr disassemble subcommand

Use jfr disassemble to decompose a flight recording file into its chunk file pieces.

The syntax is:

jfr disassemble [--max-chunks chunks] [--output <directory>] [--max-size size] [file]

where:

--output <directory>
The location to write the disassembled file, by default the current directory
--max-chunks chunks
Maximum number of chunks per file, by default 5. The chunk size varies, but is typically around 15 MB.
--max-size size
Maximum number of bytes per file.
file
Location of the flight recording file (.jfr)

This function can be useful for repairing a broken file by removing the faulty chunk. It can also be used to reduce the size of a file that is too large to transfer. The resulting chunk files are named myfile_1.jfr, myfile_2.jfr, etc. If needed, the resulting file names will be padded with zeros to preserve chronological order. For example, the chunk file name is myfile_001.jfr if the recording consists of more than 100 chunks.
