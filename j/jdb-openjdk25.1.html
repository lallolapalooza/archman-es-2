DESCRIPCIÓ

N

El Depurador de Java (JDB) es un depurador de línea de comandos simple para clases de Java. El comando jdb y sus opciones invocan el JDB. El comando jdb demuestra la Arquitectura de Depuración de la Plataforma Jav

a y proporciona la inspección y depur
ación de una JVM local o remota.

INICIAR UNA SESIÓN DE

JDB

Hay muchas formas de iniciar una sesión de JDB. La forma más utilizada es hacer que el JDB lance una nueva JVM con la clase principal de la aplicación a depurar. Hágalo sustituyendo el comando jdb por el comando java en la línea de comandos. Por ejemplo, si la clase principal de su aplicación es MyClass, entonces use el siguiente comando para depurarla bajo el

JDB:

jdb

MyC
lass

Cuando se inicia de esta manera, el comando jdb invoca una segunda JVM con los parámetros especificados, carga la clase especificada y detiene la JVM antes de ejecutar la primera instrucción de esa

clase.

Otra forma de usar el comando jdb es adjuntándolo a una JVM que ya está en ejecución. La sintaxis para iniciar una JVM a la que el comando jdb se adjunta cuando la JVM está en ejecución es la siguiente. Esto carga las bibliotecas de depuración en el proceso y especifica el tipo de conexión a

realizar.

El argumento MyClass no se especifica en la línea de comandos de jdb en este caso porque el comando jdb se está conectando a una JVM existente en lugar de lanzar una nueva

JVM.

EXCEPCIONE

S

Cuando ocurre una excepción para la que no hay una declaración catch en ninguna parte de la pila de llamadas del hilo que la lanza, la JVM normalmente imprime un rastro de excepción y sale. Sin embargo, cuando se ejecuta bajo el JDB, el control regresa al JDB en el punto de lanzamiento ofensivo. Luego puede usar el comando jdb para diagnosticar la causa de la

excepción.

Use el comando catch para hacer que la aplicación depurada se detenga en otras excepciones lanzadas, por ejemplo: catch java.io.FileNotFoundException o catch mypackage.BigTroubleException. Cualquier excepción que sea una instancia de la clase especificada o de una subclase detiene la aplicación en el punto donde se lanza la

excepción.

El comando ignore anula el efecto de un comando catch anterior. El comando ignore no hace que la JVM depurada ignore excepciones específicas, sino que solo ignora al depurador. OPCIONES PARA

OPTIONS FOR THE JDB COMMAND

The following options are passed to the JDB VM:

-tclient
Ejecuta la aplicación en la VM cliente de Java HotSpot.
-trackallthreads
Rastrea todos los hilos a medida que se crean, incluidos los hilos virtuales. Ver Trabajo con hilos virtuales más abajo.
-tserver
Ejecuta la aplicación en la VM servidor de Java HotSpot.
-Jopción
Pasa opción a la JVM de JDB, donde opción es una de las opciones descritas en la página de referencia del lanzador de aplicaciones de Java. Por ejemplo, -J-Xms48m establece la memoria de inicio en 48 MB. Consulte Descripción general de las opciones de Java en java.

Las siguientes opciones se reenvían al proceso de depuración:

-Ropción
Pasa opción a la JVM de depuración, donde opción es una de las opciones descritas en la página de referencia del lanzador de aplicaciones de Java. Por ejemplo, -R-Xms48m establece la memoria de inicio en 48 MB. Consulte Descripción general de las opciones de Java en java.
-v o -verbose[:clase|gc|jni]
Activa el modo detallado.
-Dnombre=valor
Establece una propiedad del sistema.
-classpath dir
Enumera los directorios separados por dos puntos en los que buscar clases.
-X opción
Una opción no estándar de la JVM de destino.

Se admiten otras opciones para proporcionar mecanismos alternativos para conectar el depurador a la JVM que se va a depurar.

TRABAJO CON HILOS VIRTUALES

A menudo, los hilos virtuales se crean en tal número y frecuencia que pueden saturar un depurador. Por esta razón, por defecto JDB no rastrea los hilos virtuales a medida que se crean. Solo rastreará los hilos virtuales en los que haya llegado un evento, como un evento de punto de interrupción. La opción -trackallthreads se puede usar para que JDB rastree todos los hilos virtuales a medida que se crean.

Cuando JDB se conecta por primera vez, solicita una lista de todos los hilos conocidos del Agente de Depuración. Por defecto, el agente de depuración no devuelve ningún hilo virtual en esta lista, una vez más porque la lista podría ser tan grande que sature al depurador. El Agente de Depuración tiene una opción includevirtualthreads que se puede habilitar para cambiar este comportamiento, de modo que se incluyan todos los hilos virtuales conocidos en la lista. La opción JDB -trackallthreads hará que JDB habilite automáticamente la opción includevirtualthreads del Agente de Depuración cuando JDB inicie una aplicación para depurar. Sin embargo, tenga en cuenta que el Agente de Depuración puede no conocer ningún hilo virtual que se haya creado antes de que JDB se conectara a la aplicación depurada.
