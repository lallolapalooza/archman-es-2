NOMBRE

jj-revert - Aplicar la inversa de las revisiones dadas

SINOPSIS

jj revert [-r|--revisions] [-o|--onto] [-A|--insert-after] [-B|--insert-before] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help]

DESCRIPCIÓN

Aplicar la inversa de las revisiones dadas

La inversa de cada una de las revisiones dadas se aplica secuencialmente en orden topológico inverso en la ubicación dada.

La descripción de las nuevas revisiones se puede personalizar con la variable de configuración `templates.revert_description`.

OPCIONES

-r, --revisions <REVSETS>
La(s) revisión(es) de las cuales aplicar la inversa
-o, --onto <REVSETS>
La(s) revisión(es) sobre las cuales aplicar los cambios inversos
-A, --insert-after <REVSETS>
La(s) revisión(es) después de las cuales insertar los cambios inversos (se puede repetir para crear un commit de fusión)
-B, --insert-before <REVSETS>
La(s) revisión(es) antes de las cuales insertar los cambios inversos (se puede repetir para crear un commit de fusión)
-h, --help
Imprimir ayuda (ver un resumen con '-h')

OPCIONES GLOBALES

-R, --repository <REPOSITORY>
Ruta al repositorio sobre el cual operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No hacer instantánea del directorio de trabajo y no actualizarlo

Por defecto, Jujutsu toma una instantánea del directorio de trabajo al inicio de cada comando. El directorio de trabajo también se actualiza al final del comando, si el comando modificó el commit del directorio de trabajo (`@`). Si desea evitar hacer una instantánea del directorio de trabajo y en su lugar ver un commit del directorio de trabajo posiblemente desactualizado, puede usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tiene otro proceso que confirma el directorio de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu previene la reescritura de commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y le permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puede usar `--at-op=<ID de operación>` para ver cómo se veía el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` le mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Use `jj op log` para encontrar el ID de operación que desea. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, el directorio de trabajo será ignorado, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutantes al cargar el repositorio en una operación anterior. Hacer eso es equivalente a haber ejecutado comandos concurrentes que comienzan en la operación anterior. Rara vez hay una razón para hacer eso, pero es posible.

--debug
Habilitar registro de depuración
--color <WHEN>
Cuándo colorear la salida

[valores posibles: always, never, debug, auto]

--quiet
Silenciar la salida no principal del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no le dirá si el directorio de trabajo fue fotografiado o si los descendientes fueron rebasados.

Las advertencias y errores seguirán imprimiéndose.

--no-pager
Desactivar el paginador
--config <NAME=VALUE>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves puntadas de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado en ningún constructo TOML (como notación de matriz), se pueden omitir las comillas.

--config-file <PATH>
Archivos de configuración adicionales (se pueden repetir)
revert
