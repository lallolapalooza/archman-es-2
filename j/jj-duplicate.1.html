NOMBRE

jj-duplicate - Crear nuevos cambios con el mismo contenido que los existentes

SINOPSIS

jj duplicate [-o|--onto] [-A|--insert-after] [-B|--insert-before] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] [REVSETS]

DESCRIPCIÓN

Crear nuevos cambios con el mismo contenido que los existentes

Cuando no se proporcionan los argumentos `--onto`, `--insert-after`, o `--insert-before`, los commits se duplicarán sobre sus padres existentes o sobre otros commits duplicados recientemente.

Cuando se proporcionan los argumentos `--onto`, `--insert-after`, o `--insert-before`, las raíces de los commits especificados se duplicarán sobre el destino indicado por los argumentos. Otros commits especificados se duplicarán sobre estos commits recién duplicados. Si se proporcionan los argumentos `--insert-after` o `--insert-before`, los nuevos hijos indicados por los argumentos se reorganizarán sobre las cabeceras de los commits especificados.

Por defecto, los commits duplicados conservan las descripciones de los originales. Esto se puede personalizar con la configuración `templates.duplicate_description`.

OPCIONES

-o, --onto <REVSETS>
La(s) revisión(es) sobre la(s) que duplicar (se puede repetir para crear un commit de fusión)
-A, --insert-after <REVSETS>
La(s) revisión(es) donde insertar después (se puede repetir para crear un commit de fusión)
-B, --insert-before <REVSETS>
La(s) revisión(es) donde insertar antes (se puede repetir para crear un commit de fusión)
-h, --help
Imprimir ayuda (ver un resumen con '-h')
[REVSETS]
La(s) revisión(es) a duplicar (por defecto: @)

OPCIONES GENERALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No tomar una instantánea del directorio de trabajo, y no actualizarlo

Por defecto, Jujutsu toma una instantánea del directorio de trabajo al principio de cada comando. El directorio de trabajo también se actualiza al final del comando, si el comando modificó el commit del directorio de trabajo (`@`). Si desea evitar tomar una instantánea del directorio de trabajo y ver en su lugar un commit del directorio de trabajo posiblemente obsoleto, puede usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en un prompt de comandos, especialmente si tiene otro proceso que hace commit del directorio de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu previene la reescritura de commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa comprobación y le permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta a la comprobación. No afecta al revset `immutable_heads()` ni a la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puede usar `--at-op=<ID de operación>` para ver cómo era el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` le mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Use `jj op log` para encontrar el ID de operación que desea. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignorará el directorio de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repositorio en una operación anterior. Hacer eso es equivalente a haber ejecutado comandos concurrentes a partir de la operación anterior. Raramente hay una razón para hacer eso, pero es posible.

--debug
Habilitar el registro de depuración
--color <CUANDO>
Cuándo colorear la salida

[posibles valores: siempre, nunca, depurar, auto]

--quiet
Silenciar la salida de comandos no primarios

Por ejemplo, `jj file list` seguirá listando archivos, pero no le dirá si se tomó una instantánea del directorio de trabajo o si se reorganizaron los descendientes.

Las advertencias y errores aún se imprimirán.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se puede repetir)

El nombre debe especificarse como claves con puntos de TOML. El valor debe especificarse como una expresión TOML. Si el valor de la cadena no está encerrado en ninguna construcción de TOML (como notación de matriz), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se puede repetir)
