JPACKAGE(1) Comandos del JDK JPACKAGE(1)

NOMBRE

jpackage - herramienta para empaquetar aplicaciones Java autónomas.

SINOPSIS

jpackage [opciones]

opciones
Opciones de la línea de comandos separadas por espacios. Véase Opciones de jpackage.

DESCRIPCIÓN

La herramienta jpackage tomará como entrada una aplicación Java y una imagen de tiempo de ejecución de Java, y producirá una imagen de aplicación Java que incluye todas las dependencias necesarias. Será capaz de producir un paquete nativo en un formato específico de la plataforma, como un exe en Windows o un dmg en macOS. Cada formato debe compilarse en la plataforma en la que se ejecuta, no hay soporte multiplataforma. La herramienta tendrá opciones que permiten personalizar las aplicaciones empaquetadas de varias maneras.

OPCIONES DE JPACKAGE

Opciones genéricas:

@nombre-de-archivo
Leer opciones de un archivo.

Esta opción puede usarse varias veces.

--type o -t tipo
El tipo de paquete a crear

Los valores válidos son: {"app-image", "exe", "msi", "rpm", "deb", "pkg", "dmg"}

Si esta opción no se especifica, se creará un tipo predeterminado dependiente de la plataforma.

--app-version versión
Versión de la aplicación y/o del paquete
--copyright copyright
Copyright de la aplicación
--description descripción
Descripción de la aplicación
--help o -h
Imprime el texto de uso con una lista y descripción de cada opción válida para la plataforma actual en el flujo de salida, y sale.
--icon ruta
Ruta del icono del paquete de la aplicación

(ruta absoluta o relativa al directorio actual)

--name o -n nombre
Nombre de la aplicación y/o del paquete
--dest o -d destino
Ruta donde se coloca el archivo de salida generado

(ruta absoluta o relativa al directorio actual).

Por defecto es el directorio de trabajo actual.

--temp directorio
Ruta de un directorio nuevo o vacío usado para crear archivos temporales

(ruta absoluta o relativa al directorio actual)

Si se especifica, el directorio temporal no se eliminará al finalizar la tarea y debe eliminarse manualmente.

Si no se especifica, se creará un directorio temporal y se eliminará al finalizar la tarea.

--vendor proveedor
Proveedor de la aplicación
--verbose
Habilita la salida detallada.
--version
Imprime la versión del producto en el flujo de salida y sale.

Opciones para crear la imagen del tiempo de ejecución:

--add-modules nombre-de-módulo [,nombre-de-módulo...]
Una lista de módulos a añadir separada por comas (",")

Esta lista de módulos, junto con el módulo principal (si se especifica), se pasará a jlink como el argumento --add-module. Si no se especifica, se usará o bien solo el módulo principal (si se especifica --module), o bien el conjunto predeterminado de módulos (si se especifica --main-jar).

Esta opción puede usarse varias veces.

--module-path o -p ruta-de-módulos [,ruta-de-módulos...]
Una lista de rutas separadas por File.pathSeparator

Cada ruta es o bien un directorio de módulos o la ruta a un jar modular, y es absoluta o relativa al directorio actual.

Esta opción puede usarse varias veces.

--jlink-options opciones
Una lista de opciones separadas por espacios para pasar a jlink

Si no se especifica, el valor predeterminado es "--strip-native-commands --strip-debug --no-man-pages --no-header-files"

Esta opción puede usarse varias veces.

--runtime-image directorio
Ruta de la imagen de tiempo de ejecución predefinida que se copiará en la imagen de la aplicación

(ruta absoluta o relativa al directorio actual)

Si --runtime-image no se especifica, jpackage ejecutará jlink para crear la imagen del tiempo de ejecución usando las opciones especificadas por --jlink-options.

Opciones para crear la imagen de la aplicación:

--input o -i directorio
Ruta del directorio de entrada que contiene los archivos a empaquetar

(ruta absoluta o relativa al directorio actual)

Todos los archivos del directorio de entrada se empaquetarán en la imagen de la aplicación.

`--app-content contenido-adicional[,contenido-adicional...]
Una lista separada por comas de rutas a archivos y/o directorios para añadir a la carga útil de la aplicación.

Esta opción puede usarse más de una vez.

Opciones para crear los lanzadores de la aplicación:

--add-launcher nombre=ruta
Nombre del lanzador, y una ruta a un archivo de propiedades que contiene una lista de pares clave, valor

(ruta absoluta o relativa al directorio actual)

Las claves "module", "main-jar", "main-class", "description", "arguments", "java-options", "app-version", "icon", "launcher-as-service", "win-console", "win-shortcut", "win-menu", "linux-app-category", y "linux-shortcut" pueden usarse.

Estas opciones se añaden, o se usan para sobrescribir, las opciones originales de la línea de comandos para construir un lanzador alternativo adicional. El lanzador principal de la aplicación se construirá a partir de las opciones de la línea de comandos. Se pueden construir lanzadores alternativos adicionales usando esta opción, y esta opción puede usarse varias veces para construir múltiples lanzadores adicionales.

--arguments argumentos
Argumentos de la línea de comandos para pasar a la clase principal si no se dan argumentos de la línea de comandos al lanzador

Esta opción puede usarse varias veces.

--java-options opciones
Opciones para pasar al tiempo de ejecución de Java

Esta opción puede usarse varias veces.

--main-class nombre-de-clase
Nombre calificado de la clase principal de la aplicación a ejecutar

Esta opción solo puede usarse si se especifica --main-jar.

--main-jar jar-principal
El JAR principal de la aplicación; que contiene la clase principal (especificada como una ruta relativa a la ruta de entrada)

Se puede especificar la opción --module o --main-jar pero no ambas.

--module o -m nombre-de-módulo[/nombre-de-clase-principal]
El módulo principal (y opcionalmente la clase principal) de la aplicación

Este módulo debe estar ubicado en la ruta de módulos.

Cuando se especifica esta opción, el módulo principal se enlazará en la imagen del tiempo de ejecución de Java. Se puede especificar la opción --module o --main-jar pero no ambas.

Opción dependiente de la plataforma para crear el lanzador de la aplicación:

Opciones de la plataforma Windows (disponibles solo al ejecutarse en Windows):

--win-console
<dd>Crea un lanzador de consola para la aplicación, debe especificarse para aplicaciones que requieren interacciones de consola

Opciones de la plataforma macOS (disponibles solo cuando se ejecuta en macOS):

--mac-package-identifier identificador
Un identificador que identifica de forma única la aplicación para macOS

Por defecto es el nombre de la clase principal.

Solo puede utilizar caracteres alfanuméricos (A-Z, a-z, 0-9), guion (-) y punto (.)

--mac-package-name nombre
Nombre de la aplicación tal como aparece en la barra de menús

Esto puede ser diferente del nombre de la aplicación.

Este nombre debe tener menos de 16 caracteres y ser adecuado para mostrarlo en la barra de menús y en la ventana de información de la aplicación. Por defecto es el nombre de la aplicación.

--mac-package-signing-prefix prefijo
Al firmar el paquete de la aplicación, este valor se antepone a todos los componentes que necesitan ser firmados y que no tienen un identificador de paquete existente.
--mac-sign
Solicita que el paquete o la imagen de aplicación predefinida sea firmada.
--mac-signing-keychain nombre-de-llavero
Nombre del llavero donde buscar la identidad de firma

Si no se especifica, se utilizan los llaveros estándar.

--mac-signing-key-user-name nombre
Nombre del equipo o usuario en las identidades de firma de Apple
--mac-app-store
Indica que la salida de jpackage está destinada a la Mac App Store.
--mac-entitlements ruta
Ruta al archivo que contiene los derechos de uso para firmar ejecutables y bibliotecas en el paquete
--mac-app-category categoría
Cadena utilizada para construir LSApplicationCategoryType en el archivo plist de la aplicación

El valor por defecto es "utilities".

Opciones para crear el paquete de la aplicación:

--about-url url
URL de la página de inicio de la aplicación
--app-image directorio
Ubicación de la imagen de aplicación predefinida que se utiliza para crear un paquete instalable (en todas las plataformas) o para ser firmada (en macOS)

(ruta absoluta o relativa al directorio actual)

--file-associations ruta
Ruta a un archivo de propiedades que contiene una lista de pares clave, valor

(ruta absoluta o relativa al directorio actual)

Las claves "extension", "mime-type", "icon" y "description" se pueden utilizar para describir la asociación.

Esta opción se puede usar varias veces.

--install-dir ruta
Ruta absoluta del directorio de instalación de la aplicación (en macOS o Linux), o subruta relativa del directorio de instalación como "Archivos de Programa" o "AppData" (en Windows)
--license-file ruta
Ruta al archivo de licencia

(ruta absoluta o relativa al directorio actual)

--resource-dir ruta
Ruta para sobrescribir los recursos de jpackage

(ruta absoluta o relativa al directorio actual)

Los iconos, archivos de plantilla y otros recursos de jpackage pueden ser sobrescritos añadiendo recursos de reemplazo a este directorio.

--runtime-image ruta
Ruta de la imagen de tiempo de ejecución predefinida a instalar

(ruta absoluta o relativa al directorio actual)

La opción es obligatoria al crear un instalador de tiempo de ejecución.

--launcher-as-service
Solicita crear un instalador que registre el lanzador principal de la aplicación como una aplicación de tipo servicio en segundo plano.

Opciones dependientes de la plataforma para crear el paquete de la aplicación:

Opciones de la plataforma Windows (disponibles solo cuando se ejecuta en Windows):

--win-dir-chooser
Añade un diálogo para permitir al usuario elegir un directorio en el que se instalará el producto.
--win-help-url url
URL donde el usuario puede obtener más información o soporte técnico
--win-menu
Solicita añadir un acceso directo en el Menú Inicio para esta aplicación
--win-menu-group nombre-del-grupo-de-menú
Grupo del Menú Inicio en el que se coloca esta aplicación
--win-per-user-install
Solicita realizar una instalación por usuario
--win-shortcut
Solicita crear un acceso directo en el escritorio para esta aplicación
--win-shortcut-prompt
Añade un diálogo para permitir al usuario elegir si el instalador creará accesos directos
--win-update-url url
URL de la información de actualización de la aplicación disponible
--win-upgrade-uuid id
UUID asociado con las actualizaciones para este paquete

Opciones de la plataforma Linux (disponibles solo cuando se ejecuta en Linux):

--linux-package-name nombre
Nombre para el paquete de Linux

Por defecto es el nombre de la aplicación.

--linux-deb-maintainer dirección-de-correo
Responsable del paquete .deb
--linux-menu-group nombre-del-grupo-de-menú
Grupo de menú en el que se coloca esta aplicación
--linux-package-deps
Paquetes o capacidades requeridas para la aplicación
--linux-rpm-license-type tipo
Tipo de licencia ("License: valor" del archivo .spec de RPM )
--linux-app-release lanzamiento
Valor de lanzamiento del archivo .spec RPM <nombre> o valor de revisión DEB del archivo de control DEB
--linux-app-category valor-de-categoría
Valor de grupo del archivo .spec RPM o valor de Sección del archivo de control DEB
--linux-shortcut
Crea un acceso directo para la aplicación.

Opciones de la plataforma macOS (disponibles solo cuando se ejecuta en macOS):

'--mac-dmg-content contenido-adicional[,contenido-adicional...]'
Incluye todo el contenido referenciado en el dmg.

Esta opción se puede usar más de una vez.

EJEMPLOS DE JPACKAGE


Generar un paquete de aplicación adecuado para el sistema anfitrión:


Para una aplicación modular:
    jpackage -n nombre -p rutaMódulo -m nombreMódulo/nombreClase
Para una aplicación no modular:
    jpackage -i directorioEntrada -n nombre \
        --main-class nombreClase --main-jar miJar.jar
Desde una imagen de aplicación preconstruida:
    jpackage -n nombre --app-image directorioImagenApp


Generar una imagen de aplicación:


Para una aplicación modular:
    jpackage --type app-image -n nombre -p rutaMódulo \
        -m nombreMódulo/nombreClase
Para una aplicación no modular:
    jpackage --type app-image -i directorioEntrada -n nombre \
        --main-class nombreClase --main-jar miJar.jar
Para proporcionar tus propias opciones a jlink, ejecuta jlink por separado:
    jlink --output imagenRuntimeApp -p rutaMódulo \
        --add-modules nombreMódulo \
        --no-header-files [<opciones adicionales de jlink>...]
    jpackage --type app-image -n nombre \
        -m nombreMódulo/nombreClase --runtime-image imagenRuntimeApp


Generar un paquete de tiempo de ejecución de Java:


jpackage -n nombre --runtime-image <runtime-image>


Firmar la imagen de aplicación predefinida (en macOS):


jpackage --type app-image --app-image <imagen-app> \
    --mac-sign [<opciones de firma adicionales>...]
Nota: las únicas opciones adicionales permitidas en este modo son:
      el conjunto de opciones de firma adicionales de Mac y --verbose

DIRECTORIO DE RECURSOS DE JPACKAGE

Los iconos, archivos de plantilla y otros recursos de jpackage pueden ser sobrescritos añadiendo recursos de reemplazo a este directorio. jpackage buscará archivos con nombres específicos en el directorio de recursos.

Archivos del directorio de recursos considerados solo cuando se ejecuta en Linux:

<nombre-lanzador>.png
Icono del lanzador de la aplicación

El recurso por defecto es JavaApp.png

<nombre-lanzador>.desktop
Un archivo de escritorio que se utilizará con el comando xdg-desktop-menu

Considerrojo con lanzadores de aplicaciones registrados para asociaciones de archivos y/o que tienen un icono

El recurso predeterminado es template.desktop

Archivos del directorio de recursos considerados solo al construir el instalador Linux DEB/RPM:

<package-name>-<launcher-name>.service
Archivo de unidad systemd para el lanzador de aplicaciones registrado como una aplicación de servicio en segundo plano

El recurso predeterminado es unit-template.service

Archivos del directorio de recursos considerados solo al construir el instalador Linux RPM:

<package-name>.spec
Archivo de especificación RPM

El recurso predeterminado es template.spec

Archivos del directorio de recursos considerados solo al construir el instalador Linux DEB:

control
Archivo de control

El recurso predeterminado es template.control

copyright
Archivo de copyright

El recurso predeterminado es template.copyright

preinstall
Script de shell de pre-instalación

El recurso predeterminado es template.preinstall

prerm
Script de shell de pre-eliminación

El recurso predeterminado es template.prerm

postinstall
Script de shell de post-instalación

El recurso predeterminado es template.postinstall

postrm
Script de shell de post-eliminación

El recurso predeterminado es template.postrm

Archivos del directorio de recursos considerados solo al ejecutarse en Windows:

<launcher-name>.ico
Icono del lanzador de aplicaciones

El recurso predeterminado es JavaApp.ico

<launcher-name>.properties
Archivo de propiedades para el ejecutable del lanzador de aplicaciones

El recurso predeterminado es WinLauncher.template

Archivos del directorio de recursos considerados solo al construir el instalador Windows MSI/EXE:

<application-name>-post-image.wsf
Un archivo de script de Windows (WSF) para ejecutar después de construir la imagen de la aplicación
main.wxs
Archivo principal del proyecto WiX

El recurso predeterminado es main.wxs

overrides.wxi
Archivo de proyecto WiX de anulaciones

El recurso predeterminado es overrides.wxi

service-installer.exe
Ejecutable del instalador de servicios

Se considera si algunos lanzadores de aplicaciones están registrados como aplicaciones de servicio en segundo plano

<launcher-name>-service-install.wxi
Archivo de proyecto WiX del instalador de servicios

Se considera si algunos lanzadores de aplicaciones están registrados como aplicaciones de servicio en segundo plano

El recurso predeterminado es service-install.wxi

<launcher-name>-service-config.wxi
Archivo de proyecto WiX del instalador de servicios

Se considera si algunos lanzadores de aplicaciones están registrados como aplicaciones de servicio en segundo plano

El recurso predeterminado es service-config.wxi

InstallDirNotEmptyDlg.wxs
Archivo de proyecto WiX para el cuadro de diálogo de la interfaz del instalador que verifica que el directorio de instalación no exista o esté vacío

El recurso predeterminado es InstallDirNotEmptyDlg.wxs

ShortcutPromptDlg.wxs
Archivo de proyecto WiX para el cuadro de diálogo de la interfaz del instalador que configura los accesos directos

El recurso predeterminado es ShortcutPromptDlg.wxs

bundle.wxf
Archivo de proyecto WiX con la jerarquía de componentes de la imagen de la aplicación
ui.wxf
Archivo de proyecto WiX para la interfaz del instalador

Archivos del directorio de recursos considerados solo al construir el instalador Windows EXE:

WinInstaller.properties
Archivo de propiedades para el ejecutable del instalador

El recurso predeterminado es WinInstaller.template

<package-name>-post-msi.wsf
Un archivo de script de Windows (WSF) para ejecutar después de construir el instalador MSI incrustado para el instalador EXE

Archivos del directorio de recursos considerados solo al ejecutarse en macOS:

<launcher-name>.icns
Icono del lanzador de aplicaciones

El recurso predeterminado es JavaApp.icns

Info.plist
Archivo de lista de propiedades de la aplicación

El recurso predeterminado es Info-lite.plist.template

Runtime-Info.plist
Archivo de lista de propiedades de Java Runtime

El recurso predeterminado es Runtime-Info.plist.template

<application-name>.entitlements
Archivo de lista de propiedades de los permisos de firma

Archivos del directorio de recursos considerados solo al construir el instalador macOS PKG/DMG:

<package-name>-post-image.sh
Script de shell para ejecutar después de construir la imagen de la aplicación
