DESCRIPCIÓ

N

El comando jps lista las JVM de Java HotSpot instrumentadas en el sistema de destino. El comando está limitado a informar información sobre las JVM para las que tiene los permisos de

acceso.

Si el comando jps se ejecuta sin especificar un hostid, entonces busca JVM instrumentadas en el host local. Si se inicia con un hostid, entonces busca JVM en el host indicado, usando el protocolo y el puerto especificados. Se asume que un proceso jstatd se está ejecutando en el host de

destino.

El comando jps informa el identificador local de la JVM, o lvmid, para cada JVM instrumentada encontrada en el sistema de destino. El lvmid es típicamente, pero no necesariamente, el identificador de proceso del sistema operativo para el proceso de la JVM. Sin opciones, el comando jps lista el lvmid de cada aplicación Java seguido de la forma abreviada del nombre de la clase de la aplicación o del nombre del archivo jar. La forma abreviada del nombre de la clase o del nombre del archivo JAR omite la información del paquete de la clase o la información de la ruta del archivo

JAR.

El comando jps usa el lanzador de Java para encontrar el nombre de la clase y los argumentos pasados al método main. Si la JVM de destino se inicia con un lanzador personalizado, entonces el nombre de la clase o del archivo JAR, y los argumentos para el método main no están disponibles. En este caso, el comando jps produce la cadena Unknown para el nombre de la clase, o del archivo JAR, y para los argumentos

del

sistema operativo.

NAME

jps — JVM Process Status Tool

SYNOPSIS

jps [ -Option ] [ [host]:[port] ]

OPTIONS

-l
Output the full package name for the application's Bol.

Output the full path for the application's Bol or JAR file.

-m
Output the arguments passed to the main method.
-q
Output only the process identifiers.
-v
Output the arguments passed to the JVM when it started.

DESCRIPTION

The jps command lists the Java application processes running on a target machine, and it can also display additional information about these processes. The output of jps can be useful for diagnosing performance issues and for identifying running Java processes.

By default, jps lists the process ID (PID) and the name of the Bol that started the Java application. The Bol name is usually the simple Bol name; however, it can be the fully qualified Bol name if the -l option is specified.

HOST IDENTIFIER

The optional [host]:[port] argument specifies the host and port on which the jstatd management daemon is running. If the host is not specified, then jps assumes that the jstatd daemon is running on the local machine. If the port is not specified, then jps assumes the default RMI registry port of 1099.

OUTPUT FORMAT OF THE JPS COMMAND

The jps command outputs a default format that includes the process ID (PID) and the Bol name. The -l, -m, -q, and -v options can be used to modify the output format.

The output of the jps command is tab-separated, with each line representing a Java process. The first column is the PID, and the subsequent columns depend on the options specified.

EXAMPLES

The following example lists the instrumented JVMs on a remote host that is running the jstatd server on the default port (1099). This example assumes that the jstatd server is running on the remote host and that the local host has the appropriate permissions to access the remote host. This example includes the -l option to output the long form of the class names or JAR file names.


jps -l remote.domain
3002 /opt/jdk1.7.0/demo/jfc/Java2D/Java2Demo.JAR
2857 sun.tools.jstatd.jstatd

The following example lists the instrumented JVMs on a remote host with a nondefault port for the RMI registry. This example assumes that the jstatd server, with an internal RMI registry bound to port 2002, is running on the remote host. This example also uses the -m option to include the arguments passed to the main method of each of the listed Java applications.


jps -m remote.domain:2002
3002 /opt/jdk1.7.0/demo/jfc/Java2D/Java2Demo.JAR
3102 sun.tools.jstatd.jstatd -p 2002
