JLINK(1) Comandos JDK JLINK(1)

NOMBRE

jlink - ensambla y optimiza un conjunto de módulos y sus dependencias en una imagen de tiempo de ejecución personalizada

SINOPSIS

jlink [opciones] --module-path rutamodulos --add-modules modulo [, modulo...]

opciones
Opciones de línea de comandos separadas por espacios. Consulte Opciones de jlink.
rutamodulos
La ruta donde la herramienta jlink descubre módulos observables. Estos módulos pueden ser archivos JAR modulares, archivos JMOD o módulos descomprimidos.
modulo
Los nombres de los módulos a agregar a la imagen de tiempo de ejecución. La herramienta jlink agrega estos módulos y sus dependencias transitivas.

DESCRIPCIÓN

La herramienta jlink enlaza un conjunto de módulos, junto con sus dependencias transitivas, para crear una imagen de tiempo de ejecución personalizada.

Nota:

Los desarrolladores son responsables de actualizar sus imágenes de tiempo de ejecución personalizadas.

OPCIONES DE JLINK

--add-modules mod [, mod...]
Agrega los módulos nombrados, mod, al conjunto predeterminado de módulos raíz. El conjunto predeterminado de módulos raíz está vacío.
--bind-services
Enlaza módulos proveedores de servicios y sus dependencias.
-c ={0|1|2} o --compress={0|1|2}
Habilita la compresión de recursos:
•
0: Sin compresión
•
1: Compartición de cadenas constantes
•
2: ZIP
--disable-plugin nombreplugin
Deshabilita el plugin especificado. Consulte Plugins de jlink para obtener la lista de plugins compatibles.
--endian {little|big}
Especifica el orden de bytes de la imagen generada. El valor predeterminado es el formato de la arquitectura de su sistema.
-h o --help
Imprime el mensaje de ayuda.
--ignore-signing-information
Suprime un error fatal cuando se enlazan archivos JAR modulares firmados en la imagen de tiempo de ejecución. Los archivos relacionados con la firma de los archivos JAR modulares firmados no se copian a la imagen de tiempo de ejecución.
--launcher comando=modulo o --launcher comando=modulo/main
Especifica el nombre del comando lanzador para el módulo o el nombre del comando para el módulo y la clase principal (los nombres del módulo y de la clase principal están separados por una barra /).
--limit-modules mod [, mod...]
Limita el universo de módulos observables a aquellos en el cierre transitivo de los módulos nombrados, mod, más el módulo principal, si lo hay, más cualquier módulo adicional especificado en la opción --add-modules.
--list-plugins
Lista los plugins disponibles, a los que puede acceder a través de opciones de línea de comandos; consulte Plugins de jlink.
-p o --module-path rutamodulos
Especifica la ruta de módulos.

Si esta opción no se especifica, la ruta de módulos predeterminada es $JAVA_HOME/jmods. Este directorio contiene el módulo java.base y los módulos estándar y JDK restantes. Si esta opción se especifica pero el módulo java.base no se puede resolver a partir de ella, el comando jlink agrega $JAVA_HOME/jmods a la ruta de módulos.

--no-header-files
Excluye archivos de encabezado.
--no-man-pages
Excluye páginas de manual.
--output ruta
Especifica la ubicación de la imagen de tiempo de ejecución generada.
--save-opts nombrearchivo
Guarda las opciones de jlink en el archivo especificado.
--suggest-providers [nombre, ...]
Sugiere proveedores que implementan los tipos de servicio dados de la ruta de módulos.
--version
Imprime información de la versión.
@nombrearchivo
Lee las opciones del archivo especificado.

Un archivo de opciones es un archivo de texto que contiene las opciones y valores que normalmente introduciría en un símbolo del sistema. Las opciones pueden aparecer en una línea o en varias líneas. No puede especificar variables de entorno para nombres de ruta. Puede comentar líneas anteponiendo un símbolo de almohadilla (#) al principio de la línea.

El siguiente es un ejemplo de archivo de opciones para el comando jlink:


#Mié 07 Dic 00:40:19 EST 2016
--module-path mlib
--add-modules com.greetings
--output greetingsapp

PLUGINS DE JLINK

Nota:

Los plugins no listados en esta sección no son compatibles y están sujetos a cambios.

Para las opciones de plugin que requieren una lista de patrones, el valor es una lista separada por comas de elementos, y cada elemento utiliza una de las siguientes formas:

•
patron_glob
•
glob:patron_glob
•
regex:patron_regex
•
@nombrearchivo
•
nombrearchivo es el nombre de un archivo que contiene patrones a usar, un patrón por línea.

Para obtener una lista completa de todos los plugins disponibles, ejecute el comando jlink --list-plugins.

Plugin compress

Opciones
--compress={0|1|2}[:filter=lista_patrones]
Descripción
Comprime todos los recursos en la imagen de salida.
•
Nivel 0: Sin compresión
•
Nivel 1: Compartición de cadenas constantes
•
Nivel 2: ZIP

Se puede especificar un filtro opcional de lista_patrones para listar el patrón de archivos a incluir.

Plugin include-locales

Opciones
--include-locales=etiqueta_idioma[,etiqueta_idioma]*
Descripción
Incluye la lista de locales donde etiqueta_idioma es una etiqueta de idioma BCP 47. Esta opción admite la coincidencia de locales según se define en RFC 4647. Asegúrese de agregar el módulo jdk.localedata al usar esta opción.

Ejemplo:

--add-modules jdk.localedata --include-locales=en,ja,*-IN

Plugin order-resources

Opciones
--order-resources=lista_patrones
Descripción
Ordena las rutas especificadas en orden de prioridad. Si se especifica @nombrearchivo, cada línea en lista_patrones debe ser una coincidencia exacta de las rutas a ordenar.

Ejemplo:

--order-resources=/module-info.class,@classlist,/java.base/java/lang/

Plugin strip-debug

Opciones
--strip-debug
Descripción
Elimina información de depuración de la imagen de salida.

Plugin generate-cds-archive

Opciones
--generate-cds-archive
Descripción
Genera el archivo CDS si la imagen de tiempo de ejecución admite la función CDS.

EJEMPLOS DE JLINK

El siguiente comando crea una imagen de tiempo de ejecución en el directorio greetingsapp. Este comando enlaza el módulo com.greetings, cuya definición de módulo se encuentra en el directorio mlib.


jlink --module-path mlib --add-modules com.greetings --output greeti
ngsapp

El siguiente comando lista los módulos en la imagen de ejecución

greetingsapp: 

greetingsapp/bin/java --list-modules
com.greetings
java.base@11
java.logging@11
org.astro@1.0

El siguiente comando crea una imagen de ejecución en el directorio compressedrt que está depurada de símbolos de depuración, usa compresión para reducir el espacio, e incluye información de configuración regional de idioma

francés: 

jlink --add-modules jdk.localedata --strip-debug --compress=2 --include-locales=fr --output compressedrt

El siguiente ejemplo compara el tamaño de la imagen de ejecución compressedrt con fr_rt, que no está depurada de símbolos de depuración y no usa

compresión: 

jlink --add-modules jdk.localedata --include-locales=fr --output fr_rt
du -sh ./compressedrt ./fr_rt
23M     ./compressedrt
36M     ./fr_rt

jlink --suggest-providers java.security.Provider

  jdk.crypto.cryptoki proporciona java.security.Provider usado por java.base
  jdk.crypto.ec proporciona java.security.Provider usado por java.base
  jdk.crypto.mscapi proporciona java.security.Provider usado por java.base
  jdk.security.jgss proporciona java.security.Provider usado por java.base

El siguiente ejemplo crea una imagen de ejecución personalizada llamada mybuild que incluye solo java.naming y jdk.crypto.cryptoki y sus dependencias pero ningún otro proveedor. Tenga en cuenta que estas dependencias deben existir en la ruta de

módulos: 

jlink --add-modules java.naming,jdk.crypto.cryptoki --output mybuild

El siguiente comando es similar al que crea una imagen de ejecución llamada greetingsapp, excepto que vinculará los módulos resueltos desde los módulos raíz con enlace de servicios; véase el Configuration.resolveAndBind método

jlink --module-path mlib --add-modules com.greetings --output greetingsapp --bind-services
