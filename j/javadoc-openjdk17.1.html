NOMBRE

javadoc - genera páginas HTML de documentación de API a partir de archivos fuente de Java

SINOPSIS

javadoc [opciones] [nombresdepaquete] [archivosfuente] [@archivos]

opciones
Especifica las opciones de línea de comandos, separadas por espacios. Consulte Opciones para javadoc, Opciones Extendidas, Opciones del doclet estándar y Opciones Adicionales Proporcionadas por el doclet estándar.
nombresdepaquete
Especifica los nombres de los paquetes que desea documentar, separados por espacios, por ejemplo java.lang java.lang.reflect java.awt. Si también desea documentar los subpaquetes, utilice la opción -subpackages para especificar los paquetes.

Por defecto, javadoc busca los paquetes especificados en el directorio actual y sus subdirectorios. Utilice la opción -sourcepath para especificar la lista de directorios donde buscar los paquetes.

archivosfuente
Especifica los nombres de los archivos fuente de Java que desea documentar, separados por espacios, por ejemplo Class.java Object.java Button.java. Por defecto, javadoc busca las clases especificadas en el directorio actual. Sin embargo, puede especificar la ruta completa al archivo de clase y utilizar caracteres comodín, por ejemplo /home/src/java/awt/Graphics*.java. También puede especificar la ruta relativa al directorio actual.
@archivos
Especifica los nombres de los archivos que contienen una lista de opciones de la herramienta javadoc, nombres de paquetes y nombres de archivos fuente en cualquier orden.

DESCRIPCION

La herramienta javadoc analiza las declaraciones y los comentarios de documentación en un conjunto de archivos fuente de Java y produce páginas HTML correspondientes que describen (por defecto) las clases públicas y protegidas, clases anidadas (pero no clases internas anónimas), interfaces, constructores, métodos y campos. Puede utilizar la herramienta javadoc para generar la documentación de la API o la documentación de la implementación para un conjunto de archivos fuente.

Puede ejecutar la herramienta javadoc en paquetes completos, archivos fuente individuales o ambos. Al documentar paquetes completos, puede usar la opción -subpackages para recorrer recursivamente un directorio y sus subdirectorios, o para pasar una lista explícita de nombres de paquetes. Al documentar archivos fuente individuales, pase una lista de nombres de archivos fuente de Java. Consulte Información general de javadoc [https://www.oracle.com/pls/topic/lookup?ctx=en/java/javase/13/tools&id=JSJAV-GUID-7A344353-3BBF-45C4-8B28-15025DDCC643] en la Guía de Javadoc de la Edición Estándar de la Plataforma Java para obtener información sobre el uso de la herramienta javadoc.

CONFORMIDAD

El doclet estándar no valida el contenido de los comentarios de documentación en busca de conformidad, ni intenta corregir ningún error en los comentarios de documentación. Se recomienda a cualquiera que ejecute javadoc que sea consciente de los problemas que pueden surgir al generar salida no conforme o salida que contenga contenido ejecutable, como JavaScript. El doclet estándar proporciona la característica doclint para ayudar a los desarrolladores a detectar problemas comunes en los comentarios de documentación; pero también se recomienda comprobar la salida generada con las herramientas de conformidad y otras herramientas de verificación apropiadas.

Para obtener más detalles sobre los requisitos de conformidad para documentos HTML5, consulte Requisitos de conformidad [https://www.w3.org/TR/html5/infrastructure.html#conformance-requirements] en la Especificación HTML5. Para obtener más detalles sobre problemas de seguridad relacionados con páginas web, consulte la página del Open Web Application Security Project (OWASP) [https://www.owasp.org].

-breakiterator
Calcula la primera frase con BreakIterator. La primera frase se copia al resumen del paquete, clase o miembro y al índice alfabético. La clase BreakIterator se utiliza para determinar el final de una frase para todos los idiomas excepto para el inglés.
•
Algoritmo por defecto de separación de frases en inglés --- Se detiene en un punto seguido de un espacio o una etiqueta de bloque HTML, como <P>.
•
Algoritmo de separación de frases de Breakiterator --- Se detiene en un punto, signo de interrogación o signo de exclamación seguido de un espacio cuando la siguiente palabra comienza con una letra mayúscula. Esto está pensado para manejar la mayoría de las abreviaturas (como "El número de serie. es válido", pero no manejará "Sr. Smith"). La opción -breakiterator no se detiene en etiquetas HTML o frases que comienzan con números o símbolos. El algoritmo se detiene en el último punto de ../nombrearchivo, incluso cuando está incrustado en una etiqueta HTML.

-locale name
Especifica la configuración regional (locale) que la herramienta javadoc utiliza al generar la documentación. El argumento es el nombre de la configuración regional, como se describe en la documentación de java.util.Locale, por ejemplo, en_US (inglés, Estados Unidos) o en_US_WIN (variante de Windows).

Nota:

La opción -locale debe colocarse antes (a la izquierda) de cualquier opción proporcionada por el doclet estándar o cualquier otro doclet. De lo contrario, las barras de navegación aparecerán en inglés. Esta es la única opción de línea de comandos que depende del orden.

Especificar una configuración regional hace que la herramienta javadoc elija los archivos de recursos de esa configuración regional para mensajes como cadenas en la barra de navegación, encabezados de listas y tablas, contenido del archivo de ayuda, comentarios en el archivo stylesheet.css, etc. También especifica el orden de clasificación para listas ordenadas alfabéticamente y el separador de oraciones para determinar el final de la primera oración. La opción -locale no determina la configuración regional del texto del comentario de documentación especificado en los archivos fuente de las clases documentadas.

OPCIONES GENERALES

-breakiterator
Uses the BreakIterator interface to correctly break navigable sentences that are found in natural language, regardless of the locale. Without the -breakiterator option, the javadoc tool uses the sentence.separator.regex property to split sentences, which works well for English but can cause problems for other languages.
-locale locale
Specifies the locale to use when searching for javadoc source files. Locales are specified as language, e.g., en, or language-country, e.g., en-US (English-United States). If you do not specify the -locale option, then javadoc uses the default locale of the computer it runs on.
-public
Shows only public classes and members.
-protected
Shows only protected and public classes and members. This is the default behavior.
-sincefile file
Specifies the path to the since file.
-overview file
Specifies the HTML file that contains an overview of all the packages. This option is used to specify the source file for the overview page, which is linked to by the Overview link on the top navigation bar. The default is to use the file named overview.html. If the -overview option is not specified, the javadoc tool looks for overview.html in the current directory.

Command-line example:

javadoc -overview my_overview.html com.mypackage

-package
Shows only package, protected, and public classes and members.
-private
Shows all classes and members.
-splitindex
Splits the index into one file per letter.
-use
Includes a link to the "Use" page for each class and package. The "Use" page explains which other classes or packages use the documented class or package.
-version
Includes the @version information in the generated docs.
-warn
Shows all warnings.
-verbose
Provides more detailed messages while the javadoc tool runs. Without the -verbose option, messages appear for loading the source files, generating the documentation (one message per source file), and sorting. The -verbose option causes the printing of additional messages that specify the number of milliseconds to parse each Java source file.
--version
Prints version information.
-Werror
Reports an error if any warnings occur.

-bottom código-html
Especifica el texto que se colocará en la parte inferior de cada archivo de salida. El texto se coloca en la parte inferior de la página, debajo de la barra de navegación inferior. El texto puede contener etiquetas HTML y espacios en blanco, pero cuando lo hace, el texto debe ir entre comillas. Utilice caracteres de escape para cualquier comilla interna dentro del texto.
-charset nombre
Especifica el juego de caracteres HTML para este documento. El nombre debe ser un nombre MIME preferido, como se especifica en el Registro IANA de juegos de caracteres [http://www.iana.org/assignments/character-sets].

Por ejemplo:

javadoc -charset "iso-8859-1" mypackage

Este comando inserta la siguiente línea en la cabecera de cada página generada:

<META http-equiv="Content-Type" content="text/html; charset=ISO-8859-1">

La etiqueta META se describe en el estándar HTML (4197265 y 4137321), Representación de documentos HTML [http://www.w3.org/TR/REC-html40/charset.html#h-5.2.2].

-d directorio
Especifica el directorio de destino donde la herramienta javadoc guarda los archivos HTML generados. Si omite la opción -d, los archivos se guardan en el directorio actual. El valor directorio puede ser absoluto o relativo al directorio de trabajo actual. El directorio de destino se crea automáticamente cuando se ejecuta la herramienta javadoc.
•
Linux y OS X: Por ejemplo, el siguiente comando genera la documentación para el paquete com.mypackage y guarda los resultados en el directorio /user/doc/:

javadoc -d /user/doc/ com.mypackage

•
Windows: Por ejemplo, el siguiente comando genera la documentación para el paquete com.mypackage y guarda los resultados en el directorio \user\doc\:

javadoc -d \user\doc\ com.mypackage

-docencoding nombre
Especifica la codificación de los archivos HTML generados. El nombre debe ser un nombre MIME preferido, como se especifica en el Registro IANA de juegos de caracteres [http://www.iana.org/assignments/character-sets].

Hay tres opciones disponibles para usar en un comando de codificación de javadoc. La opción -encoding se usa para codificar los archivos leídos por la herramienta javadoc, mientras que las opciones -docencoding y -charset se usan para codificar los archivos escritos por la herramienta. De las tres opciones disponibles, como máximo, solo se utilizan una opción de codificación de entrada y una de salida en un único comando de codificación. Si especifica ambas opciones de codificación de entrada y salida en un comando, deben tener el mismo valor. Si no especifica ninguna opción de salida, la herramienta utiliza la codificación de entrada por defecto.

Por ejemplo:

javadoc -docencoding "iso-8859-1" mypackage

Cuando la opción -Xdoclint está habilitada, informa sobre problemas con mensajes similares a los de la comando javac. La herramienta javadoc imprime un mensaje, una copia de la línea de origen y un cursor que apunta a la posición exacta donde se detectó el error. Los mensajes pueden ser advertencias o errores, dependiendo de su gravedad y la probabilidad de causar un error si la documentación generada se sometiera a un validador. Por ejemplo: comentarios de documentación faltantes, información duplicada y comentarios superfluos no hacen que la herramienta javadoc genere HTML inválido, por lo que estos problemas se informan como advertencias; errores de sintaxis, etiquetas de cierre HTML requeridas faltantes y referencias a elementos faltantes o mal escritos hacen que la herramienta javadoc genere una salida inválida, por lo que estos problemas se informan como

errores.

solicitado.
