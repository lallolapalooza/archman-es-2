NOMBRE

jj-interdiff - Compara los cambios de dos commits

SINOPSIS

jj interdiff [-f|--from] [-t|--to] [-s|--summary] [--stat] [--types] [--name-only] [--git] [--color-words] [--tool] [--context] [-w|--ignore-all-space] [-b|--ignore-space-change] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] [FILESETS]

DESCRIPCIÓN

Compara los cambios de dos commits

Esto excluye los cambios de otros commits rebajando temporalmente `--from` sobre los padres de `--to`. Si deseas comparar el mismo cambio entre versiones, considera usar `jj evolog -p` en su lugar.

OPCIONES

-f, --from <REVSET>
Muestra los cambios de esta revisión
-t, --to <REVSET>
Muestra los cambios hasta esta revisión
-h, --help
Imprime la ayuda (ver un resumen con '-h')
[FILESETS]
Restringe la diferencia a estas rutas

OPCIONES DE FORMATEO DE DIFERENCIA

-s, --summary
Para cada ruta, muestra solo si fue modificada, añadida o eliminada
--stat
Muestra un histograma de los cambios
--types
Para cada ruta, muestra solo su tipo antes y después

La diferencia se muestra como dos letras. La primera letra indica el tipo antes y la segunda letra indica el tipo después. '-' indica que la ruta no estaba presente, 'F' representa un archivo regular, `L' representa un enlace simbólico, 'C' representa un conflicto y 'G' representa un submódulo de Git.

--name-only
Para cada ruta, muestra solo su ruta

Típicamente útil para comandos de shell como: `jj diff -r @- --name-only | xargs perl -pi -e's/VIEJO/NUEVO/g`

--git
Muestra una diferencia en formato Git
--color-words
Muestra una diferencia a nivel de palabra con cambios indicados solo por color
--tool <TOOL>
Genera la diferencia mediante un comando externo

También se puede especificar un formato incorporado como `:<nombre>`. Por ejemplo, `--tool=:git` es equivalente a `--git`.

--context <CONTEXT>
Número de líneas de contexto a mostrar
-w, --ignore-all-space
Ignora el espacio en blanco al comparar líneas
-b, --ignore-space-change
Ignora los cambios en la cantidad de espacio en blanco al comparar líneas

OPCIONES GLOBALES

-R, --repository <REPOSITORY>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio más cercano `.jj/` en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No guardar una instantánea del directorio de trabajo y no actualizarlo

Por defecto, Jujutsu guarda una instantánea del directorio de trabajo al principio de cada comando. El directorio de trabajo también se actualiza al final del comando, si el comando modificó el commit del directorio de trabajo (`@`). Si deseas evitar guardar una instantánea del directorio de trabajo y ver en su lugar un commit del directorio de trabajo posiblemente desactualizado, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tienes otro proceso que confirma el directorio de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu evita reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y te permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puedes usar `--at-op=<ID de operación>` para ver cómo se veía el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` te mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor por defecto, excepto que las operaciones divergentes nunca se fusionarán.

Usa `jj op log` para encontrar el ID de operación que deseas. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, el directorio de trabajo se ignorará, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes a partir de la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilita el registro de depuración
--color <WHEN>
Cuándo colorear la salida

[valores posibles: always, never, debug, auto]

--quiet
Silencia la salida no principal del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no te dirá si se guardó una instantánea del directorio de trabajo o si se rebasaron los descendientes.

Las advertencias y errores seguirán imprimiéndose.

--no-pager
Deshabilita el paginador
--config <NAME=VALUE>
Opciones de configuración adicionales (se puede repetir)

El nombre debe especificarse como claves puntuales de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado en ninguna construcción de TOML (como notación de arreglo), las comillas se pueden omitir.

--config-file <PATH>
Archivos de configuración adicionales (se pueden repetir)
interdiff
