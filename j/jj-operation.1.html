NOMBRE

jj-operation - Comandos para trabajar con el registro de operaciones

SINOPSIS

jj operation [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <subcomandos>

DESCRIPCIÓN

Comandos para trabajar con el registro de operaciones

Consulta la [documentación del registro de operaciones] para más información.

[documentación del registro de operaciones]: https://docs.jj-vcs.dev/latest/operation-log/

OPCIONES

-h, --help
Imprimir ayuda (ver resumen con '-h')

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No tomar instantánea de la copia de trabajo, ni actualizarla

Por defecto, Jujutsu toma una instantánea de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si deseas evitar tomar una instantánea de la copia de trabajo y ver en su lugar un commit de copia de trabajo posiblemente obsoleto, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en un prompt de comandos, especialmente si tienes otro proceso que confirma la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu evita reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa comprobación y te permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la comprobación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repo

Operación en la que cargar el repo. Por defecto, Jujutsu carga el repo en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puedes usar `--at-op=<ID de operación>` para ver cómo se veía el repo en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` te mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de terminar. `--at-op=@` es prácticamente lo mismo que por defecto, excepto que las operaciones divergentes nunca se fusionarán.

Usa `jj op log` para encontrar el ID de operación que deseas. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repo en una operación anterior, se ignorará la copia de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutantes al cargar el repo en una operación anterior. Hacer eso es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilitar registro de depuración
--color <CUANDO>
Cuándo colorear la salida

[posibles valores: always, never, debug, auto]

--quiet
Silenciar la salida no principal del comando

Por ejemplo, `jj file list` todavía listará los archivos, pero no te dirá si la copia de trabajo fue fotografiada o si los descendientes fueron rebasados.

Las advertencias y los errores seguirán imprimiéndose.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves separadas por puntos TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado en ningún constructo TOML (como la notación de matriz), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
