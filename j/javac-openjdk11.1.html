javac(1) Herramientas Básicas javac(1)

NOMBRE

javac - Lee definiciones de clases e interfaces de Java y las compila en bytecode y archivos de clase.

SINOPSIS

javac [ opciones ] [ archivosfuente ] [ clases] [ @archivosarg ]

Los argumentos pueden estar en cualquier orden:

opciones
Opciones de línea de comandos. Ver Opciones.
archivosfuente
Uno o más archivos fuente para compilar (como MiClase.java).
clases
Una o más clases para procesar anotaciones (como MiPaquete.MiClase).
@archivosarg
Uno o más archivos que listan opciones y archivos fuente. Las opciones -J no están permitidas en estos archivos. Ver Archivos de Argumentos de Línea de Comandos.

DESCRIPCIÓN

El comando javac lee definiciones de clases e interfaces, escritas en el lenguaje de programación Java, y las compila en archivos de clase de bytecode. El comando javac también puede procesar anotaciones en archivos fuente y clases de Java.

Hay dos maneras de pasar nombres de archivos de código fuente a javac.

•
Para un número pequeño de archivos fuente, liste los nombres de archivo en la línea de comandos.
•
Para un número grande de archivos fuente, liste los nombres de archivo en un archivo separado por espacios o saltos de línea. Use el nombre del archivo de lista precedido por una arroba (@) con el comando javac.

Los nombres de archivo de código fuente deben tener extensiones .java, los nombres de archivo de clase deben tener extensiones .class, y tanto los archivos fuente como los de clase deben tener nombres raíz que identifiquen la clase. Por ejemplo, una clase llamada MiClase se escribiría en un archivo fuente llamado MiClase.java y se compilaría en un archivo de clase de bytecode llamado MiClase.class.

Las definiciones de clases internas producen archivos de clase adicionales. Estos archivos de clase tienen nombres que combinan los nombres de la clase interna y externa, como MiClase$MiClaseInterna.class.

Organice los archivos fuente en una estructura de directorios que refleje su árbol de paquetes. Por ejemplo, si todos sus archivos fuente están en /workspace, entonces ponga el código fuente de com.miempresa.mipaquete.MiClase en /workspace/com/miempresa/mipaquete/MiClase.java.

Por defecto, el compilador coloca cada archivo de clase en el mismo directorio que su archivo fuente. Puede especificar un directorio de destino diferente con la opción -d.

OPCIONES

El compilador tiene un conjunto de opciones estándar que son compatibles en el entorno de desarrollo actual. Un conjunto adicional de opciones no estándar son específicas de la implementación actual de la máquina virtual y del compilador y están sujetas a cambios en el futuro. Las opciones no estándar comienzan con la opción -X.

OPCIONES&#x00A0;ESTÁNDAR

-Aclave[=valor]

Especifica opciones para pasar a los procesadores de anotaciones. Estas opciones no son interpretadas directamente por javac, sino que se ponen a disposición para su uso por procesadores individuales. El valor de clave debe ser uno o más identificadores separados por un punto (.).
-cp ruta o -classpath ruta

Especifica dónde encontrar los archivos de clase de usuario y (opcionalmente) procesadores de anotaciones y archivos fuente. Esta ruta de clases anula la ruta de clases de usuario en la variable de entorno CLASSPATH. Si no se especifica CLASSPATH, -cp ni -classpath, entonces la ruta de clases de usuario es el directorio actual. Ver Establecer la Ruta de Clases.

Si la opción -sourcepath no se especifica, entonces también se busca en la ruta de clases de usuario los archivos fuente.

Si la opción -processorpath no se especifica, entonces también se busca en la ruta de clases los procesadores de anotaciones.

-Djava.ext.dirs=directorios

Anula la ubicación de las extensiones instaladas.
-Djava.endorsed.dirs=directorios

Anula la ubicación de la ruta de estándares avalados.
-d directorio

Establece el directorio de destino para los archivos de clase. El directorio debe existir previamente porque javac no lo crea. Si una clase forma parte de un paquete, entonces javac coloca el archivo de clase en un subdirectorio que refleja el nombre del paquete y crea directorios según sea necesario.

Si especifica -d/home/misclases y la clase se llama com.mipaquete.MiClase, entonces el archivo de clase es /home/misclases/com/mipaquete/MiClase.class.

Si la opción -d no se especifica, entonces javac coloca cada archivo de clase en el mismo directorio que el archivo fuente del cual fue generado.

Nota: El directorio especificado por la opción -d no se añade automáticamente a su ruta de clases de usuario.

-deprecation

Muestra una descripción de cada uso o anulación de un miembro o clase en desuso. Sin la opción -deprecation, javac muestra un resumen de los archivos fuente que usan o anulan miembros o clases en desuso. La opción -deprecation es una abreviatura de -Xlint:deprecation.
-encoding codificación

Establece el nombre de codificación del archivo fuente, como EUC-JP y UTF-8. Si la opción -encoding no se especifica, entonces se utiliza el conversor predeterminado de la plataforma.
-endorseddirs directorios

Anula la ubicación de la ruta de estándares avalados.
-extdirs directorios

Anula la ubicación del directorio ext. La variable de directorios es una lista de directorios separada por dos puntos. Cada archivo JAR en los directorios especificados se busca para encontrar archivos de clase. Todos los archivos JAR encontrados forman parte de la ruta de clases.

Si está compilando de forma cruzada (compilando clases contra clases de arranque y de extensión de una implementación diferente de la plataforma Java), entonces esta opción especifica los directorios que contienen las clases de extensión. Ver Opciones de Compilación Cruzada para más información.

-g

Genera toda la información de depuración, incluyendo variables locales. Por defecto, solo se genera información de número de línea y archivo fuente.
-g:none

No genera ninguna información de depuración.
-g:[lista de palabras clave]

Genera solo algunos tipos de información de depuración, especificados por una lista de palabras clave separadas por comas. Las palabras clave válidas son:
source
Información de depuración del archivo fuente.
lines
Información de depuración del número de línea.
vars
Información de depuración de variables locales.
-help

Imprime una sinopsis de las opciones estándar.
-implicit:[clase, ninguna]

Controla la generación de archivos de clase para archivos fuente cargados implícitamente. Para generar archivos de clase automáticamente, use -implicit:class. Para suprimir la generación de archivos de clase, use -implicit:none. Si esta opción no se especifica, entonces el valor predeterminado es generar archivos de clase automáticamente. En este caso, el compilador emite una advertencia si se generan dichos archivos de clase al realizar también procesamiento de anotaciones. La advertencia no se emite cuando la opción -implicit se establece explícitamente. Ver Búsqueda de Tipos.

PROCESAMIENTO DE

ANOTACIONES

El comando javac proporciona soporte directo para el procesamiento de anotaciones, superando la necesidad del comando separado de procesamiento de anotaciones, apt

.

La API para los procesadores de anotaciones está definida en los paquetes javax.annotation.processing y javax.lang.model y sus

subpaquetes.

CÓMO FUNCIONA EL PROCESAMIENTO DE

ANOTACIONES

A menos que el procesamiento de anotaciones esté deshabilitado con la opción -proc:none, el compilador busca cualquier procesador de anotaciones que esté disponible. La ruta de búsqueda se puede especificar con la opción -processorpath. Si no se especifica ninguna ruta, se utiliza la ruta de clases del usuario. Los procesadores se localizan por medio de archivos de configuración de proveedores de servicio llamados META-INF/services/javax.annotation.processing.Processor en la ruta de búsqueda. Dichos archivos deben contener los nombres de los procesadores de anotaciones a usar, listados uno por línea. Alternativamente, los procesadores se pueden especificar explícitamente, usando la opción -proc

essor.

Después de escanear los archivos fuente y clases en la línea de comandos para determinar qué anotaciones están presentes, el compilador consulta a los procesadores para determinar qué anotaciones procesan. Cuando se encuentra una coincidencia, se llama al procesador. Un procesador puede reclamar las anotaciones que procesa, en cuyo caso no se hace ningún intento adicional de encontrar procesadores para esas anotaciones. Después de que todas las anotaciones son reclamadas, el compilador no busca procesadores

adicionales.

Si algún procesador genera nuevos archivos fuente, se produce otra ronda de procesamiento de anotaciones: Se escanean los archivos fuente recién generados y se procesan las anotaciones como antes. Los procesadores llamados en rondas anteriores también se llaman en todas las rondas posteriores. Esto continúa hasta que no se generen nuevos archivos

fuente.

Después de una ronda en la que no se generan nuevos archivos fuente, se llaman a los procesadores de anotaciones una última vez, para darles la oportunidad de completar cualquier trabajo restante. Finalmente, a menos que la opción -proc:only sea usada, el compilador compila

los archivos fuente origin
ales y todos los generados.

BÚSQUEDA DE

TIPOS

Para compilar un archivo fuente, el compilador a menudo necesita información sobre un tipo, pero la definición del tipo no está en los archivos fuente especificados en la línea de comandos. El compilador necesita información de tipo para cada clase o interfaz usada, extendida o implementada en el archivo fuente. Esto incluye clases e interfaces no mencionadas explícitamente en el archivo fuente, pero que proporcionan información a través de la

herencia.

Por ejemplo, cuando creas una subclase de java.applet.Applet, también estás usando las clases ancestro de Applet: java.awt.Panel, java.awt.Container, java.awt.Component, y java.lang.O

bject.

Cuando el compilador necesita información de tipo, busca un archivo fuente o un archivo de clase que defina el tipo. El compilador busca los archivos de clase primero en las clases de arranque y de extensión, luego en la ruta de clases del usuario (que por defecto es el directorio actual). La ruta de clases del usuario se define configurando la variable de entorno CLASSPATH o usando la opción -clas

spath.

Si configuras la opción -sourcepath, el compilador busca en la ruta indicada archivos fuente. De lo contrario, el compilador busca en la ruta de clases del usuario tanto archivos de clase como archivos

fuente.

Puedes especificar clases de arranque o de extensión diferentes con las opciones -bootclasspath y -extdirs. Ver Opciones de Compilación

Cruzada.

Una búsqueda de tipos exitosa puede producir un archivo de clase, un archivo fuente, o ambos. Si se encuentran ambos, puedes usar la opción -Xprefer para indicar al compilador cuál usar. Si se especifica newer, el compilador usa el más reciente de los dos archivos. Si se especifica source, el compilador usa el archivo fuente. El valor por defecto es newer

.

Si una búsqueda de tipos encuentra un archivo fuente para un tipo requerido, ya sea por sí mismo, o como resultado de la configuración de la opción -Xprefer, el compilador lee el archivo fuente para obtener la información que necesita. Por defecto, el compilador también compila el archivo fuente. Puedes usar la opción -implicit para especificar el comportamiento. Si se especifica none, no se generan archivos de clase para el archivo fuente. Si se especifica class, se generan archivos de clase para el archivo

fuente.

El compilador podría no descubrir la necesidad de alguna información de tipo hasta que se complete el procesamiento de anotaciones. Cuando la información de tipo se encuentra en un archivo fuente y no se especifica la opción -implicit, el compilador emite una advertencia de que el archivo se está compilando sin estar sujeto al procesamiento de anotaciones. Para deshabilitar la advertencia, especifica el archivo en la línea de comandos (para que esté sujeto al procesamiento de anotaciones) o usa la opción -implicit para especificar si se deben gene

rar o no archivos de clase p
ara dichos archivos fuente.

Ejemplo 4 Separar archivos fuente y archivos de clase

El siguiente ejemplo utiliza javac para compilar código que se ejecuta en JVM 1.7.

javac -source 1.7 -target 1.7 -bootclasspath jdk1.7.0/lib/rt.jar \
-extdirs "" OldCode.java

La opción -source 1.7 especifica que la versión 1.7 (o 7) del lenguaje de programación Java se utilizará para compilar OldCode.java. La opción -target 1.7 asegura que los archivos de clase generados sean compatibles con JVM 1.7. Tenga en cuenta que en la mayoría de los casos, el valor de la opción -target es el valor de la opción -source; en este ejemplo, puede omitir la opción -target.

Debe especificar la opción -bootclasspath para especificar la versión correcta de las clases de arranque (la biblioteca rt.jar). Si no lo hace, el compilador generará una advertencia:

javac -source 1.7 OldCode.java
warning: [options] bootstrap class path not set in conjunction with
-source 1.7

Si no especifica la versión correcta de las clases de arranque, el compilador utiliza las reglas del lenguaje antiguo (en este ejemplo, utiliza la versión 1.7 del lenguaje de programación Java) combinadas con las clases de arranque nuevas, lo que puede dar lugar a archivos de clase que no funcionan en la plataforma anterior (en este caso, Java SE 7) porque se pueden incluir referencias a métodos inexistentes.
