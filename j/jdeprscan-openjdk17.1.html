JDEPRSCAN(1) Comandos JDK JDEPRSCAN(1)

NOMBRE

jdeprscan - herramienta de análisis estático que escanea un archivo jar (o alguna otra agregación de archivos de clase) en busca de usos de elementos de API obsoletos

SINOPSIS

jdeprscan [opciones] {dir|jar|clase}

opciones
Ver Opciones para el comando jdeprscan
dir|jar|clase
jdeprscan escanea cada argumento en busca de usos de APIs obsoletas. Los argumentos pueden ser:
•
dir: Directorio
•
jar: Archivo JAR
•
clase: Nombre de clase o archivo de clase

El nombre de clase debe usar un punto (.) como separador. Por ejemplo:

java.lang.Thread

Para clases anidadas, se debe usar el carácter separador de signo de dólar $. Por ejemplo:

java.lang.Thread$State

También se puede nombrar un archivo de clase. Por ejemplo:

build/classes/java/lang/Thread$State.class

DESCRIPCIÓN

La herramienta jdeprscan es una herramienta de análisis estático proporcionada por el JDK que escanea un archivo JAR o alguna otra agregación de archivos de clase en busca de usos de elementos de API obsoletos. Las APIs obsoletas identificadas por la herramienta jdeprscan son solo aquellas definidas por Java SE. Las APIs obsoletas definidas por bibliotecas de terceros no se reportan.

Para escanear un archivo JAR o un conjunto de archivos de clase, primero debe asegurarse de que todas las clases de las que dependen las clases escaneadas estén presentes en la ruta de clases. Establezca la ruta de clases utilizando la opción --class-path descrita en Opciones para el comando jdeprscan. Típicamente, utilizaría la misma ruta de clases que la que utiliza al invocar su aplicación.

Si jdeprscan no puede encontrar todas las clases dependientes, generará un mensaje de error para cada clase faltante. Estos mensajes de error suelen tener el formato:

error: no se puede encontrar la clase ...

Si ocurren estos errores, debe ajustar la ruta de clases para que incluya todas las clases dependientes.

OPCIONES PARA EL COMANDO JDEPRSCAN

Las siguientes opciones están disponibles:

--class-path ruta
Proporciona una ruta de búsqueda para la resolución de clases dependientes.

ruta puede ser una ruta de búsqueda que consiste en uno o más directorios separados por el separador de rutas específico del sistema. Por ejemplo:

•
Linux y OS X:

--class-path /algún/directorio:/otro/directorio/diferente

Nota:

En Windows, use un punto y coma ; como separador en lugar de dos puntos :.

•
Windows:

--class-path \algún\directorio;\otro\directorio\diferente

--for-removal
Limita el escaneo o listado a APIs que están obsoletas para su eliminación. No se puede usar con un valor de lanzamiento de 6, 7 u 8.
--full-version
Imprime la cadena de versión completa de la herramienta.
--help o -h
Imprime un mensaje de ayuda completo.
--list o -l
Imprime el conjunto de APIs obsoletas. No se realiza ningún escaneo, por lo que no se deben proporcionar argumentos de directorio, jar o clase.
--release 6|7|8|9
Especifica la versión de Java SE que proporciona el conjunto de APIs obsoletas para el escaneo.
--verbose o -v
Habilita la salida de mensajes adicionales durante el procesamiento.
--version
Imprime la cadena de versión abreviada de la herramienta.

EJEMPLO DE SALIDA DE JDEPRSCAN

El archivo JAR para esta biblioteca se llamará algo similar a commons-math3-3.6.1.jar. Para escanear este archivo JAR en busca del uso de APIs obsoletas, ejecute el siguiente comando:

jdeprscan commons-math3-3.6.1.jar

Este comando produce varias líneas de salida. Por ejemplo, una línea de salida podría ser:


la clase org/apache/commons/math3/util/MathUtils usa el método obsoleto java/lang/Double::<init>(D)V

Nota:

El nombre de la clase se especifica utilizando el nombre binario separado por barras como se describe en JVMS 4.2.1. Esta es la forma utilizada internamente en los archivos de clase.

La API obsoleta que utiliza es un método en la clase java.lang.Double.

El nombre del método obsoleto es <init>, que es un nombre especial que significa que el método es en realidad un constructor. Otro nombre especial es <clinit>, que indica un inicializador estático de clase.

Otros métodos se enumeran solo por su nombre de método. Después del nombre del método viene la lista de argumentos y el tipo de retorno:

(D)V

Esto indica que toma solo un valor double (un primitivo) y devuelve void. Los tipos de argumento y retorno pueden volverse crípticos. Por ejemplo, otra línea de salida podría ser:


la clase org/apache/commons/math3/util/Precision usa el método obsoleto java/math/BigDecimal::setScale(II)Ljava/math/BigDecimal;

En esta línea de salida, el método obsoleto está en la clase java.math.BigDecimal, y el método es setScale(). En este caso, (II) significa que toma dos argumentos int. El Ljava/math/BigDecimal; después de los paréntesis significa que devuelve una referencia a java.math.BigDecimal.

        DESCRIPTION
      

      
The jdeprscan utility is a command-line
          tool that scans the given class files, archives, or directories for
          uses of deprecated APIs.

      
It checks the specified classname or
          all classes found in the specified classpath for
          uses of deprecated APIs.

      
The deprecated API scanner can be version-specific. It checks
          for uses of deprecated APIs that were deprecated in or before the
          specified release value. For example, if
          release is set to 8, jdeprscan
          reports uses of APIs deprecated in Java SE 5, Java SE 6, Java SE 7,
          and Java SE 8.

      
If jdeprscan finds deprecated APIs, it
          reports them to standard output.

    

    

      

        OPTIONS FOR THE JDEPRSCAN COMMAND
      

      
The options are as follows:

      

        
--class-path

        
Specifies the search path for application classes and resources.
          This overrides the default class path location of the application.

        

          --release
          release
Checks for uses of deprecated APIs that were deprecated in or before the specified release value. The default value is the current platform release.
--fail-on-deprecated =all|usage|none
Exits with a non-zero status if deprecated APIs are found.
all
Exits with a non-zero status if any deprecated API is used.
usage
Exits with a non-zero status if any deprecated API is used, except those deprecated before the specified release.
none
Does not exit with a non-zero status.
--enable-preview
Enables preview language features for the preview language features of the specified release.
--release release
Compiles against the specified API release.
--source release
Specifies the source code version of the features to be used in compilation.
--{-Xlint[:all[,key]] | all[-key]}
Enables additional diagnostic messages. The default is to show all messages.
--help
Prints a help message and exits.
--module-path modulepath
Location of modular Jars and directories of uncompiled modular class files and resources.
--patch-module module = file
Overrides classes in a given module with variants in file.
--module module
The name of the module to process.
--module-source-path modulepath
Location of source files in named modules.
--upgrade-module-path modulepath
Location of modular Jars and directories of uncompiled modular class files and resources that replace the modules in the runtime image.

EXAMPLE OF JDEPRSCAN OUTPUT

Consider the following Java class:

package example;
import java.rmi.RMISecurityManager;
public class Deprecations {
  public static void main(String[] args) {
    new RMISecurityManager();    // deprecated in 8
    new Boolean(true);          // deprecated in 9
  }
}

The complete class compiles without warnings in JDK 7.

If you run jdeprscan on a system with JDK 9, then you see:


$ jdeprscan --class-path classes --release 7 example.Deprecations
(no output)

Run jdeprscan with a release value of 8:


$ jdeprscan --class-path classes --release 8 example.Deprecations
class example/Deprecations uses type java/rmi/RMISecurityManager deprecated
class example/Deprecations uses method in type java/rmi/RMISecurityManager deprecated

Run jdeprscan on JDK 9:


$ jdeprscan --class-path classes example.Deprecations
class example/Deprecations uses type java/rmi/RMISecurityManager deprecated
class example/Deprecations uses method in type java/rmi/RMISecurityManager deprecated
class example/Deprecations uses method java/lang/Boolean <init> (Z)V deprecated

JDEPRSCAN ANALYSIS CAN BE VERSION-SPECIFIC

The jdeprscan tool identifies usages of APIs that have been deprecated. The set of deprecated APIs depends on the Java SE release against which the code is being compiled or analyzed.

For example, RMISecurityManager was deprecated in Java SE 8. The constructor Boolean(boolean) was deprecated in Java SE 9.

When jdeprscan is run with --release 8, it identifies uses of APIs that were deprecated in or before Java SE 8. This includes the usage of RMISecurityManager.

When jdeprscan is run without the --release option (or with a release value of 9 or later), it identifies uses of APIs deprecated in or before the default release. This includes both RMISecurityManager and the Boolean(boolean) constructor.
