NOMBRE

jdb - Encuentra y corrige errores en programas de la plataforma Java.

SINOPSIS

jdb [opciones] [nombreclase] [argumentos]
opciones
Opciones de línea de comandos. Ver Opciones.
nombreclase
Nombre de la clase principal a depurar.
argumentos
Argumentos pasados al método main() de la clase.

DESCRIPCIÓN

El depurador de Java (JDB) es un depurador simple de línea de comandos para clases de Java. El comando jdb y sus opciones llaman a JDB. El comando jdb demuestra la Arquitectura de Depuración de la Plataforma Java (JDBA) y proporciona inspección y depuración de una máquina virtual Java (JVM) local o remota. Ver Arquitectura de Depuración de la Plataforma Java (JDBA) en http://docs.oracle.com/javase/8/docs/technotes/guides/jpda/index.html

INICIAR UNA SESIÓN DE JDB

Hay muchas formas de iniciar una sesión de JDB. La forma más utilizada es hacer que JDB inicie una nueva JVM con la clase principal de la aplicación a depurar. Haz esto sustituyendo el comando jdb por el comando java en la línea de comandos. Por ejemplo, si la clase principal de tu aplicación es MiClase, entonces usa el siguiente comando para depurarla bajo JDB:

jdb MiClase

Cuando se inicia de esta manera, el comando jdb llama a una segunda JVM con los parámetros especificados, carga la clase especificada y detiene la JVM antes de ejecutar la primera instrucción de esa clase.

Otra forma de usar el comando jdb es adjuntándolo a una JVM que ya se está ejecutando. La sintaxis para iniciar una JVM a la que el comando jdb se adjunta cuando la JVM está en ejecución es la siguiente. Esto carga bibliotecas de depuración en proceso y especifica el tipo de conexión que se va a realizar.

java -agentlib:jdwp=transport=dt_socket,server=y,suspend=n MiClase

Luego puedes adjuntar el comando jdb a la JVM con el siguiente comando:

jdb -attach 8000

El argumento MiClase no se especifica en la línea de comandos jdb en este caso porque el comando jdb se está conectando a una JVM existente en lugar de iniciar una nueva JVM.

Hay muchas otras formas de conectar el depurador a una JVM, y todas ellas están soportadas por el comando jdb. La Arquitectura de Depuración de la Plataforma Java tiene documentación adicional sobre estas opciones de conexión.

COMANDOS BÁSICOS DE JDB

La siguiente es una lista de los comandos básicos de jdb. JDB soporta otros comandos que puedes listar con la opción -help.

help o ?
Los comandos help o ? muestran la lista de comandos reconocidos con una breve descripción.
run
Después de iniciar JDB y establecer puntos de interrupción, puedes usar el comando run para ejecutar la aplicación depurada. El comando run solo está disponible cuando el comando jdb inicia la aplicación depurada en lugar de adjuntarse a una JVM existente.
cont
Continúa la ejecución de la aplicación depurada después de un punto de interrupción, una excepción o un paso.
print
Muestra objetos Java y valores primitivos. Para variables o campos de tipos primitivos, se imprime el valor real. Para objetos, se imprime una breve descripción. Ver el comando dump para saber cómo obtener más información sobre un objeto.

Nota: Para mostrar variables locales, la clase contenedora debe haber sido compilada con la opción javac -g.

El comando print soporta muchas expresiones Java simples, incluyendo aquellas con invocaciones de métodos, por ejemplo:

print MiClase.miCampoEstatico
print miObj.miCampoInstancia
print i + j + k (i, j, k son primitivos y ya sean campos o variables locales)
print miObj.miMetodo() (si miMetodo devuelve algo que no sea null)
print new java.lang.String("Hola").length()
dump
Para valores primitivos, el comando dump es idéntico al comando print. Para objetos, el comando dump imprime el valor actual de cada campo definido en el objeto. Se incluyen campos estáticos e de instancia. El comando dump soporta el mismo conjunto de expresiones que el comando print.
threads
Lista los hilos que se están ejecutando actualmente. Para cada hilo, se imprime su nombre y estado actual y un índice que se puede usar en otros comandos. En este ejemplo, el índice del hilo es 4, el hilo es una instancia de java.lang.Thread, el nombre del hilo es main y actualmente se está ejecutando. 
4. (java.lang.Thread)0x1 main      running
thread
Selecciona un hilo para que sea el hilo actual. Muchos comandos jdb se basan en la configuración del hilo actual. El hilo se especifica con el índice de hilo descrito en el comando threads.
where
El comando where sin argumentos imprime la pila del hilo actual. El comando whereall imprime la pila de todos los hilos en el grupo de hilos actual. El comando wherethreadindex imprime la pila del hilo especificado.

Si el hilo actual está suspendido, ya sea por un evento como un punto de interrupción o mediante el comando suspend, entonces las variables locales y los campos se pueden mostrar con los comandos print y dump. Los comandos up y down seleccionan qué marco de pila es el marco de pila actual.

PUNTOS DE INTERRUPCIÓN

Los puntos de interrupción se pueden establecer en JDB en números de línea o en la primera instrucción de un método, por ejemplo:

•
El comando stop at MiClase:22 establece un punto de interrupción en la primera instrucción de la línea 22 del archivo fuente que contiene MiClase.
•
El comando stop in java.lang.String.length establece un punto de interrupción al principio del método java.lang.String.length.
•
El comando stop in MiClase.<clinit> usa <clinit> para identificar el código de inicialización estática para MiClase.

Cuando un método está sobrecargado, también debes especificar sus tipos de argumento para que se pueda seleccionar el método correcto para un punto de interrupción. Por ejemplo, MiClase.miMetodo(int,java.lang.String) o MiClase.miMetodo().

El comando clear elimina los puntos de interrupción usando la siguiente sintaxis: clear MiClase:45. Usar el comando clear o stop sin argumentos muestra una lista de todos los puntos de interrupción establecidos actualmente. El comando cont continúa la ejecución.

PASO A PASO

El comando step avanza la ejecución a la siguiente línea, ya sea en el marco de pila actual o en un método llamado. El comando next avanza la ejecución a la siguiente línea en el marco de pila actual.

EXCEPCIONES

Cuando ocurre una excepción para la cual no hay una sentencia catch en la pila de llamadas del hilo que la lanza, la JVM normalmente imprime un rastreo de la excepción y sale. Sin embargo, cuando se ejecuta bajo JDB, el control regresa a JDB en el lanzamiento que causa el problema. Luego puedes usar el comando jdb para diagnosticar la causa de la excepción.

Usa el comando catch para hacer que la aplicación depurada se detenga en otras excepciones lanzadas, por ejemplo: catch java.io.FileNotFoundException o catchmypackage.BigTroubleException. Cualquier excepción que sea una instancia de la clase especificada o de una subclase detiene la a
