jj-evolog(1) Manual de Comandos Generales jj-evolog(1)

NOMBRE

jj-evolog - Muestra cómo un cambio ha evolucionado con el tiempo

SINOPSIS

jj evolog [-r|--revisions] [-n|--limit] [--reversed] [-G|--no-graph] [-T|--template] [-p|--patch] [-s|--summary] [--stat] [--types] [--name-only] [--git] [--color-words] [--tool] [--context] [--ignore-all-space] [--ignore-space-change] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help]

DESCRIPCIÓN

Muestra cómo un cambio ha evolucionado con el tiempo

Lista los commits previos a los que un cambio ha apuntado. El commit actual de un cambio evoluciona cuando el cambio se actualiza, se reorganiza, etc.

OPCIONES

-r, --revisions <REVSETS> [predeterminado: @]
Seguir cambios desde estas revisiones
-n, --limit <LIMIT>
Limitar el número de revisiones a mostrar

Aplicado después de que las revisiones se reordenen topológicamente, pero antes de invertirse.

--reversed
Mostrar revisiones en orden opuesto (primeras revisiones más antiguas)
-G, --no-graph
No mostrar el gráfico, mostrar una lista plana de revisiones
-T, --template <TEMPLATE>
Renderizar cada revisión usando la plantilla dada

Todos los métodos sin argumentos del tipo [`CommitEvolutionEntry`] están disponibles como palabras clave en la expresión de la plantilla. Consulta [`jj help -k templates`] para más información.

Si no se especifica, esto usa por defecto la configuración `templates.evolog`.

[`CommitEvolutionEntry` type]: https://docs.jj-vcs.dev/latest/templates/#commitevolutionentry-type

[`jj help -k templates`]: https://docs.jj-vcs.dev/latest/templates/

-p, --patch
Mostrar parche comparado con la versión anterior de este cambio

Si la versión anterior tiene padres diferentes, se reorganizará temporalmente a los padres de la nueva versión, de modo que la diferencia no se vea contaminada por cambios no relacionados.

-h, --help
Imprimir ayuda (ver un resumen con '-h')

OPCIONES DE FORMATO DE DIFERENCIA

-s, --summary
Para cada ruta, mostrar solo si fue modificada, añadida o eliminada
--stat
Mostrar un histograma de los cambios
--types
Para cada ruta, mostrar solo su tipo antes y después

La diferencia se muestra como dos letras. La primera letra indica el tipo anterior y la segunda letra indica el tipo posterior. '-' indica que la ruta no estaba presente, 'F' representa un archivo normal, `L' representa un enlace simbólico, 'C' representa un conflicto y 'G' representa un submódulo de Git.

--name-only
Para cada ruta, mostrar solo su ruta

Típicamente útil para comandos de shell como: `jj diff -r @- --name-only | xargs perl -pi -e's/OLD/NEW/g`

--git
Mostrar una diferencia en formato Git
--color-words
Mostrar una diferencia a nivel de palabra con cambios indicados solo por color
--tool <TOOL>
Generar diferencia mediante un comando externo

También se puede especificar un formato incorporado como `:<nombre>`. Por ejemplo, `--tool=:git` es equivalente a `--git`.

--context <CONTEXT>
Número de líneas de contexto a mostrar
--ignore-all-space
Ignorar espacios en blanco al comparar líneas
--ignore-space-change
Ignorar cambios en la cantidad de espacios en blanco al comparar líneas

OPCIONES GLOBALES

-R, --repository <REPOSITORY>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No capturar una instantánea del directorio de trabajo, y no actualizarlo

Por defecto, Jujutsu captura una instantánea del directorio de trabajo al inicio de cada comando. El directorio de trabajo también se actualiza al final del comando, si el comando modificó el commit del directorio de trabajo (`@`). Si desea evitar capturar una instantánea del directorio de trabajo y en su lugar ver un commit del directorio de trabajo posiblemente obsoleto, puede usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tiene otro proceso que confirma el directorio de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu evita reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y le permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta al revset `immutable_heads()` ni a la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puede usar `--at-op=<ID de operación>` para ver cómo se veía el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` le mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de terminar. `--at-op=@` es prácticamente lo mismo que el predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Use `jj op log` para encontrar el ID de operación que desea. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignorará el directorio de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutantes al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes a partir de la operación anterior. Rara vez hay una razón para hacer eso, pero es posible.

--debug
Habilitar registro de depuración
--color <WHEN>
Cuándo colorear la salida

[posibles valores: always, never, debug, auto]

--quiet
Silenciar la salida no principal del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no le dirá si se capturó una instantánea del directorio de trabajo o si los descendientes fueron reorganizados.

Las advertencias y los errores seguirán imprimiéndose.

--no-pager
Deshabilitar el paginador
--config <NAME=VALUE>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como k con puntos de TOML

es. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado por ninguna construcción TOML (como la notación de matriz), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se puede repetir)
