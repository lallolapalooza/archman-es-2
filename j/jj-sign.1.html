NOMBRE

jj-sign - Firma criptográficamente una revisión

SINOPSIS

jj sign [-r|--revisions] [--key] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help]

DESCRIPCIÓN

Firma criptográficamente una revisión

Este comando requiere configurar un backend de [firma de commits].

[firma de commits]: https://docs.jj-vcs.dev/latest/config/#commit-signing

OPCIONES

-r, --revisions <REVSETS>
Qué revisión(es) firmar

Si no se especifican revisiones, esto usa por defecto la configuración `revsets.sign`.

Tenga en cuenta que las revisiones siempre se vuelven a firmar.

Aunque eso cause incomodidad a los usuarios que firman con dispositivos de hardware, por ahora no podemos verificar de forma fiable si un commit ya está firmado por el usuario sin crear una firma (ver [#5786]).

[#5786]: https://github.com/jj-vcs/jj/issues/5786

--key <CLAVE>
La clave utilizada para firmar
-h, --help
Imprimir ayuda (ver un resumen con '-h')

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio más cercano .jj/ en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No hacer instantánea del directorio de trabajo, ni actualizarlo

Por defecto, Jujutsu hace una instantánea del directorio de trabajo al inicio de cada comando. El directorio de trabajo también se actualiza al final del comando, si el comando modificó el commit del directorio de trabajo (`@`). Si desea evitar hacer instantáneas del directorio de trabajo y en su lugar ver un commit del directorio de trabajo posiblemente obsoleto, puede usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en un prompt de comando, especialmente si tiene otro proceso que confirma el directorio de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu previene la reescritura de commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y le permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repo

Operación en la que cargar el repo. Por defecto, Jujutsu carga el repo en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puede usar `--at-op=<ID de operación>` para ver cómo era el repo en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` le mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor por defecto, excepto que las operaciones divergentes nunca se fusionarán.

Use `jj op log` para encontrar el ID de operación que desea. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repo en una operación anterior, se ignorará el directorio de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutantes al cargar el repo en una operación anterior. Hacer eso es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilitar registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[valores posibles: always, never, debug, auto]

--quiet
Silenciar la salida no principal del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no le dirá si se hizo una instantánea del directorio de trabajo o si los descendientes fueron rebasados.

Las advertencias y errores seguirán imprimiéndose.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se puede repetir)

El nombre debe especificarse como claves puntuales de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado por ninguna construcción de TOML (como la notación de array), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se puede repetir)
