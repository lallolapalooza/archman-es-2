NOMBRE

javac - lee declaraciones Java y las compila en archivos de clase

SINOPSIS

javac [opciones] [archivos_fuente_o_nombres_clase]

opciones
Opciones de línea de comandos.
archivos_fuente_o_nombres_clase
Archivos fuente a compilar (por ejemplo, Shape.java) o los nombres de clases compiladas previamente a procesar para anotaciones (por ejemplo, geometry.MyShape).

DESCRIPCIÓN

El comando javac lee archivos fuente que contienen declaraciones de módulos, paquetes y tipos escritas en el lenguaje de programación Java, y las compila en archivos de clase que se ejecutan en la Máquina Virtual Java.

El comando javac también puede procesar anotaciones en archivos fuente y clases Java.

Los archivos fuente deben tener una extensión de nombre de archivo de .java. Los archivos de clase tienen una extensión de nombre de archivo de .class. Tanto los archivos fuente como los de clase normalmente tienen nombres de archivo que identifican el contenido. Por ejemplo, una clase llamada Shape se declararía en un archivo fuente llamado Shape.java y se compilaría en un archivo de clase llamado Shape.class.

Hay dos formas de especificar archivos fuente a javac:

•
Para un pequeño número de archivos fuente, puedes listar sus nombres de archivo en la línea de comandos.
•
Para un gran número de archivos fuente, puedes usar la opción @nombre_archivo en la línea de comandos para especificar un archivo de argumentos que liste sus nombres de archivo. Consulta Opciones Estándar para una descripción de la opción y Archivos de Argumentos de Línea de Comandos para una descripción de los archivos de argumentos de javac.

El orden de los archivos fuente especificados en la línea de comandos o en un archivo de argumentos no es importante. javac compilará los archivos juntos, como un grupo, y resolverá automáticamente cualquier dependencia entre las declaraciones en los diversos archivos fuente.

javac espera que los archivos fuente estén organizados en una o más jerarquías de directorios en el sistema de archivos, descritas en Organización del Código Fuente.

Para compilar un archivo fuente, javac necesita encontrar la declaración de cada clase o interfaz que sea utilizada, extendida o implementada por el código en el archivo fuente. Esto permite a javac verificar que el código tiene derecho a acceder a esas clases e interfaces. En lugar de especificar explícitamente los archivos fuente de esas clases e interfaces, puedes usar opciones de línea de comandos para indicar a javac dónde buscar sus archivos fuente. Si has compilado esos archivos fuente previamente, puedes usar opciones para indicarle a javac dónde buscar los archivos de clase correspondientes. Las opciones, cuyos nombres terminan en "path", se describen en Opciones Estándar, y se describen más a fondo en Configuración de una Compilación y Búsqueda de Declaraciones de Módulos, Paquetes y Tipos.

Por defecto, javac compila cada archivo fuente en un archivo de clase en el mismo directorio que el archivo fuente. Sin embargo, se recomienda especificar un directorio de destino separado con la opción -d.

Las opciones de línea de comandos y las variables entorno también controlan cómo javac realiza diversas tareas:

•
Compilar código para ejecutar en versiones anteriores del JDK.
•
Compilar código para ejecutar bajo un depurador.
•
Verificar problemas de estilo en el código fuente Java.
•
Verificar problemas en comentarios de javadoc (/** ... */).
•
Procesar anotaciones en archivos fuente y de clase.
•
Actualizar y parchear módulos en el entorno de tiempo de compilación.

javac soporta Compilación para Versiones Anteriores de la Plataforma y también puede ser invocado desde código Java usando una de varias APIs

OPCIONES

javac proporciona opciones estándar y opciones adicionales que son no estándar o para uso avanzado.

Algunas opciones toman uno o más argumentos. Si un argumento contiene espacios u otros caracteres de espacio en blanco, el valor debe ser citado según las convenciones del entorno que se esté utilizando para invocar javac. Si la opción comienza con un guion simple (-) el argumento debe seguir directamente el nombre de la opción, o estar separado por dos puntos (:) o espacio en blanco, dependiendo de la opción. Si la opción comienza con un doble guion (--), el argumento puede separarse por espacio en blanco o por un carácter de igual (=) sin espacio adicional. Por ejemplo,


-Aname="J. Duke"
-proc:only
-d miDirectorio
--module-version 3
--module-version=3

En las siguientes listas de opciones, un argumento de ruta representa una ruta de búsqueda, compuesta por una lista de ubicaciones del sistema de archivos separadas por el carácter separador de ruta de la plataforma, (punto y coma ; en Windows, o dos puntos : en otros sistemas.) Dependiendo de la opción, las ubicaciones del sistema de archivos pueden ser directorios, archivos JAR o archivos JMOD.

Opciones Estándar

@nombre_archivo
Lee opciones y nombres de archivo desde un archivo. Para acortar o simplificar el comando javac, puedes especificar uno o más archivos que contengan argumentos para el comando javac (excepto las opciones -J). Esto te permite crear comandos de javac de cualquier longitud en cualquier sistema operativo. Consulta Archivos de Argumentos de Línea de Comandos.
-Aclave[=valor]
Especifica opciones para pasar a los procesadores de anotaciones. Estas opciones no son interpretadas directamente por javac, sino que se ponen a disposición para su uso por procesadores individuales. El valor de clave debe ser uno o más identificadores separados por un punto (.).
--add-modules módulo,módulo
Especifica los módulos raíz a resolver además de los módulos iniciales, o todos los módulos en la ruta de módulos si módulo es ALL-MODULE-PATH.
--boot-class-path ruta o -bootclasspath ruta
Anula la ubicación de los archivos de clase de arranque.

Nota: Esto solo se puede usar al compilar para versiones anteriores a JDK 9. Según corresponda, consulta las descripciones en --release, -source, o -target para obtener detalles. Para JDK 9 o posterior, consulta --system.

--class-path ruta, -classpath ruta, o -cp ruta
Especifica dónde encontrar los archivos de clase de usuario y los procesadores de anotaciones. Esta ruta de clases anula la ruta de clases de usuario en el
variable de entorno CLASSPATH.
•
Si no se especifican --class-path, -classpath o -cp, la ruta de clases del usuario es el valor de la variable de entorno CLASSPATH, si está establecida, o el directorio actual.
•
Si no se está compilando código para módulos, si la opción --source-path o -sourcepath` no se especifica, entonces la ruta de clases del usuario también se busca para archivos fuente.
•
Si no se especifica la opción -processorpath, entonces la ruta de clases también se busca para procesadores de anotaciones.
-d directorio
Establece el directorio de destino (o directorio de salida de clases) para los archivos de clase. Si una clase forma parte de un paquete, javac coloca el archivo de clase en un subdirectorio que refleja el nombre del módulo (si procede) y el nombre del paquete. El directorio, y cualquier subdirectorio necesario, se creará si no existe.

Si no se especifica la opción -d, entonces javac coloca cada archivo de clase en el mismo directorio que el archivo fuente del cual se generó.

Excepto cuando se compila código para múltiples módulos, el contenido del directorio de salida de clases se organizará en una jerarquía de paquetes. Al compilar código para múltiples módulos, el contenido del directorio de salida se organizará en una jerarquía de módulos, con el contenido de cada módulo en un subdirectorio separado, cada uno organizado como una jerarquía de paquetes.

Nota: Al compilar código para uno o más módulos, el directorio de salida de clases se verificará automáticamente al buscar clases compiladas previamente. Al no compilar para módulos, por compatibilidad con versiones anteriores, el directorio no se verifica automáticamente en busca de clases compiladas previamente, por lo que se recomienda especificar el directorio de salida de clases como una de las ubicaciones en la ruta de clases del usuario, utilizando la opción --class-path o una de sus formas alternativas.

-deprecation
Muestra una descripción de cada uso o anulación de un miembro o clase obsoleta. Sin la opción -deprecation, javac muestra un resumen de los archivos fuente que utilizan o anulan miembros o clases obsoletas. La opción -deprecation es un atajo para -Xlint:deprecation.
--enable-preview
Habilita las características del lenguaje de vista previa. Se utiliza en conjunción con -source o --release.
-encoding codificación
Especifica la codificación de caracteres utilizada por los archivos fuente, como EUC-JP y UTF-8. Si no se especifica la opción -encoding, se utiliza el convertidor predeterminado de la plataforma.
-endorseddirs directorios
Anula la ubicación de la ruta de estándares respaldados.

Nota: Esto solo se puede usar al compilar para versiones anteriores a JDK 9. Según corresponda, consulte las descripciones en --release, -source o -target para obtener más detalles.

-extdirs directorios
Anula la ubicación de las extensiones instaladas. directorios es una lista de directorios, separados por el separador de ruta de la plataforma (; en Windows y : en otros sistemas). Cada archivo JAR en los directorios especificados se busca en busca de archivos de clase. Todos los archivos JAR encontrados forman parte de la ruta de clases.

Si está compilando para una versión de la plataforma que admite el Mecanismo de Extensiones, entonces esta opción especifica los directorios que contienen las clases de extensión. Consulte [Compilación para otras versiones de la plataforma].

Nota: Esto solo se puede usar al compilar para versiones anteriores a JDK 9. Según corresponda, consulte las descripciones en --release, -source o -target para obtener más detalles.

-h directorio
Especifica dónde colocar los archivos de cabecera nativos generados.

Cuando se especifica esta opción, se genera un archivo de cabecera nativo para cada clase que contiene métodos nativos o que tiene una o más constantes anotadas con la anotación java.lang.annotation.Native. Si la clase forma parte de un paquete, el compilador coloca el archivo de cabecera nativo en un subdirectorio que refleja el nombre del módulo (si procede) y el nombre del paquete. El directorio, y cualquier subdirectorio necesario, se creará si no existe previamente.

CONFIGURACIÓN DEL SISTEMA DE MÓDULOS

Si desea incluir módulos adicionales en su compilación, utilice la opción --add-modules. Esto puede ser necesario cuando está compilando código que no está en un módulo, o que está en un módulo automático, y el código hace referencia a API en los módulos adicionales.

Si desea restringir el conjunto de módulos en su compilación, utilice la opción --limit-modules. Esto puede ser útil si desea asegurarse de que el código que está compilando es capaz de ejecutarse en un sistema con un conjunto limitado de módulos instalados.

Si desea romper la encapsulación y especificar que paquetes adicionales deben considerarse exportados desde un módulo, utilice la opción --add-exports. Esto puede ser útil al realizar pruebas de caja blanca; se desaconseja encarecidamente depender del acceso a API internas en el código de producción.

Si desea especificar que paquetes adicionales deben considerarse requeridos por un módulo, utilice la opción --add-reads. Esto puede ser útil al realizar pruebas de caja blanca; se desaconseja encarecidamente depender del acceso a API internas en el código de producción.

Puede parchear contenido adicional en cualquier módulo utilizando la opción --patch-module. Consulte [Parchear un Módulo] para obtener más detalles.

BÚSQUEDA DE DECLARACIONES DE MÓDULOS, PAQUETES Y TIPOS

Para compilar un archivo fuente, el compilador a menudo necesita información sobre un módulo o tipo, pero la declaración no se encuentra en los archivos fuente especificados en la línea de comandos.

javac necesita información de tipo para cada clase o interfaz utilizada, extendida o implementada en el archivo fuente. Esto incluye clases e interfaces no mencionadas explícitamente en el archivo fuente, pero que proporcionan información a través de la herencia.

Por ejemplo, al crear una subclase de java.awt.Window, también está utilizando las clases ancestras de Window: java.awt.Container, java.awt.Component y java.lang.Object.

Al compilar código para un módulo, el compilador también necesita tener disponible la declaración de ese módulo.

Una búsqueda exitosa puede producir un archivo de clase, un archivo fuente, o ambos. Si se encuentran ambos, puede usar la opción -Xprefer para indicar al compilador cuál usar.

Si una búsqueda encuentra y utiliza un archivo fuente, entonces, por defecto, javac compila ese archivo fuente. Este comportamiento se puede modificar con -implicit.

El compilador podría no descubrir la necesidad de cierta información de tipo hasta después de que finalice el procesamiento de anotaciones. Cuando la información de tipo se encuentra en un archivo fuente y no se especifica ninguna opción -implicit, el compilador emite una advertencia de que el archivo se está compilando sin estar sujeto al procesamiento de anotaciones. Para desactivar la advertencia, especifique el archivo en la línea de comandos (de modo que esté sujeto al procesamiento de anotaciones) o utilice la opción -implicit para especificar si se deben generar o no archivos de clase para dichos archivos fuente.

La forma en que javac localiza las declaraciones de esos tipos depende de si la referencia existe dentro del código de un módulo o no.

Búsqueda en Rutas Orientadas a Paquetes

Al buscar un archivo fuente o de clase en una ruta compuesta por ubicaciones orientadas a paquetes, javac verificará cada ubicación en la ruta en turno para la posible presencia del archivo. La primera ocurrencia de un archivo particular oculta (esconde) cualquier ocurrencia posterior de archivos con el mismo nombre. Este ocultamiento no afecta la búsqueda de ningún archivo con un nombre diferente. Esto puede ser conveniente al buscar archivos fuente, que pueden agruparse en diferentes ubicaciones, como código compartido, código específico de la plataforma y código generado. También puede ser útil al inyectar versiones alternativas de un archivo de clase en un paquete, para depuración u otras razones de instrumentación. Pero, también puede ser peligroso, como al colocar versiones diferentes e incompatibles de una biblioteca en la ruta de clases.

Búsqueda en Rutas Orientadas a Módulos

Antes de escanear cualquier ruta de módulos para obtener declaraciones de paquetes o tipos, javac escaneará perezosamente las siguientes rutas y ubicaciones para determinar los módulos que se utilizarán en la compilación.

•
La ruta de fuentes de módulos (ver la opción --module-source-path)
•
La ruta para módulos actualizables (ver la opción --upgrade-module-path)
•
Los módulos del sistema (ver la opción --system)
•
La ruta de módulos del usuario (ver la opción --module-path)

Para cualquier módulo, la primera ocurrencia del módulo durante el escaneo oculta completamente (esconde) cualquier aparición posterior de un módulo con el mismo nombre. Al localizar los módulos, javac puede determinar los paquetes exportados por el módulo y asociar a cada módulo una ruta orientada a paquetes para el contenido del módulo. Para cualquier módulo previamente compilado, esta ruta será típicamente una única entrada para un directorio o un archivo que proporcione una jerarquía interna similar a un directorio, como un archivo JAR. Por lo tanto, al buscar un tipo que se encuentra en un paquete que se sabe que está exportado por un módulo, javac puede localizar la declaración de forma directa y eficiente.

JERARQUÍAS DE DIRECTORIOS

javac generalmente asume que los archivos de origen y los archivos de clase compilados se organizarán en una jerarquía de directorios del sistema de archivos o en un tipo de archivo que soporte una jerarquía de directorios interna, como un archivo JAR. Se admiten tres tipos diferentes de jerarquía: una jerarquía de paquetes, una jerarquía de módulos y una jerarquía de origen de módulo.

Si bien javac es bastante flexible con la organización del código fuente, más allá de la expectativa de que el código fuente se organizará en una o varias jerarquías de paquetes, y generalmente puede adaptarse a las organizaciones prescritas por los entornos de desarrollo y las herramientas de compilación, las herramientas de Java en general, y javac y el lanzador de Java en particular, son más estrictos con respecto a la organización de los archivos de clase compilados, y se organizarán en jerarquías de paquetes o jerarquías de módulos, según corresponda.

La ubicación de estas jerarquías se especifica a javac con opciones de línea de comandos, cuyos nombres suelen terminar en "path", como --source-path o --class-path. También, como regla general, las opciones de ruta cuyos nombres incluyen la palabra module, como --module-path, se utilizan para especificar jerarquías de módulos, aunque algunas opciones de ruta relacionadas con módulos permiten especificar una jerarquía de paquetes por módulo. Todas las demás opciones de ruta se utilizan para especificar jerarquías de paquetes.

Jerarquía de Paquetes

En una jerarquía de paquetes, los directorios y subdirectorios se utilizan para representar las partes componentes del nombre del paquete, y el archivo de origen o el archivo de clase compilado para un tipo se almacena como un archivo con la extensión .java o .class en el directorio más anidado.

Por ejemplo, en una jerarquía de paquetes, el archivo de origen para una clase com.example.MyClass se almacenará en el archivo com/example/MyClass.java

Jerarquía de Módulos

En una jerarquía de módulos, el primer nivel de directorios se nombra para los módulos en la jerarquía; dentro de cada uno de esos directorios, el contenido del módulo se organiza en jerarquías de paquetes.

Por ejemplo, en una jerarquía de módulos, el archivo de clase compilado para un tipo llamado com.example.MyClass en un módulo llamado my.library se almacenará en my.library/com/example/MyClass.class.

Los diversos directorios de salida utilizados por javac (el directorio de salida de clases, el directorio de salida de origen y el directorio de salida de encabezados nativos) se organizarán en una jerarquía de módulos cuando se compilen múltiples módulos.

Jerarquía de Origen de Módulos

Aunque el origen de cada módulo individual siempre debe organizarse en una jerarquía de paquetes, puede ser conveniente agrupar esas jerarquías en una jerarquía de origen de módulos. Esto es similar a una jerarquía de módulos, excepto que puede haber directorios intermedios entre el directorio del módulo y el directorio que es la raíz de la jerarquía de paquetes para el código fuente del módulo.

Por ejemplo, en una jerarquía de origen de módulos, el archivo de origen para un tipo llamado com.example.MyClass en un módulo llamado my.library puede almacenarse en un archivo como my.library/src/main/java/com/example/MyClass.java.

LA OPCIÓN --module-source-path

La opción --module-source-path tiene dos formas: una forma específica de módulo, en la que se proporciona una ruta de paquete para cada módulo que contiene código para compilar, y una forma de patrón de módulo, en la que la ruta de origen de cada módulo se especifica mediante un patrón. La forma específica de módulo es generalmente más sencilla de usar cuando solo hay un pequeño número de módulos; la forma de patrón de módulo puede ser más conveniente cuando el número de módulos es grande y los módulos están organizados de manera regular que puede describirse mediante un patrón.

Se pueden proporcionar múltiples instancias de la opción --module-source-path, cada una utilizando la forma de patrón de módulo o la forma específica de módulo, sujeto a las siguientes limitaciones:

•
la forma de patrón de módulo puede usarse como máximo una vez
•
la forma específica de módulo puede usarse como máximo una vez para cualquier módulo dado

Si se utiliza la forma específica de módulo para cualquier módulo, la ruta de búsqueda asociada anula cualquier ruta que de otro modo podría haberse inferido de la forma de patrón de módulo.

Forma específica de módulo

La forma específica de módulo permite proporcionar una ruta de búsqueda explícita para cualquier módulo específico. Esta forma es:

•
--module-source-path nombre-módulo=ruta-archivo (separador-ruta ruta-archivo)*

El carácter separador de ruta es ; en Windows y : en otros sistemas.

Nota: esto es similar a la forma utilizada para la opción --patch-module.

Forma de patrón de módulo

La forma de patrón de módulo permite una especificación concisa de la ruta de origen del módulo para cualquier número de módulos organizados de manera regular.

•
--module-source-path patrón

El patrón se define mediante las siguientes reglas, que se aplican en orden:

•
El argumento se considera una serie de segmentos separados por el carácter separador de ruta (; en Windows y : en otros sistemas).
•
Cada segmento que contenga llaves de la forma

cadena1{alt1 ( ,alt2 )* } cadena2

se considera reemplazado por una serie de segmentos formados al "expandir" las llaves:


cadena1 alt1 cadena2
cadena1 alt2 cadena2
y así sucesivamente...

Las llaves pueden anidarse.

Esta regla se aplica a todos los usos de llaves de este tipo.

•
Cada segmento debe tener como máximo un asterisco (*). Si un segmento no contiene un asterisco, se considera como si se le añadiera el carácter separador de archivo y un asterisco.

Para cualquier módulo M, la ruta de origen para ese módulo se forma a partir de la serie de segmentos obtenidos sustituyendo el nombre del módulo M por el asterisco en cada segmento.

Nota: en este contexto, el asterisco solo se usa como un marcador especial, para indicar la posición en la ruta del nombre del módulo. No debe confundirse con el uso de * como un carácter comodín de nombre de archivo, tal como se encuentra en la mayoría de los sistemas operativos.

MÓDULOS DE PARCHE

javac permite parchear cualquier contenido, ya sea en forma fuente o compilada, en cualquier módulo usando la opción --patch-module. Puede que desee hacer esto para compilar implementaciones alternativas de una clase para parchear en tiempo de ejecución en una JVM, o para inyectar clases adicionales en el módulo, como al probar.

La forma de la opción es:

•
--patch-module nombre-del-módulo=ruta-del-archivo (separador-de-rutas ruta-del-archivo )*

El carácter separador de rutas es ; en Windows y : en otros sistemas. Las rutas dadas para el módulo deben especificar la raíz de una jerarquía de paquetes para el contenido del módulo.

La opción puede darse como máximo una vez para cualquier módulo dado. Cualquier contenido en la ruta ocultará cualquier contenido con el mismo nombre más adelante en la ruta y en el módulo parcheado.

Al parchear código fuente en más de un módulo, también se debe usar --module-source-path, para que el directorio de salida esté organizado en una jerarquía de módulos y sea capaz de contener los archivos de clase compilados para los módulos que se están compilando.

PROCESAMIENTO DE ANOTACIONES

El comando javac proporciona soporte directo para el procesamiento de anotaciones.

La API para procesadores de anotaciones se define en los paquetes javax.annotation.processing y javax.lang.model y sus subpaquetes.

Cómo funciona el procesamiento de anotaciones

A menos que el procesamiento de anotaciones se deshabilite con la opción -proc:none, el compilador buscará cualquier procesador de anotaciones disponible. La ruta de búsqueda se puede especificar con la opción -processorpath. Si no se especifica ninguna ruta, se utilizará la ruta de clases del usuario. Los procesadores se localizan mediante archivos de configuración de proveedores de servicios llamados META-INF/services/javax.annotation.processing. Los procesadores en la ruta de búsqueda. Dichos archivos deben contener los nombres de cualquier procesador de anotaciones que se vaya a utilizar, listados uno por línea. Alternativamente, los procesadores se pueden especificar explícitamente usando la opción -processor.

Después de escanear los archivos fuente y las clases en la línea de comandos para determinar qué anotaciones están presentes, el compilador consulta a los procesadores para determinar qué anotaciones procesan. Cuando se encuentra una coincidencia, se llama al procesador. Un procesador puede reclamar las anotaciones que procesa, en cuyo caso no se harán más intentos para encontrar procesadores para esas anotaciones. Después de que todas las anotaciones sean reclamadas, el compilador no buscará procesadores adicionales.

Si algún procesador genera nuevos archivos fuente, ocurre otra ronda de procesamiento de anotaciones: Se escanean los archivos fuente recién generados y las anotaciones se procesan como antes. Los procesadores que se llamaron en rondas anteriores también se llaman en todas las rondas subsiguientes. Esto continúa hasta que no se generen nuevos archivos fuente.

Después de que ocurre una ronda en la que no se generan nuevos archivos fuente, se llama a los procesadores de anotaciones una última vez, para darles la oportunidad de completar cualquier trabajo restante. Finalmente, a menos que se utilice la opción -proc:only, el compilador compila los archivos fuente originales y todos los generados.

Si utiliza un procesador de anotaciones que genera archivos fuente adicionales para incluirlos en la compilación, puede especificar un módulo predeterminado para los archivos recién generados, para su uso cuando tampoco se genera una declaración de módulo. En este caso, utilice la opción --default-module-for-created-files.

Entorno de Compilación y Entorno de Ejecución.

javac analiza las declaraciones en los archivos fuente y los archivos de clase compilados previamente en un *entorno de compilación* que es distinto del *entorno de ejecución* utilizado para ejecutar javac en sí. Aunque existe una similitud deliberada entre muchas opciones de javac y opciones con nombres similares para el *launcher* de Java, como --class-path, --module-path y otras, es importante entender que, en general, las opciones de javac solo afectan al entorno en el que se compilan los archivos fuente y no afectan al funcionamiento de javac en sí.

La distinción entre el entorno de compilación y el entorno de ejecución es significativa cuando se trata de usar procesadores de anotaciones. Aunque los procesadores de anotaciones procesan elementos (declaraciones) que existen en el entorno de compilación, el procesador de anotaciones en sí se ejecuta en el entorno de ejecución. Si un procesador de anotaciones tiene dependencias de bibliotecas que no están en módulos, las bibliotecas se pueden colocar, junto con el propio procesador de anotaciones, en la ruta del procesador. (Consulte la opción --processor-path). Si el procesador de anotaciones y sus dependencias están en módulos, debe usar la ruta de módulos del procesador en su lugar. (Consulte la opción --processor-module-path). Cuando estas no son suficientes, puede ser necesario proporcionar una configuración adicional del entorno de ejecución. Esto se puede hacer de dos maneras:

1.
Si se invoca javac desde la línea de comandos, se pueden pasar opciones al entorno de ejecución subyacente prefijando la opción con -J.
2.
Puede iniciar una instancia de una Máquina Virtual Java directamente y usar opciones de línea de comandos y API para configurar un entorno en el que se pueda invocar javac a través de una de sus API.

javac puede compilar código que se utilizará en otras versiones de la plataforma, utilizando la opción --release o las opciones --source/-source y --target/-target, junto con opciones adicionales para especificar las clases de la plataforma.

Dependiendo de la versión de plataforma deseada, existen algunas restricciones en algunas de las opciones que se pueden utilizar.

•
Al compilar para JDK 8 y versiones anteriores, no puede usar ninguna opción destinada al sistema de módulos. Esto incluye todas las siguientes opciones:
•
--module-source-path, --upgrade-module-path, --system, --module-path, --add-modules, --add-exports, --add-opens, --add-reads, --limit-modules, --patch-module

Si utiliza las opciones --source/ -source o --target/ -target, también debe configurar las clases de plataforma apropiadas utilizando la familia de opciones de ruta de clases de arranque (boot classpath).

•
Al compilar para JDK 9 y versiones posteriores, no puede usar ninguna opción destinada a configurar la ruta de clases de arranque (boot classpath). Esto incluye todas las siguientes opciones:
•
-Xbootclasspath/p:, -Xbootclasspath, -Xbootclasspath/a:, -endorseddirs, -Djava.endorsed.dirs, -extdirs, -Djava.ext.dirs, -profile

Si utiliza las opciones --source/ -source o --target/ -target, también debe configurar las clases de plataforma apropiadas utilizando la opción --system para indicar la ubicación de una versión instalada apropiada de JDK.

Al usar la opción --release, solo se puede usar la API documentada compatible para esa versión; no puede usar ninguna opción para romper el encapsulamiento y acceder a clases internas.

NAME

javac - Java compiler

SYNOPSIS

javac [options] [Source files]

DESCRIPTION

The Java programming language compiler. It translates source files written in the Java programming language into Java bytecode, which can be run by a Java virtual machine.

The javac compiler can be used to compile a single source file, or multiple source files at once. It can also be used to compile packages of classes.

The compiler can be configured using various options, which can be specified on the command line or in a configuration file.

OPTIONS

The following options are available:

-g
Enable debugging information.
-g:none
Disable debugging information.
-g:{lines,vars,source}
Enable specific debugging information.
-nowarn
Disable all warnings.
-verbose
Output what the compiler is doing.
-classpath classpath
Specify where to find user class files and annotation processors.
-cp classpath
Same as -classpath.
-sourcepath sourcepath
Specify the search path for source files.
-processor class1,class2,...
The names of the annotation processor to use.
-processorpath path
Specify the search path for annotation processors.
-p path
Same as -processorpath.
-d directory
Specify the destination directory where the .class files will be written.
-encoding encoding
Specify the character encoding of the source files.
-source version
With the specified version, the source code is only accepted if it uses features that were available as of that version. For example, with 1.5, the language level used is that of Java 5.0.
-target version
Generate the class files (bytecode) for a specific virtual machine version. For example, if the virtual machine is version 1.4, the generated class files will not make use of newer language features.
-version
Print product version and exit.
-help
Print a synopsis of standard options.
--help
Print a synopsis of standard options.
-X
Print help on non-standard options.
--options

Pass non-standard options to the Virtual Machine.

@filename

Read options from a file.

ENVIRONMENT VARIABLES

CLASSPATH

Default classpath.

SOURCEPATH

Default sourcepath.

COMMAND-LINE ARGUMENT FILES

A file whose name is specified by the @ character contains compiler options and filenames. The compiler includes the contents of the file in the list of command line options.

This feature can be used to specify a long list of options and filenames. It is also useful for setting the classpath or sourcepath.

The file can contain one or more options or filenames, separated by whitespace. Whitespace characters are space, tab, and line breaks. If an option or filename contains whitespace, you can enclose it in double quotes. The file can also contain comments, which start with the // characters and continue to the end of the line.

ARRANGEMENT OF SOURCE CODE

The Java programming language allows you to organize your code into packages. Packages help you to keep your code organized and to avoid naming conflicts.

You should arrange your source code in a directory hierarchy that mirrors the package structure. For example, if you have a package named `com.example.myapp`, you should place the source files for this package in a directory named `com/example/myapp`.

The compiler will look for source files in the current directory and in the directories specified by the -sourcepath option.

CONFIGURING A COMPILATION

The javac compiler can be configured using various options, which can be specified on the command line or in a configuration file.

The following options can be used to configure a compilation:

-d directory

Specify the destination directory where the .class files will be written.

-encoding encoding

Specify the character encoding of the source files.

-source version

With the specified version, the source code is only accepted if it uses features that were available as of that version. For example, with 1.5, the language level used is that of Java 5.0.

-target version

Generate the class files (bytecode) for a specific virtual machine version. For example, if the virtual machine is version 1.4, the generated class files will not make use of newer language features.

CONFIGURING THE MODULE SYSTEM

The javac compiler supports the Java Platform Module System (JPMS). Modules provide a way to organize your code into logical units, and to control the dependencies between these units.

The following options can be used to configure the module system:

--module-path modulepath

Specify the path to the modules.

--add-modules modules

Add the specified modules to the initial module resolution.

--limit-modules modules

Limit the set of root modules to the specified modules.

SEARCHING FOR MODULE, PACKAGE AND TYPE DECLARATIONS

The compiler searches for module, package, and type declarations in the following locations, in order:

  1. The JRE's rt.jar file.
  2. The directories and JAR files specified by the -classpath or -cp option.
  3. The directories and JAR files specified by the -sourcepath option.

DIRECTORY HIERARCHIES

When compiling a set of source files, you can specify the source files individually, or you can specify a directory. If you specify a directory, the compiler will recursively search for source files in that directory.

The compiler can also take a list of source files from standard input. This is useful for piping the output of other commands to the compiler.

THE MODULE SOURCE PATH OPTION

The --module-source-path option specifies the search path for module source files. Module source files are organized into directories, where each directory represents a module. The compiler will search for module source files in the directories specified by this option.

PATCHING MODULES

The --patch-module option allows you to replace classes in a module with classes from a different module. This is useful for testing or for applying patches to modules.

The syntax is:

--patch-module module=dir1:dir2:...

This option replaces the classes in the specified module with the classes found in the specified directories. The directories are searched in the order they are listed.

ANNOTATION PROCESSING

The javac compiler supports annotation processing. Annotation processing is a framework that allows you to generate Java source code based on annotations in your source code.

The following options can be used to configure annotation processing:

-processor class1,class2,...

The names of the annotation processor to use.

-processorpath path

Specify the search path for annotation processors.

-p path

Same as -processorpath.

-Xprint

Print information about the annotation processing environment.

-XprintProcessorInfo

Print information about the annotation processors that are discovered.

-XprintRounds

Print information about the annotation processing rounds.

COMPILING FOR EARLIER RELEASES OF THE PLATFORM

The -source and -target options can be used to specify the Java version for which the code is being compiled. This allows you to compile code that is compatible with earlier releases of the Java platform.

For example, to compile code for Java 1.5, you would use:

javac -source 1.5 -target 1.5 MyClass.java

APIS

The javac compiler can be used to compile code that uses the Java APIs. The Java APIs are a set of classes and interfaces that provide a wide range of functionality, such as networking, I/O, and GUI development.

When compiling code that uses the Java APIs, you need to make sure that the Java platform's core libraries are on the classpath. The core libraries are typically found in the rt.jar file, which is located in the lib directory of your Java installation.

EXAMPLES OF USING -XLINT KEYS

The -Xlint option can be used to enable or disable specific diagnostic checks. The following example shows how to enable all checks:

javac -Xlint MyClass.java

The following example shows how to disable a specific check, such as unchecked warnings:

javac -Xlint:-unchecked MyClass.java

The following example shows how to enable a specific check, such as deprecation warnings:

javac -Xlint:+deprecation MyClass.java

The following example shows how to enable only deprecation warnings:

javac -Xlint:deprecation MyClass.java

The following example shows how to enable deprecation warnings and disable unchecked warnings:

javac -Xlint:deprecation -Xlint:-unchecked MyClass.java
