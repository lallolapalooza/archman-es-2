NOMBRE

jj-git-fetch - Descargar desde un remoto Git

SINOPSIS

jj git fetch [-b|--branch] [--tracked] [--remote] [--all-remotes] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help]

DESCRIPCIÓN

Descargar desde un remoto Git

Si un commit de la copia de trabajo es abandonado, se le dará un nuevo commit vacío. Esto es cierto en general; no es específico de este comando.

OPCIONES

-b, --branch <RAMA>
Descargar solo algunas de las ramas

Por defecto, el nombre especificado coincide exactamente. Usa el prefijo `glob:` para expandir `*` como un comodín, ej. `--branch 'glob:push-*'`. Otros caracteres comodín como `?` *no* son soportados. Se puede repetir para especificar múltiples ramas.

--tracked
Descargar solo marcadores rastreados

Esto descarga solo los marcadores que ya están siendo rastreados desde los remotos especificados.

--remote <REMOTO>
El remoto desde el cual descargar (solo se soportan remotos con nombre, se puede repetir)

Esto tiene como valor predeterminado la configuración `git.fetch`. Si esta no está configurada, y si hay múltiples remotos, se usará el remoto llamado "origin".

Por defecto, los nombres de remoto especificados coinciden exactamente. Usa un [patrón de cadena], ej. `--remote 'glob:*'`, para seleccionar remotos usando patrones.

[patrón de cadena]: https://docs.jj-vcs.dev/latest/revsets#string-patterns

--all-remotes
Descargar desde todos los remotos
-h, --help
Imprimir ayuda (ver un resumen con '-h')

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el cual operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No hacer una instantánea de la copia de trabajo, y no actualizarla

Por defecto, Jujutsu hace una instantánea de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si quieres evitar hacer una instantánea de la copia de trabajo y ver en su lugar un commit de la copia de trabajo posiblemente desactualizado, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tienes otro proceso que hace commits de la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu previene la reescritura de commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa comprobación y te permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la comprobación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <OPERACIÓN_EN>
Operación en la cual cargar el repo

Operación en la cual cargar el repo. Por defecto, Jujutsu carga el repo en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puedes usar `--at-op=<ID de operación>` para ver cómo se veía el repo en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` te mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Usa `jj op log` para encontrar el ID de operación que deseas. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repo en una operación anterior, la copia de trabajo será ignorada, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repo en una operación anterior. Hacer eso es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacer eso, pero es posible.

--debug
Habilitar registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[posibles valores: always, never, debug, auto]

--quiet
Silenciar la salida no principal del comando

Por ejemplo, `jj file list` todavía listará los archivos, pero no te dirá si se hizo una instantánea de la copia de trabajo o si los descendientes fueron rebasados.

Las advertencias y los errores todavía se imprimirán.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se puede repetir)

El nombre debe especificarse como claves TOML con puntos. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado por ninguna construcción TOML (como la notación de array), las comillas se pueden omitir.

--config-file <RUTA>
Archivos de configuración adicionales (se puede repetir)
