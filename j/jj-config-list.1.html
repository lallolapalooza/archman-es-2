NOMBRE

jj-config-list - Lista las variables establecidas en los archivos de configuración, junto con sus valores

SINOPSIS

jj config list [--include-defaults] [--include-overridden] [--user] [--repo] [--workspace] [-T|--template] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] [NOMBRE]

DESCRIPCIÓN

Lista las variables establecidas en los archivos de configuración, junto con sus valores

OPCIONES

--include-defaults
Indica si se deben incluir explícitamente los valores predeterminados integrados en la lista
--include-overridden
Permitir la impresión de valores anulados
--user
Dirigirse a la configuración a nivel de usuario
--repo
Dirigirse a la configuración a nivel de repositorio
--workspace
Dirigirse a la configuración a nivel de espacio de trabajo
-T, --template <PLANTILLA>
Renderizar cada variable usando la plantilla dada

Las siguientes palabras clave están disponibles en la expresión de la plantilla:

* `name: String`: Nombre de la configuración. * `value: ConfigValue`: Valor a formatear en sintaxis TOML. * `overridden: Boolean`: Verdadero si el valor está eclipsado por otros. * `source: String`: Fuente del valor. * `path: String`: Ruta al archivo de configuración.

Puede ser anulado por la configuración `templates.config_list`. Para ver una lista de configuración detallada, use la plantilla `builtin_config_list_detailed`.

Consulte [`jj help -k templates`] para obtener más información.

[`jj help -k templates`]:
https://docs.jj-vcs.dev/latest/templates/

-h, --help
Imprimir ayuda (ver un resumen con '-h')
[NOMBRE]
Un nombre opcional de una opción de configuración específica a buscar

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No crear una instantánea de la copia de trabajo y no actualizarla

Por defecto, Jujutsu crea una instantánea de la copia de trabajo al inicio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si desea evitar crear una instantánea de la copia de trabajo y ver en su lugar un commit de copia de trabajo posiblemente obsoleto, puede usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tiene otro proceso que confirma la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir la reescritura de commits inmutables

Por defecto, Jujutsu evita la reescritura de commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y le permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de operaciones divergentes si las hay.

Puede usar `--at-op=<ID de operación>` para ver cómo se veía el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` le mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Use `jj op log` para encontrar el ID de operación que desea. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignorará la copia de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes a partir de la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilitar registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[posibles valores: always, never, debug, auto]

--quiet
Silenciar la salida de comandos no principales

Por ejemplo, `jj file list` seguirá listando los archivos, pero no le dirá si se creó una instantánea de la copia de trabajo o si los descendientes fueron rebautizados.

Las advertencias y los errores seguirán imprimiéndose.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves separadas por puntos en TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado entre constructores TOML (como notación de matriz), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
list
