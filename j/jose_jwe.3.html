*next) Descifra texto cifrado con el CEK usando streaming. Descripción Detallada JSON Web Encryption (RFC 7516) Un objeto JSON Web Encryption (JWE) contiene (normalmente) dos niveles de cifrado. Primero, el texto plano se cifra con una clave simétrica aleatoria. En José, llamamos a esta clave la Clave de Cifrado de Contenido (CEK). A continuación, el CEK se envuelve (cifra) con una o más claves. Estas claves son JSON Web Keys (JWK) estándar y pueden ser simétricas o asimétricas.
Por lo tanto, hay (normalmente) un CEK y uno o más JWK. Sin embargo, hay algunas excepciones a esta regla. Dos ejemplos de estos son los algoritmos: 'dir' y 'ECDH-ES'. En el primer caso, el JWK es una clave simétrica y se usa directamente como el CEK. En el segundo caso, se realiza un intercambio de claves ECDH y el resultado se usa directamente como el CEK. Pero en general, el axioma se mantiene.

Esto significa que puede cifrar los datos usando un CEK y luego cifrar el CEK para múltiples destinatarios. Con este esquema, múltiples destinatarios pueden descifrar los datos por sí mismos usando su propia clave sin tener que enviar texto cifrado separado a cada

destinatario.

Para una máxima flexibilidad, José estructura su API para aprovechar este esquema. Por ejemplo, al cifrar para dos destinatarios, el código podría verse así (se omite el manejo de

errores):

json_t *enc(void *plaintext, size_t len, json_t *jwk0, json_t *jwk1) { json_auto_t *jwe = json_object(); json_auto_t *cek = json_object(); // Envolver para el primer destinatario (CEK generado implícitamente) jose_jwe_enc_jwk(NULL, jwe, NULL, jwk0, cek); // Envolver para el segundo destinatario jose_jwe_enc_jwk(NULL, jwe, NULL, jwk1, cek); // Cifrar texto plano usando el CEK generado jose_jwe_enc_cek(NULL, jwe, cek, plaintext, len); return json_incref(jwe);

}

Sin embargo, como José pretende ser fácil de usar, también proporcionamos atajos. Por ejemplo, podría usar un JWKSet que contiene múltiples

JWK:

json_t *enc(void *plaintext, size_t len, json_t *jwkset) { json_auto_t *jwe = json_object(); // Realizar envoltura y cifrado para todos los destinatarios jose_jwe_enc(NULL, jwe, NULL, jwkset, plaintext, len); return json_incref(jwe);

}

Aquí hay dos consejos para recordar. Primero, deje que José genere su CEK implícitamente. Segundo, siempre realice el envoltorio antes del cifrado. Ambos consejos son importantes porque algunos algoritmos de envoltorio pueden imponer restricciones en la generación del

CEK. 
Para descifrar un JWE, simplemente invertimos el proceso. Primero, usamos un JWK
    para desenvolver el CEK. Luego usamos el CEK para descifrar el texto cifrado. Aquí está
    cómo podría verse en código (de nuevo, se omite el manejo de errores)
:

void *dec(json_t *jwe, json_t *jwk, size_t *len) { json_auto_t *cek = NULL; // Desenvolver el CEK usando nuestro JWK cek = jose_jwe_dec_jwk(NULL, jwe, NULL, jwk); // Descifrar texto cifrado usando el CEK return jose_jwe_dec_cek(NULL, jwe, cek, len);

} 
O, de nuevo, en forma
simplificada:

void *dec(json_t *jwe, json_t *jwk, size_t *len) { return jose_jwe_dec(NULL, jwe, NULL, jwk, len);

}

Si necesita reenviar un JWE a un nuevo destinatario, puede hacer esto sin realizar re-cifrado. Simplemente desenvuelva el CEK y luego envuelva el CEK de nuevo usando un nuevo JWK. Por

ejemplo: 
void fwd(json_t *jwe, json_t *oldjwk, json_t *newjwk) {
    json_auto_t *cek = NULL;
    // Desenvolver el CEK usando el JWK antiguo
    cek = jose_jwe_dec_jwk(NULL, jwe, NULL, oldjwk);
    // Envolver el CEK para el nuevo JWK
    jose_jwe_enc_jwk(NULL, jwe, NULL, newjwk, cek);
}

En todos los ejemplos anteriores, parámetros como qué algoritmos de cifrado usar se infirieron de nuestras claves. Donde tal inferencia no puede hacerse, se eligieron automáticamente valores predeterminados sensatos y seguros. Si desea más control sobre el proceso, simplemente establezca parámetros en los objetos apropiados (más sobre esto en la documentación de la función). Por ejemplo, para habilitar la compresión de texto plano, puede especificar la

propiedad zip 
en el Encabezado Protegido del
JWE:

json_t *enc(void *plaintext, size_t len, json_t *jwkset) { json_auto_t *jwe = json_pack("{s:{s:s}}", "protected", "zip", "DEF"); // Realizar envoltura comprimida y cifrado para todos los destinatarios jose_jwe_enc(NULL, jwe, NULL, jwkset, plaintext, len); return json_incref(jwe);

} 
José actualmente soporta los parámetros de encabezado 'alg', 'enc' y 'zip',
    así como cualquier parámetro de encabezado específico del algoritmo usado por los
    algoritmos específicos que implementamos. Otros parámetros de encabezado pueden especificarse,
    pero no afectan el comportamiento de la implementación JWE de
José.

bool jose_jwe_enc_jwk (jose_cfg_t * cfg, json_t * jwe, json_t * rcp, const json_t * jwk, json_t * cek)

Envuelve un CEK con un JWK. El propósito de esta función es envolver (cifrar) o, en algunos casos, producir el CEK (cek) a partir de los JWK(s) proporcionados (jwk). Esta función puede usarse en dos modos: JWK único y JWK múltiple.

En el modo JWK único, el parámetro jwk contiene un objeto JWK y el parámetro rcp debe contener un objeto de destinatario JWE o NULL, en cuyo caso se crea internamente un objeto de destinatario JWE vacío predeterminado.

El modo JWK múltiple funciona exactamente igual que el modo JWK único excepto que realiza múltiples envoltorios en una sola llamada. Este modo se habilita pasando como parámetro jwk un array de objetos JWK o un JWKSet. En este modo, el parámetro rcp contiene uno de los siguientes valores:

1.
Un objeto de destinatario JWE que se utilizará para todos los envoltorios. En este caso, se hará una copia para cada envoltorio y rcp no se modificará de ninguna manera.
2.
Un array de objetos de destinatario JWE. Cada objeto se utilizará con su JWK correspondiente de jwk. Si los arrays en sig y jwk tienen un tamaño diferente, ocurrirá un error.
3.
NULL. Esto tiene el mismo efecto que pasar NULL para cada JWK individual.

En cualquiera de los modos, si el JWE resultante (jwe) contuviera solo un destinatario, el JWE se representará en Sintaxis de Serialización JSON JWE Aplanada. De lo contrario, se representará en Sintaxis de Serialización JSON JWE General.

Si el parámetro 'alg' no está especificado en la Cabecera JOSE, se inferirá del JWK y el algoritmo elegido se añadirá a la Cabecera No Protegida por Destinatario del JWE. Del mismo modo, cualquier parámetro específico del algoritmo faltante y requerido se inferirá o se elegirán valores predeterminados seguros y sensatos, y los resultados se añadirán a la Cabecera No Protegida por Destinatario del JWE.

Si el CEK proporcionado (cek) no contiene material de clave, se generará implícitamente durante la primera llamada a jose_jwe_enc_jwk(). Esta característica importante permite el uso de los algoritmos 'dir' y 'ECDH-ES'. En el caso del algoritmo 'dir', el JWK es el CEK y por lo tanto el material de clave se copia de jwk a cek. Surge una situación similar con el algoritmo 'ECDH-ES' donde el resultado de un intercambio de claves se utiliza como CEK; por lo tanto, el CEK se produce durante el proceso de envoltorio. Esta característica implica que si se crean múltiples envoltorios, solo uno de ellos puede tener el algoritmo 'ECDH-ES' y debe ser el primer envoltorio. Intentar usar 'ECDH-ES' con un CEK existente resultará en un error.

Además, es posible pasar una cadena JSON de contraseña como entrada de clave a la familia de algoritmos PBES2 en cualquier lugar donde se pueda usar un JWK. Del mismo modo, si el parámetro de cabecera JOSE 'alg' no está especificado y se usa una cadena JSON en lugar de un JWK, se inferirá la familia de algoritmos PBES2.

Parámetros:

cfg El contexto de configuración (opcional).
jwe El objeto JWE.
rcp El/los objeto(s) de destinatario JWE o NULL.
jwk El/los JWK(s) o JWKSet utilizado(s) para el envoltorio.
cek El CEK a envolver (si está vacío, se genera).

Devuelve:

En caso de éxito, true. De lo contrario, false.

jose_io_t* jose_jwe_enc_cek_io (jose_cfg_t * cfg, json_t * jwe, const json_t * cek, jose_io_t * next)

Cifra texto plano con el CEK usando streaming. El texto plano se proporciona a través del objeto IO devuelto. El texto plano se cifrará y se escribirá en el siguiente objeto IO. Este objeto IO trabaja con datos binarios, por lo que es posible que necesite usar un decodificador Base64 seguro para URL en la entrada y un codificador Base64 seguro para URL en la salida, dependiendo de su situación.

El texto plano comprimido se puede habilitar implícitamente especificando el parámetro 'zip' en la Cabecera Protegida del JWE.

Si la Cabecera Protegida del JWE es un objeto JSON en lugar de una cadena codificada, esta función codificará la Cabecera Protegida del JWE a su codificación Base64 segura para URL según lo definido en RFC 7516. Sin embargo, esta función nunca modificará una Cabecera Protegida del JWE que ya esté codificada.

Si el parámetro 'enc' no está especificado en la Cabecera Protegida del JWE o en la Cabecera No Protegida Compartida del JWE, se inferirá del CEK y se almacenará en la Cabecera Protegida del JWE o en la Cabecera No Protegida Compartida del JWE (prefiriendo la Cabecera Protegida del JWE si se puede modificar).

Tenga en cuenta que la propiedad 'tag' solo se añadirá al JWE cuando jose_io_t::done() devuelva.

Parámetros:

cfg El contexto de configuración (opcional).
jwe El objeto JWE.
cek El objeto CEK.
next El siguiente objeto IO en la cadena.

Devuelve:

El nuevo objeto IO o NULL en caso de error.

json_t* jose_jwe_dec_jwk (jose_cfg_t * cfg, const json_t * jwe, const json_t * rcp, const json_t * jwk)

Desenvuelve un CEK con un JWK. El propósito de esta función es desenvolver (descifrar) o, en algunos casos, producir el CEK (cek) a partir de los JWK(s) proporcionados (jwk). Esta función puede usarse en dos modos: JWK único y JWK múltiple.

En el modo JWK único, el parámetro jwk contiene un objeto JWK y el parámetro rcp debe contener un objeto de destinatario JWE que desee desenvolver o NULL, en cuyo caso se probarán todos los destinatarios JWE.

El modo JWK múltiple funciona exactamente igual que el modo JWK único excepto que intenta desenvolver con múltiples JWK en una sola llamada. Este modo se habilita pasando como parámetro jwk un array de objetos JWK o un JWKSet. En este modo, el parámetro rcp contiene uno de los siguientes valores:

1.
Un objeto de destinatario JWE que se utilizará para todos los intentos de desenvolvimiento.
2.
Un array de objetos de destinatario JWE. Cada objeto se utilizará con su JWK correspondiente de jwk. Si los arrays en sig y jwk tienen un tamaño diferente, ocurrirá un error.
3.
NULL. Esto tiene el mismo efecto que pasar NULL para cada JWK individual.

En cualquiera de los modos, se devuelve un CEK para el primer JWK que desenvuelva con éxito un CEK. Hay dos excepciones a esta regla: si se usan los algoritmos 'dir' o 'ECDH-ES'. En este caso, se puede devolver un CEK que fallará durante el descifrado, ya que no hay forma de validar completamente el JWK con estos algoritmos. Por lo tanto, sugerimos colocar las claves para estos algoritmos al final al desenvolver con múltiples JWK.

Si el parámetro 'alg' no está especificado en la Cabecera JOSE, se inferirá del JWK. Esto incluye el uso de una cadena JSON en lugar de un JWK para la familia de algoritmos PBES2.

Parámetros:

cfg El contexto de configuración (opcional).
jwe El objeto JWE.
rcp El/los objeto(s) de destinatario JWE o NULL.
jwk El JWK(s) o JWKSet utilizado para el envoltorio.

Devuelve:

En caso de éxito, un objeto CEK recién asignado. De lo contrario, NULL.

jose_io_t* jose_jwe_dec_cek_io (jose_cfg_t * cfg, const json_t * jwe, const json_t * cek, jose_io_t * next)

Descifra el texto cifrado con el CEK utilizando streaming. El texto cifrado se proporciona a través del objeto IO devuelto. El texto cifrado será descifrado y escrito en el siguiente objeto IO. Este objeto IO trabaja con datos binarios, por lo que puede necesitar usar un decodificador Base64 seguro para URL en la entrada y un codificador Base64 seguro para URL en la salida, dependiendo de su situación.

Tenga en cuenta que la validación de la protección de integridad del texto cifrado se retrasa hasta que jose_io_t::done() retorna. Esto significa que es increíblemente importante verificar este valor de retorno y también es importante tener cuidado con el texto plano emitido hasta que se realice esta verificación.

El texto plano compruido será descomprimido internamente si la propiedad 'zip' está definida adecuadamente.

Si el parámetro 'enc' no está especificado en el Encabezado Protegido del JWE o en el Encabezado Compartido No Protegido del JWE, se inferirá del CEK.

Tenga en cuenta que la propiedad 'tag' en el JWE solo será accedida cuando jose_io_t::done() sea llamada. Por lo tanto, puede definirla en cualquier momento en el objeto JWE antes de llamar a jose_io_t::done().

Parámetros:

cfg El contexto de configuración (opcional).
jwe El objeto JWE.
cek El objeto CEK.
next El siguiente objeto IO en la cadena.

Devuelve:

El nuevo objeto IO o NULL en caso de error.
