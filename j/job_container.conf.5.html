job_container.conf - Archivo de

configuración de Slurm para los
plugins de espacio de nombres

DESCRIPCIÓ

N

job_container.conf es un archivo ASCII que define los parámetros utilizados por el plugin namespace/tmpfs de Slurm. Basándose en estos parámetros, el plugin creará el/los espacio(s) de nombres específico(s) del

trabajo.

El plugin namespace/tmpfs crea un espacio de nombres de sistema de archivos y construirá un espacio de nombres de sistema de archivos privado (o opcionalmente compartido) y montará una lista de directorios (por defecto /tmp y /dev/shm) dentro de él, dando al trabajo una vista privada de estos directorios. Estas rutas se montan dentro de la ubicación especificada por 'BasePath' en el archivo job_contai

ner.conf.

Cuando el trabajo finaliza, el espacio de nombres se desmonta y todos los archivos en él son eliminados automáticamente

.

Para hacer uso de este plugin, 'PrologFlags=Contain' también debe estar presente en su archivo slurm.conf, como se

muestra: 
NamespaceType=namespace/tmpfs
PrologFlags=Contai
n

El archivo siempre estará ubicado en el mismo directorio que el slurm.c

onf.

Si se utiliza el archivo job_container.conf para definir un espacio de nombres disponible para los nodos, el primer parámetro en la línea debe ser NodeName. Si se configura un espacio de nombres sin especificar nodos, el primer parámetro en la línea debe ser BasePath

.

Los nombres de los parámetros no distinguen entre mayúsculas y minúsculas. Cualquier texto que siga a un "#" en el archivo de configuración se trata como un comentario hasta el final de esa línea. Los cambios en el archivo de configuración entran en efecto al reiniciar los demonios de

Slurm.

Se definen los siguientes parámetros de job_container.conf para controlar el comportamiento del plugin namespace/tmpfs

.
AutoBasePa
th
Esto determina si el plugin debe crear el directorio BasePath o no. Establézcalo en 'true' si el directorio no está precreado antes del inicio de slurm
. Si se establece en true, el directorio se crea con permiso 0755. El directorio no se elimina durante el apagado de slurm. Si se establece en 'false'
o no se especifica, el plugin esperará que el directorio exista. Esta opción se puede utilizar a nivel global o por línea. Este parámetro es opcional.
BasePa
th
Especifique la RUTA que el plugin tmpfs debe usar como base para montar los directorios privados. Esta ruta debe ser legible y escribible por el plugin. El plugin construye un directorio para cada trabajo dentro de esta ruta, que luego se usa para el montaje. La BasePath se monta como 'privada' durante el inicio de slurmd y permanece montada hasta el apagado. El primer "%h" dentro del nombre se reemplaza con el nombre de host en el que se está ejecutando el slurmd. El primer "%n" dentro del nombre se reemplaza con el nombre de nodo de Slurm en el que se está ejecutando el slurmd. Establezca RUTA en 'none' para deshabilitar el plugin tmpfs en subconjuntos de nodos cuando existe una configuración global.

NOTA: La BasePath debe ser única para cada nodo. Si BasePath está en un sistema de archivos compartido, puede usar "%h" o "%n" para crear directorios únicos por

nodo.

NOTA

S

Si se cambian parámetros en job_container.conf mientras slurm está en ejecución, entonces slurmd en los nodos respectivos necesitará ser reiniciado para que los cambios surtan efecto (scontrol reconfigure no es suficiente). Adicionalmente, esto puede ser disruptivo para los trabajos ya en ejecución en el nodo. Por lo tanto, se debe tener cuidado para asegurarse de que no haya trabajos en ejecución si se despliegan cambios en job_container.

conf.

Reiniciar slurmd es seguro y no disruptivo para los trabajos e

n ejecución, siempre que job_container.conf no se cambie
entre reinicios, en cuyo caso se aplica el punto anterior.

NAME

job_container.conf - Slurm configuration file for job containerization

DESCRIPTION

Files that contain configuration information for Slurm. See slurm.conf(5) for more information. This file is used to specify parameters related to job containerization.

NOTES

The job_container.conf file is read by the slurmctld daemon and plugins that manage job containerization.

If the file does not exist, then the default parameters are used.

The default location of the job_container.conf file is /etc/slurm/job_container.conf.

Configuration options are identified by a parameter name and value separated by an equal sign (=). Options are case sensitive. White space surrounding the equal sign and leading/trailing white space surrounding the parameter name and value is ignored.

Comments may be included in the file. Any text line beginning with a '#' character is treated as a comment. All comments are ignored.

The following options are supported:

AutoBasePath
If set to true, Slurm will automatically set the BasePath to the location of the job's working directory. This is useful for ensuring that job-specific data is stored in a location that is accessible to the job.
BasePath
Specifies the base directory for storing containerized job data. If AutoBasePath is set to true, this option is ignored. Otherwise, it specifies the root directory under which job-specific directories will be created.
Dirs
A comma-separated list of directories that should be mounted into the container. These directories will be accessible from within the container. For example, Dirs=/tmp,/var/tmp would mount the /tmp and /var/tmp directories into the container. If AutoBasePath is set to true, then the BasePath directory will also be mounted into the container.

EXAMPLE

The following example shows how to configure Slurm to use /var/nvme/storage as the base path for containerized job data, and to automatically set the base path based on the job's working directory. It also configures /tmp and /var/tmp to be mounted as private mounts within the container.

AutoBasePath=true
BasePath=/var/nvme/storage Dirs=/tmp,/var/tmp
