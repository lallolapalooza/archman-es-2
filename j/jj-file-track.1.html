NOMBRE

jj-file-track - Empieza a rastrear rutas especificadas en la copia de trabajo

SINOPSIS

jj file track [--include-ignored] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <CONJUNTOS-DE-ARCHIVOS>

DESCRIPCIÓN

Empieza a rastrear rutas especificadas en la copia de trabajo.

Sin argumentos, todas las rutas que no estén ignoradas serán rastreadas.

Por defecto, los archivos nuevos en la copia de trabajo se rastrean automáticamente, por lo que este comando no tiene efecto. Puedes configurar qué rutas rastrear automáticamente estableciendo `snapshot.auto-track` (por ejemplo, a `"none()"` o `"glob:**/*.rs"`). Los archivos que no coincidan con el patrón pueden rastrearse manualmente usando este comando. El patrón por defecto es `all()`.

OPCIONES

--include-ignored
Rastrear rutas incluso si están ignoradas o son demasiado grandes.

Por defecto, `jj file track` no rastreará archivos que estén ignorados por .gitignore o que excedan el tamaño máximo de archivo. Esta bandera anula esas restricciones, rastreando explícitamente las rutas especificadas.

-h, --help
Imprimir ayuda (ver un resumen con '-h').
<CONJUNTOS-DE-ARCHIVOS>
Rutas a rastrear.

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio en el que operar.

Por defecto, Jujutsu busca el directorio `.jj/` más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No crear una instantánea de la copia de trabajo y no actualizarla.

Por defecto, Jujutsu crea una instantánea de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si quieres evitar crear una instantánea de la copia de trabajo y ver en su lugar un commit de copia de trabajo posiblemente obsoleto, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tienes otro proceso que confirma la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables.

Por defecto, Jujutsu previene la reescritura de commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y te permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta al revset `immutable_heads()` ni a la palabra clave de plantilla `immutable`.

--at-operation <OPERACIÓN_EN>
Operación en la que cargar el repositorio.

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puedes usar `--at-op=<ID de operación>` para ver cómo estaba el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` te mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente igual que el valor predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Usa `jj op log` para encontrar el ID de operación que deseas. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, la copia de trabajo se ignorará, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutantes al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilitar registro de depuración.
--color <CUÁNDO>
Cuándo colorear la salida.

[posibles valores: always, never, debug, auto]

--quiet
Silenciar la salida no principal del comando.

Por ejemplo, `jj file list` seguirá listando archivos, pero no te dirá si se creó una instantánea de la copia de trabajo o si se rebasaron los descendientes.

Las advertencias y errores aún se imprimirán.

--no-pager
Deshabilitar el paginador.
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (pueden repetirse).

El nombre debe especificarse como claves puntuales de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado por ninguna construcción de TOML (como la notación de array), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (pueden repetirse).
