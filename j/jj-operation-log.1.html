jj-operation-log(1) Manual de Comandos Generales jj-operation-log(1)

NOMBRE

jj-operation-log - Mostrar el registro de operaciones

SINOPSIS

jj operation log [-n|--limit] [--reversed] [-G|--no-graph] [-T|--template] [-d|--op-diff] [-p|--patch] [-s|--summary] [--stat] [--types] [--name-only] [--git] [--color-words] [--tool] [--context] [--ignore-all-space] [--ignore-space-change] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help]

DESCRIPCIÓN

Muestra el registro de operaciones

Al igual que otros comandos, `jj op log` crea instantáneas de los cambios actuales de la copia de trabajo y reconcilia las operaciones divergentes. Usa `--at-op=@ --ignore-working-copy` para inspeccionar el estado actual sin mutación.

OPCIONES

-n, --limit <LIMITE>
Limita el número de operaciones a mostrar

Se aplica después de que las operaciones se reordenan topológicamente, pero antes de ser invertidas.

--reversed
Muestra las operaciones en orden opuesto (operaciones más antiguas primero)
-G, --no-graph
No mostrar el grafo, mostrar una lista plana de operaciones
-T, --template <PLANTILLA>
Renderiza cada operación usando la plantilla dada

Puedes especificar expresiones de plantilla arbitrarias usando las [palabras clave integradas]. Consulta [`jj help -k templates`] para más información.

[palabras clave integradas]: https://docs.jj-vcs.dev/latest/templates/#operation-keywords

[`jj help -k templates`]: https://docs.jj-vcs.dev/latest/templates/

-d, --op-diff
Mostrar cambios en el repositorio en cada operación
-p, --patch
Muestra el parche de modificaciones a los cambios (implica --op-diff)

Si la versión anterior tiene padres diferentes, se rebajará temporalmente a los padres de la nueva versión, para que la diferencia no sea contaminada por cambios no relacionados.

-h, --help
Imprimir ayuda (ver un resumen con '-h')

OPCIONES DE FORMATO DE DIFERENCIAS

-s, --summary
Para cada ruta, muestra solo si fue modificada, agregada o eliminada
--stat
Muestra un histograma de los cambios
--types
Para cada ruta, muestra solo su tipo antes y después

La diferencia se muestra como dos letras. La primera letra indica el tipo antes y la segunda indica el tipo después. '-' indica que la ruta no estaba presente, 'F' representa un archivo regular, 'L' representa un enlace simbólico, 'C' representa un conflicto y 'G' representa un submódulo de Git.

--name-only
Para cada ruta, muestra solo su ruta

Típicamente útil para comandos de shell como: `jj diff -r @- --name-only | xargs perl -pi -e's/VIEJO/NUEVO/g`

--git
Muestra una diferencia en formato Git
--color-words
Muestra una diferencia a nivel de palabra con los cambios indicados solo por color
--tool <HERRAMIENTA>
Genera la diferencia mediante un comando externo

También se puede especificar un formato incorporado como `:<nombre>`. Por ejemplo, `--tool=:git` es equivalente a `--git`.

--context <CONTEXTO>
Número de líneas de contexto a mostrar
--ignore-all-space
Ignora el espacio en blanco al comparar líneas
--ignore-space-change
Ignora los cambios en la cantidad de espacio en blanco al comparar líneas

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No crear instantánea de la copia de trabajo, y no actualizarla

Por defecto, Jujutsu crea instantáneas de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si deseas evitar la instantánea de la copia de trabajo y en su lugar ver un commit de copia de trabajo posiblemente obsoleto, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en un prompt de comandos, especialmente si tienes otro proceso que confirma la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permite reescribir commits inmutables

Por defecto, Jujutsu evita reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y te permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puedes usar `--at-op=<ID de operación>` para ver cómo se veía el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` te mostrará lo que `jj st` habría mostrado cuando la operación dada había terminado. `--at-op=@` es prácticamente lo mismo que el valor predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Usa `jj op log` para encontrar el ID de operación que deseas. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, la copia de trabajo será ignorada, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutantes al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilitar registro de depuración
--color <CUANDO>
Cuándo colorear la salida

[valores posibles: always, never, debug, auto]

--quiet
Silenciar la salida no principal del comando

Por ejemplo, `jj file list` aún listará archivos, pero no te dirá si la copia de trabajo fue instantaneada o si los descendientes fueron rebajados.

Las advertencias y los errores aún se imprimirán.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se puede repetir)

El nombre debe especificarse como claves punteadas de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado en ninguna construcción TOML
