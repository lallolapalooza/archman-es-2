jps(1) Herramientas de monitorización jps(1)

NOMBRE

jps - Lista las Máquinas Virtuales Java (JVM) instrumentadas en el sistema de destino. Este comando es experimental y no tiene soporte.

SINOPSIS

jps [ opciones ] [ hostid ]
opciones
Opciones de la línea de comandos. Ver Opciones.
hostid
El identificador del host para el cual se debe generar el informe del proceso. El hostid puede incluir componentes opcionales que indican el protocolo de comunicación, el número de puerto y otros datos específicos de la implementación. Ver Identificador de host.

DESCRIPCIÓN

El jps comando lista las Máquinas Virtuales Java HotSpot instrumentadas en el sistema de destino. El comando se limita a informar sobre JVM para las cuales tiene los permisos de acceso.

Si el jps comando se ejecuta sin especificar un hostid, entonces busca JVM instrumentadas en el host local. Si se inicia con un hostid, entonces busca JVM en el host indicado, utilizando el protocolo y el puerto especificados. Se asume que un proceso jstatd se está ejecutando en el host de destino.

El jps comando informa el identificador local de la JVM, o lvmid, para cada JVM instrumentada encontrada en el sistema de destino. El lvmid es típicamente, pero no necesariamente, el identificador de proceso del sistema operativo para el proceso de la JVM. Sin opciones, jps lista el lvmid de cada aplicación Java seguido de la forma corta del nombre de la clase o del nombre del archivo jar de la aplicación. La forma corta del nombre de la clase o del nombre del archivo JAR omite la información del paquete de la clase o la información de la ruta del archivo JAR.

El jps comando utiliza el lanzador de Java para encontrar el nombre de la clase y los argumentos pasados al método main. Si la JVM de destino se inicia con un lanzador personalizado, entonces el nombre de la clase o del archivo JAR y los argumentos para el main método no están disponibles. En este caso, el jps comando emite la cadena Unknown para el nombre de la clase o del archivo JAR y para los argumentos del main método.

La lista de JVM producida por el jps comando puede ser limitada por los permisos concedidos al principal que ejecuta el comando. El comando solo lista las JVM para las cuales el principal tiene derechos de acceso, según lo determinado por los mecanismos de control de acceso específicos del sistema operativo.

OPCIONES

El jps comando soporta una serie de opciones que modifican la salida del comando. Estas opciones están sujetas a cambios o eliminación en el futuro.

-q

Suprime la salida del nombre de la clase, del nombre del archivo JAR y de los argumentos pasados al main método, produciendo solo una lista de identificadores locales de JVM.
-m

Muestra los argumentos pasados al main método. La salida puede ser null para JVM embebidas.
-l

Muestra el nombre completo del paquete de la clase main de la aplicación o la ruta completa al archivo JAR de la aplicación.
-v

Muestra los argumentos pasados a la JVM.
-V

Suprime la salida del nombre de la clase, del nombre del archivo JAR y de los argumentos pasados al método main, produciendo solo una lista de identificadores locales de JVM.
-Jopción

Pasa opción a la JVM, donde opción es una de las opciones descritas en la página de referencia del lanzador de aplicaciones Java. Por ejemplo, -J-Xms48m establece la memoria de inicio en 48 MB. Ver java(1).

IDENTIFICADOR DE HOST

El identificador del host, o hostid es una cadena que indica el sistema de destino. La sintaxis de la cadena hostid corresponde a la sintaxis de un URI:

[protocolo:][[//]nombrehost][:puerto][/nombreservidor]
protocolo
El protocolo de comunicación. Si el protocolo se omite y un nombrehost no se especifica, entonces el protocolo por defecto es un protocolo local, optimizado y específico de la plataforma. Si el protocolo se omite y se especifica un nombre de host, entonces el protocolo por defecto es rmi.
nombrehost
Un nombre de host o una dirección IP que indica el host de destino. Si omite el parámetro nombrehost , entonces el host de destino es el host local.
puerto
El puerto por defecto para comunicarse con el servidor remoto. Si el parámetro nombrehost se omite o el parámetro protocolo especifica un protocolo local, optimizado, entonces el parámetro puerto se ignora. De lo contrario, el tratamiento del parámetro puerto es específico de la implementación. Para el protocolo por defecto rmi , el parámetro puerto indica el número de puerto para el rmiregistry en el host remoto. Si el parámetro puerto se omite, y el parámetro protocolo indica rmi, entonces se utiliza el puerto por defecto de rmiregistry (1099).
nombreservidor
El tratamiento de este parámetro depende de la implementación. Para el protocolo local, optimizado, este campo se ignora. Para el protocolo rmi , este parámetro es una cadena que representa el nombre del objeto remoto RMI en el host remoto. Ver el comando jstatd opción -npara más información.

FORMATO DE SALIDA

La salida del jps comando sigue el siguiente patrón:

lvmid [ [ classname | JARfilename | "Unknown"] [ arg* ] [ jvmarg* ] ]

Todos los tokens de salida están separados por espacios en blanco. Un valor arg que incluye espacios en blanco introduce ambigüedad al intentar mapear los argumentos a sus parámetros posicionales reales.

Nota: Se recomienda que no escriba scripts para analizar jps la salida, ya que el formato podría cambiar en versiones futuras. Si escribe scripts que analicen la salida de jps , espere tener que modificarlos para versiones futuras de esta herramienta.

EJEMPLOS

Esta sección proporciona ejemplos del jps comando.

Lista las JVM instrumentadas en el host local:

jps
18027 Java2Demo.JAR
18032 jps
18005 jstat

El siguiente ejemplo lista las JVM instrumentadas en un host remoto. Este ejemplo asume que el servidor jstat y ya sea su registro RMI interno o un proceso rmiregistry externo separado se están ejecutando en el host remoto en el puerto por defecto (puerto 1099). También asume que el host local tiene los permisos apropiados para acceder al host remoto. Este ejemplo también incluye la opción -l para emitir la forma larga de los nombres de clase o de los nombres de archivo JAR.

jps -l remote.domain
3002 /opt/jdk1.7.0/demo/jfc/Java2D/Java2Demo.JAR
2857 sun.tools.jstatd.jstatd

El siguiente ejemplo lista las JVM instrumentadas en un host remoto con un puerto no por defecto para el registro RMI. Este ejemplo asume que el servidor jstatd , con un registro RMI interno vinculado al puerto 2002, se está ejecutando en el host remoto. Este ejemplo también usa la opción -m para incluir los argumentos pasados al main método de cada una de las aplicaciones Java listadas.

jps -m remote.domain:2002
3002 /opt/jdk1.7.0/demo/jfc/Java2D/Java2Demo.JAR
3102 sun.tools.jstatd.jstatd -p 2002
