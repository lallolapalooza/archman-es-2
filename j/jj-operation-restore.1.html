NOMBRE

jj-operation-restore - Crea una nueva operación que restaura el repositorio a un estado anterior

SINOPSIS

jj operation restore [--what] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <OPERACIÓN>

DESCRIPCIÓN

Crea una nueva operación que restaura el repositorio a un estado anterior

Esto restaura el repositorio al estado en la operación especificada, deshaciendo efectivamente todas las operaciones posteriores. Lo hace creando una nueva operación.

OPCIONES

--what <QUÉ> [predeterminado: repo,remote-tracking]
Qué porciones del estado local restaurar (se puede repetir)

Esta opción es EXPERIMENTAL.

Valores posibles:

  • repo: El estado del repositorio jj y los marcadores locales
  • remote-tracking: Los marcadores de seguimiento remoto. No los restaure si desea hacer push después de deshacer
-h, --help
Imprime la ayuda (vea un resumen con '-h')
<OPERACIÓN>
La operación a la que restaurar

Use `jj op log` para encontrar una operación a la que restaurar. Use por ejemplo `jj --at-op=<ID de operación> log` antes de restaurar a una operación para ver el estado del repositorio en esa operación.

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No crear una instantánea de la copia de trabajo, ni actualizarla

Por defecto, Jujutsu crea una instantánea de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si desea evitar crear una instantánea de la copia de trabajo y en su lugar ver un commit de la copia de trabajo posiblemente obsoleto, puede usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tiene otro proceso que confirma la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu evita reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa comprobación y le permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta a la comprobación. No afecta al revset `immutable_heads()` ni a la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puede usar `--at-op=<ID de operación>` para ver cómo se veía el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` le mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Use `jj op log` para encontrar el ID de operación que desea. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, la copia de trabajo se ignorará, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes que comienzan en la operación anterior. Raramente hay una razón para hacerlo, pero es posible.

--debug
Habilitar registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[valores posibles: always, never, debug, auto]

--quiet
Silenciar la salida de comandos no primarios

Por ejemplo, `jj file list` seguirá listando archivos, pero no le dirá si se creó una instantánea de la copia de trabajo o si los descendientes fueron rebasados.

Las advertencias y los errores seguirán imprimiéndose.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves TOML separadas por puntos. El valor debe especificarse como una expresión TOML. Si el valor de la cadena no está encerrado en ningún constructo TOML (como la notación de matriz), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
