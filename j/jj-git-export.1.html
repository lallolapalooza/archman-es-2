NOMBRE

jj-git-export - Actualizar el repositorio Git subyacente con los cambios realizados en el repositorio

SINOPSIS

jj git export [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help]

DESCRIPCIÓN

Actualizar el repositorio Git subyacente con los cambios realizados en el repositorio

No hay necesidad de ejecutar este comando si estás en un espacio de trabajo colocalizado, ya que la exportación se realiza automáticamente allí.

OPCIONES

-h, --help
Imprimir ayuda (ver resumen con '-h')

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No capturar una instantánea de la copia de trabajo y no actualizarla

Por defecto, Jujutsu captura una instantánea de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si desea evitar capturar una instantánea de la copia de trabajo y en su lugar ver un commit de la copia de trabajo posiblemente obsoleto, puede usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en un indicador de comandos, especialmente si tiene otro proceso que confirma la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir la reescritura de commits inmutables

Por defecto, Jujutsu evita la reescritura de commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y le permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puede usar `--at-op=<ID de operación>` para ver cómo se veía el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` le mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Use `jj op log` para encontrar el ID de operación que desea. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, la copia de trabajo se ignorará, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes a partir de la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilitar el registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[posibles valores: always, never, debug, auto]

--quiet
Silenciar la salida no primaria del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no le dirá si la copia de trabajo fue capturada en una instantánea o si los descendientes fueron rebasados.

Las advertencias y los errores seguirán imprimiéndose.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves con puntos de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado en ningún constructo TOML (como la notación de matriz), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
