NOMBRE

jj-bookmark-delete - Eliminar un marcador existente y propagar la eliminación a los remotos en el próximo push

SINOPSIS

jj bookmark delete [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <NOMBRES>

DESCRIPCIÓN

Eliminar un marcador existente y propagar la eliminación a los remotos en el próximo push.

Las revisiones a las que se refieren los marcadores eliminados no se abandonan. Para eliminar revisiones además de marcadores, usa `jj abandon`. Por ejemplo, `jj abandon main..<marcador>` abandonará las revisiones pertenecientes a la rama `<marcador>` (relativa a la rama `main`.)

Si no deseas que la eliminación del marcador local se propague a ningún marcador remoto rastreado, usa `jj bookmark forget` en su lugar.

OPCIONES

-h, --help
Imprimir ayuda (ver resumen con '-h')
<NOMBRES>
Los marcadores a eliminar

Por defecto, el nombre especificado coincide exactamente. Usa el prefijo `glob:` para seleccionar marcadores por [patrón comodín].

[patrón comodín]: https://docs.jj-vcs.dev/latest/revsets/#string-patterns

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No tomar instantánea del área de trabajo y no actualizarla

Por defecto, Jujutsu toma una instantánea del área de trabajo al inicio de cada comando. El área de trabajo también se actualiza al final del comando, si el comando modificó el commit del área de trabajo (`@`). Si deseas evitar tomar instantáneas del área de trabajo y ver en su lugar un commit del área de trabajo posiblemente desactualizado, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tienes otro proceso que confirma el área de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescritura de commits inmutables

Por defecto, Jujutsu evita la reescritura de commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y te permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puedes usar `--at-op=<ID de operación>` para ver cómo se veía el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` te mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Usa `jj op log` para encontrar el ID de operación que deseas. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignorará el área de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutantes al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes a partir de la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilitar registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[valores posibles: always, never, debug, auto]

--quiet
Silenciar la salida no primaria del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no te dirá si se tomó una instantánea del área de trabajo o si se reorganizaron los descendientes.

Las advertencias y errores aún se imprimirán.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves puntuales de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado en ningún constructo de TOML (como la notación de array), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
