NOMBRE

jj-util-config-schema - Imprimir el esquema JSON para el formato de configuración TOML de jj

SINOPSIS

jj util config-schema [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help]

DESCRIPCIÓN

Imprimir el esquema JSON para el formato de configuración TOML de jj

OPCIONES

-h, --help
Imprimir ayuda (ver un resumen con '-h')

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No guardar instantánea de la copia de trabajo y no actualizarla

Por defecto, Jujutsu guarda una instantánea de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si desea evitar guardar una instantánea de la copia de trabajo y ver en su lugar un commit de copia de trabajo posiblemente desactualizado, puede usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en un prompt de comandos, especialmente si tiene otro proceso que hace commits de la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescritura de commits inmutables

Por defecto, Jujutsu previene la reescritura de commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa comprobación y le permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la comprobación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puede usar `--at-op=<ID de operación>` para ver cómo era el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` le mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor por defecto, excepto que las operaciones divergentes nunca se fusionarán.

Use `jj op log` para encontrar el ID de operación que desea. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignorará la copia de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repositorio en una operación anterior. Hacer eso es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacer eso, pero es posible.

--debug
Habilitar registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[valores posibles: always, never, debug, auto]

--quiet
Silenciar la salida de comandos no primarios

Por ejemplo, `jj file list` seguirá listando archivos, pero no le dirá si la copia de trabajo fue guardada o si los descendientes fueron rebasados.

Las advertencias y errores se seguirán imprimiendo.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves separadas por puntos de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado en ninguna construcción de TOML (como la notación de matriz), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
config-schema
