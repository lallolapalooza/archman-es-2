jmap(1) Herramientas de solución de problemas jmap(1)

NOMBRE

jmap - Imprime mapas de memoria de objetos compartidos o detalles de memoria del montón para un proceso, archivo core o servidor de depuración remoto. Este comando es experimental y no está soportado.

SINOPSIS

jmap [ opciones ] pid
jmap [ opciones ] ejecutable core
jmap [ opciones ] [ pid ] id_servidor@ ] nombre_host_o_IP_remoto
opciones
Las opciones de línea de comandos. Ver Opciones.
pid
El ID del proceso para el cual se imprimirá el mapa de memoria. El proceso debe ser un proceso Java. Para obtener una lista de los procesos Java en ejecución en una máquina, use el comando jps(1).
ejecutable
El ejecutable Java del cual se produjo el volcado core.
core
El archivo core para el cual se imprimirá el mapa de memoria.
nombre_host_o_IP_remoto
El nombre de host o dirección IP del servidor de depuración remoto. Ver jsadebugd(1).
id_servidor
Un ID único opcional para usar cuando varios servidores de depuración se ejecutan en el mismo host remoto.

DESCRIPCIÓN

El comando jmap imprime mapas de memoria de objetos compartidos o detalles de memoria del montón de un proceso especificado, archivo core o servidor de depuración remoto. Si el proceso especificado se está ejecutando en una Máquina Virtual Java (JVM) de 64 bits, es posible que deba especificar la opción -J-d64, por ejemplo: jmap-J-d64 -heap pid.

Nota: Esta utilidad no está soportada y podría no estar disponible en futuras versiones del JDK. En sistemas Windows donde el archivo dbgeng.dll no está presente, se deben instalar las Herramientas de depuración para Windows para que estas herramientas funcionen. La variable de entorno PATH debe contener la ubicación del archivo jvm.dll que utiliza el proceso de destino o la ubicación desde la cual se produjo el archivo de volcado de fallos, por ejemplo: set PATH=%JDK_HOME%\jre\bin\client;%PATH%.

OPCIONES

<sin opción>
Cuando no se utiliza ninguna opción, el comando jmap imprime las asignaciones de objetos compartidos. Para cada objeto compartido cargado en la JVM de destino, se imprimen la dirección de inicio, el tamaño de la asignación y la ruta completa del archivo del objeto compartido. Este comportamiento es similar a la utilidad pmap de Oracle Solaris.
-dump:[live,] formato=b, archivo=nombre_archivo

Vuelca el montón de Java en formato binario hprof al nombre_archivo. La subopción live es opcional, pero cuando se especifica, solo se vuelcan los objetos activos en el montón. Para examinar el volcado del montón, puede usar el comando jhat(1) para leer el archivo generado.
-finalizerinfo

Imprime información sobre los objetos que están esperando la finalización.
-heap

Imprime un resumen del montón del recolector de basura utilizado, la configuración del montón y el uso del montón por generación. Además, se imprimen el número y el tamaño de las Strings internadas.
- histo[:live]

Imprime un histograma del montón. Para cada clase Java, se imprimen el número de objetos, el tamaño de la memoria en bytes y los nombres de clase completos. Los nombres de clase internos de la JVM se imprimen con un prefijo de asterisco (*). Si se especifica la subopción live, entonces solo se cuentan los objetos activos.
-clstats

Imprime estadísticas de los cargadores de clases del montón de Java. Para cada cargador de clases, se imprimen su nombre, su actividad, dirección, cargador de clases padre y el número y tamaño de las clases que ha cargado.
-F

Forzar. Use esta opción con la opción jmap -dump o jmap -histo cuando el pid no responde. La subopción live no es compatible en este modo.
-h

Imprime un mensaje de ayuda.
-help

Imprime un mensaje de ayuda.
-Jbandera

Pasa bandera a la Máquina Virtual Java donde se ejecuta el comando jmap.
