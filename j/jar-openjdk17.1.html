JAR(1) Comandos JDK JAR(1)

NOMBRE

jar - crea un archivo para clases y recursos, y manipula o restaura clases o recursos individuales de un archivo

SINOPSIS

jar [OPCIÓN ...] [ [--release VERSIÓN] [-C dir] archivos] ...

DESCRIPCIÓN

El comando jar es una herramienta de archivado y compresión de propósito general, basada en los formatos de compresión ZIP y ZLIB. Inicialmente, el comando jar fue diseñado para empaquetar applets de Java (no soportado desde JDK 11) o aplicaciones; sin embargo, a partir del JDK 9, los usuarios pueden usar el comando jar para crear JARs modulares. Para transporte y despliegue, generalmente es más conveniente empaquetar módulos como JARs modulares.

La sintaxis para el comando jar se parece a la sintaxis del comando tar. Tiene varios modos de operación principales, definidos por uno de los argumentos de operación obligatorios. Otros argumentos son opciones que modifican el comportamiento de la operación o son necesarios para realizar la operación.

Cuando los módulos o los componentes de una aplicación (archivos, imágenes y sonidos) se combinan en un solo archivo, pueden ser descargados por un agente de Java (como un navegador) en una única transacción HTTP, en lugar de requerir una nueva conexión para cada pieza. Esto mejora drásticamente los tiempos de descarga. El comando jar también comprime archivos, lo que mejora aún más el tiempo de descarga. El comando jar también permite firmar entradas individuales en un archivo para que su origen pueda ser autenticado. Un archivo JAR puede ser usado como una entrada de ruta de clases, ya sea que esté comprimido o no.

Un archivo se convierte en un JAR modular cuando incluyes un descriptor de módulo, module-info.class, en la raíz de los directorios dados o en la raíz del archivo .jar. Las siguientes operaciones descritas en Modificadores de Operación Válidos Solo en Modos de Creación y Actualización son válidas solo al crear o actualizar un JAR modular o actualizar un JAR no modular existente:

•
--module-version
•
--hash-modules
•
--module-path

Nota:

Todos los argumentos obligatorios u opcionales para las opciones largas son también obligatorios u opcionales para cualquier opción corta correspondiente.

MODOS DE OPERACIÓN PRINCIPALES

Al usar el comando jar, debes especificar la operación que deseas que realice. Especificas el modo de operación para el comando jar incluyendo los argumentos de operación apropiados descritos en esta sección. Puedes mezclar un argumento de operación con otras opciones de una sola letra. Generalmente, el argumento de operación es el primer argumento especificado en la línea de comandos.

-c o --create
Crea el archivo.
-i=ARCHIVO o --generate-index=ARCHIVO
Genera información de índice para el archivo JAR especificado.
-t o --list
Lista la tabla de contenido del archivo.
-u o --update
Actualiza un archivo JAR existente.
-x o --extract
Extrae los archivos nombrados (o todos) del archivo.
-d o --describe-module
Imprime el descriptor del módulo o el nombre del módulo automático.

MODIFICADORES DE OPERACIÓN VÁLIDOS EN CUALQUIER MODO

Puedes usar las siguientes opciones para personalizar las acciones de cualquier modo de operación incluido en el comando jar.

-C DIR
Cambia al directorio especificado e incluye los archivos especificados al final de la línea de comandos.

jar [OPCIÓN ...] [ [--release VERSIÓN] [-C dir] archivos]

-f=ARCHIVO o --file=ARCHIVO
Especifica el nombre del archivo de archivo.
--release VERSIÓN
Crea un archivo JAR multiversión. Coloca todos los archivos especificados después de la opción en un directorio versionado del archivo JAR llamado META-INF/versions/VERSIÓN/, donde VERSIÓN debe ser un entero positivo cuyo valor sea 9 o mayor.

En tiempo de ejecución, cuando existe más de una versión de una clase en el JAR, el JDK usará la primera que encuentre, buscando inicialmente en el árbol de directorios cuyo número de VERSIÓN coincida con el número de versión principal del JDK. Luego buscará en directorios con números de VERSIÓN sucesivamente menores, y finalmente buscará en la raíz del JAR.

-v o --verbose
Envía o imprime salida detallada a la salida estándar.

MODIFICADORES DE OPERACIÓN VÁLIDOS SOLO EN MODOS DE CREACIÓN Y ACTUALIZACIÓN

Puedes usar las siguientes opciones para personalizar las acciones de los modos de operación principales de creación y actualización:

-e=NOMBRE_CLASE o --main-class= NOMBRE_CLASE
Especifica el punto de entrada de la aplicación para aplicaciones independientes empaquetadas en un JAR modular o ejecutable.
-m=ARCHIVO o --manifest=ARCHIVO
Incluye la información del manifiesto del archivo de manifiesto dado.
-M o --no-manifest
No crea un archivo de manifiesto para las entradas.
--module-version=VERSIÓN
Especifica la versión del módulo al crear o actualizar un archivo JAR modular, o al actualizar un archivo JAR no modular.
--hash-modules=PATRÓN
Calcula y registra los hashes de los módulos que coinciden con el patrón dado y que dependen directa o indirectamente de un archivo JAR modular que se está creando o de un archivo JAR no modular que se está actualizando.
-p o --module-path
Especifica la ubicación de la dependencia del módulo para generar el hash.
@archivo
Lee las opciones de jar y los nombres de archivos de un archivo de texto como si hubieran sido proporcionados en la línea de comandos

MODIFICADORES DE OPERACIÓN VÁLIDOS SOLO EN CREATE, UPDATE Y

GENERATE-INDEX MODES

Puede usar las siguientes opciones para personalizar las acciones de los modos de operación principales create ( -c o --create ), update ( -u o --update ) y generate-index ( -i o --generate-index=FILE ):

-0 o --no-compress
Almacena sin usar compresión ZIP.

OTRAS OPCIONES

Las siguientes opciones son reconocidas por el comando jar y no se usan con los modos de operación:

-h o --help[:compat]
Muestra la ayuda de la línea de comandos para el comando jar o, opcionalmente, la ayuda de compatibilidad.
--help-extra
Muestra ayuda sobre opciones adicionales.
--version
Imprime la versión del programa.

EJEMPLOS DE SINTAXIS DEL COMANDO JAR

•
Crea un archivo, classes.jar, que contiene dos archivos de clase, Foo.class y Bar.class.

jar --create --file classes.jar Foo.class Bar.class

•
Crea un archivo, classes.jar, utilizando un manifest existente, mymanifest, que contiene todos los archivos del directorio foo/.

jar --create --file classes.jar --manifest mymanifest -C foo/

•
Crea un archivo JAR modular, foo.jar, donde el descriptor del módulo se encuentra en classes/module-info.class.

jar --create --file foo.jar --main-class com.foo.Main --module-version 1.0 -C foo/classes resources

•
Actualiza un archivo JAR no modular existente, foo.jar, a un archivo JAR modular.

jar --update --file foo.jar --main-class com.foo.Main --module-version 1.0 -C foo/module-info.class

•
Crea un archivo JAR con versiones o multi-release, foo.jar, que coloca los archivos del directorio classes en la raíz del JAR, y los archivos del directorio classes-10 en el directorio META-INF/versions/10 del JAR.

En este ejemplo, el directorio classes/com/foo contiene dos clases, com.foo.Hello (la clase de punto de entrada) y com.foo.NameProvider, ambas compiladas para JDK 8. El directorio classes-10/com/foo contiene una versión diferente de la clase com.foo.NameProvider, esta contiene código específico de JDK 10 y compilada para JDK 10.

Dado este escenario, crea un archivo JAR multi-release foo.jar ejecutando el siguiente comando desde el directorio que contiene los directorios classes y classes-10.

jar --create --file foo.jar --main-class com.foo.Hello -C classes . --release 10 -C classes-10 .

El archivo JAR foo.jar ahora contiene:


% jar -tf foo.jar
META-INF/
META-INF/MANIFEST.MF
com/
com/foo/
com/foo/Hello.class
com/foo/NameProvider.class
META-INF/versions/10/com/
META-INF/versions/10/com/foo/
META-INF/versions/10/com/foo/NameProvider.class

Además de otra información, el archivo META-INF/MANIFEST.MF contendrá las siguientes líneas para indicar que este es un archivo JAR multi-release con un punto de entrada de com.foo.Hello.


...
Main-Class: com.foo.Hello
Multi-Release: true

Suponiendo que la clase com.foo.Hello llama a un método en la clase com.foo.NameProvider, ejecutar el programa usando JDK 10 asegurará que la clase com.foo.NameProvider sea la que se encuentra en META-INF/versions/10/com/foo/. Ejecutar el programa usando JDK 8 asegurará que la clase com.foo.NameProvider sea la que está en la raíz del JAR, en com/foo.

•
Crea un archivo, my.jar, leyendo opciones y listas de archivos de clase desde el archivo classes.list.

Nota:

Para acortar o simplificar el comando jar, puede especificar argumentos en un archivo de texto separado y pasarlo al comando jar con el signo arroba (@) como prefijo.

Para acortar o simplificar el comando jar, puede proporcionar un archivo de argumentos que liste los archivos a incluir en el archivo JAR y pasarlo al comando jar con el signo arroba (@) como prefijo.

jar --create --file my.jar @classes.list

Si una o más entradas en el archivo de argumentos no se encuentran, el comando jar falla sin crear el archivo JAR.
