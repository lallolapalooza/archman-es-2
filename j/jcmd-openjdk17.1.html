DESCRIPCIÓ

N

La utilidad jcmd se utiliza para enviar solicitudes de comandos de diagnóstico a la JVM. Debe usarse en la misma máquina en la que se está ejecutando la JVM, y tener los mismos identificadores efectivos de usuario y grupo que se utilizaron para iniciar la JVM. Cada comando de diagnóstico tiene su propio conjunto de argumentos. Para mostrar la descripción, la sintaxis y una lista de los argumentos disponibles para un comando de diagnóstico, utilice el nombre del comando como argumento. Por

ejemplo:

jcmd pid help comma

n
d

Si los argumentos contienen espacios, debe rodearlos con comillas simples o dobles (' o "). Además, debe escapar las comillas simples o dobles con una barra invertida (\) para evitar que el shell del sistema operativo procese las comillas. Alternativamente, puede rodear estos argumentos con comillas simples y luego con comillas dobles (o con comillas dobles y luego con comillas simples)

.

Si especifica el identificador de proceso (pid) o la clase principal (main-class) como primer argumento, la utilidad jcmd envía la solicitud del comando de diagnóstico al proceso Java con el identificador especificado o a todos los procesos Java con el nombre especificado de la clase principal. También puede enviar la solicitud del comando de diagnóstico a todos los procesos Java disponibles especificando 0 como identific

ador de
proceso.

JFR.configure [opciones]
Establece los parámetros para una grabación de vuelo.

Impacto: Bajo

Nota:

Las opciones deben especificarse usando la sintaxis de clave o clave=valor. Si no se ingresan parámetros, se muestran la configuración actual.

opciones:

•
globalbuffercount: (Opcional) Número de búferes globales. Esta opción es una opción heredada: cambie el parámetro memorysize para alterar el número de búferes globales. Este valor no se puede cambiar una vez que JFR se ha inicializado. (STRING, el valor predeterminado está determinado por el valor de memorysize)
•
globalbuffersize: (Opcional) Tamaño de los búferes globales, en bytes. Esta opción es una opción heredada: cambie el parámetro memorysize para alterar el tamaño de los búferes globales. Este valor no se puede cambiar una vez que JFR se ha inicializado. (STRING, el valor predeterminado está determinado por el valor de memorysize)
•
maxchunksize: (Opcional) Tamaño máximo de un fragmento de datos individual en bytes si no se utiliza uno de los siguientes sufijos: 'm' o 'M' para megabytes O 'g' o 'G' para gigabytes. Este valor no se puede cambiar una vez que JFR se ha inicializado. (STRING, 12M)
•
memorysize: (Opcional) Tamaño total de memoria, en bytes si no se utiliza uno de los siguientes sufijos: 'm' o 'M' para megabytes O 'g' o 'G' para gigabytes. Este valor no se puede cambiar una vez que JFR se ha inicializado. (STRING, 10M)
•
repositorypath: (Opcional) Ruta a la ubicación donde se almacenan las grabaciones hasta que se escriben en un archivo permanente. (STRING, la ubicación predeterminada es el directorio temporal del sistema operativo. En sistemas operativos Linux, el directorio temporal es /tmp. En Windows, el directorio temporal se especifica mediante la variable de entorno TMP.)
•
stackdepth: (Opcional) Profundidad de la pila para rastreos de pila. Establecer este valor por encima del valor predeterminado de 64 puede causar una degradación del rendimiento. Este valor no se puede cambiar una vez que JFR se ha inicializado. (LONG, 64)
•
thread_buffer_size: (Opcional) Tamaño del búfer local para cada hilo en bytes si no se utiliza uno de los siguientes sufijos: 'k' o 'K' para kilobytes o 'm' o 'M' para megabytes. Sobrescribir este parámetro podría reducir el rendimiento y no se recomienda. Este valor no se puede cambiar una vez que JFR se ha inicializado. (STRING, 8k)
•
samplethreads: (Opcional) Indicador para activar el muestreo de hilos. (BOOLEAN, true)
JFR.dump [opciones]
Escribe datos en un archivo mientras una grabación de vuelo está en ejecución.

Impacto: Bajo

Nota:

Las opciones deben especificarse usando la sintaxis de clave o clave=valor. No se requieren opciones. La grabación continúa ejecutándose después de que se escriben los datos.

opciones:

•
begin: (Opcional) Especifica la hora desde la cual los datos de la grabación se incluirán en el archivo de volcado. El formato se especifica como hora local. (STRING, sin valor predeterminado)
•
end: (Opcional) Especifica la hora hasta la cual los datos de la grabación se incluirán en el archivo de volcado. El formato se especifica como hora local. (STRING, sin valor predeterminado)

Nota: Para begin y end, la hora debe estar en un formato que pueda ser leído por java.time.LocalTime::parse(STRING), java.time.LocalDateTime::parse(STRING) o java.time.Instant::parse(STRING). Por ejemplo, "13:20:15", "2020-03-17T09:00:00" o "2020-03-17T09:00:00Z".

Nota: Las horas de begin y end corresponden a las marcas de tiempo que se encuentran dentro de la información grabada en los datos de la grabación de vuelo.

Otra opción es usar una hora relativa a la hora actual que se especifica mediante un entero negativo seguido de "s", "m" o "h". Por ejemplo, "-12h", "-15m" o "-30s"

filename: (Opcional) Nombre del archivo en el que se vuelcan los datos de la grabación de vuelo. •
maxage: (Opcional) Duración para volcar los datos de la grabación de vuelo a un archivo. (INTEGER seguido de 's' para segundos, 'm' para minutos o 'h' para horas, sin valor predeterminado)

jcmd 1.0 2024-05-20
The jcmd utility is a multi-purpose tool that can be used to send diagnostic command requests to a running Java™ application. It can be used to perform many of the same operations as jps, jstack, jmap, jhat, and jstat, but in a unified command set.
jcmd [options] pid command [command options] jcmd [options] main-class command [command options] jcmd [options] command [command options] jcmd -f command [command options]

The following options are available:

-h
Print help message.
-f <file>
Specifies a file containing a list of pids.
-l
List all running Java HotSpot VMs on the target system. The output is a list of JVMs, each of which contains a process ID and the main class name or JAR file name of the application.
-J<flags>
Option passed to the jcmd command, on the java command line.
-x
Launch the JVM with the specified X flags. For example, -Xmx1g.

The following commands are available:

Heap.dump [options]
Dumps the Java heap.

Impact: Low --- no impact

Permission: java.lang.management.ManagementPermission(monitor)

options:

•
all-live-heaps: (Optional) Dump all live heaps. (BOOLEAN, false)
•
live: (Optional) Dump only live objects. (BOOLEAN, false)
•
format: (Optional) Specify the heap dump format. Supported formats are
†
jfr,
†
bin. Default is
†
bin. (STRING, default: "bin")
•
file: (Optional) Specify the heap dump file name. If not specified, a default file name is chosen using the pid of the target JVM process. For example, java_pid1234.hprof.
ManagementAgent.start
Starts the remote management agent. This command is deprecated. Use ManagementAgent.start_local instead.

Impact: Low --- no impact

Permission: java.lang.management.ManagementPermission(control)

The following system properties can be used to configure the remote management agent:

•
com.sun.management.agent.port: (Optional) Sets the port number for the RMI connector. (INT, no default value)
•
com.sun.management.agent.rmi.local: (Optional) Forces the RMI connector to use the local interface address. (BOOLEAN, no default value)
•
com.sun.management.jmxremote.host: (Optional) Sets the hostname for the RMI connector. (STRING, no default value)
•
com.sun.management.jmxremote.port: (Optional) Sets the port number for the RMI connector. (INT, no default value)
•

•
filename: (Optional) Name of the shared archive to be dumped (STRING, no default value)

If filename is not specified, a default file name is chosen using the pid of the target JVM process. For example, java_pid1234_static.jsa, java_pid5678_dynamic.jsa, etc.

If filename is not specified as an absolute path, the archive file is created in a directory relative to the current directory of the target JVM process.
