jsadebugd(1) Herramientas de solución de problemas jsadebugd(1)

NOMBRE

jsadebugd - Se conecta a un proceso Java o a un archivo core y actúa como un servidor de depuración. Este comando es experimental y no está soportado.

SINOPSIS

jsadebugd pid [ id-servidor ]
jsadebugd ejecutable core [ id-servidor ]
pid
El ID del proceso al que se conecta el servidor de depuración. El proceso debe ser un proceso Java. Para obtener una lista de los procesos Java que se ejecutan en una máquina, use el comando jps(1). Como máximo, una instancia del servidor de depuración puede conectarse a un solo proceso.
ejecutable
El ejecutable Java del cual se produjo el volcado core.
core
El archivo core al que debe adjuntarse el servidor de depuración.
id-servidor
Un ID único opcional que es necesario cuando se inician varios servidores de depuración en la misma máquina. Este ID debe ser utilizado por los clientes remotos para identificar el servidor de depuración específico al que conectarse. Dentro de una sola máquina, este ID debe ser único.

DESCRIPCIÓN

El comando jsadebugd se conecta a un proceso Java o a un archivo core y actúa como un servidor de depuración. Los clientes remotos como jstack, jmap y jinfo pueden conectarse al servidor a través de Java Remote Method Invocation (RMI). Antes de iniciar el comando jsadebugd, inicie el registro RMI con el comando rmiregistry de la siguiente manera, donde $JAVA_HOME es el directorio de instalación del JDK:

rmiregistry -J-Xbootclasspath/p:$JAVA_HOME/lib/sajdi.jar

Si el registro RMI no se inició, el comando jsadebugd inicia un registro RMI en un puerto estándar (1099) internamente. El servidor de depuración se puede detener enviándole una señal SIGINT. Para enviar una SIGINT, presione Ctrl+C.

Nota: Esta utilidad no está soportada y puede estar o no disponible en futuras versiones del JDK. En sistemas Windows donde dbgeng.dll no está presente, se deben instalar las Herramientas de depuración para Windows para que estas herramientas funcionen. La variable de entorno PATH debe contener la ubicación de jvm.dll utilizada por el proceso objetivo o la ubicación desde la que se produjo el archivo de volcado de bloqueo. Por ejemplo, set PATH=%JDK_HOME%\jre\bin\client;%PATH%.
