NOMBRE

jmod - crea archivos JMOD y lista el contenido de archivos JMOD existentes

SINOPSIS

jmod (create|extract|list|describe|hash) [opciones] archivo-jmod

Incluye lo siguiente:

Modos de operación principales

create
Crea un nuevo archivo de archivo JMOD.
extract
Extrae todos los archivos del archivo JMOD.
list
Imprime los nombres de todas las entradas.
describe
Imprime los detalles del módulo.
hash
Determina los módulos hoja y registra los hashes de las dependencias que los requieren directa e indirectamente.

Opciones

opciones
Ver Opciones para jmod.

Requerido

archivo-jmod
Especifica el nombre del archivo JMOD a crear o del cual recuperar información.

DESCRIPCIÓN

Nota: Para la mayoría de las tareas de desarrollo, incluida la implementación de módulos en la ruta de módulos o su publicación en un repositorio de Maven, continúe empaquetando módulos en archivos JAR modulares. La herramienta jmod está destinada a módulos que tienen bibliotecas nativas u otros archivos de configuración, o para módulos que pretende enlazar, con la herramienta jlink, a una imagen de tiempo de ejecución.

El formato de archivo JMOD le permite agregar archivos que no sean archivos .class, metadatos y recursos. Este formato es transportable pero no ejecutable, lo que significa que puede usarlo durante el tiempo de compilación o el tiempo de enlace, pero no en tiempo de ejecución.

Muchas opciones de jmod implican especificar una ruta cuyos contenidos se copian en los archivos JMOD resultantes. Estas opciones copian todos los contenidos de la ruta especificada, incluidos los subdirectorios y sus contenidos, pero excluyen los archivos cuyos nombres coinciden con el patrón especificado por la opción --exclude.

Con la opción --hash-modules o el comando jmod hash, puede, en el descriptor de cada módulo, registrar hashes del contenido de los módulos que tienen permitido depender de él, "vinculando" así estos módulos. Esto permite que un paquete se exporte a uno o más módulos con nombre específico y a ningún otro a través de exportaciones calificadas. El tiempo de ejecución verifica si el hash registrado de un módulo coincide con el resuelto en tiempo de ejecución; si no es así, el tiempo de ejecución devuelve un error.

OPCIONES PARA JMOD

--class-path ruta
Especifica la ubicación de los archivos JAR de la aplicación o un directorio que contiene clases para copiar en el archivo JMOD resultante.
--cmds ruta
Especifica la ubicación de los comandos nativos para copiar en el archivo JMOD resultante.
--compress compresión
Especifica la compresión a utilizar al crear el archivo JMOD. Los valores aceptados son zip-[0-9], donde zip-0 no proporciona compresión y zip-9 proporciona la mejor compresión. El valor predeterminado es zip-6.
--config ruta
Especifica la ubicación de los archivos de configuración editables por el usuario para copiar en el archivo JMOD resultante.
--dateFECHA-HORA
La marca de tiempo en formato extendido ISO-8601 de fecha y hora con desplazamiento opcional, para usar como marca de tiempo de las entradas, por ejemplo, "2022-02-12T12:30:00-05:00".
--dir ruta
Especifica la ubicación donde jmod coloca los archivos extraídos del archivo JMOD especificado.
--dry-run
Realiza una ejecución de prueba del modo hash. Identifica los módulos hoja y sus módulos requeridos sin registrar ningún valor de hash.
--exclude lista-de-patrones
Excluye archivos que coinciden con la lista de patrones separada por comas proporcionada, cada elemento utiliza una de las siguientes formas:
•
patrón-glob
•
glob:patrón-glob
•
regex:patrón-regex

Ver el método FileSystem.getPathMatcher para la sintaxis de patrón-glob. Ver la clase Pattern para la sintaxis de patrón-regex, que representa una expresión regular.

--hash-modules patrón-regex
Determina los módulos hoja y registra los hashes del contenido de las dependencias que los requieren directa e indirectamente, basándose en el grafo de módulos de los módulos que coinciden con el patrón-regex dado. Los hashes se registran en el archivo JMOD que se está creando, o en un archivo JMOD o JAR modular en la ruta del módulo especificada por el comando jmod hash.
--header-files ruta
Especifica la ubicación de los archivos de cabecera para copiar en el archivo JMOD resultante.
--help o -h
Imprime un mensaje de uso.
--help-extra
Imprime ayuda para opciones adicionales.
--legal-notices ruta
Especifica la ubicación de los avisos legales para copiar en el archivo JMOD resultante.
--libs ruta
Especifica la ubicación de las bibliotecas nativas para copiar en el archivo JMOD resultante.
--main-class nombre-clase
Especifica la clase principal a registrar en el archivo module-info.class.
--man-pages ruta
Especifica la ubicación de las páginas man para copiar en el archivo JMOD resultante.
--module-version versión-módulo
Especifica la versión del módulo a registrar en el archivo module-info.class.
--module-path ruta o -p ruta
Especifica la ruta del módulo. Esta opción es obligatoria si también se especifica --hash-modules.
--target-platform plataforma
Especifica la plataforma de destino.
--version
Imprime información de la versión de la herramienta jmod.
@nombre-archivo
Lee las opciones del archivo especificado.

Un archivo de opciones es un archivo de texto que contiene las opciones y los valores que normalmente introduciría en la línea de comandos. Las opciones pueden aparecer en una o varias líneas. No puede especificar variables de entorno para nombres de ruta. Puede comentar líneas anteponiendo un símbolo de almohadilla (#) al principio de la línea.

El siguiente es un ejemplo de un archivo de opciones para el comando jmod:


#Mie Dic 07 00:40:19 EST 2016
create --class-path mods/com.greetings --module-path mlib
  --cmds commands --config configfiles --header-files src/h
  --libs lib --main-class com.greetings.Main
  --man-pages man --module-version 1.0
  --os-arch "x86_x64" --os-name "macOS"
  --os-version "10.10.5" greetingsmod

OPCIONES ADICIONALES PARA JMOD

Además de las opciones descritas en Opciones para jmod, las siguientes son opciones adicionales que se pueden usar con el comando.

--do-not-resolve-by-default
Excluir del conjunto raíz predeterminado de módulos
--warn-if-resolved
Indicación para que una herramienta emita una advertencia si el módulo se resuelve. Uno de deprecated, deprecated-for-removal, o incubating.

EJEMPLO DE CREACIÓN DE JMOD

El siguiente es un ejemplo de creación de un archivo JMOD:


jmod create --class-path mods/com.greetings --cmds commands
  --config configfiles --header-files src/h --libs lib
  --main-class com.greetings.Main --man-pages man --module-version 1.0
  --os-arch "x86_x64" --os-name "macOS"
  --os-version "10.10.5" greetingsmod

Crea un archivo JMOD especificando la fecha de las entradas como 15 de marzo de 2022 00:00:00:


jmod create --class-path build/foo/classes --date 2022-03-15T00:00:00Z
   jmods/foo1.jmod

NAME

jmod - create module archives

SYNOPSIS

jmod create [OPTIONS] jmod-file module-root

jmod extract [OPTIONS] jmod-file

jmod list [OPTIONS] jmod-file

jmod describe [OPTIONS] jmod-file

jmod hash [OPTIONS] jmod-file

DESCRIPTION

The jmod tool creates and updates module archives (JMOD files). A JMOD file is a ZIP archive that contains module code and resources. It is a successor to the modular JAR file, and is used by the JDK itself to distribute modularized JDK components.

A JMOD file contains the following files and directories:

module-info.class
The compiled module descriptor.
classes
A directory containing the compiled classes of the module.
lib
A directory containing native libraries required by the module.
resources
A directory containing module resources.
.jlink
A directory containing files used by the jlink tool, such as the module hash.

The jmod tool operates on a module root directory, which is a directory that contains the module's compiled classes and resources. The module root directory must also contain a module-info.java file (or module-info.class if already compiled).

OPTIONS FOR JMOD

--class-path classpath
Specifies the classpath for finding classes and resources.
--help
Display help information for the jmod command.
--module-path modulepath
Specifies the path to a directory of modules.
-q, --quiet
Suppress informational output.
-v, --verbose
Enable verbose output.
--version
Display version information for the jmod tool.

EXTRA OPTIONS FOR JMOD

The following options are available for the jmod create, jmod hash, and jmod describe commands:

--hash-modules module-list
Specifies a comma-separated list of modules for which to compute and record hash values. The default is to compute hash values for all modules in the module path.
--dry-run
Perform a dry run of the jmod hash command, printing the computed hash values without recording them in the JMOD archives.

JMOD CREATE EXAMPLE

Create a JMOD archive for a module named ma, located in the mods/ma directory:

jmod create --class-path mods/ma jmods/ma.jmod

JMOD HASH EXAMPLE

This example demonstrates what happens when you try to link a leaf module (in this example, ma) with a required module (mb), and the hash value recorded in the required module does not match that of the leaf module.

1.
Create and compile the following .java files:
•
jmodhashex/src/ma/module-info.java

module ma {
  requires mb;
}
•
jmodhashex/src/mb/module-info.java

module mb {
}
•
jmodhashex2/src/ma/module-info.java

module ma {
  requires mb;
}
•
jmodhashex2/src/mb/module-info.java

module mb {
}
2.
Create a JMOD archive for each module. Create the directories jmodhashex/jmods and jmodhashex2/jmods, and then run the following commands from the jmodhashex directory, then from the jmodhashex2 directory:
•
jmod create --class-path mods/ma jmods/ma.jmod
•
jmod create --class-path mods/mb jmods/mb.jmod
3.
Optionally preview the jmod hash command. Run the following command from the jmodhashex directory:

jmod hash --dry-run -module-path jmods --hash-modules .*

The command prints the following:


Dry run:
mb
  hashes ma SHA-256 07667d5032004b37b42ec2bb81b46df380cf29e66962a16481ace2e71e74073a

This indicates that the jmod hash command (without the --dry-run option) will record the hash value of the leaf module ma in the module mb.

4.
Record hash values in the JMOD archive files contained in the jmodhashex directory. Run the following command from the jmodhashex directory:

jmod hash --module-path jmods --hash-modules .*

The command prints the following:

Hashes are recorded in module mb

5.
Print information about each JMOD archive contained in the jmodhashex directory. Run the highlighted commands from the jmodhashex directory:

jmod describe jmods/ma.jmod
ma
  requires mandated java.base
  requires mb
jmod describe jmods/mb.jmod
mb
  requires mandated java.base
  hashes ma SHA-256 07667d5032004b37b42ec2bb81b46df380cf29e66962a16481ace2e71e74073a
6.
Attempt to create a runtime image that contains the module ma from the directory jmodhashex2 but the module mb from the directory jmodhashex. Run the following command from the jmodhashex2 directory:
•
Linux and macOS:

jlink --module-path $JAVA_HOME/jmods:jmods/ma.jmod:../jmodhashex/jmods/mb.jmod --add-modules ma --output ma-app

•
Windows:

jlink --module-path %JAVA_HOME%/jmods;jmods/ma.jmod;../jmodhashex/jmods/mb.jmod --add-modules ma --output ma-app

The command prints an error message similar to the following:


Error: Hash of ma (a2d77889b0cb067df02a3abc39b01ac1151966157a68dc4241562c60499150d2) differs to
expected hash (07667d5032004b37b42ec2bb81b46df380cf29e66962a16481ace2e71e74073a) recorded in mb
