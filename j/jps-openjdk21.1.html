JPS(1) Comandos JDK JPS(1)

NOMBRE

jps - lista las JVM instrumentadas en el sistema destino

SINOPSIS

Nota: Este comando es experimental y no está soportado.

jps [-q] [-mlvV] [hostid]

jps [-help]

OPCIONES

-q
Suprime la salida del nombre de la clase, nombre del archivo JAR y argumentos pasados al método principal, produciendo una lista solo de identificadores locales de JVM.
-mlvV
Puede especificar cualquier combinación de estas opciones.
•
-m muestra los argumentos pasados al método principal. La salida puede ser nula para JVM incrustadas.
•
-l muestra el nombre completo del paquete de la clase principal de la aplicación o la ruta completa al archivo JAR de la aplicación.
•
-v muestra los argumentos pasados a la JVM.
•
-V suprime la salida del nombre de la clase, nombre del archivo JAR y argumentos pasados al método principal, produciendo una lista solo de identificadores locales de JVM.
hostid
El identificador del host para el cual se generará el informe del proceso. El hostid puede incluir componentes opcionales que indican el protocolo de comunicaciones, número de puerto y otros datos específicos de la implementación. Ver Identificador de Host.
-help
Muestra el mensaje de ayuda para el comando jps.

DESCRIPCIÓN

El comando jps lista las Java HotSpot VMs instrumentadas en el sistema destino. El comando se limita a informar información sobre las JVMs para las cuales tiene permisos de acceso.

Si el comando jps se ejecuta sin especificar un hostid, busca JVMs instrumentadas en el host local. Si se inicia con un hostid, busca JVMs en el host indicado, utilizando el protocolo y puerto especificados. Se asume que un proceso jstatd se está ejecutando en el host destino.

El comando jps informa el identificador local de JVM, o lvmid, para cada JVM instrumentada encontrada en el sistema destino. El lvmid es típicamente, pero no necesariamente, el identificador de proceso del sistema operativo para el proceso de la JVM. Sin opciones, el comando jps lista el lvmid de cada aplicación Java seguido de la forma abreviada del nombre de la clase de la aplicación o el nombre del archivo JAR. La forma abreviada del nombre de la clase o archivo JAR omite la información del paquete de la clase o la información de la ruta del archivo JAR.

El comando jps utiliza el lanzador de Java para encontrar el nombre de la clase y los argumentos pasados al método principal. Si la JVM destino se inicia con un lanzador personalizado, entonces el nombre de la clase o JAR, y los argumentos del método principal no están disponibles. En este caso, el comando jps genera la cadena Desconocido para el nombre de la clase o archivo JAR, y para los argumentos del método principal.

La lista de JVMs producida por el comando jps puede estar limitada por los permisos otorgados al principal que ejecuta el comando. El comando lista solo las JVMs para las cuales el principal tiene derechos de acceso según lo determinado por los mecanismos de control de acceso específicos del sistema operativo.

IDENTIFICADOR DE HOST

El identificador de host, o hostid, es una cadena que indica el sistema destino. La sintaxis de la cadena hostid corresponde a la sintaxis de una URI:

[protocolo:][[//]nombrehost][:puerto][/nombreservidor]

protocolo
El protocolo de comunicaciones. Si se omite el protocolo y no se especifica un nombrehost, entonces el protocolo predeterminado es un protocolo local optimizado y específico de la plataforma. Si se omite el protocolo y se especifica un nombre de host, entonces el protocolo predeterminado es rmi.
nombrehost
Un nombre de host o dirección IP que indica el host destino. Si omite el parámetro nombrehost, entonces el host destino es el host local.
puerto
El puerto predeterminado para comunicarse con el servidor remoto. Si se omite el parámetro nombrehost o el parámetro protocolo especifica un protocolo local optimizado, entonces el parámetro puerto se ignora. De lo contrario, el tratamiento del parámetro puerto es específico de la implementación. Para el protocolo rmi predeterminado, el parámetro puerto indica el número de puerto para el rmiregistry en el host remoto. Si se omite el parámetro puerto, y el parámetro protocolo indica rmi, entonces se utiliza el puerto predeterminado de rmiregistry (1099).
nombreservidor
El tratamiento de este parámetro depende de la implementación. Para el protocolo local optimizado, este campo se ignora. Para el protocolo rmi, este parámetro es una cadena que representa el nombre del objeto remoto RMI en el host remoto. Ver la opción -n del comando jstatd.

FORMATO DE SALIDA DEL COMANDO JPS

La salida del comando jps tiene el siguiente patrón:

lvmid [ [ nombreclase | nombrearchivoJAR | "Desconocido"] [ arg* ] [ argjvm* ] ]

Todos los tokens de salida están separados por espacios en blanco. Un valor de argumento que incluye espacios en blanco incrustados introduce ambigüedad al intentar mapear argumentos a sus parámetros posicionales reales.

Nota:

Se recomienda no escribir scripts para analizar la salida de jps, ya que el formato podría cambiar en futuras versiones. Si escribe scripts que analizan la salida de jps, prepárese para modificarlos para futuras versiones de esta herramienta.

EJEMPLOS

Esta sección proporciona ejemplos del comando jps.

Listar las JVMs instrumentadas en el host local:


jps
18027 Java2Demo.JAR
18032 jps
18005 jstat

El siguiente ejemplo lista las JVMs instrumentadas en un host remoto. Este ejemplo asume que el servidor jstat y su registro RMI interno o un proceso rmiregistry externo separado se están ejecutando en el host remoto en el puerto predeterminado (puerto 1099). También asume que el host local tiene permisos apropiados para acceder al host remoto. Este ejemplo incluye la opción -l para mostrar la forma larga de los nombres de clase o archivos JAR.


jps -l host.remoto.dominio
3002 /opt/jdk1.7.0/demo/jfc/Java2D/Java2Demo.JAR
2857 sun.tools.jstatd.jstatd

El siguiente ejemplo lista las JVMs instrumentadas en un host remoto con un puerto no predeterminado para el registro RMI. Este ejemplo asume que el servidor jstatd, con un registro RMI interno vinculado al puerto 2002, se está ejecutando en el host remoto. Este ejemplo también utiliza la opción -m para incluir los argumentos pasados al método principal de cada una de las aplicaciones Java listadas.


jps -m host.remoto.dominio:2002
3002 /opt/jdk1.7.0/demo/jfc/Java2D/Java2Demo.JAR
3102 sun.tools.jstatd.jstatd -p 2002
