JCMD(1) Comandos de JDK JCMD(1)

NOMBRE

jcmd - enviar solicitudes de comandos de diagnóstico a una Máquina Virtual Java (JVM) en ejecución

SINOPSIS

jcmd [pid | main-class] command... | PerfCounter.print | -f filename

jcmd [-l]

jcmd -h

pid
Cuando se usa, la utilidad jcmd envía la solicitud de comando de diagnóstico al ID de proceso del proceso Java.
main-class
Cuando se usa, la utilidad jcmd envía la solicitud de comando de diagnóstico a todos los procesos Java con el nombre de la clase principal especificado.
command
El command debe ser un comando jcmd válido para la JVM seleccionada. La lista de comandos disponibles para jcmd se obtiene ejecutando el comando help (jcmd pid help) donde pid es el ID de proceso del proceso Java en ejecución.
Perfcounter.print
Imprime los contadores de rendimiento expuestos por el proceso Java especificado.
-f filename
Lee y ejecuta comandos de un archivo especificado, filename.
-l
Muestra la lista de identificadores de proceso de la Máquina Virtual Java que no se están ejecutando en un proceso docker separado, junto con la clase principal y los argumentos de la línea de comandos que se utilizaron para iniciar el proceso. Si la JVM está en un proceso docker, debe usar herramientas como ps para buscar el PID.

Nota:

Usar jcmd sin argumentos es lo mismo que usar jcmd -l.

-h
Muestra la ayuda de la línea de comandos de la utilidad jcmd .

DESCRIPCIÓN

La utilidad jcmd se usa para enviar solicitudes de comandos de diagnóstico a la JVM. Debe usarse en la misma máquina en la que se está ejecutando la JVM, y tener los mismos identificadores efectivos de usuario y grupo que se usaron para iniciar la JVM. Cada comando de diagnóstico tiene su propio conjunto de opciones y argumentos. Para mostrar la descripción, la sintaxis y una lista de opciones y argumentos disponibles para un comando de diagnóstico, use el nombre del comando como argumento. Por ejemplo:

jcmd pid help command

Si los argumentos contienen espacios, debe rodearlos con comillas simples o dobles (' o "). Además, debe escapar las comillas simples o dobles con una barra invertida (\) para evitar que el shell del sistema operativo procese las comillas. Alternativamente, puede rodear estos argumentos con comillas simples y luego con comillas dobles (o con comillas dobles y luego con comillas simples).

Si especifica el identificador de proceso (pid) o la clase principal (main-class) como primer argumento, la utilidad jcmd envía la solicitud de comando de diagnóstico al proceso Java con el identificador especificado o a todos los procesos Java con el nombre de la clase principal especificado. También puede enviar la solicitud de comando de diagnóstico a todos los procesos Java disponibles especificando 0 como identificador de proceso.

COMANDOS PARA JCMD

El command debe ser un comando de diagnóstico jcmd válido para la JVM seleccionada. La lista de comandos disponibles para jcmd se obtiene ejecutando el comando help (jcmd pid help) donde pid es el ID de proceso de un proceso Java en ejecución. Si el pid es 0, los comandos se enviarán a todos los procesos Java. El argumento de la clase principal se usará para hacer coincidir, ya sea parcial o totalmente, la clase utilizada para iniciar Java. Si no se proporcionan opciones, se lista los identificadores de los procesos Java en ejecución que no están en procesos docker separados, junto con la clase principal y los argumentos de la línea de comandos que se utilizaron para iniciar el proceso (lo mismo que usar -l).

Los comandos jcmd pueden tomar opciones y argumentos. Las opciones se especifican usando la sintaxis key o key=value . Los argumentos se dan como un valor simple, nunca como nombre=valor.

Los siguientes comandos están disponibles:

help [options] [arguments]
Para más información sobre un comando específico.

arguments:

•
command name: El nombre del comando para el que se desea ayuda (STRING, sin valor predeterminado)

JFR.configure [opciones]
Establece los parámetros para una grabación de vuelo

Impacto: Bajo

Nota:

Las opciones deben especificarse usando la sintaxis clave o clave=valor . Si no se ingresan parámetros, se muestran la configuración actual.

opciones:

•
dumppath: (Opcional) Ruta a la ubicación donde se escribe un archivo de grabación en caso de que la VM encuentre un error crítico, como un fallo del sistema. (CADENA, la ubicación predeterminada es el directorio actual)
•
globalbuffercount: (Opcional) Número de búferes globales. Esta opción es una opción heredada: cambie el parámetro memorysize para alterar el número de búferes globales. Este valor no se puede cambiar una vez que JFR ha sido inicializado. (CADENA, el valor predeterminado está determinado por el valor de memorysize)
•
globalbuffersize: (Opcional) Tamaño de los búferes globales, en bytes. Esta opción es una opción heredada: cambie el parámetro memorysize para alterar el tamaño de los búferes globales. Este valor no se puede cambiar una vez que JFR ha sido inicializado. (CADENA, el valor predeterminado está determinado por el valor de memorysize)
•
maxchunksize: (Opcional) Tamaño máximo de un fragmento de datos individual en bytes si no se usa uno de los siguientes sufijos: 'm' o 'M' para megabytes O 'g' o 'G' para gigabytes. Este valor no se puede cambiar una vez que JFR ha sido inicializado. (CADENA, 12M)
•
memorysize: (Opcional) Tamaño total de memoria, en bytes si no se usa uno de los siguientes sufijos: 'm' o 'M' para megabytes O 'g' o 'G' para gigabytes. Este valor no se puede cambiar una vez que JFR ha sido inicializado. (CADENA, 10M)
•
repositorypath: (Opcional) Ruta a la ubicación donde se almacenan las grabaciones hasta que se escriben en un archivo permanente. (CADENA, la ubicación predeterminada es el directorio temporal del sistema operativo. En sistemas operativos Linux, el directorio temporal es /tmp. En Windows, el directorio temporal es especificado por la variable de entorno TMP .)
•
preserve-repository={true|false} : Especifica si los archivos almacenados en el repositorio de disco deben conservarse después de que el JVM haya salido. Si es false, los archivos se eliminan. De forma predeterminada, este parámetro está desactivado.
•
stackdepth: (Opcional) Profundidad de pila para las trazas de pila. Establecer este valor en más que el valor predeterminado de 64 puede causar una degradación del rendimiento. Este valor no se puede cambiar una vez que JFR ha sido inicializado. (LONG, 64)
•
thread_buffer_size: (Opcional) Tamaño del búfer local para cada hilo en bytes si no se usa uno de los siguientes sufijos: 'k' o 'K' para kilobytes o 'm' o 'M' para megabytes. Anular este parámetro podría reducir el rendimiento y no se recomienda. Este valor no se puede cambiar una vez que JFR ha sido inicializado. (CADENA, 8k)
•
samplethreads: (Opcional) Indicador para activar el muestreo de hilos. (BOOLEANO, true)
JFR.dump [opciones]
Escribe datos en un archivo mientras se ejecuta una grabación de vuelo

Impacto: Bajo

Nota:

Las opciones deben especificarse usando la sintaxis clave o clave=valor . No se requieren opciones. La grabación continúa ejecutándose después de que se escriben los datos.

opciones:

•
begin: (Opcional) Especifica el tiempo desde el cual los datos de la grabación se incluirán en el archivo de volcado. El formato se especifica como hora local. (CADENA, sin valor predeterminado)
•
end: (Opcional) Especifica el tiempo hasta el cual los datos de la grabación se incluirán en el archivo de volcado. El formato se especifica como hora local. (CADENA, sin valor predeterminado)

Nota: Para ambos begin y end, la hora debe estar en un formato que pueda ser leído por java.time.LocalTime::parse(STRING), java.time.LocalDateTime::parse(STRING) o java.time.Instant::parse(STRING). Por ejemplo, "13:20:15", "2020-03-17T09:00:00" o "2020-03-17T09:00:00Z".

Nota: Los tiempos begin y end

corresponden a las marcas de tiempo encontradas dentro de la información grabada en los datos de la grabación de vuelo. Otra opción es usar un tiempo relativo al tiempo actual que se especifica mediante un entero negativo seguido de "s", "m" o "h". Por ejemplo, "-12h", "-15m" o "-30s"

JFR.configure [options]
Configure a flight recording

Impact: Low

Note:

The options must be specified using either key or key=value syntax. If no parameters are entered, then the current configuration is displayed.

options:

•
dumponexit: (Optional) Flag for writing the recording to disk when the Java Virtual Machine (JVM) shuts down. If set to 'true' and no value is given for filename, the recording is written to a file in the directory where the process was started. The file name is a system-generated name that contains the process ID, the recording ID and the current time stamp. (For example: id-1-2019_12_12_10_41.jfr) (BOOLEAN, false)
•
filename: (Optional) Name of the file to which the flight recording data is dumped. If no filename is given, a filename is generated from the PID and the current date. The filename may also be a directory in which case, the filename is generated from the PID and the current date in the specified directory. If %p and/or %t is specified in the filename, it expands to the JVM's PID and the current timestamp, respectively. (FILE, no default value)
•
maxage: (Optional) Length of time for dumping the flight recording data to a file. (INTEGER followed by 's' for seconds 'm' for minutes or 'h' for hours, no default value)
•
maxsize: (Optional) Maximum size for the amount of data to dump from a flight recording in bytes if one of the following suffixes is not used: 'm' or 'M' for megabytes OR 'g' or 'G' for gigabytes. (STRING, no default value)
•
name: (Optional) Name of the recording. If no name is given, data from all recordings is dumped. (STRING, no default value)
•
path-to-gc-roots: (Optional) Flag for saving the path to garbage collection (GC) roots at the time the recording data is dumped. The path information is useful for finding memory leaks but collecting it can cause the application to pause for a short period of time. Turn on this flag only when you have an application that you suspect has a memory leak. (BOOLEAN, false)
JFR.start [options]
Start a flight recording

Impact: Low

Note:

The options must be specified using either key or key=value syntax. If no parameters are entered, then a recording is started with default values.

options:

•
delay: (Optional) Length of time to wait before starting to record (INTEGER followed by 's' for seconds 'm' for minutes or 'h' for hours, 0s)
•
disk: (Optional) Flag for also writing the data to disk while recording (BOOLEAN, true)
•
dumponexit: (Optional) Flag for writing the recording to disk when the Java Virtual Machine (JVM) shuts down. If set to 'true' and no value is given for filename, the recording is written to a file in the directory where the process was started. The file name is a system-generated name that contains the process ID, the recording ID and the current time stamp. (For example: id-1-2019_12_12_10_41.jfr) (BOOLEAN, false)
•
duration: (Optional) Length of time to record. Note that 0s means forever (INTEGER followed by 's' for seconds 'm' for minutes or 'h' for hours, 0s)
•
filename: (Optional) Name of the file to which the flight recording data is written when the recording is stopped. If no filename is given, a filename is generated from the PID and the current date and is placed in the directory where the process was started. The filename may also be a directory in which case, the filename is generated from the PID and the current date in the specified directory. If %p and/or %t is specified in the filename, it expands to the JVM's PID and the current timestamp, respectively. (FILE, no default value)
•
maxage: (Optional) Maximum time to keep the recorded data on disk. This parameter is valid only when the disk parameter is set to true. Note 0s means forever. (INTEGER followed by 's' for seconds 'm' for minutes or 'h' for hours, 0s)
•
maxsize: (Optional) Maximum size of the data to keep on disk in bytes if one of the following suffixes is not used: 'm' or 'M' for megabytes OR 'g' or 'G' for gigabytes. This parameter is valid only when the disk parameter is set to 'true'. The value must not be less than the value for the maxchunksize parameter set with the JFR.configure command. (STRING, 0 (no maximum size))
•
name: (Optional) Name of the recording. If no name is provided, a name is generated. Make note of the generated name that is shown in the response to the command so that you can use it with other commands. (STRING, system-generated default name)
•
path-to-gc-roots: (Optional) Flag for saving the path to garbage collection (GC) roots at the end of a recording. The path information is useful for finding memory leaks but collecting it is time consuming. Turn on this flag only when you have an application that you suspect has a memory leak. If the settings parameter is set to 'profile', then the information collected includes the stack trace from where the potential leaking object was allocated. (BOOLEAN, false)
•
settings: (Optional) Name of the settings file that identifies which events to record. To specify more than one file, separate the names with a comma (','). Include the path if the file is not in JAVA-HOME/lib/jfr. The following profiles are included with the JDK in the JAVA-HOME/lib/jfr directory: 'default.jfc': collects a predefined set of information with low overhead, so it has minimal impact on performance and can be used with recordings that run continuously; 'profile.jfc': Provides more data than the 'default.jfc' profile, but with more overhead and impact on performance. Use this configuration for short periods of time when more information is needed. Use none to start a recording without a predefined configuration file. (STRING, JAVA-HOME/lib/jfr/default.jfc)

Event settings and .jfc options can be specified using the following syntax:

•
option: (Optional) Specifies the option value to modify. To list available options, use the JAVA_HOME/bin/jfr tool.
•
event-setting: (Optional) Specifies the event setting value to modify. Use the form: <event-name>#<setting-name>=<value> To add a new event setting, prefix the event name with '+'.

You can specify values for multiple event settings and .jfc options by separating them with a whitespace. In case of a conflict between a parameter and a .jfc option, the parameter will take precedence. The whitespace delimiter can be omitted for timespan values, i.e. 20ms. For more information about the settings syntax, see Javadoc of the jdk.jfr package.
