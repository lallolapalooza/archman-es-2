NOMBRE

jj-next - Mover el commit de la copia de trabajo a la revisión hija

SINOPSIS

jj next [-e|--edit] [-n|--no-edit] [--conflict] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] [OFFSET]

DESCRIPCIÓN

Mover el commit de la copia de trabajo a la revisión hija

El comando crea una nueva revisión vacía de la copia de trabajo que es hija de un descendiente a `offset` revisiones de distancia del padre de la copia de trabajo actual.

Por ejemplo, cuando el offset es 1:

```text D D @ | |/ C @ => C |/ | B B ```

Si se pasa `--edit`, la revisión de la copia de trabajo se cambia a la hija de la revisión de la copia de trabajo actual.

```text D D | | C C | | B => @ | | @ A ```

OPCIONES

-e, --edit
En lugar de crear un nuevo commit de la copia de trabajo encima del commit de destino (como `jj new`), edita directamente el commit de destino (como `jj edit`)

Tiene precedencia sobre la configuración en `ui.movement.edit`; es decir, negará `ui.movement.edit = false`

-n, --no-edit
La inversa de `--edit`

Tiene precedencia sobre la configuración en `ui.movement.edit`; es decir, negará `ui.movement.edit = true`

--conflict
Saltar al siguiente descendiente en conflicto
-h, --help
Imprimir ayuda (ver un resumen con '-h')
[OFFSET] [por defecto: 1]
Cuántas revisiones avanzar. Avanza a la siguiente hija por defecto

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No guardar la copia de trabajo, y no actualizarla

Por defecto, Jujutsu guarda la copia de trabajo al inicio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si quieres evitar guardar la copia de trabajo y ver en su lugar una copia de trabajo potencialmente obsoleta, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en un prompt de comandos, especialmente si tienes otro proceso que guarda la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu evita reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa comprobación y te permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta a la comprobación. No afecta al revset `immutable_heads()` ni a la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repo

Operación en la que cargar el repo. Por defecto, Jujutsu carga el repo en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puedes usar `--at-op=<ID de operación>` para ver cómo se veía el repo en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` te mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor por defecto, excepto que las operaciones divergentes nunca se fusionarán.

Usa `jj op log` para encontrar el ID de operación que deseas. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repo en una operación anterior, la copia de trabajo será ignorada, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutantes al cargar el repo en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacer eso, pero es posible.

--debug
Habilitar registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[posibles valores: always, never, debug, auto]

--quiet
Silenciar la salida no primaria del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no te dirá si la copia de trabajo fue guardada o si los descendientes fueron rebasados.

Las advertencias y errores aún se imprimirán.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se puede repetir)

El nombre debe especificarse como claves separadas por puntos de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado por ninguna construcción de TOML (como notación de array), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se puede repetir)
