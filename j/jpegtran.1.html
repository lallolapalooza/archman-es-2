jpegtran realiza varias transformaciones útiles en archivos JPEG con pérdida (basados en DCT). Puede traducir la representación codificada de una variante de JPEG a otra, por ejemplo de JPEG baseline a JPEG progresivo o viceversa. También puede realizar algunos reordenamientos de los datos de la imagen, por ejemplo cambiar una imagen de formato horizontal a vertical mediante

rotación.

Para archivos EXIF y archivos JPEG que contienen datos Exif, puede preferir usar exiftran

.

jpegtran funciona reordenando los datos comprimidos (coeficientes DCT), sin decodificar nunca completamente la imagen. Por lo tanto, sus transformaciones son sin pérdida: no hay degradación alguna de la imagen, lo cual no sería cierto si usara djpeg seguido de cjpeg para realizar la misma conversión. Pero por la misma razón, jpegtran no puede realizar operaciones con pérdida como cambiar la calidad de la imagen. Sin embargo, mientras los datos de la imagen se transforman sin pérdida, los metadatos pueden eliminarse. Consulte la opción -copy para más

detalles.

jpegtran lee el archivo JPEG/JFIF nombrado, o la entrada estándar si no se n

ombra ningún archivo, y produce un ar
chivo JPEG/JFIF en la salida estándar.

NAME

jpegtran — lossless JPEG transformation

SYNOPSIS

jpegtran [ options ] [ input.jpg ]

DESCRIPTION

jpegtran is a program that applies lossless transformations to JPEG images. Lossless means that the image data is not altered, only rearranged. This preserves the image quality exactly. The output image is a valid JPEG file. The input image is specified by input.jpg. If absent, the input is taken from standard input.

The output image is written to standard output unless the -outfile switch is specified.

It is possible to specify multiple transformations. They are applied in the order they are given on the command line.

jpegtran can also perform a number of "near-lossless" transformations. These transformations alter the image data slightly to achieve certain effects, but the alterations are typically imperceptible. These include cropping, resizing, and color space conversions.

Lossless Transformations

-copy none
Do not copy any extra markers from the source file. This setting suppresses all comments and other metadata in the source file.
-copy comments
Copy only comment markers. This setting copies comments from the source file but discards any other metadata.
-copy icc
Copy only ICC profile markers. This setting copies the ICC profile from the source file but discards any other metadata.
-copy all
Copy all extra markers. This setting preserves miscellaneous markers found in the source file, such as JFIF thumbnails, Exif data, and Photoshop settings. In some files, these extra markers can be sizable. Note that this option will copy thumbnails as-is; they will not be transformed.

The default behavior is -copy comments. (Note: in IJG releases v6 and v6a, jpegtran always did the equivalent of -copy none.)

-flip arg
Flip the image in the specified direction:
horizontal
Flip horizontally.
vertical
Flip vertically.
-mirror
Same as -flip horizontal.
-rotate arg
Rotate the image in the specified direction:
90
Rotate 90 degrees clockwise.
180
Rotate 180 degrees.
270
Rotate 270 degrees clockwise.
-transpose
Transpose (flip vertically and rotate 90 degrees clockwise).
-transverse
Transverse (flip horizontally and rotate 270 degrees clockwise).
-perfect
Create a perfect DCT. This is the default when no transformations are requested. If transformations are requested, this option is implied unless -trim or -crop is specified.
-crop +X+Y
Crop the image to the specified dimensions. The top-left corner of the image is at (0,0). The new dimensions are determined by the size of the output image.
-trim
Trim the image. This option removes any border regions that would be lost by a subsequent transformation. For example, rotating a non-square image by 90 degrees results in a smaller image. -trim ensures that the output image is the same size as the input image, by discarding the border regions.

Progressive JPEG Conversion

-progressive
Convert the image to progressive JPEG format. Progressive JPEGs display gradually as they load, providing a smoother user experience for web images. Baseline JPEGs are displayed only after the entire image has been downloaded.
-restarts N
Insert restart markers every N coding intervals. Restart markers allow decoding to resume at any marker, rather than from the beginning of the image. This can improve resilience to transmission errors, but may slightly increase file size. The default is 0, meaning no restart markers are inserted.

jpegtran can optimize the number of scans in a progressive JPEG. Fewer scans mean a smaller file, but slower display. More scans mean a larger file, but faster display. The default is to use the minimum number of scans possible, typically 2.

-scans n1[,n2,...]
Specify the number of scans for each component. For example, -scans 2,1,1 would create a progressive JPEG with 2 scans for the luminance component and 1 scan for each of the two chrominance components.
-optimize
Optimize Huffman coding tables. This can reduce file size by a few percent, but takes longer to process.

Near-Lossless Transformations

-grayscale
Force grayscale output.

This option discards the chrominance channels if the input image is YCbCr (i.e., a standard color JPEG), resulting in a grayscale JPEG file. The luminance channel is preserved exactly, so this is a better method of reducing to grayscale than decompression, conversion, and recompression. This switch is particularly handy for fixing a monochrome picture that was mistakenly encoded as a color JPEG. (In such a case, the space savings from getting rid of the near-empty chroma channels won't be large; but the decoding time for a grayscale JPEG is substantially less than that for a color JPEG.)

-drop +X+Y filename
Drop (insert) another image at point X,Y

A lossless drop option is also provided, which allows another JPEG image to be inserted ("dropped") into the input image data at a given position, replacing the existing image data at that position:

Both the input image and the drop image must have the same subsampling level. It is best if they also have the same quantization (quality.) Otherwise, the quantization of the output image will be adapted to accommodate the higher of the input image quality and the drop image quality. The trim option can be used with the drop option to requantize the drop image to match the input image. Note that a grayscale image can be dropped into a full-color image or vice versa, as long as the full-color image has no vertical subsampling. If the input image is grayscale and the drop image is full-color, then the chrominance channels from the drop image will be discarded.

-wipe +X+Y +width+height
Wipe the specified region with gray or with reflections.

The -wipe option replaces the specified region with gray. If the -wipe option is followed by the word "reflect", the wipe region will be filled with repeated reflections of the outside region rather than grayed out.

Other not-strictly-lossless transformation switches are:

-maxmemory N
Set limit for amount of memory to use in processing large images. Value is in thousands of bytes, or millions of bytes if "M" is attached to the number. For example, -max 4m selects 4000000 bytes. If more space is needed, an error will occur.
-maxscans N
Abort if the input image contains more than N scans. This feature demonstrates a method by which applications can guard against denial-of-service attacks instigated by specially-crafted malformed JPEG images containing numerous scans with missing image data or image data consisting only of "EOB runs" (a feature of progressive JPEG images that allows potentially hundreds of thousands of adjoining zero-value pixels to be represented using only a few bytes.) Attempting to transform such malformed JPEG images can cause excessive CPU activity, since the decompressor must fully process each scan (even if the scan is corrupt) before it can proceed to the next scan.
-outfile name
Send output image to the named file, not to standard output.
-report
Report transformation progress.
-strict
Treat all warnings as fatal. This feature also demonstrates a method by which applications can guard against attacks instigated by specially-crafted malformed JPEG images. Enabling this option will cause the decompressor to abort if the input image contains incomplete or corrupt image data.
-verbose
Enable debug printout. More -v's give more output. Also, version information is printed at startup.
-debug
Same as -verbose.
-version
Print version information and exit.

Marker Handling

jpegtran also recognizes these switches that control what to do with "extra" markers, such as comment blocks:

-copy none
Copy no extra markers from source file. This setting suppresses all comments and other metadata in the source file.
-copy comments
Copy only comment markers. This setting copies comments from the source file but discards any other metadata.
-copy icc
Copy only ICC profile markers. This setting copies the ICC profile from the source file but discards any other metadata.
-copy all
Copy all extra markers. This setting preserves miscellaneous markers found in the source file, such as JFIF thumbnails, Exif data, and Photoshop settings. In some files, these extra markers can be sizable. Note that this option will copy thumbnails as-is; they will not be transformed.

The default behavior is -copy comments. (Note: in IJG releases v6 and v6a, jpegtran always did the equivalent of -copy none.)

-icc file
Embed ICC color management profile contained in the specified file. Note that this will cause jpegtran to ignore any APP2 markers in the input file, even if -copy all or -copy icc is specified.

EXAMPLES

This example converts a baseline JPEG file to progressive form:

jpegtran -progressive foo.jpg > fooprog.jpg

This example rotates an image 90 degrees clockwise, discarding any unrotatable edge pixels:

jpegtran -rot 90 -trim foo.jpg > foo90.jpg

ENVIRONMENT

JPEGMEM
If this environment variable is set, its value is the default memory limit. The value is specified as described for the -maxmemory switch. JPEGMEM overrides the default value specified when the program was compiled, and itself is overridden by an explicit -maxmemory.

BUGS

The transform options can't transform odd-size images perfectly. Use -trim or -perfect if you don't like the results.

The entire image is read into memory and then written out again, even in cases where this isn't really necessary. Expect swapping on large images, especially when using the more complex transform options.
