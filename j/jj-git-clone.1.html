jj-git-clone(1)

Paquete: jujutsu

jj-git-clone(1) General Commands Manual jj-git-clone(1)

NOMBRE

jj-git-clone - Crea un nuevo repositorio respaldado por un clon de un repositorio Git

SINOPSIS

jj git clone [--remote] [--colocate] [--no-colocate] [--depth] [--fetch-tags] [-b|--branch] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <SOURCE> [DESTINATION]

DESCRIPCIÓN

Crea un nuevo repositorio respaldado por un clon de un repositorio Git

OPCIONES

--remote <NOMBRE_REMOTO> [por defecto: origin]
Nombre del remoto recién creado
--colocate
Coloca el repositorio Jujutsu junto con el repositorio Git

Especifica que el repositorio `jj` también debe ser un repositorio `git` válido, permitiendo el uso de comandos `jj` y `git` en el mismo directorio.

El repositorio contendrá un directorio `.git` en el nivel superior. Las herramientas Git normales podrán operar en el repositorio.

**Este es el comportamiento por defecto**, y esta opción no tiene efecto, a menos que la configuración [git.colocate] se establezca en `false`.

[Configuración git.colocate]: https://docs.jj-vcs.dev/latest/config/#default-colocation

--no-colocate
Desactiva la colocación del repositorio Jujutsu junto con el repositorio Git

Evita que las herramientas Git que no conocen `jj` y los comandos Git normales operen en el repositorio. El repositorio Git que almacena la mayor parte de los datos del repositorio estará oculto dentro de un subdirectorio del directorio `.jj`.

Consulta la [documentación de colocación] para ver algunas ventajas menores de los espacios de trabajo no colocados.

[Documentación de colocación]: https://docs.jj-vcs.dev/latest/git-compatibility/#colocated-jujutsugit-repos

--depth <PROFUNDIDAD>
Crea un clon superficial de la profundidad dada
--fetch-tags <FETCH_TAGS>
Configura cuándo obtener las etiquetas

A menos que se especifique lo contrario, el clon inicial obtendrá todas las etiquetas, mientras que todas las obtenciones posteriores solo obtendrán las etiquetas incluidas.

Valores posibles:

  • all: Obtener siempre todas las etiquetas
  • included: Obtener solo las etiquetas que apuntan a objetos que ya se están transmitiendo
  • none: No obtener ninguna etiqueta
-b, --branch <RAMA>
Nombre de la rama a obtener y usar como padre del cambio de la copia de trabajo

Si no está presente, se obtienen todas las ramas y la rama predeterminada del repositorio se utiliza como padre del cambio de la copia de trabajo.

Por defecto, el nombre especificado coincide exactamente. Usa el prefijo `glob:` para expandir `*` como un comodín, por ejemplo `--branch 'glob:*push-*'`. Otros caracteres comodín como `?` *no* son soportados. Se puede repetir para especificar múltiples ramas, en cuyo caso el primer nombre de rama exacto se usa como padre de la copia de trabajo.

-h, --help
Imprime la ayuda (ver un resumen con '-h')
<SOURCE>
URL o ruta del repositorio Git a clonar

La ruta local se resolverá a su forma absoluta.

[DESTINATION]
Especifica el directorio de destino para el clon del repositorio Jujutsu. Si no se proporciona, por defecto será un directorio con el nombre del último componente de la URL de origen. Se creará la ruta completa del directorio si no existe

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un antepasado del directorio de trabajo actual.

--ignore-working-copy
No tomar instantánea de la copia de trabajo ni actualizarla

Por defecto, Jujutsu toma una instantánea de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si desea evitar tomar una instantánea de la copia de trabajo y ver en su lugar un commit de copia de trabajo posiblemente desactualizado, puede usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tiene otro proceso que confirma la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu evita reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y le permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <OPERACION_EN>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puede usar `--at-op=<ID de operación>` para ver cómo era el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` le mostrará lo que `jj st` habría mostrado cuando la operación dada había terminado. `--at-op=@` es prácticamente lo mismo que el valor predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Use `jj op log` para encontrar el ID de operación que desea. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignorará la copia de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutantes al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilita el registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[posibles valores: always, never, debug, auto]

--quiet
Silencia la salida de comandos no principales

Por ejemplo, `jj file list` todavía listará archivos, pero no le dirá si se tomó una instantánea de la copia de trabajo o si se reorganizaron los descendientes.

Las advertencias y los errores aún se imprimirán.

--no-pager
Deshabilita el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves TOML separadas por puntos. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado en ninguna construcción TOML (como la notación de matriz), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
