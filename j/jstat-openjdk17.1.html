IDENTIFICADOR DE MÁQUINA VIRTUAL

La sintaxis de la cadena vmid corresponde a la sintaxis de una URI:

[protocolo:][//]lvmid[@nombrehost[:puerto][/nombreservidor]

La sintaxis de la cadena vmid corresponde a la sintaxis de una URI. La cadena vmid puede variar desde un simple entero que representa una JVM local hasta una construcción más compleja que especifica un protocolo de comunicaciones, un número de puerto y otros valores específicos de la implementación.

protocolo
El protocolo de comunicaciones. Si se omite el valor de protocolo y no se especifica un nombre de host, el protocolo predeterminado es un protocolo local optimizado específico de la plataforma. Si se omite el valor de protocolo y se especifica un nombre de host, el protocolo predeterminado es rmi.
lvmid
El identificador de máquina virtual local para la JVM de destino. El lvmid es un valor específico de la plataforma que identifica de forma única una JVM en un sistema. El lvmid es el único componente requerido de un identificador de máquina virtual. El lvmid es típicamente, pero no necesariamente, el identificador de proceso del sistema operativo para el proceso de la JVM de destino. Puede utilizar el comando jps para determinar el lvmid siempre que los procesos de la JVM no se estén ejecutando en una instancia de docker separada. También puede determinar el lvmid en las plataformas Linux y OS X con el comando ps, y en Windows con el Administrador de tareas de Windows.
nombrehost
Un nombre de host o dirección IP que indica el host de destino. Si se omite el valor de nombrehost, el host de destino es el host local.
puerto
El puerto predeterminado para comunicarse con el servidor remoto. Si se omite el valor de nombrehost o si el valor de protocolo especifica un protocolo local optimizado, el valor de puerto se ignora. De lo contrario, el tratamiento del parámetro puerto es específico de la implementación. Para el protocolo rmi predeterminado, el valor del puerto indica el número de puerto para el rmiregistry en el host remoto. Si se omite el valor de puerto y el valor de protocolo indica rmi, se utiliza el puerto predeterminado de rmiregistry (1099).
nombreservidor
El tratamiento del parámetro nombreservidor depende de la implementación. Para el protocolo local optimizado, este campo se ignora. Para el protocolo rmi, representa el nombre del objeto remoto RMI en el host remoto.

LA OPCIÓN GCUTIL

Este ejemplo se adjunta al lvmid 21891, toma 7 muestras a intervalos de 250 milisegundos y muestra la salida según lo especificado por la opción -gcutil.

La salida de este ejemplo muestra que ocurrió una recolección de la generación joven entre la tercera y la cuarta muestra. La recolección tardó 0.078 segundos y promovió objetos del espacio Eden (E) al espacio antiguo (O), lo que resultó en un aumento de la utilización del espacio antiguo del 66.80% al 68.19%. Antes de la recolección, el espacio de supervivientes estaba utilizado al 97.02%, pero después de esta recolección está al 91.03%.

Este ejemplo se adjunta al lvmid 21891, toma muestras a intervalos de 250 milisegundos y muestra la salida según lo especificado por la opción -gcnew. Además, utiliza la opción -h3 para mostrar el encabezado de columna después de cada 3 líneas de datos.

Además de mostrar la cadena de encabezado repetida, este ejemplo muestra que entre la segunda y la tercera muestra, se produjo un GC joven. Su duración fue de 0.001 segundos. La recolección encontró suficientes datos activos como para que la utilización del espacio de supervivientes 0 (S0U) hubiera superado el tamaño deseado de supervivientes (DSS). Como resultado, los objetos se promovieron a la generación antigua (no visible en esta salida) y el umbral de tenencia (TT) se redujo de 31 a 2.

Se produce otra recolección entre la quinta y la sexta muestra. Esta recolección encontró muy pocos supervivientes y devolvió el umbral de tenencia a 31.
