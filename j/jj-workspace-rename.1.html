NOMBRE

jj-workspace-rename - Renombra el espacio de trabajo actual

SINOPSIS

jj workspace rename [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <NUEVO_NOMBRE_DEL_ESPACIO_DE_TRABAJO>

DESCRIPCIÓN

Renombra el espacio de trabajo actual

OPCIONES

-h, --help
Imprime la ayuda (ver un resumen con '-h')
<NUEVO_NOMBRE_DEL_ESPACIO_DE_TRABAJO>
El nombre del espacio de trabajo a actualizar

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio con el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No tomar una instantánea de la copia de trabajo, y no actualizarla

Por defecto, Jujutsu toma una instantánea de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si quieres evitar tomar una instantánea de la copia de trabajo y ver en su lugar un commit de copia de trabajo posiblemente obsoleto, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en un prompt de comandos, especialmente si tienes otro proceso que confirma la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu previene la reescritura de commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y te permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <OPERACIÓN_EN_LA_QUE_CARGAR>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puedes usar `--at-op=<ID de operación>` para ver cómo se veía el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` te mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor por defecto, excepto que las operaciones divergentes nunca se fusionarán.

Usa `jj op log` para encontrar el ID de operación que deseas. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignorará la copia de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutantes al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilita el registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[posibles valores: always, never, debug, auto]

--quiet
Silencia la salida no principal del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no te dirá si la copia de trabajo fue tomada como instantánea o si los descendientes fueron rebasados.

Las advertencias y los errores seguirán imprimiéndose.

--no-pager
Deshabilita el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves puntuales TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está delimitado por ninguna construcción TOML (como notación de matriz), las comillas se pueden omitir.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
