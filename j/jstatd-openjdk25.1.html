JSTATD(1) Comandos JDK JSTATD(1)

NOMBRE

jstatd - supervisa la creación y terminación de máquinas virtuales HotSpot de Java instrumentadas

SINOPSIS

ADVERTENCIA: Este comando es experimental, no está soportado y está obsoleto. Será eliminado en una futura versión.

jstatd [opciones]

opciones
Esto representa las opciones de línea de comandos de jstatd. Consulte Opciones para el comando jstatd.

DESCRIPCIÓN

El comando jstatd es una aplicación de servidor RMI que supervisa la creación y terminación de máquinas virtuales HotSpot de Java instrumentadas y proporciona una interfaz para permitir que las herramientas de monitorización remota, jstat y jps, se conecten a JVMs que se ejecutan en el host local y recopilen información sobre el proceso de la JVM.

El servidor jstatd requiere un registro RMI en el host local. El servidor jstatd intenta conectarse al registro RMI en el puerto por defecto, o en el puerto que usted especifique con la opción -p puerto. Si no se encuentra un registro RMI, entonces se crea uno dentro de la aplicación jstatd que está enlazado al puerto que se indica con la opción -p puerto o al puerto del registro RMI por defecto cuando se omite la opción -p puerto. Puede detener la creación de un registro RMI interno especificando la opción -nr.

OPCIONES PARA EL COMANDO JSTATD

-nr
Esta opción no intenta crear un registro RMI interno dentro del proceso jstatd cuando no se encuentra un registro RMI existente.
-p puerto
Esta opción establece el número de puerto donde se espera encontrar el registro RMI, o cuando no se encuentra, se crea si la opción -nr no está especificada.
-r puerto_rmi
Esta opción establece el número de puerto al que se enlaza el conector RMI. Si no se especifica, se utiliza un puerto aleatorio disponible.
-n nombre_rmi
Esta opción establece el nombre al que se enlaza el objeto RMI remoto en el registro RMI. El nombre por defecto es JStatRemoteHost. Si se inician múltiples servidores jstatd en el mismo host, el nombre del objeto RMI exportado para cada servidor puede hacerse único especificando esta opción. Sin embargo, hacerlo requiere que el nombre de servidor único se incluya en las cadenas hostid y vmid del cliente de monitorización.
-Jopción
Esta opción pasa una opción de Java a la JVM, donde la opción es una de las descritas en la página de referencia del lanzador de aplicaciones de Java. Por ejemplo, -J-Xms48m establece la memoria de inicio en 48 MB. Consulte java.

SEGURIDAD

El servidor jstatd solo puede monitorizar JVMs para las que tiene los permisos de acceso nativo apropiados. Por lo tanto, el proceso jstatd debe ejecutarse con las mismas credenciales de usuario que las JVMs objetivo. Algunas credenciales de usuario, como el usuario root en los sistemas operativos Linux y macOS, tienen permiso para acceder a la instrumentación exportada por cualquier JVM en el sistema. Un proceso jstatd ejecutándose con tales credenciales puede monitorizar cualquier JVM en el sistema, pero introduce preocupaciones de seguridad adicionales.

El servidor jstatd no proporciona ninguna autenticación de clientes remotos. Por lo tanto, ejecutar un proceso servidor jstatd expone la instrumentación exportada por todas las JVMs para las que el proceso jstatd tiene permisos de acceso a cualquier usuario en la red. Esta exposición podría ser indeseable en su entorno y, por lo tanto, las políticas de seguridad locales deben considerarse antes de iniciar el proceso jstatd, particularmente en entornos de producción o en redes que no sean seguras.

Por motivos de seguridad, el servidor jstatd utiliza un RMI ObjectInputFilter para permitir solo la deserialización de clases esenciales.

Si sus preocupaciones de seguridad no se pueden abordar, la acción más segura es no ejecutar el servidor jstatd y utilizar las herramientas jstat y jps localmente. Sin embargo, al usar jps para obtener una lista de JVMs instrumentadas, la lista no incluirá ninguna JVM que se ejecute en contenedores de Docker.

INTERFAZ REMOTA

La interfaz exportada por el proceso jstatd es propietaria y está garantizado que cambiará. Se desaconseja a los usuarios y desarrolladores que escriban en esta interfaz.

EJEMPLOS

Los siguientes son ejemplos del comando jstatd. Los scripts jstatd inician automáticamente el servidor en segundo plano.

REGISTRO RMI INTERNO

Este ejemplo muestra cómo iniciar una sesión de jstatd con un registro RMI interno. Este ejemplo asume que ningún otro servidor está enlazado al puerto del registro RMI por defecto (puerto 1099).

jstatd

REGISTRO RMI EXTERNO

Este ejemplo inicia una sesión de jstatd con un registro RMI externo.

rmiregistry&
jstatd

Este ejemplo inicia una sesión de jstatd con un servidor de registro RMI externo en el puerto 2020.

jrmiregistry 2020&
jstatd -p 2020

Este ejemplo inicia una sesión de jstatd con un servidor de registro RMI externo en el puerto 2020 y un conector JMX enlazado al puerto 2021.

jrmiregistry 2020&
jstatd -p 2020 -r 2021

Este ejemplo inicia una sesión de jstatd con un registro RMI externo en el puerto 2020 que está enlazado a AlternateJstatdServerName.

rmiregistry 2020&
jstatd -p 2020 -n AlternateJstatdServerName

DETENER LA CREACIÓN DE UN REGISTRO RMI EN PROCESO

Este ejemplo inicia una sesión de jstatd que no crea un registro RMI cuando no se encuentra uno. Este ejemplo asume que ya hay un registro RMI en ejecución. Si no hay un registro RMI en ejecución, se mostrará un mensaje de error.

jstatd -nr

HABILITAR REGISTRO RMI

Este ejemplo inicia una sesión de jstatd con la capacidad de registro RMI habilitada. Esta técnica es útil como ayuda para la resolución de problemas o para monitorizar las actividades del servidor.

jstatd -J-Djava.rmi.server.logCalls=true
