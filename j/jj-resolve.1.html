NOMBRE

jj-resolve - Resuelve archivos en conflicto con una herramienta de fusión externa

SINOPSIS

jj resolve [-r|--revision] [-l|--list] [--tool] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] [CONJUNTOS-DE-ARCHIVOS]

DESCRIPCIÓN

Resuelve archivos en conflicto con una herramienta de fusión externa.

Solo se admiten conflictos que se pueden resolver con una fusión de 3 vías. Consulte la documentación para obtener instrucciones de configuración de la herramienta de fusión. Las herramientas de fusión externas se invocarán para cada archivo en conflicto uno por uno hasta que se resuelvan todos los conflictos. Para dejar de resolver conflictos, salga de la herramienta de fusión sin realizar ningún cambio.

Tenga en cuenta que los conflictos también se pueden resolver sin usar este comando. Puede editar los marcadores de conflicto en el archivo en conflicto directamente con un editor de texto.

OPCIONES

-r, --revision <REVISION> [por defecto: @]
-l, --list
En lugar de resolver conflictos, lista todos los conflictos.
--tool <NOMBRE>
Especifica la herramienta de fusión de 3 vías a utilizar.

Las herramientas de fusión integradas `:ours` y `:theirs` se pueden usar para elegir el lado #1 y el lado #2 del conflicto, respectivamente.

-h, --help
Imprime la ayuda (vea un resumen con '-h').
[CONJUNTOS-DE-ARCHIVOS]
Resuelve solo conflictos en estas rutas. Puede usar el argumento `--list` para encontrar las rutas a utilizar aquí.

OPCIONES GENERALES

-R, --repository <REPOSITORIO>
Ruta al repositorio a operar.

Por defecto, Jujutsu busca el directorio más cercano .jj/ en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No crea una instantánea del directorio de trabajo y no lo actualiza.

Por defecto, Jujutsu crea una instantánea del directorio de trabajo al principio de cada comando. El directorio de trabajo también se actualiza al final del comando, si el comando modificó el commit del directorio de trabajo (`@`). Si desea evitar crear una instantánea del directorio de trabajo y ver en su lugar un commit del directorio de trabajo posiblemente desactualizado, puede usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en un prompt de comandos, especialmente si tiene otro proceso que confirma el directorio de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permite reescribir commits inmutables.

Por defecto, Jujutsu evita reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y le permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta al revset `immutable_heads()` ni a la palabra clave de plantilla `immutable`.

--at-operation <OPERACIÓN_EN>
Operación en la que cargar el repositorio.

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puede usar `--at-op=<ID de operación>` para ver cómo se veía el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` le mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Utilice `jj op log` para encontrar el ID de operación que desea. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignorará el directorio de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilita el registro de depuración.
--color <CUÁNDO>
Cuándo colorear la salida.

[valores posibles: always, never, debug, auto]

--quiet
Silencia la salida de comandos no primarios.

Por ejemplo, `jj file list` seguirá listando archivos, pero no le dirá si se creó una instantánea del directorio de trabajo o si los descendientes fueron rebajados.

Las advertencias y los errores seguirán imprimiéndose.

--no-pager
Deshabilita el paginador.
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir).

El nombre debe especificarse como claves puntuales de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está entrecomillado con ninguna construcción TOML (como la notación de matriz), las comillas se pueden omitir.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir).
resolve
