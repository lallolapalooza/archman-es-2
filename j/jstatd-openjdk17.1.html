JSTATD(1) Comandos JDK JSTATD(1)

NOMBRE

jstatd - monitoriza la creación y terminación de VMs HotSpot de Java instrumentadas

SINOPSIS

Nota: Este comando es experimental y no está soportado.

jstatd [opciones]

opciones
Esto representa las opciones de línea de comandos de jstatd. Ver Opciones para el comando jstatd.

DESCRIPCIÓN

El comando jstatd es una aplicación servidor RMI que monitoriza la creación y terminación de VMs HotSpot de Java instrumentadas y proporciona una interfaz para permitir a las herramientas de monitorización remota, jstat y jps, conectarse a las JVMs que se están ejecutando en el host local y recopilar información sobre el proceso de la JVM.

El servidor jstatd requiere un registro RMI en el host local. El servidor jstatd intenta conectarse al registro RMI en el puerto por defecto, o en el puerto que especifiques con la opción -p puerto. Si no se encuentra un registro RMI, se crea uno dentro de la aplicación jstatd que está enlazado al puerto indicado por la opción -p puerto o al puerto por defecto del registro RMI cuando se omite la opción -p puerto. Puedes detener la creación de un registro RMI interno especificando la opción -nr.

OPCIONES PARA EL COMANDO JSTATD

-nr
Esta opción no intenta crear un registro RMI interno dentro del proceso jstatd cuando no se encuentra un registro RMI existente.
-p puerto
Esta opción establece el número de puerto donde se espera encontrar el registro RMI, o cuando no se encuentra, crearlo si la opción -nr no está especificada.
-r puertormi
Esta opción establece el número de puerto al que se enlaza el conector RMI. Si no se especifica, se utiliza un puerto aleatorio disponible.
-n nombrermi
Esta opción establece el nombre al que se enlaza el objeto RMI remoto en el registro RMI. El nombre por defecto es JStatRemoteHost. Si se inician múltiples servidores jstatd en el mismo host, el nombre del objeto RMI exportado para cada servidor puede hacerse único especificando esta opción. Sin embargo, hacer esto requiere que el nombre de servidor único se incluya en las cadenas hostid y vmid del cliente de monitorización.
-Jopción
Esta opción pasa una opción de Java a la JVM, donde la opción es una de las descritas en la página de referencia del lanzador de aplicaciones de Java. Por ejemplo, -J-Xms48m establece la memoria de inicio en 48 MB. Ver java.

SEGURIDAD

El servidor jstatd solo puede monitorizar JVMs para las que tiene los permisos de acceso nativo apropiados. Por lo tanto, el proceso jstatd debe ejecutarse con las mismas credenciales de usuario que las JVMs objetivo. Algunas credenciales de usuario, como el usuario root en sistemas operativos Linux y OS X, tienen permiso para acceder a la instrumentación exportada por cualquier JVM en el sistema. Un proceso jstatd ejecutándose con dichas credenciales puede monitorizar cualquier JVM en el sistema, pero introduce preocupaciones de seguridad adicionales.

El servidor jstatd no proporciona ninguna autenticación de clientes remotos. Por lo tanto, ejecutar un proceso servidor jstatd expone la instrumentación exportada por todas las JVMs para las que el proceso jstatd tiene permisos de acceso a cualquier usuario en la red. Esta exposición podría ser indeseable en tu entorno, y por lo tanto, se deben considerar las políticas de seguridad locales antes de iniciar el proceso jstatd, particularmente en entornos de producción o en redes que no son seguras.

El servidor jstatd instala una instancia de RMISecurityPolicy cuando no hay ningún otro gestor de seguridad instalado, y por lo tanto, requiere que se especifique un archivo de política de seguridad. El archivo de política debe cumplir con la Implementación Predeterminada de Políticas y la Sintaxis de Archivos de Política.

Si tus preocupaciones de seguridad no pueden ser abordadas con un archivo de política personalizado, entonces la acción más segura es no ejecutar el servidor jstatd y usar las herramientas jstat y jps localmente. Sin embargo, al usar jps para obtener una lista de JVMs instrumentadas, la lista no incluirá ninguna JVM que se ejecute en contenedores docker.

INTERFAZ REMOTA

La interfaz exportada por el proceso jstatd es propietaria y está garantizada que cambiará. Se desaconseja a los usuarios y desarrolladores que escriban para esta interfaz.

EJEMPLOS

Los siguientes son ejemplos del comando jstatd. Los scripts de jstatd inician automáticamente el servidor en segundo plano.

REGISTRO RMI INTERNO

Este ejemplo muestra cómo iniciar una sesión de jstatd con un registro RMI interno. Este ejemplo asume que ningún otro servidor está enlazado al puerto por defecto del registro RMI (puerto 1099).

jstatd -J-Djava.security.policy=all.policy

REGISTRO RMI EXTERNO

Este ejemplo inicia una sesión de jstatd con un registro RMI externo.


rmiregistry&
jstatd -J-Djava.security.policy=all.policy

Este ejemplo inicia una sesión de jstatd con un servidor de registro RMI externo en el puerto 2020.


jrmiregistry 2020&
jstatd -J-Djava.security.policy=all.policy -p 2020

Este ejemplo inicia una sesión de jstatd con un servidor de registro RMI externo en el puerto 2020 y el conector JMX enlazado al puerto 2021.


jrmiregistry 2020&
jstatd -J-Djava.security.policy=all.policy -p 2020 -r 2021

Este ejemplo inicia una sesión de jstatd con un registro RMI externo en el puerto 2020 que está enlazado a AlternateJstatdServerName.


rmiregistry 2020&
jstatd -J-Djava.security.policy=all.policy -p 2020 -n AlternateJstatdServerName
#x00A0;-n AlternateJstatdServerName
