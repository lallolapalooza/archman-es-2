NOMBRE

j4-dmenu-desktop — menú de escritorio rápido

SINOPSIS

j4-dmenu-desktop [OPCIONES]

DESCRIPCIÓN

j4-dmenu-desktop es un reemplazo más rápido para i3-dmenu-desktop.

Su propósito es encontrar archivos .desktop y ofrecerle un menú para iniciar una aplicación usando dmenu.

Los argumentos son los siguientes:

-b, --display-binary
Muestra el nombre binario después de cada entrada (desactivado por defecto).
-f, --display-binary-base
Muestra el nombre base del nombre binario después de cada entrada (desactivado por defecto).
-d, --dmenu comando
Determina el comando utilizado para invocar dmenu. Se ejecuta con tu shell ($SHELL) o /bin/sh.
--no-exec
No ejecuta el comando seleccionado, lo envía a stdout en su lugar.
--no-generic
No incluye el nombre genérico de las entradas de escritorio.
-t, --term comando
Establece el emulador de terminal utilizado para iniciar aplicaciones de terminal.
--term-mode modo
Instruye a j4-dmenu-desktop sobre cómo debe ejecutar el emulador de terminal. Esta bandera también cambia el valor predeterminado de la bandera --term.

Los valores posibles son: default | xterm | alacritty | kitty | terminator | gnome-terminal | custom

Consulta MODO DE TERMINAL para más información.

--usage-log archivo
Debe apuntar a un archivo de lectura/escritura (se creará si no existe). En este modo, las entradas se ordenan por frecuencia de uso.
--prune-bad-usage-log-entries
Elimina los nombres marcados en el registro de uso para los cuales j4-dmenu-desktop no pudo encontrar un archivo de escritorio. Esto puede suceder cuando una aplicación marcada en el registro de uso ya no existe porque fue desinstalada.
-x, --use-xdg-de
Habilita la lectura de $XDG_CURRENT_DESKTOP para determinar el entorno de escritorio.
--wait-on ruta
Debe apuntar a una ruta donde se pueda crear un archivo. En este modo no se mostrará ningún menú. En su lugar, el programa espera a que se escriba en ruta (usa ‘echo > ruta’). Cada vez que esto sucede, se mostrará un menú. Los archivos de escritorio se analizan de antemano. Realizar ‘echo -n q > ruta’ saldrá del programa.
--wrapper wrapper
Un binario wrapper. El uso de ‘--wrapper "i3 exec"’ y ‘--wrapper "sway exec"’ está obsoleto, usa --i3-ipc en su lugar.
-I, --i3-ipc
Ejecuta entradas de escritorio a través de i3 IPC o Sway IPC. Requiere que i3 o Sway estén en ejecución.
--skip-i3-exec-check
Deshabilita la comprobación de --wrapper "i3 exec" o --wrapper "sway exec". j4-dmenu-desktop tiene soporte directo para i3/Sway a través de la bandera -I que debe usarse en lugar de la opción --wrapper. j4-dmenu-desktop detecta esto y sale. Esta bandera anula este comportamiento.
-i, --case-insensitive
Ordena las aplicaciones sin distinguir entre mayúsculas y minúsculas
-v
Sé más verboso. Cuando se especifica una vez, se usa INFO, cuando se especifica dos veces, se usa DEBUG. Ver NIVELES DE REGISTRO.
--log-level ERROR | WARNING | INFO | DEBUG
Una versión más explícita de -v. Esta bandera tiene precedencia sobre -v.
--log-file archivo
Especifica un archivo de registro. archivo se truncará. Por defecto, se utiliza el nivel de registro INFO.
--log-file-level ERROR | WARNING | INFO | DEBUG
Establece el nivel de registro del archivo.
--desktop-file-quirks ARGS
Modifica el mecanismo de análisis de archivos de escritorio de j4-dmenu-desktop para acomodar archivos de escritorio que no cumplen con la Especificación de Entradas de Escritorio. Se pueden especificar varios modos. Deben estar separados por una coma (,). Cada modo tiene una contraparte nomodo, que deshabilita el modo nombrado. Para deshabilitar todos los modos, usa --strict-parsing. Se imprime una advertencia cuando un archivo de escritorio hace uso de una quirk habilitada. ARGS puede contener los siguientes modos:
wine
Tolerar códigos de escape inválidos (como escapar un espacio para deshabilitar la separación de argumentos) en la clave Exec de los archivos de escritorio. Habilitado por defecto.
multispace
Tolerar el uso de varios espacios para separar argumentos en la clave Exec de los archivos de escritorio. Útil para archivos de escritorio generados por distrobox. Habilitado por defecto.

Si esta bandera se especifica varias veces, solo la última afecta. No se fusionan ni combinan de ninguna manera.

Esta bandera es mutuamente excluyente con --strict-parsing.

--strict-parsing
Adhiérete estrictamente a la Especificación de Entradas de Escritorio al analizar archivos de escritorio. No está habilitado por defecto.

Esta bandera es mutuamente excluyente con --desktop-file-quirks.

--version
Muestra la versión del programa.
-h, --help
Muestra el mensaje de ayuda.

NIVELES DE REGISTRO

Algunos argumentos admiten el establecimiento del nivel de registro. j4-dmenu-desktop utiliza los siguientes niveles de registro: ERROR, WARNING, INFO

OPTIONS

Las siguientes opciones están disponibles:

-c, --choice argumento
Permite al usuario elegir entre varias opciones. Las opciones están separadas por el carácter Pipe (|). La opción seleccionada es devuelta como salida estándar. Si no se elige ninguna opción, se devuelve una cadena vacía y el programa termina con el código de salida 0. Si el usuario presiona Esc o Ctrl-C, se devuelve una cadena vacía y el programa termina con el código de salida 1.
-C, --config archivo
Lee la configuración de un archivo. Si no se especifica, j4-dmenu-desktop buscará ~/.config/j4-dmenu-desktop/config y ~/.config/j4-dmenu-desktop/config.sh. Las opciones especificadas en la línea de comandos anulan las del archivo de configuración.
-d, --dmenu argumento
Argumento a pasar a dmenu(1). Puede especificarse varias veces. Por defecto, se utiliza el conjunto de opciones -i -p "dmenu: " -l 20.
-D, --debug
Habilita mensajes de depuración. Esto también habilita los niveles de registro INFO y WARNING. Los niveles de registro DEBUG, INFO y WARNING se muestran por defecto.
-f, --filter filtro
Filtra las aplicaciones que se muestran. El filtro se evalúa en un contexto de Lua. Consulte la sección LUA FILTER LANGUAGE para obtener más detalles.
-h, --help
Muestra un mensaje de ayuda y sale.
-l, --log nivel
Establece el nivel de registro. Los niveles disponibles son: DEBUG, INFO, WARNING, ERROR, CRITICAL. Los niveles de registro más bajos habilitan automáticamente los más altos. Los niveles de registro WARNING (y ERROR) se muestran por defecto.
-l, --list
Imprime una lista de todas las aplicaciones encontradas y sale.
-H, --show-hidden
Muestra las aplicaciones ocultas (aquellas cuyo campo NoDisplay está establecido en true).
-t, --term argumento
Especifica el comando y los argumentos para ejecutar un emulador de terminal. La forma en que se analizan estos argumentos depende del valor de --term-mode.
-m, --term-mode modo
Especifica el modo de terminal a utilizar. Consulte la sección TERM MODE para obtener una descripción de los modos disponibles.
-v, --version
Muestra la información de la versión y sale.

TERM MODE

Hay varios modos disponibles para el flag --term-mode:

default
El modo por defecto. Se crea un script de shell temporal que contiene el comando elegido. El script se autodestruye tras su ejecución, j4-dmenu-desktop nunca lo elimina. Establece el título del emulador de terminal usando secuencias de escape OSC (ver console_codes(4)). El emulador de terminal se ejecuta de la siguiente manera:
[emulador de terminal] -e [script temporal generado]

Se deben preferir otros modos. Este enfoque es universal pero frágil.

El valor por defecto de --term es i3-sensible-terminal.

xterm
Usa la convención de llamada de xterm:
[emulador de terminal] -title [Nombre de la aplicación de escritorio] -e [línea de comando]

El valor por defecto de --term es xterm. Otros emuladores de terminal compatibles incluyen: rxvt-unicode.

alacritty
Usa la convención de llamada de alacritty:
[emulador de terminal] -T [Nombre de la aplicación de escritorio] -e [línea de comando]

El valor por defecto de --term es alacritty. Otros emuladores de terminal compatibles incluyen: st, foot.

kitty
Usa la convención de llamada de kitty:
[emulador de terminal] -T [Nombre de la aplicación de escritorio] [línea de comando]

El valor por defecto de --term es kitty. Otros emuladores de terminal compatibles incluyen: foot.

terminator
Usa la convención de llamada de terminator:
[emulador de terminal] -T [Nombre de la aplicación de escritorio] -x [línea de comando]

El valor por defecto de --term es terminator. Otros emuladores de terminal compatibles incluyen: xfce4-terminal.

gnome-terminal
Usa la convención de llamada de gnome-terminal:
[emulador de terminal] --title [Nombre de la aplicación de escritorio] -- [línea de comando]

El valor por defecto de --term es gnome-terminal.

custom
Permite un manejo completamente personalizado de --term. Cuando se pasa --term-mode custom, se utiliza un sistema alternativo para manejar --term. Se maneja como una lista de argumentos separados por espacio ( ). Ningún otro carácter de espacio en blanco actúa como separador de argumentos (este comportamiento difiere del shell).

Múltiples espacios consecutivos se tratarán como un solo espacio (excepto los espacios escapados). Los espacios iniciales y finales en --term se ignorarán. Esto significa que no es posible pasar argumentos de longitud cero a --term.

El contenido de --term no se ejecuta a través de un shell. Esto significa que las construcciones del shell como redirección, encadenamiento && y || y más no funcionarán. Si necesita esto, puede crear un script de shell envoltorio y llamarlo desde --term o puede llamar directamente a /bin/sh -c o a algún otro shell desde --term (aunque se debería preferir usar un script envoltorio, porque es más claro y simple de usar).

Los siguientes marcadores de posición son reconocidos:

{name}
Nombre de la aplicación de escritorio. Útil para establecer el título.
{cmdline@}
Línea de comando a ejecutar expandida como argumentos separados. Este debe ser un argumento independiente; ‘j4-dmenu-desktop --term-mode custom --term "-e={cmdline@}"’ es inválido.
{cmdline*}
Línea de comando a ejecutar expandida como un solo argumento. Se debe preferir {cmdline@} sobre {cmdline*}. Los argumentos se escaparán; el contenido de {cmdline*} se puede pasar de forma segura a /bin/sh -c.
{script}
Nombre de archivo de un script generado por j4-dmenu-desktop. Este es el mismo script utilizado por --term-mode default. El script se generará solo si este marcador de posición se especifica al menos una vez en --term. El script establece el título del terminal por sí mismo, no debería ser necesario establecerlo manualmente.

Se deben preferir {cmdline@} y {cmdline*} sobre {script}.

Las siguientes secuencias de escape son reconocidas:

\\
Carácter \ literal.
\{
Carácter { literal.
\ 
(barra invertida seguida de espacio) No manejar el siguiente espacio como separador de argumentos.

Las secuencias de escape y marcadores de posición indefinidos resultarán en un mensaje de error y la terminación del programa.

El valor por defecto de --term es el mismo que el del modo de terminal default.

Así es como se ven otros modos cuando se escriben usando el modo custom:

default
‘j4-dmenu-desktop --term-mode custom --term "i3-sensible-terminal -e {script}"’
xterm
‘j4-dmenu-desktop --term-mode custom --term "xterm -title {name} -e {cmdline@}"’
alacritty
‘j4-dmenu-desktop --term-mode custom --term "alacritty -T {name} -e {cmdline@}"’
kitty
‘j4-dmenu-desktop --term-mode custom --term "kitty -T {name} {cmdline@}"’
terminator
‘j4-dmenu-desktop --term-mode custom --term "terminator -T {name} -x {cmdline@}"’
gnome-terminal
‘j4-dmenu-desktop --term-mode custom --term "gnome-terminal --title {name} -- {cmdline@}"’

Así es como se podría usar el flag obsoleto -e de gnome-terminal:

j4-dmenu-desktop --term-mode custom --term "gnome-terminal --title {name} -e {cmdline*}"

Así es como se pueden escapar los marcadores de posición:

j4-dmenu-desktop --term-mode custom --term "echo \{name}\ \{cmdline*}"

--term recibe dos argumentos: ‘echo’ y ‘{name} {cmdline*}’, no se reemplazan marcadores de posición. j4-dmenu-desktop vería tres argumentos en lugar de dos si no se hubiera pasado la segunda barra invertida.

ENVIRONMENT

I3SOCK
Esta variable sobrescribe la ruta del socket IPC de i3/Sway.
XDG_DATA_HOME
Directorio principal que contiene los archivos de escritorio.
XDG_DATA_DIRS
Directorios adicionales que contienen archivos de escritorio.
XDG_CURRENT_DESKTOP
Entorno de escritorio actual utilizado para habilitar/deshabilitar archivos de escritorio dependientes del entorno de escritorio. Debe ser habilitado con --use-xdg-de.

Las variables de entorno estándar para las configuraciones regionales se reconocen además de las enumeradas anteriormente. Las variables de entorno exactas utilizadas dependen de la implementación, pero generalmente funciona establecer LC_MESSAGES, LC_ALL o LANG.
