jj-help(1) Manual de Comandos Generales jj-help(1)

NOMBRE

jj-help - Imprime este mensaje o la ayuda del subcomando(s) dado(s)

SINOPSIS

jj help [-k|--keyword] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] [COMANDO]

DESCRIPCIÓN

Imprime este mensaje o la ayuda del subcomando(s) dado(s)

OPCIONES

-k, --keyword <PALABRA_CLAVE>
Muestra ayuda para palabras clave en lugar de comandos

Posibles valores:

  • bookmarks: Punteros con nombre a revisiones (similar a las ramas de Git)
  • config: Cómo y dónde configurar opciones de configuración
  • filesets: Un lenguaje funcional para seleccionar un conjunto de archivos
  • glossary: Definiciones de varios términos
  • revsets: Un lenguaje funcional para seleccionar un conjunto de revisiones
  • templates: Un lenguaje funcional para personalizar la salida de comandos
  • tutorial: Muestra un tutorial para empezar con jj
-h, --help
Imprime la ayuda (ver un resumen con '-h')
[COMANDO]
Imprime la ayuda para el(los) subcomando(s)

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio para operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No guardar la copia de trabajo, ni actualizarla

Por defecto, Jujutsu guarda la copia de trabajo al inicio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si quieres evitar guardar la copia de trabajo y ver en su lugar un commit de copia de trabajo posiblemente obsoleto, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tienes otro proceso que confirma la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permite reescribir commits inmutables

Por defecto, Jujutsu previene la reescritura de commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y te permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta el revset `immutable_heads()` ni la palabra clave `immutable` de la plantilla.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puedes usar `--at-op=<ID de operación>` para ver cómo era el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` te mostrará lo que `jj st` habría mostrado cuando la operación dada había terminado. `--at-op=@` es casi lo mismo que por defecto, excepto que las operaciones divergentes nunca se fusionarán.

Usa `jj op log` para encontrar el ID de operación que deseas. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, la copia de trabajo será ignorada, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutantes al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes a partir de la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilitar registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[posibles valores: always, never, debug, auto]

--quiet
Silenciar la salida no principal del comando

Por ejemplo, `jj file list` todavía listará archivos, pero no te dirá si la copia de trabajo fue guardada o si los descendientes fueron reescritos.

Las advertencias y errores seguirán imprimiéndose.

--no-pager
Desactivar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se puede repetir)

El nombre debe especificarse como claves punteadas de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado por ninguna construcción de TOML (como notación de array), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
