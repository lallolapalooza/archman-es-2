NOMBRE

jj-absorb - Mueve cambios de una revisión a la pila de revisiones mutables

SINOPSIS

jj absorb [-f|--from] [-t|--into] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] [CONJUNTOS_DE_ARCHIVOS]

DESCRIPCIÓN

Mueve cambios de una revisión a la pila de revisiones mutables

Este comando divide los cambios en la revisión de origen y mueve cada cambio al ancestro mutable más cercano donde las líneas correspondientes fueron modificadas por última vez. Si la revisión de destino no se puede determinar inequívocamente, el cambio permanecerá en la revisión de origen.

La revisión de origen será abandonada si todos los cambios se absorben en las revisiones de destino, y si la revisión de origen no tiene descripción.

La modificación realizada por `jj absorb` se puede revisar con `jj op show -p`.

OPCIONES

-f, --from <REVSET> [predeterminado: @]
Revisión de origen de la que absorber
-t, --into <CONJUNTOS_DE_REVISIONES> [predeterminado: mutable()]
Revisiones de destino a las que absorber

Solo se considerarán los ancestros de la revisión de origen.

-h, --help
Imprimir ayuda (ver un resumen con '-h')
[CONJUNTOS_DE_ARCHIVOS]
Mover solo cambios a estas rutas (en lugar de todas las rutas)

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No hacer una instantánea del directorio de trabajo y no actualizarlo

Por defecto, Jujutsu hace una instantánea del directorio de trabajo al principio de cada comando. El directorio de trabajo también se actualiza al final del comando, si el comando modificó el commit del directorio de trabajo (`@`). Si desea evitar hacer una instantánea del directorio de trabajo y ver en su lugar un commit del directorio de trabajo posiblemente obsoleto, puede usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tiene otro proceso que realiza commits del directorio de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu evita reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa comprobación y le permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta a la comprobación. No afecta al revset `immutable_heads()` ni a la palabra clave de plantilla `immutable`.

--at-operation <OPERACION_EN>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puede usar `--at-op=<ID_OPERACION>` para ver cómo se veía el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID_OPERACION> st` le mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Use `jj op log` para encontrar el ID de operación que desea. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, el directorio de trabajo se ignorará, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repositorio en una operación anterior. Hacer eso es equivalente a haber ejecutado comandos concurrentes a partir de la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilitar el registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[posibles valores: always, never, debug, auto]

--quiet
Silenciar la salida no principal del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no le dirá si se hizo una instantánea del directorio de trabajo o si los descendientes fueron rebasados.

Las advertencias y los errores seguirán imprimiéndose.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves anidadas de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está envuelto en ninguna construcción de TOML (como la notación de matriz), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
absorb
