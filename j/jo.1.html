jo - Salida JSON desde un

shell

SIN

OP
SIS

jo [-p] [-a] [-B] [-D] [-e] [-n] [-v] [-V] [-d keydelim] [-f file] [–] [ [-s|-n|-b]

word ...]

DESC

RIP
CIÓN

jo crea una cadena JSON

en

stdout a partir de words dadas como argumentos o leídas desde stdin. Si se especifica -f, jo primero carga el contenido de file como un objeto o array JSON, luego lo modifica con las words posteriores antes de imprimir la cadena JSON final en stdout. file puede especificarse como - para leer desde la entrada estándar de jo; esto tiene prioridad sobre la lectura de words desde stdin

.

Sin la opción -a genera un objeto en el que cada word es un par clave=valor (o clave@valor) con clave siendo el elemento del objeto JSON y valor su valor. jo intenta adivinar el tipo de valor para crear valores numéricos (usando strtod(3)), de cadena o null en

JSON.

Un valor faltante o vacío normalmente resulta en un elemento cuyo valor es null. Si se especifica -n, este elemento no se

crea.

jo normalmente trata clave como un valor de cadena literal. Si se especifica la opción -d, clave se interpretará como una ruta de objeto, cuyos componentes individuales están separados por el primer carácter de keydelim

.

jo normalmente trata valor como un valor de cadena literal, a menos que comience con uno de los siguientes

caracteres: acción hivo contenido de ivo contenido de hivo contenido de barra invertida para evitar esta
valor @arc
sustituye el archivo tal cual %arch
sustituye el archivo en forma codificada en base64 :arc
interpreta el archivo como JSON y sustituye el resultado Escape el carácter especial con una
interpretación.

jo trata clave@valor específicamente como elementos booleanos JSON: si el valor comienza con T, t, o el valor numérico es mayor que cero, el resultado es true, de lo contrario

false.

jo crea un array en lugar de un objeto cuando se especifica

-a.

Cuando se usa el operador := en

una

word, el nombre a la derecha de := es un archivo que contiene JSON el cual es analizado y asignado a la clave a la izquierda del operador. El archivo puede especificarse como - para leer desde la entrada estándar de jo

.

Crea objetos dentro de objetos; esto funciona porque si el primer carácter de valor es una llave de apertura o un corchete intentamos decodificar el resto como JSON. ¡Cuidado con los espacios en las cadenas ...

! 
$ jo -p name=JP object=$(jo fruit=Orange hungry@0 point=$(jo x=10 y=20 list=$(j

Booleanos como cadenas o como booleano (presta especial atención al switch; la opción -B desactiva la detección predeterminada de las cadenas “true”, “false” y “null”)

: 
$ jo switch=true morning@0
{"s
witch":true,"morning":false} $
jo -B switch=true morning@0 {"s
witch":"true","morning":false}

Los elementos (objetos y arrays) pueden anidarse. El siguiente ejemplo anida un array llamado point y un objeto llamado geo

: 
$ jo -p name=Jane point[]=1 point[]=2 geo[lat]=10 geo[lon]=20
{
   "name": "Jane",
   "point": [
      1,
      2
   ],
   "geo": {
      "lat": 10,
      "lon": 20
}
}

El mismo ejemplo, usando rutas de

objeto: 
$ jo -p -d. name=Jane point[]=1 point[]=2 geo.lat=10 geo.lon=20

   "name": "Jane",

      1,
      2
   ],
   "geo": {
      "lat": 10,
      "lon": 20
}
}

4K"} $ jo nested=:nested.json {"nested":{"field1":123,"field2":"abc"}}

OPCIONE

S

jo entiende las siguientes opciones

globales.
-
a
Interpretar la lista de palabras como valores de array y producir un array en lugar de un
objeto.
-
B
De forma predeterminada, jo interpreta las cadenas “true” y “false” como elementos booleanos true y false respectivamente, y “null” como null. Deshabilite con esta
opción.
-
D
Deduplicar claves de
objeto.
-
e
Ignorar stdin vacío (es decir, no producir un error de diagnóstico cuando stdin esté
vacío)
-
n
No añadir claves con valores
vacíos.
-
p
Imprimir la cadena JSON con formato en la salida en lugar de la salida de una sola línea concisa que imprime de forma
predeterminada.
-
v
Mostrar versión y
salir.
-
V
Mostrar ver
sión como u
n objeto JS
ON y salir.

ERRORE

S

Probablemente

.

Si un valor dado a jo se expande a vacío en el shell, entonces jo produce un null en modo objeto, y podría parecer que se cuelga en modo array; no se está colgando, sino que está leyendo stdin. Esto no es un

error.

Los valores numéricos se convierten a números, lo que puede producir resultados no deseados. Si cita un valor numérico, jo lo hará una cadena. Compare lo

siguiente: 
$ jo a=1.0
{"a":1} $ j
o a=\"1.0\"
{"a":"1.0"}

Omitir un corchete de cierre en un elemento anidado hace

que se imprima un mensaje de diagnóstico, pero la sal
ida contiene basura de todos modos. Fue diseñado así.
