NOMBRE

jshell - evalúa interactivamente declaraciones, sentencias y expresiones del lenguaje de programación Java en un bucle leer-evaluar-imprimir (REPL)

SINOPSIS

jshell [opciones] [archivos-a-cargar]

opciones
Opciones de línea de comandos, separadas por espacios. Ver Opciones para jshell.
archivos-a-cargar
Uno o más scripts para ejecutar cuando se inicia la herramienta. Los scripts pueden contener cualquier fragmento de código o comando JShell válido.

El script puede ser un archivo local o uno de los siguientes scripts predefinidos:

DEFAULT
Carga las entradas predeterminadas, que se usan comúnmente como importaciones.
JAVASE
Importa todos los paquetes de Java SE.
PRINTING
Define print, println y printf como métodos de jshell para usar dentro de la herramienta.

Para más de un script, usa un espacio para separar los nombres. Los scripts se ejecutan en el orden en que se ingresan en la línea de comandos. Los scripts de la línea de comandos se ejecutan después de los scripts de inicio. Para ejecutar un script después de que JShell se inicia, usa el comando /open.

Para aceptar entrada desde la entrada estándar y suprimir la E/S interactiva, ingresa un guion (-) para archivos-a-cargar. Esta opción permite el uso de la herramienta jshell en cadenas de tuberías.

DESCRIPCIÓN

JShell proporciona una forma de evaluar interactivamente declaraciones, sentencias y expresiones del lenguaje de programación Java, facilitando el aprendizaje del lenguaje, la exploración de código y APIs desconocidas, y la creación de prototipos de código complejo. Se aceptan sentencias Java, definiciones de variables, definiciones de métodos, definiciones de clases, sentencias de importación y expresiones. Los fragmentos de código ingresados se llaman snippets.

A medida que se ingresan los snippets, se evalúan y se proporciona retroalimentación. La retroalimentación varía desde los resultados y explicaciones de las acciones hasta nada, dependiendo del snippet ingresado y el modo de retroalimentación elegido. Los errores se describen independientemente del modo de retroalimentación. Comienza con el modo verboso para obtener la máxima retroalimentación mientras aprendes la herramienta.

Hay opciones de línea de comandos disponibles para configurar el entorno inicial al iniciar JShell. Dentro de JShell, hay comandos disponibles para modificar el entorno según sea necesario.

Se pueden cargar snippets existentes desde un archivo para inicializar una sesión de JShell, o en cualquier momento dentro de una sesión. Los snippets se pueden modificar dentro de la sesión para probar diferentes variaciones y realizar correcciones. Para conservar los snippets para uso posterior, guárdalos en un archivo.

OPCIONES PARA JSHELL

--add-exports módulo/paquete
Especifica un paquete que se considerará exportado desde su módulo de definición.
--add-modules módulo[,módulo...]
Especifica los módulos raíz a resolver además del módulo inicial.
-Cbandera
Proporciona una bandera para pasar al compilador. Para pasar más de una bandera, proporciona una instancia de esta opción para cada bandera o argumento de bandera necesario.
--class-path ruta
Especifica los directorios y archivos que se buscan para localizar archivos de clase. Esta opción anula la ruta en la variable de entorno CLASSPATH. Si la variable de entorno no está establecida y esta opción no se usa, entonces se busca el directorio actual. Para Linux y macOS, usa dos puntos (:) para separar elementos en la ruta. Para Windows, usa punto y coma (;) para separar elementos.
--enable-preview
Permite que el código dependa de las características de vista previa de esta versión.
--execution especificación
Especifica un motor de ejecución alternativo, donde especificación es una especificación de Control de Ejecución. Ver la documentación del paquete jdk.jshell.spi para la sintaxis de la especificación.
--feedback modo
Establece el nivel inicial de retroalimentación proporcionado en respuesta a lo que se ingresa. El nivel inicial puede ser anulado dentro de una sesión usando el comando /set feedback modo. El valor predeterminado es normal.

Los siguientes valores son válidos para modo:

verbose
Proporciona retroalimentación detallada para las entradas. Se muestra información adicional sobre la acción realizada después del resultado de la acción. El siguiente prompt se separa de la retroalimentación por una línea en blanco.
normal
Proporciona una cantidad media de retroalimentación. El siguiente prompt se separa de la retroalimentación por una línea en blanco.
concise
Proporciona retroalimentación mínima. El siguiente prompt sigue inmediatamente al fragmento de código o retroalimentación.
silent
No proporciona retroalimentación. El siguiente prompt sigue inmediatamente al fragmento de código.
custom
Proporciona modos de retroalimentación personalizados basados en cómo se define el modo. Los modos de retroalimentación personalizados se crean dentro de JShell usando el comando /set mode.
--help o -h o -?
Imprime un resumen de las opciones estándar y sale de la herramienta.
--help-extra o -X
Imprime un resumen de las opciones no estándar y sale de la herramienta. Las opciones no estándar están sujetas a cambios sin previo aviso.
-Jbandera
Proporciona una bandera para pasar al sistema de ejecución. Para pasar más de una bandera, proporciona una instancia de esta opción para cada bandera o argumento de bandera necesario.
--module-path rutamódulos
Especifica dónde encontrar los módulos de la aplicación. Para Linux y macOS, usa dos puntos (:) para separar elementos en la ruta. Para Windows, usa punto y coma (;) para separar elementos.
--no-startup
Evita que se ejecuten los scripts de inicio al comenzar JShell. Usa esta opción para ejecutar solo los scripts ingresados en la línea de comandos al iniciar JShell, o para iniciar JShell sin ninguna información previamente cargada si no se ingresan scripts. Esta opción no puede usarse si se usa la opción --startup.

start [-retain] [archivo [archivo...]|opción]
Establece los nombres de los scripts de inicio que se utilizan cuando se introduce el siguiente comando /reset, /reload o /env. Si se introducen varios scripts, los scripts se ejecutan en el orden en que se introducen. Si no se introducen scripts ni opciones, se muestran la configuración de inicio actual.

Los scripts pueden ser archivos locales o uno de los siguientes scripts predefinidos:

DEFAULT
Carga las entradas predeterminadas, que se utilizan comúnmente como importaciones.
JAVASE
Importa todos los paquetes de Java SE.
PRINTING
Define print, println y printf como métodos de jshell para su uso dentro de la herramienta.

Las siguientes opciones son válidas:

-default
Establece la configuración de inicio a la configuración predeterminada.
-none
Especifica que no se utiliza ninguna configuración de inicio.

Utilice la opción -retain para guardar la configuración de inicio entre sesiones.

truncation modo longitud selector
Establece la longitud máxima de un valor mostrado. Si no se introduce ningún modo, se muestran los valores de truncamiento actuales para todos los modos de retroalimentación. Si solo se introduce un modo, se muestran los valores de truncamiento actuales para ese modo.

Para definir los valores de truncamiento, se requieren los siguientes argumentos:

modo
Especifica el modo de retroalimentación al que se aplica el valor de truncamiento. Solo se pueden modificar los modos personalizados creados con el comando /set mode.
longitud
Especifica el entero sin signo que se utilizará como longitud máxima para el selector especificado.
selector
>
Spécifie le contexte dans lequel la valeur de troncature est appliquée. Les sélecteurs sont décrits dans l'aide en ligne, accessible depuis JShell à l'aide de la commande /help set truncation.

JAVASHELL


Start the JShell tool, a read-evaluate-print loop (REPL) for Java.


The jshell tool starts the JShell tool, a
    read-evaluate-print loop (REPL) for Java. The JShell tool enables you to
    enter, modify, and execute Java programming language statements, variable
    definitions, method definitions, class definitions, import statements, and
    expressions.


The JShell tool is useful for trying out Java language features,
    writing short programs, and debugging Java code. It can also be used to
    run Java applications.


When you start the JShell tool, a prompt is displayed, indicating
    that it is ready to accept input.



  

  

    

jshell>


  




You can enter Java statements and expressions at the prompt. The
    JShell tool will evaluate them and display the results.


The following example shows how to enter a variable declaration and
    then print its value:



  

  

    

jshell> int i =&#x00A0;42
i ==> 42


  




You can also enter method declarations, class declarations, and
    import statements.



  

  

    

jshell> jshell> System.out.println("Hello World!");
Hello World!
jshell> String name =&#x00A0;"World";
name ==> "World"
jshell> String greeting =&#x00A0;"Hello " + name;
greeting ==> "Hello World"
jshell> System.out.println(greeting);
Hello World


  




By default, JShell imports a set of common packages so that you
    don't have to import them explicitly. These are the same packages that are
    imported by default by the Java compiler.



  

  

    

s1 : import java.io.*;
s2 : import java.math.*;
s3 : import java.net.*;
s4 : import java.nio.file.*;
s5 : import java.util.*;
s6 : import java.util.concurrent.*;
s7 : import java.util.function.*;
s8 : import java.util.prefs.*;
s9 : import java.util.regex.*;
s10 : import java.util.stream.*;

    command.

EXAMPLE   OF ENTERING SNIPPETS


Snippets are Java statements, variable definitions, method
    definitions, class definitions, import statements, and expressions.
    Terminating semicolons are automatically added to the end of a completed
    snippet if they're missing.


The following example shows two variables and a method being
    defined, and the method being run. Note that a scratch variable is
    automatically created to hold the result because no variable was
  provided.



  

  

    

jshell> int a=4
a ==> 4
jshell> int b=8
b ==> 8
jshell> int square(int i1) {
   ...> return i1 * i1;
   ...> }
|  created method square(int)
jshell> square(b)
$5 ==> 64


  








EXAMPLE   OF CHANGING SNIPPETS


Change the definition of a variable, method, or class by entering
    it again.


The following examples shows a method being defined and the method
    run:



  

  

    

jshell> String grade(int testScore) {
   ...>     if (testScore >= 90) {
   ...>         return "Pass";
   ...>     }
   ...>     return "Fail";
   ...> }
|  created method grade(int)
jshell> grade(88)
$3 ==> "Fail"


  




To change the method grade to allow
    more students to pass, enter the method definition again and change the pass
    score to 80. Use the up arrow key to retrieve
    the previous entries to avoid having to reenter them and make the change in
    the if statement. The following example shows
    the new definition and reruns the method to show the new result:



  

  

    

jshell> String grade(int testScore) {
   ...>     if (testScore >= 80) {
   ...>         return "Pass";
   ...>     }
   ...>     return "Fail";
   ...> }
|  modified method grade(int)
jshell> grade(88)
$5 ==> "Pass"

    shows the command and the feedback provided when the edit window is closed.
    The /list command is used to show that the
    pass score was changed to 85.



  

  

    

jshell> /edit grade

EXAMPLE   OF CREATING A CUSTOM FEEDBACK MODE


The feedback mode determines the prompt that's displayed, the
    feedback messages that are provided as snippets are entered, and the maximum
    length of a displayed value. Predefined feedback modes are provided.
    Commands for creating custom feedback modes are also provided.


Use the /set mode command to
    create a new feedback mode. In the following example, the new mode
    mymode, is based on the predefined feedback
    mode, normal, and verifying command feedback
    is displayed:



  

  

    

jshell> /set mode mymode normal -command
|  Created new feedback mode: mymode


  




Because the new mode is based on the
    normal mode, the prompts are the same. The
    following example shows how to see what prompts are used and then changes
    the prompts to custom strings. The first string represents the standard
    JShell prompt. The second string represents the prompt for additional lines
    in multiline snippets.



  

  

    

jshell> /set prompt mymode
|  /set prompt mymode "\njshell> " "   ...> "
jshell> /set prompt mymode "\nprompt$ " "   continue$ "


  




The maximum length of a displayed value is controlled by the
    truncation setting. Different types of values can have different lengths.
    The following example sets an overall truncation value of 72, and a
    truncation value of 500 for variable value expressions:



  

  

    

jshell> /set truncation mymode 72
jshell> /set truncation mymode 500 varvalue


  




The feedback displayed after snippets are entered is controlled by
    the format setting and is based on the type of snippet entered and the
    action taken for that snippet. In the predefined mode
    normal, the string
    created is displayed when a method is
    created. The following example shows how to change that string to
    defined:



  

  

    

jshell> /set format mymode action "defined" added-primary

    command to start using the feedback mode that was just created. The
    following example shows the custom mode in use:



  

  

    

jshell> /set feedback mymode

   continue$ }
