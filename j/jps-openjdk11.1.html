jps(1) Herramientas de Monitorización jps(1)

NOMBRE

jps - Lista las Máquinas Virtuales Java (JVM) instrumentadas en el sistema de destino. Este comando es experimental y no está soportado.

SINOPSIS

jps [ opciones ] [ hostid ]
opciones
Opciones de la línea de comandos. Ver Opciones.
hostid
El identificador del host para el que se generará el informe de procesos. El hostid puede incluir componentes opcionales que indican el protocolo de comunicación, el número de puerto y otros datos específicos de la implementación. Ver Identificador de Host.

DESCRIPCIÓN

El comando jps lista las HotSpot VMs instrumentadas en el sistema de destino. El comando se limita a informar sobre JVMs para las cuales tiene permisos de acceso.

Si el comando jps se ejecuta sin especificar un hostid, entonces busca JVMs instrumentadas en el host local. Si se inicia con un hostid, entonces busca JVMs en el host indicado, usando el protocolo y puerto especificados. Se asume que un proceso jstatd está ejecutándose en el host de destino.

El comando jps informa el identificador local de JVM, o lvmid, para cada JVM instrumentada encontrada en el sistema de destino. El lvmid es típicamente, pero no necesariamente, el identificador de proceso del sistema operativo para el proceso JVM. Sin opciones, jps lista el lvmid de cada aplicación Java seguido de la forma abreviada del nombre de clase o del archivo JAR de la aplicación. La forma abreviada del nombre de clase o del nombre de archivo JAR omite la información del paquete de la clase o la información de la ruta del archivo JAR.

El comando jps utiliza el lanzador de Java para encontrar el nombre de la clase y los argumentos pasados al método principal. Si la JVM de destino se inicia con un lanzador personalizado, entonces el nombre de la clase o archivo JAR y los argumentos del método main no están disponibles. En este caso, el comando jps muestra la cadena Unknown para el nombre de la clase o archivo JAR y para los argumentos del método main.

La lista de JVMs producida por el comando jps puede estar limitada por los permisos concedidos al principal que ejecuta el comando. El comando solo lista las JVMs para las cuales el principal tiene derechos de acceso determinados por mecanismos de control de acceso específicos del sistema operativo.

OPCIONES

El comando jps soporta un número de opciones que modifican la salida del comando. Estas opciones están sujetas a cambios o eliminaciones en el futuro.

-q

Suprime la salida del nombre de la clase, nombre del archivo JAR y argumentos pasados al método main, produciendo solo una lista de identificadores locales de JVM.
-m

Muestra los argumentos pasados al método main. La salida puede ser null para JVMs incrustadas.
-l

Muestra el nombre completo del paquete de la clase main de la aplicación o la ruta completa al archivo JAR de la aplicación.
-v

Muestra los argumentos pasados a la JVM.
-V

Suprime la salida del nombre de la clase, nombre del archivo JAR y argumentos pasados al método principal, produciendo solo una lista de identificadores locales de JVM.
-Jopción

Pasa opción a la JVM, donde opción es una de las opciones descritas en la página de referencia para el lanzador de aplicaciones Java. Por ejemplo, -J-Xms48m establece la memoria de inicio en 48 MB. Ver java(1).

IDENTIFICADOR DE HOST

El identificador de host, o hostid, es una cadena que indica el sistema de destino. La sintaxis de la cadena hostid corresponde a la sintaxis de una URI:

[protocolo:][[//]hostname][:puerto][/nombreservidor]
protocolo
El protocolo de comunicación. Si se omite el protocolo y no se especifica un hostname, entonces el protocolo predeterminado es un protocolo local optimizado y específico de la plataforma. Si se omite el protocolo y se especifica un nombre de host, entonces el protocolo predeterminado es rmi.
hostname
Un nombre de host o dirección IP que indica el host de destino. Si se omite el parámetro hostname, entonces el host de destino es el host local.
puerto
El puerto predeterminado para comunicarse con el servidor remoto. Si se omite el parámetro hostname o el parámetro protocolo especifica un protocolo local optimizado, entonces el parámetro puerto se ignora. De lo contrario, el tratamiento del parámetro puerto es específico de la implementación. Para el protocolo rmi predeterminado, el parámetro puerto indica el número de puerto para el rmiregistry en el host remoto. Si se omite el parámetro puerto, y el parámetro protocolo indica rmi, entonces se utiliza el puerto predeterminado de rmiregistry (1099).
nombreservidor
El tratamiento de este parámetro depende de la implementación. Para el protocolo local optimizado, este campo se ignora. Para el protocolo rmi, este parámetro es una cadena que representa el nombre del objeto remoto RMI en el host remoto. Ver la opción -n del comando jstatd para más información.

FORMATO DE SALIDA

La salida del comando jps sigue el siguiente patrón:

lvmid [ [ nombreclase | nombreArchivoJAR | "Unknown"] [ arg* ] [ jvmarg* ] ]

Todos los tokens de salida están separados por espacios en blanco. Un valor arg que incluye espacios en blanco incrustados introduce ambigüedad al intentar mapear argumentos a sus parámetros posicionales reales.

Nota: Se recomienda no escribir scripts para analizar la salida de jps ya que el formato puede cambiar en futuras versiones. Si escribe scripts que analizan la salida de jps, prepárese para modificarlos para futuras versiones de esta herramienta.

EJEMPLOS

Esta sección proporciona ejemplos del comando jps.

Listar las JVMs instrumentadas en el host local:

jps
18027 Java2Demo.JAR
18032 jps
18005 jstat

El siguiente ejemplo lista las JVMs instrumentadas en un host remoto. Este ejemplo asume que el servidor jstat y ya sea su registro RMI interno o un proceso rmiregistry externo separado están ejecutándose en el host remoto en el puerto predeterminado (puerto 1099). También asume que el host local tiene los permisos apropiados para acceder al host remoto. Este ejemplo también incluye la opción -l para mostrar la forma larga de los nombres de clase o nombres de archivo JAR.

jps -l remote.domain
3002 /opt/jdk1.7.0/demo/jfc/Java2D/Java2Demo.JAR
2857 sun.tools.jstatd.jstatd

El siguiente ejemplo lista las JVMs instrumentadas en un host remoto con un puerto no predeterminado para el registro RMI. Este ejemplo asume que el servidor jstatd, con un registro RMI interno enlazado al puerto 2002, está ejecutándose en el host remoto. Este ejemplo también utiliza la opción -m para incluir los argumentos pasados al método main de cada una de las aplicaciones Java listadas.

jps -m remote.domain:2002
3002 /opt/jdk1.7.0/demo/jfc/Java2D/Java2Demo.JAR
3102 sun.tools.jstatd.jstatd -p 2002
