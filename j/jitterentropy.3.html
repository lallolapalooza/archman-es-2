NOMBRE

jitterentropy - Generador de números aleatorios por fluctuación de CPU

SINOPSIS

#include <jitterentropy.h>

int jent_entropy_switch_notime_impl(struct jent_notime_thread *new_thread);

int jent_set_fips_failure_callback(jent_fips_failure_cb cb);

int jent_entropy_init(void);

int jent_entropy_init_ex(unsigned int osr, unsigned int flags);

struct rand_data *jent_entropy_collector_alloc(unsigned int osr,
                                               unsigned int flags);

void jent_entropy_collector_free(struct rand_data *entropy_collector);

ssize_t jent_read_entropy(struct rand_data *entropy_collector,
                          char *data, size_t len);

ssize_t jent_read_entropy_safe(struct rand_data **entropy_collector,
                               char *data, size_t len);

#define JENT_MAJVERSION x

#define JENT_MINVERSION y

#define JENT_PATCHLEVEL z

#define JENT_VERSION (...)

unsigned int jent_version(void);

DESCRIPCIÓN

La biblioteca jitterentropy proporciona una fuente de buena entropía mediante la recopilación de fluctuaciones de tiempo de ejecución de la CPU. La entropía en la fluctuación del tiempo de ejecución de la CPU se amplifica mediante el Generador de Números Aleatorios por Fluctuación de CPU. El Generador de Números Aleatorios por Fluctuación de CPU utiliza la fluctuación de temporización de ejecución de la CPU para generar un flujo de bits que cumple con diferentes mediciones estadísticas que determinan que el flujo de bits es aleatorio.

El Generador de Números Aleatorios por Fluctuación de CPU entrega entropía que sigue los requisitos de la teoría de la información. Basado en estos estudios y la implementación, el llamador puede asumir que un bit de datos extraído del Generador de Números Aleatorios por Fluctuación de CPU contiene un bit de entropía.

El Generador de Números Aleatorios por Fluctuación de CPU proporciona una fuente descentralizada de entropía donde el llamador no necesita depender de una fuente de entropía mantenida centralmente como /dev/random o /dev/urandom.

jent_entropy_switch_notime_impl() permite al llamador establecer un manejador de hilo que es utilizado por el RNG de Fluctuación si opera en modo sin temporizador. Consulte jitterentropy.h para obtener documentación sobre new_thread. Esta función debe ser llamada antes de jent_entropy_init(), ya que después de esta llamada se deniega el cambio del manejador del hilo.

jent_set_fips_failure_callback() permite al llamador establecer una llamada de retorno que es invocada por el RNG de Fluctuación cuando se detecta un fallo en una prueba de salud. La llamada de retorno especificada con el parámetro cb a la función de la API recibe el estado del RNG de Fluctuación con el parámetro ec y el fallo de prueba de salud FIPS con el parámetro health_failure. Esta función debe ser llamada antes de jent_entropy_init(), ya que después de esta llamada se deniega el cambio de la llamada de retorno.

jent_entropy_init() inicializa el Generador de Números Aleatorios por Fluctuación de CPU. La función realiza pruebas estadísticas para verificar que el sistema subyacente ofrece las propiedades necesarias para medir y recopilar entropía. Si la inicialización es exitosa, lo que implica que las pruebas estadísticas indican que el sistema subyacente es apropiado, la llamada retorna con 0. Un código de retorno distinto de 0 indica un fallo en el que la aplicación que llama **DEBE NO** utilizar el Generador de Números Aleatorios por Fluctuación de CPU.

jent_entropy_init_ex() se comporta de manera idéntica a jent_entropy_init() excepto que permite al llamador proporcionar los parámetros osr y flags que deben ser idénticos a la invocación posterior de jent_entropy_collector_alloc(). Al especificar una tasa de sobremuestreo osr diferente de la predeterminada, la prueba de inicio honra este valor y ajusta los umbrales de corte de la autocomprobación a los mismos valores que se utilizan en tiempo de ejecución.

jent_entropy_collector_alloc() asigna una instancia de recolector de entropía de Fluctuación de CPU y devuelve el manejador al llamador. Si la asignación falla, incluidas las restricciones de memoria, la llamada devuelve NULL. La función requiere dos argumentos, la tasa de sobremuestreo osr y un conjunto de banderas con flags. El valor osr define la cantidad de sobremuestreo realizado por el recolector de entropía. Normalmente, un llamador desea proporcionar el valor 0 aquí para aplicar el sobremuestreo predeterminado. La llamada asegura que cualquier valor menor que JENT_MIN_OSR se convierte automáticamente en JENT_MIN_OSR.

El valor flags es cero o una o más de las siguientes banderas.

JENT_DISABLE_MEMORY_ACCESS
Si el sistema tiene restricciones de memoria, esta bandera deshabilita la asignación de esa memoria y, por lo tanto, los accesos a la memoria. Pero eso también implica que el proceso de recolección de entropía solo se basa en la complejidad de la CPU. Tenga en cuenta que si alguien conoce todos los detalles de esa complejidad de la CPU, esa persona podría reducir la entropía entregada por la complejidad de la CPU. Si esa persona puede empujar la entropía generada por debajo de un umbral, el generador de números aleatorios por fluctuación de CPU comienza a sobreestimar la entropía de la fuente de ruido. Por lo tanto, deshabilitar los accesos a la memoria y depender solo de la complejidad de la CPU solo debe hacerse si realmente sabe lo que está haciendo.
JENT_FORCE_INTERNAL_TIMER
Esta bandera se puede usar para forzar al RNG de Fluctuación a usar el temporizador interno de alta resolución en lugar de usar la marca de tiempo del hardware. Comúnmente, la autocomprobación de inicio realizada con jent_entropy_init() utiliza el temporizador del hardware con precedencia si se identifica que es apropiado para la recolección de entropía. Si el temporizador interno no está compilado, solicitar esta bandera devuelve un error. Aunque se genera un hilo separado para proporcionar una marca de tiempo de alta resolución, toda esta operación es completamente segura para hilos, ya que todos los datos relevantes se mantienen como parte de la estructura de datos entropy_collector.
JENT_DISABLE_INTERNAL_TIMER
Esta bandera se puede usar para asegurar que no se use el temporizador interno. Si esta bandera se usa junto con JENT_FORCE_INTERNAL_TIMER, se trata como un error y la asignación devuelve NULL. Además, en caso de que jent_entropy_init() detecte que se debe usar el temporizador interno, pero la bandera de deshabilitación está activada, la asignación devuelve NULL.
JENT_FORCE_FIPS
Forzar el cumplimiento total de FIPS 140 y SP800-90B independientemente de la configuración FIPS del sistema operativo subyacente.
JENT_MAX_MEMSIZE_*
Defina la cantidad máxima de memoria que el RNG de Fluctuación utilizará para su operación, admitiendo la recolección de ruido crudo. Sin usar una de estas banderas, el RNG de Fluctuación utiliza un límite incorporado. Cuanto mayor sea la cantidad de memoria, más entropía se recolectará. Sin embargo, el valor predeterminado es seguro en la mayoría de las CPUs. Si tiene presión de memoria pero la tasa de entropía de su CPU es suficiente, se puede usar una menor cantidad de memoria. Por el contrario, si tiene suficiente memoria pero entropía insuficiente, se pueden especificar mayores cantidades de memoria. En cualquier caso, el RNG de Fluctuación utiliza como máximo tanta memoria como la suma de las cachés de datos de la CPU.

jent_entropy_collector_free() borra y libera la instancia del recolector de entropía de Fluctuación de CPU dada.

El llamador puede proporcionar cualquier valor mayor que 0. El llamador debe asegurarse de que data sea al menos tan grande como indica len. NOMBRE

jitterentropy - Generador de números aleatorios basado en jitter de reloj de CPU

SINOPSIS

#include <stdlib.h>

uint32_t
jent_entropy_collector_alloc(unsigned int flags);

uint32_t
jent_entropy_collector_init_ex(unsigned int flags, unsigned int osr,
    unsigned int lsr);

int
jent_entropy_collector_unalloc(void);

int
jent_read_entropy(void *buf, size_t len);

int
jent_read_entropy_safe(void *buf, size_t len);

uint32_t
jent_get_version(void);

#define JENT_MAJVERSION 3
#define JENT_MINVERSION 6
#define JENT_PATCHLEVEL 3
#define JENT_VERSION (JENT_MAJVERSION * 100000 + JENT_MINVERSION * 100 + JENT_PATCHLEVEL)

DESCRIPCIÓN

El generador de números aleatorios Jitter RNG genera números aleatorios basándose en el jitter de reloj de la CPU. Proporciona una fuente de entropía de alta calidad que se puede utilizar para la generación de números aleatorios criptográficamente seguros. El generador de números aleatorios Jitter RNG se puede inicializar y utilizar de varias maneras.

La función jent_entropy_collector_alloc() inicializa una instancia del colector de entropía con los indicadores especificados. El valor de retorno es un valor de estado que indica si la inicialización se realizó correctamente o si se produjo un error. Si la inicialización falla, se recomienda aumentar el valor de osr en al menos uno al asignar una nueva instancia del colector de entropía.

La función jent_entropy_collector_init_ex() inicializa una instancia del colector de entropía con los indicadores, la tasa de muestreo de salida (OSR) y la tasa de muestreo de pérdida (LSR) especificados.

La función jent_entropy_collector_unalloc() libera la instancia del colector de entropía asignada actualmente.

La función jent_read_entropy() lee datos aleatorios de la fuente de entropía y los almacena en el búfer proporcionado. La longitud de los datos a leer se especifica mediante el argumento len.

Los códigos de retorno de las funciones de inicialización y lectura son los siguientes:

0
Éxito.
-1
Error genérico.
-2
Error al asignar memoria.
-3
Ya hay una instancia del colector de entropía asignada.
-4
No hay ninguna instancia del colector de entropía asignada.
-5
El parámetro flags no es válido.
-6
La prueba de recuento repetitivo (RCT) falló permanentemente.
-7
La prueba de proporción adaptativa (APT) falló permanentemente.
-8
La prueba de predicción de LAG falló permanentemente.

Cuando falla cualquiera de las pruebas de salud en línea, el generador de números aleatorios Jitter no tendrá ningún dato proporcionado en data. La instancia del colector de entropía permanecerá en estado de error. Para recuperarse, la instancia del colector de entropía DEBE ser desasignada y se debe asignar una nueva instancia. Se recomienda aumentar el valor de osr al menos en uno al asignar una nueva instancia del generador de números aleatorios Jitter con jent_entropy_collector_alloc(), lo que implica que las pruebas de salud son menos sensibles debido al hecho de que la tasa de entropía supuesta de la fuente de ruido es menor.

jent_read_entropy_safe() es una función de servicio y, por lo tanto, opera de manera idéntica a jent_read_entropy() con la excepción de que reasigna automáticamente el colector de entropía si se observa un error en una prueba de salud. Antes de la reasignación, se realiza una nueva prueba de salud al encendido. La asignación del nuevo colector de entropía aumenta automáticamente el OSR en uno. Esto se hace basándose en la idea de que un error en la prueba de salud indica que la tasa de entropía supuesta es demasiado alta.

Tenga en cuenta que la función devuelve un error de prueba de salud si el OSR se está volviendo demasiado grande. Si esta función devuelve un error, el generador de números aleatorios Jitter no es seguro de usar en el sistema actual.

La función jent_read_entropy_safe() tiene los mismos códigos de error que jent_read_entropy().

JENT_MAJVERSION indica cambios incompatibles de API / ABI, cambios funcionales que requieren que el consumidor sea actualizado.

JENT_MINVERSION indica cambios compatibles con la API, la ABI puede cambiar, solo mejoras funcionales, el consumidor puede permanecer sin cambios si no se consideran las mejoras.

JENT_PATCHLEVEL indica cambios compatibles con API / ABI, sin cambios funcionales, sin mejoras, solo correcciones de errores. Además, la recolección de entropía no se modifica de ninguna manera que necesite una reevaluación.

JENT_VERSION el número de versión de la biblioteca como un valor entero que aumenta monótonamente. Los números de versión son múltiplos de 100. Por ejemplo, la versión 1.2.3 se convierte en 1020300: los dos últimos dígitos están reservados para uso futuro.

jent_version() devuelve JENT_VERSION.

Consideraciones FIPS 140-3

Para que el generador de números aleatorios Jitter se ejecute en cumplimiento con FIPS 140-3 y, por extensión, también con SP800-90B y SP800-90C, se deben aplicar las siguientes consideraciones:

Habilitar modo FIPS
El modo FIPS se habilita utilizando el indicador JENT_FORCE_FIPS durante la inicialización de la biblioteca del generador de números aleatorios Jitter. En Linux, el modo FIPS se habilita de forma transparente si todo el sistema operativo se inició en modo FIPS, generalmente usando el parámetro de línea de comandos del kernel de Linux "fips=1".
Realizar análisis heurístico de entropía
El conjunto de herramientas de prueba proporcionado como parte de la distribución de la fuente de la biblioteca del generador de números aleatorios Jitter contiene la ayuda para obtener datos de ruido en bruto en tiempo de ejecución y en tiempo de inicialización para calcular la tasa de entropía SP800-90B. Esta tasa debe estar por encima de 0.333, el mínimo heurístico implícito por la biblioteca del generador de números aleatorios Jitter.
Resolver entropía insuficiente
Si se encuentra entropía insuficiente durante el análisis SP800-90B mencionado anteriormente, el conjunto de herramientas de prueba proporciona una ayuda para analizar la configuración óptima; consulte el conjunto de herramientas de prueba para obtener entropía en bruto para obtener más detalles. Se espera que los valores de configuración resultantes se usen con el parámetro flags de las llamadas jent_entropy_collector_alloc() y jent_entropy_init_ex(). Se recomienda utilizar la llamada a la API jent_read_entropy_safe() para generar números aleatorios.

NOTAS

Además de usar el flujo de bits aleatorios generado directamente para operaciones criptográficas, la salida de jent_read_entropy() se puede utilizar para sembrar un generador de números aleatorios determinista.
