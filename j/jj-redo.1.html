NOMBRE

jj-redo - Rehacer la operación deshecha más recientemente

SINOPSIS

jj redo [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help]

DESCRIPCIÓN

Rehace la operación deshecha más recientemente

Este es el contraparte natural de `jj undo`. Las invocaciones repetidas de `jj undo` y `jj redo` actúan de manera similar a los comandos Deshacer/Rehacer en un editor de texto.

Usa `jj op log` para visualizar el registro de operaciones pasadas, incluyendo una descripción detallada de cualquier operación pasada de deshacer/rehacer. Ver también `jj op restore` para restaurar explícitamente una operación anterior por su id (disponible en el registro de operaciones).

OPCIONES

-h, --help
Imprime la ayuda (ver un resumen con '-h')

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No hacer una instantánea de la copia de trabajo, y no actualizarla

Por defecto, Jujutsu hace una instantánea de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si quieres evitar hacer una instantánea de la copia de trabajo y en su lugar ver un commit de copia de trabajo posiblemente obsoleto, puedes usar `--ignore-working-copy`. Esto puede ser útil p. ej. en un prompt de comando, especialmente si tienes otro proceso que hace commit de la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu previene la reescritura de commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y te permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta a la verificación. No afecta al revset `immutable_heads()` ni a la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repo

Operación en la que cargar el repo. Por defecto, Jujutsu carga el repo en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puedes usar `--at-op=<ID de operación>` para ver cómo se veía el repo en una operación anterior. Por ejemplo `jj --at-op=<ID de operación> st` te mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de terminar. `--at-op=@` es prácticamente lo mismo que el valor por defecto excepto que las operaciones divergentes nunca se fusionarán.

Usa `jj op log` para encontrar el ID de operación que deseas. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repo en una operación anterior, la copia de trabajo será ignorada, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutantes al cargar el repo en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Raramente hay una razón para hacer eso, pero es posible.

--debug
Habilitar el registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[posibles valores: always, never, debug, auto]

--quiet
Silenciar la salida no principal del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no te dirá si la copia de trabajo fue fotografiada o si los descendientes fueron rebasados.

Las advertencias y errores seguirán imprimiéndose.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves puntuales de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado por ningún constructo TOML (como la notación de matriz), las comillas pueden omitirse.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
