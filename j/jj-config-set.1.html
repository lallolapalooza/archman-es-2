NOMBRE

jj-config-set - Actualiza un archivo de configuración para establecer la opción dada a un valor dado

SINOPSIS

jj config set [--user] [--repo] [--workspace] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <NOMBRE> <VALOR>

DESCRIPCIÓN

Actualiza un archivo de configuración para establecer la opción dada a un valor dado

OPCIONES

--user
Dirigirse a la configuración a nivel de usuario
--repo
Dirigirse a la configuración a nivel de repositorio
--workspace
Dirigirse a la configuración a nivel de espacio de trabajo
-h, --help
Imprimir ayuda (ver resumen con '-h')
<NOMBRE>
<VALOR>
Nuevo valor a establecer

El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado por ningún constructo TOML (como apóstrofes o notación de matriz), se pueden omitir las comillas. Tenga en cuenta que el valor también puede necesitar comillas del shell. Las cadenas multilínea de TOML pueden ser útiles si el valor contiene apóstrofes. Por ejemplo, para establecer `foo.bar` a la cadena "{don't}" usa `jj config set --user foo.bar "'''{don't}'''"`. Esto es válido tanto en Bash como en Fish.

Alternativamente, por ejemplo, para evitar lidiar con las comillas del shell, usa `jj config edit` para editar el archivo TOML directamente.

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No guardar una instantánea de la copia de trabajo y no actualizarla

Por defecto, Jujutsu guarda una instantánea de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si desea evitar guardar una instantánea de la copia de trabajo y ver en su lugar un commit de copia de trabajo posiblemente desactualizado, puede usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tiene otro proceso que confirma la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu evita reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y le permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de operaciones divergentes si las hay.

Puede usar `--at-op=<ID de operación>` para ver cómo se veía el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` le mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Use `jj op log` para encontrar el ID de operación que desea. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignorará la copia de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutantes al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes a partir de la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilitar registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[posibles valores: always, never, debug, auto]

--quiet
Silenciar la salida no principal del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no le dirá si la copia de trabajo se guardó en una instantánea o si los descendientes se reorganizaron. Los avisos y errores aún se imprimirán.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves TOML con puntos. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado por ningún constructo TOML (como notación de matriz), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
set
