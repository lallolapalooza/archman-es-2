NOMBRE

jj-undo - Deshacer la última operación

SINOPSIS

jj undo [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] [OPERACIÓN]

DESCRIPCIÓN

Deshace la última operación

Si se utiliza una vez después de una operación normal (no `undo`), esto deshará esa última operación restaurando su padre. Si `jj undo` se utiliza repetidamente, restaurará operaciones cada vez más antiguas, yendo más atrás en el tiempo.

También existe un comando complementario `jj redo` que, en cambio, se movería en la dirección del futuro después de uno o más `jj undo`s.

Utilice `jj op log` para visualizar el registro de operaciones anteriores, incluyendo una descripción detallada de cualquier operación anterior de deshacer/rehacer. Consulte también `jj op restore` para restaurar explícitamente una operación anterior por su ID (disponible en el registro de operaciones).

OPCIONES

-h, --help
Imprime la ayuda (ver un resumen con '-h')
[OPERACIÓN] [predeterminado: @]
(obsoleto, usa `jj op revert <operación>`)

La operación a deshacer

Utiliza `jj op log` para encontrar una operación que deshacer.

OPCIONES GENERALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No tomar una instantánea de la copia de trabajo, ni actualizarla

Por defecto, Jujutsu toma una instantánea de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si deseas evitar tomar una instantánea de la copia de trabajo y ver en su lugar un commit de copia de trabajo posiblemente desactualizado, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en un símbolo del sistema, especialmente si otro proceso confirma la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir la reescritura de commits inmutables

Por defecto, Jujutsu evita la reescritura de commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y te permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puedes usar `--at-op=<ID de operación>` para ver cómo se veía el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` te mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Utiliza `jj op log` para encontrar el ID de operación que deseas. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignorará la copia de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes a partir de la operación anterior. Rara vez hay una razón para hacer eso, pero es posible.

--debug
Habilitar registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[posibles valores: siempre, nunca, depurar, automático]

--quiet
Silenciar la salida no principal del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no te dirá si se tomó una instantánea de la copia de trabajo o si los descendientes fueron rebasados.

Las advertencias y los errores seguirán imprimiéndose.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves puntuales de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado por ninguna construcción de TOML (como la notación de array), las comillas se pueden omitir.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
