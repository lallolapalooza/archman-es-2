jj-commit(1) Manual de comandos generales jj-commit(1)

NOMBRE

jj-commit - Actualiza la descripción y crea un nuevo cambio encima [alias por defecto: ci]

SINOPSIS

jj commit [-i|--interactive] [--tool] [-m|--message] [--editor] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] [ARCHIVOS]

DESCRIPCIÓN

Actualiza la descripción y crea un nuevo cambio encima [alias por defecto: ci]

Cuando se llama sin argumentos de ruta o `--interactive`, `jj commit` es equivalente a `jj describe` seguido de `jj new`.

En caso contrario, este comando es muy similar a `jj split`. Las diferencias incluyen:

* `jj commit` no es interactivo por defecto (selecciona todos los cambios).

* `jj commit` no tiene una opción `-r`. Siempre actúa sobre el commit de la copia de trabajo (`@`).

* `jj split` (sin `-d/-A/-B`) moverá las marcas de avance desde el cambio antiguo al cambio hijo. `jj commit` no mueve las marcas de avance.

* `jj split` te permite mover los cambios seleccionados a un destino diferente con `-d/-A/-B`.

OPCIONES

-i, --interactive
Elige interactivamente qué cambios incluir en el primer commit
--tool <NOMBRE>
Especifica el editor de diferencias a usar (implica --interactive)
-m, --message <MENSAJE>
La descripción del cambio a usar (no abre editor)
--editor
Abre un editor para editar la descripción del cambio

Fuerza la apertura de un editor cuando se usa `--message` para permitir editar el mensaje posteriormente.

-h, --help
Imprime la ayuda (ver un resumen con '-h')
[ARCHIVOS]
Coloca estas rutas en el primer commit

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio `.jj/` más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No snapshotear la copia de trabajo, y no actualizarla

Por defecto, Jujutsu hace snapshot de la copia de trabajo al inicio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si quieres evitar hacer snapshot de la copia de trabajo y en su lugar ver un commit de copia de trabajo posiblemente obsoleto, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tienes otro proceso que hace commit de la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu previene la reescritura de commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y te permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la verificación. No afecta el revset `immutable_heads()` ni la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puedes usar `--at-op=<ID de operación>` para ver cómo se veía el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` te mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor por defecto, excepto que las operaciones divergentes nunca se fusionarán.

Usa `jj op log` para encontrar el ID de operación que deseas. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignorará la copia de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilitar el registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[posibles valores: always, never, debug, auto]

--quiet
Silenciar la salida no principal del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no te dirá si se hizo snapshot de la copia de trabajo o si los descendientes fueron rebazados.

Las advertencias y errores seguirán imprimiéndose.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves puntuales de TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado por ninguna construcción de TOML (como notación de array), las comillas se pueden omitir.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
