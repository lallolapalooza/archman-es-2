JDB(1) Comandos JDK JDB(1)

NOMBRE

jdb - encontrar y corregir errores en programas de la plataforma Java

SINOPSIS

jdb [opciones] [nombre_clase] [argumentos]

opciones
Esto representa las opciones de la línea de comandos de jdb. Ver Opciones para el comando jdb.
nombre_clase
Esto representa el nombre de la clase principal a depurar.
argumentos
Esto representa los argumentos que se pasan al método main() de la clase.

DESCRIPCIÓN

El Depurador Java (JDB) es un depurador simple de línea de comandos para clases Java. El comando jdb y sus opciones llaman a JDB. El comando jdb demuestra la Arquitectura de Depuración de la Plataforma Java y proporciona inspección y depuración de una JVM local o remota.

INICIAR UNA SESIÓN DE JDB

Hay muchas maneras de iniciar una sesión de JDB. La forma más utilizada es hacer que JDB inicie una nueva JVM con la clase principal de la aplicación a depurar. Haz esto sustituyendo el comando jdb por el comando java en la línea de comandos. Por ejemplo, si la clase principal de tu aplicación es MyClass, entonces usa el siguiente comando para depurarla bajo JDB:

jdb MyClass

Cuando se inicia de esta manera, el comando jdb llama a una segunda JVM con los parámetros especificados, carga la clase especificada y detiene la JVM antes de ejecutar la primera instrucción de esa clase.

Otra forma de usar el comando jdb es adjuntándolo a una JVM que ya se está ejecutando. La sintaxis para iniciar una JVM a la que se adjunta el comando jdb cuando la JVM se está ejecutando es la siguiente. Esto carga bibliotecas de depuración en el proceso y especifica el tipo de conexión que se realizará.

java -agentlib:jdwp=transport=dt_socket,server=y,suspend=n MyClass

Luego puedes adjuntar el comando jdb a la JVM con el siguiente comando:

jdb -attach 8000

8000 es la dirección de la JVM en ejecución.

El argumento MyClass no se especifica en la línea de comandos de jdb en este caso porque el comando jdb se conecta a una JVM existente en lugar de iniciar una nueva JVM.

Hay muchas otras formas de conectar el depurador a una JVM, y todas ellas son compatibles con el comando jdb. La Arquitectura de Depuración de la Plataforma Java tiene documentación adicional sobre estas opciones de conexión.

PUNTOS DE INTERRUPCIÓN

Los puntos de interrupción se pueden establecer en JDB en números de línea o en la primera instrucción de un método, por ejemplo:

•
El comando stop at MyClass:22 establece un punto de interrupción en la primera instrucción para la línea 22 del archivo fuente que contiene MyClass.
•
El comando stop in java.lang.String.length establece un punto de interrupción al principio del método java.lang.String.length.
•
El comando stop in MyClass.<clinit> usa <clinit> para identificar el código de inicialización estática para MyClass.

Cuando un método está sobrecargado, también debes especificar sus tipos de argumento para que se pueda seleccionar el método correcto para un punto de interrupción. Por ejemplo, MyClass.myMethod(int,java.lang.String) o MyClass.myMethod().

El comando clear elimina los puntos de interrupción usando la siguiente sintaxis: clear MyClass:45. Usar el comando clear o stop sin argumentos muestra una lista de todos los puntos de interrupción establecidos actualmente. El comando cont continúa la ejecución.

PASOS

El comando step avanza la ejecución a la siguiente línea, ya sea en el marco de pila actual o en un método llamado. El comando next avanza la ejecución a la siguiente línea en el marco de pila actual.

EXCEPCIONES

Cuando ocurre una excepción para la cual no hay una sentencia catch en ninguna parte de la pila de llamadas del hilo que la lanza, la JVM normalmente imprime un rastreo de la excepción y sale. Sin embargo, cuando se ejecuta bajo JDB, el control regresa a JDB en el punto donde ocurre la excepción. Luego puedes usar el comando jdb para diagnosticar la causa de la excepción.

Usa el comando catch para que la aplicación depurada se detenga en otras excepciones lanzadas, por ejemplo: catch java.io.FileNotFoundException o catch mypackage.BigTroubleException. Cualquier excepción que sea una instancia de la clase especificada o una subclase detiene la aplicación en el punto donde se lanza la excepción.

El comando ignore niega el efecto de un comando catch anterior. El comando ignore no hace que la JVM depurada ignore excepciones específicas, sino solo que ignore al depurador.

OPCIONES PARA EL COMANDO JDB

Cuando usas el comando jdb en lugar del comando java en la línea de comandos, el comando jdb acepta muchas de las mismas opciones que el comando java.

Las siguientes opciones son aceptadas por el comando jdb:

-help
Muestra un mensaje de ayuda.
-sourcepath dir1:dir2:...
Utiliza la ruta especificada para buscar archivos fuente en la ruta especificada. Si no se especifica esta opción, entonces se utiliza la ruta predeterminada de punto (.).
-attach dirección
Adjunta el depurador a una JVM en ejecución con el mecanismo de conexión predeterminado.
-listen dirección
Espera a que una JVM en ejecución se conecte a la dirección especificada con un conector estándar.
-listenany
Espera a que una JVM en ejecución se conecte en cualquier dirección disponible utilizando un conector estándar.
-launch
Inicia la aplicación depurada inmediatamente al iniciar el comando jdb. La opción -launch elimina la necesidad del comando run. La aplicación depurada se inicia y luego se detiene justo antes de que se cargue la clase de aplicación inicial. En ese momento, puedes establecer los puntos de interrupción necesarios y usar el comando cont para continuar la ejecución.
-listconnectors
Enumera los conectores disponibles en esta JVM.
-connect nombre_conector:nombre1=valor1....
Se conecta a la JVM de destino con el conector con nombre y los valores de argumento listados.
-dbgtrace [indicadores]
Imprime información para depurar el comando jdb.
-tclient
Ejecuta la aplicación en el cliente VM de Java HotSpot.
-trackallthreads
Rastrea todos los hilos a medida que se crean, incluidos los hilos virtuales. Ver Trabajar con hilos virtuales abajo.
-tserver
Ejecuta la aplicación en el servidor VM de Java HotSpot.
-Jopción
Pasa opción a la JVM de JDB, donde opción es una de las opciones descritas en la página de referencia para el lanzador de aplicaciones Java. Por ejemplo, -J-Xms48m establece la memoria de inicio en 48 MB. Ver Descripción general de las opciones de Java en java.

Las siguientes opciones se reenvían al proceso depurado:

-Ropción
Pasa opción a la JVM depurada, donde opción es una de las opciones descritas en la página de referencia para el lanzador de aplicaciones Java. Por ejemplo, -R-Xms48m establece la memoria de inicio en 48 MB. Ver Descripción general de las opciones de Java en java.
-v o -verbose[:clase|gc|jni]
Activa el modo detallado.
-Dnombre=valor
Establece una propiedad del sistema.
-classpath dir
Enumera directorios separados por dos puntos en los que buscar clases.
-X opción
Una opción no estándar de la JVM de destino.

Otras opciones son compatibles para proporcionar mecanismos alternativos para conectar el depurador a la JVM que se va a depurar.

TRABAJAR CON HILOS VIRTUALES

A menudo, los hilos virtuales se crean en tal cantidad y frecuencia que pueden abrumar a un depurador. Por esta razón, por defecto, JDB no rastrea los hilos virtuales a medida que se crean. Solo rastreará los hilos virtuales sobre los que ha llegado un evento, como un evento de punto de interrupción. La opción -trackallthreads se puede usar para que JDB rastree todos los hilos virtuales a medida que se crean.
