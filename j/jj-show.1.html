NOMBRE

jj-show - Muestra la descripción de los commits y los cambios en una revisión

SINOPSIS

jj show [-T|--template] [-s|--summary] [--stat] [--types] [--name-only] [--git] [--color-words] [--tool] [--context] [--no-patch] [-w|--ignore-all-space] [-b|--ignore-space-change] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] [REVSET]

DESCRIPCIÓN

Muestra la descripción de los commits y los cambios en una revisión

OPCIONES

-T, --template <PLANTILLA>
Renderiza una revisión usando la plantilla dada

Puedes especificar expresiones de plantilla arbitrarias usando las [palabras clave integradas]. Consulta [`jj help -k templates`] para más información.

[palabras clave integradas]: https://docs.jj-vcs.dev/latest/templates/#commit-keywords

[`jj help -k templates`]: https://docs.jj-vcs.dev/latest/templates/

-h, --help
Imprime la ayuda (ver un resumen con '-h')
[REVSET] [predeterminado: @]
Muestra los cambios en esta revisión, en comparación con su(s) padre(s)

OPCIONES DE FORMATO DE DIFERENCIA

-s, --summary
Para cada ruta, muestra solo si fue modificada, añadida o eliminada
--stat
Muestra un histograma de los cambios
--types
Para cada ruta, muestra solo su tipo antes y después

La diferencia se muestra como dos letras. La primera letra indica el tipo antes y la segunda letra indica el tipo después. '-' indica que la ruta no estaba presente, 'F' representa un archivo regular, `L' representa un enlace simbólico, 'C' representa un conflicto y 'G' representa un submódulo de Git.

--name-only
Para cada ruta, muestra solo su ruta

Típicamente útil para comandos de shell como: `jj diff -r @- --name-only | xargs perl -pi -e's/OLD/NEW/g`

--git
Muestra una diferencia en formato Git
--color-words
Muestra una diferencia a nivel de palabra con los cambios indicados solo por color
--tool <HERRAMIENTA>
Genera la diferencia mediante un comando externo

También se puede especificar un formato integrado como `:<nombre>`. Por ejemplo, `--tool=:git` es equivalente a `--git`.

--context <CONTEXTO>
Número de líneas de contexto a mostrar
--no-patch
No mostrar el parche
-w, --ignore-all-space
Ignora los espacios en blanco al comparar líneas
-b, --ignore-space-change
Ignora los cambios en la cantidad de espacios en blanco al comparar líneas

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No tomar una instantánea del directorio de trabajo, ni actualizarlo

Por defecto, Jujutsu toma una instantánea del directorio de trabajo al inicio de cada comando. El directorio de trabajo también se actualiza al final del comando, si el comando modificó el commit del directorio de trabajo (`@`). Si deseas evitar tomar una instantánea del directorio de trabajo y ver en su lugar un commit del directorio de trabajo potencialmente obsoleto, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en un prompt de comandos, especialmente si tienes otro proceso que confirma el directorio de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permite reescribir commits inmutables

Por defecto, Jujutsu evita reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y te permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta a la verificación. No afecta al conjunto de revisiones `immutable_heads()` ni a la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si las hay.

Puedes usar `--at-op=<ID de operación>` para ver cómo era el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` te mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Usa `jj op log` para encontrar el ID de operación que deseas. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignora el directorio de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutantes al cargar el repositorio en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilita el registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[valores posibles: always, never, debug, auto]

--quiet
Silencia la salida no principal del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no te dirá si el directorio de trabajo fue capturado en una instantánea o si los descendientes fueron rebasados.

Las advertencias y los errores seguirán imprimiéndose.

--no-pager
Deshabilita el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves separadas por puntos en TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado en ninguna construcción de TOML (como la notación de array), las comillas se pueden omitir.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
