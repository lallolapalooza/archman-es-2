JPACKAGE(1) Comandos del JDK JPACKAGE(1)

NOMBRE

jpackage - herramienta para empaquetar aplicaciones Java autónomas.

SINOPSIS

jpackage [opciones]

opciones
Opciones de la línea de comandos separadas por espacios. Véase Opciones de jpackage.

DESCRIPCIÓN

La herramienta jpackage tomará como entrada una aplicación Java y una imagen de tiempo de ejecución de Java, y producirá una imagen de aplicación Java que incluye todas las dependencias necesarias. Será capaz de producir un paquete nativo en un formato específico de la plataforma, como un exe en Windows o un dmg en macOS. Cada formato debe compilarse en la plataforma en la que se ejecuta, no hay soporte multiplataforma. La herramienta tendrá opciones que permiten personalizar las aplicaciones empaquetadas de varias maneras.

OPCIONES DE JPACKAGE

Opciones genéricas:

@nombre_de_archivo
Lee las opciones de un archivo.

Esta opción puede usarse varias veces.

--type o -t <cadena de tipo>
El tipo de paquete a crear

Los valores válidos son: {"app-image", "exe", "msi", "rpm", "deb", "pkg", "dmg"}

Si no se especifica esta opción, se creará un tipo predeterminado dependiente de la plataforma.

--app-version <versión>
Versión de la aplicación y/o del paquete
--copyright <cadena de copyright>
Copyright de la aplicación
--description <cadena de descripción>
Descripción de la aplicación
--help o -h
Imprime el texto de uso con una lista y descripción de cada opción válida para la plataforma actual en el flujo de salida, y sale.
--icon <ruta del archivo de icono>
Ruta del icono del paquete de la aplicación (ruta absoluta o relativa a el directorio actual)
--name o -n <nombre>
Nombre de la aplicación y/o del paquete
--dest o -d <ruta de salida>
Ruta donde se coloca el archivo de salida generado

Por defecto es el directorio de trabajo actual. (ruta absoluta o relativa al directorio actual).

--temp <ruta del directorio>
Ruta de un directorio nuevo o vacío usado para crear archivos temporales (ruta absoluta o relativa al directorio actual)

Si se especifica, el directorio temporal no se eliminará al finalizar la tarea y debe eliminarse manualmente.

Si no se especifica, se creará un directorio temporal y se eliminará al finalizar la tarea.

--vendor <cadena de proveedor>
Proveedor de la aplicación
--verbose
Habilita la salida detallada.
--version
Imprime la versión del producto en el flujo de salida y sale.

Opciones para crear la imagen de tiempo de ejecución:

--add-modules <nombre de módulo> [,<nombre de módulo>...]
Una lista de módulos a añadir separada por comas (",")

Esta lista de módulos, junto con el módulo principal (si se especifica), se pasará a jlink como el argumento --add-module. Si no se especifica, se usa ya sea solo el módulo principal (si se especifica --module), o el conjunto predeterminado de módulos (si se especifica --main-jar).

Esta opción puede usarse varias veces.

--module-path o -p <ruta de módulos>...
Una lista de rutas separadas por File.pathSeparator

Cada ruta es o bien un directorio de módulos o la ruta a un jar modular, y es absoluta o relativa al directorio actual.

Esta opción puede usarse varias veces.

--jlink-options <opciones de jlink>
Una lista de opciones separadas por espacios para pasar a jlink

Si no se especifica, el valor predeterminado es "--strip-native-commands --strip-debug --no-man-pages --no-header-files"

Esta opción puede usarse varias veces.

--runtime-image <ruta del directorio>
Ruta de la imagen de tiempo de ejecución predefinida que se copiará en la imagen de la aplicación (ruta absoluta o relativa al directorio actual)

Si --runtime-image no se especifica, jpackage ejecutará jlink para crear la imagen de tiempo de ejecución usando las opciones especificadas por --jlink-options.

Opciones para crear la imagen de la aplicación:

--input o -i <ruta de entrada>
Ruta del directorio de entrada que contiene los archivos a empaquetar (ruta absoluta o relativa al directorio actual)

Todos los archivos del directorio de entrada se empaquetarán en la imagen de la aplicación.

Opciones para crear el/los lanzador(es) de la aplicación:

--add-launcher <nombre de lanzador>=<ruta del archivo>
Nombre del lanzador, y una ruta a un archivo Properties que contiene una lista de pares clave, valor (ruta absoluta o relativa al directorio actual)

Las claves "module", "main-jar", "main-class", "arguments", "java-options", "app-version", "icon", "linux-app-category", "linux-app-release", y "win-console" pueden usarse.

Estas opciones se añaden o se usan para sobrescribir las opciones originales de la línea de comandos para construir un lanzador alternativo adicional. El lanzador principal de la aplicación se construirá a partir de las opciones de la línea de comandos. Se pueden construir lanzadores alternativos adicionales usando esta opción, y esta opción puede usarse varias veces para construir múltiples lanzadores adicionales.

--arguments <argumentos de la clase principal>
Argumentos de la línea de comandos a pasar a la clase principal si no se proporcionan argumentos de la línea de comandos

Opciones para crear el lanzador de la aplicación:

--class-path <path>
Ruta de clases adicional para el lanzador de la aplicación

Esta opción se puede usar varias veces.

--java-options <opciones de java>
Opciones a pasar al tiempo de ejecución de Java

Esta opción se puede usar varias veces.

--main-class <nombre de clase>
Nombre cualificado de la clase principal de la aplicación a ejecutar

Esta opción solo se puede usar si se especifica --main-jar.

--main-jar <archivo jar principal>
El JAR principal de la aplicación; que contiene la clase principal (especificada como una ruta relativa a la ruta de entrada)

Se puede especificar la opción --module o --main-jar, pero no ambas.

--module o -m <nombre de módulo>/<clase principal>]
El módulo principal (y opcionalmente la clase principal) de la aplicación

Este módulo debe estar ubicado en la ruta del módulo.

Cuando se especifica esta opción, el módulo principal se vinculará en la imagen del tiempo de ejecución de Java. Se puede especificar la opción --module o --main-jar, pero no ambas.

Opción dependiente de la plataforma para crear el lanzador de la aplicación:

Opciones de la plataforma Windows (disponibles solo cuando se ejecuta en Windows):

--win-console
Crea un lanzador de consola para la aplicación, debe especificarse para aplicaciones que requieren interacciones de consola

Opciones de la plataforma macOS (disponibles solo cuando se ejecuta en macOS):

--mac-package-identifier <cadena de ID>
Un identificador que identifica de forma única la aplicación para macOS

Por defecto es el nombre de la clase principal.

Solo se pueden usar caracteres alfanuméricos (A-Z, a-z, 0-9), guion (-) y punto (.) .

--mac-package-name <cadena de nombre>
Nombre de la aplicación tal como aparece en la Barra de Menú

Este puede ser diferente del nombre de la aplicación.

Este nombre debe tener menos de 16 caracteres y ser adecuado para mostrar en la barra de menú y en la ventana de información de la aplicación. Por defecto es el nombre de la aplicación.

--mac-package-signing-prefix <cadena de prefijo>
Al firmar el paquete de la aplicación, este valor se antepone a todos los componentes que necesitan ser firmados y que no tienen un identificador de paquete existente.
--mac-sign
Solicita que el paquete sea firmado.
--mac-signing-keychain <nombre del llavero>
Nombre del llavero donde buscar la identidad de firma

Si no se especifica, se utilizan los llaveros estándar.

--mac-signing-key-user-name <nombre del equipo>
Parte del nombre del equipo o usuario en las identidades de firma de Apple
--mac-app-store
Indica que la salida de jpackage está destinada a la Mac App Store.
--mac-entitlements <ruta del archivo>
Ruta al archivo que contiene los permisos a utilizar al firmar ejecutables y bibliotecas en el paquete
--mac-app-category <cadena de categoría>
Cadena utilizada para construir LSApplicationCategoryType en el archivo plist de la aplicación

El valor por defecto es "utilities".

Opciones para crear el paquete de la aplicación:

--about-url <url>
URL de la página de inicio de la aplicación
--app-image <ruta del directorio>
Ubicación de la imagen de aplicación predefinida que se utiliza para construir un paquete instalable

(ruta absoluta o relativa al directorio actual).

Consulte las opciones del modo create-app-image para crear la imagen de la aplicación.

--file-associations <ruta del archivo>
Ruta a un archivo de propiedades que contiene una lista de pares clave, valor (ruta absoluta o relativa al directorio actual)

Las claves "extension", "mime-type", "icon" y "description" se pueden utilizar para describir la asociación.

Esta opción se puede usar varias veces.

--install-dir <ruta del directorio>
Ruta absoluta del directorio de instalación de la aplicación (en macos o linux), o una subruta relativa del directorio de instalación como "Program Files" o "AppData" (en Windows)
--license-file <ruta del archivo>
Ruta al archivo de licencia (ruta absoluta o relativa al directorio actual)
--resource-dir <ruta del directorio>
Ruta para sobrescribir recursos de jpackage (ruta absoluta o relativa al directorio actual)

Los iconos, archivos de plantilla y otros recursos de jpackage pueden ser sobrescritos añadiendo recursos de reemplazo a este directorio.

--runtime-image <ruta del directorio>
Ruta de la imagen de tiempo de ejecución predefinida a instalar (ruta absoluta o relativa al directorio actual)

La opción es requerida al crear un instalador de tiempo de ejecución.

Opciones dependientes de la plataforma para crear el paquete de la aplicación:

Opciones de la plataforma Windows (disponibles solo cuando se ejecuta en Windows):

--win-dir-chooser
Añade un diálogo para permitir al usuario elegir un directorio en el que se instalará el producto.
--win-help-url <url>
URL donde el usuario puede obtener información adicional o soporte técnico
--win-menu
Solicita añadir un acceso directo en el Menú Inicio para esta aplicación
--win-menu-group <nombre del grupo de menú>
Grupo del Menú Inicio en el que se coloca esta aplicación
--win-per-user-install
Solicita realizar una instalación por usuario
--win-shortcut
Solicita crear un acceso directo en el escritorio para esta aplicación
--win-shortcut-prompt
Añade un diálogo para permitir al usuario elegir si el instalador creará accesos directos
--win-update-url <url>
URL de información de actualización de la aplicación disponible
--win-upgrade-uuid <cadena de ID>
UUID asociado con las actualizaciones para este paquete

Opciones de la plataforma Linux (disponibles solo cuando se ejecuta en Linux):

--linux-package-name <nombre del paquete>
Nombre para el paquete Linux

Por defecto es el nombre de la aplicación.

--linux-deb-maintainer <dirección de correo electrónico>
Mantenedor para el paquete .deb
--linux-menu-group <nombre del grupo de menú>
Grupo de menú en el que se coloca esta aplicación
--linux-package-deps
Paquetes o capacidades requeridos para la aplicación
--linux-rpm-license-type <tipo cadena>
Tipo de licencia ("License: <valor>" del archivo .spec de RPM)
--linux-app-release <cadena de release>
Valor de release del archivo .spec de <nombre> de RPM o valor de revisión de Debian del archivo de control DEB
--linux-app-category <cadena de categoría>
Valor de group del archivo .spec de <nombre> de RPM o valor de Section del archivo de control DEB
--linux-shortcut
Crea un acceso directo para la aplicación.

EJEMPLOS DE JPACKAGE


Genera un paquete de aplicación adecuado para el sistema anfitrión:


Para una aplicación modular:
    jpackage -n nombre -p rutaMódulo -m nombreMódulo/nombreClase
Para una aplicación no modular:
    jpackage -i directorioEntrada -n nombre \
        --main-class nombreClase --main-jar miJar.jar
Desde una imagen de aplicación precompilada:
    jpackage -n nombre --app-image directorioImagenApp


Genera una imagen de aplicación:


Para una aplicación modular:
    jpackage --type app-image -n nombre -p rutaMódulo \
        -m nombreMódulo/nombreClase
Para una aplicación no modular:
    jpackage --type app-image -i directorioEntrada -n nombre \
        --main-class nombreClase --main-jar miJar.jar
Para proporcionar tus propias opciones a jlink, ejecuta jlink por separado:
    jlink --output imagenRuntimeApp -p rutaMódulo \
        --add-modules nombreMódulo \
        --no-header-files [<opciones adicionales de jlink>...]
    jpackage --type app-image -n nombre \
        -m nombreMódulo/nombreClase --runtime-image imagenRuntimeApp


Genera un paquete de tiempo de ejecución de Java:


jpackage -n nombre --runtime-image <imagen-runtime>
