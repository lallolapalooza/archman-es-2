JSTATD(1) Comandos JDK JSTATD(1)

NOMBRE

jstatd - monitoriza la creación y terminación de VMs HotSpot de Java instrumentadas

SINOPSIS

Nota: Este comando es experimental y no está soportado.

jstatd [opciones]

opciones
Esto representa las opciones de línea de comandos de jstatd. Ver Opciones para el comando jstatd.

DESCRIPCIÓN

El comando jstatd es una aplicación de servidor RMI que monitoriza la creación y terminación de VMs HotSpot de Java instrumentadas y proporciona una interfaz para permitir que las herramientas de monitorización remota, jstat y jps, se conecten a las JVM que se ejecutan en el host local y recopilen información sobre el proceso de la JVM.

El servidor jstatd requiere un registro RMI en el host local. El servidor jstatd intenta conectarse al registro RMI en el puerto predeterminado, o en el puerto que especifique con la opción -p puerto. Si no se encuentra un registro RMI, se crea uno dentro de la aplicación jstatd que se vincula al puerto indicado por la opción -p puerto o al puerto de registro RMI predeterminado cuando se omite la opción -p puerto. Puede detener la creación de un registro RMI interno especificando la opción -nr.

OPCIONES PARA EL COMANDO JSTATD

-nr
Esta opción no intenta crear un registro RMI interno dentro del proceso jstatd cuando no se encuentra un registro RMI existente.
-p puerto
Esta opción establece el número de puerto donde se espera encontrar el registro RMI, o cuando no se encuentra, se crea si no se especifica la opción -nr.
-r puerto_rmi
Esta opción establece el número de puerto al que se vincula el conector RMI. Si no se especifica, se utiliza un puerto disponible aleatorio.
-n nombre_rmi
Esta opción establece el nombre al que se vincula el objeto RMI remoto en el registro RMI. El nombre predeterminado es JStatRemoteHost. Si se inician varios servidores jstatd en el mismo host, el nombre del objeto RMI exportado para cada servidor puede hacerse único especificando esta opción. Sin embargo, hacerlo requiere que el nombre de servidor único se incluya en las cadenas hostid y vmid del cliente de monitorización.
-Jopción
Esta opción pasa una opción de Java a la JVM, donde la opción es una de las descritas en la página de referencia del lanzador de aplicaciones de Java. Por ejemplo, -J-Xms48m establece la memoria de inicio en 48 MB. Ver java.

SEGURIDAD

El servidor jstatd solo puede monitorizar JVM para las que tiene los permisos de acceso nativo adecuados. Por lo tanto, el proceso jstatd debe ejecutarse con las mismas credenciales de usuario que las JVM de destino. Algunas credenciales de usuario, como el usuario root en los sistemas operativos Linux y macOS, tienen permiso para acceder a la instrumentación exportada por cualquier JVM del sistema. Un proceso jstatd que se ejecuta con dichas credenciales puede monitorizar cualquier JVM del sistema, pero introduce preocupaciones de seguridad adicionales.

El servidor jstatd no proporciona ninguna autenticación de clientes remotos. Por lo tanto, ejecutar un proceso servidor jstatd expone la instrumentación exportada por todas las JVM para las que el proceso jstatd tiene permisos de acceso a cualquier usuario de la red. Esta exposición podría ser indeseable en su entorno, y por lo tanto, se deben considerar las políticas de seguridad locales antes de iniciar el proceso jstatd, particularmente en entornos de producción o en redes que no son seguras.

Por motivos de seguridad, el servidor jstatd utiliza un ObjectInputFilter de RMI para permitir la deserialización solo de clases esenciales.

Si sus preocupaciones de seguridad no se pueden abordar, la acción más segura es no ejecutar el servidor jstatd y utilizar las herramientas jstat y jps localmente. Sin embargo, al usar jps para obtener una lista de JVM instrumentadas, la lista no incluirá ninguna JVM que se ejecute en contenedores Docker.

INTERFAZ REMOTA

La interfaz exportada por el proceso jstatd es propietaria y se garantiza que cambiará. Se desaconseja a los usuarios y desarrolladores que escriban en esta interfaz.

EJEMPLOS

Los siguientes son ejemplos del comando jstatd. Los scripts jstatd inician automáticamente el servidor en segundo plano.

REGISTRO RMI INTERNO

Este ejemplo muestra cómo iniciar una sesión jstatd con un registro RMI interno. Este ejemplo asume que ningún otro servidor está vinculado al puerto de registro RMI predeterminado (puerto 1099).

jstatd

REGISTRO RMI EXTERNO

Este ejemplo inicia una sesión jstatd con un servidor de registro RMI externo.


rmiregistry&
jstatd

Este ejemplo inicia una sesión jstatd con un servidor de registro RMI externo en el puerto 2020.


jrmiregistry 2020&
jstatd -p 2020

Este ejemplo inicia una sesión jstatd con un servidor de registro RMI externo en el puerto 2020 y un conector JMX vinculado al puerto 2021.


jrmiregistry 2020&
jstatd -p 2020 -r 2021

Este ejemplo inicia una sesión jstatd con un registro RMI externo en el puerto 2020 que está vinculado a AlternateJstatdServerName.


rmiregistry 2020&
jstatd -p 2020 -n AlternateJstatdServerName

DETENER LA CREACIÓN DE UN REGISTRO RMI EN PROCESO

Este ejemplo inicia una sesión jstatd que no crea un registro RMI cuando no se encuentra uno. Este ejemplo asume que ya se está ejecutando un registro RMI. Si no se está ejecutando un registro RMI, se mostrará un mensaje de error.

jstatd -nr

ACTIVAR EL REGISTRO RMI

Este ejemplo inicia una sesión jstatd con la funcionalidad de registro RMI activada. Esta técnica es útil como ayuda para la solución de problemas o para monitorizar las actividades del servidor.

jstatd -J-Djava.rmi.server.logCalls=true
