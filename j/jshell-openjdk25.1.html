JSHELL(1) Comandos de JDK JSHELL(1)

NOMBRE

jshell - evalúa interactivamente declaraciones, sentencias y expresiones del lenguaje de programación Java en un bucle de lectura-evaluación-impresión (REPL)

SINOPSIS

jshell [opciones] [archivos-de-carga]

opciones
Opciones de línea de comandos, separadas por espacios. Ver Opciones para jshell.
archivos-de-carga
Uno o más scripts para ejecutar cuando se inicia la herramienta. Los scripts pueden contener cualquier fragmento de código válido o comandos de JShell.

El script puede ser un archivo local o uno de los siguientes scripts predefinidos:

DEFAULT
Carga las entradas predeterminadas, que se usan comúnmente como importaciones.
JAVASE
Importa todos los paquetes de Java SE.
PRINTING
Define print, println y printf como métodos de jshell para usarlos dentro de la herramienta.
TOOLING
Define javac, jar y otras herramientas para ejecutar herramientas JDK a través de su interfaz de línea de comandos dentro de la herramienta jshell.

Para más de un script, use un espacio para separar los nombres. Los scripts se ejecutan en el orden en que se ingresan en la línea de comandos. Los scripts de línea de comandos se ejecutan después de los scripts de inicio. Para ejecutar un script después de que JShell se inicia, use el comando /open.

Para aceptar entrada de la entrada estándar y suprimir la E/S interactiva, ingrese un guion (-) para archivos-de-carga. Esta opción permite el uso de la herramienta jshell en cadenas de tuberías.

DESCRIPCIÓN

JShell proporciona una forma de evaluar interactivamente declaraciones, sentencias y expresiones del lenguaje de programación Java, lo que facilita el aprendizaje del lenguaje, la exploración de código y APIs desconocidas, y la creación de prototipos de código complejo. Se aceptan sentencias Java, definiciones de variables, definiciones de métodos, definiciones de clases, sentencias de importación y expresiones. Los fragmentos de código ingresados se llaman snippets.

A medida que se ingresan los snippets, se evalúan y se proporciona retroalimentación. La retroalimentación varía desde los resultados y explicaciones de las acciones hasta nada, dependiendo del snippet ingresado y del modo de retroalimentación elegido. Los errores se describen independientemente del modo de retroalimentación. Comience con el modo verboso para obtener la máxima retroalimentación mientras aprende la herramienta.

Las opciones de línea de comandos están disponibles para configurar el entorno inicial cuando se inicia JShell. Dentro de JShell, hay comandos disponibles para modificar el entorno según sea necesario.

Los snippets existentes se pueden cargar desde un archivo para inicializar una sesión de JShell, o en cualquier momento dentro de una sesión. Los snippets se pueden modificar dentro de la sesión para probar diferentes variaciones y hacer correcciones. Para conservar los snippets para su uso posterior, guárdelos en un archivo.

OPCIONES PARA JSHELL

--add-exports módulo/paquete
Especifica un paquete que se considerará exportado desde su módulo definitorio.
--add-modules módulo[,módulo...]
Especifica los módulos raíz a resolver además del módulo inicial.
-Cbandera
pasa bandera al compilador Java dentro de JShell. Por ejemplo, -C-Xlint habilita todas las advertencias de lint recomendadas, y -C--release=<N> compila para Java SE N, como si se especificara --release N.
--class-path ruta
Especifica los directorios y archivos que se buscan para localizar archivos de clase. Esta opción anula la ruta en la variable de entorno CLASSPATH. Si la variable de entorno no está establecida y esta opción no se usa, entonces se busca el directorio actual. Para Linux y macOS, use dos puntos (:) para separar los elementos de la ruta. Para Windows, use punto y coma (;) para separar los elementos.
--enable-preview
Permite que el código dependa de las características de vista previa de esta versión.
--execution especificación
Especifica un motor de ejecución alternativo, donde especificación es una especificación de ExecutionControl. Consulte la documentación del paquete jdk.jshell.spi para conocer la sintaxis de la especificación.
--feedback modo
Establece el nivel inicial de retroalimentación proporcionado en respuesta a lo que se ingresa. El nivel inicial puede ser anulado dentro de una sesión usando el comando /set feedback modo. El predeterminado es normal.

Los siguientes valores son válidos para modo:

verbose
Proporciona retroalimentación detallada para las entradas. Se muestra información adicional sobre la acción realizada después del resultado de la acción. El siguiente prompt se separa de la retroalimentación por una línea en blanco.
normal
Proporciona una cantidad promedio de retroalimentación. El siguiente prompt se separa de la retroalimentación por una línea en blanco.
concise
Proporciona retroalimentación mínima. El siguiente prompt sigue inmediatamente al fragmento de código o retroalimentación.
silent
No proporciona retroalimentación. El siguiente prompt sigue inmediatamente al fragmento de código.
custom
Proporciona modos de retroalimentación personalizados basados en cómo se define el modo. Los modos de retroalimentación personalizados se crean dentro de JShell usando el comando /set mode.
--help o -h o -?
Imprime un resumen de las opciones estándar y sale de la herramienta.
--help-extra o -X
Imprime un resumen de las opciones no estándar y sale de la herramienta. Las opciones no estándar están sujetas a cambios sin previo aviso.
-Jbandera
pasa bandera al sistema de ejecución, pero no tiene efecto en la ejecución de fragmentos de código. Para especificar banderas que afectan la ejecución de fragmentos de código, use -Rbandera. Alternativamente, use -Jbandera con --execution local.
--module-path ruta-módulos
Especifica dónde encontrar los módulos de la aplicación. Para Linux y macOS, use dos puntos (:) para separar los elementos de la ruta. Para Windows, use punto y coma (;) para separar los elementos.
--no-startup
Evita que se ejecuten scripts de inicio cuando JShell se inicia. Use esta opción para ejecutar solo los scripts ingresados en la línea de comandos cuando JShell se inicia, o para iniciar JShell sin ninguna información preCargada si no se ingresan scripts. Esta opción no se puede usar si se usa la opción --startup.
-q
Establece el modo de retroalimentación en concise, que es lo mismo que ingresar --feedback concise.
-Rbandera
pasa bandera al sistema de ejecución solo cuando se ejecutan fragmentos de código. Por ejemplo, -R-Dfoo=bar significa que la ejecución del fragmento System.getProperty(&
quot;foo") devolverá "bar".

COMANDOS DE JSHELL

JShell tiene muchos comandos que empiezan con el carácter barra diagonal (/). Estos comandos te permiten interactuar con JShell para ver y administrar las declaraciones y la historia.

/help
Muestra una lista de los comandos de JShell. Si se especifica un nombre de comando, se muestra información sobre ese comando. Por ejemplo, /help intro proporciona una introducción a JShell.

Los comandos se pueden usar para:

  • Anular el registro de un nombre de la definición correspondiente.

  • Copiar un fragmento de código en un archivo.

  • Mostrar un fragmento de código o todos los fragmentos de código registrados.

  • Editar un fragmento de código.

  • Dar un alias a un fragmento de código.

  • Eliminar un fragmento de código.

  • Deshacer la última operación de entrada de fragmentos de código.

  • Volver a ejecutar un fragmento de código.

  • Mostrar el historial de lo introducido.

  • Guardar el historial en un archivo.

  • Establecer la memoria para un fragmento de código.

  • Añadir la sentencia import a un fragmento de código.

  • Mostrar el estado de JShell.

  • Terminar la sesión de JShell.

/list
Muestra todos los fragmentos de código registrados. Se pueden especificar opciones para filtrar la lista. Por ejemplo, /list -all muestra todos los fragmentos de código, incluidos los fragmentos de inicio. /list -start muestra solo los fragmentos de código que se cargaron automáticamente cuando JShell se inició.

EJECUCIÓN DE FRAGMENTOS DE CÓDIGO

/run
Vuelve a ejecutar todos los fragmentos de código que se han definido. JShell utiliza el historial para determinar qué fragmentos de código se han definido.
/run {name|id|startID-endID} [{name|id|startID-endID}...]
Vuelve a ejecutar los fragmentos de código identificados por ID, rango de ID o nombre. Para un rango de ID, proporcione el ID de inicio y el ID de fin separados por un guion. Para proporcionar una lista, separe los elementos de la lista con un espacio. El primer elemento de la lista debe ser un ID o un rango de ID. Utilice el comando /list para ver los ID de los fragmentos de código.
/run/-n
Vuelve a ejecutar el fragmento de código anterior n. Por ejemplo, si se introdujeron 15 fragmentos de código, /run/-4 ejecuta el undécimo fragmento. Los comandos no se incluyen en el recuento.
/reload
Vuelve a ejecutar todos los fragmentos de código que se han definido. Esta es la misma operación que el comando /run.

JShell realiza un seguimiento de los fragmentos de código que se han definido y los fragmentos de código que se han modificado. Al ejecutar el comando /reload, JShell vuelve a compilar y ejecutar todos los fragmentos de código que se han definido. Esto es útil si ha realizado cambios en fragmentos de código externos que JShell utiliza.

/ !
Vuelve a ejecutar el último fragmento de código.
/ .
Lo mismo que el comando /help.

ATAJOS DE ENTRADA

Los siguientes atajos están disponibles para introducir comandos y fragmentos de código en JShell.

Autocompletado con Tabulador

<tabulador>
Al introducir fragmentos de código, comandos, subcomandos, argumentos de comando u opciones de comando, utilice la tecla Tabulador para autocompletar el elemento. Si el elemento no se puede determinar a partir de lo que se ha introducido, se proporcionan las opciones posibles.

Al introducir una llamada a un método, utilice la tecla Tabulador después del paréntesis de apertura de la llamada al método para ver los parámetros del método. Si el método tiene más de una firma, se muestran todas las firmas. Al pulsar la tecla Tabulador por segunda vez, se muestra la descripción del método y los parámetros de la primera firma. Continúe pulsando la tecla Tabulador para ver una descripción de las firmas adicionales.

Shift+<Tabulador> V
Después de introducir una expresión completa, utilice esta secuencia de teclas para convertir la expresión en una declaración de variable de un tipo determinado por el tipo de la expresión.
Shift+<Tabulador> M
Después de introducir una expresión o sentencia completa, utilice esta secuencia de teclas para convertir la expresión o sentencia en una declaración de método. Si se introduce una expresión, el tipo de retorno se basa en el tipo de la expresión.
Shift+<Tabulador> I
Cuando se introduce un identificador que no se puede resolver, utilice esta secuencia de teclas para mostrar las importaciones posibles que resuelven el identificador basándose en el contenido de la ruta de clases especificada.

Abreviaturas de comandos

Se acepta una abreviatura de un comando si la abreviatura identifica unívocamente un comando. Por ejemplo, /l se reconoce como el comando /list. Sin embargo, /s no es una abreviatura válida porque no se puede determinar si se pretende el comando /set o /save. Utilice /se para el comando /set o /sa para el comando /save.

También se aceptan abreviaturas para subcomandos, argumentos de comando y opciones de comando. Por ejemplo, utilice /m -a para mostrar todos los métodos.

Navegación por el historial

Se mantiene un historial de lo introducido entre sesiones. Utilice las flechas arriba y abajo para desplazarse por los comandos y fragmentos de código de las sesiones actuales y pasadas. Utilice la tecla Ctrl junto con las flechas arriba y abajo para saltar todas las líneas excepto la primera de los fragmentos de código multilínea.

Búsqueda en el historial

Utilice la combinación de teclas Ctrl+R para buscar en el historial la cadena introducida. El aviso cambia para mostrar la cadena y la coincidencia. Ctrl+R busca hacia atrás desde la ubicación actual en el historial a través de las entradas anteriores. Ctrl+S busca hacia adelante desde la ubicación actual en el historial a través de las entradas posteriores.

Las capacidades de edición de JShell son similares a las de otras shells comunes. Las teclas y combinaciones de teclas proporcionan atajos de edición de línea. La tecla Ctrl y la tecla Meta se utilizan en combinaciones de teclas. Si su teclado no tiene una tecla Meta, la tecla Alt a menudo se mapea para proporcionar la funcionalidad de la tecla Meta.

Flecha derecha Mueve el cursor un carácter hacia la derecha.

Ctrl+E Mueve el cursor al final de la línea.

El siguiente ejemplo muestra la definición de dos variables y un método, y la ejecución del método. Tenga en cuenta que se crea automáticamente una variable temporal para contener el resultado, ya que no se proporcionó ninguna variable.

jshell> int a=4
a ==> 4

b ==> 8

   ...> return i1 * i1;
   ...> }
|  método square(int) creado
jshell> square(b)
$5 ==> 64

EJEMPLO DE CREACIÓN DE UN MODO DE RETROALIMENTACIÓN PERSONALIZADO

El modo de retroalimentación determina el prompt que se muestra, los mensajes de retroalimentación que se proporcionan a medida que se introducen los fragmentos, y la longitud máxima de un valor mostrado. Se proporcionan modos de retroalimentación predefinidos. También se proporcionan comandos para crear modos de retroalimentación personalizados.

Utilice el comando /set mode para crear un nuevo modo de retroalimentación. En el siguiente ejemplo, el nuevo modo mymode, se basa en el modo de retroalimentación predefinido, normal, y se verifica que la retroalimentación del comando se muestre:

jshell> /set mode mymode normal -command
|  Created new feedback mode: mymode

Dado que el nuevo modo se basa en el modo normal, los prompts son los mismos. El siguiente ejemplo muestra cómo ver qué prompts se utilizan y luego cambia los prompts a cadenas personalizadas. La primera cadena representa el prompt JShell estándar. La segunda cadena representa el prompt para líneas adicionales en fragmentos multilínea.

jshell> /set prompt mymode
|  /set prompt mymode "\njshell> " "   ...> "
jshell> /set prompt mymode "\nprompt$ " "   continue$ "

La longitud máxima de un valor mostrado se controla mediante la configuración de truncamiento. Diferentes tipos de valores pueden tener diferentes longitudes. El siguiente ejemplo establece un valor de truncamiento general de 72, y un valor de truncamiento de 500 para las expresiones de valor de variable:

jshell> /set truncation mymode 72
jshell> /set truncation mymode 500 varvalue

La retroalimentación mostrada después de introducir los fragmentos se controla mediante la configuración de formato y se basa en el tipo de fragmento introducido y la acción realizada para ese fragmento. En el modo predefinido normal, la cadena created se muestra cuando se crea un método. El siguiente ejemplo muestra cómo cambiar esa cadena a defined:

jshell> /set format mymode action "defined" added-primary

Utilice el comando /set feedback para comenzar a utilizar el modo de retroalimentación que se acaba de crear. El siguiente ejemplo muestra el modo personalizado en uso:

jshell> /set feedback mymode
|  Feedback mode: mymode
prompt$ int square (int num1){
   continue$ return num1*num1;
   continue$ }
|  defined method square(int)
prompt$
