NOMBRE

jj-git-push - Empujar a un remoto de Git

SINOPSIS

jj git push [--remote] [-b|--bookmark] [--all] [--tracked] [--deleted] [--allow-empty-description] [--allow-private] [-r|--revisions] [-c|--change] [--named] [--dry-run] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help]

DESCRIPCIÓN

Empujar a un remoto de Git

Por defecto, empuja marcadores de seguimiento que apuntan a `remote_bookmarks(remote=<remoto>)..@`. Usa `--bookmark` para empujar marcadores específicos. Usa `--all` para empujar todos los marcadores. Usa `--change` para generar nombres de marcadores basados en los IDs de cambio de commits específicos.

A diferencia de Git, el remoto al que empujar no se deriva de los marcadores de remotos seguidos. Usa `--remote` para seleccionar el repositorio Git remoto por nombre. No hay opción para empujar a múltiples remotos.

Antes de que el comando mueva, cree o elimine realmente un marcador remoto, realiza varias [verificaciones de seguridad]. Si hay algún problema, es posible que necesites ejecutar `jj git fetch --remote <nombre del remoto>` y/o resolver algunos [conflictos de marcadores].

[verificaciones de seguridad]: https://docs.jj-vcs.dev/latest/bookmarks/#pushing-bookmarks-safety-checks

[conflictos de marcadores]: https://docs.jj-vcs.dev/latest/bookmarks/#conflicts

OPCIONES

--remote <REMOTO>
El remoto al que empujar (solo se admiten remotos con nombre)

Esto tiene como valor predeterminado la configuración `git.push`. Si esta no está configurada, y si hay múltiples remotos, se usará el remoto llamado "origin".

-b, --bookmark <MARCADOR>
Empujar solo este marcador, o marcadores que coincidan con un patrón (se puede repetir)

Por defecto, el nombre especificado coincide exactamente. Usa el prefijo `glob:` para seleccionar marcadores por [patrón comodín].

[patrón comodín]: https://docs.jj-vcs.dev/latest/revsets#string-patterns

--all
Empujar todos los marcadores (incluidos los nuevos marcadores)
--tracked
Empujar todos los marcadores seguidos

Esto generalmente significa que el marcador ya fue empujado o traído del [remoto relevante].

[remoto relevante]: https://docs.jj-vcs.dev/latest/bookmarks#remotes-and-tracked-bookmarks

--deleted
Empujar todos los marcadores eliminados

Solo los marcadores seguidos pueden ser eliminados con éxito en el remoto. Se imprimirá una advertencia si algún marcador no seguido en el remoto corresponde a marcadores locales ausentes.

--allow-empty-description
Permitir empujar commits con descripciones vacías
--allow-private
Permitir empujar commits que son privados

El conjunto de commits privados se puede configurar mediante la opción `git.private-commits`. El valor predeterminado es `none()`, lo que significa que todos los commits son elegibles para ser empujados.

-r, --revisions <REVSETS>
Empujar marcadores que apuntan a estos commits (se puede repetir)
-c, --change <REVSETS>
Empujar este commit creando un marcador (se puede repetir)

El marcador creado se seguirá automáticamente. Usa la opción `templates.git_push_bookmark` para personalizar el nombre del marcador generado. El valor predeterminado es `"push-" ++ change_id.short()`.

--named <NOMBRE=REVISIÓN>
Especificar un nuevo nombre de marcador y una revisión para empujar con ese nombre, por ejemplo, '--named mi-caracteristica=@'

Sigue automáticamente el marcador si es nuevo.

--dry-run
Solo mostrar lo que cambiará en el remoto
-h, --help
Imprimir ayuda (ver un resumen con '-h')

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No crear instantánea del directorio de trabajo, y no actualizarlo

Por defecto, Jujutsu crea una instantánea del directorio de trabajo al principio de cada comando. El directorio de trabajo también se actualiza al final del comando, si el comando modificó el commit del directorio de trabajo (`@`). Si deseas evitar crear una instantánea del directorio de trabajo y ver en su lugar un commit del directorio de trabajo posiblemente desactualizado, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tienes otro proceso que confirma el directorio de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu evita reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa verificación y te permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta a la verificación. No afecta al conjunto de revsets `immutable_heads()` ni a la palabra clave de plantilla `immutable`.

--at-operation <AT_OPERATION>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de operaciones divergentes si las hay.

Puedes usar `--at-op=<ID de operación>` para ver cómo se veía el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` te mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Usa `jj op log` para encontrar el ID de operación que deseas. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repositorio en una operación anterior, se ignorará el directorio de trabajo, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repositorio en una operación anterior. Hacer eso es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacer eso, pero es posible.

--debug
Habilitar registro de depuración
--color <CUÁNDO>
Cuándo colorear la salida

[posibles valores: siempre, nunca, depuración, auto]

--quiet
Silenciar la salida no principal del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no te dirá si se creó una instantánea del directorio de trabajo o si los descendientes fueron rebasados.

Las advertencias y los errores seguirán imprimiéndose.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves puntuales de TOML. El valor debe ser

especificado como una expresión TOML. Si el valor de la cadena no está entre comillas dentro de ninguna construcción TOML (como la notación de matriz), las comillas se pueden omitir.

--config-file <PATH>
Archivos de configuración adicionales (se puede repetir)
push
