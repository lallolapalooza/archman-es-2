DESCRIPCIÓ

N

Sube cambios a Gerrit para revisión de código, o actualiza cambios

existentes.

Subir un conjunto de revisiones a Gerrit crea un único "cambio" por cada revisión incluida en el revset. Estos cambios están luego disponibles para revisión en tu instancia de

Gerrit.

Nota: El ID de commit de Gerrit puede no coincidir con el de tu commit local, ya que añadimos un pie `Change-Id` al mensaje de commit si no existe ya uno. Este ID se basa en el Change-Id de jj, pero no es el

mismo.

Si ya existe un cambio para una revisión dada (es decir, contiene el mismo `Change-Id`), este comando actualizará el contenido del cambio existente para que

coincida.

Nota: este comando toma uno o más argumentos de revsets, cada uno de

los cuales puede resolver a múltiples revisiones; así que puedes publicar
árboles o rangos de commits en Gerrit para revisión de una sola vez.

--ignore-working-c

No hacer instantánea de la copia de trabajo, y no actualizarla

Por defecto, Jujutsu hace una instantánea de la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si quieres evitar hacer una instantánea de la copia de trabajo y en su lugar ver un commit de la copia de trabajo posiblemente obsoleto, puedes usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en un prompt de comandos, especialmente si tienes otro proceso que hace commits de la copia de

trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-

ble
Permitir reescribir commits inmutables

Por defecto, Jujutsu previene la reescritura de commits en el conjunto configurado de commits inmutables. Esta opción desactiva esa comprobación y te permite reescribir cualquier commit excepto el commit

raíz.

Esta opción solo afecta a la comprobación. No

afecta al revset `immutable_heads()` n
i a la palabra clave de plantilla `immutable`.
--at-operation <AT_OPERATIO
N>
Operación en la que cargar el repositorio

Operación en la que cargar el repositorio. Por defecto, Jujutsu carga el repositorio en la operación más reciente, o en la fusión de las operaciones divergentes si

las hay.

Puedes usar `--at-op=<operation ID>` para ver cómo era el repositorio en una operación anterior. Por ejemplo, `jj --at-op=<operation ID> st` te mostraría lo que `jj st` habría mostrado cuando la operación dada hubiera terminado. `--at-op=@` es prácticamente lo mismo que el defecto excepto que las operaciones divergentes nunca se

fusionarán.

Usa `jj op log` para encontrar el ID de operación que quieres. Cualquier prefijo no ambiguo del ID de operación es

suficiente.

Al cargar el repositorio en una operación anterior, la copia de trabajo se ignorará, como si se hubiera especificado `--ignore-working-c

opy`.

Es posible ejecutar comandos mutantes al cargar el repositorio en una operación ant

erior. Hacer eso es equivalente a haber ejecutado comandos concurrentes que comien
zan en la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.
