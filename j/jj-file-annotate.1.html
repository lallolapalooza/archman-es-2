NOMBRE

jj-file-annotate - Muestra el cambio de origen para cada línea del archivo objetivo

SINOPSIS

jj file annotate [-r|--revision] [-T|--template] [-R|--repository] [--ignore-working-copy] [--ignore-immutable] [--at-operation] [--debug] [--color] [--quiet] [--no-pager] [--config] [--config-file] [-h|--help] <RUTA>

DESCRIPCIÓN

Muestra el cambio de origen para cada línea del archivo objetivo.

Anota una revisión línea por línea. Cada línea incluye el cambio de origen que introdujo la línea asociada. Se debe proporcionar una ruta al archivo deseado.

OPCIONES

-r, --revision <REVSET>
una revisión opcional para empezar
-T, --template <PLANTILLA>
Renderiza cada línea usando la plantilla dada

Todos los métodos de 0 argumentos del tipo [`AnnotationLine`] están disponibles como palabras clave en la expresión de plantilla. Consulte [`jj help -k templates`] para obtener más información.

Si no se especifica, esto se establecerá por defecto en la configuración `templates.file_annotate`.

[`Tipo AnnotationLine`]: https://docs.jj-vcs.dev/latest/templates/#annotationline-type

[`jj help -k templates`]: https://docs.jj-vcs.dev/latest/templates/

-h, --help
Imprime la ayuda (ver un resumen con '-h')
<RUTA>
el archivo a anotar

OPCIONES GLOBALES

-R, --repository <REPOSITORIO>
Ruta al repositorio sobre el que operar

Por defecto, Jujutsu busca el directorio .jj/ más cercano en un ancestro del directorio de trabajo actual.

--ignore-working-copy
No fotografiar la copia de trabajo, y no actualizarla

Por defecto, Jujutsu fotografía la copia de trabajo al principio de cada comando. La copia de trabajo también se actualiza al final del comando, si el comando modificó el commit de la copia de trabajo (`@`). Si desea evitar fotografiar la copia de trabajo y ver en su lugar un commit de copia de trabajo potencialmente obsoleto, puede usar `--ignore-working-copy`. Esto puede ser útil, por ejemplo, en una línea de comandos, especialmente si tiene otro proceso que confirma la copia de trabajo.

Cargar el repositorio en una operación específica con `--at-operation` implica `--ignore-working-copy`.

--ignore-immutable
Permitir reescribir commits inmutables

Por defecto, Jujutsu evita reescribir commits en el conjunto configurado de commits inmutables. Esta opción deshabilita esa comprobación y le permite reescribir cualquier commit excepto el commit raíz.

Esta opción solo afecta la comprobación. No afecta al revset `immutable_heads()` ni a la palabra clave de plantilla `immutable`.

--at-operation <OPERACION_EN_ESE_MOMENTO>
Operación en la que cargar el repo

Operación en la que cargar el repo. Por defecto, Jujutsu carga el repo en la operación más reciente, o en la fusión de operaciones divergentes si las hay.

Puede usar `--at-op=<ID de operación>` para ver cómo era el repo en una operación anterior. Por ejemplo, `jj --at-op=<ID de operación> st` le mostrará lo que `jj st` habría mostrado cuando la operación dada acababa de finalizar. `--at-op=@` es prácticamente lo mismo que el valor predeterminado, excepto que las operaciones divergentes nunca se fusionarán.

Use `jj op log` para encontrar el ID de operación que desea. Cualquier prefijo no ambiguo del ID de operación es suficiente.

Al cargar el repo en una operación anterior, la copia de trabajo se ignorará, como si se hubiera especificado `--ignore-working-copy`.

Es posible ejecutar comandos mutables al cargar el repo en una operación anterior. Hacerlo es equivalente a haber ejecutado comandos concurrentes que comenzaron en la operación anterior. Rara vez hay una razón para hacerlo, pero es posible.

--debug
Habilitar registro de depuración
--color <CUANDO>
Cuándo colorear la salida

[posibles valores: always, never, debug, auto]

--quiet
Silenciar la salida no principal del comando

Por ejemplo, `jj file list` seguirá listando archivos, pero no le dirá si la copia de trabajo fue fotografiada o si los descendientes fueron rebasados.

Las advertencias y los errores se seguirán imprimiendo.

--no-pager
Deshabilitar el paginador
--config <NOMBRE=VALOR>
Opciones de configuración adicionales (se pueden repetir)

El nombre debe especificarse como claves separadas por puntos TOML. El valor debe especificarse como una expresión TOML. Si el valor de cadena no está encerrado en ningún constructo TOML (como la notación de matriz), se pueden omitir las comillas.

--config-file <RUTA>
Archivos de configuración adicionales (se pueden repetir)
