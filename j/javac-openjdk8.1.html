fallthrough
Verifica los bloques switch para casos de caída y proporciona un mensaje de advertencia para cualquiera que se encuentre. Los casos de caída son casos en un bloque switch, distintos del último caso en el bloque, cuyo código no incluye una sentencia break, permitiendo que la ejecución del código caiga desde ese caso al siguiente. Por ejemplo, el código que sigue a la etiqueta case 1 en este bloque switch no termina con una sentencia break: 
switch (x) {
case 1:
  System.out.println("1");
  // No hay sentencia break aquí.
case 2:
  System.out.println("2");
}

Si se utilizó la opción -Xlint:fallthrough al compilar este código, entonces el compilador emitirá una advertencia sobre una posible caída en el caso, con el número de línea del caso en cuestión.

finally
Advierte sobre cláusulas finally que no pueden completarse normalmente, por ejemplo: 
public static int m() {
  try {
     throw new NullPointerException();
  }  catch (NullPointerException(); {
     System.err.println("Se capturó NullPointerException.");
     return 1;
   } finally {
     return 0;
   }
  }

El compilador genera una advertencia para el bloque finally en este ejemplo. Cuando se llama al método int, devuelve un valor de 0. Un bloque finally se ejecuta cuando sale el bloque try. En este ejemplo, cuando el control se transfiere al bloque catch, el método int sale. Sin embargo, el bloque finally debe ejecutarse, por lo que se ejecuta, aunque el control se haya transferido fuera del método.

PROCESAMIENTO DE

ANOTACIONES

El comando javac proporciona soporte directo para el procesamiento de anotaciones, superando la necesidad del comando separado de procesamiento de anotaciones, apt

.

La API para procesadores de anotaciones está definida en los paquetes javax.annotation.processing y javax.lang.model y sus

subpaquetes.

CÓMO FUNCIONA EL PROCESAMIENTO DE

ANOTACIONES

A menos que el procesamiento de anotaciones esté deshabilitado con la opción -proc:none, el compilador busca cualquier procesador de anotaciones que esté disponible. La ruta de búsqueda se puede especificar con la opción -processorpath. Si no se especifica ninguna ruta, se utiliza la ruta de clases del usuario. Los procesadores se localizan mediante archivos de configuración de proveedores de servicio llamados META-INF/services/javax.annotation.processing.Processor en la ruta de búsqueda. Dichos archivos deben contener los nombres de los procesadores de anotaciones a usar, listados uno por línea. Alternativamente, los procesadores se pueden especificar explícitamente, usando la opción -proc

essor.

Después de escanear los archivos fuente y clases en la línea de comandos para determinar qué anotaciones están presentes, el compilador consulta a los procesadores para determinar qué anotaciones procesan. Cuando se encuentra una coincidencia, se llama al procesador. Un procesador puede reclamar las anotaciones que procesa, en cuyo caso no se hace ningún intento adicional de encontrar procesadores para esas anotaciones. Después de que todas las anotaciones sean reclamadas, el compilador no busca procesadores

adicionales.

Si algún procesador genera nuevos archivos fuente, se produce otra ronda de procesamiento de anotaciones: Se escanean los archivos fuente recién generados y las anotaciones se procesan como antes. Los procesadores llamados en rondas anteriores también se llaman en todas las rondas posteriores. Esto continúa hasta que no se generen nuevos archivos

fuente.

Después de una ronda en la que no se generan nuevos archivos fuente, los procesadores de anotaciones se llaman una última vez, para darles la oportunidad de completar cualquier trabajo restante. Finalmente, a menos que la opción -proc:only sea usada, el compilador compi

la el original y todos los
archivos fuente generados.

BÚSQUEDA DE

TIPOS

Para compilar un archivo fuente, el compilador a menudo necesita información sobre un tipo, pero la definición del tipo no está en los archivos fuente especificados en la línea de comandos. El compilador necesita información de tipo para cada clase o interfaz usada, extendida o implementada en el archivo fuente. Esto incluye clases e interfaces no mencionadas explícitamente en el archivo fuente, pero que proporcionan información a través de la

herencia.

Por ejemplo, cuando creas una subclase de java.applet.Applet, también estás usando las clases ancestrales de Applet: java.awt.Panel, java.awt.Container, java.awt.Component, y java.lang.O

bject.

Cuando el compilador necesita información de tipo, busca un archivo fuente o un archivo de clase que defina el tipo. El compilador busca archivos de clase primero en las clases de arranque y de extensión, luego en la ruta de clases del usuario (que por defecto es el directorio actual). La ruta de clases del usuario se define estableciendo la variable de entorno CLASSPATH o usando la opción -clas

spath.

Si estableces la opción -sourcepath, entonces el compilador busca archivos fuente en la ruta indicada. De lo contrario, el compilador busca en la ruta de clases del usuario tanto archivos de clase como archivos

fuente.

Puedes especificar clases de arranque o de extensión diferentes con las opciones -bootclasspath y -extdirs. Ver Opciones de Compilación

Cruzada.

Una búsqueda de tipos exitosa puede producir un archivo de clase, un archivo fuente, o ambos. Si se encuentran ambos, puedes usar la opción -Xprefer para instruir al compilador cuál usar. Si se especifica newer, el compilador usa el más reciente de los dos archivos. Si se especifica source, el compilador usa el archivo fuente. El valor por defecto es newer

.

Si una búsqueda de tipos encuentra un archivo fuente para un tipo requerido, ya sea por sí mismo, o como resultado de la configuración de la opción -Xprefer, entonces el compilador lee el archivo fuente para obtener la información que necesita. Por defecto, el compilador también compila el archivo fuente. Puedes usar la opción -implicit para especificar el comportamiento. Si se especifica none, no se generan archivos de clase para el archivo fuente. Si se especifica class, se generan archivos de clase para el archivo

fuente.

El compilador podría no descubrir la necesidad de alguna información de tipo hasta que el procesamiento de anotaciones se complete. Cuando la información de tipo se encuentra en un archivo fuente y no se especifica la opción -implicit, el compilador emite una advertencia de que el archivo se está compilando sin estar sujeto al procesamiento de anotaciones. Para deshabilitar la advertencia, especifica el archivo en la línea de comandos (para que esté sujeto al procesamiento de anotaciones) o usa la opción -implicit para especificar si deben o no ge

nerarse archivos de clase p
ara dichos archivos fuente.
