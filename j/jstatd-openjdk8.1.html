DESCRIPCIÓ

N

El comando jstatd es una aplicación de servidor RMI que monitorea la creación y terminación de VMs Java HotSpot instrumentadas y proporciona una interfaz para permitir que herramientas de monitoreo remoto se conecten a las JVM que se ejecutan en el host

local.

El servidor jstatd requiere un registro RMI en el host local. El servidor jstatd intenta conectarse al registro RMI en el puerto predeterminado, o en el puerto que usted especifique con la -ppuerto opción. Si no se encuentra un registro RMI, entonces se crea uno dentro de la aplicación jstatd que está vinculado al puerto que indica la -popción puerto o al puerto predeterminado del registro RMI cuando la -popción puerto se omite. Puede detener la creación de un registro RMI interno especificando la opción

-
nr.

SEGURIDA

D

El servidor jstatd solo puede monitorear JVM para las que tiene los permisos de acceso nativo apropiados. Por lo tanto, el proceso jstatd debe ejecutarse con las mismas credenciales de usuario que las JVM de destino. Algunas credenciales de usuario, como el usuario root en sistemas basados en UNIX, tienen permiso para acceder a la instrumentación exportada por cualquier JVM en el sistema. Un proceso jstatd que se ejecuta con tales credenciales puede monitorear cualquier JVM en el sistema, pero introduce preocupaciones de seguridad

adicionales.

El servidor jstatd no proporciona ninguna autenticación de clientes remotos. Por lo tanto, ejecutar un proceso de servidor jstatd expone la instrumentación exportada por todas las JVM para las que el proceso jstatd tiene permisos de acceso a cualquier usuario en la red. Esta exposición puede ser indeseable en su entorno, por lo tanto, se deben considerar las políticas de seguridad locales antes de que usted inicie el proceso jstatd, particularmente en entornos de producción o en redes que no son

seguras.

El servidor jstatd instala una instancia de RMISecurityPolicy cuando no hay otro gestor de seguridad instalado, y por lo tanto, requiere que se especifique un archivo de política de seguridad. El archivo de política debe cumplir con la Implementación de Política Predeterminada y Sintaxis del Archivo de Política en http://docs.oracle.com/javase/8/docs/technotes/guides/security/PolicyFiles.

html

El siguiente archivo de política permite que el servidor jstatd se ejecute sin ninguna excepción de seguridad. Esta política es menos liberal que otorgar todos los permisos a todas las bases de código, pero es más liberal que una política que otorga los permisos mínimos para ejecutar el servidor js

tatd. 
grant codebase "file:${java.home}/../lib/tools.jar"
{

AllPermission; 
}
;

Para usar esta configuración de política, copie el texto en un archivo llamado jstatd.all.policy y ejecute el servidor jstatd de la siguiente

manera: 
jstatd -J-Djava.security.policy=jstatd.all.
policy

Para sitios con prácticas de seguridad más restrictivas, es posible usar un archivo de política personalizado para limitar el acceso a hosts o redes de confianza específicos, aunque tales técnicas están sujetas a ataques de suplantación de direcciones IP. Si sus preocupaciones de seguridad no pueden abordarse con un archivo de política personalizado, entonces la acción más segura es no ejecutar el servidor jstatd y usar las herramientas jstat y jps loca
