NOMBRE

jdeps - inicia el analizador de dependencias de clases Java

SINOPSIS

jdeps [opciones] ruta ...

opciones
Opciones de línea de comandos. Para descripciones detalladas de las opciones que se pueden usar, consulte
•
Posibles Opciones
•
Opciones de Análisis de Dependencias de Módulos
•
Opciones para Filtrar Dependencias
•
Opciones para Filtrar Clases a Analizar
ruta
Un nombre de ruta a un archivo .class, directorio o archivo JAR para analizar.

DESCRIPCIÓN

El comando jdeps muestra las dependencias a nivel de paquete o a nivel de clase de los archivos de clase Java. La clase de entrada puede ser un nombre de ruta a un archivo .class, un directorio, un archivo JAR, o puede ser un nombre de clase completamente calificado para analizar todos los archivos de clase. Las opciones determinan la salida. Por defecto, el comando jdeps escribe las dependencias en la salida del sistema. El comando puede generar las dependencias en lenguaje DOT (ver la opción -dotoutput).

POSIBLES OPCIONES

-? o -h o --help
Imprime el mensaje de ayuda.
-dotoutput dir o --dot-output dir
Especifica el directorio de destino para la salida de archivos DOT. Si se especifica esta opción, el comando jdeps genera un archivo .dot por cada archivo analizado llamado nombre-archivo-archivo.dot que lista las dependencias, y también un archivo de resumen llamado summary.dot que lista las dependencias entre los archivos de archivo.
-s o -summary
Imprime solo un resumen de dependencias.
-v o -verbose
Imprime todas las dependencias a nivel de clase. Esto es equivalente a

-verbose:class -filter:none

-verbose:package
Imprime dependencias a nivel de paquete excluyendo, por defecto, las dependencias dentro del mismo paquete.
-verbose:class
Imprime dependencias a nivel de clase excluyendo, por defecto, las dependencias dentro del mismo archivo.
-apionly o --api-only
Restringe el análisis a las APIs, por ejemplo, dependencias de la firma de miembros públicos y protegidos de clases públicas, incluyendo el tipo de campo, el tipo de parámetro del método, el tipo devuelto y los tipos de excepción comprobados.
-jdkinternals o --jdk-internals
Encuentra dependencias a nivel de clase en las APIs internas del JDK. Por defecto, esta opción analiza todas las clases especificadas en la opción --classpath y los archivos de entrada, a menos que haya especificado la opción -include. No puede usar esta opción con las opciones -p, -e y -s.

Advertencia: Las APIs internas del JDK son inaccesibles.

-cp ruta, -classpath ruta, o --class-path ruta
Especifica dónde encontrar los archivos de clase.
--module-path ruta-modulo
Especifica la ruta del módulo.
--upgrade-module-path ruta-modulo
Especifica la ruta del módulo de actualización.
--system java-home
Especifica una ruta de módulo del sistema alternativa.
--add-modules nombre-modulo[, nombre-modulo...]
Añade módulos al conjunto raíz para el análisis.
--multi-release versión
Especifica la versión al procesar archivos JAR de versiones múltiples. versión debe ser un entero >=9 o base.
-q o -quiet
No muestra dependencias faltantes en la salida de -generate-module-info.
-version o --version
Imprime información de la versión.

OPCIONES DE ANÁLISIS DE DEPENDENCIAS DE MÓDULOS

-m nombre-modulo o --module nombre-modulo
Especifica el módulo raíz para el análisis.
--generate-module-info dir
Genera module-info.java en el directorio especificado. Se analizarán los archivos JAR especificados. Esta opción no se puede usar con las opciones --dot-output o --class-path. Use la opción --generate-open-module para módulos abiertos.
--generate-open-module dir
Genera module-info.java para los archivos JAR especificados en el directorio especificado como módulos abiertos. Esta opción no se puede usar con las opciones --dot-output o --class-path.
--check nombre-modulo [, nombre-modulo...]
Analiza la dependencia de los módulos especificados. Imprime el descriptor del módulo, las dependencias de módulo resultantes después del análisis y el gráfico después de la reducción de transiciones. También identifica las exportaciones calificadas no utilizadas.
--list-deps
Lista las dependencias de módulos y también los nombres de paquetes de las APIs internas del JDK (si se referencian). Esta opción analiza transitivamente las bibliotecas en la ruta de clases y la ruta de módulos si se referencian. Use la opción --no-recursive para el análisis de dependencias no transitivas.
--list-reduced-deps
Igual que --list-deps sin listar los bordes de lectura implícitos del gráfico de módulos. Si el módulo M1 lee M2, y M2 requiere transitivamente M3, entonces la lectura de M3 por M1 es implícita y no se muestra en el gráfico.
--print-module-deps
Igual que --list-reduced-deps imprimiendo una lista separada por comas de las dependencias de módulos. La salida puede ser utilizada por jlink --add-modules para crear una imagen personalizada que contenga esos módulos y sus dependencias transitivas.
--ignore-missing-deps
Ignora las dependencias faltantes.

OPCIONES PARA FILTRAR DEPENDENCIAS

-p nombre-paquete, -package nombre-paquete, o --package nombre-paquete
Encuentra dependencias que coincidan con el nombre del paquete especificado. Puede especificar esta opción varias veces para diferentes paquetes. Las opciones -p y -e son mutuamente excluyentes.
-e regex, -regex regex, o --regex regex
Encuentra dependencias que coincidan con el patrón especificado. Las opciones -p y -e son mutuamente excluyentes.
--require nombre-modulo
Encuentra dependencias que coincidan con el nombre del módulo dado (puede darse varias veces). Las opciones --package, --regex y --require son mutuamente excluyentes.
-f regex o -filter regex
Filtra las dependencias que coincidan con el patrón dado. Si se da varias veces, se seleccionará la última.
-filter:package
Filtra las dependencias dentro del mismo paquete. Este es el valor por defecto.
-filter:archive
Filtra las dependencias dentro del mismo archivo.
-filter:module
Filtra las dependencias dentro del mismo módulo.
-filter:none
Sin filtrado -filter:package y -filter:archive. El filtrado especificado mediante la opción -filter aún se aplica.
--missing-deps
Encuentra dependencias faltantes. Esta opción no se puede usar con las opciones -p, -e y -s.

OPCIONES PARA FILTRAR CLASES A ANALIZAR

-include regex
Restringe el análisis a las clases que coincidan con el patrón. Esta opción filtra la lista de clases a analizar. Se puede usar junto con -p y -e, que aplican el patrón a las dependencias.
-P o -profile
Muestra el perfil que contiene un paquete. Esta opción está obsoleta y puede eliminarse en una futura versión.
-R o --recursive
Recorre recursivamente todas las dependencias en tiempo de ejecución. La opción -R implica -filter:none. Si se especifican las opciones -p, -e o -f, solo se analizan las dependencias coincidentes.
--no-recursive
No recorrer recursivamente las dependencias.
-I o --inverse
Analiza las dependencias según las opciones dadas y luego encuentra todos los artefactos que dependen directa e indirectamente de los nodos coincidentes. Esto es equivalente a la inversa del análisis de la vista en tiempo de compilación y el resumen de dependencias de impresión. Esta opción debe usarse con las opciones --require, --package o --regex.
--compile-time
Analiza la vista en tiempo de compilación de las dependencias transitorias, como la vista en tiempo de compilación de la opción -R. Analiza las dependencias según otras opciones especificadas. Si se encuentra una dependencia de un directorio, un archivo JAR o un módulo, se analizan todas las clases en ese archivo contenedor.

EJEMPLO DE ANALIZAR DEPENDENCIAS

El siguiente ejemplo demuestra cómo analizar las dependencias del archivo Notepad.jar.

Linux y macOS:


$ jdeps demo/jfc/Notepad/Notepad.jar
Notepad.jar -> java.base
Notepad.jar -> java.desktop
Notepad.jar -> java.logging
   <unnamed> (Notepad.jar)
      -> java.awt
      -> java.awt.event
      -> java.beans
      -> java.io
      -> java.lang
      -> java.net
      -> java.util
      -> java.util.logging
      -> javax.swing
      -> javax.swing.border
      -> javax.swing.event
      -> javax.swing.text
      -> javax.swing.tree
      -> javax.swing.undo

EJEMPLO USANDO LA OPCIÓN --INVERSE


 $ jdeps --inverse --require java.xml.bind
Dependencias transitivas inversas sobre [java.xml.bind]
java.xml.bind <- java.se.ee
java.xml.bind <- jdk.xml.ws
java.xml.bind <- java.xml.ws <- java.se.ee
java.xml.bind <- java.xml.ws <- jdk.xml.ws
java.xml.bind <- jdk.xml.bind <- jdk.xml.ws
