DESCRIPCIÓ

N

La herramienta jpackage tomará como entrada una aplicación Java y una imagen de tiempo de ejecución de Java, y producirá una imagen de aplicación Java que incluye todas las dependencias necesarias. Será capaz de producir un paquete nativo en un formato específico de

la plataforma, como un exe en Windows o un dmg en macOS. Cada formato debe compilarse en la plataforma en la que se ejecuta, no
hay soporte multiplataforma. La herramienta tendrá opciones que permiten personalizar las aplicaciones empaquetadas de varias maneras.

Las claves "module", "main-jar", "main-class", "description", "arguments", "java-options", "icon", "launcher-as-service", "win-console", "win-shortcut", "win-menu", y "linux-shortcut" pueden

Estas opciones se añaden, o se usan para sobrescribir, las opciones originales de la línea de comandos para construir un lanzador alternativo adicional. El lanzador principal de la aplicación será construidos a partir de las opciones de línea de comandos. Se pueden construir lanzadores alternativos adicionales utilizando esta opción, y esta opción se puede usar varias veces para construir múltiples lanzadores adicionales.

--arguments argumentos
Argumentos de línea de comandos para pasar a la clase principal si no se proporcionan argumentos de línea de comandos al lanzador

Esta opción se puede usar varias veces.

El valor puede contener subcadenas que se expandirán en tiempo de ejecución. Se admiten dos tipos de subcadenas: variables de entorno y tokens "APPDIR", "BINDIR" y "ROOTDIR".

Una subcadena expandible debe encerrarse entre el carácter de signo de dólar ($) y el primer carácter no alfanumérico siguiente. Alternativamente, puede encerrarse entre las subcadenas "${" y "}".

Las subcadenas expandibles distinguen entre mayúsculas y minúsculas en Unix y no distinguen entre mayúsculas y minúsculas en Windows. No se producen expansiones de cadenas si la variable de entorno referenciada está indefinida.

Las variables de entorno con nombres "APPDIR", "BINDIR" y "ROOTDIR" se ignorarán, y estas subcadenas expandibles se reemplazarán por valores calculados por el lanzador de la aplicación.

Anteponer el carácter de signo de dólar con el carácter de barra invertida (\) para evitar la expansión de subcadenas.

--java-options opciones
Opciones para pasar al tiempo de ejecución de Java

Esta opción se puede usar varias veces.

El valor puede contener subcadenas que se sustituirán en tiempo de ejecución, como para la opción --arguments.

--main-class nombre-clase
Nombre cualificado de la clase principal de la aplicación a ejecutar

Esta opción solo se puede usar si se especifica --main-jar.

--main-jar jar-principal
El JAR principal de la aplicación; contiene la clase principal (especificado como una ruta relativa a la ruta de entrada)

Se puede especificar la opción --module o --main-jar, pero no ambas.

--module o -m nombre-módulo[/clase-principal]
El módulo principal (y opcionalmente la clase principal) de la aplicación

Este módulo debe estar ubicado en la ruta del módulo.

Cuando se especifica esta opción, el módulo principal se vinculará en la imagen del tiempo de ejecución de Java. Se puede especificar la opción --module o --main-jar, pero no ambas.

Ejemplos

Ejecuta una aplicación, creando un paquete de instalador de Windows MSI y un lanzador de consola.

jpackage --name myapp --input target/my.jar --main-jar my.jar --type msi --win-console

Crea un paquete de instalador de Linux RPM para la aplicación proporcionada por el módulo principal.

jpackage --name myapp --module com.myapp.main --type rpm

JPACKAGE EJEMPLOS

Genera un paquete de aplicación adecuado para el sistema anfitrión:

Para una aplicación modular:
    jpackage -n nombre -p rutaMódulos -m nombreMódulo/nombreClase
Para una aplicación no modular:
    jpackage -i directorioEntrada -n nombre \
        --main-class nombreClase --main-jar miJar.jar
Desde una imagen de aplicación precompilada:
    jpackage -n nombre --app-image directorioImagenApp

Genera una imagen de aplicación:

Para una aplicación modular:
    jpackage --type app-image -n nombre -p rutaMódulos \
        -m nombreMódulo/nombreClase
Para una aplicación no modular:
    jpackage --type app-image -i directorioEntrada -n nombre \
        --main-class nombreClase --main-jar miJar.jar
Para proporcionar tus propias opciones a jlink, ejecuta jlink por separado:
    jlink --output imagenRuntimeApp -p rutaMódulos \
        --add-modules nombreMódulo \
        --no-header-files [<opciones adicionales de jlink>...]
    jpackage --type app-image -n nombre \
        -m nombreMódulo/nombreClase --runtime-image imagenRuntimeApp

Genera un paquete de tiempo de ejecución de Java:

jpackage -n nombre --runtime-image <imagen-runtime>

Firma la imagen de aplicación predefinida (en macOS):

jpackage --type app-image --app-image <imagen-app> \
    --mac-sign [<opciones adicionales de firma>...]
Nota: las únicas opciones adicionales permitidas en este modo son:
      el conjunto de opciones adicionales de firma de Mac y --verbose

JPACKAGE Y JLINK

jpackage utilizará jlink para crear el tiempo de ejecución de Java, a menos que se utilice la opción --runtime-image. La imagen del tiempo de ejecución de Java creada en Windows incluirá las bibliotecas de tiempo de ejecución de MS incluidas con el JDK. Si se necesitan bibliotecas de tiempo de ejecución de MS de una versión diferente para la aplicación, el usuario deberá añadirlas/reemplazarlas por sí mismo.
