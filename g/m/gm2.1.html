Para cualquier archivo de entrada dado, el sufijo del nombre del archivo determina qué tipo de compilación se realiza. Se admiten los siguientes tipos de nombres de archivo de

entrada:
archivo.
mod
Archivos fuente de implementación o programa de Modula-2. Vea la -fmod= opción si desea compilar un proyecto que utiliza una extensión de archivo fuente
diferente.
archivo.
def
Archivos fuente de módulos de definición de Modula-2. Los módulos de definición no se compilan por separado, en GNU Modula-2 los módulos de definición se analizan según sea necesario cuando se compilan los módulos de programa o de implementación. Vea la -fdef= opción si desea compilar un proyecto que util
iza una extensión de
archivo fuente diferente.

Puede especificar más de un archivo de entrada en la línea de comandos de

gm2,
"-
g"
crea información de depuración para que depuradores como gdb puedan inspeccionar y controlar el
ejecutable.
"-
I"
se utiliza para especificar la ruta de búsqueda para los módulos de definición y de implementación. Un ejemplo es: "gm2 -g -c -I.:../../libs foo.mod". Si no se especifica esta opción, se añade la ruta predeterminada, que consiste en el directorio actual seguido de los directorios de bibliotecas de dialecto de lenguaje
correspondientes.
"-fauto-ini
t"
activa la inicialización automática de los punteros a NIL. Siempre que se crea un bloque, todos los punteros declarados dentro de este ámbito tendrán sus direcciones asignadas a
NIL.
"-fbound
s"
activa la comprobación en tiempo de ejecución de subrangos, índices de matriz y indirección a través de punteros "
NIL".
"-fcas
e"
activa la comprobación en tiempo de compilación para verificar si una sentencia "CASE" requiere una cláusula "ELSE" cuando no se especificó
una.
"-fcp
p"
preprocesa el código fuente con cpp -lang-asm -traditional-cpp Para obtener más detalles sobre estas opciones. Si se proporciona -fcpp, todos los módulos de definición y de implementación que se analicen serán preprocesados por cpp
.
"-fdebug-builti
ns"
llama a una función real en lugar del equivalente incorporado. Esto puede ser útil para depurar los valores de los parámetros de una función incorporada, ya que permite a los usuarios realizar una ejecución paso a paso dentro de una función
intrínseca.
"-fdef
="
reconoce el sufijo especificado como el nombre de archivo de un módulo de definición. El sufijo predeterminado del nombre de archivo de implementación y de módulo es .def. Si se usa esta opción, GNU Modula-2 seguirá recurriendo a este predeterminado si no se encuentra un módulo de definición
solicitado.
"-fdump-system-expor
ts"
muestra todos los elementos del sistema incorporados. Esta es una opción interna de la línea de
comandos.
"-fexception
s"
activa el código de manejo de excepciones. Por defecto, esta opción está activada. El manejo de excepciones se puede desactivar con -fno-exceptions y no se hacen referencias a las bibliotecas de excepciones en tiempo de
ejecución.
"-fextended-opaq
ue"
permite que los tipos opacos se implementen como cualquier tipo. Esta es una extensión de GNU Modula-2 y requiere que el módulo de implementación que define el tipo opaco esté disponible para que pueda resolverse al compilar el módulo que importa el tipo
opaco.
"-ffloatvalu
e"
activa la comprobación en tiempo de ejecución para verificar si un número de punto flotante está a punto de exceder el
rango.
"-fgen-module-list=nombrearch
ivo"
intenta encontrar todos los módulos al enlazar y genera una lista de módulos. Si el nombrearchivo es - entonces el contenido no se escribe y solo se utiliza para forzar el enlazado de todos los constructores de módulos. Esta opción no se puede usar si -fuse-list= está
habilitado.
"-finde
x"
genera código para comprobar si los valores de los índices de matriz están fuera de los límites. La comprobación de índices de matriz se puede desactivar con -fno-inde
x.
"-fis
o"
activa las características del estándar ISO. Actualmente esto habilita el módulo "SYSTEM" de ISO y altera la ruta de búsqueda de bibliotecas predeterminada para que las bibliotecas ISO se busquen antes que las bibliotecas PIM. También afecta el comportamiento de los operadores "DIV" y "MOD"
.
"-flibs
="
modifica la ruta de búsqueda de bibliotecas predeterminada. Las bibliotecas proporcionadas son: m2pim, m2iso, m2min, m2log y m2cor. Estas se corresponden con las bibliotecas base de Programming in Modula-2, las bibliotecas estándar ISO, el soporte de biblioteca mínima, la biblioteca compatible con Logitech y Programming in Modula-2 con corutinas. Se pueden especificar múltiples bibliotecas y se separan con comas, con precedencia para la primera de la lista. No es necesario usar -flibs=m2pim o -flibs=m2iso si también especifica -fpim, -fpim2, -fpim3, -fpim4 o -fiso. A menos que esté usando -flibs=m2min, debe incluir m2pim, ya que proporciona los módulos base que utilizan todos los demás dialectos. La opción -fno-libs=- desactiva el controlador gm2 de modificar las rutas de búsqueda y de
bibliotecas.
"-static-libg
m2"
En sistemas que proporcionan los tiempos de ejecución de m2 tanto como bibliotecas compartidas como estáticas, esta opción fuerza el uso de la versión
estática.
"-fm2-debug-trac
e="
activa la depuración de seguimiento usando una lista separada por comas: line,token,quad,all. Esta es una opción interna de la línea de
comandos.
"-fm2-dump
="
habilita el volcado de la representación interna de estructuras de datos de Modula-2 usando una lista separada por comas. La lista puede contener: quad,gimple,de
cl,all.
"-fm2-dump-decl=nombreba
se"
vuelca la representación de Modula-2 de un símbolo al nombrebase especificado. Esta opción solo tiene efecto si se especifica -fm2-dump-filte
r.
"-fm2-dump-gimple=nombreba
se"
vuelca la representación gimple de Modula-2 al nombrebase espec
ificado.
"-fm2-dump-quad=nombreba
se"
vuelca la representación de cuádruplas al nombrebase espec
ificado.
"-fm2-dump-filter=regla
s"
filtra los volcados de lenguaje -fdump-lang-decl, -fdump-lang-gimple y-fdump-lang-quad según reglas. reglas debe ser una lista separada por comas que puede tomar tres formas: el nombre textual completo de declaración de un procedimiento, [libname.]module.ident o [filename:]module.ident. Esta es una opción interna de la línea de comandos. Actualmente solo filtra por nombres de procedimientos y no está implementada la coincidencia de expresiones regulares. Tres ejemplos de su uso siguiendo las formas anteriores podrían ser: "-fm2-dump-filter=_M2_hello_init", "-fm2-dump-filter=m2pim.StrIO.WriteString" y "-fm2-dump-filter=StrLib.mod:Str
IO.WriteString".
"-fm2-file-offset-bit
s="
fuerza que el tipo "SYSTEM.COFF_T" se construya usando el número de bits especificado. Si no se usa esta opción, el valor predeterminado es "CSSIZE_T"
bits.
"-fm2-
g"
mejora la experiencia de depuración para los programadores novatos a costa de generar instrucciones "nop" si es necesario para asegurar la precisión de la ejecución paso a paso sobre todas las palabras clave relacionadas con el código. Un ejemplo de esto es en la terminación de una lista de sentencias "IF" anidadas donde múltiples palabras clave "END" se mapean a una secuencia de instrucciones
"nop".
"-fm2-lower-ca
se"
muestra las palabras clave en los mensajes de error en
minúsculas.
"-fm2-pathnam
e="
especifica el nombre de prefijo del módulo ofuscado para todos los módulos en las siguientes rutas de
inclusión.
"-fm2-pathnam
eI"
solo para uso interno: usado por el controlador para copiar la opción -I dirigida al
usuario.
"-fm2-plugi
n"
inserta un complemento para identificar errores en tiempo de ejecución en tiempo de compilación (activado por
defecto).
"-fm2-prefix
="
especifica el nombre de prefijo del módulo ofuscado. Todos los símbolos exportados de un módulo de definición tendrán el nombre de
prefijo.
"-fm2-statisti
cs"
genera información de cuádruplas: número de cuádruplas generadas, número de cuádruplas restantes después de la optimización y número de líneas de código fuente
compiladas.
"-fm2-strict-ty
pe"
indicador experimental para activar el nuevo verificador de tipos
estricto. t>"-fm2-whole-program"
compila todos los módulos de implementación y el módulo del programa a la vez. Ten en cuenta que debes tener cuidado si estás compilando módulos de diferentes dialectos (particularmente con los operandos negativos para el módulo). Pero esta opción, cuando se combina con "-O3", puede producir enormes mejoras de
rendimiento.
"-fmod
="
reconoce el sufijo especificado como nombres de archivo de implementación y de módulo. El sufijo predeterminado para los nombres de archivo de implementación y de módulo es .mod. Si se usa esta opción, GNU Modula-2 seguirá recurriendo a este predeterminado si necesita leer un módulo de implementación y el nombre de archivo con el sufijo especificado no
existe.
"-fni
l"
genera código para detectar el acceso a datos a través de un puntero con valor "NIL". La comprobación de desreferenciación a través de un puntero "NIL" puede desactivarse con -fno-ni
l.
"-fpi
m"
activa las características del estándar PIM. Actualmente esto habilita el módulo "SYSTEM" de PIM y determina qué identificadores son pervasivos (declarados en el módulo base). Si no se usa ninguna otra opción -fpim[234], entonces los operadores de división y módulo se comportan como se define en
PIM4.
"-fpim
2"
activa las características del estándar PIM-2. Actualmente esto elimina "SIZE" de ser un identificador pervasivo (declarado en el módulo base). Coloca "SIZE" en el módulo "SYSTEM". También afecta el comportamiento de los operadores "DIV" y "MOD"
.
"-fpim
3"
activa las características del estándar PIM-3. Actualmente esto solo afecta el comportamiento de los operadores "DIV" y "MOD"
.
"-fpim
4"
activa las características del estándar PIM-4. Actualmente esto solo afecta el comportamiento de los operadores "DIV" y "MOD"
.
"-fpositive-mod-floor-d
iv"
fuerza a que los operadores "DIV" y "MOD" se comporten como lo define PIM4. Todos los resultados del módulo son positivos y los resultados de la división se redondean hacia abajo (al piso)
.
"-fpthrea
d"
enlaza con la biblioteca pthread. Por defecto, esta opción está activada. Puede desactivarse con -fno-pthread. GNU Modula-2 usa las bibliotecas pthread de GCC para implementar corutinas (véase el módulo de implementación SYSTEM)
.
"-frang
e"
genera código para comprobar el rango de asignación, el rango del valor de retorno, el rango de establecimiento y el rango del constructor. La comprobación de rangos puede desactivarse mediante -fno-rang
e.
"-fretur
n"
genera código para comprobar que las funciones siempre salen con un "RETURN" y no caen fuera al final. La comprobación de retorno puede desactivarse mediante -fno-retur
n.
"-fruntime-module
s="
especifica, mediante una lista separada por comas, los módulos de tiempo de ejecución y su orden. Estos módulos se inicializarán primero antes que cualquier otro módulo en la dependencia de la aplicación. Por defecto, la lista de módulos de tiempo de ejecución está configurada en "m2iso:RTentity,m2iso:Storage,m2iso:SYSTEM," "m2iso:M2RTS,m2iso:RTExceptions,m2iso:IOLink". Ten en cuenta que estos módulos solo se enlazarán en tu ejecutable si son necesarios. Añadir una lista larga de módulos dependientes no afectará al tamaño del ejecutable, simplemente establece el orden de inicialización en caso de que sean
necesarios.
"-fscaffold-dynam
ic"
la opción asegura que gm2 generará una infraestructura de andamiaje dinámico al compilar módulos de implementación y de programa. Por defecto, esta opción está activada. Usa -fno-scaffold-dynamic para desactivarla o selecciona -fno-scaffold-
static.
"-fscaffold-
c"
genera un andamiaje de código fuente en C para el módulo actual que se está
compilando.
"-fscaffold-c
++"
genera un andamiaje de código fuente en C++ para el módulo actual que se está
compilando.
"-fscaffold-ma
in"
fuerza la generación de la función main. Esto no es necesario si se omite -c
.
"-fscaffold-stat
ic"
la opción asegura que gm2 generará un andamiaje estático dentro del módulo del programa. El andamiaje estático consiste en secuencias de llamadas a todos los procedimientos de inicialización y finalización de los módulos dependientes. El andamiaje estático es útil para la depuración y la ejecución paso a paso de los bloques de inicialización de los módulos de
implementación.
"-fshare
d"
genera una biblioteca compartida a partir del
módulo.
"-fsoft-check-a
ll"
activa todas las comprobaciones en tiempo de ejecución. Esto es lo mismo que invocar GNU Modula-2 usando las opciones de comando "-fnil" "-frange" "-findex" "-fwholevalue" "-fwholediv" "-fcase" "-freturn
".
"-fsource
s"
muestra la ruta al código fuente de cada módulo. Esta opción puede usarse en tiempo de compilación para comprobar que se está usando el módulo de definición
correcto.
"-fswi
g"
genera un archivo de interfaz
swig.
"-funbounded-by-referen
ce"
habilita la optimización de parámetros de longitud no acotada al intentar pasar parámetros de longitud no acotada no "VAR" por referencia. Esta optimización evita la copia implícita dentro del procedimiento invocado. GNU Modula-2 solo permitirá que los parámetros de longitud no acotada se pasen por referencia si, dentro del procedimiento invocado, no se escriben en ellos, no se calcula ninguna dirección en la matriz y no se pasa como un parámetro "VAR". Ten en cuenta que es posible escribir código que rompa esta optimización, por lo que esta opción debe usarse con cuidado. Por ejemplo, sería posible tomar la dirección de una matriz, pasar la dirección y la matriz a un procedimiento, leer de la matriz en el procedimiento y escribir en la ubicación usando el parámetro de dirección.

Debido a la naturaleza peligrosa de esta opción, no se habilita cuando se especifica la opción -O

.
"-fuse-list=filenam
e"
si -fscaffold-static está habilitado, entonces usa el archivo filename para el orden de inicialización de los módulos. Mientras que si -fscaffold-dynamic está habilitado, entonces usa este archivo para forzar el enlazado de todos los ctors de los módulos. Esta opción no puede usarse si -fgen-module-list= está
habilitada.
"-fwholedi
v"
genera código para detectar la división de números enteros por cero o el módulo por
cero.
"-fwholevalu
e"
genera código para detectar el desbordamiento y el subdesbordamiento de números
enteros.
"-Wcase-enu
m"
genera una advertencia si una sentencia "CASE" selecciona una expresión de tipo enumerado y a la sentencia le falta una o más etiquetas "CASE". No se emite ninguna advertencia si la sentencia "CASE" tiene una cláusula "ELSE" por defecto. La opción -Wall activará esta
marca.
"-Wuninit-variable-checki
ng"
emite una advertencia si una variable se usa antes de ser inicializada. La comprobación solo ocurre en el primer bloque básico de cada procedimiento. No comprueba parámetros, tipos de matriz ni tipos de
conjunto.
"-Wuninit-variable-checking=all,known,
cond"
emite una advertencia si una variable se usa antes de ser inicializada. La comprobación solo ocurrirá en el primer bloque básico de cada procedimiento si se especifica known. Si se especifica cond o all, entonces la comprobación continúa en las ramas condicionales del grafo de flujo. Toda comprobación se detendrá cuando se invoque una llamada a un procedimiento o se encuentre el inicio de un bucle. La opción -Wall activará esta marca con -Wuninit-variable-checking=known. La -Wuninit-variable-checking
=all aumentará
el tiempo de
compilación.
