DESCRIPCIÓ

N

goaccess GoAccess es un analizador de registros web en tiempo real de código abierto y visor interactivo que se ejecuta en un terminal en sistemas *nix o a través de tu navegador

.

Proporciona estadísticas HTTP rápidas y valiosas para administradores de sistemas que requieren un informe visual del servidor al

instante.

GoAccess analiza el archivo de registro web especificado y emite los datos a la terminal X. Las características

incluyen:
Estadísticas
generales:
Este panel proporciona un resumen de varias métricas, como el número de solicitudes válidas e inválidas, el tiempo empleado en analizar el conjunto de datos, visitantes únicos, archivos solicitados, archivos estáticos (CSS, ICO, JPG, etc.) referentes HTTP, 404, tamaño del archivo de registro analizado y consumo de ancho de
banda.
Visitantes
únicos
Este panel muestra métricas como aciertos, visitantes únicos y ancho de banda acumulado por fecha. Las solicitudes HTTP que contienen la misma IP, la misma fecha y el mismo agente de usuario se consideran un visitante único. Por defecto, incluye rastreadores/arañas
web.
Opcionalmente, la especificidad de la fecha se puede establecer al nivel de la hora usando --date-spec=hr lo que mostrará fechas como 05/Jun/2016:16, o al nivel del minuto produciendo 05/Jun/2016:16:59. Esto es ideal si deseas rastrear tu tráfico diario a nivel de hora o
minuto.
Archivos
solicitados
Este panel muestra los archivos (no estáticos) más solicitados en tu servidor web. Muestra aciertos, visitantes únicos y porcentaje, junto con el ancho de banda acumulado, el protocolo y el método de solicitud
utilizado.
Archivos estáticos
solicitados
Lista los archivos estáticos más frecuentes como: tipos de archivo JPG, CSS, SWF, JS, GIF y PNG, junto con las mismas métricas que el panel anterior. Se pueden agregar archivos estáticos adicionales al archivo de

--ws-auth=<jwt[:secret]> | jwt:verify:secret
Habilita la autenticación WebSocket utilizando un JSON Web Token (JWT). Esta opción admite dos formatos dependiendo de si el JWT se genera localmente o se recupera y verifica externamente:
<jwt[:secret]>: Especifica un JWT estático para la autenticación WebSocket, con un secreto opcional para generación o validación local. Si solo se proporciona "jwt" (por ejemplo, --ws-auth=jwt), GoAccess genera un JWT utilizando un secreto obtenido de la variable de entorno GOACCESS_WSAUTH_SECRET o un secreto compatible con HS256 por defecto si no está establecido. Si se incluye un secreto (por ejemplo, --ws-auth=jwt:mysecret), se utiliza directamente como clave de firma HS256 o se lee de un archivo si el valor es una ruta válida (por ejemplo, --ws-auth=jwt:/path/to/secret.key).
jwt:verify:secret: Habilita la verificación de un JWT recuperado externamente (por ejemplo, a través de --ws-auth-url). La palabra clave "verify" indica que el JWT es proporcionado por una fuente externa, y el secreto debe especificarse para su validación. El secreto puede ser una clave HS256 directa (por ejemplo, --ws-auth=jwt:verify:mysecret), una ruta de archivo (por ejemplo, --ws-auth=jwt:verify:/path/to/secret.key), o un nombre de variable de entorno (por ejemplo, --ws-auth=jwt:verify:$JWT_SECRET). Este formato es necesario cuando se utiliza --ws-auth-url y opcionalmente --ws-auth-refresh-url para obtener y verificar JWTs desde puntos finales externos.
Cuando se utiliza esta opción, el informe HTML no iniciará los datos analizados iniciales. En su lugar, solo mostrará el informe si la autenticación tiene éxito, garantizando un acceso seguro a los datos en tiempo real.
El sistema procesa esta opción de la siguiente manera:
Para <jwt[:secret]>: Si no se proporciona ningún secreto, GoAccess genera un JWT localmente utilizando la variable de entorno GOACCESS_WSAUTH_SECRET o un secreto por defecto. Si se especifica un secreto, se utiliza para firmar el JWT (directamente o desde un archivo).
Para jwt:verify:secret: El secreto es obligatorio y se utiliza para verificar JWTs obtenidos externamente. Debe coincidir con la clave de firma utilizada por el servidor de autenticación externo (por ejemplo, en --ws-auth-url).
Requiere compilar GoAccess con --with-openssl.
--ws-auth-expire=<secs>
Establece el tiempo después del cual expira el JWT. Por defecto es 8 horas (28800 segundos) si no se especifica.
Solo disponible para JWT generados localmente.
Los usuarios pueden especificar el tiempo de expiración en varios formatos. El valor se convierte a segundos para la validación de la expiración del JWT. Formatos admitidos:
  • "3600" -> 3600 segundos
  • "120s" -> 2 minutos
  • "24h" -> 24 horas = 86,400 segundos
  • "10m" -> 10 minutos = 600 segundos
  • "10d" -> 10 días = 864,000 segundos
El tiempo de expiración controla cuánto tiempo el JWT permanece válido después de su emisión, asegurando conexiones WebSocket seguras.
--ws-auth-url=<url>
Especifica la URL desde donde GoAccess recupera el JWT inicial para autenticar la conexión WebSocket.
Cuando se utiliza esta opción, GoAccess envía una solicitud GET a la URL especificada para obtener un JWT inicial. La respuesta debe ser un objeto JSON que contenga los campos status, access_token, refresh_token y expires_in.
Ejemplo: --ws-auth-url=https://site.com/api/get-auth-token
Al obtener el token, GoAccess utiliza { credentials: 'include' } como parte de la solicitud para recuperar de forma segura el token de acceso basándose en la sesión de autenticación existente del usuario en tu sistema, garantizando que la recuperación del token sea segura siempre que tus usuarios estén autenticados.
Esta opción te permite integrar tu sistema de autenticación existente con el panel de control de GoAccess, utilizando puntos finales de recuperación de tokens.
--ws-auth-refresh-url=<url>
Especifica la URL desde donde GoAccess recupera un nuevo JWT cuando el actual está a punto de expirar.
GoAccess refresca proactivamente el JWT 60 segundos antes de la expiración enviando una solicitud POST con el `refresh_token` a esta URL. Si no se proporciona, por defecto utiliza la misma URL que --ws-auth-url.
Ejemplo: --ws-auth-refresh-url=https://site.com/api/refresh-token
El formato de la respuesta debe coincidir con el de la URL de autenticación inicial.

WebSocket Authentication Flow

GoAccess ofrece opciones de autenticación flexibles, compatibles con enfoques sin estado (stateless) y con estado (stateful). En el enfoque sin estado, el token de refresco se obtiene sin cookies ni protección CSRF; tu backend valida la firma del token de refresco y emite un nuevo token de acceso. Alternativamente, el enfoque con estado permite que la obtención inicial emita JWTs junto con un `csrf_token`, que se almacena en la sesión. La solicitud de refresco posterior (POST) realiza entonces una verificación CSRF, requiriendo que la cabecera `X-CSRF-TOKEN` coincida con el token de la sesión.
Autenticación Inicial:
  • Cuando se inicia con --ws-auth-url=<url>, GoAccess envía una solicitud GET para obtener un JWT inicial.

"refresh_token" : "refresh123xyz",

REAL-TIME HTML

To enable the WebSocket server to generate a real time HTML report, you can use the --real-time-html flag:

# goaccess access.log -o report.html --real-time-html

By default, the WebSocket server listens on port 7878 and binds to the address 0.0.0.0. You can specify a different port with the --port parameter:

# goaccess access.log -o report.html --real-time-html --port=9870

And to bind the WebSocket server to a different address other than 0.0.0.0, you can specify it as:

# goaccess access.log -o report.html --real-time-html --addr=127.0.0.1

Nota: Para emitir datos en tiempo real a través de una conexión TLS/SSL, necesita usar --ssl-cert=<cert.crt> y --ssl-key=<priv.key>.

TRABAJAR CON FECHAS

Otra tubería útil sería filtrar fechas del registro web

Lo siguiente obtendrá todas las solicitudes HTTP que comiencen el 05/Dec/2010 hasta el final del archivo.

# sed -n '/05Dec2010/,$ p' access.log | goaccess -a -

o usando fechas relativas como el día de ayer o mañana:

# sed -n '/'$(date '+%d%b%Y' -d '1 week ago')'/,$ p' access.log | goaccess -a -

Si queremos analizar solo un marco de tiempo específico desde FECHA a hasta FECHA b, podemos hacerlo:

# sed -n '/5Nov2010/,/5Dec2010/ p' access.log | goaccess -a -

Si queremos conservar solo una cierta cantidad de datos y reciclar almacenamiento, podemos mantener solo un cierto número de días. Por ejemplo, para mantener y mostrar los últimos 5 días:

# goaccess access.log --keep-last=5

HOSTS VIRTUALES

Suponiendo que su registro contiene el campo de host virtual (bloques de servidor). Por ejemplo:

vhost.com:80 10.131.40.139 - - [02/Mar/2016:08:14:04 -0600] "GET /shop/bag-p-20 HTTP/1.1" 200 6715 "-" "Apache (internal dummy connection)"

Y le gustaría agregar el host virtual a la solicitud para ver a qué host virtual pertenecen las principales URL.

awk '$8=$1$8' access.log | goaccess -a -

Para excluir una lista de hosts virtuales, puede hacer lo siguiente:

# grep -v "`cat exclude_vhost_list_file`" vhost_access.log | goaccess -

ARCHIVOS & CÓDIGOS DE ESTADO

Para analizar páginas específicas, por ejemplo, vistas de página, html, htm, php, etc. dentro de una solicitud:

# awk '$7~/.html|.htm|.php/' access.log | goaccess -

Nota, $7 es el campo de solicitud para el formato de registro común y combinado (sin Host Virtual), si su registro incluye Host Virtual, entonces probablemente querrá usar $8 en su lugar. Es mejor verificar qué campo está buscando, por ejemplo:

# tail -10 access.log | awk '{print $8}'

O para analizar un código de estado específico, por ejemplo, 500 (Error interno del servidor):

# awk '$9~/500/' access.log | goaccess -

SERVIDOR

Además, vale la pena señalar que si queremos ejecutar GoAccess con una prioridad más baja, podemos hacerlo así:

# nice -n 19 goaccess -f access.log -a

y si no quieres instalarlo en tu servidor, todavía puedes ejecutarlo desde tu máquina local:

# ssh -n root@server 'tail -f /var/log/apache2/access.log' | goaccess -

Nota: SSH requiere -n para que GoAccess pueda leer desde stdin. Además, asegúrese de usar claves SSH para la autenticación, ya que no funcionará si se requiere una frase de contraseña.

PROCESAMIENTO INCREMENTAL DE REGISTROS

GoAccess tiene la capacidad de procesar registros incrementalmente a través de su almacenamiento interno y volcar sus datos en disco. Funciona de la siguiente manera:

1
Un conjunto de datos debe persistir primero con --persist, luego el mismo conjunto de datos se puede cargar con
2
--restore. Si se pasan nuevos datos (a través de tuberías o de un archivo de registro), se agregarán al conjunto de datos original.

NOTAS

GoAccess rastrea los inodos de todos los archivos procesados (suponiendo que los archivos permanecerán en la misma partición), además, extrae un fragmento de datos del registro junto con la última línea analizada de cada archivo y la marca de tiempo de la última línea analizada. por ejemplo, inode:29627417|line:20012|ts:20171231235059

Primero compara si el fragmento coincide con el registro que se está analizando, si lo hace, asume que el registro no ha cambiado dramáticamente, por ejemplo, no ha sido truncado. Si el inodo no coincide con el archivo actual, analiza todas las líneas. Si el archivo actual coincide con el inodo, entonces lee las líneas restantes y actualiza el recuento de líneas analizadas y la marca de tiempo. Como precaución adicional, no analizará las líneas de registro con una marca de tiempo ≤ que la almacenada.

Los datos enviados por tubería funcionan en función de la marca de tiempo de la última línea leída. Por ejemplo, analizará y descartará todas las entradas entrantes hasta que encuentre una marca de tiempo >= que la almacenada.

Por ejemplo:

// registro de acceso del mes pasado
# goaccess access.log.1 --persist

luego, cárguelo con

// agregar registro de acceso de este mes y preservar nuevos datos
# goaccess access.log --restore --persist

Para leer solo datos persistentes (sin analizar datos nuevos)

# goaccess --restore

NOTAS

Cada panel activo tiene un total de 366 elementos o 50 en el informe HTML en tiempo real. El número de elementos es personalizable usando max-items. Tenga en cuenta que la salida HTML, CSV y JSON permite un número máximo mayor que el valor predeterminado de 366 elementos por panel.

Un golpe es una solicitud (línea en el archivo de registro de acceso), por ejemplo, 10 solicitudes = 10 golpes. Las solicitudes HTTP con la misma IP, fecha y agente de usuario se consideran una visita única.

Si desea habilitar el soporte de pila dual, use --addr=:: en lugar del valor predeterminado --addr=0.0.0.0.

El informe generado intentará reconectarse al servidor WebSocket después de 1 segundo con retroceso exponencial. Intentará conectarse 20 veces.
