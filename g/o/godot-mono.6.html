NOMBRE

godot - motor de juegos 2D y 3D multiplataforma con un editor rico en características

SINOPSIS

godot [opciones] [ruta a la escena o al archivo 'project.godot']

DESCRIPCIÓN

Godot Engine es un motor de juegos 2D y 3D avanzado, lleno de características y multiplataforma.
Proporciona un conjunto enorme de herramientas comunes, para que puedas centrarte en crear tu juego sin tener que reinventar la rueda.

Opciones generales:

-h, --help
Muestra este mensaje de ayuda.
--version
Muestra la cadena de versión.
-v, --verbose
Usa el modo de salida estándar detallado.
--quiet
Modo silencioso, silencia los mensajes de la salida estándar. Los errores se muestran igualmente.

Opciones de ejecución:

-e, --editor
Inicia el editor en lugar de ejecutar la escena.
-p, --project-manager
Inicia el gestor de proyectos, incluso si se detecta automáticamente un proyecto.
-q, --quit
Sale después de la primera iteración.
-l, --language <locale>
Usa una configuración regional específica (<locale> siendo un código de dos letras).
--path <directory>
Ruta a un proyecto (<directory> debe contener un archivo 'project.godot').
-u, --upwards
Escanea las carpetas hacia arriba en busca del archivo project.godot.
--main-pack <file>
Ruta a un archivo pack (.pck) para cargar.
--render-thread <mode>
Modo del hilo de renderizado ('unsafe', 'safe', 'separate').
--remote-fs <address>
Sistema de archivos remoto (dirección <host/IP>[:<port>]).
--remote-fs-password <password>
Contraseña para el sistema de archivos remoto.
--audio-driver <driver>
Controlador de audio ('PulseAudio', 'ALSA', 'Dummy').
--audio-output-latency <ms>
Anula la latencia de salida de audio en milisegundos (el valor por defecto es 15 ms). Valores más bajos hacen que la reproducción del sonido sea más reactiva, pero aumentan el uso de la CPU y pueden provocar crujidos en el audio si la CPU no puede seguir el ritmo.
--video-driver <driver>
Controlador de vídeo ('Vulkan', 'GLES2').

Opciones de visualización:

-f, --fullscreen
Solicita el modo de pantalla completa.
-m, --maximized
Solicita una ventana maximizada.
-w, --windowed
Solicita el modo de ventana.
-t, --always-on-top
Solicita una ventana siempre visible.
--resolution <W>x<H>
Solicita la resolución de la ventana.
--position <X>,<Y>
Solicita la posición de la ventana.
--low-dpi
Fuerza el modo de baja densidad de píxeles (DPI) (solo en macOS y Windows).
--no-window
Desactiva la creación de ventanas (solo en Windows). Útil junto con --script.

Opciones de depuración:

-d, --debug
Depurar (depurador local de la salida estándar).
-b, --breakpoints
Lista de puntos de interrupción como pares source::line separados por comas, sin espacios (usa %20 en su lugar).
--profiling
Activa el perfilado en el depurador de scripts.
--remote-debug <address>
Depuración remota (dirección <host/IP>:<port>).
--debug-collisions
Muestra las formas de colisión al ejecutar la escena.
--debug-navigation
Muestra los polígonos de navegación al ejecutar la escena.
--max-fps <fps>
Establece un número máximo de fotogramas por segundo para renderizar (se puede usar para limitar el consumo de energía). Un valor de 0 resulta en una tasa de fotogramas ilimitada.
--frame-delay <ms>
Simula una alta carga de la CPU (retrasa cada fotograma en <ms> milisegundos). No lo uses como limitador de FPS; usa --max-fps en su lugar.
--time-scale <scale>
Fuerza la escala de tiempo (valores más altos son más rápidos, 1.0 es velocidad normal).
--disable-render-loop
Desactiva el bucle de renderizado para que el renderizado solo ocurra cuando se llame explícitamente desde un script.
--disable-crash-handler
Desactiva el manejador de fallos cuando la plataforma lo soporta.
--fixed-fps <fps>
Fuerza un número fijo de fotogramas por segundo. Esta configuración desactiva la sincronización en tiempo real.
--print-fps
Imprime los fotogramas por segundo en la salida estándar.

Herramientas independientes:

-s, --script <script>
Ejecuta un script.
--check-only
Solo analiza en busca de errores y sale (usar con --script).
--export-release <preset> <path>
Exporta el proyecto en modo de versión final usando el preset y la ruta de salida dados. El nombre del preset debe coincidir con uno definido en export_presets.cfg.
<path> debe ser absoluto o relativo al directorio del proyecto, e incluir el nombre de archivo para el binario (por ejemplo, 'builds/game.exe').
El directorio de destino debe existir.
--export-debug <preset> <path>
Exporta el proyecto en modo de depuración usando el preset y la ruta de salida dados. El nombre del preset debe coincidir con uno definido en export_presets.cfg.
<path> debe ser absoluto o relativo al directorio del proyecto, e incluir el nombre de archivo para el binario (por ejemplo, 'builds/game.exe').
El directorio de destino debe existir.
--export-pack <preset> <path>
Exporta solo los datos del proyecto usando el preset y la ruta de salida dados. La extensión de <path> determina si estará en formato PCK o ZIP.
--doctool <path>
Vuelca la referencia de la API del motor en el <path> dado en formato XML, fusionando si se encuentran archivos existentes.
--no-docbase
No permite volcar los tipos base (usado con --doctool).
--build-solutions
Compila las soluciones de scripting (por ejemplo, para proyectos C#). Implica --editor y requiere un proyecto válido para editar.
--dump-gdextension-interface
Genera el archivo de cabecera de GDExtension 'gdextension_interface.h' en la carpeta actual. Este archivo es el archivo base requerido para implementar una GDExtension.
--dump-extension-api
Genera un volcado JSON de la API de Godot para los enlaces GDExtension llamado 'extension_api.json' en la carpeta actual.
--test <test>
Ejecuta una prueba unitaria ('string', 'math', 'physics', 'physics_2d', 'render', 'oa_hash_map', 'gui', 'shaderlang', 'gd_tokenizer', 'gd_parser', 'gd_compiler', 'gd_bytecode', 'ordered_hash_map', 'astar').

ARCHIVOS

XDG_DATA_CONFIG/godot/ o ~/.config/godot/

Carpeta de configuración específica del usuario, contiene configuraciones persistentes del editor, plantillas de scripts y editores de texto y metadatos de proyectos.
XDG_DATA_HOME/godot/ o ~/.local/share/godot/
Contiene la configuración predeterminada y las carpetas de datos del usuario para juegos creados por Godot (ruta user://), así como plantillas de exportación.
XDG_DATA_CACHE/godot/ o ~/.cache/godot/
Carpeta de caché para miniaturas generadas y vistas previas de escenas, así como ubicación temporal para descargas.
/usr/share/doc/godot/
Archivos de documentación adicional.
/usr/share/licenses/godot/
Información detallada de licencias.
