NOMBRE

google-authenticator - inicializa contraseñas de un solo uso para el usuario actual

SINOPSIS

google-authenticator [opciones]

Si no se proporciona ninguna opción en la línea de comandos, google-authenticator(1) preguntará interactivamente al usuario por las opciones más importantes.

DESCRIPCIÓN

El comando google-authenticator(1) crea una nueva clave secreta en el directorio de inicio del usuario actual. Por defecto, esta clave secreta y todos los ajustes se almacenarán en ~/.google_authenticator.

Si el sistema admite la biblioteca libqrencode , se mostrará un código QR , que puede escanearse usando la aplicación Android Google Authenticator . Si el sistema no tiene esta biblioteca, google-authenticator(1) genera una URL que puede seguirse usando un navegador web. Alternativamente, la clave secreta alfanumérica también se genera y por lo tanto puede introducirse manualmente en la aplicación Android Google Authenticator.

En cualquier caso, después de que la clave se haya añadido, el valor de verificación debería comprobarse. Para ello, el usuario debe hacer clic y mantener pulsada la entrada añadida en su sistema Android hasta que aparezca el menú contextual. Luego, el usuario comprueba que el valor de verificación de la clave mostrada coincide con el proporcionado por google-authenticator(1). Tenga en cuenta que esta función puede no estar disponible en todas las compilaciones de la aplicación Android.

Cada vez que el usuario inicie sesión en el sistema, se le pedirá el código TOTP (contraseña de un solo uso basada en el tiempo) o HOTP (contraseña de un solo uso basada en el contador), dependiendo de las opciones dadas a google-authenticator(1), después de haber introducido su identificador de usuario normal y su contraseña de cuenta UNIX normal.

OPCIONES

La opción principal consiste en elegir el tipo de token de autenticación: basado en el tiempo o basado en el contador.

-c, --counter-based
Configura la verificación basada en el contador.
-t, --time-based
Configura la verificación basada en el tiempo.

De esta elección dependen las opciones disponibles.

Opciones específicas basadas en el contador

Estos ajustes solo son relevantes para las contraseñas de un solo uso basadas en el contador (HOTP):

-w, --window-size=W
Establece la ventana de códigos válidos simultáneamente.

Por defecto, tres tokens son válidos en cualquier momento. Esto tiene en cuenta los tokens generados pero no utilizados y los intentos de inicio de sesión fallidos. Para disminuir la probabilidad de problemas de sincronización, esta ventana puede aumentarse desde su tamaño predeterminado de 3.

El tamaño de la ventana debe estar entre 1 y 21.

-W, --minimal-window
Desactiva la ventana de códigos válidos simultáneamente.

Opciones específicas basadas en el tiempo

Estos ajustes solo son relevantes para las contraseñas de un solo uso basadas en el tiempo (TOTP):

-D, --allow-reuse, -d, --disallow-reuse
(Des)Permite el uso múltiple del mismo token de autenticación.

Esto restringe al usuario a un inicio de sesión aproximadamente cada 30 segundos, pero aumenta las posibilidades de detectar o incluso prevenir ataques de intermediario (man-in-the-middle).

-w, --window-size=W
Establece la ventana de códigos válidos simultáneamente.

Por defecto, la aplicación móvil genera un nuevo token cada 30 segundos. Para compensar una posible diferencia de tiempo entre el cliente y el servidor, se permite un token extra antes y después de la hora actual. Esto permite una diferencia de tiempo de hasta 30 segundos entre el servidor de autenticación y el cliente.

Por ejemplo, si se experimentan problemas con una mala sincronización de tiempo, la ventana puede aumentarse desde su tamaño predeterminado de 3 códigos permitidos (un código anterior, el código actual, el siguiente código) a 17 códigos permitidos (los 8 códigos anteriores, el código actual y los 8 códigos siguientes). Esto permitirá una diferencia de tiempo de hasta 4 minutos entre el cliente y el servidor.

El tamaño de la ventana debe estar entre 1 y 21.

-W, --minimal-window
Desactiva la ventana de códigos válidos simultáneamente.
-S, --step-size=S
Establece el intervalo entre actualizaciones de token en S segundos.

Por defecto, los tokens basados en el tiempo se generan cada 30 segundos. Se puede configurar un valor no estándar en caso de que deba usarse un valor de intervalo de tiempo diferente.

El intervalo de tiempo debe estar entre 1 y 60 segundos.

Opciones generales

-s, --secret=ARCHIVO
Especifica una ubicación de archivo no estándar para la clave secreta y los ajustes.
-f, --force
Escribe la clave secreta y los ajustes sin confirmar primero con el usuario.
-l, --label=ETIQUETA
Anula la etiqueta predeterminada en la URL otpauth:// .
-i, --issuer=EMISOR
Anula el emisor predeterminado en la URL otpauth:// .
-Q, --qr-mode=none|ansi|utf8
Modo de salida del código QR.

Suprime la salida del código QR (none), o genera el código QR usando colores ANSI (ansi), o elementos de bloque Unicode (utf8).

Los elementos de bloque Unicode hacen que el código QR sea mucho más pequeño, lo que a menudo es más fácil de escanear. Desafortunadamente, muchos emuladores de terminal no muestran estos caracteres Unicode correctamente.

-r, --rate-limit=N, -R, --rate-time=M, -u, --no-rate-limit
Desactiva la limitación de tasa, o limita los inicios de sesión a N por cada M segundos.

Si el sistema no está protegido contra intentos de inicio de sesión por fuerza bruta, se puede habilitar la limitación de tasa para el módulo de autenticación: no más de N intentos de inicio de sesión cada M segundos.

El límite de tasa debe estar entre 1 y 10 intentos. El tiempo de tasa debe estar entre 15 y 600 segundos.

-e, --emergency-codes=N
Genera N códigos de emergencia.

Se pueden generar un máximo de 10 códigos de emergencia.

-q, --quiet
Modo silencioso.
-h, --help
Imprime el mensaje de ayuda.
