NOMBRE

gdal-vector-index - Crear un índice vectorial de conjuntos de datos vectoriales

Añadido en la versión 3.12.

SINÓPSIS

Las siguientes opciones están disponibles:

Opciones estándar

-f, --of, --format, --output-format <FORMATO-SALIDA>
Qué formato vectorial de salida usar. Los valores permitidos pueden obtenerse con gdal --formats | grep vector | grep rw | sort
--co <NOMBRE>=<VALOR>
Muchos formatos tienen una o más opciones de creación opcionales que se pueden utilizar para controlar detalles sobre el archivo creado. Por ejemplo, el controlador GeoTIFF soporta opciones de creación para controlar la compresión y si el archivo debe estar en teselas.

Puede repetirse.

Las opciones de creación disponibles varían según el controlador de formato, y algunos formatos simples no tienen opciones de creación en absoluto. Una lista de opciones soportadas para un formato se puede listar con la opción de línea de comandos --formats, pero la documentación del formato es la fuente definitiva de información sobre las opciones de creación del controlador. Consulte la documentación específica del formato de Controladores ráster para conocer las opciones de creación válidas para cada formato.

-lco <NOMBRE>=<VALOR>
Opción de creación de capa (específica del formato)
--overwrite
Permite al programa sobrescribir el archivo o conjunto de datos de destino existente. De lo contrario, por defecto, gdal genera un error si el archivo o conjunto de datos de destino ya existe.
--update
Si el conjunto de datos de salida debe abrirse en modo de actualización. Implica que ya existe.
--overwrite-layer
Si se permite sobrescribir la capa vectorial de salida existente.
--append
Si se permite añadir entidades a la capa vectorial de salida existente.
-l, --nln, --layer <CAPA>
Proporciona un nombre para la capa vectorial de salida.
--recursive
Si los directorios de entrada deben explorarse recursivamente.
--filename-filter <FILTRO-NOMBRE-ARCHIVO>
Patrón que deben seguir los nombres de archivo contenidos en los directorios de entrada. '*' es un carácter comodín que coincide con cualquier número de cualquier carácter, incluido ninguno. '?' es un carácter comodín que coincide con un solo carácter. Las comparaciones se realizan sin distinguir mayúsculas y minúsculas. Se pueden especificar varios filtros.

Por ejemplo: --filename-filter "*.shp,*.gpkg"

--location-name <NOMBRE-UBICACION>
El nombre del campo de salida para mantener la ruta/ubicación del archivo a los vectores indexados. El nombre de campo por defecto es location.
--absolute-path
La ruta absoluta a los archivos vectoriales se almacena en el archivo de índice. Por defecto, los nombres de archivo de los vectores se incluirán en el archivo exactamente como se especifican en la línea de comandos.
--dst-crs <DST-CRS>
Los sobres de los archivos de entrada se transformarán al sistema de referencia de coordenadas de destino deseado. Por defecto, se crean polígonos rectangulares simples en el mismo sistema de referencia de coordenadas que los vectores de entrada.
--source-crs-field-name <NOMBRE-CAMPO-CRS-ORIGEN>
El nombre del campo para almacenar el CRS de cada tesela. Este nombre de campo puede usarse como el valor de la palabra clave TILESRS en MapServer
--source-crs-format auto|WKT|EPSG|PROJ
El formato en el que debe escribirse el CRS de cada tesela. Los tipos pueden ser auto, WKT, EPSG, PROJ. Esta opción debe usarse junto con --source-crs-field-name.
--source-layer-name <NOMBRE-CAPA-ORIGEN>
Añadir capa del nombre especificado de cada archivo de origen en el índice de teselas. Puede repetirse.
--source-layer-index <INDICE-CAPA-ORIGEN>
Añadir capa del índice especificado (base 0) de cada archivo de origen en el índice de teselas. Puede repetirse.
--accept-different-crs
Si se aceptan capas con CRS diferentes. Por defecto, el programa emitirá un error si detecta capas con CRS diferentes.
--accept-different-schemas
Si se aceptan capas con esquemas diferentes. Por defecto, el programa emitirá un error si detecta capas con esquemas diferentes.
--dataset-name-only
Si se debe escribir solo el nombre del conjunto de datos, en lugar de sufijar el nombre del archivo con el índice de la capa dentro del conjunto de datos. Esto es útil si solo hay una capa por archivo.

EJEMPLO

Crear un índice de teselas para todos los archivos shapefile en un directorio:

gdal vector index -recursive -filename-filter "*.shp" *.shp my_tileindex.shp
NOMBRE-DE-CAPA>
Añade una capa con el nombre especificado desde cada archivo de origen en el índice de teselas [puede repetirse] Si ninguno de
--source-layer-index <ÍNDICE-DE-CAPA-DE-ORIGEN>
Añade una capa con el índice especificado (basado en 0) desde cada archivo de origen en el índice de teselas [puede repetirse]
--metadata <CLAVE>=<VALOR>
Escribe un elemento de metadatos de capa arbitrario, para formatos que admitan metadatos de capa. Esta opción puede repetirse.
--accept-different-crs
Si se aceptan capas con CRS diferentes. De forma predeterminada, a menos que --dst-crs esté especificado, las capas que no tengan el mismo CRS que la primera capa del índice serán omitidas. Establecer --accept-different-crs puede ser útil para evitar la comprobación de consistencia del CRS.
--accept-different-schemas
Si se aceptan capas con esquemas diferentes. De forma predeterminada, las capas que no tengan el mismo esquema que la primera capa del índice serán omitidas.
--dataset-name-only
Si se escribe solo el nombre del conjunto de datos, en lugar de con el sufijo del índice de la capa.

ADVERTENCIA:

Establecer esta opción generará una ubicación no compatible con MapServer.

Opciones avanzadas

--oo <NOMBRE>=<VALOR>
Opción de apertura del conjunto de datos (específica del formato).

Puede repetirse.

--if <formato>
Nombre del formato/controlador que se intentará utilizar para abrir el archivo(s) de entrada. Generalmente no es necesario especificarlo, pero puede usarse para omitir la detección automática del controlador, cuando falla en seleccionar el controlador apropiado. Esta opción puede repetirse varias veces para especificar varios controladores candidatos. Nótese que no fuerza a esos controladores a abrir el conjunto de datos. En particular, algunos controladores tienen requisitos sobre las extensiones de archivo.

Puede repetirse.

EJEMPLOS

Ejemplo 1

Producir un GeoPackage con un registro por cada capa que la utilidad encontró en la carpeta countries . Cada registro contiene información que apunta a la ubicación de la imagen y también una forma de rectángulo delimitador que muestra los límites de la imagen:

gdal vector index countries/*.shp index.gpkg

Ejemplo 2

La opción --dst-crs también puede usarse para transformar todos los envolventes vectoriales de entrada a la misma proyección de salida:

gdal vector index --dst-crs EPSG:4326 --source-crs-field-name=src_srs countries/*.shp index.gpkg
