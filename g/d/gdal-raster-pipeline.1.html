NOMBRE

gdal-raster-pipeline - Procesa un conjunto de datos ráster aplicando varios pasos

Añadido en la versión 3.11.

DESCRIPCIÓN

gdal raster pipeline se puede utilizar para procesar un conjunto de datos ráster y realizar varios pasos de procesamiento que aceptan ráster y generan ráster.

Para canalizaciones que mezclan ráster y vector, consulte gdal pipeline.

La mayoría de los pasos proceden mediante la evaluación bajo demanda de bloques ráster, a menos que se indique lo contrario en su documentación, sin "materializar" el conjunto de datos resultante de cada paso. A veces, por motivos de rendimiento, puede ser deseable materializar un conjunto de datos intermedio en disco utilizando gdal raster materialize.

SINOPSIS

Uso: gdal raster pipeline [OPCIONES] <PIPELINE>
Procesa un conjunto de datos ráster aplicando varios pasos.
Argumentos posicionales:
Opciones comunes:
  -h, --help              Muestra el mensaje de ayuda y sale
  --json-usage            Muestra el uso como un documento JSON y sale
  --config <CLAVE>=<VALOR>  Opción de configuración [puede repetirse]
  -q, --quiet             Modo silencioso (sin barra de progreso)
<PIPELINE> tiene la forma: read|mosaic|stack [OPCIONES-LECTURA] ( ! <NOMBRE-PASO> [OPCIONES-PASO] )* ! info|compare|tile|write [OPCIONES-ESCRITURA]

Una canalización encadena varios pasos, separados por el carácter ! (signo de exclamación). El primer paso debe ser read, calc, mosaic o stack, y el último write, info o tile. Cada paso tiene sus propios argumentos posicionales o no posicionales. Aparte de read, calc, mosaic, stack, compare, info, tile y write, todos los demás pasos pueden usarse varias veces en una canalización.

Los pasos potenciales son:

read
* read [OPCIONES] <ENTRADA>
------------------------
Lee un conjunto de datos ráster.
Argumentos posicionales:
  -i, --input <ENTRADA>                  Conjuntos de datos ráster de entrada [obligatorio]
Opciones avanzadas:
  --if, --input-format <FORMATO-ENTRADA>  Formatos de entrada [puede repetirse]
  --oo, --open-option <CLAVE>=<VALOR>    Opciones de apertura [puede repetirse]
•
calc
* calc [OPCIONES] <ENTRADAS>...
----------------------------
Realiza álgebra ráster
Argumentos posicionales:
  -i, --input <ENTRADAS>                                     Conjuntos de datos ráster de entrada [1.. valores] [obligatorio]
Opciones:
  --ot, --datatype, --output-data-type <TIPO-DATOS-SALIDA>  Tipo de datos de salida. TIPO-DATOS-SALIDA=Byte|Int8|UInt16|Int16|UInt32|Int32|UInt64|Int64|CInt16|CInt32|Float16|Float32|Float64|CFloat32|CFloat64
  --no-check-srs                                           No comprobar la coherencia de los sistemas de referencia espacial de entrada
  --no-check-extent                                        No comprobar la coherencia de las extensiones de entrada
  --propagate-nodata                                       Si se deben establecer píxeles con el valor NoData de salida si alguno de los píxeles de entrada es NoData
  --calc <CALC>                                            Expresión(es) a evaluar [1.. valores] [obligatorio]
  --dialect <DIALECTO>                                      Dialecto de la expresión. DIALECTO=muparser|builtin (predeterminado: muparser)
  --flatten                                                Genera un único ráster de salida por banda por expresión, incluso si los conjuntos de datos de entrada son multibanda
  --nodata <NODATA>                                        Asigna un valor nodata especificado a las bandas de salida ('none', valor numérico, 'nan', 'inf', '-inf')
Opciones avanzadas:
  --if, --input-format <FORMATO-ENTRADA>                      Formatos de entrada [puede repetirse]
  --oo, --open-option <CLAVE>=<VALOR>                        Opciones de apertura [puede repetirse]

Los detalles de las opciones se pueden encontrar en gdal raster calc.

mosaic
* mosaic [OPCIONES] <ENTRADA>...
-----------------------------
Construye un mosaico, ya sea virtual (VRT) o materializado.
Argumentos posicionales:
  -i, --input <ENTRADA>                                             Conjuntos de datos ráster de entrada (o especifica @<nombrearchivo> para apuntar a un archivo que contenga nombres de archivo) [1.. valores] [obligatorio]
Opciones:
  -b, --band <BANDA>                                               Banda(s) de entrada (índice basado en 1) [puede repetirse]
  --absolute-path                                                 Si la ruta a los conjuntos de datos de entrada debe almacenarse como una ruta absoluta
  --resolution <xres>,<yres>|same|average|common|highest|lowest>  Resolución objetivo (en unidades de la CRS de destino) (predeterminado: same)
  --bbox <BBOX>                                                   Caja delimitadora objetivo como xmin,ymin,xmax,ymax (en unidades de la CRS de destino)
  --target-aligned-pixels                                         Redondea la extensión objetivo a la resolución objetivo
  --src-nodata <SRC-NODATA>                                       Establece valores nodata para las bandas de entrada. [1.. valores]
  --dst-nodata <DST-NODATA>                                       Establece valores nodata en el nivel de banda de destino. [1.. valores]
  --hide-nodata                                                   Hace que la banda de destino no informe del NoData.
  --add-alpha                                                     Añade una banda de máscara alfa al destino cuando el ráster de origen no tiene ninguna.
  --pixel-function <FUNCION-PIXEL>                                Especifica una función de píxel para calcular el valor de salida a partir de entradas superpuestas. FUNCION-PIXEL=argmax|argmin|cmul|complex|conj|dB|dB2amp|dB2pow|diff|div|exp|expression|geometric_mean|harmonic_mean|imag|intensity|interpolate_exp|interpolate_linear|inv|log10|max|mean|median|min|mod|mode|mul|norm_diff|phase|polar|pow|real|reclassify|replace_nodata|scale|sqrt|sum
  --pixel-function-arg <NOMBRE>=<VALOR>                             Especifica argumento(s) para pasar a la función de píxel [puede repetirse]
Opciones avanzadas:
  --if, --input-format <FORMATO-ENTRADA>                             Formatos de entrada [puede repetirse]
  --oo, --open-option <CLAVE>=<VALOR>                               Opciones de apertura [puede repetirse]

fill-nodata
* fill-nodata [OPTIONS]
-----------------------
Rellenar regiones ráster sin datos mediante interpolación desde los bordes.
Opciones:
  -b, --band <BAND>                                  Banda de entrada (índice basado en 1) (predeterminado: 1)
  -d, --max-distance <MAX_DISTANCE>                  La distancia máxima (en píxeles) que el algoritmo buscará valores para interpolar. (predeterminado: 100)

  --strategy <STRATEGY>                              Por defecto, los píxeles se interpolan usando una ponderación por distancia inversa (invdist). También es posible elegir una estrategia de vecino más cercano (nearest).. STRATEGY=invdist|nearest (predeterminado: invdist)

GDALG OUTPUT (CONJUNTO DE DATOS EN TIEMPO REAL / EN FLUJO)

Una canalización se puede serializar como un archivo JSON usando el GDALG formato de salida. El archivo resultante se puede abrir luego como un conjunto de datos ráster usando el GDALG: GDAL Streamed Algorithm controlador, y aplicar la canalización especificada de una manera en tiempo real / en flujo.

El command_line miembro del archivo JSON debe ser nominalmente la línea de comando completa sin el paso final write , y es lo que se genera con gdal raster pipeline ! .... ! write out.gdalg.json.

{
    "type": "gdal_streamed_alg",
    "command_line": "gdal raster pipeline ! read in.tif ! reproject --dst-crs=EPSG:32632"
}

El paso final write c

GDALG OUTPUT (ON-THE-FLY / STREAMED DATASET)

Added in version 3.12.

It is possible to serialize the whole pipeline into a file that will be a GDALG file. This file will define a virtual dataset (like a GDAL Compute Process or Raster Configuration).

In that case, the pipeline must end with a write step. The output filename must have the .gdalg.json extension.

A pipeline can also be made to output a streamed dataset. This can only be done by setting the output format to streamed, and by specifying a non-significant output dataset name. The output format of the main pipeline can be set to streamed, but if so it must explicitly specify the stream output format and a non-significant output dataset name.

{
    "type": "gdal_streamed_alg",
    "command_line": "gdal raster pipeline ! read in.tif ! reproject --dst-crs=EPSG:32632 ! write --output-format=streamed streamed_dataset"
}

SUBSTITUTIONS

Added in version 3.12.

It is possible to use gdal pipeline to use a pipeline already serialized in a .gdal.json file, and customize its existing steps, typically changing an input filename, specifying an output filename, or adding/modifying arguments of steps.

See Substitutions.

NESTED PIPELINE

Added in version 3.12.

It is possible to create "nested pipelines", i.e. pipelines inside pipelines.

A nested pipeline is delimited by square brackets ([ and ]) surrounded by a space character.

There are 2 kinds of nested pipelines:

  • input nested pipelines: where the result dataset of the nested pipeline is used as the input dataset for an argument of the main pipeline.
  • output nested pipelines: where the output of a step of the main pipeline is used as the input of the nested pipeline in a following step. Output nested pipelines can only be used with the tee step.

See Nested pipeline.

EXAMPLES

Example 1: Reproject a GeoTIFF file to CRS EPSG:32632 ("WGS 84 / UTM zone 32N") and adding a metadata item

$ gdal raster pipeline ! read in.tif ! reproject --dst-crs=EPSG:32632 ! edit --metadata AUTHOR=EvenR ! write out.tif --overwrite

Example 2: Serialize the command of a reprojection of a GeoTIFF file in a GDALG file, and later read it

$ gdal raster pipeline ! read in.tif ! reproject --dst-crs=EPSG:32632 ! write in_epsg_32632.gdalg.json --overwrite
$ gdal raster info in_epsg_32632.gdalg.json

Example 3: Mosaic on-the-fly several input files and tile that mosaic.

gdal raster pipeline ! mosaic input*.tif ! tile output_folder
