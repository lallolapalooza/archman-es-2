GDB(1) Herramientas de desarrollo GNU GDB(1)

NOMBRE

gdb - El depurador de GNU

SINOPSIS

gdb [OPCIONES] [prog|prog procID|prog core]

DESCRIPCIÓN

El propósito de un depurador como GDB es permitirle ver lo que está sucediendo "dentro" de otro programa mientras se ejecuta, o lo que otro programa estaba haciendo en el momento en que se bloqueó.

GDB puede hacer cuatro tipos principales de cosas (más otras cosas de apoyo a estas) para ayudarle a detectar errores en el acto:

  • Iniciar su programa, especificando cualquier cosa que pueda afectar su comportamiento.
  • Hacer que su programa se detenga en condiciones especificadas.
  • Examinar lo que ha sucedido cuando su programa se ha detenido.
  • Cambiar cosas en su programa, para que pueda experimentar con la corrección de los efectos de un error y continuar aprendiendo sobre otro.

Puede usar GDB para depurar programas escritos en C, C++, Fortran y Modula-2.

GDB se invoca con el comando de shell "gdb". Una vez iniciado, lee comandos desde la terminal hasta que usted le indique salir con el comando de GDB "quit" o "exit". Puede obtener ayuda en línea de GDB mismo usando el comando "help".

Puede ejecutar "gdb" sin argumentos u opciones; pero la forma más usual de iniciar GDB es con un argumento o dos, especificando un programa ejecutable como el argumento:

gdb program

También puede iniciar con un programa ejecutable y un archivo de volcado de memoria (core) especificados:

gdb program core

Puede, en cambio, especificar un ID de proceso como segundo argumento u usar la opción "-p", si desea depurar un proceso en ejecución:

gdb program 1234
gdb -p 1234

adjuntaría GDB al proceso 1234. Con la opción -p puede omitir el nombre de archivo del programa.

Aquí están algunos de los comandos de GDB más frecuentemente necesarios:

break [file:][function|line]
Establece un punto de interrupción en function o line (en file).
run [arglist]
Inicia su programa (con arglist, si se especifica).
bt
Traza inversa: muestra la pila del programa.
print expr
Muestra el valor de una expresión.
c
Continúa ejecutando su programa (después de detenerse, por ejemplo, en un punto de interrupción).
next
Ejecuta la siguiente línea del programa (después de detenerse); salta sobre cualquier llamada a funciones en la línea.
edit [file:]function
mire la línea del programa donde se ha detenido actualmente.
list [file:]function
escribe el texto del programa en las cercanías de donde se ha detenido actualmente.
step
Ejecuta la siguiente línea del programa (después de detenerse); entra en cualquier llamada a funciones en la línea.
help [name]
Muestra información sobre el comando de GDB name, o información general sobre el uso de GDB.
quit
exit
Sale de GDB.

Para detalles completos sobre GDB, vea Using GDB: A Guide to the GNU Source-Level Debugger, por Richard M. Stallman y Roland H. Pesch. El mismo texto está disponible en línea como la entrada "gdb" en el programa "info" .

OPCIONES

Cualquier argumento que no sea una opción especifica un archivo ejecutable y un archivo de volcado de memoria (o ID de proceso); es decir, el primer argumento encontrado sin una opción de bandera asociada es equivalente a una --se opción, y el segundo, si lo hay, es equivalente a una -c opción si es el nombre de un archivo. Muchas opciones tienen tanto formas largas como abreviadas; ambas se muestran aquí. Las formas largas también se reconocen si las trunca, siempre que haya suficiente de la opción presente para ser inequívoca.

Las formas abreviadas se muestran aquí con - y las formas largas se muestran con -- para reflejar cómo se muestran en --help. Sin embargo, GDB reconoce todas las siguientes convenciones para la mayoría de las opciones:

"--option=value"
"--option value"
"-option=value"
"-option value"
"--o=value"
"--o value"
"-o=value"
"-o value"

Todas las opciones y argumentos de línea de comandos que usted proporciona se procesan en orden secuencial. El orden hace una diferencia cuando se usa -x la opción.

--help
-h
Lista todas las opciones, con breves explicaciones.
--symbols=file
-s file
Lee la tabla de símbolos de file.
--write
Habilita la escritura en archivos ejecutables y de volcado de memoria (core).
--exec=file
-e file
Usa file como el archivo ejecutable a ejecutar cuando sea apropiado, y para examinar datos puros en conjunto con un volcado de memoria (core dump).
--se=file
Lee la tabla de símbolos de file y úsalo como el archivo ejecutable.
--core=file
-c file
Usa file como un volcado de memoria (core dump) a examinar.
--command=file
-x file
Ejecuta comandos de GDB desde file.
--eval-command=command
-ex command
Ejecuta el comando de GDB commandproporcionado.
--init-eval-command=command
-iex
Ejecuta el comando de GDB command antes de cargar el programa inferior.
--directory=directory
-d directory
Añade directory a la ruta de búsqueda de archivos fuente.
--nh
No ejecuta comandos de ~/.config/gdb/gdbinit, ~/.gdbinit, ~/.config/gdb/gdbearlyinit, o ~/.gdbearlyinit
--nx
-n
No ejecuta comandos de ningún .gdbinit o .gdbearlyinit archivos de inicialización.
--quiet
--silent
-q
"Silencioso". No imprime los mensajes introductorios y de copyright. Estos mensajes también se suprimen en modo por lotes.
--batch
Ejecuta en modo por lotes. Sale con estado 0 después de procesar todos los archivos de comandos especificados con -x (y .gdbinit, si no está inhibido). Sale con estado distinto de cero si ocurre un error al ejecutar los comandos de GDB en los archivos de comandos. El modo por lotes puede ser útil para ejecutar GDB como un filtro, por ejemplo para descargar y ejecutar un programa en otro ordenador; para hacer esto más útil, el mensaje

Program exited normally.

(que normalmente se emite cada vez que un programa bajo el control de GDB termina) no se emite al ejecutar en modo por lotes.

--batch-silent
Ejecutar en modo por lotes, igual que --batch, pero totalmente silencioso. Toda la salida de GDB se suprime (stderr no se ve afectado). Esto es mucho más silencioso que --silent y sería inútil para una sesión interactiva.

Esto es particularmente útil al usar objetivos que emiten Loading section mensajes, por ejemplo.

Tenga en cuenta que los objetivos que emiten su salida a través de GDB, en lugar de escribir directamente en "stdout", también se harán silenciosos.

--args prog [arglist]
Cambia la interpretación de la línea de comandos para que los argumentos que siguen a esta opción se pasen como argumentos al inferior. Como ejemplo, tome el siguiente comando: 
gdb ./a.out -q

Esto iniciaría GDB con -q, sin imprimir el mensaje introductorio. Por otro lado, usando:

gdb --args ./a.out -q

inicia GDB con el mensaje introductorio, y pasa la opción al inferior.

--pid=pid
Adjuntar GDB a un programa en ejecución, con el PID pid.
--tui
Abrir la interfaz de usuario de la terminal.
--readnow
Leer todos los símbolos del archivo de símbolos dado en el primer acceso.
--readnever
No leer archivos de símbolos.
--return-child-result
El código de salida de GDB será el mismo que el código de salida del hijo.
--configuration
Imprimir detalles sobre la configuración de GDB y luego salir.
--version
Imprimir información de versión y luego salir.
--cd=directory
Ejecutar GDB usando directory como su directorio de trabajo, en lugar del directorio actual.
--data-directory=directory
-D
Ejecutar GDB usando directory como su directorio de datos. El directorio de datos es donde GDB busca sus archivos auxiliares.
--fullname
-f
Emacs establece esta opción cuando ejecuta GDB como un subproceso. Le dice a GDB que emita el nombre completo del archivo y el número de línea de una manera estándar, reconocible, cada vez que se muestra un marco de pila (lo que incluye cada vez que el programa se detiene). Este formato reconocible se ve como dos \032 caracteres, seguidos del nombre del archivo, número de línea y posición del carácter separados por dos puntos, y una nueva línea. El programa de interfaz Emacs-GDB usa los dos \032 caracteres como una señal para mostrar el código fuente del marco.
-b baudrate
Establecer la velocidad de línea (baudios o bits por segundo) de cualquier interfaz serie usada por GDB para la depuración remota.
-l timeout
Establecer el tiempo de espera, en segundos, para la depuración remota.
--tty=device
Ejecutar usando device para la entrada y salida estándar de su programa.

info gdb

debería darle acceso al manual completo.
