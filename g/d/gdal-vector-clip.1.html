NOMBRE

gdal-vector-clip - Recortar un conjunto de datos vectorial

Añadido en la versión 3.11.

SINOPSIS

Uso: gdal vector clip [OPCIONES] <ENTRADA> <SALIDA>
Recorta un conjunto de datos vectorial.
Argumentos posicionales:
  -i, --input <ENTRADA>                                Conjuntos de datos vectoriales de entrada [requerido]
  -o, --output <SALIDA>                                Conjunto de datos vectoriales de salida [requerido]
Opciones comunes:
  -h, --help                                           Muestra el mensaje de ayuda y sale
  --json-usage                                         Muestra el uso como documento JSON y sale
  --config <CLAVE>=<VALOR>                             Opción de configuración [puede repetirse]
  -q, --quiet                                          Modo silencioso (sin barra de progreso)
Opciones:
  -l, --layer, --input-layer <CAPA-ENTRADA>            Nombre(s) de la capa de entrada [puede repetirse]
  -f, --of, --format, --output-format <FORMATO-SALIDA> Formato de salida ("GDALG" permitido)
  --co, --creation-option <CLAVE>=<VALOR>            Opción de creación [puede repetirse]
  --lco, --layer-creation-option <CLAVE>=<VALOR>       Opción de creación de capa [puede repetirse]
  --overwrite                                          Permitir sobrescribir la salida existente
  --update                                             Abrir conjunto de datos existente en modo de actualización
  --overwrite-layer                                    Permitir sobrescribir la capa de salida existente
  --append                                             Permitir añadir a la capa existente
                                                       Mutuamente exclusivo con --upsert
  --output-layer <CAPA-SALIDA>                         Nombre de la capa de salida
  --skip-errors                                        Omitir errores al escribir características
  --active-layer <CAPA-ACTIVA>                         Establecer capa activa (si no se especifica, todas)
  --bbox <BBOX>                                        Bounding box de recorte como xmin,ymin,xmax,ymax
                                                       Mutuamente exclusivo con --geometry, --like
  --bbox-crs <CRS-BBOX>                                CRS del bounding box de recorte
  --geometry <GEOMETRIA>                               Geometría de recorte (WKT o GeoJSON)
                                                       Mutuamente exclusivo con --bbox, --like
  --geometry-crs <CRS-GEOMETRIA>                       CRS de la geometría de recorte
  --like <CONJUNTO-DATOS>                              Conjunto de datos a usar como plantilla para los límites
                                                       Mutuamente exclusivo con --bbox, --geometry
  --like-sql <SENTENCIA-SELECT>                        Sentencia SELECT a ejecutar en el conjunto de datos 'like'
                                                       Mutuamente exclusivo con --like-where
  --like-layer <NOMBRE-CAPA>                           Nombre de la capa del conjunto de datos 'like'
  --like-where <EXPRESION-WHERE>                       Cláusula WHERE SQL a ejecutar en el conjunto de datos 'like'
                                                       Mutuamente exclusivo con --like-sql
Opciones avanzadas:
  --if, --input-format <FORMATO-ENTRADA>               Formatos de entrada [puede repetirse]
  --oo, --open-option <CLAVE>=<VALOR>                Opciones de apertura [puede repetirse]
  --output-oo, --output-open-option <CLAVE>=<VALOR>  Opciones de apertura de salida [puede repetirse]
  --upsert                                             Actualizar (insertar/sobrescribir) características (implica 'append')
                                                       Mutuamente exclusivo con --append

DESCRIPCIÓN

gdal vector clip se puede usar para recortar un conjunto de datos vectorial utilizando coordenadas georreferenciadas.

Se debe especificar --bbox, --geometry o --like.

clip también se puede usar como un paso de gdal vector pipeline.

El recorte a veces produce geometrías que no son de un tipo compatible con el tipo de geometría. Este programa divide las multi-geometrías o colecciones de geometrías en sus partes para las capas que son de un solo tipo de geometría (como punto, linestring, polígono) y solo conserva las partes que son de ese tipo. También promueve los tipos de geometría única (por ejemplo, polígonos) a tipos de multi-geometría (por ejemplo, multi-polígonos). Si el usuario necesita preservar cualquier tipo de intersección, la capa debe usar el tipo wkbUnknown (cualquier geometría).

Opciones estándar

-f, --of, --format, --output-format <FORMATO-SALIDA>
Qué formato vectorial de salida usar. Los valores permitidos pueden ser dados por gdal --formats | grep vector | grep rw | sort
--co <NOMBRE>=<VALOR>
Muchos formatos tienen una o más opciones de creación de conjuntos de datos opcionales que se pueden usar para controlar detalles sobre el archivo creado. Por ejemplo, el controlador GeoPackage admite opciones de creación para controlar la versión.

Puede repetirse.

Las opciones de creación de conjuntos de datos disponibles varían según el controlador de formato, y algunos formatos simples no tienen opciones de creación. Una lista de opciones compatibles con un formato se puede obtener con la opción de línea de comandos --formats, pero la documentación del formato es la fuente definitiva de información sobre las opciones de creación del controlador. Consulte la documentación específica del formato de controladores vectoriales para ver las opciones de creación legales para cada formato.

Tenga en cuenta que las opciones de creación de conjuntos de datos son diferentes de las opciones de creación de capas.

--overwrite
Permite al programa sobrescribir el archivo o conjunto de datos de destino existente. De lo contrario, por defecto, gdal genera un error si el archivo o conjunto de datos de destino ya existe.
--active-layer <CAPA-ACTIVA>
Establece la capa activa. Cuando se especifica, solo la capa especificada por su nombre estará sujeta al procesamiento. Las otras capas no se modificarán. Si no se especifica esta opción, todas las capas estarán sujetas al procesamiento.
--bbox <xmin>,<ymin>,<xmax>,<ymax>
Límites hasta los cuales recortar el conjunto de datos. Se asumen en el CRS del conjunto de datos de entrada, a menos que se especifique --bbox-crs. El eje X e Y son los "amigables para GIS", es decir, X es longitud o este, y Y es latitud o norte. Mutuamente exclusivo con --like y --geometry.
--bbox-crs <CRS>
CRS en el que se expresan los valores <xmin>,<ymin>,<xmax>,<ymax> de --bbox. Si no se especifica, se asume que es el CRS del conjunto de datos de entrada. Tenga en cuenta que especificar --bbox-crs no implica realizar una reproyección vectorial. En su lugar, los límites se reproyectan desde el bbox-crs al CRS del conjunto de datos de entrada.
--geometry <WKT_o_GeoJSON>
Geometría como una cadena WKT o GeoJSON para la cual recortar el conjunto de datos. Si la geometría de entrada es GeoJSON, se asume que su CRS es WGS84, a menos que haya un CRS definido en la geometría GeoJSON o se especifique --geometry-crs. Si la geometría de entrada es WKT, se asume que su CRS es el del conjunto de datos de entrada, a menos que se especifique --geometry-crs. El eje X e Y son los "amigables para GIS", es decir, X es longitud o este, y Y es latitud o norte. Mutuamente exclusivo con --bbox y --like.
--geometry-crs <CRS>
CRS en el que se expresan los valores de coordenadas de --geometry. Si no se especifica, se asume que es el CRS del conjunto de datos de entrada. Tenga en cuenta que especificar --geometry-crs no implica realizar una reproyección vectorial. En su lugar, los límites se reproyectan desde el geometry-crs al CRS del conjunto de datos de entrada.
--like <CONJUNTO-DATOS>
Conjunto de datos vectoriales o ráster a usar como plantilla para los límites. Si el conjunto de datos especificado es un ráster, se utilizan sus límites rectangulares como geometría de recorte. Si
el conjunto de datos especificado es un conjunto de datos vectorial, sus geometrías poligonales se unen para formar la geometría de recorte (tenga en cuenta que la unión resultante puede no ser perfecta si hay espacios entre las características poligonales individuales). Si hay varias capas presentes, --like-sql o --like-layer debe especificarse. Mutuamente exclusivo con --bbox y --geometry.
--like-sql <SELECT-STATEMENT>
Seleccione las geometrías deseadas del conjunto de datos de recorte vectorial usando una consulta SQL. por ejemplo SELECT geom FROM my_layer WHERE country = 'France'. Mutuamente exclusivo con --like-layer y --like-where
--like-layer <LAYER-NAME>
Seleccione la capa con nombre del conjunto de datos de recorte vectorial. Mutuamente exclusivo con --like-sql
--like-where <WHERE-EXPRESSION>
Restrinja las geometrías deseadas de la capa del conjunto de datos de recorte vectorial basándose en una consulta de atributos. por ejemplo country = 'France'.

Opciones avanzadas

--oo <NAME>=<VALUE>
Opción de apertura del conjunto de datos (específica del formato).

Puede repetirse.

--if <format>
Nombre del formato/controlador que se intentará para abrir el archivo(s) de entrada. Generalmente no es necesario especificarlo, pero puede usarse para omitir la detección automática del controlador, cuando falla en seleccionar el controlador apropiado. Esta opción puede repetirse varias veces para especificar varios controladores candidatos. Tenga en cuenta que no fuerza a esos controladores a abrir el conjunto de datos. En particular, algunos controladores tienen requisitos sobre las extensiones de archivo.

Puede repetirse.

EJEMPLOS

Ejemplo 1: Recortar un archivo GeoPackage al cuadro delimitador desde longitud 2, latitud 49, hasta longitud 3, latitud 50 en WGS 84

$ gdal vector clip --bbox=2,49,3,50 --bbox-crs=EPSG:4326 in.gpkg out.gpkg --overwrite
