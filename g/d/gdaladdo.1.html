NOMBRE

gdaladdo - Construye o reconstruye imágenes de vistas previas.

SINOPSIS

Uso: gdaladdo [--help] [--long-usage] [--help-general]
                [-r nearest|average|rms|gauss|bilinear|cubic|cubicspline|lanczos|average_magphase|mode]
                [-ro] [--quiet] [-b <banda>]... [-oo <NOMBRE=VALOR>]...
                [-minsize <val>]
                [[-clean]|[--partial-refresh-from-source-timestamp]|
                [--partial-refresh-from-projwin <ulx> <uly> <lrx> <lry>]|
                [--partial-refresh-from-source-extent <archivo1>[,<archivoN>]...]]
                <archivo> [<nivel>]...

DESCRIPCIÓN

La utilidad gdaladdo puede ser utilizada para construir o reconstruir imágenes de vistas previas para la mayoría de los formatos de archivo soportados con uno de varios algoritmos de reducción de escala.

--help
Muestra este mensaje de ayuda y sale.
--help-general
Proporciona un breve mensaje de uso para las opciones genéricas de línea de comandos de GDAL y sale.
-r {nearest|average|rms|gauss|bilinear|cubic|cubicspline|lanczos|average_magphase|mode}
Selecciona un algoritmo de remuestreo. El valor predeterminado es nearest, que generalmente no es apropiado si se desea precisión subpíxel.

A partir de GDAL 3.9, al actualizar vistas previas de TIFF existentes, se utilizará el método previamente empleado, tal como se indica en el elemento de metadatos RESAMPLING de la vista previa, si no se especifica -r.

Los métodos disponibles son:

nearest aplica un remuestreador de vecino más cercano (muestreo simple).

average calcula el promedio de todos los píxeles que contribuyen y no son NODATA. A partir de GDAL 3.1, es un promedio ponderado que tiene en cuenta adecuadamente el peso de los píxeles de origen que no contribuyen completamente al píxel de destino.

rms calcula la raíz cuadrática media / media cuadrática de todos los píxeles que contribuyen y no son NODATA (GDAL >= 3.3)

gauss aplica un kernel Gaussiano antes de calcular la vista previa, lo que puede llevar a mejores resultados que el promedio simple en, por ejemplo, casos de bordes afilados con alto contraste o patrones ruidosos. Los valores de nivel recomendados deben ser 2, 4, 8, ... para que se seleccione un kernel Gaussiano de remuestreo de 3x3.

bilinear aplica un kernel de convolución bilineal.

cubic aplica un kernel de convolución cúbica.

cubicspline aplica un kernel de convolución B-Spline.

lanczos aplica un kernel de convolución sinc convolucionado con ventana de Lanczos.

average_magphase promedia datos complejos en espacio mag/fase.

mode selecciona el valor que aparece con más frecuencia de todos los puntos muestreados.

-b <banda>
Selecciona una banda de entrada banda para la generación de la vista previa. La numeración de las bandas comienza en 1. Se pueden usar múltiples interruptores -b para seleccionar un conjunto de bandas de entrada para generar vistas previas.
-ro
Abre el conjunto de datos en modo de solo lectura, para generar vistas previas externas (especialmente para GeoTIFF).
-clean
Elimina todas las vistas previas.
-oo <NOMBRE>=<VALOR>
Opción de apertura del conjunto de datos (específica del formato)
-minsize <val>
Ancho o alto máximo del nivel de vista previa más pequeño. Solo se tiene en cuenta si no se especifican niveles explícitos. El valor predeterminado es 256.
--partial-refresh-from-source-timestamp
Añadido en la versión 3.8.

Esta opción realiza una actualización parcial de las vistas previas existentes, cuando <archivo> es un archivo VRT con una vista previa externa. Comprueba la marca de tiempo de modificación de todas las fuentes del VRT y regenera la vista previa para las áreas correspondientes a las fuentes cuya marca de tiempo sea más reciente que la vista previa externa del VRT. Por defecto, se actualizarán todos los niveles de vista previa existentes, a menos que se especifiquen niveles explícitos. Consulte el Ejemplo 7.

--partial-refresh-from-projwin <ulx> <uly> <lrx> <lry>
Añadido en la versión 3.8.

Esta opción realiza una actualización parcial de las vistas previas existentes, en la región de interés especificada por coordenadas de georreferencia, donde <ulx> es el valor X de la esquina superior izquierda, <uly> es el valor Y de la esquina superior izquierda, <lrx> es el valor X de la esquina inferior derecha y <lry> es el valor Y de la esquina inferior derecha. Por defecto, se actualizarán todos los niveles de vista previa existentes, a menos que se especifiquen niveles explícitos.

--partial-refresh-from-source-extent <archivo1>[,<archivoN>]...
Añadido en la versión 3.8.

Esta opción realiza una actualización parcial de las vistas previas existentes, en la región de interés especificada por uno o varios nombres de archivo (nombres separados por comas). Tenga en cuenta que los nombres de archivo solo se utilizan para determinar las regiones de interés a actualizar. Los píxeles de origen de referencia son los del conjunto de datos principal. Por defecto, se actualizarán todos los niveles de vista previa existentes, a menos que se especifiquen niveles explícitos. Consulte el Ejemplo 8.

<archivo>
El archivo para el cual se construirán las vistas previas (o cuyas vistas previas deben ser eliminadas).
<niveles>
Una lista de niveles integrales de vista previa a construir. Se ignora con la opción -clean.
Ya no se requieren niveles para construir vistas previas. En ese caso, se seleccionarán factores de potencia de dos de vista previa apropiados hasta que la vista previa más pequeña sea menor que el valor del interruptor -minsize.

A partir de GDAL 3.9, si ya existen vistas previas, se utilizarán los niveles correspondientes para actualizarlas si no se especifican niveles explícitos.

gdaladdo respetará adecuadamente las tuplas NODATA_VALUES (metadatos especiales del conjunto de datos) para que solo un triplete RGB dado (en el caso de una imagen RGB) se considere como el valor no dato y no cada valor del triplete independientemente por banda.

La selección de un valor de nivel como 2 hace que se calcule un nivel de vista previa que es 1/2 de la resolución (en cada dimensión) de la capa base. Si el archivo tiene niveles de vista previa existentes en un nivel seleccionado, esos niveles se recalcularán y se sobrescribirán en su lugar.

Para vistas previas internas de GeoTIFF (o vistas previas externas en formato GeoTIFF), tenga en cuenta que -clean no reduce el archivo. Una ejecución posterior de gdaladdo con niveles de vista previa hará que el archivo se expanda, en lugar de reutilizar el espacio de las vistas previas eliminadas previamente. Si solo desea cambiar el método de remuestreo en un archivo que ya tiene vistas previas calculadas, no necesita limpiar las vistas previas existentes.

Algunos controladores de formato no soportan vistas previas en absoluto. Muchos controladores de formato almacenan las vistas previas en un archivo secundario con la extensión .ovr que en realidad está en formato TIFF. Por defecto, el controlador GeoTIFF almacena las vistas previas internamente en el archivo operado (si es escribible), a menos que se especifique el interruptor -ro.

La mayoría de los controladores también soportan un formato de vista previa alternativo que utiliza el formato Erdas Imagine. Para activarlo, use la opción de configuración USE_RRD=YES (Ejemplo 5). Esto colocará las vistas previas en un archivo .aux asociado adecuado para su uso directo con Imagine o ArcGIS, así como con aplicaciones GDAL. (por ejemplo, --config USE_RRD YES)

VISTAS PREVIAS EXTERNAS EN FORMATO GEOTIFF

Las vistas previas externas en formato GeoTIFF se almacenan en un archivo separado, típicamente con el nombre <basefilename>.ovr. Estos archivos están en formato GeoTIFF y utilizan compresión LZW para reducir el tamaño del archivo y facilitar el acceso a las vistas previas.

EJEMPLOS

Ejemplo 1: Construir vistas previas en un archivo GeoTIFF con niveles 2, 4 y 8.
gdaladdo -r average input.tif 2 4 8
Ejemplo 2: Construir vistas previas externas para un archivo GeoTIFF usando niveles que resulten en un tamaño mínimo de 128x128.
gdaladdo -ro -minsize 128 input.tif
Ejemplo 3: Eliminar todas las vistas previas de un archivo GeoTIFF.
gdaladdo -clean input.tif
Ejemplo 4: Construir vistas previas para las bandas 1 y 3 de un archivo JPEG2000.
gdaladdo -b 1 -b 3 input.jp2
Ejemplo 5: Construir vistas previas en formato Erdas Imagine.
gdaladdo --config USE_RRD YES input.tif
Ejemplo 6: Reconstruir vistas previas existentes para un archivo GeoTIFF.
gdaladdo input.tif
Ejemplo 7: Actualizar parcialmente vistas previas externas para un VRT basándose en la marca de tiempo de los archivos fuente.
gdaladdo --partial-refresh-from-source-timestamp my_vrt.vrt
Ejemplo 8: Actualizar parcialmente vistas previas externas para un GeoTIFF, cubriendo un área geográfica específica.
gdaladdo --partial-refresh-from-projwin -100000 200000 -50000 150000 input.tif
Ejemplo 9: Actualizar parcialmente vistas previas externas para un GeoTIFF, basándose en el área cubierta por otros archivos ráster.
gdaladdo --partial-refresh-from-source-extent file1.tif,file2.img input.tif

Starting with GDAL 3.9, if the input file already contains overviews, and no levels are specified on the command line, the existing overviews will be refreshed, rather than rebuilt from scratch.

REMUESTREO

Los valores no válidos en los píxeles de origen, ya sea identificados a través de un valor nodata establecido en los metadatos de la banda de origen, una banda máscara, una banda alfa no se usarán durante el

ano

Los detalles de cómo se tienen en cuenta dependen del kernel de

remuestreo:
  • para el remuestreo más cercano, para cada píxel de destino, uno de los píxeles de origen potencialmente contribuyentes se selecciona (de una manera específica de la implementación). Su valor se usa tal cual, ya sea válido o no
    • válido.
  • para bilineal, cúbico, cúbico-spline y lanczos, para cada píxel de destino, los pesos de los píxeles de origen contribuyentes se establecen en cero para ignorarlos cuando están enmascarados. Hay una especificidad adicional para el cúbico: dado que algunos de los pesos en el kernel son negativos, esta estrategia podría conducir a un fuerte sobrepaso/subpaso cuando hay una alternancia de píxeles válidos y no válidos. En consecuencia, si en cualquiera de las direcciones horizontal o vertical, si el número máximo de píxeles de origen válidos en cada dimensión es menor que el radio del kernel de remuestreo, el píxel de destino se considera como
    • nodata.
  • para los otros métodos de remuestreo, los píxeles
    • de origen que contribuyen al píxel de dest
