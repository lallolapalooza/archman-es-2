DESCRIPCIÓ

N

gdnsd-plugin-multifo está diseñado para realizar agrupaciones de conmutación por error multi-dirección, todos activos. Básicamente, para cada nombre de recurso configurado, usted proporciona una lista etiquetada de direcciones. multifo monitoriza estas direcciones de acuerdo con "service_types", y responde a las consultas de dirección "DYNA" usando el subconjunto que no está"DOWN". El código principal de gdnsd rotará los registros de forma round-robin a

l salir, como hace con todos los conjun
tos de registros de dirección (RR-sets).

CONFIGURACIÓN DEL PLUGIN DE NIVEL

SUPERIOR

En el nivel superior de la estrofa de configuración del plugin, se admiten tres parámetros especiales: "up_thresh", "service_types", y "ignore_health". Estos establecen opciones predeterminadas por recurso con el mismo nombre para cualquier recurso que no las defina

explícitamente.

El resto de las entradas del hash en el nivel superior son los nombres de los recu

rsos que usted define. Cada recurso obtiene su propio hash de configuración para co
ntener parámetros específicos del recurso, así como los datos de dirección reales.

CONFIGURACIÓN DEL

RECURSO

Dentro de un recurso, usted tiene dos opciones básicas. Puede especificar directamente un conjunto de pares "etiqueta => dirección" que son todos de la misma familia (IPv4 o IPv6), o puede usar las sub-estrofas "addrs_v4" y/o "addrs_v6" para especificar una o ambas familias en el mismo

recurso.

Los parámetros "up_thresh", "service_types", y "ignore_health" se heredan a través de cada nivel, y pueden ser sobrescritos en cualquier nivel (incluso por familia de dirección)

:
up_thre
sh
Punto flotante, valor predeterminado 0.5, rango (0.0 - 1.0]. Esto configura el umbral "up_thresh" por recurso. Más detalles en "UMBRAL DE ACTIVIDAD" más
abajo.
service_typ
es
Array de cadenas, o una sola cadena. Valor predeterminado "default". Esto establece los service_types monitorizados para este recurso. Si se proporciona un array de más de uno, todos serán monitorizados para cada dirección, y el estado monitorizado neto será el mínimo (peor) del conjunto. Vea gdnsd.config(8) para más detalles sobre
service_types.
ignore_heal
th
Booleano, valor predeterminado false. Si se establece en true, la salud de las direcciones individuales no afectará si multifo las añade al conjunto de direcciones de salida, pero aún se comprobará y se usará para el cálculo de "up_thresh" que es consumido por meta-plugins como geoip y metafo, que pod
rían usar esa información para conmu
tar por error a un centro de datos co
mpletamente diferente como resultado.

CONFIGURACIÓN

ABREVIADA

Si no tiene parámetros (service_types, up_thresh, ignore_health) que configurar en una estrofa determinada (configuración de recurso directo de familia única, o addrs_v[46]), y no le importan las etiquetas descriptivas por dirección usadas en la monitorización, puede reemplazar el hash con un array de direcciones. Las etiquetas serán generadas para usted como una serie de enteros empezando por 1. Por ejemplo, lo siguiente es

equivalente: 
res1 => { addrs_v4 => [ 192.0.2.1, 192.0.2.2 ] }
res1 => { addrs_v4 => { 1 => 192.0.2.1, 2 => 192.0.2.2 }
}

MECÁNICA

OPERATIVA

Todas las direcciones de todos los recursos son monitorizadas usando los "service_types" heredados por familia de dirección especificados (el valor predeterminado sería el monitor virtual estático "up"). Cuando el demonio principal solicita una búsqueda para registros de dirección de una familia dada en uno de los recursos de este plugin, pasa esencialmente por el siguiente proceso para determinar el conjunto de direcciones de respuesta para esa familia de dirección: 1) Añadir todas las direcciones que no están DOWN al conjunto de resultados. 2) Si el conjunto de direcciones que no están DOWN no supera la comprobación de up_thresh, añadir *todas* las direcciones al conjunto de resultados como respaldo. 3) Si alguna dirección está en estado DOWN, reducir a la mitad el TTL especificado en el archivo de

zona.

Si "ignore_health" es true, todas las direcciones se añaden al conjunto de resultados independientemente de la salud, pero los efectos de up_thresh y TTL aún ocurren, y el estado final a nivel de recurso aún refleja el estado general como lo haría sin "ignore_health"

.

Este proceso se repite independientemente para cada uno de los subconjuntos de direcciones IPv4 e IPv6,

en el caso de que un recurso tenga ambas familias de dirección configuradas (el TTL solo se reduce a
la mitad una vez, por supuesto). Los detalles sobre la comprobación de up_thresh siguen a continuación:

UMBRAL DE

ACTIVIDAD

Si no hay suficientes direcciones UP para superar el umbral (por familia de dirección), todas las direcciones (de una familia de dirección dada) serán devueltas como

respaldo.

El umbral está implementado matemáticamente como en el siguiente pseudocódigo "if(non_down >= ceil(thresh * total)) threshold_passed;". Por ejemplo, si thresh está en el valor predeterminado de 0.5, y hay 3 direcciones IPv4 en total, entonces 2 de ellas deben estar no-down para superar el umbral. El resultado neto es que con el umbral predeterminado, el plugin nunca devolverá una dirección aislada única de un conjunto de 3. Devolverá las 3, o devolverá 2/3 si una sola dirección del conjunto ha

fallado.

Cuando la comprobación del umbral falla (y se devuelven todas las direcciones) para cualquiera de las familias de dirección, el fallo total a nivel de recurso también será señalado a cualquier meta-plugin aguas arriba aplicable como metafo o

geoip.

Reglas generales para los resultados de la fórmula de

up_thresh:
  • Un umbral de 1.0 solo pasará si todas las direcciones están no-down. Esto es mayormente inútil, podría no monitorizar nada y configurar estas direcciones como un conjunto estático en un archivo de
    • zona.
  • Un umbral de 0.01 pasará incluso si solo una dirección está viva y devolverá solo esa dirección, incluso si es, por ejemplo, la única que queda de
    • 40.
  • Debido a que un umbral de 0.0 es ilegal, si tod
    • as las direcciones están caídas el umbral siem
pre fallará, devolviendo todas las direcciones.
