NOMBRE

gdal-vector-set-field-type - Modificar el tipo de un campo de un conjunto de datos vectorial

Añadido en la versión 3.12.

SINOPSIS

Uso: gdal vector set-field-type [OPCIONES] <ENTRADA> <SALIDA>
Modificar el tipo de un campo de un conjunto de datos vectorial.
Argumentos posicionales:
  -i, --input <ENTRADA>                                  Conjuntos de datos vectoriales de entrada [requerido]
  -o, --output <SALIDA>                                Conjunto de datos vectorial de salida [requerido]
Opciones comunes:
  -h, --help                                           Mostrar mensaje de ayuda y salir
  --json-usage                                         Mostrar el uso como documento JSON y salir
  --config <CLAVE>=<VALOR>                               Opción de configuración [puede repetirse]
  -q, --quiet                                          Modo silencioso (sin barra de progreso)
Opciones:
  -l, --layer, --input-layer <CAPA-ENTRADA>             Nombre(s) de capa(s) de entrada [puede repetirse]
  -f, --of, --format, --output-format <FORMATO-SALIDA>  Formato de salida ("GDALG" permitido)
  --co, --creation-option <CLAVE>=<VALOR>                Opción de creación [puede repetirse]
  --lco, --layer-creation-option <CLAVE>=<VALOR>         Opción de creación de capa [puede repetirse]
  --overwrite                                          Si se permite sobrescribir la salida existente
  --update                                             Si se abre el conjunto de datos existente en modo de actualización
  --overwrite-layer                                    Si se permite sobrescribir la salida existente
  --append                                             Si se permite añadir a una capa existente
                                                       Excluyente mutuamente con --upsert
  --output-layer <CAPA-SALIDA>                        Nombre de la capa de salida
  --skip-errors                                        Omitir errores al escribir elementos
  --active-layer <CAPA-ACTIVA>                        Establecer la capa activa (si no se especifica, todas)
  --field-name <NOMBRE-CAMPO>                            Nombre del campo [requerido]
                                                       Excluyente mutuamente con --src-field-type
  --src-field-type <TIPO-CAMPO-FUENTE>                    Tipo o subtipo de campo de origen [requerido]
                                                       Excluyente mutuamente con --field-name
  --dst-field-type, --field-type <TIPO-CAMPO>          Tipo o subtipo de campo de destino [requerido]
Opciones avanzadas:
  --if, --input-format <FORMATO-ENTRADA>                  Formatos de entrada [puede repetirse]
  --oo, --open-option <CLAVE>=<VALOR>                    Opciones de apertura [puede repetirse]
  --output-oo, --output-open-option <CLAVE>=<VALOR>      Opciones de apertura de salida [puede repetirse]
  --upsert                                             Actualizar elementos (implica 'append')
                                                       Excluyente mutuamente con --append

DESCRIPCIÓN

gdal vector set-field-type puede utilizarse para modificar el tipo de campo de un conjunto de datos vectorial:

set-field-type también puede utilizarse como paso de gdal vector pipeline.

Opciones estándar

-f, --of, --format, --output-format <FORMATO-SALIDA>
Qué formato vectorial de salida utilizar. Los valores permitidos pueden obtenerse con gdal --formats | grep vector | grep rw | sort
--co <NOMBRE>=<VALOR>
Muchos formatos tienen una o más opciones opcionales de creación de conjuntos de datos que pueden utilizarse para controlar detalles sobre el archivo creado. Por ejemplo, el controlador de GeoPackage admite opciones de creación para controlar la versión.

Puede repetirse.

Las opciones de creación de conjuntos de datos disponibles varían según el controlador de formato, y algunos formatos simples no tienen opciones de creación en absoluto. Una lista de opciones admitidas para un formato puede listarse con la opción de línea de comandos --formats pero la documentación del formato es la fuente definitiva de información sobre las opciones de creación del controlador. Véase Controladores vectoriales documentación específica del formato para las opciones de creación legales de cada formato.

Tenga en cuenta que las opciones de creación de conjuntos de datos son diferentes de las opciones de creación de capas.

--layer-creation-option <NOMBRE>=<VALOR>
Muchos formatos tienen una o más opciones opcionales de creación de capas que pueden utilizarse para controlar detalles sobre la capa creada. Por ejemplo, el controlador de GeoPackage admite opciones de creación de capas para controlar el identificador del elemento o el nombre de la columna de geometría, establecer el identificador o la descripción, etc.

Puede repetirse.

Las opciones de creación de capas disponibles varían según el controlador de formato, y algunos formatos simples no tienen opciones de creación de capas en absoluto. Una lista de opciones admitidas para un formato puede listarse con la opción de línea de comandos --formats pero la documentación del formato es la fuente definitiva de información sobre las opciones de creación del controlador. Véase Controladores vectoriales documentación específica del formato para las opciones de creación legales de cada formato.

Tenga en cuenta que las opciones de creación de capas son diferentes de las opciones de creación de conjuntos de datos.

--overwrite
Permite al programa sobrescribir el archivo o conjunto de datos de destino existente. De lo contrario, por defecto, gdal genera un error si el archivo o conjunto de datos de destino ya existe.
--active-layer <CAPA-ACTIVA>
Establece la capa activa. Cuando se especifica, solo la capa especificada por su nombre será sometida al procesamiento. Las demás capas no serán modificadas. Si esta opción no se especifica, todas las capas serán sometidas al procesamiento.
--field-name <NOMBRE-CAMPO>
El nombre del campo a modificar.

Excluyente mutuamente con --src-field-type. Se requiere uno de ellos.

--src-field-type <TIPO-CAMPO>
El tipo de campo de los campos a modificar. Los valores válidos son: Integer, IntegerList, Real, RealList, String, StringList, Binary, ` Date, Time, DateTime, Integer64, Integer64List. En lugar de un tipo de campo puede especificarse un subtipo de campo. Los valores válidos son: Boolean, Int16, Float32, JSON, UUID.

Excluyente mutuamente con --field-name. Se requiere uno de ellos.

--field-type, --dst-field-type <TIPO-CAMPO>
El nuevo tipo de campo. Los valores válidos son: Integer, IntegerList, Real, RealList, String, StringList, Binary, ` Date, Time, DateTime, Integer64, Integer64List. En lugar de un tipo de campo puede especificarse un subtipo de campo. Los valores válidos son: Boolean, Int16, Float32, JSON, UUID. El tipo de campo se derivará del subtipo.

Opciones avanzadas

--if <formato>
Nombre del formato/controlador que se intentará utilizar para abrir el(los) archivo(s) de entrada. Generalmente no es necesario especificarlo, pero puede utilizarse para omitir la detección automática del controlador, cuando falla al seleccionar el controlador apropiado. Esta opción puede repetirse varias veces para especificar varios controladores candidatos. Tenga en cuenta que no fuerza a esos controladores a abrir el conjunto de datos. En particular, algunos controladores tienen requisitos sobre las extensiones de archivo.

Puede repetirse.

--oo <NOMBRE>=<VALOR>
Opción de apertura del conjunto de datos (específica del formato).

Puede repetirse.

--output-open-option, --output-oo <NOMBRE>=<VALOR>
Añadido en la versión 3.12.

Opción de apertura del conjunto de datos de salida (específica del formato).

Puede repetirse.

GDALG SALIDA (CONJUNTO DE DATOS EN TIEMPO REAL / EN FLUJO)

Este programa admite la serialización de la línea de comandos como un archivo JSON utilizando el GDALG formato de salida. El archivo resultante puede luego ser abierto como un conjunto de datos vectorial utilizando el GDALG: Algoritmo en flujo de GDAL controlador, y aplicar la canalización especificada de una manera en tiempo real / en flujo.

EJEMPLOS

Ejemplo 1: Cambiar el tipo de un campo dado por su nombre a Integer

$ gdal vector set-field-type input.gpkg output.gpkg --field-name myfield --field-type Integer

Ejemplo 2: Cambiar el tipo de todos los campos de tipo Date a DateTime

$ gdal vector set-field-type input.gpkg output.gpkg --src-field-type Date --dst-field-type DateTime
