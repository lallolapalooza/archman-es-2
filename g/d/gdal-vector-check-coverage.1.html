NOMBRE

gdal-vector-check-coverage - Comprobar la cobertura de polígonos para validez

Añadido en la versión 3.12.

SINOPSIS

Uso: gdal vector check-coverage [OPCIONES] <ENTRADA> <SALIDA>
Comprobar la cobertura de polígonos para validez
Argumentos posicionales:
  -i, --input <ENTRADA>                                  Conjuntos de datos vectoriales de entrada [requerido]
  -o, --output <SALIDA>                                Conjunto de datos vectoriales de salida [requerido]
Opciones comunes:
  -h, --help                                           Mostrar mensaje de ayuda y salir
  --json-usage                                         Mostrar uso como documento JSON y salir
  --config <CLAVE>=<VALOR>                               Opción de configuración [puede repetirse]
  -q, --quiet                                          Modo silencioso (sin barra de progreso)
Opciones:
  -l, --layer, --input-layer <CAPA-ENTRADA>             Nombre(s) de capa de entrada [puede repetirse]
  -f, --of, --format, --output-format <FORMATO-SALIDA>  Formato de salida (se permite "GDALG")
  --co, --creation-option <CLAVE>=<VALOR>               Opción de creación [puede repetirse]
  --lco, --layer-creation-option <CLAVE>=<VALOR>        Opción de creación de capa [puede repetirse]
  --overwrite                                          Si se permite sobrescribir la salida existente
  --update                                             Si se abre el conjunto de datos existente en modo de actualización
  --overwrite-layer                                    Si se permite sobrescribir la capa de salida existente
  --append                                             Si se añade a la capa existente
                                                       Mutuamente excluyente con --upsert
  --output-layer <CAPA-SALIDA>                         Nombre de la capa de salida
  --skip-errors                                        Omitir errores al escribir características
  --include-valid                                      Incluir entradas válidas en la salida, con geometría vacía
  --geometry-field <CAMPO-GEOMETRIA>                   Nombre del campo de geometría a comprobar
  --maximum-gap-width <ANCHO-MAXIMO-HUECO>             Ancho máximo de un hueco a marcar
Opciones avanzadas:
  --if, --input-format <FORMATO-ENTRADA>               Formatos de entrada [puede repetirse]
  --oo, --open-option <CLAVE>=<VALOR>                  Opciones de apertura [puede repetirse]
  --output-oo, --output-open-option <CLAVE>=<VALOR>    Opciones de apertura de salida [puede repetirse]
  --upsert                                             Actualizar (insertar/actualizar) características (implica 'append')
                                                       Mutuamente excluyente con --append

DESCRIPCIÓN

gdal vector check-coverage comprueba si un conjunto de datos de polígonos forma una cobertura válida, lo que significa:

  • ningún polígono se solapa
  • todos los bordes compartidos tienen nodos en las mismas ubicaciones
  • cualquier hueco entre polígonos sea mayor que un ancho especificado

Para cada polígono que no cumpla estos criterios, se generará una característica lineal con la geometría del borde inválido. Si la cobertura es válida, el conjunto de datos de salida estará vacío a menos que se use --include-valid.

Se asume que los polígonos individuales son válidos de acuerdo con el estándar OGC Simple Features. Esto puede comprobarse con gdal vector check-geometry.

NOTA:

Este comando requiere una compilación de GDAL contra la biblioteca GEOS (versión 3.12 o superior).

Opciones estándar

--geometry-field
Especifica el nombre del campo de geometría a probar, para capas que tengan múltiples campos de geometría. Por defecto se usará el primer campo de geometría.
--include-valid
Incluir características para geometrías válidas en la salida, manteniendo una correspondencia 1:1 entre las características de entrada y salida.
--maximum-gap-width <ANCHO-MÁXIMO-HUECO>
Define el área más grande que debe considerarse un hueco.
-f, --of, --format, --output-format <FORMATO-SALIDA>
Qué formato vectorial de salida usar. Los valores permitidos pueden obtenerse con gdal --formats | grep vector | grep rw | sort
--co <NOMBRE>=<VALOR>
Muchos formatos tienen una o más opciones de creación de conjunto de datos opcionales que pueden usarse para controlar detalles específicos del archivo que se crea. Por ejemplo, el controlador GeoPackage soporta opciones de creación para controlar la versión.

Puede repetirse.

Las opciones de creación de conjunto de datos disponibles varían según el controlador de formato, y algunos formatos simples no tienen opciones de creación en absoluto. Una lista de opciones admitidas para un formato se puede obtener con la opción de línea de comandos --formats, pero la documentación del formato es la fuente definitiva de información sobre las opciones de creación del controlador. Consulte la documentación específica del formato de Controladores vectoriales para ver las opciones de creación válidas para cada formato.

Tenga en cuenta que las opciones de creación de conjunto de datos son diferentes de las opciones de creación de capa.

-lco <NOMBRE>=<VALOR>
Opción de creación de capa (específica del formato)
--overwrite
Permitir que el programa sobrescriba el archivo o conjunto de datos de destino existente. De lo contrario, por defecto, gdal genera un error si el archivo o conjunto de datos de destino ya existe.

Opciones avanzadas

--oo <NOMBRE>=<VALOR>
Opción de apertura de conjunto de datos (específica del formato).

Puede repetirse.

--if <formato>
Nombre del formato/controlador que se intentará usar para abrir los archivos de entrada. Generalmente no es necesario especificarlo, pero puede usarse para omitir la detección automática del controlador, cuando esta falla al seleccionar el controlador apropiado. Esta opción puede repetirse varias veces para especificar varios controladores candidatos. Tenga en cuenta que no obliga a esos controladores a abrir el conjunto de datos. En particular, algunos controladores tienen requisitos sobre las extensiones de archivo.

Puede repetirse.

SALIDA GDALG (SOBRE LA MARCHA / TRANSMITIDA)

Este programa soporta la serialización de la línea de comandos como un archivo JSON usando el formato de salida GDALG. El archivo resultante puede luego abrirse como un conjunto de datos vectoriales usando el controlador GDALG: GDAL Streamed Algorithm, y aplicar la canalización especificada de forma sobre la marcha / transmitida.

NOTA:

Sin embargo, este algoritmo no es compatible de forma nativa con la transmisión. En consecuencia, se generará un conjunto de datos temporal en memoria, lo que puede causar tiempos de procesamiento significativos al abrir.
