NOMBRE

gdal-raster-calc - Realiza cálculos píxel a píxel en un ráster

Añadido en la versión 3.11.

SINOPSIS

Uso: gdal raster calc [OPCIONES] <ENTRADAS>... <SALIDA>
Realiza álgebra de ráster
Argumentos posicionales:
  -i, --input <ENTRADAS>                                   Conjuntos de datos ráster de entrada [1.. valores] [requerido]
  -o, --output <SALIDA>                                    Conjunto de datos ráster de salida [requerido]
Opciones comunes:
  -h, --help                                               Muestra el mensaje de ayuda y sale
  --json-usage                                             Muestra el uso como documento JSON y sale
  --config <CLAVE>=<VALOR>                                 Opción de configuración [puede repetirse]
  -q, --quiet                                              Modo silencioso (sin barra de progreso)
Opciones:
  -f, --of, --format, --output-format <FORMATO-SALIDA>     Formato de salida ("GDALG" permitido)
  --co, --creation-option <CLAVE>=<VALOR>                  Opción de creación [puede repetirse]
  --overwrite                                              Si se permite sobrescribir la salida existente
                                                           Mutuamente exclusivo con --append
  --append                                                 Añadir como subconjunto de datos a la salida existente
                                                           Mutuamente exclusivo con --overwrite
  --ot, --datatype, --output-data-type <TIPO-DATOS-SALIDA> Tipo de datos de salida. TIPO-DATOS-SALIDA=Byte|Int8|UInt16|Int16|UInt32|Int32|UInt64|Int64|CInt16|CInt32|Float16|Float32|Float64|CFloat32|CFloat64
  --no-check-srs                                           No comprueba la consistencia de los sistemas de referencia espacial de entrada
  --no-check-extent                                        No comprueba la consistencia de las extensiones de entrada
  --propagate-nodata                                       Si se deben establecer los píxeles al valor NoData de salida cuando alguno de los píxeles de entrada es NoData
  --calc <CALC>                                            Expresión(es) a evaluar [1.. valores] [requerido]
  --dialect <DIALECTO>                                     Dialecto de la expresión. DIALECTO=muparser|builtin (predeterminado: muparser)
  --flatten                                                Genera un ráster de salida de una sola banda por expresión, incluso si los conjuntos de datos de entrada son multibanda
  --nodata <NODATA>                                        Asigna un valor nodata especificado a las bandas de salida ('none', valor numérico, 'nan', 'inf', '-inf')
Opciones avanzadas:
  --if, --input-format <FORMATO-ENTRADA>                   Formatos de entrada [puede repetirse]
  --oo, --open-option <CLAVE>=<VALOR>                      Opciones de apertura [puede repetirse]

DESCRIPCIÓN

gdal raster calc realiza cálculos píxel a píxel en uno o más conjuntos de datos GDAL de entrada. Los cálculos pueden realizarse de forma anticipada, escribiendo los resultados en un formato ráster convencional, o de forma diferida, escritos como un conjunto de bandas derivadas en un VRT (Conjunto de datos virtual).

La lista de conjuntos de datos GDAL de entrada puede especificarse al final de la línea de comandos o ponerse en un archivo de texto (una entrada por línea) para listas muy largas. Si se usa más de un conjunto de datos de entrada, debe ir precedido de un nombre con el que se referirá en el cálculo, por ejemplo A=my_data.tif. (Si se usa un solo conjunto de datos, se referirá con la variable X en las fórmulas.)

A partir de GDAL 3.12, también es posible usar una función de píxel C++ de VRT (como sum, mean, min, max) especificando --dialect como builtin.

Las entradas deben tener el mismo sistema de referencia espacial y deben cubrir la misma extensión espacial, pero no se requiere que tengan la misma resolución espacial. La comprobación de la extensión espacial puede desactivarse con --no-check-extent, en cuyo caso las entradas deben tener las mismas dimensiones. La comprobación del sistema de referencia espacial puede desactivarse con --no-check-srs.

Desde GDAL 3.12, este algoritmo puede formar parte de un pipeline de gdal o gdal raster pipeline.

Las siguientes opciones están disponibles:

-f, --of, --format, --output-format <FORMATO-SALIDA>
Qué formato ráster de salida usar. Los valores permitidos pueden darse con gdal --formats | grep raster | grep rw | sort
--co <NOMBRE>=<VALOR>
Muchos formatos tienen una o más opciones de creación opcionales que pueden usarse para controlar detalles sobre el archivo creado. Por ejemplo, el controlador GeoTIFF admite opciones de creación para controlar la compresión y si el archivo debe estar en mosaico.

Puede repetirse.

Las opciones de creación disponibles varían según el controlador de formato, y algunos formatos simples no tienen opciones de creación en absoluto. Una lista de opciones admitidas para un formato puede listarse con la --formats opción de línea de comandos, pero la documentación del formato es la fuente definitiva de información sobre las opciones de creación del controlador. Véase Controladores de ráster documentación específica del formato para las opciones de creación válidas de cada formato.

--overwrite
Permite al programa sobrescribir el archivo o conjunto de datos de destino existente. De lo contrario, por defecto, gdal da error si el archivo o conjunto de datos de destino ya existe.
-i [<nombre>=]<entrada>
Selecciona un conjunto de datos de entrada a procesar. Si se proporciona más de un conjunto de datos de entrada, cada conjunto de datos debe ir precedido de un nombre con el que se referirá en --calc.
--calc
Una expresión a evaluar usando la biblioteca de análisis matemático muparser . La expresión puede referirse a bandas individuales de cada entrada (por ejemplo, X[1] + 3) o puede aplicarse a todas las bandas de una entrada (X + 3).

Hay dos métodos por los cuales una expresión puede aplicarse a múltiples bandas. En el método predeterminado, la expresión se aplica a cada banda individualmente, resultando en una banda de salida para cada banda de entrada. Por ejemplo, con una entrada de tres bandas X, la expresión --calc "X+3" se expandiría en --calc "X[1]+3" --calc "X[2]+3" --calc "X[3]+3". Si la expresión contiene una referencia a todas las bandas de múltiples entradas, esas entradas deben tener el mismo número de bandas, o una sola banda. Por ejemplo, si las entradas A y B tienen tres bandas cada una, y la entrada C tiene una sola banda, entonces el argumento --calc "A + B + C" es equivalente a --calc "A[1] + B[1] + C[1]" --calc "A[2] + B[2] + C[1]" --calc "A[3] + B[3] + C[1]". De manera similar, --calc "sum(A,B,C)" se expandiría a --calc "sum(A[1], B[1], C[1]" --calc "sum(A[2], B[2], C[1])" --calc "sum(A[3], B[3], C[1])".

En el segundo método, que se activa con --flatten, las funciones agregadas (sum, avg, miny max) invocadas en múltiples bandas se aplicarán a todas las bandas en agregado. En este caso, sum(A) se expande en sum(A[1], A[2], A[3]), y sum(A,C) se expande en sum(A[1], A[2], A[3], C[1]). Si la expresión consiste _solo_ en funciones agregadas, esto producirá una sola banda de salida sin importar cuántas bandas de entrada haya. Sin embargo, si la expresión contiene una referencia no agregada a todas las bandas de una entrada, entonces aún se producirá una banda de salida para cada banda de entrada. Un ejemplo simple es la expresión A / sum(A), que produciría un ráster de N bandas donde cada banda de salida contiene la fracción de la banda de entrada del total.

Se pueden especificar múltiples cálculos; se producirán banda(s) de salida para cada expresión en el orden en que se proporcionan.

Los rásteres de entrada se convertirán a números de punto flotante de 64 bits antes de realizar los cálculos.

A partir de GDAL 3.12, también es posible usar una función de píxel C++ de VRT (como sum, mean, min, max) especificando --dialect como builtin. Los argumentos de las funciones se pasan dentro de paréntesis, como sum(k=1), min(propagateNoData=true) o interpolate_linear(t0=1,dt=1,t=10).

--dialect muparser|builtin
Añadido en la versión 3.12.

Especifica el motor de expresiones utilizado para interpretar el valor de --calc. El valor predeterminado es muparser.

--flatten
Añadido en la versión 3.12.

Genera un ráster de salida de una sola banda por expresión, incluso si los conjuntos de datos de entrada son multibanda.

Para el dialecto muparser predeterminado, usar el nombre de un ráster de entrada (digamos A) es equivalente a A[1],A[2],...,A[n]. Esta sintaxis funciona con las funciones muparser min, max, sum y avg .

Por ejemplo, consideremos 2 rásteres A y B con 3 bandas cada uno, entonces --flatten --calc "avg(A)-avg(B)" es equivalente a --calc "avg(A[1],A[2],A[3])-avg(B[1],B[2],B[3])"

Y --flatten --dialect=builtin --calc mean calculará una sola banda con el promedio de las 4 bandas de entrada.

--no-check-extent
No verifica que los rásteres de entrada tengan la misma extensión espacial. En su lugar, se requerirá que los rásteres de entrada tengan las mismas dimensiones. La geotransformación de la primera entrada se asignará a la salida.
--no-check-srs
No comprueba la consistencia de los sistemas de referencia espacial de las entradas. Se asumirá que todas las entradas tienen el sistema de referencia espacial de la primera entrada, y este sistema de referencia espacial se utilizará para la salida.
--nodata
Añadido en la versión 3.12.

Establece el valor NoData para el conjunto de datos de salida. Puede establecerse en "none" para dejar el valor NoData sin definir. Si --nodata no se especifica, gdal raster calc usará un valor NoData del primer conjunto de datos de origen que tenga uno.

--propagate-nodata
Añadido en la versión 3.12.

Si se establece, un valor NoData en cualquier conjunto de datos de entrada utilizado en una expresión hará que el valor de salida sea NoData.

SALIDA GDALG (CONJUNTO DE DATOS EN TIEMPO REAL / EN FLUJO)

Este programa admite la serialización de la línea de comandos como un archivo JSON utilizando el formato de salida GDALG . El archivo resultante puede abrirse luego como un conjunto de datos ráster utilizando el controlador GDALG: GDAL Streamed Algorithm , y aplicar la canalización especificada de manera en tiempo real / en flujo.

EJEMPLOS

Ejemplo 1: Suma por banda de tres archivos

gdal raster calc -i "A=file1.tif" -i "B=file2.tif" -i "C=file3.tif" --calc "A+B+C" -o out.tif

Ejemplo 2: Promedio por conjunto de datos de todas las bandas de cada conjunto de datos

gdal raster calc -i "A=file1.tif" -i "B=file2.tif" -i "C=file3.tif" --flatten --calc "avg(A)" --calc "avg(B)" --calc "avg(C)" -o out.tif

Ejemplo 3: Máximo por banda de tres archivos

gdal raster calc -i "A=file1.tif" -i "B=file2.tif" -i "C=file3.tif" --calc "max(A,B,C)" -o out.tif

Ejemplo 4: Establecer los valores iguales a cero y por debajo a NaN

gdal raster calc -i "A=input.tif" -o result.tif --calc="A > 0 ? A : NaN"

Ejemplo 5: Calcular el promedio (como una sola banda) de todas las bandas de dos conjuntos de datos de entrada

gdal raster calc -i A=input1.tif -i B=input2.tif -o result.tif --flatten --calc=mean --dialect=builtin
