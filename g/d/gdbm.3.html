DESCRIPCIÓN

GNU dbm es una biblioteca de rutinas que gestiona archivos de datos que contienen pares clave/datos. El acceso proporcionado es el de almacenar, recuperar y eliminar por clave y unatraviesa no ordenada de todas las claves. Se permite a un proceso utilizar varios archivos de datos al mismo tiempo.

Apertura de una base de datos

Un proceso que abre un archivo gdbm se designa como "lector" o "escritor". Solo un escritor puede abrir un archivo gdbm y muchos lectores pueden abrir el archivo. Los lectores y escritores no pueden abrir el archivo gdbm al mismo tiempo. El procedimiento para abrir un archivo gdbm es:

GDBM_FILE gdbm_open (const char *name, int block_size,
int flags, int mode, void (*fatal_func)(const char *));
Name es el nombre del archivo (el nombre completo, gdbm no añade ningún carácter a este nombre).
block_size es el tamaño de una transferencia única desde el disco a la memoria. Si el valor es inferior a 512, se utiliza el tamaño de bloque del sistema de archivos. El tamaño se ajusta para que el bloque pueda contener un número exacto de entradas de directorio, de modo que el tamaño efectivo del bloque pueda ser ligeramente superior al solicitado. Este ajuste se deshabilita si se utiliza el *flag* GDBM_BSEXACT.
El parámetro flags es una máscara de bits, compuesta por el modo de acceso y uno o más *flags* modificadores. El modo de acceso designa al proceso como lector o escritor y debe ser uno de los siguientes:
GDBM_READER
lector
GDBM_WRITER
escritor
GDBM_WRCREAT
escritor - si la base de datos no existe, crea una nueva
GDBM_NEWDB
escritor - crea una nueva base de datos independientemente de si existe una
Se pueden combinar *flags* adicionales (*modificadores*) con estos valores mediante OR a nivel de bits. No todos son significativos con todos los modos de acceso.
Los *flags* válidos para cualquier valor de modo de acceso son:
GDBM_CLOEXEC
Establece el *flag* *close-on-exec* en el descriptor de archivo de la base de datos.
GDBM_NOLOCK
Impide que la biblioteca realice cualquier bloqueo en el archivo de la base de datos.
GDBM_NOMMAP
Instruye a gdbm_open para deshabilitar el uso de mmap(2).
GDBM_PREREAD
Al mapear el archivo GDBM a memoria, lee su contenido inmediatamente, en lugar de cuando se necesite (*prefault reading*). Esto puede ser ventajoso si abres una base de datos de *solo lectura* y vas a realizar muchas búsquedas en ella. En este caso, la base de datos completa se leerá a la vez y las búsquedas operarán sobre una copia en memoria. Por el contrario, no se debe usar GDBM_PREREAD si abres una base de datos (incluso en modo de solo lectura) solo para recuperar un par de claves.

Finalmente, nunca uses GDBM_PREREAD al abrir una base de datos para actualizaciones, especialmente para inserciones: esto degradará el rendimiento.

Este *flag* no tiene efecto si se proporciona GDBM_NOMMAP, o si el sistema operativo no soporta la lectura anticipada. Se sabe que funciona en los kernels de Linux y FreeBSD.

GDBM_XVERIFY
Habilita comprobaciones de consistencia adicionales. Con este *flag*, las eventuales corrupciones de la base de datos se descubren al abrirla, en lugar de cuando se lee una estructura corrupta durante la operación normal. Sin embargo, en bases de datos grandes, puede ralentizar el proceso de apertura.
Los siguientes *flags* adicionales son válidos cuando la base de datos se abre para escritura (GDBM_WRITER, GDBM_WRCREAT o GDBM_NEWDB):
GDBM_SYNC
Hace que todas las operaciones de la base de datos se sincronicen con el disco.

NOTA: esta opción implica una severa degradación del rendimiento y no garantiza necesariamente que el estado resultante de la base de datos sea consistente, por lo que desaconsejamos su uso. Para una discusión sobre cómo garantizar la consistencia de la base de datos con una sobrecarga mínima de rendimiento, véase TOLERANCIA A FALLOS más abajo.

GDBM_FAST
Lo opuesto a GDBM_SYNC: sincroniza las escrituras solo cuando es necesario. Este es el valor predeterminado. Este *flag* se proporciona solo por compatibilidad con versiones anteriores de GDBM.

TOLERANCIA A

FALLOS

Por defecto, GNU dbm no protege la integridad de sus bases de datos contra la corrupción o destrucción debido a fallos como cortes de energía, pánicos del kernel del sistema operativo o caídas del proceso de la aplicación. Dichos fallos podrían dañar o destruir la base de datos

subyacente.

A partir de la versión 1.21, GNU dbm incluye un mecanismo que, si se usa correctamente, permite la recuperación post-fallo a un estado consistente de la base de datos subyacente. Este mecanismo requiere soporte del SO y del sistema de archivos y debe solicitarse cuando se compila gdbm. El mecanismo de tolerancia a fallos es una característica de "opción pura", en el sentido de que no tiene ningún efecto excepto en aquellas aplicaciones que lo solicitan explícitamente. Para más detalles, vea el capítulo Tolerancia a Fallos en el manual d

e G
DBM.

GDBM incluye una biblioteca de compatibilidad libgdbm_compat, para usar con programas que esperan las interfaces tradicionales de UNIX dbm o ndbm, como, por ejemplo, Sendmail. La biblioteca es opcional y por lo tanto puede estar ausente en algunas distribuciones

binarias.

Dado que la discusión detallada de la API de compatibilidad está fuera del alcance de este documento, a continuación proporcionamos solo una referencia corta. Para detalles, véase el Manual de GDBM, capítulo Compatibilidad con dbm y ndbm es

tándar.

Rutinas de compatibilidad con

DBM

En el modo de compatibilidad con dbm solo se puede abrir un archivo a la vez. Se asume que todos los usuarios son escritores. Si el archivo de la base de datos es de solo lectura, fallará como escritor, pero se abrirá como lector. Todos los punteros devueltos en las estructuras datum apuntan a datos que la biblioteca de compatibilidad liberará. Deben tratarse como punteros estáticos (como lo hace el dbm UNIX estándar)
