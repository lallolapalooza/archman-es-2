NOMBRE

gdal-vsi-sync - Sincroniza un archivo/directorio de origen y destino ubicado en la Interfaz de Sistema de Archivos Virtual de GDAL (VSI)

Añadido en la versión 3.11.

SINOPSIS

Uso: gdal vsi sync [OPCIONES] <ORIGEN> <DESTINO>
Sincroniza un archivo/directorio de origen y destino ubicado en la Interfaz de Sistema de Archivos Virtual de GDAL (VSI).
Argumentos posicionales:
  --source <ORIGEN>                Nombre del archivo o directorio de origen [requerido]
  --destination <DESTINO>          Nombre del archivo o directorio de destino [requerido]
Opciones comunes:
  -h, --help                       Muestra el mensaje de ayuda y sale
  --json-usage                     Muestra el uso como un documento JSON y sale
  --config <CLAVE>=<VALOR>           Opción de configuración [puede repetirse]
  -q, --quiet                      Modo silencioso (sin barra de progreso)
Opciones:
  -r, --recursive                  Sincroniza recursivamente
  --strategy <ESTRATEGIA>          Estrategia de sincronización. ESTRATEGIA=timestamp|ETag|overwrite (por defecto: timestamp)
  -j, --num-threads <NUM-HILOS>    Número de trabajos (o ALL_CPUS)

DESCRIPCIÓN

gdal vsi sync sincroniza archivos y directorios ubicados en los *Sistemas de Archivos Virtuales de GDAL (comprimidos, alojados en red, etc.): /vsimem, /vsizip, /vsitar, /vsicurl, ...*.

Este comando es análogo al comando rsync de UNIX. En la implementación actual, rsync sería más eficiente para copiar archivos locales, pero el principal interés de gdal vsi sync es cuando el origen o el destino es un sistema de archivos remoto como /vsis3/ o /vsigs/, en cuyo caso puede tener en cuenta las marcas de tiempo de los archivos (o opcionalmente el ETag/MD5Sum) para evitar operaciones de copia innecesarias.

Esto se implementa de manera eficiente para:

  • sistema de archivos local <--> sistema de archivos remoto.
  • sistema de archivos remoto <--> sistema de archivos remoto, donde los sistemas de archivos remotos de origen y destino son los mismos y uno de /vsis3/, /vsigs/ o /vsiaz/. O cuando el destino es /vsiaz/ y el origen es /vsis3/, /vsigs/, /vsiadls/ o /vsicurl/

De forma similar al comportamiento de rsync, si el nombre del archivo de origen termina con una barra inclinada, significa que el contenido del directorio debe copiarse, pero no el nombre del directorio. Por ejemplo, asumiendo que /home/even/foo contiene un archivo bar, gdal vsi sync -r /home/even/foo/ /mnt/media creará un archivo /mnt/media/bar. Mientras que gdal vsi sync -r /home/even/foo /mnt/media creará un directorio /mnt/media/foo que contiene un archivo bar.

Esto se implementa mediante VSISync().

Opciones

-r, --recursive
Sincroniza recursivamente.
--strategy timestamp|ETag|overwrite
Determina qué criterio se utiliza para determinar si un archivo de destino debe ser reemplazado cuando ya existe y tiene el mismo tamaño de archivo que el origen. Solo se aplica cuando el origen o el destino es un sistema de archivos de red.

El valor por defecto es timestamp (similar a cómo funciona aws s3 sync). Para una operación de subida, un archivo remoto se reemplaza si tiene un tamaño diferente o si es más antiguo que el origen. Para una operación de descarga, un archivo local se reemplaza si tiene un tamaño diferente o si es más reciente que el archivo remoto.

La estrategia ETag asume que la metadato ETag del archivo remoto es el MD5Sum del contenido del archivo, lo cual solo es cierto en el caso de /vsis3/ para archivos que no utilizan cifrado del lado del servidor KMS y que se subieron en una sola operación PUT (por lo tanto, menores de 50 MB dado el valor por defecto utilizado por GDAL). Solo debe usarse para /vsis3/, /vsigs/ u otros sistemas de archivos que utilicen un MD5Sum como ETAG.

La estrategia overwrite sobrescribirá siempre el archivo de destino con el del origen.

-j, --num-threads <valor>
Número de trabajos a ejecutar a la vez

EJEMPLOS

Ejemplo 1: Sincronizar un directorio local en un bucket S3

$ gdal vsi sync -r mi_directorio/ /vsis3/bucket/mi_directorio
