DESCRIPCIÓ

N

El gdaldem genera rásteres de salida utilizando diferentes algoritmos para el análisis del

terreno.

En general, asume que las unidades x, y e z son idénticas. Sin embargo, para el cálculo de sombreado y pendiente, a partir de GDAL 3.11, si no se especifica ninguna de -scale, -xscale y -yscale, y el CRS es un CRS geográfico o proyectado, gdaldem determinará automáticamente la relación apropiada a partir de las unidades del CRS, así como el valor potencial de las unidades de la banda del ráster (como lo devuelve GDALRasterBand::GetUnitType(), si es metro, pie internacional o pie de encuesta de EE. UU.). Tenga en cuenta que para los CRS geográficos, el resultado para los conjuntos de datos de origen en latitudes altas puede ser incorrecto, y podría ser necesaria una reproyección previa a una proyección

polar.

Para el cálculo de sombreado y pendiente, si las unidades x (este-oeste) y y (norte-sur) son idénticas, pero las unidades z (elevación) son diferentes, la opción -scale (o -xscale y -yscale) se puede usar para establecer la relación de las unidades verticales con las horizontales. Para proyecciones LatLong cerca del ecuador, donde las unidades de latitud y las de longitud son similares, las unidades de elevación (z) se pueden convertir para que sean compatibles usando scale=370400 (si la elevación está en pies) o scale=111120 (si la elevación está en metros). Para ubicaciones que no estén cerca del ecuador, sería mejor reproyectar su cuadrícula usando gdalwarp antes de usar

gdaldem.

Este comando genera un ráster de punto flotante de 32 bits con valores entre 0° y 360° que representan el acimut hacia el que se orientan las pendientes. La definición del acimut es tal que: 0° significa que la pendiente está orientadaing el Norte, 90° está orientado hacia el Este, 180° está orientado hacia el Sur y 270° está orientado hacia el Oeste (suponiendo que la parte superior de tu ráster de entrada esté orientada al norte). El valor de aspecto -9999 se utiliza como valor nodata para indicar un aspecto indefinido en áreas planas con

pendiente=0.

f

Este comando genera un ráster de 3 bandas (RGB) o 4 bandas (RGBA) con valores calculados a partir de la elevación y un archivo de configuración de color basado en texto, que contiene la asociación entre varios valores de elevación y el color correspondiente deseado. Se pueden usar las opciones -exact_color_entry o -nearest_color_entry para evitar esa interpolación lineal para valores que no coincidan con un índice del archivo de configuración de

El archivo de configuración de color basado en texto generalmente contiene 4 columnas por línea: el valor de elevación y los componentes Rojo, Verde, Azul correspondientes (entre 0 y 255). TR

Este comando genera un ráster de una banda con valores calculados a partir de la elevación. TRI significa Índice de Rugosidad del Terreno (Terrain Ruggedness Index), que mide la diferencia entre un píxel central y sus celdas

circundantes.

El valor -9999 se utiliza como valor nodata de

salida.

La siguiente opción está

disponible:
-alg
Wilson|Riley
A partir de GDAL 3.3, el algoritmo Riley (ver Riley, S.J., De Gloria, S.D., Elliot, R. (1999): A Terrain Ruggedness that Quantifies Topographic Heterogeneity. Intermountain Journal of Science, Vol.5, No.1-4, pp.23-27) está disponible y es el nuevo valor por defecto. Este algoritmo usa la raíz cuadrada de la suma de los cuadrados de la diferencia entre un píxel central y sus celdas circundantes. Esto se recomienda para casos de uso terrestres.

El algoritmo Wilson (ver Wilson et

al 2007, Marine Geodesy 30:3-35)
usa la diferencia media entr
