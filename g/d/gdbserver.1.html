DESCRIPCIÓ

N

gdbserver es un programa que le permite ejecutar GDB en una máquina diferente a la que ejecuta el programa que se está

depurando.

Uso (lado del servidor (objetivo))

:

Primero, necesita tener una copia del programa que desea depurar en el sistema objetivo. El programa se puede eliminar de símbolos para ahorrar espacio si es necesario, ya que gdbserver no se preocupa por los símbolos. Todo el manejo de símbolos lo realiza el GDB que se ejecuta en el sistema

host.

Para usar el servidor, inicie sesión en el sistema objetivo y ejecute el programa gdbserver. Debe indicarle (a) cómo comunicarse con GDB, (b) el nombre de su programa y (c) sus argumentos. La sintaxis general

es: 
objetivo> gdbserver <comm> <programa> [<args> ...
]

Por ejemplo, usando un puerto serie, podría

decir: 
objetivo> gdbserver /dev/com1 emacs foo.
txt

Esto le dice a gdbserver que depure emacs con el argumento foo.txt, y que se comunique con GDB a través de /dev/com1. gdbserver ahora espera pacientemente a que el GDB host se comunique con

él.

Para usar una conexión TCP, podría

decir: 
objetivo> gdbserver host:2345 emacs foo.
txt

Esto dice prácticamente lo mismo que el ejemplo anterior, excepto que vamos a comunicarnos con el GDB "host" a través de TCP. El argumento "host:2345" significa que esperamos ver una conexión TCP desde "host" al puerto TCP local 2345. (Actualmente, la parte "host" se ignora.) Puede elegir cualquier número que desee para el número de puerto siempre que no entre en conflicto con ningún puerto TCP existente en el sistema objetivo. Este mismo número de puerto debe usarse en el comando "target remote" del GDB host, que se describirá brevemente. Tenga en cuenta que si eligió un número de puerto que entra en conflicto con otro servicio, gdbserver imprimirá un mensaje de error y

saldrá.

gdbserver también puede adjuntarse a programas en ejecución. Esto se logra a través del argumento --attach. La sintaxis

es: 
objetivo> gdbserver --attach <comm>
<pid>

pid es el ID de proceso de un proceso en ejecución actualmente. No es necesario apuntar gdbserver a un binario para el proceso en

ejecución.

Para iniciar "gdbserver" sin proporcionar un comando inicial para ejecutar o un ID de proceso al que adjuntarse, use la opción de línea de comandos --multi. En tal caso, debe conectarse usando "target extended-remote" para iniciar el programa que desea

depurar. 
objetivo> gdbserver --multi
<comm>

Uso (lado host)

:

Necesita una copia sin eliminar de símbolos del programa objetivo en su sistema host, ya que GDB necesita examinar sus tablas de símbolos y demás. Inicie GDB como lo haría normalmente, con el programa objetivo como primer argumento. (Puede necesitar usar la opción --baud si la línea serie está funcionando a cualquier velocidad diferente de 9600 baudios.) Es decir, "gdb TARGET-PROG", o "gdb --baud BAUD TARGET-PROG". Después de eso, el único comando nuevo que necesita conocer es "target remote" (o "target extended-remote"). Su argumento es o bien un nombre de dispositivo (usualmente un dispositivo serie, como /dev/ttyb), o un descriptor "HOST:PORT". Por

ejemplo: 
(gdb) target remote
/dev/ttyb

se comunica con el servidor a través de la línea serie /dev/ttyb,

y: 
(gdb) target remote the-target:
2345

se comunica a través de una conexión TCP al puerto 2345 en el host `the-target', donde previamente inició gdbserver con el mismo número de puerto. Tenga en cuenta que para las conexiones TCP, debe iniciar gdbserver antes de usar el comando `target remote', de lo contrario puede obtener un error que se parece a `Connection

refused'.

gdbserver también puede depurar múltiples inferiores a la vez, descrito en el manual de GDB en el nodo "Inferiors Connections and Programs" -- comando de shell "info -f gdb -n 'Inferiors Connections and Programs'". En tal caso, use la variante del comando GDB "extended-remote"

: 
(gdb) target extended-remote the-target:
2345

La opción de gdbserver --multi puede o no

usarse en
tal caso.

OPCIONE

S

Hay tres modos diferentes para invocar gdbserver

:
  • Depurar un programa específico especificado por su nombre de programa: 
    gdbserver <comm> <prog> [<args>
    ...]

    El parámetro comm especifica cómo debe el servidor comunicarse con GDB; es o bien un nombre de dispositivo (para usar una línea serie), un número de puerto TCP (":1234"), o "-" o "stdio" para usar stdin/stdout de "gdbserver". Especifique el nombre del programa a depurar en prog. Cualquier argumento restante se pasará al programa tal cual. Cuando el programa salga, GDB cerrará la conexión, y "gdbserver

    " sa
    • ldrá.
  • Depurar un programa específico especificando el ID de proceso de un programa en ejecución: 
    gdbserver --attach <comm>
    <pid>

    El parámetro comm es como se describió anteriormente. Proporcione el ID de proceso de un programa en ejecución en pid; GDB hará todo lo demás. Al igual que con el modo anterior, cuando el proceso pid salga, GDB cerrará la conexión, y "gdbserver

    " sa
    • ldrá.
  • Modo multiproceso -- depurar más de un programa/proceso: 
    gdbserver --multi
    <comm>

    En este modo, GDB puede instruir a gdbserver qué comando(s) ejecutar. A diferencia de los otros 2 modos, GDB no cer

    rará la conexión cuando un proceso e
    • n depuración salga, por lo que puede depurar
varios procesos en la misma sesión.

Instruye a "gdbserver" para mostrar información de estado extra sobre el proceso de depuración. Esta opción está destinada para el desarrollo de "gdbserver" y para informes de errores a los desarrolladores.

Cada opción es el nombre de un componente para el que debe habilitarse la depuración. La lista de opciones posibles es all, threads, event-loop, remote. La opción especial all habilita todos los componentes. La lista de opciones se procesa de izquierda a derecha, y una opción puede tener el prefijo del carácter "-" para deshabilitar la salida para ese componente, por lo que podría

escribir: 
objetivo> gdbserver --debug=all,
-event-loop
