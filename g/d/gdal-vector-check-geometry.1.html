NOMBRE

gdal-vector-check-geometry - Comprueba un conjunto de datos en busca de geometrías inválidas o no simples

Añadido en la versión 3.12.

SINOPSIS

Uso: gdal vector check-geometry [OPCIONES] <ENTRADA> <SALIDA>
Comprueba un conjunto de datos en busca de geometrías inválidas
Argumentos posicionales:
  -i, --input <ENTRADA>                                  Conjuntos de datos vectoriales de entrada [requerido]
  -o, --output <SALIDA>                                 Conjunto de datos vectoriales de salida [requerido]
Opciones comunes:
  -h, --help                                           Muestra el mensaje de ayuda y sale
  --json-usage                                         Muestra el uso como documento JSON y sale
  --config <CLAVE>=<VALOR>                             Opción de configuración [puede repetirse]
  -q, --quiet                                          Modo silencioso (sin barra de progreso)
Opciones:
  -l, --layer, --input-layer <CAPA-ENTRADA>            Nombre(s) de capa(s) de entrada [puede repetirse]
  -f, --of, --format, --output-format <FORMATO-SALIDA>  Formato de salida ("GDALG" permitido)
  --co, --creation-option <CLAVE>=<VALOR>              Opción de creación [puede repetirse]
  --lco, --layer-creation-option <CLAVE>=<VALOR>       Opción de creación de capa [puede repetirse]
  --overwrite                                          Indica si se permite sobrescribir la salida existente
  --update                                             Indica si se abre el conjunto de datos existente en modo de actualización
  --overwrite-layer                                    Indica si se permite sobrescribir la salida existente
  --append                                             Indica si se permite añadir a una capa existente
                                                       Excluyente mutuamente con --upsert
  --output-layer <CAPA-SALIDA>                         Nombre de la capa de salida
  --skip-errors                                        Omite errores al escribir elementos
  --include-valid                                      Incluye las entradas válidas en la salida, con geometría vacía
  --geometry-field <CAMPO-GEOMETRÍA>                   Nombre del campo de geometría a comprobar
Opciones avanzadas:
  --if, --input-format <FORMATO-ENTRADA>               Formatos de entrada [puede repetirse]
  --oo, --open-option <CLAVE>=<VALOR>                  Opciones de apertura [puede repetirse]
  --output-oo, --output-open-option <CLAVE>=<VALOR>    Opciones de apertura de salida [puede repetirse]
  --upsert                                             Actualiza elementos (implica 'append')
                                                       Excluyente mutuamente con --append

DESCRIPCIÓN

gdal vector check-geometry comprueba que los elementos individuales de un conjunto de datos sean válidos y simples de acuerdo con el OGC estándar de Entidades Simples. Para cada elemento inválido o no simple, emitirá una descripción y, en la mayoría de los casos, una ubicación puntual del error.

Se realizan las siguientes comprobaciones, dependiendo del tipo de geometría de entrada:

  • Los Polígonos y MultiPolígonos se comprueban en busca de validez. Se reportará un único punto de error incluso si hay múltiples causas de invalidez.
  • Las LineStrings y MultiLineStrings se comprueban en busca de simplicidad. Se reportarán todas las ubicaciones de auto-intersección si GDAL está compilado usando la versión 3.14 o posterior de la biblioteca GEOS. Con versiones anteriores, las ubicaciones de auto-intersección no se reportan.
  • A las GeometryCollections se les comprueba que sus elementos individuales sean válidos / simples. Se reportará un único punto de error incluso si hay múltiples causas de invalidez.
  • Otros tipos de geometría no se comprueban.

La comprobación de validez/simplicidad la realiza la biblioteca GEOS y debería ser consistente con los resultados de software como PostGIS, QGIS y shapely que también usan esa biblioteca. GEOS no considera los puntos repetidos como una causa de invalidez o no simplicidad.

ADVERTENCIA:

Las geometrías curvas se linealizan antes de convertirlas a GEOS. Las geometrías linealizadas pueden ser válidas/simples donde las geometrías originales no lo son, y viceversa.

Opciones estándar

--geometry-field
Especifica el nombre del campo de geometría a probar, para capas que tienen múltiples campos de geometría. Por defecto se usará el primer campo de geometría.
--include-valid
Incluye en la salida los elementos con geometrías válidas/simples, manteniendo una correspondencia 1:1 entre los elementos de entrada y de salida.
-f, --of, --format, --output-format <FORMATO-SALIDA>
Qué formato vectorial de salida usar. Los valores permitidos pueden darse con gdal --formats | grep vector | grep rw | sort
--co <NOMBRE>=<VALOR>
Muchos formatos tienen una o más opciones de creación de conjuntos de datos opcionales que pueden usarse para controlar detalles sobre el archivo creado. Por ejemplo, el controlador GeoPackage admite opciones de creación para controlar la versión.

Puede repetirse.

Las opciones de creación de conjuntos de datos disponibles varían según el controlador de formato, y algunos formatos simples no tienen opciones de creación en absoluto. Una lista de las opciones admitidas para un formato se puede listar con la opción de línea de comandos --formats pero la documentación del formato es la fuente definitiva de información sobre las opciones de creación del controlador. Vea Controladores vectoriales la documentación específica del formato para las opciones de creación legales de cada formato.

Tenga en cuenta que las opciones de creación de conjuntos de datos son diferentes de las opciones de creación de capas.

-lco <NOMBRE>=<VALOR>
Opción de creación de capa (específica del formato)
--overwrite
Permite al programa sobrescribir el archivo o conjunto de datos de destino existente. De lo contrario, por defecto, gdal produce un error si el archivo o conjunto de datos de destino ya existe.

Opciones avanzadas

--oo <NOMBRE>=<VALOR>
Opción de apertura de conjunto de datos (específica del formato).

Puede repetirse.

--if <formato>
Nombre del formato/controlador que se intentará usar para abrir el archivo(s) de entrada. Generalmente no es necesario especificarlo, pero puede usarse para omitir la detección automática del controlador, cuando falla en seleccionar el controlador apropiado. Esta opción puede repetirse varias veces para especificar varios controladores candidatos. Tenga en cuenta que no fuerza a esos controladores a abrir el conjunto de datos. En particular, algunos controladores tienen requisitos sobre las extensiones de archivo.

Puede repetirse.

SALIDA GDALG (CONJUNTO DE DATOS EN TIEMPO REAL / TRANSMITIDO)

Este programa admite la serialización de la línea de comandos como un archivo JSON usando el formato de salida GDALG El archivo resultante puede luego abrirse como un conjunto de datos vectoriales usando el GDALG: Algoritmo Transmitido de GDAL controlador, y aplicar la tubería especificada de una manera en tiempo real / transmitida.

NOTA:

Sin embargo, este algoritmo no es nativamente compatible con la transmisión. En consecuencia, se generará un conjunto de datos temporal en memoria, lo que puede causar un tiempo de procesamiento significativo al abrir.

EJEMPLOS

Ejemplo 1: Imprimir las ubicaciones de invalidez en la consola

$ gdal vector check-geometry ne_10m_admin_0_countries.shp \
         --quiet \
         -f CSV \
         --lco GEOMETRY=AS_XY \
         --lco SEPARATOR=TAB \
         /vsistdout/
# X      Y       error
# 35.6210871060001       23.1392929140001        Auto-intersección de Anillos
