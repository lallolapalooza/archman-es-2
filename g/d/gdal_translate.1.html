Paquete: gdal

GDAL_TRANSLATE(1) GDAL GDAL_TRANSLATE(1)

NOMBRE

gdal_translate - Convierte datos raster a diferentes formatos.

SINOPSIS

Uso: gdal_translate [--help] [--long-usage] [--help-general]
                      [-ot Byte|Int8|[U]Int{16|32|64}|CInt{16|32}|[C]Float{32|64}]
                      [-if <formato>]... [-of <formato_salida>] [--quiet]
                      [-b <banda>]... [-mask <máscara>] [-expand gray|rgb|rgba]
                      [[-strict]|[-not_strict]]
                      [-outsize <tamaño_x[%]|0> <tamaño_y[%]|0>] [-tr <res_x> <res_y>]
                      [-ovr <nivel>|AUTO|AUTO-<n>|NONE] [-sds]
                      [-r nearest,bilinear,cubic,cubicspline,lanczos,average,mode]
                      [[-scale [<min_fuente> <max_fuente> [<min_destino> <max_destino>]]]...|
                      [-scale_X [<min_fuente> <max_fuente> [<min_destino> <max_destino>]]]...|
                      [-unscale]]
                      [[-exponent <valor>]|[-exponent_X <valor>]...]
                      [-srcwin <desp_x> <desp_y> <tamaño_x> <tamaño_y>]
                      [-projwin <ulx> <uly> <lrx> <lry>]
                      [-projwin_srs <definición_srs>] [-epo] [-eco] [-a_srs <definición_srs>]
                      [-a_coord_epoch <epoch>] [-a_ullr <ulx> <uly> <lrx> <lry>]
                      [-a_nodata <valor>|none]
                      [-a_gt <gt(0)> <gt(1)> <gt(2)> <gt(3)> <gt(4)> <gt(5)>]
                      [-a_scale <valor>] [-a_offset <valor>] [-nogcp]
                      [-gcp <pixel> <línea> <este> <norte> [<elevación>]]...
                      [-colorinterp {red|green|blue|alpha|gray|undefined|pan|coastal|rededge|nir|swir|mwir|lwir|...},...]
                      [-colorinterp_X {red|green|blue|alpha|gray|undefined|pan|coastal|rededge|nir|swir|mwir|lwir|...}]...
                      [[-stats]|[-approx_stats]]
                      [-norat] [-noxmp] [-co <NOMBRE>=<VALOR>]...
                      [-mo <NOMBRE>=<VALOR>]... [-dmo <DOMINIO>:<CLAVE>=<VALOR>]...
                      [-oo <NOMBRE>=<VALOR>]...
                      <archivo_entrada> <archivo_salida>

DESCRIPCIÓN

La utilidad gdal_translate se puede usar para convertir datos raster entre diferentes formatos, realizando potencialmente algunas operaciones como subconjuntos, remuestreo y reescalado de píxeles en el proceso.

--help
Mostrar este mensaje de ayuda y salir.
--help-general
Proporciona un breve mensaje de uso para las opciones genéricas de línea de comandos de GDAL y sale.
-ot <tipo>
Forzar que las bandas de la imagen de salida tengan un tipo de datos específico compatible con el controlador, que puede ser uno de los siguientes: Byte, Int8, UInt16, Int16, UInt32, Int32, UInt64, Int64, Float32, Float64, CInt16, CInt32, CFloat32 o CFloat64.
-strict
No ser indulgente con las discrepancias y la pérdida de datos al traducir al formato de salida.
-if <formato>
Nombre del formato/controlador que se intentará para abrir el(los) archivo(s) de entrada. Generalmente no es necesario especificarlo, pero puede usarse para omitir la detección automática del controlador cuando falla en seleccionar el controlador apropiado. Esta opción se puede repetir varias veces para especificar varios controladores candidatos. Tenga en cuenta que no obliga a esos controladores a abrir el conjunto de datos. En particular, algunos controladores tienen requisitos sobre las extensiones de archivo.

Añadido en la versión 3.2.

-of <formato>
Seleccionar el formato de salida. Si no se especifica, el formato se adivina por la extensión. Utilice el nombre corto del formato.
-b <banda>
Seleccionar una banda de entrada banda para la salida. Las bandas se numeran a partir de 1. Se pueden usar múltiples opciones -b para seleccionar un conjunto de bandas de entrada para escribir en el archivo de salida, o para reordenar las bandas. banda también puede establecerse como "mask,1" (o simplemente "mask") para referirse a la banda de máscara de la primera banda del conjunto de datos de entrada.
-mask <banda>
Seleccionar una banda de entrada banda para crear la banda de máscara del conjunto de datos de salida. Las bandas se numeran a partir de 1. banda puede establecerse como "none" para evitar copiar la máscara global del conjunto de datos de entrada si existe. De lo contrario, se copia por defecto ("auto"), a menos que la máscara sea un canal alfa, o si se usa explícitamente como una banda regular del conjunto de datos de salida ("-b mask"). banda también puede establecerse como "mask,1" (o simplemente "mask") para referirse a la banda de máscara de la 1ª banda del conjunto de datos de entrada.
-expand gray|rgb|rgba
Para exponer un conjunto de datos de 1 banda con tabla de colores como un conjunto de datos de 3 (RGB) o 4 (RGBA) bandas. Útil para controladores de salida como JPEG, JPEG2000, MrSID, ECW que no admiten conjuntos de datos indexados por color. El valor 'gray' permite expandir un conjunto de datos con una tabla de colores que solo contiene niveles de gris a un conjunto de datos indexado por gris.
-outsize <tamaño_x>[%]|0 <tamaño_y>[%]|0
Establecer el tamaño del archivo de salida. Outsize está en píxeles y líneas a menos que se adjunte '%', en cuyo caso es una fracción del tamaño de la imagen de entrada. Si uno de los 2 valores se establece en 0, su valor se determinará a partir del otro, manteniendo la relación de aspecto del conjunto de datos de origen.
-tr <res_x> <res_y>
Establecer la resolución objetivo. Los valores deben expresarse en unidades georreferenciadas. Ambos deben ser valores positivos. Esto es mutuamente excluyente con -outsize, -a_ullr y -a_gt.
-ovr {<nivel>|AUTO|AUTO-<n>|NONE}
Añadido en la versión 3.6.

Para especificar qué nivel de vista previa del archivo fuente debe usarse. La elección predeterminada, AUTO, seleccionará el nivel de vista previa cuya resolución sea la más cercana a la resolución objetivo. Especifique un valor entero (basado en 0, es decir, 0 = 1er nivel de vista previa) para seleccionar un nivel particular. Especifique AUTO-n donde n es un entero mayor o igual a 1, para seleccionar un nivel de vista previa por debajo del AUTO. O especifique NONE para forzar el uso de la resolución base (puede ser útil si las vistas previas se han generado con un método de remuestreo de baja calidad, y se especifica un método de remuestreo de mayor calidad con -r.)

Cuando -ovr se especifica como un valor entero, y no se especifica ni -outsize ni -tr, el tamaño de la vista previa se utilizará como tamaño de salida.

Cuando se especifica -ovr, los valores de -srcwin deben expresarse como desplazamiento de píxeles y tamaño del conjunto de datos fuente de resolución completa. De manera similar, al usar -outsize con valores porcentuales, estos se refieren al tamaño del conjunto de datos fuente de resolución completa.

-r {nearest|bilinear|cubic|cubicspline|lanczos|average|rms|mode}
Seleccionar un algoritmo de remuestreo.

nearest (por defecto) aplica un resampler de vecino más cercano (muestreo simple).

average calcula el promedio de todos los píxeles contribuyentes que no son NODATA. A partir de GDAL 3.1, es un promedio ponderado que tiene en cuenta correctamente el peso de los píxeles fuente que no contribuyen completamente al píxel de destino.

rms calcula la raíz cuadrática media / media cuadrática de todos los píxeles contribuyentes que no son NODATA (GDAL >= 3.3).

bilinear aplica un kernel de convolución bilineal.

cubic aplica un kernel de convolución cúbica.

cubicspline aplica un kernel de convolución de spline cúbica.

lanczos aplica un kernel de convolución de Lanczos.

mode aplica el modo (el valor más frecuente en la ventana) resampler.

-scale [<min_fuente> <max_fuente> [<min_destino> <max_destino>]]
Reescalar los valores de los píxeles. Si no se especifican los valores de destino, se utilizan los rangos de tipo de datos de salida. Si no se especifican los valores de origen, se calculan a partir de los datos. Es posible especificar varios pares de rangos para cada banda de salida. -scale_X se puede usar para especificar rangos para bandas individuales (donde X es el índice de la banda, comenzando desde 1). Use -unscale para revertir la operación de reescalado aplicada por algunos controladores de formato (por ejemplo, aquellos que almacenan información de factor de escala y compensación).
-exponent <valor>
Elevar los valores de los píxeles a una potencia dada. Es posible especificar varios valores para diferentes bandas de salida (ej. -exponent_X <valor>). Útil para compensar la respuesta no lineal del sensor o del medio.
-srcwin <desp_x> <desp_y> <tamaño_x> <tamaño_y>
Seleccionar una subregión de la entrada para la salida. Los desplazamientos y tamaños se expresan en píxeles de la imagen de entrada.
-projwin <ulx> <uly> <lrx> <lry>
Seleccionar una subregión de la entrada para la salida utilizando las coordenadas del mundo real. Esto es más útil cuando se trabaja con conjuntos de datos georreferenciados. Los límites se especifican en las unidades del SRS de la entrada. Si el SRS de entrada no está definido, se asumirán las unidades de píxeles.
-projwin_srs <definición_srs>
Especifica el SRS en el que se dan las coordenadas -projwin. Si no se especifica, se utilizará el SRS del conjunto de datos de entrada.
-epo
Expande la ventana de recorte de la proyección si es necesario. Esto puede ocurrir si la ventana de recorte de la proyección cruza el meridiano 180. La ventana se expandirá para incluir ambos lados del meridiano 180. Esta opción solo tiene efecto si se usa con -projwin.
-eco
Expande la ventana de recorte de la proyección si es necesario. Esto puede ocurrir si la ventana de recorte de la proyección cruza el meridiano 180. La ventana se expandirá para incluir ambos lados del meridiano 180. Esta opción solo tiene efecto si se usa con -projwin.
-a_srs <definición_srs>
Asigna un Sistema de Referencia Espacial (SRS) al archivo de salida. definición_srs puede ser un nombre de archivo SRS, un código EPSG (ej. EPSG:4269), o una definición WKT.
-a_coord_epoch <epoch>
Asigna una época de coordenadas al SRS de salida. Esto solo es relevante para SRS geodésicos que admiten la época de coordenadas (por ejemplo, para dar cuenta del desplazamiento de las placas tectónicas).
-a_ullr <ulx> <uly> <lrx> <lry>
Establece el límite superior izquierdo (ul) y el límite inferior derecho (lr) del archivo de salida en coordenadas del mundo real. Esto es mutuamente exclusivo con -outsize, -tr, y -a_gt.
-a_nodata <valor>|none
Establece el valor de datos nulos para la banda de salida. Si no se especifica, se intentará inferir el valor de datos nulos de la entrada, o se asumirá que no existe.
-a_gt <gt(0)> <gt(1)> <gt(2)> <gt(3)> <gt(4)> <gt(5)>
Establece la transformación geográfica (affine geotransform) del archivo de salida. Los seis coeficientes de la matriz se proporcionan como un espacio separado. Esto es mutuamente exclusivo con -outsize, -tr, y -a_ullr.
-a_scale <valor>
Establece un factor de escala global para los valores de píxeles de salida. Se puede especificar opcionalmente un factor de escala y un desplazamiento para cada banda usando los parámetros -a_scale y -a_offset. Estos valores se escriben en los metadatos del conjunto de datos si el formato de salida los soporta. Útil para formatos que no admiten tipos de datos de punto flotante.
-a_offset <valor>
Establece un desplazamiento global para los valores de los píxeles de salida. Útil junto con -a_scale.
-nogcp
Borra las coordenadas de puntos de control (GCPs) del conjunto de datos de salida.
-gcp <pixel> <línea> <este> <norte> [<elevación>]
Añade un punto de control geográfico (GCP) al conjunto de datos de salida. Esto se puede hacer varias veces. Los GCPs se utilizan para definir la ubicación de la imagen en ausencia de una transformación geográfica completa.
-colorinterp {red|green|blue|alpha|gray|undefined|pan|coastal|rededge|nir|swir|mwir|lwir|...},...
Establece la interpretación del color para cada banda de salida. Las bandas se enumeran a partir de 1. Por ejemplo, para establecer la banda 1 como roja, la banda 2 como verde y la banda 3 como azul, usaría: -colorinterp red,green,blue. También se pueden especificar valores múltiples para bandas individuales con -colorinterp_X.
-stats
Calcula estadísticas de bandas (mínimo, máximo, media, desviación estándar) para cada banda de entrada, y las escribe en el archivo de salida si el formato lo soporta. Esto puede llevar tiempo para grandes archivos.
-approx_stats
Calcula estadísticas de bandas aproximadas (mínimo, máximo, media, desviación estándar) para cada banda de entrada, y las escribe en el archivo de salida si el formato lo soporta. Esto es más rápido que -stats, ya que solo examina una fracción de los píxeles.
-norat
Evita la copia de la tabla de atributos de la banda (RAT) de la entrada a la salida.
-noxmp
Evita la copia de los metadatos XMP de la entrada a la salida.
-co <NOMBRE>=<VALOR>
Añade opciones específicas del controlador de creación. Vea la documentación del controlador de formato de salida para las opciones disponibles.
-mo <NOMBRE>=<VALOR>
Establece un par clave-valor de metadatos a nivel de conjunto de datos en el archivo de salida. Vea la documentación del controlador de formato de salida para los dominios de metadatos disponibles.
-dmo <DOMINIO>:<CLAVE>=<VALOR>
Establece un par clave-valor de metadatos en un dominio específico (por ejemplo, "ImageDescription", "TIFFTAG_COPYRIGHT"). Vea la documentación del controlador de formato de salida para los dominios de metadatos disponibles.
-oo <NOMBRE>=<VALOR>
Opción de apertura de datos de entrada. Vea la documentación del controlador de formato de entrada para las opciones disponibles.
<archivo_entrada>
El archivo raster de entrada.
<archivo_salida>
El archivo raster de salida.

EJEMPLOS

Convertir un archivo GeoTIFF a un archivo PNG, remuestreando a 500x500 píxeles:

$ gdal_translate -outsize 500 500 input.tif output.png

Crear un archivo GeoTIFF JPEG a partir de un archivo GeoTIFF.

$ gdal_translate -of JPEG -co QUALITY=85 input.tif output.jpg

Extraer una banda específica (la banda 2) de un archivo multi-banda y guardarla como un archivo GeoTIFF independiente.

$ gdal_translate -b 2 input_multiband.tif output_band2.tif

Cambiar el tipo de datos de las bandas de salida a Byte (8 bits sin firmar).

$ gdal_translate -ot Byte input.tif output_byte.tif

Reescalar los valores de la banda 1 de 0-255 a 0-1, y la banda 2 de 0-1000 a 0-100.

$ gdal_translate -ot Float32 \
    -scale_1 0 255 0 1 \
    -scale_2 0 1000 0 100 \
    input.tif output_scaled.tif

Recortar una región de interés utilizando coordenadas de proyección.

$ gdal_translate -projwin -107.5 45.0 -103.0 43.0 input.tif output_roi.tif

Reorientar un archivo de origen a una resolución específica.

$ gdal_translate -tr 30 30 input.tif output_30m.tif

Options
-outdir <directory>
Specifies the output directory. This directory will be created if it does not exist.
-of <format>
Select the output format driver. The default is GeoTIFF (GTiff). Use the short driver name.
-setstats
Set the minimum, maximum, mean, and standard deviation values for each band.
-stats
Compute and set the minimum, maximum, mean, and standard deviation values for each band.
-nomd
Do not copy any metadata from the source dataset.
-mddimension <dimension>
Copy specific metadata dimensions from the source dataset.
-nomdlayer
Do not copy any metadata layers from the source dataset.
-mdlayer <layer>
Copy specific metadata layers from the source dataset.
-co <NAME>=<VALUE>
Many formats have one or more optional Creation Options. These are provided as a list of name = value pairs, separated by spaces. This list follows the -co flag. Format specific details and defaults can be found in the documentation for each format driver. This option can be repeated multiple times.
-a_nodata <value>
Assign a specified nodata value to output bands. It can be set to none to avoid setting a nodata value to the output file if one exists for the source file. Note that, if the input dataset has a nodata value, this does not cause pixel values that are equal to that nodata value to be changed to the value specified with this option.
-a_srs <srs_def>
Override the projection for the output file. Can be used with -a_ullr or -a_gt to specify the extent in this projection.

The coordinate reference systems that can be passed are anything supported by the OGRSpatialReference::SetFromUserInput() call, which includes EPSG Projected, Geographic or Compound CRS (i.e. EPSG:4296), a well known text (WKT) CRS definition, PROJ.4 declarations, or the name of a .prj file containing a WKT CRS definition.

NOTE:

No reprojection is done.
-a_coord_epoch <epoch>
Added in version 3.4.

Assign a coordinate epoch, linked with the output SRS. Useful when the output SRS is a dynamic CRS.

-a_scale <value>
Set band scaling value. No modification of pixel values is done. Note that the -unscale does not take into account -a_scale. You may for example specify -scale 0 1 <offset> <offset+scale> to apply a (offset, scale) tuple, for the equivalent of the 2 steps: gdal_translate input.tif tmp.vrt -a_scale scale -a_offset offset followed by gdal_translate tmp.vrt output.tif -unscale
-a_offset <value>
Set band offset value. No modification of pixel values is done. Note that the -unscale does not take into account -a_offset. You may for example specify -scale 0 1 <offset> <offset+scale> to apply a (offset, scale) tuple, for the equivalent of the 2 steps: gdal_translate input.tif tmp.vrt -a_scale scale -a_offset offset followed by gdal_translate tmp.vrt output.tif -unscale
-a_ullr <ulx> <uly> <lrx> <lry>
Assign/override the georeferenced bounds of the output file. This assigns georeferenced bounds to the output file, ignoring what would have been derived from the source file. So this does not cause reprojection to the specified SRS. This is mutually exclusive with -a_gt
-a_gt <gt(0)> <gt(1)> <gt(2)> <gt(3)> <gt(4)> <gt(5)>
Assign/override the geotransform of the output file. This assigns the geotransform to the output file, ignoring what would have been derived from the source file. So this does not cause reprojection to the specified SRS. See Geotransform Tutorial. This is mutually exclusive with -a_ullr

Added in version 3.8.

-ot <type>
Select the output data type. By default the same data type as the source is used. List of available types: Byte, Int16, UInt16, Int32, UInt32, Float32, Float64, CInt16, CInt32, CFloat32, CFloat64. Note that GeoTIFF driver requires a specific list of types (Byte, Int16, UInt16, Int32, UInt32, Float32, Float64).
-expand {gray,rgb,rgba}
Expand georeferenced pixels. It can be used to convert a grayscale image into an RGB or RGBA image, or an RGB image into an RGBA image. The expansion is done by repeating the pixel values on the new bands. For example, if gray is selected, a single band image will be converted into a 3 band RGB image where each band is a copy of the original band.
-outband <band>
Select which band(s) to write to the output file. This option can be repeated multiple times. If this option is not specified, all bands of the input file are written to the output file.
-q
Suppress progress messages.
-nodata <value>
Assign a value to all output bands as the nodata value. This option can be used to set the nodata value to none.
-setband interpretation <interpretation>
Set the band interpretation. Available interpretations depend on the driver. See GDAL documentation for a list of supported types.
-setcolorinterp <interp>
Set the color interpretation of the band. Available interpretations depend on the driver.
-setcolortable <filename>
Set the color table of the band from a file. The file must be in a format supported by GDAL (e.g., .clr, .txt, .csv).
-tr <xres> <yres>
Set the output file resolution (x and y pixel spacing). This is mutually exclusive with -sds. The user may specify only one of the two values if he wants to specify the other value from the source dataset.
-r <resampling_method>
Select the resampling method to use when resizing. The possible values are:

nearest: nearest neighbor resampling.

bilinear: bilinear interpolation.

cubic: cubic convolution interpolation.

cubicspline: applies a B-Spline convolution kernel.

lanczos: applies a Lanczos windowed sinc convolution kernel.

mode: selects the value which appears most often of all the sampled points.

-scale [<src_min> <src_max> [<dst_min> <dst_max>]]
Rescale the input pixels values from the range src_min to src_max to the range dst_min to dst_max. If omitted the output range is from the minimum value to the maximum value allowed for integer data types (for example from 0 to 255 for Byte output) or from 0 to 1 for floating-point data types. If omitted the input range is automatically computed from the source dataset, in its whole (not just the window of interest potentially specified with -srcwin or -projwin). This may be a slow operation on a large source dataset, and if using it multiple times for several gdal_translate invocation, it might be beneficial to call gdalinfo -stats {source_dataset} priorly to precompute statistics, for formats that support serializing statistics computations (GeoTIFF, VRT...) Note that the values specified after -scale are only used to compute a scale and offset to apply to the input raster values. In particular, src_min and src_max are not used to clip input values unless -exponent is also specified. Instead of being clipped, source values that are outside the range of src_min and src_max will be scaled to values outside the range of dst_min and dst_max. If clipping without exponential scaling is desired, -exponent 1 can be used. -scale can be repeated several times (if specified only once, it also applies to all bands of the output dataset), so as to specify per band parameters. It is also possible to use the -scale_bn syntax where bn is a band number (e.g. -scale_2 for the 2nd band of the output dataset) to specify the parameters of one or several specific bands.
-exponent <exp_val>
Apply non-linear scaling with a power function. exp_val is the exponent of the power function (must be positive). This option must be used with the -scale option. If specified only once, -exponent applies to all bands of the output image. It can be repeated several times so as to specify per band parameters. It is also possible to use the -exponent_bn syntax where bn is a band number (e.g. -exponent_2 for the 2nd band of the output dataset) to specify the parameters of one or several specific bands.

The scaled value Dst is calculated from the source value Src with the following formula:


{Dst} = \left( {Dst}_{max} - {Dst}_{min} \right) \times \operatorname{max} \left( 0, \operatorname{min} \left( 1, \left( \frac{{Src} - {Src}_{min}}{{Src}_{max}-{Src}_{min}} \right)^{exp\_val} \right) \right) + {Dst}_{min}



-unscale
Apply the scale/offset metadata for the bands to convert linearly-scaled values to unscaled values. It is also often necessary to reset the output datatype with the -ot switch. The unscaled value is computed from the scaled raw value with the following formula:


{unscaled\_value} = {scaled\_value} * {scale} + {offset}



-srcwin <xoff> <yoff> <xsize> <ysize>
Selects a subwindow from the source image for copying based on pixel/line location. Pixel/line offsets (xoff and yoff) are measured from the left and top of the image. If the subwindow extends beyond the bounds of the source dataset, output pixels will be written with a value of zero, unless a NoData value is defined either in the source dataset or by -a_nodata. Alternatively, gdal_translate can issue an error in this case if so directed by options -epo or -eco.
-projwin <ulx> <uly> <lrx> <lry>
Selects a subwindow from the source image for copying (like -srcwin) but with the corners given in georeferenced coordinates (by default expressed in the SRS of the dataset. Can be changed with -projwin_srs). If the subwindow extends beyond the bounds of the source dataset, output pixels will be written with a value of zero, unless a NoData value is defined either in the source dataset or by -a_nodata. Alternatively, gdal_translate can issue an error in this case if so directed by options -epo or -eco.

NOTE:

Beginning with GDAL 3.11, the extent described by -projwin will be transformed into the dataset SRS and used to select a subwindow. Before GDAL 3.11, only the two corner points were transformed into the dataset SRS, and these two transformed points were used to define an extent in the dataset SRS. Depending on the SRS involved, the subwindow selected in GDAL 3.11 may be substantially larger than in previous versions.

NOTE:

When using nearest-neighbor resampling, the window specified by -projwin is expanded (rounded, for GDAL < 3.11) if necessary to match input pixel boundaries. For other resampling algorithms, the window is not modified.
-projwin_srs <srs_def>
Specifies the SRS in which to interpret the coordinates given with -projwin. The <srs_def> may be any of the usual GDAL/OGR forms, complete WKT, PROJ.4, EPSG:n or a file containing the WKT.

WARNING:

This does not cause reprojection of the dataset to the specified SRS.
-epo
(Error when Partially Outside) If this option is set, -srcwin or -projwin values that falls partially outside the source raster extent will be considered as an error. The default behavior is to accept such requests.
-eco

MANEJO DE NODATA / MÁSCARA DE VALIDEZ DE ORIGEN DURANTE EL

REMUESTREO

Los valores enmascarados, ya sea identificados a través de un valor nodata establecido en los metadatos de la banda de origen, una banda de máscara o una banda alfa, no se utilizarán durante el remuestreo (al usar -outsize o -tr

).
huérf
ano

Los detalles de cómo se tiene en cuenta dependen del kernel de

remuestreo:
  • para el remuestreo más cercano, para cada píxel de destino, se selecciona uno de los píxeles de origen potencialmente contribuyentes (de una manera específica de la implementación). Su valor se usa tal cual, ya sea válido o
    • inválido.
  • para bilineal, cúbico, cúbico-spline y lanczos, para cada píxel de destino, los pesos de los píxeles de origen contribuyentes se establecen en cero para ignorarlos cuando están enmascarados. Hay una especificidad extra para el cúbico: dado que algunos de los pesos en el kernel son negativos, dicha estrategia podría conducir a un fuerte sobrepaso/subpaso cuando hay una alternancia de píxeles válidos e inválidos. En consecuencia, si en cualquiera de las direcciones horizontal o vertical, si el número máximo de píxeles de origen válidos en cada dimensión es menor que el radio del kernel de remuestreo, el píxel de destino se considera como
    • nodata.
  • para los otros métodos de remuestreo, los píxe
    • les de origen que contribuyen al píxel de desti
no se ignoran si están enmascarados. Solo se t
ienen en cuenta los válidos. Si no hay ninguno,
el píxel de destino se considera como nodata.
