GDALG   OUTPUT (CONJUNTO DE DATOS EN TIEMPO REAL / EN FLUJO)


Una tubería puede serializarse como un archivo JSON usando el formato de salida GDALG
    . El archivo resultante puede luego abrirse como un conjunto de datos vectorial
    usando el controlador GDALG: GDAL Streamed Algorithm , y aplicar la
    tubería especificada de forma en tiempo real / en flujo.


El miembro command_line del archivo JSON debería nominalmente
    ser la línea de comando completa sin el paso final write , y es lo que
    se genera con gdal vector pipeline ! .... ! write
  out.gdalg.json.






{
    "type": "gdal_streamed_alg",
    "command_line": "gdal vector pipeline ! read in.gpkg ! reproject --dst-crs=EPSG:32632"
}






El paso final write puede añadirse, pero de ser así debe
    especificar explícitamente el formato de salida stream y un nombre de conjunto de datos de salida no significativo.






{
    "type": "gdal_streamed_alg",
    "command_line": "gdal vector pipeline ! read in.gpkg ! reproject --dst-crs=EPSG:32632 ! write --output-format=streamed streamed_dataset"
}










SUSTITUCIONES


Añadido en la versión 3.12.


Es posible usar gdal pipeline para usar una tubería
    ya serializada en un archivo .gdal.json, y personalizar sus pasos existentes,
    típicamente cambiando un nombre de archivo de entrada, especificando un nombre de archivo de salida, o
    añadiendo/modificando argumentos de los pasos.


Ver Sustituciones.






TUBERÍA   ANIDADA


Añadido en la versión 3.12.


Es posible crear "tuberías anidadas", es decir,
    tuberías dentro de tuberías.


Una tubería anidada está delimitada por corchetes ([ y
    ]) rodeados por un carácter de espacio.


Hay 2 tipos de tuberías anidadas:




    
  
  • tuberías anidadas de entrada: donde el conjunto de datos resultado de la tubería anidada se
      usa como el conjunto de datos de entrada para un argumento de la tubería principal.
    • 
  
  • tuberías anidadas de salida: donde la salida de un paso de la tubería principal
      se usa como la entrada de la tubería anidada en un paso siguiente. Las tuberías anidadas de salida
      solo pueden usarse con el paso tee .
    • 





Ver Tubería anidada.






EJEMPLOS




Ejemplo   1: Reproyectar un archivo GeoPackage al CRS EPSG:32632 ("WGS 84 / UTM zona   32N")






$ gdal vector pipeline ! read in.gpkg ! reproject --dst-crs=EPSG:32632 ! write out.gpkg --overwrite










Ejemplo   2: Serializar el comando de una reproyección de un archivo GeoPackage en un archivo GDALG, y leerlo después






$ gdal vector pipeline ! read in.gpkg ! reproject --dst-crs=EPSG:32632 ! write in_epsg_32632.gdalg.json --overwrite
$ gdal vector info in_epsg_32632.gdalg.json










Ejemplo   3: Ninguno


Unir 2 shapefiles de origen (con estructura similar), reproyectarlos
    a EPSG:32632, mantener solo las ciudades con más de 1 millón de habitantes y escribir
    en un GeoPackage






$ gdal vector pipeline ! concat --single --dst-crs=EPSG:32632 france.shp belgium.shp ! filter --where "pop > 1e6" ! write out.gpkg --overwrite
