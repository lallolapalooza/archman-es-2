DESCRIPCIÓ

N

gdal raster overview refresh se puede usar para actualizar las vistas generales existentes de un conjunto de datos. De forma predeterminada, se actualizan todas las vistas generales, pero también es posible restringir las vistas generales actualizadas por nivel y/o

extensión.
--dataset
<DATASET>
Nombre del conjunto de datos, que se actualizará in situ de forma predeterminada (a menos que se especifique --external

--resampling {nearest|average|cubic|cubicspline|lanczos|bilinear|gauss|average_magphase|rms|mo
de}
Seleccionar un algoritmo de remuestreo. El valor predeterminado es nearest, que generalmente no es apropiado si se desea precisión a nivel de subpíxel.

Al actualizar vistas generales TIFF existentes, se utilizará el método utilizado previamente, tal como se indica en el elemento de metadatos RESAMPLING de la vista general, si -r no se

especifica.

Los métodos disponibles

son:

nearest aplica un remuestreador de vecino más cercano (muestreo

simple).

average calcula el promedio de todos los píxeles contribuyentes no NODATA. Este es un promedio ponderado que tiene en cuenta adecuadamente el peso de los píxeles de origen que no contribuyen completamente al píxel de

destino.

bilinear aplica un kernel de convolución

bilineal.

cubic aplica un kernel de convolución

cúbico.

cubicspline aplica un kernel de convolución

B-Spline.

lanczos aplica un kernel de convolución sinc con ventana de

Lanczos.

gauss aplica un kernel gaussiano antes de calcular la vista general, lo que puede conducir a mejores resultados que un simple promedio, por ejemplo, en el caso de bordes nítidos con alto contraste o patrones ruidosos. Los valores de nivel recomendados deben ser 2, 4, 8, ... para que se seleccione un kernel gaussiano de remuestreo

de 3x3.

average_magphase promedia datos complejos en el espacio

magnitud/fase.

rms calcula la raíz de la media de los cuadrados / media cuadrática de todos los píxeles contribuyentes no

NODATA

EJEMPLO

S

Ejemplo 1: Actualizar vistas generales externas de un archivo VRT usando la marca de tiempo de los archivos

fuente

Esto es necesario cuando las fuentes han sido modificadas después de la generación del .vrt.

ovr: 
gdal raster mosaic tile1.tif tile2.tif my.vrt               # crear VRT
gdal raster ov
erview add --external -r cubic my.vrt # generación inicial de la vista general
touch tile1.tif # simular la actualización
de una de las teselas de origen gdal raster overview refresh --external -r cubic \
--use-source-timestamp my.vrt # actualizar vistas generales
