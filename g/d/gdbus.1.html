gdbus(1)

Paquete: glib2

Licencias: LGPL-2.1-or-later

gdbus() gdbus()

Nombre

gdbus - Herramienta para trabajar con objetos D-Bus

SINOPSIS

gdbus introspect [--system | --session | --address dirección] --dest nombre_bus --object-path /ruta/al/objeto [--xml] [--recurse] [--only-properties]
gdbus monitor [--system | --session | --address dirección] --dest nombre_bus [--object-path /ruta/al/objeto]
gdbus call [--system | --session | --address dirección] --dest nombre_bus --object-path /ruta/al/objeto --method org.proyecto.NombreInterfaz.NombreMetodo [--timeout segundos | --interactive] [ARG…]
gdbus emit [--system | --session | --address dirección] --object-path /ruta/al/objeto --signal org.proyecto.NombreInterfaz.NombreSeñal [--dest nombre_bus_unico] [ARG…]
gdbus wait [--system | --session | --address dirección] --activate nombre_bus [--timeout segundos] nombre_bus
gdbus help

DESCRIPCIÓN

gdbus es una herramienta sencilla para trabajar con objetos D-Bus.

COMANDOS

introspect

Muestra las interfaces y los valores de las propiedades de un objeto remoto. Para que esto funcione, el propietario del objeto debe implementar la interfaz org.freedesktop.DBus.Introspectable. Si se usa la opción --xml, se imprime el XML de introspección devuelto, de lo contrario se imprime una representación formateada y legible. La opción --recurse se puede usar para introspeccionar hijos (y sus hijos, y así sucesivamente) y la opción --only-properties se puede usar para imprimir solo las interfaces con propiedades.

monitor

Monitoriza uno o todos los objetos propiedad del dueño de nombre_bus.

call

Invoca un método en un objeto remoto. Cada argumento a pasar al método debe especificarse como un GVariant serializado, excepto que las cadenas de texto no necesitan comillas explícitas. Los valores de retorno se imprimen como valores GVariant serializados.

emit

Emite una señal. Cada argumento a incluir en la señal debe especificarse como un GVariant serializado, excepto que las cadenas de texto no necesitan comillas explícitas.

wait

Espera hasta que nombre_bus sea propiedad de algún proceso en el bus. Si se especifica --activate, ese nombre de bus se iniciará automáticamente primero. Puede ser el mismo nombre de bus que se está esperando o uno diferente.

help

Muestra la ayuda y sale.

COMPLETADO CON BASH

gdbus incluye un script de completado para bash para completar comandos, destinos, nombres de bus, rutas de objetos e nombres de interfaz/método.

EJEMPLOS

Esto muestra cómo introspeccionar un objeto; tenga en cuenta que se muestra el valor de cada propiedad:

$ gdbus introspect --system \
        --dest org.freedesktop.NetworkManager \
        --object-path /org/freedesktop/NetworkManager/Devices/0
node /org/freedesktop/NetworkManager/Devices/0 {
  interface org.freedesktop.DBus.Introspectable {
    methods:
      Introspect(out s data);
  };
  interface org.freedesktop.DBus.Properties {
    methods:
      Get(in  s interface,
          in  s propname,
          out v value);
      Set(in  s interface,
          in  s propname,
          in  v value);
      GetAll(in  s interface,
             out a{sv} props);
  };
  interface org.freedesktop.NetworkManager.Device.Wired {
    signals:
      PropertiesChanged(a{sv} arg_0);
    properties:
      readonly b Carrier = false;
      readonly u Speed = 0;
      readonly s HwAddress = '00:1D:72:88:BE:97';
  };
  interface org.freedesktop.NetworkManager.Device {
    methods:
      Disconnect();
    signals:
      StateChanged(u arg_0,
                   u arg_1,
                   u arg_2);
    properties:
      readonly u DeviceType = 1;
      readonly b Managed = true;
      readwrite o Ip6Config = '/';
      readwrite o Dhcp4Config = '/';
      readwrite o Ip4Config = '/';
      readonly u State = 2;
      readwrite u Ip4Address = 0;
      readonly u Capabilities = 3;
      readonly s Driver = 'e1000e';
      readwrite s Interface = 'eth0';
      readonly s Udi = '/sys/devices/pci0000:00/0000:00:19.0/net/eth0';
  };
};

Las opciones --recurse y --only-properties pueden ser útiles cuando se desea inspeccionar todos los objetos propiedad de un proceso en particular:

$ gdbus introspect --system --dest org.freedesktop.UPower --object-path / --recurse  --only-properties
node / {
  node /org {
    node /org/freedesktop {
      node /org/freedesktop/UPower {
        interface org.freedesktop.UPower {
          properties:
            readonly b IsDocked = true;
            readonly b LidForceSleep = false;
            readonly b LidIsPresent = false;
            readonly b LidIsClosed = false;
            readonly b OnLowBattery = false;
            readonly b OnBattery = false;
            readonly b CanHibernate = true;
            readonly b CanSuspend = true;
            readonly s DaemonVersion = '0.9.10';
        };
        node /org/freedesktop/UPower/Policy {
        };
        node /org/freedesktop/UPower/Wakeups {
          interface org.freedesktop.UPower.Wakeups {
            properties:
              readonly b HasCapability = true;
          };
        };
      };
    };
  };
};

De manera similar, el comando introspect se puede usar para conocer los detalles sobre el método Notify:

[…]
  interface org.freedesktop.Notifications {
    methods:
      GetServerInformation(out s return_name,
                           out s return_vendor,
                           out s return_version,
                           out s return_spec_version);
      GetCapabilities(out as return_caps);
      CloseNotification(in  u id);
      Notify(in  s app_name,
             in  u id,
             in  s icon,
             in  s summary,
             in  s body,
             in  as actions,
             in  a{sv} hints,
             in  i timeout,
             out u return_id);
  };
[…]

Con esta información, es fácil usar el comando call para mostrar una notificación:

$ gdbus call --session \
             --dest org.freedesktop.Notifications \
             --object-path /org/freedesktop/Notifications \
             --method org.freedesktop.Notifications.Notify \
             mi_nombre_app \
             42 \
             gtk-dialog-info \
             "El Resumen" \
             "Aquí está el cuerpo de la notificación" \
             [] \
             {} \
             5000
(uint32 12,)

Llamar a un método con argumento de descriptor de archivo:

$ gdbus call --session \
             --dest org.example.foo \
             --object-path /org/example/foo \
             --method SendFDs \
             1 \
             10 \
             10<file.foo

Emitiendo una

señal: 
$ gdbus emit --session
--object-path /foo -
-signal org.bar.Foo "
['foo', 'bar', 'baz']"

Emitiendo una señal a un proceso

específico: 
$ gdbus emit --session
--object-path /bar -
-signal org.bar.Bar s
omeString --dest :1.42

Esperando a que un nombre bien conocido sea poseído en el bus; esto no iniciará automáticamente el

servicio: 
$ gdbus wa
it --sessi
on org.ba
r.SomeName

Iniciando automáticamente y luego esperando a que un nombre bien conocido sea poseído en el

bus: 
$ gdbus wait
--session --
activate org.
bar.SomeName

Iniciando automáticamente un servicio diferente y luego esperando a que un nombre bien conocido sea poseído en el bus. Esto es útil en situaciones donde SomeName no es directamente

activable: 
$ gdbus wait --sess
ion --activate org.
bar.PrerequisiteNa
me org.bar.SomeName

Esperando un nombre bien conocido y renunciando después de 30 segundos. Por defecto, el tiempo de espera está deshabilitado; o establezca --timeout a 0 para

deshabilitarlo: 
$ gdbus wa
it --sessio
n --timeou
t 30 org.bar.SomeName
