NOMBRE

gdal-mdim-mosaic - Construye un mosaico, ya sea virtual (VRT) o materializado, a partir de conjuntos de datos multidimensionales

Añadido en la versión 3.12.

SINOPSIS

Uso: gdal mdim mosaic [OPCIONES] <ENTRADA>... <SALIDA>
Construye un mosaico, ya sea virtual (VRT) o materializado, a partir de conjuntos de datos multidimensionales.
Argumentos posicionales:
  -i, --input <ENTRADA>                                Conjuntos de datos ráster multidimensionales de entrada [1.. valores] [requerido]
  -o, --output <SALIDA>                                Conjunto de datos ráster multidimensional de salida (creado por el algoritmo) [requerido]
Opciones comunes:
  -h, --help                                           Muestra el mensaje de ayuda y sale
  --json-usage                                         Muestra el uso como un documento JSON y sale
  --config <CLAVE>=<VALOR>                             Opción de configuración [puede repetirse]
  -q, --quiet                                          Modo silencioso (sin barra de progreso)
Opciones:
  -f, --of, --format, --output-format <FORMATO-SALIDA>  Formato de salida
  --co, --creation-option <CLAVE>=<VALOR>            Opción de creación [puede repetirse]
  --overwrite                                          Si se permite sobrescribir la salida existente
  --array <ARRAY>                                      Nombre de los arrays a mosaicar. [puede repetirse]
Opciones avanzadas:
  --oo, --open-option <CLAVE>=<VALOR>                 Opciones de apertura [puede repetirse]
  --if, --input-format <FORMATO-ENTRADA>               Formatos de entrada [puede repetirse]

DESCRIPCIÓN

gdal mdim mosaic construye un mosaico de array(s) multidimensional(es), a partir de una lista de conjuntos de datos GDAL multidimensionales de entrada, que puede ser un mosaico virtual en formato Multidimensional VRT (Virtual Dataset), o en un formato multidimensional más convencional como NetCDF: Network Common Data Form o Zarr.

Se pueden usar comodines '*', '?' o '['] de VSIGlob() para los nombres de los conjuntos de datos de entrada, incluso en archivos ubicados en sistemas de archivos de red como /vsis3/, /vsigs/, /vsiaz/, etc. Alternativamente, si un nombre de conjunto de datos de entrada va precedido del carácter @, se asumirá que contiene la lista de nombres de conjuntos de datos reales (uno por línea) a usar como conjuntos de datos de entrada.

Para crear un mosaico a partir de un array, se aplican ciertas restricciones estructurales a todos los arrays contribuyentes de los conjuntos de datos de entrada:

  • Todos los arrays contribuyentes deben tener el mismo nombre y ruta de array (por ejemplo, "/measurements/pressure")
  • Deben tener el mismo tipo de datos y valor nodata
  • Deben compartir el mismo número de dimensiones, en el mismo orden y con los mismos nombres.
  • cada dimensión del array debe tener una variable de indexación numérica unidimensional asociada.

Un caso de uso típico es cuando un array multidimensional se divide en varios archivos, y se desea reconstruir el array completo.

El programa puede soportar mosaicos a lo largo de varios ejes.

Puede haber "agujeros" entre los conjuntos de datos fuente a lo largo de las dimensiones mosaicales, y posiblemente solapamientos (pero solo cuando el espaciado es regular a lo largo de una dimensión mosaical). Los agujeros se rellenan con el valor nodata, si está definido en los arrays fuente, o se inicializan a cero en caso contrario. En caso de solapamiento, el orden de la lista de entrada se utiliza para determinar la prioridad. Los archivos que se listan al final son aquellos de los que se obtendrá el contenido.

Diferentes casos de uso típicos que pueden ser abordados por este programa son:

  • un array 3D se corta a lo largo de una sola dimensión (por ejemplo, una temporal) en varios archivos, y cada corte tiene una muestra a lo largo de esa dimensión. En este caso de uso, las marcas de tiempo de los cortes no necesitan estar espaciadas regularmente.
  • un array 2D se divide/emblema a lo largo de las dimensiones X e Y, con un espaciado regular a lo largo de esas dimensiones X e Y, y donde los valores de las coordenadas se alinean en la misma cuadrícula entre los emblemas.

Por defecto, se crea un array de destino para cada array con dos o más dimensiones. Este comportamiento puede restringirse a arrays específicos utilizando la opción --array.

Las siguientes opciones están disponibles:

Opciones estándar

-i, --input <ENTRADA>
Nombres de conjuntos de datos multidimensionales de entrada. Requerido.

Se pueden usar comodines '*', '?' o '['] de VSIGlob() para los nombres de los conjuntos de datos de entrada, incluso en archivos ubicados en sistemas de archivos de red como /vsis3/, /vsigs/, /vsiaz/, etc. Alternativamente, si un nombre de conjunto de datos de entrada va precedido del carácter @, se asumirá que contiene la lista de nombres de conjuntos de datos reales (uno por línea) a usar como conjuntos de datos de entrada.

-o, --output <SALIDA>
Nombre del conjunto de datos de salida. Requerido.
-f, --of, --format, --output-format <FORMATO-SALIDA>
Selecciona el formato de salida. Este puede ser un formato que soporte salida multidimensional (como NetCDF: Network Common Data Form, Multidimensional VRT). Cuando esta opción no se especifica, el formato se deduce cuando es posible a partir de la extensión del nombre de archivo de destino.
--co, --creation-option <CLAVE>=<VALOR>
Muchos formatos tienen una o más opciones de creación opcionales que se pueden usar para controlar detalles sobre el archivo creado.

Las opciones de creación disponibles varían según el controlador de formato, y algunos formatos simples no tienen opciones de creación en absoluto. Una lista de opciones soportadas para un formato se puede listar con la opción de línea de comandos --format, pero la documentación del formato es la fuente definitiva de información sobre las opciones de creación del controlador. Consulte la documentación específica del formato de Controladores ráster para ver las opciones de creación legales para cada formato.

Las opciones de creación a nivel de array pueden pasarse prefijándolas con ARRAY:. Consulte GDALGroup::CopyFrom() para obtener más detalles sobre dichas opciones.

--overwrite
Permite al programa sobrescribir el archivo o conjunto de datos de destino existente. De lo contrario, por defecto, gdal genera un error si el archivo o conjunto de datos de destino ya existe.
--array <ARRAYS>
Nombre o ruta completa de uno o varios arrays a mosaicar. Si no se especifica, se crea un array de destino para cada array con dos o más dimensiones.

Opciones avanzadas

--oo <NOMBRE>=<VALOR>
Opción de apertura de conjunto de datos (específica del formato).

Puede repetirse.

--if <formato>
Nombre del formato/controlador que se intentará para abrir los archivos de entrada. Generalmente no es necesario especificarlo, pero se puede usar para omitir la detección automática del controlador, cuando esta falla al seleccionar el controlador apropiado. Esta opción puede repetirse varias veces para especificar varios controladores candidatos. Tenga en cuenta que no fuerza a esos controladores a abrir el conjunto de datos. En particular, algunos controladores tienen requisitos sobre las extensiones de archivo.

Puede repetirse.

EJEMPLOS

Ejemplo 1: Mosaicar juntos varios archivos netCDF que comienzan con slice y que son cortes de un array 3D

gdal mdim mosaic slice*.nc out.vrt
