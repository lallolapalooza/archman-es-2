NOMBRE

gdalbuildvrt - Construye un VRT a partir de una lista de conjuntos de datos.

SINOPSIS

gdalbuildvrt [--help] [--long-usage] [--help-general]
             [--quiet]
             [[-strict]|[-non_strict]]
             [-tile_index <nombre_campo>]
             [-resolution usuario|promedio|comun|mas_alta|mas_baja|igual]
             [-tr <xres> <yres>] [-input_file_list <nombre_archivo>]
             [[-separate]|[-pixel-function <funcion>]]
             [-pixel-function-arg <NOMBRE>=<VALOR>]...
             [-allow_projection_difference] [-sd <n>] [-tap]
             [-te <xmin> <ymin> <xmax> <ymax>] [-addalpha] [-b <banda>]...
             [-hidenodata] [-overwrite]
             [-srcnodata "<valor>[ <valor>]..."]
             [-vrtnodata "<valor>[ <valor>]..."] [-a_srs <srs_def>]
             [-r nearest|bilinear|cubic|cubicspline|lanczos|average|mode]
             [-oo <NOMBRE>=<VALOR>]... [-co <NOMBRE>=<VALOR>]...
             [-ignore_srcmaskband]
             [-nodata_max_mask_threshold <umbral>]
             <nombre_dataset_vrt> [<nombre_dataset_fuente>]...

DESCRIPCION

Este programa construye un VRT (Conjunto de Datos Virtuales) que es un mosaico de una lista de conjuntos de datos GDAL de entrada. La lista de conjuntos de datos GDAL de entrada se puede especificar al final de la línea de comandos, poner en un archivo de texto (un nombre de archivo por línea) para listas muy largas, o puede ser un índice de teselas de MapServer (ver la utilidad gdaltindex). Si se utiliza un índice de teselas, todas las entradas del índice de teselas se añadirán al VRT.

NOTA:

A partir de GDAL 3.9, para mosaicos virtuales con un número muy grande de rásteres fuente (cientos de miles de rásteres fuente, o más), se recomienda utilizar la utilidad gdaltindex para generar un índice de teselas compatible con el controlador GTI.

Con -separate, cada entrada va a una banda separada en el conjunto de datos VRT. De lo contrario, los archivos se consideran rásteres fuente de un mosaico más grande y el archivo VRT tiene el mismo número de bandas que los archivos de entrada.

Si un conjunto de datos GDAL está compuesto por varios subconjuntos de datos y tiene 0 bandas ráster, se añadirán todos los subconjuntos de datos al VRT en lugar del propio conjunto de datos.

gdalbuildvrt realiza algunas comprobaciones para asegurar que todos los archivos que se incluirán en el VRT resultante tengan características similares: número de bandas, proyección, interpretación de color, etc. Si no es así, los archivos que no coincidan con las características comunes se omitirán a menos que se use -strict. (Esto solo es cierto en el modo predeterminado, y no cuando se utiliza la opción -separate)

A partir de GDAL 3.12, se puede especificar una función (por ejemplo, min, mean, median) (-pixel-function) para calcular los valores de píxeles a partir de entradas superpuestas. Si no se especifica ninguna función, o en versiones anteriores, se utiliza el orden de la lista de entrada para determinar la prioridad. Los archivos que aparecen al final son aquellos de los que se obtendrá el contenido. Tenga en cuenta que los valores nodata se tendrán en cuenta para obtener potencialmente datos de conjuntos de datos de menor prioridad, pero actualmente el canal alfa no se tiene en cuenta para la composición alfa (por lo que una fuente con alfa=0 que aparece encima de otra fuente anulará su contenido). Esto puede cambiar en versiones futuras.

--help
Muestra este mensaje de ayuda y sale.
--help-general
Muestra un breve mensaje de uso para las opciones genéricas de línea de comandos de GDAL y sale.
-tileindex <nombre_campo>
Utiliza el valor especificado como campo de índice de teselas, en lugar del valor predeterminado que es 'location'.
-resolution {mas_alta|mas_baja|promedio|usuario|igual}
En caso de que la resolución de todos los archivos de entrada no sea la misma, la bandera -resolution permite al usuario controlar cómo se calcula la resolución de salida.

mas_alta elegirá los valores más pequeños de las dimensiones de píxel dentro del conjunto de rásteres fuente.

mas_baja elegirá los valores más grandes de las dimensiones de píxel dentro del conjunto de rásteres fuente.

promedio es el valor predeterminado y calculará un promedio de las dimensiones de píxel dentro del conjunto de rásteres fuente.

usuario debe usarse en combinación con la opción -tr para especificar la resolución objetivo.

igual (añadido en GDAL 3.11) comprueba que todos los rásteres fuente tengan la misma resolución y se produce un error cuando esto no es así.

comun (añadido en GDAL 3.11) determina el máximo común divisor de las dimensiones de píxel fuente, por ejemplo, 0.2 para dimensiones de píxel fuente de 0.4 y 0.6.

-tr <xres> <yres>
Establece la resolución objetivo. Los valores deben expresarse en unidades georreferenciadas. Ambos deben ser valores positivos. Especificar estos valores es, por supuesto, incompatible con los valores mas_alta|mas_baja|promedio para la opción -resolution.
-tap
(píxeles alineados objetivo) alinea las coordenadas de la extensión del archivo de salida a los valores de -tr, de tal manera que la extensión alineada incluya la extensión mínima. La alineación significa que xmin / resx, ymin / resy, xmax / resx e ymax / resy son valores enteros.
-te <xmin> <ymin> <xmax> <ymax>
Establece las extensiones georreferenciadas del archivo VRT. Los valores deben expresarse en unidades georreferenciadas. Si no se especifican, la extensión del VRT es el cuadro delimitador mínimo del conjunto de rásteres fuente. Los píxeles dentro de la extensión del VRT pero no cubiertos por un ráster fuente se leerán como píxeles válidos con un valor de cero a menos que se especifique un valor NODATA usando -vrtnodata o se añada una banda de máscara alfa con -addalpha.
-addalpha
Añade una banda de máscara alfa al VRT cuando los rásteres fuente no la tienen. Principalmente útil para fuentes RGB (o fuentes de nivel de gris). La banda alfa se rellena sobre la marcha con el valor 0 en áreas sin ningún ráster fuente, y con el valor 255 en áreas con ráster fuente. El efecto es que un visor RGBA renderizará las áreas sin rásteres fuente como transparentes y las áreas con rásteres fuente como opacas. Esta opción no es compatible con -separate.
-hidenodata
Incluso si alguna banda contiene un valor nodata, dar esta opción hace que la banda VRT no informe del NoData. Útil cuando se desea controlar el color de fondo del conjunto de datos. Al usarlo junto con la opción -addalpha, puede preparar un conjunto de datos que no informe del valor nodata pero que sea transparente en áreas sin datos.
-srcnodata "<valor>[ <valor>]..."
Establece valores nodata para las bandas de entrada (se pueden suministrar diferentes valores para cada banda). Si se proporcionan varios valores, todos los valores deben estar entre comillas para mantenerlos juntos como un solo argumento del sistema operativo. Si la opción no se especifica, se utilizarán la configuración intrínseca de nodata en los conjuntos de datos fuente (si existen). El valor establecido por esta opción se escribe en el elemento NODATA de cada elemento ComplexSource. Utilice un valor de None para ignorar la configuración intrínseca de nodata en los conjuntos de datos fuente.
-ignore_srcmaskband
Añadido en la versión 3.3.

A partir de GDAL 3.3, si una fuente tiene una banda de máscara (banda de máscara interna/externa, o banda alfa), se crea por defecto un elemento <ComplexSource> con un elemento hijo <UseMaskBand>true</UseMaskBand>, para instruir al controlador VRT a utilizar la banda de máscara de la fuente para enmascarar los píxeles que se componen. Esto es una generalización del elemento NODATA. W

-nodata_max_mask_threshold <umbral>
Añadido en la versión 3.7.

Sólo relevante cuando se utiliza la opción -addalpha. El valor predeterminado es 255.

Cuando se utilizan fuentes con un canal alfa, el canal alfa resultante en el VRT se establecerá en 0 si el valor del canal alfa de todas las fuentes de entrada en un píxel dado es inferior a este umbral. De lo contrario, se establecerá en 255.

Esto permite que las fuentes semitransparentes que contienen información solo en áreas no totalmente transparentes se traten como si no tuvieran datos válidos, lo que hace que las áreas con datos semitransparentes se consideren transparentes.

-strict
Hace que el comando falle si hay alguna incompatibilidad entre los conjuntos de datos fuente (por ejemplo, diferentes proyecciones, número de bandas, etc.).
-non_strict
Omite archivos incompatibles sin emitir una advertencia. Este es el comportamiento predeterminado.
-pixel-function <funcion>
Especifica la función a utilizar para calcular los valores de píxeles de salida cuando hay superposición de fuentes. Las funciones disponibles son: min, mean, median, max. Si no se especifica, se utiliza el orden de las entradas para determinar la prioridad.
-pixel-function-arg <NOMBRE>=<VALOR>
Argumentos para la función especificada con -pixel-function. Actualmente, solo se admite un argumento: nodata_policy con los valores strict (por defecto) o ignore.
-allow_projection_difference
Permite la creación de un VRT incluso si las proyecciones de los conjuntos de datos fuente no coinciden exactamente. Los conjuntos de datos se transformarán en el vuelo a la proyección del primer conjunto de datos si es posible.
-sd <n>
Número de banda para el conjunto de datos de salida. La banda 1 es la primera.
-b <banda>
Selecciona una banda específica (o varias) de cada conjunto de datos fuente. La numeración de las bandas comienza en 1.
-vrtnodata "<valor>[ <valor>]..."
Establece el valor nodata para el conjunto de datos VRT de salida. Si no se especifica, el valor nodata se toma de la primera fuente (si existe). Se pueden suministrar diferentes valores para cada banda (separados por espacios). Si se especifican varios valores, todos deben estar entre comillas para mantenerlos juntos como un solo argumento del sistema operativo.
-a_srs <srs_def>
Asigna un SRS (Sistema de Referencia Espacial) al conjunto de datos VRT de salida. Si no se especifica, se intenta determinar el SRS a partir de las fuentes.
-r {nearest|bilinear|cubic|cubicspline|lanczos|average|mode}
Especifica el método de re-muestreo a utilizar en caso de que los conjuntos de datos fuente tengan diferentes resoluciones (ver también -tr). Los valores posibles son:
nearest
Re-muestreo de vecino más cercano.
bilinear
Interpolación bilinear.
cubic
Interpolación cúbica.
cubicspline
Interpolación cúbica spline.
lanczos
Interpolación Lanczos.
average
Promedio de píxeles vecinos (útil para submuestreo).
mode
Píxel más frecuente (útil para sobremuestreo).
-oo <NOMBRE>=<VALOR>
Opción de apertura de conjunto de datos. Se puede especificar varias veces.
-co <NOMBRE>=<VALOR>
Opciones de creación de conjunto de datos. Se puede especificar varias veces.
-overwrite
Sobrescribe el archivo VRT de salida si ya existe.
-input_file_list <nombre_archivo>
Especifica un archivo que contiene la lista de conjuntos de datos fuente, uno por línea.
-separate
Crea un archivo VRT donde cada conjunto de datos fuente se mapea a una banda separada. Esto es útil para crear un VRT de mosaico de bandas individuales (por ejemplo, un conjunto de imágenes multiespectrales donde cada banda es un archivo separado).
-quiet
Suprime la salida de progreso.
<nombre_dataset_vrt>
Nombre del archivo VRT a crear.
[<nombre_dataset_fuente>]...
Uno o más nombres de conjuntos de datos GDAL fuente.

EJEMPLOS

Construir un VRT a partir de dos archivos GeoTIFF:

gdalbuildvrt output.vrt input1.tif input2.tif

Construir un VRT a partir de una lista de archivos en un archivo de texto:

gdalbuildvrt -input_file_list my_list.txt output.vrt

Construir un VRT con una resolución específica y una extensión específica:

gdalbuildvrt -tr 10 10 -te -100000 -200000 200000 100000 output.vrt *.tif

Construir un VRT con cada archivo fuente en una banda separada:

gdalbuildvrt -separate output.vrt input1.tif input2.tif input3.tif

Construir un VRT donde las capas superpuestas se combinan usando la media:

gdalbuildvrt -pixel-function mean output.vrt input1.tif input2.tif

Construir un VRT que tenga un canal alfa adicional para la transparencia:

gdalbuildvrt -addalpha output.vrt input1.tif input2.tif

Construir un VRT a partir de una lista de archivos, ignorando los valores nodata de los archivos fuente y estableciendo un valor nodata específico para el VRT:

gdalbuildvrt -srcnodata None -vrtnodata -9999 output.vrt *.tif

Construir un VRT a partir de un índice de teselas:

gdaltindex -write all_tiles.shp input*.tif
gdalbuildvrt -tile_index all_tiles.shp output.vrt

Al especificar la -ignore_srcmaskband opción, la banda de máscara de las fuentes no se tendrá en cuenta, y en caso de superposición entre fuentes, la última sobrescribirá a las anteriores en las áreas de superposición.

-nodata_max_mask_threshold <threshold>
Añadido en la versión 3.9.

Inserta una <NoDataFromMaskSource> fuente, que reemplaza el valor de la fuente con el valor de -vrtnodata (o 0 si no se especifica) cuando el valor de la banda de máscara de la fuente es menor o igual al umbral. Esto se usa típicamente para transformar una imagen R,G,B,A en una R,G,B con un valor NoData.

-b <band>
Selecciona una <band> de entrada para ser procesada. Las bandas se numeran desde 1. Si no se establecen bandas de entrada, todas las bandas se añadirán al VRT. Se pueden usar múltiples -b interruptores para seleccionar un conjunto de bandas de entrada.
-sd <n>
Si el conjunto de datos de entrada contiene varios subconjuntos de datos, use un subconjunto con el número especificado (comenzando desde 1). Esta es una alternativa a dar el nombre completo del subconjunto de datos como entrada a la utilidad.
-vrtnodata "<value>[ <value>]..."
Establece valores nodata a nivel de banda del VRT (se pueden proporcionar valores diferentes para cada banda). Si se proporciona más de un valor, todos los valores deben estar entre comillas para mantenerlos juntos como un único argumento del sistema operativo (Ejemplo 4). Si no se especifica la opción, se usarán los ajustes intrínsecos de nodata del primer conjunto de datos (si existen). El valor establecido por esta opción se escribe en el NoDataValue elemento de cada elemento VRTRasterBand. Use un valor de None para ignorar los ajustes intrínsecos de nodata en los conjuntos de datos de origen.
-separate
Coloca cada archivo de entrada en una banda separada. Vea Ejemplo 3. A diferencia del modo predeterminado, no se requiere que todas las bandas tengan el mismo tipo de dato. Esta opción es mutuamente exclusiva con -pixel-function.

A partir de GDAL 3.8, todas las bandas de cada archivo de entrada se añaden como bandas VRT separadas, a menos que -b se especifique para seleccionar un subconjunto de ellas. Antes de GDAL 3.8, solo la primera banda de cada archivo de entrada se colocaba en una nueva banda VRT, y -b se ignoraba.

-pixel-function
Especifica un nombre de función para calcular un valor a partir de entradas superpuestas. Para una lista de funciones de píxel disponibles, vea Funciones de Píxel Incorporadas. Si no se especifica ninguna función, los valores se tomarán de la última entrada superpuesta. Esta opción es mutuamente exclusiva con -separate.

Añadido en la versión 3.12.

-pixel-function-arg
Especifica un argumento para ser proporcionado a una función de píxel, en el formato <NOMBRE>=<VALOR>. Se pueden especificar múltiples argumentos repitiendo esta opción.

Añadido en la versión 3.12.

-allow_projection_difference
Cuando se especifica esta opción, la utilidad creará un VRT incluso si los conjuntos de datos de entrada no tienen la misma proyección. Nota: esto no significa que serán reproyectados. Su proyección simplemente será ignorada.
-a_srs <srs_def>
Anula la proyección para el archivo de salida. El <srs_def> puede ser cualquiera de las formas habituales de GDAL/OGR, WKT completo, PROJ.4, EPSG:n o un archivo que contenga el WKT. No se realiza ninguna reproyección.
-r {nearest|bilinear|cubic|cubicspline|lanczos|average|mode}
Selecciona un algoritmo de remuestreo. Nearest es el predeterminado
-oo <NOMBRE>=<VALOR>
Opción de apertura de conjunto de datos (específica del formato)
-co <NOMBRE>=<VALOR>
Especifica una opción de creación del controlador VRT.

Añadido en la versión 3.10.

-input_file_list <filename>
Especifica un archivo de texto con un nombre de archivo de entrada en cada línea. Vea Ejemplo 2.
-q
Desactiva la barra de progreso en la consola
-overwrite
Sobrescribe el VRT si ya existe.
-strict
Convierte las advertencias en fallos. Esto es mutuamente exclusivo con -non_strict, este último es el predeterminado.

Añadido en la versión 3.4.2.

-non_strict
Omite los conjuntos de datos de origen que tienen problemas con advertencias, y continúa el procesamiento. Este es el predeterminado.

Añadido en la versión 3.4.2.

-write_absolute_path
Añadido en la versión 3.12.0.

Permite escribir la ruta absoluta de los conjuntos de datos de entrada. Por defecto, los nombres de archivo de entrada se escriben de forma relativa con respecto al nombre de archivo del VRT (cuando es posible).

EJEMPLOS

Ejemplo 1: Hacer un mosaico virtual a partir de todos los archivos TIFF contenidos en un directorio

gdalbuildvrt doq_index.vrt doq/*.tif

Ejemplo 2: Hacer un mosaico virtual a partir de archivos cuyos nombres están especificados en un archivo de texto

gdalbuildvrt -input_file_list my_list.txt doq_index.vrt

Ejemplo 3: Hacer un mosaico virtual RGB a partir de 3 archivos de entrada de una sola banda

gdalbuildvrt -separate rgb.vrt red.tif green.tif blue.tif

Ejemplo 4: Hacer un mosaico virtual con color de fondo azul (RGB: 0 0 255)

gdalbuildvrt -hidenodata -vrtnodata "0 0 255" doq_index.vrt doq/*.tif
