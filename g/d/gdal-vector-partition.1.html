    NAME

    gdal-vector-partition - Particiona un conjunto de datos vectoriales de entrada en varios archivos de salida.

    SYNOPSIS

    gdal vector partition <input_dataset> <output_directory> [--field <FIELD1[,FIELD2,...]>] [--scheme <hive|flat>] [--format <output_format>] [--template <template>] [--feature-limit <FEATURE-LIMIT>] [--max-file-size <MAX-FILE-SIZE>] [--omit-partitioned-field] [--skip-errors] [--oo <NAME>=<VALUE>] [--if <format>]

    DESCRIPTION

    La utilidad de línea de comandos gdal vector partition toma un conjunto de datos vectoriales de entrada y lo particiona en varios archivos de salida. Los archivos de salida se organizan en una estructura de directorios definida por los campos de partición y el esquema elegido.

    <input_dataset>
    La ruta al conjunto de datos vectoriales de entrada.
    <output_directory>
    El directorio donde se escribirán los archivos de salida particionados.
    --field <FIELD1[,FIELD2,...]>
    Uno o más nombres de campos del conjunto de datos de entrada que se utilizarán para la partición. Los campos se procesan en el orden especificado. Para la partición hive, esto define la jerarquía de directorios. Para la partición flat, esto se utiliza para crear subdirectorios para cada valor de campo único. Si no se especifica, se particiona un solo archivo sin ningún campo de partición.
    --scheme <hive|flat>
    El esquema de partición a utilizar.
    • hive: Crea una jerarquía de directorios similar a la utilizada por Apache Hive, donde cada nivel de directorio corresponde a un campo de partición (por ejemplo, `/year=2023/month=12/`). Este es el esquema predeterminado.
    • flat: Crea subdirectorios para cada valor de campo de partición, y todos los archivos resultantes se colocan dentro de esos subdirectorios (por ejemplo, `/US/California/`, `/US/Nevada/`).
    --format <output_format>
    El formato de archivo de salida. Si no se especifica, el formato se infiere de la extensión del directorio de salida si es aplicable. Algunos formatos comunes incluyen GPKG, Parquet, GeoJSON, Shapefile, etc.
    --template <template>
    Plantilla para el nombre del archivo de parte.

    Se aplican las siguientes directivas:

    • %d o %s: Sustituido por el nombre del directorio padre.
    • %f: Sustituido por el nombre del campo de partición.
    • %v: Sustituido por el valor del campo de partición.
    • %i: Sustituido por un contador de partes dentro de un subdirectorio dado.
    • %0Nd: Un entero con signo de N dígitos, relleno con ceros a la izquierda.
    • %0Ns: Una cadena de N caracteres, relleno con espacios a la izquierda.
    • {LAYER_NAME}: Sustituido por el nombre de la capa de entrada.
    • {FIELD_VALUE}: Sustituido por el valor del campo de partición.

    La sintaxis %010d requiere que se especifique exactamente un especificador de número de parte en el patrón.

    Los valores predeterminados para la plantilla son part_%010d para el esquema hive, y {LAYER_NAME}_{FIELD_VALUE}_%010d para el esquema flat.

    --feature-limit <FEATURE-LIMIT>
    Número máximo de características por archivo. Por defecto, ilimitado. Si se supera el límite, se crean varias partes.
    --max-file-size <MAX-FILE-SIZE>
    Tamaño máximo de archivo (se puede usar sufijo MB o GB). Por defecto, ilimitado. Si se supera el límite, se crean varias partes.

    Tenga en cuenta que el tamaño máximo de archivo se utiliza como una sugerencia y podría no respetarse estrictamente, ya que la evaluación del tamaño de archivo correspondiente a una característica se basa en heurísticas, ya que el tamaño de archivo en sí mismo no se puede utilizar de manera confiable cuando se está escribiendo. En particular, las heurísticas no suponen ninguna compresión, por lo que para formatos comprimidos, el tamaño real de una parte puede ser significativamente menor que el límite especificado.

    --omit-partitioned-field
    Si se omiten los campos particionados de la definición de la capa de destino. Se establece automáticamente para el formato de salida Parquet y la partición Hive.
    --skip-errors
    Si se ignoran los fallos al escribir características. Tenga en cuenta que esta opción establece el tamaño de la unidad de transacción en una característica a la vez, lo que puede causar una grave ralentización al insertar en bases de datos.

    Opciones avanzadas

    --oo <NAME>=<VALUE>
    Opción de apertura del conjunto de datos (específica del formato).

    Se puede repetir.

    --if <format>
    Nombre del formato/controlador que se intentará para abrir el(los) archivo(s) de entrada. Por lo general, no es necesario especificarlo, pero se puede utilizar para omitir la detección automática del controlador cuando este falla al seleccionar el controlador apropiado. Esta opción se puede repetir varias veces para especificar varios controladores candidatos. Tenga en cuenta que no fuerza a esos controladores a abrir el conjunto de datos. En particular, algunos controladores tienen requisitos sobre las extensiones de archivo.

    Se puede repetir.

EJEMPLOS

Ejemplo 1: Crear una partición basada en los campos "continent" y "country"

$ gdal vector partition world_cities.gpkg out_directory --field continent,country --format Parquet

Ejemplo 2: Crear una partición basada en el campo "country", filtrando ciudades con población mayor a 1 millón, con un esquema de partición plano

$ gdal pipeline ! read world_cities.gpkg ! filter --where "pop > 1e6" ! partition out_directory --field country --format GPKG --scheme flat
