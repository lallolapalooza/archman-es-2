NOMBRE

gdal-raster-footprint - Calcula la huella de un conjunto de datos ráster Añadido en la versión 3.11.

Añadido en la versión 3.11.

SINOPSIS

Uso: gdal raster footprint [OPCIONES] <ENTRADA>... <SALIDA>
Calcula la huella de un conjunto de datos ráster.
Argumentos posicionales:
  -i, --input <ENTRADA>                                  Conjuntos de datos ráster de entrada [puede repetirse] [obligatorio]
  -o, --output <SALIDA>                                  Conjunto de datos vectoriales de salida [obligatorio]
Opciones comunes:
  -h, --help                                           Muestra el mensaje de ayuda y sale
  --json-usage                                         Muestra el uso como documento JSON y sale
  --config <CLAVE>=<VALOR>                               Opción de configuración [puede repetirse]
  -q, --quiet                                          Modo silencioso (sin barra de progreso)
Opciones:
  -f, --of, --format, --output-format <FORMATO-DE-SALIDA>  Formato de salida
  --co, --creation-option <CLAVE>=<VALOR>                Opción de creación [puede repetirse]
  --lco, --layer-creation-option <CLAVE>=<VALOR>         Opción de creación de capa [puede repetirse]
  --append                                             Si se permite añadir a una capa existente
  --overwrite                                          Si se permite sobrescribir la salida existente
  --output-layer <CAPA-DE-SALIDA>                       Nombre de la capa de salida (por defecto: footprint)
  -b, --band <BANDA>                                    Banda(s) de entrada (índice basado en 1) [puede repetirse]
  --combine-bands <COMBINAR-BANDAS>                     Define cómo se combinan las bandas de máscara de las bandas seleccionadas para generar una sola banda de máscara, antes de ser vectorizada. COMBINAR-BANDAS=unión|intersección (por defecto: unión)
  --overview <VISTA-PREVIA>                             Qué nivel de vista previa del archivo de origen debe usarse
                                                       Exclusivo mutuamente con --src-nodata
  --src-nodata <SRC-NODATA>                            Establece los valores nodata para las bandas de entrada. [1.. valores]
                                                       Exclusivo mutuamente con --overview
  --coordinate-system <SISTEMA-DE-COORDENADAS>          Sistema de coordenadas de destino. SISTEMA-DE-COORDENADAS=georreferenciado|píxel
  --dst-crs <DST-CRS>                                  CRS de destino
  --split-multipolygons                                Si se deben dividir los multipolígonos en varias características, cada una con un solo polígono
  --convex-hull                                        Si se debe calcular el casco convexo de la huella
  --densify-distance <DISTANCIA-DE-DENSIFICACIÓN>      Distancia máxima entre 2 puntos consecutivos de la geometría de salida.
  --simplify-tolerance <TOLERANCIA-DE-SIMPLIFICACIÓN>  Tolerancia utilizada para fusionar puntos consecutivos de la geometría de salida.
  --min-ring-area <ÁREA-MÍNIMA-DEL-ANILLO>             Valor mínimo para el área de un anillo
  --max-points <PUNTOS-MÁXIMOS>                        Número máximo de puntos de cada geometría de salida (por defecto: 100)
  --location-field <CAMPO-DE-UBICACIÓN>                Nombre del campo donde se almacenará la ruta del conjunto de datos de entrada. (por defecto: location)
                                                       Exclusivo mutuamente con --no-location-field
  --no-location-field                                  Desactiva la creación de un campo con la ruta del conjunto de datos de entrada
                                                       Exclusivo mutuamente con --location-field
  --absolute-path                                      Si la ruta al conjunto de datos de entrada debe almacenarse como una ruta absoluta
Opciones avanzadas:
  --oo, --open-option <CLAVE>=<VALOR>                    Opciones de apertura [puede repetirse]
  --if, --input-format <FORMATO-DE-ENTRADA>              Formatos de entrada [puede repetirse]

DESCRIPCIÓN

gdal raster footprint calcula la huella de un archivo ráster, teniendo en cuenta los valores nodata (o más generalmente la banda de máscara adjunta a las bandas ráster), y generando polígonos/multipolígonos correspondientes a las áreas donde los píxeles son válidos, y escribe en un archivo vectorial de salida.

Desde GDAL 3.12, este algoritmo puede ser parte de un pipeline de gdal.

La utilidad gdal raster clean-collar puede ejecutarse como un paso de preprocesamiento para generar bandas de máscara adecuadas.

Ejemplo de huella calculada con las opciones por defecto de gdal raster footprint.

Las siguientes opciones están disponibles:

-f, --of, --format, --output-format <FORMATO-DE-SALIDA>
Qué formato vectorial de salida usar. Los valores permitidos pueden darse con gdal --formats | grep vector | grep rw | sort
--co <NOMBRE>=<VALOR>
Muchos formatos tienen una o más opciones de creación opcionales que pueden usarse para controlar detalles sobre el archivo creado. Por ejemplo, el controlador GeoTIFF admite opciones de creación para controlar la compresión y si el archivo debe estar en mosaico.

Puede repetirse.

Las opciones de creación disponibles varían según el controlador de formato, y algunos formatos simples no tienen opciones de creación en absoluto. Una lista de opciones admitidas para un formato puede listarse con la --formats opción de la línea de comandos, pero la documentación del formato es la fuente definitiva de información sobre las opciones de creación del controlador. Ver Documentación específica de los controladores ráster para las opciones de creación legales de cada formato.

--layer-creation-option <NOMBRE>=<VALOR>
Muchos formatos tienen una o más opciones de creación de capa opcionales que pueden usarse para controlar detalles sobre la capa creada. Por ejemplo, el controlador GeoPackage admite opciones de creación de capa para controlar el identificador de la característica o el nombre de la columna de geometría, establecer el identificador o la descripción, etc.

Puede repetirse.

Las opciones de creación de capa disponibles varían según el controlador de formato, y algunos formatos simples no tienen opciones de creación de capa en absoluto. Una lista de opciones admitidas para un formato puede listarse con la --formats opción de la línea de comandos, pero la documentación del formato es la fuente definitiva de información sobre las opciones de creación del controlador. Ver Documentación específica de los controladores vectoriales para las opciones de creación legales de cada formato.

Tenga en cuenta que las opciones de creación de capa son diferentes de las opciones de creación de conjunto de datos.

--output-layer <CAPA-DE-SALIDA>
Nombre de la capa de salida. Por defecto es footprint.
--overwrite
Permite al programa sobrescribir el archivo o conjunto de datos de destino existente. De lo contrario, por defecto, gdal da error si el archivo o conjunto de datos de destino ya existe.
--append
Si se permite añadir características a la(s) capa(s) existente(s)
-b <banda>
Selecciona una <banda> de entrada para ser procesada. Las bandas se numeran desde 1. Se pueden usar múltiples -b para seleccionar un conjunto de bandas de entrada. Si no se especifica, todas las bandas se tienen en cuenta. La forma en que se combinan múltiples bandas se controla con --combine-bands
--combine-bands unión|intersección
Define cómo se combinan las bandas de máscara de las bandas seleccionadas para generar una sola banda de máscara, antes de ser vectorizada. El valor por defecto es unión: es decir, un píxel es válido si es válido al menos para una de las bandas seleccionadas. intersección significa que un píxel es válido solo si es válido para todas las bandas seleccionadas.
--ovr <índice>
Para especificar qué nivel de vista previa del archivo de origen debe usarse, cuando hay vistas previas disponibles en el ráster de origen. Por defecto se usa el nivel de resolución completa. El índice comienza en 0, es decir, 0 significa el primer nivel de vista previa. Esta opción es exclusiva mutuamente con --src-nodata.
--src-nodata <valor>
Establece los valores valores para las bandas de entrada (se pueden proporcionar valores diferentes para cada banda). Si se especifica un único valor, se aplica a todas las bandas seleccionadas. Si se proporciona más de un valor, debe haber tantos valores como el número de bandas seleccionadas, y todos los valores deben estar entrecomillados para mantenerlos juntos como un único argumento del sistema operativo. Si no se especifica la opción, se utilizará la banda de máscara intrínseca de cada una de las bandas seleccionadas.
--coordinate-system pixel|georeferenced
Sistema de coordenadas de destino. De forma predeterminada, si el conjunto de datos de entrada está georreferenciado, georeferenced se sobreentiende, es decir, la geometría de la huella se expresará como coordenadas en el SRC del ráster (o en el especificado con --dst-crs). Si se especifica pixel, las coordenadas de la geometría de la huella son índices de columna y de línea.
--dst-crs <CRS_DEF>
SRC de destino del archivo de salida. El <CRS_DEF> puede ser cualquiera de las formas habituales de GDAL/OGR, WKT completo, PROJ.4, EPSG:n o un archivo que contenga el WKT. Especificar esta opción implica --coordinate-system=georeferenced. La huella se reproyecta desde el SRC del ráster de origen al SRC especificado.
--split-multipolygons
Cuando se especifica, los multipolígonos se dividen en varias entidades, cada una con un único polígono.
--convex-hull
Cuando se especifica, se calcula la envolvente convexa de los (multi)polígonos.
--densify-distance <value>
El valor especificado de esta opción es la distancia máxima entre 2 puntos consecutivos de la geometría de salida. La unidad de la distancia es en píxeles si --coordinate-system es igual a pixel, o de lo contrario en unidades georreferenciadas del ráster de origen. Esta opción se aplica antes de la reproyección implicada por --dst-crs.
--simplify-tolerance <value>
El valor especificado de esta opción es la tolerancia utilizada para fusionar puntos consecutivos de la geometría de salida mediante el método OGRGeometry::Simplify() . La unidad de la distancia es en píxeles si --coordinate-system es igual a pixel, o de lo contrario en unidades georreferenciadas del conjunto de datos vectorial de destino. Esta opción se aplica después de la reproyección implicada por --dst-crs.
--min-ring-area <value>
Valor mínimo para el área de un anillo. La unidad del área es en píxeles al cuadrado si --coordinate-system es igual a pixel, o de lo contrario en unidades georreferenciadas del conjunto de datos vectorial de destino. Esta opción se aplica después de la reproyección implicada por --dst-crs
--max-points <value>|unlimited
Número máximo de puntos de cada geometría de salida (sin contar el punto de cierre de cada anillo, que siempre es idéntico al primer punto). El valor predeterminado es 100. unlimited se puede utilizar para eliminar esa limitación.
--location-field <field_name>
Especifica el nombre del campo en el conjunto de datos vectorial resultante donde se almacenará la ruta del conjunto de datos de entrada. El nombre del campo predeterminado es "location". Para evitar escribir la ruta del conjunto de datos de entrada, utilice --no-location-field
--no-location-field
Desactiva la escritura de la ruta del conjunto de datos de entrada como un campo en el conjunto de datos vectorial de salida.
--absolute-path
Habilita la escritura de la ruta absoluta del conjunto de datos de entrada. De forma predeterminada, el nombre del archivo se escribe en el campo de ubicación exactamente como se especificó en la línea de comandos.

Las operaciones geométricas posteriores a la vectorización se aplican en el siguiente orden:

  • división opcional (--split-multipolygons)
  • densificación opcional (--densify-distance)
  • reproyección opcional (--dst-crs)
  • filtrado opcional por área mínima del anillo (--min-ring-area)
  • aplicación opcional de la envolvente convexa (--convex-hull)
  • simplificación opcional (--simplify-tolerance)
  • limitación del número de puntos (--max-points)

Añadido en la versión 3.12.

GDALG OUTPUT (ON-THE-FLY / STREAMED DATASET)

Este programa admite la serialización de la línea de comandos como un archivo JSON usando el GDALG formato de salida. El archivo resultante puede abrirse entonces como un conjunto de datos vectorial usando el controlador GDALG: GDAL Streamed Algorithm y aplicar la canalización especificada de forma on-the-fly / en flujo.

NOTA:

Sin embargo, este algoritmo no es nativamente compatible con el streaming. En consecuencia, se generará un conjunto de datos temporal en memoria, lo que puede causar un tiempo de procesamiento significativo al abrirlo.

EJEMPLOS

Ejemplo 1: Escribir la huella de un archivo GeoTIFF en un archivo GeoJSON.

gdal raster footprint my_raster.tif footprint.geojson
