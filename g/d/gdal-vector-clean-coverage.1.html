NOMBRE

gdal-vector-clean-coverage - Eliminar huecos y solapamientos de un conjunto de datos de polígonos

Añadido en la versión 3.12.

SINOPSIS

Uso: gdal vector clean-coverage [OPCIONES] <ENTRADA> <SALIDA>
Modifica los límites de los polígonos para hacer que los bordes compartidos sean idénticos, eliminando huecos y solapamientos.
Argumentos posicionales:
  -i, --input <ENTRADA>                                Conjuntos de datos vectoriales de entrada [requerido]
  -o, --output <SALIDA>                                Conjunto de datos vectoriales de salida [requerido]
Opciones comunes:
  -h, --help                                           Muestra el mensaje de ayuda y sale.
  --json-usage                                         Muestra el uso como un documento JSON y sale.
  --config <CLAVE>=<VALOR>                             Opción de configuración [puede repetirse]
  -q, --quiet                                          Modo silencioso (sin barra de progreso)
Opciones:
  -l, --layer, --input-layer <CAPA-ENTRADA>            Nombre(s) de la capa de entrada [puede repetirse]
  -f, --of, --format, --output-format <FORMATO-SALIDA>  Formato de salida ("GDALG" permitido)
  --co, --creation-option <CLAVE>=<VALOR>          Opción de creación [puede repetirse]
  --lco, --layer-creation-option <CLAVE>=<VALOR>     Opción de creación de capa [puede repetirse]
  --overwrite                                          Si se permite sobrescribir la salida existente.
  --update                                             Si se permite abrir el conjunto de datos existente en modo de actualización.
  --overwrite-layer                                    Si se permite sobrescribir la capa de salida existente.
  --append                                             Si se permite añadir a la capa existente.
                                                       Mutuamente excluyente con --upsert
  --output-layer <CAPA-SALIDA>                         Nombre de la capa de salida.
  --skip-errors                                        Omitir errores al escribir características.
  --active-layer <CAPA-ACTIVA>                         Establecer la capa activa (si no se especifica, todas).
  --snapping-distance <DISTANCIA-AJUSTE>               Tolerancia de distancia para ajustar nodos.
  --merge-strategy <ESTRATEGIA-FUSION>                 Algoritmo para asignar solapamientos a polígonos vecinos. ESTRATEGIA-FUSION=longest-border|max-area|min-area|min-index
  --maximum-gap-width <ANCHO-MAXIMO-HUECO>             Ancho máximo de un hueco que se cerrará.
Opciones avanzadas:
  --if, --input-format <FORMATO-ENTRADA>               Formatos de entrada [puede repetirse]
  --oo, --open-option <CLAVE>=<VALOR>                Opciones de apertura [puede repetirse]
  --output-oo, --output-open-option <CLAVE>=<VALOR> Opción de apertura de salida [puede repetirse]
  --upsert                                             Actualizar/Insertar características (implica 'append').
                                                       Mutuamente excluyente con --append

DESCRIPCIÓN

gdal vector clean-coverage modifica los límites de un conjunto de datos poligonales, de modo que los huecos y solapamientos entre características se eliminen y los bordes compartidos se definan utilizando los mismos vértices. El conjunto de datos resultante formará una cobertura poligonal que se puede utilizar con gdal vector simplify-coverage.

Este comando también se puede utilizar como un paso de gdal vector pipeline, aunque requiere cargar todo el conjunto de datos en memoria a la vez.

NOTA:

Este comando requiere una compilación de GDAL contra la biblioteca GEOS (versión 3.14 o superior).

Opciones estándar

--maximum-gap-width <ANCHO-MAXIMO-HUECO>
Define el área más grande que se considerará un "hueco" y se fusionará en un polígono adyacente. Los huecos se fusionarán a menos que un círculo con un radio mayor que la tolerancia especificada pueda inscribirse dentro del hueco. El ancho máximo de hueco predeterminado es cero, lo que significa que los huecos no se cierran.
--merge-strategy <ESTRATEGIA-FUSION>
Método por el cual los solapamientos o huecos se añadirán a los polígonos adyacentes. Las opciones incluyen: - longest-border (predeterminado): añadir áreas al polígono con el que se comparte el borde más largo - max-area: añadir áreas al polígono adyacente más grande - min-area: añadir áreas al polígono adyacente más pequeño - min-index: añadir áreas al polígono adyacente que se leyó primero.
--snapping-distance <DISTANCIA-AJUSTE>
Controla el paso de ajuste de nodos, cuando los vértices cercanos se ajustan entre sí. Por defecto, se determina una distancia de ajuste automática basada en un análisis de la entrada. Establecer a cero para desactivar todo el ajuste.
--active-layer <CAPA-ACTIVA>
Establece la capa activa. Cuando se especifica, solo la capa especificada por su nombre estará sujeta al procesamiento. Otras capas no se modificarán. Si esta opción no se especifica, todas las capas estarán sujetas al procesamiento.
-f, --of, --format, --output-format <FORMATO-SALIDA>
Qué formato vectorial de salida utilizar. Los valores permitidos pueden ser proporcionados por gdal --formats | grep vector | grep rw | sort
--co <NOMBRE>=<VALOR>
Muchos formatos tienen una o más opciones de creación de conjuntos de datos opcionales que se pueden usar para controlar detalles específicos del archivo creado. Por ejemplo, el controlador GeoPackage admite opciones de creación para controlar la versión.

Puede repetirse.

Las opciones de creación de conjuntos de datos disponibles varían según el controlador de formato, y algunos formatos simples no tienen opciones de creación. Una lista de opciones admitidas para un formato se puede listar con la opción de línea de comandos --formats, pero la documentación del formato es la fuente definitiva de información sobre las opciones de creación del controlador. Consulte la documentación específica del formato de controladores vectoriales para conocer las opciones de creación legales para cada formato.

Tenga en cuenta que las opciones de creación de conjuntos de datos son diferentes de las opciones de creación de capas.

-lco <NOMBRE>=<VALOR>
Opción de creación de capa (específica del formato)
--overwrite
Permite que el programa sobrescriba el archivo o conjunto de datos de destino existente. De lo contrario, por defecto, gdal genera un error si el archivo o conjunto de datos de destino ya existe.

Opciones avanzadas

--oo <NOMBRE>=<VALOR>
Opción de apertura de conjunto de datos (específica del formato).

Puede repetirse.

--if <formato>
Nombre del formato/controlador que se intentará para abrir los archivos de entrada. Generalmente no es necesario especificarlo, pero se puede usar para omitir la detección automática del controlador cuando esta falla al seleccionar el controlador apropiado. Esta opción se puede repetir varias veces para especificar varios controladores candidatos. Tenga en cuenta que no obliga a esos controladores a abrir el conjunto de datos. En particular, algunos controladores tienen requisitos sobre las extensiones de archivo.

Puede repetirse.

SALIDA GDALG (TRANSFORMACIÓN EN CALIENTE / CONJUNTO DE DATOS EN FLUJO)

Este programa admite la serialización de la línea de comandos como un archivo JSON utilizando el formato de salida GDALG. El archivo resultante se puede abrir como un conjunto de datos vectoriales utilizando el controlador GDALG: GDAL Streamed Algorithm, y aplicar la canalización especificada de forma sobre la marcha / en flujo.

NOTA:

Sin embargo, este algoritmo no es compatible de forma nativa con el flujo. En consecuencia, se generará un conjunto de datos temporal en memoria, lo que puede causar un tiempo de procesamiento significativo al abrir.
EJEMPLOS

Ejemplo 1: Crear y luego simplificar una cobertura poligonal

$ gdal vector pipeline read ne_10m_admin_0_countries.shp ! \
                       make-valid ! \
                       clean-coverage ! \
                       simplify-coverage --tolerance 1 ! \
                       write countries.shp
