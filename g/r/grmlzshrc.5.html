NOMBRE

grmlzshrc - Configuración de zsh de Grml

SINOPSIS

zsh [opciones]...

DESCRIPCIÓN

El proyecto Grml proporciona una configuración interactiva bastante exhaustiva (denominada grmlzshrc en este documento) para el increíble shell de Unix zsh http://zsh.sourceforge.net. Este es el manual de referencia para esa configuración.

Para usar grmlzshrc, necesita al menos la versión 5.1 de zsh.

grmlzshrc se comporta de manera diferente dependiendo del usuario que lo cargue. Para el usuario root (EUID == 0) solo se carga un subconjunto de características por defecto. Este comportamiento puede ser alterado estableciendo la VARIABLE DE INICIO GRML_ALWAYS_LOAD_ALL (ver abajo).

Los usuarios pueden querer mantener una versión actualizada de la configuración (posiblemente de las fuentes de git) en ~/.zshrc. Si eso sucede en un sistema donde el zshrc global también es un grmlzshrc (pero posiblemente uno más antiguo), puede inhibir la carga de la versión global haciendo:

echo setopt no_global_rcs >> ~/.zshenv

Tenga en cuenta que esto deshabilitará *CUALQUIER* archivo global, excepto el archivo zshenv global.

VARIABLES DE INICIO

Algunos de los comportamientos de grmlzshrc pueden ser alterados estableciendo ciertas variables de shell. Estas pueden ser establecidas temporalmente al iniciar zsh de esta manera:

% GRML_DISPLAY_BATTERY=1 zsh

O estableciéndolas permanentemente en zshrc.pre (Ver ARCHIVOS AUXILIARES abajo).

BATTERY

Obsoleto. Use GRML_DISPLAY_BATTERY en su lugar.

COMMAND_NOT_FOUND

Un valor distinto de cero activa un manejador, que se llama cuando no se encuentra un comando. El manejador está definido por GRML_ZSH_CNF_HANDLER (ver abajo).

GRML_COMP_CACHING

Si se establece en yes (el valor por defecto), la configuración habilitará el mecanismo de caché de completado de zsh, con los datos de caché colocados en $GRML_COMP_CACHE_DIR.

GRML_COMP_CACHE_DIR

Esto define dónde se colocarán los datos de caché de completado de zsh, si $GRML_COMP_CACHING está activo. El valor por defecto es ${ZDOTDIR:-$HOME}/.cache. La configuración se asegurará de que el directorio exista antes de intentar usarlo.

GRML_DISPLAY_BATTERY

Si se establece en un valor mayor que cero, grmlzshrc colocará el estado de la batería en el prompt interactivo del lado derecho. Los sistemas operativos compatibles son GNU/Linux, FreeBSD, OpenBSD y Darwin.

GRML_ZSH_CNF_HANDLER

Esta variable contiene el manejador a ser utilizado por COMMAND_NOT_FOUND (ver arriba) y por defecto es "/usr/share/command-not-found/command-not-found".

GRML_NO_APT_ALIASES

Un valor no vacío inhibe la definición de alias cortos específicos de apt, como ag, agi, ati, etc.

GRML_NO_SMALL_ALIASES

Un valor no vacío inhibe la definición de alias de 2 letras como da. ls, ll, la y otros alias comunes relacionados con ls están exentos de esto, al igual que los alias inhibidos por GRML_NO_APT_ALIASES.

GRMLSMALL_SPECIFIC

Establezca esto a cero para eliminar elementos de la configuración de zsh que no funcionan en grml-small.

HISTFILE

Dónde zsh guarda el historial. Por defecto: ${HOME}/.zsh_history.

HISTSIZE

Número de comandos a mantener en el historial. Por defecto: 5000

MAILCHECK

Establece la frecuencia en segundos para que zsh verifique el correo nuevo. Por defecto es 30. Un valor de cero desactiva la verificación.

NOCOR

Valores distintos de cero desactivan la corrección automática de comandos.

NOETCHOSTS

Valores distintos de cero desactivan el análisis de "/etc/hosts" deshabilitando la completación de host usando el contenido del archivo.

NOMENU

Si se establece en cero (por defecto), permite la selección desde un menú, si hay al menos cinco opciones de completado posibles.

NOPRECMD

Un valor distinto de cero deshabilita los comandos precmd y preexec. Estas son funciones que se ejecutan antes de cada comando (estableciendo títulos xterm/screen, etc.).

REPORTTIME

Muestra el tiempo (usuario, sistema y CPU) utilizado por comandos externos, si se ejecutan durante más tiempo que el número definido de segundos (por defecto: 5).

SAVEHIST

Número de comandos a almacenar en ${HISTFILE}. Por defecto: 10000

watch

Como en tcsh(1) un array de eventos de inicio/cierre de sesión a ser reportados por el comando incorporado "log". Para detalles ver zshparam(1). Por defecto es (notme root).

ZSH_NO_DEFAULT_LOCALE

Importa "/etc/default/locale", si se establece en cero (por defecto).

ZSH_PROFILE_RC

Un valor distinto de cero hace que las funciones del shell sean perfiladas. Los resultados se pueden obtener con el comando incorporado zprof (ver zshmodules(1) para detalles).

COMPDUMPFILE

Especifica la ubicación del archivo de volcado de completado. Por defecto: $HOME/.zcompdump.

ESTILOS ESPECÍFICOS DE GRML-ZSHRC

Los estilos son un mecanismo de configuración sensible al contexto incluido con zsh. El shell lo utiliza extensamente en subsistemas como el sistema de información de completado y VCS. Vive fuera del espacio de nombres de variables clásico del shell, por lo que evita contaminarlo. Las nuevas funcionalidades en el zshrc de grml probablemente usarán estilos en lugar de variables. Algunas características de la configuración (como el manejo de la pila de directorios) ya utilizan estilos. Esos estilos están documentados con las características específicas. Esta sección documenta estilos más generales.

Contexto: :grml:completion:compinit

Este contexto gira en torno a la llamada a la función compinit del zshrc, que inicializa el sistema de completado basado en funciones de zsh.

arguments

Este estilo permite la inyección de argumentos a la línea de comandos que se utiliza para ejecutar compinit. Es un estilo de lista y su valor por defecto es la lista vacía. Usando este estilo, es posible añadir -i a compinit para deshabilitar compaudit.
zstyle ':grml:completion:compinit' arguments -i

Haga esto solo si sabe qué tipo de comprobaciones de seguridad se deshabilitan si compaudit no está activo y si eso es aceptable para su configuración específica.

Este estilo debe establecerse en el momento en que el zshrc de Grml ejecute compinit. Una forma posible de lograr esto es establecerlo en ~/.zshrc.pre (ver ARCHIVOS AUXILIARES abajo para más detalles).

DESCRIPCIÓN DE CARACTERÍSTICAS

Esta es una descripción detallada de las características no estándar implementadas por grmlzshrc.

manejo de la pila de directorios

La pila de directorios en grmlzshrc tiene naturaleza persistente. Se almacena en un archivo cada vez que se cambia el directorio de trabajo de zsh. Ese archivo se puede configurar a través de la variable DIRSTACKFILE y por defecto es ~/.zdirs. La variable DIRSTACKSIZE por defecto es 20 en esta configuración.

El DIRSTACKFILE se carga cada vez que se inicia zsh, por lo tanto, los zsh recién iniciados heredan la pila de directorios del zsh que actualizó DIRSTACKFILE más recientemente.

Si desea deshabilitar la característica de pila de directorios persistente por completo, puede hacerlo estableciendo el estilo booleano enable a false en el contexto correcto (el valor por defecto es true):

zstyle ':grml:chpwd:dirstack' enable false

Es posible aplicar un filtro a los nombres de los directorios que se incluirán en el archivo de pila de directorios persistente. Hay dos maneras de configurar este filtro: un filtro general basado en funciones y un filtro basado en patrones. Ambos se configuran a través de estilos en el contexto ':grml:chpwd:dirstack'.

Para usar un filtro basado en funciones, establezca el estilo filter a

r ese contexto al nombre de una función a llamar cada vez que se va a añadir un nombre de directorio a la pila de directorios persistente. Si el valor de retorno de la función indica éxito (es decir, valor de retorno "0"), el nombre de directorio se filtra y no se añade a la pila persistente.

Ejemplo: 
function my_dirstack_filter() { [[ $1 == /tmp(|/*) ]] }
zstyle ':grml:chpwd:dirstack' filter my_dirstack_filt
e
r

El filtro basado en patrones utiliza una lista de patrones pasados al estilo exclude en el contexto mencionado. Cada patrón se prueba y el primero que coincida evitará que el nombre de directorio se añada a la pila persistente. Si ninguno de los patrones coincide, el nombre se añade.

Ejemplo: 
zstyle ':grml:chpwd:di
rstack' exclude "/tmp(
|/*)" "$HOME/tmp(|/*)"

El filtro basado en funciones es más general, el filtro basado en patrones es más fácil de configurar. Si ambas variantes de filtro se usan al mismo tiempo, el filtro basado en funciones se ejecutará antes que el basado en

patrones.

Si desea aplicar sus filtros mientras carga el archivo de pila de directorios persistente, establezca el estilo booleano filter-on-load (el valor predeterminado es false

): 
zstyle ':grml:ch
pwd:dirstack' fil
ter-on-load true

La configuración de los estilos filter-on-load y enable debe hacerse en ".zshrc.pre" porque los estilos deben estar establecidos cuando se ejecuta la configuración principal. Los otros estilos no tienen esta limitación, pero la activación del sistema, así como el filtrado inicial, se harán obviamente usando la configuración y los filtros que estén configurados en ese punto

.

Con respecto a filter-on-load, la regla general es: Si quiere filtrar al cargar, configure

todo en ".zshrc.pre"; de lo contrario, ".zshrc.local" funciona igual de bien.

Inicializació

n

Estilos y nombres de

perfil

Para almacenar su configuración, el sistema usa funciones y estilos (el sistema de configuración sensible al contexto de zsh), como

/*)' profile grml zstyle ':chpwd:profil

Cuando esto se hace y usted entra en un directorio que coincide con el patrón en la tercera parte del contexto, se llama a una función llamada chpwd_profile_grml, por ejemplo (si existe)

.

Si ningún patrón coincide (léase: no se detecta ningún perfil), el perfil se establece en 'default', lo que significa que se intenta llamar a chpwd_profile_default

.

Una palabra sobre el contexto (lo del ':chpwd:profiles:*' en el comando zstyle) que se usa: La tercera parte del contexto se compara con ${PWD}. Por eso usar un patrón como /foo/bar(|/|/*) tiene sentido. Porque de esa manera se detecta el perfil para todos estos valores de ${PWD}

/foo/bar
/
foo/bar/ /f
oo/bar/baz

Así que, si quiere asegurarse de que un perfil funcione en /foo/bar y en todo lo más profundo de ese árbol, simplemente use (|/|/*) y sea

feliz.

El nombre del perfil detectado estará disponible en

una variable llamada 'profile' en sus funciones.
No necesita hacer nada, simplemente estará ahí.

Control de la ejecución del

perfil

Durante su ejecución de inicialización, el sistema crea un parámetro $CHPWD_PROFILE, que se establece al perfil que está actualmente activo (el valor predeterminado es "default"). De esa manera puede evitar ejecutar código para un perfil que ya está activo, ejecutando código como el siguiente al principio de su

función:

    [[ ${profile} == ${CHPWD_PROFILE} ]] && return 1
  ...
}

así:

pwd:profile
s:*' re-ex
ecute false

Promp

t

El grmlzshrc ahora proporciona tres temas de prompt compatibles con el sistema promptinit de zsh. Los tres temas se llaman grml, grml-large y grml-chroot

.

Por defecto, se usa grml, a menos que $GRMLPROMPT esté establecido a un valor mayor que cero, en cuyo caso se usa grml-large. Por último, si $GRML_CHROOT no está vacío, se usa grml-c

hroot.

Como es habitual con los temas de promptinit, el usuario puede cambiar a un tema diferente usando la utilidad prompt

: 
prompt
grml
-large

Eso usará el tema de prompt

grml-large.

Los temas son altamente personalizables. La fuente principal de documentación sobre la personalización es la documentación del tema principal de grml, que está disponible mediante el siguiente

comando: 
promp
t -h
grml

Los otros temas también incluyen su propia documentación, pero la del tema principal es la referencia canónica sobre todos

ellos.

Esta característica requiere la versión 4.3.7 del shell. Las versiones más antiguas utilizarán el prompt clásico de grml como

alternativa.

Una nota para quienes les gusta la personalización: Si no están utilizando un tema de prompt para su personalización, sino que están configurando estáticamente $PS1 (o $PROMPT) o están construyendo una de esas variables en la función `precmd()' de zsh, asegúrense de desactivar el sistema de temas de prompt de zsh antes de hacerlo. Un ejemplo correcto de personalización podría verse

así:

prompt usted mismo: PS1='%~ %# '

También puede añadir sus propios tokens utilizando la funció

Si lee el código de grmlzshrc puede notar comentarios de aspecto extraño en él. Estos están ahí por una razón. La tarjeta de referencia de zsh de grml se genera automáticamente a partir del contenido del archivo de configuración real. Esto es lo que

significan:

Lista de etiquetas (tipos de comentario)

usadas:

)

#f# La siguiente línea contiene el comienzo de una función importante. (etiqueta de colocación: @@INSERT-functions@@

)

#v# La siguiente línea contiene una variable importante. (etiqueta de colocación: @@INSERT-variables@@

)

#k# La siguiente línea contiene una combinación de teclas importante. (etiqueta de colocación: @@INSERT-keybindings@@

)

#d# Generación de la lista de directorios con hash: start: denota el comienzo de una lista de definiciones 'hash -d'. end: denota su fin. (etiqueta de colocación: @@INSERT-hasheddirs@@

)

#A# Generación de la lista de expansión de abreviaturas: start: denota el comienzo de las abreviaturas. end: denota su

fin.

Las líneas dentro de esta sección que terminan en '#d .*' proporcionan documentación extra para ser incluida en la tarjeta de referencia. (etiqueta de colocación: @@INSERT-abbrev@@

)

#m# Esta etiqueta le permite generar manualmente entradas de la tarjeta de referencia para líneas de código que son difíciles/imposibles de

analizar.

Ejemplo

help function

n> <argument
> <comment>

Todas estas etiquetas (excepto m y o) toman dos argumentos, el primero dentro de la etiqueta, el otro después de la

etiqueta: 
#<tag><se
ction>#
<comment>

Donde <section> es realmente solo un número, que está definido por el array @secmap en la parte superior de 'genrefcard.pl'. La razón por la que se usan números en lugar de nombres es que, para el lector, la etiqueta no debería diferir mucho de un comentario regular. Para zsh, es un comentario regular de hecho.
