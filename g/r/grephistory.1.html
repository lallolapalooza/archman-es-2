GREPHISTORY(1) Documentación de InterNetNews GREPHISTORY(1)

NOMBRE

grephistory - Consulta la base de datos de historial de INN

SINOPSIS

grephistory [-eilnqsv] [-f db] [message-id]

DESCRIPCIÓN

grephistory consulta la base de datos de historial de INN para obtener información sobre el message-ID especificado. Si no se proporcionan opciones, el programa imprime el token de la API de almacenamiento del artículo correspondiente, o "/dev/null" si el artículo está listado en la base de datos de historial pero no está almacenado en el servidor. Si el message-ID no se puede encontrar en la base de datos, grephistory imprimirá "grephistory: not found" y saldrá con un estado distinto de cero.

Asegúrese de escapar cualquier carácter especial en el message-ID desde la shell. Se recomiendan las comillas simples para este propósito ya que muchos message-IDs contienen signos de dólar.

OPCIONES

-e
Imprime solo el token de almacenamiento si el artículo está almacenado en el sistema. (En otras palabras, suprime la salida de "/dev/null" o "not found" para artículos faltantes o recordados).
-f db
Consulta la base de datos de historial db en lugar de la base de datos de historial predeterminada.
-i
En lugar de esperar un message-ID en la línea de comandos, grephistory leerá una lista de message-IDs de la entrada estándar, uno por línea. Se ignora el espacio en blanco al principio y al final, así como cualquier línea mal formada. Imprimirá en la salida estándar los message-IDs que no se encuentren en la base de datos de historial. Esto se utiliza al procesar mensajes de control "ihave".
-l
Muestra la línea completa de la base de datos de historial, en lugar de solo el token de la API de almacenamiento. Si el message-ID está presente en la base de datos de historial pero no tiene un token de API de almacenamiento, grephistory no imprime nada.
-n
Si el message-ID está presente en la base de datos de historial pero no tiene un token de API de almacenamiento, imprime "/dev/null" y sale con éxito. Esto puede ocurrir si un artículo ha sido cancelado o ha expirado, pero aún se conserva información del historial. Este es el comportamiento predeterminado.
-q
No imprime ningún mensaje, pero sale con el estado apropiado.
-s
En lugar de esperar un message-ID en la línea de comandos, grephistory leerá una lista de message-IDs de la entrada estándar, uno por línea. Se ignora el espacio en blanco al principio y al final, así como cualquier línea mal formada. Imprimirá en la salida estándar los tokens de la API de almacenamiento para cualquier artículo que todavía esté disponible, uno por línea. Esta opción se utiliza al procesar mensajes de control "sendme".
-v
Imprime el hash del message-ID con fines de diagnóstico, así como cualquier otra información solicitada. Esta opción no es útil con -i o -s.

EJEMPLOS

En caso de que el artículo solicitado no esté listado en la base de datos de historial:

% grephistory '<unknown.article@news.example.com>'
grephistory: not found
% grephistory -v '<unknown.article@news.example.com>'
grephistory: not found (hash is 501C66C22932BA91131186D7218201EB)

En caso de que el artículo solicitado esté listado en la base de datos de historial pero no almacenado en el servidor:

% grephistory '<remembered.article@news.example.com>'
/dev/null

En caso de que el artículo solicitado esté almacenado en el servidor:

% grephistory '<87fxeaay1z.fsf@windlord.stanford.edu>'
@02014A2DD6231FCC00000000000000000000@
% grephistory -l '<87fxeaay1z.fsf@windlord.stanford.edu>'
[B6DDF69376E3CC199246CEC949B3ACAC]  1244517923~-~1244517912
  @02014A2DD6231FCC00000000000000000000@

Con sm, podemos recuperar el artículo y obtener su fecha de publicación:

% grephistory '<87fxeaay1z.fsf@windlord.stanford.edu>' \
    | sm | grep Date
Date: Mon, 08 Jun 2009 20:25:12 -0700
% convdate -dc 1244517912
Tue, 9 Jun 2009 03:25:12 -0000 (UTC)

Coincide con el número registrado en el historial como fecha de publicación.
