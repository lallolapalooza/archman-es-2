NOMBRE

greetd - archivo de configuración

DESCRIPCIÓN

greetd utiliza un simple archivo de configuración TOML para definir su comportamiento.

CONFIGURACIÓN

La configuración se divide en **secciones**. Las secciones se delimitan así:

[nombre_seccion]
clave_config = valor

Las claves de configuración pueden ser literales enteros o cadenas delimitadas por comillas. Las secciones de configuración se describen a continuación.

terminal

Esta sección contiene la configuración de la terminal.

vt = num|"siguiente"|"actual"

La VT en la que ejecutarse. Puede ser el número de una VT específica, "siguiente" para seleccionar la siguiente VT disponible, o "actual" para permanecer donde sea que se haya iniciado greetd. La VT específica se evalúa al arranque y no cambia durante la ejecución de greetd.

Si se utiliza la VT actual o una específica, debes asegurarte de que no haya otros usuarios de esa VT. Si se usa systemd con autovt y getty, la evitación de conflictos se puede manejar en la unidad de servicio con "Conflicts=getty@ttyN.service", donde N es el número de VT.

Se recomienda el uso de una VT específica con la evitación de conflictos adecuada.

switch = verdadero|falso

Si se debe cambiar a vt o no.

Si se establece en falso y vt no es la VT actualmente activa, greetd esperará a que vt se active antes de hacer cualquier cosa, incluyendo iniciar el greeter.

Si se establece en verdadero, greetd cambiará la VT actual a vt.

El valor predeterminado es verdadero.

general

Esta sección contiene la configuración general que no encaja en otras secciones ni merece su propia sección.

source_profile = verdadero|falso

Si se deben o no ejecutar ~/.profile y /etc/profile si están presentes al ejecutar comandos. Predeterminado a verdadero.

runfile = ruta-al-archivo-de-ejecución

Ubicación del archivo de ejecución de greetd que se crea durante la primera ejecución para evitar que la sesión inicial se ejecute de nuevo al finalizar la sesión o al reiniciar greetd.

Este archivo debe estar en una ubicación que se borre durante un reinicio.

default_session

Esta sección describe la sesión predeterminada, también conocida como el **greeter**.

command = línea-de-comandos

La línea de comandos que greetd ejecutará para iniciar la sesión predeterminada, por ejemplo, "agreety -c sway". La sesión predeterminada se inicia automáticamente cuando no hay ninguna otra sesión en ejecución, como cuando una sesión de usuario finaliza o cuando greetd se inicia inicialmente sin ninguna sesión inicial configurada.

La línea de comandos es ejecutada por sh(1), y como tal acepta sintaxis estándar del shell POSIX.

Consulte greetd-ipc(7) para obtener información sobre cómo un greeter puede crear sesiones.

user = usuario

El usuario a utilizar para ejecutar el greeter. Predeterminado a "greeter".

initial_session

Esta sección opcional describe la sesión inicial, comúnmente conocida como "auto-login".

La sesión inicial solo se ejecutará durante la primera ejecución de greetd desde el arranque para garantizar que el cierre de sesión funcione correctamente y para prevenir problemas de seguridad siempre que greetd o el greeter salgan. Esto se comprueba mediante la presencia del archivo de ejecución.

command = línea-de-comandos

La línea de comandos que greetd ejecutará para iniciar la sesión inicial, por ejemplo, "sway". La sesión inicial se iniciará exactamente una vez cuando greetd se lance inicialmente.

La línea de comandos es ejecutada por sh(1), y como tal acepta sintaxis estándar del shell POSIX.

user = usuario

El usuario a utilizar para ejecutar la sesión inicial.

EJEMPLOS

Configuración regular con agreety y sway

[terminal]
vt = 1
[default_session]
command = "agreety -c sway"

Auto-login

[terminal]
vt = 1
[default_session]
command = "agreety -c sway"
[initial_session]
command = "sway"
user = "john"
