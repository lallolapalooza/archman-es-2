DESCRIPCIÓN

El comando gfortran soporta todas las opciones soportadas por el comando gcc. Solo las opciones específicas de GNU Fortran se documentan aquí.

Todas las opciones de GCC y GNU Fortran son aceptadas tanto por gfortran como por gcc (así como por cualquier otro controlador compilado al mismo tiempo, como g++), ya que la adición de GNU Fortran a la distribución de GCC permite que todos los controladores relevantes acepten las opciones de GNU Fortran.

En algunos casos, las opciones tienen formas positiva y negativa; la forma negativa de -ffoo sería -fno-foo. Este manual documenta solo una de estas dos formas, la que no sea la predeterminada.

Opciones que controlan el dialecto de Fortran

Las siguientes opciones controlan los detalles del dialecto de Fortran aceptado por el compilador:

-ffree-form
-ffixed-form
Especifica el formato utilizado por el archivo fuente. El formato libre se introdujo en Fortran 90. El formato fijo se utilizaba tradicionalmente en programas Fortran más antiguos. Cuando no se especifica ninguna de las opciones, el formato fuente se determina por la extensión del archivo.
-fall-intrinsics
Esta opción hace que se acepten todos los procedimientos intrínsecos (incluidas las extensiones específicas de GNU). Esto puede ser útil con -std= para forzar el cumplimiento del estándar pero obtener acceso al rango completo de intrínsecos disponibles con gfortran. Como consecuencia, se ignora -Wintrinsics-std y no se llama a ningún procedimiento definido por el usuario con el mismo nombre que cualquier intrínseco, excepto cuando se declara explícitamente "EXTERNAL".
-fallow-argument-mismatch
Algunos códigos contienen llamadas a procedimientos externos con discrepancias entre las llamadas y la definición del procedimiento, o con discrepancias entre diferentes llamadas. Dicho código no cumple con el estándar y generalmente se marca con un error. Esta opción degrada el error a una advertencia que solo puede desactivarse deshabilitando todas las advertencias con -w. Solo se marca una ocurrencia por argumento con esta advertencia. -fallow-argument-mismatch está implícito en -std=legacy.

El uso de esta opción está *fuertemente* desaconsejado. Es posible proporcionar código que cumpla con el estándar y que permita diferentes tipos de argumentos utilizando una interfaz explícita y TYPE(*).

-fallow-invalid-boz
Una constante literal BOZ puede aparecer en un número limitado de contextos en Fortran conforme al estándar. Esta opción degrada una condición de error a una advertencia y permite que una constante literal BOZ aparezca donde el estándar de Fortran de lo contrario la prohibiría.

-fd-lines-as-comments
Habilita un tratamiento especial para las líneas que comienzan con "d" o "D" en fuentes de formato fijo. Si se proporciona la opción -fd-lines-as-code, se tratan como si la primera columna contuviera un espacio en blanco. Muchos compiladores Fortran, incluido GNU Fortran, permiten pasar el código fuente a través de un preprocesador de C (CPP; a veces también llamado el preprocesador de Fortran, FPP) para permitir la compilación condicional. En el caso de GNU Fortran, este es el Preprocesador de C de GNU en el modo tradicional. En sistemas con nombres de archivo que preservan mayúsculas y minúsculas, el preprocesador se invoca automáticamente si la extensión del nombre de archivo es .F, .FOR, .FTN, .fpp, .FPP, .F90, .F95, .F03 o .F08. Para invocar manualmente el preprocesador en cualquier archivo, use -cpp; para deshabilitar el preprocesamiento en archivos donde el preprocesador se ejecuta automáticamente, use -nocpp

.

Si un archivo preprocesado incluye otro archivo con la sentencia Fortran "INCLUDE", el archivo incluido no es preprocesado. Para preprocesar archivos incluidos, use la sentencia de preprocesador equivalente "#include"

OPCIONES DEL PREPROCESADOR

Estas opciones controlan el preprocesamiento del código Fortran. El preprocesamiento es el paso que realiza el compilador para manejar directivas como #include y #define, antes de la compilación real. Esto es especialmente relevante para los archivos con extensiones como .f90, .f95, etc., aunque el preprocesador de GNU Fortran también puede manejar extensiones más antiguas como .f o .for.

La compilación de archivos que requieren preprocesamiento, como los que usan macros o directivas #include, es una característica importante, aunque no sea utilizada directamente por el compilador GNU Fortran en todos los casos.

Las siguientes opciones controlan el preprocesamiento del código Fortran:

-cpp
-nocpp
Habilita el preprocesamiento. El preprocesador se invoca automáticamente si la extensión del archivo es .fpp, .FPP, .F, .FOR, .FTN, .F90, .F95, .F03 o .F08. Usa esta opción para habilitar manualmente el preprocesamiento de cualquier tipo de archivo Fortran.

Para deshabilitar el preprocesamiento de archivos con cualquiera de las extensiones listadas anteriormente, usa la forma negativa: -nocpp.

El preprocesador se ejecuta en modo tradicional. Cualquier restricción del formato del archivo, especialmente los límites de longitud de línea, se aplica también a la salida preprocesada, por lo que podría ser aconsejable usar las opciones -ffree-line-length-none o -ffixed-line-length-none.

-dM
En lugar de la salida normal, genera una lista de directivas '#define' para todas las macros definidas durante la ejecución del preprocesador, incluidas las macros predefinidas. Esto te da una forma de averiguar qué está predefinido en tu versión del preprocesador. Suponiendo que no tienes el archivo foo.f90, el comando 
touch foo.f90; gfortran -cpp -E -dM foo.f90

muestra todas las macros predefinidas.

-dD
Similar a -dM excepto en dos aspectos: no incluye las macros predefinidas y emite tanto las directivas "#define" como el resultado del preprocesamiento. Ambos tipos de salida van al archivo de salida estándar.
-dN
Similar a -dD, pero emite solo los nombres de las macros, no sus expansiones.
-dU
Similar a dD excepto en que solo se emiten las macros que se expanden, o cuya definibilidad se prueba en directivas del preprocesador; la salida se retrasa hasta el uso o la prueba de la macro; y también se emiten directivas '#undef' para macros probadas pero no definidas en ese momento.
-dI
Emite directivas '#include' además del resultado del preprocesamiento.
-fworking-directory
Habilita la generación de marcadores de línea en la salida del preprocesador que informan al compilador del directorio de trabajo actual en el momento del preprocesamiento. Cuando esta opción está habilitada, el preprocesador emite, después del marcador de línea inicial, un segundo marcador de línea con el directorio de trabajo actual seguido de dos barras. GCC usa este directorio, cuando está presente en la entrada preprocesada, como el directorio emitido como directorio de trabajo actual en algunos formatos de información de depuración. Esta opción está implícitamente habilitada si la información de depuración está habilitada, pero esto puede ser inhibido con la forma negada -fno-working-directory. Si el flag -P está presente en la línea de comandos, esta opción no tiene efecto, ya que no se emiten directivas "#line" en absoluto.
-idirafter dir
Busca en dir archivos de inclusión, pero lo hace después de que se hayan agotado todos los directorios especificados con -I y los directorios del sistema estándar. dir se trata como un directorio de inclusión del sistema. Si dir comienza con "=", entonces el "=" se reemplaza por el prefijo sysroot; consulta --sysroot y -isysroot.
-imultilib dir
Usa dir como un subdirectorio del directorio que contiene las cabeceras específicas del objetivo C++.
-iprefix prefix
Especifica prefix como el prefijo para las opciones -iwithprefix subsiguientes. Si el prefix representa un directorio, debes incluir la barra final ('/').
-isysroot dir
Esta opción es similar a la opción --sysroot, pero se aplica solo a los archivos de cabecera. Consulta la opción --sysroot para más información.
-iquote dir
Busca en dir solo para los archivos de cabecera solicitados con "#include "file""; no se buscan para "#include <file>", antes de todos los directorios especificados con -I y antes de los directorios del sistema estándar. Si dir comienza con "=", entonces el "=" se reemplaza por el prefijo sysroot; consulta --sysroot y -isysroot.
-isystem dir
Busca en dir archivos de cabecera, después de todos los directorios especificados con -I pero antes de los directorios del sistema estándar. Lo marca como un directorio del sistema, de modo que reciba el mismo tratamiento especial que se aplica a los directorios del sistema estándar. Si dir comienza con "=", entonces el "=" se reemplaza por el prefijo sysroot; consulta --sysroot y -isysroot.
-nostdinc
No busca en los directorios del sistema estándar archivos de cabecera. Solo se buscan los directorios que has especificado con las opciones -I (y el directorio del archivo actual, si es apropiado).
-undef
No predefine ninguna macro específica del sistema o específica de GCC. Las macros predefinidas estándar permanecen definidas.
-Apredicado=respuesta
Realiza una aserción con el predicado predicado y la respuesta respuesta. Esta forma es preferible a la forma antigua -A predicado(respuesta), que todavía se admite, porque no utiliza caracteres especiales del shell.
-A-predicado=respuesta
Cancela una aserción con el predicado predicado y la respuesta respuesta.
-C
No descarta comentarios. Todos los comentarios se pasan al archivo de salida, excepto los comentarios en directivas procesadas, que se eliminan junto con la directiva.

Debes estar preparado para efectos secundarios al usar -C; hace que el preprocesador trate los comentarios como tokens por derecho propio. Por ejemplo, los comentarios que aparecen al principio de lo que sería una línea de directiva tienen el efecto de convertir esa línea en una línea de código fuente ordinaria, ya que el primer token en la línea ya no es un '#'.

Advertencia: actualmente solo maneja comentarios estilo C. El preprocesador aún no reconoce comentarios estilo Fortran.

-CC
No descarta comentarios, incluso durante la expansión de macros. Esto es similar a -C, excepto que los comentarios contenidos dentro de las macros también se pasan al archivo de salida donde la macro se expande.

Además de los efectos secundarios de la opción -C, la opción -CC hace que todos los comentarios estilo C++ dentro de una macro se conviertan en comentarios estilo C. Esto es para evitar que el uso posterior de esa macro comente inadvertidamente el resto de la línea de código fuente. La opción -CC se usa generalmente para admitir comentarios lint.

Advertencia: actualmente solo maneja comentarios estilo C y C++. El preprocesador aún no reconoce comentarios estilo Fortran.

-Dnombre
Predefine nombre como una macro, con definición 1.
-Dnombre=definición
El contenido de definición se tokeniza y se procesa como si hubiera aparecido durante la fase tres de traducción en una directiva '#define'. En particular, la definición se trunca por caracteres de nueva línea incrustados.

Si estás invocando el preprocesador desde un shell o un programa similar a un shell, es posible que necesites usar la sintaxis de comillas del shell para proteger caracteres como los espacios que tienen un significado en la sintaxis del shell.

Si deseas definir una macro similar a una función en la línea de comandos, escribe su lista de argumentos con paréntesis alrededor antes del signo igual (si lo hay). Los paréntesis son significativos para la mayoría de los shells, por lo que necesitas citar la opción. Con sh y csh, funciona "-D'nombre(args...)=definición'".

Las opciones -D y -U se procesan en el orden en que se dan en la línea de comandos. Todas las opciones -imacros archivo y -include archivo se procesan después de todas las opciones -D y -U.

-H
Imprime el nombre de cada archivo de cabecera utilizado, además de otras actividades normales. Cada nombre se indenta para mostrar qué tan profundo está en la pila de '#include'.
-P
Inhabilita la generación de marcadores de línea en la salida del preprocesador. Esto podría ser útil al ejecutar el preprocesador en algo que no es código C, y se envía a un programa que podría confundirse con los marcadores de línea.
-Unombre
Cancela cualquier definición previa de nombre, ya sea integrada o proporcionada con una opción -D.

Los errores son mensajes de diagnóstico que informan que el compilador GNU Fortran no puede compilar la pieza relevante del código fuente. El compilador continúa procesando el programa en un intento de informar errores adicionales para ayudar en la depuración, pero no produce ninguna salida compilada.

Las advertencias son mensajes de diagnóstico que informan sobre construcciones que no son inherentemente erróneas pero que son arriesgadas o sugieren que es probable que haya un error en el programa. A menos que se especifique -Werror, no impiden la compilación del programa.
