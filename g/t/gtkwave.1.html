GTKWAVE(1) Visor de ondas de simulación GTKWAVE(1)

NOMBRE

gtkwave - Herramienta de visualización para archivos VCD, LXT, LXT2, VZT, FST y GHW

SINTAXIS

gtkwave [opción]... [ARCHIVODEVOLCADO] [ARCHIVODEGUARDADO] [ARCHIVORC]

DESCRIPCIÓN

Herramienta de visualización para VCD, LXT, LXT2, VZT, FST y GHW. VCD es un formato de volcado de simulación estándar de la industria. LXT, LXT2, VZT y FST han sido diseñados específicamente para su uso con gtkwave. GHW es el formato VHDL nativo generado por GHDL. Existen volcadores nativos en Icarus Verilog y la versión de código abierto de VeriWell para los formatos LXT, por lo que la conversión con vcd2lxt(1) o vcd2lxt2(1) no es necesaria para aprovechar directamente LXT con esos simuladores. Los archivos AET2 también pueden ser procesados siempre que libae2rw esté disponible, pero esto solo es de interés para personas que utilizan conjuntos de herramientas EDA de IBM.

OPCIONES

-n,--nocli <nombre de directorio>
Usar el selector de archivos para el nombre del archivo de volcado.
-f,--dump <nombre de archivo>
Especificar el nombre del archivo de volcado.
-F,--fastload
generar/usar archivos de carga rápida de grabadora VCD. Esto es similar a la -g,--giga opción, sin embargo el archivo de desbordamiento generado no es eliminado. Recargar el archivo VCD otra vez (ya sea presionando el botón de recarga o invocando gtkwave de nuevo más tarde) usará este archivo de desbordamiento generado en lugar de leer la sección de cambios de valor del archivo VCD. Esto acelerará enormemente las recargas en archivos grandes, ya que solo se necesita analizar la sección de declaración de variables. Tenga en cuenta que el archivo de desbordamiento contiene el tamaño del archivo y la fecha de modificación del archivo VCD para detectar si está obsoleto y necesita ser regenerado.
-o,--optimize
optimizar VCD a FST. Esto llamará automáticamente a vcd2fst(1) para realizar la conversión del archivo. Esta opción es muy recomendable con archivos VCD grandes para reducir el uso de memoria necesario para la visualización del archivo. Puede usarse en conjunto con -v,--vcd.
-a,--save <nombre de archivo>
Especificar el nombre del archivo de guardado. Los sufijos útiles para la integración con el escritorio son .gtkw y .sav (obsoleto).
-A,--autosavename
Asumir que el archivo de guardado es el nombre del archivo de volcado con el sufijo modificado (es decir, eliminar y reemplazar con ".gtkw").
-r,--rcfile <nombre de archivo>
Especificar el nombre del archivo .gtkwaverc de anulación.
-l,--logfile <nombre de archivo>
Especificar el nombre del archivo de registro de simulación. Se pueden especificar múltiples archivos de registro precediendo cada uno con el indicador de comando. Al seleccionar los números en el widget de texto, el marcador hará zoom inmediatamente al valor de tiempo específico.
-d,--defaultskip
Si no hay un archivo .gtkwaverc en el directorio de inicio o en el directorio actual y no se especifica explícitamente en la línea de comando, cuando esta opción está habilitada, no usar un archivo de configuración implícito y en su lugar usar el antiguo comportamiento de "pantalla en blanco".
-D,--dualid <cuál>
Especificar información de identificador de multisesión. El formato de "cuál" es m+nnnnnnnn donde m es el número de sesión 0 o 1 y nnnnnnnn es un valor hexadecimal que indica el ID de memoria compartida de un arreglo de dos estructuras gtkwave_dual_ipc_t. El uso previsto de este indicador es para front-ends como twinwave(1).
-s,--start <tiempo>
Especificar el tiempo de inicio para el salto de bloque LXT2/VZT.
-e,--end <tiempo>
Especificar el tiempo de fin para el salto de bloque LXT2/VZT.
-t,--stems <nombre de archivo>
Especificar el archivo de stems para la anotación de código fuente. Esto lanzará automáticamente el proceso auxiliar rtlbrowse(1) . Vea xml2stems(1) para información sobre la generación del archivo de stems.
-c,--cpu <numcpus>
Especificar el número de CPUs disponibles para operaciones paralelizables (por ejemplo, precarga de bloques en lecturas VZT).
-N,--nowm
Deshabilitar el gestor de ventanas para la mayoría de las ventanas. El uso previsto de esto es usarse en conjunto con la opción --script , sin embargo esto también puede usarse para reapadrinar en un gestor de ventanas alternativo.
-M,--nomenus
No renderizar la barra de menús. Esto se usa principalmente para crear una applet restringida que no puede iniciar E/S de archivos por sí misma, sin embargo también puede usarse como una solución alternativa en versiones anteriores de GTK+ que no manejan correctamente las interacciones de foco GTKSocket/GTKPlug.
-S,--script <nombre de archivo>
Especificar el archivo de script de comandos Tcl para ejecución.
-T,--tcl_init <nombre de archivo>
Especificar el script de comandos Tcl que se cargará al inicio. Implica el indicador de comando --wish.
-W,--wish
Habilitar la línea de comandos Tcl en stdio. Todos los comandos de script pueden escribirse en stdin.
-R,--repscript <nombre de archivo>
Especificar el script de comandos Tcl para ejecución periódica.
-P,--repperiod <valor>
Especifica el retraso en milisegundos entre ejecuciones sucesivas del repscript. El valor predeterminado es 500.
-X,--xid <XID>
Especificar el XID (en hexadecimal) de la ventana a la que un GtkPlug debe conectarse. GTKWave no renderiza directamente a una ventana, sino que renderiza en un GtkPlug esperando un GtkSocket en el otro extremo. Tenga en cuenta que hay problemas con el funcionamiento correcto de los aceleradores, por lo que los menús están deshabilitados en la versión componentizada de GTKWave cuando funciona como un plug-in.
-1,--rpcid <RPCID>
Especificar el RPCID de la sesión de GConf (o GSettings). Este es un valor decimal cero o mayor y es el identificador usado por GConf para saber qué datos de actualización escuchar. Esta opción solo funciona si --with-gconf (o --with-gsettings) se especificó durante ./configure.
-2,--chdir <NOMBREDEDIRECTORIO>
Especificar un nuevo directorio de trabajo actual. Esto se usa típicamente en OSX para ejecutar gtkwave si fue compilado y colocado en un paquete .app. Tenga en cuenta que si la variable de entorno GTKWAVE_CHDIR está definida, el argumento es un argumento ficticio. Esto es para soportar OSX, ya que el comando open tiene dificultades para pasar espacios como argumentos de línea de comando y es posible que pwd(1) devuelva espacios.
-3,--restore
Restaurar la sesión anterior predeterminada (0) o la sesión numerada por --rpcid RPCID. Esto solo funciona para un archivo de volcado, archivo de guardado, archivo rc y directorio de trabajo actual, por lo que tiene el efecto de restaurar el archivo cargado más recientemente. Si se usa en conjunto con la opción --rpcid , esa opción debe especificarse antes en la línea de comando que la opción --restore . Si no se especifica RPCID, se usa el valor predeterminado de 0. Esta opción solo funciona si --with-gconf (o --with-gsettings) se especificó durante ./configure. Tenga en cuenta que para GSettings, las limitaciones en su implementación le permiten solo restaurar la sesión anterior.
-4,--rcvar
Especificar valores de variables rc individuales. Estos entran en efecto después de que cualquier otra variable rc haya sido cargada de los valores predeterminados internos o de archivos de configuración.
-5,--sstexclude
Especificar el nombre del archivo del filtro de exclusión sst.
-6,--dark
Establecer gtk-application-prefer-dark-theme = TRUE.
-7,--saveonexit
Al salir, se muestra un selector para pedirle al usuario que escriba un archivo de guardado. Cancelar el selector evita escribir el archivo.
-I,--interactive</dt>
Especifica que se debe usar el modo VCD "interactivo", que permite al espectador navegar por un rastro VCD mientras GTKWave procesa el archivo VCD. Cuando se usa esta opción, el nombre del archivo se sobrecarga de tal manera que es el valor hexadecimal del ID de memoria compartida de un escritor. Tenga en cuenta que el ID de memoria compartida se puede pasar directamente desde stdin usando la opción --vcd; consulte la página man de shmidcat(1) para más detalles.
-L,--legacy
Especifica que el espectador debe usar el modo VCD heredado en lugar del codificador VCD. Tenga en cuenta que el uso del modo heredado requerirá considerablemente más memoria que el codificador y su uso no se recomienda para rastros muy grandes.
-g,--giga
Especifica que el espectador debe usar empaquetado de memoria de gigabytes al codificar (posiblemente más lento). Esto es equivalente a establecer las marcas vlist_spill y vlist_prepack en el archivo rc.
-C,--comphier
Especifica que el espectador debe usar nombres de jerarquía comprimidos al cargar el archivo volcado (disponible para codificador VCD, LXT, LXT2 y VZT). Esto utilizará menos memoria a expensas de un retraso de compresión/descompresión.
-v,--vcd
Usa stdin como un archivo volcado VCD.
-O,--output <nombre_archivo>
Especifica el nombre del archivo para la redirección de stdout/stderr. Para deshabilitar mensajes a la consola, usa /dev/null como nombre del archivo.
-z,--slider-zoom
Habilita el zoom de estiramiento de deslizador para el deslizador de tiempo horizontal. Hacer clic y luego arrastrar el borde muy izquierdo o derecho del deslizador se puede usar para proporcionar un zoom fino en tiempo real.
-V,--version
Muestra el banner de la versión y sale.
-h,--help
Muestra la ayuda y sale.
-x,--exit
Sale después de cargar el rastro (para la evaluación comparativa del cargador).

ARCHIVOS

~/.gtkwaverc (ver página man gtkwaverc(5))

EJEMPLOS

Para ejecutar este programa de la forma estándar, escriba:
gtkwave dumpfile.vcd
Alternativamente, puede ejecutarlo con un archivo de guardado como:
gtkwave dumpfile.vcd dumpfile.gtkw
Para ejecutar interactivamente usando el manejador de memoria compartida 0x00050003:
gtkwave -I 00050003 dumpfile.gtkw
Para recoger un archivo volcado automáticamente de un archivo de guardado (por ejemplo, al iniciar desde un icono):
gtkwave --save dumpfile.gtkw
Para ejecutar desde el paquete de aplicación gtkwave.app en OSX usando /bin/sh:
GTKWAVE_CHDIR=`pwd`;export GTKWAVE_CHDIR;open -n -W -a gtkwave --args --chdir dummy --dump des.vzt --save des.gtkw
Alternativamente, ejecute el siguiente script de Perl gtkwave.app/Contents/Resources/bin/gtkwave para procesar los argumentos de la línea de comandos desde scripts de shell de OSX.
Tenga en cuenta que para pasar elementos que no sean opciones y que comiencen con un guion, es necesario especificar -- para desactivar el análisis de opciones. Un segundo -- deshabilitará el análisis de cualquier argumento siguiente, de modo que puedan pasarse a scripts Tcl y recuperarse a través de gtkwave::getArgv.

Las opciones de la línea de comandos no son necesarias para representar los nombres de los archivos volcados, de guardado y de rc. Simplemente se proporcionan para permitir especificarlos fuera de orden.

ERRORES

AIX requiere -bmaxdata:0x80000000 (-bmaxdata:0xd0000000 /dsa para AIX 5.3) que se agregue a su lista de flags del compilador para xlc si desea que GTKWave pueda acceder a más de 256 MB de memoria virtual. El valor mostrado permite que el VMM use hasta 2GB (3.25GB AIX5.3). Esto puede ser necesario para rastros muy grandes.
Las operaciones Shift y Page usando la barra de desplazamiento de la ventana de ondas pueden no ser funcionales a medida que se aleja del inicio del volcado para rastros muy grandes. Se sabe que un rastro que llega a 45 mil millones de ticks exhibe este problema. Esto se debe al uso del elemento gfloat del deslizador horizontal para codificar el valor de tiempo del margen izquierdo. El resultado es una pérdida de precisión para valores muy grandes. Use las teclas de acceso rápido o los botones en la parte superior de la pantalla si esto es un problema.
Al ejecutarse bajo Cygwin, es necesario habilitar Cygserver si se está utilizando IPC de memoria compartida. Específicamente, esto ocurre cuando rtlbrowse(1) se inicia como un proceso auxiliar. Consulte la documentación de Cygwin para obtener más información sobre cómo habilitar Cygserver.
