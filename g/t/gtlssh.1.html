El programa gtlssh se conecta a un servidor remoto, autentica el servidor remoto usando SSL, y luego se autentica a sí mismo con el

servidor.

gtlsshd intentará primero una conexión SCTP

, y recurrirá a T
CP si eso no funciona.

AUTENTICACIÓN DEL

HOST

Después de conectarse, el host se valida primero usando SSL estándar. Las claves usadas para la validación están en $HOME/.gtlssh/server_certs por defecto. Si la clave dada no es reconocida, se le solicita al usuario con la huella digital del certificado si desea aceptar el

certificado.

Si el usuario acepta el certificado, este se agrega al directorio predeterminado. Si no, la conexión se

termina.

Los certificados se almacenan en la forma "<nombre de host>,<puerto>.crt" y "<dirección ip>,<puerto>.crt". Ambos se crean para

una conexión (a menos que se conecte con una dirección IP). Una conexión se verifica como coincidente con ambas entradas, si e
l certificado en el archivo no coincide con el certificado del extremo remoto, la conexión se termina y se informa al usuario.

AUTENTICACIÓN DEL

USUARIO

Si la autenticación del host tiene éxito, gtlssh se autentica con una clave y un certificado. Estos archivos se obtienen por defecto de $HOME/.gtlssh/keycerts en la forma <host>[,<puerto>].key y <host>[,<puerto>].crt. Si la forma con el host y el puerto existe, se usa esa. De lo contrario, si la forma con solo el host existe, se usa esa. De lo contrario, por defecto usa $HOME/.gtlssh/default.key y $HOME/.gttlssh/default.

crt.

El extremo remoto busca el certificado en $HOME/.gtlssh/allo

wed_certs. Si el extremo remoto no tiene el certificado
presentado, se intenta la autenticación por contraseña.

MODO

INTERACTIVO

Si el stdin de gtlssh es un tty y no se da ningún programa para ejecutar, entonces el inicio de sesión es interactivo. Cualquier tipo de retraso en el procesamiento de E/S está desactivado, y el terminal local se usa para E/S y se pone en modo

crudo

En modo no interactivo, el lado local usa stdio para E/S local y el re

traso en el procesamiento de E/S en el lado de la red no se desactiva.
Esto es útil para programas que transfieren datos a través de la conexión.

ESCAPE

S

Si se recibe el carácter de escape del usuario, el carácter no se transfiere y el programa espera otro carácter. Si el otro carácter también es el carácter de escape, se envía un solo carácter de escape. Si el otro carácter no se reconoce como un escape válido, se ignora y no se transfiere. Las mayúsculas y minúsculas son

equivalentes.

Los caracteres de escape

son:
q
Salir del
programa.
b
Enviar una interrupción a io2. Se ignora si io2 no soporta
interrupciones.
d
Volcar datos seriales para io2. Se ignora si io2 no es compatible con
RFC2217.
s
Establecer la velocidad (baudios) del puerto serie para io2. Se ignora si io2 no es compatible con RFC2177. Después de esto, la velocidad del puerto serie debe escribirse, terminada por un salto de línea. Las velocidades no válidas se ignoran, use escchar-d para saber si la estableció
correctamente.
n, o,
e
Establecer la paridad en io2 a ninguna, impar o par. Se ignora si io2 no es compatible con
RFC2217.
7,
8
Establecer el tamaño de datos en io2 a 7 u 8 bits. Se ignora si io2 no es compatible con
RFC2217.
1,
2
Establecer el número de bit
s de parada a 1 o 2 en io2.
