NOMBRE

gh-attestation-verify - Verificar la integridad de un artefacto usando atestaciones

SINOPSIS

gh attestation verify [<ruta-archivo> | oci://<uri-imagen>] [--owner | --repo] [flags]

DESCRIPCIÓN

Verifica la integridad y procedencia de un artefacto usando sus atestaciones asociadas firmadas criptográficamente.

Comprensión de la verificación

Una atestación es una afirmación (es decir, una declaración de procedencia) hecha por un actor (es decir, un flujo de trabajo de GitHub Actions) sobre un sujeto (es decir, un artefacto).

Para verificar una atestación, debes proporcionar un artefacto y validar: * la identidad del actor que produjo la atestación * el tipo de predicado de atestación esperado (la naturaleza de la afirmación)

Por defecto, este comando aplica el tipo de predicado https://slsa.dev/provenance/v1. Para verificar otros tipos de predicados de atestación, usa el flag --predicate-type.

La "identidad del actor" consiste en: * el repositorio o el dueño del repositorio con el que está vinculado el artefacto * el flujo de trabajo de Actions que produjo la atestación (también conocido como el
flujo de trabajo firmante)

Esta identidad se valida luego contra los campos SourceRepository, SourceRepositoryOwner y SubjectAlternativeName (SAN), entre otros, del certificado de la atestación.

Depende de ti decidir cuán precisamente quieres aplicar esta identidad.

Como mínimo, este comando requiere uno de los siguientes: * el flag --owner (ej. --owner github), o * el flag --repo (ej. --repo github/example)

Cuanto más precisamente especifiques la identidad, más control tendrás sobre las garantías de seguridad ofrecidas por el proceso de verificación.

Idealmente, la ruta del flujo de trabajo firmante también se valida usando los flags --signer-workflow o --cert-identity.

Tenga en cuenta: si su atestación se generó a través de un flujo de trabajo reutilizable, entonces ese flujo de trabajo reutilizable es el firmante cuya identidad debe ser validada. En esta situación, debe usar el flag --signer-workflow o el flag --signer-repo.

Para más opciones, ver los otros flags disponibles.

Carga de artefactos y atestaciones

Para especificar el artefacto, este comando requiere: * una ruta de archivo a un artefacto, o * una URI de imagen de contenedor (ej. oci://<uri-imagen>)
* (tenga en cuenta que si proporciona una URL OCI, ya debe estar autenticado con su registro de contenedor)

Por defecto, este comando intentará obtener las atestaciones relevantes a través de la API de GitHub usando los valores proporcionados a --owner o --repo.

Para obtener atestaciones desde el registro OCI de su artefacto en su lugar, use el flag --bundle-from-oci.

Para verificación sin conexión usando atestaciones almacenadas en disco (ver el comando download), proporcione una ruta al flag --bundle.

Aplicación adicional de políticas

Dado el flag --format=json, tras una verificación exitosa, este comando generará una matriz JSON que contiene una entrada por cada atestación verificada.

Esta salida puede ser utilizada para aplicar políticas adicionales, es decir, canalizándola a un motor de políticas.

Cada objeto en la matriz contiene dos propiedades: * un objeto attestation, que contiene el paquete que fue verificado * un objeto verificationResult, que es una representación analizada del contenido
del paquete que fue verificado.

Dentro del objeto verificationResult encontrará: * signature.certificate, que es una representación analizada del certificado X.509 incrustado en la atestación, * verifiedTimestamps, una matriz de objetos que denotan cuándo la atestación fue presenciada por un
log de transparencia o una autoridad de marca de tiempo * statement, que contiene la matriz subject que referencia artefactos, el campo
predicateType, y el objeto predicate que contiene metadatos adicionales, a menudo controlables por el usuario

IMPORTANTE: tenga en cuenta que solo las propiedades signature.certificate y verifiedTimestamps contienen valores que no pueden ser manipulados por el flujo de trabajo que originó la atestación.

Al tratar con atestaciones creadas dentro de GitHub Actions, el contenido de signature.certificate se completa directamente desde el token OpenID Connect generado por GitHub. El contenido de la matriz verifiedTimestamps se completa a partir de las marcas de tiempo firmadas originadas en un log de transparencia o una autoridad de marca de tiempo – y de manera similar no pueden ser falsificadas por los usuarios.

Al diseñar la aplicación de políticas usando esta salida, se debe tener especial cuidado al examinar el contenido de la propiedad statement.predicate: si un atacante obtuviera acceso al contexto de ejecución de su flujo de trabajo, podría falsificar el contenido de statement.predicate.

Para mitigar este vector de ataque, considere usar un "constructor de confianza": al generar un artefacto, haga que la compilación y la firma de la atestación ocurran dentro de un flujo de trabajo reutilizable cuya ejecución no pueda ser influenciada por la entrada proporcionada a través del flujo de trabajo que llama.

Ver arriba sobre --signer-workflow.

OPCIONES

-b, --bundle <cadena>
Ruta al paquete en disco, ya sea un solo paquete en un archivo JSON o un archivo de líneas JSON con múltiples paquetes
--bundle-from-oci
Al verificar una imagen OCI, obtener el paquete de atestación desde el registro OCI en lugar de GitHub
--cert-identity <cadena>
Aplicar que el SubjectAlternativeName del certificado coincida exactamente con el valor proporcionado
-i, --cert-identity-regex <cadena>
Aplicar que el SubjectAlternativeName del certificado coincida con la expresión regular proporcionada
--cert-oidc-issuer <cadena> (valor por defecto "https://token.actions.githubusercontent.com")
Aplicar que el emisor del token OIDC coincida con el valor proporcionado
--custom-trusted-root <cadena>
Ruta a un archivo trusted_root.jsonl; probablemente para verificación sin conexión
--deny-self-hosted-runners
Fallar la verificación para atestaciones generadas en runners autoalojados
-d, --digest-alg <cadena> (valor por defecto "sha256")
El algoritmo utilizado para calcular un digest del artefacto: {sha256|sha512}
--format <cadena>
Formato de salida: {json}
--hostname <cadena>
Configurar el host a utilizar
-q, --jq <expresión>
Filtrar la salida JSON usando una expresión jq
-L, --limit <entero> (valor por defecto 30)
Número máximo de atestaciones a obtener
--no-public-good
No verificar atestaciones firmadas con la instancia de bien público de Sigstore
-o, --owner <cadena>
Organización de GitHub para delimitar la búsqueda de atestaciones por
--predicate-type <cadena> (valor por defecto "https://slsa.dev/provenance/v1")
Aplicar que el tipo de predicado de las atestaciones verificadas coincida con el valor proporcionado

OPTIONS

-R, --repo <string>
Nombre del repositorio en el formato /
--signer-digest <string>
Forzar que el digest asociado con el flujo de trabajo del firmante coincida con el valor proporcionado.
--signer-repo <string>
Forzar que el repositorio del flujo de trabajo que firmó la atestación coincida con el valor proporcionado (/)
--signer-workflow <string>
Forzar que el flujo de trabajo que firmó la atestación coincida con el valor proporcionado ([host/]////)
--source-digest <string>
Forzar que el digest asociado con el repositorio de origen coincida con el valor proporcionado.
--source-ref <string>
Forzar que la referencia git asociada con el repositorio de origen coincida con la valor proporcionado.
-t, --template <string>
Formatear la salida JSON usando una plantilla Go; ver "gh help formatting".

CÓDIGOS DE SALIDA

0: Ejecución exitosa

1: Error

2: Comando cancelado

4: Autenticación requerida

NOTA: Los comandos específicos pueden tener códigos de salida adicionales. Consulte la ayuda del comando para obtener más información.

EJEMPLO

# Verificar un artefacto enlazado con un repositorio
$ gh attestation verify example.bin --repo github/example
# Verificar un artefacto enlazado con una organización
$ gh attestation verify example.bin --owner github
# Verificar un artefacto y mostrar el resultado completo de la verificación
$ gh attestation verify example.bin --owner github --format json
# Verificar una imagen OCI usando atestaciones almacenadas en disco
$ gh attestation verify oci://<image-uri> --owner github --bundle sha256:foo.jsonl
# Verificar un artefacto firmado con un flujo de trabajo reutilizable
$ gh attestation verify example.bin --owner github --signer-repo actions/example
