GH-RELEASE-CREATE(1) Manual de la CLI de GitHub GH-RELEASE-CREATE(1)

NOMBRE

gh-release-create - Crear una nueva versión

SINOPSIS

gh release create [<etiqueta>] [<nombre_archivo>... | <patrón>...]

DESCRIPCIÓN

Crea una nueva Versión de GitHub para un repositorio.

Se puede proporcionar una lista de archivos de activos para cargar en la nueva versión. Para definir una etiqueta de visualización para un activo, agregue texto que comience con # después del nombre del archivo.

Si aún no existe una etiqueta git coincidente, se creará automáticamente a partir del último estado de la rama predeterminada. Use --target para apuntar a una rama o commit diferente para la creación automática de etiquetas. Use --verify-tag para abortar la versión si la etiqueta no existe todavía. Para obtener la nueva etiqueta localmente después de la versión, ejecute git fetch --tags origin.

Para crear una versión a partir de una etiqueta git anotada, primero cree una localmente con git, envíe la etiqueta a GitHub y luego ejecute este comando. Use --notes-from-tag para obtener las notas de la versión de la etiqueta git anotada. Si la etiqueta no está anotada, se usará el mensaje del commit en su lugar.

Use --generate-notes para generar automáticamente notas usando la API de Notas de Versión de GitHub. Cuando se usan notas de versión generadas automáticamente, también se generará automáticamente un título de versión a menos que se haya pasado explícitamente un título. Notas de versión adicionales se pueden anteponer a las notas generadas automáticamente utilizando la opción --notes.

Por defecto, la versión se crea incluso si no hay nuevos commits desde la última versión. Esto puede resultar en la misma versión o una duplicada, lo cual puede no ser deseable en algunos casos. Use --fail-on-no-commits para fallar si no hay nuevos commits disponibles. Esta opción no tiene efecto si no existen versiones o si esta es la primera versión.

Versiones inmutables

Cuando la inmutabilidad de la versión está habilitada para un repositorio, se aplican las siguientes protecciones: - Las etiquetas Git asociadas con una versión no se pueden modificar ni eliminar. - Los activos de la versión no se pueden modificar ni eliminar.

La inmutabilidad se aplica solo después de que se publica una versión. Las versiones borradoras se pueden modificar o eliminar, y las etiquetas git asociadas también se pueden modificar o eliminar.

Al usar el comando create para adjuntar activos a una versión, se realizan llamadas API separadas para crear la versión como borrador, cargar los activos y luego publicar la versión. Las protecciones de inmutabilidad se aplicarán SOLAMENTE después de que se publique la versión.

OPCIONES

--discussion-category <cadena>
Iniciar una discusión en la categoría especificada
-d, --draft
Guardar la versión como borrador en lugar de publicarla
--fail-on-no-commits
Fallar si no hay commits desde la última versión (sin impacto en la primera versión)
--generate-notes
Generar automáticamente título y notas para la versión a través de la API de Notas de Versión de GitHub
--latest
Marcar esta versión como "Última" (por defecto [automático basado en fecha y versión]). --latest=false para explícitamente NO establecer como última
-n, --notes <cadena>
Notas de la versión
-F, --notes-file <archivo>
Leer notas de la versión desde un archivo (use "-" para leer desde la entrada estándar)
--notes-from-tag
Obtener notas de la anotación de la etiqueta o del mensaje del commit asociado con la etiqueta
--notes-start-tag <cadena>
Etiqueta a usar como punto de partida para generar las notas de la versión
-p, --prerelease
Marcar la versión como una versión preliminar
--target <rama>
Rama o SHA de commit completo de destino (por defecto [rama principal])
-t, --title <cadena>
Título de la versión
--verify-tag
Abortar en caso de que la etiqueta git no exista en el repositorio remoto

OPCIONES HEREDADAS DE COMANDOS PADRE

-R, --repo <[HOST/]PROPIETARIO/REPO>
Seleccionar otro repositorio usando el formato [HOST/]PROPIETARIO/REPO

ALIAS

gh release new

CÓDIGOS DE SALIDA

0: Ejecución exitosa

1: Error

2: Comando cancelado

4: Autenticación requerida

NOTA: Los comandos específicos pueden tener códigos de salida adicionales. Consulte la ayuda del comando para obtener más información.

EJEMPLO

# Crear una versión interactivamente
$ gh release create
# Crear una versión interactivamente desde una etiqueta específica
$ gh release create v1.2.3
# Crear una versión no interactivamente
$ gh release create v1.2.3 --notes "versión de corrección de errores"
# Usar notas de versión generadas automáticamente vía API de Notas de Versión de GitHub
$ gh release release create v1.2.3 --generate-notes
# Usar notas de versión desde un archivo
$ gh release create v1.2.3 -F release-notes.md
# Usar la anotación de etiqueta o el mensaje del commit asociado como notas
$ gh release create v1.2.3 --notes-from-tag
# No marcar la versión como la última
$ gh release create v1.2.3 --latest=false
# Cargar todos los tarballs en un directorio como activos de la versión
$ gh release create v1.2.3 ./dist/*.tgz
# Cargar un activo de versión con una etiqueta de visualización
$ gh release create v1.2.3 '/path/to/asset.zip#Mi etiqueta de visualización'
# Crear una versión e iniciar una discusión
$ gh release create v1.2.3 --discussion-category "General"
# Crear una versión solo si hay nuevos commits disponibles desde la última versión
$ gh release create v1.2.3 --fail-on-no-commits
