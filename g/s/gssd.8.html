rpc.gssd(8) Manual del Administrador del Sistema rpc.gssd(8)

NOMBRE

rpc.gssd - demonio RPCSEC_GSS

SINOPSIS

rpc.gssd [-DfMnlvrHC] [-k keytab] [-p directorio_pipefs] [-d directorio_ccache] [-t tiempo_espera] [-T tiempo_espera] [-U tiempo_espera] [-R reino]

INTRODUCCIÓN

El protocolo RPCSEC_GSS, definido en RFC 5403, se utiliza para proporcionar seguridad fuerte para protocolos basados en RPC como NFS.

Antes de intercambiar solicitudes RPC usando RPCSEC_GSS, un cliente RPC debe establecer un contexto de seguridad GSS. Un contexto de seguridad es un estado compartido en cada extremo de un transporte de red que habilita los servicios de seguridad de la API GSS.

Los contextos de seguridad se establecen utilizando credenciales de seguridad. Una credencial otorga acceso temporal a un servicio de red seguro, de manera similar a como un billete de tren otorga acceso temporal para usar un servicio ferroviario.

Un usuario típicamente obtiene una credencial proporcionando una contraseña al comando kinit(1), o a través de una biblioteca PAM al iniciar sesión. Una credencial adquirida con un principal de usuario se conoce como una credencial de usuario (ver kerberos(1) para más información sobre principales).

Ciertas operaciones requieren una credencial que no represente a ningún usuario en particular o que represente al propio host. Este tipo de credencial se llama credencial de máquina.

Un host establece su credencial de máquina utilizando un principal de servicio cuya contraseña cifrada se almacena en un archivo local conocido como keytab. Una credencial de máquina permanece efectiva sin intervención del usuario siempre que el host pueda renovarla.

Una vez obtenidas, las credenciales se almacenan típicamente en archivos temporales locales con nombres de ruta bien conocidos.

DESCRIPCIÓN

Para establecer contextos de seguridad GSS utilizando estos archivos de credenciales, el cliente RPC del kernel de Linux depende de un demonio de espacio de usuario llamado rpc.gssd. El demonio rpc.gssd usa el sistema de archivos rpc_pipefs para comunicarse con el kernel.

Credenciales de Usuario

Cuando un usuario se autentica usando un comando como kinit(1), la credencial resultante se almacena en un archivo con un nombre bien conocido construido usando el UID del usuario.

Para interactuar con un servidor NFS en nombre de un usuario particular autenticado por Kerberos, el cliente RPC del kernel de Linux solicita que rpc.gssd inicialice un contexto de seguridad con la credencial en el archivo de credenciales de ese usuario.

Típicamente, los archivos de credenciales se colocan en /tmp. Sin embargo, rpc.gssd puede buscar archivos de credenciales en más de un directorio. Ver la descripción de la opción -d para más detalles.

Credenciales de Máquina

rpc.gssd busca en el keytab por defecto, /etc/krb5.keytab, en el siguiente orden un principal y contraseña a utilizar al establecer la credencial de máquina. Para la búsqueda, rpc.gssd reemplaza <hostname> y <REALM> con el nombre de host del sistema local y el reino Kerberos.


<HOSTNAME>$@<REALM>
root/<hostname>@<REALM>
nfs/<hostname>@<REALM>
host/<hostname>@<REALM>
root/<cualquier_nombre>@<REALM>
nfs/<cualquier_nombre>@<REALM>
host/<cualquier_nombre>@<REALM>

rpc.gssd selecciona una de las entradas <cualquier_nombre> si no encuentra un principal de servicio que coincida con el nombre de host local, por ejemplo, si DHCP asigna el nombre de host local dinámicamente. La facilidad <cualquier_nombre> permite el uso del mismo keytab en múltiples sistemas. Sin embargo, usar el mismo principal de servicio para establecer una credencial de máquina en múltiples hosts puede crear exposiciones de seguridad no deseadas y, por lo tanto, no se recomienda.

Tenga en cuenta que <HOSTNAME>$@<REALM> es un principal de usuario que habilita NFS Kerberizado cuando el sistema local está unido a un dominio de Active Directory usando Samba. El keytab proporciona la contraseña para este principal.

Puede especificar un keytab diferente usando la opción -k si /etc/krb5.keytab no existe o no proporciona uno de estos principales.

Credenciales para UID 0

El UID 0 es un caso especial. Por defecto, rpc.gssd utiliza las credenciales de máquina del sistema para accesos de UID 0 que requieren autenticación GSS. Esto limita los privilegios del usuario root al acceder a recursos de red que requieren autenticación.

Especifique la opción -n al iniciar rpc.gssd si desea forzar al usuario root a obtener una credencial de usuario en lugar de usar las credenciales de máquina del sistema local.

Cuando se especifica -n, el kernel continúa solicitando un contexto GSS establecido con una credencial de máquina para operaciones NFSv4, como SETCLIENTID o RENEW, que gestionan el estado. Si rpc.gssd no puede obtener una credencial de máquina (por ejemplo, el sistema local no tiene un keytab), las operaciones NFSv4 que requieren credenciales de máquina fallarán.

Tipos de cifrado

Un administrador de reino puede optar por agregar claves codificadas en varios tipos de cifrado al keytab del sistema local. Por ejemplo, un principal host/ podría tener claves para los tipos de cifrado aes256-cts-hmac-sha1-96, aes128-cts-hmac-sha1-96, des3-cbc-sha1 y arcfour-hmac. Esto permite a rpc.gssd elegir un tipo de cifrado apropiado que el servidor NFS de destino soporte.

Estos tipos de cifrado son más fuertes que los tipos de cifrado legacy DES simple. Para interoperar en entornos donde los servidores solo soportan tipos de cifrado débiles, puede restringir su cliente para usar solo tipos de cifrado DES simple especificando la opción -l al iniciar rpc.gssd.

OPCIONES

-D
El nombre del servidor pasado a GSSAPI para autenticación es normalmente el nombre tal como se solicitó. Por ejemplo, para NFS es el nombre del servidor en la solicitud de montaje "nombre_servidor:/ruta". Solo si este nombre de servidor parece ser una dirección IP (IPv4 o IPv6) o un nombre no calificado (sin puntos) se realizará una búsqueda DNS inversa para obtener el nombre canónico del servidor.

Si -D está presente, una búsqueda DNS inversa se usará *siempre*, incluso si el nombre del servidor parece ser un nombre canónico. Por lo tanto, es necesaria si se utilizan regularmente nombres parcialmente calificados o no canónicos.

El uso de -D puede introducir una vulnerabilidad de seguridad, por lo que se recomienda que -D no se utilice y que siempre se utilicen nombres canónicos al solicitar servicios.

-f
Ejecuta rpc.gssd en primer plano y envía la salida a stderr (en lugar de syslogd)
-n
Cuando se especifica, se fuerza al UID 0 a obtener credenciales de usuario que se utilizan en lugar de las credenciales de máquina del sistema local.
-k keytab
Indica a rpc.gssd que use las claves encontradas en keytab para obtener credenciales de máquina. El valor por defecto es /etc/krb5.keytab.
-l
Cuando se especifica, restringe rpc.gssd a sesiones con tipos de cifrado débiles como des-cbc-crc. Esta opción solo está disponible cuando la biblioteca Kerberos del sistema local soporta tipos de cifrado configurables.
-p ruta
Indica a rpc.gssd dónde buscar el sistema de archivos rpc_pipefs. El valor por defecto es /var/lib/nfs/rpc_pipefs.
-d ruta_de_busqueda
Esta opción especifica una lista separada por dos puntos de directorios en los que rpc.gssd busca archivos de credenciales. El valor por defecto es /tmp:/run/user/%U. La secuencia literal "%U" puede especificarse para sustituir el UID del usuario para el que se buscan las credenciales.
