GS(1) Ghostscript GS(1)

NOMBRE

gs - Ghostscript (intérprete y visor de los lenguajes PostScript y PDF)

SINOPSIS

gs [ opciones ] [ archivos ] ... (Unix, VMS)
gswin32c [ opciones ] [ archivos ] ... (MS Windows)
gswin32 [ opciones ] [ archivos ] ... (MS Windows 3.1)
gsos2 [ opciones ] [ archivos ] ... (OS/2)

DESCRIPCIÓN

El comando gs (gswin32c, gswin32, gsos2) invoca Ghostscript, un intérprete de los lenguajes PostScript(tm) y Portable Document Format (PDF) de Adobe Systems. gs lee los "archivos" en secuencia y los ejecuta como programas de Ghostscript. Después de hacer esto, lee entrada adicional del flujo de entrada estándar (normalmente el teclado), interpretando cada línea por separado y enviando la salida a un dispositivo de salida (puede ser un archivo o una vista previa en una ventana X11, véase abajo). El intérprete sale limpiamente cuando encuentra el comando "quit" (ya sea en un archivo o desde el teclado), al final del archivo, o ante una señal de interrupción (como Control-C en el teclado).

El intérprete reconoce muchos modificadores de opciones, algunos de los cuales se describen a continuación. Por favor, consulte la documentación de uso para obtener información completa. Los modificadores pueden aparecer en cualquier lugar de la línea de comandos y se aplican a todos los archivos posteriores. Invocar Ghostscript con el modificador -h o -? produce un mensaje que muestra varios modificadores útiles, todos los dispositivos conocidos por ese ejecutable, y la ruta de búsqueda de fuentes; en Unix también muestra la ubicación de la documentación detallada.

Ghostscript puede ser compilado para usar muchos dispositivos de salida diferentes. Para ver qué dispositivos incluye su ejecutable, ejecute "gs -h".

A menos que especifique un dispositivo particular, Ghostscript normalmente abre el primero de ellos y dirige la salida a él.

Si está compilado con soporte X11, a menudo el dispositivo predeterminado es una ventana X11 (visor), de lo contrario, ghostscript normalmente usará el dispositivo bbox e imprimirá en stdout las dimensiones del archivo postscript.

Así que si el primero de la lista es el que desea usar, simplemente ejecute el comando

gs archivo.ps

También puede verificar el conjunto de dispositivos disponibles desde dentro de Ghostscript: invoque Ghostscript y escriba

devicenames ==

pero el primer dispositivo de la lista resultante puede no ser el dispositivo predeterminado que determina con "gs -h". Para especificar "AbcXyz" como el dispositivo de salida inicial, incluya el modificador

-sDEVICE=AbcXyz

Por ejemplo, para la salida a una impresora Epson, podría usar el comando

gs -sDEVICE=epson archivo.ps

El modificador "-sDEVICE=" debe preceder a la primera mención de un archivo a imprimir, y solo el primer uso del modificador tiene algún efecto.

Finalmente, puede especificar un dispositivo predeterminado en la variable de entorno GS_DEVICE. El orden de precedencia para estas alternativas de mayor a menor (Ghostscript usa el dispositivo definido más alto en la lista) es:

   setpagedevice
   (línea de comandos)
   GS_DEVICE
   (primer dispositivo en la lista de compilación)

Algunos dispositivos pueden admitir diferentes resoluciones (densidades). Para especificar la resolución en dicho dispositivo, use el modificador "-r":

gs -sDEVICE=<dispositivo> -r<xres>x<yres>

Por ejemplo, en una impresora compatible con Epson de 9 pines, obtendrá el modo de menor densidad (más rápido) con

gs -sDEVICE=epson -r60x72

y el modo de mayor densidad (mejor calidad de salida) con

gs -sDEVICE=epson -r240x72.

Si selecciona una impresora como dispositivo de salida, Ghostscript también le permite elegir a dónde envía Ghostscript la salida; en sistemas Unix, normalmente a un archivo temporal. Para enviar la salida a un archivo "foo.xyz", use el modificador

-sOutputFile=foo.xyz

Es posible que desee imprimir cada página por separado. Para hacer esto, envíe la salida a una serie de archivos "foo1.xyz, foo2.xyz, ..." usando el modificador "-sOutputFile=" con "%d" en una plantilla de nombre de archivo:

-sOutputFile=foo%d.xyz

Cada archivo resultante recibe una página de salida, y los archivos se numeran en secuencia. "%d" es una especificación de formato printf; también puede usar una variante como "%02d".

En sistemas Unix y MS Windows también puede enviar la salida a una tubería (pipe). Por ejemplo, para enviar la salida a la orden "lpr" (que, en muchos sistemas Unix, la dirige a una impresora), use la opción

-sOutputFile=%pipe%lpr

Tenga en cuenta que los caracteres '%' deben duplicarse en MS Windows para evitar que sean manipulados por el intérprete de comandos.

También puede enviar la salida a la salida estándar:

-sOutputFile=-
o 
-sOutputFile=%stdout%

En este caso, también debe usar el modificador -q para evitar que Ghostscript escriba mensajes en la salida estándar.

Para seleccionar un tamaño de papel específico, use el modificador de línea de comandos

-sPAPERSIZE=<tamaño_papel>

por ejemplo

-sPAPERSIZE=a4
o 
-sPAPERSIZE=legal

La mayoría de los tamaños de papel ISO y de EE. UU. son reconocidos. Consulte la documentación de uso para obtener una lista completa, o las definiciones en el archivo de inicialización "gs_statd.ps".

Ghostscript puede hacer muchas cosas además de imprimir o ver archivos PostScript y PDF. Por ejemplo, si desea conocer el cuadro delimitador de un archivo PostScript (o EPS), Ghostscript proporciona un "dispositivo" especial que simplemente imprime esta información.

Por ejemplo, usando uno de los archivos de ejemplo distribuidos con Ghostscript,

gs -sDEVICE=bbox golfer.ps

imprime

%%BoundingBox: 0 25 583 732
%%HiResBoundingBox: 0.808497 25.009496 582.994503 731.809445

OPCIONES

-- nombre_archivo arg1 ...
Toma el siguiente argumento como nombre de archivo como de costumbre, pero toma todos los argumentos restantes (incluso si tienen la forma sintáctica de modificadores) y define el nombre "ARGUMENTS" en "userdict" (no en "systemdict") como un array de esas cadenas, antes de ejecutar el archivo. Cuando Ghostscript termina de ejecutar el archivo, sale de nuevo a la consola.
-Dnombre=token

-dnombre=token
Define un nombre en "systemdict" con la definición dada. El token debe ser exactamente un token (como lo define el operador "token") y no puede contener espacios en blanco.
-Dnombre

-dnombre
Define un nombre en "systemdict" con valor=null.
-Snombre=cadena

-snombre=cadena
Define un nombre en "systemdict" con una cadena dada como valor. Esto es diferente de -d. Por ejemplo, -dname=35 es equivalente al fragmento de programa
/name 35 def
mientras que -sname=35 es equivalente a
/name (35) def
-P
Hace que Ghostscript busque primero en el directorio actual los archivos de biblioteca. Por defecto, Ghostscript ya no busca en el directorio actual, a menos que, por supuesto, el primer directorio explícitamente suministrado sea "." en -I. Véase también la sección ARCHIVOS DE INICIALIZACIÓN y el archivo adjunto Use.htm para una discusión detallada sobre las rutas de búsqueda y cómo Ghostscript encuentra archivos.
-q
Inicio silencioso: suprime los mensajes normales de inicio, y también hace el equivalente a -dQUIET.
-gnúmero1xnúmero2
Equivalente a -dDEVICEWIDTH=número1 y -dDEVICEHEIGHT=número2. Esto es para beneficio de dispositivos (como ventanas X11) que requieren (o permiten) especificar el ancho y la altura.

MODO

SAFER

La opción -dSAFER restringe los accesos al sistema de archivos a aquellos archivos y directorios permitidos por las variables de entorno relevantes (como GS_LIB) o por los parámetros de la línea de comandos (ver https://ghostscript.com/doc/current/Use.htm para detalles)

.

El modo SAFER es ahora el modo de operación por defecto. Por lo tanto, al ejecutar programas que necesitan abrir archivos o establecer parámetros restringidos, debe pasar la opción de línea de comandos -dNOSAFER o su sinónimo -dDELAYSAFER

.

Ejecutar con NOSAFER/DELAYSAFER (como el nombre sugiere) afloja la seguridad

y por lo tanto se recomienda ÚNICAMENTE para depuración o en flujos de trabajo M
UY controlados, y se desaconseja firmemente en cualquier otra circunstancia.

INICIALIZACIÓN

Al buscar los archivos de inicialización "gs_*.ps", los archivos relacionados con fuentes, o el archivo para el operador "run", Ghostscript primero intenta abrir el archivo con el nombre tal como se da, usando el directorio de trabajo actual si no se especifica ninguno. Si esto falla, y el nombre de archivo no especifica un directorio o unidad explícitos (por ejemplo, no contiene "/" en sistemas Unix o "\" en sistemas MS Windows ), Ghostscript intenta los directorios en este

orden:
1
.
los directorios especificados por los interruptores -I en la línea de comandos (ver abajo), si los
hay;
2
.
los directorios especificados por la variable de entorno GS_LIB, si la
hay;
3
.
los directorios especificados por la macro GS_LIB_DEFAULT en el archivo makefile de Ghostscript cuando se construyó el ejecutable. Cuando gs se construye en Unix, GS_LIB_DEFAULT es usualmente "/usr/local/share/ghostscript/#.##:/usr/local/share
/ghostscript/fonts" donde "#.##" repre
senta el número de versión de Ghostscript.

Cada uno de estos (GS_LIB_DEFAULT, GS_LIB, y el parámetro -I ) puede ser un solo directorio

o una lista de directori
os separados por ":".
