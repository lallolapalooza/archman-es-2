NOMBRE

gssproxy.conf - Archivo de configuración del demonio GssProxy

DESCRIPCIÓN

Directivas de configuración opcionales para el demonio gssproxy.

Los archivos de configuración de GSS-Proxy son archivos de configuración de estilo ini clásicos. Cada opción consiste en un par clave = valor. Cualquier carácter después de '#' se tratará como comentario y se ignorará. Los parámetros booleanos aceptan "1", "true", "yes" y "on" como valores positivos. Todos los demás valores se considerarán como valores negativos.

Los archivos de configuración de GSS-Proxy deben llamarse "gssproxy.conf" o tener el formato "##-foo.conf" (es decir, comenzar con dos números seguidos de un guión y terminar en ".conf"). Los archivos que no cumplan con esto se ignorarán a menos que se soliciten específicamente a través de parámetros de línea de comandos. Dentro de un mismo archivo, los valores o secciones duplicados se fusionarán. Entre múltiples archivos, los duplicados generarán una advertencia, y el primer valor encontrado tendrá precedencia (es decir, no hay fusión).

SECCIONES

Una sección en un archivo de configuración de GSS-Proxy se identifica por el nombre de la sección entre corchetes ([nombre_seccion]).

Hay una sección especial para la configuración global de gssproxy, llamada [gssproxy].

Servicios como nfs, apache, ssh, etc. se representan mediante secciones como [service/nfs], [service/apache], etc. y se identifican por la configuración "euid" (ver más abajo).

SUSTITUCIONES DE VARIABLES

Los parámetros de cadena pueden contener patrones de sustitución. Esto permite a gssproxy manejar patrones para la ubicación de almacenamiento de keytabs o cachés de credenciales de forma más sencilla.

Los patrones soportados son:

%U

se sustituye por el uid numérico del usuario (por ejemplo, 123)

%u

se sustituye por el nombre de usuario (por ejemplo, juan).

OPCIONES

gssproxy soporta las siguientes opciones:

allow_any_uid (booleano)

Permite que cualquier proceso de cualquier usuario utilice este servicio.

Tenga en cuenta que, en ausencia de una opción de socket personalizada, esta opción puede hacer que una definición de servicio enmascare el acceso a servicios posteriores. Para evitar problemas, cambie el orden de los servicios en su archivo de configuración para que los servicios con allow_any_uid habilitado se listen al final, o defina un socket personalizado para otros servicios.

Por defecto: falso

allow_protocol_transition (booleano)

Permite a los clientes solicitar un ticket para sí mismos para un usuario arbitrario.

Esta opción controla si las solicitudes s4u2self están permitidas para el cliente que las solicita. El keytab configurado se utiliza como la identidad del servicio para el que se solicita un ticket. El KDC aún debe permitir la operación para que tenga éxito.

Por defecto: falso

allow_constrained_delegation (booleano)

Permite a los clientes solicitar un ticket a otro servicio utilizando un ticket de evidencia.

Esta opción controla si las solicitudes s4u2proxy están permitidas para el cliente que las solicita. El KDC aún debe permitir la operación para que tenga éxito.

Por defecto: falso

allow_client_ccache_sync (booleano)

Permite a los clientes solicitar que se envíen credenciales para un mejor almacenamiento en caché.

Esta opción permite al proxy, en ciertas circunstancias, devolver una opción adicional en la estructura de respuesta de ciertas llamadas cuando determina que se puede haber agregado un nuevo ticket al ccache interno. Los clientes pueden entonces reemplazar su copia (cifrada) con el ccache actualizado.

Por defecto: falso

cred_store (cadena)

Este parámetro permite controlar de qué manera gssproxy debe utilizar la interfaz cred_store proporcionada por GSSAPI. El parámetro puede definirse varias veces por servicio.

La sintaxis del parámetro cred_store es la siguiente: cred_store = <opción_cred_store>:<valor_cred_store>

Actualmente, esta interfaz soporta las siguientes opciones:

keytab

Define el keytab que debe utilizar el servicio. Ejemplo: cred_store = keytab:/ruta/al/keytab

client_keytab

Define un keytab de cliente que debe utilizar el servicio. Ejemplo: cred_store = client_keytab:/ruta/al/client_keytab.

ccache

Define un ccache de credenciales que debe utilizar el servicio. Ejemplo: cred_store = ccache:/ruta/al/ccache.

Notablemente, la configuración client_keytab y ccache suelen utilizarse con marcadores de sustitución de variables (ver arriba). Por ejemplo:

    cred_store = keytab:/etc/krb5.keytab
    cred_store = ccache:FILE:/var/lib/gssproxy/krb5cc_%U
    cred_store = client_keytab:/var/lib/gssproxy/%U.keytab

Por defecto: cred_store =

cred_usage (cadena)

Permite restringir el tipo de operaciones permitidas para este servicio.

Las opciones permitidas son: initiate, accept, both

Por defecto: cred_usage = both

debug (booleano)

Habilita la depuración a syslog. Establecer en verdadero es idéntico a establecer debug_level a 1.

Por defecto: debug = falso

debug_level (entero)

Nivel de detalle al que se registrarán los mensajes de depuración. 0 corresponde a ningún registro, mientras que 1 activa el registro básico de depuración. El nivel 2 aumenta la verbosidad, incluyendo una verificación de credenciales más detallada.

En el nivel 3 y superior, se registran las salidas de KRB5_TRACE. Si KRB5_TRACE ya estaba configurado en el entorno de ejecución, la salida de traza se enviará a su valor en su lugar. Consulte docs/KRB5_TRACE.md para obtener más información.

Por defecto: 1 si debug es verdadero, de lo contrario 0

enforce_flags (cadena)

Una lista de Indicadores de Solicitud GSS que se agregan incondicionalmente a cada llamada de inicialización de contexto. Los indicadores solo pueden agregarse a la lista o eliminarse de la lista anteponiendo un signo +/- al nombre o valor del indicador.

Nombres de indicadores reconocidos: DELEGATE, MUTUAL_AUTH, REPLAY_DETECT, SEQUENCE, CONFIDENTIALITY, INTEGRITY, ANONYMOUS

Ejemplos:

    enforce_flags = +REPLAY_DETECT
    enforce_flags = -0x0001

Por defecto: enforce_flags =

euid (entero o cadena)

El uid efectivo numérico (por ejemplo, 48) o simbólico (por ejemplo, apache) de un proceso en ejecución, necesario para identificar un servicio.

El parámetro "euid" es imperativo, cualquier sección sin él será descartada.

Por defecto: euid =

filter_flags (cadena)

Una lista de Indicadores de Solicitud GSS que se filtran incondicionalmente de cada llamada de inicialización de contexto. Los indicadores solo pueden agregarse a la lista o eliminarse de la lista anteponiendo un signo +/- al nombre o valor del indicador.

NOTA: Dado que a menudo se utiliza gssproxy para retener el acceso a las credenciales, el Indicador de Delegación se filtra por defecto. Para permitir que un servicio delegue credenciales, use el primer ejemplo a continuación.

Nombres de indicadores reconocidos: DELEGATE, MUTUAL_AUTH, REPLAY_DETECT, SEQUENCE, CONFIDENTIALITY, INTEGRITY, ANONYMOUS

Ejemplos:

    filter_flags = -DELEGATE
    filter_flags = -0x0001 +ANONYMOUS

Por defecto: filter_flags = +DELEGATE

impersonate (booleano)

Utiliza la suplantación (s4u2self + s4u2proxy) para obtener credenciales.

Por defecto: impersonate = falso

kernel_nfsd (booleano)

Indicador booleano que permite al kernel de Linux verificar si gssproxy se está ejecutando (a través de /proc/net/rpc/use-gss-proxy).

Por defecto: kernel_nfsd = falso

krb5_principal (cadena)

El principal krb5 que se utilizará preferentemente para este servicio, si la aplicación no solicita uno. Tenga en cuenta que esto no fuerza el uso de este nombre específico; solo establece un valor predeterminado.

Por defecto: krb5_principal =

mechs (cadena)

Actualmente solo se admite krb5.

El parámetro "mechs" es imperativo, cualquier sección sin él será descartada.

Por defecto: mechs =

NAME

gssproxy.conf

configuration file for gssproxy

DESCRIPTION

The configuration file for gssproxy is located at /etc/gssproxy/gssproxy.conf. It is divided into global settings and service definitions.

A configuration file consists of one or more sections. The first section is the global section, which contains global settings. Subsequent sections define specific services. Service sections are identified by a unique name enclosed in square brackets, e.g. [[example.service]].

SECTIONS

[global]
The global section. This section is mandatory and must be the first section in the configuration file.
[service]
Service definitions. This section is optional. Multiple service definitions can be defined.

VARIABLE SUBSTITUTIONS

The following variables can be used in the configuration file:

%U
The username of the user.
%H
The hostname.
%N
The service name.
%K
The Kerberos realm.
%R
The Kerberos realm in lowercase.

OPTIONS

The following options can be specified in the configuration file:

canonicalize (boolean)

If set to true, gssproxy will attempt to canonicalize the requested service principal name. This can help to avoid problems with case sensitivity in service principal names.

Default: canonicalize = true

creds_dir (string)

The directory where gssproxy will store credential caches.

Default: creds_dir = /var/run/gssproxy/usercred

creds_backend (string)

The backend to use for storing credential caches. Supported backends are `dir` (default) and `memory`.

Default: creds_backend = dir

debug (boolean)

Enable debugging output. This option is useful for investigating problems in applications using gssproxy.

Default: debug = false

exrid (string)

If specified, this service will only match when the requested Service Principal Name (SPN) starts with the specified exrid.

Example: exrid = host/

fallback_authentication (boolean)

If set to true, gssproxy will attempt to fall back to authentication using the UID if the primary authentication mechanism fails.

Default: fallback_authentication = true

force_default_realm (boolean)

If set to true, gssproxy will always use the default Kerberos realm, even if the service principal name specifies a different realm.

Default: force_default_realm = false

gcred_dir (string)

The directory where gssproxy will store global credential caches.

Default: gcred_dir = /var/run/gssproxy/servercred

gcred_owner (string)

The user that will own the global credential caches.

Default: gcred_owner = root

include (string)

Include another configuration file. This option can be used to split the configuration into multiple files.

Example: include = /etc/gssproxy/conf.d/*.conf

kadmind_port (integer)

The port number for the Kerberos administration daemon.

Default: kadmind_port = 749

kadmind_timeout (integer)

The timeout in seconds for connections to the Kerberos administration daemon.

Default: kadmind_timeout = 5

kerberos_principal (string)

The Kerberos principal to use for the gssproxy daemon. If not specified, gssproxy will try to determine the principal from the keytab.

Default: kerberos_principal =

keytab (string)

The path to the keytab file to use for the gssproxy daemon.

Default: keytab = /etc/gssproxy/gssproxy.keytab

listen (string)

Specifies the address and port on which gssproxy should listen for incoming connections. This option can be specified multiple times.

Default: listen = /var/run/gssproxy.sock

log_syslog (boolean)

Enable logging to syslog.

Default: log_syslog = true

log_file (string)

Specifies the file path to which gssproxy should log messages.

Default: log_file = /var/log/gssproxy.log

log_level (string)

Specifies the logging level. Possible values are `DEBUG`, `INFO`, `NOTICE`, `WARNING`, `ERROR`, `CRITICAL`, `ALERT`, `EMERGENCY`.

Default: log_level = NOTICE

mech_list (string)

A comma-separated list of GSSAPI mechanisms to enable. If not specified, all available mechanisms will be enabled.

Example: mech_list = gssapi-krb5,gssapi-spnego

min_lifetime (integer)

If the cached credential lifetime is lower than this value (in minutes), gssproxy will treat the cached credential as expired and will attempt to obtain a new credential.

Default: min_lifetime = 15

program (string)

If specified, this service will only match when the program being run is the specified string.

Programs are assumed to be specified as canonical paths (i.e., no relative paths, no symlinks). Additionally, the '|' character is reserved for future use and therefore forbidden.

run_as_user (string)

The name of the user gssproxy will drop privileges to.

This option is only available in the global section.

Default: run_as_user =

selinux_context (string)

This option is deprecated. Use a custom socket or euid instead.

socket (string)

This parameter allows one to create a per-service socket file over which gssproxy client and server components communicate.

When this parameter is not set, gssproxy will use a compiled-in default.

syslog_status (boolean)

Enable per-call debugging output to the syslog. This may be useful for investigating problems in applications using gssproxy.

Default: syslog_status = false

trusted (boolean)

Defines whether this service is considered trusted. Use with caution, this enables impersonation.

Default: trusted = false

worker threads (integer)

Defines the amount of worker threads gssproxy will create at startup.

Default: worker threads =
