GSSPROXY-MECH(8) Mecanismo GSSAPI de GssProxy GSSPROXY-MECH(8)

NOMBRE

gssproxy-mech - plugin de mecanismo GSSAPI de GssProxy

SINOPSIS

proxymech_v1 2.16.840.1.113730.3.8.15.1 /usr/lib64/gssproxy/proxymech.so [opciones]

DESCRIPCIÓN

El módulo proxymech de gssproxy es un plugin intermediario que es cargado por GSSAPI. Se habilita mediante el archivo de configuración /etc/gss/mech.

El plugin intermediario permite interceptar toda la comunicación GSSAPI y redirigirla al demonio gssproxy. Cuando el plugin intermediario está instalado, se deben cumplir otras dos condiciones para activarlo:

a) archivo de configuración del intermediario

El plugin debe ser habilitado manualmente en el archivo /etc/gss/mech.

b) variable de entorno de gssproxy

Con las opciones de compilación predeterminadas, el plugin intermediario no reenviará al demonio gssproxy a menos que se establezca la variable de entorno llamada GSS_USE_PROXY=yes.

Este comportamiento predeterminado puede controlarse en el momento de la compilación y puede configurarse para reenviar siempre a menos que la variable de entorno se establezca en GSS_USE_PROXY=no.

La configuración actual para reenviar siempre es: falsa

Además, el plugin intermediario puede configurarse para comportarse de diferentes maneras cuando es llamado por GSSAPI. Este comportamiento se controla a través de la variable de entorno GSSPROXY_BEHAVIOR. Acepta cuatro valores diferentes:

LOCAL_ONLY

Todos los comandos recibidos con esta configuración harán que se vuelva a entrar inmediatamente en GSSAPI sin ninguna interacción con el demonio gssproxy. Cuando la solicitud no pueda procesarse, simplemente fallará.

LOCAL_FIRST

Todos los comandos recibidos con esta configuración harán que se vuelva a entrar inmediatamente en GSSAPI. Cuando la GSSAPI local no pueda procesar la solicitud, la reenviará al demonio gssproxy.

REMOTE_FIRST

Todos los comandos recibidos con esta configuración se reenviarán primero al demonio gssproxy. Si la solicitud no puede ser manejada allí, la solicitud volverá a entrar en la GSSAPI local.

REMOTE_ONLY

Esta configuración actualmente no está completamente implementada y, por lo tanto, no es compatible.

La configuración predeterminada para GSSPROXY_BEHAVIOR es REMOTE_FIRST.

Finalmente, el intermediario puede necesitar usar un socket especial por servicio para comunicarse con gssproxy. La ruta a este socket se establece a través de la variable de entorno GSSPROXY_SOCKET.

VER TAMBIÉN

gssproxy.conf(5) y gssproxy(8).
