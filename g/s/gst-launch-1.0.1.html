GStreamer(1) Manual de Comandos Generales GStreamer(1)

NOMBRE

gst-launch-1.0 - construye y ejecuta una canalización de GStreamer

SINOPSIS

gst-launch-1.0 [OPCIÓN...] DESCRIPCIÓN-DE-CANALIZACIÓN

DESCRIPCIÓN

gst-launch-1.0 es una herramienta que construye y ejecuta canalizaciones básicas de GStreamer .

En su forma simple, una DESCRIPCIÓN-DE-CANALIZACIÓN es una lista de elementos separados por signos de exclamación (!). Las propiedades pueden añadirse a los elementos, en la forma propiedad=valor. También se puede establecer un "preset" utilizando la sintaxis @preset=<nombre del preset> .

Para una descripción completa de las posibles DESCRIPCIONES-DE-CANALIZACIÓN, consulta la sección descripción de canalización más abajo o consulta la documentación de GStreamer.

Ten en cuenta que gst-launch-1.0 es principalmente una herramienta de depuración para desarrolladores y usuarios. No deberías construir aplicaciones sobre él. Para aplicaciones, escribe un pequeño script en Python o una aplicación en Rust (o usa cualquier otro lenguaje de programación que prefieras) y usa la función gst_parse_launch() de la API de GStreamer como una forma fácil de construir canalizaciones a partir de descripciones de canalización.

OPCIONES

gst-launch-1.0 acepta las siguientes opciones:

--help
Imprime la sinopsis de ayuda y los FLAGS disponibles
-v, --verbose
Muestra información de estado y notificaciones de propiedades
-q, --quiet
No imprime ninguna información de progreso
-m, --messages
Muestra los mensajes publicados en el bus de la canalización
-t, --tags
Muestra las etiquetas (también conocidas como metadatos)
-e, --eos-on-shutdown
Fuerza un evento EOS en las fuentes antes de apagar la canalización. Esto es útil para asegurarse de que los multiplexores creen archivos legibles cuando una canalización de multiplexación es apagada forzosamente mediante Control-C (especialmente en el caso de `mp4mux` y `qtmux`, donde el archivo creado será ilegible si el archivo no ha sido finalizado correctamente).
-f, --no-fault
No instala un manejador de fallos de segmentación
--no-position
No imprime la posición actual de la canalización. Si esta opción no se especifica, la posición se imprimirá cuando la salida estándar sea un TTY. Para habilitar la impresión de la posición cuando la salida estándar no es un TTY, usa la opción "--force-position".
--force-position
Permite imprimir la posición actual de la canalización incluso si la salida estándar no es un TTY. Esta opción no tiene efecto si se especifica la opción "--no-position".

OPCIONES DE GSTREAMER

gst-launch-1.0 también acepta las siguientes opciones que son comunes a todas las aplicaciones de GStreamer:

--gst-version
Imprime la cadena de versión de la biblioteca principal de GStreamer .
--gst-fatal-warnings
Hace que GStreamer se aborte si ocurre un mensaje de advertencia. Esto es equivalente a establecer la variable de entorno G_DEBUG a 'fatal_warnings' (consulta la sección variables de entorno más abajo para más información).
--gst-debug=STRING
Una lista separada por comas de pares nombre_de_categoría:nivel para especificar niveles de depuración para cada categoría. El nivel está en el rango 0-9, donde 0 no mostrará ningún mensaje y 9 mostrará todos los mensajes. El comodín * puede usarse para hacer coincidir nombres de categoría. Ten en cuenta que el orden de las categorías y los niveles es importante; los comodines al final pueden anular los niveles establecidos anteriormente. Los niveles de registro son: 1=ERROR, 2=ADVERTENCIA, 3=FIXME, 4=INFO, 5=DEPURACIÓN, 6=REGISTRO, 7=TRAZA, 9=VOLCADO_DE_MEMORIA. Desde GStreamer 1.2 también se pueden usar los nombres de nivel de depuración, por ejemplo, --gst-debug=*sink:REGISTRO. Una descripción completa de los distintos niveles de depuración se puede encontrar en la documentación de la API de la biblioteca principal de GStreamer, en la sección "Ejecutar aplicaciones de GStreamer".

Usa --gst-debug-help para mostrar los nombres de categoría

Ejemplo: GST_CAT:5,GST_ELEMENT_*:3,oggdemux:5

--gst-debug-level=NIVEL
Establece el umbral para imprimir mensajes de depuración. Un nivel más alto imprimirá más mensajes. El rango útil es 0-9, con 0 como valor predeterminado. El nivel 6 (nivel REGISTRO) mostrará toda la información que normalmente se necesita con fines de depuración. Los niveles más altos solo son únicos en casos muy específicos. Consulta arriba la lista completa de niveles.
--gst-debug-no-color
GStreamer normalmente imprime mensajes de depuración de modo que los mensajes estén codificados por colores cuando se imprimen en una terminal que maneja secuencias de escape ANSI. Usar esta opción hace que GStreamer imprima mensajes sin color. Establecer la variable de entorno GST_DEBUG_NO_COLOR logrará lo mismo.
--gst-debug-color-mode
GStreamer normalmente imprime mensajes de depuración de modo que los mensajes estén codificados por colores cuando se imprimen en una terminal que maneja secuencias de escape ANSI (en *nix), o usa la API de consola W32 para colorear los mensajes impresos en una consola (en W32). Usar esta opción hace que GStreamer imprima mensajes sin color ('off' o 'disable'), imprima mensajes con colores predeterminados ('on' o 'auto'), o imprima mensajes usando secuencias de escape ANSI para colorear ('unix'). Establecer la variable de entorno GST_DEBUG_COLOR_MODE logrará lo mismo.
--gst-debug-disable
Desactiva la depuración.
--gst-debug-help
Imprime una lista de las categorías de depuración disponibles y su nivel de depuración predeterminado.
--gst-plugin-path=RUTA
Añade directorios separados por ':' a la ruta de búsqueda de plugins
--gst-plugin-load=PLUGINS
Precarga los plugins especificados en una lista separada por comas. Otra forma de especificar los plugins a precargar es usar la variable de entorno GST_PLUGIN_PATH

DESCRIPCIÓN DE CANALIZACIÓN

Una canalización consta de elementos y enlaces. Los elementos pueden colocarse en contenedores de diferentes tipos. Los elementos, los enlaces y los contenedores pueden especificarse en una descripción de canalización en cualquier orden.

Elementos

TIPO-DE-ELEMENTO [PROPIEDAD1 ...]

Crea un elemento del tipo TIPO-DE-ELEMENTO y establece las PROPIEDADES.

Propiedades

PROPIEDAD=VALOR ...

Establece la propiedad en el valor especificado. Puedes usar gst-inspect-1.0(1) para averiguar las propiedades y los valores permitidos de los diferentes elementos.
Las propiedades de enumeración pueden establecerse por nombre, apodo o valor.

Presets

@preset=<nombre del preset> ...

Establece el preset en el elemento. Puedes usar gst-inspect-1.0(1) para averiguar qué presets están disponibles para un elemento específico.

Contenedores

[TIPO-DE-CONTENEDOR.] ( [PROPIEDAD1 ...] DESCRIPCIÓN-DE-CANALIZACIÓN )

Especifica que se crea un contenedor del tipo TIPO-DE-CONTENEDOR y se establecen las propiedades dadas. Cada elemento entre los corchetes se coloca en el contenedor. Ten en cuenta el punto que debe usarse después del TIPO-DE-CONTENEDOR. Casi nunca necesitarás esta funcionalidad; solo es realmente útil para aplicaciones que usan la API gst_launch_parse() con 'bin' como tipo de contenedor. De esa manera es posible construir canalizaciones parciales en lugar de una canalización de nivel superior completa.

Enlaces

[[ELEMENTO-ORIGEN].[PAD1,...]] ! [[ELEMENTO-DESTINO].[PAD1,...]] [[ELEMENTO-ORIGEN].[PAD1,...]] ! CAPS ! [[ELEMENTO-DESTINO].[PAD1,...]] [[ELEMENTO-ORIGEN].[PAD1,...]] : [[ELEMENTO-DESTINO].[PAD1,...]] [[ELEMENTO-ORIGEN].[PAD1,...]] : CAPS : [[ELEMENTO-DESTINO].[PAD1,...]]

Enlaza el elemento con nombre ELEMENTO-ORIGEN al elemento con nombre ELEMENTO-DESTINO, usando las capacidades especificadas en CAPS como filtro. Los nombres pueden establecerse en los elementos

PROPIEDADES DEL ELEMENTO

Los elementos pueden exponer propiedades que pueden ser consultadas con gst-inspect-1.0(1) y establecidas con gst-launch-1.0(1).

Hay dos tipos de propiedades:

Solo lectura
Las propiedades de solo lectura no se pueden modificar en tiempo de ejecución. Se utilizan principalmente para obtener información sobre el elemento.
Escribible
Las propiedades escribibles se pueden modificar en tiempo de ejecución. Por defecto, solo se pueden establecer al crear el elemento. Si se desea modificar una propiedad de un elemento que ya existe, el elemento debe ser conectado a un GstElementFactory(3) en lugar de ser creado directamente con su nombre.

Para ver una lista de las propiedades de un elemento, puede usar gst-inspect-1.0(1).

Vinculación de elementos

Los elementos se vinculan mediante el operador !. Esto es esencialmente una abreviatura de llamar a gst_element_link(). El orden en que se vinculan los elementos es importante, ya que define la dirección del flujo de datos. El operador ! conecta el pad de salida de un elemento al pad de entrada del siguiente elemento. Si el pad no se especifica, se intenta enlazar todos los posibles para el elemento dado.

Las conexiones también se pueden filtrar utilizando la sintaxis de caps. Esto permite especificar los tipos de datos que se espera que pasen por la conexión.

Por ejemplo:

gst-launch-1.0 videotestsrc ! video/x-raw,format=I420 ! xvimagesink

En este ejemplo, videotestsrc se vincula a xvimagesink. La conexión se filtra para que solo acepte datos de video en formato I420.

Los nombres de los pads también se pueden especificar utilizando la sintaxis padname:element o element:padname. Si el nombre del pad se omite, se utiliza el elemento que se especificó directamente antes o después del enlace. Esto funciona entre bins. Si se proporciona un nombre de pad, el enlace se realiza con estos pads. Si no se proporcionan nombres de pads, se prueban todas las posibilidades y se utiliza un pad coincidente. Si se proporcionan múltiples nombres de pads, ambos lados deben tener el mismo número de pads especificados y se realizan múltiples enlaces en el orden dado.

Por lo tanto, el enlace más simple es un simple signo de exclamación, que vincula el elemento de su izquierda con el elemento de su derecha.

La vinculación utilizando el operador : intenta vincular todos los pads posibles entre los elementos.

Caps

MEDIATYPE [, PROPERTY[, PROPERTY ...]]] [; CAPS[; CAPS ...]]

Crea una capacidad con el tipo de medio dado y, opcionalmente, con las propiedades dadas. El tipo de medio puede ser escapado usando " o '. Si desea encadenar caps, puede agregar más caps en el mismo formato después.

Propiedades

NAME=[(TYPE)]VALUE
en listas y rangos: [(TYPE)]VALUE

Establece la propiedad solicitada en las capacidades. El nombre es un valor alfanumérico y el tipo puede tener los siguientes valores sin distinguir mayúsculas y minúsculas:
- i o int para valores o rangos enteros
- f o float para valores o rangos flotantes
- b, bool o boolean para valores booleanos
- s, str o string para cadenas
- fraction para fracciones (framerate, pixel-aspect-ratio)
- l o list para listas
Si no se proporcionó ningún tipo, se intenta el siguiente orden: entero, flotante, booleano, cadena.
Los valores enteros deben ser analizables por strtol(), los flotantes por strtod(). Los valores FOURCC pueden ser enteros o cadenas. Los valores booleanos son (sin distinguir mayúsculas y minúsculas) yes, no, true o false y pueden, al igual que las cadenas, ser escapados con " o '.
Los rangos tienen este formato: [ VALUE, VALUE ]
Las listas utilizan este formato: { VALUE [, VALUE ...] }

EJEMPLOS DE PIPELINES

Los siguientes ejemplos asumen que tiene los plugins correctos disponibles. En general, "pulsesink" puede ser sustituido por otro plugin de salida de audio como "alsasink", "osxaudiosink" o "wasapisink".
Del mismo modo, "xvimagesink" puede ser sustituido por "d3dvideosink", "ximagesink", "glimagesink", o "osxvideosink".
Tenga en cuenta, sin embargo, que los diferentes sinks pueden aceptar diferentes formatos e incluso el mismo sink puede aceptar diferentes formatos en diferentes máquinas, por lo que es posible que necesite agregar elementos convertidores como audioconvert y audioresample (para audio) o videoconvert scale (para video) delante del sink para que las cosas funcionen.

Reproducción de audio

Nota: Para la reproducción de audio/video es mejor usar los elementos playbin3 o uridecodebin3, estos son solo ejemplos de pipelines.
Reproduce el archivo de música mp3 "music.mp3" usando un plugin basado en libmpg123 y la salida a un dispositivo Pulseaudio

gst-launch-1.0 filesrc location=music.mp3 ! mpegaudioparse ! mpg123audiodec ! audioconvert ! audioresample ! pulsesink

Reproduce un archivo en formato Ogg Vorbis

gst-launch-1.0 filesrc location=music.ogg ! oggdemux ! vorbisdec ! audioconvert ! audioresample ! pulsesink

Reproduce un archivo mp3 o un stream http usando GIO

gst-launch-1.0 giosrc location=music.mp3 ! mpegaudioparse ! mpg123audiodec ! audioconvert ! pulsesink

gst-launch-1.0 giosrc location=http://domain.com/music.mp3 ! mpegaudioparse ! mpg123audiodec ! audioconvert ! audioresample ! pulsesink

Usa GIO para reproducir un archivo mp3 ubicado en un servidor SMB

gst-launch-1.0 giosrc location=smb://computer/music.mp3 ! mpegaudioparse ! mpg123audiodec ! audioconvert ! audioresample ! pulsesink

Conversión de formato

Convierte un archivo de música mp3 a un archivo Ogg Vorbis

gst-launch-1.0 filesrc location=music.mp3 ! mpegaudioparse ! mpg123audiodec ! audioconvert ! vorbisenc ! oggmux ! filesink location=music.ogg

Convierte al formato FLAC

gst-launch-1.0 filesrc location=music.mp3 ! mpegaudioparse ! mpg123audiodec ! audioconvert ! flacenc ! filesink location=test.flac

Otros

Reproduce un archivo .WAV que contiene datos de audio crudos (PCM).

gst-launch-1.0 filesrc location=music.wav ! wavparse ! audioconvert ! audioresample ! pulsesink

Convierte un archivo .WAV que contiene datos de audio crudos en un archivo Ogg Vorbis o mp3

gst-launch-1.0 filesrc location=music.wav ! wavparse ! audioconvert ! vorbisenc ! oggmux ! filesink location=music.ogg

gst-launch-1.0 filesrc location=music.wav ! wavparse ! audioconvert ! lamemp3enc ! xingmux ! id3v2mux ! filesink location=music.mp3

Extrae todas las pistas del disco compacto y las convierte en un único archivo mp3

gst-launch-1.0 cdparanoiasrc mode=continuous ! audioconvert ! lamemp3enc ! mpegaudioparse ! xingmux ! id3v2mux ! filesink location=cd.mp3

Extrae la pista 5 del CD y la convierte en un único archivo mp3

gst-launch-1.0 cdparanoiasrc track=5 ! audioconvert ! lamemp3enc ! mpegaudioparse ! xingmux ! id3v2mux ! filesink location=track5.mp3

Usando gst-inspect-1.0(1), es posible descubrir configuraciones como las anteriores para cdparanoiasrc que le indicarán que extraiga todo el CD o solo pistas del mismo. Alternativamente, puede usar una URI y gst-launch-1.0 encontrará un elemento (como cdparanoia) que admita ese protocolo por usted, por ejemplo:
gst-launch-1.0 cdda://5 ! lamemp3enc vbr=new vbr-quality=6 ! filesink location=track5.mp3

Graba sonido desde su entrada de audio y lo codifica en un archivo ogg

gst-launch-1.0 pulsesrc ! audioconvert ! vorbisenc ! oggmux ! filesink location=input.ogg

Video

Nota: Para la reproducción de audio/video es mejor usar los elementos playbin3 o uridecodebin3, estos son solo ejemplos de pipelines.
Muestra solo la porción de video de un archivo de video MPEG-2 PS, enviando la salida a una ventana de visualización X

gst-launch-1.0 filesrc location=JB_FF9_TheGravityOfLove.mpg ! mpegdemux ! mpegvideoparse ! mpeg2dec ! videoconvert ! xvimagesink

Muestra la porción de video de un archivo .vob (usado en DVDs), enviando la salida a una ventana SDL

gst-launch-1.0 filesrc location=/flflfj.vob ! dvddemux ! mpegvideoparse ! mpeg2dec ! videoconvert ! sdlvideosink

Reproduce tanto la porción de video como la de audio de una película MPEG

gst-launch-1.0 filesrc location=movie.mpg ! dvddemux name=demuxer demuxer. ! queue ! mpegvideoparse ! mpeg2dec ! videoconvert ! sdlvideosink demuxer. ! queue ! mpegaudioparse ! mpg123audiodec ! audioconvert ! audioresample ! pulsesink

Reproduce una película AVI con un stream de subtítulos de texto externo
Este ejemplo también muestra cómo referirse a pads específicos por nombre si un elemento (aquí: textoverlay) tiene múltiples pads de entrada o salida.

gst-launch-1.0 textoverlay name=overlay ! videoconvert ! videoscale ! autovideosink filesrc location=movie.avi ! decodebin3 ! videoconvert ! overlay.video_sink filesrc location=movie.srt ! subparse ! overlay.text_sink

Reproduce una película AVI con un stream de subtítulos de texto externo usando playbin3

gst-launch-1.0 playbin3 uri=file:///path/to/movie.avi suburi=file:///path/to/movie.srt

Streaming de red

Transmite video usando RTP y elementos de red.

Este comando se ejecutaría en el transmisor

gst-launch-1.0 v4l2src ! queue ! videoconvert ! x264enc tune=zerolatency key-int-max=15 ! video/x-h264,profile=main !rtph264pay pt=96 config-interval=-1 ! udpsink host=192.168.1.1 port=5000

Use este comando en el receptor

gst-launch-1.0 udpsrc port=5000 ! application/x-rtp, clock-rate=90000,payload=96 ! rtpjitterbuffer ! rtph264depay ! h264parse ! avdec_h264 ! videoconvert ! xvimagesink

Diagnóstico

Genera un stream nulo y lo ignora (e imprime detalles).

gst-launch-1.0 -v fakesrc num-buffers=16 ! fakesink silent=false

Genera un tono de seno puro para probar la salida de audio

gst-launch-1.0 audiotestsrc ! audioconvert ! audioresample ! pulsesink

Genera un patrón de prueba familiar para probar la salida de video

gst-launch-1.0 videotestsrc ! xvimagesink

gst-launch-1.0 videotestsrc ! ximagesink

Vinculación automática

Puede usar el elemento decodebin para seleccionar automáticamente los elementos correctos para obtener un pipeline funcional.

Reproduce cualquier formato de audio compatible

gst-launch-1.0 filesrc location=musicfile ! decodebin3 ! audioconvert ! audioresample ! pulsesink

Reproduce cualquier formato de video compatible con salida de video y audio. Los hilos se utilizan automáticamente. Para facilitar aún más esto, puede usar el elemento playbin:

gst-launch-1.0 filesrc location=videofile ! decodebin3 name=decoder decoder. ! queue ! audioconvert ! audioresample ! pulsesink decoder. ! videoconvert ! xvimagesink

gst-launch-1.0 playbin3 uri=file:///home/joe/foo.avi

gst-launch-1.0 playbin3 uri=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm

Conexiones filtradas

Estos ejemplos le muestran cómo usar caps filtradas.

Muestra una imagen de prueba y utiliza el formato de video YUY2 o YV12 para esto.

gst-launch-1.0 videotestsrc ! 'video/x-raw,format=YUY2;video/x-raw,format=YV12' ! xvimagesink

gst-launch-1.0 v4l2src ! image/jpeg ! queue ! decodebin3 ! videoconvert ! autovideosink

Graba audio y lo escribe en un archivo .wav. Fuerza el uso de muestras con signo de 16 a 32 bits y una frecuencia de muestreo entre 32 kHz y 64 kHz.

gst-launch-1.0 pulsesrc ! 'audio/x-raw,rate=[32000,64000],format={S16LE,S24LE,S32LE}' ! wavenc ! filesink location=recording.wav

VARIABLES DE ENTORNO

GST_DEBUG
Lista separada por comas de categorías y niveles de depuración (por ejemplo, GST_DEBUG=totem:4,typefind:5). Se permite '*' como comodín para
parte de los nombres de categorías de depuración (por ejemplo, GST_DEBUG=*sink:6,*audio*:6). Desde la versión 1.2.0, también es posible especificar el nivel de registro por nombre (1=ERROR, 2=WARN, 3=FIXME, 4=INFO, 5=DEBUG, 6=LOG, 7=TRACE, 9=MEMDUMP) (por ejemplo, GST_DEBUG=*audio*:LOG)
GST_DEBUG_NO_COLOR
Cuando esta variable de entorno está definida, la salida de depuración con colores se desactiva.
GST_DEBUG_DUMP_DOT_DIR
Si se establece en una ruta del sistema de archivos, se guardarán allí los archivos 'dot' de los gráficos del pipeline. Estos pueden convertirse posteriormente en una imagen utilizando la utilidad 'dot' del conjunto de herramientas graphviz, de la siguiente manera: dot foo.dot -Tsvg -o foo.svg (png o jpg también son posibles como formatos de salida). También existe una utilidad llamada 'xdot' que permite ver el archivo .dot directamente sin necesidad de convertirlo primero.
Cuando el pipeline cambia de estado a través de NULL a PLAYING y de vuelta a NULL, se genera un archivo dot en cada cambio de estado. Para escribir una instantánea del estado del pipeline, envíe una señal SIGHUP al proceso o utilice el tracer pipeline_snapshot de los plugins de GStreamer para Rust.
GST_REGISTRY
Ruta del archivo del registro de plugins. El valor predeterminado es ~/.cache/gstreamer-1.0/registry-CPU.bin, donde CPU es el tipo de máquina/cpu para la que se compiló GStreamer, por ejemplo, 'x86_64', etc. (consulte la salida de "uname -i" y "uname -m" para más detalles).
GST_REGISTRY_UPDATE
Establezca en "no" para forzar a GStreamer a asumir que no han cambiado, añadido ni eliminado plugins. Esto hará que GStreamer omita la comprobación inicial sobre si se requiere o no una reconstrucción de la caché del registro. Esto puede ser útil en entornos incrustados donde los plugins instalados nunca cambian. No utilice esta opción en ninguna otra configuración.
GST_PLUGIN_PATH
Especifica una lista de directorios en los que buscar plugins adicionales. Estos tienen prioridad sobre los plugins del sistema.
GST_PLUGIN_SYSTEM_PATH
Especifica una lista de plugins que se cargan siempre de forma predeterminada. Si no se establece, el valor predeterminado es la ruta instalada en el sistema y los plugins instalados en el directorio de inicio del usuario.
GST_DEBUG_FILE
Establezca esta variable en una ruta de archivo para redirigir todos los mensajes de depuración de GStreamer a este archivo. Si se deja sin definir, los mensajes de depuración se emitirán por la salida de error estándar.
ORC_CODE
Variable de entorno útil de Orc. Establezca ORC_CODE=debug para permitir que depuradores como gdb creen trazas de pila útiles a partir de código generado por Orc. Establezca ORC_CODE=backup o ORC_CODE=emulate si sospecha que el generador de código SIMD de Orc está produciendo código incorrecto. (Bastantes plugins importantes de GStreamer, como videotestsrc, audioconvert o audioresample, utilizan Orc).
G_DEBUG
Variable de entorno útil de GLib. Establezca G_DEBUG=fatal_warnings para que los programas de GStreamer se aborten cuando ocurra una advertencia crítica como una falla de aserción. Esto es útil si desea averiguar qué parte del código provocó esa advertencia y bajo qué circunstancias. Simplemente establezca G_DEBUG como se mencionó anteriormente y ejecute el programa en gdb (o deje que genere un volcado de memoria). Luego obtenga una traza de pila de la manera habitual.

ARCHIVOS

~/.cache/gstreamer-1.0/registry-*.bin
La caché de plugins; puede eliminarse en cualquier momento y se volverá a crear automáticamente cuando aún no exista o cuando cambien los plugins. Se basa en XDG_CACHE_DIR, por lo que puede estar en una ubicación diferente a la sugerida.
