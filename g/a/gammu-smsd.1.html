NOMBRE

gammu-smsd - Demonio de SMS para Gammu

SINOPSIS

gammu-smsd [OPCIÓN]...

DESCRIPCIÓN

Esta página de manual documenta brevemente el comando gammu-smsd.

gammu-smsd es un programa que escanea periódicamente el módem GSM en busca de mensajes recibidos, los almacena en el almacenamiento definido y también envía mensajes encolados en este almacenamiento.

El demonio puede recargar el archivo de configuración después de enviar la señal de colgar (SIGHUP) y termina correctamente por sí mismo en SIGINT y SIGTERM.

El programa acepta las siguientes opciones (tenga en cuenta que las opciones largas pueden no ser aceptadas en algunas plataformas):

-h, --help
Muestra la ayuda.
-v, --version
Muestra la información de la versión y las características compiladas.
-c, --config=archivo
Archivo de configuración a utilizar, el valor predeterminado es /etc/gammu-smsdrc, en Windows no hay un valor predeterminado y la ruta del archivo de configuración debe especificarse siempre.

Si ejecuta SMSD como un demonio del sistema (o servicio), se recomienda usar la ruta absoluta al archivo de configuración, ya que el directorio de inicio puede ser diferente al que espera.

Consulte gammu-smsdrc para la documentación del archivo de configuración.

-p, --pid=archivo
Archivo de bloqueo para almacenar el pid, vacío para no bloquear. No compatible con Windows.
-U, --user=usuario
Reduce los privilegios del demonio al usuario elegido después de iniciar.
-G, --group=grupo
Reduce los privilegios del demonio al grupo elegido después de iniciar.
-d, --daemon
Convierte el programa en demonio al inicio. No compatible con Windows.
-i, --install-service
Instala SMSD como un servicio de Windows.
-u, --uninstall-service
Desinstala SMSD como un servicio de Windows.
-s, --start-service
Inicia el servicio SMSD de Windows.
-k, --stop-service
Detiene el servicio SMSD de Windows.
-f, --max-failures=cantidad
Termina después de un número definido de fallos. Use 0 para no terminar (este es el valor predeterminado).
-X, --suicide=segundos
Se mata a sí mismo después de un número de segundos.
-S, --run-service
Ejecuta el programa como servicio SMSD de Windows. Esto no debe usarse manualmente, sino que solo el administrador de servicios de Windows debe usar este comando.
-n, --service-name=nombre
Define el nombre de un servicio de Windows. Cada servicio requiere un nombre único, por lo que si desea ejecutar varias instancias de SMSD, debe nombrar cada servicio de manera diferente. El valor predeterminado es "GammuSMSD".
-l, --use-log
Usa el registro tal como está configurado en el archivo de configuración (predeterminado).
-L, --no-use-log
No usa el registro tal como está configurado en el archivo de configuración.
-e, --install-event-log
Instala la descripción del registro de eventos de Windows en el registro del sistema.

Nuevo en la versión 1.31.90.

-E, --uninstall-event-log
Desinstala la descripción del registro de eventos de Windows del registro del sistema.

Nuevo en la versión 1.31.90.

SEÑALES

SMSD puede controlarse usando las siguientes señales POSIX (si su plataforma lo soporta):

SIGHUP
Recarga la configuración y se reconecta al teléfono.
SIGINT, SIGTERM
Apaga el demonio de forma ordenada.
SIGALRM
Se usa internamente para gammu-smsd -X
SIGUSR1
Suspende la operación de SMSD, cerrando la conexión con el teléfono y la base de datos.
SIGUSR2
Reanuda la operación de SMSD (después de la suspensión anterior).

Cambiado en la versión 1.22.91: Se añadió soporte para SIGHUP.

Cambiado en la versión 1.22.95: Se añadió soporte para SIGALRM.

Cambiado en la versión 1.31.90: Se añadió soporte para SIGUSR1 y SIGUSR2.

EJEMPLOS

Ejemplos de Linux/Unix

Iniciar SMSD como demonio en Linux:

gammu-smsd --config /etc/gammu-smsdrc --pid /var/run/gammu-smsd.pid --daemon

Iniciar SMSD como demonio en Linux con privilegios reducidos:

gammu-smsd --config /etc/gammu-smsdrc --pid /var/run/gammu-smsd.pid --daemon --user gammu --group gammu

SMSD como un demonio de todo el sistema

Para usar SMSD como demonio, es posible que desee usar el script de inicio que se incluye con Gammu en el directorio contrib/init. No se instala de forma predeterminada, ya sea que lo instale manualmente o consulte el archivo INSTALL para instrucciones.

En Windows 7 es posible que necesite desactivar el UAC (control de cuentas de usuario) antes de poder instalar el servicio SMSD.

Ejemplos de servicios de Windows

Instalar el servicio SMSD de Windows de Gammu:

gammu-smsd.exe -c c:\Gammu\smsdrc -i

Instalar dos instancias del servicio SMSD de Windows:

gammu-smsd.exe -c c:\Gammu\smsdrc-1 -n Gammu-first-phone -i
gammu-smsd.exe -c c:\Gammu\smsdrc-2 -n Gammu-second-phone -i

Para desinstalar un servicio de Windows:

gammu-smsd.exe -u

Solución de problemas del servicio de Windows

Si Gammu falla al iniciar como servicio de Windows (normalmente obtendrá "Error 1053: El servicio no respondió a la solicitud de inicio o control a tiempo"), primero revise sus registros de SMSD. Si no contienen ninguna pista útil, intente iniciar SMSD manualmente con exactamente los mismos parámetros con los que instaló el servicio (sin -i).

Por ejemplo, la línea de comandos puede verse así:

gammu-smsd.exe -c smsdrc

Ahora debería poder obtener errores de SMSD incluso si falla al iniciar como servicio.

Invocando Gammu y suspendiendo SMSD

ComoNo puede ejecutar Gammu y Gammu SMSD al mismo tiempo en un solo dispositivo; puede sortear esta limitación suspendiendo SMSD temporalmente usando SIGUSR1 y SIGUSR2 señales (véase también Señales):

SMSD_PID=`pidof gammu-smsd`
if [ -z "$SMSD_PID" ] ; then
    echo "Failed to figure out SMSD PID!"
else
    kill -SIGUSR1 $SMSD_PID
    gammu identify
    kill -SIGUSR2 $SMSD_PID
fi

O incluso crear un gammu-safe script:

#!/bin/bash
SMSD_PID=`pidof gammu-smsd`
if [ -z "$SMSD_PID" ] ; then
  gammu $@
else
  tty=$(lsof |grep -E "gammu-sms\s+$SMSD_PID\s+.*/dev/tty*"|awk {'print $NF'})
  kill -SIGUSR1 $SMSD_PID
  while test "$(fuser $ttyfuser $tty 2> /dev/null|xargs)" = $SMSD_PID
  do
    sleep 1
  done
  sleep 1
  gammu $@
  kill -SIGUSR2 $SMSD_PID
  while test "$(fuser $ttyfuser $tty 2> /dev/null|xargs)" != $SMSD_PID
  do
    sleep 1
  done
  sleep 1
fi

LIMITACIONES CONOCIDAS

No puede usar el mismo teléfono por más de un programa al mismo tiempo. Sin embargo, en caso de que no haya habilitado el bloqueo en la sección [gammu] , podría ser posible iniciar la comunicación con el teléfono desde más de un programa. En este caso, es probable que ninguno de los programas funcione, véase Invocar Gammu y suspender SMSD para una solución alternativa.

No hay forma de detectar que un mensaje SMS es la respuesta a otro observando los encabezados del mensaje. La única forma de lograr esto es agregar algún token al mensaje y dejar que el usuario lo incluya en el mensaje al responder.
