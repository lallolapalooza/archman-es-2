GAMMU-SMSD-FILES(7) Gammu GAMMU-SMSD-FILES(7)

NOMBRE

gammu-smsd-files - backend de gammu-smsd(1) que usa el sistema de archivos como almacenamiento de mensajes

DESCRIPCIÓN

El backend FILES almacena todos los datos en el sistema de archivos en carpetas definidas por la configuración (ver gammu-smsdrc para la descripción de las opciones de configuración).

RECEPCIÓN DE MENSAJES

Los mensajes recibidos se almacenan en una carpeta definida por la configuración. El nombre del archivo será IN<fecha>_<hora>_<serie>_<remitente>_<secuencia>.<ext>, por ejemplo IN20021130_021531_00_+45409000931640979_00.txt.

Explicación de los campos:

<fecha>
fecha en formato YYYYMMDD
<hora>
hora en formato HHMMSS
<remitente>
número del remitente
<serie>
orden de un mensaje (en caso de que se recibieran varios mensajes a la vez), en formato NN
<secuencia>
parte del mensaje para mensajes multipartes, en formato NN
<ext>
txt para mensaje de texto, los mensajes de 8 bits se almacenan con la extensión bin, smsbackup para gammu-smsbackup

El contenido del archivo es el contenido del mensaje y el formato está definido por la directiva de configuración InboxFormat (ver gammu-smsdrc).

TRANSMISIÓN DE MENSAJES

Los mensajes transmitidos se leen de una carpeta definida por la configuración. El nombre del archivo debe tener uno de los siguientes formatos:

  • OUT<destinatario>.<ext>
  • OUT<prioridad>_<destinatario>_<serie>.<ext>
  • OUT<prioridad><fecha>_<hora>_<serie>_<destinatario>_<nota>.<ext>

Explicación de los campos:

<destinatario>
número del destinatario al que enviar el mensaje
<prioridad>
un carácter alfabético (A-Z) A = mayor prioridad
<ext>
txt para SMS de texto normal, smsbackup para gammu-smsbackup
<nota>
cualquier texto arbitrario que se ignora

Para mensajes de texto, puede añadir opcionalmente banderas a la extensión:

d
se solicita informe de entrega
f
SMS flash
b
marcador WAP como nombre,URL

Otros campos son iguales que para los mensajes recibidos.

Por ejemplo, OUTG20040620_193810_123_+4512345678_xpq.txtdf es un SMS de texto flash que solicita informes de entrega.

Los SMS se transmitirán secuencialmente basándose en el nombre del archivo. El contenido del archivo es el SMS a transmitir (en Unicode o conjunto de caracteres estándar).

El contenido del archivo es el SMS a transmitir (en Unicode o conjunto de caracteres estándar), para marcadores WAP se divide en Nombre,URL, para mensajes de texto se utiliza todo el contenido del archivo.

Tenga en cuenta que si el archivo no está en Unicode, la codificación se detecta basándose en las locales, que no tienen por qué estar configuradas si SMSD se ejecuta desde un script de init. Si este es su caso, por favor, añada la definición de locales al script de init.
