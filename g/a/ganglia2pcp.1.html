GANGLIA2PCP(1) Manual de comandos generales GANGLIA2PCP(1)

NOMBRE

ganglia2pcp - importa datos de ganglia y crea un archivo PCP

SINOPSIS

ganglia2pcp [-D debug] [-d dir_salida] [-e fin] [-f archivo_salida] [-h nombre_host] [-s inicio] [-V version] [-Z zona_horaria] dir_entrada

DESCRIPCIÓN

ganglia2pcp está destinado a leer un conjunto de archivos ganglia almacenados en formato rrd y traducirlos a un archivo Performance Co-Pilot (PCP) con el nombre base archivo_salida.

La intención de este conversor es tomar todos los archivos rrd encontrados en dir_entrada y generar un único archivo de archivo pcp. El mapeo de métricas ganglia a métricas pcp se define internamente.

El archivo PCP resultante puede ser utilizado con todas las herramientas cliente de PCP para graficar subconjuntos de los datos usando pmchart(1), realizar reducción de datos e informes, filtrar con el motor de inferencia de PCP pmie(1), etc.

Se creará una serie de archivos físicos con el prefijo archivo_salida. Estos son archivo_salida.0 (los datos de rendimiento), archivo_salida.meta (los metadatos que describen los datos de rendimiento) y archivo_salida.index (un índice temporal para mejorar la eficiencia de las operaciones de reproducción del archivo). Si alguno de estos archivos ya existe, entonces sar2pcp **no** los sobrescribirá y saldrá con un mensaje de error de la forma

__pmLogNewFile: ``blah.0'' ya existe, no se sobrescribirá

ganglia2pcp es un script de Perl que utiliza el wrapper Perl PCP::LogImport sobre la biblioteca libpcp_import de PCP, y como tal podría usarse como ejemplo para desarrollar nuevas herramientas para importar otros tipos de datos de rendimiento y crear archivos PCP. Se utiliza el wrapper Perl RRDs para analizar los archivos de formato rrd sin procesar.

OPCIONES

Las opciones disponibles en la línea de comandos son:

-d dir_salida
El argumento dir_salida especifica una salida para escribir. El valor predeterminado es el directorio actual.
-e fin
El argumento fin especifica una hora de fin en un formato comprendido por str2time. La hora de inicio predeterminada es la hora actual.
-f archivo_salida
El argumento archivo_salida especifica un nombre de archivo de salida. El nombre predeterminado está en el formato estándar de pmlogger basado en la hora de inicio, por ejemplo, 20150201.00.10.
-h nombre_host
El argumento nombre_host especifica un nombre de host para escribir en el archivo. El valor predeterminado se toma del nombre del directorio en el que residen los archivos rrd.
-s inicio
El argumento inicio especifica una hora de inicio en un formato comprendido por str2time. La hora de inicio predeterminada es 24 horas antes de la hora actual.
-V version
La opción -V especifica la versión para el archivo PCP de salida. Por defecto se utiliza la versión de archivo $PCP_ARCHIVE_VERSION (establecida en 3 en las versiones actuales de PCP), y los únicos valores admitidos actualmente para version son 2 o 3.
-Z zona_horaria
El argumento zona_horaria establece la zona horaria de origen en el archivo PCP (el valor predeterminado es usar la zona horaria local). La zona horaria debe tener el formato +HHMM (para horas y minutos al Este de UTC) o -HHMM (para horas y minutos al Oeste de UTC) o UTC. Tenga en cuenta en particular que **ni** el formato zoneinfo (también conocido como Olson), por ejemplo, Europe/Paris, **ni** el formato Posix TZ, por ejemplo, EST+5, están permitidos. Ejemplo: zona_horaria=``+1100''.

ENTORNO PCP

Las variables de entorno con el prefijo PCP_ se utilizan para parametrizar los nombres de archivos y directorios utilizados por PCP. En cada instalación, el archivo /etc/pcp.conf contiene los valores locales para estas variables. La variable $PCP_CONF puede usarse para especificar un archivo de configuración alternativo, como se describe en pcp.conf(5).

OPCIONES DE DEPURACIÓN

La opción -D o --debug habilita la salida de diagnósticos adicionales en stderr para ayudar a diagnosticar problemas, aunque la información a veces es críptica y está destinada principalmente a proporcionar orientación a los desarrolladores en lugar de a los usuarios finales. debug es una lista separada por comas de opciones de depuración; use pmdbg(1) con la opción -l para obtener una lista de las opciones de depuración disponibles y su significado.

Las opciones de depuración específicas para ganglia2pcp son las siguientes:

Opción Descripción
appl0 configuración y descubrimiento de métricas
appl1 generación de valores de métricas
