NOMBRE

gamemoded - demonio que optimiza el rendimiento del sistema bajo demanda

SINOPSIS

gamemoded [OPCIONES...]

DESCRIPCIÓN

GameMode es un demonio/biblioteca para Linux que permite a los juegos solicitar que se apliquen temporalmente un conjunto de optimizaciones al sistema operativo anfitrión.

El diseño tiene una abstracción clara entre el demonio anfitrión y la biblioteca (gamemoded y libgamemode), y los cargadores de clientes (libgamemodeauto y gamemode_client.h) que permite un uso seguro sin preocuparse de si el demonio está instalado o en ejecución. Este diseño también significa que, aunque la biblioteca anfitriona actualmente depende de systemd para intercambiar mensajes con el demonio, es totalmente posible implementar otros mecanismos internos que sigan funcionando con los mismos clientes.

GameMode fue diseñado principalmente como una solución temporal a problemas con los gobernadores de ahorro de energía o "ondemand" de las CPU de Intel y AMD, pero está destinado a expandirse más allá de los estados del gobernador de la CPU, ya que hay una gran cantidad de tareas de automatización que uno podría querer aplicar.

OPCIONES

-r[PID], --request=[PID]
Activa o desactiva el modo juego para el proceso. Si no se proporciona un PID, solicita el modo juego y se pausa
-s[PID], --status=[PID]
Consulta el estado del modo juego para el proceso. Si no se proporciona un PID, consulta el estado globalmente
-d, --daemonize
Ejecuta el demonio como un proceso separado (lo convierte en demonio)
-l, --log-to-syslog
Registra en syslog
-h, --help
Imprime el texto de ayuda
-t, --test
Ejecuta pruebas de diagnóstico en la instalación actual
-v, --version
Imprime la versión

USO

libgamemodeauto.so.0 puede ser precargado en cualquier programa para solicitar a gamemoded que comience o termine el modo. Consulte gamemoderun(1) para más detalles.

El archivo de cabecera gamemode_client.h puede ser utilizado por los desarrolladores para integrar las solicitudes en un programa:

#include "gamemode_client.h"
    if( gamemode_request_start() < 0 ) {
        fprintf( stderr, "gamemode request failed: %s\n", gamemode_error_string() )
    }
    /* ejecutar el proceso */
    /* No es necesario, gamemoded puede limpiar después de que el juego salga */
    gamemode_request_end();

Alternativamente, los desarrolladores pueden definir GAMEMODE_AUTO para imitar el comportamiento de libgamemodeauto.so.0:

#define GAMEMODE_AUTO
#include "gamemode_client.h"

O bien, distribuir libgamemodeauto.so.0 y enlazar con -lgamemodeauto o inyectarlo como se muestra arriba con LD_PRELOAD.

CONFIGURACIÓN

gamemoded cargará y fusionará los archivos de configuración gamemode.ini de estos directorios en el siguiente orden:

/usr/share/gamemode/
/etc/
$XDG_CONFIG_HOME o $HOME/.config/
$PWD

El comportamiento del archivo de configuración puede explicarse presentando un ejemplo comentado:

[general]
; El hilo reaper comprobará cada 5 segundos los clientes que han salido, los cambios en el archivo de configuración y el equilibrio de energía de la CPU/iGPU
reaper_freq=5
; El gobernador deseado se utiliza al entrar en GameMode en lugar de "performance"
desiredgov=performance
; El gobernador predeterminado se utiliza al salir de GameMode en lugar de restaurar el valor original
;defaultgov=powersave
; El gobernador deseado de la iGPU se utiliza cuando la GPU integrada está bajo una carga pesada
igpu_desiredgov=powersave
; Umbral a utilizar para decidir cuándo la GPU integrada está bajo una carga pesada.
; Esta es una relación de Watios de la iGPU / Watios de la CPU que se utiliza para determinar cuándo la
; GPU integrada está bajo una carga lo suficientemente pesada como para justificar el cambio a
; igpu_desiredgov. Establezca esto en -1 para desactivar todas las comprobaciones de la iGPU y usar siempre
; desiredgov para los juegos.
igpu_power_threshold=0.3
; GameMode puede cambiar la política del planificador a SCHED_ISO en kernels que lo soporten (actualmente
; no soportado por los kernels upstream). Se puede establecer en "auto", "on" u "off". "auto" lo habilitará
; con 4 o más núcleos de CPU. "on" siempre lo habilitará. Por defecto es "off".
softrealtime=off
; GameMode puede cambiar la prioridad (renice) de los procesos de juego. Puede poner cualquier valor entre 0 y 20 aquí, el valor
; se negará y se aplicará como valor de nice (0 significa sin cambio). Por defecto es 0.
; Para usar esta función, el usuario debe ser añadido al grupo gamemode (y luego reiniciar):
; sudo usermod -aG gamemode $(whoami)
renice=0
; Por defecto, GameMode ajusta la prioridad de E/S (iopriority) de los clientes a BE/0, puede poner cualquier valor
; entre 0 y 7 aquí (con 0 siendo la prioridad más alta), o uno de los valores especiales
; "off" (para desactivar) o "reset" (para restaurar el comportamiento predeterminado de Linux basado en la prioridad de la CPU),
; actualmente, solo se soporta la clase best-effort, por lo que no puede establecerlo aquí
ioprio=0
; Establece si gamemode inhibirá el salvapantallas cuando esté activo
; Por defecto es 1
inhibit_screensaver=1
; Establece si gamemode desactivará la mitigación de split lock cuando esté activo
; Por defecto es 1
disable_splitlock=1
[filter]
; Si la entrada "whitelist" tiene un valor o valores
; gamemode rechazará cualquier cosa que no esté en la lista blanca
;whitelist=RiseOfTheTombRaider
; Gamemode siempre rechazará cualquier cosa en la lista negra
;blacklist=HalfLife3
;    glxgears
[gpu]
; ¡Aquí hay dragones!
; Advertencia: Utilice estas configuraciones bajo su propio riesgo
; Cualquier daño al hardware causado por esta función es su responsabilidad y solo suya
; También se recomienda encarecidamente que pruebe estas configuraciones manualmente primero para encontrar los puntos óptimos
; Establecer esto en la frase clave "accept-responsibility" permitirá a gamemode aplicar optimizaciones de GPU como overclocks
;apply_gpu_optimisations=0
; El número de dispositivo DRM en el sistema (usualmente 0), es decir, el número en /sys/class/drm/card0/
;gpu_device=0
; Configuraciones específicas de Nvidia
; Requiere la extensión coolbits activada en nvidia-xconfig
; Esto corresponde al GPUPowerMizerMode deseado
; "Adaptive"=0 "Prefer Maximum Performance"=1 y "Auto"=2
; Ver NV_CTRL_GPU_POWER_MIZER_MODE y amigos en https://github.com/NVIDIA/nvidia-settings/blob/master/src/libXNVCtrl/NVCtrl.h
;nv_powermizer_mode=1
; Estos modificarán los relojes del núcleo y de la memoria del estado de mayor rendimiento en Nvidia PowerMizer
; Se miden como desplazamientos en Mhz desde la línea base, 0 restablecerá los valores a los predeterminados, -1 o sin establecer no modificará los valores
;nv_core_clock_mhz_offset=0
;nv_mem_clock_mhz_offset=0
; Configuraciones específicas de AMD
; Requiere un módulo de kernel AMDGPU relativamente actualizado
; Ver: https://dri.freedesktop.org/docs/drm/gpu/amdgpu.html#gpu-power-thermal-controls-and-monitoring
; También se recomienda encarecidamente que use lm-sensors (u otras herramientas disponibles) para verificar las temperaturas de la tarjeta
; Esto corresponde a power_dpm_force_performance_level, "manual" no está soportado por ahora
;amd_performance_level=high
[cpu]
; El estacionamiento (parking) o el anclaje (pinning) se pueden habilitar con "yes", "true" o "1" y deshabilitar con "no", "false" o "0".
; Cualquiera de los dos también se puede establecer en una lista específica de núcleos para estacionar o anclar, lista separada por comas donde "-" denota
; un rango. Por ejemplo, "park_cores=1,8-15" estacionaría los núcleos 1 y del 8 al 15.
; El valor por defecto sin comentar es deshabilitar el estacionamiento pero habilitar el anclaje. Si cualquiera de los dos está habilitado, el código actualmente
; solo detectará correctamente los Ryzen 7900x3d, 7950x3d y las CPU de Intel con núcleos E y P.
; Para el estacionamiento de núcleos (Core Parking), el usuario debe ser añadido al grupo gamemode (no es necesario para el anclaje de núcleos - Core Pinning):
; sudo usermod -aG gamemode $(whoami)
;park_cores=no
;pin_cores=yes
[supervisor]
; Esta sección controla las nuevas funciones de gamemode gamemode_request_start_for y gamemode_request_end_for
; La lista blanca y la lista negra controlan qué programas supervisores tienen permitido hacer las solicitudes anteriores
;supervisor_whitelist=
;supervisor_blacklist=
; En caso de que quiera permitir que un supervisor tome el control total de gamemode, se puede establecer esta opción
; Esto solo permitirá que los clientes de gamemode se registren usando las funciones anteriores por un cliente supervisor
;require_supervisor=0
[custom]
; Scripts personalizados (ejecutados usando el shell) cuando gamemode comienza y termina
;start=notify-send "GameMode started"
;    /home/me/bin/stop_foldingathome.sh
;end=notify-send "GameMode ended"
;    /home/me/bin/start_foldingathome.sh
; Tiempo de espera para los scripts (segundos). Los scripts serán terminados si no se completan dentro de este tiempo.
;script_timeout=10
