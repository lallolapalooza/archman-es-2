getaddrinfo(3) Manual de funciones de biblioteca getaddrinfo(3)

NOMBRE

getaddrinfo, freeaddrinfo, gai_strerror - traducción de direcciones y servicios de red

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/types.h>
#include <sys/socket.h>
#include <netdb.h>
int getaddrinfo(const char *restrict node,
                const char *restrict service,
                const struct addrinfo *restrict hints,
                struct addrinfo **restrict res);
void freeaddrinfo(struct addrinfo *res);
const char *gai_strerror(int errcode);

DESCRIPCIÓN

Dadas node y service, que identifican un host de Internet y un servicio, getaddrinfo() devuelve una o más estructuras addrinfo, cada una de las cuales contiene una dirección de Internet que puede especificarse en una llamada a bind(2) o connect(2). La función getaddrinfo() combina la funcionalidad proporcionada por las funciones gethostbyname(3) y getservbyname(3) en una única interfaz, pero a diferencia de estas últimas, getaddrinfo() es reentrante y permite a los programas eliminar dependencias de IPv4 frente a IPv6.

La estructura addrinfo utilizada por getaddrinfo() contiene los siguientes campos:


struct addrinfo {
    int              ai_flags;
    int              ai_family;
    int              ai_socktype;
    int              ai_protocol;
    socklen_t        ai_addrlen;
    struct sockaddr *ai_addr;
    char            *ai_canonname;
    struct addrinfo *ai_next;
};

El argumento hints apunta a una estructura addrinfo que especifica los criterios para seleccionar las estructuras de dirección de socket devueltas en la lista apuntada por res. Si hints no es NULL, apunta a una estructura addrinfo cuyos campos ai_family, ai_socktype y ai_protocol especifican criterios que limitan el conjunto de direcciones de socket devueltas por getaddrinfo(), de la siguiente manera:

ai_family
Este campo especifica la familia de direcciones deseada para las direcciones devueltas. Los valores válidos para este campo incluyen AF_INET y AF_INET6. El valor AF_UNSPEC indica que getaddrinfo() debe devolver direcciones de socket para cualquier familia de direcciones (IPv4 o IPv6, por ejemplo) que pueda usarse con node y service.
ai_socktype
Este campo especifica el tipo de socket preferido, por ejemplo SOCK_STREAM o SOCK_DGRAM. Especificar 0 en este campo indica que se pueden devolver direcciones de socket de cualquier tipo por getaddrinfo().
ai_protocol
Este campo especifica el protocolo para las direcciones de socket devueltas. Especificar 0 en este campo indica que se pueden devolver direcciones de socket con cualquier protocolo por getaddrinfo().
ai_flags
Este campo especifica opciones adicionales, descritas a continuación. Se especifican varias banderas OR-inglas bit a bit.

Todos los demás campos de la estructura a la que apunta hints deben contener 0 o un puntero nulo, según corresponda.

Especificar hints como NULL es equivalente a establecer ai_socktype y ai_protocol en 0; ai_family en AF_UNSPEC; y ai_flags en (AI_V4MAPPED | AI_ADDRCONFIG). (POSIX especifica valores por defecto diferentes para ai_flags; ver NOTAS.) node especifica una dirección de red numérica (para IPv4, notación de puntos y números como es soportado por inet_aton(3); para IPv6, formato de cadena hexadecimal como es soportado por inet_pton(3)), o un nombre de host de red, cuyas direcciones de red se buscan y resuelven. Si hints.ai_flags contiene la bandera AI_NUMERICHOST, entonces node debe ser una dirección de red numérica. La bandera AI_NUMERICHOST suprime cualquier búsqueda de dirección de host de red potencialmente larga.

Si la bandera AI_PASSIVE se especifica en hints.ai_flags, y node es NULL, entonces las direcciones de socket devueltas serán adecuadas para enlazar (bind(2)) un socket que aceptará (accept(2)) conexiones. La dirección de socket devuelta contendrá la "dirección wildcard" (INADDR_ANY para direcciones IPv4, IN6ADDR_ANY_INIT para direcciones IPv6). La dirección wildcard es utilizada por aplicaciones (típicamente servidores) que pretenden aceptar conexiones en cualquiera de las direcciones de red del host. Si node no es NULL, entonces la bandera AI_PASSIVE se ignora.

Si la bandera AI_PASSIVE no está establecida en hints.ai_flags, entonces las direcciones de socket devueltas serán adecuadas para su uso con connect(2), sendto(2), o sendmsg(2). Si node es NULL, entonces la dirección de red se establecerá en la dirección de la interfaz de loopback (INADDR_LOOPBACK para direcciones IPv4, IN6ADDR_LOOPBACK_INIT para direcciones IPv6); esto es utilizado por aplicaciones que pretenden comunicarse con pares que se ejecutan en el mismo host.

service establece el puerto en cada estructura de dirección devuelta. Si este argumento es un nombre de servicio (ver services(5)), se traduce al número de puerto correspondiente. Este argumento también puede especificarse como un número decimal, que simplemente se convierte a binario. Si service es NULL, entonces el número de puerto de las direcciones de socket devueltas quedará sin inicializar. Si AI_NUMERICSERV se especifica en hints.ai_flags y service no es NULL, entonces service debe apuntar a una cadena que contenga un número de puerto numérico. Esta bandera se utiliza para inhibir la invocación de un servicio de resolución de nombres en casos donde se sabe que no es necesario.

Ya sea node o service, pero no ambos, pueden ser NULL.

La función getaddrinfo() asigna e inicializa una lista enlazada de estructuras addrinfo, una por cada dirección de red que coincida con node y service, sujeta a cualquier restricción impuesta por hints, y devuelve un puntero al inicio de la lista en res. Los elementos de la lista enlazada están enlazados por el campo ai_next.

Hay varias razones por las que la lista enlazada puede tener más de una estructura addrinfo, incluyendo: el host de red es multi-homed, accesible a través de múltiples protocolos (por ejemplo, tanto AF_INET como AF_INET6); o el mismo servicio está disponible desde múltiples tipos de socket (una dirección SOCK_STREAM y otra dirección SOCK_DGRAM, por ejemplo). Normalmente, la aplicación debe intentar usar las direcciones en el orden en que se devuelven. La función de ordenación utilizada dentro de getaddrinfo() se define en RFC 3484; el orden se puede ajustar para un sistema particular editando /etc/gai.conf (disponible desde glibc 2.5).

Si hints.ai_flags incluye la bandera AI_CANONNAME, entonces el campo ai_canonname de la primera de las estructuras addrinfo de la lista devuelta se establece para apuntar al nombre oficial del host.

Los campos restantes de cada estructura addrinfo devuelta se inicializan de la siguiente manera:

•
Los campos ai_family, ai_socktype y ai_protocol devuelven los parámetros de creación del socket (es decir, estos campos tienen el mismo significado que los argumentos correspondientes de socket(2)). Por ejemplo, ai_family podría devolver AF_INET o AF_INET6; ai_socktype podría devolver SOCK_DGRAM o SOCK_STREAM; y ai_protocol devuelve el protocolo para el socket.
•
Se coloca un puntero a la dirección del socket en el campo ai_addr, y el tamaño de la dirección del socket, en bytes, se coloca en el campo ai_addrlen.

include la bandera AI_ADDRCONFIG, entonces las direcciones IPv4 se devuelven en la lista apuntada por res solo si el sistema local tiene al menos una dirección IPv4 configurada, y las direcciones IPv6 se devuelven solo si el sistema local tiene al menos una dirección IPv6 configurada. La dirección de loopback no se considera válida como dirección configurada en este caso. Esta bandera es útil en, por ejemplo, sistemas solo IPv4, para garantizar que getaddrinfo() no devuelva direcciones de socket IPv6 que siempre fallarían en connect(2) o bind(2).

Si hints.ai_flags especifica la bandera AI_V4MAPPED, y hints.ai_family se especificó como AF_INET6, y no se pudieron encontrar direcciones IPv6 coincidentes, entonces se devuelven direcciones IPv6 mapeadas a IPv4 en la lista apuntada por res. Si tanto AI_V4MAPPED como AI_ALL se especifican en hints.ai_flags, entonces se devuelven direcciones IPv6 y IPv6 mapeadas a IPv4 en la lista apuntada por res. AI_ALL se ignora si AI_V4MAPPED no se especifica también.

La función freeaddrinfo() libera la memoria que se asignó para la lista enlazada asignada dinámicamente res.

Extensiones a getaddrinfo() para Nombres de Dominio Internacionalizados

A partir de glibc 2.3.4, getaddrinfo() se ha ampliado para permitir selectivamente que los nombres de host de entrada y salida se conviertan transparentemente a y desde el formato de Nombre de Dominio Internacionalizado (IDN) (ver RFC 3490, Internationalizing Domain Names in Applications (IDNA)). Se definen cuatro banderas nuevas:

AI_IDN
Si se especifica esta bandera, entonces el nombre de nodo dado en node se convierte al formato IDN si es necesario. La codificación de origen es la de la configuración regional actual.
Si el nombre de entrada contiene caracteres no ASCII, entonces se utiliza la codificación IDN. Esas partes del nombre de nodo (delimitadas por puntos) que contienen caracteres no ASCII se codifican usando Codificación Compatible con ASCII (ACE) antes de pasarse a las funciones de resolución de nombres.
AI_CANONIDN
Después de una búsqueda de nombre exitosa, y si se especificó la bandera AI_CANONNAME, getaddrinfo() devolverá el nombre canónico del nodo correspondiente al valor de la estructura addrinfo devuelto. El valor de retorno es una copia exacta del valor devuelto por la función de resolución de nombres.
Si el nombre está codificado usando ACE, entonces contendrá el prefijo xn-- para uno o más componentes del nombre. Para convertir estos componentes en un formato legible, la bandera AI_CANONIDN puede pasarse además de AI_CANONNAME. La cadena resultante se codifica utilizando la codificación de la configuración regional actual.
AI_IDN_ALLOW_UNASSIGNED
AI_IDN_USE_STD3_ASCII_RULES
Establecer estas banderas habilitará las banderas IDNA_ALLOW_UNASSIGNED (permitir puntos de código Unicode no asignados) e IDNA_USE_STD3_ASCII_RULES (verificar la salida para asegurarse de que sea un nombre de host que cumpla con STD3) respectivamente para su uso en el manejo de IDNA.

VALOR DE RETORNO

getaddrinfo() devuelve 0 si tiene éxito, o uno de los siguientes códigos de error distintos de cero:

EAI_ADDRFAMILY
El host de red especificado no tiene ninguna dirección de red en la familia de direcciones solicitada.
EAI_AGAIN
El servidor de nombres devolvió una indicación de fallo temporal. Inténtelo de nuevo más tarde.
EAI_BADFLAGS
hints.ai_flags contiene banderas inválidas; o, hints.ai_flags incluyó AI_CANONNAME y node era NULL.
EAI_FAIL
El servidor de nombres devolvió una indicación de fallo permanente.
EAI_FAMILY
La familia de direcciones solicitada no es compatible.
EAI_MEMORY
Sin memoria.
EAI_NODATA
El host de red especificado existe, pero no tiene direcciones de red definidas.
EAI_NONAME
El node o service no se conocen; o tanto node como service son NULL; o AI_NUMERICSERV se especificó en hints.ai_flags y service no era una cadena de número de puerto numérico.
EAI_SERVICE
El servicio solicitado no está disponible para el tipo de socket solicitado. Puede estar disponible a través de otro tipo de socket. Por ejemplo, este error podría ocurrir si service fuera "shell" (un servicio disponible solo en sockets de flujo), y hints.ai_protocol fuera IPPROTO_UDP, o hints.ai_socktype fuera SOCK_DGRAM; o el error podría ocurrir si service no fuera NULL, y hints.ai_socktype fuera SOCK_RAW (un tipo de socket que no soporta el concepto de servicios).
EAI_SOCKTYPE
El tipo de socket solicitado no es compatible. Esto podría ocurrir, por ejemplo, si hints.ai_socktype y hints.ai_protocol son inconsistentes (por ejemplo, SOCK_DGRAM y IPPROTO_TCP, respectivamente).
EAI_SYSTEM
Otro error del sistema; errno se establece para indicar el error.

La función gai_strerror() traduce estos códigos de error a una cadena legible por humanos, adecuada para la notificación de errores.

EJEMPLOS

Los siguientes programas demuestran el uso de getaddrinfo(), gai_strerror(), freeaddrinfo(), y getnameinfo(3). Los programas son un servidor y cliente de eco para datagramas UDP.

Programa servidor

#include <netdb.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/socket.h>
#include <sys/types.h>
#include <unistd.h>
#define BUF_SIZE 500
int
main(int argc, char *argv[])
{
    int                      sfd, s;
    char                     buf[BUF_SIZE];
    ssize_t                  nread;
    socklen_t                peer_addrlen;
    struct addrinfo          hints;
    struct addrinfo          *result, *rp;
    struct sockaddr_storage  peer_addr;
    if (argc != 2) {
        fprintf(stderr, "Uso: %s puerto\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    memset(&hints, 0, sizeof(hints));
    hints.ai_family = AF_UNSPEC;    /* Permitir IPv4 o IPv6 */
    hints.ai_socktype = SOCK_DGRAM; /* Socket de datagrama */
    hints.ai_flags = AI_PASSIVE;    /* Para dirección IP comodín */
    hints.ai_protocol = 0;          /* Cualquier protocolo */
    hints.ai_canonname = NULL;
    hints.ai_addr = NULL;
    hints.ai_next = NULL;
    s = getaddrinfo(NULL, argv[1], &hints, &result);
    if (s != 0) {
        fprintf(stderr, "getaddrinfo: %s\n", gai_strerror(s));
        exit(EXIT_FAILURE);
    }
    /* getaddrinfo() devuelve una lista de estructuras de direcciones.
       Intente cada dirección hasta que se vincule correctamente (bind(2)).
       Si socket(2) (o bind(2)) falla, (cerramos el socket
       y) intentamos con la siguiente dirección.  */
    for (rp = result; rp != NULL; rp = rp->ai_next) {
        sfd = socket(rp->ai_family, rp->ai_socktype,
                     rp->ai_protocol);
        if (sfd == -1)
            continue;
        if (bind(sfd, rp->ai_addr, rp->ai_addrlen) == 0)
            break;                  /* Éxito */
        close(sfd);
    }
    freeaddrinfo(result);           /* Ya no es necesario */
    if (rp == NULL) {               /* Ninguna dirección tuvo éxito */
        fprintf(stderr, "No se pudo vincular\n");
        exit(EXIT_FAILURE);
    }
    /* Leer datagramas y enviarlos de vuelta al remitente.  */
    for (;;) {
        char host[NI_MAXHOST], service[NI_MAXSERV];
        peer_addrlen = sizeof(peer_addr);
        nread = recvfrom(sfd, buf, BUF_SIZE, 0,
                         (struct sockaddr *) &peer_addr, &peer_addrlen);
        if (nread == -1)
            continue;               /* Ignorar solicitud fallida */
        s = getnameinfo((struct sockaddr *) &peer_addr,
                        peer_addrlen, host, NI_MAXHOST,
                        service, NI_MAXSERV, NI_NUMERICSERV);
        if (s == 0)
            printf("Received %zd bytes from %s:%s\n",
                   nread, host, service);
        else
            fprintf(stderr, "getnameinfo: %s\n", gai_strerror(s));
        if (sendto(sfd, buf, nread, 0, (struct sockaddr *) &peer_addr,
                   peer_addrlen) != nread)
        {
            fprintf(stderr, "Error sending response\n");
        }
    }
}

Programa cliente

#include <netdb.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/socket.h>
#include <sys/types.h>
#include <unistd.h>
#define BUF_SIZE 500
int
main(int argc, char *argv[])
{
    int              sfd, s;
    char             buf[BUF_SIZE];
    size_t           size;
    ssize_t          nread;
    struct addrinfo  hints;
    struct addrinfo  *result, *rp;
    if (argc < 3) {
        fprintf(stderr, "Usage: %s host port msg...\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    /* Obtener direcciones que coincidan con host/puerto.  */
    memset(&hints, 0, sizeof(hints));
    hints.ai_family = AF_UNSPEC;    /* Permitir IPv4 o IPv6 */
    hints.ai_socktype = SOCK_DGRAM; /* Socket de datagramas */
    hints.ai_flags = 0;
    hints.ai_protocol = 0;          /* Cualquier protocolo */
    s = getaddrinfo(argv[1], argv[2], &hints, &result);
    if (s != 0) {
        fprintf(stderr, "getaddrinfo: %s\n", gai_strerror(s));
        exit(EXIT_FAILURE);
    }
    /* getaddrinfo() devuelve una lista de estructuras de dirección.
       Prueba cada dirección hasta que connect(2) tenga éxito.
       Si socket(2) (o connect(2)) falla, (cerramos el socket
       y) probamos la siguiente dirección.  */
    for (rp = result; rp != NULL; rp = rp->ai_next) {
        sfd = socket(rp->ai_family, rp->ai_socktype,
                     rp->ai_protocol);
        if (sfd == -1)
            continue;
        if (connect(sfd, rp->ai_addr, rp->ai_addrlen) != -1)
            break;                  /* Éxito */
        close(sfd);
    }
    freeaddrinfo(result);           /* Ya no es necesario */
    if (rp == NULL) {               /* Ninguna dirección tuvo éxito */
        fprintf(stderr, "Could not connect\n");
        exit(EXIT_FAILURE);
    }
    /* Enviar los argumentos restantes de la línea de comandos como
       datagramas separados, y leer las respuestas del servidor.  */
    for (size_t j = 3; j < argc; j++) {
        size = strlen(argv[j]) + 1;
                /* +1 para el byte nulo terminador */
        if (size > BUF_SIZE) {
            fprintf(stderr,
                    "Ignoring long message in argument %zu\n", j);
            continue;
        }
        if (write(sfd, argv[j], size) != size) {
            fprintf(stderr, "partial/failed write\n");
            exit(EXIT_FAILURE);
        }
        nread = read(sfd, buf, BUF_SIZE);
        if (nread == -1) {
            perror("read");
            exit(EXIT_FAILURE);
        }
        printf("Received %zd bytes: %s\n", nread, buf);
    }
    exit(EXIT_SUCCESS);
}
