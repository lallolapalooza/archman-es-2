gammu-smsd-tables - descripción de las tablas para los backends de base de datos de

gammu-smsd(1)

Los backends en sí mismos se describen en sus secciones, este documento describe la estructura general de la base de datos y las tablas

requeridas.

Varias instancias de SMS daemon pueden compartir una única base de datos. Si no especificas PhoneID en su configuración, todas se tratan por igual y no tienes garantía de cuál enviará el mensaje saliente. Si configuras PhoneID y lo usas al insertar el mensaje en la tabla outbox (gammu-smsd-inject hace esto), cada SMS daemo

n tendrá una cola de salida sepa
rada. Ver también smsd-multi.

SQL

Para enviar un mensaje, puede usar gammu-smsd-inject, que hace toda la magia por usted, o puede insertar el mensaje manualmente. El ejemplo más simple es un mensaje de texto

Inyección de un mensaje largo usando

SQL

Insertar mensajes multiparte es un poco más complicado, necesita construir también la cabecera UDH y almacenarla escrita en hexadecimal en el campo UDH. A menos que tenga una buena razón para hacerlo manualmente, use gammu-smsd-inject, la biblioteca C (SMSD_InjectSMS()) o la biblioteca de Python (gammu.smsd.SMSD.InjectSMS())

.

Para un mensaje de texto largo, el UDH comienza con 050003 seguido de un byte como referencia del mensaje (puede poner cualquier valor hexadecimal ahí, pero debe ser diferente para cada mensaje, D3 en el siguiente ejemplo), un byte para el número de mensajes (02 en el ejemplo, debe ser único para cada mensaje que envíe al mismo número de teléfono) y un byte para el número del mensaje actual (01 para el primer mensaje, 02 para el segundo, etc.)

.

En la mayoría de los casos, el mensaje multiparte debe ser de clase

1.
