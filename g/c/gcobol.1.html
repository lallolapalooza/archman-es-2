Según ISO, un elemento que REDEFINES a otro no puede ser más grande que el elemento que redefine, a menos que ese elemento tenga NIVEL 01 y no sea EXTERNAL. En gcobol, usando -dialect ibm, esta regla se relaja para REDEFINES con USAGE POINTER cuyo miembro redefinido es un USAGE COMP-5 de 4 bytes (usualmente PIC S9(8)), o viceversa. En ese caso, el miembro redefinido se redimensiona a 8 bytes, para acomodar el puntero. Esta característica permite la aritmética de punteros en un sistema de 64 bits con código fuente destinado a un sistema de 32

NOTAS DE

IMPLEMENTACIÓN

gcobol es un compilador de gcc, y sigue las convenciones de gcc cuando corresponde. A veces esas convenciones (y las expectativas del usuario) entran en conflicto con la práctica común de Mainframe. Salvo que la especificación ISO lo exija del compilador, cualquier conflicto de este tipo se resuelve a favor de

gcc.

Enlazad

o

A diferencia de C, la sentencia COBOL CALL implica enlazado dinámico, porque

para
CALL progra
m program puede ser una variable cuyo valor se determina en tiempo de ejecución. Sin embargo, el parámetro también puede ser una constante en tiempo de compilación, ya sea un literal alfanumérico, o un elemento de datos CONSTANT.

gcobol soporta el enlazado estático donde es posible, a menos que se anule con -fno-static-call. Si el valor del parámetro se conoce en tiempo de compilación, el compilador produce una referencia externa para ser resuelta por el enlazador. El programa referenciado se proporciona normalmente a través de un módulo de objeto, una biblioteca estática, o un objeto compartido. Si no se proporciona, el enlazador reportará un error de "símbolo no resuelto", ya sea en el momento de la construcción o, si se usa un objeto compartido, cuando se ejecuta el programa. Esta característica informa al programador del error en la primera

oportunidad.

Los programas que se espera que se ejecuten correctamente en presencia de un símbolo no resuelto (quizás porque la lógica del programa no requerirá ese CALL en particular) pueden usar la opción -no-static-call. Eso fuerza a que todas las sentencias CALL se resuelvan dinám

icamente, en tie
mpo de ejecución.

proceso.

COMPATIBILIDA

D

El estándar ISO deja la organización de archivo predeterminada a la implementación; en gcobol, el valor predeterminado es SEQUENTIAL

.

Formato en

disco

Cualquier capacidad de usar archivos producidos por otros compiladores COBOL, o para que esos compiladores usen archivos producidos por gcobol, es producto de la suerte y la intuición. Varios compiladores interpretan el estándar ISO de manera diferente, y el texto del estándar no siempre es

definitivo.

Para archivos ORGANIZATION IS LINE SEQUENTIAL (explícitamente o por defecto), gcobol, a menos que se indique específicamente, produce un archivo de texto de Linux ordinario: para cada WRITE, se escriben los datos, seguidos de un carácter ASCII NL (hex 0A). En READ, se lee el registro hasta el tamaño del registro especificado o NL, lo que ocurra primero. El NL no se incluye en los datos que se llevan al búfer de registro; sirve solo como un marcador de terminación de registro en disco. En consecuencia, SEQUENTIAL y archivos LINE SEQUENTIAL funcionan de la misma manera: el programa COBOL nunca ve el terminador de

registro.

Cuando READ y WRITE se usan con ADVANCING, sin embargo, el juego cambia. Si ADVANCING se usa con archivos LINE SEQUENTIAL, se respeta en gcobol

.

Otros compiladores pueden no hacer lo mismo. Según ISO, en WRITE (14.9.47.3 Reglas generales) ADVANCING se ignora para archivos para los que “el archivo físico no soporta posicionamiento vertical”. Además establece que, en ausencia de ADVANCING, WRITE procede como si “como si el usuario hubiera especificado AFTER ADVANCING 1 LINE”. Algunas otras implementaciones interpretan eso para significar que el primer WRITE a un archivo LINE SEQUENTIAL resulta en un NL inicial en la primera línea, y sin NL final en la última línea. Algunas además prohíben el uso de ADVANCING con archivos LIN

DESCRIPCIÓN

gcobol es el compilador COBOL para GNU compilado para el proyecto GNU.

SINÓPSIS

gcobol [OPCIÓN]... [ARCHIVO]...

EJEMPLOS DE COMPILACIÓN

gcobol myprog.cob
Compila myprog.cob en un archivo objeto myprog.o.
gcobol -o myprog myprog.cob
Compila myprog.cob y genera un ejecutable llamado myprog.
gcobol -g myprog.cob
Compila myprog.cob y genera información de depuración.

EBCDIC

Por defecto, gcobol asume que los datos de entrada están en ASCII. Si los datos de entrada están en EBCDIC, especifique la opción -E.

REDEFINES ... USO PUNTERO

gcobol soporta la cláusula REDEFINES junto con USAGE POINTER, que no se encuentra típicamente en COBOL estándar.

NOTAS DE IMPLEMENTACIÓN

El soporte de E/S de gcobol no está completamente desarrollado. Si bien los archivos LINE-SEQUENTIAL son archivos de texto ordinarios que pueden ser manipulados con utilidades estándar, los archivos INDEXED y RELATIVE producidos por gcobol no son compatibles con los de ningún otro compilador COBOL. Se prevé que las mejoras en el soporte de E/S estarán disponibles para los clientes de pago.

EXTENCIONES A ISO COBOL

El compilador soporta varias extensiones al estándar ISO COBOL, incluyendo:

  • La cláusula REDEFINES junto con USAGE POINTER.
  • Soporte de EBCDIC (con la opción -E).

Cuando gcobol pasa el 100% de las pruebas de un módulo, excluimos las (pocas) pruebas para características obsoletas. Los autores consideran que las características obsoletas en 1985 están bien y realmente obsoletas hoy en día, y no las implementaron.

Características notables pospuestas

Los módulos CCVS-85 no marcados con el estado anterior (CM, y SG) están en la lista de "difícil quizás", lo que significa que esperan a una parte interesada con código real que utilice la característica.

gcobol no implementa Report Writer ni Screen Section.

Más allá de COBOL/85

gcobol implementa cada vez más ISO/IEC 1989:2023. Por ejemplo, DECLARATIVES no es probado por CCVS-85, pero está implementado por gcobol. De manera similar, las Condiciones de Excepción no se definieron en 1985, y gcobol contiene un número creciente de ellas.

Los autores son muy conscientes de que un compilador COBOL-85 completo y puro no compilará la mayor parte del código COBOL existente. Cada proveedor ofreció (y ofrece) extensiones, y la mayoría de los entornos dependen de una variedad de preprocesadores y sistemas auxiliares definidos fuera del estándar. El objetivo expreso de agregar un front-end ISO COBOL a GCC es establecer una base sobre la cual se puedan construir las extensiones necesarias.

HISTORIA

COBOL, el lenguaje, puede ser más antiguo que el lector. Hasta donde sabe el autor, los compiladores COBOL gratuitos comenzaron a aparecer alrededor del año 2000. Por esa época, un proyecto anterior de COBOL para GCC
cobolforgcc tuvo cierto éxito, pero nunca se fusionó oficialmente con GCC.

Este compilador, gcobol, fue iniciado por COBOLworx en el otoño de 2021. El proyecto anunció una implementación completa de las características centrales del lenguaje en diciembre de 2022.
