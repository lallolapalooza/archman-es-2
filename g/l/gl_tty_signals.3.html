gl_io_mode, gl_raw_io, gl_normal_io, gl_tty_signals, gl_abandon_line,
gl_handle_signal, gl_pending_io - Cómo usar gl_get_line() desde un bucle de eventos externo.

SINOPSIS

#include <libtecla.h>
int gl_io_mode(GetLine *gl, GlIOMode mode);
int gl_raw_io(GetLine *gl);
int gl_normal_io(GetLine *gl);
int gl_tty_signals(void (*term_handler)(int),
                   void (*susp_handler)(int),
                   void (*cont_handler)(int),
                   void (*size_handler)(int));

void gl_handle_signal(int signo, GetLine *gl, int ngl);
GlPendingIO gl_pending_io(GetLine *gl);

DESCRIPCIÓN

La gl_get_line() función, la cual está documentada por separado en la gl_get_line(3) página del manual, soporta dos modos de E/S diferentes. Estos se seleccionan llamando a la gl_io_mode() función.

  int gl_io_mode(GetLine *gl, GlIOMode mode);

El modo argumento de esta función especifica el nuevo modo de E/S, y debe ser uno de los siguientes.

  GL_NORMAL_MODE   -  Selecciona el modo normal de E/S bloqueante.
                      En este modo gl_get_line()
                      no retorna hasta que ocurre un error
                      o el usuario termina de introducir una
                      nueva línea. Este modo es el foco de la
                      página del manual gl_get_line(3) .
  GL_SERVER_MODE   -  Selecciona el modo de E/S de servidor no bloqueante.
                      En este modo, ya que se usa E/S de terminal
                      no bloqueante, la introducción de cada nueva
                      línea de entrada normalmente requiere muchas
                      llamadas a gl_get_line() desde
                      un bucle de eventos externo impulsado por E/S.
                      Este modo es el foco de esta página del manual.

Los objetos GetLine recién creados comienzan en modo de E/S normal, así que para cambiar al modo de servidor no bloqueante se requiere una llamada inicial a gl_io_mode().

MODO DE E/S DE SERVIDOR

En modo de E/S de servidor no bloqueante, la aplicación está obligada a tener un bucle de eventos que llame a gl_get_line() siempre que el descriptor de archivo del terminal pueda hacer el tipo de E/S que gl_get_line() está esperando. Para determinar qué tipo de E/S gl_get_line() está esperando, la aplicación llama a la gl_pending_io() función.

  GlPendingIO gl_pending_io(GetLine *gl);

El valor de retorno de esta función es uno de los dos valores enumerados siguientes.

  GLP_READ    -  gl_get_line() está esperando para escribir un
                 carácter en el terminal.
  GLP_WRITE   -  gl_get_line() está esperando para leer un
                 carácter del teclado.

Si la aplicación está usando ya sea la select() o poll() llamadas al sistema para vigilar la E/S en un grupo de descriptores de archivo, entonces debería llamar a la gl_pending_io() función antes de cada llamada a estas funciones para ver qué dirección de E/S debería decirles que vigilen, y configurar sus argumentos en consecuencia. En el caso de la select() llamada al sistema, esto significa usar la FD_SET() macro para añadir el descriptor de archivo del terminal ya sea al conjunto de descriptores de archivo a ser vigilados por legibilidad, o al conjunto a ser vigilado por escribibilidad.

Como en modo de E/S normal, el valor de retorno de gl_get_line() es ya sea un puntero a una línea de entrada completada, o NULL. Sin embargo, mientras que en modo de E/S normal un NULL valor de retorno siempre significa que ocurrió un error, en modo de servidor no bloqueante, NULL también se retorna cuando gl_get_line() no puede leer o escribir en el terminal sin bloquear. Así que en modo de servidor no bloqueante, para determinar cuándo un NULL valor de retorno significa que ocurrió un error o no, es necesario llamar a la gl_return_status() función. Si esta función retorna el valor enumerado, GLR_BLOCKED, como está documentado en la gl_get_line(3) página del manual, esto significa que gl_get_line() está esperando E/S, y no ha ocurrido ningún error.

Cuando gl_get_line() retorna NULL y gl_return_status() indica que esto es debido a E/S de terminal bloqueada, la aplicación debería llamar a gl_get_line() de nuevo cuando el tipo de E/S reportado por gl_pending_io() se vuelva posible. Los argumentos prompt, start_line y start_pos de gl_get_line() serán ignorados en estas llamadas. Si necesita cambiar el prompt de la línea que está siendo editada actualmente, entonces puede llamar a la gl_replace_prompt() función (documentada en la página del manual gl_get_line(3) ) entre llamadas a gl_get_line().

RENDIENDO EL TERMINAL

Una complicación que es única al modo de servidor no bloqueante es que requiere que el terminal sea dejado en modo crudo entre llamadas a gl_get_line(). Si no fuera el caso, el bucle de eventos externo no sería capaz de detectar pulsaciones de teclas individuales, y la edición básica de línea implementada por el controlador del terminal entraría en conflicto con la edición provista por gl_get_line(). Lo que esto significa es que cada vez que el terminal necesita ser usado para otras cosas que introducir una nueva línea de entrada con gl_get_line(), necesita ser restaurado a un estado utilizable. En particular, siempre que el proceso sea suspendido o terminado, el terminal debe ser devuelto a un estado normal. Si esto no se hace, entonces dependiendo de las características del shell que fue usado para invocar el programa, el usuario puede terminar con un terminal colgado. Para este fin, la gl_normal_io() función es provista para cambiar el terminal de vuelta al estado en el que estaba cuando el modo crudo fue establecido por última vez.

  int gl_normal_io(GetLine *gl);

Lo que esta función hace es primero vaciar cualquier salida pendiente al terminal, luego mover el cursor al inicio de la línea del terminal que sigue al final de la línea de entrada introducida incompletamente. En este punto es seguro suspender o terminar el proceso, y es seguro para la aplicación leer y escribir en el terminal. Para reanudar la introducción de la línea de entrada, la aplicación debería llamar a la gl_raw_io() función.

  int gl_raw_io(GetLine *gl);

Esta función inicia una nueva línea, redisplaya la línea de entrada parcialmente completada (si hay alguna), restaura la posición del cursor dentro de esta línea a donde estaba cuando se llamó a gl_normal_io() , luego cambia de vuelta a modo de terminal crudo, no bloqueante, listo para continuar la introducción de la línea de entrada cuando gl_get_line() sea llamada la próxima vez.

Note que en modo de servidor no bloqueante, si gl_get_line() es llamada después de una llamada a gl_normal_io(), sin una llamada intermedia a gl_raw_io(), gl_get_line() llamará a gl_raw_mode() ella misma, y el terminal permanecerá en este modo cuando gl_get_line() retorne.

MANEJO DE SEÑALES

En la sección anterior se señaló que en modo de servidor no bloqueante, el terminal debe ser restaurado a un estado sensato siempre que se reciba una señal que suspenda o termine el proceso. En modo de E/S normal, esto es hecho por usted por gl_get_line(), pero en modo de servidor no bloqueante, ya que el terminal es dejado en modo crudo entre llamadas a gl_get_line(), este manejo de señales tiene que ser hecho por la aplicación. Ya que hay muchas señales que pueden suspender o terminar un proceso, así como otras señales que son importantes para gl_get_line(), tales como la SIGWINCH señal, la cual le dice cuándo el tamaño del terminal ha cambiado, la gl_tty_signals() función es provista para instalar manejadores de señales para todas las señales pertinentes.

  int gl_tty_signals(void (*term_handler)(int),
                     void (*susp_handler)(int),
                     void (*cont_handler)(int),
                     void (*size_handler)(int));

  susp_handler  -  Este es el manejador de señal que debe ser

NAME

gl_tty_signals — signal handling for terminal I/O

SYNOPSIS

#include <tecla.h>
int gl_handle_signal(GetLine *gl, int sig);
int gl_trap_signal(GetLine *gl, int sig, int enable);
int gl_abandon_line(GetLine *gl);

DESCRIPTION

The functions described here are intended for use with the gl_get_line function when it is used in non-blocking server I/O mode. This mode is specified by calling gl_normal_io or gl_raw_io before calling gl_get_line.

In non-blocking server I/O mode, gl_get_line does not block indefinitely waiting for input. Instead, it returns immediately. If there is no input, it returns NULL and a subsequent call to gl_return_status will return GLR_BLOCKED. If there is input, it returns the input string.

While gl_get_line is waiting for input, the application is expected to perform other tasks. These tasks may include waiting for events on other file descriptors using select or poll. When such an event occurs, or when a signal is received, the application may need to return control to gl_get_line to process the event or signal.

SERVER I/O MODE

Non-blocking server I/O mode is enabled by calling either gl_normal_io or gl_raw_io before calling gl_get_line. These functions configure the GetLine object to use non-blocking I/O and to return control to the application when no input is available. The application must then use a mechanism like select or poll to detect when input is available or when other events occur.

GIVING UP THE TERMINAL

In server I/O mode, the application may need to temporarily give up control of the terminal to gl_get_line. This is typically done when an external event occurs that requires attention. The gl_handle_signal function is used to handle signals that are received while gl_get_line is waiting for input. The gl_abandon_line function is used to discard the current input line and start a new one.

SIGNAL HANDLING

The gl_get_line function, when used in server I/O mode, can be configured to catch certain signals. When one of these signals is received, gl_get_line will return control to the application, and the application can then decide how to handle the signal.

The gl_trap_signal function is used to configure which signals gl_get_line should catch. The `sig` argument is the signal number, and the `enable` argument is a boolean value (1 to enable, 0 to disable).

The gl_handle_signal function is called by the application's signal handler to inform gl_get_line that a signal has been caught. The `sig` argument is the signal number that was caught.

The return value of gl_handle_signal indicates how gl_get_line should proceed. A return value of GLR_CONTINUE means that gl_get_line should continue processing. A return value of GLR_ABORT means that gl_get_line should abort the current input line. A return value of GLR_QUIT means that gl_get_line should terminate.

Process termination signals.

Signals such as SIGINT, SIGQUIT, and SIGTERM are typically used to terminate the process. When such a signal is caught, the application should usually allow the process to terminate.

Process suspension signals.

Signals such as SIGTSTP, SIGSTOP, and SIGCONT are used to suspend and resume the process. When such a signal is caught, the application should handle it appropriately, possibly by suspending or resuming the process.

INTERRUPTING THE EVENT LOOP

In server I/O mode, the application typically has an event loop that waits for input from various sources, including the terminal. Signals can be used to interrupt this event loop and force it to return to gl_get_line.

SIGNALS CAUGHT BY GL_GET_LINE

By default, gl_get_line catches the following signals:

SIGINT
Interrupt signal, typically generated by pressing Ctrl+C.
SIGQUIT
Quit signal, typically generated by pressing Ctrl+\.
SIGTSTP
Terminal stop signal, typically generated by pressing Ctrl+Z.

These signals can be enabled or disabled using the gl_trap_signal function.

ABORTING LINE INPUT

Often, rather than letting it terminate the process, applications respond to the SIGINT user-interrupt signal by aborting the current input line. The way to do this in non-blocking server-I/O mode is to not call gl_handle_signal() when this signal is caught, but instead to call the gl_abandon_line().

  void gl_abandon_line(GetLine *gl);

This function arranges that when gl_get_line() is next called, it first flushes any pending output to the terminal, then discardes the current input line, outputs a new prompt on the next line, and finally starts accepting input of a new input line from the user.

SIGNAL SAFE FUNCTIONS

Provided that certain rules are followed, the following functions can have been written to be safely callable from signal handlers. Other functions in this library should not be called from signal handlers.

  gl_normal_io()
  gl_raw_io()
  gl_handle_signal()
  gl_abandon_line()

In order for this to be true, all signal handlers that call these functions must be registered in such a way that only one instance of any one of them can be running at one time. The way to do this is to use the POSIX sigaction() function to register all signal handlers, and when doing this, use the sa_mask member of the corresponding sigaction structure, to indicate that all of the signals who's handlers invoke the above functions, should be blocked when the current signal is being handled. This prevents two signal handlers from operating on a GetLine object at the same time.

To prevent signal handlers from accessing a GetLine object while gl_get_line() or any of its associated public functions are operating on it, all public functions associated with gl_get_line(), including gl_get_line() itself, temporarily block the delivery of signals when they are accessing GetLine objects. Beware that the only signals that they block are the signals that gl_get_line() is currently configured to catch, so be sure that if you call any of the above functions from signal handlers, that the signals that these handlers are assigned to are configured to be caught by gl_get_line() (see gl_trap_signal()).

USING TIMEOUTS TO POLL

If instead of using select() or poll() to wait for I/O, your application just needs to get out of gl_get_line() periodically to briefly do something else before returning to accept input from the user, this can be done in non-blocking server mode by using the gl_inactivity_timeout() function (see gl_get_line(3)), to specify that a callback function that returns GLTO_CONTINUE should be called whenever gl_get_line() has been waiting for I/O for more than a specified amount of time.

When this callback is triggered, gl_get_line() will return NULL, and a following call to gl_return_status() will return GLR_BLOCKED.

Beware that gl_get_line() won't return until the user hasn't typed a key for the specified interval, so if the interval is long, and the user keeps typing, gl_get_line() may not return for a while. In other words there is no guarantee that it will return in the time specified.

THE SERVER DEMO PROGRAM

The demo3 program that is distributed with the library, provides a working example of how to use non-blocking server I/O mode in a real program. As far as the user is concerned, this program operates identically to the main demo program (called demo), except that whereas the main demo program uses the normal blocking I/O mode, demo3 using non-blocking I/O and an external event loop. The source code can be found in demo3.c, and the comments therein explain the various steps.
