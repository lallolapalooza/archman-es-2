glClearBufferSubData(3G)

GLCLEARBUFFERSUBDATA(3G) [FIXME: manual] GLCLEARBUFFERSUBDATA(3G)

NOMBRE

glClearBufferSubData, glClearNamedBufferSubData - rellenar todos o parte de los datos de un objeto de buffer con un valor fijo

ESPECIFICACIÓN EN C

void glClearBufferSubData(GLenum target, GLenum internalformat, GLintptr offset, GLsizeiptr size, GLenum format, GLenum type, const void * data);

void glClearNamedBufferSubData(GLuint buffer, GLenum internalformat, GLintptr offset, GLsizeiptr size, GLenum format, GLenum type, const void *data);

buffer

Especifica el nombre del objeto de buffer para glClearNamedBufferSubData.

internalformat

El formato interno con el que se almacenarán los datos en el objeto de buffer.

offset

El desplazamiento en unidades básicas de máquina dentro del almacenamiento de datos del objeto de buffer donde comenzar a rellenar.

size

El tamaño en unidades básicas de máquina del rango del almacenamiento de datos a rellenar.

format

El formato de los datos en la memoria direccionada por data.

type

El tipo de los datos en la memoria direccionada por data.

data

La dirección de una ubicación de memoria que almacena los datos que se replicarán en el almacenamiento de datos del buffer.

DESCRIPCIÓN

glClearBufferSubData y glClearNamedBufferSubData rellenan una región especificada del almacenamiento de datos de un objeto de buffer con datos de la memoria del cliente.

offset y size especifican la extensión de la región dentro del almacenamiento de datos del objeto de buffer a rellenar con datos. Los datos, suministrados inicialmente en un formato especificado por format en el tipo de datos type, se leen de la dirección de memoria dada por data y se convierten a la representación interna dada por internalformat, que debe ser uno de los siguientes formatos internos dimensionados:

The format and type parameters specify the format and data type of the source data in client memory. The list of accepted formats is specified in the "Formats" section of the glBufferSubData man page.

The table below lists the accepted values for type:

Type Corresponding C Type
GL_BYTE signed char
GL_UNSIGNED_BYTE unsigned char
GL_SHORT short
GL_UNSIGNED_SHORT unsigned short
GL_INT int
GL_UNSIGNED_INT unsigned int
GL_FLOAT float
GL_HALF_FLOAT half float (a 16-bit floating point type)
GL_DOUBLE double
GL_UNSIGNED_BYTE_3_3_2 unsigned char
GL_UNSIGNED_SHORT_4_4_4_4 unsigned short
GL_UNSIGNED_SHORT_5_5_5_1 unsigned short
GL_UNSIGNED_INT_8_8_8_8 unsigned int
GL_UNSIGNED_INT_10_10_10_2 unsigned int

glClearNamedBufferSubData operates on a buffer object directly, whereas glClearBufferSubData operates on the buffer object currently bound to the specified target.

If data is NULL, the contents of the specified region are undefined.

The offset and size parameters specify the region in the buffer object's data store. The entire region must be within the bounds of the buffer object. If the buffer object has not been allocated with sufficient storage, a GL error will be generated.

The internalformat must be one of the sized internal formats listed in the table above. If a non-sized internal format is provided, a GL error will be generated.

The format and type parameters specify how the data in the client memory pointed to by data is interpreted. The data is then converted to the internalformat of the buffer object.

If size is zero, no data is transferred and no error is generated.

ERRORES

GL_INVALID_OPERATION is generated if target is not one of the recognized buffer binding targets, or if the buffer object named by target (for glClearBufferSubData) or buffer (for glClearNamedBufferSubData) is not a buffer object.

GL_INVALID_OPERATION is generated if internalformat is not a sized internal format.

GL_INVALID_VALUE is generated if offset or size is negative, or if offset + size is greater than the size of the buffer object's data store.

GL_INVALID_ENUM is generated if format or type is not one of the recognized symbols.

GL_INVALID_OPERATION is generated if the combination of format and type is not compatible with internalformat.

ERRORES

GL_INVALID_ENUM se genera en glClearBufferSubData si target no es uno de los objetivos genéricos de enlace de búfer.

GL_INVALID_VALUE se genera en glClearBufferSubData si no hay ningún búfer enlazado a target.

GL_INVALID_OPERATION se genera en glClearNamedBufferSubData si buffer no es el nombre de un objeto de búfer existente.

GL_INVALID_ENUM se genera si internalformat no es uno de los formatos internos con tamaño válidos listados en la tabla anterior.

GL_INVALID_VALUE se genera si offset o range no son múltiplos del número de unidades básicas de máquina por elemento para el formato interno especificado por internalformat. Este valor puede calcularse multiplicando el número de componentes de internalformat de la tabla por el tamaño del tipo base de la tabla.

GL_INVALID_VALUE se genera si offset o size es negativo, o si $offset + size$ es mayor que el valor de GL_BUFFER_SIZE para el objeto de búfer.

GL_INVALID_OPERATION se genera si alguna parte del rango especificado del objeto de búfer está mapeada con glMapBufferRange() o glMapBuffer(), a menos que se haya mapeado con el bit GL_MAP_PERSISTENT_BIT establecido en los indicadores glMapBufferRange access .

GL_INVALID_VALUE se genera si format no es un formato válido, o type no es un tipo válido.
