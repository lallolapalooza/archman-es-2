El argumento pattern es un puntero a un patrón de nombre de ruta a expandir. La función glob() hará coincidir todos los nombres de ruta accesibles con este patrón y desarrollará una lista de todos los nombres de ruta que coincidan. Para tener acceso a un nombre de ruta, glob() requiere permiso de búsqueda en cada componente de una ruta excepto el último, y permiso de lectura en cada directorio de cualquier componente de nombre de archivo de pattern que contenga alguno de los siguientes caracteres especiales: '*', '?' y '['

.

La función glob() almacenará el número de nombres de ruta coincidentes en pglob->gl_pathc y un puntero a una lista de punteros a nombres de ruta en pglob->gl_pathv. Los nombres de ruta estarán en orden de clasificación como se define por la configuración actual de la categoría LC_COLLATE; consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 7.3.2, LC_COLLATE. El primer puntero después del último nombre de ruta será un puntero nulo. Si el patrón no coincide con ningún nombre de ruta, el número de rutas coincidentes devuelto se establece en 0, y el contenido de pglob-> gl_pathv es definido por la implementación.Es responsabilidad del llamador crear la estructura a la que

USO EN

APLICACIONES

Esta función no se proporciona con el propósito de permitir que las utilidades realicen la expansión de rutas de acceso en sus argumentos, ya que esta operación la realiza el shell, y se espera explícitamente que las utilidades no la repitan. En su lugar, se proporciona para aplicaciones que necesitan realizar la expansión de rutas de acceso en cadenas obtenidas de otras fuentes, como un patrón escrito por un usuario o leído de un

archivo.

Si una utilidad necesita ver si una ruta de acceso coincide con un patrón dado, puede usar fnmatch

().

Tenga en cuenta que gl_pathc y gl_pathv tienen significado incluso si glob() falla. Esto permite que glob() informe de resultados parciales en el caso de un error. Sin embargo, si gl_pathc es 0, gl_pathv no está especificado incluso si glob() no devolvió un

error.

La opción GLOB_NOCHECK podría usarse cuando una aplicación quiere expandir una ruta de acceso si se especifican comodines, pero quiere tratar el patrón como una cadena simple en caso contrario. La utilidad sh podría usar esto para argumentos de opción, por

ejemplo.

Las nuevas rutas de acceso generadas por una llamada posterior con GLOB_APPEND no se ordenan junto con las rutas de acceso anteriores. Esto refleja la manera en que el shell maneja la expansión de rutas de acceso cuando se realizan múltiples expansiones en una línea de

comando.

Las aplicaciones que necesitan la expansión de virgulilla y de parámetros deben usar worde

xp(
).

JUSTIFICATIV

A

Se afirmó que la bandera GLOB_DOOFFS es innecesaria porque se podría simular

usando: 
new = (char **)malloc((n + pglob->gl_pathc + 1)
       * sizeof(char *));
(void)
memcpy(new+n, pglob->gl_pathv, pglob->gl_pathc * sizeof(char *)); (void)
memset(new, 0, n * sizeof(char *)); free(pglob->gl_pathv); pglob->gl_pathv = new;

Sin embargo, esto asume que la memoria a la que apunta gl_pathv es un bloque que se creó por separado usando malloc(). Este no es necesariamente el caso. Una aplicación no debe hacer suposiciones sobre cómo se asignó la memoria a la que hacen referencia los campos en pglob. Podría haberse obtenido de malloc() en un gran bloque y luego dividirse dentro de glob(), o podría haberse creado usando un asignador de memoria diferente. No es la intención de los desarrolladores del estándar especificar o implicar cómo se gestiona la memoria usada por glob(

).

La bandera GLOB_APPEND se usaría cuando

una aplicación quiere expandir vario
s patrones diferentes en una sola lista.
