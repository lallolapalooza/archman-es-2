DESCRIPCIÓ

N

La función gl_get_line() es parte de la biblioteca tecla (véase la página man libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactivas, similares a las de la shell unix tcsh. Además de la edición simple de línea de comandos, admite el recuerdo de líneas de comandos introducidas previamente, la completación con TAB de nombres de archivos y la expansión de comodines en línea de nombres de archivos. La documentación tanto de las características de edición de línea de comandos a nivel de usuario como de todas las opciones de configuración del usuario se puede encontrar en la página man tecla(7). EJEMPLO

Lo siguiente muestra un ejemplo completo de cómo usar la función gl_get_line() para obtener entrada del

usuario: 
  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que el usuario escribió */
    GetLine *gl;   /* El objeto recurso gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* del juego de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("You typed: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
}

En el ejemplo, primero los recursos necesarios por la función gl_get_line() son creados llamando a new_GetLine(). Esto asigna la memoria usada en llamadas subsecuentes a la función gl_get_line(), incluyendo el búfer de historial para registrar líneas introducidas previamente. Luego se leen una o más líneas del usuario, hasta que ocurra un error, o el usuario escriba exit. Finalmente, los recursos que fueron asignados por new_GetLine() son devueltos al sistema llamando a del_GetLine(). Nótese el uso del valor de retorno NULL de del_GetLine() para hacer gl NULL. Esta es una precaución de seguridad. Si el programa posteriormente intenta pasar gl

a

gl_get_line(), dicha función se quejará y devolverá un error, en lugar de intentar usar el objeto recurso

eliminado.

La función gl_get_line() puede ser llamada cualquier número de veces para leer entrada del usuario. El argumento gl debe haber sido previamente devuelto por una llamada a new_GetLine(). El argumento prompt debe ser una cadena normal terminada en NUL, especificando el prompt a presentar al usuario. Por defecto los prompts se muestran literalmente, pero si se habilitan con la función gl_prompt_style() (véase más adelante), los prompts pueden contener directivas para subrayar, cambiar a y de fuentes en negrita, o activar y desactivar el

Luego puede especificar qué carácter de esta línea es donde el cursor está inicialmente posicionadoposicionado sobre, usando el argumento start_pos. Este debe ser -1 si desea que el cursor siga al último carácter de la línea de inicio. Si no desea precargar la línea de esta manera, envíe start_line como NULL, y establezca start_pos a -1. Tenga en cuenta que el puntero a la línea devuelto por una llamada a gl_get_line() puede pasarse a la siguiente llamada a gl_get_line() a través de start_line. Esto permite que la aplicación tome la última línea introducida y, si contiene un error, la presente de nuevo al usuario para su reedición, con el cursor inicialmente posicionado donde se encontró el

error.

La función gl_get_line() devuelve un puntero a la línea introducida por el usuario, o NULL en caso de error o al final de la entrada. El puntero devuelto es parte del objeto recurso gl especificado y, por lo tanto, no debe ser liberado por el llamante, ni asumirse que es inmutable de una llamada a la siguiente. Al leer de un usuario en una terminal, siempre habrá un carácter de nueva línea al final de la línea devuelta. Cuando la entrada estándar proviene de una tubería o de un archivo, de manera similar habrá una nueva línea a menos que la línea de entrada fuera demasiado larga para almacenarse en el búfer interno. En este último caso, debe llamar a gl_get_line() de nuevo para leer el resto de la línea. Tenga en cuenta que este comportamiento hace que gl_get_line() sea similar a fgets(). De hecho, cuando stdin no está conectado a una terminal,gl_get_line() simplemente llama a fget

s(

FUENTES DE CONFIGURACIÓN

ALTERNATIVAS

Como se mencionó anteriormente, de forma predeterminada los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. En algunas aplicaciones, sin embargo, este único medio de configuración es un problema. Esto es particularmente cierto del software embebido, donde no hay un sistema de archivos del cual leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de asignaciones de teclas para emular una interfaz de teclado heredada. Para atender a tales casos, la siguiente función permite a la aplicación controlar de dónde se leen la información de

configuración. 
  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file)
;

Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc de un usuario, se lean de cualquiera o ninguno de: una cadena, un archivo de configuración específico de la aplicación y/o un archivo de configuración específico del usuario. Si esta función se llama antes de la primera llamada a gl_get_line(), el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line() se deshabilita, por lo que toda la configuración debe lograrse utilizando las fuentes de configuración especificadas con esta

función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados entre sí en la cadena por caracteres de nueva línea incrustados. Si app_file != NULL entonces se interpreta como el nombre de ruta completo de un archivo de configuración específico de la aplicación. Si user_file != NULL entonces se interpreta como el nombre de ruta completo de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente

llamada, 
  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc")
;

el argumento app_string hace que la aplicación que llama comience en el modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso de la campana de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración de todo el sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario desde un archivo .teclarc opcional en el directorio de inicio del usuario. Tenga en cuenta que los argumentos se listan en orden ascendente de prioridad, con el contenido de app_string siendo potencialmente anulado por comandos en app_file, y los comandos en app_file siendo potencialmente anulados por comandos en user_file

PERSONALIZADO Si en su aplicación desea que el completado con TAB complete otras cosas además de o en lugar de nombres de archivo, puede organizarlo registrando una función de retorno de completado alternativa, mediante una llamada a la función gl_customize_completion().

Podría, por ejemplo, apuntar a la tabla de símbolos de la que se deben buscar los posibles completados. El argumento match_fn especifica la función de retorno a llamar. El tipo de función CplMatchFn está definido en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y establecer prototipos de funciones de retorno. la

entrada.

SEÑALES

Por defecto, la función gl_get_line() intercepta un número de señales. Esto es particularmente importante para señales que por defecto terminarían el proceso, ya que el terminal necesita ser restaurado a un estado utilizable antes de que esto suceda. En esta sección, se describen las señales que son atrapadas por defecto, y cómo gl_get_line() responde a ellas. Cambiar estos valores por defecto es el tema de la siguiente

sección.

Cuando se captura el siguiente subconjunto de señales, gl_get_line() primero restaura la configuración del terminal y el manejo de señales a como estaban antes de que se llamara a gl_get_line(), reenvía la señal, para permitir que los manejadores de señal de la aplicación llamante la manejen, luego si el proceso todavía existe, gl_get_line() devuelve NULL y establece errno como se especifica a

continuación. 
 SIGINT  -  Esta señal es generada tanto por la tecla de
            interrupción del teclado (usualmente ^C), como por la tecla de
            pausa del teclado.
            errno=EINTR
 SIGHUP  -  Esta señal es generada cuando el terminal de
            control sale.
            errno=ENOTTY
 SIGPIPE -  Esta señal es generada cuando un programa intenta
            escribir en una tubería cuyo extremo remoto no está siendo
            leído por ningún proceso. Esto puede suceder, por ejemplo,
            si ha llamado a gl_change_terminal() para
            redirigir la salida a una tubería oculta bajo un seudoterminal.
            errno=EPIPE
 SIGQUIT -  Esta señal es generada por la tecla de salida del
            teclado (usualmente ^\).
            errno=EINTR
 SIGABRT -  Esta señal es generada por la función estándar de C,
            abort(). Por defecto, tanto termina el proceso como genera un
            volcado de memoria (core dump).
            errno=EINTR
 SIGTERM -  Esta es la señal por defecto que el comando kill de UN*X
            envía a los procesos.
errno=EINTR

Tenga en cuenta que en el caso de todas las señales anteriores, POSIX manda que por defecto el proceso sea terminado, con la adición de un volcado de memoria en el caso de la señal SIGQUIT. En otras palabras, si la aplicación llamante no anula el manejador por defecto proporcionando su propio manejador de señal, la recepción de la señal correspondiente terminará la aplicación antes de que gl_get_line()

regrese.

Si gl_get_line() aborta con errno establecido a EINTR, puede averiguar qué señal causó que abortara, llamando a la siguiente

función. 
  int gl_last_signal(const GetLine *gl)
;

Esto devuelve el código numérico (por ejemplo, SIGINT) de la última señal que fue recibida durante la llamada más reciente a gl_get_line(), o -1 si no se recibieron

señales.

En sistemas que lo soportan, cuando se recibe una señal SIGWINCH (cambio de ventana), gl_get_line() consulta al terminal para averiguar su nuevo tamaño, redibuja la línea de entrada actual para acomodar el nuevo tamaño, luego regresa a esperar entrada de teclado del usuario. A diferencia de otras señales, esta señal no es reenviada a la

aplicación.

Finalmente, las siguientes señales causan que gl_get_line() primero restaure el terminal y el entorno de señales al que prevalecía antes de que se llamara a gl_get_line(), luego reenvíe la señal a la aplicación. Si el proceso todavía existe después de que la señal ha sido entregada, entonces gl_get_line() luego restablece sus propios manejadores de señal, cambia el terminal de vuelta a modo crudo, redisplaya la línea de entrada, y vuelve a esperar entrada de terminal del

usuario. 
 SIGCONT    -  Esta señal es generada cuando un proceso suspendido
               es reanudado.
 SIGPOLL    -  En sistemas SVR4, esta señal notifica al
               proceso de un evento de E/S asíncrona. Tenga en
               cuenta que bajo 4.3+BSD, SIGIO y SIGPOLL son
               lo mismo. En otros sistemas, SIGIO es ignorado
               por defecto, así que gl_get_line() no lo
               atrapa por defecto.
 SIGPWR     -  Esta señal es generada cuando ocurre una falla
               de energía (presumiblemente cuando el sistema está en
               un UPS).
 SIGALRM    -  Esta señal es generada cuando un temporizador
               expira.
 SIGUSR1    -  Una señal específica de la aplicación.
 SIGUSR2    -  Otra señal específica de la aplicación.
 SIGVTALRM  -  Esta señal es generada cuando un temporizador
               virtual expira (vea man setitimer(2)).
 SIGXCPU    -  Esta señal es generada cuando un proceso
               excede su límite suave de tiempo de CPU.
 SIGXFSZ    -  Esta señal es generada cuando un proceso
               excede su límite suave de tamaño de archivo.
 SIGTSTP    -  Esta señal es generada por la tecla de
               suspensión del terminal, que usualmente es ^Z, o la
               tecla de suspensión retrasada del terminal, que
               usualmente es ^Y.
 SIGTTIN    -  Esta señal es generada si el programa
               intenta leer del terminal mientras el
               programa se está ejecutando en segundo plano.
 SIGTTOU    -  Esta señal es generada si el programa
               intenta escribir en el terminal mientras
               el programa se está ejecutando en segundo
plano.

Obviamente no todas las señales anteriores son soportadas en todos los sistemas, así que el código para soportarlas es compilado condicionalmente en la biblioteca

tecla.

Tenga en cuenta que si SIGKILL o SIGPOLL, que por definición no pueden ser capturadas, o cualquiera de las señales de excepción generadas por el hardware, tales como SIGSEGV, SIGBUS y SIGFPE, son recibidas y no manejadas mientras gl_get_line() tiene el terminal en modo crudo, el programa será terminado sin que el terminal haya sido restaurado a un estado utilizable. En la práctica, los shells de contro

l de trabajos usualmente restablecen la configuración del terminal cuando un proceso re
nuncia al terminal de control, así que esto solo es un problema con shells más antiguos.

PERSONALIZADO

La sección anterior listó las señales que gl_get_line() atrapa por defecto, y describió cómo responde a ellas. Esta sección describe cómo tanto agregar como remover señales de la lista de señales atrapadas, y cómo especificar cómo gl_get_line() debería responder a una señal

dada.

Si no necesita que gl_get_line() haga algo en respuesta a una señal que normalmente atrapa, puede decirle a gl_get_line() que ignore esa señal llamando a gl_ignore_sig

nal().

;

El argumento signo es el número de la señal (por ejemplo, SIGINT) que usted quiere que sea ignorada. Si la señal especificada no es actualmente una de las que están siendo atrapadas, esta función no hace

nada.

La función gl_trap_signal() le permite tanto agregar una nueva señal a la lista que gl_get_line() atrapa, o modificar cómo responde a una señal que ya

El argumento signo es el número de la señal que desea que se capture. El argumento flags es un conjunto de indicadores que determinan el entorno en el que se invoca el manejador de señales de la aplicación, el argumento after le indica a gl_get_line() qué hacer después de que el manejador de señales de la aplicación regrese, y errno_value le indica a gl_get_line() qué valor asignar a errno si se le ordena

abortar.

El argumento flags es un OR bit a bit de cero o más de los siguientes

enumeradores: 
  GLS_RESTORE_SIG  -  Restaura el entorno de señales del
                      llamador mientras se maneja la
                      señal.
  GLS_RESTORE_TTY  -  Restaura la configuración de la terminal del
                      llamador mientras se maneja la señal.
  GLS_RESTORE_LINE -  Mueve el cursor al inicio de la
                      línea siguiente a la línea de entrada antes
                      de invocar el manejador de señales de la
                      aplicación.
  GLS_REDRAW_LINE  -  Vuelve a dibujar la línea de entrada cuando
                      el manejador de señales de la aplicación
                      regresa.
  GLS_UNBLOCK_SIG  -  Normalmente, si el programa llamador tiene
                      una señal bloqueada (man sigprocmask),
                      gl_get_line() no captura esa

                      que capture la señal y la desbloquee durante
                      la duración de la llamada a
                      gl_get_line().

                      no se reenviará al manejador de señales del
                      programa
llamador.

También se enumeran dos combinaciones de indicadores comúnmente útiles de la siguiente

manera: 
  GLS_RESTORE_ENV   = GLS_RESTORE_SIG | GLS_RESTORE_TTY |
                      GLS_REDRAW_LINE

E

Si su manejador de señales, o el manejador de señales predeterminado del sistema para esta señal, si no lo ha sobrescrito, nunca escribe en la terminal, ni suspende ni termina el programa llamador, entonces puede establecer con seguridad el argumento flags a 0

.

Si su manejador de señales siempre escribe en la terminal, lee de ella, o suspende o termina el programa, debe especificar el argumento flags como GL_SUSPEND_INPUT, de modo

que: 
1. El cursor no quede en medio de la línea de
   entrada.
2. Para que el usuario pueda escribir entrada y sea eco.
3. Para que no necesite terminar cada línea de salida con
   \r\n, en lugar de solo \n
.

La combinación GL_RESTORE_ENV es la misma que GL_SUSPEND_INPUT, excepto que no mueve el cursor, y si su manejador de señales no lee ni escribe nada en la terminal, el usuario no verá ninguna indicación visible de que se capturó una señal. Esto puede ser útil si tiene un manejador de señales que solo ocasionalmente escribe en la terminal, donde usar GL_SUSPEND_LINE haría que la línea de entrada se duplicara innecesariamente cuando no se hubiera escrito nada en la terminal. Dicho manejador de señales, cuando escriba en la terminal, debe asegurarse de iniciar una nueva línea al inicio de su primera escritura, escribiendo una nueva línea antes de regresar. Si la señal llega mientras el usuario está ingresando una línea que solo ocupa una línea de terminal de señal, o si el cursor está en la última línea de terminal de una línea de entrada más larga, esto tendrá el mismo efecto que GL_SUSPEND_INPUT. De lo contrario, comenzará a escribir en una línea que ya contiene parte de la línea de entrada mostrada. Esto no causa ningún daño, pero se ve un poco feo, por lo que la combinación GL_SUSPEND_INPUT es mejor si sabe que siempre va a escribir en la

terminal.

El argumento after, que determina qué hace gl_get_line() después de que el manejador de señales de la aplicación regrese (si regresa), puede tomar cualquiera de los siguientes

valores: 
  GLS_RETURN   - Devuelve la línea de entrada completada, tal como
                 si el usuario hubiera presionado la tecla de
                 retorno.
  GLS_ABORT    - Hace que gl_get_line() aborte. Cuando
                 esto sucede, gl_get_line() devuelve
                 NULL, y una llamada posterior a
                 gl_return_status() devolverá
                 GLR_SIGNAL. Tenga en cuenta que si la
                 aplicación necesita que errno siempre
                 tenga un valor significativo cuando
                 gl_get_line() devuelve NULL,
                 la función de retorno de llamada debe establecer
                 errno apropiadamente.
  GLS_CONTINUE - Reanuda la edición de la línea de
comandos.

El argumento errno_value está destinado a combinarse con la opción GLS_ABORT, indicando a gl_get_line() qué valor asignar a la variable estándar errno antes de devolver NULL al programa llamador. Sin embargo, también puede usarse con la opción GL_RETURN, en caso de que desee tener una forma de distinguir entre una línea de entrada

que se ingresó usando la tecla de retorno y una
que se ingresó por la recepción de una señal.

MANEJO DE SEÑALES

FIABLE

El manejo de señales es sorprendentemente difícil de hacer de manera fiable sin condiciones de carrera. En gl_get_line() se ha tenido mucho cuidado para permitir que las aplicaciones realicen un manejo de señales fiable alrededor de gl_get_line(). Esta sección explica cómo hacer uso de

esto.

Como ejemplo de los problemas que pueden surgir si la aplicación no está escrita correctamente, imagine que su aplicación tiene un manejador de señal SIGINT que establece un indicador global. Ahora suponga que la aplicación prueba este indicador justo antes de invocar gl_get_line(). Si una señal SIGINT resulta recibida en la pequeña ventana de tiempo entre la sentencia que prueba el valor de este indicador y la sentencia que llama a gl_get_line(), entonces gl_get_line() no verá la señal y no será interrumpido. Como resultado, la aplicación no podrá responder a la señal hasta que el usuario termine de ingresar la línea de entrada y gl_get_line() regrese. Dependiendo de la aplicación, esto podría o no ser un desastre, pero al menos confundiría al

usuario.

La forma de evitar tales problemas es hacer lo

siguiente.

1. Si es necesario, use la función gl_trap_signal() para
configurar gl_get_line() para que aborte cuando se capturen
señales

importantes.

2. Configure gl_get_line() de modo que si alguna de las
señales que captura están bloqueadas cuando
se llama a gl_get_line(), se desbloqueen
automáticamente durante los momentos en que gl_get_line() está
esperando E/S. Esto se puede hacer ya sea
por señal, llamando a la
función gl_trap_signal() y especificando el
atributo GLS_UNBLOCK de la señal, o globalmente llamando a la
función gl_catch_bloc

ked(). 
     void gl_catch_blocked(GetLine *gl)
;


Esta función simplemente agrega el atributo GLS_UNBLOCK
a todas las señales que actualmente está configurada para
capturar

.

3. Justo antes de llamar a gl_get_line(), bloquee la entrega
de todas las señales que gl_get_line() está
configurada para capturar. Esto se puede hacer usando la función POSIX
sigprocmask() en conjunto con la
función gl_list_signals()

. 
      int gl_list_signals(GetLine *gl, sigset_t *set)
;


Esta función devuelve el conjunto de señales que actualmente está
configurada para capturar en el argumento set,
que está en la forma requerida por sigprocma

sk().

4. En el ejemplo, ahora se probaría el indicador global que
el manejador de señales establece, sabiendo que ahora no hay
peligro de que este indicador se establezca de nuevo hasta que
gl_get_line() desbloquee sus señales mientras realiza
E/S

.

5. Eventualmente gl_get_line() regresa, ya sea porque
se capturó una señal, ocurrió un error, o el usuario
terminó de ingresar su línea de

entrada.

6. Ahora se verificaría el indicador global de señal de nuevo, y si
está establecido, se respondería a él, y se pondría el indicador a

cero.

7. Use sigprocmask() para desbloquear las señales que fueron
bloqueadas en el paso

3.

La misma técnica se puede usar alrededor de ciertas funciones POSIX conscientes de señales, como sigsetjmp() y sigsuspend(), y en particular, la primera de estas dos funciones se puede usar en conjunto con siglongjmp() para implementar un manejo de señales libre de condiciones de carrera alrededor de otras llamadas al sistema de larga duración. La forma de hacer esto se explica a continuación, mostrando cómo gl_get_line() logra capturar señales de manera fiable alrededor de llamadas a funciones como read() y select() sin condiciones de

carrera.

Lo primero que gl_get_line() hace, siempre que se llama, es usar la función POSIX sigprocmask() para bloquear la entrega de todas las señales que actualmente está configurada para capturar. Esto es redundante si la aplicación ya las ha bloqueado, pero no hace ningún daño. Deshace este paso justo antes de

regresar.

Siempre que gl_get_line() necesite llamar a read() o select() para esperar entrada del usuario, primero llama a la función POSIX sigsetjmp(), asegurándose de especificar un valor distinto de cero para su argumento savesigs. La razón de este último argumento se aclarará en

breve.

Si sigsetjmp() devuelve cero, gl_get_line() luego hace lo

siguiente. 
a. Usa la función POSIX sigaction() para registrar
   un manejador de señales temporal para todas las señales que
   está configurada para capturar. Este manejador de señales hace dos
   cosas.
   1. Registra el número de la señal que fue recibida
      en una variable de ámbito de archivo.
   2. Luego llama a la función POSIX siglongjmp()
      usando el búfer que fue pasado a
      sigsetjmp() como su primer argumento, y
      un valor distinto de cero para su segundo argumento.
   Cuando este manejador de señales está registrado, el miembro sa_mask
   del argumento struct sigaction act de la
   llamada a sigaction() está configurado para contener todas
   las señales que gl_get_line() está capturando. Esto
   asegura que solo una señal será capturada a la vez por
   nuestro manejador de señales, lo que a su vez asegura que múltiples
   instancias de nuestro manejador de señales no se interfieran entre sí.
b. Ahora que el manejador de señales ha sido configurado,
   gl_get_line() desbloquea todas las señales que
   está configurada para capturar.
c. Luego llama a las llamadas al sistema read() o select() para esperar la entrada del teclado.
d. Si esta llamada al sistema regresa (es decir, no se recibe ninguna señal),
   gl_get_line() bloquea la entrega de las señales de
   interés de nuevo.
e. Luego restablece los manejadores de señales que fueron
   desplazados por el que acaba de
instalarse.

Alternativamente, si sigsetjmp() devuelve un valor distinto de cero, esto significaque una de las señales atrapadas fue capturada mientras se ejecutaban los pasos anteriores. Cuando esto sucede, gl_get_line() hace lo siguiente.

Primero,

ten en cuenta que cuando una llamada a siglongjmp() hace que sigsetjmp() retorne, siempre que el argumento savesigs de sigsetjmp() fuera distinto de cero, como se especificó anteriormente, la máscara de proceso de señales se restaura a cómo estaba cuando sigsetjmp() fue llamada. Esta es la diferencia importante entre sigsetjmp() y el antiguo y problemático setjmp(), y es el ingrediente esencial que hace posible evitar condiciones de carrera en el manejo de señales. Debido a esto, se garantiza que todas las señales que bloqueamos antes de llamar a sigsetjmp() estén bloqueadas de nuevo tan pronto como se capture cualquier señal. Las siguientes declaraciones, que se ejecutan a continuación, están por tanto garantizadas de ser ejecutadas sin que se capturen más

señales.

1. Si así lo indican los atributos de configuración de
gl_get_line() de la señal que fue capturada, gl_get_line()
restaura los atributos del terminal a el estado que
tenían cuando gl_get_line() fue llamada. Esto es
particularmente importante para las señales que suspenden o terminan el
proceso, ya que de lo contrario el terminal quedaría en un estado
inutilizable. 2. Luego reinstala los manejadores

de

señales de la aplicación. 3. Luego usa la función de la

biblioteca

estándar de C raise() para reenviar a la aplicación
la señal que fue capturada. 3. A continuación, desbloquea
la entrega de

la

señal que acabamos de enviar. Esto resulta en que la señal que
acabó de ser enviada vía raise(), sea capturada por el manejador
de señales original de la aplicación, que ahora puede
manejarla como considere oportuno. 4. Si el manejador de señales
retorna

(es

decir, no termina el proceso), gl_get_line() bloquea la entrega de la
señal anterior de nuevo. 5. Luego deshace cualquier acción

MOSTRANDO TEXTO DINÁMICAMENTE

Entre llamadas a gl_get_line(), la función gl_display_text() proporciona una forma conveniente de mostrar párrafos de texto, justificados a la izquierda y divididos en una o más líneas de terminal según las restricciones del ancho actual de la terminal. Se pueden encontrar ejemplos del uso de esta función en los programas de demostración, donde se utiliza para mostrar introducciones. En esos ejemplos, también se ilustra el uso avanzado de prefijos, sufijos y líneas de relleno opcionales para dibujar un cuadro alrededor del texto.

  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string);

Si gl no está actualmente conectado a una terminal, por ejemplo, si la salida de un programa que utiliza gl_get_line() se está enviando a otro programa o se está redirigiendo a un archivo, entonces el valor del parámetro def_width se utiliza como el ancho de la terminal.

El argumento indentation especifica el número de caracteres que se utilizarán para indentar cada línea de salida. El argumento fill_char especifica el carácter que se utilizará para realizar esta indentación.

El argumento prefix puede ser NULL, o una cadena que se colocará al principio de cada nueva línea (después de cualquier indentación). De manera similar, el argumento suffix puede ser NULL, o una cadena que se colocará al final de cada línea. El sufijo se coloca justo contra el borde derecho de la terminal, y cualquier espacio entre su primer carácter y la última palabra de esa línea se rellena con el carácter especificado a través del argumento fill_char. Normalmente, el carácter de relleno es un espacio.

El argumento start le dice a gl_display_text() cuántos caracteres ya se han escrito en la línea de la terminal actual, y por lo tanto, le dice el índice de columna de inicio del cursor. Dado que el valor de retorno de gl_display_text() es el índice de columna final del cursor, al pasar el valor de retorno de una llamada al argumento start de la siguiente llamada, se puede componer un párrafo que se divide entre más de una cadena llamando a gl_display_text() para cada porción sucesiva del párrafo. Tenga en cuenta que los caracteres de nueva línea literales son necesarios al final de cada párrafo para forzar el inicio de una nueva línea.

En caso de error, gl_display_text() devuelve -1.

A menos que se indique lo contrario, las funciones de devolución de llamada, como las devoluciones de llamada de finalización de tabulación y las devoluciones de llamada de eventos, no deben llamar a ninguna función de este módulo. Las siguientes funciones, sin embargo, están diseñadas específicamente para ser utilizadas por funciones de devolución de llamada.

Llamar a la función gl_replace_prompt() desde una devolución de llamada le dice a gl_get_line() que muestre un aviso diferente cuando la devolución de llamada regrese. Excepto en el modo de servidor no bloqueante, no tiene ningún efecto si se usa entre llamadas a gl_get_line(). En el modo de servidor no bloqueante (ver la página del manual de gl_io_mode(3), cuando se usa entre dos llamadas a gl_get_line() que operan en la misma línea de entrada, la línea de entrada actual se redibujará con el nuevo aviso en la siguiente llamada a gl_get_line().

JUEGOS DE CARACTERES INTERNACIONALES

Desde la versión 1.4.0 de libtecla, gl_get_line() es 8-bit clean. Esto significa que todos los caracteres de 8 bits que son imprimibles en la configuración regional actual del usuario se muestran ahora textualmente y se incluyen en la línea de entrada devuelta. Suponiendo que el programa que llama contiene correctamente una llamada como la siguiente,

  setlocale(LC_CTYPE, "");

entonces la configuración regional actual está determinada por la primera de las variables de entorno LC_CTYPE, LC_ALL y LANG, que se encuentra que contiene un nombre de configuración regional válido. Si ninguna de estas variables está definida, o si el programa omite llamar a setlocale, entonces se utiliza la configuración regional predeterminada C, que es US 7-bit ASCII. En la mayoría de las plataformas tipo Unix, puede obtener una lista de configuraciones regionales válidas escribiendo el comando:

  locale -a

en el símbolo del sistema. Puede encontrar más documentación sobre cómo el usuario puede utilizar esto para introducir caracteres internacionales en la página del manual de tecla(7).

SEGURIDAD DE HILOS

En un programa multihilo, debe utilizar la versión libtecla_r.a de la biblioteca. Esta utiliza versiones reentrantes de las funciones del sistema, donde estén disponibles. Desafortunadamente, ni terminfo ni termcap fueron diseñados para ser reentrantes, por lo que no puede usar de forma segura las funciones del módulo getline en múltiples hilos (puede usar los módulos separados de expansión de archivos y finalización de palabras en múltiples hilos, consulte las páginas del manual correspondientes para obtener detalles). Sin embargo, debido al uso de funciones reentrantes POSIX para buscar directorios de inicio, etc., es seguro usar este módulo desde un solo hilo de un programa multihilo, siempre que sus otros hilos no utilicen funciones de termcap o terminfo.
