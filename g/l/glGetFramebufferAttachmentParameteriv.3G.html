DESCRIPCIÓ

N

glGetFramebufferAttachmentParameteriv y glGetNamedFramebufferAttachmentParameteriv devuelven parámetros de los adjuntos de un objeto framebuffer

especificado.

Para glGetFramebufferAttachmentParameteriv, el objeto framebuffer es el que está enlazado a target, que debe ser uno de GL_DRAW_FRAMEBUFFER, GL_READ_FRAMEBUFFER o GL_FRAMEBUFFER. GL_FRAMEBUFFER es equivalente a GL_DRAW_FRAMEBUFFER. Los búferes de los framebuffers predeterminados también pueden consultarse si están enlazados a target

.

Para glGetNamedFramebufferAttachmentParameteriv, framebuffer es el nombre del objeto framebuffer. Si framebuffer es cero, se consulta el framebuffer de dibujo

predeterminado.

Si el framebuffer especificado es un objeto framebuffer, attachment debe ser uno de GL_DEPTH_ATTACHMENT, GL_STENCIL_ATTACHMENT GL_DEPTH_STENCIL_ATTACHMENT, o GL_COLOR_ATTACHMENTi, donde i está entre cero y el valor de GL_MAX_COLOR_ATTACHMENTS menos

uno.

Si el framebuffer especificado es un framebuffer predeterminado, target, attachment debe ser uno de GL_FRONT_LEFT, GL_FRONT_RIGHT, GL_BACK_LEFT, GL_BACK_RIGHT, GL_DEPTH o GL_STENCIL, identificando el búfer correspondiente

.

Si attachment es GL_DEPTH_STENCIL_ATTACHMENT, el mismo objeto debe estar enlazado tanto a los puntos de adjunto de profundidad como de estarcido del objeto framebuffer, y se devuelve información sobre ese

objeto.

Tras una devolución exitosa, si pname es GL_FRAMEBUFFER_ATTACHMENT_OBJECT_TYPE, entonces params contendrá uno de GL_NONE, GL_FRAMEBUFFER_DEFAULT, GL_TEXTURE, o GL_RENDERBUFFER, identificando el tipo de objeto que contiene la imagen adjunta. Los demás valores aceptados para pname dependen del tipo de objeto, como se describe a

continuación.

Si el valor de GL_FRAMEBUFFER_ATTACHMENT_OBJECT_TYPE es GL_NONE, entonces o bien no hay ningún framebuffer enlazado a target; o se consulta un framebuffer predeterminado, attachment es GL_DEPTH o GL_STENCIL, y el número de bits de profundidad o de estarcido, respectivamente, es cero. En este caso, consultar pname GL_FRAMEBUFFER_ATTACHMENT_OBJECT_NAME devolverá cero, y todas las demás consultas generarán un

error.

Si el valor de GL_FRAMEBUFFER_ATTACHMENT_OBJECT_TYPE no es GL_NONE, estas consultas se aplican a todos los demás tipos de

framebuffer:
•Si pname es GL_FRAMEBUFFER_ATTACHMENT_RED_SIZE, GL_FRAMEBUFFER_ATTACHMENT_GREEN_SIZE, GL_FRAMEBUFFER_ATTACHMENT_BLUE_SIZE, GL_FRAMEBUFFER_ATTACHMENT_ALPHA_SIZE, GL_FRAMEBUFFER_ATTACHMENT_DEPTH_SIZE o GL_FRAMEBUFFER_ATTACHMENT_STENCIL_SIZE, entonces params contendrá el número de bits en el componente rojo, verde, azul, alfa, de profundidad o de estarcido correspondiente del adjunto especificado. Si el componente solicitado no está presente en el adjunto, o si no se ha especificado almacenamiento de datos o imagen de textura para el adjunto, entonces params contendrá
cero.
•Si pname es GL_FRAMEBUFFER_ATTACHMENT_COMPONENT_TYPE, entonces params contendrá el formato de los componentes del adjunto especificado, uno de GL_FLOAT, GL_INT, GL_UNSIGNED_INT, GL_SIGNED_NORMALIZED, o GL_UNSIGNED_NORMALIZED para componentes de punto flotante, entero con signo, entero sin signo, punto fijo normalizado con signo, o punto fijo normalizado sin signo, respectivamente. Solo los búferes de color pueden tener componentes enteros. Si no se ha especificado almacenamiento de datos o imagen de textura para el adjunto, entonces params contendrá GL_NONE. Esta consulta no se puede realizar para un adjunto combinado de profundidad+estarcido, ya que no tiene un formato
único.
•Si pname es GL_FRAMEBUFFER_ATTACHMENT_COLOR_ENCODING, entonces params contendrá la codificación de los componentes del adjunto especificado, uno de GL_LINEAR o GL_SRGB para componentes lineales o codificados en sRGB, respectivamente. Solo los componentes de búferes de color pueden estar codificados en sRGB; tales componentes se tratan como se describe en la Especificación de OpenGL. Para un framebuffer predeterminado, la codificación de color la determina la implementación. Para objetos framebuffer, los componentes están codificados en sRGB si el formato interno de un adjunto de color es uno de los formatos SRGB renderizables en color. Si el adjunto no es un adjunto de color, o si no se ha especificado almacenamiento de datos o imagen de textura para el adjunto, entonces params contendrá GL_LINEAR
.

ERRORE

S

GL_INVALID_ENUM es generado por glGetFramebufferAttachmentParameteriv si target no es uno de los destinos de framebuffer

aceptados.

GL_INVALID_OPERATION es generado por glGetNamedFramebufferAttachmentParameteriv si framebuffer no es cero o el nombre de un objeto framebuffer

existente.

GL_INVALID_ENUM es generado si pname no es válido para el valor de GL_FRAMEBUFFER_ATTACHMENT_OBJECT_TYPE, como se describe

anteriormente.

GL_INVALID_OPERATION es generado si attachment no es uno de los puntos de adjuntado de framebuffer aceptados, como se describe

arriba.

GL_INVALID_OPERATION se genera si el valor de GL_FRAMEBUFFER_ATTACHMENT_OBJECT_TYPE es GL_NONE y pname no es GL_FRAMEBUFFER_ATTACHMENT_OBJECT_NAME ni GL_FRAMEBUFFER_ATTACHMENT_OBJECT_TYPE

.

GL_INVALID_OPERATION se genera si attachment es GL_DEPTH_STENCIL_ATTACHMENT y hay diferentes objetos vinculados a los puntos de adjuntado de profundidad y de stencil de target

.

GL_INVALID_OPERATION se genera si attachment es GL_DEPTH_STENCIL_ATTACHMENT y pname es GL_FRAMEBUFFER_ATTACHMENT_COMPONENT_TYP

E
.
