NAME

glMapBufferRange, glMapNamedBufferRange - mapea todo o parte del almacén de datos de un objeto de buffer en el espacio de direcciones del cliente

ESPECIFICACIÓN EN C

void *glMapBufferRange(GLenum target, GLintptr offset, GLsizeiptr length, GLbitfield access);

void *glMapNamedBufferRange(GLuint buffer, GLintptr offset, GLsizeiptr length, GLbitfield access);

PARÁMETROS

target

Especifica el destino al que se vincula el objeto de buffer para glMapBufferRange, que debe ser uno de los destinos de vinculación de buffer en la siguiente tabla:
Destino de Vinculación de Buffer Propósito
GL_ARRAY_BUFFER Atributos de vértice
GL_ATOMIC_COUNTER_BUFFER Almacenamiento de contadores atómicos
GL_COPY_READ_BUFFER Fuente de copia de buffer
GL_COPY_WRITE_BUFFER Destino de copia de buffer
GL_DISPATCH_INDIRECT_BUFFER Comandos indirectos de cómputo de dispatch
GL_DRAW_INDIRECT_BUFFER Argumentos de comandos indirectos
GL_ELEMENT_ARRAY_BUFFER Índices de array de vértices
GL_PIXEL_PACK_BUFFER Destino de lectura de píxeles
GL_PIXEL_UNPACK_BUFFER Fuente de datos de textura
GL_QUERY_BUFFER Buffer de resultados de consulta
GL_SHADER_STORAGE_BUFFER Almacenamiento de lectura/escritura para shaders
GL_TEXTURE_BUFFER Buffer de datos de textura
GL_TRANSFORM_FEEDBACK_BUFFER Buffer de feedback de transformación
GL_UNIFORM_BUFFER Almacenamiento de bloques uniformes

buffer

Especifica el nombre del objeto de buffer para glMapNamedBufferRange.

offset

Especifica el desplazamiento inicial dentro del buffer del rango a mapear.

length

Especifica la longitud del rango a mapear.

access

Especifica una combinación de flags de acceso que indican el acceso deseado al rango mapeado.

DESCRIPCIÓN

glMapBufferRange y glMapNamedBufferRange mapean todo o parte del almacén de datos de un objeto de buffer especificado en el espacio de direcciones del cliente. offset y length indican el rango de datos en el objeto de buffer que se va a mapear, en términos de unidades básicas de máquina. access es un campo de bits que contiene flags que describen el mapeo solicitado. Estos flags se describen a continuación.

Se devuelve un puntero al inicio del rango mapeado una vez que todas las operaciones pendientes en el objeto de buffer han finalizado, y puede utilizarse para modificar y/o consultar el rango correspondiente del almacén de datos de acuerdo con los siguientes bits de flag establecidos en access:

•GL_MAP_READ_BIT indica que el puntero devuelto puede usarse para leer datos del objeto de buffer. No se genera ningún error de GL si el puntero se utiliza para consultar un mapeo que excluye este flag, pero el resultado no está definido y pueden ocurrir errores del sistema (posiblemente incluyendo la terminación del programa).
•GL_MAP_WRITE_BIT indica que el puntero devuelto puede usarse para modificar datos del objeto de buffer. No se genera ningún error de GL si el puntero se utiliza para modificar un mapeo que excluye este flag, pero el resultado no está definido y pueden ocurrir errores del sistema (posiblemente incluyendo la terminación del programa).
•GL_MAP_PERSISTENT_BIT indica que el mapeo se realizará de forma persistente y que el cliente pretende mantener y utilizar el puntero devuelto durante operaciones posteriores de GL. No es un error llamar a comandos de dibujo (renderizar) mientras los buffers están mapeados usando este flag. Es un error especificar este flag si el almacén de datos del buffer no fue asignado a través de una llamada al comando glBufferStorage() en el que también se estableció el GL_MAP_PERSISTENT_BIT.
•GL_MAP_COHERENT_BIT indica que un mapeo persistente también será coherente. Los mapeos coherentes garantizan que los efectos de las escrituras en el almacén de datos de un buffer por parte del cliente o del servidor se harán visibles para el otro sin intervención adicional de la aplicación. En ausencia de este bit, los mapeos persistentes no son coherentes y los rangos modificados del almacén de buffer deben comunicarse explícitamente al GL, ya sea desmapeando el buffer o mediante una llamada a glFlushMappedBufferRange() o glMemoryBarrier().

Los siguientes bits de flag *opcionales* en access pueden usarse para modificar el mapeo:

•GL_MAP_INVALIDATE_RANGE_BIT indica que el contenido anterior del rango especificado puede ser descartado. Los datos dentro de este rango no están definidos con la excepción de los datos escritos posteriormente. No se genera ningún error de GL si las operaciones de GL posteriores acceden a datos no escritos, pero el resultado no está definido y pueden ocurrir errores del sistema (posiblemente incluyendo la terminación del programa). Este flag no puede usarse en combinación con GL_MAP_READ_BIT.
•GL_MAP_INVALIDATE_BUFFER_BIT indica que el contenido anterior de todo el buffer puede ser descartado. Los datos dentro de todo el buffer no están definidos con la excepción de los datos escritos posteriormente. No se genera ningún error de GL si las operaciones de GL posteriores acceden a datos no escritos, pero el resultado no está definido y pueden ocurrir errores del sistema (posiblemente incluyendo la terminación del programa). Este flag no puede usarse en combinación con GL_MAP_READ_BIT.
•GL_MAP_FLUSH_EXPLICIT_BIT indica que uno o más subrangos discretos del mapeo pueden ser modificados. Cuando este flag está establecido, las modificaciones en cada subrango deben ser vaciadas explícitamente llamando a glFlushMappedBufferRange(). No se establece ningún error de GL si un subrango del mapeo se modifica y no se vacía, pero los datos dentro del subrango correspondiente del buffer no están definidos. Este flag solo puede usarse en conjunción con GL_MAP_WRITE_BIT. Cuando se selecciona esta opción, el vaciado se limita estrictamente a las regiones que se indican explícitamente con llamadas a glFlushMappedBufferRange() antes de desmapear; si esta opción no se selecciona, glUnmapBuffer() vaciará automáticamente todo el rango mapeado cuando se llame.
•GL_MAP_UNSYNCHRONIZED_BIT indica que el GL no debe intentar sincronizar las operaciones pendientes en el buffer antes de devolver el resultado de glMapBufferRange o glMapNamedBufferRange. No se genera ningún error de GL si las operaciones pendientes que obtienen o modifican el buffer se superponen con la región mapeada, pero el resultado de tales operaciones anteriores y posteriores no está definido.

Si ocurre un error, se devuelve un puntero NULL.

Si no ocurre ningún error, el puntero devuelto reflejará una asignación alineada al valor de GL_MIN_MAP_BUFFER_ALIGNMENT unidades básicas de máquina. Restar offset de este puntero devuelto siempre producirá un múltiplo del valor de GL_MIN_MAP_BUFFER_ALIGNMENT.

Los valores de puntero devueltos no pueden pasarse como valores de parámetro a comandos de GL. Por ejemplo, no pueden usarse para especificar punteros de array, ni para especificar o consultar datos de píxeles o imágenes de textura; tales acciones producen resultados indefinidos, aunque las implementaciones pueden no comprobar este comportamiento por razones de rendimiento.

Los mapeos a los almacenes de datos de objetos de buffer pueden tener características de rendimiento no estándar. Por ejemplo, dichos mapeos pueden marcarse como regiones de memoria no cacheadas y, en tales casos, leer de ellas puede ser muy lento. Para garantizar un rendimiento óptimo, el cliente debe utilizar el mapeo de una manera coherente con los valores de GL_BUFFER_USAGE para el objeto de buffer y de access. Utilizar un mapeo de una manera inconsistente con estos valores es probable que sea múltiples órdenes de magnitud más lento que utilizar memoria normal.

NOTAS

La alineación del puntero devuelto solo está garantizada si la versión de la versión de GL es 4.2 o superior. Además, el destino GL_ATOMIC_COUNTER_BUFFER se acepta solo si la versión de GL es 4.2 o superior.

ERRORES

GL_INVALID_ENUM es generado por glMapBufferRange si target no es uno de los objetivos de enlace de búfer listados arriba.

GL_INVALID_OPERATION es generado por glMapBufferRange si cero está enlazado a target.

GL_INVALID_OPERATION es generado por glMapNamedBufferRange si buffer no es el nombre de un objeto búfer existente.

GL_INVALID_VALUE es generado si offset o length es negativo, si $offset + length$ es mayor que el valor de GL_BUFFER_SIZE para el objeto búfer, o si access tiene algún bit establecido distinto de los definidos arriba.

GL_INVALID_OPERATION es generado para cualquiera de las siguientes condiciones:

•length es cero.
•El objeto búfer ya está en estado mapeado.
•Ni GL_MAP_READ_BIT ni GL_MAP_WRITE_BIT están establecidos.
•GL_MAP_READ_BIT está establecido y cualquiera de GL_MAP_INVALIDATE_RANGE_BIT, GL_MAP_INVALIDATE_BUFFER_BIT o GL_MAP_UNSYNCHRONIZED_BIT está establecido.
•GL_MAP_FLUSH_EXPLICIT_BIT está establecido y GL_MAP_WRITE_BIT no está establecido.
•Cualquiera de GL_MAP_READ_BIT, GL_MAP_WRITE_BIT, GL_MAP_PERSISTENT_BIT, o GL_MAP_COHERENT_BIT están establecidos, pero el mismo bit no está incluido en los indicadores de almacenamiento del búfer.

No se genera ningún error si se modifica o consulta memoria fuera del rango mapeado, pero el resultado es indefinido y pueden ocurrir errores del sistema (posiblemente incluyendo la terminación del programa).

OBTENCIONES ASOCIADAS

glGet() con pname GL_MIN_MAP_BUFFER_ALIGNMENT. El valor debe ser una potencia de dos que sea al menos 64.
