NOMBRE

glGetTexImage, glGetnTexImage, glGetTextureImage - devuelven una imagen de textura

ESPECIFICACIÓN EN C

void glGetTexImage(GLenumtarget, GLintlevel, GLenumformat, GLenumtype, void *pixels);

void glGetnTexImage(GLenumtarget, GLintlevel, GLenumformat, GLenumtype, GLsizeibufSize, void *pixels);

void glGetTextureImage(GLuinttexture, GLintlevel, GLenumformat, GLenumtype, GLsizeibufSize, void *pixels);

PARÁMETROS

target

Especifica el objetivo al que está enlazada la textura para glGetTexImage y glGetnTexImage funciones. GL_TEXTURE_1D, GL_TEXTURE_2D, GL_TEXTURE_3D, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_2D_ARRAY, GL_TEXTURE_RECTANGLE, GL_TEXTURE_CUBE_MAP_POSITIVE_X, GL_TEXTURE_CUBE_MAP_NEGATIVE_X, GL_TEXTURE_CUBE_MAP_POSITIVE_Y, GL_TEXTURE_CUBE_MAP_NEGATIVE_Y, GL_TEXTURE_CUBE_MAP_POSITIVE_Z, GL_TEXTURE_CUBE_MAP_NEGATIVE_Z, y GL_TEXTURE_CUBE_MAP_ARRAY son valores aceptables.

texture

Especifica el nombre del objeto de textura.

level

Especifica el número de nivel de detalle de la imagen deseada. El nivel 0 es el nivel de la imagen base. El nivel n es la imagen de reducción de mipmap n.

format

Especifica un formato de píxel para los datos devueltos. Los formatos admitidos son GL_STENCIL_INDEX, GL_DEPTH_COMPONENT, GL_DEPTH_STENCIL, GL_RED, GL_GREEN, GL_BLUE, GL_RG, GL_RGB, GL_RGBA, GL_BGR, GL_BGRA, GL_RED_INTEGER, GL_GREEN_INTEGER, GL_BLUE_INTEGER, GL_RG_INTEGER, GL_RGB_INTEGER, GL_RGBA_INTEGER, GL_BGR_INTEGER, GL_BGRA_INTEGER.

type

Especifica un tipo de píxel para los datos devueltos. Los tipos admitidos son GL_UNSIGNED_BYTE, GL_BYTE, GL_UNSIGNED_SHORT, GL_SHORT, GL_UNSIGNED_INT, GL_INT, GL_HALF_FLOAT, GL_FLOAT, GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, GL_UNSIGNED_SHORT_5_6_5_REV, GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, GL_UNSIGNED_INT_2_10_10_10_REV, GL_UNSIGNED_INT_24_8, GL_UNSIGNED_INT_10F_11F_11F_REV, GL_UNSIGNED_INT_5_9_9_9_REV, y GL_FLOAT_32_UNSIGNED_INT_24_8_REV.

bufSize

Especifica el tamaño del búfer pixels para glGetnTexImage y glGetTextureImage funciones.

pixels

Devuelve la imagen de textura. Debe ser un puntero a un array del tipo especificado por type.

DESCRIPCIÓN

glGetTexImage, glGetnTexImage y glGetTextureImage funciones devuelven una imagen de textura en pixels. Para glGetTexImage y glGetnTexImage, target especifica si la imagen de textura deseada es la especificada por glTexImage1D() (GL_TEXTURE_1D), glTexImage2D() (GL_TEXTURE_1D_ARRAY, GL_TEXTURE_RECTANGLE, GL_TEXTURE_2D o cualquiera de GL_TEXTURE_CUBE_MAP_*), o glTexImage3D() (GL_TEXTURE_2D_ARRAY, GL_TEXTURE_3D, GL_TEXTURE_CUBE_MAP_ARRAY). Para glGetTextureImage, texture especifica el nombre del objeto de textura. Además de los tipos de texturas aceptados por glGetTexImage y glGetnTexImage, la función también acepta objetos de textura de mapa cúbico (con el objetivo efectivo GL_TEXTURE_CUBE_MAP). level especifica el número de nivel de detalle de la imagen deseada. format y type especifican el formato y el tipo del array de imagen deseado. Consulte la página de referencia de glTexImage1D() para una descripción de los valores aceptables para los parámetros format y type respectivamente. Para las funciones glGetnTexImage y glGetTextureImage, bufSize indica el tamaño del búfer para recibir los datos de píxeles recuperados. glGetnTexImage y glGetTextureImage no escriben más de bufSize bytes en pixels.

Si un objeto de búfer con nombre distinto de cero está enlazado al objetivo GL_PIXEL_PACK_BUFFER (ver glBindBuffer()) mientras se solicita una imagen de textura, pixels se trata como un desplazamiento de byte dentro del almacén de datos del objeto de búfer.

Para comprender el funcionamiento de glGetTexImage, considere la imagen de textura interna seleccionada de cuatro componentes como un búfer de color RGBA del tamaño de la imagen. La semántica de glGetTexImage es entonces idéntica a la de glReadPixels(), con la excepción de que no se realizan operaciones de transferencia de píxeles, cuando se llama con el mismo format y type, con x y y establecidos en 0, width establecido en el ancho de la imagen de textura y height establecido en 1 para imágenes 1D, o en la altura de la imagen de textura para imágenes 2D.

Si la imagen de textura seleccionada no contiene cuatro componentes, se aplican las siguientes correspondencias. Las texturas de un solo componente se tratan como búferes RGBA con el rojo establecido en el valor del componente único, el verde en 0, el azul en 0 y el alfa en 1. Las texturas de dos componentes se tratan como búferes RGBA con el rojo establecido en el valor del componente cero, el alfa en el valor del componente uno, y el verde y el azul en 0. Finalmente, las texturas de tres componentes se tratan como búferes RGBA con el rojo establecido en el componente cero, el verde en el componente uno, el azul en el componente dos y el alfa en 1.

Para determinar el tamaño requerido de pixels, use glGetTexLevelParameter() para determinar las dimensiones de la imagen de textura interna, luego escale el número requerido de píxeles por el almacenamiento requerido para cada píxel, basado en format y type. Asegúrese de tener en cuenta los parámetros de almacenamiento de píxeles, especialmente GL_PACK_ALIGNMENT.

Si glGetTextureImage se usa con un objeto de textura de mapa cúbico, la textura se trata como una imagen tridimensional de una profundidad de 6, donde las caras del mapa cúbico se ordenan como capas de imagen, en un orden presentado en la tabla siguiente:

Número de capa Cara del mapa cúbico
0 GL_TEXTURE_CUBE_MAP_POSITIVE_X
1 GL_TEXTURE_CUBE_MAP_NEGATIVE_X
2 GL_TEXTURE_CUBE_MAP_POSITIVE_Y
3 GL_TEXTURE_CUBE_MAP_NEGATIVE_Y
4 GL_TEXTURE_CUBE_MAP_POSITIVE_Z
5 GL_TEXTURE_CUBE_MAP_NEGATIVE_Z

NOTAS

Si se genera un error, no se realiza ningún cambio en el contenido de pixels.

glGetTexImage y glGetnTexImage devuelven la imagen de textura para la unidad de textura activa.

GL_STENCIL_INDEX se acepta para format solo si la versión de GL es 4.4 o superior.

ERRORES

GL_INVALID_ENUM es generado por glGetTexImage y glGetnTexImage funciones si target no es un valor aceptado. Estos incluyen:

•GL_TEXTURE_1D, GL_TEXTURE_2D, GL_TEXTURE_3D, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_2D_ARRAY, GL_TEXTURE_CUBE_MAP_ARRAY, GL_TEXTURE_RECTANGLE, GL_TEXTURE_CUBE_MAP_POSITIVE_X, GL_TEXTURE_CUBE_MAP_NEGATIVE_X, GL_TEXTURE_CUBE_MAP_POSITIVE_Y, GL_TEXTURE_CUBE_MAP_NEGATIVE_Y, GL_TEXTURE_CUBE_MAP_POSITIVE_Z, y GL_TEXTURE_CUBE_MAP_NEGATIVE_Z para glGetTexImage y glGetnTexImage funciones.
•GL_TEXTURE_1D, GL_TEXTURE_2D, GL_TEXTURE_3D, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_2D_ARRAY, GL_TEXTURE_CUBE_MAP_ARRAY, GL_TEXTURE_RECTANGLE, y GL_TEXTURE_CUBE_

MAPA

Para la función glGetTextureImage.

GL_INVALID_OPERATION se genera si texture no es el nombre de un objeto de textura existente.

GL_INVALID_ENUM se genera si format o type no son valores aceptados.

GL_INVALID_VALUE se genera si level es menor que 0.

GL_INVALID_VALUE puede generarse si level es mayor que log 2 de max, donde max es el valor devuelto por GL_MAX_TEXTURE_SIZE.

GL_INVALID_VALUE se genera si level no es cero y el objetivo efectivo es GL_TEXTURE_RECTANGLE.

GL_INVALID_OPERATION se genera si type es uno de GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, GL_UNSIGNED_SHORT_5_6_5_REV, o GL_UNSIGNED_INT_10F_11F_11F_REV y format no es GL_RGB.

GL_INVALID_OPERATION se genera si type es uno de GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, GL_UNSIGNED_INT_2_10_10_10_REV, o GL_UNSIGNED_INT_5_9_9_9_REV y format no es ni GL_RGBA ni GL_BGRA.

GL_INVALID_OPERATION se genera si format es GL_STENCIL_INDEX y el formato interno base no es GL_STENCIL_INDEX ni GL_DEPTH_STENCIL.

GL_INVALID_OPERATION se genera si un nombre de objeto de buffer no nulo está enlazado al objetivo GL_PIXEL_PACK_BUFFER y el almacén de datos del objeto de buffer está actualmente mapeado.

GL_INVALID_OPERATION se genera si un nombre de objeto de buffer no nulo está enlazado al objetivo GL_PIXEL_PACK_BUFFER y los datos se empaquetarían en el objeto de buffer de tal manera que las escrituras de memoria requeridas excederían el tamaño del almacén de datos.

GL_INVALID_OPERATION se genera si un nombre de objeto de buffer no nulo está enlazado al objetivo GL_PIXEL_PACK_BUFFER y pixels no es divisible exactamente por el número de bytes necesarios para almacenar en memoria un dato indicado por type.

GL_INVALID_OPERATION se genera por glGetTextureImage y glGetnTexImage si el tamaño del buffer requerido para almacenar los datos solicitados es mayor que bufSize.
