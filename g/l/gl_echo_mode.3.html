DESCRIPCIÓN

La función gl_get_line() forma parte de la biblioteca tecla (ver la página del manual de libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le pide una línea de entrada, luego proporciona facilidades de edición interactivas, similares a las del shell tcsh de Unix. Además de la edición simple de la línea de comandos, admite la recuperación de líneas de comandos introducidas previamente, la autocompletación con TAB de nombres de archivo y la expansión de comodines en línea de nombres de archivo. La documentación tanto de las características de edición de línea de comandos a nivel de usuario como de todas las opciones de configuración del usuario, se puede encontrar en la página del manual de tecla(7). Esta página del manual se centra en la documentación para programadores interesados en usar esta biblioteca en su aplicación.

UN EJEMPLO

Lo siguiente muestra un ejemplo completo de cómo usar la función gl_get_line() para obtener entrada del usuario:

  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que escribió el usuario */
    GetLine *gl;   /* El objeto de recursos de gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* de conjunto de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("Escribiste: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
  }

En el ejemplo, primero se crean los recursos necesarios para la función gl_get_line() llamando a new_GetLine(). Esto asigna la memoria utilizada en llamadas posteriores a la función gl_get_line(), incluido el búfer de historial para registrar líneas introducidas previamente. Luego se leen una o más líneas del usuario, hasta que ocurra un error o el usuario escriba exit. Luego, finalmente, los recursos que fueron asignados por new_GetLine() se devuelven al sistema llamando a del_GetLine(). Tenga en cuenta el uso del valor de retorno NULL de del_GetLine() para hacer que gl sea NULL. Esta es una precaución de seguridad. Si el programa intenta posteriormente pasar gl a gl_get_line(), dicha función se quejará y devolverá un error, en lugar de intentar usar el objeto de recurso eliminado.

LAS FUNCIONES UTILIZADAS EN EL EJEMPLO

Las descripciones de las funciones utilizadas en el ejemplo son las siguientes:

  GetLine *new_GetLine(size_t linelen, size_t histlen)

Esta función crea los recursos utilizados por la función gl_get_line() y devuelve un puntero opaco al objeto que los contiene. La longitud máxima de una línea de entrada se especifica a través del argumento linelen, y el número de bytes a asignar para almacenar líneas de historial se establece mediante el argumento histlen. Las líneas de historial se almacenan una detrás de otra en un único búfer de este tamaño. Tenga en cuenta que esto significa que el número de líneas de historial que se pueden almacenar en cualquier momento depende de las longitudes de las líneas individuales. Si desea establecer un límite superior en el número de líneas que se pueden almacenar, consulte la función gl_limit_history() descrita a continuación. Si no desea historial en absoluto, especifique histlen como cero, y no se asignará ningún búfer de historial.

En caso de error, se imprime un mensaje en stderr y se devuelve NULL.

  GetLine *del_GetLine(GetLine *gl)

Esta función elimina los recursos que fueron devueltos por una llamada anterior a new_GetLine(). Siempre devuelve NULL (es decir, un objeto eliminado). No hace nada si el argumento gl es NULL.

  char *gl_get_line(GetLine *gl, const char *prompt,
                   const char *start_line, int start_pos);

La función gl_get_line() se puede llamar cualquier número de veces para leer la entrada del usuario. El argumento gl debe haber sido devuelto previamente por una llamada a new_GetLine(). El argumento prompt debe ser una cadena normal terminada en NUL, que especifica el mensaje que se mostrará al usuario. Por defecto, los mensajes se muestran literalmente, pero si se habilitan con la función gl_prompt_style() (ver más adelante), los mensajes pueden contener directivas para hacer subrayados, cambiar a y desde fuentes en negrita, o activar y desactivar el resaltado.

Si desea especificar el contenido inicial de la línea, para que el usuario lo edite, pase la cadena deseada a través del argumento start_line. Luego puede especificar en qué carácter de esta línea se posiciona inicialmente el cursor, ov

COMPLETADO DE PALABRAS PERSONALIZADO

Si en su aplicación desea que la completación con TAB complete otras cosas además de o en lugar de nombres de archivo, puede organizarlo registrando una función de devolución de llamada de completado alternativa, mediante una llamada a la función gl_customize_completion().

  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn);

El argumento data proporciona una forma para que su aplicación pase información arbitraria y específica de la aplicación a la función de devolución de llamada. Esto se pasa a la devolución de llamada cada vez que se llama. Podría, por ejemplo, apuntar a la tabla de símbolos de la que se deben buscar las completaciones posibles. El argumento match_fn especifica la función de devolución de llamada que se llamará. El tipo de función CplMatchFn se define en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y prototipar funciones de devolución de llamada. La declaración y las responsabilidades de las funciones de devolución de llamada se describen en detalle en la página man cpl_complete_word(3).

En resumen, la función de devolución de llamada es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario presionó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar las completaciones posibles de esta palabra y registrarlas una por una en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion(). Si la función de devolución de llamada desea proporcionar completado de nombres de archivo además de sus propias completaciones específicas, tiene la opción de llamar a la función de devolución de llamada incorporada de completado de nombres de archivo. Esto también se documenta en la página man de cpl_complete_word(3).

Tenga en cuenta que si desea que gl_get_line() devuelva la línea de entrada actual cuando se realiza una completación exitosa, puede organizarlo al llamar a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de nueva línea. Si hace esto, la línea de entrada se actualizará para mostrar la completación, junto con cualquier sufijo de continuación hasta el carácter de nueva línea, luego gl_get_line() devolverá esta línea de entrada.

Si, por alguna razón, su función de devolución de llamada necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto iniciará una nueva línea después de la línea de entrada que se está editando actualmente, restablecerá la E/S normal de la terminal y le indicará a gl_get_line() que la línea de entrada deberá redibujarse cuando la devolución de llamada regrese.

AGREGANDO ACCIONES DE COMPLETADO

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de completado predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que diferentes tipos de completado de palabras se puedan enlazar a diferentes secuencias de teclas. Esto se logra utilizando la función gl_completion_action().

  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq);

Los argumentos data y match_fn son como se describe en la página man de cpl_complete_word, y especifican la función de devolución de llamada que se invocará para identificar las completaciones posibles. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar cualquier completación ambigua posible, o si simplemente debe mostrar la lista de completaciones posibles sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre por el cual los archivos de configuración y las invocaciones futuras de esta función deben referirse a la acción. Este debe ser el nombre de una acción de completado existente que se va a cambiar, o un nuevo nombre no utilizado para una nueva acción. Finalmente, el argumento keyseq especifica la secuencia de teclas predeterminada a la que enlazar la acción. Si es NULL, no se enlazará ninguna secuencia de teclas nueva a la acción.

Tenga en cuenta que para que el usuario pueda cambiar la secuencia de teclas que se enlaza a las acciones que se instalan de esta manera, cuando llama a gl_completion_action() para instalar una acción dada por primera vez, debe hacerlo entre la llamada a new_GetLine() y la primera llamada a gl_get_line(). De lo contrario, cuando se lea el archivo de configuración del usuario en la primera llamada a gl_get_line(), no se conocerá el nombre de su acción adicional y cualquier referencia a ella en el archivo de configuración generará un error.

Como se discutió para gl_customize_completion(), si su función de devolución de llamada, por alguna razón, necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo.

DEFINIENDO ACCIONES PERSONALIZADAS

Aunque las acciones de enlace de teclas integradas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, enlazadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza que correspondía a un número de pieza anterior al cursor. Dicha característica está claramente fuera del alcance de las funciones de acción integradas. Por lo tanto, para tales casos especiales, se proporciona la función gl_register_action().

  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq);

Esta función permite a la aplicación registrar una función externa, fn, que en adelante se llamará siempre que el usuario introduzca la secuencia de teclas especificada, keyseq, o el usuario introduzca cualquier otra secuencia de teclas que el usuario enlace posteriormente a la acción especificada, name, en su archivo de configuración. El argumento data puede ser un puntero a cualquier cosa que la aplicación desee pasar a la función de acción, fn, siempre que se invoque esa función.

La función de acción, fn, debe declararse utilizando la siguiente macro, que se define en libtecla.h.

  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char *line)

Los argumentos gl y data son los que se pasaron previamente a gl_register_action() cuando se registró la función de acción. El argumento count es un argumento numérico que el usuario tiene la opción de introducir utilizando la acción digit-argument, antes de invocar la acción. Si el usuario no introduce un número, el argumento count se establece en 1. Nominalmente, este argumento se interpreta como un recuento de repetición, lo que significa que la acción debe repetirse tantas veces. En la práctica, sin embargo, para algunas acciones un recuento de repetición tiene poco sentido. En tales casos, las acciones pueden simplemente ignorar el argumento count o utilizar su valor para un propósito diferente.

Se pasa una copia de la línea de entrada actual en el argumento de solo lectura line. La posición actual del cursor dentro de esta cadena viene dada por el índice contenido en el argumento curpos. Tenga en cuenta que no se permite la manipulación directa de la línea de entrada y la posición del cursor. Esto se debe a que las reglas dictadas por varios modos, como el modo vi frente al modo emacs, el modo sin eco y el modo de inserción frente al modo de sobrescritura, etc., hacen que sea demasiado complejo para un escritor de aplicaciones escribir una acción de edición que cumpla, además de limitar los cambios futuros en los detalles internos de gl_get_line(). Una solución potencial a este dilema sería permitir que la función de acción edite la línea utilizando las acciones de edición existentes. Esto se está considerando actualmente.

Si la función de acción desea escribir texto en la terminal, sin que esto se mezcle con el texto mostrado de la línea de entrada, o leer desde la terminal sin tener que manejar E/S de terminal en modo raw, entonces antes de realizar cualquiera de estas operaciones, debe suspender temporalmente la edición de línea llamando a la función gl_normal_io(). Este último incluye cosas como restaurar el mapeo normal de \n a \r\n y, cuando está en modo servidor, restaurar la forma de bloqueo normal de la E/S de terminal. Después de llamar a esta función, la función de acción puede leer y escribir en la terminal sin temor a crear un desorden. No es necesario que la función de acción restaure el entorno de edición original antes de que regrese. Esto lo hace automáticamente gl_get_line() después de que la función de acción regrese. MANEJO DE SEÑALES

FIABLE

El manejo de señales es sorprendentemente difícil de hacer de forma fiable sin condiciones de carrera. En gl_get_line() se ha tenido mucho cuidado para permitir que las aplicaciones realicen un manejo de señales fiable alrededor de gl_get_line(). Esta sección explica cómo hacer uso de

esto.

Como ejemplo de los problemas que pueden surgir si la aplicación no está escrita correctamente, imagine que su aplicación tiene un manejador de señales SIGINT que establece un indicador global. Ahora suponga que la aplicación prueba este indicador justo antes de invocar gl_get_line(). Si una señal SIGINT resulta recibida en la pequeña ventana de tiempo entre la sentencia que prueba el valor de este indicador y la sentencia que llama a gl_get_line(), entonces gl_get_line() no verá la señal y no será interrumpido. Como resultado, la aplicación no podrá responder a la señal hasta que el usuario termine de ingresar la línea de entrada y gl_get_line() regrese. Dependiendo de la aplicación, esto podría o no ser un desastre, pero al menos confundiría al

usuario.

La forma de evitar tales problemas es hacer lo

siguiente.

1. Si es necesario, use la función gl_trap_signal() para
configurar gl_get_line() para que aborte cuando se capturen
señales

importantes.

2. Configure gl_get_line() de modo que si alguna de las
señales que captura está bloqueada cuando se
llama a gl_get_line(), se desbloqueen
automáticamente durante los momentos en que gl_get_line() está
esperando E/S. Esto se puede hacer ya sea
por señal, llamando a la
función gl_trap_signal() y especificando el
atributo GLS_UNBLOCK de la señal, o globalmente
llamando a la función gl_catch_blocked()

.

;


Esta función simplemente agrega el atributo GLS_UNBLOCK
a todas las señales que actualmente está configurada para
capturar

.

3. Justo antes de llamar a gl_get_line(), bloquee la entrega
de todas las señales que gl_get_line() está
configurada para capturar. Esto se puede hacer usando la función POSIX
sigprocmask() en conjunto con la
función gl_list_signals()

;


Esta función devuelve el conjunto de señales que actualmente está
configurada para capturar en el argumento set,
que está en la forma requerida por sigprocma

sk().

4. En el ejemplo, ahora se probaría el indicador global que
establece el manejador de señales, sabiendo que ahora no hay
peligro de que este indicador se establezca de nuevo hasta que
gl_get_line() desbloquee sus señales mientras realiza
E/S

5. Eventualmente gl_get_line() regresa, ya sea porque
se capturó una señal, ocurrió un error, o el usuario
terminó de ingresar su línea de

entrada.

6. Ahora se verificaría el indicador de señal global de nuevo, y si

7. Use sigprocmask() para desbloquear las señales que fueron

3.

La misma técnica se puede usar alrededor de ciertas funciones POSIX conscientes de señales, como sigsetjmp() y sigsuspend(), y en particular, la primera de estas dos funciones se puede usar en conjunto con siglongjmp() para implementar un manejo de señales libre de condiciones de carrera alrededor de otras llamadas al sistema de larga duración. La forma de hacer esto se explica a continuación, mostrando cómo gl_get_line() logra capturar señales de forma fiable alrededor de llamadas a funciones como read() y select() sin condiciones de

carrera.

Lo primero que gl_get_line() hace, siempre que es llamada, es usar la función POSIX sigprocmask() para bloquear la entrega de todas las señales que actualmente está configurada para capturar. Esto es redundante si la aplicación ya las ha bloqueado, pero no causa ningún daño. Deshace este paso justo antes de

regresar.

Siempre que gl_get_line() necesita llamar a read() o select() para esperar entrada del usuario, primero llama a la función POSIX sigsetjmp(), asegurándose de especificar un valor distinto de cero para su argumento savesigs. La razón de este último argumento se aclarará en

breve.

Si sigsetjmp() devuelve cero, gl_get_line() luego hace lo

siguiente. 
a. Usa la función POSIX sigaction() para registrar
   un manejador de señales temporal para todas las señales que está
   configurada para capturar. Este manejador de señales hace dos cosas.
   1. Registra el número de la señal recibida
      en una variable de ámbito de archivo.
   2. Luego llama a la función POSIX siglongjmp()
      usando el búfer que se pasó a
      sigsetjmp() como su primer argumento, y
      un valor distinto de cero para su segundo argumento.
   Cuando este manejador de señales está registrado, el miembro sa_mask
   del argumento struct sigaction act de la
   llamada a sigaction() está configurado para contener todas
   las señales que gl_get_line() está capturando. Esto
   asegura que solo una señal sea capturada a la vez por
   nuestro manejador de señales, lo que a su vez asegura que múltiples
   instancias de nuestro manejador de señales no interfieran entre sí.
b. Ahora que el manejador de señales ha sido configurado,
   gl_get_line() desbloquea todas las señales que está
   configurada para capturar.
c. Luego llama a las llamadas al sistema read() o select() para esperar entrada del teclado.
d. Si esta llamada al sistema regresa (es decir, no se recibe ninguna señal),
   gl_get_line() bloquea la entrega de las señales de
   interés de nuevo.
e. Luego reinstaura los manejadores de señales que fueron
   desplazados por el que se acaba de
instalar.

siguiente.

Primero, tenga en cuenta que cuando una llamada a siglongjmp() hace que sigsetjmp() retorne, siempre que el argumento savesigs de sigsetjmp() fuera distinto de cero, como se especificó anteriormente, la máscara de proceso de señales se restaura a cómo estaba cuando sigsetjmp() fue llamado. Esta es la diferencia importante entre sigsetjmp() y el problemático setjmp() anterior, y es el ingrediente esencial que hace posible evitar condiciones de carrera en el manejo de señales. Debido a esto, se garantiza que todas las señales que bloqueamos antes de llamar a sigsetjmp() estén bloqueadas de nuevo tan pronto como se capture cualquier señal. señales.

1. Si así lo indica gl_get_line() la configuración
de atributos de la señal que fue capturada,
gl_get_line() restaura los atributos del terminal a

llamado. Esto es particularmente importante para las señales que

inutilizable.

2. Luego reinstaura los manejadores de señales de la

aplicación.

3. Luego usa la función raise()

fue

EL TAMAÑO DEL

TERMINAL

En la mayoría de los sistemas, la combinación de la ioctl TIOCGWINSZ y la señal SIGWINCH se utiliza para mantener una idea precisa del tamaño del terminal. El tamaño del terminal se consulta nuevamente cada vez que gl_get_line() es llamado y siempre que una señal SIGWINCH es

recibida.

En los pocos sistemas donde este mecanismo no está disponible, al inicio new_GetLine() primero busca las variables de entorno LINES y COLUMNS. Si estas no se encuentran, o contienen valores inutilizables, entonces si una base de datos de información del terminal como terminfo o termcap está disponible, el tamaño por defecto del terminal se busca en esta base de datos. Si esto también falla en proporcionar el tamaño del terminal, se usa un tamaño por defecto de 80 columnas por 24

líneas.

Incluso en sistemas que sí soportan ioctl(TIOCGWINSZ), si el terminal está en el otro extremo de una línea serie, el controlador del terminal generalmente no tiene forma de detectar cuándo ocurre un redimensionamiento ni de consultar cuál es el tamaño actual. En tales casos no se envía ningún SIGWINCH al proceso, y las dimensiones devueltas por ioctl(TIOCGWINSZ) no son correctas. La única forma de manejar tales instancias es proporcionar una manera para que el usuario ingrese un comando que le diga al sistema remoto cuál es el nuevo tamaño. Este comando entonces llamaría a la función gl_set_term_size() para informar a gl_get_line() sobre el cambio de

tamaño. 
  int gl_set_term_size(GetLine *gl, int ncolumn, int nline)
;

Los argumentos ncolumn y nline se utilizan para especificar las nuevas dimensiones del terminal, y no deben ser menores que 1. En sistemas que sí soportan ioctl(TIOCGWINSZ), esta función primero llama a ioctl(TIOCSWINSZ) para informar al controlador del terminal sobre el cambio de tamaño. En el modo de E/S de servidor no bloqueante, si una línea está siendo ingresada actualmente, la línea de entrada se redibuja para acomodar el tamaño cambiado. Finalmente, los nuevos valores se registran en gl para uso futuro por gl_get_li

ne().

La función gl_terminal_size() le permite consultar el tamaño actual del terminal, e instalar un tamaño de respaldo alternativo para los casos en que el tamaño no esté disponible. Tenga en cuenta que el tamaño del terminal no estará disponible si se lee de una tubería o de un archivo, por lo que los valores por defecto pueden ser importantes incluso en sistemas que sí soportan formas de averiguar el tamaño del

ESCRIBES

Al ingresar información sensible, como contraseñas, es mejor no tener el texto que estás ingresando reflejado en el terminal. Además, dicho texto no debería ser registrado en la lista de historial, ya que alguien que encuentre tu terminal desatendida podría entonces recuperarlo, o alguien husmeando en tus directorios podría verlo en tu archivo de historial. Teniendo esto en mente, la función gl_echo_mode() te permite alternar la visualización y el archivo de cualquier texto que sea ingresado posteriormente en llamadas a gl_get_li

ne(). 
  int gl_echo_mode(GetLine *gl, int enable)
;

El argumento enable especifica si el texto ingresado debe ser visible o no. Si es 0, entonces las líneas ingresadas posteriormente no serán visibles en el terminal, y no serán registradas en la lista de historial. Si es 1, entonces las líneas de entrada posteriores serán mostradas a medida que se ingresan, y siempre que el historial no haya sido desactivado vía una llamada a gl_toggle_history(), también serán archivadas en la lista de historial. Finalmente, si el argumento enable es -1, entonces el modo de eco se deja sin cambios, lo que te permite consultar de forma no destructiva la configuración actual a través del valor de retorno. En todos los casos, el valor de retorno de la función es 0 si el eco estaba deshabilitado antes de que la función fuera llamada, y 1 si estaba

habilitado.

Cuando el eco está desactivado, ten en cuenta que aunque la finaliza

CONSULTAS DE UN SOLO

CARÁCTER

Usar gl_get_line() para consultar al usuario por una respuesta de un solo carácter es inconveniente para el usuario, ya que debe presionar la tecla intro o retorno antes de que el carácter que escribió sea devuelto al programa. Por lo tanto, la función gl_query_char() ha sido proporcionada para consultas de un solo carácter como

esta. 
  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar)
;

Esta función muestra el prompt especificado al comienzo de una nueva línea, y espera a que el usuario escriba un carácter. Cuando el usuario escribe un carácter, gl_query_char() lo muestra a la derecha del prompt, inicia una nueva línea, y luego devuelve el carácter al programa llamante. El valor de retorno de la función es el carácter que fue escrito. Si la lectura tuvo que ser abortada por alguna razón, se devuelve EOF en su lugar. En el último caso, la aplicación puede llamar a la previamente documentada gl_return_status(), para averiguar qué salió mal. Esto podría, por ejemplo, haber sido la recepción de una señal, o el temporizador opcional de inactividad

activándose.

Si el usuario simplemente presiona intro, el valor del argumento defchar es sustituido. Esto significa que cuando el usuario presiona ya sea nueva línea o retorno, el carácter especificado en defchar, es mostrado después del prompt, como si el usuario lo hubiera escrito, así como ser devuelto a la aplicación llamante. Si tal reemplazo no es importante, simplemente pasa '0 como el valor de defchar

.

Si el carácter ingresado es un carácter imprimible no imprimible, se muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y los caracteres más allá de 127 se muestran en octal, precedidos por una barra

invertida.

Al igual que con gl_get_line(), el eco del carácter ingresado puede ser deshabilitado usando la función gl_echo_mode()

.

Si el proceso llamante es suspendido mientras espera a que el usuario escriba su respuesta, el cursor se mueve a la línea siguiente a la línea del prompt, luego cuando el proceso se reanuda, el prompt se vuelve a mostrar, y gl_query_char() reanuda la espera de que el usuario escriba un

carácter.

Ten en cuenta que en el modo de servidor no bloqueante, (ver gl_io_mode(3)), si una línea de entrada incompleta está en proceso de ser leída cuando gl_query_char() es llamada, la línea de entrada parcial es descartada, y borrada del terminal, antes de que el nuevo prompt sea mostrado. La siguiente llamada a gl_get_line() comenzará as

nueva línea.

CRUDOS

Mientras que la función gl_query_char() le pide visiblemente al usuario un carácter, y muestra lo que escribió, la función gl_read_char() lee un carácter de señal del usuario, sin escribir nada en el terminal, o perturbar cualquier línea de entrada incompleta. ne().

;

En caso de éxito, el valor de retorno de gl_read_char() es el carácter que fue leído. bloqueante.

Ten en cuenta que ciertas teclas del teclado, como las teclas de función y las teclas de cursor, usualmente generan al menos 3 caracteres cada una, por lo que una sola llamada a gl_read_char() no bastae suficiente
