NOMBRE

glBeginQuery - delimita los límites de un objeto de consulta

ESPECIFICACIÓN C

void glBeginQuery(GLenum target, GLuint id);

void glEndQuery(GLenum target);

PARÁMETROS PARA GLBEGINQUERY

target

Especifica el tipo de destino del objeto de consulta establecido entre glBeginQuery y el posterior

glEndQuery. La constante simbólica debe ser uno de GL_SAMPLES_PASSED, GL_ANY_SAMPLES_PASSED, GL_ANY_SAMPLES_PASSED_CONSERVATIVE, GL_PRIMITIVES_GENERATED, GL_TRANSFORM_FEEDBACK_PRIMITIVES_WRITTEN, o GL_TIME_ELAPSED.

id

Especifica el nombre de un objeto de consulta.

PARÁMETROS PARA GLENDQUERY

target

Especifica el tipo de destino del objeto de consulta a ser concluido. La constante simbólica debe ser uno de GL_SAMPLES_PASSED, GL_ANY_SAMPLES_PASSED, GL_ANY_SAMPLES_PASSED_CONSERVATIVE, GL_PRIMITIVES_GENERATED, GL_TRANSFORM_FEEDBACK_PRIMITIVES_WRITTEN, o GL_TIME_ELAPSED.

DESCRIPCIÓN

glBeginQuery y

glEndQuery delimitan los límites de un objeto de consulta. query debe ser un nombre devuelto previamente por una llamada a glGenQueries(). Si un objeto de consulta con el nombre id aún no existe, se crea con el tipo determinado por target. target debe ser uno de GL_SAMPLES_PASSED, GL_ANY_SAMPLES_PASSED, GL_PRIMITIVES_GENERATED, GL_TRANSFORM_FEEDBACK_PRIMITIVES_WRITTEN, o GL_TIME_ELAPSED. El comportamiento del objeto de consulta depende de su tipo y es el siguiente.

Si target es GL_SAMPLES_PASSED, id debe ser un nombre no utilizado, o el nombre de un objeto de consulta de oclusión existente. Cuando se ejecuta glBeginQuery, el contador de muestras pasadas del objeto de consulta se reinicia a 0. La renderización posterior incrementará el contador por cada muestra que pase la prueba de profundidad. Si el valor de GL_SAMPLE_BUFFERS es 0, entonces el recuento de muestras pasadas se incrementa en 1 por cada fragmento. Si el valor de GL_SAMPLE_BUFFERS es 1, entonces el recuento de muestras pasadas se incrementa por el número de muestras cuya bit de cobertura esté establecido. Sin embargo, las implementaciones, a su discreción, pueden aumentar el recuento de muestras pasadas por el valor de GL_SAMPLES si alguna muestra en el fragmento está cubierta. Cuando se ejecuta glEndQuery, el contador de muestras pasadas se asigna al valor de resultado del objeto de consulta. Este valor se puede consultar llamando a glGetQueryObject() con pname GL_QUERY_RESULT.

Si target es GL_ANY_SAMPLES_PASSED o GL_ANY_SAMPLES_PASSED_CONSERVATIVE, id debe ser un nombre no utilizado, o el nombre de un objeto de consulta booleana de oclusión existente. Cuando se ejecuta glBeginQuery, la bandera de muestras pasadas del objeto de consulta se reinicia a GL_FALSE. La renderización posterior hará que la bandera se establezca en GL_TRUE si alguna muestra pasa la prueba de profundidad en el caso de GL_ANY_SAMPLES_PASSED, o si la implementación determina que alguna muestra podría pasar la prueba de profundidad en el caso de GL_ANY_SAMPLES_PASSED_CONSERVATIVE. La implementación puede ser capaz de proporcionar una prueba más eficiente en el caso de GL_ANY_SAMPLES_PASSED_CONSERVATIVE si algunas falsos positivos son aceptables para la aplicación. Cuando se ejecuta glEndQuery, la bandera de muestras pasadas se asigna al valor de resultado del objeto de consulta. Este valor se puede consultar llamando a glGetQueryObject() con pname GL_QUERY_RESULT.

Si target es GL_PRIMITIVES_GENERATED, id debe ser un nombre no utilizado, o el nombre de un objeto de consulta de primitivas existente previamente enlazado al enlace de consulta GL_PRIMITIVES_GENERATED. Cuando se ejecuta glBeginQuery, el contador de primitivas generadas del objeto de consulta se reinicia a 0. La renderización posterior incrementará el contador una vez por cada vértice que sea emitido desde el shader de geometría, o desde el shader de vértices si no hay un shader de geometría presente. Cuando se ejecuta glEndQuery, el contador de primitivas generadas se asigna al valor de resultado del objeto de consulta. Este valor se puede consultar llamando a glGetQueryObject() con pname GL_QUERY_RESULT.

Si target es GL_TRANSFORM_FEEDBACK_PRIMITIVES_WRITTEN, id debe ser un nombre no utilizado, o el nombre de un objeto de consulta de primitivas existente previamente enlazado al enlace de consulta GL_TRANSFORM_FEEDBACK_PRIMITIVES_WRITTEN. Cuando se ejecuta glBeginQuery, el contador de primitivas escritas del objeto de consulta se reinicia a 0. La renderización posterior incrementará el contador una vez por cada vértice que sea escrito en los búferes de feedback de transformación enlazados. Si el modo de feedback de transformación no se activa entre la llamada a glBeginQuery y glEndQuery, el contador no se incrementará. Cuando se ejecuta glEndQuery, el contador de primitivas escritas se asigna al valor de resultado del objeto de consulta. Este valor se puede consultar llamando a glGetQueryObject() con pname GL_QUERY_RESULT.

Si target es GL_TIME_ELAPSED, id debe ser un nombre no utilizado, o el nombre de un objeto de consulta de temporizador existente previamente enlazado al enlace de consulta GL_TIME_ELAPSED. Cuando se ejecuta glBeginQuery, el contador de tiempo del objeto de consulta se reinicia a 0. Cuando se ejecuta glEndQuery, el tiempo transcurrido del servidor que ha pasado desde la llamada a glBeginQuery se escribe en el contador de tiempo del objeto de consulta. Este valor se puede consultar llamando a glGetQueryObject() con pname GL_QUERY_RESULT.

Consultar GL_QUERY_RESULT implícitamente vacía la tubería de GL hasta que la renderización delimitada por el objeto de consulta se haya completado y el resultado esté disponible. GL_QUERY_RESULT_AVAILABLE se puede consultar para determinar si el resultado está inmediatamente disponible o si la renderización aún no se ha completado.

NOTAS

Si el contador del destino de la consulta excede el valor máximo representable en el número de bits disponibles, según lo informado por glGetQueryiv() con target establecido en el destino de consulta apropiado y pname GL_QUERY_COUNTER_BITS, el contador se vuelve indefinido.

Una implementación puede admitir 0 bits en su contador, en cuyo caso los resultados de la consulta son siempre indefinidos y esencialmente inútiles.

Cuando GL_SAMPLE_BUFFERS es 0, el contador de muestras pasadas de una consulta de oclusión se incrementará una vez por cada fragmento que pase la prueba de profundidad. Cuando GL_SAMPLE_BUFFERS es 1, una implementación puede incrementar el contador de muestras pasadas individualmente para cada muestra de un fragmento que pase la prueba de profundidad, o puede optar por incrementar el contador para todas las muestras de un fragmento si alguna de ellas pasa la prueba de profundidad.

Los destinos de consulta GL_ANY_SAMPLES_PASSED y GL_TIME_ELAPSED están disponibles solo si la versión de GL es 3.3 o superior.

El destino de consulta GL_ANY_SAMPLES_PASSED_CONSERVATIVE está disponible solo si la versión de GL es 4.3 o superior.

ERRORES

Se genera GL_INVALID_ENUM si target no es uno de los tokens aceptados.

Se genera GL_INVALID_OPERATION si se ejecuta glBeginQuery mientras un objeto de consulta del mismo target ya está activo.

Se genera GL_INVALID_OPERATION si

se ejecuta glEndQuery cuando un objeto de consulta del mismo target no está activo.

Se genera GL_INVALID_OPERATION si id es 0.

Se genera GL_INVALID_OPERATION si id es el nombre de un objeto de consulta ya activo.

Se genera GL_INVALID_OPERATION si id se refiere a un objeto de consulta existente cuyo tipo no coincide con target.
