DESCRIPCIÓN

La función gl_get_line() es parte de la biblioteca tecla (ver la página del manual de libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le pide al usuario una línea de entrada, luego proporciona facilidades de edición interactivas, similares a las del shell tcsh de Unix. Además de la edición simple de la línea de comandos, soporta la recuperación de líneas de comandos ingresadas previamente, autocompletado con TAB de nombres de archivo, y expansión de comodines en línea de nombres de archivo. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario, se puede encontrar en la página del manual de tecla(7). Esta página del manual se ocupa de la documentación para programadores interesados en usar esta biblioteca en su aplicación.

UN EJEMPLO

Lo siguiente muestra un ejemplo completo de cómo usar la función gl_get_line() para obtener entrada del usuario:

  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que el usuario escribió */
    GetLine *gl;   /* El objeto de recursos gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* de conjunto de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("Escribiste: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
  }

En el ejemplo, primero se crean los recursos necesarios para la función gl_get_line() llamando a new_GetLine(). Esto asigna la memoria utilizada en llamadas posteriores a la función gl_get_line(), incluido el búfer de historial para registrar las líneas ingresadas previamente. Luego, se leen una o más líneas del usuario, hasta que ocurre un error o el usuario escribe exit. Luego, finalmente, los recursos que fueron asignados por new_GetLine() se devuelven al sistema llamando a del_GetLine(). Tenga en cuenta el uso del valor de retorno NULL de del_GetLine() para hacer que gl sea NULL. Esta es una medida de precaución. Si el programa intenta posteriormente pasar gl a gl_get_line(), dicha función se quejará y devolverá un error, en lugar de intentar usar el objeto de recurso eliminado.

LAS FUNCIONES UTILIZADAS EN EL EJEMPLO

Las descripciones de las funciones utilizadas en el ejemplo son las siguientes:

  GetLine *new_GetLine(size_t linelen, size_t histlen)

Esta función crea los recursos utilizados por la función gl_get_line() y devuelve un puntero opaco al objeto que los contiene. La longitud máxima de una línea de entrada se especifica a través del argumento linelen, y el número de bytes a asignar para almacenar líneas de historial se establece mediante el argumento histlen. Las líneas de historial se almacenan una detrás de otra en un único búfer de este tamaño. Tenga en cuenta que esto significa que el número de líneas de historial que se pueden almacenar en un momento dado, depende de las longitudes de las líneas individuales. Si desea colocar un límite superior en el número de líneas que se pueden almacenar, consulte la función gl_limit_history() descrita más adelante. Si no desea historial en absoluto, especifique histlen como cero, y no se asignará ningún búfer de historial.

En caso de error, se imprime un mensaje en stderr y se devuelve NULL.

  GetLine *del_GetLine(GetLine *gl)

Esta función elimina los recursos que fueron devueltos por una llamada previa a new_GetLine(). Siempre devuelve NULL (es decir, un objeto eliminado). No hace nada si el argumento gl es NULL.

  char *gl_get_line(GetLine *gl, const char *prompt,
                   const char *start_line, int start_pos);

La función gl_get_line() puede ser llamada cualquier número de veces para leer entrada del usuario. El argumento gl debe haber sido devuelto previamente por una llamada a new_GetLine(). Por defecto, los prompts se muestran literalmente, pero si se habilitan con la función gl_prompt_style() (ver más adelante), los prompts pueden contener directivas para hacer subrayados, cambiar a y desde fuentes en negrita, o activar y desactivar el resaltado.

Si desea especificar el contenido inicial de la línea, para que el usuario lo edite, pase la cadena deseada a través del argumento start_line. Luego puede especificar en qué carácter de esta línea está inicialmente el cursor.

COMPLETADO DE PALABRAS PERSONALIZADO

Si en su aplicación, le gustaría que el completado con TAB completara otras cosas además de o en lugar de nombres de archivo, puede organizar esto registrando una función de retorno de completado alternativa, a través de una llamada a la gl_customize_completion() función.

  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn);

El data argumento proporciona una manera para que su aplicación pase información arbitraria y específica de la aplicación a la función de retorno. Esto se pasa a la función de retorno cada vez que es llamada. Podría, por ejemplo, apuntar a la tabla de símbolos de la que se deben buscar las posibles completaciones. El match_fn argumento especifica la función de retorno a llamar. El CplMatchFn tipo de función está definido en libtecla.h, al igual que una CPL_MATCH_FN() macro que puede usar para declarar y definir prototipos de funciones de retorno. La declaración y las responsabilidades de las funciones de retorno se describen en profundidad en la página del manual cpl_complete_word(3).

En resumen, la función de retorno es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario presionó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar posibles completaciones de esta palabra, y registrarlas una por una en el WordCompletion objeto que se le pasa como argumento, llamando a la cpl_add_completion() función. Si la función de retorno desea proporcionar completado de nombres de archivo además de sus propias completaciones específicas, tiene la opción de llamar por sí misma a la función de retorno de completado de nombres de archivo incorporada. Esto también está documentado en la página del manual cpl_complete_word(3) .

Tenga en cuenta que si le gustaría que gl_get_line() devolviera la línea de entrada actual cuando se haya realizado una completación exitosa, puede organizar esto cuando llame a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de nueva línea. Si hace esto, la línea de entrada se actualizará para mostrar la completación, junto con cualquier sufijo de continuación hasta el carácter de nueva línea, y luego gl_get_line() devolverá esta línea de entrada.

Si, por alguna razón, su función de retorno necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto comenzará una nueva línea después de la línea de entrada que se está editando actualmente, restablecerá la E/S normal de la terminal, y le dirá a gl_get_line() que la línea de entrada necesitará ser redibujada cuando la función de retorno regrese.

AÑADIENDO ACCIONES DE COMPLETADO

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de completado predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que diferentes tipos de completado de palabras se puedan enlazar a diferentes secuencias de teclas. Esto se logra usando la gl_completion_action() función.

  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq);

Los data y match_fn argumentos se describen en la página del manual cpl_complete_word , y especifican la función de retorno que debe ser invocada para identificar posibles completaciones. El list_only argumento determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar cualquier completación ambigua posible, o si simplemente debe mostrar la lista de posibles completaciones sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El name argumento especifica el nombre con el que los archivos de configuración y las futuras invocaciones de esta función deben referirse a la acción. Este debe ser el nombre de una acción de completado existente a cambiar, o un nombre nuevo sin usar para una nueva acción. Finalmente, el keyseq argumento especifica la secuencia de teclas predeterminada a la que enlazar la acción. Si esto es NULL, no se enlazará ninguna nueva secuencia de teclas a la acción.

Tenga cuidado de que para que el usuario pueda cambiar la secuencia de teclas que está enlazada a las acciones que se instalan de esta manera, cuando llame a gl_completion_action() para instalar una acción dada por primera vez, debe hacerlo entre la llamada a new_GetLine() y la primera llamada a gl_get_line(). De lo contrario, cuando se lea el archivo de configuración del usuario en la primera llamada a gl_get_line(), el nombre de su acción adicional no será conocido, y cualquier referencia a ella en el archivo de configuración generará un error.

Como se discutió para gl_customize_completion(), si su función de retorno, por alguna razón, necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo.

DEFINIENDO ACCIONES PERSONALIZADAS

Aunque las acciones de enlace de teclas incorporadas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, enlazadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza que correspondiera a un número de pieza precedente al cursor. Tal característica está claramente fuera del alcance de las funciones de acción incorporadas. Así que para tales casos especiales, se proporciona la gl_register_action() función.

  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq);

Esta función permite a la aplicación registrar una función externa, fn, que a partir de entonces será llamada siempre que se introduzca la secuencia de teclas especificada, keyseq, por el usuario, o cuando el usuario introduzca cualquier otra secuencia de teclas que el usuario posteriormente enlace al nombre de acción especificado, name, en su archivo de configuración. El data argumento puede ser un puntero a cualquier cosa que la aplicación desee que se pase a la función de acción, fn, siempre que esa función sea invocada.

La función de acción, fn, debe ser declarada usando la siguiente macro, que está definida en libtecla.h.

  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char *line)

Los gl y data argumentos son aquellos que fueron pasados previamente a gl_register_action() cuando la función de acción fue registrada. El count argumento es un argumento numérico que el usuario tiene la opción de introducir usando la acción digit-argument , antes de invocar la acción. Si el usuario no introduce un número, entonces el count argumento se establece en 1. Nominalmente este argumento se interpreta como un conteo de repetición, lo que significa que la acción debe repetirse ese número de veces. Sin embargo, en la práctica, para algunas acciones un conteo de repetición tiene poco sentido. En tales casos, las acciones pueden simplemente ignorar el count argumento, o usar su valor para un propósito diferente.

Una copia de la línea de entrada actual se pasa en el argumento de solo lectura line . La posición actual del cursor dentro de esta cadena está dada por el índice contenido en el curpos argumento. Tenga en cuenta que la manipulación directa de la línea de entrada y la posición del cursor no está permitida. Esto se debe a que las reglas dictadas por varios modos, como el modo vi versus el modo emacs, el modo sin eco, y el modo de inserción versus el modo de sobrescritura etc, hacen que sea demasiado compleo para un desarrollador de aplicaciones escribir una acción de edición conforme, así como restringen cambios futuros en los internos de gl_get_line(). Una solución potencial a este dilema sería permitir que la función de acción edite la línea usando las acciones de edición existentes. Esto está actualmente bajo consideración.

Si la función de acción desea escribir texto en la terminal, sin que esto se mezcle con el texto mostrado de la línea de entrada, o leer de la terminal sin tener que manejar la E/S cruda de la terminal, entonces antes de realizar cualquiera de estas operaciones, debe suspender temporalmente la edición de línea llamando a la gl_normal_io() función. Esta función vacía cualquier salida pendiente a la terminal, mueve el cursor al inicio de la línea que sigue a la última línea de terminal de la línea de entrada, y luego restaura la terminal a un estado que es adecuado para su uso con las instalaciones stdio de C. Lo último incluye cosas como restaurar el mapeo normal de \n a \r\n, y, cuando se está en modo servidor, restaurar la forma normal de bloqueo de la E/S de la terminal. Después de haber llamado a esta función, la función de acción puede leer de y escribir a la terminal sin el temor de crear un desorden. No es necesario para la función de acción restaurar el entorno de edición original antes de regresar. Esto se hace automáticamente por gl_get_line() después de que la función de acción regrese. Lo siguiente es un ejemplo simple de una función de acción que escribe la frase "Hello world" en una nueva línea de terminal después de la línea que se está editando. Cuando esta función regresa, la línea de entrada se redibuja en la línea que sigue a la línea "Hello world", y la edición de línea se reanuda.

  static GL_ACTION_FN(say_hello_fn)
  {
    if(gl_normal_io(gl))   /* Suspender temporalmente la edición */
      return GLA_ABORT;
    printf("Hola mundo\n");
    return GLA_CONTINUE;
  }

Las funciones de acción deben devolver uno de los siguientes valores, para indicar a gl_get_line() cómo proceder.

  GLA_ABORT     -   Hace que gl_get_line() devuelva NULL.
  GLA_RETURN    -   Hace que gl_get_line() devuelva la
                    línea de entrada completada.
  GLA_CONTINUE  -   Reanuda la edición de la línea de comandos.

Tenga en cuenta que el argumento name de gl_register_action() especifica el nombre por el cual un usuario puede referirse a la acción en su archivo de configuración. Esto les permite reasignar la acción a una secuencia de teclas alternativa. Para que esto funcione, es necesario llamar a gl_register_action() entre la llamada a new_GetLine() y la primera llamada a gl_get_line().

ARCHIVOS DE HISTORIAL

Para guardar el contenido del búfer de historial antes de salir de su aplicación, y posteriormente restaurarlos cuando vuelva a iniciar la aplicación, se proporcionan las siguientes funciones.

 int gl_save_history(GetLine *gl, const char *filename,
                     const char *comment, int max_lines);
 int gl_load_history(GetLine *gl, const char *filename,
                     const char *comment);

El argumento filename especifica el nombre que se le dará al archivo de historial al guardar, o el nombre de un archivo de historial existente, al cargar. Este puede contener expresiones de directorio de inicio y variables de entorno, como "~/.myapp_history" o "$HOME/.myapp_history".

Junto con cada línea del historial, se registra información adicional sobre ella, como cuándo fue ingresada por el usuario y cuál es su nivel de anidamiento, como un comentario que precede a la línea en el archivo de historial. Escribir esto como un comentario permite que el archivo de historial sirva también como archivo de comandos, en caso de que desee reproducir una sesión completa utilizándolo. Dado que los prefijos de comentario difieren en diferentes idiomas, el argumento comment se proporciona para especificar el prefijo del comentario. Por ejemplo, si su aplicación fuera un shell de Unix, como el shell de Bourne, especificaría "#" aquí. Cualquiera que sea el carácter de comentario que elija, debe especificar el mismo prefijo a gl_load_history() que utilizó cuando llamó a gl_save_history() para escribir el archivo de historial.

El argumento max_lines debe ser -1 para especificar que se guarden todas las líneas de la lista de historial, o un número positivo que especifique un límite superior de cuántas de las líneas más recientes se guardarán.

Ambas funciones devuelven un valor distinto de cero en caso de error, después de escribir un mensaje de error en stderr. Tenga en cuenta que gl_load_history() no considera la no existencia de un archivo como un error.

LISTAS DE HISTORIAL MÚLTIPLES

Si su aplicación utiliza un único objeto GetLine para ingresar muchos tipos diferentes de líneas de entrada, es posible que desee que gl_get_line() distinga los diferentes tipos de líneas en la lista de historial y solo recupere las líneas que coincidan con el tipo de línea actual. Para admitir este requisito, gl_get_line() marca las líneas que se registran en la lista de historial con un identificador entero elegido por la aplicación. Inicialmente, este identificador se establece en 0 por new_GetLine(), pero puede cambiarse posteriormente llamando a gl_group_history().

  int gl_group_history(GetLine *gl, unsigned id);

El identificador entero id puede ser cualquier número elegido por la aplicación, pero tenga en cuenta que gl_save_history() y gl_load_history() conservan la asociación entre los identificadores y las líneas de entrada históricas entre invocaciones del programa, por lo que debe elegir identificadores fijos para los diferentes tipos de líneas de entrada utilizados por su aplicación.

Cada vez que gl_get_line() agrega una nueva línea de entrada a la lista de historial, el identificador de historial actual se registra con ella, y cuando se le pide que recupere una línea de entrada histórica, solo recupera las líneas que están marcadas con el identificador actual.

MOSTRAR HISTORIAL

La lista de historial se puede mostrar llamando a gl_show_history().

  int gl_show_history(GetLine *gl, FILE *fp,
                      const char *fmt,
                      int all_groups,
                      int max_lines);

Esto muestra el contenido actual de la lista de historial al flujo de salida estándar fp. Si el argumento max_lines es mayor o igual a cero, entonces no se mostrarán más de este número de las líneas más recientes. Si el argumento all_groups es distinto de cero, se muestran las líneas de todos los grupos de historial. De lo contrario, solo se muestran las del grupo de historial seleccionado actualmente. El argumento de cadena de formato, fmt, determina cómo se muestra la línea. Puede contener caracteres arbitrarios que se escriben literalmente, intercalados con cualquiera de las siguientes directivas de formato:

  %D  -  La fecha en que la línea fue ingresada
         originalmente, formateada como 2001-11-20.
  %T  -  La hora del día en que se ingresó la línea,
         formateada como 23:59:59.
  %N  -  El número secuencial de entrada de la línea en
         el búfer de historial.
  %G  -  El número del grupo de historial al que
         pertenece la línea.
  %%  -  Un carácter % literal.
  %H  -  La línea de historial en sí.

Por lo tanto, una cadena de formato como "2001-11-20 10:23:34 Hello world" produciría algo como:

  2001-11-20 10:23:34  Hola mundo

Tenga en cuenta la inclusión de un carácter de nueva línea explícito en la cadena de formato.

BUSCAR EN EL HISTORIAL

La función gl_lookup_history() permite a la aplicación llamante buscar líneas en la lista de historial.

  typedef struct {
    const char *line;    /* La línea histórica solicitada. */
    unsigned group;      /* El grupo de historial al que */
                         /* pertenece la línea. */
    time_t timestamp;    /* La fecha y hora en que la línea */
                         /* fue ingresada originalmente. */
  } GlHistoryLine;
  int gl_lookup_history(GetLine *gl, unsigned long id,
                        GlHistoryLine *hline);

El argumento id indica qué línea buscar, donde la primera línea que se ingresó en la lista de historial después de llamar a new_GetLine() se denota con 0, y las líneas ingresadas posteriormente se denotan con números sucesivamente mayores. Tenga en cuenta que el rango de líneas actualmente conservadas en la lista de historial se puede consultar llamando a la función gl_range_of_history(), descrita más adelante. Si la línea solicitada está en la lista de historial, los detalles de la línea se registran en la variable apuntada por el argumento hline, y se devuelve 1. De lo contrario, se devuelve 0, y la variable apuntada por hline permanece sin cambios.

Tenga en cuenta que la cadena devuelta en hline->line es parte del búfer de historial, por lo que no debe ser modificada por el llamador, y será reciclada en la próxima llamada a cualquier función que tome gl como argumento. Por lo tanto, debe hacer una copia privada de esta cadena si necesita conservarla.

TRANSACCIÓN MANUAL DEL HISTORIAL

Por defecto, cada vez que el usuario ingresa una línea, se agrega automáticamente a la lista de historial, justo antes de que gl_get_line() devuelva la línea al llamador. Esto es conveniente para la mayoría de las aplicaciones, pero también hay aplicaciones que necesitan un control más fino sobre lo que se agrega a la lista de historial. En tales casos, la adición automática de las líneas ingresadas a la lista de historial se puede desactivar llamando a la función gl_automatic_history().

  int gl_automatic_history(GetLine *gl, int enable);

Si se llama a esta función con su argumento enable establecido en 0, gl_get_line() no archivará automáticamente las líneas ingresadas posteriormente. El archivo automático se puede reactivar más tarde, llamando a esta función nuevamente, con su argumento enable establecido en 1. Mientras el archivo automático del historial está deshabilitado, la aplicación llamante puede usar gl_append_history() para agregar líneas a la lista de historial según sea necesario.

  int gl_append_history(GetLine *gl, const char *line);

El argumento line especifica la línea que se agregará a la lista de historial. Debe ser una cadena normal terminada en '\0'. Si esta cadena contiene algún carácter de nueva línea, la línea que se archivará en la lista de historial se terminará con el primero de ellos. De lo contrario, se terminará con el terminador '\0'. Si la línea es más larga que la longitud máxima de línea de entrada, que se especificó al llamar a new_GetLine(), cuando se recupere la línea, se truncará a la longitud real de línea de gl_get_line().

Si tiene éxito, gl_append_history() devuelve 0. De lo contrario, devuelve un valor distinto de cero y establece errno en uno de los siguientes valores.

   EINVAL  -  Uno de los argumentos pasados a
              gl_append_history() era NULL.
   ENOMEM  -  La línea especificada era más larga que el tamaño
              asignado del búfer de historial (como se especificó al
              llamar a new_GetLine()), por lo que no se pudo archivar.

Una descripción textual del error se puede obtener opcionalmente llamando a gl_error_message(). Tenga en cuenta que después de un error de este tipo, la lista de historial permanece en un estado válido para recibir nuevas líneas de historial, por lo que hay poco daño en simplemente ignorar el estado de retorno de gl_append_history().

CONFIGURACIÓN MISCELÁNEA DEL HISTORIAL

Si desea cambiar el tamaño del búfer de historial que se especificó originalmente en la llamada a new_GetLine(), puede hacerlo con la función gl_resize_history().

  int gl_resize_history(GetLine *gl, size_t histlen);

El argumento histlen especifica el nuevo tamaño en bytes, y si lo especifica como 0, el búfer se eliminará.

Como se mencionó en la discusión de new_GetLine(), el número de líneas que se pueden almacenar en el búfer de historial depende de la longitud de las líneas individuales. Por ejemplo, un búfer de 1000 bytes podría almacenar igualmente 10 líneas de longitud promedio de 100 bytes, o 2 líneas de longitud promedio de 50 bytes. Aunque el búfer nunca se expande cuando se agregan nuevas líneas, una lista de punteros dentro del búfer se expande cuando es necesario para acomodar el número de líneas actualmente almacenadas en el búfer. Para colocar un límite superior en el número de líneas en el búfer, y por lo tanto un límite superior en la cantidad de memoria utilizada en esta lista, puede llamar a gl_limit_history() función.

  void gl_limit_history(GetLine *gl, int max_lines);

El max_lines debe ser un número positivo >= 0, que especifique un límite superior para el número de líneas en el búfer, o ser -1 para cancelar cualquier límite especificado previamente. Cuando un límite está en efecto, solo las max_lines líneas añadidas más recientemente se conservan en el búfer. Las líneas más antiguas se descartan.

Para descartar líneas del búfer de historial, use la gl_clear_history() función.

  void gl_clear_history(GetLine *gl, int all_groups);

El all_groups argumento indica a la función si debe eliminar solo las líneas asociadas con el grupo de historial actual (ver gl_group_history()), o todas las líneas históricas en el búfer.

La gl_toggle_history() función le permite activar y desactivar el historial sin perder el contenido actual de la lista de historial.

  void gl_toggle_history(GetLine *gl, int enable);

Establecer el enable argumento en 0 desactiva el mecanismo de historial, y establecerlo en 1 lo vuelve a activar. Cuando el historial está desactivado, no se añadirán nuevas líneas a la lista de historial, y las búsquedas en el historial mediante teclas de acceso actuarán como si no hubiera nada en el búfer de historial.

CONSULTA DE INFORMACIÓN DEL HISTORIAL

El estado configurado de la lista de historial se puede consultar con la gl_history_state() función.

  typedef struct {
    int enabled;     /* Verdadero si el historial está habilitado */
    unsigned group;  /* El grupo de historial actual */
    int max_lines;   /* El límite superior actual para el */
                     /*  número de líneas en la lista de */
                     /*  historial, o -1 si es ilimitado. */
  } GlHistoryState;
  void gl_state_of_history(GetLine *gl,
                           GlHistoryState *state);

Al regresar, la información de estado se registra en la variable a la que apunta el state argumento.

La gl_range_of_history() función devuelve el número y el rango de líneas en la lista de historial.

typedef struct {
  unsigned long oldest;  /* El número de entrada secuencial */
                         /*  de la línea más antigua en la */
                         /*  lista de historial. */
  unsigned long newest;  /* El número de entrada secuencial */
                         /*  de la línea más reciente en la */
                         /*  lista de historial. */
  int nlines;            /* El número de líneas en la */
                         /*  lista de historial. */
} GlHistoryRange;
void gl_range_of_history(GetLine *gl, GlHistoryRange *range);

Los valores de retorno se registran en la variable a la que apunta el range argumento. Si el nlines miembro de esta estructura es mayor que cero, entonces los miembros oldest y newest informan el rango de líneas en la lista, y newest=oldest+nlines-1. De lo contrario, ambos son cero.

La gl_size_of_history() función devuelve el tamaño total de el búfer de historial y la cantidad del búfer que está actualmente ocupada.

  typedef struct {
    size_t size;      /* El tamaño del búfer de historial */
                      /*  (bytes). */
    size_t used;      /* El número de bytes del */
                      /*  búfer de historial que están */
                      /*  actualmente ocupados. */
  } GlHistorySize;
  void gl_size_of_history(GetLine *gl, GlHistorySize *size);

Al regresar, la información de tamaño se registra en la variable a la que apunta el size argumento.

CAMBIO DE TERMINALES

La new_GetLine() función constructora asume que la entrada se leerá desde stdin, y la salida se escribirá en stdout. La siguiente función le permite cambiar a diferentes flujos de entrada y salida.

  int gl_change_terminal(GetLine *gl, FILE *input_fp,
                         FILE *output_fp, const char *term);

El gl argumento es el objeto que fue devuelto por new_GetLine(). El input_fp argumento especifica el flujo del que leer, y output_fp especifica el flujo en el que escribir. Solo si ambos se refieren a un terminal, la entrada interactiva del terminal será habilitada. De lo contrario, gl_get_line() simplemente llamará a fgets() para leer la entrada de comando. Si ambos flujos se refieren a un terminal, entonces deben referirse al mismo terminal, y el tipo de este terminal debe ser especificado a través del term argumento. El valor del term argumento se busca en la base de datos de información de terminales (terminfo o termcap), con el fin de determinar qué secuencias de control especiales se necesitan para controlar varios aspectos del terminal. new_GetLine() por ejemplo, pasa el valor de retorno de getenv("TERM") en este argumento. Note que si uno o ambos de input_fp y output_fp no se refieren a un terminal, es legal pasar NULL en lugar de un tipo de terminal.

Note que si desea pasar descriptores de archivo a gl_change_terminal(), puede hacerlo creando envoltorios de flujo stdio usando la función POSIX fdopen() .

MANEJO DE EVENTOS EXTERNOS

Por defecto, gl_get_line() no retorna hasta que el usuario ha introducido una línea de entrada completa, o ocurre un error. En programas que necesitan vigilar la E/S de otras fuentes que no sean el terminal, hay dos opciones.

  1. Use las funciones descritas en la página de manual
     gl_io_mode(3) para cambiar
     gl_get_line() al modo de servidor no bloqueante. En este modo,
     gl_get_line() se convierte en una función de edición de línea
     no bloqueante e incremental que puede ser llamada de forma segura desde
     un bucle de eventos externo. Aunque este es un método muy
     versátil, implica asumir algunas
     responsabilidades que normalmente se realizan detrás de escena por gl_get_line().
  2. Mientras gl_get_line() está esperando la entrada del
     teclado del usuario, puede pedirle que también vigile la
     actividad en descriptores de archivo arbitrarios, como
     sockets de red, tuberías, etc., y que llame a funciones
     de su elección cuando se vea actividad. Esto funciona en
     cualquier sistema que tenga la llamada al sistema select() ,
     que es la mayoría, si no todos, los sabores de unix.

Registrar un descriptor de archivo para ser vigilado por gl_get_line() implica llamar a la gl_watch_fd() función.

  int gl_watch_fd(GetLine *gl, int fd, GlFdEvent event,
                  GlFdEventFn *callback, void *data);

Si esto retorna un valor distinto de cero, entonces significa que o sus argumentos son inválidos, o que esta funcionalidad no es soportada en el sistema anfitrión.

El fd argumento es el descriptor de archivo a vigilar. El event argumento especifica qué tipo de actividad es de interés, elegido de los siguientes valores enumerados:

  GLFD_READ   -  Vigilar la llegada de datos para leer.
  GLFD_WRITE  -  Vigilar la capacidad de escribir en el descriptor
                 de archivo sin bloquear.
  GLFD_URGENT -  Vigilar la llegada de datos urgentes
                 fuera de banda en el descriptor de archivo.

El callback argumento es la función a llamar cuando se ve la actividad seleccionada. Debe ser definida con el siguiente macro, que está definido en libtecla.h.

  #define GL_FD_EVENT_FN(fn) GlFdStatus (fn)(GetLine *gl, \
                                      void *data, int fd, \
                                      GlFdEvent event)

El data argumento de la gl_watch_fd() función se pasa a la función de retorno de llamada para su propio uso, y puede apuntar a lo que desee, incluyendo NULL. El descriptor de archivo y el argumento del evento también se pasan a la función de retorno de llamada, y esto potencialmente permite que la misma función de retorno de llamada sea registrada para más de un tipo de evento y/o más de un descriptor de archivo. El valor de retorno de la función de retorno de llamada debe ser uno de los siguientes valores.

  GLFD_ABORT    -  Decirle a gl_get_line() que aborte. Cuando esto
                   sucede, gl_get_line() retorna
                   NULL, y una llamada posterior a
                   gl_return_status() retornará
                   GLR_FDABORT. Note que si la
                   aplicación necesita que errno siempre tenga un valor significativo cuando
                   gl_get_line() retorna NULL,
                   la función de retorno de llamada debe establecer
                   errno apropiadamente.
  GLFD_REFRESH  -  Redibujar la línea de entrada y luego continuar
                   esperando la entrada. Retorne esto si
                   su retorno de llamada escribió en el terminal.
  GLFD_CONTINUE -  Continuar esperando la entrada, sin
                   redibujar la línea.

Note que antes de llamar al retorno de llamada, gl_get_line() bloquea la mayoría de las señales, y deja sus propios manejadores de señal instalados, así que si necesita capturar una señal en particular, necesitará tanto instalar temporalmente su propio manejador de señal, como desbloquear la señal. Asegúrese de volver a bloquear la señal (si estaba originalmente bloqueada) y reinstalar el manejador de señal original, si lo hay, antes de retornar.

Si la función de retorno de llamada necesita leer o escribir en el terminal, idealmente debería primero llamar a gl_normal_io(gl) para suspender temporalmente la edición de línea. Esto restaurará el terminal a modo canónico, de E/S bloqueante, y moverá el cursor al inicio de una nueva línea del terminal. Más tarde, cuando el retorno de llamada retorne, gl_get_line() notará que gl_normal_io() fue llamado, redisplayará la línea de entrada y reanudará la edición. Note que en este caso los valores de retorno, GLFD_REFRESH y GLFD_CONTINUE son equivalentes.

Para soportar casos donde la función de retorno de llamada llama a una función de terceros que ocasionalmente e impredeciblemente escribe en el terminal, la conversión automática de "0 a "0 es re-habilitada antes de que la función de retorno de llamada sea llamada. Si el retorno de llamada sabe que la función de terceros escribió en el terminal, entonces debería retornar el GLFD_REFRESH valor de retorno, para decirle a gl_get_line() que redisplaye la línea de entrada.

Para remover una función de retorno de llamada que registró previamente para un descriptor de archivo y evento dados, simplemente llame a gl_watch_fd() con el mismo descriptor de archivo y los event argumentos, pero con un callback argumento de 0. El data argumento se ignora en este caso.

ESTABLECER UN TIEMPO DE ESPERA POR INACTIVIDAD

En sistemas con la select() llamada al sistema, la gl_inactivity_timeout() función puede ser usada para establecer o cancelar un tiempo de espera por inactividad. La inactividad en este caso se refiere tanto a la entrada del teclado, como a la E/S en cualquier descriptor de archivo registrado por llamadas previas y posteriores a gl_watch_fd(). En sistemas peculiares que no tienen select(), esta llamada no tiene efecto.

  int gl_inactivity_timeout(GetLine *gl, GlTimeoutFn *callback,
                     void *data, unsigned long sec,
                     unsigned long nsec);

El tiempo de espera se especifica en forma de un número entero de segundos y un número entero de nanosegundos, a través de los sec y nsec argumentos respectivamente. Posteriormente, siempre que no se detecte actividad durante este período de tiempo, se llama a la función especificada a través del callback argumento. El data argumento de gl_inactivity_timeout() se pasa literalmente a esta función de retorno de llamada cada vez que se invoca, y por lo tanto puede usarse para pasar información arbitraria específica de la aplicación a la función de retorno de llamada. Se proporciona la siguiente macro en libtecla.h para que las aplicaciones la usen para declarar y prototipar funciones de retorno de llamada de tiempo de espera.

  #define GL_TIMEOUT_FN(fn) \
               GlAfterTimeout (fn)(GetLine *gl, void *data)

Al regresar, se espera que la función de retorno de llamada de la aplicación devuelva uno de los siguientes enumeradores para decirle a gl_get_line() cómo proceder después de que el tiempo de espera haya sido manejado por la función de retorno de llamada.

  GLTO_ABORT    -  Decirle a gl_get_line() que aborte. Cuando
                   esto sucede, gl_get_line() devolverá NULL, y una llamada posterior
                   a gl_return_status() devolverá
                   GLR_TIMEOUT. Tenga en cuenta que si la
                   aplicación necesita que errno siempre tenga un valor significativo cuando
                   gl_get_line() devuelva NULL,
                   la función de retorno de llamada debe establecer
                   errno apropiadamente.
  GLTO_REFRESH  -  Redibujar la línea de entrada, luego continuar
                   esperando entrada. Debería devolver
                   este valor si su función de retorno de llamada escribió en el
                   terminal sin haber llamado primero a
                   gl_normal_io(gl).
  GLTO_CONTINUE -  En modo normal de E/S bloqueante, continuar
                   esperando entrada, sin redibujar la
                   línea de entrada del usuario.
                   En modo de E/S de servidor no bloqueante (ver
                   gl_io_mode(3)), hacer que gl_get_line()
                   actúe como si la E/S se bloqueara. Esto significa
                   que gl_get_line() devolverá inmediatamente NULL, y una llamada posterior
                   a gl_return_status() devolverá
                   GLR_BLOCKED.

Tenga en cuenta que antes de llamar a la función de retorno de llamada, gl_get_line() bloquea la mayoría de las señales, y deja instalados sus propios manejadores de señal, así que si necesita capturar una señal en particular, deberá tanto instalar temporalmente su propio manejador de señal, como desbloquear la señal. Asegúrese de volver a bloquear la señal (si estaba originalmente bloqueada) y reinstalar el manejador de señal original, si lo hay, antes de regresar.

Si la función de retorno de llamada necesita leer o escribir en el terminal, idealmente debería llamar primero a gl_normal_io(gl) para suspender temporalmente la edición de línea. Esto restaurará el terminal a modo canónico, de E/S bloqueante, y moverá el cursor al comienzo de una nueva línea de terminal. Más tarde, cuando la función de retorno de llamada regrese, gl_get_line() notará que gl_normal_io() fue llamada, redisplayará la línea de entrada y reanudará la edición. Tenga en cuenta que en este caso los valores de retorno, GLTO_REFRESH y GLTO_CONTINUE son equivalentes.

Para soportar casos donde la función de retorno de llamada llama a una función de terceros que ocasionalmente e impredeciblemente escribe en la terminal, la conversión automática de "0 a "0 se vuelve a habilitar antes de que se llame a la función de retorno de llamada. Si la función de retorno de llamada sabe que la función de terceros escribió en la terminal, debería entonces devolver el GLTO_REFRESH valor de retorno, para decirle a gl_get_line() que redibuje la línea de entrada.

Tenga en cuenta que aunque el argumento de tiempo de espera incluye un componente de nanosegundos, pocos relojes de computadora tienen actualmente resoluciones más finas que unos pocos milisegundos, así que pedir menos de unos pocos milisegundos es equivalente a solicitar cero segundos en muchos sistemas. Si esto fuera un problema, debería basar su selección de tiempo de espera en la resolución real del reloj del host (ej. llamando a sysconf(_SC_CLK_TCK)).

Para desactivar los tiempos de espera, simplemente llame a gl_inactivity_timeout() con un callback argumento de 0. El data argumento se ignora en este caso.

MANEJO POR DEFECTO DE SEÑALES

Por defecto, la gl_get_line() función intercepta un número de señales. Esto es particularmente importante para señales que por defecto terminarían el proceso, ya que el terminal necesita ser restaurado a un estado utilizable antes de que esto suceda. En esta sección, se describen las señales que son atrapadas por defecto, y cómo gl_get_line() responde a ellas. Cambiar estos valores por defecto es el tema de la siguiente sección.

Cuando el siguiente subconjunto de señales es capturado, gl_get_line() primero restaura la configuración del terminal y el manejo de señales a como estaban antes de que gl_get_line() fuera llamada, reenvía la señal, para permitir que los manejadores de señal de la aplicación que llama la manejen, luego si el proceso todavía existe, gl_get_line() devuelve NULL y establece errno como se especifica a continuación.

 SIGINT  -  Esta señal es generada tanto por la tecla
            de interrupción del teclado (usualmente ^C), como por la tecla
            de interrupción (break) del teclado.
            errno=EINTR
 SIGHUP  -  Esta señal es generada cuando el terminal
            de control termina.
            errno=ENOTTY
 SIGPIPE -  Esta señal es generada cuando un programa intenta
            escribir en un pipe cuyo extremo remoto no está siendo
            leído por ningún proceso. Esto puede suceder, por ejemplo,
            si ha llamado a gl_change_terminal() para
            redirigir la salida a un pipe oculto bajo un pseudo
            terminal.
            errno=EPIPE
 SIGQUIT -  Esta señal es generada por la tecla de salida
            del teclado (usualmente ^\).
            errno=EINTR
 SIGABRT -  Esta señal es generada por la función estándar de C,
            abort(). Por defecto, tanto termina
            el proceso como genera un volcado de memoria (core dump).
            errno=EINTR
 SIGTERM -  Esta es la señal por defecto que el comando kill
            de UN*X envía a los procesos.
            errno=EINTR

Tenga en cuenta que en el caso de todas las señales anteriores, POSIX establece que por defecto el proceso es terminado, con la adición de un volcado de memoria en el caso de la señal SIGQUIT . En otras palabras, si la aplicación que llama no anula el manejador por defecto proporcionando su propio manejador de señal, la recepción de la señal correspondiente terminará la aplicación antes de que gl_get_line() regrese.

Si gl_get_line() aborta con errno establecido a EINTR, puede averiguar qué señal causó el aborto, llamando a la siguiente función.

  int gl_last_signal(const GetLine *gl);

Esto devuelve el código numérico (ej. SIGINT) de la última señal que fue recibida durante la llamada más reciente a gl_get_line(), o -1 si no se recibieron señales.

En sistemas que lo soportan, cuando se recibe una señal SIGWINCH (cambio de ventana), gl_get_line() consulta el terminal para averiguar su nuevo tamaño, redibuja la línea de entrada actual para acomodar el nuevo tamaño, luego regresa a esperar entrada de teclado del usuario. A diferencia de otras señales, esta señal no es reenviada a la aplicación.

Finalmente, las siguientes señales causan que gl_get_line() primero restaure el terminal y el entorno de señales al que prevalecía antes de que gl_get_line() fuera llamada, luego reenvíe la señal a la aplicación. Si el proceso todavía existe después de que la señal haya sido entregada, entonces gl_get_line() reinstala sus propios manejadores de señal, cambia el terminal de vuelta a modo crudo, redisplaya la línea de entrada, y vuelve a esperar entrada de terminal del usuario.

 SIGCONT    -  Esta señal es generada cuando un proceso suspendido
               es reanudado.
 SIGPOLL    -  En sistemas SVR4, esta señal notifica al
               proceso de un evento de E/S asíncrona. Tenga en
               cuenta que bajo 4.3+BSD, SIGIO y SIGPOLL son
               lo mismo. En otros sistemas, SIGIO es ignorado
               por defecto, así que gl_get_line() no la
               atrapa por defecto.
 SIGPWR     -  Esta señal es generada cuando ocurre un fallo
               de energía (presumiblemente cuando el sistema está en un
               UPS).
 SIGALRM    -  Esta señal es generada cuando un temporizador
               expira.
 SIGUSR1    -  Una señal específica de la aplicación.
 SIGUSR2    -  Otra señal específica de la aplicación.
 SIGVTALRM  -  Esta señal es generada cuando un temporizador
               virtual expira (ver man setitimer(2)).
 SIGXCPU    -  Esta señal es generada cuando un proceso
               excede su límite de tiempo de CPU suave.
 SIGXFSZ    -  Esta señal es generada cuando un proceso
               excede su límite de tamaño de archivo suave.
 SIGTSTP    -  Esta señal es generada por la tecla de suspensión
               del terminal, que usualmente es ^Z, o la
               tecla de suspensión retrasada del terminal, que
               usualmente es ^Y.
 SIGTTIN    -  Esta señal es generada si el programa
               intenta leer del terminal mientras el
               programa se está ejecutando en segundo plano.
 SIGTTOU    -  Esta señal es generada si el programa
               intenta escribir en el terminal mientras el
               programa se está ejecutando en segundo plano.

Obviamente no todas las señales anteriores son soportadas en todos los sistemas, así que el código para soportarlas es compilado condicionalmente en la biblioteca tecla.

Tenga en cuenta que si SIGKILL o SIGPOLL, que por definición no pueden ser capturadas, o cualquiera de las señales de excepción generadas por hardware, como SIGSEGV, SIGBUS y SIGFPE, son recibidas y no manejadas mientras gl_get_line() tiene el terminal en modo crudo, el programa será terminado sin que el terminal haya sido restaurado a un estado utilizable. En la práctica, los shells con control de trabajos usualmente restablecen la configuración del terminal cuando un proceso renuncia al terminal de control, así que esto es solo un problema con shells más antiguos.

MANEJO PERSONALIZADO DE SEÑALES

La sección anterior listó las señales que gl_get_line() atrapa por defecto, y describió cómo responde a ellas. Esta sección describe cómo tanto agregar como remover señales de la lista de señales atrapadas, y cómo especificar cómo gl_get_line() debería responder a una señal dada.

Si no necesita que gl_get_line() haga algo en respuesta a una señal que normalmente atrapa, puede decirle a gl_get_line() que ignore esa señal llamando a gl_ignore_signal().

  int gl_ignore_signal(GetLine *gl, int signo);

El signo argumento es el número de la señal (ej. SIGINT) que quiere que sea ignorada. Si la señal especificada no es actualmente una de las que están siendo atrapadas, esta función no hace nada.

La función gl_trap_signal() le permite tanto agregar una nueva señal a la lista que gl_get_line() atrapa, como modificar cómo

gl_trap_signal

Sets up an application's signal handler to be invoked whenever a gl_get_line is called, and the signal is received.

  int gl_trap_signal(GetLine *gl, int signo, unsigned flags,
                     GlAfterSignal after, int errno_value);

El argumento signo es el número de la señal que desea que sea capturada. El argumento flags es un conjunto de banderas que determinan el entorno en el que se invoca el manejador de señales de la aplicación, el argumento after indica a gl_get_line() qué hacer después de que el manejador de señales de la aplicación regrese, y errno_value indica a gl_get_line() qué establecer en errno si se le indica que aborte.

El argumento flags es una OR a nivel de bits de cero o más de los siguientes enumeradores:

  GLS_RESTORE_SIG  -  Restaurar el entorno de señales del
                      llamador mientras se maneja la
                      señal.
  GLS_RESTORE_TTY  -  Restaurar la configuración de la terminal
                      del llamador mientras se maneja la
                      señal.
  GLS_RESTORE_LINE -  Mover el cursor al inicio de la línea
                      siguiente a la línea de entrada antes
                      de invocar el manejador de señales de
                      la aplicación.
  GLS_REDRAW_LINE  -  Redibujar la línea de entrada cuando el
                      manejador de señales de la aplicación
                      regresa.
  GLS_UNBLOCK_SIG  -  Normalmente, si el programa llamador tiene
                      una señal bloqueada (man sigprocmask),
                      gl_get_line() no captura esa señal.
                      Esta bandera indica a gl_get_line()
                      que capture la señal y la desbloquee
                      durante la duración de la llamada a
                      gl_get_line().
  GLS_DONT_FORWARD -  Si se incluye esta bandera, la señal no
                      será reenviada al manejador de señales
                      del programa llamador.

Dos combinaciones de banderas comúnmente útiles también se enumeran como sigue:

  GLS_RESTORE_ENV   = GLS_RESTORE_SIG | GLS_RESTORE_TTY |
                      GLS_REDRAW_LINE
  GLS_SUSPEND_INPUT = GLS_RESTORE_ENV | GLS_RESTORE_LINE

Si su manejador de señales, o el manejador de señales del sistema por defecto para esta señal, si no lo ha anulado, nunca escribe en la terminal, ni suspende o termina el programa llamador, entonces puede establecer seguramente el argumento flags a 0.

Si su manejador de señales siempre escribe en la terminal, lee de ella, o suspende o termina el programa, debe especificar el argumento flags como GL_SUSPEND_INPUT, para que:

1. El cursor no se quede en medio de la línea de entrada.
2. Para que el usuario pueda escribir entrada y que se refleje.
3. Para que no necesite terminar cada línea de salida con
   \r\n, en lugar de solo \n.

La combinación GL_RESTORE_ENV es la misma que GL_SUSPEND_INPUT, excepto que no mueve el cursor, y si su manejador de señales no lee ni escribe nada en la terminal, el usuario no verá ninguna indicación visible de que se atrapó una señal. Esto puede ser útil si tiene un manejador de señales que ocasionalmente escribe en la terminal, donde usar GL_SUSPEND_LINE causaría que la línea de entrada se duplicara innecesariamente cuando no se había escrito nada en la terminal. Dicho manejador de señales, cuando escribe en la terminal, debe asegurarse de comenzar una nueva línea al principio de su primera escritura, escribiendo una nueva línea antes de regresar. Si la señal llega mientras el usuario está ingresando una línea que solo ocupa una línea de terminal de señal, o si el cursor está en la última línea de terminal de una línea de entrada más larga, esto tendrá el mismo efecto que GL_SUSPEND_INPUT. De lo contrario, comenzará a escribir en una línea que ya contiene parte de la línea de entrada mostrada. Esto no causa ningún daño, pero se ve un poco feo, por lo que la combinación GL_SUSPEND_INPUT es mejor si sabe que siempre va a escribir en la terminal.

El argumento after, que determina qué hace gl_get_line() después de que regresa el manejador de señales de la aplicación (si regresa), puede tomar cualquiera de los siguientes valores:

  GLS_RETURN   - Devolver la línea de entrada completada, como
                 si el usuario hubiera presionado la tecla
                 enter.
  GLS_ABORT    - Hacer que gl_get_line() aborte. Cuando
                 esto sucede, gl_get_line() devuelve
                 NULL, y una llamada posterior a
                 gl_return_status() devolverá
                 GLR_SIGNAL. Tenga en cuenta que si la
                 aplicación necesita que errno siempre
                 tenga un valor significativo cuando
                 gl_get_line() devuelve NULL,
                 la función de devolución de llamada debe
                 establecer errno apropiadamente.
  GLS_CONTINUE - Reanudar la edición de la línea de comandos.

El argumento errno_value está destinado a combinarse con la opción GLS_ABORT, indicando a gl_get_line() qué establecer en la variable estándar errno antes de devolver NULL al programa llamador. Sin embargo, también se puede usar con la opción GL_RETURN, en caso de que desee tener una forma de distinguir entre una línea de entrada que se ingresó usando la tecla enter y una que se ingresó por la recepción de una señal.

MANEJO CONFIABLE DE SEÑALES

El manejo de señales es sorprendentemente difícil de hacer de manera confiable sin condiciones de carrera. En gl_get_line() se ha tomado mucho cuidado para permitir que las aplicaciones realicen un manejo de señales confiable alrededor de gl_get_line(). Esta sección explica cómo aprovechar esto.

Como ejemplo de los problemas que pueden surgir si la aplicación no está escrita correctamente, imagine que una aplicación tiene un manejador de señal SIGINT que establece una bandera global. Ahora suponga que la aplicación prueba esta bandera justo antes de invocar gl_get_line(). Si una señal SIGINT se recibe en la pequeña ventana de tiempo entre la declaración que prueba el valor de esta bandera y la declaración que llama a gl_get_line(), entonces gl_get_line() no verá la señal y no será interrumpida. Como resultado, la aplicación no podrá responder a la señal hasta que el usuario termine de ingresar la línea de entrada y gl_get_line() regrese. Dependiendo de la aplicación, esto puede ser o no un desastre, pero al menos desconcertará al usuario.

La forma de evitar tales problemas es hacer lo siguiente.

1. Si es necesario, utilice la función gl_trap_signal() para
configurar gl_get_line() para que aborte cuando se
atrapan señales importantes.

2. Configure gl_get_line() para que si alguna de las
señales que captura está bloqueada cuando
se llama a gl_get_line(), se desbloqueen
automáticamente durante los momentos en que
gl_get_line() está esperando E/S. Esto se puede
hacer, ya sea por señal individual, llamando a la
función gl_trap_signal() y especificando el
atributo GLS_UNBLOCK de la señal, o globalmente
llamando a la función gl_catch_blocked().

     void gl_catch_blocked(GetLine *gl);


Esta función simplemente agrega el atributo GLS_UNBLOCK
a todas las señales que actualmente está configurada para
capturar.

3. Justo antes de llamar a gl_get_line(), bloquee la entrega
de todas las señales que gl_get_line() está
configurada para capturar. Esto se puede hacer usando la
función POSIX sigprocmask() en conjunto con la
función gl_list_signals().

      int gl_list_signals(GetLine *gl, sigset_t *set);


Esta función devuelve el conjunto de señales que actualmente
está configurada para capturar en el argumento set,
que está en el formato requerido por sigprocmask().

4. En el ejemplo, ahora se probaría la bandera global que el
manejador de señales establece, sabiendo que ahora no hay
peligro de que esta bandera se establezca nuevamente hasta
que gl_get_line() desbloquee sus señales mientras
realiza E/S.

5. Finalmente gl_get_line() regresa, ya sea porque
se atrapó una señal, ocurrió un error, o el usuario
terminó de ingresar su línea de entrada.

6. Ahora se volvería a verificar la bandera global de señal y, si
está establecida, se respondería a ella y se pondría a cero
la bandera.

7. Use sigprocmask() para desbloquear las señales que
fueron bloqueadas en el paso 3.

La misma técnica se puede utilizar alrededor de ciertas funciones conscientes de señales POSIX, como sigsetjmp() y sigsuspend(), y en particular, la primera de estas dos funciones se puede usar en conjunto con siglongjmp() para implementar el manejo de señales libre de condiciones de carrera alrededor de otras llamadas de sistema de larga duración. La forma de hacer esto se explica a continuación, mostrando cómo gl_get_line() logra capturar señales de manera confiable alrededor de llamadas a funciones como read() y select() sin condiciones de carrera.

Lo primero que hace gl_get_line(), cada vez que se llama, es usar la función POSIX sigprocmask() para bloquear la entrega de todas las señales que está configurada para capturar. Esto es redundante si la aplicación ya las ha bloqueado, pero no causa daño. Deshace este paso justo antes de regresar.

Cada vez que gl_get_line() necesita llamar a read() o select() para esperar la entrada del usuario, primero llama a la función POSIX sigsetjmp(), asegurándose de especificar un valor distinto de cero para su argumento savesigs. La razón del último argumento se aclarará pronto.

Si sigsetjmp() devuelve cero, gl_get_line() hace lo siguiente.

a. Utiliza la función POSIX sigaction() para registrar
   un manejador de señales temporal para todas las señales que
   está configurada para capturar. Este manejador de señales hace
   dos cosas.
   1. Registra el número de la señal que se recibió
      en una variable a nivel de archivo.
   2. Luego llama a la función POSIX siglongjmp()
      usando el búfer que se pasó a sigsetjmp()
      como primer argumento, y un valor distinto de cero
      como segundo argumento.
   Cuando se registra este manejador de señales, el miembro
   sa_mask del argumento struct sigaction act
   de la llamada a sigaction() se configura para
   contener todas las señales que gl_get_line() está
   capturando. Esto asegura que solo una señal será capturada
   a la vez por nuestro manejador de señales, lo que a su vez
   asegura que múltiples instancias de nuestro manejador de
   señales no se pisen los talones.
b. Ahora que el manejador de señales ha sido configurado,
   gl_get_line() desbloquea todas las señales que está
   configurada para capturar.
c. Luego llama a las llamadas del sistema read() o select()
   para esperar la entrada del teclado.
d. Si esta llamada del sistema regresa (es decir, no se recibe
   ninguna señal), gl_get_line() vuelve a bloquear la
   entrega de las señales de interés.
e. Luego restaura los manejadores de señales que fueron
   desplazados por el que se acaba de instalar.

Alternativamente, si sigsetjmp() devuelve un valor distinto de cero, esto significa que

que una de las señales interceptadas fue capturada mientras se ejecutaban los pasos anteriores. Cuando esto sucede, gl_get_line() hace lo siguiente.

Primero, tenga en cuenta que cuando una llamada a siglongjmp() hace que sigsetjmp() retorne, siempre que el argumento savesigs de sigsetjmp() fuera distinto de cero, como se especificó anteriormente, la máscara de proceso de señales se restaura al estado en que se encontraba cuando se llamó a sigsetjmp() . Esta es la diferencia importante entre sigsetjmp() y el antiguo y problemático setjmp(), y es el ingrediente esencial que hace posible evitar condiciones de carrera en el manejo de señales. Debido a esto, se garantiza que todas las señales que bloqueamos antes de llamar a sigsetjmp() estén bloqueadas de nuevo tan pronto como se capture cualquier señal. Las siguientes instrucciones, que se ejecutan a continuación, se garantiza por tanto que se ejecuten sin que se capturen más señales.

1. Si así lo indican los gl_get_line() atributos de configuración de la señal que fue capturada,
gl_get_line()
restaura los atributos del terminal al estado en que se encontraban cuando se
llamó a gl_get_line() . Esto es particularmente importante para las señales que
suspenden o terminan el proceso, ya que de lo contrario el
terminal quedaría en un estado inutilizable.
2. A continuación, restablece los manejadores de señales de la aplicación.

3. Luego utiliza la función

raise() de la biblioteca estándar de C para reenviar a la aplicación la señal que
fue capturada.
3. A continuación, desbloquea la entrega de la señal que acabamos de

enviar. Esto resulta en que la señal que acabó de ser enviada
vía
raise() , sea capturada por el manejador de señalesoriginal de la aplicación, que ahora puede manejarla como
considere oportuno.
4. Si el manejador de señales retorna (es decir, no termina

el proceso),
gl_get_line() bloquea la entrega de la señal mencionada anteriormente de nuevo.
5. A continuación, deshace cualquier acción realizada en el primero de los

pasos anteriores, y vuelve a mostrar la línea, si la configuración de la señal
lo requiere.
6.

gl_get_line() luego retoma el intento de leer un carácter, o se aborta, dependiendo de la
configuración de la señal que fue capturada.
Lo que los pasos anteriores hacen en esencia es tomar señales entregadas de forma asíncrona y manejarlas de forma síncrona, una a la vez, en un punto del código donde

gl_get_line() tiene control total sobre su entorno. EL TAMAÑO DEL TERMINAL

En la mayoría de los sistemas, la combinación del

ioctl TIOCGWINSZ y la señal SIGWINCH se utiliza para mantener una idea precisa del tamaño del terminal. El tamaño del terminal se consulta cada vez que se llama a gl_get_line() y siempre que se recibe una señal SIGWINCH . En los pocos sistemas donde este mecanismo no está disponible, al inicio

new_GetLine() primero busca las variables de entorno LINES y COLUMNS . Si no se encuentran, o contienen valores inutilizables, entonces si está disponible una base de datos de información de terminal como terminfo o termcap, se busca el tamaño por defecto del terminal en esta base de datos. Si esto tampoco proporciona el tamaño del terminal, se utiliza un tamaño por defecto de 80 columnas por 24 líneas. Incluso en sistemas que sí admiten

ioctl(TIOCGWINSZ) , si el terminal está en el otro extremo de una línea serie, el controlador del terminal generalmente no tiene forma de detectar cuándo ocurre un redimensionamiento ni de consultar cuál es el tamaño actual. En tales casos no se envía ninguna señalSIGWINCH al proceso, y las dimensiones devueltas por ioctl(TIOCGWINSZ) no son correctas. La única forma de manejar tales casos es proporcionar una manera para que el usuario introduzca un comando que le indique al sistema remoto cuál es el nuevo tamaño. Este comando llamaría entonces a la función gl_set_term_size() para informar a gl_get_line() sobre el cambio de tamaño. int gl_set_term_size(GetLine *gl, int ncolumn, int nline);

  Los argumentos

ncolumn y nline se utilizan para especificar las nuevas dimensiones del terminal, y no deben ser menores que 1. En sistemas que sí admiten ioctl(TIOCGWINSZ) , esta función primero llama aioctl(TIOCSWINSZ) para informar al controlador del terminal sobre el cambio en el tamaño. En el modo de E/S de servidor no bloqueante, si actualmente se está introduciendo una línea, la línea de entrada se redibuja para acomodar el tamaño cambiado. Finalmente, los nuevos valores se registran en gl para uso futuro por parte de gl_get_line() .La función

gl_terminal_size() le permite consultar el tamaño actual del terminal, e instalar un tamaño alternativo de reserva para los casos en que el tamaño no esté disponible. Tenga en cuenta que el tamaño del terminal no estará disponible si se lee de una tubería o de un archivo, por lo que los valores por defecto pueden ser importantes incluso en sistemas que sí admiten formas de averiguar el tamaño del terminal. typedef struct { int nline; /* El terminal tiene nline líneas */ int ncolumn; /* El terminal tiene ncolumn columnas */ } GlTerminalSize; GlTerminalSize gl_terminal_size(GetLine *gl, int def_ncolumn, int def_nline);

  Esta función primero actualiza las dimensiones de terminal de reserva de

gl_get_line() , y luego registra sus hallazgos en el valor de retorno.Los argumentos

def_ncolumn y def_nline especifican el número por defecto de columnas y líneas del terminal a utilizar si el tamaño del terminal no se puede determinar vía ioctl(TIOCGWINSZ) o variables de entorno. OCULTANDO LO QUE ESCRIBES

Al introducir información sensible, como contraseñas, es mejor no tener el texto que está introduciendo reflejado en el terminal. Además, dicho texto no debería registrarse en la lista de historial, ya que alguien que encuentre su terminal desatendida podría recuperarlo, o alguien que esté explorando sus directorios podría verlo en su archivo de historial. Teniendo esto en cuenta, la función

gl_echo_mode() le permite activar y desactivar la visualización y el archivo de cualquier texto que se introduzca posteriormente en las llamadas a gl_get_line() .int gl_echo_mode(GetLine *gl, int enable);

  El argumento

enable especifica si el texto introducido debe ser visible o no. Si es 0 , entonces las líneas introducidas posteriormente no serán visibles en el terminal, y no se registrarán en la lista de historial. Si es1 , entonces las líneas de entrada posteriores se mostrarán a medida que se introduzcan, y siempre que el historial no se haya desactivado mediante una llamada agl_toggle_history() , también se archivarán en la lista de historial. Finalmente, si el argumentoenable es -1 , entonces el modo de eco se deja sin cambios, lo que le permite consultar de forma no destructiva la configuración actual a través del valor de retorno. En todos los casos, el valor de retorno de la función es0 si el eco estaba desactivado antes de que se llamara a la función, y 1 si estaba activado. Cuando el eco está desactivado, tenga en cuenta que aunque la finalización con tabulador completará su prefijo de forma invisible todo lo posible, las finalizaciones ambiguas no se mostrarán.

CONSULTAS DE UN SOLO CARÁCTER

Usar

gl_get_line() para consultar al usuario sobre una respuesta de un solo carácter es inconveniente para el usuario, ya que debe presionar la tecla intro o retorno antes de que el carácter que escribió sea devuelto al programa. Por lo tanto, se ha proporcionado la función gl_query_char() para consultas de un solo carácter como esta. int gl_query_char(GetLine *gl, const char *prompt, char defchar);

  Esta función muestra el indicador especificado al comienzo de una nueva
    línea, y espera a que el usuario escriba un carácter. Cuando el usuario escribe un carácter,

gl_query_char() lo muestra a la derecha del indicador, inicia una nueva línea, y luego devuelve el carácter al programa que lo llamó. El valor de retorno de la función es el carácter que fue escrito. Si la lectura tuvo que abortarse por alguna razón, EOF se devuelve en su lugar. En este último caso, la aplicación puede llamar a la función previamente documentada gl_return_status() , para averiguar qué salió mal. Esto podría haber sido, por ejemplo, la recepción de una señal, o el temporizador opcional de inactividad activándose.Si el usuario simplemente presiona intro, se sustituye el valor del argumento

defchar . Esto significa que cuando el usuario presiona retorno de línea o retorno, el carácter especificado en defchar se muestra después del indicador, como si el usuario lo hubiera escrito, así como se devuelve a la aplicación que lo llamó. Si tal sustitución no es importante, simplemente pase'0 como el valor de defchar .Si el carácter introducido es un carácter no imprimible, se muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y los caracteres por encima de 127 se muestran en octal, precedidos por una barra invertida.

Al igual que con

gl_get_line() , el eco del carácter introducido puede desactivarse usando la funcióngl_echo_mode() . Si el proceso que llama se suspende mientras espera a que el usuario escriba su respuesta, el cursor se mueve a la línea siguiente a la línea del indicador, y luego cuando el proceso se reanuda, el indicador se vuelve a mostrar, y

gl_query_char() reanuda la espera de que el usuario escriba un carácter. Tenga en cuenta que en el modo de servidor no bloqueante, (véase gl_io_mode(3)), si una línea de entrada incompleta está en proceso de lectura cuando se

llama a gl_query_char() , la línea de entrada parcial se descarta, y se borra del terminal, antes de que se muestre el nuevo indicador. La siguiente llamada a gl_get_line() comenzará por tanto a editar una nueva línea.

LEYENDO CARACTERES CRUDOS

Mientras que la función gl_query_char() solicita visiblemente al usuario un carácter, y muestra lo que escribió, la función gl_read_char() lee un carácter del usuario, sin escribir nada en el terminal, ni perturbar ninguna línea de entrada incompleta. Esto significa que puede llamarse no solo entre llamadas a gl_get_line(), sino también desde funciones de retorno que la aplicación haya registrado para ser llamadas por gl_get_line().

  int gl_read_char(GetLine *gl);

En caso de éxito, el valor de retorno de gl_read_char() es el carácter que fue leído. En caso de fallo, EOF se devuelve, y la función gl_return_status() puede ser llamada para averiguar qué salió mal. Las posibilidades incluyen el temporizador opcional de inactividad activándose, la recepción de una señal configurada para abortar gl_get_line(), o el bloqueo de E/S del terminal, cuando se está en el modo de E/S de servidor no bloqueante.

Tenga en cuenta que ciertas teclas del teclado, como las teclas de función y las teclas de cursor, suelen generar al menos 3 caracteres cada una, por lo que una sola llamada a gl_read_char()> no será suficiente para identificar tales pulsaciones de teclas.

LIMPIANDO LA TERMINAL

El programa que llama puede limpiar la terminal llamando a gl_erase_terminal(). En el modo de E/S de servidor no bloqueante, esta función también organiza que la línea de entrada actual se redibuje desde cero cuando se llame a gl_get_line() la próxima vez.

  int gl_erase_terminal(GetLine *gl);

MOSTRANDO TEXTO DINAMICAMENTE

Entre llamadas a gl_get_line(), la función gl_display_text() proporciona una forma conveniente de mostrar párrafos de texto, justificados a la izquierda y divididos en una o más líneas de terminal según las restricciones del ancho actual de la terminal. Ejemplos del uso de esta función se pueden encontrar en los programas de demostración, donde se utiliza para mostrar introducciones. En esos ejemplos, también se ilustra el uso avanzado de prefijos, sufijos y líneas de relleno opcionales para dibujar un cuadro alrededor del texto.

  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string);

Si gl no está actualmente conectado a una terminal, por ejemplo, si la salida de un programa que usa gl_get_line() se está canalizando a otro programa o se está redirigiendo a un archivo, entonces el valor del parámetro def_width se usa como el ancho de la terminal.

El argumento indentation especifica el número de caracteres que se utilizarán para indentar cada línea de salida. El argumento fill_char especifica el carácter que se utilizará para realizar esta indentación.

El argumento prefix puede ser NULL, o una cadena que se colocará al principio de cada nueva línea (después de cualquier indentación). De manera similar, el argumento suffix puede ser NULL, o una cadena que se colocará al final de cada línea. El sufijo se coloca pegado al borde derecho de la terminal, y cualquier espacio entre su primer carácter y la última palabra de esa línea se rellena con el carácter especificado a través del argumento fill_char. Normalmente, el carácter de relleno es un espacio.

El argumento start indica a gl_display_text() cuántos caracteres ya se han escrito en la línea de terminal actual, y por lo tanto le indica el índice de columna de inicio del cursor. Dado que el valor de retorno de gl_display_text() es el índice de columna final del cursor, al pasar el valor de retorno de una llamada al argumento start de la siguiente llamada, se puede componer un párrafo que se divide entre más de una cadena llamando a gl_display_text() para cada porción sucesiva del párrafo. Tenga en cuenta que los caracteres de nueva línea literales son necesarios al final de cada párrafo para forzar el inicio de una nueva línea.

En caso de error, gl_display_text() devuelve -1.

INSTALACIONES DE FUNCIONES DE LLAMADA

A menos que se indique lo contrario, las funciones de llamada, como las funciones de llamada de finalización de tabulación y las funciones de llamada de eventos, no deben llamar a ninguna función de este módulo. Las siguientes funciones, sin embargo, están diseñadas específicamente para ser utilizadas por funciones de llamada.

Llamar a la función gl_replace_prompt() desde una función de llamada le indica a gl_get_line() que muestre un prompt diferente cuando la función de llamada regrese. Excepto en el modo de servidor no bloqueante, no tiene ningún efecto si se utiliza entre llamadas a gl_get_line(). En el modo de servidor no bloqueante (consulte la página del manual gl_io_mode(3), cuando se utiliza entre dos llamadas a gl_get_line() que operan sobre la misma línea de entrada, la línea de entrada actual se redibujará con el nuevo prompt en la siguiente llamada a gl_get_line().

  void gl_replace_prompt(GetLine *gl, const char *prompt);

JUEGOS DE CARACTERES INTERNACIONALES

Desde la versión 1.4.0 de libtecla, gl_get_line() es limpio en 8 bits. Esto significa que todos los caracteres de 8 bits que son imprimibles en la configuración regional actual del usuario se muestran ahora textualmente y se incluyen en la línea de entrada devuelta. Suponiendo que el programa que llama contiene correctamente una llamada como la siguiente,

  setlocale(LC_CTYPE, "");

entonces la configuración regional actual se determina por la primera de las variables de entorno LC_CTYPE, LC_ALL y LANG, que se encuentra que contiene un nombre de configuración regional válido. Si ninguna de estas variables está definida, o si el programa omite llamar a setlocale, entonces se utiliza la configuración regional predeterminada C, que es ASCII de 7 bits de EE. UU. En la mayoría de las plataformas tipo Unix, puede obtener una lista de configuraciones regionales válidas escribiendo el comando:

  locale -a

en el prompt del shell. Puede encontrar más documentación sobre cómo el usuario puede hacer uso de esto para ingresar caracteres internacionales en la página del manual tecla(7).

SEGURIDAD EN HILOS

En un programa multihilo, debe usar la versión libtecla_r.a de la biblioteca. Esta utiliza versiones reentrantes de las funciones del sistema, cuando están disponibles. Desafortunadamente, ni terminfo ni termcap fueron diseñados para ser reentrantes, por lo que no puede usar de forma segura las funciones del módulo getline en múltiples hilos (puede usar los módulos separados de expansión de archivos y finalización de palabras en múltiples hilos, consulte las páginas del manual correspondientes para obtener detalles). Sin embargo, debido al uso de funciones reentrantes POSIX para buscar directorios de inicio, etc., es seguro usar este módulo desde un solo hilo de un programa multihilo, siempre que sus otros hilos no utilicen ninguna función de termcap o terminfo.
