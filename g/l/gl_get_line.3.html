DESCRIPCIÓN

La función gl_get_line() forma parte de la biblioteca tecla (ver la página del manual libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le solicita una línea de entrada, luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de Unix. Además de la edición simple de la línea de comandos, admite la recuperación de líneas de comandos ingresadas previamente, la autocompletación con TAB de nombres de archivo y la expansión de comodines en línea de nombres de archivo. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario, se puede encontrar en la página del manual tecla(7). Esta página del manual se centra en la documentación para programadores interesados en utilizar esta biblioteca en su aplicación.

UN EJEMPLO

El siguiente muestra un ejemplo completo de cómo usar la función gl_get_line() para obtener entrada del usuario:

  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que el usuario escribió */
    GetLine *gl;   /* El objeto de recursos de gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* de conjunto de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("Escribiste: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
  }

En el ejemplo, primero se crean los recursos necesarios para la función gl_get_line() llamando a new_GetLine(). Esto asigna la memoria utilizada en llamadas posteriores a la función gl_get_line(), incluido el búfer de historial para registrar líneas ingresadas previamente. Luego se leen una o más líneas del usuario, hasta que ocurre un error o el usuario escribe exit. Luego, finalmente, los recursos que fueron asignados por new_GetLine() se devuelven al sistema llamando a del_GetLine(). Tenga en cuenta el uso del valor de retorno NULL de del_GetLine() para hacer que gl sea NULL. Esto es una medida de seguridad. Si el programa intenta posteriormente pasar gl a gl_get_line(), dicha función se quejará y devolverá un error, en lugar de intentar utilizar el objeto de recurso eliminado.

LAS FUNCIONES UTILIZADAS EN EL EJEMPLO

Las descripciones de las funciones utilizadas en el ejemplo son las siguientes:

  GetLine *new_GetLine(size_t linelen, size_t histlen)

Esta función crea los recursos utilizados por la función gl_get_line() y devuelve un puntero opaco al objeto que los contiene. La longitud máxima de una línea de entrada se especifica a través del argumento linelen, y el número de bytes a asignar para almacenar líneas de historial se establece mediante el argumento histlen. Las líneas de historial se almacenan una detrás de otra en un único búfer de este tamaño. Tenga en cuenta que esto significa que el número de líneas de historial que se pueden almacenar en cualquier momento dado, depende de las longitudes de las líneas individuales. Si desea establecer un límite superior en el número de líneas que se pueden almacenar, consulte la función gl_limit_history() descrita más adelante. Si no desea historial en absoluto, especifique histlen como cero, y no se asignará ningún búfer de historial.

En caso de error, se imprime un mensaje en stderr y se devuelve NULL.

  GetLine *del_GetLine(GetLine *gl)

Esta función elimina los recursos que fueron devueltos por una llamada anterior a new_GetLine(). Siempre devuelve NULL (es decir, un objeto eliminado). No hace nada si el argumento gl es NULL.

  char *gl_get_line(GetLine *gl, const char *prompt,
                   const char *start_line, int start_pos);

La función gl_get_line() puede ser llamada cualquier número de veces para leer entrada del usuario. El argumento gl debe haber sido devuelto previamente por una llamada a new_GetLine(). El argumento prompt debe ser una cadena normal terminada en NUL, que especifica el aviso que se presentará al usuario. Por defecto, los avisos se muestran literalmente, pero si se habilitan con la función gl_prompt_style() (ver más adelante), los avisos pueden contener directivas para hacer subrayados, cambiar a y desde fuentes en negrita, o activar y desactivar el resaltado.

Si desea especificar el contenido inicial de la línea, para que el usuario lo edite, pase la cadena deseada a través del argumento start_line. Puede especificar entonces en qué carácter de esta línea se posiciona inicialmente el cursor

r, usando el argumento start_pos. Este debe ser -1 si desea que el cursor siga al último carácter de la línea de inicio. Si no desea precargar la línea de esta manera, envíe start_line como NULL, y establezca start_pos a -1. Tenga en cuenta que el puntero a la línea devuelto por una llamada a gl_get_line() puede pasarse a la siguiente llamada a gl_get_line() a través de start_line. Esto permite que la aplicación tome la última línea introducida y, si contiene un error, presentarla de nuevo al usuario para su reedición, con el cursor inicialmente posicionado donde se encontró el

error.

La función gl_get_line() devuelve un puntero a la línea introducida por el usuario, o NULL en caso de error o al final de la entrada. El puntero devuelto es parte del objeto de recurso gl especificado, y por lo tanto no debe ser liberado por el llamante, ni asumirse que es invariable de una llamada a la siguiente. Al leer de un usuario en una terminal, siempre habrá un carácter de salto de línea al final de la línea devuelta. Cuando la entrada estándar se toma de una tubería o de un archivo, de manera similar habrá un salto de línea a menos que la línea de entrada fuera demasiado larga para almacenarse en el búfer interno. En este último caso, debe llamar a gl_get_line() de nuevo para leer el resto de la línea. Tenga en cuenta que este comportamiento hace que gl_get_line() sea similar a fgets(). De hecho, cuando stdin no está conectado a una terminal,gl_get_line() simplemente llama a fget

s().

FUENTES DE CONFIGURACIÓN

ALTERNATIVAS

Como se mencionó anteriormente, de forma predeterminada los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. En algunas aplicaciones, sin embargo, este único medio de configuración es un problema. Esto es particularmente cierto en software embebido, donde no hay un sistema de archivos del cual leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de combinaciones de teclas para emular una interfaz de teclado heredada. Para atender a tales casos, la siguiente función permite a la aplicación controlar desde dónde se lee la información de

configuración. 
  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file)
;

Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc del usuario, se lean de una o ninguna de las siguientes fuentes: una cadena, un archivo de configuración específico de la aplicación, y/o un archivo de configuración específico del usuario. Si esta función se llama antes de la primera llamada a gl_get_line(), el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line() se deshabilita, por lo que toda la configuración debe lograrse utilizando las fuentes de configuración especificadas con esta

función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados entre sí en la cadena por caracteres de salto de línea incrustados. Si app_file != NULL entonces se interpreta como la ruta de archivo completa de un archivo de configuración específico de la aplicación. Si user_file != NULL entonces se interpreta como la ruta de archivo completa de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente

llamada, 
  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc")
;

el argumento app_string hace que la aplicación que llama comience en el modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso de la campana de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración de todo el sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario desde un archivo .teclarc opcional en el directorio de inicio del usuario. Tenga en cuenta que los argumentos se listan en orden ascendente de prioridad, con el contenido de app_string siendo potencialmente sobrescrito por comandos en app_file, y los comandos en app_file potencialmente siendo sobrescritos por comandos en user_file

.

Puede llamar a esta función tantas veces como sea necesario, con resultados acumulativos, pero tenga en cuenta que las copias de cualquier nombre de archivo especificado a través de app_file y los argumentos user_file se registran internamente para su uso posterior por parte de la función de enlace de teclas read-init-files, así que si planea llamar a esta función varias veces, asegúrese de que la última llamada especifique los nombres de archivo que desea que se vuelvan a leer cuando el usuario solicite que los archivos de configuración se vuelvan a

leer.

Las secuencias de teclas individuales también se pueden vincular y desvincular usando la función gl_bind_keyseq()

. 
  int gl_bind_keyseq(GetLine *gl, GlKeyOrigin origin,
                     const char *keyseq,
                     const char *action)
;

El argumento origin especifica la prioridad de la vinculación, según para quién se está estableciendo, y debe ser uno de los siguientes dos

valores. 
  GL_USER_KEY   -   El usuario solicitó esta vinculación de teclas.
  GL_APP_KEY    -   Esta es una vinculación predeterminada establecida por la
aplicación.

Cuando se han especificado tanto la vinculación del usuario como la de la aplicación para una secuencia de teclas dada, la vinculación del usuario tiene prioridad. La vinculación de la aplicación se restablece posteriormente si la vinculación del usuario se desvincula más tarde ya sea mediante otra llamada a esta función, o una llamada a gl_configure_ge

tline().

El argumento keyseq especifica la secuencia de teclas a vincular o desvincular, y se expresa de la misma manera que en un archivo de configuración ~/.teclarc. El argumento action debe ser una cadena que contenga el nombre de la acción a la que vincular la secuencia de teclas, o debe ser NULL o "" para desvincula

r la secuenci
a de teclas.

COMPLETADO DE PALABRAS

PERSONALIZADO

Si en su aplicación le gustaría que la completación con TAB complete otras cosas además de o en lugar de nombres de archivo, puede organizar esto registrando una función de retorno de completación alternativa, mediante una llamada a la función gl_customize_co

mpletion(). 
  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn)
;

El argumento data proporciona una manera para que su aplicación pase información arbitraria y específica de la aplicación a la función de retorno. Esto se pasa a la función de retorno cada vez que se llama. Podría, por ejemplo, apuntar a la tabla de símbolos de la que se deben buscar las posibles completaciones. El argumento match_fn especifica la función de retorno a llamar. El tipo de función CplMatchFn está definido en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y prototipar funciones de retorno. La declaración y las responsabilidades de las funciones de retorno se describen en profundidad en la página del manual cpl_complete_word(3)

.

En resumen, la función de retorno es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario presionó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar las posibles completaciones de esta palabra y registrarlas una por una en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion(). Si la función de retorno desea proporcionar completación de nombres de archivo además de sus propias completaciones específicas, tiene la opción de llamar ella misma a la función de retorno de completación de nombres de archivo incorporada. Esto también está documentado en la página del manual cpl_complete_word(3)

.

Tenga en cuenta que si le gustaría que gl_get_line() devuelva la línea de entrada actual cuando se haya realizado una completación exitosa, puede organizar esto cuando llame a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de salto de línea. Si hace esto, la línea de entrada se actualizará para mostrar la completación, junto con cualquier sufijo de continuación hasta el carácter de salto de línea, luego gl_get_line() devolverá esta línea de

entrada.

Si, por alguna razón, su función de retorno necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto iniciará una nueva línea después de la línea de entrada que se está editando actualmente, restablecerá la E/S normal de la terminal y le dirá a gl_get_line() que la línea de entrada necesitará

ser redibujada cuando la f
unción de retorno regrese.

AÑADIENDO ACCIONES DE

COMPLETACIÓN

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de completación predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que diferentes tipos de completación de palabras se puedan vincular a diferentes secuencias de teclas. Esto se logra usando la función gl_completion_action()

. 
  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq)
;

Los argumentos data y match_fn se describen en la página del manual cpl_complete_word, y especifican la función de retorno que debe invocarse para identificar las posibles completaciones. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar cualquier posible completación ambigua, o si simplemente debe mostrar la lista de posibles completaciones sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre con el que los archivos de configuración y las futuras invocaciones de esta función deben referirse a la acción. Este debe ser el nombre de una acción de completación existente que se va a cambiar, o un nombre nuevo sin usar para una nueva acción. acción.

               GlAfterTimeout (fn)(GetLine *gl, void *data)

Al regresar, se espera que la función de devolución de llamada de la aplicación devuelva uno de los siguientes enumeradores para indicar a gl_get_line() cómo proceder después de que la devolución de llamada haya gestionado el tiempo de espera.

  GLTO_ABORT    -  Indica a gl_get_line() que aborte. Cuando
                   esto ocurre, gl_get_line() devolverá
                   NULL, y una llamada posterior a
                   gl_return_status() devolverá
                   GLR_TIMEOUT. Tenga en cuenta que si la
                   aplicación necesita que errno siempre
                   tenga un valor significativo cuando
                   gl_get_line() devuelve NULL,
                   la función de devolución de llamada debe
                   establecer errno apropiadamente.
  GLTO_REFRESH  -  Redibuja la línea de entrada, luego continúa
                   esperando la entrada. Debe devolver este
                   valor si su devolución de llamada escribió
                   en la terminal sin haber llamado primero a
                   gl_normal_io(gl).
  GLTO_CONTINUE -  En el modo de E/S de bloqueo normal, continúa
                   esperando la entrada, sin redibujar la
                   línea de entrada del usuario.
                   En el modo de E/S de servidor sin bloqueo
                   (ver gl_io_mode(3)), hace que
                   gl_get_line() actúe como si la E/S
                   estuviera bloqueada. Esto significa que
                   gl_get_line() devolverá inmediatamente
                   NULL, y una llamada posterior a
                   gl_return_status() devolverá
                   GLR_BLOCKED.

Tenga en cuenta que antes de llamar a la función de devolución de llamada, gl_get_line() bloquea la mayoría de las señales y deja sus propios manejadores de señales instalados, por lo que si necesita capturar una señal en particular, deberá instalar temporalmente su propio manejador de señales y desbloquear la señal. Asegúrese de volver a bloquear la señal (si estaba bloqueada originalmente) y de restaurar el manejador de señales original, si lo hubiera, antes de regresar.

Si la función de devolución de llamada necesita leer o escribir en la terminal, idealmente debería llamar primero a gl_normal_io(gl) para suspender temporalmente la edición de línea. Esto restaurará la terminal al modo canónico y de E/S de bloqueo, y moverá el cursor al inicio de una nueva línea de terminal. Más tarde, cuando la función de devolución de llamada regrese, gl_get_line() notará que se llamó a gl_normal_io(), redibujará la línea de entrada y reanudará la edición. Tenga en cuenta que en este caso, los valores de retorno GLTO_REFRESH y GLTO_CONTINUE son equivalentes.

Para admitir casos en los que la función de devolución de llamada llama a una función de terceros que ocasionalmente y de forma impredecible escribe en la terminal, la conversión automática de "0 a "0 se vuelve a habilitar antes de que se llame a la función de devolución de llamada. Si la devolución de llamada sabe que la función de terceros escribió en la terminal, debería devolver el valor de retorno GLTO_REFRESH, para indicar a gl_get_line() que redibuje la línea de entrada.

Tenga en cuenta que aunque el argumento del tiempo de espera incluye un componente de nanosegundos, pocos relojes de computadora tienen actualmente resoluciones más finas que unos pocos milisegundos, por lo que solicitar menos de unos pocos milisegundos es equivalente a solicitar cero segundos en muchos sistemas. Si esto fuera un problema, debería basar la selección de su tiempo de espera en la resolución real del reloj del host (por ejemplo, llamando a sysconf(_SC_CLK_TCK)).

Para desactivar los tiempos de espera, simplemente llame a gl_inactivity_timeout() con un argumento callback de 0. El argumento data se ignora en este caso.

Por defecto, la función gl_get_line() intercepta varias señales. Esto es particularmente importante para las señales que por defecto terminarían el proceso, ya que la terminal debe restaurarse a un estado utilizable antes de que esto suceda.             errno=EINTR

            errno=ENOTTY

            errno=EINTR

En otras palabras, si la aplicación que llama no anula el manejador predeterminado proporcionando su propio manejador de señales, la recepción de la señal correspondiente terminará la aplicación antes de que gl_get_line() regrese.

  int gl_last_signal(const GetLine *gl);

Esto devuelve el código numérico (por ejemplo, SIGINT) de la última señal recibida durante la llamada más reciente a gl_get_line(), o -1 si no se recibieron señales.

A diferencia de otras señales, esta señal no se reenvía a la aplicación.

Si el proceso aún existe después de que se haya entregado la señal, entonces gl_get_line() restablece sus propios manejadores de señales, cambia la terminal de nuevo a modo raw, redibuja la línea de entrada y vuelve a esperar la entrada de terminal del usuario.

 SIGUSR1    -  Una señal específica de la aplicación.

 SIGXFSZ    -  Esta señal se genera cuando un proceso excede

 SIGTSTP    -  Esta señal se genera por la tecla de suspensión

Obviamente, no todas las señales anteriores son compatibles en todos los sistemas, por lo que el código para admitirlas se compila condicionalmente en la biblioteca tecla.

En la práctica, los shells de control de trabajos suelen restablecer la configuración de la terminal cuando un proceso cede la terminal de control, por lo que esto solo es un problema con shells más antiguos.

El manejo de señales es sorprendentemente difícil de hacer de forma fiable sin condiciones de carrera. En gl_get_line() se ha tenido mucho cuidado para permitir a las aplicaciones realizar un manejo de señales fiable alrededor de gl_get_line(). Esta sección explica cómo hacer uso de

SEÑALES INTERRUPTORAS

Si las señales que se estaban interceptando fueron capturadas mientras se ejecutaban los pasos anteriores. Cuando esto sucede, gl_get_line() hace lo siguiente.

Primero, ten en cuenta que cuando una llamada a siglongjmp() provoca que sigsetjmp() regrese, siempre que el argumento savesigs de sigsetjmp() no sea cero, como se especifica anteriormente, la máscara de proceso de señales se restaura a como estaba cuando se llamó a sigsetjmp(). Esta es la diferencia importante entre sigsetjmp() y el problemático setjmp() más antiguo, y es el ingrediente esencial que hace posible evitar condiciones de carrera en el manejo de señales. Debido a esto, tenemos la garantía de que todas las señales que bloqueamos antes de llamar a sigsetjmp() están bloqueadas nuevamente tan pronto como se captura cualquier señal. Por lo tanto, se garantiza que las siguientes sentencias, que se ejecutan a continuación, se ejecutarán sin capturar ninguna otra señal.

1. Si así lo indican los atributos de configuración
de gl_get_line() de la señal que se capturó,
gl_get_line() restaura los atributos de la terminal al
estado que tenían cuando se llamó a
gl_get_line(). Esto es particularmente importante para
las señales que suspenden o terminan el proceso, ya que de lo
contrario la terminal quedaría en un estado inutilizable.

2. Luego, reinstaura los manejadores de señales de la aplicación.

3. Luego, utiliza la función raise() de la biblioteca
estándar de C para reenviar la señal capturada a la
aplicación.

4. A continuación, desbloquea la entrega de la señal que acabamos
de enviar. Esto da como resultado que la señal enviada a
través de raise() sea capturada por el manejador de
señales original de la aplicación, que ahora puede
manejarla como considere conveniente.

5. Si el manejador de señales regresa (es decir, no termina el
proceso), gl_get_line() vuelve a bloquear la entrega de
la señal mencionada anteriormente.

6. Luego, deshace cualquier acción realizada en el primer paso de
los mencionados anteriormente, y redibuja la línea, si la
configuración de la señal así lo requiere.

7. gl_get_line() luego reanuda el intento de leer un
carácter, o aborta, dependiendo de la configuración de la
señal capturada.

Lo que hacen los pasos anteriores en esencia es tomar señales entregadas de forma asíncrona y manejarlas de forma síncrona, una a la vez, en un punto del código donde gl_get_line() tiene control total sobre su entorno.

TAMAÑO DE LA TERMINAL

En la mayoría de los sistemas, la combinación del ioctl TIOCGWINSZ y la señal SIGWINCH se utiliza para mantener una idea precisa del tamaño de la terminal. El tamaño de la terminal se consulta cada vez que se llama a gl_get_line() y cada vez que se recibe una señal SIGWINCH.

En los pocos sistemas donde este mecanismo no está disponible, al arrancar, new_GetLine() primero busca las variables de entorno LINES y COLUMNS. Si estas no se encuentran, o contienen valores inutilizables, entonces si una base de datos de información de terminal como terminfo o termcap está disponible, se busca el tamaño predeterminado de la terminal en esta base de datos. Si esto también falla en proporcionar el tamaño de la terminal, se utiliza un tamaño predeterminado de 80 columnas por 24 líneas.

Incluso en sistemas que admiten ioctl(TIOCGWINSZ), si la terminal está al otro lado de una línea serial, el controlador de terminal generalmente no tiene forma de detectar cuándo ocurre un redimensionamiento o de consultar cuál es el tamaño actual. En tales casos, no se envía SIGWINCH al proceso y las dimensiones devueltas por ioctl(TIOCGWINSZ) no son correctas. La única forma de manejar tales instancias es proporcionar una manera para que el usuario ingrese un comando que le diga al sistema remoto cuál es el nuevo tamaño. Este comando llamaría entonces a la función gl_set_term_size() para informar a gl_get_line() sobre el cambio de tamaño.

  int gl_set_term_size(GetLine *gl, int ncolumn, int nline);

Los argumentos ncolumn y nline se utilizan para especificar las nuevas dimensiones de la terminal y no deben ser menores que 1. En sistemas que admiten ioctl(TIOCGWINSZ), esta función llama primero a ioctl(TIOCSWINSZ) para informar al controlador de terminal sobre el cambio de tamaño. En modo de E/S de servidor no bloqueante, si una línea se está ingresando actualmente, la línea de entrada se redibuja para acomodar el tamaño cambiado. Finalmente, los nuevos valores se registran en gl para uso futuro por gl_get_line().

La función gl_terminal_size() le permite consultar el tamaño actual de la terminal e instalar un tamaño de respaldo alternativo para los casos en que el tamaño no esté disponible. Tenga en cuenta que el tamaño de la terminal no estará disponible si se lee desde una tubería o un archivo, por lo que los valores predeterminados pueden ser importantes incluso en sistemas que admiten formas de averiguar el tamaño de la terminal.

  typedef struct {
    int nline;        /* La terminal tiene nline líneas */
    int ncolumn;      /* La terminal tiene ncolumn columnas */
  } GlTerminalSize;
  GlTerminalSize gl_terminal_size(GetLine *gl,
                                  int def_ncolumn,
                                  int def_nline);

Esta función primero actualiza las dimensiones de la terminal de respaldo de gl_get_line(), luego registra sus hallazgos en el valor de retorno.

Los argumentos def_ncolumn y def_nline especifican el número predeterminado de columnas y líneas de la terminal a usar si el tamaño de la terminal no se puede determinar a través de ioctl(TIOCGWINSZ) o variables de entorno.

OCULTAR LO QUE ESCRIBES

Al ingresar información confidencial, como contraseñas, es mejor no mostrar el texto que se está ingresando en la terminal. Además, dicho texto no debe registrarse en la lista de historial, ya que alguien que encuentre su terminal desatendida podría recordarlo, o alguien que husmee en sus directorios podría verlo en su archivo de historial. Teniendo esto en cuenta, la función gl_echo_mode() le permite activar y desactivar la visualización y el archivo de cualquier texto que se ingrese posteriormente en las llamadas a gl_get_line().

  int gl_echo_mode(GetLine *gl, int enable);

El argumento enable especifica si el texto ingresado debe ser visible o no. Si es 0, entonces las líneas ingresadas posteriormente no serán visibles en la terminal y no se registrarán en la lista de historial. Si es 1, entonces las líneas de entrada posteriores se mostrarán a medida que se ingresan, y siempre que el historial no se haya deshabilitado mediante una llamada a gl_toggle_history(), también se archivarán en la lista de historial. Finalmente, si el argumento enable es -1, el modo de eco no se modifica, lo que le permite consultar de forma no destructiva la configuración actual a través del valor de retorno. En todos los casos, el valor de retorno de la función es 0 si el eco se deshabilitó antes de llamar a la función, y 1 si estaba habilitado.

Cuando el eco está desactivado, tenga en cuenta que aunque la autocompletación de tabulaciones completará invisiblemente su prefijo hasta donde sea posible, las completaciones ambiguas no se mostrarán.

CONSULTAS DE UN SOLO CARÁCTER

Usar gl_get_line() para solicitarle al usuario una respuesta de un solo carácter es inconveniente para el usuario, ya que debe presionar la tecla enter o return antes de que el carácter que escribió sea devuelto al programa. Por lo tanto, la función gl_query_char() se ha proporcionado para consultas de un solo carácter como esta.

  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar);

Esta función muestra el aviso especificado al principio de una nueva línea y espera a que el usuario escriba un carácter. Cuando el usuario escribe un carácter, gl_query_char() lo muestra a la derecha del aviso, inicia una nueva línea y luego devuelve el carácter al programa que llama. El valor de retorno de la función es el carácter que se escribió. Si la lectura tuvo que abortarse por alguna razón, se devuelve EOF en su lugar. En este último caso, la aplicación puede llamar a gl_return_status(), documentado anteriormente, para averiguar qué salió mal. Esto podría haber sido, por ejemplo, la recepción de una señal, o la expiración del temporizador de inactividad opcional.

Si el usuario simplemente presiona enter, se sustituye el valor del argumento defchar. Esto significa que cuando el usuario presiona nueva línea o retorno, el carácter especificado en defchar se muestra después del aviso, como si el usuario lo hubiera escrito, además de ser devuelto a la aplicación que llama. Si tal reemplazo no es importante, simplemente pase '0 como valor de defchar.

Si el carácter ingresado es un carácter no imprimible, se muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y los caracteres mayores que 127 se muestran en octal, precedidos por una barra invertida.

Al igual que con gl_get_line(), el eco del carácter ingresado se puede deshabilitar usando la función gl_echo_mode().

Si el proceso que llama se suspende mientras espera que el usuario escriba su respuesta, el cursor se mueve a la línea siguiente a la línea del aviso, luego cuando el proceso se reanuda, se vuelve a mostrar el aviso y gl_query_char() reanuda la espera de que el usuario escriba un carácter.

Tenga en cuenta que en modo de servidor no bloqueante (ver gl_io_mode(3)), si una línea de entrada incompleta se está leyendo cuando se llama a gl_query_char(), la línea de entrada parcial se descarta y se borra de la terminal antes de que se muestre el nuevo aviso. La próxima llamada a gl_get_line() comenzará a editar una nueva línea.

LECTURA DE CARACTERES EN BRUTO

Mientras que la función gl_query_char() muestra visiblemente un aviso al usuario para obtener un carácter y muestra lo que escribió, la función gl_read_char() lee un carácter de señal del usuario, sin escribir nada en la terminal, ni perturbar ninguna línea de entrada incompleta. Esto significa que se puede llamar no solo entre llamadas a gl_get_line(), sino también desde funciones de devolución de llamada que la aplicación ha registrado para ser llamadas por gl_get_line().

  int gl_read_char(GetLine *gl);

En caso de éxito, el valor de retorno de gl_read_char() es el carácter leído. En caso de fallo, se devuelve EOF y la función gl_return_status() puede ser llamada para averiguar qué salió mal. Las posibilidades incluyen la expiración del temporizador de inactividad opcional, la recepción de una señal configurada para abortar gl_get_line(), o un bloqueo de E/S de terminal, cuando se está en modo de E/S de servidor no bloqueante.

Tenga en cuenta que ciertas teclas del teclado, como las teclas de función y las teclas de cursor, generalmente generan al menos 3 caracteres cada una, por lo que una sola llamada a gl_read_char() no será

Entre las llamadas a gl_get_line(), la función gl_display_text() proporciona una forma conveniente de mostrar párrafos de texto, justificados a la izquierda y divididos en una o más líneas de terminal según las restricciones del ancho actual de la terminal. Desde la versión 1.4.0 de libtecla, gl_get_line() ha sido limpio de 8 bits. Esto significa que todos los caracteres de 8 bits que son imprimibles en la configuración regional actual del usuario ahora se muestran de forma literal y se incluyen en la línea de entrada devuelta.
