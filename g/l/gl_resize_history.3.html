DESCRIPCIÓ

N

La función gl_get_line() es parte de la biblioteca tecla (véase la página man libtecla(3)). Si el usuario está escribiendo en un terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de unix. Además de la edición simple de línea de comandos, soporta el recuerdo de líneas de comandos previamente introducidas, la completación con TAB de nombres de archivos, y la expansión en línea de comodines de nombres de archivos. La documentación de ambas las características de edición de línea de comandos a nivel de usuario y todas las opciones de configuración del usuario, puede encontrarse en la página man tecla(7).   #include <locale.h>

    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* del juego de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;

En el ejemplo, primero los recursos necesarios por la función gl_get_line() son creados llamando a new_GetLine(). Esto asigna la memoria usada en llamadas subsecuentes a la función gl_get_line(), incluyendo el búfer de historial para registrar líneas previamente introducidas. Entonces una o más líneas son leídas del usuario, hasta que ocurra un error, o el usuario escriba exit. Entonces finalmente los recursos que fueron asignados por new_GetLine(), son devueltos al sistema llamando a del_GetLine(). Nótese el uso del valor de retorno NULL de del_GetLine() para hacer gl NULL. Esta es una precaución de seguridad. Si el programa subsecuentemente intenta pasar gl

a

gl_get_line(), dicha función se quejará, y retornará un error, en lugar de intentar usar el objeto recurso

eliminado.

The gl_get_line() function returns a pointer to the line entered by the user, or NULL on error or at the end of the input. The returned pointer is part of the specified gl resource object, and thus should not be free'd by the caller, or assumed to be unchanging from one call to the next. When reading from a user at a terminal, there will always be a newline character at the end of the returned line. When standard input is being taken from a pipe or a file, there will similarly be a newline unless the input line was too long to store in the internal buffer. In the latter case you should call gl_get_line() again to read the rest of the line. Note that this behavior makes gl_get_line() similar to fgets(). FUENTES DE CONFIGURACIÓN

ALTERNATIVAS

Como se mencionó anteriormente, por defecto los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad, y libera al usuario de tener que configurar cada aplicación por separado. En algunas aplicaciones, sin embargo, este único medio de configuración es un problema. Esto es particularmente cierto en software embebido, donde no hay un sistema de archivos del cual leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de asignaciones de teclas para emular una interfaz de teclado heredada. Para atender a tales casos, la siguiente función permite a la aplicación controlar de dónde se lee la información de

configuración. 
  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file)
;

Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc de un usuario, se lean de cualquiera o ninguno de, una cadena, un archivo de configuración específico de la aplicación, y/o un archivo de configuración específico del usuario. Si esta función se llama antes de la primera llamada a gl_get_line(), el comportamiento por defecto de leer ~/.teclarc en la primera llamada a gl_get_line() se deshabilita, por lo que toda la configuración debe lograrse utilizando las fuentes de configuración especificadas con esta

función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados entre sí en la cadena por caracteres de salto de línea incrustados. Si app_file != NULL entonces se interpreta como la ruta de nombre completa de un archivo de configuración específico de la aplicación. Si user_file != NULL entonces se interpreta como la ruta de nombre completa de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente

llamada, 
  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc")
;

el argumento app_string hace que la aplicación que llama comience en modo de edición vi, en lugar del modo emacs por defecto, y apaga el uso de la campana de la terminal por la biblioteca. Luego intenta leer comandos de configuración de todo el sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario desde un archivo .teclarc opcional en el directorio de inicio del usuario. Note que los argumentos se listan en orden ascendente de prioridad, con el contenido de app_string siendo potencialmente sobrescrito por comandos en app_file, y los comandos en app_file potencialmente siendo sobrescritos por comandos en user_file

.

Puede llamar a esta función tantas veces como sea necesario, los resultados siendo acumulativos, pero note que las copias de cualquier nombre de archivo especificado a través de app_file y user_file se registran internamente para su uso posterior por la función de asignación de teclas read-init-files, así que si planea llamar a esta función varias veces, asegúrese de que la última llamada especifique los nombres de archivo que desea volver a leer cuando el usuario solicite que los archivos de configuración se

relean.

PERSONALIZADO

Si en su aplicación desea que el completado con TAB complete otras cosas además de o en lugar de nombres de archivo, puede organizar esto registrando una función de retorno de completado alternativa, mediante una llamada a la función gl_customize_co

mpletion(). 
  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn)

El argumento data proporciona una manera para que su aplicación pase información arbitraria específica de la aplicación a la función de retorno. Esto se pasa a la función de retorno cada vez que se la llama. Podría, por ejemplo, apuntar a la tabla de símbolos desde la cual se deben buscar las posibles completaciones. El argumento match_fn especifica la función de retorno a ser llamada. El tipo de función CplMatchFn está definido en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y prototipar funciones de retorno. La declaración y las responsabilidades de las funciones de retorno se describen en profundidad en la página del manual cpl_complete_word(3)

.

En resumen, la función de retorno es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario presionó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar posibles completaciones de esta palabra y registrarlas una por una en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion(). Si la función de retorno desea proporcionar completado de nombres de archivo además de sus propias completaciones específicas, tiene la opción de llamar ella misma a la función de retorno de completado de nombres de archivo incorporada. Esto también está documentado en la página del manual cpl_complete_word(3)

.

Tenga en cuenta que si desea que gl_get_line() devuelva la línea de entrada actual cuando se haya realizado una completación exitosa, puede organizar esto cuando llame a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de nueva línea. Si hace esto, la línea de entrada se actualizará para mostrar la completación, junto con cualquier sufijo de continuación hasta el carácter de nueva línea, y luego gl_get_line() devolverá esta línea de

entrada.

Si, por alguna razón, su función de retorno necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto iniciará una nueva línea después de la línea de entrada que se está editando actualmente, restablecerá la E/S normal de la terminal y le dirá a gl_get_line() que la línea de entrada necesitará

ser redibujada cuando la f
unción de retorno regrese.

COMPLETADO

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de completado predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que diferentes tipos de completado de palabras se puedan asignar a diferentes secuencias de teclas. Esto se logra usando la función gl_completion_action()

. 
  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq)
;

Los argumentos data y match_fn se describen en la página del manual cpl_complete_word, y especifican la función de retorno que debe ser invocada para identificar posibles completaciones. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar cualquier completación ambigua posible, o si simplemente debe mostrar la lista de posibles completaciones sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre con el que los archivos de configuración y las futuras invocaciones de esta función deben referirse a la acción. Este debe ser el nombre de una acción de completado existente a ser cambiada, o un nuevo nombre sin usar para una nueva acción. Finalmente, el argumento keyseq especifica la secuencia de teclas predeterminada a la que asignar la acción. Si esto es NULL, no se asignará ninguna nueva secuencia de teclas a la

acción.

Tenga cuidado de que para que el usuario pueda cambiar la secuencia de teclas que está asignada a las acciones que se instalan de esta manera, cuando llame a gl_completion_action() para instalar una acción dada por primera vez, debe hacerlo entre llamar a new_GetLine() y la primera llamada a gl_get_line(). De lo contrario, cuando se lea el archivo de configuración del usuario en la primera llamada a gl_get_line(), el nombre de su acción adicional no será conocido, y cualquier referencia a ella en el archivo de configuración generará un

error.

Como se discutió para gl_customize_completion(), si su función de retorno, por alguna razón, necesita escribir algo en la terminal, debe llamar a gl_normal_io() a

ntes de
hacerlo.

PERSONALIZADAS

Aunque las acciones de asignación de teclas incorporadas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, asignadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza que correspondiera a un número de pieza que precede al cursor. Tal característica está claramente fuera del alcance de las funciones de acción incorporadas. Así que para tales casos especiales, se proporciona la función gl_register_action()

. 
  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq)
;

Esta función permite a la aplicación registrar una función externa, fn, que a partir de entonces será llamada siempre que se ingrese la secuencia de teclas especificada, keyseq, por el usuario, o el usuario ingrese cualquier otra secuencia de teclas que el usuario asigne posteriormente al nombre de acción especificado, name, en su archivo de configuración. El argumento data puede ser un puntero a cualquier cosa que la aplicación desee que se pase a la función de acción, fn, cada vez que esa función sea

invocada.

La función de acción, fn, debe ser declarada usando la siguiente macro, que está definida en libtecl

a.h. 
  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char
*line)

Los argumentos gl y data son aquellos que fueron previamente pasados a gl_register_action() cuando la función de acción fue registrada. El argumento count es un argumento numérico que el usuario tiene la opción de ingresar usando la acción de argumento numérico, antes de invocar la acción. Si el usuario no ingresa un número, entonces el argumento count se establece en 1. Nominalmente este argumento se interpreta como un conteo de repetición, lo que significa que la acción debe repetirse esa cantidad de veces. En la práctica, sin embargo, para algunas acciones un conteo de repetición tiene poco sentido. En tales casos, las acciones pueden simplemente ignorar el argumento count, o usar su valor para un propósito

diferente.

Una copia de la línea de entrada actual se pasa en el argumento de solo lectura line. La posición actual del cursor dentro de esta cadena es dada por el índice contenido en el argumento curpos. Tenga en cuenta que la manipulación directa de la línea de entrada y la posición del cursor no está permitida. Esto se debe a que las reglas dictadas por varios modos, como el modo vi frente al modo emacs, el modo sin eco, y el modo de inserción frente al modo de sobrescritura, etc., hacen que sea demasiado complejo para un escritor de aplicaciones escribir una acción de edición conforme, así como restringen cambios futuros en los internos de gl_get_line(). Una solución potencial a este dilema sería permitir que la función de acción edite la línea usando las acciones de edición existentes. Esto está actualmente bajo

consideración.

Si la función de acción desea escribir texto en la terminal, sin que esto se mezcle con el texto mostrado de la línea de entrada, o leer de la terminal sin tener que manejar la E/S cruda de la terminal, entonces antes de realizar cualquiera de estas operaciones, debe suspender temporalmente la edición de línea llamando a la función gl_normal_io(). Esta función vacía cualquier salida pendiente a la terminal, mueve el cursor al inicio de la línea que sigue a la última línea de terminal de la línea de entrada, y luego restaura la terminal a un estado que es adecuado para su uso con las instalaciones stdio de C. Lo último incluye cosas como restaurar la asignación normal de \n a \r\n, y, cuando está en modo servidor, restaurar la forma normal de bloqueo de la E/S de la terminal. Después de haber llamado a esta función, la acción puede leer de y escribir en la terminal sin temor de crear un desorden. No es necesario que la función de acción restaure el entorno de edición original antes de que regrese. Esto se hace automáticamente por gl_get_line() después de que la función de acción regrese. Lo siguiente es un ejemplo simple de una función de acción que escribe la frase "Hello world" en una nueva línea de terminal después de la línea que se está editando. Cuando esta función regresa, la línea de entrada se redibuja en la línea que sigue a la línea "Hello world", y la edición de línea se

reanuda. 
  static GL_ACTION_FN(say_hello_fn)
  {
    if(gl_normal_io(gl))   /* Suspende temporalmente la edición */
      return GLA_ABORT;
    printf("Hello world\n");
    return GLA_CONTINUE;
}

Las funciones de acción deben devolver uno de los siguientes valores, para indicar a gl_get_line() cómo

proceder. 
  GLA_ABORT     -   Hace que gl_get_line() devuelva NULL.
  GLA_RETURN    -   Hace que gl_get_line() devuelva la
                    línea de entrada completada.
  GLA_CONTINUE  -   Reanuda la edición de la línea de
comandos.

Tenga en cuenta que el argumento name de gl_register_action() especifica el nombre con el que un usuario puede referirse a la acción en su archivo de configuración. Esto le permite volver a vincular la acción a una secuencia de teclas alternativa. Para que esto funcione, es necesario llamar a gl_register_action() entre la llamada a new_GetLine() y la primera llamada a gl_get_

lin

Para guardar el contenido del búfer de historial antes de salir de su aplicación y, posteriormente, restaurarlo cuando vuelva a iniciar la aplicación, se proporcionan las siguientes

historial.

ARCHIVADO MANUAL DEL

HISTORIAL

De forma predeterminada, cada vez que el usuario introduce una línea, se añade automáticamente a la lista de historial, justo antes de que gl_get_line() devuelva la línea al que llama. Esto es conveniente para la mayoría de las aplicaciones, pero también hay aplicaciones que necesitan un control más detallado sobre lo que se añade a la lista de historial. En tales casos, la adición automática de las líneas introducidas a la lista de historial se puede desactivar llamando a la función gl_automatic_hi

;

Si se llama a esta función con su argumento enable establecido en 0, gl_get_line() no archivará automáticamente las líneas introducidas posteriormente. El archivado automático se puede volver a activar más tarde, llamando a esta función de nuevo, con su argumento enable establecido en 1. Mientras el archivado automático del historial esté desactivado, la aplicación que llama puede usar la función gl_append_history() para añadir líneas a la lista de historial según sea

necesario. 
  int gl_append_history(GetLine *gl, const char *line)
;

El argumento line especifica la línea que se añadirá a la lista de historial. Esta debe ser una cadena normal terminada en ' '. Si esta cadena contiene algún carácter de salto de línea, la línea que se archive en la lista de historial terminará en el primero de ellos. De lo contrario, terminará en el terminador ' '. Si la línea es más larga que la longitud máxima de línea de entrada, que se especificó cuando se llamó a new_GetLine(), cuando se recuerde la línea, se truncará a la longitud real de la línea de gl_get_li

ne().

Si tiene éxito, gl_append_history() devuelve 0. De lo contrario, devuelve un valor distinto de cero y establece errno en uno de los siguientes

valores. 
   EINVAL  -  Uno de los argumentos pasados a
              gl_append_history() era NULL.
   ENOMEM  -  La línea especificada era más larga que el tamaño
              asignado del búfer de historial (tal como se especificó cuando se
              llamó a new_GetLine()), por lo que no se pudo
archivar.

Se puede obtener opcionalmente una descripción textual del error llamando a gl_error_message(). Tenga en cuenta que después de un error de este tipo, la lista de historial permanece en un estado válido para recibir nuevas líneas de historial, por lo que hay poco daño en simplemente ignorar el estado de retorno de gl_append_

CAMBIO DE

TERMINALES

La función constructora new_GetLine() asume que la entrada se leerá desde stdin, y la salida se escribirá en stdout. La siguiente función le permite cambiar a diferentes flujos de entrada y

salida. 
  int gl_change_terminal(GetLine *gl, FILE *input_fp,
                         FILE *output_fp, const char *term)
;

El argumento gl es el objeto que fue devuelto por new_GetLine(). El argumento input_fp especifica el flujo desde el cual leer, y output_fp especifica el flujo en el cual escribir. Solo si ambos se refieren a un terminal, se habilitará la entrada interactiva del terminal. De lo contrario, gl_get_line() simplemente llamará a fgets() para leer la entrada de comandos. Si ambos flujos se refieren a un terminal, entonces deben referirse al mismo terminal, y el tipo de este terminal debe especificarse a través del argumento term. El valor del argumento term se busca en la base de datos de información del terminal (terminfo o termcap), con el fin de determinar qué secuencias de control especiales se necesitan para controlar varios aspectos del terminal. new_GetLine(), por ejemplo, pasa el valor de retorno de getenv("TERM") en este argumento. Nótese que si uno o ambos de input_fp y output_fp no se refieren a un terminal, es legal pasar NULL en lugar de un tipo de

terminal.

Nótese que si desea pasar descriptores de archivo a gl_change_terminal(), puede hacerlo creando envoltorios de flujo stdio usando la función POSIX fdop

en(

MANEJO DE EVENTOS

EXTERNOS

Por defecto, gl_get_line() no retorna hasta que se haya introducido una línea de entrada completa por parte del usuario, o hasta que ocurra un error. En programas que necesitan vigilar la E/S de otras fuentes que no sean el terminal, hay dos

opciones. 
  1. Use las funciones descritas en la
     página del manual gl_io_mode(3) para cambiar
     gl_get_line() al modo de servidor no bloqueante. En este modo,
     gl_get_line() se convierte en una función de edición de líneas
     incremental no bloqueante que puede llamarse de forma segura desde
     un bucle de eventos externo. Aunque este es un método muy
     versátil, implica asumir algunas
     responsabilidades que normalmente se realizan detrás de escena por gl_get_line().
  2. Mientras gl_get_line() está esperando la entrada del
     teclado del usuario, puede pedirle que también vigile
     la actividad en descriptores de archivo arbitrarios, como
     sockets de red, tuberías, etc., y que llame a funciones
     de su elección cuando se detecte actividad. Esto funciona en
     cualquier sistema que tenga la llamada al sistema select(),
     que es la mayoría, si no todos, de los sabores de
unix.

Registrar un descriptor de archivo para ser vigilado por gl_get_line() implica llamar a la función gl_watch_fd()

  int gl_watch_fd(GetLine *gl, int fd, GlFdEvent event,
                  GlFdEventFn *callback, void *data)
;

Si esto devuelve un valor distinto de cero, significa que o bien sus argumentos son inválidos, o que esta funcionalidad no es compatible con el sistema

anfitrión.

El argumento fd es el descriptor de archivo a vigilar. El argumento event especifica qué tipo de actividad es de interés, elegido de los siguientes valores

enumerados: 
  GLFD_READ   -  Vigilar la llegada de datos para leer.
  GLFD_WRITE  -  Vigilar la capacidad de escribir en el descriptor
                 de archivo sin bloquear.
  GLFD_URGENT -  Vigilar la llegada de datos urgentes
                 fuera de banda en el descriptor de
archivo.

El argumento callback es la función a llamar cuando se detecta la actividad seleccionada. Debe definirse con el siguiente macro, que está definido en libtecla.

  #define GL_FD_EVENT_FN(fn) GlFdStatus (fn)(GetLine *gl, \
                                      void *data, int fd, \
                                      GlFdEvent
event)

El argumento data de la función gl_watch_fd() se pasa a la función de retorno de llamada para su propio uso, y puede apuntar a lo que desee, incluyendo NULL. El descriptor de archivo y el argumento event también se pasan a la función de retorno de llamada, y esto potencialmente permite que la misma función de retorno de llamada se registre para más de un tipo de evento y/o más de un descriptor de archivo. El valor de retorno de la función de retorno de llamada debe ser uno de los siguientes

valores. 
  GLFD_ABORT    -  Decirle a gl_get_line() que aborte. Cuando esto
                   ocurre, gl_get_line() retorna
                   NULL, y una llamada posterior a
                   gl_return_status() retornará
                   GLR_FDABORT. Nótese que si la
                   aplicación necesita que errno siempre
                   tenga un valor significativo cuando
                   gl_get_line() retorna NULL,
                   la función de retorno de llamada debe establecer
                   errno apropiadamente.
  GLFD_REFRESH  -  Redibujar la línea de entrada y luego continuar
                   esperando entrada. Retorne esto si
                   su retorno de llamada escribió en el terminal.
  GLFD_CONTINUE -  Continuar esperando entrada, sin
                   redibujar la
línea.

Nótese que antes de llamar al retorno de llamada, gl_get_line() bloquea la mayoría de las señales, y deja instalados sus propios manejadores de señal, así que si necesita capturar una señal en particular, necesitará tanto instalar temporalmente su propio manejador de señal, como desbloquear la señal. Asegúrese de volver a bloquear la señal (si estaba originalmente bloqueada) y reinstalar el manejador de señal original, si lo hay, antes de

retornar.

Si la función de retorno de llamada necesita leer o escribir en el terminal, idealmente debería primero llamar a gl_normal_io(gl) para suspender temporalmente la edición de líneas. Esto restaurará el terminal al modo canónico, de E/S bloqueante, y moverá el cursor al inicio de una nueva línea del terminal. Más tarde, cuando el retorno de llamada retorna, gl_get_line() notará que gl_normal_io() fue llamada, volverá a mostrar la línea de entrada y reanudará la edición. Nótese que en este caso los valores de retorno, GLFD_REFRESH y GLFD_CONTINUE son

equivalentes.

entrada.

MANEJO POR DEFECTO DE

SEÑALES

Por defecto, la función gl_get_line() intercepta un número de señales. Esto es particularmente importante para las señales que por defecto terminarían el proceso, ya que el terminal necesita ser restaurado a un estado utilizable antes de que esto suceda. En esta sección, se describen las señales que son atrapadas por defecto, y cómo gl_get_line() responde a ellas. Cambiar estos valores por defecto es el tema de la siguiente

sección.

Cuando se captura el siguiente subconjunto de señales, gl_get_line() primero restaura la configuración del terminal y el manejo de señales a como estaban antes de que gl_get_line() fuera llamada, reenvía la señal, para permitir que los manejadores de señal de la aplicación que llama la manejen, luego si el proceso todavía existe, gl_get_line() devuelve NULL y establece errno como se especifica a

continuación. 
 SIGINT  -  Esta señal es generada tanto por la tecla
            de interrupción del teclado (usualmente ^C), como por la tecla
            de interrupción (break) del teclado.
            errno=EINTR
 SIGHUP  -  Esta señal es generada cuando el terminal de control
            sale.
            errno=ENOTTY
 SIGPIPE -  Esta señal es generada cuando un programa intenta
            escribir en un pipe cuyo extremo remoto no está siendo
            leído por ningún proceso. Esto puede pasar, por ejemplo,
            si ha llamado a gl_change_terminal() para
            redirigir la salida a un pipe oculto bajo un pseudo
            terminal.
            errno=EPIPE
 SIGQUIT -  Esta señal es generada por la tecla de salida del teclado
            (usualmente ^\).
            errno=EINTR
 SIGABRT -  Esta señal es generada por la función estándar de C,
            abort(). Por defecto, tanto termina
            el proceso como genera un volcado de memoria (core dump).
            errno=EINTR
 SIGTERM -  Esta es la señal por defecto que el comando kill de UN*X
            envía a los procesos.
errno=EINTR

Tenga en cuenta que en el caso de todas las señales anteriores, POSIX establece que por defecto el proceso es terminado, con la adición de un volcado de memoria en el caso de la señal SIGQUIT. En otras palabras, si la aplicación que llama no anula el manejador por defecto proporcionando su propio manejador de señal, la recepción de la señal correspondiente terminará la aplicación antes de que gl_get_line()

regrese.

Si gl_get_line() aborta con errno establecido en EINTR, puede averiguar qué señal causó el aborto, llamando a la siguiente

función. 
  int gl_last_signal(const GetLine *gl)
;

Devuelve el código numérico (por ejemplo, SIGINT) de la última señal que fue recibida durante la llamada más reciente a gl_get_line(), o -1 si no se recibieron

señales.

En los sistemas que lo soportan, cuando se recibe una señal SIGWINCH (cambio de ventana), gl_get_line() consulta al terminal para averiguar su nuevo tamaño, redibuja la línea de entrada actual para acomodarse al nuevo tamaño, luego regresa a esperar la entrada del teclado del usuario. A diferencia de otras señales, esta señal no es reenviada a la

aplicación.

Finalmente, las siguientes señales causan que gl_get_line() primero restaure el terminal y el entorno de señales al que prevalecía antes de que gl_get_line() fuera llamado, luego reenvíe la señal a la aplicación. Si el proceso todavía existe después de que la señal ha sido entregada, entonces gl_get_line() reinstala sus propios manejadores de señal, cambia el terminal de vuelta a modo crudo (raw), vuelve a mostrar la línea de entrada, y regresa a esperar la entrada del terminal del

usuario. 
 SIGCONT    -  Esta señal es generada cuando un proceso suspendido
               es reanudado.
 SIGPOLL    -  En los sistemas SVR4, esta señal notifica al
               proceso de un evento de E/S asíncrona. Tenga en cuenta
               que bajo 4.3+BSD, SIGIO y SIGPOLL son
               lo mismo. En otros sistemas, SIGIO es ignorada
               por defecto, así que gl_get_line() no la
               atrapa por defecto.
 SIGPWR     -  Esta señal es generada cuando ocurre un fallo
               de energía (presumiblemente cuando el sistema está en un
               UPS).
 SIGALRM    -  Esta señal es generada cuando un temporizador
               expira.
 SIGUSR1    -  Una señal específica de la aplicación.
 SIGUSR2    -  Otra señal específica de la aplicación.
 SIGVTALRM  -  Esta señal es generada cuando un temporizador
               virtual expira (ver man setitimer(2)).
 SIGXCPU    -  Esta señal es generada cuando un proceso
               excede su límite de tiempo de CPU suave.
 SIGXFSZ    -  Esta señal es generada cuando un proceso
               excede su límite de tamaño de archivo suave.
 SIGTSTP    -  Esta señal es generada por la tecla de suspensión
               del terminal, que usualmente es ^Z, o la
               tecla de suspensión retrasada del terminal, que
               usualmente es ^Y.
 SIGTTIN    -  Esta señal es generada si el programa
               intenta leer del terminal mientras el
               programa se está ejecutando en segundo plano.
 SIGTTOU    -  Esta señal es generada si el programa
               intenta escribir en el terminal mientras el
               programa se está ejecutando en segundo
plano.

Obviamente, no todas las señales anteriores están soportadas en todos los sistemas, así que el código para soportarlas se compila condicionalmente en la biblioteca

tecla.

Tenga en cuenta que si SIGKILL o SIGPOLL, que por definición no pueden ser capturadas, o cualquiera de las señales de excepción generadas por el hardware, tales como SIGSEGV, SIGBUS y SIGFPE, son recibidas y no manejadas mientras gl_get_line() tiene el terminal en modo crudo, el programa será terminado sin que el terminal haya sido restaurado a un estado utilizable. En la práctica, los shells de contro

l de trabajos usualmente restablecen la configuración del terminal cuando un proceso re
nuncia al terminal de control, así que esto solo es un problema con shells más antiguos.

MANEJO PERSONALIZADO DE

SEÑALES

La sección anterior enumeró las señales que gl_get_line() atrapa por defecto, y describió cómo responde a ellas. Esta sección describe cómo tanto añadir como eliminar señales de la lista de señales atrapadas, y cómo especificar cómo gl_get_line() debería responder a una señal

dada.

Si no necesita que gl_get_line() haga algo en respuesta a una señal que normalmente atrapa, puede decirle a gl_get_line() que ignore esa señal llamando a gl_ignore_sig

nal(). 
  int gl_ignore_signal(GetLine *gl, int signo)
;

El argumento signo es el número de la señal (por ejemplo, SIGINT) que quiere que sea ignorada. Si la señal especificada no es actualmente una de las que están siendo atrapadas, esta función no hace

nada.

La función gl_trap_signal() le permite tanto añadir una nueva señal a la lista que gl_get_line() atrapa, como modificar cómo res

gl_trap_SIGNAL

El argumento signo es el número de la señal que desea capturar. El argumento flags es un conjunto de indicadores que determinan el entorno en el que se invoca el controlador de señales de la aplicación, el argumento after le dice a gl_get_line() qué hacer después de que regrese el controlador de señales de la aplicación, y errno_value le dice a gl_get_line() qué establecer en errno si se le indica que aborte.

El argumento flags es una OR a nivel de bits de cero o más de los siguientes enumeradores:

  GLS_RESTORE_SIG  -  Restaura el entorno de señales del
                      llamador mientras se maneja la
                      señal.
  GLS_RESTORE_TTY  -  Restaura la configuración de la terminal
                      del llamador mientras se maneja la
                      señal.
  GLS_RESTORE_LINE -  Mueve el cursor al inicio de la línea
                      siguiente a la línea de entrada antes
                      de invocar el controlador de señales de
                      la aplicación.
  GLS_REDRAW_LINE  -  Redibuja la línea de entrada cuando
                      regresa el controlador de señales de
                      la aplicación.
  GLS_UNBLOCK_SIG  -  Normalmente, si el programa llamador
                      tiene una señal bloqueada (man
                      sigprocmask), gl_get_line() no captura
                      esa señal. Este indicador le dice a
                      gl_get_line() que capture la señal y la
                      desbloquee durante la duración de la
                      llamada a gl_get_line().
  GLS_DONT_FORWARD -  Si se incluye este indicador, la señal
                      no se reenviará al controlador de
                      señales del programa llamador.

Dos combinaciones de indicadores comúnmente útiles también se enumeran de la siguiente manera:

  GLS_RESTORE_ENV   = GLS_RESTORE_SIG | GLS_RESTORE_TTY |
                      GLS_REDRAW_LINE
  GLS_SUSPEND_INPUT = GLS_RESTORE_ENV | GLS_RESTORE_LINE

Si su controlador de señales, o el controlador de señales del sistema predeterminado para esta señal, si no lo ha anulado, nunca escribe en la terminal, ni suspende o termina el programa llamador, entonces puede establecer de forma segura el argumento flags en 0.

Si su controlador de señales siempre escribe en la terminal, lee de ella, o suspende o termina el programa, debe especificar el argumento flags como GL_SUSPEND_INPUT, para que:

1. El cursor no quede en medio de la línea de entrada.
2. Para que el usuario pueda escribir entrada y que esta se imprima.
3. Para que no necesite terminar cada línea de salida con
   \r\n, en lugar de solo \n.

La combinación GL_RESTORE_ENV es la misma que GL_SUSPEND_INPUT, excepto que no mueve el cursor, y si su controlador de señales no lee ni escribe nada en la terminal, el usuario no verá ninguna indicación visible de que se capturó una señal. Esto puede ser útil si tiene un controlador de señales que solo ocasionalmente escribe en la terminal, donde usar GL_SUSPEND_LINE causaría que la línea de entrada se duplicara innecesariamente cuando no se ha escrito nada en la terminal. Dicho controlador de señales, cuando escribe en la terminal, debe asegurarse de iniciar una nueva línea al principio de su primera escritura, escribiendo una nueva línea antes de regresar. Si la señal llega mientras el usuario está escribiendo una línea que solo ocupa una línea de terminal de señal, o si el cursor está en la última línea de terminal de una línea de entrada más larga, esto tendrá el mismo efecto que GL_SUSPEND_INPUT. De lo contrario, comenzará a escribir en una línea que ya contiene parte de la línea de entrada mostrada. Esto no causa ningún daño, pero se ve un poco feo, por lo que la combinación GL_SUSPEND_INPUT es mejor si sabe que siempre va a escribir en la terminal.

El argumento after, que determina qué hace gl_get_line() después de que regresa el controlador de señales de la aplicación (si regresa), puede tomar cualquiera de los siguientes valores:

  GLS_RETURN   - Devuelve la línea de entrada completada, como
                 si el usuario hubiera presionado la tecla de
                 retorno.
  GLS_ABORT    - Hace que gl_get_line() aborte. Cuando
                 esto sucede, gl_get_line() devuelve
                 NULL, y una llamada posterior a
                 gl_return_status() devolverá
                 GLR_SIGNAL. Tenga en cuenta que si la
                 aplicación necesita que errno siempre
                 tenga un valor significativo cuando
                 gl_get_line() devuelve NULL,
                 la función de devolución de llamada debe
                 establecer errno apropiadamente.
  GLS_CONTINUE - Reanuda la edición de la línea de comandos.

El argumento errno_value está destinado a combinarse con la opción GLS_ABORT, indicando a gl_get_line() qué establecer en la variable estándar errno antes de devolver NULL al programa llamador. Sin embargo, también se puede usar con la opción GL_RETURN, en caso de que desee tener una forma de distinguir entre una línea de entrada que se ingresó usando la tecla de retorno y una que se ingresó por la recepción de una señal.

MANEJO DE SEÑALES CONFIABLES

El manejo de señales es sorprendentemente difícil de hacer de manera confiable sin condiciones de carrera. En gl_get_line() se ha puesto mucho cuidado para permitir que las aplicaciones realicen un manejo de señales confiable alrededor de gl_get_line(). Esta sección explica cómo aprovechar esto.

Como ejemplo de los problemas que pueden surgir si la aplicación no está escrita correctamente, imagine que la aplicación tiene un controlador de señales SIGINT que establece una bandera global. Ahora suponga que la aplicación prueba esta bandera justo antes de invocar gl_get_line(). Si una señal SIGINT se recibe en la pequeña ventana de tiempo entre la instrucción que prueba el valor de esta bandera y la instrucción que llama a gl_get_line(), entonces gl_get_line() no verá la señal y no se interrumpirá. Como resultado, la aplicación no podrá responder a la señal hasta que el usuario termine de ingresar la línea de entrada y gl_get_line() regrese. Dependiendo de la aplicación, esto puede ser o no un desastre, pero al menos confundirá al usuario.

La forma de evitar tales problemas es hacer lo siguiente.

1. Si es necesario, use la función gl_trap_signal() para
configurar gl_get_line() para abortar cuando se capturen
señales importantes.

2. Configure gl_get_line() de tal manera que si alguna de las
señales que captura está bloqueada cuando se llama a
gl_get_line(), se desbloquearán automáticamente
durante los momentos en que gl_get_line() está
esperando E/S. Esto se puede hacer por señal, llamando a
la función gl_trap_signal() y especificando el
atributo GLS_UNBLOCK de la señal, o globalmente
llamando a la función gl_catch_blocked().

     void gl_catch_blocked(GetLine *gl);


Esta función simplemente agrega el atributo GLS_UNBLOCK a todas las señales que actualmente está
configurada para capturar.

3. Justo antes de llamar a gl_get_line(), bloquee la entrega
de todas las señales que gl_get_line() está
configurada para capturar. Esto se puede hacer usando la
función POSIX sigprocmask() en conjunto con la
función gl_list_signals().

      int gl_list_signals(GetLine *gl, sigset_t *set);


Esta función devuelve el conjunto de señales que
actualmente está configurada para capturar en el argumento
set, que está en el formato requerido por
sigprocmask().

4. En el ejemplo, ahora se probaría la bandera global que
establece el controlador de señales, sabiendo que ahora no
hay peligro de que esta bandera se establezca nuevamente
hasta que gl_get_line() desbloquee sus señales al
realizar E/S.

5. Eventualmente, gl_get_line() regresa, ya sea porque
se capturó una señal, ocurrió un error o el usuario
terminó de ingresar su línea de entrada.

6. Ahora se volvería a verificar la bandera global de señales
y, si está establecida, se respondería a ella y se pondría a
cero la bandera.

7. Use sigprocmask() para desbloquear las señales que
fueron bloqueadas en el paso 3.

La misma técnica se puede usar alrededor de ciertas funciones POSIX conscientes de señales, como sigsetjmp() y sigsuspend(), y en particular, la primera de estas dos funciones se puede usar en conjunto con siglongjmp() para implementar un manejo de señales libre de condiciones de carrera alrededor de otras llamadas del sistema de larga duración. La forma de hacer esto se explica a continuación, mostrando cómo gl_get_line() logra capturar señales de manera confiable alrededor de llamadas a funciones como read() y select() sin condiciones de carrera.

Lo primero que hace gl_get_line(), cada vez que se llama, es usar la función POSIX sigprocmask() para bloquear la entrega de todas las señales que actualmente está configurada para capturar. Esto es redundante si la aplicación ya las ha bloqueado, pero no causa ningún daño. Deshace este paso justo antes de regresar.

Cada vez que gl_get_line() necesita llamar a read() o select() para esperar la entrada del usuario, primero llama a la función POSIX sigsetjmp(), asegurándose de especificar un valor distinto de cero para su argumento savesigs. La razón del último argumento se aclarará en breve.

Si sigsetjmp() devuelve cero, gl_get_line() hace lo siguiente.

a. Utiliza la función POSIX sigaction() para registrar
   un controlador de señales temporal para todas las señales
   que está configurada para capturar. Este controlador de
   señales hace dos cosas.
   1. Registra el número de la señal recibida en una variable
      de ámbito de archivo.
   2. Luego llama a la función POSIX siglongjmp()
      usando el búfer que se pasó a sigsetjmp() como
      primer argumento, y un valor distinto de cero como
      segundo argumento.
   Cuando se registra este controlador de señales, el miembro
   sa_mask del argumento struct sigaction act de
   la llamada a sigaction() se configura para contener
   todas las señales que gl_get_line() está capturando.
   Esto asegura que nuestro controlador de señales solo capture
   una señal a la vez, lo que a su vez asegura que múltiples
   instancias de nuestro controlador de señales no se pisen los
   talones.
b. Ahora que el controlador de señales se ha configurado,
   gl_get_line() desbloquea todas las señales que está
   configurada para capturar.
c. Luego llama a las llamadas del sistema read() o
   select() para esperar la entrada del teclado.
d. Si esta llamada del sistema regresa (es decir, no se recibe
   ninguna señal), gl_get_line() vuelve a bloquear la
   entrega de las señales de interés.
e. Luego restaura los controladores de señales que fueron
   desplazados por el que se acaba de instalar.

Alternativamente, si sigsetjmp() devuelve un valor distinto de cero, esto significa que

una de las señales atrapadas fue capturada mientras los pasos anteriores se estaban ejecutando. Cuando esto sucede, gl_get_line() hace lo

siguiente.

Primero, tenga en cuenta que cuando una llamada a siglongjmp() hace que sigsetjmp() retorne, siempre que el argumento savesigs de sigsetjmp() fuera distinto de cero, como se especificó anteriormente, la máscara de proceso de señales se restaura a cómo estaba cuando sigsetjmp() fue llamado. Esta es la diferencia importante entre sigsetjmp() y el antiguo y problemático setjmp(), y es el ingrediente esencial que hace posible evitar condiciones de carrera en el manejo de señales. Debido a esto, se garantiza que todas las señales que bloqueamos antes de llamar a sigsetjmp() estén bloqueadas de nuevo tan pronto como se capture cualquier señal. Las siguientes declaraciones, que se ejecutan a continuación, se garantiza por tanto que se ejecuten sin que se capturen más

señales.

1. Si así lo indican los atributos de configuración de
gl_get_line() de la señal que fue capturada,
gl_get_line() restaura los atributos del terminal a
el estado que tenían cuando gl_get_line() fue
llamado. Esto es particularmente importante para las señales que
suspenden o terminan el proceso, ya que de lo contrario el
terminal quedaría en un estado

inutilizable.

2. A continuación, reinstala los manejadores de señales de la

aplicación.

3. Luego usa la función raise()
de la biblioteca estándar de C para reenviar a la aplicación la señal que
fue

capturada.

3. A continuación, desbloquea la entrega de la señal que acabamos de
enviar. Esto resulta en que la señal que fue enviada
vía raise(), sea capturada por el manejador de señales
original de la aplicación, que ahora puede manejarla como
considere

oportuno.

4. Si el manejador de señales retorna (es decir, no termina
el proceso), gl_get_line() bloquea la entrega de la
señal anterior de

nuevo.

5. A continuación, deshace cualquier acción realizada en el primero de los
pasos anteriores, y vuelve a mostrar la línea, si la configuración de la señal
lo

requiere.

6. gl_get_line() luego reanuda el intento de
leer un carácter, o se aborta, dependiendo de la
configuración de la señal que fue

capturada.

Lo que los pasos anteriores hacen en esencia es tomar señales entregadas de forma asíncrona y manejarlas de forma síncrona, una a la vez, en un punto del código donde gl_get_line() tiene control c

ompleto sobre s
u entorno.

TERMINAL

En la mayoría de los sistemas, la combinación de la ioctl TIOCGWINSZ y la señal SIGWINCH se utiliza para mantener una idea precisa del tamaño del terminal. El tamaño del terminal se consulta de nuevo cada vez que se llama a gl_get_line() y siempre que se recibe una señal SIGWINCH. En los pocos sistemas donde este mecanismo no está disponible, al

Al introducir información sensible, como contraseñas, es mejor no tener el texto que está introduciendo reflejado en el terminal. Además, dicho texto no debería registrarse en la lista de historial, ya que alguien que encuentre su terminal sin atender podría entonces recuperarlo, o alguien que esté husmeando en sus directorios podría verlo en su archivo de historial. Teniendo esto en cuenta,

la función

gl_echo_mode() le permite activar y desactivar la visualización y el archivo de cualquier texto que se introduzca posteriormente en las llamadas a gl_get_line(). int gl_echo_mode(GetLine *gl, int enable)

; 
  El
argumento

enable especifica si el texto introducido debe ser visible o no. Si es 1, entonces las líneas de entrada posteriores se mostrarán a medida que se introducen, y siempre que el historial no se haya desactivado mediante una llamada a gl_toggle_history(), también se archivarán en la lista de historial. En todos los casos, el valor de retorno de la función es 0 si el eco estaba desactivado antes de que se llamara a la función, y 1 si estaba activado. Entre las llamadas a gl_get_line(), la función gl_display_text() proporciona una manera conveniente de mostrar párrafos de texto, justificados a la izquierda y divididos en una o más líneas de la terminal de acuerdo con las restricciones del ancho actual de la terminal. Ejemplos del uso de esta función se pueden encontrar en los programas de demostración, donde se utiliza para mostrar introducciones. En esos ejemplos también se ilustra el uso avanzado de prefijos, sufijos y líneas rellenas opcionales para dibujar un cuadro alrededor del

texto. 
  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string)
;

Si gl no está actualmente conectado a una terminal, por ejemplo si la salida de un programa que usa gl_get_line() se está redirigiendo a otro programa o a un archivo, entonces se utiliza el valor del parámetro def_width como el ancho de la

terminal.

El argumento indentation especifica el número de caracteres a usar para sangrar cada línea de salida. El argumento fill_char especifica el carácter que se usará para realizar esta

sangría.

El argumento prefix puede ser NULL, o una cadena de texto a colocar al comienzo de cada línea nueva (después de cualquier sangría). De manera similar, el argumento suffix puede ser NULL, o una cadena de texto a colocar al final de cada línea. El sufijo se coloca al ras contra el borde derecho de la terminal, y cualquier espacio entre su primer carácter y la última palabra de esa línea se rellena con el carácter especificado a través del argumento fill_char. Normalmente, el carácter de relleno es un

espacio.

El argumento start le indica a gl_display_text() cuántos caracteres ya se han escrito en la línea de terminal actual, y así le indica el índice de columna inicial del cursor. Dado que el valor de retorno de gl_display_text() es el índice de columna final del cursor, al pasar el valor de retorno de una llamada al argumento start de la siguiente llamada, se puede componer un párrafo que está dividido entre más de una cadena llamando a gl_display_text() para cada porción sucesiva del párrafo. Tenga en cuenta que los caracteres de salto de línea literales son necesarios al final de cada párrafo para forzar el inicio de una nueva

línea.

INTERNACIONALES

Desde la versión 1.4.0 de libtecla, gl_get_line() ha sido 8-bit limpio. Esto significa que todos los caracteres de 8 bits que son imprimibles en la configuración regional actual del usuario ahora se muestran literalmente y se incluyen en la línea de entrada devuelta. Asumiendo que el programa que llama contiene correctamente una llamada como la

siguiente, 
  setlocale(LC_CTYPE, "")
;

entonces la configuración regional actual se determina por la primera de las variables de entorno LC_CTYPE, LC_ALL, y LANG, que se encuentre que contiene un nombre de configuración regional válido. Si ninguna de estas variables está definida, o el programa omite llamar a setlocale, entonces se usa la configuración regional C por defecto, que es US 7-bit ASCII. En la mayoría de las plataformas tipo unix, puede obtener una lista de configuraciones regionales válidas escribiendo el

comando: 
  locale
-a

en el símbolo del sistema. Documentación adicional sobre cómo el usuario puede hacer uso de esto para introducir caracteres internacionales se puede encontrar en la página del man

SEGURIDAD DE

HILOS

En un programa multihilo, debe usar la versión libtecla_r.a de la biblioteca. Esta usa versiones reentrantes de las funciones del sistema, donde están disponibles. Desafortunadamente, ni terminfo ni termcap fueron diseñados para ser reentrantes, por lo

que no puede usar de forma segura las funciones del módulo getline en múltiples hilos (puede usar los módulos separados de expansión de archivos y completamiento de palabras en múltiples hilos, vea las páginas de manual correspondientes para más deta
lles). Sin embargo, debido al uso de funciones reentrantes POSIX para buscar directorios de inicio, etc., es seguro usar este módulo desde un solo hilo de un programa multihilo, siempre que sus otros hilos no usen ninguna función de termcap o terminfo.
