DESCRIPCIÓ

N

La función gl_get_line() es parte de la biblioteca tecla (véase la página man libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de unix. Además de la edición simple de línea de comandos, admite el recuerdo de líneas de comandos introducidas previamente, la finalización con TAB de nombres de archivos y la expansión de comodines en línea de nombres de archivos. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario se puede encontrar en la página man tecla(7). Esta página man se ocupa de la documentación par

a programadores interesados en usar e
sta biblioteca en su aplicación.

EJEMPLO

Lo siguiente muestra un ejemplo completo de cómo usar la función gl_get_line() para obtener entrada del

usuario: 
  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que el usuario escribió */
    GetLine *gl;   /* El objeto de recursos gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* de conjunto de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("You typed: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
}

En el ejemplo, primero los recursos necesarios por la función gl_get_line() se crean llamando a new_GetLine(). Esto asigna la memoria utilizada en llamadas subsecuentes a la función gl_get_line(), incluyendo el búfer de historial para registrar líneas introducidas previamente. Luego se leen una o más líneas del usuario, hasta que ocurra un error, o el usuario escriba exit. Finalmente, los recursos que fueron asignados por new_GetLine() se devuelven al sistema llamando a del_GetLine(). Nótese el uso del valor de retorno NULL de del_GetLine() para hacer gl NULL. Esta es una precaución de seguridad. Si el programa posteriormente intenta pasar gl a gl_get_line(), dicha función se quejará y devolverá un error,

en lugar de intentar usar e
l objeto de recursos eliminado.

La función gl_get_line() puede llamarse cualquier número de veces para leer entrada del usuario. El argumento gl debe haber sido previamente devuelto por una llamada a new_GetLine(). El argumento prompt debe ser una cadena normal terminada en NUL, que especifique el prompt a presentar al usuario. Este debe ser -1 si desea que el cursor siga al último carácter de la línea inicial. Si no desea precargar la línea de esta manera, envíe start_line como NULL, y establezca start_pos a -1. Tenga en cuenta que el puntero a línea devuelto por una llamada a gl_get_line() puede pasarse a la siguiente llamada a gl_get_line() a través de start_line. Esto permite que la aplicación tome la última línea introducida y, si contiene un error, la presente de nuevo al usuario para su reedición, con el cursor inicialmente posicionado donde se encontró el

error.

La función gl_get_line() devuelve un puntero a la línea introducida por el usuario, o NULL en caso de error o al final de la entrada. El puntero devuelto es parte del objeto recurso gl especificado, y por lo tanto no debe ser liberado por el llamante, ni asumirse que es invariable de una llamada a la siguiente. Al leer de un usuario en una terminal, siempre habrá un carácter de salto de línea al final de la línea devuelta. Cuando la entrada estándar se toma de una tubería o de un archivo, de manera similar habrá un salto de línea a menos que la línea de entrada fuera demasiado larga para almacenarse en el búfer interno. En este último caso, debe llamar a gl_get_line() de nuevo para leer el resto de la línea. Tenga en cuenta que este comportamiento hace que gl_get_line() sea similar a fgets(). De hecho, cuando stdin no está conectado a una terminal,gl_get_line() simplemente llama a fget

s(

FUENTES DE CONFIGURACIÓN

ALTERNATIVAS

Como se mencionó anteriormente, por defecto los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. En algunas aplicaciones, sin embargo, este único medio de configuración es un problema. Esto es particularmente cierto en software embebido, donde no hay un sistema de archivos del cual leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de asignaciones de teclas para emular una interfaz de teclado heredada. Para atender a tales casos, la siguiente función permite a la aplicación controlar de dónde se lee la información de

configuración. 
  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file)
;

Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc de un usuario, se lean de cualquiera o ninguno de ellos: una cadena, un archivo de configuración específico de la aplicación y/o un archivo de configuración específico del usuario. Si esta función se llama antes de la primera llamada a gl_get_line(), el comportamiento por defecto de leer ~/.teclarc en la primera llamada a gl_get_line() se deshabilita, por lo que toda la configuración debe lograrse utilizando las fuentes de configuración especificadas con esta

función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados entre sí en la cadena por caracteres de salto de línea incrustados. Si app_file != NULL entonces se interpreta como la ruta de archivo completa de un archivo de configuración específico de la aplicación. Si user_file != NULL entonces se interpreta como la ruta de archivo completa de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente

llamada, 
  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc")
;

el argumento app_string hace que la aplicación que llama comience en el modo de edición vi, en lugar del modo emacs por defecto, y desactiva el uso de la campana de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración de todo el sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario desde un archivo .teclarc opcional en el directorio de inicio del usuario. Tenga en cuenta que los argumentos se listan en orden ascendente de prioridad, con el contenido de app_string siendo potencialmente sobreescrito por comandos en app_file, y los comandos en app_file potencialmente sobreescritos por comandos en user_file

.

Puede llamar a esta función tantas veces como sea necesario, siendo los resultados acumulativos, pero tenga en cuenta que las copias de cualquier nombre de archivo especificado a través de app_file y los argumentos user_file se registran internamente para su uso posterior por la función de vinculación de teclas read-init-files, así que si planea llamar a esta función varias veces, asegúrese de que la última llamada especifique los nombres de archivo que desea volver a leer cuando el usuario solicite que los archivos de configuración se

relean.

COMPLETADO DE PALABRAS

PERSONALIZADO

Si en su aplicación desea que el completado con TAB complete otras cosas además de o en lugar de nombres de archivo, puede organizar esto registrando una función de retorno de completado alternativa, mediante una llamada a la función gl_customize_co

mpletion(). 
  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn)
;

El argumento data proporciona una manera para que su aplicación pase información arbitraria y específica de la aplicación a la función de retorno. Esto se pasa a la función de retorno cada vez que se la llama. Podría, por ejemplo, apuntar a la tabla de símbolos de la que se deben buscar los posibles completados. El argumento match_fn especifica la función de retorno a llamar. El tipo de función CplMatchFn está definido en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y prototipar funciones de retorno. La declaración y las responsabilidades de las funciones de retorno se describen en profundidad en la página del manual cpl_complete_word(3)

.

En resumen, la función de retorno es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario presionó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar los posibles completados de esta palabra y registrarlos uno por uno en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion(). Si la función de retorno desea proporcionar completado de nombres de archivo además de sus propios completados específicos, tiene la opción de llamar ella misma a la función de retorno de completado de nombres de archivo incorporada. Esto también está documentado en la página del manual cpl_complete_word(3)

.

Tenga en cuenta que si desea que gl_get_line() devuelva la línea de entrada actual cuando se haya realizado un completado exitoso, puede organizar esto cuando llame a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de salto de línea. Si hace esto, la línea de entrada se actualizará para mostrar el completado, junto con cualquier sufijo de continuación hasta el carácter de salto de línea, y luego gl_get_line() devolverá esta línea de

entrada.

Si, por alguna razón, su función de retorno necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto iniciará una nueva línea después de la línea de entrada que se está editando actualmente, restablecerá la E/S normal de la terminal y le dirá a gl_get_line() que la línea de entrada necesitará

ser redibujada cuando la f
unción de retorno regrese.

AÑADIENDO ACCIONES DE

COMPLETADO

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de completado predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que diferentes tipos de completado de palabras se puedan vincular a diferentes secuencias de teclas. Esto se logra usando la función gl_completion_action()

. 
  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq)
;

Los argumentos data y match_fn se describen en la página del manual de cpl_complete_word, y especifican la función de retorno que debe invocarse para identificar los posibles completados. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar cualquier completado ambiguo posible, o si simplemente debe mostrar la lista de posibles completados sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre con el que los archivos de configuración y las futuras invocaciones de esta función deben referirse a la acción. Este debe ser el nombre de una acción de completado existente que se va a cambiar, o un nuevo nombre no utilizado para una nueva acción. Finalmente, el argumento keyseq especifica la secuencia de teclas predeterminada a la que vincular la acción. Si esto es NULL, no se vinculará ninguna nueva secuencia de teclas a la

acción.

Tenga cuidado de que para que el usuario pueda cambiar la secuencia de teclas vinculada a las acciones instaladas de esta manera, cuando llame a gl_completion_action() para instalar una acción determinada por primera vez, debe hacerlo entre la llamada a new_GetLine() y la primera llamada a gl_get_line(). De lo contrario, cuando se lea el archivo de configuración del usuario en la primera llamada a gl_get_line(), el nombre de su acción adicional no será conocido, y cualquier referencia a ella en el archivo de configuración generará un

error.

DEFINIENDO ACCIONES

PERSONALIZADAS

Aunque las acciones de vinculación de teclas incorporadas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, vinculadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza que correspondiera a un número de pieza anterior al cursor. Tal característica está claramente fuera del alcance de las funciones de acción incorporadas. Así que para tales casos especiales, se proporciona la función gl_register_action()

El argumento data puede ser un puntero a cualquier cosa que la aplicación desee que se pase a la función de acción, fn, cada vez que se invoque esa

función.

La función de acción, fn, debe declararse usando la siguiente macro, que está definida en libtecl

a.h. 
  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char
*line)

Los argumentos gl y data son aquellos que se pasaron previamente a gl_register_action() cuando se registró la función de acción. El argumento count es un argumento numérico que el usuario tiene la opción de ingresar usando la acción digit-argument, antes de invocar la acción. Si el usuario no ingresa un número, entonces el argumento count se establece en 1. Nominalmente, este argumento se interpreta como un conteo de repetición, lo que significa que la acción debe repetirse esa cantidad de veces. Sin embargo, en la práctica, para algunas acciones un conteo de repetición tiene poco sentido. En tales casos, las acciones pueden simplemente ignorar el argumento count o usar su valor para un propósito

diferente.

Se pasa una copia de la línea de entrada actual en el argumento de solo lectura line. La posición actual del cursor dentro de esta cadena se indica por el índice contenido en el argumento curpos. Tenga en cuenta que no se permite la manipulación directa de la línea de entrada y la posición del cursor. Esto se debe a que las reglas dictadas por varios modos, como el modo vi frente al modo emacs, el modo sin eco, y el modo de inserción frente al modo de sobrescritura, etc., hacen que sea demasiado complejo para un programador de aplicaciones escribir una acción de edición conforme, así como restringen cambios futuros en los internos de gl_get_line(). Una solución potencial a este dilema sería permitir que la función de acción edite la línea usando las acciones de edición existentes. Esto está actualmente bajo

consideración.

Si la función de acción desea escribir texto en la terminal, sin que esto se mezcle con el texto mostrado de la línea de entrada, o leer de la terminal sin tener que manejar la E/S cruda de la terminal, entonces antes de realizar cualquiera de estas operaciones, debe suspender temporalmente la edición de línea llamando a la función gl_normal_io(). Esta función vacía cualquier salida pendiente a la terminal, mueve el cursor al inicio de la línea que sigue a la última línea de terminal de la línea de entrada, y luego restaura la terminal a un estado que es adecuado para su uso con las instalaciones de stdio de C. Lo último incluye cosas como restaurar la asignación normal de \n a \r\n, y, cuando está en modo servidor, restaurar la forma normal de bloqueo de la E/S de la terminal. Después de haber llamado a esta función, la función de acción puede leer de y escribir en la terminal sin temor de crear un desorden. No es necesario que la función de acción restaure el entorno de edición original antes de regresar. Esto lo hace automáticamente la gl_get_line() después de que la función de acción regrese. Lo siguiente es un ejemplo sencillo de una función de acción que escribe la frase "Hello world" en una nueva línea de terminal después de la línea que se está editando. Cuando esta función regresa, la línea de entrada se redibuja en la línea que sigue a la línea "Hello world", y la edición de línea se

      return GLA_ABORT;

  GLA_RETURN    -   Hace que gl_get_line() devuelva la

  GLA_CONTINUE  -   Reanuda la edición de la línea de
comandos.

Tenga en cuenta que el argumento name de gl_register_action() especifica el nombre con el que un usuario puede referirse a la acción en su archivo de configuración. Esto le permite reasignar la acción a una secuencia de teclas alternativa. Para que esto funcione, es necesario llamar a gl_register_action() entre la llamada a new_GetLine() y la primera llamada a gl_get_

Esto restaurará el terminal a modo canónico, de E/S bloqueante, y moverá el cursor al comienzo de una nueva línea del terminal. Más tarde, cuando la función de retorno de llamada regrese, gl_get_line() notará que gl_normal_io() fue llamada, redisplayará la línea de entrada y reanudará la edición. entrada.

en est

SEÑALES

Por defecto, la función gl_get_line() intercepta un número de señales. Esto es particularmente importante para señales que por defecto terminarían el proceso, ya que el terminal necesita ser restaurado a un estado utilizable antes de que esto suceda. En esta sección, se describen las señales que son atrapadas por defecto, y cómo gl_get_line() responde a ellas. Cambiar estos valores por defecto es el tema de la siguiente

sección.

continuación. 
 SIGINT  -  Esta señal es generada tanto por la tecla de
            interrupción del teclado (usualmente ^C), como por la tecla de
            corte del teclado.
            errno=EINTR
 SIGHUP  -  Esta señal es generada cuando el terminal de control
            sale.
            errno=ENOTTY
 SIGPIPE -  Esta señal es generada cuando un programa intenta
            escribir en una tubería cuyo extremo remoto no está siendo leído
            por ningún proceso. Esto puede suceder, por ejemplo, si ha
            llamado a gl_change_terminal() para
            redirigir la salida a una tubería oculta bajo un terminal
            pseudo.
            errno=EPIPE
 SIGQUIT -  Esta señal es generada por la tecla de salida del
            teclado (usualmente ^\).
            errno=EINTR
 SIGABRT -  Esta señal es generada por la función estándar de C,
            abort(). Por defecto, tanto termina el proceso como genera un

            errno=EINTR

errno=EINTR

Nótese que en el caso de todas las señales anteriores, POSIX establece que por defecto el proceso es terminado, con la adición de un volcado de memoria en el caso de la señal SIGQUIT. En otras palabras, si la aplicación que llama no anula el manejador por defecto proporcionando su propio manejador de señal, la recepción de la señal correspondiente terminará la aplicación antes de que gl_get_line()

regrese.

Si gl_get_line() aborta con errno establecido a EINTR, puede averiguar qué señal causó que abortara, llamando a la siguiente

función. 
  int gl_last_signal(const GetLine *gl)
;

Esto devuelve el código numérico (p. ej. SIGINT) de la última señal que fue recibida durante la llamada más reciente a gl_get_line(), o -1 si no se recibieron

señales.

En sistemas que lo soportan, cuando se recibe una señal SIGWINCH (cambio de ventana), gl_get_line() consulta al terminal para averiguar su nuevo tamaño, redibuja la línea de entrada actual para acomodar el nuevo tamaño, luego regresa a esperar entrada de teclado del usuario. A diferencia de otras señales, esta señal no es reenviada a la

aplicación.

Finalmente, las siguientes señales causan que gl_get_line() primero restaure el terminal y el entorno de señales a lo que prevalecía antes de que se llamara a gl_get_line(), luego reenvíe la señal a la aplicación. Si el proceso todavía existe después de que la señal ha sido entregada, entonces gl_get_line() reestablece sus propios manejadores de señal, cambia el terminal de vuelta a modo crudo, redisplaya la línea de entrada, y vuelve a esperar entrada del terminal del

usuario. 
 SIGCONT    -  Esta señal es generada cuando un proceso
               suspendido es reanudado.
 SIGPOLL    -  En sistemas SVR4, esta señal notifica al
               proceso de un evento de E/S asíncrono. Nótese
               que bajo 4.3+BSD, SIGIO y SIGPOLL son
               el mismo. En otros sistemas, SIGIO es ignorado
               por defecto, así que gl_get_line() no lo
               atrapa por defecto.
 SIGPWR     -  Esta señal es generada cuando ocurre un fallo
               de energía (presumiblemente cuando el sistema está en un
               UPS).
 SIGALRM    -  Esta señal es generada cuando un temporizador
               expira.
 SIGUSR1    -  Una señal específica de la aplicación.
 SIGUSR2    -  Otra señal específica de la aplicación.
 SIGVTALRM  -  Esta señal es generada cuando expira un
               temporizador virtual (véase man setitimer(2)).
 SIGXCPU    -  Esta señal es generada cuando un proceso
               excede su límite blando de tiempo de CPU.
 SIGXFSZ    -  Esta señal es generada cuando un proceso
               excede su límite blando de tamaño de archivo.
 SIGTSTP    -  Esta señal es generada por la tecla de
               suspensión del terminal, que usualmente es ^Z, o la
               tecla de suspensión retrasada del terminal, que
               usualmente es ^Y.
 SIGTTIN    -  Esta señal es generada si el programa
               intenta leer del terminal mientras el
               programa se está ejecutando en segundo plano.
 SIGTTOU    -  Esta señal es generada si el programa
               intenta escribir en el terminal mientras el
               programa se está ejecutando en segundo
plano.

Obviamente no todas las señales anteriores están soportadas en todos los sistemas, así que el código para soportarlas es compilado condicionalmente en la biblioteca

tecla.

Nótese que si SIGKILL o SIGPOLL, que por definición no pueden ser capturadas, o cualquiera de las señales de excepción generadas por hardware, como SIGSEGV, SIGBUS y SIGFPE, son recibidas y no manejadas mientras gl_get_line() tiene el terminal en modo crudo, el programa será terminado sin que el terminal haya sido restaurado a un estado utilizable. En la práctica, los shells de contro

l de trabajos usualmente restablecen la configuración del terminal cuando un proceso re
nuncia al terminal de control, así que esto solo es un problema con shells más antiguos.

PERSONALIZADO

La sección anterior listó las señales que gl_get_line() atrapa por defecto, y describió cómo responde a ellas. Esta sección describe cómo tanto añadir como remover señales de la lista de señales atrapadas, y cómo especificar cómo gl_get_line() debería responder a una señal

dada.

Si no necesita que gl_get_line() haga algo en respuesta a una señal que normalmente atrapa, puede decirle a gl_get_line() que ignore esa señal llamando a gl_ignore_sig

nal().

;

El argumento signo es el número de la señal (p. ej. SIGINT) que quiere que sea ignorada. Si la señal especificada no es actualmente una de las que están siendo atrapadas, esta función no hace

nada.

La función gl_trap_signal() le permite tanto añadir una nueva señal a la lista que gl_get_line() atrapa, como modificar cómo respondes a una señal que ya

captura. 
  int gl_trap_signal(GetLine *gl, int signo, unsigned flags,

El argumento signo es el número de la señal que desea que se capture. El argumento flags es un conjunto de banderas que determinan el entorno en el que se invoca el manejador de señales de la aplicación, el argumento after le indica a gl_get_line() qué hacer después de que el manejador de señales de la aplicación regrese, y errno_value le indica a gl_get_line() qué asignar a errno si se le ordena

abortar.

El argumento flags es un OR bit a bit de cero o más de los siguientes

enumeradores:

                      llamador mientras se maneja la
                      señal.
  GLS_RESTORE_TTY  -  Restaura la configuración de la
                      terminal del llamador mientras se
                      maneja la señal.
  GLS_RESTORE_LINE -  Mueve el cursor al inicio de la
                      línea siguiente a la línea de entrada
                      antes de invocar el manejador de
                      señales de la aplicación.
  GLS_REDRAW_LINE  -  Redibuja la línea de entrada cuando
                      el manejador de señales de la
                      aplicación regresa.
  GLS_UNBLOCK_SIG  -  Normalmente, si el programa llamador
                      tiene una señal bloqueada (man
                      sigprocmask), gl_get_line() no
                      captura esa señal. Esta bandera le
                      dice a gl_get_line() que capture la
                      señal y la desbloquee durante la
                      duración de la llamada a
                      gl_get_line().

                      no será reenviada al manejador de
                      señales del programa
llamador.

También se enumeran dos combinaciones de banderas comúnmente útiles de la siguiente

manera: 
  GLS_RESTORE_ENV   = GLS_RESTORE_SIG | GLS_RESTORE_TTY |
                      GLS_REDRAW_LINE
  GLS_SUSPEND_INPUT = GLS_RESTORE_ENV | GLS_RESTORE_LIN
E

Si su manejador de señales, o el manejador de señales predeterminado del sistema para esta señal, si no lo ha sobrescrito, nunca escribe en la terminal, ni suspende o termina el programa llamador, entonces puede establecer de forma segura el argumento flags a 0

.

Si su manejador de señales siempre escribe en la terminal, lee de ella, o suspende o termina el programa, debe especificar el argumento flags como GL_SUSPEND_INPUT, de modo

que: 
1. El cursor no quede en medio de la línea de
   entrada.
2. Para que el usuario pueda escribir entrada y sea
   reflejada.
3. Para que no necesite terminar cada línea de salida con
   \r\n, en lugar de solo \n
.

La combinación GL_RESTORE_ENV es la misma que GL_SUSPEND_INPUT, excepto que no mueve el cursor, y si su manejador de señales no lee ni escribe nada en la terminal, el usuario no verá ninguna indicación visible de que se capturó una señal. Esto puede ser útil si tiene un manejador de señales que solo escribe ocasionalmente en la terminal, donde usar GL_SUSPEND_LINE haría que la línea de entrada se duplicara innecesariamente cuando no se hubiera escrito nada en la terminal. Un manejador de señales así, cuando escribe en la terminal, debe asegurarse de iniciar una nueva línea al inicio de su primera escritura, escribiendo un salto de línea antes de regresar. Si la señal llega mientras el usuario está ingresando una línea que solo ocupa una línea de terminal, o si el cursor está en la última línea de terminal de una línea de entrada más larga, esto tendrá el mismo efecto que GL_SUSPEND_INPUT. De lo contrario, comenzará a escribir en una línea que ya contiene parte de la línea de entrada mostrada. Esto no causa ningún daño, pero se ve un poco feo, por lo que la combinación GL_SUSPEND_INPUT es mejor si sabe que siempre va a escribir en la

terminal.

El argumento after, que determina qué hace gl_get_line() después de que el manejador de señales de la aplicación regrese (si regresa), puede tomar cualquiera de los siguientes

valores: 
  GLS_RETURN   - Devuelve la línea de entrada completada, tal
                 como si el usuario hubiera presionado la
                 tecla de retorno.
  GLS_ABORT    - Provoca que gl_get_line() aborte. Cuando

                 NULL, y una llamada posterior a
                 gl_return_status() devolverá
                 GLR_SIGNAL. Tenga en cuenta que si la
                 aplicación necesita que errno siempre
                 tenga un valor significativo cuando
                 gl_get_line() devuelva NULL,
                 la función de retorno de llamada debe asignar
                 errno apropiadamente.
  GLS_CONTINUE - Reanuda la edición de la línea de
comandos.

El argumento errno_value está destinado a combinarse con la opción GLS_ABORT, indicándole a gl_get_line() qué asignar a la variable estándar errno antes de devolver NULL al programa llamador. Sin embargo, también puede usarse con la opción GL_RETURN, en caso de que desee tener una forma de distinguir entre una línea de entrad

a que se ingresó usando la tecla de retorno y

MANEJO DE SEÑALES

FIABLE

El manejo de señales es sorprendentemente difícil de hacer de forma fiable sin condiciones de carrera. En gl_get_line() se ha tenido mucho cuidado para permitir que las aplicaciones realicen un manejo de señales fiable alrededor de gl_get_line(). Esta sección explica cómo hacer uso de

esto.

Como ejemplo de los problemas que pueden surgir si la aplicación no está escrita correctamente, imagine que su aplicación tiene un manejador de señales SIGINT que establece una bandera global. Ahora suponga que la aplicación prueba esta bandera justo antes de invocar gl_get_line(). Si una señal SIGINT resulta recibida en la pequeña ventana de tiempo entre la sentencia que prueba el valor de esta bandera y la sentencia que llama a gl_get_line(), entonces gl_get_line() no verá la señal, y no será interrumpida. Como resultado, la aplicación no podrá responder a la señal hasta que el usuario termine de ingresar la línea de entrada y gl_get_line() regrese. Dependiendo de la aplicación, esto podría o no ser un desastre, pero como mínimo confundiría al

usuario.

La forma de evitar tales problemas es hacer lo

siguiente.

1. Si es necesario, use la función gl_trap_signal() para
configurar gl_get_line() para que aborte cuando se
capturen señales

importantes.

2. Configure gl_get_line() de modo que si alguna de las
señales que captura están bloqueadas cuando se
llama a gl_get_line(), se desbloqueen
automáticamente durante los momentos en que gl_get_line() está
esperando E/S. Esto puede hacerse ya sea
de forma individual por señal, llamando a la
función gl_trap_signal(), y especificando el
atributo GLS_UNBLOCK de la señal, o globalmente
llamando a la función gl_catch_blocked()

. 
     void gl_catch_blocked(GetLine *gl)
;


Esta función simplemente agrega el atributo GLS_UNBLOCK
a todas las señales para las que está configurada actualmente para
capturar

.

3. Justo antes de llamar a gl_get_line(), bloquee la entrega
de todas las señales que gl_get_line() está
configurada para capturar. Esto puede hacerse usando la función POSIX
sigprocmask() en conjunto con la
función gl_list_signals()

. 
      int gl_list_signals(GetLine *gl, sigset_t *set)
;


Esta función devuelve el conjunto de señales que está
configurada actualmente para capturar en el argumento set,
el cual está en la forma requerida por sigprocma

sk().

4. En el ejemplo, ahora se probaría la bandera global que
establece el manejador de señales, sabiendo que ahora no hay
peligro de que esta bandera se establezca de nuevo hasta que
gl_get_line() desbloquee sus señales mientras realiza
E/S

.

5. Eventualmente gl_get_line() regresa, ya sea porque
se capturó una señal, ocurrió un error, o el usuario
terminó de ingresar su línea de

entrada.

6. Ahora se verificaría la bandera global de señal de nuevo, y si
está establecida, respondería a ella, y pondría la bandera a

cero.

7. Use sigprocmask() para desbloquear las señales que fueron
bloqueadas en el paso

3.

La misma técnica puede usarse alrededor de ciertas funciones POSIX conscientes de señales, como sigsetjmp() y sigsuspend(), y en particular, la primera de estas dos funciones puede usarse en conjunto con siglongjmp() para implementar un manejo de señales libre de condiciones de carrera alrededor de otras llamadas al sistema de larga duración. La forma de hacer esto se explica a continuación, mostrando cómo gl_get_line() logra capturar señales de forma fiable alrededor de llamadas a funciones como read() y select() sin condiciones de

carrera.

Lo primero que gl_get_line() hace, siempre que se llama, es usar la función POSIX sigprocmask() para bloquear la entrega de todas las señales para las que está configurada actualmente para capturar. Esto es redundante si la aplicación ya las ha bloqueado, pero no causa ningún daño. Deshace este paso justo antes de

regresar.

Siempre que gl_get_line() necesita llamar a read() o select() para esperar entrada del usuario, primero llama a la función POSIX sigsetjmp(), asegurándose de especificar un valor distinto de cero para su argumento savesigs. La razón de este último argumento se aclarará en

breve.

Si sigsetjmp() devuelve cero, gl_get_line() luego hace lo

siguiente. 
a. Usa la función POSIX sigaction() para registrar
   un manejador de señales temporal para todas las señales para las que está
   configurada para capturar. Este manejador de señales hace dos cosas.
   1. Registra el número de la señal que fue recibida
      en una variable de ámbito de archivo.
   2. Luego llama a la función POSIX siglongjmp()
      usando el búfer que se pasó a
      sigsetjmp() como su primer argumento, y
      un valor distinto de cero para su segundo argumento.
   Cuando este manejador de señales está registrado, el miembro sa_mask
   del argumento struct sigaction act de la
   llamada a sigaction() está configurado para contener todas
   las señales que gl_get_line() está capturando. Esto
   asegura que solo una señal sea capturada a la vez por
   nuestro manejador de señales, lo que a su vez asegura que múltiples
   instancias de nuestro manejador de señales no interfieran entre sí.
b. Ahora que el manejador de señales ha sido configurado,
   gl_get_line() desbloquea todas las señales para
   las que está configurada para capturar.
c. Luego llama a las llamadas al sistema read() o select() para esperar
   entrada del teclado.
d. Si esta llamada al sistema regresa (es decir, no se recibe
   ninguna señal),
   gl_get_line() bloquea la entrega de las señales de
   interés nuevamente.
e. Luego reinstala los manejadores de señales que fueron
   desplazados por el que acaba de
instalarse.

Alternativamente, si sigsetjmp() devuelve un valor distinto de cero, esto significa que uno de las señales que se estaban atrapando fue capturada mientras se ejecutaban los pasos anteriores. Cuando esto sucede, gl_get_line() hace

lo

siguiente. Primero, ten en cuenta que cuando una llamada a siglongjmp() hace que sigsetjmp() retorne, siempre que el argumento savesigs de sigsetjmp() fuera distinto de cero, como se especificó anteriormente, la máscara de proceso de señales se restaura a como estaba cuando sigsetjmp() fue llamada. Esta es la diferencia importante entre sigsetjmp() y el antiguo y problemático setjmp(), y es el ingrediente esencial que hace posible evitar condiciones de carrera en el manejo de señales. Debido a esto, se garantiza que todas las señales que bloqueamos antes de llamar a sigsetjmp() estén bloqueadas de nuevo tan pronto como se capture cualquier señal. Las siguientes sentencias, que se ejecutan a continuación, están por tanto garantizadas para ejecutarse sin que se capturen más

señales.

1. Si así lo indican los atributos de configuración de
gl_get_line() de la señal que fue capturada, gl_get_line()
restaura los atributos del terminal a el estado que
tenían cuando gl_get_line() fue llamada. Esto es particularmente
importante para las señales que suspenden o terminan el
proceso, ya que de lo contrario el terminal quedaría en un estado
inutilizable. 2. Luego reinstaura los manejadores

de

señales de la aplicación. 3. Luego usa la función raise() de

la

biblioteca estándar de C para reenviar a la aplicación
la señal que fue capturada. 3. A continuación, desbloquea
la entrega de

la

señal que acabamos de enviar. Esto resulta en que la señal que
fue enviada vía raise(), sea capturada por el manejador de
señales original de la aplicación, que ahora puede manejarla
como considere oportuno. 4. Si el manejador de señales retorna

HILOS

En un programa multihilo, debe usar la versión libtecla_r.a de la biblioteca. Esta usa versiones reentrantes de las funciones del sistema, cuando están disponibles. Desafortunadamente, ni terminfo ni termcap fueron diseñados para ser reentrantes, por
