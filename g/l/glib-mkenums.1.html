Paquete: glib2-devel

glib-mkenums() glib-mkenums()

Nombre

glib-mkenums - Utilidad para generar descripciones de enumeraciones en lenguaje C

SINOPSIS

glib-mkenums [OPCIÓN…] [ARCHIVO…]

DESCRIPCIÓN

glib-mkenums es una pequeña utilidad que analiza código C para extraer definiciones de enumeraciones y produce descripciones de enumeraciones basadas en plantillas de texto especificadas por el usuario. Normalmente, puede usar esta herramienta para generar tipos de enumeración para el sistema de tipos GType, para propiedades de GObject y marshalling de señales; además, puede usarla para generar valores de enumeración de esquemas GSettings.

glib-mkenums toma como entrada una lista de archivos de código C válidos. Las opciones especificadas controlan el texto generado, sustituyendo varias palabras clave encerradas en @ caracteres en las plantillas.

Desde la versión 2.74, GLib proporciona las macros de preprocesador C G_DEFINE_ENUM_TYPE y G_DEFINE_FLAGS_TYPE Estas macros pueden usarse para definir un GType para proyectos que tienen pocas y pequeñas enumeraciones sin pasar por las complejidades de generar código en tiempo de compilación.

SUSTITUCIONES DE TEXTO DE PRODUCCIÓN

Ciertas palabras clave encerradas en @ caracteres serán sustituidas en el texto emitido. Para los ejemplos de sustitución de las palabras clave siguientes, se asume la siguiente definición de enumeración de ejemplo:

typedef enum
{
  PREFIX_THE_XVALUE    = 1 << 3,
  PREFIX_ANOTHER_VALUE = 1 << 4
} PrefixTheXEnum;

@EnumName@

El nombre de la enumeración que se está procesando actualmente, se asume que los nombres de enumeraciones están correctamente espaciados en nombres y usan capitalización mixta para separar palabras (por ejemplo, PrefixTheXEnum).

@enum_name@

El nombre de la enumeración con las palabras en minúsculas y separadas por guiones bajos (por ejemplo, prefix_the_xenum).

@ENUMNAME@

El nombre de la enumeración con las palabras en mayúsculas y separadas por guiones bajos (por ejemplo, PREFIX_THE_XENUM).

@ENUMSHORT@

El nombre de la enumeración con las palabras en mayúsculas y separadas por guiones bajos, con el prefijo eliminado (por ejemplo, THE_XENUM).

@ENUMPREFIX@

El prefijo del nombre de la enumeración (por ejemplo, PREFIX).

@VALUENAME@

El nombre del valor de enumeración que se está procesando actualmente con las palabras en mayúsculas y separadas por guiones bajos, esta es la notación literal asumida de los valores de enumeración en los fuentes C (por ejemplo, PREFIX_THE_XVALUE).

@valuenick@

Un apodo para el valor de enumeración que se está procesando actualmente, esto se genera normalmente eliminando las palabras de prefijo comunes de todos los valores de enumeración de la enumeración actual, las palabras están en minúsculas y los guiones bajos se sustituyen por un guion (por ejemplo, the-xvalue).

@valuenum@

El valor entero para el valor de enumeración que se está procesando actualmente. Si la evaluación falla, glib-mkenums saldrá con un estado de error, pero esto solo ocurre si @valuenum@ aparece en su plantilla de producción de valores. (Desde: 2.26)

@type@

Esto se sustituye por ‘enum’ o ‘flags’, dependiendo de si las definiciones de valores de enumeración contenían operadores de desplazamiento de bits (por ejemplo, flags).

@Type@

Igual que @type@ con la primera letra en mayúscula (por ejemplo, Flags).

@TYPE@

Igual que @type@ con todas las letras en mayúsculas (por ejemplo, FLAGS).

@filename@

La ruta completa del archivo de entrada que se está procesando actualmente (por ejemplo, /build/environment/project/src/foo.h).

@basename@

El nombre base del archivo de entrada que se está procesando actualmente (por ejemplo, foo.h). Normalmente, desea usar @basename@ en lugar de @filename@ en sus plantillas, para mejorar la reproducibilidad de la compilación. (Desde: 2.22)

EXTENSIONES DE TRIGRAFO

Algunos comentarios C se tratan de manera especial en las definiciones de enumeraciones analizadas, estos comentarios comienzan con la secuencia de trigrafo /*< y terminan con la secuencia de trigrafo >*/.

Las siguientes opciones pueden especificarse por cada definición de enumeración:

skip

Indica que esta definición de enumeración debe omitirse.

flags

Indica que esta enumeración debe tratarse como una definición de flags.

underscore_name

Especifica la separación de palabras usada en la función *_get_type() Por ejemplo, /*< underscore_name=gnome_vfs_uri_hide_options >*/.

since

Especifica la etiqueta de versión que se usará para sustituir la palabra clave @enumsince@ en la plantilla, útil al documentar métodos generados a partir de las enumeraciones (por ejemplo, Since: @enumsince@). (Desde: 2.66)

Las siguientes opciones pueden especificarse por cada definición de valor:

skip

Indica que el valor debe omitirse.

nick

Especifica el apodo que de otro modo se generaría automáticamente.

Ejemplos:

typedef enum /*< skip >*/
{
  PREFIX_FOO
} PrefixThisEnumWillBeSkipped;
typedef enum /*< flags,prefix=PREFIX,since=1.0 >*/
{
  PREFIX_THE_ZEROTH_VALUE,   /*< skip >*/
  PREFIX_THE_FIRST_VALUE,
  PREFIX_THE_SECOND_VALUE,
  PREFIX_THE_THIRD_VALUE,    /*< nick=the-last-value >*/
} PrefixTheFlagsEnum;

OPCIONES

--fhead <TEXTO>

Emite TEXTO antes de procesar los archivos de entrada.

Puede especificar esta opción varias veces, y TEXTO se concatenará.

Cuando se usa junto con un archivo de plantilla, TEXTO se antepondrá a la sección file-header de la plantilla.

--fprod <TEXTO>

Emite TEXTO cada vez que se procesa un nuevo archivo de entrada.

Puede especificar esta opción varias veces, y TEXTO se concatenará.

Cuando se usa junto con un archivo de plantilla, TEXTO se añadirá a la sección file-production de la plantilla.

--ftail <TEXTO>

Emite TEXTO después de que se hayan procesado todos los archivos de entrada.

Puede especificar esta opción varias veces, y TEXTO se concatenará.

Cuando se usa junto con un archivo de plantilla, TEXTO se añadirá a la sección file-tail de la plantilla.

--eprod <TEXTO>

Emite TEXTO cada vez que se encuentra una enumeración en los archivos de entrada.

--vhead <TEXTO>

Emite TEXTO antes de iterar sobre el conjunto de valores de una enumeración.

Puede especificar esta opción varias veces, y TEXTO se concatenará.

Cuando se usa junto con un archivo de plantilla, TEXTO se antepondrá a la sección value-header de la plantilla.

--vprod <TEXTO>

Emite TEXTO para cada valor de una enumeración.

Puede especificar esta opción varias veces, y TEXTO se concatenará.

Cuando se usa junto con un archivo de plantilla, TEXTO se añadirá a la sección value-production de la plantilla.

--vtail <TEXTO>

Emite TEXTO después de iterar sobre todos los valores de una enumeración. s="Pp">Puedes especificar esta opción varias veces, y el TEXTO se concatenará.

Cuando se usa junto con un archivo de plantilla, el TEXTO se añadirá a la sección value-tail de la plantilla.

--comments <TEXTO>

Plantilla para comentarios autogenerados, el valor predeterminado (para generaciones de código C) es "/* @comment@ */".

--template <ARCHIVO>

Lee las plantillas del archivo dado. Las plantillas están encerradas en comentarios C con un formato especial: 
/*** BEGIN section ***/
/*** END section ***/

section puede ser file-header, file-production, file-tail, enumeration-production, value-header, value-production, value-tail o comment.

--identifier-prefix <PREFIJO>

Indica qué parte del nombre del enum debe interpretarse como el prefijo (por ejemplo, el Gtk en GtkDirectionType). Normalmente se deducirá automáticamente, pero es posible que necesites anular el valor predeterminado si tu espacio de nombres tiene una capitalización inusual.

--symbol-prefix <PREFIJO>

Indica qué prefijo debe usarse para corresponder al prefijo del identificador en los nombres de funciones C relacionadas (por ejemplo, el gtk en gtk_direction_type_get_type). Equivalente a la versión en minúsculas del componente de prefijo de los nombres de valores del enum (por ejemplo, el GTK en GTK_DIR_UP). El valor predeterminado es el prefijo del identificador, convertido a minúsculas.

--help

Imprime una ayuda breve y sale.

--version

Imprime la versión y sale.

--output <ARCHIVO>

Escribe la salida en ARCHIVO en lugar de en stdout.

@ARCHIVO_RSP

Cuando se pasa como único argumento, lee y analiza los argumentos reales desde ARCHIVO_RSP. Útil en sistemas con un límite bajo en la longitud de la línea de comandos. Por ejemplo, Windows tiene un límite de 8191 caracteres.

USO DE PLANTILLAS

En lugar de pasar las distintas secciones del archivo generado por la línea de comandos de glib-mkenums, se recomienda encarecidamente usar un archivo de plantilla, especialmente para generar fuentes en C.

Un archivo de plantilla de cabecera C típicamente tendrá este aspecto:

/*** BEGIN file-header ***/
#pragma once
/* Include the main project header */
#include "project.h"
G_BEGIN_DECLS
/*** END file-header ***/
/*** BEGIN file-production ***/
/* enumerations from "@basename@" */
/*** END file-production ***/
/*** BEGIN value-header ***/
GType @enum_name@_get_type (void) G_GNUC_CONST;
#define @ENUMPREFIX@_TYPE_@ENUMSHORT@ (@enum_name@_get_type ())
/*** END value-header ***/
/*** BEGIN file-tail ***/
G_END_DECLS
/*** END file-tail ***/

Un archivo de plantilla de fuente C típicamente tendrá este aspecto:

/*** BEGIN file-header ***/
#include "config.h"
#include "enum-types.h"
/*** END file-header ***/
/*** BEGIN file-production ***/
/* enumerations from "@basename@" */
/*** END file-production ***/
/*** BEGIN value-header ***/
GType
@enum_name@_get_type (void)
{
  static GType static_g_@type@_type_id = 0;
  if (g_once_init_enter_pointer (&static_g_@type@_type_id))
    {
      static const G@Type@Value values[] = {
/*** END value-header ***/
/*** BEGIN value-production ***/
        { @VALUENAME@, "@VALUENAME@", "@valuenick@" },
/*** END value-production ***/
/*** BEGIN value-tail ***/
        { 0, NULL, NULL }
      };
      GType g_@type@_type_id =
        g_@type@_register_static (g_intern_static_string ("@EnumName@"), values);
      g_once_init_leave_pointer (&static_g_@type@_type_id, g_@type@_type_id);
    }
  return static_g_@type@_type_id;
}
/*** END value-tail ***/

Los archivos de plantilla son más fáciles de modificar y actualizar, y pueden usarse para generar varios tipos de salidas usando la misma línea de comandos o herramientas durante la compilación.

USO DE GLIB-MKENUMS CON MESON

Meson admite la generación de tipos de enumeración usando glib-mkenums de forma nativa en su módulo gnome .

En tu archivo meson.build normalmente llamarás al método gnome.mkenums_simple() para generar tipos de enumeración idiomáticos a partir de una lista de cabeceras a inspeccionar:

project_headers = [
  'project-foo.h',
  'project-bar.h',
  'project-baz.h',
]
gnome = import('gnome')
enum_files = gnome.mkenums_simple('enum-types',
  sources: project_headers,
)

La variable enum_files contendrá un array de dos elementos en el siguiente orden:

1.
un objetivo de compilación para el archivo fuente
2.
un objetivo de compilación para el archivo de cabecera

Debes usar los objetos devueltos para proporcionar una dependencia en todos los demás objetivos de compilación que referencien el archivo fuente o de cabecera; por ejemplo, si estás usando la fuente para compilar una biblioteca:

mainlib = library('project',
  sources: project_sources + enum_files,
  …
)

Además, si estás incluyendo el archivo de cabecera generado dentro de un objetivo de compilación que depende de la biblioteca que acabas de construir, debes asegurarte de que la dependencia interna incluya el archivo de cabecera generado como archivo fuente requerido:

mainlib_dep = declare_dependency(sources: enum_files[1], link_with: mainlib)

No debes incluir también el archivo fuente generado, de lo contrario se compilará por separado para cada objetivo que dependa de él, causando fallos de compilación. Para saber más sobre por qué se requiere todo esto, consulta la entrada correspondiente en las preguntas frecuentes de Meson https://mesonbuild.com/FAQ.html#how-do-i-tell-meson-that-my-sources-use-generated-headers.

Si estás generando archivos de cabecera y fuente C que requieren plantillas especiales, puedes usar gnome.mkenums() para proporcionar esas cabeceras, por ejemplo:

enum_files = gnome.mkenums('enum-types',
  sources: project_headers,
  h_template: 'enum-types.h.in',
  c_template: 'enum-types.c.in',
  install_header: true,
)

Para más información, consulta la documentación de Meson https://mesonbuild.com/Gnome-module.html#gnomegenmarshal para gnome.mkenums().

USO DE GLIB-MKENUMS CON AUTOTOOLS

Para usar glib-mkenums en tu proyecto cuando usas Autotools como sistema de compilación, primero necesitarás modificar tu archivo configure.ac para asegurarte de encontrar el comando apropiado usando pkg-config, de manera similar a como descubres los indicadores del compilador y del enlazador para GLib:

PKG_PROG_PKG_CONFIG([0.28])
PKG_CHECK_VAR([GLIB_MKENUMS], [glib-2.0], [glib_mkenums])

En tu archivo Makefile.am normalmente usarás reglas como estas:

# A list of headers to inspect
project_headers = \
        project-foo.h \
        project-bar.h \
        project-baz.h
enum-types.h: $(project_headers) enum-types.h.in
        $(AM_V_GEN)$(GLIB_MKENUMS) \
                --template=enum-types.h.in \
                --output=$@ \
               $(project_headers)
enum-types.c: $(project_headers) enum-types.c.in enum-types.h
        $(AM_V_GEN)$(GLIB_MKENUMS) \
                --template=enum-types.c.in \
                --output=$@ \
                $(project_headers)
# Build the enum types files before every other target
BUILT_SOURCES += enum-types.h enum-types.c
CLEANFILES += enum-types.h enum-types.c
EXTRA_DIST += enum-types.h.in enum-types.c.in

En el ejemplo anterior, tenemos una variable llamada project_headers donde referenciamos todos los archivos de cabecera que queremos inspeccionar para generar GTypes de enumeración. En la enum-types.h regla usamos glib-mkenums con una plantilla llamada enum-types.h.in para generar el archivo de cabecera; de manera similar, en la enum-types.c regla usamos una plantilla llamada enum-types.c.in.
