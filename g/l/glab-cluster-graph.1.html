NOMBRE

glab-cluster-graph - Consulta el grafo de objetos de Kubernetes, utilizando el Agente de GitLab para Kubernetes. (EXPERIMENTAL)

SINOPSIS

glab cluster graph [flags]

DESCRIPCIÓN

Este comando inicia un servidor web que muestra una vista en vivo del grafo de objetos de Kubernetes en un navegador. Utiliza el Agente de GitLab para Kubernetes que se ejecuta en el clúster. Requiere:

  • Versión 18.1 o posterior de GitLab y del Agente de GitLab.
  • Al menos el rol de Desarrollador en el proyecto del agente.
  • Este comando requiere un token de acceso personal o un token de acceso de proyecto para la autenticación. El token debe tener los ámbitos read_api y k8s_proxy.

Deja comentarios en el issue 7900 ⟨https://gitlab.com/gitlab-org/cli/-/issues/7900⟩.

Filtrado de recursos

Para filtrar recursos, espacios de nombres y seleccionar objetos raíz, utiliza el Lenguaje de Expresiones Comunes (CEL) ⟨https://cel.dev/⟩.

object_selector_expression: Filtra objetos. La expresión debe devolver un booleano. Estas variables están disponibles:

  • obj: El objeto de Kubernetes que se está evaluando.
  • group: El grupo del objeto.
  • version: La versión del objeto.
  • resource: El nombre del recurso del objeto, como pods para el tipo Pod.
  • namespace: El espacio de nombres del objeto.
  • name: El nombre del objeto.
  • labels: Las etiquetas del objeto.
  • annotations: Las anotaciones del objeto.

resource_selector_expression: Filtra la información de descubrimiento de Kubernetes para incluir o excluir recursos de la solicitud de watch. La expresión debe devolver un booleano. Estas variables están disponibles:

  • group: El grupo del objeto.
  • version: La versión del objeto.
  • resource: El nombre del recurso del objeto, como pods para el tipo Pod.
  • namespaced: El ámbito del grupo, versión y recurso. Puede ser bool, true o false.

Para seleccionar objetos raíz, utiliza la bandera --root-expression. Cuando se establece, solo se muestran los objetos que son alcanzables directa o transitivamente desde los objetos raíz. Esta bandera utiliza las mismas variables que object_selector_expression y debe devolver un booleano. Múltiples valores se unen con declaraciones OR. Si alguno coincide, el objeto se utiliza como raíz.

Para más información sobre el uso de selectores de etiquetas ⟨https://kubernetes.io/docs/concepts/overview/working-with-objects/labels/#label-selectors⟩ y selectores de campos ⟨https://kubernetes.io/docs/concepts/overview/working-with-objects/field-selectors/⟩ para seleccionar espacios de nombres, consulta la documentación de Kubernetes.

Uso avanzado

Aparte de las formas de alto nivel para construir la consulta, este comando te permite construir y enviar la consulta utilizando todas las características de la API subyacentes. Para entender qué es posible y cómo hacerlo, consulta el documento de diseño técnico ⟨https://gitlab.com/gitlab-org/cluster-integration/gitlab-agent/-/blob/master/doc/graph_api.md⟩

El usuario debe tener permiso para acceder al proyecto del agente. Para más información, consulta Otorgar acceso a Kubernetes a los usuarios ⟨https://docs.gitlab.com/user/clusters/agent/user_access/⟩.

Esta característica es experimental. Puede estar rota o eliminarse sin previo aviso. Lee más sobre lo que significan las características experimentales en https://docs.gitlab.com/policy/development_stages_support/

Utiliza las características experimentales bajo tu propio riesgo.

OPCIONES

-a, --agent=0 El ID numérico del Agente al que conectarse.

--apps[=false] Vigila despliegues, replicasets, daemonsets y statefulsets en el grupo apps/v1.

--batch[=false] Vigila jobs y cronjobs en el grupo batch/v1.

--cluster-rbac[=false] Vigila clusterroles y clusterrolebindings en el grupo rbac.authorization.k8s.io/v1.

--core[=false] Vigila pods, secrets, configmaps y serviceaccounts en el grupo core/v1

--crd[=false] Vigila customresourcedefinitions en el grupo apiextensions.k8s.io/v1.

--ignore-arc-direction[=false] Ignora la dirección del arco al evaluar la conectividad de las raíces. Requiere GitLab y agente 18.3+.

--listen-addr="localhost:0" Dirección en la que escuchar.

--listen-net="tcp" Red en la que escuchar conexiones.

--log-watch-request[=false] Registra la solicitud de watch en stdout. Útil para depuración.

-n, --namespace=[] Espacios de nombres a vigilar. Si no se especifican, se vigilan todos los espacios de nombres con filtrado de selectores de etiquetas y campos.

--ns-expression="" Expresión CEL para seleccionar espacios de nombres. Se evalúa antes de que se vigile un espacio de nombres y en cualquier actualización del objeto namespace.

--ns-field-selector="" Selector de campo para seleccionar espacios de nombres.

--ns-label-selector="" Selector de etiquetas para seleccionar espacios de nombres.

--rbac[=false] Vigila roles y rolebindings en el grupo rbac.authorization.k8s.io/v1.

-r, --resource=[] Una lista de recursos a vigilar. Puedes ver la lista de recursos que tu clúster soporta ejecutando 'kubectl api-resources'.

--root-expression=[] Expresión CEL para seleccionar objetos raíz. Requiere GitLab y agente 18.3+.

--stdin[=false] Lee la solicitud de watch desde la entrada estándar.

OPCIONES HEREDADAS DE COMANDOS PADRE

-h, --help[=false] Muestra la ayuda para este comando.

-R, --repo="" Selecciona otro repositorio. Puede usar el formato OWNER/REPO o GROUP/NAMESPACE/REPO. También acepta URL completas o URL Git.

EJEMPLO

# Ejecuta la consulta por defecto para el agente 123
$ glab cluster graph -R usuario/proyecto -a 123
# Muestra recursos comunes de los grupos core y RBAC
$ glab cluster graph -R usuario/proyecto -a 123 --core --rbac
# Muestra recursos específicos
$ glab cluster graph -R usuario/proyecto -a 123 --resource=pods --resource=configmaps
# Lo mismo que arriba, pero más compacto
$ glab cluster graph -R usuario/proyecto -a 123 -r={pods,configmaps}
# Selecciona un espacio de nombres específico
$ glab cluster graph -R usuario/proyecto -a 123 -n={mi-ns,mi-cosa}
# Selecciona todos los espacios de nombres que tengan una anotación específica
$ glab cluster graph -R usuario/proyecto -a 123 --ns-expression='"mi-anotacion" in annotations'
# Uso avanzado - pasa la consulta completa directamente a través de stdin.
# La consulta siguiente vigila service accounts en todos los espacios de nombres excepto en kube-system.
$ Q='{"queries":[{"include":{"resource_selector_expression":"resource == \"serviceaccounts\""}}],"namespaces":{"object_selector_expression":"name != \"kube-system\""}}'
$ echo -n "$Q" | glab cluster graph -R usuario/proyecto -a 123 --stdin
# Filtrado de raíces
$ glab cluster graph -R usuario/proyecto -a 123 --root-expression 'group == "" && resource == "pods"'
