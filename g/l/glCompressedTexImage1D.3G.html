GLCOMPRESSEDTEXIMAGE(3G) [FIXME: manual] GLCOMPRESSEDTEXIMAGE(3G)

NOMBRE

glCompressedTexImage1D - especifica una imagen de textura unidimensional en un formato comprimido

ESPECIFICACIÓN EN C

void glCompressedTexImage1D(GLenumtarget, GLintlevel, GLenuminternalformat, GLsizeiwidth, GLintborder, GLsizeiimageSize, const void *data);

PARÁMETROS

target

Especifica la textura de destino. Debe ser GL_TEXTURE_1D o GL_PROXY_TEXTURE_1D.

level

Especifica el número de nivel de detalle. El nivel 0 es el nivel de imagen base. El nivel n es la n-ésima imagen de reducción del mipmap.

internalformat

Especifica el formato de los datos de imagen comprimidos almacenados en la dirección data.

width

Especifica el ancho de la imagen de textura. Todas las implementaciones admiten imágenes de textura con al menos 64 texels de ancho. La altura de la imagen de textura 1D es 1.

border

Este valor debe ser 0.

imageSize

Especifica el número de bytes sin signo de los datos de imagen que comienzan en la dirección especificada por data.

data

Especifica un puntero a los datos de imagen comprimidos en memoria.

DESCRIPCIÓN

El mapeo de texturas permite que los elementos de un arreglo de imágenes sean leídos por los shaders.

glCompressedTexImage1D carga una imagen de textura unidimensional comprimida previamente definida y recuperada si target es GL_TEXTURE_1D (véase glTexImage1D()).

Si target es GL_PROXY_TEXTURE_1D, no se leen datos desde data, pero todo el estado de la imagen de textura es recalculado, verificado en cuanto a consistencia y verificado con las capacidades de la implementación. Si la implementación no puede manejar una textura del tamaño solicitado, establece todo el estado de la imagen en 0, pero no genera un error (véase glGetError()). Para consultar un arreglo completo de mipmap, use un nivel de arreglo de imagen mayor o igual a 1.

internalformat debe ser un formato de textura comprimida especificado por una extensión. Cuando una textura se carga con glTexImage1D() usando un formato de textura comprimida genérico (por ejemplo, GL_COMPRESSED_RGB) el GL selecciona una de sus extensiones que admiten texturas comprimidas. Para cargar la imagen de textura comprimida usando glCompressedTexImage1D, consulte el tamaño y el formato de la imagen de textura comprimida usando glGetTexLevelParameter().

Si un objeto buffer con nombre distinto de cero está enlazado al objetivo GL_PIXEL_UNPACK_BUFFER (véase glBindBuffer()) mientras se especifica una imagen de textura, data se trata como un desplazamiento de bytes dentro del almacén de datos del objeto buffer.

Si los datos comprimidos están organizados en bloques de tamaño fijo de texels, los modos de almacenamiento de píxeles pueden usarse para seleccionar un subrectángulo de un rectángulo contenedor más grande. Estos modos de almacenamiento de píxeles operan de la misma manera que lo hacen para glTexImage1D(). En la siguiente descripción, denótese por bs, bw, bh y bd los valores de los modos de almacenamiento de píxeles GL_UNPACK_COMPRESSED_BLOCK_SIZE, GL_UNPACK_COMPRESSED_BLOCK_WIDTH, GL_UNPACK_COMPRESSED_BLOCK_HEIGHT, y GL_UNPACK_COMPRESSED_BLOCK_DEPTH, respectivamente. bs es el tamaño del bloque comprimido en bytes; bw, bh y bd son el ancho, la altura y la profundidad del bloque comprimido en píxeles.

Por defecto, los modos de almacenamiento de píxeles GL_UNPACK_ROW_LENGTH, GL_UNPACK_SKIP_ROWS, GL_UNPACK_SKIP_PIXELS, GL_UNPACK_IMAGE_HEIGHT y GL_UNPACK_SKIP_IMAGES se ignoran para imágenes comprimidas. Para habilitar GL_UNPACK_SKIP_PIXELS y GL_UNPACK_ROW_LENGTH, bs y bw deben ser ambos distintos de cero. Para habilitar también GL_UNPACK_SKIP_ROWS y GL_UNPACK_IMAGE_HEIGHT, bh debe ser distinto de cero. Para habilitar también GL_UNPACK_SKIP_IMAGES, bd debe ser distinto de cero. Todos los parámetros deben ser consistentes con el formato comprimido para producir los resultados deseados.

Al seleccionar un subrectángulo de una imagen comprimida,

•el valor de GL_UNPACK_SKIP_PIXELS debe ser un múltiplo de bw

imageSize debe ser igual a:

b s × width b w

ERRORES

GL_INVALID_ENUM se genera si internalformat no es un formato interno comprimido específico admitido, o es uno de los formatos internos comprimidos genéricos: GL_COMPRESSED_RED, GL_COMPRESSED_RG, GL_COMPRESSED_RGB, GL_COMPRESSED_RGBA. GL_COMPRESSED_SRGB, o GL_COMPRESSED_SRGB_ALPHA.

GL_INVALID_VALUE se genera si imageSize no es consistente con el formato, las dimensiones y el contenido de los datos de imagen comprimidos especificados.

GL_INVALID_VALUE se genera si border no es 0.

GL_INVALID_OPERATION se genera si las combinaciones de parámetros no son admitidas por el formato interno comprimido específico como se especifica en la extensión de compresión de textura específica.

GL_INVALID_OPERATION se genera si un nombre de objeto buffer distinto de cero está enlazado al objetivo GL_PIXEL_UNPACK_BUFFER y el almacén de datos del objeto buffer está actualmente mapeado.

GL_INVALID_OPERATION se genera si un nombre de objeto buffer distinto de cero está enlazado al objetivo GL_PIXEL_UNPACK_BUFFER y los datos se desempaquetarían del objeto buffer de manera que las lecturas de memoria requeridas excederían el tamaño del almacén de datos.

Se generan resultados indefinidos, incluyendo la terminación anormal del programa, si data no está codificado de una manera consistente con la especificación de la extensión que define el formato de compresión interno.
