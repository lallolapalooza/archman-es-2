función gl_get_line() es parte de la biblioteca tecla (véase la página man libtecla(3)). Si el usuario está escribiendo en un terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de unix. Completado de Palabras Personalizado

Si en su aplicación desea que la compleción TAB complete otras cosas además de o en lugar de los nombres de archivo, puede organizarlo registrando una función de devolución de llamada de compleción alternativa, mediante una llamada a la función gl_customize_completion().

  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn);

El argumento data proporciona una forma para que su aplicación pase información arbitraria y específica de la aplicación a la función de devolución de llamada. Esto se pasa a la devolución de llamada cada vez que se llama. Por ejemplo, podría apuntar a la tabla de símbolos de la que se buscarán las compleciones posibles. El argumento match_fn especifica la función de devolución de llamada que se llamará. El tipo de función CplMatchFn se define en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede utilizar para declarar y prototipar funciones de devolución de llamada. La declaración y las responsabilidades de las funciones de devolución de llamada se describen en detalle en la página del manual cpl_complete_word(3).

En resumen, la función de devolución de llamada es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario presionó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar compleciones posibles de esta palabra y registrarlas una por una en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion(). Si la función de devolución de llamada desea proporcionar completado de nombres de archivo además de sus propias compleciones específicas, tiene la opción de llamar ella misma a la función de devolución de llamada de nombre de archivo incorporada. Esto también se documenta en la página del manual cpl_complete_word(3).

Tenga en cuenta que si desea que gl_get_line() devuelva la línea de entrada actual cuando se realiza una compleción exitosa, puede organizarlo cuando llama a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de nueva línea. Si hace esto, la línea de entrada se actualizará para mostrar la compleción, junto con cualquier sufijo de continuación hasta el carácter de nueva línea, luego gl_get_line() devolverá esta línea de entrada.

Si, por alguna razón, su función de devolución de llamada necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto iniciará una nueva línea después de la línea que se está editando actualmente, restablecerá la E/S normal de la terminal y le dirá a gl_get_line() que la línea de entrada deberá redibujarse cuando la devolución de llamada regrese.

Agregando Acciones de Completado

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de completado predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que diferentes tipos de completado de palabras se puedan enlazar a diferentes secuencias de teclas. Esto se logra utilizando la función gl_completion_action().

  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq);

Los argumentos data y match_fn son como se describen en la página del manual cpl_complete_word, y especifican la función de devolución de llamada que se invocará para identificar compleciones posibles. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar posibles compleciones ambiguas, o si simplemente debe mostrar la lista de compleciones posibles sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre por el cual los archivos de configuración y las invocaciones futuras de esta función deben referirse a la acción. Este debe ser el nombre de una acción de completado existente a modificar, o un nuevo nombre no utilizado para una nueva acción. Finalmente, el argumento keyseq especifica la secuencia de teclas predeterminada a la que enlazar la acción. Si es NULL, no se enlaza ninguna secuencia de teclas nueva a la acción.

Tenga en cuenta que para que el usuario pueda cambiar la secuencia de teclas que se enlaza a las acciones que se instalan de esta manera, cuando llama a gl_completion_action() para instalar una acción dada por primera vez, debe hacerlo entre la llamada a new_GetLine() y la primera llamada a gl_get_line(). De lo contrario, cuando se lea el archivo de configuración del usuario en la primera llamada a gl_get_line(), no se conocerá el nombre de su acción adicional y cualquier referencia a ella en el archivo de configuración generará un error.

Como se discutió para gl_customize_completion(), si su función de devolución de llamada, por alguna razón, necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo.

Definiendo Acciones Personalizadas

Aunque las acciones de enlace de teclas incorporadas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, enlazadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza que correspondiera a un número de pieza anterior al cursor. Dicha característica está claramente fuera del alcance de las funciones de acción incorporadas. Por lo tanto, para tales casos especiales, se proporciona la función gl_register_action().

  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq);

Esta función permite a la aplicación registrar una función externa, fn, que posteriormente se llamará cada vez que el usuario introduzca la secuencia de teclas especificada, keyseq, o el usuario introduzca cualquier otra secuencia de teclas que el usuario enlace posteriormente a la acción especificada, name, en su archivo de configuración. El argumento data puede ser un puntero a cualquier cosa que la aplicación desee pasar a la función de acción, fn, cada vez que se invoque esa función.

La función de acción, fn, debe declararse utilizando la siguiente macro, que se define en libtecla.h.

  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char *line)

Los argumentos gl y data son aquellos que se pasaron previamente a gl_register_action() cuando se registró la función de acción. El argumento count es un argumento numérico que el usuario tiene la opción de introducir utilizando la acción digit-argument, antes de invocar la acción. Si el usuario no introduce un número, el argumento count se establece en 1. Nominalmente, este argumento se interpreta como un recuento de repetición, lo que significa que la acción debe repetirse ese número de veces. En la práctica, sin embargo, para algunas acciones un recuento de repetición tiene poco sentido. En tales casos, las acciones pueden simplemente ignorar el argumento count, o utilizar su valor para un propósito diferente.

Se pasa una copia de la línea de entrada actual en el argumento de solo lectura line. La posición actual del cursor dentro de esta cadena se da por el índice contenido en el argumento curpos. Tenga en cuenta que no se permite la manipulación directa de la línea de entrada y la posición del cursor. Esto se debe a que las reglas dictadas por varios modos, como el modo vi frente al modo emacs, el modo sin eco y el modo de inserción frente al modo de sobrescritura, etc., hacen que sea demasiado complejo para un escritor de aplicaciones escribir una acción de edición que cumpla, además de restringir los cambios futuros en los detalles internos de gl_get_line(). Una solución potencial a este dilema sería permitir que la función de acción edite la línea utilizando las acciones de edición existentes. Esto se está considerando actualmente.

Si la función de acción desea escribir texto en la terminal, sin que esto se mezcle con el texto mostrado de la línea de entrada, o leer desde la terminal sin tener que manejar E/S de terminal en bruto, entonces antes de realizar cualquiera de estas operaciones, debe suspender temporalmente la edición de línea llamando a la función gl_normal_io(). Esta función vacía cualquier salida pendiente a la terminal, mueve el cursor al inicio de la línea que sigue a la última línea de terminal de la línea de entrada, luego restaura la terminal a un estado adecuado para su uso con las facilidades de E/S estándar de C. Este último incluye cosas como restaurar el mapeo normal de \n a \r\n, y, cuando está en modo servidor, restaurar la forma de bloqueo normal de la E/S de terminal. Habiendo llamado a esta función, la función de acción puede leer y escribir en la terminal sin temor a crear un desastre. No es necesario que la función de acción restaure el entorno de edición original antes de que regrese. Esto lo hace automáticamente gl_get_line() después de que la función de acción regresa. continuación.

usuario.

PERSONALIZADO

La sección anterior listó las señales que gl_get_line() atrapa por defecto, y describió cómo responde a ellas. Esta sección describe cómo tanto agregar como eliminar señales de la lista de señales atrapadas, y cómo especificar cómo gl_get_line() debería responder a una señal

dada.

Si no necesita que gl_get_line() haga algo en respuesta a una señal que normalmente atrapa, puede decirle a gl_get_line() que ignore esa señal llamando a gl_ignore_sig

nal().

;

El argumento signo es el número de la señal (p. ej. SIGINT) que quiere que sea ignorada. Si la señal especificada no es actualmente una de las que están siendo atrapadas, esta función no hace

nada.

La función gl_trap_signal() le permite tanto agregar una nueva señal a la lista que gl_get_line() atrapa, como modificar cómo responde a una señal que ya

captura. 
  int gl_trap_signal(GetLine *gl, int signo, unsigned flags,

El argumento signo es el número de la señal que desea que se capture. abortar.

El argumento flags es un OR bit a bit de cero o más de los siguientes

enumeradores:

                      llamador mientras se maneja la
                      señal.

                      llamador mientras se maneja la señal.

                      línea siguiente a la línea de entrada antes
                      de invocar el manejador de señales de la
                      aplicación.
  GLS_REDRAW_LINE  -  Redibuja la línea de entrada cuando
                      el manejador de señales de la aplicación
                      regresa.
  GLS_UNBLOCK_SIG  -  Normalmente, si el programa llamador tiene
                      una señal bloqueada (man sigprocmask),
                      gl_get_line() no captura esa

                      la llamada a
                      gl_get_line().

                      programa
llamador.

También se enumeran dos combinaciones de indicadores comúnmente útiles de la siguiente

manera: 
  GLS_RESTORE_ENV   = GLS_RESTORE_SIG | GLS_RESTORE_TTY |
                      GLS_REDRAW_LINE

E

Si su manejador de señales, o el manejador de señales predeterminado del sistema para esta señal, si no lo ha sobrescrito, nunca escribe en la terminal, ni suspende o termina el programa llamador, entonces puede establecer de forma segura el argumento flags a 0

.

Si su manejador de señales siempre escribe en la terminal, lee de ella, o suspende o termina el programa, debe especificar el argumento flags como GL_SUSPEND_INPUT, de modo

que: 
1. El cursor no quede en medio de la línea de entrada.
2. Para que el usuario pueda escribir entrada y esta sea reflejada.
3. Para que no necesite terminar cada línea de salida con
   \r\n, en lugar de solo \n
.

La combinación GL_RESTORE_ENV es la misma que GL_SUSPEND_INPUT, excepto que no mueve el cursor, y si su manejador de señales no lee ni escribe nada en la terminal, el usuario no verá ninguna indicación visible de que se capturó una señal. Esto puede ser útil si tiene un manejador de señales que solo escribe ocasionalmente en la terminal, donde usar GL_SUSPEND_LINE haría que la línea de entrada se duplicara innecesariamente cuando no se hubiera escrito nada en la terminal. Dicho manejador de señales, cuando escriba en la terminal, debe asegurarse de iniciar una nueva línea al comienzo de su primera escritura, escribiendo un salto de línea antes de regresar. Si la señal llega mientras el usuario está ingresando una línea que solo ocupa una línea de terminal, o si el cursor está en la última línea de terminal de una línea de entrada más larga, esto tendrá el mismo efecto que GL_SUSPEND_INPUT. De lo contrario, comenzará a escribir en una línea que ya contiene parte de la línea de entrada mostrada. Esto no causa ningún daño, pero se ve un poco feo, que es por qué la combinación GL_SUSPEND_INPUT es mejor si sabe que siempre va a escribir en la

terminal.

valores:

                 si el usuario hubiera presionado la tecla
                 de retorno.

                 GLR_SIGNAL. Tenga en cuenta que si la

                 tenga un valor significativo cuando

                 la función de retorno de llamada debe asignar
                 errno apropiadamente.

comandos.

que se ingresó usando la tecla de retorno, y una

MANEJO DE SEÑALES

FIABLE

El manejo de señales es sorprendentemente difícil de hacer de forma fiable sin condiciones de carrera. En gl_get_line() se ha tomado mucho cuidado para permitir que las aplicaciones realicen un manejo de señales fiable alrededor de gl_get_line(). Esta sección explica cómo hacer uso de

esto.

Como ejemplo de los problemas que pueden surgir si la aplicación no está escrita correctamente, imagine que su aplicación tiene un manejador de señales SIGINT que establece una bandera global. Ahora suponga que la aplicación prueba esta bandera justo antes de invocar gl_get_line(). Si una señal SIGINT resulta recibida en el pequeño intervalo de tiempo entre la instrucción que prueba el valor de esta bandera, y la instrucción que llama a gl_get_line(), entonces gl_get_line() no verá la señal, y no será interrumpida. Como resultado, la aplicación no podrá responder a la señal hasta que el usuario termine de ingresar la línea de entrada y gl_get_line() regrese. Dependiendo de la aplicación, esto podría o no ser un desastre, pero al menos confundiría al

usuario.

La forma de evitar tales problemas es hacer lo

siguiente.

1. Si es necesario, use la función gl_trap_signal() para
configurar gl_get_line() para que aborte cuando se capturen
señales

importantes.

2. Configure gl_get_line() de modo que si alguna de las
señales que captura está bloqueada cuando se
llama a gl_get_line(), se desbloqueen
automáticamente durante los momentos en que gl_get_line() está
esperando E/S. Esto se puede hacer ya sea
por señal, llamando a la
función gl_trap_signal(), y especificando el
atributo GLS_UNBLOCK de la señal, o globalmente
llamando a la función gl_catch_blocked()

. 
     void gl_catch_blocked(GetLine *gl)
;


Esta función simplemente agrega el atributo GLS_UNBLOCK
a todas las señales que actualmente está configurada para
capturar

.

3. Justo antes de llamar a gl_get_line(), bloquee la entrega
de todas las señales que gl_get_line() está
configurada para capturar. Esto se puede hacer usando la función POSIX
sigprocmask() en conjunto con la
función gl_list_signals()

. 
      int gl_list_signals(GetLine *gl, sigset_t *set)
;


Esta función devuelve el conjunto de señales que actualmente está
configurada para capturar en el argumento set,
que está en la forma requerida por sigprocma

sk().

4. En el ejemplo, ahora se probaría la bandera global que
establece el manejador de señales, sabiendo que ahora no hay
peligro de que esta bandera se establezca de nuevo hasta que
gl_get_line() desbloquee sus señales mientras realiza
E/S

.

5. Eventualmente gl_get_line() regresa, ya sea porque
se capturó una señal, ocurrió un error, o el usuario
terminó de ingresar su línea de

entrada.

6. Ahora se verificaría la bandera de señal global de nuevo, y si
está establecida, se respondería a ella, y se pondría la bandera a

cero.

7. Use sigprocmask() para desbloquear las señales que fueron
bloqueadas en el paso

3.

La misma técnica se puede usar alrededor de ciertas funciones POSIX conscientes de señales, como sigsetjmp() y sigsuspend(), y en particular, la primera de estas dos funciones se puede usar en conjunto con siglongjmp() para implementar un manejo de señales libre de condiciones de carrera alrededor de otras llamadas al sistema de larga duración. La forma de hacer esto se explica a continuación, mostrando cómo gl_get_line() logra capturar señales de forma fiable alrededor de llamadas a funciones como read() y select() sin condiciones de

carrera.

Lo primero que gl_get_line() hace, siempre que es llamada, es usar la función POSIX sigprocmask() para bloquear la entrega de todas las señales que actualmente está configurada para capturar. Esto es redundante si la aplicación ya las ha bloqueado, pero no hace ningún daño. Deshace este paso justo antes de

regresar.

Siempre que gl_get_line() necesite llamar a read() o select() para esperar entrada del usuario, primero llama a la función POSIX sigsetjmp(), asegurándose de especificar un valor distinto de cero para su argumento savesigs. La razón de este último argumento se aclarará en

breve.

Si sigsetjmp() devuelve cero, gl_get_line() luego hace lo

siguiente. 
a. Usa la función POSIX sigaction() para registrar
   un manejador de señales temporal para todas las señales que
   está configurada para capturar. Este manejador de señales hace dos
   cosas.
   1. Registra el número de la señal que fue recibida
      en una variable de ámbito de archivo.
   2. Luego llama a la función POSIX siglongjmp()
      usando el búfer que se pasó a
      sigsetjmp() como su primer argumento, y
      un valor distinto de cero para su segundo argumento.
   Cuando este manejador de señales está registrado, el miembro sa_mask
   del argumento struct sigaction act de la
   llamada a sigaction() está configurado para contener todas
   las señales que gl_get_line() está capturando. Esto
   asegura que solo una señal sea capturada a la vez por
   nuestro manejador de señales, lo que a su vez asegura que múltiples
   instancias de nuestro manejador de señales no se interfieran entre sí.
b. Ahora que el manejador de señales ha sido configurado,
   gl_get_line() desbloquea todas las señales que
   está configurada para capturar.
c. Luego llama a las llamadas al sistema read() o select() para esperar entrada del teclado.
d. Si esta llamada al sistema regresa (es decir, no se recibe ninguna señal),
   gl_get_line() bloquea nuevamente la entrega de las señales de
   interés.
e. Luego restablece los manejadores de señales que fueron
   desplazados por el que se acaba de
instalar.

Alternativamente, si sigsetjmp() devuelve un valor distinto de cero, esto significa que una de las señales atrapadas fue capturada mientras se ejecutaban los pasos anteriores. Cuando esto sucede, gl_get_line() hace lo

siguiente.

Primero, tenga en cuenta que cuando una llamada a siglongjmp() hace que sigsetjmp() retorne, siempre que el argumento savesigs de sigsetjmp() fuera distinto de cero, como se especificó anteriormente, la máscara de proceso de señales se restaura a cómo estaba cuando sigsetjmp() fue llamada. Esta es la diferencia importante entre sigsetjmp() y el problemático setjmp() más antiguo, y es el ingrediente esencial que hace posible evitar condiciones de carrera en el manejo de señales. Debido a esto, se garantiza que todas las señales que bloqueamos antes de llamar a sigsetjmp() estén bloqueadas de nuevo tan pronto como se capture cualquier señal. Las siguientes instrucciones, que se ejecutan a continuación, por lo tanto, se garantiza que se ejecuten sin que se capturen más

señales.

1. Si así lo indica la configuración de gl_get_line()
de la señal que fue capturada,
gl_get_line() restaura los atributos de la terminal a
el estado que tenían cuando gl_get_line() fue
llamada. Esto es particularmente importante para las señales que
suspenden o terminan el proceso, ya que de lo contrario la
terminal quedaría en un estado

inutilizable.

2. Luego reinstala los manejadores de señales de la

aplicación.

3. Luego usa la función de la biblioteca estándar de C raise()
para reenviar a la aplicación la señal que
fue

capturada.

3. A continuación, desbloquea la entrega de la señal que acabamos de
enviar. Esto resulta en que la señal que acababa de ser enviada
a través de raise(), sea capturada por el manejador de señales

EL TAMAÑO DE LA

TERMINAL

En la mayoría de los sistemas, la combinación de la ioctl TIOCGWINSZ y la señal SIGWINCH se utiliza para mantener una idea precisa del tamaño de la terminal. El tamaño de la terminal se consulta nuevamente cada vez que se llama a gl_get_line() y siempre que se recibe una señal SIGWINCH

.

En los pocos sistemas donde este mecanismo no está disponible, al inicio new_GetLine() primero busca las variables de entorno LINES y COLUMNS. Si no se encuentran, o contienen valores inutilizables, entonces si está disponible una base de datos de información de terminal como terminfo o termcap, se busca el tamaño por defecto de la terminal en esta base de datos. Si esto también falla para proporcionar el tamaño de la terminal, se usa un tamaño por defecto de 80 columnas por 24

líneas.

Incluso en sistemas que sí admiten ioctl(TIOCGWINSZ), si la terminal está en el otro extremo de una línea serie, el controlador de la terminal generalmente no tiene forma de detectar cuándo ocurre un redimensionamiento ni de consultar cuál es el tamaño actual. En tales casos, no se envía ningún SIGWINCH al proceso, y las dimensiones devueltas por ioctl(TIOCGWINSZ) no son correctas. La única manera de manejar tales instancias es proporcionar una forma para que el usuario introduzca un comando que le diga al sistema remoto cuál es el nuevo tamaño. Este comando entonces llamaría a la función gl_set_term_size() para informar a gl_get_line() sobre el cambio de

tamaño. 
  int gl_set_term_size(GetLine *gl, int ncolumn, int nline)
;

Los argumentos ncolumn y nline se utilizan para especificar las nuevas dimensiones de la terminal, y no deben ser menores que 1. En sistemas que sí admiten ioctl(TIOCGWINSZ), esta función primero llama a ioctl(TIOCSWINSZ) para informar al controlador de la terminal sobre el cambio en el tamaño. En el modo de E/S de servidor no bloqueante, si actualmente se está introduciendo una línea, la línea de entrada se redibuja para acomodar el tamaño cambiado. Finalmente, los nuevos valores se registran en gl para uso futuro por gl_get_li

ne().

La función gl_terminal_size() le permite consultar el tamaño actual de la terminal, e instalar un tamaño de respaldo alternativo para los casos en que el tamaño no esté disponible. Tenga en cuenta que el tamaño de la terminal no estará disponible si se lee de una tubería o de un archivo, por lo que los valores por defecto pueden ser importantes incluso en sistemas que sí admiten formas de averiguar el tamaño de la

terminal. 
  typedef struct {
    int nline;        /* La terminal tiene nline líneas */
    int ncolumn;      /* La terminal tiene ncolumn columnas */

  GlTerminalSize gl_terminal_size(GetLine *gl,
                                  int def_ncolumn,
                                  int def_nline)
;

Esta función primero actualiza las dimensiones de respaldo de la terminal de gl_get_line(), luego registra sus hallazgos en el valor de

retorno.

Los argumentos def_ncolumn y def_nline especifican el número por defecto de columnas y líneas de la terminal a usar si el tamaño de la terminal no puede ser determinado a través de ioctl(TIOCGWINSZ) o

variables d

OCULTANDO LO QUE

ESCRIBES

Al introducir información sensible, como contraseñas, es mejor no tener el texto que está introduciendo reflejado en la terminal. Además, dicho texto no debería ser registrado en la lista de historial, ya que alguien que encuentre su terminal desatendida podría entonces recuperarlo, o alguien que esté husmeando en sus directorios podría verlo en su archivo de historial. Teniendo esto en cuenta, la función gl_echo_mode() le permite activar y desactivar la visualización y el archivo de cualquier texto que se introduzca posteriormente en las llamadas a gl_get_li

ne(). 
  int gl_echo_mode(GetLine *gl, int enable)
;

El argumento enable especifica si el texto introducido debe ser visible o no. Si es 0, entonces las líneas introducidas posteriormente no serán visibles en la terminal, y no serán registradas en la lista de historial. Si es 1, entonces las líneas de entrada posteriores se mostrarán a medida que se introducen, y siempre que el historial no haya sido desactivado a través de una llamada a gl_toggle_history(), también serán archivadas en la lista de historial. Finalmente, si el argumento enable es -1, entonces el modo de eco se deja sin cambios, lo que le permite consultar de forma no destructiva la configuración actual a través del valor de retorno. En todos los casos, el valor de retorno de la función es 0 si el eco estaba desactivado antes de que se llamara a la función, y 1 si estaba

activado.

Cuando el eco está desactivado, tenga en cuenta que aunque la fi

nalización con tabulador completará su prefijo de forma invisible lo
más lejos posible, las finalizaciones ambiguas no se mostrarán.

CONSULTAS DE UN SOLO

CARÁCTER

Usar gl_get_line() para consultar al usuario para una respuesta de un solo carácter, es inconveniente para el usuario, ya que debe presionar la tecla intro o retorno antes de que el carácter que escribió sea devuelto al programa. Por lo tanto, la función gl_query_char() ha sido proporcionada para consultas de un solo carácter como

esta. 
  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar)
;

Esta función muestra el prompt especificado al comienzo de una nueva línea, y espera a que el usuario escriba un carácter. Cuando el usuario escribe un carácter, gl_query_char() lo muestra a la derecha del prompt, inicia una nueva línea, y luego devuelve el carácter al programa que lo llamó. El valor de retorno de la función es el carácter que fue escrito. Si la lectura tuvo que ser abortada por alguna razón, se devuelve EOF en su lugar. En el último caso, la aplicación puede llamar a la previamente documentada gl_return_status(), para averiguar qué salió mal. Esto podría, por ejemplo, haber sido la recepción de una señal, o el temporizador opcional de inactividad

activándose.

Si el usuario simplemente presiona intro, el valor del argumento defchar se sustituye. Esto significa que cuando el usuario presiona ya sea nueva línea o retorno, el carácter especificado en defchar, se muestra después del prompt, como si el usuario lo hubiera escrito, así como ser devuelto a la aplicación que lo llamó. Si tal reemplazo no es importante, simplemente pase '0 como el valor de defchar

.

Si el carácter introducido es un carácter no imprimible, se muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y los caracteres más allá de 127 se muestran en octal, precedidos por una barra

invertida.

Al igual que con gl_get_line(), el eco del carácter introducido puede ser desactivado usando la función gl_echo_mode()

.

Si el proceso que llama es suspendido mientras espera a que el usuario escriba su respuesta, el cursor se mueve a la línea siguiente a la línea del prompt, luego, cuando el proceso se reanuda, el prompt se vuelve a mostrar, y gl_query_char() reanuda la espera de que el usuario escriba un

carácter.

Tenga en cuenta que en el modo de servidor no bloqueante, (vea gl_io_mode(3)), si una línea de entrada incompleta está en proceso de ser leída cuando se llama a gl_query_char(), la línea de entrada parcial se descarta, y se borra de la terminal, antes de que se muestre el nuevo prompt. La siguiente llamada a gl_get_line() comenzará por lo

tanto a editar
una nueva línea.

LEYENDO CARACTERES

CRUDOS

Mientras que la función gl_query_char() solicita visiblemente al usuario un carácter, y muestra lo que escribió, la función gl_read_char() lee un carácter de la señal del usuario, sin escribir nada en la terminal, o perturbar alguna línea de entrada incompletamente introducida. Esto significa que puede ser llamada no solo entre las llamadas a gl_get_line(), sino también desde funciones de retorno que la aplicación ha registrado para ser llamadas por gl_get_li

ne(). 
  int gl_read_char(GetLine *gl)
;

En caso de éxito, el valor de retorno de gl_read_char() es el carácter que fue leído. En caso de fallo, se devuelve EOF, y la función gl_return_status() puede ser llamada para averiguar qué salió mal. Las posibilidades incluyen el temporizador opcional de inactividad activándose, la recepción de una señal que está configurada para abortar gl_get_line(), o el bloqueo de la E/S de la terminal, cuando se está en el modo de E/S de servidor no

bloqueante.

Tenga en cuenta que ciertas teclas del teclado, como las teclas de función, y las teclas de cursor, usualmente generan al menos 3 caracteres cada una, por lo que una sola llamada a gl_read_char()</b> no será suficiente

para identificar esas
pulsaciones de teclas.

MOSTRANDO TEXTO

DINÁMICAMENTE

Entre las llamadas a gl_get_line(), la función gl_display_text() proporciona una forma conveniente de mostrar párrafos de texto, justificados a la izquierda y divididos en una o más líneas de la terminal de acuerdo con las restricciones del ancho actual de la terminal. Se pueden encontrar ejemplos del uso de esta función en los programas de demostración, donde se utiliza para mostrar introducciones. En esos ejemplos también se ilustra el uso avanzado de prefijos, sufijos y líneas rellenas opcionales para dibujar un cuadro alrededor del

texto. 
  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string)
;

Si gl no está conectado actualmente a una terminal, por ejemplo si la salida de un programa que usa gl_get_line() se está canalizando a otro programa o se está redirigiendo a un archivo, entonces se utiliza el valor del parámetro def_width como el ancho de la

terminal.

El argumento indentation especifica el número de caracteres a usar para sangrar cada línea de la salida. El argumento fill_char especifica el carácter que se usará para realizar esta

sangría.

El argumento prefix puede ser NULL, o ser una cadena de texto para colocar al comienzo de cada línea nueva (después de cualquier sangría). De manera similar, el argumento suffix puede ser NULL, o ser una cadena de texto para colocar al final de cada línea. El sufijo se coloca alineado contra el borde derecho de la terminal, y cualquier espacio entre su primer carácter y la última palabra en esa línea se rellena con el carácter especificado a través del argumento fill_char. Normalmente, el carácter de relleno es un

espacio.

El argumento start le indica a gl_display_text() cuántos caracteres ya se han escrito en la línea de la terminal actual, y por lo tanto le indica el índice de columna inicial del cursor. Dado que el valor de retorno de gl_display_text() es el índice de columna final del cursor, al pasar el valor de retorno de una llamada al argumento start de la siguiente llamada, se puede componer un párrafo que está dividido entre más de una cadena llamando a gl_display_text() para cada porción sucesiva del párrafo. Tenga en cuenta que son necesarios caracteres de salto de línea literales al final de cada párrafo para forzar el inicio de una nueva

línea.

INTERNACIONALES

Desde la versión 1.4.0 de libtecla, gl_get_line() ha sido compatible con 8 bits. Esto significa que todos los caracteres de 8 bits que son imprimibles en la configuración regional actual del usuario ahora se muestran de forma literal y se incluyen en la línea de entrada devuelta. Asumiendo que el programa que llama contiene correctamente una llamada como la

siguiente, 
  setlocale(LC_CTYPE, "")
;

entonces la configuración regional actual está determinada por la primera de las variables de entorno LC_CTYPE, LC_ALL y LANG que se encuentre que contiene un nombre de configuración regional válido. Si ninguna de estas variables está definida, o el programa omite llamar a setlocale, entonces se utiliza la configuración regional C predeterminada, que es ASCII de 7 bits de EE. UU. En la mayoría de las plataformas tipo unix, puede obtener una lista de configuraciones regionales válidas escribiendo el

comando: 
  locale
-a
