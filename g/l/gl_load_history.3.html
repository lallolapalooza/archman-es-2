función gl_get_line() es parte de la biblioteca tecla (véase la página man libtecla(3)). Si el usuario está escribiendo en un terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de unix. Además de la edición simple de línea de comandos, admite el recuerdo de líneas de comandos introducidas previamente, la completación con TAB de nombres de archivos y la expansión en línea de comodines de nombres de archivos. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario, puede encontrarse en la página man tecla(7). FUENTES DE CONFIGURACIÓN

ALTERNATIVAS

Como se mencionó anteriormente, de forma predeterminada los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. En algunas aplicaciones, sin embargo, este único medio de configuración es un problema. Esto es particularmente cierto en el software embebido, donde no hay un sistema de archivos del cual leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de asignaciones de teclas para emular una interfaz de teclado heredada. Para atender a tales casos, la siguiente función permite a la aplicación controlar de dónde se leen la información de

configuración. 
  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file)
;

Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc de un usuario, se lean de cualquiera o ninguno de: una cadena, un archivo de configuración específico de la aplicación, y/o un archivo de configuración específico del usuario. Si esta función se llama antes de la primera llamada a gl_get_line(), el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line() se deshabilita, por lo que toda la configuración debe lograrse usando las fuentes de configuración especificadas con esta

función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados unos de otros en la cadena por caracteres de salto de línea incrustados. Si app_file != NULL entonces se interpreta como el nombre de ruta completo de un archivo de configuración específico de la aplicación. Si user_file != NULL entonces se interpreta como el nombre de ruta completo de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente

llamada, 
  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc")
;

el argumento app_string hace que la aplicación que llama comience en el modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso de la campana de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración de todo el sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario desde un archivo .teclarc opcional en el directorio de inicio del usuario. Tenga en cuenta que los argumentos se listan en orden ascendente de prioridad, con el contenido de app_string siendo potencialmente anulado por comandos en app_file, y los comandos en app_file siendo potencialmente anulados por comandos en user_file

.

Puede llamar a esta función tantas veces como sea necesario, siendo los resultados acumulativos, pero tenga en cuenta que las copias de cualquier nombre de archivo especificado a través de app_file y user_file se registran internamente para su uso posterior por la función read-init-files de enlace de teclas, así que si tiene la intención de llamar a esta función varias veces, asegúrese de que la última llamada especifique los nombres de archivo que desea volver a leer cuando el usuario solicite que se releer los archivos de

configuración.

COMPLETADO DE PALABRAS

PERSONALIZADO

Si en su aplicación desea que el completado con TAB complete otras cosas además de o en lugar de nombres de archivo, puede organizarlo registrando una función de retorno de completado alternativa, mediante una llamada a la función gl_customize_co

mpletion(). 
  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn)
;

El argumento data proporciona una manera para que su aplicación pase información arbitraria y específica de la aplicación a la función de retorno. Esto se pasa a la función de retorno cada vez que se la llama. Podría, por ejemplo, apuntar a la tabla de símbolos de la que se deben buscar las posibles completaciones. El argumento match_fn especifica la función de retorno a llamar. El tipo de función CplMatchFn está definido en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y definir prototipos de funciones de retorno. La declaración y las responsabilidades de las funciones de retorno se describen en profundidad en la página del manual cpl_complete_word(3)

.

En resumen, la función de retorno es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario pulsó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar posibles completaciones de esta palabra y registrarlas una por una en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion(). Si la función de retorno desea proporcionar completado de nombres de archivo además de sus propias completaciones específicas, tiene la opción de llamar ella misma a la función de retorno de completado de nombres de archivo incorporada. Esto también está documentado en la página del manual cpl_complete_word(3)

.

Tenga en cuenta que si desea que gl_get_line() devuelva la línea de entrada actual cuando se haya realizado una completación exitosa, puede organizarlo cuando llame a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de nueva línea. Si hace esto, la línea de entrada se actualizará para mostrar la completación, junto con cualquier sufijo de continuación hasta el carácter de nueva línea, y luego gl_get_line() devolverá esta línea de

entrada.

Si, por alguna razón, su función de retorno necesita escribir algo en el terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto iniciará una nueva línea después de la línea de entrada que se está editando actualmente, restablecerá la E/S normal del terminal y le dirá a gl_get_line() que la línea de entrada necesitará

ser redibujada cuando la f
unción de retorno regrese.

AÑADIENDO ACCIONES DE

COMPLETADO

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de completado predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que diferentes tipos de completado de palabras se puedan enlazar a diferentes secuencias de teclas. Esto se logra usando la función gl_completion_action()

. 
  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq)
;

Los argumentos data y match_fn se describen en la página del manual cpl_complete_word, y especifican la función de retorno que debe invocarse para identificar posibles completaciones. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar cualquier completación ambigua posible, o si debe simplemente mostrar la lista de posibles completaciones sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre con el que los archivos de configuración y las futuras invocaciones de esta función deben referirse a la acción. Este debe ser el nombre de una acción de completado existente que se va a cambiar, o un nombre nuevo sin usar para una nueva acción. Finalmente, el argumento keyseq especifica la secuencia de teclas predeterminada para enlazar la acción. Si esto es NULL, no se enlazará ninguna nueva secuencia de teclas a la

acción.

Tenga cuidado de que, para que el usuario pueda cambiar la secuencia de teclas que está enlazada a las acciones que se instalan de esta manera, cuando llame a gl_completion_action() para instalar una acción determinada por primera vez, debe hacerlo entre la llamada a new_GetLine() y la primera llamada a gl_get_line(). De lo contrario, cuando se lea el archivo de configuración del usuario en la primera llamada a gl_get_line(), el nombre de su acción adicional no será conocido, y cualquier referencia a ella en el archivo de configuración generará un

error.

Como se discutió para gl_customize_completion(), si su función de retorno, por alguna razón, necesita escribir algo en el terminal, debe llamar a gl_normal_io() a

ntes de
hacerlo.

PERSONALIZADAS

Aunque las acciones de enlace de teclas incorporadas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, enlazadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza que correspondía a un número de pieza que precedía al cursor. Tal característica claramente está fuera del alcance de las funciones de acción incorporadas. Así que para tales casos especiales, se proporciona la función gl_register_action()

. 
  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq)
;

Esta función permite a la aplicación registrar una función externa, fn, que a partir de entonces será llamada cada vez que se introduzca la secuencia de teclas especificada, keyseq, por el usuario, o que el usuario introduzca cualquier otra secuencia de teclas que el usuario enlace posteriormente a la acción especificada, name, en su archivo de configuración. El argumento data puede ser un puntero a cualquier cosa que la aplicación desee que se pase a la función de acción, fn, cada vez que esa función sea

invocada.

La función de acción, fn, debe declararse usando la siguiente macro, que está definida en libtecl

a.h. 
  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char
*line)

Los argumentos gl y data son aquellos que se pasaron previamente a gl_register_action() cuando se registró la función de acción. El argumento count es un argumento numérico que el usuario tiene la opción de introducir usando la acción digit-argument, antes de invocar la acción. Si el usuario no introduce un número, entonces el argumento count se establece en 1. Nominalmente, este argumento se interpreta como un conteo de repetición, lo que significa que la acción debe repetirse esa cantidad de veces. Sin embargo, en la práctica, para algunas acciones un conteo de repetición tiene poco sentido. En tales casos, las acciones pueden simplemente ignorar el argumento count, o usar su valor para un propósito

diferente.

Una copia de la línea de entrada actual se pasa en el argumento de solo lectura line. La posición actual del cursor dentro de esta cadena está dada por el índice contenido en el argumento curpos. Tenga en cuenta que no se permite la manipulación directa de la línea de entrada y la posición del cursor. Esto se debe a que las reglas dictadas por varios modos, como el modo vi frente al modo emacs, el modo sin eco, y el modo de inserción frente al modo de sobrescritura, etc, hacen que sea demasiado compleo para un desarrollador de aplicaciones escribir una acción de edición conforme, así como limitan cambios futuros en los internos de gl_get_line(). Una solución potencial a este dilema sería permitir que la función de acción edite la línea usando las acciones de edición existentes. Actualmente se está

considerando.

Si la función de acción desea escribir texto en el terminal, sin que esto se mezcle con el texto mostrado de la línea de entrada, o leer del terminal sin tener que manejar la E/S cruda del terminal, entonces antes de realizar cualquiera de estas operaciones, debe suspender temporalmente la edición de línea llamando a la función gl_normal_io(). Esta función vacía cualquier salida pendiente al terminal, mueve el cursor al inicio de la línea que sigue a la última línea del terminal de la línea de entrada, y luego restaura el terminal a un estado que es adecuado para su uso con las instalaciones stdio de C. Lo último incluye cosas como restaurar el mapeo normal de \n a \r\n, y, cuando está en modo servidor, restaurar la forma normal de bloqueo de la E/S del terminal. Después de haber llamado a esta función, la acción puede leer de y escribir al terminal sin temor de crear un desastre. No es necesario que la función de acción restaure el entorno de edición original antes de regresar. Esto lo hace automáticamente gl_get_line() después de que la función de acción regrese. Lo siguiente es un ejemplo sencillo de una función de acción que escribe la frase "Hello world" en una nueva línea del terminal después de la línea que se está editando. Cuando esta función regresa, la línea de entrada se redibuja en la línea que sigue a la línea "Hello world", y la edición de línea se

reanuda. 
  static GL_ACTION_FN(say_hello_fn)
  {
    if(gl_normal_io(gl))   /* Suspender temporalmente la edición */
      return GLA_ABORT;
    printf("Hello world\n");
    return GLA_CONTINUE;
}

Las funciones de acción deben devolver uno de los siguientes valores, para indicar a gl_get_line() cómo

proceder. 
  GLA_ABORT     -   Hace que gl_get_line() devuelva NULL.
  GLA_RETURN    -   Hace que gl_get_line() devuelva la
                    línea de entrada completada.
  GLA_CONTINUE  -   Reanuda la edición de la línea de
comandos.

Tenga en cuenta que el argumento name de gl_register_action() especifica el nombre con el que un usuario puede referirse a la acción en su archivo de configuración. Esto les permite reasociar la acción a una secuencia de teclas alternativa. Para que esto funcione, es necesario llamar a gl_register_action() entre la llamada a new_GetLine() y la primera llamada a gl_get_

lin

ARCHIVADO MANUAL DEL

HISTORIAL

Por defecto, cada vez que el usuario introduce una línea, esta se añade automáticamente a la lista de historial, justo antes de gl_get_line() devuelve la línea al llamante. Esto es conveniente para la mayoría de aplicaciones, pero también hay aplicaciones que necesitan un control más detallado sobre lo que se añade a la lista de historial. En tales casos, la adición automática de las líneas introducidas a la lista de historial se puede desactivar llamando a la función gl_automatic_

history(). 
  int gl_automatic_history(GetLine *gl, int enable)
;

Si se llama a esta función con su argumento enable establecido en 0, gl_get_line() no archivará automáticamente las líneas introducidas posteriormente. El archivado automático se puede reactivar más tarde, llamando a esta función de nuevo, con su argumento enable establecido en 1. Mientras el archivado automático del historial esté desactivado, la aplicación que llama puede usar la función gl_append_history() para añadir líneas a la lista de historial según sea

necesario. 
  int gl_append_history(GetLine *gl, const char *line)
;

El argumento line especifica la línea que se añadirá a la lista de historial. Esta debe ser una cadena normal terminada en '\0'. Si esta cadena contiene algún carácter de salto de línea, la línea que se archiva en la lista de historial terminará en el primero de ellos. De lo contrario, terminará en el terminador '\0'. Si la línea es más larga que la longitud máxima de línea de entrada, que se especificó cuando se llamó a new_GetLine(), cuando se recuerde la línea, se truncará a la longitud real de la línea de gl_get_li

ne().

Si tiene éxito, gl_append_history() devuelve 0. De lo contrario, devuelve un valor distinto de cero y establece errno en uno de los siguientes

valores. 
   EINVAL  -  Uno de los argumentos pasados a
              gl_append_history() era NULL.
   ENOMEM  -  La línea especificada era más larga que el tamaño
              asignado del búfer de historial (tal como se especificó cuando se
              llamó a new_GetLine()), por lo que no se pudo
archivar.

Se puede obtener opcionalmente una descripción textual del error llamando a gl_error_message(). Tenga en cuenta que después de un error así, la lista de historial permanece en un estado válido para recibir nuevas líneas de historial, por lo que hay poco daño en simplemente ignorar el estado de retorno de gl_append_

histo

CAMBIO DE

TERMINALES

La función constructora new_GetLine() asume que la entrada se leerá desde stdin, y que la salida se escribirá en stdout. La siguiente función le permite cambiar a diferentes flujos de entrada y

salida. 
  int gl_change_terminal(GetLine *gl, FILE *input_fp,
                         FILE *output_fp, const char *term)
;

El argumento gl es el objeto que fue devuelto por new_GetLine(). El argumento input_fp especifica el flujo desde el que leer, y output_fp especifica el flujo en el que escribir. Solo si ambos se refieren a un terminal, se habilitará la entrada interactiva del terminal. De lo contrario, gl_get_line() simplemente llamará a fgets() para leer la entrada del comando. Si ambos flujos se refieren a un terminal, entonces deben referirse al mismo terminal, y el tipo de este terminal debe especificarse a través del argumento term. El valor del argumento term se busca en la base de datos de información del terminal (terminfo o termcap), con el fin de determinar qué secuencias de control especiales se necesitan para controlar varios aspectos del terminal. new_GetLine(), por ejemplo, pasa el valor de retorno de getenv("TERM") en este argumento. Nótese que si uno o ambos de input_fp y output_fp no se refieren a un terminal, es legal pasar NULL en lugar de un tipo de

terminal.

Nótese que si desea pasar descriptores de archivo a gl_change_terminal(), puede hacerlo creando envoltorios de flujo stdio usando la función POSIX fdop

en(

MANEJO DE EVENTOS

EXTERNOS

Por defecto, gl_get_line() no regresa hasta que el usuario ha introducido una línea de entrada completa, o hasta que ocurre un error. En programas que necesitan vigilar la E/S de otras fuentes que no sean el terminal, hay dos

opciones. 
  1. Use las funciones descritas en la
     página del manual gl_io_mode(3) para cambiar
     gl_get_line() al modo de servidor no bloqueante. En este modo,
     gl_get_line() se convierte en una función de edición de líneas
     incremental no bloqueante que puede ser llamada de forma segura desde
     un bucle de eventos externo. Aunque este es un método muy
     versátil, implica asumir algunas
     responsabilidades que normalmente se realizan entre bastidores por gl_get_line().
  2. Mientras gl_get_line() está esperando la entrada del
     teclado del usuario, puede pedirle que también vigile la
     actividad en descriptores de archivo arbitrarios, como
     sockets de red, tuberías, etc., y que llame a funciones
     de su elección cuando se detecte actividad. Esto funciona en
     cualquier sistema que tenga la llamada al sistema select(),
     que es la mayoría, si no todos, de los sabores de
unix.

Registrar un descriptor de archivo para ser vigilado por gl_get_line() implica llamar a la función gl_watch_fd()

. 
  int gl_watch_fd(GetLine *gl, int fd, GlFdEvent event,
                  GlFdEventFn *callback, void *data)
;

Si esto devuelve un valor distinto de cero, significa que o sus argumentos son inválidos, o que esta funcionalidad no está soportada en el sistema

anfitrión.

El argumento fd es el descriptor de archivo a vigilar. El argumento event especifica qué tipo de actividad es de interés, elegido de los siguientes valores

enumerados: 
  GLFD_READ   -  Vigilar la llegada de datos para leer.
  GLFD_WRITE  -  Vigilar la capacidad de escribir en el descriptor
                 de archivo sin bloquear.
  GLFD_URGENT -  Vigilar la llegada de datos urgentes
                 fuera de banda en el descriptor de
archivo.

El argumento callback es la función a llamar cuando se detecta la actividad seleccionada. Debe definirse con el siguiente macro, que está definido en libtecla.

h. 
  #define GL_FD_EVENT_FN(fn) GlFdStatus (fn)(GetLine *gl, \
                                      void *data, int fd, \
                                      GlFdEvent
event)

El argumento data de la función gl_watch_fd() se pasa a la función de retorno de llamada para su propio uso, y puede apuntar a lo que desee, incluyendo NULL. El descriptor de archivo y el argumento event también se pasan a la función de retorno de llamada, y esto potencialmente permite que la misma función de retorno de llamada se registre para más de un tipo de evento y/o más de un descriptor de archivo. El valor de retorno de la función de retorno de llamada debe ser uno de los siguientes

valores. 
  GLFD_ABORT    -  Decirle a gl_get_line() que aborte. Cuando esto
                   ocurre, gl_get_line() regresa
                   NULL, y una llamada posterior a
                   gl_return_status() devolverá
                   GLR_FDABORT. Nótese que si la
                   aplicación necesita que errno siempre
                   tenga un valor significativo cuando
                   gl_get_line() regresa NULL,
                   la función de retorno de llamada debe establecer
                   errno apropiadamente.
  GLFD_REFRESH  -  Redibujar la línea de entrada y luego continuar
                   esperando la entrada. Devuelva esto si
                   su retorno de llamada escribió en el terminal.
  GLFD_CONTINUE -  Continuar esperando la entrada, sin
                   redibujar la
línea.

Nótese que antes de llamar al retorno de llamada, gl_get_line() bloquea la mayoría de las señales, y deja instalados sus propios manejadores de señal, así que si necesita capturar una señal en particular, necesitará tanto instalar temporalmente su propio manejador de señal, como desbloquear la señal. Asegúrese de volver a bloquear la señal (si estaba originalmente bloqueada) y reinstalar el manejador de señal original, si lo hay, antes de

regresar.

Si la función de retorno de llamada necesita leer o escribir en el terminal, idealmente debería primero llamar a gl_normal_io(gl) para suspender temporalmente la edición de líneas. Esto restaurará el terminal al modo canónico, de E/S bloqueante, y moverá el cursor al inicio de una nueva línea del terminal. Más tarde, cuando el retorno de llamada regresa, gl_get_line() notará que gl_normal_io() fue llamada, volverá a mostrar la línea de entrada y reanudará la edición. Nótese que en este caso los valores de retorno, GLFD_REFRESH y GLFD_CONTINUE son

equivalentes.

Para soportar los casos en los que la función de retorno de llamada llama a una función de terceros que ocasional e imprevisiblemente escribe en el terminal, la conversión automática de "0 a "0 se vuelve a habilitar antes de que se llame a la función de retorno de llamada. Si el retorno de llamada sabe que la función de terceros escribió en el terminal, entonces debe devolver el valor de retorno GLFD_REFRESH, para decirle a gl_get_line() que vuelva a mostrar la línea de

entrada.

gnora en

MANEJO CONFIABLE DE SEÑALES

El manejo de señales es sorprendentemente difícil de hacer de forma confiable sin condiciones de carrera. En gl_get_line() se ha puesto mucho cuidado para permitir que las aplicaciones realicen un manejo confiable de señales alrededor de gl_get_line(). Esta sección explica cómo aprovechar esto.

Como ejemplo de los problemas que pueden surgir si la aplicación no está escrita correctamente, imagine que una aplicación tiene un manejador de señales SIGINT que establece una bandera global. Ahora suponga que la aplicación prueba esta bandera justo antes de invocar gl_get_line(). Si una señal SIGINT se recibe en la pequeña ventana de tiempo entre la instrucción que prueba el valor de esta bandera y la instrucción que llama a gl_get_line(), entonces gl_get_line() no verá la señal y no será interrumpido. Como resultado, la aplicación no podrá responder a la señal hasta que el usuario termine de ingresar la línea de entrada y gl_get_line() retorne. Dependiendo de la aplicación, esto puede ser o no un desastre, pero como mínimo desconcertará al usuario.

La forma de evitar tales problemas es hacer lo siguiente.

1. Si es necesario, utilice la función gl_trap_signal() para configurar gl_get_line() para que aborte cuando se capturen señales importantes.

2. Configure gl_get_line() de tal manera que si alguna de las señales que captura está bloqueada cuando se llama a gl_get_line(), se desbloqueará automáticamente durante los momentos en que gl_get_line() esté esperando E/S. Esto se puede hacer ya sea por señal, llamando a la función gl_trap_signal() y especificando el atributo GLS_UNBLOCK de la señal, o globalmente llamando a la función gl_catch_blocked().

     void gl_catch_blocked(GetLine *gl);

Esta función simplemente agrega el atributo GLS_UNBLOCK a todas las señales que actualmente está configurada para interceptar.

3. Justo antes de llamar a gl_get_line(), bloquee la entrega de todas las señales que gl_get_line() está configurada para interceptar. Esto se puede hacer usando la función POSIX sigprocmask() en conjunto con la función gl_list_signals().

      int gl_list_signals(GetLine *gl, sigset_t *set);

Esta función retorna el conjunto de señales que actualmente está configurada para capturar en el argumento set, que tiene el formato requerido por sigprocmask().

4. En el ejemplo, ahora se probaría la bandera global que el manejador de señales establece, sabiendo que ya no hay peligro de que esta bandera se establezca nuevamente hasta que gl_get_line() desbloquee sus señales mientras realiza E/S.

5. Eventualmente gl_get_line() retorna, ya sea porque se capturó una señal, ocurrió un error, o el usuario terminó de ingresar su línea de entrada.

6. Ahora se revisaría nuevamente la bandera global de señales, y si está establecida, se respondería a ella, y se pondría a cero la bandera.

7. Se usaría sigprocmask() para desbloquear las señales que se bloquearon en el paso 3.

La misma técnica se puede utilizar alrededor de ciertas funciones conscientes de señales POSIX, como sigsetjmp() y sigsuspend(), y en particular, la primera de estas dos funciones se puede usar en conjunto con siglongjmp() para implementar un manejo de señales libre de condiciones de carrera alrededor de otras llamadas de sistema de larga duración. La forma de hacer esto se explica a continuación, mostrando cómo gl_get_line() logra interceptar señales de manera confiable alrededor de llamadas a funciones como read() y select() sin condiciones de carrera.

Lo primero que hace gl_get_line(), cada vez que se llama, es usar la función POSIX sigprocmask() para bloquear la entrega de todas las señales que actualmente está configurada para capturar. Esto es redundante si la aplicación ya las ha bloqueado, pero no causa ningún daño. Deshace este paso justo antes de retornar.

Cada vez que gl_get_line() necesita llamar a read() o select() para esperar entrada del usuario, primero llama a la función POSIX sigsetjmp(), asegurándose de especificar un valor distinto de cero para su argumento savesigs. La razón del último argumento se aclarará en breve.

Si sigsetjmp() retorna cero, gl_get_line() hace lo siguiente.

a. Usa la función POSIX sigaction() para registrar un
   manejador de señales temporal para todas las señales que
   está configurada para capturar. Este manejador de señales
   hace dos cosas.
   1. Registra el número de la señal recibida en una variable
      de ámbito de archivo.
   2. Luego llama a la función POSIX siglongjmp()
      usando el búfer que se pasó a sigsetjmp() como
      su primer argumento, y un valor distinto de cero como
      su segundo argumento.
   Cuando este manejador de señales se registra, el miembro
   sa_mask del argumento struct sigaction act de la
   llamada a sigaction() se configura para contener todas
   las señales que gl_get_line() está capturando. Esto
   asegura que solo una señal será capturada a la vez por
   nuestro manejador de señales, lo que a su vez asegura que
   múltiples instancias de nuestro manejador de señales no se
   pisen los talones.
b. Ahora que el manejador de señales ha sido configurado,
   gl_get_line() desbloquea todas las señales que está
   configurada para capturar.
c. Luego llama a las llamadas al sistema read() o
   select() para esperar entrada del teclado.
d. Si esta llamada al sistema retorna (es decir, no se recibe
   ninguna señal), gl_get_line() vuelve a bloquear la
   entrega de las señales de interés.
e. Luego reinstaura los manejadores de señales que fueron
   desplazados por el que se acaba de instalar.

En la mayoría de los sistemas, la combinación del ioctl TIOCGWINSZ y la señal SIGWINCH se utiliza para mantener una idea precisa del tamaño del terminal. El tamaño del terminal se consulta nuevamente cada vez que se llama a gl_get_line() y siempre que se recibe una señal SIGWINCH

.

En los pocos sistemas donde este mecanismo no está disponible, al inicio new_GetLine() primero busca las variables de entorno LINES y COLUMNS. Si no se encuentran, o contienen valores inutilizables, entonces si está disponible una base de datos de información del terminal como terminfo o termcap, se busca el tamaño predeterminado del terminal en esta base de datos. Si esto también falla para proporcionar el tamaño del terminal, se utiliza un tamaño predeterminado de 80 columnas por 24

líneas.

Incluso en sistemas que sí admiten ioctl(TIOCGWINSZ), si el terminal está en el otro extremo de una línea serie, el controlador del terminal generalmente no tiene forma de detectar cuándo ocurre un redimensionamiento ni de consultar cuál es el tamaño actual. En tales casos, no se envía SIGWINCH al proceso, y las dimensiones devueltas por ioctl(TIOCGWINSZ) no son correctas. La única forma de manejar tales instancias es proporcionar una manera para que el usuario ingrese un comando que le indique al sistema remoto cuál es el nuevo tamaño. Este comando entonces llamaría a la función gl_set_term_size() para informar a gl_get_line() sobre el cambio de

tamaño. 
  int gl_set_term_size(GetLine *gl, int ncolumn, int nline)
;

Los argumentos ncolumn y nline se utilizan para especificar las nuevas dimensiones del terminal, y no deben ser menores que 1. En sistemas que sí admiten ioctl(TIOCGWINSZ), esta función primero llama a ioctl(TIOCSWINSZ) para informar al controlador del terminal sobre el cambio de tamaño. En el modo de E/S de servidor no bloqueante, si actualmente se está ingresando una línea, la línea de entrada se vuelve a dibujar para acomodar el cambio de tamaño. Finalmente, los nuevos valores se registran en gl para uso futuro por gl_get_li

ne().

La función gl_terminal_size() le permite consultar el tamaño actual del terminal, e instalar un tamaño de respaldo alternativo para los casos en que el tamaño no esté disponible. Tenga en cuenta que el tamaño del terminal no estará disponible si se lee desde una tubería o un archivo, por lo que los valores predeterminados pueden ser importantes incluso en sistemas que sí admiten formas de averiguar el tamaño del

terminal. 
  typedef struct {
    int nline;        /* El terminal tiene nline líneas */
    int ncolumn;      /* El terminal tiene ncolumn columnas */
  } GlTerminalSize;
  GlTerminalSize gl_terminal_size(GetLine *gl,
                                  int def_ncolumn,
                                  int def_nline)
;

Esta función primero actualiza las dimensiones de respaldo del terminal de gl_get_line(), luego registra sus hallazgos en el valor de

retorno.

Los argumentos def_ncolumn y def_nline especifican el número predeterminado de columnas y líneas del terminal a usar si el tamaño del terminal no puede ser determinado a través de ioctl(TIOCGWINSZ) o

variables d
e entorno.

OCULTANDO LO QUE

ESCRIBES

Al ingresar información sensible, como contraseñas, es mejor no tener el texto que está ingresando reflejado en el terminal. Además, dicho texto no debería ser registrado en la lista de historial, ya que alguien que encuentre su terminal desatendida podría entonces recuperarlo, o alguien que esté husmeando en sus directorios podría verlo en su archivo de historial. Teniendo esto en cuenta, la función gl_echo_mode() le permite activar y desactivar la visualización y el archivo de cualquier texto que se ingrese posteriormente en las llamadas a gl_get_li

ne(). 
  int gl_echo_mode(GetLine *gl, int enable)
;

El argumento enable especifica si el texto ingresado debe ser visible o no. Si es 0, entonces las líneas ingresadas posteriormente no serán visibles en el terminal, y no serán registradas en la lista de historial. Si es 1, entonces las líneas de entrada posteriores se mostrarán a medida que se ingresan, y siempre que el historial no se haya desactivado a través de una llamada a gl_toggle_history(), también serán archivadas en la lista de historial. Finalmente, si el argumento enable es -1, entonces el modo de eco se deja sin cambios, lo que le permite consultar de forma no destructiva la configuración actual a través del valor de retorno. En todos los casos, el valor de retorno de la función es 0 si el eco estaba desactivado antes de que se llamara a la función, y 1 si estaba

activado.

Cuando el eco está desactivado, tenga en cuenta que aunque la final

ización con tabulador completará su prefijo de forma invisible lo
más lejos posible, las finalizaciones ambiguas no se mostrarán.

CONSULTAS DE UN SOLO

CARÁCTER

Usar gl_get_line() para consultar al usuario para una respuesta de un solo carácter, es inconveniente para el usuario, ya que debe presionar la tecla intro o retorno antes de que el carácter que escribió sea devuelto al programa. Por lo tanto, la función gl_query_char() ha sido proporcionada para consultas de un solo carácter como

esta. 
  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar)
;

Esta función muestra el indicador especificado al comienzo de una nueva línea, y espera a que el usuario escriba un carácter. Cuando el usuario escribe un carácter, gl_query_char() lo muestra a la derecha del indicador, inicia una nueva línea, y luego devuelve el carácter al programa que lo llamó. El valor de retorno de la función es el carácter que fue escrito. Si la lectura tuvo que ser abortada por alguna razón, se devuelve EOF en su lugar. En el último caso, la aplicación puede llamar a la función previamente documentada gl_return_status(), para averiguar qué salió mal. Esto podría, por ejemplo, haber sido la recepción de una señal, o el temporizador opcional de inactividad

activándose.

Si el usuario simplemente presiona intro, se sustituye el valor del argumento defchar. Esto significa que cuando el usuario presiona retorno de línea o retorno, el carácter especificado en defchar, se muestra después del indicador, como si el usuario lo hubiera escrito, así como ser devuelto a la aplicación que lo llamó. Si tal reemplazo no es importante, simplemente pase '0 como el valor de defchar

.

Si el carácter ingresado es un carácter no imprimible, se muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y los caracteres más allá de 127 se muestran en octal, precedidos por una barra

invertida.

Al igual que con gl_get_line(), el eco del carácter ingresado puede ser desactivado usando la función gl_echo_mode()

.

Si el proceso que llama es suspendido mientras espera a que el usuario escriba su respuesta, el cursor se mueve a la línea siguiente a la línea del indicador, luego cuando el proceso se reanuda, el indicador se vuelve a mostrar, y gl_query_char() reanuda la espera de que el usuario escriba un

carácter.

Tenga en cuenta que en el modo de servidor no bloqueante, (ver gl_io_mode(3)), si una línea de entrada incompleta está en proceso de ser leída cuando se llama a gl_query_char(), la línea de entrada parcial se descarta, y se borra del terminal, antes de que se muestre el nuevo indicador. La siguiente llamada a gl_get_line() comenzará por tant

o a editar una
nueva línea.

LEYENDO CARACTERES

CRUDOS

Mientras que la función gl_query_char() solicita visiblemente al usuario un carácter, y muestra lo que escribió, la función gl_read_char() lee un carácter de señal del usuario, sin escribir nada en el terminal, o perturbar alguna línea de entrada incompleta. Esto significa que puede ser llamada no solo entre llamadas a gl_get_line(), sino también desde funciones de retorno que la aplicación ha registrado para ser llamadas por gl_get_li

ne(). 
  int gl_read_char(GetLine *gl)
;

En caso de éxito, el valor de retorno de gl_read_char() es el carácter que fue leído. En caso de fallo, se devuelve EOF, y la función gl_return_status() puede ser llamada para averiguar qué salió mal. Las posibilidades incluyen el temporizador opcional de inactividad activándose, la recepción de una señal que está configurada para abortar gl_get_line(), o el bloqueo de E/S del terminal, cuando se está en el modo de E/S de servidor no

bloqueante.

Tenga en cuenta que ciertas teclas del teclado, como las teclas de función y las teclas de cursor, usualmente generan al menos 3 caracteres cada una, por lo que una sola llamada a gl_read_char() not be enough t

MOSTRANDO TEXTO

DINÁMICAMENTE

Entre las llamadas a gl_get_line(), la función gl_display_text() proporciona una forma conveniente de mostrar párrafos de texto, justificados a la izquierda y divididos en una o más líneas de terminal según las restricciones del ancho actual de la terminal. Se pueden encontrar ejemplos del uso de esta función en los programas de demostración, donde se utiliza para mostrar introducciones. En esos ejemplos también se ilustra el uso avanzado de prefijos, sufijos y líneas de relleno opcionales para dibujar un cuadro alrededor del

texto. 
  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string)
;

Si gl no está actualmente conectado a una terminal, por ejemplo si la salida de un programa que usa gl_get_line() se está redirigiendo a otro programa o a un archivo, entonces se utiliza el valor del parámetro def_width como el ancho de la

terminal.

El argumento indentation especifica el número de caracteres a usar para sangrar cada línea de salida. El argumento fill_char especifica el carácter que se usará para realizar esta

sangría.

El argumento prefix puede ser NULL, o ser una cadena de texto a colocar al comienzo de cada nueva línea (después de cualquier sangría). De manera similar, el argumento suffix puede ser NULL, o ser una cadena de texto a colocar al final de cada línea. El sufijo se coloca alineado contra el borde derecho de la terminal, y cualquier espacio entre su primer carácter y la última palabra en esa línea se rellena con el carácter especificado a través del argumento fill_char. Normalmente el carácter de relleno es un

espacio.

El argumento start le indica a gl_display_text() cuántos caracteres ya se han escrito en la línea de terminal actual, y por lo tanto le indica el índice de columna inicial del cursor. Dado que el valor de retorno de gl_display_text() es el índice de columna final del cursor, al pasar el valor de retorno de una llamada al argumento start de la siguiente llamada, se puede componer un párrafo que está dividido entre más de una cadena llamando a gl_display_text() para cada porción sucesiva del párrafo. Tenga en cuenta que son necesarios caracteres de salto de línea literales al final de cada párrafo para forzar el inicio de una nueva

línea.

JUEGOS DE CARACTERES

INTERNACIONALES

Desde la versión 1.4.0 de libtecla, gl_get_line() ha sido compatible con 8 bits. Esto significa que todos los caracteres de 8 bits que son imprimibles en la configuración regional actual del usuario ahora se muestran literalmente y se incluyen en la línea de entrada devuelta. Asumiendo que el programa que llama contiene correctamente una llamada como la

siguiente, 
  setlocale(LC_CTYPE, "")
;

entonces la configuración regional actual está determinada por la primera de las variables de entorno LC_CTYPE, LC_ALL, y LANG, que se encuentre que contiene un nombre de configuración regional válido. Si ninguna de estas variables está definida, o el programa omite llamar a setlocale, entonces se utiliza la configuración regional predeterminada C, que es ASCII de 7 bits de EE. UU. En la mayoría de las plataformas tipo unix, puede obtener una lista de configuraciones regionales válidas escribiendo el

comando: 
  locale
-a

en el prompt del shell. Se puede encontrar documentación adicional sobre cómo el usuario puede hacer uso de esto para introducir caracteres internacionales en la página del man

ual te
cla(7).

SEGURIDAD DE

HILOS

En un programa multihilo, debería usar la versión libtecla_r.a de la biblioteca. Esta usa versiones reentrantes de las funciones del sistema, donde están disponibles. Desafortunadamente ni terminfo ni termcap fueron diseñados para ser reentrantes, por l

o que no puede usar de forma segura las funciones del módulo getline en múltiples hilos (puede usar los módulos separados de expansión de archivos y finalización de palabras en múltiples hilos, vea las páginas de manual correspondientes para más detall
es). Sin embargo, debido al uso de funciones reentrantes de POSIX para buscar directorios de inicio, etc., es seguro usar este módulo desde un solo hilo de un programa multihilo, siempre que sus otros hilos no usen ninguna función de termcap o terminfo.
