NOMBRE

glBufferData, glNamedBufferData - crea e inicializa el almacén de datos de un objeto de búfer

ESPECIFICACIÓN C

void glBufferData(GLenum target, GLsizeiptr size, const void * data, GLenum usage);

void glNamedBufferData(GLuint buffer, GLsizeiptr size, const void *data, GLenum usage);

PARÁMETROS

target

Especifica el destino al que está enlazado el objeto de búfer para glBufferData, que debe ser uno de los destinos de enlace de búferes en la siguiente tabla:
Destino de Enlace de Búfer Propósito
GL_ARRAY_BUFFER Atributos de vértice
GL_ATOMIC_COUNTER_BUFFER Almacenamiento de contadores atómicos
GL_COPY_READ_BUFFER Fuente de copia de búfer
GL_COPY_WRITE_BUFFER Destino de copia de búfer
GL_DISPATCH_INDIRECT_BUFFER Comandos indirectos de cómputo de despacho
GL_DRAW_INDIRECT_BUFFER Argumentos de comandos indirectos
GL_ELEMENT_ARRAY_BUFFER Índices de array de vértices
GL_PIXEL_PACK_BUFFER Destino de lectura de píxeles
GL_PIXEL_UNPACK_BUFFER Fuente de datos de textura
GL_QUERY_BUFFER Búfer de resultados de consulta
GL_SHADER_STORAGE_BUFFER Almacenamiento de lectura/escritura para shaders
GL_TEXTURE_BUFFER Búfer de datos de textura
GL_TRANSFORM_FEEDBACK_BUFFER Búfer de retroalimentación de transformación
GL_UNIFORM_BUFFER Almacenamiento de bloques uniformes

buffer

Especifica el nombre del objeto de búfer para la función glNamedBufferData.

size

Especifica el tamaño en bytes del nuevo almacén de datos del objeto de búfer.

data

Especifica un puntero a los datos que se copiarán en el almacén de datos para su inicialización, o NULL si no se copiarán datos.

usage

Especifica el patrón de uso esperado del almacén de datos. La constante simbólica debe ser GL_STREAM_DRAW, GL_STREAM_READ, GL_STREAM_COPY, GL_STATIC_DRAW, GL_STATIC_READ, GL_STATIC_COPY, GL_DYNAMIC_DRAW, GL_DYNAMIC_READ, o GL_DYNAMIC_COPY.

DESCRIPCIÓN

glBufferData y glNamedBufferData crean un nuevo almacén de datos para un objeto de búfer. En el caso de glBufferData, se utiliza el objeto de búfer actualmente enlazado a target. Para glNamedBufferData, se utilizará en su lugar un objeto de búfer asociado con el ID especificado por el llamador en buffer.

Al crear el nuevo almacenamiento, se elimina cualquier almacén de datos preexistente. El nuevo almacén de datos se crea con el tamaño en bytes y el uso especificados. Si data no es NULL, el almacén de datos se inicializa con los datos de este puntero. En su estado inicial, el nuevo almacén de datos no está mapeado, tiene un puntero mapeado NULL y su acceso mapeado es GL_READ_WRITE.

usage es una pista para la implementación de GL sobre cómo se accederá al almacén de datos del objeto de búfer. Esto permite a la implementación de GL tomar decisiones más inteligentes que pueden afectar significativamente el rendimiento del objeto de búfer. Sin embargo, no restringe el uso real del almacén de datos. usage se puede dividir en dos partes: primero, la frecuencia de acceso (modificación y uso), y segundo, la naturaleza de ese acceso. La frecuencia de acceso puede ser una de las siguientes:

STREAM

El contenido del almacén de datos se modificará una vez y se utilizará como máximo unas pocas veces.

STATIC

El contenido del almacén de datos se modificará una vez y se utilizará muchas veces.

DYNAMIC

El contenido del almacén de datos se modificará repetidamente y se utilizará muchas veces.

La naturaleza del acceso puede ser una de las siguientes:

DRAW

El contenido del almacén de datos es modificado por la aplicación y se utiliza como fuente para comandos de dibujo y especificación de imágenes de GL.

READ

El contenido del almacén de datos se modifica leyendo datos de GL y se utiliza para devolver esos datos cuando son consultados por la aplicación.

COPY

El contenido del almacén de datos se modifica leyendo datos de GL y se utiliza como fuente para comandos de dibujo y especificación de imágenes de GL.

NOTAS

Si data es NULL, aún se crea un almacén de datos del tamaño especificado, pero su contenido permanece sin inicializar y, por lo tanto, indefinido.

Los clientes deben alinear los elementos de datos de manera consistente con los requisitos de la plataforma cliente, con un requisito adicional de nivel base de que un desplazamiento dentro de un búfer a un dato que comprende N bytes sea un múltiplo de N.

El destino GL_ATOMIC_COUNTER_BUFFER solo está disponible si la versión de GL es 4.2 o superior.

Los destinos GL_DISPATCH_INDIRECT_BUFFER y GL_SHADER_STORAGE_BUFFER solo están disponibles si la versión de GL es 4.3 o superior.

El destino GL_QUERY_BUFFER solo está disponible si la versión de GL es 4.4 o superior.

ERRORES

Se genera GL_INVALID_ENUM por glBufferData si target no es uno de los destinos de búfer aceptados.

Se genera GL_INVALID_ENUM si usage no es GL_STREAM_DRAW, GL_STREAM_READ, GL_STREAM_COPY, GL_STATIC_DRAW, GL_STATIC_READ, GL_STATIC_COPY, GL_DYNAMIC_DRAW, GL_DYNAMIC_READ, o GL_DYNAMIC_COPY.

Se genera GL_INVALID_VALUE si size es negativo.

Se genera GL_INVALID_OPERATION por glBufferData si el nombre de objeto de búfer reservado 0 está enlazado a target.

Se genera GL_INVALID_OPERATION por glNamedBufferData si buffer no es el nombre de un objeto de búfer existente.

Se genera GL_INVALID_OPERATION si el indicador GL_BUFFER_IMMUTABLE_STORAGE del objeto de búfer es GL_TRUE.

Se genera GL_OUT_OF_MEMORY si GL no puede crear un almacén de datos con el tamaño size especificado.

NAME

glNamedBufferData — Parameters for Buffer Object Textures

C SPECIFICATION

void glNamedBufferData(GLintptr size, const GLvoid *data, GLenum usage);

void glNamedBufferDataEXT(GLuint buffer, GLsizeiptr size, const GLvoid *data, GLenum usage);

PARAMETERS

buffer
Specifies the buffer object to be modified.
size
Specifies the size, in basic memory units, of the buffer object's new data store.
data
Specifies a pointer to the data that will be copied into the new data store for the buffer object. If data is NULL, then the contents of the new data store are not defined.
usage
Specifies the intended usage pattern of the buffer object, which is used by the GL driver to optimize buffer operations. The hint is specified as one of the following symbolic constants:
GL_STREAM_DRAW
The data store will be modified once and used multiple times for drawing or data transmission.
GL_STATIC_DRAW
The data store will be initialized once and used multiple times for drawing or data transmission.
GL_DYNAMIC_DRAW
The data store will be modified multiple times and used multiple times for drawing or data transmission.
GL_STREAM_READ
The data store will be modified once and used multiple times for reading by the GL.
GL_STATIC_READ
The data store will be initialized once and used multiple times for reading by the GL.
GL_DYNAMIC_READ
The data store will be modified multiple times and used multiple times for reading by the GL.
GL_STREAM_COPY
The data store will be modified once and used multiple times for reading by the GL and for drawing or transmission to other GL operations.
GL_STATIC_COPY
The data store will be initialized once and used multiple times for reading by the GL and for drawing or transmission to other GL operations.
GL_DYNAMIC_COPY
The data store will be modified multiple times and used multiple times for reading by the GL and for drawing or transmission to other GL operations.

DESCRIPTION

glNamedBufferData updates the data store of a buffer object. It is equivalent to calling glBindBuffer with the target corresponding to buffer, followed by a call to glBufferData.

If data is not NULL, then the contents of the buffer object are initialized to the same value as the contents of data. The size parameter specifies the number of basic memory units that will be used to store data.

If data is NULL, then the contents of the buffer object are not modified. This is useful for pre-allocating space for a buffer object that will be populated later, perhaps with multiple calls to glBufferSubData.

The usage parameter is a GLintptr that provides a hint to the GL implementation about the nature of the expected data operations on the buffer object. This hint is used to optimize GL performance, but it is not a constraint. It is valid to specify a usage pattern that differs from the actual usage of the buffer object. The usage pattern is specified as one of the symbolic constants listed in the description of the usage parameter.

Calling glNamedBufferData with a size of 0 creates an empty buffer object. If data is not NULL, it must be NULL if size is 0.

When a buffer object is deleted, its name is freed and can be reused. Any associated buffer object memory is freed.

The glNamedBufferDataEXT function is provided for compatibility with earlier versions of OpenGL and may be deprecated in future versions. It is recommended to use glNamedBufferData instead.

NOTES

Buffer objects are an optional feature of OpenGL. To use buffer objects, the GL must have the GL_ARB_vertex_buffer_object extension enabled.

The usage parameter is a hint to the GL driver. The driver may use this hint to optimize buffer operations, but it is not a constraint. It is valid to specify a usage pattern that differs from the actual usage of the buffer object.

ERRORS

GL_INVALID_VALUE is generated if buffer is not the name of an existing buffer object.

GL_INVALID_VALUE is generated if size is negative.

GL_INVALID_OPERATION is generated if data is not NULL and size is zero.

GL_INVALID_ENUM is generated if usage is not one of the accepted symbolic constants.
