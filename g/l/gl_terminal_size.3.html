DESCRIPCIÓ

N

La función gl_get_line() es parte de la biblioteca tecla (véase la página man libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de unix. Además de la edición de línea de comandos simple, soporta el recuerdo de líneas de comandos previamente introducidas, la completación con TAB de nombres de archivo, y la expansión en línea de comodines de nombres de archivo. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario, se puede encontrar en la página man tecla(7). PERSONALIZADO

Si en su aplicación, le gustaría que el completado con TAB completara otras cosas además de o en lugar de nombres de archivo, puede organizar esto registrando una función de retorno de completado alternativa, mediante una llamada a la función gl_customize_co

mpletion(). 
  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn)
;

El argumento data proporciona una manera para que su aplicación pase información arbitraria, específica de la aplicación, a la función de retorno. Esto se pasa a la función de retorno cada vez que se llama. Podría, por ejemplo, apuntar a la tabla de símbolos de la que se deben buscar los posibles completados. El argumento match_fn especifica la función de retorno a ser llamada. El tipo de función CplMatchFn está definido en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y prototipar funciones de retorno. La declaración y las responsabilidades de las funciones de retorno se describen en profundidad en la página de manual cpl_complete_word(3)

.

En resumen, la función de retorno es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario presionó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar posibles completados de esta palabra, y registrarlos uno por uno en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion(). Si la función de retorno desea proporcionar completado de nombres de archivo además de sus propios completados específicos, tiene la opción de llamar por sí misma a la función de retorno de completado de nombres de archivo incorporada. Esto también está documentado en la página de manual cpl_complete_word(3)

.

Tenga en cuenta que si le gustaría que gl_get_line() devuelva la línea de entrada actual cuando se haya realizado un completado exitoso, puede organizar esto cuando llame a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de salto de línea. Si hace esto, la línea de entrada se actualizará para mostrar el completado, junto con cualquier sufijo de continuación hasta el carácter de salto de línea, entonces gl_get_line() devolverá esta línea de

entrada.

Si, por alguna razón, su función de retorno necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto iniciará una nueva línea después de la línea de entrada que se está editando actualmente, restablecerá la E/S normal de la terminal, y le dirá a gl_get_line() que la línea de entrada necesitará

ser redibujada cuando la f
unción de retorno regrese.

Esto se logra usando la función gl_completion_action()

  int gl_completion_action(GetLine *gl,

Los argumentos data y match_fn se describen en la página de manual cpl_complete_word, y especifican la función de retorno que debe ser invocada para identificar posibles completados. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar cualquier posible completado ambiguo, o si simplemente debe mostrar la lista de posibles completados sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre con el que los archivos de configuración y las futuras invocaciones de esta función deben referirse a la acción. Este debe ser el nombre de una acción de completado existente a ser cambiada, o ser un nuevo nombre no utilizado para una nueva acción. Finalmente, el argumento keyseq especifica la secuencia de teclas predeterminada a la que asociar la acción. Si esto es NULL, no se asociará ninguna nueva secuencia de teclas a la

acción.

Tenga cuidado de que para que el usuario pueda cambiar la secuencia de teclas que está asociada a las acciones instaladas de esta manera, cuando llame a gl_completion_action() para instalar una acción dada por primera vez, debe hacerlo entre llamar a new_GetLine() y la primera llamada a gl_get_line(). De lo contrario, cuando se lea el archivo de configuración del usuario en la primera llamada a gl_get_line(), el nombre de su acción adicional no será conocido, y cualquier referencia a ella en el archivo de configuración generará un

error.

ntes de
hacerlo.

DEFINIENDO ACCIONES

PERSONALIZADAS

Aunque las acciones de asociación de teclas incorporadas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, asociadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza que correspondiera a un número de pieza precedente al cursor. Tal característica está claramente fuera del alcance de las funciones de acción incorporadas. Así que para tales casos especiales, se proporciona la función gl_register_action()

. 
  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq)
;

Esta función permite a la aplicación registrar una función externa, fn, que a partir de entonces será llamada siempre que se introduzca la secuencia de teclas especificada, keyseq, por el usuario, o el usuario introduzca cualquier otra secuencia de teclas que el usuario asocie posteriormente al nombre de acción especificado, name, en su archivo de configuración. El argumento data puede ser un puntero a cualquier cosa que la aplicación desee que se pase a la función de acción, fn, siempre que esa función sea

invocada.

La función de acción, fn, debe ser declarada usando la siguiente macro, que está definida en libtecl

a.h. 
  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char
*line)

Los argumentos gl y data son aquellos que fueron previamente pasados a gl_register_action() cuando la función de acción fue registrada. El argumento count es un argumento numérico que el usuario tiene la opción de introducir usando la acción digit-argument, antes de invocar la acción. Si el usuario no introduce un número, entonces el argumento count se establece en 1. Nominalmente este argumento se interpreta como un conteo de repetición, lo que significa que la acción debe repetirse esa cantidad de veces. En la práctica, sin embargo, para algunas acciones un conteo de repetición tiene poco sentido. En tales casos, las acciones pueden simplemente ignorar el argumento count, o usar su valor para un propósito

diferente.

Una copia de la línea de entrada actual se pasa en el argumento de solo lectura line. La posición actual del cursor dentro de esta cadena es dada por el índice contenido en el argumento curpos. Tenga en cuenta que la manipulación directa de la línea de entrada y la posición del cursor no está permitida. Esto se debe a que las reglas dictadas por varios modos, como el modo vi versus el modo emacs, el modo sin eco, y el modo de inserción versus el modo de sobrescritura etc, hacen que sea demasiado complejo para un escritor de aplicaciones escribir una acción de edición conforme, así como restringir cambios futuros a los internos de gl_get_line(). ACTIONS


When gl_get_line() is called, it executes commands, that
    are typically bound to keys or key sequences. When the user presses a key, or
    key sequence, that is bound to an action, then that action is executed. An
    action is really nothing more than a function, that is called with the
    current GetLine object as its sole argument. It is expected to perform
    some operation, and then to return one of the values listed below.


The following example demonstrates a simple action, that prints
    "Hello world" to the terminal, and then resumes command-line
    editing.


  int my_action(GetLine *gl) {
    if (gl_something_nasty(gl))  /* Temporarily suspend editing */
      return GLA_ABORT;
    printf("Hello world\n");
    return GLA_CONTINUE;
  }


Las funciones de acción deben devolver uno de los siguientes valores
    para indicar a gl_get_line() cómo proceder.


  GLA_ABORT     -   Hace que gl_get_line() devuelva NULL.
  GLA_RETURN    -   Hace que gl_get_line() devuelva la
                    línea de entrada completada.
  GLA_CONTINUE  -   Reanuda la edición de la línea de comandos.


Tenga en cuenta que el argumento name de
    gl_register_action() especifica el nombre por el cual un usuario puede
    referirse a la acción en su archivo de configuración. Esto les permite volver a
    enlazar la acción a una secuencia de teclas alternativa. Para que esto funcione,
    es necesario llamar a gl_register_action() entre la llamada a
    new_GetLine() y la primera llamada a gl_get_line().






ARCHIVOS DE HISTORIAL


Para guardar el contenido del búfer de historial antes de salir de
    su aplicación, y posteriormente restaurarlo cuando la inicie nuevamente, se
    proporcionan las siguientes funciones.


 int gl_save_history(GetLine *gl, const char *filename,
                     const char *comment, int max_lines);
 int gl_load_history(GetLine *gl, const char *filename,
                     const char *comment);


El argumento filename especifica el nombre que se dará al
    archivo de historial al guardar, o el nombre de un archivo de historial
    existente al cargar. Esto puede contener expresiones de directorio de inicio
    y variables de entorno, como "~/.myapp_history" o
    "$HOME/.myapp_history".


Junto con cada línea del historial, se graba información adicional
    sobre ella, como cuándo fue ingresada por el usuario y cuál es su nivel de
    anidamiento, como un comentario que precede a la línea en el archivo de
    historial. Escribirlo como un comentario permite que el archivo de historial
    sirva también como archivo de comandos, en caso de que desee reproducir una
    sesión completa utilizándolo. Dado que los prefijos de comentario difieren en
    diferentes idiomas, se proporciona el argumento comment para especificar
    el prefijo del comentario. Por ejemplo, si su aplicación fuera un shell de Unix,
    como el shell de Bourne, especificaría "#" aquí. Cualquiera que sea
    el carácter de comentario que elija, debe especificar el mismo prefijo a
    gl_load_history() que utilizó cuando llamó a
    gl_save_history() para escribir el archivo de historial.


El argumento max_lines debe ser -1 para especificar que se
    guarden todas las líneas de la lista de historial, o un número positivo que
    especifique un límite superior sobre cuántas de las líneas más recientes
    deben guardarse.


Ambas funciones devuelven un valor distinto de cero en caso de error,
    después de escribir un mensaje de error en stderr. Tenga en cuenta que
    gl_load_history() no considera la no existencia de un archivo como un
    error.






MÚLTIPLES LISTAS DE HISTORIAL


Si su aplicación utiliza un único objeto GetLine para ingresar
    muchos tipos diferentes de líneas de entrada, es posible que desee que
    gl_get_line() distinga los diferentes tipos de líneas en la lista de
    historial y solo recupere líneas que coincidan con el tipo de línea actual.
    Para admitir este requisito, gl_get_line() marca las líneas que se
    graban en la lista de historial con un identificador entero elegido por la
    aplicación. Inicialmente, este identificador se establece en 0 por
    new_GetLine(), pero puede cambiarse posteriormente llamando a
    gl_group_history().


  int gl_group_history(GetLine *gl, unsigned id);


El identificador entero id puede ser cualquier número elegido
    por la aplicación, pero tenga en cuenta que gl_save_history() y
    gl_load_history() conservan la asociación entre los identificadores y
    las líneas de entrada históricas entre invocaciones del programa, por lo que
    debe elegir identificadores fijos para los diferentes tipos de líneas de
    entrada utilizados por su aplicación.


Cada vez que gl_get_line() agrega una nueva línea de
    entrada a la lista de historial, se registra el identificador de historial
    actual con ella, y cuando se le pide que recupere una línea de entrada
    histórica, solo recupera las líneas que están marcadas con el identificador
    actual.






MOSTRANDO EL HISTORIAL


La lista de historial se puede mostrar llamando a
    gl_show_history().


  int gl_show_history(GetLine *gl, FILE *fp,
                      const char *fmt,
                      int all_groups,
                      int max_lines);


Esto muestra el contenido actual de la lista de historial al flujo de
    salida stdio fp. Si el argumento max_lines es mayor o igual a
    cero, no se mostrarán más de las líneas más recientes. Si el argumento
    all_groups es distinto de cero, se mostrarán líneas de todos los grupos
    de historial. De lo contrario, solo se mostrarán las del grupo de historial
    seleccionado actualmente. El argumento de cadena de formato, fmt,
    determina cómo se muestra la línea. Puede contener caracteres arbitrarios que
    se escriben tal cual, intercalados con cualquiera de las siguientes directivas
    de formato:


  %D  -  La fecha en la que la línea fue ingresada
         originalmente, formateada como 2001-11-20.
  %T  -  La hora del día en que se ingresó la línea,
         formateada como 23:59:59.
  %N  -  El número secuencial de entrada de la línea en
         el búfer de historial.
  %G  -  El número del grupo de historial al que
         pertenece la línea.
  %%  -  Un carácter % literal.
  %H  -  La línea de historial en sí.


Por lo tanto, una cadena de formato como
    "%D %T %H0 generaría algo como:


  2001-11-20 10:23:34  Hello world


Tenga en cuenta la inclusión de un carácter de nueva línea explícito
    en la cadena de formato.

ARCHIVO MANUAL DE HISTORIAL


Por defecto, cada vez que el usuario ingresa una línea, se agrega
    automáticamente al historial, justo antes de que gl_get_line()
    devuelva la línea al llamador. Esto es conveniente para la mayoría de las
    aplicaciones, pero también hay aplicaciones que necesitan un control más
    detallado sobre lo que se agrega al historial. En tales casos, la adición
    automática de líneas ingresadas al historial se puede desactivar llamando a
    la función gl_automatic_history().


  int gl_automatic_history(GetLine *gl, int enable);


Si se llama a esta función con su argumento enable establecido
    en 0, gl_get_line() no archivará automáticamente las líneas
    ingresadas posteriormente. El archivado automático se puede reactivar más
    tarde, llamando a esta función nuevamente, con su argumento enable
    establecido en 1. Mientras el archivado automático del historial está
    desactivado, la aplicación llamante puede usar
    gl_append_history() para agregar líneas a la lista de historial según
    sea necesario.


  int gl_append_history(GetLine *gl, const char *line);


El argumento line especifica la línea que se agregará a la
    lista de historial. Debe ser una cadena normal terminada en ' '. Si
    esta cadena contiene algún carácter de nueva línea, la línea que se archive en
    el historial se terminará con el primero de ellos. De lo contrario, se
    terminará con el terminador ' '. Si la línea es más larga que la
    longitud máxima de línea de entrada, que se especificó al llamar a
    new_GetLine(), cuando la línea se recupere, se truncará a la longitud
    real de la línea de gl_get_line().


Si tiene éxito, gl_append_history() devuelve 0. De lo
    contrario, devuelve un valor distinto de cero y establece errno en
    uno de los siguientes valores.


   EINVAL  -  Uno de los argumentos pasados a
              gl_append_history() era NULL.
   ENOMEM  -  La línea especificada era más larga que el
              tamaño asignado del búfer de historial (según lo
              especificado al llamar a new_GetLine()), por lo
              que no se pudo archivar.


Opcionalmente, se puede obtener una descripción textual del error
    llamando a gl_error_message(). Tenga en cuenta que después de un error
    de este tipo, la lista de historial permanece en un estado válido para recibir
    nuevas líneas de historial, por lo que hay poco daño en simplemente ignorar el
    estado de retorno de gl_append_history().

MANIPULATING THE HISTORY LIST


The history list may be manipulated in several ways. A limit can be
    placed on the number of lines stored in the history list by means of the
    gl_limit_history() function.


  void gl_limit_history(GetLine *gl, int max_lines);


The max_lines should either be a positive number >=
    0, specifying an upper limit on the number of lines in the buffer, or be
    -1 to cancel any previously specified limit. When a limit is in
    effect, only the max_lines most recently appended lines are kept in
    the buffer. Older lines are discarded.


To discard lines from the history buffer, use the
    gl_clear_history() function.


  void gl_clear_history(GetLine *gl, int all_groups);


The all_groups argument tells the function whether to
    delete just the lines associated with the current history group (see
    gl_group_history()), or all historical lines in the buffer.


The gl_toggle_history() function allows you to toggle
    history on and off without losing the current contents of the history
    list.


  void gl_toggle_history(GetLine *gl, int enable);


Setting the enable argument to 0 turns off the history
    mechanism, and setting it to 1 turns it back on. When history is turned off,
    no new lines will be added to the history list, and history lookup
    key-bindings will act as though there is nothing in the history buffer.

CHANGING TERMINALS


The new_GetLine() constructor function assumes that input
    is to be read from stdin, and output written to stdout. The
    following function allows you to switch to different input and output
    streams.


  int gl_change_terminal(GetLine *gl, FILE *input_fp,
                         FILE *output_fp, const char *term);


The gl argument is the object that was returned by
    new_GetLine(). The input_fp argument specifies the stream to
    read from, and output_fp specifies the stream to be written to. Only
    if both of these refer to a terminal, will interactive terminal input be
    enabled. Otherwise gl_get_line() will simply call fgets() to
    read command input. If both streams refer to a terminal, then they must
    refer to the same terminal, and the type of this terminal must be specified
    via the term argument. The value of the term argument is
    looked up in the terminal information database (terminfo or termcap), in
    order to determine which special control sequences are needed to control
    various aspects of the terminal. new_GetLine() for example, passes
    the return value of getenv("TERM") in this argument. Note
    that if one or both of input_fp and output_fp don't refer to a
    terminal, then it is legal to pass NULL instead of a terminal
  type.


Note that if you want to pass file descriptors to
    gl_change_terminal(), you can do this by creating stdio stream
    wrappers using the POSIX fdopen() function.






EXTERNAL EVENT HANDLING


By default, gl_get_line()
    doesn't return until either a
    complete input line has been entered by the user, or an error occurs. In
    programs that need to watch for I/O from other sources than the terminal,
    there are two options.


  1. Use the functions described in the
     gl_io_mode(3) man page to switch
     gl_get_line() into non-blocking server mode. In this mode,
     gl_get_line() becomes a non-blocking, incremental
     line-editing function that can safely be called from
     an external event loop. Although this is a very
     versatile method, it involves taking on some
     responsibilities that are normally performed behind
     the scenes by gl_get_line().
  2. While gl_get_line() is waiting for keyboard
     input from the user, you can ask it to also watch for
     activity on arbitrary file descriptors, such as
     network sockets, pipes etc, and have it call functions
     of your choosing when activity is seen. This works on
     any system that has the select() system call,
     which is most, if not all flavors of unix.


Registering a file descriptor to be watched by
    gl_get_line() involves calling the gl_watch_fd()
    function.


  int gl_watch_fd(GetLine *gl, int fd, GlFdEvent event,
                  GlFdEventFn *callback, void *data);


If this returns non-zero, then it means that either your arguments
    are invalid, or that this facility isn't supported on the host system.


The fd argument is the file descriptor to be watched. The
    event argument specifies what type of activity is of interest, chosen
    from the following enumerated values:


  GLFD_READ   -  Watch for the arrival of data to be read.
  GLFD_WRITE  -  Watch for the ability to write to the file
                 descriptor without blocking.
  GLFD_URGENT -  Watch for the arrival of urgent
                 out-of-band data on the file descriptor.


The callback argument is the function to call when the
    selected activity is seen. It should be defined with the following macro,
    which is defined in libtecla.h.


  #define GL_FD_EVENT_FN(fn) GlFdStatus (fn)(GetLine *gl, \
                                      void *data, int fd, \
                                      GlFdEvent event)


The data argument of the gl_watch_fd() function is
    passed to the callback function for its own use, and can point to anything
    you like, including NULL. The file descriptor and the event argument
    are also passed to the callback function, and this potentially allows the
    same callback function to be registered to more than one type of event
    and/or more than one file descriptor. The return value of the callback
    function should be one of the following values.


  GLFD_ABORT    -  Tell gl_get_line() to abort. When this
                   happens, gl_get_line() returns
                   NULL, and a following call to
                   gl_return_status() will return
                   GLR_FDABORT. Note that if the
                   application needs errno always to
                   have a meaningful value when
                   gl_get_line() returns NULL,
                   the callback function should set
                   errno appropriately.
  GLFD_REFRESH  -  Redraw the input line then continue
                   waiting for input. Return this if
                   your callback wrote to the terminal.
  GLFD_CONTINUE -  Continue to wait for input, without
                   redrawing the line.


Note that before calling the callback, gl_get_line() blocks
    most signals, and leaves its own signal handlers installed, so if you need
    to catch a particular signal you will need to both temporarily install your
    own signal handler, and unblock the signal. Be sure to re-block the signal
    (if it was originally blocked) and reinstate the original signal handler, if
    any, before returning.


If the callback function needs to read or write to the terminal,
    it should ideally first call gl_normal_io() to temporarily suspend
    line editing. This will restore the terminal to canonical, blocking-I/O,
    mode, and move the cursor to the start of a new terminal line. Later, when
    the callback returns, gl_get_line() will notice that
    gl_normal_io() was called, redisplay the input line and resume
    editing. Note that in this case the return values, GLFD_REFRESH and
    GLFD_CONTINUE are equivalent.


To support cases where the callback function calls a third-party
    function which occasionally and unpredictably writes to the terminal, the
    automatic conversion of "0 to "0 is re-enabled
    before the callback function is called. If the callack knows that the
    third-party function wrote to the terminal, it should then return the
    GLFD_REFRESH return value, to tell gl_get_line() to redisplay
    the input line.


To remove a callback function that you previously registered for a
    given file descriptor and event, simply call gl_watch_fd() with the
    same file descriptor and event arguments, but with a callback
    argument of 0. The data argument is ignored in this case.

GL_TRAP_SIGNAL


Esta función se utiliza para configurar la biblioteca
    gl_get_line para que reaccione ante señales. La función rastrea la
    señal especificada y, si se recibe, ejecuta un manejador de señales definido
    por la aplicación antes de realizar la acción especificada por el argumento
    after. Si el manejador de señales de la aplicación se sale,
    gl_get_line puede reaccionar de varias maneras, como devolver la línea
    completada, abortar o reanudar la edición de la línea de comandos. La función
    devuelve 0 si tiene éxito y un valor distinto de cero si se produce un error.


  int gl_trap_signal(GetLine *gl, int signo, unsigned flags,
                     GlAfterSignal after, int errno_value);


El argumento signo es el número de la señal que desea
    rastrear. El argumento flags es un conjunto de banderas que determinan
    el entorno en el que se invoca el manejador de señales de la aplicación, el
    argumento after indica a gl_get_line() qué hacer después de
    que el manejador de señales de la aplicación regrese, y errno_value
    indica a gl_get_line() qué valor establecer para errno si se le
    indica que aborte.


El argumento flags es un OR a nivel de bits de cero o más de
    los siguientes enumeradores:


  GLS_RESTORE_SIG  -  Restaura el entorno de señales de la llamada
                      mientras se maneja la señal.
  GLS_RESTORE_TTY  -  Restaura la configuración de la terminal de la
                      llamada mientras se maneja la señal.
  GLS_RESTORE_LINE -  Mueve el cursor al inicio de la línea
                      siguiente a la línea de entrada antes de
                      invocar el manejador de señales de la
                      aplicación.
  GLS_REDRAW_LINE  -  Redibuja la línea de entrada cuando el
                      manejador de señales de la aplicación
                      regresa.
  GLS_UNBLOCK_SIG  -  Normalmente, si el programa que llama tiene una
                      señal bloqueada (man sigprocmask),
                      gl_get_line() no rastrea esa señal. Esta
                      bandera indica a gl_get_line() que rastree
                      la señal y la desbloquee durante la
                      duración de la llamada a gl_get_line().
  GLS_DONT_FORWARD -  Si se incluye esta bandera, la señal no se
                      reenviará al manejador de señales del
                      programa que llama.


Dos combinaciones de banderas comúnmente útiles también se
    enumeran de la siguiente manera:


  GLS_RESTORE_ENV   = GLS_RESTORE_SIG | GLS_RESTORE_TTY |
                      GLS_REDRAW_LINE
  GLS_SUSPEND_INPUT = GLS_RESTORE_ENV | GLS_RESTORE_LINE


Si su manejador de señales, o el manejador de señales predeterminado
    del sistema para esta señal, si no lo ha reemplazado, nunca escribe en la
    terminal, ni suspende o termina el programa que llama, entonces puede
    establecer de forma segura el argumento flags a 0.


Si su manejador de señales siempre escribe en la terminal, lee de
    ella, o suspende o termina el programa, debe especificar el argumento
    flags como GL_SUSPEND_INPUT, para que:


1. El cursor no se quede en medio de la línea de entrada.
2. El usuario pueda escribir entrada y que se refleje.
3. Para que no necesite terminar cada línea de salida con
   \r\n, en lugar de solo \n.


La combinación GL_RESTORE_ENV es la misma que
    GL_SUSPEND_INPUT, excepto que no mueve el cursor, y si su manejador de
    señales no lee ni escribe nada en la terminal, el usuario no verá ninguna
    indicación visible de que se ha capturado una señal. Esto puede ser útil si
    tiene un manejador de señales que solo escribe ocasionalmente en la terminal,
    donde el uso de GL_SUSPEND_LINE haría que la línea de entrada se
    duplicara innecesariamente cuando no se ha escrito nada en la terminal. Dicho
    manejador de señales, cuando escribe en la terminal, debe asegurarse de
    iniciar una nueva línea al principio de su primera escritura, escribiendo una
    nueva línea antes de regresar. Si la señal llega mientras el usuario está
    introduciendo una línea que solo ocupa una línea de terminal de señal, o si
    el cursor está en la última línea de terminal de una línea de entrada más
    larga, esto tendrá el mismo efecto que GL_SUSPEND_INPUT. De lo
    contrario, comenzará a escribir en una línea que ya contiene parte de la línea
    de entrada mostrada. Esto no causa ningún daño, pero se ve un poco feo, por
    eso la combinación GL_SUSPEND_INPUT es mejor si sabe que siempre
    va a escribir en la terminal.


El argumento after, que determina qué hace
    gl_get_line() después de que el manejador de señales de la aplicación
    regresa (si regresa), puede tomar cualquiera de los siguientes valores:


  GLS_RETURN   - Devuelve la línea de entrada completada, como si
                 el usuario hubiera presionado la tecla de retorno.
  GLS_ABORT    - Hace que gl_get_line() aborte. Cuando esto
                 sucede, gl_get_line() devuelve NULL, y
                 una llamada posterior a gl_return_status()
                 devolverá GLR_SIGNAL. Tenga en cuenta que
                 si la aplicación necesita que errno siempre
                 tenga un valor significativo cuando
                 gl_get_line() devuelve NULL, la
                 función de devolución de llamada debe establecer
                 errno apropiadamente.
  GLS_CONTINUE - Reanuda la edición de la línea de comandos.


El argumento errno_value está destinado a combinarse con la
    opción GLS_ABORT, indicando a gl_get_line() qué valor establecer
    para la variable estándar errno antes de devolver NULL al programa
    que llama. Sin embargo, también se puede usar con la opción GL_RETURN,
    en caso de que desee tener una forma de distinguir entre una línea de entrada
    que se introdujo usando la tecla de retorno y una que se introdujo por la
    recepción de una señal.






MANEJO CONFIABLE DE SEÑALES


El manejo de señales es sorprendentemente difícil de hacer de forma
    confiable sin condiciones de carrera. En gl_get_line() se ha puesto
    mucha atención para permitir que las aplicaciones realicen un manejo confiable
    de señales alrededor de gl_get_line(). Esta sección explica cómo hacer
    uso de esto.


Como ejemplo de los problemas que pueden surgir si la aplicación no
    está escrita correctamente, imagine que la aplicación tiene un manejador de
    señales SIGINT que establece una bandera global. Ahora suponga que la
    aplicación prueba esta bandera justo antes de invocar gl_get_line().
    Si una señal SIGINT se recibe en la pequeña ventana de tiempo entre la
    instrucción que prueba el valor de esta bandera y la instrucción que llama a
    gl_get_line(), entonces gl_get_line() no verá la señal y no
    será interrumpida. Como resultado, la aplicación no podrá responder a la
    señal hasta que el usuario termine de introducir la línea de entrada y
    gl_get_line() regrese. Dependiendo de la aplicación, esto puede ser
    un desastre o no, pero al menos desconcertará al usuario.


La forma de evitar tales problemas es hacer lo siguiente.


1. Si es necesario, utilice la función gl_trap_signal() para
    configurar gl_get_line() para que aborte cuando se detecten señales
    importantes.


2. Configure gl_get_line() de tal manera que si alguna de las
    señales que captura está bloqueada cuando se llama a
    gl_get_line(), se desbloquearán automáticamente durante los momentos
    en que gl_get_line() está esperando E/S. Esto se puede hacer de forma
    individual para cada señal, llamando a la función
    gl_trap_signal() y especificando el atributo GLS_UNBLOCK de la
    señal, o de forma global llamando a la función gl_catch_blocked().


     void gl_catch_blocked(GetLine *gl);


Esta función simplemente agrega el atributo GLS_UNBLOCK a
    todas las señales que actualmente está configurada para rastrear.


3. Justo antes de llamar a gl_get_line(), bloquee la entrega
    de todas las señales que gl_get_line() está configurada para rastrear.
    Esto se puede hacer usando la función POSIX sigprocmask() en
    conjunción con la función gl_list_signals().


      int gl_list_signals(GetLine *gl, sigset_t *set);


Esta función devuelve el conjunto de señales que actualmente está
    configurada para capturar en el argumento set, que está en el formato
    requerido por sigprocmask().


4. En el ejemplo, ahora probaría la bandera global que establece el
    manejador de señales, sabiendo que ahora no hay peligro de que esta bandera
    se establezca nuevamente hasta que gl_get_line() desbloquee sus
    señales mientras realiza E/S.


5. Finalmente gl_get_line() regresa, ya sea porque se
    capturó una señal, ocurrió un error o el usuario terminó de introducir su
    línea de entrada.


6. Ahora volvería a verificar la bandera de señal global y, si está
    establecida, respondería a ella y pondría la bandera a cero.


7. Use sigprocmask() para desbloquear las señales que se
    bloquearon en el paso 3.


La misma técnica se puede usar alrededor de ciertas funciones POSIX
    conscientes de señales, como sigsetjmp() y sigsuspend(), y en
    particular, la primera de estas dos funciones se puede usar en conjunción
    con siglongjmp() para implementar el manejo de señales libre de
    condiciones de carrera alrededor de otras llamadas del sistema de larga
    duración. La forma de hacer esto se explica a continuación, mostrando cómo
    gl_get_line() logra rastrear señales de manera confiable alrededor de
    llamadas a funciones como read() y select() sin condiciones de
    carrera.


Lo primero que hace gl_get_line(), cada vez que se llama,
    es usar la función POSIX sigprocmask() para bloquear la entrega de
    todas las señales que está configurada para capturar. Esto es redundante si
    la aplicación ya las ha bloqueado, pero no hace daño. Deshace este paso justo
    antes de regresar.


Cada vez que gl_get_line() necesita llamar a read() o
    select() para esperar la entrada del usuario, primero llama a la
    función POSIX sigsetjmp(), asegurándose de especificar un valor distinto
    de cero para su argumento savesigs. La razón de este último argumento
    se aclarará en breve.


Si sigsetjmp() devuelve cero, gl_get_line() hace lo
    siguiente.


a. Utiliza la función POSIX sigaction() para registrar un
   manejador de señales temporal para todas las señales que está
   configurada para capturar. Este manejador de señales hace dos
   cosas.
   1. Registra el número de la señal recibida en una variable de
      ámbito de archivo.
   2. Luego llama a la función POSIX siglongjmp() usando el
      búfer que se pasó a sigsetjmp() como primer
      argumento, y un valor distinto de cero como segundo
      argumento.
   Cuando este manejador de señales se registra, el miembro
   sa_mask del argumento struct sigaction act de la
   llamada a sigaction() se configura para contener todas
   las señales que gl_get_line() está capturando. Esto
   asegura que solo una señal será capturada a la vez por nuestro
   manejador de señales, lo que a su vez asegura que múltiples
   instancias de nuestro manejador de señales no se pisen entre
   sí.
b. Ahora que el manejador de señales se ha configurado,
   gl_get_line() desbloquea todas las señales que está
   configurada para capturar.
c. Luego llama a las llamadas al sistema read() o
   select() para esperar la entrada del teclado.
d. Si esta llamada al sistema regresa (es decir, no se recibe
   ninguna señal), gl_get_line() vuelve a bloquear la
   entrega de las señales de interés.
e. Luego restaura los manejadores de señales que fueron
   desplazados por el que se acaba de instalar.

    de cero, esto significa que



una de las señales atrapadas fue capturada mientras se ejecutaban los pasos anteriores. Cuando esto ocurre, gl_get_line() hace lo 
siguiente.

TERMINAL

En la mayoría de los sistemas, la combinación de la ioctl TIOCGWINSZ y la
    señal SIGWINCH se utiliza para mantener una idea precisa del
    tamaño del terminal. El tamaño del terminal se consulta de nuevo cada vez que se llama a
    gl_get_line() y siempre que se recibe una señal SIGW
INCH.

En los pocos sistemas donde este mecanismo no está disponible, al
    inicio new_GetLine() primero busca las variables de entorno LINES y
    COLUMNS. Si no se encuentran, o contienen
    valores inutilizables, entonces si está disponible una base de datos de información de terminal como terminfo o
    termcap, se busca el tamaño por defecto del terminal en esta
    base de datos. Si esto también falla para proporcionar el tamaño del terminal, se utiliza un tamaño por defecto de
    80 columnas por 24 
líneas.

Incluso en sistemas que sí soportan ioctl(TIOCGWINSZ), si el
    terminal está en el otro extremo de una línea serie, el controlador del terminal generalmente
    no tiene forma de detectar cuándo ocurre un redimensionamiento ni de consultar cuál es el
    tamaño actual. En tales casos no se envía ninguna SIGWINCH al proceso, y las
    dimensiones devueltas por ioctl(TIOCGWINSZ) no son correctas. La única forma
    de manejar tales instancias es proporcionar una manera para que el usuario introduzca un comando
    que le diga al sistema remoto cuál es el nuevo tamaño. Este comando entonces llamaría a la función gl_set_term_size() para decirle a gl_get_line()
    sobre el cambio de 
tamaño.

  int gl_set_term_size(GetLine *gl, int ncolumn, int nline)
;

Los argumentos ncolumn y nline se utilizan para especificar
    las nuevas dimensiones del terminal, y no deben ser menores que 1. En sistemas
    que sí soportan ioctl(TIOCGWINSZ), esta función primero llama a
    ioctl(TIOCSWINSZ) para informar al controlador del terminal sobre el cambio en
    el tamaño. En el modo de E/S de servidor no bloqueante, si una línea está siendo introducida actualmente,
    la línea de entrada se redibuja para acomodar el tamaño cambiado. Finalmente, los
    nuevos valores se registran en gl para uso futuro por
  gl_get_li
ne().

La función gl_terminal_size() le permite consultar el
    tamaño actual del terminal, e instalar un tamaño de reserva alternativo para
    los casos en que el tamaño no esté disponible. Tenga en cuenta que el tamaño del terminal no estará
    disponible si se lee desde una tubería o un archivo, por lo que los valores por defecto pueden ser
    importantes incluso en sistemas que sí soportan formas de averiguar el tamaño del 
terminal.

  typedef struct {
    int nline;        /* El terminal tiene nline líneas */
    int ncolumn;      /* El terminal tiene ncolumn columnas */
  } GlTerminalSize;
  GlTerminalSize gl_terminal_size(GetLine *gl,
                                  int def_ncolumn,
                                  int def_nline)
;

Esta función primero actualiza las dimensiones de reserva del terminal de gl_get_line(), luego registra sus hallazgos en el valor de 
retorno.

Los argumentos def_ncolumn y def_nline especifican el número
    por defecto de columnas y líneas del terminal a usar si el tamaño del terminal no puede ser determinado a través de ioctl(TIOCGWINSZ) o 
variables d
e entorno.



OCULTANDO   LO QUE 
ESCRIBES

Al introducir información sensible, como contraseñas, es mejor
    no tener el texto que estás introduciendo reflejado en el terminal.
    Además, dicho texto no debería ser registrado en la lista de historial, ya que
    alguien que encuentre tu terminal desatendida podría entonces recuperarlo, o alguien
    que esté husmeando en tus directorios podría verlo en tu archivo de historial. Con
    esto en mente, la función gl_echo_mode() te permite activar y
    desactivar la visualización y el archivo de cualquier texto que sea introducido posteriormente en
    llamadas a gl_get_li
ne().

  int gl_echo_mode(GetLine *gl, int enable)
;

El argumento enable especifica si el texto introducido debe
    ser visible o no. Si es 0, entonces las líneas introducidas posteriormente no
    serán visibles en el terminal, y no serán registradas en la lista de
    historial. Si es 1, entonces las líneas de entrada posteriores se mostrarán a
    medida que se introduzcan, y siempre que el historial no haya sido desactivado a través de una
    llamada a gl_toggle_history(), también serán archivadas en la
    lista de historial. Finalmente, si el argumento enable es -1, entonces el
    modo de eco se deja sin cambios, lo que le permite consultar de forma no destructiva
    la configuración actual a través del valor de retorno. En todos los casos, el valor de retorno de
    la función es 0 si el eco estaba desactivado antes de que se llamara a la función, y 1 si estaba 
activado.

Cuando el eco está desactivado, tenga en cuenta que aunque la com
pletación con tabulador completará su prefijo de forma invisible l
o más lejos posible, las completaciones ambiguas no se mostrarán.



CONSULTAS   DE UN SOLO 
CARÁCTER

Usar gl_get_line() para consultar al usuario por una respuesta de un solo
    carácter, es inconveniente para el usuario, ya que debe presionar la tecla intro o retorno antes de que el carácter que escribió sea devuelto al
    programa. Por lo tanto, la función gl_query_char() ha sido proporcionada para
    consultas de un solo carácter como 
esta.

  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar)
;

Esta función muestra el indicador especificado al comienzo de una nueva
    línea, y espera a que el usuario escriba un carácter. Cuando el usuario escribe un
    carácter, gl_query_char() lo muestra a la derecha del indicador,
    inicia una nueva línea, y luego devuelve el carácter al programa llamante. El
    valor de retorno de la función es el carácter que fue escrito. Si la lectura
    tuvo que ser abortada por alguna razón, se devuelve EOF en su lugar. En el
    último caso, la aplicación puede llamar a la previamente documentada
    gl_return_status(), para averiguar qué salió mal. Esto podría, por
    ejemplo, haber sido la recepción de una señal, o el temporizador opcional de inactividad
    
activándose.

Si el usuario simplemente presiona intro, el valor del argumento defchar
    se sustituye. Esto significa que cuando el usuario presiona ya sea nueva línea
    o retorno, el carácter especificado en defchar, se muestra después del
    indicador, como si el usuario lo hubiera escrito, así como ser devuelto a la
    aplicación llamante. Si tal reemplazo no es importante, simplemente pase
    '0 como el valor de defchar
.

Si el carácter introducido es un carácter no imprimible, se
    muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y
    los caracteres más allá de 127 se muestran en octal, precedidos por una barra 
invertida.

Al igual que con gl_get_line(), el eco del carácter introducido puede
    ser desactivado usando la función gl_echo_mode()
.

Si el proceso llamante es suspendido mientras espera a que el usuario
    escriba su respuesta, el cursor se mueve a la línea siguiente a la línea del indicador,
    luego cuando el proceso se reanuda, el indicador se vuelve a mostrar, y
    gl_query_char() reanuda la espera de que el usuario escriba un 
carácter.

Tenga en cuenta que en el modo de servidor no bloqueante, (vea gl_io_mode(3)), si una
    línea de entrada incompleta está en proceso de ser leída cuando se llama a
    gl_query_char(), la línea de entrada parcial se descarta, y
    se borra del terminal, antes de que se muestre el nuevo indicador. La siguiente llamada
    a gl_get_line() comenzará as
í a editar una
 nueva línea.



LEYENDO   CARACTERES EN 
BRUTO

Mientras que la función gl_query_char() pide visiblemente al
    usuario un carácter, y muestra lo que escribió, la
    función gl_read_char() lee un carácter de señal del usuario,
    sin escribir nada en el terminal, o perturbar cualquier línea de entrada
    incompleta. Esto significa que puede ser llamada no solo entre
    llamadas a gl_get_line(), sino también desde funciones de retorno de llamada que la
    aplicación ha registrado para ser llamadas por gl_get_li
ne().

  int gl_read_char(GetLine *gl)
;

En caso de éxito, el valor de retorno de gl_read_char() es el
    carácter que fue leído. En caso de fallo, se devuelve EOF, y la
    función gl_return_status() puede ser llamada para averiguar qué fue
    lo que salió mal. Las posibilidades incluyen el temporizador opcional de inactividad activándose, la
    recepción de una señal que está configurada para abortar gl_get_line(), o el bloqueo de
    E/S del terminal, cuando se está en el modo de E/S de servidor no 
bloqueante.

Tenga en cuenta que ciertas teclas del teclado, como las teclas de función, y
    las teclas de cursor, usualmente generan al menos 3 caracteres cada una, por lo que una sola llamada

MOSTRANDO   TEXTO DINÁMICAMENTE


Entre llamadas a gl_get_line(), la función
    gl_display_text() proporciona una forma conveniente de mostrar párrafos
    de texto, justificados a la izquierda y divididos en una o más líneas de la
    terminal según las restricciones del ancho actual de la terminal. Ejemplos
    de uso de esta función se pueden encontrar en los programas de demostración,
    donde se utiliza para mostrar introducciones. En esos ejemplos, también se
    ilustra el uso avanzado de prefijos, sufijos y líneas de relleno opcionales
    para dibujar un cuadro alrededor del texto.


  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string);


Si gl no está conectado actualmente a una terminal, por
    ejemplo, si la salida de un programa que utiliza gl_get_line() se
    está canalizando a otro programa o se está redirigiendo a un archivo, entonces
    se utiliza el valor del parámetro def_width como el ancho de la
    terminal.


El argumento indentation especifica el número de caracteres
    a utilizar para indentar cada línea de salida. El argumento fill_char
    especifica el carácter que se utilizará para realizar esta indentación.


El argumento prefix puede ser NULL, o una cadena para
    colocar al principio de cada nueva línea (después de cualquier indentación).
    De manera similar, el argumento suffix puede ser NULL, o una
    cadena para colocar al final de cada línea. El sufijo se coloca al ras del
    borde derecho de la terminal, y cualquier espacio entre su primer carácter
    y la última palabra de esa línea se rellena con el carácter especificado a
    través del argumento fill_char. Normalmente, el carácter de relleno
    es un espacio.


El argumento start le dice a gl_display_text()
    cuántos caracteres ya se han escrito en la línea actual de la terminal, y por
    lo tanto le indica el índice de la columna inicial del cursor. Dado que el
    valor de retorno de gl_display_text() es el índice de la columna final
    del cursor, al pasar el valor de retorno de una llamada al argumento
    start de la siguiente llamada, se puede componer un párrafo que se
    divide entre más de una cadena llamando a gl_display_text() para cada
    porción sucesiva del párrafo. Tenga en cuenta que se requieren caracteres de
    nueva línea literales al final de cada párrafo para forzar el inicio de una
    nueva línea.


En caso de error, gl_display_text() devuelve -1.






FACILIDADES DE FUNCIONES DE LLAMADA


A menos que se indique lo contrario, las funciones de llamada, como
    las funciones de llamada de completado de tabulación y las funciones de
    llamada de eventos, no deben llamar a ninguna función de este módulo. Las
    siguientes funciones, sin embargo, están diseñadas específicamente para ser
    utilizadas por funciones de llamada.


Llamar a la función gl_replace_prompt() desde una función de
    llamada le dice a gl_get_line() que muestre un prompt diferente cuando
    la función de llamada regrese. Excepto en el modo de servidor no bloqueante,
    no tiene ningún efecto si se usa entre llamadas a gl_get_line(). En
    modo de servidor no bloqueante (ver la página del manual
    gl_io_mode(3), cuando se usa entre dos llamadas a
    gl_get_line() que operan en la misma línea de entrada, la línea de
    entrada actual se redibujará con el nuevo prompt en la siguiente llamada a
    gl_get_line().


  void gl_replace_prompt(GetLine *gl, const char *prompt);






JUEGOS   DE CARACTERES INTERNACIONALES


Desde la versión 1.4.0 de libtecla, gl_get_line() es compatible
    con 8 bits. Esto significa que todos los caracteres de 8 bits que son imprimibles
    en la configuración regional actual del usuario ahora se muestran tal cual y se
    incluyen en la línea de entrada devuelta. Suponiendo que el programa que
    llama contiene correctamente una llamada como la siguiente,


  setlocale(LC_CTYPE, "");


entonces la configuración regional actual se determina por la primera
    de las variables de entorno LC_CTYPE, LC_ALL y LANG, que
    se encuentra que contiene un nombre de configuración regional válido. Si
    ninguna de estas variables está definida, o el programa omite llamar a
    setlocale, entonces se utiliza la configuración regional predeterminada
    C, que es ASCII de 7 bits de EE. UU. En la mayoría de las plataformas
    tipo Unix, puede obtener una lista de las configuraciones regionales
    válidas escribiendo el comando:


  locale -a


en el prompt de la shell. Puede encontrar más documentación sobre cómo
    el usuario puede utilizar esto para ingresar caracteres internacionales en la
    página del manual tecla(7).






SEGURIDAD   DE HILOS


En un programa multihilo, debe usar la versión libtecla_r.a de la
    biblioteca. Esta utiliza versiones reentrantes de las funciones del sistema,
    cuando están disponibles. Desafortunadamente, ni terminfo ni termcap fueron
    diseñados para ser reentrantes, por lo que no puede usar de manera segura las
    funciones del módulo getline en múltiples hilos (puede usar los módulos
    separados de expansión de archivos y completado de palabras en múltiples
    hilos, consulte las páginas del manual correspondientes para obtener
    detalles). Sin embargo, debido al uso de funciones reentrantes POSIX para
    buscar directorios de inicio, etc., es seguro usar este módulo desde un solo
    hilo de un programa multihilo, siempre que sus otros hilos no utilicen
    ninguna función de termcap o terminfo.
