DESCRIPCIÓN

La función gl_get_line() forma parte de la biblioteca tecla (véase la página del manual de libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le solicita una línea de entrada y luego proporciona funciones de edición interactivas, similares a las del shell tcsh de Unix. Además de la edición simple de la línea de comandos, admite la recuperación de líneas de comandos introducidas previamente, la finalización con TAB de nombres de archivos y la expansión de comodines en línea de nombres de archivos. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario se puede encontrar en la página del manual de tecla(7). Esta página del manual se centra en la documentación para programadores interesados en utilizar esta biblioteca en sus aplicaciones.

UN EJEMPLO

Lo siguiente muestra un ejemplo completo de cómo utilizar la función gl_get_line() para obtener entrada del usuario:

  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que el usuario escribió */
    GetLine *gl;   /* El objeto de recursos de gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* del conjunto de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("Escribiste: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
  }

En el ejemplo, primero se crean los recursos necesarios para la función gl_get_line() llamando a new_GetLine(). Esto asigna la memoria utilizada en llamadas posteriores a la función gl_get_line(), incluido el búfer de historial para registrar líneas introducidas previamente. Luego se leen una o más líneas del usuario, hasta que ocurre un error o el usuario escribe exit. Finalmente, los recursos que fueron asignados por new_GetLine() se devuelven al sistema llamando a del_GetLine(). Tenga en cuenta el uso del valor de retorno NULL de del_GetLine() para hacer que gl sea NULL. Esto es una precaución de seguridad. Si el programa intenta posteriormente pasar gl a gl_get_line(), dicha función se quejará y devolverá un error, en lugar de intentar utilizar el objeto de recursos eliminado.

LAS FUNCIONES UTILIZADAS EN EL EJEMPLO

Las descripciones de las funciones utilizadas en el ejemplo son las siguientes:

  GetLine *new_GetLine(size_t linelen, size_t histlen)

Esta función crea los recursos utilizados por la función gl_get_line() y devuelve un puntero opaco al objeto que los contiene. La longitud máxima de una línea de entrada se especifica a través del argumento linelen, y el número de bytes a asignar para almacenar líneas de historial se establece mediante el argumento histlen. Las líneas de historial se almacenan una detrás de otra en un único búfer de este tamaño. Tenga en cuenta que esto significa que el número de líneas de historial que se pueden almacenar en cualquier momento depende de las longitudes de las líneas individuales. Si desea establecer un límite superior en el número de líneas que se pueden almacenar, consulte la función gl_limit_history() descrita más adelante. Si no desea historial en absoluto, especifique histlen como cero, y no se asignará ningún búfer de historial.

En caso de error, se imprime un mensaje en stderr y se devuelve NULL.

  GetLine *del_GetLine(GetLine *gl)

Esta función elimina los recursos que fueron devueltos por una llamada anterior a new_GetLine(). Siempre devuelve NULL (es decir, un objeto eliminado). No hace nada si el argumento gl es NULL.

  char *gl_get_line(GetLine *gl, const char *prompt,
                   const char *start_line, int start_pos);

La función gl_get_line() se puede llamar cualquier número de veces para leer la entrada del usuario. El argumento gl debe haber sido devuelto previamente por una llamada a new_GetLine(). El argumento prompt debe ser una cadena normal terminada en NUL, que especifica el aviso que se presentará al usuario. Por defecto, los avisos se muestran literalmente, pero si se habilitan con la función gl_prompt_style() (ver más adelante), los avisos pueden contener directivas para hacer subrayado, cambiar entre fuentes en negrita o activar y desactivar el resaltado.

Si desea especificar el contenido inicial de la línea, para que el usuario lo edite, pase la cadena deseada a través del argumento start_line. Luego puede especificar en qué carácter de esta línea se posiciona inicialmente el cursor

FUENTES ALTERNATIVAS DE

CONFIGURACIÓN

Como se mencionó anteriormente, de forma predeterminada los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. En algunas aplicaciones, sin embargo, este único medio de configuración es un problema. Esto es particularmente cierto para el software embebido, donde no hay un sistema de archivos del cual leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de asignaciones de teclas para emular una interfaz de teclado heredada. Para atender a tales casos, la siguiente función permite a la aplicación controlar desde dónde se leen la información de

configuración. 
  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file)
;

Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc del usuario, se lean de una, ninguna o varias de estas fuentes: una cadena, un archivo de configuración específico de la aplicación y/o un archivo de configuración específico del usuario. Si esta función se llama antes de la primera llamada a gl_get_line(), el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line() se deshabilita, por lo que toda la configuración debe lograrse utilizando las fuentes de configuración especificadas con esta

función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados entre sí en la cadena por caracteres de salto de línea incrustados. Si app_file != NULL, entonces se interpreta como la ruta de acceso completa de un archivo de configuración específico de la aplicación. Si user_file != NULL, entonces se interpreta como la ruta de acceso completa de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente

llamada, 
  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc")
;

el argumento app_string hace que la aplicación que llama inicie en el modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso de la campana del terminal por parte de la biblioteca. Luego intenta leer comandos de configuración de todo el sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario desde un archivo .teclarc opcional en el directorio de inicio del usuario. Tenga en cuenta que los argumentos se listan en orden ascendente de prioridad, con el contenido de app_string siendo potencialmente sobrescrito por comandos en app_file, y los comandos en app_file potencialmente siendo sobrescritos por comandos en user_file

.

Puede llamar a esta función tantas veces como sea necesario, con resultados acumulativos, pero tenga en cuenta que las copias de cualquier nombre de archivo especificado a través de app_

Argumentos de inicialización y relectura

Los argumentos file y user_file se registran internamente para su uso posterior por la función de enlace de teclas read-init-files, por lo que si planea llamar a esta función varias veces, asegúrese de que la última llamada especifique los nombres de archivo que desea volver a leer cuando el usuario solicite que los archivos de configuración se vuelvan a leer.

Las secuencias de teclas individuales también se pueden enlazar y desenlazar usando la función gl_bind_keyseq().

  int gl_bind_keyseq(GetLine *gl, GlKeyOrigin origin,
                     const char *keyseq,
                     const char *action);

El argumento origin especifica la prioridad del enlace, según para quién se está estableciendo, y debe ser uno de los dos valores siguientes.

  GL_USER_KEY   -   El usuario solicitó este enlace de teclas.
  GL_APP_KEY    -   Este es un enlace predeterminado establecido por la
                    aplicación.

Cuando se han especificado enlaces de usuario y de aplicación para una secuencia de teclas dada, el enlace de usuario tiene prioridad. El enlace de la aplicación se restablece posteriormente si el enlace del usuario se desenlaza más tarde, ya sea a través de otra llamada a esta función o una llamada a gl_configure_getline().

El argumento keyseq especifica la secuencia de teclas a enlazar o desenlazar, y se expresa de la misma manera que en un archivo de configuración de ~/.teclarc. El argumento action debe ser una cadena que contenga el nombre de la acción a la que se enlaza la secuencia de teclas, o debe ser NULL o "" para desenlazar la secuencia de teclas.

COMPLETADO DE PALABRAS PERSONALIZADO

Si en su aplicación desea que la compleción TAB complete otras cosas además de o en lugar de nombres de archivo, puede organizarlo registrando una función de devolución de llamada de compleción alternativa, mediante una llamada a la función gl_customize_completion().

  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn);

El argumento data proporciona una forma para que su aplicación pase información arbitraria específica de la aplicación a la función de devolución de llamada. Esto se pasa a la devolución de llamada cada vez que se llama. Podría, por ejemplo, apuntar a la tabla de símbolos de la que se deben buscar las compleciones posibles. El argumento match_fn especifica la función de devolución de llamada a la que se debe llamar. El tipo de función CplMatchFn se define en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y prototipar funciones de devolución de llamada. La declaración y las responsabilidades de las funciones de devolución de llamada se describen en profundidad en la página man de cpl_complete_word(3).

En resumen, la función de devolución de llamada es responsable de mirar hacia atrás en la línea de entrada, desde el punto en que el usuario presionó TAB, para encontrar el inicio de la palabra que se está completando. Luego, debe buscar compleciones posibles de esta palabra y registrarlas una por una en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion(). Si la función de devolución de llamada desea proporcionar compleción de nombres de archivo además de sus propias compleciones específicas, tiene la opción de llamar a la función de devolución de llamada de compleción de nombres de archivo integrada. Esto también se documenta en la página man de cpl_complete_word(3).

Tenga en cuenta que si desea que gl_get_line() devuelva la línea de entrada actual cuando se realiza una compleción exitosa, puede organizarlo al llamar a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de nueva línea. Si hace esto, la línea de entrada se actualizará para mostrar la compleción, junto con cualquier sufijo de continuación hasta el carácter de nueva línea, luego gl_get_line() devolverá esta línea de entrada.

Si, por alguna razón, su función de devolución de llamada necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto iniciará una nueva línea después de la línea que se está editando actualmente, restablecerá la E/S normal de la terminal y le dirá a gl_get_line() que la línea de entrada deberá redibujarse cuando la devolución de llamada regrese.

AGREGANDO ACCIONES DE COMPLETADO

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de compleción predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que se puedan enlazar diferentes tipos de compleción de palabras a diferentes secuencias de teclas. Esto se logra utilizando la función gl_completion_action().

  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq);

Los argumentos data y match_fn son como se describen en la página man de cpl_complete_word, y especifican la función de devolución de llamada que debe invocarse para identificar las compleciones posibles. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar las compleciones ambiguas posibles, o si simplemente debe mostrar la lista de compleciones posibles sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre por el cual los archivos de configuración y las invocaciones futuras de esta función deben referirse a la acción. Este debe ser el nombre de una acción de compleción existente que se va a cambiar, o un nuevo nombre no utilizado para una nueva acción. Finalmente, el argumento keyseq especifica la secuencia de teclas predeterminada a la que se enlaza la acción. Si esto es NULL, no se enlazará ninguna secuencia de teclas nueva a la acción.

Tenga cuidado, ya que para que el usuario pueda cambiar la secuencia de teclas que se enlaza a las acciones que se instalan de esta manera, cuando llama a gl_completion_action() para instalar una acción determinada por primera vez, debe hacerlo entre la llamada a new_GetLine() y la primera llamada a gl_get_line(). De lo contrario, cuando se lea el archivo de configuración del usuario en la primera llamada a gl_get_line(), el nombre de su acción adicional no se conocerá y cualquier referencia a él en el archivo de configuración generará un error.

Como se discutió para gl_customize_completion(), si su función de devolución de llamada, por alguna razón, necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo.

Aunque las acciones de enlace de teclas integradas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, enlazadas a secuencias de teclas específicas de la aplicación. ARCHIVOS DE HISTORIAL

Para guardar el contenido del búfer de historial antes de salir de su aplicación, y posteriormente restaurarlo cuando la inicie de nuevo, se proporcionan las siguientes funciones.

 int gl_save_history(GetLine *gl, const char *filename,
                     const char *comment, int max_lines);
 int gl_load_history(GetLine *gl, const char *filename,
                     const char *comment);

El argumento filename especifica el nombre que se le dará al archivo de historial al guardar, o el nombre de un archivo de historial existente al cargar. Esto puede contener expresiones de directorio personal y de variables de entorno, como "~/.myapp_history" o "$HOME/.myapp_history".

Junto con cada línea del historial, se registra información adicional sobre ella, como cuándo fue ingresada por el usuario y cuál es su nivel de anidamiento, como un comentario que precede a la línea en el archivo de historial. Escribir esto como un comentario permite que el archivo de historial sirva también como archivo de comandos, en caso de que desee reproducir una sesión completa utilizándolo. Dado que los prefijos de comentario difieren en diferentes lenguajes, el argumento comment se proporciona para especificar el prefijo del comentario. Por ejemplo, si su aplicación fuera un shell de Unix, como el shell de Bourne, especificaría "#" aquí. Sea cual sea el carácter de comentario que elija, debe especificar el mismo prefijo a gl_load_history() que utilizó cuando llamó a gl_save_history() para escribir el archivo de historial.

El argumento max_lines debe ser -1 para especificar que se guarden todas las líneas de la lista de historial, o un número positivo que especifique un límite superior de cuántas de las líneas más recientes deben guardarse.

Ambas funciones devuelven un valor distinto de cero en caso de error, después de escribir un mensaje de error en stderr. Tenga en cuenta que gl_load_history() no considera la inexistencia de un archivo como un error.

MÚLTIPLES LISTAS DE HISTORIAL

Si su aplicación utiliza un único objeto GetLine para ingresar muchos tipos diferentes de líneas de entrada, es posible que desee que gl_get_line() distinga los diferentes tipos de líneas en la lista de historial y solo recupere las líneas que coinciden con el tipo de línea actual. Para admitir este requisito, gl_get_line() marca las líneas que se registran en la lista de historial con un identificador entero elegido por la aplicación. Inicialmente, este identificador se establece en 0 por new_GetLine(), pero se puede cambiar posteriormente llamando a gl_group_history().

  int gl_group_history(GetLine *gl, unsigned id);

El identificador entero id puede ser cualquier número elegido por la aplicación, pero tenga en cuenta que gl_save_history() y gl_load_history() conservan la asociación entre los identificadores y las líneas de entrada históricas entre invocaciones del programa, por lo que debe elegir identificadores fijos para los diferentes tipos de líneas de entrada utilizados por su aplicación.

Cada vez que gl_get_line() agrega una nueva línea de entrada a la lista de historial, se registra el identificador de historial actual con ella, y cuando se le pide que recupere una línea de entrada histórica, solo recupera las líneas que están marcadas con el identificador actual.

                      int all_groups,

Esto muestra el contenido actual de la lista de historial al flujo de salida stdio fp.   %D  -  La fecha en que se ingresó originalmente la

  %N  -  El número secuencial de entrada de la línea en

ARCHIVADO MANUAL DEL HISTORIAL

Por defecto, cada vez que el usuario ingresa una línea, se agrega automáticamente a la lista de historial, justo antes de que gl_get_line() devuelva la línea al llamador. Esto es conveniente para la mayoría de las aplicaciones, pero también hay aplicaciones que necesitan un control más fino sobre lo que se agrega a la lista de historial. En tales casos, la adición automática de las líneas ingresadas a la lista de historial se puede desactivar llamando a la función gl_automatic_history().

  int gl_automatic_history(GetLine *gl, int enable);

Si se llama a esta función con su argumento enable establecido en 0, gl_get_line() no archivará automáticamente las líneas ingresadas posteriormente. El archivado automático se puede habilitar nuevamente más tarde, llamando a esta función de nuevo, con su argumento enable establecido en 1. Mientras el archivado automático del historial está deshabilitado, la aplicación llamante puede usar gl_append_history() para agregar líneas a la lista de historial según sea necesario.

  int gl_append_history(GetLine *gl, const char *line);

El argumento line especifica la línea que se agregará a la lista de historial. Debe ser una cadena normal terminada en ' '. Si esta cadena contiene caracteres de nueva línea, la línea que se archivará en la lista de historial terminará con el primero de ellos. De lo contrario, terminará con el terminador ' '. Si la línea es más larga que la longitud máxima de línea de entrada, que se especificó al llamar a new_GetLine(), cuando la línea se recupere, se truncará a la longitud real de la línea de gl_get_line().

Si tiene éxito, gl_append_history() devuelve 0. De lo contrario, devuelve un valor distinto de cero y establece errno en uno de los siguientes valores.

   EINVAL  -  Uno de los argumentos pasados a
              gl_append_history() era NULL.
   ENOMEM  -  La línea especificada era más larga que el
              tamaño asignado del búfer de historial (como
              se especificó al llamar a new_GetLine()), por lo
              que no se pudo archivar.

Se puede obtener una descripción textual del error opcionalmente llamando a gl_error_message(). Tenga en cuenta que después de un error de este tipo, la lista de historial permanece en un estado válido para recibir nuevas líneas de historial, por lo que hay poco daño en simplemente ignorar el estado de retorno de gl_append_history().

SIGNAL HANDLING

When gl_get_line() is called, it installs signal handlers for a number of signals, including SIGINT, SIGQUIT, SIGTSTP, SIGTTIN, SIGTTOU, SIGINFO, SIGTERM, and SIGWINCH. These handlers are designed to allow gl_get_line() to be interrupted by signals without corrupting its internal state.

When a signal is received while gl_get_line() is executing, the signal handler is invoked. The handler first saves the current state of the GetLine structure, then restores the terminal attributes to their state before gl_get_line() was called. It then reinstalls the application's original signal handlers, and re-sends the signal to the application. This allows the application to handle the signal in the usual way.

If the application's signal handler returns, gl_get_line() re-blocks the signal, restores the terminal attributes, and resumes execution from where it was interrupted. If the signal handler does not return, gl_get_line() will not be called again.

The gl_get_line() function provides a mechanism for handling signals in a safe and robust manner. By saving and restoring the state of the GetLine structure, and by reinstating the application's original signal handlers, gl_get_line() ensures that signals do not corrupt the editing state or interfere with the application's signal handling logic.

When a signal is caught, and the savesigs argument of sigsetjmp() was non-zero, the signal process mask is restored to how it was when sigsetjmp() was called. This ensures that all signals that were blocked before the call to sigsetjmp() are still blocked after the signal is caught. This is the key difference between sigsetjmp() and the older setjmp(), and it makes it possible to avoid signal handling race conditions.

The following steps are executed when a signal is caught:

  1. If the signal handler is configured to do so, the terminal attributes are restored to their state before gl_get_line() was called.
  2. The application's signal handlers are reinstated.
  3. The caught signal is re-sent to the application using the raise() function.
  4. The signal is unblocked, so that the application's signal handler can catch it.
  5. If the application's signal handler returns, the signal is blocked again.
  6. Any changes made to the terminal attributes are undone.
  7. The line is redisplayed, if necessary.
  8. gl_get_line() either resumes reading a character or aborts, depending on the signal configuration.

This process effectively transforms asynchronously delivered signals into synchronously handled events, ensuring that gl_get_line() has complete control over its environment when handling signals.

THE TERMINAL SIZE

On most systems the combination of the TIOCGWINSZ ioctl and the SIGWINCH signal is used to maintain an accurate idea of the terminal size. The terminal size is newly queried every time that gl_get_line() is called and whenever a SIGWINCH signal is received.

On the few systems where this mechanism isn't available, at startup new_GetLine() first looks for the LINES and COLUMNS environment variables. If these aren't found, or they contain unusable values, then if a terminal information database like terminfo or termcap is available, the default size of the terminal is looked up in this database. If this too fails to provide the terminal size, a default size of 80 columns by 24 lines is used.

Even on systems that do support ioctl(TIOCGWINSZ), if the terminal is on the other end of a serial line, the terminal driver generally has no way of detecting when a resize occurs or of querying what the current size is. In such cases no SIGWINCH is sent to the process, and the dimensions returned by ioctl(TIOCGWINSZ) aren't correct. The only way to handle such instances is to provide a way for the user to enter a command that tells the remote system what the new size is. This command would then call the gl_set_term_size() function to tell gl_get_line() about the change in size.

  int gl_set_term_size(GetLine *gl, int ncolumn, int nline);

The ncolumn and nline arguments are used to specify the new dimensions of the terminal, and must not be less than 1. On systems that do support ioctl(TIOCGWINSZ), this function first calls ioctl(TIOCSWINSZ) to tell the terminal driver about the change in size. In non-blocking server-I/O mode, if a line is currently being input, the input line is then redrawn to accomodate the changed size. Finally the new values are recorded in gl for future use by gl_get_line().

The gl_terminal_size() function allows you to query the current size of the terminal, and install an alternate fallback size for cases where the size isn't available. Beware that the terminal size won't be available if reading from a pipe or a file, so the default values can be important even on systems that do support ways of finding out the terminal size.

  typedef struct {
    int nline;        /* The terminal has nline lines */
    int ncolumn;      /* The terminal has ncolumn columns */
  } GlTerminalSize;
  GlTerminalSize gl_terminal_size(GetLine *gl,
                                  int def_ncolumn,
                                  int def_nline);

This function first updates gl_get_line()'s fallback terminal dimensions, then records its findings in the return value.

The def_ncolumn and def_nline specify the default number of terminal columns and lines to use if the terminal size can't be determined via ioctl(TIOCGWINSZ) or environment variables.

HIDING WHAT YOU TYPE

When entering sensitive information, such as passwords, it is best not to have the text that you are entering echoed on the terminal. Furthermore, such text should not be recorded in the history list, since somebody finding your terminal unattended could then recall it, or somebody snooping through your directories could see it in your history file. With this in mind, the gl_echo_mode() function allows you to toggle on and off the display and archival of any text that is subsequently entered in calls to gl_get_line().

  int gl_echo_mode(GetLine *gl, int enable);

The enable argument specifies whether entered text should be visible or not. If it is 0, then subsequently entered lines will not be visible on the terminal, and will not be recorded in the history list. If it is 1, then subsequent input lines will be displayed as they are entered, and provided that history hasn't been turned off via a call to gl_toggle_history(), then they will also be archived in the history list. Finally, if the enable argument is -1, then the echoing mode is left unchanged, which allows you to non-destructively query the current setting via the return value. In all cases, the return value of the function is 0 if echoing was disabled before the function was called, and 1 if it was enabled.

When echoing is turned off, note that although tab completion will invisibly complete your prefix as far as possible, ambiguous completions will not be displayed.

SINGLE CHARACTER QUERIES

Using gl_get_line() to query the user for a single character reply, is inconvenient for the user, since they must hit the enter or return key before the character that they typed is returned to the program. Thus the gl_query_char() function has been provided for single character queries like this.

  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar);

This function displays the specified prompt at the start of a new line, and waits for the user to type a character. When the user types a character, gl_query_char() displays it to the right of the prompt, starts a newline, then returns the character to the calling program. The return value of the function is the character that was typed. If the read had to be aborted for some reason, EOF is returned instead. In the latter case, the application can call the previously documented gl_return_status(), to find out what went wrong. This could, for example, have been the reception of a signal, or the optional inactivity timer going off.

If the user simply hits enter, the value of the defchar argument is substituted. This means that when the user hits either newline or return, the character specified in defchar, is displayed after the prompt, as though the user had typed it, as well as being returned to the calling application. If such a replacement is not important, simply pass '0 as the value of defchar.

If the entered character is an unprintable character, it is displayed symbolically. For example, control-A is displayed as ^A, and characters beyond 127 are displayed in octal, preceded by a backslash.

As with gl_get_line(), echoing of the entered character can be disabled using the gl_echo_mode() function.

If the calling process is suspended while waiting for the user to type their response, the cursor is moved to the line following the prompt line, then when the process resumes, the prompt is redisplayed, and gl_query_char() resumes waiting for the user to type a character.

Note that in non-blocking server mode, (see gl_io_mode(3)), if an incomplete input line is in the process of being read when gl_query_char() is called, the partial input line is discarded, and erased from the terminal, before the new prompt is displayed. The next call to gl_get_line() will thus start editing a new line.

READING RAW CHARACTERS

Whereas the gl_query_char() function visibly prompts the user for a character, and displays what they typed, the gl_read_char() function reads a signal character from the user, without writing anything to the terminal, or perturbing any incompletely entered input line. This means that it can be called not only from between calls to gl_get_line(), but also from callback functions that the application has registered to be called by gl_get_line().

  int gl_read_char(GetLine *gl);

On success, the return value of gl_read_char() is the character that was read. On failure, EOF is returned, and the gl_return_status() function can be called to find out what went wrong. Possibilities include the optional inactivity timer going off, the receipt of a signal that is configured to abort gl_get_line(), or terminal I/O blocking, when in non-blocking server-I/O mode.
