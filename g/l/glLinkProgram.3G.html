DESCRIPCIÓ

N

glLinkProgram vincula el objeto de programa especificado por program. Si hay objetos de shader de tipo GL_VERTEX_SHADER adjuntos a program, se utilizarán para crear un ejecutable que se ejecutará en el procesador de vértices programable. Si hay objetos de shader de tipo GL_GEOMETRY_SHADER adjuntos a program, se utilizarán para crear un ejecutable que se ejecutará en el procesador de geometría programable. Si hay objetos de shader de tipo GL_FRAGMENT_SHADER adjuntos a program, se utilizarán para crear un ejecutable que se ejecutará en el procesador de fragmentos

programable.

El estado de la operación de vinculación se almacenará como parte del estado del objeto de programa. Este valor se establecerá a GL_TRUE si el objeto de programa se vinculó sin errores y está listo para su uso, y a GL_FALSE en caso contrario. Se puede consultar llamando a glGetProgram() con los argumentos program y GL_LINK_STATUS

.

Como resultado de una operación de vinculación exitosa, todas las variables uniformes definidas por el usuario activas que pertenezcan a program se inicializarán a 0, y a cada una de las variables uniformes activas del objeto de programa se le asignará una ubicación que se puede consultar llamando a glGetUniformLocation(). Además, cualquier variable de atributo definida por el usuario activa que no haya sido vinculada a un índice de atributo de vértice genérico será vinculada a uno en este

momento.

La vinculación de un objeto de programa puede fallar por varias razones, tal como se especifica en la Especificación del Lenguaje de Sombreado de OpenGL. A continuación se enumeran algunas de las condiciones que causarán un error de

Cuando un objeto de programa se ha vinculado correctamente, el objeto de programa puede formar parte del estado actual llamando a glUseProgram(). Independientemente de si la operación de vinculación fue exitosa o no, el registro de información del objeto de programa será sobrescrito. El registro de información se puede recuperar llamando a glGetProgramInf

oLog().

glLinkProgram también instalará los ejecutables generados como parte del estado de renderizado actual si la operación de vinculación fue exitosa y el objeto de programa especificado ya está actualmente en uso como resultado de una llamada previa a glUseProgram(). Si el objeto de programa actualmente en uso se vincula de nuevo sin éxito, su estado de vinculación se establecerá a GL_FALSE , pero los ejecutables y el estado asociado permanecerán como parte del estado actual hasta una llamada posterior a glUseProgram que lo quite del uso. Una vez que se ha quitado del uso, no puede formar parte del estado actual hasta que se haya vinculado de nuevo

correctamente.

Si program contiene objetos de shader de tipo GL_VERTEX_SHADER, y opcionalmente de tipo GL_GEOMETRY_SHADER, pero no contiene objetos de shader de tipo GL_FRAGMENT_SHADER, el ejecutable del shader de vértices se instalará en el procesador de vértices programable, el ejecutable del shader de geometría, si está presente, se instalará en el procesador de geometría programable, pero no se instalará ningún ejecutable en el procesador de fragmentos. Los resultados de rasterizar primitivas con un programa así serán

indefinidos.

El registro de información del objeto de programa se actualiza y el programa se genera en el momento de la operación de vinculación. Después de la operación de vincul

ación, las aplicaciones son libres de modificar los objetos de shader adjuntos, compilar los objetos de shader adjuntos, desvincular objetos de shader, eliminar objetos de
shader y adjuntar objetos de shader adicionales. Ninguna de estas operaciones afecta al registro de información o al programa que forma parte del objeto de programa.

NAME

glLinkProgram

links a program object

C SPECIFICATION

void glLinkProgram(GLuint program);

PARAMETERS

program
Specifies the handle of the program object whose associated glDeleteProgram, glUseProgram, and glUniform commands are affected by the linking operation.

DESCRIPTION

glLinkProgram links the *program* object. The linking operation associates the individual glCreateShader() objects that have been attached to *program* using glAttachShader() and reorganizes the intermediate representation of the calling environment into a usable binary representation.

Linking is a potentially time-consuming operation. The results of the link operation can be queried using glGetProgram() with arguments program and GL_LINK_STATUS.

If the link operation fails, the program object is left untouched. The reason for failure can be queried using glGetProgramInfoLog() with argument program.

If the link operation succeeds, the program object is updated to reflect the results of the link. Uniforms which were present in the program object prior to the link operation are preserved. However, any uniforms that are not explicitly declared in the shader source code attached to the program object may be removed. Any attributes which were specified using glBindAttribLocation() prior to the link operation are preserved.

If the link operation fails, the state of the program object remains unchanged from before the link operation.

A program object for which the link operation has not yet been attempted or completed is considered to be in an unlinked state. A program object can be linked multiple times. If a program object is linked more than once, all previous information about the program object is discarded, and the program object is reset to the unlinked state before the new link operation begins.

The default fragment shader is equivalent to a fragment shader that outputs a single, hardcoded, `(1, 1, 1, 1)` RGBA value. If a program object contains no fragment shader, the default fragment shader is used during the linking process. If a program object contains no vertex shader, the default vertex shader is used during the linking process.

The default vertex shader is equivalent to a vertex shader that simply passes the input vertex attributes through to the output vertex attributes of the same name without modification.

If the link operation fails, the program object remains in its previous state. If the program object was previously linked successfully, it remains valid and usable. If the program object was previously unlinked, it remains unlinked.

If the link operation succeeds, the program object is updated to reflect the results of the link. Uniforms which were present in the program object prior to the link operation are preserved. However, any uniforms that are not explicitly declared in the shader source code attached to the program object may be removed. Any attributes which were specified using glBindAttribLocation() prior to the link operation are preserved.

After a successful link operation, glUseProgram can be invoked to make the linked program object part of the current OpenGL state. When a program object is part of the current state, the vertices processed by OpenGL are processed by the vertex shader, and the fragments generated by the vertex shader are processed by the fragment shader.

NOTES

The behavior of glLinkProgram is undefined if any of the shader objects attached to *program* have not been compiled or if they are not compiled successfully. Use glCompileShader() to compile each shader object, and query the compile status using glGetShader() and glGetShaderInfoLog() before linking.

If program is not the name of a program object, the behavior is undefined.

glLinkProgram also compiles any attached shader objects that have not been compiled.

ERRORS

GL_INVALID_VALUE is generated if *program* does not identify a value returned by calling glCreateProgram.

glGetProgramInfoLog() with argument program

glGetUniform() with argument program and a uniform variable location
