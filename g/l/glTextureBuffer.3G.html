Cuando un objeto de búfer se adjunta a una textura de búfer, el almacén de datos del objeto de búfer se toma como el arreglo de texels de la textura. El número de texels en el arreglo de texels de la textura de búfer viene dado por $$ \left\lfloor { size \over { components \times sizeof(base\_type) } } \right\rfloor $$ donde $size$ es el tamaño del objeto de búfer en unidades básicas de máquina (el valor de GL_BUFFER_SIZE para buffer), y $components$ y $base\_type$ son el número de elementos y el tipo de datos base para los elementos, como se especifica en la tabla anterior. El número de texels en el arreglo de texels se limita entonces al valor del límite dependiente de la implementación GL_MAX_TEXTURE_BUFFER_SIZE. Cuando se accede a una textura de búfer en un shader, los resultados de una obtención de texel son indefinidos si la coordenada de texel especificada es negativa, o mayor o igual que el número limitado de texels en el arreglo de texels.

ERRORES

GL_INVALID_ENUM se genera por glTexBuffer si target no es GL_TEXTURE_BUFFER.

GL_INVALID_OPERATION se genera por glTextureBuffer si texture no es el nombre de un objeto de textura existente.

GL_INVALID_ENUM se genera por glTextureBuffer si el destino efectivo de texture no es GL_TEXTURE_BUFFER.

GL_INVALID_ENUM se genera si internalformat no es uno de los formatos internos dimensionados descritos anteriormente.

GL_INVALID_OPERATION se genera si buffer no es cero y no es el nombre de un objeto de búfer existente.

OBTENCIONES ASOCIADAS

glGet() con el argumento GL_MAX_TEXTURE_BUFFER_SIZE

glGet() con el argumento GL_TEXTURE_BINDING_BUFFER

glGetTexLevelParameter() con el argumento GL_TEXTURE_BUFFER_DATA_STORE_BINDING
