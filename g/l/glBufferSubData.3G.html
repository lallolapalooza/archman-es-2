GLBUFFERSUBDATA(3G) [FIXME: manual] GLBUFFERSUBDATA(3G)

NOMBRE

glBufferSubData, glNamedBufferSubData - actualiza un subconjunto del almacén de datos de un objeto buffer

ESPECIFICACIÓN EN C

void glBufferSubData(GLenumtarget, GLintptroffset, GLsizeiptrsize, const void *data);

void glNamedBufferSubData(GLuintbuffer, GLintptroffset, GLsizeiptrsize, const void *data);

PARÁMETROS

target

Especifica el objetivo al que está vinculado el objeto buffer para glBufferSubData, que debe ser uno de los objetivos de vinculación de buffers de la siguiente tabla:
Objetivo de vinculación del buffer Propósito
GL_ARRAY_BUFFER Atributos de vértices
GL_ATOMIC_COUNTER_BUFFER Almacenamiento de contadores atómicos
GL_COPY_READ_BUFFER Fuente de copia de buffer
GL_COPY_WRITE_BUFFER Destino de copia de buffer
GL_DISPATCH_INDIRECT_BUFFER Comandos de despacho de cómputo indirecto
GL_DRAW_INDIRECT_BUFFER Argumentos de comandos indirectos
GL_ELEMENT_ARRAY_BUFFER Índices de arrays de vértices
GL_PIXEL_PACK_BUFFER Objetivo de lectura de píxeles
GL_PIXEL_UNPACK_BUFFER Fuente de datos de textura
GL_QUERY_BUFFER Buffer de resultados de consultas
GL_SHADER_STORAGE_BUFFER Almacenamiento de lectura-escritura para shaders
GL_TEXTURE_BUFFER Buffer de datos de textura
GL_TRANSFORM_FEEDBACK_BUFFER Buffer de transform feedback
GL_UNIFORM_BUFFER Almacenamiento de bloques uniformes

buffer

Especifica el nombre del objeto buffer para glNamedBufferSubData.

offset

Especifica el desplazamiento dentro del almacén de datos del objeto buffer donde comenzará el reemplazo de datos, medido en bytes.

size

Especifica el tamaño en bytes de la región del almacén de datos que se está reemplazando.

data

Especifica un puntero a los nuevos datos que serán copiados en el almacén de datos.

DESCRIPCIÓN

glBufferSubData y glNamedBufferSubData redefinen parte o la totalidad del almacén de datos del objeto buffer especificado. Los datos que comienzan en el desplazamiento de byte offset y se extienden por size bytes son copiados al almacén de datos desde la memoria apuntada por data. offset y size deben definir un rango que se encuentre completamente dentro del almacén de datos del objeto buffer.

NOTAS

Al reemplazar todo el almacén de datos, considere usar glBufferSubData en lugar de recrear completamente el almacén de datos con glBufferData. Esto evita el costo de reasignar el almacén de datos.

Considere usar múltiples objetos buffer para evitar bloquear el pipeline de renderizado durante las actualizaciones del almacén de datos. Si algún renderizado en el pipeline hace referencia a datos en el objeto buffer que está siendo actualizado por glBufferSubData, especialmente desde la región específica que se está actualizando, ese renderizado debe drenarse del pipeline antes de que el almacén de datos pueda ser actualizado.

Los clientes deben alinear los elementos de datos de manera consistente con los requisitos de la plataforma del cliente, con un requisito adicional de nivel base de que un desplazamiento dentro de un buffer hacia un dato que comprende $N$ bytes debe ser un múltiplo de $N$.

El objetivo GL_ATOMIC_COUNTER_BUFFER está disponible solo si la versión de GL es 4.2 o superior.

Los objetivos GL_DISPATCH_INDIRECT_BUFFER y GL_SHADER_STORAGE_BUFFER están disponibles solo si la versión de GL es 4.3 o superior.

El objetivo GL_QUERY_BUFFER está disponible solo si la versión de GL es 4.4 o superior.

ERRORES

GL_INVALID_ENUM es generado por glBufferSubData si target no es uno de los objetivos de buffer aceptados.

GL_INVALID_OPERATION es generado por glBufferSubData si cero está vinculado a target.

GL_INVALID_OPERATION es generado por glNamedBufferSubData si buffer no es el nombre de un objeto buffer existente.

GL_INVALID_VALUE es generado si offset o size es negativo, o si $offset + size$ es mayor que el valor de GL_BUFFER_SIZE para el objeto buffer especificado.

GL_INVALID_OPERATION es generado si alguna parte del rango especificado del objeto buffer está mapeada con glMapBufferRange() o glMapBuffer(), a menos que haya sido mapeada con el bit GL_MAP_PERSISTENT_BIT establecido en los flags de acceso glMapBufferRange access .

GL_INVALID_OPERATION es generado si el valor del flag GL_BUFFER_IMMUTABLE_STORAGE del objeto buffer es GL_TRUE y el valor de GL_BUFFER_STORAGE_FLAGS para el objeto buffer no tiene el bit GL_DYNAMIC_STORAGE_BIT establecido.
