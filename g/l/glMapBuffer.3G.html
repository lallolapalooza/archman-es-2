glMapBuffer(3G)

Paquete: opengl-man-pages

GLMAPBUFFER(3G) [FIXME: manual] GLMAPBUFFER(3G)

NOMBRE

glMapBuffer, glMapNamedBuffer - mapear el espacio de direcciones del cliente de todo el almacenamiento de datos de un objeto de búfer

ESPECIFICACIÓN C

void *glMapBuffer(GLenum target, GLenum access);

void *glMapNamedBuffer(GLuint buffer, GLenum access);

PARÁMETROS

target

Especifica el destino al que está enlazado el objeto de búfer para glMapBuffer, que debe ser uno de los destinos de enlace de búfer en la siguiente tabla:
Destino de enlace de búfer Propósito
GL_ARRAY_BUFFER Atributos de vértice
GL_ATOMIC_COUNTER_BUFFER Almacenamiento de contadores atómicos
GL_COPY_READ_BUFFER Fuente de copia de búfer
GL_COPY_WRITE_BUFFER Destino de copia de búfer
GL_DISPATCH_INDIRECT_BUFFER Comandos indirectos de cómputo de dispatch
GL_DRAW_INDIRECT_BUFFER Argumentos de comandos indirectos
GL_ELEMENT_ARRAY_BUFFER Índices de array de vértices
GL_PIXEL_PACK_BUFFER Destino de lectura de píxeles
GL_PIXEL_UNPACK_BUFFER Fuente de datos de textura
GL_QUERY_BUFFER Búfer de resultados de consulta
GL_SHADER_STORAGE_BUFFER Almacenamiento de lectura/escritura para shaders
GL_TEXTURE_BUFFER Búfer de datos de textura
GL_TRANSFORM_FEEDBACK_BUFFER Búfer de feedback de transformación
GL_UNIFORM_BUFFER Almacenamiento de bloques uniformes

buffer

Especifica el nombre del objeto de búfer para glMapNamedBuffer.

access

Especifica la política de acceso para glMapBuffer y glMapNamedBuffer, indicando si será posible leer, escribir, o leer y escribir en el almacenamiento de datos mapeado del objeto de búfer. La constante simbólica debe ser GL_READ_ONLY, GL_WRITE_ONLY, o GL_READ_WRITE.

DESCRIPCIÓN

glMapBuffer y glMapNamedBuffer mapean todo el almacenamiento de datos de un objeto de búfer especificado al espacio de direcciones del cliente. Los datos pueden ser leídos y/o escritos directamente en relación con el puntero devuelto, dependiendo de la política de access especificada.

Se devuelve un puntero al principio del rango mapeado una vez que todas las operaciones pendientes en ese objeto de búfer han completado, y puede ser utilizado para modificar y/o consultar el rango correspondiente del almacenamiento de datos de acuerdo con el valor de access:

•GL_READ_ONLY indica que el puntero devuelto puede ser utilizado para leer los datos del objeto de búfer.
•GL_WRITE_ONLY indica que el puntero devuelto puede ser utilizado para modificar los datos del objeto de búfer.
•GL_READ_WRITE indica que el puntero devuelto puede ser utilizado para leer y modificar los datos del objeto de búfer.

Si se genera un error, se devuelve un puntero NULL.

Si no ocurre ningún error, el puntero devuelto reflejará una asignación alineada al valor de las unidades básicas de máquina de GL_MIN_MAP_BUFFER_ALIGNMENT.

Los valores de puntero devueltos no pueden ser pasados como parámetros a comandos de GL. Por ejemplo, no pueden ser utilizados para especificar punteros de array, ni para especificar o consultar datos de imagen de píxeles o texturas; tales acciones producen resultados indefinidos, aunque las implementaciones pueden no comprobar este tipo de comportamiento por razones de rendimiento.

No se genera ningún error de GL si el puntero devuelto se accede de una manera inconsistente con access (por ejemplo, usarlo para leer de un mapeo realizado con access GL_WRITE_ONLY o escribir en un mapeo realizado con access GL_READ_ONLY), pero el resultado es indefinido y pueden ocurrir errores del sistema (incluyendo posiblemente la terminación del programa).

Los mapeos a los almacenes de datos de los objetos de búfer pueden tener características de rendimiento no estándar. Por ejemplo, dichos mapeos pueden ser marcados como regiones de memoria no cacheadas, y en tales casos leer de ellas puede ser muy lento. Para asegurar un rendimiento óptimo, el cliente debe usar el mapeo de una manera consistente con los valores de GL_BUFFER_USAGE para el objeto de búfer y de access. Usar un mapeo de una manera inconsistente con estos valores es probable que sea múltiples órdenes de magnitud más lento que usar memoria normal.

NOTAS

La alineación del puntero devuelto solo está garantizada si la versión de GL es 4.2 o superior. Además, el destino GL_ATOMIC_COUNTER_BUFFER solo se acepta si la versión de GL es 4.2 o superior.

Los destinos GL_DISPATCH_INDIRECT_BUFFER y GL_SHADER_STORAGE_BUFFER solo están disponibles si la versión de GL es 4.3 o superior.

El destino GL_QUERY_BUFFER solo está disponible si la versión de GL es 4.4 o superior.

ERRORES

GL_INVALID_ENUM es generado por glMapBuffer si target no es uno de los destinos de enlace de búfer listados anteriormente.

GL_INVALID_OPERATION es generado por glMapBuffer si cero está enlazado a target.

GL_INVALID_OPERATION es generado por glMapNamedBuffer si buffer no es el nombre de un objeto de búfer existente.

GL_INVALID_ENUM es generado si access no es GL_READ_ONLY, GL_WRITE_ONLY, o GL_READ_WRITE.

GL_OUT_OF_MEMORY es generado si el GL no puede mapear el almacenamiento de datos del objeto de búfer. Esto puede ocurrir por una variedad de razones específicas del sistema, como la ausencia de memoria virtual restante suficiente.

GL_INVALID_OPERATION es generado si el objeto de búfer está en estado mapeado.

GETS ASOCIADOS

glGetBufferPointerv() con el argumento GL_BUFFER_MAP_POINTER

glGetBufferParameter() con el argumento GL_BUFFER_MAPPED, GL_BUFFER_ACCESS, o GL_BUFFER_USAGE

glGet() con pname GL_MIN_MAP_BUFFER_ALIGNMENT. El valor debe ser una potencia de dos que sea al menos 64.
