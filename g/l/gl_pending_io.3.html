DESCRIPCIÓ

N

La función gl_get_line(), que se documenta por separado en la página del manual gl_get_line(3), admite dos modos de E/S diferentes. Estos se seleccionan llamando a la función gl_io_mode()

. 
  int gl_io_mode(GetLine *gl, GlIOMode mode)
;

El argumento mode de esta función especifica el nuevo modo de E/S, y debe ser uno de los

siguientes. 
  GL_NORMAL_MODE   -  Selecciona el modo de E/S bloqueante normal.
                      En este modo gl_get_line()
                      no retorna hasta que ocurre un error
                      o el usuario termina de introducir una
                      nueva línea. Este modo es el foco de
                      la página del manual gl_get_line(3).
  GL_SERVER_MODE   -  Selecciona el modo de E/S de servidor no bloqueante.
                      En este modo, ya que se utiliza E/S de terminal
                      no bloqueante, la introducción de cada nueva
                      línea de entrada normalmente requiere muchas
                      llamadas a gl_get_line() desde
                      un bucle de eventos externo impulsado por E/S.
                      Este modo es el foco de esta página
                      del
manual.

Los objetos GetLine recién creados comienzan en modo de E/S normal, por lo que para cambiar al modo de servidor no bloqueante se requiere una llamada inicial a gl_io_

mode
().

MODO DE E/S DE

SERVIDOR

En el modo de E/S de servidor no bloqueante, la aplicación debe tener un bucle de eventos que llame a gl_get_line() siempre que el descriptor de archivo del terminal pueda realizar el tipo de E/S que gl_get_line() está esperando. Para determinar qué tipo de E/S gl_get_line() está esperando, la aplicación llama a la función gl_pending_io()

. 
  GlPendingIO gl_pending_io(GetLine *gl)
;

El valor de retorno de esta función es uno de los dos valores enumerados

siguientes. 
  GLP_READ    -  gl_get_line() está esperando para escribir un
                 carácter en el terminal.
  GLP_WRITE   -  gl_get_line() está esperando para leer un
                 carácter del
teclado.

Si la aplicación está utilizando ya sea la select() o la llamada al sistema poll() para vigilar la E/S en un grupo de descriptores de archivo, entonces debería llamar a la función gl_pending_io() antes de cada llamada a estas funciones para ver qué dirección de E/S debería decirles que vigilen, y configurar sus argumentos en consecuencia. En el caso de la llamada al sistema select(), esto significa usar la macro FD_SET() para añadir el descriptor de archivo del terminal ya sea al conjunto de descriptores de archivo a vigilar por legibilidad, o al conjunto a vigilar por

escribibilidad.

Como en el modo de E/S normal, el valor de retorno de gl_get_line() es ya sea un puntero a una línea de entrada completada, o NULL. Sin embargo, mientras que en el modo de E/S normal un valor de retorno NULL siempre significa que ocurrió un error, en el modo de servidor no bloqueante, NULL también se retorna cuando gl_get_line() no puede leer o escribir en el terminal sin bloquearse. Así que en el modo de servidor no bloqueante, para determinar cuándo un valor de retorno NULL significa que ocurrió un error o no, es necesario llamar a la función gl_return_status(). Si esta función retorna el valor enumerado GLR_BLOCKED, como se documenta en la página del manual gl_get_line(3), esto significa que gl_get_line() está esperando E/S, y no ha ocurrido ningún

error.

Cuando gl_get_line() retorna NULL y gl_return_status() indica que esto se debe a E/S de terminal bloqueada, la aplicación debería llamar a gl_get_line() de nuevo cuando el tipo de E/S reportado por gl_pending_io() se vuelva posible. Los argumentos prompt, start_line y start_pos de gl_get_line() serán ignorados en estas llamadas. Si necesita cambiar el prompt de la línea que se está editando actualmente, entonces puede llamar a la función gl_replace_prompt() (documentada en la página del manual gl_get_line(3)) entre llamadas a gl_get_

lin
e().

RENUNCIANDO AL

TERMINAL

Una complicación única del modo de servidor no bloqueante es que requiere que el terminal se deje en modo crudo entre llamadas a gl_get_line(). Si no fuera el caso, el bucle de eventos externo no sería capaz de detectar pulsaciones de teclas individuales, y la edición de línea básica implementada por el controlador del terminal entraría en conflicto con la edición proporcionada por gl_get_line(). Lo que esto significa es que cada vez que el terminal necesita ser usado para otras cosas que no sean introducir una nueva línea de entrada con gl_get_line(), necesita ser restaurado a un estado utilizable. En particular, siempre que el proceso sea suspendido o terminado, el terminal debe ser devuelto a un estado normal. Si esto no se hace, entonces dependiendo de las características del shell que se usó para invocar el programa, el usuario puede terminar con un terminal colgado. Para este fin, la función gl_normal_io() está provista para cambiar el terminal de vuelta al estado en el que estaba cuando se estableció el modo crudo por última

vez. 
  int gl_normal_io(GetLine *gl)
;

Lo que hace esta función es primero vaciar cualquier salida pendiente hacia el terminal, luego mover el cursor al inicio de la línea del terminal que sigue al final de la línea de entrada introducida incompletamente. En este punto es seguro suspender o terminar el proceso, y es seguro para la aplicación leer y escribir en el terminal. Para reanudar la introducción de la línea de entrada, la aplicación debería llamar a la función gl_raw_io()

. 
  int gl_raw_io(GetLine *gl)
;

Esta función inicia una nueva línea, vuelve a mostrar la línea de entrada parcialmente completada (si la hay), restaura la posición del cursor dentro de esta línea a donde estaba cuando se llamó a gl_normal_io(), luego cambia de vuelta al modo de terminal crudo, no bloqueante, listo para continuar la introducción de la línea de entrada cuando gl_get_line() sea llamada la próxima

vez.

Nótese que en el modo de servidor no bloqueante, si gl_get_line() es llamada después de una llamada a gl_normal_io(), sin una llamada intermedia a gl_raw_io(), gl_get_line() llamará a gl_raw_mode() por sí misma, y el terminal permanecerá en este modo cuando gl_get_line

() re
torne.

MANEJO DE

SEÑALES

En la sección anterior se señaló que en el modo de servidor no bloqueante, el terminal debe ser restaurado a un estado razonable siempre que se reciba una señal que suspenda o termine el proceso. En el modo de E/S normal, esto se hace por usted por gl_get_line(), pero en el modo de servidor no bloqueante, ya que el terminal se deja en modo crudo entre llamadas a gl_get_line(), este manejo de señales tiene que ser hecho por la aplicación. Dado que hay muchas señales que pueden suspender o terminar un proceso, así como otras señales que son importantes para gl_get_line(), como la señal SIGWINCH, que le dice cuándo ha cambiado el tamaño del terminal, la función gl_tty_signals() está provista para instalar manejadores de señales para todas las señales

pertinentes. 
  int gl_tty_signals(void (*term_handler)(int),
                     void (*susp_handler)(int),
                     void (*cont_handler)(int),
                     void (*size_handler)(int))
;

siguientes. 
  term_handler  -  Este es el manejador de señales que debe ser
                   usado para atrapar señales que por defecto
                   terminan cualquier proceso que las reciba
                   (ej. SIGINT o SIGTERM).
  susp_handler  -  Este es el manejador de señales que debe ser
                   usado para atrapar señales que por defecto
                   suspenden cualquier proceso que las reciba,
                   (ej. SIGTSTP o SIGTTOU).

                   par l'utilisateur (ex. SIGWINCH).

ABORTAR LA ENTRADA DE

LÍNEA

A menudo, en lugar de permitir que termine el proceso, las aplicaciones responden a la señal de interrupción de usuario SIGINT abortando la línea de entrada actual. La forma de hacer esto en modo de E/S de servidor no bloqueante es no llamar a gl_handle_signal() cuando se captura esta señal, sino en su lugar llamar a gl_abandon_l

ine(). 
  void gl_abandon_line(GetLine *gl)
;

Esta función hace que cuando se llame a gl_get_line() la próxima vez, primero vuelque cualquier salida pendiente a la terminal, luego descarte la línea de entrada actual, em

ita un nuevo prompt en la siguiente línea y, finalmente, comience
a aceptar la entrada de una nueva línea de entrada del usuario.

FUNCIONES SEGURAS PARA

SEÑALES

Si se siguen ciertas reglas, las siguientes funciones pueden haber sido escritas para poder llamarse de forma segura desde manejadores de señales. No se deben llamar desde manejadores de señales otras funciones de esta

biblioteca. 
  gl_normal_io()
  gl_raw_io()
  gl_handle_signal()
  gl_abandon_line(
)

Para que esto sea cierto, todos los manejadores de señales que llamen a estas funciones deben estar registrados de tal manera que solo una instancia de cualquiera de ellas pueda estar en ejecución a la vez. La forma de hacer esto es usar la función POSIX sigaction() para registrar todos los manejadores de señales y, al hacer esto, usar el miembro sa_mask de la estructura sigaction correspondiente, para indicar que todas las señales cuyos manejadores invocan las funciones anteriores, deben bloquearse cuando se esté manejando la señal actual. Esto evita que dos manejadores de señales operen sobre un objeto GetLine al mismo

tiempo.

Para evitar que los manejadores de señales accedan a un objeto GetLine mientras gl_get_line() o cualquiera de sus funciones públicas asociadas están operando sobre él, todas las funciones públicas asociadas con gl_get_line(), incluyendo gl_get_line() en sí misma, bloquean temporalmente la entrega de señales cuando están accediendo a objetos GetLine. Tenga en cuenta que las únicas señales que bloquean son las señales que gl_get_line() está configurada actualmente para capturar, así que asegúrese de que si llama a alguna de las funciones anteriores desde manejadores de señales, las señales a las que están asignados estos manejadores estén configuradas para ser capturadas por gl_get_line() (vea gl_trap_s

ignal
()).

USAR TEMPORIZIZADORES PARA

SONDEAR

Si en lugar de usar select() o poll() para esperar la E/S, su aplicación solo necesita salir de gl_get_line() periódicamente para hacer brevemente otra cosa antes de volver a aceptar la entrada del usuario, esto se puede hacer en modo de servidor no bloqueante usando la función gl_inactivity_timeout() (vea gl_get_line(3)), para especificar que una función de retorno de llamada que retorne GLTO_CONTINUE debe ser llamada siempre que gl_get_line() haya estado esperando E/S durante más de una cantidad de tiempo

especificada.

Cuando se activa esta función de retorno de llamada, gl_get_line() retornará NULL, y una llamada posterior a gl_return_status() retornará GLR_BLOCKED

.

Tenga en cuenta que gl_get_line() no retornará hasta que el usuario no haya escrito una tecla durante el intervalo especificado, así que si el intervalo es largo, y el usuario sigue escribiendo, gl_get_line() puede no retornar durante un tiempo. En otras pala

bras, no hay garantía de que reto
rne en el tiempo especificado.
