DESCRIPCIÓ

N

glBufferStorage y glNamedBufferStorage crean un nuevo almacén de datos inmutable. Para glBufferStorage, el objeto de búfer actualmente enlazado a target será inicializado. Para glNamedBufferStorage, buffer es el nombre del objeto de búfer que se configurará. El tamaño del almacén de datos se especifica mediante size. Si hay datos iniciales disponibles, su dirección puede proporcionarse en data. De lo contrario, para crear un almacén de datos no inicializado, data debe ser NULL

.

El parámetro flags especifica el uso previsto del almacén de datos del búfer. Debe ser una combinación por bits de un subconjunto de los siguientes

indicadores:

GL_DYNAMIC_STORAGE_BI

T
El contenido del almacén de datos puede actualizarse después de la creación mediante llamadas a glBufferSubData(). Si este bit no está establecido, el contenido del búfer no puede actualizarse directamente por el cliente. El argumento data puede usarse para especificar el contenido inicial del almacén de datos del búfer, independientemente de la presencia de GL_DYNAMIC_STORAGE_BIT. Independientemente de la presencia de este bit, los búferes siempre pueden actualizarse con llamadas del lado del servidor como glCopyBufferSubData() y glClearBufferSu
bData().

GL_MAP_READ_BI

T
El almacén de datos puede ser mapeado por el cliente para acceso de lectura y obtenerse un puntero en el espacio de direcciones del cliente desde el que se pueda
leer.

GL_MAP_WRITE_BI

T
El almacén de datos puede ser mapeado por el cliente para acceso de escritura y obtenerse un puntero en el espacio de direcciones del cliente a través del cual se pueda
escribir.

GL_MAP_PERSISTENT_BI

T
El cliente puede solicitar que el servidor lea de o escriba en el búfer mientras está mapeado. El puntero del cliente al almacén de datos permanece válido mientras el almacén de datos esté mapeado, incluso durante la ejecución de comandos de dibujo o
despacho.

GL_MAP_COHERENT_BI

T
El acceso compartido a búferes que están simultáneamente mapeados para acceso del cliente y son usados por el servidor será coherente, siempre que ese mapeo se realice mediante glMapBufferRange(). Es decir, los datos escritos en el almacén por el cliente o el servidor serán inmediatamente visibles para el otro sin que la aplicación tome ninguna acción adicional. En particular,
•Si GL_MAP_COHERENT_BIT no está establecido y el cliente realiza una escritura seguida de una llamada al comando glMemoryBarrier() con GL_CLIENT_MAPPED_BUFFER_BARRIER_BIT establecido, entonces en los comandos subsiguientes el servidor verá las
escrituras.
•Si GL_MAP_COHERENT_BIT está establecido y el cliente realiza una escritura, entonces en los comandos subsiguientes el servidor verá las
escrituras.
•Si GL_MAP_COHERENT_BIT no está establecido y el servidor realiza una escritura, la aplicación debe llamar a glMemoryBarrier() con GL_CLIENT_MAPPED_BUFFER_BARRIER_BIT establecido y luego llamar a glFenceSync() con GL_SYNC_GPU_COMMANDS_COMPLETE (o glFinish). Entonces la CPU verá las escrituras después de que la sincronización se
complete.
•Si GL_MAP_COHERENT_BIT está establecido y el servidor realiza una escritura, la aplicación debe llamar a glFenceSync con GL_SYNC_GPU_COMMANDS_COMPLETE (o glFinish()). Entonces la CPU verá las escritura
s después de que la sin
cronización se complete.

GL_CLIENT_STORAGE_BI

T
Cuando se cumplen todos los demás criterios para la asignación de almacenamiento del búfer, este bit puede ser usado por una implementación para determinar si usar almacenamiento local al servidor o al cliente como almacén de respaldo para el
búfer.

Las combinaciones permitidas de indicadores están sujetas a ciertas restricciones. Son las

siguientes:
•Si flags contiene GL_MAP_PERSISTENT_BIT, también debe contener al menos uno de GL_MAP_READ_BIT o GL_MAP_WRITE_BIT
.
•Si flags contiene GL_MAP_COHERENT_BIT, también debe contener GL_MAP_PERSISTENT_BI
T
.

NOMBRE

glBufferStorage - crea y, opcionalmente, inicializa el almacenamiento de un búfer de objetos de búfer

ESPECIFICACIÓN C

void glBufferStorage(
    GLenum target,
    GLsizeiptr size,
    const void *data,
    GLbitfield flags
);

PARÁMETROS

indica el tipo de objeto de búfer que se va a crear. El símbolo target debe ser uno de GL_ARRAY_BUFFER, GL_ATOMIC_COUNTER_BUFFER, GL_COPY_READ_BUFFER, GL_COPY_WRITE_BUFFER, GL_DRAW_INDIRECT_BUFFER, GL_ELEMENT_ARRAY_BUFFER, GL_PIXEL_PACK_BUFFER, GL_PIXEL_UNPACK_BUFFER, GL_SHADER_STORAGE_BUFFER, GL_TEXTURE_BUFFER, GL_TRANSFORM_FEEDBACK_BUFFER, o GL_UNIFORM_BUFFER.

especifica el tamaño en bytes del nuevo búfer. Cualquier valor de tamaño anterior asociado con el objeto de búfer enlazado a target se perderá.

proporciona los datos iniciales para el nuevo búfer. Si data es NULL, entonces no se cargan datos iniciales. Si data no es NULL, entonces se copian size bytes desde la ubicación de memoria apuntada por data al búfer.

especifica las propiedades del nuevo búfer.

El bit flags es una máscara de bits que puede contener cero o más de las siguientes banderas:

GL_MAP_READ_BIT
El búfer puede ser mapeado para leer.
GL_MAP_WRITE_BIT
El búfer puede ser mapeado para escribir.
GL_MAP_PERSISTENT_BIT
El búfer se asigna de forma persistente. El búfer permanece mapeado hasta que se libera o se reemplaza, y los resultados de las operaciones de escritura son visibles para las operaciones de renderizado en la misma o en operaciones posteriores. El búfer debe ser mapeado explícitamente usando glMapBufferRange. Los búferes que se crean con GL_MAP_PERSISTENT_BIT también deben ser GL_MAP_READ_BIT o GL_MAP_WRITE_BIT.
GL_MAP_COHERENT_BIT
Si se establece esta bandera, las escrituras del host en el búfer mapeado son coherentes. Si GL_MAP_PERSISTENT_BIT se establece pero GL_MAP_COHERENT_BIT no, las escrituras del host no son necesariamente visibles para el dispositivo de renderizado hasta que se llama a glMemoryBarrier con GL_CLIENT_MAPPED_BUFFER_BARRIER_BIT, o hasta que se realizan otras operaciones de sincronización del búfer, como glBufferSubData. Si GL_MAP_COHERENT_BIT se establece, entonces GL_MAP_PERSISTENT_BIT también debe ser establecida.
GL_DYNAMIC_STORAGE_BIT
Si se establece esta bandera, el búfer es dinámicamente modificable. Si no se establece, entonces el búfer es inmutable y no se puede modificar más allá de la inicialización inicial, excepto mediante la llamada a glBufferStorage nuevamente.

DESCRIPCIÓN

glBufferStorage crea y, opcionalmente, inicializa el almacenamiento de un objeto de búfer. Cuando se crea un objeto de búfer, inicialmente no tiene ningún dato asociado. glBufferStorage vincula un nuevo objeto de búfer al búfer de destino especificado por target. Los datos del búfer anterior, si los hubiera, se pierden.

El parámetro size especifica el tamaño en bytes del nuevo búfer. Si size es mayor que el tamaño anterior del búfer, el búfer se ampliará. Si size es menor que el tamaño anterior del búfer, el búfer se recortará. Si size es cero, se desasociará cualquier dato asociado del búfer.

Si se proporciona el puntero data, se copian size bytes al búfer. Si data es NULL, el contenido del búfer inicial no se define.

El parámetro flags controla el comportamiento posterior del búfer. Si flags no incluye GL_DYNAMIC_STORAGE_BIT, el búfer se crea como inmutable y el tamaño y los datos iniciales del búfer no se pueden cambiar más adelante, excepto llamando nuevamente a glBufferStorage.

Si se incluye GL_DYNAMIC_STORAGE_BIT en flags, el búfer se crea como dinámicamente modificable. El búfer se puede modificar posteriormente llamando a glBufferSubData y glCopyBufferSubData. El tamaño de un búfer dinámicamente modificable se puede cambiar llamando a glBufferData. Los búferes dinámicamente modificables no pueden tener la bandera GL_CLIENT_STORAGE_BIT establecida.

Si se incluye GL_CLIENT_STORAGE_BIT en flags, se pueden almacenar datos fuera del control de la memoria de acceso directo de la GPU. El acceso a un búfer con esta bandera puede ser más lento que el acceso a un búfer sin ella.

Si se incluye GL_MAP_PERSISTENT_BIT en flags, el búfer puede ser mapeado persistentemente. Un búfer mapeado persistentemente no puede ser reasignado por glBufferData o glBufferStorage, y no puede ser destruido hasta que se desmapea. Si GL_MAP_COHERENT_BIT también está configurado, entonces las escrituras en el búfer son coherentes.

Los búferes creados con GL_MAP_PERSISTENT_BIT también deben tener GL_MAP_READ_BIT y/o GL_MAP_WRITE_BIT establecidos. Los búferes creados con GL_MAP_COHERENT_BIT deben tener GL_MAP_PERSISTENT_BIT establecido.

Si target es GL_ELEMENT_ARRAY_BUFFER, GL_PIXEL_PACK_BUFFER, GL_PIXEL_UNPACK_BUFFER, GL_TEXTURE_BUFFER, GL_UNIFORM_BUFFER, o GL_SHADER_STORAGE_BUFFER, se puede pasar un argumento flags que incluya cualquiera de las banderas de asignación mencionadas anteriormente.

Si target es GL_ARRAY_BUFFER, GL_ATOMIC_COUNTER_BUFFER, GL_COPY_READ_BUFFER, GL_COPY_WRITE_BUFFER, GL_DRAW_INDIRECT_BUFFER, GL_TRANSFORM_FEEDBACK_BUFFER, y se pasa el argumento flags, solo se permite GL_DYNAMIC_STORAGE_BIT. Si no se pasa ninguna bandera, se asume GL_DYNAMIC_STORAGE_BIT. No se permiten banderas de asignación.

NOTAS

glBufferStorage está disponible en las versiones de OpenGL 4.4 y posteriores.

glNamedBufferStorage es una versión de interfaz sin estado de glBufferStorage.

ERRORES

Se genera un GL_INVALID_ENUM si target no es un búfer de destino válido.

Se genera un GL_INVALID_VALUE si size es negativo.

Se genera un GL_INVALID_OPERATION si se intenta vincular un objeto de búfer con el tamaño 0 y se están utilizando banderas de asignación.

Se genera un GL_INVALID_OPERATION si se está llamando a glBufferStorage en un búfer vinculado a GL_ATOMIC_COUNTER_BUFFER o GL_SHADER_STORAGE_BUFFER y se pasa el argumento flags con GL_DYNAMIC_STORAGE_BIT establecido.

Se genera un GL_INVALID_OPERATION si se está llamando a glBufferStorage en un búfer vinculado a GL_DRAW_INDIRECT_BUFFER y se pasa el argumento flags con GL_DYNAMIC_STORAGE_BIT establecido.

Se genera un GL_INVALID_OPERATION si se está llamando a glBufferStorage en un búfer vinculado a GL_ELEMENT_ARRAY_BUFFER y se pasa el argumento flags con GL_DYNAMIC_STORAGE_BIT establecido.

Se genera un GL_INVALID_OPERATION si se está llamando a glBufferStorage en un búfer vinculado a GL_TRANSFORM_FEEDBACK_BUFFER y se pasa el argumento flags con GL_DYNAMIC_STORAGE_BIT establecido.

Se genera un GL_INVALID_OPERATION si se está llamando a glBufferStorage en un búfer vinculado a GL_PIXEL_PACK_BUFFER o GL_PIXEL_UNPACK_BUFFER y se pasa el argumento flags con GL_DYNAMIC_STORAGE_BIT establecido.

Se genera un GL_INVALID_OPERATION si se está llamando a glBufferStorage en un búfer vinculado a GL_TEXTURE_BUFFER y se pasa el argumento flags con GL_DYNAMIC_STORAGE_BIT establecido.

Se genera un GL_INVALID_OPERATION si GL_MAP_COHERENT_BIT se establece y GL_MAP_PERSISTENT_BIT no se establece.

Se genera un GL_INVALID_OPERATION si GL_MAP_PERSISTENT_BIT se establece y GL_MAP_READ_BIT y GL_MAP_WRITE_BIT no se establecen.

Se genera un GL_INVALID_OPERATION si se establece la bandera GL_CLIENT_STORAGE_BIT en flags y también se establece la bandera GL_DYNAMIC_STORAGE_BIT.

Se genera un GL_OUT_OF_MEMORY si no hay suficiente memoria para asignar size bytes para el búfer.
