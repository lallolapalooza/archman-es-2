DESCRIPCIÓ

N

El texturizado asigna una porción de una imagen de textura especificada a cada primitiva gráfica para la que el texturizado está habilitado. Para habilitar y deshabilitar el texturizado tridimensional, llame a glEnable()

y

glDisable con el argumento GL_TEXTURE_3D

.

Para definir imágenes de textura, llame a glTexImage3D. Los argumentos describen los parámetros de la imagen de textura, como la altura, el ancho, la profundidad, el ancho del borde, el número de nivel de detalle (vea glTexParameter()), y el número de componentes de color proporcionados. Los últimos tres argumentos describen cómo se representa la imagen en

memoria.

Si target es GL_PROXY_TEXTURE_3D, no se leen datos de data, pero todo el estado de la imagen de textura se recalcula, se comprueba su coherencia y se verifica con las capacidades de la implementación. Si la implementación no puede manejar una textura del tamaño solicitado, establece todo el estado de la imagen en 0, pero no genera un error (vea glGetError()). Para consultar una matriz de mipmap completa, use un nivel de matriz de imagen mayor o igual que

1.

Si target es GL_TEXTURE_3D, se leen datos de data como una secuencia de bytes, shorts o longs con signo o sin signo, o valores de punto flotante de precisión simple, dependiendo de type. Estos valores se agrupan en conjuntos de uno, dos, tres o cuatro valores, dependiendo de format, para formar elementos. Cada byte de datos se trata como ocho elementos de 1 bit, con el orden de bits determinado por GL_UNPACK_LSB_FIRST (vea glPixelStore())

.

Si un objeto de búfer con nombre distinto de cero está vinculado al objetivo GL_PIXEL_UNPACK_BUFFER (vea glBindBuffer()) mientras se especifica una imagen de textura, data se trata como un desplazamiento en bytes dentro del almacén de datos del objeto de

búfer.

El primer elemento corresponde a la esquina inferior izquierda de la imagen de textura. Los elementos siguientes avanzan de izquierda a derecha a través de los texels restantes en la fila más baja de la imagen de textura, y luego en filas sucesivamente más altas de la imagen de textura. El último elemento corresponde a la esquina superior derecha de la imagen de

textura.

format determina la composición de cada elemento en data. Puede asumir uno de estos valores

simbólicos:

GL_RE

D
Cada elemento es un solo componente rojo. GL lo convierte a punto flotante y lo ensambla en un elemento RGBA adjuntando 0 para verde y azul, y 1 para alfa. Cada componente se limita al rango [0,1]
.

GL_R

G
Cada elemento es un par rojo y verde. GL convierte cada uno a punto flotante y los ensambla en un elemento RGBA adjuntando 0 para azul, y 1 para alfa. Cada componente se limita al rango [0,1]
.

GL_RGB, GL_BG

R
Cada elemento es una tripleta RGB. GL lo convierte a punto flotante y lo ensambla en un elemento RGBA adjuntando 1 para alfa. Cada componente se limita al rango [0,1]
.

GL_RGBA, GL_BGR

A
Cada elemento contiene los cuatro componentes. Cada componente se limita al rango [0,1]
.

Si una aplicación desea almacenar la textura en una cierta resolución o en un cierto formato, puede solicitar la resolución y el formato con internalformat. GL elegirá una representación interna que se aproxime a la solicitada por internalformat, pero puede que no coincida exactamente. (Las representaciones especificadas por GL_RED, GL_RG, GL_RGB, y GL_RGBA deben coincidir exactamente.

)

Si el
parámetro internalformat es uno de los formatos comprimidos genéricos, GL_COMPRESSED_RED, GL_COMPRESSED_RG, GL_COMPRESSED_RGB, o GL_COMPRESSED_RGBA, el GL reemplazará el formato interno con la constante simbólica para un formato interno específico y comprimirá la textura antes del almacenamiento. Si no hay un formato interno correspondiente disponible, o el GL no puede comprimir esa imagen por cualquier razón, el formato interno se reemplaza en su lugar con un formato interno base correspondiente

.

Si el parámetro internalformat es GL_SRGB, GL_SRGB8, GL_SRGB_ALPHA, o GL_SRGB8_ALPHA8, la textura se trata como si los componentes rojo, verde, azul o luminancia estuvieran codificados en el espacio de color sRGB. Cualquier componente alfa se deja sin cambios. La conversión desde el componente codificado en sRGB c s a un componente lineal c l

es:

c l = { c s 12.92 si c s ≤ 0.04045 ( c s + 0.055 1.055 ) 2.4 si c s > 0.

04045

Asuma que c s es el componente sRGB en el rango [0,1]

.

Utilice el objetivo GL_PROXY_TEXTURE_3D para probar una resolución y formato. La implementación actualizará y recomputará su mejor coincidencia para la resolución y formato de almacenamiento solicitados. Para luego consultar este estado, llame a glGetTexLevelParameter(). Si la textura no puede ser acomodada, el estado de la textura se establece a

0.

Una imagen de textura de un componente usa solo el componente rojo del color RGBA extraído de data. Una imagen de dos componentes usa los valores R y A. Una imagen de tres componentes

usa los valores R, G y B. Una imagen de cua
tro componentes usa todos los componentes RGBA.

NOTA

S

El modo de glPixelStore() afecta las imágenes de

textura.

data puede ser un puntero nulo. En este caso se asigna memoria de textura para acomodar una textura de ancho width, alto height y profundidad depth. Luego puede descargar subtexturas para inicializar esta memoria de textura. La imagen es indefinida si el usuario intenta aplicar una porción no inicializada de la imagen de textura a una

primitiva.

glTexImage3D especifica la textura tridimensional para la unidad de textura actual, especificada con glActiveText

ure().

GL_STENCIL_INDEX puede usarse para format solo si la versi

ón de GL es 4
.4 o superior.

ERRORE

S

Se genera GL_INVALID_ENUM si target no es GL_TEXTURE_3D o GL_PROXY_TEXTURE_3D

.

Se genera GL_INVALID_ENUM si format no es una constante de formato aceptada. Se aceptan constantes de formato distintas de GL_STENCIL_INDEX y GL_DEPTH_COMPONENT

.

Se genera GL_INVALID_ENUM si type no es una constante de

tipo.

Se genera GL_INVALID_VALUE si level es menor que

0.

Puede generarse GL_INVALID_VALUE si level es mayor que log 2 ⁡ max, donde max es el valor devuelto de GL_MAX_TEXTURE_SIZE

.

Se genera GL_INVALID_VALUE si internalformat no es una de las constantes simbólicas de resolución y formato

aceptadas.

Se genera GL_INVALID_VALUE si width, height o depth es menor que 0 o mayor que GL_MAX_TEXTURE_SIZE

.

Se genera GL_INVALID_VALUE si border no es

0.

Se genera GL_INVALID_OPERATIONgenerado si el tipo es uno de GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, o GL_UNSIGNED_SHORT_5_6_5_REV y el formato no es GL_RGB

.

Se genera GL_INVALID_OPERATION si el tipo es uno de GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, o GL_UNSIGNED_INT_2_10_10_10_REV y el formato no es ni GL_RGBA ni GL_BGRA

.

Se genera GL_INVALID_OPERATION si el formato o el internalformat es GL_DEPTH_COMPONENT, GL_DEPTH_COMPONENT16, GL_DEPTH_COMPONENT24, o GL_DEPTH_COMPONENT32

.

Se genera GL_INVALID_OPERATION si un nombre de objeto de búfer distinto de cero está vinculado al objetivo GL_PIXEL_UNPACK_BUFFER y el almacén de datos del objeto de búfer está actualmente

mapeado.

Se genera GL_INVALID_OPERATION si un nombre de objeto de búfer distinto de cero está vinculado al objetivo GL_PIXEL_UNPACK_BUFFER y los datos se desempaquetarían del objeto de búfer de manera que las lecturas de memoria requeridas excederían el tamaño del almacén de

datos.

Se genera GL_INVALID_OPERATION si un nombre de objeto de búfer distinto de cero está vinculado al objetivo GL_PIXEL_UNPACK_BUFFER y los datos no son divisibles uniformemente por el número de bytes necesarios para almacenar en memoria un dato indicado por ty

pe
.
