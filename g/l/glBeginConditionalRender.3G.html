DESCRIPCIÓ

N

El renderizado condicional se inicia con glBeginConditionalRender y se finaliza con glEndConditionalRender. Durante el renderizado condicional, todos los comandos de matrices de vértices, así como glClear() y glClearBuffer() no tienen efecto si el resultado (GL_SAMPLES_PASSED) del objeto de consulta id es cero, o si el resultado (GL_ANY_SAMPLES_PASSED) es GL_FALSE. Los resultados de los comandos que establecen el estado actual de los vértices, como glVertexAttrib(), son indefinidos. Si el resultado (GL_SAMPLES_PASSED) es distinto de cero o si el resultado (GL_ANY_SAMPLES_PASSED) es GL_TRUE, dichos comandos no se descartan. El parámetro id de glBeginConditionalRender debe ser el nombre de un objeto de consulta devuelto previamente por una llamada a glGenQueries(). mode especifica cómo se deben interpretar los resultados del objeto de consulta. Si mode es GL_QUERY_WAIT, la GL espera a que los resultados de la consulta estén disponibles y luego los utiliza para determinar si los comandos de renderizado posteriores se descartan. Si mode es GL_QUERY_NO_WAIT, la GL puede optar por ejecutar incondicionalmente los comandos de renderizado posteriores sin esperar a que la consulta se

complete.

Si mode es GL_QUERY_BY_REGION_WAIT, la GL también esperará los resultados de la consulta de oclusión y descartará los comandos de renderizado si el resultado de la consulta de oclusión es cero. Si el resultado de la consulta es distinto de cero, los comandos de renderizado posteriores se ejecutan, pero la GL puede descartar los resultados de los comandos para cualquier región del búfer de trazado que no haya contribuido al recuento de muestras en la consulta de oclusión especificada. Cualquier descarte de este tipo se realiza de una manera dependiente de la implementación, pero los resultados de los comandos de renderizado no pueden descartarse para ninguna muestra que haya contribuido al recuento de muestras de la consulta de oclusión. Si mode es GL_QUERY_BY_REGION_NO_WAIT, la GL opera como en GL_QUERY_BY_REGION_WAIT, pero puede optar por ejecutar incondicionalmente los

comandos de renderizado posteriores sin
esperar a que la consulta se complete.

    glBeginConditionalRender(3G)

    NOMBRE 

        glBeginConditionalRender - Comienza una renderización condicional

    SINTAXIS 

        void glBeginConditionalRender(GLuint query);
    void glEndConditionalRender(void);

    VERSIÓN DE GLSL 

        Shader GLSL 3.30

    DESCRIPCIÓN

    glBeginConditionalRender y glEndConditionalRender delimitan un bloque de comandos de renderizado cuyos resultados se aplican condicionalmente. La condición se basa en el resultado de una consulta GL_SAMPLES_PASSED generada previamente.

    glBeginConditionalRender inicia el bloque. El parámetro query debe ser el identificador de una consulta activa generada previamente que está configurada para contar GL_SAMPLES_PASSED. Si la consulta no es de este tipo, o si ya se ha llamado a glBeginConditionalRender sin una llamada coincidente a glEndConditionalRender, se generará un error GL_INVALID_OPERATION.

    Cuando se llama a glBeginConditionalRender, el pipeline de renderizado de OpenGL comprueba el resultado de la consulta especificada. Si la consulta aún no ha finalizado (es decir, la ejecución de la consulta no ha completado el recuento de GL_SAMPLES_PASSED), glBeginConditionalRender entra en un estado en el que se ignorarán todos los comandos de renderizado y el estado hasta que se llame a glEndConditionalRender. Si la consulta ha finalizado y el resultado es cero, también se ignorarán todos los comandos de renderizado y el estado. Si la consulta ha finalizado y el resultado es distinto de cero, los comandos de renderizado se procesarán normalmente.

    glEndConditionalRender finaliza el bloque. Debe llamarse para cada llamada a glBeginConditionalRender. Si se llama a glEndConditionalRender sin una llamada coincidente a glBeginConditionalRender, se generará un error GL_INVALID_OPERATION.

    El renderizado condicional puede anidarse hasta una profundidad determinada por GL_MAX_SHADER_STORAGE_BUFFER_BINDINGS. Los resultados de las consultas anidadas se combinan mediante una operación AND booleana.

    ARGUMENTOS 

        query
        El identificador de una consulta activa generada previamente que está configurada para contar GL_SAMPLES_PASSED.

    COLORES

    Ninguno

    ERRORES

    GL_INVALID_OPERATION se genera si query no es un identificador de consulta válido, o si la consulta especificada no está configurada para contar GL_SAMPLES_PASSED, o si glBeginConditionalRender se llama cuando un renderizado condicional ya está en curso en el contexto de llamada.

    GL_INVALID_OPERATION se genera si glEndConditionalRender se llama cuando no hay ningún renderizado condicional en curso en el contexto de llamada.

    EJEMPLOS 

        // Crear una consulta que cuente las muestras que pasan:
    GLuint queryID;
    glGenQueries(1, &queryID);

    // ...

    // Iniciar la renderización condicional
    glBeginConditionalRender(queryID);

    // Dibujar geometría aquí. Solo se renderizará si el resultado de la consulta es distinto de cero.
    glDrawArrays(GL_TRIANGLES, 0, 3);

    // Finalizar la renderización condicional
    glEndConditionalRender();
