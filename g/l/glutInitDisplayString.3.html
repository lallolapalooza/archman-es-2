glutInitDisplayString(3)

Paquete: freeglut

Licencias: X11

glutInitDisplayString(3) freeglut glutInitDisplayString(3)

NOMBRE

glutInitDisplayString - establece el modo de visualización inicial a través de una cadena.

SINTAXIS

void glutInitDisplayString(char *string);

ARGUMENTOS

string
Cadena de descripción del modo de visualización, ver más abajo.

DESCRIPCIÓN

La cadena de descripción del modo de visualización inicial se utiliza al crear ventanas de nivel superior, subventanas y superposiciones para determinar el modo de visualización de OpenGL para la ventana o superposición que se va a crear.

La cadena es una lista de cero o más descripciones de capacidades separadas por espacios y tabulaciones. Cada descripción de capacidad es un nombre de capacidad opcionalmente seguido de un comparador y un valor numérico. Por ejemplo, "double" y "depth>=12" son ambos criterios válidos.

Las descripciones de capacidades se traducen en un conjunto de criterios utilizados para seleccionar la configuración de búfer de fotogramas apropiada.

Los criterios se comparan en orden estricto de izquierda a derecha según su precedencia. Es decir, el primer criterio especificado (el más a la izquierda) tiene precedencia sobre los criterios posteriores para los criterios no exactos (comparadores como mayor que, menor que, etc.). Los criterios exactos (comparadores igual, distinto) deben coincidir exactamente, por lo que la precedencia no es relevante.

El valor numérico es un entero que se analiza según el comportamiento de strtol(str, strptr, 0) del ANSI C. Esto significa que se aceptan valores decimales, octales (con 0 inicial) y hexadecimales (con 0x inicial).

Los comparadores válidos son:

=
Igual.
!=
Distinto.
<
Menor que y prefiriendo la diferencia más grande (el menor es el mejor).
>
Mayor que y prefiriendo las diferencias más grandes (el mayor es el mejor).
<=
Menor o igual y prefiriendo la diferencia más grande (el menor es el mejor).
>=
Mayor o igual y prefiriendo más en lugar de menos. Este comparador es útil para asignar recursos como la precisión de color o la precisión del búfer de profundidad, donde generalmente se prefiere la precisión máxima. Contraste con el comparador tilde (~).
~
Mayor o igual pero prefiriendo menos en lugar de más. Este comparador es útil para asignar recursos como bits de stencil o búferes de color auxiliares, donde preferirías no sobreasignar.

Cuando no se especifican el comparador y el valor numérico, cada nombre de capacidad tiene un valor predeterminado diferente (un valor predeterminado es requerir un comparador y un valor numérico).

Los nombres de capacidades válidos son:

alpha
Precisión del búfer de color alfa en bits. El valor predeterminado es ">=1".
acca
Precisión del búfer de acumulación de rojo, verde, azul y alfa en bits. El valor predeterminado es ">=1" para las capacidades de rojo, verde, azul y alfa.
acc
Precisión del búfer de acumulación de rojo, verde y azul en bits y cero bits de precisión del búfer de acumulación alfa. El valor predeterminado es ">=1" para las capacidades de rojo, verde y azul, y "~0" para la capacidad de alfa.
auxbufs
Número de búferes auxiliares.
blue
Precisión del búfer de color azul en bits. El valor predeterminado es ">=1".
buffer
Número de bits en el búfer de color de índice de color. El valor predeterminado es ">=1".
conformant
Booleano que indica si la configuración del búfer de fotogramas es conforme o no. La información de conformidad se basa en la extensión EXT_visual_rating de GLX si es compatible. Si la extensión no es compatible, se asume que todos los visuales son conformes. El valor predeterminado es "=1".
depth
Número de bits de precisión en el búfer de profundidad. El valor predeterminado es ">=12".
double
Booleano que indica si el búfer de color es de doble búfer. El valor predeterminado es "=1".
green
Precisión del búfer de color verde en bits. El valor predeterminado es ">=1".
index
Booleano que indica si el modelo de color es de índice de color o no. Verdadero significa índice de color. El valor predeterminado es ">=1".
luminance
Número de bits de rojo en el búfer de color RGBA y cero bits de verde y azul (alfa no especificado) de precisión. El valor predeterminado es ">=1" para la capacidad de rojo, "=0" para las capacidades de verde y azul, "=1" para la capacidad del modelo de color RGBA y, para X11, "=1" para la capacidad StaticGray ("xstaticgray").

SGI InfiniteReality (y otras máquinas futuras) soportan un modo de visualización de luminancia de 16 bits (canal único) (también se puede solicitar un canal alfa adicional de 16 bits). El canal rojo se mapea a escala de grises y los canales verde y azul no están disponibles. Un modo de visualización de luminancia con precisión de 16 bits a menudo es apropiado para aplicaciones de imagen médica. No esperes que muchas máquinas soporten modos de visualización de luminancia de precisión extendida.

num
Un nombre de capacidad especial que indica que el valor representa la N-ésima configuración de búfer de fotogramas que coincide con la cadena de descripción. Cuando no se especifica, glutInitDisplayString también devuelve la primera configuración (la que mejor coincide). num requiere un comparador y un valor numérico.
red
Precisión del búfer de color rojo en bits. El valor predeterminado es ">=1".
rgba
Número de bits de rojo, verde, azul y alfa en el búfer de color RGBA. El valor predeterminado es ">=1" para las capacidades de rojo, verde, azul y alfa, y "=1" para la capacidad del modelo de color RGBA.
rgb
Número de bits de rojo, verde y azul en el búfer de color RGBA y cero bits de precisión del búfer de color alfa. El valor predeterminado es ">=1" para las capacidades de rojo, verde y azul, "~0" para la capacidad de alfa, y "=1" para la capacidad del modelo de color RGBA.
samples
Indica el número de muestras múltiples a usar basado en la extensión SGIS_multisample de GLX (para antialiasing). El valor predeterminado es "<=4". Este valor predeterminado significa que una aplicación GLUT puede solicitar muestreo múltiple si está disponible simplemente especificando "samples".
single
Booleano que indica que el búfer de color es de búfer único. Capacidad de doble búfer "=1".
slow
Booleano que indica si la configuración del búfer de fotogramas es lenta o no. Para la implementación de GLUT en X11, la información de lentitud se basa en la extensión EXT_visual_rating de GLX si es compatible. Si la extensión EXT_visual_rating no es compatible, se asume que todos los visuales son rápidos. Para la implementación de GLUT en Win32, la lentitud se basa en si el Descriptor de Formato de Píxel (PFD) subyacente está marcado como "genérico" y no "acelerado". Esto implica que se utiliza la implementación de OpenGL por software relativamente lenta de Microsoft para este PFD. Ten en cuenta que la lentitud es una designación relativa en comparación con otras configuraciones de búfer de fotogramas disponibles. La intención de la capacidad slow es ayudar a los programas a evitar configuraciones de búfer de fotogramas que sean más lentas (pero quizás de mayor precisión) para la máquina actual. El valor predeterminado es ">=0" si no se proporcionan comparador y valor numérico. Este valor predeterminado significa que se prefieren los visuales lentos a los rápidos, pero los visuales rápidos aún estarán permitidos.
stencil
Número de bits en el búfer de stencil.
stereo
Booleano que indica si el búfer de color soporta estéreo estilo OpenGL. El valor predeterminado es "=1".
win32pfd
Solo se reconoce en las implementaciones de GLUT para Win32.2, este nombre de capacidad coincide con el Descriptor de Formato de Píxel de Win32 por número. win32pfd requiere un comparador y un valor numérico.
xdirectcolor
Solo se reconoce en implementaciones GLUT para el Sistema de Ventanas X, booleano que indica si el X visual de la configuración del búfer de trama es de tipo DirectColor. El valor predeterminado es "=1".
xgrayscale
Solo se reconoce en implementaciones GLUT para el Sistema de Ventanas X, booleano que indica si el X visual de la configuración del búfer de trama es de tipo GrayScale. El valor predeterminado es "=1".
xpseudocolor
Solo se reconoce en implementaciones GLUT para el Sistema de Ventanas X, booleano que indica si el X visual de la configuración del búfer de trama es de tipo PsuedoColor. El valor predeterminado es "=1".
xstaticcolor
Solo se reconoce en implementaciones GLUT para el Sistema de Ventanas X, booleano que indica si el X visual de la configuración del búfer de trama es de tipo StaticColor. El valor predeterminado es "=1".
xstaticgray
Solo se reconoce en implementaciones GLUT para el Sistema de Ventanas X, booleano que indica si el X visual de la configuración del búfer de trama es de tipo StaticGray. El valor predeterminado es "=1".
xtruecolor
Solo se reconoce en implementaciones GLUT para el Sistema de Ventanas X, booleano que indica si el X visual de la configuración del búfer de trama es de tipo TrueColor. El valor predeterminado es "=1".
xvisual
Solo se reconoce en implementaciones GLUT para el Sistema de Ventanas X, este nombre de capacidad coincide con el ID del X visual por número. xvisual requiere un comparador y un valor numérico.

Las descripciones de capacidades no especificadas resultarán en la generación de criterios no especificados. Estos criterios no especificados ayudan a que glutInitDisplayString se comporte de manera sensata con cadenas de descripción de modo de visualización breves. Por ejemplo, si no se proporciona una descripción de capacidad "slow", se elegirán configuraciones de búfer de trama rápidas con preferencia sobre configuraciones de búfer de trama lentas, pero aún se elegirán configuraciones de búfer de trama lentas si no hay disponible una mejor configuración de búfer de trama rápida.

EJEMPLO

Aquí hay un ejemplo usando glutInitDisplayString:

  glutInitDisplayString("stencil~2 rgb double depth>=16 samples");
La llamada anterior solicita una ventana con un modelo de color RGBA (pero sin solicitar bits de alfa), un búfer de profundidad con al menos 16 bits de precisión pero prefiriendo más, muestreo múltiple si está disponible, y al menos 2 bits de stencil (favoreciendo menos stencil a más siempre que estén disponibles 2 bits).
