función gl_get_line() es parte de la biblioteca tecla (véase la página man libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de unix. Además de la edición de línea de comandos simple, admite la recuperación de líneas de comandos introducidas previamente, la finalización con TAB de nombres de archivos y la expansión de comodines en línea de nombres de archivos. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario se puede encontrar en la página man tecla(7). La función gl_get_line() puede ser llamada cualquier número de veces para leer la entrada del usuario. El argumento gl debe haber sido previamente devuelto por una llamada a new_GetLine(). error.

La función gl_get_line() devuelve un puntero a la línea introducida por el usuario, o NULL en caso de error o al final de la entrada. El puntero devuelto forma parte del objeto recurso gl especificado, y por lo tanto no debe ser liberado por el llamante, ni asumirse que es inmutable de una llamada a la siguiente. Cuando la entrada estándar proviene de una tubería o de un archivo, de manera similar habrá una nueva línea a menos que la línea de entrada fuera demasiado larga para almacenarse en el búfer interno. En este último caso, debería llamar a gl_get_line() de nuevo para leer el resto de la línea. Tenga en cuenta que este comportamiento hace que gl_get_line() sea similar a fgets(). FUENTES ALTERNATIVAS DE

CONFIGURACIÓN

Como se mencionó anteriormente, de forma predeterminada los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. En algunas aplicaciones, sin embargo, este único medio de configuración es un problema. Esto es particularmente cierto en el software embebido, donde no hay un sistema de archivos del cual leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de asignaciones de teclas para emular una interfaz de teclado heredada. Para atender a estos casos, la siguiente función permite a la aplicación controlar de dónde se leen los datos de

configuración. 
  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file)
;

Permite que los comandos de configuración que normalmente se leerían desde el archivo ~/.teclarc de un usuario, se lean desde cualquiera o ninguno de: una cadena, un archivo de configuración específico de la aplicación, y/o un archivo de configuración específico del usuario. Si se llama a esta función antes de la primera llamada a gl_get_line(), el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line() se deshabilita, por lo que toda la configuración debe lograrse utilizando las fuentes de configuración especificadas con esta

función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados entre sí en la cadena por caracteres de nueva línea incrustados. Si app_file != NULL entonces se interpreta como el nombre de ruta completo de un archivo de configuración específico de la aplicación. Si user_file != NULL entonces se interpreta como el nombre de ruta completo de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente

llamada, 
  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc")
;

el argumento app_string hace que la aplicación que llama comience en el modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso de la campana de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración de todo el sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario desde un archivo .teclarc opcional en el directorio de inicio del usuario. Tenga en cuenta que los argumentos se listan en orden ascendente de prioridad, con el contenido de app_string siendo potencialmente anulado por comandos en app_file, y los comandos en app_file potencialmente siendo anulados por comandos en user_file

.

Puede llamar a esta función tantas veces como sea necesario, siendo los resultados acumulativos, pero tenga en cuenta que las copias de cualquier nombre de archivo especificado a través del >app_file y los argumentos user_file se registran internamente para su uso posterior por parte de la función de enlace de teclas read-init-files, así que si planea llamar a esta función varias veces, asegúrese de que la última llamada especifique los nombres de archivo que desea releer cuando el usuario solicite que los archivos de configuración sean

releídos.

COMPLETADO DE PALABRAS

PERSONALIZADO

Si en su aplicación, le gustaría que la completación con TAB completara otras cosas además de o en lugar de nombres de archivo, puede organizar esto registrando una función de retorno de completación alternativa, mediante una llamada a la función gl_customize_co

mpletion(). 
  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn)
;

El argumento data proporciona una manera para que su aplicación pase información arbitraria específica de la aplicación a la función de retorno. Esto se pasa a la función de retorno cada vez que se llama. Podría, por ejemplo, apuntar a la tabla de símbolos de la que se deben buscar las posibles completaciones. El argumento match_fn especifica la función de retorno a ser llamada. El tipo de función CplMatchFn está definido en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y prototipar funciones de retorno. La declaración y las responsabilidades de las funciones de retorno se describen en profundidad en la página del manual cpl_complete_word(3)

.

En resumen, la función de retorno es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario presionó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar completaciones posibles de esta palabra y registrarlas una por una en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion(). Si la función de retorno desea proporcionar completación de nombres de archivo además de sus propias completaciones específicas, tiene la opción de llamar ella misma a la función de retorno de completación de nombres de archivo incorporada. Esto también está documentado en la página del manual cpl_complete_word(3)

.

Tenga en cuenta que si le gustaría que gl_get_line() devolviera la línea de entrada actual cuando se haya realizado una completación exitosa, puede organizar esto cuando llame a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de nueva línea. Si hace esto, la línea de entrada se actualizará para mostrar la completación, junto con cualquier sufijo de continuación hasta el carácter de nueva línea, y luego gl_get_line() devolverá esta línea de

entrada.

Si, por alguna razón, su función de retorno necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto iniciará una nueva línea después de la línea de entrada que se está editando actualmente, restablecerá la E/S normal de la terminal y le dirá a gl_get_line() que la línea de entrada necesitará

ser redibujada cuando la f
unción de retorno regrese.

AÑADIENDO ACCIONES DE

COMPLETACIÓN

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de completación predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que diferentes tipos de completación de palabras se puedan enlazar a diferentes secuencias de teclas. Esto se logra usando la función gl_completion_action()

. 
  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq)
;

Los argumentos data y match_fn se describen como en la página del manual de cpl_complete_word, y especifican la función de retorno que debe ser invocada para identificar posibles completaciones. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar cualquier posible completación ambigua, o si simplemente debe mostrar la lista de posibles completaciones sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre con el que los archivos de configuración y las futuras invocaciones de esta función deben referirse a la acción. Este debe ser el nombre de una acción de completación existente a ser cambiada, o un nuevo nombre sin usar para una nueva acción. Finalmente, el argumento keyseq especifica la secuencia de teclas predeterminada a la que enlazar la acción. Si esto es NULL, no se enlazará ninguna nueva secuencia de teclas a la

acción.

Tenga cuidado de que para que el usuario pueda cambiar la secuencia de teclas que está enlazada a las acciones que se instalan de esta manera, cuando llame a gl_completion_action() para instalar una acción dada por primera vez, debe hacerlo entre la llamada a new_GetLine() y la primera llamada a gl_get_line(). De lo contrario, cuando se lea el archivo de configuración del usuario en la primera llamada a gl_get_line(), el nombre de su acción adicional no será conocido, y cualquier referencia a ella en el archivo de configuración generará un

error.

Como se discutió para gl_customize_completion(), si su función de retorno, por alguna razón, necesita escribir algo en la terminal, debe llamar a gl_normal_io() a

ntes de

PERSONALIZADAS

Aunque las acciones de enlace de teclas incorporadas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, enlazadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza que correspondiera a un número de pieza precedente al cursor. Tal característica claramente está fuera del alcance de las funciones de acción incorporadas. Así que para tales casos especiales, se proporciona la función gl_register_action()

  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq)
;

Esta función permite a la aplicación registrar una función externa, fn, que será llamada a partir de entonces cada vez que se introduzca la secuencia de teclas especificada, keyseq, por el usuario, o el usuario introduzca cualquier otra secuencia de teclas que el usuario posteriormente enlace al nombre de acción especificado, name, en su archivo de configuración. El argumento data puede ser un puntero a cualquier cosa que la aplicación desee que se pase a la función de acción, fn, cada vez que esa función sea

invocada.

La función de acción, fn, debe ser declarada usando la siguiente macro, que está definida en libtecl

a.h. 
  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char
*line)

Los argumentos gl y data son aquellos que fueron previamente pasados a gl_register_action() cuando la función de acción fue registrada. El argumento count es un argumento numérico que el usuario tiene la opción de introducir usando la acción digit-argument, antes de invocar la acción. Si el usuario no introduce un número, entonces el argumento count se establece en 1. Nominalmente este argumento se interpreta como un conteo de repetición, lo que significa que la acción debe repetirse esa cantidad de veces. Sin embargo, en la práctica, para algunas acciones un conteo de repetición tiene poco sentido. En tales casos, las acciones pueden simplemente ignorar el argumento count, o usar su valor para un propósito

diferente.

Una copia de la línea de entrada actual se pasa en el argumento de solo lectura line. La posición actual del cursor dentro de esta cadena es dada por el índice contenido en el argumento curpos. Tenga en cuenta que la manipulación directa de la línea de entrada y la posición del cursor no está permitida. Esto se debe a que las reglas dictadas por varios modos, como el modo vi versus el modo emacs, el modo sin eco, y el modo de inserción versus el modo de sobrescritura etc, hacen que sea demasiado compleo para un desarrollador de aplicaciones escribir una acción de edición conforme, así como restringen cambios futuros en los internos de gl_get_line(). Una solución potencial a este dilema sería permitir que la función de acción edite la línea usando las acciones de edición existentes. Esto está actualmente bajo

consideración.

Si la función de acción desea escribir texto en la terminal, sin que esto se mezcle con el texto mostrado de la línea de entrada, o leer de la terminal sin tener que manejar la E/S cruda de la terminal, entonces antes de realizar cualquiera de estas operaciones, debe suspender temporalmente la edición de línea llamando a la función gl_normal_io(). Esta función vacía cualquier salida pendiente a la terminal, mueve el cursor al inicio de la línea que sigue a la última línea de terminal de la línea de entrada, y luego restaura la terminal a un estado que es adecuado para su uso con las instalaciones stdio de C. Lo último incluye cosas como restaurar el mapeo normal de \n a \r\n, y, cuando está en modo servidor, restaurar la forma normal de bloqueo de la E/S de la terminal. Después de haber llamado a esta función, la acción puede leer de y escribir a la terminal sin el temor de crear un desorden. No es necesario para la función de acción restaurar el entorno de edición original antes de que regrese. Esto se hace automáticamente por gl_get_line() después de que la función de acción regrese. Lo siguiente es un ejemplo simple de una función de acción que escribe la frase "Hello world" en una nueva línea de terminal después de la línea que se está editando. Cuando esta función regresa, la línea de entrada se redibuja en la línea que sigue a la línea "Hello world", y la edición de línea se

reanuda. 
  static GL_ACTION_FN(say_hello_fn)
  {
    if(gl_normal_io(gl))   /* Suspender temporalmente la edición */
      return GLA_ABORT;
    printf("Hello world\n");
    return GLA_CONTINUE;
}

proceder. 
  GLA_ABORT     -   Hace que gl_get_line() devuelva NULL.
  GLA_RETURN    -   Hace que gl_get_line() devuelva la
                    línea de entrada completada.
  GLA_CONTINUE  -   Reanuda la edición de la línea de
comando.

Tenga en cuenta que el argumento name de gl_register_action() especifica el nombre con el que un usuario puede referirse a la acción en su archivo de configuración. Esto le permite volver a vincular la acción a una secuencia de teclas alternativa. Para que esto funcione, es necesario llamar a gl_register_action() entre la llamada a new_GetLine() y la primera llamada a gl_get_

SEÑALES

Por defecto, la función gl_get_line() intercepta un número de señales. Esto es particularmente importante para las señales que por defecto terminarían el proceso, ya que la terminal necesita ser restaurada a un estado utilizable antes de que esto suceda. En esta sección, se describen las señales que son atrapadas por defecto y cómo gl_get_line() responde a ellas. Cambiar estos valores por defecto es el tema de la siguiente

sección.

Cuando se captura el siguiente subconjunto de señales, gl_get_line() primero restaura la configuración de la terminal y el manejo de señales a como estaban antes de que se llamara a gl_get_line(), reenvía la señal para permitir que los manejadores de señal de la aplicación que llama la manejen, luego, si el proceso aún existe, gl_get_line() devuelve NULL y establece errno como se especifica a

continuación. 
 SIGINT  -  Esta señal es generada tanto por la tecla de
            interrupción del teclado (usualmente ^C), como por la tecla de
            corte del teclado.
            errno=EINTR
 SIGHUP  -  Esta señal es generada cuando la terminal de control sale.
            errno=ENOTTY
 SIGPIPE -  Esta señal es generada cuando un programa intenta escribir
            en un pipe cuyo extremo remoto no está siendo leído por ningún
            proceso. Esto puede suceder, por ejemplo, si ha llamado a gl_change_terminal() para redirigir la salida a un pipe oculto
            bajo un pseudo-terminal.
            errno=EPIPE
 SIGQUIT -  Esta señal es generada por la tecla de salida del teclado
            (usualmente ^\).
            errno=EINTR
 SIGABRT -  Esta señal es generada por la función estándar de C,
            abort(). Por defecto, tanto termina el proceso como genera un
            volcado de memoria (core dump).
            errno=EINTR
 SIGTERM -  Esta es la señal por defecto que el comando kill de UN*X
            envía a los procesos.
errno=EINTR

En otras palabras, si la aplicación que llama no anula el manejador por defecto proporcionando su propio manejador de señal, la recepción de la señal correspondiente terminará la aplicación antes de que gl_get_line()

regrese.

aplicación.

               terminal, que usualmente es ^Z, o la tecla de suspensión
               retrasada de la terminal, que usualmente es ^Y.
 SIGTTIN    -  Esta señal es generada si el programa intenta leer de la
               terminal mientras el programa se está ejecutando en el
               segundo plano.
 SIGTTOU    -  Esta señal es generada si el programa intenta escribir en
               la terminal mientras el programa se está ejecutando en el
               segundo
plano.

Obviamente, no todas las señales anteriores están soportadas en todos los sistemas, por lo que el código para soportarlas se compila condicionalmente en la biblioteca

tecla.

Tenga en cuenta que si SIGKILL o SIGPOLL, que por definición no pueden ser capturadas, o cualquiera de las señales de excepción generadas por el hardware, como SIGSEGV, SIGBUS y SIGFPE, son recibidas y no manejadas mientras gl_get_line() tiene la terminal en modo crudo, el programa será terminado sin que la terminal haya sido restaurada a un estado utilizable. En la práctica, los shells de control de

trabajos usualmente restablecen la configuración de la terminal cuando un proceso renuncia
a la terminal de control, por lo que esto solo es un problema con shells más antiguos.

MANEJO DE SEÑALES

PERSONALIZADO

La sección anterior listó las señales que gl_get_line() atrapa por defecto y describió cómo responde a ellas. Esta sección describe cómo tanto agregar como remover señales de la lista de señales atrapadas, y cómo especificar cómo gl_get_line() debería responder a una señal

dada.

Si no necesita que gl_get_line() haga algo en respuesta a una señal que normalmente atrapa, puede decirle a gl_get_line() que ignore esa señal llamando a gl_ignore_sig

nal(). 
  int gl_ignore_signal(GetLine *gl, int signo)
;

El argumento signo es el número de la señal (por ejemplo, SIGINT) que quiere que sea ignorada. Si la señal especificada no es actualmente una de las que están siendo atrapadas, esta función no hace

nada.

La función gl_trap_signal() le permite tanto agregar una nueva señal a la lista que gl_get_line() atrapa, como modificar cómoresponde a una señal que ya está atrapando.

  int gl_trap_signal(GetLine *gl, int signo, unsigned flags,
                     GlAfterSignal after, int errno_value);

El argumento signo es el número de la señal que desea atrapar. El argumento flags es un conjunto de banderas que determinan el entorno en el que se invoca el manejador de señales de la aplicación, el argumento after le dice a gl_get_line() qué hacer después de que el manejador de señales de la aplicación retorne, y errno_value le dice a gl_get_line() qué valor establecer para errno si se le indica que aborte.

El argumento flags es una operación OR a nivel de bits de cero o más de los siguientes enumeradores:

  GLS_RESTORE_SIG  -  Restaura el entorno de señales
                      del llamador mientras se maneja
                      la señal.
  GLS_RESTORE_TTY  -  Restaura la configuración de la
                      terminal del llamador mientras se
                      maneja la señal.
  GLS_RESTORE_LINE -  Mueve el cursor al inicio de la
                      línea después de la línea de
                      entrada antes de invocar el
                      manejador de señales de la
                      aplicación.
  GLS_REDRAW_LINE  -  Redibuja la línea de entrada cuando
                      el manejador de señales de la
                      aplicación retorna.
  GLS_UNBLOCK_SIG  -  Normalmente, si el programa llamador
                      tiene una señal bloqueada (man
                      sigprocmask), gl_get_line() no
                      atrapa esa señal. Esta bandera le
                      dice a gl_get_line() que atrape
                      la señal y la desbloquee durante
                      la llamada a gl_get_line().
  GLS_DONT_FORWARD -  Si se incluye esta bandera, la señal
                      no se reenviará al manejador de
                      señales del programa llamador.

Dos combinaciones de banderas comúnmente útiles también se enumeran de la siguiente manera:

  GLS_RESTORE_ENV   = GLS_RESTORE_SIG | GLS_RESTORE_TTY |
                      GLS_REDRAW_LINE
  GLS_SUSPEND_INPUT = GLS_RESTORE_ENV | GLS_RESTORE_LINE

Si su manejador de señales, o el manejador de señales del sistema por defecto para esta señal, si no lo ha anulado, nunca escribe en la terminal, ni suspende o termina el programa llamador, entonces puede establecer de forma segura el argumento flags a 0.

Si su manejador de señales siempre escribe en la terminal, lee de ella, o suspende o termina el programa, debe especificar el argumento flags como GL_SUSPEND_INPUT, para que:

1. El cursor no quede en medio de la línea de entrada.
2. Para que el usuario pueda escribir entrada y que esta sea
   reflejada.
3. Para que no necesite terminar cada línea de salida con
   \r\n, en lugar de solo \n.

La combinación GL_RESTORE_ENV es la misma que GL_SUSPEND_INPUT, excepto que no mueve el cursor, y si su manejador de señales no lee ni escribe nada en la terminal, el usuario no verá ninguna indicación visible de que se atrapó una señal. Esto puede ser útil si tiene un manejador de señales que solo escribe ocasionalmente en la terminal, donde usar GL_SUSPEND_LINE causaría que la línea de entrada se duplique innecesariamente cuando no se ha escrito nada en la terminal. Dicho manejador de señales, cuando sí escribe en la terminal, debe asegurarse de iniciar una nueva línea al principio de su primera escritura, escribiendo una nueva línea antes de retornar. Si la señal llega mientras el usuario está introduciendo una línea que solo ocupa una línea de terminal, o si el cursor está en la última línea de terminal de una línea de entrada más larga, esto tendrá el mismo efecto que GL_SUSPEND_INPUT. De lo contrario, comenzará a escribir en una línea que ya contiene parte de la línea de entrada mostrada. Esto no causa ningún daño, pero se ve un poco feo, razón por la cual la combinación GL_SUSPEND_INPUT es mejor si sabe que siempre va a escribir en la terminal.

El argumento after, que determina qué hace gl_get_line() después de que el manejador de señales de la aplicación retorna (si retorna), puede tomar cualquiera de los siguientes valores:

  GLS_RETURN   - Retorna la línea de entrada completada, como si
                 el usuario hubiera presionado la tecla de retorno.
  GLS_ABORT    - Hace que gl_get_line() aborte. Cuando esto
                 sucede, gl_get_line() retorna NULL, y
                 una llamada posterior a gl_return_status()
                 retornará GLR_SIGNAL. Tenga en cuenta que si
                 la aplicación necesita que errno siempre
                 tenga un valor significativo cuando
                 gl_get_line() retorna NULL, la
                 función de devolución de llamada debe establecer
                 errno apropiadamente.
  GLS_CONTINUE - Reanuda la edición de la línea de comandos.

El argumento errno_value está destinado a combinarse con la opción GLS_ABORT, indicando a gl_get_line() qué valor establecer en la variable estándar errno antes de retornar NULL al programa llamador. Sin embargo, también se puede usar con la opción GL_RETURN, en caso de que desee tener una forma de distinguir entre una línea de entrada que se ingresó usando la tecla de retorno y una que se ingresó por la recepción de una señal.

MANEJO DE SEÑALES CONFIABLE

El manejo de señales es sorprendentemente difícil de hacer de forma confiable sin condiciones de carrera. En gl_get_line() se ha puesto mucha atención para permitir que las aplicaciones realicen un manejo de señales confiable alrededor de gl_get_line(). Esta sección explica cómo hacer uso de esto.

Como ejemplo de los problemas que pueden surgir si la aplicación no está escrita correctamente, imagine que una aplicación tiene un manejador de señales SIGINT que establece una bandera global. Ahora suponga que la aplicación prueba esta bandera justo antes de invocar gl_get_line(). Si una señal SIGINT llega a recibirse en la pequeña ventana de tiempo entre la instrucción que prueba el valor de esta bandera y la instrucción que llama a gl_get_line(), entonces gl_get_line() no verá la señal y no se interrumpirá. Como resultado, la aplicación no podrá responder a la señal hasta que el usuario termine de ingresar la línea de entrada y gl_get_line() retorne. Dependiendo de la aplicación, esto podría ser o no un desastre, pero al menos desconcertaría al usuario.

La forma de evitar tales problemas es hacer lo siguiente.

1. Si es necesario, use la función gl_trap_signal() para
configurar gl_get_line() para que aborte cuando se
atrapan señales importantes.

2. Configure gl_get_line() de tal manera que si alguna de
las señales que atrapa está bloqueada cuando se
llama a gl_get_line(), se desbloqueará
automáticamente durante los momentos en que
gl_get_line() está esperando E/S. Esto se puede
hacer, ya sea por señal individualmente, llamando a la
función gl_trap_signal() y especificando el
atributo GLS_UNBLOCK de la señal, o globalmente
llamando a la función gl_catch_blocked().

     void gl_catch_blocked(GetLine *gl);


Esta función simplemente agrega el atributo
GLS_UNBLOCK a todas las señales que está
actualmente configurada para atrapar.

3. Justo antes de llamar a gl_get_line(), bloquee la
entrega de todas las señales que gl_get_line()
está configurada para atrapar. Esto se puede hacer
usando la función POSIX sigprocmask() en
conjunción con la función gl_list_signals().

      int gl_list_signals(GetLine *gl, sigset_t *set);


Esta función devuelve el conjunto de señales que está
actualmente configurada para atrapar en el argumento
set, que está en el formato requerido por
sigprocmask().

4. En el ejemplo, ahora probaría la bandera global que
establece el manejador de señales, sabiendo que ahora
no hay peligro de que esta bandera se establezca de
nuevo hasta que gl_get_line() desbloquee sus
señales al realizar E/S.

5. Eventualmente gl_get_line() retorna, ya sea porque
se atrapó una señal, ocurrió un error, o el usuario
terminó de ingresar su línea de entrada.

6. Ahora probaría la bandera global de señales nuevamente, y
si está establecida, respondería a ella y pondría la
bandera a cero.

7. Use sigprocmask() para desbloquear las señales que
fueron bloqueadas en el paso 3.

La misma técnica se puede utilizar alrededor de ciertas funciones POSIX conscientes de señales, como sigsetjmp() y sigsuspend(), y en particular, la primera de estas dos funciones se puede usar en conjunción con siglongjmp() para implementar un manejo de señales libre de condiciones de carrera alrededor de otras llamadas del sistema de larga duración. La forma de hacer esto se explica a continuación, mostrando cómo gl_get_line() logra atrapar señales de manera confiable alrededor de llamadas a funciones como read() y select() sin condiciones de carrera.

Lo primero que hace gl_get_line(), cada vez que se llama, es utilizar la función POSIX sigprocmask() para bloquear la entrega de todas las señales que está configurada para atrapar. Esto es redundante si la aplicación ya las ha bloqueado, pero no causa daño. Deshace este paso justo antes de retornar.

Cada vez que gl_get_line() necesita llamar a read() o select() para esperar la entrada del usuario, primero llama a la función POSIX sigsetjmp(), asegurándose de especificar un valor distinto de cero para su argumento savesigs. La razón del último argumento se aclarará en breve.

Si sigsetjmp() retorna cero, gl_get_line() hace lo siguiente.

a. Utiliza la función POSIX sigaction() para registrar
   un manejador de señales temporal para todas las señales
   que está configurada para atrapar. Este manejador de
   señales hace dos cosas.
   1. Registra el número de la señal recibida en una
      variable a nivel de archivo.
   2. Luego llama a la función POSIX siglongjmp()
      usando el búfer que se pasó a sigsetjmp()
      como primer argumento, y un valor distinto de cero
      como segundo argumento.
   Cuando se registra este manejador de señales, el miembro
   sa_mask de la estructura struct sigaction act
   del argumento de la llamada a sigaction() se
   configura para contener todas las señales que
   gl_get_line() está atrapando. Esto asegura que
   solo una señal sea atrapada a la vez por nuestro manejador
   de señales, lo que a su vez asegura que múltiples instancias
   de nuestro manejador de señales no se pisen los talones.
b. Ahora que el manejador de señales ha sido configurado,
   gl_get_line() desbloquea todas las señales que está
   configurada para atrapar.
c. Luego llama a las llamadas al sistema read() o
   select() para esperar la entrada del teclado.
d. Si esta llamada al sistema retorna (es decir, no se recibe
   ninguna señal), gl_get_line() bloquea nuevamente la
   entrega de las señales de interés.
e. Luego restaura los manejadores de señales que fueron
   desplazados por el que se acaba de instalar.

Alternativamente, si sigsetjmp() retorna un valor distinto de cero, esto significa que

en uno de los señales que se están atrapando fue capturada mientras los pasos anteriores se estaban ejecutando. Cuando esto sucede, gl_get_line() hace lo

siguiente.

Primero, tenga en cuenta que cuando una llamada a siglongjmp() hace sigsetjmp() regresar, siempre que el argumento savesigs de sigsetjmp() fuera distinto de cero, como se especificó anteriormente, la máscara de proceso de la señal se restaura a cómo estaba cuando sigsetjmp() fue llamado. Esta es la diferencia importante entre sigsetjmp() y el antiguo problemático setjmp(), y es el ingrediente esencial que hace posible evitar condiciones de carrera en el manejo de señales. Debido a esto, se garantiza que todas las señales que bloqueamos antes de llamar a sigsetjmp() estén bloqueadas nuevamente tan pronto como cualquier señal sea capturada. Las siguientes declaraciones, que se ejecutan a continuación, están por lo tanto garantizadas para ser ejecutadas sin que se capturen más

señales.

1. Si así se lo indica por los atributos de configuración de
gl_get_line() de la señal que fue capturada,
gl_get_line() restaura los atributos del terminal a
el estado que tenían cuando gl_get_line() fue
llamado. Esto es particularmente importante para las señales que
suspenden o terminan el proceso, ya que de lo contrario el
terminal quedaría en un estado

inutilizable.

2. Luego reinstala los manejadores de señales de la

aplicación.

3. Luego usa la función raise()
de la biblioteca estándar de C para reenviar a la aplicación la señal que
fue

capturada.

3. A continuación, desbloquea la entrega de la señal que acabamos de
enviar. Esto resulta en que la señal que acababa de ser enviada
vía raise(), sea capturada por el manejador de señales
original de la aplicación, que ahora puede manejarla como
considere

adecuado.

4. Si el manejador de señales regresa (es decir, no termina
el proceso), gl_get_line() bloquea la entrega de la
señal anterior

nuevamente.

5. Luego deshace cualquier acción realizada en el primero de los
pasos anteriores, y vuelve a mostrar la línea, si la configuración de la señal
lo

requiere.

6. gl_get_line() luego reanuda el intento de
leer un carácter, o se aborta, dependiendo de la
configuración de la señal que fue

capturada.

Lo que los pasos anteriores hacen en esencia es tomar señales entregadas de forma asíncrona y manejarlas de forma síncrona, una a la vez, en un punto del código donde gl_get_line() tiene control c

ompleto sobre s
u entorno.

EL TAMAÑO DEL

TERMINAL

En la mayoría de los sistemas, la combinación de el ioctl TIOCGWINSZ y la señal SIGWINCH se utiliza para mantener una idea precisa del tamaño del terminal. El tamaño del terminal se consulta nuevamente cada vez que gl_get_line() es llamado y siempre que se recibe una señal SIGW

INCH.

En los pocos sistemas donde este mecanismo no está disponible, al inicio new_GetLine() primero busca las variables de entorno LINES y COLUMNS. Si estas no se encuentran, o contienen valores inutilizables, entonces si está disponible una base de datos de información del terminal como terminfo o termcap, se busca el tamaño por defecto del terminal en esta base de datos. Si esto también falla para proporcionar el tamaño del terminal, se usa un tamaño por defecto de 80 columnas por 24

líneas.

Incluso en sistemas que sí soportan ioctl(TIOCGWINSZ), si el terminal está en el otro extremo de una línea serie, el controlador del terminal generalmente no tiene forma de detectar cuándo ocurre un redimensionamiento ni de consultar cuál es el tamaño actual. En tales casos, no se envía ningún SIGWINCH al proceso, y las dimensiones devueltas por ioctl(TIOCGWINSZ) no son correctas. La única forma de manejar tales instancias es proporcionar una manera para que el usuario ingrese un comando que le diga al sistema remoto cuál es el nuevo tamaño. Este comando entonces llamaría a la función gl_set_term_size() para decirle a gl_get_line() sobre el cambio de

tamaño. 
  int gl_set_term_size(GetLine *gl, int ncolumn, int nline)
;

Los argumentos ncolumn y nline se utilizan para especificar las nuevas dimensiones del terminal, y no deben ser menores que 1. En sistemas que sí soportan ioctl(TIOCGWINSZ), esta función primero llama a ioctl(TIOCSWINSZ) para informar al controlador del terminal sobre el cambio en el tamaño. En el modo de E/S de servidor no bloqueante, si actualmente se está ingresando una línea, la línea de entrada se redibuja para acomodar el tamaño cambiado. Finalmente, los nuevos valores se registran en gl para uso futuro por gl_get_li

ne().

La función gl_terminal_size() le permite consultar el tamaño actual del terminal, e instalar un tamaño de respaldo alternativo para los casos en que el tamaño no esté disponible. Tenga en cuenta que el tamaño del terminal no estará disponible si se está leyendo de una tubería o de un archivo, por lo que los valores por defecto pueden ser importantes incluso en sistemas que sí soportan formas de averiguar el tamaño del

terminal. 
  typedef struct {
    int nline;        /* El terminal tiene nline líneas */
    int ncolumn;      /* El terminal tiene ncolumn columnas */
  } GlTerminalSize;
  GlTerminalSize gl_terminal_size(GetLine *gl,
                                  int def_ncolumn,
                                  int def_nline)
;

Esta función primero actualiza las dimensiones de respaldo del terminal de gl_get_line(), luego registra sus hallazgos en el valor de

retorno.

Los argumentos def_ncolumn y def_nline especifican el número por defecto de columnas y líneas del terminal a usar si el tamaño del terminal no puede ser determinado vía ioctl(TIOCGWINSZ) o

variables d
e entorno.

OCULTANDO LO QUE

ESCRIBES

Al ingresar información sensible, como contraseñas, es mejor no tener el texto que está ingresando reflejado en el terminal. Además, dicho texto no debería ser registrado en la lista de historial, ya que alguien que encuentre su terminal desatendida podría entonces recuperarlo, o alguien husmeando en sus directorios podría verlo en su archivo de historial. Teniendo esto en cuenta, la función gl_echo_mode() le permite alternar la visualización y el archivo de cualquier texto que se ingrese posteriormente en las llamadas a gl_get_li

ne(). 
  int gl_echo_mode(GetLine *gl, int enable)
;

El argumento enable especifica si el texto ingresado debe ser visible o no. Si es 0, entonces las líneas ingresadas posteriormente no serán visibles en el terminal, y no serán registradas en la lista de historial. Si es 1, entonces las líneas de entrada posteriores se mostrarán a medida que se ingresan, y siempre que el historial no haya sido desactivado vía una llamada a gl_toggle_history(), también serán archivadas en la lista de historial. Finalmente, si el argumento enable es -1, entonces el modo de eco se deja sin cambios, lo que le permite consultar de forma no destructiva la configuración actual a través del valor de retorno. En todos los casos, el valor de retorno de la función es 0 si el eco estaba deshabilitado antes de que la función fuera llamada, y 1 si estaba

habilitado.

Cuando el eco está desactivado, tenga en cuenta que aunque la final

ización con tabulador completará invisiblemente su prefijo lo
más lejos posible, las finalizaciones ambiguas no se mostrarán.

CONSULTAS DE UN SOLO

CARÁCTER

Usar gl_get_line() para consultar al usuario para una respuesta de un solo carácter, es inconveniente para el usuario, ya que debe presionar la tecla intro o retorno antes de que el carácter que escribió sea devuelto al programa. Por lo tanto, se ha proporcionado la función gl_query_char() para consultas de un solo carácter como

esta. 
  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar)
;

Esta función muestra el prompt especificado al comienzo de una nueva línea, y espera a que el usuario escriba un carácter. Cuando el usuario escribe un carácter, gl_query_char() lo muestra a la derecha del prompt, inicia una nueva línea, y luego devuelve el carácter al programa llamador. El valor de retorno de la función es el carácter que fue escrito. Si la lectura tuvo que ser abortada por alguna razón, se devuelve EOF en su lugar. En el último caso, la aplicación puede llamar a la previamente documentada gl_return_status(), para averiguar qué salió mal. Esto podría, por ejemplo, haber sido la recepción de una señal, o el temporizador opcional de inactividad

activándose.

Si el usuario simplemente presiona intro, el valor del argumento defchar se sustituye. Esto significa que cuando el usuario presiona ya sea nueva línea o retorno, el carácter especificado en defchar, se muestra después del prompt, como si el usuario lo hubiera escrito, así como ser devuelto a la aplicación llamadora. Si tal reemplazo no es importante, simplemente pase '0 como el valor de defchar

.

Si el carácter ingresado es un carácter no imprimible, se muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y los caracteres más allá de 127 se muestran en octal, precedidos por una barra

invertida.

Al igual que con gl_get_line(), el eco del carácter ingresado puede ser deshabilitado usando la función gl_echo_mode()

.

Si el proceso llamador es suspendido mientras espera a que el usuario escriba su respuesta, el cursor se mueve a la línea siguiente a la línea del prompt, luego cuando el proceso se reanuda, el prompt se vuelve a mostrar, y gl_query_char() reanuda la espera de que el usuario escriba un

carácter.

Tenga en cuenta que en el modo de servidor no bloqueante, (vea gl_io_mode(3)), si una línea de entrada incompleta está en proceso de ser leída cuando gl_query_char() es llamada, la línea de entrada parcial se descarta, y se borra del terminal, antes de que se muestre el nuevo prompt. La siguiente llamada a gl_get_line() comenzará por lo

tanto a editar
una nueva línea.

LEYENDO CARACTERES

CRUDOS

Mientras que la función gl_query_char() solicita visiblemente al usuario un carácter, y muestra lo que escribió, la función gl_read_char() lee un carácter de señal del usuario, sin escribir nada en el terminal, o perturbar alguna línea de entrada incompleta. Esto significa que puede ser llamada no solo entre las llamadas a gl_get_line(), sino también desde funciones de retorno de llamada que la aplicación ha registrado para ser llamadas por gl_get_li

ne(). 
  int gl_read_char(GetLine *gl)
;

En caso de éxito, el valor de retorno de gl_read_char() es el carácter que fue leído. En caso de fallo, se devuelve EOF, y la función gl_return_status() puede ser llamada para averiguar qué salió mal. Las posibilidades incluyen el temporizador opcional de inactividad activándose, la recepción de una señal que está configurada para abortar gl_get_line(), o el bloqueo de E/S del terminal, cuando se está en el modo de E/S de servidor no

bloqueante.

Tenga en cuenta que ciertas teclas del teclado, como las teclas de función y las teclas de cursor, usualmente generan al menos 3 caracteres cada una, por lo que una sola llamada a gl_read_char() no será suficiente par

a identificar dichas
pulsaciones de teclas.

El argumento indentation especifica el número de caracteres a usar para sangrar cada línea de la salida. El argumento fill_char especifica el carácter que se usará para realizar esta

sangría.

El argumento prefix puede ser NULL, o ser una cadena de texto a colocar al comienzo de cada nueva línea (después de cualquier sangría). De manera similar, el argumento suffix puede ser NULL, o ser una cadena de texto a colocar al final de cada línea. El sufijo se coloca alineado contra el borde derecho de la terminal, y cualquier espacio entre su primer carácter y la última palabra de esa línea se rellena con el carácter especificado mediante el argumento fill_char. Normalmente el carácter de relleno es un

espacio.

INTERNACIONALES

Desde la versión 1.4.0 de libtecla, gl_get_line() ha sido compatible con 8 bits. Esto significa que todos los caracteres de 8 bits que son imprimibles en la configuración regional actual del usuario ahora se muestran de forma literal y se incluyen en la línea de entrada devuelta. Asumiendo que el programa que llama contiene correctamente una llamada como la

siguiente, 
  setlocale(LC_CTYPE, "")
;

entonces la configuración regional actual está determinada por la primera de las variables de entorno LC_CTYPE, LC_ALL, y LANG, que se encuentre que contiene un nombre de configuración regional válido. Si ninguna de estas variables está definida, o el programa omite llamar a setlocale, entonces se utiliza la configuración regional C predeterminada, que es ASCII de 7 bits de EE. UU. En la mayoría de las plataformas tipo unix, se puede obtener una lista de configuraciones regionales válidas escribiendo el

comando: 
  locale
-a

SEGURIDAD DE

HILOS

En un programa multi-hilo, se debería usar la versión libtecla_r.a de la biblioteca. Esta usa versiones reentrantes de las funciones del sistema, cuando están disponibles. Desafortunadamente, ni terminfo ni termcap fueron diseñados para ser reentrantes, por l

o que no se pueden usar de forma segura las funciones del módulo getline en múltiples hilos (se pueden usar los módulos separados de expansión de archivos y finalización de palabras en múltiples hilos, véanse las páginas de manual correspondientes para más d
etalles). Sin embargo, debido al uso de funciones reentrantes de POSIX para buscar directorios de inicio, etc., es seguro usar este módulo desde un solo hilo de un programa multi-hilo, siempre que sus otros hilos no usen ninguna función de termcap o terminfo.
