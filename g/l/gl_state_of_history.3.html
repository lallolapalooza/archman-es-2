función gl_get_line() es parte de la biblioteca tecla (ver la página man libtecla(3)). Si el usuario está escribiendo en un terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de unix. Además de la edición de línea de comandos simple, soporta el recuerdo de líneas de comandos introducidas previamente, la completación con TAB de nombres de archivos, y la expansión de comodines en línea de nombres de archivos. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario, se puede encontrar en la página man tecla(7). Esta página man se ocupa de la documentación para programadores interesados en usar esta biblioteca en su aplicación. UN E

Esta función crea los recursos usados por la función gl_get_line() y retorna un puntero opaco al objeto que los contiene. La función gl_get_line() puede ser llamada cualquier número de veces para leer entrada del usuario. El argumento gl debe haber sido retornado previamente por una llamada a new_GetLine(). El argumento prompt debería ser una cadena normal terminada en NUL, especificando el prompt a presentar al usuario. Por defecto los prompts se muestran literalmente, pero si se habilitan con la función gl_prompt_style() (ver más adelante), los prompts pueden contener directivas para subrayar, cambiar a y de fuentes en negrita, o activar y desactivar el

resaltado.

Si quieres especificar el contenido inicial de la línea, para que el usuario la edite, pasa la cadena deseada vía el argumento start_line. Luego puedes especificar qué carácter de esta línea debe ser inicialmente posicionadoen segundo plano, utilizando el argumento start_pos. Este debe ser -1 si deseas que el cursor siga al último carácter de la línea de inicio. Si no deseas precargar la línea de esta manera, envía start_line como NULL y establece start_pos a -1. Ten en cuenta que el puntero de línea devuelto por una llamada a gl_get_line() puede pasarse a la siguiente llamada a gl_get_line() a través de start_line. Esto permite a la aplicación tomar la última línea introducida y, si contiene un error, presentarla nuevamente al usuario para su reedición, con el cursor posicionado inicialmente donde se encontró el error.

La función gl_get_line() devuelve un puntero a la línea introducida por el usuario, o NULL en caso de error o al final de la entrada. El puntero devuelto forma parte del objeto de recurso gl especificado y, por lo tanto, el llamador no debe liberarlo ni asumir que no cambiará de una llamada a otra. Al leer desde un usuario en una terminal, siempre habrá un carácter de nueva línea al final de la línea devuelta. Cuando la entrada estándar se está tomando de una tubería o un archivo, similarmente habrá una nueva línea a menos que la línea de entrada fuera demasiado larga para almacenarse en el búfer interno. En este último caso, debes llamar a gl_get_line() nuevamente para leer el resto de la línea. Ten en cuenta que este comportamiento hace que gl_get_line() sea similar a fgets(). De hecho, cuando stdin no está conectado a una terminal, gl_get_line() simplemente llama a fgets().

FUENTES DE CONFIGURACIÓN ALTERNATIVAS

Como se mencionó anteriormente, por defecto los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es una ventaja y una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. Sin embargo, en algunas aplicaciones, este único medio de configuración es un problema. Esto es particularmente cierto en el software integrado, donde no hay un sistema de archivos para leer un archivo de configuración, y también en aplicaciones donde se necesita una opción radicalmente diferente de asignaciones de teclas para emular una interfaz de teclado heredada. Para atender tales casos, la siguiente función permite a la aplicación controlar de dónde se leen las informaciones de configuración.

  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file);

Permite que los comandos de configuración que normalmente se leerían de un archivo ~/.teclarc del usuario, se lean de cualquiera o ninguna de las siguientes opciones: una cadena, un archivo de configuración específico de la aplicación y/o un archivo de configuración específico del usuario. Si esta función se llama antes de la primera llamada a gl_get_line(), se deshabilita el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line(), por lo que toda la configuración debe lograrse utilizando las fuentes de configuración especificadas con esta función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados entre sí en la cadena por caracteres de nueva línea incrustados. Si app_file != NULL, entonces se interpreta como la ruta completa de un archivo de configuración específico de la aplicación. Si user_file != NULL, entonces se interpreta como la ruta completa de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente llamada,

  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc");

el argumento app_string hace que la aplicación que llama comience en modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso de la campana de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración del sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario desde un archivo opcional .teclarc en el directorio de inicio del usuario. Tenga en cuenta que los argumentos se enumeran en orden ascendente de prioridad, y el contenido de app_string puede ser anulado por comandos en app_file, y los comandos en app_file pueden ser anulados por comandos en user_file.

Puede llamar a esta función tantas veces como sea necesario, siendo los resultados acumulativos, pero tenga en cuenta que copias de cualquier nombre de archivo especificado a través del

>app_file y los argumentos user_file se registran internamente para su uso posterior por parte de la función de enlace de teclas read-init-files, así que si planea llamar a esta función varias veces, asegúrese de que la última llamada especifique los nombres de archivo que desea releer cuando el usuario solicite que se relean los archivos de

configuración.

PERSONALIZADO

Si en su aplicación desea que el completado con TAB complete otras cosas además de o en lugar de nombres de archivo, puede organizarlo registrando una función de retorno de completado alternativa, mediante una llamada a la función gl_customize_co

mpletion(). 
  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn)

El argumento data proporciona una manera para que su aplicación pase información arbitraria específica de la aplicación a la función de retorno. Esto se pasa a la función de retorno cada vez que se la llama. Podría, por ejemplo, apuntar a la tabla de símbolos de la que se deben buscar los posibles completados. El argumento match_fn especifica la función de retorno a llamar. El tipo de función CplMatchFn está definido en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y prototipar funciones de retorno. La declaración y las responsabilidades de las funciones de retorno se describen en profundidad en la página de manual de cpl_complete_word(3)

.

En resumen, la función de retorno es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario pulsó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar posibles completados de esta palabra y registrarlos uno por uno en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion(). Si la función de retorno desea proporcionar completado de nombres de archivo además de sus propios completados específicos, tiene la opción de llamar por sí misma a la función de retorno de completado de nombres de archivo incorporada. Esto también está documentado en la página de manual de cpl_complete_word(3)

.

Tenga en cuenta que si desea que gl_get_line() devuelva la línea de entrada actual cuando se haya realizado un completado exitoso, puede organizarlo cuando llame a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de nueva línea. Si hace esto, la línea de entrada se actualizará para mostrar el completado, junto con cualquier sufijo de continuación hasta el carácter de nueva línea, y luego gl_get_line() devolverá esta línea de

entrada.

Si por alguna razón su función de retorno necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto iniciará una nueva línea después de la línea de entrada que se está editando actualmente, restablecerá la E/S normal de la terminal y le dirá a gl_get_line() que la línea de entrada necesitará

ser redibujada cuando la f
unción de retorno regrese.

COMPLETADO

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de completado predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que se puedan enlazar diferentes tipos de completado de palabras a diferentes secuencias de teclas. Esto se logra usando la función gl_completion_action()

. 
  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq)
;

Los argumentos data y match_fn se describen como en la página de manual de cpl_complete_word, y especifican la función de retorno que debe invocarse para identificar posibles completados. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar cualquier completado ambiguo posible, o si debe simplemente mostrar la lista de posibles completados sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre con el que los archivos de configuración y las futuras invocaciones de esta función deben referirse a la acción. Este debe ser el nombre de una acción de completado existente que se va a cambiar, o un nombre nuevo sin usar para una nueva acción. Finalmente, el argumento keyseq especifica la secuencia de teclas predeterminada para enlazar la acción. Si esto es NULL, no se enlazará ninguna nueva secuencia de teclas a la

acción.

Tenga cuidado de que para que el usuario pueda cambiar la secuencia de teclas que está enlazada a las acciones instaladas de esta manera, cuando llame a gl_completion_action() para instalar una acción dada por primera vez, debe hacerlo entre la llamada a new_GetLine() y la primera llamada a gl_get_line(). De lo contrario, cuando se lea el archivo de configuración del usuario en la primera llamada a gl_get_line(), el nombre de su acción adicional no será conocido, y cualquier referencia a ella en el archivo de configuración generará un

error.

Como se discutió para gl_customize_completion(), si su función de retorno, por alguna razón, necesita escribir algo en la terminal, debe llamar a gl_normal_io() a

ntes de
hacerlo.

Aunque las acciones de enlace de teclas incorporadas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, enlazadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza que correspondiera a un número de pieza precedente al cursor. Tal característica está claramente fuera del alcance de las funciones de acción incorporadas. Así que para tales casos especiales, se proporciona la función gl_register_action()

. 
  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq)
;

Esta función permite a la aplicación registrar una función externa, fn, que a partir de entonces será llamada cada vez que se introduzca la secuencia de teclas especificada, keyseq, por el usuario, o que el usuario introduzca cualquier otra secuencia de teclas que el usuario enlace posteriormente al nombre de acción especificado, name, en su archivo de configuración. El argumento data puede ser un puntero a cualquier cosa que la aplicación desee que se pase a la función de acción, fn, cada vez que esa función sea

invocada.

El argumento count es un argumento numérico que el usuario tiene la opción de introducir usando la acción digit-argument, antes de invocar la acción. Si el usuario no introduce un número, entonces el argumento count se establece en 1. Nominalmente, este argumento se interpreta como un conteo de repetición, lo que significa que la acción debe repetirse ese número de veces. Sin embargo, en la práctica, para algunas acciones un conteo de repetición tiene poco sentido. ACTION FUNCTIONS


An action function is one that has been registered with the
    gl_register_action() function, and which is called when the user
    presses a key sequence to which that action has been bound. It is passed a
    pointer to the GetLine object and is expected to return
    one of the values defined by the GLA_xxx macros.


  typedef int (*gl_action_func_t)(GetLine *gl));


The following is an example of an action function:


  int my_action(GetLine *gl)
  {
    if (gl_normal_io(gl))   /* Temporarily suspend editing */
      return GLA_ABORT;
    printf("Hello world\n");
    return GLA_CONTINUE;
  }


Action functions must return one of the following values, to tell
    gl_get_line() how to procede.


  GLA_ABORT     -   Cause gl_get_line() to return NULL.
  GLA_RETURN    -   Cause gl_get_line() to return the
                    completed input line.
  GLA_CONTINUE  -   Resume command-line editing.


Note that the name argument of gl_register_action()
    specifies the name by which a user can refer to the action in their
    configuration file. This allows them to re-bind the action to an alternate
    key-seqeunce. In order for this to work, it is necessary to call
    gl_register_action() between calling new_GetLine() and the
    first call to gl_get_line().






HISTORIAL DE ARCHIVOS


Para guardar el contenido del búfer de historial antes de salir de
    su aplicación y, posteriormente, restaurarlo la próxima vez que la inicie, se
    proporcionan las siguientes funciones.


 int gl_save_history(GetLine *gl, const char *filename,
                     const char *comment, int max_lines);
 int gl_load_history(GetLine *gl, const char *filename,
                     const char *comment);


El argumento filename especifica el nombre que se le dará al
    archivo de historial al guardar, o el nombre de un archivo de historial
    existente al cargar. Este puede contener expresiones de directorio de inicio
    y variables de entorno, como "~/.myapp_history" o
    "$HOME/.myapp_history".


Junto con cada línea del historial, se registra información
    adicional sobre ella, como cuándo fue ingresada por el usuario y cuál es su
    nivel de anidación, como un comentario que precede a la línea en el archivo
    de historial. Escribirlo como un comentario permite que el archivo de
    historial funcione también como un archivo de comandos, en caso de que
    desee reproducir una sesión completa utilizándolo. Dado que los prefijos de
    comentario difieren en diferentes idiomas, el argumento comment se
    proporciona para especificar el prefijo de comentario. Por ejemplo, si su
    aplicación fuera un shell de Unix, como el shell de Bourne, especificaría
    "#" aquí. Cualquiera que sea el carácter de comentario que elija,
    debe especificar el mismo prefijo a gl_load_history() que utilizó
    cuando llamó a gl_save_history() para escribir el archivo de
    historial.


El argumento max_lines debe ser -1 para especificar que se
    guarden todas las líneas de la lista de historial, o un número positivo que
    especifique un límite máximo de cuántas de las líneas más recientes se deben
    guardar.


Ambas funciones devuelven un valor distinto de cero en caso de error,
    después de escribir un mensaje de error en stderr. Tenga en cuenta que
    gl_load_history() no considera la no existencia de un archivo como un
    error.






LISTAS DE HISTORIAL MÚLTIPLES


Si su aplicación utiliza un único objeto GetLine para
    ingresar muchos tipos diferentes de líneas de entrada, es posible que desee
    que gl_get_line() distinga los diferentes tipos de líneas en la lista
    de historial y solo recupere líneas que coincidan con el tipo de línea
    actual. Para respaldar este requisito, gl_get_line() marca las
    líneas que se registran en la lista de historial con un identificador
    entero elegido por la aplicación. Inicialmente, este identificador se
    establece en 0 por new_GetLine(), pero se puede cambiar
    posteriormente llamando a gl_group_history().


  int gl_group_history(GetLine *gl, unsigned id);


El identificador entero id puede ser cualquier número elegido
    por la aplicación, pero tenga en cuenta que gl_save_history() y
    gl_load_history() conservan la asociación entre los identificadores y
    las líneas de entrada históricas entre invocaciones del programa, por lo que
    debe elegir identificadores fijos para los diferentes tipos de líneas de
    entrada utilizados por su aplicación.


Siempre que gl_get_line() agrega una nueva línea de entrada a
    la lista de historial, se registra el identificador de historial actual con
    ella, y cuando se le pide que recupere una línea de entrada histórica, solo
    recupera las líneas que están marcadas con el identificador actual.






MOSTRANDO EL HISTORIAL


La lista de historial se puede mostrar llamando a
    gl_show_history().


  int gl_show_history(GetLine *gl, FILE *fp,
                      const char *fmt,
                      int all_groups,
                      int max_lines);


Esto muestra el contenido actual de la lista de historial al flujo de
    salida stdio fp. Si el argumento max_lines es mayor o igual a
    cero, no se mostrarán más de las líneas más recientes. Si el argumento
    all_groups es distinto de cero, se mostrarán líneas de todos los
    grupos de historial. De lo contrario, solo se mostrarán las del grupo de
    historial actualmente seleccionado. El argumento de cadena de formato,
    fmt, determina cómo se muestra la línea. Esto puede contener caracteres
    arbitrarios que se escriben literalmente, intercalados con cualquiera de las
    siguientes directivas de formato:


  %D  -  La fecha en que se ingresó originalmente la línea,
         formateada como 2001-11-20.
  %T  -  La hora del día en que se ingresó la línea,
         formateada como 23:59:59.
  %N  -  El número secuencial de entrada de la línea en
         el búfer de historial.
  %G  -  El número del grupo de historial al que
         pertenece la línea.
  %%  -  Un carácter % literal.
  %H  -  La línea de historial en sí.


Por lo tanto, una cadena de formato como "%D %T %H\n
    produciría algo como:


  2001-11-20 10:23:34  Hola mundo


Tenga en cuenta la inclusión de un carácter de nueva línea explícito
    en la cadena de formato.






BUSCANDO EN EL HISTORIAL


La función gl_lookup_history() permite a la aplicación
    llamante buscar líneas en la lista de historial.


  typedef struct {
    const char *line;    /* La línea histórica solicitada */
                         /* */
    unsigned group;      /* El grupo de historial al que */
                         /* pertenece la línea. */
    time_t timestamp;    /* La fecha y hora en que */
                         /* se ingresó originalmente la */
                         /* línea. */
  } GlHistoryLine;
  int gl_lookup_history(GetLine *gl, unsigned long id,
                        GlHistoryLine *hline);


El argumento id indica qué línea buscar, donde la primera
    línea que se ingresó en la lista de historial después de llamar a
    new_GetLine() se denota con 0, y las líneas ingresadas posteriormente
    se denotan con números sucesivamente mayores. Tenga en cuenta que el rango de
    líneas actualmente conservadas en la lista de historial se puede consultar
    llamando a la función gl_range_of_history(), descrita más adelante.
    Si la línea solicitada está en la lista de historial, los detalles de la
    línea se registran en la variable apuntada por el argumento hline, y
    se devuelve 1. De lo contrario, se devuelve 0, y la variable
    apuntada por hline permanece sin cambios.


Tenga cuidado, ya que la cadena devuelta en hline->line
    es parte del búfer de historial, por lo que no debe ser modificada por el
    llamante y será reciclada en la próxima llamada a cualquier función que tome
    gl como argumento. Por lo tanto, debe hacer una copia privada de esta
    cadena si necesita conservarla.






ARCHIVO MANUAL DE HISTORIAL


Por defecto, cada vez que el usuario ingresa una línea, esta se
    agrega automáticamente a la lista de historial, justo antes de que
    gl_get_line() devuelva la línea al llamante. Esto es conveniente para
    la mayoría de las aplicaciones, pero también hay aplicaciones que necesitan un
    control más detallado sobre lo que se agrega a la lista de historial. En
    tales casos, la adición automática de las líneas ingresadas a la lista de
    historial se puede desactivar llamando a la función
    gl_automatic_history().


  int gl_automatic_history(GetLine *gl, int enable);


Si se llama a esta función con su argumento enable establecido
    en 0, gl_get_line() no archivará automáticamente las líneas
    ingresadas posteriormente. El archivo automático de historial se puede
    reactivar más tarde, llamando a esta función nuevamente, con su argumento
    enable establecido en 1. Mientras el archivo automático de historial
    está desactivado, la aplicación llamante puede usar
    gl_append_history() para agregar líneas a la lista de historial según
    sea necesario.


  int gl_append_history(GetLine *gl, const char *line);


El argumento line especifica la línea que se agregará a la
    lista de historial. Debe ser una cadena normal terminada en ' '.
    Si esta cadena contiene algún carácter de nueva línea, la línea que se
    archive en la lista de historial terminará con el primero de ellos. De lo
    contrario, terminará con el terminador ' '. Si la línea es
    más larga que la longitud máxima de línea de entrada, que se especificó al
    llamar a new_GetLine(), cuando la línea se recupere, se truncará a la
    longitud de línea real de gl_get_line().


Si tiene éxito, gl_append_history() devuelve 0. De lo
    contrario, devuelve un valor distinto de cero y establece errno en
    uno de los siguientes valores.


   EINVAL  -  Uno de los argumentos pasados a
              gl_append_history() era NULL.
   ENOMEM  -  La línea especificada era más larga que el
              tamaño asignado del búfer de historial (como
              se especificó al llamar a new_GetLine()), por
              lo que no se pudo archivar.


Se puede obtener una descripción textual del error opcionalmente
    llamando a gl_error_message(). Tenga en cuenta que después de un error
    de este tipo, la lista de historial permanece en un estado válido para
    recibir nuevas líneas de historial, por lo que hay poco daño en simplemente
    ignorar el estado de retorno de gl_append_history().

CAMBIO   DE 
TERMINALES

La función constructora new_GetLine() asume que la entrada
    se leerá desde stdin, y la salida se escribirá en stdout. La
    siguiente función le permite cambiar a diferentes flujos de entrada y 
salida.

  int gl_change_terminal(GetLine *gl, FILE *input_fp,
                         FILE *output_fp, const char *term)
;

El argumento gl es el objeto que fue devuelto por
    new_GetLine(). El argumento input_fp especifica el flujo desde el que
    leer, y output_fp especifica el flujo en el que escribir. Solo
    si ambos se refieren a un terminal, se habilitará la entrada interactiva del terminal. De lo contrario, gl_get_line() simplemente llamará a fgets() para
    leer la entrada del comando. Si ambos flujos se refieren a un terminal, entonces deben
    referirse al mismo terminal, y el tipo de este terminal debe ser especificado
    a través del argumento term. El valor del argumento term se
    busca en la base de datos de información del terminal (terminfo o termcap), para
    determinar qué secuencias de control especiales se necesitan para controlar
    varios aspectos del terminal. new_GetLine(), por ejemplo, pasa
    el valor de retorno de getenv("TERM") en este argumento. Tenga en
    cuenta que si uno o ambos de input_fp y output_fp no se refieren a un
    terminal, entonces es legal pasar NULL en lugar de un tipo de
  
terminal.

Tenga en cuenta que si desea pasar descriptores de archivo a
    gl_change_terminal(), puede hacerlo creando envoltorios de flujo stdio
    utilizando la función POSIX fdop

MANEJO   DE EVENTOS 
EXTERNOS

Por defecto, gl_get_line() no regresa hasta que el usuario
    ha introducido una línea de entrada completa, o ocurre un error. En
    programas que necesitan vigilar la E/S de otras fuentes que no sean el terminal,
    hay dos 
opciones.

  1. Utilice las funciones descritas en la página de manual
     gl_io_mode(3) para cambiar
     gl_get_line() al modo de servidor no bloqueante. En este modo,
     gl_get_line() se convierte en una función de edición de líneas
     incremental no bloqueante que se puede llamar de forma segura desde
     un bucle de eventos externo. Aunque este es un método muy
     versátil, implica asumir algunas
     responsabilidades que normalmente se realizan detrás de escena por gl_get_line().
  2. Mientras gl_get_line() está esperando la entrada del
     teclado del usuario, puede pedirle que también vigile
     la actividad en descriptores de archivo arbitrarios, como
     sockets de red, tuberías, etc., y que llame a funciones
     de su elección cuando se observe actividad. Esto funciona en
     cualquier sistema que tenga la llamada al sistema select(), que es la mayoría, si no todos, los sabores de 
unix.

Registrar un descriptor de archivo para ser vigilado por
    gl_get_line() implica llamar a la función gl_watch_fd()
.

  int gl_watch_fd(GetLine *gl, int fd, GlFdEvent event,
                  GlFdEventFn *callback, void *data)
;

Si esto devuelve un valor distinto de cero, entonces significa que sus argumentos
    son inválidos, o que esta facilidad no está soportada en el sistema 
anfitrión.

El argumento fd es el descriptor de archivo a vigilar. El
    argumento event especifica qué tipo de actividad es de interés, elegido
    de los siguientes valores 
enumerados:

  GLFD_READ   -  Vigilar la llegada de datos para leer.
  GLFD_WRITE  -  Vigilar la capacidad de escribir en el descriptor
                 de archivo sin bloquear.
  GLFD_URGENT -  Vigilar la llegada de datos urgentes
                 fuera de banda en el descriptor de 
archivo.

El argumento callback es la función a llamar cuando se
    observa la actividad seleccionada. Debe definirse con el siguiente macro,
    que está definido en libtecla.
h.

  #define GL_FD_EVENT_FN(fn) GlFdStatus (fn)(GetLine *gl, \
                                      void *data, int fd, \
                                      GlFdEvent 
event)

El argumento data de la función gl_watch_fd() se
    pasa a la función de retorno de llamada para su propio uso, y puede apuntar a cualquier
    cosa que desee, incluyendo NULL. El descriptor de archivo y el argumento event
    también se pasan a la función de retorno de llamada, y esto potencialmente permite
    que la misma función de retorno de llamada se registre para más de un tipo de evento
    y/o más de un descriptor de archivo. El valor de retorno de la función de retorno de llamada
    debe ser uno de los siguientes 
valores.

  GLFD_ABORT    -  Decirle a gl_get_line() que aborte. Cuando esto
                   ocurre, gl_get_line() regresa
                   NULL, y una llamada posterior a
                   gl_return_status() devolverá
                   GLR_FDABORT. Tenga en cuenta que si la
                   aplicación necesita errno tenga siempre
                   un valor significativo cuando
                   gl_get_line() regrese NULL,
                   la función de retorno de llamada debe establecer
                   errno apropiadamente.
  GLFD_REFRESH  -  Redibujar la línea de entrada y luego continuar
                   esperando entrada. Devuelva esto si
                   su retorno de llamada escribió en el terminal.
  GLFD_CONTINUE -  Continuar esperando entrada, sin
                   redibujar la 
línea.

Tenga en cuenta que antes de llamar al retorno de llamada, gl_get_line() bloquea
    la mayoría de las señales, y deja sus propios manejadores de señal instalados, así que si necesita
    capturar una señal en particular, necesitará tanto instalar temporalmente su
    propio manejador de señal, como desbloquear la señal. Asegúrese de volver a bloquear la señal
    (si estaba originalmente bloqueada) y reinstalar el manejador de señal original, si
    lo hay, antes de 
regresar.

Si la función de retorno de llamada necesita leer o escribir en el terminal,
    idealmente debería primero llamar a gl_normal_io(gl) para suspender temporalmente
    la edición de líneas. Esto restaurará el terminal a modo canónico, de E/S bloqueante,
    y moverá el cursor al inicio de una nueva línea del terminal. Más tarde, cuando
    el retorno de llamada regrese, gl_get_line() notará que
    gl_normal_io() fue llamado, volverá a mostrar la línea de entrada y reanudará
    la edición. Tenga en cuenta que en este caso los valores de retorno, GLFD_REFRESH y
    GLFD_CONTINUE son 
equivalentes.

Para soportar casos donde la función de retorno de llamada llama a una función de terceros
    que ocasionalmente e impredeciblemente escribe en el terminal, la
    conversión automática de "0 a "0 se vuelve a habilitar
    antes de que se llame a la función de retorno de llamada. Si el retorno de llamada sabe que la
    función de terceros escribió en el terminal, entonces debe devolver el
    valor de retorno GLFD_REFRESH, para decirle a gl_get_line() que vuelva a mostrar
    la línea de 
entrada.

Para eliminar una función de retorno de llamada que registró previamente para un
    descriptor de archivo y evento dados, simplemente llame a gl_watch_fd() con el
    mismo descriptor de archivo y argumentos event, pero con un argumento callback
    de 0. El argumento data se i
gnora en 
este caso.



ESTABLECIMIENTO   DE UN TIEMPO DE ESPERA POR 
INACTIVIDAD

En sistemas con la llamada al sistema select(), la
    función gl_inactivity_timeout() se puede utilizar para establecer o cancelar un
    tiempo de espera por inactividad. La inactividad en este caso se refiere tanto a la entrada del teclado,
    como a la E/S en cualquier descriptor de archivo registrado por llamadas previas y posteriores a gl_watch_fd(). En sistemas peculiares que no tienen select(),
    esta llamada no tiene 
efecto.

  int ggl_inactivity_timeout(GetLine *gl, GlTimeoutFn *callback,
                     void *data, unsigned long sec,
                     unsigned long nsec)
;

El tiempo de espera se especifica en forma de un número entero de
    segundos y un número entero de nanosegundos, a través de los sec y
    nsec argumentos respectivamente. Posteriormente, siempre que no se
    observe actividad durante este período de tiempo, se llama a la función
    especificada a través del argumento callback.
    El argumento data de
    gl_inactivity_timeout() se pasa literalmente a esta función de
    callback cada vez que se invoca, y por lo tanto se puede utilizar para
    pasar información arbitraria específica de la aplicación al callback. Se
    proporciona la siguiente macro en libtecla.h para que las aplicaciones la utilicen para declarar y
    definir prototipos de funciones de callback de tiempo de 
espera.

  #define GL_TIMEOUT_FN(fn) \
               GlAfterTimeout (fn)(GetLine *gl, void 
*data)

Al regresar, se espera que el callback de la aplicación devuelva uno
    de los siguientes enumeradores para decirle a gl_get_line() cómo proceder
    después de que el callback haya manejado el tiempo de 
espera.

  GLTO_ABORT    -  Decirle a gl_get_line() que aborte. Cuando
                   esto sucede, gl_get_line() devolverá NULL, y una llamada posterior
                   a gl_return_status() devolverá
                   GLR_TIMEOUT. Tenga en cuenta que si la
                   aplicación necesita que errno siempre tenga
                   un valor significativo cuando
                   gl_get_line() devuelva NULL,
                   la función de callback debe establecer
                   errno de forma apropiada.
  GLTO_REFRESH  -  Redibujar la línea de entrada, luego continuar
                   esperando entrada. Debe devolver
                   este valor si su callback escribió en el
                   terminal sin haber llamado primero a
                   gl_normal_io(gl).
  GLTO_CONTINUE -  En el modo normal de E/S bloqueante, continuar
                   esperando entrada, sin redibujar la
                   línea de entrada del usuario.
                   En el modo de E/S de servidor no bloqueante (vea
                   gl_io_mode(3)), hacer que gl_get_line()
                   actúe como si la E/S se bloqueara. Esto significa
                   que gl_get_line() devolverá inmediatamente NULL, y una llamada posterior
                   a gl_return_status() devolverá
                   GLR_BLOCKED
.

Tenga en cuenta que antes de llamar al callback, gl_get_line() bloquea
    la mayoría de las señales y deja instalados sus propios manejadores de
    señal, así que si necesita capturar una señal en particular, deberá tanto
    instalar temporalmente su propio manejador de señal como desbloquear la
    señal. Asegúrese de volver a bloquear la señal (si originalmente estaba
    bloqueada) y reinstalar el manejador de señal original, si lo hay, antes
    de 
regresar.

Si la función de callback necesita leer o escribir en el terminal,
    idealmente debería llamar primero a gl_normal_io(gl) para suspender temporalmente
    la edición de línea. Esto restaurará el terminal a modo canónico, de E/S
    bloqueante, y moverá el cursor al inicio de una nueva línea de terminal.
    Más tarde, cuando el callback regrese, gl_get_line() notará que
    gl_normal_io() fue llamada,
    volverá a mostrar la línea de entrada y reanudará la edición. Tenga en
    cuenta que en este caso los valores de retorno, GLTO_REFRESH y
    GLTO_CONTINUE son 
equivalentes.

Para soportar casos donde la función de callback llama a una función
    de terceros que ocasional e imprevisiblemente escribe en el terminal, la
    conversión automática de "0 a "0 se vuelve a habilitar
    antes de que se llame a la función de callback. Si el callback sabe que
    la función de terceros escribió en el terminal, entonces debe devolver el
    valor de retorno
    GLTO_REFRESH, para decirle a gl_get_line() que vuelva a mostrar
    la línea de 
entrada.

Tenga en cuenta que aunque el argumento de tiempo de espera incluye
    un componente de nanosegundos, pocos relojes de computadora tienen
    actualmente resoluciones más finas que unos pocos milisegundos, por lo
    que pedir menos de unos pocos milisegundos es equivalente a solicitar
    cero segundos en muchos sistemas. Si esto fuera un problema, debería
    basar su selección de tiempo de espera en la resolución real del reloj
    del host (p. ej., llamando a sysconf(_SC_CLK_TCK))
.

Para desactivar los tiempos de espera, simplemente llame a gl_inactivity_timeout()
    con un argumento callback de 0. El argumento data se ignora
 en est
e caso.



MANEJO POR DEFECTO DE 
SEÑALES

Por defecto, la función gl_get_line() intercepta una serie
    de señales. Esto es particularmente importante para las señales que por
    defecto terminarían el proceso, ya que el terminal necesita ser restaurado
    a un estado utilizable antes de que esto suceda. En esta sección, se
    describen las señales que son atrapadas por defecto y cómo gl_get_line() responde a ellas.
    Cambiar estos valores por defecto es el tema de la siguiente
  
sección.

Cuando se captura el siguiente subconjunto de señales,
    gl_get_line() primero restaura la configuración del terminal y el
    manejo de señales a como estaban antes de que gl_get_line() fuera llamada, reenvía
    la señal, para permitir que los manejadores de señales de la aplicación
    que llama la manejen, luego si el proceso aún existe, gl_get_line() devuelve NULL
    y establece errno como se especifica a 
continuación.

 SIGINT  -  Esta señal es generada tanto por la tecla
            de interrupción del teclado (usualmente ^C), como por la tecla
            de pausa del teclado.
            errno=EINTR
 SIGHUP  -  Esta señal es generada cuando el terminal de
            control termina.
            errno=ENOTTY
 SIGPIPE -  Esta señal es generada cuando un programa intenta
            escribir en un pipe cuyo extremo remoto no está siendo
            leído por ningún proceso. Esto puede suceder, por ejemplo,
            si ha llamado a gl_change_terminal() para
            redirigir la salida a un pipe oculto bajo un pseudo
            terminal.
            errno=EPIPE
 SIGQUIT -  Esta señal es generada por la tecla de salida
            del teclado (usualmente ^\).
            errno=EINTR
 SIGABRT -  Esta señal es generada por la función estándar de C,
            abort(). Por defecto, tanto termina el proceso como genera un
            volcado de memoria (core dump).
            errno=EINTR
 SIGTERM -  Esta es la señal por defecto que el comando kill de UN*X
            envía a los procesos.
            
errno=EINTR

Tenga en cuenta que en el caso de todas las señales anteriores, POSIX
    dicta que por defecto el proceso es terminado, con la adición de un
    volcado de memoria en el caso de la señal SIGQUIT. En otras palabras, si la aplicación
    que llama no anula el manejador por defecto proporcionando su propio
    manejador de señal, la recepción de la señal correspondiente terminará la
    aplicación antes de que gl_get_line() 
regrese.

Si gl_get_line() aborta con errno establecido en EINTR, puede averiguar
    qué señal causó el aborto, llamando a la siguiente 
función.

  int gl_last_signal(const GetLine *gl)
;

Esto devuelve el código numérico (p. ej., SIGINT) de la última
    señal que fue recibida durante la llamada más reciente a
    gl_get_line(), o -1 si no se recibieron 
señales.

En los sistemas que lo soportan, cuando se recibe una señal SIGWINCH
    (cambio de ventana), gl_get_line() consulta al terminal para averiguar su nuevo
    tamaño, redibuja la línea de entrada actual para acomodar el nuevo tamaño,
    luego regresa a esperar la entrada de teclado del usuario. A diferencia de
    otras señales, esta señal no es reenviada a la 
aplicación.

Finalmente, las siguientes señales causan que gl_get_line() primero restaure
    el terminal y el entorno de señales a aquel que prevalecía antes de que
    gl_get_line() fuera llamado, luego reenvíe la señal a la aplicación.
    Si el proceso aún existe después de que la señal ha sido entregada, entonces
    gl_get_line() luego restablece sus propios manejadores de señal, cambia
    el terminal de vuelta a modo crudo, vuelve a mostrar la línea de entrada y
    regresa a esperar la entrada del terminal del 
usuario.

 SIGCONT    -  Esta señal es generada cuando un proceso
               suspendido es reanudado.
 SIGPOLL    -  En los sistemas SVR4, esta señal notifica al
               proceso de un evento de E/S asíncrono. Tenga en
               cuenta que bajo 4.3+BSD, SIGIO y SIGPOLL son
               lo mismo. En otros sistemas, SIGIO es ignorado
               por defecto, así que gl_get_line() no lo
               atrapa por defecto.
 SIGPWR     -  Esta señal es generada cuando ocurre un fallo
               de energía (presumiblemente cuando el sistema está en un
               UPS).
 SIGALRM    -  Esta señal es generada cuando un temporizador
               expira.
 SIGUSR1    -  Una señal específica de la aplicación.
 SIGUSR2    -  Otra señal específica de la aplicación.
 SIGVTALRM  -  Esta señal es generada cuando un temporizador
               virtual expira (vea man setitimer(2)).
 SIGXCPU    -  Esta señal es generada cuando un proceso
               excede su límite de tiempo de CPU suave.
 SIGXFSZ    -  Esta señal es generada cuando un proceso
               excede su límite de tamaño de archivo suave.
 SIGTSTP    -  Esta señal es generada por la tecla de
               suspensión del terminal, que usualmente es ^Z, o la
               tecla de suspensión retrasada del terminal, que
               usualmente es ^Y.
 SIGTTIN    -  Esta señal es generada si el programa
               intenta leer del terminal mientras el
               programa se está ejecutando en segundo plano.
 SIGTTOU    -  Esta señal es generada si el programa
               intenta escribir en el terminal mientras el
               programa se está ejecutando en segundo 
plano.

Obviamente no todas las señales anteriores están soportadas en todos
    los sistemas, así que el código para soportarlas se compila
    condicionalmente en la biblioteca 
tecla.

Tenga en cuenta que si SIGKILL o SIGPOLL, que por definición
    no pueden ser capturadas, o cualquiera de las señales de excepción
    generadas por el hardware, tales como
    SIGSEGV, SIGBUS y SIGFPE, son recibidas y no manejadas
    mientras gl_get_line() tiene el terminal en modo crudo, el programa será
    terminado sin que el terminal haya sido restaurado a un estado utilizable.
    En la práctica, los shells de contro
l de trabajos usualmente restablecen la
    configuración del terminal cuando un proceso re
nuncia al terminal de
    control, así que esto solo es un problema con shells más antiguos.



MANEJO DE SEÑALES 
PERSONALIZADO

La sección anterior enumeró las señales que gl_get_line()
    atrapa por defecto, y describió cómo responde a ellas. Esta sección
    describe cómo tanto añadir como eliminar señales de la lista de señales
    atrapadas, y cómo especificar cómo gl_get_line() debe responder a una
    señal 
dada.

Si no necesita gl_get_line() que haga algo en respuesta
    a una señal que normalmente atrapa, puede decirle a gl_get_line() que
    ignore esa señal llamando a gl_ignore_sig
nal().

  int gl_ignore_signal(GetLine *gl, int signo)
;

El argumento signo es el número de la señal (p. ej.,
    SIGINT) que quiere que sea ignorada. Si la señal especificada no es
    actualmente una de las que están siendo atrapadas, esta función no hace
    
nada.

La función gl_trap_signal() le permite tanto añadir una
    nueva señal a la lista que gl_get_line() atrapa, como modificar cómo


GL_TRAP_SIGNAL


Sets up gl_get_line() to respond to a signal that it already
    captures.


  int gl_trap_signal(GetLine *gl, int signo, unsigned flags,
                     GlAfterSignal after, int errno_value);


El argumento signo es el número de la señal que desea capturar.
    El argumento flags es un conjunto de indicadores que determinan el
    entorno en el que se invoca el manejador de señales de la aplicación. El
    argumento after indica a gl_get_line() qué hacer después de que
    el manejador de señales de la aplicación regrese, y errno_value indica a
    gl_get_line() qué establecer en errno si se le indica que aborte.


El argumento flags es una operación OR a nivel de bits de cero o
    más de las siguientes enumeraciones:


  GLS_RESTORE_SIG  -  Restaura el entorno de señales del
                      llamador mientras se maneja la
                      señal.
  GLS_RESTORE_TTY  -  Restaura la configuración de la terminal
                      del llamador mientras se maneja la
                      señal.
  GLS_RESTORE_LINE -  Mueve el cursor al inicio de la línea
                      siguiente a la línea de entrada antes
                      de invocar el manejador de señales de
                      la aplicación.
  GLS_REDRAW_LINE  -  Redibuja la línea de entrada cuando el
                      manejador de señales de la aplicación
                      regresa.
  GLS_UNBLOCK_SIG  -  Normalmente, si el programa que llama
                      tiene una señal bloqueada (ver
                      man sigprocmask), gl_get_line() no
                      captura esa señal. Este indicador
                      indica a gl_get_line() que capture la
                      señal y la desbloquee durante la
                      duración de la llamada a
                      gl_get_line().
  GLS_DONT_FORWARD -  Si se incluye este indicador, la señal
                      no se reenviará al manejador de
                      señales del programa que llama.


Dos combinaciones de indicadores comúnmente útiles también se
    enumeran de la siguiente manera:


  GLS_RESTORE_ENV   = GLS_RESTORE_SIG | GLS_RESTORE_TTY |
                      GLS_REDRAW_LINE
  GLS_SUSPEND_INPUT = GLS_RESTORE_ENV | GLS_RESTORE_LINE


Si su manejador de señales, o el manejador de señales predeterminado
    del sistema para esta señal, si no lo ha anulado, nunca escribe en la
    terminal, ni suspende o termina el programa que llama, entonces puede
    establecer de forma segura el argumento flags en 0.


Si su manejador de señales siempre escribe en la terminal, lee de ella,
    o suspende o termina el programa, debe especificar el argumento flags
    como GL_SUSPEND_INPUT, para que:


1. El cursor no se quede en medio de la línea de entrada.
2. Para que el usuario pueda escribir entrada y que se vea reflejada.
3. Para que no necesite terminar cada línea de salida con
   \r\n, en lugar de solo \n.


La combinación GL_RESTORE_ENV es la misma que
    GL_SUSPEND_INPUT, excepto que no mueve el cursor, y si su manejador de
    señales no lee ni escribe nada en la terminal, el usuario no verá ninguna
    indicación visible de que se capturó una señal. Esto puede ser útil si tiene
    un manejador de señales que solo escribe ocasionalmente en la terminal, donde
    usar GL_SUSPEND_LINE causaría que la línea de entrada se duplicara
    innecesariamente cuando no se hubiera escrito nada en la terminal. Dicho
    manejador de señales, cuando escribe en la terminal, debe asegurarse de
    comenzar una nueva línea al principio de su primera escritura, escribiendo una
    nueva línea antes de regresar. Si la señal llega mientras el usuario está
    ingresando una línea que solo ocupa una línea de terminal, o si el cursor
    está en la última línea de terminal de una línea de entrada más larga, esto
    tendrá el mismo efecto que GL_SUSPEND_INPUT. De lo contrario, comenzará
    a escribir en una línea que ya contiene parte de la línea de entrada mostrada.
    Esto no causa ningún daño, pero se ve un poco feo, por lo que la combinación
    GL_SUSPEND_INPUT es mejor si sabe que siempre va a escribir en la
    terminal.


El argumento after, que determina qué hace
    gl_get_line() después de que el manejador de señales de la aplicación
    regresa (si regresa), puede tomar cualquiera de los siguientes valores:


  GLS_RETURN   - Devuelve la línea de entrada completada, como
                 si el usuario hubiera presionado la tecla
                 enter.
  GLS_ABORT    - Hace que gl_get_line() aborte. Cuando
                 esto sucede, gl_get_line() devuelve
                 NULL, y una llamada posterior a
                 gl_return_status() devolverá
                 GLR_SIGNAL. Tenga en cuenta que si la
                 aplicación necesita que errno siempre
                 tenga un valor significativo cuando
                 gl_get_line() devuelve NULL,
                 la función de devolución de llamada debe
                 establecer errno apropiadamente.
  GLS_CONTINUE - Reanuda la edición de la línea de comandos.


El argumento errno_value está destinado a combinarse con la
    opción GLS_ABORT, indicando a gl_get_line() qué establecer en
    la variable estándar errno antes de devolver NULL al programa
    que llama. Sin embargo, también se puede usar con la opción GL_RETURN,
    en caso de que desee tener una forma de distinguir entre una línea de entrada
    que se ingresó usando la tecla enter y una que se ingresó por la recepción
    de una señal.






MANEJO CONFIABLE DE SEÑALES


El manejo de señales es sorprendentemente difícil de hacer de manera
    confiable sin condiciones de carrera. En gl_get_line() se ha puesto
    mucha atención para permitir que las aplicaciones realicen un manejo de
    señales confiable alrededor de gl_get_line(). Esta sección explica
    cómo hacer uso de esto.


Como ejemplo de los problemas que pueden surgir si la aplicación no
    está escrita correctamente, imagine que la aplicación tiene un manejador de
    señales SIGINT que establece una bandera global. Ahora suponga que la
    aplicación prueba esta bandera justo antes de invocar gl_get_line().
    Si una señal SIGINT se recibe en la pequeña ventana de tiempo entre la
    sentencia que prueba el valor de esta bandera y la sentencia que llama a
    gl_get_line(), entonces gl_get_line() no verá la señal y no
    será interrumpido. Como resultado, la aplicación no podrá responder a la
    señal hasta que el usuario termine de ingresar la línea de entrada y
    gl_get_line() regrese. Dependiendo de la aplicación, esto puede ser
    o no un desastre, pero al menos confundirá al usuario.


La forma de evitar tales problemas es hacer lo siguiente.


1. Si es necesario, use la función gl_trap_signal() para
  

   configurar gl_get_line() para que aborte cuando se
  

   capturen señales importantes.


2. Configure gl_get_line() de tal manera que si alguna de
  

   las señales que captura está bloqueada cuando se
  

   llama a gl_get_line(), se desbloquearán
  

   automáticamente durante los momentos en que
  

   gl_get_line() está esperando E/S. Esto se puede
  

   hacer de forma individual para cada señal, llamando a
  

   la función gl_trap_signal() y especificando el
  

   atributo GLS_UNBLOCK de la señal, o globalmente
  

   llamando a la función gl_catch_blocked().


     void gl_catch_blocked(GetLine *gl);



  

   Esta función simplemente agrega el atributo
  

   GLS_UNBLOCK a todas las señales que actualmente está
  

   configurada para capturar.


3. Justo antes de llamar a gl_get_line(), bloquee la
  

   entrega de todas las señales que gl_get_line()
  

   está configurada para capturar. Esto se puede hacer
  

   usando la función POSIX sigprocmask() en
  

   conjunción con la función gl_list_signals().


      int gl_list_signals(GetLine *gl, sigset_t *set);



  

   Esta función devuelve el conjunto de señales que
  

   actualmente está configurada para capturar en el
  

   argumento set, que está en el formato requerido
  

   por sigprocmask().


4. En el ejemplo, ahora se probaría la bandera global que
  

   establece el manejador de señales, sabiendo que ya no
  

   hay peligro de que esta bandera se establezca de nuevo
  

   hasta que gl_get_line() desbloquee sus señales
  

   mientras realiza E/S.


5. Finalmente, gl_get_line() regresa, ya sea porque
  

   se capturó una señal, ocurrió un error o el usuario
  

   terminó de ingresar su línea de entrada.


6. Ahora se volvería a verificar la bandera de señal global y,
  

   si está establecida, se respondería a ella y se pondría a
  

   cero la bandera.


7. Use sigprocmask() para desbloquear las señales que
  

   fueron bloqueadas en el paso 3.


La misma técnica se puede usar alrededor de ciertas funciones POSIX
    conscientes de las señales, como sigsetjmp() y sigsuspend(), y
    en particular, la primera de estas dos funciones se puede usar en conjunción
    con siglongjmp() para implementar un manejo de señales libre de
    condiciones de carrera alrededor de otras llamadas al sistema de larga
    duración. La forma de hacer esto se explica a continuación, mostrando cómo
    gl_get_line() logra capturar señales de manera confiable alrededor de
    llamadas a funciones como read() y select() sin condiciones de
    carrera.


Lo primero que hace gl_get_line(), cada vez que se llama, es
    usar la función POSIX sigprocmask() para bloquear la entrega de todas
    las señales que actualmente está configurada para capturar. Esto es redundante
    si la aplicación ya las ha bloqueado, pero no causa ningún daño. Deshace este
    paso justo antes de regresar.


Cada vez que gl_get_line() necesita llamar a read() o
    select() para esperar la entrada del usuario, primero llama a la
    función POSIX sigsetjmp(), asegurándose de especificar un valor no
    cero para su argumento savesigs. La razón de este último argumento
    será clara en breve.


Si sigsetjmp() devuelve cero, gl_get_line() hace lo
    siguiente.


a. Utiliza la función POSIX sigaction() para registrar
   un manejador de señales temporal para todas las señales
   que está configurada para capturar. Este manejador de
   señales hace dos cosas.
   1. Registra el número de la señal recibida en una
      variable de ámbito de archivo.
   2. Luego llama a la función POSIX siglongjmp()
      utilizando el búfer que se pasó a sigsetjmp()
      como primer argumento, y un valor no cero para su
      segundo argumento.
   Cuando se registra este manejador de señales, el miembro
   sa_mask de la estructura struct sigaction act
   del argumento de la llamada a sigaction() se
   configura para contener todas las señales que
   gl_get_line() está capturando. Esto asegura que solo
   una señal será capturada a la vez por nuestro manejador
   de señales, lo que a su vez asegura que múltiples
   instancias de nuestro manejador de señales no se pisarán
   entre sí.
b. Ahora que el manejador de señales ha sido configurado,
   gl_get_line() desbloquea todas las señales que está
   configurada para capturar.
c. Luego llama a las llamadas al sistema read() o
   select() para esperar la entrada del teclado.
d. Si esta llamada al sistema regresa (es decir, no se
   recibe ninguna señal), gl_get_line() vuelve a

EL   TAMAÑO DEL 
TERMINAL

En la mayoría de los sistemas, la combinación del ioctl TIOCGWINSZ y la
    señal SIGWINCH se utiliza para mantener una idea precisa del
    tamaño del terminal. El tamaño del terminal se consulta de nuevo cada vez que
    gl_get_line() es llamado y siempre que una señal SIGWINCH es
    
recibida.

En los pocos sistemas donde este mecanismo no está disponible, al
    inicio new_GetLine() primero busca las variables de entorno LINES y
    COLUMNS. Si estas no se encuentran, o contienen
    valores inutilizables, entonces si una base de datos de información de terminal como terminfo o
    termcap está disponible, el tamaño por defecto del terminal se busca en esta
    base de datos. Si esto también falla en proporcionar el tamaño del terminal, se usa un tamaño por defecto de
    80 columnas por 24 
líneas.

Incluso en sistemas que sí soportan ioctl(TIOCGWINSZ), si el
    terminal está en el otro extremo de una línea serie, el controlador del terminal generalmente
    no tiene forma de detectar cuándo ocurre un redimensionamiento ni de consultar cuál es el tamaño
    actual. En tales casos, no se envía ningún SIGWINCH al proceso, y las
    dimensiones devueltas por ioctl(TIOCGWINSZ) no son correctas. La única forma
    de manejar tales instancias es proporcionar una manera para que el usuario ingrese un comando
    que le diga al sistema remoto cuál es el nuevo tamaño. Este comando entonces llamaría a la función gl_set_term_size() para informar a gl_get_line()
    sobre el cambio de 
tamaño.

  int gl_set_term_size(GetLine *gl, int ncolumn, int nline)
;

Los argumentos ncolumn y nline se usan para especificar
    las nuevas dimensiones del terminal, y no deben ser menores que 1. En sistemas
    que sí soportan ioctl(TIOCGWINSZ), esta función primero llama a
    ioctl(TIOCSWINSZ) para informar al controlador del terminal sobre el cambio en
    el tamaño. En modo de E/S de servidor no bloqueante, si una línea está siendo ingresada actualmente,
    la línea de entrada se redibuja para acomodar el tamaño cambiado. Finalmente, los
    nuevos valores se registran en gl para uso futuro por
  gl_get_li
ne().

La función gl_terminal_size() le permite consultar el
    tamaño actual del terminal, e instalar un tamaño de reserva alternativo para
    casos donde el tamaño no esté disponible. Tenga en cuenta que el tamaño del terminal no estará
    disponible si se lee desde una tubería o un archivo, por lo que los valores por defecto pueden ser
    importantes incluso en sistemas que sí soportan formas de averiguar el tamaño del 
terminal.

  typedef struct {
    int nline;        /* El terminal tiene nline líneas */
    int ncolumn;      /* El terminal tiene ncolumn columnas */
  } GlTerminalSize;
  GlTerminalSize gl_terminal_size(GetLine *gl,
                                  int def_ncolumn,
                                  int def_nline)
;

Esta función primero actualiza las dimensiones de reserva del terminal de gl_get_line(),
    luego registra sus hallazgos en el valor de 
retorno.

Los argumentos def_ncolumn y def_nline especifican el número
    por defecto de columnas y líneas del terminal a usar si el tamaño del terminal no puede ser
    determinado vía ioctl(TIOCGWINSZ) o 
variables d
e entorno.



OCULTANDO   LO QUE 
ESCRIBES

Al ingresar información sensible, como contraseñas, es mejor
    no tener el texto que está ingresando reflejado en el terminal.
    Además, dicho texto no debería ser registrado en la lista de historial, ya que
    alguien que encuentre su terminal desatendida podría entonces recuperarlo, o alguien
    que esté husmeando en sus directorios podría verlo en su archivo de historial. Con
    esto en mente, la función gl_echo_mode() le permite alternar
    la visualización y el archivo de cualquier texto que sea ingresado posteriormente en
    llamadas a gl_get_li
ne().

  int gl_echo_mode(GetLine *gl, int enable)
;

El argumento enable especifica si el texto ingresado debe
    ser visible o no. Si es 0, entonces las líneas ingresadas posteriormente no
    serán visibles en el terminal, y no serán registradas en la lista de
    historial. Si es 1, entonces las líneas de entrada posteriores se mostrarán a
    medida que se ingresan, y siempre que el historial no haya sido desactivado vía una
    llamada a gl_toggle_history(), también serán archivadas en la
    lista de historial. Finalmente, si el argumento enable es -1, entonces el
    modo de eco se deja sin cambios, lo que le permite consultar de forma no destructiva
    la configuración actual a través del valor de retorno. En todos los casos, el valor de retorno de
    la función es 0 si el eco estaba deshabilitado antes de que la función fuera
    llamada, y 1 si estaba 
habilitado.

Cuando el eco está desactivado, tenga en cuenta que aunque la comple
tación con tabulador completará
    su prefijo de forma invisible lo
 más lejos posible, las completaciones ambiguas
    no se mostrarán.



CONSULTAS   DE UN SOLO 
CARÁCTER

Usar gl_get_line() para consultar al usuario por una respuesta de un solo
    carácter es inconveniente para el usuario, ya que debe presionar la tecla enter
    o retorno antes de que el carácter que escribió sea devuelto al
    programa. Por lo tanto, la función gl_query_char() ha sido proporcionada para
    consultas de un solo carácter como 
esta.

  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar)
;

Esta función muestra la indicación especificada al comienzo de una nueva
    línea, y espera a que el usuario escriba un carácter. Cuando el usuario escribe un
    carácter, gl_query_char() lo muestra a la derecha de la indicación,
    inicia una nueva línea, y luego devuelve el carácter al programa llamante. El
    valor de retorno de la función es el carácter que fue escrito. Si la lectura
    tuvo que ser abortada por alguna razón, EOF es devuelto en su lugar. En el
    último caso, la aplicación puede llamar a la previamente documentada
    gl_return_status(), para averiguar qué salió mal. Esto podría, por
    ejemplo, haber sido la recepción de una señal, o el temporizador opcional de inactividad
    
activándose.

Si el usuario simplemente presiona enter, el valor del argumento defchar
    es sustituido. Esto significa que cuando el usuario presiona tanto newline
    o return, el carácter especificado en defchar, se muestra después de la
    indicación, como si el usuario lo hubiera escrito, así como ser devuelto a la
    aplicación llamante. Si tal reemplazo no es importante, simplemente pase
    '0 como el valor de defchar
.

Si el carácter ingresado es un carácter imprimible, se
    muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y
    los caracteres más allá de 127 se muestran en octal, precedidos por una barra 
invertida.

Al igual que con gl_get_line(), el eco del carácter ingresado puede
    ser deshabilitado usando la función gl_echo_mode()
.

Si el proceso llamante es suspendido mientras espera a que el usuario
    escriba su respuesta, el cursor se mueve a la línea que sigue a la línea de
    indicación, luego cuando el proceso se reanuda, la indicación se vuelve a mostrar, y
    gl_query_char() reanuda la espera de que el usuario escriba un 
carácter.

Tenga en cuenta que en modo de servidor no bloqueante, (vea gl_io_mode(3)), si una
    línea de entrada incompleta está en proceso de ser leída cuando
    gl_query_char() es llamada, la línea de entrada parcial se descarta, y
    se borra del terminal, antes de que se muestre la nueva indicación. La siguiente llamada
    a gl_get_line() comenzará as
í a editar una
 nueva línea.



LEYENDO   CARACTERES 
CRUDOS

Mientras que la función gl_query_char() pide visiblemente al
    usuario un carácter, y muestra lo que escribió, la
    función gl_read_char() lee un carácter de señal del usuario,
    sin escribir nada en el terminal, ni perturbar ninguna línea de entrada
    incompleta. Esto significa que puede ser llamada no solo entre
    llamadas a gl_get_line(), sino también desde funciones de retorno de llamada que la
    aplicación ha registrado para ser llamadas por gl_get_li
ne().

  int gl_read_char(GetLine *gl)
;

En caso de éxito, el valor de retorno de gl_read_char() es el
    carácter que fue leído. En caso de fallo, EOF es devuelto, y la
    función gl_return_status() puede ser llamada para averiguar qué salió
    mal. Las posibilidades incluyen el temporizador opcional de inactividad activándose, la
    recepción de una señal que está configurada para abortar gl_get_line(), o el bloqueo de
    E/S del terminal, cuando se está en modo de E/S de servidor no 
bloqueante.

Tenga en cuenta que ciertas teclas del teclado, como las teclas de función y
    las teclas de cursor, usualmente generan al menos 3 caracteres cada una, por lo que una sola llamada
    a gl_read_char() won't be enough to identify such keystrokes.

MOSTRANDO   TEXTO DINÁMICAMENTE


Entre llamadas a gl_get_line(), la función
    gl_display_text() proporciona una forma conveniente de mostrar párrafos
    de texto, justificados a la izquierda y divididos en una o más líneas de
    terminal según las restricciones del ancho actual de la terminal. Ejemplos
    del uso de esta función se pueden encontrar en los programas de demostración,
    donde se utiliza para mostrar introducciones. En esos ejemplos, también se
    ilustra el uso avanzado de prefijos, sufijos y líneas de relleno opcionales
    para dibujar un cuadro alrededor del texto.


  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string);


Si gl no está actualmente conectado a una terminal, por
    ejemplo, si la salida de un programa que usa gl_get_line() se está
    canalizando a otro programa o se está redirigiendo a un archivo, entonces el
    valor del parámetro def_width se usa como el ancho de la terminal.


El argumento indentation especifica el número de caracteres
    que se utilizarán para sangrar cada línea de salida. El argumento
    fill_char especifica el carácter que se utilizará para realizar esta
    sangría.


El argumento prefix puede ser NULL o una cadena que se
    colocará al principio de cada nueva línea (después de cualquier sangría).
    Del mismo modo, el argumento suffix puede ser NULL o una cadena
    que se colocará al final de cada línea. El sufijo se coloca pegado al borde
    derecho de la terminal, y cualquier espacio entre su primer carácter y la
    última palabra de esa línea se rellena con el carácter especificado a
    través del argumento fill_char. Normalmente, el carácter de relleno es
    un espacio.


El argumento start indica a gl_display_text() cuántos
    caracteres ya se han escrito en la línea de terminal actual y, por lo tanto,
    indica el índice de columna de inicio del cursor. Dado que el valor de retorno
    de gl_display_text() es el índice de columna final del cursor, al pasar
    el valor de retorno de una llamada al argumento start de la siguiente
    llamada, se puede componer un párrafo que se divide entre más de una cadena
    llamando a gl_display_text() para cada porción sucesiva del párrafo.
    Tenga en cuenta que los caracteres de nueva línea literales son necesarios al
    final de cada párrafo para forzar el inicio de una nueva línea.


En caso de error, gl_display_text() devuelve -1.

A menos que se indique lo contrario, las funciones de llamada, como
    las llamadas de finalización de tabulación y las llamadas de eventos, no
    deben llamar a ninguna función de este módulo. Las siguientes funciones, sin
    embargo, están diseñadas específicamente para ser utilizadas por funciones de
    llamada.


Llamar a la función gl_replace_prompt() desde una llamada le
    dice a gl_get_line() que muestre un prompt diferente cuando la llamada
    retorne. Excepto en el modo de servidor no bloqueante, no tiene ningún efecto
    si se usa entre llamadas a gl_get_line(). En el modo de servidor no
    bloqueante (ver la página del manual gl_io_mode(3),
    cuando se usa entre dos llamadas a gl_get_line() que operan en la misma
    línea de entrada, la línea de entrada actual se redibujará con el nuevo prompt
    en la siguiente llamada a gl_get_line().


  void gl_replace_prompt(GetLine *gl, const char *prompt);






JUEGOS DE CARACTERES INTERNACIONALES


Desde la versión 1.4.0 de libtecla, gl_get_line() es limpia
    para 8 bits. Esto significa que todos los caracteres de 8 bits que son
    imprimibles en la configuración regional actual del usuario se muestran ahora
    literalmente y se incluyen en la línea de entrada devuelta. Suponiendo que el
    programa que llama contiene correctamente una llamada como la siguiente,


  setlocale(LC_CTYPE, "");


entonces la configuración regional actual se determina por la
    primera de las variables de entorno LC_CTYPE, LC_ALL y
    LANG, que se encuentra que contiene un nombre de configuración regional
    válido. Si ninguna de estas variables está definida, o si el programa omite
    llamar a setlocale, entonces se utiliza la configuración regional predeterminada
    C, que es US 7-bit ASCII. En la mayoría de las plataformas tipo Unix,
    puede obtener una lista de configuraciones regionales válidas escribiendo el
    comando:


  locale -a


en el prompt de la shell. Puede encontrar más documentación sobre
    cómo el usuario puede utilizar esto para introducir caracteres
    internacionales en la página del manual tecla(7).






SEGURIDAD DE HILOS


En un programa multihilo, debe usar la versión libtecla_r.a de la
    biblioteca. Esta utiliza versiones reentrantes de las funciones del sistema,
    cuando están disponibles. Desafortunadamente, ni terminfo ni termcap fueron
    diseñados para ser reentrantes, por lo que no puede usar de forma segura las
    funciones del módulo getline en múltiples hilos (puede usar los módulos
    separados de expansión de archivos y finalización de palabras en múltiples
    hilos, vea las páginas del manual correspondientes para obtener detalles).
    Sin embargo, debido al uso de funciones reentrantes POSIX para buscar
    directorios de inicio, etc., es seguro usar este módulo desde un solo hilo de
    un programa multihilo, siempre que sus otros hilos no utilicen ninguna función
    de termcap o terminfo.
