función gl_get_line() es parte de la biblioteca tecla (véase la página man libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de unix. Además de la edición simple de línea de comandos, admite el recuerdo de líneas de comandos introducidas previamente, la completación con TAB de nombres de archivos y la expansión en línea de comodines de nombres de archivos. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario se puede encontrar en la página man tecla(7). DÉFINITION D'ACTION

PERSONNALISÉE

Bien que les actions de liaison de touche intégrées soient suffisantes pour les besoins de la plupart des applications, occasionnellement une application spécialisée peut avoir besoin de définir une ou plusieurs actions personnalisées, liées à des séquences de touches spécifiques à l'application. Par exemple, une application de vente bénéficierait d'avoir une séquence de touches qui affichait le nom de pièce correspondant à un numéro de pièce précédant le curseur. Une telle fonctionnalité est clairement au-delà de l'étendue des fonctions d'action intégrées. Ainsi, pour de tels cas spéciaux, la fonction gl_register_action() est

fournie. 
  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq)
;

Cette fonction permet à l'application d'enregistrer une fonction externe, fn, qui sera appelée par la suite chaque fois que soit la séquence de touches spécifiée, keyseq, est saisie par l'utilisateur, ou que l'utilisateur saisit toute autre séquence de touches que l'utilisateur lie par la suite à l'action nom spécifiée, name, dans leur fichier de configuration. L'argument data peut être un pointeur vers n'importe quoi que l'application souhaite avoir transmis à la fonction d'action, fn, chaque fois que cette fonction est

invoquée.

La fonction d'action, fn, doit être déclarée en utilisant le macro suivant, qui est défini dans libtecl

a.h. 
  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char
*line)

Le gl et data arguments sont ceux qui ont précédemment été transmis à gl_register_action() lors de l'enregistrement de la fonction d'action. L'argument count est un argument numérique que l'utilisateur a la possibilité de saisir en utilisant l'action digit-argument, avant d'invoquer l'action. Si l'utilisateur ne saisit pas un nombre, alors l'argument count est défini à 1. Nominalement, cet argument est interprété comme un compteur de répétition, ce qui signifie que l'action devrait être répétée ce nombre de fois. En pratique cependant, pour certaines actions, un compteur de répétition a peu de sens. Dans de tels cas, les actions peuvent soit simplement ignorer l'argument count, soit utiliser sa valeur pour un autre

but.

Une copie de la ligne d'entrée actuelle est transmise dans l'argument lisible en écriture seule line. La position actuelle du curseur au sein de cette chaîne est donnée par l'index contenu dans l'argument curpos. Notez que la manipulation directe de la ligne d'entrée et de la position du curseur n'est pas autorisée. C'est parce que les règles dictées par divers modes, tels que le mode vi versus le mode emacs, le mode sans-écho, et le mode insertion versus le mode surimpression etc, le rendent trop complexe pour qu'un auteur d'application écrive une action de modification conforme, ainsi que de restreindre les changements futurs aux internals de gl_get_line(). Une solution potentielle à ce dilemme serait d'autoriser la fonction d'action à modifier la ligne en utilisant les actions de modification existantes. Cela est actuellement en cours

d'examen.

Si la fonction d'action souhaite écrire du texte dans le terminal, sans que cela ne se mêle au texte affiché de la ligne d'entrée, ou lire du terminal sans avoir à gérer le I/O terminal brut, alors avant de faire l'un ou l'autre de ces opérations, elle doit suspendre temporairement la modification de ligne en appelant la fonction gl_normal_io(). Cette fonction vide tout output en attente vers le terminal, déplace le curseur au début de la ligne qui suit la dernière ligne de terminal de la ligne d'entrée, puis restaure le terminal dans un état approprié pour être utilisé avec les facilities C stdio. Le dernier inclut de telles choses comme le rétablissement de la normale mapping de \n à \r\n, et, en mode serveur, le rétablissement de la normale forme bloquante de l'I/O terminal. Après avoir appelé cette fonction, la fonction d'action peut lire et écrire dans le terminal sans la peur de créer un désordre. Il n'est pas nécessaire pour la fonction d'action de restaurer l'environnement de modification original avant qu'elle retourne. Cela est fait automatiquement par gl_get_line() après que la fonction d'action retourne. Le suivant est un exemple simple d'une fonction d'action qui écrit la phrase "Hello world" sur une nouvelle ligne de terminal après la ligne étant modifiée. Lorsque cette fonction retourne, la ligne d'entrée est re dessinée sur la ligne qui suit la ligne "Hello world", et la modification de ligne

reprend. 
  static GL_ACTION_FN(say_hello_fn)
  {
    if(gl_normal_io(gl))   /* Suspender temporalmente la edición */
      return GLA_ABORT;
    printf("Hello world\n");
    return GLA_CONTINUE;
}

Para guardar el contenido del búfer de historial antes de salir de su aplicación, y posteriormente restaurarlo cuando vuelva a iniciar la aplicación, se proporcionan las siguientes

funciones.

El argumento filename especifica el nombre que se le dará al archivo de historial al guardarlo, o el nombre de un archivo de historial existente, al cargarlo. Este puede contener expresiones de directorio de inicio y variables de entorno, como "~/.myapp_history" o "$HOME/.

myapp_history".

Junto con cada línea del historial, se registra información adicional sobre ella, como cuándo fue introducida por el usuario y cuál es su nivel de anidamiento, como un comentario que precede a la línea en el archivo de historial. Escribir esto como un comentario permite que el archivo de historial sirva también como archivo de comandos, por si desea reproducir toda una sesión con él. invertida.

Si el proceso que llama se suspende mientras espera a que el usuario escriba su respuesta, el cursor se mueve a la línea siguiente a la línea del indicador, luego cuando el proceso se reanuda, el indicador se vuelve a mostrar, y gl_query_char() reanuda la espera de que el usuario escriba un

carácter.

bloqueante.

Entre les appels à gl_get_line(), la fonction gl_display_text() fournit un moyen pratique d'afficher des paragraphes de texte, justifiés à gauche et répartis sur une ou plusieurs lignes de terminal en fonction des contraintes de la largeur actuelle du terminal. Dans ces exemples, l'utilisation avancée de préfixes, suffixes et lignes de remplissage optionnels pour dessiner un cadre autour du texte est également

;

terminal.

L' argument indentation spécifie le nombre de caractères à utiliser pour indenter chaque ligne de sortie. L' argument fill_char spécifie le caractère qui sera utilisé pour effectuer cette

indentation.

L' argument prefix peut être soit NULL, soit une chaîne à placer au début de chaque nouvelle ligne (après toute indentation). De même, l' argument suffix peut être soit NULL, soit une chaîne à placer à la fin de chaque ligne. Le suffixe est placé à fleur du bord droit du terminal, et tout espace entre son premier caractère et le dernier mot de cette ligne est rempli par le caractère spécifié via l' argument fill_char. Normalement, le caractère de remplissage est une

espace.

L' argument start indique à gl_display_text() combien de caractères ont déjà été écrits sur la ligne de terminal actuelle, et indique ainsi l'index de colonne de départ du curseur. Puisque la valeur de retour de gl_display_text() est l'index de colonne de fin du curseur, en passant la valeur de retour d'un appel à l'argument start du appel suivant, un paragraphe qui est interrompu entre plus d'une chaîne peut être composé en appelant gl_display_text() pour chaque portion successive du paragraphe. Notez que des caractères de saut de ligne littéraux sont nécessaires à la fin de chaque paragraphe pour forcer le début d'une nouvelle

ligne.

INTERNATIONAUX

Depuis la version 1.4.0 de libtecla, gl_get_line() est propre aux 8 bits. Cela signifie que tous les caractères sur 8 bits qui sont imprimables dans la locale actuelle de l'utilisateur sont désormais affichés verbatim et inclus dans la ligne d'entrée retournée. En supposant que le programme appelant contient correctement un appel comme le

Si aucune de ces variables n'est définie, ou si le programme néglige d'appeler setlocale, alors la locale par défaut C est utilisée, qui est l'ASCII 7 bits US. Sur la plupart des plateformes unix-like, vous pouvez obtenir une liste des locales valides en tapant la commande

SÉCURITÉ DES

THREADS

Dans un programme multi-thread, vous devriez utiliser la version libtecla_r.a de la bibliothèque. Celle-ci utilise des versions réentrantes des fonctions système, lorsqu'elles sont disponibles. Malheureusement, ni terminfo ni termcap n'ont été conçus pour être réentrants, vous ne

pouvez donc pas utiliser en toute sécurité les fonctions du module getline dans plusieurs threads (vous pouvez utiliser les modules distincts d'expansion de fichiers et de complétion de mots dans plusieurs threads, voir les pages de manuel correspondantes pour plus de détails). Cep
endant, en raison de l'utilisation de fonctions POSIX réentrantes pour rechercher les répertoires personnels etc., il est sûr d'utiliser ce module depuis un seul thread d'un programme multi-thread, à condition que vos autres threads n'utilisent aucune fonction termcap ou terminfo.
