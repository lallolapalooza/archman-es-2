NOMBRE

glTexImage2D - especifica una imagen de textura bidimensional

ESPECIFICACIÓN EN C

void glTexImage2D(GLenumtarget, GLintlevel, GLintinternalformat, GLsizeiwidth, GLsizeiheight, GLintborder, GLenumformat, GLenumtype, const void *data);

PARÁMETROS

target

Especifica la textura de destino. Debe ser GL_TEXTURE_2D, GL_PROXY_TEXTURE_2D, GL_TEXTURE_1D_ARRAY, GL_PROXY_TEXTURE_1D_ARRAY, GL_TEXTURE_RECTANGLE, GL_PROXY_TEXTURE_RECTANGLE, GL_TEXTURE_CUBE_MAP_POSITIVE_X, GL_TEXTURE_CUBE_MAP_NEGATIVE_X, GL_TEXTURE_CUBE_MAP_POSITIVE_Y, GL_TEXTURE_CUBE_MAP_NEGATIVE_Y, GL_TEXTURE_CUBE_MAP_POSITIVE_Z, GL_TEXTURE_CUBE_MAP_NEGATIVE_Z, o GL_PROXY_TEXTURE_CUBE_MAP.

level

Especifica el número de nivel de detalle. El nivel 0 es el nivel de imagen base. El nivel n es la nº imagen de reducción de mipmap. Si target es GL_TEXTURE_RECTANGLE o GL_PROXY_TEXTURE_RECTANGLE, level debe ser 0.

internalformat

Especifica el número de componentes de color en la textura. Debe ser uno de los formatos internos base dados en la Tabla 1, uno de los formatos internos con tamaño dados en la Tabla 2, o uno de los formatos internos comprimidos dados en la Tabla 3, más abajo.

width

Especifica el ancho de la imagen de textura. Todas las implementaciones admiten imágenes de textura de al menos 1024 texels de ancho.

height

Especifica la altura de la imagen de textura, o el número de capas en una matriz de textura, en el caso de los objetivos GL_TEXTURE_1D_ARRAY y GL_PROXY_TEXTURE_1D_ARRAY . Todas las implementaciones admiten imágenes de textura 2D de al menos 1024 texels de alto, y matrices de textura de al menos 256 capas de profundidad.

border

Este valor debe ser 0.

format

Especifica el formato de los datos de píxel. Se aceptan los siguientes valores simbólicos: GL_RED, GL_RG, GL_RGB, GL_BGR, GL_RGBA, GL_BGRA, GL_RED_INTEGER, GL_RG_INTEGER, GL_RGB_INTEGER, GL_BGR_INTEGER, GL_RGBA_INTEGER, GL_BGRA_INTEGER, GL_STENCIL_INDEX, GL_DEPTH_COMPONENT, GL_DEPTH_STENCIL.

type

Especifica el tipo de datos de los píxeles. Se aceptan los siguientes valores simbólicos: GL_UNSIGNED_BYTE, GL_BYTE, GL_UNSIGNED_SHORT, GL_SHORT, GL_UNSIGNED_INT, GL_INT, GL_HALF_FLOAT, GL_FLOAT, GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, GL_UNSIGNED_SHORT_5_6_5_REV, GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, y GL_UNSIGNED_INT_2_10_10_10_REV.

data

Especifica un puntero a los datos de la imagen en memoria.

DESCRIPCIÓN

El mapeo de texturas permite que los elementos de una matriz de imágenes sean leídos por los shaders.

Para definir imágenes de textura, llame a glTexImage2D. Los argumentos describen los parámetros de la imagen de textura, como la altura, el ancho, el ancho del borde, el número de nivel de detalle (véase glTexParameter()) y el número de componentes de color proporcionados. Los últimos tres argumentos describen cómo se representa la imagen en memoria.

Si target es GL_PROXY_TEXTURE_2D, GL_PROXY_TEXTURE_1D_ARRAY, GL_PROXY_TEXTURE_CUBE_MAP, o GL_PROXY_TEXTURE_RECTANGLE, no se leen datos de data, pero se recalcula todo el estado de la imagen de textura, se comprueba su consistencia y se verifica contra las capacidades de la implementación. Si la implementación no puede manejar una textura del tamaño solicitado, establece todo el estado de la imagen a 0, pero no genera un error (véase glGetError()). Para consultar una matriz de mipmap completa, use un nivel de matriz de imagen mayor o igual que 1.

Si target es GL_TEXTURE_2D, GL_TEXTURE_RECTANGLE o uno de los objetivos GL_TEXTURE_CUBE_MAP , se leen datos de data como una secuencia de bytes con signo o sin signo, shorts o longs, o valores de punto flotante de precisión simple, dependiendo de type. Estos valores se agrupan en conjuntos de uno, dos, tres o cuatro valores, dependiendo de format, para formar elementos. Cada byte de datos se trata como ocho elementos de 1 bit, con el orden de bits determinado por GL_UNPACK_LSB_FIRST (véase glPixelStore()).

Si target es GL_TEXTURE_1D_ARRAY, los datos se interpretan como una matriz de imágenes unidimensionales.

Si un objeto de búfer con nombre distinto de cero está vinculado al objetivo GL_PIXEL_UNPACK_BUFFER (véase glBindBuffer()) mientras se especifica una imagen de textura, data se trata como un desplazamiento en bytes dentro del almacén de datos del objeto de búfer.

El primer elemento corresponde a la esquina inferior izquierda de la imagen de textura. Los elementos posteriores avanzan de izquierda a derecha a través de los texels restantes de la fila más baja de la imagen de textura, y luego en filas sucesivamente más altas de la imagen de textura. El último elemento corresponde a la esquina superior derecha de la imagen de textura.

format determina la composición de cada elemento en data. Puede asumir uno de estos valores simbólicos:

GL_RED

Cada elemento es un único componente rojo. GL lo convierte a punto flotante y lo ensambla en un elemento RGBA adjuntando 0 para verde y azul, y 1 para alfa. Cada componente se limita al rango [0,1].

GL_RG

Cada elemento es un doble rojo/verde. GL lo convierte a punto flotante y lo ensambla en un elemento RGBA adjuntando 0 para azul, y 1 para alfa. Cada componente se limita al rango [0,1].

GL_RGB, GL_BGR

Cada elemento es una tripleta RGB. GL lo convierte a punto flotante y lo ensambla en un elemento RGBA adjuntando 1 para alfa. Cada componente se limita al rango [0,1].

GL_RGBA, GL_BGRA

Cada elemento contiene los cuatro componentes. Cada componente se limita al rango [0,1].

GL_DEPTH_COMPONENT

Cada elemento es un único valor de profundidad. GL lo convierte a punto flotante y lo limita al rango [0,1].

GL_DEPTH_STENCIL

Cada elemento es un par de valores de profundidad y esténcil. El componente de profundidad del par se interpreta como en GL_DEPTH_COMPONENT. El componente de esténcil se interpreta en función del formato interno de profundidad + esténcil especificado.

Si una aplicación desea almacenar la textura a una cierta resolución o en un cierto formato, puede solicitar la resolución y el formato con internalformat. GL elegirá una representación interna que se aproxime de cerca a la solicitada por internalformat, pero puede que no coincida exactamente. (Las representaciones especificadas por GL_RED, GL_RG, GL_RGB, y GL_RGBA deben coincidir exactamente.)

Si el parámetro internalformat es uno de los formatos genéricos comprimidos, GL_COMPRESSED_RED, GL_COMPRESSED_RG, GL_COMPRESSED_RGB, o GL_COMPRESSED_RGBA, el GL reemplazará el formato interno con la constante simbólica de un formato interno específico y comprimirá la textura antes de su almacenamiento. Si no hay un formato interno correspondiente disponible, o si el GL no puede comprimir la imagen por alguna razón, el formato interno se reemplazará en su lugar por un formato interno base correspondiente.

Si el parámetro internalformat es GL_SRGB, GL_SRGB8, GL_SRGB_ALPHA, o GL_SRGB8_ALPHA8, la textura se tratará como si los componentes rojo, verde o azul estuvieran codificados en el espacio de color sRGB. Cualquier componente alfa se dejará sin cambios. La conversión de un componente codificado en sRGB cs a un componente lineal cl es:

cl = { cs * 12.92 si cs ≤ 0.04045 ( cs + 0.055 ) / 1.055 ^ 2.4 si cs > 0.04045

Se asume que cs es el componente sRGB en el rango [0,1].

Utilice el destino GL_PROXY_TEXTURE_2D, GL_PROXY_TEXTURE_1D_ARRAY, GL_PROXY_TEXTURE_RECTANGLE, o GL_PROXY_TEXTURE_CUBE_MAP para probar una resolución y un formato. La implementación actualizará y recalculará su mejor coincidencia para la resolución y el formato de almacenamiento solicitados. Para consultar este estado, llame a glGetTexLevelParameter(). Si la textura no puede ser acomodada, el estado de la textura se establecerá en 0.

Una imagen de textura de un solo componente utiliza solo el componente rojo del color RGBA extraído de data. Una imagen de dos componentes utiliza los valores R y G. Una imagen de tres componentes utiliza los valores R, G y B. Una imagen de cuatro componentes utiliza todos los componentes RGBA.

El sombreado basado en imágenes se puede habilitar comparando las coordenadas r de la textura con los valores de la textura de profundidad para generar un resultado booleano. Consulte glTexParameter() para obtener detalles sobre la comparación de texturas.

NOTAS

El modo glPixelStore() afecta a las imágenes de textura.

data puede ser un puntero nulo. En este caso, se asignará memoria de textura para acomodar una textura de ancho width y alto height. Luego puede descargar subtexturas para inicializar esta memoria de textura. La imagen no está definida si el usuario intenta aplicar una porción no inicializada de la imagen de textura a una primitiva.

glTexImage2D especifica la textura bidimensional para la unidad de textura actual, especificada con glActiveTexture().

GL_STENCIL_INDEX puede usarse para format solo si la versión de GL es 4.4 o superior.

GL_INVALID_ENUM se genera si target no es GL_TEXTURE_2D, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_RECTANGLE, GL_PROXY_TEXTURE_2D, GL_PROXY_TEXTURE_1D_ARRAY, GL_PROXY_TEXTURE_RECTANGLE, GL_PROXY_TEXTURE_CUBE_MAP, GL_TEXTURE_CUBE_MAP_POSITIVE_X, GL_TEXTURE_CUBE_MAP_NEGATIVE_X, GL_TEXTURE_CUBE_MAP_POSITIVE_Y, GL_TEXTURE_CUBE_MAP_NEGATIVE_Y, GL_TEXTURE_CUBE_MAP_POSITIVE_Z, o GL_TEXTURE_CUBE_MAP_NEGATIVE_Z.

GL_INVALID_ENUM se genera si target es uno de los seis objetivos de imagen 2D de mapa cúbico y los parámetros de ancho y alto no son iguales.

GL_INVALID_ENUM se genera si type no es una constante de tipo.

GL_INVALID_VALUE se genera si width es menor que 0 o mayor que GL_MAX_TEXTURE_SIZE.

GL_INVALID_VALUE se genera si target no es GL_TEXTURE_1D_ARRAY o GL_PROXY_TEXTURE_1D_ARRAY y height es menor que 0 o mayor que GL_MAX_TEXTURE_SIZE.

GL_INVALID_VALUE se genera si target es GL_TEXTURE_1D_ARRAY o GL_PROXY_TEXTURE_1D_ARRAY y height es menor que 0 o mayor que GL_MAX_ARRAY_TEXTURE_LAYERS.

GL_INVALID_VALUE se genera si level es menor que 0.

GL_INVALID_VALUE puede generarse si level es mayor que log 2 ⁡ max, donde max es el valor devuelto de GL_MAX_TEXTURE_SIZE.

GL_INVALID_VALUE se genera si internalformat no es una de las constantes simbólicas de resolución y formato aceptadas.

GL_INVALID_VALUE se genera si width o height es menor que 0 o mayor que GL_MAX_TEXTURE_SIZE.

GL_INVALID_VALUE se genera si border no es 0.

GL_INVALID_OPERATION se genera si type es uno de GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, GL_UNSIGNED_SHORT_5_6_5_REV, o GL_UNSIGNED_INT_10F_11F_11F_REV, y format no es GL_RGB.

GL_INVALID_OPERATION se genera si type es uno de GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, GL_UNSIGNED_INT_2_10_10_10_REV, o GL_UNSIGNED_INT_5_9_9_9_REV, y format no es ni GL_RGBA ni GL_BGRA.

GL_INVALID_OPERATION se genera si target no es GL_TEXTURE_2D, GL_PROXY_TEXTURE_2D, GL_TEXTURE_RECTANGLE, o GL_PROXY_TEXTURE_RECTANGLE, y internalformat es GL_DEPTH_COMPONENT, GL_DEPTH_COMPONENT16, GL_DEPTH_COMPONENT24, o GL_DEPTH_COMPONENT32F.

GL_INVALID_OPERATION se genera si format es GL_DEPTH_COMPONENT y internalformat no es GL_DEPTH_COMPONENT, GL_DEPTH_COMPONENT16, GL_DEPTH_COMPONENT24, o GL_DEPTH_COMPONENT32F.

GL_INVALID_OPERATION se genera si internalformat es GL_DEPTH_COMPONENT, GL_DEPTH_COMPONENT16, GL_DEPTH_COMPONENT24, o GL_DEPTH_COMPONENT32F, y format no es GL_DEPTH_COMPONENT.

GL_INVALID_OPERATION se genera si un nombre de objeto de búfer distinto de cero está vinculado al objetivo GL_PIXEL_UNPACK_BUFFER y el almacén de datos del objeto de búfer está actualmente mapeado.

GL_INVALID_OPERATION se genera si un nombre de objeto de búfer distinto de cero está vinculado al objetivo GL_PIXEL_UNPACK_BUFFER y los datos se desempaquetarían del objeto de búfer de manera que las lecturas de memoria requeridas excederían el tamaño del almacén de datos.

GL_INVALID_OPERATION se genera si un nombre de objeto de búfer distinto de cero está vinculado al objetivo GL_PIXEL_UNPACK_BUFFER y data no es divisible uniformemente por el número de bytes necesarios para almacenar en memoria un dato indicado por type.

GL_INVALID_VALUE se genera si target es GL_TEXTURE_RECTANGLE o GL_PROXY_TEXTURE_RECTANGLE y level no es 0.
