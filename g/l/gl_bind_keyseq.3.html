DESCRIPCIÓN

La función gl_get_line() forma parte de la biblioteca tecla (ver la página del manual libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le pide una línea de entrada, luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de unix. Además de la edición simple de línea de comandos, admite la recuperación de líneas de comandos introducidas previamente, la finalización con TAB de nombres de archivo y la expansión de comodines de nombres de archivo en línea. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario, se puede encontrar en la página del manual tecla(7). Esta página del manual se centra en la documentación para programadores interesados en usar esta biblioteca en su aplicación.

UN EJEMPLO

Lo siguiente muestra un ejemplo completo de cómo usar la función gl_get_line() para obtener entrada del usuario:

  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que el usuario escribió */
    GetLine *gl;   /* El objeto de recursos de gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* de conjunto de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("Escribiste: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
  }

En el ejemplo, primero se crean los recursos necesarios para la función gl_get_line() llamando a new_GetLine(). Esto asigna la memoria utilizada en llamadas posteriores a la función gl_get_line(), incluido el búfer de historial para registrar las líneas introducidas previamente. Luego se leen una o más líneas del usuario, hasta que ocurre un error o el usuario escribe exit. Luego, finalmente, los recursos que fueron asignados por new_GetLine() se devuelven al sistema llamando a del_GetLine(). Observe el uso del valor de retorno NULL de del_GetLine() para hacer que gl sea NULL. Esto es una medida de precaución. Si el programa intenta posteriormente pasar gl a gl_get_line(), dicha función se quejará y devolverá un error, en lugar de intentar usar el objeto de recurso eliminado.

LAS FUNCIONES UTILIZADAS EN EL EJEMPLO

Las descripciones de las funciones utilizadas en el ejemplo son las siguientes:

  GetLine *new_GetLine(size_t linelen, size_t histlen)

Esta función crea los recursos utilizados por la función gl_get_line() y devuelve un puntero opaco al objeto que los contiene. La longitud máxima de una línea de entrada se especifica a través del argumento linelen, y el número de bytes a asignar para almacenar líneas del historial se establece mediante el argumento histlen. Las líneas del historial se almacenan una detrás de otra en un único búfer de este tamaño. Tenga en cuenta que esto significa que el número de líneas del historial que se pueden almacenar en cualquier momento depende de las longitudes de las líneas individuales. Si desea establecer un límite superior en el número de líneas que se pueden almacenar, consulte la función gl_limit_history() descrita más adelante. Si no desea historial en absoluto, especifique histlen como cero, y no se asignará ningún búfer de historial.

En caso de error, se imprime un mensaje en stderr y se devuelve NULL.

  GetLine *del_GetLine(GetLine *gl)

Esta función elimina los recursos que fueron devueltos por una llamada anterior a new_GetLine(). Siempre devuelve NULL (es decir, un objeto eliminado). No hace nada si el argumento gl es NULL.

  char *gl_get_line(GetLine *gl, const char *prompt,
                   const char *start_line, int start_pos);

La función gl_get_line() se puede llamar cualquier número de veces para leer la entrada del usuario. El argumento gl debe haber sido devuelto previamente por una llamada a new_GetLine(). El argumento prompt debe ser una cadena normal terminada en NUL, que especifica el prompt que se le presentará al usuario. Por defecto, los prompts se muestran literalmente, pero si se habilitan con la función gl_prompt_style() (ver más adelante), los prompts pueden contener directivas para hacer subrayado, cambiar a y desde fuentes en negrita, o activar y desactivar el resaltado.

Si desea especificar el contenido inicial de la línea, para que el usuario lo edite, pase la cadena deseada a través del argumento start_line. Luego puede especificar en qué carácter de esta línea está posicionado inicialmente el cursor

Si no quieres precargar la línea de esta manera, envía start_line como NULL y establece start_pos a -1. Ten en cuenta que el puntero de línea devuelto por una llamada a gl_get_line() puede pasarse a la siguiente llamada a gl_get_line() a través de start_line. Esto permite a la aplicación tomar la última línea introducida y, si contiene un error, presentarla de nuevo al usuario para su reedición, con el cursor inicialmente posicionado donde se encontró el error.

La función gl_get_line() devuelve un puntero a la línea introducida por el usuario, o NULL en caso de error o al final de la entrada. El puntero devuelto forma parte del objeto de recurso gl especificado y, por lo tanto, el llamador no debe liberarlo ni asumir que cambiará de una llamada a la siguiente. Al leer de un usuario en una terminal, siempre habrá un carácter de nueva línea al final de la línea devuelta. Cuando la entrada estándar se toma de una tubería o un archivo, habrá una nueva línea de manera similar, a menos que la línea de entrada sea demasiado larga para almacenarla en el búfer interno. En este último caso, deberías llamar a gl_get_line() de nuevo para leer el resto de la línea. Ten en cuenta que este comportamiento hace que gl_get_line() sea similar a fgets(). De hecho, cuando stdin no está conectado a una terminal, gl_get_line() simplemente llama a fgets().

                               size_t n);

FUENTES DE CONFIGURACIÓN ALTERNATIVAS

Como se mencionó anteriormente, por defecto los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. Sin embargo, en algunas aplicaciones, este único medio de configuración es un problema. Esto es particularmente cierto en el software embebido, donde no hay un sistema de archivos para leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de enlaces de teclas para emular una interfaz de teclado heredada. Para atender tales casos, la siguiente función permite a la aplicación controlar de dónde se leen las informaciones de configuración.

  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file);

Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc de un usuario, se lean de cualquiera o ninguna de las siguientes fuentes: una cadena, un archivo de configuración específico de la aplicación y/o un archivo de configuración específico del usuario. Si esta función se llama antes de la primera llamada a gl_get_line(), se deshabilita el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line(), por lo que toda la configuración debe lograrse utilizando las fuentes de configuración especificadas con esta función.

Si app_string != NULL, se interpreta como una cadena que contiene uno o más comandos de configuración, separados entre sí en la cadena por caracteres de nueva línea incrustados. Si app_file != NULL, se interpreta como la ruta de acceso completa de un archivo de configuración específico de la aplicación. Si user_file != NULL, se interpreta como la ruta de acceso completa de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente llamada,

  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc");

el argumento app_string hace que la aplicación que llama comience en modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso del timbre de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración del sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario desde un archivo opcional .teclarc en el directorio de inicio del usuario. Ten en cuenta que los argumentos se enumeran en orden ascendente de prioridad, y el contenido de app_string puede ser anulado por comandos en app_file, y los comandos en app_file pueden ser anulados por comandos en user_file.

Por defecto, gl_get_line() no retorna hasta que se ha introducido una línea de entrada completa por parte del usuario, o hasta que ocurre un error. En programas que necesitan vigilar la E/S de otras fuentes además del terminal, hay dos

opciones. 
  1. Use las funciones descritas en la página del manual
     gl_io_mode(3) para cambiar
     gl_get_line() al modo servidor no bloqueante. En este modo,
     gl_get_line() se convierte en una función de edición de líneas
     incremental no bloqueante que puede llamarse de forma segura desde
     un bucle de eventos externo. Aunque este es un método muy
     versátil, implica asumir algunas
     responsabilidades que normalmente se realizan de forma transparente por gl_get_line().
  2. Mientras gl_get_line() está esperando la entrada del
     teclado del usuario, puede pedirle que también vigile
     la actividad en descriptores de archivo arbitrarios, como
     sockets de red, tuberías, etc., y que llame a funciones
     de su elección cuando se detecte actividad. Esto funciona en
     cualquier sistema que tenga la llamada al sistema select(), que es la mayoría, si no todos, de los sabores de
unix.

Si esto retorna un valor distinto de cero, significa que o bien sus argumentos son inválidos, o que esta funcionalidad no es compatible con el sistema

anfitrión.

El argumento fd es el descriptor de archivo a vigilar. El argumento event especifica qué tipo de actividad es de interés, elegido de los siguientes valores

enumerados: 
  GLFD_READ   -  Vigilar la llegada de datos para leer.
  GLFD_WRITE  -  Vigilar la capacidad de escribir en el descriptor
                 de archivo sin bloquear.
  GLFD_URGENT -  Vigilar la llegada de datos urgentes
                 fuera de banda en el descriptor de
archivo.

El argumento callback es la función a llamar cuando se detecta la actividad seleccionada. Debe definirse con el siguiente macro, que está definido en libtecla.

                                      void *data, int fd, \
                                      GlFdEvent
event)

El argumento data de la función gl_watch_fd() se pasa a la función de retorno de llamada para su propio uso, y puede apuntar a lo que desee, incluyendo NULL. El descriptor de archivo y el argumento event también se pasan a la función de retorno de llamada, y esto potencialmente permite que la misma función de retorno de llamada se registre para más de un tipo de evento y/o más de un descriptor de archivo. El valor de retorno de la función de retorno de llamada debe ser uno de los siguientes

valores. 
  GLFD_ABORT    -  Decirle a gl_get_line() que aborte. Cuando esto
                   ocurre, gl_get_line() retorna
                   NULL, y una llamada posterior a
                   gl_return_status() retornará
                   GLR_FDABORT. Nótese que si la
                   aplicación necesita errno tenga
                   siempre un valor significativo cuando
                   gl_get_line() retorna NULL,
                   la función de retorno de llamada debe establecer
                   errno adecuadamente.
  GLFD_REFRESH  -  Redibujar la línea de entrada y luego continuar
                   esperando la entrada. Retorne esto si
                   su retorno de llamada escribió en el terminal.

                   redibujar la

Nótese que antes de llamar al retorno de llamada, gl_get_line() bloquea la mayoría de las señales, y deja instalados sus propios manejadores de señales, así que si necesita capturar una señal en particular, necesitará tanto instalar temporalmente su propio manejador de señales, como desbloquear la señal. Asegúrese de volver a bloquear la señal (si estaba originalmente bloqueada) y reinstalar el manejador de señales original, si lo hay, antes de

retornar.

Si la función de retorno de llamada necesita leer o escribir en el terminal, idealmente debería primero llamar a gl_normal_io(gl) para suspender temporalmente la edición de líneas. Esto restaurará el terminal al modo canónico, de E/S bloqueante, y moverá el cursor al inicio de una nueva línea del terminal. Más tarde, cuando el retorno de llamada retorna, gl_get_line() notará que gl_normal_io() fue llamada, volverá a mostrar la línea de entrada y reanudará la edición. EL TAMAÑO DEL

TERMINAL

En la mayoría de los sistemas, la combinación del ioctl TIOCGWINSZ y la señal SIGWINCH se utiliza para mantener una idea precisa del tamaño del terminal. El tamaño del terminal se consulta de nuevo cada vez que se llama a gl_get_line() y siempre que se recibe una señal SIGW

INCH.

En los pocos sistemas donde este mecanismo no está disponible, al inicio new_GetLine() primero busca las variables de entorno LINES y COLUMNS. Si estas no se encuentran, o contienen valores inutilizables, entonces si está disponible una base de datos de información del terminal como terminfo o termcap, se busca en esta base de datos el tamaño por defecto del terminal. Si esto tampoco proporciona el tamaño del terminal, se utiliza un tamaño por defecto de 80 columnas por 24

líneas.

Incluso en sistemas que sí admiten ioctl(TIOCGWINSZ), si el terminal está en el otro extremo de una línea serie, el controlador del terminal generalmente no tiene forma de detectar cuándo ocurre un redimensionamiento ni de consultar cuál es el tamaño actual. En tales casos, no se envía ningún SIGWINCH al proceso, y las dimensiones devueltas por ioctl(TIOCGWINSZ) no son correctas. La única forma de manejar tales instancias es proporcionar una manera para que el usuario introduzca un comando que le diga al sistema remoto cuál es el nuevo tamaño. Este comando llamaría entonces a la función gl_set_term_size() para informar a gl_get_line() sobre el cambio de

tamaño. 
  int gl_set_term_size(GetLine *gl, int ncolumn, int nline)
;

Los argumentos ncolumn y nline se utilizan para especificar las nuevas dimensiones del terminal, y no deben ser menores que 1. En sistemas que sí admiten ioctl(TIOCGWINSZ), esta función primero llama a ioctl(TIOCSWINSZ) para informar al controlador del terminal sobre el cambio de tamaño. En el modo de E/S de servidor no bloqueante, si actualmente se está introduciendo una línea, la línea de entrada se redibuja para acomodarse al tamaño cambiado. Finalmente, los nuevos valores se registran en gl para su uso futuro por gl_get_li

ne().

La función gl_terminal_size() le permite consultar el tamaño actual del terminal, e instalar un tamaño de reserva alternativo para los casos en que el tamaño no esté disponible. Tenga en cuenta que el tamaño del terminal no estará disponible si se lee desde una tubería o un archivo, por lo que los valores por defecto pueden ser importantes incluso en sistemas que sí admiten formas de averiguar el tamaño del

terminal. 
  typedef struct {
    int nline;        /* El terminal tiene nline líneas */
    int ncolumn;      /* El terminal tiene ncolumn columnas */
  } GlTerminalSize;
  GlTerminalSize gl_terminal_size(GetLine *gl,
                                  int def_ncolumn,
                                  int def_nline)
;

Esta función primero actualiza las dimensiones de reserva del terminal de gl_get_line(), luego registra sus hallazgos en el valor de

retorno.

Los argumentos def_ncolumn y def_nline especifican el número por defecto de columnas y líneas del terminal a usar si el tamaño del terminal no puede ser determinado vía ioctl(TIOCGWINSZ) o

variables d
e entorno.

OCULTANDO LO QUE

ESCRIBES

Al introducir información sensible, como contraseñas, es mejor no tener el texto que estás introduciendo reflejado en el terminal. Además, dicho texto no debería ser registrado en la lista de historial, ya que alguien que encuentre tu terminal sin vigilancia podría entonces recuperarlo, o alguien que esté husmeando en tus directorios podría verlo en tu archivo de historial. Teniendo esto en cuenta, la función gl_echo_mode() te permite activar y desactivar la visualización y el archivo de cualquier texto que se introduzca posteriormente en llamadas a gl_get_li

ne(). 
  int gl_echo_mode(GetLine *gl, int enable)
;

El argumento enable especifica si el texto introducido debe ser visible o no. Si es 0, entonces las líneas introducidas posteriormente no serán visibles en el terminal, y no serán registradas en la lista de historial. Si es 1, entonces las líneas de entrada posteriores serán mostradas a medida que se introducen, y siempre que el historial no haya sido desactivado mediante una llamada a gl_toggle_history(), también serán archivadas en la lista de historial. Finalmente, si el argumento enable es -1, entonces el modo de eco se deja sin cambios, lo que le permite consultar de forma no destructiva la configuración actual a través del valor de retorno. En todos los casos, el valor de retorno de la función es 0 si el eco estaba desactivado antes de que la función fuera llamada, y 1 si estaba

activado.

Cuando el eco está desactivado, tenga en cuenta que aunque la compl

etación con tabulador completará de forma invisible su prefijo tant
o como sea posible, las completaciones ambiguas no serán mostradas.

CONSULTAS DE UN SOLO

CARÁCTER

Usar gl_get_line() para consultar al usuario por una respuesta de un solo carácter, es inconveniente para el usuario, ya que debe presionar la tecla intro o retorno antes de que el carácter que escribió sea devuelto al programa. Por lo tanto, la función gl_query_char() ha sido proporcionada para consultas de un solo carácter como

esta. 
  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar)
;

Esta función muestra el prompt especificado al comienzo de una nueva línea, y espera a que el usuario escriba un carácter. Cuando el usuario escribe un carácter, gl_query_char() lo muestra a la derecha del prompt, inicia una nueva línea, y luego devuelve el carácter al programa que lo llamó. El valor de retorno de la función es el carácter que fue escrito. Si la lectura tuvo que ser abortada por alguna razón, se devuelve EOF en su lugar. En el último caso, la aplicación puede llamar a la previamente documentada gl_return_status(), para averiguar qué salió mal. Esto podría, por ejemplo, haber sido la recepción de una señal, o el temporizador opcional de inactividad

activándose.

Si el usuario simplemente presiona intro, el valor del argumento defchar es sustituido. Esto significa que cuando el usuario presiona ya sea newline o return, el carácter especificado en defchar, es mostrado después del prompt, como si el usuario lo hubiera escrito, así como ser devuelto a la aplicación que lo llamó. Si tal reemplazo no es importante, simplemente pase '0 como el valor de defchar

.

Si el carácter introducido es un carácter no imprimible, se muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y los caracteres más allá de 127 se muestran en octal, precedidos por una barra

invertida.

Al igual que con gl_get_line(), el eco del carácter introducido puede ser desactivado usando la función gl_echo_mode()

.

Si el proceso que llama es suspendido mientras espera a que el usuario escriba su respuesta, el cursor se mueve a la línea siguiente a la línea del prompt, luego, cuando el proceso se reanuda, el prompt se vuelve a mostrar, y gl_query_char() reanuda la espera de que el usuario escriba un

carácter.

Tenga en cuenta que en el modo de servidor no bloqueante, (vea gl_io_mode(3)), si una línea de entrada incompleta está en proceso de ser leída cuando se llama a gl_query_char(), la línea de entrada parcial es descartada, y borrada del terminal, antes de que el nuevo prompt sea mostrado. La siguiente llamada a gl_get_line() comenzará por ta

nto a editar u
na nueva línea.

LEYENDO CARACTERES

CRUDOS

Mientras que la función gl_query_char() solicita visiblemente al usuario un carácter, y muestra lo que escribió, la función gl_read_char() lee un carácter del usuario, sin escribir nada en el terminal, ni perturbar ninguna línea de entrada incompleta. Esto significa que puede ser llamada no solo entre llamadas a gl_get_line(), sino también desde funciones de retorno de llamada que la aplicación ha registrado para ser llamadas por gl_get_li

ne(). 
  int gl_read_char(GetLine *gl)
;

En caso de éxito, el valor de retorno de gl_read_char() es el carácter que fue leído. En caso de fallo, se devuelve EOF, y la función gl_return_status() puede ser llamada para averiguar qué salió mal. Las posibilidades incluyen el temporizador opcional de inactividad activándose, la recepción de una señal que está configurada para abortar gl_get_line(), o el bloqueo de la E/S del terminal, cuando se está en el modo de E/S de servidor no

bloqueante.

Tenga en cuenta que ciertas teclas del teclado, como las teclas de función y las teclas de cursor, usualmente generan al menos 3 caracteres cada una, por lo que una sola llamada a gl_read_char() no sea suficiente para

identificar dichas pu
lsaciones de teclas.

VISUALIZACIÓN DINÁMICA DE

TEXTO

Entre las llamadas a gl_get_line(), la función gl_display_text() proporciona una manera conveniente de mostrar párrafos de texto, justificados a la izquierda y divididos en una o más líneas de la terminal de acuerdo con las restricciones del ancho actual de la terminal. Ejemplos del uso de esta función se pueden encontrar en los programas de demostración, donde se utiliza para mostrar introducciones. En esos ejemplos también se ilustra el uso avanzado de prefijos, sufijos y líneas de relleno opcionales para dibujar un cuadro alrededor del

texto. 
  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string)
;

Si gl no está actualmente conectado a una terminal, por ejemplo si la salida de un programa que usa gl_get_line() se está canalizando a otro programa o se está redirigiendo a un archivo, entonces se usa el valor del parámetro def_width como el ancho de la

terminal.

El argumento indentation especifica el número de caracteres a usar para sangrar cada línea de salida. El argumento fill_char especifica el carácter que se usará para realizar esta

sangría.

El argumento prefix puede ser NULL, o ser una cadena de texto a colocar al comienzo de cada línea nueva (después de cualquier sangría). De manera similar, el argumento suffix puede ser NULL, o ser una cadena de texto a colocar al final de cada línea. El sufijo se coloca alineado contra el borde derecho de la terminal, y cualquier espacio entre su primer carácter y la última palabra de esa línea se rellena con el carácter especificado a través del argumento fill_char. Normalmente el carácter de relleno es un

espacio.

El argumento start le indica a gl_display_text() cuántos caracteres ya se han escrito en la línea de terminal actual, y por lo tanto le indica el índice de columna inicial del cursor. Dado que el valor de retorno de gl_display_text() es el índice de columna final del cursor, al pasar el valor de retorno de una llamada al argumento start de la siguiente llamada, se puede componer un párrafo que está dividido entre más de una cadena llamando a gl_display_text() para cada porción sucesiva del párrafo. Nótese que son necesarios caracteres de salto de línea literales al final de cada párrafo para forzar que se inicie una línea

nueva.

JUEGOS DE CARACTERES

INTERNACIONALES

Desde la versión 1.4.0 de libtecla, gl_get_line() ha sido compatible con 8 bits. Esto significa que todos los caracteres de 8 bits que son imprimibles en el locale actual del usuario ahora se muestran literalmente y se incluyen en la línea de entrada devuelta. Asumiendo que el programa que llama contiene correctamente una llamada como la

siguiente, 
  setlocale(LC_CTYPE, "")
;

entonces el locale actual lo determina la primera de las variables de entorno LC_CTYPE, LC_ALL, y LANG, que se encuentre que contiene un nombre de locale válido. Si ninguna de estas variables está definida, o el programa omite llamar a setlocale, entonces se usa el locale por defecto C, que es ASCII de 7 bits de EE. UU. En la mayoría de las plataformas tipo unix, se puede obtener una lista de locales válidos escribiendo el

comando: 
  locale
-a

en el símbolo del shell. Se puede encontrar documentación adicional sobre cómo el usuario puede hacer uso de esto para introducir caracteres internacionales en la página del man

ual te
cla(7).

SEGURIDAD DE

HILOS

En un programa multihilo, se debe usar la versión libtecla_r.a de la biblioteca. Esta usa versiones reentrantes de las funciones del sistema, cuando están disponibles. Desafortunadamente, ni terminfo ni termcap fueron diseñados para ser reentrantes, por lo

que no se pueden usar de forma segura las funciones del módulo getline en múltiples hilos (se pueden usar los módulos separados de expansión de archivos y completado de palabras en múltiples hilos, véanse las páginas de manual correspondientes para más det
alles). Sin embargo, debido al uso de funciones reentrantes de POSIX para buscar directorios de inicio, etc., es seguro usar este módulo desde un solo hilo de un programa multihilo, siempre que sus otros hilos no usen ninguna función de termcap o terminfo.
