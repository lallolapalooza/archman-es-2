DESCRIPCIÓN

La función gl_get_line() es parte de la biblioteca tecla (ver la página del manual de libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactiva, similares a las del shell tcsh de Unix. Además de la edición simple de la línea de comandos, admite la recuperación de líneas de comandos previamente introducidas, la finalización con TAB de nombres de archivo y la expansión de comodines de nombres de archivo en línea. La documentación de las características de edición de la línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario se puede encontrar en la página del manual de tecla(7). Esta página del manual se centra en la documentación para programadores interesados en usar esta biblioteca en sus aplicaciones.

UN EJEMPLO

Lo siguiente muestra un ejemplo completo de cómo usar la función gl_get_line() para obtener entrada del usuario:

  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que escribió el usuario */
    GetLine *gl;   /* El objeto de recursos de gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* de conjunto de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("Escribiste: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
  }

En el ejemplo, primero se crean los recursos necesarios para la función gl_get_line() llamando a new_GetLine(). Esto asigna la memoria utilizada en llamadas posteriores a la función gl_get_line(), incluido el búfer de historial para registrar líneas introducidas previamente. Luego se leen una o más líneas del usuario, hasta que ocurre un error o el usuario escribe exit. Finalmente, los recursos que fueron asignados por new_GetLine() se devuelven al sistema llamando a del_GetLine(). Tenga en cuenta el uso del valor de retorno NULL de del_GetLine() para hacer que gl sea NULL. Esta es una medida de seguridad. Si el programa posteriormente intenta pasar gl a gl_get_line(), dicha función se quejará y devolverá un error, en lugar de intentar utilizar el objeto de recursos eliminado.

LAS FUNCIONES UTILIZADAS EN EL EJEMPLO

Las descripciones de las funciones utilizadas en el ejemplo son las siguientes:

  GetLine *new_GetLine(size_t linelen, size_t histlen)

Esta función crea los recursos utilizados por la función gl_get_line() y devuelve un puntero opaco al objeto que los contiene. La longitud máxima de una línea de entrada se especifica a través del argumento linelen, y el número de bytes a asignar para almacenar líneas de historial se establece mediante el argumento histlen. Las líneas de historial se almacenan una detrás de otra en un único búfer de este tamaño. Tenga en cuenta que esto significa que el número de líneas de historial que se pueden almacenar en cualquier momento depende de las longitudes de las líneas individuales. Si desea establecer un límite superior en el número de líneas que se pueden almacenar, consulte la función gl_limit_history() descrita más adelante. Si no desea historial en absoluto, especifique histlen como cero y no se asignará ningún búfer de historial.

En caso de error, se imprime un mensaje en stderr y se devuelve NULL.

  GetLine *del_GetLine(GetLine *gl)

Esta función elimina los recursos que fueron devueltos por una llamada anterior a new_GetLine(). Siempre devuelve NULL (es decir, un objeto eliminado). No hace nada si el argumento gl es NULL.

  char *gl_get_line(GetLine *gl, const char *prompt,
                   const char *start_line, int start_pos);

La función gl_get_line() puede llamarse cualquier número de veces para leer la entrada del usuario. El argumento gl debe haber sido devuelto previamente por una llamada a new_GetLine(). El argumento prompt debe ser una cadena normal terminada en NUL, que especifica el aviso que se presentará al usuario. Por defecto, los avisos se muestran literalmente, pero si se habilitan con la función gl_prompt_style() (ver más adelante), los avisos pueden contener directivas para hacer subrayado, cambiar entre fuentes en negrita o activar y desactivar el resaltado.

Si desea especificar el contenido inicial de la línea, para que el usuario lo edite, pase la cadena deseada a través del argumento start_line. Luego puede especificar en qué carácter de esta línea se posiciona inicialmente el cursor

sobre, usando el start_pos argumento. Este debería ser -1 si desea que el cursor siga al último carácter de la línea de inicio. Si no desea precargar la línea de esta manera, envíe start_line como NULL, y establezca start_pos a -1. Tenga en cuenta que el puntero de línea devuelto por una llamada a gl_get_line() puede pasarse a la siguiente llamada a gl_get_line() a través de start_line. Esto permite que la aplicación tome la última línea introducida y, si contiene un error, la presente de nuevo al usuario para su reedición, con el cursor inicialmente posicionado donde se encontró el error.

La gl_get_line() función devuelve un puntero a la línea introducida por el usuario, o NULL en caso de error o al final de la entrada. El puntero devuelto es parte del objeto recurso especificado gl , y por lo tanto no debe ser liberado (free'd) por el llamante, ni asumirse que es inmutable de una llamada a la siguiente. Al leer de un usuario en una terminal, siempre habrá un carácter de nueva línea al final de la línea devuelta. Cuando la entrada estándar se toma de una tubería (pipe) o de un archivo, de manera similar habrá una nueva línea a menos que la línea de entrada fuera demasiado larga para almacenarse en el búfer interno. En este último caso, debería llamar a gl_get_line() de nuevo para leer el resto de la línea. Tenga en cuenta que este comportamiento hace que gl_get_line() sea similar a fgets(). De hecho, cuando stdin no está conectado a una terminal,gl_get_line() simplemente llama a fgets().

EL ESTADO DE RETORNO DE GL_GET_LINE

Como se describió anteriormente, la gl_get_line() función tiene dos valores de retorno posibles; un puntero a la línea de entrada completada, o NULL. Información adicional sobre qué causó que gl_get_line() retornara está disponible tanto al inspeccionar errno, como al llamar a la gl_return_status() función.

Los siguientes son los posibles valores enumerados que esta función devuelve.

El valor de retorno es un puntero al mensaje que ocurrió. Si el buff argumento es NULL, este será un puntero a un búfer dentro de gl, cuyo valor probablemente cambiará en la siguiente llamada a cualquier función asociada con gl_get_line(). elementos de este búfer, y el valor de retorno será un puntero al primer elemento de este búfer. Si el mensaje no cabe en el búfer proporcionado, se truncará para que quepa.

FUENTES DE CONFIGURACIÓN ALTERNATIVAS Como se mencionó anteriormente, de forma predeterminada los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc

  en sus directorios de inicio. El hecho de que todas
    las aplicaciones compartan este mismo archivo de configuración es tanto una
    ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya
    que fomenta la uniformidad y libera al usuario de tener que configurar cada
    aplicación por separado. Sin embargo, en algunas aplicaciones, este único
    medio de configuración es un problema. Esto es particularmente cierto en
    software embebido, donde no hay un sistema de archivos del cual leer un
    archivo de configuración, y también en aplicaciones donde se necesita una
    elección radicalmente diferente de asignaciones de teclas para emular una
    interfaz de teclado heredada. Para atender a tales casos, la siguiente
    función permite a la aplicación controlar de dónde se leen los datos de
    configuración.

int gl_configure_getline(GetLine *gl, const char *app_string, const char *app_file, const char *user_file); Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc del usuario, se lean de cualquiera o ninguno de: una cadena, un archivo de configuración específico de la aplicación y/o un archivo de configuración específico del usuario. Si esta función se llama antes de la primera llamada agl_get_line() , el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line()

está deshabilitado, por lo que toda la configuración debe lograrse utilizando las fuentes de configuración especificadas con esta función. Siapp_string != NULL , entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados entre sí en la cadena por caracteres de nueva línea incrustados. Si app_file != NULL entonces se interpreta como la ruta de archivo completa de un archivo de configuración específico de la aplicación. Si user_file != NULL entonces se interpreta como la ruta de archivo completa de un archivo de configuración específico del usuario, como~/.teclarc

  . Por ejemplo, en la siguiente llamada,

gl_configure_getline(gl, "edit-mode vi \n nobeep", "/usr/share/myapp/teclarc", "~/.teclarc"); el app_string argumento hace que la aplicación que llama comience en el modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso de la campana de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración de todo el sistema desde un archivo opcional llamado/usr/share/myapp/teclarc , y finalmente lee comandos de configuración específicos del usuario desde un archivo .teclarc opcional en el directorio de inicio del usuario. Tenga en cuenta que los argumentos se enumeran en orden ascendente de prioridad, con el contenido de app_string siendo potencialmente sobreescrito por comandos enapp_file , y los comandos en app_file siendo potencialmente sobreescritos por comandos enuser_file

. Puede llamar a esta función tantas veces como sea necesario, los resultados siendo acumulativos, pero tenga en cuenta que las copias de cualquier nombre de archivo especificado a través de los argumentos que comienzan conarchivo y user_file se registran internamente para su uso posterior por la read-init-files función de enlace de teclas, así que si planea llamar a esta función varias veces, asegúrese de que la última llamada especifique los nombres de archivo que desea volver a leer cuando el usuario solicite que los archivos de configuración sean releídos.

Las secuencias de teclas individuales también pueden ser enlazadas y desenlazadas usando la gl_bind_keyseq() función.

  int gl_bind_keyseq(GetLine *gl, GlKeyOrigin origin,
                     const char *keyseq,
                     const char *action);

El origin argumento especifica la prioridad del enlace, de acuerdo con para quién se está estableciendo, y debe ser uno de los siguientes dos valores.

  GL_USER_KEY   -   El usuario solicitó este enlace de teclas.
  GL_APP_KEY    -   Este es un enlace predeterminado establecido por la
                    aplicación.

Cuando se han especificado enlaces de usuario y de aplicación para una misma secuencia de teclas, el enlace del usuario tiene prioridad. El enlace de la aplicación se restablece posteriormente si el enlace del usuario es desenlazado más tarde a través de otra llamada a esta función, o de una llamada a gl_configure_getline().

El keyseq argumento especifica la secuencia de teclas a ser enlazada o desenlazada, y se expresa de la misma manera que en un archivo de configuración ~/.teclarc . El action argumento debe ser o bien una cadena que contenga el nombre de la acción a la que enlazar la secuencia de teclas, o debe ser NULL o "" para desenlazar la secuencia de teclas.

COMPLETADO DE PALABRAS PERSONALIZADO

Si en su aplicación, le gustaría que la completación con TAB complete otras cosas además de o en lugar de nombres de archivo, puede organizar esto registrando una función de retorno de completación alternativa, a través de una llamada a la gl_customize_completion() función.

  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn);

El data argumento proporciona una manera para que su aplicación pase información arbitraria y específica de la aplicación a la función de retorno. Esto se pasa a la función de retorno cada vez que es llamada. Podría, por ejemplo, apuntar a la tabla de símbolos de la que se deben buscar las posibles completaciones. El match_fn argumento especifica la función de retorno a ser llamada. El CplMatchFn tipo de función está definido en libtecla.h, al igual que una CPL_MATCH_FN() macro que puede usar para declarar y establecer prototipos de funciones de retorno. La declaración y las responsabilidades de las funciones de retorno se describen en profundidad en la página del manual cpl_complete_word(3).

En resumen, la función de retorno es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario pulsó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar completaciones posibles de esta palabra, y registrarlas una por una en el WordCompletion objeto que se le pasa como argumento, llamando a la cpl_add_completion() función. Si la función de retorno desea proporcionar completación de nombres de archivo además de sus propias completaciones específicas, tiene la opción de llamar por sí misma a la función de retorno de completación de nombres de archivo incorporada. Esto también está documentado en la página del manual cpl_complete_word(3) .

Tenga en cuenta que si le gustaría que gl_get_line() devuelva la línea de entrada actual cuando se haya realizado una completación exitosa, puede organizar esto cuando llame a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de nueva línea. Si hace esto, la línea de entrada se actualizará para mostrar la completación, junto con cualquier sufijo de continuación hasta el carácter de nueva línea, y luego gl_get_line() devolverá esta línea de entrada.

Si, por alguna razón, su función de retorno necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto comenzará una nueva línea después de la línea de entrada que está siendo editada actualmente, restablecerá la E/S normal de la terminal, y le dirá a gl_get_line() que la línea de entrada necesitará ser redibujada cuando la función de retorno regrese.

AÑADIENDO ACCIONES DE COMPLETACIÓN

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de completación predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que diferentes tipos de completación de palabras puedan ser enlazados a diferentes secuencias de teclas. Esto se logra usando la gl_completion_action() función.

  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq);

Los data y match_fn argumentos son como se describen en la página del manual cpl_complete_word , y especifican la función de retorno que debe ser invocada para identificar las completaciones posibles. El list_only argumento determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar cualquier completación ambigua posible, o si debe simplemente mostrar la lista de completaciones posibles sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El name argumento especifica el nombre por el cual los archivos de configuración y futuras invocaciones de esta función deben referirse a la acción. Este debe ser o bien el nombre de una acción de completación existente a ser cambiada, o un nombre nuevo sin usar para una nueva acción. Finalmente, el keyseq argumento especifica la secuencia de teclas predeterminada a la que enlazar la acción. Si esto es NULL, ninguna nueva secuencia de teclas será enlazada a la acción.

Tenga cuidado de que para que el usuario pueda cambiar la secuencia de teclas que está enlazada a las acciones que se instalan de esta manera, cuando llame a gl_completion_action() para instalar una acción dada por primera vez, debe hacerlo entre la llamada a new_GetLine() y la primera llamada a gl_get_line(). De lo contrario, cuando el archivo de configuración del usuario sea leído en la primera llamada a gl_get_line(), el nombre de su acción adicional no será conocido, y cualquier referencia a ella en el archivo de configuración generará un error.

Como se discutió para gl_customize_completion(), si su función de retorno, por alguna razón, necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo.

DEFINIENDO ACCIONES PERSONALIZADAS

Aunque las acciones de enlace de teclas incorporadas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, enlazadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza que correspondiera a un número de pieza que precede al cursor. Tal característica está claramente más allá del alcance de las funciones de acción incorporadas. Así que para tales casos especiales, se proporciona la gl_register_action() función.

  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq);

Esta función permite a la aplicación registrar una función externa, fn, que a partir de entonces será llamada cada vez que la secuencia de teclas especificada, keyseq, sea introducida por el usuario, o que el usuario introduzca cualquier otra secuencia de teclas que el usuario posteriormente enlace al nombre de acción especificado, name, en su archivo de configuración. El data argumento puede ser un puntero a cualquier cosa que la aplicación desee que sea pasada a la función de acción, fn, cada vez que esa función sea invocada.

La función de acción, fn, debe ser declarada usando la siguiente macro, que está definida en libtecla.h.

  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char *line)

Los gl y data argumentos son aquellos que fueron previamente pasados a gl_register_action() cuando la función de acción fue registrada. El count argumento es un argumento numérico que el usuario tiene la opción de introducir usando la acción digit-argument , antes de invocar la acción. Si el usuario no introduce un número, entonces el count argumento se establece en 1. Nominalmente este argumento se interpreta como un conteo de repetición, lo que significa que la acción debe ser repetida ese número de veces. En la práctica, sin embargo, para algunas acciones un conteo de repetición tiene poco sentido. En tales casos, las acciones pueden simplemente ignorar el count argumento, o usar su valor para un propósito diferente.

Una copia de la línea de entrada actual es pasada en el argumento de solo lectura line . La posición actual del cursor dentro de esta cadena es dada por el índice contenido en el curpos argumento. Tenga en cuenta que la manipulación directa de la línea de entrada y la posición del cursor no está permitida. Una solución potencial a este dilema sería permitir que la función de acción edite la línea usando las acciones de edición existentes. Esto está actualmente bajo consideración.

Si la función de acción desea escribir texto en la terminal, sin que esto se mezcle con el texto mostrado de la línea de entrada, o leer de la terminal sin tener que manejar la E/S cruda de la terminal, entonces antes de hacer cualquiera de estas operaciones, debe suspender temporalmente la edición de línea llamando a la gl_normal_io() función. Esta función vacía cualquier salida pendiente a la terminal, mueve el cursor al inicio de la línea que sigue a la última línea de terminal de la línea de entrada, y luego restaura la terminal a un estado que es adecuado para su uso con las instalaciones stdio de C. Lo último incluye cosas como restaurar el mapeo normal de \n a \r\n, y, cuando se está en modo servidor, restaurar la forma normal de bloqueo de la E/S de la terminal. Después de haber llamado a esta función, la acción puede leer de y escribir a la terminal sin temor a crear un desastre. ACCIONES DE USUARIO


Las funciones de acción se utilizan para permitir al usuario ejecutar
    comandos arbitrarios en el momento en que se está editando una línea. Por
    ejemplo, para permitir que el usuario ejecute el comando de C shell
    alias mientras edita una línea, puede usar la función
    gl_register_action() para registrar una acción y luego vincularla
    a una secuencia de teclas particular, como por ejemplo, "\ea"
    (control-e, a).


La función de acción definida a continuación es una versión muy
    simplificada de la que se usa en la implementación de esta biblioteca.


  #include <Get/Get.h>
  #include <stdio.h>
  int my_action(GetLine *gl, int ch)
  {
    if (gl_emacs_getchar(gl) == EOF)
      return GLA_ABORT;
    printf("Hello world\n");
    return GLA_CONTINUE;
  }


Las funciones de acción deben devolver uno de los siguientes valores,
    para indicar a gl_get_line() cómo proceder.


  GLA_ABORT     -   Hace que gl_get_line() devuelva NULL.
  GLA_RETURN    -   Hace que gl_get_line() devuelva la
                    línea de entrada completada.
  GLA_CONTINUE  -   Reanuda la edición de la línea de comandos.


Tenga en cuenta que el argumento name de
    gl_register_action() especifica el nombre por el cual un usuario puede
    referirse a la acción en su archivo de configuración. Esto les permite volver
    a vincular la acción a una secuencia de teclas alternativa. Para que esto
    funcione, es necesario llamar a gl_register_action() entre la llamada a
    new_GetLine() y la primera llamada a gl_get_line().






ARCHIVOS DE HISTORIAL


Para guardar el contenido del búfer de historial antes de salir de su
    aplicación, y posteriormente restaurarlo cuando la inicie de nuevo, se
    proporcionan las siguientes funciones.


 int gl_save_history(GetLine *gl, const char *filename,
                     const char *comment, int max_lines);
 int gl_load_history(GetLine *gl, const char *filename,
                     const char *comment);


El argumento filename especifica el nombre que se le dará al
    archivo de historial al guardar, o el nombre de un archivo de historial
    existente, al cargar. Esto puede contener expresiones de directorio de inicio
    y variables de entorno, como "~/.myapp_history" o
    "$HOME/.myapp_history".


Junto con cada línea del historial, se registra información
    adicional sobre ella, como cuándo fue ingresada por el usuario y cuál es su
    nivel de anidación, como un comentario que precede a la línea en el archivo
    de historial. Escribir esto como un comentario permite que el archivo de
    historial sirva también como archivo de comandos, en caso de que desee
    reproducir una sesión completa utilizándolo. Dado que los prefijos de
    comentario difieren en diferentes lenguajes, se proporciona el argumento
    comment para especificar el prefijo del comentario. Por ejemplo, si su
    aplicación fuera un shell de Unix, como el shell Bourne, especificaría
    "#" aquí. Cualquiera que elija para el carácter de comentario, debe
    especificar el mismo prefijo a gl_load_history() que utilizó cuando
    llamó a gl_save_history() para escribir el archivo de historial.


El argumento max_lines debe ser -1 para especificar que todas
    las líneas de la lista de historial se guarden, o un número positivo que
    especifique un límite superior de cuántas de las líneas más recientes se
    deben guardar.


Ambas funciones devuelven un valor distinto de cero en caso de error,
    después de escribir un mensaje de error en stderr. Tenga en cuenta que
    gl_load_history() no considera la no existencia de un archivo como un
    error.






LISTAS DE HISTORIAL MÚLTIPLES


Si su aplicación utiliza un único objeto GetLine para ingresar
    muchos tipos diferentes de líneas de entrada, es posible que desee que
    gl_get_line() distinga los diferentes tipos de líneas en la lista de
    historial y solo recupere líneas que coincidan con el tipo de línea actual.
    Para soportar este requisito, gl_get_line() marca las líneas que se
    están grabando en la lista de historial con un identificador entero elegido
    por la aplicación. Inicialmente, este identificador se establece en 0 por
    new_GetLine(), pero se puede cambiar posteriormente llamando a
    gl_group_history().


  int gl_group_history(GetLine *gl, unsigned id);


El identificador entero id puede ser cualquier número elegido
    por la aplicación, pero tenga en cuenta que gl_save_history() y
    gl_load_history() conservan la asociación entre los identificadores y
    las líneas de entrada históricas entre invocaciones del programa, por lo que
    debe elegir identificadores fijos para los diferentes tipos de líneas de
    entrada utilizados por su aplicación.


Cada vez que gl_get_line() agrega una nueva línea de entrada a
    la lista de historial, el identificador de historial actual se registra con
    ella, y cuando se le pide que recupere una línea de entrada histórica, solo
    recupera líneas que están marcadas con el identificador actual.






MOSTRANDO EL HISTORIAL


La lista de historial se puede mostrar llamando a
    gl_show_history().


  int gl_show_history(GetLine *gl, FILE *fp,
                      const char *fmt,
                      int all_groups,
                      int max_lines);


Esto muestra el contenido actual de la lista de historial al flujo de
    salida stdio fp. Si el argumento max_lines es mayor o igual a
    cero, no se mostrarán más de este número de las líneas más recientes. Si el
    argumento all_groups no es cero, se mostrarán líneas de todos los
    grupos de historial. De lo contrario, solo se mostrarán las del grupo de
    historial actualmente seleccionado. El argumento de cadena de formato,
    fmt, determina cómo se muestra la línea. Esto puede contener caracteres
    arbitrarios que se escriben verbatim, intercalados con cualquiera de las
    siguientes directivas de formato:


  %D  -  La fecha en que se ingresó originalmente la
         línea, formateada como 2001-11-20.
  %T  -  La hora del día en que se ingresó la línea,
         formateada como 23:59:59.
  %N  -  El número de entrada secuencial de la línea en
         el búfer de historial.
  %G  -  El número del grupo de historial al que
         pertenece la línea.
  %%  -  Un carácter % literal.
  %H  -  La línea de historial en sí.


Por lo tanto, una cadena de formato como
    "%D %T %H\n" generaría algo como:


  2001-11-20 10:23:34  Hello world


Tenga en cuenta la inclusión de un carácter de nueva línea explícito
    en la cadena de formato.






BUSCANDO EN EL HISTORIAL


La función gl_lookup_history() permite a la aplicación
    llamante buscar líneas en la lista de historial.


  typedef struct {
    const char *line;    /* La línea histórica */
                         /*  solicitada. */
    unsigned group;      /* El grupo de historial al que */
                         /*  pertenece la línea. */
    time_t timestamp;    /* La fecha y hora en que */
                         /*  se ingresó originalmente la */
                         /*  línea. */
  } GlHistoryLine;
  int gl_lookup_history(GetLine *gl, unsigned long id,
                        GlHistoryLine *hline);


El argumento id indica qué línea buscar, donde la primera
    línea que se ingresó en la lista de historial después de que se llamó a
    new_GetLine(), se denota con 0, y las líneas ingresadas posteriormente se
    denotan con números sucesivamente mayores. Tenga en cuenta que el rango de
    líneas actualmente conservadas en la lista de historial se puede consultar
    llamando a la función gl_range_of_history(), descrita más adelante. Si la
    línea solicitada está en la lista de historial, los detalles de la línea se
    registran en la variable apuntada por el argumento hline, y se devuelve
    1. De lo contrario, se devuelve 0, y la variable apuntada por
    hline permanece sin cambios.


Tenga en cuenta que la cadena devuelta en
    hline->line es parte del búfer de historial, por lo que no debe ser
    modificada por el llamador, y será reciclada en la próxima llamada a
    cualquier función que tome gl como argumento. Por lo tanto, debe hacer
    una copia privada de esta cadena si necesita conservarla.






ARCHIVO MANUAL DEL HISTORIAL


Por defecto, cada vez que el usuario ingresa una línea, se agrega
    automáticamente a la lista de historial, justo antes de que gl_get_line()
    devuelva la línea al llamador. Esto es conveniente para la mayoría de las
    aplicaciones, pero también hay aplicaciones que necesitan un control más
    detallado sobre lo que se agrega a la lista de historial. En tales casos, la
    adición automática de líneas ingresadas a la lista de historial se puede
    desactivar llamando a la función gl_automatic_history().


  int gl_automatic_history(GetLine *gl, int enable);


Si se llama a esta función con su argumento enable establecido
    en 0, gl_get_line() no archivará automáticamente las líneas
    ingresadas posteriormente. El archivado automático se puede volver a habilitar
    en un momento posterior, llamando a esta función nuevamente, con su argumento
    enable establecido en 1. Mientras el archivado automático del historial
    está deshabilitado, la aplicación llamante puede usar gl_append_history()
    para agregar líneas a la lista de historial según sea necesario.


  int gl_append_history(GetLine *gl, const char *line);


El argumento line especifica la línea que se agregará a la lista
    de historial. Debe ser una cadena normal terminada en ' '. Si esta
    cadena contiene algún carácter de nueva línea, la línea que se archive en la
    lista de historial terminará con el primero de ellos. De lo contrario,
    terminará con el terminador ' '. Si la línea es más larga que la
    longitud máxima de línea de entrada, que se especificó cuando se llamó a
    new_GetLine(), cuando se recupere la línea, se truncará a la longitud
    real de la línea de gl_get_line().


Si tiene éxito, gl_append_history() devuelve 0. De lo contrario,
    devuelve un valor distinto de cero y establece errno en uno de los
    siguientes valores.


   EINVAL  -  Uno de los argumentos pasados a
              gl_append_history() era NULL.
   ENOMEM  -  La línea especificada era más larga que el
              tamaño asignado del búfer de historial (como
              se especificó al llamar a new_GetLine()), por lo
              que no se pudo archivar.


Se puede obtener una descripción textual del error opcionalmente
    llamando a gl_error_message(). Tenga en cuenta que después de dicho
    error, la lista de historial permanece en un estado válido para recibir
    nuevas líneas de historial, por lo que hay poco daño en simplemente ignorar
    el estado de retorno de gl_append_history().






CONFIGURACIÓN MISCELÁNEA DEL HISTORIAL


Si desea cambiar el tamaño del búfer de historial que se especificó
    originalmente en la llamada a new_GetLine(), puede hacerlo con la
    función gl_resize_history().


  int gl_resize_history(GetLine *gl, size_t histlen);


El argumento histlen especifica el nuevo tamaño en bytes, y si
    especifica esto como 0, el búfer se eliminará.


Como se mencionó en la discusión de new_GetLine(), el número
    de líneas que se pueden almacenar en el búfer de historial depende de las
    longitudes de las líneas individuales. Por ejemplo, un búfer de 1000 bytes
    podría almacenar igualmente 10 líneas de longitud promedio de 100 bytes, o
    2 líneas de longitud promedio de 50 bytes. Aunque el búfer nunca se expande
    cuando se agregan nuevas líneas, una lista de punteros dentro del búfer se
    expande cuando es necesario para acomodar el número de líneas actualmente
    almacenadas en el búfer. Para colocar un límite superior en el número de
    líneas en el búfer, y por lo tanto un techo en la cantidad de memoria
    utilizada en esta lista, puede llamar a gl_limit_history

()
    función.


  void gl_limit_history(GetLine *gl, int max_lines);


El max_lines debe ser un número positivo >=
    0, que especifique un límite superior para el número de líneas en el búfer, o ser
    -1 para cancelar cualquier límite especificado previamente. Cuando un límite está en
    efecto, solo se conservan en el búfer las max_lines líneas añadidas más recientemente. Las líneas más antiguas se descartan.


Para descartar líneas del búfer de historial, use la
    gl_clear_history() función.


  void gl_clear_history(GetLine *gl, int all_groups);


El all_groups argumento le indica a la función si debe
    eliminar solo las líneas asociadas con el grupo de historial actual (véase
    gl_group_history()), o todas las líneas históricas en el búfer.


La gl_toggle_history() función le permite activar y desactivar
    el historial sin perder el contenido actual de la lista de historial.


  void gl_toggle_history(GetLine *gl, int enable);


Establecer el enable argumento en 0 desactiva el mecanismo de historial, y establecerlo en 1 lo reactiva. Cuando el historial está desactivado,
    no se añadirán nuevas líneas a la lista de historial, y las combinaciones de teclas de búsqueda de historial actuarán como si no hubiera nada en el búfer de historial.

CAMBIO DE TERMINALES


La new_GetLine() función constructora asume que la entrada
    debe leerse de stdin, y la salida escribirse en stdout. La
    siguiente función le permite cambiar a flujos de entrada y salida
    diferentes.


  int gl_change_terminal(GetLine *gl, FILE *input_fp,
                         FILE *output_fp, const char *term);


El gl argumento es el objeto que fue devuelto por
    new_GetLine(). El input_fp argumento especifica el flujo del
    que leer, y output_fp especifica el flujo en el que escribir. Solo
    si ambos se refieren a un terminal, se habilitará la entrada interactiva del terminal. De lo contrario, gl_get_line() simplemente llamará a fgets() para
    leer la entrada de comandos. Si ambos flujos se refieren a un terminal, entonces deben
    referirse al mismo terminal, y el tipo de este terminal debe especificarse
    a través del term argumento. El valor del term argumento se
    busca en la base de datos de información de terminales (terminfo o termcap), con
    el fin de determinar qué secuencias de control especiales se necesitan para controlar
    varios aspectos del terminal. new_GetLine() por ejemplo, pasa
    el valor de retorno de getenv("TERM") en este argumento. Tenga en
    cuenta que si uno o ambos de input_fp y output_fp no se refieren a un
    terminal, es legal pasar NULL en lugar de un tipo de
  terminal.


Tenga en cuenta que si desea pasar descriptores de archivo a
    gl_change_terminal(), puede hacerlo creando envoltorios de flujos stdio
    usando la función POSIX fdopen() .






MANEJO DE EVENTOS EXTERNOS


Por defecto, gl_get_line() no retorna hasta que el usuario ha ingresado una
    línea de entrada completa, o ocurre un error. En
    programas que necesitan vigilar la E/S de fuentes distintas al terminal,
    hay dos opciones.


  1. Use las funciones descritas en la página del manual
     gl_io_mode(3) para cambiar
     gl_get_line() al modo de servidor no bloqueante. En este modo,
     gl_get_line() se convierte en una función de edición de líneas
     incremental no bloqueante que puede ser llamada de forma segura desde
     un bucle de eventos externo. Aunque este es un método muy
     versátil, implica asumir algunas
     responsabilidades que normalmente se realizan detrás de escena por gl_get_line().
  2. Mientras gl_get_line() está esperando la entrada del
     teclado del usuario, puede pedirle que también vigile
     la actividad en descriptores de archivo arbitrarios, como
     sockets de red, tuberías, etc., y que llame a funciones
     de su elección cuando se detecte actividad. Esto funciona en
     cualquier sistema que tenga la llamada al sistema select() ,
     que es la mayoría, si no todos, los sabores de unix.


Registrar un descriptor de archivo para ser vigilado por
    gl_get_line() implica llamar a la gl_watch_fd() función.


  int gl_watch_fd(GetLine *gl, int fd, GlFdEvent event,
                  GlFdEventFn *callback, void *data);


Si esto retorna un valor distinto de cero, significa que o sus argumentos
    son inválidos, o que esta funcionalidad no está soportada en el sistema anfitrión.


El fd argumento es el descriptor de archivo a vigilar. El
    event argumento especifica qué tipo de actividad es de interés, elegida
    de los siguientes valores enumerados:


  GLFD_READ   -  Vigilar la llegada de datos para leer.
  GLFD_WRITE  -  Vigilar la capacidad de escribir en el descriptor
                 de archivo sin bloquear.
  GLFD_URGENT -  Vigilar la llegada de datos urgentes
                 fuera de banda en el descriptor de archivo.


El callback argumento es la función a llamar cuando se
    detecta la actividad seleccionada. Debe definirse con el siguiente macro,
    que está definido en libtecla.h.


  #define GL_FD_EVENT_FN(fn) GlFdStatus (fn)(GetLine *gl, \
                                      void *data, int fd, \
                                      GlFdEvent event)


El data argumento de la gl_watch_fd() función se
    pasa a la función de retorno de llamada para su propio uso, y puede apuntar a lo que
    desee, incluyendo NULL. El descriptor de archivo y el argumento del evento
    también se pasan a la función de retorno de llamada, y esto potencialmente permite
    que la misma función de retorno de llamada se registre para más de un tipo de evento
    y/o más de un descriptor de archivo. El valor de retorno de la función
    de retorno de llamada debe ser uno de los siguientes valores.


  GLFD_ABORT    -  Decirle a gl_get_line() que aborte. Cuando esto
                   sucede, gl_get_line() retorna
                   NULL, y una llamada posterior a
                   gl_return_status() retornará
                   GLR_FDABORT. Tenga en cuenta que si la
                   aplicación necesita que errno siempre tenga un valor significativo cuando
                   gl_get_line() retorna NULL,
                   la función de retorno de llamada debe establecer
                   errno apropiadamente.
  GLFD_REFRESH  -  Redibujar la línea de entrada y luego continuar
                   esperando entrada. Retorne esto si
                   su retorno de llamada escribió en el terminal.
  GLFD_CONTINUE -  Continuar esperando entrada, sin
                   redibujar la línea.


Tenga en cuenta que antes de llamar al retorno de llamada, gl_get_line() bloquea
    la mayoría de las señales, y deja sus propios manejadores de señal instalados, así que si necesita
    capturar una señal en particular, necesitará tanto instalar temporalmente su
    propio manejador de señal, como desbloquear la señal. Asegúrese de volver a bloquear la señal
    (si estaba originalmente bloqueada) y reinstalar el manejador de señal original, si
    lo hay, antes de retornar.


Si la función de retorno de llamada necesita leer o escribir en el terminal,
    idealmente debería llamar primero a gl_normal_io(gl) para suspender temporalmente
    la edición de líneas. Esto restaurará el terminal a modo canónico, de E/S bloqueante,
    y moverá el cursor al inicio de una nueva línea del terminal. Más tarde, cuando
    el retorno de llamada retorne, gl_get_line() notará que
    gl_normal_io() fue llamada, volverá a mostrar la línea de entrada y reanudará
    la edición. Tenga en cuenta que en este caso los valores de retorno, GLFD_REFRESH y
    GLFD_CONTINUE son equivalentes.


Para soportar casos donde la función de retorno de llamada llama a una función de terceros
    que ocasionalmente e impredeciblemente escribe en el terminal, la
    conversión automática de "0 a "0 se reactiva
    antes de que se llame a la función de retorno de llamada. Si el retorno de llamada sabe que la
    función de terceros escribió en el terminal, entonces debería retornar el
    GLFD_REFRESH valor de retorno, para decirle a gl_get_line() que vuelva a mostrar
    la línea de entrada.


Para eliminar una función de retorno de llamada que registró previamente para un
    descriptor de archivo y evento dados, simplemente llame a gl_watch_fd() con
    el mismo descriptor de archivo y los argumentos event , pero con un callback
    argumento de 0. El data argumento se ignora en este caso.

    gl_normal_io(), redibujará la línea de entrada y reanudará la

MANEJO POR DEFECTO DE SEÑALES


Por defecto, la función gl_get_line() intercepta un
    número de señales. Esto es particularmente importante para las señales que
    por defecto terminarían el proceso, ya que la terminal necesita ser
    restaurada a un estado utilizable antes de que esto suceda. En esta
    sección, se describen las señales que son capturadas por defecto y cómo
    gl_get_line() responde a ellas. Cambiar estos valores por defecto es
    el tema de la siguiente sección.


Cuando se capturan el siguiente subconjunto de señales,
    gl_get_line() primero restaura la configuración de la terminal y el
    manejo de señales a cómo estaban antes de que se llamara a
    gl_get_line(), reenvía la señal, para permitir que los manejadores
    de señales de la aplicación llamante la manejen, y luego, si el proceso
    aún existe, gl_get_line() devuelve NULL y establece
    errno como se especifica a continuación.


 SIGINT  -  Esta señal se genera tanto por la tecla de
            interrupción del teclado (generalmente ^C),
            como por la tecla de interrupción del teclado.
            errno=EINTR
 SIGHUP  -  Esta señal se genera cuando sale la terminal
            de control.
            errno=ENOTTY
 SIGPIPE -  Esta señal se genera cuando un programa intenta
            escribir en una tubería cuya extremo remoto no está
            siendo leído por ningún proceso. Esto puede ocurrir,
            por ejemplo, si ha llamado a
            gl_change_terminal() para redirigir la salida
            a una tubería oculta bajo una terminal pseudo.
            errno=EPIPE
 SIGQUIT -  Esta señal se genera por la tecla de
            desconexión del teclado (generalmente ^\).
            errno=EINTR
 SIGABRT -  Esta señal se genera por la función estándar C,
            abort(). Por defecto, termina el proceso y genera
            un volcado de núcleo.
            errno=EINTR
 SIGTERM -  Esta es la señal por defecto que el comando
            UN*X kill envía a los procesos.
            errno=EINTR


Tenga en cuenta que en el caso de todas las señales anteriores,
    POSIX exige que por defecto el proceso se termine, con la adición de un
    volcado de núcleo en el caso de la señal SIGQUIT. En otras
    palabras, si la aplicación que llama no anula el manejador por defecto
    proporcionando su propio manejador de señales, la recepción de la señal
    correspondiente terminará la aplicación antes de que gl_get_line()
    regrese.


Si gl_get_line() se aborta con errno establecido en EINTR, puede
    averiguar qué señal provocó la aborto, llamando a la siguiente función.


  int gl_last_signal(const GetLine *gl);


Esto devuelve el código numérico (por ejemplo, SIGINT) de la
    última señal recibida durante la llamada más reciente a
    gl_get_line(), o -1 si no se recibieron señales.


En sistemas que lo soportan, cuando se recibe una señal SIGWINCH
    (cambio de ventana), gl_get_line() consulta la terminal para
    averiguar su nuevo tamaño, redibuja la línea de entrada actual para
    acomodar el nuevo tamaño, y luego regresa a esperar la entrada del teclado
    del usuario. A diferencia de otras señales, esta señal no se reenvía a la
    aplicación.


Finalmente, las siguientes señales hacen que gl_get_line()
    restaure primero la configuración de la terminal y las señales a la que
    prevalecía antes de que se llamara a gl_get_line(), luego reenvíe
    la señal a la aplicación. Si el proceso aún existe después de que se haya
    entregado la señal, entonces gl_get_line() restablece sus propios
    manejadores de señales, cambia la terminal de nuevo a modo crudo, redibuja
    la línea de entrada y vuelve a esperar la entrada de la terminal del
    usuario.


 SIGCONT    -  Esta señal se genera cuando se reanuda un
               proceso suspendido.
 SIGPOLL    -  En sistemas SVR4, esta señal notifica al
               proceso de un evento de E/S asíncrono. Tenga
               en cuenta que bajo 4.3+BSD, SIGIO y SIGPOLL
               son lo mismo. En otros sistemas, SIGIO es
               ignorado por defecto, por lo que
               gl_get_line() no lo captura por defecto.
 SIGPWR     -  Esta señal se genera cuando ocurre un fallo de
               alimentación (presumiblemente cuando el sistema
               está en un SAI).
 SIGALRM    -  Esta señal se genera cuando expira un temporizador.
 SIGUSR1    -  Una señal específica de la aplicación.
 SIGUSR2    -  Otra señal específica de la aplicación.
 SIGVTALRM  -  Esta señal se genera cuando expira un temporizador
               virtual (ver man setitimer(2)).
 SIGXCPU    -  Esta señal se genera cuando un proceso excede
               su límite de tiempo de CPU suave.
 SIGXFSZ    -  Esta señal se genera cuando un proceso excede
               su límite de tamaño de archivo suave.
 SIGTSTP    -  Esta señal se genera por la tecla de suspensión
               de la terminal, que suele ser ^Z, o la tecla de
               suspensión retardada de la terminal, que suele
               ser ^Y.
 SIGTTIN    -  Esta señal se genera si el programa intenta leer
               desde la terminal mientras el programa se
               ejecuta en segundo plano.
 SIGTTOU    -  Esta señal se genera si el programa intenta
               escribir en la terminal mientras el programa se
               ejecuta en segundo plano.


Obviamente, no todas las señales anteriores son compatibles en todos
    los sistemas, por lo que el código para soportarlas se compila condicionalmente
    en la biblioteca tecla.


Tenga en cuenta que si SIGKILL o SIGPOLL, que por
    definición no pueden ser capturados, o cualquiera de las señales de excepción
    generadas por hardware, como SIGSEGV, SIGBUS y SIGFPE,
    se reciben y no se manejan mientras gl_get_line() tiene la terminal
    en modo crudo, el programa terminará sin que la terminal haya sido
    restaurada a un estado utilizable. En la práctica, los shells de control de
    trabajo suelen restablecer la configuración de la terminal cuando un proceso
    cede la terminal de control, por lo que esto solo es un problema con shells
    antiguos.

GL_TRAP_SIGNAL


You can use the gl_trap_signal() function to set up
    signal handlers to be invoked by gl_get_line(). If the signal handler
    is invoked, then gl_get_line() will be interrupted, and the
    application's signal handler will be invoked. When the application's signal
    handler returns, then gl_get_line() will resume its operation.


  int gl_trap_signal(GetLine *gl, int signo, unsigned flags,
                     GlAfterSignal after, int errno_value);


The signo argument is the number of the signal that you
    wish to have trapped. The flags argument is a set of flags which
    determine the environment in which the application's signal handler is
    invoked, the after argument tells gl_get_line() what to do
    after the application's signal handler returns, and errno_value tells
    gl_get_line() what to set errno to if told to abort.


The flags argument is a bitwise OR of zero or more of the
    following enumerators:


  GLS_RESTORE_SIG  -  Restore the caller's signal
                      environment while handling the
                      signal.
  GLS_RESTORE_TTY  -  Restore the caller's terminal settings
                      while handling the signal.
  GLS_RESTORE_LINE -  Move the cursor to the start of the
                      line following the input line before
                      invoking the application's signal
                      handler.
  GLS_REDRAW_LINE  -  Redraw the input line when the
                      application's signal handler returns.
  GLS_UNBLOCK_SIG  -  Normally, if the calling program has
                      a signal blocked (man sigprocmask),
                      gl_get_line() does not trap that
                      signal. This flag tells gl_get_line()
                      to trap the signal and unblock it for
                      the duration of the call to
                      gl_get_line().
  GLS_DONT_FORWARD -  If this flag is included, the signal
                      will not be forwarded to the signal
                      handler of the calling program.


Two commonly useful flag combinations are also enumerated as
    follows:


  GLS_RESTORE_ENV   = GLS_RESTORE_SIG | GLS_RESTORE_TTY |
                      GLS_REDRAW_LINE
  GLS_SUSPEND_INPUT = GLS_RESTORE_ENV | GLS_RESTORE_LINE


If your signal handler, or the default system signal handler for
    this signal, if you haven't overridden it, never either writes to the
    terminal, nor suspends or terminates the calling program, then you can
    safely set the flags argument to 0.


If your signal handler always writes to the terminal, reads from
    it, or suspends or terminates the program, you should specify the
    flags argument as GL_SUSPEND_INPUT, so that:


1. The cursor doesn't get left in the middle of the input
   line.
2. So that the user can type in input and have it echoed.
3. So that you don't need to end each output line with
   \r\n, instead of just \n.


The GL_RESTORE_ENV combination is the same as
    GL_SUSPEND_INPUT, except that it doesn't move the cursor, and if your
    signal handler doesn't read or write anything to the terminal, the user
    won't see any visible indication that a signal was caught. This can be
    useful if you have a signal handler that only occasionally writes to the
    terminal, where using GL_SUSPEND_LINE would cause the input line to
    be unnecessarily duplicated when nothing had been written to the terminal.
    Such a signal handler, when it does write to the terminal, should be sure to
    start a new line at the start of its first write, by writing a new line
    before returning. If the signal arrives while the user is entering a line
    that only occupies a signal terminal line, or if the cursor is on the last
    terminal line of a longer input line, this will have the same effect as
    GL_SUSPEND_INPUT. Otherwise it will start writing on a line that
    already contains part of the displayed input line. This doesn't do any harm,
    but it looks a bit ugly, which is why the GL_SUSPEND_INPUT
    combination is better if you know that you are always going to be writting
    to the terminal.


The after argument, which determines what
    gl_get_line() does after the application's signal handler returns (if
    it returns), can take any one of the following values:


  GLS_RETURN   - Return the completed input line, just as
                 though the user had pressed the return
                 key.
  GLS_ABORT    - Cause gl_get_line() to abort. When
                 this happens, gl_get_line() returns
                 NULL, and a following call to
                 gl_return_status() will return
                 GLR_SIGNAL. Note that if the
                 application needs errno always to
                 have a meaningful value when
                 gl_get_line() returns NULL,
                 the callback function should set
                 errno appropriately.
  GLS_CONTINUE - Resume command line editing. 


The errno_value argument is intended to be combined with
    the GLS_ABORT option, telling gl_get_line() what to set the
    standard errno variable to before returning NULL to the
    calling program. It can also, however, be used with the GL_RETURN
    option, in case you wish to have a way to distinguish between an input line
    that was entered using the return key, and one that was entered by the
    receipt of a signal.






RELIABLE SIGNAL HANDLING


Signal handling is suprisingly hard to do reliably without race
    conditions. In gl_get_line() a lot of care has been taken to allow
    applications to perform reliable signal handling around
    gl_get_line(). This section explains how to make use of this.


As an example of the problems that can arise if the application
    isn't written correctly, imagine that one's application has a SIGINT signal
    handler that sets a global flag. Now suppose that the application tests this
    flag just before invoking gl_get_line(). If a SIGINT signal happens
    to be received in the small window of time between the statement that tests
    the value of this flag, and the statement that calls gl_get_line(),
    then gl_get_line() will not see the signal, and will not be
    interrupted. As a result, the application won't be able to respond to the
    signal until the user gets around to finishing entering the input line and
    gl_get_line() returns. Depending on the application, this might or
    might not be a disaster, but at the very least it would puzzle the user.


The way to avoid such problems is to do the following.


1. If needed, use the gl_trap_signal() function to
    configure gl_get_line() to abort when important
    signals are caught.


2. Configure gl_get_line() such that if any of the
    signals that it catches are blocked when
    gl_get_line() is called, they will be unblocked
    automatically during times when gl_get_line() is
    waiting for I/O. This can be done either
    on a per signal basis, by calling the
    gl_trap_signal() function, and specifying the
    GLS_UNBLOCK attribute of the signal, or globally by
    calling the gl_catch_blocked() function.


     void gl_catch_blocked(GetLine *gl);


This function simply adds the GLS_UNBLOCK attribute
    to all of the signals that it is currently configured to
    trap.


3. Just before calling gl_get_line(), block delivery
    of all of the signals that gl_get_line() is
    configured to trap. This can be done using the POSIX
    sigprocmask() function in conjunction with the
    gl_list_signals() function.


      int gl_list_signals(GetLine *gl, sigset_t *set);


This function returns the set of signals that it is
    currently configured to catch in the set argument,
    which is in the form required by sigprocmask().


4. In the example, one would now test the global flag that
    the signal handler sets, knowing that there is now no
    danger of this flag being set again until
    gl_get_line() unblocks its signals while performing
    I/O.


5. Eventually gl_get_line() returns, either because
    a signal was caught, an error occurred, or the user
    finished entering their input line.


6. Now one would check the global signal flag again, and if
    it is set, respond to it, and zero the flag.


7. Use sigprocmask() to unblock the signals that were
    blocked in step 3.


The same technique can be used around certain POSIX signal-aware
    functions, such as sigsetjmp() and sigsuspend(), and in
    particular, the former of these two functions can be used in conjunction
    with siglongjmp() to implement race-condition free signal handling
    around other long-running system calls. The way to do this, is explained
    next, by showing how gl_get_line() manages to reliably trap signals
    around calls to functions like read() and select() without
    race conditions.


The first thing that gl_get_line() does, whenever it is
    called, is to use the POSIX sigprocmask() function to block the
    delivery of all of the signals that it is currently configured to catch.
    This is redundant if the application has already blocked them, but it does
    no harm. It undoes this step just before returning.


Whenever gl_get_line() needs to call read() or
    select() to wait for input from the user, it first calls the POSIX
    sigsetjmp() function, being sure to specify a non-zero value for its
    savesigs argument. The reason for the latter argument will become
    clear shortly.


If sigsetjmp() returns zero, gl_get_line() then does
    the following.


a. It uses the POSIX sigaction() function to register
   a temporary signal handler to all of the signals that it
   is configured to catch. This signal handler does two
   things.
   1. It records the number of the signal that was received
      in a file-scope variable.
   2. It then calls the POSIX siglongjmp()
      function using the buffer that was passed to
      sigsetjmp() for its first argument, and
      a non-zero value for its second argument.
   When this signal handler is registered, the sa_mask
   member of the struct sigaction act argument of the
   call to sigaction() is configured to contain all of
   the signals that gl_get_line() is catching. This
   ensures that only one signal will be caught at once by
   our signal handler, which in turn ensures that multiple
   instances of our signal handler don't tread on each
   other's toes.
b. Now that the signal handler has been set up,
   gl_get_line() unblocks all of the signals that it
   is configured to catch.
c. It then calls the read() or select() system
   calls to wait for keyboard input.
d. If this system call returns (ie. no signal is received),
   gl_get_line() blocks delivery of the signals of
   interest again.
e. It then reinstates the signal handlers that were
   displaced by the one that was just installed.

    sigsetjmp() retorne, siempre que el argumento savesigs de
    sigsetjmp() fuera distinto de cero, como se especificó anteriormente, la máscara de señales del proceso se restaura a cómo estaba cuando sigsetjmp() fue llamado. Esta es la diferencia importante entre sigsetjmp() y el antiguo y problemático

   terminal quedaría en un estado inutilizable.


2. Luego, reinstala los manejadores de señales de la aplicación.


3. Luego, usa la función de la biblioteca estándar de C raise()
  

   para reenviar a la aplicación la señal que
  

   fue capturada.


3. A continuación, desbloquea la entrega de la señal que acabamos de
  

   enviar. Esto resulta en que la señal que acabó de ser enviada
  

   vía raise(), sea capturada por el manejador de señales
  

   original de la aplicación, que ahora puede manejarla como
  

   considere conveniente.


4. Si el manejador de señales retorna (es decir, no termina
  

   el proceso), gl_get_line() bloquea la entrega de la
  

   señal anterior nuevamente.


5. Luego deshace cualquier acción realizada en el primero de los
  

   pasos anteriores, y vuelve a mostrar la línea, si la configuración de la señal
  

   lo requiere.


6. gl_get_line() luego o bien reanuda el intento de
  

   leer un carácter, o se aborta, dependiendo de la
  

   configuración de la señal que fue capturada.


Lo que los pasos anteriores hacen en esencia es tomar señales
    entregadas de forma asíncrona y manejarlas de forma síncrona, una a una, en un punto
    del código donde gl_get_line() tiene control total sobre su
    entorno.






EL   TAMAÑO DEL TERMINAL


En la mayoría de los sistemas, la combinación del TIOCGWINSZ ioctl y
    la señal SIGWINCH se utiliza para mantener una idea precisa del
    tamaño del terminal. El tamaño del terminal se consulta nuevamente cada vez que
    gl_get_line() es llamado y siempre que se recibe una señal SIGWINCH .


En los pocos sistemas donde este mecanismo no está disponible, al
    inicio new_GetLine() primero busca las variables de entorno LINES y
    COLUMNS . Si no se encuentran, o contienen valores inutilizables, entonces si está disponible una base de datos de información del terminal como terminfo o termcap, se busca el tamaño por defecto del terminal en esta base de datos. Si esto también falla en proporcionar el tamaño del terminal, se usa un tamaño por defecto de 80 columnas por 24 líneas.


Incluso en sistemas que sí soportan ioctl(TIOCGWINSZ), si el terminal está en el otro extremo de una línea serie, el controlador del terminal generalmente no tiene forma de detectar cuándo ocurre un redimensionamiento ni de consultar cuál es el tamaño actual. En tales casos, no se envía ningún SIGWINCH al proceso, y las dimensiones devueltas por ioctl(TIOCGWINSZ) no son correctas. La única manera de manejar tales instancias es proporcionar una forma para que el usuario introduzca un comando que le diga al sistema remoto cuál es el nuevo tamaño. Este comando entonces llamaría a la función gl_set_term_size() para informar a gl_get_line()
    sobre el cambio de tamaño.


  int gl_set_term_size(GetLine *gl, int ncolumn, int nline);


Los argumentos ncolumn y nline se utilizan para especificar
    las nuevas dimensiones del terminal, y no deben ser menores que 1. En sistemas que sí soportan ioctl(TIOCGWINSZ), esta función primero llama a
    ioctl(TIOCSWINSZ) para informar al controlador del terminal sobre el cambio en
    el tamaño. En el modo de E/S de servidor no bloqueante, si actualmente se está introduciendo una línea, la línea de entrada se redibuja para acomodar el tamaño cambiado. Finalmente, los nuevos valores se registran en gl para uso futuro por
  gl_get_line().


La función gl_terminal_size() le permite consultar el
    tamaño actual del terminal, e instalar un tamaño de reserva alternativo para los casos en que el tamaño no esté disponible. Tenga en cuenta que el tamaño del terminal no estará disponible si se lee de una tubería o un archivo, por lo que los valores por defecto pueden ser importantes incluso en sistemas que sí soportan formas de averiguar el tamaño del terminal.


  typedef struct {
    int nline;        /* El terminal tiene nline líneas */
    int ncolumn;      /* El terminal tiene ncolumn columnas */
  } GlTerminalSize;
  GlTerminalSize gl_terminal_size(GetLine *gl,
                                  int def_ncolumn,
                                  int def_nline);


Esta función primero actualiza las dimensiones de reserva del terminal de gl_get_line(), luego registra sus hallazgos en el valor de retorno.


Los argumentos def_ncolumn y def_nline especifican el número por defecto de columnas y líneas del terminal a usar si el tamaño del terminal no se puede determinar vía ioctl(TIOCGWINSZ) o variables de entorno.






OCULTANDO   LO QUE ESCRIBES


Al introducir información sensible, como contraseñas, es mejor no tener el texto que está introduciendo reflejado en el terminal. Además, dicho texto no debería ser registrado en la lista de historial, ya que alguien que encuentre su terminal desatendida podría entonces recuperarlo, o alguien que esté husmeando en sus directorios podría verlo en su archivo de historial. Teniendo esto en cuenta, la función gl_echo_mode() le permite activar y desactivar la visualización y el archivo de cualquier texto que se introduzca posteriormente en las llamadas a gl_get_line().


  int gl_echo_mode(GetLine *gl, int enable);


El argumento enable especifica si el texto introducido debe ser visible o no. Si es 0, entonces las líneas introducidas posteriormente no serán visibles en el terminal, y no serán registradas en la lista de historial. Si es 1, entonces las líneas de entrada posteriores se mostrarán a medida que se introducen, y siempre que el historial no se haya desactivado mediante una llamada a gl_toggle_history(), también serán archivadas en la lista de historial. Finalmente, si el argumento enable es -1, entonces el modo de eco se deja sin cambios, lo que le permite consultar de forma no destructiva la configuración actual a través del valor de retorno. En todos los casos, el valor de retorno de la función es 0 si el eco estaba desactivado antes de que se llamara a la función, y 1 si estaba activado.


Cuando el eco está desactivado, tenga en cuenta que aunque la finalización con tabulador completará su prefijo de forma invisible lo más lejos posible, las finalizaciones ambiguas no se mostrarán.






CONSULTAS   DE UN SOLO CARÁCTER


Usar gl_get_line() para consultar al usuario para una respuesta de un solo carácter, es inconveniente para el usuario, ya que debe presionar la tecla intro o retorno antes de que el carácter que escribió sea devuelto al programa. Por lo tanto, la función gl_query_char() ha sido proporcionada para consultas de un solo carácter como esta.


  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar);


Esta función muestra el prompt especificado al comienzo de una nueva línea, y espera a que el usuario escriba un carácter. Cuando el usuario escribe un carácter, gl_query_char() lo muestra a la derecha del prompt, inicia una nueva línea, y luego devuelve el carácter al programa que lo llamó. El valor de retorno de la función es el carácter que fue escrito. Si la lectura tuvo que ser abortada por alguna razón, se devuelve EOF en su lugar. En este último caso, la aplicación puede llamar a la función previamente documentada
    gl_return_status(), para averiguar qué salió mal. Esto podría haber sido, por ejemplo, la recepción de una señal, o el temporizador opcional de inactividad activándose.


Si el usuario simplemente presiona intro, se sustituye el valor del argumento defchar
    . Esto significa que cuando el usuario presiona ya sea nueva línea o retorno, el carácter especificado en defchar, se muestra después del prompt, como si el usuario lo hubiera escrito, así como ser devuelto a la aplicación que lo llamó. Si tal reemplazo no es importante, simplemente pase
    '0 como el valor de defchar.


Si el carácter introducido es un carácter no imprimible, se muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y los caracteres más allá de 127 se muestran en octal, precedidos por una barra invertida.


Al igual que con gl_get_line(), el eco del carácter introducido puede
    ser desactivado usando la función gl_echo_mode() .


Si el proceso que llama es suspendido mientras espera a que el usuario escriba su respuesta, el cursor se mueve a la línea siguiente a la línea del prompt, luego cuando el proceso se reanuda, el prompt se vuelve a mostrar, y
    gl_query_char() reanuda la espera a que el usuario escriba un carácter.


Tenga en cuenta que en el modo de servidor no bloqueante, (ver gl_io_mode(3)), si una línea de entrada incompleta está en proceso de ser leída cuando
    gl_query_char() es llamado, la línea de entrada parcial se descarta, y se borra del terminal, antes de que se muestre el nuevo prompt. La siguiente llamada a gl_get_line() comenzará por lo tanto a editar una nueva línea.






LEYENDO   CARACTERES CRUDOS


Mientras que la función gl_query_char() pide visiblemente al usuario un carácter, y muestra lo que escribió, la función
    gl_read_char() lee un carácter del usuario, sin escribir nada en el terminal, ni perturbar ninguna línea de entrada incompleta. Esto significa que puede ser llamada no solo entre llamadas a gl_get_line(), sino también desde funciones de retorno que la aplicación haya registrado para ser llamadas por gl_get_line().


  int gl_read_char(GetLine *gl);


En caso de éxito, el valor de retorno de gl_read_char() es el carácter que fue leído. En caso de fallo, se devuelve EOF , y se puede llamar a la función
    gl_return_status() para averiguar qué salió mal. Las posibilidades incluyen el temporizador opcional de inactividad activándose, la recepción de una señal que está configurada para abortar gl_get_line(), o el bloqueo de E/S del terminal, cuando se está en el modo de E/S de servidor no bloqueante.


Tenga en cuenta que ciertas teclas del teclado, como las teclas de función y las teclas de cursor, usualmente generan al menos 3 caracteres cada una, por lo que una sola llamada a gl_read_char() no será suficiente para identificar dichas pulsaciones de teclas.






BORRANDO   LA TERMINAL


El programa que llama puede borrar la terminal invocando
    gl_erase_terminal(). En el modo de E/S de servidor no bloqueante, esta función
    también se encarga de que la línea de entrada actual se redibuje desde cero cuando
    gl_get_line() se llame a continuación.


  int gl_erase_terminal(GetLine *gl);






MOSTRANDO   TEXTO DINÁMICAMENTE


Entre las llamadas a gl_get_line(), la
    gl_display_text() función proporciona una manera conveniente de mostrar
    párrafos de texto, alineados a la izquierda y divididos en una o más líneas de
    la terminal de acuerdo con las restricciones del ancho actual de la terminal. Ejemplos
    del uso de esta función se pueden encontrar en los programas de demostración, donde se
    utiliza para mostrar introducciones. En esos ejemplos también se ilustra el uso avanzado de
    prefijos opcionales, sufijos y líneas llenas para dibujar un cuadro alrededor del texto.


  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string);


Si gl no está actualmente conectado a una terminal, por ejemplo
    si la salida de un programa que usa gl_get_line() se está canalizando a
    otro programa o se está redirigiendo a un archivo, entonces el valor del
    def_width parámetro se utiliza como el ancho de la terminal.


El indentation argumento especifica el número de caracteres
    a usar para sangrar cada línea de salida. El fill_char argumento especifica
    el carácter que se usará para realizar esta sangría.


El prefix argumento puede ser NULL, o ser una
    cadena para colocar al comienzo de cada nueva línea (después de cualquier sangría).
    De manera similar, el suffix argumento puede ser NULL, o ser una
    cadena para colocar al final de cada línea. El sufijo se coloca al ras contra el
    borde derecho de la terminal, y cualquier espacio entre su primer carácter
    y la última palabra en esa línea se rellena con el carácter especificado a través del fill_char argumento. Normalmente el carácter de relleno es un espacio.


El start argumento le dice a gl_display_text() cuántos
    caracteres ya se han escrito en la línea de terminal actual, y por lo tanto
    le dice el índice de columna inicial del cursor. Dado que el valor de retorno de
    gl_display_text() es el índice de columna final del cursor, al
    pasar el valor de retorno de una llamada al start argumento de la
    siguiente llamada, se puede componer un párrafo que está dividido entre más de una
    cadena llamando a gl_display_text() para cada porción sucesiva del
    párrafo. Tenga en cuenta que los caracteres de salto de línea literales son necesarios al final
    de cada párrafo para forzar que se inicie una nueva línea.


En caso de error, gl_display_text() devuelve -1.






INSTALACIONES DE   FUNCIONES DE RETROLLAMADA


A menos que se indique lo contrario, las funciones de retrollamada, como las
    retrollamadas de finalización con tabulación y las retrollamadas de eventos, no deben llamar a ninguna función en
    este módulo. Las siguientes funciones, sin embargo, están diseñadas específicamente para
    ser usadas por funciones de retrollamada.


Llamar a la gl_replace_prompt() función desde una retrollamada
    le dice a gl_get_line() que muestre un mensaje de invitación diferente cuando la retrollamada
    regrese. Excepto en el modo de servidor no bloqueante, no tiene efecto si se usa
    entre llamadas a gl_get_line(). En el modo de servidor no bloqueante (vea la
    gl_io_mode(3) página del manual, cuando se usa entre dos llamadas a
    gl_get_line() que están operando en la misma línea de entrada, la línea de
    entrada actual se volverá a dibujar con el nuevo mensaje de invitación en la siguiente llamada a
    gl_get_line().


  void gl_replace_prompt(GetLine *gl, const char *prompt);






JUEGOS DE CARACTERES   INTERNACIONALES


Desde la versión 1.4.0 de libtecla, gl_get_line() ha sido de 8 bits
    limpio. Esto significa que todos los caracteres de 8 bits que son imprimibles en el
    locale actual del usuario ahora se muestran literalmente y se incluyen en la línea de
    entrada devuelta. Asumiendo que el programa que llama contiene correctamente una llamada como la
    siguiente,


  setlocale(LC_CTYPE, "");


entonces el locale actual está determinado por el primero de las
    variables de entorno LC_CTYPE, LC_ALL, y LANG, que
    se encuentre que contiene un nombre de locale válido. Si ninguna de estas variables está
    definida, o el programa omite llamar a setlocale, entonces se usa el locale
    C por defecto, que es ASCII de 7 bits de EE. UU. En la mayoría de los
    plataformas tipo unix, puede obtener una lista de locales válidos escribiendo el comando:


  locale -a


en el símbolo del shell. Documentación adicional sobre cómo el usuario puede
    hacer uso de esto para ingresar caracteres internacionales se puede encontrar en la
    tecla(7) página del manual.






SEGURIDAD DE   HILOS


En un programa multi-hilo, debería usar la versión libtecla_r.a
    de la biblioteca. Esta usa versiones reentrantes de las funciones del sistema,
    donde están disponibles. Desafortunadamente ni terminfo ni termcap fueron diseñados para
    ser reentrantes, por lo que no puede usar de manera segura las funciones del módulo getline en
    múltiples hilos (puede usar los módulos separados de expansión de archivos y
    finalización de palabras en múltiples hilos, vea las páginas de manual correspondientes
    para más detalles). Sin embargo, debido al uso de funciones reentrantes de POSIX para
    buscar directorios de inicio, etc., es seguro usar este módulo desde un solo
    hilo de un programa multi-hilo, siempre que sus otros hilos no
    usen ninguna función de termcap o terminfo.
