DESCRIPCIÓ

N

La función gl_get_line() es parte de la biblioteca tecla (vea la página man libtecla(3)). Si el usuario está escribiendo en un terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de unix. Además de la edición simple de línea de comandos, soporta el recuerdo de líneas de comandos previamente introducidas, la completación con TAB de nombres de archivos, y la expansión en línea de comodines de nombres de archivos. La documentación de ambas las características de edición de línea de comandos a nivel de usuario y todas las opciones de configuración del usuario, puede encontrarse en la página man tecla(7). Lo siguiente muestra un ejemplo completo de cómo usar la función gl_get_line() para obtener entrada del

usuario: 
  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que el usuario escribió */
    GetLine *gl;   /* El objeto recurso de gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* del juego de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("Usted escribió: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
}

En el ejemplo, primero los recursos necesarios por la función gl_get_line() son creados llamando a new_GetLine(). Esto asigna la memoria usada en llamadas subsecuentes a la función gl_get_line(), incluyendo el búfer de historial para registrar líneas previamente introducidas. Entonces una o más líneas son leídas del usuario, hasta que ocurre un error, o el usuario escribe exit. Entonces finalmente los recursos que fueron asignados por new_GetLine(), son devueltos al sistema llamando a del_GetLine(). Note el uso del valor de retorno NULL de del_GetLine() para hacer gl NULL. Esta es una precaución de seguridad. Si el programa posteriormente intenta pasar gl a gl_get_line(), dicha función se quejará, y retornará un erro

r, en lugar de intentar usa
r el objeto recurso eliminado.

FUENTES ALTERNATIVAS DE

CONFIGURACIÓN

Como se mencionó anteriormente, de forma predeterminada los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. En algunas aplicaciones, sin embargo, este único medio de configuración es un problema. Esto es particularmente cierto en el software embebido, donde no hay un sistema de archivos del cual leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de asignaciones de teclas para emular una interfaz de teclado heredada. Para atender a tales casos, la siguiente función permite a la aplicación controlar de dónde se leen los datos de

configuración. 
  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file)
;

Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc de un usuario, se lean de cualquiera o ninguno de: una cadena, un archivo de configuración específico de la aplicación y/o un archivo de configuración específico del usuario. Si esta función se llama antes de la primera llamada a gl_get_line(), el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line() se deshabilita, por lo que toda la configuración debe lograrse usando las fuentes de configuración especificadas con esta

función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados entre sí en la cadena por caracteres de nueva línea incrustados. Si app_file != NULL entonces se interpreta como la ruta de archivo completa de un archivo de configuración específico de la aplicación. Si user_file != NULL entonces se interpreta como la ruta de archivo completa de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente

llamada, 
  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc")
;

el argumento app_string hace que la aplicación que llama inicie en el modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso de la campana de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración de todo el sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee los comandos de configuración específicos del usuario de un archivo .teclarc opcional en el directorio de inicio del usuario. Tenga en cuenta que los argumentos se listan en orden ascendente de prioridad, con el contenido de app_string siendo potencialmente sobreescrito por comandos en app_file, y los comandos en app_file siendo potencialmente sobreescritos por comandos en user_file

.

Puede llamar a esta función tantas veces como sea necesario, los resultados siendo acumulativos, pero tenga en cuenta que las copias de cualquier nombre de archivo especificado a través de aplos argumentos p_file y user_file se registran internamente para su uso posterior por parte de la función de enlace de teclas read-init-files, así que si planea llamar a esta función varias veces, asegúrese de que la última llamada especifique los nombres de archivo que desea volver a leer cuando el usuario solicite que se releerán los archivos de

configuración.

PERSONALIZADO

Si en su aplicación desea que la finalización con TAB complete otras cosas además de o en lugar de nombres de archivo, puede organizarlo registrando una función de retorno de finalización alternativa, mediante una llamada a la función gl_customize_co

mpletion(). 
  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn)
;

El argumento data proporciona una manera para que su aplicación pase información arbitraria y específica de la aplicación a la función de retorno. Esto se pasa a la función de retorno cada vez que se la llama. Podría, por ejemplo, apuntar a la tabla de símbolos de la que se deben buscar las posibles finalizaciones. El argumento match_fn especifica la función de retorno a llamar. El tipo de función CplMatchFn está definido en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y definir prototipos de funciones de retorno. La declaración y las responsabilidades de las funciones de retorno se describen en profundidad en la página del manual cpl_complete_word(3)

.

En resumen, la función de retorno es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario pulsó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar posibles finalizaciones de esta palabra y registrarlas una por una en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion(). Si la función de retorno desea proporcionar finalización de nombres de archivo además de sus propias finalizaciones específicas, tiene la opción de llamar ella misma a la función de retorno de finalización de nombres de archivo incorporada. Esto también está documentado en la página del manual cpl_complete_word(3)

.

Tenga en cuenta que si desea que gl_get_line() devuelva la línea de entrada actual cuando se haya realizado una finalización exitosa, puede organizarlo cuando llame a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de nueva línea. Si hace esto, la línea de entrada se actualizará para mostrar la finalización, junto con cualquier sufijo de continuación hasta el carácter de nueva línea, y luego gl_get_line() devolverá esta línea de

entrada.

Si, por alguna razón, su función de retorno necesita escribir algo en el terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto iniciará una nueva línea después de la línea de entrada que se está editando actualmente, restablecerá la E/S normal del terminal y le dirá a gl_get_line() que la línea de entrada necesitará

ser redibujada cuando la f
unción de retorno regrese.

AÑADIENDO ACCIONES DE

FINALIZACIÓN

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de finalización predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que diferentes tipos de finalización de palabras se puedan vincular a diferentes secuencias de teclas. Esto se logra mediante el uso de la función gl_completion_action()

. 
  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq)
;

Los argumentos data y match_fn se describen en la página del manual de cpl_complete_word, y especifican la función de retorno que debe invocarse para identificar posibles finalizaciones. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar cualquier finalización ambigua posible, o si debe simplemente mostrar la lista de posibles finalizaciones sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre con el que los archivos de configuración y las futuras invocaciones de esta función deben referirse a la acción. Este debe ser el nombre de una acción de finalización existente que se va a cambiar, o un nombre nuevo no utilizado para una nueva acción. Finalmente, el argumento keyseq especifica la secuencia de teclas predeterminada a la que vincular la acción. Si esto es NULL, no se vinculará ninguna nueva secuencia de teclas a la

ARCHIVOS DE HISTORIA


Para guardar el contenido del búfer de historial antes de salir de su aplicación, y posteriormente restaurarlos cuando la inicie de nuevo, se proporcionan las siguientes funciones.


 int gl_save_history(GetLine *gl, const char *filename,
                     const char *comment, int max_lines);
 int gl_load_history(GetLine *gl, const char *filename,
                     const char *comment);


El argumento filename especifica el nombre que se le dará al archivo de historial al guardar, o el nombre de un archivo de historial existente, al cargar. Esto puede contener expresiones de directorio de inicio y variables de entorno, como "~/.myapp_history" o "$HOME/.myapp_history".


Junto con cada línea del historial, se registra información adicional sobre ella, como cuándo fue ingresada por el usuario y cuál es su nivel de anidamiento, como un comentario que precede a la línea en el archivo de historial. Escribirlo como un comentario permite que el archivo de historial sirva también como archivo de comandos, en caso de que desee reproducir una sesión completa utilizándolo. Dado que los prefijos de comentario difieren en diferentes idiomas, el argumento comment se proporciona para especificar el prefijo de comentario. Por ejemplo, si su aplicación fuera un shell de Unix, como el shell de Bourne, especificaría "#" aquí. Cualquiera que sea el carácter de comentario que elija, debe especificar el mismo prefijo a gl_load_history() que utilizó cuando llamó a gl_save_history() para escribir el archivo de historial.


El argumento max_lines debe ser -1 para especificar que se guarden todas las líneas de la lista de historial, o un número positivo que especifique un límite superior de cuántas de las líneas más recientes deben guardarse.


Ambas funciones devuelven un valor distinto de cero en caso de error, después de escribir un mensaje de error en stderr. Tenga en cuenta que gl_load_history() no considera la inexistencia de un archivo como un error.






MÚLTIPLES LISTAS DE HISTORIAL


Si su aplicación utiliza un único objeto GetLine para ingresar muchos tipos diferentes de líneas de entrada, es posible que desee que gl_get_line() distinga los diferentes tipos de líneas en la lista de historial, y solo recupere las líneas que coincidan con el tipo de línea actual. Para admitir este requisito, gl_get_line() marca las líneas que se graban en la lista de historial con un identificador entero elegido por la aplicación. Inicialmente, este identificador se establece en 0 por new_GetLine(), pero puede cambiarse posteriormente llamando a gl_group_history().


  int gl_group_history(GetLine *gl, unsigned id);


El identificador entero id puede ser cualquier número elegido por la aplicación, pero tenga en cuenta que gl_save_history() y gl_load_history() conservan la asociación entre los identificadores y las líneas de entrada históricas entre invocaciones del programa, por lo que debe elegir identificadores fijos para los diferentes tipos de líneas de entrada utilizados por su aplicación.


Cada vez que gl_get_line() agrega una nueva línea de entrada a la lista de historial, se registra el identificador de historial actual con ella, y cuando se le pide que recupere una línea de entrada histórica, solo recupera las líneas que están marcadas con el identificador actual.






MOSTRAR HISTORIAL


La lista de historial se puede mostrar llamando a gl_show_history().


  int gl_show_history(GetLine *gl, FILE *fp,
                      const char *fmt,
                      int all_groups,
                      int max_lines);


Esto muestra el contenido actual de la lista de historial al flujo de salida stdio fp. Si el argumento max_lines es mayor o igual a cero, entonces no se mostrarán más de este número de las líneas más recientes. Si el argumento all_groups es distinto de cero, se mostrarán líneas de todos los grupos de historial. De lo contrario, solo se mostrarán las del grupo de historial actualmente seleccionado. El argumento de cadena de formato, fmt, determina cómo se muestra la línea.   %D  -  La fecha en la que la línea fue ingresada originalmente,
         con formato como 2001-11-20.
  %T  -  La hora del día en que se ingresó la línea,
         con formato como 23:59:59.
  %N  -  El número secuencial de entrada de la línea en
         el búfer de historial.
  %G  -  El número del grupo de historial al que
         pertenece la línea.
  %%  -  Un carácter % literal.
  %H  -  La línea de historial en sí misma.


Por lo tanto, una cadena de formato como "%D %T %H0 generaría algo como:


  2001-11-20 10:23:34  Hola mundo


Tenga en cuenta la inclusión de un carácter de nueva línea explícito en la cadena de formato.

ARCHIVADO MANUAL DE HISTORIAL


Por defecto, cada vez que el usuario ingresa una línea, esta se agrega automáticamente a la lista de historial, justo antes de que gl_get_line() devuelva la línea al llamador. Esto es conveniente para la mayoría de las aplicaciones, pero también hay aplicaciones que necesitan un control más detallado sobre lo que se agrega a la lista de historial. En tales casos, la adición automática de las líneas ingresadas a la lista de historial se puede desactivar llamando a la función gl_automatic_history().


  int gl_automatic_history(GetLine *gl, int enable);


Si se llama a esta función con su argumento enable establecido en 0, gl_get_line() no archivará automáticamente las líneas ingresadas posteriormente. El archivado automático se puede volver a habilitar más tarde, llamando a esta función nuevamente, con su argumento enable establecido en 1. Mientras el archivado automático del historial está deshabilitado, la aplicación que llama puede usar gl_append_history() para agregar líneas a la lista de historial según sea necesario.


  int gl_append_history(GetLine *gl, const char *line);


El argumento line especifica la línea que se agregará a la lista de historial. Debe ser una cadena normal terminada en ' '. Si esta cadena contiene algún carácter de nueva línea, la línea que se archive en la lista de historial terminará con el primero de ellos. De lo contrario, terminará con el terminador ' '. Si la línea es más larga que la longitud máxima de línea de entrada, que se especificó cuando se llamó a new_GetLine(), cuando la línea se recupere, se truncará a la longitud real de la línea de gl_get_line().


Si tiene éxito, gl_append_history() devuelve 0. De lo contrario, devuelve un valor distinto de cero y establece errno en uno de los siguientes valores.


   EINVAL  -  Uno de los argumentos pasados a
              gl_append_history() era NULL.
   ENOMEM  -  La línea especificada era más larga que el
              tamaño asignado del búfer de historial (como se
              especificó al llamar a new_GetLine()), por lo
              que no se pudo archivar.


Se puede obtener una descripción textual del error opcionalmente llamando a gl_error_message(). Tenga en cuenta que después de un error de este tipo, la lista de historial permanece en un estado válido para recibir nuevas líneas de historial, por lo que hay poco daño en simplemente ignorar el estado de retorno de gl_append_history().

MOSTRAR TEXTO DINÁMICAMENTE

Entre llamadas a gl_get_line(), la función gl_display_text() proporciona una forma conveniente de mostrar párrafos de texto, justificados a la izquierda y divididos en una o más líneas de terminal según las restricciones del ancho actual de la terminal. Ejemplos del uso de esta función se pueden encontrar en los programas de demostración, donde se utiliza para mostrar introducciones. En esos ejemplos también se ilustra el uso avanzado de prefijos, sufijos y líneas de relleno opcionales para dibujar un cuadro alrededor del texto.

  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string);

Si gl no está conectado actualmente a una terminal, por ejemplo, si la salida de un programa que usa gl_get_line() se está canalizando a otro programa o redirigiendo a un archivo, entonces el valor del parámetro def_width se usa como el ancho de la terminal.

El argumento indentation especifica el número de caracteres que se utilizarán para indentar cada línea de salida. El argumento fill_char especifica el carácter que se utilizará para realizar esta indentación.

El argumento prefix puede ser NULL, o una cadena que se colocará al principio de cada nueva línea (después de cualquier indentación). De manera similar, el argumento suffix puede ser NULL, o una cadena que se colocará al final de cada línea. El sufijo se coloca alineado con el borde derecho de la terminal, y cualquier espacio entre su primer carácter y la última palabra de esa línea se rellena con el carácter especificado a través del argumento fill_char. Normalmente, el carácter de relleno es un espacio.

El argumento start le dice a gl_display_text() cuántos caracteres ya se han escrito en la línea de terminal actual, y por lo tanto le dice el índice de columna de inicio del cursor. Dado que el valor de retorno de gl_display_text() es el índice de columna final del cursor, al pasar el valor de retorno de una llamada al argumento start de la siguiente llamada, un párrafo que se divide entre varias cadenas puede componerse llamando a gl_display_text() para cada porción sucesiva del párrafo. Tenga en cuenta que los caracteres de nueva línea literales son necesarios al final de cada párrafo para forzar el inicio de una nueva línea.

En caso de error, gl_display_text() devuelve -1.

INSTALACIONES DE FUNCIONES DE LLAMADA

A menos que se indique lo contrario, las funciones de llamada, como las devoluciones de llamada de finalización de tabulación y las devoluciones de llamada de eventos, no deben llamar a ninguna función de este módulo. Las siguientes funciones, sin embargo, están diseñadas específicamente para ser utilizadas por funciones de llamada.

Llamar a la función gl_replace_prompt() desde una llamada de retorno le dice a gl_get_line() que muestre un aviso diferente cuando la llamada de retorno regrese. Excepto en el modo de servidor no bloqueante, no tiene ningún efecto si se usa entre llamadas a gl_get_line(). En el modo de servidor no bloqueante (consulte la página del manual gl_io_mode(3), cuando se usa entre dos llamadas a gl_get_line() que operan en la misma línea de entrada, la línea de entrada actual se redibujará con el nuevo aviso en la siguiente llamada a gl_get_line().

  void gl_replace_prompt(GetLine *gl, const char *prompt);

JUEGOS DE CARACTERES INTERNACIONALES

Desde la versión 1.4.0 de libtecla, gl_get_line() es compatible con 8 bits. Esto significa que todos los caracteres de 8 bits que son imprimibles en la configuración regional actual del usuario ahora se muestran literalmente y se incluyen en la línea de entrada devuelta. Suponiendo que el programa que llama contiene correctamente una llamada como la siguiente,

  setlocale(LC_CTYPE, "");

entonces la configuración regional actual se determina por la primera de las variables de entorno LC_CTYPE, LC_ALL y LANG, que se encuentra que contiene un nombre de configuración regional válido. Si ninguna de estas variables está definida, o si el programa no logra llamar a setlocale, entonces se utiliza la configuración regional predeterminada de C, que es ASCII de 7 bits de EE. UU. En la mayoría de las plataformas tipo Unix, puede obtener una lista de configuraciones regionales válidas escribiendo el comando:

  locale -a

en el indicador del shell. Encontrará más documentación sobre cómo el usuario puede utilizar esto para introducir caracteres internacionales en la página del manual tecla(7).

SEGURIDAD EN HILOS

En un programa multihilo, debe usar la versión libtecla_r.a de la biblioteca. Esta utiliza versiones reentrantes de las funciones del sistema, donde están disponibles. Desafortunadamente, ni terminfo ni termcap fueron diseñados para ser reentrantes, por lo que no puede usar de forma segura las funciones del módulo getline en varios hilos (puede usar los módulos separados de expansión de archivos y finalización de palabras en varios hilos, consulte las páginas del manual correspondientes para obtener detalles). Sin embargo, debido al uso de funciones reentrantes POSIX para buscar directorios de inicio, etc., es seguro usar este módulo desde un solo hilo de un programa multihilo, siempre que sus otros hilos no utilicen ninguna función de termcap o terminfo.
