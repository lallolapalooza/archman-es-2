DESCRIPCIÓN

La función gl_get_line() forma parte de la biblioteca tecla (ver la página del manual libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le pide una línea de entrada, luego proporciona funciones de edición interactivas, similares a las del shell tcsh de Unix. Además de la edición simple de línea de comandos, soporta la recuperación de líneas de comandos introducidas previamente, completado con TAB de nombres de archivo y expansión de comodines de nombres de archivo en línea. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario, se puede encontrar en la página del manual tecla(7). Esta página del manual se centra en la documentación para programadores interesados en utilizar esta biblioteca en su aplicación.

UN EJEMPLO

Lo siguiente muestra un ejemplo completo de cómo usar la función gl_get_line() para obtener la entrada del usuario:

  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que el usuario escribió */
    GetLine *gl;   /* El objeto de recursos de gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* de conjunto de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("Escribiste: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
  }

En el ejemplo, primero se crean los recursos necesarios para la función gl_get_line() llamando a new_GetLine(). Esto asigna la memoria utilizada en llamadas posteriores a la función gl_get_line(), incluido el búfer de historial para almacenar líneas introducidas previamente. Luego se leen una o más líneas del usuario, hasta que ocurre un error o el usuario escribe exit. Luego, finalmente, los recursos que fueron asignados por new_GetLine() se devuelven al sistema llamando a del_GetLine(). Tenga en cuenta el uso del valor de retorno NULL de del_GetLine() para hacer que gl sea NULL. Esta es una medida de precaución. Si el programa intenta posteriormente pasar gl a gl_get_line(), dicha función se quejará y devolverá un error, en lugar de intentar utilizar el objeto de recursos eliminado.

LAS FUNCIONES UTILIZADAS EN EL EJEMPLO

Las descripciones de las funciones utilizadas en el ejemplo son las siguientes:

  GetLine *new_GetLine(size_t linelen, size_t histlen)

Esta función crea los recursos utilizados por la función gl_get_line() y devuelve un puntero opaco al objeto que los contiene. La longitud máxima de una línea de entrada se especifica a través del argumento linelen, y el número de bytes a asignar para almacenar líneas de historial se establece mediante el argumento histlen. Las líneas de historial se almacenan una detrás de otra en un único búfer de este tamaño. Tenga en cuenta que esto significa que el número de líneas de historial que se pueden almacenar en cualquier momento depende de las longitudes de las líneas individuales. Si desea establecer un límite superior en el número de líneas que se pueden almacenar, consulte la función gl_limit_history() descrita más adelante. Si no desea historial en absoluto, especifique histlen como cero, y no se asignará ningún búfer de historial.

En caso de error, se imprime un mensaje en stderr y se devuelve NULL.

  GetLine *del_GetLine(GetLine *gl)

Esta función elimina los recursos que fueron devueltos por una llamada anterior a new_GetLine(). Siempre devuelve NULL (es decir, un objeto eliminado). No hace nada si el argumento gl es NULL.

  char *gl_get_line(GetLine *gl, const char *prompt,
                   const char *start_line, int start_pos);

La función gl_get_line() se puede llamar cualquier número de veces para leer la entrada del usuario. El argumento gl debe haber sido devuelto previamente por una llamada a new_GetLine(). El argumento prompt debe ser una cadena normal terminada en NUL, que especifica el aviso que se presentará al usuario. Por defecto, los avisos se muestran literalmente, pero si se habilitan con la función gl_prompt_style() (ver más adelante), los avisos pueden contener directivas para hacer subrayados, cambiar a y desde fuentes en negrita, o activar y desactivar el resaltado.

Si desea especificar el contenido inicial de la línea, para que el usuario lo edite, pase la cadena deseada a través del argumento start_line. Luego puede especificar en qué carácter de esta línea se posiciona inicialmente el cursor

Si la función de retorno de llamada necesita leer o escribir en el terminal, idealmente debería primero llamar a gl_normal_io(gl) para suspender temporalmente la edición de línea. Esto restaurará el terminal a modo canónico, de E/S bloqueante, y moverá el cursor al comienzo de una nueva línea del terminal. Más tarde, cuando el retorno de llamada regrese, gl_get_line() notará que gl_normal_io() fue llamada, volverá a mostrar la línea de entrada y reanudará la edición. Nótese que en este caso los valores de retorno, GLFD_REFRESH y GLFD_CONTINUE son

equivalentes.

Para soportar casos donde la función de retorno de llamada llama a una función de terceros que ocasionalmente e impredeciblemente escribe en el terminal, la conversión automática de "0 a "0 se vuelve a habilitar antes de que se llame a la función de retorno de llamada. entrada.

Para eliminar una función de retorno de llamada que registró previamente para un descriptor de archivo y evento dados, simplemente llame a gl_watch_fd() con el mismo descriptor de archivo y los argumentos event, pero con un argumento callback de 0. El argumento data se i

gnora en
este caso.

    gl_inactivity_timeout() con un argumento callback de 0.
    El argumento data se ignora en este caso.






CONFIGURACIÓN PREDETERMINADA DEL MANEJO DE SEÑALES


Por defecto, la función gl_get_line() intercepta una serie
    de señales. Esto es particularmente importante para las señales que, por
    defecto, terminarían el proceso, ya que la terminal necesita ser restaurada
    a un estado utilizable antes de que esto ocurra. En esta sección, se describen
    las señales que son capturadas por defecto y cómo responde
    gl_get_line() a ellas. El cambio de estas configuraciones predeterminadas
    es el tema de la siguiente sección.


Cuando se capturan el siguiente subconjunto de señales,
    gl_get_line() primero restaura la configuración de la terminal y el
    manejo de señales a como estaban antes de llamar a
    gl_get_line(), reenvía la señal, para permitir que los manejadores
    de señales de la aplicación llamante la manejen, y luego, si el proceso
    aún existe, gl_get_line() devuelve NULL y establece errno
    como se especifica a continuación.


 SIGINT  -  Esta señal se genera tanto por la tecla de
            interrupción del teclado (generalmente ^C) como
            por la tecla de ruptura del teclado.
            errno=EINTR
 SIGHUP  -  Esta señal se genera cuando sale la terminal de
            control.
            errno=ENOTTY
 SIGPIPE -  Esta señal se genera cuando un programa intenta
            escribir en una tubería cuyo extremo remoto no está
            siendo leído por ningún proceso. Esto puede ocurrir,
            por ejemplo, si ha llamado a
            gl_change_terminal() para redirigir la salida
            a una tubería oculta bajo un pseudo terminal.
            errno=EPIPE
 SIGQUIT -  Esta señal se genera por la tecla de salida del
            teclado (generalmente ^\).
            errno=EINTR
 SIGABRT -  Esta señal se genera por la función estándar C,
            abort(). Por defecto, termina el proceso y genera
            un volcado de memoria.
            errno=EINTR
 SIGTERM -  Esta es la señal por defecto que el comando
            UN*X kill envía a los procesos.
            errno=EINTR


Tenga en cuenta que en el caso de todas las señales anteriores,
    POSIX exige que por defecto el proceso se termine, con la adición de un
    volcado de memoria en el caso de la señal SIGQUIT. En otras palabras,
    si la aplicación que llama no anula el manejador por defecto proporcionando
    su propio manejador de señales, la recepción de la señal correspondiente
    terminará la aplicación antes de que gl_get_line() regrese.


Si gl_get_line() aborta con errno establecido en EINTR, puede
    descubrir qué señal causó que abortara, llamando a la siguiente función.


  int gl_last_signal(const GetLine *gl);


Esto devuelve el código numérico (por ejemplo, SIGINT) de la
    última señal recibida durante la llamada más reciente a
    gl_get_line(), o -1 si no se recibieron señales.


En sistemas que lo soportan, cuando se recibe una señal SIGWINCH
    (cambio de ventana), gl_get_line() consulta la terminal para averiguar
    su nuevo tamaño, redibuja la línea de entrada actual para acomodar el nuevo
    tamaño, y luego regresa a esperar la entrada del teclado del usuario. A
    diferencia de otras señales, esta señal no se reenvía a la aplicación.


Finalmente, las siguientes señales hacen que gl_get_line()
    primero restaure la terminal y el entorno de señales a lo que prevalecía antes
    de que se llamara a gl_get_line(), luego reenvíe la señal a la
    aplicación. Si el proceso todavía existe después de que la señal haya sido
    entregada, entonces gl_get_line() reestablece sus propios manejadores
    de señales, cambia la terminal de vuelta al modo raw, redibuja la línea de
    entrada y vuelve a esperar la entrada de terminal del usuario.


 SIGCONT    -  Esta señal se genera cuando se reanuda un
               proceso suspendido.
 SIGPOLL    -  En sistemas SVR4, esta señal notifica al
               proceso de un evento de E/S asíncrono. Tenga
               en cuenta que bajo 4.3+BSD, SIGIO y SIGPOLL son
               lo mismo. En otros sistemas, SIGIO es ignorada
               por defecto, por lo que gl_get_line() no
               la captura por defecto.
 SIGPWR     -  Esta señal se genera cuando ocurre una falla
               de energía (presumiblemente cuando el sistema
               está en un UPS).
 SIGALRM    -  Esta señal se genera cuando expira un temporizador.
 SIGUSR1    -  Una señal específica de la aplicación.
 SIGUSR2    -  Otra señal específica de la aplicación.
 SIGVTALRM  -  Esta señal se genera cuando expira un
               temporizador virtual (ver man setitimer(2)).
 SIGXCPU    -  Esta señal se genera cuando un proceso excede
               su límite de tiempo de CPU suave.
 SIGXFSZ    -  Esta señal se genera cuando un proceso excede
               su límite de tamaño de archivo suave.
 SIGTSTP    -  Esta señal se genera por la tecla de suspensión
               de la terminal, que suele ser ^Z, o la tecla de
               suspensión de terminal retardada, que suele ser
               ^Y.
 SIGTTIN    -  Esta señal se genera si el programa intenta
               leer de la terminal mientras el programa se
               ejecuta en segundo plano.
 SIGTTOU    -  Esta señal se genera si el programa intenta
               escribir en la terminal mientras el programa se
               ejecuta en segundo plano.


Obviamente, no todas las señales anteriores son compatibles en
    todos los sistemas, por lo que el código para admitirlas se compila
    condicionalmente en la biblioteca tecla.


Tenga en cuenta que si SIGKILL o SIGPOLL, que por
    definición no se pueden capturar, o cualquiera de las señales de excepción
    generadas por hardware, como SIGSEGV, SIGBUS y SIGFPE,
    se reciben y no se manejan mientras gl_get_line() tiene la terminal
    en modo raw, el programa terminará sin que la terminal haya sido restaurada a
    un estado utilizable. En la práctica, los shells de control de trabajos suelen
    restablecer la configuración de la terminal cuando un proceso renuncia a la
    terminal de control, por lo que esto solo es un problema con shells antiguos.

MANEJO DE SEÑALES 
FIABLE

El manejo de señales es sorprendentemente difícil de hacer de
    forma fiable sin condiciones de carrera. En gl_get_line() se ha tenido mucho cuidado para permitir que
    las aplicaciones realicen un manejo de señales fiable alrededor de
    gl_get_line(). Esta sección explica cómo hacer uso de 
esto.

Como ejemplo de los problemas que pueden surgir si la aplicación
    no está escrita correctamente, imagine que su aplicación tiene un manejador
    de señales SIGINT que establece un indicador global. Ahora suponga que la
    aplicación prueba este indicador justo antes de invocar gl_get_line(). Si una señal SIGINT resulta
    recibirse en la pequeña ventana de tiempo entre la instrucción que prueba
    el valor de este indicador y la instrucción que llama a gl_get_line(),
    entonces gl_get_line() no verá la señal y no será
    interrumpido. Como resultado, la aplicación no podrá responder a la
    señal hasta que el usuario termine de ingresar la línea de entrada y
    gl_get_line() regrese. Dependiendo de la aplicación, esto podría
    ser o no un desastre, pero como mínimo confundiría al 
usuario.

La forma de evitar tales problemas es hacer lo 
siguiente.

1. Si es necesario, use la función gl_trap_signal() para
  

   configurar gl_get_line() para que aborte cuando se capturen
  

   señales 
importantes.

2. Configure gl_get_line() de modo que si alguna de las
  

   señales que captura están bloqueadas cuando se llama a
  

   gl_get_line(), se desbloqueen
  

   automáticamente durante los momentos en que gl_get_line() está
  

   esperando E/S. Esto se puede hacer ya sea
  

   por señal, llamando a la
  

   función gl_trap_signal() y especificando el
  

   atributo GLS_UNBLOCK de la señal, o globalmente
  

   llamando a la función gl_catch_blocked()
.

     void gl_catch_blocked(GetLine *gl)
;


  

   Esta función simplemente agrega el atributo GLS_UNBLOCK
  

   a todas las señales que actualmente está configurada para
  

   capturar
.

3. Justo antes de llamar a gl_get_line(), bloquee la entrega
  

   de todas las señales que gl_get_line() está
  

   configurada para capturar. Esto se puede hacer usando la función POSIX
  

   sigprocmask() en conjunto con la
  

   función gl_list_signals()
.

      int gl_list_signals(GetLine *gl, sigset_t *set)
;


  

   Esta función devuelve el conjunto de señales que está
  

   configurada para capturar actualmente en el argumento set,
  

   que está en la forma requerida por sigprocma
sk().

4. En el ejemplo, ahora se probaría el indicador global que
  

   el manejador de señales establece, sabiendo que ahora no hay
  

   peligro de que este indicador se establezca de nuevo hasta que
  

   gl_get_line() desbloquee sus señales mientras realiza
  

   E/S
.

5. Eventualmente gl_get_line() regresa, ya sea porque
  

   se capturó una señal, ocurrió un error, o el usuario
  

   terminó de ingresar su línea de 
entrada.

6. Ahora se verificaría el indicador global de señal de nuevo, y si
  

   está establecido, respondería a él y pondría el indicador a 
cero.

7. Use sigprocmask() para desbloquear las señales que fueron
  

   bloqueadas en el paso 
3.

La misma técnica se puede usar alrededor de ciertas funciones POSIX
    conscientes de señales, como sigsetjmp() y sigsuspend(), y en
    particular, la primera de estas dos funciones se puede usar en conjunto
    con siglongjmp() para implementar un manejo de señales libre de
    condiciones de carrera alrededor de otras llamadas al sistema de larga
    duración. La forma de hacer esto se explica a continuación, mostrando cómo gl_get_line() logra capturar señales de forma fiable
    alrededor de llamadas a funciones como read() y select() sin
    condiciones de 
carrera.

Lo primero que gl_get_line() hace, cada vez que es
    llamada, es usar la función POSIX sigprocmask() para bloquear la
    entrega de todas las señales que actualmente está configurada para
    capturar. Esto es redundante si la aplicación ya las ha bloqueado, pero no
    hace ningún daño. Deshace este paso justo antes de 
regresar.

Cada vez que gl_get_line() necesita llamar a read() o
    select() para esperar la entrada del usuario,
    primero llama a la función POSIX
    sigsetjmp(), asegurándose de especificar un valor distinto de
    cero para su argumento
    savesigs. La razón de este último argumento se aclarará
    en 
breve.

Si sigsetjmp() devuelve cero, gl_get_line() luego hace
    lo 
siguiente.

a. Usa la función POSIX sigaction() para registrar
   un manejador de señales temporal para todas las señales que está
   configurada para capturar. Este manejador de señales hace dos
   cosas.
   1. Registra el número de la señal que fue recibida
      en una variable de ámbito de archivo.
   2. Luego llama a la función POSIX siglongjmp()
      usando el búfer que se pasó a
      sigsetjmp() como su primer argumento, y
      un valor distinto de cero como su segundo argumento.
   Cuando este manejador de señales está registrado, el miembro sa_mask
   del argumento struct sigaction act de la
   llamada a sigaction() está configurado para contener todas las
   señales que gl_get_line() está capturando. Esto
   asegura que solo una señal sea capturada a la vez por
   nuestro manejador de señales, lo que a su vez asegura que múltiples
   instancias de nuestro manejador de señales no interfieran entre sí.
b. Ahora que el manejador de señales ha sido configurado,
   gl_get_line() desbloquea todas las señales que está
   configurada para capturar.
c. Luego llama a las llamadas al sistema read() o select() para esperar la entrada del
   teclado.
d. Si esta llamada al sistema regresa (es decir, no se recibe ninguna
   señal),
   gl_get_line() vuelve a bloquear la entrega de las señales de
   interés.
e. Luego reinstaura los manejadores de señales que fueron
   desplazados por el que se acaba de 
instalar.

Alternativamente, si sigsetjmp() devuelve un valor distinto de cero, esto significa
    que una de las señales atrapadas fue capturada mientras se ejecutaban los pasos anteriores. Cuando esto ocurre, gl_get_line() hace lo 
siguiente.

Primero, tenga en cuenta que cuando una llamada a siglongjmp() hace que
    sigsetjmp() retorne, siempre que el argumento savesigs de
    sigsetjmp() fuera distinto de cero, como se especificó anteriormente, la máscara de proceso de señales
    se restaura a cómo estaba cuando sigsetjmp() fue llamado. Esta es la
    diferencia importante entre sigsetjmp() y el antiguo y problemático
    setjmp(), y es el ingrediente esencial que hace posible
    evitar condiciones de carrera en el manejo de señales. Debido a esto, se garantiza
    que todas las señales que bloqueamos antes de llamar a sigsetjmp()
    vuelvan a estar bloqueadas tan pronto como se capture cualquier señal. Las siguientes sentencias,
    que se ejecutan a continuación, están por tanto garantizadas para ser ejecutadas sin que
    se capturen más 
señales.

1. Si así lo indican los atributos de configuración de gl_get_line()
  

   de la señal que fue capturada,
  

   gl_get_line() restaura los atributos del terminal a
  

   el estado que tenían cuando gl_get_line() fue
  

   llamado. Esto es particularmente importante para las señales que
  

   suspenden o terminan el proceso, ya que de lo contrario el
  

   terminal quedaría en un estado 
inutilizable.

2. Luego, reinstaura los manejadores de señales de la 
aplicación.

3. Después, usa la función raise()
  

   de la biblioteca estándar de C para reenviar a la aplicación la señal que
  

   fue 
capturada.

3. A continuación, desbloquea la entrega de la señal que acabamos de
  

   enviar. Esto resulta en que la señal que fue enviada
  

   vía raise(), sea capturada por el manejador de señales
  

   original de la aplicación, que ahora puede manejarla como
  

   considere 
oportuno.

4. Si el manejador de señales retorna (es decir, no termina
  

   el proceso), gl_get_line() bloquea de nuevo la entrega de la
  

   señal 
anterior.

5. Luego deshace cualquier acción realizada en el primero de los
  

   pasos anteriores, y vuelve a mostrar la línea, si la configuración de la señal
  

   lo 
requiere.

6. gl_get_line() luego reanuda el intento de
  

   leer un carácter, o se aborta, dependiendo de la
  

   configuración de la señal que fue 
capturada.

Lo que los pasos anteriores hacen en esencia es tomar señales
    entregadas de forma asíncrona y manejarlas de forma síncrona, una a la vez, en un punto
    del código donde gl_get_line() tiene control 
total sobre s
u
    entorno.



EL TAMAÑO DEL 
TERMINAL

En la mayoría de los sistemas, la combinación de la ioctl TIOCGWINSZ y la
    señal SIGWINCH se utiliza para mantener una idea precisa del
    tamaño del terminal. El tamaño del terminal se consulta de nuevo cada vez que se llama a
    gl_get_line() y siempre que se recibe una señal SIGW
INCH.

En los pocos sistemas donde este mecanismo no está disponible, al
    inicio new_GetLine() primero busca las variables de entorno LINES y
    COLUMNS. Si no se encuentran, o contienen valores inutilizables, entonces si está disponible una base de datos de información del terminal como terminfo o
    termcap, se busca el tamaño por defecto del terminal en esta
    base de datos. Si esto también falla en proporcionar el tamaño del terminal, se utiliza un tamaño por defecto de
    80 columnas por 24 
líneas.

Incluso en sistemas que sí soportan ioctl(TIOCGWINSZ), si el
    terminal está en el otro extremo de una línea serie, el controlador del terminal generalmente
    no tiene forma de detectar cuándo ocurre un redimensionamiento ni de consultar cuál es el tamaño
    actual. En tales casos, no se envía ningún SIGWINCH al proceso, y las
    dimensiones devueltas por ioctl(TIOCGWINSZ) no son correctas. La única forma
    de manejar tales instancias es proporcionar una manera para que el usuario introduzca un comando
    que le diga al sistema remoto cuál es el nuevo tamaño. Este comando llamaría entonces a la función gl_set_term_size() para informar a gl_get_line()
    sobre el cambio de 
tamaño.

  int gl_set_term_size(GetLine *gl, int ncolumn, int nline)
;

Los argumentos ncolumn y nline se utilizan para especificar
    las nuevas dimensiones del terminal, y no deben ser menores que 1. En sistemas
    que sí soportan ioctl(TIOCGWINSZ), esta función primero llama a
    ioctl(TIOCSWINSZ) para informar al controlador del terminal sobre el cambio en
    el tamaño. En el modo de E/S de servidor no bloqueante, si una línea está siendo introducida actualmente,
    la línea de entrada se redibuja para acomodar el tamaño cambiado. Finalmente, los
    nuevos valores se registran en gl para uso futuro por
  gl_get_li
ne().

La función gl_terminal_size() le permite consultar el
    tamaño actual del terminal, e instalar un tamaño de respaldo alternativo para
    los casos en que el tamaño no esté disponible. Tenga en cuenta que el tamaño del terminal no estará
    disponible si se lee desde una tubería o un archivo, por lo que los valores por defecto pueden ser
    importantes incluso en sistemas que sí soportan formas de averiguar el tamaño del 
terminal.

  typedef struct {
    int nline;        /* El terminal tiene nline líneas */
    int ncolumn;      /* El terminal tiene ncolumn columnas */
  } GlTerminalSize;
  GlTerminalSize gl_terminal_size(GetLine *gl,
                                  int def_ncolumn,
                                  int def_nline)
;

Esta función primero actualiza las dimensiones de respaldo del terminal de gl_get_line(), luego registra sus hallazgos en el valor de 
retorno.

Los argumentos def_ncolumn y def_nline especifican el número
    por defecto de columnas y líneas del terminal a usar si el tamaño del terminal no puede ser determinado vía ioctl(TIOCGWINSZ) o 
variables d
e entorno.



OCULTANDO LO QUE 
ESCRIBES

Al introducir información sensible, como contraseñas, es mejor
    no tener el texto que estás introduciendo reflejado en el terminal.
    Además, dicho texto no debería ser registrado en la lista de historial, ya que
    alguien que encuentre tu terminal desatendida podría entonces recuperarlo, o alguien
    husmeando en tus directorios podría verlo en tu archivo de historial. Teniendo esto en cuenta, la función gl_echo_mode() te permite activar y desactivar
    la visualización y el archivo de cualquier texto que se introduzca posteriormente en las llamadas a gl_get_li
ne().

  int gl_echo_mode(GetLine *gl, int enable)
;

El argumento enable especifica si el texto introducido debe
    ser visible o no. Si es 0, entonces las líneas introducidas posteriormente no
    serán visibles en el terminal, y no serán registradas en la lista de
    historial. Si es 1, entonces las líneas de entrada posteriores se mostrarán a medida que
    se introduzcan, y siempre que el historial no haya sido desactivado mediante una
    llamada a gl_toggle_history(), también serán archivadas en la
    lista de historial. Finalmente, si el argumento enable es -1, entonces el
    modo de eco se deja sin cambios, lo que te permite consultar de forma no destructiva
    la configuración actual a través del valor de retorno. En todos los casos, el valor de retorno de
    la función es 0 si el eco estaba desactivado antes de que se llamara a la función, y 1 si estaba 
activado.

Cuando el eco está desactivado, ten en cuenta que aunque la compl
etación con tabulador completará tu prefijo de forma invisible l
o más lejos posible, las completaciones ambiguas no se mostrarán.



CONSULTAS DE UN SOLO 
CARÁCTER

Usar gl_get_line() para consultar al usuario por una respuesta de un solo
    carácter, es inconveniente para el usuario, ya que debe presionar la tecla intro o retorno antes de que el carácter que escribió sea devuelto al
    programa. Por lo tanto, la función gl_query_char() ha sido proporcionada para
    consultas de un solo carácter como 
esta.

  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar)
;

Esta función muestra el indicador especificado al comienzo de una nueva
    línea, y espera a que el usuario escriba un carácter. Cuando el usuario escribe un
    carácter, gl_query_char() lo muestra a la derecha del indicador,
    inicia una nueva línea, y luego devuelve el carácter al programa llamante. El
    valor de retorno de la función es el carácter que fue escrito. Si la lectura
    tuvo que ser abortada por alguna razón, se devuelve EOF en su lugar. En el
    último caso, la aplicación puede llamar a la previamente documentada
    gl_return_status(), para averiguar qué salió mal. Esto podría, por
    ejemplo, haber sido la recepción de una señal, o el temporizador opcional de inactividad
    
activándose.

Si el usuario simplemente presiona intro, el valor del argumento defchar
    es sustituido. Esto significa que cuando el usuario presiona ya sea nueva línea
    o retorno, el carácter especificado en defchar, se muestra después del
    indicador, como si el usuario lo hubiera escrito, así como ser devuelto a la
    aplicación llamante. Si tal reemplazo no es importante, simplemente pasa
    '0 como el valor de defchar
.

Si el carácter introducido es un carácter no imprimible, se
    muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y
    los caracteres más allá de 127 se muestran en octal, precedidos por una barra 
invertida.

Al igual que con gl_get_line(), el eco del carácter introducido puede
    ser desactivado usando la función gl_echo_mode()
.

Si el proceso llamante es suspendido mientras espera a que el usuario
    escriba su respuesta, el cursor se mueve a la línea siguiente a la línea del indicador,
    luego cuando el proceso se reanuda, el indicador se vuelve a mostrar, y
    gl_query_char() reanuda la espera de que el usuario escriba un 
carácter.

Ten en cuenta que en el modo de servidor no bloqueante, (ver gl_io_mode(3)), si una
    línea de entrada incompleta está en proceso de ser leída cuando se llama a
    gl_query_char(), la línea de entrada parcial se descarta, y
    se borra del terminal, antes de que se muestre el nuevo indicador. La siguiente llamada a gl_get_line() comenzará por ta
nto a editar u
na nueva línea.



LEYENDO CARÁCTERES EN 
BRUTO

Mientras que la función gl_query_char() pide visiblemente al
    usuario un carácter, y muestra lo que escribió, la
    función gl_read_char() lee un carácter de señal del usuario,
    sin escribir nada en el terminal, o perturbar cualquier línea de entrada
    incompleta. Esto significa que puede ser llamada no solo entre
    llamadas a gl_get_line(), sino también desde funciones de retorno de llamada que la
    aplicación ha registrado para ser llamadas por gl_get_li
ne().

  int gl_read_char(GetLine *gl)
;

En caso de éxito, el valor de retorno de gl_read_char() es el
    carácter que fue leído. En caso de fallo, se devuelve EOF, y la
    función gl_return_status() puede ser llamada para averiguar qué salió
    mal. Las posibilidades incluyen el temporizador opcional de inactividad activándose, la
    recepción de una señal que está configurada para abortar gl_get_line(), o el bloqueo de E/S del
    terminal, cuando se está en el modo de E/S de servidor no 
bloqueante.

Ten en cuenta que ciertas teclas del teclado, como las teclas de función y
    las teclas de cursor, usualmente generan al menos 3 caracteres cada una, por lo que una sola llamada a gl_read_char() no't serían suficientes p
ara identificar dichas

MOSTRANDO   TEXTO 
DINÁMICAMENTE

Entre las llamadas a gl_get_line(), la función
    gl_display_text() proporciona una manera conveniente de mostrar
    párrafos de texto, justificados a la izquierda y divididos en una o más líneas de la terminal
    de acuerdo con las restricciones del ancho actual de la terminal. Ejemplos
    del uso de esta función se pueden encontrar en los programas de demostración, donde se
    utiliza para mostrar introducciones. En esos ejemplos también se ilustra el uso avanzado de
    prefijos opcionales, sufijos y líneas de relleno para dibujar un cuadro alrededor del 
texto.

  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string)
;

Si gl no está actualmente conectado a una terminal, por ejemplo
    si la salida de un programa que usa gl_get_line() se está canalizando a
    otro programa o se está redirigiendo a un archivo, entonces se utiliza el valor del
    parámetro def_width como el ancho de la 
terminal.

El argumento indentation especifica el número de caracteres
    a usar para sangrar cada línea de salida. El argumento fill_char especifica
    el carácter que se usará para realizar esta 
sangría.

El argumento prefix puede ser NULL, o ser una
    cadena de texto a colocar al comienzo de cada línea nueva (después de cualquier sangría).
    De manera similar, el argumento suffix puede ser NULL, o ser una
    cadena de texto a colocar al final de cada línea. El sufijo se coloca al ras contra
    el borde derecho de la terminal, y cualquier espacio entre su primer carácter
    y la última palabra de esa línea se rellena con el carácter especificado a través del argumento fill_char. Normalmente, el carácter de relleno es un 
espacio.

El argumento start le indica a gl_display_text() cuántos
    caracteres ya se han escrito en la línea de la terminal actual, y así
    le indica el índice de columna inicial del cursor. Dado que el valor de retorno de
    gl_display_text() es el índice de columna final del cursor, al
    pasar el valor de retorno de una llamada al argumento start de la
    siguiente llamada, se puede componer un párrafo que está dividido entre más de una cadena
    llamando a gl_display_text() para cada porción sucesiva del
    párrafo. Tenga en cuenta que los caracteres de salto de línea literales son necesarios al final
    de cada párrafo para forzar que se inicie una nueva 
línea.

En caso de error, gl_display_text
() devu
elve -1.

JUEGOS DE CARACTERES   
INTERNACIONALES

Desde la versión 1.4.0 de libtecla, gl_get_line() ha sido 8-bit
    limpio. Esto significa que todos los caracteres de 8 bits que son imprimibles en el
    locale actual del usuario ahora se muestran literalmente y se incluyen en la línea de entrada
    devuelta. Asumiendo que el programa que llama contiene correctamente una llamada como la
    
siguiente,

  setlocale(LC_CTYPE, "")
;

entonces el locale actual está determinado por la primera de las
    variables de entorno LC_CTYPE, LC_ALL, y LANG, que
    se encuentre que contiene un nombre de locale válido. Si ninguna de estas variables está
    definida, o el programa omite llamar a setlocale, entonces se usa el locale
    C predeterminado, que es ASCII de 7 bits de EE. UU. En la mayoría de las plataformas tipo unix,
    puede obtener una lista de locales válidos escribiendo el 
comando:

  locale 
-a

en el símbolo del shell. Se puede encontrar documentación adicional sobre cómo el usuario puede
    aprovechar esto para introducir caracteres internacionales en la
    página del man
ual te
cla(7).



SEGURIDAD DE   
HILOS

En un programa multi-hilo, debe usar la versión libtecla_r.a
    de la biblioteca. Esta usa versiones reentrantes de las funciones del sistema,
    cuando están disponibles. Desafortunadamente, ni terminfo ni termcap fueron diseñados para
    ser reentrantes, por lo que 
no puede usar de forma segura las funciones del módulo getline en
    múltiples hilos (puede usar los módulos separados de expansión de archivos y
    finalización de palabras en múltiples hilos, consulte las páginas de manuales correspondientes
    para más detalles). 
Sin embargo, debido al uso de funciones reentrantes de POSIX para
    buscar directorios de inicio de sesión, etc., es seguro usar este módulo desde un solo
    hilo de un programa multi-hilo, siempre que sus otros hilos no
    usen ninguna función de termcap o terminfo.
