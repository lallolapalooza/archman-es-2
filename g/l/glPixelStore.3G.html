NOMBRE

glPixelStore - establecer modos de almacenamiento de píxeles

ESPECIFICACIÓN C

void glPixelStoref(GLenum pname, GLfloat param);

void glPixelStorei(GLenum pname, GLint param);

PARÁMETROS

pname

Especifica el nombre simbólico del parámetro a establecer. Seis valores afectan al empaquetado de los datos de píxeles en memoria: GL_PACK_SWAP_BYTES, GL_PACK_LSB_FIRST, GL_PACK_ROW_LENGTH, GL_PACK_IMAGE_HEIGHT, GL_PACK_SKIP_PIXELS, GL_PACK_SKIP_ROWS, GL_PACK_SKIP_IMAGES y GL_PACK_ALIGNMENT. Seis más afectan al desempaquetado de los datos de píxeles *desde* la memoria: GL_UNPACK_SWAP_BYTES, GL_UNPACK_LSB_FIRST, GL_UNPACK_ROW_LENGTH, GL_UNPACK_IMAGE_HEIGHT, GL_UNPACK_SKIP_PIXELS, GL_UNPACK_SKIP_ROWS, GL_UNPACK_SKIP_IMAGES y GL_UNPACK_ALIGNMENT.

param

Especifica el valor al que se establece pname.

DESCRIPCIÓN

glPixelStore establece modos de almacenamiento de píxeles que afectan a la operación de glReadPixels() posteriores, así como al desempaquetado de patrones de texturas (ver glTexImage1D(), glTexImage2D(), glTexImage3D(), glTexSubImage1D(), glTexSubImage2D(), glTexSubImage3D()), glCompressedTexImage1D(), glCompressedTexImage2D(), glCompressedTexImage3D(), glCompressedTexSubImage1D(), glCompressedTexSubImage2D() o glCompressedTexSubImage1D().

pname es una constante simbólica que indica el parámetro a establecer, y param es el nuevo valor. Seis de los doce parámetros de almacenamiento afectan a cómo se devuelven los datos de píxeles a la memoria del cliente. Son los siguientes:

GL_PACK_SWAP_BYTES

Si es verdadero, el orden de los bytes para componentes de color de varios bytes, componentes de profundidad o índices de plantilla se invierte. Es decir, si un componente de cuatro bytes consta de los bytes b 0, b 1, b 2, b 3, se almacena en memoria como b 3, b 2, b 1, b 0 si GL_PACK_SWAP_BYTES es verdadero. GL_PACK_SWAP_BYTES no tiene efecto en el orden de memoria de los componentes dentro de un píxel, solo en el orden de los bytes dentro de los componentes o índices. Por ejemplo, los tres componentes de un píxel con formato GL_RGB siempre se almacenan con el rojo primero, el verde segundo y el azul tercero, independientemente del valor de GL_PACK_SWAP_BYTES.

GL_PACK_LSB_FIRST

Si es verdadero, los bits se ordenan dentro de un byte de menor a mayor significancia; de lo contrario, el primer bit de cada byte es el de mayor significancia.

GL_PACK_ROW_LENGTH

Si es mayor que 0, GL_PACK_ROW_LENGTH define el número de píxeles en una fila. Si el primer píxel de una fila se coloca en la ubicación p en memoria, entonces la ubicación del primer píxel de la siguiente fila se obtiene omitiendo

k = n ⁢ l a s ⁢ s ⁢ n ⁢ l a ⁢ s >= a s < a

componentes o índices, donde n es el número de componentes o índices en un píxel, l es el número de píxeles en una fila (GL_PACK_ROW_LENGTH si es mayor que 0, de lo contrario, el argumento width de la rutina de píxeles), a es el valor de GL_PACK_ALIGNMENT, y s es el tamaño, en bytes, de un solo componente (si a < s, entonces es como si a = s). En el caso de valores de 1 bit, la ubicación de la siguiente fila se obtiene omitiendo

k = 8 ⁢ a ⁢ n ⁢ l 8 ⁢ a

componentes o índices.

La palabra componente en esta descripción se refiere a los valores no de índice rojo, verde, azul, alfa y profundidad. El formato de almacenamiento GL_RGB, por ejemplo, tiene tres componentes por píxel: primero rojo, luego verde y finalmente azul.

GL_PACK_IMAGE_HEIGHT

Si es mayor que 0, GL_PACK_IMAGE_HEIGHT define el número de píxeles en un volumen de textura tridimensional de imagen, donde "imagen" se define por todos los píxeles que comparten el mismo índice de tercera dimensión. Si el primer píxel de una fila se coloca en la ubicación p en memoria, entonces la ubicación del primer píxel de la siguiente fila se obtiene omitiendo

k = n ⁢ l ⁢ h a s ⁢ s ⁢ n ⁢ l ⁢ h a ⁢ s >= a s < a

componentes o índices, donde n es el número de componentes o índices en un píxel, l es el número de píxeles en una fila (GL_PACK_ROW_LENGTH si es mayor que 0, de lo contrario, el argumento width de la rutina glTexImage3D()), h es el número de filas en una imagen de píxeles (GL_PACK_IMAGE_HEIGHT si es mayor que 0, de lo contrario, el argumento height de la rutina glTexImage3D()), a es el valor de GL_PACK_ALIGNMENT, y s es el tamaño, en bytes, de un solo componente (si a < s, entonces es como si a = s).

La palabra componente en esta descripción se refiere a los valores no de índice rojo, verde, azul, alfa y profundidad. El formato de almacenamiento GL_RGB, por ejemplo, tiene tres componentes por píxel: primero rojo, luego verde y finalmente azul.

GL_PACK_SKIP_PIXELS, GL_PACK_SKIP_ROWS y GL_PACK_SKIP_IMAGES

Estos valores se proporcionan como una conveniencia para el programador; no ofrecen ninguna funcionalidad que no pueda duplicarse simplemente incrementando el puntero pasado a glReadPixels(). Establecer GL_PACK_SKIP_PIXELS a i es equivalente a incrementar el puntero en i ⁢ n componentes o índices, donde n es el número de componentes o índices por píxel. Establecer GL_PACK_SKIP_ROWS a j es equivalente a incrementar el puntero en j ⁢ m componentes o índices, donde m es el número de componentes o índices por fila, tal como se calculó en la sección GL_PACK_ROW_LENGTH. Establecer GL_PACK_SKIP_IMAGES a k es equivalente a incrementar el puntero en k ⁢ p, donde p es el número de componentes o índices por imagen, tal como se calculó en la sección GL_PACK_IMAGE_HEIGHT.

GL_PACK_ALIGNMENT

Especifica los requisitos de alineación para el inicio de cada fila de píxeles en memoria. Los valores permitidos son 1 (alineación de bytes), 2 (filas alineadas a bytes pares), 4 (alineación de palabras) y 8 (filas que comienzan en límites de doble palabra).

Los otros seis de los doce parámetros de almacenamiento afectan a cómo se leen los datos de píxeles desde la memoria del cliente. Estos valores son significativos para glTexImage1D(), glTexImage2D(), glTexImage3D(), glTexSubImage1D(), glTexSubImage2D() y glTexSubImage3D()

Son los siguientes:

GL_UNPACK_SWAP_BYTES

Si es verdadero, el orden de los bytes para componentes de color de varios bytes, componentes de profundidad o índices de plantilla se invierte. Es decir, si un componente de cuatro bytes consta de los bytes b 0, b 1, b 2, b 3, se toma de la memoria como b 3, b 2, b 1, b 0 si GL_UNPACK_SWAP_BYTES es verdadero. GL_UNPACK_SWAP_BYTES no tiene efecto en el orden de memoria de los componentes dentro de un píxel, solo en el orden de los bytes dentro de los componentes o índices. Por ejemplo, los tres componentes de un píxel con formato GL_RGB siempre se almacenan con el rojo primero, el verde segundo y el azul tercero, independientemente del valor de GL_UNPACK_SWAP_BYTES.

GL_UNPACK_LSB_FIRST

Si es verdadero, los bits se ordenan dentro de un byte de menor a mayor significancia; de lo contrario, el primer bit de cada byte es el de mayor significancia.

GL_UNPACK_ROW_LENGTH

Si es mayor que 0, GL_UNPACK_ROW_LENGTH define el número de píxeles en una fila. Si el primer píxel de una fila se coloca en la ubicación p en memoria, entonces la ubicación del primer píxel de la siguiente fila se obtiene omitiendo

glPixelStoref se puede usar para establecer cualquier parámetro de almacenamiento de píxeles. Si el tipo de parámetro es booleano, entonces si param es 0, el parámetro es falso; de lo contrario se establece en verdadero. Si pname es un parámetro de tipo entero, param se redondea al entero más

cercano.

Del mismo modo, glPixelStorei también se puede usar para establecer cualquiera de los parámetros de almacenamiento de píxeles. Los parámetros booleanos se establecen en falso si param es 0 y en ver

dadero de lo contrario.

S

aceptado.

Se genera GL_INVALID_VALUE si se especifica una longitud de fila, un salto de píxel o un s

alto de fila negativo, o si la alineación se
especifica como distinta de 1, 2, 4 u 8.
