NOMBRE

glBufferStorage, glNamedBufferStorage - crea e inicializa el almacén de datos inmutable de un objeto de búfer

ESPECIFICACIÓN EN C

void glBufferStorage(GLenumtarget, GLsizeiptrsize, const void *data, GLbitfieldflags);

void glNamedBufferStorage(GLuintbuffer, GLsizeiptrsize, const void *data, GLbitfieldflags);

PARÁMETROS

target

Especifica el destino al que se enlaza el objeto de búfer para glBufferStorage, que debe ser uno de los objetivos de enlace de búfer de la siguiente tabla:
Objetivo de enlace de búfer Propósito
GL_ARRAY_BUFFER Atributos de vértice
GL_ATOMIC_COUNTER_BUFFER Almacenamiento de contadores atómicos
GL_COPY_READ_BUFFER Origen de copia de búfer
GL_COPY_WRITE_BUFFER Destino de copia de búfer
GL_DISPATCH_INDIRECT_BUFFER Comandos de despacho de cómputo indirecto
GL_DRAW_INDIRECT_BUFFER Argumentos de comando indirectos
GL_ELEMENT_ARRAY_BUFFER Índices de matriz de vértices
GL_PIXEL_PACK_BUFFER Destino de lectura de píxeles
GL_PIXEL_UNPACK_BUFFER Fuente de datos de textura
GL_QUERY_BUFFER Búfer de resultados de consulta
GL_SHADER_STORAGE_BUFFER Almacenamiento de lectura-escritura para shaders
GL_TEXTURE_BUFFER Búfer de datos de textura
GL_TRANSFORM_FEEDBACK_BUFFER Búfer de transform feedback
GL_UNIFORM_BUFFER Almacenamiento de bloques uniformes

buffer

Especifica el nombre del objeto de búfer para la función glNamedBufferStorage .

size

Especifica el tamaño en bytes del nuevo almacén de datos del objeto de búfer.

data

Especifica un puntero a los datos que se copiarán en el almacén de datos para la inicialización, o NULL si no se deben copiar datos.

flags

Especifica el uso previsto del almacén de datos del búfer. Debe ser una combinación por bits de los siguientes indicadores. GL_DYNAMIC_STORAGE_BIT, GL_MAP_READ_BIT GL_MAP_WRITE_BIT, GL_MAP_PERSISTENT_BIT, GL_MAP_COHERENT_BIT, y GL_CLIENT_STORAGE_BIT.

DESCRIPCIÓN

glBufferStorage y glNamedBufferStorage crean un nuevo almacén de datos inmutable. Para glBufferStorage, el objeto de búfer actualmente enlazado a target será inicializado. Para glNamedBufferStorage, buffer es el nombre del objeto de búfer que se configurará. El tamaño del almacén de datos se especifica mediante size. Si hay datos iniciales disponibles, su dirección puede proporcionarse en data. De lo contrario, para crear un almacén de datos no inicializado, data debe ser NULL.

El parámetro flags especifica el uso previsto del almacén de datos del búfer. Debe ser una combinación por bits de un subconjunto de los siguientes indicadores:

GL_DYNAMIC_STORAGE_BIT

El contenido del almacén de datos puede actualizarse después de la creación mediante llamadas a glBufferSubData(). Si este bit no está establecido, el contenido del búfer no puede ser actualizado directamente por el cliente. El argumento data puede usarse para especificar el contenido inicial del almacén de datos del búfer independientemente de la presencia de GL_DYNAMIC_STORAGE_BIT. Independientemente de la presencia de este bit, los búferes siempre pueden actualizarse con llamadas del lado del servidor como glCopyBufferSubData() y glClearBufferSubData().

GL_MAP_READ_BIT

El almacén de datos puede ser mapeado por el cliente para acceso de lectura y obtener un puntero en el espacio de direcciones del cliente desde el que se pueda leer.

GL_MAP_WRITE_BIT

El almacén de datos puede ser mapeado por el cliente para acceso de escritura y obtener un puntero en el espacio de direcciones del cliente a través del cual se pueda escribir.

GL_MAP_PERSISTENT_BIT

El cliente puede solicitar que el servidor lea de o escriba en el búfer mientras está mapeado. El puntero del cliente al almacén de datos permanece válido mientras el almacén de datos esté mapeado, incluso durante la ejecución de comandos de dibujo o despacho.

GL_MAP_COHERENT_BIT

El acceso compartido a búferes que están simultáneamente mapeados para acceso del cliente y son utilizados por el servidor será coherente, siempre que ese mapeo se realice mediante glMapBufferRange(). Es decir, los datos escritos en el almacén por el cliente o el servidor serán inmediatamente visibles para el otro sin ninguna acción adicional por parte de la aplicación. En particular,
•Si GL_MAP_COHERENT_BIT no está establecido y el cliente realiza una escritura seguida de una llamada al comando glMemoryBarrier() con GL_CLIENT_MAPPED_BUFFER_BARRIER_BIT establecido, entonces en comandos posteriores el servidor verá las escrituras.
•Si GL_MAP_COHERENT_BIT está establecido y el cliente realiza una escritura, entonces en comandos posteriores el servidor verá las escrituras.
•Si GL_MAP_COHERENT_BIT no está establecido y el servidor realiza una escritura, la aplicación debe llamar a glMemoryBarrier() con GL_CLIENT_MAPPED_BUFFER_BARRIER_BIT establecido y luego llamar a glFenceSync() con GL_SYNC_GPU_COMMANDS_COMPLETE (o glFinish). Entonces la CPU verá las escrituras después de que la sincronización se complete.
•Si GL_MAP_COHERENT_BIT está establecido y el servidor realiza una escritura, la aplicación debe llamar a glFenceSync con GL_SYNC_GPU_COMMANDS_COMPLETE (o glFinish()). Entonces la CPU verá las escrituras después de que la sincronización se complete.

GL_CLIENT_STORAGE_BIT

Cuando se cumplen todos los demás criterios para la asignación del almacenamiento del búfer, este bit puede ser utilizado por una implementación para determinar si usar almacenamiento local al servidor o al cliente para servir como almacén de respaldo del búfer.

Las combinaciones permitidas de indicadores están sujetas a ciertas restricciones. Son las siguientes:

•Si flags contiene GL_MAP_PERSISTENT_BIT, también debe contener al menos uno de GL_MAP_READ_BIT o GL_MAP_WRITE_BIT.
•Si flags contiene GL_MAP_COHERENT_BIT, también debe contener GL_MAP_PERSISTENT_BIT.

NOTAS

glBufferStorage está disponible solo si la versión de GL es 4.4 o superior.

glNamedBufferStorage está disponible solo si la versión de GL es 4.5 o superior.

Si data es NULL, un almacén de datos del tamaño especificado se crea igualmente, pero su contenido permanece sin inicializar y por lo tanto es indefinido.

ERRORES

GL_INVALID_ENUM es generado por glBufferStorage si target no es uno de los objetivos de búfer aceptados.

GL_INVALID_OPERATION es generado por glNamedBufferStorage si buffer no es el nombre de un objeto de búfer existente.

GL_INVALID_VALUE es generado si size es menor o igual a cero.

GL_INVALID_OPERATION es generado por glBufferStorage si el nombre de objeto de búfer reservado 0 está enlazado a target.

GL_OUT_OF_MEMORY es generado si el GL no puede crear un almacén de datos con las propiedades solicitadas en flags.

GL_INVALID_VALUE es generado si flags tiene algún bit establecido distinto de los definidos anteriormente.

GL_INVALID_VALUE se genera si flags contiene GL_MAP_PERSISTENT_BIT pero no contiene al menos uno de GL_MAP_READ_BIT o GL_MAP_WRITE_BIT.

GL_INVALID_VALUE es generado si flags contiene GL_MAP_COHERENT_BIT, pero no contiene también GL_MAP_PERSISTENT_BIT.

GL_INVALID_OPERATION es generadovalorado por glBufferStorage si el GL_BUFFER_IMMUTABLE_STORAGE bandera del buffer vinculado a target es GL_TRUE.
