NOMBRE

glClearTexSubImage - rellena toda o parte de una imagen de textura con un valor constante

ESPECIFICACIÓN EN C

void glClearTexSubImage(GLuinttexture, GLintlevel, GLintxoffset, GLintyoffset, GLintzoffset, GLsizeiwidth, GLsizeiheight, GLsizeidepth, GLenumformat, GLenumtype, const void *data);

PARÁMETROS

texture

El nombre de un objeto de textura existente que contiene la imagen a limpiar.

level

El nivel de texture que contiene la región a limpiar.

xoffset

La coordenada del borde izquierdo de la región a limpiar.

yoffset

La coordenada del borde inferior de la región a limpiar.

zoffset

La coordenada del frente de la región a limpiar.

width

El ancho de la región a limpiar.

height

La altura de la región a limpiar.

depth

La profundidad de la región a limpiar.

format

El formato de los datos cuya dirección en memoria es dada por data.

type

El tipo de los datos cuya dirección en memoria es dada por data.

data

La dirección en memoria de los datos a usar para limpiar la región especificada.

DESCRIPCIÓN

glClearTexSubImage rellena toda o parte de una imagen contenida en una textura con un valor proporcionado por la aplicación. texture debe ser el nombre de una textura existente. Además, texture no puede ser el nombre de una textura de búfer, ni su formato interno puede estar comprimido.

Los argumentos xoffset, yoffsety zoffset especifican las coordenadas del texel inferior izquierdo de una subregión rectangular de la matriz de texels con ancho, alto y profundidad dados.

Para texturas de arreglo unidimensional, yoffset se interpreta como la primera capa a limpiar y height es el número de capas a limpiar. Para texturas de arreglo bidimensional, zoffset se interpreta como la primera capa a limpiar y depth es el número de capas a limpiar. Las texturas de mapa cúbico se tratan como un arreglo de seis rebanadas en la dimensión z, donde el valor de zoffset se interpreta como la especificación de la cara del mapa cúbico para la capa correspondiente y depth es el número de caras a limpiar. Para texturas de arreglo de mapa cúbico, zoffset es la primera capa-cara a limpiar, y depth es el número de capas-caras a limpiar. Cada capa-cara se traduce en una capa de arreglo y una cara de mapa cúbico como se describe en la Especificación de OpenGL.

Los valores negativos de xoffset, yoffsety zoffset corresponden a las coordenadas de los texels del borde. Para tipos de textura que no tienen ciertas dimensiones, este comando trata esas dimensiones como si tuvieran un tamaño de 1. Por ejemplo, para limpiar una porción de una textura bidimensional, use zoffset igual a cero y depth igual a uno.

format y type especifican el formato y el tipo de los datos de origen y se interpretan como se hace para glTexImage3D(). Las texturas con un formato interno base de GL_DEPTH_COMPONENT, GL_STENCIL_INDEXo GL_DEPTH_STENCIL requieren datos de componente de profundidad, de stencil o de profundidad-stencil respectivamente. Las texturas con otros formatos internos base requieren formatos RGBA. Las texturas con formatos internos enteros requieren datos enteros.

data es un puntero a un arreglo de entre uno y cuatro componentes de datos de texel que se usarán como fuente para el valor de relleno constante. Los elementos de data son convertidos por la GL al formato interno de la imagen de la textura (que fue especificado cuando el nivel fue definido por cualquiera de los comandos glTexImage*, glTexStorage* o glCopyTexImage* ), y luego se usan para llenar el rango especificado del nivel de la textura de destino. Si data es NULL, entonces el puntero es ignorado y el subrango de la imagen de la textura se rellena con ceros. Si la textura es una textura multisample, todas las muestras en un texel se limpian al valor especificado por data.

NOTAS

glClearTexSubImage está disponible solo si la versión de GL es 4.4 o superior.

ERRORES

GL_INVALID_OPERATION se genera si texture es cero o no es el nombre de un objeto de textura existente.

GL_INVALID_OPERATION se genera si texture es una textura de búfer.

GL_INVALID_OPERATION se genera si texture tiene un formato interno comprimido.

GL_INVALID_OPERATION se genera si el formato interno base es GL_DEPTH_COMPONENT y format no es GL_DEPTH_COMPONENT.

GL_INVALID_OPERATION se genera si el formato interno base es GL_DEPTH_STENCIL y format no es GL_DEPTH_STENCIL.

GL_INVALID_OPERATION se genera si el formato interno base es GL_STENCIL_INDEX y format no es GL_STENCIL_INDEX.

GL_INVALID_OPERATION se genera si el formato interno base es GL_RGBA y format es GL_DEPTH_COMPONENT, GL_STENCIL_INDEXo GL_DEPTH_STENCIL.

GL_INVALID_OPERATION se genera si el formato interno es entero y format no especifica datos enteros.

GL_INVALID_OPERATION se genera si el formato interno no es entero y format especifica datos enteros.

GL_INVALID_OPERATION se genera un error si los parámetros xoffset, yoffset, zoffset, width, heighty depth (o combinaciones de ellos) especifican una región que cae fuera de la matriz de la imagen de la textura definida (incluyendo el borde, si lo hay).
