PARÁMETROS

location

Especifica la ubicación de la variable uniforme que se va a modificar.

count

Para los comandos de vector (glUniform*v), especifica el número de elementos que se van a modificar. Debe ser 1 si la variable uniforme objetivo no es un arreglo, y 1 o más si es un arreglo.

Para los comandos de matriz (glUniformMatrix*), especifica el número de matrices que se van a modificar. Debe ser 1 si la variable uniforme objetivo no es un arreglo de matrices, y 1 o más si es un arreglo de matrices.

transpose

Para los comandos de matriz, especifica si se debe transponer la matriz a medida que los valores se cargan en la variable uniforme.

v0, v1, v2, v3

Para los comandos escalares, especifica los nuevos valores que se utilizarán para la variable uniforme especificada.

value

Para los comandos de vector y matriz, especifica un puntero a un arreglo de count valores que se utilizarán para actualizar la variable uniforme especificada.

DESCRIPCIÓN

glUniform modifica el valor de una variable uniforme o de un arreglo de variables uniformes. La ubicación de la variable uniforme a modificar se especifica mediante location, que debe ser un valor devuelto por glGetUniformLocation(). glUniform opera sobre el objeto de programa que pasó a formar parte del estado actual mediante una llamada a glUseProgram().

Los comandos glUniform{1|2|3|4}{f|i|ui} se utilizan para cambiar el valor de la variable uniforme especificada por location usando los valores pasados como argumentos. El número especificado en el comando debe coincidir con el número de componentes del tipo de dato de la variable uniforme especificada (por ejemplo, 1 para float, int, unsigned int, bool; 2 para vec2, ivec2, uvec2, bvec2, etc.). El sufijo f indica que se están pasando valores de punto flotante; el sufijo i indica que se están pasando valores enteros; el sufijo ui indica que se están pasando valores enteros sin signo, y este tipo también debe coincidir con el tipo de dato de la variable uniforme especificada. Las variantes i de esta función deben usarse para proporcionar valores a variables uniformes definidas como int, ivec2, ivec3, ivec4, o arreglos de estas. Las variantes ui de esta función deben usarse para proporcionar valores a variables uniformes definidas como unsigned int, uvec2, uvec3, uvec4, o arreglos de estas. Las variantes f deben usarse para proporcionar valores a variables uniformes de tipo float, vec2, vec3, vec4, o arreglos de estas. Se puede usar cualquiera de las variantes i, ui o f para proporcionar valores a variables uniformes de tipo bool, bvec2, bvec3, bvec4, o arreglos de estas. La variable uniforme se establecerá en false si el valor de entrada es 0 o 0.0f, y se establecerá en true en caso contrario.

Todas las variables uniformes activas definidas en un objeto de programa se inicializan a 0 cuando el objeto de programa se enlaza correctamente. Conservan los valores asignados por una llamada a glUniform hasta que ocurra la siguiente operación de enlace exitosa en el objeto de programa, momento en el que se inicializan nuevamente a 0.

Los comandos glUniform{1|2|3|4}{f|i|ui}v se pueden usar para modificar una sola variable uniforme o un arreglo de variables uniformes. Estos comandos pasan un conteo y un puntero a los valores que se cargarán en una variable uniforme o en un arreglo de variables uniformes. Se debe usar un conteo de 1 si se modifica el valor de una sola variable uniforme, y se puede usar un conteo de 1 o mayor para modificar un arreglo completo o parte de un arreglo. Al cargar n elementos comenzando en una posición arbitraria m en un arreglo de variables uniformes, los elementos m + n - 1 del arreglo se reemplazarán con los nuevos valores. Si m + n - 1 es mayor que el tamaño del arreglo de variables uniformes, los valores para todos los elementos del arreglo más allá del final del arreglo se ignorarán. El número especificado en el nombre del comando indica el número de componentes para cada elemento en value, y debe coincidir con el número de componentes del tipo de dato de la variable uniforme especificada (por ejemplo, 1 para float, int, bool; 2 para vec2, ivec2, bvec2, etc.). El tipo de dato especificado en el nombre del comando debe coincidir con el tipo de dato de la variable uniforme especificada tal como se describió anteriormente para glUniform{1|2|3|4}{f|i|ui}.

Para los arreglos de variables uniformes, cada elemento del arreglo se considera del tipo indicado en el nombre del comando (por ejemplo, glUniform3f o glUniform3fv se pueden usar para cargar un arreglo de variables uniformes de tipo vec3). El número de elementos del arreglo de variables uniformes a modificar se especifica mediante count

Los comandos glUniformMatrix{2|3|4|2x3|3x2|2x4|4x2|3x4|4x3}fv se utilizan para modificar una matriz o un arreglo de matrices. Los números en el nombre del comando se interpretan como la dimensionalidad de la matriz. El número 2 indica una matriz de 2 × 2 (es decir, 4 valores), el número 3 indica una matriz de 3 × 3 (es decir, 9 valores), y el número 4 indica una matriz de 4 × 4 (es decir, 16 valores). La dimensionalidad de matrices no cuadradas es explícita, con el primer número representando el número de columnas y el segundo número representando el número de filas. Por ejemplo, 2x4 indica una matriz de 2 × 4 con 2 columnas y 4 filas (es decir, 8 valores). Si transpose es GL_FALSE, se asume que cada matriz se proporciona en orden por columnas. Si transpose es GL_TRUE, se asume que cada matriz se proporciona en orden por filas. El argumento count indica el número de matrices a pasar. Se debe usar un conteo de 1 si se modifica el valor de una sola matriz, y se puede usar un conteo mayor que 1 para modificar un arreglo de matrices.

NOTAS

glUniform1i y glUniform1iv son las dos únicas funciones que pueden usarse para cargar variables uniformes definidas como tipos de muestreador. Cargar muestreadores con cualquier otra función resultará en un error GL_INVALID_OPERATION.

Si count es mayor que 1 y la variable uniforme indicada no es un arreglo, se genera un error GL_INVALID_OPERATION y la variable uniforme especificada permanecerá sin cambios.

Aparte de las excepciones anteriores, si el tipo y el tamaño de la variable uniforme tal como se define en el shader no coinciden con el tipo y el tamaño especificados en el nombre del comando usado para cargar su valor, se generará un error GL_INVALID_OPERATION y la variable uniforme especificada permanecerá sin cambios.

Si location es un valor distinto de -1 y no representa una ubicación de variable uniforme válida en el objeto de programa actual, se generará un error y no se realizarán cambios en el almacenamiento de la variable uniforme del objeto de programa actual. Si location es igual a -1, los datos pasados se ignorarán silenciosamente y la variable uniforme especificada no se cambiará.

ERRORES

Se genera GL_INVALID_OPERATION si no hay ningún objeto de programa actual.

Se genera GL_INVALID_OPERATION si el tamaño de la variable uniforme declarada en el shader no coincide con el tamaño indicado por el comando glUniform.

Se genera GL_INVALID_OPERATION si se usa una de las variantes de entero con signo o sin signo de esta función para cargar una variable uniforme de tipo float, vec2, vec3, vec4, o un arreglo de estas, o si se usa una de las variantes de punto flotante de esta función para cargar una variable uniforme de tipo int, ivec2, ivec3, ivec4, unsigned int, uvec2, uvec3, uvec4, o un arreglo de estas.

Se genera GL_INVALID_OPERATION si se usa una de las variantes de entero con signo de esta función para cargar una variable uniforme de tipo unsigned int, uvec2, uvec3, uvec4, o un arreglo de estas.

Se genera GL_INVALID_OPERATION si se usa una de las variantes de entero sin signo de esta función para cargar una variable uniforme de tipo int, ivec2, ivec3, ivec4, o un arreglo de estas.

Se genera GL_INVALID_OPERATION si location es una ubicación uniforme no válida para el objeto de programa actual y location no es igual a -1.

Se genera GL_INVALID_VALUE si count es menor que 0.

Se genera GL_INVALID_OPERATION si count es mayor que 1 y la variable uniforme indicada no es una variable de arreglo.

Se genera GL_INVALID_OPERATION si se carga un sampler usando un comando distinto de glUniform1i y glUniform1iv.
