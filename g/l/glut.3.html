NOMBRE

glut - una introducción al OpenGL Utility Toolkit

SINOPSIS

#include <GL/glut.h>

DESCRIPCIÓN

El OpenGL Utility Toolkit (GLUT) es una interfaz de programación con enlaces ANSI C y FORTRAN para escribir programas OpenGL independientes del sistema de ventanas. El toolkit soporta la siguiente funcionalidad:

Múltiples ventanas para el renderizado OpenGL.
Procesamiento de eventos dirigido por callbacks.
Varios dispositivos de entrada incluyendo teclado, ratón, tableta, caja de diales y botones, joystick y Spaceball.
Una rutina de "inactividad" y temporizadores.
Una instalación simple de menús emergentes en cascada.
Rutinas de utilidad para generar varios objetos sólidos y de alambre.
Soporte para fuentes de mapa de bits y de trazo.
Funciones diversas de gestión de ventanas, incluyendo gestión de superposiciones, redimensionamiento dinámico de vídeo y soporte de pantalla completa orientado a juegos.

El autor ha implementado una implementación ANSI C de GLUT tanto para el Sistema de Ventanas X (X11) como para Windows 95, 98 y NT (Win32). Están disponibles enlaces de lenguaje para FORTRAN y Ada. Los programas C++ pueden llamar a GLUT directamente a través de la interfaz C. También están disponibles implementaciones de GLUT para MacOS y OS/2.

ANTECEDENTES

Uno de los logros principales en la especificación de OpenGL fue el aislamiento de las dependencias del sistema de ventanas del modelo de renderizado de OpenGL. El resultado es que OpenGL es independiente del sistema de ventanas.

Las operaciones del sistema de ventanas, como la creación de una ventana de renderizado y el manejo de eventos del sistema de ventanas, se dejan al sistema de ventanas nativo para definir. Las interacciones necesarias entre OpenGL y el sistema de ventanas, como crear y vincular un contexto OpenGL a una ventana, se describen por separado de la especificación de OpenGL en una especificación dependiente del sistema de ventanas. Por ejemplo, la especificación GLX describe el estándar por el cual OpenGL interactúa con el Sistema de Ventanas X. Del mismo modo, la interfaz WGL define cómo OpenGL interactúa con el sistema operativo Windows de Microsoft.

El predecesor de OpenGL es IRIS GL. A diferencia de OpenGL, IRIS GL sí especifica cómo se crean y manipulan las ventanas de renderizado. La interfaz de ventanas de IRIS GL es razonablemente popular en gran parte porque es simple de usar. Los programadores de IRIS GL pueden preocuparse por la programación gráfica sin necesidad de ser expertos en la programación del sistema de ventanas nativo. La experiencia también demostró que la interfaz de ventanas de IRIS GL era lo suficientemente de alto nivel como para poder ser redirigida a diferentes sistemas de ventanas. Silicon Graphics migró de NeWS al Sistema de Ventanas X sin ningún cambio importante en la interfaz de ventanas básica de IRIS GL.

Eliminar las operaciones del sistema de ventanas de OpenGL es una decisión acertada porque permite que el sistema gráfico OpenGL sea redirigido a varios sistemas, incluyendo estaciones de trabajo gráficas potentes pero costosas, así como sistemas gráficos de producción masiva como videojuegos, decodificadores para televisión interactiva y PCs.

Desafortunadamente, la falta de una interfaz de sistema de ventanas para OpenGL es una brecha en la utilidad de OpenGL. Aprender APIs nativas del sistema de ventanas como Xlib o Motif del Sistema de Ventanas X puede ser intimidante. Incluso aquellos familiarizados con las APIs nativas del sistema de ventanas necesitan entender la interfaz que vincula OpenGL al sistema de ventanas nativo. Y cuando un programa OpenGL se escribe usando la interfaz del sistema de ventanas nativo, a pesar de la portabilidad del código de renderizado OpenGL del programa, el programa en sí será dependiente del sistema de ventanas.

Probar y documentar la funcionalidad de OpenGL llevó al desarrollo de los toolkits tk y aux. El toolkit aux se usa en los ejemplos encontrados en la Guía de Programación de OpenGL. Desafortunadamente, aux tiene numerosas limitaciones y su utilidad se limita en gran parte a programas de juguete. La biblioteca tk tiene más funcionalidad que aux pero fue desarrollada de una manera ad hoc y aún carece de mucha funcionalidad importante que los programadores de IRIS GL esperan, como menús emergentes y superposiciones.

GLUT está diseñado para llenar la necesidad de una interfaz de programación independiente del sistema de ventanas para programas OpenGL. La interfaz está diseñada para ser simple pero aún así satisfacer las necesidades de programas OpenGL útiles. Se incluyen características de las interfaces IRIS GL, aux y tk para facilitar a los programadores acostumbrados a estas interfaces el desarrollo de programas para GLUT.

FILOSOFÍA

GLUT simplifica la implementación de programas que usan renderizado OpenGL. La interfaz de programación de aplicaciones (API) de GLUT requiere muy pocas rutinas para mostrar una escena gráfica renderizada usando OpenGL. La API de GLUT (al igual que la API de OpenGL) es con estado. La mayoría del estado inicial de GLUT está definido y el estado inicial es razonable para programas simples.

Las rutinas de GLUT también toman relativamente pocos parámetros. No se devuelven punteros. Los únicos punteros pasados a GLUT son punteros a cadenas de caracteres (todas las cadenas pasadas a GLUT se copian, no se referencian) y manejadores de fuentes opacos.

La API de GLUT es (en la medida de lo razonable) independiente del sistema de ventanas. Por esta razón, GLUT no devuelve ningún manejador, puntero u otra estructura de datos nativa del sistema de ventanas. GLUT evita dependencias más sutiles del sistema de ventanas, como la dependencia de fuentes dependientes del sistema de ventanas; en su lugar, GLUT proporciona su propio conjunto (limitado) de fuentes.

Para facilitar la programación, GLUT proporciona una simple sub-API de menús. Aunque el soporte de menús está diseñado para ser implementado como menús emergentes, GLUT da libertad al sistema de ventanas para soportar la funcionalidad de menús de otra manera (menús desplegables, por ejemplo).

Dos de las piezas más importantes del estado de GLUT son la ventana actual y el menú actual. La mayoría de las rutinas de ventanas y menús afectan a la ventana o menú actual respectivamente. La mayoría de los callbacks establecen implícitamente la ventana y el menú actuales a la ventana o menú apropiados responsables del callback. GLUT está diseñado para que un programa con solo una ventana y/o menú no necesite llevar la cuenta de ningún identificador de ventana o menú. Esto simplifica enormemente los programas GLUT muy simples.

GLUT está diseñado para programas simples a moderadamente complejos centrados en el renderizado OpenGL. GLUT implementa su propio bucle de eventos. Por esta razón, mezclar GLUT con otras APIs que demandan su propia estructura de manejo de eventos puede ser difícil. La ventaja de un bucle de despacho de eventos integrado es la simplicidad.

GLUT contiene rutinas para renderizar fuentes y objetos geométricos, sin embargo GLUT no reclama el espacio de nombres de listas de visualización de OpenGL. Por esta razón, ninguna de las rutinas de renderizado de GLUT usa listas de visualización de OpenGL. Corresponde al programador de GLUT compilar la salida de las rutinas de renderizado de GLUT en listas de visualización si esto es deseado.

Las rutinas de GLUT están organizadas lógicamente en varias sub-APIs según su funcionalidad. Las sub-APIs son:

Inicialización.
El procesamiento de la línea de comandos, la inicialización del sistema de ventanas y el estado inicial de creación de ventanas están controlados por estas rutinas.
Comienzo del Procesamiento de Eventos.
Esta rutina entra en el bucle de procesamiento de eventos de GLUT. Esta rutina nunca retorna, y llama continuamente a los callbacks de GLUT según sea necesario.
Gestión de Ventanas.
Estas rutinas crean y controlan ventanas.
Gestión de Superposiciones.
Estas rutinas establecen y gestionan superposiciones para ventanas.
Gestión de Menús.
Estas rutinas crean y controlan menús emergentes.
Registro de Callbacks.
Estas rutinas registran callbacks para ser llamados por el bucle de procesamiento de eventos de GLUT.
Gestión de Mapas de Color de Índice de Color.
Estas rutinas permiten la manipulación de mapas de color de índice de color para ventanas.
Modo de Pantalla Completa Orientado a Juegos.
Estas rutinas permiten usar OpenGL en un modo de pantalla completa a varias resoluciones y profundidades de pantalla.
Recuperación de Estado.
Estas rutinas permiten a los programas recuperar estado de GLUT.
Renderizado de Fuentes.
Estas rutinas permiten el renderizado de fuentes de trazo y de mapa de bits.
Renderizado de Formas Geométricas.
Estas rutinas permiten el renderizado de objetos 3D objetos geométricos
, incluyendo

CONVENCIONE

S

Las coordenadas de ventana y de pantalla de GLUT se expresan en píxeles. La esquina superior izquierda de la pantalla o de una ventana es (0,0). Las coordenadas X aumentan hacia la derecha; las coordenadas Y aumentan hacia abajo. Nota: Esto es inconsistente con el esquema de coordenadas de OpenGL, que generalmente considera que la coordenada inferior izquierda de una ventana está en (0,0), pero es consistente con la mayoría de los sistemas de ventana

populares.

Los identificadores enteros en GLUT comienzan con uno, no con cero. Por lo tanto, los identificadores de ventana, los identificadores de menú y los índices de los elementos del menú se basan en uno, no en

cero.

En el enlace ANSI C de GLUT, para la mayoría de las rutinas, se utilizan tipos básicos (int, char*) como parámetros. En las rutinas donde los parámetros se pasan directamente a rutinas de OpenGL, se utilizan tipos de OpenGL (GLfloat)

.

Los archivos de cabecera para GLUT deben incluirse en los programas GLUT con la siguiente directiva de

inclusión: 
#include <GL/glut.
h>

Debido a que un proveedor de software de sistemas de ventana muy grande (que permanecerá sin nombre) tiene una aparente incapacidad para apreciar que la API de OpenGL es independiente de su API de sistema de ventana, los programas GLUT ANSI C portables no deben incluir directamente <GL/gl.h> o <GL/glu.h>. En su lugar, los programas GLUT ANSI C deben confiar en que <GL/glut.h> incluya los archivos de cabecera necesarios relacionados con OpenGL y

GLU.

El archivo de biblioteca ANSI C de GLUT se denomina típicamente libglut.a en los sistemas Unix. Los programas GLUT necesitan enlazar con las bibliotecas OpenGL y GLUT del sistema (y con cualquier biblioteca de la que estas bibliotecas dependan potencialmente). También puede ser necesario un conjunto de bibliotecas dependientes del sistema de ventana para enlazar los programas GLUT. Por ejemplo, los programas que utilizan la implementación GLUT de X11 típicamente necesitan enlazar con Xlib, la biblioteca de extensiones de X, posiblemente la biblioteca de extensión de entrada de X, la biblioteca de utilidades misceláneas de X y la biblioteca de matemáticas. Una línea de compilación de ejemplo para X11/Unix se vería

así: 
cc -o foo foo.c -lgl
ut -lGLU -lGL -lXmu -
lXi -lXext -lX11 -lm
