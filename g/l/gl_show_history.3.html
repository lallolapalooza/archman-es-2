DESCRIPCIÓ

N

La función gl_get_line() es parte de la biblioteca tecla (véase la página man libtecla(3)). Si el usuario está escribiendo en un terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de unix. Además de la edición de línea de comandos simple, soporta el recuerdo de líneas de comandos introducidas previamente, la completación con TAB de nombres de archivos, y la expansión en línea de comodines de nombres de archivos. La documentación de ambas las características de edición de línea de comandos a nivel de usuario y todas las opciones de configuración de usuario, se puede encontrar en la página man tecla(7). ar esta biblioteca en su aplicación.

EJEMPLO

Lo siguiente muestra un ejemplo completo de cómo usar la función gl_get_line() para obtener entrada del

usuario: 
  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que el usuario escribió */
    GetLine *gl;   /* El objeto recurso de gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* de juego de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("Usted escribió: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
}

En el ejemplo, primero los recursos necesarios por la función gl_get_line() son creados llamando a new_GetLine(). Esto asigna la memoria usada en llamadas subsecuentes a la función gl_get_line(), incluyendo el búfer de historial para registrar líneas introducidas previamente. Entonces se leen una o más líneas del usuario, hasta que ocurra un error, o el usuario escriba exit. Entonces finalmente los recursos que fueron asignados por new_GetLine(), son devueltos al sistema llamando a del_GetLine(). Nótese el uso del valor de retorno NULL de del_GetLine() para hacer gl NULL. Esta es una precaución de seguridad. Si el programa subsecuentemente intenta pasar gl

a

gl_get_line(), dicha función se quejará, y retornará un error, en lugar de intentar usar el objeto recurso

eliminado.

La función gl_get_line() puede ser llamada cualquier número de veces para leer entrada del usuario. El argumento gl debe haber sido previamente retornado por una llamada a new_GetLine(). El argumento prompt debería ser una cadena normal terminada en NUL, especificando el prompt a presentar al usuario. Por defecto los prompts son mostrados literalmente, pero si es habilitado con la función gl_prompt_style() (véase más adelante), los prompts pueden contener directivas para hacer subrayado, cambiar a y de fuentes en negrita, o activar y desactivar el

Este debe ser -1 si desea que el cursor siga al último carácter de la línea de inicio. Si no desea precargar la línea de esta manera, envíe start_line como NULL, y establezca start_pos en -1. Tenga en cuenta que el puntero a la línea devuelto por una llamada a gl_get_line() puede pasarse a la siguiente llamada a gl_get_line() a través del start_line. Esto permite a la aplicación tomar la última línea introducida y, si contiene un error, presentarla de nuevo al usuario para su reedición, con el cursor inicialmente posicionado donde se encontró el

error.

La función gl_get_line() devuelve un puntero a la línea introducida por el usuario, o NULL en caso de error o al final de la entrada. El puntero devuelto es parte del objeto recurso gl especificado y, por lo tanto, no debe ser liberado por el llamante, ni asumirse que es invariable de una llamada a la siguiente. Al leer de un usuario en una terminal, siempre habrá un carácter de salto de línea al final de la línea devuelta. Cuando la entrada estándar se toma de una tubería o de un archivo, de manera similar habrá un salto de línea a menos que la línea de entrada fuera demasiado larga para almacenarse en el búfer interno. En este último caso, debe llamar a gl_get_line() de nuevo para leer el resto de la línea. Tenga en cuenta que este comportamiento hace que gl_get_line() sea similar a fgets(). De hecho, cuando stdin no está conectado a una terminal,gl_get_line() simplemente llama a fget

s(

FUENTES DE CONFIGURACIÓN

ALTERNATIVAS

Como se mencionó anteriormente, de forma predeterminada los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. En algunas aplicaciones, sin embargo, este único medio de configuración es un problema. Esto es particularmente cierto en software embebido, donde no hay un sistema de archivos del cual leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de asignaciones de teclas para emular una interfaz de teclado heredada. Para atender a estos casos, la siguiente función permite a la aplicación controlar desde dónde se leen la información de

configuración. 
  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file)
;

Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc del usuario, se lean de una, ninguna o varias de estas fuentes: una cadena, un archivo de configuración específico de la aplicación y/o un archivo de configuración específico del usuario. Si esta función se llama antes de la primera llamada a gl_get_line(), el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line() se deshabilita, por lo que toda la configuración debe lograrse utilizando las fuentes de configuración especificadas con esta

función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados entre sí en la cadena por caracteres de salto de línea incrustados. Si app_file != NULL entonces se interpreta como la ruta de acceso completa de un archivo de configuración específico de la aplicación. Si user_file != NULL entonces se interpreta como la ruta de acceso completa de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente

llamada, 
  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc")
;

el argumento app_string hace que la aplicación que llama comience en el modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso de la campana de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración de todo el sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario desde un archivo .teclarc opcional en el directorio de inicio del usuario. Tenga en cuenta que los argumentos se listan en orden ascendente de prioridad, con el contenido de app_string siendo potencialmente sobreescrito por comandos en app_file, y los comandos en app_file potencialmente siendo sobreescritos por comandos en user_file

.

Puede llamar a esta función tantas veces como sea necesario, siendo los resultados acumulativos, pero tenga en cuenta que las copias de cualquier nombre de archivo especificado a través de app_file y user_file se registran internamente para su uso posterior por la función de asociación de teclas read-init-files, así que si planea llamar a esta función varias veces, asegúrese de que la última llamada especifique los nombres de archivo que desea volver a leer cuando el usuario solicite que los archivos de configuración se

relean.

COMPLETADO DE PALABRAS

PERSONALIZADO

Si en su aplicación desea que la completación con TAB complete otras cosas además de o en lugar de nombres de archivo, puede organizar esto registrando una función de retorno de completación alternativa, mediante una llamada a la función gl_customize_co

mpletion(). 
  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn)
;

El argumento data proporciona una manera para que su aplicación pase información arbitraria y específica de la aplicación a la función de retorno. Esto se pasa a la función de retorno cada vez que se la llama. Podría, por ejemplo, apuntar a la tabla de símbolos desde la cual se deben buscar las posibles completaciones. El argumento match_fn especifica la función de retorno a llamar. El tipo de función CplMatchFn está definido en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y prototipar funciones de retorno. La declaración y las responsabilidades de las funciones de retorno se describen en profundidad en la página del manual cpl_complete_word(3)

.

En resumen, la función de retorno es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario presionó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar posibles completaciones de esta palabra y registrarlas una por una en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion(). Si la función de retorno desea proporcionar completación de nombres de archivo además de sus propias completaciones específicas, tiene la opción de llamar ella misma a la función de retorno de completación de nombres de archivo incorporada. Esto también está documentado en la página del manual cpl_complete_word(3)

.

Tenga en cuenta que si desea que gl_get_line() devuelva la línea de entrada actual cuando se haya realizado una completación exitosa, puede organizar esto cuando llame a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de salto de línea. Si hace esto, la línea de entrada se actualizará para mostrar la completación, junto con cualquier sufijo de continuación hasta el carácter de salto de línea, y luego gl_get_line() devolverá esta línea de

entrada.

Si, por alguna razón, su función de retorno necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto iniciará una nueva línea después de la línea de entrada que se está editando actualmente, restablecerá la E/S normal de la terminal y le dirá a gl_get_line() que la línea de entrada necesitará

ser redibujada cuando la f
unción de retorno regrese.

AÑADIENDO ACCIONES DE

COMPLETACIÓN

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de completación predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que diferentes tipos de completación de palabras se puedan asociar a diferentes secuencias de teclas. Esto se logra usando la función gl_completion_action()

. 
  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq)
;

Los argumentos data y match_fn se describen en la página del manual de cpl_complete_word, y especifican la función de retorno que debe invocarse para identificar posibles completaciones. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar cualquier posible completación ambigua, o si simplemente debe mostrar la lista de posibles completaciones sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre con el que los archivos de configuración y las futuras invocaciones de esta función deben referirse a la acción. Este debe ser el nombre de una acción de completación existente que se va a cambiar, o un nuevo nombre sin usar para una nueva acción. Finalmente, el argumento keyseq especifica la secuencia de teclas predeterminada a la que asociar la acción. Si esto es NULL, no se asociará ninguna nueva secuencia de teclas a la

acción.

Tenga cuidado de que para que el usuario pueda cambiar la secuencia de teclas asociada a las acciones instaladas de esta manera, cuando llame a gl_completion_action() para instalar una acción determinada por primera vez, debe hacerlo entre la llamada a new_GetLine() y la primera llamada a gl_get_line(). DEFINIENDO ACCIONES

PERSONALIZADAS

Aunque las acciones de asociación de teclas incorporadas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, asociadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza que correspondía a un número de pieza anterior al cursor. Tal característica está claramente fuera del alcance de las funciones de acción incorporadas. Así que para tales casos especiales, se proporciona la función gl_register_action()

  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq)
;

Esta función permite a la aplicación registrar una función externa, fn, que a partir de entonces será llamada cada vez que se introduzca la secuencia de teclas especificada, keyseq, por el usuario, o cuando el usuario introduzca cualquier otra secuencia de teclas que el usuario asocie posteriormente al nombre de acción especificado, name, en su archivo de configuración. El argumento data puede ser un puntero a cualquier cosa que la aplicación desee que se pase a la función de acción, fn, cada vez que esa función sea

invocada.

La función de acción, fn, debe declararse usando la siguiente macro, que está definida en libtecl

a.h. 
  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char
*line)

Los argumentos gl y data son aquellos que se pasaron previamente a gl_register_action() cuando se registró la función de acción. El argumento count es un argumento numérico que el usuario tiene la opción de introducir usando la acción digit-argument, antes de invocar la acción. Si el usuario no introduce un número, entonces el argumento count se establece en 1. Nominalmente, este argumento se interpreta como un conteo de repetición, lo que significa que la acción debe repetirse esa cantidad de veces. Sin embargo, en la práctica, para algunas acciones un conteo de repetición tiene poco sentido. En tales casos, las acciones pueden simplemente ignorar el argumento count, o usar su valor para un propósito

diferente.

Se pasa una copia de la línea de entrada actual en el argumento de solo lectura line. La posición actual del cursor dentro de esta cadena está dada por el índice contenido en el argumento curpos. Tenga en cuenta que no se permite la manipulación directa de la línea de entrada y la posición del cursor. Esto se debe a que las reglas dictadas por varios modos, como el modo vi frente al modo emacs, el modo sin eco, y el modo de inserción frente al modo de sobrescritura, etc., hacen que sea demasiado compleo para un programador de aplicaciones escribir una acción de edición conforme, así como restringen cambios futuros en los internos de gl_get_line(). Una solución potencial a este dilema sería permitir que la función de acción edite la línea usando las acciones de edición existentes. Actualmente esto está en

consideración.

Si la función de acción desea escribir texto en la terminal, sin que esto se mezcle con el texto mostrado de la línea de entrada, o leer de la terminal sin tener que manejar la E/S cruda de la terminal, entonces antes de realizar cualquiera de estas operaciones, debe suspender temporalmente la edición de línea llamando a la función gl_normal_io(). Esta función vacía cualquier salida pendiente hacia la terminal, mueve el cursor al inicio de la línea que sigue a la última línea de terminal de la línea de entrada, y luego restaura la terminal a un estado que es adecuado para su uso con las instalaciones de stdio de C. Lo último incluye cosas como restaurar el mapeo normal de \n a \r\n, y, cuando está en modo servidor, restaurar la forma normal de bloqueo de la E/S de la terminal. Después de haber llamado a esta función, la acción puede leer de y escribir en la terminal sin temor a crear un desorden. No es necesario que la función de acción restaure el entorno de edición original antes de regresar. Esto lo hace automáticamente el gl_get_line() después de que la función de acción regrese. Lo siguiente es un ejemplo sencillo de una función de acción que escribe la frase "Hello world" en una nueva línea de terminal después de la línea que se está editando. Cuando esta función regresa, la línea de entrada se redibuja en la línea que sigue a la línea "Hello world", y la edición de línea se

reanuda. 
  static GL_ACTION_FN(say_hello_fn)
  {
    if(gl_normal_io(gl))   /* Temporarily suspend editing */
      return GLA_ABORT;
    printf("Hello world\n");
    return GLA_CONTINUE;
}

proceder. 
  GLA_ABORT     -   Hace que gl_get_line() devuelva NULL.
  GLA_RETURN    -   Hace que gl_get_line() devuelva la
                    línea de entrada completada.
  GLA_CONTINUE  -   Reanuda la edición de la línea de
comandos.

Tenga en cuenta que el argumento name de gl_register_action() especifica el nombre con el que un usuario puede referirse a la acción en su archivo de configuración. Esto les permite volver a vincular la acción a una secuencia de teclas alternativa. Para que esto funcione, es necesario llamar a gl_register_action() entre la llamada a new_GetLine() y la primera llamada a gl_get_

La función constructora new_GetLine() asume que la entrada debe leerse desde stdin, y que la salida se escribe en stdout. La siguiente función le permite cambiar a diferentes flujos de entrada y

Por defecto, gl_get_line() no retorna hasta que el usuario ha introducido una línea de entrada completa, o hasta que ocurre un error. En programas que necesitan vigilar la E/S de otras fuentes que no sean el terminal, hay dos

opciones. 
  1. Utilice las funciones descritas en la página de manual
     gl_io_mode(3) para cambiar
     gl_get_line() al modo de servidor no bloqueante. En este modo,
     gl_get_line() se convierte en una función de edición de
     líneas incremental no bloqueante que puede llamarse de forma segura desde
     un bucle de eventos externo. Aunque este es un método muy
     versátil, implica asumir algunas
     responsabilidades que normalmente se realizan de forma transparente por gl_get_line().
  2. Mientras gl_get_line() está esperando la entrada del
     teclado del usuario, puede pedirle que también vigile
     la actividad en descriptores de archivo arbitrarios, como
     sockets de red, tuberías, etc., y que llame a funciones
     de su elección cuando se detecte actividad. Esto funciona en
     cualquier sistema que tenga la llamada al sistema select(),
     que es la mayoría, si no todos, de las variantes de
unix.

;

Si esto retorna un valor distinto de cero, significa que o bien sus argumentos son inválidos, o que esta funcionalidad no es compatible con el sistema

anfitrión.

El argumento fd es el descriptor de archivo a vigilar. El argumento event especifica qué tipo de actividad es de interés, elegida de entre los siguientes valores

enumerados: 
  GLFD_READ   -  Vigilar la llegada de datos para leer.
  GLFD_WRITE  -  Vigilar la capacidad de escribir en el descriptor
                 de archivo sin bloquear.
  GLFD_URGENT -  Vigilar la llegada de datos urgentes
                 fuera de banda en el descriptor de
archivo.

El argumento callback es la función a llamar cuando se detecta la actividad seleccionada. Debe definirse con la siguiente macro, que está definida en libtecla.

  #define GL_FD_EVENT_FN(fn) GlFdStatus (fn)(GetLine *gl, \
                                      void *data, int fd, \
                                      GlFdEvent
event)

El argumento data de la función gl_watch_fd() se pasa a la función de retorno de llamada para su propio uso, y puede apuntar a lo que desee, incluyendo NULL. El descriptor de archivo y el argumento event también se pasan a la función de retorno de llamada, y esto potencialmente permite que la misma función de retorno de llamada se registre para más de un tipo de evento y/o más de un descriptor de archivo. El valor de retorno de la función de retorno de llamada debe ser uno de los siguientes

valores. 
  GLFD_ABORT    -  Decirle a gl_get_line() que aborte. Cuando esto
                   ocurre, gl_get_line() retorna
                   NULL, y una llamada posterior a
                   gl_return_status() retornará
                   GLR_FDABORT. Nótese que si la
                   aplicación necesita errno tenga
                   siempre un valor significativo cuando
                   gl_get_line() retorna NULL,
                   la función de retorno de llamada debe establecer
                   errno de forma apropiada.
  GLFD_REFRESH  -  Redibujar la línea de entrada y luego continuar
                   esperando entrada. Retorne esto si
                   su retorno de llamada escribió en el terminal.

                   redibujar la
línea.

Nótese que antes de llamar al retorno de llamada, gl_get_line() bloquea la mayoría de las señales, y deja instalados sus propios manejadores de señal, así que si necesita capturar una señal en particular, necesitará tanto instalar temporalmente su propio manejador de señal, como desbloquear la señal. Asegúrese de volver a bloquear la señal (si estaba originalmente bloqueada) y reinstalar el manejador de señal original, si lo hay, antes de

retornar.

Si la función de retorno de llamada necesita leer o escribir en el terminal, idealmente debería primero llamar a gl_normal_io(gl) para suspender temporalmente la edición de líneas. Esto restaurará el terminal a modo canónico, de E/S bloqueante, y moverá el cursor al comienzo de una nueva línea del terminal. Más tarde, cuando el retorno de llamada retorna, gl_get_line() notará que gl_normal_io() fue llamada, volverá a mostrar la línea de entrada y reanudará la edición. Nótese que en este caso los valores de retorno, GLFD_REFRESH y GLFD_CONTINUE son

equivalentes.

Para soportar los casos en los que la función de retorno de llamada llama a una función de terceros que ocasionalmente e imprevisiblemente escribe en la terminal, la conversión automática de "0 a "0 se vuelve a habilitar antes de que se llame a la función de retorno de llamada. Si el retorno de llamada sabe que la función de terceros escribió en el terminal, entonces debe retornar el valor de retorno GLFD_REFRESH, para decirle a gl_get_line() que vuelva a mostrar la línea de

entrada.

El tiempo de espera se especifica en forma de un número entero de

  #define GL_TIMEOUT_FN(fn) \

Al regresar, se espera que la función de callback de la aplicación
    devuelva uno de los siguientes enumeradores para indicar a
    gl_get_line() cómo proceder después de que el callback haya manejado
    el tiempo de espera.


  GLTO_ABORT    -  Indica a gl_get_line() que aborte. Cuando
                   esto sucede, gl_get_line() devolverá
                   NULL, y una llamada posterior a
                   gl_return_status() devolverá
                   GLR_TIMEOUT. Tenga en cuenta que si la
                   aplicación necesita que errno siempre
                   tenga un valor significativo cuando
                   gl_get_line() devuelve NULL,
                   la función de callback debe establecer
                   errno apropiadamente.

                   esperando entrada. Debe devolver este
                   valor si su callback escribió en la
                   terminal sin haber llamado primero a
                   gl_normal_io(gl).
  GLTO_CONTINUE -  En el modo normal de E/S bloqueante, continúa
                   esperando entrada, sin redibujar la línea
                   de entrada del usuario.
                   En el modo de E/S de servidor no bloqueante
                   (ver gl_io_mode(3)), hace que
                   gl_get_line() actúe como si la E/S se
                   hubiera bloqueado. Esto significa que
                   gl_get_line() devolverá inmediatamente
                   NULL, y una llamada posterior a
                   gl_return_status() devolverá
                   GLR_BLOCKED.


Tenga en cuenta que antes de llamar a la función de callback,
    gl_get_line() bloquea la mayoría de las señales y deja sus propios
    manejadores de señales instalados, por lo que si necesita capturar una señal
    particular, deberá instalar temporalmente su propio manejador de señales y
    desbloquear la señal. Asegúrese de volver a bloquear la señal (si estaba
    bloqueada originalmente) y restablecer el manejador de señales original, si
    lo hay, antes de regresar.


Si la función de callback necesita leer o escribir en la terminal,
    idealmente debería llamar primero a gl_normal_io(gl) para suspender
    temporalmente la edición de línea. Esto restaurará la terminal al modo
    canónico de E/S bloqueante y moverá el cursor al inicio de una nueva línea
    de terminal. Más tarde, cuando la función de callback regrese,
    gl_get_line() notará que se llamó a gl_normal_io(), redibujará
    la línea de entrada y reanudará la edición. Tenga en cuenta que en este caso
    los valores de retorno, GLTO_REFRESH y GLTO_CONTINUE son
    equivalentes.


Para soportar casos en los que la función de callback llama a una
    función de terceros que ocasionalmente y de forma impredecible escribe en la
    terminal, la conversión automática de "0 a "0 se
    vuelve a habilitar antes de llamar a la función de callback. Si el callback
    sabe que la función de terceros escribió en la terminal, entonces debería
    devolver el valor de retorno GLTO_REFRESH, para indicar a
    gl_get_line() que redibuje la línea de entrada.


Tenga en cuenta que aunque el argumento de tiempo de espera incluye
    un componente de nanosegundos, pocos relojes de computadora tienen actualmente
    resoluciones más finas que unos pocos milisegundos, por lo que solicitar
    menos de unos pocos milisegundos es equivalente a solicitar cero segundos en
    muchos sistemas. Si esto fuera un problema, debería basar su selección de
    tiempo de espera en la resolución real del reloj del host (por ejemplo,
    llamando a sysconf(_SC_CLK_TCK)).


Para desactivar los tiempos de espera, simplemente llame a
    gl_inactivity_timeout() con un argumento callback de
    0. El argumento data se ignora en este caso.






VALORES PREDETERMINADOS DE MANEJO DE SEÑALES


Por defecto, la función gl_get_line() intercepta varias
    señales. Esto es particularmente importante para las señales que por defecto
    terminarían el proceso, ya que la terminal debe restaurarse a un estado
    utilizable antes de que esto suceda. En esta sección, se describen las
    señales que son capturadas por defecto y cómo responde
    gl_get_line() a ellas. Cambiar estos valores predeterminados es el tema
    de la siguiente sección.


Cuando se capturan el siguiente subconjunto de señales,
    gl_get_line() primero restaura la configuración de la terminal y el
    manejo de señales a como estaban antes de que se llamara a
    gl_get_line(), reenvía la señal, para permitir que los manejadores de
    señales de la aplicación que llama la manejen, luego si el proceso todavía
    existe, gl_get_line() devuelve NULL y establece errno
    según se especifica a continuación.


 SIGINT  -  Esta señal es generada tanto por la tecla de
            interrupción del teclado (generalmente ^C), como
            por la tecla de pausa del teclado.
            errno=EINTR
 SIGHUP  -  Esta señal se genera cuando la terminal de control
            sale.
            errno=ENOTTY
 SIGPIPE -  Esta señal se genera cuando un programa intenta
            escribir en una tubería cuyo extremo remoto no está
            siendo leído por ningún proceso. Esto puede suceder,
            por ejemplo, si ha llamado a
            gl_change_terminal() para redirigir la salida
            a una tubería oculta bajo una terminal pseudo.
            errno=EPIPE
 SIGQUIT -  Esta señal es generada por la tecla de salir del
            teclado (generalmente ^\).
            errno=EINTR
 SIGABRT -  Esta señal es generada por la función estándar
            de C, abort(). Por defecto, termina el proceso y
            genera un volcado del núcleo.
            errno=EINTR
 SIGTERM -  Esta es la señal predeterminada que el comando
            kill de UN*X envía a los procesos.
            errno=EINTR


Tenga en cuenta que en el caso de todas las señales anteriores,
    POSIX exige que, por defecto, el proceso termine, con la adición de un volcado
    del núcleo en el caso de la señal SIGQUIT. En otras palabras, si la
    aplicación que llama no anula el manejador predeterminado proporcionando su
    propio manejador de señales, la recepción de la señal correspondiente terminará
    la aplicación antes de que gl_get_line() regrese.


Si gl_get_line() se aborta con errno establecido en EINTR, puede
    averiguar qué señal provocó el aborto llamando a la siguiente función.


  int gl_last_signal(const GetLine *gl);


Esto devuelve el código numérico (por ejemplo, SIGINT) de la
    última señal recibida durante la llamada más reciente a
    gl_get_line(), o -1 si no se recibió ninguna señal.


En sistemas que lo soportan, cuando se recibe una señal SIGWINCH
    (cambio de ventana), gl_get_line() consulta la terminal para conocer
    su nuevo tamaño, redibuja la línea de entrada actual para acomodar el nuevo
    tamaño y luego regresa a esperar la entrada del teclado del usuario. A
    diferencia de otras señales, esta señal no se reenvía a la aplicación.


Finalmente, las siguientes señales hacen que gl_get_line()
    primero restaure la terminal y el entorno de señales al que prevalecía antes
    de que se llamara a gl_get_line(), luego reenvíe la señal a la
    aplicación. Si el proceso aún existe después de que la señal ha sido
    entregada, entonces gl_get_line() reestablece sus propios manejadores
    de señales, cambia la terminal de nuevo a modo raw, redibuja la línea de
    entrada y vuelve a esperar la entrada de la terminal del usuario.


 SIGCONT    -  Esta señal se genera cuando se reanuda un
               proceso suspendido.
 SIGPOLL    -  En sistemas SVR4, esta señal notifica al
               proceso de un evento de E/S asíncrono. Tenga
               en cuenta que bajo 4.3+BSD, SIGIO y SIGPOLL
               son lo mismo. En otros sistemas, SIGIO es
               ignorado por defecto, por lo que
               gl_get_line() no lo captura por defecto.
 SIGPWR     -  Esta señal se genera cuando ocurre un corte de
               energía (presumiblemente cuando el sistema está
               en un UPS).
 SIGALRM    -  Esta señal se genera cuando expira un temporizador.
 SIGUSR1    -  Una señal específica de la aplicación.
 SIGUSR2    -  Otra señal específica de la aplicación.
 SIGVTALRM  -  Esta señal se genera cuando expira un temporizador
               virtual (ver man setitimer(2)).
 SIGXCPU    -  Esta señal se genera cuando un proceso excede
               su límite de tiempo de CPU suave.
 SIGXFSZ    -  Esta señal se genera cuando un proceso excede
               su límite de tamaño de archivo suave.
 SIGTSTP    -  Esta señal es generada por la tecla de suspender
               la terminal, que suele ser ^Z, o la tecla de
               suspender la terminal retardada, que suele ser
               ^Y.
 SIGTTIN    -  Esta señal se genera si el programa intenta leer
               de la terminal mientras el programa se ejecuta en
               segundo plano.
 SIGTTOU    -  Esta señal se genera si el programa intenta escribir
               en la terminal mientras el programa se ejecuta en
               segundo plano.


Obviamente, no todas las señales anteriores son compatibles en todos
    los sistemas, por lo que el código para soportarlas se compila condicionalmente
    en la biblioteca tecla.


Tenga en cuenta que si SIGKILL o SIGPOLL, que por
    definición no pueden ser capturados, o cualquiera de las señales de excepción
    generadas por hardware, como SIGSEGV, SIGBUS y SIGFPE,
    se reciben y no se manejan mientras gl_get_line() tiene la terminal
    en modo raw, el programa terminará sin que la terminal se restaure a un estado
    utilizable. En la práctica, los shells de control de trabajos suelen restablecer
    la configuración de la terminal cuando un proceso cede la terminal de control,
    por lo que esto solo es un problema con shells más antiguos.






MANEJO PERSONALIZADO DE SEÑALES


La sección anterior enumeró las señales que gl_get_line()
    atrapa por defecto y describió cómo responde a ellas. Esta sección describe
    cómo agregar y eliminar señales de la lista de señales atrapadas, y cómo
    especificar cómo gl_get_line() debe responder a una señal dada.


Si no necesita que gl_get_line() haga nada en respuesta a
    una señal que normalmente atrapa, puede indicarle a gl_get_line() que
    ignore esa señal llamando a gl_ignore_signal().


  int gl_ignore_signal(GetLine *gl, int signo);


El argumento signo es el número de la señal (por ejemplo,
    SIGINT) que desea ignorar. Si la señal especificada no es actualmente
    una de las que se están atrapando, esta función no hace nada.


La función gl_trap_signal() le permite agregar una nueva señal
    a la lista que gl_get_line() atrapa, o modificar cómo responde




gl_trap_signal


The function gl_trap_signal() tells the GetLine library
    that it should trap a particular signal, and what to do with it.


  int gl_trap_signal(GetLine *gl, int signo, unsigned flags,
                     GlAfterSignal after, int errno_value);


El argumento signo es el número de la señal que desea que
    sea interceptada. El argumento flags es un conjunto de indicadores
    que determinan el entorno en el que se invoca el manejador de señales de la
    aplicación, el argumento after indica a gl_get_line() qué
    hacer después de que retorne el manejador de señales de la aplicación, y
    errno_value indica a gl_get_line() qué establecer en
    errno si se le indica que aborte.


El argumento flags es una operación OR a nivel de bits de
    cero o más de los siguientes enumeradores:


  GLS_RESTORE_SIG  -  Restaurar el entorno de señales del
                      llamador mientras se maneja la
                      señal.
  GLS_RESTORE_TTY  -  Restaurar los ajustes del terminal del
                      llamador mientras se maneja la
                      señal.
  GLS_RESTORE_LINE -  Mover el cursor al inicio de la línea
                      siguiente a la línea de entrada antes
                      de invocar el manejador de señales de
                      la aplicación.
  GLS_REDRAW_LINE  -  Redibujar la línea de entrada cuando el
                      manejador de señales de la aplicación
                      retorne.
  GLS_UNBLOCK_SIG  -  Normalmente, si el programa que llama tiene
                      una señal bloqueada (ver man sigprocmask),
                      gl_get_line() no intercepta esa
                      señal. Este indicador le dice a
                      gl_get_line() que intercepte la señal y la
                      desbloquee durante la duración de la
                      llamada a gl_get_line().
  GLS_DONT_FORWARD -  Si se incluye este indicador, la señal
                      no será reenviada al manejador de
                      señales del programa que llama.


Dos combinaciones de indicadores comúnmente útiles también se
    enumeran de la siguiente manera:


  GLS_RESTORE_ENV   = GLS_RESTORE_SIG | GLS_RESTORE_TTY |
                      GLS_REDRAW_LINE
  GLS_SUSPEND_INPUT = GLS_RESTORE_ENV | GLS_RESTORE_LINE


Si su manejador de señales, o el manejador de señales predeterminado
    del sistema para esta señal, si no lo ha anulado, nunca escribe en el
    terminal, ni suspende o termina el programa que llama, entonces puede
    establecer de forma segura el argumento flags a 0.


Si su manejador de señales siempre escribe en el terminal, lee de
    él, o suspende o termina el programa, debe especificar el argumento
    flags como GL_SUSPEND_INPUT, para que:


1. El cursor no quede en medio de la línea de entrada.
2. Para que el usuario pueda escribir entrada y sea reflejada.
3. Para que no necesite terminar cada línea de salida con
   \r\n, en lugar de solo \n.


La combinación GL_RESTORE_ENV es la misma que
    GL_SUSPEND_INPUT, excepto que no mueve el cursor, y si su manejador de
    señales no lee ni escribe nada en el terminal, el usuario no verá ninguna
    indicación visible de que se atrapó una señal. Esto puede ser útil si tiene
    un manejador de señales que solo escribe ocasionalmente en el terminal, donde
    usar GL_SUSPEND_LINE causaría que la línea de entrada se duplique
    innecesariamente cuando no se ha escrito nada en el terminal. Dicho manejador
    de señales, cuando sí escribe en el terminal, debe asegurarse de comenzar una
    nueva línea al inicio de su primera escritura, escribiendo una nueva línea
    antes de retornar. Si la señal llega mientras el usuario está ingresando una
    línea que solo ocupa una línea del terminal, o si el cursor está en la última
    línea del terminal de una línea de entrada más larga, esto tendrá el mismo
    efecto que GL_SUSPEND_INPUT. De lo contrario, comenzará a escribir en
    una línea que ya contiene parte de la línea de entrada mostrada. Esto no causa
    ningún daño, pero se ve un poco feo, por lo que la combinación
    GL_SUSPEND_INPUT es mejor si sabe que siempre va a escribir en el
    terminal.


El argumento after, que determina qué hace
    gl_get_line() después de que retorna el manejador de señales de la
    aplicación (si retorna), puede tomar cualquiera de los siguientes
    valores:


  GLS_RETURN   - Retornar la línea de entrada completada, tal
                 como si el usuario hubiera presionado la
                 tecla de retorno.
  GLS_ABORT    - Hacer que gl_get_line() aborte. Cuando
                 esto sucede, gl_get_line() retorna
                 NULL, y una llamada posterior a
                 gl_return_status() retornará
                 GLR_SIGNAL. Tenga en cuenta que si la
                 aplicación necesita que errno siempre
                 tenga un valor significativo cuando
                 gl_get_line() retorna NULL,
                 la función de callback debe establecer
                 errno apropiadamente.
  GLS_CONTINUE - Reanudar la edición de la línea de comandos.


El argumento errno_value está destinado a ser combinado con
    la opción GLS_ABORT, indicándole a gl_get_line() qué
    establecer en la variable estándar errno antes de retornar
    NULL al programa que llama. Sin embargo, también puede usarse con la
    opción GL_RETURN, en caso de que desee tener una forma de distinguir
    entre una línea de entrada que se ingresó usando la tecla de retorno, y una
    que se ingresó por la recepción de una señal.






MANEJO FIABLE DE SEÑALES


El manejo de señales es sorprendentemente difícil de hacer de manera
    fiable sin condiciones de carrera. En gl_get_line() se ha tenido
    mucho cuidado para permitir que las aplicaciones realicen un manejo fiable de
    señales alrededor de gl_get_line(). Esta sección explica cómo
    aprovechar esto.


Como ejemplo de los problemas que pueden surgir si la aplicación no
    está escrita correctamente, imagine que una aplicación tiene un manejador de
    señales SIGINT que establece una bandera global. Ahora suponga que la
    aplicación prueba esta bandera justo antes de invocar gl_get_line().
    Si una señal SIGINT se recibe en la pequeña ventana de tiempo entre la
    declaración que prueba el valor de esta bandera y la declaración que llama a
    gl_get_line(), entonces gl_get_line() no verá la señal y no
    será interrumpida. Como resultado, la aplicación no podrá responder a la
    señal hasta que el usuario termine de ingresar la línea de entrada y
    gl_get_line() retorne. Dependiendo de la aplicación, esto puede ser o
    no un desastre, pero como mínimo desconcertaría al usuario.


La forma de evitar tales problemas es hacer lo siguiente.


1. Si es necesario, utilice la función gl_trap_signal() para
    configurar gl_get_line() para que aborte cuando se atrapen
    señales importantes.


2. Configure gl_get_line() de tal manera que si alguna de las
    señales que atrapa está bloqueada cuando se llama a gl_get_line(),
    serán desbloqueadas automáticamente durante los momentos en que
    gl_get_line() esté esperando E/S. Esto se puede hacer ya sea por
    señal, llamando a la función gl_trap_signal() y especificando el
    atributo GLS_UNBLOCK de la señal, o globalmente llamando a la
    función gl_catch_blocked().


     void gl_catch_blocked(GetLine *gl);


Esta función simplemente agrega el atributo GLS_UNBLOCK a
    todas las señales que actualmente está configurada para interceptar.


3. Justo antes de llamar a gl_get_line(), bloquee la entrega
    de todas las señales que gl_get_line() está configurada para
    interceptar. Esto se puede hacer usando la función POSIX sigprocmask()
    en conjunto con la función gl_list_signals().


      int gl_list_signals(GetLine *gl, sigset_t *set);


Esta función retorna el conjunto de señales que actualmente está
    configurada para atrapar en el argumento set, que está en el formato
    requerido por sigprocmask().


4. En el ejemplo, ahora se probaría la bandera global que el manejador
    de señales establece, sabiendo que ahora no hay peligro de que esta bandera
    se establezca nuevamente hasta que gl_get_line() desbloquee sus
    señales mientras realiza E/S.


5. Finalmente gl_get_line() retorna, ya sea porque se atrapó
    una señal, ocurrió un error, o el usuario terminó de ingresar su línea de
    entrada.


6. Ahora se verificaría nuevamente la bandera global de señales, y si
    está establecida, se respondería a ella y se pondría la bandera a cero.


7. Use sigprocmask() para desbloquear las señales que se
    bloquearon en el paso 3.


La misma técnica se puede usar alrededor de ciertas funciones POSIX
    conscientes de señales, como sigsetjmp() y sigsuspend(), y en
    particular, la primera de estas dos funciones se puede usar en conjunto con
    siglongjmp() para implementar el manejo de señales libre de condiciones
    de carrera alrededor de otras llamadas de sistema de larga duración. La forma
    de hacer esto se explica a continuación, mostrando cómo gl_get_line()
    logra interceptar señales de manera fiable alrededor de llamadas a funciones
    como read() y select() sin condiciones de carrera.


Lo primero que hace gl_get_line(), cada vez que se llama, es
    utilizar la función POSIX sigprocmask() para bloquear la entrega de
    todas las señales que actualmente está configurada para atrapar. Esto es
    redundante si la aplicación ya las ha bloqueado, pero no causa daño. Deshace
    este paso justo antes de retornar.


Cada vez que gl_get_line() necesita llamar a read() o
    select() para esperar la entrada del usuario, primero llama a la
    función POSIX sigsetjmp(), asegurándose de especificar un valor no
    cero para su argumento savesigs. La razón del último argumento se
    hará clara en breve.


Si sigsetjmp() retorna cero, gl_get_line() hace lo
    siguiente.


a. Utiliza la función POSIX sigaction() para registrar
   un manejador de señales temporal para todas las señales que
   está configurada para atrapar. Este manejador de señales hace
   dos cosas.
   1. Registra el número de la señal que se recibió
      en una variable a nivel de archivo.
   2. Luego llama a la función POSIX siglongjmp()
      usando el búfer que se pasó a sigsetjmp() como
      su primer argumento, y un valor no cero para su
      segundo argumento.
   Cuando este manejador de señales se registra, el miembro
   sa_mask del argumento struct sigaction act de la
   llamada a sigaction() se configura para contener todas
   las señales que gl_get_line() está atrapando. Esto
   asegura que solo una señal será atrapada a la vez por nuestro
   manejador de señales, lo que a su vez asegura que múltiples
   instancias de nuestro manejador de señales no se pisen entre
   sí.
b. Ahora que el manejador de señales ha sido configurado,
   gl_get_line() desbloquea todas las señales que está
   configurada para atrapar.
c. Luego llama a las llamadas al sistema read() o
   select() para esperar la entrada del teclado.
d. Si esta llamada al sistema retorna (es decir, no se recibe
   ninguna señal), gl_get_line() vuelve a bloquear la
   entrega de las señales de interés.
e. Luego restaura los manejadores de señales que fueron
   desplazados por el que se acaba de instalar.


Alternativamente, si sigsetjmp() retorna un valor distinto de
    cero, esto significa que o



una de las señales atrapadas fue capturada mientras se ejecutaban los pasos anteriores. Cuando esto sucede, gl_get_line() hace lo 
siguiente.

Primero, tenga en cuenta que cuando una llamada a siglongjmp() hace que
    sigsetjmp() retorne, siempre que el argumento savesigs de
    sigsetjmp() fuera distinto de cero, como se especificó anteriormente, la máscara de proceso de señales se restaura a cómo estaba cuando se llamó a sigsetjmp(). Esta es la diferencia importante entre sigsetjmp() y el problemático
    setjmp() más antiguo, y es el ingrediente esencial que hace posible evitar condiciones de carrera en el manejo de señales. Debido a esto, se garantiza que todas las señales que bloqueamos antes de llamar a sigsetjmp() estén bloqueadas nuevamente tan pronto como se capture cualquier señal. Las siguientes instrucciones, que se ejecutan a continuación, se garantiza por tanto que se ejecuten sin que se capturen más 
señales.

  función gl_query_char() para consultas de un solo carácter como

Cuando el usuario escribe un carácter, gl_query_char() lo muestra a la derecha del mensaje, inicia una nueva línea, y luego devuelve el carácter al programa que lo llama. El valor de retorno de la función es el carácter que fue escrito. Si la lectura tuvo que abortarse por alguna razón,
    se devuelve EOF en su lugar. En este último caso, la aplicación puede llamar a la función previamente 
documentada

gl_return_status() para averiguar qué salió mal. Esto podría haber sido, por ejemplo, la recepción de una señal, o el temporizador opcional de inactividad activándose. Si el usuario simplemente presiona intro, se sustituye el valor del argumento defchar. Esto significa que cuando el usuario presiona retorno o intro, el carácter especificado en
    defchar se muestra después del mensaje, como si el usuario lo hubiera escrito, así como se devuelve a la aplicación que lo llama. Si tal reemplazo no es importante, simplemente pase '0 como el va

Si el carácter ingresado es un carácter no imprimible, se muestra simbólicamente. MOSTRANDO TEXTO DINÁMICAMENTE


Entre llamadas a gl_get_line(), la función
    gl_display_text() proporciona una forma conveniente de mostrar
    párrafos de texto, justificados a la izquierda y divididos en una o más líneas
    de terminal según las restricciones del ancho actual de la terminal. Ejemplos
    del uso de esta función se pueden encontrar en los programas de demostración,
    donde se utiliza para mostrar introducciones. En esos ejemplos, también se
    ilustra el uso avanzado de prefijos, sufijos y líneas de relleno opcionales
    para dibujar un cuadro alrededor del texto.


  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string);


Si gl no está actualmente conectado a una terminal, por
    ejemplo, si la salida de un programa que usa gl_get_line() se está
    canalizando a otro programa o se redirige a un archivo, entonces se usa el
    valor del parámetro def_width como el ancho de la terminal.


El argumento indentation especifica el número de caracteres
    a utilizar para indentar cada línea de salida. El argumento fill_char
    especifica el carácter que se utilizará para realizar esta indentación.


El argumento prefix puede ser NULL, o ser una cadena
    para colocar al principio de cada nueva línea (después de cualquier
    indentación). De manera similar, el argumento suffix puede ser
    NULL, o ser una cadena para colocar al final de cada línea. El sufijo
    se coloca al ras del borde derecho de la terminal, y cualquier espacio entre
    su primer carácter y la última palabra de esa línea se rellena con el
    carácter especificado a través del argumento fill_char. Normalmente,
    el carácter de relleno es un espacio.


El argumento start le indica a
    gl_display_text() cuántos caracteres ya se han escrito en la línea de
    terminal actual, y por lo tanto le indica el índice de la columna inicial
    del cursor. Dado que el valor de retorno de gl_display_text() es el
    índice de la columna final del cursor, al pasar el valor de retorno de una
    llamada al argumento start de la siguiente llamada, se puede componer
    un párrafo que se divide entre más de una cadena llamando a
    gl_display_text() para cada porción sucesiva del párrafo. Tenga en
    cuenta que son necesarios caracteres de nueva línea literales al final de
    cada párrafo para forzar el inicio de una nueva línea.


En caso de error, gl_display_text() devuelve -1.

JUEGOS DE CARACTERES INTERNACIONALES


Desde la versión 1.4.0 de libtecla, gl_get_line() es
    limpio de 8 bits. Esto significa que todos los caracteres de 8 bits que son
    imprimibles en la configuración regional actual del usuario se muestran ahora
    literalmente y se incluyen en la línea de entrada devuelta. Suponiendo que el
    programa que llama contiene correctamente una llamada como la siguiente,


  setlocale(LC_CTYPE, "");


entonces la configuración regional actual se determina por la primera
    de las variables de entorno LC_CTYPE, LC_ALL y LANG, que
    se encuentre que contenga un nombre de configuración regional válido. Si
    ninguna de estas variables está definida, o si el programa omite llamar a
    setlocale, entonces se utiliza la configuración regional predeterminada
    C, que es US 7-bit ASCII. En la mayoría de las plataformas tipo unix,
    puede obtener una lista de configuraciones regionales válidas escribiendo el
    comando:


  locale -a


en el prompt del shell. Puede encontrar más documentación sobre cómo
    el usuario puede usar esto para ingresar caracteres internacionales en la
    página del manual tecla(7).






SEGURIDAD DE HILOS


En un programa multihilo, debe usar la versión libtecla_r.a de la
    biblioteca. Esta utiliza versiones reentrantes de las funciones del sistema,
    cuando están disponibles. Desafortunadamente, ni terminfo ni termcap fueron
    diseñados para ser reentrantes, por lo que no puede usar de forma segura las
    funciones del módulo getline en múltiples hilos (puede usar los módulos
    separados de expansión de archivos y finalización de palabras en múltiples
    hilos, ver las páginas de manual correspondientes para más detalles). Sin
    embargo, debido al uso de funciones reentrantes POSIX para buscar directorios
    personales, etc., es seguro usar este módulo desde un solo hilo de un
    programa multihilo, siempre que sus otros hilos no utilicen ninguna función
    de termcap o terminfo.
