PARÁMETROS

location

Especifica la ubicación de la variable uniforme que se va a modificar.

count

Para los comandos de vector (glUniform*v), especifica el número de elementos que se van a modificar. Esto debe ser 1 si la variable uniforme de destino no es un array, y 1 o más si es un array.

Para los comandos de matriz (glUniformMatrix*), especifica el número de matrices que se van a modificar. Esto debe ser 1 si la variable uniforme de destino no es un array de matrices, y 1 o más si es un array de matrices.

transpose

Para los comandos de matriz, especifica si se debe transponer la matriz al cargar los valores en la variable uniforme.

v0, v1, v2, v3

Para los comandos escalares, especifica los nuevos valores que se usarán para la variable uniforme especificada.

value

Para los comandos de vector y matriz, especifica un puntero a un array de count valores que se usarán para actualizar la variable uniforme especificada.

DESCRIPCIÓN

glUniform modifica el valor de una variable uniforme o de un array de variables uniformes. La ubicación de la variable uniforme que se va a modificar se especifica mediante location, que debe ser un valor devuelto por glGetUniformLocation(). glUniform opera sobre el objeto de programa que se hizo parte del estado actual al llamar a glUseProgram().

Los comandos glUniform{1|2|3|4}{f|i|ui} se utilizan para cambiar el valor de la variable uniforme especificada por location usando los valores pasados como argumentos. El número especificado en el comando debe coincidir con el número de componentes en el tipo de datos de la variable uniforme especificada (por ejemplo, 1 para float, int, unsigned int, bool; 2 para vec2, ivec2, uvec2, bvec2, etc.). El sufijo f indica que se están pasando valores de punto flotante; el sufijo i indica que se están pasando valores enteros; el sufijo ui indica que se están pasando valores enteros sin signo, y este tipo también debe coincidir con el tipo de datos de la variable uniforme especificada. Las variantes i de esta función deben usarse para proporcionar valores para variables uniformes definidas as int, ivec2, ivec3, ivec4, o matrices de estos. Las variantes ui de esta función deben usarse para proporcionar valores para variables uniformes definidas como unsigned int, uvec2, uvec3, uvec4, o matrices de estas. Las variantes f deben usarse para proporcionar valores para variables uniformes de tipo float, vec2, vec3, vec4, o matrices de estas. Cualquiera de las variantes i, ui o f puede usarse para proporcionar valores para variables uniformes de tipo bool, bvec2, bvec3, bvec4, o matrices de estas. La variable uniforme se establecerá en false si el valor de entrada es 0 o 0.0f, y se establecerá en true en caso contrario.

Todas las variables uniformes activas definidas en un objeto de programa se inicializan a 0 cuando el objeto de programa se enlaza correctamente. Conservan los valores que se les asignan mediante una llamada a glUniform hasta la siguiente operación de enlace exitosa en el objeto de programa, momento en el cual se inicializan nuevamente a 0.

Los comandos glUniform{1|2|3|4}{f|i|ui}v se pueden usar para modificar una variable uniforme única o una matriz de variables uniformes. Estos comandos pasan un recuento y un puntero a los valores que se cargan en una variable uniforme o una matriz de variables uniformes. Se debe usar un recuento de 1 si se modifica el valor de una variable uniforme única, y se puede usar un recuento de 1 o mayor para modificar una matriz completa o parte de una matriz. Al cargar n elementos comenzando en una posición arbitraria m en una matriz de variables uniformes, los elementos m + n - 1 en la matriz se reemplazarán con los nuevos valores. Si m + n - 1 es mayor que el tamaño de la matriz de variables uniformes, se ignorarán los valores de todos los elementos de la matriz posteriores al final de la matriz. El número especificado en el nombre del comando indica el número de componentes para cada elemento en value, y debe coincidir con el número de componentes del tipo de dato de la variable uniforme especificada (por ejemplo, 1 para float, int, bool; 2 para vec2, ivec2, bvec2, etc.). El tipo de dato especificado en el nombre del comando debe coincidir con el tipo de dato de la variable uniforme especificada, como se describió anteriormente para glUniform{1|2|3|4}{f|i|ui}.

Para las matrices de variables uniformes, cada elemento de la matriz se considera del tipo indicado en el nombre del comando (por ejemplo, glUniform3f o glUniform3fv se pueden usar para cargar una matriz de variables uniformes de tipo vec3). El número de elementos de la matriz de variables uniformes que se modificarán se especifica mediante count

Los comandos glUniformMatrix{2|3|4|2x3|3x2|2x4|4x2|3x4|4x3}fv se utilizan para modificar una matriz o una matriz de matrices. Los números en el nombre del comando se interpretan como la dimensionalidad de la matriz. El número 2 indica una matriz de 2 × 2 (es decir, 4 valores), el número 3 indica una matriz de 3 × 3 (es decir, 9 valores) y el número 4 indica una matriz de 4 × 4 (es decir, 16 valores). La dimensionalidad de matrices no cuadradas es explícita, siendo el primer número el número de columnas y el segundo número el número de filas. Por ejemplo, 2x4 indica una matriz de 2 × 4 con 2 columnas y 4 filas (es decir, 8 valores). Si transpose es GL_FALSE, cada matriz se supone que se suministra en orden de columna principal. Si transpose es GL_TRUE, cada matriz se supone que se suministra en orden de fila principal. El argumento count indica el número de matrices que se van a pasar. Se debe usar un recuento de 1 si se modifica el valor de una matriz única, y se puede usar un recuento mayor que 1 para modificar una matriz de matrices.

NOTAS

glUniform1i y glUniform1iv son las únicas dos funciones que se pueden usar para cargar variables uniformes definidas como tipos sampler. Cargar samplers con cualquier otra función resultará en un error GL_INVALID_OPERATION.

Si count es mayor que 1 y la variable uniforme indicada no es una matriz, se genera un error GL_INVALID_OPERATION y la variable uniforme especificada permanecerá sin cambios.

Aparte de las excepciones anteriores, si el tipo y el tamaño de la variable uniforme tal como se definen en el shader no coinciden con el tipo y el tamaño especificados en el nombre del comando utilizado para cargar su valor, se generará un error GL_INVALID_OPERATION y la variable uniforme especificada permanecerá sin cambios.

Si location es un valor distinto de -1 y no representa una ubicación uniforme válida en el objeto de programa actual, se generará un error y no se realizarán cambios en el almacenamiento de la variable uniforme del objeto de programa actual. Si location es igual a -1, los datos proporcionados se ignorarán silenciosamente y la variable uniforme especificada no se modificará.

ERRORES

Se genera GL_INVALID_OPERATION si no hay ningún objeto de programa actual.

Se genera GL_INVALID_OPERATION si el tamaño de la variable uniforme declarada en el shader no coincide con el tamaño indicado por el comando glUniform.

Se genera GL_INVALID_OPERATION si se utiliza una de las variantes de entero con signo o sin signo de esta función para cargar una variable uniforme de tipo float, vec2, vec3, vec4, o una matriz de estas, o si se utiliza una de las variantes de punto flotante de esta función para cargar una variable uniforme de tipo int, ivec2, ivec3, ivec4, unsigned int, uvec2, uvec3, uvec4, o una matriz de estas.

Se genera GL_INVALID_OPERATION si se utiliza una de las variantes de entero con signo de esta función para cargar una variable uniforme de tipo unsigned int, uvec2, uvec3, uvec4, o una matriz de estas.

Se genera GL_INVALID_OPERATION si se utiliza una de las variantes de entero sin signo de esta función para cargar una variable uniforme de tipo int, ivec2, ivec3, ivec4, o una matriz de estas.

Se genera GL_INVALID_OPERATION si location es una ubicación uniforme inválida para el objeto de programa actual y location no es igual a -1.

Se genera GL_INVALID_VALUE si count es menor que 0.

Se genera GL_INVALID_OPERATION si count es mayor que 1 y la variable uniforme indicada no es una variable de matriz.

Se genera GL_INVALID_OPERATION si se carga un sampler utilizando un comando que no sea glUniform1i y glUniform1iv.

glUniformMatrix3x2fv(3G)

GLAPI manual page

NAME

glUniformMatrix3x2fv, glUniformMatrix4x2fv, glUniformMatrix2x3fv, glUniformMatrix4x3fv, glUniformMatrix2x4fv, glUniformMatrix3x4fv — set uniform matrix variables

C SPECIFICATION

void glUniformMatrix2x3fv(GLint location, GLsizei count, GLboolean transpose,
                          const GLfloat *value);
void glUniformMatrix4x2fv(GLint location, GLsizei count, GLboolean transpose,
                          const GLfloat *value);
void glUniformMatrix2x3fv(GLint location, GLsizei count, GLboolean transpose,
                          const GLfloat *value);
void glUniformMatrix4x3fv(GLint location, GLsizei count, GLboolean transpose,
                          const GLfloat *value);
void glUniformMatrix2x4fv(GLint location, GLsizei count, GLboolean transpose,
                          const GLfloat *value);
void glUniformMatrix3x4fv(GLint location, GLsizei count, GLboolean transpose,
                          const GLfloat *value);

PARAMETERS

location
Specifies the uniform variable location.
count
Specifies the number of matrices that will be downloaded and updated in the uniform variable. For example, if the uniform variable declared as `uniform mat2x3 myMatrix[2];` in the shader, then `count` should be 2.
transpose
Specifies whether to transpose the matrix when it is received by the GL server. `GL_FALSE` indicates that the matrix is loaded in its specified order, and `GL_TRUE` indicates that it should be transposed. This parameter is ignored if the underlying OpenGL implementation does not support matrix transpose for the specified uniform type.
value
Specifies a pointer to an array of count values that will be used to update the specified uniform variable.

DESCRIPTION

glUniformMatrix*fv functions set the value of a uniform variable in the current active shader program. These functions can only be used to update uniforms of type matrix.

The names of the functions indicate the dimensions of the matrices they are used to set. For example, glUniformMatrix2x3fv is used to set uniform variables that are 2x3 matrices. The f indicates that the data is specified as floating-point numbers, and the v indicates that the data is passed as a vector (an array).

The transpose parameter is ignored if the OpenGL implementation does not support the transpose of the specified matrix size. In such cases, the matrix is loaded as is.

To use these functions, you must first obtain the location of the uniform variable within the shader program using glGetUniformLocation.

NOTES

These functions are available only if the GLSL version is 1.20 or higher.

For non-square matrices, the behaviour is undefined if the transpose parameter is set to GL_TRUE.

ERRORS

A GL error is generated if the uniform variable indicated by location is not of a type that can be set by glUniformMatrix*fv, or if the number of elements in value is not compatible with the size of the uniform variable.

ASSOCIATED GETS

glGetUniformfv(), glGetUniformiv(), glGetUniformLocation()
