GLINVALIDATEFRAMEBUF(3G) [FIXME: manual] GLINVALIDATEFRAMEBUF(3G)

NOMBRE

glInvalidateFramebuffer, glInvalidateNamedFramebufferData - invalidan el contenido de uno o todos los adjuntos de un framebuffer

ESPECIFICACIÓN C

void glInvalidateFramebuffer(GLenum target, GLsizei numAttachments, const GLenum * attachments);

void glInvalidateNamedFramebufferData(GLuint framebuffer, GLsizei numAttachments, const GLenum *attachments);

PARÁMETROS

target

Especifica el destino al que está conectado el objeto de framebuffer para glInvalidateFramebuffer.

framebuffer

Especifica el nombre del objeto de framebuffer para glInvalidateNamedFramebufferData.

numAttachments

Especifica el número de entradas en la matriz attachments.

attachments

Especifica un puntero a una matriz que identifica los adjuntos a invalidar.

DESCRIPCIÓN

glInvalidateFramebuffer y glInvalidateNamedFramebufferData invalidan todo el contenido de un conjunto especificado de adjuntos de un framebuffer.

Para glInvalidateFramebuffer, el objeto de framebuffer es el que está conectado a target. target debe ser GL_FRAMEBUFFER, GL_READ_FRAMEBUFFER o GL_DRAW_FRAMEBUFFER. GL_FRAMEBUFFER es equivalente a GL_DRAW_FRAMEBUFFER. Los framebuffers predeterminados también pueden ser invalidados si están conectados a target.

Para glInvalidateNamedFramebufferData, framebuffer es el nombre del objeto de framebuffer. Si framebuffer es cero, se ve afectado el framebuffer de dibujo predeterminado.

El conjunto de adjuntos cuyo contenido se va a invalidar se especifica en la matriz attachments, que contiene numAttachments elementos.

Si el framebuffer especificado es un objeto de framebuffer, cada elemento de attachments debe ser uno de GL_DEPTH_ATTACHMENT, GL_STENCIL_ATTACHMENT, GL_DEPTH_STENCIL_ATTACHMENT, o GL_COLOR_ATTACHMENTi, donde i está entre cero y el valor de GL_MAX_FRAMEBUFFER_ATTACHMENTS menos uno.

Si el framebuffer especificado es un framebuffer predeterminado, cada elemento de attachments debe ser uno de GL_FRONT_LEFT, GL_FRONT_RIGHT, GL_BACK_LEFT, GL_BACK_RIGHT, GL_AUXi, GL_ACCUM, GL_COLOR, GL_DEPTH, o GL_STENCIL. GL_COLOR se trata como GL_BACK_LEFT para un contexto de doble búfer y GL_FRONT_LEFT para un contexto de búfer único. Los otros adjuntos identifican el búfer específico correspondiente.

Todo el contenido de cada adjunto especificado se vuelve indefinido después de la ejecución de glInvalidateFramebuffer o glInvalidateNamedFramebufferData.

Si el objeto de framebuffer no está completo, glInvalidateFramebuffer y glInvalidateNamedFramebufferData pueden ser ignorados. Esto no es un error.

ERRORES

Se genera GL_INVALID_ENUM por glInvalidateFramebuffer si target no es uno de los destinos de framebuffer aceptados.

Se genera GL_INVALID_OPERATION por glInvalidateNamedFramebufferData si framebuffer no es cero o el nombre de un objeto de framebuffer existente.

Se genera GL_INVALID_VALUE si numAttachments es negativo.

Se genera GL_INVALID_ENUM si algún elemento de attachments no es uno de los puntos de adjunto de framebuffer aceptados, como se describe anteriormente.

Se genera GL_INVALID_OPERATION si un elemento de attachments es GL_COLOR_ATTACHMENTm donde m es mayor o igual al valor de GL_MAX_COLOR_ATTACHMENTS.

GETS ASOCIADOS

glGet() con el argumento GL_MAX_COLOR_ATTACHMENTS
