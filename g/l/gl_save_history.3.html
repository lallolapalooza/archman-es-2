DESCRIPCIÓ

N

La función gl_get_line() es parte de la biblioteca tecla (véase la página del manual libtecla(3)). Si el usuario está escribiendo en un terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de unix. Además de la edición simple de línea de comandos, admite el recuerdo de líneas de comandos introducidas previamente, la completación con TAB de nombres de archivos y la expansión en línea de comodines de nombres de archivos. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario se puede encontrar en la página del manual tecla(7). a programadores interesados en usar
esta biblioteca en su aplicación.

UN

EJEMPLO

Lo siguiente muestra un ejemplo completo de cómo usar la función gl_get_line() para obtener entrada del

usuario: 
  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que el usuario escribió */
    GetLine *gl;   /* El objeto recurso de gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* del juego de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("You typed: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
}

En el ejemplo, primero se crean los recursos necesarios por la función gl_get_line() llamando a new_GetLine(). Esto asigna la memoria utilizada en las llamadas subsecuentes a la función gl_get_line(), incluyendo el búfer de historial para registrar las líneas introducidas previamente. Luego se leen una o más líneas del usuario, hasta que ocurra un error, o hasta que el usuario escriba exit. Finalmente, los recursos que fueron asignados por new_GetLine() se devuelven al sistema llamando a del_GetLine(). Nótese el uso del valor de retorno NULL de del_GetLine() para hacer gl NULL. Esta es una precaución de seguridad. Si el programa posteriormente intenta pasar gl a gl_get_line(), dicha función se quejará y devolverá un error

, en lugar de intentar usa
r el objeto recurso eliminado.

La función gl_get_line() puede ser llamada cualquier número de veces para leer entrada del usuario. El argumento gl debe haber sido devuelto previamente por una llamada a new_GetLine(). El argumento prompt debe ser una cadena normal terminada en NUL, especificando el prompt a presentar al usuario. Por defecto los prompts se muestran literalmente, pero si se habilitan con la función gl_prompt_style() (véase más adelante), los prompts pueden contener directivas para subrayar, cambiar a y de fuentes en negrita, o activar y desactivar el

Este debe ser -1 si desea que el cursor siga al último carácter de la línea de inicio. Si no desea precargar la línea de esta manera, envíe start_line como NULL, y establezca start_pos a -1. Tenga en cuenta que el puntero de línea devuelto por una llamada a gl_get_line() puede pasarse a la siguiente llamada a gl_get_line() a través de start_line. Esto permite que la aplicación tome la última línea introducida y, si contiene un error, la presente de nuevo al usuario para su reedición, con el cursor inicialmente posicionado donde se encontró el

error.

La función gl_get_line() devuelve un puntero a la línea introducida por el usuario, o NULL en caso de error o al final de la entrada. El puntero devuelto es parte del objeto recurso especificado gl, y por lo tanto no debe ser liberado por el llamador, ni asumirse que es inmutable de una llamada a la siguiente. Al leer de un usuario en una terminal, siempre habrá un carácter de salto de línea al final de la línea devuelta. Cuando la entrada estándar se toma de una tubería o de un archivo, de manera similar habrá un salto de línea a menos que la línea de entrada fuera demasiado larga para almacenarse en el búfer interno. En este último caso, debe llamar a gl_get_line() de nuevo para leer el resto de la línea. Tenga en cuenta que este comportamiento hace que gl_get_line() sea similar a fgets(). De hecho, cuando stdin no está conectado a una terminal,gl_get_line() simplemente llama a fget

s(

FUENTES ALTERNATIVAS DE

CONFIGURACIÓN

Como se mencionó anteriormente, de forma predeterminada los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. En algunas aplicaciones, sin embargo, este único medio de configuración es un problema. Esto es particularmente cierto en el software embebido, donde no hay un sistema de archivos del cual leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de asignaciones de teclas para emular una interfaz de teclado heredada. Para atender a tales casos, la siguiente función permite a la aplicación controlar de dónde se leen los datos de

configuración. 
  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file)
;

Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc del usuario, se lean de cualquiera o ninguno de: una cadena, un archivo de configuración específico de la aplicación y/o un archivo de configuración específico del usuario. Si esta función se llama antes de la primera llamada a gl_get_line(), el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line() se deshabilita, por lo que toda la configuración debe lograrse usando las fuentes de configuración especificadas con esta

función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados unos de otros en la cadena por caracteres de salto de línea incrustados. Si app_file != NULL entonces se interpreta como la ruta de archivo completa de un archivo de configuración específico de la aplicación. Si user_file != NULL entonces se interpreta como la ruta de archivo completa de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente

llamada, 
  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc")
;

el argumento app_string hace que la aplicación llamante inicie en el modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso de la campana de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración de todo el sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario desde un archivo .teclarc opcional en el directorio de inicio del usuario. Tenga en cuenta que los argumentos se listan en orden ascendente de prioridad, con el contenido de app_string siendo potencialmente anulado por comandos en app_file, y los comandos en app_file siendo potencialmente anulados por comandos en user_file

.

Puede llamar a esta función tantas veces como sea necesario, siendo los resultados acumulativos, pero tenga en cuenta que las copias de cualquier nombre de archivo especificado a través de app_file y user_file se registran internamente para su uso posterior por la función read-init-files de enlace de teclas, así que si planea llamar a esta función varias veces, asegúrese de que la última llamada especifique los nombres de archivo que desea releer cuando el usuario solicite que los archivos de configuración sean

Podría, por ejemplo, apuntar a la tabla de símbolos de la cual se deben buscar los posibles completados. El argumento match_fn especifica la función de retorno a llamar. El tipo de función CplMatchFn está definido en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y prototipar funciones de retorno. SEGURIDAD EN ENTORNOS DE HILOS

MÚLTIPLES

En un programa de hilos múltiples, debe usar la versión libtecla_r.a de la biblioteca. Esta usa versiones reentrantes de las funciones del sistema, cuando están disponibles. Desafortunadamente, ni terminfo ni termcap fueron diseñados para ser reentrantes, po

r lo que no puede usar de forma segura las funciones del módulo getline en múltiples hilos (puede usar los módulos separados de expansión de archivos y finalización de palabras en múltiples hilos, vea las páginas de manual correspondientes para más detalles).
