PARÁMETROS

location

Especifica la ubicación de la variable uniforme a modificar.

count

Para los comandos de vector (glUniform*v), especifica el número de elementos que se van a modificar. Debe ser 1 si la variable uniforme de destino no es un array, y 1 o más si es un array.

Para los comandos de matriz (glUniformMatrix*), especifica el número de matrices que se van a modificar. Debe ser 1 si la variable uniforme de destino no es un array de matrices, y 1 o más si es un array de matrices.

transpose

Para los comandos de matriz, especifica si se debe transponer la matriz al cargar los valores en la variable uniforme.

v0, v1, v2, v3

Para los comandos escalares, especifica los nuevos valores que se utilizarán para la variable uniforme especificada.

value

Para los comandos de vector y matriz, especifica un puntero a un array de count valores que se utilizarán para actualizar la variable uniforme especificada.

DESCRIPCIÓN

glUniform modifica el valor de una variable uniforme o un array de variables uniformes. La ubicación de la variable uniforme a modificar se especifica mediante location, que debe ser un valor devuelto por glGetUniformLocation(). glUniform opera sobre el objeto de programa que se convirtió en parte del estado actual llamando a glUseProgram().

Los comandos glUniform{1|2|3|4}{f|i|ui} se utilizan para cambiar el valor de la variable uniforme especificada por location utilizando los valores pasados como argumentos. El número especificado en el comando debe coincidir con el número de componentes en el tipo de dato de la variable uniforme especificada (por ejemplo, 1 para float, int, unsigned int, bool; 2 para vec2, ivec2, uvec2, bvec2, etc.). El sufijo f indica que se están pasando valores de punto flotante; el sufijo i indica que se están pasando valores enteros; el sufijo ui indica que se están pasando valores enteros sin signo, y este tipo también debe coincidir con el tipo de dato de la variable uniforme especificada. Las variantes i de esta función deben usarse para proporcionar valores para variables uniformes definidas como int, ivec2, ivec3, ivec4, sampler*, lock*, o **bvec**. Los valores enteros proporcionados a glUniform*i se usan directamente para variables uniformes de tipo int. Los valores enteros proporcionados a glUniform*ui se usan directamente para variables uniformes de tipo unsigned int.

Los comandos glUniform*v son idénticos a los comandos escalares, excepto que toman un puntero a un array de count valores en lugar de valores individuales. Si la variable uniforme de destino es un array, cada uno de los count elementos del array se actualizará con los valores correspondientes del puntero. Si la variable uniforme de destino no es un array, el primer elemento del puntero se usará para actualizar el valor de la variable uniforme, y los demás elementos del puntero se ignorarán. El número de elementos en el array al que apunta value debe ser al menos count. Para glUniform1i y glUniform1ui, count debe ser 1. Para glUniform2i y glUniform2ui, count debe ser 1 o 2. Para glUniform3i y glUniform3ui, count debe ser 1, 2 o 3. Para glUniform4i y glUniform4ui, count debe ser 1, 2, 3 o 4.

Los comandos glUniformMatrix* se utilizan para actualizar las variables uniformes de tipo matriz. El argumento transpose indica si la matriz se debe transponer antes de cargarla en la variable uniforme. Si transpose es GL_TRUE, la matriz se transpondrá. Si es GL_FALSE, no se transpondrá. Las matrices se pasan en memoria en orden de columna, lo que significa que los elementos de una columna se almacenan consecutivamente en memoria. El número de elementos en la matriz depende de las dimensiones especificadas en el nombre del comando. Por ejemplo, glUniformMatrix2fv espera una matriz de 2x2, que tiene 4 elementos. glUniformMatrix2x3fv espera una matriz de 2x3, que tiene 6 elementos. Si la variable uniforme de destino es un array de matrices, el argumento count especifica el número de matrices que se van a actualizar, y cada matriz en el array se actualizará con los valores correspondientes del puntero value. Si la variable uniforme de destino no es un array de matrices, count debe ser 1, y solo la primera matriz en el puntero value se utilizará para actualizar la variable uniforme.

Si la variable uniforme de destino se declara como un tipo entero (por ejemplo, int, ivec2, sampler2D) y se llama a glUniform*fv o glUniformMatrix*fv para actualizarla, los valores de punto flotante se truncarán al entero más cercano. Si la variable uniforme de destino se declara como un tipo sin signo (por ejemplo, unsigned int, uvec2) y se llama a glUniform*fv o glUniform*iv para actualizarla, los valores se interpretarán como si estuvieran en el formato de punto flotante o entero sin signo, respectivamente.

Si location es el valor devuelto por glGetUniformLocation() para una variable uniforme que no existe en el objeto de programa actual, o si el objeto de programa actual no es un programa, estas funciones no harán nada.

Si se llama a glUniform con un valor que no coincide con el tipo de la variable uniforme de destino (por ejemplo, llamar a glUniform3f en una variable de tipo vec2), el comportamiento es indefinido.

Si location corresponde a una variable uniforme de bloque, se producirá un error GL_INVALID_OPERATION.

ERRORES

GL_INVALID_OPERATION se genera si el objeto de programa actual no es un programa.

GL_INVALID_OPERATION se genera si location no es válido.

GL_INVALID_OPERATION se genera si location corresponde a una variable uniforme de bloque.

GL_INVALID_VALUE se genera si count es negativo.

GL_INVALID_VALUE se genera si count es mayor que la cantidad máxima de matrices o vectores que se pueden cargar en un programa de shader.

FUNCIONES ASOCIADAS

glGetUniformLocation(), glUseProgram(), glGetActiveUniformsiv(), glGetUniformfv(), glGetUniformiv().

ivec2, ivec3, ivec4, o arrays de estos. Las variantes ui de esta función deben usarse para proporcionar valores para variables uniformes definidas como unsigned int, uvec2, uvec3, uvec4, o arrays de estos. Las variantes f deben usarse para proporcionar valores para variables uniformes de tipo float, vec2, vec3, vec4, o arrays de estos. Cualquiera de las variantes i, ui o f puede usarse para proporcionar valores para variables uniformes de tipo bool, bvec2, bvec3, bvec4, o arrays de estos. La variable uniforme se establecerá en false si el valor de entrada es 0 o 0.0f, y se establecerá en true en caso contrario.

Todas las variables uniformes activas definidas en un objeto de programa se inicializan a 0 cuando el objeto de programa se enlaza correctamente. Conservan los valores que se les asignan mediante una llamada a glUniform hasta la siguiente operación de enlace exitosa en el objeto de programa, momento en el cual se vuelven a inicializar a 0.

Los comandos glUniform{1|2|3|4}{f|i|ui}v se pueden usar para modificar una variable uniforme única o un array de variables uniformes. Estos comandos pasan un recuento y un puntero a los valores que se cargarán en una variable uniforme o un array de variables uniformes. Se debe usar un recuento de 1 si se modifica el valor de una variable uniforme única, y se puede usar un recuento de 1 o superior para modificar un array completo o parte de un array. Al cargar n elementos a partir de una posición arbitraria m en un array de variables uniformes, los elementos m + n - 1 en el array se reemplazarán con los nuevos valores. Si m + n - 1 es mayor que el tamaño del array de variables uniformes, se ignorarán los valores para todos los elementos del array que queden fuera del final del array. El número especificado en el nombre del comando indica el número de componentes para cada elemento en value, y debe coincidir con el número de componentes en el tipo de datos de la variable uniforme especificada (por ejemplo, 1 para float, int, bool; 2 para vec2, ivec2, bvec2, etc.). El tipo de datos especificado en el nombre del comando debe coincidir con el tipo de datos de la variable uniforme especificada, como se describió anteriormente para glUniform{1|2|3|4}{f|i|ui}.

Para los arrays de variables uniformes, cada elemento del array se considera del tipo indicado en el nombre del comando (por ejemplo, glUniform3f o glUniform3fv se pueden usar para cargar un array de variables uniformes de tipo vec3). El número de elementos del array de variables uniformes que se modificarán se especifica mediante count

Los comandos glUniformMatrix{2|3|4|2x3|3x2|2x4|4x2|3x4|4x3}fv se utilizan para modificar una matriz o un array de matrices. Los números en el nombre del comando se interpretan como la dimensionalidad de la matriz. El número 2 indica una matriz de 2 × 2 (es decir, 4 valores), el número 3 indica una matriz de 3 × 3 (es decir, 9 valores), y el número 4 indica una matriz de 4 × 4 (es decir, 16 valores). La dimensionalidad de matrices no cuadradas es explícita, siendo el primer número el número de columnas y el segundo número el número de filas. Por ejemplo, 2x4 indica una matriz de 2 × 4 con 2 columnas y 4 filas (es decir, 8 valores). Si transpose es GL_FALSE, cada matriz se asume que se suministra en orden de columnas. Si transpose es GL_TRUE, cada matriz se asume que se suministra en orden de filas. El argumento count indica el número de matrices que se van a pasar. Se debe usar un recuento de 1 si se modifica el valor de una matriz única, y se puede usar un recuento mayor que 1 para modificar un array de matrices.

NOTAS

glUniform1i y glUniform1iv son las únicas dos funciones que pueden usarse para cargar variables uniformes definidas como tipos sampler. Cargar samplers con cualquier otra función resultará en un error GL_INVALID_OPERATION.

Si count es mayor que 1 y la variable uniforme indicada no es un array, se generará un error GL_INVALID_OPERATION y la variable uniforme especificada permanecerá sin cambios.

Aparte de las excepciones anteriores, si el tipo y el tamaño de la variable uniforme, tal como se definen en el shader, no coinciden con el tipo y el tamaño indicados en el nombre del comando utilizado para cargar su valor, se generará un error GL_INVALID_OPERATION y la variable uniforme especificada permanecerá sin cambios.

Si location es un valor distinto de -1 y no representa una ubicación de variable uniforme válida en el objeto de programa actual, se generará un error y no se realizarán cambios en el almacenamiento de la variable uniforme del objeto de programa actual. Si location es igual a -1, los datos pasados serán ignorados silenciosamente y la variable uniforme especificada no se modificará.

ERRORES

Se genera GL_INVALID_OPERATION si no hay ningún objeto de programa actual.

Se genera GL_INVALID_OPERATION si el tamaño de la variable uniforme declarada en el shader no coincide con el tamaño indicado por el comando glUniform.

Se genera GL_INVALID_OPERATION si se utiliza una de las variantes de entero con signo o sin signo de esta función para cargar una variable uniforme de tipo float, vec2, vec3, vec4, o un array de estos, o si se utiliza una de las variantes de punto flotante de esta función para cargar una variable uniforme de tipo int, ivec2, ivec3, ivec4, unsigned int, uvec2, uvec3, uvec4, o un array de estos.

Se genera GL_INVALID_OPERATION si se utiliza una de las variantes de entero con signo de esta función para cargar una variable uniforme de tipo unsigned int, uvec2, uvec3, uvec4, o un array de estos.

Se genera GL_INVALID_OPERATION si se utiliza una de las variantes de entero sin signo de esta función para cargar una variable uniforme de tipo int, ivec2, ivec3, ivec4, o un array de estos.

Se genera GL_INVALID_OPERATION si location es una ubicación uniforme inválida para el objeto de programa actual y location no es igual a -1.

Se genera GL_INVALID_VALUE si count es menor que 0.

Se genera GL_INVALID_OPERATION si count es mayor que 1 y la variable uniforme indicada no es una variable de array.

Se genera GL_INVALID_OPERATION si un sampler se carga utilizando un comando distinto de glUniform1i y glUniform1iv.
