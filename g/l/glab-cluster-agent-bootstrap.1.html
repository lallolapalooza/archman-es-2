DESCRIPCIÓ

N

Inicializa un Agente de GitLab para Kubernetes (agentk) en un

proyecto.

El primer argumento debe ser el nombre del

agente.

Requiere que los comandos kubectl y flux estén accesibles a través de $PATH

.

Este comando consta de múltiples pasos

idempotentes:
1
.
Registrar el agente con el
proyecto.
2
.
Configurar el
agente.
3
.
Configurar un entorno con panel de control para el
agente.
4
.
Configurar un entorno con panel de control para FluxCD (si se usa --create-flux-envi
ronment).
5
.
Crear un t
oken para
el agente.
  • Si el agente ha alcanzado la cantidad máxima de tokens, se revoca el que lleva más tiempo sin usarse y se crea uno
    • nuevo.
  • Si el agente no ha al
    • canzado la cantidad m
áxima de tokens, se
crea uno nuevo.
6
.
Enviar el Secreto de Kubernetes que contiene el token al
clúster.
7
.
Crear los recursos HelmRepository y HelmRelease de
Flux.
8
.
Confirmar y enviar los recursos Helm de Flux creados a la ruta del
manifiesto.
9
.
Desencadenar la reconciliación de Flux del HelmRelease del Agente de GitLab (a menos que se use --no-r
econ

OPCIONE

S

--commit-author-email="noreply@glab.gitlab.com" El correo electrónico del autor de la confirmación de Git a utilizar. Entra en conflicto con la bandera --use-api-commit-author

.

--commit-author-name="glab" El nombre del autor de la confirmación de Git a utilizar. Entra en conflicto con la bandera --use-api-commit-author

.

--create-environment[=true] Crear un entorno para el Agente de

GitLab.

--create-flux-environment[=true] Crear un entorno para FluxCD. Afecta solo a la creación del entorno, no al uso de Flux en sí. Flux siempre es necesario para el proceso de

inicialización.

--environment-flux-resource-path="helm.toolkit.fluxcd.io/v2beta1/namespaces//helmreleases/" Ruta del recurso de Flux del entorno para el Agente de

GitLab.

--environment-name="/" Nombre del entorno para el Agente de

GitLab.

--environment-namespace="" Espacio de nombres de Kubernetes del entorno para el Agente de

GitLab.

--flux-environment-flux-resource-path="kustomize.toolkit.fluxcd.io/v1/namespaces/flux-system/kustomizations/flux-system" Ruta del recurso de Flux del entorno para

FluxCD.

--flux-environment-name="/" Nombre del entorno para

FluxCD.

--flux-environment-namespace="" Espacio de nombres de Kubernetes del entorno para

FluxCD.

--flux-source-name="flux-system" Nombre de la fuente de

Flux.

--flux-source-namespace="flux-system" Espacio de nombres de la fuente de

Flux.

--flux-source-type="git" Tipo de fuente de flux-system, como Git, OCI o

Helm.

--gitlab-agent-token-secret-name="gitlab-agent-token" Nombre del Secreto donde se almacena el token para el Agente de GitLab. Se asume helm-release-target-namespace como el espacio de nombres del

Secreto.

--helm-release-filepath="gitlab-agent-helm-release.yaml" Ruta del archivo dentro del proyecto del Agente de GitLab para confirmar el HelmRelease de

Flux.

--helm-release-name="gitlab-agent" Nombre del manifiesto HelmRelease de

Flux.

--helm-release-namespace="flux-system" Espacio de nombres del manifiesto HelmRelease de

Flux.

--helm-release-target-namespace="gitlab-agent" Espacio de nombres del despliegue del Agente de

GitLab.

--helm-release-values=[] Ruta local a los archivos values.yaml. Se pueden especificar múltiples archivos separados por comas o repitiendo la

bandera.

--helm-release-values-from=[] Referencia a un objeto de Kubernetes que contiene la clave de datos values.yaml en el formato '/', donde 'kind' debe ser uno de: (Secret, ConfigMap). Se pueden especificar múltiples referencias separadas por comas o repitiendo la

bandera.

--helm-repository-address="https://charts.gitlab.io" Dirección del

HelmRepository.

--helm-repository-filepath="gitlab-helm-repository.yaml" Ruta del archivo dentro del proyecto del Agente de GitLab para confirmar el HelmRepository de

Flux.

--helm-repository-name="gitlab" Nombre del manifiesto HelmRepository de

Flux.

--helm-repository-namespace="flux-system" Espacio de nombres del manifiesto HelmRepository de

Flux.

-b, --manifest-branch="" Rama a la que confirmar los Manifiestos de Flux. (por defecto, la rama predeterminada del

proyecto)

-p, --manifest-path="" Ubicación del directorio en el repositorio de Git para almacenar los recursos Helm del Agente de GitLab para

Kubernetes.

--no-reconcile[=false] No desencadenar la reconciliación de Flux para el recurso de Flux del Agente de GitLab para

Kubernetes.

--use-api-commit-author[=false] Al crear confirmaciones de Git usar el usuario de la solicitud de API autenticada. Entra en conflicto con las banderas --commit-author-name y --commit-author-emai

l
.

EJEMPL

O 
# Inicializar "my-agent" en la raíz del proyecto de Git en el directorio de trabajo actual, y desencadenar la reconciliación
$ glab cluster agent bootstrap my-agent
# Inicializar "my-agent" en "manifests/" del proyecto de Git en el directorio de trabajo actual, y desencadenar la reconciliación
# Especialmente útil cuando se usa "flux bootstrap gitlab --path manifests/".
# Asegúrese de que el "--path" del comando "flux bootstrap gitlab" coincida
# con el "--manifest-path" del comando "glab cluster agent bootstrap".
$ glab cluster agent bootstrap my-agent --manifest-path manifests/
# Inicializar "my-agent" en "manifests/" del proyecto de Git en el directorio de trabajo actual, y no desencadenar manualmente una reconciliación
$ glab cluster agent bootstrap my-agent --manifest-path manifests/ --no-reconcile
# Inicializar "my-agent" sin configurar un entorno
$ glab cluster agent bootstrap my-agent --create-environment=false
# Inicializar "my-agent" y configurar un entorno con nombre y espacio de nombres de Kubernetes personalizados
$ glab cluster agent bootstrap my-agent --environment-name production --environment-namespace default
# Inicializar "my-agent" sin configurar un entorno de FluxCD
$ glab cluster agent bootstrap my-agent --create-flux-environment=false
# Inicializar "my-agent" y configurar un entorno de FluxCD con nombre y espacio de nombres de Kubernetes personalizados
$ glab cluster agent bootstrap my-agent --flux-environment-name production-flux --flux-environment-namespace flux-system
# Inicializar "my-agent" y pasar valores adicionales del Gráfico de Helm de GitLab desde un archivo local
$ glab cluster agent bootstrap my-agent --helm-release-values values.yaml
# Inicializar "my-agent" y pasar valores adicionales del Gráfico de Helm de GitLab desde un ConfigMap de Kubernetes
$ glab cluster agent bootstrap my-agent --helm-release-values-from ConfigMap/agent-config
# Inicializar "my-agent" y confirmar con un usuario personalizado
$ glab cluster agent bootstrap my-agent --commit-author-name="Tanuki" --commit-author-email="tanuki@example.com"
# Inicializar "my-agent" con el usuario de la API autenticada
$ glab cluster agent bootstrap my-agent --use-api-commit-auth
