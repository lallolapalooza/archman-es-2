NOMBRE

glab-api - Realiza una solicitud autenticada a la API de GitLab.

SINOPSIS

glab api [flags]

DESCRIPCIÓN

Realiza una solicitud HTTP autenticada a la API de GitLab e imprime la respuesta. El argumento del endpoint debe ser una ruta de un endpoint de la API v4 de GitLab, o graphql para acceder a la API GraphQL de GitLab.

  • Documentación de la API REST de GitLab ⟨https://docs.gitlab.com/api/⟩
  • Documentación de GraphQL de GitLab ⟨https://docs.gitlab.com/api/graphql/⟩

Si el directorio actual es un directorio Git, utiliza el host autenticado de GitLab en el directorio actual. De lo contrario, se utilizará gitlab.com. Para anular el nombre de host de GitLab, use --hostname.

Estos valores de marcador de posición, cuando se usan en el argumento del endpoint, se reemplazan con valores del repositorio del directorio actual:

  • :branch
  • :fullpath
  • :group
  • :id
  • :namespace
  • :repo
  • :user
  • :username

Métodos: el método de solicitud HTTP predeterminado es GET, si no se agregan parámetros, y POST en caso contrario. Anule el método con --method.

Pase uno o más valores de --raw-field en formato clave=valor para agregar parámetros codificados en JSON al cuerpo de la solicitud POST.

El flag --field se comporta como --raw-field con conversión de tipo mágica basada en el formato del valor:

  • Los valores literales true, false, null y los números enteros se convierten a los tipos JSON apropiados.
  • Los valores de marcador de posición :namespace, :repo y :branch se completan con valores del repositorio del directorio actual.
  • Si el valor comienza con @, el resto del valor se interpreta como un nombre de archivo del cual leer el valor. Pase - para leer de la entrada estándar.

Para solicitudes GraphQL, todos los campos excepto query y operationName se interpretan como variables GraphQL.

El cuerpo de la solicitud sin procesar se puede pasar desde el exterior a través de un archivo especificado por --input. Pase - para leer de la entrada estándar. En este modo, los parámetros especificados con los flags --field se serializan en parámetros de consulta URL.

En el modo --paginate, se solicitan todas las páginas de resultados secuencialmente hasta que no queden más páginas de resultados. Para solicitudes GraphQL:

  • La consulta original debe aceptar una variable $endCursor: String.
  • La consulta debe obtener el conjunto de campos pageInfo{ hasNextPage, endCursor } de una colección.

OPCIONES

-F, --field=[] Agrega un parámetro de tipo inferido. Cambia el método HTTP predeterminado a "POST".

-H, --header=[] Agrega una cabecera de solicitud HTTP adicional.

--hostname="" El nombre de host de GitLab para la solicitud. Por defecto es 'gitlab.com' o el host autenticado en el directorio Git actual.

-i, --include[=false] Incluye las cabeceras de respuesta HTTP en la salida.

--input="" El archivo a usar como cuerpo para la solicitud HTTP.

-X, --method="GET" El método HTTP para la solicitud.

--paginate[=false] Realiza solicitudes HTTP adicionales para obtener todas las páginas de resultados.

-f, --raw-field=[] Agrega un parámetro de cadena.

--silent[=false] No imprime el cuerpo de la respuesta.

OPCIONES HEREDADAS DE COMANDOS PADRE

-h, --help[=false] Muestra la ayuda para este comando.

EJEMPLO

$ glab api projects/:fullpath/releases
$ glab api projects/gitlab-com%2Fwww-gitlab-com/issues
$ glab api issues --paginate
$ glab api graphql -f query="query { currentUser { username } }"
$ glab api graphql -f query='
  query {
    project(fullPath: "gitlab-org/gitlab-docs") {
      name
      forksCount
      statistics {
        wikiSize
      }
      issuesEnabled
      boards {
        nodes {
          id
          name
        }
      }
    }
  }
'
$ glab api graphql --paginate -f query='
  query($endCursor: String) {
    project(fullPath: "gitlab-org/graphql-sandbox") {
      name
      issues(first: 2, after: $endCursor) {
        edges {
          node {
            title
          }
        }
        pageInfo {
          endCursor
          hasNextPage
        }
      }
    }
  }'
