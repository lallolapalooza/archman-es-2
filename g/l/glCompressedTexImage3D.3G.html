DESCRIPCIÓ

N

El mapeo de texturas permite que los elementos de un arreglo de imágenes sean leídos por los

sombreadores.

glCompressedTexImage3D carga una imagen de textura tridimensional comprimida previamente definida y obtenida, si target es GL_TEXTURE_3D (véase glTexImage3D())

.

Si target es GL_TEXTURE_2D_ARRAY, data se trata como un arreglo de texturas 2D

comprimidas.

Si target es GL_PROXY_TEXTURE_3D o GL_PROXY_TEXTURE_2D_ARRAY, no se leen datos de data, pero todo el estado de la imagen de textura se recalcula, se comprueba su consistencia y se verifica contra las capacidades de la implementación. Si la implementación no puede manejar una textura del tamaño solicitado, establece todo el estado de la imagen en 0, pero no genera un error (véase glGetError()). Para consultar un arreglo de mipmap completo, use un nivel de arreglo de imagen mayor o igual a

1.

internalformat debe ser un formato de imagen comprimida conocido (como GL_RGTC) o un formato de textura comprimida especificado por una extensión. Cuando se carga una textura con glTexImage2D() usando un formato de textura comprimida genérico (por ejemplo, GL_COMPRESSED_RGB), GL selecciona una de sus extensiones que admiten texturas comprimidas. Para cargar la imagen de textura comprimida usando glCompressedTexImage3D, consulte el tamaño y el formato de la imagen de textura comprimida usando glGetTexLevelPara

meter().

Si un objeto de búfer con nombre distinto de cero está vinculado al objetivo GL_PIXEL_UNPACK_BUFFER (véase glBindBuffer()) mientras se especifica una imagen de textura, data se trata como un desplazamiento en bytes dentro del almacén de datos del objeto de

búfer.

Si los datos comprimidos están dispuestos en bloques de tamaño fijo de texels, se pueden usar los modos de almacenamiento de píxeles para seleccionar un subrectángulo de un rectángulo contenedor más grande. Estos modos de almacenamiento de píxeles funcionan de la misma manera que para glTexImage1D(). En la siguiente descripción, denótese por bs, bw, bh y bd los valores de los modos de almacenamiento de píxeles GL_UNPACK_COMPRESSED_BLOCK_SIZE, GL_UNPACK_COMPRESSED_BLOCK_WIDTH, GL_UNPACK_COMPRESSED_BLOCK_HEIGHT y GL_UNPACK_COMPRESSED_BLOCK_DEPTH, respectivamente. bs es el tamaño del bloque comprimido en bytes; bw, bh y bd son el ancho, el alto y la profundidad del bloque comprimido en

píxeles.

De forma predeterminada, los modos de almacenamiento de píxeles GL_UNPACK_ROW_LENGTH, GL_UNPACK_SKIP_ROWS, GL_UNPACK_SKIP_PIXELS, GL_UNPACK_IMAGE_HEIGHT y GL_UNPACK_SKIP_IMAGES se ignoran para imágenes comprimidas. Para habilitar GL_UNPACK_SKIP_PIXELS y GL_UNPACK_ROW_LENGTH, bs y bw deben ser ambos distintos de cero. Para habilitar también GL_UNPACK_SKIP_ROWS y GL_UNPACK_IMAGE_HEIGHT, bh debe ser distinto de cero. Para habilitar también GL_UNPACK_SKIP_IMAGES, bd debe ser distinto de cero. Todos los parámetros deben ser consistentes con el formato comprimido para producir los resultados

deseados.

Al seleccionar un subrectángulo de una imagen

comprimida:
•el valor de GL_UNPACK_SKIP_PIXELS debe ser un múltiplo de
bw;
•el valor de GL_UNPACK_SKIP_ROWS debe ser un múltiplo de
bw;
•el valor de GL_UNPACK_SKIP_IMAGES debe ser un múltiplo de
bw.

imageSize debe ser igual

ERRORE

S

Se genera GL_INVALID_ENUM si internalformat no es uno de los formatos internos comprimidos genéricos: GL_COMPRESSED_RED, GL_COMPRESSED_RG, GL_COMPRESSED_RGB, GL_COMPRESSED_RGBA. GL_COMPRESSED_SRGB o GL_COMPRESSED_SRGB_ALPHA

.

Se genera GL_INVALID_VALUE si imageSize no es consistente con el formato, las dimensiones y el contenido de los datos de imagen comprimida

especificados.

Se genera GL_INVALID_VALUE si border no es

0.

Se genera GL_INVALID_OPERATION si las combinaciones de parámetros no son admitidas por el formato interno comprimido específico, tal como se especifica en la extensión de compresión de textura

específica.

Se genera GL_INVALID_OPERATION si un nombre de objeto de búfer distinto de cero está vinculado al objetivo GL_PIXEL_UNPACK_BUFFER y el almacén de datos del objeto de búfer está actualmente

mapeado.

Se genera GL_INVALID_OPERATION si un nombre de objeto de búfer distinto de cero está vinculado al objetivo GL_PIXEL_UNPACK_BUFFER y los datos se desempaquetarían del objeto de búfer de manera que las lecturas de memoria requeridas excederían el tamaño del almacén de

datos.

Se generan resultados indefinidos, incluyendo la terminación anormal del programa, si data no está codificado de una manera consistente con la especif

icación de la extensión que define
el formato de compresión interno.
