CIÓN

glGetCompressedTextureSubImage se puede utilizar para obtener una subregión de una imagen de textura comprimida en lugar de la imagen completa, siempre que los datos comprimidos estén dispuestos en bloques de tamaño

fijo de texeles.

texture es el nombre del objeto de textura y no debe ser una textura de búfer ni de muestreo múltiple. El objetivo efectivo es el valor de GL_TEXTURE_TARGET para texture. level y pixels tienen el mismo significado que los argumentos correspondientes de glCompressedTexSubImage3D. bufSize indica el tamaño del búfer para recibir los datos de píxeles recuperados. Para las texturas de mapa cúbico, el comportamiento es como si se llamara

a

glGetCompressedTexImage una vez por cada cara solicitada (seleccionada por zoffset y depth, como se describe a continuación) con target correspondiente a la cara del mapa cúbico de la textura solicitada, como se indica en la tabla presentada a continuación. pixels se desplaza adecuadamente para cada imagen

sucesiva. capa l mapa cúbico 0 IVE_X 1 IVE_X 2 IVE_Y 3 IVE_Y 4 IVE_Z 5 VE_

xoffset, yoffset y zoffset indican la posición de la subregión a devolver. width, height y depth indican el tamaño de la región a devolver. Estos argumentos tienen el mismo significado que para glCompressedTexSubImage3D, aunque hay restricciones adicionales, descritas en la sección de errores a

continuación.

El mapeo entre los parámetros xoffset, yoffset, zoffset, width, height y depth y las caras, capas y caras de capa para las texturas de mapa cúbico, de matriz y de matriz de mapa cúbico es el mismo que para glGetTextureSubImage

.

Los desplazamientos xoffset, yoffset, zoffset y los tamaños width, height y depth deben ser múltiplos de los valores de GL_PACK_COMPRESSED_BLOCK_WIDTH, GL_PACK_COMPRESSED_BLOCK_HEIGHT y GL_PACK_COMPRESSED_BLOCK_DEPTH respectivamente, a menos que el desplazamiento sea cero y el tamaño correspondiente sea igual al tamaño de la textura en esa

dimensión.

Los modos de almacenamiento de píxeles se tratan como en glGetCompressedTexSubImage. El texel en (xoffset, yoffset, zoffset) se almacenará en la ubicación indicada por pixels y los parámetros actual

es de empaquet
ado de píxeles.

ERRORE

S

Se genera el error GL_INVALID_OPERATION si texture es el nombre de una textura de búfer o de muestreo

múltiple.

Se genera el error GL_INVALID_OPERATION si el tamaño de búfer necesario para almacenar los datos solicitados es mayor que bufSize

.

Se genera el error GL_INVALID_OPERATION si el formato de compresión de la textura no se basa en bloques de tamaño

fijo.

Se genera el error GL_INVALID_VALUE si texture no es el nombre de un objeto de textura

existente.

Se genera GL_INVALID_VALUE si xoffset, yoffset o zoffset son

negativos.

Se genera GL_INVALID_VALUE si xoffset + width es mayor que el ancho de la textura, yoffset + height es mayor que la altura de la textura, o zoffset + depth es mayor que la profundidad de la

textura.

Se genera el error GL_INVALID_VALUE si el objetivo efectivo es GL_TEXTURE_1D y yoffset no es cero, o height no es

uno.

Se genera el error GL_INVALID_VALUE si el objetivo efectivo es GL_TEXTURE_1D, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_2D o GL_TEXTURE_RECTANGLE y zoffset no es cero, o depth no es

uno.

Se genera el error GL_INVALID_VALUE si xoffset, yoffset o zoffset no es un múltiplo del ancho, la altura o la profundidad del bloque comprimido respectivamente

.

Se genera el error GL_INVALID_VALUE si width, height o depth no es un múltiplo del ancho, la altura o la profundidad del bloque comprimido respectivamente, a menos que el desplazamiento sea cero y el tamaño sea igual al tamaño

de la imagen
de la textura.
