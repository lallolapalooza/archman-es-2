NOMBRE

glab-release-create - Crea una nueva versión de GitLab, o actualiza una existente.

SINOPSIS

glab release create [...] [flags]

DESCRIPCIÓN

Crea una nueva versión de GitLab para un repositorio, o actualiza una existente. Requiere al menos el rol de Desarrollador.

Una versión existente se actualiza con la nueva información que proporciones.

Para crear una versión a partir de una etiqueta Git anotada:

1.
Crea la etiqueta localmente con Git y sube la etiqueta a GitLab.
2.
Ejecuta este comando.
3.
Si la etiqueta Git que especificas no existe, el comando crea una versión a partir del último estado de la rama por defecto y la etiqueta con el nombre de etiqueta que especifiques.

Para anular este comportamiento, usa --ref. El ref
puede ser un SHA de commit, otro nombre de etiqueta o un nombre de rama. 4. Opcional. Para obtener la nueva etiqueta localmente después de la versión, ejecuta
git fetch --tags origin.

OPCIONES

-a, --assets-links="" Representación en cadena JSON de los enlaces de los activos. Ver la documentación para ejemplos.

-m, --milestone=[] El título de cada hito con el que se asocia la versión. Se pueden especificar varios hitos separados por comas o repitiendo la opción.

-n, --name="" El nombre o título de la versión.

--no-close-milestone[=false] Evita cerrar los hitos después de crear la versión.

--no-update[=false] Evita actualizar la versión existente.

-N, --notes="" Las notas de la versión o descripción. Acepta Markdown.

-F, --notes-file="" Lee las notas de la versión del 'archivo'. Para leer desde la entrada estándar, usa '-'.

--package-name="release-assets" El nombre del paquete, al subir activos al registro de paquetes genérico con --use-package-registry.

--publish-to-catalog=false ⟨EXPERIMENTAL⟩ Publica la versión en el catálogo CI/CD de GitLab.

-r, --ref="" Si la etiqueta especificada no existe, crea una versión a partir del ref y la etiqueta con el nombre de etiqueta especificado. Acepta un SHA de commit, un nombre de etiqueta o un nombre de rama.

-D, --released-at="" Fecha y hora en formato ISO 8601 de cuándo estuvo lista la versión. Por defecto, la fecha y hora actuales.

-T, --tag-message="" Mensaje a usar si se crea una nueva etiqueta anotada.

--use-package-registry[=false] Sube los activos de la versión al registro de paquetes genérico del proyecto. Anula la variable de entorno GITLAB_RELEASE_ASSETS_USE_PACKAGE_REGISTRY.

OPCIONES HEREDADAS DE COMANDOS PADRE

-h, --help[=false] Muestra la ayuda para este comando.

-R, --repo="" Selecciona otro repositorio. Puede usar el formato PROPIETARIO/REPO o GRUPO/NAMESPACE/REPO. También acepta URL completa o URL Git.

EJEMPLO

# Crear una versión interactivamente
$ glab release create v1.0.1
# Crear una versión de forma no interactiva especificando una nota
$ glab release create v1.0.1 --notes "versión de corrección de errores"
# Usar notas de versión de un archivo
$ glab release create v1.0.1 -F changelog.md
# Subir un activo de versión con un nombre de visualización (el tipo será 'other' por defecto)
$ glab release create v1.0.1 '/path/to/asset.zip#Mi etiqueta de visualización'
# Subir un activo de versión con un nombre de visualización y tipo
$ glab release create v1.0.1 '/path/to/asset.png#Mi etiqueta de visualización#image'
# Subir todos los activos en una carpeta especificada (los tipos son 'other' por defecto)
$ glab release create v1.0.1 ./dist/*
# Subir todos los archivos tar.gz en una carpeta especificada (los tipos son 'other' por defecto)
$ glab release release create v1.0.1 ./dist/*.tar.gz
# Crear una versión con activos especificados como objeto JSON
$ glab release create v1.0.1 --assets-links='
  [
    {
      "nombre": "Activo1",
      "url": "https://<dominio>/alguna/ubicacion/1",
      "tipo_enlace": "other",
      "ruta_activo_directa": "ruta/al/archivo"
    }
  ]'
# (EXPERIMENTAL) Crear una versión y publicarla en el catálogo CI/CD de GitLab
# Requiere que el flag de función `ci_release_cli_catalog_publish_option` esté habilitado
# para este proyecto en tu instancia de GitLab. NO lo ejecutes manualmente. Úsalo como parte
# de un pipeline CI/CD con la palabra clave "release":
#
# - Recupera componentes del repositorio actual buscando
#   archivos `yml` dentro del directorio "templates" y sus subdirectorios.
# - Falla si el flag de función `ci_release_cli_catalog_publish_option`
#   no está habilitado para este proyecto en tu instancia de GitLab.
# Los componentes se pueden definir:
# - En archivos individuales que terminan en `.yml` para cada componente, como `templates/secret-detection.yml`.
# - En subdirectorios que contienen archivos `template.yml` como puntos de entrada,
#   para componentes que agrupan varios archivos relacionados. Por ejemplo,
#   `templates/secret-detection/template.yml`.
$ glab release create v1.0.1 --publish-to-catalog
