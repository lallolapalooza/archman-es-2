DESCRIPCIÓ

N

La función gl_get_line() es parte de la biblioteca tecla (véase la página man libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de unix. Además de la edición simple de línea de comandos, soporta el recuerdo de líneas de comandos introducidas previamente, la completación con TAB de nombres de archivos y la expansión en línea de comodines de nombres de archivos. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario se puede encontrar en la página man tecla(7). Esta página man se ocupa de la documentación par

a programadores interesados en usar
esta biblioteca en su aplicación.

EJEMPLO

Lo siguiente muestra un ejemplo completo de cómo usar la función gl_get_line() para obtener entrada del

usuario: 
  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que el usuario escribió */
    GetLine *gl;   /* El objeto recurso de gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* de conjunto de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("You typed: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
}

En el ejemplo, primero los recursos necesarios por la función gl_get_line() son creados llamando a new_GetLine(). Esto asigna la memoria usada en llamadas subsecuentes a la función gl_get_line(), incluyendo el búfer de historial para registrar líneas introducidas previamente. Luego se leen una o más líneas del usuario, hasta que ocurra un error, o el usuario escriba exit. Finalmente, los recursos que fueron asignados por new_GetLine() son devueltos al sistema llamando a del_GetLine(). Nótese el uso del valor de retorno NULL de del_GetLine() para hacer gl NULL. Esta es una precaución de seguridad. Si el programa posteriormente intenta pasar gl a gl_get_line(), dicha función se quejará y devolverá un err

or, en lugar de intentar usar
el objeto recurso eliminado.

La función gl_get_line() puede ser llamada cualquier número de veces para leer entrada del usuario. El argumento gl debe haber sido previamente devuelto por una llamada a new_GetLine(). El argumento prompt debería ser una cadena normal terminada en NUL, especificando el prompt a presentar al usuario. Por defecto los prompts se muestran literalmente, pero si se habilitan con la función gl_prompt_style() (véase más adelante), los prompts pueden contener directivas para subrayar, cambiar a y de fuentes en negrita, o activar y desactivar el

resaltado.

Si desea especificar el contenido inicial de la línea, para que el usuario la edite, pase la cadena deseada a través del argumento start_line. Luego puede especificar sobre qué carácter de esta línea se posiciona inicialmente el cursorr, usando el argumento start_pos. Este debe ser -1 si desea que el cursor siga al último carácter de la línea de inicio. Si no desea precargar la línea de esta manera, envíe start_line como NULL, y establezca start_pos a -1. Tenga en cuenta que el puntero a la línea devuelto por una llamada a gl_get_line() puede pasarse a la siguiente llamada a gl_get_line() a través de start_line. Esto permite que la aplicación tome la última línea introducida y, si contiene un error, la presente de nuevo al usuario para su reedición, con el cursor inicialmente posicionado donde se encontró el

error.

La función gl_get_line() devuelve un puntero a la línea introducida por el usuario, o NULL en caso de error o al final de la entrada. El puntero devuelto es parte del objeto recurso gl especificado, y por lo tanto no debe ser liberado por el llamador, ni asumirse que es inmutable de una llamada a la siguiente. Al leer de un usuario en una terminal, siempre habrá un carácter de nueva línea al final de la línea devuelta. Cuando la entrada estándar se toma de una tubería o de un archivo, de manera similar habrá una nueva línea a menos que la línea de entrada fuera demasiado larga para almacenarse en el búfer interno. En este último caso, debe llamar a gl_get_line() de nuevo para leer el resto de la línea. Tenga en cuenta que este comportamiento hace que gl_get_line() sea similar a fgets(). De hecho, cuando stdin no está conectado a una terminal,gl_get_line() simplemente llama a fget

s(

FUENTES DE CONFIGURACIÓN

ALTERNATIVAS

Como se mencionó anteriormente, de forma predeterminada los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. Sin embargo, en algunas aplicaciones, este único medio de configuración es un problema. Esto es particularmente cierto en el software embebido, donde no hay un sistema de archivos del cual leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de asignaciones de teclas para emular una interfaz de teclado heredada. Para atender a tales casos, la siguiente función permite a la aplicación controlar desde dónde se lee la información de

configuración. 
  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file)
;

Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc de un usuario, se lean de una cadena, un archivo de configuración específico de la aplicación, y/o un archivo de configuración específico del usuario, o de ninguno. Si esta función se llama antes de la primera llamada a gl_get_line(), el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line() se deshabilita, por lo que toda la configuración debe lograrse utilizando las fuentes de configuración especificadas con esta

función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados unos de otros en la cadena por caracteres de nueva línea incrustados. Si app_file != NULL entonces se interpreta como la ruta de archivo completa de un archivo de configuración específico de la aplicación. Si user_file != NULL entonces se interpreta como la ruta de archivo completa de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente

llamada, 
  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc")
;

el argumento app_string hace que la aplicación que llama comience en el modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso de la campana de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración de todo el sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario desde un archivo opcional .teclarc en el directorio de inicio del usuario. Tenga en cuenta que los argumentos se listan en orden ascendente de prioridad, con el contenido de app_string siendo potencialmente sobreescrito por comandos en app_file, y los comandos en app_file siendo potencialmente sobreescritos por comandos en user_file

.

Puede llamar a esta función tantas veces como sea necesario, con resultados acumulativos, pero tenga en cuenta que las copias de cualquier nombre de archivo especificado a través de app_fil

Los argumentos e y user_file se registran internamente para su uso posterior por la función de enlace de teclas read-init-files, por lo que si planea llamar a esta función varias veces, asegúrese de que la última llamada especifique los nombres de archivo que desea volver a leer cuando el usuario solicite que se vuelvan a leer los archivos de configuración.

Las secuencias de teclas individuales también se pueden enlazar y desenlazar utilizando la función gl_bind_keyseq().

  int gl_bind_keyseq(GetLine *gl, GlKeyOrigin origin,
                     const char *keyseq,
                     const char *action);

El argumento origin especifica la prioridad del enlace, según para quién se está estableciendo, y debe ser uno de los dos valores siguientes.

  GL_USER_KEY   -   El usuario solicitó este enlace de teclas.
  GL_APP_KEY    -   Este es un enlace predeterminado establecido por la
                    aplicación.

Cuando se especifican enlaces de usuario y de aplicación para una secuencia de teclas dada, el enlace del usuario tiene prioridad. El enlace de la aplicación se restablece posteriormente si el enlace del usuario se desvincula más tarde a través de otra llamada a esta función o de una llamada a gl_configure_getline().

El argumento keyseq especifica la secuencia de teclas a enlazar o desenlazar, y se expresa de la misma manera que en un archivo de configuración ~/.teclarc. El argumento action debe ser una cadena que contenga el nombre de la acción a la que enlazar la secuencia de teclas, o debe ser NULL o "" para desenlazar la secuencia de teclas.

COMPLETADO PERSONALIZADO DE PALABRAS

Si en su aplicación desea que la compleción TAB complete otras cosas además de o en lugar de los nombres de archivo, puede organizarlo registrando una función de devolución de llamada de compleción alternativa, mediante una llamada a la función gl_customize_completion().

  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn);

El argumento data proporciona una forma para que su aplicación pase información arbitraria y específica de la aplicación a la función de devolución de llamada. Esto se pasa a la devolución de llamada cada vez que se llama. Podría, por ejemplo, apuntar a la tabla de símbolos de la que se deben buscar las posibles compleciones. El argumento match_fn especifica la función de devolución de llamada que se debe llamar. El tipo de función CplMatchFn se define en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede utilizar para declarar y prototipar funciones de devolución de llamada. La declaración y las responsabilidades de las funciones de devolución de llamada se describen en detalle en la página man de cpl_complete_word(3).

En resumen, la función de devolución de llamada es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario presionó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar posibles compleciones de esta palabra y registrarlas una por una en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion(). Si la función de devolución de llamada desea proporcionar compleción de nombres de archivo además de sus propias compleciones específicas, tiene la opción de llamar a la función de devolución de llamada de compleción de nombres de archivo incorporada. Esto también se documenta en la página man de cpl_complete_word(3).

Tenga en cuenta que si desea que gl_get_line() devuelva la línea de entrada actual cuando se realiza una compleción exitosa, puede organizarlo al llamar a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de nueva línea. Si hace esto, la línea de entrada se actualizará para mostrar la compleción, junto con cualquier sufijo de continuación hasta el carácter de nueva línea, luego gl_get_line() devolverá esta línea de entrada.

Si, por alguna razón, su función de devolución de llamada necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto iniciará una nueva línea después de la línea que se está editando actualmente, restablecerá la E/S normal de la terminal y le indicará a gl_get_line() que la línea de entrada deberá redibujarse cuando la devolución de llamada regrese.

AGREGANDO ACCIONES DE COMPLETADO

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de compleción predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que se puedan enlazar diferentes tipos de compleción de palabras a diferentes secuencias de teclas. Esto se logra utilizando la función gl_completion_action().

  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq);

Los argumentos data y match_fn son como se describe en la página man de cpl_complete_word, y especifican la función de devolución de llamada que se debe invocar para identificar compleciones posibles. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar las posibles compleciones ambiguas, o si simplemente debe mostrar la lista de compleciones posibles sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0 y la segunda especificando un valor de 1. El argumento name especifica el nombre por el cual los archivos de configuración y las futuras invocaciones de esta función se referirán a la acción. Debe ser el nombre de una acción de compleción existente que se va a cambiar, o un nombre nuevo no utilizado para una nueva acción. Finalmente, el argumento keyseq especifica la secuencia de teclas predeterminada a la que se enlazará la acción. Si es NULL, no se enlazará ninguna secuencia de teclas nueva a la acción.

Tenga en cuenta que para que el usuario pueda cambiar la secuencia de teclas que está enlazada a las acciones que se instalan de esta manera, cuando llame a gl_completion_action() para instalar una acción determinada por primera vez, debe hacerlo entre la llamada a new_GetLine() y la primera llamada a gl_get_line(). De lo contrario, cuando se lea el archivo de configuración del usuario en la primera llamada a gl_get_line(), el nombre de su acción adicional no se conocerá y cualquier referencia a él en el archivo de configuración generará un error.

Como se discutió para gl_customize_completion(), si su función de devolución de llamada, por alguna razón, necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo.

DEFINIENDO ACCIONES PERSONALIZADAS

Aunque las acciones de enlace de teclas integradas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, enlazadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza que correspondía a un número de pieza anterior al cursor. Tal característica está claramente fuera del alcance de las funciones de acción integradas. Por lo tanto, para tales casos especiales, se proporciona la función gl_register_action().

  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq);

Esta función permite a la aplicación registrar una función externa, fn, que posteriormente se llamará cada vez que el usuario ingrese la secuencia de teclas especificada, keyseq, o cualquier otra secuencia de teclas que el usuario enlace posteriormente al nombre de acción especificado, name, en su archivo de configuración. El argumento data puede ser un puntero a cualquier cosa que la aplicación desee pasar a la función de acción, fn, cada vez que se invoque esa función.

La función de acción, fn, debe declararse utilizando la siguiente macro, que se define en libtecla.h.

  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char *line)

Los argumentos gl y data son los que se pasaron previamente a gl_register_action() cuando se registró la función de acción. El argumento count es un argumento numérico que el usuario tiene la opción de ingresar usando la acción digit-argument, antes de invocar la acción. Si el usuario no ingresa un número, el argumento count se establece en 1. Nominalmente, este argumento se interpreta como un recuento de repetición, lo que significa que la acción debe repetirse tantas veces. En la práctica, sin embargo, para algunas acciones, un recuento de repetición tiene poco sentido. En tales casos, las acciones pueden simplemente ignorar el argumento count o usar su valor para un propósito diferente.

Una copia de la línea de entrada actual se pasa en el argumento de solo lectura line. La posición actual del cursor dentro de esta cadena se da por el índice contenido en el argumento curpos. Tenga en cuenta que no se permite la manipulación directa de la línea de entrada y la posición del cursor. Esto se debe a que las reglas dictadas por varios modos, como el modo vi frente al modo emacs, el modo sin eco y el modo de inserción frente al modo de sobrescritura, etc., hacen que sea demasiado complejo para un escritor de aplicaciones escribir una acción de edición que cumpla, además de restringir los cambios futuros en los detalles internos de gl_get_line(). Una solución potencial a este dilema sería permitir que la función de acción edite la línea utilizando las acciones de edición existentes. Esto está actualmente en consideración.

Si la función de acción desea escribir texto en la terminal, sin que esto se mezcle con el texto mostrado de la línea de entrada, o leer desde la terminal sin tener que manejar la E/S de terminal sin procesar, entonces antes de realizar cualquiera de estas operaciones, debe suspender temporalmente la edición de línea llamando a la función gl_normal_io(). Esta función vacía cualquier salida pendiente a la terminal, mueve el cursor al inicio de la línea que sigue a la última línea de terminal de la línea de entrada, luego restaura la terminal a un estado adecuado para su uso con las instalaciones de C stdio. Este último incluye cosas como restaurar el mapeo normal de \n a \r\n y, cuando está en modo servidor, restaurar la forma de bloqueo normal de la E/S de terminal. Después de llamar a esta función, la función de acción puede leer y escribir en la terminal sin temor a crear un desorden. No es necesario que la función de acción restaure el entorno de edición original antes de que regrese. Esto lo hace automáticamente gl_get_line() después de que la función de acción regresa. Nótese que en este caso los valores de retorno, GLFD_REFRESH y GLFD_CONTINUE son

Para soportar los casos en los que la función de retorno de llamada llama a una función de terceros que ocasional e impredeciblemente escribe en el terminal, la conversión automática de "0 a "0 se vuelve a habilitar antes de que se llame a la función de retorno de llamada. Si el retorno de llamada sabe que la función de terceros escribió en el terminal, entonces debe devolver el valor de retorno GLFD_REFRESH, para decirle a gl_get_line() que vuelva a mostrar la línea de

entrada.

Para eliminar una función de retorno de llamada que registró previamente para un descriptor de archivo y evento dados, simplemente llame a gl_watch_fd() con el mismo descriptor de archivo y los argumentos event, pero con un argumento callback de 0. El argumento data se i

gnora en
este caso.

En sistemas raros que no tienen select(), esta llamada no tiene

efecto. 
  int gl_inacti


gl_inactivity_timeout

El tiempo de espera se especifica en forma de un número entero de
    segundos y un número entero de nanosegundos, a través de los argumentos
    sec y nsec respectivamente. Posteriormente, siempre que no se
    detecte actividad durante este período de tiempo, se llama a la función

  #define GL_TIMEOUT_FN(fn) \
               GlAfterTimeout (fn)(GetLine *gl, void *data)


Al regresar, se espera que la devolución de llamada de la
    aplicación devuelva uno de los siguientes enumeradores para indicar a
    gl_get_line() cómo proceder después de que el tiempo de espera haya
    sido manejado por la devolución de llamada.


  GLTO_ABORT    -  Indica a gl_get_line() que aborte. Cuando
                   esto sucede, gl_get_line() devolverá
                   NULL, y una llamada posterior a
                   gl_return_status() devolverá
                   GLR_TIMEOUT. Tenga en cuenta que si la
                   aplicación necesita que errno siempre
                   tenga un valor significativo cuando
                   gl_get_line() devuelve NULL,
                   la función de devolución de llamada debe
                   establecer errno apropiadamente.
  GLTO_REFRESH  -  Vuelve a dibujar la línea de entrada, luego
                   continúa esperando entrada. Debería devolver
                   este valor si su devolución de llamada escribió
                   en la terminal sin haber llamado primero a
                   gl_normal_io(gl).
  GLTO_CONTINUE -  En el modo normal de E/S de bloqueo, continúa
                   esperando entrada, sin volver a dibujar la
                   línea de entrada del usuario.
                   En el modo de E/S de servidor no bloqueante
                   (ver gl_io_mode(3)), hace que
                   gl_get_line() actúe como si la E/S
                   se hubiera bloqueado. Esto significa que
                   gl_get_line() devolverá inmediatamente
                   NULL, y una llamada posterior a
                   gl_return_status() devolverá
                   GLR_BLOCKED.


Tenga en cuenta que antes de llamar a la devolución de llamada,
    gl_get_line() bloquea la mayoría de las señales y deja sus propios
    manejadores de señales instalados, por lo que si necesita capturar una
    señal particular, deberá instalar temporalmente su propio manejador de
    señales y desbloquear la señal. Asegúrese de volver a bloquear la señal
    (si originalmente estaba bloqueada) y restablecer el manejador de señales
    original, si lo hay, antes de regresar.


Si la función de devolución de llamada necesita leer o escribir en
    la terminal, idealmente debería llamar primero a gl_normal_io(gl)
    para suspender temporalmente la edición de línea. Esto restaurará la
    terminal al modo canónico y de E/S de bloqueo, y moverá el cursor al
    principio de una nueva línea de terminal. Más tarde, cuando la devolución de
    llamada regrese, gl_get_line() notará que se llamó a
    gl_normal_io(), redibujará la línea de entrada y reanudará la
    edición. Tenga en cuenta que en este caso los valores de retorno,
    GLTO_REFRESH y GLTO_CONTINUE son equivalentes.


Para admitir casos en los que la función de devolución de llamada
    llama a una función de terceros que ocasionalmente y de forma impredecible
    escribe en la terminal, la conversión automática de "0 a
    "0 se vuelve a habilitar antes de que se llame a la función de
    devolución de llamada. Si la devolución de llamada sabe que la función de
    terceros escribió en la terminal, debería devolver el valor de retorno
    GLTO_REFRESH, para indicarle a gl_get_line() que redibuje la
    línea de entrada.


Tenga en cuenta que aunque el argumento de tiempo de espera incluye
    un componente de nanosegundos, pocos relojes de computadora tienen actualmente
    resoluciones más finas que unos pocos milisegundos, por lo que solicitar
    menos de unos pocos milisegundos es equivalente a solicitar cero segundos en
    muchos sistemas. Si esto fuera un problema, debería basar su selección de
    tiempo de espera en la resolución real del reloj del host (por ejemplo,
    llamando a sysconf(_SC_CLK_TCK)).


Para desactivar los tiempos de espera, simplemente llame a
    gl_inactivity_timeout() con un argumento callback de
    0. El argumento data se ignora en este caso.






MANEJO POR DEFECTO DE SEÑALES


Por defecto, la función gl_get_line() intercepta un número de
    señales. Esto es particularmente importante para las señales que por defecto
    terminarían el proceso, ya que la terminal debe restaurarse a un estado
    utilizable antes de que esto suceda. En esta sección, se describen las
    señales que se capturan por defecto y cómo responde gl_get_line() a
    ellas. El cambio de estos valores predeterminados es el tema de la siguiente
    sección.


Cuando se capturan el siguiente subconjunto de señales,
    gl_get_line() restaura primero la configuración de la terminal y el
    manejo de señales a cómo estaban antes de que se llamara a
    gl_get_line(), reenvía la señal, para permitir que los manejadores de
    señales de la aplicación que llama la manejen, y luego, si el proceso aún
    existe, gl_get_line() devuelve NULL y establece errno
    como se especifica a continuación.


 SIGINT  -  Esta señal se genera tanto por la tecla de
            interrupción del teclado (generalmente ^C), como
            por la tecla de interrupción del teclado.
            errno=EINTR
 SIGHUP  -  Esta señal se genera cuando sale la terminal
            de control.
            errno=ENOTTY
 SIGPIPE -  Esta señal se genera cuando un programa intenta
            escribir en una tubería cuya extremo remoto no está
            siendo leído por ningún proceso. Esto puede suceder,
            por ejemplo, si ha llamado a
            gl_change_terminal() para redirigir la salida
            a una tubería oculta bajo una pseudo-terminal.
            errno=EPIPE
 SIGQUIT -  Esta señal se genera por la tecla de fin del
            teclado (generalmente ^\).
            errno=EINTR
 SIGABRT -  Esta señal se genera por la función estándar
            C, abort(). Por defecto, termina el proceso y
            genera un volcado del núcleo.
            errno=EINTR
 SIGTERM -  Esta es la señal predeterminada que el comando
            UN*X kill envía a los procesos.
            errno=EINTR


Tenga en cuenta que en el caso de todas las señales anteriores, POSIX
    garantiza que por defecto el proceso se termina, con la adición de un volcado
    del núcleo en el caso de la señal SIGQUIT. En otras palabras, si la
    aplicación que llama no anula el manejador por defecto proporcionando su
    propio manejador de señales, la recepción de la señal correspondiente
    terminará la aplicación antes de que gl_get_line() regrese.


Si gl_get_line() aborta con errno establecido en EINTR, puede averiguar
    qué señal provocó que abortara, llamando a la siguiente función.


  int gl_last_signal(const GetLine *gl);


Esto devuelve el código numérico (por ejemplo, SIGINT) de la
    última señal que se recibió durante la llamada más reciente a
    gl_get_line(), o -1 si no se recibieron señales.


En sistemas que lo soportan, cuando se recibe una señal SIGWINCH
    (cambio de ventana), gl_get_line() consulta la terminal para averiguar
    su nuevo tamaño, redibuja la línea de entrada actual para acomodar el nuevo
    tamaño, y luego regresa a esperar la entrada del teclado del usuario. A
    diferencia de otras señales, esta señal no se reenvía a la aplicación.


Finalmente, las siguientes señales hacen que gl_get_line()
    restaure primero la configuración de la terminal y el entorno de señales a
    cómo estaban antes de que se llamara a gl_get_line(), luego reenvía
    la señal a la aplicación. Si el proceso aún existe después de que se haya
    entregado la señal, entonces gl_get_line() restablece sus propios
    manejadores de señales, cambia la terminal de nuevo a modo raw, redibuja la
    línea de entrada y vuelve a esperar la entrada de la terminal del usuario.


 SIGCONT    -  Esta señal se genera cuando se reanuda un
               proceso suspendido.
 SIGPOLL    -  En sistemas SVR4, esta señal notifica al
               proceso un evento de E/S asíncrono. Tenga
               en cuenta que bajo 4.3+BSD, SIGIO y SIGPOLL
               son lo mismo. En otros sistemas, SIGIO es
               ignorado por defecto, por lo que
               gl_get_line() no lo captura por defecto.
 SIGPWR     -  Esta señal se genera cuando ocurre una falla
               de energía (presumiblemente cuando el sistema
               está en un UPS).
 SIGALRM    -  Esta señal se genera cuando expira un temporizador.
 SIGUSR1    -  Una señal específica de la aplicación.
 SIGUSR2    -  Otra señal específica de la aplicación.
 SIGVTALRM  -  Esta señal se genera cuando expira un temporizador
               virtual (ver man setitimer(2)).
 SIGXCPU    -  Esta señal se genera cuando un proceso excede
               su límite de tiempo de CPU suave.
 SIGXFSZ    -  Esta señal se genera cuando un proceso excede
               su límite de tamaño de archivo suave.
 SIGTSTP    -  Esta señal se genera por la tecla de suspensión
               de la terminal, que suele ser ^Z, o la tecla de
               suspensión de terminal retardada, que suele ser
               ^Y.
 SIGTTIN    -  Esta señal se genera si el programa intenta
               leer de la terminal mientras el programa se
               ejecuta en segundo plano.
 SIGTTOU    -  Esta señal se genera si el programa intenta
               escribir en la terminal mientras el programa se
               ejecuta en segundo plano.


Obviamente, no todas las señales anteriores son compatibles en todos
    los sistemas, por lo que el código para soportarlas se compila condicionalmente
    en la biblioteca tecla.


Tenga en cuenta que si se reciben y no se manejan SIGKILL o
    SIGPOLL, que por definición no se pueden capturar, o ninguna de las
    señales de excepción generadas por hardware, como SIGSEGV,
    SIGBUS y SIGFPE, mientras gl_get_line() tiene la
    terminal en modo raw, el programa se terminará sin que la terminal se haya
    restaurado a un estado utilizable. En la práctica, los shells de control de
    trabajo suelen restablecer la configuración de la terminal cuando un proceso
    cede el control de la terminal, por lo que esto solo es un problema con shells
    más antiguos.






MANEJO PERSONALIZADO DE SEÑALES


La sección anterior enumeró las señales que gl_get_line()
    captura por defecto y describió cómo responde a ellas. Esta sección describe
    cómo agregar y eliminar señales de la lista de señales capturadas, y cómo
    especificar cómo debe responder gl_get_line() a una señal dada.


Si no necesita que gl_get_line() haga nada en respuesta a
    una señal que normalmente captura, puede indicarle a gl_get_line()
    que ignore esa señal llamando a gl_ignore_signal().


  int gl_ignore_signal(GetLine *gl, int signo);


El argumento signo es el número de la señal (por ejemplo,
    SIGINT) que desea que se ignore. Si la señal especificada no es
    actualmente una de las que se están capturando, esta función no hace nada.


La función gl_trap_signal() le permite agregar una nueva
    señal a la lista que gl_get_line() captura, o modificar cómo responde




gl_trap_SIGNAL


Esta función se utiliza para permitir que la aplicación o
    GetLine capturen una señal. Si la aplicación configura la función para que
    capture una señal que ya está siendo capturada, su configuración se aplicará
    a la señal.


  int gl_trap_signal(GetLine *gl, int signo, unsigned flags,
                     GlAfterSignal after, int errno_value);


El argumento signo es el número de la señal que desea
    capturar. El argumento flags es un conjunto de indicadores que
    determinan el entorno en el que se invoca el manejador de señales de la
    aplicación, el argumento after indica a gl_get_line() qué
    hacer después de que regrese el manejador de señales de la aplicación, y
    errno_value indica a gl_get_line() qué establecer en
    errno si se le indica que abandone.


El argumento flags es un OR a nivel de bits de cero o más
    de los siguientes enumeradores:


  GLS_RESTORE_SIG  -  Restaurar el entorno de señales del
                      llamador mientras se maneja la
                      señal.
  GLS_RESTORE_TTY  -  Restaurar la configuración de la
                      terminal del llamador mientras se
                      maneja la señal.
  GLS_RESTORE_LINE -  Mover el cursor al inicio de la línea
                      después de la línea de entrada antes
                      de invocar el manejador de señales
                      de la aplicación.
  GLS_REDRAW_LINE  -  Redibujar la línea de entrada cuando
                      el manejador de señales de la
                      aplicación regrese.
  GLS_UNBLOCK_SIG  -  Normalmente, si el programa que llama
                      tiene una señal bloqueada (ver
                      sigprocmask en el manual),
                      gl_get_line() no captura esa
                      señal. Este indicador le indica a
                      gl_get_line() que capture la señal y
                      la desbloquee durante la llamada a
                      gl_get_line().
  GLS_DONT_FORWARD -  Si se incluye este indicador, la señal
                      no se reenviará al manejador de
                      señales del programa llamador.


Dos combinaciones de indicadores comúnmente útiles también se
    enumeran de la siguiente manera:


  GLS_RESTORE_ENV   = GLS_RESTORE_SIG | GLS_RESTORE_TTY |
                      GLS_REDRAW_LINE
  GLS_SUSPEND_INPUT = GLS_RESTORE_ENV | GLS_RESTORE_LINE


Si su manejador de señales, o el manejador de señales predeterminado
    del sistema para esta señal, si no lo ha anulado, nunca escribe en la
    terminal, ni suspende o termina el programa llamador, entonces puede
    establecer de forma segura el argumento flags a 0.


Si su manejador de señales siempre escribe en la terminal, lee de
    ella, o suspende o termina el programa, debe especificar el argumento
    flags como GL_SUSPEND_INPUT, para que:


1. El cursor no se quede en medio de la línea de entrada.
2. Para que el usuario pueda escribir entrada y que se refleje.
3. Para que no necesite terminar cada línea de salida con
   \r\n, en lugar de solo \n.


La combinación GL_RESTORE_ENV es la misma que
    GL_SUSPEND_INPUT, excepto que no mueve el cursor, y si su manejador
    de señales no lee ni escribe nada en la terminal, el usuario no verá ninguna
    indicación visible de que se capturó una señal. Esto puede ser útil si tiene
    un manejador de señales que ocasionalmente escribe en la terminal, donde el
    uso de GL_SUSPEND_LINE haría que la línea de entrada se duplicara
    innecesariamente cuando no se había escrito nada en la terminal. Dicho
    manejador de señales, cuando escribe en la terminal, debe asegurarse de
    comenzar una nueva línea al principio de su primera escritura, escribiendo
    una nueva línea antes de regresar. Si la señal llega mientras el usuario
    está ingresando una línea que solo ocupa una línea de terminal de señal, o si
    el cursor está en la última línea de terminal de una línea de entrada más
    larga, esto tendrá el mismo efecto que GL_SUSPEND_INPUT. De lo
    contrario, comenzará a escribir en una línea que ya contiene parte de la
    línea de entrada mostrada. Esto no causa ningún daño, pero se ve un poco
    feo, por lo que la combinación GL_SUSPEND_INPUT es mejor si sabe que
    siempre va a escribir en la terminal.


El argumento after, que determina qué hace
    gl_get_line() después de que regresa el manejador de señales de la
    aplicación (si regresa), puede tomar cualquiera de los siguientes valores:


  GLS_RETURN   - Devolver la línea de entrada completada, como
                 si el usuario hubiera presionado la tecla
                 enter.
  GLS_ABORT    - Hacer que gl_get_line() abandone. Cuando
                 esto sucede, gl_get_line() devuelve
                 NULL, y una llamada posterior a
                 gl_return_status() devolverá
                 GLR_SIGNAL. Tenga en cuenta que si la
                 aplicación necesita que errno siempre
                 tenga un valor significativo cuando
                 gl_get_line() devuelve NULL,
                 la función de devolución de llamada debe
                 establecer errno apropiadamente.
  GLS_CONTINUE - Reanudar la edición de la línea de comandos. 


El argumento errno_value está destinado a combinarse con
    la opción GLS_ABORT, indicando a gl_get_line() qué establecer
    en la variable estándar errno antes de devolver NULL al
    programa llamador. Sin embargo, también se puede utilizar con la opción
    GL_RETURN, en caso de que desee tener una forma de distinguir entre
    una línea de entrada que se ingresó usando la tecla enter, y una que se
    ingresó por la recepción de una señal.






MANEJO DE SEÑALES CONFIABLE


El manejo de señales es sorprendentemente difícil de hacer de manera
    confiable sin condiciones de carrera. En gl_get_line() se ha puesto
    mucho cuidado para permitir que las aplicaciones realicen un manejo de
    señales confiable alrededor de gl_get_line(). Esta sección explica
    cómo hacer uso de esto.


Como ejemplo de los problemas que pueden surgir si la aplicación no
    está escrita correctamente, imagine que su aplicación tiene un manejador de
    señales SIGINT que establece una bandera global. Ahora suponga que la
    aplicación prueba esta bandera justo antes de invocar gl_get_line().
    Si una señal SIGINT se recibe en la pequeña ventana de tiempo entre la
    declaración que prueba el valor de esta bandera y la declaración que llama a
    gl_get_line(), entonces gl_get_line() no verá la señal y no
    será interrumpida. Como resultado, la aplicación no podrá responder a la
    señal hasta que el usuario termine de ingresar la línea de entrada y
    gl_get_line() regrese. Dependiendo de la aplicación, esto puede ser o
    no un desastre, pero al menos desconcertaría al usuario.


La forma de evitar tales problemas es hacer lo siguiente.


1. Si es necesario, use la función
    gl_trap_signal() para configurar
    

    gl_get_line() para que abandone cuando se capturen
    

    señales importantes.


2. Configure gl_get_line() de tal manera que si alguna
    

    de las señales que captura está bloqueada cuando
    

    se llama a gl_get_line(), se desbloqueará
    

    automáticamente durante los momentos en que
    

    gl_get_line() está esperando E/S. Esto se puede
    

    hacer ya sea por señal individualmente, llamando a la
    

    función gl_trap_signal() y especificando el
    

    atributo GLS_UNBLOCK de la señal, o globalmente
    

    llamando a la función gl_catch_blocked().


     void gl_catch_blocked(GetLine *gl);



  

   Esta función simplemente agrega el atributo
  

   GLS_UNBLOCK a todas las señales que actualmente está
  

   configurada para capturar.


3. Justo antes de llamar a gl_get_line(), bloquee la
  

   entrega de todas las señales que gl_get_line()
  

   está configurada para capturar. Esto se puede hacer
  

   usando la función POSIX sigprocmask() en
  

   conjunción con la función gl_list_signals().


      int gl_list_signals(GetLine *gl, sigset_t *set);



  

   Esta función devuelve el conjunto de señales que
  

   actualmente está configurada para capturar en el
  

   argumento set, que está en el formato requerido
  

   por sigprocmask().


4. En el ejemplo, ahora probaría la bandera global que el
  

   manejador de señales establece, sabiendo que ahora no
  

   hay peligro de que esta bandera se establezca nuevamente
  

   hasta que gl_get_line() desbloquee sus señales
  

   mientras realiza E/S.


5. Eventualmente gl_get_line() regresa, ya sea porque
  

   se capturó una señal, ocurrió un error, o el usuario
  

   terminó de ingresar su línea de entrada.


6. Ahora volvería a verificar la bandera de señal global y, si
  

   está establecida, respondería a ella y pondría la bandera
  

   a cero.


7. Use sigprocmask() para desbloquear las señales que
  

   fueron bloqueadas en el paso 3.


La misma técnica se puede usar alrededor de ciertas funciones POSIX
    conscientes de señales, como sigsetjmp() y sigsuspend(), y
    en particular, la primera de estas dos funciones se puede usar en conjunto
    con siglongjmp() para implementar el manejo de señales libre de
    condiciones de carrera alrededor de otras llamadas de sistema de larga
    duración. La forma de hacer esto se explica a continuación, mostrando cómo
    gl_get_line() logra capturar señales de manera confiable alrededor de
    llamadas a funciones como read() y select() sin condiciones
    de carrera.


Lo primero que hace gl_get_line(), cada vez que se llama, es
    usar la función POSIX sigprocmask() para bloquear la entrega de todas
    las señales que actualmente está configurada para capturar. Esto es redundante
    si la aplicación ya las ha bloqueado, pero no causa daño. Deshace este paso
    justo antes de regresar.


Siempre que gl_get_line() necesita llamar a read() o
    select() para esperar la entrada del usuario, primero llama a la
    función POSIX sigsetjmp(), asegurándose de especificar un valor no
    cero para su argumento savesigs. La razón del último argumento se
    volverá clara en breve.


Si sigsetjmp() devuelve cero, gl_get_line() hace lo
    siguiente.


a. Utiliza la función POSIX sigaction() para registrar
   un manejador de señales temporal para todas las señales
   que está configurada para capturar. Este manejador de
   señales hace dos cosas.
   1. Registra el número de la señal que se recibió
      en una variable a nivel de archivo.
   2. Luego llama a la función POSIX siglongjmp()
      usando el búfer que se pasó a sigsetjmp()
      como su primer argumento, y un valor distinto de
      cero para su segundo argumento.
   Cuando este manejador de señales se registra, el miembro
   sa_mask del argumento struct sigaction act
   de la llamada a sigaction() se configura para
   contener todas las señales que gl_get_line()
   está capturando. Esto asegura que solo una señal sea
   capturada a la vez por nuestro manejador de señales, lo que
   a su vez asegura que múltiples instancias de nuestro
   manejador de señales no se pisen entre sí.
b. Ahora que el manejador de señales se ha configurado,
   gl_get_line() desbloquea todas las señales que está
   configurada para capturar.
c. Luego llama a las llamadas al sistema read() o
   select() para esperar la entrada del teclado.
d. Si esta llamada al sistema regresa (es decir, no se recibe
   ninguna señal), gl_get_line() vuelve a bloquear la
   entrega de las señales de interés.
e. Luego restablece los manejadores de señales que fueron
   desplazados por el que se acaba de instalar.


Alternativamente, si sigsetjmp() devuelve un valor distinto
    de cero, esto significa que uno o



f los señales que se están atrapando fue capturada mientras los pasos anteriores se estaban ejecutando. Cuando esto sucede, gl_get_line() hace lo 
siguiente.

Primero, tenga en cuenta que cuando una llamada a siglongjmp() causa
    que sigsetjmp() retorne, siempre que el argumento savesigs de
    sigsetjmp() fuera distinto de cero, como se especificó anteriormente, la máscara de proceso de señales
    se restaura a cómo estaba cuando sigsetjmp() fue llamado. Esta es la
    diferencia importante entre sigsetjmp() y el antiguo y problemático
    setjmp(), y es el ingrediente esencial que hace posible
    evitar condiciones de carrera en el manejo de señales. Debido a esto, se garantiza
    que todas las señales que bloqueamos antes de llamar a sigsetjmp()
    estén bloqueadas de nuevo tan pronto como cualquier señal sea capturada. Las siguientes declaraciones,
    que se ejecutan a continuación, están por tanto garantizadas de ser ejecutadas sin que
    ninguna otra señal sea 
capturada.

1. Si así lo indica la configuración de gl_get_line()
  

   de la señal que fue capturada,
  

   gl_get_line() restaura los atributos del terminal a
  

   el estado que tenían cuando gl_get_line() fue
  

   llamado. Esto es particularmente importante para las señales que
  

   suspenden o terminan el proceso, ya que de lo contrario el
  

   terminal quedaría en un estado 
inutilizable.

2. Luego reinstala los manejadores de señales de la 
aplicación.

3. Luego usa la función raise()
  

   de la biblioteca estándar de C para reenviar a la aplicación la señal que
  

   fue 
capturada.

3. A continuación, desbloquea la entrega de la señal que acabamos de
  

   enviar. Esto resulta en que la señal que fue enviada
  

   vía raise(), sea capturada por el manejador de señales
  

   original de la aplicación, que ahora puede manejarla como
  

   considere 
oportuno.

4. Si el manejador de señales retorna (es decir, no termina
  

   el proceso), gl_get_line() bloquea la entrega de la
  

   señal anterior de 
nuevo.

5. Luego deshace cualquier acción realizada en el primero de los
  

   pasos anteriores, y vuelve a mostrar la línea, si la configuración de la señal
  

   lo 
requiere.

6. gl_get_line() luego reanuda el intento de
  

   leer un carácter, o aborta, dependiendo de la
  

   configuración de la señal que fue 
capturada.

Lo que los pasos anteriores hacen en esencia es tomar señales
    entregadas de forma asíncrona y manejarlas de forma síncrona, una a la vez, en un punto
    del código donde gl_get_line() tiene control c
ompleto sobre s
u
    entorno.



EL   TAMAÑO DEL 
TERMINAL

En la mayoría de los sistemas, la combinación del ioctl TIOCGWINSZ y la
    señal SIGWINCH se utiliza para mantener una idea precisa del
    tamaño del terminal. El tamaño del terminal se consulta de nuevo cada vez que
    gl_get_line() es llamado y siempre que una señal SIGWINCH es
    
recibida.

En los pocos sistemas donde este mecanismo no está disponible, al
    inicio new_GetLine() primero busca las variables de entorno LINES y
    COLUMNS. Si estas no se encuentran, o contienen
    valores inutilizables, entonces si una base de datos de información de terminal como terminfo o
    termcap está disponible, el tamaño por defecto del terminal se busca en esta
    base de datos. Si esto también falla en proporcionar el tamaño del terminal, se usa un tamaño por defecto de
    80 columnas por 24 
líneas.

Incluso en sistemas que sí soportan ioctl(TIOCGWINSZ), si el
    terminal está en el otro extremo de una línea serie, el controlador del terminal generalmente
    no tiene forma de detectar cuándo ocurre un redimensionamiento ni de consultar cuál es el tamaño
    actual. En tales casos, no se envía ningún SIGWINCH al proceso, y las
    dimensiones devueltas por ioctl(TIOCGWINSZ) no son correctas. La única forma
    de manejar tales instancias es proporcionar una manera para que el usuario introduzca un comando
    que le diga al sistema remoto cuál es el nuevo tamaño. Este comando entonces llamaría a la función gl_set_term_size() para decirle a gl_get_line()
    sobre el cambio de 
tamaño.

  int gl_set_term_size(GetLine *gl, int ncolumn, int nline)
;

Los argumentos ncolumn y nline se usan para especificar
    las nuevas dimensiones del terminal, y no deben ser menores que 1. En sistemas
    que sí soportan ioctl(TIOCGWINSZ), esta función primero llama a
    ioctl(TIOCSWINSZ) para informar al controlador del terminal sobre el cambio en
    el tamaño. En modo de E/S de servidor no bloqueante, si una línea se está introduciendo actualmente,
    la línea de entrada se redibuja para acomodar el tamaño cambiado. Finalmente, los
    nuevos valores se registran en gl para uso futuro por
  gl_get_li
ne().

La función gl_terminal_size() le permite consultar el
    tamaño actual del terminal, e instalar un tamaño de respaldo alternativo para
    los casos en que el tamaño no esté disponible. Tenga cuidado de que el tamaño del terminal no estará
    disponible si se lee de una tubería o de un archivo, por lo que los valores por defecto pueden ser
    importantes incluso en sistemas que sí soportan formas de averiguar el tamaño del 
terminal.

  typedef struct {
    int nline;        /* El terminal tiene nline líneas */
    int ncolumn;      /* El terminal tiene ncolumn columnas */
  } GlTerminalSize;
  GlTerminalSize gl_terminal_size(GetLine *gl,
                                  int def_ncolumn,
                                  int def_nline)
;

Esta función primero actualiza las dimensiones de terminal de respaldo de gl_get_line(), luego registra sus hallazgos en el valor de 
retorno.

Los argumentos def_ncolumn y def_nline especifican el número por defecto
    de columnas y líneas del terminal a usar si el tamaño del terminal no puede ser
    determinado vía ioctl(TIOCGWINSZ) o 
variables d
e entorno.



OCULTANDO   LO QUE 
ESCRIBES

Al introducir información sensible, como contraseñas, es mejor
    no tener el texto que estás introduciendo reflejado en el terminal.
    Además, dicho texto no debería ser registrado en la lista de historial, ya que
    alguien que encuentre tu terminal desatendida podría entonces recuperarlo, o alguien
    que esté husmeando en tus directorios podría verlo en tu archivo de historial. Con
    esto en mente, la función gl_echo_mode() te permite activar y
    desactivar la visualización y el archivo de cualquier texto que sea introducido posteriormente en
    llamadas a gl_get_li
ne().

  int gl_echo_mode(GetLine *gl, int enable)
;

El argumento enable especifica si el texto introducido debe
    ser visible o no. Si es 0, entonces las líneas introducidas posteriormente no
    serán visibles en el terminal, y no serán registradas en la lista de
    historial. Si es 1, entonces las líneas de entrada posteriores se mostrarán a
    medida que se introduzcan, y siempre que el historial no haya sido desactivado vía una
    llamada a gl_toggle_history(), también serán archivadas en la
    lista de historial. Finalmente, si el argumento enable es -1, entonces el
    modo de eco se deja sin cambios, lo que te permite consultar de forma no destructiva
    la configuración actual a través del valor de retorno. En todos los casos, el valor de retorno de
    la función es 0 si el eco estaba desactivado antes de que la función fuera
    llamada, y 1 si estaba 
activado.

Cuando el eco está desactivado, ten en cuenta que aunque la comple
tación con tabulador completará tu prefijo de forma invisible has
ta donde sea posible, las completaciones ambiguas no se mostrarán.



CONSULTAS   DE UN SOLO 
CARÁCTER

Usar gl_get_line() para consultar al usuario por una respuesta de un solo
    carácter, es inconveniente para el usuario, ya que debe presionar la tecla intro o retorno antes de que el carácter que escribió sea devuelto al
    programa. Por lo tanto, la función gl_query_char() ha sido proporcionada para
    consultas de un solo carácter como 
esta.

  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar)
;

Esta función muestra el prompt especificado al inicio de una nueva
    línea, y espera a que el usuario escriba un carácter. Cuando el usuario escribe un
    carácter, gl_query_char() lo muestra a la derecha del prompt,
    inicia una nueva línea, y luego devuelve el carácter al programa llamante. El
    valor de retorno de la función es el carácter que fue escrito. Si la lectura
    tuvo que ser abortada por alguna razón, se devuelve EOF en su lugar. En el
    último caso, la aplicación puede llamar a la previamente documentada
    gl_return_status(), para averiguar qué salió mal. Esto podría, por
    ejemplo, haber sido la recepción de una señal, o el temporizador opcional de inactividad
    
activándose.

Si el usuario simplemente presiona intro, el valor del argumento defchar
    es sustituido. Esto significa que cuando el usuario presiona ya sea nueva línea
    o retorno, el carácter especificado en defchar, se muestra después del
    prompt, como si el usuario lo hubiera escrito, así como ser devuelto a la
    aplicación llamante. Si tal reemplazo no es importante, simplemente pasa
    '0 como el valor de defchar
.

Si el carácter introducido es un carácter no imprimible, se
    muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y
    los caracteres más allá de 127 se muestran en octal, precedidos por una barra 
invertida.

Al igual que con gl_get_line(), el eco del carácter introducido puede
    ser desactivado usando la función gl_echo_mode()
.

Si el proceso llamante es suspendido mientras espera a que el usuario
    escriba su respuesta, el cursor se mueve a la línea que sigue a la línea del prompt,
    luego cuando el proceso se reanuda, el prompt se vuelve a mostrar, y
    gl_query_char() reanuda la espera de que el usuario escriba un 
carácter.

Ten en cuenta que en modo de servidor no bloqueante, (ver gl_io_mode(3)), si una
    línea de entrada incompleta está en proceso de ser leída cuando
    gl_query_char() es llamada, la línea de entrada parcial es descartada, y
    borrada del terminal, antes de que el nuevo prompt sea mostrado. La siguiente llamada
    a gl_get_line() comenzará as
í a editar una
 nueva línea.



LEYENDO   CARÁCTERES 
CRUDOS

Mientras que la función gl_query_char() pide visiblemente al
    usuario un carácter, y muestra lo que escribió, la
    función gl_read_char() lee un carácter de señal del usuario,
    sin escribir nada en el terminal, ni perturbar ninguna línea de entrada
    incompleta. Esto significa que puede ser llamada no solo entre
    llamadas a gl_get_line(), sino también desde funciones de retorno de llamada que la
    aplicación ha registrado para ser llamadas por gl_get_li
ne().

  int gl_read_char(GetLine *gl)
;

En caso de éxito, el valor de retorno de gl_read_char() es el
    carácter que fue leído. En caso de fallo, se devuelve EOF, y la
    función gl_return_status() puede ser llamada para averiguar qué salió
    mal. Las posibilidades incluyen el temporizador opcional de inactividad activándose, la
    recepción de una señal que está configurada para abortar gl_get_line(), o el bloqueo de
    E/S del terminal, cuando se está en modo de E/S de servidor no 
bloqueante.

Ten cuidado de que ciertas teclas del teclado, como las teclas de función y
    las teclas de cursor, usualmente generan al menos 3 caracteres cada una, por lo que una sola llamada
    a gl_read_char() no será suficiente para ide
ntificar dichas pul
saciones de teclas.

MOSTRANDO   TEXTO 
DINÁMICAMENTE

Entre las llamadas a gl_get_line(), la función
    gl_display_text() proporciona una manera conveniente de mostrar
    párrafos de texto, justificados a la izquierda y divididos en una o más líneas de
    terminal según las restricciones del ancho actual de la terminal. Se pueden encontrar
    ejemplos del uso de esta función en los programas de demostración, donde se
    utiliza para mostrar introducciones. En esos ejemplos también se ilustra el uso
    avanzado de prefijos, sufijos y líneas de relleno para dibujar un cuadro alrededor
    del 
texto.

  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string)
;

Si gl no está conectado actualmente a una terminal, por ejemplo
    si la salida de un programa que usa gl_get_line() se está canalizando a
    otro programa o se está redirigiendo a un archivo, entonces se utiliza el valor del
    parámetro
    def_width como el ancho de la 
terminal.

El argumento indentation especifica el número de caracteres
    a usar para sangrar cada línea de salida. El argumento fill_char especifica
    el carácter que se usará para realizar esta 
sangría.

El argumento prefix puede ser NULL, o ser una
    cadena a colocar al comienzo de cada nueva línea (después de cualquier sangría).
    De manera similar, el argumento suffix puede ser NULL, o ser una
    cadena a colocar al final de cada línea. El sufijo se coloca al ras contra el borde
    derecho de la terminal, y cualquier espacio entre su primer carácter y la última
    palabra en esa línea se rellena con el carácter especificado a través del argumento fill_char. Normalmente el carácter de relleno es un 
espacio.

El argumento start le indica a gl_display_text() cuántos
    caracteres ya se han escrito en la línea de terminal actual, y por lo tanto le indica
    el índice de columna inicial del cursor. Dado que el valor de retorno de
    gl_display_text() es el índice de columna final del cursor, al
    pasar el valor de retorno de una llamada al argumento start de la
    siguiente llamada, se puede componer un párrafo que está dividido entre más de una
    cadena llamando a gl_display_text() para cada porción sucesiva del
    párrafo. Tenga en cuenta que son necesarios caracteres de salto de línea literales
    al final de cada párrafo para forzar el inicio de una nueva 
línea.

En caso de error, gl_display_text
() devu
elve -1.

Desde la versión 1.4.0 de libtecla, gl_get_line() ha sido de 8 bits
    limpio. Esto significa que todos los caracteres de 8 bits que son imprimibles en el
    locale actual del usuario ahora se muestran literalmente y se incluyen en la línea
    de entrada devuelta. Asumiendo que el programa que llama contiene correctamente una
    llamada como la 
siguiente,

  setlocale(LC_CTYPE, "")
;

entonces el locale actual lo determina la primera de las variables de entorno LC_CTYPE, LC_ALL, y LANG, que
    se encuentre que contiene un nombre de locale válido. Si ninguna de estas variables
    está definida, o el programa omite llamar a setlocale, entonces se usa el locale
    predeterminado
    C, que es US 7-bit ASCII. En la mayoría de las plataformas tipo unix,
    puede obtener una lista de locales válidos escribiendo el 
comando:

  locale 
-a

en el símbolo del sistema. Se puede encontrar documentación adicional sobre cómo
    el usuario puede hacer uso de esto para introducir caracteres internacionales en la
    página del manual

HILOS

En un programa multi-hilo, debería usar la versión libtecla_r.a

    desde un solo hilo de un programa multi-hilo, siempre que sus otros hilos no usen
    ninguna función termcap o terminfo.
