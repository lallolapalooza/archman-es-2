NOMBRE

glDebugMessageControl - controla el informe de mensajes de depuración en un contexto de depuración

ESPECIFICACIÓN EN C

void glDebugMessageControl(GLenumsource, GLenumtype, GLenumseverity, GLsizeicount, const GLuint *ids, GLbooleanenabled);

PARÁMETROS

source

La fuente de los mensajes de depuración a habilitar o deshabilitar.

type

El tipo de mensajes de depuración a habilitar o deshabilitar.

severity

La gravedad de los mensajes de depuración a habilitar o deshabilitar.

count

La longitud del array ids.

ids

La dirección de un array de enteros sin signo que contiene los identificadores de los mensajes a habilitar o deshabilitar.

enabled

Un indicador booleano que determina si los mensajes seleccionados deben habilitarse o deshabilitarse.

DESCRIPCIÓN

glDebugMessageControl controla el informe de mensajes de depuración generados por un contexto de depuración. Los parámetros source, type y severity forman un filtro para seleccionar mensajes del conjunto de mensajes potenciales generados por el GL.

source puede ser GL_DEBUG_SOURCE_API, GL_DEBUG_SOURCE_WINDOW_SYSTEM_, GL_DEBUG_SOURCE_SHADER_COMPILER, GL_DEBUG_SOURCE_THIRD_PARTY, GL_DEBUG_SOURCE_APPLICATION, GL_DEBUG_SOURCE_OTHER para seleccionar mensajes generados por el uso de la API GL, el sistema de ventanas, el compilador de shaders, herramientas o bibliotecas de terceros, explícitamente por la aplicación o por alguna otra fuente, respectivamente. También puede tomar el valor GL_DONT_CARE. Si source no es GL_DONT_CARE entonces solo se referenciarán los mensajes cuya fuente coincida con source .

type puede ser uno de GL_DEBUG_TYPE_ERROR, GL_DEBUG_TYPE_DEPRECATED_BEHAVIOR, GL_DEBUG_TYPE_UNDEFINED_BEHAVIOR, GL_DEBUG_TYPE_PORTABILITY, GL_DEBUG_TYPE_PERFORMANCE, GL_DEBUG_TYPE_MARKER, GL_DEBUG_TYPE_PUSH_GROUP, GL_DEBUG_TYPE_POP_GROUP, o GL_DEBUG_TYPE_OTHER para indicar el tipo de mensajes que describen errores de GL, intentos de usar funciones obsoletas, activación de comportamiento no definido, problemas de portabilidad, notificaciones de rendimiento, marcadores, eventos de apertura y cierre de grupos, y otros tipos de mensajes, respectivamente. También puede tomar el valor GL_DONT_CARE. Si type no es GL_DONT_CARE entonces solo se referenciarán los mensajes cuyo tipo coincida con type .

severity puede ser uno de GL_DEBUG_SEVERITY_LOW, GL_DEBUG_SEVERITY_MEDIUM, o GL_DEBUG_SEVERITY_HIGH para seleccionar mensajes de baja, media o alta gravedad, o GL_DEBUG_SEVERITY_NOTIFICATION para notificaciones. También puede tomar el valor GL_DONT_CARE. Si severity no es GL_DONT_CARE entonces solo se referenciarán los mensajes cuya gravedad coincida con severity .

ids contiene una lista de count identificadores de mensajes para seleccionar mensajes específicos del conjunto de mensajes disponibles. Si count es cero, el valor de ids se ignora. De lo contrario, solo se seleccionan los mensajes que aparecen en esta lista. En este caso, source y type no pueden ser GL_DONT_CARE y severity debe ser GL_DONT_CARE.

Si enabled es GL_TRUE entonces se habilitan los mensajes que coinciden con el filtro formado por source, type, severity y ids . De lo contrario, esos mensajes se deshabilitan.

NOTAS

Aunque los mensajes de depuración pueden habilitarse en un contexto que no es de depuración, la cantidad y el detalle de dichos mensajes pueden ser sustancialmente inferiores a los de un contexto de depuración. En particular, una implementación válida de la cola de mensajes de depuración en un contexto que no es de depuración puede no producir ningún mensaje.

GL_DEBUG_TYPE_MARKER, GL_DEBUG_TYPE_PUSH_GROUP, GL_DEBUG_TYPE_POP_GROUP, y GL_DEBUG_SEVERITY_NOTIFICATION están disponibles solo si la versión de GL es 4.3 o superior.

ERRORES

Se genera GL_INVALID_VALUE si count es negativo.

Se genera GL_INVALID_ENUM si alguno de source, type o severity no es uno de los tipos de interfaz aceptados.

Se genera GL_INVALID_OPERATION si count no es cero y ya sea source o type es GL_DONT_CARE o si severity no es GL_DONT_CARE.
