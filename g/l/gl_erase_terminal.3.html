DESCRIPCIÓN

La gl_get_line() función es parte de la biblioteca tecla (véase la libtecla(3) página del manual). Si el usuario está escribiendo en un terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de unix. Además de la edición de línea de comandos simple, admite el recuerdo de líneas de comandos introducidas previamente, la completación con TAB de nombres de archivos, y la expansión de comodines de nombres de archivos en línea. La documentación de las características de edición de línea de comandos a nivel de usuario y todas las opciones de configuración del usuario, se puede encontrar en la tecla(7) página del manual. Esta página del manual se ocupa de la documentación para programadores interesados en usar esta biblioteca en su aplicación.

UN EJEMPLO

Lo siguiente muestra un ejemplo completo de cómo usar la gl_get_line() función para obtener entrada del usuario:

  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que el usuario escribió */
    GetLine *gl;   /* El objeto recurso gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* de conjunto de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("You typed: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
  }

En el ejemplo, primero los recursos necesarios por la gl_get_line() función son creados llamando a new_GetLine(). Esto asigna la memoria usada en llamadas subsecuentes a la gl_get_line() función, incluyendo el búfer de historial para registrar líneas introducidas previamente. Luego se leen una o más líneas del usuario, hasta que ocurra un error, o el usuario escriba exit. Entonces finalmente los recursos que fueron asignados por new_GetLine(), son devueltos al sistema llamando a del_GetLine(). Nótese el uso del NULL valor de retorno de del_GetLine() para hacer gl NULL. Esta es una precaución de seguridad. Si el programa posteriormente intenta pasar gl a gl_get_line(), dicha función se quejará, y devolverá un error, en lugar de intentar usar el objeto recurso eliminado.

LAS FUNCIONES USADAS EN EL EJEMPLO

Las descripciones de las funciones usadas en el ejemplo son como sigue:

  GetLine *new_GetLine(size_t linelen, size_t histlen)

Esta función crea los recursos usados por la gl_get_line() función y devuelve un puntero opaco al objeto que los contiene. La longitud máxima de una línea de entrada se especifica a través del linelen argumento, y el número de bytes a asignar para almacenar líneas de historial se establece por el histlen argumento. Las líneas de historial son almacenadas una tras otra en un solo búfer de este tamaño. Nótese que esto significa que el número de líneas de historial que pueden ser almacenadas en cualquier momento dado, depende de las longitudes de las líneas individuales. Si desea colocar un límite superior al número de líneas que pueden ser almacenadas, véase la gl_limit_history() función descrita más adelante. Si no quiere historial en absoluto, especifique histlen como cero, y no se asignará búfer de historial.

En caso de error, se imprime un mensaje en stderr y NULL es devuelto.

  GetLine *del_GetLine(GetLine *gl)

Esta función elimina los recursos que fueron devueltos por una llamada previa a new_GetLine(). Siempre devuelve NULL (es decir, un objeto eliminado). No hace nada si el gl argumento es NULL.

  char *gl_get_line(GetLine *gl, const char *prompt,
                   const char *start_line, int start_pos);

La gl_get_line() función puede ser llamada cualquier número de veces para leer entrada del usuario. El gl argumento debe haber sido previamente devuelto por una llamada a new_GetLine(). El prompt argumento debe ser una cadena normal NUL terminada, especificando el prompt a presentar al usuario. Por defecto los prompts se muestran literalmente, pero si se habilita con la gl_prompt_style() función (véase más adelante), los prompts pueden contener directivas para subrayar, cambiar a y desde fuentes en negrita, o activar y desactivar el resaltado.

Si desea especificar los contenidos iniciales de la línea, para que el usuario la edite, pase la cadena deseada a través del start_line argumento. Luego puede especificar qué carácter de esta línea el cursor inicialmente se posicionadesplazado, usando el start_pos argumento. Este debe ser -1 si desea que el cursor siga al último carácter de la línea inicial. Si no desea precargar la línea de esta manera, envíe start_line como NULL, y establezca start_pos a -1. Tenga en cuenta que el puntero a la línea devuelto por una llamada a gl_get_line() puede pasarse a la siguiente llamada a gl_get_line() a través de start_line. Esto permite que la aplicación tome la última línea introducida y, si contiene un error, la presente de nuevo al usuario para su reedición, con el cursor inicialmente posicionado donde se encontró el error.

La gl_get_line() función devuelve un puntero a la línea introducida por el usuario, o NULL en caso de error o al final de la entrada. El puntero devuelto es parte del objeto recurso gl especificado, y por lo tanto no debe ser liberado por el llamador, ni asumirse que es inmutable de una llamada a la siguiente. Al leer de un usuario en una terminal, siempre habrá un carácter de nueva línea al final de la línea devuelta. Cuando la entrada estándar se toma de una tubería o de un archivo, de manera similar habrá una nueva línea a menos que la línea de entrada fuera demasiado larga para almacenarse en el búfer interno. En este último caso, debería llamar a gl_get_line() de nuevo para leer el resto de la línea. Tenga en cuenta que este comportamiento hace que gl_get_line() sea similar a fgets(). De hecho, cuando stdin no está conectado a una terminal,gl_get_line() simplemente llama a fgets().

EL ESTADO DE RETORNO DE GL_GET_LINE

Como se describió anteriormente, la gl_get_line() función tiene dos valores de retorno posibles; un puntero a la línea de entrada completada, o NULL. Información adicional sobre qué causó que gl_get_line() devolviera está disponible tanto al inspeccionar errnocomo al llamar a la gl_return_status() función.

  GlReturnStatus gl_return_status(GetLine *gl);

Los siguientes son los valores enumerados posibles que esta función devuelve.

  GLR_NEWLINE     -  La última llamada a gl_get_line()
                     devolvió con éxito una línea de
                     entrada completada.
  GLR_BLOCKED     -  gl_get_line() estaba en modo de servidor no bloqueante
                     y devolvió temprano para
                     evitar bloquear el proceso mientras
                     esperaba la E/S de la terminal. La
                     gl_pending_io() función puede
                     usarse para ver qué tipo de E/S
                     gl_get_line() estaba esperando.
                     (véase la gl_io_mode(3) página del manual
                     para más detalles).
  GLR_SIGNAL      -  Una señal fue capturada por
                     gl_get_line() que tenía una
                     disposición después de la señal de
                     GLS_ABORT (véase gl_trap_signal()).
  GLR_TIMEOUT     -  El temporizador de inactividad expiró mientras
                     gl_get_line() esperaba
                     entrada, y la función de retorno de tiempo de espera
                     devolvió GLTO_ABORT.
                     Véase gl_inactivity_timeout() para
                     información sobre tiempos de espera.
  GLR_FDABORT     -  Una llamada de retorno de E/S de la aplicación devolvió
                     GLFD_ABORT (véase gl_watch_fd()).
  GLR_EOF         -  Se alcanzó el fin de archivo. Esto puede ocurrir
                     cuando la entrada proviene de un archivo o una
                     tubería, en lugar de la terminal. También
                     ocurre si el usuario invoca las
                     list-or-eof o del-char-or-list-or-eof
                     acciones al comienzo de una nueva línea.
  GLR_ERROR       -  Un error inesperado causó que
                     gl_get_line() abortara (consulte
                     errno y/o
                     gl_error_message() para más detalles.

Cuando gl_return_status() devuelve GLR_ERROR, y el valor de errno no es suficiente para explicar lo que sucedió, puede usar la función gl_error_message() para solicitar una descripción del último error que ocurrió.

  const char *gl_error_message(GetLine *gl, char *buff,
                               size_t n);

El valor de retorno es un puntero al mensaje que ocurrió. Si el buff argumento es NULL, este será un puntero a un búfer dentro de gl, cuyo valor probablemente cambiará en la siguiente llamada a cualquier función asociada con gl_get_line(). De lo contrario, si se proporciona un argumentobuff no nulo , el mensaje de error, incluyendo el terminador '\0' , se escribirá dentro de los primeros n elementos de este búfer, y el valor de retorno será un puntero al primer elemento de este búfer. Si el mensaje no cabe en el búfer proporcionado, se truncará para que quepa.

FORMATO OPCIONAL DEL PROMPT

Mientras que de forma predeterminada la cadena de prompt que usted especifica se muestra literalmente, sin ninguna interpretación especial de los caracteres dentro de ella, la gl_prompt_style() función puede usarse para habilitar directivas de formato opcionales dentro del prompt.

  void gl_prompt_style(GetLine *gl, GlPromptStyle style);

El style argumento, que especifica el estilo de formato, puede tomar cualquiera de los siguientes valores:

  GL_FORMAT_PROMPT   -  En este estilo, las directivas de
                        formato descritas a continuación, cuando se
                        incluyen en cadenas de prompt, se
                        interpretan de la siguiente manera:
                          %B  -  Mostrar los caracteres
                                 siguientes con una fuente
                                 en negrita.
                          %b  -  Dejar de mostrar los caracteres
                                 con la fuente en negrita.
                          %F  -  Hacer que los caracteres
                                 siguientes parpadeen.
                          %f  -  Desactivar los caracteres
                                 que parpadean.
                          %U  -  Subrayar los caracteres
                                 siguientes.
                          %u  -  Dejar de subrayar los
                                 caracteres.
                          %P  -  Cambiar a una fuente pálida
                                 (media luminosidad).
                          %p  -  Dejar de usar la fuente pálida.
                          %S  -  Resaltar los caracteres
                                 siguientes (también conocido como
                                 modo destacado).
                          %s  -  Dejar de resaltar los
                                 caracteres.
                          %V  -  Activar el vídeo invertido.
                          %v  -  Desactivar el vídeo invertido.
                          %%  -  Mostrar un único carácter %.
                        Por ejemplo, en este modo, una cadena de
                        prompt como "%UOK%u$ " mostraría
                        el prompt "OK$ ",
                        pero con la parte OK subrayada.
                        Tenga en cuenta que aunque un par de
                        caracteres que comienza con un carácter %,
                        pero no coincide con ninguna de las
                        directivas anteriores, se muestra literalmente, si
                        posteriormente se introduce una nueva directiva que sí
                        coincide, el prompt mostrado cambiará,
                        por lo que es mejor usar siempre
                        %% para mostrar un % literal.
                        Tenga en cuenta también que no todas las terminales
                        soportan todos estos atributos de texto, y que algunas
                        sustituyen un atributo diferente por los que faltan.
  GL_LITERAL_PROMPT  -  En este estilo, la cadena de prompt se
                        imprime literalmente. Este es el
                        estilo predeterminado.

FUENTES DE CONFIGURACIÓN ALTERNATIVAS

Como se mencionó anteriormente, de forma predeterminada los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. Sin embargo, en algunas aplicaciones, este único medio de configuración es un problema. Esto es particularmente cierto en el software embebido, donde no hay un sistema de archivos del cual leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de asignaciones de teclas para emular una interfaz de teclado heredada. Para atender a tales casos, la siguiente función permite a la aplicación controlar desde dónde se lee la información de configuración.

  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file);

Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc del usuario, se lean de una cadena, un archivo de configuración específico de la aplicación, y/o un archivo de configuración específico del usuario, o de ninguno. Si esta función se llama antes de la primera llamada a gl_get_line(), el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line() se deshabilita, por lo que toda la configuración debe lograrse usando las fuentes de configuración especificadas con esta función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados entre sí en la cadena por caracteres de nueva línea incrustados. Si app_file != NULL entonces se interpreta como la ruta de archivo completa de un archivo de configuración específico de la aplicación. Si user_file != NULL entonces se interpreta como la ruta de archivo completa de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente llamada,

  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc");

el app_string argumento hace que la aplicación que llama comience en modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso de la campana de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración de todo el sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario desde un archivo opcional .teclarc en el directorio de inicio del usuario. Tenga en cuenta que los argumentos se listan en orden ascendente de prioridad, con el contenido de app_string siendo potencialmente anulado por comandos en app_file, y los comandos en app_file siendo potencialmente anulados por comandos en user_file.

Puede llamar a esta función tantas veces como sea necesario, siendo los resultados acumulativos, pero tenga en cuenta que las copias de cualquier nombre de archivo especificado a través de app_file y user_file se registran internamente para su uso posterior por la función de enlace de teclas read-init-files , así que si planea llamar a esta función varias veces, asegúrese de que la última llamada especifique los nombres de archivo que desea que se vuelvan a leer cuando el usuario solicite que se releer los archivos de configuración.

Las secuencias de teclas individuales también se pueden enlazar y desenlazar usando la función gl_bind_keyseq() .

  int gl_bind_keyseq(GetLine *gl, GlKeyOrigin origin,
                     const char *keyseq,
                     const char *action);

El argumento origin especifica la prioridad del enlace, según para quién se está estableciendo, y debe ser uno de los siguientes dos valores.

  GL_USER_KEY   -   El usuario solicitó este enlace de teclas.
  GL_APP_KEY    -   Este es un enlace predeterminado establecido por la
                    aplicación.

Cuando se han especificado enlaces de usuario y de aplicación para una misma secuencia de teclas, el enlace del usuario tiene prioridad. El enlace de la aplicación se restablece posteriormente si el enlace del usuario se desenlaza más tarde a través de otra llamada a esta función, o una llamada a gl_configure_getline().

El argumento keyseq especifica la secuencia de teclas a enlazar o desenlazar, y se expresa de la misma manera que en un archivo de configuración ~/.teclarc . El argumento action debe ser una cadena que contenga el nombre de la acción a la que enlazar la secuencia de teclas, o debe ser NULL o "" para desenlazar la secuencia de teclas.

COMPLETADO DE PALABRAS PERSONALIZADO

Si en su aplicación desea que la completación con TAB complete otras cosas además de o en lugar de nombres de archivo, puede organizar esto registrando una función de retorno de completación alternativa, a través de una llamada a la función gl_customize_completion() .

  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn);

El argumento data proporciona una manera para que su aplicación pase información arbitraria y específica de la aplicación a la función de retorno. Esto se pasa a la función de retorno cada vez que se llama. Podría, por ejemplo, apuntar a la tabla de símbolos de la que se deben buscar las posibles completaciones. El argumento match_fn especifica la función de retorno a llamar. El tipo de función CplMatchFn está definido en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y definir el prototipo de funciones de retorno. La declaración y las responsabilidades de las funciones de retorno se describen en profundidad en la página del manual de cpl_complete_word(3).

En resumen, la función de retorno es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario presionó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar las posibles completaciones de esta palabra y registrarlas una por una en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion() . Si la función de retorno desea proporcionar completación de nombres de archivo además de sus propias completaciones específicas, tiene la opción de llamar por sí misma a la función de retorno de completación de nombres de archivo incorporada. Esto también está documentado en la página del manual de cpl_complete_word(3) .

Tenga en cuenta que si desea que gl_get_line() devuelva la línea de entrada actual cuando se haya realizado una completación exitosa, puede organizar esto cuando llame a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de nueva línea. Si hace esto, la línea de entrada se actualizará para mostrar la completación, junto con cualquier sufijo de continuación hasta el carácter de nueva línea, y luego gl_get_line() devolverá esta línea de entrada.

Si, por alguna razón, su función de retorno necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto iniciará una nueva línea después de la línea de entrada que se está editando actualmente, restablecerá la E/S normal de la terminal y le dirá a gl_get_line() que la línea de entrada necesitará ser redibujada cuando la función de retorno regrese.

AÑADIENDO ACCIONES DE COMPLETACIÓN

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de completación predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que se puedan enlazar diferentes tipos de completación de palabras a diferentes secuencias de teclas. Esto se logra usando la función gl_completion_action() .

  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq);

Los argumentos data y match_fn se describen en la página del manual de cpl_complete_word y especifican la función de retorno que debe invocarse para identificar las posibles completaciones. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar cualquier completación ambigua posible, o si simplemente debe mostrar la lista de posibles completaciones sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre con el que los archivos de configuración y las futuras invocaciones de esta función deben referirse a la acción. Este debe ser el nombre de una acción de completación existente que se va a cambiar, o un nombre nuevo no utilizado para una nueva acción. Finalmente, el argumento keyseq especifica la secuencia de teclas predeterminada a la que enlazar la acción. Si esto es NULL, no se enlazará ninguna nueva secuencia de teclas a la acción.

Tenga cuidado de que para que el usuario pueda cambiar la secuencia de teclas que está enlazada a las acciones instaladas de esta manera, cuando llame a gl_completion_action() para instalar una acción determinada por primera vez, debe hacerlo entre la llamada a new_GetLine() y la primera llamada a gl_get_line(). De lo contrario, cuando se lea el archivo de configuración del usuario en la primera llamada a gl_get_line(), el nombre de su acción adicional no será conocido, y cualquier referencia a ella en el archivo de configuración generará un error.

DEFINIENDO ACCIONES PERSONALIZADAS

Aunque las acciones de enlace de teclas incorporadas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, enlazadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza que correspondía a un número de pieza precedente al cursor. Tal característica está claramente fuera del alcance de las funciones de acción incorporadas. Así que para tales casos especiales, se proporciona la función gl_register_action() .

Esta función permite a la aplicación registrar una función externa, fn, que a partir de entonces será llamada siempre que el usuario introduzca la secuencia de teclas especificada, keyseq, o que introduzca cualquier otra secuencia de teclas que el usuario enlace posteriormente al nombre de acción especificado, name, en su archivo de configuración. El argumento data puede ser un puntero a cualquier cosa que la aplicación desee que se pase a la función de acción, fn, cada vez que esa función sea invocada.

La función de acción, fn, debe declararse usando la siguiente macro, que está definida en libtecla.h.

  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char *line)

Los argumentos gl y data son aquellos que se pasaron previamente a gl_register_action() cuando se registró la función de acción. El argumento count es un argumento numérico que el usuario tiene la opción de introducir usando la acción digit-argument , antes de invocar la acción. Si el usuario no introduce un número, entonces el argumento count se establece en 1. Nominalmente, este argumento se interpreta como un conteo de repetición, lo que significa que la acción debe repetirse esa cantidad de veces. En la práctica, sin embargo, para algunas acciones un conteo de repetición tiene poco sentido. En tales casos, las acciones pueden simplemente ignorar el argumento count o usar su valor para un propósito diferente.

Se pasa una copia de la línea de entrada actual en el argumento de solo lectura line . La posición actual del cursor dentro de esta cadena está dada por el índice contenido en el argumento curpos . Tenga en cuenta que no se permite la manipulación directa de la línea de entrada y la posición del cursor. Esto se debe a que las reglas dictadas por varios modos, como el modo vi versus el modo emacs, el modo sin eco, y el modo de inserción versus el modo de sobrescritura, etc., hacen que sea demasiado complejo para un desarrollador de aplicaciones escribir una acción de edición que cumpla con las reglas, así como restringir cambios futuros en los internos de gl_get_line(). Una solución potencial a este dilema sería permitir que la función de acción edite la línea usando las acciones de edición existentes. Esto está actualmente bajo consideración.

Si la función de acción desea escribir texto en la terminal, sin que esto se mezcle con el texto mostrado de la línea de entrada, o leer de la terminal sin tener que manejar la E/S cruda de la terminal, entonces antes de realizar cualquiera de estas operaciones, debe suspender temporalmente la edición de línea llamando a la función gl_normal_io() . Esta función vacía cualquier salida pendiente a la terminal, mueve el cursor al inicio de la línea que sigue a la última línea de terminal de la línea de entrada, y luego restaura la terminal a un estado adecuado para su uso con las instalaciones de stdio de C. Lo último incluye cosas como restaurar el mapeo normal de \n a \r\n, y, cuando se está en modo servidor, restaurar la forma normal de bloqueo de la E/S de la terminal. Después de haber llamado a esta función, la función de acción puede leer de y escribir en la terminal sin temor a crear un desastre. No es necesario que la función de acción restaure el entorno de edición original antes de regresar. Esto lo hace automáticamente gl_get_line() después de que la función de acción regrese. El siguiente es un ejemplo sencillo de una función de acción que escribe la frase "Hello world" en una nueva línea de terminal después de la línea que se está editando. Cuando esta función regresa, la línea de entrada se redibuja en la línea que sigue a la línea "Hello world", y la edición de línea se reanuda.

De lo contrario, comenzará a escribir en una línea que ya contiene parte de la línea de entrada mostrada. Esto no causa ningún daño, pero se ve un poco feo, por lo que la GL_SUSPEND_INPUT combinación es mejor si sabe que siempre va a escribir en la terminal.

MANEJO CONFIABLE DE SEÑALES

El manejo de señales es sorprendentemente difícil de hacer de forma confiable sin condiciones de carrera (race conditions). En gl_get_line() se ha tenido mucho cuidado para permitir que las aplicaciones realicen un manejo de señales confiable alrededor de gl_get_line(). Esta sección explica cómo hacer uso de esto.

Como ejemplo de los problemas que pueden surgir si la aplicación no está escrita correctamente, imagine que su aplicación tiene un manejador de señal SIGINT que establece un indicador (flag) global. Ahora suponga que la aplicación prueba este indicador justo antes de invocar gl_get_line(). Si una señal SIGINT resulta ser recibida en la pequeña ventana de tiempo entre la instrucción que prueba el valor de este indicador, y la instrucción que llama a gl_get_line(), entonces gl_get_line() no verá la señal, y no será interrumpido. Como resultado, la aplicación no podrá responder a la señal hasta que el usuario termine de ingresar la línea de entrada y gl_get_line() retorne. Dependiendo de la aplicación, esto podría o no ser un desastre, pero como mínimo confundiría al usuario.

La forma de evitar tales problemas es hacer lo siguiente.

1. Si es necesario, use la función gl_trap_signal() para
configurar gl_get_line() para que aborte cuando se capturen
señales importantes.

2. Configure gl_get_line() de tal manera que si alguna de las
señales que captura están bloqueadas cuando se llama a
gl_get_line() , sean desbloqueadas
automáticamente durante los momentos en que gl_get_line() está
esperando E/S (I/O). Esto puede hacerse ya sea
por señal individual, llamando a la
gl_trap_signal() función, y especificando el atributo
GLS_UNBLOCK de la señal, o globalmente llamando a la
función gl_catch_blocked() .

     void gl_catch_blocked(GetLine *gl);


Esta función simplemente agrega el atributo GLS_UNBLOCK a todas las señales que actualmente está configurada para
capturar.
3. Justo antes de llamar a

gl_get_line() , bloquee la entregade todas las señales que
gl_get_line() está configurada para capturar. Esto puede hacerse usando la función POSIX
sigprocmask()
en conjunto con la función
gl_list_signals() .

      int gl_list_signals(GetLine *gl, sigset_t *set);


Esta función retorna el conjunto de señales que actualmente está
configurada para capturar en el set argumento,
el cual está en la forma requerida por sigprocmask().

4. En el ejemplo, ahora se probaría el indicador global que
el manejador de señales establece, sabiendo que ahora no hay
peligro de que este indicador se establezca de nuevo hasta que
gl_get_line() desbloquee sus señales mientras realiza
E/S (I/O).

5. Eventualmente gl_get_line() retorna, ya sea porque
se capturó una señal, ocurrió un error, o el usuario
terminó de ingresar su línea de entrada.

6. Ahora se verificaría el indicador global de señal de nuevo, y si
está establecido, se respondería a él, y se pondría el indicador a cero.

Use sigprocmask() para desbloquear las señales que fueron
bloqueadas en el paso 3.

La misma técnica puede usarse alrededor de ciertas funciones POSIX conscientes de señales, tales como sigsetjmp() y sigsuspend(), y en particular, la primera de estas dos funciones puede usarse en conjunto con siglongjmp() para implementar un manejo de señales libre de condiciones de carrera alrededor de otras llamadas al sistema de larga duración. La forma de hacer esto se explica a continuación, mostrando cómo gl_get_line() logra capturar señales de forma confiable alrededor de llamadas a funciones como read() y select() sin condiciones de carrera.

Lo primero que gl_get_line() hace, siempre que es llamada, es usar la función POSIX sigprocmask() para bloquear la entrega de todas las señales que actualmente está configurada para capturar. Esto es redundante si la aplicación ya las ha bloqueado, pero no hace ningún daño. Deshace este paso justo antes de retornar.

Siempre que gl_get_line() necesita llamar a read() o select() para esperar entrada del usuario, primero llama a la función POSIX sigsetjmp() , asegurándose de especificar un valor distinto de cero para su savesigs argumento. La razón de este último argumento se aclarará en breve.

Si sigsetjmp() retorna cero, gl_get_line() luego hace lo siguiente.

a. Usa la función POSIX sigaction() para registrar
   un manejador de señales temporal para todas las señales que está
   configurada para capturar. Este manejador de señales hace dos
   cosas.
   1. Registra el número de la señal que fue recibida
      en una variable de ámbito de archivo.
   2. Luego llama a la función POSIX siglongjmp()
      usando el búfer que fue pasado a
      sigsetjmp() como su primer argumento, y
      un valor distinto de cero como su segundo argumento.
   Cuando este manejador de señales está registrado, el miembro sa_mask
   del argumento struct sigaction act de la
   llamada a sigaction() está configurado para contener todas
   las señales que gl_get_line() está capturando. Esto
   asegura que solo una señal sea capturada a la vez por
   nuestro manejador de señales, lo que a su vez asegura que múltiples
   instancias de nuestro manejador de señales no interfieran entre sí.
b. Ahora que el manejador de señales ha sido configurado,
   gl_get_line() desbloquea todas las señales que está
   configurada para capturar.
c. Luego llama a las llamadas al sistema read() o select() para esperar entrada del teclado.
d. Si esta llamada al sistema retorna (es decir, no se recibe ninguna señal),
   gl_get_line() vuelve a bloquear la entrega de las señales de
   interés.
e. Luego reinstaura los manejadores de señales que fueron
   desplazados por el que acaba de instalarse.

Alternativamente, si sigsetjmp() retorna un valor distinto de cero, esto significa que una de las señales atrapadas fue capturada mientras se ejecutaban los pasos anteriores. Cuando esto sucede, gl_get_line() hace lo siguiente.

Primero, tenga en cuenta que cuando una llamada a siglongjmp() hace que sigsetjmp() retorne, siempre que el argumento savesigs de sigsetjmp() fuera distinto de cero, como se especificó anteriormente, la máscara de señales del proceso se restaura a cómo estaba cuando se sigsetjmp() fue llamado. Esta es la importante diferencia entre sigsetjmp() y el antiguo y problemático setjmp(), y es el ingrediente esencial que hace posible evitar condiciones de carrera en el manejo de señales. Debido a esto, se garantiza que todas las señales que bloqueamos antes de llamar a sigsetjmp() estén bloqueadas nuevamente tan pronto como se capture cualquier señal. Las siguientes declaraciones, que se ejecutan a continuación, por lo tanto, se garantiza que se ejecutarán sin que se capturen más señales.

1. Si así lo indica la configuración gl_get_line() de
la señal que fue capturada,
gl_get_line() restaura los atributos del terminal a
el estado que tenían cuando gl_get_line() fue
llamado. Esto es particularmente importante para las señales que
suspenden o terminan el proceso, ya que de lo contrario el
terminal quedaría en un estado inutilizable.

2. Luego reinstala los manejadores de señales de la aplicación.

3. Luego usa la función de la biblioteca estándar de C raise()
para reenviar a la aplicación la señal que
fue capturada.

3. A continuación, desbloquea la entrega de la señal que acabamos de
enviar. Esto resulta en que la señal que acabó de ser enviada
vía raise(), sea capturada por el manejador de señales
original de la aplicación, que ahora puede manejarla como
considere oportuno.

4. Si el manejador de señales retorna (es decir, no termina
el proceso), gl_get_line() bloquea la entrega de la
señal anterior nuevamente.

5. Luego deshace cualquier acción realizada en el primero de los
pasos anteriores, y vuelve a mostrar la línea, si la configuración de la señal
lo requiere.

6. gl_get_line() luego o bien reanuda el intento de
leer un carácter, o aborta, dependiendo de la
configuración de la señal que fue capturada.

Lo que los pasos anteriores hacen en esencia es tomar señales entregadas de forma asíncrona y manejarlas de forma síncrona, una a la vez, en un punto del código donde gl_get_line() tiene control completo sobre su entorno.

EL TAMAÑO DEL TERMINAL

En la mayoría de los sistemas, la combinación de TIOCGWINSZ ioctl y la señal SIGWINCH se utiliza para mantener una idea precisa del tamaño del terminal. El tamaño del terminal se consulta nuevamente cada vez que se llama a gl_get_line() y siempre que se recibe una señal SIGWINCH .

En los pocos sistemas donde este mecanismo no está disponible, al inicio new_GetLine() primero busca las variables de entorno LINES y COLUMNS . Si no se encuentran, o contienen valores inutilizables, entonces si hay disponible una base de datos de información del terminal como terminfo o termcap, se busca el tamaño por defecto del terminal en esta base de datos. Si esto tampoco proporciona el tamaño del terminal, se usa un tamaño por defecto de 80 columnas por 24 líneas.

Incluso en sistemas que sí soportan ioctl(TIOCGWINSZ), si el terminal está en el otro extremo de una línea serie, el controlador del terminal generalmente no tiene forma de detectar cuándo ocurre un redimensionamiento ni de consultar cuál es el tamaño actual. En tales casos no se envía SIGWINCH al proceso, y las dimensiones devueltas por ioctl(TIOCGWINSZ) no son correctas. La única manera de manejar tales instancias es proporcionar una forma para que el usuario introduzca un comando que le diga al sistema remoto cuál es el nuevo tamaño. Este comando entonces llamaría a la función gl_set_term_size() para informar a gl_get_line() sobre el cambio de tamaño.

  int gl_set_term_size(GetLine *gl, int ncolumn, int nline);

Los argumentos ncolumn y nline se utilizan para especificar las nuevas dimensiones del terminal, y no deben ser menores que 1. En sistemas que sí soportan ioctl(TIOCGWINSZ), esta función primero llama a ioctl(TIOCSWINSZ) para informar al controlador del terminal sobre el cambio en el tamaño. En el modo de E/S de servidor no bloqueante, si actualmente se está introduciendo una línea, la línea de entrada se redibuja para acomodar el tamaño cambiado. Finalmente, los nuevos valores se registran en gl para uso futuro por gl_get_line().

La función gl_terminal_size() le permite consultar el tamaño actual del terminal, e instalar un tamaño de reserva alternativo para los casos en que el tamaño no esté disponible. Tenga cuidado de que el tamaño del terminal no estará disponible si se lee de una tubería o un archivo, por lo que los valores por defecto pueden ser importantes incluso en sistemas que sí soportan formas de averiguar el tamaño del terminal.

  typedef struct {
    int nline;        /* El terminal tiene nline líneas */
    int ncolumn;      /* El terminal tiene ncolumn columnas */
  } GlTerminalSize;
  GlTerminalSize gl_terminal_size(GetLine *gl,
                                  int def_ncolumn,
                                  int def_nline);

Esta función primero actualiza las dimensiones de reserva del terminal de gl_get_line(), luego registra sus hallazgos en el valor de retorno.

El def_ncolumn y def_nline especifican el número por defecto de columnas y líneas del terminal a usar si el tamaño del terminal no se puede determinar vía ioctl(TIOCGWINSZ) o variables de entorno.

OCULTANDO LO QUE ESCRIBES

Al introducir información sensible, como contraseñas, es mejor no tener el texto que está introduciendo reflejado en el terminal. Además, dicho texto no debería ser registrado en la lista de historial, ya que alguien que encuentre su terminal sin atender podría entonces recuperarlo, o alguien que esté husmeando en sus directorios podría verlo en su archivo de historial. Teniendo esto en cuenta, la función gl_echo_mode() le permite activar y desactivar la visualización y el archivo de cualquier texto que se introduzca posteriormente en las llamadas a gl_get_line().

  int gl_echo_mode(GetLine *gl, int enable);

El argumento enable especifica si el texto introducido debe ser visible o no. Si es 0, entonces las líneas introducidas posteriormente no serán visibles en el terminal, y no serán registradas en la lista de historial. Si es 1, entonces las líneas de entrada posteriores se mostrarán a medida que se introduzcan, y siempre que el historial no haya sido desactivado mediante una llamada a gl_toggle_history(), también serán archivadas en la lista de historial. Finalmente, si el argumento enable es -1, entonces el modo de eco se deja sin cambios, lo que le permite consultar de forma no destructiva la configuración actual a través del valor de retorno. En todos los casos, el valor de retorno de la función es 0 si el eco estaba desactivado antes de que se llamara a la función, y 1 si estaba activado.

Cuando el eco está desactivado, tenga en cuenta que aunque la finalización con tabulador completará invisiblemente su prefijo hasta donde sea posible, las finalizaciones ambiguas no se mostrarán.

CONSULTAS DE UN SOLO CARÁCTER

Usar gl_get_line() para consultar al usuario para una respuesta de un solo carácter, es inconveniente para el usuario, ya que debe presionar la tecla enter o return antes de que el carácter que escribió sea devuelto al programa. Por lo tanto, la función gl_query_char() ha sido proporcionada para consultas de un solo carácter como esta.

  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar);

Esta función muestra el prompt especificado al comienzo de una nueva línea, y espera a que el usuario escriba un carácter. Cuando el usuario escribe un carácter, gl_query_char() lo muestra a la derecha del prompt, inicia una nueva línea, y luego devuelve el carácter al programa que lo llamó. El valor de retorno de la función es el carácter que fue escrito. Si la lectura tuvo que ser abortada por alguna razón, EOF se devuelve en su lugar. En este último caso, la aplicación puede llamar a la previamente documentada gl_return_status(), para averiguar qué salió mal. Esto podría haber sido, por ejemplo, la recepción de una señal, o el temporizador opcional de inactividad activándose.

Si el usuario simplemente presiona enter, el valor del argumento defchar es sustituido. Esto significa que cuando el usuario presiona newline o return, el carácter especificado en defchar, se muestra después del prompt, como si el usuario lo hubiera escrito, así como ser devuelto a la aplicación que lo llamó. Si tal reemplazo no es importante, simplemente pase '0 como el valor de defchar.

Si el carácter introducido es un carácter no imprimible, se muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y los caracteres más allá de 127 se muestran en octal, precedidos por una barra invertida.

Al igual que con gl_get_line(), el eco del carácter introducido puede ser desactivado usando la función gl_echo_mode() .

Si el proceso que llama es suspendido mientras espera a que el usuario escriba su respuesta, el cursor se mueve a la línea que sigue a la línea del prompt, luego cuando el proceso se reanuda, el prompt se vuelve a mostrar, y gl_query_char() reanuda la espera de que el usuario escriba un carácter.

Tenga en cuenta que en el modo de servidor no bloqueante, (vea gl_io_mode(3)), si una línea de entrada incompleta está en proceso de ser leída cuando se llama a gl_query_char() , la línea de entrada parcial se descarta, y se borra del terminal, antes de que se muestre el nuevo prompt. La siguiente llamada a gl_get_line() comenzará por lo tanto a editar una nueva línea.

LEYENDO CARÁCTERES CRUDOS

Mientras que la función gl_query_char() pide visiblemente al usuario un carácter, y muestra lo que escribió, la función gl_read_char() lee un carácter del usuario, sin escribir nada en el terminal, ni perturbar ninguna línea de entrada incompleta. Esto significa que puede ser llamada no solo entre gl_get_line(), sino también desde funciones de retorno que la aplicación ha registrado para ser llamadas por gl_get_line().

  int gl_read_char(GetLine *gl);

En caso de éxito, el valor de retorno de gl_read_char() es el carácter que fue leído. En caso de fallo, EOF se devuelve, y la función gl_return_status() puede ser llamada para averiguar qué salió mal. NAME

gl_erase_terminal, gl_display_text - clear the terminal and display text dynamically.

SYNOPSIS

#include <tecla.h>

int gl_erase_terminal(GetLine *gl);

int gl_display_text(GetLine *gl, int indentation,
                    const char *prefix,
                    const char *suffix, int fill_char,
                    int def_width, int start,
                    const char *string);

DESCRIPTION

The functions of the getline module are designed to provide a convenient interface to the user for typing commands. They are intended to be used in interactive command-line applications.

The library provides a means of displaying text dynamically, and of clearing the terminal screen.

In normal usage, the calling program will have initialized the GetLine structure by calling gl_init(3), and will then repeatedly call gl_get_line(3) to read commands.

The functionality provided by these functions is intended to be used to enhance the user interface of applications that use the libtecla library.

When the terminal is cleared, the prompt is redisplayed, and the current input line is redrawn. This is achieved by writing an appropriate sequence of terminal control characters to the terminal, and then redisplaying the prompt, together with any text that has already been typed on the current line. In non-blocking server-I/O mode, the redisplay is delayed until the next call to gl_get_line(3), in order to avoid potential race conditions.

It is not possible to distinguish between different kinds of control characters, such as those generated by arrow keys and function keys. Therefore, it is not possible to identify such keystrokes.

CLEARING THE TERMINAL

The calling program can clear the terminal by calling gl_erase_terminal(). In non-blocking server-I/O mode, this function also arranges for the current input line to be redrawn from scratch when gl_get_line() is next called.

  int gl_erase_terminal(GetLine *gl);

DISPLAYING TEXT DYNAMICALLY

Between calls to gl_get_line(), the gl_display_text() function provides a convenient way to display paragraphs of text, left-justified and split over one or more terminal lines according to the constraints of the current width of the terminal. Examples of the use of this function may be found in the demo programs, where it is used to display introductions. In those examples the advanced use of optional prefixes, suffixes and filled lines to draw a box around the text is also illustrated.

  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string);

If gl isn't currently connected to a terminal, for example if the output of a program that uses gl_get_line() is being piped to another program or redirected to a file, then the value of the def_width parameter is used as the terminal width.

The indentation argument specifies the number of characters to use to indent each line of ouput. The fill_char argument specifies the character that will be used to perform this indentation.

The prefix argument can either be NULL, or be a string to place at the beginning of each new line (after any indentation). Similarly, the suffix argument can either be NULL, or be a string to place at the end of each line. The suffix is placed flush against the right edge of the terminal, and any space between its first character and the last word on that line is filled with the character specified via the fill_char argument. Normally the fill-character is a space.

The start argument tells gl_display_text() how many characters have already been written to the current terminal line, and thus tells it the starting column index of the cursor. Since the return value of gl_display_text() is the ending column index of the cursor, by passing the return value of one call to the start argument of the next call, a paragraph that is broken between more than one string can be composed by calling gl_display_text() for each successive portion of the paragraph. Note that literal newline characters are necessary at the end of each paragraph to force a new line to be started.

On error, gl_display_text() returns -1.

CALLBACK FUNCTION FACILITIES

Unless otherwise stated, callback functions, such as tab completion callbacks and event callbacks should not call any functions in this module. The following functions, however, are designed specifically to be used by callback functions.

Calling the gl_replace_prompt() function from a callback tells gl_get_line() to display a different prompt when the callback returns. Except in non-blocking server mode, it has no effect if used between calls to gl_get_line(). In non-blocking server mode (see the gl_io_mode(3) man page, when used between two calls to gl_get_line() that are operating on the same input line, the current input line will be re-drawn with the new prompt on the following call to gl_get_line().

  void gl_replace_prompt(GetLine *gl, const char *prompt);

INTERNATIONAL CHARACTER SETS

Since libtecla version 1.4.0, gl_get_line() has been 8-bit clean. This means that all 8-bit characters that are printable in the user's current locale are now displayed verbatim and included in the returned input line. Assuming that the calling program correctly contains a call like the following,

  setlocale(LC_CTYPE, "");

then the current locale is determined by the first of the environment variables LC_CTYPE, LC_ALL, and LANG, that is found to contain a valid locale name. If none of these variables are defined, or the program neglects to call setlocale, then the default C locale is used, which is US 7-bit ASCII. On most unix-like platforms, you can get a list of valid locales by typing the command:

  locale -a

at the shell prompt. Further documentation on how the user can make use of this to enter international characters can be found in the tecla(7) man page.

THREAD SAFETY

In a multi-threaded program, you should use the libtecla_r.a version of the library. This uses reentrant versions of system functions, where available. Unfortunately neither terminfo nor termcap were designed to be reentrant, so you can't safely use the functions of the getline module in multiple threads (you can use the separate file-expansion and word-completion modules in multiple threads, see the corresponding man pages for details). However due to the use of POSIX reentrant functions for looking up home directories etc, it is safe to use this module from a single thread of a multi-threaded program, provided that your other threads don't use any termcap or terminfo functions.
