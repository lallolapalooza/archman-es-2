DESCRIPCIÓ

N

La función gl_get_line() es parte de la biblioteca tecla (véase la página man libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le solicita una línea de entrada, y luego proporciona instalaciones de edición interactivas, similares a las del shell tcsh de unix. Además de la edición simple de línea de comandos, soporta el recuerdo de líneas de comandos previamente introducidas, la completación con TAB de nombres de archivos, y la expansión en línea de comodines de nombres de archivos. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario, puede encontrarse en la página man tecla(7). The data argument provides a way for your application to pass arbitrary, application-specific information to the callback function. This is passed to the callback every time that it is called. It might for example, point to the symbol table from which possible completions are to be sought. The match_fn argument specifies the callback function to be called. The CplMatchFn function type is defined in libtecla.h, as is a CPL_MATCH_FN() macro that you can use to declare and prototype callback functions. The declaration and responsibilities of callback functions are described in depth in the cpl_complete_word(3) man

page.

In brief, the callback function is responsible for looking backwards in the input line, back from the point at which the user pressed TAB, to find the start of the word being completed. It then must lookup possible completions of this word, and record them one by one in the WordCompletion object that is passed to it as an argument, by calling the cpl_add_completion() function. If the callback function wishes to provide filename completion in addition to its own specific completions, it has the option of itself calling the builtin file-name completion callback. This also, is documented in the cpl_complete_word(3) man

page.

Note that if you would like gl_get_line() to return the current input line when a successful completion is been made, you can arrange this when you call cpl_add_completion(), by making the last character of the continuation suffix a newline character. If you do this, the input line will be updated to display the completion, together with any contiuation suffix up to the newline character, then gl_get_line() will return this input

line.

If, for some reason, your callback function needs to write something to the terminal, it must call gl_normal_io() before doing so. This will start a new line after the input line that is currently being edited, reinstate normal terminal I/O, and tell gl_get_line() that the input line will n

PERSONALIZADAS

Although the built-in key-binding actions are sufficient for the needs of most applications, occasionally a specialized application may need to define one or more custom actions, bound to application-specific key-sequences. For example, a sales application would benefit from having a key-sequence that displayed the part name that corresponded to a part number preceding the cursor. Such a feature is clearly beyond the scope of the built-in action functions. So for such special cases, the gl_register_action() function is

provided. 
  int gl_register_action(GetLine *gl, void *data,
			 GlActionFn *fn, const char *name,
			 const char *keyseq)
;

This function lets the application register an external function, fn, that will thereafter be called whenever either the specified key-sequence, keyseq, is entered by the user, or the user enters any other key-sequence that the user subsequently binds to the specified action name, name, in their configuration file. The data argument can be a pointer to anything that the application wishes to have passed to the action function, fn, whenever that function is

invoked.

The action function, fn, should be declared using the following macro, which is defined in libtecl

a.h. 
  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char
*line)

The gl and data arguments are those that were previously passed to gl_register_action() when the action function was registered. The count argument is a numeric argument which the user has the option of entering using the digit-argument action, before invoking the action. If the user doesn't enter a number, then the count argument is set to 1. Nominally this argument is interpreted as a repeat count, meaning that the action should be repeated that many times. In practice however, for some actions a repeat count makes little sense. In such cases, actions can either simply ignore the count argument, or use its value for a different

purpose.

A copy of the current input line is passed in the read-only line argument. The current cursor position within this string is given by the index contained in the curpos argument. Note that direct manipulation of the input line and the cursor position is not permitted. This is because the rules dicated by various modes, such as vi mode versus emacs mode, no-echo mode, and insert mode versus overstrike mode etc, make it too complex for an application writer to write a conforming editing action, as well as constrain future changes to the internals of gl_get_line(). A potential solution to this dilema would be to allow the action function to edit the line using the existing editing actions. This is currently under

consideration.

If the action function wishes to write text to the terminal, without this getting mixed up with the displayed text of the input line, or read from the terminal without having to handle raw terminal I/O, then before doing either of these operations, it must temporarily suspend line editing by calling the gl_normal_io() function. This function flushes any pending output to the terminal, moves the cursor to the start of the line that follows the last terminal line of the input line, then restores the terminal to a state that is suitable for use with the C stdio facilities. The latter includes such things as restoring the normal mapping of \n to \r\n, and, when in server mode, restoring the normal blocking form of terminal I/O. Having called this function, the action function can read from and write to the terminal without the fear of creating a mess. It isn't necessary for the action function to restore the original editing environment before it returns. This is done automatically by gl_get_line() after the action function returns. The following is a simple example of an action function which writes the sentence "Hello world" on a new terminal line after the line being edited. When this function returns, the input line is redrawn on the line that follows the "Hello world" line, and line editing

resumes. 
  static GL_ACTION_FN(say_hello_fn)
  {
    if(gl_normal_io(gl))   /* Temporarily suspend editing */
      return GLA_ABORT;
    printf("Hello world\n");
    return GLA_CONTINUE;
}

CAMBIO DE TERMINALES

La función constructora new_GetLine() asume que la entrada se leerá de stdin y la salida se escribirá en stdout. La siguiente función le permite cambiar a diferentes flujos de entrada y salida.

  int gl_change_terminal(GetLine *gl, FILE *input_fp,
                         FILE *output_fp, const char *term);

El argumento gl es el objeto devuelto por new_GetLine(). El argumento input_fp especifica el flujo del que se leerá y output_fp especifica el flujo al que se escribirá. Solo si ambos se refieren a una terminal, se habilitará la entrada interactiva de terminal. De lo contrario, gl_get_line() simplemente llamará a fgets() para leer la entrada del comando. Si ambos flujos se refieren a una terminal, deben referirse a la misma terminal, y el tipo de esta terminal debe especificarse a través del argumento term. El valor del argumento term se busca en la base de datos de información de terminales (terminfo o termcap), para determinar qué secuencias de control especiales se necesitan para controlar varios aspectos de la terminal. new_GetLine(), por ejemplo, pasa el valor de retorno de getenv("TERM") en este argumento. Tenga en cuenta que si uno o ambos de input_fp y output_fp no se refieren a una terminal, entonces es legal pasar NULL en lugar de un tipo de terminal.

Tenga en cuenta que si desea pasar descriptores de archivo a gl_change_terminal(), puede hacerlo creando envoltorios de flujo stdio utilizando la función POSIX fdopen().

MANEJO DE EVENTOS EXTERNOS

Por defecto, gl_get_line() no regresa hasta que el usuario haya introducido una línea de entrada completa o se produzca un error. En programas que necesitan observar E/S de otras fuentes además de la terminal, hay dos opciones.

  1. Utilice las funciones descritas en la
     página del manual gl_io_mode(3) para cambiar
     gl_get_line() al modo de servidor no bloqueante. En este
     modo, gl_get_line() se convierte en una función de edición
     de línea incremental no bloqueante que puede ser llamada de forma segura
     desde un bucle de eventos externo. Aunque este es un método muy versátil,
     implica asumir algunas responsabilidades que normalmente son realizadas
     en segundo plano por gl_get_line().
  2. Mientras gl_get_line() espera la entrada del teclado del usuario,
     puede pedirle que también vigile la actividad en descriptores de archivo
     arbitrarios, como sockets de red, pipes, etc., y que llame a funciones de
     su elección cuando se detecte actividad. Esto funciona en cualquier sistema
     que tenga la llamada al sistema select(), que es la mayoría, si no
     todos los sabores de unix.

Registrar un descriptor de archivo para ser vigilado por gl_get_line() implica llamar a la función gl_watch_fd().

  int gl_watch_fd(GetLine *gl, int fd, GlFdEvent event,
                  GlFdEventFn *callback, void *data);

Si esto devuelve un valor distinto de cero, significa que sus argumentos son inválidos o que esta funcionalidad no es compatible en el sistema anfitrión.

El argumento fd es el descriptor de archivo a vigilar. El argumento event especifica qué tipo de actividad es de interés, elegido entre los siguientes valores enumerados:

  GLFD_READ   - Vigilar la llegada de datos para ser leídos.
  GLFD_WRITE  - Vigilar la capacidad de escribir en el descriptor
                de archivo sin bloquear.
  GLFD_URGENT - Vigilar la llegada de datos urgentes
                fuera de banda en el descriptor de archivo.

El argumento callback es la función a llamar cuando se detecta la actividad seleccionada. Debe definirse con la siguiente macro, que está definida en libtecla.h.

  #define GL_FD_EVENT_FN(fn) GlFdStatus (fn)(GetLine *gl, \
                                      void *data, int fd, \
                                      GlFdEvent event)

El argumento data de la función gl_watch_fd() se pasa a la función de callback para su propio uso, y puede apuntar a cualquier cosa que desee, incluyendo NULL. El descriptor de archivo y el argumento de evento también se pasan a la función de callback, y esto potencialmente permite que la misma función de callback se registre para más de un tipo de evento y/o más de un descriptor de archivo. El valor de retorno de la función de callback debe ser uno de los siguientes valores.

  GLFD_ABORT    - Indicar a gl_get_line() que aborte. Cuando esto
                   ocurre, gl_get_line() devuelve
                   NULL, y una llamada posterior a
                   gl_return_status() devolverá
                   GLR_FDABORT. Tenga en cuenta que si la
                   aplicación necesita que errno siempre tenga
                   un valor significativo cuando
                   gl_get_line() devuelve NULL,
                   la función de callback debe establecer
                   errno apropiadamente.
  GLFD_REFRESH  - Redibujar la línea de entrada y luego continuar
                   esperando la entrada. Devolver esto si
                   su callback escribió en la terminal.
  GLFD_CONTINUE - Continuar esperando la entrada, sin
                   redibujar la línea.

Tenga en cuenta que antes de llamar a la función de callback, gl_get_line() bloquea la mayoría de las señales y deja sus propios manejadores de señales instalados, por lo que si necesita capturar una señal particular, deberá instalar temporalmente su propio manejador de señales y desbloquear la señal. Asegúrese de volver a bloquear la señal (si estaba originalmente bloqueada) y de reinstalar el manejador de señales original, si lo hay, antes de regresar.

Si la función de callback necesita leer o escribir en la terminal, idealmente debería llamar primero a gl_normal_io(gl) para suspender temporalmente la edición de línea. Esto restaurará la terminal al modo canónico de E/S bloqueante y moverá el cursor al inicio de una nueva línea de terminal. Más tarde, cuando la función de callback regrese, gl_get_line() notará que se llamó a gl_normal_io(), redibujará la línea de entrada y reanudará la edición. Tenga en cuenta que en este caso los valores de retorno, GLFD_REFRESH y GLFD_CONTINUE son equivalentes.

Para admitir casos en los que la función de callback llama a una función de terceros que ocasionalmente y de forma impredecible escribe en la terminal, la conversión automática de "0 a "0 se vuelve a habilitar antes de llamar a la función de callback. Si la función de callback sabe que la función de terceros escribió en la terminal, debería devolver el valor de retorno GLFD_REFRESH, para indicar a gl_get_line() que redibuje la línea de entrada.

Para eliminar una función de callback que previamente registró para un descriptor de archivo y evento dados, simplemente llame a gl_watch_fd() con los mismos argumentos de descriptor de archivo y event, pero con un argumento callback de 0. El argumento data se ignora en este caso.

SEÑALES

Usar gl_get_line() para consultar al usuario por una respuesta de un solo carácter es inconveniente para el usuario, ya que debe presionar la tecla intro o retorno antes de que el carácter que escribió sea devuelto al programa. Por lo tanto, la función gl_query_char() ha sido proporcionada para consultas de un solo carácter como

esta. 
  int gl_query_char(GetLine *gl, const char *prompt,
                    char defchar)
;

Esta función muestra el prompt especificado al inicio de una nueva línea, y espera a que el usuario escriba un carácter. Cuando el usuario escribe un carácter, gl_query_char() lo muestra a la derecha del prompt, inicia una nueva línea, y luego devuelve el carácter al programa que lo llamó. El valor de retorno de la función es el carácter que fue escrito. Si la lectura tuvo que ser abortada por alguna razón, EOF es devuelto en su lugar. En este último caso, la aplicación puede llamar a la previamente documentada gl_return_status(), para averiguar qué salió mal. Esto podría haber sido, por ejemplo, la recepción de una señal, o el temporizador opcional de inactividad

activándose.

Si el usuario simplemente presiona intro, el valor del argumento defchar es sustituido. Esto significa que cuando el usuario presiona ya sea nueva línea o retorno, el carácter especificado en defchar, es mostrado después del prompt, como si el usuario lo hubiera escrito, así como ser devuelto a la aplicación que lo llamó. Si tal reemplazo no es importante, simplemente pasa '0 como el valor de defchar

.

Si el carácter introducido es un carácter no imprimible, se muestra simbólicamente. Por ejemplo, control-A se muestra como ^A, y los caracteres más allá de 127 se muestran en octal, precedidos por una barra

invertida.

Al igual que con gl_get_line(), el eco del carácter introducido puede ser desactivado usando la función gl_echo_mode()

.

Si el proceso que llama es suspendido mientras espera a que el usuario escriba su respuesta, el cursor se mueve a la línea siguiente a la línea del prompt, luego cuando el proceso se reanuda, el prompt se vuelve a mostrar, y gl_query_char() reanuda la espera a que el usuario escriba un

carácter.

Ten en cuenta que en el modo de servidor no bloqueante, (ver gl_io_mode(3)), si una línea de entrada incompleta está en proceso de ser leída cuando se llama a gl_query_char(), la línea de entrada parcial es descartada, y borrada del terminal, antes de que el nuevo prompt sea mostrado. La siguiente llamada a gl_get_line() comenzará por lo

tanto a editar
una nueva línea.

MOSTRANDO TEXTO DINÁMICAMENTE

Entre llamadas a gl_get_line(), la función gl_display_text() proporciona una forma conveniente de mostrar párrafos de texto, justificados a la izquierda y divididos en una o más líneas de terminal según las restricciones del ancho actual de la terminal. Ejemplos del uso de esta función se pueden encontrar en los programas de demostración, donde se utiliza para mostrar introducciones. En esos ejemplos, también se ilustra el uso avanzado de prefijos, sufijos y líneas de relleno opcionales para dibujar un recuadro alrededor del texto.

  int gl_display_text(GetLine *gl, int indentation,
                      const char *prefix,
                      const char *suffix, int fill_char,
                      int def_width, int start,
                      const char *string);

Si gl no está actualmente conectado a una terminal, por ejemplo, si la salida de un programa que usa gl_get_line() se está canalizando a otro programa o redirigiendo a un archivo, entonces se usa el valor del parámetro def_width como el ancho de la terminal.

El argumento indentation especifica el número de caracteres a utilizar para indentar cada línea de salida. El argumento fill_char especifica el carácter que se utilizará para realizar esta indentación.

El argumento prefix puede ser NULL, o una cadena para colocar al principio de cada nueva línea (después de cualquier indentación). De manera similar, el argumento suffix puede ser NULL, o una cadena para colocar al final de cada línea. El sufijo se coloca pegado al borde derecho de la terminal, y cualquier espacio entre su primer carácter y la última palabra de esa línea se rellena con el carácter especificado mediante el argumento fill_char. Normalmente, el carácter de relleno es un espacio.

El argumento start le dice a gl_display_text() cuántos caracteres ya se han escrito en la línea de terminal actual, y por lo tanto, le dice el índice de la columna de inicio del cursor. Dado que el valor de retorno de gl_display_text() es el índice de la columna final del cursor, al pasar el valor de retorno de una llamada al argumento start de la siguiente llamada, se puede componer un párrafo que se divide entre más de una cadena llamando a gl_display_text() para cada porción sucesiva del párrafo. Tenga en cuenta que los caracteres de nueva línea literales son necesarios al final de cada párrafo para forzar el inicio de una nueva línea.

En caso de error, gl_display_text() devuelve -1.

INSTALACIONES DE FUNCIONES DE LLAMADA

A menos que se indique lo contrario, las funciones de llamada, como las devoluciones de llamada de completado de tabulación y las devoluciones de llamada de eventos, no deben llamar a ninguna función de este módulo. Las siguientes funciones, sin embargo, están diseñadas específicamente para ser utilizadas por funciones de llamada.

Llamar a la función gl_replace_prompt() desde una llamada le indica a gl_get_line() que muestre un aviso diferente cuando la llamada retorne. Excepto en el modo de servidor no bloqueante, no tiene ningún efecto si se usa entre llamadas a gl_get_line(). En el modo de servidor no bloqueante (consulte la página del manual gl_io_mode(3), cuando se usa entre dos llamadas a gl_get_line() que operan sobre la misma línea de entrada, la línea de entrada actual se redibujará con el nuevo aviso en la siguiente llamada a gl_get_line().

  void gl_replace_prompt(GetLine *gl, const char *prompt);

JUEGOS DE CARACTERES INTERNACIONALES

Desde la versión 1.4.0 de libtecla, gl_get_line() es compatible con 8 bits. Esto significa que todos los caracteres de 8 bits que son imprimibles en la configuración regional actual del usuario ahora se muestran verbatim y se incluyen en la línea de entrada devuelta. Suponiendo que el programa que llama contiene correctamente una llamada como la siguiente,

  setlocale(LC_CTYPE, "");

entonces la configuración regional actual se determina por la primera de las variables de entorno LC_CTYPE, LC_ALL y LANG, que se encuentre que contenga un nombre de configuración regional válido. Si ninguna de estas variables está definida, o si el programa omite llamar a setlocale, entonces se utiliza la configuración regional predeterminada C, que es ASCII de 7 bits de EE. UU. En la mayoría de las plataformas tipo Unix, puede obtener una lista de configuraciones regionales válidas escribiendo el comando:

  locale -a

en el símbolo del sistema. Más documentación sobre cómo el usuario puede utilizar esto para introducir caracteres internacionales se puede encontrar en la página del manual tecla(7).

SEGURIDAD DE HILOS

En un programa multihilo, debe utilizar la versión libtecla_r.a de la biblioteca. Esta utiliza versiones reentrantes de las funciones del sistema, cuando están disponibles. Desafortunadamente, ni terminfo ni termcap fueron diseñados para ser reentrantes, por lo que no puede utilizar de forma segura las funciones del módulo getline en múltiples hilos (puede usar los módulos separados de expansión de archivos y completado de palabras en múltiples hilos, consulte las páginas del manual correspondientes para obtener detalles). Sin embargo, debido al uso de funciones reentrantes POSIX para buscar directorios de inicio, etc., es seguro usar este módulo desde un solo hilo de un programa multihilo, siempre que sus otros hilos no utilicen ninguna función de termcap o terminfo.
