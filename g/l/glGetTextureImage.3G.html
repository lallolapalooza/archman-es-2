NOMBRE

glGetTexImage, glGetnTexImage, glGetTextureImage - devolver una imagen de textura

ESPECIFICACIÓN EN C

void glGetTexImage(GLenumtarget, GLintlevel, GLenumformat, GLenumtype, void *pixels);

void glGetnTexImage(GLenumtarget, GLintlevel, GLenumformat, GLenumtype, GLsizeibufSize, void *pixels);

void glGetTextureImage(GLuinttexture, GLintlevel, GLenumformat, GLenumtype, GLsizeibufSize, void *pixels);

PARÁMETROS

target

Especifica el objetivo al que está enlazada la textura para glGetTexImage y glGetnTexImage funciones. GL_TEXTURE_1D, GL_TEXTURE_2D, GL_TEXTURE_3D, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_2D_ARRAY, GL_TEXTURE_RECTANGLE, GL_TEXTURE_CUBE_MAP_POSITIVE_X, GL_TEXTURE_CUBE_MAP_NEGATIVE_X, GL_TEXTURE_CUBE_MAP_POSITIVE_Y, GL_TEXTURE_CUBE_MAP_NEGATIVE_Y, GL_TEXTURE_CUBE_MAP_POSITIVE_Z, GL_TEXTURE_CUBE_MAP_NEGATIVE_Z, y GL_TEXTURE_CUBE_MAP_ARRAY son aceptables.

texture

Especifica el nombre del objeto de textura.

level

Especifica el número de nivel de detalle de la imagen deseada. El nivel 0 es el nivel de imagen base. El nivel n es la n-ésima imagen de reducción de mipmap.

format

Especifica un formato de píxel para los datos devueltos. Los formatos soportados son GL_STENCIL_INDEX, GL_DEPTH_COMPONENT, GL_DEPTH_STENCIL, GL_RED, GL_GREEN, GL_BLUE, GL_RG, GL_RGB, GL_RGBA, GL_BGR, GL_BGRA, GL_RED_INTEGER, GL_GREEN_INTEGER, GL_BLUE_INTEGER, GL_RG_INTEGER, GL_RGB_INTEGER, GL_RGBA_INTEGER, GL_BGR_INTEGER, GL_BGRA_INTEGER.

type

Especifica un tipo de píxel para los datos devueltos. Los tipos soportados son GL_UNSIGNED_BYTE, GL_BYTE, GL_UNSIGNED_SHORT, GL_SHORT, GL_UNSIGNED_INT, GL_INT, GL_HALF_FLOAT, GL_FLOAT, GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, GL_UNSIGNED_SHORT_5_6_5_REV, GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, GL_UNSIGNED_INT_2_10_10_10_REV, GL_UNSIGNED_INT_24_8, GL_UNSIGNED_INT_10F_11F_11F_REV, GL_UNSIGNED_INT_5_9_9_9_REV, y GL_FLOAT_32_UNSIGNED_INT_24_8_REV.

bufSize

Especifica el tamaño del búfer pixels para glGetnTexImage y glGetTextureImage funciones.

pixels

Devuelve la imagen de textura. Debe ser un puntero a un array del tipo especificado por type.

DESCRIPCIÓN

glGetTexImage, glGetnTexImage y glGetTextureImage funciones devuelven una imagen de textura en pixels. Para glGetTexImage y glGetnTexImage, target especifica si la imagen de textura deseada es la especificada por glTexImage1D() (GL_TEXTURE_1D), glTexImage2D() (GL_TEXTURE_1D_ARRAY, GL_TEXTURE_RECTANGLE, GL_TEXTURE_2D o cualquiera de GL_TEXTURE_CUBE_MAP_*), o glTexImage3D() (GL_TEXTURE_2D_ARRAY, GL_TEXTURE_3D, GL_TEXTURE_CUBE_MAP_ARRAY). Para glGetTextureImage, texture especifica el nombre del objeto de textura. Además de los tipos de texturas aceptados por glGetTexImage y glGetnTexImage, la función también acepta objetos de textura de mapa cúbico (con el objetivo efectivo GL_TEXTURE_CUBE_MAP). level especifica el número de nivel de detalle de la imagen deseada. format y type especifican el formato y tipo del array de imagen deseado. Consulte la página de referencia de glTexImage1D() para una descripción de los valores aceptables para los parámetros format y type , respectivamente. Para las funciones glGetnTexImage y glGetTextureImage, bufSize indica el tamaño del búfer para recibir los datos de píxeles recuperados. glGetnTexImage y glGetTextureImage no escriben más de bufSize bytes en pixels.

Si un objeto de búfer con nombre distinto de cero está enlazado al objetivo GL_PIXEL_PACK_BUFFER (véase glBindBuffer()) mientras se solicita una imagen de textura, pixels se trata como un desplazamiento de byte en el almacén de datos del objeto de búfer.

Para entender el funcionamiento de glGetTexImage, considere la imagen de textura interna seleccionada de cuatro componentes como un búfer de color RGBA del tamaño de la imagen. La semántica de glGetTexImage es entonces idéntica a la de glReadPixels(), con la excepción de que no se realizan operaciones de transferencia de píxeles, cuando se llama con el mismo format y type, con x y y establecidos en 0, width establecido al ancho de la imagen de textura y height establecido a 1 para imágenes 1D, o a la altura de la imagen de textura para imágenes 2D.

Si la imagen de textura seleccionada no contiene cuatro componentes, se aplican los siguientes mapeos. Las texturas de un solo componente se tratan como búfers RGBA con rojo establecido al valor del componente único, verde a 0, azul a 0 y alfa a 1. Las texturas de dos componentes se tratan como búfers RGBA con rojo establecido al valor del componente cero, alfa al valor del componente uno, y verde y azul a 0. Finalmente, las texturas de tres componentes se tratan como búfers RGBA con rojo establecido al componente cero, verde al componente uno, azul al componente dos y alfa a 1.

Para determinar el tamaño requerido de pixels, use glGetTexLevelParameter() para determinar las dimensiones de la imagen de textura interna, luego escale el número requerido de píxeles por el almacenamiento requerido para cada píxel, basado en format y type. Asegúrese de tener en cuenta los parámetros de almacenamiento de píxeles, especialmente GL_PACK_ALIGNMENT.

Si glGetTextureImage se usa con un objeto de textura de mapa cúbico, la textura se trata como una imagen tridimensional de una profundidad de 6, donde las caras del mapa cúbico están ordenadas como capas de imagen, en un orden presentado en la tabla siguiente:

Número de capa Cara del mapa cúbico
0 GL_TEXTURE_CUBE_MAP_POSITIVE_X
1 GL_TEXTURE_CUBE_MAP_NEGATIVE_X
2 GL_TEXTURE_CUBE_MAP_POSITIVE_Y
3 GL_TEXTURE_CUBE_MAP_NEGATIVE_Y
4 GL_TEXTURE_CUBE_MAP_POSITIVE_Z
5 GL_TEXTURE_CUBE_MAP_NEGATIVE_Z

NOTAS

Si se genera un error, no se realiza ningún cambio en el contenido de pixels.

glGetTexImage y glGetnTexImage devuelven la imagen de textura para la unidad de textura activa.

GL_STENCIL_INDEX se acepta para format solo si la versión de GL es 4.4 o superior.

ERRORES

GL_INVALID_ENUM es generado por glGetTexImage y glGetnTexImage funciones si target no es un valor aceptado. Estos incluyen:

•GL_TEXTURE_1D, GL_TEXTURE_2D, GL_TEXTURE_3D, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_2D_ARRAY, GL_TEXTURE_CUBE_MAP_ARRAY, GL_TEXTURE_RECTANGLE, GL_TEXTURE_CUBE_MAP_POSITIVE_X, GL_TEXTURE_CUBE_MAP_NEGATIVE_X, GL_TEXTURE_CUBE_MAP_POSITIVE_Y, GL_TEXTURE_CUBE_MAP_NEGATIVE_Y, GL_TEXTURE_CUBE_MAP_POSITIVE_Z, y GL_TEXTURE_CUBE_MAP_NEGATIVE_Z para glGetTexImage y glGetnTexImage funciones.
•GL_TEXTURE_1D, GL_TEXTURE_2D, GL_TEXTURE_3D, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_2D_ARRAY, GL_TEXTURE_CUBE_MAP_ARRAY, GL_TEXTURE_RECTANGLE, y GL_TEXTURE_CU

glGetTextureImage

retrieve a texture image from client-side memory

C SPECIFICATION

void glGetTextureImage(GLenum target, GLint level, GLenum format, GLenum type, GLsizei bufSize, void *pixels);

PARAMETERS

target Specifies the texture target for which the image will be returned. Must be one of GL_TEXTURE_1D, GL_TEXTURE_2D, GL_TEXTURE_3D, GL_TEXTURE_1D_ARRAY, GL_TEXTURE_2D_ARRAY, GL_TEXTURE_2D_MULTISAMPLE, GL_TEXTURE_2D_MULTISAMPLE_ARRAY, GL_TEXTURE_CUBE_MAP_POSITIVE_X, GL_TEXTURE_CUBE_MAP_NEGATIVE_X, GL_TEXTURE_CUBE_MAP_POSITIVE_Y, GL_TEXTURE_CUBE_MAP_NEGATIVE_Y, GL_TEXTURE_CUBE_MAP_POSITIVE_Z, GL_TEXTURE_CUBE_MAP_NEGATIVE_Z, GL_TEXTURE_CUBE_MAP_RETROGRADE, GL_TEXTURE_CUBE_MAP_ARCROGRADE, or GL_TEXTURE_RECTANGLE.

level Specifies the level-of-detail number of the deemed texture image.

format Specifies the pixel format that will be used to reconstruct the texture image. See the glDrawPixels manual page for a list of accepted format arguments.

type Specifies the data type of the pixel data. See the glDrawPixels manual page for a list of accepted type arguments.

bufSize Specifies the length of the buffer in bytes pointed to by pixels.

pixels Returns the width, height, depth, and pixel data of the specified texture image.

DESCRIPTION

glGetTextureImage returns a texture image from client-side memory. The texture referred to by target must be an existing texture object. The level parameter selects the mipmap level, and the format and type parameters specify the format and data type of the returned pixel data.

The returned pixel data will be stored in the array of memory pointed to by pixels. The size of the buffer must be large enough to hold all the pixels in the specified texture image level. The dimensions of the texture image can be determined by querying GL_TEXTURE_WIDTH, GL_TEXTURE_HEIGHT, and GL_TEXTURE_DEPTH (for 3D textures).

The texture image is returned as a sequence of pixels. The order of pixels is the same as for glReadPixels. The pixel storage parameters (see glPixelStore) affect the returned data.

If a buffer object is bound to the GL_PIXEL_PACK_BUFFER target, then pixels is treated as an offset into that buffer object, and the data are read from the buffer object.

NOTES

glGetTextureImage is equivalent to calling glGetnTexImage with the same parameters, including the bufSize parameter. This function is intended for use with the version-4.5 compatibility profile, or with a core profile context using GL_EXT_direct_state_access.

The behavior of glGetTextureImage is undefined if bufSize is less than the required size to store the texture image.

ERRORS

GL_INVALID_ENUM is generated if target is not one of the accepted texture targets.

GL_INVALID_OPERATION is generated if target is GL_TEXTURE_BINDING_1D, GL_TEXTURE_BINDING_2D, GL_TEXTURE_BINDING_3D, GL_TEXTURE_BINDING_1D_ARRAY, GL_TEXTURE_BINDING_2D_ARRAY, GL_TEXTURE_BINDING_2D_MULTISAMPLE, GL_TEXTURE_BINDING_2D_MULTISAMPLE_ARRAY, GL_TEXTURE_BINDING_CUBE_MAP, or GL_TEXTURE_BINDING_RECTANGLE.

GL_INVALID_OPERATION is generated if target is GL_TEXTURE_RECTANGLE and level is not zero.

GL_INVALID_OPERATION is generated if the texture object does not exist or if level is not a valid level for the texture object.

GL_INVALID_VALUE is generated if level is less than 0.

GL_INVALID_VALUE may be generated if level is greater than log 2 ⁡ max, where max is the returned value of GL_MAX_TEXTURE_SIZE.

GL_INVALID_ENUM is generated if format or type is not an accepted value.

GL_INVALID_OPERATION is generated if type is one of GL_UNSIGNED_BYTE_3_3_2, GL_UNSIGNED_BYTE_2_3_3_REV, GL_UNSIGNED_SHORT_5_6_5, GL_UNSIGNED_SHORT_5_6_5_REV, or GL_UNSIGNED_INT_10F_11F_11F_REV and format is not GL_RGB.

GL_INVALID_OPERATION is generated if type is one of GL_UNSIGNED_SHORT_4_4_4_4, GL_UNSIGNED_SHORT_4_4_4_4_REV, GL_UNSIGNED_SHORT_5_5_5_1, GL_UNSIGNED_SHORT_1_5_5_5_REV, GL_UNSIGNED_INT_8_8_8_8, GL_UNSIGNED_INT_8_8_8_8_REV, GL_UNSIGNED_INT_10_10_10_2, GL_UNSIGNED_INT_2_10_10_10_REV, or GL_UNSIGNED_INT_5_9_9_9_REV and format is neither GL_RGBA or GL_BGRA.

GL_INVALID_OPERATION is generated if format is GL_STENCIL_INDEX and the base internal format is not GL_STENCIL_INDEX or GL_DEPTH_STENCIL.

GL_INVALID_OPERATION is generated if a non-zero buffer object name is bound to the GL_PIXEL_PACK_BUFFER target and the buffer object's data store is currently mapped.

GL_INVALID_OPERATION is generated if a non-zero buffer object name is bound to the GL_PIXEL_PACK_BUFFER target and the data would be packed to the buffer object such that the memory writes required would exceed the data store size.

GL_INVALID_OPERATION is generated if a non-zero buffer object name is bound to the GL_PIXEL_PACK_BUFFER target and pixels is not evenly divisible into the number of bytes needed to store in memory a datum indicated by type.

GL_INVALID_OPERATION is generated by glGetTextureImage and glGetnTexImage if the buffer size required to store the requested data is greater than bufSize.
