Opciones de Vinculación de Recursos

-fauto-bind-uniforms

La opción -fauto-bind-uniforms indica al compilador que asigne automáticamente números de vinculación a las variables uniformes, cuando no se especifica una vinculación explícita en el código fuente del sombreado.

Se puede especificar un número de vinculación explícito en el código fuente del sombreado utilizando un cualificador de diseño binding. Por ejemplo:

layout(binding = 12) uniform texture2D;

-fhlsl-iomap

La opción -fhlsl-iomap indica al compilador que utilice las asignaciones de registro de HLSL como valores de vinculación.

-fimage-binding-base

La opción -fimage-binding-base [stage] base establece la vinculación de menor valor asignada automáticamente para las imágenes. Si se especifica una etapa, solo afecta a la etapa especificada.

Para HLSL, establece uno menos que la base.

-fsampler-binding-base

La opción -fsampler-binding-base [stage] base establece la vinculación de menor valor asignada automáticamente para los samplers. Si se especifica una etapa, solo afecta a la etapa especificada.

Para HLSL, establece uno menos que la base.

-ftexture-binding-base

La opción -ftexture-binding-base [stage] base establece la vinculación de menor valor asignada automáticamente para las texturas. Si se especifica una etapa, solo afecta a la etapa especificada.

Para HLSL, establece uno menos que la base.

-fubo-binding-base

La opción -fubo-binding-base [stage] base establece la vinculación de menor valor asignada automáticamente para los Uniform Buffer Objects (GLSL) o Cbuffers (HLSL). Si se especifica una etapa, solo afecta a la etapa especificada.

Para HLSL, establece uno menos que la base.

-fcbuffer-binding-base

La opción -fcbuffer-binding-base [stage] base es la misma que -fubo-binding-base [stage] base.

-fssbo-binding-base

La opción -fssbo-binding-base [stage] base establece la vinculación de menor valor asignada automáticamente para los Shader Storage Buffer Objects (GLSL). Si se especifica una etapa, solo afecta a la etapa especificada.

Esto solo afecta a la compilación de GLSL.

-fuav-binding-base

La opción -fuav-binding-base [stage] base establece uno menos que la vinculación de menor valor asignada automáticamente para Unordered Access Views (UAV). Si se especifica una etapa, solo afecta a la etapa especificada.

Esto solo afecta a la compilación de HLSL.

-fresource-set-binding

La opción -fresource-set-binding [stage] <reg0> <set0> <binding0> establece el conjunto de descriptores y la vinculación para un recurso HLSL, por nombre de registro. Para especificar configuraciones para más registros, agregue sus triples que consisten en el nombre del registro, el conjunto de descriptores y la vinculación.

Ejemplo:

# Para una textura en el registro t1, usa el conjunto 1, vinculación 0.
# Para una textura en el registro t2, usa el conjunto 1, vinculación 3
glslc -x hlsl foo.frag -fresource-set-binding t1 1 0 t2 1 3

Si se especifica una etapa, solo afecta a la etapa especificada.

# Igual que el ejemplo anterior, pero las configuraciones solo se aplican
# a los sombreados de fragmentos (píxeles).
glslc -x hlsl foo.frag -fresource-set-binding frag t1 1 0 t2 1 3

DIVERGENCIA DE Y EXTENSIONES A LAS ESPECIFICACIONES DE GLSL

Directiva #line y macro __FILE__ basada en el nombre del archivo fuente

Esta sección describe cómo el compilador glslc extiende la sintaxis para la directiva #line y la macro __FILE__. Por defecto, el compilador glslc habilita la extensión GL_GOOGLE_cpp_style_line_directive. Generará esta sintaxis extendida en la salida preprocesada (obtenida a través de la opción -E).


Advertencia

Esta sección todavía está en evolución. Espere cambios.

Las especificaciones de GLSL tienen una noción de cadenas de fuente.

La fuente de un sombreado único es un arreglo de cadenas de caracteres del conjunto de caracteres. Un sombreado único se forma por la concatenación de estas cadenas.


— Sección 3.2 de las versiones 3.30 y 4.50

Con la noción anterior, el segundo parámetro de la directiva #line debería ser una expresión entera constante que represente el número de cadena de fuente. Además, la macro __FILE__ "sustituirá una constante entera decimal que indica qué cadena de fuente se está procesando actualmente".

El compilador glslc implementa la sintaxis estándar de #line y __FILE__. También proporciona una extensión, GL_GOOGLE_cpp_style_line_directive, para permitir el uso de nombres de archivos fuente en lugar de índices enteros de cadenas de fuente. Específicamente, la directiva #line puede tener, después de la sustitución de macros, una de las siguientes tres formas:

#line numero-de-linea
#line numero-de-linea indice-cadena-fuente-entero
#line numero-de-linea "nombre-archivo-fuente"

donde nombre-archivo-fuente puede ser cualquier combinación de caracteres excepto comillas dobles. (Tenga en cuenta que según la especificación de GLSL, "no hay secuencias de escape ni otros usos de la barra invertida más allá de su uso como carácter de continuación de línea").

Y si se utiliza #line basada en nombre de archivo fuente, la macro __FILE__ se expande a una cadena cuyo contenido es el nombre del archivo entrecomillado con comillas dobles. El nombre del archivo se determina como el último de:

•El nombre del archivo proporcionado al compilador glslc,
•El argumento del nombre de archivo de la directiva #line más reciente, si la hay.

#include

El compilador glslc extiende GLSL con la sintaxis de inclusión al activar la extensión GL_GOOGLE_include_directive. Preprocesará y sustituirá las directivas #include correctamente con los siguientes comportamientos.


Advertencia

Esta sección todavía está en evolución. Espere cambios.

Si se utilizan directivas #include en un sombreado, se generará una línea #extension GL_GOOGLE_include_directive : enable en la salida preprocesada.

La extensión GL_GOOGLE_cpp_style_line_directive se activa implícitamente por la extensión GL_GOOGLE_include_directive.

El argumento del archivo para #include debe estar entre comillas dobles. Debe ser una ruta relativa, utilizando el separador de rutas que admita el sistema operativo. Sin embargo, el último elemento de la ruta — el nombre del archivo en sí — no debe contener '/' ni '\', independientemente del separador de rutas utilizado. Esto no se señalará como un error, sino que provocará un comportamiento indefinido. Por ejemplo, supongamos que hay un archivo llamado f\ilename.vert en un sistema operativo Unix. No es posible crear una directiva #include que incluya ese archivo.

Además, no es posible escapar ningún carácter en una directiva #include, por lo que el argumento del archivo no puede contener caracteres especiales que necesiten ser escapados en C.
