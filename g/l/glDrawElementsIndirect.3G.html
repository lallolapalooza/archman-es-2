NOMBRE

glDrawElementsIndirect - renderiza primitivas indexadas a partir de datos de array, tomando los parámetros de la memoria

ESPECIFICACIÓN EN C

void glDrawElementsIndirect(GLenummode, GLenumtype, const void *indirect);

PARÁMETROS

mode

Especifica qué tipo de primitivas se deben renderizar. Se aceptan las constantes simbólicas GL_POINTS, GL_LINE_STRIP, GL_LINE_LOOP, GL_LINES, GL_LINE_STRIP_ADJACENCY, GL_LINES_ADJACENCY, GL_TRIANGLE_STRIP, GL_TRIANGLE_FAN, GL_TRIANGLES, GL_TRIANGLE_STRIP_ADJACENCY, GL_TRIANGLES_ADJACENCYy GL_PATCHES .

type

Especifica el tipo de datos en el buffer vinculado al enlace GL_ELEMENT_ARRAY_BUFFER .

indirect

Especifica la dirección de una estructura que contiene los parámetros de dibujo.

DESCRIPCIÓN

glDrawElementsIndirect especifica múltiples primitivas geométricas indexadas con muy pocas llamadas a subrutinas. glDrawElementsIndirect se comporta de manera similar a glDrawElementsInstancedBaseVertexBaseInstance(), excepto que los parámetros de glDrawElementsInstancedBaseVertexBaseInstance() se almacenan en la memoria en la dirección dada por indirect.

Los parámetros a los que se accede mediante indirect se empaquetan en una estructura que tiene la forma (en C):

    typedef  struct {
        uint  count;
        uint  instanceCount;
        uint  firstIndex;
        int  baseVertex;
        uint  baseInstance;
    } DrawElementsIndirectCommand;

glDrawElementsIndirect es equivalente a:

    void glDrawElementsIndirect(GLenum mode, GLenum type, const void * indirect) {
        const DrawElementsIndirectCommand *cmd  = (const DrawElementsIndirectCommand *)indirect;
        glDrawElementsInstancedBaseVertexBaseInstance(mode,
                                                      cmd->count,
                                                      type,
                                                      cmd->firstIndex * size-of-type,
                                                      cmd->instanceCount,
                                                      cmd->baseVertex,
                                                      cmd->baseInstance);
    }

Si un buffer está vinculado al enlace GL_DRAW_INDIRECT_BUFFER en el momento de una llamada a glDrawElementsIndirect, indirect se interpreta como un desplazamiento, en unidades básicas de máquina, dentro de ese buffer, y los datos de los parámetros se leen del buffer en lugar de la memoria del cliente.

Tenga en cuenta que los índices almacenados en la memoria del cliente no están soportados. Si no hay ningún buffer vinculado al enlace GL_ELEMENT_ARRAY_BUFFER , se generará un error.

Los resultados de la operación son indefinidos si el miembro reservedMustBeZero de la estructura de parámetros no es cero. Sin embargo, en este caso no se genera ningún error.

Los atributos de vértice que son modificados por glDrawElementsIndirect tienen un valor no especificado después de que glDrawElementsIndirect retorna. Los atributos que no son modificados permanecen bien definidos.

NOTAS

El miembro baseInstance de la estructura DrawElementsIndirectCommand está definido solo si la versión de GL es 4.2 o superior. Para versiones de GL inferiores a 4.2, este parámetro está presente pero está reservado y debe establecerse en cero. En versiones anteriores de GL, el comportamiento es indefinido si no es cero.

ERRORES

GL_INVALID_ENUM se genera si mode no es un valor aceptado.

GL_INVALID_OPERATION se genera si cero está vinculado al enlace GL_ELEMENT_ARRAY_BUFFER , o si el almacén de datos de dicho buffer está actualmente mapeado.

GL_INVALID_OPERATION se genera si un nombre de objeto buffer no nulo está vinculado a un array habilitado o al enlace GL_DRAW_INDIRECT_BUFFER y el almacén de datos del objeto buffer está actualmente mapeado.

GL_INVALID_OPERATION se genera si un shader de geometría está activo y mode es incompatible con el tipo de primitiva de entrada del shader de geometría en el objeto programa actualmente instalado.

GL_INVALID_OPERATION se genera si mode es GL_PATCHES y no hay ningún shader de control de teselación activo.
