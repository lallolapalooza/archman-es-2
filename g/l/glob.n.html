El comando glob difiere del globbing de csh de dos maneras. Primero, no ordena su lista de resultados (use el comando lsort si quiere la lista ordenada). Segundo, glob solo devuelve los nombres de los archivos que realmente existen; en csh no se realiza ninguna comprobación de existencia a menos que un patrón contenga una construcción ?, *, o []

.

Cuando el comando glob devuelve rutas relativas cuyos nombres de archivo comienzan con un tilde “~” (por ejemplo a través de glob * o glob -tails, la lista devuelta no citará el tilde con “./”. Esto significa que se debe tener cuidado si esos nombres se van a usar posteriormente con file join, para evitar que se interpreten como

rutas absolutas que apun
tan al directorio de in
icio de un usuario dado.

PROBLEMAS DE PORTABILIDAD EN

WINDOWS

Para los nombres UNC de Windows, los componentes servername y sharename de la ruta no pueden contener construcciones ?, *, o []. En Windows NT, si patrón es de la forma “~username@domain”, se refiere al directorio de inicio del usuario cuya información de cuenta reside en el servidor de dominio NT especificado. De lo contrario, la información de la cuenta de usuario se obtiene del equipo

local.

Dado que el carácter de barra invertida tiene un significado especial para el comando glob, los patrones glob que contienen separadores de ruta al estilo de Windows requieren especial cuidado. El patrón “C:\\foo\\*” se interpreta como “C:\foo\*” donde “\f” coincidirá con el carácter único “f” y “\*” coincidirá con el carácter único “*” y no se interpretará como un carácter comodín. Una solución a este problema es usar la barra inclinada hacia adelante al estilo de Unix como separador de ruta. Las rutas al estilo de Windows se pueden convertir a rutas al estilo de Unix con el comando “file join $path” o “file normalize $path
