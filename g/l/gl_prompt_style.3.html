DESCRIPCIÓN

La función gl_get_line() es parte de la biblioteca tecla (ver la página del manual de libtecla(3)). Si el usuario está escribiendo en una terminal, cada llamada le pide una línea de entrada, luego proporciona facilidades de edición interactivas, similares a las del shell tcsh de Unix. Además de la edición simple de línea de comandos, soporta la recuperación de líneas de comandos introducidas previamente, el completado con TAB de nombres de archivo, y la expansión de comodines de nombres de archivo en línea. La documentación de las características de edición de línea de comandos a nivel de usuario y de todas las opciones de configuración del usuario, se puede encontrar en la página del manual de tecla(7). Esta página del manual se ocupa de la documentación para programadores interesados en utilizar esta biblioteca en su aplicación.

UN EJEMPLO

Lo siguiente muestra un ejemplo completo de cómo usar la función gl_get_line() para obtener entrada del usuario:

  #include <stdio.h>
  #include <locale.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  { 
    char *line;    /* La línea que escribió el usuario */
    GetLine *gl;   /* El objeto de recursos de gl_get_line() */
    setlocale(LC_CTYPE, ""); /* Adoptar la elección del usuario */
                             /* del conjunto de caracteres. */
    gl = new_GetLine(1024, 2048);
    if(!gl)
      return 1;
    while((line=gl_get_line(gl, "$ ", NULL, -1)) != NULL &&
           strcmp(line, "exit\n") != 0)
      printf("Escribiste: %s\n", line);
    gl = del_GetLine(gl);
    return 0;
  }

En el ejemplo, primero se crean los recursos necesarios para la función gl_get_line() llamando a new_GetLine(). Esto asigna la memoria utilizada en llamadas posteriores a la función gl_get_line(), incluido el búfer de historial para grabar líneas introducidas previamente. Luego se leen una o más líneas del usuario, hasta que ocurre un error o el usuario escribe exit. Luego, finalmente, los recursos que fueron asignados por new_GetLine(), se devuelven al sistema llamando a del_GetLine(). Tenga en cuenta el uso del valor de retorno NULL de del_GetLine() para hacer que gl sea NULL. Esta es una precaución de seguridad. Si el programa intenta posteriormente pasar gl a gl_get_line(), dicha función se quejará y devolverá un error, en lugar de intentar usar el objeto de recurso eliminado.

LAS FUNCIONES UTILIZADAS EN EL EJEMPLO

Las descripciones de las funciones utilizadas en el ejemplo son las siguientes:

  GetLine *new_GetLine(size_t linelen, size_t histlen)

Esta función crea los recursos utilizados por la función gl_get_line() y devuelve un puntero opaco al objeto que los contiene. La longitud máxima de una línea de entrada se especifica a través del argumento linelen, y el número de bytes a asignar para almacenar líneas de historial se establece mediante el argumento histlen. Las líneas de historial se almacenan una tras otra en un único búfer de este tamaño. Tenga en cuenta que esto significa que el número de líneas de historial que se pueden almacenar en cualquier momento dado, depende de las longitudes de las líneas individuales. Si desea establecer un límite superior en el número de líneas que se pueden almacenar, consulte la función gl_limit_history() descrita más adelante. Si no desea historial en absoluto, especifique histlen como cero, y no se asignará ningún búfer de historial.

En caso de error, se imprime un mensaje en stderr y se devuelve NULL.

  GetLine *del_GetLine(GetLine *gl)

Esta función elimina los recursos que fueron devueltos por una llamada anterior a new_GetLine(). Siempre devuelve NULL (es decir, un objeto eliminado). No hace nada si el argumento gl es NULL.

  char *gl_get_line(GetLine *gl, const char *prompt,
                   const char *start_line, int start_pos);

La función gl_get_line() puede ser llamada cualquier número de veces para leer entrada del usuario. El argumento gl debe haber sido devuelto previamente por una llamada a new_GetLine(). El argumento prompt debe ser una cadena normal terminada en NUL, que especifica el prompt que se presentará al usuario. Por defecto, los prompts se muestran literalmente, pero si se habilitan con la función gl_prompt_style() (ver más adelante), los prompts pueden contener directivas para subrayar, cambiar a y desde fuentes en negrita, o activar y desactivar el resaltado.

Si desea especificar el contenido inicial de la línea, para que el usuario lo edite, pase la cadena deseada a través del argumento start_line. Luego puede especificar en qué carácter de esta línea se posiciona inicialmente el cursor

En este último caso, debería llamar a gl_get_line() de nuevo para leer el resto de la línea. Tenga en cuenta que este comportamiento hace que gl_get_line() sea similar a fgets(). FUENTES ALTERNATIVAS DE

CONFIGURACIÓN

Como se mencionó anteriormente, de forma predeterminada los usuarios tienen la opción de configurar el comportamiento de gl_get_line() a través de un archivo de configuración llamado .teclarc en sus directorios de inicio. El hecho de que todas las aplicaciones compartan este mismo archivo de configuración es tanto una ventaja como una desventaja. En la mayoría de los casos es una ventaja, ya que fomenta la uniformidad y libera al usuario de tener que configurar cada aplicación por separado. En algunas aplicaciones, sin embargo, este único medio de configuración es un problema. Esto es particularmente cierto en el software embebido, donde no hay un sistema de archivos del cual leer un archivo de configuración, y también en aplicaciones donde se necesita una elección radicalmente diferente de combinaciones de teclas para emular una interfaz de teclado heredada. Para atender a tales casos, la siguiente función permite a la aplicación controlar desde dónde se lee la información de

configuración. 
  int gl_configure_getline(GetLine *gl,
                           const char *app_string,
                           const char *app_file,
                           const char *user_file)
;

Permite que los comandos de configuración que normalmente se leerían del archivo ~/.teclarc de un usuario, se lean de uno, varios o ninguno de los siguientes: una cadena, un archivo de configuración específico de la aplicación y/o un archivo de configuración específico del usuario. Si esta función se llama antes de la primera llamada a gl_get_line(), el comportamiento predeterminado de leer ~/.teclarc en la primera llamada a gl_get_line() se deshabilita, por lo que toda la configuración debe lograrse utilizando las fuentes de configuración especificadas con esta

función.

Si app_string != NULL, entonces se interpreta como una cadena que contiene uno o más comandos de configuración, separados entre sí en la cadena por caracteres de salto de línea incrustados. Si app_file != NULL entonces se interpreta como la ruta de acceso completa de un archivo de configuración específico de la aplicación. Si user_file != NULL entonces se interpreta como la ruta de acceso completa de un archivo de configuración específico del usuario, como ~/.teclarc. Por ejemplo, en la siguiente

llamada, 
  gl_configure_getline(gl, "edit-mode vi \n nobeep",
                           "/usr/share/myapp/teclarc",
                           "~/.teclarc")
;

el argumento app_string hace que la aplicación que llama comience en el modo de edición vi, en lugar del modo emacs predeterminado, y desactiva el uso de la campana de la terminal por parte de la biblioteca. Luego intenta leer comandos de configuración de todo el sistema desde un archivo opcional llamado /usr/share/myapp/teclarc, y finalmente lee comandos de configuración específicos del usuario desde un archivo .teclarc opcional en el directorio de inicio del usuario. Tenga en cuenta que los argumentos se listan en orden ascendente de prioridad, con el contenido de app_string siendo potencialmente sobrescrito por comandos en app_file, y los comandos en app_file potencialmente siendo sobrescritos por comandos en user_file

.

Puede llamar a esta función tantas veces como sea necesario, siendo los resultados acumulativos, pero tenga en cuenta que las copias de cualquier nombre de archivo especificado a través de app_file y user_file se registran internamente para su uso posterior por la función de asignación de teclas read-init-files, así que si planea llamar a esta función varias veces, asegúrese de que la última llamada especifique los nombres de archivo que desea volver a leer cuando el usuario solicite que los archivos de configuración se

relean.

Las secuencias de teclas individuales también se pueden asignar y desasignar usando la función gl_bind_keyseq()

  int gl_bind_keyseq(GetLine *gl, GlKeyOrigin origin,
                     const char *keyseq,
                     const char *action)

El argumento origin especifica la prioridad de la asignación, según para quién se está estableciendo, y debe ser uno de los siguientes dos

valores. 
  GL_USER_KEY   -   El usuario solicitó esta asignación de tecla.
  GL_APP_KEY    -   Esta es una asignación predeterminada establecida por la
aplicación.

Cuando se han especificado tanto la asignación de usuario como la de la aplicación para una secuencia de teclas dada, la asignación de usuario tiene prioridad. La asignación de la aplicación se restablece posteriormente si la asignación del usuario se desasigna más tarde ya sea mediante otra llamada a esta función, o una llamada a gl_configure_ge

tline().

El argumento keyseq especifica la secuencia de teclas a ser asignada o desasignada, y se expresa de la misma manera que en un archivo de configuración ~/.teclarc. El argumento action debe ser una cadena que contenga el nombre de la acción a la que asignar la secuencia de teclas, o debe ser NULL o "" para desasigna

r la secuenci

COMPLETADO DE PALABRAS

PERSONALIZADO

Si en su aplicación, le gustaría que la completación con TAB completara otras cosas además de o en lugar de nombres de archivo, puede organizar esto registrando una función de retorno de completación alternativa, mediante una llamada a la función gl_customize_co

mpletion(). 
  int gl_customize_completion(GetLine *gl, void *data,
                              CplMatchFn *match_fn)
;

El argumento data proporciona una manera para que su aplicación pase información arbitraria y específica de la aplicación a la función de retorno. Esto se pasa a la función de retorno cada vez que se la llama. Podría, por ejemplo, apuntar a la tabla de símbolos desde la cual se deben buscar las posibles completaciones. El argumento match_fn especifica la función de retorno a ser llamada. El tipo de función CplMatchFn está definido en libtecla.h, al igual que una macro CPL_MATCH_FN() que puede usar para declarar y prototipar funciones de retorno. La declaración y las responsabilidades de las funciones de retorno se describen en profundidad en la página del manual cpl_complete_word(3)

.

En resumen, la función de retorno es responsable de buscar hacia atrás en la línea de entrada, desde el punto en el que el usuario presionó TAB, para encontrar el inicio de la palabra que se está completando. Luego debe buscar posibles completaciones de esta palabra y registrarlas una por una en el objeto WordCompletion que se le pasa como argumento, llamando a la función cpl_add_completion(). Si la función de retorno desea proporcionar completación de nombres de archivo además de sus propias completaciones específicas, tiene la opción de llamar ella misma a la función de retorno de completación de nombres de archivo incorporada. Esto también está documentado en la página del manual cpl_complete_word(3)

.

Tenga en cuenta que si le gustaría que gl_get_line() devuelva la línea de entrada actual cuando se haya realizado una completación exitosa, puede organizar esto cuando llame a cpl_add_completion(), haciendo que el último carácter del sufijo de continuación sea un carácter de salto de línea. Si hace esto, la línea de entrada se actualizará para mostrar la completación, junto con cualquier sufijo de continuación hasta el carácter de salto de línea, y luego gl_get_line() devolverá esta línea de

entrada.

Si, por alguna razón, su función de retorno necesita escribir algo en la terminal, debe llamar a gl_normal_io() antes de hacerlo. Esto comenzará una nueva línea después de la línea de entrada que se está editando actualmente, restablecerá la E/S normal de la terminal y le dirá a gl_get_line() que la línea de entrada necesitará

ser redibujada cuando la f
unción de retorno regrese.

AÑADIENDO ACCIONES DE

COMPLETACIÓN

En la sección anterior se describió la capacidad de personalizar el comportamiento de la única acción de completación predeterminada, complete-word. En esta sección se describe la capacidad de instalar funciones de acción adicionales, de modo que diferentes tipos de completación de palabras se puedan asignar a diferentes secuencias de teclas. Esto se logra usando la función gl_completion_action()

. 
  int gl_completion_action(GetLine *gl,
                           void *data, CplMatchFn *match_fn,
                           int list_only, const char *name,
                           const char *keyseq)
;

Los argumentos data y match_fn se describen en la página del manual de cpl_complete_word, y especifican la función de retorno que debe ser invocada para identificar posibles completaciones. El argumento list_only determina si la acción que se está definiendo debe intentar completar la palabra tanto como sea posible en la línea de entrada antes de mostrar cualquier posible completación ambigua, o si debe simplemente mostrar la lista de posibles completaciones sin tocar la línea de entrada. La primera opción se selecciona especificando un valor de 0, y la segunda especificando un valor de 1. El argumento name especifica el nombre con el que los archivos de configuración y las futuras invocaciones de esta función deben referirse a la acción. Este debe ser el nombre de una acción de completación existente a ser cambiada, o un nuevo nombre sin usar para una nueva acción. DEFINIENDO ACCIONES

PERSONALIZADAS

Aunque las acciones de asignación de teclas incorporadas son suficientes para las necesidades de la mayoría de las aplicaciones, ocasionalmente una aplicación especializada puede necesitar definir una o más acciones personalizadas, asignadas a secuencias de teclas específicas de la aplicación. Por ejemplo, una aplicación de ventas se beneficiaría de tener una secuencia de teclas que mostrara el nombre de la pieza que correspondía a un número de pieza que precedía al cursor. Tal característica está claramente fuera del alcance de las funciones de acción incorporadas. Así que para tales casos especiales, se proporciona la función gl_register_action()

El argumento data puede ser un puntero a cualquier cosa que la aplicación desee que se pase a la función de acción, fn, cada vez que esa función sea

invocada.

La función de acción, fn, debe ser declarada usando la siguiente macro, que está definida en libtecl

a.h. 
  #define GL_ACTION_FN(fn) GlAfterAction (fn)(GetLine *gl, \
              void *data, int count, size_t curpos, \
              const char
*line)

Los argumentos gl y data son aquellos que fueron previamente pasados a gl_register_action() cuando la función de acción fue registrada. El argumento count es un argumento numérico que el usuario tiene la opción de introducir usando la acción digit-argument, antes de invocar la acción. Si el usuario no introduce un número, entonces el argumento count se establece en 1. Nominalmente este argumento se interpreta como un conteo de repetición, lo que significa que la acción debe repetirse esa cantidad de veces. En la práctica, sin embargo, para algunas acciones un conteo de repetición tiene poco sentido. En tales casos, las acciones pueden simplemente ignorar el argumento count, o usar su valor para un propósito

diferente.

Una copia de la línea de entrada actual se pasa en el argumento de solo lectura line. La posición actual del cursor dentro de esta cadena está dada por el índice contenido en el argumento curpos. Tenga en cuenta que la manipulación directa de la línea de entrada y la posición del cursor no está permitida. Esto se debe a que las reglas dictadas por varios modos, como el modo vi versus el modo emacs, el modo sin eco, y el modo de inserción versus el modo de sobrescritura, etc., hacen que sea demasiado compleo para un programador de aplicaciones escribir una acción de edición conforme, así como restringir cambios futuros en los internos de gl_get_line(). Una solución potencial a este dilema sería permitir que la función de acción edite la línea usando las acciones de edición existentes. Esto está actualmente bajo

consideración.

Si la función de acción desea escribir texto en la terminal, sin que esto se mezcle con el texto mostrado de la línea de entrada, o leer de la terminal sin tener que manejar la E/S cruda de la terminal, entonces antes de hacer cualquiera de estas operaciones, debe suspender temporalmente la edición de línea llamando a la función gl_normal_io(). Esta función vacía cualquier salida pendiente a la terminal, mueve el cursor al inicio de la línea que sigue a la última línea de terminal de la línea de entrada, y luego restaura la terminal a un estado que es adecuado para su uso con las instalaciones de stdio de C. Lo último incluye cosas como restaurar la asignación normal de \n a \r\n, y, cuando está en modo servidor, restaurar la forma normal de bloqueo de la E/S de la terminal. Después de haber llamado a esta función, la función de acción puede leer de y escribir a la terminal sin temor de crear un desorden. No es necesario que la función de acción restaure el entorno de edición original antes de regresar. Esto se hace automáticamente por gl_get_line() después de que la función de acción regrese. Lo siguiente es un ejemplo simple de una función de acción que escribe la frase "Hello world" en una nueva línea de terminal después de la línea que se está editando. Cuando esta función regresa, la línea de entrada se redibuja en la línea que sigue a la línea "Hello world", y la edición de línea se

reanuda. 
  static GL_ACTION_FN(say_hello_fn)
  {

      return GLA_ABORT;
    printf("Hello world\n");
    return GLA_CONTINUE;
}

  GLA_RETURN    -   Hace que gl_get_line() devuelva la
                    línea de entrada completada.
  GLA_CONTINUE  -   Reanuda la edición de la línea de
comandos.

Tenga en cuenta que el argumento name de gl_register_action() especifica el nombre con el que un usuario puede referirse a la acción en su archivo de configuración. Esto les permite volver a vincular la acción a una secuencia de teclas alternativa. Para que esto funcione, es necesario llamar a gl_register_action() entre la llamada a new_GetLine() y la primera llamada a gl_get_

De forma predeterminada, cada vez que el usuario introduce una línea, se añade automáticamente a la lista de historial, justo antes de gl_get_line() devuelve la línea al llamante. La función constructora new_GetLine() asume que la entrada debe leerse desde stdin, y que la salida se escribe en stdout. La siguiente función le permite cambiar a diferentes flujos de entrada y

     gl_get_line() se convierte en una función de edición de líneas
     incremental no bloqueante que puede llamarse de forma segura desde
     un bucle de eventos externo. Aunque este es un método muy
     versátil, implica asumir algunas
     responsabilidades que normalmente se realizan detrás de escena por gl_get_line().

     teclado del usuario, puede pedirle que también vigile la

enumerados:

Por defecto, la función gl_get_line() intercepta una serie de señales. Esto es particularmente importante para las señales que por defecto terminarían el proceso, ya que el terminal necesita ser restaurado a un estado utilizable antes de que esto suceda. sección.

continuación.

            interrupción del teclado (usualmente ^C), como por la tecla de
            pausa del teclado.
            errno=EINTR
 SIGHUP  -  Esta señal es generada cuando el terminal de
            control termina.
            errno=ENOTTY
 SIGPIPE -  Esta señal es generada cuando un programa intenta
            escribir en una tubería cuyo extremo remoto no está siendo leído
            por ningún proceso. Esto puede suceder, por ejemplo, si ha
            llamado a gl_change_terminal() para
            redirigir la salida a una tubería oculta bajo un
            pseudo-terminal.
            errno=EPIPE
 SIGQUIT -  Esta señal es generada por la tecla de salida del
            teclado (usualmente ^\).
            errno=EINTR
 SIGABRT -  Esta señal es generada por la función estándar de C,

errno=EINTR

regrese.

;

Devuelve el código numérico (p. ej., SIGINT) de la última señal que fue recibida durante la llamada más reciente a gl_get_line(), o -1 si no se recibieron

señales.

aplicación.

Si el proceso todavía existe después de que la señal haya sido entregada, entonces gl_get_line() restablece sus propios manejadores de señal, cambia el terminal de vuelta a modo crudo, vuelve a mostrar la línea de entrada y vuelve a esperar la entrada del terminal del

usuario.

               suspendido es reanudado.
 SIGPOLL    -  En sistemas SVR4, esta señal notifica al

 SIGPWR     -  Esta señal es generada cuando ocurre un fallo

 SIGALRM    -  Esta señal es generada cuando un temporizador
               expira.
 SIGUSR1    -  Una señal específica de la aplicación.
 SIGUSR2    -  Otra señal específica de la aplicación.

 SIGXFSZ    -  Esta señal es generada cuando un proceso

 SIGTSTP    -  Esta señal es generada por la tecla de

Obviamente no todas las señales anteriores están soportadas en todos los sistemas, así que el código para soportarlas se compila condicionalmente en la biblioteca

Usar gl_get_line() para consultar al usuario por una respuesta de un solo carácter, es inconveniente para el usuario, ya que debe presionar la tecla enter o return antes de que el carácter que escribió sea devuelto al programa. Desde la versión 1.4.0 de libtecla, gl_get_line() ha sido de 8 bits limpios. Esto significa que todos los caracteres de 8 bits que son imprimibles en la configuración regional actual del usuario ahora se muestran literalmente y se incluyen en la línea de entrada devuelta. Si ninguna de estas variables está definida, o el programa omite llamar a setlocale, entonces se usa la configuración regional predeterminada C, que es ASCII de 7 bits de EE. UU. SEGURIDAD DE

HILOS

En un programa multihilo, debería usar la versión libtecla_r.a de la biblioteca. Esta usa versiones reentrantes de las funciones del sistema, cuando están disponibles. Desafortunadamente, ni terminfo ni termcap fueron diseñados para ser reentrantes, por

lo que no puede usar de forma segura las funciones del módulo getline en múltiples hilos (puede usar los módulos separados de expansión de archivos y completado de palabras en múltiples hilos, vea las páginas de manual correspondientes para más detall
es). Sin embargo, debido al uso de funciones reentrantes de POSIX para buscar directorios de inicio, etc., es seguro usar este módulo desde un solo hilo de un programa multihilo, siempre que sus otros hilos no usen ninguna función de termcap o terminfo.
