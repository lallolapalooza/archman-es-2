DESCRIPCIÓ

N

La función gl_get_line(), que se documenta por separado en la página del manual gl_get_line(3), admite dos modos de E/S diferentes. Estos se seleccionan llamando a la función gl_io_mode()

. 
  int gl_io_mode(GetLine *gl, GlIOMode mode)
;

El argumento mode de esta función especifica el nuevo modo de E/S, y debe ser uno de los

siguientes. 
  GL_NORMAL_MODE   -  Selecciona el modo normal de E/S bloqueante.
                      En este modo gl_get_line()
                      no retorna hasta que ocurre un error o el usuario termina de introducir una nueva línea. Este modo es el foco de la
                      página del manual gl_get_line(3).
  GL_SERVER_MODE   -  Selecciona el modo de E/S de servidor no bloqueante.
                      En este modo, ya que se utiliza E/S de terminal no bloqueante, la introducción de cada nueva línea de entrada normalmente requiere muchas llamadas a gl_get_line() desde
                      un bucle de eventos externo impulsado por E/S.
                      Este modo es el foco de esta página del
manual.

Los objetos GetLine recién creados comienzan en modo de E/S normal, por lo que para cambiar al modo de servidor no bloqueante se requiere una llamada inicial a gl_io_

mode
().

MODO DE E/S DE

SERVIDOR

En el modo de E/S de servidor no bloqueante, la aplicación debe tener un bucle de eventos que llame a gl_get_line() siempre que el descriptor de archivo del terminal pueda realizar el tipo de E/S que gl_get_line() está esperando. Para determinar qué tipo de E/S gl_get_line() está esperando, la aplicación llama a la función gl_pending_io()

. 
  GlPendingIO gl_pending_io(GetLine *gl)
;

El valor de retorno de esta función es uno de los dos valores enumerados

siguientes. 
  GLP_READ    -  gl_get_line() está esperando para escribir un carácter en el terminal.
  GLP_WRITE   -  gl_get_line() está esperando para leer un carácter del
teclado.

Si la aplicación está utilizando ya sea la select() o la llamada al sistema poll() para vigilar la E/S en un grupo de descriptores de archivo, entonces debe llamar a la función gl_pending_io() antes de cada llamada a estas funciones para ver qué dirección de E/S debe decirles que vigilen, y configurar sus argumentos en consecuencia. En el caso de la llamada al sistema select(), esto significa usar la macro FD_SET() para añadir el descriptor de archivo del terminal ya sea al conjunto de descriptores de archivo a vigilar por legibilidad, o al conjunto a vigilar por

escribibilidad.

Como en el modo de E/S normal, el valor de retorno de gl_get_line() es ya sea un puntero a una línea de entrada completada, o NULL. Sin embargo, mientras que en el modo de E/S normal un valor de retorno NULL siempre significa que ocurrió un error, en el modo de servidor no bloqueante, NULL también se retorna cuando gl_get_line() no puede leer o escribir en el terminal sin bloquearse. Así que en el modo de servidor no bloqueante, para determinar si un valor de retorno NULL significa que ocurrió un error o no, es necesario llamar a la función gl_return_status(). Si esta función retorna el valor enumerado GLR_BLOCKED, como se documenta en la página del manual gl_get_line(3), esto significa que gl_get_line() está esperando E/S, y no ha ocurrido ningún

error.

Cuando gl_get_line() retorna NULL y gl_return_status() indica que esto se debe a E/S de terminal bloqueada, la aplicación debe llamar a gl_get_line() de nuevo cuando el tipo de E/S reportado por gl_pending_io() se vuelva posible. Los argumentos prompt, start_line y start_pos de gl_get_line() serán ignorados en estas llamadas. Si necesita cambiar el prompt de la línea que se está editando actualmente, entonces puede llamar a la función gl_replace_prompt() (documentada en la página del manual gl_get_line(3)) entre llamadas a gl_get_

lin
e().

CEDER EL

TERMINAL

Una complicación única del modo de servidor no bloqueante es que requiere que el terminal se deje en modo crudo entre llamadas a gl_get_line(). Si no fuera el caso, el bucle de eventos externo no sería capaz de detectar pulsaciones de teclas individuales, y la edición de línea básica implementada por el controlador del terminal entraría en conflicto con la edición proporcionada por gl_get_line(). Lo que esto significa es que cada vez que el terminal necesita ser usado para otras cosas que no sean introducir una nueva línea de entrada con gl_get_line(), necesita ser restaurado a un estado utilizable. En particular, siempre que el proceso sea suspendido o terminado, el terminal debe ser devuelto a un estado normal. Si esto no se hace, entonces dependiendo de las características del shell que se usó para invocar el programa, el usuario puede terminar con un terminal colgado. Para este fin, la función gl_normal_io() se proporciona para cambiar el terminal de vuelta al estado en el que estaba cuando se estableció por última vez el modo

crudo. 
  int gl_normal_io(GetLine *gl)
;

Lo que hace esta función es primero vaciar cualquier salida pendiente al terminal, luego mover el cursor al inicio de la línea del terminal que sigue al final de la línea de entrada introducida incompletamente. En este punto es seguro suspender o terminar el proceso, y es seguro para la aplicación leer y escribir en el terminal. Para reanudar la introducción de la línea de entrada, la aplicación debe llamar a la función gl_raw_io()

. 
  int gl_raw_io(GetLine *gl)
;

Esta función inicia una nueva línea, vuelve a mostrar la línea de entrada parcialmente completada (si la hay), restaura la posición del cursor dentro de esta línea a donde estaba cuando se llamó a gl_normal_io(), luego cambia de vuelta al modo de terminal crudo no bloqueante listo para continuar la introducción de la línea de entrada cuando gl_get_line() sea llamado la próxima

vez.

Nótese que en el modo de servidor no bloqueante, si gl_get_line() es llamado después de una llamada a gl_normal_io(), sin una llamada intermedia a gl_raw_io(), gl_get_line() llamará a gl_raw_mode() por sí mismo, y el terminal permanecerá en este modo cuando gl_get_line

() re
torne.

MANEJO DE

SEÑALES

En la sección anterior se señaló que en el modo de servidor no bloqueante, el terminal debe ser restaurado a un estado razonable siempre que se reciba una señal que suspenda o termine el proceso. En el modo de E/S normal, esto se hace por usted por gl_get_line(), pero en el modo de servidor no bloqueante, ya que el terminal se deja en modo crudo entre llamadas a gl_get_line(), este manejo de señales debe ser hecho por la aplicación. Ya que hay muchas señales que pueden suspender o terminar un proceso, así como otras señales que son importantes para gl_get_line(), como la señal SIGWINCH, que le dice cuándo ha cambiado el tamaño del terminal, la función gl_tty_signals() se proporciona para instalar manejadores de señal para todas las señales

pertinentes. 
  int gl_tty_signals(void (*term_handler)(int),
                     void (*susp_handler)(int),
                     void (*cont_handler)(int),
                     void (*size_handler)(int))
;

Lo que hace esto es usar la lista interna de señales de gl_get_line() para asignar manejadores de señal especificados a grupos de señales. Los argumentos de esta función son los

siguientes. 
  term_handler  -  Este es el manejador de señal que se va a usar para atrapar señales que por defecto terminan cualquier proceso que las reciba (ej. SIGINT o SIGTERM).
  susp_handler  -  Este es el manejador de señal que se va a usar para atrapar señales que por defecto suspenden cualquier proceso que las reciba, (ej. SIGTSTP o SIGTTOU).
  cont_handler  -  Este es el manejador de señal que se va a usar para atrapar señales que usualmente se envían cuando un proceso se reanuda después de sersuspendido (normalmente SIGCONT). Tenga cuidado de que no hay nada que impida a un usuario enviar una de estas señales en otros momentos.
                   size_handler  -  Este manejador de señales se utiliza para atrapar
                   señales que se envían a los procesos cuando
                   sus terminales de control son redimensionados
                   por el usuario (por ejemplo, SIGWINCH).
Todos estos
argumentos

pueden ser el mismo, si así se desea, y puede especificar SIG_IGN (ignorar esta señal) o SIG_DFL (usar el manejador de señal predeterminado proporcionado por el sistema) en lugar de una función donde sea pertinente. En particular, rara vez es útil atrapar SIGCONT, por lo que el argumento cont_handler normalmente será SIG_DFL o SIG_IGN. La funció

n

g l_tty_signals() utiliza la función POSIX sigaction() para instalar estos manejadores de señales, y tiene cuidado de usar el miembro sa_mask de cada estructura sigaction para asegurar que solo una de estas señales se entregue alguna vez a la vez. Esto protege contra que diferentes instancias de estos manejadores de señales intenten simultáneamente escribir en datos globales comunes, como un búfer sigsetjmp() compartido o una bandera de señal recibida. Los

manejadores

de señales que son instalados por esta función deberían llamar a la gl_handle_signal().

  gl_handle_signal(int signo, GetLine *gl, int ngl);
El

Para que gl_get_line() sea llamado lo antes posible para hacer esto, gl_handle_signal() también organiza que la próxima llamada a gl_pending_io() devolverá GLP_WRITE. Así que si la aplicación espera E/S en select() o poll(), entonces la aplicación necesita asegurarse de que estas funciones serán abortadas de manera fiable

GL_GET_LINE Dado que se espera que la aplicación maneje las señales en modo de servidor no bloqueante, gl_get_line() no intenta duplicar esto cuando está siendo llamado. Si el proceso no es terminado por esta señal, gl_get_line() devuelve NULL, y una llamada posterior a gl_return_status() devuelve el enumvalor calificado GLR_SIGNA

ABORTANDO LA ENTRADA DE

LÍNEA

A menudo, en lugar de dejar que termine el proceso, las aplicaciones responden a la señal de interrupción del usuario SIGINT abortando la línea de entrada actual. La forma de hacer esto en el modo de E/S de servidor no bloqueante es no llamar a gl_handle_signal() cuando se captura esta señal, sino en su lugar llamar a la gl_abandon_l

ine(). 
  void gl_abandon_line(GetLine *gl)
;

Esta función hace que cuando gl_get_line() sea llamada a continuación, primero vacíe cualquier salida pendiente hacia la terminal, luego descarte la línea de entrada actua

l, emita un nuevo mensaje de solicitud en la siguiente línea, y finalmente
comience a aceptar la entrada de una nueva línea de entrada del usuario.

FUNCIONES SEGURAS PARA

SEÑALES

Si se siguen ciertas reglas, las siguientes funciones pueden haber sido escritas para ser llamadas de forma segura desde manejadores de señales. Otras funciones de esta biblioteca no deben ser llamadas desde manejadores de

señales. 
  gl_normal_io()
  gl_raw_io()
  gl_handle_signal()
  gl_abandon_line(
)

Para que esto sea cierto, todos los manejadores de señales que llaman a estas funciones deben estar registrados de tal manera que solo una instancia de cualquiera de ellas pueda estar en ejecución a la vez. La forma de hacer esto es usar la función POSIX sigaction() para registrar todos los manejadores de señales, y al hacer esto, usar el miembro sa_mask de la estructura sigaction correspondiente, para indicar que todas las señales cuyos manejadores invocan las funciones anteriores, deben estar bloqueadas cuando se está manejando la señal actual. Esto evita que dos manejadores de señales operen en un objeto GetLine al mismo

tiempo.

Para evitar que los manejadores de señales accedan a un objeto GetLine mientras gl_get_line() o cualquiera de sus funciones públicas asociadas están operando en él, todas las funciones públicas asociadas con gl_get_line(), incluyendo gl_get_line() misma, bloquean temporalmente la entrega de señales cuando están accediendo a objetos GetLine. Tenga en cuenta que las únicas señales que bloquean son las señales que gl_get_line() está actualmente configurada para capturar, así que asegúrese de que si llama a cualquiera de las funciones anteriores desde manejadores de señales, las señales a las que están asignados estos manejadores estén configuradas para ser capturadas por gl_get_line() (véase gl_trap_s

ignal
()).

USAR TIEMPOS DE ESPERA PARA

SONDEAR

Si en lugar de usar select() o poll() para esperar la E/S, su aplicación solo necesita salir de gl_get_line() periódicamente para hacer brevemente otra cosa antes de volver a aceptar la entrada del usuario, esto se puede hacer en el modo de servidor no bloqueante usando la función gl_inactivity_timeout() (véase gl_get_line(3)), para especificar que una función de retorno de llamada que devuelva GLTO_CONTINUE debe ser llamada siempre que gl_get_line() haya estado esperando la E/S durante más de una cantidad de tiempo

especificada.

Cuando se activa esta función de retorno de llamada, gl_get_line() devolverá NULL, y una llamada posterior a gl_return_status() devolverá GLR_BLOCKED

.

Tenga en cuenta que gl_get_line() no devolverá hasta que el usuario no haya escrito una tecla durante el intervalo especificado, así que si el intervalo es largo, y el usuario sigue escribiendo, gl_get_line() puede no devolver durante un tiempo. En otras pala

bras, no hay garantía de que devolv
erá en el tiempo especificado.
