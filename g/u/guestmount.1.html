guestmount(1) Soporte de Virtualización guestmount(1)

NOMBRE

guestmount - Montar un sistema de archivos de invitado en el host usando FUSE y libguestfs

SINOPSIS

guestmount [--opciones] -a disco.img -m dispositivo [--ro] punto_montaje
guestmount [--opciones] -a disco.img -i [--ro] punto_montaje
guestmount [--opciones] -d Invitado -i [--ro] punto_montaje

ADVERTENCIA

Usar "guestmount" en modo escritura en máquinas virtuales en vivo, o concurrentemente con otras herramientas de edición de discos, puede ser peligroso, pudiendo causar corrupción del disco. La máquina virtual debe estar apagada antes de usar este comando, y las imágenes de disco no deben ser editadas concurrentemente.

Use la opción --ro (solo lectura) para usar "guestmount" de forma segura si la imagen del disco o la máquina virtual pudieran estar en vivo. Podría ver resultados extraños o inconsistentes si se ejecuta concurrentemente con otros cambios, pero con esta opción no se arriesgará a la corrupción del disco.

DESCRIPCION

El programa guestmount se puede usar para montar sistemas de archivos de máquinas virtuales y otras imágenes de disco en el host. Usa libguestfs para acceder al sistema de archivos del invitado, y FUSE (el "sistema de archivos en el espacio de usuario") para hacerlo aparecer como un dispositivo montable.

Junto con otras opciones, debe proporcionar al menos un dispositivo (opción -a) o un dominio libvirt (opción -d), y al menos un punto de montaje (opción -m) o usar la opción de inspección -i. Cómo funciona esto se explica mejor en la página del manual de guestfish(1), o mirando los ejemplos a continuación.

FUSE permite montar sistemas de archivos como usuario no root. El punto de montaje debe ser de su propiedad. El sistema de archivos no será visible para ningún otro usuario a menos que realice cambios en la configuración, consulte "NOTAS" a continuación.

Para desmontar el sistema de archivos, use el comando guestunmount(1).

EJEMPLOS

Para un invitado típico de Windows que tiene su sistema de archivos principal en la primera partición:

guestmount -a windows.img -m /dev/sda1 --ro /mnt

Para un invitado típico de Linux que tiene un sistema de archivos /boot en la primera partición, y el sistema de archivos raíz en un volumen lógico:

guestmount -a linux.img -m /dev/VG/LV -m /dev/sda1:/boot --ro /mnt

Para que libguestfs detecte los puntos de montaje del invitado automáticamente:

guestmount -a guest.img -i --ro /mnt

Para un invitado de libvirt llamado "Invitado" podrías hacer:

guestmount -d Invitado -i --ro /mnt

Si no sabe qué sistemas de archivos contiene un invitado o una imagen de disco, use virt-filesystems(1) primero:

virt-filesystems -d MiInvitado

Si desea rastrear las llamadas a libguestfs pero sin información de depuración excesiva, recomendamos:

guestmount [...] --trace /mnt

Si desea depurar el programa, recomendamos:

guestmount [...] --trace --verbose /mnt

Para desmontar el sistema de archivos después de usarlo:

guestunmount /mnt

NOTAS

Otros usuarios no pueden ver el sistema de archivos por defecto

Si monta un sistema de archivos como un usuario (por ejemplo, root), otros usuarios no podrán verlo por defecto. La solución es agregar la opción de FUSE "allow_other" al montar:

sudo guestmount [...] -o allow_other /mnt

y habilitar esta opción en /etc/fuse.conf.

Habilitar FUSE

En algunas distribuciones, puede que necesite agregarse a un grupo especial (por ejemplo, "fuse") antes de poder usar cualquier sistema de archivos FUSE. Esto es necesario en Debian y sus derivados.

En otras distribuciones, no se requiere ningún grupo especial. No es necesario en Fedora o Red Hat Enterprise Linux.

error fusermount: "Dispositivo o recurso ocupado"

Puede ver este error cuando otro proceso en el sistema accede al punto de montaje que acaba de crear, manteniéndolo abierto y impidiéndole desmontarlo. Los culpables habituales son varios programas GUI de "indexación".

La solución popular para este problema es reintentar el comando "fusermount -u" varias veces hasta que funcione (guestunmount(1) hace esto por usted). Desafortunadamente, esta no es una solución confiable si (por ejemplo) el sistema de archivos montado es particularmente grande y el programa intruso es particularmente persistente.

Una solución adecuada es usar un punto de montaje privado creando un nuevo espacio de nombres de montaje usando la bandera específica de Linux clone(2)/unshare(2) "CLONE_NEWNS". Desafortunadamente, en este momento requiere root y también necesitaríamos agregarlo como una función a guestmount.

Condiciones de carrera posibles al cerrar la conexión

Cuando guestunmount(1)/fusermount(1) sale, guestmount puede seguir ejecutándose y limpiando el punto de montaje. La imagen del disco no se finalizará completamente.

Esto significa que scripts como el siguiente tienen una condición de carrera desagradable:

guestmount -a disco.img -i /mnt
# copiar cosas en /mnt
guestunmount /mnt
# intentar usar 'disco.img' inmediatamente ** INSEGURO **

La solución es usar la opción --pid-file para escribir el PID de guestmount en un archivo, y luego, después de guestunmount, esperar hasta que este PID salga.

guestmount -a disco.img -i --pid-file guestmount.pid /mnt

# ...
# ...

# Guardar el PID de guestmount *antes* de llamar a guestunmount.
pid="$(cat guestmount.pid)"

# Desmontar el sistema de archivos.
guestunmount /mnt

timeout=10

count=$timeout
while kill -0 "$pid" 2>/dev/null && [ $count -gt 0 ]; do
    sleep 1
    ((count--))
done
if [ $count -eq 0 ]; then
    echo "$0: la espera de que guestmount salga falló después de $timeout segundos"
    exit 1
fi

# Ahora es seguro usar la imagen del disco.

Tenga en cuenta que si usa directamente la API "guestfs_mount_local" (consulte "MONTAJE LOCAL" en guestfs(3)) entonces es mucho más fácil escribir un programa seguro y libre de condiciones de carrera.

OPCIONES

-a IMAGEN
--add IMAGEN
Agregar un dispositivo de bloque o una imagen de máquina virtual.

El formato de la imagen del disco se detecta automáticamente. Para anular esto y forzar un formato particular, use la opción --format=...

-a URI
--add URI
Agregar almacenamiento remoto. Consulte "AÑADIR ALMACENAMIENTO REMOTO" en guestfish(1).
--blocksize=512
--blocksize=4096
--blocksize
Este parámetro establece el tamaño del sector del disco. Afecta a todos los discos añadidos explícitamente posteriormente a este parámetro. Usar --blocksize sin argumento cambia el tamaño del sector del disco al valor predeterminado, que suele ser de 512 bytes. Consulte también "guestfs_add_drive_opts" en guestfs(3).
-c URI
--connect URI
Cuando se usa junto con la opción -d, especifica la URI de libvirt a utilizar. El valor predeterminado es usar la conexión libvirt por defecto.
-d DOMINIO-LIBVIRT
--domain LIBVIRT-DOMAIN
Añade discos del dominio libvirt nombrado. Si también se usa la opción --ro, se puede usar cualquier dominio libvirt. Sin embargo, en modo de escritura, solo se pueden nombrar aquí los dominios libvirt que estén apagados.

Se pueden usar UUIDs de dominio en lugar de nombres.

--dir-cache-timeout N
Establece el tiempo de espera de la caché de readdir a N segundos, siendo el valor por defecto 60 segundos. La caché de readdir [en realidad, hay varias cachés semi-independientes] se popula después de una llamada a readdir(2) con las estadísticas y atributos extendidos de los archivos en el directorio, anticipando que se solicitarán poco después.

También hay un atributo de caché diferente implementado por FUSE (ver la opción FUSE -o attr_timeout), pero la caché de FUSE no anticipa solicitudes futuras, solo cachea las existentes.

--echo-keys
Al solicitar claves y contraseñas, guestfish normalmente desactiva el eco para que no puedas ver lo que estás escribiendo. Si no te preocupan los ataques Tempest y no hay nadie más en la habitación, puedes especificar esta bandera para ver lo que escribes.
--fd=FD
Especifica un descriptor de archivo de tubería o eventfd. Cuando el punto de montaje esté listo para ser utilizado, guestmount escribirá un solo byte en este descriptor de archivo. Esto se puede usar en conjunción con --no-fork para ejecutar guestmount de forma cautiva bajo otro proceso.
--format=raw|qcow2|..
--format
El valor por defecto para la opción -a es auto-detectar el formato de la imagen del disco. Usar esto fuerza el formato del disco para las opciones -a que siguen en la línea de comandos. Usar --format sin argumentos vuelve a la auto-detección para las opciones -a subsiguientes.

Si tienes imágenes de disco de invitado en formato raw sin confiar en ellas, deberías usar esta opción para especificar el formato del disco. Esto evita un posible problema de seguridad con invitados maliciosos (CVE-2010-3851). Ver también "guestfs_add_drive_opts" en guestfs(3).

--fuse-help
Muestra ayuda sobre opciones especiales de FUSE (ver -o abajo).
--help
Muestra ayuda breve y sale.
-i
--inspector
Usando el código de virt-inspector(1), inspecciona los discos buscando un sistema operativo y monta los sistemas de archivos como se montarían en la máquina virtual real.
--key SELECTOR
Especifica una clave para LUKS, para abrir automáticamente un dispositivo LUKS al usar la inspección.
--key NOMBRE:key:CADENA_CLAVE
--key UUID:key:CADENA_CLAVE
--key all:key:CADENA_CLAVE
"NOMBRE" es el nombre del dispositivo libguestfs (ej. "/dev/sda1"). "UUID" es el UUID del dispositivo. "all" significa intentar la clave contra cualquier dispositivo cifrado.

Usa la "CADENA_CLAVE" especificada como contraseña.

--key NOMBRE:file:NOMBRE_ARCHIVO
--key UUID:file:NOMBRE_ARCHIVO
--key all:file:NOMBRE_ARCHIVO
Lee la contraseña del archivo NOMBRE_ARCHIVO.
--key NOMBRE:clevis
--key UUID:clevis
--key all:clevis
Intenta desbloquear el dispositivo sin contraseña con Clevis, a través de la red. Por favor, consulta "DISCOS CIFRADOS" en guestfs(3) para más información sobre el cifrado de discos enlazados a la red (NBDE).

Ten en cuenta que si alguna de estas opciones está presente en la línea de comandos, la red de usuario de QEMU se habilitará automáticamente para la instancia de libguestfs.

--keys-from-stdin
Lee parámetros de clave o contraseña desde stdin. El valor por defecto es intentar leer las contraseñas del usuario abriendo /dev/tty.

Si hay varios dispositivos cifrados, es posible que necesites suministrar varias claves en stdin, una por línea.

-m dev[:mountpoint[:options[:fstype]]
--mount dev[:mountpoint[:options[:fstype]]]
Monta la partición o volumen lógico nombrado en el punto de montaje dado en el invitado (esto no tiene nada que ver con los puntos de montaje en el host).

Si se omite el punto de montaje, se usa / por defecto. Tienes que montar algo en /.

La tercera (y raramente usada) parte del parámetro de montaje es la lista de opciones de montaje utilizadas para montar el sistema de archivos subyacente. Si no se proporciona, las opciones de montaje son la cadena vacía o "ro" (la última si se usa la bandera --ro). Al especificar las opciones de montaje, anulas esta elección por defecto. Probablemente la única vez que usarías esto es para habilitar ACLs y/o atributos extendidos si el sistema de archivos puede soportarlos:

-m /dev/sda1:/:acl,user_xattr

La cuarta parte del parámetro es el controlador del sistema de archivos a usar, como "ext3" o "ntfs". Esto rara vez es necesario, pero puede ser útil si varios controladores son válidos para un sistema de archivos (ej: "ext2" y "ext3"), o si libguestfs identifica erróneamente un sistema de archivos.

--no-fork
No daemonizar (o ejecutar en segundo plano).
-n
--no-sync
Por defecto, intentamos sincronizar el disco del invitado al desmontar el punto de montaje FUSE. Si especificas esta opción, entonces no intentamos sincronizar el disco. Ver la discusión sobre autosync en la página man de guestfs(3).
-o OPCION
--option OPCION
Pasa opciones adicionales a FUSE.

Para obtener una lista de todas las opciones adicionales soportadas por FUSE, usa el comando de abajo. Ten en cuenta que solo se pueden pasar las opciones -o de FUSE, y solo algunas de ellas son una buena idea.

guestmount --fuse-help

Algunas opciones de FUSE potencialmente útiles:

-o allow_other
Permite que otros usuarios vean el sistema de archivos. Esta opción no tiene efecto a menos que la habilites globalmente en /etc/fuse.conf.
-o attr_timeout=N
Habilita el almacenamiento en caché de atributos por parte de FUSE y establece el tiempo de espera a N segundos.
-o kernel_cache
Permite al kernel almacenar archivos en caché (reduce el número de lecturas que tienen que pasar por la API de guestfs(3)). Esto es generalmente una buena idea si puedes permitirte el uso extra de memoria.
-o uid=N -o gid=N
Usa estas opciones para mapear todos los UIDs y GIDs dentro del sistema de archivos del invitado a los valores elegidos.
-o use_ino
Preserva los números de inodo del sistema de archivos subyacente.

Sin esta opción, FUSE inventa sus propios números de inodo. Los números de inodo que ves en stat(2), "ls -i", etc., no son los números de inodo del sistema de archivos subyacente.

Nota: esta opción es potencialmente peligrosa si el sistema de archivos subyacente consta de varios puntos de montaje, ya que puedes ver números de inodo duplicados apareciendo a través de FUSE. El uso de esta opción puede confundir a algunos programas.

--pid-file NOMBRE_ARCHIVO
Escribe el PID del proceso trabajador de guestmount en "NOMBRE_ARCHIVO".
-r
--ro
Añade dispositivos y monta todo en modo de solo lectura. También prohíbe las escrituras y hace que el disco parezca de solo lectura para FUSE.

Esto es muy recomendable si no vas a editar el disco del invitado. Si el invitado está en ejecución y esta opción *no* se proporciona, existe un fuerte riesgo de corrupción del disco en el invitado. Intentamos evitar que esto suceda, pero no siempre es posible.

Ver también "ABRIR DISCOS PARA LECTURA Y ESCRITURA" en guestfish(1).

--selinux
Esta opción se proporciona por compatibilidad hacia atrás y no hace nada.
-v
--verbose
Habilita mensajes detallados de la librería subyacente libguestfs.
-V
--version
Muestra la versión del programa y sale.
-w
--rw
Esto cambia las opciones -a, -d y -m para que los discos se añadan y los montajes se realicen en modo de lectura y escritura.

Ver "ABRIR DISCOS PARA LECTURA Y ESCRITURA" en guestfish(1).
