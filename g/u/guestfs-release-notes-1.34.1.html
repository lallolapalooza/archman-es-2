NOTAS DE LA VERSIÓN PARA LIBGUESTFS 1.

34

Estas notas de la versión solo cubren las diferencias con la división estable/desarrollo anterior (1.32.0). Para registros de cambios detallados, consulte el repositorio git o el archivo ChangeLog distribuido en el

tarball.

Nuevas

características

Se realizaron múltiples mejoras de rendimiento en libguestfs. El tiempo de "caché caliente" para iniciar el appliance debería ser inferior a 1 segundo, siempre que se instalen un qemu y un kernel recientes. También hay nuevas utilidades para realizar benchmarks precisos de libguestfs (utils/boot-benchmark y utils/boot-analysis en el árbol de código fuente)

.

La herramienta virt-p2v para convertir máquinas físicas en máquinas virtuales fue mejorada sustancialmente. Esto incluye: salida más clara y con colores durante las conversiones, soporte para Gtk 3, información más detallada sobre el hardware, clic para identificar interfaces de red, más herramientas de depuración incluidas con el ISO y muchas correcciones de

errores.

Ahora se soporta f2fs (Flash Friendly File System) (Pino Toscano)

.

Nuevas

herramientas

virt-p2v-make-kiwi(1) se puede usar para construir el ISO de virt-p2v basado en SLES y openSUSE, usando la utilidad kiwi (Cédric Bosdonnat)

.

Nuevas características en herramientas

existentes

virt-resize ahora preservará el GUID GPT. Esto era necesario para Windows Server 2012 R2, donde el gestor de arranque se confundiría si el GUID cambiaba (Maxim Perevedentsev)

.

virt-resize usará copia dispersa para particiones extendidas (de estilo MBR antiguo). Esto hace que el redimensionamiento de invitados que usan particiones extendidas sea mucho más rápido (Maxim Perevedentsev)

.

Las opciones de línea de comandos del kernel de virt-p2v ahora se pueden usar para establecer valores predeterminados para la configuración de la

GUI.

Las opciones de depuración de virt-p2v se han eliminado por completo, simplificando la interfaz y la documentación. La información de depuración ahora se captura completamente automáticamente

.

virt-p2v-make-disk le permite especificar una opción --arch, lo que le permite construir un virt-p2v de 32 bits, para compatibilidad con sistemas más

antiguos.

virt-p2v-make-disk ya no requiere que especifique una "os-version" para el disco de virt-p2v. Si se omite, intentará elegir una "os-version" adecuada dependiendo de su sistema

anfitrión.

virt-p2v-make-disk y virt-p2v-make-kickstart obtienen ambas una nueva opción --install que le permite agregar paquetes extra arbitrarios al ISO de virt-p2v, para personalización, herramientas de depuración adicionales,

etc.

virt-v2v ahora desinstalará Parallels Tools (o el equivalente Virtuozzo Tools) de los invitados Linux. También evitará que los controladores de Windows se carguen en el arranque. (Roman Kagan y Pavel

Butsykin)

virt-v2v El modo --in-place ha sido mejorado para permitir al llamador elegir si instalar o no ciertos controladores virtio en el invitado (Roman Kagan)

.

La conversión de virt-v2v de invitados Windows fue reescrita y simplificada sustancialmente (Roman Kagan)

.

virt-v2v El modo --in-place ahora soporta la instalación de controladores virtio-scsi en invitados (Roman Kagan)

.

virt-v2v ahora puede convertir invitados SUSE con y sin UEFI (Cédric Bosdonnat y Jim Fehlig)

.

virt-v2v ahora puede convertir invitados a Glance que tengan múltiples discos. Anteriormente fallaría con tales

invitados.

Las opciones virt-v2v --no-trim y --vmtype ahora son operaciones nulas. Imprimirán una advertencia pero se ignorarán de lo contrario. virt-v2v ahora puede generar el vmtype OVF correctamente sin intervención del

usuario.

virt-v2v ha sido probado ahora contra SUSE Xen como hipervisor de origen (Cédric Bosdonnat)

.

virt-v2v agrega soporte para controladores VMDP de SUSE (Cédric Bosdonnat)

.

virt-v2v puede convertir archivos OVA que contengan subcarpetas, como los producidos por SUSE Studio (Cédric Bosdonnat)

.

virt-v2v establece el elemento "<Origin>" del OVF correctamente. oVirt ha sido extendido para soportar más hipervisores de origen (Shahar Havivi)

.

virt-v2v ahora soporta Windows Server 2016 (Tomáš Golembiovský)

.

La opción --list de virt-builder ahora se puede usar para mostrar todas las plantillas o una sola plantilla (Pino Toscano)

.

Todas las herramientas basadas en OCaml ahora usan getopt_long(3) para el análisis de opciones, y la salida de --help ha sido mejorada (Pino Toscano)

.

La opción --selinux-relabel de virt-builder y virt-customize ahora puede reetiquetar completamente el sistema de archivos del invitado en tiempo de construcción, sin requerir un largo autorelabel en el primer

arranque.

virt-customize --delete ahora acepta

comodines.

La nueva opción --uninstall de virt-customize le permite desinstalar

paquetes.

virt-customize ahora puede usar "pvvxsvc" como alternativa a "rhsrvany" para ejecutar scripts de firstboot en invitados Windows (Cédric Bosdonnat)

.

virt-customize ahora usa el esquema de hash más fuerte para contraseñas en Arch y Void Linux (Pino Toscano)

.

virt-customize --install ahora funciona correctamente en Arch (Pino Toscano)

.

virt-inspector tiene nuevas opciones --no-applications y --no-icon para evitar que la lista de aplicaciones y el icono se incluyan en la salida XML (Pino Toscano)

.

Se ha añadido la nueva opción --network de virt-sysprep, lo que le permite usar realmente las opciones --install, etc., que estaban presentes en virt-sysprep antes pero que normalmente no funcionaban. Tenga en cuenta que la red sigue estando deshabilitada por

defecto.

La operación "fs-uuids" de virt-sysprep ya no falla en invitados btrfs (Maxim Perevedentsev)

.

virt-dib puede generar imágenes Docker (Pino Toscano)

.

virt-dib tiene una nueva opción --drive-format que permite al usuario especificar el formato de la unidad auxiliar (Pino Toscano)

.

Todas las herramientas virt de OCaml ahora tienen una opción --colors/--colours que habilita la salida con colores (usando secuencias de escape ANSI) incluso si la salida no es un tty. El valor predeterminado es comprobar si la salida es un tty y deshabilitar la salida con colores si no lo es. Esto permite que otras herramientas consuman la salida con

colores.
