Cambios en la API

"guestfs_canonical_device_name"
Esta llamada ya no modificará incorrectamente los nombres de dispositivos RAID por software de Linux (como /dev/mdX).
"guestfs_file_architecture"
Anteriormente, la API "file_architecture" podía devolver cualquiera de las cadenas "i386" o "i486" para binarios x86 de 32 bits. Ahora solo devuelve "i386" (como se documenta).

Esta API ahora puede devolver los siguientes valores nuevos: "riscv32", "riscv64", "riscv128", "s390", "s390x".

"guestfs_hivex_open"
Ahora tiene una bandera opcional "GUESTFS_HIVEX_OPEN_UNSAFE" que permite abrir ciertas colmenas del Registro de Windows corruptas. Esta función requiere hivex ≥ 1.3.14 (Dawid Zamirski).
"guestfs_list_partitions"
Esta llamada ahora devuelve particiones RAID por software de Linux.
"guestfs_part_to_dev"
Esta llamada ahora maneja correctamente los nombres de partición que incluyen "p<N>" (Pino Toscano).
"guestfs_set_label"
Esta llamada ahora puede cambiar las etiquetas de las particiones de intercambio (Pino Toscano).

Cambios en la compilación

libmagic, la parte de la biblioteca del comando "file", ahora es necesaria en tiempo de compilación (anteriormente opcional).

GCC 7 ahora es compatible.

Ahora se utilizan "reglas silenciosas" para programas OCaml y enlaces Java. Para mostrar la línea de comandos completa ejecutada, agregue "V=1" en la línea de comandos de make (Pino Toscano).

Las pruebas lentas ("make check-slow") ahora cubren: scripts de primer arranque en invitados de Linux; conversión de v2v de una selección de invitados reales de Linux; la configuración de --hostname y --timezone de virt-customize; el parámetro --root-password; que la consola serial funcione en invitados de virt-builder.

Los archivos fuente de C generados grandes, por ejemplo, la lista de comandos que se encuentran en fish/cmds.c (y muchos más), se han dividido en archivos más pequeños para acelerar la compilación paralela.

"make maintainer-check-extra-dist" ahora verifica que todos los archivos generados estén incluidos en el tarball.

Las pruebas ya no asumen que "." está en @INC de Perl, ya que pronto se eliminará (Pino Toscano).

Ahora se admiten hosts Debian que usan UsrMerge (Pino Toscano).

Los archivos de encabezado y las estructuras C ahora pueden tener documentación interna utilizando los comentarios especiales "/** ... */".

Las sustituciones de "@VAR@" en "./run" ahora están completamente entre comillas. Esto es necesario para que (por ejemplo) "./configure PYTHON=/some/path" funcione de manera robusta si contiene caracteres que necesitan ser entrecomillados (Hilko Bengen).

gperf ≥ 3.1 ahora es compatible.

Las compilaciones antiguas de edk2 de Kraxel ya no se pueden utilizar para el soporte UEFI. El código UEFI ahora es software completamente libre, así que use las versiones incluidas en su distribución de Linux en su lugar.

Virt-p2v ahora se puede compilar en Linux RHEL 5 (era 2007) con Gtk 2.10.

Internos

Los módulos generador y mllib "Common_utils" ahora se comparten del mismo archivo fuente.

Se ha trasladado una cantidad considerable de código común al directorio common en el código fuente y ahora se compila una sola vez. Las mini-bibliotecas ubicadas aquí son: common/edit, common/errnostring, common/miniexpect, common/options, common/parallel, common/progress, common/protocol, common/utils, common/visit, common/windows.

El directorio que contiene el código de la biblioteca principal se ha movido de src → lib.

Todas las pruebas escritas en script de shell ahora utilizan un archivo común de funciones de utilidad ( tests/test-functions.sh). Hay varias funciones de utilidad nuevas, principalmente para omitir pruebas. Además, estos scripts de prueba ahora pueden usar variables de ruta similares a autoconf, como $abs_top_srcdir.

Las rutas UEFI ahora se almacenan en el generador (generator/uefi.ml).

La forma en que el generador maneja las acciones y los números de procedimiento ha sido modificada de manera bastante sustancial. Consulte generator/actions_*.ml y generator/proc_nr.ml.

Ahora se utiliza el módulo gnulib "getprogname" en todas partes cuando se necesita/imprime el nombre del programa (Pino Toscano).

perl/Guestfs.c no es traducible (Nikos Skalkotos).

Las plantillas de Virt-builder se movieron de builder/website a builder/templates y ahora hay un único programa unificado que puede construir cualquier plantilla.

Todas las utilidades del registro de Windows utilizadas por virt-customize y virt-v2v se han movido a un módulo común llamado "Registry" bajo mllib.

Todas las vinculaciones POSIX se han movido a un nuevo módulo llamado "Unix_utils" bajo mllib.

Inspection, virt-customize y virt-v2v ya no recalculan el "%systemroot%" de Windows, "CurrentControlSet" o las rutas a las colmenas "HKLM\SYSTEM" y "HKLM\SOFTWARE" en varios lugares. En su lugar, todas estas se calculan una vez (durante la inspección) y se pasan a las otras herramientas a través de varias APIs de "guestfs_inspect_get_windows_*".

ahora está disponible dentro de la aplicación, por lo que cualquier herramienta que ejecutemos y que requiera una pty ahora funcionará (Pino Toscano).

Se han corregido la mayoría de las advertencias de OCaml.

Ahora existe una única función común para crear archivos temporales ("guestfs_int_make_temp_path") (Matteo Cafasso).

La variable de entorno $TERM ahora se valida antes de pasarla a la línea de comandos del kernel de la aplicación.

Los dispositivos USB y memballoon inútiles ya no se crean en la aplicación (Laine Stump).

En aarch64, ahora usamos virtio-pci para la aplicación. Esto es algo más rápido que virtio-mmio.

Se ha minimizado el uso de srandom(3) y random(3). En particular, los nombres de archivo temporales ya no se crean basándose en la aleatoriedad devuelta por random(3), sino que se utiliza /dev/urandom en su lugar.
