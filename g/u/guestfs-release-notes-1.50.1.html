NOTAS DE LA VERSIÓN PARA LIBGUESTFS 1.

50

Estas son las notas de la versión para la versión estable de libguestfs 1.50. Aquí se describen los cambios principales desde la versión 1.

48.

Libguestfs 1.50.0 se publicó el 7 de febrero d

e 2023.

Enlaces de

idiomas

Corregidos los enlaces de PHP para PHP8 (Geoff Amey)

.

Corregidas varias advertencias de obsolescencia en los enlaces de

GObject.

Ya no usamos la biblioteca o

bsoleta distutils de Python (
gracias a Miro Hrončok).

Inspecció

n

Al listar los paquetes en invitados basados en RPM, la API de inspección ya no verifica las firmas de los paquetes. Esto se debe a que la versión más reciente de librpm utilizada por libguestfs no entiende las firmas almacenadas en invitados más antiguos, como las SHA1 usadas por RHEL 6 (gracias a Panu Matilainen)

.

"guestfs_inspect_get_hostname" en guestfs(3) puede ahora manejar archivos /etc/hostname que contienen comentarios (gracias a Dawid Zamirski)

.

"guestfs_file_architecture" en guestfs(3) ahora puede analizar archivos que usan compresión

zstd.

"guestfs_inspect_get_osinfo" en guestfs(3) ahora devuelve el campo osinfo correcto para Windows 11. Sin embargo, debido a decisiones tomadas por Microsoft, estos invita

dos aún devuelven el nombre del producto y otras cadenas que los id
entifican como Windows 10 (gracias a Yaakov Selkowitz, Yongkui Guo).

AP

I

Nuevas

API

"guestfs_device_name" en guestfs(3) es una nueva API para leer el nombre del dispositivo asociado con una unidad, por ejemplo, llamar a esta función con 0 devolverá "/dev/sda"

.

"guestfs_clevis_luks_unlock" en guestfs(3) es una nueva API para desbloquear discos usando el esquema de cifrado de disco completo basado en red Clevis/Tang. Además, se implementa esto en guestfish y guestmount (Laszlo Ersek)

.

"guestfs_inspect_get_build_id" en guestfs(3) es una nueva API para leer el ID de compilación de algunos invitados Linux y Windows. No se usa ampliamente en Linux, pero para Windows es vital para identificar Windows

11.

Otros cambios en la

API

En la API "guestfs_add_drive" en guestfs(3), los campos "name" y "iface" no se usan. "name" no se ha usado desde aproximadamente 2017, pero la documentación solo se ha actualizado ahora para reflejar esto. "iface" nunca estuvo permitido para el backend de libvirt y no funcionaba de manera confiable con el backend directo (Laszlo Ersek)

.

"guestfs_readdir" en guestfs(3) ya no está limitado al tamaño máximo del mensaje, sino

que puede leer un directorio de
cualquier tamaño (Laszlo Ersek).

Cambios en la

compilación

Tenga en cuenta que los enlaces de Augeas para libguestfs ya no están incluidos en libguestfs y deben compilarse por separado. Vea: https://people.redhat.com/~rjones/augeas/ Para RHEL 7+, reconstruir el paquete Fedora Rawhide

funcionará.

Tenga en cuenta que libguestfs ahora requiere como mínimo OCaml 4.04. No se compilará en RHEL

6.

Tenga en cuenta que zstd es ahora una dependencia

requerida.

OCaml gettext ya no es una dependencia de libguestfs. (El gettext simple sigue usándose opcionalmente para traducir archivos de código fuente C.

)

Añadido soporte para OCaml 4.

14.

Corregida la compilación por funciones faltantes de la biblioteca estándar en OCaml 4.

04.

Corregido "./configure --disable-ocaml". OCaml sigue siendo necesario para compilar libguestfs, pero ahora esto desactiva correctamente los enlaces de OCaml de la

API.

Añadido soporte preliminar para compilar en Artix, Rocky y Virtuozzo (Halil Tezcan KARABULUT, Neil Hanlon, Andrey Drobyshev). Además, al determinar la distribución local, ahora miramos $ID_LIKE en /etc/os-release antes de $ID, lo que ayuda en Arch (gracias a S D Rausty)

.

Añadido soporte preliminar para compilar libguestfs en

macOS.

Corregida la descripción del sitio web sobre cómo clonar el repositorio de libguestfs (Kashyap Chamarthy)

.

Ya no usamos el printf personalizado de

glibc.

Ya no usamos "LD_PRELOAD=libSegFault.so" en el appliance. Esta característica fue eliminada en glibc 2.

35.

Ya no usamos

sondas dtrace
/ systemtap.

Interno

s

Corregidas las pruebas de regresión para usar las rutas correctas (Nikolay Shirokovskiy)

.

Varias mejoras en el manejo del appliance qcow2 (Andrey Drobyshev)

.

Deshabilitadas las tablas de páginas de 5 niveles en qemu. Esto evita un error en versiones más antiguas de

qemu.

Deshabilitado el devicesfile de LVM2 en el appliance ya que interfiere con los LVs clonados que tienen el mismo UUID (Laszlo Ersek)

.

No usar "-cpu max" en RISC-V ya que aún no es soportado por la emulación TCG de qemu de esa arquitectura. Esto se volverá a habilitar cuando qemu tenga

soporte.

Se evitó un bloqueo raro que ocurría al iniciar el appliance. Resultó ser causado por usar la llamada insegura setenv(3) entre fork y exec (gracias a Siddhesh Poyarekar)

.

Al ejecutar el comando file dentro del appliance, ahora deshab

ilitamos seccomp ya que interfiere con el procesamiento d
e archivos comprimidos (gracias a David Runge, Toolybird).
