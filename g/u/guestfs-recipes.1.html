Calcular el checksum de un archivo o dispositivo dentro de una imagen de

disco

Para calcular el checksum de un dispositivo completo, o una partición, LV, etc., dentro de una imagen de

disco: 
guestfish --ro -a disk.img run : checksum-device md5
/dev/sda1

Reemplaza "md5" con el tipo de checksum que desees. Consulta "guestfs_checksum_device" en guestfs(3) para una lista de tipos

soportados.

/dev/sda1 significa "la primera partición". Podrías usar /dev/sda para calcular el checksum de toda la imagen de disco, o el nombre de un volumen lógico o dispositivo

RAID.

Para calcular el checksum de un solo

archivo: 
guestfish --ro -a disk.img -i checksum sha256
/etc/passwd

o para un huésped

Windows: 
guestfish --ro -a disk.img -i \
  checksum sha256 'win:\windows\system32\config\SOFTWAR
E
'

Convertir de un formato/sistema de archivos a

otro

Si tienes un disco de datos en un formato / sistema de archivos / partición / gestor de volúmenes, puedes convertirlo a otro usando esta

técnica.

En este ejemplo, comenzamos con un disco de datos que tiene una sola partición que contiene un sistema de archivos, y queremos crear otro disco que contenga los mismos archivos pero en un sistema de archivos ext3 incrustado en un volumen lógico en un disco raw con formato

sparse.

Primero crea el disco destino formateado pero

vacío:

virt-format -a target.img --partition=mbr --lvm --filesystem=ext

disco: 
guestfish --ro -a source.img -m /dev/sda1  -- tar-out / - | \
guestfish --rw -a target.img -m /dev/VG/LV -- tar-in -
/

Para examinar la imagen de disco final,

haz: 
guestfish --ro -a target.img -m /dev/VG/LV
><fs> ll
/

Esta técnica es bastante poderosa, permitiéndote, por ejemplo, dividir los directorios de origen entre los sistemas de archivos de

destino.

Ten en cuenta que esto no funcionará (al menos, no

Convertir una imagen sin particiones estilo Xen a una imagen de disco con

particiones

Las imágenes de disco Xen a menudo no tienen particiones, lo que significa que el sistema de archivos comienza directamente al principio del disco sin una tabla de particiones. De hecho, puedes usarlas directamente en KVM (siempre que el huésped no sea Windows), pero algunas personas prefieren convertirlas a imágenes de disco con particiones regulares, y esto es necesario para huéspedes Windows. Aquí está cómo usar guestfish para hacer

esto: 
guestfish
><fs> add-ro input.img
><fs> sparse output.img 10G     # ajusta el tamaño de salida
><fs> run
# Crea una tabla de particiones en el disco de salida:
><fs> part-init /dev/sdb mbr
><fs> part-add /dev/sdb p 2048 -2048
# Copia los datos a la partición destino:
><fs> copy-device-to-device /dev/sda /dev/sdb1 sparse:true
# Opcionalmente redimensiona el sistema de archivos destino. Usa ntfsresize
# para huéspedes Windows:
><fs> resize2fs
/dev/sdb1

Una imagen de disco así no será directamente arrancable. Puede que necesites arrancarla con un kernel e initramfs externos (ver abajo). O puedes usar los comandos de guestfish "syslinux" o "extlinux" para instalar un car

gador de arranq
ue SYSLINUX.

Letras de unidad sobre

FUSE

Tiene un invitado de Windows y quiere exponer las letras de unidad como puntos de montaje FUSE (/C/..., /D/... etc). En lugar de guestmount(1), use este script de

Perl: 
#!/usr/bin/perl -w
use strict;
use Sys::Guestfs;
$| = 1;
die "usage: $0 mountpoint disk.img" if @ARGV < 2;
my $mp = shift @ARGV;
my $g = new Sys::Guestfs;
$g->add_drive_opts ($_) foreach @ARGV;
$g->launch;
my @roots = $g->inspect_os;
die "$0: no operating system found" if @roots != 1;
my $root = $roots[0];
die "$0: not Windows" if $g->inspect_get_type ($root) ne "windows";
my %map = $g->inspect_get_drive_mappings ($root);
foreach (keys %map) {
    $g->mkmountpoint ("/$_");
    eval { $g->mount ($map{$_}, "/$_") };
    warn "$@ (ignored)\n" if $@;
}
$g->mount_local ($mp);
print "filesystem ready on $mp\n";
$g->mount_local_run;
$g->
shutdown;

Exportar kernel e initramfs (initrd)

externos

Si un invitado de Linux no tiene un cargador de arranque o está roto, entonces generalmente puede arrancarlo usando un kernel e initramfs externos. En esta configuración, el hipervisor actúa como un cargador de arranque, cargando el kernel desde el disco del host en la memoria del invitado y saltando directamente al

kernel.

Sin embargo, puede preguntarse cómo obtener el kernel correcto correspondiente a la imagen de disco que tiene. Desde libguestfs ≥ 1.24 virt-builder(1) puede obtener el kernel más reciente y el initramfs correspondiente para

usted:

virt-builde
r --get-kernel disk.img -o
outputdir ls -lh outputdir

Instalar el gestor de arranque SYSLINUX en un

huésped

SYSLINUX es un gestor de arranque pequeño y fácil de configurar para huéspedes Linux y Windows. Si tu huésped no es arrancable, puedes instalar el gestor de arranque SYSLINUX usando los comandos de guestfish "syslinux" (para huéspedes basados en FAT) o "extlinux" (para huéspedes basados en ext2/3/4 y btrfs)

.

Esta guía asume un huésped Linux donde /dev/sda1 es /boot, /boot/vmlinuz es el kernel del huésped, y /dev/sda3 es la partición raíz. Para un huésped Windows necesitarías una partición de arranque formateada en FAT y necesitarías usar el comando "syslinux" en su

lugar.

Crea un archivo de configuración syslinux.cfg. Deberías consultar la documentación de SYSLINUX en http://www.syslinux.org pero podría verse algo

así: 
DEFAULT linux
LABEL linux
  SAY Booting the kernel
  KERNEL vmlinuz
  INITRD initrd
  APPEND ro
root=/dev/sda3

Localiza el registro de arranque maestro de syslinux (un archivo llamado algo como /usr/share/syslinux/mbr.bin)

. 
guestfish -a disk.img -i
# Subir el registro de arranque maestro y el archivo de configuración:
><fs> upload ..../mbr.bin /boot/mbr.bin
><fs> upload ..../syslinux.cfg /boot/syslinux.cfg
# Poner el MBR en el sector de arranque:
><fs> copy-file-to-device /boot/mbr.bin /dev/sda size:440
# Instalar syslinux en la primera partición:
><fs> extlinux /boot
# Establecer la primera partición como arrancable:
><fs> part-set-bootable /dev/sda 1
true

Ver también: http://rwmj.wordpress.com/2013/04/04/new-in-libguestfs-use-syslinux-or-extlinux-to-make-bootable-guests/#conte

correcto:
