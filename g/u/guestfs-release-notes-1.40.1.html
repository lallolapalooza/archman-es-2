NOMBRE

guestfs-release-notes - Notas de la versión de libguestfs

NOTAS DE LA VERSIÓN PARA LIBGUESTFS 1.40

Estas notas de la versión solo cubren las diferencias respecto a la anterior división de ramas estable/desarrollo (1.38.0). Para registros de cambios detallados, consulte el repositorio git o el archivo ChangeLog distribuido en el tarball.

Nuevas características

Nuevas características en herramientas existentes

Virt-inspector ahora muestra el ID corto de libosinfo para los invitados (Pino Toscano).

Guestfish -N ahora generará discos de 1G en lugar de discos de 100M de forma predeterminada.

Virt-resize admite sistemas de archivos f2fs (Pino Toscano).

libguestfs-test-tool ahora admite autocompletado con tabulador en bash (Pino Toscano).

La opción --machine-readable ahora admite enviar la salida a archivos o a stdout/stderr. Esto funciona de manera uniforme en la mayoría de las herramientas virt basadas en OCaml, específicamente: virt-builder, virt-builder-repository, virt-dib, virt-get-kernel, virt-resize, virt-sparsify y virt-v2v (Pino Toscano).

La opción --uninstall de Virt-builder ahora funciona en SUSE (Sebastian Meyer).

Virt-builder ahora admite Windows. No podemos distribuir plantillas de Windows en el repositorio público por razones evidentes de licencia, pero si es usted suscriptor de MSDN puede crear las suyas propias. Vea https://rwmj.wordpress.com/2018/09/13/creating-windows-templates-for-virt-builder/

Muchas herramientas ahora admiten una opción --key que le permite pasar claves de descifrado para sistemas de archivos almacenados en archivos locales en el host en lugar de tener que introducirlas por stdin (Pino Toscano).

virt-v2v y virt-p2v

Nuevo modo -o rhv-upload para subir imágenes directamente a RHV, omitiendo el Dominio de Almacenamiento de Exportación (Tomáš Golembiovský, Nir Soffer, Daniel Erez, Pino Toscano).

Nuevo modo -o openstack para subir imágenes directamente a OpenStack y Cinder usando las APIs de OpenStack.

Virt-v2v ahora tiene un mecanismo general para las opciones de entrada y salida: -io y -oo.

Virt-v2v ahora puede instalar las herramientas de RHV o QEMU GA en los invitados (Tomáš Golembiovský).

El enorme manual se ha dividido ahora en varios documentos más pequeños y está más enfocado en ayudar a los usuarios a realizar tareas específicas de v2v.

Múltiples mejoras en los metadatos OVF al convertir a RHV (Tomáš Golembiovský, Pino Toscano, Arik Hadas).

Virt-v2v ahora puede convertir invitados Linux con paquetes de kernel divididos, especialmente Ubuntu 18.04 (Pino Toscano).

La antigua opción --password-file de Virt-v2v ha sido reemplazada por -ip (la opción antigua se mantiene por compatibilidad hacia atrás).

Virt-v2v ahora preserva el ID de Generación de la VM.

Virt-v2v tiene una nueva opción --mac que permite mapear NICs específicas con precisión a redes o puentes en el destino.

Nueva opción --print-estimate de virt-v2v para estimar el tamaño de los datos que virt-v2v copiará.

Virt-v2v ahora suele ser capaz de eliminar open-vm-tools y VMware Tools del invitado Linux durante la conversión (Pino Toscano).

Virt-v2v ahora puede admitir conversiones UEFI a RHV (Tomáš Golembiovský).

Virt-p2v ahora prefiere que apague en lugar de reiniciar la máquina después de que la conversión haya finalizado (Pino Toscano).

Virt-v2v ahora escribe el ID corto de libosinfo en los metadatos de libvirt cuando se usan los modos de salida -o local y -o libvirt (Martin Kletzander).

Enlaces de lenguaje

Se admite OpenJDK 10+ (Pino Toscano).

Enlaces de Java corregidos para el host Gentoo (Martin Kletzander).

Inspección

Soporte para Kali Linux (Pino Toscano).

Al inspeccionar puntos de montaje, buscar también /etc/mdadm/mdadm.conf además de /etc/mdadm.conf (Nikolay Ivanets).

Soporte mejorado para OpenSUSE Tumbleweed (Pino Toscano).

Arquitecturas y plataformas

Varios arreglos de compilación para macOS (Adam Robinson).

Otros

Múltiples erratas en la documentación corregidas (Yuri Chornoivan).

Seguridad

Vea también guestfs-security(1).

CVE-2018-11806

El slirp de Qemu (red en espacio de usuario) tenía varios desbordamientos de búfer que podían ser provocados desde el invitado o desde el lado de la red.

API

Nuevas APIs

"f2fs_expand"
Expandir un sistema de archivos f2fs (Pino Toscano).
"inspect_get_osinfo"
Obtener el ID corto de libosinfo para el invitado inspeccionado (Pino Toscano).
"lvm_scan"
Esto reescanea todos los PVs, VGs y LVs, activándolos opcionalmente.

Otros cambios de API

"part_get_mbr_part_type" fue reimplementado en OCaml (Nikolay Ivanets).

"list_filesystems" ahora filtra las particiones extendidas MBR (Nikolay Ivanets).

"vgscan" ha quedado obsoleto. Utilice la nueva API "lvm_scan" en su lugar.

Cambios de compilación

La biblioteca JSON cambió de yajl a Jansson ≥ 2.7 (Pino Toscano).

Soporte para The Sleuth Kit 4.5 (Pino Toscano).

Múltiples mejoras en el script "./configure" (Lin Ma).

Más arreglos para compilaciones fuera del árbol (Hilko Bengen).

Algo de trabajo sobre compilaciones reproducibles (Bernhard M. Wiedemann).

Internos

lvmetad ahora se usa incondicionalmente, y se inicia mucho antes en el proceso de arranque del appliance. Esto corrige el soporte para ciertos tipos de PV.

En Debian, dash se instala dentro del appliance y en virt-rescue (Pino Toscano).

La cantidad de RAM asignada al appliance se ha aumentado de 500M a 768M (en x86_64, otras arquitecturas tienen límites diferentes). Esto permite el uso de hasta 255 discos al usar kernels Linux recientes.

Virt-v2v ahora modela el tipo de máquina de origen (p. ej. i440FX, Q35 o virt).

Virt-p2v ahora genera automáticamente el código de configuración, incluyendo el código para analizar la línea de comandos del kernel.

Utilizar "LT_INIT" en lugar de "AC_PROG_LIBTOOL".

El código "JSON" de OCaml para analizar y serializar se ha unificado en un único tipo de dato abstracto.

La mayoría de las herramientas OCaml se compilan ahora usando el runtime PIC. Esto tiene una penalización de rendimiento en i686, pero es relativamente gratuito en otras arquitecturas y tiene beneficios de seguridad.

El backend directo ahora consulta al binario de qemu sobre la disponibilidad de KVM, en lugar de usar una heurística basada en /dev/kvm (Andrea Bolognani).

Nuestras "ingeniosas" macros de escritor de libxml2 se usan ahora de manera consistente en todas las partes de la base de código.

Qemu eliminó -nodefconfig sin avisarnos. La opción equivalente -no-user-config se usa ahora en su lugar. Qemu también movió la opción "serial" de -drive a -device, de nuevo sin ningún aviso, y esto también está corregido.
