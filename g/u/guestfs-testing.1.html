guestfs-testing(1) Soporte de virtualización guestfs-testing(1)

NOMBRE

guestfs-testing - pruebas manuales de libguestfs, ¡puedes ayudar!

DESCRIPCIÓN

Esta página contiene pruebas manuales que puedes probar en libguestfs. Cada persona tiene una combinación ligeramente diferente de plataforma, hardware y huéspedes, por lo que esta prueba es muy valiosa. ¡Gracias por ayudar!

Las pruebas marcadas con un * (asterisco) pueden destruir datos si no tienes cuidado. Las demás son seguras y no modificarán nada.

Estas pruebas requieren libguestfs ≥ 1.22.

Puedes informar de errores que encuentres a través de este enlace:

https://bugzilla.redhat.com/enter_bug.cgi?component=libguestfs&product=Virtualization+Tools

o publicar en la lista de correo (el registro no es no necesario, pero si no estás registrado, tendrás que esperar a que un moderador apruebe manualmente tu mensaje):

https://lists.libguestfs.org

PRUEBAS

Ejecuta libguestfs-test-tool

Ejecuta:

libguestfs-test-tool

Este comando realiza una prueba muy simple y no destructiva para comprobar que libguestfs funciona correctamente. No necesitas ejecutarlo como root.

Si no no imprime "===== TEST FINISHED OK =====", repórtalo como un error. Es muy importante que incluyas la salida completa y sin editar de "libguestfs-test-tool" en tu informe de error. Consulta la sección "ERRORES" al final de esta página.

Comprueba que se está usando la aceleración KVM.

Si tu host tiene aceleración de virtualización por hardware, entonces con una caché caliente libguestfs debería poder iniciarse en unos segundos. Ejecuta el siguiente comando varias veces:

time guestfish -a /dev/null run

Después de algunas ejecuciones, el tiempo debería estabilizarse en unos segundos (menos de 3 segundos en hardware rápido de 64 bits).

Si el comando anterior no funciona en absoluto, usa libguestfs-test-tool(1).

Comprueba qué versión de libguestfs, qemu, libvirt, etc. se está utilizando.

Mira la salida de "libguestfs-test-tool" y comprueba:

  • ¿Qué versión de libguestfs se está utilizando? Cerca del principio de la salida verás una línea como: 
    library version: 1.22.0fedora=19,release=1.fc19,libvirt
  • ¿Se está utilizando libvirt? Puedes saber la diferencia buscando el backend: 
    guestfs_get_backend: direct

    o:

    guestfs_get_backend: libvirt
  • ¿Qué versión de qemu se está utilizando? Puede que se imprima: 
    libguestfs: qemu version 1.5
  • ¿Qué kernel se está utilizando? supermin(1) intentará seleccionar el kernel más reciente instalado en tu máquina. Puedes ver la versión en la salida del appliance, por ejemplo: 
    [    0.000000] Linux version 3.9.2-200.fc18.x86_64 [...]

Intenta abrir una imagen de huésped local con guestfish.

Puedes usar cualquier imagen de disco de huésped para esta prueba. Asegúrate de usar el indicador "--ro" para que guestfish(1) abra la imagen de disco en modo de solo lectura.

guestfish --ro -a /path/to/disk.img -i

Si el comando es exitoso, debería imprimir el nombre del sistema operativo del huésped y ponerte en el prompt de guestfish "><fs>" . Puedes usar comandos de guestfish como "ll /" para mirar dentro de la imagen de disco. Para salir, escribe "exit".

Si obtienes un error, intenta habilitar la depuración (añade "-v" a la línea de comandos). También asegúrate de que libguestfs-test-tool(1) tiene éxito.

Intenta abrir una imagen de huésped remota con guestfish.

También puede que tengas que deshabilitar libvirt estableciendo esto:

export LIBGUESTFS_BACKEND=direct

Si tienes una imagen de disco disponible a través de HTTP/FTP, intenta abrirla.

guestfish --ro -i --format=raw -a http://www.example.com/disk.img

Para SSH necesitarás asegurarte de que ssh-agent esté configurado para no necesitar una contraseña para iniciar sesión en la máquina remota. Luego un comando similar a este debería funcionar:

guestfish --ro -i --format=raw \
  -a ssh://remote.example.com/path/to/disk.img

Si obtienes un error, intenta habilitar la depuración (añade "-v" a la línea de comandos). También asegúrate de que libguestfs-test-tool(1) tiene éxito.

Ejecuta virt-alignment-scan en todos tus huéspedes.

Ejecuta virt-alignment-scan(1) en huéspedes o imágenes de disco:

virt-alignment-scan -a /path/to/disk.img

o:

virt-alignment-scan -d Guest

¿El informe de alineación coincide con cómo están alineadas las particiones del huésped?

Ejecuta virt-cat en algunos archivos de los huéspedes.

virt-cat(1) puede mostrar archivos de los huéspedes. Para un huésped Linux, prueba:

virt-cat LinuxGuest /etc/passwd

Una característica reciente es el soporte para rutas de Windows, por ejemplo:

virt-cat WindowsGuest 'c:\windows\win.ini'

Una prueba aún mejor es si tienes un huésped Windows con múltiples unidades. ¿Funcionan correctamente las rutas como "D:", "E:" etc.?

* Copia algunos archivos a un huésped apagado .

virt-copy-in(1) puede copiar recursivamente archivos y directorios a un huésped o imagen de disco.

virt-copy-in -d Guest /etc /tmp

Esto debería copiar el directorio local /etc a /tmp/etc en el huésped (recursivamente). Si arrancas el huésped, ¿puedes ver todos los archivos y directorios copiados?

Apaga el huésped e intenta copiar múltiples archivos y directorios:

virt-copy-in -d Guest /home /etc/issue /tmp

Copia algunos archivos de un huésped.

virt-copy-out(1) puede copiar recursivamente archivos y directorios de un huésped o imagen de disco.

virt-copy-out -d Guest /home .

Ten en cuenta que el espacio final y el punto en el comando no son un error tipográfico.

Esto debería copiar /home del huésped al directorio actual.

Ejecuta virt-df.

virt-df(1) lista el espacio en disco. Ejecuta:

virt-df

Puedes intentar comparar esto con los resultados de df(1)] dentro del huésped, pero hay algunas advertencias:

  • El huésped debe estar inactivo.
  • Los discos del huésped deben estar sincronizados usando sync(1).
  • Cualquier acción como arrancar el huésped escribirá archivos de registro, lo que hará que los números cambien.

No garantizamos que los números sean idénticos incluso bajo estas circunstancias. Deberían ser similares. Indicaría un error si vieras números muy diferentes.

Intenta importar la salida CSV de virt-df en una hoja de cálculo o base de datos.

Ejecuta:

virt-df --csv > /tmp/report.csv

Ahora intenta cargar esto en tu hoja de cálculo o base de datos favorita. ¿Se reproducen fielmente los resultados en la hoja de cálculo/base de datos?

http://www.postgresql.org/docs/8.1/static/sql-copy.html http://dev.mysql.com/doc/refman/5.1/en/load-data.html

* Editar un archivo en un apagado huésped.

virt-edit(1) puede editar archivos en huéspedes. Pruebe este comando en un huésped RHEL o Fedora:

virt-edit LinuxGuest /etc/sysconfig/network

En otros huéspedes Linux, pruebe a editar otros archivos como:

virt-edit LinuxGuest /etc/motd

¿Se ven los cambios dentro del huésped cuando se arranca?

Mostrar los sistemas de archivos / particiones / LVs en un huésped.

virt-filesystems(1) se puede utilizar para mostrar sistemas de archivos en un huésped. Pruebe este comando en cualquier imagen de disco o huésped:

virt-filesystems -a /ruta/a/disk.img --all --long -h

o:

virt-filesystems -d Guest --all --long -h

¿Coinciden los resultados con lo que se ve en el huésped?

Ejecute virt-inspector en todos sus huéspedes.

Utilice virt-inspector(1) para obtener un informe de todos sus huéspedes o imágenes de disco:

virt-inspector -a /ruta/a/disk.img | less

o:

virt-inspector -d Guest | less

¿Coinciden los resultados con lo que realmente hay en el huésped?

Si tiene un huésped inusual (una distribución Linux poco común, una versión muy nueva de Windows), ¿reconoce virt-inspector el huésped? Si no, entonces es probablemente un error.

Pruebe las características de auditoría de virt-ls en todos sus huéspedes.

Liste todos los programas setuid o setgid en una máquina virtual Linux:

virt-ls -lR -d Guest / | grep '^- [42]'

Liste todos los directorios con escritura pública en una máquina virtual Linux:

virt-ls -lR -d Guest / | grep '^d ...7'

Liste todos los sockets de dominio Unix en una máquina virtual Linux:

virt-ls -lR -d Guest / | grep '^s'

Liste todos los archivos regulares con nombres de archivo que terminan en ‘.png’:

virt-ls -lR -d Guest / | grep -i '^-.*\.png$'

Muestre archivos mayores de 10MB en los directorios de inicio:

virt-ls -lR -d Guest /home | awk '$3 > 10*1024*1024'

Encuentre todo lo modificado en los últimos 7 días:

virt-ls -lR -d Guest --time-days / | awk '$6 <= 7'

Encuentre archivos regulares modificados en las últimas 24 horas:

virt-ls -lR -d Guest --time-days / | grep '^-' | awk '$6 < 1'

¿Coinciden los resultados con lo que hay en el huésped?

Cree una imagen de disco a partir de un archivo tarball.

Utilice virt-make-fs(1) para crear una imagen de disco a partir de cualquier tarball que tenga a mano:

virt-make-fs --partition=mbr --type=vfat /cualquier/tarball.tar.gz output.img

Añada ‘output.img’ como un disco sin procesar a un huésped existente. Compruebe que el huésped puede ver los archivos. Esta prueba es particularmente útil si la realiza con un huésped Windows.

Pruebe otros esquemas de particionado, p. ej. --partition=gpt.

Pruebe otros formatos de sistema de archivos, p. ej. --type=ntfs, --type=ext2.

* Ejecute virt-rescue en una apagada imagen de disco o huésped.

Utilice virt-rescue(1) para examinar, rescatar o reparar un huésped apagado o una imagen de disco:

virt-rescue -a /ruta/a/disk.img

o:

virt-rescue -d Guest

¿Puede usar comandos de shell ordinarios para examinar el huésped?

* Redimensione sus huéspedes.

Utilice virt-resize(1) para dar a un huésped algo más de espacio en disco. Por ejemplo, si tiene una imagen de disco que es menor de 30G, aumente a 30G haciendo:

truncate -s 30G newdisk.img
virt-filesystems -a /ruta/a/olddisk.img --all --long -h
virt-resize /ruta/a/olddisk.img newdisk.img --expand /dev/sda1
qemu-kvm -m 1024 -hda newdisk.img

¿Arranca todavía el huésped? Pruebe a expandir otras particiones.

* Reduzca el tamaño disperso de un disco de huésped.

Utilizando virt-sparsify(1), haga que una imagen de disco sea más dispersa:

virt-sparsify /ruta/a/olddisk.img newdisk.img

¿Sigue siendo newdisk.img arrancable después de reducir el tamaño disperso? ¿Es la imagen de disco resultante más pequeña (utilice "du" para comprobarlo)?

Construya y arranque un huésped

Utilizando virt-builder(1), elija un huésped de la lista:

virt-builder -l

constrúyalo:

virt-builder -o disk.img [versión-del-sistema-operativo-de-la-lista-superior]

y arránquelo:

qemu-kvm -cpu host -m 2048 -drive file=disk.img,format=raw

¿Arranca?

* "Sysprep" a un huésped Linux apagado.

Nota que esto realmente arruinará un huésped existente, así que es mejor clonar el huésped antes de intentarlo.

virt-sysprep --hostname newhost.example.com -a /ruta/a/disk.img

¿Fue exitoso el sysprep? Después de arrancar, ¿qué cambios se hicieron y fueron exitosos?

Vuelque el Registro de Windows de sus huéspedes Windows.

Utilice virt-win-reg(1) para volcar el Registro de Windows de cualquier huésped Windows que tenga.

virt-win-reg --unsafe-printable-strings WindowsGuest 'HKLM\Software' |
  less
virt-win-reg --unsafe-printable-strings WindowsGuest 'HKLM\System' |
  less

¿Coincide la salida con la de ejecutar "regedit" dentro del huésped?

Una característica reciente es la capacidad de volcar registros de usuario, así que pruebe esto, reemplazando nombredeusuario con el nombre de un usuario local en el huésped:

virt-win-reg --unsafe-printable-strings WindowsGuest 'HKEY_USERS\nombredeusuario' |
  less
