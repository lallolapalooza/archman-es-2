NOMBRE

gupnp-binding-tool-1.6 - crea wrappers de conveniencia en C para servicios UPnP

SINOPSIS

gupnp-binding-tool-1.6 [--prefijo {PREFIJO}] [--modo {cliente|servidor}] {archivo SCPD}

DESCRIPCIÓN

gupnp-binding-tool-1.6 toma un archivo SCPD y genera funciones C de conveniencia que llaman a las funciones GUPnP reales. Los bindings del lado del cliente pueden verse como una versión específica del servicio de la API GUPnPServiceProxy y los bindings del lado del servidor son los mismos para GUPnPService.

Estas funciones generadas son menos verbosas y también más seguras, ya que los parámetros de las llamadas a funciones están correctamente tipados. Los nombres de acciones, variables y consultas son más fáciles de obtener correctamente con bindings (o al menos los errores serán de tiempo de compilación en lugar de tiempo de ejecución), y también están disponibles en el autocompletado del editor.

BINDINGS DEL LADO DEL CLIENTE

Como ejemplo, esta acción:

<action>
  <name>DeletePortMapping</name>
  <argumentList>
    <argument>
      <name>NewRemoteHost</name>
      <direction>in</direction>
      <relatedStateVariable>RemoteHost</relatedStateVariable>
    </argument>
    <argument>
      <name>NewExternalPort</name>
      <direction>in</direction>
      <relatedStateVariable>ExternalPort</relatedStateVariable>
    </argument>
    <argument>
      <name>NewProtocol</name>
      <direction>in</direction>
      <relatedStateVariable>PortMappingProtocol</relatedStateVariable>
    </argument>
  </argumentList>
</action>

Generará la siguiente función síncrona del lado del cliente (punto de control):

static inline gboolean
igd_delete_port_mapping (GUPnPServiceProxy *proxy,
                         const gchar *in_new_remote_host,
                         const guint in_new_external_port,
                         const gchar *in_new_protocol,
                         GError **error);

Como se puede ver, los argumentos tienen los tipos correctos y están prefijados con la dirección del argumento.

gupnp-binding-tool-1.6 genera wrappers síncronos y asíncronos. El ejemplo igd_delete_port_mapping anterior es la forma síncrona, la forma asíncrona es la siguiente:

typedef void (*igd_delete_port_mapping_reply) (GUPnPServiceProxy *proxy,
                                               GError *error,
                                               gpointer userdata);
static inline GUPnPServiceProxyAction *
igd_delete_port_mapping_async (GUPnPServiceProxy *proxy,
                               const gchar *in_new_remote_host,
                               const guint in_new_external_port,
                               const gchar *in_new_protocol,
                               igd_delete_port_mapping_reply callback,
                               gpointer userdata);

La forma asíncrona (implementada usando gupnp_service_proxy_begin_action() y gupnp_service_proxy_end_action()) se devolverá sin bloquear e invocará posteriormente el callback desde el bucle principal cuando se reciba la respuesta.

La herramienta también crea bindings para notificaciones de variables de estado. Esta definición de variable de estado:

<stateVariable sendEvents="yes">
  <name>ExternalIPAddress</name>
  <dataType>string</dataType>
</stateVariable>

Creará este binding de cliente que se puede usar para obtener notificaciones sobre cambios en "ExternalIPAddress":

typedef void
(*igd_external_ip_address_changed_callback) (GUPnPServiceProxy *proxy,
                                             const gchar *external_ip_address,
                                             gpointer userdata);
static inline gboolean
igd_external_ip_address_add_notify (GUPnPServiceProxy *proxy,
                                    igd_external_ip_address_changed_callback callback,
                                    gpointer userdata);

Todos los ejemplos fueron producidos con gupnp-binding-tool-1.6 --prefijo igd --modo cliente WANIPConnection.xml.

BINDINGS DEL LADO DEL SERVIDOR

Los bindings de servidor correspondientes para la misma acción UPnP (DeletePortMapping) se ven así:

void
igd_delete_port_mapping_action_get (GUPnPServiceAction *action,
                                    gchar **in_new_remote_host,
                                    guint *in_new_external_port,
                                    gchar **in_new_protocol);
gulong
igd_delete_port_mapping_action_connect (GUPnPService *service,
                                        GCallback callback,
                                        gpointer userdata);

La función *_action_connect() generada se puede usar para conectar el manejador de acciones. Las funciones *_action_get() y *_action_set() se pueden usar dentro del manejador de acciones para obtener/establecer variables de acción. Si las variables notificadas se modifican, se debe usar *_variable_notify() para enviar las notificaciones (ver abajo).

typedef gchar *(*igd_external_ip_address_query_callback) (GUPnPService *service,
                                                          gpointer userdata);
gulong
igd_external_ip_address_query_connect (GUPnPService *service,
                                       igd_external_ip_address_query_callback callback,
                                       gpointer userdata);
void
igd_external_ip_address_variable_notify (GUPnPService *service,
                                         const gchar *external_ip_address);

La función *_query_connect() se puede usar para conectar el manejador de consultas específico del servicio. El valor de retorno del manejador es el valor de la variable de estado devuelto.

Todos los ejemplos fueron producidos con gupnp-binding-tool-1.6 --prefijo igd --modo servidor WANIPConnection.xml.
