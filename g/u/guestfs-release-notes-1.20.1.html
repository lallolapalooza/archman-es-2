guestfs-release-notes - Notas de lanzamiento de libguestfs

NOTAS DE LANZAMIENTO PARA LIBGUESTFS 1.20

Estas notas de lanzamiento solo cubren las diferencias de la división anterior de ramas estables/de desarrollo (1.18.0). Para obtener registros de cambios detallados, consulte el repositorio de git o el archivo ChangeLog distribuido en el tarball.

Nuevas características

libvirt y sVirt (confinamiento SELinux)

Puede usar opcionalmente libvirt para iniciar y administrar la aplicación de backend:

  • estableciendo "LIBGUESTFS_ATTACH_METHOD=libvirt[:URI]"
  • usando "./configure --with-default-attach-method=libvirt[:URI]"
  • o llamando al método de API "guestfs_set_attach_method"

SVirt (confinamiento SELinux) se utiliza para asegurar la aplicación de libguestfs, si se selecciona el backend de libvirt.

virtio-scsi, mayor número de discos, hotplugging

Ahora se utiliza virtio-scsi por defecto, si está disponible. Esto aumenta enormemente el número de discos que se pueden agregar a un solo manejador de libguestfs (hasta 255).

Ahora puede conectar/desconectar discos en caliente (agregar y eliminar discos después del inicio).

Libguestfs ahora puede manejar más de 25 discos, en todas las API, herramientas y pruebas.

Puede etiquetar discos al agregarlos, y luego referirse a ellos por etiqueta (/dev/disk/guestfs/ETIQUETA) en lugar de tener que usar nombres de dispositivo (/dev/sda).

nuevas características de la biblioteca

Ahora se pueden leer y escribir Listas de Control de Acceso (ACL) POSIX y capacidades de sistemas de archivos Linux a través de la API.

Ahora se admiten los discos dinámicos de Windows. La metadata solo se puede leer (los volúmenes no se pueden modificar ni crear). Sin embargo, los datos/sistemas de archivos en los volúmenes mismos se pueden montar, leer y escribir (Matthew Booth).

Hivex (edición del Registro de Windows) ahora es compatible directamente a través de la API, lo que hace que la lectura o edición del Registro de Windows sea mucho más eficiente.

Varias API de libguestfs se reimplementaron para que ya no tengan límites de salida. Las API reimplementadas son: "guestfs_cat", "guestfs_find", "guestfs_read_file", "guestfs_read_lines", "guestfs_write", "guestfs_write_append", "guestfs_lstatlist", "guestfs_lxattrlist", "guestfs_readlinklist", "guestfs_ls".

herramientas virt

"guestfish touch 'win:c:\new_file'" ahora funciona como se esperaba.

"guestfish" tiene una nueva opción --network, que habilita la red de usuario en libguestfs.

Puede establecer "GUESTFISH_PS1" para usar prompts elegantes en "guestfish".

"rsync", "ssh", "less" y "lrzip" ahora están disponibles en virt-rescue. Además, "rsync" se puede usar a través de la API para realizar copias incrementales.

"virt-sparsify" utiliza qcow2 v3 para una mayor eficiencia.

Mejoras en "virt-sysprep":

  • generar nuevos UUID para PV y VG
  • eliminar el ID de la máquina local (Wanlong Gao)
  • eliminar datos de ABRT (Wanlong Gao)
  • eliminar claves y archivos de registro de puppet (Wanlong Gao)
  • eliminar archivos de contabilidad de procesos (Wanlong Gao)
  • nuevo parámetro --firstboot que permite scripts de primer arranque para personalizar invitados
  • eliminar el campo HOSTNAME de los archivos "ifcfg-eth*" (Wanlong Gao)
  • mejoras diversas para SuSE (Olaf Hering)
  • eliminar la caché de páginas de manual (Wanlong Gao)
  • eliminar datos de fallos generados por kexec-tools (Wanlong Gao)

"virt-make-fs" ahora puede crear discos flexibles virtuales (VFD).

"guestmount" tiene una opción --pid-file, que se puede usar para evitar una condición de carrera entre el desmontaje del sistema de archivos y el uso de la imagen de disco subyacente.

enlaces de idiomas

Se agregaron enlaces de Lua completos en esta versión (gracias a Jerome Vuarand por muchas sugerencias).

En Ruby, el hash de argumentos opcionales es opcional.

En Python, los argumentos opcionales ahora no usan valores "centinela" especiales, por lo que se puede pasar cualquier entero como argumento opcional.

Los enlaces de Erlang ahora vienen con ejemplos y pruebas.

Los enlaces de Erlang ahora manejan correctamente los parámetros de enteros de 64 bits.

Las 'bindtests' automatizadas ahora prueban la limpieza de 64 bits en el paso de parámetros. Como resultado, se encontraron y corrigieron varios errores en los enlaces.

Un mejor manejo de funciones bloqueantes y no bloqueantes debería hacer que las llamadas a libguestfs sean más eficientes.

inspección

Ahora se admiten invitados de Windows con Registros de tamaño ilimitado. Al agregar la API de hivex a la API de libguestfs, es mucho más eficiente y fácil inspeccionar y modificar el Registro de Windows en los invitados.

Mejor soporte para invitados SuSE (Olaf Hering).

Devolver la arquitectura de las aplicaciones instaladas (John Eckersberg).

Ahora se admite Windows 8.

Ahora se admite Fedora 18.

La inspección de ISO/CD/DVD ahora puede usar la base de datos libosinfo.

puertos

Libguestfs sin la aplicación se puede compilar en Mac OS X (Masami HIRATA).

Ahora se admite explícitamente RHEL 5 a través de la rama 'oldlinux' en el git principal.

Ahora se admite PowerPC de 64 bits. Además, libguestfs se ha examinado en busca de errores de endianness y se han corregido.

daemon

Se incluye una página de manual para el daemon (guestfsd(8)).

Seguridad

archivo de historial de guestfish

El archivo de historial $HOME/.guestfish ahora se crea con permisos 0600 (en lugar de 0644 antes) por lo que ya no es legible para todos.

CVE-2012-2690

Versiones antiguas tanto de "virt-edit" como del comando "edit" de "guestfish" creaban un nuevo archivo que contenía los cambios pero no establecían los permisos, etc. del nuevo archivo para que coincidieran con el antiguo. El resultado fue que si editaba un archivo sensible a la seguridad como /etc/shadow, este quedaba legible para todos después de la edición.

Este problema se asignó a CVE-2012-2690 y se corrigió en libguestfs ≥ 1.16.

Para más información, vea https://bugzilla.redhat.com/show_bug.cgi?id=788642

Internals

Se requiere qemu ≥ 1.1 ( ≥ 1.2 preferido).

Se requiere febootstrap ≥ 3.20.

libvirt es opcional, pero si quieres usar el nuevo backend libvirt para lanzar la appliance, se requeriría libvirt ≥ 0.10.2.

Se ha ejecutado Coverity en la base de código completa, y se han corregido muchos problemas (gracias a Ondrej Vasik, Kamil Dudka).

Las funciones que previamente no tenían argumentos opcionales ahora pueden ser convertidas a funciones con argumentos opcionales, haciendo la API más flexible. Se preserva la compatibilidad binaria y de código fuente para los usuarios de la API.

La forma en que las APIs y estructuras de libguestfs se representan en el generador ha cambiado para usar una estructura OCaml en lugar de una tupla. Esto hace que las descripciones del generador sean más flexibles y fáciles de entender. Para detalles, ver los commits 39d1a7db y eb185eef.

Separación del código de la biblioteca en más archivos:

  • Los backends de lanzamiento ahora se encuentran en archivos separados, p. ej., src/launch-appliance.c, "src/launch-libvirt.c".
  • El código de acción generado ahora se divide en varios archivos src/action*.c, para una compilación más rápida.
  • El gran archivo src/guestfs.c ahora está dividido en unidades lógicas más pequeñas.

POD (documentación) ahora se genera usando un programa Perl reescrito en lugar de pod2* + scripts de shell.

Las páginas man ahora contienen fechas estables (Hilko Bengen).

Las pruebas omitidas ahora salen con el código 77, por lo que aparecen como "SKIP:" en la salida de "make check".

La prueba paralela mount-local ha sido reescrita en C (RHBZ#838081).

Ahora se soporta Ruby 1.8.5 (aunque se prefiere Ruby ≥ 1.9).

Los bindings de Perl pueden deshabilitarse mediante "./configure --disable-perl" (Wulf C. Krueger). Nota: Perl todavía es necesario para compilar libguestfs.

Los bindings de Java ahora se habilitan/deshabilitan usando "./configure --with-java" o "./configure --without-java" (Wulf C. Krueger).

Nuevas opciones de configuración "./configure --enable-code-profiling" y "./configure --enable-code-coverage".

Múltiples correcciones en el uso de enteros de 64 bits en los bindings de lenguaje.

El backend de la appliance ahora usa sgabios en lugar de vgabios (Dan Berrange).

El script "./run" ahora establece suficientes variables de entorno para que puedas ejecutar programas OCaml, Python, Ruby, Java, GJS, Erlang, Lua.

Flag "./run --test" para ejecutar pruebas con salida mínima. También imprime el tiempo empleado en ejecutar cada prueba.

El script "./run" ahora construye rutas acumulativamente, lo que significa que puedes usar "./run" dos veces, o usar juntos los scripts "./run" de libguestfs y libvirt.

Puedes extraer una lista de comandos externos requeridos por el demonio, facilitando la compilación de la appliance en ciertas distribuciones (Olaf Hering).

El comando "virt-rescue" ahora se prueba durante "make check".

El generador ahora elimina archivos generados no utilizados. Esto ayuda al ir y venir con git rebase, git bisect, etc.

Las pruebas ahora se ejecutan en un directorio de nivel superior separado "tmp/" en el código fuente. Esto permite que el directorio sea etiquetado para SELinux (sVirt), y también hace que sea más fácil de limpiar.

"make syntax-check" ahora funciona en mayor medida, y muchos problemas en el código principal encontrados por syntax-check han sido corregidos (gracias Jim Meyering).

Se ha añadido el modo Emacs (-*- foo -*-) a los archivos generados.

La salida de la barra de progreso ahora se envía a /dev/tty para que no termine en la salida regular del programa. virt-resize y virt-sparsify ahora suprimen las barras de progreso si stdout no es una tty.

Ahora hay una opción "./configure --without-libvirt". Esto es útil para probar que el código todavía compila sin libvirt.

Ahora hay una mini-biblioteca interna para ejecutar comandos. Esto nos permite redirigir errores de comandos externos a eventos.

El código para manejar directorios temporales y la caché de la appliance fue completamente revisado.

El código para ignorar/deshabilitar temporalmente errores ahora se ve así:

guestfs_push_error_handler (g, NULL, NULL);
guestfs_mkdir (g, "/foo"); /* No nos importa si esto falla. */
guestfs_pop_error_handler (g);

El directorio "tests/extra" ha desaparecido. Las "pruebas extra" ahora se dividen en objetivos ejecutables por separado, como "make check-valgrind". Usa "make help" para obtener un resumen de los objetivos.

La opción "lpj" se pasa al kernel de la appliance cuando se usa TCG. Esto debería mejorar la estabilidad del reloj (gracias Marcelo Tosatti, Olaf Hering).
