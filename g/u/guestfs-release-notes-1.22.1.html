NOTAS DE LA VERSIÓN PARA LIBGUESTFS 1.

22

Estas notas de la versión solo cubren las diferencias con la división estable/desarrollo anterior (1.20.0). Para los registros de cambios detallados, consulte el repositorio git o el archivo ChangeLog distribuido en el

tarball.

Nuevas

características

P

Los cargadores de arranque SYSLINUX y EXTLINUX ahora se pueden instalar en imágenes de disco usando la

API.

La inspección ahora puede manejar sistemas de archivos como btrfs, donde los subvolúmenes se pueden montar por separado (Matthew Booth)

.

Los "métodos de adjuntar" ahora se conocen como "backends". Se mantiene la compatibilidad con el código

existente.

Los nombres de archivo pueden contener ':', siempre que se esté usando una versión más reciente de

QEMU.

Herramient

as

Virt-alignment-scan y virt-df escanean múltiples invitados en

paralelo.

Guestmount ahora pasa el errno de vuelta al espacio de usuario con precisión en casi todos los

casos.

Guestfish y otras herramientas ahora pueden usar una sintaxis similar a una URI para acceder a discos remotos, por

ejemplo: 
guestfish -a ssh://example.com/path/to/disk.
img

Guestfish y guestmount ahora le permiten especificar el tipo de sistema de archivos al montar, lo cual es más seguro (Dave Vasilevsky)

.

Guestfish ahora es el "guest filesystem shell" (shell del sistema de archivos del invitado)

.

Guestfish solo permite 1 "true" "t" "yes" "y" "on" 0 "false" "f" "no" "n" "off" para valores booleanos (sin distinguir mayúsculas de minúsculas), y da un error para todas las demás

cadenas.

Nueva herramienta "guestunmount" para desmontar sistemas de archivos FUSE de forma

segura.

La opción "guestmount --no-fork" evita que guestmount se convierta en un

demonio.

Virt-resize ahora usa copias dispersas de forma predeterminada, ahorrando un espacio considerable para invitados que están mayormente

vacíos.

La finalización de tabulación de Bash ha sido reescrita y ahora puede manejar la mayoría de las herramientas, y finalizar correctamente con tabulación las opciones "--long". Además, los scripts de finalización de bash se cargan bajo

demanda.

Enlaces de

lenguaje

La API de Java ahora soporta

eventos.

El objeto de Python ahora hereda de la clase base

"object".

Los métodos de Python que anteriormente devolvían listas de tuplas ahora pueden devolver un dict de Python. Por compatibilidad hacia atrás, tiene que habilitar esto usando la opción del constructor "guestfs.GuestFS (python_retu

rn_dict=True)".

Los enlaces de PHP ahora se prueban correctamente, y han tenido múltiples

correcciones.

La biblioteca de Perl "Sys::Guestfs::Lib", que llevaba mucho tiempo obsoleta, ha sido eliminada. https://www.redhat.com/archives/libguestfs/2013-April/msg00001.

html

Interno

s

La herramienta febootstrap ahora ha sido renombrada a "supermin". Libguestfs puede usar cualquiera, pero ahora prefiere "supermin". http://people.redhat.com/~rjones/supermin

/

Se requiere libxml2 para compilar

libguestfs.

Se requiere el programa hivexregedit (de hivex) para compilar desde

git.

Las funciones internas ya no se pueden usar a menos que el llamador defina "-DGUESTFS_PRIVATE=1"

.

Habilitar advertencias del compilador C en los enlaces de Python y

Ruby.

Fallar temprana y claramente si libvirt no soporta qemu/KVM (por ejemplo, si la conexión predeterminada de libvirt es a Xen)

.

La regla "make print-subdirs", útil para ejecutar pruebas

selectivamente.

Múltiples correcciones para permitir compilaciones separadas (sourcedir != builddir)

.

Múltiples correcciones a los enlaces de

Haskell.

Las APIs "ln" y "ln-f" ahora capturan "errno" correct

amente.

Las pruebas de enlaces de lenguaje usan (mayormente) un esquema de numeración estándar y tienen como objetivo probar el mismo rango de características en cada lenguaje. Además, el número de lanzamientos requeridos se ha reducido, por lo que estas pruebas deberían ejecutarse mucho más

rápido.

El código de la biblioteca usa internamente GCC "__attribute__((cleanup))" (si está disponible) para simplificar la asignación de

memoria.

Los archivos de cabecera internos han sido reorganizados. Vea los comentarios en src/guestfs-internal*.

h

El código interno compartido entre la biblioteca y ciertas herramientas ahora se encuentra en una biblioteca estática "libutils"

.

Casi todos los subdirectorios ahora pueden usar compilaciones en paralelo, aunque tenga en cuenta que los directorios de nivel superior todavía se compilan en

serie.

El uso de "PATH_MAX" y "NAME_MAX" ha sido eliminado del

código.

La API de Java ahora requiere JVM ≥ 1.

6.

Forzar el uso de "serial-tests" con automake ≥ 1.

12.

El uso de sockets en la capa de protocolo de la biblioteca está abstraído, permitiendo que se agreguen otras capas no-POSIX en el futuro (vea src/conn-socket.c)

.

Se usa "qemu-img info --output json" si está disponible, para un análisis más seguro de la salida de este

comando.

Las distribuciones ahora pueden usar "make INSTALLDIRS=vendor install" para colocar los enlaces de Ruby en el vendordir. Esto elimina un parche no upstream que tanto Fedora como Debian

llevaban.

Los archivos de registro de Valgrind ahora se escriben en tmp/valgrind-DATE-PID.

log

"make clean" limpia el directorio local "tmp/"

.

Las pruebas de la API de C han sido reescritas usando

un lenguaje de generación más flexible que perm
ite ejecutar código C arbitrario durante las pruebas.
