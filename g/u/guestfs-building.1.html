NOMBRE

guestfs-building - Cómo compilar libguestfs desde el código fuente

DESCRIPCIÓN

Esta página del manual describe cómo compilar libguestfs desde el código fuente.

Los pasos principales son:

  • Instalar los requisitos.
  • Compilar, ya sea desde el repositorio git o desde un tarball.
  • Ejecutar las pruebas.
  • Ejecutar las herramientas desde el directorio fuente, o instalar.

REQUISITOS

Atajo para usuarios de Fedora o Red Hat Enterprise Linux (RHEL)

En Fedora, usa dnf(8) para instalar todos los requisitos:

dnf builddep libguestfs
dnf install autoconf automake libtool gettext-devel

En sistemas que todavía usan yum(8), haz:

yum-builddep libguestfs
yum install autoconf automake libtool gettext-devel

Atajo para usuarios de Debian o Ubuntu

Usa APT para instalar todos los requisitos:

apt-get build-dep libguestfs
apt-get install autoconf automake libtool-bin gettext

Si ese comando no funciona, echa un vistazo al paquete fuente de Debian http://packages.debian.org/source/libguestfs, a la lista de "build-depends" y "build-depends-indep", e instala todo lo listado ahí.

appliance/packagelist.in
Instala tantos nombres de paquetes como sea posible que se encuentren en este archivo. (No es estrictamente necesario instalarlos todos).

Nota: Si compilas libguestfs y luego instalas paquetes de appliance, la compilación no los recogerá automáticamente, incluso si haces "make clean". Tienes que ejecutar este comando para limpiar el appliance supermin antiguo y forzar la preparación de uno nuevo:

make -C appliance clean-supermin-appliance

COMPILACIÓN DESDE GIT

Necesitará instalar dependencias adicionales "autoconf", "automake", "gettext", OCaml findlib y po4a al compilar desde git.

git clone https://github.com/libguestfs/libguestfs
cd libguestfs
git submodule update --init
autoreconf -i
./configure CFLAGS=-fPIC
make

COMPILACIÓN DESDE TARBALLS

Los tarballs se descargan desde http://download.libguestfs.org/. Los tarballs estables están firmados con la clave GnuPG para "rich@annexia.org", véase https://pgp.mit.edu/pks/lookup?op=vindex&search=0x91738F73E1B768A0. La huella digital es "F777 4FB1 AD07 4A7E 8C87 67EA 9173 8F73 E1B7 68A0".

Descargue y descomprima el tarball.

cd libguestfs-1.xx.yy
./configure
make

EJECUTAR LAS PRUEBAS

¡NO ejecute las pruebas como root! Libguestfs puede ser compilado y probado como no-root. Ejecutar las pruebas como root podría incluso ser peligroso, no lo haga.

Para una comprobación básica de que la compilación funcionó, haga:

make quickcheck

Para ejecutar las pruebas básicas, haga:

make check

Hay muchas más pruebas que puede ejecutar. Véase guestfs-hacking(1) para más detalles.

INSTALACIÓN

¡NO use "make install"! Terminará con versiones conflictivas de libguestfs instaladas, y esto causa constantes dolores de cabeza a los usuarios. Véase la siguiente sección para cómo usar el ./run script en su lugar.

Los empaquetadores de distribuciones pueden usar:

make INSTALLDIRS=vendor DESTDIR=[temp-build-dir] install

EL SCRIPT ./run

Puede ejecutar guestfish(1), guestmount(1) y las herramientas virt sin necesidad de instalarlas usando el ./run script en el directorio superior. Este script funciona estableciendo varias variables de entorno.

Por ejemplo:

./run guestfish [argumentos habituales de guestfish ...]
./run virt-inspector [argumentos habituales de virt-inspector ...]

El ./run script añade cada binario de libguestfs al $PATH, así que los ejemplos anteriores ejecutan guestfish y virt-inspector desde el directorio de compilación (no el guestfish instalado globalmente si existe).

Puede usar el script desde cualquier directorio. Si quisiera ejecutar su propio programa que usa libguestfs, entonces el siguiente comando también funcionará:

/ruta/a/libguestfs/run ./mi_programa [...]

También puede ejecutar los programas C bajo valgrind así:

./run valgrind [opciones de valgrind...] virt-cat [opciones de virt-cat...]

o bajo gdb:

./run gdb --args virt-cat [opciones de virt-cat...]

Esto también funciona con sudo (por ejemplo, si necesita acceso root para libvirt o para acceder a un dispositivo de bloque):

sudo ./run virt-cat -d LinuxGuest /etc/passwd

Para establecer variables de entorno, puede hacer:

LIBGUESTFS_HV=/mi/qemu ./run guestfish

o:

./run env LIBGUESTFS_HV=/mi/qemu guestfish

local* ARCHIVOS

Los archivos en el directorio de código fuente superior que comienzan con el prefijo local* son ignorados por git. Estos archivos pueden contener configuración local o scripts que necesita para compilar libguestfs.

Tengo un archivo llamado localconfigure que es un simple envoltorio alrededor de configure que contiene personalizaciones de configure locales que necesito. Se ve así:

. localenv
./configure.sh \
    -C \
    --enable-werror \
    "$@"

Así puedo usar esto para compilar libguestfs:

./localconfigure && make

Si hay un archivo en el directorio de compilación superior llamado localenv, entonces será cargado por "make". Este archivo puede contener cualquier variable de entorno local necesaria, por ejemplo, para omitir pruebas:

# Omitir esta prueba, está rota.
export SKIP_TEST_BTRFS_FSCK=1

Tenga en cuenta que localenv es incluido por el Makefile superior (así que es un fragmento de Makefile). Pero si también es cargado por su localconfigure script entonces es usado como un script de shell.

Deshabilita enlaces de lenguajes específicos, incluso si "./configure" encuentra que todas las bibliotecas necesarias están instaladas y podrían ser compiladas.

Tenga en cuenta que deshabilitar OCaml (enlaces) o Perl tendrá el efecto en cadena de deshabilitar partes de la suite de pruebas y algunas herramientas.

OCaml es requerido para compilar libguestfs y este requisito no puede ser eliminado. Usar --disable-ocaml solo deshabilita los enlaces.

--disable-fuse
Deshabilita el soporte FUSE en la API y la guestmount(1) herramienta.
--disable-static
No compilar una versión enlazada estáticamente de la biblioteca libguestfs.
--enable-install-daemon
Normalmente guestfsd(8) no es instalado por "make install", ya que eso no sería útil (en su lugar es "instalado" dentro del appliance supermin). Sin embargo, si los empaquetadores están compilando "libguestfs live" entonces deberían usar esta opción.
--enable-werror
Esto convierte las advertencias del compilador en errores (es decir, "-Werror"). Use esto para desarrollo, especialmente al enviar parches. Generalmente no debería usarse para compilaciones de producción o de distribución.
--with-default-backend=libvirt
Esto controla el método por defecto que libguestfs usa para ejecutar qemu (véase "BACKEND" en guestfs(3)). Si no se especifica, el backend predeterminado es "direct" , lo que significa que libguestfs ejecuta qemu directamente. Fedora y Red Hat Enterprise Linux (RHEL) ≥ 7 utilizan esta bandera para cambiar el backend predeterminado a "libvirt" , porque (especialmente en RHEL) la política no permite que ningún programa ejecute qemu excepto a través de libvirt. Tenga en cuenta que, a pesar de esta configuración, todos los backends están integrados en libguestfs, y puede anular el backend en tiempo de ejecución estableciendo la variable de entorno $LIBGUESTFS_BACKEND
