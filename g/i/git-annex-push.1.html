NOMBRE

git-annex-push - enviar contenido a remotos

SINOPSIS

git annex push [remoto ...]

DESCRIPCIÓN

Este comando envía contenido a remotos. Sube tanto el contenido del repositorio git como el contenido de los archivos anexados.

Puedes usar git push y git annex copy manualmente para hacer lo mismo que este comando, pero este comando maneja varios detalles, incluyendo asegurarse de que la rama git-annex se envíe al remoto.

Cuando se usa git-annex, a menudo los remotos no son repositorios "bare", porque es útil agregar remotos para máquinas cercanas a las que deseas acceder al mismo contenido anexado. Enviar a un remoto no "bare" normalmente no actualizará la rama actual del remoto con los cambios del repositorio local. (A menos que el remoto esté configurado con receive.denyCurrentBranch=updateInstead.)

Para facilitar el trabajo con remotos no "bare", este comando envía no solo master local a master remoto, sino también a synced/master remoto (y similar con otras ramas). Cuando git annex pull (o git annex sync) se ejecute más tarde en el remoto, fusionará las ramas synced/ que se le enviaron.

Algunos remotos especiales permiten exportar un árbol de archivos a ellos (exporttree=yes), y este comando se puede usar para enviar a esos remotos así como a remotos git normales. Consulte git-annex-export(1) para obtener detalles sobre cómo funcionan esos remotos especiales. Para que este comando exporte a un remoto especial, también debe estar configurado remote.<nombre>.annex-tracking-branch, y tener el mismo valor que la rama actualmente seleccionada.

Cuando se ha utilizado git-annex-adjust(1) para seleccionar una rama ajustada, este comando propagará los cambios que se han realizado de vuelta a la rama padre, sin propagar los ajustes.

Normalmente, esto intenta subir el contenido de cada archivo anexado que está en el árbol de trabajo, a cualquier remoto al que se esté enviando y que no tenga una copia. Para controlar qué archivos se suben a un remoto, configure el contenido preferido del remoto. Cuando un archivo no es el contenido preferido de un remoto, o del repositorio local, este comando intentará eliminar el contenido del archivo. Consulte git-annex-preferred-content(1).

OPCIONES

[remoto]
Por defecto, este comando envía a todos los remotos disponibles, excepto a aquellos que tienen remote.<nombre>.annex-push (o remote.<nombre>.annex-sync) establecido en falso o remote.<nombre>.annex-readonly establecido en verdadero.
Al especificar los nombres de los remotos (o grupos de remotos), puedes controlar a cuáles enviar.
--fast
Solo enviar a los remotos con el valor annex-cost más bajo configurado.
Cuando se proporciona una lista de remotos (o grupos de remotos), se elige entre ellos, de lo contrario, se elige entre todos los remotos.
--only-annex -a, --not-only-annex
Solo enviar la rama git-annex y el contenido anexado a los remotos, no otras ramas git.
La configuración annex.synconlyannex puede establecerse en verdadero para que este sea el comportamiento por defecto. Para anular una configuración así, use --not-only-annex.
Cuando esto se combina con --no-content, solo se enviará la rama git-annex.
--no-content, -g, --content
Use --no-content o -g para evitar subir (y eliminar) el contenido de los archivos anexados.
Si a menudo usa --no-content, puede establecer la configuración annex.synccontent en falso para evitar subir contenido por defecto. La opción --content anula esa configuración.
--content-of=ruta -C ruta
Solo subir (o eliminar) archivos anexados en la ruta dada.
Esta opción se puede repetir varias veces con diferentes rutas.
Tenga en cuenta que esta opción no evita exportar otros archivos a un remoto con "exporttree=yes".
--all -A
Normalmente, este comando opera sobre archivos anexados en la rama actual. Esta opción hace que opere sobre todas las versiones disponibles de todos los archivos anexados (cuando la configuración de contenido preferido lo permite).
Tenga en cuenta que la configuración de contenido preferido que usa include= o exclude= solo coincidirá con la versión de los archivos actualmente en el árbol de trabajo, pero no con versiones pasadas de los archivos.
--jobs=N -JN
Habilita el envío paralelo con hasta el número especificado de trabajos ejecutándose a la vez. Por ejemplo: -J10
Establecer esto en "cpus" ejecutará un trabajo por núcleo de CPU.
--cleanup
Elimina las ramas locales y remotas synced/, que fueron creadas y enviadas por git-annex push o git-annex sync. Esta opción evita toda otra actividad.
Esto puede ser útil cuando has enviado un cambio a remotos y ahora deseas restablecer tu rama master a antes de ese cambio. Así que ejecutas git reset y envías forzosamente la rama master a los remotos, solo para descubrir que el siguiente git annex merge o git annex pull trae de vuelta los cambios. ¿Por qué? Porque la rama synced/master sigue ahí y todavía tiene el cambio en ella. Limpiar las ramas synced/ evita ese problema.
También se pueden usar las git-annex-common-options(1).
