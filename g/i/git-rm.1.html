git-rm - Eliminar ar

chivos del árbol de
trabajo y del índice

SINOPSI

S 
git rm [-f | --force] [-n] [-r] [--cached] [--ignore-unmatch]
       [--quiet] [--pathspec-from-file=<file> [--pathspec-file-nul]]
       [--] [<pathspec>..
.
]

DESCRIPCIÓ

N

Elimina del índice los archivos que coincidan con pathspec, o del árbol de trabajo y del índice. git rm no eliminará un archivo solo de tu directorio de trabajo. (No existe una opción para eliminar un archivo solo del árbol de trabajo y mantenerlo en el índice; usa /bin/rm si quieres hacer eso.) Los archivos que se eliminan deben ser idénticos a la punta de la rama, y no se pueden preparar actualizaciones de su contenido en el índice, aunque ese comportamiento predeterminado se puede anular con la opción -f. Cuando se especifica --cached, el contenido preparado debe coincidir con la punta de la rama o con el archivo en disco, lo que permite eliminar el archivo solo del índice. Cuando se usan sparse-checkouts (ver git-sparse-checkout(1)), git rm solo eliminará rutas dentro de los patrones de

sparse-checkout
.

OPCIONE

S

<pathspec>..

.
Archivos a eliminar. Se puede dar un nombre de directorio inicial (por ejemplo, dir para eliminar dir/file1 y dir/file2) para eliminar todos los archivos en el directorio, y recursivamente todos los subdirectorios, pero esto requiere que se dé explícitamente la opción -r.

El comando elimina solo las rutas que Git

conoce.

La expansión de comodines de archivos coincide a través de los límites de los directorios. Así, dado dos directorios d y d2, hay una diferencia entre usar git rm 'd*' y git rm 'd/*', ya que la primera también eliminará todo el directorio d2

.

Para más detalles, ver la entrada <pathspec> en gitgloss

ary
(7).

-f, --forc

e
Anula la comprobación de
actualización.

-n, --dry-ru

n
No elimina realmente ningún archivo. En su lugar, solo muestra si existen en el índice y serían eliminados por el
comando.

-

r
Permite la eliminación recursiva cuando se da un nombre de directorio
inicial.

-

-
Esta opción se puede usar para separar las opciones de la línea de comandos de la lista de archivos (útil cuando los nombres de archivo podrían confundirse con opciones de la línea de comandos)
.

--cache

d
Usa esta opción para despreparar y eliminar rutas solo del índice. Los archivos del árbol de trabajo, estén modificados o no, se dejarán
intactos.

--ignore-unmatc

h
Sale con un estado cero incluso si ningún archivo
coincide.

--spars

e
Permite actualizar entradas del índice fuera del cono de sparse-checkout. Normalmente, git rm rechaza actualizar entradas del índice cuyas rutas no encajan dentro del cono de sparse-checkout. Ver git-sparse-checkout(1) para más
información.

-q, --quie

t
git rm normalmente emite una línea (en la forma de un comando rm) por cada archivo eliminado. Esta opción suprime esa
salida.

--pathspec-from-file=<file

>
El pathspec se pasa en <file> en lugar de en args. Si <file> es exactamente -, se usa la entrada estándar. Los elementos del pathspec están separados por LF o CR/LF. Los elementos del pathspec pueden estar entrecomillados como se explica para la variable de configuración core.quotePath (ver git-config(1)). Ver también --pathspec-file-nul y la global --literal-pathspecs
.

--pathspec-file-nu

l
Solo tiene sentido con --pathspec-from-file. Los elementos del pathspec están separados por el carácter NUL y todos los demás caracteres se toman litera
lmente (incluyendo salt
os de línea y comillas).

ELIMINACIÓN DE ARCHIVOS QUE HAN DESAPARECIDO DEL SISTEMA DE

ARCHIVOS

No hay una opción para git rm que elimine solo del índice las rutas que han desaparecido del sistema de archivos. Sin embargo, dependiendo del caso de uso, hay varias maneras de

hacerlo.

Usando “git commit

-a”

Si pretendes que tu próximo commit registre todas las modificaciones de los archivos rastreados en el árbol de trabajo y registre todas las eliminaciones de archivos que han sido eliminados del árbol de trabajo con rm (a diferencia de git rm), usa git commit -a, ya que automáticamente notará y registrará todas las eliminaciones. También puedes tener un efecto similar sin hacer commit usando git add -u

.

Usando “git add

-A”

Al aceptar una nueva entrega de código para una rama de proveedor, probablemente quieras registrar tanto la eliminación de rutas como la adición de nuevas rutas, así como las modificaciones de las rutas

existentes.

Típicamente primero eliminarías todos los archivos rastreados del árbol de trabajo usando este

comando: 
git ls-file
s -z | xar
gs -0 rm -f

y luego descomprimirías el nuevo código en el árbol de trabajo. Alternativamente, podrías rsync los cambios al árbol de

trabajo.

Después de eso, la forma más fácil de registrar todas las eliminaciones, adiciones y modificaciones en el árbol de trabajo

es: 
git
add
-A

Ver git-ad

d(
1).

Otras

formas

Si todo lo que realmente quieres hacer es eliminar del índice los archivos que ya no están presentes en el árbol de trabajo (quizás porque tu árbol de trabajo está sucio y no puedes usar git commit -a), usa el siguiente

comando: 
git diff --na
me-only --dif
f-filter=D -z
| xargs -0 gi
t rm --cached

SUBMÓDULO

S

Solo los submódulos que usan un gitfile (lo que significa que fueron clonados con una versión de Git 1.7.8 o más reciente) serán eliminados del árbol de trabajo, ya que su repositorio vive dentro del directorio .git del superproyecto. Si un submódulo (o uno de los anidados dentro de él) todavía usa un directorio .git, git rm mueve el directorio git del submódulo al directorio git del superproyecto para proteger el historial del submódulo. Si existe, la sección submodule.<name> en el archivo gitmodules(5) también será eliminada y ese archivo será preparado (a menos que se usen --cached o -n)

.

Un submódulo se considera actualizado cuando el HEAD es el mismo que el registrado en el índice, ningún archivo rastreado está modificado y no hay archivos no rastreados que no estén ignorados presentes en el árbol de trabajo del submódulo. Los archivos ignorados se consideran prescindibles y no impedirán que se elimine el árbol de trabajo de un

submódulo.

Si solo quieres eliminar la copia local de un submódulo de tu árbol de trabajo sin hacer commit de la eliminación, usa git-submodule(1) deinit en su lugar. Ver también gitsubmodules(7) para detalles so

bre la eliminació
n de submódulos.

EJEMPLO

S

git rm Documentation/\*.

txt
Elimina todos los archivos *.txt del índice que están bajo el directorio Documentation y cualquiera de sus subdirectorios.

Nota que el asterisco * está escapado del shell en este ejemplo; esto permite que Git, y no el shell, expanda los nombres de ruta de los archivos y subdirectorios bajo el directorio Document

ati
on/.

git rm -f git-*.

sh
Debido a que este ejemplo permite que el shell expanda el asterisco (es decir, estás listando los archivos explícitamente), no elimina subdir/gi
t-foo
.sh.

ERRORE

S

Cada vez que una actualización del superproyecto elimina un submódulo poblado (por ejemplo, al cambiar entre commits antes y después de la eliminación) se deja un submóduloe checkout permanecerá en la ubicación antigua. Eliminar el directorio antiguo solo es seguro cu

ando utiliza un gitfile, ya que de lo contrario el historial del submódulo también se eliminará.
Este paso quedará obsoleto cuando se haya implementado la actualización recursiva de submódulos.
