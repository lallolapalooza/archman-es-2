GIT-IMAP-SEND(1) Manual de Git GIT-IMAP-SEND(1)

NOMBRE

git-imap-send - Envía una colección de parches desde stdin a una carpeta IMAP

SINOPSIS

git imap-send [-v] [-q] [--[no-]curl] [(--folder|-f) <folder>]
git imap-send --list

DESCRIPCIÓN

Este comando sube un buzón generado con git format-patch a una carpeta de borradores de IMAP. Esto permite enviar parches como cualquier otro correo electrónico cuando se utilizan clientes de correo que no pueden leer archivos de buzón directamente. El comando también funciona con cualquier buzón general en el que los correos electrónicos tengan los campos From, Datey Subject en ese orden.

El uso típico es algo como:

$ git format-patch --signoff --stdout --attach origin | git imap-send

OPCIONES

-v, --verbose

Ser detallado.

-q, --quiet

Ser silencioso.

-f <folder>, --folder=<folder>

Especifica la carpeta en la que deben guardarse los correos electrónicos. Por ejemplo: --folder=[Gmail]/Drafts o -f INBOX/Drafts.

--curl

Usa libcurl para comunicarse con el servidor IMAP, a menos que se establezca un túnel hacia él. Se ignora si Git fue compilado sin la opción USE_CURL_FOR_IMAP_SEND.

--no-curl

Se comunica con el servidor IMAP usando las propias rutinas IMAP de git en lugar de usar libcurl. Se ignora si Git fue compilado con la opción NO_OPENSSL.

--list

Ejecuta el comando LIST de IMAP para mostrar una lista de todas las carpetas presentes.

CONFIGURACIÓN

Para usar la herramienta, imap.folder y ya sea imap.tunnel o imap.host deben establecerse con valores apropiados.

Todo lo que hay por encima de esta línea en esta sección no está incluido desde la git-config(1) documentación. El contenido que sigue es el mismo que el que se encuentra allí:

imap.folder

La carpeta en la que se deben depositar los correos, que típicamente es la carpeta de borradores. Por ejemplo: INBOX.Drafts, INBOX/Drafts oGmail]/Drafts. La carpeta IMAP con la que interactuar DEBE ser especificada; el valor de esta variable de configuración se usa como valor predeterminado de reserva cuando la opción --folder no se proporciona.

imap.tunnel

Comando utilizado para establecer un túnel al servidor IMAP a través del cual se canalizarán los comandos en lugar de usar una conexión de red directa al servidor. Es requerido cuando imap.host no está establecido.

imap.host

Una URL que identifica al servidor. Usa un prefijo imap:// para conexiones no seguras y un prefijo imaps:// para conexiones seguras. Se ignora cuando imap.tunnel está establecido, pero es requerido en caso contrario.

imap.user

El nombre de usuario a usar al iniciar sesión en el servidor.

imap.pass

La contraseña a usar al iniciar sesión en el servidor.

imap.port

Un número de puerto entero al cual conectarse en el servidor. El valor predeterminado es 143 para hosts imap:// y 993 para hosts imaps://. Se ignora cuando imap.tunnel está establecido.

imap.sslverify

Un booleano para habilitar/deshabilitar la verificación del certificado del servidor usado por la conexión SSL/TLS. El valor predeterminado es true. Se ignora cuando imap.tunnel está establecido.

imap.preformattedHTML

Un booleano para habilitar/deshabilitar el uso de codificación html al enviar un parche. Un parche codificado en html será delimitado con <pre> y tendrá un tipo de contenido de text/html. Irónicamente, habilitar esta opción causa que Thunderbird envíe el parche como un correo electrónico plain/text, format=fixed. El valor predeterminado es false.

imap.authMethod

Especifica el método de autenticación para autenticarse con el servidor IMAP. Si Git fue compilado con la opción NO_CURL, o si tu versión de curl es anterior a 7.34.0, o si estás ejecutando git-imap-send con la opción --no-curl , los únicos métodos soportados son PLAIN, CRAM-MD5, OAUTHBEARER y XOAUTH2. Si esto no está establecido, entonces git imap-send usa el comando IMAP básico de texto plano LOGIN .

OBTENIENDO UNA LISTA DE CARPETAS DISPONIBLES

Para enviar un correo electrónico a una carpeta específica, necesitas conocer el nombre correcto de la carpeta deseada en tu buzón. Los nombres como "Junk", "Trash", etc. mostrados por varios clientes de correo no necesariamente son los nombres reales de las carpetas almacenadas en el servidor de correo de tu proveedor de correo electrónico.

Para obtener el nombre correcto de la carpeta a usar con git imap-send, puedes ejecutar git imap-send --list. Esto mostrará una lista de nombres de carpetas válidos. Un ejemplo de tal salida cuando se ejecuta en una cuenta de Gmail es:

* LIST (\HasNoChildren) "/" "INBOX"
* LIST (\HasChildren \Noselect) "/" "[Gmail]"
* LIST (\All \HasNoChildren) "/" "[Gmail]/All Mail"
* LIST (\Drafts \HasNoChildren) "/" "[Gmail]/Drafts"
* LIST (\HasNoChildren \Important) "/" "[Gmail]/Important"
* LIST (\HasNoChildren \Sent) "/" "[Gmail]/Sent Mail"
* LIST (\HasNoChildren \Junk) "/" "[Gmail]/Spam"
* LIST (\Flagged \HasNoChildren) "/" "[Gmail]/Starred"
* LIST (\HasNoChildren \Trash) "/" "[Gmail]/Trash"

Aquí, puedes observar que el nombre correcto para la carpeta "Junk" es [Gmail]/Spam y para la carpeta "Trash" es [Gmail]/Trash. Una lógica similar puede usarse para determinar otras carpetas también.

EJEMPLOS

Usando el modo túnel:

[imap]
    folder = "INBOX.Drafts"
    tunnel = "ssh -q -C user@example.com /usr/bin/imapd ./Maildir 2> /dev/null"

Usando el modo directo:

[imap]
    folder = "INBOX.Drafts"
    host = imap://imap.example.com
    user = bob
    pass = p4ssw0rd

Usando el modo directo con SSL:

[imap]
    folder = "INBOX.Drafts"
    host = imaps://imap.example.com
    user = bob
    pass = p4ssw0rd
    port = 123
    ; sslVerify = false

Nota

Puede que quieras usar sslVerify=false mientras solucionas problemas, si sospechas que la razón por la que tienes problemas para conectarte es porque el certificado que usas en el servidor privado example.com que estás intentando configurar (o has configurado) puede no estar siendo verificado correctamente.

Usando la interfaz IMAP de Gmail:

[imap]
    folder = "[Gmail]/Drafts"
    host = imaps://imap.gmail.com
    user = user@gmail.com
    port = 993

Gmail no permite usar tu contraseña regular para git imap-send. Si tienes autenticación multifactor configurada en tu cuenta de Gmail, puedes generar una contraseña específica de la aplicación para usar con git imap-send. Visita https://security.google.com/settings/security/apppasswords para crearla. Alternativamente, usa autenticación OAuth2.0 como se describe a continuación.


Nota

Puede que necesites usar en su lugar: folder = "[Google Mail]/Drafts" si recibes un error de que "La carpeta no existe". También puedes ejecutar git imap-send --list para obtener una lista de carpetas disponibles.


Nota

Si tu cuenta de Gmail está configurada en otro idioma que no sea inglés, el nombre de la carpeta "Drafts" estará localizado.

Si quieres usar autenticación basada en OAuth2.0, puedes especificar el mecanismo OAUTHBEARER o XOAUTH2 en tu configuración. Es más seguro que usar contraseñas específicas de la aplicación, y tampoco impone la necesidad de tener autenticación multifactor. Tendrás que usar un token de acceso OAuth2.0 en lugar de tu contraseña al usar esta autenticación.

[imap]
    folder = "[Gmail]/Drafts"
    host = imaps://imap.gmail.com
    user = user@gmail.com
    port = 993
    authmethod = OAUTHBEARER

Usando Outlook19;s interfaz IMAP:

A diferencia de Gmail, Outlook solo admite autenticación basada en OAuth2.0. Además, solo admite XOAUTH2 como mecanismo.

[imap]
    folder = "Drafts"
    host = imaps://outlook.office365.com
    user = user@outlook.com
    port = 993
    authmethod = XOAUTH2

Una vez que los commits estén listos para enviarse, ejecute el siguiente comando:

$ git format-patch --cover-letter -M --stdout origin/master | git imap-send

Solo asegúrese de desactivar el ajuste de líneas en el cliente de correo (la interfaz web de Gmail ajustará las líneas de todos modos, por lo que debe usar un cliente IMAP real).

En caso de que esté utilizando autenticación OAuth2.0, es más fácil usar los auxiliares de credenciales para generar tokens. Los auxiliares de credenciales sugeridos en git-send-email(1) pueden usarse para git imap-send también.

PRECAUCIÓN

Sigue siendo su responsabilidad asegurarse de que el mensaje de correo electrónico enviado por su programa de correo cumpla con los estándares de su proyecto. A muchos proyectos no les gustan los parches adjuntos. Algunos agentes de correo transformarán los parches (por ejemplo, ajustarán las líneas, los enviarán como format=flowed) de maneras que los hacen fallar. Recibirá correos enojados burlándose de usted si no verifica esto.

Thunderbird en particular es conocido por ser problemático. Los usuarios de Thunderbird pueden visitar esta página web para más información: https://kb.mozillazine.org/Plain_text_e-mail_-_Thunderbird#Completely_plain_email
