NOMBRE

git-annex-expire - expira repositorios inactivos

SINOPSIS

git annex expire [repositorio:]tiempo ...

DESCRIPCIÓN

Este comando expira repositorios que no han realizado ninguna actividad dentro de un período de tiempo especificado. Un repositorio se expira marcándolo como muerto. También se realiza la desexpiración; si un repositorio muerto realizó alguna actividad recientemente, se marca nuevamente como semitrust.

Esto puede ser útil cuando no es posible hacer un seguimiento del estado de los repositorios manualmente. Por ejemplo, una red distribuida de repositorios donde nadie puede acceder directamente a todos los repositorios para verificar su estado.

El repositorio se puede especificar usando el nombre de un remoto, o la descripción o uuid del repositorio.

El tiempo tiene el formato "60d" o "1y". Un tiempo de "nunca" desactivará la expiración.

Si se especifica un tiempo sin un repositorio, se utiliza como el valor predeterminado para todos los repositorios. Tenga en cuenta que el repositorio actual nunca se expira.

OPCIONES

--no-act
Imprime lo que se haría, pero sin expirar ni desexpirar realmente ningún repositorio.
--activity=Nombre
Especifica la actividad que un repositorio debe haber realizado para evitar ser expirado. El valor predeterminado es cualquier actividad.
Actualmente, la única actividad que se puede realizar para evitar la expiración es --activity=Fsck, que corresponde a git annex fsck. Tenga en cuenta que hacer fsck a un remoto actualiza la expiración del repositorio remoto, no del repositorio local.
La primera versión de git-annex que registró actividad de fsck fue 5.20150405.
--json
Habilita la salida JSON. Esto está destinado a ser analizado por programas que usan git-annex. Cada línea de salida es un objeto JSON.
--json-error-messages
Los mensajes que normalmente se enviarían a la salida de error estándar se incluyen en el JSON en su lugar.
También se pueden usar las opciones comunes de git-annex(1).
