-I <rutas>, --include=<rutas

>
Especificar lfs.fetchinclude solo para esta invocación; consulte INCLUIR Y

-X <rutas>, --exclude=<rutas

Especificar lfs.fetchexclude solo para esta invocación; consulte INCLUIR Y

--recen

t
Descargar objetos referenciados por ramas y commits recientes además de los que se descargarían de otra manera. Consulte CAMBIOS
RECIENTES.

--al

l
Descargar todos los objetos referenciados por cualquier commit alcanzable desde las referencias proporcionadas como argumentos. Si no se proporcionan referencias, se obtienen todas las referencias. Esto es principalmente para fines de copia de seguridad y migración. No se puede combinar con --recent o --include/--exclude. Ignora cualquier ruta de inclusión y exclusión configurada globalmente para asegurar que todos los objetos sean
descargados.

--prune, -

p
Podar objetos antiguos y no referenciados después de la obtención, equivalente a ejecutar git lfs prune después. Consulte git-lfs-prune(1) para más
detalles.

--refetc

h
También obtener objetos que ya están presentes
localmente.

--dry-run, -

d

nada.

--json, -

j

INCLUIR Y

EXCLUIR

Puede configurar Git LFS para obtener solo objetos que satisfagan referencias en ciertas rutas del repositorio, y/o excluir ciertas rutas del repositorio, para reducir el tiempo que pasa descargando cosas que no

usa.

En su configuración de Git o en un archivo .lfsconfig, puede establecer una o ambas de lfs.fetchinclude y lfs.fetchexclude a listas de rutas separadas por comas. Si lfs.fetchinclude está definido, los objetos Git LFS se obtendrán solo si su ruta coincide con una en esa lista, y si lfs.fetchexclude está definido, los objetos Git LFS se obtendrán solo si su ruta no coincide con una en esa lista. Las rutas se coinciden usando coincidencia de comodines según gitignore(5)

.

Tenga en cuenta que el uso de las opciones de línea de comandos -I y -X anula las respectivas configuraciones. Establecer cualquiera de las opciones a una cadena vacía limpia el

valor.

REMOTO POR

DEFECTO

Sin argumentos, fetch descarga desde el remoto por defecto. El remoto por defecto es el mismo que para git fetch, es decir, basado en la rama remota que

está rastreando primero, o
origin de lo contrario.

REFERENCIAS POR

DEFECTO

Si no se dan referencias como argumentos, se usa la referencia actualmente v

erificada. Además, si está habilitado, las referencias y commits recientemente
cambiados también se incluyen. Consulte CAMBIOS RECIENTES para más detalles.

CAMBIOS

RECIENTES

Si se especifica la opción --recent, o si la opción gitconfig lfs.fetchrecentalways es verdadera, entonces después de obtener la referencia actual (o las de los argumentos), también buscamos cambios 'recientes' para obtener objetos, de modo que sea más conveniente hacer checkout o diff de esos commits sin incurrir en más

descargas.

Qué cambios se consideran 'recientes' se basa en una serie de opciones de

gitconfig:

lfs.fetchrecentrefsday

s
Si no es cero, incluye ramas que tienen commits dentro de N días de la fecha actual. Solo se incluyen referencias locales a menos que lfs.fetchrecentremoterefs sea verdadera. El valor predeterminado es 7
días.

lfs.fetchrecentremoteref

s
Si es verdadero, obtiene referencias remotas (para el remoto del que está obteniendo) así como referencias locales en la ventana reciente. Esto es útil para obtener objetos para ramas remotas que podría querer verificar más tarde. El valor predeterminado es verdadero; si establece esto en falso, la obtención para esas ramas solo ocurrirá cuando las verifique (perdiendo la ventaja de fetch --recent), o cree una rama local de seguimiento por separado y luego obtenga de
nuevo.

lfs.fetchrecentcommitsday

s
Además de obtener en las ramas, también obtiene cambios hechos dentro de N días del último commit en la rama. Esto es útil si a menudo está revisando cambios recientes. El valor predeterminado es 0 (sin cambios anteriores)
.

lfs.fetchrecentalway

s
Operar siempre como si se
proporcionara --recent e
n la línea de comandos.
