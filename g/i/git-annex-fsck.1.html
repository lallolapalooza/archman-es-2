NOMBRE

git-annex-fsck - encontrar y arreglar problemas

SINOPSIS

git annex fsck [ruta ...]

DESCRIPCIÓN

Este comando comprueba los archivos anexados en busca de consistencia y advierte o arregla cualquier problema encontrado. Es un buen complemento para git fsck.

Por defecto, se comprueban todos los archivos anexados en el directorio actual y sus subdirectorios. Con parámetros, solo se comprueban los archivos especificados.

Los problemas que encuentra fsck incluyen archivos que se han corrompido, archivos cuyo contenido se ha perdido de alguna manera, archivos que aún no tienen el número configurado de copias, y claves que pueden actualizarse a un formato mejor.

OPCIONES

--from=remoto
Comprueba un remoto en lugar del repositorio local.
Tenga en cuenta que, por defecto, se copiarán archivos del remoto para comprobar su contenido. Para evitar esta costosa transferencia y verificar solo que el remoto todavía tiene los archivos esperados, añada la opción --fast.
--fast
Evita costosos cálculos de suma de comprobación (y costosas transferencias al comprobar un remoto).
--incremental
Inicia una nueva pasada incremental de fsck, borrando los registros de todos los archivos que se comprobaron en la pasada incremental anterior.
--more
Omite los archivos que se comprobaron desde que se inició la última pasada incremental de fsck.
Tenga en cuenta que antes de usar --incremental para iniciar una pasada incremental de fsck, los archivos que se comprueban todavía se registran, y el uso de esta opción omitirá la comprobación de esos archivos nuevamente.
La reanudación puede comprobar redundantes algunos archivos que se comprobaron antes. Cualquier archivo que fsck encontrara problemas antes, se volverá a comprobar al reanudar. Además, se hacen puntos de control cada 1000 archivos o cada 5 minutos durante un fsck, y se reanuda desde el último punto de control, por lo que si un fsck incremental se interrumpe usando, por ejemplo, ctrl-c, volverá a comprobar los archivos que no llegaron al último punto de control.
--incremental-schedule=tiempo
Esto inicia un nuevo fsck incremental solo un período de tiempo especificado después de que se inició el último fsck incremental.
El tiempo está en el formato "10d" o "300h".
Quizás le gustaría ejecutar un fsck durante 5 horas por la noche, retomando cada noche donde lo dejó. Le gustaría que esto continuara hasta que todos los archivos se hayan verificado. Y una vez que haya terminado, le gustaría que se iniciara una nueva pasada de fsck, pero no con más frecuencia que una vez al mes. Entonces, ponga esto en un trabajo cron nocturno:

git annex fsck --incremental-schedule 30d --time-limit 5h
--numcopies=N
Anula el número de copias normalmente configurado.
Para verificar solo la integridad de los datos, ignorando el número requerido de copias, use --numcopies=1.
--all -A
Normalmente, solo se verifican los archivos en la rama actualmente extraída. Esta opción hace que se verifiquen todas las versiones de todos los archivos.
Este es el comportamiento predeterminado al ejecutar git-annex en un repositorio desnudo (bare).
--branch=ref
Opera sobre los archivos en la rama o árbol especificado.
--unused
Opera sobre los archivos encontrados por la última ejecución de git-annex unused.
--key=nombreclave
Use esta opción para verificar una clave específica.
opciones de coincidencia
Se pueden usar las opciones de coincidencia de git-annex-matching-options(1) para controlar qué verificar.
--jobs=N -JN
Ejecuta múltiples trabajos de fsck en paralelo. Por ejemplo: -J4
Establecer esto en "cpus" ejecutará un trabajo por núcleo de CPU.
--json
Habilita la salida JSON. Está diseñado para ser analizado por programas que utilizan git-annex. Cada línea de salida es un objeto JSON.
--json-error-messages
Los mensajes que normalmente se emitirían a la salida de error estándar se incluyen en el JSON.
--quiet
Como todos los comandos de git-annex, esta opción hace que solo se muestren los mensajes de error y advertencia. Esto es particularmente útil con fsck, que normalmente muestra todos los archivos que está comprobando, incluso cuando no hay ningún problema con ellos.
También se pueden usar las opciones comunes de git-annex-common-options(1).
