NOMBRE

git-shell - Shell de inicio de sesión restringido para acceso SSH solo a Git

SINOPSIS

chsh -s $(command -v git-shell) <usuario>
git clone <usuario>@localhost:/ruta/al/repo.git
ssh <usuario>@localhost

DESCRIPCIÓN

Este es un shell de inicio de sesión para cuentas SSH que proporciona acceso restringido a Git. Permite la ejecución solo de comandos Git del lado del servidor que implementan la funcionalidad de extracción/inserción (pull/push), además de comandos personalizados presentes en un subdirectorio llamado git-shell-commands en el directorio de inicio del usuario.

COMANDOS

git shell acepta los siguientes comandos después de la opción -c:

git receive-pack <argumento>, git upload-pack <argumento>, git upload-archive <argumento>

Llama al comando del servidor correspondiente para admitir la solicitud git push, git fetch o git archive --remote del cliente.

cvs server

Imita un servidor CVS. Ver git-cvsserver(1).

Si existe un directorio ~/git-shell-commands, git shell también manejará otros comandos personalizados ejecutando "git-shell-commands/<comando> <argumentos>" desde el directorio de inicio del usuario.

USO INTERACTIVO

Por defecto, los comandos anteriores solo se pueden ejecutar con la opción -c; el shell no es interactivo.

Si existe un directorio ~/git-shell-commands, git shell también se puede ejecutar interactivamente (sin argumentos). Si hay un comando help en el directorio git-shell-commands, se ejecuta para proporcionar al usuario una descripción general de las acciones permitidas. Luego se presenta un indicador de "git> " en el que se puede ingresar cualquiera de los comandos del directorio git-shell-commands, o exit para cerrar la conexión.

Generalmente, este modo se utiliza como una interfaz administrativa para permitir a los usuarios listar repositorios a los que tienen acceso, crear, eliminar o renombrar repositorios, o cambiar descripciones y permisos de repositorios.

Si existe un comando no-interactive-login, se ejecuta y se interrumpe el shell interactivo.

EJEMPLOS

Para deshabilitar inicios de sesión interactivos, mostrando un saludo en su lugar:

$ chsh -s /usr/bin/git-shell
$ mkdir $HOME/git-shell-commands
$ cat >$HOME/git-shell-commands/no-interactive-login <<\EOF
#!/bin/sh
printf '%s\n' "¡Hola $USER! Te has autenticado correctamente, pero no"
printf '%s\n' "proporcionamos acceso interactivo al shell."
exit 128
EOF
$ chmod +x $HOME/git-shell-commands/no-interactive-login

Para habilitar el acceso a git-cvsserver (que generalmente debería tener el ejemplo no-interactive-login anterior como requisito previo, ya que la creación del directorio git-shell-commands permite inicios de sesión interactivos):

$ cat >$HOME/git-shell-commands/cvs <<\EOF
if ! test $# = 1 && test "$1" = "server"
then
        echo >&2 "git-cvsserver solo maneja \"server\""
        exit 1
fi
exec git cvsserver server
EOF
$ chmod +x $HOME/git-shell-commands/cvs
