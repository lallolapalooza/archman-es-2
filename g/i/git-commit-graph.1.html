GIT-COMMIT-GRAPH(1) Manual de Git GIT-COMMIT-GRAPH(1)

NOMBRE

git-commit-graph - Escribe y verifica archivos commit-graph de Git

SINOPSIS

git commit-graph verify [--object-dir <dir>] [--shallow] [--[no-]progress]
git commit-graph write [--object-dir <dir>] [--append]
                        [--split[=<strategy>]] [--reachable | --stdin-packs | --stdin-commits]
                        [--changed-paths] [--[no-]max-new-filters <n>] [--[no-]progress]
                        <split-options>

DESCRIPCIÓN

Gestiona el archivo commit-graph serializado.

OPCIONES

--object-dir

Usa el directorio dado para la ubicación de los archivos pack y del archivo commit-graph. Este parámetro existe para especificar la ubicación de un alternativo que solo tiene el directorio de objetos, no un directorio completo .git . Se espera que el archivo commit-graph esté en el <dir>/info y que los archivos pack estén en <dir>/pack. Si el directorio no se pudo convertir en una ruta absoluta, o no coincide con ningún directorio de objetos conocido, git commit-graph ... saldrá con un estado distinto de cero.

--progress, --no-progress

Activa/desactiva explícitamente el progreso. Si no se especifica ninguno, se muestra el progreso si la salida de error estándar está conectada a una terminal.

COMANDOS

write

Escribe un archivo commit-graph basado en los commits encontrados en los archivos pack. Si la opción de configuración core.commitGraph está deshabilitada, entonces este comando emitirá una advertencia y luego devolverá éxito sin escribir un archivo commit-graph.

Con la --stdin-packs opción, genera el nuevo grafo de commits recorriendo objetos solo en los índices de pack especificados. (No se puede combinar con --stdin-commits o --reachable.)

Con la --stdin-commits opción, genera el nuevo grafo de commits recorriendo commits a partir de los commits especificados en stdin como una lista de OIDs en hexadecimal, un OID por línea. Los OIDs que resuelven a no-commits (ya sea directamente, o al desempaquetar etiquetas) se ignoran silenciosamente. Los OIDs que están mal formados, o no existen generan un error. (No se puede combinar con --stdin-packs o --reachable.)

Con la --reachable opción, genera el nuevo grafo de commits recorriendo commits a partir de todas las referencias. (No se puede combinar con --stdin-commits o --stdin-packs.)

Con la --append opción, incluye todos los commits que están presentes en el archivo commit-graph existente.

Con la --changed-paths opción, calcula y escribe información sobre las rutas cambiadas entre un commit y su primer padre. Esta operación puede tardar un tiempo en repositorios grandes. Proporciona ganancias de rendimiento significativas para obtener el historial de un directorio o un archivo con git log -- <path>. Si se da esta opción, escrituras futuras de commit-graph asumirán automáticamente que esta opción estaba destinada. Usa --no-changed-paths para dejar de almacenar estos datos. --changed-paths está implícito por la configuración commitGraph.changedPaths=true.

Con la --max-new-filters=<n> opción, genera como máximo n nuevos filtros Bloom (si --changed-paths está especificado). Si n es -1, no se aplica ningún límite. Solo los commits presentes en la nueva capa cuentan contra este límite. Para calcular retroactivamente filtros Bloom sobre capas anteriores, se aconseja usar --split=replace. Sobreescribe la commitGraph.maxNewFilters configuración.

Con la --split[=<strategy>] opción, escribe el commit-graph como una cadena de múltiples archivos commit-graph almacenados en <dir>/info/commit-graphs. Las capas de commit-graph se fusionan basándose en la estrategia y otras opciones de división. Los nuevos commits no ya presentes en el commit-graph se añaden en un nuevo archivo "tip". Este archivo se fusiona con el existente si se cumplen las siguientes condiciones de fusión:

•Si --split=no-merge está especificado, una fusión nunca se realiza, y las opciones restantes se ignoran. --split=replace sobreescribe la cadena existente con una nueva. Un --split simple difiere a las opciones restantes. (Nota que fusionar una cadena de grafos de commits reemplaza la cadena existente con una cadena de longitud 1 donde el primer y único incremental contiene el grafo completo).
•Si --size-multiple=<X> no está especificado, deja que X sea igual a 2. Si el nuevo archivo tip tendría N commits y el tip anterior tiene M commits y X veces N es mayor que M, en su lugar fusiona los dos archivos en un solo archivo.
•Si --max-commits=<M> está especificado con M un entero positivo, y el nuevo archivo tip tendría más de M commits, entonces en su lugar fusiona el nuevo tip con el tip anterior.

Finalmente, si --expire-time=<datetime> no está especificado, deja que datetime sea la hora actual. Después de escribir el commit-graph dividido, borra todos los commit-graph no usados cuyos tiempos de modificación sean más antiguos que datetime.

verify

Lee el archivo commit-graph y verifica su contenido contra la base de datos de objetos. Usado para comprobar datos corruptos.

Con la --shallow opción, solo verifica el archivo commit-graph de punta en una cadena de commit-graph divididos.

EJEMPLOS

•Escribe un archivo commit-graph para los commits empaquetados en tu directorio local .git . 
$ git commit-graph write
•Escribe un archivo commit-graph, extendiendo el archivo commit-graph actual usando commits en <pack-index>. 
$ echo <pack-index> | git commit-graph write --stdin-packs
•Escribe un archivo commit-graph que contiene todos los commits alcanzables. 
$ git show-ref -s | git commit-graph write --stdin-commits
•Escribe un archivo commit-graph que contiene todos los commits en el archivo commit-graph actual junto con aquellos alcanzables desde HEAD. 
$ git rev-parse HEAD | git commit-graph write --stdin-commits --append

CONFIGURACIÓN

Todo lo que está debajo de esta línea en esta sección se incluye selectivamente de la git-config(1) documentación. El contenido es el mismo que el que se encuentra allí:

commitGraph.generationVersion

Especifica el tipo de versión de número de generación a usar al escribir o leer el archivo commit-graph. Si se especifica la versión 1, entonces las fechas de commit corregidas no se escribirán ni leerán. Por defecto es 2.

commitGraph.maxNewFilters

Especifica el valor por defecto para la --max-new-filters opción de git commit-graph write (c.f., git-commit-graph(1)).

commitGraph.changedPaths

Si es verdadero, entonces git commit-graph write calculará y escribirá filtros Bloom de rutas cambiadas por defecto, equivalente a pasar --changed-paths. Si es falso o no está establecido, los filtros Bloom de rutas cambiadas se escribirán durante git commit-graph write solo si los filtros ya existen en el archivo commit-graph actual. Esto coincide con el comportamiento por defecto de git commit-graph write sin ninguna --[no-]changed-paths opción. Para reescribir un archivo commit-graph sin ningún filtro, usa la --no-changed-paths opción. La opción de línea de comandos --[no-]changed-paths siempre tiene precedencia sobre esta configuración. Por defecto no está establecido.

commitGraph.readChangedPaths

Obsoleto. Equivalente a commitGraph.changedPathsVersion=-1 si es verdadero, y commitGraph.changedPathsVersion=0 si es falso. (Si commitGraph.changedPathVersion también está establecido, commitGraph.changedPathsVersion tiene precedencia.)

commitGraph.changedPathsVersion

Especifica la versión de los filtros Bloom de rutas cambiadas que Git leerá y escribirá. Puede ser -1, 0, 1, o 2. Ten en cuenta que los valores mayores que 1 pueden ser incompatibles con versiones anteriores de Git que todavía no entienden esas versiones. Usa precaución al operar en un entorno de versiones mixtas.

Por defecto es -1.

Si es -1, Git usará la versión de los filtros Bloom de rutas cambiadasm filtros en el repositorio, por defecto 1 si no hay ninguno.

Si es 0, Git no leerá ningún filtro Bloom, y escribirá filtros Bloom de versión 1 cuando se le indique escribir.

Si es 1, Git solo leerá filtros Bloom de versión 1, y escribirá filtros Bloom de versión 1.

Si es 2, Git solo leerá filtros Bloom de versión 2, y escribirá filtros Bloom de versión 2.

Ver git-commit-graph(1) para más información.
