NOMBRE

git-fetch-pack - Recibir objetos faltantes de otro repositorio

SINOPSIS

git fetch-pack [--all] [--quiet|-q] [--keep|-k] [--thin] [--include-tag]
        [--upload-pack=<git-upload-pack>]
        [--depth=<n>] [--no-progress]
        [-v] <repositorio> [<refs>...]

DESCRIPCIÓN

Normalmente, deberías usar git fetch, que es un envoltorio de nivel superior de este comando, en su lugar.

Invoca git-upload-pack en un repositorio posiblemente remoto y le pide que envíe los objetos que faltan en este repositorio, para actualizar las cabezas (heads) nombradas. La lista de commits disponibles localmente se obtiene escaneando la jerarquía local de refs/ y se envía a git-upload-pack ejecutándose en el otro extremo.

Este comando degenera a descargar todo para completar las refs solicitadas desde el lado remoto cuando el lado local no tiene un ancestro común.

OPCIONES

--all

Obtener todas las refs remotas.

--stdin

Tomar la lista de refs de stdin, una por línea. Si hay refs especificadas en la línea de comandos además de esta opción, las refs de stdin se procesan después de las de la línea de comandos.

Si se especifica --stateless-rpc junto con esta opción, entonces la lista de refs debe estar en formato de paquetes (pkt-line). Cada ref debe estar en un paquete separado, y la lista debe terminar con un paquete de limpieza (flush packet).

-q, --quiet

Pasa la bandera -q a git unpack-objects; esto hace que el proceso de clonación sea menos verboso.

-k, --keep

No invocar git unpack-objects sobre los datos recibidos, sino crear un único archivo de paquete a partir de ellos, y almacenarlo en la base de datos de objetos. Si se proporciona dos veces, el paquete se bloquea contra el repaquetado.

--thin

Obtener un paquete "delgado" (thin), que registra los objetos en forma delgada (deltified) basándose en los objetos no incluidos en el paquete para reducir el tráfico de red.

--include-tag

Si el lado remoto lo soporta, los objetos de etiquetas anotadas se descargarán en la misma conexión que los otros objetos si el objeto al que apunta la etiqueta se descarga. El llamante debe, de lo contrario, determinar las etiquetas que esta opción hizo disponibles.

--upload-pack=<git-upload-pack>

Úselo para especificar la ruta a git-upload-pack en el lado remoto, si no se encuentra en su $PATH. Las instalaciones de sshd ignoran los scripts de configuración del entorno del usuario para shells de inicio de sesión (por ejemplo, .bash_profile) y su git instalado privadamente puede no encontrarse en el $PATH predeterminado del sistema. Otra solución sugerida es configurar su $PATH en ".bashrc", pero esta bandera es para personas que no quieren pagar la sobrecarga para shells no interactivos al tener un .bashrc liviano (configuran la mayoría de las cosas en .bash_profile).

--exec=<git-upload-pack>

Igual que --upload-pack=<git-upload-pack>.

--depth=<n>

Limitar la obtención a cadenas de ancestros no más largas que n. git-upload-pack trata la profundidad especial 2147483647 como infinita, incluso si existe una cadena de ancestros tan larga.

--shallow-since=<fecha>

Profundizar o acortar el historial de un repositorio superficial para incluir todos los commits alcanzables después de <fecha>.

--shallow-exclude=<ref>

Profundizar o acortar el historial de un repositorio superficial para excluir commits alcanzables desde una rama o etiqueta remota especificada. Esta opción se puede especificar varias veces.

--deepen-relative

El argumento --depth especifica el número de commits desde el límite superficial actual en lugar de desde la punta del historial de cada rama remota.

--refetch

Omite la negociación de commits con el servidor para obtener todos los objetos coincidentes. Úselo para volver a aplicar un nuevo filtro de blob/árbol de clonación parcial.

--no-progress

No mostrar el progreso.

--check-self-contained-and-connected

Salida "connectivity-ok" si el paquete recibido está autocontenido y conectado.

-v

Ejecutar verbosamente.

<repositorio>

La URL del repositorio remoto.

<refs>...

Las cabezas remotas a actualizar. Esto es relativo a $GIT_DIR (por ejemplo, "HEAD", "refs/heads/master"). Cuando no se especifica, actualiza desde todas las cabezas que tiene el lado remoto.

Si el remoto ha habilitado las opciones uploadpack.allowTipSHA1InWant, uploadpack.allowReachableSHA1InWant, o uploadpack.allowAnySHA1InWant, alternativamente pueden ser sha1s hexadecimales de 40 caracteres presentes en el remoto.
