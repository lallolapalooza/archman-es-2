GIT-HTTP-FETCH(1) Manual de Git GIT-HTTP-FETCH(1)

NOMBRE

git-http-fetch - Descargar desde un repositorio Git remoto vía HTTP

SINOPSIS

git http-fetch [-c] [-t] [-a] [-d] [-v] [-w <nombrearchivo>] [--recover] [--stdin | --packfile=<hash> | <commit>] <URL>

DESCRIPCIÓN

Descarga un repositorio Git remoto vía HTTP.

Este comando siempre obtiene todos los objetos. Históricamente, existían tres opciones -a, -c y -t para elegir qué objetos descargar. Ahora se ignoran silenciosamente.

OPCIONES

id-commit

Ya sea el hash o el nombre del archivo bajo [URL]/refs/ para hacer pull.

-a, -c, -t

Estas opciones se ignoran por razones históricas.

-v

Reportar lo que se está descargando.

-w <nombrearchivo>

Escribe el id-commit en el nombre de archivo especificado bajo $GIT_DIR/refs/<nombrearchivo> en el extremo local después de que la transferencia se complete.

--stdin

En lugar de un id-commit en la línea de comandos (que no se espera en este caso), git http-fetch espera líneas en la entrada estándar en el formato 
<id-commit>['\t'<nombrearchivo-como-en--w>]

--packfile=<hash>

Solo para uso interno. En lugar de un id-commit en la línea de comandos (que no se espera en este caso), git http-fetch descarga el packfile directamente en la URL dada y usa index-pack para generar los archivos .idx y .keep correspondientes. El hash se usa para determinar el nombre del archivo temporal y es arbitrario. La salida de index-pack se imprime en la salida estándar. Requiere --index-pack-args.

--index-pack-args=<args>

Solo para uso interno. El comando a ejecutar en el contenido del paquete descargado. Los argumentos están codificados en URL y separados por espacios.

--recover

Verifica que todo lo alcanzable desde el objetivo se ha descargado. Se usa después de que una descarga anterior se interrumpe.
