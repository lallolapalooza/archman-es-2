NOMBRE

git-multi-pack-index - Escribe y verifica multi-pack-indexes

SINOPSIS

git multi-pack-index [--object-dir=<dir>] [--[no-]bitmap] <sub-comando>

DESCRIPCIÓN

Escribe o verifica un archivo multi-pack-index (MIDX).

OPCIONES

--object-dir=<dir>

Usa el directorio dado para la ubicación de los objetos Git. Verificamos <dir>/packs/multi-pack-index para el archivo MIDX actual, y <dir>/packs para los archivos de paquete a indexar.

<dir> debe ser un alternativo del repositorio actual.

--progress, --no-progress

Activa/desactiva explícitamente el progreso. Si no se especifica ninguno, el progreso se muestra si la salida de error estándar está conectada a una terminal. Compatible con los subcomandos write, verify, expire y repack.

Los siguientes subcomandos están disponibles:

write

Escribe un nuevo archivo MIDX. Las siguientes opciones están disponibles para el subcomando write:

--preferred-pack=<pack>

Cuando se especifica, rompe empates a favor de este paquete cuando hay copias adicionales de sus objetos en otros paquetes. Los empates para objetos no encontrados en el paquete preferido siempre se resuelven a favor de la copia en el paquete con el mtime más alto. Si no se especifica, por defecto se usa el paquete con el mtime más bajo. El paquete preferido debe tener al menos un objeto.

--[no-]bitmap

Controla si se escribe o no un mapa de bits de multi-paquete.

--stdin-packs

Escribe un índice de multi-paquetes que contiene solo el conjunto de nombres base de índices de paquetes delimitados por líneas proporcionados a través de stdin.

--refs-snapshot=<path>

Con --bitmap, opcionalmente especifica un archivo que contiene una "instantánea de referencias" tomada antes de volver a empaquetar.

Una instantánea de referencia se compone de OIDs delimitados por líneas correspondientes a las puntas de referencia, generalmente tomadas por git repack antes de generar un nuevo paquete. Una línea opcionalmente puede comenzar con un carácter + para indicar que la referencia que corresponde a ese OID es "preferida" (ver git-config(1) pack.preferBitmapTips).

Se espera que el archivo dado en <path> sea legible y puede contener duplicados. (Si un OID dado se da más de una vez, se marca como preferido si al menos una instancia de él comienza con el marcador especial +).

--incremental

Escribe un archivo MIDX incremental que contiene solo objetos y paquetes no presentes en una capa MIDX existente. Migra MIDXs no incrementales a incrementales cuando sea necesario. Incompatible con --bitmap.

verify

Verifica el contenido del archivo MIDX.

expire

Elimina los archivos de paquete que son rastreados por el archivo MIDX, pero no tienen objetos referenciados por el MIDX (con la excepción de los paquetes .keep y los paquetes de descarte). Reescribe el archivo MIDX posteriormente para eliminar todas las referencias a estos archivos de paquete.

Nota
este modo es incompatible con archivos MIDX incrementales.

repack

Crea un nuevo archivo de paquete que contiene objetos en paquetes pequeños referenciados por el multi-pack-index. Si el tamaño dado por el argumento --batch-size=<size> es cero, entonces crea un paquete que contiene todos los objetos referenciados por el multi-pack-index. Para un tamaño de lote distinto de cero, selecciona los archivos de paquete examinando los paquetes de más antiguo a más reciente, calculando el "tamaño esperado" contando el número de objetos en el paquete referenciado por el multi-pack-index, luego divide por el número total de objetos en el paquete y multiplica por el tamaño del paquete. Seleccionamos paquetes con un tamaño esperado por debajo del tamaño del lote hasta que el conjunto de paquetes tenga un tamaño esperado total de al menos el tamaño del lote, o se consideren todos los archivos de paquete. Si solo se selecciona un archivo de paquete, no hagas nada. Si se crea un nuevo archivo de paquete, reescribe el multi-pack-index para referenciar el nuevo archivo de paquete. Una ejecución posterior de git multi-pack-index expire eliminará los archivos de paquete que formaron parte de este lote.

Si repack.packKeptObjects es false, entonces cualquier archivo de paquete con un archivo .keep asociado no se seleccionará para el lote a repaquetar.


Nota
este modo es incompatible con archivos MIDX incrementales.

EJEMPLOS

•Escribe un archivo MIDX para los archivos de paquete en el directorio .git actual. 
$ git multi-pack-index write
•Escribe un archivo MIDX para los archivos de paquete en el directorio .git actual con un mapa de bits correspondiente. 
$ git multi-pack-index write --preferred-pack=<pack> --bitmap
•Escribe un archivo MIDX para los archivos de paquete en un almacén de objetos alternativo. 
$ git multi-pack-index --object-dir <alt> write
•Verifica el archivo MIDX para los archivos de paquete en el directorio .git actual. 
$ git multi-pack-index verify
