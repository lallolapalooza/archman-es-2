NOMBRE

git-mailinfo - Extrae parches y autoría de un solo mensaje de correo electrónico

SINOPSIS

git mailinfo [-k|-b] [-u | --encoding=<codificación> | -n]
               [--[sin-]scissors] [--quoted-cr=<acción>]
               <msg> <patch>

DESCRIPCIÓN

Lee un único mensaje de correo electrónico desde la entrada estándar, y escribe el mensaje de registro de commit en el archivo <msg>, y los parches en el archivo <patch>. El nombre del autor, el correo electrónico y el asunto del correo electrónico se escriben en la salida estándar para ser utilizados por git am para crear un commit. Por lo general, no es necesario usar este comando directamente. Consulte git-am(1) en su lugar.

OPCIONES

-k

Normalmente, el programa elimina la "basura" del correo electrónico de la línea de encabezado Subject: para extraer la línea de título para el mensaje de registro de commit. Esta opción evita esta manipulación, y es más útil cuando se usa para leer la salida de git format-patch -k.

Específicamente, se eliminan los siguientes elementos hasta que ninguno de ellos permanezca:

•Espacios en blanco al principio y al final.
•Prefijos Re:, re: y :.
•Cadenas entre corchetes al principio (entre [ y ], normalmente [PATCH]).

Finalmente, las secuencias de espacios en blanco se normalizan a un solo carácter de espacio ASCII.

-b

Cuando -k no está en efecto, se eliminan todas las cadenas principales delimitadas por pares de corchetes [ y ]. Esta opción limita la eliminación solo a los pares cuya cadena entre corchetes contenga la palabra "PATCH".

-u

El mensaje de registro de commit, el nombre del autor y el correo electrónico del autor se toman del correo electrónico, y después de decodificar mínimamente la codificación de transferencia MIME, se vuelven a codificar en el conjunto de caracteres especificado por i18n.commitEncoding (por defecto UTF-8) transliterándolos. Esto solía ser opcional, pero ahora es el valor predeterminado.

Tenga en cuenta que el parche siempre se utiliza tal cual, sin conversión de conjunto de caracteres, incluso con esta bandera.

--encoding=<codificación>

Similar a -u. Pero al recodificar, se utiliza el conjunto de caracteres especificado aquí en lugar del especificado por i18n.commitEncoding o UTF-8.

-n

Desactiva toda la recodificación de conjuntos de caracteres de los metadatos.

-m, --message-id

Copia el encabezado Message-ID al final del mensaje de commit. Esto es útil para asociar commits con discusiones de listas de correo.

--scissors

Elimina todo el cuerpo antes de una línea de tijeras (por ejemplo, "-- >8 --"). La línea representa tijeras y marcas de perforación, y se utiliza para solicitar al lector que corte el mensaje en esa línea. Si esa línea aparece en el cuerpo del mensaje antes del parche, todo lo que esté antes de ella (incluida la propia línea de tijeras) se ignora cuando se utiliza esta opción.

Esto es útil si desea comenzar su mensaje en un hilo de discusión con comentarios y sugerencias sobre el mensaje al que está respondiendo, y concluirlo con el envío de un parche, separando la discusión y el inicio del mensaje de registro de commit propuesto con una línea de tijeras.

Esto se puede habilitar por defecto con la opción de configuración mailinfo.scissors.

--no-scissors

Ignora las líneas de tijeras. Útil para anular la configuración de mailinfo.scissors.

--quoted-cr=<acción>

Acción al procesar mensajes de correo electrónico enviados con codificación base64 o quoted-printable, y las líneas decodificadas terminan con un CRLF en lugar de un LF simple.

Las acciones válidas son:

•nowarn: Git no hará nada cuando se encuentre dicho CRLF.
•warn: Git emitirá una advertencia por cada mensaje si se encuentra dicho CRLF.
•strip: Git convertirá esos CRLF a LF.

La acción predeterminada se puede establecer mediante la opción de configuración mailinfo.quotedCR. Si no se ha establecido dicha opción de configuración, se utilizará warn.

<msg>

El mensaje de registro de commit extraído del correo electrónico, generalmente excepto la línea de título que proviene del asunto del correo electrónico.

<patch>

El parche extraído del correo electrónico.

CONFIGURACIÓN

Todo lo que aparece debajo de esta línea en esta sección se incluye selectivamente de la documentación de git-config(1). El contenido es el mismo que el que se encuentra allí:

mailinfo.scissors

Si es verdadero, hace que git-mailinfo(1) (y, por lo tanto, git-am(1)) actúe por defecto como si la opción --scissors se hubiera proporcionado en la línea de comandos. Cuando está activo, esta función elimina todo del cuerpo del mensaje antes de una línea de tijeras (es decir, que consiste principalmente en ">8", "8<" y "-").
