GIT-CHECK-REF-FORMAT(1) Manual de Git GIT-CHECK-REF-FORMAT(1)

NOMBRE

git-check-ref-format - Asegura que un nombre de referencia esté bien formado

SINOPSIS

git check-ref-format [--normalize]
       [--[no-]allow-onelevel] [--refspec-pattern]
       <refname>
git check-ref-format --branch <shorthand-nombre-rama>

DESCRIPCIÓN

Comprueba si un refname dado es aceptable y sale con un estado distinto de cero si no lo es.

Una referencia se utiliza en Git para especificar ramas y etiquetas. La cabeza de una rama se almacena en la jerarquía refs/heads, mientras que una etiqueta se almacena en la jerarquía refs/tags del espacio de nombres de referencia (típicamente en los directorios $GIT_DIR/refs/heads y $GIT_DIR/refs/tags o, como entradas en el archivo $GIT_DIR/packed-refs si las referencias están empaquetadas por git gc).

Git impone las siguientes reglas sobre cómo se nombran las referencias:

1. Pueden incluir barras / para agrupación jerárquica (directorios), pero ningún componente separado por barras puede comenzar con un punto . o terminar con la secuencia .lock.
2. Deben contener al menos una /. Esto garantiza la presencia de una categoría como heads/, tags/, etc., pero los nombres reales no están restringidos. Si se utiliza la opción --allow-onelevel, esta regla se omite.
3. No pueden tener puntos consecutivos .. en ningún lugar.
4. No pueden contener caracteres de control ASCII (es decir, bytes cuyos valores son inferiores a \040, o \177 DEL), espacio, tilde ~, circunflejo ^, o dos puntos : en ningún lugar.
5. No pueden contener signo de interrogación ?, asterisco *, o corchete de apertura [ en ningún lugar. Consulte la opción --refspec-pattern a continuación para una excepción a esta regla.
6. No pueden comenzar ni terminar con una barra / ni contener barras consecutivas (consulte la opción --normalize a continuación para una excepción a esta regla).
7. No pueden terminar con un punto ..
8. No pueden contener una secuencia @{.
9. No pueden ser el carácter único @.
10. No pueden contener un \.

Estas reglas facilitan el análisis de nombres de referencia por herramientas basadas en scripts de shell, la expansión de nombres de ruta por el shell cuando se utiliza un nombre de referencia sin comillas (por error), y también evitan ambigüedades en ciertas expresiones de nombres de referencia (consulte gitrevisions(7)):

1. Un doble punto .. se utiliza a menudo como en ref1..ref2, y en algunos contextos esta notación significa ^ref1 ref2 (es decir, no en ref1 y en ref2).
2. Una tilde ~ y un circunflejo ^ se utilizan para introducir la operación postfix de n-ésimo padre y desenvolver la cebolla.
3. Un dos puntos : se utiliza como en srcref:dstref para significar "usar el valor de srcref y almacenarlo en dstref" en operaciones de fetch y push. También puede usarse para seleccionar un objeto específico, como con git cat-file: "git cat-file blob v1.3.3:refs.c".
4. El arroba-llave de apertura @{ se utiliza como notación para acceder a una entrada de reflog.

Con la opción --branch, el comando toma un nombre y comprueba si puede usarse como un nombre de rama válido (por ejemplo, al crear una nueva rama). Pero tenga cuidado al usar la sintaxis de checkout anterior que puede referirse a un estado de HEAD desconectado. La regla que implementa git check-ref-format --branch $nombre puede ser más estricta que lo que dice git check-ref-format refs/heads/$nombre (por ejemplo, un guion puede aparecer al principio de un componente de referencia, pero está explícitamente prohibido al principio de un nombre de rama). Cuando se ejecuta con la opción --branch en un repositorio, la entrada se expande primero para la «sintaxis de checkout anterior» @{-n}. Por ejemplo, @{-1} es una forma de referirse a lo último que se cambió con la operación "git switch" o "git checkout". Esta opción debe ser utilizada por las capas superiores para aceptar esta sintaxis dondequiera que se espere un nombre de rama, de modo que puedan actuar como si hubiera escrito el nombre de la rama. Como excepción, tenga en cuenta que la «operación de checkout anterior» puede resultar en un nombre de objeto commit cuando lo último cambiado N veces no era una rama.

OPCIONES

--allow-onelevel, --no-allow-onelevel

Controla si se aceptan nombres de referencia de un solo nivel (es decir, nombres de referencia que no contienen múltiples componentes separados por /). El valor predeterminado es --no-allow-onelevel.

--refspec-pattern

Interpreta <refname> como un patrón de nombre de referencia para un refspec (como se usa con repositorios remotos). Si esta opción está habilitada, <refname> puede contener un único * en el refspec (por ejemplo, foo/bar*/baz o foo/bar*baz/, pero no foo/bar*/baz*).

--normalize

Normaliza refname eliminando cualquier carácter de barra inicial (/) y colapsando series de barras adyacentes entre componentes de nombre en una sola barra. Si el refname normalizado es válido, imprímalo en la salida estándar y salga con un estado de 0, de lo contrario, salga con un estado distinto de cero. (--print es una forma obsoleta de escribir --normalize.)

EJEMPLOS

•Imprimir el nombre de lo último que se cambió: 
$ git check-ref-format --branch @{-1}
•Determinar el nombre de referencia a utilizar para una nueva rama: 
$ ref=$(git check-ref-format --normalize "refs/heads/$newbranch")||
{ echo "no nos gusta '$newbranch' como nombre de rama." >&2 ; exit 1 ; }
