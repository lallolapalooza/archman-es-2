NOMBRE

git-pack-refs - Empaqueta cabeceras y etiquetas para un acceso eficiente al repositorio

SINOPSIS

git pack-refs [--all] [--no-prune] [--auto] [--include <patrón>] [--exclude <patrón>]

DESCRIPCIÓN

Tradicionalmente, las puntas de las ramas y las etiquetas (colectivamente conocidas como refs) se almacenaban en un archivo por ref en un directorio (sub)bajo el directorio $GIT_DIR/refs. Si bien muchas puntas de rama tienden a actualizarse a menudo, la mayoría de las etiquetas y algunas puntas de rama nunca se actualizan. Cuando un repositorio tiene cientos o miles de etiquetas, este formato de un archivo por ref desperdicia almacenamiento y perjudica el rendimiento.

Este comando se utiliza para resolver el problema de almacenamiento y rendimiento almacenando las refs en un único archivo, $GIT_DIR/packed-refs. Cuando una ref no se encuentra en la jerarquía tradicional del directorio $GIT_DIR/refs, se busca en este archivo y se utiliza si se encuentra.

Las actualizaciones posteriores de las ramas siempre crean nuevos archivos en la jerarquía del directorio $GIT_DIR/refs.

Una práctica recomendada para tratar con un repositorio con demasiadas refs es empaquetar sus refs con --all una vez, y ejecutar ocasionalmente git pack-refs. Las etiquetas son estacionarias por definición y no se espera que cambien. Las cabeceras de las ramas se empaquetarán con el pack-refs inicial --all, pero solo las cabeceras de rama activas actualmente se desempaquetarán, y el siguiente pack-refs (sin --all) las dejará desempaquetadas.

OPCIONES

--all

El comando, por defecto, empaqueta todas las etiquetas y refs que ya están empaquetadas, y deja las otras refs intactas. Esto se debe a que se espera que las ramas se desarrollen activamente y empaquetar sus puntas no ayuda al rendimiento. Esta opción hace que todas las refs también se empaqueten, con la excepción de las refs ocultas, las refs rotas y las refs simbólicas. Útil para un repositorio con muchas ramas de interés histórico.

--no-prune

El comando generalmente elimina las refs sueltas bajo la jerarquía $GIT_DIR/refs después de empaquetarlas. Esta opción le indica que no lo haga.

--auto

Empaqueta refs según sea necesario según el estado actual de la base de datos de refs. El comportamiento depende del formato de ref utilizado por el repositorio y puede cambiar en el futuro.
•"files": Las referencias sueltas se empaquetan en el archivo packed-refs según la relación entre referencias sueltas y el tamaño del archivo packed-refs. Cuanto más grande sea el archivo packed-refs, más referencias sueltas deben existir antes de volver a empaquetar.
•"reftable": Las tablas se compactan de tal manera que forman una secuencia geométrica. Para dos tablas N y N+1, donde N+1 es más nueva, esto mantiene la propiedad de que N es al menos el doble de grande que N+1. Solo las tablas que violan esta propiedad se compactan.

--include <patrón>

Empaqueta refs basándose en un patrón glob(7). Las repeticiones de esta opción acumulan patrones de inclusión. Si una ref está incluida tanto en --include como en --exclude, --exclude tiene precedencia. Usar --include excluirá todas las etiquetas por defecto. Las refs simbólicas y rotas nunca se empaquetarán. Cuando se usa con --all, será una operación nula. Utilice --no-include para borrar y restablecer la lista de patrones.

--exclude <patrón>

No empaquetar refs que coincidan con el patrón glob(7) dado. Las repeticiones de esta opción acumulan patrones de exclusión. Utilice --no-exclude para borrar y restablecer la lista de patrones. Si una ref ya está empaquetada, incluirla con --exclude no la desempaquetará.

Cuando se usa con --all, empaqueta solo las refs sueltas que no coinciden con ninguno de los patrones --exclude proporcionados.

Cuando se usa con --include, se empaquetarán las refs proporcionadas a --include menos las refs proporcionadas a --exclude.

ERRORES

La documentación anterior escrita antes de la introducción del mecanismo de refs empaquetadas todavía puede decir cosas como "existe el archivo .git/refs/heads/<rama>" cuando en realidad significa "existe la rama <rama>".
