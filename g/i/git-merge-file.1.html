NOMBRE

git-merge-file - Ejecutar una fusión de archivos de tres vías

SINOPSIS

git merge-file [-L <nombre-actual> [-L <nombre-base> [-L <nombre-otro>]]]
        [--ours|--theirs|--union] [-p|--stdout] [-q|--quiet] [--marker-size=<n>]
        [--[no-]diff3] [--object-id] <actual> <base> <otro>

DESCRIPCIÓN

Dados tres archivos <actual>, <base> y <otro>, git merge-file incorpora todos los cambios que van desde <base> a <otro> en <actual>. El resultado va normalmente a <actual>. git merge-file es útil para combinar cambios separados en un original. Suponga que <base> es el original, y tanto <actual> como <otro> son modificaciones de <base>, entonces git merge-file combina ambos cambios.

Ocurre un conflicto si tanto <actual> como <otro> tienen cambios en un segmento común de líneas. Si se encuentra un conflicto, git merge-file normalmente emite una advertencia y encierra el conflicto con líneas que contienen marcadores <<<<<<< y >>>>>>>. Un conflicto típico se verá así:

<<<<<<< A
líneas en el archivo A
=======
líneas en el archivo B
>>>>>>> B

Si hay conflictos, el usuario debe editar el resultado y eliminar una de las alternativas. Sin embargo, cuando las opciones --ours, --theirs o --union están activas, estos conflictos se resuelven favoreciendo las líneas de <actual>, las líneas de <otro> o las líneas de ambos respectivamente. La longitud de los marcadores de conflicto se puede dar con la opción --marker-size.

Si se especifica --object-id, ocurre exactamente el mismo comportamiento, excepto que en lugar de especificar qué fusionar como archivos, se especifica como una lista de IDs de objeto que se refieren a blobs.

El valor de salida de este programa es negativo en caso de error, y el número de conflictos en caso contrario (truncado a 127 si hay más de tantos conflictos). Si la fusión fue limpia, el valor de salida es 0.

git merge-file está diseñado para ser un clon mínimo de RCS merge; es decir, implementa toda la funcionalidad de RCS merge que es necesaria para git(1).

OPCIONES

--object-id

Especificar el contenido a fusionar como blobs en el repositorio actual en lugar de archivos. En este caso, la operación debe tener lugar dentro de un repositorio válido.

Si se especifica la opción -p, el archivo fusionado (incluyendo conflictos, si los hay) va a la salida estándar como de costumbre; de lo contrario, el archivo fusionado se escribe en el almacén de objetos y el ID del objeto de su blob se escribe en la salida estándar.

-L <etiqueta>

Esta opción se puede dar hasta tres veces y especifica las etiquetas a utilizar en lugar de los nombres de archivo correspondientes en los informes de conflicto. Es decir, git merge-file -L x -L y -L z a b c genera una salida que parece provenir de los archivos x, y y z en lugar de los archivos a, b y c.

-p

Enviar resultados a la salida estándar en lugar de sobrescribir <actual>.

-q

Silencioso; no advertir sobre conflictos.

--diff3

Mostrar conflictos en estilo "diff3".

--zdiff3

Mostrar conflictos en estilo "zdiff3".

--ours, --theirs, --union

En lugar de dejar conflictos en el archivo, resolver conflictos favoreciendo nuestro lado (o el suyo o ambos) de las líneas.

--diff-algorithm={patience|minimal|histogram|myers}

Usar un algoritmo de diferencia diferente al fusionar. El predeterminado actual es "myers", pero seleccionar un algoritmo más reciente como "histogram" puede ayudar a evitar fusiones incorrectas que ocurren debido a líneas coincidentes sin importancia (como llaves de funciones distintas). Ver también git-diff(1) --diff-algorithm.

EJEMPLOS

git merge-file README.mivida README README.upstream

combina los cambios de README.mivida y README.upstream desde README, intenta fusionarlos y escribe el resultado en README.mivida.

git merge-file -L a -L b -L c tmp/a123 tmp/b234 tmp/c345

fusiona tmp/a123 y tmp/c345 con la base tmp/b234, pero usa las etiquetas a y c en lugar de tmp/a123 y tmp/c345.

git merge-file -p --object-id abc1234 def567 890abcd

combina los cambios del blob abc1234 y 890abcd desde def567, intenta fusionarlos y escribe el resultado en la salida estándar.
