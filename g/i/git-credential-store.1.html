NOMBRE

git-credential-store - Ayudante para almacenar credenciales en disco

SINOPSIS

git config credential.helper 'store [<opciones>]'

DESCRIPCIÓN


Nota

El uso de este ayudante almacenará tus contraseñas sin cifrar en disco, protegidas únicamente por los permisos del sistema de archivos. Si esto no es una compensación de seguridad aceptable, prueba git-credential-cache(1), o busca un ayudante que se integre con el almacenamiento seguro proporcionado por tu sistema operativo.

Este comando almacena credenciales indefinidamente en disco para su uso por programas Git futuros.

Probablemente no querrás invocar este comando directamente; está destinado a ser utilizado como un ayudante de credenciales por otras partes de git. Vea gitcredentials(7) o EJEMPLOS abajo.

OPCIONES

--file=<ruta>

Usa <ruta> para buscar y almacenar credenciales. El archivo tendrá sus permisos de sistema de archivos configurados para evitar que otros usuarios en el sistema lo lean, pero no estará cifrado ni protegido de otra manera. Si no se especifica, las credenciales se buscarán en ~/.git-credentials y $XDG_CONFIG_HOME/git/credentials, y las credenciales se escribirán en ~/.git-credentials si existe, o en $XDG_CONFIG_HOME/git/credentials si existe y el primero no. Ver también la sección llamada “ARCHIVOS”.

ARCHIVOS

Si no se establece explícitamente con --file, hay dos archivos donde git-credential-store buscará credenciales en orden de precedencia:

~/.git-credentials

Archivo de credenciales específico del usuario.

$XDG_CONFIG_HOME/git/credentials

Segundo archivo de credenciales específico del usuario. Si $XDG_CONFIG_HOME no está establecido o está vacío, se usará $HOME/.config/git/credentials. Cualquier credencial almacenada en este archivo no se usará si ~/.git-credentials también tiene una credencial coincidente. Es una buena idea no crear este archivo si a veces usas versiones antiguas de Git que no lo admiten.

Para búsquedas de credenciales, los archivos se leen en el orden dado arriba, con la primera credencial coincidente encontrada que tiene precedencia sobre las credenciales encontradas en archivos más abajo en la lista.

El almacenamiento de credenciales, por defecto, escribirá en el primer archivo existente en la lista. Si ninguno de estos archivos existe, se creará y se escribirá en ~/.git-credentials.

Al borrar credenciales, las credenciales coincidentes se borrarán de todos los archivos.

EJEMPLOS

El propósito de este ayudante es reducir el número de veces que debes escribir tu nombre de usuario o contraseña. Por ejemplo:

$ git config credential.helper store
$ git push http://example.com/repo.git
Nombre de usuario: <escribe tu nombre de usuario>
Contraseña: <escribe tu contraseña>
[varios días después]
$ git push http://example.com/repo.git
[tus credenciales se utilizan automáticamente]

FORMATO DE ALMACENAMIENTO

El archivo .git-credentials se almacena en texto plano. Cada credencial se almacena en su propia línea como una URL tipo:

https://user:pass@example.com

No se permiten otros tipos de líneas (por ejemplo, líneas vacías o líneas de comentario) en el archivo, aunque algunas pueden ser ignoradas silenciosamente. No veas o edites el archivo con editores.

Cuando Git necesita autenticación para un contexto de URL particular, credential-store considerará ese contexto como un patrón para coincidir con cada entrada en el archivo de credenciales. Si el protocolo, el nombre de host y el nombre de usuario (si ya tenemos uno) coinciden, entonces la contraseña se devuelve a Git. Ver la discusión de configuración en gitcredentials(7) para más información.
