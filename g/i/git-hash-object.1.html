NOMBRE

git-hash-object - Calcular el ID del objeto y opcionalmente crear un objeto a partir de un archivo

SINOPSIS

git hash-object [-t <tipo>] [-w] [--path=<archivo> | --no-filters]
                [--stdin [--literally]] [--] <archivo>...
git hash-object [-t <tipo>] [-w] --stdin-paths [--no-filters]

DESCRIPCIÓN

Calcula el valor del ID del objeto con el tipo especificado, utilizando el contenido del archivo nombrado (que puede estar fuera del directorio de trabajo), y opcionalmente escribe el objeto resultante en la base de datos de objetos. Informa su ID de objeto en su salida estándar. Cuando no se especifica <tipo>, se utiliza por defecto "blob".

OPCIONES

-t <tipo>

Especifica el tipo de objeto a crear (por defecto: "blob"). Los valores posibles son commit, tree, blob y tag.

-w

Escribe realmente el objeto en la base de datos de objetos.

--stdin

Lee el objeto de la entrada estándar en lugar de un archivo.

--stdin-paths

Lee nombres de archivo de la entrada estándar, uno por línea, en lugar de desde la línea de comandos.

--path

Calcula el hash del objeto como si estuviera ubicado en la ruta dada. La ubicación del archivo no influye directamente en el valor del hash, pero la ruta se utiliza para determinar qué filtros de Git se aplicarán al objeto antes de que pueda ser colocado en la base de datos de objetos. Como resultado de la aplicación de filtros, el blob real que se pone en la base de datos de objetos puede diferir del archivo dado. Esta opción es principalmente útil para calcular el hash de archivos temporales ubicados fuera del directorio de trabajo o archivos leídos de la entrada estándar.

--no-filters

Calcula el hash del contenido tal cual, ignorando cualquier filtro de entrada que hubiera sido elegido por el mecanismo de atributos, incluida la conversión de fin de línea. Si el archivo se lee de la entrada estándar, esto siempre se implica, a menos que se especifique la opción --path.

--literally

Permite que --stdin calcule el hash de cualquier basura en un objeto suelto que de otro modo no pasaría los controles estándar de análisis de objetos o de git-fsck. Útil para probar exhaustivamente Git en sí mismo o para reproducir características de objetos corruptos o falsos encontrados en la naturaleza.
