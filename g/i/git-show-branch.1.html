GIT-SHOW-BRANCH(1) Manual de Git GIT-SHOW-BRANCH(1)

NOMBRE

git-show-branch - Muestra ramas y sus commits

SINOPSIS

git show-branch [-a | --all] [-r | --remotes] [--topo-order | --date-order]
                [--current] [--color[=<cuándo>] | --no-color] [--sparse]
                [--more=<n> | --list | --independent | --merge-base]
                [--no-name | --sha1-name] [--topics]
                [(<rev> | <glob>)...]
git show-branch (-g | --reflog)[=<n>[,<base>]] [--list] [<ref>]

DESCRIPCIÓN

Muestra el grafo de ancestros de commits comenzando desde los commits nombrados con <rev> o <glob> (o todos los refs bajo refs/heads y/o refs/tags) de forma semi-visual.

No puede mostrar más de 26 ramas y commits a la vez.

Utiliza elementos de configuración multi-valorados showbranch.default si no se proporciona ningún <rev> o <glob> en la línea de comandos.

OPCIONES

<rev>

Expresión SHA-1 extendida arbitraria (ver gitrevisions(7)) que típicamente nombra una cabeza de rama o una etiqueta.

<glob>

Un patrón glob que coincide con nombres de ramas o etiquetas bajo refs/. Por ejemplo, si tienes muchas ramas de tema bajo refs/heads/topic, dar topic/* mostraría todas ellas.

-r, --remotes

Muestra las ramas de seguimiento remoto.

-a, --all

Muestra tanto las ramas de seguimiento remoto como las ramas locales.

--current

Con esta opción, el comando incluye la rama actual en la lista de revs a mostrar cuando no se proporciona en la línea de comandos.

--topo-order

Por defecto, las ramas y sus commits se muestran en orden cronológico inverso. Esta opción hace que aparezcan en orden topológico (es decir, los commits descendientes se muestran antes que sus padres).

--date-order

Esta opción es similar a --topo-order en el sentido de que ningún padre viene antes que todos sus hijos, pero de lo contrario, los commits se ordenan según su fecha de commit.

--sparse

Por defecto, la salida omite merges que son alcanzables desde una sola punta que se muestra. Esta opción los hace visibles.

--more=<n>

Normalmente el comando detiene la salida al mostrar el commit que es el ancestro común de todas las ramas. Esta bandera le dice al comando que vaya <n> commits comunes más allá de eso. Cuando <n> es negativo, muestra solo los <ref> dados, sin mostrar el árbol de ancestros de commits.

--list

Sinónimo de --more=-1

--merge-base

En lugar de mostrar la lista de commits, determina posibles bases de merge para los commits especificados. Todas las bases de merge estarán contenidas en todos los commits especificados. Esto es diferente de cómo git-merge-base(1) maneja el caso de tres o más commits.

--independent

Entre los <ref> dados, muestra solo aquellos que no pueden ser alcanzados desde ningún otro <ref>.

--no-name

No muestres cadenas de nombres para cada commit.

--sha1-name

En lugar de nombrar los commits usando el camino para alcanzarlos desde las cabezas (por ejemplo, "master~2" para referirse al abuelo de "master"), nómbralos con el prefijo único de sus nombres de objeto.

--topics

Muestra solo commits que NO están en la primera rama dada. Esto ayuda a rastrear ramas de tema ocultando cualquier commit que ya esté en la línea principal de desarrollo. Cuando se da "git show-branch --topics master topic1 topic2", esto mostrará las revisiones dadas por "git rev-list ^master topic1 topic2"

-g, --reflog[=<n>[,<base>]] [<ref>]

Muestra las <n> entradas de reflog más recientes para el ref dado. Si se proporciona <base>, <n> entradas hacia atrás desde esa entrada. <base> se puede especificar como recuento o fecha. Cuando no se proporciona ningún parámetro explícito de <ref>, por defecto es la rama actual (o HEAD si está desconectada).

--color[=<cuándo>]

Colorea el signo de estado (uno de estos: * ! + -) de cada commit correspondiente a la rama en la que se encuentra. El valor debe ser siempre (por defecto), nunca, o auto.

--no-color

Desactiva la salida en color, incluso cuando el archivo de configuración da la salida predeterminada para colorear. Igual que --color=never.

Ten en cuenta que las opciones --more, --list, --independent y --merge-base son mutuamente excluyentes.

SALIDA

Dadas N <ref>s, las primeras N líneas son la descripción de una línea de su mensaje de commit. La cabeza de rama a la que apunta $GIT_DIR/HEAD está prefijada con un asterisco * mientras que otras cabezas están prefijadas con un signo !.

Después de estas N líneas, se muestra un log de una línea para cada commit, con sangría de N lugares. Si un commit está en la I-ésima rama, el I-ésimo carácter de sangría muestra un signo +; de lo contrario, muestra un espacio. Los commits de merge se denotan con un signo -. Cada commit muestra un nombre corto que puede usarse como un SHA-1 extendido para nombrar ese commit.

El siguiente ejemplo muestra tres ramas, "master", "fixes" y "mhf":

$ git show-branch master fixes mhf
* [master] Add 'git show-branch'.
 ! [fixes] Introduce "reset type" flag to "git reset"
  ! [mhf] Allow "+remote:local" refspec to cause --force when fetching.
---
  + [mhf] Allow "+remote:local" refspec to cause --force when fetching.
  + [mhf~1] Use git-octopus when pulling more than one head.
 +  [fixes] Introduce "reset type" flag to "git reset"
  + [mhf~2] "git fetch --force".
  + [mhf~3] Use .git/remote/origin, not .git/branches/origin.
  + [mhf~4] Make "git pull" and "git fetch" default to origin
  + [mhf~5] Infamous 'octopus merge'
  + [mhf~6] Retire git-parse-remote.
  + [mhf~7] Multi-head fetch.
  + [mhf~8] Start adding the $GIT_DIR/remotes/ support.
*++ [master] Add 'git show-branch'.

Estas tres ramas se bifurcaron de un commit común, [master], cuyo mensaje de commit es "Add 'git show-branch'". La rama "fixes" añade un commit "Introduce "reset type" flag to "git reset"". La rama "mhf" añade muchos otros commits. La rama actual es "master".

EJEMPLOS

Si mantienes tus ramas principales inmediatamente debajo de refs/heads, y las ramas de tema en subdirectorios de ellas, tener lo siguiente en el archivo de configuración puede ayudar:

[showbranch]
        default = --topo-order
        default = heads/*

Con esto, git show-branch sin parámetros adicionales mostraría solo las ramas principales. Además, si te encuentras en tu rama de tema, esta también se muestra.

$ git show-branch --reflog="10,1 hour ago" --list master

muestra 10 entradas de reflog hacia atrás desde la punta hace 1 hora. Sin --list, la salida también muestra cómo estas puntas están relacionadas topológicamente entre sí.

CONFIGURACIÓN

Todo lo que está debajo de esta línea en esta sección se incluye selectivamente de la documentación de git-config(1). El contenido es el mismo que lo que se encuentra allí:

showBranch.default

El conjunto predeterminado de ramas para git-show-branch(1). Ver git-show-branch(1).
