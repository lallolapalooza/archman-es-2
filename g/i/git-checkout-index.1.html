Simplemente ejecutar git checkout-index no hace nada. Probablemente querías decir git checkout-index -a. Y si quieres forzarlo, quieres git checkout-index -f -a

.

La intuición no es el objetivo aquí. La repetibilidad lo es. La razón del comportamiento de "sin argumentos significa sin trabajo" es que desde scripts se supone que debes poder

hacer: 
$ find . -name '*.h'
-print0 | xargs -0 git
checkout-index -f --

lo que forzará que todos los archivos *.h existentes sean reemplazados con sus copias en caché. Si una línea de comandos vacía implicara "todos", esto forzaría la actualización de todo en el índice, que no era el propósito. Pero como git checkout-index acepta --stdin, sería más rápido

usar: 
$ find . -name '*.h'
-print0 | git checkou
t-index -f -z --stdin

El -- es solo una buena idea cuando sabes que el resto serán nombres de archivo; evitará problemas con un nombre de archivo como, por ejemplo, -a. Usar -- es probablemente una b

uena política
en scripts.

USANDO --TEMP O

--STAGE=ALL

Cuando se usa --temp (o se implica con --stage=all) git checkout-index creará un archivo temporal para cada entrada del índice que se esté extrayendo. El índice no se actualizará con la información de estado. Estas opciones pueden ser útiles si el llamador necesita todos los escenarios de todas las entradas sin fusionar para que los archivos sin fusionar puedan ser procesados por una herramienta de fusión

externa.

Se escribirá un listado en la salida estándar que proporciona la asociación de los nombres de archivo temporales con los nombres de ruta rastreados. El formato del listado tiene dos

variaciones:
1.nombretmp TAB ruta RS

El primer formato es el que se usa cuando --stage se omite o no es --stage=all. El campo nombretmp es el nombre del archivo temporal que contiene el contenido del arc

hivo y ruta es el nombre de ruta rastreado en e
l índice. Solo se muestran las entradas solicitadas.
2.escenario1tmp SP escenario2tmp SP escenario3tmp TAB ruta RS

El segundo formato es el que se usa cuando --stage=all. Los tres campos temporales de escenario (escenario1tmp, escenario2tmp, escenario3tmp) listan el nombre del archivo temporal si hay una entr

ada de escenario en el índice o . si no hay entrada de escenario. Las rutas
que solo tienen una entrada de escenario 0 siempre se omitirán de la salida.

En ambos formatos RS (el separador de registro) es un salto de línea de forma predeterminada pero será el byte nulo si se pasó -z en la línea de comandos. Los nombres de los archivos temporales siempre son cadenas seguras; nunca contendrán separadores de directorio ni caracteres de espacio en blanco. El campo de ruta siempre es relativo al directorio actual y los nombres de los archivos temporales siempre son relativos al directorio de nivel

superior.

Si el objeto que se está copiando a un archivo temporal es un enlace sim

bólico, el contenido del enlace se escribirá en un archivo normal. Corr
esponde al usuario final o a la Porcelain hacer uso de esta información.
