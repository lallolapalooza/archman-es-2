NOMBRE

git-request-pull - Genera un resumen de los cambios pendientes

SINOPSIS

git request-pull [-p] <inicio> <URL> [<fin>]

DESCRIPCIÓN

Genera una solicitud pidiendo a tu proyecto upstream que extraiga cambios en su árbol. La solicitud, impresa en la salida estándar, comienza con la descripción de la rama, resume los cambios e indica desde dónde se pueden extraer.

Se espera que el proyecto upstream tenga el commit nombrado por <inicio> y la salida le pide que integre los cambios que has hecho desde ese commit, hasta el commit nombrado por <fin>, visitando el repositorio nombrado por <URL>.

OPCIONES

-p

Incluye el texto del parche en la salida.

<inicio>

Commit desde el que empezar. Esto nombra un commit que ya está en el historial del upstream.

<URL>

La URL del repositorio del que se extraerá.

<fin>

Commit hasta el que terminar (por defecto es HEAD). Esto nombra el commit en la punta del historial que pides que se extraiga.

Cuando el repositorio nombrado por <URL> tiene el commit en la punta de una referencia que es diferente de la referencia que tienes localmente, puedes usar la sintaxis <local>:<remota>, para tener su nombre local, dos puntos :, y su nombre remoto.

EJEMPLOS

Imagina que has basado tu trabajo en tu rama master encima del lanzamiento v1.0 y quieres que se integre en el proyecto. Primero empujas ese cambio a tu repositorio público para que otros lo vean:

git push https://git.ko.xz/project master

Luego, ejecutas este comando:

git request-pull v1.0 https://git.ko.xz/project master

lo que producirá una solicitud al upstream, resumiendo los cambios entre el lanzamiento v1.0 y tu master, para extraerlo desde tu repositorio público.

Si has empujado tu cambio a una rama cuyo nombre es diferente del que tienes localmente, por ejemplo:

git push https://git.ko.xz/project master:for-linus

entonces puedes pedir que se extraiga con

git request-pull v1.0 https://git.ko.xz/project master:for-linus
