Un objeto commit puede tener cualquier número de padres. Con exactamente un padre, es un commit ordinario. Tener más de un padre convierte el commit en una fusión entre varias líneas de historial. Los commits iniciales (raíz) no tienen padres. Mientras que un tree representa un estado particular de directorio de un directorio de trabajo, un commit representa ese estado en el "tiempo", y explica cómo llegar allí. Normalmente un commit identificaría un nuevo estado "HEAD", y aunque a Git no le importa dónde guarda la nota sobre ese estado, en la práctica tendemos a escribir simplemente el resultado en el archivo al

. DISCUSIÓN Git es hasta cierto punto agnóstico en cuanto a la codificación de caracteres. •El contenido de los objetos blob son secuencias de bytes sin interpretar. No hay traducción de codificación a nivel del núcleo. •Los nombres de ruta están codificados en la forma de normalización C de UTF-8. Esto se aplica a los objetos tree, el archivo índice, los nombres de referencia, así como los nombres de ruta en argumentos de línea de comandos,
variables de
entorno y archivos
de configuración (

Tenga en cuenta que Git a nivel del núcleo trata los nombres de ruta simplemente como secuencias de bytes no NUL, no hay conversiones de codificación de nombres de ruta (excepto en Mac y Windows). Por lo tanto, usar nombres de ruta no ASCII funcionará en su mayoría incluso en plataformas y sistemas de archivos que usan codificaciones ASCII extendidas heredadas. Sin embargo, los repositorios creados en tales sistemas no funcionarán correctamente en sistemas basados en UTF-8 (por ejemplo, Linux, Mac, Windows) y viceversa. Además, muchas herramientas basadas en Git simplemente asumen que los nombres de ruta son UTF-8 y fallarán al mostrar otras codificaciones correctamente. •Los mensajes de registro de commits típicamente están codificados en UTF-8, pero también se admiten otras codificaciones ASCII extendidas. Esto incluye ISO-8859-x, CP125x y muchas otras, pero no UTF-16/32, EBCDIC y codificaciones multibyte CJK (GBK, Shift-JIS, Big5, EUC-x, CP9xx etc.). Aunque

fomentamos que los mensajes de registro de commits estén codificados en UTF-8, tanto el núcleo como Git Porcelain est

án diseñados para no forzar UTF-8 en los proyectos. Si todos los participantes de un proyecto en particular encuentra
n más conveniente usar codificaciones heredadas, Git no lo prohíbe. Sin embargo, hay algunas cosas a tener en cuenta.
