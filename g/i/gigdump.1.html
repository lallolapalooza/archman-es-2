NOMBRE

gigdump - Listar información sobre un archivo Gigasampler (.gig).

SINOPSIS

gigdump [OPCIONES] ARCHIVO_GIG

DESCRIPCIÓN

Por defecto, imprime una lista de todas las muestras disponibles, scripts de instrumentos en tiempo real e instrumentos dentro de un archivo Gigasampler (.gig), junto con información detallada sobre sus propiedades y configuraciones.

OPCIONES

 ARCHIVO_GIG
nombre del archivo Gigasampler
 --instrument-names
Solo listar nombres de instrumentos y su número de índice.
 --rebuild-checksums
Reconstruir la tabla de sumas de verificación para todas las muestras. Lea la descripción de la opción  --verify para más detalles sobre las sumas de verificación de muestras en general. Por lo general, solo necesita usar  --rebuild-checksums en caso de que la tabla de sumas de verificación CRC de las muestras estuviera dañada. La opción  --verify le indicará si ese es realmente el caso y le sugerirá usar  --rebuild-checksums para reparar la tabla en tales casos. Si solo muestras individuales resultaron dañadas, probablemente querrá reemplazar solo esas muestras dañadas con gigedit(1) por ejemplo. Lea la descripción de  --verify para conocer las razones para hacerlo. Al usar  --rebuild-checksums se regenerarán todas las sumas de verificación de todas las muestras. Por lo tanto, debe verificar manualmente todas las muestras una vez después de usar esta opción. Es decir, usando sus oídos, o exportando las muestras, pero no usando la opción  --verify. Porque esta última no puede identificar muestras dañadas que se dañaron antes de que se regenerara toda la tabla de sumas de verificación.
 -v
Imprimir versión y salir.
 --verify
Verificar la integridad de los datos de onda crudos de todas las muestras e imprimir el resultado de esta verificación. Para todas las muestras de un archivo gig, se almacena una suma de verificación CRC32 correspondiente junto a sus datos de onda crudos cada vez que se realiza un cambio consciente en los datos de onda. Al llamar a gigdump con esta opción, se escanean todas las muestras y se comparan con sus sumas de verificación existentes para detectar cualquier daño en muestras individuales. gigdump lista las muestras individuales dañadas en este caso. Dado que esencialmente el archivo completo tiene que ser leído, esto puede llevar mucho tiempo y, por lo tanto, esta verificación no se realiza por defecto, es decir, cada vez que se carga un archivo gig para uso regular, por ejemplo. En consecuencia, puede usar  --verify de vez en cuando para verificar explícitamente si sus archivos gig se han dañado por alguna razón, es decir, después de modificarlos con un editor de instrumentos como gigedit(1). En caso de que se encontraran muestras dañadas, puede reemplazar esas muestras dañadas con gigedit(1). Al hacerlo, solo se actualizarán las sumas de verificación de las muestras reemplazadas. Todas las demás sumas de verificación permanecen intactas. Es por eso que este enfoque se recomienda en lugar de usar  --rebuild-checksums en tales casos.
