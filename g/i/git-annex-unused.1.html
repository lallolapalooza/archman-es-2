NOMBRE

git-annex-unused - buscar contenido de archivo no utilizado

SINOPSIS

git annex unused

DESCRIPCIÓN

Comprueba el annex para ver datos que no corresponden a ningún archivo presente en ninguna etiqueta o rama, o en el índice de git, e imprime una lista numerada de los datos.

Después de ejecutar este comando, puedes usar la opción --unused con muchos otros comandos de git-annex para operar sobre todos los datos no utilizados que se encontraron.

Por ejemplo, para mover todos los datos no utilizados a origin:


git annex unused; git annex move --unused --to origin

OPCIONES

--fast
Solo muestra archivos temporales y defectuosos no utilizados.
--from=repositorio
Comprueba si hay datos no utilizados que se encuentran en un repositorio.
El repositorio debe especificarse utilizando el nombre de un remoto configurado, o el UUID o la descripción de un repositorio.
--used-refspec=+ref:-ref
Por defecto, se considera utilizado cualquier dato que utilice el índice de git, o al que apunten las ramas del repositorio de git. Si solo deseas utilizar algunas ramas, puedes usar esta opción para especificar cuáles usar. Los datos que no estén en las ramas especificadas (y no utilizados por el índice) se considerarán entonces no utilizados.
Consulta FORMATO REFSPEC a continuación para obtener detalles sobre el formato de esta configuración.
La configuración de git annex.used-refspec se puede usar para configurar esto de una manera más permanente.
--json
Habilita la salida JSON. Está pensado para ser analizado por programas que utilizan git-annex.
--json-error-messages
Los mensajes que normalmente se emitirían al error estándar se incluyen en el JSON en su lugar.
También se pueden usar las opciones generales de git-annex(1).

FORMATO REFSPEC

El formato refspec para --used-refspec y annex.used-refspec es una lista separada por dos puntos de adiciones y eliminaciones de ramas. Un ejemplo algo forzado:


+refs/heads/*:+HEAD^:+refs/tags/*:-refs/tags/etiqueta-antigua:reflog

Esto agrega todas las ramas refs/heads/, así como la versión anterior de HEAD. También agrega todas las etiquetas, excepto etiqueta-antigua. Y agrega todas las ramas del reflog.

El comportamiento predeterminado es equivalente a --used-refspec=+refs/*:+HEAD

El refspec se procesa comenzando con un conjunto vacío de ramas, y recorriendo la lista en orden de izquierda a derecha.

Cada + que usa un comodín coincide con todas las ramas relevantes (un subconjunto de git show-ref) y todas las ramas coincidentes se agregan al conjunto. Por ejemplo, "+refs/remotes/*" agrega todas las ramas remotas.

Cada + sin comodín agrega el valor literal al conjunto. Por ejemplo, "+HEAD^" agrega "HEAD^".

Cada - se compara con el conjunto de ramas acumulado hasta el momento. Cualquier rama con nombres que coincidan se elimina del conjunto.

"reflog" agrega todas las ramas del reflog. Esto hará que las versiones anteriores de los archivos no se consideren no utilizadas hasta que la rama expire del reflog (por defecto durante 90 días). Ten en cuenta que esto puede hacer que git-annex unused tarde algún tiempo en completarse, si necesita comprobar cada rama del reflog.
