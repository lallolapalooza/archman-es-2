AJUSTES DE OPCIONES AVANZADAS

Los comandos que admiten el analizador de opciones mejorado le permiten agregar opciones cortas. Esto significa que puede usar, por ejemplo, git rm -rf o git clean -fdx.

Abreviar opciones largas

Los comandos que admiten el analizador de opciones mejorado aceptan un prefijo único de una opción larga como si estuviera completamente escrito, pero úselo con precaución. Por ejemplo, git commit --amen se comporta como si hubiera escrito git commit --amend, pero eso solo es cierto hasta que una versión posterior de Git introduzca otra opción que comparta el mismo prefijo, por ejemplo, la opción git commit --amenity.

Separar argumento de la opción

Puede escribir el parámetro de opción obligatorio para una opción como una palabra separada en la línea de comandos. Eso significa que todos los siguientes usos funcionan:

$ git foo --long-opt=Arg
$ git foo --long-opt Arg
$ git foo -oArg
$ git foo -o Arg

Sin embargo, esto NO está permitido para los modificadores con un valor opcional, donde se debe usar la forma pegada:

$ git describe --abbrev HEAD     # correcto
$ git describe --abbrev=10 HEAD  # correcto
$ git describe --abbrev 10 HEAD  # NO ES LO QUE QUERÍAS

Opciones mágicas de nombre de archivo

Las opciones que toman un nombre de archivo permiten el prefijo :(opcional). Por ejemplo:

git commit -F :(optional)COMMIT_EDITMSG
# si COMMIT_EDITMSG no existe, lo anterior es equivalente a
git commit

Al igual que con los valores de configuración, si el archivo nombrado no se encuentra, Git se comporta como si la opción no se hubiera dado en absoluto. Vea "Valores" en git-config(1).

NOTAS SOBRE OPCIONES CONFUSAS FRECUENTEMENTE

Muchos comandos que pueden trabajar en archivos en el árbol de trabajo y/o en el índice pueden tomar las opciones --cached y/o --index. A veces la gente piensa incorrectamente que, dado que el índice se llamaba originalmente caché, estos dos son sinónimos. No lo son; estas dos opciones significan cosas muy diferentes.

•La opción --cached se utiliza para pedir a un comando que normalmente trabaja con archivos en el árbol de trabajo que trabaje solo con el índice. Por ejemplo, git grep, cuando se usa sin un commit para especificar desde qué commit buscar cadenas, normalmente trabaja con archivos en el árbol de trabajo, pero con la opción --cached, busca cadenas en el índice.
•La opción --index se utiliza para pedir a un comando que normalmente trabaja con archivos en el árbol de trabajo que también afecte al índice. Por ejemplo, git stash apply normalmente fusiona los cambios registrados en una entrada de stash en el árbol de trabajo, pero con la opción --index, también fusiona los cambios en el índice.

El comando git apply se puede usar con --cached y --index (pero no al mismo tiempo). Normalmente el comando solo afecta a los archivos en el árbol de trabajo, pero con --index, aplica parches tanto a los archivos como a sus entradas de índice, y con --cached, modifica solo las entradas de índice.

Vea también https://lore.kernel.org/git/7v64clg5u9.fsf@assigned-by-dhcp.cox.net/ y https://lore.kernel.org/git/7vy7ej9g38.fsf@gitster.siamese.dyndns.org/ para más información.

Algunos otros comandos que también trabajan con archivos en el árbol de trabajo y/o en el índice pueden tomar --staged y/o --worktree.

•--staged es exactamente como --cached, que se usa para pedir a un comando que trabaje solo en el índice, no en el árbol de trabajo.
•--worktree es lo opuesto, para pedir a un comando que trabaje solo en el árbol de trabajo, no en el índice.
•Las dos opciones se pueden especificar juntas para pedir a un comando que trabaje tanto en el índice como en el árbol de trabajo.
