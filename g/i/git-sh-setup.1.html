GIT-SH-SETUP(1) Manual de Git GIT-SH-SETUP(1)

NOMBRE

git-sh-setup - Código común de configuración de scripts de shell de Git

SINOPSIS

. "$(git --exec-path)/git-sh-setup"

DESCRIPCIÓN

Este no es un comando que el usuario final deba ejecutar. Nunca. Esta documentación está destinada a personas que estudian los scripts tipo Porcelain o que están escribiendo nuevos.

El scriptlet git sh-setup está diseñado para ser incluido (usando .) por otros scripts de shell para configurar algunas variables que apuntan a los directorios normales de Git y algunas funciones auxiliares de shell.

Antes de incluirlo, su script debe configurar algunas variables; USAGE (y LONG_USAGE, si existe) se utiliza para definir el mensaje proporcionado por la función de shell usage(). SUBDIRECTORY_OK puede establecerse si el script puede ejecutarse desde un subdirectorio del árbol de trabajo (algunos comandos no pueden).

El scriptlet establece las variables de shell GIT_DIR y GIT_OBJECT_DIRECTORY, pero no las exporta al entorno.

FUNCIONES

die

sale después de emitir el mensaje de error proporcionado al flujo de error estándar.

usage

sale con el mensaje de uso.

set_reflog_action

establece la variable de entorno GIT_REFLOG_ACTION a una cadena dada (típicamente el nombre del programa) a menos que ya esté establecida. Cada vez que el script ejecuta un comando git que actualiza referencias, se crea una entrada de reflog utilizando el valor de esta cadena para dejar constancia de qué comando actualizó la referencia.

git_editor

ejecuta un editor de la elección del usuario (GIT_EDITOR, core.editor, VISUAL o EDITOR) en un archivo dado, pero falla si no se especifica ningún editor y la terminal es tonta.

is_bare_repository

emite true o false al flujo de salida estándar para indicar si el repositorio es un repositorio desnudo (es decir, sin un árbol de trabajo asociado).

cd_to_toplevel

ejecuta chdir al nivel superior del árbol de trabajo.

require_work_tree

verifica si el directorio actual está dentro del árbol de trabajo del repositorio, y de lo contrario, falla.

require_work_tree_exists

verifica si el árbol de trabajo asociado con el repositorio existe, y de lo contrario, falla. A menudo se hace antes de llamar a cd_to_toplevel, lo cual es imposible de hacer si no hay un árbol de trabajo.

require_clean_work_tree <acción> [<sugerencia>]

verifica que el árbol de trabajo y el índice asociados con el repositorio no tengan cambios no confirmados en archivos rastreados. De lo contrario, emite un mensaje de error de la forma Cannot <acción>: <razón>. <sugerencia>, y falla. Ejemplo: 
require_clean_work_tree rebase "Por favor, confírmalos o agrégalos a la pila."

get_author_ident_from_commit

emite código para usar con eval para establecer las variables GIT_AUTHOR_NAME, GIT_AUTHOR_EMAIL y GIT_AUTHOR_DATE para un commit dado.

create_virtual_base

modifica el primer archivo para que solo permanezcan las líneas en común con el segundo archivo. Si hay material común insuficiente, entonces el primer archivo se deja vacío. El resultado es adecuado como entrada de base virtual para una fusión de 3 vías.
