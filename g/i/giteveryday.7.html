DESARROLLADOR INDIVIDUAL

(AUTÓNOMO)

Un desarrollador individual autónomo no intercambia parches con otras personas, y trabaja solo en un solo repositorio, usando los siguientes

comandos.
•git-init(1) para crear un nuevo
repositorio.
•git-log(1) para ver qué
sucedió.
•git-switch(1) y git-branch(1) para cambiar de
rama.
•git-add(1) para gestionar el archivo
índice.
•git-diff(1) y git-status(1) para ver en qué estás
trabajando.
•git-commit(1) para avanzar la rama
actual.
•git-restore(1) para deshacer
cambios.
•git-merge(1) para fusionar entre ramas
locales.
•git-rebase(1) para mantener ramas de
temas.
•git-tag(1) para marcar un punto
conocido.

DESARROLLADOR INDIVIDUAL

(PARTICIPANTE)

Un desarrollador que trabaja como participante en un proyecto de grupo necesita aprender a comunicarse con otros, y usa estos comandos además de los necesarios para un desarrollador

autónomo.
•git-clone(1) desde el upstream para preparar tu repositorio
local.
•git-pull(1) y git-fetch(1) desde "origin" para mantenerte al día con el
upstream.
•git-push(1) al repositorio compartido, si adoptas el flujo de trabajo de repositorio compartido estilo
CVS.
•git-format-patch(1) para preparar el envío por correo electrónico, si adoptas el flujo de trabajo de foro público estilo kernel de
Linux.
•git-send-email(1) para enviar tu correo electrónico sin corrupción por tu
MUA.
•git-request-pull(1) para crear un resumen de cambios para que tu upstream haga
pull.

INTEGRADO

R

Una persona bastante central que actúa como integrador en un proyecto de grupo recibe cambios realizados por otros, los revisa e integra y publica el resultado para que otros lo usen, usando estos comandos además de los necesarios para los

participantes.

Esta sección también puede ser usada por aquellos que responden a git request-pull o pull-request en GitHub (www.github.com) para integrar el trabajo de otros en su historial. Un subteniente de un repositorio actuará tanto como participante como

integrador.
•git-am(1) para aplicar parches enviados por correo electrónico de tus
colaboradores.
•git-pull(1) para fusionar desde tus tenientes de
confianza.
•git-format-patch(1) para preparar y enviar sugerencias alternativas a los
colaboradores.
•git-revert(1) para deshacer confirmaciones (commits)
erróneas.
•git-push(1) para publicar la última versión de desarrollo (bleeding edge)
.

NAME

                    
giteveryday — everyday Git commands

                

                

                    
SYNOPSIS

                    

                        git add, git commit, git push, git pull, git fetch, git merge, git clone, git log, git diff, git status, git branch, git checkout, git reset, git rm, git mv
                    

                

                

                    
DESCRIPTION

                    
This is a gentle introduction to Git commands for beginners. It is not intended to be exhaustive, but rather to provide a basic understanding of how to use Git on a day-to-day basis.

                    
The goal is to make Git approachable for users who may not have prior experience with version control systems.

                

                

                    
INDIVIDUAL DEVELOPER (STANDALONE)

                    
If you are working on a project alone, you can use Git to keep track of your changes. This is useful for reverting to previous versions or for experimenting with new features without fear of losing your work.

                    
    
                        
  • 
                            
    Initialize a new repository:
    
                            
    git init
    
                        
    • 
                        
  • 
                            
    Add files to be tracked:
    
                            
    git add <file>
    
                        
    • 
                        
  • 
                            
    Commit your changes:
    
                            
    git commit -m "Your commit message"
    
                        
    • 
                        
  • 
                            
    View your commit history:
    
                            
    git log
    
                        
    • 
                    

                

                

                    
INDIVIDUAL DEVELOPER (PARTICIPANT)

                    
If you are part of a team, Git allows you to collaborate with others by managing different versions of the project.

                    
    
                        
  • 
                            
    Clone an existing repository:
    
                            
    git clone <repository_url>
    
                        
    • 
                        
  • 
                            
    Fetch changes from the remote repository:
    
                            
    git fetch
    
                        
    • 
                        
  • 
                            
    Pull changes from the remote repository (fetch + merge):
    
                            
    git pull
    
                        
    • 
                        
  • 
                            
    Push your local commits to the remote repository:
    
                            
    git push
    
                        
    • 
                        
  • 
                            
    Merge changes from another branch:
    
                            
    git merge <branch_name>
    
                        
    • 
                    

                

                

                    
INTEGRATOR

                    
An integrator is responsible for merging changes from different developers into the main project line.

                    
    
                        
  • 
                            
    Pull all the latest changes:
    
                            
    git pull --all
    
                        
    • 
                        
  • 
                            
    Create a new branch for integration:
    
                            
    git checkout -b integration-branch
    
                        
    • 
                        
  • 
                            
    Merge changes from individual branches:
    
                            
    git merge developer-branch
    
                        
    • 
                        
  • 
                            
    Resolve any merge conflicts.
    
                        
    • 
                        
  • 
                            
    Commit the merged changes:
    
                            
    git commit
    
                        
    • 
                        
  • 
                            
    Push the integration branch to the remote repository:
    
                            
    git push origin integration-branch
    
                        
    •
