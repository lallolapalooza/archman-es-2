DESCRIPCIÓ

N

Este comando simula el comportamiento de git-annex en una red de repositorios, determinando qué archivos llegarían a qué repositorios según la configuración de contenido preferido, numcopies, nivel de confianza,

etc.

La entrada para la simulación es un archivo sim, y/o comandos sim que se ejecutan después de iniciarlo. Estos tienen la forma "git annex sim command" con el comando en el mismo formato utilizado en el archivo sim (ver la lista de comandos sim más abajo). Por ejemplo, "git annex sim step 1" ejecuta la simulación un

paso.

La simulación mantiene un registro mientras se ejecuta, que contiene toda la entrada de la simulación, así como las acciones realizadas en la simulación, y los resultados de la simulación. Use "git-annex sim show" para mostrar el registro. Esto permite volver a ejecutar la misma simulación más tarde, así como analizar los resultados de la

simulación.

Use "git annex sim end" para finalizar la simulación y

limpiar.

Como conveniencia, para ejecutar un sim desde un archivo y luego detenerlo, use "git-annex sim run". Si hay un problema al ejecutar el sim, se mostrará antes de que se

detenga.

Tenga en cuenta que interrumpir este comando mientras se está ejecutando puede dejar la simul

ación en un estado inconsistente. Y ejecutar múltiples comandos sim al mismo tiempo también pu
ede, aunque es seguro ejecutar "git annex sim visit" mientras se ejecutan otros comandos sim.

comentarios.

COMANDOS

SIM

Este es el conjunto completo de comandos que se pueden usar en el archivo sim así como pasar a "git annex sim" mientras una simulación está en

ejecución.
init
name
Inicializa un repositorio simulado, dándole un nombre que se usará en la
simulación.
initremote
name
Inicializa un remoto especial
simulado.
use name here|remote|description|u
uid
Usa un repositorio existente en la simulación, con su configuración existente (nivel de confianza, grupos, contenido preferido y requerido, maxsize, y la configuración groupwanted de sus grupos)
.
El repositorio recibe un nombre para los fines de la simulación. El repositorio a usar se puede especificar por nombre de remoto, uuid, etc. Ejemplo: "use myrepo
here"
visit repo
[command]
Ejecuta el comando de shell especificado dentro del repositorio simulado, y espera a que
salga.
Cuando no se especifica un comando de shell, ejecuta un shell
interactivo.
El comando se ejecuta en un repositorio git cuya rama git-annex contiene el estado de ese repositorio simulado. Esto permite ejecutar cualquier comando git-annex, como git-annex whereis para examinar el estado de la simulación. Debería evitar hacer cambios en el estado de
git-annex.
connect repo [<-|->|<->] repo [.
..]
Añade una conexión entre dos o más repositorios. La flecha indica en qué dirección corre la conexión, y puede ser bidireccional. Por ejemplo, "connect foo -> bar" hace que bar sea un remoto de foo, mientras que "connect foo <-> bar" hace que cada uno sea el remoto del otro. Una cadena de conexiones puede extenderse a muchos repositorios, por ejemplo "connect foo -> bar -> baz ->
foo"
disconnect repo [<-|->|<->] repo [.
..]
Elimina conexiones entre
repositorios.
Por ejemplo, "disconnect foo -> bar" hace que foo ya no tenga bar como
remoto.
addtree repo
expression
Añade archivos annexed del repositorio git a la simulación haciéndolos estar presentes en el repositorio
especificado.
La expresión es una expresión de contenido preferido (ver git-annex-preferred-content(1)) que especifica qué archivos annexed añadir. Aunque es posible inclir todos o un gran número de archivos de esta manera, tenga en cuenta que a menudo es más eficiente simular una pequeña cantidad de archivos que tienen las propiedades particulares que le
interesan.
Cuando se ejecuta en un subdirectorio del repositorio, solo se consideran para la adición los archivos en ese
subdirectorio.
Esto se puede usar con los mismos archivos más de una vez, para hacer que múltiples repositorios en la simulación contengan los mismos
archivos.
add filename size repo [repo .
..]
Crea un archivo annexed simulado con el nombre de archivo y tamaño especificados, que está presente en el repositorio, o repositorios,
especificado.
El tamaño se puede especificar usando cualquier unidad usual, por ejemplo "10mb" o "3.
3terabytes"
El nombre de archivo no puede contener un
espacio.
Esto prepara un archivo en el índice, de modo que se puedan usar comandos git-annex regulares para consultar el estado del archivo annexed simulado. Si ya existe un archivo annexed con ese nombre, será sobrescrito con el nuevo
archivo.
Tenga en cuenta que la simulación no cubre la adición de archivos en conflicto a diferentes repositorios. Los archivos en la simulación son los mismos en todos los repositorios
simulados.
addmulti N suffix minsize maxsize repo [repo .
..]
Añade múltiples archivos annexed simulados, con tamaños aleatorios en el rango entre minsize y
maxsize.
Los archivos se nombran combinando el número, que comienza en 1 y sube hasta N, con el
sufijo.
Por
ejemplo:

addmulti 100 testfile.jpg 100kb 10mb
foo
Eso añade archivos nombrados "1testfile.jpg", 2testfile.jpg",
etc.
Tenga en cuenta que añadir un gran número de archivos a la simulación puede ralentizarla y hacer que use mucha
memoria.
step
N
Ejecuta la simulación hacia adelante este número de
pasos.
En cada paso de la simulación, un archivo se transfiere o se elimina, según el contenido preferido y otra
configuración.
Si no hay más archivos que puedan transferirse o eliminarse según la configuración actual, se mostrará un mensaje para indicar que la simulación se ha
estabilizado.
Esto también simula git pull y git push siendo ejecutados en cada repositorio, según sea necesario para encontrar cosas adicionales que
hacer.
stepstable
N
Ejecuta la simulación hacia adelante este número de pasos, en cuyo punto se espera que se haya
estabilizado.
Si la simulación no se estabiliza, el comando saldrá con un estado de salida distinto de
cero.
action repo getwanted
remote
Simula que el repositorio obtiene los archivos que desea del
remoto.
action repo
dropunwanted
Simula que el repositorio descarta los archivos que no desea, cuando es capaz de verificar que existen suficientes copias en los
remotos.
action repo dropunwantedfrom
remote
Simula que el repositorio descarta archivos del remoto que el remoto no desea, cuando es capaz de verificar que existen suficientes
copias.
action repo sendwanted
remote
Simula que el repositorio envía los archivos que el remoto
desea.
action repo gitpush
remote
Simula que el repositorio envía (push) la rama git-annex al
remoto.
action repo gitpull
remote
Simula que el repositorio recibe (pull) la rama git-annex del
remoto.
action repo pull
remote
Simula el equivalente a git-annex-pull(1), combinando las acciones gitpull, getwanted y
dropunwanted.
action repo push
remote
Simula el equivalente a git-annex-push(1) combinando las acciones sendwanted, dropunwantedfrom y
gitpush.
action repo sync
remote
Simula el equivalente a git-annex-sync(1) combinando las acciones gitpull, getwanted, sendwanted, dropunwanted y
gitpush.
action [...] while action [.
..]
Simula la ejecución de las dos acciones de forma concurrente. Aunque la simulación solo simula realmente que una cosa ocurre a la vez, cuando las acciones operan cada una en múltiples archivos, se intercalarán
aleatoriamente.
Se pueden combinar de esta manera cualquier número de
acciones.
Por
ejemplo:

action foo dropunwanted while action bar getwanted
foo
En este ejemplo, bar puede o no obtener un archivo antes de que foo lo
descarte.
seed
N
Establece la semilla aleatoria a un número determinado. Usar esto debería hacer que los resultados de la simulación sean deterministas. El archivo sim de salida siempre incluye la semilla aleatoria, por lo que puede usarse para reproducir la
simulación.
present repo
file
Esto indica el estado esperado de la simulación en este punto. El repositorio debería contener el contenido del archivo. Si no lo hace, la discrepancia se indicará en la salida de error estándar, y el comando git-annex sim terminará eventualmente con un código de salida distinto de
cero.
Esto se añade al archivo sim de salida a medida que se ejecuta la
simulación.
notpresent repo
file
Esto indica el estado esperado de la simulación en este punto. El repositorio no debería contener el contenido del archivo. Si lo hace, la discrepancia se indicará en la salida de error estándar, y el comando git-annex sim terminará eventualmente con un código de salida distinto de
cero.
Esto se añade al archivo sim de salida a medida que se ejecuta la
simulación.
numcopies
N
Establece el número deseado de copias. Esto es equivalente a git-annex-numcopies(1)
.
Tenga en cuenta que la simulación no usa otra configuración que establezca numcopies, como los archivos .
gitattributes.
mincopies
N
Establece el número mínimo de copias. Esto es equivalente a git-annex-mincopies(1)
.
trustlevel repo trusted|untrusted|semitrusted|d
ead
Establece el nivel de confianza del repositorio. Esto es equivalente a git-annex-trust(1), git-annex-untrust(1),
etc.
wanted repo
expression
Configura el contenido preferido de un repositorio. Esto es equivalente a git-annex-wanted(1)
.
required repo
expression
Configura el contenido requerido de un repositorio. Esto es equivalente a git-annex-required(1)
.
groupwanted group
expression
Configura la expresión groupwanted. Esto es equivalente a git-annex-groupwanted(1)
.
randomwanted repo term.
..
Configura el contenido preferido de un repositorio a una expresión aleatoria generada combinando una selección aleatoria de los términos proporcionados con "and", "or" y
"not".
Por ejemplo, "randomwanted foo exclude=*.x include=*.x largerthan=100kb" podría generar una expresión como "exclude=*.x or not largerthan=100kb and include=*.x" o podría generar una expresión como "include=*.x and exclude=*.
x".
randomrequired repo term.
..
Configura el contenido requerido de un repositorio a una expresión
aleatoria.
randomgroupwanted group term.
..
Configura el groupwanted a una expresión
aleatoria.
group repo
group
Añade un repositorio a un grupo. Esto es equivalente a git-annex-group(1)
.
ungroup repo
group
Elimina un repositorio de un grupo. Esto es equivalente a git-annex-ungroup(1)
.
metadata filename
expression
Cambia los metadatos del archivo simulado. La expresión está en el mismo formato que la opción --set del comando git-annex-metadata. Por ejemplo: metadata foo
year=2025
maxsize repo
size
Configura el tamaño máximo de un repositorio. Esto es equivalente a git-annex-maxsize(1)
.
rebalance
[on|off]
Establecer "rebalance on" es equivalente a pasar la opción --rebalance a git-annex. Establecer "rebalance off" deshace
eso.
Por
ejemplo:

maxsize foo 1tb
rebalance on
step 100
rebalance
off
clusternode name
repo
Simula que un repositorio es un nodo de un clúster, al cual se puede hacer referencia usando el nombre
especificado.
En lugar de simular una puerta de enlace de clúster como una entidad separada, cualquier conexión a un nodo de clúster con ese nombre se trata como el acceso a ese repositorio a través de la misma puerta de enlace del
clúster.
Dado que una puerta de enlace de clúster conoce todos los cambios que se hacen a los nodos a través de ella, cada repositorio que tenga una conexión a un nodo de clúster conocerá inmediatamente los cambios hechos a través de ese nodo, sin necesitar un git pull
simulado.
Para simular que un repositorio es un nodo
de más de un clúster, o detrás de múltiples
puertas de enlace en el mismo clúster, use
este comando para darle múltiples nombres.
