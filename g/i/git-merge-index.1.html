NOMBRE

git-merge-index - Ejecuta una fusión para archivos que necesitan ser fusionados

SINOPSIS

git merge-index [-o] [-q] <programa-de-fusion> (-a | ( [--] <archivo>... ) )

DESCRIPCIÓN

Esto busca en el índice el(los) <archivo>(s) y, si hay alguna entrada de fusión, pasa el hash SHA-1 para esos archivos como argumentos 1, 2, 3 (argumento vacío si no hay archivo), y <archivo> como argumento 4. Los modos de archivo para los tres archivos se pasan como argumentos 5, 6 y 7.

OPCIONES

--

No interpretes más argumentos como opciones.

-a

Ejecuta la fusión contra todos los archivos en el índice que necesiten ser fusionados.

-o

En lugar de detenerse en la primera fusión fallida, hazlas todas de una vez. Continúa con la fusión incluso cuando las fusiones anteriores devolvieron errores, y solo devuelve el código de error después de todas las fusiones.

-q

No te quejes de un programa de fusión fallido (un fallo del programa de fusión generalmente indica conflictos durante la fusión). Esto es para porcelanas que podrían querer emitir mensajes personalizados.

Si se llama a git merge-index con múltiples <archivo>s (o -a) entonces los procesa en orden, deteniéndose solo si la fusión devuelve un código de salida distinto de cero.

Típicamente esto se ejecuta con un script que llama a la imitación de Git del comando merge del paquete RCS.

Un script de ejemplo llamado git merge-one-file está incluido en la distribución.

¡ALERTA ALERTA ALERTA! El orden de los objetos de fusión de Git es diferente del orden de los objetos de fusión del programa merge de RCS. En el orden anterior, el original está primero. Pero el orden de los argumentos para el programa de fusión de 3 vías merge tiene el original en el medio. No me preguntes por qué.

Ejemplos:

torvalds@ppc970:~/merge-test> git merge-index cat MM
This is MM from the original tree.              # original
This is modified MM in the branch A.            # merge1
This is modified MM in the branch B.            # merge2
This is modified MM in the branch B.            # current contents

o

torvalds@ppc970:~/merge-test> git merge-index cat AA MM
cat: : No such file or directory
This is added AA in the branch A.
This is added AA in the branch B.
This is added AA in the branch B.
fatal: merge program failed

donde el último ejemplo muestra cómo git merge-index dejará de intentar fusionar una vez que algo haya devuelto un error (es decir, cat devolvió un error para el archivo AA, porque no existía en el original, y por lo tanto git merge-index ni siquiera intentó fusionar el elemento MM).
