DESCRIPCIÓ

N

git-annex-shell es un shell restringido, similar a git-shell, que puede usarse como shell de inicio de sesión para cuentas

SSH.

Dado que su sintaxis es idéntica a la de git-shell, puede usarse como r

eemplazo directo en cualquier lugar donde se use git-shell. Por ejemplo,
puede usarse como shell de inicio de sesión restringido de un usuario.

git-shell.

Ten en cuenta que el parámetro de directorio debe ser una ruta absoluta, de lo contrario se asume que es relativa al directorio de inicio del usuario. Además, el primer "/~/" o "/~user/" se expande al directorio de inicio

especificado.

remoto.

EJEMPLO

S

Para crear un ~/.ssh/authorized_keys archivo que solo permita ejecutar git-annex-shell, y no otros comandos, pasa el comando original a la opción

-c:


command="git-annex-shell -c \"$SSH_ORIGINAL_COMMAND\"",no-agent-forwarding,no-port-forwarding,no-X11-forwarding ssh-rsa AAAAB3NzaC1y[...] user@example.

com

Para restringir aún más git-annex-shell a un repositorio en particular, y bloquearlo completamente en modo solo

lectura:


command="GIT_ANNEX_SHELL_DIRECTORY=/srv/annex GIT_ANNEX_SHELL_LIMITED=true GIT_ANNEX_SHELL_READONLY=true git-annex-shell -c \"$SSH_ORIGINAL_COMMAND\"",restrict ssh-rsa AAAAB3NzaC1y[...] user@example.

com

Obviamente, ssh-rsa AAAAB3NzaC1y[...] user@example.com necesita ser reemplazado con tu clave SSH. Lo anterior también asume que git-annex-shell está disponible en tu $PATH, usa una ruta absoluta si no es el caso. También nota cómo lo anterior usa la opción restrict en lugar de una lista explícita de funcionalidades a prohibir. Esto solo funciona en ciertas versiones de OpenSSH, a partir de la 7.

1p2.

Para permitir solo la adición de nuevos objetos al repositorio, la variable GIT_ANNEX_SHELL_APPENDONLY también puede

usarse:

command="GIT_ANNEX_SHELL_DIRECTORY=/srv/annex GIT_ANNEX_SHELL_APPENDONLY=true git-annex-shell -c \"$SSH_ORIGINAL_COMMAND\"",restrict ssh-rsa AAAAB3NzaC1y[...] user@example.

com

Esto no impedirá que un atacante destruya el historial de git, como se explicó anteriormente. Para esto, podrías querer prohibir ciertas operaciones, como la eliminación de ramas y el force-push, con opciones de git-config(1). Por

ejemplo:

git config receive.denyDeletes true git config receive.denyNonFastForwards

true

Con esta configuración, los commits de git aún pueden eliminar archivos, pero seguirán disponibles en el historial de git y git-annex conservará su contenido. Sin embargo, los cambios en la rama git-annex pueden afectar negativamente la información de seguimiento de ubicación de git-annex y podrían causar pérdida de datos. Para solucionar este problema, se requieren ganchos más complejos, consulta por ejemplo el gancho update-paranoid en la d

istribución de
fuentes de git.
