NOMBRE

git-annex-reinject - inyecta contenido de archivo de nuevo en el annex

SINOPSIS

git annex reinject [fuente destino]

git annex reinject --known [fuente]

DESCRIPCIÓN

Mueve el contenido del o los archivos fuente al annex. Solo se reinyectarán los contenidos de archivos conocidos. Cualquier archivo fuente desconocido se dejará sin modificar.

Esto puede ser útil si ha obtenido el contenido de un archivo de otro lugar y desea ponerlo en el annex local. Por ejemplo, si se ha perdido el contenido de un archivo y tiene una copia de seguridad, puede restaurar la copia de seguridad y reinyectarla en su repositorio local.

Hay dos formas de usar este comando. Especificar un archivo fuente y el nombre de un archivo destino (ubicado dentro del árbol de trabajo del repositorio) inyecta el archivo fuente como el contenido del archivo destino.


git annex reinject /tmp/foo.iso foo.iso

O la opción --known se puede usar para reinyectar todos los archivos fuente conocidos, sin necesidad de especificar el archivo destino.


git annex reinject --known /tmp/*.iso

OPCIONES

--known
Con esta opción, cada archivo fuente especificado se hashea usando el backend clave-valor predeterminado (o el especificado con --backend), y si git-annex tiene un registro de que la clave resultante ha estado en el annex anteriormente, se inyecta el contenido.
Tenga en cuenta que, al usar un backend clave-valor que incluye la extensión del nombre de archivo en la clave, esto solo funcionará si los archivos fuente tienen las mismas extensiones que los archivos con el mismo contenido que se agregaron originalmente a git-annex.
Tenga en cuenta que esto reinyectará versiones antiguas de archivos que se han modificado o eliminado de la rama git actual. Use git-annex-unused(1) para detectar cuándo se han reinyectado archivos antiguos y potencialmente no utilizados.
--backend
Especifica el backend clave-valor a usar al verificar si un archivo es conocido con la opción --known.
--guesskeys
Con esta opción, cada archivo fuente especificado se verifica para ver si tiene el nombre de una clave de git-annex, y si es así, se importa como el contenido de esa clave.
Esto se puede usar para extraer objetos de git-annex de lost+found, siempre que no se haya perdido el nombre de archivo original, y es particularmente útil cuando se usan backends clave-valor que no hashean el contenido de un archivo.
Cuando el backend clave-valor admite hasheo, el contenido del archivo se verifica antes de importarlo.
--json
Habilita la salida JSON. Esto está destinado a ser analizado por programas que usan git-annex. Cada línea de salida es un objeto JSON.
--json-error-messages
Los mensajes que normalmente se enviarían a la salida estándar de error se incluyen en el JSON en su lugar.
También se pueden usar las opciones comunes de git-annex(1).
