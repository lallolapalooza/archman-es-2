NOMBRE

git-annex-add - añade archivos al annex de git

SINOPSIS

git annex add [ruta ...]

DESCRIPCIÓN

Añade los archivos especificados al annex. Si se especifica un directorio, actúa sobre todos los archivos dentro del directorio y sus subdirectorios. Si no se especifica ninguna ruta, añade archivos del directorio actual y sus subdirectorios.

Los archivos que ya están en git y no han sido modificados, o que git ha sido configurado para ignorar, serán omitidos silenciosamente.

Si annex.largefiles está configurado (en la configuración de git, gitattributes, o la configuración de git-annex), y no coincide con un archivo, git annex add se comportará de la misma manera que git add y añadirá el archivo no grande directamente al repositorio de git, en lugar de al annex. (Por defecto, se asume que los archivos ocultos (dotfiles) y el contenido de los directorios ocultos (dotdirs) no son grandes, y se añaden directamente a git, pero annex.dotfiles puede configurarse para añadir esos también.) Consulte el manual de git-annex para obtener documentación sobre estas y otras configuraciones.

Por defecto, los archivos grandes se añaden al annex en forma bloqueada, lo que impide la modificación posterior de su contenido hasta que se desbloqueen con git-annex-unlock(1). (Sin embargo, esto no ocurre cuando un repositorio está en un sistema de archivos que no soporta enlaces simbólicos). La configuración de git annex.addunlocked (y la configuración de git-annex) puede utilizarse para cambiar este comportamiento.

Este comando también puede utilizarse para añadir enlaces simbólicos, tanto enlaces simbólicos a contenido anexado como otros enlaces simbólicos.

EJEMPLOS


# git annex add foo bar
añadir foo ok
añadir bar ok
# git commit -m añadido

OPCIONES

--no-check-gitignore
Añade archivos ignorados por git.
--force-large
Trata todos los archivos como archivos grandes, ignorando la configuración de annex.largefiles y annex.dotfiles, y los añade al annex.
--force-small
Trata todos los archivos como archivos pequeños, ignorando la configuración de annex.largefiles, annex.dotfiles y annex.addsmallfiles, y los añade a git.
--backend
Especifica qué backend de clave-valor utilizar.
opciones de coincidencia de archivos
Muchas de las git-annex-matching-options(1) pueden utilizarse para especificar archivos a añadir.
Por ejemplo: --largerthan=1GB
--jobs=N -JN
Añade múltiples archivos en paralelo. Esto puede ser más rápido. Por ejemplo: -J4
Establecer esto a "cpus" ejecutará un trabajo por núcleo de CPU.
--update -u
Al igual que git add --update, esto no añade archivos nuevos, pero cualquier actualización a archivos rastreados se añadirá al índice.
--dry-run
Muestra lo que se haría para cada archivo, pero evita hacer cambios.
--json
Habilita la salida JSON. Está pensada para ser procesada por programas que usan git-annex. Cada línea de salida es un objeto JSON.
--json-progress
Incluye objetos de progreso en la salida JSON.
--json-error-messages
Los mensajes que normalmente se emitirían a la salida de error estándar se incluyen en el JSON.
--batch
Habilita el modo por lotes, en el que un archivo a añadir se lee en una línea de stdin, se añade el archivo y se repite.
Tenga en cuenta que si un archivo se omite (debido a que no existe, está ignorado por git, ya está en git, o no cumple las opciones de coincidencia), se emitirá una línea vacía en lugar de la salida normal producida al añadir un archivo.
-z
Hace que la entrada de --batch esté delimitada por nulos en lugar de las nuevas líneas habituales.
También se pueden utilizar las git-annex-common-options(1).
