Un archivo gitignore especifica archivos no rastreados

Git

si ignorar una ruta, Git normalmente comprueba patrones gitignore de múltiples fuentes, con el siguiente orden de precedencia, de mayor a menor (dentro de un mismo nivel de precedencia, el último patrón coincidente decide el resultado): •Patrones leídos desde la línea de comandos para aquellos comandos que los admiten. •Patrones leídos desde

un

padre

Estos patrones coinciden en relación con la ubicación del archivo .gitignore. Un proyecto normalmente incluye tales archivos .gitignore en su repositorio, que contienen patrones para archivos generados como parte de la compilación del proyecto. •Patrones leídos desde $GIT_DIR/info/exclude. •Patrones leídos desde el archivo especificado por la variable de
configuración
core.excludesFile. En qué archivo colocar
un patrón
depende de cómo se pretende usar el patrón. •Los patrones que deben ser controlados por v
ersiones

desarrolladores
querrán ignorar) deben ir en un archivo .gitignore. •Los patrones que son específicos de un repositorio en particular pero que no necesitan ser compartidos con otros repositorios relacionados (por
ejemplo,
archivos auxiliares que viven dentro del repositorio pero son específicos para el flujo de trabajo de un usuario) deben ir en el archivo $GIT_DIR/info/exclude. •Los patrones que un usuario quiere que Git ignore en todas las situaciones (por ejemplo, archivos de copia de seguridad o temporales generados
por
el editor de elección del usuario) generalmente van en un archivo especificado por core.excludesFile en el ~/.gitconfig del usuario. Su valor por defecto es $XDG_CONFIG_HOME/git/ignore. Si $XDG_CONFIG_HOME no está configurado o está vacío, se usa $HOME/.config/git/ignore en su lugar. Las herramientas de fontanería subyacentes de Git, como git ls-files y git read-tree, leen patrones gitignore especificados
por

opciones de línea de comandos, o desde archivos especificados por opciones de línea de comandos. Las herramientas de Git de nivel más alto, como git status y git add, usan patrones de las fuentes especificadas arriba. NOTAS El

propósit

o

de los archivos gitignore es asegurar que ciertos archivos no rastreados por Git permanezcan sin rastrear.

Para

dejar de rastrear un archivo que está siendo rastreado actualmente, use git rm --cached para eliminar el archivo del índice. El nombre del archivo puede ser añadido al archivo .gitignore para evitar que el archivo sea reintroducido en commits

posteriores.

Git no sigue los enlaces simbólicos al acceder a un archivo . gitignore en el árbol de trabajo. Esto mantiene el comportamiento consistente cuando e

•El
patrón hello. * coincide con cualquier archivo o directorio cuyo nombre comienza con " hello.". Si uno quiere restringir esto solo al directorio y no a sus subdirectorios, se puede anteponer una barra inclinada al patrón, es decir, " /hello.*"; el patrón ahora coincide con " hello. txt", " hello. c" pero no con " a/hello.j
ava".
•El patrón foo/ coincidirá con un directorio " foo" y las rutas debajo de él, pero no coincidirá con un archivo normal o un enlace simbólico " foo" (esto es consistente con la forma en que funciona el pathspec en general en
Git)
. •Los patrones doc/frotz y /doc/frotz tienen el mismo efecto en cualquier archivo .gitignore. En otras palabras, una barra inclinada inicial no es relevante si ya hay una barra inclinada en el medio en el
patrón.
•El patrón foo/*, coincide con " foo/test.json" (un archivo normal), " foo/bar" (un directorio), pero no coincide con " foo/bar/hello.c" (un archivo normal), ya que el asterisco en el patrón no coincide bar/hello.c que contiene una barra
