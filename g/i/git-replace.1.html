git-replace - Crea, list

a y elimina referencias
para reemplazar objetos

SINOPSI

S 
git replace [-f] <object> <replacement>
git replace [-f] --edit <object>
git replace [-f] --graft <commit> [<parent>...]
git replace [-f] --convert-graft-file
git replace -d <object>...
git replace [--format=<format>] [-l [<pattern>
]
]

DESCRIPCIÓ

N

Añade una referencia de reemplazo en el espacio de nombres refs/replace/

.

El nombre de la referencia de reemplazo es el SHA-1 del objeto que se reemplaza. El contenido de la referencia de reemplazo es el SHA-1 del objeto de

reemplazo.

El objeto reemplazado y el objeto de reemplazo deben ser del mismo tipo. Esta restricción se puede evitar usando -f

.

A menos que se proporcione -f, la referencia de reemplazo no debe existir

todavía.

No hay otras restricciones sobre los objetos reemplazados y de reemplazo. Los commits de fusión (merge) pueden ser reemplazados por commits que no sean de fusión y

viceversa.

Las referencias de reemplazo se usarán de forma predeterminada por todos los comandos de Git, excepto aquellos que realizan recorridos de alcance (prune, transferencia de paquetes y fsck)

.

Es posible deshabilitar el uso de referencias de reemplazo para cualquier comando usando la opción --no-replace-objects justo después de git

.

Por ejemplo, si el commit foo ha sido reemplazado por el commit bar

: 
$ git --no-repl
ace-objects cat-
file commit foo

muestra información sobre el commit foo, mientras

que: 
$ git ca
t-file co
mmit foo

muestra información sobre el commit bar

.

La variable de entorno GIT_NO_REPLACE_OBJECTS se puede establecer para lograr el mismo efecto que la opción --no-replace-object

s
.

OPCIONE

S

-f,

--force
Si ya existe una referencia de reemplazo para el mismo objeto, se sobrescribirá (en lugar de fallar)
.

-d,

--delete
Elimina las referencias de reemplazo existentes para los objetos
dados.

--edit

<object>
Edita el contenido de un objeto interactivamente. El contenido existente de <object> se imprime de forma formateada en un archivo temporal, se lanza un editor sobre el archivo, y el resultado se analiza para crear un nuevo objeto del mismo tipo que <object>. Luego se crea una referencia de reemplazo para reemplazar <object> con el objeto recién creado. Véase git-var(1) para detalles sobre cómo se elegirá el
editor.

--ra

w
Al editar, proporciona el contenido crudo del objeto en lugar de su versión formateada. Actualmente esto solo afecta a los árboles (trees), que se mostrarán en su forma binaria. Esto es más difícil de trabajar, pero puede ayudar al reparar un árbol que está tan corrupto que no se puede formatear. Ten en cuenta que puede que necesites configurar tu editor para leer y escribir datos binarios de forma
limpia.

--graft <commit> [<parent>...

]
Crea un commit de injerto (graft). Se crea un nuevo commit con el mismo contenido que <commit> excepto que sus padres serán [<parent>...] en lugar de los padres de <commit>. Luego se crea una referencia de reemplazo para reemplazar <commit> con el commit recién creado. Usa --convert-graft-file para convertir un archivo $GIT_DIR/info/grafts y usar referencias de reemplazo en su
lugar.

--convert-graft-fil

e
Crea commits de injerto para todas las entradas en $GIT_DIR/info/grafts y elimina ese archivo tras el éxito. El propósito es ayudar a los usuarios a transitar desde el archivo de injertos, ahora
obsoleto.

-l <pattern>, --list

<pattern>
Lista las referencias de reemplazo para los objetos que coinciden con el patrón dado (o todas si no se da un patrón). Escribir "git replace" sin argumentos también lista todas las referencias de
reemplazo.

--format=<format

>
Al listar, usa el <format> especificado, que puede ser uno de short, medium y long. Si se omite, el formato por defecto es
short.

FORMATO

S

Los siguientes formatos están

disponibles:
•short:
<replaced-sha1>
•medium: <replaced-sha1> → <replacement-sha1
>
•long: <replaced-sha1> (<replaced-type>)
→ <replacement-sha1>
(<replacement-type>)

CREACIÓN DE OBJETOS DE

REEMPLAZO

git-hash-object(1), git-rebase(1), y git-filter-repo[1], entre otros comandos de git, se pueden usar para crear objetos de reemplazo a partir de objetos existentes. La opción --edit también se puede usar con git replace para crear un objeto de reemplazo editando un objeto

existente.

Si quieres reemplazar muchos blobs, árboles o commits que son parte de una cadena de commits, quizás

solo quieras crear una cadena de commits de reemplazo y luego solo reemplazar el commit en la punta
de la cadena de commits objetivo con el commit en la punta de la cadena de commits de reemplazo.

ERRORE

S

Comparar blobs o árboles que han sido reemplazados con aquellos que los reemplazan no funcionará correctamente. Y usar git reset --hard para volver a un commit reemplazado moverá la rama al commit de reemplazo en lugar del commit

reemplazado.

Puede haber otros problemas al usar git rev-list relacionado

s con objetos
pendientes.
