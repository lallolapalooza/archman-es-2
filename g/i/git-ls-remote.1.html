GIT-LS-REMOTE(1) Manual de Git GIT-LS-REMOTE(1)

NOMBRE

git-ls-remote - Listar referencias en un repositorio remoto

SINOPSIS

git ls-remote [--branches] [--tags] [--refs] [--upload-pack=<ejecutable>]
              [-q | --quiet] [--exit-code] [--get-url] [--sort=<clave>]
              [--symref] [<repositorio> [<patrones>...]]

DESCRIPCIÓN

Muestra las referencias disponibles en un repositorio remoto junto con los identificadores de commit asociados.

OPCIONES

-b, --branches, -t, --tags

Limita solo a ramas locales y etiquetas locales, respectivamente. Estas opciones *no* son mutuamente excluyentes; cuando se dan ambas, se muestran las referencias almacenadas en refs/heads y refs/tags. Tenga en cuenta que --heads y -h son sinónimos obsoletos para --branches y -b y pueden eliminarse en el futuro. Tenga en cuenta también que git ls-remote -h, utilizado sin nada más en la línea de comandos, proporciona ayuda, de manera consistente con otros subcomandos de git.

--refs

No muestre etiquetas peladas o pseudoreferencias como HEAD en la salida.

-q, --quiet

No imprima la URL remota en stderr.

--upload-pack=<ejecutable>

Especifique la ruta completa de git-upload-pack en el host remoto. Esto permite listar referencias de repositorios accedidos vía SSH y donde el demonio SSH no utiliza la PATH configurada por el usuario.

--exit-code

Salga con el estado "2" cuando no se encuentren referencias coincidentes en el repositorio remoto. Normalmente el comando sale con el estado "0" para indicar que se comunicó con éxito con el repositorio remoto, independientemente de si encontró alguna referencia coincidente.

--get-url

Expanda la URL del repositorio remoto dado, teniendo en cuenta cualquier configuración de "url.<base>.insteadOf" (ver git-config(1)) y salga sin comunicarse con el remoto.

--symref

Además del objeto apuntado por él, muestre la referencia subyacente apuntada por él cuando muestre una referencia simbólica. Actualmente, upload-pack solo muestra la referencia simbólica HEAD, por lo que será la única que muestre ls-remote.

--sort=<clave>

Ordene según la clave dada. Prefije - para ordenar en orden descendente del valor. Soporta "version:refname" o "v:refname" (los nombres de etiqueta se tratan como versiones). El orden de ordenación "version:refname" también puede verse afectado por la variable de configuración "versionsort.suffix". Consulte git-for-each-ref(1) para obtener más opciones de ordenación, pero tenga en cuenta que claves como committerdate que requieren acceso a los objetos en sí mismas no funcionarán para referencias cuyos objetos aún no se han obtenido del remoto, y darán un error de objeto faltante.

-o <opción>, --server-option=<opción>

Transmita la cadena dada al servidor al comunicarse utilizando el protocolo versión 2. La cadena dada no debe contener un carácter NUL ni LF. Cuando se dan varias --server-option=<opción>, todas se envían al otro lado en el orden en que aparecen en la línea de comandos. Cuando no se proporciona ninguna --server-option=<opción> desde la línea de comandos, se utilizan los valores de la variable de configuración remote.<nombre>.serverOption en su lugar.

<repositorio>

El repositorio "remoto" a consultar. Este parámetro puede ser una URL o el nombre de un remoto (ver las secciones GIT URLS y REMOTES de git-fetch(1)).

<patrones>...

Cuando no se especifican, se muestran todas las referencias, después de filtrarlas con --heads y --tags. Cuando se especifican <patrones>..., solo se muestran las referencias que coinciden con uno o más de los patrones dados. Cada patrón se interpreta como un comodín (ver glob en gitglossary(7)) que se compara con la "parte final" de una ref, comenzando desde el inicio de la ref (por lo que un nombre completo como refs/heads/foo coincide) o desde un separador de barra (por lo que bar coincide con refs/heads/bar pero no con refs/heads/foobar).

SALIDA

La salida tiene el formato:

<oid> TAB <ref> LF

Al mostrar una etiqueta anotada, a menos que se proporcione --refs, se muestran dos líneas de este tipo: una con el nombre de referencia de la etiqueta en sí como <ref>, y otra con <ref> seguido de ^{}. El <oid> en esta última línea muestra el nombre del objeto al que apunta la etiqueta.

EJEMPLOS

•Listar todas las referencias (incluyendo simbólicas y pseudoreferencias), pelando etiquetas: 
$ git ls-remote
27d43aaaf50ef0ae014b88bba294f93658016a2e        HEAD
950264636c68591989456e3ba0a5442f93152c1a        refs/heads/main
d9ab777d41f92a8c1684c91cfb02053d7dd1046b        refs/heads/next
d4ca2e3147b409459955613c152220f4db848ee1        refs/tags/v2.40.0
73876f4861cd3d187a4682290ab75c9dccadbc56        refs/tags/v2.40.0^{}
•Listar todas las referencias que coinciden con los patrones dados: 
$ git ls-remote http://www.kernel.org/pub/scm/git/git.git master seen rc
5fe978a5381f1fbad26a80e682ddd2a401966740        refs/heads/master
c781a84b5204fb294c9ccc79f8b3baceeb32c061        refs/heads/seen
•Listar solo etiquetas que coincidan con un patrón de comodín dado: 
$ git ls-remote --tags http://www.kernel.org/pub/scm/git/git.git v\*
485a869c64a68cc5795dd99689797c5900f4716d        refs/tags/v2.39.2
cbf04937d5b9fcf0a76c28f69e6294e9e3ecd7e6        refs/tags/v2.39.2^{}
d4ca2e3147b409459955613c152220f4db848ee1        refs/tags/v2.40.0
73876f4861cd3d187a4682290ab75c9dccadbc56        refs/tags/v2.40.0^{}
