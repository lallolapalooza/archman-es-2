GITFORMAT-BUNDLE(5) Manual de Git GITFORMAT-BUNDLE(5)

NOMBRE

gitformat-bundle(5) — El formato de archivo de bundle

SINOPSIS

*.bundle
*.bdl

DESCRIPCIÓN

El formato de bundle de Git es un formato que representa tanto refs como objetos de Git. Un bundle es una cabecera en un formato similar a git-show-ref(1) seguido de un pack en formato *.pack.

El formato es creado y leído por el comando git-bundle(1), y soportado por, por ejemplo, git-fetch(1) y git-clone(1).

FORMATO

Usaremos la notación ABNF para definir el formato de bundle de Git. Ver gitprotocol-common(5) para los detalles.

Un bundle v2 se ve así:

bundle    = signature *prerequisite *reference LF pack
signature = "# v2 git bundle" LF
prerequisite = "-" obj-id SP comment LF
comment      = *CHAR
reference    = obj-id SP refname LF
pack         = ... ; packfile

Un bundle v3 se ve así:

bundle    = signature *capability *prerequisite *reference LF pack
signature = "# v3 git bundle" LF
capability   = "@" key ["=" value] LF
prerequisite = "-" obj-id SP comment LF
comment      = *CHAR
reference    = obj-id SP refname LF
key          = 1*(ALPHA / DIGIT / "-")
value        = *(%01-09 / %0b-FF)
pack         = ... ; packfile

SEMÁNTICA

Un bundle de Git consta de varias partes.

•"Capacidades", que solo están en el formato v3, indican la funcionalidad que el bundle requiere para ser leído correctamente.
•"Prerrequisitos" listan los objetos que NO están incluidos en el bundle y que el lector del bundle DEBE tener ya, para poder usar los datos del bundle. Los objetos almacenados en el bundle pueden referirse a objetos prerrequisito y a todo lo que sea alcanzable desde ellos (por ejemplo, un objeto árbol en el bundle puede referirse a un blob que sea alcanzable desde un prerrequisito) y/o expresado como un delta contra objetos prerrequisito.
•"Referencias" registran las puntas del gráfico de historial, es decir, lo que el lector del bundle PUEDE "git fetch" de él.
•"Pack" es el flujo de datos del pack que "git fetch" enviaría, si haces fetch desde un repositorio que tiene las referencias registradas en las "Referencias" anteriores a un repositorio que tiene referencias apuntando a los objetos listados en los "Prerrequisitos" anteriores.

En el formato de bundle, puede haber un comentario después de un obj-id de prerrequisito. Es un comentario y no tiene un significado específico. El escritor del bundle PUEDE poner cualquier cadena aquí. El lector del bundle DEBE ignorar el comentario.

Nota sobre clones superficiales y bundles de Git

Tenga en cuenta que los prerrequisitos no representan un límite de clonación superficial. Las semánticas de los prerrequisitos y los límites de clonación superficial son diferentes, y el formato de bundle de Git v2 no puede representar un repositorio de clonación superficial.

CAPACIDADES

Dado que no hay oportunidad de negociación, las capacidades desconocidas hacen que git bundle se aborte.

•object-format especifica el algoritmo de hash en uso, y puede tomar los mismos valores que el valor de configuración extensions.objectFormat.
•filter especifica un filtro de objetos como en la opción --filter de git-rev-list(1). El archivo pack resultante debe marcarse como un archivo pack .promisor después de ser desempaquetado.
