NOMBRE

git-patch-id - Calcular un ID único para un parche

SINOPSIS

git patch-id [--stable | --unstable | --verbatim]

DESCRIPCIÓN

Lee un parche de la entrada estándar y calcula su ID de parche.

Un "ID de parche" no es más que una suma SHA-1 de las diferencias de archivos asociadas con un parche, ignorando los números de línea. Como tal, es "razonablemente estable", pero al mismo tiempo también es razonablemente único; es decir, es casi seguro que dos parches que tienen el mismo "ID de parche" son lo mismo.

El caso de uso principal para este comando es buscar posibles commits duplicados.

Al tratar con la salida de git diff-tree, aprovecha el hecho de que el parche está prefijado con el nombre del objeto del commit, y genera dos cadenas hexadecimales de 40 bytes. La primera cadena es el ID del parche y la segunda cadena es el ID del commit. Esto se puede usar para crear un mapeo de ID de parche a ID de commit.

OPCIONES

--verbatim

Calcula el patch-id de la entrada tal como se proporciona, no elimina ningún espacio en blanco.

Esta es la opción predeterminada si patchid.verbatim es true.

--stable

Usa una suma "estable" de hashes como ID de parche. Con esta opción:
•Reordenar las diferencias de archivos que componen un parche no afecta al ID. En particular, dos parches producidos al comparar los mismos dos árboles con dos configuraciones diferentes para -O<orderfile> resultan en la misma firma de ID de parche, lo que permite que el resultado calculado se utilice como clave para indexar metadatos sobre el cambio entre los dos árboles;
•El resultado es diferente del valor producido por git 1.9 y versiones anteriores o producido cuando se configura un hash "inestable" (ver --unstable abajo), incluso cuando se usa en una salida de diferencias tomada sin ningún uso de -O<orderfile>, lo que hace que las bases de datos existentes que almacenan dichos patch-ids históricos o "inestables" queden inutilizables.
•Se ignoran todos los espacios en blanco dentro del parche y no afectan al ID.

Esta es la opción predeterminada si patchid.stable está configurado como true.

--unstable

Usa un hash "inestable" como ID de parche. Con esta opción, el resultado producido es compatible con el valor de patch-id producido por git 1.9 y versiones anteriores, y se ignoran los espacios en blanco. Los usuarios con bases de datos preexistentes que almacenan patch-ids producidos por git 1.9 y versiones anteriores (que no manejan parches reordenados) pueden querer usar esta opción.

Esta es la opción predeterminada.
