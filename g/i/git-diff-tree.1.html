Cuando se utiliza con -M, un archivo reescrito totalmente también se considera como la fuente de un renombre (normalmente -M solo considera un archivo que desapareció como fuente de un renombre), y el número <n> controla este aspecto de la opción -B (por defecto es 50%). -B20% especifica que un cambio con adición y eliminación comparado con el 20% o más del tamaño del archivo es elegible para ser recogido como una posible fuente de renombre a otro archivo.

-M[<n>], --find-renames[=<n>]

Detecta renombres. Si se especifica <n>, es un umbral en el índice de similitud (es decir, cantidad de adición/eliminación comparada con el tamaño del archivo). Por ejemplo, -M90% significa que Git debe considerar un par de eliminación/adición como un renombre si más del 90% del archivo no ha cambiado. Sin un signo %, el número debe leerse como una fracción, con un punto decimal antes. Es decir, -M5 se convierte en 0.5, y por lo tanto es lo mismo que -M50%. De manera similar, -M05 es lo mismo que -M5%. Para limitar la detección a renombres exactos, use -M100%. El índice de similitud por defecto es 50%.

-C[<n>], --find-copies[=<n>]

Detecta copias además de renombres. Ver también --find-copies-harder. Si se especifica <n>, tiene el mismo significado que para -M<n>.

--find-copies-harder

Por razones de rendimiento, por defecto, la opción -C encuentra copias solo si el archivo original de la copia fue modificado en el mismo conjunto de cambios. Esta bandera hace que el comando inspeccione archivos no modificados como candidatos para la fuente de la copia. Esta es una operación muy costosa para proyectos grandes, así que úsela con precaución. Dar más de una opción -C tiene el mismo efecto.

-D, --irreversible-delete

Omite la preimagen de las eliminaciones, es decir, imprime solo la cabecera pero no la diferencia entre la preimagen y /dev/null. El parche resultante no está destinado a ser aplicado con patch o git apply; esto es solo para personas que desean concentrarse en revisar el texto después del cambio. Además, la salida obviamente carece de información suficiente para aplicar dicho parche de forma inversa, incluso manualmente, de ahí el nombre de la opción.

Cuando se usa junto con -B, omite también la preimagen en la parte de eliminación de un par eliminación/creación.

-l<num>

Las opciones -M y -C involucran algunos pasos preliminares que pueden detectar subconjuntos de renombres/copias de forma económica, seguidos por una porción de respaldo exhaustiva que compara todos los destinos restantes sin pareja con todas las fuentes relevantes. (Para renombres, solo las fuentes restantes sin pareja son relevantes; para copias, todas las fuentes originales son relevantes). Para N fuentes y destinos, esta comprobación exhaustiva es O(N^2). Esta opción evita que se ejecute la porción exhaustiva de la detección de renombres/copias si el número de archivos fuente/destino involucrados supera el número especificado. Por defecto es diff.renameLimit. Tenga en cuenta que un valor de 0 se trata como ilimitado.

--diff-filter=[(A|C|D|M|R|T|U|X|B)...[*]]

Selecciona solo archivos que son Añadidos (A), Copiados (C), Eliminados (D), Modificados (M), Renombrados (R), han cambiado su tipo (es decir, archivo regular, enlace simbólico, submódulo, ... ) (T), no están Fusionados (U), son Desconocidos (X), o han tenido su pareja Rota (B). Se puede usar cualquier combinación de los caracteres de filtro (incluida ninguna). Cuando * (Todo o nada) se añade a la combinación, todas las rutas se seleccionan si hay algún archivo que coincida con otros criterios en la comparación; si no hay ningún archivo que coincida con otros criterios, no se selecciona nada.

Además, estas letras mayúsculas pueden escribirse en minúsculas para excluir. Por ejemplo, --diff-filter=ad excluye las rutas añadidas y eliminadas.

Tenga en cuenta que no todas las diffs pueden presentar todos los tipos. Por ejemplo, las entradas copiadas y renombradas no pueden aparecer si la detección para esos tipos está deshabilitada.

-S<string>

Busca diferencias que cambien el número de ocurrencias de la cadena especificada <string> (es decir, adición/eliminación) en un archivo. Destinado al uso del script.

Es útil cuando buscas un bloque de código exacto (como una estructura) y quieres conocer el historial de ese bloque desde que se creó por primera vez: usa la característica iterativamente para introducir el bloque interesante en la preimagen de nuevo en -S, y sigue hasta que obtengas la primera versión del bloque.

Los archivos binarios también se buscan.

-G<regex>

Busca diferencias cuyo texto del parche contenga líneas añadidas/eliminadas que coincidan con <regex>.

Para ilustrar la diferencia entre -S<regex> --pickaxe-regex y -G<regex>, considera un commit con la siguiente diff en el mismo archivo:

+    return frotz(nitfol, two->ptr, 1, 0);
...
-    hit = frotz(nitfol, mf2.ptr, 1, 0);

Mientras que git log -G"frotz\(nitfol" mostrará este commit, git log -S"frotz\(nitfol" --pickaxe-regex no lo hará (porque el número de ocurrencias de esa cadena no cambió).

A menos que se suministre --text, los parches de archivos binarios sin un filtro textconv serán ignorados.

Ver la entrada de *pickaxe* en gitdiffcore(7) para más información.

--find-object=<object-id>

Busca diferencias que cambien el número de ocurrencias del objeto especificado. Similar a -S, solo que el argumento es diferente en que no busca una cadena específica, sino un ID de objeto específico.

El objeto puede ser un blob o un commit de submódulo. Implica la opción -t en git-log para encontrar también árboles.

--pickaxe-all

Cuando -S o -G encuentran un cambio, muestra todos los cambios en ese conjunto de cambios, no solo los archivos que contienen el cambio en <string>.

--pickaxe-regex

Trata la <string> dada a -S como una expresión regular extendida POSIX para coincidir.

-O<orderfile>

Controla el orden en que aparecen los archivos en la salida. Esto anula la variable de configuración diff.orderFile (ver git-config(1)). Para cancelar diff.orderFile, use -O/dev/null.

El orden de salida se determina por el orden de los patrones glob en <orderfile>. Todos los archivos con nombres de ruta que coinciden con el primer patrón se sacan primero, todos los archivos con nombres de ruta que coinciden con el segundo patrón (pero no con el primero) se sacan a continuación, y así sucesivamente. Todos los archivos con nombres de ruta que no coinciden con ningún patrón se sacan al final, como si hubiera un patrón implícito de coincidencia de todo al final del archivo. Si múltiples nombres de ruta tienen el mismo rango (coinciden con el mismo patrón pero no con patrones anteriores), su orden de salida entre sí es el orden normal.

<orderfile> se analiza de la siguiente manera:

•Las líneas en blanco se ignoran, por lo que pueden usarse como separadores para legibilidad.
•Las líneas que comienzan con un hash ("#") se ignoran, por lo que pueden usarse para comentarios. Agregue una barra invertida ("\") al principio del patrón si comienza con un hash.
•Cada otra línea contiene un solo patrón.

Los patrones tienen la misma sintaxis y semántica que los patrones utilizados para fnmatch(3) sin el indicador FNM_PATHNAME, excepto que un nombre de ruta también coincide con un patrón si eliminar cualquier número de los componentes finales del nombre de ruta coincide con el patrón. Por ejemplo, el patrón "foo*bar" coincide con "fooasdfbar" y "foo/bar/baz/asdf" pero no con "foobarx".

    archivos A y B con una sola columna que tiene el prefijo - (menos — aparece

    B), o " " (espacio — sin cambios), este formato compara dos o más archivos
    file1, file2,... con un archivo X, y muestra cómo X difiere de cada fileN.
    Se antepone una columna para cada fileN a la línea de salida para indicar
    cómo la línea de X difiere de ella.


Un carácter - en la columna N significa que la línea aparece
    en fileN pero no aparece en el resultado. Un carácter + en la columna N significa que la línea aparece
    en el resultado, y fileN no tiene esa línea (en otras palabras, la línea
    fue añadida, desde el punto de vista de ese padre).


En el ejemplo de salida anterior, la firma de la función fue cambiada
    en ambos archivos (de ahí dos - eliminaciones de file1 y file2, más
    ++ para significar que una línea añadida no aparece en file1 ni en
    file2). Además, otras ocho líneas son iguales en file1 pero no aparecen en
    file2 (de ahí el prefijo +).


Cuando se muestra con git diff-tree -c, compara los
    padres de una confirmación de fusión con el resultado de la fusión (es
    decir, file1..fileN son los padres). Cuando se muestra con git diff-files -c, compara los
    dos padres de fusión sin resolver con el archivo del árbol de trabajo (es
    decir, file1 es el escenario 2, también conocido como "nuestra versión",
    file2 es el escenario 3, también conocido como "su versión").






OTROS FORMATOS DE DIFF


La opción --summary describe los archivos añadidos, eliminados,
    renombrados y copiados recientemente. La opción --stat añade el gráfico de diffstat(1)
    a la salida. Estas opciones pueden combinarse con otras opciones, como -p, y están destinadas al consumo humano.


Al mostrar un cambio que involucra un renombrado o una copia,
    --stat formatea las rutas de forma compacta combinando el prefijo y sufijo comunes
    de las rutas. Por ejemplo, un cambio que mueve
    arch/i386/Makefile a arch/x86/Makefile mientras modifica 4
    líneas se mostrará así:




arch/{i386 => x86}/Makefile    |   4 +--




La opción --numstat da la información de diffstat(1) pero
    está diseñada para un consumo más fácil por máquinas. Una entrada en la
    salida de --numstat
    se ve así:




1       2       README
3       1       arch/{i386 => x86}/Makefile




Es decir, de izquierda a derecha:


 1. el número de líneas añadidas;


 2. un tabulador;


 3. el número de líneas eliminadas;


 4. un tabulador;


 5. ruta (posiblemente con información de
  renombrado/copia);


 6. un salto de línea.


Cuando la opción de salida -z está activa, la salida se formatea
    de esta manera:




1       2       README NUL
3       1       NUL arch/i386/Makefile NUL arch/x86/Makefile NUL




Es decir:


 1. el número de líneas añadidas;


 2. un tabulador;


 3. el número de líneas eliminadas;


 4. un tabulador;


 5. un NUL (solo existe si se renombró/copió);


 6. ruta en la imagen previa;


 7. un NUL (solo existe si se renombró/copió);


 8. ruta en la imagen posterior (solo existe si
  se renombró/copió);


 9. un NUL.


El NUL extra antes de la ruta de la imagen previa en el caso de
    renombrado es para permitir que los scripts que leen la salida sepan si el
    registro actual que se está leyendo es un registro de una sola ruta o un
    registro de renombrado/copia sin tener que leer en exceso. Después de leer
    las líneas añadidas y eliminadas, leer hasta el NUL daría la
    ruta, pero si eso es NUL, el registro mostrará dos rutas.
