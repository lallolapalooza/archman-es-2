git-annex-matching-

options - especific
ar sobre qué actuar

DESCRIPCIÓ

N

Muchos comandos de git-annex permiten usar estas opciones para especificar sobre qué archivos actúan. Algunas de estas opciones también pueden ser usadas por comandos para especificar sobre qué claves

actuar.

Se pueden construir expresiones arbitrariamente complicadas usando estas opciones. Por

ejemplo:


--include='*.mp3' --and -( --in=usbdrive --or --in=archive

-)

El ejemplo anterior hace que git-annex tra

baje solo con archivos mp3 que están pr
esentes en cualquiera de dos repositorios.

OPCIONE

S
--exclude=gl
ob
Omite archivos que coinciden con el patrón glob. El glob se compara en relación con el directorio actual. Por
ejemplo:

git annex get --exclude='*.mp3' --exclude='subdir
/*'
Tenga en cuenta que esto no coincidirá con nada cuando se usa --all o
--unused.
--include=gl
ob
Omite archivos que no coinciden con el patrón glob. (Igual que --not --exclude.) Por ejemplo, para incluir solo archivos mp3 y
ogg:

git annex get --include='*.mp3' --or --include='*.
ogg'
Tenga en cuenta que esto no omitirá nada cuando se usa --all o
--unused.
--excludesamecontent=g
lob
Omite un archivo cuando existe otro archivo con el mismo contenido, cuyo nombre coincide con el glob. El glob se compara en relación con el directorio
actual.
Por ejemplo, para eliminar archivos en el directorio archive, pero no cuando el mismo contenido es usado por un archivo en el directorio
work:

git annex drop archive/ --excludesamecontent='work
/*'
--includesamecontent=g
lob
Omite archivos cuando no existe otro archivo con el mismo contenido cuyo nombre coincide con el glob. (Igual que --not --excludesameconte
nt)
Por ejemplo, si tiene directorios inbox y outbox, y quiere encontrar algo en el inbox que tenga el mismo contenido que algo en el
outbox:

git annex find inbox --includesamecontent='outbox
/*'
--in=reposit
ory
Coincide solo cuando git-annex cree que el contenido está presente en un
repositorio.
El repositorio debe especificarse usando el nombre de un remoto configurado, o el UUID o la descripción de un repositorio. Para el repositorio actual, use --in=he
re
Tenga en cuenta que esto no verifica los repositorios remotos para confirmar que el contenido sigue presente en ellos. Sin embargo, al verificar el repositorio actual, sí verifica que el contenido está presente en
él.
--in=repository@{da
te}
Coincide solo cuando el contenido estaba presente en un repositorio en la fecha
dada.
La fecha se especifica en la misma sintaxis documentada en gitrevisions(7). Tenga en cuenta que esto usa el reflog, por lo que no se pueden consultar fechas muy
antiguas.
Por ejemplo, podría necesitar ejecutar git annex drop . para liberar temporalmente espacio en disco. Al día siguiente, puede recuperar los archivos que eliminó usando git annex get . --in=here@{yesterd
ay}
--expected-pres
ent
Coincide solo cuando git-annex cree que el contenido está presente en el repositorio
local.
Esto es como --in=here, excepto que no verifica que el contenido esté realmente presente. Por lo tanto, puede usarse en situaciones donde se sabe que la información de seguimiento de ubicación está
desactualizada.
Por ejemplo, si un repositorio se está restaurando desde una copia de seguridad que no incluía los objetos de git-annex, esto podría usarse para recuperar todos los archivos que se esperaba que estuvieran en él: git-annex get --expected-pres
ent
--copies=num
ber
Coincide solo cuando git-annex cree que hay el número especificado de copias, o más. Tenga en cuenta que no verifica los remotos para confirmar que las copias siguen
existiendo.
--copies=trustlevel:
number
Coincide solo cuando git-annex cree que hay el número especificado de copias, en remotos con el nivel de confianza especificado. Por ejemplo, --copies=trusted:
2
Para coincidir con cualquier nivel de confianza igual o superior a un nivel dado, use 'trustlevel+'. Por ejemplo, --copies=semitrusted+:
2
--copies=groupname:
number
Coincide solo cuando git-annex cree que hay el número especificado de copias, en remotos en el grupo especificado. Por ejemplo, --copies=archive:
2
--lackingcopies=num
ber
Coincide solo cuando git-annex cree que se necesitan hacer el número especificado o más copias adicionales para satisfacer los ajustes de
numcopies.
--approxlackingcopies=num
ber
Como lackingcopies, pero no mira los ajustes annex.numcopies de .gitattributes. Esto lo hace significativamente más
rápido.
--inbackend=n
ame
Coincide solo cuando el contenido está almacenado usando el backend clave-valor
especificado.
--secureha
sh
Coincide solo cuando el contenido se ha resumido (hash) usando una función criptográficamente
segura.
--inallgroup=groupn
ame
Coincide solo cuando git-annex cree que el contenido está presente en todos los repositorios del grupo
especificado.
--onlyingroup=groupn
ame
Coincide solo cuando git-annex cree que el contenido está presente en al menos un repositorio que está en el grupo especificado, y no está presente en ningún repositorio que no esté en el grupo
especificado.
--smallerthan=s
ize
--largerthan=s
ize
Coincide solo cuando el contenido es más pequeño que, o más grande que el tamaño
especificado.
El tamaño puede especificarse con cualquier unidad comúnmente usada, por ejemplo, "0.5 gb" o "100
KiloBytes"
--metadata
field=glob
Coincide solo cuando hay un campo de metadatos adjunto con un valor que coincide con el glob. Los valores de los campos de metadatos se comparan sin distinguir mayúsculas de
minúsculas.
--metadata field<value / --metadata field>
value
--metadata field<=value / --metadata field>
=value
Coincide solo cuando hay un campo de metadatos adjunto con un valor que es menor o mayor que el valor especificado,
respectivamente.
Cuando ambos valores son números, la comparación se hace numéricamente. Cuando uno de los valores no es un número, los valores se comparan lexicográficamen
te.
(Tenga en cuenta que necesitará entrecomillar el segundo parámetro para evitar que el shell haga una redirección.
)
--url=gl
ob
Coincide cuando el contenido está registrado como presente en una url que coincide con el
glob.
--want-g
et
Coincide solo cuando los ajustes de contenido preferido para el repositorio local hacen que quiera obtener el contenido. Tenga en cuenta que esto coincidirá incluso cuando el contenido ya esté presente, a menos que se limite con, por ejemplo, --not
--in=here
--want-dr
op
Coincide solo cuando los ajustes de contenido preferido para el repositorio local hacen que quiera eliminar el contenido. Tenga en cuenta que esto coincidirá incluso cuando el contenido no esté presente, a menos que se limite con, por ejemplo, --not
--in=here
Las cosas con las que esto coincide no necesariamente serán eliminado por git-annex drop --auto. Esto no comprueba que haya suficientes copias para eliminar. Además, el mismo contenido puede ser usado por un archivo que no se desea
eliminar.
--want-get-by=reposit
ory
Coincide solo cuando la configuración de contenido preferido para el repositorio especificado hace que quiera obtener contenido. Ten en cuenta que esto coincidirá incluso cuando el contenido ya esté presente en ese repositorio, a menos que se limite con, por ejemplo, --not
--in=repository
El repositorio debe especificarse usando el nombre de un remoto configurado, o el UUID o la descripción de un repositorio. --want-get-by=here es lo mismo que --want-ge
t.
--want-drop-by=reposit
ory
Coincide solo cuando la configuración de contenido preferido para el repositorio especificado hace que quiera eliminar contenido. Ten en cuenta que esto coincidirá incluso cuando el contenido no esté presente, a menos que se limite con, por ejemplo, --not
--in=repository
El repositorio debe especificarse usando el nombre de un remoto configurado, o el UUID o la descripción de un repositorio. --want-drop-by=here es lo mismo que --want-dro
p.
--accessedwithin=inter
val
Coincide cuando el contenido fue accedido recientemente, dentro del intervalo de tiempo
especificado.
El intervalo puede tener la forma "5m" o "1h" o "2d" o "1y", o una combinación como
"1h5m".
Así que, por ejemplo, --accessedwithin=1d coincide cuando el contenido fue accedido dentro del último
día.
Si el sistema operativo o el sistema de archivos no soportan tiempos de acceso, esto no coincidirá con
nada.
--unlock
ed
Coincide con archivos anexados que están
desbloqueados.
--lock
ed
Coincide con archivos anexados que están
bloqueados.
--mimetype=g
lob
Busca el tipo MIME de un archivo y comprueba si el glob coincide con
él.
Por ejemplo, --mimetype="text/*" coincidirá con muchas variedades de archivos de texto, incluyendo "text/plain", pero también "text/x-shellscript", "text/x-makefile",
etc.
Los tipos MIME son los mismos que se muestran al ejecutar file
--mime-type
Si el contenido anexado del archivo no está presente, el archivo no
coincidirá.
Esto solo está disponible para usar cuando git-annex fue compilado con la bandera de compilación
MagicMime.
--mimeencoding=g
lob
Busca la codificación MIME de un archivo y comprueba si el glob coincide con
ella.
Por ejemplo, --mimeencoding=binary coincidirá con muchos tipos de archivos
binarios.
Las codificaciones MIME son las mismas que se muestran al ejecutar file
--mime-encoding
Si el contenido anexado del archivo no está presente, el archivo no
coincidirá.
Esto solo está disponible para usar cuando git-annex fue compilado con la bandera de compilación
MagicMime.
--anythi
ng
Siempre coincide. Una forma en que esto puede ser útil es git-annex find --anything listará todos los archivos anexados, ya sea que su contenido esté presente o
no.
--nothi
ng
Nunca coincide. (Lo mismo que --not --any
thing)
--n
ot
Invierte la siguiente opción de coincidencia. Por ejemplo, para coincidir cuando hay menos de 3 copias, usa --not
--copies=3
--a
nd
Requiere que tanto la opción de coincidencia anterior como la siguiente coincidan. El valor
predeterminado.
--
or
Requiere que la opción de coincidencia anterior o la siguiente
coincidan.
-
(
Abre un grupo de opciones de
coincidencia.
-
)
Cierra un g
rupo de opc
iones de co
incidencia.
