USO DE --REFRESH

--refresh no calcula un nuevo archivo sha1 ni actualiza el índice con cambios de modo/contenido. Lo que sí hace es "volver a emparejar" la información de estado de un archivo con el índice, de modo que puedes actualizar el índice para un archivo que no ha sido modificado pero cuya entrada de estado está desactualizada.

Por ejemplo, querrás hacer esto después de ejecutar un git read-tree, para vincular los detalles del índice de estado con los archivos correctos.

USO DE --CACHEINFO O --INFO-ONLY

--cacheinfo se utiliza para registrar un archivo que no se encuentra en el directorio de trabajo actual. Esto es útil para fusiones de checkout mínimo.

Para simular que tienes un archivo en la ruta con modo y sha1, di:

$ git update-index --add --cacheinfo <modo>,<sha1>,<ruta>

--info-only se utiliza para registrar archivos sin colocarlos en la base de datos de objetos. Esto es útil para repositorios de solo estado.

Tanto --cacheinfo como --info-only se comportan de manera similar: el índice se actualiza pero la base de datos de objetos no. --cacheinfo es útil cuando el objeto está en la base de datos pero el archivo no está disponible localmente. --info-only es útil cuando el archivo está disponible, pero no deseas actualizar la base de datos de objetos.

USO DE --INDEX-INFO

--index-info es un mecanismo más potente que te permite alimentar definiciones de múltiples entradas desde la entrada estándar, y está diseñado específicamente para scripts. Puede aceptar entradas de tres formatos:

1. modo ESPACIO tipo ESPACIO sha1 TAB ruta

Este formato es para introducir la salida de git ls-tree en el índice.

2. modo ESPACIO sha1 ESPACIO etapa TAB ruta

Este formato es para colocar etapas de orden superior en el archivo de índice y coincide con la salida de git ls-files --stage.

3. modo ESPACIO sha1 TAB ruta

Este formato ya no es producido por ningún comando de Git, pero es y seguirá siendo compatible con update-index --index-info.

Para colocar una entrada de etapa superior en el índice, la ruta primero debe eliminarse alimentando una entrada con modo=0 para la ruta, y luego alimentando las líneas de entrada necesarias en el tercer formato.

Por ejemplo, comenzando con este índice:

$ git ls-files -s
100644 8a1218a1024a212bb3db30becd860315f9f3ac52 0       frotz

puedes alimentar la siguiente entrada a --index-info:

$ git update-index --index-info
0 0000000000000000000000000000000000000000      frotz
100644 8a1218a1024a212bb3db30becd860315f9f3ac52 1       frotz
100755 8a1218a1024a212bb3db30becd860315f9f3ac52 2       frotz

La primera línea de la entrada alimenta 0 como modo para eliminar la ruta; el SHA-1 no importa siempre que esté bien formateado. Luego, la segunda y tercera línea alimentan las etapas 1 y 2 para esa ruta. Después de lo anterior, terminaríamos con esto:

$ git ls-files -s
100644 8a1218a1024a212bb3db30becd860315f9f3ac52 1       frotz
100755 8a1218a1024a212bb3db30becd860315f9f3ac52 2       frotz

USO DEL BIT “ASUMIR SIN CAMBIOS”

Muchas operaciones en Git dependen de que tu sistema de archivos tenga una implementación eficiente de lstat(2), para que la información st_mtime de los archivos del árbol de trabajo se pueda verificar fácilmente para ver si el contenido del archivo ha cambiado desde la versión registrada en el archivo de índice. Desafortunadamente, algunos sistemas de archivos tienen un lstat(2) ineficiente. Si tu sistema de archivos es uno de ellos, puedes establecer el bit "asumir sin cambios" para las rutas que no has modificado para que Git no realice esta verificación. Ten en cuenta que establecer este bit en una ruta no significa que Git verificará el contenido del archivo para ver si ha cambiado, sino que hace que Git omita cualquier verificación y asuma que **no** ha cambiado. Cuando realices cambios en los archivos del árbol de trabajo, deberás informar explícitamente a Git eliminando el bit "asumir sin cambios", ya sea antes o después de modificarlos.

Para establecer el bit "asumir sin cambios", usa la opción --assume-unchanged. Para desestablecerlo, usa --no-assume-unchanged. Para ver qué archivos tienen el bit "asumir sin cambios" establecido, usa git ls-files -v (ver git-ls-files(1)).

El comando examina la variable de configuración core.ignorestat. Cuando esta es verdadera, las rutas actualizadas con git update-index paths... y las rutas actualizadas con otros comandos de Git que actualizan tanto el índice como el árbol de trabajo (por ejemplo, git apply --index, git checkout-index -u y git read-tree -u) se marcan automáticamente como "asumir sin cambios". Ten en cuenta que el bit "asumir sin cambios" **no** se establece si git update-index --refresh encuentra que el archivo del árbol de trabajo coincide con el índice (usa git update-index --really-refresh si deseas marcarlos como "asumir sin cambios").

A veces los usuarios confunden el bit asumir sin cambios con el bit skip-worktree. Ver el último párrafo de la sección "Bit skip-worktree" a continuación para una explicación de las diferencias.

EJEMPLOS

Para actualizar y refrescar solo los archivos ya extraídos:

$ git checkout-index -n -f -a && git update-index --ignore-missing --refresh

En un sistema de archivos ineficiente con core.ignorestat establecido

$ git update-index --really-refresh              (1)
$ git update-index --no-assume-unchanged foo.c   (2)
$ git diff --name-only                           (3)
$ edit foo.c
$ git diff --name-only                           (4)
M foo.c
$ git update-index foo.c                         (5)
$ git diff --name-only                           (6)
$ edit foo.c
$ git diff --name-only                           (7)
$ git update-index --no-assume-unchanged foo.c   (8)
$ git diff --name-only                           (9)
M foo.c
1. fuerza lstat(2) para establecer bits de "asumir sin cambios" para rutas que coinciden con el índice.
2. marca la ruta para editarla.
3. realiza lstat(2) y encuentra que el índice coincide con la ruta.
4. realiza lstat(2) y encuentra que el índice **no** coincide con la ruta.
5. registrar la nueva versión en el índice establece el bit de "asumir sin cambios".
6. y se asume sin cambios.
7. incluso después de editarlo.
8. puedes informar del cambio después de que ocurra.
9. ahora comprueba con lstat(2) y encuentra que ha sido modificado.

BIT SKIP-WORKTREE

El bit skip-worktree se puede definir en una frase larga: Indica a git que evite escribir el archivo en el directorio de trabajo cuando sea razonablemente posible, y que trate el archivo como sin cambios cuando no esté presente en el directorio de trabajo.

Ten en cuenta que no todos los comandos de git prestarán atención a este bit, y algunos solo lo admiten parcialmente.

Las banderas de update-index y las capacidades de read-tree relacionadas con el bit skip-worktree precedieron a la introducción del comando git-sparse-checkout(1), que proporciona una forma mucho más sencilla de configurar y gestionar los bits skip-worktree. Si deseas reducir tu árbol de trabajo para tratar solo un subconjunto de los archivos en el repositorio, te animamos encarecidamente a usar git-sparse-checkout(1) en lugar de las primitivas de bajo nivel update-index y read-tree.

El propósito principal del bit skip-worktree es permitir los checkouts dispersos, es decir, tener directorios de trabajo con solo un subconjunto de rutas presentes. Cuando el bit skip-worktree está establecido, los comandos de Git (como switch, pull, merge) evitarán escribir estos archivos. Sin embargo, estos comandos a veces escribirán estos archivos de todos modos en casos importantes, como conflictos durante una fusión o rebase. Los comandos de Git también evitarán tratar la ausencia de estos archivos como una eliminación intencional; por ejemplo, git add -u no marcará una eliminación para estos archivos y git commit -a no realizará una confirmación eliminándolos.

Aunque este bit parece similar al bit assume-unchanged, su objetivo es diferente. El bit assume-unchanged es para dejar el archivo en el árbol de trabajo pero hacer que Git omita su verificación de cambios y presuma que el archivo no ha cambiado (aunque si puede determinar sinut stat’ing el archivo para indicar que ha cambiado, es libre de registrar los cambios). skip-worktree le indica a Git que ignore la ausencia del archivo, evite actualizarlo cuando sea posible con comandos que normalmente actualizan gran parte del directorio de trabajo (por ejemplo, checkout, switch, pull, etc.), y que la ausencia del archivo no se registre en los commits. Ten en cuenta que en checkouts dispersos (configurados por git sparse-checkout o configurando core.sparseCheckout a true),

si un archivo está marcado como skip-worktree en el í
