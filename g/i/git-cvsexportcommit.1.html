GIT-CVSEXPORTCOMMIT(1) Manual de Git GIT-CVSEXPORTCOMMIT(1)

NOMBRE

git-cvsexportcommit - Exportar un único commit a un checkout de CVS

SINOPSIS

git cvsexportcommit [-h] [-u] [-v] [-c] [-P] [-p] [-a] [-d <cvsroot>]
        [-w <cvs-workdir>] [-W] [-f] [-m <prefijo-msg>] [<commit-padre>] <id-commit>

DESCRIPCIÓN

Exporta un commit de Git a un checkout de CVS, facilitando la fusión de parches de un repositorio Git a un repositorio CVS.

Especifique el nombre de un checkout de CVS usando el interruptor -w o ejecútelo desde la raíz de la copia de trabajo de CVS. En este último caso, GIT_DIR debe estar definido. Ver ejemplos a continuación.

Hace todo lo posible para actuar de forma segura, verificará que los archivos no han sido modificados y están actualizados en el checkout de CVS, y no hará commit automático por defecto.

Soporta adiciones, eliminaciones y commits de archivos que afectan a archivos binarios.

Si el commit es un commit de fusión, debe indicar a git cvsexportcommit contra qué padre se debe realizar el cambio de conjunto.

OPCIONES

-c

Hace commit automáticamente si el parche se aplicó limpiamente. No hará commit si alguna parte falla al aplicarse o si hubo otros problemas.

-p

Sé pedante (paranoico) al aplicar parches. Invoca patch con --fuzz=0

-a

Añade información de autoría. Añade la línea de Autor, y el Responsable (si es diferente del Autor) al mensaje.

-d

Establece un CVSROOT alternativo a usar. Esto corresponde al parámetro -d de CVS. Normalmente los usuarios no querrán establecer esto, excepto si usan CVS de forma asimétrica.

-f

Fuerza la fusión incluso si los archivos no están actualizados.

-P

Fuerza el commit padre, incluso si no es un padre directo.

-m

Añade el prefijo proporcionado al mensaje de commit. Útil para series de parches y similares.

-u

Actualiza los archivos afectados desde el repositorio CVS antes de intentar la exportación.

-k

Invierte la expansión de palabras clave de CVS (por ejemplo, $Revision: 1.2.3.4$ se convierte en $Revision$) en la copia de trabajo de CVS antes de aplicar el parche.

-w

Especifica la ubicación del checkout de CVS a usar para la exportación. Esta opción no requiere que GIT_DIR se establezca antes de la ejecución si el directorio actual está dentro de un repositorio Git. El valor predeterminado es el valor de cvsexportcommit.cvsdir.

-W

Indica a cvsexportcommit que el directorio de trabajo actual no es solo un checkout de Git, sino también el checkout de CVS. Por lo tanto, Git restaurará el directorio de trabajo al commit padre antes de continuar.

-v

Verboso.

CONFIGURACIÓN

cvsexportcommit.cvsdir

La ubicación predeterminada del checkout de CVS a usar para la exportación.

EJEMPLOS

Fusionar un parche en CVS

$ export GIT_DIR=~/proyecto/.git
$ cd ~/checkout_proyecto_cvs
$ git cvsexportcommit -v <commit-sha1>
$ cvs commit -F .msg <archivos>

Fusionar un parche en CVS (opciones -c y -w). El directorio de trabajo está dentro del Repositorio Git

        $ git cvsexportcommit -v -c -w ~/checkout_proyecto_cvs <commit-sha1>

Fusionar parches pendientes en CVS automáticamente — solo si realmente sabes lo que estás haciendo

$ export GIT_DIR=~/proyecto/.git
$ cd ~/checkout_proyecto_cvs
$ git cherry cvshead myhead | sed -n 's/^+ //p' | xargs -l1 git cvsexportcommit -c -p -v
