GIT-REMOTE-EXT(1) Manual de Git GIT-REMOTE-EXT(1)

NOMBRE

git-remote-ext - Puente de transporte inteligente a un comando externo.

SINOPSIS

git remote add <apodo> "ext::<comando>[ <argumentos>...]"

DESCRIPCIÓN

Este asistente de remoto utiliza el <comando> especificado para conectarse a un servidor Git remoto.

Se asume que los datos escritos en la entrada estándar del <comando> especificado se envían a un servidor git://, git-upload-pack, git-receive-pack o git-upload-archive (según la situación), y se asume que los datos leídos de la salida estándar del <comando> se reciben del mismo servicio.

El comando y los argumentos están separados por un espacio sin escapar.

Las siguientes secuencias tienen un significado especial:

'% '

Espacio literal en el comando o argumento.

%%

Signo de porcentaje literal.

%s

Se reemplaza con el nombre (receive-pack, upload-pack, o upload-archive) del servicio que Git quiere invocar.

%S

Se reemplaza con el nombre largo (git-receive-pack, git-upload-pack, o git-upload-archive) del servicio que Git quiere invocar.

%G (debe ser los primeros caracteres de un argumento)

Este argumento no se pasará al <comando>. En su lugar, hará que el asistente comience enviando solicitudes de servicio git:// al lado remoto con el campo de servicio configurado al valor apropiado y el campo de repositorio configurado al resto del argumento. Por defecto, no se envía dicha solicitud.

Esto es útil si el lado remoto es un servidor git:// accedido a través de algún túnel.

%V (debe ser los primeros caracteres de un argumento)

Este argumento no se pasará al <comando>. En su lugar, establece el campo vhost en la solicitud de servicio git:// (al resto del argumento). Por defecto, no se envía vhost en dicha solicitud (si se envía).

VARIABLES DE ENTORNO

GIT_TRANSLOOP_DEBUG

Si está configurado, imprime información de depuración sobre varias lecturas/escrituras.

VARIABLES DE ENTORNO PASADAS AL COMANDO

GIT_EXT_SERVICE

Configurado con el nombre largo (git-upload-pack, etc...) del servicio que el asistente necesita invocar.

GIT_EXT_SERVICE_NOPREFIX

Configurado con el nombre largo (upload-pack, etc...) del servicio que el asistente necesita invocar.

EJEMPLOS

Este asistente de remoto es utilizado transparentemente por Git cuando utilizas comandos como "git fetch <URL>", "git clone <URL>", , "git push <URL>" o "git remote add <apodo> <URL>", donde <URL> comienza con ext::. Ejemplos:

"ext::ssh -i /home/foo/.ssh/alguna_clave usuario@host.ejemplo %S foo/repo"

Similar a host.ejemplo:foo/repo, pero utiliza /home/foo/.ssh/alguna_clave como par de claves y usuario como el usuario en el lado remoto. Esto evita la necesidad de editar .ssh/config.

"ext::socat -t3600 - ABSTRACT-CONNECT:/git-server %G/somerepo"

Representa un repositorio con la ruta /somerepo accesible a través del protocolo git en la dirección de espacio de nombres abstracto /git-server.

"ext::git-server-alias foo %G/repo"

Representa un repositorio con la ruta /repo accedido utilizando el programa asistente "git-server-alias foo". La ruta al repositorio y el tipo de solicitud no se pasan en la línea de comandos, sino como parte del flujo del protocolo, como es habitual con el protocolo git://.

"ext::git-server-alias foo %G/repo %Vfoo"

Representa un repositorio con la ruta /repo accedido utilizando el programa asistente "git-server-alias foo". El nombre de host para el servidor remoto pasado en el flujo del protocolo será "foo" (esto permite que varios servidores Git virtuales compartan una dirección a nivel de enlace).

"ext::git-server-alias foo %G/repo% con% espacios %Vfoo"

Representa un repositorio con la ruta /repo con espacios accedido utilizando el programa asistente "git-server-alias foo". El nombre de host para el servidor remoto pasado en el flujo del protocolo será "foo" (esto permite que varios servidores Git virtuales compartan una dirección a nivel de enlace).

"ext::git-ssl foo.ejemplo /bar"

Representa un repositorio accedido utilizando el programa asistente "git-ssl foo.ejemplo /bar". El tipo de solicitud puede ser determinado por el asistente utilizando variables de entorno (ver arriba).
