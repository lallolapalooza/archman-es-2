NOMBRE

git-ls-tree - Lista el contenido de un objeto tree

SINOPSIS

git ls-tree [-d] [-r] [-t] [-l] [-z]
            [--name-only] [--name-status] [--object-only] [--full-name] [--full-tree] [--abbrev[=<n>]] [--format=<formato>]
            <tree-ish> [<ruta>...]

DESCRIPCIÓN

Lista el contenido de un objeto tree dado, similar a lo que hace "/bin/ls -a" en el directorio de trabajo actual. Nótese que:

•El comportamiento es ligeramente diferente al de "/bin/ls" en que la <ruta> denota solo una lista de patrones a coincidir, por ejemplo, especificar un nombre de directorio (sin -r) se comportará de manera diferente, y el orden de los argumentos no importa.
•El comportamiento es similar al de "/bin/ls" en que la <ruta> se toma como relativa al directorio de trabajo actual. Por ejemplo, cuando estás en un directorio sub que tiene un directorio dir, puedes ejecutar git ls-tree -r HEAD dir para listar el contenido del tree (que es sub/dir en HEAD). No querrás dar un tree que no esté en el nivel raíz (por ejemplo, git ls-tree -r HEAD:sub dir) en este caso, ya que eso resultaría en una solicitud de sub/sub/dir en el commit HEAD. Sin embargo, el directorio de trabajo actual puede ser ignorado al pasar la opción --full-tree.

OPCIONES

<tree-ish>

ID de un tree-ish.

-d

Muestra solo la entrada del tree nombrada en sí misma, no sus hijos.

-r

Recursivamente en los sub-trees.

-t

Muestra las entradas del tree incluso cuando se va a recursarlas. No tiene efecto si no se pasó -r. -d implica -t.

-l, --long

Muestra el tamaño del objeto de las entradas blob (archivo).

-z

Terminación de línea \0 en la salida y no cita los nombres de archivo. Consulte FORMATO DE SALIDA a continuación para más información.

--name-only, --name-status

Lista solo los nombres de archivo (en lugar de la salida "larga"), uno por línea. No se puede combinar con --object-only.

--object-only

Lista solo los nombres de los objetos, uno por línea. No se puede combinar con --name-only o --name-status. Esto es equivalente a especificar --format='%(objectname)', pero tanto para esta opción como para ese formato exacto, el comando toma una ruta de código optimizada a mano en lugar de pasar por el mecanismo de formateo genérico.

--abbrev[=<n>]

En lugar de mostrar las líneas de objeto hexadecimales completas de 40 bytes, muestra el prefijo más corto que tenga al menos <n> dígitos hexadecimales de longitud que se refiera de forma única al objeto. Se puede especificar un número de dígitos no predeterminado con --abbrev=<n>.

--full-name

En lugar de mostrar los nombres de ruta relativos al directorio de trabajo actual, muestra los nombres de ruta completos.

--full-tree

No limita la lista al directorio de trabajo actual. Implica --full-name.

--format=<formato>

Una cadena que interpola %(nombrecampo) del resultado que se está mostrando. También interpola %% a %, y %xNN donde NN son dígitos hexadecimales se interpola al carácter con código hexadecimal NN; por ejemplo, %x00 se interpola a \0 (NUL), %x09 a \t (TAB) y %x0a a \n (LF). Cuando se especifica, --format no se puede combinar con otras opciones que alteran el formato, incluidas --long, --name-only y --object-only.

[<ruta>...]

Cuando se proporcionan rutas, las muestra (tenga en cuenta que estas no son realmente rutas de acceso en bruto, sino una lista de patrones a coincidir). De lo contrario, utiliza implícitamente el nivel raíz del tree como el único argumento de ruta.

FORMATO DE SALIDA

El formato de salida de ls-tree está determinado por la opción --format, u otras opciones que alteran el formato como --name-only etc. (consulte --format arriba).

El uso de ciertas directivas de --format es equivalente a usar esas opciones, pero invocar la maquinaria de formateo completa puede ser más lento que usar una opción de formateo adecuada.

En casos donde el --format se mapearía exactamente a una opción existente, ls-tree usará la ruta más rápida apropiada. Por lo tanto, el formato predeterminado es equivalente a:

%(objectmode) %(objecttype) %(objectname)%x09%(path)

Este formato de salida es compatible con lo que espera git update-index con las opciones --index-info --stdin.

Cuando se usa la opción -l, el formato cambia a

%(objectmode) %(objecttype) %(objectname) %(objectsize:padded)%x09%(path)

El tamaño del objeto identificado por <objectname> se da en bytes y está justificado a la derecha con un ancho mínimo de 7 caracteres. El tamaño del objeto solo se da para entradas blob (archivo); para otras entradas se usa el carácter - en lugar del tamaño.

Sin la opción -z, los nombres de ruta con caracteres "inusuales" se citan como se explica para la variable de configuración core.quotePath (consulte git-config(1)). Usando -z, el nombre de archivo se saca textualmente y la línea termina con un byte NUL.

Formato personalizado:

Es posible imprimir en un formato personalizado usando la opción --format, que es capaz de interpolar diferentes campos usando la notación %(nombrecampo). Por ejemplo, si solo te importan los campos "objectname" y "path", puedes ejecutar con un "--format" específico como

git ls-tree --format='%(objectname) %(path)' <tree-ish>

NOMBRES DE CAMPO

Se pueden usar varios valores de campos estructurados para interpolar en la salida resultante. Para cada línea de salida, se pueden usar los siguientes nombres:

objectmode

El modo del objeto.

objecttype

El tipo del objeto (commit, blob o tree).

objectname

El nombre del objeto.

objectsize[:padded]

El tamaño de un objeto blob ("-" si es un commit o tree). También admite un formato acolchado del tamaño con "%(objectsize:padded)".

path

El nombre de ruta del objeto.
