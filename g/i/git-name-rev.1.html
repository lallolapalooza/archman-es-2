NOMBRE

git-name-rev - Encontrar nombres simbólicos para revisiones dadas

SINOPSIS

git name-rev [--tags] [--refs=<patrón>]
               ( --all | --annotate-stdin | <commit-ish>... )

DESCRIPCIÓN

Encuentra nombres simbólicos adecuados para la digestión humana para revisiones dadas en cualquier formato analizable por git rev-parse.

OPCIONES

--tags

No utilizar nombres de rama, sino solo etiquetas para nombrar los commits

--refs=<patrón>

Solo usar refs cuyos nombres coincidan con un patrón de shell dado. El patrón puede ser un nombre de rama, un nombre de etiqueta o un nombre de ref completamente calificado. Si se da varias veces, usar refs cuyos nombres coincidan con cualquiera de los patrones de shell dados. Usar --no-refs para borrar cualquier patrón de ref previo dado.

--exclude=<patrón>

No usar ninguna ref cuyo nombre coincida con un patrón de shell dado. El patrón puede ser uno de nombre de rama, nombre de etiqueta o nombre de ref completamente calificado. Si se da varias veces, una ref será excluida cuando coincida con cualquiera de los patrones dados. Cuando se usa junto con --refs, una ref se usará como coincidencia solo cuando coincida con al menos un patrón --refs y no coincida con ningún patrón --exclude. Usar --no-exclude para borrar la lista de patrones de exclusión.

--all

Listar todos los commits alcanzables desde todos los refs

--annotate-stdin

Transformar stdin sustituyendo todos los hashes hex de SHA-1 de 40 caracteres (digamos $hex) con "$hex ($rev_name)". Cuando se usa con --name-only, sustituir con "$rev_name", omitiendo $hex por completo. Esta opción se llamaba --stdin en versiones anteriores de Git.

Por ejemplo:

$ cat sample.txt
Una revisión abreviada 2ae0a9cb82 no será sustituida.
El nombre completo después de la sustitución es 2ae0a9cb8298185a94e5998086f380a355dd8907,
mientras que su objeto de árbol es 70d105cc79e63b81cfdcb08a15297c23e60b07ad
$ git name-rev --annotate-stdin <sample.txt
Una revisión abreviada 2ae0a9cb82 no será sustituida.
El nombre completo después de la sustitución es 2ae0a9cb8298185a94e5998086f380a355dd8907 (master),
mientras que su objeto de árbol es 70d105cc79e63b81cfdcb08a15297c23e60b07ad
$ git name-rev --name-only --annotate-stdin <sample.txt
Una revisión abreviada 2ae0a9cb82 no será sustituida.
El nombre completo después de la sustitución es master,
mientras que su objeto de árbol es 70d105cc79e63b81cfdcb08a15297c23e60b07ad

--name-only

En lugar de imprimir tanto el SHA-1 como el nombre, imprimir solo el nombre. Si se da con --tags, el prefijo de etiqueta habitual de "tags/" también se omite del nombre, coincidiendo más de cerca con la salida de git-describe.

--no-undefined

Morir con código de error != 0 cuando una referencia no está definida, en lugar de imprimir undefined.

--always

Mostrar el commit object abreviado de forma única como último recurso.

EJEMPLOS

Dado un commit, averiguar dónde se encuentra en relación con los refs locales. Digamos que alguien te escribió sobre ese fantástico commit 33db5f4d9027a10e477ccf054b2c1ab94f74c85a. Por supuesto, miras el commit, pero eso solo te dice qué sucedió, no el contexto.

Introduce git name-rev:

% git name-rev 33db5f4d9027a10e477ccf054b2c1ab94f74c85a
33db5f4d9027a10e477ccf054b2c1ab94f74c85a tags/v0.99~940

Ahora eres más sabio, porque sabes que ocurrió 940 revisiones antes de v0.99.

Otra cosa interesante que puedes hacer es:

% git log | git name-rev --annotate-stdin
