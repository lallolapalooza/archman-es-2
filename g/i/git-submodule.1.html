OPCIONES

--checkout

Esta opción solo es válida para el comando update. Hacer checkout del commit registrado en el superproyecto en un HEAD separado en el submódulo. Este es el comportamiento por defecto, el uso principal de esta opción es para anular submodule.$name.update cuando se establece a un valor distinto de checkout. Si la clave submodule.$name.update no está explícitamente establecida o está establecida a checkout, esta opción es implícita.

--merge

Esta opción solo es válida para el comando update. Fusionar el commit registrado en el superproyecto en la rama actual del submódulo. Si se proporciona esta opción, el HEAD del submódulo no estará separado. Si un fallo de fusión impide este proceso, deberás resolver los conflictos resultantes dentro del submódulo con las herramientas habituales de resolución de conflictos. Si la clave submodule.$name.update está establecida a merge, esta opción es implícita.

--rebase

Esta opción solo es válida para el comando update. Reorganizar la rama actual sobre el commit registrado en el superproyecto. Si se proporciona esta opción, el HEAD del submódulo no estará separado. Si un fallo de fusión impide este proceso, deberás resolver estos fallos con git-rebase(1). Si la clave submodule.$name.update está establecida a rebase, esta opción es implícita.

--init

Esta opción solo es válida para el comando update. Inicializar todos los submódulos para los cuales no se ha llamado aún a "git submodule init" antes de actualizar.

--name

Esta opción solo es válida para el comando add. Establece el nombre del submódulo a la cadena dada en lugar de usar su ruta por defecto. El nombre debe ser válido como nombre de directorio y no puede terminar con un /.

--reference <repository>

Estas opciones solo son válidas para los comandos add y update. Estos comandos a veces necesitan clonar un repositorio remoto. En este caso, esta opción se pasará al comando git-clone(1).

NOTA: NO uses esta opción a menos que hayas leído cuidadosamente la nota para las opciones --reference, --shared y --dissociate de git-clone(1).

--dissociate

Estas opciones solo son válidas para los comandos add y update. Estos comandos a veces necesitan clonar un repositorio remoto. En este caso, esta opción se pasará al comando git-clone(1).

NOTA: ver la NOTA para la opción --reference.

--recursive

Esta opción solo es válida para los comandos foreach, update, status y sync. Recorre los submódulos recursivamente. La operación se realiza no solo en los submódulos del repositorio actual, sino también en cualquier submódulo anidado dentro de esos submódulos (y así sucesivamente).

--depth

Esta opción es válida para los comandos add y update. Crea un clon superficial con un historial truncado al número de revisiones especificado. Ver git-clone(1)

--recommend-shallow, --no-recommend-shallow

Esta opción solo es válida para el comando update. La clonación inicial de un submódulo usará por defecto el submodule.<name>.shallow recomendado, tal como se proporciona en el archivo .gitmodules. Para ignorar las sugerencias, usa --no-recommend-shallow.

-j <n>, --jobs <n>

Esta opción solo es válida para el comando update. Clona nuevos submódulos en paralelo con tantos trabajos como sea posible. Por defecto, se usa la opción submodule.fetchJobs.

--single-branch, --no-single-branch

Esta opción solo es válida para el comando update. Clona solo una rama durante la actualización: HEAD o una especificada por --branch.

<path>...

Rutas a submódulos. Cuando se especifican, restringirán el comando para que opere solo en los submódulos encontrados en las rutas especificadas. (Este argumento es obligatorio con add).

ARCHIVOS

Al inicializar submódulos, se utiliza un archivo .gitmodules en el directorio principal del repositorio contenedor para encontrar la URL de cada submódulo. Este archivo debe tener el mismo formato que $GIT_DIR/config. La clave para cada URL de submódulo es "submodule.$name.url". Ver gitmodules(5) para detalles.
