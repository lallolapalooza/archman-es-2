DESCRIPCIÓ

N

Crea un archivo del formato especificado que contiene la estructura de árbol del árbol con nombre, y lo escribe en la salida estándar. Si se especifica <prefix>, se antepone a los nombres de archivo en el

archivo.

git archive se comporta de manera diferente cuando se le da un ID de árbol en lugar de un ID de commit o de etiqueta. Cuando se proporciona un ID de árbol, se usa la hora actual como hora de modificación de cada archivo en el archivo. Por otro lado, cuando se proporciona un ID de commit o de etiqueta, se usa la hora del commit registrada en el objeto commit referenciado. Además, el ID del commit se almacena en una cabecera pax extendida global si se usa el formato tar; se puede extraer usando git get-tar-commit-id. En los archivos ZIP

se almacena como un
comentario de archivo.

OPCIONE

S

--format=<fmt

>
Formato del archivo resultante. Los valores posibles son tar, zip, tar.gz, tgz, y cualquier formato definido usando la opción de configuración tar.<format>.command. Si --format no se proporciona, y se especifica el archivo de salida, el formato se infiere del nombre de archivo si es posible (por ejemplo, escribir en foo.zip hace que la salida esté en el formato zip). De lo contrario, el formato de salida es tar
.

-l,

--list
Muestra todos los formatos
disponibles.

-v,

--verbose
Informa del progreso a
stderr.

--prefix=<prefix>

/
Antepone <prefix>/ a las rutas en el archivo. Puede repetirse; se usa su valor más a la derecha para todos los archivos rastreados. Vea más abajo qué valor usa --add-file
.

-o <file>,

--output=<file>
Escribe el archivo en <file> en lugar de
stdout.

--add-file=<file

>
Añade un archivo no rastreado al archivo. Puede repetirse para añadir múltiples archivos. La ruta del archivo en el archivo se construye concatenando el valor de la última opción --prefix (si hay alguna) antes de este --add-file y el nombre base de <file>
.

--add-virtual-file=<path>:

<content>
Añade el contenido especificado al archivo. Puede repetirse para añadir múltiples archivos.

El argumento <path> puede empezar y terminar con un carácter de comilla doble literal; el nombre de archivo contenido se interpreta como una cadena estilo C, es decir, la barra invertida se interpreta como carácter de escape. La ruta debe estar entre comillas si contiene dos puntos, para evitar que los dos puntos se interpreten erróneamente como el separador entre la ruta y el contenido, o si la ruta empieza o termina con un carácter de comilla

doble.

El modo del archivo se limita a un archivo normal, y la opción puede estar sujeta a límites de línea de comandos dependientes de la plataforma. Para casos no triviales, escriba un archivo no rastreado y use --add-file en su

lugar.

Tenga en cuenta que a diferencia de --add-file, la ruta creada en el archivo no se ve afectada por la opción --prefix, ya que se puede dar una <path> completa co

mo valor de
la opción.

--worktree-attribute

s
Busca atributos también en los archivos .gitattributes en el árbol de trabajo (vea la sección llamada “ATRIBUTOS”)
.

--mtime=<time

>
Establece la hora de modificación de las entradas del archivo. Sin esta opción se usa la hora del committer si <tree-ish> es un commit o una etiqueta, y la hora actual si es un
árbol.

<extra

>
Puede ser cualquier opción que el backend del archiver entienda. Vea la siguiente
sección.

--remote=<repo

>
En lugar de crear un archivo tar del repositorio local, recupera un archivo tar de un repositorio remoto. Tenga en cuenta que el repositorio remoto puede imponer restricciones sobre qué expresiones sha1 se pueden permitir en <tree-ish>. Vea git-upload-archive(1) para más
detalles.

--exec=<git-upload-archive

>
Se usa con --remote para especificar la ruta al git-upload-archive en el lado
remoto.

<tree-ish

>
El árbol o el commit para el cual producir un
archivo.

<path

>
Sin un parámetro de ruta opcional, todos los archivos y subdir
ectorios del directorio de trabajo actual se incluyen en el archi
vo. Si se especifican una o más rutas, solo estas se incluyen.

CONFIGURACIÓ

N

tar.

umask
Esta variable se puede usar para restringir los bits de permiso de las entradas del archivo tar. El valor predeterminado es 0002, que desactiva el bit de escritura para todos. El valor especial "user" indica que se usará el umask del usuario que archiva en su lugar. Vea umask(2) para más detalles. Si --remote se usa, entonces solo la configuración del repositorio remoto tiene
efecto.

tar.<format>.

command
Esta variable especifica un comando de shell a través del cual se debe pasar la salida tar generada por git archive. El comando se ejecuta usando el shell con el archivo tar generado en su entrada estándar, y debe producir la salida final en su salida estándar. Cualquier opción de nivel de compresión se pasará al comando (por ejemplo, -9).

Los formatos tar.gz y tgz se definen automáticamente y usan el comando mágico git archive gzip por defecto, que invoca u

na implementación
interna de gzip.

tar.<format>.

remote
Si es verdadero, habilita el formato para su uso por clientes remotos a través de git-upload-archive(1). Por defecto es falso para formatos definidos por el usuario, pero verdadero para los formatos tar.gz y tg
z
.

ATRIBUTO

S

export-ignor

e
Los archivos y directorios con el atributo export-ignore no se añadirán a los archivos de archivo. Vea gitattributes(5) para más
detalles.

export-subs

t
Si el atributo export-subst está establecido para un archivo, Git expandirá varios marcadores de posición al añadir este archivo a un archivo. Vea gitattributes(5) para más
detalles.

Tenga en cuenta que los atributos se toman por defecto de los archivos .gitattributes en el árbol que se está archivando. Si desea ajustar la manera en que se genera la salida después del hecho (por ejemplo, hizo commit sin añadir un export-ignore apropiado en su .gitattributes), ajuste el archivo .gitattributes comprobado según sea necesario y use la opción --worktree-attributes. Alternativamente, puede mantener los atributos necesarios que deberían aplicarse al archivar cualquier árbol en su archivo $GIT_DIR/info/attribute

s
.
