NOMBRE

git-repair - Reparar un repositorio git roto

SINOPSIS

git-repair [--force]

DESCRIPCIÓN

Esto puede reparar un repositorio git corrupto o roto, del cual git fsck solo se quejaría de que tiene problemas.

Lo hace eliminando todos los objetos corruptos y recuperando todos los objetos faltantes que puede de los remotos del repositorio.

Si eso no es suficiente para recuperar completamente el repositorio, también puede restablecer las ramas a commits anteriores a la corrupción, eliminar ramas que ya no están disponibles debido a la pérdida de datos y eliminar archivos faltantes del índice. Solo hará esto si se ejecuta con la opción --force, ya que eso reescribe el historial y descarta los datos faltantes. Tenga en cuenta que la opción --force nunca toca las etiquetas, incluso si ya no son utilizables debido a datos faltantes.

Después de ejecutar este comando, probablemente querrá ejecutar git fsck para verificar que reparó el repositorio. Tenga en cuenta que fsck todavía puede quejarse de objetos referenciados por el reflog o el stash, si no pudieron ser recuperados. Este comando no intenta limpiar el reflog ni el stash.

Dado que este comando desempaqueta todos los packs del repositorio, es posible que desee ejecutar git gc después.

PRUEBAS

git-repair puede probarse a sí mismo, haciendo una copia temporal del repositorio git en el que se ejecuta, dañándolo de formas aleatorias y verificando que puede repararlo para que git fsck no informe ningún problema.

Esto se hace usando el parámetro --test y los parámetros asociados --numtests y --retry.

Tenga en cuenta que las pruebas a veces encontrarán repositorios que solo se pueden reparar cuando se usa --force; esto es esperado. Por otro lado, si falla en recuperar un repositorio con --force, ¡entonces las pruebas han encontrado un error!
