NOMBRE

git-lfs-prune - Elimina archivos LFS antiguos del almacenamiento local

SINOPSIS

git lfs prune [opciones]

DESCRIPCIÓN

Elimina copias locales de archivos LFS que están obsoletos, liberando así espacio en disco. Prune opera enumerando todos los objetos almacenados localmente, y luego eliminando cualquiera que no sea referenciado por al menos UNO de los siguientes:

•el checkout actual
•todos los stashes existentes
•una 'rama reciente'; ver ARCHIVOS RECIENTES
•un 'commit reciente' en la rama actual o ramas recientes; ver ARCHIVOS RECIENTES
•un commit que no ha sido subido; ver ARCHIVOS LFS NO SUBIDOS
•cualquier otro checkout de worktree; ver git-worktree(1)

En términos generales, prune eliminará archivos que no estés usando actualmente y que no sean 'recientes', siempre y cuando hayan sido subidos, es decir, la copia local no sea la única.

El reflog no se considera, solo los commits. Por lo tanto, los objetos LFS que solo son referenciados por commits huérfanos siempre se eliminan.

Nota: no debes ejecutar git lfs prune si tienes diferentes repositorios compartiendo el mismo directorio de almacenamiento personalizado; ver git-lfs-config(5) para más detalles sobre la opción lfs.storage.

En tu configuración de Git o en un archivo .lfsconfig, puedes establecer lfs.fetchexclude a una lista de rutas separadas por comas. Si lfs.fetchexclude está definida, entonces cualquier archivo Git LFS cuyas rutas coincidan con una de esa lista será eliminado a menos que sea referenciado por un stash o un commit no subido. Las rutas se comparan usando coincidencia de comodines según gitignore(5).

OPCIONES

--dry-run, -d

No elimines nada realmente, solo informa sobre lo que se habría hecho.

--force, -f

Elimina todos los objetos excepto los objetos no subidos, incluidos los objetos requeridos para las refs actualmente en checkout. Implica --recent.

--recent

Elimina incluso objetos que normalmente serían preservados por las opciones de configuración especificadas a continuación en ARCHIVOS RECIENTES.

--verify-remote, -c

Contacta al remoto y verifica que las copias de los archivos alcanzables que íbamos a eliminar definitivamente existen antes de eliminarlos. Ver VERIFICAR REMOTO.

--no-verify-remote

Deshabilita la verificación remota si lfs.pruneverifyremotealways estaba habilitado en la configuración. Ver VERIFICAR REMOTO.

--verify-unreachable

Al realizar --verify-remote, contacta al remoto y verifica también los objetos inalcanzables. Ver VERIFICAR REMOTO.

--no-verify-unreachable

Deshabilita la verificación remota de archivos inalcanzables si lfs.pruneverifyunreachablealways estaba habilitado en la configuración. Ver VERIFICAR REMOTO.

--when-unverified=<halt,continue>

Cuando --verify-remote no puede verificar un objeto en el remoto, ya sea detiene la ejecución o continúa la eliminación de objetos verificados. Ver VERIFICAR REMOTO.

--verbose, -v

Informa con todo detalle lo que se está/estaría eliminando.

ARCHIVOS RECIENTES

Prune no eliminará archivos LFS referenciados por commits 'recientes', en caso de que quieras usarlos de nuevo sin tener que descargarlos. La definición de 'reciente' se deriva de la usada por git-lfs-fetch(1) para descargar objetos recientes con la opción --recent, con un desplazamiento de un número de días (por defecto 3) para asegurar que siempre mantenemos archivos que descargas durante unos días.

Aquí están los ajustes de git-config(1) que controlan este comportamiento:

•lfs.pruneoffsetdays El número de días adicionales que se añaden a la configuración de fetch recent al usarla para decidir cuándo eliminar. Así, para que una referencia se considere lo suficientemente antigua como para ser eliminada, tiene que ser esta cantidad de días más antigua que la referencia más antigua que se descargaría a través de git lfs fetch --recent. Solo se usa si el valor de días de la configuración de fetch recent relevante no es cero. Por defecto 3 días.
•lfs.fetchrecentrefsdays lfs.fetchrecentremoterefs lfs.fetchrecentcommitsdays Estos tienen el mismo significado que git-lfs-fetch(1) con la opción --recent, se usan como base para el desplazamiento anterior. Todo lo que caiga fuera de esta ventana desplazada se considera lo suficientemente antiguo como para ser eliminado. Si un valor de días es cero, esa condición no se usa en absoluto para retener objetos y serán eliminados.

ARCHIVOS LFS NO SUBIDOS

Cuando la única copia de un archivo LFS es local, y todavía es alcanzable desde cualquier referencia, ese archivo nunca puede ser eliminado, sin importar cuán antiguo sea.

Para determinar si un archivo LFS ha sido subido, comprobamos la diferencia entre las refs locales y las refs remotas; donde la ref local está adelantada, cualquier archivo LFS referenciado en esos commits no ha sido subido y no será eliminado. Esto funciona porque el hook pre-push de LFS siempre asegura que los archivos LFS se suban antes de que la rama remota sea actualizada.

Ver REMOTE PREDETERMINADO, para saber qué remoto se considera 'subido' a efectos de eliminación.

VERIFICAR REMOTO

La opción --verify-remote llama al remoto para asegurar que cualquier archivo LFS alcanzable a ser eliminado tenga copias en el remoto antes de eliminarlos realmente.

Generalmente la comprobación realizada por ARCHIVOS LFS NO SUBIDOS es suficiente para determinar que los archivos han sido subidos, pero si quieres estar extra seguro a costa de una sobrecarga adicional, puedes hacer que prune llame realmente a la API remota y verifique la presencia de los archivos que estás a punto de eliminar localmente. Ver REMOTE PREDETERMINADO para saber qué remoto se verifica.

Puedes hacer que este comportamiento sea el predeterminado estableciendo lfs.pruneverifyremotealways a true.

Además de la sobrecarga de llamar al remoto, usar esta opción también requiere que prune distinga entre archivos totalmente inalcanzables (por ejemplo, aquellos que se añadieron al índice pero nunca se commitearon, o referenciados solo por commits huérfanos), y archivos que todavía son referenciados, pero por commits que son eliminables. Esto hace que el proceso de prune lleve más tiempo.

Si quieres verificar también los objetos inalcanzables, establece la opción --verify-unreachable.

Puedes verificar objetos inalcanzables por defecto estableciendo lfs.pruneverifyunreachablealways a true.

Por defecto, --verify-remote detiene la ejecución si un archivo no puede ser verificado. Establece --when-unverified=continue para no detener la ejecución, sino continuar eliminando todos los objetos que puedan ser verificados.

REMOTE PREDETERMINADO

Al identificar ARCHIVOS LFS NO SUBIDOS y realizar VERIFICAR REMOTO, normalmente se usa un solo remoto, 'origin', como referencia. Este único remoto se considera canónico; incluso si usas múltiples remotos, probablemente quieras conservar tus copias locales hasta que hayan llegado a ese remoto. 'origin' se usa por defecto porque normalmente será un repositorio central principal, o tu fork del mismo, en ambos casos es una copia de seguridad válida de tu trabajo. Si origin no existe, entonces por defecto no se eliminará nada porque todo se trata como 'no subido'.

Puedes alterar el remoto a través de git config: lfs.pruneremotetocheck. Establécelo a un nombre de remoto diferente para verificar ese en lugar de 'origin'.

git-lfs-fetch(1), gitignore(5).

git-lfs-prune(1) - Arch manual pages

NAME

git-lfs-prune - Remove old and unreferenced LFS files from local storage

SYNOPSIS

git lfs prune []

DESCRIPTION

This command removes old and unreferenced LFS files from local storage. These are files that are no longer referenced by any commit in your local repository, and are older than the period specified in lfs.prune.older-than.

The purpose of this command is to free up disk space by removing old LFS files that are no longer needed.

OPTIONS

--verbose
Print additional information about which files are being removed.
--dry-run
Show what would be removed, without actually removing anything.
--force
Remove all local LFS files older than the specified period, regardless of whether they are referenced or not. Use with caution.
--recent-files-only
Only remove files that are older than the period specified in lfs.prune.older-than. This is the default behavior.
--unpushed-files-only
Only remove files that have not yet been pushed to the remote. This is useful for cleaning up local LFS files that you know you won't need to push.

RECENT FILES

By default, git-lfs-prune will not delete LFS files that were downloaded in the last 30 days. This period can be configured using the lfs.prune.older-than configuration variable. For example, to keep files for 90 days: 

git config lfs.prune.older-than 90d

UNPUSHED LFS FILES

By default, git-lfs-prune will not delete local copies of LFS files that have not yet been pushed to the remote. This is to prevent accidentally deleting files that you may still need to push.

If you want to delete unpushed files, you can use the --unpush-files-only option.

VERIFY REMOTE

When pruning, git-lfs-prune can optionally verify that the LFS files exist on the remote storage before deleting them locally. This can be enabled using the lfs.prune.verifyRemote configuration option: 

git config lfs.prune.verifyRemote true

This option can be useful to ensure that you don't delete files locally that you might need later, but it will increase the time it takes to prune.

DEFAULT REMOTE

If you have multiple remotes configured, git-lfs-prune will operate on the LFS files associated with the default remote. You can specify a different remote using the --remote option.
