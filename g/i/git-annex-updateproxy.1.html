NOMBRE

git-annex-updateproxy - actualizar registros con configuración de proxy

SINOPSIS

git annex updateproxy

DESCRIPCIÓN

Un repositorio git-annex puede actuar como un proxy para sus remotos. Eso permite que el contenido anexado se almacene y elimine de los remotos del proxy, por repositorios que no tienen una conexión directa con los remotos.

Por defecto, no se realiza ningún proxy. Para configurar el repositorio local para que actúe como proxy para su remoto llamado "foo", ejecute git config remote.foo.annex-proxy true.

Después de configurar o anular la configuración de remote.<nombre>.annex-proxy en git, ejecute git-annex updateproxy para registrar la configuración del proxy en la rama git-annex. Eso informa a otros repositorios sobre la configuración del proxy.

Supongamos, por ejemplo, que el remoto "work" ha tenido este comando ejecutado en él. Luego, después de extraer de "work", git-annex conocerá un remoto adicional, "work-foo". Ese remoto se accederá utilizando "work" como proxy.

Los proxies solo se pueden acceder a través de ssh o mediante una URL annex+http.

Para configurar el proxy a un remoto especial que está configurado con exporttree=yes, es necesario que también esté configurado con annexobjects=yes. Y, "remote.<nombre>.annex-tracking-branch" necesita ser configurado a la rama que se exportará al remoto especial. Cuando esa rama se envíe al proxy, actualizará el árbol exportado al remoto especial. Cuando los archivos se copien al remoto a través del proxy, también actualizará el árbol exportado.

Tenga en cuenta que el proxy para un remoto especial puede usar temporalmente espacio en disco en el repositorio, para mantener temporalmente el contenido de los archivos anexados.

OPCIONES

Las git-annex-common-options(1) pueden ser utilizadas.
