Paquete: git

GIT-INTERPRET-TRAILERS(1) Manual de Git GIT-INTERPRET-TRAILERS(1)

NOMBRE

git-interpret-trailers - Añadir o analizar información estructurada en mensajes de commit

SINOPSIS

git interpret-trailers [--in-place] [--trim-empty]
                        [(--trailer (<clave>|<alias-de-clave>)[(=|:)<valor>])...]
                        [--parse] [<archivo>...]

DESCRIPCIÓN

Añadir o analizar líneas de trailer que se parecen a las cabeceras de correo electrónico RFC 822, al final de la parte de lo contrario de forma libre de un mensaje de commit. Por ejemplo, en el siguiente mensaje de commit

asunto
Lorem ipsum dolor sit amet, consectetur adipiscing elit.
Signed-off-by: Alice <alice@example.com>
Signed-off-by: Bob <bob@example.com>

las últimas dos líneas que comienzan con "Signed-off-by" son trailers.

Este comando lee mensajes de commit desde los argumentos <archivo> o desde la entrada estándar si no se especifica ningún <archivo>. Si se especifica --parse , la salida consiste en los trailers analizados provenientes de la entrada, sin influir en ellos con ninguna opción de línea de línea de comandos o variable de configuración.

De lo contrario, este comando aplica las variables de configuración trailer.* (que podrían potencialmente añadir nuevos trailers, así como reposicionarlos), así como cualquier argumento de línea de comandos que pueda anular las variables de configuración (como --trailer=... que también podría añadir nuevos trailers), a cada archivo de entrada. El resultado se emite en la salida estándar.

Este comando también puede operar sobre la salida de git-format-patch(1), que es más elaborada que un simple mensaje de commit. Es decir, dicha salida incluye un mensaje de commit (como arriba), una línea divisoria "---", y una parte de parche. Para estas entradas, las partes de divisorio y parche no son modificadas por este comando y se emiten tal cual en la salida, a menos que se especifique --no-divider .

Algunas variables de configuración controlan la manera en que los argumentos --trailer se aplican a cada entrada y la manera en que cualquier trailer existente en la entrada es cambiada. También hacen posible añadir automáticamente algunos trailers.

Por defecto, un argumento <clave>=<valor> o <clave>:<valor> dado usando --trailer se añadirá después de los trailers existentes solo si el último trailer tiene un par (<clave>, <valor>) diferente (o si no hay ningún trailer existente). Las partes <clave> y <valor> serán recortadas para eliminar el espacio en blanco inicial y final, y la <clave> y <valor> resultantes del recorte aparecerán en la salida así:

clave: valor

Esto significa que la <clave> y <valor> recortados serán separados por ': ' (dos puntos seguidos de un espacio).

Por conveniencia, un <alias-de-clave> puede ser configurado para hacer que el uso de --trailer sea más corto de escribir en la línea de comandos. Esto puede ser configurado usando la variable de configuración trailer.<alias-de-clave>.clave . El <aliasDeClave> debe ser un prefijo de la cadena completa <clave>, aunque la sensibilidad a mayúsculas no importa. Por ejemplo, si tienes

trailer.sign.key "Signed-off-by: "

en tu configuración, solo necesitas especificar --trailer="sign: foo" en la línea de comandos en lugar de --trailer="Signed-off-by: foo".

Por defecto el nuevo trailer aparecerá al final de todos los trailers existentes. Si no hay ningún trailer existente, el nuevo trailer aparecerá al final de la entrada. Se añadirá una línea en blanco antes del nuevo trailer si no hay una ya.

Los trailers existentes son extraídos de la entrada buscando un grupo de una o más líneas que (i) son todas trailers, o (ii) contienen al menos un trailer generado por Git o configurado por el usuario y consiste en al menos un 25% de trailers. El grupo debe ser precedido por una o más líneas vacías (o solo con espacios en blanco). El grupo debe estar al final de la entrada o ser las últimas líneas no-blanco antes de una línea que comienza con --- (seguido de un espacio o el final de la línea).

Al leer trailers, no puede haber espacios en blanco antes o dentro de la <clave>, pero cualquier número de caracteres de espacio y tabulación normales están permitidos entre la <clave> y el separador. Puede haber espacios en blanco antes, dentro o después del <valor>. El <valor> puede ser dividido en múltiples líneas con cada línea subsiguiente comenzando con al menos un espacio en blanco, como el "plegado" en RFC 822. Ejemplo:

clave: Este es un valor muy largo, con espacios y
  saltos de línea en él.

Ten en cuenta que los trailers no siguen (ni están destinados a seguir) muchas de las reglas para las cabeceras RFC 822. Por ejemplo, no siguen la regla de codificación.

OPCIONES

--in-place

Editar los archivos en el lugar.

--trim-empty

Si la parte <valor> de cualquier trailer contiene solo espacios en blanco, el trailer completo será eliminado de la salida. Esto se aplica tanto a trailers existentes como a trailers nuevos.

--trailer <clave>[(=|:)<valor>]

Especificar un par (<clave>, <valor>) que debe ser aplicado como un trailer a las entradas. Ver la descripción de este comando.

--where <ubicación>, --no-where

Especificar dónde se añadirán todos los trailers nuevos. Una configuración proporcionada con --where anula las variables de configuración trailer.where y cualquier trailer.<aliasDeClave>.where aplicables y se aplica a todas las opciones --trailer hasta la siguiente aparición de --where o --no-where. Al encontrar --no-where, se limpia el efecto de cualquier uso previo de --where, de modo que las variables de configuración relevantes ya no son anuladas. Las ubicaciones posibles son after, before, end o start.

--if-exists <acción>, --no-if-exists

Especificar qué acción se realizará cuando ya existe al menos un trailer con la misma <clave> en la entrada. Una configuración proporcionada con --if-exists anula las variables de configuración trailer.ifExists y cualquier trailer.<aliasDeClave>.ifExists aplicables y se aplica a todas las opciones --trailer hasta la siguiente aparición de --if-exists o --no-if-exists. Al encontrar --no-if-exists, se limpia el efecto de cualquier uso previo de --if-exists, de modo que las variables de configuración relevantes ya no son anuladas. Las acciones posibles son addIfDifferent, addIfDifferentNeighbor, add, replace y doNothing.

--if-missing <acción>, --no-if-missing

Especificar qué acción se realizará cuando no hay ningún otro trailer con la misma <clave> en la entrada. Una configuración proporcionada con --if-missing anula las variables de configuración trailer.ifMissing y cualquier trailer.<aliasDeClave>.ifMissing aplicables y se aplica a todas las opciones --trailer hasta la siguiente aparición de --if-missing o --no-if-missing. Al encontrar --no-if-missing, se limpia el efecto de cualquier uso previo de --if-missing, de modo que las variables de configuración relevantes ya no son anuladas. Las acciones posibles son doNothing o add.

--only-trailers

Salir solo los trailers, no cualquier otra parte de la entrada.

--only-input

Salir solo los trailers que existen en la entrada; no añadir ninguno de la línea de comandos o aplicando las variables de configuración trailer.* .

--unfold

Si un trailer tiene un valor que se extiende sobre múltiples líneas (también conocido como "plegado"), reformatear el valor en una sola línea.

--parse

Un alias conveniente para --only-trailers --only-input --unfold. Esto facilita ver solo los trailers provenientes de la entrada sin influir en ellos con ninguna opción de línea de comandos o variable de configuración, mientras también hace la salida amigable para máquinas con --unfold.

--no-divider

No tratar --- como el final del mensaje de commit. Usar esto cuando sabes que tu entrada contiene solo el mensaje de commit en sí (y no un correo electrónico o la salida de git format-patch).

VARIABLES DE CONFIGURACIÓN

Todo lo que está debajo de esta línea en esta sección es incluido selectivamente desde el ig.1.es'>git-config(1) documentación. El contenido es el mismo que el que se encuentra allí:

trailer.separators

Esta opción indica qué caracteres se reconocen como separadores de remolques. Por defecto, solo se reconoce : como separador de remolques, excepto que = siempre se acepta en la línea de comandos por compatibilidad con otros comandos de git.

El primer carácter proporcionado por esta opción será el carácter predeterminado utilizado cuando no se especifica otro separador en la configuración para este remolque.

Por ejemplo, si el valor de esta opción es "%=$", entonces solo las líneas que usan el formato <clave><sep><valor> con <sep> que contenga %, = o $ y luego espacios se considerarán remolques. Y % será el separador predeterminado utilizado, por lo que por defecto los remolques aparecerán como: <clave>% <valor> (se imprimirá un signo de porcentaje y un espacio entre la clave y el valor).

trailer.where

Esta opción indica dónde se agregará un nuevo remolque.

Puede ser end, que es el valor predeterminado, start, after o before.

Si es end, entonces cada nuevo remolque aparecerá al final de los remolques existentes.

Si es start, entonces cada nuevo remolque aparecerá al principio, en lugar del final, de los remolques existentes.

Si es after, entonces cada nuevo remolque aparecerá justo después del último remolque con la misma <clave>.

Si es before, entonces cada nuevo remolque aparecerá justo antes del primer remolque con la misma <clave>.

trailer.ifexists

Esta opción permite elegir qué acción se realizará cuando ya existe al menos un remolque con la misma <clave> en la entrada.

Los valores válidos para esta opción son: addIfDifferentNeighbor (este es el valor predeterminado), addIfDifferent, add, replace o doNothing.

Con addIfDifferentNeighbor, se agregará un nuevo remolque solo si no existe ningún remolque con el mismo par (<clave>, <valor>) arriba o abajo de la línea donde se agregará el nuevo remolque.

Con addIfDifferent, se agregará un nuevo remolque solo si no existe ya ningún remolque con el mismo par (<clave>, <valor>) en la entrada.

Con add, se agregará un nuevo remolque, incluso si ya existen algunos remolques con el mismo par (<clave>, <valor>) en la entrada.

Con replace, se eliminará un remolque existente con la misma <clave> y se agregará el nuevo remolque. El remolque eliminado será el más cercano (con la misma <clave>) al lugar donde se agregará el nuevo.

Con doNothing, no se hará nada; es decir, no se agregará ningún remolque nuevo si ya existe uno con la misma <clave> en la entrada.

trailer.ifmissing

Esta opción permite elegir qué acción se realizará cuando aún no existe ningún remolque con la misma <clave> en la entrada.

Los valores válidos para esta opción son: add (este es el valor predeterminado) y doNothing.

Con add, se agregará un nuevo remolque.

Con doNothing, no se hará nada.

trailer.<keyAlias>.key

Define un <keyAlias> para la <clave>. El <keyAlias> debe ser un prefijo (no distingue entre mayúsculas y minúsculas) de la <clave>. Por ejemplo, en git config trailer.ack.key "Acked-by" la "Acked-by" es la <clave> y "ack" es el <keyAlias>. Esta configuración permite la invocación más corta de la línea de comandos --trailer "ack:..." usando el <keyAlias> "ack" en lugar de la más larga --trailer "Acked-by:...".

Al final de la <clave>, puede aparecer un separador y luego algunos espacios. Por defecto, el único separador válido es :, pero esto se puede cambiar usando la variable de configuración trailer.separators.

Si hay un separador en la clave, anula el separador predeterminado al agregar el remolque.

trailer.<keyAlias>.where

Esta opción toma los mismos valores que la variable de configuración trailer.where y anula lo especificado por esa opción para los remolques con el <keyAlias> especificado.

trailer.<keyAlias>.ifexists

Esta opción toma los mismos valores que la variable de configuración trailer.ifexists y anula lo especificado por esa opción para los remolques con el <keyAlias> especificado.

trailer.<keyAlias>.ifmissing

Esta opción toma los mismos valores que la variable de configuración trailer.ifmissing y anula lo especificado por esa opción para los remolques con el <keyAlias> especificado.

trailer.<keyAlias>.command

Obsoleto en favor de trailer.<keyAlias>.cmd. Esta opción se comporta de la misma manera que trailer.<keyAlias>.cmd, excepto que no pasa nada como argumento al comando especificado. En su lugar, la primera aparición de la subcadena $ARG se reemplaza por el <valor> que se pasaría como argumento.

Tenga en cuenta que $ARG en el comando del usuario solo se reemplaza una vez y que la forma original de reemplazar $ARG no es segura.

Cuando se proporcionan tanto trailer.<keyAlias>.cmd como trailer.<keyAlias>.command para el mismo <keyAlias>, se usa trailer.<keyAlias>.cmd y se ignora trailer.<keyAlias>.command.

trailer.<keyAlias>.cmd

Esta opción se puede usar para especificar un comando de shell que se llamará una vez para agregar automáticamente un remolque con el <keyAlias> especificado, y luego se llamará cada vez que se especifique un argumento --trailer <keyAlias>=<value> para modificar el <value> del remolque que esta opción produciría.

Cuando el comando especificado se llama por primera vez para agregar un remolque con el <keyAlias> especificado, el comportamiento es como si se hubiera agregado un argumento especial --trailer <keyAlias>=<value> al principio del comando "git interpret-trailers", donde el <value> se toma de la salida estándar del comando con los espacios en blanco iniciales y finales eliminados.

Si también se pasan algunos argumentos --trailer <keyAlias>=<value> en la línea de comandos, el comando se vuelve a llamar una vez por cada uno de estos argumentos con el mismo <keyAlias>. Y la parte <value> de estos argumentos, si la hay, se pasará al comando como su primer argumento. De esta manera, el comando puede producir un <value> calculado a partir del <value> pasado en el argumento --trailer <keyAlias>=<value>.

EJEMPLOS

•Configura un remolque sign con una clave Signed-off-by, y luego agrega dos de estos remolques a un archivo de mensaje de commit: 
$ git config trailer.sign.key "Signed-off-by"
$ cat msg.txt
subject
body text
$ git interpret-trailers --trailer 'sign: Alice <alice@example.com>' --trailer 'sign: Bob <bob@example.com>' <msg.txt
subject
body text
Signed-off-by: Alice <alice@example.com>
Signed-off-by: Bob <bob@example.com>
•Usa la opción --in-place para editar un archivo de mensaje de commit en el lugar: 
$ cat msg.txt
subject
body text
Signed-off-by: Bob <bob@example.com>
$ git interpret-trailers --trailer 'Acked-by: Alice <alice@example.com>' --in-place msg.txt
$ cat msg.txt
subject
body text
Signed-off-by: Bob <bob@example.com>
Acked-by: Alice <alice@example.com>
•Extrae el último commit como un parche y agrégale un remolque Cc y un Reviewed-by: 
$ git format-patch -1
0001-foo.patch
$ git interpret-trailers --trailer 'Cc: Alice <alice@example.com>' --trailer 'Reviewed-by: Bob <bob@example.com>' 0001-foo.patch >0001-bar.patch
•Configura un remolque sign con un comando para agregar automáticamente un 'Signed-off-by: ' con la información del autor solo si no hay ya un 'Signed-off-by: ', y muestra cómo funciona: 
$ cat msg1.txt
subject
body text
$ git config trailer.sign.key "Signed-off-by: "
$ git config trailer.sign.ifmissing add
$ git config trailer.sign.ifexists doNothing
$ git config trailer.sign.cmd 'echo "$(git config user.name) <$(git config user.email)>"'
$ git interpret-trailers --trailer sign <msg1.txt
subject
body text
Signed-off-by: Bob <bob@example.com>
$ cat msg2.txt
subject
body text
Signed-off-by: Alice <alice@example.com>
$ git interpret-trailers --trailer sign <msg2.txt
subject
body text
Signed-off-by: Alice <alice@example.com>
•Configura un remolque fix con una clave que contiene un # y ningún espacio después de este carácter, y muestra cómo funciona: 
$ git config trailer.separators ":#"
$ git config trailer.fix.key "Fix #"
$ echo "subject" | git interpret-trailers --trailer fix=42
subject
Fix #42
•Configura un remolque help con un cmd que usa un script glog-find-author que busca la identidad del autor especificada en el log de git en el repositorio de git y muestra cómo funciona: 
$ cat ~/bin/glog-find-author
#!/bin/sh
test -n "$1" && git log --author="$1" --pretty="%an <%ae>" -1 || true
$ cat msg.txt
subject
body text
$ git config trailer.help.key "Helped-by: "
$ git config trailer.help.ifExists "addIfDifferentNeighbor"
$ git config trailer.help.cmd "~/bin/glog-find-author"
$ git interpret-trailers --trailer="help:Junio" --trailer="help:Couder" <msg.txt
subject
body text
Helped-by: Junio C Hamano <gitster@pobox.com>
Helped-by: Christian Couder <christian.couder@gmail.com>
•Configura un remolque ref con un cmd que usa un script glog-grep para buscar el último commit relevante del log de git en el repositorio de git y muestra cómo funciona: 
$ cat ~/bin/glog-grep
#!/bin/sh
test -n "$1" && git log --grep "$1" --pretty=reference -1 || true
$ cat msg.txt
subject
body text
$ git config trailer.ref.key "Reference-to: "
$ git config trailer.ref.ifExists "replace"
$ git config trailer.ref.cmd "~/bin/glog-grep"
$ git interpret-trailers --trailer="ref:Add copyright notices." <msg.txt
subject
body text
Reference-to: 8bc9a0c769 (Add copyright notices., 2005-04-07)
•Configura un remolque see con
command to show the subject of a commit that is related, and show how it works: 
$ cat msg.txt
subject
body text
see: HEAD~2
$ cat ~/bin/glog-ref
#!/bin/sh
git log -1 --oneline --format="%h (%s)" --abbrev-commit --abbrev=14
$ git config trailer.see.key "See-also: "
$ git config trailer.see.ifExists "replace"
$ git config trailer.see.ifMissing "doNothing"
$ git config trailer.see.cmd "glog-ref"
$ git interpret-trailers --trailer=see <msg.txt
subject
body text
See-also: fe3187489d69c4 (subject of related commit)
•Configure a commit template with some trailers with empty values (using sed to show and keep the trailing spaces at the end of the trailers), then configure a commit-msg hook that uses git interpret-trailers to remove trailers with empty values and to add a git-version trailer: 
$ cat temp.txt
***subject***
***message***
Fixes: Z
Cc: Z
Reviewed-by: Z
Signed-off-by: Z
$ sed -e 's/ Z$/ /' temp.txt > commit_template.txt
$ git config commit.template commit_template.txt
$ cat .git/hooks/commit-msg
#!/bin/sh
git interpret-trailers --trim-empty --trailer "git-version: \$(git describe)" "\$1" > "\$1.new"
mv "\$1.new" "\$1"
$ chmod +x .git/hooks/commit-msg
