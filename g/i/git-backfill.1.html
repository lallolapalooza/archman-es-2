NOMBRE

git-backfill - Descarga objetos faltantes en un clon parcial

SINOPSIS

git backfill [--min-batch-size=<n>] [--[no-]sparse]

DESCRIPCIÓN

Los clones parciales sin blobs se crean usando git clone --filter=blob:none y luego se configura el repositorio local de tal manera que el cliente Git evite descargar objetos blob a menos que sean necesarios para una operación local. Inicialmente, esto significa que el clon y las posteriores recuperaciones descargan commits y árboles alcanzables, pero ningún blob. Operaciones posteriores que cambian el puntero HEAD, como git checkout o git merge, pueden necesitar descargar blobs faltantes para completar su operación.

En el peor de los casos, comandos que calculan diffs de blobs, como git blame, se vuelven muy lentos ya que descargan los blobs faltantes en solicitudes de un solo blob para satisfacer el objeto faltante a medida que el comando Git lo necesita. Esto conduce a múltiples solicitudes de descarga y ninguna capacidad para que el servidor Git proporcione compresión delta entre esos objetos.

El comando git backfill proporciona una forma para que el usuario solicite que Git descargue los blobs faltantes (con filtros opcionales) de tal manera que los blobs faltantes que representan versiones históricas de archivos puedan ser descargados en lotes. El comando backfill intenta optimizar la solicitud agrupando blobs que aparecen en la misma ruta, lo que potencialmente conduce a una buena compresión delta en el archivo de paquete enviado por el servidor.

De esta manera, git backfill proporciona un mecanismo para dividir un clon grande en partes más pequeñas. Comenzando con un clon parcial sin blobs con git clone --filter=blob:none y luego ejecutando git backfill en el repositorio local, se proporciona una forma de descargar todos los objetos alcanzables en varias llamadas de red más pequeñas que descargar todo el repositorio en el momento del clonado.

Por defecto, git backfill descarga todos los blobs alcanzables desde el commit HEAD. Este conjunto puede ser restringido o expandido usando varias opciones.

ESTE COMANDO ES EXPERIMENTAL. SU COMPORTAMIENTO PUEDE CAMBIAR EN EL FUTURO.

OPCIONES

--min-batch-size=<n>

Especifica un tamaño mínimo para un lote de objetos faltantes a solicitar al servidor. Este tamaño puede ser superado por el último conjunto de blobs vistos en una ruta dada. El tamaño mínimo de lote por defecto es 50,000.

--sparse, --no-sparse

Solo descarga objetos si aparecen en una ruta que coincide con el checkout disperso actual. Si la función de checkout disperso está habilitada, entonces se asume --sparse y se puede deshabilitar con --no-sparse.

VER TAMBIÉN
