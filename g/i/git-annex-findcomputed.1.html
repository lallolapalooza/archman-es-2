NOMBRE

git-annex-findcomputed - lista archivos computados

SINOPSIS

git annex findcomputed [ruta ...]

DESCRIPCIÓN

Muestra una lista de archivos en la ruta especificada que pueden ser computados por remotos especiales de cómputo habilitados. Sin ruta, lista archivos en el directorio actual y sus subdirectorios.

Junto con el nombre de cada archivo computado, se muestra la entrada que se proporcionó a git-annex-addcomputed(1).

Por ejemplo:

# git-annex findcomputed foo.jpeg (imageconvert) -- convert file.raw file.jpeg passes=10 bar.gz (compressor) -- compress bar --level=9

OPCIONES

opciones de coincidencia
Se pueden usar las opciones de coincidencia de git-annex(1) para especificar los archivos a listar.
--branch=ref
Lista los archivos computados en la rama o tree-ish especificada.
--inputs
Muestra cada archivo computado seguido de la entrada que se usa para producirlo. Se muestra la ubicación actual del archivo de entrada en el árbol de trabajo, pero si el archivo de entrada no está en el árbol de trabajo, se muestra su clave.
Por ejemplo:
foo.jpeg file.raw bar.gz bar
Cuando se necesitan varios archivos de entrada para computar un archivo, se muestran varias líneas para ese archivo:
foo bar foo baz
--format=valor
Usa formato de salida personalizado.
Esta opción funciona igual que en git-annex-find(1), con las siguientes variables adicionales disponibles para su uso: "${remote}", "${computation}"
El formato de salida predeterminado es el mismo que --format='${file} (${remote}) -- ${computation}\n', excepto cuando se muestra en una terminal, los caracteres de control se escaparán.
Cuando se usa --inputs, hay variables adicionales "${inputfile}" que es el nombre del archivo de entrada, "${inputkey}" que es la clave de entrada, y "${input}" que es el nombre del archivo o la clave. El formato de salida predeterminado para --inputs es el mismo que --format='${file} ${input}\n' Para separar los pares de archivos con nulos en su lugar, usa, por ejemplo --format='${file}\000${input}\n'
--json
Muestra la lista de archivos en formato JSON.
Esto está diseñado para ser analizado por programas que utilizan git-annex. Cada línea de salida es un objeto JSON.
--json-error-messages
Los mensajes que normalmente se mostrarían en la salida estándar de error se incluyen en el JSON.
