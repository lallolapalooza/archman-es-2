NOMBRE

git-annex-benchmark - evaluar el rendimiento de los comandos de git-annex

SINOPSIS

git annex benchmark [criterionopts] ( -- comando [; comando] | --databases=N )

DESCRIPCIÓN

Cuando git-annex se compila con soporte para evaluación de rendimiento, este comando puede usarse para evaluar el rendimiento de cualquier otro comando de git-annex. Por ejemplo, "git annex benchmark -- get ." evaluará el rendimiento de "git annex get".

El comando que se está evaluando se ejecuta en el repositorio actual de git-annex. No se ejecuta solo una vez; el proceso de evaluación lo ejecutará varias veces para obtener un resultado estadísticamente significativo.

Al evaluar una acción como "git annex get", la primera ejecución a menudo hará mucho más que las ejecuciones posteriores. Para que la evaluación repita una acción como obtener un archivo cada vez, se pueden listar comandos adicionales, separados por ';'. (Tenga en cuenta que ';' debe ser escapado del shell). El script combinado se ejecutará repetidamente por la evaluación. Un ejemplo de uso de esto:


git annex benchmark -- get . ';' drop .

Tenga en cuenta que git-annex benchmark no crea nuevos procesos de git-annex al evaluar el rendimiento; llama al comando a evaluar internamente, y así evita la sobrecarga de inicio de git-annex. (Así que no intente usarlo para optimizar el inicio de git-annex).

OPCIONES

Antes de "--", se pueden usar cualquiera de las opciones de línea de comandos de la biblioteca criterion.

Cualquier opción que git-annex acepte normalmente puede incluirse después del comando a evaluar.

La opción --databases=N evalúa el uso de bases de datos sqlite por parte de git-annex, en lugar de un comando. N es el número de elementos a evaluar.

SALIDA

La salida de los comandos que se están evaluando va a la salida estándar y al error estándar como de costumbre. A menudo es una buena idea usar --quiet para evitar una salida innecesaria, a menos que la generación de esa salida sea parte de lo que desea evaluar.

El informe de evaluación se muestra en la salida estándar por defecto, aunque las opciones de criterion se pueden usar para redirigirlo a un archivo. Por ejemplo:


git annex benchmark -o bench -- find >/dev/null
