DESCRIPCIÓ

N

Gitweb proporciona una interfaz web para los repositorios de Git. Sus características

incluyen:
•Visualizar múltiples repositorios de Git con una raíz
común.
•Navegar por cada revisión del
repositorio.
•Ver el contenido de los archivos en el repositorio en cualquier
revisión.
•Ver el registro de revisiones de las ramas, el historial de archivos y directorios, viendo qué se cambió, cuándo y por
quién.
•Ver los detalles de blame/anotación de cualquier archivo (si está habilitado)
.
•Generar feeds RSS y Atom de commits, para cualquier rama. Los feeds se pueden autodescubrir en navegadores web
modernos.
•Ver todo lo que se cambió en una revisión, y avanzar por las revisiones una a una, viendo el historial del
repositorio.
•Encontrar commits cuyos mensajes coincidan con un término de búsqueda
dado.

Vea https://repo.or.cz/w/git.git/tree/HEAD:/gitweb/ para el

código fuente de gitweb, n
avegado usando gitweb mismo.

Repositorio

s

Gitweb puede mostrar información de uno o más repositorios de Git. Estos repositorios deben estar todos en el sistema de archivos local, y deben compartir una raíz de repositorio común, es decir, estar todos bajo un solo repositorio padre (pero vea también la sección "Configuración avanzada del servidor web", subsección "Configuración del servidor web con raíz de múltiples proyectos")

Controlar el acceso a los repositorios de

Git

Por defecto, todos los repositorios de Git bajo $projectroot son visibles y disponibles para gitweb. Sin embargo, puede configurar cómo gitweb controla el acceso a los

repositorios.
•Como se describe en la sección "Formato del archivo de lista de proyectos", puede controlar qué proyectos son visibles incluyendo selectivamente repositorios en el archivo de lista de proyectos, y estableciendo la variable de configuración de gitweb $projects_list para que apunte a él. Con $strict_export establecido, el archivo de lista de proyectos se puede usar para controlar qué repositorios son disponibles t
ambién.
•Puede configurar gitweb para que solo liste y permita ver los repositorios exportados explícitamente, a través de la variable $export_ok en el archivo de configuración de gitweb; vea la página man gitweb.conf(5). Si se evalúa como verdadero, gitweb muestra los repositorios solo si este archivo nombrado por $export_ok existe en su base de datos de objetos (si el directorio tiene el archivo mágico nombrado $export_ok).

Por ejemplo, git-daemon(1) por defecto (a menos que se use la opción --export-all) permite hacer pull solo para aquellos repositorios que tienen el archivo git-daemon-export-ok.

Añadiendo

"
;

hace que gitweb muestre y permita el acceso solo a aquellos repositorios que se pueden obtener a través del protocol

o git

•Finalmente, es posible especificar una subrutina de perl arbitraria que se llamará para cada repositorio para determinar si se puede exportar. La subrutina recibe un absolutoruta única al proyecto (repositorio) como su único parámetro (es decir, "$projectroot/$project").

Por ejemplo, si usa mod_perl para ejecutar el script y tiene configurada la autenticación de protocolo HTTP simple para sus repositorios, puede usar el siguiente hook para permitir el acceso solo si el usuario está autorizado a leer los

use Apache2::Const -compile => qw(HTTP_OK); my $path = "$
_[0]/HEAD"; my $r = Apache2::RequestUtil->request;
my $sub = $r->lookup_file($path); return $sub->filename
eq $path && $sub->status == Apache2::Const::HTTP_OK; };
