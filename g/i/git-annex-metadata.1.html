git-annex-metadata(1) Manual de Comandos Generales git-annex-metadata(1)

NOMBRE

git-annex-metadata - establece u obtiene los metadatos de un archivo

SINOPSIS

git annex metadata [ruta ...]

DESCRIPCIÓN

El contenido de un archivo anexado puede tener cualquier número de campos de metadatos adjuntos para describirlo. Cada campo de metadatos puede, a su vez, tener cualquier número de valores.

Este comando se puede usar para establecer metadatos o mostrar los metadatos establecidos actualmente.

Cuando se ejecuta sin ningún parámetro -s o -t, muestra los metadatos actuales.

Cada campo de metadatos tiene su propio metadato "campo-últimocambio", que contiene la fecha en que el campo fue cambiado por última vez. A diferencia de otros metadatos, este no puede ser modificado directamente por este comando. Se actualiza automáticamente.

Tenga en cuenta que los metadatos se adjuntan a la clave de git-annex correspondiente al contenido de un archivo, no a un nombre de archivo particular en una rama de git particular. Todos los archivos con la misma clave comparten los mismos metadatos, que se almacenan en la rama git-annex. Si un archivo es modificado, los metadatos de la versión anterior se copiarán a la nueva clave cuando git-annex añada el archivo modificado.

OPCIONES

-g campo / --get campo
Obtiene el valor (o valores) de un solo campo.
Los valores se mostrarán uno por línea, sin ninguna otra salida, por lo que esto es adecuado para su uso en un script.
-s campo=valor / --set campo=valor
Establece el valor de un campo, eliminando cualquier valor antiguo.
-s campo+=valor / --set campo+=valor
Añade un valor adicional, conservando cualquier valor antiguo.
-s campo?=valor / --set campo?=valor
Establece un valor, pero solo si el campo no tiene ya un valor establecido.
-s campo-=valor / --set campo-=valor
Elimina un valor de un campo, dejando cualquier otro valor que el campo tenga establecido.
-r campo / --remove campo
Elimina todos los valores actuales del campo.
-t etiqueta / --tag etiqueta
Establece una etiqueta. Tenga en cuenta que una etiqueta es solo un valor del campo "tag".
-u etiqueta / --unset etiqueta
Elimina una etiqueta.
--remove-all
Elimina todos los metadatos de los archivos especificados.
Cuando un archivo es modificado y se añade la nueva versión, git-annex copiará los metadatos de la versión antigua del archivo. En situaciones donde no desee esos metadatos copiados, puede usar esta opción para eliminarlos.
--force
Por defecto, git annex metadata rechaza establecer metadatos recursivamente en los archivos de un directorio. Esta opción habilita dicho establecimiento recursivo.
opciones de coincidencia
Se pueden usar las git-annex-matching-options(1) para controlar sobre qué actuar.
--all -A
Especificar en lugar de un archivo para obtener/establecer metadatos en todas las claves conocidas.
--branch=ref
Especificar en lugar de un archivo para obtener/establecer metadatos en todos los archivos de la rama o árbol especificado.
--unused
Especificar en lugar de un archivo para obtener/establecer metadatos en los archivos encontrados por la última ejecución de git-annex unused.
--key=nombreclave
Especificar en lugar de un archivo para obtener/establecer metadatos de la clave especificada.
--json
Habilita la salida JSON (y la entrada). Cada línea es un objeto JSON.
El formato de los objetos JSON cambió en la versión de git-annex 6.20160726.
Ejemplo del nuevo formato:

{"command":"metadata","file":"foo","key":"...","fields":{"author":["bar"],...},"note":"...","success":true}
Ejemplo del formato antiguo, que carece del objeto de campos interno:

{"command":"metadata","file":"foo","key":"...","author":["bar"],...,"note":"...","success":true}
--json-error-messages
Los mensajes que normalmente se enviarían a la salida de error estándar se incluyen en el JSON en su lugar.
--batch
Habilita el modo por lotes, que se puede usar para obtener, almacenar y eliminar metadatos para múltiples archivos o claves.
El modo por lotes actualmente solo admite entrada JSON. Por lo tanto, debe habilitar --json junto con --batch.
En el modo por lotes, git-annex lee líneas de la entrada estándar, que contienen objetos JSON. Responde a cada archivo anexado de entrada con un objeto JSON de salida. (Pero si el archivo no es un archivo anexado, se emitirá una línea vacía.)
El formato del JSON enviado a git-annex puede ser el mismo que el JSON que emite. O, una versión simplificada. Solo el campo "file" (o "key") es realmente necesario.
Por ejemplo, para obtener los metadatos actuales del archivo foo:

{"file":"foo"}
Para obtener los metadatos actuales de la clave k:


{"key":"k"}

Cualquier campo de metadatos incluido en el objeto JSON se almacenará, reemplazando cualquier valor que los campos tuvieran antes. Para eliminar un campo, inclúyalo con una lista vacía de valores.
Para cambiar el autor del archivo foo a bar:

{"file":"foo","fields":{"author":["bar"]}}
Para eliminar el autor del archivo foo:

{"file":"foo","fields":{"author":[]}}
También se pueden usar las git-annex-common-options(1).

EJEMPLOS

Para establecer algunas etiquetas en un archivo y también su autor:


git annex metadata annexscreencast.ogv -t video -t screencast -s author+=Alice
