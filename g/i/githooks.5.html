DESCRIPCIÓ

N

Los hooks son programas que puedes colocar en un directorio de hooks para desencadenar acciones en ciertos puntos de la ejecución de git. Los hooks que no tienen establecido el bit de ejecución son

ignorados.

Por defecto, el directorio de hooks es $GIT_DIR/hooks, pero eso se puede cambiar a través de la variable de configuración core.hooksPath (ver git-config(1))

.

Antes de que Git invoque un hook, cambia su directorio de trabajo a $GIT_DIR en un repositorio desnudo o a la raíz del árbol de trabajo en un repositorio no desnudo. Una excepción son los hooks desencadenados durante un push (pre-receive, update, post-receive, post-update, push-to-checkout) que siempre se ejecutan en

$GIT_DIR.

Las variables de entorno, como GIT_DIR, GIT_WORK_TREE, etc., se exportan para que los comandos de Git ejecutados por el hook puedan localizar correctamente el repositorio. Si tu hook necesita invocar comandos de Git en un repositorio externo o en un árbol de trabajo diferente del mismo repositorio, entonces debería limpiar estas variables de entorno para que no interfieran con las operaciones de Git en la ubicación externa. Por

ejemplo: 
local_desc=$(git describe)
foreign_des
c=$(unset $(git rev-parse --local-env-v
ars); git -C ../foreign-repo describe)

Los hooks pueden obtener sus argumentos a través del entorno, los argumentos de la línea de comandos y stdin. Ver la documentación de cada hook a continuación para

detalles.

git init puede copiar hooks al nuevo repositorio, dependiendo de su configuración. Ver la sección "DIRECTORIO DE PLANTILLA" en git-init(1) para detalles. Cuando el resto de este documento se refiere a "hooks por defecto", está hablando de la plantilla por defecto incluida con

Este gancho es invocado cuando la opción de configuración core.fsmonitor se establece en .git/hooks/fsmonitor-watchman o .git/hooks/fsmonitor-watchmanv2 dependiendo de la versión del hook a

utilizar.

La versión 1 toma dos argumentos, una versión (1) y el tiempo en nanosegundos transcurridos desde la medianoche del 1 de enero de

1970.

La versión 2 toma dos argumentos, una versión (2) y un token que se usa para identificar cambios desde el token. Para watchman, esto sería un id de reloj. Esta versión debe imprimir en stdout el nuevo token seguido de un NUL antes de la lista de

archivos.

El hook debe imprimir en stdout la lista de todos los archivos en el directorio de trabajo que puedan haber cambiado desde el tiempo solicitado. La lógica debe ser inclusiva para no perder ningún cambio potencial. Las rutas deben ser relativas a la raíz del directorio de trabajo y estar separadas por un solo

NUL.

Está bien incluir archivos que no hayan cambiado realmente. Todos los cambios, incluyendo archivos recién creados y eliminados, deben ser incluidos. Cuando los archivos sean renombrados, tanto el nombre antiguo como el nuevo deben ser

incluidos.

Git limitará qué archivos verifica en busca de cambios, así como qué directorios se verifican en busca de archivos no rastreados, basándose en los nombres de ruta

proporcionados.

Una forma optimizada de decirle a git "todos los archivos han cambiado" es devolver el nombre de archivo /
