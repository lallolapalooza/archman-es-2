NOMBRE

git-annex-whereis - lista los repositorios que tienen contenido de archivo

SINOPSIS

git annex whereis [ruta ...]

DESCRIPCIÓN

Muestra información sobre dónde se encuentra el contenido de los archivos.

Por ejemplo:


# git annex whereis
whereis mi_archivo_genial_grande (1 copia)
0c443de8-e644-11df-acbf-f7cd7ca6210d -- laptop
whereis otro_archivo (3 copias)
0c443de8-e644-11df-acbf-f7cd7ca6210d -- laptop
62b39bbe-4149-11e0-af01-bb89245a1e61 -- disco usb [aquí]
7570b02e-15e9-11e0-adf0-9f3f94cb2eaa -- disco de respaldo

Tenga en cuenta que este comando no contacta a los remotos para verificar si todavía tienen el contenido de los archivos. Solo informa sobre la última información recibida de los remotos.

OPCIONES

opciones de emparejamiento
Las opciones de emparejamiento de git-annex(1) se pueden usar para controlar sobre qué actuar.
--key=nombreclave
Muestra dónde se encuentra una clave de git-annex particular.
--all -A
Muestra información whereis para todas las claves conocidas.
(Excepto para las claves que han sido marcadas como muertas, ver git-annex-dead(1).)
--branch=ref
Muestra información whereis para archivos en la rama o árbol especificado.
--unused
Muestra información whereis para archivos encontrados por la última ejecución de git-annex unused.
--batch
Habilita el modo por lotes, en el cual se lee un archivo en una línea desde stdin, se muestra su información y se repite.
Tenga en cuenta que si el archivo no es un archivo anexado o no coincide con las opciones de emparejamiento especificadas, se emitirá una línea vacía en su lugar.
--batch-keys
Esto es como --batch pero las líneas leídas desde stdin se analizan como claves.
-z
Hace que la entrada del lote esté delimitada por nulos en lugar de las nuevas líneas habituales.
--json
Habilita la salida JSON. Esto está destinado a ser analizado por programas que usan git-annex. Cada línea de salida es un objeto JSON.
--json-error-messages
Los mensajes que normalmente se emitirían al error estándar se incluyen en el JSON en su lugar.
--format=valor
Usa formato de salida personalizado.
El valor es una cadena de formato, en la que '${var}' se expande al valor de una variable. Para justificar a la derecha una variable con espacios, use '${var;width}'; para justificar a la izquierda una variable, use '${var;-width}'; para escapar caracteres inusuales (incluidos caracteres de control) en una variable, use '${escaped_var}'
Estas variables están disponibles para su uso en formatos: file, key, uuid, url, backend, bytesize, humansize, keyname, hashdirlower, hashdirmixed, mtime (para el campo mtime de una clave WORM).
Además, '\n' es una nueva línea, '\000' es un NULL, etc.
Cuando el formato contiene la variable uuid, se expandirá sucesivamente para cada repositorio que contenga el contenido del archivo. Por ejemplo, con --format="${file} ${uuid}\n", la salida se verá así:

foo 00000000-0000-0000-0000-000000000001
foo a7f7ddd0-9a08-11ea-ab66-8358e4209d30
bar a7f7ddd0-9a08-11ea-ab66-8358e4209d30
Lo mismo aplica cuando se usa la variable url y un archivo tiene múltiples urls registradas.
También se pueden usar las opciones comunes de git-annex(1).
