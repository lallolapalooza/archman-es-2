NOMBRE

git-annex-addcomputed - añade archivos computados al repositorio

SINOPSIS

git annex addcomputed --to=remoto -- ...

DESCRIPCIÓN

Añade archivos al annex que se computan a partir de archivos de entrada en el repositorio, utilizando un remoto especial de cómputo.

Una vez que un archivo ha sido añadido a un remoto de cómputo, comandos como git-annex get lo utilizarán para computar el contenido del archivo.

La sintaxis de este comando después de -- depende del programa que el remoto especial de cómputo esté configurado para ejecutar para realizar el cómputo.

Para ver el uso del programa, puedes ejecutar:

git-annex addcomputed --to=foo

Generalmente proporcionarás un archivo de entrada (o archivos), y a menudo también un nombre de archivo de salida, y parámetros adicionales para controlar el cómputo.

Puede haber más de un archivo de entrada que se combinen para computar un archivo de salida. Y se pueden computar múltiples archivos de salida al mismo tiempo.

Algunos ejemplos de cómo esto podría verse:

git-annex addcomputed --to=x -- convert file.raw file.jpeg passes=10 git-annex addcomputed --to=y -- compress foo --level=9 git-annex addcomputed --to=z -- clip foo 2:01-3:00 combine with bar to baz

Ten en cuenta que los parámetros que se pasaron a git-annex initremote al configurar el remoto especial de cómputo se añadirán al final de los parámetros proporcionados a git-annex addcomputed.

OPCIONES

--to=remoto
Especifica qué remoto computará los archivos.
Debe ser un remoto de cómputo. Por ejemplo, se puede inicializar con:
git-annex initremote photoconv type=compute \ program=git-annex-compute-photoconv
Para detalles sobre remotos de cómputo, y una lista de algunos de los programas disponibles, ver https://git-annex.branchable.com/special_remotes/compute/
--fast
Añade archivos computados al repositorio, sin hacer ningún trabajo aún para computar su contenido.
Esto implica --unreproducible, porque incluso si el remoto de cómputo produce salida reproducible, no está disponible.
--unreproducible, -u
Indica que no se espera que el cómputo sea completamente reproducible. Puede variar, de formas que producen archivos equivalentes lo suficiente para ser intercambiables, pero no necesariamente idénticos.
Este es el valor predeterminado a menos que el remoto de cómputo indique que produce salida reproducible.
--reproducible, -r
Indica que se espera que el cómputo sea completamente reproducible.
Este es el valor predeterminado cuando el remoto de cómputo indica que produce salida reproducible (excepto cuando se usa --fast).
Si un cómputo resulta no ser completamente reproducible, entonces obtener un archivo computado del remoto de cómputo fallará más tarde con un error de verificación de suma de verificación. Una cosa que se puede hacer entonces es usar git-annex recompute --original --unreproducible.
--backend
Especifica qué backend de clave-valor usar.
--json
Habilita la salida JSON. Está destinado a ser analizado por programas que utilizan git-annex. Cada línea de salida es un objeto JSON.
También las opciones_generales_de_git-annex(1) pueden ser usadas.
