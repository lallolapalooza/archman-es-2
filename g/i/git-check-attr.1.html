Paquete: git

Licencias: GPL-2.0-only

GIT-CHECK-ATTR(1) Manual de Git GIT-CHECK-ATTR(1)

NOMBRE

git-check-attr - Muestra información de gitattributes

SINOPSIS

git check-attr [--source <árbol-a-verificar>] [-a | --all | <attr>...] [--] <ruta_de_acceso>...
git check-attr --stdin [-z] [--source <árbol-a-verificar>] [-a | --all | <attr>...]

DESCRIPCIÓN

Para cada ruta de acceso, este comando listará si cada atributo está no especificado, establecido o no establecido como gitattribute en esa ruta de acceso.

OPCIONES

-a, --all

Lista todos los atributos que están asociados con las rutas especificadas. Si se usa esta opción, los atributos no especificados no se incluirán en la salida.

--cached

Considera solo los .gitattributes en el índice, ignorando el árbol de trabajo.

--stdin

Lee las rutas de acceso desde la entrada estándar, una por línea, en lugar de desde la línea de comandos.

-z

El formato de salida se modifica para ser analizable por máquina. Si también se proporciona --stdin, las rutas de entrada se separan con un carácter NUL en lugar de un carácter de nueva línea.

--source=<árbol-a-verificar>

Verifica los atributos contra el árbol especificado. Es común especificar el árbol fuente nombrando un commit, rama o etiqueta asociado a él.

--

Interpreta todos los argumentos anteriores como atributos y todos los argumentos siguientes como nombres de ruta.

Si no se utilizan --stdin, --all o --, el primer argumento se tratará como un atributo y el resto de los argumentos como rutas de acceso.

SALIDA

La salida tiene la forma: <ruta> DOS PUNTOS ESP <atributo> DOS PUNTOS ESP <info> LF

a menos que -z esté en efecto, en cuyo caso NUL se usa como delimitador: <ruta> NUL <atributo> NUL <info> NUL

<ruta> es la ruta de un archivo que se consulta, <atributo> es un atributo que se consulta, y <info> puede ser:

no especificado

cuando el atributo no está definido para la ruta.

no establecido

cuando el atributo está definido como falso.

establecido

cuando el atributo está definido como verdadero.

<valor>

cuando se ha asignado un valor al atributo.

El almacenamiento en búfer ocurre como se documenta en la opción GIT_FLUSH en git(1). El llamador es responsable de evitar puntos muertos causados por llenar demasiado un búfer de entrada o leer de un búfer de salida vacío.

EJEMPLOS

En los ejemplos, se utiliza el siguiente archivo .gitattributes:

*.java diff=java -crlf miAttr
NoMyAttr.java !miAttr
README caveat=unspecified
•Listar un solo atributo: 
$ git check-attr diff org/example/MyClass.java
org/example/MyClass.java: diff: java
•Listar varios atributos para un archivo: 
$ git check-attr crlf diff myAttr -- org/example/MyClass.java
org/example/MyClass.java: crlf: unset
org/example/MyClass.java: diff: java
org/example/MyClass.java: myAttr: set
•Listar todos los atributos para un archivo: 
$ git check-attr --all -- org/example/MyClass.java
org/example/MyClass.java: diff: java
org/example/MyClass.java: myAttr: set
•Listar un atributo para varios archivos: 
$ git check-attr myAttr -- org/example/MyClass.java org/example/NoMyAttr.java
org/example/MyClass.java: myAttr: set
org/example/NoMyAttr.java: myAttr: unspecified
•No todos los valores son igualmente inequívocos: 
$ git check-attr caveat README
README: caveat: unspecified
