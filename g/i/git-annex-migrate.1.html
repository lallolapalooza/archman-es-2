NOMBRE

git-annex-migrate - cambiar datos a un backend diferente

SINOPSIS

git annex migrate [ruta ...]

git annex migrate --update

DESCRIPCIÓN

Cambia los archivos anexionados especificados para que utilicen el backend de clave-valor predeterminado (o el especificado con --backend). Solo se migran los archivos cuyo contenido está actualmente presente.

Tenga en cuenta que el contenido también se almacena utilizando las claves antiguas después de la migración. Cuando sea posible, se utilizan enlaces duros para evitar que ocupen espacio adicional en el disco. Utilice git annex unused para encontrar y eliminar las claves antiguas.

Normalmente, no se hará nada con los archivos especificados que ya estén utilizando el nuevo backend. Sin embargo, si un backend cambia la información que utiliza para construir una clave, esto también se puede usar para migrar archivos para que utilicen el nuevo formato de clave.

OPCIONES

--update
Esto actualiza el repositorio local para las migraciones que se realizaron en otro lugar. Solo se realizarán nuevas migraciones desde la última vez que se ejecutó esto.
Esto no modifica el árbol de trabajo, sino que solo enlaza (o en algunos casos copia) objetos de anexo a sus nuevas claves.
git annex pull y git annex sync --content hacen esto automáticamente, a menos que la configuración annex.syncmigrations esté establecida en false.
Tenga en cuenta que las versiones anteriores de git-annex no registraban las migraciones de una manera que esto pudiera utilizar. Las migraciones realizadas con esas versiones anteriores tenían que ejecutarse manualmente en cada clon del repositorio.
--apply
Esto aplica todas las migraciones registradas al repositorio local. Es la forma no incremental de --update.
Una situación en la que esto puede ser útil es cuando se ha ejecutado git-annex migrate --update, pero desde entonces han entrado objetos no migrados en el repositorio. El uso de esta opción asegura que dichos objetos se migren.
Tenga en cuenta que las versiones anteriores de git-annex no registraban las migraciones de una manera que esto pudiera utilizar. Las migraciones realizadas con esas versiones anteriores tenían que ejecutarse manualmente en cada clon del repositorio.
--backend
Especificar el nuevo backend de clave-valor a utilizar para los datos migrados.
--force
Forzar la migración de claves que ya están utilizando el nuevo backend.
opciones de coincidencia de archivos
Las git-annex-matching-options(1) pueden usarse para especificar archivos a migrar.
También se pueden usar las opciones comunes de git-annex, como las de git-annex-common-options(1).
--remove-size
Las claves a menudo incluyen el tamaño de su contenido, lo cual es generalmente algo útil. De hecho, este comando, por defecto, añade información de tamaño faltante a las claves en la mayoría de las migraciones. Con esta opción, la información de tamaño se elimina en su lugar.
Un uso de esta opción es convertir claves de URL que fueron añadidas por git-annex addurl --fast a aquellas que se habrían añadido si ese comando se ejecutara con la opción --relaxed. Por ejemplo:

git-annex migrate --remove-size --backend=URL algunarchivo
Para añadir de nuevo el tamaño a una clave de URL, use esto:
git-annex migrate --backend=URL algunarchivo
--json
Habilitar salida JSON. Está destinado a ser analizado por programas que usan git-annex. Cada línea de salida es un objeto JSON.
--json-error-messages
Los mensajes que normalmente se mostrarían en la salida estándar de error se incluyen en el JSON en su lugar.
