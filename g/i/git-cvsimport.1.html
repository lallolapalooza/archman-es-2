git-cvsimport(1)

Paquete: git

GIT-CVSIMPORT(1) Manual de Git GIT-CVSIMPORT(1)

NOMBRE

git-cvsimport - Salva tus datos de otro SCM que la gente adora odiar

SINOPSIS

git cvsimport [-o <rama-para-HEAD>] [-h] [-v] [-d <CVSROOT>]
              [-A <archivo-conv-autor>] [-p <opciones-para-cvsps>] [-P <archivo>]
              [-C <repositorio-git>] [-z <fuzz>] [-i] [-k] [-u] [-s <sustitucion>]
              [-a] [-m] [-M <regex>] [-S <regex>] [-L <limite-commits>]
              [-r <remoto>] [-R] [<modulo-CVS>]

DESCRIPCIÓN

ADVERTENCIA: git cvsimport utiliza cvsps versión 2, que se considera obsoleta; no funciona con cvsps versión 3 y posteriores. Si está realizando una importación única de un repositorio CVS, considere usar cvs2git[1] o cvs-fast-export[2].

Importa un repositorio CVS a Git. Creará un nuevo repositorio o importará incrementalmente en uno existente.

La división del log de CVS en conjuntos de parches se realiza mediante cvsps. Se requiere al menos la versión 2.1.

ADVERTENCIA: para ciertas situaciones la importación conduce a resultados incorrectos. Por favor, consulte la sección PROBLEMAS para más referencias.

Usted nunca debe hacer ningún trabajo propio en las ramas que son creadas por git cvsimport. Por defecto, la importación inicial creará y poblará una rama "master" de la rama principal del repositorio CVS que usted puede usar libremente; después de eso, debe hacer git merge las importaciones incrementales, o cualquier rama de CVS, usted mismo. Es aconsejable especificar un remoto con nombre a través de -r para separar y proteger las ramas de entrada.

Si tiene la intención de configurar un repositorio público compartido que todos los desarrolladores puedan leer/escribir, o si desea utilizar git-cvsserver(1), entonces probablemente querrá hacer un clon bare del repositorio importado, y usar el clon como el repositorio compartido. Ver gitcvs-migration(7).

OPCIONES

-v

Verbosidad: deja que cvsimport informe de lo que está haciendo.

-d <CVSROOT>

La raíz del archivo CVS. Puede ser local (una ruta simple) o remota; actualmente, solo se admiten los métodos de acceso :local:, :ext: y :pserver:. Si no se proporciona, git cvsimport intentará leerlo de CVS/Root. Si no existe tal archivo, buscará la variable de entorno CVSROOT.

<modulo-CVS>

El módulo CVS que desea importar. Relativo a <CVSROOT>. Si no se proporciona, git cvsimport intenta leerlo de CVS/Repository.

-C <directorio-destino>

El repositorio Git a importar. Si el directorio no existe, se creará. Por defecto es el directorio actual.

-r <remoto>

El remoto Git a importar este repositorio CVS. Mueve todas las ramas CVS a remotes/<remoto>/<rama> de forma similar a como git clone usa origin por defecto.

-o <rama-para-HEAD>

Cuando no se especifica un remoto (vía -r), la rama HEAD de CVS se importa a la rama origin dentro del repositorio Git, ya que HEAD ya tiene un significado especial para Git. Cuando se especifica un remoto, la rama HEAD se llama remotes/<remoto>/master reflejando el comportamiento de git clone. Utilice esta opción si desea importar a una rama diferente.

Use -o master para continuar una importación que fue inicialmente realizada por la antigua herramienta cvs2git.

-i

Solo importar: no realizar un checkout después de importar. Esta opción asegura que el directorio de trabajo y el índice permanecen intactos y no los creará si no existen.

-k

Eliminar palabras clave: extraerá archivos con -kk del archivo CVS para evitar conjuntos de cambios ruidosos. Muy recomendable, pero desactivado por defecto para mantener la compatibilidad con árboles importados anteriormente.

-u

Convierte guiones bajos en nombres de etiquetas y ramas a puntos.

-s <sustitucion>

Sustituye el carácter "/" en los nombres de rama con <sustitucion>.

-p <opciones-para-cvsps>

Opciones adicionales para cvsps. Las opciones -u y -A son implícitas y no deben usarse aquí.

Si necesita pasar múltiples opciones, sepárelas con una coma.

-z <fuzz>

Pasa el factor de tolerancia de marca de tiempo a cvsps, en segundos. Si no se establece, cvsps usa un valor predeterminado de 300s.

-P <archivo-salida-cvsps>

En lugar de llamar a cvsps, lee el archivo de salida de cvsps proporcionado. Útil para depuración o cuando cvsps se maneja fuera de cvsimport.

-m

Intenta detectar fusiones basándose en el mensaje de commit. Esta opción habilitará expresiones regulares predeterminadas que intentan capturar el nombre de la rama de origen del mensaje de commit.

-M <regex>

Intenta detectar fusiones basándose en el mensaje de commit con una expresión regular personalizada. Se puede usar con -m para habilitar también las expresiones regulares predeterminadas. Debe escapar las barras inclinadas.

La expresión regular debe capturar el nombre de la rama de origen en $1.

Esta opción se puede usar varias veces para proporcionar varias expresiones regulares de detección.

-S <regex>

Omite las rutas que coincidan con la expresión regular.

-a

Importa todos los commits, incluidos los recientes. cvsimport por defecto omite los commits que tienen una marca de tiempo de menos de 10 minutos.

-L <limite>

Limita el número de commits importados. Solución para casos en los que cvsimport consume memoria.

-A <archivo-conv-autor>

CVS por defecto utiliza el nombre de usuario de Unix al escribir sus registros de commit. Usando esta opción y un archivo author-conv-file se mapea el nombre registrado en CVS al nombre del autor, correo electrónico y zona horaria opcional: 
        exon=Andreas Ericsson <ae@op5.se>
        spawn=Simon Pawn <spawn@frog-pond.org> America/Chicago

git cvsimport hará que parezca que esos autores tenían su GIT_AUTHOR_NAME y GIT_AUTHOR_EMAIL configurados correctamente todo el tiempo. Si se especifica una zona horaria, a GIT_AUTHOR_DATE se le aplicará el desplazamiento correspondiente.

Para mayor comodidad, estos datos se guardan en $GIT_DIR/cvs-authors cada vez que se proporciona la opción -A y se leen del mismo archivo cada vez que se ejecuta git cvsimport.

No se recomienda usar esta característica si tiene la intención de exportar cambios de nuevo a CVS más tarde con git cvsexportcommit.

-R

Genera un archivo $GIT_DIR/cvs-revisions que contiene un mapeo desde los números de revisión de CVS a los IDs de commit de Git recién creados. El archivo generado contendrá una línea por cada par (nombre de archivo, revisión) importado; cada línea se verá así: 
src/widget.c 1.1 1d862f173cdc7325b6fa6d2ae1cfd61fd1b512b7

Los datos de revisión se añaden al archivo si ya existe, para ser utilizados al hacer importaciones incrementales.

Esta opción puede ser útil si tiene números de revisión de CVS almacenados en mensajes de commit, sistemas de seguimiento de errores, archivos de correo electrónico y similares.

-h

Imprime un mensaje de uso corto y sale.

SALIDA

Si se especifica -v, el script informa de lo que está haciendo.

De lo contrario, el éxito se indica a la manera Unix, es decir, simplemente saliendo con un estado de salida cero.

PROBLEMAS

Problemas relacionados con las marcas de tiempo:

•Si las marcas de tiempo de los commits en el repositorio CVS no son lo suficientemente estables para ser utilizadas para ordenar los commits, los cambios pueden aparecer en el orden incorrecto.
•Si algún archivo fue alguna vez "cvs import"ado más de una vez (por ejemplo, importación de más de un lanzamiento de proveedor), el HEAD contiene el contenido incorrecto.
•Si el orden de marcas de tiempo de diferentes archivos cruza el orden de revisión dentro de la ventana de tiempo de coincidencia de commit, el orden de los commits puede ser incorrecto.

Problemas relacionados con las ramas:

•Las ramas en las que no se han realizado commits no se importan.
•Todos los archivos desde el punto de ramificación se añaden a una rama incluso si nunca se añadieron en CVS.
•Esto se aplica a los archivos añadidos a la rama de origen
h después de que se creó una rama hija: si previamente no se había realizado ningún commit en la rama hija, erróneamente se añadirán a la rama hija en git.

Problemas relacionados con las

etiquetas:
•No se importan múltiples etiquetas en la misma
revisión.
