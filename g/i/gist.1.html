GIST(1) Manual de Gist GIST(1)

NOMBRE

gist - subir código a https://gist.github.com

SINOPSIS

La gema gist proporciona un comando gist que puedes usar desde tu terminal para subir contenido a https://gist.github.com/.

INSTALACIÓN

○
Si tienes ruby instalado:
gem install gist
○
Si estás usando Bundler:
source :rubygems gem ´gist´
○
Para OS X, gist se encuentra en Homebrew
brew install gist
○
Para FreeBSD, gist se encuentra en los ports
pkg install gist

COMANDO

○
Para subir el contenido de a.rb simplemente:
gist a.rb
○
Subir múltiples archivos:
gist a b c gist *.rb
○
Por defecto lee de STDIN, y puedes establecer un nombre de archivo con -f.
gist -f test.rb <a.rb
○
Alternativamente, puedes simplemente pegar desde el portapapeles:
gist -P
○
Usa -p para hacer el gist privado:
gist -p a.rb
○
Usa -d para añadir una descripción:
gist -d "Error aleatorio de rbx" a.rb
○
Puedes actualizar gists existentes con -u:
gist -u ID_DEL_GIST NOMBRE_DEL_ARCHIVO gist -u 42f2c239d2eb57299408 test.txt
○
Si deseas copiar la URL resultante a tu portapapeles, usa -c.
gist -c <a.rb
○
Si deseas copiar la URL incrustable resultante a tu portapapeles, usa -e.
gist -e <a.rb
○
Y puedes simplemente pedirle a gist que abra una ventana del navegador directamente con -o.
gist -o <a.rb
○
Para listar gists (públicos o todos los gists para el usuario autenticado) de un usuario
gist -l : todos los gists para el usuario autenticado gist -l defunkt : lista los gists públicos de defunkt

Para leer un gist e imprimirlo en STDOUT

gist -r ID_DEL_GIST
gist -r 374130
○
Ver gist --help para más detalles.

INICIO DE SESIÓN

Antes de usar gist por primera vez, necesitarás iniciar sesión. Hay dos flujos de inicio de sesión admitidos:

1.
El flujo OAuth de código de dispositivo de Github. Este es el valor predeterminado para autenticarse en github.com, y se puede habilitar para Github Enterprise creando una aplicación OAuth y exportando la variable de entorno GIST_CLIENT_ID con el ID del cliente de la aplicación OAuth.
2.
El flujo (obsoleto) de intercambio de nombre de usuario y contraseña por token. Este es el valor predeterminado para GitHub Enterprise y se puede usar para iniciar sesión en github.com exportando la variable de entorno GIST_USE_USERNAME_AND_PASSWORD.

El flujo de código de dispositivo

Este flujo te permite obtener un token iniciando sesión en GitHub en el navegador e introduciendo un código de verificación. Este es el mecanismo preferido.

gist --login
Requesting login parameters...
Please sign in at https://github.com/login/device
  and enter code: XXXX-XXXX
Success! https://github.com/settings/connections/applications/4f7ec0d4eab38e74384e

El access_token devuelto se almacena en ~/.gist y se utiliza para todos los gists futuros. Si necesitas revocar el acceso, puedes hacerlo desde https://github.com/settings/connections/applications/4f7ec0d4eab38e74384e.

El flujo de nombre de usuario-contraseña

Este flujo solicita tu nombre de usuario y contraseña de GitHub (y código 2FA), y los intercambia por un token con el permiso "gist" (tu nombre de usuario y contraseña no se almacenan). Este mecanismo está obsoleto por GitHub, pero aún puede funcionar con GitHub Enterprise.

gist --login
Obtaining OAuth2 access_token from GitHub.
GitHub username: ConradIrwin
GitHub password:
2-factor auth code:
Success! https://github.com/settings/tokens

Este token se almacena en ~/.gist y se utiliza para todos los gists futuros. Si necesitas revocarlo, puedes hacerlo desde https://github.com/settings/tokens, o simplemente eliminar el archivo.

Si tienes un requisito de autorización complicado, puedes crear manualmente un archivo de token pegando un token de GitHub con el scope gist (y quizás user:email para GitHub Enterprise) en un archivo llamado ~/.gist. Puedes crear uno desde https://github.com/settings/tokens

Este archivo solo debe contener el token (~40 caracteres hexadecimales) y, para que sea más fácil de editar, opcionalmente puede tener una nueva línea final (\n o \r\n).

Por ejemplo, una forma de crear este archivo sería ejecutar:

(umask 0077 && echo MI_TOKEN_SECRETO > ~/.gist)

El umask asegura que el archivo solo sea accesible desde tu cuenta de usuario.

GitHub Enterprise

Si deseas que gist utilice tu GitHub Enterprise instalado localmente https://enterprise.github.com/, necesitas exportar la variable de entorno GITHUB_URL (normalmente se hace en tu ~/.bashrc).

export GITHUB_URL=http://github.internal.example.com/

Una vez que lo hayas hecho y reiniciado tu terminal (o ejecutado source ~/.bashrc), gist utilizará automáticamente GitHub Enterprise en lugar del github.com público.

Tu token para GitHub Enterprise se almacenará en .gist.<protocolo>.<nombre.servidor>[.<puerto>] (por ejemplo, ~/.gist.http.github.internal.example.com para el ejemplo de GITHUB_URL anterior) en lugar de en ~/.gist.

Si tienes varios servidores o usas Enterprise y GitHub público con frecuencia, puedes solucionar esto creando scripts que configuren la variable de entorno y luego ejecuten gist. Ten en cuenta que para usar el GitHub público debes anular la configuración de la variable de entorno. Simplemente establecerla en la URL pública no funcionará. Usa unset GITHUB_URL

Formato del archivo de token

Si no puedes usar contraseñas, como ocurre en la mayoría de las instalaciones de Enterprise, puedes generar el token a través de la interfaz web y luego simplemente guardar la cadena en el archivo correcto. Evita saltos de línea o podrías ver: $ gist -l Error: Credenciales incorrectas

Puedes usar Gist también como biblioteca desde tu código ruby:

Si necesitas funciones más avanzadas, también puedes pasar:

○
:access_token para autenticarte usando OAuth2 (el valor predeterminado es `File.read("~/.gist")).
○
:filename para cambiar el resaltado de sintaxis (el valor predeterminado es a.rb).
○
:public si quieres que tu gist tenga una URL adivinable.
○
:description para añadir una descripción a tu gist.
○
:update para actualizar un gist existente (puede ser una URL o un ID).
○
:copy para copiar la URL resultante al portapapeles (el valor predeterminado es false).
○
:open para abrir la URL resultante en un navegador (el valor predeterminado es false).

NOTA: El access_token debe tener el scope gist y puede requerir también el scope user:email.
