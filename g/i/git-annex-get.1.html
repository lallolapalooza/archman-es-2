NOMBRE

git-annex-get - hacer que el contenido de los archivos anexados esté disponible

SINOPSIS

git annex get [ruta ...]

DESCRIPCIÓN

Hace que el contenido de los archivos anexados esté disponible en este repositorio. Esto implicará copiarlos de un repositorio remoto, descargarlos o transferirlos desde algún tipo de almacén de clave-valor.

Sin parámetros, obtiene todos los archivos anexados en el directorio actual cuyo contenido aún no estaba presente. Se pueden especificar rutas de archivos o directorios para obtener.

EJEMPLOS


# evince foo.pdf
error: Unable to open document foo.pdf: No such file or directory
# ls foo.pdf
foo.pdf@
# git annex get foo.pdf
get foo.pdf (from origin..) ok
# evince foo.pdf

OPCIONES

--auto
En lugar de obtener todos los archivos especificados, obtén solo aquellos que aún no tengan el número deseado de copias, o que sean contenido preferido del repositorio. Ver git-annex-preferred-content(1)
--from=remoto
Normalmente, git-annex elegirá de qué repositorios remotos obtener el contenido, prefiriendo los repositorios con costos más bajos. Usa esta opción para especificar qué repositorio remoto usar.
Cualquier archivo que no esté disponible en el repositorio remoto será omitido silenciosamente.
--jobs=N -JN
Permite la descarga paralela con hasta el número especificado de trabajos ejecutándose a la vez. Por ejemplo: -J10
Establecer esto a "cpus" ejecutará un trabajo por núcleo de CPU.
Cuando los archivos se pueden descargar de múltiples repositorios remotos, habilitar descargas paralelas dividirá la carga entre los repositorios remotos. Por ejemplo, si los archivos están disponibles en los repositorios remotos A y B, entonces se descargará un archivo de A y otro archivo de B en paralelo. (Los repositorios con costos más bajos todavía se prefieren sobre los de mayor costo.)
opciones de coincidencia
Se pueden usar las opciones de coincidencia de git-annex-matching-options(1) para controlar qué obtener.
--incomplete
Reanuda las descargas incompletas de archivos que se iniciaron y se interrumpieron en algún momento anterior. Útil para continuar donde lo dejaste... cuando no recuerdas exactamente dónde fue eso.
Estos archivos incompletos son los mismos que se enumeran como archivos temporales no utilizados por git-annex-unused(1).
Ten en cuenta que se mostrará la clave de git-annex al descargar, ya que git-annex no conoce el archivo asociado, y el archivo asociado puede que ni siquiera esté en el directorio de trabajo de git actual.
--all -A
En lugar de especificar un nombre de archivo o ruta para obtener, esta opción se puede usar para obtener todas las versiones disponibles de todos los archivos.
Este es el comportamiento predeterminado cuando se ejecuta git-annex en un repositorio vacío.
--branch=ref
Opera sobre los archivos en la rama o árbol especificado.
--unused
Opera sobre los archivos encontrados por la última ejecución de git-annex unused.
--failed
Opera sobre los archivos que han fallado recientemente al transferirse.
No confundir con --incomplete, que reanuda solo las descargas que lograron transferir parte del contenido de un archivo.
--key=nombre_clave
Usa esta opción para obtener una clave especificada.
--batch
Permite el modo por lotes, en el que se leen líneas que contienen nombres de archivos para obtener desde la entrada estándar.
A medida que se procesa cada archivo especificado, se muestra la salida de progreso habitual. Si el contenido del archivo especificado ya está presente, o no coincide con las opciones de coincidencia especificadas, o no es un archivo anexado, en su lugar se emite una línea en blanco en respuesta.
Dado que la salida habitual al obtener un archivo es detallada y no puede ser analizada por máquinas, es posible que desees usar --json en combinación con --batch.
--batch-keys
Esto es como --batch, pero las líneas leídas desde la entrada estándar se analizan como claves.
-z
Hace que la entrada del lote sea delimitada por nulos en lugar de las nuevas líneas habituales.
--json
Habilita la salida JSON. Está pensada para ser analizada por programas que utilizan git-annex. Cada línea de salida es un objeto JSON.
--json-progress
Incluye objetos de progreso en la salida JSON.
--json-error-messages
Los mensajes que normalmente se emitirían a la salida de error estándar se incluyen en el JSON en su lugar.
También se pueden usar las opciones comunes de git-annex-common-options(1).
