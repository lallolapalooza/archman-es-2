NOMBRE

git-annex-common-options - opciones compatibles con muchos comandos de git-annex

DESCRIPCIÓN

Estas opciones comunes son aceptadas por muchos comandos de git-annex, y es posible que no se listen explícitamente en sus páginas de manual individuales. La mayoría de estas opciones son aceptadas por todos los comandos de git-annex. (Muchos comandos también aceptan las opciones de coincidencia de git-annex-matching-options(1).)

OPCIONES

--force
Fuerza acciones inseguras, como eliminar el contenido de un archivo cuando no se puede verificar que exista otra fuente del mismo, o agregar archivos ignorados. Usar con cuidado.
--fast
Evita algunas operaciones costosas que normalmente realiza un comando. Lo que se evita depende del comando, consulta las páginas de manual individuales de cada comando para obtener detalles.
--quiet
Evita la visualización detallada por defecto de lo que se hace; solo muestra errores.
--verbose
Habilita la visualización detallada. Habilitado por defecto pero se puede deshabilitar con --quiet.
--explain
Muestra explicaciones de lo que git-annex tiene en cuenta al decidir qué hacer. Las explicaciones estarán entre corchetes. Por ejemplo, "[foo no está presente aquí]"
Esto incluye explicaciones de por qué las expresiones de contenido preferido y otras expresiones similares como annex.largefiles coinciden o no coinciden. En estas explicaciones, se muestra la expresión, seguida de cada término por "[VERDADERO]" o "[FALSO]" para indicar el valor. Los términos irrelevantes se omitirán de la explicación, por ejemplo, "exclude=* and copies=1" se mostrará como "exclude=*[FALSE]"
--debug
Muestra mensajes de depuración en la salida estándar de error.
--no-debug
Deshabilita la visualización de mensajes de depuración.
--debugfilter=nombre[,nombre..]
Cuando se ha habilitado la visualización de mensajes de depuración con --debug, esto filtra los mensajes de depuración que se muestran para aquellos provenientes de módulos con los nombres especificados.
Para encontrar los nombres de los módulos, consulta la salida de depuración completa, que incluye el nombre del módulo, por ejemplo, "(Utility.Process)"
El nombre completo del módulo no necesita especificarse al usar esto, una subcadena del nombre será suficiente.
Por ejemplo, --debugfilter=Process,External mostrará la salida de depuración cuando git-annex ejecute procesos y cuando se comunique con remotos especiales externos.
--numcopies=n
Anula la configuración de numcopies.
--mincopies=n
Anula la configuración de mincopies.
--rebalance
Cambia el comportamiento de la expresión de contenido preferido "balanced" para que sea igual a "fullbalanced" y la expresión "sizebalanced" para que sea igual a "fullsizebalanced". Cuando se usan estas expresiones, esto puede generar mucho trabajo para reequilibrar los repositorios.
--time-limit=tiempo
Limita cuánto tiempo se ejecuta un comando de git-annex. El tiempo puede ser algo como "5h", o "30m" o incluso "45s" o "10d".
Ten en cuenta que git-annex puede seguir ejecutándose durante algún tiempo después del límite de tiempo especificado, para terminar de procesar archivos que comenzó antes de que se alcanzara el límite de tiempo. Eso y un apagado más limpio son las diferencias entre usar esta opción y un comando como timeout(1).
Cuando el límite de tiempo impide que git-annex haga todo lo que se le pidió, saldrá con un código especial, 101.
--size-limit=tamaño
Limita el tamaño total de los archivos anexados que un comando de git-annex puede procesar.
El tamaño se puede especificar con cualquier unidad comúnmente utilizada, por ejemplo, "50gb".
En algunos casos, no se conoce el tamaño de un archivo anexado. Esta opción evitará que git-annex procese dichos archivos.
Cuando el límite de tamaño impide que git-annex actúe sobre algún archivo, saldrá con un código especial, 101.
--semitrust=repositorio
--untrust=repositorio
Anula la configuración de confianza para un repositorio. Se puede especificar más de una vez.
El repositorio debe especificarse utilizando el nombre de un remoto configurado, o el UUID o la descripción de un repositorio.
--trust=repositorio
Esto solía anular la configuración de confianza para un repositorio, pero ahora no lo hará, ya que confiar en un repositorio puede llevar a la pérdida de datos, y la pérdida de datos ahora solo se habilita cuando se usa la opción --force.
--trust-glacier
Esto solía anular la configuración de confianza para los remotos especiales de Glacier, pero ahora no lo hará, ya que podría llevar a la pérdida de datos, y la pérdida de datos ahora solo se habilita cuando se usa la opción --force.
--user-agent=valor
Anula el User-Agent a utilizar al descargar archivos de la web, o al acceder a servicios web de otra manera.
--notify-finish
Causa que se muestre una notificación de escritorio después de cada descarga y carga de archivo exitosa.
(Solo compatible en algunas plataformas, por ejemplo, Linux con dbus. No hace nada cuando no es compatible.)
--notify-start
Causa que se muestre una notificación de escritorio cuando ha comenzado una carga o descarga de archivo, o cuando se elimina un archivo.
-c nombre=valor
Anula la configuración de git. Se puede especificar varias veces.
