git-lfs-checkout(1)

Paquete: git-lfs

Licencias: MIT

GIT-LFS-CHECKOUT(1)   GIT-LFS-CHECKOUT(1)

NOMBRE

git-lfs-checkout - Actualiza la copia de trabajo con el contenido de los archivos si está disponible

SINOPSIS

git lfs checkout [<patrón-glob>...]
git lfs checkout --to <archivo> {--base|--ours|--theirs} <ruta-objeto-conflicto>

DESCRIPCIÓN

Intenta asegurarse de que la copia de trabajo contenga el contenido de los archivos para los objetos Git LFS para la referencia actual, si los datos del objeto están disponibles. No descarga ningún contenido; vea git-lfs-fetch(1) para eso.

Checkout escanea la referencia actual en busca de todos los objetos LFS que serían necesarios, luego donde un archivo está ausente en la copia de trabajo, o contiene contenido de puntero placeholder con el mismo SHA, el archivo real se escribe, siempre que lo tengamos en la tienda local. Los archivos modificados nunca se sobrescriben.

Se puede proporcionar uno o más patrones de archivo como argumentos para restringir el conjunto de archivos que se actualizan. Los patrones glob se comparan según el formato descrito en gitignore(5).

Cuando se utiliza con --to y el árbol de trabajo está en un estado conflictivo debido a una fusión, esta opción extrae una de las tres etapas de un objeto Git LFS conflictivo en un archivo separado (que puede estar fuera del árbol de trabajo). Esto puede facilitar el uso de herramientas de diferencia para inspeccionar y resolver fusiones. Se debe proporcionar la ruta de archivo de un solo objeto Git LFS en <ruta-objeto-conflicto>. Si <archivo> ya existe, ya sea como un archivo regular, un enlace simbólico o un directorio, se eliminará y reemplazará, a menos que sea un directorio no vacío o no se pueda eliminar de otra manera.

Si la versión de Git instalada es igual o posterior a la 2.42.0, este comando, por defecto, extraerá objetos Git LFS para archivos solo si están presentes en el índice de Git y si coinciden con un atributo de filtro de Git LFS de un archivo .gitattributes que esté presente en el índice o en el árbol de trabajo actual (o, como siempre es el caso, si coinciden con un atributo de filtro de Git LFS en un archivo gitattributes local como $GIT_DIR/info/attributes). Estas restricciones no se aplican con versiones anteriores de Git.

En un repositorio con clonación parcial o checkout disperso, por lo tanto, es aconsejable extraer todos los archivos .gitattributes de HEAD antes de usar este comando, si se instala Git v2.42.0 o posterior. Alternativamente, la variable de entorno GIT_ATTR_SOURCE puede establecerse en HEAD, lo que hará que Git solo lea atributos de los archivos .gitattributes en HEAD e ignore los del índice o árbol de trabajo.

En un repositorio desnudo, este comando no tiene efecto. En una versión futura, este comando puede salir con un error si se ejecuta en un repositorio desnudo.

OPCIONES

--base

Extrae la base de fusión del archivo especificado.

--ours

Extrae nuestro lado (el de la rama actual) del conflicto para el archivo especificado.

--theirs


Extrae su lado (el de la otra rama) del conflicto para el archivo especificado.

--to <ruta>

Si el árbol de trabajo está en un estado de conflicto, extrae la porción del conflicto especificada por --base, --ours, o --theirs a la ruta dada.

EJEMPLOS

•Extraer todos los archivos que faltan o son placeholders:
$ git lfs checkout
•Extraer un par de archivos específicos:
$ git lfs checkout ruta/a/archivo1.png ruta/a.archivo2.png
•Extraer una ruta con un conflicto de fusión en archivos separados:
# Intentar fusionar con una rama que tiene un conflicto de fusión
$ git merge rama-en-conflicto
CONFLICT (contenido): Conflicto de fusión en ruta/a/archivo/en/conflicto/archivo.dat
# Extraer versiones del archivo en conflicto en archivos temporales
$ git lfs checkout --to ours.dat --ours ruta/a/archivo/en/conflicto/archivo.dat
$ git lfs checkout --to theirs.dat --theirs ruta/a/archivo/en/conflicto/archivo.dat
# Comparar las versiones en conflicto en ours.dat y theirs.dat,
# luego resolver el conflicto (por ejemplo, eligiendo una versión
# sobre la otra, o creando una nueva versión)
# Limpiar y continuar con la fusión
$ rm ours.dat theirs.dat
$ git add ruta/a/archivo/en/conflicto/archivo.dat
$ git merge --continue
