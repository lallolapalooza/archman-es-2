NOMBRE

git-fsmonitor--daemon - Un monitor de sistema de archivos incorporado

SINOPSIS

git fsmonitor--daemon start
git fsmonitor--daemon run
git fsmonitor--daemon stop
git fsmonitor--daemon status

DESCRIPCIÓN

Un demonio para vigilar el directorio de trabajo en busca de cambios en archivos y directorios utilizando mecanismos de notificación del sistema de archivos específicos de la plataforma.

Este demonio se comunica directamente con comandos como git status utilizando la interfaz IPC simple[1] en lugar de la más lenta interfaz de githooks(5).

Este demonio está integrado en Git para que no se requieran herramientas de terceros.

OPCIONES

start

Inicia un demonio en segundo plano.

run

Ejecuta un demonio en primer plano.

stop

Detiene el demonio que se ejecuta en el directorio de trabajo actual, si existe.

status

Sale con estado cero si un demonio está vigilando el directorio de trabajo actual.

OBSERVACIONES

Este demonio es un proceso de larga duración utilizado para vigilar un único directorio de trabajo y mantener una lista de los archivos y directorios modificados recientemente. El rendimiento de comandos como git status puede mejorar si simplemente solicitan un resumen de los cambios en el directorio de trabajo y pueden evitar escanear el disco.

Cuando core.fsmonitor está configurado a true (ver git-config(1)), comandos como git status solicitarán los cambios al demonio y lo iniciarán automáticamente (si es necesario).

Para más información, consulte la sección "File System Monitor" en git-update-index(1).

ADVERTENCIAS

El demonio fsmonitor actualmente no conoce los submodulos y no sabe filtrar los eventos del sistema de archivos que ocurren dentro de un submódulo. Si el demonio fsmonitor está vigilando un repositorio principal y un archivo se modifica dentro del directorio de trabajo de un submódulo, informará el cambio (como si ocurriera contra el repositorio principal). Sin embargo, el cliente ignorará correctamente estos eventos adicionales, por lo que el rendimiento puede verse afectado, pero no causará un resultado incorrecto.

Por defecto, el demonio fsmonitor se niega a trabajar con repositorios montados en red; esto puede ser anulado estableciendo fsmonitor.allowRemote a true. Tenga en cuenta, sin embargo, que no se garantiza que el demonio fsmonitor funcione correctamente con todos los repositorios montados en red, por lo que dicho uso se considera experimental.

En Mac OS, la comunicación entre procesos (IPC) entre varios comandos de Git y el demonio fsmonitor se realiza a través de un socket de dominio Unix (UDS) —un tipo especial de archivo— que es compatible con los sistemas de archivos nativos de Mac OS, pero no en sistemas de archivos montados en red, NTFS o FAT32. Otros sistemas de archivos pueden o no tener el soporte necesario; no se garantiza que el demonio fsmonitor funcione con estos sistemas de archivos y dicho uso se considera experimental.

Por defecto, el socket se crea en el directorio .git. Sin embargo, si el directorio .git está en un sistema de archivos montado en red, se creará en su lugar en $HOME/.git-fsmonitor-* a menos que $HOME mismo esté en un sistema de archivos montado en red, en cuyo caso debe establecer la variable de configuración fsmonitor.socketDir al directorio de un directorio en un sistema de archivos nativo de Mac OS en el cual crear el archivo socket.

Si ninguno de los directorios anteriores (.git, $HOME o fsmonitor.socketDir) está en un sistema de archivos nativo de Mac OS, el demonio fsmonitor informará un error que provocará la salida del demonio y del comando en ejecución.

CONFIGURACIÓN

Todo lo que está debajo de esta línea en esta sección se incluye selectivamente de la documentación de git-config(1). El contenido es el mismo que el que se encuentra allí:

fsmonitor.allowRemote

Por defecto, el demonio fsmonitor se niega a trabajar con repositorios montados en red. Establecer fsmonitor.allowRemote a true anula este comportamiento. Solo se respeta cuando core.fsmonitor está configurado a true.

fsmonitor.socketDir

Esta opción específica de Mac OS, si está establecida, especifica el directorio en el que se creará el socket de dominio Unix utilizado para la comunicación entre el demonio fsmonitor y varios comandos de Git. El directorio debe residir en un sistema de archivos nativo de Mac OS. Solo se respeta cuando core.fsmonitor está configurado a true.
