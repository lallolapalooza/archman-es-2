te - crea un remoto

SINOPSI

S

git annex initremote nombre tipo=valor [parametro=valor ..

.
]

DESCRIPCIÓ

N

Crea un nuevo remoto especial y lo añade a .git/con

fig.

Ejemplo de remoto Amazon

S3:


git annex initremote mys3 type=S3 encryption=hybrid keyid=me@example.com

datacenter=EU

git-annex admite muchos tipos diferentes de remotos especiales. Para obtener una lista y detalles, consulta https://git-annex.branchable.com/special_remotes

/

La configuración del remoto se especifica mediante los parámetros pasados a este comando. Diferentes tipos de remotos especiales necesitan diferentes valores de configuración, así que consulta la documentación de un remoto especial para detalles. El comando te pedirá cualquier parámetro requerido que hayas omitido; también puedes pasar --whatelse para ver parámetros

adicionales.

Algunos parámetros que son soportados por todos los remotos especiales están documentados en la siguiente

sección.

Una vez que un remoto especial ha sido inicializado una vez con este comando, otros clones del repositorio también pueden ser configurados para acceder a él usando git annex enab

leremote.

El nombre que proporciones para el remoto no puede ser uno que haya sido usado para cualquier otro remoto especial antes, porque git-annex enableremote usa el nombre para identificar qué remoto especial habilitar. Si algún remoto especial antiguo que ya no se usa ha tomado el nombre que quieres reutilizar, podrías querer usar git annex re

namer
emote.

OPCIONE

S
--with-u
rl
Esto configura el remoto con una url "annex::", lo que permite a git hacer push y pull de él, usando
git-remote-annex.
--whatelse / -
w
Describe parámetros de configuración adicionales que podrías
especificar.
Por ejemplo, si sabes que quieres un remoto S3, pero olvidas cómo
configurarlo:

git annex initremote mys3 type=S3
--whatelse
Para obtener una lista legible por máquina de los parámetros, usa esto con --jso
n.
--fa
st
Al inicializar un remoto que usa cifrado, se crea una clave criptográfica. Esto requiere suficiente entropía. Si initremote parece colgarse o tardar mucho tiempo al generar la clave, podrías querer interrumpirlo con Ctrl-c y volver a ejecutarlo con --fast, lo que hace que use una fuente de aleatoriedad de menor calidad. (Es decir, /dev/urandom en lugar de
/dev/random)
--sameas=rem
oto
Usa esto cuando el nuevo remoto especial usa el mismo almacenamiento subyacente que algún otro remoto. Esto resultará en que el nuevo remoto especial tenga el mismo uuid que el remoto especificado, y cualquiera de ellos puede ser usado para acceder al mismo
contenido.
El remoto puede ser el nombre de un remoto git, o la descripción o uuid de cualquier repositorio
git-annex.
Al usar esta opción, el nuevo remoto hereda los ajustes de cifrado del remoto existente, así que no deberías especificar ningún parámetro de cifrado. Ninguna otra configuración se hereda del remoto
existente.
Esto solo funcionará si ambos remotos usan el almacenamiento subyacente de maneras compatibles. Consulta esta página para información sobre compatibilidades conocidas. http://git-annex.branchable.com/tips/multiple_remotes_accessing_the_same_data_sto
re/
--priva
te
Evita registrar información sobre el remoto especial en la rama git-annex. El remoto especial solo será utilizable desde el repositorio donde fue
creado.
--js
on
Habilita la salida JSON. Está destinado a ser analizado por programas que usan
git-annex.
--json-error-messa
ges
Los mensajes que normalmente se emitirían a la salida de error estándar se incluyen en el JSON en su
lugar.
También se puede usar git-annex-common-options(1)
.

PARÁMETROS DE CONFIGURACIÓN

COMUNES
encrypti
on
Casi todos los remotos especiales soportan cifrado. Necesitarás especificar qué cifrado, si alguno,
usar.
Si no quieres ningún cifrado, usa encryption=n
one
Para cifrar a una clave GPG, usa encryption=hybrid keyid=$keyid ... y rellena el id de la clave GPG (o una dirección de correo electrónico asociada a una clave
GPG).
Para detalles sobre esto y otros ajustes de cifrado, consulta https://git-annex.branchable.com/encryption/ o
--whatelse
autoenab
le
Para evitar tener que ejecutar git annex enableremote, puedes pasar "autoenable=true". Entonces, cuando git-annex se ejecute en un nuevo clon, intentará habilitar el remoto especial. Por supuesto, esto funciona mejor cuando el remoto especial no necesita nada especial para ser
habilitado.
co
st
Especifica esto para anular el costo por defecto del remoto especial. Esta configuración puede ser anulada por la configuración git local, por ejemplo remote.name.
annex-cost.
uu
id
Normalmente, git-annex initremote genera un nuevo UUID para el nuevo re
moto especial. Si quieres, puedes especificar un UUID para que lo
use, pasando un parámetro uuid=whatever. Esto puede ser útil en
algunas situaciones inusuales. Pero si tienes dudas, no lo hagas.
