NOMBRE

git-lfs-merge-driver - Fusiona archivos de texto LFS

SINOPSIS

git lfs merge-driver [opciones]

DESCRIPCIÓN

Fusiona archivos de texto almacenados en Git LFS utilizando la maquinaria de fusión predeterminada de Git, o un controlador de fusión personalizado si se especifica. Tenga en cuenta que esto, en general, no admite renombrados o copias parciales porque Git no los admite en este caso.

Este programa está destinado a ser invocado automáticamente por Git y no por usuarios manualmente. Consulte CONFIGURACIÓN para obtener detalles sobre la configuración requerida para ello.

OPCIONES

--ancestor <ruta>

Especifica el archivo que contiene la revisión ancestral.

--current <ruta>

Especifica el archivo que contiene la revisión actual.

--marker-size <num>

Especifica el tamaño del marcador de conflicto como un entero.

--other <ruta>

Especifica el archivo que contiene la otra revisión.

--program <programa>

Especifica un comando, que se pasa al shell después de la sustitución, que realiza la fusión real. Si esto no se especifica, se invoca git merge-file con los argumentos apropiados para realizar la fusión del archivo.

Consulte CONFIGURACIÓN para conocer las secuencias que se sustituyen aquí.

CONFIGURACIÓN

Git permite el uso de un controlador de fusión personalizado para archivos basado en el atributo merge establecido en .gitattributes. Por defecto, al usar git lfs track, este valor se establece en lfs.

Dado que Git LFS se puede usar para almacenar archivos de texto y binarios, y no siempre está claro qué comportamiento se debe usar, Git LFS no habilita este controlador de fusión de forma predeterminada. Sin embargo, si sabe que algunos o todos sus archivos son archivos de texto, puede establecer el atributo merge para esos archivos en lfs-text y usar git config para establecer el controlador de fusión de la siguiente manera:

$ git config merge.lfs-text.driver 'git lfs merge-driver --ancestor %O --current %A --other %B --marker-size %L --output %A'

Esto le dice a Git que invoque el controlador de fusión personalizado de Git LFS, que a su vez utiliza la maquinaria de fusión de Git, para fusionar archivos donde el atributo merge está establecido en lfs-text. Tenga en cuenta que lfs-text aquí es un ejemplo y se puede usar cualquier valor sintácticamente válido.

Si está utilizando un tipo especial de archivo que necesita reglas diferentes de la maquinaria de fusión estándar de Git, también puede especificar la opción --program, que se pasa a sh después de sustituir sus propios escapes codificados en porcentaje:

•%A: la versión actual
•%B: la otra versión
•%D: la versión de destino
•%O: la versión ancestral
•%L: el tamaño del marcador de conflicto

Tenga en cuenta que el signo de porcentaje debe duplicarse típicamente para evitar que Git sustituya sus propios valores aquí. Por lo tanto, especificar explícitamente el comportamiento predeterminado se ve así:

$ git config merge.lfs-text.driver \
  'git lfs merge-driver --ancestor %O --current %A --other %B --marker-size %L --output %A --program '\''git merge-file --stdout --marker-size=%%L %%A %%O %%B >%%D'\'''

El estado de salida del comando personalizado debe ser cero en caso de éxito o distinto de cero en caso de conflictos u otro fallo.

Tenga en cuenta que si no se especifica ningún controlador de fusión para el valor del atributo merge (como es el caso por defecto con merge=lfs), entonces se utiliza la estrategia de fusión predeterminada de Git. Para los archivos LFS, esto significa que Git intentará fusionar los archivos de puntero, lo cual generalmente no es útil.
