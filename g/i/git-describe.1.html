NOMBRE

git-describe - Asigna a un objeto un nombre legible para humanos basado en una referencia disponible

SINOPSIS

git describe [--all] [--tags] [--contains] [--abbrev=<n>] [<commit-ish>...]
git describe [--all] [--tags] [--contains] [--abbrev=<n>] --dirty[=<mark>]
git describe <blob>

DESCRIPCIÓN

El comando encuentra la etiqueta más reciente a la que se puede llegar desde un commit. Si la etiqueta apunta al commit, entonces solo se muestra la etiqueta. De lo contrario, añade al nombre de la etiqueta el número de commits adicionales sobre el objeto etiquetado y el nombre abreviado del commit más reciente. El resultado es un nombre de objeto "legible para humanos" que también puede usarse para identificar el commit ante otros comandos de git.

De forma predeterminada (sin --all ni --tags) git describe solo muestra etiquetas anotadas. Para más información sobre cómo crear etiquetas anotadas, consulta las opciones -a y -s de git-tag(1).

Si el objeto dado se refiere a un blob, se describirá como <commit-ish>:<path>, de modo que el blob pueda encontrarse en <path> en el <commit-ish>, el cual describe el primer commit en el que aparece este blob en un recorrido inverso de revisión desde HEAD.

OPCIONES

<commit-ish>...

Nombres de objetos commit-ish a describir. Por defecto es HEAD si se omite.

--dirty[=<mark>], --broken[=<mark>]

Describe el estado del árbol de trabajo. Cuando el árbol de trabajo coincide con HEAD, la salida es la misma que "git describe HEAD". Si el árbol de trabajo tiene modificaciones locales, se añade "-dirty" al final. Si un repositorio está corrupto y Git no puede determinar si hay modificaciones locales, Git emitirá un error, a menos que se proporcione ‘--broken’, que añade el sufijo "-broken" en su lugar.

--all

En lugar de usar solo las etiquetas anotadas, usa cualquier referencia encontrada en el espacio de nombres refs/ . Esta opción permite hacer coincidir cualquier rama conocida, rama de seguimiento remoto o etiqueta ligera.

--tags

En lugar de usar solo las etiquetas anotadas, usa cualquier etiqueta encontrada en el espacio de nombres refs/tags . Esta opción permite hacer coincidir una etiqueta ligera (no anotada).

--contains

En lugar de encontrar la etiqueta que precede al commit, encuentra la etiqueta que viene después del commit y, por lo tanto, lo contiene. Implica automáticamente --tags.

--abbrev=<n>

En lugar de usar el número predeterminado de dígitos hexadecimales (que variará según el número de objetos en el repositorio, con un valor predeterminado de 7) del nombre abreviado del objeto, usa <n> dígitos, o tantos dígitos como sean necesarios para formar un nombre de objeto único. Un <n> de 0 suprimirá el formato largo, mostrando solo la etiqueta más cercana.

--candidates=<n>

En lugar de considerar solo las 10 etiquetas más recientes como candidatas para describir el commit-ish de entrada, considera hasta <n> candidatas. Aumentar <n> por encima de 10 tomará un poco más de tiempo pero puede producir un resultado más preciso. Un <n> de 0 hará que solo se emitan coincidencias exactas.

--exact-match

Solo emite coincidencias exactas (una etiqueta referencia directamente el commit proporcionado). Esto es un sinónimo de --candidates=0.

--debug

Muestra de forma detallada información sobre la estrategia de búsqueda empleada en la salida de error estándar. El nombre de la etiqueta seguirá imprimiéndose en la salida estándar.

--long

Siempre emite el formato largo (la etiqueta, el número de commits y el nombre abreviado del commit) incluso cuando coincide con una etiqueta. Esto es útil cuando quieres ver partes del nombre del objeto commit en la salida de "describe", incluso cuando el commit en cuestión resulta ser una versión etiquetada. En lugar de emitir solo el nombre de la etiqueta, describirá dicho commit como v1.2-0-gdeadbee (commit 0 desde la etiqueta v1.2 que apunta al objeto deadbee....).

--match <pattern>

Solo considera etiquetas que coincidan con el patrón glob(7) dado, excluyendo el prefijo "refs/tags/". Si se usa con --all, también considera ramas locales y referencias de seguimiento remoto que coincidan con el patrón, excluyendo respectivamente los prefijos "refs/heads/" y "refs/remotes/"; las referencias de otros tipos nunca se consideran. Si se da varias veces, se acumulará una lista de patrones, y se considerarán las etiquetas que coincidan con cualquiera de los patrones. Usa --no-match para limpiar y restablecer la lista de patrones.

--exclude <pattern>

No considera etiquetas que coincidan con el patrón glob(7) dado, excluyendo el prefijo "refs/tags/". Si se usa con --all, tampoco considera ramas locales y referencias de seguimiento remoto que coincidan con el patrón, excluyendo respectivamente los prefijos "refs/heads/" y "refs/remotes/"; las referencias de otros tipos nunca se consideran. Si se da varias veces, se acumulará una lista de patrones, y se excluirán las etiquetas que coincidan con cualquiera de los patrones. Cuando se combina con --match, una etiqueta se considerará cuando coincida con al menos un patrón --match y no coincida con ninguno de los patrones --exclude. Usa --no-exclude para limpiar y restablecer la lista de patrones.

--always

Muestra el objeto commit abreviado de forma única como alternativa.

--first-parent

Sigue solo el commit padre primero al encontrar un commit de fusión. Esto es útil cuando no deseas que se hagan coincidir etiquetas en ramas fusionadas en el historial del commit objetivo.

EJEMPLOS

Con algo como el árbol actual de git.git, obtengo:

[torvalds@g5 git]$ git describe parent
v1.0.4-14-g2414721

es decir, la cabecera actual de mi rama "parent" está basada en v1.0.4, pero como tiene algunos commits encima de eso, describe ha añadido el número de commits adicionales ("14") y un nombre abreviado del objeto para el propio commit ("2414721") al final.

El número de commits adicionales es el número de commits que mostraría "git log v1.0.4..parent". El sufijo del hash es "-g" + una abreviatura no ambigua para el commit punta de parent (que era 2414721b194453f058079d897d13c4e377f92dc6). La longitud de la abreviatura escala a medida que crece el repositorio, usando el número aproximado de objetos en el repositorio y un poco de matemáticas alrededor de la paradoja del cumpleaños, y tiene un mínimo predeterminado de 7. El prefijo "g" significa "git" y se usa para permitir describir la versión de un software dependiendo del SCM con el que se gestiona el software. Esto es útil en un entorno donde las personas pueden usar diferentes SCM.

Hacer un git describe en un nombre de etiqueta solo mostrará el nombre de la etiqueta:

[torvalds@g5 git]$ git describe v1.0.4
v1.0.4

Con --all, el comando puede usar cabeceras de ramas como referencias, por lo que la salida muestra también la ruta de la referencia:

[torvalds@g5 git]$ git describe --all --abbrev=4 v1.0.5^2
tags/v1.0.0-21-g975b
[torvalds@g5 git]$ git describe --all --abbrev=4 HEAD^
heads/lt/describe-7-g975b

Con --abbrev establecido a 0, el comando puede usarse para encontrar el nombre de etiqueta más cercano sin ningún sufijo:

[torvalds@g5 git]$ git describe --abbrev=0 v1.0.5^2
tags/v1.0.0

Ten en cuenta que el sufijo que obtienes si escribes estos comandos hoy puede ser más largo de lo que Linus vio arriba cuando ejecutó estos comandos, ya que tu repositorio de Git puede tener commits nuevos cuyos nombres de objeto comienzan con 975b que no existían en ese entonces, y el sufijo "-g975b" por sí solo puede no ser suficiente para desambiguar estos commits.

ESTRATEGIA DE BÚSQUEDA

Para cada commit-ish proporcionado, git describe primero buscará una etiqueta que etiquete exactamente ese commit. Las etiquetas anotadas siempre se preferirán sobre las etiquetas ligeras, y las etiquetas con fechas más recientes siempre se preferirán sobre las etiquetas con fechas más antiguas. Si se encuentra una coincidencia exacta, se emitirá su nombre y la búsqueda se detendrá.

Si no se encontró una coincidencia exacta, git describe recorrerá el historial de commits hacia atrás para localizar un commit ancestro que haya sido etiquetado. La etiqueta del ancestro se emitirá junto con una abreviatura del SHA-1 del commit-ish de entrada. Si --first-parent fue especificado entoncesalk solo considerará el primer padre de cada commit.

Si se encontraron múltiples etiquetas durante el recorrido, se seleccionará y mostrará la etiqueta que tenga la menor cantidad de commits diferentes del commit-ish de entrada. Aquí, la menor cantidad de commits diferentes se define como el número de commits que mostraría git log tag..input será el número más pequeño de commits posible.

ERRORES

Los objetos de árbol, así como los objetos de etiqueta que no apuntan a commits, no se pueden describir. Al describir blobs, las etiquetas ligeras que apuntan a blobs se ignoran, pero el blob aún se describe como <commit-ish>:<ruta> a pesar de que la etiqueta ligera sería preferible.
