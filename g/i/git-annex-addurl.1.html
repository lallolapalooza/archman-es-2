NOMBRE

git-annex-addurl - añadir urls al annex

SINOPSIS

git annex addurl [url ...]

DESCRIPCIÓN

Descarga cada url a su propio archivo, que se añade al annex.

Cuando yt-dlp está instalado, se puede usar para buscar un vídeo incrustado en una página web en la url, y ese se añade al annex en su lugar. (Sin embargo, esto está deshabilitado por defecto ya que puede ser un riesgo de seguridad. Consulte la documentación de annex.security.allowed-ip-addresses en git-annex(1) para más detalles.)

Los remotos especiales pueden añadir otro manejo especial de urls particulares. Por ejemplo, los remotos especiales de bittorrent hacen que las urls de archivos torrent (incluidos los enlaces magnet) descarguen el contenido del torrent, usando aria2c.

Normalmente el nombre del archivo se basa en la url completa, por lo que se verá como "www.ejemplo.com_dir_subdir_archivo_grande". En algunos casos, addurl es capaz de encontrar un mejor nombre de archivo basado en otra información. Las opciones también se pueden usar para obtener mejores nombres de archivo.

OPCIONES

--fast
Evita descargar la url inmediatamente. La url todavía se verifica (mediante HEAD) para confirmar que existe y para obtener su tamaño si es posible.
--relaxed
No descargues la url inmediatamente, y evita almacenar el tamaño del contenido de la url. Esto hace que git-annex acepte cualquier contenido que esté allí en un momento futuro.
Esta es la opción más rápida, pero todavía tiene que acceder a la red para verificar si la url contiene medios incrustados. Al añadir un gran número de urls, usar --relaxed --raw es mucho más rápido.
--verifiable -V
Esto se puede usar con la opción --fast o --relaxed. Mejora la seguridad del archivo anexado resultante, permitiendo que su contenido sea verificado con una suma de comprobación cuando se transfiere entre repositorios de git-annex, así como por cosas como git-annex fsck.
Cuando se usa con --relaxed, el contenido del remoto web siempre será aceptado, incluso si ha cambiado, y la suma de comprobación se registrará para su verificación posterior.
Cuando se usa con --fast, la suma de comprobación se registra la primera vez que el contenido se descarga del remoto web. Una vez que se ha registrado una suma de comprobación, las descargas posteriores del remoto web deben tener la misma suma de comprobación.
Cuando addurl se usó sin esta opción antes, el archivo que añadió puede ser convertido para ser verificable migrándolo al backend VURL. Por ejemplo: git-annex migrate foo --backend=VURL
--raw
Evita el manejo especial de urls por yt-dlp, y por bittorrent y otros remotos especiales. Esto, por ejemplo, hará que addurl descargue el archivo .torrent y no los contenidos a los que apunta.
--no-raw
Requiere que el contenido apuntado por la url sea descargado usando yt-dlp o un remoto especial. Si eso no se puede hacer, la adición fallará.
--raw-except=remote
Evita el manejo especial de urls por todos los remotos especiales excepto el especificado. Para permitir el manejo especial solo por yt-dlp, usa --raw-except=web.
--file=nombre
Úsalo con un nombre de archivo que aún no exista para añadir un nuevo archivo con el nombre especificado y el contenido descargado de la url.
Si el archivo ya existe, addurl registrará que se puede descargar de las url(s) especificadas.
--preserve-filename
Cuando el servidor web (o torrent, etc.) proporciona un nombre de archivo, úsalo tal cual, evitando sanear caracteres inusuales, o truncarlo, o cualquier otra modificación.
git-annex todavía verificará el nombre del archivo en busca de seguridad, y si el nombre del archivo tiene un problema de seguridad como traversa de directorios o un carácter de control, se negará a añadirlo.
--pathdepth=N
En lugar de basar el nombre del archivo en toda la url, esto provoca que se construya una ruta, comenzando en la profundidad especificada dentro del camino de la url.
Por ejemplo, añadir la url http://www.ejemplo.com/dir/subdir/archivo_grande con --pathdepth=1 usará "dir/subdir/archivo_grande", mientras que --pathdepth=3 usará "archivo_grande".
También puede ser negativo; --pathdepth=-2 usará las dos últimas partes de la url.
--prefix=foo --suffix=bar
Úsalo para ajustar los nombres de archivo que crea addurl. Por ejemplo, --suffix=.mp3 se puede usar para añadir una extensión al archivo.
--no-check-gitignore
Por defecto, los gitignores se respetan y se negará a descargar una url a un archivo que sería ignorado. Esto hace que dichos archivos se añadan a pesar de cualquier ignorado.
--jobs=N -JN
Habilita descargas paralelas cuando se añaden múltiples urls. Por ejemplo: -J4
Establecer esto a "cpus" ejecutará un trabajo por núcleo de CPU.
--batch
Habilita el modo batch, en el que las líneas que contienen urls a añadir se leen desde la entrada estándar.
-z
Hace que la entrada de --batch esté delimitada por nulos en lugar de las saltos de línea habituales.
--with-files
Cuando el modo batch está habilitado, hace que analice líneas de la forma: "$url $archivo"
Eso añade la url especificada al archivo especificado, descargando su contenido si el archivo aún no existe; lo mismo que git annex addurl $url --file $archivo
--json
Habilita la salida JSON. Esto está destinado a ser analizado por programas que usan git-annex. Cada línea de salida es un objeto JSON.
--json-progress
Incluye objetos de progreso en la salida JSON.
--json-error-messages
Los mensajes que normalmente se emitirían a la salida de error estándar se incluyen en el JSON en su lugar.
--backend
Especifica qué backend de clave-valor usar.
También las opciones-comunes-de-git-annex(1) pueden ser utilizadas.

ADVERTENCIAS

Si annex.largefiles está configurado, y no coincide con un archivo, git annex addurl añadirá el archivo no grande directamente al repositorio de git, en lugar de al annex. Sin embargo, esto no se hace cuando se usan --fast o --relaxed.
