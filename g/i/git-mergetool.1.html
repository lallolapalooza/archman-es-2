DESCRIPCIÓ

N

Utiliza git mergetool para ejecutar una de varias utilidades de fusión para resolver conflictos de fusión. Normalmente se ejecuta después de git merge

.

Si se proporcionan uno o más parámetros <archivo>, el programa de herramienta de fusión se ejecutará para resolver las diferencias en cada archivo (omitir aquellos sin conflictos). Especificar un directorio incluirá todos los archivos sin resolver en esa ruta. Si no se especifican nombres de <archivo>, git mergetool ejecutará el programa de herramienta de

fusión en cada archivo c
on conflictos de fusión.

OPCIONE

S

-t <herramienta>, --tool=<herramient

a>
Utiliza el programa de resolución de fusión especificado por <herramienta>. Los valores válidos incluyen emerge, gvimdiff, kdiff3, meld, vimdiff, y tortoisemerge. Ejecuta git mergetool --tool-help para obtener la lista de configuraciones válidas de <herramienta>.

Si no se especifica un programa de resolución de fusión, git mergetool utilizará la variable de configuración merge.tool. Si la variable de configuración merge.tool no está establecida, git mergetool elegirá un valor predeterminado

adecuado.

Puedes proporcionar explícitamente una ruta completa a la herramienta estableciendo la variable de configuración mergetool.<herramienta>.path. Por ejemplo, puedes configurar la ruta absoluta a kdiff3 estableciendo mergetool.kdiff3.path. De lo contrario, git mergetool asume que la herramienta está disponible en $PATH

.

En lugar de ejecutar uno de los programas de herramienta de fusión conocidos, git mergetool se puede personalizar para ejecutar un programa alternativo especificando la línea de comandos a invocar en una variable de configuración mergetool.<herramienta>.cm

d.

Cuando git mergetool se invoca con esta herramienta (ya sea a través de la opción -t o --tool o la variable de configuración merge.tool), la línea de comandos configurada se invocará con BASE establecido al nombre de un archivo temporal que contiene la base común para la fusión, si está disponible; LOCAL establecido al nombre de un archivo temporal que contiene el contenido del archivo en la rama actual; REMOTE establecido al nombre de un archivo temporal que contiene el contenido del archivo a fusionar, y MERGED establecido al nombre del archivo en el que la herramienta de fusión debe escribir el resultado de la resolución de la

fusión.

Si la herramienta de fusión personalizada indica correctamente el éxito de una resolución de fusión con su código de salida, entonces la variable de configuración mergetool.<herramienta>.trustExitCode se puede establecer en true. De lo contrario, git mergetool preguntará al usuario para indicar el éxito de la resol

ución después de que la herramien
ta personalizada haya terminado.

Si merge.guitool no está establecida, se recurrirá a la herramienta configurada en merge.tool. Esto puede autoseleccionarse usando la variable de configuración mergetool.guiD
efault.

--no-gu

Esto anula una configuración anterior de -g o --gui o la configuración de mergetool.guiDefault y lee la herramienta de fusión predeterminada de la variable configurada merge.t

CONFIGURACIÓ

N

Todo lo que hay debajo de esta línea en esta sección se incluye selectivamente de la documentación de git-config(1). El contenido es el mismo que el que se encuentra

allí:

mergetool.<herramienta>.

path
Anula la ruta para la herramienta dada. Esto es útil en caso de que tu herramienta no esté en el $PATH
.

mergetool.<herramienta>.

cmd
Especifica el comando para invocar la herramienta de fusión especificada. El comando especificado se evalúa en el shell con las siguientes variables disponibles: BASE es el nombre de un archivo temporal que contiene la base común de los archivos a fusionar, si está disponible; LOCAL es el nombre de un archivo temporal que contiene el contenido del archivo en la rama actual; REMOTE es el nombre de un archivo temporal que contiene el contenido del archivo de la rama que se está fusionando; MERGED contiene el nombre del archivo en el que la herramienta de fusión debe escribir los resultados de una fusión
exitosa.

mergetool.<herramienta>.

hideResolved
Permite al usuario anular el valor global de mergetool.hideResolved para una herramienta específica. Ver mergetool.hideResolved para la descripción
completa.

mergetool.<herramienta>.

trustExitCode
Para un comando de fusión personalizado, especifica si el código de salida del comando de fusión se puede utilizar para determinar si la fusión fue exitosa. Si esto no está establecido en true, se comprueba la marca de tiempo del archivo de destino de la fusión, y se asume que la fusión fue exitosa si el archivo ha sido actualizado; de lo contrario, se le pregunta al usuario para indicar el éxito de la
fusión.

mergetool.meld.

hasOutput
Versiones antiguas de meld no soportan la opción --output. Git intentará detectar si meld soporta --output inspeccionando la salida de meld --help. Configurar mergetool.meld.hasOutput hará que Git omita estas comprobaciones y utilice el valor configurado en su lugar. Establecer mergetool.meld.hasOutput en true le dice a Git que utilice incondicionalmente la opción --output, y false evita el uso de --output
.

mergetool.meld.

useAutoMerge
Cuando se proporciona --auto-merge, meld fusionará automáticamente todas las partes no conflictivas, resaltará las partes conflictivas y esperará la decisión del usuario. Establecer mergetool.meld.useAutoMerge en true le dice a Git que utilice incondicionalmente la opción --auto-merge con meld. Establecer este valor en auto hace que git detecte si --auto-merge está soportado y solo usará --auto-merge cuando esté disponible. Un valor de false evita el uso de --auto-merge por completo, y es el valor
predeterminado.

mergetool.<variante>.

layout
Configura el diseño de ventana dividida para la <variante> de vimdiff, que es cualquiera de vimdiff, nvimdiff, gvimdiff. Al iniciar git mergetool con --tool=<variante> (o sin --tool si merge.tool está configurado como <variante>), Git consultará mergetool.<variante>.layout para determinar el diseño de la herramienta. Si la configuración específica de la variante no está disponible, se usa la de vimdiff como alternativa. Si esa tampoco está disponible, se usará un diseño predeterminado con 4 ventanas. Para configurar el diseño, ver la sección PISTAS ESPECÍFICAS DEL
BACKEND.

mergetool.

hideResolved
Durante una fusión, Git resolverá automáticamente tantos conflictos como sea posible y escribirá el archivo $MERGED que contiene marcadores de conflicto alrededor de cualquier conflicto que no pueda resolver; $LOCAL y $REMOTE normalmente son las versiones del archivo de antes de la resolución de conflictos de Git. Esta bandera hace que $LOCAL y $REMOTE se sobrescriban para que solo se presenten los conflictos sin resolver al herramienta. Se puede configurar por herramienta mediante la mergetool.<tool>.hideResolved variable de configuración. Por defecto es false
.

mergetool.

keepBackup
Después de realizar una fusión, el archivo original con marcadores de conflicto se puede guardar como un archivo con una extensión .orig. Si esta variable está configurada a false, entonces este archivo no se conserva. Por defecto es true (es decir, conservar los archivos de respaldo)
.

mergetool.

keepTemporaries
Al invocar una herramienta de fusión personalizada, Git utiliza un conjunto de archivos temporales para pasar a la herramienta. Si la herramienta devuelve un error y esta variable está configurada a true, entonces estos archivos temporales se conservarán; de lo contrario, se eliminarán después de que la herramienta haya terminado. Por defecto es false
.

mergetool.

writeToTemp
Git escribe temporales BASE, LOCAL y REMOTE versiones de los archivos en conflicto en el árbol de trabajo de forma predeterminada. Git intentará usar un directorio temporal para estos archivos cuando se establezca true. Por defecto es false
.

mergetool.

prompt
Preguntar antes de cada invocación del programa de resolución de
fusión.

mergetool.

guiDefault
Establecer true para usar la merge.guitool de forma predeterminada (equivalente a especificar el argumento --gui), o auto para seleccionar merge.guitool o merge.tool dependiendo de la presencia de un valor de la variable de entorno DISPLAY. El valor predeterminado es false, donde el argumento --gui debe proporcionarse explícitamente para que se utilice la merge.guitool. ARCHIVOS

Descripción

Al especificar --tool=vimdiff en git mergetool Git abrirá Vim con un diseño de 4 ventanas distribuido de la siguiente

manera: 
------------------------------------------
|             |           |              |
|   LOCAL     |   BASE    |   REMOTE     |
|             |           |              |
------------------------------------------
|                                        |
|                MERGED                  |
|                                        |
----------------------------------------
-
-

LOCAL, BASE y REMOTE son buffers de solo lectura que muestran el contenido del archivo en conflicto en commits específicos ("commit al que te estás fusionando", "commit ancestro común" y "commit desde el que te estás fusionando" respectivamente

)

MERGED es un buffer de escritura donde tienes que resolver los conflictos (usando los otros buffers de solo lectura como referencia). Una vez que termines, guarda y sal de Vim como de costumbre (:wq) o, si quieres abortar, sal usando :c

q
.

Configuración del diseño

Puedes cambiar el diseño de ventanas usado por Vim configurando la variable de configuración mergetool.vimdiff.layout, que acepta una cadena donde los siguientes separadores tienen un significado

especial:
•+ se usa para "abrir una nueva
pestaña"
•, se usa para "abrir una nueva división
vertical"
•/ se usa para "abrir una nueva división
horizontal"
•@ se usa para indicar el archivo que contiene la versión final después de resolver los conflictos. Si no está presente, MERGED se usará por
defecto.

La precedencia de los operadores es la siguiente (puedes usar paréntesis para cambiarla)

: 
`@` > `+` > `/` >
`,
`

funciona:

Variantes

En lugar de --tool=vimdiff, también puedes usar una de estas otras

variantes:
•--tool=gvimdiff, para abrir gVim en lugar de

•--tool=nvimdiff, para abrir Neovim en lugar de
Vim.

Al usar estas variantes, para especificar un diseño personalizado tendrás que configurar las variables de configuración mergetool.gvimdiff.layout y mergetool.nvimdiff.layout en lugar de mergetool.vimdiff.layout (aunque esta última se usará como respaldo si la específica de la variante no está configurada)
