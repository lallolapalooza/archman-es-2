--informative-errors, --no-informative-error

s
Cuando los errores informativos están activados, git-daemon reportará errores más detallados al cliente, diferenciando condiciones como "no such repository" (repositorio no encontrado) de "repository not exported" (repositorio no exportado). Esto es más conveniente para los clientes, pero puede filtrar información sobre la existencia de repositorios no exportados. Cuando los errores informativos no están activados, todos los errores reportan "access denied" (acceso denegado) al cliente. El valor predeterminado es --no-informative-errors
.

--access-hook=<path

>
Cada vez que un cliente se conecta, primero se ejecuta un comando externo especificado por el <path> con el nombre del servicio (por ejemplo, "upload-pack"), la ruta al repositorio, el nombre de host (%H), el nombre de host canónico (%CH), la dirección IP (%IP) y el puerto TCP (%P) como sus argumentos de línea de comandos. El comando externo puede decidir rechazar el servicio saliendo con un estado distinto de cero (o permitirlo saliendo con un estado cero). También puede examinar las variables de entorno $REMOTE_ADDR y $REMOTE_PORT para conocer al solicitante cuando toma esta decisión.

Estos servicios se pueden habilitar/deshabilitar globalmente usando las opciones de línea de comandos de este comando. Si se desea un control más detallado (por ejemplo, para permitir que git archive se ejecute solo en unos pocos repositorios seleccionados que sirve el demonio), se puede usar el archivo de configuración por repositorio para habilitarlos o deshabilitarlos

upload-pac

k
Este sirve a los clientes git fetch-pack y git ls-remote. Está habilitado de forma predeterminada, pero un repositorio puede deshabilitarlo estableciendo el elemento de configuración daemon.uploadpack a false
.

upload-archiv

e
Este sirve a git archive --remote. Está deshabilitado de forma predeterminada, pero un repositorio puede habilitarlo estableciendo el elemento de configuración daemon.uploadarch a true
.

receive-pac

k
Este sirve a los clientes git send-pack, permitiendo push anónimo. Está deshabilitado de forma predeterminada, ya que no hay autenticación en el protocolo (en otras palabras, cualquiera puede hacer push de cualquier cosa en el repositorio, incluida la eliminación de refs). Esto está destinado únicamente para un entorno de LAN cerrado donde todos son amigables. Este servicio se puede habilitar estableciendo el elemento de configuración daemon.receivepack a tr
