DESCRIPCIÓ

N

Un demonio TCP de Git realmente simple que normalmente escucha en el puerto "DEFAULT_GIT_PORT" también conocido como 9418. Espera una conexión que solicite un servicio, y servirá ese servicio si está

habilitado.

Verifica que el directorio tenga el archivo mágico "git-daemon-export-ok", y se negará a exportar cualquier directorio de Git que no haya sido marcado explícitamente para exportación de esta manera (a menos que se especifique el parámetro --export-all). Si pasas algunas rutas de directorio como argumentos de git daemon, las ofertas se limitan a los repositorios dentro de esos

directorios.

Por defecto, solo está habilitado el servicio upload-pack, que sirve a los clientes git fetch-pack y git ls-remote, que se invocan desde git fetch, git pull y git clone

.

Esto es idealmente adecuado para actualizaciones de solo lectura, es decir, para hacer pull desde repositorios de

Git.

También existe un upload-archive para servir git arch

iv
e.

OPCIONE

S

--strict-path

s
Coincidir rutas exactamente (es decir, no permitir "/foo/repo" cuando la ruta real es "/foo/repo.git" o "/foo/repo/.git") y no hacer rutas relativas al usuario. git daemon se negará a iniciar cuando esta opción esté habilitada y no se proporcionen argumentos de
directorio.

--base-path=<path

>
Remapear todas las solicitudes de ruta como relativas a la ruta dada. Esto es como una "raíz de Git" - si ejecutas git daemon con --base-path=/srv/git en example.com, entonces si más tarde intentas hacer pull desde git://example.com/hello.git, git daemon interpretará la ruta como /srv/git/hell
o.git.

--base-path-relaxe

d
Si --base-path está habilitado y la búsqueda del repositorio falla, con esta opción git daemon intentará buscar sin prefijar la ruta base. Esto es útil para cambiar al uso de --base-path mientras se siguen permitiendo las rutas
antiguas.

--interpolated-path=<pathtemplate

>
Para soportar hosting virtual, se puede usar una plantilla de ruta interpolada para construir dinámicamente rutas alternativas. La plantilla soporta %H para el nombre de host de destino proporcionado por el cliente pero convertido a minúsculas, %CH para el nombre de host canónico, %IP para la dirección IP del servidor, %P para el número de puerto y %D para la ruta absoluta del repositorio con nombre. Después de la interpolación, la ruta se valida contra la lista de
directorios.

--export-al

l
Permitir hacer pull desde todos los directorios que parezcan repositorios de Git (tengan los subdirectorios objects y refs), incluso si no tienen el archivo git-daemon-export-ok
.

--inet

d
Hacer que el servidor se ejecute como un servicio de inetd. Implica --syslog (puede ser sobrescrito con --log-destination=). Incompatible con las opciones --detach, --port, --listen, --user y --group
.

--listen=<host-or-ipaddr

>
Escuchar en una dirección IP o nombre de host específico. Las direcciones IP pueden ser una dirección IPv4 o una dirección IPv6 si está soportado. Si IPv6 no está soportado, entonces --listen=<hostname> tampoco está soportado y --listen debe recibir una dirección IPv4. Puede darse más de una vez. Incompatible con la opción --inetd
.

--port=<n

>
Escuchar en un puerto alternativo. Incompatible con la opción --inetd
.

--init-timeout=<n

>
Tiempo de espera (en segundos) entre el momento en que se establece la conexión y el momento en que se recibe la solicitud del cliente (típicamente un valor bastante bajo, ya que debería ser básicamente inmediato)
.

--timeout=<n

>
Tiempo de espera (en segundos) para sub-solicitudes específicas del cliente. Esto incluye el tiempo que tarda el servidor en procesar la sub-solicitud y el tiempo de espera para la siguiente solicitud del
cliente.

--max-connections=<n

>
Número máximo de clientes concurrentes, por defecto 32. Establece a cero para no tener
límite.

--syslo

g
Abreviatura de --log-destination=syslog
.

--log-destination=<destination

>
Enviar mensajes de registro al destino especificado. Ten en cuenta que esta opción no implica --verbose, por lo que por defecto solo se registrarán condiciones de error. El <destination> debe ser uno de:

stder

r
Escribir en la salida de error estándar. Ten en cuenta que si --detach está especificado, el proceso se desconecta de la salida de error real, haciendo que este destino sea efectivamente equivalente a none
.

syslo

g
Escribir en syslog, usando el identificador git-daemon
.

non

e
Deshabilitar todos los
registros.

El destino por defecto es syslog si --inetd o --detach está especificado, de lo contrario stde

r
r.

--user-path, --user-path=<path

>
Permitir que se use la notación ~user en las solicitudes. Cuando se especifica sin parámetro, una solicitud a git://host/~alice/foo se toma como una solicitud para acceder al repositorio foo en el directorio de inicio del usuario alice. Si --user-path=<path> está especificado, la misma solicitud se toma como una solicitud para acceder al repositorio <path>/foo en el directorio de inicio del usuario alice
.

--verbos

e
Registrar detalles sobre las conexiones entrantes y los archivos
solicitados.

--reuseadd

r
Usar SO_REUSEADDR al enlazar el socket de escucha. Esto permite al servidor reiniciarse sin esperar a que las conexiones antiguas
caduquen.

--detac

h
Desacoplarse del shell. Implica --syslog
.

--pid-file=<file

>
Guardar el id del proceso en <file>. Ignorado cuando el demonio se ejecuta bajo --inetd
.

--user=<user>, --group=<group

>
Cambiar el uid y gid del demonio antes de entrar en el bucle de servicio. Cuando solo se da --user sin --group, se usa el ID de grupo primario del usuario. Los valores de la opción se pasan a getpwnam(3) y getgrnam(3) y no se soportan IDs numéricos.

Dar estas opciones es un error cuando se usan con --inetd; usa la facilidad del demonio inet para lograr lo mismo antes de generar git daemon si es

necesario.

Como muchos programas que cambian el id de usuario, el demonio no restablece variables de entorno como HOME cuando ejecuta programas de Git, por ejemplo upload-pack y receive-pack. Al usar esta opción, también puedes querer establecer y exportar HOME para que apunte al directorio de inicio de <user> antes de iniciar el demonio, y asegurarte de que cualquier archivo de configuración de Git en ese directorio sea legible por <use

r
>.

--enable=<service>, --disable=<service

>
Habilitar/deshabilitar el servicio en todo el sitio por defecto. Ten en cuenta que un servicio deshabilitado en todo el sitio todavía se puede habilitar por repositorio si está marcado como sobrescribible y el repositorio habilita el servicio con un elemento de
configuración.

--allow-override=<service>, --forbid-override=<service

>
Permite/prohíbe sobrescribir el valor predeterminado de todo el sitio con la configuración por repositorio. De forma predeterminada, todos los servicios pueden ser
sobrescritos.

--informative-errors, --no-informative-error

s
Cuando los errores informativos están activados, git-daemon reportará errores más detallados al cliente, diferenciando condiciones como "no such repository" (repositorio no encontrado) de "repository not exported" (repositorio no exportado). Esto es más conveniente para los clientes, pero puede filtrar información sobre la existencia de repositorios no exportados. Cuando los errores informativos no están activados, todos los errores reportan "access denied" (acceso denegado) al cliente. El valor predeterminado es --no-informative-errors
.

--access-hook=<path

>
Cada vez que un cliente se conecta, primero se ejecuta un comando externo especificado por el <path> con el nombre del servicio (por ejemplo, "upload-pack"), la ruta al repositorio, el nombre de host (%H), el nombre de host canónico (%CH), la dirección IP (%IP) y el puerto TCP (%P) como sus argumentos de línea de comandos. El comando externo puede decidir rechazar el servicio saliendo con un estado distinto de cero (o permitirlo saliendo con un estado cero). También puede examinar las variables de entorno $REMOTE_ADDR y $REMOTE_PORT para conocer al solicitante cuando toma esta decisión.

El comando externo puede, opcionalmente, escribir una sola l

ínea en su salida estándar para ser enviada al solicita
nte como un mensaje de error cuando rechaza el servicio.

<directory

>
Los argumentos restantes proporcionan una lista de directorios. Si se especifican directorios, entonces el proceso git-daemon servirá un directorio solicitado solo si está contenido en uno de estos directorios. Si --strict-paths se especifica, entonces el directorio solicita
do debe coincidir exactamente
con uno de estos directorios.

SERVICIO

S

Estos servicios se pueden habilitar/deshabilitar globalmente usando las opciones de línea de comandos de este comando. Si se desea un control más detallado (por ejemplo, para permitir que git archive se ejecute solo en unos pocos repositorios seleccionados que sirve el demonio), se puede usar el archivo de configuración por repositorio para habilitarlos o deshabilitarlos

.

upload-pac

k
Este sirve a los clientes git fetch-pack y git ls-remote. Está habilitado de forma predeterminada, pero un repositorio puede deshabilitarlo estableciendo el elemento de configuración daemon.uploadpack a false
.

upload-archiv

e
Este sirve a git archive --remote. Está deshabilitado de forma predeterminada, pero un repositorio puede habilitarlo estableciendo el elemento de configuración daemon.uploadarch a true
.

receive-pac

k
Este sirve a los clientes git send-pack, permitiendo push anónimo. Está deshabilitado de forma predeterminada, ya que no hay autenticación en el protocolo (en otras palabras, cualquiera puede hacer push de cualquier cosa en el repositorio, incluida la eliminación de refs). Esto está destinado únicamente para un entorno de LAN cerrado donde todos son amigables. Este servicio se puede habilitar estableciendo el elemento de configuración daemon.receivepack a tr
ue
.

inetd
Para configurar git daemon como un servicio inetd que maneja cualquier repositorio dentro de /pub/foo o /pub/bar, coloque una entrada como la siguiente en /etc/inetd, todo en una sola línea: 
        git stream tcp nowait nobody  /usr

virtuales
Para configurar git daemon como un servicio inetd que maneja repositorios para diferentes hosts virtuales, www.example.com y www.example.org, coloque una entrada como la siguiente en /etc/inetd, todo en una sola línea: 
        git stream tcp nowait nobody /usr/bin/git
                git daemon --inetd --verbose -
-export-all --interpolated-path=/pub/%H%D /pub/www.exam
ple.org/software /pub/www.example.com/software /software

En este ejemplo, el directorio de nivel raíz /pub contendrá un subdirectorio para cada nombre de host virtual admitido. Además, ambos hosts anuncian repositorios simplemente como git://www.example.com/software/repo.git. Para clientes anteriores a la versión 1.4.0, se podría crear un enlace simbólico desde /software hacia el repositor
