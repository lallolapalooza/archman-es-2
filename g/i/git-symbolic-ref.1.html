NOMBRE

git-symbolic-ref - Leer, modificar y eliminar refs simbólicas

SINOPSIS

git symbolic-ref [-m <razón>] <nombre> <ref>
git symbolic-ref [-q] [--short] [--no-recurse] <nombre>
git symbolic-ref --delete [-q] <nombre>

DESCRIPCIÓN

Dado un argumento, lee a qué cabecera de rama se refiere la ref simbólica dada y muestra su ruta, relativa al directorio .git/. Típicamente, darías HEAD como argumento <nombre> para ver en qué rama está tu árbol de trabajo.

Dados dos argumentos, crea o actualiza una ref simbólica <nombre> para que apunte a la rama <ref> dada.

Dado --delete y un argumento adicional, elimina la ref simbólica dada.

Una ref simbólica es un archivo regular que almacena una cadena que comienza con ref: refs/. Por ejemplo, tu .git/HEAD es un archivo regular cuyo contenido es ref: refs/heads/master.

OPCIONES

-d, --delete

Elimina la ref simbólica <nombre>.

-q, --quiet

No emita un mensaje de error si <nombre> no es una ref simbólica sino un HEAD desvinculado; en su lugar, salga con un estado distinto de cero silenciosamente.

--short

Al mostrar el valor de <nombre> como una ref simbólica, intenta acortar el valor, por ejemplo, de refs/heads/master a master.

--recurse, --no-recurse

Al mostrar el valor de <nombre> como una ref simbólica, si <nombre> se refiere a otra ref simbólica, sigue una cadena de refs simbólicas hasta que el resultado ya no apunte a una ref simbólica (--recurse, que es el valor predeterminado). --no-recurse se detiene después de desreferenciar solo un nivel de ref simbólica.

-m

Actualiza el reflog de <nombre> con <razón>. Esto solo es válido al crear o actualizar una ref simbólica.

NOTAS

En el pasado, .git/HEAD era un enlace simbólico que apuntaba a refs/heads/master. Cuando queríamos cambiar a otra rama, hacíamos ln -sf refs/heads/newbranch .git/HEAD, y cuando queríamos saber en qué rama estábamos, hacíamos readlink .git/HEAD. Pero los enlaces simbólicos no son completamente portátiles, por lo que ahora están obsoletos y se utilizan refs simbólicas (como se describe anteriormente) por defecto.

git symbolic-ref saldrá con el estado 0 si el contenido de la ref simbólica se imprimió correctamente, con el estado 1 si el nombre solicitado no es una ref simbólica, o 128 si ocurre otro error.
