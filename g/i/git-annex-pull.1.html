NOMBRE

git-annex-pull - extraer contenido de remotos

SINOPSIS

git annex pull [remoto ...]

DESCRIPCIÓN

Este comando extrae contenido de remotos. Descarga tanto el contenido del repositorio de git como el contenido de los archivos anexados. Al igual que git pull, fusiona los cambios en la rama actual.

Puedes usar git pull y git annex get manualmente para hacer lo mismo que este comando, pero este comando maneja varios detalles, incluyendo asegurarse de que la rama git-annex se extraiga del remoto.

Algunos remotos especiales contienen un árbol de archivos que puede ser importado, y este comando se puede usar para extraer de esos remotos así como de remotos de git regulares. Vea git-annex-import(1) para detalles sobre cómo funcionan esos remotos especiales. Para que este comando importe desde un remoto especial, remote.<nombre>.annex-tracking-branch también debe estar configurado, y tener el mismo valor que la rama actualmente extraída.

Cuando se ha usado git-annex-adjust(1) para extraer una rama ajustada, este comando también extraerá cambios de la rama padre.

Cuando se ha usado git-annex-view(1) para extraer una rama de vista, este comando actualizará la rama de vista para reflejar cualquier cambio en la rama padre o metadatos.

Cuando se ha usado git-annex-migrate(1) en otros repositorios, esto también actualiza el contenido en el repositorio local para esas migraciones.

Normalmente, este comando intenta descargar el contenido de cada archivo anexado, desde cualquier remoto del que esté extrayendo que tenga una copia. Para controlar qué archivos descarga, configure el contenido preferido del repositorio local. También eliminará archivos de un remoto que no sean contenido preferido del remoto. Vea git-annex-preferred-content(1).

OPCIONES

[remoto]
Por defecto, este comando extrae de todos los remotos disponibles, excepto de aquellos que tienen remote.<nombre>.annex-pull (o remote.<name>.annex-sync) configurado a falso.
Al especificar los nombres de remotos (o grupos de remotos), puedes controlar de cuáles extraer.
--fast
Solo extraer con los remotos con el menor valor de coste de annex configurado.
Cuando se proporciona una lista de remotos (o grupos de remotos), elige entre ellos, de lo contrario, elige entre todos los remotos.
--only-annex -a, --not-only-annex
Solo extraer la rama git-annex y el contenido anexado de los remotos, no otras ramas de git.
La configuración annex.synconlyannex se puede establecer a true para hacer que este sea el comportamiento por defecto. Para anular dicha configuración, usa --not-only-annex.
Cuando esto se combina con --no-content, solo se extraerá la rama git-annex.
--no-content, -g, --content
Usa --no-content o -g para evitar descargar (y eliminar) el contenido de los archivos anexados, y también para prevenir cualquier migración de contenido.
Si usas --no-content frecuentemente, puedes configurar annex.synccontent a falso para evitar descargar contenido por defecto. La opción --content anula esa configuración.
Para prevenir solo migraciones de contenido, puedes configurar annex.syncmigrations a falso. La opción --content también anula esa configuración.
--content-of=ruta -C ruta
Solo descargar (y eliminar) los archivos anexados en la ruta dada.
Esta opción se puede repetir varias veces con diferentes rutas.
--all -A
Normalmente, este comando opera sobre archivos anexados en la rama actual. Esta opción hace que opere sobre todas las versiones disponibles de todos los archivos anexados (cuando la configuración de contenido preferido lo permita).
Ten en cuenta que la configuración de contenido preferido que usa include= o exclude= solo coincidirá con la versión de los archivos actualmente en el árbol de trabajo, pero no con versiones anteriores de los archivos.
--jobs=N -JN
Habilita la extracción paralela con hasta el número especificado de trabajos ejecutándose simultáneamente. Por ejemplo: -J10
Establecer esto a "cpus" ejecutará un trabajo por núcleo de CPU.
(Nota que las extracciones de git no se ejecutan en paralelo porque tiende a ser menos eficiente.)
--allow-unrelated-histories, --no-allow-unrelated-histories
Se pasa a git merge, para controlar si se fusionan o no historiales que no comparten un ancestro común.
--resolvemerge, --no-resolvemerge
Por defecto, los conflictos de fusión se manejan automáticamente por este comando. Cuando dos versiones conflictivas de un archivo han sido confirmadas, ambas se añadirán al árbol, bajo diferentes nombres de archivo. Por ejemplo, el archivo "archivo" sería reemplazado por "archivo.variante-A" y "archivo.variante-B". (Vea git-annex-resolvemerge(1) para detalles.)
Usa --no-resolvemerge para deshabilitar esta resolución automática de conflictos de fusión. También se puede deshabilitar configurando annex.resolvemerge a falso.
--backend
Especifica qué backend de clave-valor usar al importar desde un remoto especial.
También se pueden usar las opciones generales de git-annex(1).
