El comando por defecto empaqueta todas las etiquetas y referencias que ya están empaquetadas, y deja las otras referencias solas. Esto es porque se espera que las ramas estén en desarrollo activo y empaquetar sus puntas no ayuda al rendimiento. Esta opción hace que todas las referencias también se empaqueten, con la excepción de las referencias ocultas, las referencias rotas y las referencias

simbólicas. Útil para un repositorio con muchas ramas de interés histórico.

o dent">Empaqueta las referencias según sea necesario dependiendo del estado actual de la base de datos de referencias. El comportamiento depende del formato de referencia utilizado por el repositorio y puede cambiar en el futuro.
•"files": Las referencias sueltas se empaquetan en el packed-refs archivo basándose en la proporción de referencias sueltas al tamaño del packed-refs archivo. Cuanto más grande sea el packed-refs archivo, más referencias sueltas deben existir antes de que reempaquetemos.
•"reftable": Las tablas se compactan de tal manera que forman una secuencia geométrica. Para dos tablas N y N+1, donde N+1 es más reciente, esto mantiene la propiedad de que N es al menos dos veces más grande que N+1. Solo se compactan las tablas que violan esta propiedad.

--include <pattern>

Empaqueta las referencias basándose en un glob(7) patrón. Las repeticiones de esta opción acumulan patrones de inclusión. Si una referencia está incluida tanto en --include como en --exclude, --exclude tiene precedencia. Usar --include excluirá todas las etiquetas de ser incluidas por defecto. Las referencias simbólicas y las referencias rotas nunca se empaquetan. Cuando se usa con --all, será una operación sin efecto. Usa --no-include para limpiar y restablecer la lista de patrones.

--exclude <pattern>

No empaquetar las referencias que coincidan con el glob(7) patrón dado. Las repeticiones de esta opción acumulan patrones de exclusión. Usa --no-exclude para limpiar y restablecer la lista de patrones. Si una referencia ya está empaquetada, incluirla con --exclude no la desempaquetará.

Cuando se usa con --all, empaqueta solo las referencias sueltas que no coincidan con ninguno de los --exclude patrones proporcionados.

Cuando se usa con --include, las referencias proporcionadas a --include, menos las referencias proporcionadas a --exclude , serán empaquetadas.

LIMITACIONES CONOCIDAS

La migración del formato de referencia tiene varias limitaciones conocidas en su forma actual:

•No es posible migrar repositorios que tienen árboles de trabajo.
•No hay forma de bloquear escrituras concurrentes en el repositorio durante una migración en curso. Las escrituras concurrentes pueden llevar a un estado migrado inconsistente. Se espera que los usuarios bloqueen las escrituras en un nivel superior. Si tu repositorio está registrado para mantenimiento programado, se recomienda desregistrarlo primero con git-maintenance(1).

Estas limitaciones pueden eventualmente eliminarse.
