NOMBRE

git-remote-annex - programa auxiliar de remoto para almacenar un repositorio git en un remoto especial de git-annex

SINOPSIS

git fetch annex::uuid?param=value&param=value...

DESCRIPCIÓN

Este es un programa auxiliar de remoto de git que permite a git clonar, obtener y enviar desde un repositorio git que está almacenado en un remoto especial de git-annex con una URL que comienza con "annex::"

El remoto especial necesita tener configurada una remote.<nombre>.url para usar esto. Esto se configura automáticamente al clonar desde un remoto especial.

Para hacer que git-annex-initremote(1) y git-annex-enableremote(1) configuren la URL, págales la opción --with-url.

O, para configurar un remoto especial existente con una URL abreviada, ejecute:

git config remote.nombre.url annex::

Una vez configurada la URL, puede usar git pull, git push, etc. con el remoto especial de manera similar a como lo haría con cualquier otro remoto de git. Pero consulte PUSHES CONFLICTIVOS a continuación para algunas situaciones en las que se comporta de manera ligeramente diferente.

FORMATO DE URL

Utiliza una URL que comienza con "annex::". Hay tres formas de tales URLs:

URL Completa
Contiene el UUID y todos los parámetros de configuración del remoto especial que se pasaron al usar git-annex initremote.
Por ejemplo, para clonar desde un remoto especial de directorio:
git clone annex::358ff77e-0bc3-11ef-bc49-872e6695c0e3?type=directory&encryption=none&directory=/mnt/foo/
URL Abreviada
Esto facilita la configuración de un remoto especial existente con una URL sin tener que inventar la URL completa.
annex::
Al usar esta URL abreviada, la URL completa se mostrará cada vez que haga git pull o push, cuando sea posible que git-annex la determine. (Aunque en algunos casos, como el remoto especial de directorio, algunos parámetros pueden omitirse de la URL mostrada).
URL Web
Esta URL apunta a un archivo en la web, que contiene la URL annex:: completa.
annex::https://example.com/foo-repo
No todos los remotos especiales pueden ser accedidos por dicha URL, por razones de seguridad. Actualmente, esto se limita a remotos especiales httpalso.

PUSHES CONFLICTIVOS

Como cualquier repositorio git, un repositorio git almacenado en un remoto especial puede tener cosas conflictivas enviadas desde diferentes lugares. Esto funciona en su mayoría igual que cualquier otro repositorio git, por ejemplo, se evitará un push que sobrescriba otro trabajo a menos que se fuerce.

Sin embargo, es posible, cuando se realizan pushes conflictivos al mismo tiempo, que uno de los pushes sea sobrescrito por el otro. En esta situación, el push sobrescrito parecerá haber tenido éxito, pero al hacer pull más tarde se mostrará la situación real.

FORMATO DEL REPOSITORIO

El repositorio git se almacena en el remoto especial usando objetos especiales de annex cuyos nombres comienzan con "GITMANIFEST" y "GITBUNDLE". Para más detalles, ver: https://git-annex.branchable.com/internals/git-remote-annex/

Los pushes a un remoto especial se realizan generalmente de forma incremental. Sin embargo, a veces se vuelve a cargar todo el repositorio git. Esto se hace al forzar el push de una referencia, o al eliminar una referencia del remoto. También se hace cuando se acumulan demasiados bundles git en el remoto especial, según lo configurado por el archivo de configuración git remote.<nombre>.annex-max-git-bundles.

Tenga en cuenta que una recarga del repositorio no elimina los objetos GITBUNDLE antiguos del mismo. Esto significa que las referencias enviadas al remoto especial aún se pueden acceder incluso después de eliminarlas o sobrescribirlas.

Un push que elimina todas las referencias del remoto especial eliminará todos los objetos GITBUNDLE acumulados. Pero, por supuesto, hacer un push de este tipo significa que alguien que clone desde el remoto especial en ese momento verá un remoto vacío.
