-v,

--verbose
Sé un poco más detallado y muestra la URL remota después del nombre. Para los remotes promisor, muestra también qué filtros (blob:none etc.) están configurados. NOTA: Esto debe colocarse entre remote y el subcomando. remoto y

COMANDO

S

Sin argumentos, muestra una lista de los remotes existentes. Hay varios subcomandos disponibles para realizar operaciones en los

remotes.

ad

d
Añade un remote llamado <name> para el repositorio en <URL>. El comando git fetch <name> puede usarse entonces para crear y actualizar ramas de seguimiento remoto <name>/<branch>.

Con la opción -f, git fetch <name> se ejecuta inmediatamente después de configurar la información del

remote.

Con la opción --tags, git fetch <name> importa cada etiqueta del repositorio

remoto.

Con la opción --no-tags, git fetch <name> no importa etiquetas del repositorio

remoto.

Por defecto, solo se importan las etiquetas de las ramas obtenidas (véase git-fetch(1))

.

Con la opción -t <branch>, en lugar del refspec glob por defecto para que el remote rastree todas las ramas bajo el espacio de nombres refs/remotes/<name>/, se crea un refspec para rastrear solo <branch>. Puedes dar más de una -t <branch> para rastrear múltiples ramas sin capturar todas las

ramas.

Con la opción -m <master>, se configura un symbolic-ref refs/remotes/<name>/HEAD para que apunte a la rama <master> del remote. Véase también el comando

set-head.

Cuando se crea un espejo de fetch con --mirror=fetch, las referencias no se almacenarán en el espacio de nombres refs/remotes/, sino que todo lo que haya en refs/ del remote se reflejará directamente en refs/ del repositorio local. Esta opción solo tiene sentido en repositorios desnudos (bare), porque un fetch sobrescribiría cualquier commit

local.

Cuando se crea un espejo de push con --mirror=push, entonces git push se comportará siempre como si se hubiera pasado --mi

rro
r.

renam

e
Renombra el remote llamado <old> a <new>. Se actualizan todas las ramas de seguimiento remoto y la configuración del remote.

En caso de que <old> y <new> sean iguales, y <old> sea un archivo bajo $GIT_DIR/remotes o $GIT_DIR/branches, el remote se convie

rte al formato de arch
ivo de configuración.

remove, r

m
Elimina el remote llamado <name>. Se eliminan todas las ramas de seguimiento remoto y la configuración del
remote.

set-hea

d
Establece o elimina la rama predeterminada (es decir, el destino del symbolic-ref refs/remotes/<name>/HEAD) para el remote nombrado. No es necesario tener una rama predeterminada para un remote, pero permite especificar el nombre del remote en lugar de una rama específica. Por ejemplo, si la rama predeterminada para origin está establecida en master, entonces origin puede especificarse donde normalmente especificarías origin/master.

Con -d o --delete, se elimina el symbolic-ref refs/remotes/<name>/HEAD

.

Con -a o --auto, se consulta al remote para determinar su HEAD, y luego el symbolic-ref refs/remotes/<name>/HEAD se establece en la misma rama. Por ejemplo, si el HEAD del remote apunta a next, git remote set-head origin -a establecerá el symbolic-ref refs/remotes/origin/HEAD en refs/remotes/origin/next. Esto solo funcionará si refs/remotes/origin/next ya existe; si no, debe obtenerse

primero.

Usa <branch> para establecer el symbolic-ref refs/remotes/<name>/HEAD explícitamente. Por ejemplo, git remote set-head origin master establecerá el symbolic-ref refs/remotes/origin/HEAD en refs/remotes/origin/master. Esto solo funcionará si refs/remotes/origin/master ya exis

te; si no, debe o
btenerse primero.

set-branche

s
Cambia la lista de ramas rastreadas por el remote nombrado. Esto puede usarse para rastrear un subconjunto de las ramas remotas disponibles después de la configuración inicial de un remote.

Las ramas nombradas se interpretarán como si se hubieran especificado con la opción -t en la línea de comandos de git remote add

.

Con --add, en lugar de reemplazar la lista de ramas

actualmente rastreada
s, se añade a esa lista.

get-ur

l
Recupera las URLs de un remote. Las configuraciones de insteadOf y pushInsteadOf se expanden aquí. Por defecto, solo se lista la primera URL.

Con --push, se consultan las URLs de push en lugar de las URLs de

fetch.

Con --all, se listarán tod

as las URLs
del remote.

set-ur

l
Cambia las URLs del remote. Establece la primera URL para el remote <name> que coincida con la expresión regular <oldurl> (la primera URL si no se da <oldurl>) en <newurl>. Si <oldurl> no coincide con ninguna URL, se produce un error y no se cambia nada.

Con --push, se manipulan las URLs de push en lugar de las URLs de

fetch.

Con --add, en lugar de cambiar las URLs existentes, se añade una nueva

URL.

Con --delete, en lugar de cambiar las URLs existentes, se eliminan todas las URLs que coincidan con la expresión regular <URL> para el remote <name>. Intentar eliminar todas las URLs que no sean de push es un

error.

Ten en cuenta que la URL de push y la URL de fetch, aunque pueden establecerse de forma diferente, deben seguir refiriéndose al mismo lugar. Lo

que hayas hecho push a la URL de push debería ser lo que verías si hicieras fetch inmediatamente desde la URL de fetch. Si estás intentand
o hacer fetch de un lugar (por ejemplo, tu upstream) y push a otro (por ejemplo, tu repositorio de publicación), usa dos remotes separados.

Da alguna información sobre el remote <name>.

Con la opción -n, no se consultan primero las cabeceras del remote con git ls-remote <name>; se usa la información

almacenada en ca
ché en su lugar.

prun

e
Elimina las referencias obsoletas asociadas con <name>. Por defecto, se eliminan las ramas de seguimiento remoto obsoletas bajo <name>, pero dependiendo de la configuración global y de la configuración del remote, podríamos incluso podar etiquetas locales que no se han hecho push allí. Equivalente a git fetch --prune <name>, excepto que no se obtendrán nuevas referencias.

Véase la sección PRUNING de git-fetch(1) para ver qué se podará dependiendo de la

configuración.

Con la opción --dry-run, informa de qué ramas se

podarían, pero n
o las poda realmente.

e
Obtiene actualizaciones para remotes o grupos de remotes en el repositorio según lo definido por remotes.<group>. Si no se especifica ni grupo ni remote en la línea de comandos, se usará el parámetro de configuración remotes.default; si remotes.default no está definido, se usarán todos los remotes que no tengan el parámetro de configuración remote.<name>.skipDefaultUpdateb> establecido en true será actualizado. (Véase git-config(1)).

Con la opción --prune, se ejecuta la

poda en todos lo
s remotos qu
