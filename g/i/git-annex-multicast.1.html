NOMBRE

git-annex-multicast - distribución de archivos multicast

SINOPSIS

git annex multicast [opciones]

DESCRIPCIÓN

Multicast permite la difusión de archivos a múltiples receptores, típicamente en una única red local.

El programa uftp se utiliza para multicast. http://uftp-multicast.sourceforge.net/

OPCIONES

--gen-address
Genera una clave de cifrado multicast y almacena una dirección multicast correspondiente en la rama git-annex.
--send [archivo]
Envía los archivos especificados a cualquier receptor cuyas direcciones multicast estén almacenadas en la rama git-annex.
Cuando no se especifican archivos, se envían todos los archivos anexados en el directorio actual y subdirectorios.
Las opciones de coincidencia de git-annex (git-annex-matching-options(1)) se pueden usar para controlar qué archivos enviar. Por ejemplo:

git annex multicast send . --not --copies 2
--receive
Recibe archivos de los remitentes cuyas direcciones multicast están almacenadas en la rama git-annex.
A medida que se recibe cada archivo, se muestra su nombre de archivo. Este es el nombre de archivo que utilizó el remitente; el árbol de trabajo local puede usar un nombre diferente para el archivo, o no contener un enlace al archivo.
Este comando continúa ejecutándose hasta que lo interrumpas presionando Ctrl+C.
Ten en cuenta que la reserva de disco configurada annex.diskreserve no es honrada por este comando, ya que uftpd recibe los archivos reales y puede recibir archivos de cualquier tamaño.
--uftp-opt=opción -Uopción
Pasa una opción al comando uftp/uftpd. Se puede especificar varias veces.
Por ejemplo, para transmitir a 50 Mbps:

git annex multicast send -U-R -U50000
También se pueden usar las opciones comunes de git-annex (git-annex-common-options(1)).

EJEMPLO

Supongamos que un profesor quiere distribuir archivos por multicast a los estudiantes en un aula.

Esto asume que el profesor y los estudiantes han clonado un repositorio git-annex, y que ambos pueden enviar cambios a su rama git-annex, o de lo contrario enviarse cambios entre sí.

Primero, el profesor ejecuta git annex multicast --gen-address; git annex sync

A continuación, cada estudiante ejecuta git annex multicast --gen-address; git annex sync

Una vez que todos los estudiantes han generado direcciones, el profesor ejecuta git annex sync una vez más. (Ahora los estudiantes han recibido la dirección del profesor, y el profesor ha recibido todas las direcciones de los estudiantes).

A continuación, cada estudiante ejecuta git annex multicast --receive

Finalmente, una vez que los estudiantes están escuchando (ejem), el profesor ejecuta git annex multicast --send
