git-update-ref - Actualiza d

e forma segura el nombre de
objeto almacenado en una ref

SINOPSI

S 
git update-ref [-m <reason>] [--no-deref] -d <ref> [<old-oid>]
git update-ref [-m <reason>] [--no-deref] [--create-reflog] <ref> <new-oid> [<old-oid>]
git update-ref [-m <reason>] [--no-deref] --stdin [-z] [--batch-update
s
]

DESCRIPCIÓ

N

Dados dos argumentos, almacena el <new-oid> en el <ref>, posiblemente desreferenciando las refs simbólicas. Por ejemplo: git update-ref HEAD <new-oid> actualiza la cabecera de la rama actual al nuevo

objeto.

Dados tres argumentos, almacena el <new-oid> en el <ref>, posiblemente desreferenciando las refs simbólicas, después de verificar que el valor actual del <ref> coincide con <old-oid>. Por ejemplo: git update-ref refs/heads/master <new-oid> <old-oid> actualiza la cabecera de la rama master a <new-oid> solo si su valor actual es <old-oid>. Puedes especificar 40 caracteres "0" o una cadena vacía como <old-oid> para asegurarte de que la ref que estás creando no

existe.

Los argumentos finales son nombres de objetos; este comando sin ninguna opción no soporta actualizar una ref simbólica para que apunte a otra ref (véase git-symbolic-ref(1)). Pero git update-ref --stdin sí tiene los comandos symref-* para que las refs regulares y las refs simbólicas puedan confirmarse en la misma

transacción.

Si se indica --no-deref, el propio <ref> se sobrescribe, en lugar del resultado de seguir los punteros

simbólicos.

Con -d, elimina el <ref> nombrado después de verificar que todavía contiene <old-oid>

.

Con --stdin, update-ref lee instrucciones de la entrada estándar y realiza todas las modificaciones juntas. Especifica comandos de la

forma: 
update SP <ref> SP <new-oid> [SP <old-oid>] LF
create SP <ref> SP <new-oid> LF
delete SP <ref> [SP <old-oid>] LF
verify SP <ref> [SP <old-oid
>] LF symref-update SP <ref> SP <new-target> [SP (ref SP <old-target> | oid SP <old-oid>)] LF symref-create SP <ref> SP <new-target> LF symr
ef-delete SP <ref> [SP <old-target>] LF symref-verify SP <ref> [SP <old-target>] LF option SP <opt> LF start LF prepare LF commit LF abort LF

Con --create-reflog, update-ref creará un reflog para cada ref incluso si normalmente no se crearía

uno.

Con --batch-updates, update-ref ejecuta las actualizaciones en un lote pero permite que actualizaciones individuales fallen debido a entradas de usuario inválidas o incorrectas, aplicando solo las actualizaciones exitosas. Sin embargo, los errores relacionados con el sistema—como fallos de E/S o problemas de memoria—resultarán en un fallo total de todas las actualizaciones en lote. Cualquier actualización fallida será reportada en el siguiente

formato: 
rejected SP (<old-oid> | <old-t
arget>) SP (<new-oid> | <new-ta
rget>) SP <rejection-reason> LF

Cita los campos que contienen espacios en blanco como si fueran cadenas en el código fuente de C; es decir, rodeados por comillas dobles y con escapes de barra invertida. Usa 40 caracteres "0" o la cadena vacía para especificar un valor cero. Para especificar un valor ausente, omite el valor y su SP precedente por

completo.

Alternativamente, usa -z para especificar en formato terminado por NUL, sin

comillas: 
update SP <ref> NUL <new-oid> NUL [<old-oid>] NUL
create SP <ref> NUL <new-oid> NUL
delete SP <ref> NUL [<old-oid>] NUL
verify SP <ref> NUL [<old-oid
>] NUL symref-update SP <ref> NUL <new-target> [NUL (ref NUL <old-target> | oid NUL <old-oid>)] NUL symref-create SP <ref> NUL <new-target> NUL symre
f-delete SP <ref> [NUL <old-target>] NUL symref-verify SP <ref> [NUL <old-target>] NUL option SP <opt> NUL start NUL prepare NUL commit NUL abort NUL

En este formato, usa 40 caracteres "0" para especificar un valor cero, y usa la cadena vacía para especificar un valor

ausente.

En cualquier formato, los valores pueden especificarse en cualquier forma que Git reconozca como un nombre de objeto. Los comandos en cualquier otro formato o un <ref> repetido producen un error. Los significados de los comandos

son:

updat

e
Establece <ref> a <new-oid> después de verificar <old-oid>, si se proporcionó. Especifica un <new-oid> cero para asegurar que la ref no exista después de la actualización y/o un <old-oid> cero para asegurar que la ref no exista antes de la
actualización.

creat

e
Crea <ref> con <new-oid> después de verificar que no existe. El <new-oid> proporcionado no puede ser
cero.

delet

e
Elimina <ref> después de verificar que existe con <old-oid>, si se proporcionó. Si se proporcionó, <old-oid> no puede ser
cero.

symref-updat

e
Establece <ref> a <new-target> después de verificar <old-target> u <old-oid>, si se proporcionó. Especifica un <old-oid> cero para asegurar que la ref no exista antes de la
actualización.

verif

y
Verifica <ref> contra <old-oid> pero no la cambia. Si <old-oid> es cero o ausente, la ref no debe
existir.

symref-create: Crea una ref simbólica <ref> con <new-target> después de verificar que no

existe.

symref-delet

e
Elimina <ref> después de verificar que existe con <old-target>, si se
proporcionó.

symref-verif

y
Verifica la <ref> simbólica contra <old-target> pero no la cambia. Si <old-target> está ausente, la ref no debe existir. Solo puede usarse en el modo no-deref
.

optio

n
Modifica el comportamiento del siguiente comando que nombre un <ref>. La única opción válida es no-deref para evitar desreferenciar una ref
simbólica.

star

t
Inicia una transacción. En contraste con una sesión no transaccional, una transacción se abortará automáticamente si la sesión termina sin una confirmación explícita. Este comando puede crear una nueva transacción vacía cuando la actual ya ha sido confirmada o
abortada.

prepar

e
Prepara para confirmar la transacción. Esto creará archivos de bloqueo para todas las actualizaciones de referencias en cola. Si una referencia no pudo ser bloqueada, la transacción será
abortada.

commi

t
Confirma todas las actualizaciones de referencias en cola para la transacción, terminando la
transacción.

abor

t
Aborta la transacción, liberando todos los bloqueos si la transacción está en estado
preparado.

Si todas las <ref>s pueden ser bloqueadas con <old-oid>s coincidentes simultáneamente, todas las modificaciones s

e realizan. De lo contrario, no se realizan modificaciones. Ten en cuenta que mientras cada <ref> individual se ac
tualiza o elimina de forma atómica, un lector concurrente aún puede ver un subconjunto de las modificaciones.

REGISTRO DE

ACTUALIZACIONES

Si el parámetro de configuración "core.logAllRefUpdates" es verdadero y la ref está bajo "refs/heads/", "refs/remotes/", "refs/notes/", o es un pseudoref como HEAD u ORIG_HEAD; o el archivo "$GIT_DIR/logs/<ref>" existe entonces git update-ref añadirá una línea al archivo de registro "$GIT_DIR/logs/<ref>" (desreferenciando todas las refs simbólicas antes de crear el nombre del registro) describiendo el cambio en el valor de la ref. Las líneas de registro se formatean

como: 
oldsha1 SP
newsha1 SP c
ommitter LF

Donde "oldsha1" es el valor hexadecimal de 40 caracteres previamente almacenado en <ref>, "newsha1" es el valor hexadecimal de 40 caracteres de <new-oid> y "committer" es el nombre del confirmador, la dirección de correo electrónico y la fecha en el formato estándar de identidad de confirmador de

Git.

Opcionalmente con

-m: 
oldsha1 SP news
ha1 SP committer
TAB message LF

Donde todos los campos son como se describió arriba y "message" es el valor proporcionado a la opción

-m.

Una actualización fallará (sin cambiar <ref>) si el usuario actual

no puede crear un nuevo archivo de registro, añadir al archivo de re
gistro existente o no tiene información de confirmador disponible.

NOTE

S

Las referencias simbólicas se implementaron inicialmente usando enlaces simbólicos. Esto está obsoleto desde que no todos los sistemas de archivos soportan enlaces

simbólicos.

Este comando sigue enlaces simbólicos reales solo si comienzan con "refs/": de lo contrario, simplemente intentará leerlos y actualizarlos como un archivo regular (e

s decir, permitirá que el sistema de archivos los siga, pero sobrescribi
rá tal enlace simbólico hacia otro lugar con un nombre de archivo regular).
