NOMBRE

git-archimport - Importa un repositorio de GNU Arch a Git

SINOPSIS

git archimport [-h] [-v] [-o] [-a] [-f] [-T] [-D <profundidad>] [-t <dir_temporal>]
               <archivo>/<rama>[:<rama-git>]...

DESCRIPCIÓN

Importa un proyecto desde uno o más repositorios de GNU Arch. Seguirá ramas y repositorios dentro de los espacios de nombres definidos por los parámetros <archivo>/<rama> proporcionados. Si no puede encontrar la rama remota de la que proviene una fusión, simplemente la importará como un commit regular. Si puede encontrarla, la marcará como una fusión siempre que sea posible (ver discusión a continuación).

El script espera que le proporciones las raíces clave desde donde puede comenzar la importación con un commit de Arch de tipo importación inicial o etiqueta. Seguirá e importará nuevas ramas dentro de las raíces proporcionadas.

Espera tratar con un solo proyecto. Si detecta ramas que tienen raíces diferentes, se negará a ejecutarse. En ese caso, edita tus parámetros <archivo>/<rama> para definir claramente el alcance de la importación.

git archimport utiliza **tla** extensivamente en segundo plano para acceder al repositorio de Arch. Asegúrate de tener una versión reciente de **tla** disponible en el PATH. **tla** debe conocer los repositorios que le pasas a git archimport.

Para la importación inicial, git archimport espera encontrarse en un directorio vacío. Para seguir el desarrollo de un proyecto que usa Arch, vuelve a ejecutar git archimport con los mismos parámetros que la importación inicial para realizar importaciones incrementales.

Mientras que git archimport intentará crear nombres de rama sensatos para los archivos que importa, también es posible especificar nombres de rama de Git manualmente. Para hacerlo, escribe un nombre de rama de Git después de cada parámetro <archivo>/<rama>, separado por dos puntos. De esta manera, puedes acortar los nombres de rama de Arch y convertir la jerga de Arch a jerga de Git, por ejemplo, mapeando una rama "PROYECTO--devo--VERSIÓN" a "master".

Es posible asociar múltiples ramas de Arch a una sola rama de Git; el resultado solo tendrá sentido si no se realizan commits en la primera rama después de que se cree la segunda. Aun así, esto es útil para convertir repositorios de Arch que han sido rotados periódicamente.

FUSIONES

Los datos de fusión de parches de Arch también se utilizan para marcar las fusiones en Git. A Git no le importa mucho el seguimiento de parches y solo considera una fusión cuando una rama incorpora todos los commits desde el punto en que se bifurcaron. El resultado final es que Git tendrá una buena idea de cuán divergidas están las ramas. Por lo tanto, el proceso de importación pierde algunos metadatos de intercambio de parches.

Afortunadamente, cuando intentas fusionar ramas importadas de Arch, Git encontrará una buena base de fusión y tiene una buena probabilidad de identificar los parches que se han intercambiado fuera de secuencia entre las ramas.

OPCIONES

-h

Muestra el uso.

-v

Salida detallada.

-T

Muchas etiquetas. Creará una etiqueta para cada commit, reflejando el nombre del commit en el repositorio de Arch.

-f

Utiliza la estrategia de importación rápida de conjuntos de parches. Esto puede ser significativamente más rápido para árboles grandes, pero no puede manejar renombres de directorios ni cambios de permisos. La estrategia predeterminada es lenta y segura.

-o

Úsalo para compatibilidad con nombres de rama de estilo antiguo utilizados por versiones anteriores de git archimport. Los nombres de rama de estilo antiguo eran categoría--rama, mientras que los nombres de rama de estilo nuevo son archivo,categoría--rama--versión. En ambos casos, los nombres dados en la línea de comandos anularán los generados automáticamente.

-D <profundidad>

Sigue la ascendencia de fusión e intenta importar árboles que se han fusionado. Especifica una profundidad mayor que 1 si los registros de parches se han podado.

-a

Intenta registrar automáticamente los archivos en http://mirrors.sourcecontrol.net Esto es particularmente útil con la opción -D.

-t <dir_temporal>

Anula el directorio temporal predeterminado.

<archivo>/<rama>

Identificador <archivo>/<rama> en un formato que entiende tla **log**.
