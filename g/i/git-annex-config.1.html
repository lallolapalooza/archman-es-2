DESCRIPCIÓ

N

Establece u obtiene ajustes de configuración almacenados en la rama

git-annex.

A diferencia de los ajustes de git config, estos ajustes pueden ser vistos en todas las clonaciones del repositorio, una vez que sus ramas git-annex hayan sido

sincronizadas.

Estos ajustes pueden ser sobrescritos por repositorio utilizando git con

fig.

git-annex no comprueba la rama git-annex para todos los ajustes de git config que le afectan (los cuales están listados en la sección CONFIGURATION de la página man de git-annex). Solo unos pocos tienen sent

ido para poder establecerlos de modo que todas las clonaciones de un
repositorio vean el ajuste, y por lo tanto git-annex solo busca estos.

AJUSTES

SOPORTADOS
annex.
numcopies
Indica a git-annex cuántas copias debe preservar de los archivos, a lo largo de todos los repositorios. El valor predeterminado
es 1.
Cuando se le pide a git-annex que descarte un archivo, primero verifica que el número de copias pueda ser satisfecho entre todos los demás repositorios que tengan una copia del
archivo.
En situaciones inusuales, que involucren remotos especiales que no soportan bloqueo, y descartes concurrentes del mismo contenido desde múltiples repositorios, git-annex puede violar el ajuste numcopies. Aun así garantiza que al menos 1 copia sea preservada. Esto puede ser configurado estableciendo annex.
mincopies.
Este es el mismo ajuste que configura el comando git-annex-numcopies(1). Puede ser sobrescrito por archivo mediante el ajuste annex.numcopies en los archivos .gitat
tributes.
annex.
mincopies
Indica a git-annex cuántas copias es obligatorio preservar de los archivos, a lo largo de todos los repositorios. El valor predeterminado
es 1.
Esto complementa el ajuste annex.numcopies. En situaciones inusuales, que involucren remotos especiales que no soportan bloqueo, y descartes concurrentes del mismo contenido desde múltiples repositorios, git-annex puede violar el ajuste numcopies. En estas situaciones inusuales, git-annex asegura que el número de copias nunca baje de
mincopies.
Es una buena idea no depender únicamente de establecer mincopies. Establece también numcopies, con un número mayor, y mantén mincopies en el mínimo absoluto con el que te sientas cómodo. Establecer mincopies a un número grande, en lugar de establecer numcopies, en algunos casos impedirá descartar contenido en situaciones completamente
seguras.
Este es el mismo ajuste que configura el comando git-annex-mincopies(1). Puede ser sobrescrito por archivo mediante el ajuste annex.mincopies en los archivos .gitat
tributes.
annex.
largefiles
Se usa para configurar qué archivos son lo suficientemente grandes como para ser añadidos al anexo. Es una expresión que coincide con los archivos grandes, por ejemplo "include=*.mp3 o largerthan(500kb)". Ver git-annex-matching-expression(1) para detalles sobre la
sintaxis.
Esto configura el comportamiento tanto de git-annex como de git al añadir archivos al repositorio. Por defecto, git-annex add añade todos los archivos al anexo (excepto archivos ocultos y archivos en directorios ocultos), y git add añade archivos a git (a menos que hayan sido añadidos al anexo previamente). Cuando annex.largefiles está configurado, tanto git annex add como git add añadirán los archivos grandes que coincidan al anexo, y los demás archivos a
git.
Otros comandos de git-annex también respetan annex.largefiles, incluyendo git annex import, git annex addurl, git annex importfeed, git-annex assist, y el git-annex ass
istant.
Esto establece un valor predeterminado, que puede ser sobrescrito por atributos annex.largefiles en los archivos .gitattributes, o por git con
fig.
annex.
dotfiles
Normalmente, los archivos ocultos y los archivos dentro de directorios ocultos se asumen que son archivos de configuración como .gitignore, cuyo contenido siempre debería ser parte del repositorio git, por lo que no serán añadidos al anexo. Establecer annex.dotfiles a true hace que estos archivos sean añadidos al anexo igual que cualquier otro
archivo.
Esto establece un valor predeterminado, que puede ser sobrescrito por annex.dotfiles en git c
onfig.
annex.
addunlocked
Comandos como git-annex add añaden archivos al repositorio en forma bloqueada por defecto. Esto puede hacer que añada los archivos en forma desbloqueada, igual que si se ejecutara git-annex-unlock(1) sobre los
archivos.
Esto puede establecerse a "true" para añadir todo desbloqueado, o puede ser una expresión más complicada que coincida con archivos por nombre, tamaño o contenido. Ver git-annex-matching-expression(1) para
detalles.
Esto establece un valor predeterminado, que puede ser sobrescrito por annex.addunlocked en git con
fig.
annex.
autocommit
Establecer a false para evitar que git-annex assistant, git-annex assist y git-annex sync hagan commit automático de cambios en los archivos del
repositorio.
Esto establece un valor predeterminado, que puede ser sobrescrito por annex.autocommit en git c
onfig.
annex.
resolvemerge
Establecer a false para evitar que los conflictos de fusión en la rama actualmente comprobada sean resueltos automáticamente por git-annex assitant, git-annex sync, git-annex pull, git-annex merge, y el gancho post-receive de
git-annex.
Esto establece un valor predeterminado, que puede ser sobrescrito por annex.resolvemerge en git con
fig.
annex.
synccontent
Establecer a true para hacer que git-annex sync transfiera contenido anexado por
defecto.
Establecer a false para evitar que git-annex pull y git-annex push transfieran contenido
anexado.
Esto establece un valor predeterminado, que puede ser sobrescrito por annex.synccontent en git con
fig.
annex.
synconlyannex
Establecer a true para hacer que git-annex sync, git-annex pull y git-annex push operen por defecto solo sobre la rama git-annex y el contenido
anexado.
Esto establece un valor predeterminado, que puede ser sobrescrito por annex.synconlyannex en git con
fig.
annex.
securehashesonly
Establecer a true para indicar que el repositorio solo debería usar hashes criptográficamente seguros (SHA2, SHA3) y no hashes inseguros (MD5, SHA1) para el
contenido.
Cuando esto está establecido, el contenido de archivos que usen hashes criptográficamente inseguros no se permitirá que sea añadido al
repositorio.
Además, git-annex fsck se quejará de cualquier archivo presente en el repositorio que use hashes
inseguros.
Ten en cuenta que esto solo se lee de la rama git-annex por git annex init, y se copia al ajuste git config correspondiente. Por lo ta

it-annex no afectarán a un repositorio u

NOMBRE

git-annex-config - obtener y establecer la configuración de git-annex

SINOPSIS

git annex config [option <value> ...] [--show-origin <file> ]

git annex config --unset option ...

git annex config --get option ...

git annex config --get-all option ...

git annex config --show-origin [option ...]

DESCRIPCIÓN

Esto se utiliza para obtener y establecer la configuración de git-annex. La configuración se puede guardar en varios lugares, incluyendo el archivo .git/config, el archivo .gitattributes (si se utiliza la opción --local), o la configuración global de git. git-annex busca la configuración en este orden:

  1. El archivo .git/annex/annex.conf local (si se utiliza la opción --local).
  2. La configuración del repositorio local de git (en .git/config).
  3. La configuración del repositorio global de git (en ~/.gitconfig).
  4. La configuración del sistema de git (en /etc/gitconfig).
  5. Valores predeterminados.

Por lo tanto, las opciones establecidas en el archivo .git/config anularán las establecidas en el archivo ~/.gitconfig, etc.

La opción --local se utiliza para establecer la configuración en el archivo .git/annex/annex.conf local. Este archivo se utiliza para guardar la configuración que sólo se aplica a la copia local del repositorio, como por ejemplo las claves de las API de los servicios de almacenamiento. Esta configuración no se comparte con los demás clones del repositorio y, por lo tanto, no debe contener opciones que afecten al comportamiento de git-annex para otros usuarios (como por ejemplo annex.autocommit).

AJUSTES SOPORTADOS

annex.autocommit
Un valor booleano. Si es true (predeterminado), git-annex hará commit automáticamente de los cambios en los archivos y en los metadatos del contenido de git-annex. Si es false, git-annex no hará commit de los cambios, requiriendo un commit manual de git.
annex.descriptionmatching
Un valor booleano. Si es true (predeterminado), los archivos con metadatos de descripción (como .gitattributes) se tratarán como si tuvieran el mismo contenido si sus descripciones coinciden. Esto puede ser útil cuando se copian archivos que sólo varían en sus nombres de archivo. Si es false, cada archivo se tratará como único.
annex.numcopies
Un número entero. Especifica cuántas copias de cada archivo se deben mantener en el repositorio.
annex.worktreekeys
Un valor booleano. Si es true, git-annex incluirá claves de archivos en el árbol de trabajo. Esto permite la sincronización de árboles de trabajo de git-annex mediante el protocolo estándar de git, pero puede dar lugar a una mayor cantidad de datos que se transmiten.
annex.trustlocalkeys
Un valor booleano. Si es true (predeterminado), git-annex confiará en las claves de los archivos que se encuentran en el directorio de trabajo local. Si es false, git-annex verificará las claves de los archivos consultando a los servidores de almacenamiento remoto.
annex.webapp.autostart
Un valor booleano. Si es true (predeterminado), el servidor web de git-annex se iniciará automáticamente cuando sea necesario.
annex.web.browser
La ruta al ejecutable del navegador web que se utilizará para abrir la interfaz web de git-annex.
annex.backend
El nombre del backend de git-annex a utilizar. Por ejemplo, git-annex para el backend predeterminado, o SHA256E para utilizar SHA256 como backend.
annex.thin.content
Un valor booleano. Si es true, git-annex intentará almacenar contenido de forma "delgada", permitiendo que el mismo contenido sea compartido entre diferentes archivos si el contenido es el mismo. Esto requiere que el backend subyacente soporte esta característica (por ejemplo, git-annex backend). Si es false (predeterminado), cada archivo se almacenará por separado.
annex.webapp.port
El número de puerto en el que se ejecutará el servidor web de git-annex. Si no se especifica, se utilizará un puerto aleatorio.
annex.ssh.command
El comando SSH a utilizar para conectarse a servidores remotos. Esto puede ser útil si necesita especificar opciones SSH personalizadas, como claves SSH específicas o puertos.

OPCIONES

--set option value
Establece el valor de la option a value. Si la opción ya está establecida, se anula su valor.
--unset option
Elimina la option de la configuración.
--get option
Obtiene el valor de la option. Si la opción está establecida en varios lugares, se devuelve el valor que tiene mayor prioridad (es decir, el más específico).
--get-all option
Obtiene todos los valores de la option. Esto es útil cuando una opción puede estar establecida en varios lugares (por ejemplo, múltiples entradas para remote.origin.annex-ignore).
--show-origin
Muestra el origen de la configuración de cada opción. Por ejemplo, si la opción annex.autocommit está establecida en .git/config, se mostrará --git-dir/.git/config annex.autocommit true.
--local
Establece la configuración en el archivo .git/annex/annex.conf local. Esto se utiliza para opciones que sólo se aplican a la copia local del repositorio, como las claves de API. No se comparte con los demás clones.
--for-file file
Se puede utilizar en combinación con --show-origin para especificar el nombre de archivo a comprobar en .gitattributes.
También se pueden utilizar las git-annex-common-options(1).

EJEMPLO

Supongamos que desea evitar que git annex sync haga commit de los cambios en los archivos, para que se utilice un flujo de trabajo de commit manual en todos los clones del repositorio. Entonces ejecute:


git annex config --set annex.autocommit false

Si desea anular esto en un clon particular, simplemente use git config en el clon:


git config annex.autocommit true

Y para volver al comportamiento predeterminado:


git annex config --unset annex.autocommit
