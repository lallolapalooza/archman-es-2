NOMBRE

git-credential-cache - Ayudante para almacenar temporalmente contraseñas en memoria

SINOPSIS

git config credential.helper 'cache [<opciones>]'

DESCRIPCIÓN

Este comando almacena en caché credenciales para su uso por programas Git posteriores. Las credenciales almacenadas se mantienen en memoria del proceso daemon de caché (en lugar de escribirse en un archivo) y se olvidan después de un tiempo de espera configurable. Las credenciales se olvidan antes si el daemon de caché muere, por ejemplo, si el sistema se reinicia. La caché es accesible a través de un socket de dominio Unix, restringido al usuario actual por permisos del sistema de archivos.

Probablemente no quieras invocar este comando directamente; está destinado a ser utilizado como un ayudante de credenciales por otras partes de Git. Consulta gitcredentials(7) o EJEMPLOS a continuación.

OPCIONES

--timeout <segundos>

Número de segundos para almacenar en caché las credenciales (por defecto: 900).

--socket <ruta>

Usa <ruta> para contactar a un daemon de caché en ejecución (o iniciar un nuevo daemon de caché si no hay uno iniciado). Por defecto es $XDG_CACHE_HOME/git/credential/socket a menos que ~/.git-credential-cache/ exista, en cuyo caso se utiliza ~/.git-credential-cache/socket en su lugar. Si tu directorio personal está en un sistema de archivos montado en red, puede que necesites cambiarlo a un sistema de archivos local. Debes especificar una ruta absoluta.

CONTROL DEL DAEMON

Si deseas que el daemon salga temprano, olvidando todas las credenciales almacenadas en caché antes de su tiempo de espera, puedes emitir una acción exit:

git credential-cache exit

EJEMPLOS

El propósito de este ayudante es reducir el número de veces que debes escribir tu nombre de usuario o contraseña. Por ejemplo:

$ git config credential.helper cache
$ git push http://example.com/repo.git
Username: <escribe tu nombre de usuario>
Password: <escribe tu contraseña>
[funciona durante 5 minutos más]
$ git push http://example.com/repo.git
[tus credenciales se usan automáticamente]

Puedes proporcionar opciones a través de la variable de configuración credential.helper (este ejemplo aumenta el tiempo de caché a 1 hora):

$ git config credential.helper 'cache --timeout=3600'

TOKENS DE ACCESO PERSONAL

Algunos remotos aceptan tokens de acceso personal, que se generan aleatoriamente y son difíciles de memorizar. Típicamente tienen una vida útil de semanas o meses.

git-credential-cache es inherentemente inadecuado para el almacenamiento persistente de tokens de acceso personal. La credencial se olvidará después del tiempo de espera de la caché. Incluso si configuras un tiempo de espera largo, las credenciales se olvidarán si el daemon muere.

Para evitar la regeneración frecuente de tokens de acceso personal, configura un ayudante de credenciales con almacenamiento persistente. Alternativamente, configura un ayudante de credenciales OAuth para generar credenciales automáticamente. Consulta gitcredentials(7), secciones "Available helpers" y "OAuth".
