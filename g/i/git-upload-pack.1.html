GIT-UPLOAD-PACK(1) Manual de Git GIT-UPLOAD-PACK(1)

NOMBRE

git-upload-pack - Envía objetos empaquetados a git-fetch-pack

SINOPSIS

git-upload-pack [--[no-]strict] [--timeout=<n>] [--stateless-rpc]
                  [--advertise-refs] <directorio>

DESCRIPCIÓN

Invocado por git fetch-pack, aprende qué objetos faltan en el otro lado y los envía después de empaquetarlos.

Este comando normalmente no es invocado directamente por el usuario final. La interfaz de usuario para el protocolo está en el lado de git fetch-pack, y el par de programas está destinado a ser utilizado para obtener actualizaciones de un repositorio remoto. Para operaciones de push, consulte git send-pack.

OPCIONES

--strict, --no-strict

No intente <directorio>/.git/ si <directorio> no es un directorio Git.

--timeout=<n>

Interrumpe la transferencia después de <n> segundos de inactividad.

--stateless-rpc

Realiza un único ciclo de lectura-escritura con stdin y stdout. Esto encaja con el modelo de procesamiento de solicitudes HTTP POST donde un programa puede leer la solicitud, escribir una respuesta y debe salir.

--http-backend-info-refs

Utilizado por git-http-backend(1) para servir las solicitudes $GIT_URL/info/refs?service=git-upload-pack. Consulte "Clientes Inteligentes" en gitprotocol-http(5) y "Transporte HTTP" en la documentación de gitprotocol-v2(5). También es entendido por git-receive-pack(1).

<directorio>

El repositorio desde el cual sincronizar.

AMBIENTE

GIT_PROTOCOL

Variable interna utilizada para el handshake del protocolo de red. Los administradores del servidor pueden necesitar configurar algunos transportes para permitir que esta variable sea pasada. Consulte la discusión en git(1).

GIT_NO_LAZY_FETCH

Al clonar o obtener de un repositorio parcial (es decir, uno clonado con --filter), el upload-pack del lado del servidor puede necesitar obtener objetos adicionales de su upstream para completar la solicitud. Por defecto, upload-pack se negará a realizar dicha obtención diferida, porque git fetch puede ejecutar comandos arbitrarios especificados en la configuración y los hooks del repositorio de origen (y upload-pack intenta ser seguro para ejecutarse incluso en directorios .git no confiables).

Esto se implementa haciendo que upload-pack establezca internamente la variable GIT_NO_LAZY_FETCH a 1. Si desea anularla (porque está obteniendo de un clon parcial y está seguro de que confía en él), puede establecer explícitamente GIT_NO_LAZY_FETCH a 0.

SEGURIDAD

La mayoría de los comandos de Git no deben ejecutarse en un directorio .git no confiable (consulte la sección SEGURIDAD en git(1)). upload-pack intenta evitar cualquier opción de configuración o hook peligroso del repositorio que esté sirviendo, lo que lo hace seguro para clonar un directorio no confiable y ejecutar comandos en el clon resultante.

Para un nivel adicional de seguridad, puede ser capaz de ejecutar upload-pack como un usuario alternativo. Los detalles dependerán de la plataforma, pero en muchos sistemas puede ejecutar:

git clone --no-local --upload-pack='sudo -u nobody git-upload-pack' ...
