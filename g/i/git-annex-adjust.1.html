NOMBRE

git-annex-adjust - entrar en una rama ajustada

SINOPSIS

git annex adjust --unlock|--lock|--fix|--hide-missing [--unlock|--lock|--fix]|--unlock-present

DESCRIPCIÓN

Entra en una forma ajustada de la rama actual. Los archivos anexados serán tratados de manera diferente. Por ejemplo, con --unlock todos los archivos anexados se desbloquearán.

La rama ajustada tendrá un nombre como "ajustado/master(desbloqueado)". Dado que es una rama de git normal, puede usar git checkout para volver a la rama original en cualquier momento.

Esto permite cambiar cómo se manejan los archivos anexados, sin hacer cambios en una rama pública con comandos como git-annex unlock.

Mientras esté en la rama ajustada, puede usar comandos de git-annex y git como de costumbre. Cualquier confirmación que realice se realizará inicialmente solo en la rama ajustada.

Para propagar confirmaciones desde la rama ajustada de vuelta a la rama original, y a otros repositorios, así como para fusionar cambios de otros repositorios, ejecute git annex sync. Esto propagará los cambios que haya realizado, como agregar/eliminar archivos, pero no propagará los ajustes realizados por este comando.

Cuando esté en una rama ajustada, usar git merge otherbranch a menudo no es ideal, ya que fusionar una rama no ajustada puede generar conflictos de fusión innecesarios o agregar archivos en forma no ajustada. Y dichas fusiones no se pueden propagar desde la rama ajustada de vuelta a la rama original. Para evitar esos problemas, use git annex merge otherbranch.

Volver a ejecutar este comando con las mismas opciones mientras se está dentro de la rama ajustada actualizará la rama ajustada según sea necesario (por ejemplo, para --hide-missing y --unlock-present), y también propagará las confirmaciones de vuelta a la rama original.

OPCIONES

--unlock
Desbloquea todos los archivos anexados en la rama ajustada. Esto permite modificar los archivos anexados.
Normalmente, desbloquear un archivo requiere hacer una copia de su contenido, para que se preserve su contenido original, mientras que la copia puede ser modificada. Para usar menos espacio, puede establecer annex.thin a true antes de ejecutar este comando; esto hará que se cree un enlace duro al contenido en lugar de una copia. (Cuando el sistema de archivos lo soporta.) Si bien esto puede ahorrar una cantidad considerable de espacio en disco, cualquier modificación realizada en un archivo provocará la pérdida de la versión anterior del archivo del repositorio local. Por lo tanto, habilite annex.thin con cuidado.
Cuando esté en una rama ajustada desbloqueada, git annex add agregará archivos desbloqueados en lugar del comportamiento predeterminado de agregarlos bloqueados.
--lock
Bloquea todos los archivos anexados en la rama ajustada. Esto puede ser preferido por aquellos a quienes les gusta ver enlaces simbólicos rotos cuando el contenido de un archivo anexado no está presente.
Cuando esté en una rama ajustada bloqueada, git annex add agregará archivos bloqueados, como de costumbre. Sin embargo, git add (y git commit -a etc.) todavía agregan archivos desbloqueados. Esto se debe a que no es posible que esos comandos git agreguen archivos bloqueados.
--fix
Repara los enlaces simbólicos a archivos anexados para que apunten al directorio de objetos de git annex local. Esto puede ser útil si un repositorio se extrae de una manera inusual que impide que los enlaces simbólicos confirmados en git apunten a los objetos annex.
--hide-missing
Solo incluye los archivos anexados en la rama ajustada cuando su contenido esté presente.
La rama ajustada no se cambia inmediatamente cuando la disponibilidad del contenido cambia, por lo que si git annex drop archivos, se convertirán en enlaces rotos de la manera habitual. Y cuando los archivos que faltaban se copien en el repositorio desde otro lugar, no serán inmediatamente visibles en la rama.
Para actualizar la rama ajustada y reflejar los cambios en la disponibilidad del contenido, ejecute git annex adjust --hide-missing de nuevo. O, para automatizar las actualizaciones, configure el ajuste annex.adjustedbranchrefresh.
A pesar de que los archivos que faltan se ocultan, git annex sync --content aún operará sobre ellos y se puede usar para descargar archivos faltantes de remotos. También actualiza la rama ajustada después de transferir contenido.
Esta opción se puede combinar con --unlock, --lock o --fix.
--unlock-present
Desbloquea los archivos cuyo contenido está presente y bloquea los archivos cuyo contenido falta. Esto proporciona los beneficios de trabajar con archivos desbloqueados, pero hace que sea más fácil ver cuándo falta el contenido de un archivo, ya que será un enlace simbólico roto.
La rama ajustada no se cambia inmediatamente cuando la disponibilidad del contenido cambia, por lo que cuando git annex get archivos, permanecerán bloqueados. Y cuando git annex drop archivos, permanecerán bloqueados y por lo tanto no serán enlaces simbólicos rotos.
Para actualizar la rama ajustada y reflejar los cambios en la disponibilidad del contenido, ejecute git annex adjust --unlock-present de nuevo. O, para automatizar las actualizaciones, configure el ajuste annex.adjustedbranchrefresh. O use git-annex sync --content, que actualiza la rama después de transferir contenido.
También se pueden usar las opciones comunes de git-annex(1).
