La variable de entorno GIT_HTTP_EXPORT_ALL puede pasarse a git-http-backend para omitir la verificación del archivo "git-daemon-export-ok" en cada repositorio antes de permitir la exportación de ese repositorio. L

a

variable de entorno GIT_HTTP_MAX_REQUEST_BUFFER (o la opción de configuración http.maxRequestBuffer) puede definirse para cambiar la solicitud de negociación de refs más grande que git manejará durante una obtención; cualquier obtención que requiera un búfer más grande no tendrá éxito. Normalmente no es necesario cambiar este valor, pero puede ser útil si se está obteniendo desde un repositorio con un número extremadamente grande de refs. El valor puede especificarse con una unidad (por ejemplo, 100M para 100 megabytes). El valor predeterminado es 10 megabytes. Los clientes pueden sondear capacidades de protocolo opcionales (como el protocolo v2) usando

la

cabecera HTTP Git-Protocol. Para soportar estas, el contenido de esa cabecera debe aparecer en la variable de entorno GIT_PROTOCOL. La mayoría de los servidores web pasarán esta cabecera al CGI a través de la variable HTTP_GIT_PROTOCOL, y git-http-backend la copiará automáticamente a GIT_PROTOCOL. Sin embargo, algunos servidores web pueden ser más selectivos sobre qué cabeceras pasarán, en cuyo caso deben configurarse explícitamente (véase la mención de Git-Protocol en la configuración de Apache de la sección EJEMPLOS anterior). El proceso backend establece GIT_COMMITTER_NAME

como

$REMOTE_USER y GIT_COMMITTER_EMAIL como ${REMOTE_USER}@http.${REMOTE_ADDR}, asegurando que cualquier reflog creado por git-receive-pack contenga alguna información identificativa del usuario remoto que realizó el push. Toda
