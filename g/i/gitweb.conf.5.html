El script CGI de gitweb para ver repositorios Git a través de la web usa un fragmento de script perl como su archivo de configuración. Puedes establecer variables usando "our $variable = valor"; el texto desde un carácter "#" hasta el final de una línea se ignora. Ver perlsyn(1) para más detalles. Un ejem

plo:

org >> Repos'; 
El archivo de configuración se usa para anular la
configuración predeterminada que estaba integra
da en gitweb en el momento en que se generó el

script gitweb.cgi. Aunque se podrían alterar directamente los ajustes de configuración en el propio CGI de gitweb, esos cambios se perderían al actualizar. Los ajustes de configuración también podrían colocarse en un archivo en el mismo directorio que el script CGI con el nombre

predeterminado

gitweb_config.perl — lo que permite tener múltiples instancias de gitweb con diferentes configuraciones mediante el uso de enlaces simbólicos. Ten en cuenta que alguna configuración se puede controlar a nivel de repositorio en lugar de a nivel global de gitweb: ver la subsección "Configuración de gitweb por repositorio" en

Encontrando

archivos

Las siguientes variables de configuración indican a gitweb dónde encontrar archivos. Los valores de estas variables son rutas en el sistema de

archivos.

$GI

T
Ejecutable de git core a utilizar. Por defecto, está establecido en $GIT_BINDIR/git, que a su vez está establecido por defecto en $(bindir)/git. Si usas Git instalado desde un paquete binario, normalmente deberías establecer esto en "/usr/bin/git". Esto puede ser simplemente "git" si tu servidor web tiene un PATH sensato; desde el punto de vista de la seguridad, es mejor usar la ruta absoluta al binario de git. Si tienes múltiples versiones de Git instaladas, se puede usar para elegir cuál utilizar. Debe estar (correctamente) establecido para que gitweb pueda
funcionar.

$mimetypes_fil

e
Archivo a utilizar para la adivinación de tipos MIME (basada en la extensión del nombre de archivo) antes de intentar /etc/mime.types. NOTA que esta ruta, si es relativa, se toma como relativa al repositorio Git actual, no al script CGI. Si no está definida, solo se usa /etc/mime.types (si está presente en el sistema de archivos). Si no se encuentra ningún archivo de tipos mime, la adivinación del tipo mime basada en la extensión del archivo está deshabilitada. No definida por
defecto.

$highlight_bi

n
Ruta al ejecutable highlight a utilizar (debe ser el de http://andre-simon.de/zip/download.php debido a suposiciones sobre parámetros y salida). Por defecto, está establecido en highlight; establece la ruta completa al ejecutable highlight si no está instalado en el PATH de tu servidor web. Ten en cuenta que la función de resaltado debe estar activada para que gitweb utilice el resaltado de sintaxis.

NOTA: para que un archivo sea resaltado, su tipo de sintaxis debe ser detectado y esa sintaxis debe ser soportada por "highlight". La detección de sintaxis por defecto es mínima, y hay muchos tipos de sintaxis soportados sin detección por defecto. Hay tres opciones para añadir detección de sintaxis. La primera y segunda prioridad son %highlight_basename y %highlight_ext, que detectan basándose en el nombre base (el nombre de archivo completo, por ejemplo "Makefile") y la extensión (por ejemplo "sh"). Las claves de estos hashes son el nombre base y la extensión, respectivamente, y el valor para una clave dada es el nombre de la sintaxis a pasar mediante --syntax <syntax> a "highlight". La última prioridad es la configuración de "highlight" de expresiones regulares Shebang para detectar el idioma basándose en la primera línea del archivo, (por ejemplo, coincidiendo con la línea "#!/bin/bash"). Consulta la documentación de highlight y la configuración predeterminada en /etc/highlight/filetypes.conf para más

detalles.

Por ejemplo, si los repositorios que alojas usan la extensión "phtml" para archivos PHP, y quieres tener el resaltado de sintaxis correcto para esos archivos, puedes añadir lo siguiente a la configuración de

Algunas características y políticas

opcionales

La mayoría de las características se configuran a través de el hash %feature; sin embargo, algunas de las características extra de gitweb pueden activarse y configurarse usando las variables descritas a continuación. Esta lista, además de las variables de configuración que controlan cómo se ve gitweb, contiene variables que configuran el lado administrativo de gitweb (por ejemplo, prevención de scripting entre sitios; admitidamente esto, como efecto secundario, afecta a cómo se ven las páginas de "resumen", o limitación de carga)

@git_base_url_lis

t
Lista de URLs base de Git. Estas URLs se usan para generar URLs que describen desde dónde obtener un proyecto, que se muestran en la página de resumen del proyecto. La URL completa de obtención es "$git_base_url/$project", para cada elemento de esta lista. Puedes configurar múltiples URLs base (por ejemplo, una para el protocolo git://, y una para el protocolo http://).

Ten en cuenta que la configuración por repositorio se puede establecer en el archivo $GIT_DIR/cloneurl, o como valores de la variable de configuración de múltiples valores gitweb.url en la configuración del proyecto. La configuración por repositorio tiene precedencia sobre el valor compuesto a partir de los elementos de @git_base_url_list y el nombre del

Puedes configurar un solo valor (una sola entrada/elemento en esta lista) en el momento de la compilación estableciendo la variable de configuración GITWEB_BASE_URL en tiempo de compilación. Por defecto está establecida a (), es decir, una lista v

CONFIGURANDO LAS CARACTERÍSTICAS DE

GITWEB

Muchas características de gitweb pueden habilitarse (o deshabilitarse) y configurarse usando el hash %feature. Los nombres de las características de gitweb son las claves de este

hash.

Cada elemento del hash %feature es una referencia a un hash y tiene la siguiente

estructura: 
"<feature-name>" => {
        "sub" => <feature-sub-(subroutine)>,
        "override" => <allow-override-(boolean)>,
        "default" => [ <options>... ]
}
,

Algunas características no se pueden sobrescribir por proyecto. Para esas características la estructura del elemento apropiado de %feature tiene una forma más

simple: 
"<feature-name>" => {
        "override" => 0,
        "default" => [ <options>... ]
}
,

Como se puede ver, carece del elemento

'sub'.

El significado de cada parte de la configuración de la característica se describe a

continuación:

defaul

t
Lista (referencia a un array) de parámetros de la característica (si hay alguno), usada también para alternar (habilitar o deshabilitar) la característica dada.

Ten en cuenta que actualmente es siempre una referencia a un array, incluso si la característica no acepta ningún parámetro de configuración, y 'default' se usa solo para encenderla o apagarla. En tal caso, enciendes la característica estableciendo este elemento a [1], y la apagas estableciéndolo a [0]. Ver también el pasaje sobre la característica "blame" en la sección

"Ejemplos".

Para deshabilitar características que aceptan parámetros (son configurables), necesitas establecer este elemento a lista vacía, es decir

[]
.

Normalmente, la "<feature>" dada es configurable a través de la variable de configuración gitweb.<feature> en el archivo de configuración de Git por

repositorio.

fork

s
Si esta característica está habilitada, gitweb considera que los proyectos en subdirectorios de la raíz del proyecto (nombre base) son bifurcaciones de proyectos existentes. Para cada proyecto $projname.git, los proyectos en el directorio $projname/ y sus subdirectorios no se mostrarán en la lista principal de proyectos. En su lugar, se muestra una marca '+' junto a $projname, que enlaza a una vista "forks" que lista todas las bifurcaciones (todos los proyectos en el subdirectorio $projname/). Adicionalmente, una vista "forks" para un proyecto está enlazada desde la página de resumen del proyecto.

Si la lista de proyectos se toma de un archivo ($projects_list apunta a un archivo), las bifurcaciones solo se reconocen si están listadas después del proyecto principal en ese

archivo.
